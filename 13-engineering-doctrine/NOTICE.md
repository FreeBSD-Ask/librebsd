## 项目侧回流建议（2026-10-22）

以下条目由《给我自由—一部 BSD 史》编纂项目提出，**尚未进入教义正文**；上游采纳前，项目侧只在自身规则中落地。条目格式：编号｜建议条款｜证据｜代价与失效条件。

| 编号 | 建议条款 | 证据 | 代价与失效条件 |
| ---- | -------- | ---- | -------------- |
| TG-001 | 在阶段模型外增设“长线战役”变更类型：基线、批次、断点、续跑、收口五要素 | 17 条长线；H1–H4 跨 119 批 | 增加阶段裁剪行；短周期项目不适用 |
| TG-003 | 以“证据型验证”替代强制单元测试：负向夹具、独立复算、双跑／回放、抽样人工判读 | 外部站点、OCR、ASR 与人工判读 | 需要更高的人工复核成本；确定性项目仍应使用单元测试 |
| TG-004 | 以“证据复核”替代纯 diff review：输入版本、命令复跑、数据回读、抽样与全量复算 | 数据与文档产品的审查对象不是代码差异 | 复核成本高；纯代码项目可保留 diff review |
| TG-005 | 增设五字段轻量 ADR，高风险任务仍用十二字段 | 小任务占比高，完整 ADR 易被跳过 | 轻量 ADR 可能弱化形式审查；高风险任务须强制完整 |
| TG-007 | 增设“记录生命周期”：创建、活跃、收口、轮替、归档、复审 | 长期档案项目的台账与批次史持续增长 | 与软件发布模型不同；短周期项目不适用 |
| TG-008 | 增设“AI 代理可靠性”：自报不可信、独立复算、上下文交接、并发写锁 | 单人＋AI 多会话协作 | 增加核查成本；多人团队可弱化 |

复制到其他项目时，请保留本文件与 `README.md` 的来源说明。
