# 269.2.4 合图层——许可证哲学与商业模式的不可调和性及阶段性妥协

**要点**：合图层将此张力置于更宏大的结构中理解：Apple 使用 FreeBSD 代码但不回馈争议是“许可证哲学与商业模式的不可调和性”的典型案例——BSD 许可证的“完全消极自由”（允许商业使用、修改、再发布而无强制回馈）与 Apple 作为商业公司的“商业模式封闭性”（Mac OS X 整体作为专有软件销售）在根本目标上存在张力，APSL 2.0 选择性开源与 libdispatch Apache 2.0 开源是此张力的阶段性妥协而非根本解决。**项目史观总纲第 24.2 节** 明言“BSD 的许可证被商业公司利用却不被回馈，Linux 的 GPL 却借此聚拢了生态。版本控制工具的更替同样是劣币驱逐良币的典型——占据主流的未必是最优的。这不是技术优劣的较量，而是形式主义的权力运作”——此即合图层的史观根基。合图层承认此争议的部分不可调和性：Apple 作为商业公司的商业模式封闭性（Mac OS X 整体专有销售、iOS 封闭生态、App Store 抽成模式）与 FreeBSD 作为社区项目的完全开放性（BSD 许可证、社区共建、无商业模式约束）在根本目标上存在张力，Apache 2.0 选择性开源（libdispatch）与 APSL 2.0 部分开源（Darwin）是阶段性妥协而非根本解决。但合图层亦指出和解路径——**Jordan Hubbard 在 Apple 与 FreeBSD 间的中介作用**、**libdispatch 以 Apache 2.0 开源使 FreeBSD 可无障碍移植**、**Apple 通过 opensource.apple.com 持续发布 Darwin 源代码** 均是阶段性和解的具体显现，此和解不消解结构性不对称但缓解其张力。freebsd.duckdb 一手数据印证此合图：freebsd-src 仓库 2009-2011 年间 `@apple.com` 域名 commit 数量稀少［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 反映 Apple 工程师未直接向 FreeBSD 主线提交代码，但 freebsd-ports 仓库 2009-09-23 Sedov 移植 libdispatch 反映 FreeBSD 社区自主吸收 Apple 的开源回馈——此即“Apple 选择性开源 →FreeBSD 自主移植”的非对称流动格局的延续。

**史观**：总纲第 13 条——法律与道德是利益分配：BSD 许可证的法律合法性与 Apple 商业模式的利益分配是两个层面，合图层不将二者混淆；总纲第 19 条——解释学循环与权力知识共谋：批判方、反批评方、再回应方在解释学循环中对话，合图层承认各方视角的局部合理性而非绝对化任何一方；总纲第 6 条——和解优于斗争：阶段性和解（libdispatch Apache 2.0 开源、Darwin 源码公开、Hubbard 中介作用）不消解结构性不对称但缓解其张力；总纲第 8 条——本体论上各方平等：Apple 与 FreeBSD 在本体论上地位相等，合图层不将 Apple 叙述为“掠夺者”亦不将 FreeBSD 叙述为“受害者”，而还原为两个本体论平等主体在代码与人才层面的非对称交往
