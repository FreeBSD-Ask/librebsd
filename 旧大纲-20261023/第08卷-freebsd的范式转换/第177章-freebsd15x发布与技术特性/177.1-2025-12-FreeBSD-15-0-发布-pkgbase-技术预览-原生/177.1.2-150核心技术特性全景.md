# 177.1.2 15.0 核心技术特性全景

**要点**：15.0 带来的核心技术变更包括但不限于：① **pkgbase（打包基本系统）** 作为技术预览引入——基本系统可通过 **pkg(8)** 软件包管理器安装与管理，**bsdinstall(8)** 提供 “Distribution Sets（传统方式）” 与 “Packages（pkgbase 新方式）” 两种安装选项，传统方式计划在 16.0 移除，pkgbase 是 VM 镜像与公有云镜像的默认方式；② **原生 ** inotify(7)** 实现**——不再依赖 Linux 兼容层的 inotify 模拟，原生实现简化了 Linux 桌面应用移植与目录监控；③ OpenZFS 升级至 **2.4.0-rc4**（含 RAIDZ expansion 在线扩容、vdev initialization、fast dedup、zstd 快压缩改进、contiguous dirty dnodes 等长期需求特性）；④ OpenSSL 升级至 **3.5.4 LTS**——支持 QUIC 协议与已标准化的后量子算法（ML-KEM、ML-DSA、SLH-DSA）；⑤ OpenSSH 升级至 **10.0p2**——**默认启用后量子密钥交换**（ML-KEM-512 混合密钥交换），这是主流 OS 中首批默认启用抗量子计算密钥交换的系统之一；⑥ 默认工具链 Clang/LLVM 升级至 **19.x**（15.1 将跟进至更高版本）；⑦ 所有平台（包括 32 位兼容层）完成 **64-bit time_t** 转换，彻底解决 Y2038 问题；⑧ LinuxKPI（Linux Kernel API 兼容层）大幅改进，对齐 Linux 6.x API，以支持从 Linux 移植的现代 GPU 驱动（drm-kmod）与 WiFi 驱动（iwlwifi/rtw88/rtw89）；⑨ KTLS（内核 TLS）TLS 1.3 发送/接收双向卸载默认完善；⑩ **pf(4)** 防火墙改进（syncookie 默认、dummynet 集成等）；⑪ bhyve 虚拟化改进（Intel AMX 支持、更多设备模拟、**p9fs(4)** Plan 9 文件系统共享在 15.1 完善）；⑫ **makefs(8)** 成熟支持 ZFS 镜像无需 root 构建；⑬ **fwget(8)**/**fwctl(8)** 固件管理框架完善；⑭ Linux 兼容层（Linuxulator）改进，支持 Ubuntu 24.04/Debian 12 用户态，Wine/Proton 兼容性持续提升

**史观**：总纲第 17 条——软件工程：pkgbase 的引入是 FreeBSD 基本系统软件包管理范式的根本转变——自 1993 年以来，FreeBSD 基本系统一直通过 “distribution sets”（tar 分发软件包）与 **freebsd-update(8)** 管理，pkgbase 将基本系统与第三方软件包统一到同一个软件包管理框架下；这一转变的工程意义不亚于 2012 年 **pkg(8)** 取代旧 pkg_* 工具——那次是第三方软件包管理现代化，这次是基本系统本身的软件包管理现代化；无需 root 的构建流程则是现代软件工程 “最小权限原则” 在发布工程中的具体实践

**辨析**：关于 “默认 shell 从 tcsh 改为 sh” 的说法需精确澄清——14.0 已将 **root 用户默认 shell 从 csh/tcsh 改为 /bin/sh**（BSD Bourne Shell），15.0 延续了这一改变并进一步改进了 /bin/sh 的交互使用体验，但 **并非 15.0 新引入的变化**；**wg(4)** WireGuard 驱动状态——14.0 已集成 **wg(4)** 但未默认编入 GENERIC，15.0 中 **wg(4)** 持续完善但仍需手动加载；OpenZFS 版本为 **2.4.0-rc4** 而非某些来源所说的 2.3——2.4 系列包含 RAIDZ expansion 等 2.3 没有的重大特性，但标记为 rc 表明某些边缘功能仍在稳定化过程中；**后量子密码学默认启用** 是 15.0 最具前瞻性的安全特性——OpenSSH 10.0p2 默认使用 <sntrup761x25519-sha512@openssh.com> 混合密钥交换（结合 X25519 与 ML-KEM-768 近似版本），确保即使量子计算机出现也能保证 SSH 连接的前向安全性
