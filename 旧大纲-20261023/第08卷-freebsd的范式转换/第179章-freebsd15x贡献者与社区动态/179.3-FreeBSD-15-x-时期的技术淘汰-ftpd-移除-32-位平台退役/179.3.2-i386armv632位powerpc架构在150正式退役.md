# 179.3.2 i386/armv6/32 位 powerpc 架构在 15.0 正式退役

**要点**：FreeBSD 15.0-RELEASE 正式退役 i386、armv6、32 位 powerpc 三大 32 位硬件平台，仅 armv7 作为 “最后支持的 32 位平台” 保留 Tier-2 支持；32 位应用兼容性通过 64 位平台的 lib32 兼容层延续，lib32 本身不在退役范围；Core Team 于 2023.2 公布 32 位平台弃用计划，John Baldwin（约翰·鲍德温）（<jhb@FreeBSD.org>）于 2025.6.18 在 freebsd-arch 邮件列表详述退役时间线——2025.6 起在 main 分支禁用 i386 内核配置并将 32 位 powerpc 移出 universe 默认目标列表、停止 i386/powerpc 的 release 镜像构建与二进制包构建、禁用 CI 作业；2025.9 stable/15 分支后排除 i386/powerpc 的 CI 与包构建；BSDCan 2026 devsummit 评估 stable/14 弃用平台是否受 MFC 影响，决定是否开始从 main 删除 i386/powerpc 内核代码；最终在 14.x 最后一个版本（2027.9）后将退役代码 MFC 至 stable/15

  **32 位平台在 15.0 的退役状态**：

  | 平台 | 15.0 状态 | 说明 |
  |---|---|---|
  | i386 | 退役 | 2025.6 起禁用内核配置、停止镜像与包构建 |
  | armv6 | 退役 | - |
  | 32 位 powerpc | 退役 | 移出 universe 默认目标列表 |
  | armv7 | 保留 Tier-2 | “最后支持的 32 位平台” |
  | lib32 兼容层 | 保留 | 64 位平台上的 32 位应用兼容性延续 |

**史料**：FreeBSD 15.0-RELEASE Release Notes（Architectures 部分）、John Baldwin 2025.6.18 freebsd-arch “Deprecation of i386 and 32-bit powerpc for 15.0” 邮件、Core Team 2023.2 32 位平台弃用公告、FreeBSD Platforms 页面（i386/powerpc/armv6 列为 Unsupported） ［A］

**史观**：总纲第 22 条——知识注定过时：32 位平台退役是 FreeBSD 对硬件代际更替的工程回应——AMD 64 位 Opteron 2003.4.22 发布至今已逾 22 年，与 Intel 8086 1978 发布时 x86 整体年龄相当；总纲第 25 条——终结与延续：32 位 “硬件平台” 终结但 32 位 “应用兼容性” 通过 lib32 延续，体现 BSD 项目 “终结以延续为前提” 的工程哲学（本节两处原伪标签“总纲第 7 条——硬件与软件辩证／总纲第 25 条——终结与延续”已按权威表分别订正为总纲 22／总纲 4）

**辨析**：须严格区分 “32 位硬件平台退役” 与 “32 位应用兼容性移除” 两类事实——前者为 15.0 实际事件，后者并未发生且按 Colin Percival 在 freebsd-arch 邮件中的回应 “Hopefully never” 明确不会发生；社区讨论中出现 Vadim Goncharov 等用户对 32 位虚拟机构建持续需求的关切，反映退役决策对低内存虚拟机场景的影响；15.1 公告提到提供实验性 i386 VM 镜像，但这仅为测试目的，不代表 i386 重新成为 RELEASE 架构；与 Debian 13（2025.8）与 Ubuntu 19.10（2019.10）相继弃用 x86-32 的趋势一致，体现 64 位化在 2020 年代中后期成为开源操作系统普遍选择
