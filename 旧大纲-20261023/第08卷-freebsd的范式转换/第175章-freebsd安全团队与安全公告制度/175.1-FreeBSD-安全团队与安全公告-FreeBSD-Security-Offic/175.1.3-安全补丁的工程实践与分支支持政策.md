# 175.1.3 安全补丁的工程实践与分支支持政策

**要点**：分析 FreeBSD 安全补丁的工程实践——补丁开发遵循与普通提交相同的代码审查流程但优先级更高；安全补丁需同时应用于 head（current）和所有受支持的 stable/releng 分支；安全支持分支政策（EOL）经过多次调整，目前每个 major 版本提供约 5 年安全支持；安全补丁回溯（backport）是安全团队的重要日常工作，需确保补丁在旧分支上的兼容性和正确性

**史料**：FreeBSD 安全支持周期页面、src 仓库中安全补丁的 commit 记录（带 Security: 标记）、Release Engineering 团队文档、FreeBSD 基金会关于安全支持的声明、stable 分支的安全补丁测试流程 ［A］

**史观**：专题语（不设总纲条号）——开源安全协作（原挂总纲第 22 条系伪名目）：安全补丁的多分支同步维护是开源社区 “负责任的安全实践” 的体现——不仅修复最新版本的问题，还要为生产环境中广泛使用的稳定分支提供安全支持，这是企业级用户选择 FreeBSD 的重要原因之一

**辨析**：EOL 政策的严格执行（到期后不再提供安全补丁）既是对用户的负责（明确预期）也可能带来安全风险（用户升级不及时则暴露于已知漏洞）；安全补丁回溯的质量保证是工程难题——旧分支上的补丁可能因代码差异而引入新问题，如何在 “快速响应” 与 “质量保证” 之间取得平衡是持久的挑战
