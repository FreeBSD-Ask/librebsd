# 178.3.1 Linux 6.12-6.18：Rust for Linux、sched_ext BPF 调度器与 AI 时代的 Linux 演进

**要点**：15.x 同期（2025-2026）Linux 内核持续演进：Linux 6.12（2024.11）合入 **sched_ext** 框架（BPF 可编程调度器），允许通过 eBPF 程序在用户态编写自定义调度策略；Linux 6.14（2025.3.24）标记 sched_ext 为稳定、同时标记 **Rust for Linux** 为 “可用于新驱动开发”（即 Rust 支持从实验性升级为可用，但仅推荐用于新驱动而非重写现有代码）；Linux 6.18（2025.11）是 2025 年最后一个主要版本；Linux 持续在 eBPF 生态、云原生支持（容器、Kubernetes 优化）、新硬件支持（Intel/AMD/NVIDIA GPU、NPU/AI 加速器）、内存安全（Rust 驱动）等领域快速迭代；Linux 6.6 LTS（2023.11）仍是多数企业发行版采用的 LTS 版本，6.12 是较新的 LTS 版本

  **15.x 同期 Linux 内核版本时间线**：

  | 版本 | 发布时间 | 关键特性 |
  |---|---|---|
  | Linux 6.6 LTS | 2023.11 | 多数企业发行版采用的 LTS |
  | Linux 6.12 LTS | 2024.11 | **sched_ext** BPF 可编程调度器 |
  | Linux 6.14 | 2025.3.24 | sched_ext 稳定、**Rust for Linux** 标记可用于新驱动 |
  | Linux 6.18 | 2025.11 | 2025 年最后一个主要版本 |

**史观**：总纲第 4 条——分离聚合是永恒规律（原“技术路线分化”系伪名目，按族例改挂）：Linux 与 FreeBSD 在 2020 年代的技术路线分化日益明显：Linux 走 “快速迭代、拥抱新功能、Rust 渐进引入、BPF 可编程一切” 路线；FreeBSD 走 “保守稳定、小 base 哲学、Ports 提供新软件、审慎评估 Rust” 路线；两种路线各有适用场景——Linux 主导云原生、AI 训练、新硬件支持领域；FreeBSD 在网络设备（Juniper、Netgate）、存储（TrueNAS、Netflix CDN）、嵌入式等领域保持强势

**辨析**：“Rust for Linux 稳定” 不等于 “Linux 内核大量使用 Rust”——截至 2026.7，Linux 内核中 Rust 代码量仍非常有限（主要是一些示例驱动与基础设施），绝大多数核心内核仍为 C 代码；sched_ext 是一个有趣的实验，但生产环境中绝大多数 Linux 系统仍使用默认调度器（EEVDF 或 CFS）；FreeBSD 的 kern.sched.name（15.1 引入）与 Linux sched_ext 目标不同——前者是内核内调度器模块选择，后者是 BPF 可编程调度器框架
