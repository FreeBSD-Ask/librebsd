# 178.1.3 Rust 与 C/C++ 在 FreeBSD 生态中的共存展望

**要点**：截至 2026.7，Rust 在 FreeBSD 生态中的实际状态是：Ports 中已有成熟的 Rust 工具链与大量 Rust 编写的第三方软件（如 ripgrep、exa、fd-find、rustc 本身、Firefox 部分组件等）；FreeBSD 内核中 **没有** Rust 代码；base system 中 **没有** Rust 组件；但社区讨论中逐渐形成一种可能的渐进路径：① 先在 ports 中持续维护 Rust 工具链的高质量支持；② 允许用 Rust 编写一些可选的用户态工具（如新的管理工具、测试工具）作为 ports 存在；③ 考虑引入 Rust 标准库到 base 以支持 Rust 编写的 base 组件（如果/当共识形成）；④ 内核 Rust 支持是非常远期的可能性（即使在 Linux 中也仍处于实验阶段）；16.0（预计 2027-2028）周期内是否会有 Rust 组件进入 base 仍是未知数

  **Rust 进入 FreeBSD 生态的渐进路径**：

  | 阶段 | 内容 | 状态（截至 2026.7） |
  |---|---|---|
  | ① | ports 中持续维护 Rust 工具链高质量支持 | 已实现 |
  | ② | 允许 Rust 编写可选用户态工具作为 ports 存在 | 部分实现 |
  | ③ | 引入 Rust 标准库到 base 以支持 Rust 编写的 base 组件 | 讨论中 |
  | ④ | 内核 Rust 支持 | 非常远期（Linux 中仍实验阶段） |

**史料**：FreeBSD Ports Collection lang/rust 目录与相关 Rust 应用 port 历史；freebsd-arch@ 邮件列表 Rust 架构讨论 ［A］

**史观**：专题语（不设条号）——技术路线分化：C 语言与 Rust 在操作系统开发中的争论是 2020 年代最重大的编程语言路线分化——Linux 选择 “实验性支持 Rust 驱动” 路径，OpenBSD 选择 “明确拒绝 Rust” 路径，FreeBSD 选择 “长期讨论、渐进探索” 路径，三种路径各有其哲学基础与工程逻辑；这种分化不是 “谁对谁错” 的问题，而是不同社区在同一技术变革面前基于自身历史与价值观做出的不同选择（原“总纲第 6 条”标号与基线第 6 条“和解优于斗争”不符，按 R2140 先例改不设条号专题语——批次 C275 问题 1）

**辨析**：需警惕两种极端叙事——一种是 “Rust 会立刻取代 C 成为 FreeBSD 主要语言”（不现实，30 多年 C 代码不可能重写），另一种是 “Rust 永远不会进入 FreeBSD base”（过于绝对，技术演进往往超出预期）；合理预期是：未来数年内 Rust 可能以有限方式进入 FreeBSD 生态（如某些可选工具、测试基础设施），但 C 语言仍将是 FreeBSD 内核与 base 系统的主导语言
