# 180.1.3 第三方软件变更的史料辨析

**要点**：15.0 的第三方软件变更以 “加密组件现代化” 与 “工具链持续升级” 为主题——OpenSSL 3.5/OpenSSH 10.0 的后量子加密支持是安全层面的前瞻性升级，Clang 20 是工具链层面的持续改进。15.0 的变更与 10.0/14.0 的模式不同——10.0 是 “集中引入新组件”，14.0 是 “集中退役旧组件”，15.0 是 “持续升级 + 架构收缩”——新组件升级（OpenSSL 3.5、OpenSSH 10.0、Clang 20）是持续改进，无类似 10.0 的 “集中换代” 事件；架构收缩（i386 降级、32 位架构退役）是资源聚焦而非技术创新。

  **FreeBSD 10.0/14.0/15.0 第三方软件变更模式对照**：

  | 版本 | 变更模式 | 主要变更 |
  |---|---|---|
  | 10.0（2014） | 集中引入新组件 | compiler/debugger/DNS/installer/MTA 等多项替换 |
  | 14.0（2023） | 集中退役旧组件 | sendmail→DMA、telnetd 移除、root shell 切换等 |
  | 15.0（2025） | 持续升级 + 架构收缩 | OpenSSL 3.5/OpenSSH 10.0/Clang 20 升级、i386 降级、32 位架构退役 |

**史观**：总纲第 25 条——终结与延续：15.0 的 i386 降级是 “终结”，OpenSSL 3.5/OpenSSH 10.0 的后量子加密支持是 “延续”——FreeBSD 在收缩硬件支持范围的同时，在加密安全领域持续前瞻性投入，这是资源有限的开源项目必须做出的权衡

**辨析**：15.0 的第三方软件变更 “规模” 小于 10.0 和 14.0——10.0 有 compiler/debugger/DNS/installer/MTA 等多项替换，14.0 有 sendmail→DMA/telnetd 移除/root shell 切换等多项变更，15.0 的变更集中在加密组件升级和架构降级，这反映了 FreeBSD 在 30 周年后 “稳定优于变革” 的工程哲学——大规模组件替换已完成，后续版本集中于持续改进和架构优化
