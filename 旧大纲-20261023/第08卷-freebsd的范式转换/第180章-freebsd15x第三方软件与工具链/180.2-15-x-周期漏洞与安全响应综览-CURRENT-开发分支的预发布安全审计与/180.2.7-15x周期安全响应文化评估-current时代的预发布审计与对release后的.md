# 180.2.7 15.x 周期安全响应文化评估——-CURRENT 时代的预发布审计与对 RELEASE 后的预测

**要点**：15.x 周期（-CURRENT 阶段）的安全响应文化与 14.x 周期（stable + releng 多分支维护）形成鲜明对比——① **无 SA 公告流程**：-CURRENT 阶段所有 CVE 修复直接合入 main 分支，不经过 SA 披露流程，管理员无需在 -CURRENT 上处理 SA 补丁；② **审计密度更高**：383 条 CVE commit（半年）vs 14.x 周期 648 条（约 2 年 8 个月），月均密度 15.x 约 55 条 vs 14.x 约 20 条——15.x 周期审计密度约为 14.x 的 2.7 倍；③ **核心贡献者集中**：Mark Johnston（约 150 条 commit）、Gordon Tetlow（约 30 条，OpenSSL 批量修复）、Mariusz Zaborski（约 25 条，libnv/libcasper）、Ed Maste（约 20 条）、John Baldwin（约 15 条，ktls）等核心 Security Team 成员主导；④ **dma(8) 作为默认 MTA 消除 sendmail CVE 后续风险**：自 14.x 切换至 **dma(8)** 后，15.x 周期 base 系统不再有 sendmail 相关 CVE，这是 “减法” 型架构现代化的安全收益；⑤ **pkgbase 推进改变安全更新分发**：15.x 推进 pkgbase（基本系统软件包化），用户可通过 **pkg(8)** 更新 base 系统组件，安全补丁分发机制从 freebsd-update(8) 单一渠道转向 freebsd-update(8) + pkg(8) 双渠道；⑥ **对 RELEASE 后的预测**：当 stable/15 分支创建后，SA 公告流程将恢复——但由于 -CURRENT 阶段已密集修复大量 CVE，stable/15 的初始 SA 数量可能低于 14.x 同期

  **15.x vs 14.x 安全响应文化对比**：

  | 指标 | 15.x 周期 | 14.x 周期 |
  |---|---|---|
  | 阶段 | -CURRENT 开发阶段 | stable/14 + releng/14.x 多分支维护 |
  | 周期长度 | 半年（2026.1.1-2026.7.22） | 约 2 年 8 个月（2023.11-2026.7） |
  | CVE commit 总数 | 383 条 | 648 条 |
  | 月均密度 | 约 55 条 | 约 20 条 |
  | 密度倍数 | 约为 14.x 的 2.7 倍 | 基准 |
  | 分支结构 | main（-CURRENT）单分支 | stable/14 + releng/14.x 多分支并行 |
  | SA 公告流程 | 无 SA 流程（-CURRENT 阶段） | 有 SA 公告（跨分支补丁协调） |
  | 核心贡献者 | Mark Johnston 约 150 条 commit | 多名 Security Team 成员分担 |

  **15.x 周期安全响应六大特征**：

  | 序号 | 特征 | 说明 |
  |---|---|---|
  | ① | 无 SA 公告流程 | -CURRENT 阶段所有 CVE 修复直接合入 main，不经 SA 披露 |
  | ② | 审计密度更高 | 383 条 commit（半年），月均约 55 条，约为 14.x 的 2.7 倍 |
  | ③ | 核心贡献者集中 | Mark Johnston 约 150 条、Gordon Tetlow 约 30 条、Mariusz Zaborski 约 25 条、Ed Maste 约 20 条、John Baldwin 约 15 条 |
  | ④ | **dma(8)** 消除 sendmail CVE 后续 | 自 14.x 切换至 **dma(8)** 后，15.x base 不再有 sendmail CVE |
  | ⑤ | pkgbase 推进改变分发 | 安全补丁从 **freebsd-update(8)** 单渠道转向 **freebsd-update(8)** + **pkg(8)** 双渠道 |
  | ⑥ | RELEASE 后预测 | stable/15 创建后 SA 流程恢复，但初始 SA 数量可能低于 14.x 同期 |

**史料**：**freebsd.duckdb** `commits` 表 freebsd-src 仓库 15.x 与 14.x 周期 CVE commit 密度对比查询——15.x：`SELECT count(*) FROM commits WHERE repo_name='freebsd-src' AND author_date>='2026-01-01' AND author_date<'2026-07-22' AND (message_subject LIKE '%CVE-%' OR message_body LIKE '%CVE-%')` 结果 383；14.x：`SELECT count(*) FROM commits WHERE repo_name='freebsd-src' AND author_date>='2023-11-01' AND author_date<'2026-07-22' AND (message_subject LIKE '%CVE-%' OR message_body LIKE '%CVE-%')` 结果 648；15.x 周期主要贡献者 commit 统计（按 author_name 分组）；FreeBSD Security Officer Team 历史成员名单（Mark Johnston、Philip Paeps、Gordon Tetlow 等）；OpenBSD errata 发布政策［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 23 条——社区治理：15.x 周期 “-CURRENT 阶段预发布审计” 模式标志着 FreeBSD 安全文化的进一步成熟——Security Team 在 -CURRENT 阶段密集修复 CVE，将漏洞消灭在发布前；这一模式与 OpenBSD 的 “-current 审计 → release 稳定” 流程趋同，但 FreeBSD 的 -CURRENT 周期更长（通常 2 至 3 年），审计窗口更大；核心贡献者的高度集中（Mark Johnston 一人约 150 条 commit）反映 Security Team 的人力资源瓶颈——这一瓶颈在 14.x 周期已显现，15.x 周期进一步加剧；dma(8) 替代 sendmail 与 pkgbase 推进是 “减法” 与 “加法” 并行的架构现代化——减法消除历史 CVE 来源，加法改进安全更新分发

**辨析**：**需精确说明 -CURRENT 与 stable 的区别**：① -CURRENT（main 分支）是开发分支，无 ABI 稳定性保证，用户群体为开发者和测试者；stable/N 分支是稳定分支，ABI 稳定，用户群体为生产环境；SA 公告仅针对 stable 与 releng 分支，-CURRENT 修复不发布 SA；② **15.0-RELEASE 是否已发布存在考据矛盾**——版本周期文件标注 “15.0-CURRENT 开发中（截至 2026.7）”，但现有大纲其他节记载 15.0-RELEASE 于 2025 年 12 月发布，本节采信版本周期文件的数据 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；③ **审计密度对比的辨析**：15.x 周期 383 条 commit 的高密度部分源于 14.x 周期遗留 CVE 的集中清理（如 Heimdal 历史漏洞），不全部是 15.x 新引入代码的漏洞；④ **核心贡献者集中的风险**：Mark Johnston 一人承担约 40% 的 CVE 修复 commit，存在 “bus factor” 风险——这是 FreeBSD Security Team 长期面临的人力资源挑战
