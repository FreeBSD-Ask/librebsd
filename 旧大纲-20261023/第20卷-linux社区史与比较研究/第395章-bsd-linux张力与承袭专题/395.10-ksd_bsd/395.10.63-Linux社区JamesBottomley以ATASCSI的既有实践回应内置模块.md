# 395.10.63 Linux社区JamesBottomley以ATASCSI的既有实践回应内置模块

- 【Linux社区】James Bottomley：以 ATA/SCSI 的既有实践回应内置模块依赖问题——**“你有没有考虑过使用 transport template 或 attribute container？我们就是这样管理 ATA/SCSI 里那些复杂层级的”**；并展示其依赖链 **“ata_dev->transport->ata->scsi（或 SCSI 里的 dev->transport->scsi）……我们的链比这复杂得多，因为我在探测开始之前就停住了，而探测是异步的”**；其化解办法是 **“ata 与 scsi 都用 subsystem_init 处理各自的独占资源，这意味着它们与顺序无关；探测由硬件模块启动，所以走 module_init（即 subsystem_init 之后），同样与顺序无关。其余依赖性的初始化在 transport/attribute 代码里完成，也就是说直到某个消费者真正被实例化时才做”** `<!-- ROW_MINE: ksummit-discuss.messages.346995 -->`
- 【Linux社区】James Bottomley：补完上封未写完的论点——**“基本要点是，你可以通过把初始化拆成一个子系统部分（保证在任何设备被探测之前）与一个设备部分（可以在设备实例化时做）来化解大部分‘依赖’问题”** `<!-- ROW_MINE: ksummit-discuss.messages.346996 -->`

- 【Linux社区】James Bottomley：交代 transport class 的历史与适用范围，并提出其一般化的“可分离性定理”——**“transport class？据我所知只有 SCSI 及其依赖子系统。它已经存在很久了（我记得是 2004 年；有一篇 OLS 论文），但此前只有我们有那种复杂依赖问题，尤其是它为之设计的驱动/传输分离”**；其哲学表述是 **“基本原理是可分离性定理：任何一组可分离的问题，如果你用错误的方式看它们，都可以被弄得任意复杂。推论是：任何极其复杂的相互依赖，也许只要换一种方式看问题就可以变得不必要。事实证明，只要我们以正确的方式看待，我们大多数的复杂依赖问题都能消失”** `<!-- ROW_MINE: ksummit-discuss.messages.347000 -->`
