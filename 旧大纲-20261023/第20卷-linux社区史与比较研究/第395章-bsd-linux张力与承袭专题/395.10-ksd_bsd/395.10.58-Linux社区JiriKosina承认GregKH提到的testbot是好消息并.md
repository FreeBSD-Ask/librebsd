- 【Linux社区】Andy Lutomirski：提出把密钥与策略管理大幅下移到 bootloader 的架构提案——**主张“把那个支点提前，不再操心把信任根烘焙进内核镜像”：“如果我们决定以某种明确定义的方式信任 bootloader（或其他内核之前的代码），这个两难就消失了；如果你想要求由静态密钥签名，就把那个密钥烘焙进*bootloader*而不是内核”**；据此列出分工（bootloader 向内核提供公钥与策略、按需验证 initramfs/命令行/设备树，内核用模块哈希加 bootloader 提供的密钥验证模块、按 bootloader 策略初始化 IMA 与/或 dm-verity、按需用密钥与策略扩展 PCR），并指出现有 **certs/ 目录** 那套做法 **“让我们自己的处境比必要的复杂得多”**；给出跨架构的具体机制：**定义 struct trusted_policy_header { unsigned long size; }，调整链接脚本使 trusted_policy 位于内核虚拟地址空间最末端并独占一个 ELF 段（filesize == 0、memsize == sizeof(header)）、标记该段使 bootloader 知晓，bootloader 只需把策略写入该处即可提供密钥与任何它想要的东西**；附带好处是 **“可以很容易地写个工具把策略追加到已编译内核镜像——字面上追加到 ELF 文件末尾并相应调整 program table”，从而使“构建过程最终相当简单”** `<!-- ROW_MINE: ksummit-discuss.messages.346878 -->`
