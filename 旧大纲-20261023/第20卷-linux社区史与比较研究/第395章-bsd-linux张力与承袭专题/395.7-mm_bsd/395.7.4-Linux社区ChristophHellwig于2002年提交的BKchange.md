# 395.7.4 Linux社区ChristophHellwig于2002年提交的BKchange

- 【Linux社区】Christoph Hellwig 于 2002 年提交的 BK changeset 将 madvise(2) 从 filemap.c 拆分为独立源文件，changeset 署名行写作 “ChangeSet@1.490, 2002-08-17 23:43:39+02:00, hch@sb.bsdonline.org”，邮箱域名带 BSD 字样。补丁正文为常规 Linux VM 代码整理，扩展 mmap.c 的 splitvma() 以便清理 madvise 函数并删除大量重复代码，不含 BSD 技术论述。BSD 关联仅体现在作者所用域名的 BSD 命名，属 BSD 与 Linux 内核开发之间的人员交叉线索。`<!-- ROW_MINE: linux-mm.messages.807952 -->`
- 【Linux社区】Andi Kleen 在 2000 年 Linux 2.3.99-pre6-3 VM 再平衡补丁讨论中反驳全局 LRU 方案的公平性，认为内存大户可以高速分配并弄脏页面，从而挤占小型守护进程的换出资源。他转而援引 FreeBSD 作为参照，原文引语 “At least the FreeBSD code i have here has a way to limit maximum swapout per process.”，并说明该限额会随驻留页 rlimit 递增，同时断言 Linux 在新机制下同样需要这类限制。这是 Linux VM 换页公平性设计显式对标 BSD 实现的早期史料，直接记录了 FreeBSD 每进程换出上限与驻留页 rlimit 的联动机制。`<!-- ROW_MINE: linux-mm.messages.807999 -->`
- 【Linux社区】KAMEZAWA Hiroyuki 于 2012 年 3 月回复 memcg 的 __GFP_NOACCOUNT 补丁评审时，嵌套引用链条完整保留了提交者的 FreeBSD 组织署名，即 “Suleiman Souhlal <ssouhlal@FreeBSD.org> wrote:”。讨论焦点为 GFP 标志命名争议，KAMEZAWA 反对过宽地把 slab 分配统一记账，主张从 dcache、icache 等可回收缓存小步开始；Souhlal 则主张覆盖进程上下文下的全部 slab 分配并质疑逐次标记的做法。补丁本体属常规 memcg 设计讨论，BSD 关联仅存在于作者署名归属。`<!-- ROW_MINE: linux-mm.messages.808501 -->`
- 【Linux社区】2003-10-13 Roger Luethi 在 struct rusage 的 ru_majflt 计数 RFC 中指出 Linux 的实现既不同于 BSD、也不同于字段名本身的含义，并明确点出该结构体正是从 BSD 移植而来，原话为 “neither what BSD (where Linux got its copy of the struct from) does”。William Lee Irwin III 据此提出把 pgmajfault 自增上提到 do_no_page 的补丁。这是 Linux 内存与 VFS 接口层继承 BSD 谱系的直接文本证据，说明 rusage 家族结构体在语义上存在 BSD 与 POSIX 文档的双重基准。`<!-- ROW_MINE: linux-mm.messages.809262 -->`
- 【Linux社区】2002-09-05 Rik van Riel 在 MAP_SHARED 处理讨论中回应 Andrew Morton 关于 dirty page 重新绕回 LRU 列表的建议，直接援引 FreeBSD 的内核实践作为先例，原话为 “FreeBSD is doing this and seems to be getting good results with it”，并据此预期 Linux 的 VM 也会随之改善。这是 Linux 虚拟机团队主动引用 FreeBSD 内核机制的跨内核技术借鉴证据。`<!-- ROW_MINE: linux-mm.messages.810471 -->`
