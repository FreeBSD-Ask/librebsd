# 403.1.2 11.1 【Linux社区】printk 收尾：反过度设计与串口之争

**要点**：Linus：guys you're overdesigning——旧 printk 的 continuation 无人用（坏了都没人报）；sequence+时间戳也不会有人用；真正会被用的是“数码相机拍屏”和 dmesg 输出（dmesg 也不用 seq）；这两条不是首要目标则讨论无意义，cool features/性能/理论死锁规避与之相比一文不值；Rostedt：critical prints 正是我原信 #1——相机永远只能抓住一个 backtrace，而第 5 个 backtrace 的根因常被前 4 个副作用冲掉；最好第一个 bug 就停内核；printk 用得太过——提出“info-only”带外 printk，或干脆审计删减多余 printk；死锁报告非理论、大机器真实发生；debug printk 应转 trace point（要 config 的用户常常开不了）；Al Viro：我敢怕拍屏……printk 到串口 console 必须继续工作；不在乎时间戳粒度，但失去这个用例很伤；这真的是不常见用例吗？；Lunn：嵌入式世界就是这样运作的——RS232，或更常见的 RS232+内置 USB-RS232 转接器（host 端用 USB）；这就是串口用例的现实；Linus：不是说串口不能是选项，但对大用户群它不是——PC/DC 都没串口了；死机时 oops 常出在中断/盘层里到不了磁盘；netconsole 有已知问题但“总比没有强”，绝不作默认；USB 对死机无效（除非 debug dongle）；console 死锁大概不值得修，目标是“dmesg 存不住时 console 大多时间能开”（>>99%）；乱序可活，但一条都没有——因抽象进 buffer 等 IO 而永远打不出来——才是灾难；Jiri：数据中心反例——中高端无 UART 芯片但固件模拟、RJ-45 串口集中器 → telnet/串口客户端，DC 里很常见；IPMI 良好的机器也带；Sergey：疯狂想法——标记 logbuf 第一条 panic 条目永不丢弃；满时丢新不丢旧；周期重放 logbuf（从 panic 条目起）让相机更容易拍到；panic_timeout 已有，可加 panic_reflush_console_timeout 分支：刷新到串口/early console/或新回调 emergency_write()（uart_console_write 不锁 port->lock）；重放应该无碍（反正都要刷）

- 【Linux社区】Linus在printk重新设计讨论中直言各方过度设计，指出旧printk的continuations功能无人使用，序号与时间戳同样无人会去使用，强调屏摄数字相机与dmesg输出才是printk的绝对首要目标，其余特性与此相比皆无关紧要。
