# 311.2.25 告别GPL文章的作者归属在转写中存在噪声主持人将文章与localfirstsof

- “告别 GPL”文章的作者归属在转写中存在噪声：主持人将文章与 local-first software 论文作者（Kleppmann 等）并置转述，作者身份与论文关系须以原文署名核实。[存疑脚注] 转写将 Martin Kleppmann 读作文章作者，须核对原文署名 [存疑脚注] 文章作者身份与 local-first 论文作者关系系主持人转述，转写噪声明显，须以原文署名核实（BSD Now EP402，[322.02-349.9]，L4）
- Xenix 时间线作者自称 1986 年入职时为团队最资浅者，1986 年前的 OEM 关系其本人无亲历知识，时间线系资深同事协作成果；转写未署名，人物归属待考。[考据脚注] 时间线作者姓名在转写中缺失，须回溯原文核对 [存疑脚注] Xenix 时间线作者身份未署名，1986 年前内容系二手追述（BSD Now EP402，[949.5-962.14]，L4）
- 主持人“广告条款几乎已从所有软件中消失”的说法系概括性陈述：4-Clause BSD 广告条款于 1999 年由 UC Berkeley 正式废除，但“remnants 存在与否”无法在对话中核验。（BSD Now EP402，[585.46-592.34]，L2）
- OpenBSD RISC-V 初始支持的功劳归属存在两层：commit 落于 Dale Rahn，技术基础是 Bamsch 等人的移植论文；主持人的致谢转述对两代贡献的边界较模糊，引用时宜并置。（BSD Now EP402，[2284.52-2314.22]，L2）
- Dunkels 自述曾以 FreeBSD 为主力操作系统十年，后因笔记本电脑的 USB 存储设备与 CPU 睡眠模式兼容性转用 Windows 宿主，但在 VMware 中继续运行 FreeBSD 做全部开发工作，理由是 BSD 的 tap/tun 网络接口与 sysctl 控制面使协议栈的测量评估极为便利；此为单一当事人使用体验，其关于笔记本硬件支持差异的概括不构成对两系统整体成熟度的评价。 [存疑脚注] 当事人对 FreeBSD 桌面/笔记本体验的负面评价系 2007 年单一用户自述，反映其特定硬件环境，不宜外推为系统级结论（BSDTalk EP107，[1455.53-1548.83]，L1）
- 关于网络文件系统的竞争格局，Macklem 认为 NFS 的强项不在独有特性而在互操作性与 IETF 标准身份：SMB/CIFS 是纯粹的微软协议，外部实现只能被动追赶微软的变动；AFS 近年陷入挣扎，缺乏强力支持，虽有开源实现但协议没有良好定义、真相只在代码之内，且他个人不信任 AFS 在最终用户工作站到服务器场景下的安全性、仅认可其服务器对服务器用途。生态方面他列出当时支持 NFSv4 的系统：Solaris 10 客户端服务器双端、AIX、Linux（仍偏实验性）、Network Appliance 与 EMC 的服务器产品，以及 Hummingbird 为 Windows 提供的双端实现；互操作验证依赖每年一至两次在安纳堡密歇根大学举办的 Connectathon 测试会（他曾多次参加，加州场次费用高昂）。 [存疑脚注] AIX 具体版本号转写作“5.4 or later”，其 NFSv4 引入版本待核；“NSS”按上下文应为 AFS 之误转（BSDTalk EP116，[307.8-423.14, 343.42-361.7]，L1）
- 关于 Theora 与 H.264 的质量之争：YouTube 以“每比特质量更优”为由支持 H.264 而不支持 Theora；当事人承认 Theora 尚不及 H.264，但指出该评价基于数代之前的编码器，此后 Theora 质量已大幅提升，差距会继续收窄。此为当事人辩护，YouTube 立场系转述，两说并陈待跨源验证。（BSDTalk EP189，[1756.34-1801.80]，L2）
- Losher 自认非许可专家，其所述 ISC 许可证与 BSD 许可证“约三处差异”为运维人员的非专业概括，精确条款差异须以 ISC 许可证文本对照 BSD-2-Clause 逐条考据 [存疑脚注]。转写将 ISC 误作“ISE”、FreeBSD 误作“free VSD”，据上下文校正；转写中的“FRUIT”疑为 F-Root 相关项目名之误，具体名称待核。 [存疑脚注] ISC 许可证差异细节系口述概括，法律文本层面的逐条比对仍属待考（BSDTalk EP206，[213.68-244.92]，L4）
- 转写专名失真须全面校核：BBN 被记作 Bermick and Nguyen，应为 Bolt Beranek and Newman；DSP FAST file system 应为 BSD Fast File System；TreeBSD 应为 FreeBSD；PreBSD 应为 FreeBSD；microstation 应为 workstations；Sleepy Cat 应为 Sleepycat。另有一处年代压缩风险：1989 年发布、黑客补齐六文件、1990 年出现独立 BSD 的叙述把 Net/1、Net/2 与 386BSD 的序列压成约数，精确版本学须对照发行物原件。 [存疑脚注] 年代压缩系当事人约数记忆，须以 Networking Release 1（1989）、Release 2（1991）与 386BSD（1992）的原始发行记录复核。（BSDTalk EP18，[267.67-349.19]，L1）
- 可用性失败的历史包袱与新的竞争威胁：开源社区对可用性“做得很糟”，根源是工程传统承自 UNIX 社区，而 UNIX 社区的特征是除用户界面外一切都对；BSD 与 Linux 在复刻原初命令行 UNIX 的目标上其实早已完成，那曾是衡量自身的模型，一旦进入没有现成范本的新领域便出现混乱的界面局面；他因此提出“忘掉 Windows”——纯开源操作系统当下真正的威胁竞争是 Mac OS X：它收编了 UNIX 技术优势与半开源路线的优势，又有漂亮 GUI，开源阵营必须学得更好，否则终将被其夺走午餐；相比之下 OpenSolaris 给他的印象是亦步亦趋，Sun 内部方向反复摇摆，他称等到 Sun 开源 Java 才会有兴趣。（BSDTalk EP38，[755.46-865.42]，L1）
- 主持人称 Darwin 不使用 FreeBSD 内核而使用另一微内核；XNU 实为 Mach 微内核与 BSD 组件的混合内核，该表述反映 2005 年大众话语对微内核标签的通行用法，与内核混合架构的实际不符。[存疑脚注] 主持人非内核开发者，系转述层面口误风险，需以 Apple XNU 源码与 Darwin 文档核证。 [存疑脚注] 主持人对 Darwin 内核的描述与 XNU 混合架构事实不符，属口述简化。（BSDTalk EP1，[223.20-237.60]，L4）[订正：原 [213.90-226.24]，2026-09-29 SenseAudio 重转核对]
- 主持人承认 SunOS 原本基于 BSD 代码、后转 Solaris，但判断仍存活的 SunOS 数量属印象式陈述，无 deployment 数据支撑；引用该期作为 SunOS 存量证据时须另寻统计来源。[存疑脚注] 单一来源印象推断。 [存疑脚注] SunOS 存量流行度为主持人印象，无量化依据。（BSDTalk EP1，[182.06-197.72]，L4）
