- 〔USENIX Security（推测）〕Delphi 的预处理/在线两阶段协议与混合激活函数。主讲人将线性层协议拆成与客户端输入无关的预处理阶段和依赖输入的在线阶段，使客户端与服务端持有 L(x) 的秘密分享、在明文上做线性计算从而 GPU 兼容，把延迟与通信降到 13 秒和 350 MB。针对 ReLU 在两方计算（2PC）成本模型中昂贵的问题，Delphi 的机器学习规划器在给定精度阈值下输出 ReLU 与二次激活混合网络：在 ResNet32/CIFAR-100 上替换 32 层中 26 层的 ReLU 仅损失约 2% 精度（直接换成恒等映射会损失超 10%），端到端推理比 Gazelle 快一个数量级，整体在各项指标上比先前工作高效 9 到 22 倍。（YouTube EPQMWBEFc3RK4，[381.0-727.7]，L1）
- 〔SREcon（推测）〕当 Bash 外壳反击：重访“一切皆自动化”。主讲人 Jay Paul Reid（持有人因与系统安全硕士学位，长期担任构建与发布工程师）用一个发票系统多年演化的故事开篇，并借波音 737 Max（MCAS 系统为维持飞行员熟悉感而叠加软件、FAA 交由波音自证、飞行员早期微弱告警被忽视）与 2012 年骑士资本自动化出错每秒亏损 17 万美元、45 分钟内击垮业务的案例，说明系统长期漂移、需求割裂、测试孤岛如何随自动化累积酿灾。他引入 Bainbridge 1983 年“自动化的悖论”：自动化使操作技能退化、新策略生成依赖系统知识、速度与正确性难以兼得、自动化会掩盖系统当前状态、失败也不明显，且训练操作员执行指令却又要其值守全自动系统本身即是最大悖论。（YouTube EPQN6-5b4FuMM，[9.0-1215.5]，L1）
- 〔SREcon（推测）〕联合认知系统视角与自动化的治理对策。主讲人对比人与自动化在自主性、权限、定向注意力与可重定向性上的差异，指出自动化缺失协调的三大基础，并引 Dave Woods 的论断——技术人常把连通性误当协调性；再借“拟生命悖论”（事后看是确定性机器的 bug，情境中却像 gremlins 捣乱，737 Max 即是 hindsight 与 in-context 的落差）与 Rasmussen 三角（经济失败、不可接受工作负载与事故边界）解释自动化的脆弱性：它无法参与人在 discretionary space 中的补救。对策包括：以 Checklist Manifesto 式双人执行-评审清单提炼需求规格直到清单不再变化、把自动化当有 product owner 的产品并纳入版本控制（low-code 环境尤其危险）、checks over locks、用 chaos engineering/模拟与复盘为操作者“买时间”，以及以限制控制跨度、可分解启停与回溯审计改善协调。（YouTube EPQN6-5b4FuMM，[1216.1-2461.9]，L1）
- 〔SREcon〕SRE 十年回顾：从手工装机到可观测性。主讲人 Heinrich（Zalando 高级首席工程师，曾领导 SRE 组约两年半，此前任监控厂商首席数据科学家）回顾自 2014 年首届 SRECon 以来的进展：从 OmniOS zone 加 pkg/yum 手工装机、年度 RPS 预测与长达一个月的服务上线，演进到 AWS + Kubernetes 基础设施即代码；从 Nagios/graphite/Ganglia 演进到 Prometheus 与 Grafana 胜出，以及 OpenTelemetry 的标准化。他强调真正的可观测性是跨应用调试：Google Dapper 与 Facebook Scuba 的商业后裔 Lightstep（被 ServiceNow 收购）与 Honeycomb 让 Zalando 首页每个请求约 250 个 span（微服务链路可达上千）的分布式追踪可定位故障团队，告警与 SLO 也直接由追踪数据导出。（YouTube EPQSLRWBV7vFY，[16.0-1020.9]，L1）
- 〔SREcon〕可靠性工程的原则与三大前沿。主讲人提出可靠性更大程度是人与沟通问题：应面向用户体验而非保护机器，只对用户路径 SLO 告警，公司越大越需要知识共享、postmortem、weekly operational review 与风险管理（保卫 Cyber Week）。未来五到十年三个前沿：管理可靠性（数百行 Python 脚本自动生成含 incident/SLO/on-call 健康表的可靠性周报，连周与 CTO 评审构成驱动可靠性的“机器”，on-call 每周被打断 10 次即标红由管理层解释）；移动端可观测性（未检出的订单下跌与 Android add-to-cart 被边缘防护误判 bot 流量的事故，推动把 OpenTelemetry 追踪扩展到客户端，尽管 App Store 审核使发布需四周才达 80% 渗透）；数据运维（2022 年欧元事件：非法货币字段令异步目录流水线需三个半小时全量重灌，需数据契约、数据 SLO 与 OpenLineage 式数据血缘，并大胆设想用“HTTP 式管道”重造数据系统集成）。（YouTube EPQSLRWBV7vFY，[1020.9-2327.5]，L1）
- 〔会议不详〕可靠系统利用异构核心：慢核心有时更好。主讲人（与导师 Andy Tanenbaum 及 Herbert Bos 合作，工作基于微内核的多服务器系统）指出把操作系统功能实现为用户态隔离的服务与设备驱动虽提升可靠性，却因各服务只处理请求的一小部分而频繁切换 CPU，带来大量上下文切换与缓存、TLB、分支预测器失效。其设计将部分 CPU 专用于性能关键的服务器进程，并弃用微内核 IPC、改用纯用户态通信，使专用核的快路径完全避开内核；鉴于 OS 代码难以受益于乱序深流水线与多媒体扩展，主张以大量顺序浅流水线小核（如 Intel Xeon Phi，60 余核每核 4 线程）搭配少量大核（Core i7 级），并让硬件线程作为进程上下文的容器由硬件代做上下文切换。（YouTube EPQSR70gL5Qrg，[9.7-649.5]，L1）
- 〔会议不详〕用降频近似慢核的 TCP 实验与结论。因尚无目标硬件，主讲人用双路四核 Xeon 借频率调节与 thermal throttling 模拟低至 200 MHz 的核心，以 TCP 流为基准：TCP 核跑 1600 MHz、IP 与驱动核跑 600 MHz 的配置仅需峰值组合频率的 40%，吞吐反升 5%；全栈跑 200 MHz 仍有约 2 Gbit/s，对桌面/移动场景够用。实验还揭示 CPU 利用率在 30-40% 区间时频繁休眠（monitor/mwait 在 Intel 上是特权指令）引入抖动与开销，而超线程能交织执行、隐藏内存延迟并减少休眠，性能反优于三核方案。结论：核心速度必须匹配服务与负载需求，只有异构核心能提供合宜资源，且性能不能以牺牲可靠性为代价。（YouTube EPQSR70gL5Qrg，[650.1-1104.3]，L1）
- 〔IEEE S&P（推测）〕I/O 高效动态可搜索加密遇上前向与后向隐私。主讲人 Priyanka（UC Santa Cruz 研究生，与香港大学的 Javad、Dimitris 及导师 Yanis 合作）定义动态可搜索加密（DSE）的两大事实隐私保证：前向隐私要求服务器无法将新更新与过往查询关联，后向隐私要求搜索时只学到删除条目的受控信息。过去研究者认为前向隐私与 I/O 效率不可兼得——把同关键词的新条目放到旧条目相邻位置虽提升 locality 却泄露关联，SSD 上的 page efficiency 同理；且 Cash 与 Tassaro 在 Eurocrypt 2014 已证明最优 locality、read efficiency 与最优空间不能同时达成。（YouTube EPQSZ4OIITQTI，[8.1-424.5]，L1）
- 〔IEEE S&P（推测）〕用 oblivious merge 构造 I/O 高效的前向/后向私有 DSE。该工作以 NDSS 2020 的静态-动态编译器 SDA 为起点，但 SDA 更新是摊销的；同文的 SDD 框架虽去摊销，实例化 I/O 高效静态方案（如 one-choice allocation）时会因条目放置是值的直接函数而破坏前向隐私。主讲人提出以 oblivious merge（把 old 索引拷入缓冲区、按关键词字典序与 bin tag 多次 oblivious 排序并辅以线性扫描，全程不泄露关键词、顺序、数量或关联）替换 O-map，得到 I/O 高效的 LSD 框架，并实现 one/two-choice allocation 与 LogN 等方案及多种优化。实验显示搜索时间在 HDD 上最多快 1000 倍、SSD 上最多快 300 倍，渐近更优，RAM 上也略有改善。（YouTube EPQSZ4OIITQTI，[424.5-826.3]，L1）
- 〔会议不详〕Duhu：面向分布式数据处理框架的共享 disaggregated 内存协调。主讲人针对字节可寻址、连接多主机的可组合内存池（SDM 类内存池设备）提出 Duhu：在全局硬件缓存一致的内存池（如 x86 类内存池）中，频繁回失效消息会撑爆互连、限制扩展性，因此改为只在本地缓存一致、无全局一致性的前提下协调跨节点共享。目标框架假设只读所有权模型（单 owner、多 borrower）与类血缘（lineage）重建机制；系统将共享内存池划分为归各节点所有的 segment 以分散协调压力，每个节点内嵌 Duhu 引用管理器，管理本段数据块与元数据并经 in-SDM RPC 通道高效通信。（YouTube EPQSzW-HUIKYs，[18.5-502.9]，L1）
- 〔会议不详〕Duhu 的 in-SDM RPC 通道、故障恢复与评估。get-ref 协议中 owner 节点先追加读锁再更新引用位图并返回对象地址；为消除多消息开销，Duhu 设计了实现在 SDM 中、缓存行对齐的定长环形缓冲区 RPC 通道，用 owner 位与版本位两个状态位保证无人消费脏数据、服务器不会覆写上一 epoch 未消费的响应。节点故障走三步容忍协议：新节点从 SDM 残留元数据重建引用管理器状态、按元数据重放 RPC 请求（幂等操作保证安全）、并依据版本位安全重发响应。在 6 单元原型内存池（10 GB/s 双向带宽）与 Ray 上的评估显示：多阶段 shuffling 端到端最高快 3.39 倍，TPC-H 最受益的 4 个查询平均快 1.26 倍（21 查询平均 1.08 倍），fan-out 工作流中对象获取阻塞时间缩短 2.8-4.2 倍。（YouTube EPQSzW-HUIKYs，[503.4-985.1]，L1）
- 〔IEEE S&P（推测）〕在泄漏的电脑上检查密码：Google 密码泄露检测协议的侧信道分析。主讲人 Jason Kim 指出凭据填充攻击下约 6.9% 的被泄露凭据在其他站点仍然有效，Google 因此在 Chrome 默认内置 password leak detection：以内存困难函数 scrypt 哈希口令、经椭圆曲线 hash-to-curve 映射为点 Q 后用随机盲化因子 a 做模幂盲化，服务器基于盲化值计算含泄露信息的 P，Chrome 用模逆去盲后给出提示。该协议双向保护隐私，但所用密码原语未受硬件安全审视：在本地对手模型下，攻击者计时 scrypt 对大数组 V 的缓存访问时序，以 RockYou 泄露的 1400 多万真实口令构建口令-热图迹字典，5 次测量共约 5 秒即有 80% 概率首次猜中口令。（YouTube EPQT2KRH4clNM，[8.2-447.7]，L1）
- 〔IEEE S&P（推测）〕浏览器与恶意服务器两种威胁模型下的攻击。浏览器对手只需让目标在另一标签页登录：hash-to-curve 的 while 循环迭代次数依赖输入，测缓存-内存时序尖峰的时长可得迭代次数，尽管 JavaScript 沙箱与分层 JIT 增加噪声，5 次测量约 5 秒仍以 66% 成功率恢复部分口令。若对手兼运行服务器，Chrome 计算模逆所用的二元扩展欧几里得算法（BEA）非常数时间，会泄露盲化因子之逆；结合已持有的 Q^a 即可还原对每个口令确定的点 Q，34 毫秒内完整恢复盲化因子与口令。三处攻击的共同根源是算法非输入无关、在跨进程与网页边界的 CPU 缓存留下可测痕迹，作者呼吁 Chrome 采用常数时间实现，并指出 Edge（全同态加密）与 Safari（另一 PSI 方案）的侧信道韧性仍是开放问题。（YouTube EPQT2KRH4clNM，[449.5-860.0]，L1）
- 〔会议不详〕GAT：桥接关系 OLTP 与图分析的内存 HTAP 系统。主讲人（上海交通大学、阿里巴巴集团与上海人工智能实验室合作）指出社交网络用 PageRank、业务用图遍历与 GNN 做推荐等图分析（GAP）大多作用于关系 OLTP 数据，用户被迫用关系操作改写图操作，用 join 表达图遍历代价高且产生巨大中间结果。现有路线各有缺陷：离线 ETL 到图专用系统数据新鲜度差，OLTP 图扩展执行低效，Neo4j/TigerGraph 等原生图库事务性能显著慢。该工作在 HTAP（混合事务与分析处理）基于事务日志的松耦合架构上扩展出混合事务与图分析处理（HTGAP），提出内存系统 GAT，含关系-图模式映射与动态图存储两个关键组件，并确立透明数据模型转换与支持更新的读局部性两大设计目标。（YouTube EPQVZfKw4XyB0，[15.7-597.4]，L1）
- 〔会议不详〕GAT 的动态图存储设计与评估。针对通用动态图存储的三大问题（CSR 不可变、插入代价高；细粒度 MVCC 开销大且破坏边扫描局部性；属性存储不灵活），主讲人利用 HTGAP 负载洞察重新设计：将边数组划分为带预留空位的可变 CSR 边段（满则写时复制加倍扩容，边以逻辑偏移索引以免段迁移时改写元数据，取读写性能折衷），MVCC 采用按 epoch 记版本的粗粒度方案，属性存储按访问模式由用户定义。在扩展 LDBC 与 TPC-C 的混合基准上，与 Diamante + GraphScope 离线方案及 Neo4j 在线方案对比：GAT 的 OLTP 与 GAP 性能可比专用系统、比在线方案快数个数量级且新鲜度相当；以 PageRank 为例约 80% 的性能提升来自拓扑设计，OLTP 性能退化可忽略、GAP 因版本检查约降 12%。（YouTube EPQVZfKw4XyB0，[597.6-1189.8]，L1）
- 〔会议不详〕Cortex：面向 LLM 智能体的语义缓存。主讲人 Chao-Yuan（新加坡国立大学，与多伦多大学及 USTC 合作者）指出智能体“思考-调用工具-反馈”循环中每次工具调用都是远程往返：典型多跳问题串联 4-6 次调用，搜索智能体在 40-50% 的挂钟时间里 GPU 空转等数据，Google 搜索 API 每千次 5 美元、另一搜索 API 每千次 25 美元且有硬性限流。从拉取的 Google 搜索 trace 看，头部查询量约为第 5 名的 10 倍、尾部高度重复，加之突发与相关性使缓存可行；但智能体查询是自然语言转述而非字节相同，需要语义匹配而非精确匹配，现有键值缓存、GPT cache 式 prompt 缓存（文本相似不等于语义相同，“讲一个笑话”与“讲两个笑话”即反例）与 Redis/RocksDB 类传统精确匹配缓存均无法同时满足语义匹配、低延迟、可分布式与吸收限流突发四项要求。（YouTube EPQVm8eRfAxSY，[18.7-494.0]，L1）
- 〔会议不详〕Cortex 的设计与评估。最近邻检索 strawman（HNSW 索引，相似度超 0.95 即复用答案）在语义、缓存容量与数据新鲜度三方面失效；Cortex 因此把响应与 cost、staleness、frequency、size、latency 五个元数据字段封装为可独立排序的语义条目，检索管线先用 ANN 粗筛、再以 0.6B 参数的 Qwen 小模型做 LLM-as-judge 复核、并动态重校准两级阈值。缓存策略上命中须由 judge 确认，驱逐采用综合频率、成本、延迟与陈旧度除以大小的 LCFU 策略，配轻量 Markov 模型预取；并用 CUDA MPS 让 judge 模型与智能体模型共享单块 GPU 且保证优先级。在 Qwen 系开源搜索智能体与真实 Google 搜索 API 评测中取得约 3.6 倍吞吐，LCFU 应对 Google trends 突发时近 95% 命中率与 3.8 倍吞吐，相比 LRU 避免约 10 点精度损失，成本效率最高提升 6 倍。（YouTube EPQVm8eRfAxSY，[494.2-1017.5]，L1）
