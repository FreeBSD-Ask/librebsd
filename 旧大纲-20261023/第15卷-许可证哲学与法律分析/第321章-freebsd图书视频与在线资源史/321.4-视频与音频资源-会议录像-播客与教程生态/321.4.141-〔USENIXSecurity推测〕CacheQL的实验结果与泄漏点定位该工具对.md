- 〔Vault（推测）〕Linux 数据完整性栈的三大缺口与 flexible PI。主讲人 Anuj 介绍保护信息 PI（protection information）是附在每个数据块上的元数据标签，含 guard（校验和）、application、reference（逻辑块地址，防误写）三类 tag，分 DIF（PI 与数据交织）与 DIX（PI 单独存放，Linux 支持）两种模型，按设备校验范围分 type 0-3；现有栈缺口为：应用层无用户态接口、文件系统不感知设备完整性能力而重复做校验、块层未支持全部 PI 格式；flexible PI 引入由驱动在注册 integrity profile 时设置的 PI offset 字段，使块层兼容 PI 位于元数据缓冲区尾部等不同 NVMe 格式，已并入 6.9 内核。（YouTube EPNkE9PJz599M，[18-260]，L1）
- 〔Vault（推测）〕io_uring PI 接口与文件系统管理 PI（FSPI）。io_uring PI 接口让应用随数据提交 PI：先在 SQE 内嵌 PI 信息因膨胀 SQE 被弃用，改为用户空间准备 io_uring attr PI 结构（flag、PI buffer 长度与地址、reference tag 重映射 seed、application tag）以指针传入，使端到端数据完整性成为可能，已并入 6.14 内核；核心的 FSPI 由 Christoph 完成大部分基础工作，把 PI 生成与校验提前到文件系统层以捕获文件系统处理阶段引入的软件性错误：Btrfs 借此弃用独立校验树、以设备强制的 PI 取代，显著降低写放大与 CPU 开销（随机写收益最大，host 写与 NAND 写大幅减少）；XFS 已有元数据校验但缺数据校验，FSPI 在通用 iomap 路径补齐且不改磁盘格式，开销小而可预期（Christoph 的 XFS 补丁有望上游合入）。（YouTube EPNkE9PJz599M，[261-848]，L1）
- 〔USENIX Security（推测）〕IPFS 内容审查的背景与 BadBits 名单。一位来自德国（演讲中提及 USENIX 在德国声誉、与多位德国作者合作）的研究者介绍对 IPFS 这一 P2P 存储检索网络内容审查方案的测量：IPFS 用 Kademlia DHT 存内容标识 CID 到 provider 的映射，节点间经 BitSwap 交换数据，外部经 HTTP 网关访问，网关即服务（gateway-as-a-service）商提供子域名且不审查用途，易被用于钓鱼内容托管；P2P 系统无 CID 中央注册、一条链接即可传播、内容寻址可生成多个 URL，导致审查困难；IPFS 开发商 Protocol Labs 2021 年基于邮件举报建立约 40 万条目的 BadBits 名单（取 CID、规范化、哈希后上榜），多数条目为 DMCA 版权内容，亦有钓鱼与恶意软件。（YouTube EPNl8vhqVLydw，[8-363]，L1）
- 〔USENIX Security（推测）〕BadBits 名单的演化、响应时延与网关执行情况。测量显示 2023 年名单爆炸式增长且多成批进入；DMCA 内容多为 PDF（主要是研究论文），钓鱼多为 HTML；由于名单是被动的、需先发邮件触发，从内容在网络上出现到上榜的响应时间较慢，而 Protocol Labs 收到邮件后处理较快，OpenPhish、PhishTank、Google Safe Browsing 等反钓鱼服务整体响应更快；请求日志显示 2023 年以来钓鱼请求明显上升，但总体仅约不到 1% 的请求指向被封锁内容；gateway-as-a-service 提供商基本不执行任何名单，Protocol Labs 自营网关遵守自家 BadBits，其余执行情况参差；作者建议去中心化审查、为名单添加注解、让 Web2 过滤理解 CID 并把反钓鱼数据喂给 Web3 名单。（YouTube EPNl8vhqVLydw，[365-690]，L1）

- 〔FAST（推测）〕Postman：用中置盒分流小包处理以快速缓解突发流量（上半）。华中科技大学博士生 Yi Pei 报告：突发流量（据 Akamai 与 Alibaba 统计，Cyber Monday 转化率 24 小时内升 35%，双十一峰值订单超每秒 3200 万）造成后端负载不均，而 Memcached 类服务的请求很小（Facebook 称其缓存层多数键小于 30 字节、值中位数 135 字节），小包处理开销很高；迁移热数据耗时长（Amazon Dynamo 以最低优先级迁移，购物季近一天才完成）且拖慢已高载服务器，故提出在 helper 中置盒上按需把小包合并成大包再发给高载服务器，把包处理开销分流出去；Postman 以 DPDK 加 mTCP 实现，包头换为三元组 Postman 头（1 字节类型码 request/reply/connect、2 字节载荷长度、4 字节源 IP 与端口，其中源 IP 低 16 位哈希成 2 字节标识可覆盖约六万余台机器的适度规模集群），per-core 线程与独立 per-core 上下文避免同步；helper 失效时凭无状态性质重定向到其他 helper，客户端经新 helper 发 reconnect 消息与服务器交换已发已收包计数，对照缓冲偏移确定需重传的包；Postman 库提供 connect、decompose、compose、getinfo 等附加 API。（YouTube EPNlMxGjEbggc，[10-414]，L1）

- 〔USENIX Security（推测）〕Double Trouble：非包容缓存层级上的 CPU 与 FPGA 联合攻击（上半）。来自 imec-COSIC（KU Leuven）的 Antoine Pernot（与 Furkan Turan、Ingrid Verbauwhede 合作）提出新的攻击者模型——同时控制 CPU 核与一个或多个 FPGA 等次要设备的组合攻击者，针对 Intel Xeon 近期服务器的非包容（non-inclusive）LLC；次要设备经 Intel DDIO 把内存流量直接路由进 LLC：次要设备读不分配 cache line、写仅约束到 LLC 组内两个 way（默认，称 DDIO 区域），且读取对元数据状态不可见、不保留历史；攻击者用 FPGA 只需 DMA 与自实现计时器两个构件，并借双重视角对 cache line 在层级间的迁移做 FPGA 辅助逆向工程（部分发现与先前工作不符，附开源仓库实验佐证），组合攻击者可细粒度控制 line 所在缓存层级。（YouTube EPNn-RKqOA5vk，[10-388]，L1）
- 〔USENIX Security（推测）〕组合攻击的应用与结论（下半）。FPGA 加速器把 eviction set 构造压缩到 200 微秒以内（每秒数千个，比先前工作快一到三个数量级），其加速恰源于次要设备读取不可见与 DDIO 区域极小这些限制而非新增能力；逆向工程发现缓存中还有未文档化的 DDIO+ 区域且在各 DDIO 配置下稳定存在；组合攻击者不仅可固定 line 所在层级还可固定所在 way（前所未有），可用极小 eviction set 从特定 way 失效 line、跨 socket 驱逐共享 line 而不在目录上产生竞争或触发 flush，并据此实现针对 AES 的端到端攻击和按被驱逐 line 数量及 DDIO/DDIO+ 区域归属编码数据的新型隐蔽信道；结论：FPGA 灵活、自带计时器、常驻且开启缓存攻击所需的逻辑资源占用小到几乎无法检测，组合攻击者的对抗措施棘手，因为攻击源自既有限制而非被授予的能力，业界应重审微体系攻防的常见假设（作者还开源了软硬件 PoC）。（YouTube EPNn-RKqOA5vk，[389-773]，L1）
