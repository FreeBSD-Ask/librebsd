- 〔会议不详〕DING 面向常见路径卸载、罕见路径回落用户态的设计与评测。eBPF 受限编程模型（指令数受限、有界循环、无 malloc）承载不了故障处理等复杂罕见路径，DING 据此把三个关键组件分别卸载：锁管理器用内核内 eBPF 数组存锁状态并以原子 CAS 获锁、哈希冲突等罕见情况直接返回失败让客户端重试；键值存储用静态分配的 eBPF map 桶缓存几十字节小键值对、桶内嵌 Bloom filter 免去不存在键的用户态检查（删除溢出键时由用户态经 eBPF bookkeeping 程序重建过滤器）、大键值溢出到用户态 malloc 内存；日志管理器用每核 eBPF ring buffer、恢复时重放并避免跨核同步。分离中断处理与罕见路径处理的调用集合优化在极端 I/O 密集负载下带来最高 2.4 倍提升；系统以约 2K 行 eBPF 加 4K 行 C++ 实现两类事务协议，TATP 负载上尾延迟远优于 Linux 内核网络栈、I/O 密集负载最高达 22 倍，甚至超过内核旁路基线 Caledon（避免其 socket API 的额外包拷贝），且可按负载良好地伸缩 CPU 使用。（YouTube EPEgdXrjwBdBA，[501.0-1102.9]，L1）
- 〔SREcon〕Bloomberg 交易解决方案 SRE 团队的 Danny Chen 谈日志器自身的可观测性。主讲人从 1980 年入职 Bell Labs 任 Unix 性能工程师、1985 年前后开发据信为首个通用 Unix 内核跟踪包 Casper、1988 年在 Usenix 发表的经历讲起，并援引上届 SREcon 两场报告的启发：Tanya Riley 的纽约消防规范史引出为可扩展可靠系统建立软件消防规范（他把可观测性原语视为其中一条），Lauren Hoxton 的 antics 与 drift 论断（复杂系统运行必然偏离预期）则要求对各层栈都有可见性。他复盘十年前的 logger 时刻：金融危机期间投行中间件团队被应用方指出 100% CPU 饱和竟出在自家 C++ logger 里的 strftime 上，当时 Solaris 8/SPARC 上每次调用约 1 毫秒而库的拥有者毫无感知；他还给出 Java Logback 文件日志（多数写落在 100–170 微秒、长尾可达 3.3 毫秒）与 HTTP 日志转发器（主体低于 7 毫秒、最大近四分之一秒）的延迟直方图实测，并澄清 Unix 文件写天然异步、异步日志器异步的其实是 write 系统调用。（YouTube EPElGlnn1wrbQ，[10.6-723.3]，L1）
- 〔SREcon〕malloc 时刻与缺乏可观测性的成因、出路。2007 年同一消息团队发现服务器周末重启后越跑越慢，定位为 glibc malloc 随一周运行越来越久（反复分配同一大小对象命中问题 bin），若非碰巧撞上该对象大小便无人知晓；他把成因归为指标与日志混淆（开发者听到指标就写日志，而可视化光谱一端是昂贵且携带上下文的日志、另一端是刻意廉价的指标）、缺乏进程/应用级指标标准（回顾 30 年前 PMWG 与其把 sar 数据做成进程可只读内存解引用、每秒百次采集无感知开销的原型）与习得性无助，主张提供类似 /proc 的接口供 malloc、logger 等底层代码导出共享内存中的指标。结尾建议更聪明地记录日志：日志已从人读变为程序消费，可改用 epoch 时间戳（Linux 上 strftime 已降到约 15 微秒但仍是系统调用数倍）并顺带消除分布式系统时区转换之苦、对异步日志器 burst buffer 的丢日志风险保持警惕；被问及普通 SRE 最该做什么时，他答先在晴天与雨天环境测量延迟，并请社区追问服务提供方请测量延迟、请提供指标。（YouTube EPElGlnn1wrbQ，[724.1-1798.2]，L1）
- 〔FAST（推测）〕来自 Haifa 合作团队的 Michael 报告实时压缩场景下的压缩比估计与资源有效利用。研究面向企业存储主数据的实时压缩（gzip 背后的 zlib，Lempel-Ziv 找重复替换为短指针加 Huffman 编码），压缩并非免费（CPU、内存开销），对磁盘与 CPU 配比高或后端为 SSD 的存储系统代价显著，且 zlib 在压缩比越差时运行越慢、加密数据与 JPEG 等不可压数据反而工作最重，因此要避免压缩不可压数据；估计压缩比还能支撑评估与 sizing（压缩比决定后端磁盘数量即花钱）。现有做法只有经验法则、按文件扩展名推断（块存储下不可用）与无保证的前缀压缩采样，且 Raskhodnikova 等 2007 年性质测试论文分析证明除非几乎读完全部数据否则无法准确估计 LZ77 压缩；作者提出宏观（GB 到 TB 级卷，估计数分钟内）与微观（KB 级单次写，须极快）两种粒度的互补方案。（YouTube EPEn9ORsDifpQ，[16.6-554.2]，L1）
- 〔FAST（推测）〕宏观以字节采样获得统计保证、微观以启发式在线决策。宏观方案定义字节的 locality 与其贡献，证明整体压缩比是全部字节贡献的平均，从而把问题化为统计学家擅长的均值采样：按置信与加性精度代入即得样本量，且样本量与卷大小无关（GB、TB、PB 同样保证）、结果近似正态分布使实际误差通常远小于声称值；实测 C 多线程工具（IBM Compression Estimator）在 3.2TB 卷上 73 秒、误差低于 0.5%，而穷举压缩近 4 小时。微观因不可压性定理仍成立而转向启发式：前缀估计（8K 块先压 1K 即判停或继续）对可压数据近乎零开销但会浪费不可压数据上的工作，启发式方法综合码集大小、字节熵与字符对分布等指标、自适应采样并惰性求值尽早停机，还可建议只做 Huffman 不做 LZ；实测前缀法把 CPU 降至完整压缩的 74%（总容量增 2.2%）、启发式进一步降至 65%（增 2.3%），并按数据可压性在宏观估计、前缀、启发式与直接关闭压缩之间选择。（YouTube EPEn9ORsDifpQ，[566.6-1691.5]，L1）
- 〔会议不详〕主讲人 David 报告论文 Jenny：为基于保护键的内存隔离系统加固系统调用。PKU（protection keys for user space）通过页表项中 4 位保护键（Intel 上共 16 个键）与 pkeyru 寄存器在用户态实现细粒度进程内隔离与快速权限切换，但 Hodor、Donky 等沙箱往往不过滤系统调用或依赖慢机制、定制硬件（Donky 的硬件扩展把系统调用直接递交给进程内监视器），而把复杂过滤逻辑移入内核会扩大攻击面、经信号转回监视器又引入额外上下文切换。主讲人系统分析内核接口找出大量必须过滤的调用：madvise 可无视保护键清页、brk 可清页甚至移除保护键、userfaultfd 可向受保护页写任意值、personality 可使后续映射可执行而击穿 write XOR execute 策略、core dump 造成信息泄漏，并由此导出 base Donky、base x86 与 local storage 三组过滤规则，对内存、映射与磁盘别名多层设防。（YouTube EPEnk0FQOwy9I，[8.4-233.8]，L1）

- 〔USENIX Security（推测）〕RC4 NOMORE：新偏置挖掘与明文恢复改进，敦促彻底弃用 RC4。主讲人指出 RC4 是描述极简的流密码，仍用于 WEP、WPA-TKIP、SSL/TLS 多个密码套件及某些端到端加密协议，ICSI notary 监测数据显示首个针对 TLS 的 RC4 攻击发表时约半数 TLS 连接使用 RC4、两年后仍有 30%、近年降至 13%，但浏览器 RC4 回退（握手失败消息可被攻击者伪造）使 13% 只是易受攻击连接数的下界。方法上把偏置搜索自动化为假设检验：以均匀分布为零假设，用卡方检验查单字节非均匀、用 Fox 等的 M 检验（擅长发现离群点）查双字节相关，找到 256 之后仍非均匀的字节、每 256 字节块内第一与第三字节偏向 0 和 128 的长程偏置以及前两字节泄露大量信息等新偏置；明文恢复在 AlFardan 等 2013 年攻击（同一明文多次加密、以诱导密钥流分布与真实分布匹配来验证猜测）基础上改为生成按似然递减的候选列表以支持利用已知结构剪枝与暴力破解。（YouTube EPEt8E1Y9c2GM，[10.1-812.1]，L1）
- 〔USENIX Security（推测）〕利用 RC4 偏置破解 WPA-TKIP 与 HTTPS cookie。WPA-TKIP 每包密钥由共享密钥、发送方 MAC 与初始化向量混合而成，设计者覆写前三字节以避免毁掉 WEP 的弱密钥，反而公开了密钥前三字节并引入 IV 相关偏置；MIC 校验较弱，解出 MIC 字段即可高效反推 MIC 密钥，攻击者诱导受害者连接恶意服务器后借 TCP 重传（合法协议行为、防火墙不拦）重复发送同一明文包，用候选列表加 CRC 重算剪枝，约 2 的 24 次方个包、每秒生成 2500 包即一小时内完成，并在实验室成功恢复 MIC 密钥。HTTPS 攻击面向认证 cookie：诱导受害者连到不使用 HTTPS 的子域以删除并注入 secure cookie 使其两侧被可预测明文包围，中间人注入 JavaScript 生成海量 keep-alive 请求收集密文，模拟显示约 2 的 31 次方 keystream 下用至多 2 的 23 次方候选暴力破解成功率超 90%（单候选仅约 20%），现场演示经 rc4nomore 网站成功恢复 cookie；被问及 Snowden 所称政府机构实时解密 RC4 时，主讲人猜测其可能在恢复内部状态并对此持怀疑态度。（YouTube EPEt8E1Y9c2GM，[813.1-1743.5]，L1）
