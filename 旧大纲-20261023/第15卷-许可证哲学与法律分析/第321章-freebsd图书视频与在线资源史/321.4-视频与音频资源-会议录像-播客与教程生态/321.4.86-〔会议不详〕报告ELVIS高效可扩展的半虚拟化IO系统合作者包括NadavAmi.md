# 321.4.86 〔会议不详〕报告ELVIS高效可扩展的半虚拟化IO系统合作者包括NadavAmi

- 〔会议不详〕报告 ELVIS：高效可扩展的半虚拟化 I/O 系统，合作者包括 Nadav Amit、Alex Landau、Muli Ben-Yehuda、Abhishek Tripathi、Razya Ladelsky。 hypervisor 拦截 I/O 可支撑软件定义网络、文件后端块设备、热迁移、容错与防火墙等特性，但裸金属性能最好却失去灵活性、模拟设备灵活却慢、半虚拟化需改 guest、SR-IOV 快却失去拦截能力（其先前 ASPLOS 的 ELI 让物理设备中断直达虚拟机但仍无拦截）。现行基于通知的半虚拟化 I/O 开销巨大：guest 经 KVM 的 PIO 特权指令触发 exit、hypervisor 线程处理 I/O 后再用 IPI 强制 exit 并注入虚拟中断，多核多设备下退出泛滥且 hypervisor 线程调度器对队列中挂起请求的多少与等待时长一无所知；面向多核增多、网络带宽增大而 I/O 虚拟化本身耗 CPU 的趋势，ELVIS 为 I/O 专设核心且每个 I/O 核只跑单线程，可按队列活动与等待时长做细粒度 I/O 调度以在吞吐与延迟间权衡，并通过轮询队列获得免 exit 的通信通道。（YouTube EPEz1vrZQw-2Y，[9.8-764.3]，L1）
- 〔会议不详〕ELVIS 的实现细节与评测。host 到 guest 的免 exit 通知通过扩展 ELI 实现：由 I/O 核向运行 guest vCPU 的核注入核间 IPI 而无需 exit，这实际上模拟了未来处理器的 posted interrupts（Intel 术语）或 doorbell interrupts（AMD 术语）特性；细粒度 I/O 调度先服务吞吐密集队列、监测到 stuck 队列（有挂起请求但无新请求，表明延迟敏感负载）尽快切换，并可用类 NAPI 方式在轮询与通知间按活动切换；建议每 CPU socket 专设一个 I/O 核以利用共享末级缓存与 DDIO（设备直接把 I/O 数据推入处理器缓存），并把物理设备中断直接送达 I/O 核、借多功能设备或宿主侧 SR-IOV 虚函数把中断均衡到多个 I/O 核。系统实现于 KVM 的 vhost 内核框架之上，用双路 8 核、双口 10GbE SR-IOV 服务器对 1–13 个虚拟机测 netperf TCP stream：ELVIS 接近甚至优于免拦截配置（批处理把每虚函数约 3 万中断/秒合并为每机 4K–11K），随虚拟机增多仍线性扩展，显著优于 baseline 与 baseline+affinity，延迟接近免拦截（SR-IOV 本身在裸金属上即增加 22% 延迟），memcached 负载下 3 个虚拟机后 I/O 核饱和、加第二个 I/O 核即恢复扩展；未来工作包括让调度考虑虚拟机 SLA 与按负载动态分配 I/O 核。（YouTube EPEz1vrZQw-2Y，[765.0-1636.6]，L1）
- 〔FAST〕经典缓存"最大化命中率"的 wisdom 在现代存储层级上失效。主讲人 Kan Wu（UW-Madison，与 Microsoft 等合作）指出，3D XPoint 持久内存与 Intel Optane SSD 等新设备使常见设备对之间的最小性能差距通常小于 3 倍、甚至相互重叠，仅优化命中率会让 flash SSD 上的可用性能被浪费。为此提出 NHC（non-hierarchical caching，转写音作 long-horizon predictions），以动态负载准入（data admit flag）与请求卸载（load switch 加 load admittance ratio）扩充经典缓存。（YouTube EPFBiz0rd1qqY，[103.8-256.0]，L1）
- 〔FAST〕NHC 用基于反馈的缓存调度器把负载在缓存/容量设备间再分配，并以 Orthus 系统落地。调度器按类梯度下降方式调节负载比例，优化用户提供的度量函数 f（吞吐、平均延迟或 P99 尾延迟），兼容既有缓存策略且无需设备或负载先验知识。Orthus 实现为块层内核模块加用户态键值缓存层，评测显示其在现代层级上较经典缓存取得显著吞吐提升，模拟层级结果还可预测收益。（YouTube EPFBiz0rd1qqY，[396.0-663.6]，L1）
- 〔OSDI〕Okapi 把数据条带（striping）与冗余组（redundancy group）解耦。主讲人 Sanjith（CMU 博士生，与 CMU 及 Google 的同事合作）说明：现今系统用同一 K-of-N 配置同时决定纠删码分组与条带化，只能优化其一，且更换纠删码方案被迫重新条带化、引入大量不必要 I/O。条带为 I/O 效率服务（cell 约 1MB、block 约 8MB，最优条带宽度取决于应用访问模式），分组为可靠性与成本权衡服务，二者最优解的决定因素不同，不应严格耦合。（YouTube EPFCr2JOI-mEA，[46.6-406.0]，L1）
- 〔OSDI〕Okapi 的微基准与转码结果显著优于耦合系统。在 20 节点集群、6-of-9 纠删码下，Okapi 按请求大小调优条带宽度始终胜出；Google 数据显示约 60-90% 抽样文件在 150 天内请求大小完全一致，使这种调优现实可行。转码只是重新分组而非重排条带，可完全消除数据移动，把 1GB 文件转码的 I/O 开销降低近 50%；元数据膨胀用模运算从条带信息推导分组解决，客户端缓冲与降级读开销分别用部分校验块（partial parities）和缓存/预取控制。（YouTube EPFCr2JOI-mEA，[653.7-1009.0]，L1）
- 〔OSDI〕分布式锁服务需要获取快且锁数量可扩展（主讲人 Hanze Zhang，上海交通大学 IPADS）。分布式内存应用执行已进入微秒级、共享数据规模接近十亿级；纯服务器方案（ASR 音作 servlog/SerLock）因排队延迟慢出超过一个数量级的方差，可编程交换机上的 NetLock 虽近零排队延迟但片上内存受限、百万锁时只能加速不到 1% 的请求（Zipf 负载下至多 30%）且依赖静态剖析。关键洞察是把锁获取解耦为授权决策（留在交换机）与元数据维护（异步放服务器），由此提出 lock fission 原则并构建 FissLock。（YouTube EPFD0O6l6ik6g，[30.2-382.5]，L1）
- 〔OSDI〕FissLock 的交换机内存设计与评测结果。通过逐级精打细算地设计决策流水线各 stage，可管理超过一百万把锁，比 NetLock 高两个数量级；在 8 台逻辑节点加 Intel Tofino 交换机的集群上，FissLock 在各种读写比与均匀/Zipf 负载下保持低而稳定的锁延迟，峰值吞吐约为 NetLock 的 2 倍、百万锁时超 5 倍，TATP 与 TPCC 事务处理加速约 2 倍，锁授权尾延迟削减超过 90%。（YouTube EPFD0O6l6ik6g，[570.7-827.0]，L1）
- 〔会议不详〕边缘系统研究受困于缺少真实边缘负载。主讲人 Oleg（初任博士生，与 Gala、Sumit、Amina 合作）在做边缘存储研究时发现，已没有可靠方法评估真实边缘系统的各个方面：边缘是易波动的本地服务，又是由高度异构提供者组成的分布式服务；已部署的少数真实边缘系统数据并不公开。负载是定义设计目标、权衡与评测的基础，而现有数据中心负载与合成负载均难以反映边缘基础设施及其应用需求。（YouTube EPFHMYqreAae0，[23.2-207.5]，L1）
- 〔会议不详〕用多数据集拼接合成代表性边缘工作负载的完整示例。以纽约出租车下车时空信息加 NYC 热点数据集定义各区域、各时段的需求，在下车时间与区域上定义浏览会话并用 Wikipedia 文章链接图按退出概率 p_exit 生成对象访问序列，补齐数据对象、时间、位置、节点四类属性。相关性分析（各区域下车量与热点数、日/夜趋势）显示该组合有依据而非暴力合并，这一方法可推广到任务调度、分布式计算等任何基础设施层设计与优化。（YouTube EPFHMYqreAae0，[348.5-504.5]，L1）
- 〔USENIX Security〕Retbleed：对返回指令也能做分支目标注入。主讲人 Johannes（ETH Zurich ComSec，与导师 Kaveh Razavi 合作）介绍，Spectre 时代为消灭易受 BTI 的间接跳转而引入 retpoline、改用返回指令；但返回指令依赖 RSB 预测，Intel 在深调用栈耗尽 RSB 后回退到 BTB，AMD 在 BTB 索引冲突时直接采用 BTB 表项，因此攻击者可以对非特权用户与内核之间的返回指令实施跨特权 BTI，打破内核 ASLR 并转储内核特权内存。（YouTube EPFIcb693ColA，[8.6-155.2]，L1）
- 〔USENIX Security〕跨特权 BTI 的三个要件与攻击效果。AMD 上碰撞只需考虑最近分支目的地与程序计数器、翻转两位即可命中碰撞组合逻辑；Intel 上借助系统调用测试套件加 ftrace 函数图与简易污点分析找到约一千个易受攻击的返回（AMD 上所有返回皆可，演示选用 mmap 控制六个寄存器）；用户态里"跳向内核内存"的非法分支虽触发页错误仍会更新 BTB。多数 AMD CPU（Zen 3 除外）与全部 Skylake 受影响、后续 Intel 靠增强 IBRS 保护，约 220 B/s 到 4 KB/s 的泄露速率即可定位 /etc/shadow 并窃取口令哈希；缓解方面 Intel 须启用 IBRS，AMD 采用 jump-to-ret。（YouTube EPFIcb693ColA，[341.1-637.4]，L1）
- 〔OSDI〕ZNS 消除闪存 SSD 的"块接口税"（主讲人 Matias Bjørling，Western Digital；CMU PDL 与 Penn State 合作）。块接口假设可原地覆写，而闪存必须顺序写入擦除块，SSD 用 FTL 加 7-28% 超额配置来弥补，既贵又慢。ZNS 把擦除块内的细粒度数据放置上移到主机，接口只允许追加写与显式 reset，换来 7-28% 额外容量与可预期性能：写满后 7% 超配块盘跌至约 380 MB/s、28% 超配约 600 MB/s，ZNS 全程保持介质全速。主机侧演进路径有宿主侧 FTL、文件系统（已启用 F2FS）与端到端放置（为 RocksDB 构建的 ZenFS 后端）三种。（YouTube EPFJASdd6r4zo，[7.9-453.0]，L1）
- 〔OSDI〕ZNS 的内核支持与生产硬件评测。工作包括 Linux 内核 zone block 设备子系统与 NVMe 驱动（active zones）支持；在生产平台上同一硬件仅换固件，对比 2TB ZNS（14 个 active zone、zone 大小 2GB、可写容量约 1077MB）与 7%/28% 超配块盘。RocksDB 端到端集成在覆写阶段性能约为块盘方案的两倍，写放大 ZenFS 为 1x、XFS 约 2x、F2FS 约 2.4x；并发写下尾延迟改善 30-40%，解除写入限制后以近两倍写入量还获得约 4 倍尾延迟改善。总结：99.9 分位随机读延迟至少低 2-4 倍、写吞吐高 2 倍，全部工作已上游开源。（YouTube EPFJASdd6r4zo，[572.9-963.3]，L1）
- 〔FAST〕Kevlar：用虚拟内存管理持久内存磨损（主讲人 Vaibhav Gogte，密歇根大学；ASR 音作 Gokhale）。持久内存单元仅能承受一千万到十亿次写，既有 wear leveling 多在硬件实现、只支持片内（intradie）且需额外转译层，wear reduction 依赖内存控制器硬件计数且不支持把 PM 当存储的应用。Kevlar 复用操作系统的虚-物理页映射周期性随机洗牌做 wear leveling，无需逐页测量写入即可达到近均匀磨损：解析模型给出 8192 次洗牌可达理想 wear 的 94%，但 wear leveling 单独只能做到约 2-2.8 年寿命，不足以支撑 4-6 年的系统寿命目标。（YouTube EPFJp_6XnMStA，[74.6-536.8]，L1）
- 〔FAST〕wear reduction 把寿命提升到可配置目标：按 4 年目标、一千万次耐久，把每 GB 应用足迹的 PM 写带宽限制到 2 万次/秒，超阈值时把写入最重的前 10% 页迁移到 DRAM。难点在于写回发生在缓存行回写而非处理器 store，Kevlar 用近似缓存模型估计逐页写回：PEBS 每第 17 个 store 采样一次、Bloom 过滤器按 LLC 块数定长、双过滤器交错清空。原型在 Linux 4.5 实现，wear 估计可正确识别 80% 的前 10% 热页，寿命超过 4 年目标、总开销仅 1.2%；问答补充 DRAM 占用不足应用足迹 5%、迁移导致的尾延迟劣化不超过 2-3%。（YouTube EPFJp_6XnMStA，[562.7-1313.6]，L1）
- 〔OSDI〕构建首批形式化验证的持久内存存储系统（主讲人 Haley LeBlanc，与 Azure Storage 合作者共同完成）。持久内存仅有 8 字节原子写，崩溃一致性与损坏检测极难达成；项目目标是为 Azure 内部系统构建经形式化验证的 PM 键值存储，并选用 Rust 验证工具 Verus；但 Verus 无内建崩溃安全推理，因此提出工具无关（tool-agnostic）技术。成果包括 Verus 写就的 Capybara KV 与 Dafny 写就的 Capybara NS 两套首批形式化验证 PM 存储系统，验证均在一分钟内完成、性能与未验证的 PM 键值存储相当。（YouTube EPFKdckSrLLv8，[17.3-288.2]，L1）
- 〔OSDI〕PoWER 与"损坏检测布尔"（CDB）两项核心技术。与 FSCQ 引入的 crash condition 不同，PoWER（Preconditions on Writes Enforcing Recoverability）仅靠前置条件表达每次写入引入的全部潜在崩溃状态在恢复后一致，可用于几乎所有验证工具；持久内存 8 字节原子写使数据与 CRC 之间出现大量潜在不一致崩溃态，NovaFortis 的 Tik-Tok 依赖 CRC 区分并不严格。CDB 用 CRC(0)/CRC(1) 而非 0/1 作布尔值的底，使布尔与校验和同处 8 字节内原子更新，可当有效位或写时复制指针使用。Capybara KV 约 2.5 万行代码、多数机器 20-30 秒完成验证，性能与未验证系统相当。（YouTube EPFKdckSrLLv8，[543.1-1009.4]，L1）
- 〔OSDI〕把虚拟化功能进一步逐出内核（主讲人 Jiahao Chen，上海交通大学 IPADS）。KVM 与 Xen 在内核中留下约 500 个 CVE，其中超过 90% 的宿主攻击型 CVE 可被用来发动 DDoS、部分可提权；先前的去特权化工作（如 Nova、DeHype）无法消除全部内核 CVE——80 个 KVM 宿主攻击 CVE 中仍有 47 个留在内核，且把更多组件移入用户态会让 QEMU/KVM 的 MMIO 读开销中 44-73% 消耗在额外转发上。根因是硬件虚拟化扩展与内核态的紧耦合，方案是委托虚拟化：DV 扩展加用户态 hypervisor（DuVisor）加极小的 DV 驱动。（YouTube EPFLWvcdfGPxs，[33.1-310.6]，L1）
- 〔OSDI〕DuVisor 的设计、实现与评测。DV 扩展把虚拟化接口安全地抬升到用户态，Dovisor 在用户态直接处理 stage-2 缺页与 VM 退出，DV 驱动用物理内存检查（PMC）限制 VM 可访问的物理地址范围；原型基于 RISC-V Rocket 芯片，DV 扩展约 500 行 Chisel、Dovisor 约 7000 行（Rust 约 5000 行）、DV 驱动仅 337 行，运行时只需 17 个系统调用即可服务 Linux VM，可用 seccomp 约束被攻陷的 hypervisor。FireSim FPGA 评测：hypercall 与 stage-2 缺页处理比 KVM 少 65% 与 89% 时间，MMIO 模拟快 10 倍，应用性能与优化后的 KVM 相当、接近原生。（YouTube EPFLWvcdfGPxs，[370.3-716.2]，L1）
- 〔NSDI〕PreAcher：把口令预认证下沉到 CDN 而不向 CDN 泄露口令（主讲人来自 Duke 大学，ASR 音作 Shuhan Ning）。应用层 DDoS 常伴随撞库攻击出现，Akamai 报告每天约 2.8 亿次可疑登录；实测以 150 次登录/秒的多源 bots 绕过 Cloudflare 的防火墙限速与 bot 检测后，服务器 CPU 打满且无法服务其他请求。验证码可被 AI 识破、双因子仍以口令为第一因子、限速可用 VPN 换 IP 绕过、机器学习 bot 检测有漏报误报、单点登录有单点故障风险，PreAcher 的关键洞察是在 CDN 上部署预认证过滤无效登录，同时不向 CDN 暴露口令。（YouTube EPFNBlFzI1RZE，[16.2-267.9]，L1）
- 〔NSDI〕PreAcher 的完整流程、部署与评测。客户端先用 LSH（weighted k-min-hash）把口令哈希成伪口令做预认证、同时发送加密口令做全认证，CDN 预认证通过才转发，服务器再用真实口令做全认证兜底，并以超过阈值的全认证失败检测 CDN 内部攻击者的在线猜测；部署上服务器用 C++ 库、客户端用 JavaScript 库、CDN 侧用现成的 serverless 计算服务让开发者自行部署代码片段，Web 开发者可单方面采用。评测：攻击者以 400 次无效登录/秒攻击时 baseline 与 SGX CDN 都无法服务有效登录，PreAcher 在测试床与真实互联网上仍保持接近 100 次登录/秒，k=4、q=20 时账号破解率低于 0.2%。（YouTube EPFNBlFzI1RZE，[454.8-766.4]，L1）
