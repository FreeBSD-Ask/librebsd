- 〔USENIX WOOT〕常数时间模型。主讲人（约二十年前以时序攻击方向博士论文起家、为 OpenSSL 贡献约二十年的研究者）坦言“常数时间”至今没有公认定义：每次与厂商做责任披露都会得到一个与其相冲突的新定义，攻防双方都在为自身便利自定义。他借 OpenSSL 检测常数时间违规的注解 PR 负面测试给出公认反例：秘密相关查表（数据缓存侧）与由秘密值约束循环次数（控制流侧）。随后梳理五种模型：2005 年的 program counter security model 只要求程序计数器轨迹公开、允许秘密相关查表（契合当时无缓存无 MMU 的嵌入式设备）；约同期由 DJB、Percival、Osvik 等工作汇聚成的传统常数时间模型要求控制流与数据地址全部公开、但允许调用方非常数时间（crypto in a vacuum），如今被编译器相关漏洞击破；Intel scatter-gather 模型允许在单个 cache line 内违规（2016 年数据侧、2018 年代码侧被击破）；OpenSSL 安全政策只在乎可远程测量的时序数据（本地微架构攻击大多出局，Red Hat 曾就 PowerPC ECDSA 时序在 2025 年与社区强行发布 CVE 的冲突即是例证）。（YouTube EPQXEFcNUKKKw，[9.9-723.9]，L1）
- 〔USENIX WOOT〕BoringSSL 变长输入泄露与“盯数据”的方法论。第五种模型是 BoringSSL：对定长输入类似传统模型，但允许变长输入非常数时间。主讲人主张攻击者应瞄准规范而非代码：读 RFC/标准找对秘密的怪异处理，再找实现确认泄露。实例是椭圆曲线私钥的 ASN.1/DER 编码：ASN.1 整数取最小规范表示会剥去前导零字节，P384 私钥可因此短一字节，而 BoringSSL 的 bin2bin 以文件中的实际编码长度为界，天然非常数时间；构造不同字节长度私钥测量显示 BoringSSL 的各曲线统计可分，泄露程度约比 OpenSSL 差两个数量级——尽管其威胁模型名义上更强。他给出的临时修复是在解码函数入口分叉并行执行一次按最大长度密钥的哑解析与真实解析再 join 取最大时间，并以下述观点收尾：别陷入模型与威胁模型语义之争，也许 OpenSSL“只看数据”的做法才抓住了要害。（YouTube EPQXEFcNUKKKw，[740.3-1432.5]，L1）
- 〔SOSP（推测）〕面向事务的缓存优化：事务命中率与缓存污染。主讲人 Audrey（报告为 UC Berkeley 与威斯康星大学麦迪逊分校的合作工作）指出主流缓存算法优化的 object hit rate 对事务而言根本有缺陷，在 Meta 开源社交图基准 TaoBench 的 Product Group 2 负载上，LRU/LFU 在某些缓存规模下超过 95% 的缓存键对事务延迟毫无帮助。核心论断是冷键会污染热对象的可缓存性（cache contamination），并据此定义事务长度（transaction length）与事务命中（transaction hit）：只有降低未缓存顺序访问长度的命中才算有效。在 100 个事务的示例中，缓存 A 与 B 虽使对象命中率从 50% 降至 37.5%，却换来 25% 工作负载的延迟改进。（YouTube EPQY-83DX-R2I，[16-446]，L1）
- 〔SOSP（推测）〕Detox 系统与分组缓存策略。Detox（转写亦作 D-Talks）把事务中并行访问的键组成 group 缓存，用可互换组（interchangeable groups）把候选组从指数级降到线性，并提出 levels 技术在缺少依赖图时从并行请求执行动态推断分组；组频率取组内最小值以应对事务的全有全无（all-or-nothing）属性。系统基于 Redis 与 Postgres/TiKV、两阶段锁保证可串行化，在 TaoBench Product Group 2 上事务命中率达近 90%（基线约 50%，提升 76%），缓存空间效率提升 3.4 倍，平均延迟与吞吐各改善约 30%。（YouTube EPQY-83DX-R2I，[448-879]，L1）
- 〔会议不详（推测：密码学会议）〕FRI 基多变量多项式承诺与可验证秘密共享。主讲人 Wei Han Li（北京航空航天大学博士生，与张中原教授、郭彦培、徐可欣合作，合作者还包括 CUHK 的 Shenghao Chu、福州大学刘西蒙等）指出单变量 FRI 承诺可达线性证明复杂度而多线性承诺受限于拟线性，提出两个研究问题：线性证明者的 FRI 基多线性承诺，以及一对多（one-to-many）多项式承诺。一对多承诺支持一个证明者对 n 个验证者，可直接构造基于 Shamir 秘密共享的 VSS；面对不假设有界网络延迟的 AVSS（异步 VSS），方案采用双变量多项式承诺与 share of shares 技术处理诚实验证者消息延迟带来的不确定性。（YouTube EPQfHBIE7kSsk，[8-361]，L1）
- 〔会议不详（推测：密码学会议）〕滚批式 FRI、一对多双变量承诺与 PolyFrame 实现。通过观察求值协议内部多项式尺寸天然递减，提出 rolling batch FRI 免去 padding，把 HyperPlonk 类承诺的证明者复杂度降至最优线性；利用 VSS 求值点可预先固定为 2 的单位根并重用步骤，实现 n²logn 证明复杂度的一对多双变量多项式承诺，并构造复杂度 n²logn 的新 AVSS 方案。实现系统 PolyFrame 的实验显示证明者时间比既有工作至少快 5 倍，验证时间与证明大小保持竞争力。（YouTube EPQfHBIE7kSsk，[362-719]，L1）
- 〔会议不详（推测：FOSDEM）〕Minecastle：面向边缘与云的加密压缩块设备。演讲者（曾在 VMware 参与 Lithium/vSAN 原型、后加入 Bromium 的工程师，现做边缘 AI）介绍 Minecastle 是一个压缩、加密、自认证、cache-oblivious 的块设备，用于把同一容器镜像以防篡改方式部署到大量智能摄像头等小型 Linux 设备，也可把 Mindspore 训练容器放 S3、用 spot 实例训练以降低成本。报告回顾其源于 2011 年 Bromium（由 Xen 创始人创办，把 Windows 会话拆成 N 个 VM 做安全隔离）的 swap 存储系统：VHD 类格式只是间接层不减少 IO 且有空间膨胀，B-tree 点写放大近千倍，最终采用 LSM 式多级结构——每级一张（B+）树与一个日志，树始终由排序输入线性生成并用于指导合并，且支持多级并行合并。（YouTube EPQgOkDiP0C4c，[10-818]，L1）
- 〔会议不详（推测：FOSDEM）〕Minecastle 的分布式化、内容寻址与性能。Bromium 开源后作者把其从 Windows 移植到 Linux，加入 HTTP 取块、以内容哈希命名块的内容寻址存储与全程加密，形成 Merkle 哈希树，根节点（UUID、256 位 AES 密钥、snapshot ID 与 fallback 列表）即可在云端或本地唯一定位一个块设备版本，可经邮件、云 VM 参数或推送到摄像头引导精确版本。前端提供 NBD 与 KVM tool（可用 XFS 格式化或直接跑 VM），并讨论固定尺寸分块在触发合并时会引发大量回源重写、建议改用 rsync 式基于内容的分块来局部化合并；性能上最坏情形足迹从 16GB 降到 131MB，加密对写几乎无影响、对读约 50% 开销，未来工作包括 PyKV 乱序访问数据库（在七年前的机械盘上以约 1000 张图/秒跟上两块 TPU 的 SGD）、FUSE POSIX 层与崩溃一致性。（YouTube EPQgOkDiP0C4c，[835-1630]，L1）
- 〔会议不详（推测：密码学会议）〕安全群组消息的密码学管理员。主讲人 David 报告与 Daniel Collins、Serge Vaudenay 合作的论文“Cryptographic Administration for Secure Group Messaging”，指出群成员资格（group membership）管理普遍停留在 UI/服务器层面，服务器或恶意用户可以潜入陌生人群、悄悄移除成员并伪装成自主退群。核心主张是把实践中已存在的管理员角色下沉到密码学层面，提出 cryptographic administrators 形式化及其正确性与安全定义，以被广泛研究、构成 MLS 基础的连续群组密钥协商（CGKA）为基础，要求仅管理员可在恶意网络下提交群组变更。（YouTube EPQhYko9LegTY，[8-324]，L1）
- 〔会议不详（推测：密码学会议）〕两种模块化构造与 MLS 集成评估。方案给出 admin CGKA 扩展（新增管理员子集 G*、新提案与提交类型及强管理安全模型），并提出两种模块化构造：为每个管理员签发凭证并在提交时签名验证，以及支持群内管理员匿名的动态群签名（dynamic group signature），均可搭配任意 CGKA 且支持管理员密钥刷新以保持 FS/PCS 一致。MLS 集成评估表明规范改动极小，实现相对基线 MLS 开销很小，作者认为该思路同样适用于 WhatsApp sender keys 等现实协议；团队还将在海报环节展示对 Signal/WhatsApp 群组协议 sender keys 的实用安全分析。（YouTube EPQhYko9LegTY，[324-645]，L1）
- 〔USENIX FAST（推测）〕ZNS（转写误作 GNS/Genesys）背景与代价。主讲人成均馆大学 Tong Guoxin（与三星电子 Memory Solution Lab 合作）介绍 ZNS：原始（raw）zone 数据空间划分为固定大小 zone、须顺序写并显式复位以复用，已纳入 NVMe 标准，三星发布基于 QLC 的 ZNS SSD。ZNS 相比传统 SSD 提供 I/O 流间性能隔离、维护 zone 级小容量 L2P 映射表，且顺序失效避免了 GC 的写放大与不可预测长延迟；但使用 ZNS 需把 EXT4 换成追加日志文件系统（本文面向 F2FS）并为每个 zone 提供顺序投递的 I/O 调度，线程日志（threaded logging）因随机写与 ZNS 不兼容而被现有 F2FS 补丁禁用，而常规段压缩由受害者选择、块定位、经主机读写的数据拷贝与元数据/检查点四步构成，主机发起的拷贝无法充分利用盘内带宽并产生大量空闲间隔。（YouTube EPQjrPiWrfM3k，[8-413]，L1）
- 〔USENIX FAST（推测）〕ZNS+ 接口、盘内压缩与评估。指出 ZNS 把复杂度全部推给主机，主机侧 GC 开销远高于设备侧，需要主机-设备协作而非简单搬运；据此提出支持盘内 zone 压缩与稀疏顺序写的 ZNS Plus：把数据拷贝任务下放到 SSD 以利用跨并行闪存芯片调度并省去主机-设备传输，允许在经 T R open 打开的日志上稀疏顺序写，由盘端在连续请求间用同段未动有效块内插补洞（internal plugging）转成稠密顺序写；配合 ZNS Plus 感知的 LFS 采用混合段回收与 copyback 感知的块分配。用 Femu（QEMU 基模拟器）与修改 Cosmos+ OpenSSD 平台的真机评估，F2FS 4.0.10 下仅盘内压缩的 IGC 吞吐达原 ZNS 的 1.9 倍，ZNS Plus 达 2.9 倍、元数据写流量降低约 48%、86% 以上回收段由线程日志处理；SSD 已从黑盒走向灰盒/白盒模型，ZNS+ 把每个存储管理任务放到最合适的位置并让主机与 SSD 协作。（YouTube EPQjrPiWrfM3k，[429-814]，L1）
- 〔USENIX Security（推测）〕劫持者银河指南：经 DNS 污染接管互联网资源账户。作者之一 Philipp Eitner 介绍该论文覆盖区域互联网注册机构（RIR）、域名注册商（如 GoDaddy）、云服务商（Google/Amazon）与证书 CA 四类资源提供方，攻击核心是劫持账户的密码找回邮件：在资源提供方解析器中投毒 DNS 缓存，把受害者域的邮件服务器映射到攻击者 IP，再触发找回流程重置密码并接管账户。评估了 BGP 子前缀劫持、SAD DNS 侧信道与 IP 分片三种投毒手段，BGP 子前缀与分片攻击对大多数受测提供方有效；由于多数提供方仅凭邮箱即可触发找回而 whois 公开库泄漏账号邮箱，约 75% 的 RIR 客户与 11% 的 Alexa Top 100K 域名客户可满足攻击前提，视投毒方法不同 11%–56% 的账户存在漏洞。（YouTube EPQkeuv_dkD1s，[8-343]，L1）

- 〔SREcon（推测）〕Netflix 从 Trusty 到 Xenial（Ubuntu LTS）的迁移策略。主讲人 Ed（Netflix 性能工程负责人，曾长期任职 Sun Microsystems）2016 年受命在“无痛迁移”约束下完成升级：约 15–18 万台 VM 分布三个区域、16 种实例类型对应逾百种硬件配置、Java/Node/C++/Scala/Ruby 等多语言微服务、每天约 4000 次部署且绝不能拖慢创新或弄垮服务。策略上两人 OS 团队只改必要部分（采用 Ubuntu LTS、几乎不做代码改动），先内部把稳再选择多语言、多用例的“朋友”服务当预 alpha 用户；通过 base AMI + bakery 以不可变基础设施产出应用 AMI，并用 easy config 元语言工具屏蔽 init/Tomcat/Apache 等配置细节——使用 easy config 的团队迁移几乎无缝，自己写 init 脚本的团队则需适配 systemd。（YouTube EPQqYXAaDvMzw，[10-786]，L1）
