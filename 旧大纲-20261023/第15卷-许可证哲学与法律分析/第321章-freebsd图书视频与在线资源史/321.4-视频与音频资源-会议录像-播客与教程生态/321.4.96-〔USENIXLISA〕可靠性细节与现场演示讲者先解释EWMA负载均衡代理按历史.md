- 〔USENIX Security（推测）〕Abe Clements 与 Eric Gustafson（两人同等工作量）介绍 HALucinator，通过抽象层仿真实现嵌入式裸机固件的 rehosting。IoT 设备中的裸机固件编译为单体二进制直接运行在硬件上、用原始内存读写访问硬件，传统硬件调试代价高且并行性受限于物理设备数量；rehosting 的最大障碍是外设——现代微控制器有 20 到 30 种外设而 QEMU 只有少数几个，无外设支持时评估中大多数固件只执行 8 个基本块，而 Mouser 在售微控制器超过 4.4 万款、横跨 26 家厂商；HALucinator 利用 NXP、STMicro、Atmel 等 SDK 普遍提供的硬件抽象层（HAL，也内嵌于 RIOT、FreeRTOS 等常见操作系统），在 rehosting 时用高层实现替换 HAL、用 QEMU 系统仿真器替换硬件，把支持数千种设备/外设的问题化为支持几十个 HAL，并演示了替换 I2C read buffer 函数的 Python handler 实现。（YouTube EP7mFqTjfLuEM，[8.8-374.0]，L1）
- 〔USENIX Security（推测）〕LibMatch、评估与 fuzzing。Eric 介绍 LibMatch：从厂商获取 SDK 后先用内容匹配找函数，再用 SDK 提供的上下文检查碰撞函数的 caller/callee 消歧，还能推断被应用厂商定制过的函数名，比纯内容匹配多得最多 10% 的函数名；评估用三家厂商 16 个固件样本，85% 以上 handler 属于 trivial 或 translating 两类、实现成本低，其余需要 SDK 文档之外内部逻辑的多因 HAL 抽象不彻底；基于 AFL Unicorn 框架的 HALfuzz 借助完全解耦硬件可扩展到数亿次并行执行，使 ST 的 PLC 套件与 Atmel 的 HTTP server 崩溃，发现 Contiki 实时操作系统中两个此前未知的 bug 并获得 CVE 编号（已披露并修复）；对同一 HTTP server 固件按不同替换层级分别 rehost 各找到一个 bug，说明多层次方法可聚焦想要找 bug 的区域；团队还借 rehosting 固件在嵌入式系统夺旗挑战中解出全部题目夺冠，HALucinator、HALfuzz、LibMatch 源码均已开源且通过 artifact evaluation。（YouTube EP7mFqTjfLuEM，[374.5-721.7]，L1）
- 〔IEEE S&P（推测）〕首尔国立大学的 Chao Rong 介绍 hypervisor 模糊测试工具 MundoFuzz。hypervisor 是管理并运行虚拟机的系统软件，是云计算的关键攻击面：恶意 guest VM 一旦利用 hypervisor 漏洞拿到 hypervisor 特权，其上所有 guest VM 都会被攻陷；hypervisor fuzzing 的输入由 VM 经 PIO、MMIO、DMA 等低级 I/O 接口产生，主要攻击虚拟设备，而 hypervisor 模拟 NVMe、NIC、USB 等大量各有独特输入格式的设备。现有两类输入生成方式各有缺陷——无格式随机输入无法生成正确格式、探不到设备深层状态，手工输入语法非平凡且代价高；MundoFuzz 用自动语法推理解决，难点在于 hypervisor 语法有两类隐藏语义：I/O 地址语义（控制类型地址值用作调用设备功能的函数号、数据类型用作参数）与 I/O 顺序语义（操作必须按正确顺序执行）。（YouTube EP7nGN7Y9duMU，[7.8-353.1]，L1）
- 〔IEEE S&P（推测）〕统计覆盖率推断与评估。MundoFuzz 通过给 I/O 地址写不同值观察覆盖率是否不同来识别控制/数据类型，通过省略前置 I/O 操作观察覆盖率畸变来识别操作依赖顺序；由于 hypervisor 虚拟化 timer、interrupt 等异步事件引入非确定性噪声覆盖，又利用目标覆盖在所有执行中都出现而噪声覆盖因执行而异的特点，设计统计差分覆盖率测量——对全部测得的覆盖取交集以获得干净的目标覆盖。整体流程为采集真实应用产生的 hypervisor 输入 trace、按两类语义操纵输入、统计噪声过滤后分析语义生成语法再用语法找 bug；MundoFuzz 在 QEMU 与 Bhyve 中共发现 40 个新 bug（QEMU 23 个、Bhyve 17 个），覆盖率比最先进的 HyperCube 与 Nyx 分别高 4.9 与 6.6，且在复杂 USB 设备上比使用手工语法规则的 Nyx 覆盖率更高。（YouTube EP7nGN7Y9duMU，[353.9-698.4]，L1）
- 〔会议不详〕哥伦比亚大学的研究者（与 Angelos 合作的又一项工作，致谢 Steve Checkoway 等）分析 HBBTV 混合广播宽带电视标准并指出其三大严重缺陷。全球约 17 亿台电视中约半数为联网智能电视，HBBTV 于 2012 年进入欧洲市场、在电视广播流之外多传一路带元数据的 HTML 内容，可叠加在广播视频之上、响应遥控器彩色按钮并连接互联网（世界杯数据、互动投票等应用）；讲者强调这是标准本身的漏洞而非某台电视的 exploit：其一，HBBTV 应用生命周期无用户控制——无提示、无运行指示、遥控器上没有任何按键能关闭；其二，广播内容被标准允许自行声明 web origin，意味着广播频道内容可任意声明任何网站同源、从而在互联网任何网站上执行任意代码；其三，RF 广播与互联网连接打破了 HTTP 的双向、单播、有 IP/DNS 可追责等前提，三者叠加后果更严重。（YouTube EP7svPQMQbRis，[9.8-527.6]，L1）
- 〔会议不详〕攻击、成本与对策。讲者以海绵宝宝中 Plankton 恶评 Krusty Krab 餐厅为例演示攻击：因广播内容可自声明 origin，电视收到广播的 JavaScript 后即访问评论网站、把验证码发往人工打码农场并上传差评，同时攻击者无须搭建任何服务器即可借 RF 控制数千台设备；论文实测的攻击设置针对 DVB 地面广播——廉价 USB 调谐器截取热门频道、电脑往复用流中加入元数据与恶意应用后再调制发射，整体成本约 450 美元即可覆盖直径约 700 米的区域，曼哈顿实测圈内有 6 到 8 万人口且可压制 Univision、Telemundo、CBS、Fox 与 NBC 的信号，攻击在成本上完全可行；对策包括仿 HTML5 fullscreen API 的许可控制、用签名认证/PKI 修复 web origin、以及让广播内容不跨入互联网，但'人员测量器'等基于现有协议设计属性的商业模式使修复缺乏商业动力，讲者对此悲观；结论指出这本质是'攻击的是互联网而非电视'，任何接入互联网的敏感传感器设备都面临同类问题，问答中确认可利用电视上已存的用户凭证并借 HBBTV 传播开放源代码组件的 exploit。（YouTube EP7svPQMQbRis，[529.7-1334.9]，L1）
- 〔NSDI（推测）〕讲者与同事 Yao Mu、Yi Wen 及导师 Mosharaf 与 Kang 合作开发 InfiniSwap，一个基于 RDMA 网络的高效内存解耦（内存去聚合）系统。VoltDB（跑 TPC-C）与 Memcached（跑 Facebook 工作负载）等内存密集应用在物理内存仅容纳 75% 工作集时性能骤降——VoltDB 只去掉 25% 内存性能却掉 80% 以上，Memcached 剩余性能不足峰值一半，用户因此普遍高估内存需求，造成集群内存低利用率（Google 集群超 80% 内存已分配但实际使用不足 50%）；现有方案均有不足——体系结构界的 memory blade 需要新硬件一致性支持、HPC 的高性能块设备 HPBD 无容错且不可扩展到集群、HERD 与 FaRM 等 RDMA KV 系统需要修改应用；InfiniSwap 由块设备（内核可加载模块，内含把 swap 请求按远端映射状态转发到本地盘或远端内存的请求路由器）与用户态 daemon（维护本地内存区域供远端使用）组成，本地盘异步备份换出数据以容忍远端故障，全部组件经 RDMA 单边操作通信、不涉及远端 CPU。（YouTube EP7zI2Is8nTos，[10.2-524.7]，L1）
- 〔NSDI（推测）〕去中心化远端内存管理与评估。块设备与 daemon 都以 1GB 大 slab 聚合小页以减少远端映射元数据（1GB 需 25.6 万条目）与等量往返通信；选远端机器用 power-of-two-choice——每次随机查询两台机器的内存信息、挑利用率低者建映射以均衡全集群利用率，避免集中式控制器的单点故障与扩展性瓶颈；daemon 驱逐时因单边 RDMA 不知各已映射 slab 的活跃度，用多选算法随机挑 e+e' 个查询活跃度后驱逐其中最不活跃的 e 个。在 32 节点 56Gbps InfiniBand 集群上，一半工作集放远端内存时应用性能比本地盘 swap 提升 2 到 6 倍（最小改善来自 GraphX，其 swap 突发使本地盘成为瓶颈），90 容器场景下集群内存利用率从 40% 提升到 60%；问答讨论了 1GB slab 由 daemon 预分配注册、无需周期性碎片整理，GraphX 本地盘瓶颈、尚不支持大页，以及未与 SSD swap 对比（评测用的是机械盘）。（YouTube EP7zI2Is8nTos，[526.4-1432.3]，L1）
