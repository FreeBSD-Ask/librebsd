- 〔USENIX ATC〕USENIX ATC '14 论文 XvMotion: Unified Virtual Machine Migration over Long Distance。主讲人（论文一作，斯坦福大学，与 VMware 合作）介绍首个商用可行的广域网虚拟机迁移方案 XvMotion，支持测试转生产迁移、政府强制的灾难准备演练、跨数据中心负载均衡与日益常见的 shared-nothing 架构。传统方案需共享存储、快速网络与同子网；广域网仅有约 1 Gbps、数百毫秒时延（加州到印度约 200 ms）且被多应用共享而丢包不稳，而高可用应用的秒级超时要求停机必须低于 1 秒。方案用异步 I/O 镜像处理存储迁移，把内存迁移与存储迁移绑定为单步原子切换（切换前任何失败都可回退源端），以流控机制保证内存与磁盘复制低开销完成，已部署于城域网。（YouTube EPLRooaX2SGtA，[10-605]，L1）
- 〔USENIX ATC〕XvMotion 的流控技术与评测。针对预拷贝依赖网络快于脏页率、早恢复（postcopy）在广域网上远程缺页极贵（200 ms/次，5 次即多 1 秒）且不原子的问题，提出 SDPS（Stun During Page Send）：在页故障处理中注入毫秒级睡眠把脏率压到网络速率以下，DVD Store 48 用户场景停机从约 2 秒降为恒定约 0.5 秒。存储侧用异步 I/O 镜像加类 TCP 拥塞控制的反压：限制目标端缓冲空间并把空闲量反馈给源端，按盘独立实施兼顾多盘公平。评测（12 GB 数据盘 OLTP）显示 0-200 ms 时延下停机恒约 1 秒、迁移时间仅随 TCP 慢启动线性微增，加州-印度 1 Gbps/214 ms RTT 实测内存复制 89 MB/s、盘复制 68 MB/s，负载惩罚仅 11% 且与本地迁移无异；Q&A 讨论了失败回退，并致敬 Theimer 等二十年前的预拷贝先行工作。（YouTube EPLRooaX2SGtA，[605-1195]，L1）

- 〔OSDI〕OSDI '24 论文 Identifying On-/Off-CPU Bottlenecks Together with Blocked Samples。主讲人 Minu（博士生，与 Zhang Min、Yang Jin 及其导师合作）指出计算环境演进使 on-CPU 与 off-CPU 边界模糊：高性能存储把 I/O 密集应用的瓶颈从阻塞 I/O 转向未同步事件，加速器把计算密集应用的瓶颈转移到加速器计算与设备间通信，因此必须同时考虑两类事件才能找到真瓶颈。现有分析器各有缺陷：Linux perf 在线程阻塞时停止采样，Coz 的 virtual speedup 只覆盖 on-CPU 路径，off-CPU 分析器 wperf 虽能追踪等待事件并以 wait-for 图闭环定位瓶颈，却缺 on-CPU 上下文、也不给出优化收益预估，可能导致优化不落在关键路径上。（YouTube EPLUU6UsfKhgk，[16-502]，L1）
- 〔OSDI〕BlockSample 采样技术与 bperf/BCOZ 两分析器。BlockSample 采集阻塞前最后的用户/内核指令指针与调用链、阻塞子类（阻塞 I/O、锁等待、CPU 调度等）并用 weight 字段合并重复样本以降开销；bperf 在扩展的 Linux perf 中给 off-CPU 样本加符号注解，BCOZ 把 Coz 的虚拟加速扩展到阻塞样本。RocksDB 用例一（OLTP、小块缓存）：bperf 显示 pread 引起的阻塞 I/O 开销最高并给出 filter/index/data blocks 三条调用链，BCOZ 预判优化 filter block I/O 收益最大，异步化后阻塞 I/O 事件减少 74%、总吞吐提升 1.8 倍。用例二（prefix 测试、大块缓存）：瓶颈是块缓存单锁竞争，分片（sharding）后锁等待减少 97%、吞吐提升 3.4 倍，而 BCOZ 提前显示优化阻塞盘 I/O 收益甚微。（YouTube EPLUU6UsfKhgk，[502-996]，L1）
- 〔USENIX Security〕USENIX Security '21 论文 PhishPrint: Evading Phishing Detection Crawlers by Prior Profiling。主讲人 Bhupendra Acharya（新奥尔良大学，与 Phani Vadrevu 合作）指出 Google Safe Browsing（部署于 40 亿设备）、PhishTank、Microsoft SmartScreen 等安全爬虫必须保持不可识别以防 cloaking 攻击，团队为此构建不含钓鱼内容的评估框架 PhishPrint：用单个二级域名派生多个三级域名保证可扩展性，以 IP、HTTP 头、DOM 属性与浏览器指纹等 forensics 信息刻画爬虫而非预设 cloaking 向量。实验 10 周内向 23 个爬虫每天各提交 12 个 URL，共 1.85 万个 token URL，约 90% 被扫描；8 个爬虫把 URL 分享给 VirusTotal 使累计爬虫达 80 个（VirusTotal 形同元爬虫），中位回扫时间 1.25 分钟（4 秒到 11.75 小时），共建立约 35 万个 HTTP 会话。（YouTube EPLUk2E9jHhfc，[8-319]，L1）
- 〔USENIX Security〕爬虫弱点画像与逃逸验证。基于浏览器异常（JS 执行、真实浏览器、自动化痕迹）、网络基础设施多样性（源 IP 与 AS）与指纹多样性（font/canvas/WebGL）得出 0-100 的 CVD 评分：GSB 因缺 WebGL 支持仅 23.9 分，Outlook、Avira 等真实浏览器项为 0，AlienVault 仅 1 个源 IP、OpenPhish 仅 2 个；35 万 HTTP 会话仅 204 个指纹元组，6 个爬虫因无真实浏览器连一个指纹都给不出，最好的 Bitdefender 也只有 9.3 分。验证实验中 6 个未 cloaking 钓鱼站约 3 小时全部被封，而 20 个基于弱点构造的 cloaking 站 4.5 天内无一被封、其余 18 个无限期未封；用户研究（约 11.15 万 Emtrak 用户与 50 万指纹库）显示 10-20% 用户会被该 cloaking 逻辑逃逸。团队建议爬虫使用真实浏览器、多样化网络基础设施、透明随机化指纹并监控与审核举报者，经负责任披露获得漏洞赏金与整改。（YouTube EPLUk2E9jHhfc，[319-642]，L1）
- 〔NSDI〕NSDI '26 论文 In Link We Trust: BFT at the Speed of CFT using Switches。主讲人（以色列理工学院 Technion）说明 BFT 比崩溃容错（CFT）更贵：需 3f+1 而非 2f+1 副本、依赖签名等密码学、需更多通信轮次；已有的可信组件路线（智能网卡、TEE、内存 sticky bits）靠消除 equivocation 提升容错，但仍依赖签名且出错时通信开销高。该工作提出把数据中心本就存在的可编程交换机作为可信组件：它看到全部协议消息、知道消息来源并可按包计算，且许多 BFT 协议本就隐式信任交换机（发未签名消息并假定不被篡改），控制平面与数据网络隔离、还可被厂商锁定。SwitchBFT 据此用入口端口做包来源认证（不靠密码学）、对客户端消息排序实现无跨副本通信的单轮快速路径提交，并通过协议验证在有副本出错时保持安全。（YouTube EPLWnWS-fRmU0，[18-495]，L1）
- 〔NSDI〕SwitchBFT 协议与评测。协议引入可验证不可靠原子广播（verifiable unreliable atomic broadcast）原语：无丢包时恰好一次投递、全或无、全序，且服务器可用 verify 函数校验第 k 条消息——客户端发送消息与摘要，交换机分配序列号并存储序列号与摘要。网络丢包时服务器凭序列号检测缺口并启动恢复协议：向其他服务器请求消息并用该原语校验，收到 f+1 个 bottom 值则认为该槽无消息；交换机另存每服务器 2 bit 状态，锁定每个序列号的一致恢复结果并强制后续恢复一致。基于 Tofino 交换机用 P4 实现，与用交换机排序的 NOPaxos、在交换机上用 FPGA 做密码学的 NeoBFT、用 SGX 的 MinBFT 等对比：端到端性能与 NOPaxos 相当，256 字节内哈希开销可忽略、最大消息尺寸下仅慢 15%，0.1% 丢包下几乎保持峰值性能、高丢包率下下降 20%，而 NeoBFT 高丢包时无法恢复部分消息。（YouTube EPLWnWS-fRmU0，[495-980]，L1）
- 〔USENIX Security〕USENIX Security '22 论文 GAROTA: Generalized Active Root-Of-Trust Architecture（for Tiny Embedded Devices）。主讲人 Ivan De Oliveira Nunes（罗切斯特理工学院，与 Esmerald Aliaj、Gene Tsudik（加州大学欧文分校）合作）指出多数信任根（root of trust）是被动的：能证明系统状态或设备执行过某动作，却无法保证某状态必被达成、某动作必被执行。GAROTA 追求广义的主动信任根：任意触发事件（传感器越阈、定时器到期、收到安全攸关命令等）都能保证 TCB 代码在整机软件全被攻破时仍被执行，触发事件与被触发的可执行体均可配置。首版设计面向无内核、无 MMU/虚拟化的裸机低功耗 MCU（几 MHz 单核、几 KB 程序存储），因易形式化建模而成为白板式（clean-slate）主动信任根设计的自然第一步，其思路是把未修改 MCU 的系统中断配置为 trigger 并绑定 TCB 执行。（YouTube EPLWsRoCeTdGM，[8-388]，L1）
- 〔USENIX Security〕GAROTA 的机制与形式化验证。GAROTA 用可信硬件保护触发配置（中断向量表与配置寄存器）不被 TCB 外软件篡改以保证 guaranteed triggering，并保证 TCB 代码运行时不可变（防 CPU 与 DMA）、原子执行、从入口受控调用；违规按 MCU 处理异常的方式复位，但复位后硬件强制 TCB 代码最先执行（retriggering on failure），使恶意软件陷入两难：让 TCB 运行，或复位后 TCB 照样运行。团队用线性时序逻辑（LTL）形式化这两个关键性质，先由证明助手证明硬件性质作用于 MCU 机器模型足以蕴含高层性质，再用模型检查器把 Verilog 设计转成符号模型验证实现满足性质。实现为监控程序计数器、访存地址等 CPU 信号的 Verilog FSM 子模块，成本不高于甚至低于同器件的被动信任根方案（因复用既有中断支持），代码、证明与玩具用例均已开源。（YouTube EPLWsRoCeTdGM，[388-775]，L1）
- 〔会议不详〕Zono：每核可扩展的日志（journal）设计。主讲人 Jong Seok Kim（成均馆大学），与三星电子合作完成。核心论断：Linux ext4 的 JBD2 日志为集中式设计，无论系统多大只有一个日志，所有核的缓冲区修改在日志层串行化、对存储设备的写也被提交事务串行化，无法利用现代 SSD 的内部并行性；而简单地让每个核心拥有独立日志，又会因共享元数据块在崩溃时出现"一个核的修改已持久、另一个核的修改从未提交"的一致性问题，因此需要为并行日志引入日志一致性协议（journal coherence protocol）。（YouTube EPLYQU5xU8HDY，[7-450]，L1）
- 〔会议不详〕序保持事务链与评估结果。Zono 维护已提交事务的事务链图记录优先序，checkpoint 时据此判断事务能否安全回写，链表采用无锁数据结构使各核可独立提交并在彼此日志中留下事务标记；commit block 额外存储事务链表与提交起始时间戳，恢复过程据此按全局序选择最新缓冲区镜像。在 Linux 内核实现并替换 ext4 的 JBD2 后，FFXmark 低共享场景 80 核较 JBD2 提升约 30%，filebench fileserver 场景 20 核提升 315%，80 核后因 NUMA 远程内存访问增多而缓慢回落。（YouTube EPLYQU5xU8HDY，[445-898]，L1）
