- 〔会议不详〕Consul：微服务架构下服务发现、负载均衡、健康检查与动态配置的统一方案。主讲人 Seth 任 HashiCorp 技术布道/技术倡导负责人且本人深度贡献代码，先以 SOA/微服务导入，归纳服务发现、流量负载均衡（内部网络中放负载均衡器是引入单点故障的反模式）、健康检查与运行时动态配置推送四大问题，并指出 ZooKeeper、etcd、Sensu 各只能覆盖其一；Consul 单二进制以 client/server 模式运行，客户端与服务器经 RPC 和 gossip 协议（主要走 UDP、可加密）通信，多数据中心经 WAN gossip 互联、跨数据中心流量经服务器转发；服务发现提供 HTTP 与 DNS API（.consul 后缀的逻辑服务名、随机轮询 A 记录、SRV 记录），旧式 Java 应用也能直接受益；健康检查内嵌于服务发现层、在节点本机执行且只返回健康节点，KV 存储支持 CAS、锁、会话与 TTL，Twitch、Datadog 等公司在数十万节点单集群规模使用；健康检查为 passing/warning/failing 三态（退出码 0/1/其他），warning 适合磁盘、内存等渐进资源，仅对状态变化告警，节点死亡靠 gossip 由同伴节点法定人数判定而无需心跳洪泛，Consul 因此能自愈——从服务发现层移除不健康节点，0.6+ 支持就近路由，结合 prepared query 可在数据中心故障时自动切换区域。（YouTube EPNFYb86qVcgo，[11.6-1270.4]，L1）

- 〔会议不详〕不经意密文压缩与解密问题定义及总体结果。主讲人（合作者包括转写作 Alexander Bierstock、Sarah Fattal、Kevin Yu 的三位）研究两个对偶问题：不经意密文压缩——服务器持有 n 个由客户端密钥（假设为同态加密方案）加密的密文，其中恰 K 个相关条目、其余条目加密为 0，服务器只知数量分布，客户端知道想取的相关条目索引，目标是压缩传输以降低通信；不经意密文解密——客户端持 n 个明文、要把 K 个相关条目加密发给服务器，且不泄露无关条目的位置信息；方案仅考虑半诚实模型、非交互、只产生单程单向通信，且只需加性同态加密；通信量从朴素的 n 降到 (1+ε)K，服务器计算 O(λn)、客户端计算 O(λ)。（YouTube EPNNqC3CCiTtg，[8.1-271.3]，L1）
- 〔会议不详〕基于公开矩阵的构造、banded 矩阵生成与实验应用。压缩方向：双方约定公开矩阵 A（维 (1+ε)K×N），服务器对加密向量做同态矩阵-向量乘得密文向量 B（加密为 0 的无关块在乘法中消去），客户端解密后以满秩子块 A1 解线性方程组恢复相关条目；解密方向对偶（N×(1+ε)K 矩阵，客户端先解线性系统再加密发送，服务器端乘法还原 n 长向量）；矩阵 A 的生成借鉴转写作 DW19 的既有结果并加以扩展：按列（压缩）/按行（解密）只在宽度 W 的小带宽窗口内生成随机项，W 足够长时 A1 以压倒性概率满秩；实验以同态加密库实现、固定 ε=0.07、n=1.5K 验证两协议开销，应用涵盖单服务器 batch PIR、双服务器 batch PIR 与 label PSI（详见论文）。（YouTube EPNNqC3CCiTtg，[314.4-722.4]，L1）
