- 〔NSDI（推测）〕Hashing Linearity：ECMP 并非黑盒。UCLA 的 Zhehui Zhang 与阿里巴巴集团合作提出 Repack。Clos 三层（leaf/spine/core）数据中心为高带宽与高可用构建了丰富路径多样性（服务器对之间通常数百条路径），但现状 ECMP（Equal-Cost Multipath）无状态、仅按包头哈希选路：哈希极化导致流量不均，故障容忍又依赖 BGP 等网内检测，无法发现链路健康、心跳可达但用户流量被丢的 ACL 误配置；MPTCP/Fuso 需改传输层且不具控制性，可编程交换机方案难部署，SOTA 的 X-Pass 需全新路由设计。通过研读多家交换机厂商支持的交换机抽象接口（SAI）开源代码与技术报告，作者发现 ECMP 流程（预处理位运算、XOR/CRC 哈希、后处理掩码/洗牌、取模选桶映射下一跳）满足哈希线性性这一基本性质，端主机改变包头即可预测并按需迁移流。（YouTube EPR6cUoGy9UTo，[8-389]，L1）
- 〔NSDI（推测）〕Repack 的基向量路径控制与测试床评测。利用线性性，Repack 无需为 112 位包头空间建 2^112 的表，只需记录 112 个单有效位的基包头，以 XOR 组合得完整路径空间与路径图：故障容忍时选非零相对路径变化把受影响流重定向，负载均衡时选负载最小的路径。示例中 spine-core 链路失效，端主机基于 TCP 重传检测故障后查询路径图、改包头第二有效位，spine 与 core 交换机同时换路避开失效链路。测试床（与生产数据中心同配置）评测显示 Repack 能亚秒级恢复链路故障，优于随机选路、无法恢复故障的 MPTCP，也快过需数十秒的 LACP 网内方案；高分辨率 RTO 可把故障检测触发缩短到数十毫秒，且与网内方案互补——静默丢包只有 Repack 能发现。作者展望基于 SAI 暴露的底层性质还有网络监控等更多应用。（YouTube EPR6cUoGy9UTo，[391-793]，L1）
- 〔会议不详〕Deca：应用定义的去中心化访问控制。德州大学奥斯汀分校（UT Austin）的 Zhongxu Yuan（转写 Yuan Zhongxu）指出好的访问控制需简单性与灵活性兼得，但 Unix/Linux 以用户、组与集中式 root 换取简单而过于僵化，setuid/suexec 等补充反而引入复杂性（Apache 文档甚至警告慎用），服务器应用只能自建访问控制逻辑、其漏洞被列为十大安全风险。OS 机制不灵活的原因在于 32 位 UID/GID 平坦命名空间迫使服务器做用户映射、root 权限集中管理且主体定义于口令文件等敏感系统文件。Deca（decentralized access control）以层次化点分字符串属性标识主体（.u.alice 为 .u.alice.photo 的父属性、代表其权限超集），可表示 OS 用户/组、服务器用户乃至应用组件；进程携带属性集并跨 fork/exec 继承，文件以 read/write/execute/modify 四访问模式（各为无否定析取范式的属性公式）的 ACL 控制，modify 对应 DAC 中的属主权。任何进程可添加现有属性的子属性并放弃父属性实现去特权而无需 root，PDF 查看器沙箱与服务器 dispatcher/worker 请求隔离均由 OS 直接裁决。（YouTube EPR7hV9patAc8，[9-497]，L1）
- 〔会议不详〕属性网关、与 DAC 共存及性能评测。为支持权限提升，Deca 引入属性网关（attribute gateway，系统中的特殊文件，read 访问模式指定普通成员、modify 指定管理员）表达普通用户自建的 ad hoc 组（如 Alice 的 reading group、服务器用户 Bob 的 friends 组），各应用可独立管理网关而无需同步全局策略文件。Deca 与传统 DAC 共存（二者任一允许即放行），因此 Linux 磁盘镜像仍是合法 Deca 镜像、支持增量部署；为隔离同 UID 不同属性的进程新增 p_mask 与 uid bit（进程只能清除以去特权，不能反向），p_mask=555 时 DAC 无法授予写权限。引导依靠保留的 root 与改造的 login/sshd/lightdm 为登录进程设置初始属性集；ACL 存于扩展属性并配内存缓存（可按时间戳/哈希失效）。应用演示包括未修改程序沙箱包装器、改造 DokuWiki、跨机 NFS 与 SSHD 子用户登录；文件系统微基准中 ACL 可放入 inode 时 ext4 减速不到 4%（需额外磁盘块最高 9%）、NFS 始终低于 5%，内核编译负载减速不到 2%，DokuWiki 回放六千余次修订无减速。（YouTube EPR7hV9patAc8，[505-1021]，L1）
- 〔FAST（推测）〕SMART：面向分离式内存的自适应基数树。复旦大学 Xu Chuan（转写）与华为云、香港中文大学合作提出 SMART。分离式内存（disaggregated memory）架构将计算与内存资源物理分离为两池并以 RDMA 网络互连，带来更好的资源利用率与弹性，但既有链式索引基于 B+ 树而在分离式内存上读写放大严重：内部节点含大量无用键与指针，叶节点聚多条 KV 导致整叶重写（内部节点可缓存时 B+ 树读放大约为叶节点跨度 32）；SOTA B+ 树 Sherman 用条目级版本避免写放大但读放大仍大。基数树叶节点仅存单条 KV、几乎无放大，但须克服三个挑战：远程粗粒度锁昂贵导致写性能差、内存节点 RDMA 网卡 IOPS 有上限（冗余小 IO 打满上限）、路径压缩与自适应节点使计算侧缓存校验复杂。SMART 的混合并发控制把每个部分键与对应子指针嵌入可用 RDMA CAS 原子修改的单个 8 字节条目、头部亦定长 8 字节，叶节点改用就地更新的日志式增量设计避免缓存抖动。（YouTube EPR7i9BacJ9Eo，[16-401]，L1）
- 〔FAST（推测）〕读委托、写合并、反向链与 YCSB 评测。SMART 另三项设计：重嵌入日志置于每个叶节点尾部，结合 RDMA in-order 投递把日志释放与叶节点写回合并、以校验和解决读写冲突；读委托用本地锁在每计算节点选出一个委托客户端执行相同远程读并共享结果，写合并把同键并发写聚入本地写合并缓冲，消除冗余 IO 与远程冲突；反向链在每个远程节点前部存指向父节点的指针，读取时与缓存条目中的节点地址不匹配即判定过期，化解父子关系调整导致的缓存失效。腾讯云实验（16 计算节点 + 2 内存节点）YCSB 整数键负载下，SMART 较 Sherman 写密集吞吐最高 6.1 倍、延迟低 1.4 倍，只读吞吐最高 2.8 倍；从 ART 逐项叠加的消融显示无锁内部节点与就地更新叶节点各带来 1.5 倍、重嵌入日志 3 倍、读委托与写合并各 1.1 倍提升。（YouTube EPR7i9BacJ9Eo，[393-799]，L1）
