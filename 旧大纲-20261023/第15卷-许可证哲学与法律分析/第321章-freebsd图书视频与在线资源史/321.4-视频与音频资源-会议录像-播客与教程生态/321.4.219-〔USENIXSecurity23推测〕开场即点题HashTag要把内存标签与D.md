- 〔USENIX Security '23（推测）〕开场即点题：HashTag 要把内存标签与 DRAM 完整性保护这两项互不相关的技术结合成一，并以案例研究证明能覆盖广泛标签内存架构，对其中一种架构还可把性能开销平均削减二十倍。内存标签的价值在于"it's hardware enforced security and we can mitigate a lot of memory safety issues by using memory tagging"〔00:08〕，代价则在于"we have this problem that it induces uh performance and memory overheads. There are tags that need to be fetched and they need to be stored somewhere"〔00:35〕；反观 DRAM 完整性保护，它是"an essential part in server computing"、且"usually has a very low memory overhead"〔00:43〕。〔01:03〕给出贡献定位后，讲者先铺 DRAM 背景：CPU 内存控制器经控制总线与数据总线连向 DIMM，芯片内有 bank，bank 内是行列式存储阵列，最小存储单元由晶体管与电容构成，电荷承载逻辑值；故障源于电容漏电与温度、辐射等外部影响，论文只考虑自然发生的位故障，明确不含 Rowhammer（讲者自称是 Csi Rowhammer 共同作者）。〔03:35〕ECC 用一到两个冗余芯片存放对写入数据计算的线性校验和并在每次读回时校验，DDR4 情形下代价是总线宽度从 64 位增至 72 位。线性码有哈明距离限制，错误超出后"might not even be detected or even worse it might be miscorrected"〔04:09〕，反而把错误放大。据此否掉两条捷径：从线性码偷比特存标签会同时削弱检错与纠错；把标签隐式编进校验和虽能在标签用错时暴露校验和不匹配，但标签从此不可再读，而且"Aliasing is possible"〔06:27〕，标签错配与真实错误互相冒充。〔07:06〕故结论是要显式存储标签并改用非线性函数。（YouTube EPY4zed8r47LQ，[8-436]，L1）
- 〔USENIX Security '23（推测）〕设计主线是抛弃线性校验和、改用截断散列："we throw out the linear checksum and we replace it with a hash"〔07:16〕，讲者强调这里的散列不需要密码学强度，只需要"a function that offers good diffusion"〔07:16〕，即改变输入一个比特时每个输出比特翻转的概率约为二分之一。〔07:46〕散列按缓存行粒度计算且"we include the tag in the hash computation"，于是标签自身的位故障也可被检出，截断后的散列与标签一起存放在 ECC 冗余芯片中，换来"tags are now readable because they are explicitly stored, and errors are detectable"〔07:46〕。〔08:33〕对函数的硬性要求是"the possibility of a collision should be sufficiently low"，最好 n 位散列的碰撞概率为 1/2 的 n 次方，同时要足够快，因为每次读 DRAM 都要算一遍。〔09:01〕讲者考察两种基于分组密码的结构：上方那种不具密码学安全但更快，把数据喂入分组密码实例后求和再截断；另一种"basically a PMAC construct"、"This one is cryptographically secure, but it's a bit slower"〔09:25〕，因最后一次分组密码调用要等其他调用结束。〔09:36〕由于只假设自然发生的位故障、没有主动攻击者，任何强扩散函数都够用。〔09:53〕难点随之而来："when we move away from linear codes error correction becomes a bit tricky"。暴力纠错是猜测错误向量、施加于读出数据、重算散列并与存储值比对，命中即认为纠对，复杂度随迭代次数近似指数增长；加额外奇偶位虽不能定位错误，但可把搜索范围缩到缓存行前一半或前四分之一。更有效的思路是利用 DRAM 错误形态：单个卡死引脚错误读出的故障位间距恒定，可强约束搜索空间。〔11:31〕对比给出量级差距：八位错误用暴力纠错"it just takes about a year"，而基于模式的方案"it takes less than a millisecond"，模式法还支持到十六位，远超暴力可及范围。〔12:25〕案例研究中实现 Arm MTE 的方案用八个奇偶位保证捕获单位故障、再配四十位散列获得可观纠错能力，且无需额外的取标签或写标签动作，因为标签与校验信息共存于冗余芯片；三个理论模型 A/B/C 把上限推到"a tag size of uh fifty one tag bits"〔12:53〕仍能保留部分纠错与检测。〔13:18〕性能在"gem five simulator"上建模，红条是单独存放标签的常规标签内存架构，蓝橙两色是改用散列并把标签与散列相邻存放后的结果。〔13:57〕结论收束为"replacing ECC with a truncated hash allows us to co-locate tags in this additional chip"，从而消除存储与取标签开销，同时仍提供检错与纠错。（YouTube EPY4zed8r47LQ，[436-860]，L1）
- 〔USENIX Security '15（推测）〕开场申明工作性质："a measurement study on co-residence threat inside the cloud"〔00:15〕。背景是公有云里攻击者自己也能成为用户，从而"can launch attacks from inside the cloud"，而这类内部攻击"can leverage on more victim information and exploit more attack vectors, be more stealthy and therefore cause more damage"〔01:02〕。〔01:21〕讲者给出定义："Co-residence here is defined that in a public multi-tenant cloud, virtual machines belong to different users can be located in the same physical area"，并区分两类——机器级共驻下攻击 VM 与受害 VM 同宿一台物理机，既可走私道（需受害者配合，借 L3 缓存或内存总线等非预期通道通信），也可走侧信道；而"the side channel is a more serious problem because the attacker does not need to control the victim but can steal information through those unintended channels"〔01:51〕。机架级共驻则可引发功耗攻击，即在同一机架部署大量攻击实例、同时推高服务器功耗以试图触发该机架断路器。〔03:51〕选样理由是"we choose Amazon EC2 as our particular study candidate because it is the pioneer of IaaS and it has the largest business scale"，且 EC2 多数业务集中在北弗吉尼亚数据中心，故聚焦 US East 区域。〔05:43〕量化结果是"It is not very easy to achieve co-residence. An attacker might need more than two hundred probing instances to get a random pair of instances on the same physical machine"；若要与某一特定目标共驻，"the attacker needs around two to three hundred probing instances to achieve such coherency"〔06:16〕；机架级则"the attack needs around five hundred probing instances to place twenty instances under the same rack"〔06:52〕。〔07:41〕历史对比更说明问题：2008 年只需四十个实例即可得到七八对共驻，2012 年研究称约一百六十个探针可换得两对随机共驻，本研究却需逾两百个探针达成同等目标——"achieving correctness in E C two has become more and more difficult"〔08:06〕（正解 co-residence）。〔08:30〕溯源第一项：实例池显著扩大，"Back in two thousand and eight, the study only observed eighty-seven distinct physical machines"，本环境可观测到逾六百台承载同型号 m1.small 实例的物理机，放置选择更多意味着共驻概率更低。〔09:16〕第二项是放置局部性大幅下降——以私网 IP 作为物理位置强指示做可视化对比，2008 年同型号节点聚得更紧，说明当年型号局部性远强；可用区局部性同样如此，用户在启动前选择的可用区在 2008 年对物理位置的影响更强。〔11:19〕讲者还观察到放置策略变得更动态：公私网 IP 映射变化非常频繁，甚至出现不同型号实例同宿一台物理机的罕见情形，而既有文献称此前从未发生。（YouTube EPY5MVl6u7Xpc，[10-743]，L1）
- 〔USENIX Security '15（推测）〕中段转向网络管理策略：最明显的变化是"the domain zero information is no longer available in situ"〔12:23〕——域名零是 Xen 特权域，此前实例全部流量都经它，攻击者据此可唯一标识宿主机，隐藏后便难以核实目标物理位置。〔13:16〕路由路径上也被打了码：2013 年有研究称 EC2 路径跳数为偶数，本研究却"found that more than thirty four percent of those paths become odd number of hops"，提示部分关键路由器与交换机可能已不出现在路径上；另有逾 76% 的路径至少被混淆一跳，使云拓扑测绘与相关攻击都更难。〔14:04〕讲者提出更快的算法判断两个实例是否同机架、以及是否经机架顶交换机（ToR）拓扑连接，共识别出一百零九个不同机架，分类结果显示"the dominating topology in E-C two"是 ToR 且已成趋势〔14:51〕，但这恰恰让机架级相关攻击更脆弱，因为 ToR 交换机本身容易暴露哪个机架承载了某实例。〔15:27〕VPC 是 EC2 提出的防御性服务，"by hiding most of the networking information, it has made the old way to achieve coexistence impossible in VPC"，且已被广泛使用；但它并不物理隔离实例，共驻威胁仍在。〔16:35〕讲者给出新解法："we are able to propose a new way to achieve correctness in VPC by leveraging on the end-to-end latency and the number of routing hops"。先在 EC2 各可用区部署锚点实例构建时延表，每列是一个锚点、每行是一个某型号某可用区的 VPC 实例，据此比对相似性推测目标型号与可用区，"our evaluation shows that such speculation can achieve an accuracy of 78 percent"〔17:46〕；再以跳数不同先剔除逾六成候选，再用时延阈值过滤其余。〔19:06〕经私道信道验证后，"the attacker can achieve a confidence around seventy percent that the rest probing instances are located on the same physical machine with the target"——VPC 确实大幅抬高门槛。〔20:03〕据此给出建议：云内 DNS 应更好保护、可考虑引入随机性，公布全部公网 IP 段本身值得商榷，ToR 交换机等关键路由信息需更好防护，虚拟机放置策略应引入更多动态性（如利用用户历史信息）。〔21:27〕总括一句："even with all those management adjustment and the newly introduced defensive services, coherence threat has not been eliminated yet"。问答环节被追问探针成本，讲者确认公有云按量计费、成本随实例规格上升；被问六年后再看，他答"I don't think like this problem like can be totally eliminated like in a shorter time"〔23:49〕，威胁会被显著缓解但难以根除；被问方法能否迁移到其他云，他称因需纵向比较演进史故只研究 EC2。主持人与另一位作者随后澄清两项研究互补："they looked at older generations uh instances"、"M one M four and we looked at T two dot small"〔25:42〕，且各自在无私道信道的共驻检测与目标型号推测上互为前置条件。（YouTube EPY5MVl6u7Xpc，[743-1651]，L1）
- 〔WOOT '13（推测）〕开场抛出野心："This is our adventures in instructionless computation. We're going to compute uh at full Turing power without ever dispatching an instruction successfully"〔00:09〕。研究动机是关注目标里客观存在、却不被其设计者、程序员与安全加固者所预期的计算结构〔00:25〕；讲者把漏洞利用视为一门工程学科，指出"Programming those structures has become the foundation of all the advanced exploitation methods"〔00:59〕，这类未被预期的底层架构、额外状态与额外转移早在经典漏洞利用文献中便已十分显眼〔01:14〕，漏洞本质上就是对"非预期计算可行"的构造性证明〔01:21〕，并给出口号"any input is a program"〔01:36〕——"Any sufficiently complex input"、"is indistinguishable from bytecode"〔02:08〕，因为"We don't think of inputs as running on programs, but in fact they are, because this is what exploitation is"〔02:42〕——漏洞利用的日常就是构造能引发目标状态转移的程序、再追问这些目标能算什么〔02:56〕；而计算机科学最初提出"什么是可计算的"，由 Church 与 Turing 给出形式化，安全研究者则针对每一个平台回答完全相同的问题，只是不假想开发者所设的那一套〔03:32〕。〔03:57〕正题开始。〔04:17〕问题聚焦在指令之外的硬件逻辑：我们"describe trustworthy operation of computers in terms of traces"，而处理器里还满是缓存、微架构等额外状态，于是追问"How much can we cram into this logic?"〔04:40〕PAX 团队早已"made Excellent use of uh um uh i cache d cache uh split tlb lookups uh to actually store policy state"〔05:06〕，而"The computational power that's in there is Turing complete"〔05:24〕——尽管讲者承认"you can't argue with root shell. you can't argue with turing completeness"〔05:42〕，亚图灵架构对利用未必弱于图灵完备，"Wish we had a better, a more granular scale"〔06:04〕。〔07:13〕关键洞见是"People think of the x86 MMU as a lookup table. But in fact it has state transitions it's a whole automaton programmed by the tables"；陷阱处理"not only fires"、"It also writes"〔07:47〕，"it writes the error code to the stack. to where it thinks the stack is"〔08:06〕，于是"How about we write back to the data that affects the operation of the trap hammer"〔08:19〕，"We're sort of getting a tape of a Turing machine that way"。〔10:16〕构造取材于中断描述符表的三种门：常规的中断门与陷阱门之外，32 位架构还保留任务门——"a holdover from previous times when you could actually trap into a new task. We're going to use that"；入口 8 是双重故障、入口 14 是页故障，"Our machine is going to tick between page fault, double fault, page fault, double fault"〔10:37〕。〔12:43〕把任务门作为入口 14 后，CPU 会把包括虚拟内存基址 CR3 在内的全部状态按任务寄存器所指位置保存，再查找新任务；"There is a bit there called a busy bit. If that bit is uh set, then you have a double fault. You can't enter a busy task"〔13:22〕。〔14:07〕数据通路是"a task gate in the IDT points to a descriptor in the global descriptor table, GDT"，GDT 指向 TSS，而"TSS, uh, it's a large structure, it's over a hundred bytes"〔14:29〕，内含全部寄存器、各特权级栈指针、eip 与 cr3。〔15:00〕单条指令即可充当全部逻辑："this is the instruction that we're going to use a single instruction...which uh happens to be uh Turing complete, in fact"，即"decrement branch if negative"——一次内存拷贝加条件跳转与算术。〔16:17〕实现要点是"Keep EIP At an invalid memory location everywhere in all the test segment"（正解 task segment，任务段），每次取指都触发页故障；"The role of the decrement will be played by pushing the error code on the stick"〔16:40〕（正解 stack），不在乎错误码的值，而在乎栈指针被递减。（YouTube EPYFGwZA_4URg，[9-1085]，L1）
