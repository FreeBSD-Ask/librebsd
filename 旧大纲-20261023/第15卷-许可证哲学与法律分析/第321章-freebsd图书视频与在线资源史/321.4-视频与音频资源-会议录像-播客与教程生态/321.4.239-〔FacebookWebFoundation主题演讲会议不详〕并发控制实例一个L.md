- 〔Facebook Web Foundation 主题演讲（会议不详）〕并发控制实例、一个 Linux 内核设置、主动调查的价值与 TCP 指标。Memcache leases：对某个 Memcache key、其背后数据可能不可用（例如一个极热对象、其数据库正过载），会看到同一时刻一千个请求都在该 key 上 miss 并试图回填；与其让它们全部砸向后端资源、不如告诉它们“这个对象当前不可用、很多同类也在抢、尽快失败、连试都不用试”〔07:05〕。对 Thrift 同样：在某台服务器上注意到大量请求都试图联系同一个后端服务时，就说“你们都在试图联系 messages、或 ads、或 newsfeed、它看起来确实不太工作、别试了”，这能阻止一个服务里的灾难性故障扩散〔07:48〕。然后是“今天就能在 Linux 内核里改的一个设置”、它救过 Facebook 免于宕机——TCP abort on overflow：Linux 收到 SYN、若等待 accept 的连接太多、默认行为是丢弃报文〔08:31〕。内核文档的理论是这提升可靠性、因为客户端会像普通丢包一样稍后重试；但实际是根本无法接受新连接的服务器就是过载了、重试毫无帮助，而且按内核版本不同还会多出长达一到三秒的延迟——在服务世界里一到三秒是永恒〔09:03〕。该设置就是告诉内核遇到过载队列时直接发 TCP reset、它确实阻止了 Facebook 宕机〔09:37〕。团队使命之一是主动调查性能问题——主动去找服务负责人说“你的 TCP abort on overflow 没设对”；但调查有时感觉像《X 档案》：系统里大量未解现象、你要弄清到底发生了什么〔09:55〕。为什么还要主动调查？SRE 与 PE 的文化是被告警驱动、不应成为运营团队；作者认为这确实成立、但不知异常就去看、深挖一次能带来很多帮助：很多时候你不知道自己不知道什么、连指标都没有，一次调查常挖出长期可监控的新指标；主动调查还能在影响扩大前抓住问题——常发现只发生在百分之一请求上的问题、若等一周就会滚出一百；好的调查也养成好的调试工作流、危机时省时间〔10:10〕。调查由两部分组成：一个指标、以及对该指标分组的方式〔11:37〕。显见的指标如内存、CPU、磁盘 I/O 大家都有，但 TCP 栈拥有丰富的监控统计、即使应用开发者什么都不做也能告诉你网络与应用的性能〔11:51〕。其一 TCP resets（连接被强制中止）能告诉你某服务在超时请求、某服务在崩溃、甚至某服务根本没在运行〔12:20〕。另一个极有用、或许是最有用的指标是 TCP retransmissions：TCP 之所以重传、是为了在本质上不可靠的网络之上制造可靠网络的幻象，因此必须重传就说明底层网络出了问题——可指示坏掉的网卡、坏掉的网线、工作不正常的交换机与路由器；他们还给内核做了插桩、使内核记录每一次 TCP 重传及其源与目标〔12:43〕。（转写至此中断、演讲后半关于事故管理与学习的内容未包含在转写内。）（YouTube EPZWYaFXM4wQ8，[409-804]，L1）
- 〔USENIX Security 2023（推测）〕主讲人回顾 PrimeMatch（转写在 Primus／Primates／PrimeMatch 间摇摆）历经近三年、多重挑战才落地为产品的过程，感谢摩根大通内部的多元团队——量化、多方计算专家（转写音写为 N P C）、网络安全与销售人员，其共同努力是产品上线生产的关键〔00:08〕。更宏观的动机是：MPC 的首个一次性应用是 2008 年在丹麦的一场甜菜双拍卖、此后多年几乎没有其他应用；伯克利的同行维护的 MPC 仪表板记录产业采用情况、应用不多、多数集中在钱包、但整体采用率正稳步上升〔00:42〕。他们想在金融领域找一个 MPC 的真实应用：围绕隐私保护暗池有不少学术工作（本质是连续双拍卖）、但那些工作无一落地生产，因此回到起点重新思考拍卖、力求做出一个有盈利的产品——于是有了 PrimeMatch〔01:16〕。改造前的流程：银行每天向约六十家客户（对冲基金）发送库存清单，内容为 Apple、Microsoft、Google 之类标的、加上下单方向（long 即买入、short 即卖出）与数量；所有银行都这么做〔02:14〕。问题在于银行显然暴露了自身库存；此外客户端户提出异议——假设昨天从某客户那买入大额订单、库存因此变大、客户会怀疑“你今天库存多了这么多、是不是从我们这里买的”，于是客户要求把与它们之间的所有交易活动从清单里剔除、结果清单被缩减；而客户当然也不愿提交自己的库存、因为那会暴露策略〔03:08〕。解法是让客户也把库存以加密或掩蔽的方式提交：例如某客户加密提交了对某标的三百股的需求、而银行只有两百、即可匹配两百；公开出来的只有匹配数量——他们知道匹配了两百、永远不知道客户原本要三百；若无匹配则什么都不知道、连是 Apple 都不知道〔04:16〕。核心计算是求客户与银行数量的最小值、这是整个流程里最需要以密码学方式完成也是最贵的操作〔04:56〕。汇总即：一批客户把加密库存提交给银行、银行再尝试匹配，并可以做更有趣的客户间匹配——比如某标的（如 Apple）银行库存为零、但两个客户之间可以匹配、同样只公开匹配数量。密码学上最主要的新东西是安全比较协议：与既往工作相比、他们实现的协议不需要任何非线性运算、因此各方可以在本地自行计算而无需交互；另一处是既往协议的轮数复杂度是参与比较位数的对数级、而他们只有两轮——把数据发给服务器、本地算完即可得到答案；并且以高效的方式做到了恶意安全、这是密码学上的贡献；他们也强调并非直接套用现成的密码学工具（原话转写为 "we couldn't use some crypto tools from the south"）〔05:39〕。之后把产品推向生产的挑战之一是通用反馈：当你把这种东西卖给银行、他们会问“给我看一个已经用上 MPC 的应用”——那时什么都不存在、无法举例、这算负面因素；但积极的一面是银行已经有一批愿意尝试新事物的老客户、确实帮了很大忙〔06:40〕。（YouTube EPZXbvEhgoo6w，[8-464]，L1）
