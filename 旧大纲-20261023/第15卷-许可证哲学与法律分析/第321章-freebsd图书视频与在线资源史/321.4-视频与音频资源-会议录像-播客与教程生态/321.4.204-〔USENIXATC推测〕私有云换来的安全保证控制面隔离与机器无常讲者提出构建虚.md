- 〔USENIX ATC（推测）〕私有云换来的安全保证：控制面、隔离与机器无常。讲者提出构建虚拟化基础设施实质上是给服务器自建了类似网络带外管理网的控制面，因而可在 hypervisor 层做安全性与完整性检查；OpenStack 各租户跑在交换机上隔离的独立 VLAN，安全组由 hypervisor 强制执行入站防火墙策略，配合“机器无常”理念（出事后销毁实例并从黄金镜像恢复到已知安全状态），把取证与横向排查成本大幅压缩。团队还在构建三层安全能力：按 1 台、20%、50% 直至全量逐级推进的自动补丁滚动，配合健康检查并逐级通知 NOC、开发团队与业务方；在 hypervisor 侧只读挂载 VM 文件系统做 Tripwire 式哈希的运行时完整性检查，因发生在控制面而不可被绕过；以及按服务声明式描述网络 ACL，由编排层调用 Palo Alto 防火墙 API 自动下发。另有 VM 级进程完整性与内存行为建模、用自研 PCIe HSM 实现不可见的“盲 VM”可信计算、以及 VM 逃逸加固（ASLR/DEP）等开放研究方向。（YouTube EPWf7WCzw9lPg，[1900-3620]，L1）
- 〔SREcon（推测）〕Decentralized Data。Indeed 的 SRE Jason Cope（转写音写为 Jason Copy）做闪电演讲，介绍其为求职搜索引擎构建的 Lucene 索引数据分发系统：索引构建器把数据写入文件系统，再用 rsync 分发到可独立于数据库横向扩展的应用服务器；早期只有集中的系统管理团队管理这条复制栈，开发团队新增数据工件都得排队找他们配置，公司增长后成为明显瓶颈。他回顾了多年的故障形态：生产者写盘途中宕机导致数据损坏、重启后无法续写，早期只能人工回填已知良好数据；数据中心间丢包或断链时人工改写复制路径绕行第三数据中心；生产者侧网络 I/O 被海量消费者打满后引入“预置层”（staging tier）分摊带宽；以及重载 Lucene 索引时 JVM 堆从稳态 65% 冲到 95%、部分实例飙到 100% 引发级联宕机，最终靠刻意保留一批小堆实例充当保险丝。（YouTube EPWkupTQewzHc，[10-315]，L1）
- 〔SREcon（推测）〕下一代系统 RAD 与运维教训。另一类严重事故是把坏数据复制出去：生产者文件系统写满叠加发布代码缺陷，使损坏工件被复制全集群，消费者全部加载失败并通过健康检查，负载均衡器随之把它们全部摘除，造成 Indeed 全站空白页级故障。团队随后做下一代系统 RAD：用 BitTorrent 替换点对点 rsync，显著提升生产者侧网络横向扩展能力并自动绕开数据中心间断链；让开发者在代码里声明生产者与消费者使复制配置自动生成，让 SRE 规模随开发者增长呈亚线性；用 Consul 协调“金丝雀”式数据重载——集群中一台实例先拿锁率先加载新版本并等待其健康，再放行其余实例，取代按集群、区域、服务分别维护的定制堆大小。经验总结为：数据更新永远从已知良好数据续写、写盘尽量用原子文件系统操作、把发布工程的“金丝雀”思想也用到数据重载、用 BitTorrent 分发，以及为整个工程组织构建自助式系统以获得组织级可扩展性。（YouTube EPWkupTQewzHc，[315-520]，L1）
- 〔USENIX FAST（推测）〕备份去重存储的碎片化拖慢恢复速度。讲者（与合著者 Kaveh、Pavel 的联合工作）指出，每日增量备份采用“新块追加到存储末尾、旧块原地不动”的写入方式，随时间让块配方（chunk recipe）越来越纠缠，恢复时在逻辑上顺序的数据对应大量随机寻址，表现为碎片随时间近似线性累积、恢复速度不断衰减；定期重整布局并不可行，因为各备份对块的最优顺序彼此不一致，且若把最近一次备份的块保持有序，需搬动的数据比新块多两个数量级（30 倍去重率下每 1 个新块要搬 29 个旧块）。为此他们提出只依赖配方与缓存大小、不依赖具体 I/O 特性的度量“每恢复 1 MB 需读取的容器数”，其倒数（称为 speed factor）与恢复速度线性成正比，而缓存大小相当于设定观察碎片的尺度。数据集为 HP Storage 提供的两年碎片压力测试（480 个备份、变长块均值 4 KB、容器 4 MB、30 天删除周期、不合并小容器），在十块数据盘 RAID 6 的估算下速度因子降到约 0.2 时仅对应 8 MB/s 的恢复速度。（YouTube EPWmTY5sSwKMA，[9-678]，L1）
- 〔USENIX FAST（推测）〕前进装配区（Forward Assembly Area）与封顶（Capping）两条正交优化。前进装配区利用配方对未来访问的全知做缓存：用 100 MB 装配区按片装配，配 4 MB 容器缓冲与约占 2% 的配方缓冲，块直接落到目标位置，避免中间存储与额外拷贝，且每个容器每片只加载一次；rolling 变体改用环形缓冲做 O(1) 滑窗并增量输出，消除跨片边界的重复加载，两者在实际缓存规模下都显著优于 LRU；而当容器变大时，LRU 因分不清有用块与无用块、把宝贵缓存空间喂给无关块而性能塌陷，装配区方法则仍存在容器大小的甜点位。封顶在摄入侧直接限制碎片：把输入备份切成 20 MB 段，每段最多与 t 个既有容器去重，从而把碎片上界压到 (t+5)/20 MB，即用去重率换恢复速度；具体做法是取命中块最多的前 t 个容器，其余一律复制为新块追加到存储末尾。实验显示多花 10% 空间可使恢复提速 2 到近 4 倍、多花 20% 可提速 4 到约 6.5 倍，且对摄入速度影响很小甚至可能更快。（YouTube EPWmTY5sSwKMA，[678-1420]，L1）
- 〔USENIX Security（推测）〕OptiSan：在开销预算内组合多种空间内存错误防御。UC Riverside 研究生 Rahul George（与宾州州立大学合作）指出，近三年来严重度评分 7 以上的栈 CVE 逾 200 个，Apache 等 Web 服务器依然存在类似漏洞；用值域分析等静态分析手段在 Apache 中可找出多达约 3000 处可能越界的“不安全操作”。他们区分两类空间内存错误防御：一类在指针运算处检查是否越界、元数据记录对象边界（即 BaggyBounds 一类）；另一类在内存访问处检查是否触及无效内存、由元数据标记有效性（即 AddressSanitizer 一类）。由于内存访问可能远比指针运算更频繁，AddressSanitizer 的检查开销反而可能高于 BaggyBounds，因此在整程序尺度上必须建模开销；其目标是在施加多种防御时权衡性能与可利用性，把防御布置当作一个优化问题求解。（YouTube EPWotfsnPTZAo，[8-255]，L1）
- 〔USENIX Security（推测）〕方法论、实验与结论。团队先回应三个挑战：以操作粒度建模防御开销（先前工作如 E-SAP 只算检查开销，导致部分 SPEC 程序超预算）、建模可利用性以在多个潜在内存错误间定优先级、以及在预算约束下生成防御布置。实现上先用静态分析（源码或 bitcode）定位不安全操作，识别对应栈对象以建模可利用性，运行程序实测各项检查与元数据开销，再交给求解器产出布置并据此插桩。在 SPEC CPU 2006 的 17 个基准与若干服务器上，组合 BaggyBounds 与 AddressSanitizer 对不安全操作的覆盖最多提升 52%；BaggyBounds 约 85% 的时间被选用，原因是程序不安全操作的频率分布呈正偏，便宜的交给 BaggyBounds、昂贵的交给 AddressSanitizer，且部分程序上 AddressSanitizer 反而更慢。预算精度实验按覆盖全部开销的 25%、50%、75% 设三档预算，多数方案在 1 到 3 次迭代内收敛，仅个别案例略超预算。（YouTube EPWotfsnPTZAo，[255-512]，L1）
- 〔USENIX Security（推测）〕Uninvited Guests: Analyzing the Identity and Behavior of Certificate Transparency Bots。Brian Kadracki 与合著者 Johnny So、Nick Nikiforakis 指出，Komodo、DigiNotar 等 CA 被黑事件催生了证书透明度（CT）系统——一个公开追加日志，记录证书签发及其关联域名，使公众可审计 CA 行为；随着 TLS 普及与支持 CT 的 CA 增多，CT 事实上成为新网站上线的“代理日志”。他们研究三个问题：Web 机器人是否监控 CT 日志寻找目标、是否依据域名内容定向特定主机、其行为是否恶意。方法为蜜罐系统 CTPot：12 个测量节点各运行 HTTP 反向代理与 SSH/Telnet/FTP 蜜罐，周期性经 Let's Encrypt 为伪随机域名签发证书并交由 CT 日志公开；域名由编码签发时间戳的伪随机串、三分类子域（仿冒商标如 Apple/Facebook/Twitter、敏感串如 wp-admin、基线串）以及用树加花加鸟名拼出以规避商标冲突的良性主域构成。十周内共签发逾 4600 张 TLS 证书，收到逾 150 万次 HTTP 请求、来自近 3.2 万个机器人 IP。（YouTube EPWqQsTEQa6fM，[7-333]，L1）
- 〔USENIX Security（推测）〕实验发现：CT 机器人是自成一类的网络机器人。统计显示基于 IP 直连的机器人群与三类 CT 机人群重叠极少，说明 CT 机器人构成独立子类；新域名在证书签发后最快 12 秒即收到机器人访问，因此站主应把安全机制在申请证书之前就位。行为差异明显：针对仿冒域名的机器人约 80% 只发一次请求，另两类仅约 30%。TLS 指纹识别发现 75% 至 85% 的机器人把 User-Agent 伪装成 Chrome 或 Firefox，底层却多为 Python requests 之类抓取库，真正浏览器仅占 2% 至 12%。恶意性方面，针对敏感域名的机器人向网络蜜罐发起的请求近乎翻倍，三组中逾 90% 会真正尝试认证而非仅探测端口 22。结论是机器人用 CT 发现新站、按子域内容定向并随意图表现不同行为，且恶意机器人在总体中占相当比例；数据集发布于 uninvited-guests.github.io。（YouTube EPWqQsTEQa6fM，[333-551]，L1）
- 〔USENIX Security〕Global Confusion: TrustZone Trusted Application 0-days by Design。EPFL 与 Hexhive 实验室的 Marcel 与同事 Philipp、Matthias 合作指出，现代手机以基于 ARM TrustZone 的可信执行环境（TEE）隔离指纹、PIN/图案/口令与加密密钥等最敏感服务；GlobalPlatform 的 TEE Internal Core API 是可信应用开发者的事实标准，相当于该领域的 POSIX API。问题出在 InvokeCommand 入口点：签名中除会话数据外还有攻击者完全可控的 commandId、参数类型与 TEParam 数组，其中参数可为内存引用或数值；规范要求开发者自行校验类型，不匹配时可信应用应安全中止，但该校验是可选的。于是可信应用一旦漏掉校验、把数值当成内存引用处理，攻击者即可在内存拷贝操作中向 TEE 地址空间传入任意指针——这正是他们在跨厂商生态中反复发现、按设计产生的漏洞模式。（YouTube EPWq_Gc1kuB0g，[8-382]，L1）
- 〔USENIX Security〕流行度研究与缓解方案。团队收集覆盖全球约 65% 市场份额的五家头部 Android 厂商、约 545 份固件镜像、54 款设备、5 种 TEE 实现、2016 至 2024 年间约 14500 个可信应用，基于 NSA 开源逆向工具 Ghidra 构建静态分析器 GPCheck 做批量检测。在约 6900 个符合 GlobalPlatform 规范的可信应用中，850 个存在该漏洞、归并为 33 个不同受影响应用：9 个已有公开 CVE 或安全公告、10 个被供应商静默修复、14 个仍存在于最新版本；问题自 2016 年底华为、2018 年初三星起持续蔓延，并波及小米、OPPO、vivo 等厂商，且能拿到跨厂商、可直接在 TEE 内立足的 0-day，最终获得逾 1.2 万美元赏金。缓解方案是把“缺省放行”改为“缺省失败”：类型校验改为强制、缺失时可信应用安全中止，提案已提交 GlobalPlatform 进入评审，改动不影响外部 API 因而向后兼容，并基于开源 TEE 参考实现 OP-TEE 完成实现。（YouTube EPWq_Gc1kuB0g，[382-730]，L1）
- 〔USENIX Security（推测）〕SSH 公钥认证的信息泄露与更私密的新协议。讲者来自俄勒冈州立大学（Oregon State University），与 Lance、Stan、Yongjin 合作。SSH 公钥认证的既有问题是：客户端逐个提交公钥广告，服务器若全部拒绝即可学到客户端持有的全部密钥，配合 GitHub 上公开的公钥便能对客户端做指纹（该问题源自 Filippo Valsorda 的博文演示）；反向地，客户端可用他人公钥探测服务器是否认识某把密钥；服务器还会看到究竟用哪把密钥通过认证并持有相应签名，足以作为“某人登录过此服务器”的凭证，这属协议根本设计、无法靠配置修掉；此外服务器对一切请求一律放行即可充当蜜罐，诱使首次连接便信任陌生服务器的客户端连错地方。工作目标是设计一种让双方只学到最少信息的认证方法，兼容现有 RSA/ECDSA/EdDSA 密钥对，且开箱即用、不依赖易错的特殊配置。（YouTube EPWrX5UmUJoXw，[7-451]，L1）
- 〔USENIX Security（推测）〕协议构造、UC 安全分析与实测性能。两个构件是匿名多钥加密与集合求交：服务器把密文寄给一组接收方公钥，不同私钥解出不同明文，且密文不泄露接收方身份、只泄露其数量；再用一种“客户端可证明交集非空”的 PSI 变体，使客户端学到自己哪些密钥成功、服务器只学到交集是否为空。因此服务器只学到客户端密钥数量与“是否持有一把匹配私钥”这一比特、客户端学到服务器持有多少密钥及其授权情况，而自己没有私钥的公钥其授权状态不可被探测；想把人放进来的蜜罐服务器必须显式知道并纳入对方公钥，从而抬高首次连接被劫持的难度。方案已在 OpenSSH 中实现，安全分析在 UC 安全模型下完成；典型场景（客户端 5 把键、服务器 10 把键）认证只需几十毫秒与几 KB 数据量，即便服务器持上千把键，RSA 约 1 秒、ECDSA 约 0.25 秒。（YouTube EPWrX5UmUJoXw，[451-858]，L1）
- 〔USENIX Security（推测）〕Scalable and Hardware Independent Firmware Testing via Automatic Peripheral Interface Modeling。讲者与同事 Alejandro Mira、导师 Long Lu 合作，面向 MCU 固件测试（2018 年全球售出 281 亿颗 MCU）：MCU 漏洞既可造成隐私泄露等数字损害，也可能造成人身伤害等物理损害，而多数漏洞来自涵盖应用、库、操作系统与驱动的整条固件栈，例如 2018 年 FreeRTOS 的缓冲区溢出。由于 MCU 资源受限无法在设备上 fuzz，只能上仿真器，但仿真器不仿真外设，固件因而根本无法启动。已有三类方案各有短板：外设仿真支持不全且每种外设都需大量人工；硬件在环测试依赖真实硬件因而慢且不可扩展；部分仿真用软件桩替换外设依赖代码，既测不到外设相关代码又需大量人工。他们据此设定自动、硬件无关、协议无关、可扩展四个目标，并观察到外设千差万别而“接口”高度一致，于是把外设当黑盒，抽象出统一处理寄存器访问与中断触发的模型，从而不再仿真任何外设。（YouTube EPWwTRuvO_P5I，[9-343]，L1）
