# 321.4.151 〔USENIXATC〕GraphOne面向演化图实时分析的数据存储GraphOn

- 〔USENIX ATC〕GraphOne：面向演化图实时分析的数据存储。GraphOne 作者 Pradeep Kumar 指出现有图数据库只支持细粒度摄入与整图查询、批式引擎只支持粗粒度摄入，没有系统能同时支持批分析与流分析，拼装多套系统又导致私有数据存储间的过度复制与最慢组件拖垮整体。其核心是"数据可见性（data visibility）"抽象：数据始终先顺序写入 edge log（细粒度、快速摄入），再批量归档到按源顶点索引的邻接表快照，由分析端自行选择只读邻接表（快）或连同 log 中未归档边一起读取（最新）。删除以 tombstone 负数索引的追加操作实现，统一 API 的 graph view 逻辑视图（get_neighbor_degree/get_neighbors、create/update view 等）让 BFS、PageRank、求关节点等分析只需简单编程。（YouTube EPPqps3bz1LE0，[11-814]，L1）
- 〔USENIX ATC〕无锁归档、内存优化与对比评测。用 edge sharding 把边按区间分片，使归档阶段无需原子锁即可并行执行，带来良好扩展性；针对邻接表元数据内存开销，提出 cache line 对齐分配与 hub vertex（如社交网络中粉丝极多的名人节点）按 4KB 边界分配，把 40 亿边图的内存需求从约 150GB 降到 47GB（平均链长 2.47），且因内存对齐缓存一致性不成为瓶颈。归档阈值取 2^16 条边（批量与归档重叠）时摄入速率约 43.68M 边/秒，日志速率可达 80M 边/秒、支持更高的临时摄入。对比实验：摄入比 Stinger 快 5 倍以上、BFS/PageRank 更快；仅提供快照隔离（MVCC）的前提下比强一致性图数据库快 2-3 个数量级；比静态引擎（Galois 与 GraphOne 静态版）约慢 17%，并完全免去静态引擎约 34 倍于 BFS 本身的预处理开销。Q&A 说明重复边检查由前端负责、当前无磁盘缓存层，适合工作集可放入内存的场景。（YouTube EPPqps3bz1LE0，[818-1628]，L1）
- 〔会议不详〕LRMiner：检测操作系统内核中的数据竞争。福州大学的 Ziyu Lin 代表团队介绍 OS 内核数据竞争的危害——可导致数据损坏、未定义行为与内存泄露，进而引发 DoS、提权与限制绕过，Linux 内存管理子系统的 Dirty COW 即因数据竞争可被攻击者篡改关键内存乃至获取 root；内核代码逻辑复杂、高度并发且同步原语（互斥锁、自旋锁等）繁多，开发者易误用序列化机制。检测面临三大挑战：内核缺乏"哪个变量应由哪把锁保护"的文档且结构嵌套使加锁规则难以从代码直接推导；指针与数据结构大量使用导致复杂别名关系影响规则违反检测的有效性；良性竞争无法引发安全问题，需自动区分有害竞争。为此提出三项关键技术：field-aware mining 推导加锁规则、alias-aware checking 检查加锁规则违反、pattern-based estimation 识别有害数据竞争。（YouTube EPPrdV91WA7E0，[8-356]，L1）
- 〔会议不详〕field graph、别名分析与有害模式分类及评估。通过 field graph 以节点表示字段、边表示低层字段被高层结构访问的方式，拥有共同祖先的节点即属同一数据结构，从而自动判定变量与锁的对应关系并按访问计数阈值推导加锁规则；再经 field graph 上的别名识别与 lock set 分析（加锁入集、解锁出集、无锁访问即竞争）检出违规。归纳四类可造成安全问题的竞争模式：空指针解引用、错误处理绕过、未定义行为与 double fetch。在 Linux 与 FreeBSD 上评估：LRMiner 共报告 200 个有害数据竞争，其中空指针解引用 37、错误处理绕过 65、未定义行为 60、double fetch 38；与三个知名竞争检测工具对比，检出竞争更多、误报更少。（YouTube EPPrdV91WA7E0，[356-713]，L1）
- 〔会议不详〕AutoArmor：微服务间访问控制策略自动生成。浙江大学的 Xin Li 介绍微服务架构把大应用按业务边界拆分为可独立开发部署升级的微服务，service mesh 以代理透明地管理流量并加入访问控制、流量管理与监控；但原本本地调用的通信经网络暴露后形成攻击面（如 logging 服务被攻陷后，攻击者可直连数据库服务窃取敏感信息），而 Kubernetes、Istio 等提供的服务间访问控制仍依赖耗时、易错且不灵活的手工配置。既有文档、历史与模型三类自动策略生成方法在准确性、完整性与敏捷性上均不适合微服务；微服务小、调用方式统一、协议与库有限的特点为静态分析创造机会。团队据此设计 AutoArmor，含基于静态分析的请求抽取与基于权限图（permission graph）的策略管理两个阶段，由离线静态分析引擎、权限引擎与策略生成器三个组件组成：源码提交 CI 服务器后生成调用清单，部署时并入权限图，策略生成器计算需增改的策略并下发到控制平面。（YouTube EPPst9CpUZ13Q，[8-353]，L1）
- 〔会议不详〕程序切片请求抽取、权限图去重与评估。请求抽取通过建模调用库定位发起服务间调用的语句，从这些语句出发在控制流图上做反向污点传播获取程序切片，再经语义分析提取 URL、方法等属性，以最小但关键的代码片段降低静态分析复杂度。权限图用 service node 与 version node 整合同一微服务多版本共享的权限，消除为每版本单独生成策略带来的冗余策略与不必要更新。在 5 个开源微服务应用（64 个服务、6 种编程语言）上评估：755 个请求识别率 100%、属性抽取率 99.5%，每服务平均分析仅 57 秒；单应用策略生成少于 2 秒，更新与删除均优于逐版本生成的基线，千服务应用 12 秒内生成 900 条策略；消除冗余策略加速运行时策略检查，使应用端到端性能更优。（YouTube EPPst9CpUZ13Q，[353-706]，L1）
- 〔会议不详〕互联网范围的公开 LDAP 服务器测量。德国明斯特应用技术大学（FH Münster）的 Jonas 介绍 LDAP 协议除通讯录外还支撑集中认证/单点登录、基于角色的访问控制等关键用途，但此前缺乏全面研究；团队为此开发工具扫描整个 IPv4 互联网上开放 389（明文 LDAP）与 636（LDAP over TLS）端口的主机，识别 LDAP 服务器并评估其配置（含 TLS），ZMap 各发现约 370 万响应主机，其中约 8.2 万个不同 IP 对 LDAP bind 请求有响应。研究严格遵循伦理：仅请求与处理最小样本、以不实际传输凭据的独特计数方法统计泄露、数据在受限访问的内部服务器处理且分类后删除样本仅留元数据，并与国家 CERT 合作开展披露运动。（YouTube EPPv9jnMrZdro，[8-360]，L1）
- 〔会议不详〕发现：无 bind 读取、明文凭据、弱 TLS 与披露成效。约 92,000 次 root DSE 读取中 95% 无需任何 bind 即可获得，其余多可用空用户名/空口令的 bind 取得，暴露认证与授权配置错误；近 3000 个连接返回含凭据属性的条目。分类显示约 2.6 万台服务器支持被研究者证明多数不安全的 SASL 机制，9000 台暴露 Microsoft Active Directory 策略等内部信息，600 多台存在已知漏洞；1.2 万台发布姓名、邮箱、电话、社会安全号码等个人信息。1800 多台 Active Directory 服务器暴露凭据，人工+自动抽样分析显示约 32% 泄露可信凭据（含明文），估计逾 390 万凭据在 2024 年 1 月公开可访问，其中 526 台至少一个用户名含 admin 且伴随密码泄露；TLS 侧 36% 支持最新版本、65% 使用不推荐密码套件，弱加密与敏感数据泄露相关。2025 年 2 月向国家 CERT 披露后回访：1817 台泄露服务器中 475 台已下线、5 台改为要求认证，但仍有大量在线。（YouTube EPPv9jnMrZdro，[360-728]，L1）
- 〔会议不详〕用形式化验证构建生产级集群管理控制器（ESR 规约）。伊利诺伊大学的 Xu Dong（与威斯康星大学、VMware Research 等合作）指出 Kubernetes 等 fleet of controllers 运行在高并发异步环境且需随时处理任意点崩溃，正确性至关重要但难以保证：此前团队用故障注入工具 Seer 与 fuzzing 工具 ACTO 在 19 个成熟控制器中发现 100 多个 bug，但测试空间巨大、无通用正确性规约、活性违反难以可靠检出。论文提出控制器正确性形式规约 ESR（eventually stable reconciliation）——对任意状态描述 D，若期望状态从某点起固定为 D，则集群状态最终匹配 D 并一直保持，以单一时序公式捕获进展（progress）与稳定（stability），天然覆盖妨碍前进或稳定的任何类型 bug；并给出基于 Verus 的 Rust 验证框架 Unveil，已验证管理 ZooKeeper、RabbitMQ、Fluent Bit 的三个控制器，与未验证成熟实现功能对齐且端到端性能相同。（YouTube EPPv_0XLJ8eJc，[16-515]，L1）
- 〔会议不详〕证明方法：环境模型、活性假设、证明策略与工程成本。Unveil 提供环境模型（暴露集群状态的 API server、可任意时刻改期望状态的 client、共享状态的相邻控制器与异步网络，允许 TOCTOU、任意次数崩溃与任意离线、请求任意失败）以推理控制器与环境的交互；活性证明需要必要假设——借鉴 TLA 弱公平（就绪消息终将送达）、崩溃任意多次但终会停止（不限制实际次数）——以排除无法前进的对抗情形。证明策略把 ESR 分解为"环境终将稳定"与"稳定环境中期望状态终被实现"两个引理，后者仍需覆盖协调的各类角落情形，正是形式化验证发现深层 bug 之处。验证/代码比约 4.5-7.4，首个控制器证明约 2 人月、其余两个各约 2 人周；验证发现 4 个深层 bug，其中 2 个同样存在于参考实现；用 ACTO 与 Seer 生成的 1800 多个端到端功能与崩溃测试仅在自写的 ZooKeeper API 信任规约中发现 1 个 bug，被验证代码未发现 bug；代码已在 GitHub 开源。（YouTube EPPv_0XLJ8eJc，[515-1036]，L1）
- 〔会议不详〕MFKDF：把多因子认证密码学化地并入密钥派生。主讲人指出典型密码管理服务以"加 MFA（如 TOTP）保护登录 + PBKDF 派生密钥加密静态数据"应对弱密码与数据库泄露，却留下"既然密码弱到需要多因子认证，为何还能单独派生密钥"的矛盾。MFKDF（multi-factor key derivation function）的基本创新是把用户已在使用的 SMS、TOTP、YubiKey 等因子以密码学方式并入密钥派生过程：TOTP 等因子是动态变化的，通过密钥反馈机制在函数内临时保存秘密，每次派生密钥时即预设好下一次登录的成功条件（当且仅当提供正确因子），实现覆盖 HOTP/TOTP、YubiKey、各类带外认证乃至生物特征等内在因子。暴力破解必须穷举所有因子的全部组合而非逐因子破解，获得指数级抗性提升，且 KDF 本应缓慢以抗暴力破解，故额外开销微乎其微。（YouTube EPPwBg3DjOk8g，[8-314]，L1）
- 〔会议不详〕门限恢复、密钥堆叠与落地场景。针对"忘记密码即丢失数据"的恢复困境（要么数据全失、要么引入可解任何账号的主密钥中心故障点），提出基于 Shamir 秘密共享的门限版 MFKDF：如设置密码+TOTP+恢复码而日常仅用前两个的 2-of-3 方案，忘记任一因子仍可由其余因子派生同一密钥，形成无中心故障点的客户端安全恢复机制。进一步把派生密钥作为另一 MFKDF 的因子实现"密钥堆叠（key stacking）"，以逻辑电路任意复杂地组合认证因子，把认证策略（如基于风险的认证）从软件强制变为密码学直接强制。基准测试显示相对 PBKDF 开销仅毫秒级；演示了全因子加密的密码管理器与客户端管理密钥的加密货币钱包（外观如中心化交易所、实为纯客户端），并作为 PBKDF2 的即插即用替代（mfkdf.com，甚至把 PBKDF2 重定向到 MFKDF），可推广到 Wi-Fi 认证、iOS/Windows 磁盘加密等 PBKDF2 现有用例。（YouTube EPPwBg3DjOk8g，[314-629]，L1）
- 〔会议不详〕用无密码学映射解耦机密数据库中的保护与间接。中国科学院软件研究所操作系统实验室的工作指出，机密数据库（CDB）以数据库系统结合 TEE 抵御不可信云基础设施，现有设计分 monolithic（整库入 TEE，安全高效但成了 DBA 无法诊断的黑盒）与 split 架构（主 DBMS 留在 TEE 外、敏感算子入 TEE，即现代商用机密数据库采用的设计）两类。以 sum 聚合查询为例剖析其两大瓶颈：服务端在关键路径上对数百万行做同步加解密（占执行时间约 56%），以及密文膨胀（4 字节整数加 16 字节 MAC 与 12 字节 nonce 膨胀为 32 字节密文，约 8 倍，占 25%）；根因是密文同时承担"在 TEE 外保护数据"与"作为数据库标识"两个角色，每次查找都要昂贵解密、每个产出都要昂贵加密。系统 Zeno 的关键洞察是解耦二者：数据库存储明文独立字段标识 FID，TEE 内 mapping store 维护 FID 到明文值的映射，计算时仅做约 30 周期的映射查找并返回结果新 FID，持久化时映射存储按块加密，保持与最先进设计相当的安全保证。（YouTube EPPwMcgD5hZMk，[18-500]，L1）
- 〔会议不详〕可扩展映射存储、跨域崩溃一致性与评测。扩展性上采用自增整数 FID（较原序列化表示省 71.4% 空间）、以稠密 FID 直接作数组下标实现 O(1) 映射存储，并解决数据库与映射存储布局错位导致的读放大（示例中达 3 倍）：存储布局感知分区使映射分区跟随底层堆表，FID 高位编码分区号、低位编码偏移，数据库页与映射页共用 OS 页缓存顺序预取；并发控制已由 DBMS 解决，映射记录访问无锁。跨域崩溃一致性上观察到只需单向一致性（每个 DBMS 可见的 FID 必须有有效映射，孤立映射无害可回收），由此强制映射存储日志先于数据库日志持久化，并把两者合并为单一日志流——提交时 Zeno 仅封存（块加密并复制）映射日志、由数据库日志单次落盘托管，以一次块加密取代串行双刷盘。评测在非可信 Xen L2 与 Intel TDX 上对比 PostgreSQL、HEDB 及 TPC-H/TPC-C 与真实工业负载：TPC-H 上较 HEDB 快至 53.1 倍，TPC-C 显著收窄与明文 PostgreSQL 的吞吐差距（HEDB 吞吐损失最高减少 49.8%），TPC-H/TPC-C 存储开销分别降低 52.8%/38.9%；代码开源，性能技术已并入 GaussDB。（YouTube EPPwMcgD5hZMk，[500-1006]，L1）
