- 〔会议不详〕浏览器扩展引发的权限提升攻击：主讲人 Yang Mingkun（Southern University，导师 Pingyang Li 教授）。现代浏览器把不可信远程内容放入沙箱渲染进程，Chrome 与 Firefox 已实现站点隔离，使浏览器安全依托 OS 进程边界；但扩展先于站点隔离设计：扩展拥有独立 origin 与专用渲染进程，可在声明权限后访问浏览器 API 与跨站数据（如 Cookie），其内容脚本（content script）与页面同一进程运行且无额外特权，需通过扩展消息向扩展页面请求 Cookie 等特权操作。两类攻击者——读写能力者可利用渲染引擎漏洞执行任意代码并伪造 IPC 消息（Chromium 团队也承认渲染进程无法做到无漏洞）；只读能力者可用 Spectre、Meltdown 等瞬态执行攻击读取渲染进程内存——因此可伪造扩展消息、读取扩展存储与内容脚本内存，而研究发现的多个浏览器缺陷使扩展消息的 sender 字段不可信。（YouTube EPOjHjnw5j-UE，[8.2-328.4]，L1）

- 〔ACSAC（推测）〕MultiFuzz：面向单片（裸机）固件的多流模糊测试器。目标固件直接访问硬件、无 OS 与可挂接的硬件抽象层，广泛存在于 3D 打印机、CNC 机床等嵌入式设备，其输入经内存映射 I/O（MMIO）与多样化、可能复杂的外设交互；把 AFL 类文件式模糊器的输入逐字节映射到每次 MMIO 访问会引入大量与硬件实际消费方式脱节的低效字节。作者聚焦文件式模糊的三个问题：输入稳定性（对输入的小改动可能剧烈改变其被消费方式，突变频繁破坏反馈机制）、事件驱动固件在等待足够数据处停滞、数据散射（相关数据散布输入各处使部分突变策略失效）；MultiFuzz 改用多流输入表示，为各外设分配独立输入流，保证突变后的字节仍被同一外设消费。（YouTube EPOmRRxnzHMLQ，[7.8-300.2]，L1）
- 〔ACSAC（推测）〕MultiFuzz 的自适应流扩展与评估结果。当模糊器耗尽某条流时自适应叠加三种扩展策略：直接随机值（加速度计、温度读数等无特定期望值场景成功率出乎意料地高）、复制流内与同一外设寄存器关联的先前值（应对固件反复请求同步等重复交互）、以及每流字典加全 0/全 1 等典型边界值（满足复杂比较条件）；多流表示还把散落数据压回连续块，使基于 logging 比较替换的传统突变可对每条流独立生效。在多个固件目标上的评估显示 MultiFuzz 的代码覆盖与查错能力均优于或持平文件式模糊器，并发现已知与新 bug；案例研究逐条回放发现某键值对命令崩溃所用突变链（流扩展过串口读写、input-to-state 替换命中命令、复制先前值构造两条就绪命令、常规突变注入损坏的 URI 参数）；项目在 GitHub 完全开源。（YouTube EPOmRRxnzHMLQ，[300.5-619.4]，L1）
- 〔会议不详〕为什么要把密码学密钥移出进程地址空间：主讲人 Ignat 来自 Cloudflare（负责其生产网络运行的操作系统）。进程数据段里应用内部状态、用户数据与密码学密钥混杂，地址空间内一切可互访，一旦发生越界读（Heartbleed）、任意远程代码执行（Log4Shell）、缓冲区复用残留密钥（解密函数退出后密钥留在栈上）、core dump 或 ptrace 调试，密钥即告泄露；相比用户数据泄露尚可恢复，私钥泄露意味着身份被接管、数据完整性受损、彻底游戏结束（Heartbleed 也暴露了 CRL 证书吊销机制在大量吊销场景下不可扩展）。常见对策是 agent 模型（SSH-agent、GPG-agent）：把密钥挪进独立进程、以精简且严格定义的接口代为执行密码学操作，但需要维护两个进程、设计不易被利用的 IPC 接口并对主进程认证与 ACL。Linux 内核密钥保留服务（kernel key store）把这套 agent 换成内核：密钥以内核对象存储，具备类似文件的权限/ACL 并受 LSM 钩子约束，密钥生命周期隐式绑定代码生命周期、进程终止即由 OS 强制销毁并清零；现场用 keyctl 演示创建自定义 keyring、add/read 密钥与序列号标识。（YouTube EPOpPVX8gMe3I，[13.2-1221.4]，L1）
- 〔会议不详〕keyring 类型、企业级密钥管理方案与 request-key 接口。演示不共享用户组的 Alice/Bob 通过 keyring 权限位实现密钥共享；session keyring 绑定 SSH 会话，退出即被内核自动销毁（现场用 bpftrace 探针观察 user_destroy_key 触发），thread/process/user/session 等隐式 keyring 分别对应线程私有（如 Nginx 每线程一域一私钥）、用户级共享等生命周期，persistent keyring 靠定时器存活、适合 cron 等非交互任务。密钥类型包括 user（内核缓冲区）、logon（不可读回、供磁盘加密等内核服务共享密钥）、asymmetric（PKCS#8 私钥入内核后可请求签名并用 OpenSSL 验证）、encrypted（wrapping key 包装、明文不出内核）与 trusted（绑定 TPM）；进一步给出每次启动用 TPM 解包根密钥、云端 KMS/HSM 下发各进程包裹密钥的组合方案，以及 request-key 系统调用：进程只报密钥标签，内核回调指定路径的用户态 helper 程序（可按标签路由到云 HSM 等后端并做认证、组校验与 ACL），使密钥分发成为操作系统核心服务、应用与存储后端完全解耦；Cloudflare 博客附带可用内核 keyring 替代 ssh-agent 的 OpenSSH 补丁与密钥泄漏测试代码。（YouTube EPOpPVX8gMe3I，[1222.7-2433.0]，L1）
- 〔会议不详〕ELISE：以冗余消减与表示学习驱动的存储高效安全日志压缩系统。Linux、Windows、MySQL 等都为入侵检测与调试收集日志，存储开销巨大：先前工作显示单台机器一天产生超 3GB 日志、某企业一年需收集超 17PB、SEAL 显示少量机器一天即 50GB；剪枝与有损压缩会丢失频次型检测所需的重复事件、不适用于通用任务。现有无损方案中 GZIP 先做重复串预处理再以基于字符频率的哈夫曼编码压缩，DeepZip 用深度神经网络预测字符概率后接算术编码、压缩率更好，但缺乏日志领域知识、无预处理步骤且在整份日志上训练耗时。ELISE 由四个组件构成：日志格式化（转 JSON 并分块）、冗余消减处理规则、DNN 编码器与算术编码，最终产物为模型、参考表与压缩文件。（YouTube EPOrFwjh09Fpo，[8.8-344.0]，L1）
- 〔会议不详〕ELISE 的四条领域知识预处理规则与评估。规则一将日志条目中的键替换为短码（键组合不可枚举）；规则二对同一会话共享的字段值（如同进程日志的进程 ID）每会话只存一次；规则三对可枚举取值（如计算机架构）替换短码；规则四将时间戳替换为相对最小时间戳的偏移量，高频词（如文件路径）按频次编码。编码器为两层 LSTM、一层批归一化加两层全连接，训练后以预测结果驱动算术编码。在 13 个来自不同系统与应用的日志文件数据集上评估：ELISE 某数据集压缩比可比现有方法好 13 倍，平均比 DeepZip 快约 6 倍（结论中称压缩比优于 GZIP 与 BZIP2 两到三倍）；实验还表明只用部分数据微调一个 epoch 即可获得与多次训练相当或更好的压缩效果，训练/微调数据比例是压缩率与压缩时间的权衡。（YouTube EPOrFwjh09Fpo，[344.5-715.3]，L1）
