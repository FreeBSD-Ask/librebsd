# 321.4.147 〔会议不详〕对最先进基于溯源的入侵检测系统PIDS的系统化分析主讲人Trista

- 〔会议不详〕对最先进基于溯源的入侵检测系统（PIDS）的系统化分析：主讲人 Tristan（巴黎-萨克雷大学博士生、UBC 访问学生）。团队选取 8 篇近年发表于顶级会议的博士论文所对应的 PIDS，在统一框架（单一代码库、每系统一个 YAML 参数文件）中重实现，这些系统架构相似、均基于 GNN 并以自监督方式无监督训练；框架之上还搭建可跨运行复用先前计算的实验流水线（只重跑被修改组件），支持组合式架构探索。研究在 DARPA TC 数据集（DAP-TC/OP-TC）上实验并结合论文设计评估共找出 9 个关键缺陷；重点指出 recall/precision 等标准指标不适合攻击检测：数据集含多个攻击需分别验证真阳性、recall 过度看重检出全部真阳性（少量节点即可重构攻击，低误报更重要）、不适配极端类不平衡，且阈值位置对指标影响巨大——以 KDD CUP 99 上 Archers、NodeLink、Kairos 三个系统的节点级异常分数分布为例，阈值放置的好坏可完全改变检测结果。（YouTube EPOr_iAucWqT4，[10.1-351.6]，L1）
- 〔会议不详〕提出阈值无关的攻击检测精度指标 ADP，并用极简基线 Vilocx 击败全部 8 个 SOTA 系统。Vilocx 对文件路径、进程命令行、IP 地址等系统实体做 word2vec 文本嵌入后接简单神经网络，以类型预测任务自监督训练；在 9 个 DARPA 数据集、超 400 GPU 训算日的对比中，Vilocx 的平均 ADP 全面领先、判别能力最佳，且仅凭入边即可实时检测（约 5MB 内存、低 CPU、每秒处理超 2000 条边）。这引出两点观察：系统日益复杂但未必必要，需以全面的消融研究验证每个组件的价值；DARPA 数据集中文本属性已足以检出多数攻击，与 APT 攻击不应被如此简单特征检出的预期矛盾。近期研究发现 GNN 仅凭图结构也能检出攻击、捕捉不同语义且检测边际更大，但 GNN 部署实用性差，使用前应与简单方法充分基准对比；未来将构建文本特征不泄露信息的 APT 类数据集、研究捕获机制，并探索 Vilocx 部署在客户端、服务器端 GNN 深度检测的两阶段方案；框架 PIDS-maker 与 8 个基线、9 个数据集已在 GitHub 开源。（YouTube EPOr_iAucWqT4，[352.4-728.7]，L1）
- 〔会议不详〕IoT 库管理测量研究：主讲人 Han Zhang（与卡内基梅隆大学的 Abhijit、Matt、Urvashi 合作）。知名品牌的 IoT 设备同样带有众所周知的漏洞，原因在于 IoT 软件栈与传统应用一样存在第三方库复用与补丁滞后；由于固件以二进制发布、无法直接得知库版本，作者借助开源库的 GPL 披露（含库名与精确版本号）测量 5 家流行厂商、27 款设备、8 年间 122 个固件发布的库使用情况。关键发现：厂商极少更新库、大部分时间使用含漏洞版本——Nest Learning Thermostat 仅在三个时间段使用最新 OpenSSL 版本，Nest Protect 的库版本一度落后超 1500 天，即使同厂商不同设备的库版本也不一致；结合 Ripple20、Code Strangler 等近期 IoT 库漏洞事件，作者认为把及时更新所有库的责任压给个体厂商费力而回报低、不可持续。（YouTube EPOsKWUCQbdog，[7.9-355.2]，L1）
- 〔会议不详〕提出 Capture：集中化 IoT 库管理的新架构。现状下每台设备把库运行时打进固件、更新须重打包发布，而本地多台设备常复用同一库或类似替代品；Capture 让用户手机上的专用 Capture Hub（兼作本地设备 Wi-Fi 接入点）保存库的唯一最新副本并负责安全更新，设备拆为运行在 hub 上的驱动程序加本地固件两件套，开发者对两者完全掌控且仍可在固件内保留 hub 未覆盖的特殊依赖。安全上利用 WPA2 特性构建设备专属 VLAN 与独立网络凭据、为每台设备绑定虚拟网络接口并分配子网，为每个驱动创建安全域管理共享 hub 上的资源隔离，再以网络防火墙与 Linux 安全模块建立强隔离运行时，并阻断本地设备除驱动外的全部网络通信，即使固件含漏洞组件也受保护，驱动仍可与公网通信以保留云功能。迁移方面提出原生驱动、OS 替换与框架扩展三种集成方案，将 9 个 GitHub 开源应用集成进 Capture 评估：部分应用因计算移入更强的 hub 而时延改善，最差时延增加 50%（硬件平台差异导致 6 至 200 多毫秒波动）；IFTTT 触发-动作小程序宏基准显示与原基线无显著差异，延迟主要来自云后端服务的数秒级开销。（YouTube EPOsKWUCQbdog，[356.6-723.2]，L1）
- 〔会议不详〕Magi：复杂网络实验编排，基于 DETER 测试床七年使用的工具，主讲人 Olivia Hussein。网络实验要求在用户规模的互联网/企业网模型上对被测系统做真实、可重复的评估；被测系统多为多源技术集成的分布式部件，可按多种方式配置并与背景流量、应用混合耦合，实验目标包括识别难以跟踪的角落性能问题（网络安全实验中攻击下的不可预期行为只能在测试床评估中看到）并获得统计可靠、可复现的结果。现有手段不足：SSH/shell 脚本脆弱、可重复性差且少有报错与校验能力，Ansible 类配置管理工具虽工具丰富但表达力有限，各测试床各有专用工具，DETER 第一代点选工具 Cir 之后演进为聚焦规模、可重复与自动化的 Magi。Magi 实验由概念模型翻译为 YAML 规范，包含 group、agent、event、event streams 与 triggers 五个指令：group 把行为角色映射到物理/虚拟机，agent 指定代码实现与执行参数，event 对应 agent 内可调用的方法，事件按序组成事件流，trigger 提供基于时间或事件的同步点。（YouTube EPOvHUve1I_eE，[8.3-450.5]，L1）
- 〔会议不详〕Magi 编排器架构、DETER 案例与经验总结。编排器由 parser（读实验脚本、识别事件流并调度）、scheduler（每个事件流一个线程、向各节点异步非阻塞发事件）与 evaluator（关联节点返回值、驱动触发条件协调事件流）组成，节点上部署轻量 daemon 接收事件、启动并控制 Python 实现的 agent 模块并回传结果。案例覆盖：本科计算机网络课程的多里程碑项目评估（学生客户端与 30 客户端分布式系统评测）、2000 web 客户端与 1000 控制客户端对 Apache 服务器农场维持瓶颈链路 100Mbps 流量的感知-决策-执行反馈回路、五个团队在 Tor 上部署抗审查通信（10-100 节点，Magi 完整编排 Tor 网络搭建、五项技术部署及微博、VoIP、文件共享背景流量）以及 IEEE 39 节点电力总线叠加 18 节点通信拓扑研究 DoS 攻击对功率流振荡影响的网络物理实验。经验：拓扑无关规范可从小规模实验直接放大复用、事件流与同步点带来的并发与异步操作支撑大规模快速执行、daemon 的系统性错误反馈显著助力调试与优雅降级；代码开源并已用于 EmuLab、GENI 等其他测试床环境。（YouTube EPOvHUve1I_eE，[450.5-933.4]，L1）
- 〔会议不详〕x86 系统管理模式（Ring -2）二十年的权力、特权与危险：系统化研究。主讲人系统化梳理了运行于 SMRAM、经 SMI 中断进入并以 RSM 指令返回的 SMM（System Management Mode），回顾了 69 篇研究与 57 份厂商通告，并给出按启动期/运行期、平台配置、内存安全、微架构与 shielding 分类树标注各工作的方法；第一纪以平台误配置漏洞为主（厂商把本应锁定的控制位留开，攻击者可篡改 SMRAM），以 Intel 推出 CHIPSEC 平台评估工具为界，此后转向更多运行期与代码类漏洞。（YouTube EPP02ResrIGXo，[9.4-461.0]，L1）
- 〔会议不详〕第三纪（至 2026 年）漏洞趋势与六大未来研究支柱。第三纪中 shielding 与内存安全类漏洞持续增长，评估固件代码的工具越多发现越多，而 AMD 因缺乏平台配置工具使十五年前已解决的问题重现；主讲人提出 SMM 硬化（ASLR、分页）、内存安全语言重写固件、以根信任去特权化 SMM、开放评估与工具（TianoCore、coreboot，Intel 计划发布固件版 Pin）、弥合学术界/工业界/黑客社区鸿沟并建设可复用数据集、补足微架构安全评估（微架构相关通告中仅 8 份提及 SMM 可被影响）等支柱，并把 x86 经验推广到 RISC-V 与 Arm 的其他特权模式，现场以 QR code 提供含全部表格与通告的在线网站供社区持续贡献。（YouTube EPP02ResrIGXo，[461.0-971.0]，L1）
- 〔会议不详〕DeHalox：基于符号微分的通用反编译器测试框架。普渡大学的 Mu Qi 介绍反编译四步流水线（反汇编器生成汇编、lifter 生成 IR（如 LLVM IR、Ghidra 的 P-code、IDA 的 BEX IR）、反编译器施加数百条启发式、printer 输出 C 代码），其调研的 15 个反编译器中仅 4 个使用语义保持启发式且大多只涉及控制流图；DeHalox 由 recompiler（利用编译错误日志在函数级迭代修正并把高层代码重编译回 IR）、基于符号执行与 SMT 求解器比对不同 IR 符号模型的 SimDiff、以及开关现有启发式定位问题规则的 Tuner 三部分组成。（YouTube EPP4TtXmWZaBs，[8.0-293.5]，L1）
- 〔会议不详〕在 Ghidra 与 Angr 上的评估与两个案例研究。团队对 Ghidra 与 Angr 测试了 56 个函数，发现 25 个 bug（17 个未知），Ghidra 中约 80% 的 bug 可归为函数原型恢复（43%）、lifted 变量恢复（18%）与类型恢复（18%）三类，Tuner 修复了 16% 的函数并正确定位 4 条问题启发式；案例一是 DWARF 信息误用（参数顺序颠倒、函数重载时 title 匹配失败返回 void、结构体参数被局部变量替代，均可通过禁用 dwarf 修复），案例二是常量 128 被打印为 -128（Intel-less-equal 规则与 subvarious sign-extension 规则交互所致）；框架已开源，并感谢 Ghidra 与 Angr 团队的及时响应及 NSF、ONR、DARPA 资助。（YouTube EPP4TtXmWZaBs，[293.5-626.7]，L1）

- 〔会议不详〕Deterministic Client：在确定性沙箱中原生执行智能合约代码。主讲人指出可扩展的复制状态机（即智能合约）要求用户程序除隔离、可抢占外还须确定性，而现有 JIT/解释器方案相对原生代码开销大；x86 的 eflags 在 divide 等指令后未定义（Intel 与 AMD 微架构行为还各不相同）、RDTSC 读时间戳与 Arm 上 ISA 标注 unpredictable 的 load 指令都会破坏确定性，此外还须解决非确定性的定时器抢占与同一地址空间运行多沙箱的问题；项目 Dekel 支持 x86 与 Arm（此版本将浮点排除在外），要求代码与数据页分离、寄存器零初始化，用改造版 Clang 在汇编层重写并配合静态验证器，采用经典 SFI 的 32 字节 aligned bundles（如 Native Client）禁止指令跨 bundle 边界、间接跳转目标经掩码清零低 32 位以证明对齐，Arm 定长指令则无需此步。（YouTube EPPA3p6138Oeg，[17.9-518.7]，L1）
- 〔会议不详〕确定性计量、位置无关代码与性能评估。为避免非确定性定时器中断在副本间不一致处抢占，分支计量把指令计数保留在寄存器 R12 并在每个基本块末尾用不依赖标志位的 JRCXZ 指令检查越界；timer-based metering 优化为在定时器触发或外部调用时再检查 gas，保证程序在副作用外化之前必然终止；位置无关代码（position oblivious code）禁止读指针高 32 位（读 RSP 禁止、ESP 允许）并完全禁用 call 指令，以消除地址随机化带来的非确定性；SPEC 评估显示相对 LFI 仅 metering 产生显著开销（timer 约 15%、Arm 分支约 20%、x86 分支约 35%），并优于带 fuel 计量的 Wasmtime，零知识证明验证接近原生性能，端到端 Groundhog 智能合约系统在把密码学例程放入沙箱时事务吞吐翻倍。（YouTube EPPA3p6138Oeg，[518.7-1037.4]，L1）
