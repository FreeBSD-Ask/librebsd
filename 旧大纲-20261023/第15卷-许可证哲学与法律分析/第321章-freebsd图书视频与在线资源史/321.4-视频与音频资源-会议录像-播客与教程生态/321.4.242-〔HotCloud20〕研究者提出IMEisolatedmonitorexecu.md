# 321.4.242 〔HotCloud20〕研究者提出IMEisolatedmonitorexecu

- 〔HotCloud '20〕研究者提出 IME（isolated monitor execution），主张数据中心多租户隔离机制必须被重新设计，而非在 SGX 一类可信硬件上做增量修补。SGX 是加进 x86 芯片的 ISA 级指令族加配套微架构以强制更强的硬件隔离，但学界随即指出其易受侧信道攻击；Intel 承认事实却淡化处理，称此类攻击小众且难以规模化——"with the discovery of Spectre and Meltdown clearly these assumptions were disproven"〔00:38〕，随后 Foreshadow 基本击穿 SGX 的保密性保证，而修补代价不菲：为 Foreshadow 必须关闭超线程，"which in its worst case scenario can incur an overhead of as high as fifty percent"〔01:08〕。作者把缺陷归为三类：隔离很弱，因为租户共享微架构状态；缺乏对 enclave 内计算做加载后完整性检查的机制，使执行检查的代码可驻留在独立隔离地址空间；整个生态不透明，Intel 微码加密、补丁常常不正确或不完整——"the current state of the art of trusted hardware cannot really be trusted"〔01:40〕。IME 的实现路径是：开发者编写含核心逻辑与对应安全检查的源码，编译器同时产出应用二进制与安全 monitor，两者上传不可信数据中心，应用在 top half 流水线运行、monitor 在 bottom half 运行，且"these two pipelines are physically isolated from each other and share no microarchitectural state"〔02:29〕。IME 的三个目标依次是：对应用施加动态安全不变式以提供加载后完整性保证；为 top half 流水线中所有应用进程（无论受监与否）提供强微架构保证；以及以硬件构造的 Scala DSL 给出微架构的软件可读描述，即"we are implementing this in Chisel"〔03:17〕。对照 SGX 速览：enclave 嵌入宿主进程用户地址空间并拥有独立栈堆数据代码段，且"the untrusted host process itself cannot access the enclave pages unless it invokes the EENTER instruction"〔03:56〕；enclave 运行在权限最低的 ring 3 却可访问宿主全部地址空间却不能发起系统调用，IO 必须经宿主读写宿主可见内存；硬件维护 EPCM 记录全部 EPC 页元数据、只可由 SGX 指令修改，每次访问 EPC 页都据此判定，另有内存加密引擎加密写出数据并对读入数据解密与做完整性校验。作者再逐条给出 SGX 的根因缺陷：物理核上两组逻辑执行前端虽隔离，但"instruction queue stage uh all the microarchitectural state is actually shared"〔06:20〕，竞争由此产生；缓存侧信道方面，宿主与 enclave 共享 L1，宿主可诱使 enclave 把明文秘密带入 L1 再用 L1 terminal fault 泄漏，这正是 Foreshadow。IME 的结构是一个 diad——受监线程加充当动态完整性检查器的 monitor，"this monitor will run in the bottom half pipeline, entirely isolated from the top half pipeline"〔07:53〕，为便于内省，bottom half 可读 top half 的指令序列与寄存器状态，即"the top half ISA level, the ISA level register state will be mirrored in the bottom half CPU"〔08:00〕，bottom half 还能对 top half 流水线 stall、resume 或引发异常。地址空间上 top half 线程映射落在受其独占的 top-half RAM 页（类似 EPC），bottom half 中 monitor 是整个地址空间内唯一实体、不存在系统软件。（YouTube EPZkXh2SaF-fQ，[8-575]，L1）
- 〔HotCloud '20〕讲者随后以 CFI 为例说明 IME 上可表达的安全策略，并给出微架构细节、相关工作与开放挑战。CFI 要求程序执行遵循静态 CFG：同一目标节点走左分支合法、走右分支非法；由于判定只需寄存器状态里反映出的地址，作者规定所有能在 IME 上表达的策略"only can introspect the register state"〔09:53〕，即只内省 top half 寄存器状态而不得依赖其他状态。微架构上 top half 为乱序执行，bottom half 则"this five stage in order execution model"〔10:05〕，关键部件是 code pointer table——键为触发 monitor 代码的 top-half PC、值为对应 monitor 代码，top-half PC 命中条目即在 bottom half 触发检查；bottom half 硬件还把 top half 指令流复制进环形缓冲，其 ISA 能同时操作 bottom-half 状态与 top-half 流状态，例如对某 PC 快照 TI0 再与 bottom-half 寄存器 B1 比较；"the bottom half pipeline can basically stall or zap the top half instruction retirement and memory writes"〔11:29〕，检查通过才放行退休否则 squash。作者以一段 move 加 call 与 monitor 比较 rcx 快照值为例逐周期说明依赖如何跨流水线传导。相关工作方面：SGX 已被 Azure 与 Signal 的联系人发现功能采用；ARM TrustZone 因设有可访问一切的"the secure world privilege mode"〔15:00〕而与"数据中心本身不可信"的假设不合；Sanctum 用开源 monitor 在 RISC-V 机器级实现 enclave 隔离并提供缓存级分区，但未给出微架构的软件可读描述、微架构状态仍共享因而仍易受超线程侧信道，且"has no mechanism to provide to perform runtime integrity checks"〔16:09〕。开放挑战包括 monitor 引入 stall 带来的侧信道（对策为按 monitor 最坏执行时间做常数时间执行，或"early launch of monitors"提前发射〔16:48〕）、需切出受监模式的高性能网络 IO、多线程下能否让兄弟线程共享 monitor、系统调用、diad 迁移时额外的 monitor 状态，以及新增硬件带来的芯片面积与功耗；结论是 IME 能把安全计算与本机包括特权计算在内的全部本地计算隔离并施加动态运行期检查，第三个目标"the third goal is, which is still in work in progress"〔18:30〕——通过 Chisel 实现微码的软件可读描述——仍在进行中。（YouTube EPZkXh2SaF-fQ，[575-1142]，L1）
- 〔USENIX LISA 大会主题演讲·DevOps 运动〕讲者速写运维管理百年史，点明今天所谓常识多是 20 世纪的发明：1911 年泰勒出版《科学管理原理》，把科学方法用于日常劳动——虽然“站在人背后掐秒表”让他落下骂名，但其本意是让工人更高效、从而挣得更多、工时更短〔46:30〕；亨利·福特把 Model T 的售价从 1908 年投产时折合今日 2 万美元，降到 1927 年停产时的 3 千美元，“本质上还是同一辆车，只是越造越好”〔47:33〕；斯隆则在工厂之上补齐了大公司管理，还资助 MIT（今有其名字的大楼）。丰田家创业者少年时看母亲、祖母纺纱，纱线常断、穿回机器费时费力，遂发明后来称为自働化（jidoka）的招数——装一根小针，线一断机器即停，“其实就像早期的故障管理”，1927 年他创办自己的织机厂，后来才转产汽车，五问法也是这家公司的贡献、构成精益的核心〔49:12〕。休哈特自 1925 年任职贝尔实验室直到 1956 年退休，是统计过程控制之父，PDCA 最初是他提出的 PDSA（计划-执行-研究-行动）〔50:14〕；戴明作为其学生，毕生多在向世界证明老师是对的——PDCA 常被叫作“戴明环”，但“戴明本人从不这样叫，他始终称之为休哈特环”；二战后戴明赴日协助人口普查并教授统计过程控制，几乎拿遍日本能拿的荣誉、受天皇褒奖，被尊为质量运动之父，在美国却直到 70 年代末仍受冷落〔50:50〕。大野耐一则被公认为丰田生产方式之父——也就是今天所谓的“精益”：二战刚结束，丰田社长立誓“三年内追不上美国的生产效率，日本就完了”，最严酷的处境逼出了最有趣的方案〔51:42〕，他也是准时制与看板之父，多数心法承自福特与戴明〔52:19〕。（YouTube EP3KpPBnEtRj4，[2790-3168]，L1）
- 〔USENIX LISA 大会主题演讲·DevOps 运动〕后半段聚焦丰田体系的技术底座：新乡重夫（Shigeo Shingo）是丰田生产方式背后的技术功臣，发明了 SMED——“十分钟内换模”〔52:48〕。当年冲压机换一套模具动辄数小时甚至数天，而大野想要的是只生产当下所需零件的看板/准时制流水，可“只打算做五个零件、换模却要一小时，你就完了”——这与今天裸机开通太慢只好批量攒批的困境如出一辙；SMED 指个位数分钟内完成切换，让机器压五个零件就换型、只造真正需要的量。讲者由此断言“配置管理本质上就是我们这个行业的 SMED”——如今起新服务器不过是套用 recipe 与 cookbook，从前难以落地的变更管理忽然全然可行〔54:02〕；大野还说过“没有 SMED，看板早就当场夭折”，理想主义必须配上技术组件〔54:29〕。随后还有防错法（poka-yoke）及其引出的零质控；德鲁克则在 1939 到 2005 年间写了 39 部管理学著作，“你们老板多半被他教育过还不自知”〔55:30〕。历史的转折：美国长期无人理会这套效率学问，直到 1973 年石油危机重创大批量生产——美国厂继续把没人买的汽车倾倒满地，日本厂却凭准时制“只造所需”当即停产、需求一回暖便复产，靠丰田生产方式安然渡劫〔57:17〕；80 年代日本质量令美国蒙羞，而把这一切带回美国的，竟是 1980 年 NBC 那部讲“日本人为何把我们打得落花流水”的纪录片——戴明的咨询业务从此火爆，1983 年起在美国出书〔58:11〕。之后高德拉特把约束理论写成小说《目标》，因为没人爱读商业书；沃马克 1988 年在《哈佛商业评论》撰文介绍日本质量，“lean（精益）”一词由此得名，1990 年又成书《改变世界的机器》〔59:35〕。全段的寓意：我们身边被推着接受的理念，多来自一群解决过自己问题、并把知识写成书分享出去的人〔60:07〕。（YouTube EP3KpPBnEtRj4，[3168-3620]，L1）
