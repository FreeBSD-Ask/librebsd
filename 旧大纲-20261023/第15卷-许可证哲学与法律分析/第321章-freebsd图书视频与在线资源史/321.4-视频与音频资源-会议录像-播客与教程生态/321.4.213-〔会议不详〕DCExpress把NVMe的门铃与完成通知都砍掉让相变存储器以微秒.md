- 〔会议不详〕DC Express：把 NVMe 的门铃与完成通知都砍掉，让相变存储器以微秒级时延接上 PCIe。HGST 研究组演讲者开场即声明这场报告“actually not going to be about phase change memory at all”，PCM 只是把团队推向该方向的第一项技术，真正想推动的是下一代 CPU 与总线该长什么样〔00:09〕。该组自称坐着的活就是琢磨“what comes after NAND flash”，认为“NAND flash is for revenues and not for research”〔00:37〕。作者反对把 DRAM 当下一件大事：维持一 TB 数据常驻 DRAM 要持续灌约一千瓦电，用旋转磁盘做同样的事只要约一瓦〔01:06〕。他梳理 STT-MRAM、FRAM、RRAM、CB-RAM 与最不惹眼的 PCM，指出共性是争夺电阻读出交叉点技术——电子穿过器件、感应放大器可在百纳秒内稳定，故读得快、代价是高成本高速，STT-MRAM 若成功“not going to displace NAND flash. - 〔会议不详〕接着处理完成信号与中断，最终协议实测队列深度 1 可达约 70 万 IOPS、端到用户进程约 1.4 微秒。中断被明确放弃——“The interrupt we want to avoid at all costs”：最快的 CPU 上跑 Linux，一次休眠加中断唤醒的上下文切换约 1.5 微秒，比器件本身慢一个数量级；于是取消中断、改轮询完成信号，并进一步彻底取消完成通知、直接轮询数据本身，因为读是快操作且发出命令前就知道数据落点〔11:39〕〔12:05〕。难点是 PCIe 是网络而非总线、允许乱序接收，重传包可能迟到，只盯最后一个包会造成数据损坏，故利用到 DRAM 的链路比 PCIe 快约两个数量级（混合内存立方体约 3 Tbps 对约 50 Gbps），在读命令发出前把一个自选的“未完成标记”写在各 DRAM 块尾——协议由此反转，不是等数据到来而是等自己写下的标记消失，再逐块检查标记是否还在以判断哪些包尚未抵达〔13:16〕〔13:51〕。标记与真实数据碰撞会让主机永远等不到完成；作者判断这仅与硬实时这类极小客户群相关，Linux 与 Windows 并不介意偶发时延尖峰，且 PCM 读是确定性的，最大时延即读时间乘队列深度，超时后重选随机标记继续〔14:01〕〔14:46〕。最终协议是端点从 DRAM 侧轮询、命令两端乒乓、主机轮询完成，设备空闲与否都在跑〔15:34〕。实测：以 512 字节为单位队列深度 1 可达约 70 万 IOPS，而 PCIe SSD 约 1.3 万且受闪存而非协议限制；带宽由链路决定，但那段近一微秒的协议时延在 PCIe 上不会缩小，故协议仍比器件慢约一个数量级，这正是希望下一代 CPU 与总线改变的地方〔15:57〕〔16:57〕。总结：PCIe 可承载近实时的批量读，端到用户进程往返约 1.4 微秒，是台上实测而非仿真，因此上下文切换已无必要；由数据推完成可推广到任何用两条时延悬殊链路乒乓内存的场景〔17:25〕〔17:46〕。答疑：HP Labs 的 Brad Morris 问为何不上 DRAM 总线，答要等 DDR 引入队列概念，且混合方案成本高、占插槽，做成 PCIe 卡在成本上更容易，PCM 写入受功耗限制更希望显卡式额外供电〔18:39〕〔19:34〕。Northeastern 的 Peter Desnoyers 问 PCIe 应如何演进，作者力荐混合内存立方体联盟，称 HMC 是“just like PCIe but done right”，且 PCIe 的 16 条通道不可拆分、必须等齐造成时延，HMC 每通道独立对接 vault，天然贴合交叉点存储〔21:25〕。Google 的 Ted Chou 问持续轮询的功耗，答论文实测仅约 6%、且是相对整机空载功耗，整机负载下更可忽略〔22:10〕。（YouTube EPXU5Bsw8Picc，[685-1397]，L1）
