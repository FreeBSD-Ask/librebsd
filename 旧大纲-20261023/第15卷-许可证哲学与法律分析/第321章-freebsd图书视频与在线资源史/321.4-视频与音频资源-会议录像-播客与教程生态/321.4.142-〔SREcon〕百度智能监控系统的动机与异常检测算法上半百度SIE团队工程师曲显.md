- 〔会议不详〕Shade：使分布式深度学习工作负载真正可缓存的系统。讲者（弗吉尼亚理工分布式系统与存储实验室）指出远程存储取数约占分布式训练总时间的 85-90%，而 GPU spot VM 可被随时抢占导致本地存储状态丢失、RAM 昂贵且容量不足，本地全量存储并不可行。缓存 DL 工作负载非平凡：样本随机访问且每个 epoch 全量遍历，但并非所有样本同等重要——FEMNIST 文本识别中易被误判为 C 而非 E、T 的难学样本决定收敛速度；训练 ResNet-18 于 CIFAR-10 时 26% 样本被访问超一次、10% 超三次，存在重复访问模式。由此得出 Shade 的关键洞察：DL 训练可区别对待不同样本，若能预测 I/O 访问即可缓存重要样本、根本性提升 I/O 效率。（YouTube EPNwIYM3O-qvA，[13.6-412.9]，L1）

- 〔SIGCOMM（推测）〕Poise：面向上下文感知 BYOD 策略的可编程网内安全。来自 Rice 大学与香港理工的讲者（Qiao）指出 BYOD（自带设备）设备管理薄弱、易被入侵，需按客户端安全上下文（库版本、录音状态、GPS 位置等）动态实施访问控制。现有 SDN 方案在控制器软件中维护每流状态并接收客户端模块上下文更新，防御敏捷性低（更新须经软件控制器）且易受控制平面 DoS 攻击（恶意客户端可发大量上下文更新压垮控制器）；根因是通用软件控制器处理速度远低于以硬件线速运行的交换机。工作观察到 P4 可编程数据平面（可定制协议解析、板载有状态内存、算术运算、匹配-动作处理）的硬件特性可转化为 BYOD 防御的安全收益，设计 Poise 系统与策略语言、编译器，将策略下推到数据平面以线速执行。（YouTube EPNy4IBFQYrus，[9.5-337.7]，L1）
- 〔SIGCOMM（推测）〕Poise 数据平面设计与 Tofino 评测。策略语言将两行策略编译为定制报文头（如 16 位 SSL 库版本字段）与匹配-动作表，并支持策略组合与资源优化等高级特性。为避免逐包打标的高流量开销，Poise 采用每流周期性发送仅含头部与上下文的 context packet：P4 交换机据此决策并记住，同一流后续数据包按最新决策强制执行，数据包本身不被修改，用户可调节发送周期权衡准确度；每流安全决策用 match-action 表在数据平面直接更新，新流插入延迟由精心设计的 cache 结构缓冲，表规模控制与针对每流表的 DoS 防护详见论文。在真实 Tofino 硬件 P4 交换机评测中，重 DoS 攻击下 SDN 方案首包延迟近 1 秒且新流安装失败，Poise 因上下文变更全部在数据平面处理、控制平面无攻击流量而始终能安装新流，展现对控制平面 DoS 的韧性。（YouTube EPNy4IBFQYrus，[369.1-741.9]，L1）
- 〔USENIX Security（推测）〕应用层无限流量环路的系统化分析。讲者给出环路示例：off-path 攻击者伪造源 IP 向运行不同 DNS 软件的服务器注入畸形报文，第一台返回 command unknown 错误，第二台因实现不一致不识别该错误而返回 not implemented 错误，两台服务器从此以错误报文互相响应形成持续环路，攻击者注入载荷即可催生。此类环路可用于单点打满目标、配对目标网络内脆弱设备打满骨干网或配对内外设备打满上行链路；约 20 年前已知 chargen 与 echo 可成环，此后缺乏对真实互联网的系统分析。方法学先用 Shadowserver 日报获取运行特定协议的服务器清单，发送 20-30 个手工探针触发差异化响应并按语义差异聚类，再以样本响应为探针二轮扫描，据此构建有向图发现潜在环路，最后以代理服务器居中被动转发验证环路可持续。（YouTube EPNz8XA710evc，[7.8-319.5]，L1）

- 〔会议不详〕Ken Thompson 与 Dennis Ritchie 谈 Unix 起源。1969 年贝尔实验室的几位计算机科学家为自用开发程序，他们当时所开发的逐步演化为如今在全球广泛使用的 Unix 操作系统。Dennis Ritchie 回忆 1960 年代末当时操作系统过于复杂，他与 Thompson 决定在小型机上构建一个小而简单的操作系统以逆转这一趋势；他们要保留的不只是良好的编程环境，而是一个能让社区形成的系统——分时系统所供给的公共计算之本质不仅在于把程序敲进终端而非卡片机，更在于鼓励紧密交流与同事情谊。（YouTube EPO-ddUItBk1Y，[2.7-63.5]，L1）
- 〔会议不详〕Unix 系统的三大组成。Unix 系统在此受欢迎的主要原因在于它为分解复杂计算任务提供了优雅的设施，其构成基本分为三部分：内核（操作系统本体）管理机器控制并负责调度；shell 作为命令解释器负责用户与系统本身之间的通信；第三部分也是最大的部分是各类实用工具程序，完成编辑文件、数字排序、绘图等具体任务，即不作为操作系统内核直接提供的所有其他程序。（YouTube EPO-ddUItBk1Y，[77.9-136.9]，L1）
- 〔TCHES（推测）〕SCARF：面向安全缓存随机化的低延迟分组密码。作为缓存攻击 session 的首个报告，讲者介绍组相联缓存如何被 prime+probe 攻击利用：攻击者用自身地址空间中映射到同一 index 位区间的地址填满缓存组，受害者按秘密访问后驱逐攻击者一条数据，攻击者通过计时即可测知，该攻击已用于泄露密码学代码密钥及 Meltdown、Spectre 等推测执行攻击场景。主流对策缓存随机化用函数 f_k 将地址的 tag 与 index 映射到每个 way 中的伪随机候选位置，但随机化函数如何选取常被忽视。SCARF（Secure Cache Randomization Function）设定功能需求：低延迟（每次访存都须先评估且在判知命中与否之前）、密钥依赖、给定 tag 可逆向还原地址（对写回缓存至关重要），聚焦 1024 组缓存——需将 48 位 tag 加 10 位 index 映射为 10 位输出并忽略 offset 位；攻击者模型允许查询两地址是否碰撞但永远看不到实际输出位置。（YouTube EPO1Ll0XLjUiI，[8.3-313.5]，L1）
- 〔TCHES（推测）〕SCARF 设计与硬件实现。直接采用 PRINCE 等低延迟分组密码会因 64 位块长需要对 58 位输入做填充，带来存储开销与更宽的 tag 比较逻辑，而定制 58 位分组密码又会引入部分密文碰撞这一别扭攻击者模型、难以兼顾低延迟与安全论证。SCARF 转而设计 10 位输入、48 位公开 tweak（即 tag）的可调分组密码：共 8 轮、前 7 轮相同、第 8 轮略异，采用 Feistel 与 SPN 混合结构，S 盒可并行执行近乎免费，从而在少数轮内吸收尽可能多的密钥位、把轮数减半并在攻击者视图下保持安全。硬件实现基于 Nangate 门库（45 纳米与 50 纳米），相较 PRINCE、Mantis、Karma 等低延迟分组密码，延迟与面积均减半；并用 PARSEC 基准套件评估采用 SCARF 的随机化缓存性能（对 PRINCE 系延迟减半作假设），讲者预告本 session 后续将报告一个可配合 SCARF 的随机化缓存架构。（YouTube EPO1Ll0XLjUiI，[340-680.2]，L1）
