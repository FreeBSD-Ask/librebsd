# 316.1.2 LibreSSL 从 OpenSSL fork 的工程史

**要点**：LibreSSL 由 OpenBSD 项目于 2014 年 4 月 Heartbleed 漏洞（CVE-2014-0160，2014 年 4 月 7 日公开）公开后启动 fork，由 Bob Beck 与 Theo de Raadt 主导；首个 portable 版本于 2014 年 7 月 11 日发布，2014 年 11 月 1 日随 OpenBSD 5.6 首次进入基本系统；Beck 自述 fork 真正诱因并非 Heartbleed 而是 OpenSSL 的 LIFO 内存分配器破坏了 Coverity 与 Valgrind 的可用性；fork 后首周内删除约 9 万行 C 代码，发现大量 20 年未维护的 FIPS 认证遗留代码（“abandonware”）；LibreSSL 后被 FreeBSD ports（2014 年 7 月 12 日加入 security/libressl）、Linux 发行版（Gentoo 等）、macOS 等采用

**史料**：threatpost.com/libressl-sticks-a-fork-in-openssl/105653（2014.4.23 Beck 访谈）、threatpost.com/first-version-of-libressl-debuts（2014.7.14）、openbsd.org/56.html（OpenBSD 5.6 release）、FreshPorts security/libressl 条目（Port Added: 2014-07-12）、libressl.org 官网、OpenBSD 源代码 src/lib/libssl、Beck 在 BSDCan 2014 演讲幻灯片 ［A］

**史观**：0 信任原则：Beck 自述 fork 诱因须独立考据，不能仅因官方叙事即采信；0 信任原则：FIPS 遗留代码问题需通过 OpenSSL 仓库核实

**辨析**：LibreSSL 的实际采用率远低于预期——OpenSSL 仍占主流，LibreSSL 主要在 OpenBSD 基本系统与少数 Linux 发行版中；fork 后 API 兼容性维护策略（Beck 称 “preserve API compatibility”）是否真实现需通过下游应用编译记录核实；“9 万行删除” 数字据 Beck 自述为 fork 首周内删除，需通过 OpenBSD CVS commit 历史核实具体时间分布；[考据完成：2026-07-30 三次联网核查补入 Beck 2014.4.23 Threatpost 访谈具体引文——访谈作者 Michael Mimoso，发布日期 2014-04-23 12:57 pm，URL `https://threatpost.com/libressl-sticks-a-fork-in-openssl/105653/`，原文引文如下：(1) "Bob Beck, an OpenBSD developer, told Threatpost via email that 90,000 lines of C code have already been deleted as the code has been converted slowly to modern C programming practices, including modern memory allocation practices and integer overflow avoidance, just to name two.“（90,000 行 C 代码已删除，转换为现代 C 编程实践）；(2) ”I‘d say we’ve probably already ‘improved’ it. For the time being we want to make sure that other than anything we find that is intrinsically dangerous, we want to preserve API compatibility so we don't break all the software out there that uses this.“（API 兼容性维护策略原话）；(3) ”Forking isn't something we take lightly, we know darn good and well it's a lot of work, however it had become painfully obvious in the past while that we would not be getting useful fixes from upstream“（fork 决策原话）；(4) ”For myself, and for Theo, I know it's been in the works seriously since we saw that allocator.“（fork 真正诱因为 LIFO 内存分配器，非 Heartbleed）；(5) ”The LibreSSL developers have found 20-year-old chunks of unmaintained code in OpenSSL, ‘abandonware,’ as Beck put it, code that was added for FIPS certification and never attended to again."（20 年未维护的 FIPS 认证遗留代码）；(6) “Important bugs sat in OpenSSL's tracker for four years—until we found them and fixed them in our tree.”（OpenSSL bug tracker 中重要 bug 滞留四年）；(7) "Most of the code doesn't use anything approaching best practices for modern C code. Lots of it will make your eyes bleed and roll backwards into your skull as your brain tries desperately not to see it."（OpenSSL 代码质量问题原话）；[存疑脚注] OpenBSD CVS commit 历史中“9 万行删除”的具体 commit hash 与时间三次复查未得——OpenBSD CVS 仓库 `https://cvsweb.openbsd.org/src/lib/libssl/` 可访问，但具体删除 90,000 行代码的 commit 序列须通过 CVS commit log 逐条核验，三次 WebFetch 抓取 cvsweb.openbsd.org 超时未能获取具体 commit hash，标注为存疑待后续 CVS 日志本地核验后补充确证]
