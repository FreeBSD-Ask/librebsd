# 034.10.2 UNIX/32V 简单换页机制 → 3BSD 请求调页式虚拟内存的引入（1979）

**要点**：UNIX/32V（Bell Labs 1978 年由 John Reiser 和 Tom London 完成移植，UNIX V7 内核的 VAX 移植版）仅支持简单的换页（swapping）机制——整个进程在内存与磁盘交换区之间整体换入换出，无法按需调页，导致进程地址空间受物理内存限制、上下文切换开销大；**3BSD**（**1979 年 12 月**）由 Özalp Babaoğlu 实现核心 working set 分页系统、Bill Joy 协助集成到 32V 内核并调试，加入请求调页式虚拟内存（demand paging）——利用 VAX 硬件页表与 TLB，进程可使用大于物理内存的虚拟地址空间，仅按需将页面从磁盘调入内存，淘汰了 32V 的整体换页机制；3BSD 内核镜像命名为 `/vmunix`（virtual memory UNIX），此命名延续至 4.4BSD；3BSD 虚拟内存机制是 BSD 在 VAX 上的核心创新，为后续 4BSD（1980.10）、4.1BSD（1981.6）、4.2BSD（1983.8）、4.3BSD（1986.6）的虚拟内存子系统奠定基础；4.4BSD（1994）采用从 CMU Mach 2.5 移植的虚拟内存系统，UVM（Universal Virtual Memory）为 NetBSD 于 1998 年左右引入的替代 VM 系统，非 4.4BSD 所有；请求调页的核心设计可追溯至 3BSD

| 维度 | UNIX/32V（1978） | 3BSD（1979.12） |
| -- | -------------- | ------------- |
| 内存机制 | 简单换页（swapping） | 请求调页（demand paging） |
| 进程地址空间 | 受物理内存限制 | 大于物理内存的虚拟空间 |
| 硬件利用 | 无虚拟内存硬件支持 | 利用 VAX 页表与 TLB |
| 上下文切换 | 整体换入换出，开销大 | 按需调页，开销小 |
| 内核镜像命名 | — | `/vmunix` |
| 核心实现者 | John Reiser、Tom London（32V 移植） | Özalp Babaoğlu（VM）、Bill Joy（集成） |

**史观**：第 7 条硬件与软件辩证——VAX 的硬件虚拟内存支持（页表、TLB）使 3BSD 的请求调页实现成为可能，硬件能力决定软件设计空间；第 17 条软件工程——请求调页是软件工程中内存管理抽象化的关键迁移，从整体换页到按需调页

**辨析**：32V 的换页机制被 “淘汰” 指 BSD 谱系中的弃用，32V 本身作为 Bell Labs 产品未被立即淘汰，须区分 BSD 内部迁移与 AT&T 32V 产品延续；3BSD 虚拟内存的核心实现者为 Özalp Babaoğlu（主导 working set paging 设计与初始实现），Bill Joy 协助内核集成、调试与用户空间工具移植；UNIX/32V 移植者为 Bell Labs 的 John Reiser 与 Tom London，David Kashtan 为 SRI 研究员（未参与 32V 或 3BSD 开发，后做 VMS vs BSD 性能基准测试）；3BSD 虚拟内存是否受 TENEX/TOPS-20 设计影响存在争议，需核对设计文档；`/vmunix` 命名在 CSRG 4.xBSD 系列中一直沿用，4.4BSD-Lite（1995）仍为 `/vmunix`；FreeBSD 2.x/3.x 时代仍使用 `/vmunix`，后改为 `/kernel`，现代 FreeBSD 使用 `/boot/kernel/kernel`，须区分各 BSD 版本与分支的内核镜像命名演变；[2026-08-14 两库核查：32V（John Reiser、Tom London 1978）与 3BSD（1979.12）请求调页迁移早于邮件库覆盖范围，参考文献库无 32V/3BSD 条目，两库无法验证]
