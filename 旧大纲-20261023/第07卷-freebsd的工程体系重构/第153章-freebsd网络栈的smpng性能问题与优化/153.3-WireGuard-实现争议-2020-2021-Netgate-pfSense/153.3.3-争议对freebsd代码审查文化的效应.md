# 153.3.3 争议对 FreeBSD 代码审查文化的效应

**要点**：WireGuard 事件对 FreeBSD 项目产生了多方面的持久影响：① 代码审查流程改进——安全敏感代码（加密、认证、网络协议）现在需要更严格的审查，且鼓励邀请相关领域专家（包括上游项目作者）参与；② 实验性代码的标记——新的安全相关功能会更明确地标记为实验性，提醒用户注意；③ 与上游项目的沟通——FreeBSD 开发者在移植其他项目代码时更重视与上游的沟通和协作；④ 商业赞助与社区治理的平衡——事件后社区更公开地讨论商业实体在 FreeBSD 开发中的角色和边界；⑤ 新 WireGuard 实现的质量更高——经过重写的 **wg(4)** 获得了 Donenfeld 的认可，代码质量和安全性显著提升；需要指出的是，这一事件没有出现 “核心开发者出走” 或 “社区分裂”，社区通过公开讨论和技术修复解决了问题

**史观**：总纲第 23 条——社区治理：开源项目的治理能力不体现在 “永不犯错”，而体现在 “犯错后能否公开承认、快速修复、流程改进”；FreeBSD 在 WireGuard 事件后的反应体现了成熟开源项目的自我纠错能力——虽然初始合并有问题，但社区通过公开透明的讨论和技术重构解决了问题

**辨析**：事件是否 “严重损害了 FreeBSD 声誉”——短期内在黑客新闻等技术社区引发了讨论，但长期影响有限；FreeBSD 在 Netflix、Juniper、NetApp 等企业用户中的使用未受影响；pfSense/Netgate 的声誉是否受损——部分用户对 Netgate 的做法有批评，但 pfSense 作为产品仍在持续发展；是否有 committer 因事件被撤销权限——经公开记录核查，没有 committer 因 WireGuard 事件被撤销权限
