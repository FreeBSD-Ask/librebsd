# 164.2.4 MTA 更替史料辨析

**要点**：**dma(8)** 导入 FreeBSD base 的工程过程可追溯至：2022 年 Baptiste Daroussin 开始在 freebsd-current 测试 dma，2023 年初正式导入 ports（mail/dma）作为测试，2023 年中在 14.0-CURRENT 中导入 base 并设置为默认，经过 BETA/RC 阶段的测试与 bug 修复后于 2023.11 随 14.0-RELEASE 正式发布；导入 base 的 commit 由 Baptiste Daroussin 提交，Simon J. Gerraty（sjg@）、Ed Maste（埃德·马斯特）（emaste@）等参与代码评审；DragonFly BSD 的 **dma(8)** 最初由 Matthias Schmidt（<matthias@dragonflybsd.org>）于 2010 年前后开发，作为 DragonFly 替换 sendmail 计划的一部分，至 2023 年已有十余年稳定运行历史；**dma(8)** 在 FreeBSD 中的版本持续跟进 DragonFly 上游，但也有 FreeBSD 特定的修改（如 mailer.conf 集成、与 FreeBSD sendmail 路径兼容等）

**史料**：cgit.freebsd.org/src/ dma import commit（2023 年）；DragonFly BSD Git 仓库 dma 目录历史；Baptiste Daroussin 邮件列表 dma 状态更新 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：dma 采用 BSD 3-Clause 许可证，与 FreeBSD 完全兼容；这是 dma 能够被直接导入 base 而无许可证障碍的关键——如果 dma 是 GPL 许可，即使技术上更优也无法进入 FreeBSD base；许可证兼容性是 BSD base system 组件选择的硬性约束——许可证选择本质是法律框架下的利益分配结构，base 准入规则即该结构的直接体现

**辨析**：**dma(8)** 在 FreeBSD 14.0 中的具体版本号对应 DragonFly BSD 哪个版本未在 Release Notes 中明确记载，需通过源码树 vcs 历史追溯；邮件列表讨论中有用户提出 “dma 是否会与 port 版本冲突”——答案是 base_dma 与 mail/dma 设计为不冲突，base 版本安装在 /usr/libexec/dma 与 /usr/sbin/dma，port 版本通常安装在 /usr/local，通过 mailer.conf 切换

**文献**：FreeBSD Project. dma(8) Manual Page [EB/OL]. [2026-07-19]. <https://man.freebsd.org/dma/8>; Schmidt M. DragonFly Mail Agent (dma) — Design and Implementation [EB/OL]. (2010)[2026-07-19]. DragonFly BSD documentation.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
