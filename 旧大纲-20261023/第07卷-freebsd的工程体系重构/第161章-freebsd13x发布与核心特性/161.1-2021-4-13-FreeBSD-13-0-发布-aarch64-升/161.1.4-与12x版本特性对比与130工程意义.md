# 161.1.4 与 12.x 版本特性对比与 13.0 工程意义

**要点**：13.0 相比 12.x 的核心特性跨越包括：(1) 工具链全架构 LLVM 化；(2) aarch64 升 Tier-1；(3) KTLS（内核 TLS 卸载）支持 TLS 1.0-1.3（详见 84.2）；(4) OpenZFS 取代原 FreeBSD ZFS 分支（详见 84.3 相关，ch72 详述）；(5) 64 位 inode 支持（UFS/UFS2），突破 2^32 inode 限制，支持超过 80 亿文件；(6) bsdgrep 成为默认 grep，移除 GNU grep；(7) iflib 网络驱动框架成为默认；(8) bhyve 虚拟化改进（AMD-V/VT-d 优化、更多 vCPU 支持，13.2 起支持 > 16 vCPU）；(9) Linux ABI 兼容层改进，引入基于 Debian/Ubuntu 的 Linux 用户态支持（不只是 CentOS）；(10) **fusefs(4)** 文件系统完善；(11) VMDk/VHD/VHDX 虚拟机镜像格式官方支持；(12) **makefs(8)** 支持 ZFS；(13) ASLR 在 13.2 起对 64 位可执行文件默认启用；(14) Capsicum/Casper 能力系统持续完善；(15) 移除 Beastie ASCII 启动菜单（新启动菜单不再包含 Beastie ASCII art）；(16) **syscons(4)** 从 GENERIC 内核移除，**vt(4)** 成为默认控制台

**史料**：FreeBSD 13.0-RELEASE Release Notes 完整“New Features”章节；FreeBSD 12.4-RELEASE Release Notes 对比；src/UPDATING 13.0 相关条目［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L1 代码；L3 官方文档〕

**史观**：总纲第 25 条——终结与延续：13.0 是 FreeBSD“去 GNU 化”第一阶段的终结（GCC 移除完成），同时也是“ARM64 原生支持”时代的开端；Beastie ASCII 启动菜单的移除引发部分老用户怀旧情绪，但这是启动加载器现代化的必然——新启动菜单支持 UEFI、多架构、高分辨率等特性

**辨析**：“64-bit inode”并非指文件指针变为 64 位（那早已实现），而是指 UFS/UFS2 的 inode 编号从 32 位扩展到 64 位，解决了大容量存储上 inode 编号溢出问题；Beastie 吉祥物本身并未被“取消”，只是启动菜单的 ASCII art 版本不再默认显示，Beastie 标识仍用于宣传材料和启动图标；**dma(8)** DragonFly Mail Agent 在 13.x 中并未成为默认 MTA，仍为可选，默认 MTA 是 sendmail，dma 默认化发生在 FreeBSD 14.0
