# 161.1.3 aarch64（arm64）升 Tier-1 架构的战略意义

**要点**：FreeBSD 13.0 将 64 位 ARM 架构（称为 arm64 或 AArch64）正式提升为 **Tier-1** 架构，与 amd64 并列成为 FreeBSD 最高支持级别的架构；Tier-1 地位意味着：发布工程团队为 aarch64 构建 RELEASE 镜像、提供安全更新和 errata、提供官方二进制软件包集、RELEASE 构建阻塞级别为 blocking（即 aarch64 构建失败会阻塞整个发布）；aarch64 支持最初由 Andrew Turner 等开发者于 FreeBSD 11.0（2016）引入，12.x 期间为 Tier-2，13.0 升 Tier-1 标志着 ARM 服务器市场（如 AWS Graviton、Ampere Altra、Apple M 系列芯片）成熟，FreeBSD 成为少数将 ARM64 列为一等公民的通用操作系统；13.0 同时为 aarch64 提供 AWS EC2 AMI、Google Compute Engine 镜像等云平台支持

**史料**：FreeBSD 13.0 Release Notes“Architectures”章节；FreeBSD 架构支持页面（freebsd.org/platforms/）；Andrew Turner 关于 arm64 移植的邮件列表帖子；AWS Graviton 2 发布时间（2020 年）与 FreeBSD aarch64 云镜像记录 ［A］

**史观**：技术路线分化：aarch64 升 Tier-1 是 FreeBSD 应对计算架构从 x86 独大向 x86/ARM 双极转变的战略决策；Linux 在 ARM 服务器市场先行一步，但 FreeBSD 在云厂商原生 ARM 支持上跟进迅速，这与 Netflix、AWS 等商业用户的需求直接相关

**辨析**：Tier-1 升的是 **aarch64（arm64）**，而非 32 位 armv6/armv7——32 位 ARM 在 13.0 中仍为 Tier-2，且后续版本持续降级；riscv64 在 13.0 中为 Tier-2，并未如部分传闻所述升 Tier-1；MIPS 架构在 13.0 中从 Tier-2 降级（详见 84.11.1）
