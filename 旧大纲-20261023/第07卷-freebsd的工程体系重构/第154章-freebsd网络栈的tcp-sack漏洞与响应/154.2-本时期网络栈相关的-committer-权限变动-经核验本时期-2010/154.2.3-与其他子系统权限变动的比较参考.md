# 154.2.3 与其他子系统权限变动的比较参考

**要点**：对比 FreeBSD 其他子系统，网络栈的 committer 团队相对稳定；安全子系统和 Ports 子系统历史上有过一些公开的权限变动和社区争议，但网络栈（除了 WireGuard 事件的流程争议外）没有发生重大治理危机；这可能因为：① 网络栈代码成熟，架构稳定，不需要大规模重写；② 维护团队有长期服务的核心成员；③ 网络栈的技术决策更多基于工程标准而非意识形态争议；需要注意，committer 权限变动记录只反映公开的正式治理动作，私人协商的开发者退出或退休不会出现在公开记录中

**史料**：FreeBSD Core Team 所有公开公告；其他 BSD 社区类似事件的对比分析（仅作背景参考） ［A］

**史观**：社区治理：网络栈维护团队的稳定性是 FreeBSD 网络栈质量的重要保障——长期维护者带来代码的深度理解和架构一致性；相比之下，某些快速迭代的子系统可能因为核心维护者变更导致架构不稳定

**辨析**：本节不应对其他子系统的权限事件做未经核实的断言，只陈述网络栈本身的情况；“没有公开权限撤销” 不等于 “没有任何争议”——WireGuard 事件虽然没有导致权限撤销，但确实是重大争议事件；核心维护者平稳传承是 FreeBSD 网络栈的优势，但也可能被批评为 “维护者圈子封闭”
