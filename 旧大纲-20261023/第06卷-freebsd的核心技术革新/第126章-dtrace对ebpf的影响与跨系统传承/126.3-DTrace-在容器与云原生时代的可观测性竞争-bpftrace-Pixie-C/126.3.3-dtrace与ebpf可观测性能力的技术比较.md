# 126.3.3 DTrace 与 eBPF 可观测性能力的技术比较

**要点**：从可观测性技术能力角度比较 DTrace 和 eBPF：(1) 探针覆盖——DTrace 的 fbt provider 可动态追踪内核中几乎所有函数，Linux eBPF 通过 kprobes 实现类似能力；(2) 聚合模型——DTrace 的 aggregations（`count()`, `sum()`, `quantize()` 等）是高级原语，使用简洁；eBPF 需要通过 maps 手动实现类似功能，bpftrace 提供了类似 D 的高层抽象；(3) 安全性——二者均通过验证器保证安全执行，但 eBPF 验证器更复杂（支持有界循环等）；(4) 用户态追踪——DTrace 通过 pid/fasttrap provider 实现，eBPF 通过 uprobes 实现；(5) 生产环境可用性——DTrace 自 2005 年起在 Solaris/FreeBSD 生产环境经过大规模验证，eBPF 自 2014 年起在 Linux 生产环境快速成熟；(6) 生态——eBPF 在工具数量、云原生集成、社区活跃度上远超 DTrace

**史料**：Gregg《BPF Performance Tools》中的 DTrace vs eBPF 对比章节；Gregg 博客中的性能对比测试；YouTube 上“Performance Analysis of DTrace on FreeBSD and eBPF on Linux”等对比视频 ［C］

**史观**：技术路线分化：DTrace 和 eBPF 代表了可观测性技术的两种范式——DTrace 是专门为可观测性设计的一体化框架，D 语言和聚合模型高度优化；eBPF 是通用内核可编程平台，通过组合不同组件实现可观测性，灵活性更高但使用门槛也更高

**辨析**：Brendan Gregg 对二者的评价较为平衡——他多次指出 DTrace 在“任意内核函数动态追踪”的便利性上仍有优势（一行命令即可启用 fbt 探针），而 eBPF 在网络和安全场景的能力远超 DTrace；性能对比因工作负载和平台差异较大，不能简单说某一方更快
