# 134.1.1 从 8.x 到 9.x 的开发周期与版本规划

**要点**：FreeBSD 9.0 开发始于 stable/8 分支冻结后，历时近两年（2010 年中至 2012.1.12 正式发布），是 FreeBSD 历史上开发周期最长的大版本之一；9.x 系列包含四个 RELEASE：9.0（2012.1.12）、9.1（2012.12.30）、9.2（2013.9.30）、9.3（2014.7.16），无 9.4-RELEASE；9.3 作为 9.x 系列终章获得超长支持周期至 2017.1.1，是生产环境长期部署的 “企业级稳定版”

**史观**：总纲第 25 条——终结与延续：9.x 是 8.x 时代的 “终结” 与 10.x 时代的 “延续” 之间的过渡——它既完成了 bsdinstall、SUJ、ZFS v28、Capsicum 等 10.x 时代核心特性的落地与验证，又保持了 GCC 4.2.1、pkg_install 等旧栈作为默认，为许可证纯洁化大迁移（GCC→Clang、pkg_install→pkg、BIND→Unbound）铺垫了两年缓冲期

**辨析**：9.x 常被叙事为 “新一代”（标题中 “新一代” 标签），但技术上多数核心特性在 8-CURRENT 已开始开发（如 USB 栈重写始于 8.0），9.0 是集成与稳定化而非全新革命；9.3 的超长支持周期（至 2017）与 10.x 系列较短的支持周期（10.0 至 2015.1.31）形成对比，表明生产用户对 9.x 稳定性的认可；**数据库验证结论**：9.x 四个 RELEASE 的 tagger_date 均早于公开声明日期 4-27 日，符合 “tag 创建后等待公告” 的 FreeBSD 发布流程；9.1 的 27 日偏差最大，反映 9.1 公告多次推迟的历史；9.0 的 10 日偏差在 SVN 时代 release 中较大，可能与 FreeBSD 9.0 公告准备时间较长有关；**重要修正项**：本次数据库验证修正了原大纲 79.1.1 中 4 项事实错误——9.0.0 tagger_name 应为 Ken Smith 而非 cvs2svn（cvs2svn 是 2008 年 CVS-to-SVN 迁移工具，9.x 时代已不在使用，原大纲混淆了 SVN 时代 release tag 与迁移脚本生成的 tag）；9.0.0 target_commit_hash 应为 `4e26149e5c0c0cd171a9ea428eafec0c80946c30` 而非 `9b5e2a67d39a...`；9.1.0/9.2.0/9.3.0 三个 tagger_date 时间戳的小时分钟秒部分原大纲均误作较晚时间，已据数据库 tags 表精确值修正；0 信任原则提示：9.x 全系列在 SVN 时代发布，commit hash 经 2020 年 SVN-to-Git 迁移重算，tagger_date 由迁移脚本回填，须以 FreeBSD 官方发布公告为权威；但 tagger_name = Ken Smith/Glen Barber 与 FreeBSD 各版本 Release Announcement Acknowledgments 章节所列 release engineer 名单一致，可信度较高；[考据完成：2026-08-15 复核查] 邮件列表库验证通过：freebsd-announce“FreeBSD 9.0-RELEASE Available”（Ken Smith，2012-01-12，Message-ID: <20120112214237.GA75114@myers.cse.buffalo.edu>）、“FreeBSD 9.1-RELEASE Available”（Ken Smith，2012-12-30，Message-ID: <20121230173811.GA93592@myers.cse.buffalo.edu>，公告载“New Intel GPU driver with GEM/KMS”），与 9.0/9.1 发布日一致
