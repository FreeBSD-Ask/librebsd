# 138.3.2 DRM 与图形栈更新

**要点**：10.2 中 Direct Rendering Manager（DRM）代码更新至匹配 Linux 3.8.13 版本，主要改进：**radeonkms(4)** 驱动稳定性提升，支持同时运行多个 X 服务器；Intel drm/i915 驱动持续改进但版本仍落后于 Radeon。Jean-Sébastien Pédron（dumbbell@）是 10.x 时期 FreeBSD DRM/KMS 驱动移植的核心维护者，持续将 Linux 内核 DRM 代码移植到 FreeBSD。10.2 中 GNOME 更新至 3.14.2，KDE 更新至 4.14.3，但这些桌面环境通过 ports 提供而非 base 系统组件。

**史料**：FreeBSD 10.2-RELEASE Announcement（"The drm code has been updated to match Linux version 3.8.13, allowing running multiple X servers simultaneously"）、Jean-Sébastien Pédron 在 freebsd-x11 邮件列表的 DRM 移植状态报告、FreeBSD Quarterly Status Reports X11/DRM 章节。 ［A］

**史观**：总纲第 22 条——知识注定过时：FreeBSD 的图形驱动始终落后于 Linux 内核 2-5 年，这是因为 DRM/KMS 驱动与 Linux 内核内部 API 深度耦合，移植工作量巨大且持续。Pédron 等人的工作是在 “追着 Linux 跑”，这种模式注定难以在桌面市场与 Linux 竞争。

**辨析**：10.2 中不存在 “feature flags 形式的 ZFS 版本切换”——ZFS feature flags 实际在 FreeBSD 9.x 与 10.0 时期已引入；10.2 中 bhyve 的 Windows 客户机支持仍处于实验阶段，无官方 UEFI 固件，需通过 ports 中的 uefi-edk2-bhyve 自行构建。

**文献**：FreeBSD 10.2-RELEASE Announcement/Release Notes [Z]. 2015；Pédron J-S. FreeBSD Graphics Status Report [EB/OL]. freebsd-x11 mailing list, 2015. ［A］
