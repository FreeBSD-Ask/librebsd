# 127.1.3 与 POSIX 能力模型的范式比较

**要点**：Capsicum 与 POSIX capabilities（Linux capabilities）属于完全不同的能力范式：POSIX capabilities 是对 UNIX root 权限的分割——将 root 的全能特权拆分为 CAP_NET_ADMIN、CAP_SYS_ADMIN 等约 40 个细粒度特权位，仍以“进程持有哪些特权”为中心，保留全局命名空间访问能力；Capsicum 是对象能力模型（object-capability model）——以文件描述符为唯一能力载体，进程进入能力模式后完全丧失全局命名空间访问权（无法以路径名 open 文件、无法访问 PID 命名空间的任意进程、无法动态加载内核模块），仅能通过启动时传入或通过 Unix domain socket 接收的能力文件描述符执行操作；POSIX capabilities 解决的是“root 权限过大”问题（root 被攻破则系统全部沦陷），Capsicum 解决的是“任何进程被攻破都可能造成大规模损害”问题（沙箱内进程被攻破只能损害该沙箱持有的能力范围内的资源）

**史观**：技术路线分化〔订正注：原“总纲第 6 条”伪标签去条号，权威总纲 6 为“和解优于斗争”〕：Capsicum vs POSIX capabilities 的范式分化是安全架构设计中“身份中心 vs 对象中心”这一根本哲学分歧的体现——POSIX/Linux capabilities 仍以“进程身份（UID/特权位）”为授权基础，Capsicum 则以“对象引用（文件描述符/能力）”为授权基础；这一分化可追溯至 1970 年代 PSOS、Hydra 等系统的能力研究，但在 UNIX 世界中长期处于边缘位置，Capsicum 是首个在主流 BSD 系统中产品化的对象能力实现

**辨析**：LWN Jake Edge 在 2012 年文章开篇说 Capsicum 采取“very different approach”并定性为非主流异类，但通读全文可知 Edge 并非批评 Capsicum——LWN 的标题“Capsicum: practical capabilities for UNIX”是正面的技术介绍，评论区也主要是 Linux 用户询问移植可能性；将该句解读为“将 Capsicum 与 Linux 既有能力体系对立”属于过度诠释，Edge 的对比性描述是技术新闻写作中常用的定位手法；真正的范式差异在于：POSIX capabilities 是对 setuid-root 模型的修补，Capsicum 是对 ambient authority 模型的替换
