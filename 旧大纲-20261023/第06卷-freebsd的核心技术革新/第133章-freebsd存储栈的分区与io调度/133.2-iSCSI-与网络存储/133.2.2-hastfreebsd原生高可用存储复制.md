# 133.2.2 HAST：FreeBSD 原生高可用存储复制

**要点**：HAST（Highly Available Storage）由 Paweł Jakub Dawidek（GELI 作者）设计，2010-02-18 提交、随 FreeBSD 8.1（2010 年 7 月）正式引入基本系统；HAST 通过 GEOM 类 **hast(4)** 实现块级同步复制，在两个 FreeBSD 节点之间同步存储数据，类似于 DRBD（Linux Distributed Replicated Block Device）；HAST 工作在主-从模式下，主节点接受读写并同步到从节点，主节点故障时从节点可提升为主；HAST 使用 **hastd(8)** 守护进程处理网络通信和数据同步，支持同步复制（数据写入两个节点后返回成功）和异步复制模式；HAST 与 CARP（Common Address Redundancy Protocol）、ucarp 等配合可构建完整的高可用存储集群

**史料**：**hast(4)**, **hastd(8)**, **hastctl(8)** 手册页；Dawidek 2009-2010 年 HAST 设计文档与提交记录；FreeBSD 8.1 Release Notes HAST 章节；FreeBSD Handbook “High Availability Storage” 章节 ［A］

**史观**：总纲第 9 条——经验优先：HAST 是 FreeBSD 生态中 “原生解决高可用存储” 需求的实践——在 HAST 之前，FreeBSD 用户要么依赖商业 NAS/SAN，要么使用复杂的 ggate+ 自定义脚本，Dawidek 作为 GELI 作者将 GEOM 框架的设计哲学延伸到网络复制领域，用一个 GEOM class 解决了问题

**辨析**：HAST 与 DRBD 的定位类似但技术路线不同：DRBD 长期在 Linux 内核主线外，后并入主线，支持更多复制模式和四节点以上集群；HAST 自 FreeBSD 8.1 起内置于基本系统，但仅支持双节点复制，没有发展出多节点集群功能；HAST 在 FreeBSD 生产环境中使用度远低于 ZFS 复制（zfs send/receive）和外部存储阵列，部分原因是 ZFS 内置复制功能更灵活且与文件系统深度集成；截至 2025 年，HAST 仍随 FreeBSD 发布但新功能开发较少
