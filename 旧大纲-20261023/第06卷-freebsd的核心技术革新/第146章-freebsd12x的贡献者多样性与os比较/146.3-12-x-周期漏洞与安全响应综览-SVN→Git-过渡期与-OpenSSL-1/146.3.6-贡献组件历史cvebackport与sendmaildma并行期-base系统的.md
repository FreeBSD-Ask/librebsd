# 146.3.6 贡献组件历史 CVE backport 与 sendmail/dma 并行期——base 系统的“维护债”

**要点**：12.x 周期 FreeBSD base 中“贡献组件维护滞后”现象集中爆发——Cy Schubert 在 2019-2020 年间批量处理多个积压 CVE：① **wpa_supplicant/hostapd**——Cy Schubert 于 2019-04-23 与 2019-05-01 将 wpa_supplicant 从 2.6 升级至 2.8，一次性修复 CVE-2019-9494/9495/9496/9497/9498/9499 六个 CVE（commit `4bc523382c7e`、`5f5f5d2ca9a8`），对应 SA-19:03.wpa；② **SQLite**——Cy Schubert 于 2019-05-05 将 SQLite 升级至 3.28.0，修复 CVE-2019-9936/9937（commit `32335203e048`），Gordon Tetlow 于 2020-08-05 再次升级修复 CVE-2020-11655/11656/13434/13435/13630/13631/13632 七个 CVE（commit `1b1e7cabc366`），对应 SA-20:22.sqlite；③ **bzip2**——Gordon Tetlow 于 2019-08-06 修复 CVE-2016-3189（bzip2recover use-after-free，2016 年披露但积压 3 年）与 CVE-2019-12900（commit `a870b2fd1675`），对应 SA-19:18.bzip2；④ **libarchive**——Martin Matuska 于 2019-02-12 同步 libarchive 至上游，修复 CVE-2019-1000019/1000020（commit `fbb1b16ad8bc`）；⑤ **Unbound**——Cy Schubert 于 2020-05-21 升级 Unbound 至 1.10.1，修复 CVE-2020-12662/12663（commit `6a53c00e64c4`），Gordon Tetlow 于 2020-07-08 修复对应漏洞（commit `4c9ce523b4c7`），对应 SA-20:19.unbound；⑥ **ntpd**——Gordon Tetlow 于 2019-05-14 升级 ntpd 至 4.2.8p13，修复 CVE-2019-8936（commit `d7a48680970e`），对应 SA-19:04.ntp；**sendmail 仍是默认 MTA**——12.x 全周期 sendmail 仍是 FreeBSD base 默认邮件传输代理，尽管 **dma(8)** DragonFly Mail Agent 在 12.4 更新但仅作为可选替代；sendmail 在 12.x 周期虽无重大 CVE，但其历史 CVE 库庞大（数十个），是 base 系统最大的“潜在安全债务”之一

**史料**：**freebsd.duckdb** `commits` 表 `freebsd-src` 仓库贡献组件 CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2018-12-01' AND author_date<'2021-04-01' AND (message_subject LIKE '%wpa%' OR message_subject LIKE '%sqlite%' OR message_subject LIKE '%bzip2%' OR message_subject LIKE '%libarchive%' OR message_subject LIKE '%unbound%' OR message_subject LIKE '%ntpd%' OR message_subject LIKE '%sendmail%' OR message_subject LIKE '%dma%') AND message_body LIKE '%CVE-%' ORDER BY author_date ASC`；FreeBSD-SA-19:03.wpa、SA-19:04.ntp、SA-19:18.bzip2、SA-20:19.unbound、SA-20:22.sqlite PGP 签名公告；Cy Schubert、Martin Matuska、Gordon Tetlow 的贡献组件 CVE 修复 commit 序列；FreeBSD 12.x Release Notes（dma 在 12.4 更新但 sendmail 仍为默认 MTA） ［A］

**史观**：总纲第 5 条——没有必然性，只有偶然性：12.x 周期贡献组件 CVE 集中清理事件反映“vendor import 周期与 CVE 修复周期脱节”的开源治理通病——FreeBSD base 中包含的贡献组件（OpenSSL、wpa_supplicant、SQLite、bzip2、libarchive、Unbound、ntpd 等）是数年前 vendor import 的版本，上游 CVE 修复未及时回溯至 FreeBSD stable 分支；这种现象在 12.x 周期被 Cy Schubert、Martin Matuska 等维护者通过“批量 vendor import + MFC 同步”模式集中清理；**与 14.x 周期 Heimdal 清理对比**：14.x 周期 Heimdal 集中清理（2024-02-14/15 两天处理 6 个积压 CVE）与 12.x 周期 wpa_supplicant/SQLite 批量升级是同一种工作模式——周期性审计贡献组件 CVE 积压，集中批量修复；**sendmail 作为“潜在债务”的辨析**：sendmail 在 12.x 周期虽无 CVE，但其代码量大（约 8 万行）、历史 CVE 库庞大（CVE-2003-0694 至 CVE-2020-7549 等数十个）、配置复杂，是 base 系统中“潜在但未爆发的债务”——14.x 周期 14.2（2024.12）将 dma(8) 设为默认 MTA、sendmail 移至 ports，是对这一债务的最终清算

**辨析**：**需精确说明贡献组件与 FreeBSD base 的关系**：贡献组件（contributed software）是 FreeBSD base 中包含但源自第三方项目的软件——FreeBSD 通过 vendor import 机制定期同步上游版本；贡献组件的 CVE 修复通常通过两种路径：① 完整 vendor import 升级（如 SQLite 3.27.2→3.28.0）；②MFC（Merge From Current）选择性回溯补丁（如 OpenSSL 1.1.1a→1.1.1d 的小版本升级）；**Cy Schubert 的角色辨析**：Cy Schubert（cy@）是 12.x 周期贡献组件维护的核心人物——他同时维护 wpa_supplicant、Unbound、SQLite、Heimdal 等多个贡献组件，是 FreeBSD Security Team 在贡献组件治理上的关键执行者；**SQLite 在 base 中的用途辨析**：FreeBSD base 中的 SQLite 主要用于 **pkg(8)** 软件包数据库（pkg 在 12.x 仍依赖 SQLite）与部分系统工具，并非用户直接交互的组件；**bzip2 CVE-2016-3189 的积压时间**：此 CVE 在 2016 年披露但 2019 年才在 FreeBSD base 中修复，积压 3 年——这反映 FreeBSD base 中 bzip2 升级滞后于上游；**sendmail vs dma 的工程哲学辨析**：sendmail 是 1980 年代 BSD 时代的遗产，配置复杂（m4 宏）、代码量大、维护者稀少；**dma(8)** 是 DragonFly BSD 项目开发的轻量级 MTA，BSD 许可、配置简单；FreeBSD 在 12.x 周期保留 sendmail 作为默认 MTA 是出于兼容性考虑（许多既有配置依赖 sendmail），14.2 切换至 dma 是工程债务清算
