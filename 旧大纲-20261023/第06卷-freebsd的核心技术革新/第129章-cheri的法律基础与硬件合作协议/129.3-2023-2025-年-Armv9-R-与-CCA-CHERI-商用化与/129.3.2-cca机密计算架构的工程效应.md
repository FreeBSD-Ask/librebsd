# 129.3.2 CCA 机密计算架构的工程效应

**要点**：ARM CCA（Confidential Compute Architecture）是 Armv9-A 引入的机密计算框架，基于 RME（Realm Management Extension）扩展，允许在硬件隔离的“Realm”中运行受保护虚拟机/工作负载，即使 hypervisor 或主机 OS 被攻破也无法访问 Realm 内存；CCA 与 CHERI 解决不同层面的安全问题：CHERI 解决进程内内存安全漏洞（C/C++ 指针错误），CCA 解决虚拟机/工作负载间的隔离问题（云环境中租户间隔离、机密计算）；二者可在未来结合——CHERI 保护进程内安全，CCA 保护 VM 间隔离；但 CCA 与 CHERI 是独立扩展，Morello 板不实现 CCA（CCA 需要 Armv9-A + RME，Morello 基于 Armv8-A 派生架构）

**史料**：Arm CCA 架构文档 developer.arm.com/architecture/security-features/arm-confidential-compute-architecture；Arm RME 介绍 ［D］ 〔L3 官方文档〕

**史观**：总纲第 4 条——分离聚合是永恒规律：ARM 同时推进 CCA（机密计算，面向云/服务器市场）和 CHERI/Morello（内存安全，面向未来长期架构演进）反映了安全需求的多层性——机密计算和内存安全是两个独立但互补的安全市场；Intel 对应推出了 TDX（Trust Domain Extensions）与 ARM CCA 竞争，AMD 推出 SEV-SNP；但在细粒度内存安全层面，Intel/AMD 目前仅提供粗粒度的内存标签扩展（如 Intel MKTME、AMD SME/SEV）而非 CHERI 级别的能力指针保护

**辨析**：原大纲本节内容在 “Intel 对应推出” 处截断，已补全；CCA 与 CHERI 并非竞争关系而是互补关系——未来 ARM 处理器可能同时支持 CCA（虚拟机级隔离）和 CHERI（进程内内存安全），提供多层防御；Morello 板基于 Armv8-A 派生架构，不支持 Armv9-A 的 CCA/RME，这是研究原型与产品级架构的差异
