# 137.1.5 总纲3不存在进步只有权力再分配嘉宾口述的最佳保密秘密现象揭示了BSD企业采用史的

- 总纲3 不存在进步，只有权力再分配：嘉宾口述的最佳保密秘密现象揭示了 BSD 企业采用史的深层结构：大量公司以 FreeBSD 做 ZFS 存储、以 OpenBSD 做防火墙与路由却从不宣传，如同不宣传所用 Brocade 交换机一般；其决定机制并非技术优劣，而是责任规避的劳动政治——出问题的若是人人皆用的主流方案则无人担责，引入非主流系统者则独揽故障罪名，故 BSD 进入企业依赖懂行者的个人决断，与十年前 Linux 的处境同构。技术采纳史因此不能写成进步叙事，而是支持生态与责任分配的权力再分配史。“倘若你带来一台 OpenBSD 机器，随后整个防火墙基础设施因故崩溃，那就要算在你头上”（1926.14-1942.32）。（BSD Now EP86，[1899.18-1952.26]，L2）
- 总纲8 本体论上各方平等：四大分支并存的发布工程学——FreeBSD 的版本矩阵与 ABI 冻结、OpenBSD 的节律与冻结、NetBSD 的大版本、小版本与安全版本三类划分及新装机可直接安装已打补丁镜像、DragonFly 依赖开发者私有 Git 侧分支使发版不扰动主线——没有一种可被追认为主流进化方向，各自是不同社区规模、版本控制工具与用户结构下偶然成形又自我强化的形式安排；讲述者明言所有方案各有优劣、其偏好 OpenBSD 模式属个人趣味而非历史必然。“所有这些方案都有优点和缺点”（5084.72-5088.06）。历史书写应在本体论层面平等对待各分支的工程文化，而非以某一家为进步标尺。（BSD Now EP86，[4886.76-5182.96]，L2）
- 总纲10 动手者创造历史：包体系的演进由动手者驱动而非领袖钦定：Google Summer of Code 学生写出新的依赖求解器使 package set -o 大半退役，构建集群从小两台机器被不断塞机器式地扩张并由个人以自写脚本勉力管理，Port Manager lurker 计划以 IRC 频道吸纳 Matt、Steve Wills 等新血——基础设施史的正主是这些具体操持者，正合总纲之动手者创造历史。（BSD Now EP46，[2126.10-2148.62]，L2）
- 总纲9 经验优先：发行工程对稳定分支宁可关闭新特性也不愿引入回归，体现以既有用户升级经验为优先的保守取向，而非功能扩张优先的进步叙事。（BSD Now EP2，[3189.04-3237.52]，L1）
- 总纲13 法律与道德是利益分配：GCC 退出基本系统与 BIND 替换是许可证与维护成本共同驱动的工具替换，属利益与负担在工具链层面的重新分配。（BSD Now EP2，[543.86-645.78]，L2）
- 总纲4 分离聚合是永恒规律：Poudriere 以 jail 将单一构建任务分离为按版本、架构与选项隔离的并发构建，并以增量重建聚合为统一二进制仓库，是分离与聚合的工程实践。（BSD Now EP2，[865.40-1801.56]，L2）
- 总纲5 没有必然性，只有偶然性：他的 FreeBSD 之路始于纯粹偶然：十余年前为学习架设 IRC 服务器而租用 shell 账户，对方恰好运行 FreeBSD；自办 shell 托管公司时依据的不过是 IRC 上“用 Linux 会被 root”的流言，起点约为 FreeBSD 4.0/4.1；建 CDN 时其 FreeBSD 经验压过合伙人的 NetBSD 背景，遂成今日 80 台 FreeBSD 机器且从未考虑更换的格局。技术选型的延续并非必然规律，而是一连串具体处境下偶然选择的路径固化。（BSDTalk EP235，[1293.46-1431.94]，L1）

**辨析**：

- 听众质疑 pkg-ng 以二进制包取代源码编译是否为针对 Unix 传统的一次 systemd 式反叛，主持人澄清 ports 树相对于 Linux 的历史价值在于提供可定制编译的框架而非拒绝二进制（如自打补丁限定运行时长的 rsync），pkg-ng 的每周构建化解了旧时代 ports 与冻结二进制包不可混用的痛点，同规模部署的安装时间从约四十五分钟的编译压缩至三分钟装包；进一步的可复现构建愿景是自编译结果与官方包逐位一致以供安全验证。嘉宾以 OpenBSD 的 Flavor 变体包机制（如带 LDAP 支持的 Dovecot 独立包名）反衬 FreeBSD options 变更导致的重编译痛点（Bacula 默认绑定 PostgreSQL 而其自用 MySQL，每次升级被要求重装），并期待 ports 树本身可作为包安装、与官方包的构建基线保持同步。 [存疑脚注] 转写将 Dovecot 记作 Bacode，Bacula 数据库选项对话以听写近似呈现，专名以通行拼写为准。（BSD Now EP86，[4173.42-4411.42]，L2）
- 关于 Netflix 存储架构的孤证说法须存疑：主持人称 Netflix 以 discrete wire 将 SATA 磁盘一对一接 LSI HBA 而回避 SAS 扩展器，并自认“我不是百分百确定”（4922.54）；此说既非当事人自述亦无文档佐证，且转写将 HBA 误作 HPA，引用前应以 Netflix 工程实践一手材料核证。 [存疑脚注] 说话人自陈不确定且非当事人，属单一来源推断，Netflix 磁盘直连实践待核（BSD Now EP46，[4918.94-4944.68]，L4）
- PF 双雄之争在节目中仅为转述层材料：OpenBSD 邮件列表风暴中社区主张与其仅 SMP 化 PF 不如做通用 SMP 改造，DragonFly 已多线程化 PF，FreeBSD 侧则有 PF 前途之问与 IPFW 复兴的杂音；“快四倍”“随核数线性”等数字均出自主持人复述，且网卡多队列等底层论断含糊，映射入史前必须回查 2014 年邮件列表原帖。 [存疑脚注] 争论细节与性能数字仅经主持人转述，须以邮件列表一手原文复核（BSD Now EP46，[668.06-893.54]，L2）
- FreeBSD 10.0 是否彻底移除 BIND、以及 resolv.conf 与 DHCP 切换的具体方案在本期仍属进行中的计划，须以 10.0 最终发布说明为准。 [存疑脚注] BIND 移除与解析配置迁移为当时未定稿规划，播客转述不等同于正式发布决策。（BSD Now EP2，[4181.74-4227.38]，L4）
- pkgng 在 2013 年呈现两面性：对当事人而言是部署速度的数量级改善与比 portupgrade 更顺畅的大版本迁移，但同一访谈里主持人自述“一碰 pkgng 受挫就放弃”，PHP 与 Perl 的 origin 手工修补、仓库元数据的整体一致性约束也显示工具链尚未成熟；这一工程必要性与生态滞后的张力，须与此后 FreeBSD 10.0 将 pkg 设为默认的过程交叉验证，方能判断争议如何收束。（BSDTalk EP235，[1069.80-1168.04]，L1）
- 两点须存疑处理：其一，对 OpenBSD 十年前整体重写、NetBSD 增补难以为继的评述是单一当事人的单方概括，各项目包工具的实际演进须以各自仓库与邮件列表交叉验证；其二，“有问题则什么都不装”等属设计承诺而非当时已充分验证的实况，pkg 是否兑现该承诺，须以后续 FreeBSD 10.0 默认化进程与实际故障记录检验。 [存疑脚注] 对兄弟项目包工具路线的评述与对新工具可靠性的断言均为演讲者单方陈述（BSDTalk EP239，[218.92-291.66]，L4）
