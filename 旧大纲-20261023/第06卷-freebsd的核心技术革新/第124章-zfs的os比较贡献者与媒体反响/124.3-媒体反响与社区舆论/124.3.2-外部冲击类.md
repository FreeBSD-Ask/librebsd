# 124.3.2 外部冲击类

### 新闻条目 1

- **新闻标题（中英）**：Project Indiana 细节浮现（Project Indiana Details Emerge）
- **新闻来源**：Phoronix + Michael Larabel + 2007-06-09 + <https://www.phoronix.com/news/NTgyOQ> + <https://web.archive.org/web/2007*/phoronix.com/news/NTgyOQ>
- **新闻摘要**：2007 年 6 月 Sun 推进 Project Indiana（即后来的 OpenSolaris 二进制发行版），由 Ian Murdock 领导，目标是构建基于 OpenSolaris 的二进制发行版。Project Indiana 推动了 ZFS 与 DTrace 在开源社区的曝光度，间接促进 FreeBSD 社区对这些技术的移植兴趣。
- **与本章主题的关联说明**：本章记述 FreeBSD 社区对 ZFS 移植的动机背景，Project Indiana 提升了 ZFS 在开源操作系统圈的可见性，是 FreeBSD 移植决策的外部刺激因素之一。
- **与官方史料的交叉验证结论**：Project Indiana 由 Sun 官方宣布，Ian Murdock 担任领导在 Sun 官方博客与新闻稿中可验证；Phoronix 报道与 Sun 官方公告一致。

### 新闻条目 2

- **新闻标题（中英）**：OpenSolaris 不会与 Linux 合并（OpenSolaris Will Not Merge With Linux）
- **新闻来源**：Phoronix + Michael Larabel + 2007-08-09 + <https://www.phoronix.com/news/NTk2Ng> + <https://web.archive.org/web/2007*/phoronix.com/news/NTk2Ng>
- **新闻摘要**：2007 年 8 月 Sun 高层明确表示 OpenSolaris 不会与 Linux 内核合并，ZFS 与 DTrace 将保持独立 CDDL 协议组件。这一表态意味着 FreeBSD 等第三方操作系统若要使用 ZFS，必须以 CDDL 兼容方式移植，无法通过 Linux 内核模块路径间接获取。
- **与本章主题的关联说明**：本章记述 FreeBSD 直接移植 ZFS 的工程路径选择，Sun 的这一表态排除了“通过 Linux 间接获取 ZFS”的可能，强化了 FreeBSD 独立移植工程的必要性。
- **与官方史料的交叉验证结论**：Sun 高层声明在 OpenSolaris 邮件列表存档可交叉验证；Phoronix 报道与 Sun 官方表态一致。
