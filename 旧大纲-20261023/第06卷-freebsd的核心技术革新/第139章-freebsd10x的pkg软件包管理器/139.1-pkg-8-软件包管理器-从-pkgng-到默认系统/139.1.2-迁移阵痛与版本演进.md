# 139.1.2 迁移阵痛与版本演进

**要点**：从旧 pkg_*迁移到 * *pkg(8)* * 的过程在 10.x 早期（2014-2015）伴随大量兼容性问题与用户抱怨：pkg 1.10.1 等早期版本升级后出现 pkg 数据库损坏导致 “整个 pkg 环境无法使用” 的问题；从 pkg 1.x 早期版本升级到后续版本时出现大量包被意外安装的依赖解析 bug；jail 环境中 pkg 命令在特定配置下陷入无限循环；ports 中大量旧 pkg_* 相关脚本需重写；第三方 pkg 仓库（如 PC-BSD/TrueOS 仓库）格式变化导致配置不兼容。这些问题在 pkg 1.3（10.1 携带）、pkg 1.4/1.5（10.2 时期）中逐步修复，至 pkg 1.8/1.9（10.3-10.4 时期）进入稳定期。坚持使用 ports 源码编译（make install clean）而不使用二进制包的用户比例在迁移初期较高，后随 pkg 成熟而下降。

**史料**：freebsd-pkg/freebsd-ports 邮件列表 2014-2015 问题报告、pkg GitHub 仓库 Issues 与 release notes、FreeBSD Forum 迁移问题讨论帖。 ［A］

**史观**：软件工程：软件包管理器是操作系统中最脆弱的组件之一——它管理系统上所有其他软件，自身的 bug 可能导致整个软件安装环境不可用。**pkg(8)** 迁移期问题印证了 “不要在 .0 版本切换核心基础设施” 的工程 wisdom，FreeBSD 虽将 **pkg(8)** 默认设置放在 10.0，但实际上多数生产用户等到 10.1/10.2/10.3 才完成迁移。

**辨析**：原文件提到的问题版本号 “pkg 1.10.1” 与 “从 1.x 升级到 2.10”——经 pkg 项目 release history 核实，pkg 1.x 系列最高版本约为 1.1x，pkg 2.x 系列在 FreeBSD 11/12 时期才出现，因此 “2.10” 版本号可能为误记；10.x 全系列携带的 pkg 均为 1.x 系列（10.0 约 pkg 1.2、10.1 为 1.3.8、10.2-10.4 为 1.5-1.10 区间）。
