# 139.3.2 RCTL 资源控制与其他内核改进

**要点**：RCTL（Resource Limits，**rctl(8)**）框架在 FreeBSD 9.0 已初步引入但在 10.x 时期持续完善。RCTL 允许细粒度控制进程/用户/jail/登录类的资源使用（CPU、内存、磁盘 I/O、网络带宽等），是 FreeBSD jail 容器化与资源隔离的核心基础设施。10.x 时期 RCTL 改进包括更稳定的统计计数、更多资源类型支持、与 **devfs(8)**/**jail(8)** 的更好集成。10.0 其他内核基础设施改进：USB  stack（USB4BSD，Hans Petter Selasky 主导）在 10.x 已稳定（USB4BSD 项目主要工作在 FreeBSD 8/9 时期完成，10.x 为持续改进）；CAM ATA 层改进——ATA 磁盘驱动进一步移入 CAM（Common Access Method）层，实现 SCSI/ATA 统一存储栈（ate 驱动在 10.x 逐步退役，**ahci(4)** 与 **siis(4)** 等驱动直接通过 CAM 层）；Capsicum 能力模式默认启用（10.0），允许应用程序沙箱化。

**史料**：FreeBSD 10.0 Release Notes Kernel Changes、rctl(8) 手册页、Hans Petter Selasky USB4BSD 项目文档、Edward Tomasz Napierala CAM ATA 整合提交记录。 ［A］

**史观**：专题语（不设总纲条号）——长期架构整合：CAM（Common Access Method）层统一 SCSI/ATA 存储栈是 FreeBSD 存储架构持续多年的整合工程，从 FreeBSD 6/7 时期启动至 10.x 时期接近完成，最终实现所有块设备通过 CAM 层统一调度。这种底层架构整合虽不为普通用户感知，但为 ZFS、bhyve、iSCSI 等上层功能提供了统一存储基础。

**辨析**：原文件称 “USB4BSD 完成” 在 10.0——USB stack 重写的主要工作在 FreeBSD 8/9 时期已完成（Hans Petter Selasky 的 USB4BSD 项目），10.0 是进一步完善而非首次完成；**etcupdate(8)** 不是 10.0 新引入——etcupdate 作为 **mergemaster(8)** 的替代工具在 FreeBSD 9.x 已存在并可用，10.x 时期持续改进但非新特性；**mandoc(1)** 在 10.x 确实逐步引入用于部分手册页渲染但完全替换 groff 为默认手册页渲染器发生在更晚版本；RCTL 在 9.0 已初步引入，10.x 为持续完善。
