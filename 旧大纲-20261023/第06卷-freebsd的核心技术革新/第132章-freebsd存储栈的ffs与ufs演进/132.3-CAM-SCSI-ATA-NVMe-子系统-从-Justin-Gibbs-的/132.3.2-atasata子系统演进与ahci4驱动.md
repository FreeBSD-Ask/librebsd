# 132.3.2 ATA/SATA 子系统演进与 **ahci(4)** 驱动

**要点**：FreeBSD 2.x-4.x 时代的 ATA 驱动由 Søren Schmidt 编写和维护，名为 **ad(4)**——系对 386BSD 时代旧 **wd(4)**（“Winchester Disk”）驱动的重写替代而非简单改名，是一个独立于 CAM 的直接驱动；随着 SATA 和 AHCI（Advanced Host Controller Interface）标准普及，Alexander Motin 在 FreeBSD 7.x/8.x 时代重写了 ATA 子系统，最终在 FreeBSD 9.0（2012 年）前后将 ATA/SATA 设备统一接入 CAM 子系统，形成新的 **ada(4)** 驱动（ATA Direct Access）；**ahci(4)** 驱动支持 AHCI 标准 SATA 控制器，支持原生指令队列（NCQ）、热插拔、端口倍增器等高级功能；**siis(4)** 支持 Silicon Image SATA 控制器、**mvs(4)** 支持 Marvell SATA 控制器；统一接入 CAM 后，ATA 磁盘与 SCSI/SAS 磁盘使用统一的 **camcontrol(8)** 工具管理，不再需要独立的 **atacontrol(8)** 工具

**史料**：FreeBSD 9.0-RELEASE Release Notes ATA/CAM 整合章节；**ahci(4)**, **ada(4)**, **camcontrol(8)** 手册页；Alexander Motin 在 freebsd-current@ 2010-2012 年 ATA/CAM 整合讨论；FreeBSD 8.0-RELEASE Release Notes 中 AHCI 驱动状态说明 ［A］

**史观**：软件工程（专题语，不设总纲条号；原挂“总纲第 17 条”系伪标签，依核查报告订正）：ATA 子系统从独立驱动到 CAM 整合的过程是 FreeBSD 现代化进程中 “架构统一” 的典型——旧的 **ad(4)** 驱动维护了十几年，但 ATA 功能越来越复杂（SATA、NCQ、AHCI、ATA PASS-THROUGH），独立维护成本越来越高；将 ATA 纳入 CAM 框架后，所有块设备共享同一错误处理、同一设备发现、同一用户态工具，这是 “用架构统一降低长期维护成本” 的工程决策

**辨析**：一个常见时间点错误：“**ahci(4)** 在 FreeBSD 7.0 引入”——实际上 **ahci(4)** 驱动在 FreeBSD 7.0 中以实验状态引入，FreeBSD 8.0 开始稳定，到 FreeBSD 9.0 才完成 ATA 设备全面接入 CAM 并废弃旧 **ad(4)**/atacontrol；**atacontrol(8)** 工具在 FreeBSD 9.x 仍保留用于兼容，但新系统应使用 **camcontrol(8)**；USB 大容量存储设备（**umass(4)**）从一开始就通过 CAM 的 **da(4)** 驱动（直接访问）接入，因此 U 盘在 FreeBSD 中显示为 /dev/da *，这与旧的 ATA 磁盘（/dev/ad*，后改为 /dev/ada*）不同

**文献**：FreeBSD Project. *FreeBSD 9.0 Release Notes* (2012-01); FreeBSD Project. **ahci(4)**, **ada(4)**, **camcontrol(8)** Manual Pages; Motin, A. (2010-2012). *ATA/CAM Integration Commits*. svn.freebsd.org. ［A］
