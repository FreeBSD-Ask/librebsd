# 141.1.2 **vt(4)** Newcons 默认控制台替换 **syscons(4)**

**要点**：**vt(4)**（Newcons 项目）在 FreeBSD 11.0 正式成为默认控制台驱动，替换了自 BSD 时代沿用近三十年的 **syscons(4)**。**vt(4)** 主要开发者包括 Ed Schouten（ed@）、Marius Strobl（marius@）等人，FreeBSD Foundation 赞助了部分开发工作。10.x 时期 **vt(4)** 已合并但需通过 `kern.vty=vt` loader 变量手动启用，11.0 起此变量默认即为 vt，**syscons(4)** 仍保留但不再是默认。**vt(4)** 核心优势：原生支持 KMS（Kernel Mode Setting）驱动，可与 **drm2(4)** Radeon/Intel GPU 驱动配合实现高分辨率控制台；完善的 Unicode/UTF-8 终端支持；多显示器支持；与 Xorg 图形系统更平滑的切换；支持集成到 bhyve 图形 framebuffer 中。**syscons(4)** 因架构设计局限无法支持现代 GPU 的 KMS 模式切换，其退役是图形栈现代化的必然步骤。

**史料**：FreeBSD 11.0-RELEASE Release Notes（Kernel Configuration 章节关于默认控制台的说明）、vt(4) 手册页、Ed Schouten BSDCan 2013“Newcons: FreeBSD's New Console Driver”演讲、svn commit 记录中 GENERIC 内核配置文件关于 `kern.vty` 默认值变更的提交。 ［A］

**史观**：技术债务与代码考古：**syscons(4)** 代表了 1980 年代 Unix 控制台的设计范式——文本模式、VGA 兼容、单显示器假设；**vt(4)** 则面向 2010 年代的硬件现实——高分辨率显示、多显示器、GPU 加速、Unicode 全球化。这种“默认值切换”看似简单，但从 **vt(4)** 项目启动（约 2008 年）到默认启用历时近八年，体现了 BSD 项目对核心基础设施变更的极度审慎——**syscons(4)** 是用户每次登录都要交互的组件，任何回归都将影响所有用户。

**辨析**：部分资料称“**syscons(4)** 在 11.0 被移除”——经 GENERIC 内核配置与 Release Notes 核实，**syscons(4)** 仍保留在 11.x 内核源码中，用户可通过 `kern.vty=sc` 切换回旧控制台；**syscons(4)** 从 GENERIC 中移除发生在更晚版本（FreeBSD 13.0 前后）。另有说法称“**vt(4)** 在 10.3 默认启用”——经 10.3 Release Notes 与 10.x GENERIC 配置核实，10.x 全系列默认仍为 **syscons(4)**，**vt(4)** 需手动启用；默认切换至 **vt(4)** 确为 11.0。

**文献**：Schouten E. Newcons: FreeBSD's New Console Driver [C]//BSDCan 2013. Ottawa, 2013；FreeBSD vt(4)/syscons(4) Manual Pages [Z]；FreeBSD 11.0-RELEASE Release Notes [Z]. 2016.
