# 145.6.7 GPL 阵营的再回应层——Apache 2.0 双标论与架构弃用具正当化

**要点**：GPL 阵营对 FreeBSD 反批评层（61.9.6）的再回应集中于两点。其一，“Apache 2.0 双标论”回应：FreeBSD 接受 Apache 2.0（含专利报复条款 §3）的 LLD 却排斥 GPLv3（含专利报复条款 §11）的 GCC，在专利条款逻辑上不自洽——若 FreeBSD 反对的是专利报复条款本身，则应同时排斥 Apache 2.0 与 GPLv3；若 FreeBSD 接受的是专利报复条款的特定范围，则须精确说明 Apache 2.0 §3 与 GPLv3 §11 的法律差异，而非笼统以“GPLv3 专利风险”为由驱逐 GCC。这一“双标”批评与 Clang/LLVM 迁移专章合图层对 Clang/LLVM 迁移的批评同构，揭示“纯洁化”话语的利益选择性——BSD 阵营以“Apache 2.0 §3 防御性授权 vs GPLv3 §11 延伸性授权”区分二者，但 GPL 阵营指出此区分掩盖了一个事实：Apache 2.0 §3 同样在专利诉讼触发时终止专利授权，且 Apache 2.0 的“防御性”措辞在实践中与 GPLv3 §11 的法律效果差异远小于 BSD 阵营的工程化叙事所暗示，FreeBSD 的接受/驱逐边界更多反映对 copyleft 整体（非仅专利条款）的排斥，而非纯粹的法律技术评估。其二，“架构弃用具正当化”再回应：FreeBSD 反批评中“sparc64 废弃主因硬件市场萎缩”的论证，只证明架构弃用有多重原因，不证明许可证纯洁化无责任——GCC 移除是“压垮骆驼的最后一根稻草”，许可证纯洁化加速了架构弃用，即便不是根本原因也是直接诱因之一，FreeBSD 须承认这一“附带损害”而非完全归因于市场；且 mips 架构同样面临 Clang 支持不完善与硬件市场萎缩的双重困境，许可证纯洁化不是唯一变量但确是加速变量，BSD 阵营将架构弃用完全归因于市场是话语规避而非因果澄清。

**史料**：GPLv3 §6（“用户产品”定义）与 §11 官方文本（2007-06-29，一手法律文本）、Apache License 2.0 §3 专利条款（2004-01，一手法律文本）、FSF GPL FAQ 关于 §11 专利条款范围的说明（**<https://www.gnu.org/licenses/gpl-faq.html>**，#GPLv3PatentGrant 条目）、FSF 许可证评论页面关于 Apache 2.0“防止专利背叛”的官方推荐（** <https://www.gnu.org/licenses/license-list.html**>，#apache2 条目，Clang/LLVM 迁移专章已 WebFetch 一手核验）、freebsd-arch 邮件列表 GPL 阵营开发者对 FreeBSD 反批评的再回应（未取得原文，标注［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）、参见 Clang/LLVM 迁移专章 58.18.1 再回应层考据。 ［A］

**史观**：总纲第 19 条——解释学循环与权力知识共谋：GPL 阵营的再回应揭示了 FreeBSD 反批评层的话语策略——将 copyleft 的设计目的（单向兼容）重新表述为“许可证污染”，将 Apache 2.0 与 GPLv3 专利条款的法律差异工程化为“接受/驱逐”的客观边界。这一话语策略本身是前理解差异的产物：BSD 阵营的前理解是“宽容许可 = 真正的自由”，故 copyleft 的单向性被解读为“污染”；GPL 阵营的前理解是“copyleft = 用户保护”，故单向性被解读为“设计目的”。两种前理解各自内部自洽，再回应层无法消除此分歧——这正是解释学循环的不可通约性，与 Clang/LLVM 迁移专章 58.18.1 再回应层的史观映射同构。
