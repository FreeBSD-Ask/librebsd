# 352.2.3 BSD MFC/pullup/errata 回溯机制与 Linux stable/illumos 发行版特定补丁的工程差异

  **要点**：四大 BSD 各自维护独立的漏洞修复回溯机制——FreeBSD MFC（Merge From Current）将 head 分支修复回溯至 stable/ 分支，freebsd.duckdb 查询 L3.1.1 显示 freebsd-src 中含 `MFC` 关键词的 commit 持续活跃；NetBSD pullup 机制将 -current 修复回溯至 release branches；OpenBSD errata patches 机制为已发布版本提供二进制补丁；DragonFly BSD 无明确回溯机制，依赖 release branch 维护；Linux kernel stable tree 由 Greg Kroah-Hartman 维护，将主线修复回溯至 stable kernels（5.4.x、5.10.x、5.15.x、6.1.x、6.6.x 等 LTS 版本），freebsd.duckdb 查询 L7.3.1 显示 Linux kernel commit 量远超 BSD 但回溯机制透明度较低；illumos 无统一回溯机制，各发行版（OmniOS、OpenIndiana、SmartOS）各自维护发行版特定补丁
  **史料**：FreeBSD MFC 文档（freebsd.org 2026-07-22 直接访问确认 MFC 为 FreeBSD release engineering 标准流程）、NetBSD pullup 文档、OpenBSD errata 机制文档、Linux kernel stable tree 维护文档（kernel.org 2026-07-22 直接访问确认 Greg Kroah-Hartman 为 stable tree 维护者，LTS 版本清单含 5.4/5.10/5.15/6.1/6.6）、illumos 发行版各自的安全公告页面［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；illumos-gate.duckdb 查询 L3.1.1（MFC 关键词 commit 演化）、L7.3.1（Linux vs BSD commit 对比）［A］
  **史观**：总纲第 9 条——企业研究的双重性，Linux stable tree 由企业赞助维护（Google、Microsoft、Intel 等），BSD MFC/pullup/errata 由社区志愿者主导；总纲第 23 条——社区治理与经济约束共同决定回溯机制
  **辨析**：MFC 回溯的具体周期（平均修复到回溯的天数）需查 freebsd-src commit 时间序列中 `MFC` 标记 commit 与原 commit 的时间差；Linux stable tree 回溯是否覆盖所有 CVE 修复需查 stable kernel changelog；illumos 发行版特定补丁是否回馈上游 illumos-gate 需查 commit 流向；Greg Kroah-Hartman 个人 commit 占比是否构成 bus factor 风险需查 L3.4.1
