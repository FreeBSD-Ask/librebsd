# 354.2.7 securelevel 传统：BSD 内核安全级别与不可逆降级机制

  **要点**：securelevel 自 4.4BSD（1994 年）引入；BSD securelevel 是内核安全级别机制，分为多个级别——-1 永久不安全模式（permanently insecure）、0 不安全模式（insecure mode，默认启动状态）、1 安全模式（secure mode，无法清除文件 schg 标志、无法 /dev/mem、无法写已挂载文件系统的 raw 分区）、2 高度安全模式（highly secure mode，无法设置系统时间、无法写 /dev/mem 与 /dev/kmem）、3 网络安全模式（network secure mode，无法调整网络接口与 IP 防火墙规则）；FreeBSD、NetBSD、OpenBSD、DragonFly BSD 均保留 securelevel；NetBSD About 页面明确 "the traditional BSD securelevels further restrict operations that can be performed by even the superuser“；securelevel 是 BSD 安全设计的经典范例，将 ”even root cannot bypass" 制度化，与 chflags 结合实现纵深防御；高级别 securelevel 无法降级至低级别（除非重启）是 BSD 独有的不可逆安全机制
  **史料**：NetBSD About 页面（<https://www.netbsd.org/about/>，访问 2026-07-27，原文 "the traditional BSD securelevels further restrict operations that can be performed by even the superuser"）；NetBSD secmodel_securelevel man page（<https://man.netbsd.org/secmodel_securelevel>，访问 2026-07-27）；FreeBSD init(8) man page（<https://man.freebsd.org/cgi/man.cgi?query=init&sektion=8>，访问 2026-07-27，含 securelevel 描述） ［A］
  **史观**：总纲第 9 条——经验优先，securelevel 各级别（-1、0、1、2、3）是工程实践的具体沉淀，每级别的限制规则皆源于实际安全需求；总纲第 4 条——分离聚合是永恒规律，securelevel 从 4.4BSD 聚合至四大 BSD 分支，是分离聚合律的具体显现；总纲第 7 条——理论必须自反，本子节作为 securelevel 传统的考据叙事，自身亦嵌入 “不可逆即安全善” 的前理解，须自觉呈现这一前理解；总纲第 8 条——本体论上各方平等，BSD securelevel 与 Linux SELinux、AppArmor 在本体论上地位相等，差异仅是一刻状态的不同；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，“securelevel 是 BSD 安全设计的经典范例” 等文化意义叙事是史家基于当下史料的形式主义建构
  **辨析**：考据过程留痕——【查证来源】NetBSD About 页面经 netbsd.org/about/ 一手核验，确认 "the traditional BSD securelevels further restrict operations that can be performed by even the superuser" 表述；NetBSD secmodel_securelevel man page 经 man.netbsd.org/secmodel_securelevel 一手核验；FreeBSD init(8) man page 经 man.freebsd.org 一手核验，含 securelevel 描述；【交叉验证方法】securelevel 各级别限制规则须以四大 BSD init(8) 或 secmodel_securelevel man page 互证；securelevel 不可逆降级机制须以 init(8) man page 与 sysctl(8) man page 互证；【0 信任原则·“4.4BSD 1994 年引入”】“securelevel 自 4.4BSD（1994 年）引入” 的考据须以 4.4BSD 源码或 init(8) man page 核验，本考据以既有学术文献为间接依据；【0 信任原则·各 BSD securelevel 实现差异】四大 BSD 的 securelevel 实现可能存在差异（如 FreeBSD 自 FreeBSD 5.x 起引入 MAC Framework 后 securelevel 的角色变化），须以各 BSD init(8) man page 与文档核验，本考据以 NetBSD About 页面与 secmodel_securelevel man page 为主要依据；【0 信任原则·“高级别无法降级至低级别（除非重启）”】“高级别 securelevel 无法降级至低级别（除非重启）” 的不可逆性须以各 BSD init(8) man page 核验，部分 BSD 可能在 securelevel = 1 时仍允许降级至 0，本考据以 NetBSD secmodel_securelevel man page 为依据；【与同类 UNIX/BSD 习俗对比】Linux 无原生 securelevel 机制；SELinux、AppArmor、Linux capabilities 提供不同维度的安全控制；BSD securelevel 因简洁与不可逆性独树一帜；illumos 与 Solaris 有 Trusted Extensions 但实现不同；【自反性声明】本子节作为 securelevel 传统的考据叙事，自身嵌入 “不可逆即安全善” 的前理解，实际 securelevel 的工程价值（如在现代容器化与云原生环境的适用性、与 MAC Framework 的协同）须以多源交叉验证逼近史实
