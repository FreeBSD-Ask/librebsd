# 349.1.1 Linux 社区对 BSD 文化封闭性的批评

  **要点**：Linux 社区（特别是 LKML 与 Linux Foundation 关联人物）对 BSD 文化封闭性的批评包括——BSD committer 制度的排他性、BSD 邮件列表的“老男孩俱乐部”氛围、BSD 对外部贡献者的轻视、BSD 对商业化推广的抗拒；参见相关章节 Linux 治理模式对 FreeBSD 批评部分；Linux 社区批评的背景是 Linux 与 BSD 在市场份额、社区规模、商业生态上的全面竞争；Linux 社区批评须辩证看待——部分批评成立，部分批评是竞争性话语
  **史料**：LKML 邮件列表档案；Linux Foundation 关联人物公开声明；Linux 社区对 BSD 的批评档案；参见相关章节 Linux 社区对 BSD 的批评部分史料 ［A］；openbsd.duckdb 查询 L3.1.1.Linux 显示：22 仓库合计 commit message 含 ‘Linux’ 关键词占比从 1993 年 0.11%（24/21,585）增至 2000 年 0.86%（1,690/195,667）、2005 年 1.04%（2,780/267,087）、2008 年 3.96%（10,510/265,133）、2009 年达峰值 4.72%（13,442/284,708），后回落至 2018 年 2.18%（7,341/336,461），反映 BSD 仓库 commit 中对 Linux 的引用关注度在 2008-2009 年（Linux 内核 2.6.28/2.6.31 等大版本密集发布期）达到峰值，与 Linux 社区对 BSD 文化封闭性批评的话语高峰期大致重叠
  **史观**：历史解释学与权力，Linux 社区批评是话语权争夺的呈现；社区与文明历史哲学，文化封闭性批评是文明接触带的典型现象
  **辨析**：Linux 社区批评的具体来源须考据（是 Linus Torvalds 个人观点还是 Linux 社区普遍观点）；批评的成立性须逐一分析；【0 信任原则·关键词匹配局限】L3.1.1.Linux 基于 `LIKE '%Linux%'` 关键词匹配，“Linux”可能出现在非文化批评语境（如技术移植说明“port from Linux”、兼容性声明“Linux compatibility layer”、对比基准“vs Linux performance”等），关键词占比不等于文化批评强度，2008-2009 年峰值可能受 Linuxulator 兼容层技术 commit 与 Linux 内核移植讨论驱动，而非文化批评话语增加；【0 信任原则·commit message 语境缺失】L3.1.1.Linux 仅匹配 message_subject 首行，未分析 message body，无法区分批评性引用、技术性引用与中性引用
