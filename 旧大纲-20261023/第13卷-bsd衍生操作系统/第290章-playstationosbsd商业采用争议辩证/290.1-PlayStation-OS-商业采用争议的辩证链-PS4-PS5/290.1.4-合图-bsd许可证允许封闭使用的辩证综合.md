# 290.1.4 合图——BSD 许可证允许封闭使用的辩证综合

  - 要点：合图层不追求 “消除分歧”，而是 “在分歧中呈现各主体性”——（1）“允许封闭” 与 “期待回馈” 的对称合法性：BSD 许可证赋予 Sony 封闭使用的合法权利，BSD 社区亦有合法理由期待 Sony 实质回馈——二者在法律与道德层面均有正当性，合图不以 “对称合法性” 回避 Sony 回馈不足的实质问题，但亦不以 “回馈不对称” 否定 Sony 封闭使用的合法权利；（2）BSD 许可证哲学的 “改革” 张力：BSD 选择 “允许封闭” 的改革路径而非 GPL 的 “革命” 路径（copyleft 强制公开），这一选择在 Sony 案例中显现双重效应——正面效应是 FreeBSD 获得 Sony 等商业实体的大规模采用（PS4/PS5 亿级装机），扩大了 FreeBSD 的影响力；负面效应是商业用户的回馈激励不足，Sony 享受 FreeBSD “开放” 传统但未对应回馈 freebsd-src 上游——这是 BSD 改革路径的固有张力，总纲第 21 条 “改革的困难远高于革命” 在此显现；（3）“封闭化必然性” 与 “开放价值” 的并存：合图层承认游戏主机商品形式主义下的封闭化具有结构性必然性（Xbox、Nintendo Switch 同样封闭），但不以 “必然性” 否定 FreeBSD “开放” 传统在消费电子领域被封闭化的实质损失——PS4/PS5 用户未享受 FreeBSD “开放” 的对应自由，这一损失是真实的，即使 Sony 的封闭化是商品形式主义的必然结果；（4）合图不追求 “消除分歧”：BSD/Linux 阵营以 “开放-回馈” 为预设，Sony 阵营以 “许可证允许封闭-行业普遍特征” 为预设，两套预设基于不同价值观，合图不是 “消除分歧” 而是 “在分歧中呈现各主体性”——Sony 的 PS4/PS5 封闭化使用是 BSD 许可证赋予的合法权利行使，BSD/Linux 阵营对 Sony 回馈不足的批评亦是合法的社区诉求，二者在本体论上地位相等（总纲第 8 条）
  - **PlayStation OS 商业采用争议合图层四维度表**：

- 史观：总纲第 8 条——本体论上各方平等：Sony 与 FreeBSD 社区在本体论上地位相等，BSD 许可证赋予 Sony 封闭使用的权利与 BSD 社区期待 Sony 回馈的诉求各自成立，差异仅是一刻状态的不同；总纲第 21 条——革命与改革：BSD 的 “允许封闭” 改革路径与 GPL 的 copyleft 革命路径在 Sony 案例中显现固有张力——“改革的困难远高于革命”，BSD 改革路径扩大了 FreeBSD 的采用范围但削弱了回馈激励；总纲第 11 条——商品是形式主义：PS4/PS5 的封闭化是商品形式主义下 “劣币驱逐良币” 的显现，但 “劣币驱逐良币” 是描述性规律而非规范性判断——合图层承认这一规律的运作，但不以规律否定 BSD/Linux 阵营对 “开放” 价值的实质诉求；总纲第 19 条——解释学循环：BSD/Linux 阵营与 Sony 阵营的前理解差异使 PlayStation OS 商业采用争议的分歧不可避免，合图不是 “消除分歧” 而是 “在分歧中呈现各主体性”

**要点**：

- PS4 采用 FreeBSD 的说服路径：Rosenberg 在 PS3 时期已判断东京操作系统团队对游戏团队的真实需求了解不足，主张平台独有功能自研而管线性工作交给开源项目；Vita 时期团队以移植 Linux 的试验取得组织内部证据，再经法务确认 BSD 许可证无碍后正式采用 FreeBSD；他估计从已能在目标硬件上运行的工作系统起步“节省了大概两年的开发时间”（2834.22-2850.10）。（BSD Now EP122，[1810.84-2154.22]，L1）
- PS4 对 FreeBSD 的定制清单：日本系统团队首先剥离标准 BIOS 支持、仅允许自研引导，导致无法用 VirtualBox 或 VMware 的 GDB 桩做内核调试；用户态代码几乎全部重写、所有 API 调用按编码规范加 SCE 前缀改名，代价是无法检索现成答案；资源管理改为预算制，为后台守护进程预留 CPU 核心与内存；文件系统按计划出货的最差存储介质加余量给出带宽下限并以模拟模块过 QA；线程调度对高优先级抢占、低优先级协作。（BSD Now EP122，[2564.02-2850.10]，L1）
- 编译器路线：Vita 时期并存三条路线——SN Systems 基于其 1980 年代收购代码的自有编译器、Foster City 团队维护的 GCC、以及 Rosenberg 自 2001 至 2002 年起持续关注并推动评估的 LLVM；经 BeagleBone 裸机测试三者性能互有胜负，Vita 采纳了更受 Windows 游戏开发者欢迎的自有编译器，而 PS4 因自有编译器无 x86 支持使 LLVM 成为唯一现实选项；Rosenberg 称 Sony 以更少人力成为 LLVM 仅次于 Google 与 Apple 的第三大贡献者，并批评 GCC 社区不欢迎新贡献者。（BSD Now EP122，[2158.24-2450.12]，L1）

**史料**：

- 本期核心一手史料为 Alex Rosenberg 的当事人口述（2015 年 12 月 30 日录制）：包括 Sony 内部将一款 PS3 游戏移植到 vanilla Linux 的试验决策、“What is this FreeBSD you speak of? Is that like Linux?”式的组织陌生反应（1925.50-1928.20）、向法务解释 BSD 许可证后开始使用 FreeBSD 的过程，以及 Sony 开源许可声明与 Mark Cerny 公开仅称 BSD 的发言记录；另涉及其提及的 Chris Lattner 2001 至 2002 年间的 LLVM 邮件列表早期帖子、sony.co.jp 版权声明页与维基百科证据链等可回溯材料。（BSD Now EP122，[1810.84-2154.22]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：PS4 采用 FreeBSD 并非技术进步叙事中的必然胜利，而是一连串偶然条件的汇流：一位在 Apple 时期接触过 BSD 与 Cell 芯片细节的工程师、一次移植 Linux 的内部试验恰好成功、一份恰好让法务放心的许可证；换掉其中任何一环，主机史上的这次 BSD 采用都无从谈起，偶然性先于所谓规律。 [存疑脚注] 此为基于单一当事人口述的编纂层史学提炼，非史料直接陈述，判断依据为访谈中试验、法务与人事三条偶然线索的并置（BSD Now EP122，[1963.54-2154.22]，L4）
- 总纲4 分离聚合是永恒规律：Sony 与 FreeBSD 上游的关系呈现分离聚合的双向运动：API 改名、BIOS 剥离与用户态重写是组织对共同代码的形式主义化分离，而安全补丁回流、LLVM 上游贡献与 bootloader bcache 改进在 FreeBSD 与 Illumos 间的互引则是聚合；商业采用既非单向收割也非无私奉献，而是权力与资源在社区与企业间的再分配过程。 [存疑脚注] 此为编纂层对访谈证据的模式化提炼，Sony 分支具体改动规模缺乏仓库级数据支撑，仅凭当事人自述定性（BSD Now EP122，[3196.28-3242.78]，L4）

**辨析**：

- Apple 转向 LLVM 的偶然节点：Rosenberg 自述两名 Apple 工程师写出 LLVM 的 PowerPC 后端后被开发工具负责人以永远不会好过 GCC 为由驳回，随后 FSF 的 GPLv3 草案以 TiVo 化等条款令企业法务恐惧，成为 Apple 全押 LLVM 并雇佣 Chris Lattner 的直接推力；此说将编译器史上的关键转折归于法律文本的起草波动而非纯技术优劣，与常见的进步叙事构成可辨析的张力，且系单一当事人记忆，日期与细节待独立佐证。（BSD Now EP122，[3336.24-3409.00]，L1）
- 回馈不对称的自供状：Rosenberg 承认 PS4 的 BSD 分支已成为自己的东西，安全团队负责盯梢上游补丁并拉取，但客观上因不是社区的活跃参与者而受损；公司需审查的不止内核与编译器而是大量开源组件。此一手证词与导演方关注的商业采用与回馈不对称问题互证，同时提示企业分支脱钩的隐性成本，可视为厂商侧对自身脱钩行为的罕见坦承。（BSD Now EP122，[3196.28-3242.78]，L1）
