# 286.2.1 OPNsense 的诞生

  - 要点：OPNsense 由 Deciso B.V.（荷兰公司，Franco Fichtner 主导）于 2014 年自 pfSense 分叉启动，2015 年 1 月首次正式发布；分叉动因兼具技术与社区双重维度——技术上 OPNsense 团队认为 pfSense 长期固守 FreeBSD 8.x 基础过旧、缺乏对现代 PHP 与组件的更新，社区上 OPNsense 团队对 pfSense 商业化方向（Netgate 的封闭开发模式）表示不满；OPNsense 采用更频繁的发布节奏（半年一次大版本）与不同的 Web 框架（基于 Phalcon PHP 框架重构），二者竞争推动 BSD 防火墙生态成熟。2015 年 2 月 m0n0wall 终止后，Manuel Kasper 将 m0n0wall 开发社区转交给 OPNsense 项目，OPNsense 在品牌叙事中即以“m0n0wall 与 pfSense 共同继承者”自居，这一谱系声称须以 OPNsense 官方公告与 m0n0wall 终止声明交叉验证，不得仅凭 OPNsense 单方叙事采信。
  - 史料：OPNsense 公告（Deciso，2015）、pfSense/OPNsense 对比文献；**bsd-derivatives.duckdb** 查询 L7.1.1.opnsense-core（opnsense-core 仓库 2015-2026 年 merge commit 比例时间序列，识别 OPNsense 从 pfSense fork 后的分歧路径〔原标注 bsd_commits.duckdb 系拆分前旧库名，已更正〕）；**bsd-derivatives.duckdb** 查询 L1.1.1（opnsense-core 仓库 2015-2026 年每年 commit 量时间序列，与 pfsense-src 同期对比）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
  - 史观：总纲第 4 条——分离聚合是永恒规律（原“技术路线分化与并行演化”系伪名目，按论旨重挂）；统计结论印证：C-54（跨数据库关联分析 Task 28 多元 Spearman 相关矩阵）显示 opnsense-core 仓库 142 个非零月与 pfsense-src 394 个非零月存在时间序列相关，OPNsense 作为 pfSense 的二次 fork 其 commit 历史包含 pfSense 继承的 FreeBSD 上游历史与 OPNsense 本地分歧，体现 BSD 衍生谱系中 “fork 内 fork” 的多层分歧拓扑，0 信任原则适用：Spearman 相关不等于因果，opnsense-core 与 pfsense-src 的相关可能由共同的 FreeBSD 上游同步行为驱动
