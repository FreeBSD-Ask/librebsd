# 287.6.2 MidnightBSD起于Holt2004年的构想定位桌面BSD系统以易用与安全

- MidnightBSD 起于 Holt 2004 年的构想，定位桌面 BSD 系统，以易用与安全为核心诉求；他判定其他 BSD 项目对普通用户不够友好。桌面环境选择 GNUstep 而非 KDE 或 GNOME：PC-BSD 与 DesktopBSD 已占据 KDE 路线，GNOME 被众多 Linux 发行版采用而不合其差异化意图，且 Mac 社区存在 Objective-C 动量可资借助；其论证援引 NeXTSTEP 与 Mac OS X 的 BSD 痕迹与共享代码——Cocoa 即 NeXTSTEP、OpenStep 原始库的增强版本，GNUstep 则在库层面克隆 OpenStep，故 GNUstep 配 BSD 是历史的自然搭配。（BSDTalk EP126，[55.96-190.24]，L1）
- mports 是项目差异化重点：Holt 批评 FreeBSD ports 中相当一部分无法正确构建可复用的包，项目首要目标是让所有 port 都能打包，以 pkg_add、pkg_delete 式工具像 Linux 发行版那样消费二进制包，并完全重写包工具、提供命令行与图形两种界面、进而兼作系统更新之用。开发者 Chris Reinhardt 已完成初始脚本与 makefile 改动，正开发 ports 构建集群测试工具，包工具库与命令行界面随后，图形界面与系统偏好工具由 Holt 之妻以 GNUstep 编写。（BSDTalk EP126，[197.80-310.78]，L1）
- 基线与发布策略：当时仅发 i386，AMD64 随下一版本，Sparc64 仅为开发兴趣、PowerPC 无近期计划；项目继续基于 FreeBSD 6 系列，仅个别特性自 7 回移，Holt 强调“我们不是发行版，而是从 FreeBSD 项目分出的分支”；安装仍用 FreeBSD 的 sysinstall，基于 GNUstep 的 live CD 图形安装器（后端库加可选命令行界面）在开发中；镜像站点包括项目自有 FTP、ISD、东密歇根大学与 allbsd.org。1.0 设有自我约束门槛：普通用户放入光盘即得完整桌面环境并能图形化管理系统的程度未达，即不发布 1.0，以 Ubuntu 的开箱即用为参照；1.0 前至少五个发布，0.2 前完成包工具与新安装器，0.3 增加偏好工具，其余视社区反馈自适应。（BSDTalk EP126，[313.06-601.54]，L1）
- Holt 自陈开发以来最大障碍是获得社区接受：项目必须使用大量 GPL 许可的工具；操作系统偏好根深蒂固，Linux 仍然流行，许多开发者不愿看到又一个 BSD 出现；向上游提交补丁的成败因项目而异，Perl 项目是第一个接受其上游补丁的项目。安全方面，项目计划提供按服务开关、易于配置的防火墙面板（以 Mac OS X 防火墙控制面板为参照），并做用户态与内核的透明安全增强，针对 X11 的历史安全问题；明确不走 OpenBSD 那种妨碍用户的极端路线；ProPolice 曾进入代码树但因线程库问题撤出，未来可能恢复或转向 GCC 4.2；项目设安全官员专责研究。（BSDTalk EP126，[749.70-869.04]，L1）
- CodeWeavers 的工程模式为上游优先：全部工作先做进 Wine，再围绕较受限的功能集打磨稳定为 Crossover 商业产品；White 以 Debian 的不稳定版与稳定版类比，称 Wine 对应不稳定分支，Crossover 则是打磨且受支持的一方。（BSDTalk EP148，[84.60-121.60]，L1）
- White 强调 Wine 是从零重写的 Windows API 完整实现而非模拟器，与 VMware、Xen 先虚拟一台 PC 再安装 Windows 的路线相对；他主张免装 Windows、性能与桌面集成体验俱佳是兼容层路线的优势，同时自认立场有偏。（BSDTalk EP148，[125.68-167.32]，L1）
- Crossover for BSD 的出现并非公司战略，而是偶然条件叠加：BSD 社区成员多年在 Wine 上游改进 BSD 专属支持，White 花一个下午编译即成功，加之社区以礼貌方式提出移植请求，公司遂以不受支持版本形式发布；该版本可在 FreeBSD 与 PC-BSD 运行，FreeBSD 6 需应用补丁，开发与基础测试在 PC-BSD 完成，与 Linux 版尚不齐平且无直接支持资源。（BSDTalk EP148，[536.36-712.18]，L1）
- 商业模式上 BSD 版不单独发售：购买 Crossover for Linux 即可获取 BSD 构建（Crossover Games 先行，Crossover Linux 7.0 发布后扩展至办公版）；White 同时向 BSD 社区抛出挑战——用户可在兼容中心投票，当时仅十人购买并投票约合 400 美元，他直言该数额不足以构成商业吸引力，另一路径是参与 Wine 的 BSD 专属 Wiki 开发。（BSDTalk EP148，[756.36-915.44]，L1）
- 应用兼容图景：Microsoft Office 是旗舰，Office 2003 支持成熟、Office 2007 即将支持，Outlook 仍是最薄弱环节；游戏因只依赖 DirectX 接口且结构简单反而比 Outlook 易支持，World of Warcraft、Team Fortress 2 等 Steam 游戏可运行，Steam 分发缓解了 CD 拷贝保护障碍，主流作品仍以 DirectX 9 为主。（BSDTalk EP148，[188.32-341.16]，L1）
- DaemonForums 的起源是一次社区自救：bsdforums.org 自 2002 年运转良好，但管理员失联约两年，垃圾信息尤其是色情广告泛滥且无从处置，原社群于 2008 年 5 月自立门户；新论坛定位为官方 FreeBSD 邮件列表之外的互联网论坛补充，服务偏好论坛形态的用户；因旧论坛内容的版权归属无法迁移旧帖，论坛全新起步，而原社区几乎所有用户迁入。（BSDTalk EP155，[58.64-93.76]，L1）
- 运营形态：论坛暂由加拿大用户 Stukoff 托管并计划数月内自置服务器，运行于 FreeBSD；论坛软件经试用多个免费包（不完整、过简或缺功能）后购入商业授权使用（转写软件名不可靠，疑为 vBulletin）；反垃圾依托较新的 CAPTCHA，而旧论坛因软件多年未更新其 CAPTCHA 已被攻破，必要时将追加措施。（BSDTalk EP155，[104.84-201.00]，L1）
- 用户生态面向全体：从提问一次即离开的新人到有三十年经验的 BSD 老手均在其中；各 BSD 中 FreeBSD 用户最多、OpenBSD 次之、NetBSD 远少，与 BSDStats.org 的使用统计大体一致，Tournoij 认为论坛构成反映了真实的使用分布。（BSDTalk EP155，[208.48-263.52]，L1）
- 个人使用图景：Tournoij 约 2000 年因厌倦 Windows 而在 Linux、Solaris 与 BSD 间比较，最终以 FreeBSD 落定并沿用至今；家用桌面以 FreeBSD 承担视频播放、游戏与文字处理等全部事务，任系统管理员时混用 BSD、Linux 与 Windows；他强调选择 BSD 出于使用体验而非技术指标，就是喜欢其工作方式且简单；硬件以廉价或免费的旧机为主，含一台 SPARCstation，运行 FreeBSD 6 与 7 的 STABLE 分支，升级到 7 对终端用户几乎无感。（BSDTalk EP155，[281.96-394.42]，L1）
- 受访者 Chess Griffin 自述其技术轨迹：20 世纪 70 年代末以 Apple II 接触计算机、青年时期用 Pascal 与汇编、90 年代中后期主要使用 Mac，2001 年起在家全职使用 Linux，并主持 Linux 播客两年；约 2007 年前后通过 BSDTalk 节目系统接触 BSD 后开始认真使用，经历以爱好者身份在 FreeBSD 与 OpenBSD 之间平均分配精力，家中十余台机器多为 Linux 与 BSD 双引导或三引导。（BSDTalk EP158，[121.92-244.76]，L1）
- 他认为 Linux 经验可大体迁移至 BSD：shell、文件系统与命令行技能顺畅衔接，BSD 文件系统的整洁与逻辑性给他留下深刻印象；最大的调整并非技术本身，而是重新养成依赖一手系统文档的习惯——BSD 侧有 man page、FreeBSD Handbook、OpenBSD FAQ 等体系化文档，而各 Linux 发行版文档实践不一，部分发行版甚至剥离文档，他此前习惯于搜索引擎与论坛求解，转 BSD 后改为优先读官方文档。（BSDTalk EP158，[317.36-411.40]，L1）
- 在他看来，base 系统与第三方 ports/packages 的分离是 BSD 区别于 Linux 的结构性优点：Linux 用户习惯将整个系统视作一整套软件包，初见 base 与第三方应用的边界需要适应，但理解后认为该设计十分合理；服务启停方式的差异与更换 shell 属于次要适应点，均不构成实质障碍。（BSDTalk EP158，[425.40-468.80]，L1）
- 闭源驱动与 Flash 缺失构成 2008 年 BSD 桌面化的现实门槛：NVIDIA 闭源驱动彼时仅覆盖 32 位 FreeBSD 等少数组合，儿童教育网站普遍依赖 Flash，这直接阻碍他将孩子的机器换成 BSD。他个人的应对是用购买决策规避——只买开放驱动可用的 ATI 与 Intel 显卡、受支持的无线网卡——并以离线下载视频等方式绕过 Flash；但他承认对依赖专有软件的用户而言这仍是劝退因素。（BSDTalk EP158，[471.32-520.60]，L1）
- 他报告的版本升级实践为 BSD 升级路径的平稳性提供了用户侧证据：FreeBSD 自 6.2 经 make buildworld 原地升级至 7.0，OpenBSD 自 4.0/4.1 逐级升级至 4.3 并跟进 4.4-current 快照，全程无痛；他认为只要遵循官方文档，BSD 的升级体验与 Debian 的 apt 式更新相去不远。（BSDTalk EP158，[700.64-786.44]，L1）
- 对桌面化衍生项目的第一手评价：他在 ThinkPad X40 上试用 PC-BSD 运行良好，认为 PBI 单包下载点击安装对新用户极为友好、体验近似 Windows，附带的无线图形配置工具实用；但他本人偏好传统 ports 管理且不接受 KDE 默认桌面，故未长期使用——这一分化恰好显示桌面 BSD 用户群中新手向易用性与老手向可控性两条路径并存。（BSDTalk EP158，[788.24-899.98]，L1）
- 他自述曾长期无法理解 Linux 的 iptables，而 PF 让防火墙配置变得有趣；其家用防火墙由 Soekris net4801 单板机承担，运行 OpenBSD 并自 CompactFlash 卡启动。这一自建嵌入式 BSD 防火墙案例是 2008 年前后爱好者网络中 BSD 硬件生态的典型形态，也说明 PF 的配置可读性成为吸引用户从 Linux 防火墙工具迁移的实际因素。（BSDTalk EP158，[973.70-1020.98]，L1）
- 受访者 Eric Oyen 居于亚利桑那州凤凰城，约 2007 年经朋友寄赠 OpenBSD 4.2 官方购买版而开始使用 OpenBSD；此前他已是 Linux 防火墙配置的准专家，比较后认为 OpenBSD 的防火墙能力更强，遂尽量坚持使用 OpenBSD。约 2010 年他完全失明，访谈时（2012 年 11 月）在一台 900 MHz AMD Athlon 旧机上运行 OpenBSD 5.0 作家用防火墙。（BSDTalk EP220，[95.00-133.34]，L1）
- 他向本地 Linux 社区推介 OpenBSD 时给出的核心理由是防火墙脚本编写体验：iptables 编写繁琐复杂，而 PF 有专门的规则布局、条目顺序明确，理解与维护成本低；OpenBSD 亦可配置为对多数 IP 流量不可见的桥接式防火墙，在更低协议层过滤，与常规路由防火墙互为补充。（BSDTalk EP220，[554.32-589.74]，L1）
- 他认为 OpenBSD 坚持命令行配置与极简配置文件对屏幕阅读器用户格外友好，并特别称赞 afterboot 等手册页逐步引导的写法；其日常工作流是在 Mac 上用 VoiceOver 经 SSH 操作 OpenBSD，并开两个 SSH 会话交叉阅读文档与编辑配置，以绕开终端重读行等屏幕阅读器通病。（BSDTalk EP220，[509.34-543.22]，L1）
- 无障碍工具链方面：终端环境的 SpeakUp 以截取送往屏幕的文本的方式朗读，仅需标准 105 键键盘；图形桌面则依赖 GNOME 或启用无障碍特性的 GTK 桌面（如 XFCE）配 Orca，但在未知硬件上启动 X 并配置屏幕阅读器仍不可靠。完全失明后他安装 OpenBSD 需视觉辅助或自定义脚本，期待安装镜像能像 live DVD 一样检测驱动并在启动时提供语音接口。（BSDTalk EP220，[178.50-368.06]，L1）
- 关于无障碍的远程系统管理：他描述了两类途径——串口控制台（启动阶段仅需他人敲入重定向命令，之后可从终端经 screen 会话接入串口设备）与“屏幕抓取”专用卡（对系统表现为文本图形显示，实际将文本经串口或网络输出，不依赖操作系统驱动），后者还包括服务器级主板的板载管理子板，可经 SSH 进入固件设置，从而在开机全程不看屏幕。（BSDTalk EP220，[741.94-902.68]，L1）
- LightZone 项目源于 2011 年 Light Crafts 公司骤然倒闭后的“救生艇”行动：时任公司论坛志愿版主的 Tex Andrews 应论坛用户之请，与经 Digital Photography Review 联络的 Doug Pardee 合作，以 Drupal 网站与互助论坛为骨架，试图接管这家 2005 年创立的商业照片编辑器公司留下的孤儿软件。（BSDTalk EP262，[54.04-157.44]，L1）
- 接管方始终无法直接说服创始人 Fabio Riccardi 开源，转机来自原开发者 Anton Kast 主动联系社区并由其斡旋；Fabio 最终同意以 BSD 许可证放行源码，唯一条件是社区不得将软件用于出售。志愿者团队（含 Pavel Benak、后任主开发的日本开发者 Masahiro Kitagawa）历时约七个月完成重新编译，2013 年前后以 LightZone Project 名义发布并持续小幅升级。（BSDTalk EP262，[194.38-302.82]，L1）
- Tex Andrews 概括 LightZone 在 2005 至 2006 年间的四项技术标识：全流程非破坏性编辑（编辑参数存于 sidecar 文件而绝不改动 RAW 原片）、从工具到输出的全链路 14 位深度、借助矢量图形选区实现羽化局部编辑，以及把 Ansel Adams 与 Fred Archer 的区域曝光法改造为半档分区的 ZoneFinder/ZoneMapper 调色工具，后者使其在黑白摄影用户中长期保有回头客。（BSDTalk EP262，[348.72-535.24]，L1）
- DesktopBSD 的定位是“预配置的 FreeBSD 桌面系统”而非分叉：不改动 FreeBSD 内核与用户态，只调整默认设置与内核配置，使其易装并默认搭载 KDE 桌面环境，另附软件包安装升级、设备挂载、网络配置、硬件监控等专用图形工具；当事人强调目标是提供易用的 FreeBSD 图形配置界面，而非克隆其他操作系统。（BSDTalk EP31，[135.96-182.36]，L1）
- 项目约于访谈两年前启动、一年前公开，动机在于 FreeBSD 虽可靠、强大、安全且软件丰富，但对 FreeBSD 与 UNIX 新手并不友好：KDE 须手动安装、登录管理器须自行配置、设备须以命令行挂载；当事人由此决定改善这一局面，并以 ports 集合的便利作为其留在 FreeBSD 阵营的原因。（BSDTalk EP31，[186.16-232.0]，L1）
- 与上游的关系与 1.0 版情况：DesktopBSD 1.0 基于最新的 FreeBSD 稳定版或 FreeBSD 5 快照，此前全部候选版本皆基于 FreeBSD 5；当事人称与 FreeBSD 项目数月前有过沟通，并判断 FreeBSD 并不热衷在 base 中纳入图形安装器；1.0 反响良好但功能尚薄，仍须完善包管理器、扩展无线支持；团队计划将 DesktopBSD 工具发布进 FreeBSD ports，使其可安装在原版 FreeBSD 上。（BSDTalk EP31，[235.72-389.16]，L1）
- 当事人的双重身份：在 Opera 担任邮件客户端开发者（负责 IMAP 等全部邮件功能），同时是公司内少数负责 FreeBSD 移植工作的开发者之一，须保证 Opera 在 FreeBSD 上编译并正常运行。（BSDTalk EP36，[63.52-86.04]，L1）
- Opera 的跨平台架构：FreeBSD 版源码与 Linux、Solaris 等完全相同，用户界面平台特定而 HTML 渲染等核心代码在 Mac、Windows 与 Unix 上共享；Opera 9 beta 的两大新特性为内置 BitTorrent 协议支持（浏览器内直接下载种子文件）与 widgets——可后台驻留的小型 Web 应用，且一个 widget 无需改动即可在全部操作系统上运行，平台无关正是其设计目标。（BSDTalk EP36，[94.52-166.72]，L1）
