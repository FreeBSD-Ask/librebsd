# 295.1.5 关于IPv6受访者给出关键的历史定性KAME团队当年向多个操作系统交付IPv6参

- 关于 IPv6，受访者给出关键的历史定性：KAME 团队当年向多个操作系统交付 IPv6 参考实现，对 FreeBSD 而言属于外部贡献，项目此后逐步取得该代码的所有权，使其与自有网络栈收敛、消除残余的巨型锁，并确立“凡改动 IPv4 必须同步改动 IPv6 并说明”的开发准则；IPv6 多播（MLD 与选择源多播）重新实现而非沿袭 IPv4 的后补设计，服务 IPTV 类应用；部署上日本与亚洲、欧洲部分地区已可取得原生 IPv6 服务而北美多为隧道，美国国防部要求采购支持 IPv6，Apple 的 Mac OS X 亦使用 FreeBSD 派生代码完成部分设备的 IPv6 配置。 [存疑脚注] 转写将 KAME 误作 Kami、将 cvsup6 服务器名讹化为 cvsub 等表述，引用时以原始音频核对（BSDTalk EP173，[1934.8-2165.3]，L1）
- 核心团队描述与 PC-BSD 的协作关系：PC-BSD 团队连续数年参加 FreeBSD 开发者峰会并演示其新版集成 jail 的图形化创建与管理功能；团队与上游合作改进桌面硬件支持，其中长期阻碍 64 位平台 Nvidia 驱动所需的虚拟内存特性由 John Baldwin 补齐，预期 FreeBSD 8.0 与 7.3 将支持 64 位 Nvidia；PC-BSD 背后由 iXsystems 推动，核心团队正吸纳其成员深入社区、增进对发布过程的了解，并期待其最终实现与 FreeBSD 发布同步。 [存疑脚注] 转写将 PC-BSD 讹作 PCVSD、PCBSC 等，将 iXsystems 误转为 IAC systems，将 Kris Moore 仅记作 Chris，正名以通行拼法为准（BSDTalk EP173，[1311.4-1460.4]，L1）
- 关于 pfSense，核心团队将其定位为面向防火墙场景的嵌入式 FreeBSD 衍生发行版，配以 web 管理界面；该产品直接集成 8.x 的虚拟接入点支持，使单块无线网卡可承载多个 SSID 与属性各异的网络，并吸纳了在 FreeBSD 社区搁置已久的 NAT-T 补丁；其大规模部署为这些代码提供了额外的实战检验，反馈回流使代码回归 base 树时更成熟，pfSense 团队亦因此受邀参加开发者峰会，带来与既有 PR 渠道不同的用户需求清单。（BSDTalk EP173，[1460.4-1553.9]，L1）
- Kris Moore 介绍 2008 年 11 月完成的 PBI schema 2.0 重构：终端用户界面不变而后端彻底重想，构建服务器自 ports 树自动生成 PBI，例如 Firefox 的安全更新会在约 24 小时内触发对应 PBI 的重建与上传；配合 local base 方案，应用不再编译进 usr/local 并以符号链接挂接系统，而是自包含于按应用与版本划分的 Program 目录（如 Program 下的 Firefox 及其版本号），从而消除符号链接被 ports 安装破坏的失效点，使 PBI 与 ports 树、基本系统真正相互独立，升级时亦不摧毁用户的 usr/local 树。 [存疑脚注] 转写将符号链接误作 sim links、Program 目录路径存在讹化，路径细节以 PC-BSD 文档核对（BSDTalk EP174，[706.2-794.2]，L1）
- Warden 是 PC-BSD 为 jail 提供的前端工具，提供 shell、图形界面与 dialog 远程三种接口，后端以插件脚本直接调用 jail 命令与系统配置，不经中间元数据库；其配套的 inmates（囚友）模板把整套应用栈（如含 Apache、MySQL、PHP 与配置脚本的 Joomla）打包为一键安装单元，自动适配 jail 的 IP 地址并完成初始化，面向不熟悉 jail 与 Apache 的初级管理员；工具还支持将配置好的 jail 停止、导出为压缩文件、在异机以新 IP 导入并直接启动，实现远小于整机虚拟镜像的 jail 级迁移，类同虚拟设备市场的分发思路。 [存疑脚注] 转写将 Joomla 误作 JUMLA、Juewell 等形式，工具名 Warden 与模板名 inmates 以项目文档为准（BSDTalk EP174，[246.9-417.9]，L1）
- 自 PC-BSD 发布以来用户持续请求瘦客户端方案，Moore 约一年前着手实现为独立 PBI：自动配置 PXE 与 NFS、搭建客户端启动环境并引导至 KDM 登录界面，安装时仅需选择一块网卡设置 DHCP；最新版本支持按客户端 MAC 地址在服务器保存各自的 Xorg 配置（含双头输出），重启后自动匹配应用；当时尚缺本地设备映射与流式音频支持，目标年内发布 1.0。 [存疑脚注] 转写将 KDM 误作 KTM、PXE 误作 pixie，此处按上下文订正（BSDTalk EP174，[434.5-575.9]，L1）
- 关于发布策略，PC-BSD 7.2 将是 7 系列的收官版本，仅随附最新 ports 与修复；重心转向 FreeBSD 8 所带来的 Linux 模拟改进（2.6 内核支持）与 Wi-Fi 等基础能力，并自 8 起重写系统安装器、拟以后端脚本化（提及 Lua）扩展功能；在开发者峰会上萌生的另一特性是允许从 PC-BSD 安装盘直接安装原生 FreeBSD，包括 sysinstall 无法完成的 ZFS 根分区图形化安装；PC-BSD 团队规模远小于 FreeBSD 但力求贴近其发布节奏，目标在上游版本发布后两三个月内跟进，且已迁入新构建农场、将每周发布开发快照（此前自建机房带宽不足以周传数 GB 的 ISO）。（BSDTalk EP174，[582.1-706.2]，L1）
- 在产品哲学上，Moore 坦言 netbook 场景（其自购机仅 4GB SSD）尚无精简安装选项、可能留待 8.0 考虑，但 PC-BSD 刻意维持统一的基本系统：一旦提供过多可选组合，包之间对基本系统内容的假设就会落空、可靠性下降，而声明确定组件常驻基本系统则可放心依赖；当前安装实际占用约 6GB、建议 10GB 磁盘且短期不会攀升；Fluxbox 自首个版本即内置但从未宣传，iXsystems 的 James Nixon 为其做了主题美化，GNOME、XFCE4 与 WindowMaker 则将以自包含 PBI 形式提供，用户不必被锁定在 KDE4。 [存疑脚注] 转写将 GNOME 误作 Nome、WindowMaker 误作 XWidnoManager，正名以通行拼法为准（BSDTalk EP174，[818.1-914.1]，L1）
- PC-BSD 8将PBI浏览器整合进软件与更新工具：在统一界面内浏览、排队下载、安装、更新与移除软件（以Amarok为例），无须再赴PBI Dir网站手动下载；PBI构建服务器自动由ports树构建PBI并定期更新；Kris Moore为PBI工具添加挂钩使其可被调用，该工具于2010年2月前后随8系列beta推出。（BSDTalk EP185，[119.76-191.74]，L1）
- Life Preserver是rsync的图形前端，支持整机（非仅用户主目录）向本地或远程备份与还原；配合PC-BSD 8的DVD安装器，可从Life Preserver备份直接安装复原整个系统，当事人称此为可供宣传的完整回滚路径。（BSDTalk EP185，[191.74-238.46]，L1）
- Port Jail针对“用户构建port时依赖连锁可能毁坏系统”的老问题：将ports树置于jail内任意安装构建，替代以往dual local bases的权宜做法；X应用与声音须额外配置方能工作，当事人以Sauerbraten在jail内运行验证可行，视为困扰已久的构建隔离问题的解法。（BSDTalk EP185，[261.66-301.38]，L1）
- PC-BSD 8令64位桌面首次实用化：64位NVIDIA驱动到位，经修整32位库后32位Wine PBI可运行于64位系统，当事人随即安装Steam并以Assassin's Creed验证（Dragon Age图形仍有瑕疵），并断言以缺乏Wine或3D为由否认BSD有64位桌面的批评不再成立。（BSDTalk EP185，[313.50-394.14]，L1）
- The Definitive Guide to PC-BSD（Apress出版）为PC-BSD首部专著，恰与2010年2月的PC-BSD 8同期面世；PC-BSD 8大量新特性彼时缺乏文档，作者自述系“边写边创造文档”，对KDE部分以反复试错摸清功能；全书定位兼顾两端——Windows或Mac背景的开源新手与资深FreeBSD用户（后者可自三分之一处进入）。（BSDTalk EP188，[63.40-267.34]，L1）
- 全书结构从开源与PC-BSD起源讲起（作者直言须回应“软件不付费即不合法”的误解），继而覆盖安装（live DVD、虚拟机、双启动与自定义启动管理器；PC-BSD 8亦可直接安装FreeBSD且安装后端开放）、日常任务与定制（仿Windows控制面板分用户设置与系统管理员设置）、软件安装三法（PBI一键安装、packages、ports；ports与packages在新版中于jail环境运行以免损坏系统）、社区沟通与高级内容（jails图形化管理、FreeBSD package近自动化转为PBI、翻译、以SVN自制定制版与自定义安装）。（BSDTalk EP188，[262.24-730.08]，L1）
- 作者特设社区章并视之为技术书中的首例：向完全新手解释IRC、论坛、邮件列表与网络礼仪，教导如何有效提问而不扰众，并列举不写代码者的参与途径；她称写作中最意外的是PC-BSD社区的深度与响应速度——邮件列表服务老用户、论坛与社交媒体服务新用户，“总有办法到达你所在之处”。（BSDTalk EP188，[548.44-1066.62]，L1）
- 硬件要求呈分层：默认KDE需要较新机器（至少512MB内存与像样处理器）；随附的Fluxbox出乎意料地干净轻快，且PC-BSD全部工具（更新管理器、软件安装、jails）在其下均可用，老硬件亦可胜任；资源极度受限者可自DVD安装barebones FreeBSD（速度极快，但不能如传统安装挑选安装集）。（BSDTalk EP188，[1094.32-1185.54]，L1）
- BSD认证的BSDP（professional级）面向两年以上BSD管理经验者（现有BSDA面向约六个月经验的初级），其job task分析采集雇主、在职管理员与HR反馈以定考核重点，调查结果已于访谈前一周公布；分析识别两类受众——初级须具备跨BSD基础能力（会FreeBSD配置网卡亦应能在OpenBSD完成），高级管理员拒绝被指定BSD与软件（如sendmail与postfix任选），故BSDP将改为任务加产出的考核、不指定平台与工具、贴近真实工作场景，且无需先过BSDA；考试形式受访多数要求lab与笔试结合，笔试已运营两年而lab考试在全球会议的交付方式尚待解决，BSDCan上Jim Brown将讲BSDP流程，会后另设全天公开会议并网络直播，邀请心理测量学家与公众商议考核设计。（BSDTalk EP188，[1243.22-1438.12]，L1）
- Kris Moore 说明 PC-BSD 9 直接基于 FreeBSD 9（HEAD 快照），版本节奏与 FreeBSD 9 发布工程同步；本期最大变化之一是 PBI 系统自零重写：抛弃以 QT4 为中心的结构，改为 shell 命令行驱动的后端（pbi add、info、remove、update、patch 等命令并配手册页），QT4 图形界面降为调用后端的前端，命令行用户亦可完整使用 PBI 体系。（BSDTalk EP201，[195.34-307.22]，L1）
- 桌面策略的根本转向：PC-BSD 9 不再以 KDE4 为唯一中心，KDE、GNOME、XFCE 与 LXDE 四大桌面环境在安装时即可勾选、装后亦可更换；其实现基于操作 FreeBSD 软件包的 PC Meta Package Manager 元包工具，发布时冻结一组互相兼容的包集，用户改变选择时由系统卸载旧包、自安装介质补装新包。（BSDTalk EP201，[92.72-195.34]，L1）
- PBI 新格式特性：安装时校验各应用间完全相同的库并以硬链接共享（hash 目录），既省磁盘与内存又保留按应用隔离的独立性；PBI 自构建服务器起即带数字签名，企业或个人可自签自建分发；引入二进制差分更新，一百五十 MB 的 PBI 更新差分可能仅四 MB，失败自动回退整包下载；pbi add -r 支持从仓库按架构取包，并可在 64 位系统上装 32 位包（如 Wine）。（BSDTalk EP201，[307.22-435.06]，L1）
- 构建体系与外溢计划：PBI 换用全新构建设施，pbi_makeport 命令内建全部构建工具，无需 chroot 即以独立前缀干净构建并签名，附自动批量构建脚本；计划当年年底将 PBI 工具链送入 FreeBSD ports 树、远期争取进入基本系统，使原生 FreeBSD 用户亦能取用；port jail 机制保留，允许在独立 jail 中试装 ports 而不触碰基本系统。（BSDTalk EP201，[516.86-693.16]，L1）
- 安装器与运维细节：磁盘页新增自动分区复选项，可选 ZFS、软更新日志（SUJ）或普通软更新，GPT 分区一键开关，但 Moore 提醒老式 BIOS 读取 GPT 盘可能挂起、仅能拔盘自救；介质分 USB 安装器、boot-only、安装 DVD 与 KDE4 版 Live DVD；8 至 9 无平滑升级路径（PBI 格式不兼容），官方建议备份 home 目录后重装。（BSDTalk EP201，[852.08-1034.52]，L1）
- James Nixon 在 iXsystems 负责 FreeNAS 的界面布局与社区倡导工作并充当 Django 模板问题的兜底支持；John Hixson 当时正打磨 FreeNAS API，Nixon 计划在 API 完成后编写第一个官方插件并发布逐步教程，以自身示范带动社区代码贡献；插件形态预计与 PC-BSD 的 PBI 模块类似，只要对接 API 即可用 Django 或任何语言编写。（BSDTalk EP210，[294.50-436.70]，L1）
- LISA 2011 展台演示的 TrueNAS 运行于小型 NAS 设备，含 ZFS v28 与 ZFS 复制功能，而社区版 FreeNAS 当时停留在 ZFS v15；iXsystems 将 TrueNAS 所需的特定 ZFS 特性回移植进 FreeBSD 8 系列，计划随 FreeBSD 9 发布回流公共侧；FreeNAS 下一主版本确定基于 FreeBSD 9，并与 PC-BSD 的发布节奏保持对齐。（BSDTalk EP210，[59.48-89.72]，L1）
- iXsystems 接管 FreeNAS 的缘由：原开发者 Olivier 因个人精力转向 Linux 曾考虑把项目迁往 Linux 平台，其副手近年承担主要维护工作，但 FreeNAS 7 所基于的 m0n0wall 框架难以添加新功能；iXsystems 内部使用 FreeNAS 已五年，为给社区保留 BSD 路线的 NAS 方案而接管项目并获得 Olivier 同意，随后重写 FreeNAS.org 并建立新论坛。（BSDTalk EP210，[983.02-1054.28]，L1）
- PC-BSD 9 isotope 版本自 beta1 起可一路升级而无需光盘重装；系统更新工具主动提示 RC 与 PBI 更新；新 PBI 系统改为差分下载，不再出现一百六十兆级的 Firefox 更新包；新控制面板与 meta package 机制支持 GNOME、KDE、LXDE、XFCE4 四大桌面（Fluxbox、TWM、Awesome 等可用但未官方支持），标志 PC-BSD 由 KDE 中心转向桌面中立；iXsystems 办公室桌面大量自用 PC-BSD，以 KDE 的 Dolphin 文件管理器访问 FreeNAS 共享。（BSDTalk EP210，[443.06-623.22]，L1）
- 社区生态方面，iXsystems 聘用 Dru Lavigne 统管 PC-BSD 与 FreeNAS 等项目的社区管理；论坛与 IRC 中社区保持活跃且敢于发声，有若干核心社区成员充当公司与社区之间的纽带；社区最期待 mini-DLNA 与 Transmission 等多媒体与下载插件回归，而插件系统在 FreeNAS 8.0 发布时尚未就绪；受访者预期社区会把 NAS 延伸为媒体中心，并愿意指导新人参与代码。（BSDTalk EP210，[623.22-787.18]，L1）
- ZFS 被视为 BSD NAS 的杀手特性：CDDL 许可证使 ZFS 在 BSD 侧的整合远比 Linux 侧容易，Linux 侧移植当时性能不切实际，受访者以 2004 年模拟 Dreamcast 每秒一帧作比；Oracle 收购 Sun 之后，公开 ZFS 预计止步于 v28，Oracle 内部后续版本不会开源，BSD 社区将自行延续开发；iXsystems 已实现盘故障通知、盘位指示灯等特性，并在自研 ZFS daemon。（BSDTalk EP210，[1054.28-1175.64]，L1）
- 用户侧证据显示 FreeNAS 在教育等预算受限场景被广泛推荐：主持人在缅因州 K-12 学区环境中观察到，学生统一配发苹果笔记本打破单一微软生态后，无法依赖 Windows 文件服务器的完全集成，FreeNAS 因此常被列为替代方案；TrueNAS 初装存在困惑，iXsystems 自 Cisco 招募 Garrett Cooper 专职客户支持，规划中的设置向导界面即针对初装门槛。（BSDTalk EP210，[916.74-965.42]，L1）
