# 023.3.1 BCPL-B-语言与-C-语言前身-Cantabrigian-到

## 要点

1966 年，Martin Richards（Cambridge University Computer Laboratory，剑桥大学计算机实验室）设计 BCPL（Basic Combined Programming Language），灵感来源于 Christopher Strachey 的 CPL（Combined Programming Language，1963，剑桥大学与伦敦大学联合设计）；BCPL 的核心特征是 “无类型语言（typeless）——所有数据皆为机器字（word）”，简洁的语法（如 `V1 := V2 + 1`），块结构与递归；BCPL 1967 年首次实现于 CTSS（Compatible Time-Sharing System），1969 年 Richards 在 MIT 访问期间实现 BCPL 编译器，使 BCPL 成为跨平台语言。
1969 年，Ken Thompson（Bell Labs）在 Multics 项目终止后，于 PDP-7 上实现第一版 UNIX（1969 年夏），用 PDP-7 汇编编写；为提升 UNIX 开发效率，Thompson 基于 BCPL 设计了 B 语言（1969），保留 BCPL 的无类型特性，但简化语法（如 `v1 = v2 + 1;` 替代 BCPL 的 `V1 := V2 + 1`）。
B 语言的局限性：B 语言的无类型特性（所有数据皆为 word）在 PDP-7（18 位 word）与 PDP-11（16 位 word，8 位 byte）上导致内存效率低下——PDP-11 引入字节寻址后，B 语言无法区分字节与字，使字符串处理与结构体操作效率低下；此外，B 语言的解释执行（threaded code）比编译执行慢，无法满足 UNIX 内核性能需求。
1971 年，Dennis Ritchie 开始在 B 语言基础上开发 NB（New B），引入类型系统（char、int、float、pointer 等）、结构体（struct）、数组（array）等特性；NB 演化为 C 语言（1972），首个 C 语言编译器在 PDP-11 上实现；C 语言的命名 “C” 源于 “BCPL 的第二个字母 B 之后是 C”（A、B、C 序列，A 语言为 ALGOL 60 谱系的早期名称，B 语言为 BCPL 简化版，C 语言为 B 语言的演化）。
A 语言的辨析：A 语言（A Language）在编程语言史中存在多重含义——部分文献指 “ALGOL 60 的早期名称”，部分指 “Ken Thompson 在 BCPL 之前尝试的语言”，部分指 “A₀（A-zero，1958，Remington Rand）” 等早期语言；本子节采用 “A 语言” 指 “BCPL 谱系之前的 ALGOL 60 早期名称”（与 B 语言、C 语言形成 A→B→C 序列），其他含义在辨析字段中说明。

## 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 4（分离聚合是永恒规律）**——见 据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

BCPL → B → C 的演化呈现分离聚合——BCPL（剑桥）与 B（Murray Hill）从分离（不同团队）到聚合（B 基于 BCPL），B 与 C 从聚合（C 基于 B）到分离（C 引入类型系统，B 保持无类型）——这一系列分离聚合并非线性进步，而是不同主体在不同历史阶段的形式主义化选择。

**总纲 3（不存在进步，只有权力再分配）**——见 据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

C 语言从 B 语言演化而来，并非 “C 语言优于 B 语言的进步”，而是 PDP-11 硬件能力的权力再分配——PDP-11 引入字节寻址后，B 语言的无类型特性无法高效利用硬件能力，C 语言的类型系统是 “硬件能力 → 语言表达” 的重新分配；同理，B 语言从 BCPL 演化而来，是 PDP-7 硬件能力（18 位 word，无字节寻址）的权力再分配。所谓 “C 语言必然取代 B 语言” 的叙事，掩盖了硬件能力与语言设计的辩证关系。

**总纲 5（没有必然性，只有偶然性）**——见 据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义。”

若 Martin Richards 未在 1966 年设计 BCPL，若 Ken Thompson 未在 1969 年访问 MIT 接触 BCPL，若 Dennis Ritchie 未在 1971 年开始 NB（New B）项目，C 语言可能根本不会诞生。所谓 “C 语言必然诞生于 Bell Labs” 的叙事是史家的事后重构，掩盖了 BCPL → B → C 演化路径的多重偶然。

**总纲 10（动手者创造历史）**——见 据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

Martin Richards 亲自在剑桥实现 BCPL 编译器，Ken Thompson 亲自在 PDP-7 上用汇编实现 B 语言编译器，Dennis Ritchie 亲自在 PDP-11 上实现 C 语言编译器——这些是动手者的实践，而非 “Bell Labs 决定开发 C 语言” 等高管决策的产物。须注意：Bell Labs 提供了研究环境，但 BCPL/B/C 的具体设计与实现是 Richards、Thompson、Ritchie 的主体性选择。

**总纲 2（历史是形式主义化的非存在）**——见 据原文第 2 章 2.5 节：

> “谁试图诠释历史，谁就在篡改历史。”

所谓 “BCPL → B → C 的线性演化” 的判定本身即形式主义化的非存在——若以 Multics 项目为主线（Multics 用 PL/I 编写，BCPL/B/C 皆为 Multics 后的语言），若以 Pascal（1970，Niklaus Wirth）为主线，若以其他系统语言为主线，“C 语言前身史” 会呈现完全不同的脉络。本子节选取 “BCPL → B → C” 为主线，但这一选取本身须以自反性声明显化。

**自反性声明**：本子节选取 “BCPL（剑桥）→ B（Thompson）→ C（Ritchie）” 为 C 语言前身主线，但这一选取本身即形式主义化的非存在。若以 CPL（1963）为主线，若以 PL/I（Multics 语言）为主线，若以 Pascal（1970）为主线，“C 语言前身史” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

## 辨析

**A 语言含义辨析**：A 语言在编程语言史中存在多重含义——（1）ALGOL 60 的早期名称（1958，部分委员会成员称呼）；（2）Ken Thompson 在 BCPL 之前尝试的语言（部分文献提及，但无原始文档存档）；（3）A₀（A-zero，1958，Remington Rand，早期商业语言）；（4）APL（A Programming Language，1962，Kenneth Iverson）的早期名称。本子节采用 “A 语言指 ALGOL 60 早期名称” 的限定性表述，其他含义在文献中说明。

**B 语言设计开始日期辨析**：部分二手资料称 “B 语言于 1969 年设计”，部分称 “1970 年”；考据结论：Thompson 在 1969 年夏开始 B 语言设计（基于 BCPL），1970 年 B 语言编译器在 PDP-7 上运行，1971 年 B 语言用户手册发布。本子节采用 “B 语言设计始于 1969 年，1970 年编译器运行” 的限定性表述。

**NB（New B）与 C 关系辨析**：部分二手资料称 “NB 即 C 语言”，但 NB（1971）与 C（1972）有差异——NB 引入了类型系统但仍保留部分 B 语言特性，C 语言是 NB 的进一步演化。本子节采用 “NB（1971）为 B 与 C 之间的过渡语言，C（1972）为 NB 的演化” 的区分性表述。

**C 语言命名辨析**：部分二手资料称 “C 语言命名为 C 因其为 BCPL 的后继”，部分称 “因 B 之后的字母”；考据结论：Dennis Ritchie 本人在 1993 年论文中说明 “C 语言命名为 C 因其为 B 语言的后继，B 语言命名为 B 因其为 BCPL 的首字母”，A、B、C 序列是事后归因。本子节采用 “C 语言命名为 C 因其为 B 语言的后继（A、B、C 序列事后归因）” 的限定性表述。
