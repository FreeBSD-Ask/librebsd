# 012.11.2 System III/V 的安全增强与审计子系统——SVR2/SVR3/SVR4 时间线

**要点**：1981 年 AT&T 将 PWB/UNIX 与 Research UNIX V7 部分特性合并发布 System III，作为对外商业发行的首个 UNIX 系统版本；1983 年 System V Release 1 发布，此后 System V 经历 SVR2（1984 年，引入 `audit()` 系统调用雏形）、SVR3（1986 年，引入完整的审计子系统含 `/usr/sbin/audit` 与 `/etc/security/audit_event`）、SVR4（1988 年，引入可信计算基 TCB 框架含 label 机制与 `/etc/security/` 配置目录）等版本，逐步引入审计子系统、TCB 框架、MAC 雏形以应对 TCSEC（橘皮书）评估需求；这些机制与 BSD 同期发展的 chroot、securelevel、Kerberos 形成 1980 年代 UNIX 安全的三大分野

**史料**：System III 与 System V Release Notes（AT&T 商业发行版本说明，含安全机制变更，部分存档于 `docs.oracle.com` 与 TUHS `www.tuhs.org` 镜像）；Bach 1986《The Design of the UNIX Operating System》关于 System V 安全机制（含 SVR2/SVR3 的 setuid、审计子系统雏形）的详细叙述；TCSEC 橘皮书（DoD 5200.28-STD，1985 年，存档于 NIST 与互联网档案馆）；Salus 1994 编年史；freebsd.duckdb 数据库交叉印证——`SELECT * FROM commits WHERE repo_name='freebsd-src' AND (message_subject LIKE '%audit%' OR message_subject LIKE '%TCB%')` 未返回 System V 审计子系统直接相关 commit（预期内，System V TCB 未直接进入 FreeBSD 主线），但 FreeBSD 6.0 起的 OpenBSM 审计框架可视为 System V 审计理念的迟来回流 〔L1 代码 + L3 官方文档 + L5 书籍〕

**史观**：技术路线分化：System V 的商用化安全增强与 BSD 的网络化安全扩展形成 1980 年代 UNIX 安全的分野；法律结构：TCSEC 评估需求作为政府监管塑造商用软件安全机制的实例

**辨析**：SVR2 引入 `audit()` 系统调用的精确时间（1984 年）需考据——按 Bach 1986 教材与 Salus 1994 编年史两方独立来源交叉印证；SVR3 审计子系统的完整性程度需考据——“完整”系相对于 SVR2 雏形而言，与 SVR4 TCB 框架相比仍有差距；System V 安全增强与 BSD 安全扩展的“分野”是否被夸大需辨析——两者均继承 Research UNIX 的 root 与 rwx 基础模型
