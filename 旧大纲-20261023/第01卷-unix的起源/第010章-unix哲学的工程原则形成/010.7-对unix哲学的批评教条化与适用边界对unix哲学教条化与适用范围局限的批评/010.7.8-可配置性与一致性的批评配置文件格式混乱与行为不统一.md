# 010.7.8 可配置性与一致性的批评：配置文件格式混乱与行为不统一

**要点**：UNIX 系统缺乏统一的配置文件格式标准——各程序使用各自的格式（纯文本键值对、INI、XML、JSON、YAML、自定义脚本等），用户需要学习每种格式；命令行选项风格不统一——短选项（`-v`）、长选项（`--verbose`）、BSD 风格无横线选项（`ps aux`）、GNU 风格双横线选项并存，混乱不堪；环境变量与配置文件的优先级关系缺乏统一规范，不同程序处理方式不同；上述不一致性增加了用户的认知负担，也使配置管理（如 Ansible、Puppet）变得复杂

**史料**：getopt 历史（Aaron Cohen 约 1979 年编写 getopt 最初版本，AT&T 于 1985 年 UNIFORUM 会议首次公开发表，System III 1981 年发布时首次纳入 getopt 手册页与源代码 [考据脚注]）、GNU getopt_long 设计文档、X/Open Portability Guide 对命令行语法的规定、配置管理工具（Ansible/Puppet/Chef）的设计文档 ［A］

**史观**：总纲第 4 条——分离与聚合：配置格式的分离（各程序独立设计）导致多样性，但也缺乏聚合层面的统一标准

**辨析**：配置格式的多样性是“做一件事并做好”哲学的体现——每个程序选择最适合自己的格式，还是缺乏协调的混乱；GNU 项目与 BSD 项目在命令行风格上的差异是技术分歧还是文化差异；[考据脚注] getopt 起源、首次发布与 System III 纳入经多方独立来源交叉印证——(1) Aaron Cohen 约 1979 年编写 getopt 最初版本（TUHS 2024-03-04 邮件列表自述"Having written the first versions of **getopt(3)**, **getopt(1)**, and associated man pages around 1979"）；(2) AT&T 于 1985 年 UNIFORUM 会议首次公开发表 getopt 源代码（sources.debian.org getopt.c 注释"It is the code which was given out at the 1985 UNIFORUM conference in Dallas"、TUHS mod.sources 1985-12-04 邮件列表）；(3) System III（Unix 3.0，1981 年发布）首次纳入 getopt 手册页与源代码——Henry Spencer 1982-01-11 TUHS comp.sources.unix 帖文明确记载"written locally to match the description in a copy of the Unix 3.0 manual that I got to see once"，证明 Unix 3.0 手册已包含 getopt 描述；同时 AT&T 1985 年公开的 getopt.c 源码 SCCS 标识“3.0 SID # 9.2”进一步印证该源码首次提交于 Unix 3.0（即 System III）；早期表述“AT&T System III 引入 getopt”中 System III 是否为首个纳入 getopt 的 UNIX 发行版原本缺乏直接一手证据，现已通过 Henry Spencer 1982 帖文与 AT&T SCCS 标识两方独立来源印证后确认
