# 017.1.2 BSD 社区对 C++ 的接纳与抵制

**要点**：BSD 社区对 C++ 态度分化——用户态工具（如 KDE 早期、g++ 编译器）接纳，内核长期抵制，基本系统则呈现 “以实用为导向的有限接纳”；此分化体现工程实用主义；**FreeBSD 基本系统中实际存在的 C++ 组件**（经 freebsd-src 仓库 2026-07-28 核实）：**devd**（`sbin/devd`，设备守护进程，基于硬件存在与配置动态管理设备节点）、**zfsd**（`cddl/usr.sbin/zfsd`，ZFS 文件系统守护进程，处理元数据管理与 I/O 操作）、**fusefs 测试套件**（`tests/sys/fs/fusefs`，FUSE 文件系统测试，Alan Somers 在 freebsd-hackers 邮件列表 2024-01-20 002823 号邮件中说明 "Absolutely impossible to do in C. I considered Rust, but went with C++ so they could live in base"）；此三组件证明 FreeBSD 基本系统并非纯粹的 “无 C++ 区”，而是遵循 “内核禁用、用户态按需” 的分层策略

**史料**：freebsd-src 仓库 `sbin/devd/`、`cddl/usr.sbin/zfsd/`、`tests/sys/fs/fusefs/` 目录源码（github.com/freebsd/freebsd-src 核实，2026-07-28）；freebsd-hackers 邮件列表 2024-01-20 Alan Somers "The Case for Rust (in the base system)" 002823 号邮件（lists.freebsd.org/archives/freebsd-hackers/2024-January/002823.html，2026-07-28 WebFetch 核实）；BSD 邮件列表讨论；FreeBSD committer 文化文献 ［A］

**史观**：总纲第 4 条与第 25 条——分离聚合是永恒规律与逻辑是形式主义。项目史观总纲第 25 章载 “分离聚合是永恒规律”——BSD 社区内部对 C++ 进入基本系统的分化态度即分离聚合的具体呈现，ABI 稳定性、二进制大小、性能开销三重工程论证是 BSD 内核最小化原则与 C++ 形式主义膨胀（参第 1 章 1.5 节 “形式主义发展史”）之间的张力；总纲第 25 条 “逻辑是形式主义而非世界本身的结构” 提示 C++ 模板与异常机制的形式主义化设计并非 “客观缺陷” 而是事后归约；须自反：将 FreeBSD 基本系统描述为 “完全抵制 C++” 也是一种形式主义化的简化叙事，实际历史是按组件需求分层选择的结果

**辨析**：BSD 社区对 C++ 的态度须分层表述——(1) 内核层（`sys/`）严格禁用 C++，理由有三：ABI 稳定性（C++ ABI 在 GCC 3.2 至 4.x 间多次变更，内核模块需长期稳定）、二进制大小（C++ 模板实例化导致代码膨胀，与内核最小化原则冲突）、性能开销（异常处理与 RTTI 引入运行时开销，内核场景不可接受）；(2) 基本系统用户态层（`sbin/`、`usr.sbin/`、`tests/`）按需接纳 C++，典型案例为 devd、zfsd、fusefs 测试套件，此三组件选择 C++ 的共同动机为 “需要面向对象抽象但避免引入外部依赖”；(3) Ports 层完全开放 C++（g++/clang++ 均可用）；[考据脚注·FreeBSD 基本系统 C++ 组件的考据过程] 经三轮核实：其一，freebsd-src 仓库 GitHub 镜像（github.com/freebsd/freebsd-src）2026-07-28 WebFetch 核实 `sbin/devd/`、`cddl/usr.sbin/zfsd/`、`tests/sys/fs/fusefs/` 三个目录均存在 C++ 源文件（.cpp/.cc 后缀）；其二，freebsd-hackers 邮件列表 2024-01-20 Alan Somers "The Case for Rust (in the base system)" 邮件（lists.freebsd.org/archives/freebsd-hackers/2024-January/002823.html）明确列出此三组件为 "Currently C++"，并说明 fusefs 测试 "Absolutely impossible to do in C. I considered Rust, but went with C++ so they could live in base. They are too closely coupled to fusefs(5) to live out-of-tree."；其三，Warner Losh（沃纳·洛什）（imp）在同日 18:37:25 UTC 回复邮件（002830 号）中确认 devd 与 zfsd 为 C++ 组件，并建议以渐进方式引入 Rust 替代部分 C++ 组件；综上，FreeBSD 基本系统存在 C++ 组件一事经邮件列表一手档案与仓库源码双重印证
