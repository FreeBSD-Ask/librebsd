**要点**：

- Girish Venkatachalam 的路径：1999 年在班加罗尔 Novell 的第一份工作时安装 FreeBSD（所识第一个 BSD），此后在多种 Unix 间往复，约五六年前涉足 OpenBSD、四年前起坚定专守；2000 年前后对密码学的偏好与第四份工作（2002 至 2003 年间）被派往公司路由器的 Nucleus 实时操作系统实现 IPsec，构成其转向的技术契机。（BSDTalk EP180，[83.5-103.9]，L1）
- IPsec 代码考察的排序叙事：先读 Linux 内核的 IPsec 实现两三周而无进展、沮丧放弃；再看 FreeBSD 的 KAME 项目，对其 IPv6 与整体不满；最后看 OpenBSD，第一眼即折服于缩进风格、编程的严肃性、代码简洁与可循 RFC 标准阅读的品质，自述如一见钟情；遂决定把 OpenBSD 的 IPsec 实现移植到 Nucleus OS——BSD 许可证助益很大，但代码质量重于许可证。（BSDTalk EP180，[196.3-309.2]，L1）
- 首次贡献经历：2003 年修复 IPsec 内存泄漏的约三行补丁，因不知邮件列表存在而直接寄给 OpenBSD IPsec 实现作者 Angelos Keromytis，次晨发现补丁在下一分钟已被提交；其后在家联网时的 PPPoE 补丁亦于次日提交；社区对无名贡献者的接纳与尊重成为其情感归属的开端。〔存疑：PPPoE 代码作者姓名转写无法可靠复原〕（BSDTalk EP180，[347.4-422.0]，L1）
- 选择并留在 OpenBSD 的论据：在低端与旧机器上 Linux 中以 Debian 的硬件资源利用最佳、次为 FreeBSD，嵌入式或低端 PC 则首推 OpenBSD；极简主义与不向用户多问的取向、安装与包安装的简易；IPsec 工作使其完整理解 OpenBSD 内核与网络子系统，对比 FreeBSD 与 Linux 内核后确信代码质量、纪律与最小必需物取向是其长久根基；美与优雅遍布内核、用户态与 ports，言论自由与诚实的开发者文化带来内心的安宁。（BSDTalk EP180，[434.2-714.4]，L1）
- 商业化路径：以 OpenBSD 为唯一商业平台，理由即内核代码的技术质量本身；自任底层 C 程序员只做硬核产品（路由器、防火墙、垃圾控制），不拿定义不清之物赌市场名声；对客户直言别家商业产品基于 Linux 而其产品基于 OpenBSD，视之为天然优势。（BSDTalk EP180，[721.2-801.6]，L1）
- SpamCheetah 器件：在 OpenBSD spamd 之上加 web 界面的垃圾邮件过滤器，印度售硬件盒装、全球售 live CD，恪守只做一件事并做好的精神——仅做垃圾过滤、不干预用户邮件服务器选择；内容扫描方案须使过滤器成为邮件服务器的一部分，而 spamd 在网络层拦截。（BSDTalk EP180，[806.3-907.9]，L1）
- spamd 的技术论：OpenBSD spamd 及关联代码由 Bob Beck 开发，在网络层就地拦截垃圾邮件，与 SpamAssassin 等内容扫描路径——垃圾先进网、耗尽带宽与存储再事后反应——根本不同；邮件以线速流入且无假阳性之虞；他从不声称产品为自己所开发，只求推广 OpenBSD 之名，并已向 Google、Yahoo 等推介，产品在其两个客户现场运行良好。（BSDTalk EP180，[841.2-986.3]，L1）
- 印度市场与认知生态：客户不在乎底层（南印度最大珠宝展厅只求能用且指定 Linux 方案），价格敏感市场中开源的成本优势是关键；多数人知道 Linux 甚至不知 OpenBSD 存在，BSD 各分支常被混为一谈——他几周前向朋友明确澄清自己与 FreeBSD 无关；开源概念广为人知、贡献意愿真实（友人立志月底提交补丁）但受制于日常工作无暇；其 PPTP 工作因想做时无人评审、有评审时无时间的时间错位至今未进入基本系统。（BSDTalk EP180，[986.6-1204.5]，L1）
- 自由分享与商业的调和：所有产品将开源，器件模式本身即为自由分享知识与代码的精神服务；赚钱与慈善并行，若只为赚钱 OpenBSD 或非最佳选择；他惊讶于商业厂商仍不认真对待一个主动鼓励公司取用源码获益的社区；Live USB 为周末级项目、无财务动机，旨在让更多人熟悉 OpenBSD；并寄望印度涌现大量开源开发者、未来能在印度举办会议。（BSDTalk EP180，[1256.9-1341.0]，L1）

**史料**：

- 该期提及的一手线索包括：OpenBSD IPsec 实现（作者 Angelos Keromytis）与 2003 年内存泄漏补丁的提交记录；PPPoE 补丁；Bob Beck 的 spamd 及关联代码；www.spam-cheetah.com 器件产品与 live CD 版本；OpenBSD live USB 发行；其在 BSD Magazine 发表的 OpenBSD 垃圾控制特性文章；本地 BSD 与 Linux 用户组活动记录。（BSDTalk EP180，[363.6-371.2]，L1）

**史观**：

- 总纲第 9 条——经验优先：其全部论据皆出自亲手经历：逐个读码比较 IPsec 实现、低端机器上的资源利用观察、两个客户现场的 spamd 运行反馈——技术判断始终以第一手操作与阅读经验为准，而非阵营话语。（BSDTalk EP180，[626.9-657.7]，L1）
- 总纲第 10 条——动手者创造历史：其叙事中心始终是补丁、器件与客户现场——三行内存泄漏补丁与两个客户点的运行即构成其全部权威来源；他刻意把功劳归于 Bob Beck 与 OpenBSD 并自定位为推广者，凸显动手劳作而非头衔在社区声望体系中的位置。（BSDTalk EP180，[982.4-986.3]，L1）
