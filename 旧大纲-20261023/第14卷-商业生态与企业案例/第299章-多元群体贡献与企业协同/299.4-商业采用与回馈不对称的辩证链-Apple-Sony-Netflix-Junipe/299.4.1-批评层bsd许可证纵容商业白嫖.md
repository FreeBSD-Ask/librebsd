# 299.4.1 批评层：BSD 许可证纵容商业白嫖

**要点**：BSD 阵营对商业采用者的核心批评是——Apple Darwin/BSD 用户空间、Sony PS3/PS4/PS5 Orbis OS、Netflix Open Connect CDN、Juniper Junos、NetApp ONTAP 等大量商业产品基于 FreeBSD 代码但未对等回馈源代码；BSDL 仅要求保留版权声明与免责声明，不要求回馈源代码修改，与 GPLv2 的 copyleft 强制回馈形成根本对照；批评者据此主张 BSDL 在法律上“纵容”了商业白嫖，使 FreeBSD 社区承担代码散逸成本而未获对等商业回报

  商业采用者采用范围与回馈形态对照：

  | 采用者 | 采用的 FreeBSD 范围 | 核心商业逻辑是否开源 | 已知回馈 |
  | --- | --- | --- | --- |
  | Apple | Darwin/BSD 用户空间 | 否（iOS 用户空间、Darwin 仅部分开源） | Apple Darwin Source 部分开源 |
  | Sony | PS3/PS4/PS5 Orbis OS 固件 | 否（DRM、专有驱动） | 未发现 |
  | Netflix | Open Connect CDN 底层 | 否（推荐算法、内容分发调度） | RACK/TLP、KTLS 等网络栈优化回馈 freebsd-src 上游 |
  | Juniper | Junos 控制平面 | 否（转发平面为 Juniper 自研） | 工程师参与社区提交 patch |
  | NetApp | ONTAP 基底 | 否（WAFL 为 NetApp 专有） | 文件系统相关工作参与 |
  | WhatsApp | 服务器架构依赖 FreeBSD | 不适用 | Jan Koum（简·库姆） 2014-11 捐赠 $1,000,000 至 Foundation |

**史料**：BSD 许可证原文（1989、1990 修订版）、GPLv2 文本（1989）、Apple Darwin Source 发布页、Sony PS4 系统文档、Netflix Tech Blog、Juniper Junos 文档、NetApp ONTAP 文档；freebsd.duckdb〔原标注 openbsd.duckdb 系挂库讹误，数据本体为 freebsd-src 口径〕 查询 L3.2.1 显示商业实体 commit 占比 2005-2010 年间不足 1%，说明企业参与在 commit 层面是边际性而非主导性，但该统计基于 author_email 域名匹配，可能遗漏使用 @FreeBSD.org 或个人邮箱的企业开发者［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**史观**：总纲第 13 条——法律与道德是利益分配，BSDL 作为利益分配的法律形式

**辨析**：考据过程留痕——【查证来源】FreeBSD Handbook 官方“Who’s Using FreeBSD”页面（**<https://www.freebsd.org.cn（中文镜像站，非官方主站 freebsd.org）/freebsdhandbook/nutshell.html>** 与 **<https://docs.freebsd.org/en/books/handbook/introduction/>**，访问日期 2026-07-23）一手核验确认 Apple（“OS X 中大量借鉴了 FreeBSD 的网络协议栈，虚拟文件系统，以及许多用户层组件”）、Juniper（“JunOS 是驱动着所有 Juniper 网络设备的操作系统，它是基于 FreeBSD 的”）、NetApp（“Data ONTAP GX 存储设备是基于 FreeBSD 的”）、Netflix（“OpenConnect 是提供给 Netflix 用户的电影流媒体服务，它是基于 FreeBSD 的”）、Sony（“两个 PlayStation 3 和 PlayStation 4 游戏机运行在修改版的 FreeBSD 之上”）、WhatsApp（“当 WhatsApp 需要一个能够处理每个服务器超过 100 万并发的 TCP 连接时，它们选择了 FreeBSD”）六家商业采用事实；BSD 许可证原文（1989、1990 修订版）与 GPLv2 文本（1989）经 Open Source Initiative 许可证页一手核验；【交叉验证方法】FreeBSD Handbook 官方文档（一手）与 freebsd.duckdb 查询 L3.2.1（freebsd-src 仓库总 444067 commits 中，@netflix.com 邮箱 64 commits 占 0.0144%、@juniper.net 29 commits 占 0.0065%、@netapp.com 11 commits 占 0.0025%、@apple.com 6 commits 占 0.0014%、@sony.com 0 commits、@whatsapp.com 0 commits；2005-2010 年窗口内上述六域邮箱 commit 数均为 0）互证，确认商业实体在企业邮箱层面 commit 占比极低；但“商业产品基于 FreeBSD 代码且未开源核心商业逻辑”这一事实由 FreeBSD Handbook 官方列表与各企业文档互证成立；【存疑判定依据】“白嫖”一词是价值判断而非事实判断——BSDL 的设计意图明确允许商业使用不强制回馈，“纵容”与“允许”在许可证框架内是同义表述；0 信任原则提示：freebsd.duckdb L3.2.1 商业实体识别基于 author_email 域名匹配，可能遗漏受薪开发者（如 Watson/Baldwin 使用 @FreeBSD.org 邮箱而非企业邮箱），commit 占比偏低不能直接等同于“商业回馈稀薄”——Netflix 工程师 Jonathan T. Looney 使用 `jtl@FreeBSD.org` 邮箱在 freebsd-src 有 205 条 commit（2015-10-29 至 2026-01-27），Andrew Gallatin（安德鲁·加拉廷） 使用 `gallatin@FreeBSD.org` 邮箱有 759 条 commit（1999-01-18 至 2026-07-08），此二人经 freebsd.duckdb contributors 表核实为 Netflix 雇员但使用项目官方邮箱而非 @netflix.com，证实邮箱域名识别的局限，故“商业实体 commit 占比不足 1%”仅反映企业邮箱直接 commit 而非总体回馈规模
