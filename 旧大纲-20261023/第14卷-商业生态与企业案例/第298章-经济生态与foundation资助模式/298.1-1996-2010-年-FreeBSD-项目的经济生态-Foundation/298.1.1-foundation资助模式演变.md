# 298.1.1 Foundation 资助模式演变

**要点**：FreeBSD Foundation 2000 年 3 月在科罗拉多州注册成立（Justin Gibbs、Kirk McKusick 等），早期资金来自个人小额捐赠与企业赞助；2005 年起建立 staff developer 薪酬岗位（Robert Watson 等首批受薪开发者），资助模式从纯志愿转向“志愿 + 受薪 + 项目合同”的混合结构；2020 年后受 Netflix、Juniper、NetApp 等企业赞助影响显著

**史观**：专题语（不设总纲条号）：Foundation 的“轻治理”模式是否避免形式主义膨胀

**辨析**：Foundation 是否受大企业影响优先级——freebsd.duckdb freebsd-doc 仓库 2001-2006 年间的 Foundation 相关 commit 主要涉及法律实体建立（2001）、商标转让（2004）、企业捐赠（2005）、人员任命（2006）四类节点，未发现企业赞助直接干预技术优先级的 commit 证据，“轻治理”在 2001-2006 年间成立；与原大纲“早期资金来自个人小额捐赠与企业赞助”叙事一致；原大纲“2005 年起建立 staff developer 薪酬岗位”在 commit 中无直接命中——查询 freebsd-src 仓库 message_subject LIKE ‘%staff%’ 与 freebsd-doc 仓库 message_subject LIKE ’%contract%’（2004-2010）均无 staff/contract developer 主题 commit，说明该制度的内部讨论主要在邮件列表与 Foundation 内部文件而非 commit message 中；0 信任原则适用说明：author_email 字段可由提交者任意填写，但 @FreeBSD.org 官方 email 可信度较高；FreeBSD SVN-to-Git 2020 迁移可能引入 hash 重算，但 committer_date 与 author 信息在迁移前后应保持一致；contributors 表 commit_count 反映在 freebsd-src 仓库的总体活跃度，不直接证明“受薪”状态——Watson 与 Baldwin 在 2005 年前后活跃仅说明其持续贡献，“受薪”事实须依赖 Foundation 年度报告与邮件列表存档等非代码来源交叉验证；freebsd.duckdb 查询 L3.2.1 局限说明：商业实体识别基于 author_email 域名匹配（如 @netflix.com、@juniper.net、@netapp.com 等），可能遗漏使用个人邮箱（@gmail.com、@FreeBSD.org）的企业开发者——受薪开发者 Watson/Baldwin/Dawidek 均使用 @FreeBSD.org 邮箱而非企业邮箱，故 L3.2.1 统计无法捕捉其企业关联；commit_count 不等于商业贡献质量，企业 commit 可能集中于特定子系统（如 Netflix 网络栈、Juniper 路由）而非全仓。双库核查（2026-08-15）：参考文献库 ref_id=1049（FreeBSD Foundation Timeline PDF）确证 Foundation 2000 年成立与 2004 年商标转让；commit 记录 edef4307484a（Murray Stokely 2004-11-27）已在大纲中援引。邮件列表库无法验证。
