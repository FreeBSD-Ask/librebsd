# 093.0.1 要点

- 边缘贡献者的史料辨析须对照三类史料交叉验证——技术贡献（补丁、本地化）经 **bsd_commits.duckdb** commit 数统计、文化贡献（翻译、培训）经 BSD 本地化项目档案、组织贡献（大会、联络）经 BSD 大会与社区组织档案；不得仅依赖代码提交记录评估贡献
- 浪漫化叙事的批评——分裂时期部分叙事将三项目的文化差异浪漫化为标签（如 “FreeBSD 商业英雄”、“NetBSD 可移植精英”、“OpenBSD 安全独狼”），须对照具体史实剥离浪漫化成分，恢复被标签遮蔽的实际复杂性
- 选择性记忆的批评——部分叙事突出冲突事件（de Raadt 被逐、Jolitz 指控）而淡化协调事件（Core Team 内部协商、社区合作），须对照完整事件档案双向核实，不得以冲突线索替代完整图景
- 边缘传播者的叙事缺位——译者、培训者与会议组织者在主流叙事中被系统性低估，其贡献须经 BSD 邮件列表贡献记录、BSD 本地化项目档案、BSD 大会与社区组织档案交叉验证，不得仅依赖代码提交记录
- 批评的方法与边界——以一手史料（诉讼文书、邮件列表、提交记录）核对二手回顾叙事，明确区分叙事层与史料层；批评须自反，须区分有据叙事与浪漫化叙事，不得因存在浪漫化而否定全部文化差异叙事
