# 084.2.7 合图层：三足鼎立格局争议的辩证闭合

  **要点**：批评层（三项目分裂代价与协同失败）、反批评层（BSD 阵营的定位差异、技术多样性、许可证哲学辩护）、再回应层（批评方对反批评的再回应）构成辩证链的完整往复，但争议并未由此消解，反而在往复中显现其不可调和的结构性根源。合图层审视揭示：BSD 三项目的分立本质是社区资源分配与工程方向选择的具体行使，而非简单的“分裂代价”或“多样性价值”的伦理判断。FreeBSD、NetBSD、OpenBSD 三项目共享 4.4BSD-Lite 遗产，但走向不同方向——FreeBSD 聚焦于 features, speed, and stability，NetBSD 聚焦于 portability，OpenBSD 聚焦于 correctness, security, standardization, portability。三项目的定位差异是工程选择的偶然产物（呼应总纲第 5 条），各有其工程成就与负资产——FreeBSD 的性能优化使其成为服务器与嵌入式场景的主流选择，NetBSD 的可移植定位使其扩展至 50+ 平台，OpenBSD 的安全审计使其成为安全敏感场景的事实标准。三种定位皆是工程选择的具体行使，分立是偶然，分立的代价是结构性伴随物而非偶发缺陷。BSD 阵营与批评方对“三足鼎立格局”的解释受各自前理解支配而不可调和：批评方的前理解将“代码共享与协同效率”视为社区健康标准，故读出三项目分立是“分裂代价”；BSD 阵营的前理解将“工程自由与定位差异”视为社区使命，故读出三项目分立是“多样性价值”。前理解的不可调和性决定了辩证链不会以一方说服另一方终结，而以各方在各自前理解框架内自洽地解释而持续。合图层的审视在于：史家不应将 BSD 三项目分立写成“分裂失败”的单一叙事，亦不应将 BSD 阵营的“多样性价值”辩护写成“工程自由”的正当化叙事，而应揭示三项目分立是社区资源分配与工程方向选择的具体行使，争议的不可调和源于双方将工程选择道德化。争议的和解路径不在于“统一为单一项目”（此路径与 BSD 许可证哲学相悖），亦不在于“维持三项目完全独立”（此路径忽视协同治理的必要性），而在于“三项目在保持定位差异的前提下建立系统性的代码共享机制”——此路径的具体形式（如共享底层库、跨项目补丁回流协议）须由 BSD 社区在工程实践中探索，史家不预设答案。

| 辩证层 | 阵营 | 核心论点 | 关键证据 |
| ---- | -- | ------ | ------ |
| 批评层 | Linux 阵营与 BSD 内部反思 | 三项目分裂代价、协同失败、生态孤岛化 | 三项目主线合并记录、跨项目 committer 名单统计、BSDCan/AsiaBSDCon 议题对比 |

| 再回应层 | 批评方 | 定位不同不等于协同必要；技术多样性辩护回避核心问题；fork 代价不应由社区承担 | Linux 内核 driver/subsystem maintainer 体系；`pf`/OpenSSH 事后扩散 vs eBPF/cgroups 项目内扩散；三项目文档/邮件列表/治理结构三重分割 |
