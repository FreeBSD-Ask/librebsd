# 075.4.4 三路径的命运分化

  **要点**：Linux、FreeBSD、NetBSD、386BSD 四路径在 1993-2000 年间命运分化——Linux 商业资源汇聚，FreeBSD 聚焦 i386 与服务器市场，NetBSD 坚守多平台移植，386BSD 中断；分化决定后续竞争力格局。四路径分化对照如下：

| 项目 | 许可证 | 平台策略 | 商业绑定 | 后续命运 |
| -- | ---- | ------ | ------ | ------ |
| Linux | GPL | 单平台优先（i386） | 商业资源汇聚 | 商业胜出 |
| FreeBSD | BSD | i386 性能优先 | Walnut Creek CDROM | 服务器市场立足 |
| NetBSD | BSD | 多平台移植优先 | 较少 | 嵌入式与边缘平台 |
| 386BSD | BSD | 单平台 | 无 | 维护中断，用户分流 |

**史观**：组织结构塑造技术路径：四路径的命运分化是许可证、平台策略、商业绑定与社区治理的综合结果

**辨析**：命运分化的主因存在不同叙事——Linux 派归因于 GPL，BSD 派归因于商业绑定差异；需对照多项目交叉数据核实

### 史观映射

> “of course it runs NetBSD”——这句自嘲背后是一个严肃的立场：没有哪个平台天生比另一个更重要。在 NetBSD 的世界里，每块硬件都是一个等待被移植的平等主体。但这种平等是有代价的：当你的资源分散到数十个平台，每个平台都只能得到最少的关注。可移植的理想是一种对有限性的抵抗——人的精力有限，但 NetBSD 假装这种有限性不存在，结果是在每一个平台上都活着，但在每一个平台上都活得不够好
