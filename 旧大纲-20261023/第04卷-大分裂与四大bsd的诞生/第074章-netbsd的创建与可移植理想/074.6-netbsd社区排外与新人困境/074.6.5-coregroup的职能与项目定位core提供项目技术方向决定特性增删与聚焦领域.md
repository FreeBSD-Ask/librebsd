# 074.6.5 coregroup的职能与项目定位core提供项目技术方向决定特性增删与聚焦领域

- core group 的职能与项目定位：core 提供项目技术方向、决定特性增删与聚焦领域、裁决社区僵局争执、确定发布时机与内容，本质是技术项目管理，非技术事务另归独立董事会；NetBSD 的自我概括是“它当然能跑 NetBSD”——高度可移植的 BSD 系操作系统、无 GNU 许可顾虑，从 4 至 8MB 内存的小型嵌入式系统一直覆盖到 AMD64、Alpha、SPARC 大型服务器；全部架构共用一个集成源码树，无单独内核树或用户态树，各架构支持水平差异仅源于志愿工作量，项目几乎全靠志愿者、没有企业金主。（BSDTalk EP35，[76.8-232.72]，L1）
- 当事人的用途画像：本人主要将 NetBSD 用作嵌入式系统与复古计算——找不到操作系统的旧机器“过时了就跑 NetBSD”；桌面使用者虽存在但他本人用 OS X；嵌入式工作的优势在于源码树完全集成、易于裁去不需要的部分，且全 BSD 许可使企业无需担忧 GPL 义务；他所在公司的施乐复印机说明书即载明其内部使用 NetBSD。（BSDTalk EP35，[236.24-312.56]，L1）
- 3.x 与 4.x 的路线：3.0 系列引入 PAM、显著改进 AMD64 支持并以原生线程实现 pthread，同时 3.0 的维护性小版本即将开始；4.0 计划升级 GCC 与 binutils，并以 OS X 的内核授权机制为蓝本替换标准内核授权设施；当事人强调 NetBSD 没有 not-invented-here 的毛病，其他操作系统的好想法只要合理可用就会采纳。（BSDTalk EP35，[312.56-397.24]，L1）
- 平台持久性承诺：NetBSD 恪守继续支持厂商已放弃架构的传统，Apple 转向 Intel 后其旧 PowerPC 硬件仍将由 NetBSD 支持且当事人看不出停止的理由；NetBSD 历史上仅放弃过一个平台，原因是该 port 所面向的两颗处理器被物理销毁，此外所有被移植过的平台至今仍存在于源码树中。（BSDTalk EP35，[638.68-682.54]，L1）
- 桌面笔记本短板与 pkgsrc 广度：NetBSD 已有 ACPI 支持与辅助睡眠的电源守护进程但未达理想，SpeedStep 与增强型 SpeedStep 仍在改进；瓶颈在于 ACPI 实现数量庞大且普遍带有缺陷、须逐机型添加 quirk，耗时费力；pkgsrc 由 NetBSD 首创、是传统 BSD ports 之外的路径，现已支持 Solaris、Linux、HP-UX 等操作系统并包含 OS X，应用数量与 NetBSD ports 相当而目标广度更大——可能没有全部 port，但运行在比以往 BSD ports 更多的硬件目标上。（BSDTalk EP35，[682.54-790.66]，L1）
- 参与门槛与捐赠生态：当事人坦言 NetBSD 代码质量标准很高（自称此说听来精英主义），大量志愿工程师相当资深，外部贡献常达不到标准，新人须比其他项目获得更多指导，建议路径是认领未决缺陷、通过修缺陷学习代码并以既有代码为范本；NetBSD Foundation 为经认证的 501(c)(3) 非营利组织、捐款可抵税，主要用于改进构建与测试平台且总体开支不大；文档与网页改进建议受欢迎，硬件捐赠则视实用性——古怪的小型嵌入式板卡有人认领，需整机架的大家伙无人问津。（BSDTalk EP35，[797.74-969.98]，L1）
- Taylor R Campbell 在开场自陈身份：NetBSD 核心团队成员，社区行名为 riastradh，使用 NetBSD 约十五年、任开发者约十二年，工作横跨网络、文件系统、并发与图形等领域；其入坑动因系一段计算自主权个案——2007 至 2008 年前后 Apple 决定禁止在调试器下运行 iTunes，他视之为对自己计算机自主权的剥夺，强调通用计算机本可执行任意计算、运行何种软件应由用户而非厂商决定；恰逢 Apple 弃用 PowerPC，他为手头闲置的 PowerBook G4 寻找尊重用户自主且能从源码构建的系统，在考察 Linux 与多家 BSD 后认定唯 NetBSD 使从源码构建并掌控所运行内容变得真正容易，遂于 2008 年迁移。（YouTube EPgm-F3GnM8yM，[41.28-407.80]，L1） [订正：原[41.28-395.64]→[41.28-407.80]，内容复核——“遂于 2008 年迁移”的转写依据（首封邮件落款 June 5th 2008）位于（402.56-407.80），原范围未覆盖]
- 其新人历程由两个案例构成：一是安装后数周内在适配 stunnel TLS 隧道时复现一个内核级 bug——POSIX cmsg 辅助数据 API 的对齐判据疑似比较符写错，在严格对齐的 PowerPC 上出错而 x86 无碍，他循调用路径读内核源码并在 netbsd-users 邮件列表提出一行修复，数日内经 Christos Zoulas 提交入库，事后证明该修复并不完整、问题数年后才彻底解决，此事使从未做过内核编程的他确信自己可以参与开发；二是受此鼓舞后承接 Broadcom AirPort Extreme 驱动移植，以 OpenBSD 代码为底本、对照 FreeBSD 与 DragonFly 的实现，按编译、链接、运行的次序迭代数月至当年 9 月可用，其间依赖双机工作流——在 32 位 Intel MacBook 上交叉编译、经 FireWire Target Disk Mode 向 PowerBook G4 直送新内核，并评价 Broadcom 硬件与文档对开发者极不友好。 [存疑脚注] cmsg 对齐 bug 的比较符与分支细节系十五年后回忆，演讲人自认记忆不确，且修复非其一人完成，具体提交须以 2008 年邮件列表存档与 CVS 记录核验。（YouTube EPgm-F3GnM8yM，[402.55-845.52]，L1）
- 演讲主体系统演示 NetBSD 构建工作流：源码可经 CVS、git 或 Mercurial 检出，主库为 CVS，Mercurial 自动转换滞后数小时，官方明言近期将弃用 CVS 但尚未发生；build.sh 以 -O 收拢构建产物、-U 非特权构建（他主张本应为默认，1980 年代以来以 root 全程构建的传统今日观之并不妥当）、-u 增量更新、-m 指定架构、-N 与 -j 控制冗长与并行；release 目标一次产出交叉工具链、分发集、DESTDIR 阶段安装与各内核，且除非刻意配置，每次构建皆为交叉构建，从而把构建与宿主环境隔离、避免结构体定义失配；kernel=GENERIC 适用于多数端口，64 位 ARM 与 RISC-V 为 GENERIC64，evbppc、evbarm 等评估板端口按板裁剪内核，他以 Alpha、VAX 交叉构建与尚未完成的 PDP-10 移植玩笑展示架构覆盖之广。（YouTube EPgm-F3GnM8yM，[849.84-1247.24]，L1） [订正：原[849.84-1231.64]→[849.84-1247.24]，内容复核——“评估板端口按板裁剪内核”（kernel tailored to that one evaluation board）位于（1231.64-1239.80）、evbarm 提及位于（1242.20-1246.16），均在原范围之外]
- 调试与测试底座的演示覆盖一条完整工具链：以 QEMU virt 虚机（附 virtio RNG 熵源与网卡）引导 arm64 镜像，经 vnd 将普通文件暴露为块设备以便挂载根文件系统更新内核；借 netbsd.gdb 符号文件与 -s 选项以 GDB 观察活内核数据结构，build.sh -V MKCROSSGDB 可产出交叉 GDB，宿主非提权状态下甚至可直接调试本机内核；崩溃后由转储设备保存核心，crash(8)——内核调试器 DDB 的用户态版本——负责解读栈回溯，串口 hw.cnmagic 与 sysctl crashme 旋钮分别用于陷入调试器与强制 panic 验证转储可用性，另有关中断死循环的每 CPU 卡死检测；测试侧以 atf-run 接 atf-report 运行数千项自动测试，特权运行覆盖内核路径而免权运行跳过危险用例，输出含崩溃栈回溯与单行摘要，发布工程站点持续运行自动化测试供新架构 bring-up 参照；2023 年他的实况工作台为 ThinkPad 运行 -current 内核加 NetBSD 9 用户态 chroot，在该 chroot 中验证发往 NetBSD 8、9、10 分支的 pull-up（安全补丁与特性回移），单机无需虚拟机，彼时 NetBSD 10 发布候选在即，团队刚完成 OpenSSL 升级至 3 的迁移，他直言大版本迁移皆是痛苦、差别仅在痛苦的风味，并答问指出 LibreSSL 已弃 VAX 支持且无法交叉构建，而 OpenSSL 在 NetBSD 上仍可交叉构建至 VAX。 [存疑脚注] OpenSSL 在 VAX 上 Ed448 用例失败的归因（GCC 误编译抑或实现 bug）为演讲现场未经验证的猜想。（YouTube EPgm-F3GnM8yM，[1297.60-2342.16]，L1）
- 设备驱动部分以去神秘化为纲：驱动并非公众印象中的黑魔法，而是与倔强硬件打交道的普通程序，困难常在缺少数据手册时须对硬件本身做科学探究；autoconf 框架经 PCI 总线、设备树与 ACPI 枚举硬件，驱动以 softc 持有状态（其词源连讲解人也不知，现场戏拟为软件副本）、经 CFATTACH_DECL 历代宏声明（参数累加的产物，终将迁往 C99 指定初始化器），match 函数比对 PCI vendor/product ID 与设备树 compatible 并返回优先级，attach 分配缓冲、互斥与线程，detach 处理热拔（他援引自己 EuroBSDcon 2022 的 detach 专题演讲）；用户态界面经由字符设备——主设备号路由操作逻辑，cloning 设备按次打开分配独立状态，音频混音器与用于 USB 栈测试的 vhc 虚拟主机控制器为实例；硬件访问层 bus_space 以 tag 与 handle 封装 I/O 端口与内存映射寄存器窗口，BIT、BITS、SHIFTIN、SHIFTOUT 宏使驱动近乎直译数据手册（以 Rockchip 加密引擎 TRNG 控制寄存器为例），bus_dma 则免去 memcpy 并以 bounce buffer 抽象地址限制；rump 内核允许在用户态进程运行内核组件，VFS 测试在 chroot 内以 ATF 驱动并可挂 GDB，他自述借此完成 rename 系统调用一类棘手文件系统问题的调试。（YouTube EPgm-F3GnM8yM，[2486.79-3383.56]，L1）

**史料**：

- 当事人二十余年 BSD 履历的一手自述：80 年代早期在 Digital 从 4.2BSD 开始，该系统演化为 Ultrix 32 与 Ultrix，他参与将 Ultrix 移植到 MIPS 处理器，其后演化为仍基于 4.3BSD 的 DEC OSF/1 并延伸至 Alpha；在 Digital 面对公司各类网卡起意“为自由操作系统写驱动有多难”，遂以编写网卡驱动进入 BSD 世界，离开 Digital 后日益投入 NetBSD 并不断购置硬件；2001 年加入一家以 PowerPC 与 NetBSD 构建嵌入式系统的初创公司（20 颗 PPC、数 GB 内存的非典型嵌入式环境），因当时 PowerPC 支持不足而重写 PMAP 模块、重做大量中断代码，使 NetBSD 的 PowerPC 支持稳定成熟。（BSDTalk EP35，[473.8-637.68]，L1）
- 本期的核心一手史料包括：演讲人展示的其 2008 年 6 月 5 日首封 NetBSD 邮件列表邮件截图（自述安装文档复杂但按序执行顺利）、netbsd-users 列表上的修复提案与 Christos Zoulas 的提交、EuroBSDcon 2023 演讲幻灯片（经二维码分享）与现场问答、其对 EuroBSDcon 2022 detach 函数专题演讲的自引，以及 build.sh、GENERIC.local、nbmake 架构后缀封装脚本、ddb(4) 手册页等可复核的官方工程入口。 [已核脚注] 本期转写文件的两路分段交错重复缺陷经滚动重叠重建后已不复存在，现为单轨顺序转写；本卡片时间戳均取自原始 segment 可资追溯，但精确措辞引用前须比对原视频。（YouTube EPgm-F3GnM8yM，[402.55-423.08]，L1）[订正：原[存疑脚注]（“本期转写文件由两路分段交错重复而成，语序错乱”）→[已核脚注]，依 rev6 新转写单轨顺序（时间戳单调递增）可证缺陷已修复]

**史观**：

- 总纲10 动手者创造历史：全场以第一人称示范了动手者如何进入并留在系统开发之中：从邮件列表一行修复、Wi-Fi 驱动移植到文件系统调试，NetBSD 的技术史由具体提交、调试与文档迭代的动手行为续写，演讲本身即一位核心团队成员向后来者传授动手路径的现身说法，历史主体不是台前名人而是每日构建与测试的实践者。（YouTube EPgm-F3GnM8yM，[658.76-703.96]，L1）
- 总纲3 不存在进步，只有权力再分配：演讲人把 2007 至 2008 年 Apple 禁止在调试器下运行 iTunes 的决定理解为对用户计算机主权的剥夺，其出走并非宣称 NetBSD 技术更优，而是控制权归属之争——对通用计算机的支配从厂商手里移回用户手里；个人计算平台的迁移史在此呈现为用户与供应商之间权力关系的再分配，而非单纯的技术进步叙事。（YouTube EPgm-F3GnM8yM，[238.35-306.60]，L1）

**辨析**：

- 内核许可证纪律与 GPL 排斥的实例：NetBSD 内核几乎全部 BSD 许可，当前内核中已无非 BSD 许可内容；用户态则保留一批 GNU 工具，因为无处可得能运行于数十种架构的编译器；当事人举例称很想引入 SGI 为 Linux 编写的 XFS 支持，但该代码仅以 GPL 发布、与 BSD 许可不兼容而只得放弃，若有双许可本可两全；至于大公司只发 GPL 代码，要求其改用 BSD 许可意味着多付律师费做额外工作，并不现实。（BSDTalk EP35，[397.24-473.6]，L1）
