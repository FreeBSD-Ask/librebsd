# 078.0.1 要点

- IPFilter 许可证争议引发 OpenBSD 对全部依赖组件的许可证审计——审计结果导致多个组件被移除或重写；连锁反应强化 OpenBSD 对自由软件准则的严格执行
- OpenBSD 早期（1996-2003）技术淘汰具有“安全驱动而非商业驱动”的鲜明特征——淘汰决策主要基于安全论证而非市场份额或商业压力；这一特征使 OpenBSD 在 BSD 阵营中独树一帜，与 FreeBSD 的“兼容优先”形成对照；但需警惕将 OpenBSD 叙事为“安全原教旨主义”的回溯性建构——彼时 OpenBSD 的移除决策多基于具体工程权衡（如 telnetd 移除后 ssh 已成熟可用），而非抽象安全原则
- Sun Solaris 2.5（1995）是基于 SVR4 的 UNIX，运行于 SPARC 与 x86，面向企业服务器与工作站台；作为商业 UNIX，Solaris 拥有成熟的企业安全特性但无 OpenBSD 式的公开代码审计文化。OpenBSD 在 1995-1996 以 “开源 + 主动安全” 开辟了一个商业 UNIX 与 Linux 都未占据的细分市场。
- **辨析**：4.4BSD-Lite 替代 386BSD 作为 OpenBSD 直接基线的时间点须严格区分——NetBSD 1.0 rebase 至 4.4BSD-Lite 于 1994 年 10 月 26 日完成，早于 OpenBSD 1.0 fork（1995 年 10 月 18 日）约一年，故 OpenBSD 1.0 fork 时即直接基于 4.4BSD-Lite 而非 386BSD；securelevel 在 4.4BSD-Lite 中为概念雏形，OpenBSD 后续主动加固并演化为 **securelevel(7)** 手册页，与 FreeBSD 的 `kern.securelevel` sysctl 形成路径分化；OpenBSD 1.0/1.2 时期 securelevel 的实际启用状态需对照源码与 release notes 核实，概念雏形与默认启用为不同维度
  
- OpenBSD 1.2 在 BSD 社区引发关注——部分成员认可安全审计路径，部分成员质疑分叉的必要性；反响在 BSD 与 Linux 邮件列表持续讨论
