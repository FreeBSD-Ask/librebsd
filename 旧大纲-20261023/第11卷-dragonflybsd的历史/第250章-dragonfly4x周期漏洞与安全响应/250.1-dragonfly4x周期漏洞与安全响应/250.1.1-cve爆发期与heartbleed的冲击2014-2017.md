# 250.1.1 CVE 爆发期与 Heartbleed 的冲击（2014-2017）

**要点**：DragonFly 4.x 版本周期（2014-04-01 至 2017-08-01）**dragonfly.duckdb** dragonfly-src 仓库收录 30 条 CVE commit 与 5 条无 CVE 编号的 Security fix commit，去重 CVE 数达 78 条——是 DragonFly 各版本周期中 CVE 数量最多的一期，较 3.x 周期的 23 条增长 3.4 倍。4.x 周期 CVE 爆发的主要驱动是 2014-04 Heartbleed（**CVE-2014-0160**）后的 OpenSSL 漏洞群持续披露——78 条去重 CVE 中 OpenSSL 相关漏洞占 60 条以上。CVSS v3 评分分布如下：

| 评分等级 | CVE 数 | 代表 CVE |
|---|---|---|
| Medium（5.5） | 1 | CVE-2016-7056（LibreSSL） |
| 无 v3 评分 | 77 | 其余全部 CVE |
    4.x 周期是 DragonFly 首个有 CVSS v3 评分 CVE 的版本周期，反映 NVD 在 2014 年后开始为部分 CVE 提取 v3 评分。Heartbleed（**CVE-2014-0160**）于 **2014-04-07** 披露，DragonFly 在同日由 commit `8b433ce356b93ab0860f82b85543ae8895f55cab` 修复——此 commit 同时修复 CVE-2013-4353/6449/6450/2014-0076/2014-0160 五条 CVE，反映 OpenSSL 版本升级式修复的多 CVE 覆盖特征
**史料**：**dragonfly.duckdb** dragonfly-src 仓库 4.x 周期 CVE commit 30 条、Security fix commit 5 条、去重 CVE 78 条；commit `8b433ce356b93ab0860f82b85543ae8895f55cab`（2014-04-07 CVE-2013-4353/6449/6450/2014-0076/2014-0160）；原材料/研究/bsd 漏洞史/版本周期/dragonflybsd-4.x.md CVSS v3 评分分布表（Medium 1、无评分 77） ［A］

**史观**：专题语（不设条号）：DragonFly 4.x 周期 78 条去重 CVE 的爆发是依赖外部加密库（OpenSSL）的代价——DragonFly 在 4.x 周期延续“跟进上游 OpenSSL”策略，Heartbleed 后的 OpenSSL 漏洞群持续披露让 DragonFly 被迫在 3 年内处理 60 条以上 OpenSSL CVE，这一“外部漏洞驱动内部响应”的循环是依赖外部安全关键库的 BSD 项目的共同代价（原挂“总纲第 6 条——技术选择的代价”，基线第 6 条为“和解优于斗争”，主题对不上基线，按 R2140 先例改不设条号专题语——2026-09-12 整改）

**辨析**：4.x 周期 CVE 数量爆发的原因有二——其一，Heartbleed（2014-04）后 OpenSSL 经历大规模安全审计，大量历史漏洞被集中披露；其二，NVD 在 2014 年后逐步完善 CVE 编号与 CVSS v3 评分的覆盖；78 条去重 CVE 中仅 1 条有 CVSS v3 评分，写作中不臆造评分 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
