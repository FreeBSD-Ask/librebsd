# 241.1.4 Linux 2.6（2003）

**要点**：Linux 2.6（2003）在 DragonFly 1.x 同期以 O(1) 调度器、抢占式内核与良好 SMP 见长；与 DragonFly 1.x 的 LWKT 对照——Linux 2.6 的 SMP 经锁与抢占实现，DragonFly 1.x 探索消息传递，二者在 2003-2007 形成并发路线对照。

**史料**：Linux 2.6 发布说明（2003，含 2.6.0 Release Notes、O(1) 调度器文档、BKL 渐进移除记录）；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `03-原始史料库/01-代码仓库史料/05-DragonFlyBSD/db/duckdb/〔原引 01-数据库本体 路径断链，订正〕`，dragonfly-src 2003-2008 年 commit 演化）；DragonFly BSD 邮件列表存档（<https://www.dragonflybsd.org/mailinglists/>）；**DragonFly> BSD Release Notes（<https://www.dragonflybsd.org/releases/>）；**Dillon> fork 公告（<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>）；**HAMMER> 设计 PDF（<https://www.dragonflybsd.org/hammer/hammer.pdf>）**[三角验证：dragonfly.duckdb> + 邮件列表 + Release Notes 三类来源互参] ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律：Linux 2.6 的抢占/锁 SMP vs DragonFly LWKT 消息传递，是并发哲学差异。

**辨析**：Linux 2.6 的 SMP 成熟度高于早期 DragonFly 1.x，但后者探索不同路径。具体争议点：1) Linux 2.6 的 BKL（Big Kernel Lock）移除是渐进过程，2003-2008 年间仍保留大量 BKL 用法，完全移除延续至 2011 年后的 2.6.39 与 3.x 系列 [存疑脚注：Linux 2.6 BKL 移除的具体进度须以 LKML 与 Linux Kernel commit log 核验]；2) Linux 2.6 O(1) 调度器与 DragonFly LWKT 调度器的对比须以同硬件同负载基准测试核验，二者目标不同（Linux 通用 SMP vs DragonFly 消息传递并行）。0 信任原则应用维度：跨项目比较须控制硬件/负载/版本混淆变量、“成熟度” 判定须以部署规模与生态而非单一技术指标衡量。考据记录归档至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8n 节。
