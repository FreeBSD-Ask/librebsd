**史料**：freebsd.duckdb dragonfly-src/netbsd-src/openbsd-src/freebsd-src 仓库 commits 表（按年统计对照）；OpenBSD Foundation 年报（openbsdfoundation.org/）；NetBSD Foundation 年报（netbsd.org/foundation/）；DragonFly 无独立 Foundation 法律实体（dragonflybsd.org/foundation/ 页面 404）；**统计结论 C-06**——描述性统计.md SubTask 2.1 显示 dragonfly-src 全时段 49,280 commits、freebsd-src 444,203 commits、openbsd-src 245,904 commits、netbsd-src 211,446 commits；**统计结论 E-24**——外部基准-Academic-CVE.md 第 2 节显示 NVD DragonFly BSD CVE 仅 1 个、FreeBSD 421、OpenBSD 168、NetBSD 136〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：技术路线分化决定社区规模：DragonFly 选择 LWKT 消息传递 + HAMMER/HAMMER2 + vkernel 路线，该组合在 2003-2010 年代未获业界主流采纳（Linux/FreeBSD/Solaris 均选择细粒度锁 + ZFS/ext4 + KVM/bhyve 路线），导致 DragonFly 缺乏细分市场支撑——对比 OpenBSD 的“安全细分市场”与 NetBSD 的“跨平台细分市场”，DragonFly 的“消息传递 + 个人主导文件系统”细分市场过窄，社区规模随之萎缩；统计结论 C-06 印证——dragonfly-src 全时段 49,280 commits 仅为 freebsd-src 的约 11.1%，反映 fork 后 DragonFly 工程规模远小于 FreeBSD 主线，工程动员能力的差距是社区规模分化的量化显现；统计结论 E-24 印证——DragonFly CVE 仅 1 个（占 BSD 4 项目合计 0.14%）与 FreeBSD 421 个（57.8%）的悬殊差距既反映用户基数差异，也反映 DragonFly 无独立 VSA 公告系列的披露机制缺位，安全响应制度化缺位是社区规模萎缩的伴随效应

**辨析**：比较采用同一 dragonfly.duckdb 数据库四仓库同口径年度 commit 量统计，避免跨数据库口径差异；DragonFly 2024 年 commit 谷值 277 条与 OpenBSD 同期 5097 条的差距不仅反映社区规模，也反映项目目标差异——OpenBSD 每年 6 个月固定发布周期（5 月、11 月）强制 commit 节奏，DragonFly 无固定发布周期，commit 节奏由 Dillon 个人精力决定；【统计显著 ≠ 实际显著·E-24 局限】NVD CVE 数量不等于实际漏洞数量——DragonFly CVE 仅 1 个不意味着 DragonFly 仅有 1 个安全漏洞，可能反映 NVD CPE 命名不完整、DragonFly 无独立 VSA 公告系列导致的披露不足、用户基数小导致的漏洞报告稀少等多重因素；【用户基数与 CVE 披露的正相关】CVE 披露与用户基数正相关，DragonFly 用户基数小导致 CVE 报告稀少，但这一统计事实不否定 DragonFly 可能存在未披露漏洞；【C-06 全时段 commit 总量的局限】C-06 反映全时段 commit 总量但未控制时间窗口差异——dragonfly-src 仓库始于 2003-06（fork 后），而 freebsd-src 仓库始于 1993-01（CSRG 时期），时间窗口差异（dragonfly-src 23 年 vs freebsd-src 33 年）是 commit 总量差距的部分原因，须以年均 commit 量对照核验；【多重比较风险】C-06 与 E-24 同源 dragonfly.duckdb dragonfly-src 仓库与 NVD 数据库，跨数据库关联须警惕选择性偏差
