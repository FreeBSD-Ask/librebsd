# 237.1.5 对BSD不受CVE20157547影响的结论须分层限定FreeBSDlibc与g

- 对 BSD 不受 CVE-2015-7547 影响的结论须分层限定：FreeBSD libc 与 glibc 解析器同源，但缺陷源于 glibc 重写后并行发出 A/AAAA 查询时的缓冲区管理失误，BSD 系仍串行查询故不涉险；可一旦经 Linux 仿真层安装 linux_base-c6 之类依赖，易感 glibc 即随之进入系统；再叠加 Red Hat 指明的 nss_dns 模块条件与 musl 等其他 libc 的差异，风险归属取决于 libc 具体实现与安装路径，而非操作系统阵营标签。（BSD Now EP129，[253.2-312.2]，L3）[订正：原 [259.76-311.34]，2026-09-30 SenseAudio 重转核对]
- 关于把 Ada 前端移植到 LLVM 的可行性：受访者认为 GNAT 前端技术上可嫁接，但中端须重写，且即便完成也无法摆脱源自 GPL 的许可约束，故工作量与收益严重不成比例；这一判断与 DragonFly 计划以 clang 3.8 取代旧 GCC 的路线互为表里，凸显许可证与维护成本共同塑造编译器版图。 [存疑脚注] 移植可行性与许可约束判断仅为受访者单一来源推断，未经实现验证或第三方评审。（BSD Now EP129，[2869.1-2949.2]，L4）[订正：原 [2894.30-2947.78]，2026-09-30 SenseAudio 重转核对]
- 受访者转述 Bryan Cantrill 以“十二岁偷车贼终会长成”讽刺对 btrfs 以年轻为数据丢失开脱的辩护，对照 ZFS 建造目标自始不丢数据的自我叙事——此为利益相关方的单方修辞，折射写时复制文件系统两大阵营的价值分歧，可信度受转述链条限制，不可径作事实采信，宜与 btrfs 社区自述对勘。 [存疑脚注] 转写人名失真（Brian Cantrell 应为 Bryan Cantrill），系依语境恢复，btrfs 新转写已拼写正确；比喻细节为单方转述（BSD Now EP90，[2211.32-2247.56]，L2）[订正：原 失真清单含 butterfs，2026-09-30 SenseAudio 重转核对]
- ZFS on Linux 因 CDDL 与内核许可不兼容而不入主线，访谈以 Ubuntu 编解码器与 FreeBSD ports 树的禁止再分发标志作类比——代码可入仓库只是不能进安装介质，揭示许可证塑造的是分发渠道而非技术存在性，用户实际以自行引导安装与内核模块重编译的方式绕行。（BSD Now EP90，[2082.66-2121.54]，L2）
- 六 TB 外置盘“缩水”的新手困惑由 UFS 默认为 root 保留约 8% 空间以防 syslog 被普通用户写满的设计余量，与十进制二进制换算差异叠加而成——1990 年代的磁盘安全设计在 2015 年仍是理解 BSD 文件系统行为的入口，旧机制的解释成本随存储规模放大而重新显形。 [存疑脚注] 转写称保留比例为“6% 或 9%”，与 UFS minfree 默认 8% 的通说不符，数值依 tunefs(8) 语境恢复，待核（BSD Now EP90，[4169.82-4267.68]，L2）
- 演讲者批评 BSD 用户态代码保留上世纪 C 语言惯例：函数首部集中声明、return 加括号、void 空参数表，并以 1991 年以来少有改动的 dump 为例指出手工缓冲索引易致越界错误；他主张内核作为最后防线应尽量启用语言机制防错，同时承认这些代码经大量人力审读、存量缺陷已被清理，审查文化与现代语言防御之间的张力构成其论证核心。（YouTube EPPxeiGB3q17M，[1257.39-2252.51]，L1）[订正：原“ls”→“dump”，新转写 1826.5-1898.5 段明示该 1991 年小工具为 dump 且自述“calculate index for dump”] [订正：原 [1257.39-1294.5] 仅覆盖 return/void 段→扩至 [1257.39-2252.51]，以并含函数首部集中声明段（2154.16-2169.52）、1991 年 dump 手工缓冲索引越界段（1824.62-1917.02）与内核最后防线/语言机制防错段（2207.92-2252.51），内容复核]
