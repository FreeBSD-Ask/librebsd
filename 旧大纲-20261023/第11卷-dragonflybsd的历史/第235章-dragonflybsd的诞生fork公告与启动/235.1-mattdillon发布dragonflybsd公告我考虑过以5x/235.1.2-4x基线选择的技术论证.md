# 235.1.2 4.x 基线选择的技术论证

**要点**：Dillon 在 2003.7.16 公告原文中明确表述 “it is simply too heavily mutexed”——指 FreeBSD 5.x SMPng 细粒度互斥锁在 2002-2003 年代主流双路/四路 SMP 服务器硬件上反而因锁竞争降低单线程性能。4.x 的 BGL（Giant Lock）虽粗粒度但可逐步优化，Dillon 选择 4.8-RELEASE 作为基线即 “以退为进”。dragonfly.duckdb 显示 fork 首 commit `984263bcb83a`（2003-06-17T02:57:24Z）标题 “Initial import from FreeBSD RELENG_4” 证实基线选择——Dillon 从 FreeBSD 4.x 而非 5.x 分叉
    > it is simply too heavily mutexed — Matt Dillon，2003-07-16 fork 公告，论 FreeBSD 5.x SMPng 的 mutex 路线
**史料**：Dillon 2003.7.16 公告原文中 mutex 论述段（lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html）；FreeBSD 5.0 SMPng 设计文档（Baldwin J. “FreeBSD SMPng Implementation” 2002，freebsd.org/platforms/smp.html）；dragonfly.duckdb dragonfly-src 仓库 commits 表 commit_hash = 984263bcb83a（author_date = 2003-06-17T02:57:24Z, message_subject = “Initial import from FreeBSD RELENG_4”）；Dillon 在 dragonfly.kernel 邮件列表 2003-2005 年关于 BGL 优化路径的发言

**史观**：硬件与软件辩证：2002-2003 年代 SMP 硬件普及推动 FreeBSD 5.x 锁机制重构（SMPng），但软件重构速度滞后于硬件演进——SMPng 在双路/四路硬件上的锁竞争反降性能，Dillon 选择 4.x BGL 起步后逐步优化的路径即 “软件重构速度须匹配硬件演进速度” 的具体显现

**辨析**：4.x 基线是否更优的判断须以 2003 年硬件语境为准——DragonFly 后续在 LWKT 框架内引入细粒度锁（如 2003-06-20 LWKT 首引 commit `8ad65e080342` 即已采用 per-CPU 数据结构规避全局锁），并非退回 SMPng 路线，而是以消息传递 + LWKT 子系统替代锁粒度优化路径；LWKT 首引 commit 的 author_date 须经 dragonfly.duckdb 与 DragonFly 邮件列表交叉核验 [存疑脚注：LWKT 首引 commit `8ad65e080342` 的 author_date 2003-06-20T02:09:59Z 须经 dragonfly.duckdb commits 表与 DragonFly kernel@ 邮件列表时间戳交叉核验，本轮考据未联网核验]。0 信任原则应用维度：author 字段可伪造（Dillon 作为 commit 作者须与 committer 字段交叉验证）、tagger_date 与实际发布日期可能偏差（fork 首 commit 无 tag，须以 author_date 为准）、关键词匹配局限（LWKT 关键词搜索可能遗漏以 token/message 为关键词的 commit，须以 commit_files 表 sys/kern/lwkt/ 路径核验）。考据留痕至 `03-原始史料库/06-考据记录/20260730_jianyi缺口补全考据.md` 8an 节
