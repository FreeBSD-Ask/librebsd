# 251.7.4 Linux 5.x（btrfs/ZFS，2018-2020）

**要点**：Linux 5.x（2018-2020）在 DragonFly 5.x 同期以 ext4/btrfs 为主流文件系统，ZFS 经 OpenZFS-on-Linux 树外提供（因 CDDL 许可证冲突无法合入主线）。Linux 内核主线同期 commit 规模远超 BSD 各项目〔存疑：linux-stable 仅含 stable 分支，主线量化口径未复核〕。与 DragonFly 5.x 的 HAMMER2 对照——btrfs 与 HAMMER2 同为 CoW 实验且均曾有稳定性争议，Linux 5.x 的 ZFS 树外与 BSD 基树整合对照

**史料**：Linux 5.x 文件系统文档（kernel.org/doc/html/latest/filesystems/）；OpenZFS-on-Linux 项目（github.com/openzfs/zfs）；DragonFly 5.x HAMMER2 文档〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 4 条——分离聚合是永恒规律：Linux 5.x 的 ZFS 树外提供（因 CDDL 许可证冲突）与 BSD 基树整合形成对照——FreeBSD/NetBSD 直接整合 OpenZFS 至基树，Linux 因许可证冲突无法整合；总纲第 13 条——法律与道德是利益分配：CDDL vs GPL 许可证冲突是 Linux ZFS 树外提供的法律根源，反映许可证利益分配对技术整合的约束

**辨析**：CoW FS 的稳定性是共性工程难题，HAMMER2 与 btrfs 各有取舍；Linux 5.x 的 ZFS 树外提供使 ZFS 在 Linux 上无法随内核启动，须额外配置 initramfs；linux-stable 仓库仅含 stable 分支，主线 commit 量须以 git.kernel.org 核验
