# 244.2.1 CVE 引用增长与独立安全响应能力的建立（2007-2011）

**要点**：DragonFly 2.x 版本周期（2007-02-01 至 2011-03-01）dragonfly.duckdb dragonfly-src 仓库收录 41 条 CVE commit 与 13 条无 CVE 编号的 Security fix commit，去重 CVE 数达 25 条——较 1.x 周期的 5 条去重 CVE 大幅增长，反映 DragonFly 在 fork 四年后建立起独立的 CVE 编号引用习惯与安全响应能力；2.x 周期 commit message 中 CVE 编号引用成为主流，例如 2007-03-16 Sepherosa Ziehau commit `c73157f11b4f21cc3f08e9cdc1825be9dfbccfae`：
    > Add a fix for CVE-2007-1218
    FreeBSD SA 跟进式引用退居次要——2007-03-23 Victor Balada Diaz commit `5bb4d25cdb6e9ae2dfc288e4bf87bd99a6528755` 仍标注：
    > Import security fix for CVE-2007-0493 and CVE-2007-0494 from FreeBSD.
    说明 DragonFly 2.x 时期安全响应呈现 “CVE 直引为主、FreeBSD SA 跟进为辅” 的过渡特征；25 条去重 CVE 全部无 CVSS v3 评分，NVD 未为其提取 v3 评分

**史观**：总纲第 4 条——分离聚合是永恒规律：DragonFly 2.x 时期 CVE 引用习惯的建立是 “分离后聚合” 的体现——代码层面与 FreeBSD 分离，但安全响应层面仍部分聚合至 FreeBSD SA 体系（如 CVE-2007-0493/0494 经 FreeBSD 跟进），同时开始独立聚合至 CVE 编号体系，反映 fork 项目安全响应能力的成熟化路径
