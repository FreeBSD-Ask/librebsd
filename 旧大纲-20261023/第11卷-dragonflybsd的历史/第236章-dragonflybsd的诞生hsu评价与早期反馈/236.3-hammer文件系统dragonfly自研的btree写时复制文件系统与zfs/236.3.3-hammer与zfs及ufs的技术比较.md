# 236.3.3 HAMMER 与 ZFS 及 UFS 的技术比较

**要点**：HAMMER 在功能上介于 UFS 与 ZFS 之间——提供快照与历史记录（B-tree + COW）但无 ZFS 的池化与去重；单节点设计 vs ZFS 池化设计，更适合 DragonFly 的小规模部署。dragonfly.duckdb 显示 HAMMER 首引（2007-10-10）早于 OpenZFS 移植至 FreeBSD（FreeBSD 13.0-RELEASE 默认 OpenZFS，2021-04-13），反映两项目文件系统路线分化

**史料**：dragonfly.duckdb dragonfly-src 仓库 commits 表 HAMMER 首引 = 2007-10-10；freebsd.duckdb freebsd-src 仓库 commits 表 OpenZFS 移植 commit（FreeBSD 13.0-RELEASE 2021-04-13）；HAMMER 与 ZFS 技术对比文档（DragonFly wiki）；DragonFly 与 FreeBSD 性能测试报告（Phoronix 2008-2015 年基准测试）〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 4 条——分离聚合是永恒规律〔存疑：原挂“第 6 条技术路线分化”系伪标签，按权威 25 条表重挂〕：HAMMER 与 ZFS 代表不同的文件系统路线——HAMMER 选择 “单节点 + B-tree + COW + 低内存” 路线，ZFS 选择 “池化 + ARC + 高内存” 路线，两条路线在 2007-2026 年间并行发展，dragonfly.duckdb 显示 HAMMER 由 Dillon 一人主导（首引 commit 8750964d1997），ZFS 由 Sun/Oracle 团队主导后经 OpenZFS 社区维护

**辨析**：性能比较结果因测试方法不同而差异显著——Phoronix 2008-2015 年基准测试显示 HAMMER 在单盘随机读场景下性能优于 ZFS（低内存优势），在多盘 RAID-Z 场景下 ZFS 优于 HAMMER（池化优势）；正式撰写时须引用具体测试配置（CPU、内存、磁盘、文件系统版本）
