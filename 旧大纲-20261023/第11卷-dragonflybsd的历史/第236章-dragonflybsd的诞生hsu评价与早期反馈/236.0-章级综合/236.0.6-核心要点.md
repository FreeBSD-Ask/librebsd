# 236.0.6 核心要点

**要点**：DragonFly BSD 由 Matthew Dillon 自 FreeBSD 4.x 系分叉创立（2003 年，选择 4.x 而非 5.x 的核心论据是 SMPng 路线过度复杂）；Dillon 1998-08-26 起活跃于 FreeBSD 提交（contributors 表实证 1,027 commits），2003-02-03 提交权限被 FreeBSD Core Team 撤销（Greg Lehey 日记与库内末次 commit 2003-01-28 双源）——技术实力过硬但不擅团队合作（215.2/215.8）；Jeffrey Hsu 等早期开发者与社区对 fork 的评价两极（215.1）；DragonFly 自研 HAMMER（B-tree 写时复制）文件系统与 ZFS 形成技术路线对照（215.3），许可证延续 BSD 系（215.4）；fork 二十年后的 2023-11-19，Dillon 坦承“大多数较新的网络驱动尚未从 FreeBSD 移植”，API 分歧已累积至难以简单合并（见 MAIL_INSIGHT）。

**史料**：freebsd.duckdb contributors 表（Dillon first_commit 1998-08-26、1,027 commits）与末次 commit 记录（2003-01-28）；Greg Lehey 日记 2003-02-03；dragonfly.duckdb dragonfly-src commits 表；dragonfly-users 邮件列表 Dillon 2023-11-19 邮件（Message-ID 锚点）；MAIL_MINE hsu 关键词命中 257 封（2003-2019）

**史观**：总纲第 5 条——没有必然性，只有偶然性：DragonFly 的诞生系 Dillon 与 Core Team 治理冲突、SMPng 技术判断分歧等偶然事件链的产物，并非 BSD 版图演化的必然环节（与 215.7 节呼应）；总纲第 3 条——不存在进步，只有权力再分配：提交权限的授予与撤销、fork 与反 fork 的争论是贡献者与治理机构之间权力再分配的呈现；总纲第 4 条——分离聚合是永恒规律：DragonFly 从 FreeBSD 分离，而 ports/用户态工具与人才流动仍维持聚合面（Dillon 2023 年邮件所言的 API 分歧正是分离深化的量化注脚）

**辨析**：“fork 即决裂”的叙事须辨析——DragonFly 长期沿用 FreeBSD 许可证与部分用户态（215.4），分离主要发生在内核调度与 VM 层；Hsu 评价、BSD 分裂讽刺段子（215.5）等史料多属当事人立场与社区幽默，引用时须区分事实陈述与修辞性表达；数据库统计受镜像与口径影响存在偏差。自反性声明：本节五字段系 2026-09-12 章级核查整改补写，提炼自 215.1-215.8 各节与自动增补块，属形式主义化重构，欢迎被更诚实的叙事所超越（总纲第 23 条）
