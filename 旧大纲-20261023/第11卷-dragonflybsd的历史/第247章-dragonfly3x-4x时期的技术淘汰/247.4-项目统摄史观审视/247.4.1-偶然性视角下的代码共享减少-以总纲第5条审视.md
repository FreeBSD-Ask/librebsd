# 247.4.1 偶然性视角下的代码共享减少——以总纲第 5 条审视

**要点**：DragonFly 与 FreeBSD 代码共享减少的历史偶然性体现于多个具体环节——dragonfly.duckdb 显示 MFC commit 量按年序列为 6/34/37/34/18，2011 年仅 6 条反映 v3.x 系列初期 DragonFly 与 FreeBSD 代码共享已接近“几乎独立”状态，但 2012 年骤增至 34 条与 2013 年峰值 37 条反映代码共享的非线性演化——2012 年的骤增可能与 v3.2.0（2012-08-20）与 v3.4.0（2013-04-29）时期 DragonFly 从 FreeBSD 移植驱动程序的偶然高峰相关，2013 年的峰值 37 条可能与 v3.6.0（2013-11-25）时期的多核调度改进或 LWKT 改进相关，但 2014 年回落至 34 条与 2015 年降至 18 条反映代码共享减少的整体趋势——若 DragonFly 未在 v3.x-v4.x 时期持续独立维护 HAMMER2/LWKT/vkernel 等核心子系统，若 FreeBSD 9.x/10.x 的细粒度锁与 NUMA 支持的技术路线分化未使 DragonFly 难以移植，若 Dillon 未在 2012 年达 commit 量峰值 567 条（反映其 HAMMER2 开发活跃度的偶然高峰），代码共享减少的具体形态将根本不同；代码共享减少是 fork 关系自然演化的预期结果，但 MFC commit 量波动的具体形态（2011 = 6、2012 = 34、2013 = 37、2014 = 34、2015 = 18）具有偶然性——dragonfly.duckdb 提供的时间戳数据可精确还原这些偶然性节点的时序，但偶然性本身不否定代码共享减少的整体趋势（分离加剧）

**史观**：总纲第 5 条——偶然性改写历史：代码共享减少的历史偶然性体现于 MFC commit 量波动的具体形态（2011 = 6、2012 = 34、2013 = 37、2014 = 34、2015 = 18）、DragonFly v3.x-v4.x 时期各版本 release 时点、Dillon 2012 年 commit 峰值等多个环节——dragonfly.duckdb 提供的时间戳数据可精确还原这些偶然性节点的时序，但偶然性本身不否定代码共享减少的整体趋势（分离加剧）；偶然性与必然性的辩证关系须以多元因果框架审视——单一偶然事件（如 2013 年 MFC commit 峰值 37 条）不构成代码共享减少的因果链条，但多个偶然事件的累积（HAMMER2 自研 + LWKT 路线分化 + FreeBSD 技术路线分化）形成代码共享减少的因果网络
