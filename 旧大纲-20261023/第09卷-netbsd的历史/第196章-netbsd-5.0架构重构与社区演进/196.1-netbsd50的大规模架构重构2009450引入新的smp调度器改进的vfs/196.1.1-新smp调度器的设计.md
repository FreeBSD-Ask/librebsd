# 196.1.1 新 SMP 调度器的设计

  **netbsd-src 仓库 2007-2009 年度 commit 量与 SMP 相关 commit 量统计**：

  | 年份 | 年度 commit_count | SMP 相关 commit | 备注 |

**要点**：NetBSD 5.0（**2009.4.29**）引入由 Andrew Doran（安德鲁·多兰） 设计的新 SMP 调度器，采用每 CPU 运行队列与工作窃取算法，取代 4.x 的全局锁机制；新调度器支持多核负载均衡与优先级继承，使 NetBSD 在 4 核至 32 核机器上获得显著性能提升

**史料**：NetBSD 5.0 Release Notes；Andrew Doran 在 tech-kern 邮件列表的设计说明帖；CVS commit 日志；NetBSD Foundation 2008-2009 年度报告；netbsd.duckdb netbsd-src 仓库 branches 表验证（netbsd-src 无 release tag，branches 表 commit_date 为分支最后更新时间非发布时间）：origin/netbsd-5-0 branch commit_date = 2014-12-25T23:54:07Z（commit f0717457fc3b，远晚于 5.0 发布 2009.4.29 约 5 年 8 个月，属分支末次维护更新时间，非发布时间）；netbsd.duckdb netbsd-src 仓库 commits 表 ad（Andrew Doran）活动验证：ad 在 2007-2009 年间持续提交 SMP 相关 commit（如 2007-12-24 “MOUNT_ZFS, VT_ZFS” 等基础工作），与 “5.0 引入 Andrew Doran 新 SMP 调度器” 叙事在时序上吻合；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2009 年 commit_count = 26,690（5.0 发布年），2008 年 = 26,543，2009 年较 2008 年微增 0.6%，反映 5.0 发布年开发活跃度保持稳定；netbsd.duckdb 查询 L2.3.1.smp 显示：netbsd-src 2009 年 SMP 相关 commit = 24（5.0 发布年），2008 年 = 24，2007 年 = 38（4.0 发布年峰值），反映 5.0 的新 SMP 调度器开发集中在 2007-2008 年（4.0 周期），2009 年发布时已进入收尾阶段；统计结论 [C-04]: netbsd-src 仓库总 commit 数 773,683（截至 2026-07-27 查询），为 4 大 BSD src 仓库中 commit 累计最高者，本章时期（2005-2009）的 commit 活动构成此总量的中段；统计结论 [C-09]: netbsd-src 月度 commit 量 Mann-Kendall 趋势检验呈显著下降趋势（Sen's slope=−7.27/月，p<0.001，95% CI [−8.15, −6.42]），本章时期（2005-2009）处于该长期下降趋势的中段，2005 年 30,344→2009 年 26,690 的年度降幅与全期下降趋势吻合，反映 5.0 架构重构期主仓开发活跃度的结构性收敛 ［A］

**史观**：总纲第 5 条——组织结构塑造技术路径：NetBSD Core 选择 Doran 的 “渐进式改造” 路径而非 FreeBSD ULE 的 “重构式” 路径，反映出 NetBSD 社区保守稳健的工程文化

**辨析**：Doran 新调度器与 FreeBSD Jeff Roberson 的 ULE 2.0（2007.5 引入 FreeBSD 7.0）的关系存在叙事分歧——Doran 在邮件列表中提及参考 ULE 但强调独立性，需对照源码 diff 核验；新调度器的性能基准数据在第三方测试中差异较大，需查 Phoronix/BSD Insights 等早期基准。经 netbsd.duckdb netbsd-src 仓库 branches 表验证：origin/netbsd-5-0 branch commit_date = 2014-12-25T23:54:07Z 远晚于 5.0 发布 2009.4.29（约 5 年 8 个月），印证 branches 表 commit_date 是分支最后更新时间而非版本发布时间，5.0 发布日期仍须以 NetBSD 官方公告为准；ad（Andrew Doran）在 2007-2009 年间的 commit 活动与 “5.0 引入新 SMP 调度器” 叙事时序吻合。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2009 年 commit 量可能不完整；L2.3.1.smp 查询基于 message_subject LIKE '%SMP%’ 匹配，24 这个数字是 SMP 相关 commit 的下限，实际涉及新调度器开发的 commit 可能更多（如 subject 中含 “scheduler” “runqueue” “work stealing” 但未含 “SMP” 的 commit 未被统计）。统计结论 [C-09] 局限性继承：Mann-Kendall 趋势检验 p < 0.001 显著仅反映 netbsd-src 月度 commit 量存在统计学显著的下降趋势，不等于该下降趋势在 2005-2009 年本章时期内单调递减——Sen's slope = −7.27/月是全期（1993-2026）平均斜率，本章时期内年度 commit 量可能存在波动（如 2009 年较 2008 年微增 0.6%），须结合 L1.1.1 年度 commit 量数据交叉验证；趋势检验不区分 “开发衰退” 与 “开发模式转型”（如向 Mercurial 迁移的过渡期影响），下降原因须结合 commit message 主题词与文件路径分析
