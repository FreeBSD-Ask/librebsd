# 196.7.1 旧 SMP 调度器 → 新 SMP 调度器（2009.4）

**要点**：NetBSD 4.x 的 SMP 调度器采用全局运行队列与粗粒度锁，多核扩展性受限；NetBSD 5.0（2009.4）引入由 Andrew Doran（安德鲁·多兰） 设计的新 SMP 调度器，采用每 CPU 运行队列与工作窃取算法；新调度器支持多核负载均衡与优先级继承；新调度器使 NetBSD 在 4 核至 32 核机器上获得显著性能提升；从旧 SMP 调度器到新 SMP 调度器的 “淘汰” 使 NetBSD 多核性能追上 FreeBSD 7.0 的 ULE 2.0

**史料**：NetBSD 5.0 Release Notes；Andrew Doran “A New SMP Scheduler for NetBSD” 邮件列表与论文；CVS commit log 中调度器相关 commit；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2009 年 commit_count = 26,690（5.0 发布年），2008 年 = 26,543，2007 年 = 28,670（4.0 发布年），2007-2009 年间 commit 量稳定在 26,000-29,000 区间，反映新 SMP 调度器开发期（2007-2008）与发布年（2009）的持续工程投入；netbsd.duckdb 查询 L2.3.1.smp 显示：netbsd-src 2007 年 SMP 相关 commit = 38（4.0 周期，开发峰值），2008 年 = 24，2009 年 = 24（5.0 发布年），SMP 相关 commit 在 4.0 周期（2007）达峰后在 5.0 发布年保持稳定，印证新 SMP 调度器核心开发集中在 4.0 周期、5.0 发布时已进入维护阶段；netbsd.duckdb 查询 L1.4.1 显示：netbsd-src 无标准 release tag，分支 netbsd-5-0 commit_date = 2014-12-25T23:54:07Z（远晚于 5.0 发布 2009.4.29 约 5 年 8 个月），发布间隔须以 branches 表与官方公告交叉验证 ［A］

**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：新 SMP 调度器付出复杂度代价，但获得多核性能；总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：从全局队列到每 CPU 队列是调度器 “形式” 的演进

**辨析**：Doran 新调度器与 FreeBSD ULE 2.0 的关系存在叙事分歧——Doran 在邮件列表中提及参考 ULE 但强调独立性，需对照源码 diff 核验；新调度器的性能基准数据在第三方测试中差异较大，需查 Phoronix 等早期基准。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 CVS **cvs.netbsd.org**；hg.NetBSD.org 系 Mercurial 镜像而非主仓），2007-2009 年 commit 量可能不完整；L2.3.1.smp 查询基于 message_subject LIKE '%SMP%’ 匹配，38/24/24 这组数字是 SMP 相关 commit 的下限，实际涉及新调度器开发的 commit 可能更多（如 subject 中含 “scheduler” “runqueue” “priority” “preemption” 但未含 “SMP” 的 commit 未被统计）；L1.4.1 查询的 “无匹配 tag” 是 tag 命名约定差异导致，非 netbsd-src 无版本标签，须以 branches 表替代分析

**文献**：Andrew Doran “A New SMP Scheduler for NetBSD”；Jeff Roberson “Introducing ULE”（BSDCan 2007）；NetBSD 5.0 Release Notes；netbsd.duckdb 数据分析·宏观趋势统计.md §L1.1.1（netbsd-src 2007-2009 年度 commit 量）、§L2.3.1.smp（netbsd-src SMP 相关 commit 2007-2009）、§L1.4.1（netbsd-src release tag 查询无匹配） ［A］
