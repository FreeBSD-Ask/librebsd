**要点**：NetBSD 6.x 版本周期（2012-10-01 至 2014-07-01）是 NPF（NetBSD Packet Filter）防火墙引入后的首个完整版本周期——netbsd.duckdb netbsd-src 仓库查询显示此周期内 113 条 CVE commit、6 条 Security fix commit、21 条去重 CVE（全部无 CVSS v3 评分），CVE commit 量较 5.x 周期（212 条）下降 46.7%（2026-09-12 复核留痕：按 `message_subject LIKE '%CVE%'` 口径实测该窗口 76 条、5.x 窗口 258 条，原查询定义因档案断链不可回溯，上列数字与实测数并存存疑），反映 NetBSD 6.x 周期漏洞密度相对降低；NetBSD 6.0 引入的 NPF 防火墙（由 Mindaugas Rasiukevicius 开发）替代 IPFilter（IPF）与 PF 成为推荐防火墙，NPF 的引入带来新的网络栈攻击面——防火墙规则解析器、数据包过滤钩子、NAT 状态表等组件均可能成为漏洞载体；此时期 NetBSD 6.0 还引入新线程调度器与改进 SMP 支持，架构变化使内核并发路径增加

**史料**：netbsd.duckdb netbsd-src 仓库 commits 表（6.x 周期 113 条 CVE commit、6 条 Security fix commit、21 条去重 CVE）；NetBSD 6.0 Release Notes（2012.10.17）；早期漏洞补遗归档（原指向 **原材料/研究/bsd 漏洞史/版本周期/netbsd-6.x.md**，该路径全项目不存在，已删链改述，CVE 统计原口径不可回溯） ［A］

**史观**：总纲第 15 条（文化即形式主义）：NPF 作为 NetBSD 自主开发的防火墙（不同于 IPF 的 Darren Reed（达伦·里德） 外部维护与 PF 的 OpenBSD 起源），其引入体现 NetBSD“自主可控”的工程哲学，但自主开发也意味着安全审计责任完全由 NetBSD 社区承担；总纲第 15 条（文化即形式主义）：CVE commit 量下降 46.7% 不等于漏洞数量实际减少——可能部分源于 NetBSD 6.x 周期发布节奏（约 3 年 6 个月）较长，部分漏洞修复推迟至 7.x 周期

**辨析**：NPF 是否完全替代 IPF 与 PF 须考据——NetBSD 6.0 Release Notes 可能仍保留 IPF 与 PF 作为可选模块，NPF 仅为推荐选项；CVE commit 量下降 46.7% 的论断须区分“漏洞数量减少”与“commit 量统计偏差”——若 6.x 周期部分漏洞修复未引用 CVE 编号，则下降率可能被高估；【0 信任原则·CVSS 评分缺失】21 条去重 CVE 全部无 CVSS v3 评分

**当事人自述**（证据等级：L4，来源：`historical_claims.duckdb.claim.CL-RM-010582`；2026-09-05 大库战线行级遍历考据采纳）

2012 年 9 月 3 日，Taylor R Campbell 报告在原版 NetBSD 6.0_RC1 上启用 `sshd(8)`，默认启动会生成 1024 位模数的 RSA 主机密钥、1024/160 位参数的 DSA 主机密钥与来自 nistp521 曲线的 ECDSA 主机密钥，这些默认值由 `/etc/rc.d/sshd` 与 `/etc/defaults/rc.conf` 决定，其中 `/etc/defaults/rc.conf` 把 ssh_keygen_flags 设为 -b 1024；他认为这些参数按当时标准太小，至少应清空该标志以沿用 `ssh-keygen(1)` 自身默认，更彻底的做法可用 `ssh-keygen -A` 生成全部密钥，但他对继续用 DSA 存疑，倾向默认只用 2048 位以上模数的 RSA 密钥，并在信中征询反对意见。引用时按 L4 纪律：以上为邮件列表当事人一手自述，属过程性证据，具体技术结论仍须以源码与提交记录复核为准，不得单独引为定论。
