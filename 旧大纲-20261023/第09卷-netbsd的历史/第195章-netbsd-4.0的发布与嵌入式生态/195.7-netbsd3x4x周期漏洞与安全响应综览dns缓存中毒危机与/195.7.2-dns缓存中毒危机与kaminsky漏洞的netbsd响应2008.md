# 195.7.2 DNS 缓存中毒危机与 Kaminsky 漏洞的 NetBSD 响应（2008）

  **NetBSD 修复 Kaminsky 漏洞的 commit 原文**：

  > Pull up patch (requested by adrianp in ticket #1948):
  >
  > Update BIND to 9.3.5-P1 to fix CVE-2008-1447 and turn off pthreads.
  >
  > ——netbsd-src 仓库，commit `3c106208a887babeafa2560cd4e021b2b198dcc3`, 2008-07-24

**要点**：CVE-2008-1447（Kaminsky DNS 缓存中毒漏洞，**2008 年 7 月** 披露，Dan Kaminsky 发现 DNS 协议设计缺陷使攻击者可向递归 DNS 服务器注入恶意记录）是 NetBSD 4.x 周期影响最广泛的漏洞之一——netbsd.duckdb 显示 NetBSD **2008-07-24** commit `3c106208a887babeafa2560cd4e021b2b198dcc3` 修复该漏洞，commit 标题与正文为 “Pull up patch (requested by adrianp in ticket #1948): Update BIND to 9.3.5-P1 to fix CVE-2008-1447 and turn off pthreads.”（netbsd-4 分支 pullup）；该漏洞影响 NetBSD 基本系统集成的 BIND 9 递归解析器，所有启用 DNS 递归查询的 NetBSD 服务器均受影响；NetBSD 的修复通过将基本系统集成的 BIND 升级至 9.3.5-P1 落实上游源端口随机化缓解，降低缓存中毒成功率；该漏洞的特殊性在于其根因是 DNS 协议设计缺陷而非实现缺陷，修复方式是通过实现层缓解（源端口随机化）而非协议层修改，反映 “协议设计漏洞” 与 “实现缓解” 的工程张力

**史料**：netbsd.duckdb netbsd-src 仓库 commit `3c106208a887babeafa2560cd4e021b2b198dcc3`（2008-07-24，CVE-2008-1447 Kaminsky DNS 缓存中毒）；ISC BIND 9.3.5-P1 升级公告；Dan Kaminsky 漏洞披露原始公告 ［A］

**史观**：总纲第 15 条——文化即形式主义：Kaminsky 漏洞揭示 “协议设计缺陷” 的工程困境——DNS 协议的 16 位事务 ID 空间在 2008 年的计算能力下已可被暴力枚举，修复须通过实现层缓解（源端口随机化）将有效熵从 16 位扩展至约 30 位，此为 “在不修改协议的前提下通过实现加固缓解设计缺陷” 的典型范式；总纲第 9 条——经验优先：Dan Kaminsky 的漏洞披露方式（协调多厂商同步发布）成为后来 CVE 协调披露的范本，但 NetBSD 的修复时序须与 ISC、其他 BSD 项目交叉验证

**辨析**：NetBSD commit `3c106208a887babeafa2560cd4e021b2b198dcc3` 的修复日期（2008-07-24）与 Kaminsky 漏洞公开披露日期（2008-07-08）相差 16 天，反映协调披露窗口——NetBSD 在公开披露前已获得补丁；“源端口随机化” 作为缓解措施的有效性须考据——Kaminsky 漏洞的完整修复须 DNSSEC 部署，源端口随机化仅为过渡方案；【0 信任原则·CVSS 评分缺失】CVE-2008-1447 无 CVSS v3 评分，但 “DNS 缓存中毒” 的机制类型本身暗示较高风险（可导致域名劫持）
