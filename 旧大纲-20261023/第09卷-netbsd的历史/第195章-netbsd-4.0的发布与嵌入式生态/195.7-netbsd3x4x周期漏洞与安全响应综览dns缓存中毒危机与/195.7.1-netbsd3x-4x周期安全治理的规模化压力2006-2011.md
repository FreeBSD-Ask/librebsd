**要点**：NetBSD 3.x（2006-12 至 2008-05）与 4.x（2008-05 至 2011-04）版本周期（窗口系发布间隔近似划分，非发布日口径）是 CVE commit 量显著上升的时期——netbsd.duckdb netbsd-src 仓库查询显示 3.x 周期 82 条 CVE commit、15 条 Security fix commit、17 条去重 CVE，4.x 周期 212 条 CVE commit、22 条 Security fix commit、33 条去重 CVE，4.x 周期 CVE commit 量较 3.x 周期增长 158.5%，反映 NVD CVE 编号分配体系的成熟与 NetBSD commit message 引用 CVE 习惯的固化；两窗口求和 50 条、去重 49 条 CVE（3.x 17 条 + 4.x 33 条，1 条跨周期重复）均无 CVSS v3 评分，反映 NVD 对 2011 年前 CVE 的 CVSS v3 回填滞后；此时期 NetBSD 4.0（**2007.12.19**）引入细粒度 SMP 锁、改进调度器，架构变化使内核攻击面扩大——SMP 锁引入新的竞态条件可能性（1:1 原生线程支持系 NetBSD 5.0 特性，4.0 的 pthread 仍为 SA 路线，本节不将其归属 4.0）

**史料**：netbsd.duckdb netbsd-src 仓库 commits 表（3.x 周期 82 条 CVE commit、4.x 周期 212 条 CVE commit）；NetBSD 4.0 Release Notes（2007.12.19） ［A］

**史观**：总纲第 15 条——文化即形式主义：CVE commit 量的显著上升不等于漏洞数量的实际增长——部分源于 CVE 编号体系普及带来的 “统计显性化”，部分源于 NetBSD 4.0 架构重构（SMP 锁、原生线程）引入的新攻击面；总纲第 15 条——文化即形式主义：commit message 引用 CVE 习惯的固化是 NetBSD 安全文化形式主义化的深化——从 2.x 时期的 “开始引用” 到 3.x-4.x 时期的 “普遍引用”

**辨析**：4.x 周期 CVE commit 量较 3.x 周期增长 158.5% 的论断须区分 “漏洞数量增长” 与 “CVE 编号引用习惯普及” 两个因素——若 3.x 周期部分漏洞修复未引用 CVE 编号，则增长率可能被高估；全部 49 条去重 CVE（两窗口求和 50）无 CVSS v3 评分系 NVD 回填滞后所致，本节不臆造评分；【0 信任原则·架构变化与漏洞关联】NetBSD 4.0 SMP 锁与原生线程支持是否直接导致特定 CVE 须对照源码 diff 核验——架构变化与漏洞出现的时序关联不等于因果关系
