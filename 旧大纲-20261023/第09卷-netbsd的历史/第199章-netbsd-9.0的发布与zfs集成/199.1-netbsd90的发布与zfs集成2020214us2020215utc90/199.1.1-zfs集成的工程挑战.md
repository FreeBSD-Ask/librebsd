**史观**：总纲第 4 条——分离聚合是永恒规律〔订正注：原挂“总纲第 2 条——分离与聚合”系伪标签，权威第 2 条为“历史是形式主义化的非存在”，分离聚合改挂总纲 4〕：OpenZFS 作为 Solaris 衍生代码与 NetBSD 内核聚合，但 SPL 作为分离层维护兼容性

**辨析**：NetBSD ZFS 与 FreeBSD OpenZFS 的关系存在叙事分歧——部分资料称 NetBSD 直接移植 FreeBSD OpenZFS，部分称通过 OpenZFS 仓库共享代码，需对照源码核验。经 netbsd.duckdb netbsd-src 仓库 commits 表验证：NetBSD ZFS 代码由 chs（Chuck Silvers）于 2018-05-28 从 FreeBSD SVN r315983 首次大批量导入（commit aa52db7bd6f0f630edc90d06231f27ac9af1a442“import new CDDL dtrace and ZFS code from FreeBSD svn r315983”），明确证实 NetBSD ZFS 是从 FreeBSD SVN 仓库移植而非直接从 OpenZFS 仓库共享代码，存疑已解决（代码来源与移植路径得到代码级确认）；ZFS 在 NetBSD 上的早期痕迹可追溯至 2007.6.9（christos PR/36464 修复 ZFS 兼容性），2007.12.24 ad 添加 MOUNT_ZFS/VT_ZFS 与 major 设备号预留，反映 NetBSD 在 9.0 正式集成前已有约 12 年的 ZFS 兼容性准备工作；ZFS 在 NetBSD 上的稳定性“不及 FreeBSD”在不同工作负载上差异较大 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；9.0 发布日期时区差异已获考据确认——NetBSD 官方 formal.html 页面（**<https://www.netbsd.org/releases/formal-9/NetBSD-9.0.html>**）写“February 14, 2020”使用美国西部时间（UTC-8），mail-index.netbsd.org netbsd-announce 邮件列表存档（** <https://mail-index.netbsd.org/netbsd-announce/2020/02/15/msg000309.html**>）显示 Martin Husemann 发信时间“Sat, 15 Feb 2020 14:57”使用 UTC，2020-02-15 00:57 UTC = 2020-02-14 16:57 PST，二者实为同一时刻的不同时区表示，无实质分歧，存疑已解决。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2018-2019 年 commit 量可能不完整；L2.3.1.zfs 查询基于 message_subject LIKE'%ZFS%’匹配（大小写敏感），31/40 这组数字是 ZFS 相关 commit 的下限，实际涉及 ZFS 集成（如 SPL 适配、UVM 转换、并发原语）的 commit 可能更多（如 subject 中含“zpool”“znode”“dbuf”“dmu”“spa”“dsl”但未含“ZFS”的 commit 未被统计）；2019 年 ZFS commit 峰值（40）与 9.0 发布前稳定化投入时序吻合，但 commit 量峰值不等于技术成熟度峰值。统计结论 [C-09] 局限性继承：Mann-Kendall 趋势检验 p < 0.001 显著仅反映 netbsd-src 月度 commit 量存在统计学显著的下降趋势，不等于该下降趋势在 2018-2020 年本章时期内单调递减——Sen's slope = −7.27/月是全期（1993-2026）平均斜率，本章时期内 ZFS 子领域 commit 反增长 29.0%（2018 年 31→2019 年 40），须结合 L1.1.1 年度 commit 量数据交叉验证；趋势检验不区分 “开发衰退” 与 “开发模式转型”（如向 Mercurial 迁移的过渡期影响），下降原因须结合 commit message 主题词与文件路径分析
