# 334.2.45 题眼冷知识考据POSIX路径解析中的双斜杠除以两个连续斜杠开头的情形外路径中的多

- 题眼冷知识考据 POSIX 路径解析中的双斜杠：除以两个连续斜杠开头的情形外，路径中的多余斜杠均可折叠为单斜杠，而“//”开头的路径被允许按实现定义方式解释——规格的 rationale 小节对此并未给出解释；主持人循 Stack Overflow 旧帖盘点各实现：Samba 以之承载 Windows UNC 网络路径，Cygwin 中连 C:/ 亦按 Unix 斜杠解释，IBM z/OS 用以访问 MVS 数据集，Apollo Domain OS 同样用于 UNC 路径，另一分布式文件系统与 AT&T System V Release 3 的 RFS 远程文件共享以“//主机/路径”指向他机文件，Perforce 的 //depot 指向版本库内文件，Blender 甚至以双斜杠表示相对路径——多源并置足证该空隙是各实现历史分岔在标准文本中的沉淀，而非规范自身的逻辑要求。（BSD Now EP183，[536.94-661.60]，L3）[订正：原 “Cygwin 以之承载 Windows UNC 网络路径”及“Apollo Domain OS 以‘//主机/路径’指向他机文件”，2026-09-30 SenseAudio 重转核对]
- 随着苹果宣布 APFS 将随 iOS 10.3 出货，Adam Leventhal 延续其对 APFS 的 DTrace 考古：以约十九行 C 程序调用 fs_snapshot 系统调用遭权限拒绝，借 DTrace 十三万七千个插桩点定位到凭证检查函数，对照 xnu 源码加 sudo 后创建成功，继而以暴力枚举重建了 WWDC 演示中未曾发放的快照工具，随后却在 Sierra 系统目录里发现官方 apfs_snapshot 与疑似支持就地转换的 hfs_convert；更具考据价值的是回滚语义——revert 调用返回成功却不即时生效，须卸载重挂方见回退，且静默删除其后全部快照，而 ZFS 面对同样操作会显式警告将销毁快照；同一概念在两个谱系中的约定程度落差，叠加快照致磁盘工具失序乃至仅重启可解的挂载死锁，显示该文件系统尚在成形途中。 [存疑脚注] 转写开头将受访者误作“Evan Leventhal”，后文“adam being adam”可证为 Adam Leventhal，引用时以 dtrace.org 原文为准。（BSD Now EP183，[710.08-1139.12]，L2）
