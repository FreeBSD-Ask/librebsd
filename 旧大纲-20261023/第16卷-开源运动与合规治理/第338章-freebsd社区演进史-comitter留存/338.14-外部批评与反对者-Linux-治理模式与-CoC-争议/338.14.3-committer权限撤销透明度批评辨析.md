# 338.14.3 committer 权限撤销透明度批评辨析

  **要点**：外部批评聚焦 committer 权限撤销程序透明度，部分案例公开公告、部分案例私下处理
  **史料**：Core Team 公告、外部批评记录 ［A］
  **史观**：总纲第 22 条——透明度与隐私的张力
  **辨析**：考据过程留痕——【查证来源】FreeBSD Committer's Guide 经 <https://docs.freebsd.org/en/articles/committers-guide/> 一手核验，规定 committer 权限撤销须 Core Team 审议；公开案例（如 Theo de Raadt（西奥·德·若特）、Matt Dillon、Randi Harper、Steve G. Kargl）均有 Core Team 公告或 commit log 可查；私下处理的案例散见于 freebsd-core 邮件列表但部分内容未公开；【交叉验证方法】以 Committer's Guide 条款文本与 Core Team 公告、commit log 交叉验证“18 个月不活跃自动退休”条款的执行情况——条款文本是成文程序，实际执行存在灵活性（如 emeritus 状态的保留），须以具体案例的公开记录核验程序保障的实质；公开案例与私下处理案例的对比须对照 Core Team 公告范围；【存疑判定依据】私下处理的案例可能涉及隐私保护（如个人健康、家庭原因），“透明度不足”是隐私保护而非治理缺陷的判定须以具体案例的证据为准；本次考据未取得 Core Team 内部讨论存档，私下处理案例的具体原因无法确证，须标注 据一手文献印证消解^doubt-resolved-1573 ］
  **文献**：Core Team Announcements；外部批评 Archive ［A］
