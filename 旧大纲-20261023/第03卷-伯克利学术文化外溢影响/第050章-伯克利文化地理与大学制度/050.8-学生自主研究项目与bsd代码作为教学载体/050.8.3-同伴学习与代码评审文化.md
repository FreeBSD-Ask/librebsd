# 050.8.3 同伴学习与代码评审文化

  **要点**：CSRG 内部形成了同伴学习与代码评审文化，区别于正式课堂的“教师-学生”单向传授。学生之间通过邮件列表（CSRG 内部邮件、UNIX Wizards 邮件列表）、走廊讨论、代码互评等方式相互学习；Joy 与 Babaoglu 关于虚拟内存的协作、McKusick 与 Leffler 关于 4.2BSD 的协调、Karels 与 Bostic 关于 4.3BSD 的接力均体现同伴学习特征。代码评审无正式流程，多通过邮件讨论与口头评议进行，呈现非制度化的同伴评审特征，此文化是 hacker 伦理与学术自由融合的教育侧投影

  | 同伴学习形式 | 载体 | 案例 |
| ---------- | -- | -- |
| 邮件列表讨论 | CSRG 内部邮件、UNIX Wizards | 虚拟内存设计讨论 |
| 走廊讨论 | Evans Hall 走廊 | — |
| 代码互评 | 邮件 + 口头评议 | Joy/Babaoglu、McKusick/Leffler、Karels/Bostic |

**史料**：CSRG 内部邮件列表存档（Bancroft 图书馆 CU-551 全宗）、UNIX Wizards 邮件列表存档、McKusick 关于同伴学习的访谈、Joy 与 Babaoglu 的协作记录［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
  
**史观**：第 4 条分离聚合（见 据原文第 4 章 4.1 节）：“UNIX 分裂出各种 BSD，BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离；而各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”——同伴学习（学生横向）与师徒传授（师生纵向）在组织上分离，在 BSD 代码产出上聚合，分离与聚合塑造同伴学习的双重性；第 10 条动手者创造历史（见 据原文第 14 章 14.5 节）：“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”——同伴学习的邮件、讨论、评审虽非代码本身，却是 BSD 项目得以成立的“外围形式主义”，没有这些同伴交流，代码难以聚合为发行；第 19 条解释学循环（见 据原文第 25 章 总纲第 19 条）：“解释学循环是历史认识的根本条件”——同伴学习中的分歧源于前理解差异，邮件列表讨论是解释学循环的具体场域，分歧与协商构成 BSD 知识生产的认识论条件
  
**辨析**：CSRG 内部邮件列表存档的完整性需核对（部分邮件可能遗失或未存档）；“非制度化”的判断需核对——CSRG 是否有正式代码评审流程需考据，避免将“非正式评审”夸大为“无评审”；Joy/Babaoglu、McKusick/Leffler 等组合的“同伴”关系需区分“同伴学习”与“师徒传授”的边界，Babaoglu 与 Joy 是否构成对等同伴关系需核对 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
