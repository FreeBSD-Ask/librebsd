# 049.2.4 要点BSD文档的修道度人维度为文档编写是开发者自我修行修道文档阅读是后来者学习度

  **要点**：BSD 文档的修道度人维度为：文档编写是开发者自我修行（修道），文档阅读是后来者学习（度人），两者辩证统一，CSRG 成员通过编写 man pages 与手册实现自我修行，同时通过文档发布帮助后来者学习 BSD

  > 代码即文档，文档即修行；写文档的人度不了别人，但写文档这件事本身就是在修行。

  | 维度 | 修道（自我修行） | 度人（后来者学习） |
| -- | -------------- | ---------------- |
| 主体 | CSRG 成员（文档编写者） | 后来者（文档阅读者） |
| 形式 | 编写 man pages 与手册 | 阅读 man pages 与手册 |
| 关系 | 辩证统一 | 同左 |

**史料**：McKusick 关于文档编写的访谈、CSRG 文档编写规范、BSD 文档用户反馈 ［B］
  
**史观**：第 14 章边缘者——文档编写的 “度人” 维度常被代码开发的 “修道” 维度掩盖，需恢复文档编写的度人价值
  
**辨析**：修道度人的 “哲学深度” 需谨慎，CSRG 成员未必有系统的修道度人思考，需区分 “实践哲学” 与 “理论哲学”
  
**文献**：McKusick, K. (1999) “Twenty Years of Berkeley Unix”；CSRG 文档档案；Unix Programming Manual ［B］

**史家判断**（证据等级：L2，来源：`cross_indexes.duckdb.concept_history.10`）

2001 年夏 Jeff Bonwick 与 Matt Ahrens 在 Sun Microsystems 启动 ZFS 项目，历时约 4 年由十余人团队实现存储池、写时拷贝（CoW）、RAID-Z、快照、send/receive 等核心；2005 年并入 Solaris trunk，作为 OpenSolaris build 27 向开发者发布（2005-11-16），此后以 CDDL 许可证开源；2006 年在 Solaris 10 6/06 更新中正式纳入。2005–2010 年移植到 FreeBSD、Linux、Mac OS X。2010 年 Oracle 收购 Sun 后停止向社区贡献 ZFS 代码并关闭 OpenSolaris，催生 illumos fork（2010）；2013 年 9 月 OpenZFS 成立，协调 FreeBSD、Linux、illumos、macOS 等平台的开源 ZFS 开发。

**要点**：

- Callahan 自述 BSD 课程扩张的困境是一个循环：需要更多 BSD 从业者才有人进入教育领域开课，而开设课程才能培养更多从业者；他给出的破局路径包括 BSD 人士主动进高校承担客座讲授、由企业或基金会资助高校课程——并举 Red Hat 向大学捐资开设开源课程、Nexenta 在多所大学设立文件系统研发培养职位的先例——以及以学生社团（如 RPIsec 令 RPI 以计算机安全闻名）等自下而上方式建立 BSD 的校园存在感。（BSD Now EP114，[1215.24-1515.36]，L1）
- Callahan 详述其客座文档实验课的设计：学生从 FreeBSD 手册、网页与 man 页或 OpenBSD FAQ 中任选材料，目标不是学习内容本身而是找出错别字或语法问题，由此顺带学会 SVN/CVS 基本操作、生成 diff 补丁并经 FreeBSD Bugzilla 等正规渠道提交；他认为该设计一举三得——入门非 Git 系版本控制、练习阅读文档这一独立技能、并首次体会成为 BSD 社区一分子的含义。（BSD Now EP114，[2014.16-2098.38]，L1）
- 主持人转述 Netflix 公布的单台设备出流量曲线：一台 FreeBSD 流媒体设备从上线爬坡至约 65 Gbps、快照后继续升至 72-75 Gbps，配置为单路高端 Xeon E5 加双口 40GbE Chelsio T580 网卡与 NVMe/SSD 混合存储（部分 NVMe 读速达 1.7 GB/s），CPU 占用仅约 65%，TLS 加密流量占比 10%-15%；主持人强调此前的 52 Gbps 纪录依赖大量实验性调参，而本次成绩近乎出厂默认设置，凸显 FreeBSD 网络栈的默认扩展性。（BSD Now EP114，[3978.86-4103.00]，L2）
- 主持人转述 Salter 对备份工具的结构性论证：rsync 为找出文件变更必须完整读取两侧文件，而 ZFS 复制只需按块查询自某快照以来变更的块并传输增量，1500 万文件的数据集前者可能耗时数日、后者仅需数秒；并举 FreeBSD 集群将家目录 NFS 从加州迁往纽约时 rsync 反复运行仍需约 20 小时锁服同步的实例，说明文件系统级快照复制在一致性瞬间与增量效率上对文件级同步的优势。（BSD Now EP114，[524.38-616.70]，L2）
- 主持人自 2009 年起在 University of Maine at Augusta 以兼职教师身份教授 UNIX 基础课程；课程源起于所在计算机信息系统系部署 Linux 机器时求助于其任职的 ISP；多年以 Linux 为主、以 Mark Sobel 的 A Practical Guide to Linux 为教材，属通用 UNIX 课程而非 Linux 专属课，全命令行授课并辅以 Apache 虚拟主机配置等系统管理内容。（BSDTalk EP208，[71.76-196.86]，L1）
- 课程长期在多系统间轮换以展示技能可迁移性，曾引入 Solaris、Darwin 与 Silicon Graphics IRIS 工作站；因院系要求压缩教材成本，改用免费的在线 Linux 命令行书，换书导致课程格式全面重排；同期更新 Linux 虚拟机时遭遇 init 体系由传统 init 经 upstart 到 systemd 的更替与包管理工具的分化，最终促使 2011 年把课程重点转为以 BSD 为主、Linux 为辅。（BSDTalk EP208，[190.18-327.54]，L1）
- 选择 OpenBSD 作为主教学平台的理由包括：安装镜像极小，对比 Debian、Fedora 镜像之庞大，三十名学生同时下载不致拖慢课堂；提供完整 UNIX 用户态与编译器栈，X 环境简明；安装器易用；系统行为长期稳定，教学示例不易失效。（BSDTalk EP208，[368.36-486.88]，L1）
- 具体教学法：每节课要求学生重新下载全新虚拟机镜像，以保证全体学生从同一已知良好基准出发，防止学生在 U 盘镜像上自行改动导致环境漂移；借 TWM 极简窗口管理器演示应用程序与窗口管理器的区分、手动窗口管理乃至 X 窗口系统的网络本质；OpenBSD 安装后的 Charlie Root 欢迎邮件、afterboot 手册页与 help 命令教程为学生提供了顺畅的入门引导。（BSDTalk EP208，[402.62-533.24]，L1）
- 与 Linux 对照的主要摩擦点：BSD 的 init 脚本系统长期未变、易于掌握，而 Linux 的快速变迁令教学者产生过时感；网络配置上 OpenBSD 只需在 hostname.if 文件写入 dhcp 即可，而 Linux 的动态设备检测使网卡命名不一致，导致同班学生网络配置时灵时不灵；受访者理解 Linux 的动态化源自 USB 与笔记本时代的设备模型，而 UNIX 传统服务器常年稳定运行的模型更契合 OpenBSD 的静态配置方式。（BSDTalk EP208，[539.48-707.42]，L1）
- 学期以 BSD 为主授课未收到学生的重大抱怨；受访者的教学立场是可迁移性与灵活性——Apache 配置文件位置在 Solaris、Red Hat 与 FreeBSD 上各不相同，关键在于学生会查文档、理解管道组合工具、会读手册页并掌握 sed、awk 等基本原理；学期末把学生分组抛到未曾接触的陌生系统上完成任务，以验证技能的可迁移性。（BSDTalk EP208，[327.54-846.18]，L1）
- 受访者的核心观察是 UNIX 基本原理三十年未变：1970 年代 AT&T System V 老书的目录至今仍然适用；系统不发生脚下变动本身就是教学价值；计划来年夏季重开课程，开发更多 BSD 专属教学资源，甚至自行撰写 Teaching UNIX with BSD 一书。（BSDTalk EP208，[849.62-894.58]，L1）
- mandoc 项目起于约六年前其原作者不满 groff 生成 HTML 手册的输出质量而另起格式化器，项目很快进入 OpenBSD 源码树，至 2010 年前后完成全树手册的构建切换；如今 OpenBSD 与 NetBSD 已采用其替代 groff，FreeBSD 与 DragonFly 正在准备切换并已完成大量筹备工作。 [存疑脚注] 原作者姓名转写音为 Christoph Johnson，据 mandoc 项目通行记载应为 Kristaps Dzonsons（BSDTalk EP243，[84.14-165.10]，L1）
- Schwarze 口述手册页格式语言谱系：Saltzer 于 1964 年实现 runoff 工具（后更名 roff），其语法已有 50 年历史且建基于五十年代末六十年代初 CTSS 的文档传统；Ritchie 与 Thompson 在贝尔实验室以 PDP-7 汇编重写 roff 并立即用于排版第一版 AT&T UNIX 手册；research Unix 演进到第 4 版时出现第一代高级宏，第 7 版 Unix 于七十年代末定型今日的 man 语言；约 1990 年伯克利 CSRG 发明 mdoc，首次支持语义标记并沿用至今。 [存疑脚注] Jerry Saltzer 之名转写音为 Soltzer，据 MIT 通行记载校正（BSDTalk EP243，[199.42-296.74]，L1）
- 语义标记的价值有三层：书写时标注语义角色（作者名、标题、函数名）比记忆物理修饰更直观；同一标记可按需要派生多种输出格式；最关键的是支撑精确检索——以 apropos 按语义字段查询即可列出所有使用 USER 环境变量的工具手册，而物理标记只能得到粗糙的模糊匹配，预格式化手册甚至令 grep 与 apropos 完全失效。（BSDTalk EP243，[325.58-421.54]，L1）
- mandoc 的工程负担源于 man 语言原是建于 groff 之上的宏层，凡 groff 具备的特性迟早会有人用进手册，故为覆盖真实世界文本必须实现完整的 roff 数值处理与条件指令；与此同时新功能持续推进：历时三年开发的增强检索在近期冲刺优化，计划吸收 preconv 以透明处理 UTF-8 的日文、俄文手册，内置的 mdoc 到 man 转换器则让可移植项目能为 Solaris 等二十年间始终没有 mdoc 实现的系统自动分发 man 版本。（BSDTalk EP243，[525.04-756.27]，L1）
