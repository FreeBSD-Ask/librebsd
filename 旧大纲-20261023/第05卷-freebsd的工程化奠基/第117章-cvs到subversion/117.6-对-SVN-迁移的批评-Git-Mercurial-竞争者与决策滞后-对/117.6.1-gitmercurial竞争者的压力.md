# 117.6.1 Git/Mercurial 竞争者的压力

  **要点**：2005-2008 年 Git 与 Mercurial 快速崛起：Git 因 Linux 内核采用而普及，Mercurial 因 Python 实现跨平台友好；FreeBSD 迁移 SVN 时 Git 已成熟（1.5 版 2007-02 首发），社区中出现 “为何不选 Git” 的强烈质疑
  
**史料**：freebsd-hackers 邮件（2007-2008）、Git 1.5 Release Notes、Mercurial 文档 ［A］
  
**史观**：总纲第 5 条——没有必然性，只有偶然性：Linux BitKeeper 事件催生 Git 改变整个版本控制格局（原“第 1 条——偶然性改写历史”与基线第 1 条“一切真历史都是古代史”不符，按权威表改挂——2026-09-12 整改）
  
**辨析**：2008 年 Git 1.5 已发布，但 Git 在大规模仓库（如 FreeBSD src 数十万文件）上的性能基准在 freebsd.duckdb 中不可得，须依赖 2007-2008 年 SVN vs Git 性能基准测试报告与 freebsd-hackers 邮件列表讨论交叉验证；社区中“为何不选 Git”的质疑本身证明 Git 已具备候选资格
  
**文献**：《Pro Git》；《Mercurial: The Definitive Guide》 [考据脚注：Pro Git 经 Scott Chacon（Apress, 2009）出版信息确认，Mercurial: The Definitive Guide 经 mercurial.selenic.com 官方页面与 O'Reilly 出版信息交叉验证确证。]
