# 115.11.3 ZFS 从实验性状态 → 一等文件系统（8.0，2009.11.25）

  **要点**：FreeBSD 7.0-RELEASE（2008.2）由 Pawel Jakub Dawidek 移植引入 ZFS（OpenSolaris 来源，CDDL 许可证），作为实验性文件系统（ZFS pool version 6）；7.x 时期 ZFS 因需要大量内核内存、稳定性问题、32 位架构不友好等被标记为实验性；FreeBSD 8.0-RELEASE（2009.11.25）将 ZFS 升级到 pool version 13，并正式宣布 ZFS 为“production ready”（生产就绪）；升级内容包括：普通用户 ZFS 操作、L2ARC（二级自适应替换缓存）、独立设备的 ZFS Intent Log（slog）、稀疏卷（sparse volumes）等；同时将内核可分配内存上限从 2GB 提升至 512GB，以适应 ZFS 对内核内存的大需求；8.0-RELEASE Press Release 明确：“ZFS moving from experimental to production status”；ZFS 成为“一等文件系统”（first-class filesystem）标志着 UFS 在 FreeBSD 主线中的边缘化起步——UFS2 仍是默认根文件系统，但 ZFS 在新部署中逐步成为首选；8.1/8.2/8.3/8.4 持续更新 ZFS 版本至 v14/v15/v5000，并完善快照、去重（dedup）、加密实验等功能

**史观**：总纲第 24 条——许可证政治：ZFS 采用 CDDL 许可证，与 FreeBSD 的 BSD 许可证存在许可证不兼容问题，导致 ZFS 无法被 Linux 内核主线采纳（Linux 通过 OpenZFS 用户态项目间接支持），FreeBSD 因 BSD 许可证的兼容性得以原生集成 ZFS；简洁与复杂的辩证：ZFS 的复杂设计（事务性、COW、快照、池化）换取了功能优势，但牺牲了简洁性
  
**辨析**：经 freebsd.duckdb commits 表验证，commit a4e6b460d3c9fcca09219322de97b8f3750a39dd（2009-09-15T11:34:53Z）明确移除 ZFS 实验性警告，message_subject 直接陈述“We believe ZFS is ready for production use”，证明 8.0 时期 ZFS 已被开发者认定为 production ready，“8.0 即生产就绪”的叙事得到代码级一手证据支持；先前“8.0 即生产就绪 vs 8.1 才完全稳定”之争的核心已由数据库证据解决——8.0 commit 明确表明开发者认定 ZFS 已 ready for production use；但功能完整度的差异（NFSv4 ACL 在 8.0 不完整，预期 8.1 完成）仍属功能演进问题，与“production ready”标签不冲突——production ready 不等于功能完整，仅表示可用于生产环境；ZFS 在 32 位架构上的支持在 8.x 时期仍被官方“不推荐”，仅 64 位架构推荐；UFS 在 8.x 时期的边缘化程度难以量化，需对照新部署调查；0 信任原则适用说明：commit a4e6b460d3c9fcca09219322de97b8f3750a39dd 的 author 字段与 committer 字段均为 Pawel Jakub Dawidek（<pjd@FreeBSD.org>），交叉验证一致；author_date 与 committer_date 相同（2009-09-15T11:34:53Z），无被 `git commit --date` 修改迹象；FreeBSD SVN-to-Git 2020 迁移可能引入 hash 重算，但该 commit 的 message_subject 与日期信息在迁移前后应保持一致；该 commit 早于 8.0-RELEASE（release/8.0.0 tagger_date = 2009-11-21T06:13:29Z）约两个月，符合“release 前最后清理”的工程惯例
