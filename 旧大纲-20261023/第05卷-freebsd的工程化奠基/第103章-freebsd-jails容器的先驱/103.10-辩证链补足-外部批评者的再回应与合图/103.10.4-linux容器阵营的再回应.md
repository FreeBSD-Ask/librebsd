# 103.10.4 Linux 容器阵营的再回应

  **要点**：Linux 容器阵营对 FreeBSD“先驱不被记住”叙事的再回应指出四点：其一，Docker 团队未公开否认容器技术有先驱，但其工程立场是“生态与标准化比时间先后更重要”；其二，Docker 的镜像分层、`Dockerfile` 声明式接口、Docker Hub 分发机制是 Jails 设计中不存在的工程层，并非简单“市场包装”；其三，“先驱”身份本身也是一种形式主义——以时间先后作为技术价值的评判标准，恰恰是 FreeBSD 阵营所批评的形式主义的镜像；其四，Docker 官方文档的叙事选择构成事实层面的“沉默抹除”——经查证 Docker 官方文档“Docker Overview”页面“The underlying technology”小节原文为“Docker is written in the Go programming language and takes advantage of several features of the Linux kernel to deliver its functionality. Docker uses a technology called namespaces to provide the isolated workspace called the container.”，该小节仅提及 Linux namespaces 与 Linux 内核特性，未提及 FreeBSD jails、Solaris Zones 等 BSD 谱系先驱，这一叙事选择既非明确否认亦非明确承认，而是通过“仅叙述 Linux 内核起源”的框架将 jails 排除在容器正史之外，其效果是让 Docker 用户在阅读官方文档时无从知晓 jails 的存在，这比明确否认更有效地实现了先驱的遗忘

**史观**：总纲第 11 条——商品是形式主义，“先驱”话语本身是市场形式主义的反向运作；总纲第 15 条——文化即形式主义，官方文档的叙事框架是文化形式主义的运作
  
**辨析**：Docker 团队是否“公开承认”Jails 影响的考据存疑；Docker 官方文档“Underlying Technology”小节经查证仅明确提及 Linux namespaces，未明确提及 cgroups（cgroups 在该小节未出现，可能在文档其他页面提及），未提及 Jails，但该文档是否构成“否认”先驱存在须审慎判断——“未提及”与“明确否认”有程度差异，Docker 文档的沉默更接近“框架性排除”而非“主动否认” ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；Solomon Hykes 是否在非官方场合（如推文、访谈）提及 jails 须进一步考据 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
