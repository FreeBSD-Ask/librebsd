# 103.2.1 chroot 的历史局限

  **要点**：**chroot(2)** 的引入两说并置〔考据注：一说由 Bill Joy 于 1979 年在 4.2BSD 引入（McKusick，据 SCCS 日志）；另一说 1979 年随第 7 版 Unix 引入、SCCS“出现”系代码搬迁错觉（Warner Losh 考订，另有 Michael Lucas 1975-1979 快照旁证；4.2BSD 实际发布于 1983，“1979 年在 4.2BSD 引入”的年份混搭亦见张力）——两说交锋全文见本文件 PODCAST 区 EP392，辨析明标“尚未完全闭合，须并置裁决”，依核查报告两说并置〕：仅隔离文件系统视图不隔离网络、进程、用户，root 用户可逃逸 chroot；chroot 设计初衷是测试构建环境而非安全隔离

  chroot、Jails 与 Docker 隔离能力对照：

  | 特性 | chroot(1979) | Jails(1999) | Docker(2013) |
| -- | ---------- | --------- | ---------- |
| 引入者 | Bill Joy | Poul-Henning Kamp（波尔-亨宁·坎普） | Solomon Hykes |
| 文件系统隔离 | 是 | 是 | 是 |
| 网络隔离 | 否 | 是（IP 绑定） | 是（veth） |
| 进程隔离 | 否 | 是 | 是（PID namespace） |
| root 权限限制 | 否 | 是 | 是（capabilities） |
| 内核共享 | 是 | 是 | 是 |

**史料**：chroot(2) 手册页、4.2BSD 文档、chroot 安全分析论文 ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔存疑：原挂总纲第 25 条系伪标签（权威第 25 条为“逻辑是形式主义而非世界本身的结构”），“终结与延续”语义依族例改挂第 3 条，语境适配未经总纲原文逐字复核〕，Jails 终结 chroot 安全用途，延续文件隔离
  
**辨析**：chroot 是否 “完全不安全” 存在争议，非 root 进程仍有一定隔离
