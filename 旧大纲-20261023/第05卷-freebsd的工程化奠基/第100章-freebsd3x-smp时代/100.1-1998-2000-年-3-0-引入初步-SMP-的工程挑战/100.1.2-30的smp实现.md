# 100.1.2 3.0 的 SMP 实现

  **要点**：FreeBSD 3.0(1998.10) 引入初步 SMP，采用单一 Giant Lock 但允许中断在任意 CPU 处理，IPI(处理器间中断) 机制用于 CPU 间通信；SMP 支持通过 SMP 内核选项启用，默认 UP 内核仍可用
  
**史料**：SVN 仓库 sys/i386/i386/ 模块 SMP commit、3.0 SMP 配置文档、freebsd-smp 邮件列表；freebsd.duckdb freebsd-src 仓库 tags 表 release/3.0.0 的 tagger_date = 1999-01-21T00:55:32Z（target_commit_hash = 76b5366091f76c9bc73570149ef5055648fc2c39），与官方公告的 1998.10.16 发布日期存在时差，按 0 信任原则推断 tagger_date 反映 2020 年 SVN-to-Git 迁移期 tag 重打时间而非原始 release tag 时间，采信官方公告 1998.10.16 ［A］
  
**史观**：实践先于理论，3.0 SMP 是渐进式实践而非理论最优设计
  
**辨析**：3.0 SMP 是否 “真正” 支持多 CPU 存在争议，Giant Lock 下同时刻仅一 CPU 在内核态；bsd_commits.duckdb 中 3.0 tagger_date(1999-01-21) 与 4.0 tagger_date(2000-03-20)、5.0 tagger_date(2003-01-16) 间隔模式不符合同一迁移规则下应有的 “约 1 年/3 年间隔” 规律，进一步印证 3.0 tag 在迁移期被重打；【0 信任原则·SVN-to-Git 迁移】L2.2.1.sys_kern 数据基于 2020 年 SVN-to-Git 迁移后的仓库，迁移过程中转换脚本可能引入日期偏差或作者归属错误，sys/kern 路径匹配 sys/kern% 可能漏掉重命名后的文件，须与 SVN 时代邮件列表存档交叉验证；bsd_commits.duckdb 查询 L2.3.1.smp（SMP 特性引入周期）在已读取的中观模式挖掘报告中未找到对应数据段落，SMP 特性的 commit 级引入时间线存疑，待后续直接查询数据库补充
