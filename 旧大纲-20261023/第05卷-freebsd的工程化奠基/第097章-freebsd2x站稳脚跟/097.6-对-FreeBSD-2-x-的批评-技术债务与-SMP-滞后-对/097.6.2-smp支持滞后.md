# 097.6.2 SMP 支持滞后

  **要点**：FreeBSD 2.x 的 SMP 支持仅限于单一 Giant Lock，内核同一时刻只能有一个 CPU 执行内核代码，在多 CPU 服务器上扩展性极差，而同期 Solaris 2.6 已实现细粒度锁，Linux 2.2 已开始 BKL 细化
  
**史料**：freebsd-smp 邮件列表 1996-1999 年讨论、Giant Lock 实现代码、Solaris 2.6 内核锁文档；**freebsd.duckdb** 查询 L1.4.1 显示：FreeBSD 2.x 系列 release tag 间隔天数——release/2.1.0 至 release/2.1.5 间隔 278 天、release/2.1.5 至 release/2.1.7 间隔 156 天（含 2.1.6.1 中间 tag 121 天）、release/2.2.0 至 release/2.2.1 间隔 9 天、release/2.2.5 至 release/2.2.6 间隔 154 天、release/2.2.7 至 release/2.2.8 间隔 180 天，2.2.x 系列平均 release 间隔约 4 个月，反映 2.x 时期稳定版维护节奏；2.2.8（1999-01-21）与 3.0.0（1999-01-21）tagger_date 同日——经实查两行为同一秒的 cvs2svn 迁移重构 tag（00:55:30 与 00:55:32），同日系迁移伪影而非历史接续证据；库内原始行 release/3.0.0=1998-10-16、release/2.2.8=1998-11-30，实际 3.0 先于 2.2.8 约一个半月 ［A］
  
**史观**：总纲第 21 条——革命与改革是历史方法论的分歧（原“硬件与软件辩证”系自创名目，按报告处方重挂），多 CPU 硬件普及倒逼 FreeBSD 在 3.x/5.x 推行 SMPng
  
**辨析**：SMP 滞后是工程选择还是技术能力不足存在争议，Core Team 优先稳定性而推迟 SMP 的决策需放在 2.x 时期 ISP 单 CPU 为主的背景下理解；【0 信任原则·SVN-to-Git 迁移】L1.4.1 部分.tag 为 svn2git 重构时打的标签（tagger_name =‘svn2git’），非原始发布时间，2.x 时期部分 tagger_date 可能在 2008 年 CVS→SVN 与 2020 年 SVN→Git 两次迁移中引入日期偏差，须与 SVN 时代邮件列表存档交叉验证；【0 信任原则·release tag 不等于实际发布】部分 release tag 与正式 Release Announcement 日期可能相差 1-2 日（如 2.2.5 tagger_date = 1997-10-21 而 Release Announcement 为 1997-10-22），考据时须以 Release Announcement 为准
