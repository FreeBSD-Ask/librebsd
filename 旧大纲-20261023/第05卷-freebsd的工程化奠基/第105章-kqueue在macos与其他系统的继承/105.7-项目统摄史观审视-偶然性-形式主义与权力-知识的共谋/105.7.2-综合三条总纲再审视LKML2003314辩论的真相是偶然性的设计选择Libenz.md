# 105.7.2 综合三条总纲再审视LKML2003314辩论的真相是偶然性的设计选择Libenz

综合三条总纲再审视，LKML 2003.3.14 辩论的真相是：偶然性的设计选择（Libenzi 的 composable 与 Lemon 的 filter 中心化）在形式主义化的修辞争夺中被重构为必然性的归属判断（“过度膨胀” vs “语义丰富”），而权力-知识共谋（LKML 的主场/客场不对称、市场份额作为设计优越性证据）塑造了什么被记录（Libenzi 的 epoll 设计哲学）、什么被遗忘（kqueue 对 epoll 的实际影响程度）。史家的任务不是在 “过度膨胀” 与 “语义丰富” 之间做出技术胜负判定，而是揭示这一争议本身的形式主义性质与权力-知识共谋机制，并在解释学循环中保持对前理解的自反意识——这一立场本身亦须接受 0 信任原则的审视，避免沦为无立场的相对主义或隐蔽的阵营偏见。

### 史观映射

> kqueue 的设计哲学只有一个字：消。它不是在堆功能，而是在消解 select 与 poll 的复杂性——用一个统一的 filter 接口替代两套过时的 API，这就是简洁即消解的美。但 Conill 说它是“技术债务堆积如山”，Libenzi 用 epoll 的 composable 设计证明 kqueue 的 filter 中心化是“每新增一种资源就新增一种 filter”的累赘——简洁的代价是扩展时必须改内核，而 epoll 不用。美感被工程便利击败，不是第一次了
