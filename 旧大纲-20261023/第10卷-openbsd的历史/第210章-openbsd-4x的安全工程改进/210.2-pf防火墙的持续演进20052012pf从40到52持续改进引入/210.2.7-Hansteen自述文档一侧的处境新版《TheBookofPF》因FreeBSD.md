# 210.2.7 Hansteen自述文档一侧的处境新版《TheBookofPF》因FreeBSD

- Hansteen 自述文档一侧的处境：新版《The Book of PF》因 FreeBSD 与 NetBSD 移植 4.7 等价代码的时间无从预料，索性完整收录新旧两套示例；现役版本中古老的 FTP proxy 示例被整体移除，而 FTP proxy 是一项“长期的挣扎”，已第三次从头实现；三大 BSD 的 PF 已严重分叉，FreeBSD 基线约为 4.1 加补丁。（BSDTalk EP192，[1082.60-1178.20]，L1）[订正：原 [1077.74-1185.94]，2026-09-30 SenseAudio 重转核对]
- 作者本人完整口述 CARP 协议定名史：因 VRRP 受专利阻碍，OpenBSD 向 IANA 申请多播地址被拒，遂复用 VRRP 的多播地址与报头格式，使 CARP 报文自称为 VRRP 版本 3，从而永久占据该版本号；PFSYNC 申请协议号同样被 IANA 拒绝，该号码现被列为保留。此口述为研究 CARP 协议诞生时标准组织与专利环境作用的一手材料。（BSDTalk EP214，[1037.12-1131.48]，L1）
- 受访者自述 BGPD 过滤器引擎最初仅是线性匹配的工作原型而非最终设计，无法扩展至十万条路由级别：阿姆斯特丹 AMS-IX 互联网交换点实际在用，而法兰克福 DE-CIX 因约十万条路由的复杂过滤需求无法使用；重写过滤器引擎与过滤语言的计划因缺乏人力长期搁置。该自述同时记录了 BGP 会话 TCP MD5 保护在 OpenBSD 借由 IPsec 框架实现及 FreeBSD 侧跟进的线索。（BSDTalk EP214，[2925.0-3086.08]，L1）
- 受访者供职昆士兰大学工程建筑与信息技术学院并管理全院技术栈，构成大规模 PF 生产部署的一手数据：十三四栋楼各设员工、实验室与受管设备三类网络，连同隔离区合计约六十个网络；中央防火墙对仅三个物理接口，其上叠加六十个 VLAN 与 CARP 地址接口，接口总数过百，上游经 OSPF 取缺省路由，客户端侧以 CARP 通告缺省网关。接手时继承六台 FreeBSD IPF 防火墙、各载两千至一万六千条规则合计约四万条，整合至一对 OpenBSD 防火墙后借 PF 语言特性先降至四千五百条、再降至约两千三百行，规则文件以 vi 编辑并纳入 Subversion 版本控制。（BSDTalk EP219，[1317.78-1547.34]，L1）
- TFTPD 重写的一手缘由：学院实验室镜像原以单播方式逐台分发且镜像日益庞大，管理者须在学期初数周人工排队调度镜像服务器；改用 BitTorrent 后启动环境连带更换，TFTP 在此场景暴露可扩展性问题，促成 5.2 全新 TFTPD 与 5.3 TFTP 代理替换。受访者另证实 Debian 缺省收录 OpenBSD 的小型网络守护进程，其本人在 Debian 系统上也使用 OpenBSD 的 TFTP 守护进程，为 OpenBSD 用户态工具跨发行版扩散提供当事人证词。（BSDTalk EP219，[1657.2-1731.44]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：match 规则今日被视为 PF 的根基，其诞生却是偶然的聚合：一个 2003 年起的个人执念多年无人附议，恰逢 NAT 改造的工程需要才获得实现契机，连实现者本人也未曾预料其根本性——数年前社区 consensus 还将其斥为无用的东西。技术共识的方向并不由先验论证决定。（BSDTalk EP192，[214.34-251.26]，L1）
- 总纲22 知识注定过时：文档作者随 4.7 双轨重写全部示例、FTP proxy 第三次从头再来、man page 因黏着性语义反复改写，共同印证围绕活跃系统的技术知识注定过时：写作者的劳动不是记录恒定之理，而是追赶形式不断重铸的表述。（BSDTalk EP192，[1136.42-1157.26]，L1）
- 总纲9 经验优先：PFSYNC 主主负载分担在技术上不可能真正高效：同步状态表使每条连接的工作量翻倍，防御手段唯有延迟并批量打包同步报文，而这又引入级联延迟；据此作者依据真实运维经验主张生产环境采用平淡的主备两节点配置，认为多节点增加的复杂性本身就在提高失败概率。可靠性来自尽量简单的工程判断，是对炫目特性优先的价值观反驳。（BSDTalk EP214，[1203.64-1429.22]，L1）
- 总纲4 分离聚合是永恒规律：三大 BSD 自 1995 年最后一次分叉后已各自独立开发逾十五年，但当事人观察认为 OpenBSD 与 FreeBSD 在用户视角下的差异小于共享同一代码基础的若干 Linux 发行版之间的差异；BSD 项目间的技术互取被视为理所当然而不必每两周重造轮子。分叉后的再聚合以技术共享而非代码合并的形式延续，呈现分离与聚合的循环结构。（BSDTalk EP214，[3225.86-3283.85]，L1）
- 总纲4 分离聚合是永恒规律：受访者以年龄与经验变化解释其向软件 RAID 的转移：设备与磁盘之间的抽象越少，栈的上层越容易做聪明的事；随着 Dynamo 论文及 Riak、Voldemort、Cassandra 等实现在应用层接管数据存活与冗余，磁盘层高可用降为次要关切。数据冗余职责由硬件 RAID 层向应用层转移，存储栈呈现逐层分离再聚合的演进结构。（BSDTalk EP219，[309.26-399.72]，L1）

**辨析**：

- 语义陷阱与保守策略并存：match 与 pass 在动作黏着性上不同，旧 PF 实现中许多动作不黏着本属设计缺陷，却不可更改——旧规则集仍会被加载，静默改变行为过于危险，man page 为此打磨良久；NAT 只能出向、RDR 只能入向的旧限制源于返回流量路由查找使用未改回的地址，4.7 以 pfctl 的简单检查阻止反向用法，Brauer 倾向未来移除检查并以文档说明后果，4.8 或许放开。（BSDTalk EP192，[805.30-1057.90]，L1）[订正：原 [805.32-1049.02]，2026-09-30 SenseAudio 重转核对]
- Apple 在 OS X 中维护自己的 PF 分支，受访者称 Apple 是 FreeBSD 代码的主要消费者之一，且 OS X 上存在相当数量手写 PF 配置的用户；Peter Hansteen 愿意为移植提供协助，而 Henning Brauer 对是否关心 Apple 分支态度冷淡。FreeBSD 是否会跟进新版 PF 在访谈中仅为推测与期望，未见任何一方的正式承诺，须以 FreeBSD 源码树与提交记录核证。 [存疑脚注] FreeBSD 跟进新版 PF 与 Apple PF 分支的维护细节均为访谈中口头推测，非正式路线陈述（BSDTalk EP214，[439.96-491.92]，L4）
- bioctl 统一管理硬件与软件 RAID 的设想在访谈中仍停留在意图层面：受访者坦言各厂商在术语、布局与物理盘到逻辑盘的抽象上差异过大，找出让接口易用的统一抽象尚无成案，只确立硬件 RAID 无非带磁盘的磁盘、应如 ifconfig 一般寻址的方向。该统一接口理想当时未兑现，考据 bioctl 能力边界时应以其后手册页与源码为准。 [存疑脚注] bioctl 统一抽象的实现进度在访谈时点为未完成设想，后续进展须以源码树核证（BSDTalk EP219，[235.76-309.26]，L1）
