# 212.5.4 合图——OpenSSH fork 的辩证综合

**要点**：合图层综合 Ylönen 阵营与 OpenBSD 阵营的论点，指出二者非对立而是互补——（1）双方权利的对称合法性：Ylönen 将 SSH 1.2.13+ 转为商业许可是对其软件的商业决策权行使，OpenBSD fork SSH 1.2.12 是对自由许可权利的合法行使——两方在法律层面均正当，“商业可持续性”与“软件自由”是两种合法但不同的价值观；（2）贡献的互补性：Ylönen 的数年开发创造了 SSH 的技术基础（协议设计、核心实现、安全架构），OpenBSD 团队的审计与纯洁化创造了 OpenSSH 的安全标准（代码审计、许可证合规、privilege separation 架构）——OpenSSH 成为全球标准是双方贡献叠加的结果而非单方成就，Ylönen 的原创与 OpenBSD 的审计缺一不可；（3）“纯洁化”叙事的辩证定位：合图层不否定“纯洁化”工作的技术价值（移除非可移植代码确实提升可审计性、移除 GPL 组件确实使 OpenSSH 可在 BSD 许可下发布），但指出“纯洁化”叙事的道德预判须经 Ylönen 阵营的对称呈现后方可评估——“纯洁化”是法律与技术层面的正当工作，但“纯洁化”叙事在道德层面不应将 Ylönen 定位为“限制者”而将 OpenBSD 定位为“解放者”，双方均为各自价值观的合法行使者；（4）合图不追求“消除分歧”：Ylönen 阵营与 OpenBSD 阵营的前理解差异（总纲第 19 条）使分歧不可避免——Ylönen 阵营以“商业可持续性”为预设，OpenBSD 阵营以“软件自由”为预设，两套预设基于不同价值观，合图不是“消除分歧”而是“在分歧中呈现各主体性”

**史料**：OpenSSH 项目历史页面（记载"derivative of the original free ssh 1.2.12 release from Tatu Ylönen“与”Parts of OpenSSH still bear Tatu's license"——归属承认的存在）；参见 OpenSSH 专章诞生、纯洁化、全球部署与比较记录；SSH Communications Security 商业产品页面（<https://www.ssh.com/>）；参见“结构与偶然的合图”方法论相关章节 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：OpenSSH 从 SSH Communications Security 的商业实现分离后聚合入 OpenBSD 源码树，再从 OpenBSD 聚合入 FreeBSD、NetBSD 与各 Linux 发行版——分离以法律结构（自由许可）为基础，聚合以 BSD 许可证为法律基础；总纲第 19 条——解释学循环是历史认识的根本条件：合图层承认 Ylönen 阵营与 OpenBSD 阵营的前理解差异使 fork 争议的分歧不可避免，合图不是“消除分歧”而是“在分歧中呈现各主体性”——“权力与知识在历史书写中共谋”：什么被记录为“解放 SSH”、什么被记录为“fork SSH”，本身就是权力行使；总纲第 21 条——革命与改革是历史方法论的分歧：Ylönen 的商业化是“革命”（以新许可证模型替换自由许可），OpenBSD 的 fork 是“改革”（在 SSH 1.2.12 基础上渐进审计与纯洁化而非从零重写）——“改革的困难远高于革命”，OpenBSD 的渐进审计与纯洁化比 Ylönen 的许可证革命更具工程复杂度

**辨析**：合图的解释力须经具体场景评估并以三段式呈现——【查证来源】（1）OpenSSH 官方历史页面（<https://www.openssh.com/history.html>）经 2026-07-23 WebFetch 一手核验，确认"derivative of the original free ssh 1.2.12 release from Tatu Ylönen“与”Parts of OpenSSH still bear Tatu's license"措辞均原文存在，证实合图层的“归属承认”有 OpenBSD 阵营的一手自陈；（2）openbsd.duckdb openbsd-src 仓库 commits 表验证：fork 启动 commit `84959968510b`（deraadt，1999-09-26T20:53:32Z）与 OpenSSH-1.0 commit `bf74e864c129`（deraadt，1999-10-01T18:58:56Z）共同证实 OpenBSD fork 的代码级起点；Provos libgmp 移除完整时间线（commit `76c6bcb9f8b9`/`d9d42abc7ed4`/`84174f65ff52`/`348a6efc411d`，1999-09-28 至 2000-12-15）证实“纯洁化”工作的工程复杂度；Beck 1999.09-2000.12 期间 40 条 ssh 相关 commit 证实 OpenSSL/RSA/Makefile 处理的工程参与；openbsd.duckdb 同时记录 Ylönen 在 openbsd-src 仓库的 commit 为 0 条，证实 Ylönen 阵营在 OpenBSD 代码库层面无直接贡献记录——但“无代码 commit”不等于“无贡献”，Ylönen 的原创贡献体现在 SSH 1.2.12 的源码本身（OpenBSD fork 的起点）而非 OpenBSD 仓库的 commit 历史；【交叉验证方法】（1）“对称合法性”的边界：Ylönen 的商业许可与 OpenBSD 的 fork 在法律层面均正当，但在道德层面存在张力——Ylönen 阵营可论证 OpenBSD 的 fork 削弱了 SSH 的商业可持续性（参见 212.5.1 节“投资回报断裂”论点），OpenBSD 阵营可论证 Ylönen 的递进限制使 SSH 的自由使用范围逐步收窄（参见 212.5.2 节“许可证递进限制”实证），两种道德论证须对称呈现而非以一方压制另一方——“对称”须经 SSH 1.2.12 原始许可证文本、OpenSSH LICENCE 文件、SSH Communications Security 商业许可证声明三方比对核实，不得仅凭哲学推论即断定“对称”；（2）“贡献互补性”的边界：Ylönen 的原创与 OpenBSD 的审计确为互补，但“互补”不等于“等价”——Ylönen 创造了 SSH 的技术基础（从零到一），OpenBSD 在此基础上审计与纯洁化（从一到标准），两类贡献的性质不同，“互补”须区分“原创贡献”与“改进贡献”——openbsd.duckdb 显示 OpenBSD 阵营在 fork 后 14 个月（1999-09 至 2000-12）持续提交 libgmp 移除与代码审计 commit，证实“改进贡献”的工程量，但这一工程量须与 Ylönen 数年（1995-1999）开发 SSH 1.0 至 1.2.12 的原创工程量分别评估，不得以 commit 量直接对比两类贡献的“价值”；（3）合图的辨析边界——合图须区分“有史料支撑的合图”（基于 OpenSSH 官方历史的归属承认、openbsd.duckdb commit 记录、OpenSSH 专章考据的多因素分析）与“无史料支撑的折中”（为回避立场而强行调和的折中主义），前者须保留，后者须剔除；【0 信任原则·合图须考据】合图的“双方权利对称合法性”须经 SSH 1.2.12 原始许可证文本、OpenSSH LICENCE 文件、SSH Communications Security 商业许可证声明交叉验证，不得仅凭哲学推论即断定“对称”；【存疑判定依据】（1）“对称合法性”的道德边界存疑：openbsd.duckdb 的代码级证据可证实双方在法律层面的正当性（Ylönen 的商业许可变更与 OpenBSD 的 fork 均为合法行使许可权利），但道德层面的“对称”无法以代码级证据判定——Ylönen 阵营的“投资回报断裂”道德论证与 OpenBSD 阵营的“软件自由”道德论证须以 comp.security.ssh Usenet 1999-2000 年存档、SSH Communications Security 官方声明、OpenBSD misc@ 邮件列表 1999-2000
