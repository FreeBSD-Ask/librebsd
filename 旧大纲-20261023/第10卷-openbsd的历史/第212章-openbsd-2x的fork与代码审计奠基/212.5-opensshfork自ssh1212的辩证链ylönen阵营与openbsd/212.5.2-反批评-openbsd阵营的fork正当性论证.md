# 212.5.2 反批评——OpenBSD 阵营的 fork 正当性论证

**要点**：OpenBSD 阵营的 fork 正当性论证沿四条线索展开——（1）许可证权利的合法行使：SSH 1.2.12 以自由许可发布，fork 是对自由许可权利的合法行使，Ylönen 在发布 1.2.12 时授予复用权，后续版本的商业许可不影响 1.2.12 的许可状态；（2）许可证递进限制的实证：OpenSSH 官方历史记载，1.2.12 之后的 SSH 版本“带有逐步更严格的许可证”（bore successively more restrictive licenses）——“第一个限制性许可证禁止制作 Windows 或 DOS 版本”（forbade people from making a Windows or DOS version），“后来的许可证限制了 ssh 在商业环境中的使用，要求公司向 Datafellows 购买昂贵版本”（restricted the use of ssh in a commercial environment, instead requiring companies to buy an expensive version from a company called Datafellows）——许可证递进限制使 SSH 的自由使用范围逐步收窄；（3）GPL 违规的技术困境：OpenSSH 官方历史记载，1.2.12 之后的版本仍包含 libgmp（GPL 许可），但商业许可证与 GPL 不兼容，“这实际上使 SSH 成为 GPL 违规”（That effectively made SSH a GPL violation）——OpenBSD 阵营可论证 Ylönen 的商业许可变更不仅在道德上“限制自由”，在法律上亦与 GPL 组件产生冲突；（4）社区需求驱动：OpenBSD 需要在 2.6 发行版中集成 SSH，但商业许可使集成不可能，fork 是满足社区对自由 SSH 实现的需求的必要路径

**史料**：OpenSSH 项目历史页面（<https://www.openssh.com/history.html>，记载“bore successively more restrictive licenses”、“forbade people from making a Windows or DOS version”、“restricted the use of ssh in a commercial environment”、“That effectively made SSH a GPL violation”）；OpenSSH LICENCE 文件（<https://cvsweb.openbsd.org/src/usr.bin/ssh/LICENCE>，记载各组件许可证组合）；openbsd.duckdb openbsd-src 仓库 commit 84959968510b（1999-09-26 deraadt 初始导入）、commit bf74e864c129（1999-10-01 deraadt“OpenSSH-1.0”）；参见 OpenSSH 专章诞生与许可证纯洁化记录 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配（原“法律结构”挂第 12 条系错配，按许可证利益论旨改挂）：OpenBSD 阵营的 fork 正当性基于法律结构——SSH 1.2.12 的自由许可授予复用权，后续版本的商业许可不影响已发布版本的许可状态；总纲第 4 条——分离聚合是永恒规律（原“分离与聚合”挂第 2 条系编号错挂，正名）：OpenSSH 从 SSH Communications Security 的闭源实现分离后聚合入 OpenBSD 源码树，分离以法律结构（自由许可）为基础

**辨析**：OpenBSD 阵营论证的考据须遵循 0 信任原则——【查证来源】（1）OpenSSH 官方历史页面（<https://www.openssh.com/history.html>）经 2026-07-23 WebFetch 一手核验，确认“bore successively more restrictive licenses”“forbade people from making a Windows or DOS version”"restricted the use of ssh in a commercial environment, instead requiring companies to buy an expensive version from a company called Datafellows"“That effectively made SSH a GPL violation”等措辞均原文存在；（2）openbsd.duckdb openbsd-src 仓库 commits 表验证：Provos 移除 libgmp（GPL 组件）的代码级证据——commit `76c6bcb9f8b9`（provos，1999-09-28T04:45:35Z，commit subject 原文"convert all uses of gmp to SSL bignum convert all used of rsa to SSL rsa functions"），证实 fork 后两天即启动 libgmp→SSL bignum 转换工作；commit `84174f65ff52`（provos，2000-12-12T00:46:49Z，subject“gmp gone”）与 commit `348a6efc411d`（provos，2000-12-15T01:58:27Z，subject“more cleanup. remove last vestiges of gmp”）证实 libgmp 移除工作延续至 2000 年 12 月方告完成；commit `d9d42abc7ed4`（provos，2000-12-11T02:22:53Z，subject“another piece of GPL software gone”）进一步证实 GPL 组件移除是系统工程而非单点修复；【交叉验证方法】（1）OpenSSH 官方历史页面（一手叙事）与 openbsd.duckdb commit 记录（一手代码级证据）交叉验证“GPL 违规”论点——官方历史称 SSH 1.2.12 之后的版本“商业许可证与 GPL 不兼容构成 GPL violation”，openbsd.duckdb 显示 Provos 在 fork 后立即（1999-09-28，距 fork 启动仅 2 天）启动 libgmp→SSL bignum 转换，至 2000-12-15 完成“remove last vestiges of gmp”，这一时间线证明 OpenBSD 阵营确实以移除 GPL 组件为正当性论证的技术基础；（2）“许可证递进限制”的具体许可证文本须经 SSH Communications Security 历年许可证文件原始文本核实，不得仅凭 OpenSSH 官方历史的转述即采信——OpenSSH 官方历史是 OpenBSD 阵营的单方面叙事，其“freeing SSH”与“cleaning up the license mess”措辞存在自利偏差，将 fork 定位为“解放”与“清理”使 OpenBSD 阵营占据道德高地，Ylönen 阵营的对称叙事须以 comp.security.ssh Usenet 存档与 SSH Communications Security 官方声明补全；（3）“社区需求驱动”论点须与 OpenBSD 2.6 Release Notes 交叉验证——OpenBSD 2.6（1999.12）确实集成 OpenSSH 1.0，但“fork 是唯一路径”的论点须考据，OpenBSD 亦可选择不集成 SSH 或集成其他自由 SSH 实现（如 Lsh），fork SSH 1.2.12 是选择而非必然；【存疑判定依据】（1）“GPL 违规”论点的法律有效性边界：GPL 违规的判定权在 GPL 许可证持有者（FSF 与 libgmp 作者 T. Granlund），而非 OpenBSD 阵营，OpenBSD 阵营以“GPL violation”论证 fork 正当性存在法律越位风险——openbsd.duckdb 显示 Provos 的 libgmp→SSL bignum 转换工作（commit `76c6bcb9f8b9`，1999-09-28）证明 OpenBSD 阵营主动移除 GPL 组件以使 OpenSSH 可在 BSD 许可下发布，但“移除 GPL 组件”与“指控 Ylönen 的 SSH 1.2.13+ 为 GPL 违规”是两个不同层面——前者是技术必要，后者是法律判断，两者不得混淆；（2）“Provos 赴加拿大移除加密与 GPL 组件”的代码级证据待补：openbsd.duckdb 查询显示 Provos 在 1999.09-2000.12 期间持续提交 libgmp 移除相关 commit，但 commit 元数据未直接记录“Provos 赴加拿大工作”这一地理位移——Provos 赴加拿大的史实须经 OpenBSD misc@ 邮件列表 1999-2000 年存档、Provos 个人主页或访谈、OpenBSD Jumpstart 项目介绍交叉验证后方可采信，保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；（3）“Friedl 替换 SSH 1.3 协议为 1.5”的 openbsd.duckdb 查询结果：以“friedl”为 author_name 与“ssh”“protocol”“1.3”“1.5”为关键词组合查询 commits 表，未直接匹配到 Friedl 协议替换相关 commit（0 条匹配），Friedl 协议替换工作须经 OpenSSH 邮件列表存档与 OpenSSH 官方历史页面交叉验证后方可采信，保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；（4）Beck 处理 OpenSSL/RSA/Makefile 的代码级证据：openbsd.duckdb 查询显示 Beck 在 1999.09-2000.12 期间共 40 条 ssh 相关 commit，涉及 Makefile、OpenSSL、RSA 专利规避，与 OpenSSH 官方历史所载“Beck 处理 Makefile 避开 RSA 专利”叙事吻合
