# 214.4.5 批评层——de Raadt 单方面撤权与 PF 移植的批评

**要点**：对 de Raadt 单方面撤权与 PF 移植到 FreeBSD 的批评集中于四点——其一，de Raadt 个人主导的权限模型缺乏程序正义，新 committer 由 de Raadt 邀请无正式提名流程，撤权由 de Raadt 单方面决定无申诉机制，对比 FreeBSD Core Team 集体决策与 NetBSD Foundation 董事会审议的“程序正义”，OpenBSD 的“个人独裁”在治理合法性上受质疑；其二，PF 移植到 FreeBSD 与 NetBSD 导致 OpenBSD 失去对 PF 代码演进的主导权——FreeBSD 在移植后对 PF 进行 FreeBSD 特定的修改（如 anchor 机制扩展、FreeBSD 风格的配置语法），OpenBSD 上游与 FreeBSD 下游的 PF 代码逐步分化，OpenBSD 作为 PF 原作者的“话语权”被 FreeBSD 移植维护者稀释；其三，de Raadt 在 IPFilter 许可证变更（2001.5.30）后选择 fork 而非与 Darren Reed（达伦·里德） 协商的“对抗性路径”被批评为意识形态优先于工程实用——IPFilter 在许可证变更后仍被 Linux/Solaris 等系统使用，OpenBSD 的 fork 是否真正解决了 IPFilter 的工程问题存疑；其四，PF 与 FreeBSD IPFW、Linux iptables 的“性能对比”中 PF 不占优势——FreeBSD IPFW 在原生性能测试中领先，Linux iptables 在灵活性上领先，PF 的状态跟踪与简洁语法是其优势但在性能与灵活性上不构成对其他防火墙的压倒性优势

**史观**：总纲第 8 条——本体论上各方平等：de Raadt 与被撤权者、OpenBSD 阵营与 FreeBSD PF 移植维护者、Darren Reed 与 de Raadt 在本体论上地位平等——撤权与 fork 的争议是平等主体间的分歧，不构成任何一方的本体论优越或劣等；商业与社区的张力：PF 移植至 FreeBSD 后 FreeBSD 维护者对 PF 的修改反映商业社区（FreeBSD 因企业部署需求驱动 PF 演进）与原社区（OpenBSD 因安全审计需求驱动 PF 演进）的张力

**辨析**：【0 信任原则·程序正义批评的语境性】“个人独裁缺乏程序正义”的批评须以 OpenBSD 项目目标语境评估——OpenBSD 的“安全至上”目标与 de Raadt 个人主导的“快速决策”模式存在工程效率上的契合，程序正义的缺失不等于工程效率的失败；【PF 移植主导权稀释的实证】FreeBSD 对 PF 的具体修改清单须以 freebsd.duckdb freebsd-src 仓库 sys/netpfil/pf/ 目录 commit 历史核验，不得仅凭推测；【IPFilter fork 必要性的辨析】Darren Reed 在 IPFilter 3.4.31 许可证变更后的具体条款须对照原始 LICENSE 文件核验，“不得修改或重新分发”的条款是否实质影响 OpenBSD 的 BSD 许可证传统须具体分析；【性能对比的方法论】PF 与 IPFW/iptables 的性能对比须以同硬件同负载的第三方 benchmark（如 Phoronix）为准，不得仅凭单方面声明；【多源交叉验证不可靠性规则】多个 Linux 社区批评者在“PF 性能不占优势”上的一致可能源于 Linux 阵营的共同立场而非独立验证
