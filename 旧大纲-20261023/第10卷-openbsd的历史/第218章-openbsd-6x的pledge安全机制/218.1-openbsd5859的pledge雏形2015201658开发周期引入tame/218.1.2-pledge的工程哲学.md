# 218.1.2 pledge 的工程哲学

**要点**：pledge 的设计哲学是“让程序员轻松做正确的事”——程序自愿声明权限而非被动接受沙箱，声明接口简洁（`pledge("stdio rpath", NULL)` 一行即可），避免 Linux seccomp 的复杂 BPF 过滤器；de Raadt 在 tech@ 邮件列表中主张 pledge 应简化至程序员愿意主动使用的程度；pledge 最初用于 OpenBSD 自带的用户态工具（如 **tcpdump(1)**、**nc(1)**），后续扩展至更多基本系统程序

**史料**：de Raadt 在 tech@ 关于 pledge 哲学的发言（<https://marc.info/?laccopenbsd-tech>）；OpenBSD pledge 设计文档；**pledge(2)** 手册页 DESIGN 部分（<https://man.openbsd.org/pledge.2>）；openbsd.duckdb openbsd-src 仓库 pledge 相关 commit（2015-10-09 起 deraadt、semarie、benno 等的 commit）〔L1 代码/构建产物/L2 即时通讯记录/L3 官方文档与公告〕

**史观**：软件工程：pledge 的设计哲学是 OpenBSD 对软件工程的独特理解——安全机制的可采用性取决于接口简洁度，复杂的沙箱接口（如 seccomp BPF）因使用门槛高而采用率低，pledge 以“一行声明”降低采用门槛，使安全约束成为程序员的主动选择而非被动负担

**辨析**：pledge 与 seccomp 的工程哲学比较——两者设计目标不同，seccomp 以 BPF 过滤器提供细粒度系统调用控制但配置复杂，pledge 以预定义权限类别提供粗粒度控制但配置简洁；pledge 的“自愿”特性是否导致使用率不足——OpenBSD 基本系统中 pledge 覆盖率以 Release Notes 与 commit log 中 pledge 相关 commit 计数为准，基本系统主要用户态工具已普遍采用 pledge
