# 218.1.6 节目解读OpenBSD的pledge机制程序在完成启动阶段所需的特权操作后调用p

- 节目解读 OpenBSD 的 pledge 机制：程序在完成启动阶段所需的特权操作后调用 pledge 承诺此后仅使用特定资源，违约即由内核以 SIGABRT 终止；execpromises 可为子进程单独设定承诺集，error 标志使违约返回错误而非杀死进程。（BSD Now EP236，[0.0-463.3]，L2）

- Bryan Cantrill 指出 POSIX 将 madv_dontneed 定义为“近期不再使用此内存”的建议，FreeBSD 与 illumos 将其实现为纯粹的页面置换优先级建议并保留映射，Linux 却将其实现为立即撕毁映射并保证再次访问读到全零，语义与所有其他 Unix 截然不同；Joyent 团队严格按建议语义实现该调用后，依赖 Linux 破坏性语义的 jemalloc（随 Facebook 代码引入）在生产环境于调用栈深处离奇崩溃，且因无帧指针而难以取得栈回溯，排查极为艰难。他还以 mmap 为例说明“撕毁映射要击落 TLB、改写页表”的真实开销，批评依赖未经度量的直觉判断系统性能。（BSD Now EP117，[3446.14-3786.44]，L1）
- Cantrill 阐明 BSD、illumos 与 Linux 对“操作系统”边界的定义分歧：前二者视操作系统为内核、用户态与系统工具的整体，ls 亦属操作系统；Linux 则只是内核，GNU 栈与 glibc 皆属发行版层面，这也解释了 GNU 与 Linux 之争的根源。正因 Linux 将 ABI 僵化地锚定在系统调用层且极不情愿破坏任何应用，SmartOS 得以在 LX 品牌化区域中完整实现 Linux 系统调用表使 Linux 二进制直接运行；该机制原为 Sun 所创、因当年 Linux 演进过快而封存，2014 年由社区成员在区域内跑通 Linux 版 Skype 而意外复活，此后经 2014 至 2015 年推向完成。（BSD Now EP117，[2111.92-2333.50]，L1）

- Delphix 的 George Wilson 阐明 Compressed ARC 的设计路线：放弃业界通行的内存换出前压缩方案，利用磁盘块本已压缩的事实，让内存始终保持压缩形态、仅在读取瞬间解压，即“uncompressing data is a heck of a lot faster than compressing it”（2309.42-2314.38）。第一轮激进实现（跨文件系统共享块加回调通知机制）在完成约百分之九十五时暴露重大架构缺陷而中止，第二轮简化方案成为最终交付版本，计划于 2016 年 1 月进入 OpenZFS；实测 ARC 有效容量膨胀约 2.5 至 3 倍，128K 块解压读取约 200 微秒，单核解压吞吐 1.8-2 GB/s，不可压缩块经 shared ARC 共享指针免二次拷贝。（BSD Now EP116，[2258.47-2443.30]，L1）
- Wilson 回顾池恢复工作的起点：入职 ZFS 团队后的首个任务即排查一起客户存储池损坏，通过解析全盘 DD 镜像中的文件头，最终发现损坏根源是一名管理员误将池中磁盘重新分区为 Linux 盘，与 ZFS 本身无关；此后约完成百余次池恢复，多数归因于用户误操作或其他软件的编程错误。他将池恢复视为超越本职、观察用户真实用法的窗口，此叙事呈现了维护者隐性运维经验的生成过程。（BSD Now EP116，[3839.40-3959.18]，L1）

- OpenBSD 在 2015 年开发周期推出实验性沙箱机制 tame：以单个系统调用把进程锁定在有限的操作类别（计算、内存管理、网络、文件描述符写操作、打开文件等）之内，限制可层层叠加且一经放弃不可恢复；相比要求围绕能力模型重写程序的 Capsicum，tame 以更小改造成本换取快速普及，内核部分已合入源码树，userland 改动陆续跟进，cat、ping、httpd、ntpd、syslogd、tcpdump、traceroute 等 29 个基础程序已开始接入。（BSD Now EP99，[87.36-139.34]，L2）
- GLib 维护者 Ryan Lortie 以当事人身份拆解 KDBus 的动因与设计：现行 D-Bus 依赖系统级与会话级两个用户态守护进程中转消息，一次调用需四次上下文切换并伴随大量数据拷贝，且规范强制守护进程逐项校验；KDBus 将内核本身变为消息传递机制，改传不透明数据块并把校验责任移至接收方，其关键依赖 MemFD 配合 sealing，让发送方承诺缓冲区不可变并由内核背书，而这一机制在 BSD 上完全不存在，构成移植的硬缺口；他坦言此前多次把 D-Bus 塞进内核的尝试“皆以失败告终”（2662.99-2677.20），本次团队更强但进展依然艰难。（BSD Now EP99，[2488.84-2649.36]，L1）
