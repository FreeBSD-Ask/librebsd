# 218.3.8 pledge/unveil 设计争议的辩证合图（合图层）

**要点**：pledge/unveil 设计争议的辩证合图——pledge/unveil 既是 OpenBSD 对 seccomp-bpf 与 Capsicum 复杂性的工程回应（反批评层）也是其细粒度局限与可移植性缺陷的具体显现（批评层与再回应层），二者并非非此即彼；pledge/unveil 在 OpenBSD 生态内具有工程合理性（粗粒度类别降低配置错误率、fail-closed 语义提供调用后强制约束、与 unveil 配合形成双重沙箱），但在跨平台生态内具有外部性（复杂应用须人为拆分进程、跨平台应用须单独维护 OpenBSD 分支、与 seccomp/landlock 的过滤精度差距）；合图不寻求“折中”而寻求揭示 pledge/unveil 的结构性张力——它既是 OpenBSD 安全哲学的工程实践也是其生态孤立的具体显现，“简洁自主”与“细粒度不足”是同一决策的共生效应，不可分割；本体论上，pledge/unveil 与 seccomp、Capsicum、landlock 在本体论上地位相等，差异仅是工程哲学的不同而非本体等级的高下——pledge 的“粗粒度正确性”与 seccomp 的“细粒度灵活性”各自在其生态内具有合理性，史家的任务不是判定优劣而是呈现张力；pledge/unveil 的历史意义不在于“取代 seccomp”（这一目标从未实现，亦非 OpenBSD 所求）而在于“证明粗粒度声明式沙箱是可行的安全范式”——pledge/unveil 的存在本身对 Linux landlock（2021 引入的声明式路径限制）与 FreeBSD Capsicum 的工程方向形成对照压力，促使各项目重新审视“简洁性”与“灵活性”的权衡

**史料**：pledge/unveil 与 seccomp/Capsicum/landlock 综合对比研究、BSD/Linux 沙箱机制演进史、OpenBSD Security Advisories 中 pledge/unveil 限制漏洞影响范围的具体案例、Linux landlock 与 pledge/unveil 的设计对照文档〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 8 条——本体论上各方平等：pledge/unveil 与 seccomp、Capsicum、landlock 在本体论上地位相等；总纲第 19 条——解释学循环：pledge/unveil 评估受前理解差异制约，合图不寻求消除差异而寻求呈现差异；总纲第 6 条——和解优于斗争：合图不寻求消除张力而寻求呈现张力，pledge/unveil 与 seccomp/Capsicum/landlock 的共存本身是安全机制生态的多元呈现

**辨析**：合图不寻求消除张力而寻求呈现张力——pledge/unveil 的“简洁自主”与“细粒度不足”是同一决策的共生效应，不可分割；【0 信任原则·合图的非终结性】合图并非辩证链的终结而是阶段性综合，随 pledge/unveil 与 seccomp/landlock 演进（如 landlock 的功能扩展与 pledge 的 promises 类别增加）须重新展开；【0 信任原则·合图的非折中主义】合图不是“pledge 在 OpenBSD 内合理、在跨平台外不合理”的简单分类，而是揭示“简洁自主”与“细粒度责任”的张力——OpenBSD 以跨平台兼容性成本换取工程自主是结构性选择而非道德缺陷，但这一选择的外部性须被自觉呈现；【0 信任原则·历史意义的辨析】“pledge/unveil 促使 landlock 引入”论证须对照时序——landlock 自 Linux 5.13（2021-06）引入，pledge 自 OpenBSD 5.9（2015-10）引入，unveil 自 OpenBSD 6.4（2018-10）引入，时序关联存在但因果关系须谨慎评估，landlock 的设计可能源于 Linux 自身的容器安全需求而非 pledge/unveil 的对照压力
