# 219.1.3 VMM 虚拟化的进展

**要点**：**vmm(4)** 与 **vmd(8)** 虚拟化子系统首次出现于 OpenBSD 5.9（由 Mike Larkin（迈克·拉金） 独立开发，**vmm(4)** 手册页 HISTORY 段明确记载），基于 Intel VT-x/AMD-V 的轻量级虚拟机监控器；OpenBSD 6.4（2018-10-18 发布）对 vmm 子系统做了重大改进与稳定化（OpenBSD 独有，与 FreeBSD **vmm(4)**/**bhyve(8)** 同名但实现不同——FreeBSD vmm(4) 由 Neel Natu（尼尔·纳图） 与 Peter Grehan（彼得·格雷汉） 在 NetApp Inc. 开发，OpenBSD vmm(4) 由 Mike Larkin 独立开发）；vmm 让 OpenBSD 可作为 hypervisor 运行 OpenBSD/Linux guest；vmm 设计简洁，不支持复杂特性（如 PCI passthrough）——这一设计选择是 OpenBSD“简洁优先于功能”哲学的实践

**史料**：OpenBSD 5.9 Release Notes vmm 部分（<https://www.openbsd.org/59.html>）；OpenBSD 6.4 Release Notes vmm 部分（<https://www.openbsd.org/64.html>）；**vmm(4) ** 手册页 HISTORY 段（<https://man.openbsd.org/vmm.4>，原文“The vmm driver appeared in OpenBSD 5.9”）、** vmd(8)** 手册页（<https://man.openbsd.org/vmd.8>）；tech@ 邮件列表 vmm 讨论（<https://marc.info/?laccopenbsd-tech>）

**史观**：总纲第 3 条——不存在进步只有权力再分配：OpenBSD 选择自研 vmm 而非采用 Linux KVM 或 FreeBSD bhyve——以“代码可审计与简洁优先”为预设，宁可支持较少功能也不引入外部复杂虚拟化栈——自研与引入外部栈的取舍实为代码控制权的再分配

**辨析**：vmm 与 bhyve/KVM 的功能对比以各自手册页与设计文档为准——vmm 仅支持基本虚拟化功能（CPU/内存/网络/磁盘），bhyve/KVM 支持 PCI passthrough、live migration 等高级特性；vmm 的实际部署规模无权威统计 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
