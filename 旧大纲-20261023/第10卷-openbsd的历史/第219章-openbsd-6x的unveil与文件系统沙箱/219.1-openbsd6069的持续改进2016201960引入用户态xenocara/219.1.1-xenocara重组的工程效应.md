# 219.1.1 xenocara 重组的工程效应


**OpenBSD 6.x 版本发布时间线与关键特性**：

| 版本 | 发布日期 | 关键特性 |
| --- | --- | --- |
| 6.0 | 2016-09-01 | xenocara 重组、默认禁用超线程、KARL |
| 6.1 | 2017-04 | SMP 性能改进（细粒度锁扩展、网络栈多队列）、**syspatch(8)** |
| 6.4 | 2018-10-18 | **unveil(2)**、RETGUARD、**vmm(4)**/**vmd(8)** 重大改进与稳定化（vmm 首次出现于 OpenBSD 5.9，6.4 为重大改进；OpenBSD 独有，与 FreeBSD **vmm(4)**/**bhyve(8)** 同名但实现不同） |
| 6.9 | 2021-05 | 网络驱动改进 |

**要点**：OpenBSD 6.0（2016-09-01 发布）引入 xenocara 重组——将 X.Org 服务器与驱动重组为用户态组件，简化 X 服务器维护；xenocara 让 OpenBSD 的 X 系统与其他 BSD/Linux 区分；重组后 X 服务器以普通用户权限运行（部分组件除外）；openbsd.duckdb 显示 OpenBSD 6.0 release 相关 commit 为 2016-09-01（deraadt commit“Celebrate OpenBSD 6.0 release by retiring the sparc port”）

**史料**：openbsd.duckdb openbsd-src 仓库 commit 2016-09-01 deraadt“Celebrate OpenBSD 6.0 release by retiring the sparc port”；OpenBSD 6.0 Release Notes xenocara 部分（<https://www.openbsd.org/60.html>）；xenocara 设计文档；tech@ 邮件列表讨论（<https://marc.info/?laccopenbsd-tech>）

**史观**：总纲第 9 条——经验优先：xenocara 重组是“简化与权限分离”原则的实践——将 X 服务器从特权运行降级为普通用户权限运行，减少了 X 服务器漏洞对系统安全的潜在影响，系以既往 X 特权运行漏洞经验为据的取舍

**辨析**：xenocara 与 X.Org upstream 的关系以 xenocara 设计文档与 commit log 为准——xenocara 是 OpenBSD 对 X.Org 的 fork，定期从 upstream 同步代码但移除 OpenBSD 不需要的部分；重组的实际安全收益以 OpenBSD Security Advisories 中 X 服务器相关漏洞的影响范围变化为准
