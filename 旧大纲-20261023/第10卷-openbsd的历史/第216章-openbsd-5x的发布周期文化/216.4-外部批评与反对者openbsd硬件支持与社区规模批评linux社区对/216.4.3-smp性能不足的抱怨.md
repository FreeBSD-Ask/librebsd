# 216.4.3 SMP 性能不足的抱怨

**要点**：用户对 OpenBSD 的常见抱怨是“SMP 性能不足”——OpenBSD 长期保留 big-lock 模型，多核扩展性不及 FreeBSD SMPng 与 Linux；OpenBSD 在网络设备与桌面场景表现尚可，但在数据库等高并发场景落后；de Raadt 辩称安全优先于性能

**史料**：OpenBSD SMP 设计文档；基准测试对比报告；misc@ 邮件列表中关于 SMP 性能的抱怨（<https://marc.info/?laccopenbsd-misc>）；openbsd.duckdb openbsd-src 仓库 guenther 2011-06-01 commit fe87c1086dc1c35c10f7ebc07d0d8cff3ba09b9d（NOLOCK 标记）与 art 2011-07-07 commit 22bce29c5f9a889e73b7b15a16f9b2c974ce4862（kernel lock 修复）［A］

**史观**：技术路线分化：OpenBSD 选择安全优先的 SMP 路线（保留 big-lock 但通过 NOLOCK 标记渐进改进），牺牲多核扩展性换安全审计可行性——big-lock 模型使内核代码审计更简单，符合 OpenBSD“代码可审计为可信来源”的预设

**辨析**：SMP 性能差距以同硬件同负载的基准测试为准——OpenBSD big-lock 模型在高并发数据库场景（如 PostgreSQL/pgbench）落后于 FreeBSD SMPng 与 Linux，但在网络设备场景（如 pf 路由）差距较小；big-lock 模型的改进幅度以 openbsd.duckdb openbsd-src 仓库中 NOLOCK 标记与 kernel lock 相关 commit 计数为准——5.0 周期 guenther 与 art 的 commit 是渐进改进的代表
