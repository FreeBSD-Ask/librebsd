# 开发与运维

面向接手会话的开工手册：环境、脚本放置、提交、批处理、故障排查与恢复。判据正文仍在 `01-规则/`。

## 一、环境

| 项 | 配置 |
| -- | ---- |
| Python | 3.14.2（`C:/Python314/python.exe`） |
| DuckDB | `duckdb==2.0.0`，锁在 `脚本与命令/duckdb-version-baseline.txt` |
| Git | 提交钩子两条：`.git/hooks/pre-commit`、`commit-msg`（薄壳不入库，重建 clone 后须重装） |
| Node.js | 仅目录页三套浏览器回归需要，非日常必需 |
| 平台 | Windows 10/11，shell 为 Git Bash |

无 CI、无构建步骤、无容器化。**项目禁止自动化与定时任务**，除既有的三个数据库备份任务外不得新增。

## 二、脚本放置与登记

- 临时脚本与中间产物放 `script/`，不入库、不做备份副本。
- 固定脚本放 `00-编纂规则与格式规范/01-规则/脚本与命令/`，须被规则或索引引用，并在 `audit_gate_registry.py` 的 `REGISTRY` 与 `STAGE_MAP` 登记；漏登记由 R3／R4／R8 判 FAIL。
- 脚本头必须有 docstring：用途、输入、输出、退出码、用法。
- 含反引号或 `$` 的文本禁用 `python -c` 双引号内联，一律写临时脚本再跑。

## 三、提交

- 判据：`流程规则/08-Git 与提交.md`（暂存门槛、放行标记、H1 提交说明质量）。
- 钩子自动执行：pre-commit 改直角引号、不可见字符、CRLF；commit-msg 阻断忽略项、大文件、根目录越界、删备份、全角空格、旁路副本、说明质量、暂存 `.md` 含直角引号。
- 现行实践（描述，非判据）：提交首行形如 `feat(landing05): …`、`fix(...): …`、`chore(longline): …`，括号内为批次或对象；**规则不强制 commit type**，只要求首行非空、至少 8 字符、非占位、无 BOM。
- 无 PR 流程、无分支命名强制约定；`main` 为工作分支。不要引用不存在的 CI 或 PR 检查。
- 提交前自查：`git status --ignored`、`git diff --cached --numstat`；单文件超 5 MB 或忽略项须走批准标记。

## 四、批处理流程

1. **准入**（G1）：`任务审计台账.md` 增行，填任务 ID、风险级别、准入证据、复核轮次；未 PASS 不开工。
2. **设计**（G2）：新增目录、固定脚本、门禁、跨层调用先落 ADR。
3. **实现**（G3）：改内容源→装配；改结构→镜像与落地门禁；改文档→格式门禁。
4. **验收**（G4）：独立复核，作者不自批；复核须复跑命令或回读产物。
5. **收口**（G5）：回填复核轮次与收口证据，记 changelog，核对轮替状态。
6. **提交**：按 pathspec 提交本批文件，不夹带他会话改动。

## 五、故障排查

| 现象 | 原因 | 处置 |
| ---- | ---- | ---- |
| `assemble_index.py --check` 报漂移 | 内容源、样式、模板或 `src/js/manifest.txt` 变了 | 常规装配重写 `index.html` 后再 `--check` |
| 装配报缺占位符 | 页壳与装配器假设不同步 | 检查缺失的 `{{XXX}}` 是否在 `page-template` 中 |
| 装配报语言标记非法 | `⟦⟧` 未配对、嵌套或语言码不合规 | 修 `outline.txt`，不绕过 |
| `sync_outline_mirror.py --check` 报题面改字 | 目录名、H1 与 `SUMMARY.md` 不一致 | 先改上游名，再 `--write` |
| 写盘报 `W_NORM` | 大纲名含应在上游改名的旧词（如“基础系统”） | 上游改名后重跑 |
| `audit_outline_landing.py` 退出码 2 | 缺 `targets.tsv`、大纲根不存在，或 `mapping.tsv`／`layout.tsv` 半损 | 补齐台账或重建注册表 |
| L7 FAIL | `CONFIRMED` 落点的父节目录在 `SUMMARY.md` 无条目行 | `sync_outline_mirror.py --write` |
| L8 FAIL | 主题索引 schema 或计数与树不一致 | `build_theme_index.py --write` |
| L11 FAIL | `layout.tsv` 的 dest 在磁盘不存在 | 核落盘与台账，勿改台账迁就磁盘 |
| `audit_keyword_index.py` FAIL | 词数越界、禁用词、反查不一致 | 看七组报告定位后重生成 |
| 元门禁 R1／R3／R4 FAIL | 登记表缺件、漏登记或无规则引用 | 补 `REGISTRY`／补引用，勿删检查 |
| 提交被拒 G1／G2 | 暂存了忽略项或超 5 MB 文件 | `git rm --cached` 撤回，勿用 `--no-verify` |
| 备份日志连续缺失 | 计划任务失败 | 查 `backup_log.jsonl` 与任务状态，修复前暂停写库 |

## 六、灾难恢复

- **代码与大纲**：一切留痕靠 Git。旧树迁移前状态用标签 `outline-pre-landing-20261023` 逐件取证（`git show <tag>:<旧路径>`）。
- **数据库**：从 `12-数据库备份/<库>/` 取最近可用归档，`IMPORT DATABASE` 重灌；先 `verify_archive()` 三段校验。不得用单文件拷贝，不得直接跑档内 `load.sql`。
- **大纲树**：`12-数据库备份/` 另有 `backup_outline.py` 产出的 `05-卷册大纲/` 打包件。
- **恢复后必做**：重跑装配与落地门禁，确认 `index.html`、`SUMMARY.md`、主题索引与树一致。

## 七、禁忌

- 不写正文；不手改 `index.html`、`SUMMARY.md`、两个索引 JSON。
- 不在根目录新建文件或目录；不建旁路备份副本（`.bak`、`.prebak`、`.orig` 等）。
- 不对数据库做原地升级；不擅自删除 `12-数据库备份/` 内容。
- 不以“改动很小”豁免门禁；不以 AI 自报代替磁盘与命令输出。
