# 门禁与核查体系

门禁分三层：**阶段门禁**（G0–G5，按批裁剪）、**面门禁**（按触发面选件）、**核查体系**（史料与数据质量的周期性核查）。判据正文在 `01-规则/`，本文件只给分工、触发面与证据位置。

## 一、阶段门禁 G0–G5

阶段集合固定为 G0–G5，**不存在 G6–G9**。定义见 `流程规则/01-复核与验证.md`“工程实践生命周期与阶段门禁”。

| 阶段 | 名称 | 关键产物 |
| ---- | ---- | -------- |
| G0 | 立项与范围 | 范围声明、范围类 ADR、目录边界 |
| G1 | 需求基线 | 规格、任务清单、验收清单、任务准入 |
| G2 | 设计基线 | 设计说明、契约、ADR、专项档案 |
| G3 | 实现与单元验证 | 源码、测试、测试输出、变更记录 |
| G4 | 集成与验收 | 证据目录、验收勾选、执行记录、独立复核 |
| G5 | 发布与归档 | changelog、归档记录、已知限制、复审台账、任务收口与轮替 |

按变更类型裁剪的表（纯文档、缺陷修复、需求／范围、平台／依赖、紧急修复、内容编纂、AI 生成、长线战役）在同节；裁剪不等于跳过证据，须在 `tasks.md` 写明适用与不适用理由。

| 面 | 主要件次 |
| -- | -------- |
| 目录页装配与结构 | 第七件结构自检、第八件装配漂移、第九件页面资产、第十八件版本递增、第二十二件无障碍、第二十三件行为源块作用域 |

## 五、运行顺序与失败处置

1. **改装配源后**：`assemble_index.py --check` → 目录页九件 → 三套浏览器回归（`visual_regression.mjs`、`full_matrix_regression.mjs`、`fullsize_regression.mjs`）。不得以“改动很小”只跑子集。
2. **改大纲结构后**：`sync_outline_mirror.py --check` → `audit_keyword_index.py` → `audit_outline_landing.py`。
3. **写库前**：`claimdb_guard.py --db <库名>` PASS 才写；register 走 `register_waterlock.py`。
4. **收口**：`audit_task_lifecycle.py`（L1–L12）→ `audit_engineering_practice.py`（E1–E7）→ 常备四项。
5. **失败处置**：门禁 FAIL 即停手，修正后重跑；不得以“基本完整”放行；不得用 `--no-verify` 绕过钩子（绕行须留痕）。

## 六、边界

- 无 CI、无自动化、无定时任务；门禁全部由人在场批次本地执行。
- 本文件是分发图，不是判据；冲突以 `01-规则/` 与 `audit_gate_registry.py` 为准。
