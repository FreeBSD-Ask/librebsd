## 四、单段 SOP（十步，详见技能 usenet-row-mining）

```
1 dump     _dump_generic.py <list_id> <lo> <hi> > _ngNN_dump_sK_YYYYMMDD.txt
2 全读     派读手子代理，分块 ≤1000 行，禁抽样；产出 raw 候选（pk|L4或L3|摘要，摘要 20–80 字）
3 候选     review_logs/usenet_ng__<id>_<name>_candidates_sK_raw.txt
4 spec     复制 raw → review_logs/ngNN_sK_spec.txt
5 消毒     _fix_cand_chars.py（半角 * \ 角引号 → 全角）
6 gen      _pipeline_gen.py → c1
7 check    _pipeline_check.py（须 0 不一致）
8 register _pipeline_register.py <list_id> <anchor> <c1>（CL-RM 实时 MAX+1）
9 分组     派分组子代理 → _groups_ngNN_sK.json + _targets_ngNN_sK.json
10 入纲    _pipeline_blocks.py --write → 二跑 0 → supplement → changelog → 门禁 → git add → staging
```

## 五、硬性验收标准（每段必过）

1. check“不一致项 0 条”
2. register“写后反查 N/N”“四表 join N”
3. 块脚本二跑“总计拟插: 0 块”
4. supplement 二跑 append 0
5. changelog 脚本真幂等（存在即 no-op）
6. 门禁 `audit_evidence_level_labels.py` 判定 PASS（错标 0）
7. git 仅 `add` 宿主 .md，**不 commit**
8. staging 追加一行，记录：块数/等级分布/宿主/窗口/CL-RM 段/反查/changelog id/plan 目标值

## 六、安全与边界

- **块头证据等级一律从 DB 真值读**（`evidence.anchor` → `claim.evidence_level`），严禁写死字面
- 子代理只读 + 产候选/分组，**不写库、不 commit**
- 收编由主会话串行执行，避免并发写库冲突
- 大库（源码归档）不读正文，走 digest 发行版级合并
- 并行会话持续写库/提交属常态：判定落地须 `git show HEAD:<path>` 复核；门禁错标数变化须逐文件比对
