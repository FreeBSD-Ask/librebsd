## 2. 现行口径（2026-09-16 反向统一 · 权威）

**门禁二“仅 L4 入纲、L3 留库”已撤回。现行：L3 亦入纲，块头等级写 DB 真值。**

| 级 | 含义 | 处置 |
| :---: | --- | --- |
| **L4** | 提供可入史的史实 | claim 落库 ＋ 大纲写回块（块头 `L4`） |
| **L3** | 有信息量，但不可独立入史 | claim 落库 ＋ 大纲写回块（块头 `L3`） |
| **不收** | 无信息价值（七类） | 不落库、不入纲 |

依据 `_GRADING_RUBRIC_20260914.md` §七：“真正的缺陷不是 L3 入不入纲，而是**标签失真**”。

**三条硬约束**：

1. **禁止再执行** `_ng<list>_s<K>_outline_blocks_*.py` —— 其 `levels.get(p) != "L4" → raise`
   断言会**静默滤掉 L3**。落块一律用 `_backfill_orphan_blocks.py`。
2. **等级不再是撤块理由**。撤块理由只剩：**不收七类** ｜ **标签失真须改级** ｜ **同线程重复**。
3. **块头等级必须从 DB 真值读**（`claim.evidence_level`，按 claim_id 查），并与 SPEC 交叉校验；
   **严禁写死字面**。事后跑 `audit_evidence_level_labels.py`。

**连带结论**（勿再翻转）：

- s1–s10 的 290 个 L3 块在纲属**正确形态**，不在治理范围。

- s13 的 293 个 L3 块撤除依据失效，已恢复（`_c1_REVOKED_ng38_s13_20260916.md`）。

## 7. 风险与回滚

| 风险 | 表现 | 处置 |
|---|---|---|
| **并发写同一宿主** | 整文件覆盖致他人块丢失 | 写前查宿主 mtime；**整文件覆盖前先 diff 备份与现值，逐 pk 取并集再写**；每次写前留备份目录 |
| **claim_map 语义误用** | `_verify_outline_landing.py` AssertionError | claim_map ＝ **本段落盘集**；回补取并、撤除取缩 |
| **`_groups` 键名口径不一** | 归属核对失败 | 各段 key 去点口径不同（s13 `585`／s14 `278.26`）→ 一律**按 targets 路径 basename 比对** |
| **核验器盲区** | PASS 却不证明块体忠实 | `_verify_outline_landing.py` **不查块体是否等于 `claim_text`** → 另跑块体保真比对与多宿主扫描 |
| **`progress.jsonl` / plan 滞后** | 前沿误判 | 一律用 DB 真值重算，**严禁采信 plan** |
| **批号前缀写错** | 用错库 | 开工前必打开脚本看 `MAILDB` / `CAND` 实值 |
| **模板替换静默不命中** | 重复追加块 | 模板替换后**必须 grep 生成文件确认旧值 0 残留**，再写盘 |

**回滚**：每次写操作前建 `script/_backup_<动作>_<日期>/`（宿主原文 ＋ 相关 JSON）。
回滚 ＝ 从备份恢复 ＋ 用 `_verify_outline_landing.py` / `_progress_audit_7groups.py` 复验 ＋ changelog 记更正。
