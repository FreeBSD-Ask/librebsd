## 九、1M 上下文适配（⬅ 本节为 Rev6 核心修订）

### 9.1 预算与容量

- **预算**：上下文总闸 **1M**（85% 警戒 = **850K**）。
- **实务建议**：在 **600K** 处即做一次**厚检查点**（刷新 `_RESUME.md` + state + 提交），防长上下文性能衰减导致后段判读质量下滑。
- **子代理段成本**：主代理 ≈ **10–15K/段**（调派提示词 + 回报 + 脚本输出 + 复核 + 提交）→ **单会话 25–40 段**（200K 时代为 6–8 段）。
- **solo 段成本**：读 compact digest ≈ 60–70K + 写 TSV + 复核 ≈ **100–150K/段** → **单会话 6–8 段**。
- **批量**：一批 **4 段**并行（4 个子代理）；1M 下可放宽至一批 **6–8 段**。

### 9.2 长线会话三原则（避免中断）

1. **段末必提交**：任何一段落地即 pathspec 提交，**绝不积压**（积压即被并发收编或中断丢失）。
2. **每 3–4 段刷新检查点**：`_RESUME.md` + `long_task_state.json` + 本交接书 §二 真值表。
3. **不写段级总结**：段收官后直接发下一段开工调用；**总结只在批次末尾写一次**。

### 9.3 子代理监控（避免死等）

- **后台派发**：`run_in_background` 派发，主线程并行做检查点／下一段素材／文档维护。
- **硬时间盒 25 分钟**；超时未产出 → `TaskStop` → **主代理 solo 接管该段**。
- **永不 block 扑杀；只查盘核验**。
- **警戒线**：上下文 ≥ **850K** → 完成当前段（已半写则完成落地 + 收尾 + 提交），写检查点四项，**停会话不空转**。

### 9.4 产出规范

- 摘要统一 **≥32 且 ≤80 字**；弱 L3 凝 DROP，防超限返工（list23 s12–s14 曾因过宽判至 66–70% 返工）。
