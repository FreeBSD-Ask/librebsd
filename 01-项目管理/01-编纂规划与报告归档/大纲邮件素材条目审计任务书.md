## 2 审计五问（每条必答）

对每一条 ROW_MINE / MAIL_INSIGHT 块依序回答：

1. **内容忠实**：摘要/转述/引语与源库 body 全文语义是否一致？人名、机构、版本号、commit hash、日期有无误？是否张冠李戴（某人说的话安到别人头上）？二手转述是否被误标一手（抬头-L4）？
2. **适合性**：内容主讲的实质话题与所在节主题是否符合？完全无关或明显更贴另一节 → 判「重映射」并给出目标宿主（卷.章.节＋节名）；仍属本节但顺序错位 → 原地调整。
3. **格式合规**：五条核对——行数恒 5；抬头↔等级↔纪律串三一致；摘要 30–80 字；无禁项（中文直角引号「」『』、ASCII 直引号、`*` 强调、判词/元注释）；日期前缀 `YYYY 年 M 月 D 日，` 或省略。
4. **字数**：摘要下限 30 字。不足→从源 body 忠实补全（补的是源文有的事实，非编造）。
5. **作者/时间/署名**：源 from_name/date 与文字内人名年份一致；不篡改用户名/文件名/版本号/手册页引用（写作规则各条）。

## 3 判定类别（每条唯一结论）

| 判定 | 含义 | 处置 |
| --- | --- | --- |
| keep | 五问全部 7 项达标 | 仅台账登记 |
| fix-format | 仅格式不符（行数/抬头/纪律句/字数/标点/日期） | 原地改 .md，不动库 |
| fix-text | 内容与源不完全符合（误读、翻译走样、略改） | 按源全文原地改写摘要/转述；不动库 |
| remap | 内容不属于本节 | 台账登记目标宿主；现有宿主可安放的单条重组可由人工原地完成；**无处安放的允许在 05-大纲目录新建节 `.md`**（2026-09-27 主理人增补授权），新建须遵循节号连续性规则、章概述索引登记、`sync_gitbook_summary.py` 同步与写作规则全部格式要求 |
| fix-db | 库侧（claim_text/fact_text/evidence_level/anchor）与源不符 | 走 §6 受控修库流程 |
| 存疑 | 无法仅凭 src 判定（多义/缺页/冲突） | 记台账 pending 类，联网考据（§7.4）后回决 |

**判据铁律**：判定只依据【源库 body 全文】＋【主库登记元数据】两把尺；本块自己的自称（标题、抬头、纪律句）不是依据。

### 4.2 数据库修正（受控、留痕、备份）

只允许改主库 `historical_claims.duckdb` 下列三种情形：

1. `evidence.fact_text` / `claim.claim_text` 与源 body 逐字比对确属事实性错误（张冠李戴/倒果为因/臆造细节）
2. `evidence.anchor` 或 `raw_source.local_pk` 与大纲锚点/源实际行号错锚
3. `claim.evidence_level` 与源不符（一手/转述错标）——**高风险项，须主理人批注后才动**

**执行顺序（不可变）**：
1. **备份**：`12-数据库备份/` 下建 `OAA_<批次>_<时间戳>.duckdb`（cp 只读库或按 backup_databases.py 全库备份）
2. **改**：只更新对应行
3. **留痕**：`provenance_history` 写 `event_type='claim_fix'`、detail 记批次/旧新值；`update_log` 写一条
4. **收口**：写后**只读回查**更新行 + 三表行数守恒（claim/claim_evidence/evidence 数前后相等；只 UPDATE 不带增删，必然守恒）

## 6 批次节奏与方法论

1. **批大小**：试点批＝3 个宿主节（§10）；正式批每次 5–8 节（按块数配平，一批 ≤6,000 块）。
2. **循环**（每批）：快照+差集 → 提取全集反查（本地脚本生成「块→源全文+claim 元数据」大表）→ 拟判定 → 主理人复核 → 修大纲（原地）→ 修库（若需，受控）→写台账 → `oaa_verify` 门禁 → commit。
3. **并行**：批内按节分发到子代理（每代理一节；允许只读库+写自己的 report 文件）；**派发严格在途 ≤2–4 路**（2026-09-28 主理人裁定，从 ≤30 滚动进一步降至 2–4 路，逐片完成再补）；主理人以**磁盘为准**复核一切回报；只重派 MISSING 单件，不整波重派。
4. **联网考据**：凡疑似臆造/版本-日期冲突/需证伪的，按考据规则**三次复查**（≥3 次独立 WebSearch 与 WebFetch 交叉验证）；结果记 `03-原始史料库/06-考据记录/YYYYMMDD_<主题>.md`（三字段：查证来源/交叉验证方法/存疑判定依据）。

## 附录 A 常用 SQL 模板

```sql
-- 1. 主库锚点→claim（oaa 反查核心，仿 _hdcheck.py）
SELECT CAST(rs.local_pk AS VARCHAR), c.claim_id, c.evidence_level, c.claim_text,
       e.fact_text, e.anchor
FROM claim c
JOIN claim_evidence ce ON ce.claim_id = c.claim_id
JOIN evidence e       ON e.evidence_id = ce.evidence_id
JOIN raw_source rs    ON rs.source_id = e.source_id
WHERE e.anchor = <锚点>;

-- 2. 源邮件全文（以源库 messages 表）
SELECT CAST(id AS VARCHAR), date, from_name, subject, body
FROM messages WHERE CAST(id AS BIGINT) = <pk>;
```
