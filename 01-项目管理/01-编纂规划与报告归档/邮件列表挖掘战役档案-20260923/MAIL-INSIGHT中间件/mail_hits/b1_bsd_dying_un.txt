OpenBSD allocates a fixed number of network buffers and
it is my experience that once that number is exceeded the
whole network stack stops working.  FreeBSD is basically
the same.  Look for errors in /var/log/messages.  It would
be better behaviour if the kernel would drop packets while
there are no spare buffers and later recover when some
become available.  You can help by increasing the number
of network buffers either by setting the option and recompiling
the kernel or by using the config utility.  See the FAQ
chapter 11.

RH.

	Is the filesystem mounted?  I would umount it (I'm presuming
that you have a separate partition for /usr/local), and run the fsck on
the  unmounted filesystem.

	The alternative is to boot to single-user mode and run the fsck
as root while in single-user mode.

	If it recovers the directory (or the files which should be in
the directory) they are likely to wind up in that partitions's
"lost+found" directory, with cryptic names "#" followed by the inode
number, as the filenames have been lost with the corrupted directory.  I
suspect that the problem is a bad sector in the actual directory, which
can lose a bunch of files like that.  The real trick is figuring out
which file used to have which name. :-( If it is any help, here are the

[2004-11-14T22:57:13+00:00] [Marco S Hyman <marc@snafu.org>] [robertks@hotmail.com (Robert K S) writes:

> The system did get shutdown improperly one or two days ago, so this
> may have been the source of the problem.  I'd like to run a disk
> repair before blaming it on a faulty hard drive, it's just that I
> haven't been able to successfully  run fsck, even using fsck -y.

fsck's meaning of "repair" and yours may be different.   Make sure
the file system is unmounted then run "fsck -p /dev/xxxx" on the
raw device for the filesystem in question.   fsck will "repair"
the fs for use.  That does NOT mean it will restore your files.
That's what backups are for.   You *do* have a backup, don't you?

If not, and if the only lost files are emacs related, then all you
need to do is delete and re-install emacs.   See pkg_delete(1) and
pkg_add(1).
