## 五、技术要点与坑（血泪清单）

1. **反查真键**：`raw_source.source_db + CAST(local_pk AS VARCHAR)` → evidence → claim_evidence → claim。**`evidence.anchor` 存的是批次标签（如 fhk_b038），不是 `<库>.messages.<pk>`**，勿用它反查。
2. **G2/G5 基线会随并行会话漂移**（他人持续加锚/建 claim）：跑 verify 时 G2 取“当前实测 ROW_MINE 总数”、G5 取当前三表计数；若报漂移先查是否并行会话所为（`created_at` 时间戳可证），非本批违规就重取基线。
3. **apply_fixes 对 inline 型是整行替换**：读手新行不含行尾锚点时必须从 fetch 档案的 `anchor_line` **补回锚尾巴**，否则丢锚（B001 曾丢 814 行，已加 `remap_remove.py` 同类教训）。替换后必须 `git show HEAD:` 对比锚点集合逐点一致。
4. **`*` 星号判定（is_bad_star）**：`*BSD`/`*nix` 缩写、`comp.unix.*` 层级通配、`(*compar)` 指针、`/* */` C 注释均豁免；仅成对 `*word*`/`**bold**` 或中文两侧夹 `*` 判违规。
5. **字数口径**：standalone 摘要正文按**汉字**计 30–80（英文术语/数字/半角标点不计），总字符 ≤200；inline 叙述不查 30–80（100–400 字量级）。
6. **B002 宿主高发缺陷**：①中文叙述混用半角标点＋ASCII 双引号（fix-format 大宗，400+ 条）②英文叙述未转中文（fix-text）③F1 归属倒挂（把 `>` 引文内被引用者的话挂给发帖人）——判定与修正时注意。
7. **script/ 全树被 gitignore**：提交台账须 `git add -f`；`.git/index.lock` 被并行会话占用时等待后重试。
8. **提交后台跑**（pinentry 弹窗需人工输入口令）；commit 后核对 `git log -1 --format=%G?` 应为 `G`（签名）。
