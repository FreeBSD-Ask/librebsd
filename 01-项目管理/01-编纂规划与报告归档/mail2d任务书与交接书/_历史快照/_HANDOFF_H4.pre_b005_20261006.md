### 1.6 上下游关系（本线只做中间一段）

## 四、格式铁律（违反即返工）

1. **`ROW_MINE` 块 = 恰好 5 行**：标记行 ／ `**当事人自述**（证据等级：Lx，来源：…）` ／ 空行 ／ 正文 ／ 空行；
2. **块头等级必须从 DB 真值读**（门禁 `audit_evidence_level_labels.py`），严禁写死字面；
3. **叙述文件三铁律**（`_chk_mount_narr.py` 拦截）：①第二列＝**宿主节号**（非 claim_id）；②叙述正文**不含日期前缀、不含来源尾巴**（生成器自动补）；③**末尾不得有 。，；：**；
4. 候选摘要 **20–80 字**；禁直角引号“”／星号／反斜杠／竖线，末尾无句号；超长须压缩（改动集＝原超长集）；
5. 编码 **UTF-8 无 BOM、LF**；叙述长度 **60–140 字**；
6. **不收**：pkg-fallout／portscout／tinderbox／bugzilla 纯状态变更／提交通知／例行升版／纯求助问答／空正文。

### 11.2 🔴 坑㊿：大纲整块删除不得正序切片

`for m in list(BLK.finditer(txt)): new = new[:m.start()] + new[m.end():]`
——`m.start()`／`m.end()` 取自**原始 `txt`**，而 `new` 在被切短，第二个 offset 起整体失真。
实测后果：报“删 4,224 块”而目标文件残留上百块，**宿主文件损坏**。

正解：`for m in reversed(list(BLK.finditer(txt)))`（倒序删则前面 offset 不受影响）
＋ 写后**重新读回**断言目标 pk 残留 0。
**配套纪律**：大纲批量破坏性操作前整目录备份（本批 `_outlinebak_b147/` 因此保住了 14 个文件）；

正解：`.*?(?=\n\n<!-- ROW_MINE:|\Z)` + `re.S`。

   （🔴 不是字面“删除 0”：宿主末尾的 `<!-- /PODCAST_REVIEW -->` 闭合标记会被移到
   新块之后，每处 −1/+1 成对，见 §十八 numstat 修正）→ `bookkeep` 三零 →
   **台账落账**。🔴 **台账未推进不算闭环**（b051 教训：判据是 `review_logs/<tag>_ledger_append.txt`
   存在否，不是凭记忆）。
2. **依赖顺序不可倒**：`register` 成功才可 `outline`；叙述合并＋回源核验通过才可 `outline`。
   `claim_text` 终态＝合并叙述（叙述闭环后回写：零新造、只改 `claim_text`＋`updated_at` 两列、
   rejected 不动、先 level 后 text）。
3. **两口径分离**：入库忠实于源（占位值照录即真值），大纲忠实于读者（占位值内联改写）。
4. **红线**：claim 库全线共享——禁整表重写、禁 DELETE 清孤儿、验收只断言本批行；
   rejected 门禁不得绕过；建批前双查（本窗 claim 库 0 条、大纲 0 块）；宿主写入前必须备份
   （宿主是长命文件，批后无法从别处还原）。

### ◐A⁺ 波次频次强制（2026-10-03 主理人令：**每个波次都必须执行一次入库入大纲**）

1. **禁令**：不得“等整批读完／40 份分件全落盘后再 register／outline”——等待期长达数小时
   （H5 h5fs_b527 实测），register 单次事务越大越易撞前台超时与库锁窗口，中断损失也是批量的。
   **每个波次收尾必须各执行一次入库与一次入大纲**：
   - **读手波收尾**：滚动在途清零（或新落盘分件累计达一波）→“已落盘即合并”（孤儿保护门禁：
     既有 candidates.txt 的 pk 必须全部出现在本次分件集合内，防不完整集合覆盖定稿候选）→
     check → `register --apply` **一次**；
   - **叙述波收尾**：同判据 → `_merge_narr` ＋回源核验过门禁 → 4b claim_text 补遗 →
     `outline --write` **一次** → bookkeep → pathspec 提交 → **台账落账（游标按波次粒度推进）**。
2. **可执行判据**：任何时刻，**未入库的已合并候选、未入大纲的已核验叙述不得积压超过一个波次**
   ——见到积压即执行，不等下一波。
3. **波间幂等（先例 H5 §10.49 h5fs_b527）**：后波合并时前波 pk 仍在候选集合内——register 的
   `source_id` 去重自动跳过已入库行、outline 的 ROW_MINE 锚点幂等自动跳过已写块，
   **两波产物相加即全批，无需重跑前波**；被剔除 pk 是无害孤儿，禁为“清孤儿”DELETE claim 表。
4. **号段连续性**：register 每波按全库 max(seq)+1 派生（§4.5 口径不变），波与波之间自然连续无穿插窗口。
5. **例外与过渡**：配额硬停（`token plan entitlement exhausted`）截断的波次，恢复后先按
   “冻结前验盘稳定”流程收尾再起新波；**在途批不追溯重切波**——H1 fq_b096 叙述、
   H2 fpo_b191 叙述、H3 fhk_b060 p50、H5 b516_3 叙述均按各自断点收尾即可。

### ◐C 子代理超时监控协议（主动监控；会话内同步滚动驱动）

1. **派单登记**：每派一路，主会话即时把（批次／分件号／派发时刻）记入在途清单，
   40 路在途的账面随时可点、可对、可断。
2. **巡检节奏**：监控由主会话在会话内同步滚动驱动——每完成一件主会话侧工作
   （合并、register、写任务书、提交），即对在途清单做一轮验盘巡检
   （`ls -la`＋`wc -l` 清点落盘份数与新增）。
3. **判死线**：派出后 **22 分钟**零落盘（H2 实测 20 分钟会误杀慢件，统一 22）
   ＋ SendMessage 报 No active local_agent task；**首落盘目标 5 分钟**（H1 口径）。
4. **判死前必须验盘**：`ls -la`／`wc -l`／字节数三查——被取消／中断／报错的路
   **可能已落盘**（H2 第四批 8 路报中断、6 份已落盘；H1 b082 中断两次全部落盘；
   H5 payload 死亡 9 路多数已落盘）。**死亡 ≠ 页损失**，判死前验盘是铁律。
5. **重派纪律**：只重派缺失的那一份，换名不复用 agentId；叙述手常有 300s+ 正文回读期，
   零落盘先等 15 分钟再动手；二次零落盘 → 主会话 solo 自写。
6. **长任务判活**：register／merge 是几十分钟级任务，日志静默是预期；判活只看进程
   **工作集递增**（b188 实测 82,312K→88,160K→91,276K 为健康），
   **绝不轮询 claim 库**（写连接未关时第二个 read_only 连接直接 Fatal）；
   撞库锁退避重试（`_retry_until_db_free.py`），禁杀他会话进程。
7. **HOT 态禁触碰**：mtime < 2 分钟的分件正在写入，勿读勿改勿判。
8. **回报不采信**：子代理回报（含自报门禁结论）一律不采信，唯一验收是磁盘产物；
   校验命令的原始输出必须贴进回报（TB1 波 61 教训：贴原始输出后此类失真归零）。

### ◐D UNC／D 盘环境适配规约（D:\librebsd 与 \\DESKTOP-M5P610N\d\librebsd 为同一仓库双身份）

1. **路径写法表**：
   - Write／Edit 工具 → **Windows 反斜杠路径**（`\\DESKTOP-M5P610N\d\librebsd\...` 或
     `D:\librebsd\...`）；POSIX 路径（`/d/librebsd/...`）会**报成功但不落盘**；
   - bash → `//DESKTOP-M5P610N/d/...`（无 `/mnt`）；
   - Python → 正斜杠 `d:/librebsd/...`（反斜杠 UNC 会解析到只含 `_tmp` 的幻影目录）；
     主会话自写脚本一律四反斜杠 UNC。
2. **🔴 禁内联 `python -c` 与 heredoc 直接写／校验 UNC 路径**
   （`FileNotFoundError` 指向明明存在的目录，已三次以上坐实）——一律写 `.py` 文件再跑。
3. **写后必须独立验盘**：Write／Edit 报成功 ≠ 落盘（UNC 静默失败家族）；写后用**独立命令**
   （`ls -la` 字节数／`wc -l`／`grep` 锚点计数）复核；`os.path.isfile` 对刚写完的文件
   可能返回过期 False（写后负缓存），间隔重读再判。
4. **UNC 假阴性三族**：`os.listdir` 可能漏列真实存在的项（按精确路径 `os.stat` 复核才可信）；
   `grep -c` 对中文路径宿主可能假阴报 0（真值取 Python `io.open`）；
   **子代理报“文件不存在”先按 SMB 假阴处理**，主会话复核后才可判死。
5. **慢 IO 纪律**：单代理内并行 Read 多份输入会 30s 双双超时——一律串行读；
   `ls`／`grep` 走 UNC 极慢，计数类统计用单进程 Python 遍历。
6. **mtime 口径**：UNC 与本机时钟存在 ~15h 时区**标签**差（git `+0800`／`−0700` 混用同源，
   全链无真实漂移）；mtime 绝对值可信、相对年龄不可用；HOT 判据（mtime<2 分钟）以本机钟为准。
7. **git 纪律**：提交前 `git update-index --refresh`（UNC stat 缓存会让已写盘文件显示无改动）；
   pathspec 白名单精确列出（`*bNNN*` 通配会撞他线标签）；禁 `git add -A`、禁 amend、
   不删 `.git/index.lock`（持锁 sleep 15 重试）；管道别用 `tail`（吞非零退出码）；
   校验 CRLF（shell 重定向会带 CR）。
8. `glob.glob` 在 Windows 返回反斜杠路径，跨平台匹配一律 `os.path.basename`。

### ◐E 临时文件清理规约（2026-10-04 主理人令固化；全五线同文，自包含）

**目标**：每会话产生的一次性脚本／日志／pathspec／台账备份不得在仓库内长期堆积。

（台账类备份的内容都能从 git 历史找回，另存一份只会造成新旧混淆）。

1. **清理范围（按文件名判归属，不猜）**：
   - 本会话 `_tmp/` 下的一次性探针／校验／落账脚本（`_probe_*`、`_stage_*`、
     `_patch_resume_*`、会话专用 `_tmp_*`）；
   - 本会话写进 `.git/` 根的非标准文件（如 `pathspec_*.txt`，可达 5 MB 量级，属垃圾）；
   - 本会话在 `$TEMP` 下的日志与提交信息草稿（`cmt*.log`、`cmtmsg_*.txt`）；
   - 本会话产生的台账备份（`mail2d_read_ledger.bak_before_*`）。

   - 他会话同名前缀文件（`_f1_*`／`_f2_*`／`_f4b08_*` 等按文件名归属他线）；
   - `supplement_log.jsonl`（严禁入库，也严禁删）；`.duckdb` 数据库本体；
   - 批次链产物（`review_logs/` 内已入库的 claim_map／mount_narr／prompts 目录）；
   - `_HANDOFF_*.md`／`_RESUME_*.md`／台账本体。
3. **复核四步（先复核后清理）**：① 按 mtime＋文件名前缀枚举候选 → ② 逐件确认
   “本会话创建＋已完成使命”→ ③ 打印清单复核 → ④ 删除后用独立命令验盘
   （`os.stat` 确认不存在）。
