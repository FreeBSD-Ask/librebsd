## §4 单批标准流程（6 步）

1. **判主题定宿主**：`dump` 后**先读 digest 前 5–10 行**判断该库真实主题与年代；按**主题**选章节，年代仅作同主题内细分；改 spec 的 `hosts` 后用 `load_hosts()` 验证 4 个 key 均可解析。
2. **拆份派读手**：把 digest 拆成每份 500 行的若干份，**并行**派子代理（见 §8）。
3. **合并候选** → `register --apply` → `body` → 按候选数拆份派**叙述**子代理（并行）。
4. **合并叙述** → `outline --write`（内含幂等二跑，二跑须为 +0）。
5. **`bookkeep --write`**：落地核验（缺块/claim_id/重复 三项须全 0）+ 格式校验 + progress + catalog 升格。
6. **`commit --apply`**：按宿主核块数（权威）+ 行数容差校验 → 提交。

## §5 铁律（违反即返工）

1. **块格式**：ROW_MINE 块 = **恰好 5 行**（标记 + `**当事人自述**（证据等级：Lx…）` + 空 + 摘要 + 空），标记在块首。
2. **机器块不可改**：`DB_REF/DEEP_ANALYSIS/COL_SCAN/DB_POINTS/PODCAST_REVIEW/MAIL_INSIGHT/ROW_MINE` 一律只登记、不修改。
3. **替换须完整锚点 + `count==1` 断言**，先 dry-run 再 write；禁止全字串替换。
4. **不得新建/移动/重命名源文件**；不在 `D:\librebsd` 根目录建文件；不在 `08-核查报告与多轮复核/` 下新增 .md。
5. **格式**：UTF-8 无 BOM、LF、中文弯引号、**禁用直角引号“”**、路径与文件名加粗、手册页 `xx(N)` 加粗。
6. **catalog 状态只升不降**：只做 `pending/deferred → in_progress`；`completed` 由专门流程判定。**绝不可用 `批数 × 500` 反推状态**（曾误降 95 个 completed，需人工回滚）。
7. **不 commit 他人改动**：`git commit -- <paths>` 提交的是**工作区状态**，宿主常被多会话共用；提交前须按宿主核块数。**不 commit 时也不得 `git add` 全树。**
8. **收/不收纪律**（读手提示词必须逐条写清）：
   - **不收**：pkg-fallout、portscout、tinderbox、bugmaster 报告、bugzilla/GNATS 转发、提交通知；例行版本提升；纯求助/问答/联络/对骂；空正文或极短正文。
   - **要收**：当事人一手自述（L4）；可查事实（L3）；里程碑（新建/退役 port、破坏性变更、CVE、架构改动）。
9. **密度基准逐库给定**（见 §9 表）：同批大小下收率可差 **35 倍**（elastic 0.9% vs www 31.9%）。**基准跨库套用必然系统性多收或少收。**

## §7 1M 上下文适配：**会话最小化方案**

### 7.1 核心策略

**每次会话整库清完**（而非一次只做一批）。做法：

1. **窗口放大到 2000 行**（digest 约 1MB，1M 上下文可轻松容纳）。
2. **一次 dump 多窗**：小库直接 `n = 剩余全部封数`（上限 10000）；大库按 2000 行滚动。
3. **读手 4 路并行**、**叙述 4 路并行**（一条消息内多个子代理调用）。
4. **自己在上下文内维护状态**：把各份候选文件的行数与 pk 区间记在回复里，避免反复 `ls`/`wc` 探查（每次探查都是往返开销）。
5. **合并与校验用一次 Python 调用串起**（`&&` 链接），不要分多次。

### 7.2 每次会话的预算与产出

| 项 | 建议值 |

## §8 子代理派发与监控（**必须做**）

### 8.1 派发

- **一条消息内放多个 `Agent` 调用**才能真正并行。
- 每个子代理的提示词必须**自包含**，含：读哪个文件、写哪个文件、格式、收/不收清单、**该库的密度基准**、约束。
- 提示词里必须写明“**严禁反复读同一文件（超约 10 次触发循环检测）**”与建议的 Read 次数。

### 8.2 监控（逐份核验，不可只看子代理的口头汇报）

每份读手/叙述返回后，**用一次 Python 调用**核验其产出文件：

```python
# 候选文件核验：行数、pk 是否在 digest 范围内、是否升序、等级分布、摘要长度、禁用字符
# 叙述文件核验：行数、pk 集合是否与候选一致、host_key 分布、长度 60-140、禁用字符
```

**校验项清单**：

| 对象 | 必查 |
|---|---|
| 候选文件 | 行数符合预期；pk 全部落在该份 digest 区间内；**无重复**；`L4/L3` 合法；摘要 20–80 字；无“”`*`\；末尾无句号 |
| 叙述文件 | 行数 == 该份候选数；**pk 集合与候选一致**；`host_key` ∈ spec 的 hosts；长度 60–140 字；无禁用字符 |
| 合并后 | **各份 pk 交集必须为 0**，并集 == 总数（防子代理复制错份） |
| 落库后 | `写后反查 quote` 与 `四表 join 命中` 均等于候选数 |
| 回写后 | 幂等二跑 **+0**；落地核验 缺块/claim_id 不符/重复 **三项全 0** |
| 提交前 | 按宿主核块数 == 该宿主分到的块数（**权威判据**）；行数与 `块数×5` 差 ≤ 宿主数（分隔空行容差） |
