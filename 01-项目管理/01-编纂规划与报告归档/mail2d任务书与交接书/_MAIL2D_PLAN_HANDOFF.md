  18. **🔴 子代理配额耗尽后的“主会话直读”作业法**（`fisp_b130` 实证，可与经验 16 的“主会话装配叙述”配套）：配额满后 `Agent` 工具直接报错，**读手与叙述手都须由主会话承担**。要点：① **单批规模必须收窄**——Read 工具单次上限 20,000 token，而 474 行 digest 约 58k token，故一份须分 3–4 次读；主会话总上下文有限，**一批以 1–2 份（约 950 封）为宜**，不宜照搬子代理时代的 15,000 封整库吞吐；② 判读结果**逐份写入候选分件脚本**（`_cand_<tag>_pK.py`，内含 ROWS 列表 + 长度/禁字符自检 + 写盘），避免上下文丢失导致返工；③ **摘要长度要一次写足 60–75 字**，实测首轮 21 条超 80 字、二轮仍有 7 条，三轮才清零——**写成后立即用脚本打印越限全文再改**；④ 短摘要（<60 字）的叙述扩写同样需 2–3 轮，脚本 `_narr_<tag>.py` 内用 `FIX`/`FIX2` 链式覆盖。**该作业法比子代理慢约 10 倍，仅在配额耗尽时使用。**

## §5 附录：入库与入大纲**完整机制**（自包含，接手必读）

> 原稿只给了 `register`/`outline` 两条命令，未说明候选如何变成四表行、又如何写成大纲块。以下为依据模板脚本（`_register_*.py` / `_outline_*.py`）还原的**契约与逐步骤**，接手照此核对即可。

### 5A 入库（`register --apply`：candidates → claim 四表）

每个候选 `pk|L3/L4|摘要` 经注册脚本汇入 `historical_claims.duckdb` **四表**，**单事务**（BEGIN→COMMIT，崩溃 ROLLBACK，禁止部分提交）：

| 步 | 动作 | 契约 |
|---|---|---|
| 1 | 源库只读取值 | `messages` 按 `CAST(id AS BIGINT)=pk` 取 subject/body/date/from_name；正文空则以主题作引文兜底 |
| 2 | 引文 quote | `body` 前 **300 字符原样同串**（先按行、再按空格边界回退截断）；**写前复核** `make_quote ∈ body`，**写后反查** evidence.quote ∈ 源正文（§6.2） |
| 3 | 双去重（幂等） | `source_id`=`SRC-rowmine:<db>.messages.<pk>`、`content_hash`=`sha256(source_id\|quote)`，各查已有集命中即跳过 |
| 4 | CL-RM 编号 | `claim_id`/`evidence_id` 续**库内** `MAX(CL-RM-*) + 1`（注册时实测，抗并行占号） |
| 5 | 四表写入 | `raw_source`(source_id/namespace=row_mine_db/source_db/source_table=messages/local_pk/content_hash/title/author/date…) ｜ `evidence`(ev_id/source_id/anchor/quote/quote_lang=en/fact_text=摘要/event_date/confidence) ｜ `claim`(cl_id/claim_text=摘要/evidence_level=Lx/wording_gate) ｜ `claim_evidence`(id/claim_id/ev_id/role=supporting/strength) |
| 6 | 词表固定 | role=`supporting`；strength/confidence L4/L3=`strong`/`0.85`；wording_gate=`attribution_allowed`（L2/L1 降 contextual） |
| 7 | 校验与产出 | dry-run 连接 `read_only=True`（**真干跑、零写库**）；apply 后输出 `COMMITTED`、`写后反查 quote N/N`、`四表 join 命中 N`、`MAPJSON`（pk→claim_id，写盘为 `<tag>_claim_map.json`，供 outline 用） |

**产出物**：`review_logs/<tag>_claim_map.json`（pk→CL-RM-N）+ 四表行。`register --dry`（不带 `--apply`）只打印计划与校验、**不写库**——是每库首窗的排练闸门。

### 5B 入大纲（`outline --write`：claim_map + mount_narr → 章节 ROW_MINE 块）

依赖 `claim_map.json`（pk→claim_id，来自 5A）与 `mount_narr.tsv`（pk→host_key→叙述，来自叙述子代理）：

| 步 | 动作 | 契约 |
|---|---|---|
| 1 | 拼装 block | 每个候选一条 **ROW_MINE 块，恰 5 行**：`<!-- ROW_MINE: <db>.messages.<pk> -->` ＋ `**当事人自述**（证据等级：Lx，来源：\`historical_claims.duckdb.claim.<claim_id>\`；<TAG> 全库行级遍历考据采纳）` ＋ 空行 ＋ `中文日期+叙述正文+纪律收束句` ＋ 空行 |
| 2 | 等级从 DB 真值读 | `evidence_level` 取自 claim_map 对应 `claim.evidence_level`（脚本由 DB 注入，**禁写死字面**，§7.3） |
| 3 | host 定位 | `host_key`（节号去点，如 `172.2`→`1722`）经 `load_hosts()` 双源解析 → 章节相对路径 → `resolve()` 按节号前缀实际定位文件（规避文件名 Unicode 差异） |
| 4 | 幂等追加 | 目标 .md 末尾追加；`<!-- ROW_MINE: db.messages.pk -->` 已存在即跳过；二跑须 **+0**（§6.3） |
| 5 | 纪律收束 | 正文补句号后追加 L4/L3/L2/L1 纪律句（TAIL 映射）；统一补中文日期前缀 |
| 6 | 留痕 | `supplement_log.jsonl` 逐条追加（ts/db/batch/row_id/claim_id/target/block/kind/level/note） |
| 7 | 格式门禁 | 写入前断言无 BOM、无 `\r`（§6.6） |

**产出物**：宿主 .md 新增 ROW_MINE 块 + `supplement_log.jsonl`。随后 `bookkeep`（落地核验三项全 0 + progress + catalog 升格）→ `commit --apply`（按宿主核块数 + 行数容差，原子提交）。

**一句话**：`register --apply` 把候选写成四表行并产出 `claim_map.json`；`outline --write` 依 claim_map + mount_narr 把每个候选写成宿主章节末尾的 5 行 ROW_MINE 块；`bookkeep`+`commit` 收尾。

1. **块格式**：ROW_MINE 块 = **恰好 5 行**（标记 + `**当事人自述**（证据等级：Lx…）` + 空 + 摘要 + 空），标记在块首。

3. **块头证据等级必须从 DB 真值读**，严禁写死字面。
4. **替换须完整锚点 + `count==1` 断言**，先 dry-run 再 write；禁止全字串替换。**模板替换生成脚本后，必须 grep 确认旧值 0 残留再写盘**（2026-09-16 138 块误写事故）。

7. **catalog 状态只升不降**：只做 `pending/deferred → in_progress`；`completed` 由专门流程判定。**绝不可用 `批数 × 500` 反推状态**（曾误降 95 个 completed，需人工回滚）。
8. **源库全程 `read_only=True`**；**禁关键词筛行**；禁脚本自动分类/提炼/写库。
9. **不 commit 他人改动**：`git commit -- <paths>` 提交的是**工作区状态**，宿主常被多会话共用。
10. **遇 duckdb 锁冲突**：退避重试，**不得杀他人进程**。
11. **收/不收纪律**（读手提示词必须逐条写清）：

## §9 1M 上下文适配：**整库吞吐 + 超并行子代理**（会话最小化）

### §9.1 1M token 预算分配（关键：**不把 digest 载入主上下文**）

1M 主上下文的真正占用是**编排状态与子代理回报**，而非史料全文——**digest 一律由读手/叙述在各自子代理上下文内读**，主会话只收“份→行数→pk区间→摘要计数”一行摘要。据此：

- 主上下文常驻：任务书（本文件，可一开即读一次）+ 各 spec JSON + check/register-dry 输出 + 各份候选/叙述的**计数与 pk 区间**（每份 ≤3 行）。
- 一次性载入估算：读手/叙述各 8 路的回报 ≈ 40–80 条摘要行 ≈ **5–10k token**；一轮窗口的编排状态 ≈ **1–3k token**。即主上下文在 1M 内**可容纳数十轮**——会话容量由**工具调用次数与子代理墙钟**决定，不由上下文封顶。
- **推论**：会话内可安全合并更多库/窗（见 §9.2 第 5 条），会话总数只受“子代理吞吐 + 门禁调用”约束。
- 若某库 digest 确需主会话直读（如复核），一次只放 **≤3 份**（3×250k≈75 万 token），读后即从回复中精简为计数摘要。

|---|---|---|
| 1 | **一库一批**：小/中库 `n=剩余全部`（≤10000），整库一次 dump、一次 register、一次 outline | 每库仅 1 组门禁调用，省掉逐窗重复 register/outline（§9 原“8–12 窗/会话”的往返大头） |
| 2 | **读手/叙述 ≥8 路并行**：一条消息内多个 `Agent` | 子代理墙钟从“串行×N”降为“一次并行” |
| 3 | **门禁 `&&` 一次串起**：register→body→outline→bookkeep→commit 单条命令 | 5 次往返 → 1 次 |
| 4 | **上下文内记状态**：各份行数/pk区间直接记在回复里 | 杜绝 `ls`/`wc` 探查（每次都是往返开销） |
| 5 | **同库多窗合并**：大库一次 `n=多窗` dump、候选抽全后统一拆叙述 | 省多次 dump/body |
| 6 | **密度基准逐库入提示词**（§7.12） | 避免跨库多收/少收返工 |
| 7 | **register-dry 作排练**（见 §9.3） | 首窗先看 DB 写预览再 --apply，防脏库 |

### §9.3 干执行（dry-run）边界（实测结论，接手必读）

**只有前半段能真干跑**，后半段依赖真态：

- ✅ **可干跑（零副作用）**：`new`→`dump`→`check`→`register`（**不带 `--apply`**，生成脚本并运行 dry，只打印 DB 写预览，不写库）→`body`（只抽正文）。`status`/`check` 只读。
- ❌ **不可干跑**：`outline`/`bookkeep`/`commit` 必须读取 `review_logs/<tag>_claim_map.json` 与**已写进大纲的块**——而 claim_map.json 仅在 `register --apply` 后生成、大纲块仅在 `outline --write` 后存在。**故 outline+ 无法在不动库/不改文件的前提下排练。**
- **因此“整批干执行”的落点是 register-dry**；outline 及以上用两重就地校验兜底（§6.3 幂等二跑 +0 + §6.4 独立落地核验三项全 0），本身即低风险真写，不另设 dry 态。
- **实操建议**：每库首窗先跑 `check` + `register --dry` 看预览（quote N/N、四表 join），无误再 `--apply` 走完后段。这既是 0.3% 量级“干执行”样本的验证，也是每库的质量闸门。

## §10 子代理派发与监控（**必须做**）

### 10.1 派发

- **一次并行 2–4 个子代理**（读手或叙述）；**一条消息内放多个 `Agent` 调用**才能真正并行。超过 4 个必须拆到下一轮，**严禁一次性海量派发**。
- 每个子代理提示词必须**自包含**：读哪个文件、写哪个文件、格式、收/不收清单、**该库密度基准**、约束。
- 必须写明“**严禁反复读同一文件（超约 10 次触发循环检测）**”与建议 Read 次数。

### 10.2 监控与**时间盒（不允许死等）**

- **每个子代理硬时间盒 25 分钟**：派发后**后台轮询**，每轮先查盘上目标文件是否已产出（§8.9：返回空 ≠ 没产出）；到点未回即判超时，**不许干等**。
- 超时处置（择一，主会话串行兜底）：① 检查盘上文件——若已产出则直接继续，不再重派；② 若确实未产出，按剩余工作量**重派（≤4 个）或由主会话串行补齐**，并记录。**绝不无限轮询单个子代理**。
- 逐份核验下表，**只看盘上文件，不看子代理口头汇报**：

| 对象 | 必查 |
|---|---|
| 候选文件 | 行数符合预期；pk 全部落在该份 digest 区间；**无重复**；`L4/L3` 合法；摘要 20–80 字；无“”`*`\；末尾无句号 |
| 叙述文件 | 行数 == 该份候选数；**pk 集合与候选一致**；`host_key` ∈ spec 的 hosts；长度 60–140 字；无禁用字符 |
| 合并后 | **各份 pk 交集必须为 0**，并集 == 总数（防子代理复制错份） |
| 落库后 | `写后反查 quote` 与 `四表 join 命中` 均等于候选数 |
| 回写后 | 幂等二跑 **+0**；落地核验 缺块／claim_id 不符／重复 **三项全 0** |
| 提交前 | 按宿主核块数 == 该宿主分到的块数（**权威判据**）；行数与 `块数×5` 差 ≤ 宿主数 |
