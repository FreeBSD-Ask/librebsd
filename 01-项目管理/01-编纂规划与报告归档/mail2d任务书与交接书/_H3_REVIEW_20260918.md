## 五、开工后新增发现（执行中实测，两库通用性待验）

### P6｜“容器行”机制：`body` 吞并整段 mbox 的缺陷行（**本线此前无记录**）

- **事实**：`freebsd-hackers` 库内存在一类行，其 `body` **吞并了其后整段 mbox**——实测单行内含
  **18 / 202 / 623** 封**他人**邮件（pk 1675／1676／2573），体积 56 KB–1.35 MB，且行间 `date`
  呈**近整周间隔**（1994-12-17、12-18、12-25、1995-01-01…），`from_email` 只对应其中一封。
- **规模**：全库 `body` >20 KB 者 **431 行 / 201,463（0.21%）**；本线首批窗口（库内序 0–1999）内
  达 **304 行（15.2%）**——即该窗口六成候选行是此类，属**低 id 区集中现象**。第二批窗口（库内序 2000–3999）
  为 **0 行**，可见其分布随 id 区段急剧变化，须**逐批实测**（`_list_container_pks.py`）。
- **史料学判定：不收**（三条依据均已实测）：
  1. **归属错误风险**：容器行 `from` 非正文大多数消息的作者，落库将**系统性错误归属**（触犯 0 信任原则与人物名誉纪律）；
  2. **内容重复**：其内嵌消息在**同库另有独立行**——40/40 抽样命中（如 pk 1675 的
     "Who has an EISA config file" 另有 id 2540522、体积 298 字节的独立行），**不收不损失史料**；
  3. **规则依据**：本线既定“机器转发／汇总不构成史料”。
- **机具化**：新增 `_list_container_pks.py`（客观判据：`LENGTH(body)>20000` 且行首 `From ` ≥3 且含 `From owner-`），
  逐批生成 `review_logs/<tag>_container_pks.txt` 交读手；行本身**不从 digest 中剔除**（保持“不隐藏、不跳过”纪律）。
