### 〇之二 UNC·D 盘环境适配规约（2026-10-03 主理人令，F1–F4 同文；与 H1–H5 五线 UNC·D 盘适配规约对齐）

**本战役全程跑在 SMB/UNC 上（`D:\librebsd` 与 `\\DESKTOP-M5P610N\d\librebsd` 为同一仓库双身份）；下列规约为硬约束，与本任务书既有流程冲突处按本节从严。**

1. **路径写法表**：Write／Edit 工具 → **Windows 反斜杠路径**（`\\DESKTOP-M5P610N\d\librebsd\...`；POSIX 路径 `/d/librebsd/...` 会**报成功但不落盘**）；bash → `//DESKTOP-M5P610N/d/librebsd/...`（无 `/mnt`）；Python → 正斜杠或 `os.path` 拼接（反斜杠 UNC 字面量是转义陷阱）。
2. **🔴 禁内联 `python -c` 与 `python - <<'EOF'` heredoc 在 UNC 上直接执行**（`FileNotFoundError` 指向明明存在的目录，已多次坐实）——本任务书各 heredoc **仅作逻辑留档**，执行时一律先落成 `.py` 文件（各组 `work/` 下自有命名，如 F1 的 `work/_f1_hosts.py`）再 `python <该文件>` 跑。
3. **写后必须独立验盘**：Write／Edit 报成功 ≠ 落盘（UNC 静默失败家族）；宿主备份（`b3_bak/`）、判读件、台账、`hosts_*.txt` 清单写后用**独立命令**（`ls -la` 字节数／`wc -l`／grep 锚点计数）复核；`os.path.isfile` 对刚写完的文件可能返回过期 False（写后负缓存），间隔重读再判。
4. **UNC 假阴性三族**：`os.listdir` 可能漏列真实存在的项（按精确路径 `os.stat` 复核才可信）；`grep -c` 对中文路径可能假阴报 0（真值取 Python `io.open` 遍历）；**子代理报「文件不存在」先按 SMB 假阴处理**，主会话按精确路径复核后才可判死（与 §〇之一.4 联动）。
5. **慢 IO 纪律**：单代理内并行 Read 多份输入会 30s 双双超时——子代理一律**串行读**；`ls`／`grep` 走 UNC 极慢，fetch×judgements×shards 三方对账等批量计数用**单进程 Python 遍历**，禁 shell 循环（中文路径 bash for 只跑首个）。
6. **mtime 口径**：UNC 与本机时钟存在 ~15h 时区**标签**差（git `+0800`／`−0700` 混用同源，全链无真实漂移）；mtime 绝对值可信、相对年龄不可用；HOT 判据（<2 分钟）以本机钟为准。
7. **git 纪律（UNC 增补）**：提交前 `git update-index --refresh`（UNC stat 缓存会让已写盘文件显示无改动）；pathspec 白名单精确列出＋`git add -f`（`/script` 整树被 `.gitignore` 忽略）；禁 `git add -A`、禁 amend、**不删 `.git/index.lock`**（持锁 sleep 15 重试）；管道别用 `tail`（吞退出码——`echo RC=$?` 或 `PIPESTATUS[0]` 单独取）；`hosts_*.txt`／路径清单必须**纯 LF**（shell 重定向会带 CR，一律用 Write 工具写；CRLF 清单已实证令 apply 报 Errno 22）。
8. **glob 归一**：`glob.glob` 在 Windows 返回反斜杠路径——路径比较、台账登记一律 `os.path.basename` 或 `replace(chr(92),chr(47))` 归一后进行。

### 5. 入库与入纲频次（2026-10-09 主理人令加强；批次十四起固化）

**「每波一次」是下限、不是节拍——不凑整批、不等全波收口。** 批次十四实证：3,638 块判读落盘后首波补字只覆盖 87 条，178 条 remap 块因「以为会被搬走」整整空转一轮，直到 `oaa_verify` 报 178 项 G3 才抓回。频次不足＝缺陷在盘上停留更久、门禁要跑的次数翻倍。

- **判读落盘即入纲**：任一分片组（≥10 片或 ≥400 块）判读＋独立核验一绿，**当即 dry-run → apply → 差分门禁 → 安装上盘**，不等同批其余片收口。
- **补字与判定分离、同波入纲**：判读阶段先出判定，字数不足块在判读落盘后**同波**补字并入纲；**判定类别不决定门禁义务**——块只要还留在大纲上就受 G3 约束，remap／keep／fix-db 一律照补（批次十四报告 §二：`apply` 原地改写、不搬块，remap 块在原地照样被字数门禁审）。
- **register 至少每宿主一次**：单一宿主改写块数达 200 即 `oaa_register` 入账一次（`--ledger processed_f4.jsonl` 幂等按 key 覆盖，多次 register 不重复计数），避免「判读在盘、台账未登」的浮标盲区——浮标口径是锚点扫描量、台账口径是 register 入账量，两者不同步时会话间互相误判进度。
- **浮标 `--refresh` 每批至少两次**：开工一次、register 后一次；批内已 register 且单宿主达 200 块级，中途再刷一次让待办及时可见。
- **门禁跟着频次走**：`oaa_verify --len-flex` 每次 register 后跑一次（实测约 70 秒，可接受）；差分门禁每次 apply 后跑一次。**门禁跑得起才敢提频次**——本批门禁判据全部落成独立本机脚本（§〇之四），宿主级 dry-run 可单跑，这是频次能提上去的前提。
