# DuckDB 2.0 · historical_claims 迁移试验与原子替换演练

- 日期：2026-10-24
- 依据：ykla 当日指令“historical_claims.duckdb 的也改造，最后做原子替换，反正是只读的。changelog 暂时放弃”；`.trae/specs/upgrade-duckdb-to-2-0-0-20261024/spec.md`
- 环境：全局 `C:/Python314/python.exe` = duckdb 1.5.5；沙箱 venv = duckdb 2.0.0（清华镜像安装，全局未动）
- 纪律：源库仅只读打开；未触碰生产路径；未新建备份；沙箱体用完即删

## 一、结论摘要

1. **迁移等价成立**：`historical_claims` 34 表／2,109,042 行／255 列／12 约束，导出导入后逐项一致（表清单、列定义、约束、索引、逐表行数、抽样 100 行 sha256、`schema_meta` 全文全 PASS）。
2. **唯一差异为引擎内置宏**：源 118 名／131 条，新 121 名／140 条；差集全为 2.0.0 运行时内置宏（移除 `round_even`／`roundbankers`，新增 `assert_true`／`if`／`json_copy_strftime_*`／`variant_group_array`，29 个权限宏定义变化）。**用户自定义宏两库均为 0**，不构成数据差异。
3. **体量大幅下降**：643,837,952 B → 424,423,424 B（−219,414,528 B，**−34.1%**）。
4. **关键实测（推翻先前假设）**：2.0.0 对 v64 库执行真实写入＋`CHECKPOINT` 后，文件头存储版本**仍为 64**，**不会就地升级**。故“changelog 暂缓”在运行时切到 2.0.0 后依然成立。
5. **原子替换机制可用**：目标文件被只读句柄占用时 `os.replace` 报 `PermissionError [WinError 5]`；句柄释放后重试成功，替换后 SHA-256 与新库一致。

## 四、格式探针：2.0.0 写入是否就地升级 v64

在 `changelog` 的沙箱副本（40.6 MB，存储版本 64）上以 2.0.0 执行 `CREATE TABLE`＋`INSERT`＋`DROP TABLE`＋两次 `CHECKPOINT`：

- 写入前存储版本 **64**，写入后 **64**，`是否就地升级 = False`。

**意义**：运行时切换到 2.0.0 后，未迁移库（含 `changelog`）在 2.0.0 下正常读写且保持 v64；`changelog` 暂缓迁移不会因他线写入而被被动升级。

## 五、原子替换演练

以 `fact_checks` 副本模拟“旧库”，以本试验新库模拟“新库”：

1. 子进程以 `read_only=True` 持有旧库句柄；
2. `os.replace(新库, 旧库)` → `PermissionError [WinError 5] 拒绝访问`（**有活跃句柄时不可替换**）；
3. 子进程退出后再执行 → 成功；
4. 替换后 SHA-256 与新库一致（内容未被改写）。

**结论**：原子替换本身可靠，但**必须在无活跃句柄的瞬间执行**；替换前须做连接探测与重试，不能假定一次成功。

## 六、runbook（供 Task 7 使用）

1. 切换运行时到 2.0.0（Task 8）——`historical_claims` 的三个读者（`audit_evidence_level_labels.py`、`audit_anchor_resolution.py`、`outline_writer.py --db`）才能打开新格式库；
2. 对每库：1.5.5 导出 → 2.0.0 导入 → 逐项等价核对 → 确认无活跃句柄 → `os.replace` 原子替换 → 复读校验；
3. `historical_claims` 替换前探测三类读者是否在跑；占用时退避重试（建议 5 次×2 s），仍占用则跳过并登记 `SWAP_BLOCKED`，不强行替换；
4. `changelog` 本轮**不迁**，保持 v64；待大纲落地批收口后单独执行同一流水线；
5. 每库导出体在下一库开始前删除；全程串行。

## 七、待办与限制

- 本报告只证“单库可迁、替换机制可用”，**未执行生产替换**；
- `historical_claims` 新库文件未保留（沙箱已删），替换时按 runbook 重跑（约 10 s）；
- `IMPORT DATABASE` 不吃 `?` 参数绑定；宏差异属运行时集合，不写入任何库；
- 存储版本 999 与官方文档“69”的差异仍未解释，不影响本批结论。
