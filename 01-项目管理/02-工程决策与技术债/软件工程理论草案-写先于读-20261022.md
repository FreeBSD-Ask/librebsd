## 一、核心原则（P0，强制）

**任何规范化、改造或加固程序，第一步必须在生产等价副本上执行一次完整写入演练——覆盖该链路的全部写入面（库、宿主文件、台账），含幂等二跑与回滚断言——之后才允许开展读侧审计、规格编写与门禁建设。**

顺序不是偏好，而是判据的依赖关系：**写侧可用性是真值，读侧判据是对真值的描述**。顺序颠倒会产出“判据自洽而与真值无关”的规范——本项目的 26 条 FR 与 29 件门禁都曾在未验写侧的情况下被判为“全绿”。

## 二、三条推论

- **C1 写先于读**：读侧审计与规格的每一处结论，必须能指向一次已完成的写入演练；无写入演练的链路，其读侧结论只能标 `未验证`，不得标 `通过`。
- **C2 dry-run 不是演练**：dry-run 只证明“定位与计划”，不证明“写入正确、可复跑、可回滚”。凡以 dry-run 结项的链路，结论只能写“计划已核，写入未验”。
- **C3 沉默失败是首要对手**：显式 FAIL 会被修，静默跳过不会。凡“跳过／放弃／零结果”的分支，必须在 stdout 留可见计数（D5 的“只写 stderr”正是 30 单位时整宿主停摆被漏报的机制）。

## 三、演练完成的最小可判定集（Definition of Done）

一次写入演练，**五项断言缺一不可**，全部机器可判：

| # | 断言 | 判定方式 |
| - | ---- | -------- |
| A1 | 对**生产等价副本**（库副本、宿主副本、台账副本）执行了**真实写入** | 写入后有新增行的行数／新增块的计数证据 |
| A2 | **幂等二跑 +0** | 同输入再跑一次，新增计数为 0，且两次输出逐字节一致 |
| A3 | **回滚／还原断言** | 删除或还原后，副本回到演练前状态（哈希或行数比对） |
| A4 | **生产零改动** | 生产路径的 SHA-256／聚合哈希在演练前后一致，并留档 |
| A5 | **失败路径演练** | 注入一个坏件（坏 key、空正文、越界 pk），断言该宿主／该批**停摆**且**stdout 有可见计数** |

**禁止条款**：不得以“selftest 全绿”替代演练；不得以“dry-run 输出一致”替代写入；不得以“子代理回报”替代磁盘回读。

## 四、强制请示条款（消除“该问没问”）

出现下列任一情形，**必须停手请示主理人，不得自行裁量**：

1. **任务含范围歧义词**且无既有定义：演练、全链路、规范化、优化、完善、收口、清理、加固；
2. **动作可能触及生产写入**（库、大纲、台账、提交），包括“看起来只是 dry-run”但实现路径可能写盘的场景；
3. **判据无法机器判定**，只能靠文字评审；
4. **发现既有脚本／规格与本原则冲突**（如幂等判据为文件级而非块级）；
5. **同一处连续两次以上不确定**时。

请示格式固定三行：**要做什么｜影响面｜请批准或改判**。
