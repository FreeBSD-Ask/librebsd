# ADR-0013：任务准入门禁以“已启动”为界

- **状态**：已接受
- **日期**：2026-10-22
- **裁决人**：ykla
- **执行者**：主代理
- **复审日期**：2027-01-22
- **替代关系**：无；细化《工程实践规则》§0.1 第 1 条与第三十二件门禁 L2 的作用域，不改其义务内容

## 1. 形式

第三十二件门禁 `audit_task_lifecycle.py` 的 **L2**（准入行判据）作用域收窄为“**已启动**的生效后任务”，机械判据如下：

1. **启动信号（三者任一即算已启动）**：① 该 spec 的 `tasks.md` 中已有 `- [x]`／`- [X]`；② 该 slug 已作为任务 ID 出现在 `任务审计台账.md`；③ 该 slug 已作为任务 ID 出现在 `任务复核台账.md`（只看任务 ID 列，正文提及不算）。
2. **已启动**者仍须有准入行；缺行即 L2 FAIL，判据与结论文字保持“缺准入行：<slug>”。
3. **未启动**者免准入，不计 FAIL，计入 SKIP；L2 详情须打印“扫描 N 个生效后 spec／已启动 M／未启动 K 计入 SKIP：<slug 列表，截断前 10 个>”。
4. **L3 不变**：已收口任务（`tasks.md` 全部勾选）仍须 PASS 收口行与四段收口证据。
5. 判据归属：本件只改“何时须准入”，不改“准入须填什么”（字段表见《工程实践规则》§0.2）。

## 2. 矛盾

- **不做的后果**：`spec.md` 写盘即产生 spec 目录，“目录存在”被等同于“任务已启动”。立项草案、待裁方案、跨批预研一律被 L2 判 FAIL，门禁长期带假阳；为消警只能给未开工草案补准入行，等于**伪造准入记录**，反向破坏准入证据的可信度。
- **实测**：本批开工时对 `.trae/specs/` 全量扫描，`reframe-outline-five-parts-20261022` 的 `tasks.md` 全部勾选框为 `- [ ]`、`任务复核台账.md` 无其任务 ID 行、`changelog.duckdb` 零命中，而 L2 仍报“缺准入行”，门禁 exit 1；该 FAIL 与同批真实 FAIL 混列，掩盖真问题。
- **受影响者**：主代理（每批须解释假阳）、ykla（验收时无法凭退出码判断）、复核子代理（须逐项区分真假阳）、接手会话（易误补行）。

## 3. 正面

- **能力**：L2 的判据与规则原文“**开工前**在台账增一行”对齐，义务触发点从“草案存在”回到“动手开工”；门禁退出码重新可当批次放行信号用。
- **受益者**：主代理、ykla、复核子代理、接手会话。
- **验证方式**：`--selftest` 新增正负两例——“已启动且缺准入行”必须 FAIL（`tasks.md` 有 `- [x]`、无审计行、无复核行），“未启动且缺准入行”不得 FAIL（`tasks.md` 全 `- [ ]`、无审计行、无复核行）；实跑须打印 SKIP 数量与 slug 列表。

## 4. 负面

- **成本**：已启动/未启动的判定依赖 `tasks.md` 勾选纪律；若任务实际动手却从不勾选，信号①失效，只能靠②③兜底。
- **可绕过面**：先写 spec、开工后仍不勾选任何任务且不进两个台账，则 L2 看不见该任务（记为 SKIP），准入义务靠 L3（收口须 PASS 行与四段证据）与《工程实践规则》§0.3 季度抽查兜底——绕过者一旦要收口，必然暴露。
- **边界**：不追溯生效前的 spec；不改变字段、轮次、签收与收口判据；不因本件放宽任何已启动任务的准入要求。

## 5. 承担者

| 负面 | 承担者 | 承担时点 |
| ---- | ------ | -------- |
| 勾选纪律（开工即勾第一条任务） | 主代理 | 每批开工时 |
| SKIP 口径的解释与抽查 | 复核子代理、ykla | 每批复核与季度抽查 |
| 绕过情形的识别与登记 | 复核子代理 | 季度抽查（2027-01-22 首次） |

## 6. 过去依据

- **历史条件**：2026-10-22 起施行的准入审计要求“开工前增一行”，但门禁 L2 的实现以“spec 目录存在且 slug 不在审计台账”为唯一判据，未区分草案与已开工任务。
- **此前形式为何失效**：立项草案（`spec.md` 已落、`tasks.md` 全未勾选、无复核行、无 changelog 条目）被计入 FAIL；消警的唯一路径是给未开工草案补准入行，与“开工前才登记”的时序要求直接冲突。
- **证据**：本会话实跑 `audit_task_lifecycle.py` 原始输出（L2 FAIL 仅列 `reframe-outline-five-parts-20261022`）；裁决时刻该 spec 的 `tasks.md` 勾选框统计（顶层 9 个全为 `- [ ]`、已勾 0）、`任务复核台账.md` 任务 ID 列零命中、`changelog.duckdb` 表 `entries`／`file_archive` 全列零命中。
- **时序说明（0 信任侧披露）**：同一 spec 在本件裁决后（2026-10-22 21:20—21:27）由并行会话实际开工并勾选任务，勾选状态已非全空。该变化不改本件判据：草案期计入 SKIP，开工后按信号①转为“已启动”，随即须有准入行——这正是本件要区分的两种状态，而非判据失效。

## 7. 现在依据

- **测试／测量**：`audit_task_lifecycle.py --selftest` 16 例全 PASS（原 14 例保留，新增 `started-without-intake` 负例与 `unstarted-without-intake` 正例）；实跑 L2 详情含 SKIP 数量与 slug 列表。
- **日期与环境**：2026-10-22，Windows，`d:\librebsd`，`C:/Python314/python.exe`。
- **证据路径**：`script/_l2_scope_fix_20261022.md`（判定依据、改动、门禁原始输出、selftest 结果）；`script/_l2_evidence_20261022.py`（三信号采集）。

## 8. 将来失效条件

1. `.trae/specs/<slug>/` 改为**一次性生命周期目录**（立项即建、收口即归档销毁），“草案存在”与“任务已启动”不再可区分；
2. 出现**自动勾选机制**（CI 或脚本按提交／门禁结果回写 `tasks.md` 勾选），信号①不再代表人工开工意图；
3. 准入登记改为**先于 spec 创建**的强制流程（如台账行生成 spec 骨架），本件的“启动后才须准入”失去意义；
4. `tasks.md` 勾选框语义被替换（如改为状态字段），三信号须重定义。

## 9. 0 信任校验

- **独立复现方式**：不复用门禁自报，另行读取 `tasks.md` 原文统计 `- [x]`／`- [ ]`，并直接查询 `changelog.duckdb`（只读连接）与两个台账的任务 ID 列；三信号逐条给出读数。
- **交叉验证工具**：`script/_l2_evidence_20261022.py`（独立脚本，不复用门禁内部函数）；`audit_task_lifecycle.py --selftest` 正负夹具。
- **原始证据位置**：本批报告 `script/_l2_scope_fix_20261022.md`；门禁与自检 stdout 原文。

## 10. 自由影响

- **退出**：门禁退出码语义更严——只有“已启动却缺准入”才为 1，草案不再拖累批次；不影响任何任务的实际施工自由度。
- **导出**：SKIP 列表进入门禁文本输出，便于批次报告直接引用；无新增二进制或闭源依赖。
- **离线**：全部本机执行，无联网依赖、无外部服务。
- **默认值可撤销性**：三信号与本件判据由 ykla 按 §8 事件裁定调整；回退只需恢复 L2 原式并回退 selftest 两例，无数据迁移。

## 11. 安全和解

- **资产**：`任务审计台账.md`（准入与收口的唯一主表）、`任务复核台账.md`、`.trae/specs/` 勾选状态。
- **对手**：伪造准入记录、开工不登记、以草案充数、以勾选掩盖未登记。
- **攻击面**：`tasks.md` 勾选框（可被批量伪造）、台账任务 ID 列、门禁对 spec 目录的扫描面。
- **信任边界**：主代理执行与自报、复核子代理只读复验、ykla 签收；门禁只信盘面文本，不信自述。
- **现有控制**：L2 只放行“未启动”者，已启动仍须行；L3 强制收口行与四段证据；L6 唯一性；季度抽查（《工程实践规则》§0.3）；复核者与作者角色分离。
- **残余风险**：开工不勾选且不进两台账的“隐形开工”，L2 记 SKIP、须靠 L3 收口与抽查发现；勾选状态与真实进度可能不同步。
- **证据**：本批实跑输出与 selftest；`script/_l2_evidence_20261022.py` 读数。
- **代价**：见 §4。
- **失效条件**：见 §8。

## 12. 复审触发

- **时间**：2027-01-22（与工程实践复审同批）。
- **事件**：出现“开工不勾选”绕过实例；spec 目录改为生命周期目录；自动勾选机制上线；L2 再次出现成批假阳或漏判；`tasks.md` 勾选语义变更。
- **复审动作**：核对本批后的 L2 实跑记录与 SKIP 列表、季度抽查结果与绕过实例，决定维持、修订或替代本件，结论写入 `工程实践复审台账.md`。

## 附：替代方案与取舍

| 方案 | 正面 | 负面 | 为何未选 |
| ---- | ---- | ---- | -------- |
| 维持“spec 目录存在即须准入”（现状） | 零改动 | 草案成批假阳；消警只能伪造准入行 | 判据越界，破坏准入证据可信度 |
| 取消 L2，只靠人工抽查 | 无假阳 | 准入义务失去机器兜底 | 与本条规则“未 PASS 不得开工”冲突 |
| 以 spec 目录 mtime／正文规模推断启动 | 不需勾选纪律 | 判据不可解释、可被文件保存动作触发 | 不满足二值可判 |
| **以三个启动信号为界（本件）** | 与规则原文对齐、可机判、可自检 | 依赖勾选纪律；有“隐形开工”绕过面 | 采用 |
