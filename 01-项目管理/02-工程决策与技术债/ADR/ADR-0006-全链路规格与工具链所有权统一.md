# ADR-0006：全链路规格与工具链所有权统一

- **状态**：已接受
- **日期**：2026-10-22
- **裁决人**：ykla
- **执行者**：主代理
- **复审日期**：2027-01-22
- **替代关系**：补充 ADR-0001 的工程实践基线，不替代其他 ADR

## 1. 形式

本决策为 F1–F4、H1–H4、重构2026 三条全链路固定四项边界：

1. **规格位置**：线级 spec 统一放 `01-项目管理/02-工程决策与技术债/全链路规格/`，命名 `<线名>-全链路规格.md`；不放入被忽略的 `.trae/specs/`。规格采用 `工程实践规则.md` §1 的轻量基线：范围、非目标、FR/NFR、验收判据、证据位置、证伪条件。
2. **工具链所有权**：
   - F 线：`脚本与命令/oaa_*.py`、`apply_fixes.py` 为权威件；门槛脚本 `_f3_apply_dryrun.py` 一类须重建并升格，不得继续只存在于 `script/`。
   - H 线：核心驱动 `_prep_batches.py`、`_mail2d_run_batch.py`、`_mail2d_batch_dump.py`、`_build_read_ledger.py`、`_merge_cand.py`、`_merge_narr.py`、`_vn_narr.py` 按 SHA-256 **复制**入 `脚本与命令/`，前缀 `mail2d_`，并登记；`script/_db_row_mining/` 原件在在途批次收口前保持运行，路径切换另批执行。批内一次性脚本留 `script/`，不迁。
   - 重构2026：`assemble_index.py` 为唯一装配写者；`embed.py`、`font_subset_rebuild.py` 的直写行为登记为有意识例外，须在各自 README 行注明对象面与触发面。
3. **台账单写入口**：每条线只保留一个台账写入口；F 线为 `oaa_beacon.py`（刷新）与 `oaa_register.py`（登记），H 线为 `_build_read_ledger.py`（重建）＋批内 append 件（仅追加），两者不得互相覆盖。出现第二写入口即判双源，先停写后合并。
4. **批次门禁**：F 族新增 `audit_oaa_batch.py`，H 族新增 `audit_mail2d_batch.py`，均须 `--selftest`（负向夹具）并登记 `audit_gate_registry.py`；重构2026 沿用既有编号门禁，补登记与锚点同步，不另造平行门禁。

**边界**：不改变在途批次的数据契约、判读产物、台账 key 结构、claim 号段或大纲块；不改变读者可见页面。

## 2. 矛盾

- 不做：F/H 的验收判据散在任务书正文，工具链 15,412 个 `.py`／约 88.6 MB 全部未入库，4 个被引用脚本已不存在；重构2026 有四件门禁未登记、两处自检声明不符、`review_v2_full` 锚点停在 37 卷 352 章 3,023 节。
- 受影响者：主代理（复现与评审）、ykla（验收）、复核子代理（无统一判据）、后续接手者（脚本丢失即无法续跑）。

## 3. 正面

- 能力：每条线有唯一 spec、唯一台账写入口、一组可自检的批次门禁；核心工具链可 diff、可复现、可追责。
- 受益者：接手会话、ykla、复核者。
- 验证方式：`audit_engineering_practice.py` E1–E7、`audit_gate_registry.py` R1–R8、两件新批次门禁的 `--selftest`、`_longline_status.py --check`。

## 4. 负面

- 成本：H 线核心驱动复制与登记增加维护面；F 线三件补 selftest 需负向夹具；新门禁需在真实批次上校准。
- 风险：复制件与运行原件可能分叉；台账单写入口收敛会触碰批内 append 件；新门禁若判据过严会阻断在途批次。
- 边界：本轮不全量迁移 15,412 件，不切换 H 线路径，不重构 `embed.py`／字体脚本的写盘行为。

## 5. 承担者

| 台账写入口收敛 | 主代理、ykla | H 线下一批前 |

## 8. 将来失效条件

1. `.trae/specs/` 纳入版本控制并成为规格权威位置；
2. H 线核心驱动完成路径切换，复制件与原件合并；
3. 台账改为数据库主存储并有单一写服务；
4. 批次门禁被合并进统一收口器，单线门禁不再需要；
5. 任务类型消失或三线全部闭口。

## 9. 0 信任校验

- 独立复现：`audit_gate_registry.py`、`audit_engineering_practice.py`、两件新批次门禁 `--selftest`。
- 交叉验证：复制件 SHA-256 与原件逐件比对；台账 `--check` 与权威源比对；spec 的 FR/NFR 逐条有验收与证据路径。
- 原始证据：审计报告、`git status`、门禁输出、changelog。

## 10. 自由影响

- 退出：不改变读者可见界面与导出、离线能力。
- 导出：spec 与门禁均为普通 Markdown／Python，可直接读取与复跑。
- 离线：全部本机执行，不依赖外部服务。
- 默认值可撤销性：工具链边界与路径由 ykla 按 §8 修订，复制件可回退。

## 11. 安全和解

- 资产：任务入口、判读产物、台账、claim 库、目录页产物。
- 对手：时间与并发导致的双源、脚本丢失、门禁假绿、在途批次被打断。
- 攻击面：`script/` 未入库件、台账写入口、门禁登记表、复制件同步。
- 信任边界：主代理执行、ykla 批准、复核子代理只读核对。
- 现有控制：写前备份、waterlock、guard、门禁、changelog、SHA-256。
- 残余风险：复制件分叉、旧批内脚本未迁移、新门禁误判。
- 证据：审计报告、R1–R8、E1–E7、复制件哈希。
- 代价：每批增加一次哈希同步与门禁运行。
- 失效条件：见 §8。
