# ADR-0019：意图确证前置与手段次位

- **状态**：已接受
- **日期**：2026-10-29
- **裁决人**：用户（ykla）
- **执行者**：主代理
- **复审日期**：2027-01-29
- **替代关系**：无（新增）；是缺口 `TG-012` 的落地方案，与 `ADR-0007`（软件工程理论的项目化裁剪与增补）同向；不追溯口径与 `ADR-0013`（准入以已启动为界）、`ADR-0014`（复核轮次以收口为界）一致

## 1. 形式

- **决策**：新增理论件 `13-软件工程/08-intent-first.md`（命题与来源、工程翻译、意图确证单、三问 STOP、手段次位条款、反模式与自反）；在 `流程规则/01-复核与验证.md` 设顶层 H2“意图确证（知难行易；全任务适用；2026-10-29 立）”作为判据正文，定义档 A 全量六字段（用户原话、目标、非目标、验收判据、手段自由度、未知／`[待验证]`）与档 B 轻量三要素（用户原话、目标、完成判据）；工程类批次由 `工程实践规则.md` §0.6 落地；门禁由 `audit_engineering_practice.py` 的 E8 校验接线。
- **单一来源边界**：判据正文只在 `流程规则/01-复核与验证.md` 该全局节；`08-intent-first.md` 承载命题来源、原文引用与工程翻译；`工程实践规则.md` §0.6 只补工程类批次落地细目与 E8 指向；`AGENTS.md`、`01-规则/README.md`、模板 I 与门禁脚本只留指针，不复制正文。
- **落点**：档 A 写于 `spec.md` 首节、`tasks.md` 批首或长线任务书；档 B 写于任务书或会话记录一行；`任务审计台账.md` 的准入证据须写明定位（文件名＋小节名或行号），不得只写“已确认”。
- **边界**：不追溯已收口任务与已完成批次；不新增独立脚本与门禁件；不改 `05-卷册大纲/` 的结构与内容；不改 `13-软件工程/00`–`07` 正文。

## 2. 矛盾

- **手段先于目标**：G0 的旧退出判据只有范围项（范围有书面结论、范围外逐条列出、阻塞有登记、代价承担者写明）加长线续跑项，没有“用户到底要什么”的可判定证明；工具、脚本、技术栈与既有设施因而先被固定，目标后补或被反剪。
- **先做后问**：`工程实践规则.md` §0.2 的准入字段表（任务 ID、任务名、类型、风险级别、起算日、准入结论、准入证据、复核轮次、理论适用性、承担者、复审触发）无任何意图项；§1 需求基线的“来源”一列仅列用户原话、Issue、审计编号、门禁输出或故障记录，不要求写出目标与非目标；§0.5 的违规清单只列“未准入即开工”，未列入“未经意图确认即动手”。
- **覆盖面缺口**：`工程实践规则.md` 的适用范围止于工程类批次，并明确不适用史料考据、正文撰写、大纲内容增删；这些任务与纯只读任务在全链上没有任何意图环节。
- **受影响者**：任务发起者（ykla，目标被动改写的最终代价承担者）、主代理（只能靠上下文猜测目标）、被派发的子代理（派发提示不含非目标与验收判据时按自选标准交付）、接手会话（接过无目标记录的在途批次时须重新推断目标）。

## 3. 正面

- **可判定的意图契约**：档 A 六字段与档 B 三要素把“知”从口头共识变为可定位的书面对象；三问 STOP（谁在痛——不做会怎样／做完算成功吗——二值判据／不做什么——非目标）给出停手判据，任一答不出即停手澄清。
- **手段可替换**：验收判据先行固定后，工具、脚本与设施的选择降为次要项；换手段须保持验收判据不变并记录理由，抑制以既有手段反推目标造成的返工。
- **受益者**：任务发起者（目标不被代理擅自改写）、主代理（有停手依据，不必猜测）、子代理（派发提示自带目标、非目标与验收判据）、接手会话（意图基线可续跑）。
- **验证方式**：门禁 E8 的七项接线判据；`audit_task_lifecycle.py` L2 对准入证据定位的校验；`工程实践规则.md` §0.3 的季度抽查（不少于两条任务）；本批 `任务复核台账.md` 的三轮记录。

## 4. 负面

- **多一道前置**：每个任务开工前须写意图确证，档 A 六字段、档 B 一行，均在既有准入之上增加书写成本；高风险批次还须在 G0 结算意图变更并回 G1 重列验收。
- **档 B 可被敷衍**：三要素可被写成无信息量的占位（如“按要求改文件”），形式合规而不改变任何决策，机器判据识别不出，只能靠复核抽查。
- **承担者**：档 A／档 B 的书写者为任务发起者与主代理；档 B 敷衍的判定与纠正者为复核子代理与主代理。
- **边界**：不承诺“知”的完备性；不替用户定义目标；档 B 不强制写 spec，避免把轻量任务制度化为文档工程。

## 5. 承担者

| 负面 | 承担者 | 承担时点 |
| ---- | ------ | -------- |
| 意图确证书写与可定位 | 任务发起者（ykla）、主代理 | 每次任务开工前 |
| 档 B 敷衍的识别与纠正 | 复核子代理、主代理 | 每轮复核与季度抽查（不少于两条任务） |
| 目标与手段倒置的仲裁 | 任务发起者（ykla） | 出现“先做后问”争议或手段反剪目标时 |
| 复审与失效判定 | 主代理 | 2027-01-29 |

## 6. 过去依据

- **历史条件**：G0 于 2026-10-22 立，退出判据服务于变更裁剪与门禁阶段归属，故只要求范围与阻塞可判；`ADR-0013` 确立准入以“已启动”为界、`ADR-0014` 确立复核轮次以“收口”为界，两条确立的非追溯口径本 ADR 沿用。
- **此前形式为何失效**：意图未被列为任何字段，故“先做后问”在流程上不可见——它不违反 G0（范围可先划），也不违反 §0.2（准入字段齐全），只在返工发生后由人工察觉，无法由门禁判出。
- **指导思想底色**：项目七条方法论规范中的“自反性声明”与“经验优先”要求写明判断前提；本 ADR 把这层要求落到可判定字段，而不是仅作写作风格要求。

## 8. 将来失效条件

- 意图确证连续两季零改变决策：季度复审中无一条任务因意图确证而改变目标、手段或验收判据；
- 或全部任务由单一发起人即时口头确认且无跨会话、无子代理派发，意图基线无处施加；
- 或上游 `13-软件工程/` 直接吸收同一要求，项目侧改为指针并删除重复正文。
- 触发任一条件即降级为说明或废止；废止保留原文与迁移指针，不删除本件。

## 9. 0 信任校验

- 门禁 E8 只验接线（理论件存在、六字段关键词齐备、`13-软件工程/README.md` 在册、全局节含“全任务适用／档 A／档 B”、G0 行含“意图”、`AGENTS.md` 有全任务行、模板 I 有条目），不验内容质量，不得以 E8 PASS 代替人工判定。
- 不信任自报：`audit_task_lifecycle.py` L2 以台账准入证据的定位路径判定；复核者须回读 `spec.md`／`tasks.md` 原文，不得只采信“已写意图确证”。
- 抽查留痕：按 `工程实践规则.md` §0.3 每季度随机抽查不少于两条任务，核对意图确证与后续手段选择的一致性，结论写入 `工程实践复审台账.md`。
- 落地记录只写文件与节位（见 `软件工程理论缺口与增补登记.md` 的 TG-012 行），不写“已全面落实”一类不可证伪结论。

## 10. 自由影响

- 不替用户定义目标：档 A 第一字段是“用户原话”，主代理只作翻译与结构化，不以自身技术偏好填充目标。
- 档 B 不强制写 spec、不强制建文档，避免把轻量任务制度化为文档工程。
- 允许用户随时改写目标：目标实质变动回 G0 重写意图确证单、回 G1 重列需求与验收；已完成批次不重做。
- 自反：承认“知”不可能完备，收敛于最小可判定契约，禁止以无限调研代替开工。

## 11. 安全和解

- 不写凭据：意图确证单只写目标、非目标、验收判据与手段自由度，不写 key、Cookie 或账户。
- 不落副本：留痕只靠 Git 与 `changelog.duckdb`，不建旁路备份（红线 12）。
- 只读为主：E8 判据全部为文件存在性与关键词匹配，不写库、不改树、不触网。
- 不引入自动化与定时任务（项目禁止）；门禁仍由人在场批次执行。
