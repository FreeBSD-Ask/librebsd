# ADR-0014：复核轮次门禁以“收口”为界

- **状态**：已接受
- **日期**：2026-10-22
- **裁决人**：主理人
- **执行者**：主代理
- **复审日期**：2027-01-22
- **替代关系**：无；细化《工程实践规则》§0.1 第 2 条与第三十二件门禁 L7 的作用域，不改其义务内容；与 `ADR-0013` 同源（判据以生命周期阶段为界）

## 1. 形式

第三十二件门禁 `audit_task_lifecycle.py` 的 **L7**（复核轮次与角色合规）改为**以收口为界结算**：

1. **收口行**（`收口结论` ∈ {PASS, 不适用}）仍判 FAIL 的四项：实有轮次 < 声明轮次、实有轮次 < 最低轮次（普通 2／高风险 3）、轮次编号不连续、高风险缺主理人签收。
2. **在途行**（未收口）上列四项不足一律记 **WARN**：单列于 L7 详情（前缀“WARN 在途未足（不判 FAIL）：”），**不影响退出码**。
3. **对全部行保留 FAIL**：声明轮次 < 最低轮次（声明即最低义务，开工时即须写足）、轮次非整数、作者自批（角色＝作者）、轮次编号重复（同一轮次号出现两次及以上）。
4. 判据归属：本件只改“轮次充足性与签收在何时结算”，不改轮次下限数值（《工程实践规则》§0.2／§0.3），不改字段表与收口证据四段。

## 2. 矛盾

- **不做的后果**：旧 L7 对审计台账**每一行**要求“实有 ≥ 声明 ≥ 最低”，于是**刚准入、仍在执行中的任务必然 FAIL**。轮次义务被提前到“任务存在”时刻结算，与规则原文“**未复核即收口**属违规”（《工程实践规则》§0.1 第 2 条、§0.5）的**收口时点**约束不符。
- **实测**：本批之前几轮与 `adr0010` 线均因在途行轮次未满而误报；`reframe-outline-five-parts-20261022` 刚开工（`tasks.md` 已勾 5/9、产出 161 号文）时，一旦补上准入行即触发 L7 FAIL，而该行距收口尚远。
- **受影响者**：主代理（每批须解释假阳）、主理人（退出码失去放行语义）、复核子代理（须区分真假阳）、接手会话（易为消警补造复核行，等于伪造复核记录）。

## 3. 正面

- **能力**：L7 由“按行全量结算”改为“**按生命周期阶段结算**”，与 L2 以“已启动”为界（`ADR-0013`）构成同一族判据；门禁退出码重新可作批次放行信号。
- **受益者**：主代理、主理人、复核子代理、接手会话。
- **验证方式**：`--selftest` 新增三例并保留原 16 例（共 19 例全 PASS）——① 未收口＋高风险＋0 复核行 → L7 不判 FAIL（WARN）；② 已收口 PASS＋高风险＋2 复核行 → 必须 FAIL；③ 已收口 PASS＋高风险＋3 复核行且含主理人 → PASS。

## 4. 负面

- **成本**：门禁输出新增 WARN 段，批次报告须转述在途欠账；退出码不再反映“复核进度落后”。
- **可绕过面（核心代价）**：**长期不收口即可长期少复核**——只要 `收口结论` 停在“未收口”，轮次不足只报警不拦截。兜底为 L3（`tasks.md` 全部勾选即视为已收口，必须 PASS 收口行与四段证据）与《工程实践规则》§0.3 季度抽查（不少于两条任务，核对记录与实际产物）；一旦勾完却仍不收口，L3 直接 FAIL。
- **边界**：本件不改 L4——未收口行的“最新复核 ID”仍按 L4 必填判 FAIL，0 复核行的在途行仍会因 L4 而非 L7 退出码 1；该字段属准入期字段与收口期字段混列问题，另批裁定（见 §12）。不追溯本件生效前的历史行。

## 5. 承担者

| 负面 | 承担者 | 承担时点 |
| ---- | ------ | -------- |
| 在途欠账的转述与到期提醒 | 主代理 | 每批收口报告 |
| “长期不收口＝长期少复核”的识别与裁断 | 主理人 | 季度复审（2027-01-22 首次） |
| 抽查核实在途行的真实复核进度 | 复核子代理 | 季度抽查 |
| L3 与 L7 的接口一致性复核 | 主代理 | 每次改 L3／L7 判据时 |

## 6. 过去依据

- **历史条件**：2026-10-22 起施行的任务强制审计，要求普通任务至少 2 轮、高风险至少 3 轮复核；门禁 L7 的实现把“实有 ≥ 声明 ≥ 最低”与“高风险须主理人签收”无差别施加于全部审计行。
- **此前形式为何失效**：审计行在**开工前**即建立（准入审计要求），而复核轮次在**收口时**才可能满足；两者在同一行上被同一判据同时要求，导致任何在途任务都处于 FAIL 状态。
- **证据**：本会话实跑 `audit_task_lifecycle.py` 的旧 L7 输出与在途夹具（`script/_l7_warn_demo_20261022.py`）复现；旧夹具 `insufficient-rounds`（收口 PASS＋2 轮）与在途行在旧式下同判，无法区分“未做完”与“做漏了”。

## 7. 现在依据

- **测试／测量**：`audit_task_lifecycle.py --selftest` 19 例全 PASS（原 16 例保留，新增 `in-flight-zero-review-warn`、`closed-highrisk-two-rounds`、`closed-highrisk-three-rounds`）；`script/_l7_warn_demo_20261022.py` 以独立构造的临时仓库根跑真实 CLI，L7 输出为 PASS＋WARN 单列。
- **日期与环境**：2026-10-22，Windows，`d:\librebsd`，`C:/Python314/python.exe`。
- **证据路径**：`script/_l7_scope_fix_20261022.md`（判定依据、改动、三例输出、门禁退出码）；`script/_l7_warn_demo_20261022.py`（在途夹具 CLI 取证）。

## 8. 将来失效条件

1. 审计台账改为**分阶段两表**（准入表／收口表），在途行不再与收口行同表，“按行结算”不再产生歧义；
2. 复核轮次改为**事件触发制**（每完成一个检查点即强制一轮），轮次数不再有“提前声明”的时点问题；
3. 出现**自动复核流水**（门禁结果自动生成复核行），轮次充足性可由证据自动判定，无需按阶段放宽；
4. 收口结论枚举变更（如取消“未收口”或引入“暂停”“挂起”），在途/收口的二分须重定义；
5. L4 对“最新复核 ID”的必填口径被修正，本件 §4 的边界说明须同步改写。

## 9. 0 信任校验

- **独立复现方式**：不复用门禁内部 fixture，另建临时仓库根（含三表、规则接线件与在途 spec）以 `--root` 跑真实 CLI，观察 L7 判读与退出码；`--selftest` 另以内存夹具覆盖三例边界。
- **交叉验证工具**：`script/_l7_warn_demo_20261022.py`（独立脚本，自行写表、不 import 门禁内部函数）；`audit_markdown_lint.py`、`audit_gate_registry.py`、`audit_engineering_practice.py` 与门禁同批实跑。
- **原始证据位置**：`script/_l7_scope_fix_20261022.md` 收录门禁与自检 stdout 原文。

## 10. 自由影响

- **退出**：门禁退出码语义更准——在途任务不再拖累批次放行，只有已收口却轮次不足才为 1；不改变任何任务的实际施工自由度。
- **导出**：WARN 段进入门禁文本输出，可直接引用到批次报告，无新增二进制或闭源依赖。
- **离线**：全部本机执行，无联网依赖、无外部服务。
- **默认值可撤销性**：回退只需恢复 L7 原式并回退 selftest 三例，无数据迁移；判据调整由主理人按 §12 事件裁定。

## 11. 安全和解

- **资产**：`任务复核台账.md`（复核唯一明细）、`任务审计台账.md` 的复核轮次与收口结论列、`.trae/specs/<slug>/tasks.md` 勾选状态。
- **对手**：伪造复核行、以“未收口”状态长期规避轮次、以在途状态掩盖漏复核、自批代签。
- **攻击面**：`收口结论` 列（可被长期留在“未收口”）、`复核轮次` 声明值（可虚高或虚低）、复核行角色列（可伪造主理人）。
- **信任边界**：主代理执行与自报、复核子代理只读复验、主理人签收；门禁只信盘面文本，不信自述。
- **现有控制**：L3 强制已勾选任务的 PASS 收口行与四段证据；L7 的“声明 < 最低”对全部行 FAIL，虚低不可行；作者自批对全部行 FAIL；L8 校验最新复核 ID 与复核行引用一致；季度抽查；复核者与作者角色分离。
- **残余风险**：长期不收口即可长期少复核；0 复核行的在途行仍被 L4 判 FAIL（本件未处理）；复核行本身可为凑数而写。
- **证据**：本批实跑输出、`--selftest` 19 例、在途夹具 CLI 原文。
- **代价**：见 §4。
- **失效条件**：见 §8。

## 12. 复审触发

- **时间**：2027-01-22（与工程实践复审同批）。
- **事件**：出现“长期不收口以规避轮次”的实例；在途行 WARN 连续跨批不消；L7 再次出现成批假阳或漏判；L4 的“最新复核 ID”必填口径被改动；台账改分阶段两表。
- **复审动作**：核对本批后的 L7 实跑记录、WARN 清单与季度抽查结果，决定维持、修订或替代本件，结论写入 `工程实践复审台账.md`。

## 附：替代方案与取舍

| 方案 | 正面 | 负面 | 为何未选 |
| ---- | ---- | ---- | -------- |
| 维持“按行全量结算”（现状） | 零改动 | 在途任务必然 FAIL；消警只能伪造复核行 | 判据越界，破坏复核证据可信度 |
| 取消 L7，只靠人工抽查 | 无假阳 | 复核轮次失去机器兜底 | 与“未复核即收口属违规”冲突 |
| 在途行直接 SKIP（不出 WARN） | 输出最干净 | 欠账不可见，收口时易漏 | 丢失“到期提醒”功能 |
| 按“tasks.md 勾选比例”折算应完成轮次 | 进度更贴合 | 折算系数不可解释、可被勾选伪造 | 不满足二值可判 |
| **以收口为界，在途记 WARN（本件）** | 与规则收口时点对齐、可机判、可自检 | 长期不收口即可长期少复核，靠 L3 与抽查兜底 | 采用 |
