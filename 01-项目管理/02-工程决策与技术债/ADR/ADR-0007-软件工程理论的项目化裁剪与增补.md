# ADR-0007：软件工程理论的项目化裁剪与增补

- **状态**：已接受
- **日期**：2026-10-22
- **裁决人**：主理人
- **执行者**：主代理
- **复审日期**：2027-01-22
- **替代关系**：补充 ADR-0001 的工程实践基线，不替代其他 ADR

## 1. 形式

本决策把“软件工程理论不满足本项目实际”时的处理固定为一条可判路径：

1. **先登记**：每个缺口以 `TG-NNN` 登记在 `01-项目管理/02-工程决策与技术债/软件工程理论缺口与增补登记.md`，含理论条款、不满足处、项目证据、增补或修订建议、落地载体、优先级、采纳状态、失效条件与复审触发。
2. **项目规则优先**：只影响本项目的增补写入 `工程实践规则.md`、`流程规则.md` 或 `任务轮替与归档规则.md`，并配门禁或抽样判据；不直接改 `13-engineering-doctrine/` 正文。
3. **上游回流**：可普适条款按 `13-engineering-doctrine/NOTICE.md` 版本化回流，写清条款、证据、代价与失效条件。
4. **任务准入判断**：每个新任务的准入行必须填“理论适用性”；不适用时引用 `TG-NNN`，不得临场发明流程。
5. **季度复审**：检查缺口是否仍改变决策、是否已被上游吸收、是否与现有规则重复；空壳条款降级或删除。

本批采纳 TG-001–TG-010，TG-011 部分采纳（项目侧只留指针，正文由 `考据规则.md` 承载）。

## 2. 矛盾

- 不做：新任务遇到长线战役、滚动范围、外部采集、OCR／ASR 非确定性、数据与文档审查、单人＋AI 多会话等情形时，只能各自临时发挥；同一缺口会反复以“任务书补丁”出现，无法比较、无法复审。
- 受影响者：主代理（每次重新发明流程）、主理人（无法用统一判据验收）、复核子代理（无判据可复跑）、后续接手者（上下文丢失后无法复原决策）。

## 3. 正面

- 能力：理论不满足时有唯一登记入口、唯一落地路径与唯一复审触发；项目规则与上游教义不再互相污染。
- 受益者：接手会话、主代理、主理人、复核者。
- 验证方式：`audit_task_lifecycle.py` L12 校验理论适用性与 `TG-NNN` 引用；`audit_engineering_practice.py` E1–E7；`audit_gate_registry.py` R1–R8；季度复审台账。

## 4. 负面

- 成本：新增一份缺口登记、一份 ADR、十一条 TG 条目与一条 L12 判据；每批任务多填一列“理论适用性”。
- 风险：TG 表可能变成“建议仓库”而不落地；项目规则与教义可能重复；季度复审可能流于形式。
- 边界：不追溯旧任务；不改教义正文；不新增自动化；TG-011 只留指针，不复制考据规则正文。

## 8. 将来失效条件

1. `13-engineering-doctrine/` 新版已吸收全部 TG 条款，项目侧只需指针；
2. 项目转为短周期软件发布，长线战役、记录生命周期与不变量度量不再适用；
3. 任务改为多人团队并有独立 QA，AI 代理可靠性条款不再必要；
4. 连续两个季度没有新增 TG，且现有 TG 全部被上游吸收；
5. 项目不再产出学术文本，TG-011 的学术证据质量指针失效。

## 10. 自由影响

- 退出：不改变任何读者可见界面；不引入强制在线、账户或遥测。
- 导出：TG 登记、ADR 与规则均为普通 Markdown，可直接读取与复制。
- 离线：全部登记、落地与校验在本机完成，不依赖外部服务。
- 默认值可撤销性：TG 优先级、采纳状态与复审周期均为项目默认值，可由主理人按 §8 修订并开新 ADR。

## 11. 安全和解

- 资产：规则文本、任务台账、TG 登记与门禁输出。
- 对手：误用理论导致的流程绕过、记录失真、空壳条款。
- 攻击面：任务准入、复核记录、轮替指针、上游回流。
- 现有控制：不追溯条款、独立复核、L12 判据、季度复审。
- 残余风险：人工填写的理论适用性仍可能失真；由抽查与复核台账控制。
- 代价：每批多一列、每季多一次复审。
- 失效条件：L12 连续两季未命中任何真实缺口，或 TG 表全部空壳。
