# ADR-0012：数据与资产写盘后强制装配校验

- **状态**：已接受
- **日期**：2026-10-22
- **裁决人**：ykla
- **执行者**：主代理
- **复审日期**：2027-01-22
- **关联债务**：TD-018（偿还中）；审计 `全链路工程化审计-20261022.md` §3.1／§3.2、缺口 G-R5

> 本件按《工程实践规则》§2.2“轻量 ADR（TG-005）”使用五字段：形式、矛盾、选择、代价、失效条件；另附状态、日期、复审触发与门禁字段映射。本项非高风险（不涉写库、删除、凭据、平台承诺与不可逆数据格式），故不使用十二字段完整版。

## 1. 形式

两脚本**保留写盘能力**，但写盘后由机器强制跑装配校验，退出码即判据：

1. **`embed.py`**：无参运行时（写盘分支与幂等无变更分支皆同）自动调用同目录 `assemble_index.py --check`，`cwd` 为仓库根，子进程解释器取 `sys.executable`。成功打印 `[assembly] PASS`；失败打印 `[assembly] FAIL` 并附子进程末尾 20 行输出，`sys.exit(3)`。其 `--check` 分支是纯检测，**不触发**嵌套调用。
2. **`font_subset_rebuild.py`**：写回 `assets/doc.css` 后，先跑 `assemble_index.py`（不带 `--check`，即重新装配），再跑 `assemble_index.py --check`；两步任一非零即打印 `[assembly] FAIL` 并 `sys.exit(3)`。其 `--check`（只审计不写回）分支**不触发**装配，只读路径不产生写盘。
3. **装配器不改**：`assemble_index.py` 仍是 `重构2026/index.html` 的唯一写者；本决策只给两处旁路写盘加“写后必须由唯一写者复核”的机器约束。

## 2. 矛盾

- **不做会怎样**：`embed.py` 可直写 `index.html`、`font_subset_rebuild.py` 可直写 `doc.css`，而“随后须跑 `assemble_index.py --check`／重新装配”此前**只是文档纪律**，无任何机器强制。漏跑一次，产物与源即不一致：数据块 SRI 与页面装载器失配而降级，或格式层改动停留在源中、下次装配按旧源覆盖。
- **证据**：审计 `全链路工程化审计-20261022.md` §3.1 阶段表（数据／资产两行的写者列与门禁列）、§3.2“唯一写者”条、§3.3 缺口 G-R5（P1）；技术债 `TD-018`；`embed.py` 原 `cmd_embed()` 写盘分支与 `font_subset_rebuild.py` 原 `main()` 写回后仅有提示性 `print`。
- **受影响者**：主代理（执行写盘）、ykla（验收）、复核子代理（复现）、接手者（判断产物是否可信）。

## 3. 选择

**选定：写盘后强制校验＋非零退出。** 两脚本不降级为库，也不改成“输出中间件”。

| 方案 | 正面 | 负面 | 为何未选 |
| ---- | ---- | ---- | -------- |
| 维持人工纪律（现状） | 零成本 | 不可强制、漏跑无痕 | 正是本债成因 |
| 中间件：脚本只输出到 stdout，由装配器消费 | 写者彻底唯一 | 装配器需重读 `catalog.json` 与字体源；中间件成为第二份输入 | 引入第二数据源，且装配器已复用 `embed` 的序列化函数，会形成双向依赖 |
| 两脚本改为只读库、删去写盘 | 无旁路 | 字体源与 catalog 的独立重装能力丧失，排障粒度变粗 | 能力损失大于收益 |
| **写盘后强制校验（本件）** | 旁路保留、越界可判；失败即批次中止 | 每轮多一次装配检测 | 采用 |

不选“输出中间件”的关键理由：装配器需要**读** `data/catalog.json` 与字体源（字符集扫描、SRI 计算、`@font-face` 合并）才能完成装配，中间件必须重新交付这些输入，等于再造一份数据源，与单一真值冲突。

## 4. 代价

- 每轮写盘多一次全量装配（`--check` 或重装配），秒级；`font_subset_rebuild.py` 为两次。
- 校验失败即 `exit 3` 中止批次，须人判读子进程输出；误报会停摆（复审触发的判据见 §6）。
- **残余风险**：①校验只证明“装配器重装结果与盘面一致”，不证明语义正确；②失败时旁路已写盘，产物短暂处于未验证态，回退依赖 git 与 `12-数据库备份/` 既有快照；③若 `assemble_index.py --check` 判据本身空转（审计 §3.2 所述 G-R4 同类风险），校验形同虚设；④第二十九件 E1 目前未实现轻量 ADR 分支，本件以字段映射满足门禁（见附录），属规则与门禁的已知错位，待规则侧补齐。
- **承担者**：主代理（执行与回归）、ykla（裁决与误报裁定）、复核子代理（独立复验）。

## 5. 失效条件

1. `assemble_index.py` 改为直接吸收 `embed.py` 的序列化／SRI 与 `font_subset_rebuild.py` 的子集化能力，两脚本退役或降为纯库——本 ADR 随之失效；
2. 产物写盘改由统一写入器（单入口、单事务）承担，旁路不复存在；
3. `assemble_index.py` 不再可独立调用，或 `--check` 退出码语义变更（非零≠漂移）；
4. 出现“批末一次性更强门禁”并经验证可替代逐次校验（须另有 ADR）。
