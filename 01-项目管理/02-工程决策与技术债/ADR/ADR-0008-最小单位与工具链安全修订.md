# ADR-0008：最小单位与工具链安全修订

- **状态**：已接受
- **日期**：2026-10-22
- **裁决人**：ykla
- **执行者**：主代理
- **复审日期**：2027-01-22
- **替代关系**：补充 ADR-0006，不替代其他 ADR

## 1. 形式

依据 2026-10-22 八条线各 30 个最小单位的烟测结果，固定以下边界：

1. **F 线最小单位**＝30 个**当前大纲中的宿主 `.md` 文件**。读取前必须把 `claims_F*.txt` 重建／回映到现行路径；新增清单新鲜度判据：30 条路径存在率 100%，否则拒绝开批。
2. **F 线抓取安全**：`oaa_fetch.py` 必须显式 `--workdir`，缺省不得写生产 `audit_outline/work/`；输出统一 LF；提供批量入口。新增 `oaa_remap_claims.py`（或 `oaa_beacon.py --rebuild-claims`）。
3. **CLI 安全默认**：`apply_fixes.py`、`_prep_batches.py` 等破坏性工具，`--help` 不得触发执行；默认 dry-run，写盘须显式 `--apply`（或等价开关）。`--dry-run` 不得被静默忽略。
4. **H 线最小单位**＝30 个 `messages` **行**，并逐行记录其是否为整包 mbox／多封串联；逻辑邮件数另行统计。禁止再以“30 行＝30 封”表述。H2／H3 实测 30 行可含 27–189 个 `Subject:`，H4 的 id 序不等于日期序。
5. **H 线核心驱动副本**：`脚本与命令/mail2d_*.py` 要么连同依赖一并复制并可运行，要么在 `mail2d核心驱动清单.md` 明确标“参考件、不可直接运行”；`--help` 不得因缺 `_git_lsfiles.py` 崩溃。
6. **门禁加固**：
   - `audit_oaa_batch.py`：缺判读件不得空转 PASS；`--batch` 必须同时过滤分片与判读件；S4 字段语义须显式声明，不得静默按 `pk→id→key` 切换。
   - `audit_mail2d_batch.py`：增加 `--srcdb` 存在性判据（幽灵 pk 不得全绿）与叙述长度／尾标点判据。
   - 两门禁拒绝 `pilot-synthetic` 生产件（显式字段或文件名标记）。

**边界**：不改变在途批次数据契约；不切换 H 线运行路径；不修复生产台账；只改工具与规格。

## 2. 矛盾

- 不做：F 线认领清单已 0/30 命中，任何开批都会读错宿主；`oaa_fetch` 漏写 `--out` 会污染生产 work；`apply_fixes --help` 会触发执行路径；H 线 30 行不等于 30 封，按“30 封”评估会低估体量 27–189 倍；副本缺依赖使 `--help` 崩溃。
- 受影响者：主代理（开批与工具调用）、ykla（验收）、复核者（判据可信度）。

## 3. 正面

- 能力：最小单位口径统一、可复现；破坏性工具默认安全；门禁不再被缺件与幽灵 pk 欺骗。
- 受益者：接手会话、ykla、复核者。
- 验证方式：两条新门禁 `--selftest` 增加对应负向夹具；`oaa_remap_claims` 路径存在率 100%；`--help` 冒烟不执行。

## 4. 负面

- 成本：需新增回映脚本、改三件 CLI、加固两件门禁、更新两份 spec。
- 风险：默认 dry-run 会改变既有调用习惯；H 线“行≠封”会使历史“30 封”口径全部需要重述；副本依赖复制会增加维护面。
- 边界：本轮不全量重跑 F/H 历史批次，不修旧 spec 的 `pk_missing_count` 与 `src_db` 异常。

## 6. 过去依据

- F1–F4 烟测：`claims_F*` 路径 0/30、0/63、0/146、0/847 命中；`apply_fixes --help` 触发执行；`oaa_fetch` 默认写生产 work 且 CRLF。
- H1–H4 烟测：30 行可含 27–189 个 `Subject:`；H3 30 行 2,222 万字符；H4 幽灵 pk 五项全绿；`prep --help` 假成功 exit 0。
- 证据：`script/_pilot_20261022/<线>/<线>-pilot.md`；`全链路工程化审计-20261022.md` §五。

## 7. 现在依据

- 日期与环境：2026-10-22，Windows，`d:\librebsd`。
- 测试：八条线各 30 单位，合成判读标 `pilot-synthetic`，未写生产。
- 证据路径：八份 pilot 报告；`audit_oaa_batch.py`／`audit_mail2d_batch.py` 的 `--selftest`。

## 8. 将来失效条件

1. F 线认领清单改为由 `oaa_beacon.py --refresh` 自动重建且路径存在率 100%；
2. H 线消息表拆分为“一封一行”，行语义不再有歧义；
3. 破坏性工具全部改用 argparse 并默认 dry-run，本 ADR 的 CLI 条款可并入工具文档；
4. 两件门禁被统一收口器取代；
5. 任务线闭口或迁移出本仓库。

## 9. 0 信任校验

- 独立复现：八份 pilot 报告的命令与计数；两件门禁 `--selftest` 负向夹具；`oaa_fetch --workdir` 冒烟。
- 交叉验证：清单路径存在率；`--help` 退出码与是否写盘；副本 SHA-256 与依赖清单。
- 原始证据：pilot 报告、`git status`、门禁输出。

## 10. 自由影响

- 退出：不改变读者可见界面。
- 导出：规则与工具均为普通文件，可直接读取。
- 离线：全部本机执行。
- 默认值可撤销性：dry-run 默认可由 ykla 按 §8 调整。

## 11. 安全和解

- 资产：生产大纲、台账、claim 库、认领清单。
- 对手：误触执行、路径漂移、幽灵 pk、缺件空转、行／封语义混淆。
- 攻击面：CLI 参数、默认输出目录、认领清单、门禁探测字段。
- 信任边界：主代理执行、ykla 批准、复核只读。
- 现有控制：pilot 合成标记、SHA-256、门禁 selftest、写前备份。
- 残余风险：旧 spec 数据异常、副本依赖未全量补齐、历史“30 封”口径需重述。
- 证据：pilot 报告与门禁输出。
- 代价：新增回映脚本与两件门禁加固。
- 失效条件：见 §8。

## 12. 复审触发

- 时间：2027-01-22。
- 事件：F 线开批、H 线路径切换、CLI 默认变更、门禁误判、副本依赖缺失。
- 复审动作：重跑 30 单位烟测，核对清单存在率与门禁负向夹具，结论写入复审台账。
