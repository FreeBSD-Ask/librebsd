# ADR-0016：全库禁止旁路备份副本，Git 为唯一留痕与回滚机制

- **状态**：已接受
- **日期**：2026-10-23
- **裁决人**：用户（ykla）
- **执行者**：主代理
- **复审日期**：2027-01-23
- **替代关系**：替代 `流程规则.md` 2026-10-17“写前备份通则”中“备份一律置 `script/_bak/`”的口径；补充 ADR-0015 第 11 节“现有控制”中的 `prebak` 表述

## 1. 形式

- 形式：工作区内**一律不得创建**写前／写后备份副本——`.bak`／`.bak-*`／`.bak_*`／`.bak.<数字>`／`.pre`／`.prebak*`／`-bak`／`.orig`／`.rej`／`~` 等任何后缀或改名副本，以及 `script/_bak/`、`prebak-*` 等备份目录；留痕与回滚**唯一依赖 Git**（提交、标签、`git show`）；数据库快照**唯一依赖** `12-数据库备份/` 三计划任务＋重大施工前的专项正式备份槽（`<YYYYMMDD_HHMMSS>.db.gz` 或 `before_<批次>_<日期>.db.gz`）。
- 边界：不禁止**正式备份体系**（`12-数据库备份/` 的密槽／日槽／逻辑导出）；不禁止 Git 自身的 `.git/` 内部对象；不改变“删除 `12-数据库备份/` 任何内容须用户明示”的红线。

## 2. 矛盾

- 不做的后果：旁路副本持续累积。2026-10-23 实测 `prebak*` **783 件、17.7 GB**，`bak` 类 **1 077 件、874 MB**，散落在 `script/`、`08-`、`01-`、`03-`、`04-` 与 `12-数据库备份/`；其中 1 件被 Git 跟踪；个别上游源码文件（`README.ORIG`）与唯一副本混入候选删除面，需逐件复核才不致误删。
- 受影响者：用户（仓库体积与审计噪声）、主代理（每批写前写后各落副本、台账膨胀）、接手会话（无法判断哪份是现行）、Git 历史（旁路副本掩盖真实变更）。

## 3. 正面

- 能力：仓库体积与文件数可预期；每一处历史变更都能由 Git 提交或标签复现；备份路径唯一（正式备份目录），不再“三套后缀并存”。
- 受益者：用户、接手会话、复核者、CI 与门禁。
- 验证方式：全库复扫 `prebak`／`bak` 类为 0（豁免 `README.ORIG` 与 13 件唯一副本待裁决项）；`git_commit_gate.py --selftest` 34/34（含 B5 四项）；`audit_silent_loss_guard.py` 以 Git 提交 `305b320` 为 T1 实跑 PASS；`_longline_status.py --check` PASS。

## 4. 负面

- 成本：需改造 6 个产生副本的脚本（`oaa_remap_claims.py`、`_longline_status.py`、`sync_review_v2_anchors.py`、`review_v2_full.py`、`review_v2_job_r41.py`、`dual_marker_registry.py`）与 8 处规则条款；依赖已删快照的两处门禁需改为 Git 取证。
- 风险：删除后无法从磁盘回看旧快照；若 Git 提交缺失或未及时提交，回滚能力下降；历史脚本若被重跑可能重新生成副本。
- 边界：不删除唯一副本与上游源码文件；不修改 `12-数据库备份/` 正式备份；不做批量改写以外的语义改动。

## 6. 过去依据

- 历史条件：2026-09-28 立 `.gitignore` 备份后缀清单，只挡新增、不清存量；2026-10-17 立“写前备份通则”，允许备份置 `script/_bak/`；2026-10-18 先把“禁止副本”限定在大纲树，其他战役不受约束。
- 此前形式为何失效：多套后缀（`.bak-`／`.prebak-`／`.bak_`／`.bak.<日期>`／无日期 `.bak`）无单一 glob 可覆盖；`script/_bak/` 作为“合法备份区”继续膨胀；脚本各自实现写前复制，无统一生命周期；DuckDB 快照因文件大而反复复制，单库副本达 643 MB。

## 7. 现在依据

- 测试／测量／故障／反馈：2026-10-23 全库扫描——`prebak*` 783 件／17.7 GB（`script/` 2.69 GB、`12-数据库备份/` 约 2.4 GB、`references_fulltext` 1.5 GB 等）；`bak` 类 1 077 件／874 MB；逐件复核后 `SAFE` 52＋`TEMP` 1 012 可删、`ORPHAN` 13 保留；`README.ORIG` 为上游源码，非备份。
- 日期与环境：2026-10-23，Windows，`d:\librebsd`；Python 3.14。
- 证据路径：`script/_purge_sidecar_20261023/`（`sidecar-list.tsv`、`sidecar-review.tsv`、`sidecar-purge-result.tsv`、`sidecar-keep-orphan.tsv`）；`git_commit_gate.py --selftest`；`audit_silent_loss_guard.py` 输出（T1＝`305b320`，321 章，0 疑零承接）。

## 8. 将来失效条件

1. Git 仓库不再承担留痕职责（例如改用外部制品库且工作区需自带快照）；
2. 出现比 Git 更低成本、可逐件校验的版本机制；
3. 正式备份体系无法覆盖数据库写前状态，且专项正式槽实测不可用；
4. B5 判据在实际提交中产生不可接受的误伤（例如合法文件名含 `.bak` 语义）且无更精确判据。

## 9. 0 信任校验

- 独立复现方式：全库复扫文件与目录名；对每个候选件计算“基准路径是否存在、大小与 SHA-256 是否相同”；删除后复扫为零。
- 交叉验证工具：`script/_purge_sidecar_20261023/probe.py`／`review.py`／`purge.py`；`git ls-files`；`git_commit_gate.py --selftest`。
- 原始证据位置：上述 TSV 台账；`git status --porcelain`；`audit_silent_loss_guard.py` 实跑输出。

## 10. 自由影响

- 退出：不影响读者可见界面与导出；目录页仍可离线打开。
- 导出：Git 归档与 `12-数据库备份/` 逻辑导出均保持。
- 离线：全部本机执行。
- 默认值可撤销性：本 ADR 可被后续 ADR 替代；已删除件若曾入库可由 Git 恢复，未入库者不再可恢复（已在删除前记录路径、字节与 SHA-256）。

## 11. 安全和解

- 资产：全库源文件、数据库文件、历史快照、上游源码文件。
- 对手：清扫器误删唯一副本、上游文件被当备份、脚本重跑再生成副本、提交期漏挡。
- 攻击面：按文件名通配删除、目录名含被清扫模式、被跟踪文件删除、数据库备份目录。
- 信任边界：主代理执行、用户明示删除范围、Git 保存已入库历史。
- 现有控制：逐件复核（基准存在＋哈希）、`ORPHAN` 一律保留、上游文件单列、`.gitignore` 收紧、commit-msg B5 无放行标记、规则红线。
- 残余风险：13 件唯一副本尚未裁决；未入库的已删件不可恢复；历史脚本若被重跑仍可能生成副本（已在文件头标注禁用）。
- 证据：见 §7。
- 代价：每批写前只打印 SHA-256，不再落副本；重大写库多一步正式备份槽。
- 失效条件：见 §8。

## 12. 复审触发

- 时间：2027-01-23。
- 事件：任一脚本重新生成旁路副本；B5 误伤合法文件；正式备份槽缺失或不可用；用户要求恢复某份已删快照（验证 Git 取证能力）。
- 复审动作：核对 `.gitignore`、B5 自检、全库复扫结果与正式备份目录清单；结论写入 `工程实践复审台账.md`。
