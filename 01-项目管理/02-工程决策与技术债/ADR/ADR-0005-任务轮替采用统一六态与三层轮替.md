# ADR-0005：任务轮替采用统一六态与三层轮替

- **状态**：已接受
- **日期**：2026-10-22
- **裁决人**：ykla
- **执行者**：主代理
- **复审日期**：2027-04-22
- **替代关系**：扩展现行《长线任务归档规则》并更名，不替代其他 ADR

## 1. 形式

本决策把项目内任务的历史管理固定为一条可判规则：

- **统一六态**：`REGISTERED`／`ACTIVE`／`DORMANT`／`CLOSED`／`ARCHIVED`／`REVIEW`；状态迁移须有证据，闭口不等于删除。
- **三层轮替**：
  1. 登记层：总登记表 §十五 变更记录按三日窗口轮替；
  2. 线层：在推线的已闭环批次史按子线迁入 08–11 类分册；
  3. 任务书层：版本块、`_历史快照/`、`.prebak-*` 按窗口保留，旧件逐字迁出。
- **三类对象**：长线任务（17 条登记线＋未入册线）、其他任务（阶段性／一次性）、工程批次（`.trae/specs/`，只留存规格三件，不物理迁移原目录）。
- **边界**：不约束数据库备份轮换、大纲内容版本、正文修订与 `script/` 临时件清理。

## 2. 矛盾

- 不做的后果：长线以外的任务没有闭口与归档口径，已完成任务与在推任务混在同一目录；`.trae/specs/` 226 个批次目录（约 8.0 MB）无留存规则；任务书版本块无上限累积，`_HANDOFF_H3.md` 已达 736,001 B，接手者须先读数十版历史才能定位当前入口。
- 受影响者：主代理（接手任一任务需先判状态与真值源）、ykla（验收与归档批准）、复核子代理（无法用统一判据核对）、后续复审者。

## 3. 正面

- 能力：任一任务可用同一六态判定“现在在哪、下一步做什么、历史去哪找”；归档与轮替有固定去向、命名与阈值。
- 受益者：接手会话、ykla、复核者；长线与“其他任务”不再两套口径。
- 验证方式：`_longline_status.py --check` PASS；`任务轮替与归档规则.md` §六 人工核对五项；`audit_engineering_practice.py` E1–E7 与 `audit_gate_registry.py` R1–R8 全 PASS。

## 4. 负面

- 成本：规则文件由 110 行扩至约 260 行；引用该规则的文件需同步改名；每批轮替增加人工核对五项。
- 风险：阈值过松会导致频繁搬迁，过紧会重新积压；未入册线与“其他任务”的闭口判据依赖主代理判断，存在主观空间。
- 边界：`.trae/specs/` 旧批次不追溯迁移，历史规格仍只在忽略域内；自动化门禁本轮不新增。

## 5. 承担者

| 负面 | 承担者 | 承担时点 |

## 6. 过去依据

- 2026-10-18 立《长线任务归档规则》，只覆盖 17 条登记长线；2026-10-19 两轮轮替把总登记表从 334,632 B 压到 100,165 B，证明窗口轮替有效。
- 2026-10-19／21 的 gapa662、DDJ 批次史轮替是“其他任务”先例，但只存在于各自目录，未上升为规则。

- 日期与环境：2026-10-22，Windows，工作区 `d:\librebsd`。
- 证据路径：`00-编纂规则与格式规范/01-规则/任务轮替与归档规则.md`；`01-项目管理/01-编纂规划与报告归档/长线任务归档总登记表/index.md`；`01-项目管理/01-编纂规划与报告归档/任务书迁移登记.md`。

## 8. 将来失效条件

1. 机读台账改为数据库主存储，登记表不再是派生视图；
2. 归档目录被重构或合并，`NN-` 编号体系失效；
3. 任务类型消失或全部任务转为同一生命周期，三层轮替不再必要；
4. 连续两季无轮替需求，或阈值在三个批次内被两次证伪；
5. `.trae/specs/` 纳入版本控制并具备独立归档机制，12 分册失去唯一载体地位。

## 9. 0 信任校验

- 独立复现：`_longline_status.py --check`、`sync_refactor2026_baseline.py --check`、`audit_engineering_practice.py`、`audit_gate_registry.py`。
- 交叉验证：归档目录清单与磁盘目录双向比对；`_历史快照/` 件与索引引用比对；`git diff --stat` 核对改名与引用同步范围。
- 原始证据：本批 `git status`／`git diff`、文件体量实测输出、changelog 条目。

## 10. 自由影响

- 退出：不改变任何读者可见界面；不引入强制在线或账户。
- 导出：归档件均为普通 Markdown，可直接读取与复制。
- 离线：全部规则、归档与校验在本机完成，不依赖外部服务。
- 默认值可撤销性：六态与阈值为项目默认值，可由 ykla 按 §8 修订并开新 ADR。

## 11. 安全和解

- 资产：任务入口、历史证据、交接连续性。
- 对手：时间造成的入口漂移、双源、误删、并发写者覆盖。
- 攻击面：总登记表、任务书、归档目录、机读块。
- 信任边界：主代理执行、ykla 批准、复核子代理只读核对。
- 现有控制：写前备份、锚点断言、原子替换、`--check`、changelog、逐字保真。
- 残余风险：其他任务的闭口判断仍靠人；旧工程批次规格未追溯；人工核对可能漏项。
- 证据：本批门禁输出与文件体量实测。
- 代价：每批轮替增加约五项人工核对。
- 失效条件：见 §8。

## 12. 复审触发

- 时间：2027-04-22。
- 事件：任一阈值在一个季度内触发两次以上、出现双源或误删、任务类型变化、归档目录重构、`.trae/specs` 纳入版本控制。
- 复审动作：重判阈值与六态、核对归档索引与磁盘、把结论写入 `工程实践复审台账.md`；必要时开新 ADR 替代本件。

## 附：替代方案与取舍

| 方案 | 正面 | 负面 | 为何未选 |
| ---- | ---- | ---- | -------- |
| 最小范围：只补其他任务 | 改动小，长线规则不动 | 长线与“其他任务”继续两套口径；任务书版本块与 specs 仍无规则 | 不能解决入口漂移的主因 |
| 新建独立规则、旧规则改指针 | 新文件边界清晰 | 两处维护、旧引用需二次跳转 | ykla 选择扩展现有规则 |
| 全量范围：含 specs 物理迁移与自动门禁 | 一次性收干净 | 226 个目录历史状态不一，迁移风险高；门禁改动未验证 | 超出本轮“规则＋ADR”交付点 |
| **扩展现有规则＋统一六态（本件）** | 一套口径覆盖三类对象；旧引用同步改名；不动物理历史 | 规则变长；旧 specs 不追溯 | 采用 |
