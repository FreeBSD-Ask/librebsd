## 二、🔴 anchor 定位弃用留痕（本批最重要的实测发现）

设计原案（依规格 P1-9）：`showPopover({source})`＋`position-anchor: implicit`＋`position-area: block-end span-inline-end`＋`position-try-fallbacks` 交浏览器定位与翻转。**实测三个事实**（取证脚本 `script/_pop_minimal_20261011.mjs`／`_pop_forensic2`／`_pop_geom`）：

| 场景 | 结果 |
| ---- | ---- |
| 最小用例（button 锚） | anchor **生效**：popTop=344＝锚底 330＋margin 14，分毫不差；`positionAnchor` computed 序列化 quirk 显示 "auto" 但布局正确 |
| 生产页（a.plink 锚，同引擎同 API） | **不生效**：打开态 dTop=558（应 14）、dLeft=559、`position-area` computed 在场（"start span-end"）且 **inset 被 position-area 机制接管**——内联定位被吞、浮层落异常位置 |
| Esc light dismiss 事件 | **只发 beforetoggle/toggle，不发 close/cancel**（两场景一致）→ `.open` 同步必须挂 toggle |

裁决：implicit anchor 组合在该引擎**行为不确定**（最小用例可、生产页不可，根因未再深挖）——**弃用**，CSS 守卫整段注释保留（待显式 `anchor-name` 方案复核）；定位回归 JS 补位（`popPlace`，与基线 left 语义一致且新增上下 clamp）。这与评估表“中可行性、需浏览器支持回退”的预期兑现。
