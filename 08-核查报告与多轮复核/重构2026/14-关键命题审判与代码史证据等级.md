# 第一部分 关键命题审判机制（第二十七阶段）

## 1.1 定位：审判是证据清点，不是裁决历史

任务书第二十七阶段要求对 8 大命题建立审判机制。本体系对"审判"一词做一次受总纲约束的转译：

1. **审判的对象是"命题的可辩护性"，不是"历史的真相"。** 每次审判清点的是：正方证据有哪些、反方证据有哪些、替代解释有哪些、各自落在哪一层史料、哪一级证据等级。审判的产出是**证据地图**，不是判决书。这与 P43（诚实而非客观）及争议系统（09 号文档系统五"不给定论"）同构——命题审判是争议系统在"全书级大命题"上的特化形态：争议系统处理章内辨析，命题审判处理贯穿全书的八大命题。
2. **"本书解释"栏的法定性质**（承接裁决 R12）：六栏模板中的"本书解释"栏**不是定论栏**，而是"编纂者建构声明栏"——其法定句式为 P35 原文规定的"编纂者基于……选择以……方式归因"。凡命中原样适用 R12（如"BSD 最大影响是什么"），该栏写的是"本书如何呈现该问题的多版本，并声明为何不给定论"，而不是答案。
3. **审判必须可重开**。新证据到达即触发重审（`trial_round` 递增），历史审判记录不删除——审判史本身是考据留痕（P30）。

| ---- | -------------- | ------------------ | -------- |

| TP-2 | BSD 为何影响巨大 | BSD 的技术影响通过哪些具体机制传播（逐类分解，拒绝笼统"巨大"） | 问题树 Q2；07 号文档十二分类 |
| TP-3 | BSD 为何未成主流 | BSD 的边缘位置如何形成、并生产了什么独特品质 | 问题树 Q3；总纲 8/20（禁成败框架、禁倒灌"主流"） |
| TP-4 | BSD 许可证为何形成 | BSD 许可证是谁的利益分配方案、经何种决策过程形成 | 问题树 Q4；总纲 13（禁理念还原） |
| TP-5 | BSD 与自由软件的关系 | BSD 与自由软件/开源运动的话语与利益双线关系如何 | 问题树 Q5 |
| TP-6 | Linux 继承了 BSD 什么 | Linux 从 BSD/Unix 取走了什么、没取走什么（十二类逐类审计） | 问题树 Q6；07 号文档 §3.2 |
| TP-7 | BSD 为何被遮蔽 | BSD 在历史叙事中被遮蔽的机制：由谁、借何种叙事、何时开始 | 问题树 Q7；R13 分布式承载 |

## 1.3 六栏模板与命题审判 DDL

**六栏模板**（任务书规定的六栏，逐栏给出填写规范）：

```
【命题审判记录】 trial_id: PT-TP<n>-<轮次>
★ 命题            ：入库措辞（1.2 表）+ original_wording（口语原形）
★ 栏1 正方证据    ：支持该命题（或命题中某一解答方向）的证据清单；
                    每条：证据ID + 证据等级(L1-L5) + 史料层级(1-5) + 定位信息
★ 栏2 反方证据    ：反对证据清单，同上格式；
                    无则填"已检索，未见反证（附检索记录引用 search_log_ref）"——不许留空
★ 栏3 替代解释    ：竞争性解释清单，每条含证据挂接与处置状态（未评估/已排除/并存）；
                    至少登记一条——单因解释违反问题4（五段式分析段不接受单一原因）
★ 栏4 一手史料    ：第一、二层史料的专项清点（代码产物/邮件/IRC/Bugzilla），
                    逐条列标识与时间戳（P42：追踪讨论串全程、注意谁没说话）
★ 栏5 二手研究    ：第四、五层史料专项清点，逐条标注其依赖的下层史料（若有）；
                    第五层不得独立支撑任何栏目的结论（P41）
★ 栏6 本书解释    ：编纂者建构声明（非定论）。句式强制："编纂者基于[栏1-5的证据分布]
                    选择以[方式]呈现/归因……"（P35）；TP-8 类命题按 R12 写
                    "多版本并置声明 + 为何不给定论"
  审判状态        ：open / evidence_reviewed / statement_drafted / frozen
  重审记录        ：trial_round + 每轮的增量证据与状态变化日志
```

**DDL（设计文本，不执行）**：

```sql
-- ============================================================
-- 关键命题审判 schema v0.1（设计文本 · 不执行）
-- 依据：任务书第二十七阶段；05-历史问题树 Q0-Q8；01b 裁决 R11/R12
-- ============================================================

CREATE TABLE IF NOT EXISTS proposition (
    proposition_id   TEXT PRIMARY KEY,      -- TP-1 … TP-8
    original_wording TEXT NOT NULL,         -- 任务书口语原形（留痕）
    compliant_wording TEXT NOT NULL,        -- 入库合规措辞（1.2 表）
    question_tree_ref TEXT NOT NULL,        -- 挂接问题树节点 Q0-Q8（R11：问题树为索引）
    verdict_policy   TEXT NOT NULL DEFAULT 'tentative_statement'
                     CHECK (verdict_policy IN
                       ('tentative_statement','multi_version_no_verdict')),
                     -- TP-8 取 multi_version_no_verdict（R12），其余取 tentative_statement

    related_claim_ids TEXT,                 -- JSON：关联影响主张 claim_id
    created_at       TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at       TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS proposition_trial (
    trial_id        TEXT PRIMARY KEY,       -- PT-TP<n>-R<轮次>
    proposition_id  TEXT NOT NULL REFERENCES proposition(proposition_id),
    trial_round     INTEGER NOT NULL,       -- 第几轮审判（重审递增）
    status          TEXT NOT NULL DEFAULT 'open'
                    CHECK (status IN ('open','evidence_reviewed',
                                      'statement_drafted','frozen')),
    opened_by       TEXT,
    opened_at       TEXT NOT NULL DEFAULT (datetime('now')),
    closed_at       TEXT,
    UNIQUE (proposition_id, trial_round)
);

-- 六栏统一为一张"审判材料"表，column_code 区分栏位（便于审计查询与视图）
CREATE TABLE IF NOT EXISTS trial_material (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    trial_id       TEXT NOT NULL REFERENCES proposition_trial(trial_id) ON DELETE CASCADE,
    column_code    TEXT NOT NULL CHECK (column_code IN
                   ('pro_evidence','con_evidence','alternatives',
                    'primary_sources','secondary_sources','book_statement')),
                   -- 栏1 正方证据 / 栏2 反方证据 / 栏3 替代解释 /
                   -- 栏4 一手史料 / 栏5 二手研究 / 栏6 本书解释
    item_text      TEXT NOT NULL,           -- 证据/解释/史料的描述
    evidence_id    TEXT,                    -- 主张库 evidence 表主键，EV-<六位序号>（06 §8.2 约定）
    evidence_level TEXT CHECK (evidence_level IN ('L1','L2','L3','L4','L5')),
    source_layer   INTEGER CHECK (source_layer BETWEEN 1 AND 5),
    citation_detail TEXT,                   -- commit/Message-ID/页码定位
    disposition    TEXT,                    -- 栏3 用：未评估/已排除/并存
    search_log_ref TEXT,                    -- 栏2"未见反证"时的检索留痕
    created_at     TEXT NOT NULL DEFAULT (datetime('now')),
    CHECK ( (column_code = 'book_statement' AND evidence_id IS NULL)
         OR (column_code <> 'book_statement') )
    -- 栏6 是建构声明，不挂证据ID（其依据是栏1-5的整体分布，引用写在 item_text 中）
);
CREATE INDEX IF NOT EXISTS idx_tm_trial  ON trial_material(trial_id, column_code);
CREATE INDEX IF NOT EXISTS idx_tm_evid   ON trial_material(evidence_id);

-- 审判轮次日志（重审留痕）
CREATE TABLE IF NOT EXISTS trial_round_log (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    trial_id     TEXT NOT NULL REFERENCES proposition_trial(trial_id) ON DELETE CASCADE,
    delta_summary TEXT NOT NULL,            -- 本轮相对上轮的增量：新证据/新替代解释/措辞变化
    logged_by    TEXT NOT NULL,
    logged_at    TEXT NOT NULL DEFAULT (datetime('now'))
);
```

## 1.4 审判程序规则

- **T1（措辞前置）**：命题未按 1.2 完成措辞转换不得开审。口语原形保留在 `original_wording`，书稿中禁止出现。
- **T2（反证义务）**：栏 2 为空或无 `search_log_ref` 的审判，`status` 封顶 `open`。"没找反证"与"找了没找到"必须可区分。
- **T3（替代解释义务）**：栏 3 少于一条"已处置"（`disposition != '未评估'`）替代解释的审判不得进入 `statement_drafted`。
- **T4（层级清点义务）**：栏 4、栏 5 必须分开清点（一手/二手不混栏）；栏 5 中每条第五层史料须标注其依赖的下层史料或标"无下层依赖——独立二手论述"（后者不得支撑任何结论句）。
- **T5（建构声明句式）**：栏 6 不以"编纂者基于……"句式开头即违规（P35）；TP-8 类命题栏 6 必须以"本章/本命题不提供定论，因为……"开头（R12）。
- **T6（重审触发）**：任一栏挂接的 `evidence_id` 被主张库标记为失效/降级时，对应审判自动重开一轮（`trial_round` +1，原轮次 `frozen` 保留）。
- **T7（出口绑定）**：书稿中任何"全书级大判断"（卷首概述、遗产段）必须引用某个 `status != 'open'` 的审判 trial_id；未过审的大判断禁写。

# 第二部分 代码史研究（第二十八阶段）

## 2.1 定位：代码是第一层史料的考据学

P41 把代码与构建产物列为第一层史料（可信度最高、形式主义程度最低："代码是行动的直接痕迹"）。第二十八阶段的代码史（Code Provenance）就是把这一层史料**考据学化**：为每一处"某代码源自某 BSD 版本"的主张建立可审计的谱系记录，并系统性排除"代码相似 = 继承"的谬误。

三个基本设定：

1. **谱系记录的对象是 file/function 级实体**，不是"系统级血统"。"macOS 基于 BSD"不是谱系记录，"Darwin 代码树中 `sys/kern/uipc_socket.c` 的某函数可追溯至 4.4BSD-Lite 的同名文件"才是。系统级判断只能由 file/function 级记录的聚合推出，且聚合时须声明覆盖率（审计了多大比例的文件）。
2. **谱系证据链的每一环都要落证据等级**：file→BSD version 靠版本记录（L5），BSD version→commit 靠 commit 记录（L5），commit→author 靠提交元数据（L5/L4），author→later project 靠后续项目中的出现记录+传播路径（L5 若有直接复制记录，否则降级）。任一环降级，整条谱系的定级取最低环。
3. **负面结论同样记录**："经审计未发现 X 项目中 BSD 来源代码"是合法的、重要的代码史结论（对应 07 号文档 Q-META-01 元规则），须附审计方法说明（比对了什么、用什么方法、覆盖范围），记为 `negative_finding`。

## 2.2 Code Provenance 记录模板

任务书规定七要素：file/function → BSD version → commit → author → later project → evidence。逐要素扩展为可填模板：

```
【代码谱系记录】 prov_id: CP-<序号>
★ 对象实体       ：file（完整路径）或 function（文件+函数签名）
★ 对象快照标识   ：该实体的内容指纹（hash 或关键行引用），防止"同名不同物"
★ BSD 来源版本   ：归属的 BSD 版本（如 4.3BSD-Reno / 4.4BSD-Lite / FreeBSD 2.x）
★ 来源 commit    ：该实体在来源版本中的 commit/变更集标识（SCCS/CVS/Git）
★ 来源 author    ：作者（对应主张库 person 对象；匿名/集体署名须注明）
★ 去向项目       ：later project（该项目中的路径/函数名，若改名须注明对应依据）
★ 证据           ：每环的证据条目（证据ID + 等级），取最低环等级为整条定级
  传播路径类型   ：直接复制 / vendor import / cherry-pick / 人工移植 / 独立实现存疑
  许可证痕迹     ：去向文件中保留的来源版权头/许可证声明（有/无/部分，附原文定位）
  相似度说明     ：若非逐字复制，说明差异范围（重写程度）及判定依据
  负面结论位     ：negative_finding（本条不适用时留空；专项负面审计另立记录）
  关联           ：linked_impact_claim_id（该谱系支撑哪条影响主张，07号文档类型1）
```

## 2.3 "相似≠继承"判定流程（规则 C1–C4）

任务书明令"代码相似 ≠ 继承"。落为四步判定流程，任何谱系主张必须走完：

- **C1（排除共同祖先）**：相似的两个实体是否同源于更早的共同代码库（如 AT&T Unix V7、早期共享的 utilities）？若是，则两后继项目之间**无**谱系关系，只有共因——该主张改挂"共同祖先"标签，不得记为两者间继承。方法：查找两实体能否各自追溯到共同祖先版本。
- **C2（排除独立实现）**：实体是否属于"面对相同约束的高概率相似解"（如标准算法的教科书实现、RFC 协议的直接实现、相同硬件手册驱动的代码）？若是，相似不构成继承证据；须另找传播路径证据（谁见过谁）才能升级。
- **C3（排除中间标准层）**：相似是否经由标准/公共参照物（POSIX 文本、RFC、公开教材代码）中介？若是，谱系记为"来源→标准→去向"两段，且"来源→标准"段须单独举证（BSD 实践是否真的进入了该标准条文——这是历史问题，不是逻辑推定）。
- **C4（路径证据要求）**：通过 C1–C3 后，仍须存在传播路径证据（代码树的 import 记录、邮件中的复制讨论、当事人的复制陈述）方可定级 L5/L4；只有相似度而无路径证据的，封顶 L2"强技术对应"，禁写继承（07 号文档措辞门禁）。

**流程即记录**：每次判定在谱系记录中留 `c1_c4_check` 字段（JSON：四步各填结论与依据），使"为何这不是共因/独立实现"本身可复核。

# 第三部分 技术影响证据五级（第二十九阶段）

## 3.1 五级判定标准

任务书第二十九阶段的五级在 07 号文档已作措辞门禁引用，本节给出**判定标准**（每条证据归入哪一级的操作定义）与边界裁决规则。

| 等级 | 任务书名称 | 操作定义（判定标准） | 典型证据形态 |
| ---- | ---------- | -------------------- | ------------ |
| L5 | 直接代码来源证据 | 存在**可复核的物质性代码谱系**：版权头链、commit/vendor 记录、文件级复制痕迹，任何第三方可独立复核 | code_provenance 记录（第二部分）；许可证声明中的原版权文本 |
| L4 | 作者开发者明确陈述 | 影响链条上的当事人**明确说出**影响关系（"我参考了 X""我们从 Y 取用了 Z"），且陈述可定位到具体文本 | 邮件、访谈、自述、commit message 中的归因语句 |
| L3 | 技术文档论文明确说明 | 非当事人自述、而是**官方/技术文档或论文中明确记载**了该影响关系 | 设计文档、release notes、RFC、论文、官方 FAQ |
| L2 | 强技术对应但缺直接证明 | 两侧技术实体**高度同构**（结构/行为/细节错误方式一致），但无 L3-L5 的传承路径证据 | 实现对照分析 + C1–C3 已排除共因/独立实现/标准中介的记录 |
| L1 | 仅历史相关性相似性 | 仅有**时序相伴、表面相似、共同祖先遗产**，无同构性深度证据或同构性未经审计 | 流行说法、百科式综述、"都是 Unix"式笼统关联 |

**边界裁决规则**：

- **L-1（降级链）**：证据等级按最弱环定级。"L4 陈述 + L1 佐证"仍只是 L4；"L5 谱系但去向不明"不构成完整影响证据（谱系只证"代码移动过"，还需证"移动到了哪里"）。
- **L-2（陈述可靠性折扣）**：L4 陈述本身按史料层级再分——当时文本中的陈述（第一、二层）为满额 L4；事后访谈/回忆录中的陈述（第四层）记 L4*，**书稿措辞必须带"据其事后回忆"限定**，且尽量配当时文本佐证（P41、09 号文档系统三记忆降权规则）。
- **L-3（L2 的准入门槛）**：声称 L2 必须先完成第二部分 C1–C3 排除记录；未做排除流程的"技术对应"一律先记 L1，待流程补做后升级。
- **L-4（L1 的合法地位）**：L1 是研究线索不是废品——它进入研究问题清单（07 号文档第三部分）、进入命题审判的待查栏，只是不得以继承/影响句式进入书稿。

## 3.2 措辞门禁与违规示例对照

07 号文档 §2.3 已给门禁表，本节补**违规/合规对照**（供复核扫描与写作者自查）：

| 证据等级 | 违规表述示例 | 合规替代表述 |
| -------- | ------------ | ------------ |
| L1 | "Linux 继承了 BSD 的 Unix 设计" | "Linux 与 BSD 共享 Unix 传统；该传统分别经由何种路径到达两者，待逐条审计" |
| L1 | "BSD 的衰落给了 Linux 机会" | "USL 诉讼期（1992-1994）与 Linux 早期发展在时间上重叠；因果关联需按因果链程序单独审计" |
| L2 | "Linux 网络栈借鉴了 BSD"（无路径证据） | "Linux 与 BSD 网络栈存在强技术对应；传承路径证据目前缺失（L2）" |
| L4* | "Linus 说 BSD 启发了他"（事后访谈，未核对原文） | "据其后来的访谈称……（事后陈述，未配当时文本，L4*）" |
| L4 | （合规）"据 1992 年 X 邮件，作者明确写道……" | —— |
| L5 | （合规）"文件 F 的版权头与 vendor 记录显示其于 C 次提交进入该项目" | —— |

**扫描规则**（供复核）：书稿文本中出现"继承/源自/借鉴/基于/抄自/影响了"等承继类动词时，生成器/复核器要求该句引用一个 `evidence_level ∈ {L3,L4,L5}` 的主张 ID；引用 L1/L2 或未引用即标红。

## 3.3 证据等级 × 史料层级二维矩阵

证据等级（L1–L5，证"影响关系"的强度）与史料层级（1–5，证"史料本身"的可信度，P41）是**两个独立维度**，不得互相代替。矩阵给出常见组合的处置：

| 组合 | 含义 | 处置 |
| ---- | ---- | ---- |
| L5 + 层级1 | 代码谱系证据即代码本身 | 最强组合，可直接支撑继承句 |
| L4 + 层级2 | 当时邮件中的明确陈述 | 强；陈述者立场须按 P42 标注 |
| L4 + 层级4 | 事后访谈中的明确陈述（L4*） | 带"事后回忆"限定使用；须尽量补层级1-2佐证 |
| L3 + 层级3 | 官方文档明确记载 | 可用；注意官方文档的立场性（第三层） |
| L3 + 层级5 | 二手研究转述的"文档记载" | 必须回溯原始文档；回溯失败则降级 L1 |
| L2 + 任何层级 | 强对应无路径 | 只写"强技术对应"；启动路径证据搜寻 |
| L1 + 层级4/5 | 事后/二手的笼统说法 | 只进研究线索与争议登记；禁入书稿因果句 |

**反例警示**（审计中高频出现的错误）：用"层级 1 的相似代码"直接跳到"L5"——层级 1 只说明该证据本身可信（代码是真的），不说明影响关系成立（相似还需过 C1–C3）。层级高 ≠ 等级高。

# 第四部分 人物动机证据五级（第三十阶段）

## 4.1 五级定义与判定标准

技术影响证据（第三部分）回答"X 是否影响了 Y"，动机证据回答"某人**为何**这样做"。后者在 BSD 史中尤其危险：动机叙述是事后合理化、英雄叙事（P20 禁天才叙事）、苦难叙事（标准 7）的重灾区。任务书第三十阶段的五级：

| 等级 | 任务书名称 | 操作定义（判定标准） | 典型证据形态 |
| ---- | ---------- | -------------------- | ------------ |
| M1 | DIRECT_STATEMENT | 当事人**当时**明确说出动机（不是事后解释当时行为） | 决策当时的邮件原句："我这样做是因为……"；会议记录中的动机陈述 |
| M2 | CONTEMPORARY_DOCUMENT | 同时代文档**显示**了动机条件（当事人未明说，但当时记录呈现了其处境/约束/选项） | 当时的资源限制记录、合同条款、讨论串中呈现的两难、时间压力证据 |
| M3 | STRONG_INFERENCE | 编纂者从多条 M2 级同时代证据作出的**强推断**，推断链条完整、每环有据、替代动机已排除至少一条 | 证据组合+推断备忘录（写明推断步骤与每步依据） |
| M4 | WEAK_INFERENCE | 证据不足以支撑完整推断链，只有方向性猜测 | 零散的同时代旁证；行为与动机的弱关联 |
| M5 | SPECULATION | 无同时代证据支撑的动机设想，包括一切"他一定想……""显然他是为了……" | 事后回忆中的动机追认、传记作者的想象、流行叙事 |

**判定规则**：

- **M-A（当时性铁律）**：M1/M2 的"当时"以行为发生时间为基准——事后陈述当时动机（哪怕只晚一年）自动降为 M5 处理，再按 09 号文档系统三的记忆降权规则评估是否可作线索使用。理由：动机的事后陈述是记忆重构的最高发区（P42、系统三）。
- **M-B（推断留痕）**：M3 必须附推断备忘录（`inference_memo` 字段）：列出每一步推断、每步依据的 M2 证据、排除的替代动机。无备忘录的"强推断"自动降 M4。
- **M-C（单证不成动机）**：任何单独一条证据（哪怕 M1）若与当事人的已知处境矛盾（如声称"为理想"而同时代记录显示是合同义务），必须并置呈现矛盾，不得择一采信（P55 多版本并置在动机层的适用）。
- **M-D（动机≠后果归因）**：证明某人有某动机，不等于证明该动机产生了某历史后果——动机记录与因果箭头分立，后果归因仍走 07 号文档的箭头审计程序。

## 4.2 措辞门禁：SPECULATION 禁写成 FACT

| 等级 | 允许措辞 | 禁止措辞 |
| ---- | -------- | -------- |
| M1 DIRECT_STATEMENT | "据其当时的邮件，X 表示动机是……" | 不得写"X 的动机就是……"（陈述≠真相，须带归源限定） |
| M2 CONTEMPORARY_DOCUMENT | "当时的记录显示 X 面临……条件/约束" | 不得把处境直接读作内心动机（"因为穷所以……"式还原禁止） |
| M3 STRONG_INFERENCE | "编纂者基于[证据组合]推断 X 的动机可能是……（替代解释……已排除/未排除）" | 不得去掉"推断"限定词 |
| M4 WEAK_INFERENCE | "一种可能的解释是……，现有证据不足以确证" | 不得写成"事实上是为了……" |
| M5 SPECULATION | **禁入书稿事实性陈述**；只可在辨析/争议栏以"流行说法/传记想象"身份出现并标注 M5 | 禁写"X 是为了……""X 显然想……"；禁以 M5 支撑任何因果句 |

**高频违规模式（复核扫描清单）**：

1. **天才动机倒灌**："Linus 出于对完美的追求……"——无当时陈述的动机美化，M5 伪装 M1；
2. **苦难动机倒灌**："尽管资源匮乏，社区仍然出于热爱坚持……"——标准 7 禁令 + M5；
3. **利益动机独断**："他们显然是为了商业利益"——无 M2 处境证据的还原论，M5；
4. **事后动机追认当事实**：以二十年后的访谈解释当年的决定——按 M-A 降 M5，若采用须带"事后回忆"限定。

## 4.4 与人物书写原则的衔接

- **P20 人物不神化**：动机记录的用途是**约束**人物书写——凡传记性段落出现动机句，复核器要求挂接 mot_id；无 mot_id 的动机句视为 M5 违规。这使"不将个体叙述为天才/远见卓识者"变成可机检的规则，而非风格建议。
- **标准 12 非核心贡献者**：动机证据义务平等适用于所有人物——非核心贡献者的行为同样只允许在有证据时写动机，没有证据就写具体行动本身（"提交了补丁 X"），不猜测动机。
- **与 09 号文档系统三的联动**：事后动机追认（M-A 降级产物）若构成"重新归因"型记忆变形，同步登记到 Event Memory 的 `distortion_type`。

## 5.2 审计视图（SQL，设计文本）

```sql
-- 命题审判完整性：六栏缺栏即红旗
CREATE VIEW IF NOT EXISTS v_trial_completeness AS
SELECT t.trial_id, t.status,
       SUM(CASE WHEN m.column_code = 'pro_evidence'      THEN 1 ELSE 0 END) AS col1,
       SUM(CASE WHEN m.column_code = 'con_evidence'      THEN 1 ELSE 0 END) AS col2,
       SUM(CASE WHEN m.column_code = 'alternatives'      THEN 1 ELSE 0 END) AS col3,
       SUM(CASE WHEN m.column_code = 'primary_sources'   THEN 1 ELSE 0 END) AS col4,
       SUM(CASE WHEN m.column_code = 'secondary_sources' THEN 1 ELSE 0 END) AS col5,
       SUM(CASE WHEN m.column_code = 'book_statement'    THEN 1 ELSE 0 END) AS col6
FROM proposition_trial t LEFT JOIN trial_material m ON m.trial_id = t.trial_id
GROUP BY t.trial_id, t.status;
-- 复核判读：col1-col6 任一为 0 即未达 T2-T5 义务；col3 须再查 disposition 非"未评估"（T3）

-- 措辞门禁违规：书稿引用的主张若为 L1/L2 却使用承继类措辞（需书稿侧标注引用后扫描）
CREATE VIEW IF NOT EXISTS v_claim_wording_risk AS
SELECT claim_id, claim_text, evidence_level
FROM impact_claim
WHERE evidence_level IN ('L1','L2');
-- （与 07 号文档附录 B2 互补：B2 查"低等级却 supported"，本视图供书稿引用扫描用）

-- 代码谱系低环警示：存在 L1/L2 证据环的谱系记录
CREATE VIEW IF NOT EXISTS v_provenance_weak_links AS
SELECT p.prov_id, p.target_project, pl.link_stage, pl.evidence_level
FROM code_provenance p JOIN provenance_link pl ON pl.prov_id = p.prov_id
WHERE pl.evidence_level IN ('L1','L2');

-- 动机当时性红旗（4.3 已附 v_motivation_anachronism，此处补 M5 占比监控）
CREATE VIEW IF NOT EXISTS v_motivation_speculation_share AS
SELECT person_ref,
       COUNT(*) AS total,
       SUM(CASE WHEN evidence_level = 'SPECULATION' THEN 1 ELSE 0 END) AS speculation_count
FROM motivation_record GROUP BY person_ref;
-- 某人物名下 SPECULATION 占比过高提示该人物的书稿段落存在动机想象风险
```
