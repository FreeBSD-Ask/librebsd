## 0. 原则锚定：为什么要"重定义"参考文献的作用

〔原文〕lishidagang.md §1.2.1 史料五层级：代码（L1）→即时通讯（L2）→官方文档（L3）→事后叙述（L4）→二手研究（L5），"优先使用第一、二层""从不以第五层为唯一来源"。
〔原文〕§3.2.3："每条事实性陈述标注史料来源。"标准 9："区分一手史料与二手文献，两类分列。"
〔推断〕传统用法把参考文献当作"支撑论点的权威清单"——这是一种形式主义的自然化（把"被引用多"当作"更真实"）。本文的重定义是：**参考文献不是"权威"，而是"有特定用途、有明确不能证明之事"的证据节点**。每条文献须回答两个问题——它能用来做什么（What it is useful for），它不能证明什么（What it cannot prove）。

## 1. 第一部分：参考文献作用重定义

### 1.1 作用元数据 schema（新增字段）

在现有 `references` 表上扩展（不破坏既有 source_tier），新增以下字段：

| 字段 | 说明 | 取值 |
| ---- | ---- | ---- |
| `useful_for` | 本文献可用于支撑的对象类型 | 多选：事实/背景/人物/技术/制度/争议/回忆/代码/统计/同期舆论 |
| `cannot_prove` | 本文献**不能**证明的事项 | 自由文本 + 枚举提示 |
| `evidence_role` | 证据角色 | original（原始证据）/ repost（转载）/ commentary（评论）/ synthesis（综合） |
| `independence_key` | 独立性键（用于来源谱系计数，见第二部分） | 指向 Original Evidence 的标识 |
| `memory_caveat` | 若为 L4 事后叙述，标注记忆重构局限 | 文本 |
| `tier_note` | 与 source_tier 的对应说明 | 文本 |

### 1.2 十类用途的定义与边界

〔推断〕任务指定十类用途，逐一定义其"可用"与"不可用"边界：

| 用途 | What it is useful for | What it cannot prove |
| ---- | --------------------- | -------------------- |
| 事实 | 支撑具体史实（时间/人/事件） | 不能单独证明因果 |
| 背景 | 提供时代语境（接 Task #14 系统一） | 不能作为事件本身的证据 |
| 人物 | 人物生平/行动 | 不能证明人物动机（动机须挂三角模型证据等级） |
| 技术 | 技术实现/设计 | 不能证明"技术优秀"（进步叙事禁止） |
| 制度 | 治理/许可证/合规 | 不能证明制度"更先进" |
| 争议 | 呈现某方观点 | 不能作为争议定论 |
| 回忆 | 当事者事后叙述（L4） | 不能独立支撑事实（须配 L1/L2） |
| 代码 | 代码/commit 直接痕迹（L1） | 不能证明代码之外的人际决策 |
| 统计 | 量化特征（提交数/行数） | 不能证明质量/重要性 |
| 同期舆论 | 当时的媒体/社区反应 | 不能当作事实本身（它是"当时如何被叙述"） |

### 1.3 与现有 source_tier 的映射

〔原文/现状〕现有 `source_tier` 取值：primary / primary_hand / secondary / secondary_authoritative / secondary_nonauthoritative / banned_repost。
〔推断映射〕：

- primary / primary_hand → L1-L3（一手），`useful_for` 侧重 事实/代码/制度；
- secondary_authoritative → L5 上层（可作背景/争议参照，不可作唯一来源）；
- secondary_nonauthoritative → L5 下层（仅作线索）；
- banned_repost → 禁用（对应 §1.2.1 禁维基/CSDN），`cannot_prove`＝一切。

### 1.4 操作规则

1. **引用前置查询**：撰写者引用某文献前须查其 `useful_for`/`cannot_prove`；越界引用（用回忆类文献独立支撑事实）即违规。
2. **两类分列**：章末/卷末书目按标准 9 一手/二手分列，并标注每条的 `useful_for`。
3. **L4 必带 caveat**：凡引用采访/回忆录，正文须带 `memory_caveat`（接 Task #14 系统三记忆史）。

## 2. 第二部分：来源谱系系统（Source Lineage）

### 2.1 解决的问题

〔原文锚定〕标准 1"每条事实有可溯源史料"+标准 4"至少两个独立来源交叉验证"。
〔推断〕交叉验证的前提是"来源真正独立"。但 BSD 史中大量文献是**同源转载**——一篇原始邮件被 10 篇博客转载，若不加甄别，"10 篇引用"会被误算为"10 个独立证据"。来源谱系系统的功能是：**追溯每条引用到 Original Evidence，自动计算真正的 Independent Sources 计数，识别"10 篇转载=1 个独立来源"**。

### 2.2 Source Lineage schema

| 字段 | 说明 |
| ---- | ---- |
| `lineage_id` | 谱系记录标识 |
| `citing_ref_id` | 引用方文献（references.id，A） |
| `cited_ref_id` | 被引方文献（references.id，B） |
| `relation_type` | A 与 B 的关系：cites（正常引用）/ reposts（转载）/ derives_from（派生）/ same_event（同事件独立记录） |
| `original_evidence_id` | 追溯到的 Original Evidence（最终源头，可为 L1 代码/L2 邮件） |
| `independent_source_count` | 自动计算的独立来源数 |
| `is_repost_cluster` | 是否属于转载簇（10 篇转载=1 源） |

### 2.3 独立性判定规则

〔推断〕"独立来源"的判定标准：

1. **同事件、不同记录者、无相互抄袭** → 计为独立（+1）。
2. **A 转载/派生自 B** → A 与 B 计为同一独立来源（不重复计数）。
3. **追溯到同一 Original Evidence 的多条** → 全部归并为 1 个独立来源。
4. **`independent_source_count` 计算**：对某事实的所有引用，按其 `original_evidence_id` 去重后的数目。

### 2.4 操作规则

1. **转载簇识别**：对 `relation_type=reposts` 的引用群，标记 `is_repost_cluster=true`，其 `independent_source_count=1`，并在正文脚注警示"此 N 篇为同源转载"。
2. **交叉验证门槛**：标准 1 要求"至少两次独立核验"——核验的是 `independent_source_count ≥ 2`，而非引用篇数 ≥ 2。
3. **Original Evidence 优先**：若某事实可追溯到 L1/L2 Original Evidence，正文应直接引用 Original Evidence，而非转引二手转载。
4. **与争议系统联动**：争议各方的 `sources_per_position` 须标注独立来源数，防止以转载簇冒充多方证据。

### 2.5 与既有数据库的衔接

〔现状〕`references_fulltext.db` 已有 `reference_duplicates`（去重）、`key_facts`（事实抽取，含 confidence）表。
〔推断〕来源谱系可作为新表 `source_lineage` 加入，`citing_ref_id`/`cited_ref_id` 外键指向 `references.id`；`key_facts.related_*` 字段可与谱系联动，为每条 fact 计算独立来源数。
