## 第一部分 大纲生成算法：十步流水线（第二十二阶段）

### 1.1 总则：两条生产链的对立

用户任务书第二十二阶段的指令是：**不要让模型"根据资料生成目录"**。改为十步流水线。本部分将其固化为可执行算法。两条生产链的对立是全部规则的出发点：

**被禁止的旧流程**（简称"资料直生链"）：

```
资料（03-原始史料库 / 04-现代研究文献 / 各 .db）
   │   （模型对资料做无结构总结）
   ▼
AI 总结（聚类、分段、起标题）
   ▼
章节结构（目录）
```

**强制的新流程**（简称"十步链"）：

```
思想 → 问题 → 史料 → 证据 → 历史解释 → 章节
```

展开为十个步骤：**①解析编纂思想 → ②建立历史问题树 → ③建立历史对象 → ④建立时间轴 → ⑤建立技术谱系 → ⑥建立组织谱系 → ⑦建立制度变化 → ⑧建立争议 → ⑨建立历史解释 → ⑩生成章节结构**。

### 1.2 为什么"资料→AI总结→章节"被禁止

禁止不是姿态，是结构性理由。六条：

1. **目录被资料分布绑架**。资料的现存分布是采集偶然性的产物（见《02-数据库盘点》：research_notes.db 272 MB、邮件列表库 11.2 GB、代码仓库库 23 GB，而 fact_checks.db 活跃文件为 0）。"根据资料生成目录"等价于"根据采集偏态生成目录"——资料多的时期章节密、资料少的时期章节疏或消失。这直接违反 R2（裁决记录：篇幅与史料丰度成比例是**操作规则**，但比例的对象是"经问题树确认应当叙述的对象的史料丰度"，不是"已采集到的文件体量"）。
2. **解释缺位**。资料直生链中不存在"历史解释"这一层，章的存在理由只能是"这一时期发生了很多事情"——正是第二十四阶段要求降级的形态。删除这样的章，全书不失去任何解释（见第二部分判据）。
3. **违反经验优先（P19）**。P19 要求理论框架在一手经验**之后**形成；资料直生链却让模型带着隐式的、未经声明的框架（聚类算法的相似度即框架）一步到位产出章节，等于先验框架伪装成归纳结果，且不可审查。十步链把框架的引入显式拆到第 1 步（声明式）与第 9 步（证据后）。
4. **违反解释学循环的自觉（P29）**。P29 承认理解总在前理解中，对策是"回到具体事件"。十步链的每一步都是一个可被 Skeptic 审查的具体中间产物；资料直生链把全部解释学选择压缩进一次不可见的模型调用。
5. **不可回溯、不可审计**。本书的质量承诺是"单位篇幅的证据密度"（R1）。密度可核查的前提是：章 → 历史解释 → 证据 → 史料 → 问题 → 思想 的逆向回溯链完整。资料直生链没有中间层，回溯链在第 2 步就断裂。v3 审计的三项基线（47% 章锚定素材=0、52% 章参考文献匹配=0、30% 双零章）正是资料直生链的历史后果：**章节先于证据存在，证据回填永远追不上**。
6. **复现与分工不可能**。资料直生链无法分工（单次调用）、无法增量（重跑即重洗）、无法 A/B 比较（无中间产物可对照）。十步链每一步产物落盘、可冻结、可版本化，支持任务清单中 Phase 23-25 的 A/B/C 三版大纲对照实验。

### 1.4 AI 四角色分工总表

四角色定义（与任务清单 Phase 34-37 的"AI四角色"阶段对齐；本文只定义其在大纲生成中的职责边界）：

- **Researcher（研究者）**：负责获取、登记、分层史料；不做解释。
- **Historian（史家）**：负责建立对象、谱系、解释与章节结构；不做资料获取，不裁决争议。
- **Skeptic（怀疑者）**：负责质检关卡的逐条执行与否决；不产出内容，只产出"通过/不通过/存疑 + 理由"。
- **Editor（编者）**：负责把通过质检的解释装配为章节结构、控制体例与前后一致；不新增历史主张。

| 步骤 | 主责 | 副责 | 质检（Skeptic 关卡） |
| :--: | :--- | :--- | :------------------- |
| 1 思想解析 | Historian | Editor | 关卡 G1 |
| 2 问题树 | Historian | Researcher | 关卡 G2 |
| 3 历史对象 | Historian | Researcher | 关卡 G3 |
| 4 时间轴 | Researcher | Historian | 关卡 G4 |
| 5 技术谱系 | Researcher | Historian | 关卡 G5 |
| 6 组织谱系 | Researcher | Historian | 关卡 G6 |
| 7 制度变化 | Historian | Researcher | 关卡 G7 |
| 8 争议 | Skeptic 主责 | Historian | 关卡 G8（互查：Historian 复核 Skeptic 的争议清单是否遗漏） |
| 9 历史解释 | Historian | Skeptic | 关卡 G9 |
| 10 章节结构 | Editor | Historian | 关卡 G10 |

铁律：**同一步骤的主责与质检不得为同一角色的同一次调用**（角色分离即利益冲突回避）。

#### 步骤 2：建立历史问题树

- **输入**：步骤 1 产物（问题 1-10 的三层设问：形式层/实质层/价值层，见《原则清单》第三部分）；既有大纲仅作**对照物**不作原料。
- **动作**：把编纂思想中的总问题分解为问题树：根问题（本书回答什么）→ 主干问题（五维度：技术/法律/社区/商业/文化各自的演变机制）→ 枝问题（每个分合相位中发生了什么）→ 叶问题（可由单条史料回答的原子问题）。每个节点登记：问题文本、父节点、回答它所需的史料类型、它在《原则清单》中的原文依据。

- **执行者**：Historian 主责，Researcher 标注每个叶问题的可答性（现有史料能否回答）。
- **质检关卡 G2**：(a) 树中每个非根节点必须有父节点（无孤儿问题）；(b) 每个叶问题必须标注"现有史料可答 / 部分可答 / 不可答"——不可答的叶问题**不删除**，转入第四部分研究缺口登记（这是问题树与研究缺口系统的原生接口）；(c) Skeptic 抽查 ≥10% 节点，验证原文依据不是事后比附。

- **动作**：登记制度层的每次变化：许可证条款变化、治理结构变化、法律地位变化、规范/标准变化。每项登记：制度对象、变化前状态、变化后状态、变化时点（或区间）、触发事件、受影响对象、证据。**制度是本书"利益分配"分析（R11）的载体**——每条制度变化须标注"它重新分配了什么利益"（代码使用权/署名权/商业收益/治理权），标注不出的登记为"机制待析"。
- **输出**：制度变化登记表。
- **执行者**：Historian 主责（制度分析），Researcher 副责（文本版本比对）。
- **质检关卡 G7**：(a) 变化前/后状态均须有文本出处（"历来如此"式表述禁止）；(b) 每个制度变化至少连接 1 个历史对象与 1 个时间轴节点；(c) Skeptic 核对许可证条款引文的逐字准确性。
- **产物与归档**：`S07-制度变化登记.md` + `S07-institutional_changes.json`。

#### 步骤 8：建立争议

- **输入**：步骤 3-7 全部产物；`doubts_standalone.db`（88.6 MB 存疑库，项目既有存疑闭环）；邮件列表中的争论串；既有章节概述中的"存疑"字段（v3 审计：Ch84 存疑 52 条、Ch284 存疑 38 条等）。
- **动作**：把史料间的冲突、解释间的分歧、后世叙述与当时记录的矛盾，逐条登记为争议。每条争议登记：争议命题、甲方立场+证据、乙方立场+证据、各方史料的层级（一手/二手，对接 R9 史料分层）、当前裁决状态（未决/已裁决/不可裁决）、裁决依据。**争议登记是 Skeptic 唯一主责的步骤**——因为争议的本质是怀疑的制度化。
- **输出**：争议登记表（每条争议是第 9 步"历史解释"的候选输入：解释必须回应争议，绕开争议的解释在 G9 打回）。
- **执行者**：Skeptic 主责，Historian 副责（防止 Skeptic 造争议，Historian 有权对"伪争议"提出异议并留痕）。
- **质检关卡 G8**：(a) 每条争议双方都必须有具名证据持有者（"有人认为"式争议禁止）；(b) 与既有存疑库去重对账；(c) Historian 反向抽查：是否存在应登记而未登记的争议（以 v3 审计已发现的口径矛盾为抽样框）。
- **产物与归档**：`S08-争议登记.md` + `S08-disputes.json`。

#### 步骤 9：建立历史解释

- **输入**：问题树（每个待答枝问题）、证据层产物（时间轴/谱系/制度/争议）、史料原文。
- **动作**：对问题树的每个枝问题，由证据**之后**形成解释（P19 的操作化：解释是一手经验登记完成后的产物，不是起点）。每张解释卡片登记：解释命题、它回答的问题树节点、支持证据（指向 S04-S08 的具体条目）、反面证据与处理、相关争议编号、置信度（充分/较强/薄弱/存疑）、替代解释。**禁止**解释卡片先于证据存在；禁止一张卡片不提供任何证据指引。
- **输出**：历史解释卡片库（预计百级；卡片是章节的直接原料——**一章存在的充分理由是它承载一个或一组不可替代的历史解释**）。
- **执行者**：Historian 主责，Skeptic 逐卡审查证据指引的真实性。
- **质检关卡 G9**：(a) 每张卡片 ≥1 条支持证据指引，且指引可解析（指向存在的中间产物条目）；(b) 置信度为"薄弱/存疑"的卡片不销毁，转第四部分缺口系统（标注为"解释待证据"）；(c) Skeptic 抽查 ≥15% 卡片的证据指引实际存在且支持命题。

#### 步骤 10：生成章节结构

- **输入**：历史解释卡片库（**唯一章节原料**）、问题树（组织轴）、时间轴与六期框架（卷级骨架，P44）、对象登记表（章的挂载单位）。
- **动作**：Editor 把解释卡片装配为章节：**章 = 一组回答同一枝问题、围绕同一历史对象簇、共享因果位置的解释卡片**。章的标题必须是事件/对象名而非理论命题名（P19：章节不得以理论命题为标题；P29：以总判断为章题的须拆分为具体事件章节）。卷级骨架沿用六期×分合相位（P14/标准 11），但卷内章序由第三部分的因果图决定，不由日历顺序机械决定。
- **输出**：章节结构（卷-章-节三级 + 每章的解释卡片挂载清单 + 每章的因果图位置）。
- **执行者**：Editor 主责（装配与体例），Historian 副责（解释卡片的完整性），Skeptic 终审。
- **质检关卡 G10**（章节出生时的全套体检）：
  1. 每章 ≥1 张解释卡片，且卡片全部通过 G9（无卡片或卡片未过检的章**不得出生**）；
  2. 每章通过第二部分 Historical Necessity 评分（得分与等级写入章元数据）；
  3. 每章在因果图中有坐标（入边、出边或显式声明为孤点并说明理由）；
  4. 每章标注研究缺口八级分类（第四部分）；
  5. 与既有大纲（19 卷 354 章）逐章做映射登记：保留/合并/拆分/重写/废除，映射表随结构文件归档。
- **产物与归档**：`S10-章节结构.md`（人读）+ `S10-outline.json`（机读：章→卡片→问题→证据的回溯链字段）+ `S10b-新旧大纲映射表.md`。

### 1.6 流水线治理规则

1. **硬依赖**：步骤 N 的产物未通过关卡 GN 之前，步骤 N+1 不得开工。Skeptic 的关卡结论落盘为 `12-大纲生成中间产物/G{N}-关卡记录.md`（通过/不通过/存疑 + 抽样明细）。
2. **迭代回边**：允许且只允许三条回边——第 9 步发现证据缺口 → 回第 4-7 步补登记；第 10 步发现解释不足 → 回第 9 步补卡片；任何步发现原则冲突 → 回第 1 步提请 ykla 裁决（走 01b 裁决记录体例）。禁止跨步跳跃（如第 10 步直接回读原始资料绕过证据层——那等于资料直生链复辟）。
3. **既有大纲的定位**：现存 19 卷 354 章大纲在流水线中是**对照物与映射对象**，不是原料。它只在两处进入流程：第 3 步（对象审计对账，Task #4）、第 10 步（新旧映射）。任何"在现有目录上增删几章"式的产出都不算执行了本算法。
4. **版本冻结**：每步产物定稿即冻结（只读），修订须新开版本号文件（如 `S02-历史问题树_v2.md`）并在修订记录说明动因——为 Phase 23-25 的 A/B/C 三版大纲比较保留干净基线。

## 第二部分 章节存在性评分：Historical Necessity（第二十四阶段）

### 2.1 核心判据

用户任务书第二十四阶段：**每章计算 Historical Necessity——如果删除这一章，全书是否失去一个不可替代的历史解释？如果只是"这一时期发生了很多事情"但删除后核心论证不受影响，则降低优先级。**

形式化为**删除测试**（deletion test）：

> 设章 C 承载解释卡片集合 E(C)。在全书论证图中移除 C（及其卡片），检查：
> (1) 是否存在某个问题树节点，其唯一或最佳回答位于 E(C)？（解释不可替代性）
> (2) 因果图中经过 C 的路径是否断裂，且无法由其余章节的解释补上？（因果链位置）
> (3) 移除后，读者对 BSD 史的认识改变量是否为零？（第 10 问判据，见 04-审计报告标尺：无法回答"本章改变了读者对 BSD 历史的什么认识"的章节高度可能是资料堆积）
>
> 三项全空 → 该章无存在必要性（"发生了很多事情"型章节的原形）；任一非空 → 进入量化评分。

**"发生了很多事情"的操作性识别**（四个症状，命中任一即在评分表中显式扣分并在记录中引证）：

- 章题或概述只有时段+分支名，无事件、无对象转变（如"××时期（1998-2002）的发展"）；
- 章内节目录是编年流水，节与节之间删除任何一节不影响其余节（节间无依赖）；
- 概述无法回答第 10 问（"本章改变读者什么认识"）；
- 章的锚定素材全部是同一时段的同质资料堆（资料堆积，v3 审计的 30% 双零章是其极端形态：连堆都没有）。

### 2.2 评分维度（四维，各 0-10 分）

| 维度 | 代号 | 定义 | 高分形态 | 低分形态 |
| :--- | :--: | :--- | :------- | :------- |
| **问题意识独立性** | Q | 该章是否回答一个其他章不回答的问题树节点 | 独占 ≥1 个枝问题，且该问题在树中非冗余 | 问题是别章问题的复述或时段切片 |
| **史料支撑度** | S | 承载该章的解释卡片背后的证据存量与等级 | 一手史料≥3 条独立来源，解释卡片置信度"充分/较强" | 二手转述、单一来源、或零锚定（对接 v3 基线） |
| **因果链位置** | C | 该章在第三部分因果图中的结构位置 | 是 ≥2 条跨章因果路径的必经节点（桥点） | 孤点或仅悬挂性节点（删之图不断裂） |
| **替代章节可合并性**（反向） | M | 该章被并入邻章后是否损失解释 | 并入任何邻章都会丢失解释或造成章内对象簇异质 | 内容可无缝并入邻章且合并后更紧凑 |

四维度分数的合成：

```
HN(C) = 0.35×Q + 0.25×S + 0.25×C + 0.15×M        （0-10 分制）
```

权重理由：问题意识独立性是"删除测试"第 (1) 项的直接测量，权重最高；史料支撑度落实 R1"单位篇幅证据密度"与 R2"篇幅与史料丰度成比例"；因果链位置落实第二十五阶段；可合并性是纯反向检查，权重最低但具一票降档功能（见 2.4）。

**维度 S 与 v3 审计基线的对接**（这是评分体系必须落的 R1 裁决要求）：

| v3 审计状态（既有章专用，元规则不做实打分） | S 维初判上限 |
| :------------------------------------------ | :----------: |
| 锚定素材=0 且 ref 匹配=0（双零章，~106 章/30%） | ≤ 2 |
| 锚定素材=0 但 ref>0（~57 章） | ≤ 4 |
| 锚定>0 且 ref=0（如 Ch22：锚定 423/ref 0 的不对称） | ≤ 5，且触发"锚定-文献失配"专项核 |
| 锚定>0 且 ref>0 | 按证据等级实评（一手≥3 独立来源可达 8-10） |

说明：47% 锚定=0、52% ref=0 是**现状审计事实**；在元规则中它们转化为 S 维的天花板规则——评分机制由此把"证据密度"从口号变成算术。

| :-----: | :--: | :--- | :--- |

### 2.4 一票降档与否决项

无论合成分多高，命中任一项即**至少降一档**（A→B、B→C，依此类推）：

## 第三部分 章节间因果图：Chapter A → Historical Transformation → Chapter B（第二十五阶段）

### 3.1 设计动机

用户任务书第二十五阶段：**章节不是线性排列，而是 `Chapter A → Historical Transformation → Chapter B`。**

现行大纲的卷级骨架是一条从 1969 到当代的单向时间线（《原则清单》T10 已诊断：卷级时间骨架与"循环替代线性"宣言在形式上矛盾；原文解法是"时间线是呈现循环的载体"）。本部分给出矛盾的技术解：**线性目录保留为导航装置（GitBook 读者界面），因果图作为底层结构装置（章节为什么这样排列、删谁图会断的依据）**。两者并存，各司其职。

### 3.2 数据模型

因果图 G = (N, E)：

**节点 N**（两类）：

| 类型 | 记号 | 定义 | 字段 |
| :--- | :--: | :--- | :--- |
| 章节点 | `CH-{章号}` | 承载历史解释的章 | 章题、解释卡片集、HN 等级、八级缺口分类 |
| 对象点 | `HO-{对象号}` | 跨章存续的历史对象（可选节点，用于长程边） | 对象名、类型、存续时段 |

**边 E**（唯一类型：Historical Transformation，历史转变）：

```
edge = {
  id:            T-{序号},
  from:          CH-a 或 HO-x,        # 转变前的状态承载者
  to:            CH-b 或 HO-y,        # 转变后的状态承载者
  transformation: "一句话命题：X 转变为 Y",
  mechanism:     机制类型（受控词表，见下）,
  evidence:      [S04-S08 条目编号, ...],   # 边上挂证据
  time:          日期/区间/不确定度,
  reversibility: 不可逆 / 部分可逆 / 可逆（循环相位标注，对接 P14 分离聚合）,
  confidence:    充分 / 较强 / 薄弱 / 待证
}
```

**机制受控词表**（mechanism 字段只许以下取值，防止因果图退化为自由联想）：

| 机制代号 | 名称 | 含义 | 本书典型 |
| :------: | :--- | :--- | :------- |
| m1 | 代码传播 | fork/cherry-pick/vendor import 造成的技术转移 | Berkeley 获得 Unix 源码 |
| m2 | 人员流动 | 携带知识与惯例的人的迁移 | CSRG 成员流向各分支 |
| m3 | 制度重构 | 许可证/治理/法律地位变化重设激励 | BSD 许可证改写、USL 和解 |
| m4 | 组织分化 | 一个组织分裂出承担新功能的组织 | 386BSD → FreeBSD/NetBSD |
| m5 | 组织聚合 | 代码共享、标准趋同、人员回流 | 各分支 vendor branch 互哺 |
| m6 | 需求牵引 | 使用场景变化拉动技术重心移动 | 网络研究需求把 TCP/IP 推入核心 |
| m7 | 生态反馈 | 外部采纳改变原项目的地位与约束 | 商业 Unix 吸收 BSD 后 Berkeley 议价地位变化 |
| m8 | 观念迁移 | 术语、哲学、叙事框架的传播 | "自由"话语进入许可证争论 |

**结构规则**：

1. **每条边必须挂机制与证据**——"A 之后 B"不是因果，"A 通过机制 m 使 B"才是；无证据的转变只能标 `confidence=待证` 并自动进入第四部分研究缺口；
2. **禁止目的论边**：边的表述不得含"必然导致""注定""走向成熟"等词（P15 偶然性优先；《原则清单》T2 残余风险条款：必然性词汇只能用于结构层）；
3. **环允许且必须标注**：分离聚合循环（P14）在图上表现为 m4/m5 交替成环——环不是错误，是本书史观的图论形态；每个环标注相位（分离相/聚合相）；
4. **孤点须申报**：无任何入边出边的章节点必须在 G10 关卡提交孤点理由（如"背景卷"），否则视为接线失败。

### 3.4 因果图与线性目录的并存关系

| 装置 | 形态 | 职能 | 读者可见性 |
| :--- | :--- | :--- | :--------- |
| GitBook 线性目录（SUMMARY.md） | 卷→章顺序排列 | 导航、阅读顺序、印刷形态 | 可见（唯一读者界面） |
| 因果图（S10-outline.json 内嵌或独立 `12-大纲生成中间产物/S10c-因果图.json`） | 有向图 | 章序的正当性依据、删除测试载体、断点定位 | 不直接可见，以章末"结构性关联"注记间接呈现 |

并存的三条规则：

1. **线性序是因果图的拓扑排序 + 相位修辞**。章序首先须与因果方向相容（不许把"果"章排在"因"章之前而无注释说明）；在因果图允许的自由度内（无因果约束的章对），按六期时间轴（P44）与分合相位（P14/标准 11）排布。排序冲突时：**时间序让步于因果序，并在卷首概述声明这一偏离**（对接 T10 处理建议：时间骨架是导航装置而非价值方向）。
2. **标准 11 的章末标注升级为图引用**。标准 11 要求"章末标注与后续章节的结构性关联"——本机制将其从自由文本升级为因果图出边引用（`本章出边：T10（m3+m4 → 第×章）`），使线性读者也能看见因果接缝。
3. **因果图是评分与缺口的公共底座**。第二部分 C 维的计算、删除测试第 (2) 项的路径检查、第四部分"边证据缺失"型缺口，全部读取同一张图。图更新（新证据加入、边被推翻）须触发受影响章的 HN 复评——这是"新考据结论触发全书回溯修改义务"（P50）在元规则层的落点。

### 3.5 因果图的质检（并入 G10，单列于此以便执行）

1. 每条边的 mechanism 在受控词表内；每条边 ≥1 条证据指引或标"待证"；
2. 全图无悬挂词：边命题中出现的名词必须能解析到对象登记表条目；
3. 环检测：每个环标注相位与成员边清单（防止无标注环被当成"循环史观"的修辞遮羞布）；
4. 抽样复验：Skeptic 抽 ≥10% 的边，沿证据指引回读原始出处，验证"机制"不是事后编造的连词。

## 第四部分 研究缺口八级分类与 Research Queue（第二十六阶段）

### 4.1 八级分类：精确定义与判定规则

用户任务书第二十六阶段：对每章自动生成八级分类，最后一类自动进入 Research Queue。

**分级对象**：章的解释承载状态（即第 9 步解释卡片 + 其证据指引的证据学处境），不是"资料的物理存在量"。分级回答的问题是："本章的历史解释，其证据处境处于哪一档？"

**判定流程**（每章一次，由 Skeptic 执行，落盘为缺口报告）：按 L1→L8 顺序自上而下扫描，**命中即停**（取最高满足档）：

| 级 | 代号 | 名称 | 精确定义 | 判定规则（全部可机检/半机检） |
| -- | :--: | :--- | :------- | :---------------------------- |
| L1 | FULL | 已充分证明 | 章的每张解释卡片均有 ≥2 条**独立一手来源**支持，来源间无未决冲突，且经三次复查流程（考据规则）闭环 | 一手来源数≥2/卡；冲突登记=0；复查记录完整 |
| L2 | STRONG | 有较强证据但仍存在问题 | 一手来源 ≥1 条/卡，但存在以下之一：孤证关键节点、个别事实仅二手佐证、存疑项未闭环（doubts_standalone 有 open 条目） | 一手≥1/卡；open 存疑>0 或 二手依赖节点≥1 |
| L3 | SECONDARY | 只有二手来源 | 章的解释全部由二手文献承载，无一手史料锚定 | 一手来源=0；二手来源>0。对应 v3 基线：锚定=0 但 ref>0 的章 |
| L4 | SINGLE | 只有单一来源 | 全部解释依赖同一条来源链（同一作者/同一机构/同一份文件），无独立旁证 | 独立来源链数=1。判定"同源"标准：作者同一、或机构同一、或直接引用自同一底本 |
| L5 | CONFLICT | 来源互相冲突 | ≥2 条来源对同一事实给出不可调和的陈述，且冲突未在争议登记表（S08）中获得裁决状态 | S08 中本章关联争议的裁决状态=未决 且 冲突涉及章内核心事实 |
| L6 | RETRO | 只有后来的回忆 | 唯一证据是事后多年的口述/回忆录/访谈，无当时即时记录佐证 | 来源均为回忆类 且 回忆时点距事件 >5 年（阈值可调）；即时记录=0 |
| L7 | NONE | 尚无可靠来源 | 解释存在，但无任何达到最低可信阈值的来源（现有材料或不可溯源、或层级过低、或已被存疑库否定） | 可靠来源=0；解释卡片置信度=存疑 |
| L8 | SEEK | 需要继续寻找一手史料 | 已确认该章解释**需要且可能存在**一手史料，但尚未获得——与 L7 的区别：L7 是"不知可靠来源何在/是否存在"，L8 是"知道要找什么、可能在哪，但还没找到" | L7 条件 + 检索线索非空（见 4.2 线索字段）。**L8 自动进入 Research Queue** |

**分级铁律**：

1. **L3/L4 不自动进队列但自动降优先级**：二手-only 与单一来源章的写作可继续，但章末须标注证据处境（"史料透明"，P37），其 HN 评分 S 维按 2.2 节天花板封顶；
2. **L5 冲突章冻结定稿**：冲突未裁决前该章不得通过 G10——冲突不是缺口，是未完成的考据；
3. **L6 回忆章须双标注**：标注"回忆性质"+ 回忆时点，写作中按偶然性规范处理（回忆的重构性本身是历史对象）；
4. **L8 的入队判定由线索存在性触发**：一条缺口若写不出检索线索，说明它其实是 L7（连找的方向都没有），不得伪装成 L8 刷队列；
5. 分级结果写入章元数据与 HN 评分卡第 4 节回溯链，并与第三部分因果图的边 confidence 联动：`待证`边所指向的章，其分级不得高于 L2。

### 4.2 Research Queue 数据模型

**定义**：Research Queue（研究队列）是 L8 缺口（及被显式升级的 L7 缺口）的工作清单，按优先级排序，供 Researcher 角色消费。它是第一步问题树"不可答叶问题"（G2 关卡）、第五步"待证谱系边"（G5）、第八步"未决争议"（S08）三类上游信号的**统一汇聚点**。

每条队列记录：

```json
{
  "rq_id": "RQ-{卷号}-{序号}",
  "chapter": "第×章（章号+章题）",
  "gap_level": "L8（或 L7-升级）",
  "gap_type": "需一手史料（细分：当事人文件/机构档案/代码记录/邮件记录/法律文本/实物证据）",
  "question": "该缺口对应的具体问题树节点（S02-#{...}）与解释卡片（S09-#{...}）",
  "needed_primary_sources": "所需一手史料的描述：什么材料、由谁产生、大致时段、应包含什么内容",
  "search_clues": [
    "检索线索 1：具体档案馆/邮件列表归档/代码仓库路径/已知的二手文献中的转引出处",
    "检索线索 2：...",
  ],
  "known_secondary": "已知最接近的二手来源（证明该史料可能存在）",
  "priority": "P0/P1/P2",
  "priority_reason": "定级理由（引用 HN 维度：该章 Q/C 分高而 S 分低=值得回填）",
  "status": "open/in_progress/found/closed_unfindable",
  "found_record": "找到后的入库路径（03-原始史料库 路径 / 数据库表+ID）",
  "created_from": "生成来源（G2 叶问题 / G5 待证边 / S08 争议 / HN 评分 / v3 基线映射）",
  "created_at": "ISO 日期",
  "updated_at": "ISO 日期"
}
```

**优先级定级规则**（与第二部分的评分联动，使"回填"资源流向结构价值最高的缺口）：

| 优先级 | 条件 | 含义 |
| :----: | :--- | :--- |
| P0 | 章 HN 的 Q 或 C 维 ≥7 且 S 维 ≤2，或该缺口阻断因果图 ≥2 条路径（桥点章的 L8） | 结构关键章的史料空洞——全书论证图的断点风险，最优先回填 |
| P1 | 章 HN 总分 C 级及以上，缺口为单卡级 | 值得保留章的局部空洞 |
| P2 | D/E 级章的缺口，或背景性、装饰性缺口 | 缓办；若章最终废除，其 P2 条目随之关闭（closed_unfindable 之外的第四种终态：closed_chapter_dropped） |

**状态机**：`open → in_progress → found（回填入库，触发章分级复评与 HN 复评）`；或 `open → closed_unfindable（穷尽线索后正式登记"找不到"——这本身是考据结论，该章分级回落为 L7 并在正文以"信息黑洞"标注呈现，对接 R2 裁决"史料稀少不强行拉长，以信息黑洞标注替代推测填充"）`。
