### 3.6 本章书目述评

**源**：本章书目述评：旧07卷《freebsd的工程体系重构》卷末书目述评——学术论争·争议三（约 5 条/段）

#### 争议三：FreeBSD 安全模型的认证地位——FreeBSD Project 与商业产品的认证边界

争议主题：FreeBSD 安全模型的合规认证地位——FreeBSD Project 本身是否持有 Common Criteria、FIPS 140 等合规证书，抑或证书仅由基于 FreeBSD 的商业产品各自申请；这一认证边界如何影响 FreeBSD 在企业市场的定位。 立场甲（项目持有说）：部分二手来源将 FreeBSD 安全模型的合规认证归功于 FreeBSD Project 本身，主张 FreeBSD 通过了 Common Criteria、FIPS 140 等认证。 立场乙（商业产品持有说）：以 FreeBSD Project 官方文档与 Foundation 年度报告为代表，主张 FreeBSD Project 本身不持有合规证书，证书由基于 FreeBSD 的商业产品（如 pfSense、OPNsense、Junos OS 等）各自申请与维护，FreeBSD Project 提供安全基础设施但非证书持有主体。 史料依据：立场甲主要依据部分二手来源的模糊表述；立场乙主要依据 FreeBSD Project 官方文档与 Foundation 年度报告。两派史料的分歧本质上反映“项目安全基础设施”与“商业产品合规认证”的概念混淆。 史家判断：按 0 信任原则，本卷史家认为 FreeBSD Project 本身不持有合规证书，证书由基于 FreeBSD 的商业产品各自申请。本卷叙事须明确区分 FreeBSD Project 的安全基础设施（Security Advisories、Security Team、MAC 框架）与商业产品的合规认证（Common Criteria、FIPS 140 等），避免将商业产品认证归功于 FreeBSD Project。这一区分的史学意义在于：它揭示了开源项目与商业生态的认证边界，避免叙事中的概念混淆。
