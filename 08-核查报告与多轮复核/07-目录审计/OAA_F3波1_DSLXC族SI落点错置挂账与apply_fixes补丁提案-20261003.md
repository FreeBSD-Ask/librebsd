## 〇、2026-10-04 定因修订（覆盖本文原第二、三、六节）

上一版把缺陷定因为“si 落到纪律尾行、旧摘要原地残留”，并据此提案“按 `summ_line` 精确匹配重定位”。
04:20–04:40 逐键复现 `apply_fixes.main` 的定位顺序后，定因**修正**如下：

**真根因＝搜索窗口 `range(ln, min(ln + 5, len(lines)))` 不设边界，会越过下一个 `<!-- ROW_MINE: -->` 锚点。**
`ln` 指向锚点行（1-based），窗口从锚点的**下一行**起数 5 行；若块体摘要行本身无纪律串，
5 行窗口内最先被 TAIL／ALT_TAIL 或 `summ_line` 命中的往往属于**下一个块**，于是写入落到别的块上。

04:3x 落点分类实测（`_f3_land_audit.json`，2,347 条可写判读）：

| 落点类别 | 条数 | 说明 |
| --- | ---: | --- |
| A_OK | 2,335 | 落在本块内，安全 |
| **B_ANCHOR** | **11** | 兜底命中下一块的 ROW_MINE 锚点行 → 新摘要**覆盖锚点** |
| **C_OUTSIDE** | **1** | 命中越出本块的摘要行 → **跨块误写** |

两类危险全部集中在 **157.6-BSD-许可的人文意义**，该宿主前段（L59–L100）是“摘要行在前、
多锚点连排”的特殊布局：

```
 82 | 2015 年 7 月的 Kernel Summit，David Woodhouse 观察 GPL 执法光谱：…     ← 1756 的摘要（在锚点之前）
 83 | <!-- ROW_MINE: ksummit.messages.1756 -->                              ← 锚点 ln=83
 84 | <!-- ROW_MINE: ksummit.messages.2029 -->                              ← 下一锚点，紧跟
 85 | （空行）
 86 | 2022 年 7 月，这场辩论在 linux-man 邮件列表上达到哲学层面…            ← 属 2029 的摘要
```

- pk=1756：`summ_line`＝L86（2029 的摘要）→ 兜底命中 L86，属**跨块误写**。
- pk=8298645 等 11 条：`summ_line`＝下一块锚点行 → 兜底命中锚点行，属**覆盖锚点**。
- 另 pk=740332 曾命中 L98 `**史料**：linux-mm 邮件列表（…）`，会**整行覆盖节末史料行**
  （本轮因该键另归 B_ANCHOR 族，未走此路径）。

**因此上一版补丁提案不可用**：它“按 `summ_line` 精确匹配重定位”，而本类缺陷里 `summ_line`
本身指的就是错的行（下一块锚点／别块摘要）。照提案打补丁会把错置从“命中尾行”改成
“命中锚点行”，**越改越糟**。

正确补丁见第六节：**把搜索窗口止于下一个 ROW_MINE 锚点行**。

## 二、两类落点错置（并存，机制不同）

**① 窗口越锚（本轮新增定因，12 条）**：窗口越过下一锚点，命中别块的锚点行／摘要行。
见〇节实测。特征：本块摘要行在锚点**之前**，或块体摘要无纪律串且紧邻下一锚点。

**② 块体三段分离（原挂账定因，1,559 条／7 宿主）**：DSLXC 族块体是
“摘要正文行／空行／纪律尾行”三段，摘要正文行不含纪律串，前两趟搜索落到**尾行**，
旧摘要正文原地残留 → 块体出现两个摘要、纪律串重复或被冲掉。

```
205 | <!-- ROW_MINE: linux-man.messages.748100 -->                          ← 锚点 ln
206 | **当事人素材**（来源：dslinux_claims.duckdb claim 库；…）             ← 抬头
207 | （空行）
208 | Colomar 在 groff 1.23.0 讨论串中说明 string_copying(7) 的许可安排…   ← 摘要正文（summ_line）
209 | （空行）
210 | 以上为邮件列表当事人一手自述/主张，属过程性证据…【linux邮件提取】     ← 纪律尾行 ← si 落这里
```

①②的共同点是“定位窗口不受块边界约束”，但落点不同，修法见第六节——一个补丁同时覆盖两类。

## 六、补丁提案（修订版，待裁定）

在独立行锚型的 si 搜索处，**把三趟搜索的窗口统一止于下一个 ROW_MINE 锚点行**。
一个补丁同时覆盖 ① 越锚与 ② 三段分离两类：

```python
            # 块边界：搜索窗口不得越过下一个 ROW_MINE 锚点，否则窗口内的
            # 纪律串／summ_line 可能属于下一块——2026-10-04 F3 波 1 实测 157.6
            # 有 11 条命中下一块锚点行、1 条命中下一块摘要行。
            nxt = len(lines)
            for j in range(ln, len(lines)):
                if lines[j].lstrip().startswith("<!--"):
                    nxt = j
                    break
            hi = min(ln + 5, nxt)
            si = -1
            for j in range(ln, hi):
                if TAIL in lines[j]:
                    si = j
                    break
            if si < 0:
                for j in range(ln, hi):
                    if ALT_TAIL in lines[j]:
                        si = j
                        break
            if si < 0 and (fb.get("summ_line") or "").strip():
                for j in range(ln, hi):
                    if lines[j].strip() and lines[j] == fb["summ_line"]:
                        si = j
                        break
            if si < 0:
                print(f"  ! 摘要行（纪律串）未找到: {key} line {ln}", file=sys.stderr)
                n_err += 1
                continue
            # 落点三方校验：写前必须与 fetch 摘要行原文一致，不一致即报错停机
            if lines[si].strip() != (fb.get("summ_line") or "").strip() and \
                    not (TAIL in lines[si] or ALT_TAIL in lines[si]):
                print(f"  ! 摘要行落点与 fetch summ_line 不一致: {key} line {ln}",
                      file=sys.stderr)
                n_err += 1
                continue
```

**零回归论证**：对落点正确的键，窗口收窄不改变命中结果（A_OK 2,335 条本就在块内），
且新增校验在“落点为纪律串行”时按原语义放行。对 ① 类 12 条，窗口收窄后 si 找不到 → 报错停机，
不写错行。对 ② 类 1,559 条，si 落到摘要正文行、校验通过（或需先做第五节的 65 条改写）。
这是“只会把错误写入变成报错”的收窄型改动，不放宽任何既有门禁。
