我最初把“总长”量到整句，导致 64 条假 FAIL。grep `oaa_verify.py` 第 135 行确认真值：

```python
body = summ.split("引用时按")[0].rstrip("。")
C, L = cjk(body), len(body)      # 总长量的是 body，不是整句！
if C < 30: FAIL "G3 字数不足"
```

`--len-flex` **只放宽上限（80／200 记入备案），不放宽下限**：`C < 30` 恒定 FAIL。

### 六-2 本轮新增教训

1. **门禁口径必须直接 grep 脚本取真值，不可凭记忆**：`L = len(body)` 而非整句，
   `--len-flex` 只放宽上限不放宽下限。
2. **`rstrip("。")` 吞全部尾随句号**：任何“以句号收尾”守卫必须验 rstrip 之前的原串，
   否则守卫自相矛盾、全数假 FAIL。
3. **差分门禁默认参数带 `--` 前缀会静默假绿**：`f.startswith('--bak=.bak-f4b11a')` 永假，
   无参调用时 0 分片、PASS 全绿。第 1 轮脚本已去掉前缀，第 2 轮脚本沿用。
4. **补全波与判读轮判定冲突时以判读件为准**：挂账类（fix-db／remap／存疑）不得借
   “补字数”之名改写正文，须在 apply 侧设硬闸排除，而非事后回退。
5. **`oaa_verify` 退出码 1 时只打 `fails[:30]`**：须整份重定向到文件再统计，
   否则尾部 FAIL 被吞。
6. **浮标的“已”是跨线合并台账口径**：F4 已 62,385 ≠ 本线 `processed_f4.jsonl` 55,022
   （`merged_done()` 合并 `processed.jsonl` ∪ `processed_f1..f4.jsonl`，
   他会话台账里也含 F4 宿主锚点）。
7. **浮标锚点总数 420,464 比 `oaa_verify` 的 420,470 少 6**：系批次十一已记录的
   锚点正则盲区（`SRC-rowmine:<lib>` 冒号形态库名不被 `[\\w-]` 匹配），非本批引入。
8. **浮标 F4 “较上次 −2,874”系他会话并章注销所致**：`e061d48fb`（1d-3 T10-ch9 并章去重，
   6 节注销＋3 节并入）与 `ac7abc294`（C24 拆两章）会移动／删除 F4 范围内宿主锚点，
   使已处理计数下降；本批只增锚点（4,036 登记）未删任何锚点。
9. **UNC 上 `ls`／`os.listdir` 列表结果不可信**：判丢失一律按精确路径 `stat`／`os.path.isfile`
