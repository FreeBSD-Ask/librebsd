## 二、本批最重要的一件事：门禁正则的两个假阳性族与交叉式结构判定

本批 532 条 FAIL 全部出自同一条门禁规则（`oaa_verify.py:131` 的 G3 inline 禁字符），
而**不是**正文真的违规。判据来自 `is_bad_star()` 的正则：

```python
STAR_PAIR = (?<!/)\*([^*\s/]{1,16})\*(?!\w)
```

它把所有 `*短词*` 一律判为“禁用强调符”。但本宿主语料里，短词星号绝大多数是
**相邻两枚 Markdown 粗体的接缝**：

```
**A 有空格的长粗体**；直接负责项目：**"每年确保 Plumbers 有规划委员会"**
                ^                              ^
                前一对闭合标记的第 2 字符        下一对开启标记的第 1 字符
```

正则从这里抓出 `*；直接负责项目：*` 之外的更短匹配——两个星号被当作一对短词强调。
全语料实测（`_f4b13_juncprobe.py`，575 行命中 STAR_PAIR）分布为：

| 类别 | 条数 | 处置 |
| --- | --- | --- |
| A 真短词强调（`*不是*`／`*反对*`／`*永远*`／`*知深浅去找对的人*`…） | 96 | 剥星 |
| B 跨对强调 | 2 | 剥星 |
| C 粗体接缝（相邻两枚 `**` 之间） | 1,040 | **保留** |
| D 通配星间隔（`*BSD`、`comp.unix.*`、`multi_x*_defconfig`）／粗体内含标点（正则量词 `*`） | 34 ＋ 43 | **保留** |

**唯一能分开“接缝”与“短词强调”的是结构位置**，不是邻接关系、不是配对奇偶。
终态判据（`_f4b13_apply.py:violation_stars`）：STAR_PAIR 命中判违规当且仅当

1. **内文匹配 `PLAUSIBLE = ^\w[\w'\u2019-]*$`**（纯字母／CJK／数字／下划线／连字符／撇号，
   不含任何标点）——含标点的内文只可能是通配星间隔或粗体内的正则量词，不可能是被强调的词；
2. **且非跨对接缝**——“接缝”＝ 起星落在**某对**的**闭合**标记（其第 2 个字符）、
   终星落在**另一对**的**开启**标记（其第 1 个字符）。

`**exclusive**` 的命中起星是**同一对**开启标记的第 2 字符，不构成跨对，故判真强调、剥星。
48 项单测（`_f4b13_normtest3.py`）**48/48 PASS**，其中 T22 用真实语料最小复现出接缝，
T16 覆盖“粗体内部的真短词强调”，T18 断言 `**exclusive**` 失星而正则量词星号存活。

### 三-2 ⚠ 本批的 EOL 陷阱（第一次撞上“两宿主 EOL 不同”）

170 备份原件是**整文件 CRLF**（3,141 处），171 是**纯 LF**。G6 门禁要求现盘 LF-only，
故 apply 把 170 归一为 LF。后果是：

- 若逐字比对备份与现盘，170 会**全量假变更**（3,138 行全部“不同”）。
- `.gitattributes` 已声明 `*.md text eol=lf`，故 CRLF→LF 在 git 侧**不产生 diff**——
  git numstat 只显示真变更 394 行，与门禁的 394 完全一致。这是本次能靠 numstat
  独立交叉验证门禁结果的前提；若 `.gitattributes` 未声明，numstat 会报 3,138 行。
- 两宿主现盘 EOL 不同（170 由 CRLF 归一为 LF、171 本为 LF）本身**不构成违规**——
  门禁只禁**文件内混合**，不禁**文件间不同**。
- 差分门禁两侧统一按剥 `\r` 归一再拆行（`to_lines`），并单独断言现盘字节层
  无 CRLF、无裸 CR，双保险。

### 三-3 分隔符两形态与切片 off-by-one（第三次踩）

inline 块的分隔符有两种：`- 【Linux社区】<叙述> <!--ROW_MINE:...-->`（**无空格**）
与 `- 【Linux社区】<叙述> <!--ROW_MINE:...-->`（**带空格**）。剥前缀后取正文必须先取
`sep = body[len(body.rstrip(" \t")):]` 再 `body[:len(body)-len(sep)]`。

写成 `body[:len(body) - len(body.rstrip(" \t"))]` 会得到**尾随空格个数**而不是正文长度，
于是 `body[:2]` 只留两个字符。本批两次踩中：

- 首轮差分门禁脚本（`_f4b13_diff42.py`）踩中一次，产出 792 条假 no-op（真值 42/38）；
- §四 的 532 取证脚本初版又踩中一次，532 条全部落入“其他”桶、断言炸掉。

`_f4b13_apply.py` 与 `_f4b13_diffgate3.py` 从头就用的正确 `sep` 形态。

### 三-4 ⚠ `oaa_verify` 只打印 `fails[:30]`，无法从 stdout 取证
