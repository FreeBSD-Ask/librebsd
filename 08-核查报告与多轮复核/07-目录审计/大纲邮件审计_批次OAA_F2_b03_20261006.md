## 五、事件与教训（供后续批次沿用）

1. **fetch 档案命名不一致导致 G4 覆盖率 0%**：`oaa_verify` 的 glob 只认 `work/*.fetch.jsonl`，本批档案名是 `work/f2_b03_all.jsonl`，导致等级真值档案匹配 0 行、G4 对本批覆盖率 **0.00%**——即 G4 名义上通过实为空跑。**已复制为 `work/179.1-…vfs.fetch.jsonl`（27,032,752 B 字节一致），G4 恢复对 8,507 块全覆盖。**教训：fetch 档案命名是门禁有效性的前提，不是形式主义。
2. **remap 判定会把块内归属缺陷永久掩埋**：64 条 remap 中 8 条实为块内归属倒挂。留作 remap 的后果是双重错误——摘要缺陷永不修，且分流到错误的队列（X2 处理章节归属，不碰摘要文本）。**判定六类中“remap”只应指章节级错挂；块内归属倒挂一律 fix-text。**已写入 `_f2_b03_RULES.md` 铁律 4 并在本批全量扫描关键词复查。
3. **子代理伪报第六次坐实**：批 02（s059/s072）8 条字数下限指控中 7 条为误报，s156 片 20 条**全为误报**（实测 CJK 全在 30–54）。**独立重算后才派单，不采信回报。**
4. **`_f2_b03_apply_outline.py` 不带 `--dry` 即真落地**：曾以为在干跑，实际已写入。以 `git diff --numstat` 交叉核对（2143 → 2178 → 2184）确认实际落地量与干跑自报一致，非数据事故，但记为坑。
5. **UNC 上对含中文目录的子进程 spawn 会假阴**：`subprocess.run([python, ".../01-规则/脚本与命令/oaa_register.py"])` 报 `No such file or directory`，而同目录 `os.listdir`／`os.path.getsize` 均正常。**改为 `importlib.util.spec_from_file_location` 进程内加载执行**即通过。与 `ls`／`find` 假阴同族。
6. **UNC stat 缓存是间歇性故障**：同一绝对路径 `os.path.getsize` 先失败、随后成功；`oaa_register.py` 报 2,477 B 而 `Read` 工具读到的内容一致。**判文件丢失前必须按精确路径交叉验盘，不得据单次失败定论。**
7. **`%TEMP%\struct.py` 遮蔽 stdlib**：凡在 `%TEMP%` 下启动的 python 命令一律加 `PYTHONSAFEPATH=1`，否则触发 `{` 未闭合的 `SyntaxError`。
8. **浮标耗时估算是错的**：b02 报告据“全树重扫并读两遍”估 75 分钟、并因三次超时把浮标判为长期未闭环。本批实测 **0.9 分钟**即完成——`outline_scan_snapshot.json`（168 MB）提供增量缓存，b02 的三次失败另有原因（详见 b02 §七 的退出码与超时记录），**不应据此估算的时长决定“是否值得跑”**。
9. **校验脚本自身造象**：本批自建统计脚本先后两次错（①用片号当行号导致行数只算 370；②宿主摘要对账键用了 `db|pk` 而判读件 key 是 `db|pk|host`，致 2,574 条全报“锚缺”）。**统计数字必须经第二个独立算法交叉核对后才可写入报告。**
