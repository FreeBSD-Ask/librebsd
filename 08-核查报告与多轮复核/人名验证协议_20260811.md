# 人名逐个复核联网验证协议

## 任务

对一批 BSD 史人名逐个联网复核，产出结构化验证结果 JSON。本书为约 300-400 万字的科学技术史学术专著《给我自由——一部 BSD 史》。

## 输入

读取 `d:\librebsd\script\_person_verify_workorders\<批次>.json`，为数组，每个元素含：

- `person_id`：主键
- `person_name`：slug 标识
- `name_en`：当前英文全名
- `name_zh`：当前中文译名（可能为 null 或空）
- `priority`：P0/P1/P2
- `role`：身份/角色描述

## 复核内容（对每个人逐个执行）

### 1. name_en 拼写核查

- 确认全名拼写：含中间名、姓/名顺序、连字符、重音符号（如 Özalp Babaoğlu、Garrett D'Amore）。
- 以权威来源交叉验证：本人主页、官方讣告、NAS/ACM 悼文、学术档案（如 dblp、大学官网）、权威机构页面。
- 发现拼写错误则改正并记 `name_en_changed: true`。

### 2. name_zh 译名核查

仅在存在“正式中文出版物 / 权威中文来源”依据时填入译名。可信来源优先级（从高到低）：

1. book.bsdcn.org
2. 正式中文出版物（书籍、译著）
3. 中央级权威媒体（人民日报 / 新华社 / 央视 / 光明日报）
4. 本人中文自署（GitHub / 博客 / 演讲）
5. 高校官方报道

**铁律**：

- 中国籍 / 台湾籍开发者：中文名是原始姓名（非音译），须以本人自署或可信来源为据，不可凭音译推测。
- 无依据者：`name_zh` 保持 `null`，并在 `doubt_flags` 记录 `{"field":"name_zh","doubt":"无正式出版物译名依据，保持英文原名","status":"open"}`。
- 严禁采用维基百科、百度百科、CSDN、普通博客作为证据源（仅可作检索线索，不可作依据）。

### 3. 0 信任原则 + 三次复查

- 一手来源不豁免，须与其他独立来源交叉验证。
- 所有结论必须基于真实 WebSearch / WebFetch 结果，严禁基于模型记忆臆造核查结论。
- sources 的 `url` 必须是真实检索所得 URL，严禁编造。

## 输出

写入 `d:\librebsd\script\_person_verify_results\<批次>.json`（UTF-8 无 BOM，LF 换行）。结构为数组，每个元素：

```json
{
  "person_id": "原 person_id",
  "name_en": "核实后的完整英文名",
  "name_en_changed": false,
  "name_zh": "核实后的中文名（无依据则为 null）",
  "name_zh_changed": false,
  "name_zh_basis": "译名依据 URL 或 null",
  "doubt_flags": [{"field": "name_zh", "doubt": "……", "status": "open"}],
  "sources": [{"type": "一手", "ref": "来源描述", "url": "真实URL", "checked": "2026-08-14"}]
}
```

## 纪律

- 逐个处理，不跳人。
- 不修改任何数据库或源文件，只产出结果 JSON。
- `name_en`/`name_zh` 无变化时，对应 `*_changed` 为 `false`，但仍须记录 `sources`。
- 若发现同批内有重复人物（同一人两条记录），在结果中照常产出，并在最后追加一条说明。
