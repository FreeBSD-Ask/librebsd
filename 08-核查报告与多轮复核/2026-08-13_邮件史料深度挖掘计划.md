# BSD 邮件列表史料深度挖掘计划（不计成本版）

> 版本：v1.0 ｜ 制定日期：2026-08-13 ｜ 定位：规划文档（待主理人批准后执行）
> 目标：从 6 库 261 万封 BSD 邮件列表中，系统性、语义级、全量地挖掘有价值历史信息，补充到大纲 19 卷 355 章要点，并落库史学主张库（五层隔离）。

---

## 一、计划定位与总体目标

### 1.1 问题背景

第一阶段挖掘（2026-08-13 已完成）采用的路径是：

```
章节标题 → 提取关键词 → FTS5 命中统计 → top 邮件列表 → 写回概述.md
```

这属于**浅层命中**，存在四个根本局限：

| 局限 | 表现 | 后果 |
|------|------|------|
| 关键词覆盖不全 | 依赖标题英文词 + 手写 KW_EXPAND（仅 48 章有扩展词） | 195 章无精确词命中 |
| 宽泛词淹没 | freebsd/ports/network 等命中数十万，无区分度 | 精确词被噪声淹没 |
| 无语义提炼 | 只列"命中邮件标题+作者"，未提炼**这封邮件证明了什么史实** | 编纂时仍要人工重读 |
| 未对接史学主张库 | 产出是零散 MD 块，未落库 32 表五层隔离 | 无法做证据链/一致性/反偏见审计 |

**本计划的核心升级**：从"关键词命中"升级为"**证据抽取 → 主张提炼 → 五层落库 → 反哺大纲**"的语义级深度挖掘。

### 1.2 总体目标（不计成本 = 追求最高覆盖度 + 最深提炼）

1. **全量覆盖**：261 万封邮件全部纳入挖掘范围，不抽样、不跳过；
2. **语义级提炼**：把邮件从"原始文本"提炼为**原子历史主张（claim）+ 证据（evidence）**；
3. **五层落库**：全部产出落库到 `historical_claims.db`（32 表 + 8 视图，五层隔离）；
4. **反哺大纲**：355 章每章的要点都能追溯到具体邮件证据，形成"主张→证据→原始史料"完整链条；
5. **可审计**：一致性规则 T1-T5/N1-N6、措辞门禁、反偏见审查全部可机器执行。

## 三、挖掘方法论：六层模型

从浅到深，每层产出不同粒度的史学资产：

```
L0 基础设施   —— FTS5 全文索引（✅ 已完成）
L1 主题定位   —— 关键词命中 + 讨论串聚类（第一阶段部分完成）
L2 证据抽取   —— 邮件 → 可引用的"引句+事实"（evidence）
L3 主张提炼   —— 证据 → 原子历史主张（claim，含影响/起源/动机/争议）
L4 实体图谱   —— 邮件 → 人物/机构/项目节点 + 关系（entity/relation）
L5 解释叙事   —— 主张 → 解释框架 → 大纲叙事单元（interpretation/narrative）
```

**不计成本原则**：L2-L5 对 261 万封邮件**全量执行**，其中 L2/L3 由 LLM 语义提炼辅助，L4/L5 由规则 + LLM 结合。

## 四、分阶段执行计划（P0-P10）

### P0 基线审计与工程准备

**目标**：确认所有资产可读、建库、建索引基线。

| 任务 | 技术路径 | 产出 | 验收 |
|------|---------|------|------|
| 建 `historical_claims.db` | 执行 06a DDL（先备份原则） | 32 表 + 8 视图 | 建库成功 |
| 邮件坐标登记 | 6 库 `messages` → `raw_source`(namespace='mail') | SRC-mail 注册表 | 261 万行 |
| 邮件内容哈希 | msg_hash → content_hash | 防漂移哈希 | 全量 |
| FTS 中文预处理 | 标题/主题中文词素切分到附加列 | 中文可检索 | 抽查 |

**资源**：建库秒级；坐标登记 261 万行约数分钟。

### P1 讨论串与线索重建（thread graph）

**目标**：把 261 万封散信重建为讨论串（thread），恢复"谁回应谁、话题如何演变"。

| 任务 | 技术路径 | 产出 |
|------|---------|------|
| thread 聚类 | 用 `in_reply_to / thread_refs / subject` 归一化建图（union-find） | 每库 thread 数、thread 树 |
| 话题标注 | 每 thread 根消息 subject + 关键词 | thread→topic 映射 |
| 关键串识别 | 长串（>20 封）/核心人物串/跨年串 标记 | key_thread 清单 |

**产出**：`thread` 表（追加到史学主张库或独立表），thread 内证据共现（同一讨论串的多封邮件可互证）。

**资源**：纯本地图算法，261 万节点秒级～分钟级。

### P2 人物共现网络与实体消歧

**目标**：从 `from_email / from_name` 提取人物实体，与 `person_records` 对齐，构建"谁与谁讨论过什么"。

| 任务 | 技术路径 | 产出 |
|------|---------|------|
| 发件人聚合 | from_email 归一化（大小写/域名别名）→ 人物候选 | 发件人→邮件数/时间跨度 |
| 实体对齐 | 候选 与 person_records(1141)/person_bio_research(158) 对齐 | entity(person) 落库 |
| 共现网络 | 同 thread 内人物共现 → entity_relation(discussed/worked_on) | 人物网络图 |
| 高价值人物 | 核心开发者/领袖（P0/P1 级）优先精研 | 重点人物清单 |

**产出**：`entity`(person/org/project) + `entity_relation` + `evidence_entity`（邮件证据→实体关联）。

### P3 术语史与概念史挖掘

**目标**：利用 `terminology_index`(237 词) 追踪关键术语在邮件中的首次出现与语义演变。

| 任务 | 技术路径 | 产出 |
|------|---------|------|
| 术语首现 | FTS 检索每个术语的最早命中邮件 | 术语→首现时间/邮件 |
| 术语演变 | 术语按年份频率分布 → 概念转折点 | concept_history 增补 |
| 时代性校验 | 触发 T4 规则（术语不得早于登记首现时间） | 一致性检查输入 |

### P4 核心史实与主张提炼（LLM 语义级）★核心

**目标**：把邮件从文本提炼为原子历史主张。这是"不计成本"投入最大的阶段。

**技术路径**：分卷分章批处理。对每章，用其关键词 + 讨论串 + 人物从对应库定向抽取候选邮件（不再是全库命中，而是 thread/人物 引导的精准抽取），再对候选邮件做 LLM 提炼。

| 任务 | 技术路径 | 产出 | 规模估算 |
|------|---------|------|---------|
| 候选邮件定向抽取 | 卷→库映射 + 章关键词 + 人物 + 时间窗 | 每章候选集（约 100-1000 封） | 355 章 |
| LLM 证据抽取 | 邮件 → quote(引句) + fact_text(规范化事实) + evidence_kind | `evidence` 落库 | 逐封 |
| LLM 主张提炼 | 多证据 → 原子 claim（FACT/CAUSAL/ORIGIN/FIRST_APPEARANCE/MOTIVATION/INFLUENCE） | `claim` 落库 | 逐章 |
| 证据等级标注 | 按措辞门禁表（L1-L5）自动判级 | evidence_level + wording_gate | 逐条 |
| 主张-证据挂接 | claim_evidence（supporting/contradicting） | 关联表 | 逐条 |

**不计成本量化**：若对 261 万封全量 LLM 提炼（每封 ~1500 token 输出），约 39 亿 token。分级策略：
- **P0/P1 核心邮件**（关键人物、关键 thread、关键术语、争议串）→ 逐封精提炼；
- **一般邮件** → 批量提炼（每封产出 1-3 条 fact）；
- **纯噪音邮件**（自动回复、订阅确认、签名变更）→ 规则过滤跳过。

**产出**：`evidence`（目标 50-100 万条）+ `claim`（目标 3-5 万条）+ `claim_evidence` 关联。

### P5 争议挖掘

**目标**：识别历史争议（fork 动机、许可证存废、技术路线之争），落库 `controversy`。

| 任务 | 技术路径 | 产出 |
|------|---------|------|
| 争议事件清单 | 从大纲争议点 + 关键词（fork/motive/dispute/license）定位 | 争议候选 |
| 立场抽取 | 争议串内对立观点 → controversy_position | 立场 A/B/C |
| 主张化 | 各立场 → claim（CONTROVERSY 类型） | 争议主张 |
| 跨卷一致 | 触发 N6（动机一致性）审计 | 一致性检查 |

### P6 时间线与事件重建

**目标**：从邮件时间戳重建 BSD 史关键事件时间线。

| 任务 | 技术路径 | 产出 |
|------|---------|------|
| timeline_event | evidence_kind='timeline_event' 的邮件 → 事件 | 事件时间线 |
| 事件与章节对齐 | 事件 → source_chapter(vol/ch/sec) | 史料×章节 |
| 日期冲突检测 | 触发 N3（日期唯一性） | 一致性检查 |

### P7 反偏见与多源互证审查

**目标**：执行一致性规则 + 反偏见审查，保证史学严谨性。

| 任务 | 技术路径 | 产出 |
|------|---------|------|
| 一致性检查 | 执行 T1-T5/N1-N6 审计 SQL → consistency_check | 冲突清单 |
| 多源互证 | source_independence（independent/repost/conflict） | 独立性标注 |
| 反偏见 | 10-反偏见审查矩阵对照 | 叙事对照 |
| 冲突处置 | block 级冲突 → 裁决或并存标注 | resolution |

### P8 五层隔离审计

**目标**：验证五层引用合法性。

- L5 禁直引 L1（narrative_citation 不含 raw_source）——视图 v_layer_violation；
- 无证据主张清零（v_claim_unsupported）；
- 禁用来源清零（v_banned_source）；
- 悬空引用清零（v_dangling_ref）。

### P9 反哺大纲写回

**目标**：把提炼后的结构化主张，取代第一阶段浅层 MD 块，写回 355 章概述.md。

**写回格式**（每章）：

```markdown
<!-- MAIL_CLAIM v20260813 -->
## 邮件史料证据索引（自动挖掘）

### 关键主张
- **CL-5-001**：{原子主张} [L4证据] {邮件证据引用}
- ...

### 支撑证据
- EV-000001：{引句} ← [2003-05] {from} {thread 链接}

### 争议/存疑
- controversy：{标题}（立场 A/B）
<!-- /MAIL_CLAIM -->
```

**验收**：355 章全部写回，每章主张可追溯到 evidence → raw_source → 邮件。

## 七、质量保障与验收标准

1. **证据可溯源**：每条 claim 必须 ≥1 条 supporting evidence，每条 evidence 必须指向 raw_source（邮件坐标）；
2. **措辞门禁**：claim 措辞与 evidence_level 匹配（L2 不得用"继承/影响"）；
3. **五层隔离**：narrative 不直引 raw_source；
4. **一致性零 block**：T1-T5/N1-N6 的 block 级冲突全部处置；
5. **反偏见**：争议事件双立场并陈，不单采一说；
6. **抽查**：每阶段产出人工抽查 ≥5%，LLM 提炼结果逐条带 `extracted_by='llm:<model>'` 留痕，可回溯。


## 十、决策点（2026-08-13 主理人已批准）

主理人指令：“**最大化成本，最大化质量。进行一定预处理后（如去重）逐个精炼边挖边复核边落库。对于邮件列表数据库**”。3 项决策已锁定如下：

1. **LLM 提炼引擎** → **本 agent 语义提炼**（规则预处理做机械抽取/去重/候选定向，agent 负责语义级 evidence/claim 提炼与复核），每条产出带 `extracted_by='llm:agent'` 留痕。
2. **P4 覆盖粒度** → **全量精提炼**（最大化质量：不抽样、不跳章；逐章逐个候选邮件精炼，噪音邮件由规则前置过滤后仍保留 raw_source 登记）。
3. **落库时机** → **边挖边复核边落库**（增量落库：每完成一章候选邮件的“挖→复核→提炼→落库”循环即提交，可随时审计）。
4. **新增预处理（去重）**：进入精炼循环前，先对邮件库执行消息级去重核验 + `msg_hash` 跨列表/跨库去重登记（repost 标注），确保不产生重复 evidence/claim。

**执行口径**：`historical_claims.db` 已建成（33 表 + 9 视图，L1-L5 五层隔离）。当前基线：raw_source 28,662（mail 仅 304，需补 261 万）、evidence 33,966（规则 key_facts 为主）、claim 0（P4 未启动）。按 P0（去重+全量登记）→ P1/P2/P3（thread/人物/术语）→ P4（主张提炼★）→ … → P10 顺序执行，本阶段从第一卷第一章起逐个精炼。
