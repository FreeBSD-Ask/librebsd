## 审阅基准条目

### 条目1：经济斩杀线呈现

**规范名称**：经济斩杀线的四维微观呈现

**sacred 源材料出处**：

- `02-sacred源材料/05-经济哲学与补充哲学.md` 第58-64行（第一定律）：
  > "棺材房，北上广，手动挡，手动量程。"
  >
  > "此定律以极度压缩的形式揭示了经济哲学的核心洞见：资源的稀缺性在最基本的生存层面（住房、交通、劳动工具）上被形式主义化了。'棺材房'指代极端压缩的居住空间——不是因为没有土地，而是因为土地被形式主义化为商品、投资品和身份符号。'北上广'指代资源的空间集中——人们不是因为喜欢拥挤而聚集，而是因为资源被形式主义化为'机会'并集中在少数城市。'手动挡'和'手动量程'指代劳动工具的形式主义化——工具不是为人服务的，而是反过来要求人适应工具。"
  >
  > "这四个词的并置构成了一种'经济斩杀线'的微观呈现：个体在每一个生存维度上都被形式主义化的经济系统所约束——住房、地理位置、交通工具、劳动工具——这些都不是自由选择，而是结构性约束。自由意志在市场面前只是一种浅显的幻觉。"

- `02-sacred源材料/shigang.md` 第454行（经济哲学第一定律）：
  > "此定律以极度压缩的形式揭示了经济斩杀线的微观呈现：住房（棺材房）、地理位置（北上广）、交通工具（手动挡）、劳动工具（手动量程）——每一个生存维度都被形式主义化为结构性约束。个体在这些维度上没有自由选择——自由意志在市场面前只是一种浅显的幻觉。"

**判定标准**：

- **违规情形**：大纲在涉及开源社区资源分配、开发者生存状况、项目资金等议题时，将资源分配描述为"个人选择""自由竞争""市场自然调节"的结果，而未揭示其背后的结构性约束。具体表现为：
  - 仅描述个体选择（如"开发者选择全职投入开源项目"），不追问选择背后的资源约束
  - 将 BSD 项目的边缘化地位归因于"技术选择"或"社区偏好"，不分析资源集中与路径依赖的结构性原因
  - 以"优绩主义"（meritocracy）框架解释资源分配，不追问"绩"由谁定义、分配逻辑由谁设定
  - 将资源稀缺呈现为"自然的"而非制度性建构的

- **合规情形**：大纲在涉及资源分配议题时，至少揭示以下四维中的一维或多维结构性约束：
  - **住房/居住维度**：开发者的物理生存条件（收入、住房、基本生活保障）如何约束其参与开源的能力
  - **地理位置维度**：资源（资金、会议、就业机会）的空间集中如何塑造 BSD 社区的参与结构
  - **交通工具/劳动工具维度**：硬件获取、网络接入、编译环境等物质条件如何构成事实上的参与门槛
  - **劳动工具维度**：版本控制系统、构建基础设施、测试框架等工具的形式主义化如何反过来要求开发者适应工具，而非工具适应开发者

**违规示例**：

```markdown
## 要点
FreeBSD 社区的核心开发者大多选择全职投入开源项目，这体现了开源精神中的奉献与自由选择。
```

> 违规原因：将"全职投入开源项目"描述为"自由选择"而非结构性约束下的有限选择，未揭示开发者面临的经济斩杀线。

```markdown
## 辨析
NetBSD 的市场份额较小，主要是因为其技术路线过于保守，未能跟上现代操作系统的演进节奏。
```

> 违规原因：将资源分配的边缘化结果归因于"技术路线"而非结构性因素（资源集中、路径依赖），属于"技术决定论"的形式主义还原。

**合规示例**：

```markdown
## 要点
OpenBSD 项目在早期阶段曾因欠缴电费面临关停——开源项目的基础设施运行成本构成了最基本的经济斩杀线。开发者并非因"选择"参与开源而贫困，而是因为参与开源本身就是一种在斩杀线边缘的生存实践。
```

```markdown
## 辨析
FreeBSD 基金会作为 501(c)(3) 非营利机构的资金来源——Netflix、Juniper 等企业捐赠——并非单纯的"公益支持"，而是企业以捐赠形式进行的利益分配。捐赠者获得影响力和技术路线的话语权，而社区贡献者中的大多数仍然处于斩杀线以下——这不是个人选择问题，而是结构性分配问题。
```

- `02-sacred源材料/shigang.md` 第438行（总纲11引用）：
  > "斩杀线是一种市场化资源分配标准：一旦个体或群体无法满足既定标准，便不会获得有效的资源分配。问题并不在于制度标签，而在于具体的分配逻辑。"

**判定标准**：

- **违规情形**：大纲在涉及商业公司与 BSD 许可证的关系、企业行为、商业模式等议题时，仅作道德评判（如"商业公司剥削开源社区""GPL 比 BSD 更道德""企业应该回馈社区"），而未揭示商业公司"取而不回"的结构性特征。具体表现为：
  - 以"道德/不道德"框架评判商业公司的行为，而非分析其行为的结构性必然性
  - 将 BSD 许可证的"被利用"归因于"许可证设计缺陷"而忽略商品形式主义的运作逻辑
  - 将商业公司描述为"盗取社区成果"的道德主体，而非形式主义经济系统内的理性参与者
  - 以"企业应该回馈"的规范性呼吁替代对"为何不回馈"的结构性分析

- **合规情形**：大纲在涉及商业公司与 BSD 的关系时，揭示以下结构性特征：
  - 商业公司对 BSD 代码的"取用"是商品形式主义运作的必然结果——不是道德问题，而是系统逻辑
  - BSD 许可证的"自由"本身就是形式主义——形式上的自由导致了事实上的不自由（贡献者无法获得回馈）
  - 商品文化对消费者的"召唤"不仅是商业营销，更是整个开源生态的运作方式——各公司不是"决定"是否回馈，而是被商品形式主义所"决定"
  - 对商业行为的分析须超越"道德谴责"与"道德辩护"的二元对立，揭示其形式主义本质

**违规示例**：

```markdown
## 辨析
苹果公司利用 BSD 代码构建 macOS 却不回馈社区，这是一种典型的技术剥削，体现了大公司对开源精神的背叛。
```

> 违规原因：仅作道德谴责（"剥削""背叛"），未分析苹果公司"取而不回"的结构性原因——在商品形式主义逻辑下，商业公司的"取而不回"不是道德缺陷，而是系统运作的必然结果。BSD 许可证允许"取而不回"恰恰是其形式主义本质的体现。

```markdown
## 史观
映射总纲3（不存在进步，只有权力再分配）：商业公司控制开源项目是对社区权力的篡夺。
```

> 违规原因：将商业公司与社区的关系简化为"篡夺"的道德叙事，未揭示"权力的篡夺"本身就是商品形式主义运作的正常形式——不是例外，而是常态。

**合规示例**：

```markdown
## 辨析
BSD 许可证的"自由"本身构成了一种形式主义悖论：它赋予了商业公司最大的形式自由——可以取用代码而不回馈——但正是这种形式上的自由导致了贡献者事实上的不自由。商业公司对 BSD 代码的"取用"不是在"选择"是否回馈，而是在遵循商品形式主义的运作逻辑。GPL 通过形式限制自由反而保护了生态——两者都是利益分配的形式主义方案，不存在谁"更道德"的问题。
```

```markdown
## 史观
映射总纲11（商品是形式主义）：macOS 对 BSD 代码的"取用"揭示的不是苹果公司的道德问题，而是商品形式主义运作的必然结果——不是人们在追求商品，而是商品在召唤人们。苹果塑造的不是某种操作系统，而是一种文化——FreeBSD 代码被纳入这种文化召唤，不是被"盗取"，而是被商品形式主义所"吸收"。
```

### 条目3："忙碌"的形式主义批判

**规范名称**：贡献者无偿劳动的结构性原因揭示

**sacred 源材料出处**：

- `02-sacred源材料/05-经济哲学与补充哲学.md` 第70-78行（第二定律/特朗普第一定律）：
  > "特朗普定律：当一个人钱没有特朗普多，或者官职没有特朗普大的时候。那么他必定不会忙，必定是在一个地方水，无论是线上/线下的地方。当 A 钱没有特朗普多，或官职没有特朗普大的时候，他不可能处于忙碌状态，必定在一个地方野，无论如何，称不上忙，或者没有时间，他肯定在 B 处浪费时间。"
  >
  > "此定律以特朗普为参照系，揭示了'忙碌'的社会建构性质。'忙碌'在现代社会中被形式主义化为一种身份标识——'我很忙'意味着'我很重要''我被需要''我有价值'。但特朗普定律指出：除非一个人的财富或权力达到了特朗普的量级，否则他的'忙碌'不过是一种形式主义化的自我欺骗。"
  >
  > "深层含义是：大多数人的'忙碌'不是因为客观上需要处理的事务太多，而是因为他们在形式主义化的社会结构中被迫'表演'忙碌——这种表演本身就是形式主义。真正的权力和财富持有者不需要'表演'忙碌——他们的存在本身就是价值的确证。而普通人则通过'忙碌'来证明自己的存在价值。"
  >
  > "'他肯定在 B 处浪费时间'——这一判断不是道德谴责，而是结构分析：在形式主义化的经济系统中，大多数人的时间被分配到了低效的、重复的、形式主义化的事务上。这不是因为他们懒惰或无能，而是因为系统的结构决定了大多数人只能在'B 处'——即非核心、非创造性、非自主的位置上——消耗时间。"

- `02-sacred源材料/shigang.md` 第456-457行（经济哲学第二定律）：
  > "'忙碌'在现代社会中被形式主义化为一种身份标识——'我很忙'意味着'我很重要''我被需要''我有价值'。但此定律指出：除非财富或权力达到特朗普的量级，否则'忙碌'不过是形式主义化的自我表演。深层含义是：大多数人的时间被分配到了低效的、重复的、形式主义化的事务上——这不是因为懒惰或无能，而是因为系统的结构决定了大多数人只能在非核心、非创造性、非自主的位置上消耗时间。"

**判定标准**：

- **违规情形**：大纲在涉及 BSD 开发者/贡献者的劳动与付出时，将无偿劳动神圣化、浪漫化或道德化。具体表现为：
  - 以"奉献精神""开源理想""黑客伦理"等话语解释贡献者的无偿劳动，将之神圣化而非揭示其结构性原因
  - 将贡献者的"忙碌"描述为"热情""投入""热爱"的正面表现，而非分析其作为形式主义表演的一面
  - 以"社区凝聚力""协作精神"等话语遮蔽贡献者在系统中被分配到"B 处"（非核心、非创造性位置）的实质
  - 将核心开发者与边缘贡献者的劳动在话语层面平等化，不揭示二者在权力/资源分配上的结构差异

- **合规情形**：大纲在涉及贡献者劳动时，至少揭示以下结构性层面：
  - 贡献者的"忙碌"是形式主义化的身份表演——在开源社区中，commit 数量、邮件列表活跃度、会议参与等构成"忙碌"的外在标识
  - 大多数贡献者的时间被分配到了低效、重复、非核心的事务上，这不是能力问题，而是系统结构决定的
  - 开源社区中真正拥有权力/资源的核心开发者不需要"表演"忙碌，而边缘贡献者则通过"忙碌"来证明自身价值
  - 无偿劳动的结构性原因须被揭示——贡献者不是"选择"无偿劳动，而是被经济斩杀线系统性地排除在"有偿劳动"之外

**违规示例**：

```markdown
## 要点
FreeBSD 社区的开发者以极大的热情投入到代码提交、文档维护和用户支持中，展现了黑客精神的核心价值——对技术的纯粹热爱与无私奉献。
```

> 违规原因：将贡献者的无偿劳动神圣化为"热情""热爱""无私奉献"，未揭示其作为形式主义表演的一面，也未追问为何这些劳动被系统性地划入"无偿"范畴。

```markdown
## 史观
映射总纲10（动手者创造历史）：BSD 项目的每一行代码都是由默默无闻的贡献者书写的，他们用双手推动了操作系统的演进。
```

> 违规原因：将"动手者"简单等同于"英雄"，仅讴歌其劳动而未揭示其劳动在系统中的结构性位置——大多数贡献者的时间被分配到了"B 处"。

**合规示例**：

```markdown
## 辨析
BSD 贡献者的"忙碌"——commit 数量、邮件列表活跃度、会议参与——并非单纯的"热情"表现，而是形式主义化的身份标识。在开源社区的权力结构中，真正掌握资源分配的核心开发者不需要"表演"忙碌，而边缘贡献者则通过"忙碌"来证明自身的存在价值。大多数贡献者被系统性地分配到非核心、非创造性、非自主的事务上——这不是个人能力问题，而是经济斩杀线在开源生态中的结构性运作。与其讴歌"奉献精神"，不如揭示：为何这些劳动被系统性地划入"无偿"范畴？
```

```markdown
## 史观
映射经济哲学第二定律（"忙碌"的形式主义批判）：BSD 贡献者的时间分配不是个人选择问题——大多数人的时间被系统结构决定了只能在"B 处"（非核心、非创造性、非自主的位置上）消耗。将这种结构性消耗神圣化为"奉献精神"，本身就是一种形式主义操作——它使贡献者自觉接受自身位置，从而使斩杀线从外在的强制转化为内在的认同。
```

### 条目4：经济决策悖论

**规范名称**：技术决策中的信息不对称揭示

**sacred 源材料出处**：

- `02-sacred源材料/05-经济哲学与补充哲学.md` 第100-106行（第四定律）：
  > "一切真正重要的东西往往没有经过周全考虑便下决断，而一切细枝末节的东西总是看了又看。事实上，机会总有很多次，但真正愿意去做的次数却寥寥无几。"
  >
  > "此定律揭示了经济决策中的形式主义悖论：最重要的决策（职业选择、婚姻、迁移）往往是在信息不充分的情况下做出的，而最不重要的决策（买什么牌子的牙膏、午餐吃什么）反而被反复权衡。这不是个人理性不足的问题，而是经济系统的形式主义化运作——'重要决策'的不确定性如此之高，以至于'周全考虑'在形式上不可能；而'细枝末节'的确定性足够高，因此可以被形式主义化地'反复比较'。"

**判定标准**：

- **违规情形**：大纲在涉及 BSD 历史上的重大技术决策（如分支分裂、架构选择、许可证变更、项目方向调整）时，将决策呈现为"基于充分信息的理性选择"或"经过审慎考虑的必然结果"。具体表现为：
  - 将重大技术决策（如 NetBSD 从 FreeBSD 分裂、DragonFly BSD 的独立、OpenBSD 的 fork）叙述为"经过充分论证的理性决策"，而非在信息不充分下的决断
  - 将细枝末节的技术争论（如编辑器选择、编码风格、构建工具）叙述为"纯技术讨论"，不揭示其作为"反复权衡的细枝末节"的形式主义本质
  - 以"事后合理化"的叙事将偶然决策重构为"必然选择"——将"没想清楚就做了"改写为"看清楚了才做"
  - 以"决策者理性"的话语遮蔽决策中的信息不对称——最重要的决策恰恰是信息最不充分时做出的

- **合规情形**：大纲在涉及重大技术决策时，至少揭示以下悖论层面：
  - 重大决策（项目分支、架构选择、许可证变更）往往是在信息极度不充分的情况下做出的——当事人事后所做的"周全论证"是形式主义化的"事后合理化"
  - 细枝末节的技术争论（编码风格、构建工具、命名规范）之所以被反复权衡，恰恰是因为这些决策的确定性足够高，可以被形式主义化地"反复比较"——这是一种决策能量的错误配置
  - 主体性的有限性：不是所有机会都有意义，不是所有选择都值得做出——BSD 历史上的某些"机会"（如商业化的窗口期）之所以未被抓住，不是因为"错失"，而是因为主体的意愿本身是有限的
  - 决策的分析不应以"结果论"倒推"决策合理性"——成功的决策不一定是"理性"的，失败的决策不一定是"非理性"的

**违规示例**：

```markdown
## 辨析
NetBSD 团队之所以选择从 FreeBSD 分裂出来，是基于对跨平台可移植性的深刻洞察和长期技术规划。这一决策经过核心团队的充分论证，体现了 NetBSD 项目的技术远见。
```

> 违规原因：将重大决策（项目分裂）叙述为"充分论证的理性选择"，遮蔽了决策时信息极度不充分的事实——"深刻洞察"和"长期技术规划"是事后合理化，而非决策时的真实状态。

```markdown
## 要点
BSD 社区在编码风格（KNF vs 其他风格）上进行了长期且深入的讨论，最终形成了统一的规范，这体现了社区的民主决策精神。
```

> 违规原因：将编码风格争论作为"正面的社区决策案例"呈现，未揭示其作为"细枝末节反复权衡"的形式主义本质——这恰恰是经济决策悖论的典型表现：不重要的事情被反复讨论。

**合规示例**：

```markdown
## 辨析
DragonFly BSD 从 FreeBSD 4.x 的分裂——这一决策是 Matt Dillon 在信息极度不充分的情况下做出的。事后对 SMP 架构差异的"技术论证"是形式主义化的"事后合理化"——决策时的真实状态是：最重要的决策恰恰在信息最不充分时做出，而事后对决策的"合理化"论证不过是对偶然性的必然性包装。这并非对 Dillon 决策的否定，而是对决策本质的诚实揭示。
```
