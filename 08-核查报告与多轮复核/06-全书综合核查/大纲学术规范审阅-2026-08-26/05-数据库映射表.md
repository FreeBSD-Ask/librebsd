# 缺口类型→数据库映射表

**Published Date**: 2026-08-26
**Document Type**: 大纲学术规范审阅——数据库映射表（缺口类型→查询数据库→查询表/字段）
**Source**: 项目全部数据库（16 非邮件正式库 + 4 邮件合并库 + 13 代码仓库 DuckDB + 邮件列表子库 + 7 文件夹级 SQLite 库 + 5 功能库）
**Scope**: 供审阅者在大纲学术规范审阅中定位缺口对应的数据库查询路径

---

## 自反性声明

本文是一种形式主义化的数据库映射，不声称穷尽了所有可能的查询路径。本文的"缺口类型"分类是基于审阅基准文档（01-04 号）的形式主义化提取——某些缺口之间的边界本身就是建构的（如"史料字段空"与"参考文献缺失"在数据库中可能指向同一张表）。本文的"查询表/字段"基于当前数据库 Schema 的快照（2026-08-25 DuckDB 升格后），Schema 可能在未来版本中变更。本文不声称提供了"最优查询路径"——查询效率取决于具体数据分布，本文仅提供概念性映射。

本文坦然承认自身是形式主义，欢迎被更精确的映射方案所超越。

### 3.3 查询示例

**示例 1：检查某章总纲映射覆盖率**

```sql
-- 在 sacred_sources.db 中搜索总纲关键词
SELECT file_path, block_content
FROM blocks
WHERE block_content LIKE '%总纲%'
  AND file_path LIKE '%shigang.md%'
LIMIT 50;
```

**示例 2：检查 FreeBSD 1.0 发布时间在不同卷中是否一致**

```sql
-- 在 资料数据库.duckdb 中查询
SELECT vol, ch, content
FROM materials
WHERE content LIKE '%FreeBSD 1.0%'
  AND content LIKE '%1993%'
ORDER BY vol, ch;
```

**示例 3：查询某贡献者的 commit 记录**

```sql
-- 在 freebsd.duckdb 中查询
SELECT author, date, message
FROM commits
WHERE author LIKE '%Kamp%'
ORDER BY date
LIMIT 100;
```

**示例 4：查询存疑记录按章节汇总**

```sql
-- 在 doubts_standalone.db 中查询
SELECT outline_path, COUNT(*) as cnt
FROM doubts_to_resolve
WHERE resolution_status = 'open'
GROUP BY outline_path
ORDER BY cnt DESC;
```

## 四、审阅执行说明

1. 本映射表是概念性映射——具体查询语句需根据实际 Schema 调整。在查询前建议先执行 `PRAGMA table_info(<table_name>)`（SQLite）或 `DESCRIBE <table_name>`（DuckDB）确认字段名。
2. 邮件列表数据库按项目/列表拆分，查询时需先确定目标列表（如要查询 FreeBSD 架构讨论，应定位到 `freebsd-arch.duckdb`）。
3. 代码仓库数据库的 commits 表结构各项目可能略有差异，查询前建议先执行 `DESCRIBE commits` 确认字段。
4. 本映射表未覆盖的缺口类型，可在审阅执行过程中补充。
5. 查询结果须与大纲文件原文交叉比对，本映射表仅提供数据库查询路径，不替代人工审阅判断。
