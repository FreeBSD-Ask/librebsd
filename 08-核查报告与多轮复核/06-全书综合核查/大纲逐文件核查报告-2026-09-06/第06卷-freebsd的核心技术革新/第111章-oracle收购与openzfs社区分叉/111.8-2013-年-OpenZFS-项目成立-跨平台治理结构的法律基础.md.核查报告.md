## 补充说明（正样本与复核留痕）

- OpenZFS 治理史的考据框架完整：Bylaws（选举指导委员会/平台代表席位/贡献与发布流程）、商标由 Ahrens 个人转让至组织、2013-11-18-19 首届 Developer Summit 旧金山、Ahrens LinuxCon 2013 宣讲——法律结构与人物节点齐备。
- feature flags 机制的工程解释出色（行 115）：pool version 28 之后每个新功能对应一个 feature flag、各平台独立选择启用、避免池版本号全局同步——这是 OpenZFS 跨平台协调的关键技术，且准确锚定约 2012 年引入。
- upstream/downstream 逆转分析（111.8.3）准确且自纠：OpenZFS 不是 illumos 的 fork（最初是协调组织无独立代码库）、2.0 以 ZoL 代码为基础因 ZoL 2013-2020 更活跃、2020 后 illumos 反向从 OpenZFS 同步——常见误解的纠正到位。
- netbsd.duckdb L6.1.1 的 tag 谱系考据有价值但库名错挂（条目 3）：zfs-0.4.1（2009-01-21，Behlendorf，ZoL 时代继承）至 zfs-0.6.1（2013-03-26）至 zfs-2.0.0（跨平台统一）的 tag 序列与 137.5 报告的 zfs-0.8.0/2.0.0/2.2.0 实测互证；0 信任自警 openzfs/zfs 仓库 2019-11-07 前历史继承自 openzfs/openzfs 可能丢失早期 commit——仓库迁移史料风险的自觉。
