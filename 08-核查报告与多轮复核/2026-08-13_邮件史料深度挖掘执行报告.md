## 三、精炼流水线

建立了“挖 → 复核 → 落库”三步流水线：

### 3.1 挖（dig）
`script/_staging/mailmine/extract_candidates.py --ch N`
- 从 `chapter_keywords.json` 派生搜索词（关键词 + 标题/子节英文 token）
- FTS5 跨 6 邮件库搜索
- msg_hash 去重（跨列表 repost 合并）
- 输出候选邮件 markdown 文件（含完整 subject/from/date/body excerpt/source_id/msg_hash）

### 3.2 复核 + 提炼（review + refine）
Agent 阅读候选邮件，对具有史学价值的邮件提取：
- **evidence**：原文引句（quote）+ 规范化事实（fact_text）+ 证据种类（evidence_kind='quote'）+ 事件日期 + 置信度
- **claim**：原子历史主张，类型 ∈ {FACT, CAUSAL_CLAIM, ORIGIN_CLAIM, MOTIVATION, INTERPRETATION, FIRST_APPEARANCE, INFLUENCE_CLAIM, CONTROVERSY, UNVERIFIED}
- 证据等级 L1-L5（L5 最强=当事人本人陈述、L4=当事人/第一手陈述、L3=技术文档）
- 措辞门禁（wording_gate，遵循 `wording_gate_rule` 表 L1-L5 规则）
- 输出 JSON 文件 `refined_chNNN.json`

### 3.3 落库（write）
`script/_staging/mailmine/write_claims.py --json refined_chNNN.json`
- 写入 `evidence` / `claim` / `claim_evidence` / `source_chapter` 四表
- 幂等（INSERT OR IGNORE），可重复执行
