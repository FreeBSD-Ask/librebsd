## 0. 使用方法

对每一个文件，**必须用 Read 工具完整打开并读完**，再按下列 A–E 五组共 22 个检查项逐项判定。
每项判定结果只允许取：`合规` / `违规` / `不适用`。
凡判为 `违规`，必须记录**可定位的证据**（行号或原文片段摘录，≤40 字）。

## A 组：结构与层级（A1–A6）

| 编号 | 检查项 | 判定标准 | 规则依据 |
| :- | :- | :- | :- |
| A1 | H1 唯一性 | 文件有且仅有一个一级标题 `# `；若无 H1 或有多个 H1，判违规 | 结构清晰原则 |
| A2 | 标题层级跳变 | 标题等级须逐级递进，不得出现 H1→H3、`##`→`####` 之类跳级 | 写作规则“结构化大纲规则·结构清晰” |
| A3 | 章标题格式 | 章首页 H1 须为 `# 第 N 章 <标题>`；**不得携带节范围与字数**（如不得写`（N.1-N.9 节，约 14,565 字）`） | 写作规则“正式书稿格式规范·概述.md 模板·格式约束”（历史定稿的模板约束） |
| A4 | 节号连续性 | 章目录下节文件编号 `N.M` 从最小到最大须连续无缺号；概述索引引用的节号须与磁盘实际节文件范围一致 | 流程规则“大纲节号连续性规则·禁止跳号”（无例外） |
| A5 | frontmatter 一致性 | `概述.md` 的 `chapter`/`id`/`volume` 字段须与所在卷号、章号一致，不得遗留重排前旧编号 | 流程规则“Frontmatter 元数据一致性规则”（无例外） |
| A6 | 索引标题写法 | 章首页节索引标题统一为 `## 本章节索引`，不得写作 `## 子节索引` 等其他写法 | 写作规则“概述.md 模板·格式约束” |

## B 组：五字段完整性（B1–B3）

| 编号 | 检查项 | 判定标准 | 规则依据 |
| :- | :- | :- | :- |
| B1 | 五字段齐全 | 子节内容须含 要点 / 史料 / 史观 / 辨析 / 文献 五个字段，缺任一判违规 | 写作规则“结构化大纲规则·结构清晰”（5 字段要求） |
| B2 | 占位未填 | 字段值为“（待从数据库提取）”“待补”“TODO”“TBD”“（待定）”等占位符，判违规 | 考据规则 0 信任原则；防幻觉原则 |
| B3 | 字段格式统一 | 5 字段统一用加粗段落标签（`**要点**：`）或统一列表符号，**不得混用** | 写作规则“结构化大纲规则·结构清晰” |

## C 组：写作规则符合性（C1–C10）

| 编号 | 检查项 | 判定标准 | 规则依据 |
| :- | :- | :- | :- |
| C1 | ASCII 直引号 | 中文正文（含注释、脚注、辨析字段、说明文字）出现 ASCII 直引号 `"`（U+0022）或 `'`（U+0027）判违规。**例外**：英文人名撇号（O'Neill）、英文所有格（Programmer's）、代码字符串定界符、行间代码内部、引文原文 | 写作规则“中文引号强制规则”“中英文混合判断原则” |
| C2 | 方头括号/白双引号 | 出现 U+300C/U+300D/U+300E/U+300F 判违规 | 写作规则“标点符号规则” |
| C3 | 一段一行 | 同一段落内不得插入换行符（软换行/硬折行）；段间须空行 | 写作规则“一段一行规则” |
| C4 | 路径/IP/文件名加粗 | 带 `\` 的路径、IP 地址、文件名须用 `**加粗**`，**不得使用反引号**，也不得与斜体混用 | 写作规则“路径与 IP 加粗规则” |
| C5 | 手册页引用格式 | `命令(N)`（如 `vt(4)`、`jail(8)`）须保持括号数字原式并加粗，**不得改为点号格式**（vt.4），**不得用反引号** | 写作规则“手册页引用规则” |
| C6 | Port 单复数 | 中文上下文用单数 `Port`，不写作 `Ports`。**例外**：专有名词 FreeBSD Ports Collection / FreeBSD Ports 系统 | 写作规则“Port 一词单复数规则” |
| C7 | 欧化汉语 | 滥用“已”（“XX 已新增”应为“新增 XX”）、滥用“一个 xx”翻译腔、“xx yy”倒置结构（“xx 可调参数”应为“可调参数 xx”）、病句/倒装 | 写作规则“避免欧化汉语规则” |
| C8 | 裸写章号 | 跨章/跨节引用须用链接包裹 `[文本](路径)`，**不得裸写章号**（如“参见第 310 章”“第 26 章 26.5 节”） | 写作规则“结构化大纲规则·综合使用 Markdown 标记”（不裸写章号） |
| C9 | 术语统一 | GSoC→“编程之夏”；package/packages→“软件包”（代码块与命令输出内保留英文）。不得机械替换 | 写作规则“术语翻译统一规则” |
| C10 | 书名号 | 书名、作品名（电影/动漫/论文）须用《》包裹；商标与专名须写完整 | 写作规则“书名、商标、动漫名词规则” |

## D 组：结构化大纲规则（D1–D4）

| 编号 | 检查项 | 判定标准 | 规则依据 |
| :- | :- | :- | :- |
| D1 | 一段一要点 | 一个段落或列表项只承载一个要点；多要点须拆分或嵌套，不得混杂 | 写作规则“结构化大纲规则·一段一要点”“不混杂” |
| D2 | Markdown 标记综合使用 | 应综合使用 todo/task、加粗、序号、子编号、缩进、链接、表格等标记，而非通篇纯文本 | 写作规则“结构化大纲规则·综合使用 Markdown 标记” |
| D3 | 积极使用表格 | 凡多维度对照数据（版本时间线、特性对照、人物活动时间、fork 对比、平台矩阵、许可证对比、性能基准、史料可信度评级等）须用表格；表格须含表头行 + 对齐分隔行 + 数据行 | 写作规则“结构化大纲规则·积极使用表格原则” |
| D4 | 同级符号统一 | 同级要点须统一用 `-` 或统一用 `1.` `2.`，不得混用 | 写作规则“结构化大纲规则·结构清晰” |

## 3. 主理人裁决（v1.1，2026-09-06，对全体核查员统一适用）

> 下列裁决由主理人于试点批次（batch_131）回报后作出，用于统一判定尺度，避免各批次宽严不一。

**裁决 1 —— 数据库指针块（DB_POINTS）中的文件名反引号**：仍判 **C4 违规**。
依据：写作规则“路径与 IP 加粗规则”明确“文件名加粗，不篡改”，规则文件中不存在数据库指针块的豁免条款。
执行要求：判违规的同时，须在 `note` 中标注“数据库指针块”，以便最终报告将其单列为**模板批量可修复项**，不与正文违规混同统计。

**裁决 2 —— 模板未填占位（“待补”“TODO”“（待从数据库提取）”）**：判 **E3/B2 违规**。
依据：考据规则 0 信任原则与防幻觉原则；流程规则“重复与错误文档清理规则”未成品判定。
执行要求：无论占位出现在表格单元格、字段值还是脚注，一律判违规；在 `note` 中注明占位所在位置（如“数据核验表”）。

**裁决 3 —— A4 节号连续性的核查分工**：
- 核查员**只判定章内跳号**：即该章实际存在的节文件编号，从最小到最大之间是否有缺失。有缺失即判 A4 违规。
- 章首节号不从 1 开始（如第 46 章仅有 46.18–46.20）**不由核查员判定**，该问题由主理人以全书扫描统一处理（属跨章继承历史遗留，需单独裁决）。核查员仅需在 `note` 中标注“章首节号非 1（起于 N.M）”，供主理人汇总。

**裁决 4 —— C1 中文正文 ASCII 直引号**：中文正文中的 ASCII 直单引号 `'`（如 `'~163 章锚定=0'`）同样判违规，不因其为单引号而豁免；仅英文人名撇号、英文所有格、代码定界符、引文原文豁免。

**裁决 5 —— 判定存疑的处理**：存疑项仍写入 `findings`，`判定` 字段填“存疑”，并在 `note` 中说明。严禁为求结论而臆断，严禁编造行号或原文。

**裁决 6 —— 中文行文中包裹英文术语的 ASCII 直引号**（如 `“UNIX”`、`"Free Software"` 用 ASCII 直引号）：判 **C1 违规，不降级**。
依据：规则明文“中文正文（含注释、脚注、辨析字段、说明性文字）中的引号一律使用弯引号”。包裹英文术语的引号处于中文语境，既非代码字符串定界符，也非引文原文，不适用豁免。豁免仅限：英文人名撇号、英文所有格、代码定界符、行间代码内部、引文原文。

**裁决 7 —— 手册页引用未加粗（C5）**：判 **违规，目录语境不豁免**。
依据：写作规则“手册页引用规则”明文“手册页引用一律使用加粗包裹”，无目录/索引语境豁免条款。
执行要求：判违规同时在 `note` 标注“目录条目”，最终报告单列统计。

**裁决 8 —— 拟定稿规划标记（“★必设”“[存疑脚注]”等，E3）**：判 **违规**。
依据：考据规则防幻觉原则；此类标记为未成品痕迹。
执行要求：判违规同时在 `note` 标注“拟定稿规划标记”，最终报告单列，不与正文占位混同。

**裁决 9 —— 小写 `ports`（C6）按上下文区分**：
- 指 **FreeBSD ports 集合 / ports 树**（专有名词 `FreeBSD Ports Collection` 的语境简称）→ **豁免**，不判违规；
- 指 **单个 Port 的复数**（中文语境中“多个 Port”却写作 ports）→ **判违规**。
判不准时填“存疑”并说明，不得臆断。

## 1. 输出格式（每个文件一条）

```json
{
  "file": "第01卷-unix的起源/第1章-unix前史/概述.md",
  "bytes": 12345,
  "read_status": "full",
  "verdict": "有问题",
  "findings": [
    {"项": "C1", "判定": "违规", "证据": "第 12 行：……使用 \"引号\" 表述……"},
    {"项": "B2", "判定": "违规", "证据": "第 5 行：要点：（待从数据库提取）"}
  ],
  "note": "可选，一句话总体评价"
}
```

`verdict` 取值：`合格` / `有问题` / `严重`（严重 = 结构性缺失，如空文件、五字段全缺、编号错乱）。

## 2. 纪律要求

1. **必须逐个打开文件读完**，禁止抽样、禁止跳过、禁止以脚本扫描替代人工阅读。
2. 只读，**不得修改、重命名、移动、删除任何文件**，不得写入 `05-卷册大纲/`。
3. 判定拿不准时，判为“存疑”并在 `note` 中说明，**不得臆断**。
4. 引用证据必须真实来自所读文件，**禁止编造行号或原文**。
5. C1 判定须区分中文正文与代码/英文引文，避免误判。
