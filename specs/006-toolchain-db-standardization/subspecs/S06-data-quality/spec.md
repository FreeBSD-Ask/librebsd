# S06 数据库数据质量评估

## 1. 意图确证（档 A 摘要）

- **用户原话（节录）**：对数据库数据质量进行全方位评估，提出不计成本的改进建议。
- **目标**：以 ISO/IEC 25012 十五特性为骨架，结合 GB/T 36344 六类与 DCMM 2025，对全部正式库做只读全量剖析、质量记分卡、问题清单与不计成本的改进建议。
- **非目标**：
  - 不写库、不建临时表、不改 schema。
  - 不以抽样替代全量剖析；抽样只用于人工逐字复核。
  - 不把注册表当唯一真值；须磁盘、SCOPE、注册表三方对账。
  - 不承诺“零缺陷”；缺陷如实挂账。
- **验收判据**：
  - Tier A 28 库记分卡 100%；Tier B/C 有清单与风险分级。
  - 15 维指标有公式、阈值、证据；关键指标第二脚本复算差异 0。
  - 注册表自身质量问题单列（built_at、size_bytes、sha256）。
  - 改进建议按风险×影响排序，标注成本与回退。
- **手段自由度**：
  - 只读 DuckDB；`PRAGMA`、`information_schema`、`duckdb_databases()`。
  - 全表全列剖析；大库分片或复制后剖析。
  - 抽样逐字复核与跨库对账。
- **未知／[待验证]**：
  - 346 件库中哪些属项目内容资产、哪些是沙箱／临时件。
  - 部分库被锁或体量过大（lkml 33.85 GB）。
  - 跨库同一事实的裁决标准。

## 3. 用户故事与验收场景

### US-S06-1 每库有分数

**Why this priority**：维护者需要可比较的质量画像。

**Independent Test**：任取一库，记分卡 15 维有分数与证据。

**Acceptance Scenarios**：

1. Given 一个正式库，When 查记分卡，Then 总分、风险级别、top issues 齐全。
2. Given 一个低分维度，When 查证据，Then 有 SQL 与输出。

### US-S06-2 问题可修

**Why this priority**：问题清单要能指导修复，不是泛泛而谈。

**Independent Test**：任取一条问题，有表、列、行数、影响、建议动作。

**Acceptance Scenarios**：

1. Given 一个空值问题，When 查清单，Then 有表列、比例、影响。
2. Given 一个孤儿问题，When 查清单，Then 有反连接 SQL。

### US-S06-3 不计成本但不失焦

**Why this priority**：全量剖析成本高，仍需优先级。

**Independent Test**：改进建议按风险×影响排序，有成本与回退。

**Acceptance Scenarios**：

1. Given 一条建议，When 查优先级，Then 有风险×影响评分。
2. Given 一条高风险建议，When 查回退，Then 有回退步骤。

## 4. 功能需求

| 编号 | 需求 | 验收判据 |
| ---- | ---- | -------- |
| S06-FR-01 | MUST 把 15 维映射到 ISO/IEC 25012 特性，并给出与 GB/T 36344 六类的对应。 | 映射表；无孤儿维度。 |
| S06-FR-02 | MUST 对 Tier A 每库做全表全列剖析：行数、空值、基数、键、孤儿、时间范围。 | 覆盖率 100%；输出路径。 |
| S06-FR-03 | MUST 为每维定义公式、分母、阈值、证据。 | 指标表；公式可复算。 |
| S06-FR-04 | MUST 产出每库记分卡（15 维＋加权总分＋风险级别）。 | 记分卡 TSV；权重有依据。 |
| S06-FR-05 | MUST 产出问题清单：表、列、行数、比例、影响、严重级别、建议动作。 | 清单非空；每条可定位。 |
| S06-FR-06 | MUST 做跨库对账（claim／outline／reference 等）与抽样逐字复核。 | 对账报告；抽样记录。 |
| S06-FR-07 | MUST 评估注册表自身质量：built_at、size_bytes、sha256、schema_version、覆盖。 | 注册表质量节；异常计数。 |
| S06-FR-08 | MUST 保证只读与可复现；关键指标第二脚本复算。 | 只读证据；复算差异 0。 |
| S06-FR-09 | MUST 给出不计成本的改进建议，按风险×影响排序，标成本与回退。 | 建议表；排序依据。 |
| S06-FR-10 | MUST 如实披露无法评估的库／表与原因。 | 限制节；缺项清单。 |

## 5. 非功能需求

- 只读：不写库、不建表、不改数据。
- 可复现：脚本、输入、版本、命令可追溯。
- 可解释：分数有公式与证据，不是黑箱。
- 性能：大库分片，超时有记录。
