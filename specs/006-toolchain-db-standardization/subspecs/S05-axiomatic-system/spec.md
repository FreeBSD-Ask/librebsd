# S05 公理化体系

## 1. 意图确证（档 A 摘要）

- **用户原话（节录）**：对0的产物进行公理化体系建立，证明，一致性，充分性，完备性。
- **目标**：对任务书、spec、工具、数据库、标准、缓存六类对象建立形式系统：排序、符号、公理、定义、定理与证明；用 Alloy／TLA+／Lean 做机器检查；证明相对于声明范围的一致、充分、完备，并明确不可证事项。
- **非目标**：
  - 不声称对全项目、全语义做绝对证明；只做相对于声明范围的相对证明。
  - 不把工程规格等同于数学公理系统；需求完备性是经验问题。
  - 不在本 spec 改数据库或工具；只读形式化建模。
  - 不引入未经验证的形式化工具依赖。
- **验收判据**：
  - 形式系统含排序、符号、公理 A01—A12、定义、定理 T01—T08。
  - Alloy／TLC 模型可复跑；无矛盾或有反例解释。
  - 覆盖矩阵显示每个目标至少一个 spec；每个 spec 至少一个目标。
  - 限制文件列明不可证事项、假设、失效条件。
- **手段自由度**：
  - Z 记号（ISO/IEC 13568）写规格；Alloy 找反例；TLA+ 检查状态机；Lean／Rocq 证明核心引理。
  - Armstrong 公理与 Codd 关系模型用于数据库函数依赖。
  - 机器检查文件与命令入库（或工作区）可复跑。
- **未知／[待验证]**：
  - Alloy／TLA+／Lean 的学习与建模成本。
  - 哪些公理是真正独立、哪些可从定义推出。
  - 项目对象域的边界（是否含正文、历史档案）。

## 3. 用户故事与验收场景

### US-S05-1 公理可检查

**Why this priority**：公理集必须能找出矛盾，而不是纸面自洽。

**Independent Test**：Alloy／TLC 可复跑；矛盾有反例。

**Acceptance Scenarios**：

1. Given 公理集，When 跑 Alloy，Then 输出无模型或反例。
2. Given 一个反例，When 解释，Then 指出哪条公理冲突。

### US-S05-2 目标充分覆盖

**Why this priority**：每个目标都要有 spec 承接。

**Independent Test**：覆盖矩阵 100%，无孤儿。

**Acceptance Scenarios**：

1. Given 目标 G10，When 查矩阵，Then 至少一个 spec 覆盖。
2. Given 一个 spec，When 查目标，Then 至少一个目标。

### US-S05-3 边界诚实

**Why this priority**：不能把相对证明说成绝对证明。

**Independent Test**：限制文件列明范围、假设、不可证事项。

**Acceptance Scenarios**：

1. Given “完备”主张，When 查限制，Then 写“相对于声明范围”。
2. Given 需求演化，When 查失效条件，Then 有复审触发。

## 4. 功能需求

| 编号 | 需求 | 验收判据 |
| ---- | ---- | -------- |
| S05-FR-01 | MUST 定义排序与符号：Tool、Artifact、Database、Dataset、Standard、Rule、Record、Metric、Actor、Time。 | 签名表；每个符号有类型。 |
| S05-FR-02 | MUST 给出公理 A01—A12，每条有自然语言解释与形式写法。 | 公理表；无歧义。 |
| S05-FR-03 | MUST 给出定义 D01—D08（合规、可追溯、稳定工具、绑定等）。 | 定义表；可展开。 |
| S05-FR-04 | MUST 给出定理 T01—T08 与证明；证明可逐步复核。 | 证明件；每步有依据。 |
| S05-FR-05 | MUST 用 Alloy 或 TLA+ 检查一致性；有反例则修正公理或解释。 | 模型文件＋运行输出。 |
| S05-FR-06 | MUST 用 Lean 或 Rocq 证明至少 3 条核心引理。 | 证明文件＋编译输出。 |
| S05-FR-07 | MUST 建目标→spec→公理→定理→证据的覆盖矩阵。 | 矩阵 100%。 |
| S05-FR-08 | MUST 定义完备性等级：语法完备、语义完备、相对完备、经验完备。 | 定义表；主张对应等级。 |
| S05-FR-09 | MUST 写限制文件：范围、假设、不可证事项、失效条件、复审触发。 | 限制文件非空。 |
| S05-FR-10 | MUST 提供复跑命令与依赖版本；机器检查可重复。 | README；命令可执行。 |

## 5. 非功能需求
