# S01 标准与规范调研

## 1. 意图确证（档 A 摘要）

- **用户原话（节录）**：进行全面的国内、国际标准，规范，规则调研（除Ai披露）
- **目标**：建立分级、现行、可定位的标准清单：覆盖数据质量、软件工程、记录档案、OCR／音频、Rust／工具链、供应链、形式化方法与学术规范八域；每条经官方来源核验，完成四问抽取与三转化，并登记版本冲突与检索留痕。
- **非目标**：
  - 不购买或翻译标准全文；条款级核对以官方预览、摘要与公开页为限，取不到者标 [待核验]。
  - 不把标准直接改写成项目规则；只给判据、设计约束与复核项建议。
  - 不声称合规认证；本标准清单是方法基线，不是认证证据。
  - 不把 AI 内部知识当依据；不凭记忆写条款号与参数。
  - 不调研、不采纳强制标记 AI 生成内容的披露规范（ykla 2026-11-27 裁定）；检索命中者列入排除清单。
- **验收判据**：
  - 清单 ≥60 条，八域各有覆盖；每条含标准号、版本、状态、适用条款、约束、例外、冲突、官方 URL、检索日期。
  - [一手已核] 比例 ≥80%；[待核验] 条目有明确复核路径。
  - 版本冲突表覆盖任务书 §5.6 的 18 项，并逐项给出处置。
  - 每条标准至少完成三转化之一：FR／NFR 判据、设计约束、复核项。
  - AI 披露类标准不进入采用清单；命中者列入排除清单并说明理由。
- **手段自由度**：
  - Tavily CLI 优先；iso.org、iec.ch、ieee.org、itu.int、w3.org、openstd.samr.gov.cn、saac.gov.cn 等官方域优先。
  - 可读标准预览页与公开摘要；不绕过付费墙。
  - 国标状态以全国标准信息公共服务平台与国家标准全文公开系统为准。
- **未知／[待验证]**：
  - AI 披露范围已裁定：强制标记 AI 生成内容的规范不采纳；S01 只登记排除，不展开调研。
  - ISO 条款级正文多需购买；只能用摘要与预览页。
  - GB 标准全文受版权保护，平台只给状态与元数据。

## 2. 范围

### 2.1 范围内

- 八域标准的分级检索与状态核验
- 四问抽取（适用性／约束／例外／冲突）
- 与项目规则、S02—S12 的映射
- 版本冲突与换版跟踪
- 检索留痕与复审周期

### 2.2 范围外

- 标准全文翻译
- 合规认证
- 替 ykla 决定位阶冲突
- 把标准条文直接写成项目规则
- 强制标记 AI 生成内容的披露规范

### 2.3 依赖

- 无前置；为 S02—S12 的约束输入
- 依赖官方站点可达

## 3. 用户故事与验收场景

### US-S01-1 可引用的标准清单

**Why this priority**：后续 spec 需要外部锚点，不能凭记忆写“业界通常”。

**Independent Test**：任取 10 条，复核者按 URL 与条款号可定位；状态与清单一致。

**Acceptance Scenarios**：

1. Given 一条标准，When 打开官方 URL，Then 标准号、版本、状态与清单一致。
2. Given 一条“现行”标准，When 查替代关系，Then 清单注明是否被代替或修订中。

### US-S01-2 冲突可处置

**Why this priority**：GB 与 ISO 版本不一致时，不能静默取舍。

**Independent Test**：任取一条冲突，能说出位阶、处置与登记位置。

**Acceptance Scenarios**：

1. Given GB/T 25000.10-2016 与 ISO/IEC 25010:2023，When 查冲突表，Then 有“方法基线用 ISO、引 GB 注明 2011 版”的处置。
2. Given 项目规则与标准冲突，When 查位阶，Then 以 01-规则 现行版本为准并登记。

## 4. 功能需求

| 编号 | 需求 | 验收判据 |
| ---- | ---- | -------- |
| S01-FR-01 | 标准清单 MUST 使用统一字段：std_id、number、edition、title、body、status、clauses、constraint、exception、conflict、url、retrieved_at、evidence_level、mapped_specs。 | 字段齐全率 100%；缺字段即 FAIL。 |
| S01-FR-02 | 八域 MUST 各有 ≥5 条；总条目 ≥60。 | 按域计数；不足即 FAIL。 |
| S01-FR-03 | 每条 MUST 核验状态（现行／被代替／修订中／废止）与替代关系。 | 官方页有状态证据；无证据标 [待核验]。 |
| S01-FR-04 | 每条 MUST 完成四问抽取；答不出“约束”者不得进入清单。 | 四问字段非空；约束须落到具体条款或明示“无直接约束”。 |
| S01-FR-05 | 冲突表 MUST 覆盖任务书 §5.6 全部条目，并给位阶处置。 | 逐项对照；缺项即 FAIL。 |
| S01-FR-06 | 每条 MUST 映射到至少一个 spec 或项目规则；无映射者标“参考”。 | mapped_specs 非空或标“参考”。 |
| S01-FR-07 | 检索留痕 MUST 记录查询词、官方域、受阻情况与日期。 | 留痕文件存在；可复跑关键查询。 |
| S01-FR-08 | 复审周期 MUST 明确；标准换版触发即时复核。 | 复审日期与触发条件写入清单头部。 |
| S01-FR-09 | 不得以 AI 记忆替代官方来源；无法核实者 MUST 标 [待核验]。 | 抽查 10 条，全部有 URL；无 URL 即 FAIL。 |
| S01-FR-10 | 交付物 MUST 可被 S02—S12 直接引用（稳定 std_id）。 | std_id 不被后续批次改写；改名须留别名。 |
| S01-FR-11 | 强制标记 AI 生成内容的披露规范 MUST NOT 纳入采用清单；检索命中者列入排除清单并说明理由。 | 排除清单存在；采用清单零命中。 |

## 5. 非功能需求

- 可定位：标准号＋年份＋条款＋URL＋检索日期。
- 可复述：每条有一句“对本项目管什么”。
- 可判定：约束能写成二值判据或明确“无直接约束”。
- 可维护：复审周期与换版触发明确。

## 6. 关键实体

- Standard（std_id、number、edition、status、url）
- Clause（条款号、约束、例外）
- Conflict（标准 A、标准 B、位阶、处置）
- Mapping（std_id、spec_id、规则路径）
