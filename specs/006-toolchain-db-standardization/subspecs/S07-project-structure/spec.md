# S07 项目结构建议

## 1. 意图确证（档 A 摘要）

- **用户原话（节录）**：对项目结构提出建议。
- **目标**：评估 12 个编号目录、工具／spec／数据库／缓存落点与命名，给出方案对比、迁移与回退、决策点；评估可立即执行，不实际改动。
- **非目标**：
  - 不改目录结构、不移动文件、不新建根目录。
  - 只读评估，不改动 `05-卷册大纲/` 与 Task 8.2／8.3 在途工作面。
  - 不把 `.trae/specs/` 批量入库；`specs/` 已入库状态不在本 spec 重议。
  - 不替 ykla 做结构决定。
- **验收判据**：
  - 现状地图覆盖 12 个编号目录与 6 个保留目录。
  - 约束检查 PASS：不新增根目录、编号缺口不复用、`05-卷册大纲/` 不动。
  - 至少 3 个方案对比，含成本、风险、回退。
  - 每个建议有决策点与需谁批。
  - 评估可立即执行；结构施工有冻结条件。
- **手段自由度**：
  - 只读目录树、规则、`.gitignore`、ADR。
  - 与 S02／S03／S09／S11 的落点建议对齐。
  - 评估可立即；结构施工冻结到 Task 8.2／8.3 收口。
- **未知／[待验证]**：
  - ykla 对共享库、Rust 源码入库、数据字典落点的偏好。
  - Task 8.2／8.3 收口时间。
  - 现有 260 个 `.trae/specs` 的清理策略。

## 3. 用户故事与验收场景

### US-S07-1 结构有依据

**Why this priority**：结构建议不能凭审美，须对照约束与成本。

**Independent Test**：任取一个建议，能说出约束、成本、风险、回退。

**Acceptance Scenarios**：

1. Given 共享库建议，When 查约束，Then 不新增根目录、不改 05。
2. Given 迁移建议，When 查回退，Then 有步骤。

### US-S07-2 评估不干扰在途工作

**Why this priority**：只读评估可与大纲迁移并行；结构施工不能同批。

**Independent Test**：方案明确“评估可立即、施工冻结”的条件。

**Acceptance Scenarios**：

1. Given Task 8.2 在途，When 做评估，Then 只读、不改 05。
2. Given 收口后，When 施工，Then 有独立批次。

### US-S07-3 决策可批

**Why this priority**：建议要能让 ykla 直接拍板。

**Independent Test**：每个决策点有选项、建议、需谁批。

**Acceptance Scenarios**：

1. Given D-01 共享库入库，When 查表，Then 有选项与建议。
2. Given D-03 治理型 spec 入库，When 查表，Then 有 ADR 需求。
