# S08 软件工程理论复核

## 1. 意图确证（档 A 摘要）

- **用户原话（节录）**：以上复核软件工程理论.
- **目标**：把 12 目标与项目治理（G0—G5、ADR、任务审计、门禁、轮替）对照软件工程理论／标准，识别缺口，按六段化登记 TG，提出 ADR 建议；不直接改理论正文。
- **非目标**：
  - 不直接改 `13-软件工程/` 正文；按 NOTICE 回流。
  - 不新增门禁脚本；只提建议。
  - 不重复 TG-001—TG-017 已覆盖内容。
  - 不把理论当教条；须项目证据。
- **验收判据**：
  - 对照覆盖 12207:2026、15288:2023、29148:2018、29119-1:2022、25010:2023、42010:2022、15289:2019、15489/26162、SSDF/SLSA/5230、Armstrong/Codd、TLA+/Alloy/Lean。
  - 每个缺口有证据、六段化、落地载体、失效条件。
  - 与既有 TG-001—TG-017 去重；重复者标“已覆盖”。
  - 至少 3 条 ADR 草案。
- **手段自由度**：
  - 只读规则、ADR、台账、复盘件。
  - 标准原文与官方摘要。
  - 项目证据（门禁、批次、缺陷）优先于理论推演。
- **未知／[待验证]**：
  - 理论条款与项目实践的适配度。
  - 哪些缺口应回流上游、哪些只项目内。
  - 新增 TG 的优先级。

## 3. 用户故事与验收场景

### US-S08-1 理论能落地

**Why this priority**：对照不是列书名，要能改变判据。

**Independent Test**：每条建议有落地载体与判据。

**Acceptance Scenarios**：

1. Given 12207:2026，When 查对照，Then 有 G0—G5 映射与缺口。
2. Given 一个缺口，When 查落地，Then 有规则／ADR／门禁载体。

### US-S08-2 不与既有重复

**Why this priority**：TG 已 17 条，不能重复登记。

**Independent Test**：每条新 TG 标“新增”或“已覆盖”。

**Acceptance Scenarios**：

1. Given 一个新缺口，When 查 TG，Then 有编号与去重结论。
2. Given 已覆盖项，When 查，Then 指向既有 TG。

### US-S08-3 边界诚实

**Why this priority**：理论不能解释一切；要写失效条件。

**Independent Test**：每条建议有反模式与失效条件。

**Acceptance Scenarios**：

1. Given 一条建议，When 查失效，Then 有触发条件。
2. Given 一个反模式，When 查，Then 有纠正。
