# 音频流水线规范（S12；v1）

## 流程（响度归一→转写→字幕→质检）

```text
输入 音频/视频
→ ① 抽取音轨（ffmpeg → PCM 24bit/48kHz 母版暂存；DA/T 62-2017 口径）
→ ② 响度测量与归一（ITU-R BS.1770-5 算法；EBU R 128 目标 −23 LUFS ±0.5 LU / TP ≤ −1 dBTP；EBU Mode 表 + LRA 并记录）
→ ③ 转写（本地 Whisper large-v3 或 SenseAudio，按批评估选择；时间戳精度 ≤100ms）
→ ④ 字幕产物（WebVTT 主；需广播级交换时 TTML2；SRT 兼容导出）
→ ⑤ 质量门（WER/CER≤阈值、时间戳漂移≤250ms、抽样人工复核 5%；失败分级同 OCR）
→ ⑥ 入库（播客库 episodes 补结构元数据列：sample_rate/bit_depth/loudness_lufs/true_peak_dbtp/codec）
→ ⑦ provenance（音源 sha256、模型+参数、归一实测值、批号、操作者）
```

## 判据

- **响度**：只测不推（历史母版不改写原文件）；新交付物归一至 R128 并记录实测值。
- **元数据**：按 DA/T 63-2017 四实体对齐——现 `youtube.duckdb` 无采样率/位深/编码列，迁移批补列。
- **字幕状态**：WebVTT 引用须写 CRD 2026-05-20（非 Recommendation）；TTML2 第 1 版 2018 Rec 可用于交换。
- **TTS 不在范围**（ykla 2026-11-27 裁定）。

## 与现状差距

1. 无 LUFS/dBTP 测量（现 `18_audit_mp3.py` 只查解码与大小）→ 试点批加 ffmpeg `loudnorm` 测量段。
2. 无 WER/CER 评测 → 采 NIST SCTK 方法，参考文本=人工抽校稿。
3. episodes 表缺结构元数据列 → S02 迁移批补列。
