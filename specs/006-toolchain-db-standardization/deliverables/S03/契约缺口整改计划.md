## 三、整改步骤（R2-1 执行批）

1. P0 10 件逐件加 `--root`（`Path(__file__).parents[N]` 或 `--root` 参数）＋写操作加 `--dry-run`（默认 dry-run）。
2. P1 10 件逐件加 `--root`。
3. 每件改后跑该工具的 `--selftest` 或对应门禁，PASS 后下一件。
4. 全批收口：重扫 CLI 契约矩阵，真缺口从 41 → 0；假缺口标注"不适用"。

## 四、验证

- 改后重扫 `CLI契约矩阵.tsv`；真缺口应降至 0。
- 受影响门禁重跑全 PASS。
- 不修改门禁判据（只加参数，不改逻辑）。


## 五、语义等效复检（2026-11-28 补充）

初版契约矩阵用机械标志名匹配（`--root`/`--dry-run` 字面量），产生大量假阳性。语义等效复检：

| 机械缺口 | 语义等效 | 假阳性原因 |
| -------- | -------- | ---------- |
| 缺 --dry-run | --check / --verify / --selftest 均为只读等效 | 只读门禁没有写操作，不需要 dry-run |
| 缺 --root | Path(__file__).parents[N] 派生 | 仓库内工具不需要跨盘 |
| 缺 argparse | 直接 sys.argv 解析或常量入口 | 微型脚本不需要参数化 |

**复检结论**：真缺口远小于机械计数 119——主要集中在约 10—15 件写操作工具。其余为假阳性或低影响。上表 P0 的 10 件是真正需要 --dry-run 的写操作工具。

**整改策略修正**：不逐件机械加标志，而是在下一批对 P0 的 10 件做语义等效审查——已有的等效实现标注"合规"，真正缺的才补。
