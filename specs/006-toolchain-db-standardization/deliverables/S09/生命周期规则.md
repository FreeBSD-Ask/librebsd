# 生命周期规则（S09-FR-05／06／07；2026-11-28）

> 判据二值、可自动校验，唯一实现在 `build_tool_registry.py`（判定）与 `audit_tool_registry.py`（校验，B2／B3／B5／B6／B9）。本文件只陈述规则，不承载逐件状态。

## 一、五态定义

| 生命周期 | 判据（全部满足才成立） | 自动校验 | 处置 |
| -------- | ---------------------- | -------- | ---- |
| `stable` | ①在固定工具目录 `00-编纂规则与格式规范/01-规则/脚本与命令/` ②`git ls-files` 已跟踪 ③被至少一处 `01-规则/**/*.md` 引用文件名 ④声明 `--selftest`（或 `audit_gate_registry.py` REGISTRY 登记 selftest） | B5／B6 | 长期保留；改动走规则流程 |
| `experimental` | 在固定工具目录但缺 stable 判据任一（`notes` 记缺失项） | B6 | 观察期；补判据后升 stable |
| `deprecated` | 仅由 `例外覆盖.tsv` 显式指定 | B3 | 保留一版，下批删除需明示 |
| `one-shot` | 路径以 `script/` 开头 | B9 | 30 天 TTL；超期入清理候选，不自动删除 |
| `external` | 仓库外依赖，本表不收录 | — | 仅备注 |

**90 天调用证据（stable 第四判据）**：本仓库无调用日志，无法自动校验；由 `last_verified` 字段人工签收。校验器对 stable 行 `last_verified` 为空只出 WARN、不阻断（B6）。

## 二、one-shot TTL 与日期判据（重要局限）

`script/` 顶层 3 936 件文本脚本的 TTL 判定不采用 mtime，因为 **`script/` 的 mtime 曾被 2026-10-28／29 的批量操作整体刷新**（实测最早 mtime＝2026-10-28，不能反映真实新旧）。日期三级判据：

| 级别 | 判据 | 覆盖率（2026-11-28 实测） | 可信度 |
| ---- | ---- | ------------------------ | ------ |
| 1 | 文件名内嵌 `20YYMMDD`／`20YY-MM-DD` | 708 件（18%） | 高 |
| 2 | 内容首 4 KB 内最晚日期 | 1 969 件（50%） | 中（可能是示例日期） |
| 3 | mtime 兜底 | 1 258 件（32%） | 低（已失真），TTL 判 `unknown` |

- `stale`＝可信日期距今 > 30 天（2026-11-28 实测 94 件），只进 `one-shot清单.tsv` 与 dashboard 清理候选，**不自动删除**；删除走 `cleanup_temp.py` 四步流程（S11 机制）。
- `unknown`＝不可信，不判超期、不入候选；需人工判断或补文件名日期。

## 三、例外覆盖（S09-FR-09）

`例外覆盖.tsv` 字段：`tool_id`（或 `path`）、`field`、`value`、`reason`。

- 允许覆盖：`notes`、`risk`、`lifecycle`（→ `deprecated` 或 `external`）。
- 禁止覆盖生成字段：`path`、`tracked`、`created_at`、`rule_references`、`verification_method`——这些是判据输入，改了等于伪造证据。
- 覆盖只影响 `工具总表.tsv` 对应单元格并追加 `reason` 到 `notes`；不改变校验器判据（B6 仍按真实判据算）。

## 四、升级与降级

- `experimental → stable`：补齐 tracked／规则引用／selftest 三判据后重跑生成器即自动升级。
- `stable → experimental`：任一判据失效（如规则引用被删）自动降级，`notes` 记缺失项。
- `→ deprecated`：覆盖表指定＋changelog 留痕；删除须 ykla 明示（AGENTS.md 红线 9 同口径）。

## 五、与外部标准的关系

- 状态枚举与转换参照 ISO/IEC 19770-2:2015（SWID 生命周期标记）与 SPDX 3.0.1 `LifecycleScope`；本表不引入外部枚举值，仅在语义上对齐。
- 时间格式 ISO 8601-1:2019（`YYYY-MM-DD`）；TSV 排序按 `path` 字典序以保证可 diff（SemVer 2.0.0 不适用于工具表，仅用于 spec 版本）。
