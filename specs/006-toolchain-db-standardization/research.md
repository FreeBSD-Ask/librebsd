# Research: 标准调研方法与种子结论

> 本件是 S01 的方法基线，不是全量调研。执行期 S01 按本方法扩展，逐条四问抽取、三可留痕、三转化落地。

## 1. 方法（沿用 `13-软件工程/10-standards-first.md`）

### 1.1 分级检索（L1—L5）

| 级 | 对象 | 本项目实例 |
| -- | ---- | ---------- |
| L1 | 国际标准：ISO、IEC、IEEE、ITU、W3C、IETF | ISO/IEC 25012、ISO/IEC/IEEE 12207、ITU-R BS.1770、W3C PROV |
| L2 | 国家标准：GB、GB/T | GB/T 36344、GB/T 26162、GB/T 25000 系列 |
| L3 | 官方规范：POSIX、语言规范、协议规范 | Rust Reference、DuckDB 文档、RFC 2119 |
| L4 | 官方文档：项目手册、README、发布说明 | DuckDB 并发文档、Tesseract 文档、Rust API Guidelines |
| L5 | 官方建议：BCP、best practice、维护者声明 | SLSA、OpenSSF、EBU R128 |

### 1.2 四问抽取

| 问 | 抽取 | 落点 |
| -- | ---- | ---- |
| 适用性 | 是否约束本批；现行版本；替代关系 | 清单“适用级别”列 |
| 约束 | 对本项目 FR／NFR／设计的约束 | spec 判据、ADR 依据 |
| 例外 | 不适用条件；标准未覆盖部分 | 非目标、checklist 注记 |
| 冲突 | 与项目规则／更高位阶的冲突 | 位阶处置＋登记 |

### 1.3 吃透三可

- **可引用**：标准号＋年份＋条款＋URL＋检索日期。
- **可复述**：能说清适用范围与本项目接合点。
- **可判定**：能写出二值可判的约束条目。

### 1.4 落地三转化（至少其一）

1. 转化为 FR／NFR 验收判据或 checklist 项。
2. 转化为设计约束（ADR 依据、设计检查项）。
3. 转化为复核判据（模板 I 收口项）。

### 1.5 来源纪律

- 官方页优先；二手转述只作线索。
- 不采信模型记忆；每条标准必须回官方原文。
- 版本状态必须核：现行／被代替／修订中／废止。
- 查不到官方原文的标 `[待核验]`，不得写成已核。

## 2. 种子结论（2026-11-27 已核验）

### 2.1 数据质量

| 结论 | 证据 | 用途 |
| ---- | ---- | ---- |
| ISO/IEC 25012:2008 定义 15 个数据质量特性，分固有与系统依赖两视角 | iso.org/standard/35736.html | S06 的维度骨架 |
| ISO/IEC 25024:2015 为 25012 特性提供度量 | iso.org/standard/35749.html | 指标公式 |
| ISO 8000-1:2022 提供数据质量原则与管理能力总览 | iso.org/standard/81745.html | 治理框架 |
| GB/T 25000.12-2017 采 ISO/IEC 25012；GB/T 36344-2018 给评价指标框架 | openstd.samr.gov.cn | 中国等效依据 |
| GB/T 36073-2025 DCMM 2.0 定义数据管理能力域；2018 版已废止，2025-12-31 发布、2026-07-01 实施 | openstd.samr.gov.cn | 成熟度参考；换版 |
| ISO/IEC 11179-1:2023 为现行元数据注册框架；2015 版已撤 | iso.org/standard/78914.html | 数据字典 |

**对本项目的含义**：S06 以 25012 的 15 特性为骨架，不另造维度；每个指标必须能映射到一个特性，并给出公式、阈值、证据。GB/T 36344 用于中国学术／档案语境的可解释性。

### 2.2 软件与系统质量

| 结论 | 证据 | 用途 |
| ---- | ---- | ---- |
| ISO/IEC 25010:2023 为 9 特性、40 子特性；新增 Safety；Usability→Interaction Capability；Portability→Flexibility；使用质量移至 ISO/IEC 25019 | iso.org/standard/78176.html | NFR 分类 |
| GB/T 25000.10-2016 采 ISO/IEC 25010:2011（8 特性） | openstd.samr.gov.cn | 版本滞后说明 |
| ISO/IEC/IEEE 12207:2026、15288:2023 为生命周期过程框架；2017 版已撤销 | iso.org | G0—G5 对照 |
| ISO/IEC/IEEE 29148:2018 为需求工程 | iso.org OBP | spec FR 质量 |
| ISO/IEC/IEEE 29119-1:2022 为测试概念 | iso.org/standard/81291.html | 证据型验证 |
| ISO/IEC/IEEE 42010:2022 为架构描述 | iso.org/standard/74393.html | 工具链架构 |

**对本项目的含义**：NFR 采用 ISO 25010:2023 的九特性；G0—G5 对照 12207／15288；需求质量按 29148；测试按 29119 的抽样与 oracle 概念；架构描述按 42010 的视点。

### 2.3 记录、档案、日期

| 结论 | 证据 | 用途 |
| ---- | ---- | ---- |
| ISO 15489-1:2016 已发布但状态为“to be revised”（90.92）；AWI Ed.3 已立项 | iso.org/standard/62542.html | 记录管理原则；版本跟踪 |
| GB/T 26162-2021 为现行中国等效（2022-07-01 实施） | 国家档案局标准库 | 中国档案语境 |
| GB/T 18894-2016 为电子文件归档规范（2017-03-01 实施） | 国家档案局标准库 | 归档 |
| ISO 8601-1:2019 为日期时间表示；Amd 1:2022 已发布 | iso.org/standard/70907.html | 时间戳 |
| GB/T 7408.1-2023 等同采用 ISO 8601-1:2019；GB/T 7408-2005 已废止 | openstd.samr.gov.cn | 中国日期时间 |
| ISO/IEC 19770-2:2015 为 SWID | iso.org | 工具表可借鉴 |
| W3C PROV-O 2013 为溯源本体 | w3.org/TR/prov-o | provenance 模型 |

**对本项目的含义**：时间戳统一 ISO 8601 扩展格式；记录状态、版本、处置按 15489／26162；provenance 采用 Entity／Activity／Agent 三元，字段可映射。

### 2.4 OCR、文档、音频

| 结论 | 证据 | 用途 |
| ---- | ---- | ---- |
| ISO 19005-4:2020 为 PDF/A-4，基于 PDF 2.0；状态 90.92 拟修订（DIS 19005-4.2 在投票） | loc.gov FDD | 长期保存 |
| ISO 14721:2025 为 OAIS 第3版，替代 2012 版；ISO 16363:2025 替代 2012 版 | iso.org | 长期保存信息包 |
| ALTO XML 4.4 为 LoC 官方 schema | loc.gov/standards/alto | OCR 版面 |
| hOCR 为事实标准，无 ISO 号 | 社区规范 | OCR 文本表示 |
| DA/T 31-2017 为纸质档案数字化规范（代替 2005 版） | 国家档案局通知 | 中国档案数字化 |
| DA/T 62/63-2017 为录音录像数字化与元数据 | 国家档案局通知 | 音频档案 |
| ITU-R BS.1770-5（2023-11）为响度与真峰值算法 | itu.int | 音频归一 |
| EBU R 128 为 −23 LUFS／±0.5 LU／−1 dBTP | tech.ebu.ch | 音频目标 |
| W3C WebVTT 现行为 CRD（2026-05-20），不是 Recommendation；TTML2 第1版 2018 为 Rec | w3.org | 字幕交换；引用须写对状态 |

**对本项目的含义**：OCR 流水线应产 ALTO 或 hOCR＋纯文本；音频转写应做响度归一与字幕格式校验；质量门用 CER／WER 与抽样人工复核。

### 2.5 工具链、供应链、形式化

| 结论 | 证据 | 用途 |
| ---- | ---- | ---- |
| Rust 2024 Edition 自 1.85.0（2025-02-20）稳定；当前 stable 1.100.0（2026-11-12） | 官方发布史 | Rust 基线 |
| Rust API Guidelines 为官方 API 设计规范 | github.com/rust-lang/api-guidelines | crate 设计 |
| SLSA 1.2（2025-11-24）为当前规范；1.0 稳定于 2023 | slsa.dev | 构建完整性 |
| SPDX 3.0.1（2024-12）为当前稳定规范；ISO/IEC 5962:2021 对应 2.2.1；ISO 3.0 版出版中 | spdx.dev | SBOM |
| ISO/IEC 5230:2020 为 OpenChain 许可合规 | iso.org/standard/81039.html | 许可 |
| NIST SP 800-218 SSDF v1.1 为安全开发框架 | csrc.nist.gov | 安全 |
| ISO/IEC 13568:2002 为 Z 记号 | iso.org/standard/21573.html | 形式规约 |
| RFC 2119／8174 为义务级用语 | rfc-editor.org | 条文用语 |

**对本项目的含义**：Rust 采用 Edition 2024＋`rust-version` 声明；SBOM 用 SPDX 3.0.1 或 CycloneDX 1.7，注明 ISO 版本差异；公理化可用 Z 写规格、Alloy／TLA+ 检查、Lean／Rocq 证明核心引理。
