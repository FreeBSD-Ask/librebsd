# Plan: 工具链与数据库标准化

## 1. 技术上下文（Technical Context）

| 项 | 现状 | 目标 |
| -- | ---- | ---- |
| 语言 | Python 3.15（121 个固定脚本）、SQL、JS（bun）、少量 Shell | Python 基线＋Rust 热路径＋统一语言标准 |
| 数据库 | DuckDB 2.0.0，约 28 个正式库，346 个 `.duckdb` 文件（约 83.3 GiB，含 `script/` 与邮件列表库） | 单写多读、schema_meta 全覆盖、质量记分卡 |
| 工具入口 | 裸文件名、无统一 CLI、21 个含盘符文本（仅 1 个真实代码路径） | 统一 `--help/--root/--dry-run/--apply/--verify` 契约 |
| 标准 | 20 条既有基线，散落引用 | 分级清单＋四问抽取＋版本冲突表 |
| 形式化 | 无 | 公理集＋Alloy／TLA+／Lean 模型 |
| 缓存 | 多目录并存，无统一 TTL | 分类、判据、清单、隔离、复扫 |
| specs | `specs/` 入库跟踪（2026-11-27）；`.trae/specs/` 260 个工作区目录 | Git＋BINDING sha256 双留痕 |

### 2.1 数据流

1. **标准流**：S01 清单 → 各 spec 的 FR／NFR 约束 → 收口核对。
2. **数据流**：只读剖析 → 记分卡 → 问题清单 → 归一化方案 → dry-run → 写批（另批）→ 复核。
3. **工具流**：扫描 → 工具表 → 生命周期判定 → CLI 契约 → 并发／锁 → 基准 → Rust 评估。
4. **公理流**：实体／关系 → 公理 → 定理 → Alloy／TLA+／Lean → 覆盖矩阵。
5. **清理流**：扫描 → 分类 → 引用检查 → 清单 → 计划 → 执行（另批）→ 复扫。

## 4. 阶段与任务（Phases）

### Phase P0 — 规划（本批）

- 任务书、总 spec、12 子 spec、契约、绑定清单。
- 验收：任务书 A-01—A-09；本文件 §7。
- 退出：ykla 复核；执行批另走准入。

### Phase P1 — 基线（只读）

- S01 标准清单；S06 质量剖析 v0；S09 工具表 v0。
- 产出：`标准清单.tsv`、`质量记分卡.tsv`、`工具总表.tsv`。
- 退出：标准 `[一手已核]` ≥80%；记分卡覆盖 100%；工具表 stable 覆盖 100%。

### Phase P2 — 设计与机制

- S02 数据字典与归一化方案；S03 CLI／并发／锁；S11 缓存机制。
- 产出：设计件＋dry-run 方案。
- 退出：每项有判据、回退、证据路径；无写库。

### Phase P3 — 评估与生产改写

- S04 Rust 评估与生产改写（按批准）；S12 OCR／音频任务书模板。
- 产出：评估矩阵、语言标准、生产改写方案、流水线规范。
- 退出：候选覆盖 100%；影子运行与回退方案就绪；质量指标可判。

### Phase P4 — 形式化与理论

- S05 公理化；S08 理论复核。
- 产出：公理、定理、证明、Alloy／TLA+／Lean、TG／ADR 建议。
- 退出：模型可复跑；覆盖 100%；限制文件完整。

### Phase P5 — 结构评估与建议

- S07 结构评估可立即执行；结构施工冻结到 Task 8.2／8.3 收口。
- 产出：评估、对比、迁移与回退、决策点。
- 退出：约束 PASS；无实际改动。

### Phase P6 — 综合与收口

- S10 综合最佳建议；绑定终验；G6 反思。
- 产出：路线图、决策记录、绑定 PASS、复盘。
- 退出：全部 SC；changelog；任务审计收口。
