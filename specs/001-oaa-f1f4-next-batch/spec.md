# Feature Specification: OAA F1–F4 四组交接书与下一批任务书

**Feature Branch**: `001-oaa-f1f4-next-batch`

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "更新 F1、2、3、4 交接书和任务，制定接下来的 F1、2、3、4 共 4 组任务书，读取磁盘实际进度"

## User Scenarios & Testing *(mandatory)*

本特性是一次**编纂工程文档同步**：把 OAA（大纲邮件素材条目审计）战役 F1–F4 四组的**磁盘真实进度**固化成四份**组级交接书**，并为每组写出**下一批任务书**（派发书）。它不是写代码，产出物是 `script/_db_row_mining/audit_outline/` 下的交接书与 `01-项目管理/01-编纂规划与报告归档/` 下的任务书。

### User Story 1 - 读盘取得 F1–F4 真实进度（Priority: P1）

接手人打开战役时，必须先知道**此刻磁盘上到底做完多少、还剩多少、有没有在途批**。本故事要求以“合并台账（`processed.jsonl` ∪ `processed_f1..f4.jsonl`）＋ 大纲实测 ROW_MINE 锚点 ＋ 分片/判读盘面”三源实算，产出每组的：认领宿主数、已审块数、待审块数、在途批（片数／已判片数／进度）、按卷分布。

**Why this priority**: 这是全部后续动作的地基。此前多次事故（台账口径混乱、重派覆盖已 PASS 件、把在途批误判为未开工）都源于进度取自“单方回报”而非磁盘。

**Independent Test**: 把实算结果与 `_BEACON.md` 浮标逐组比对，四组待审块数误差 ≤1%；并列出每组在途批的“片数／已判片数／进度”，可与 `shards/` `judgements/` 目录逐一核对。

**Acceptance Scenarios**:

1. **Given** 合并台账 59,563 条与大纲 350,280 个 ROW_MINE 锚点，**When** 按认领清单 `beacon/claims_FN.txt` 逐宿主差集，**Then** 得到 F1 待审 72,791／F2 待审 88,722／F3 待审 57,969（含避让 9,110）／F4 待审 71,545，与浮标一致。
2. **Given** `judgements/` 目录，**When** 按前缀聚合计数，**Then** 识别出四组各有在途批：`f1_b03` 120/459 片、`f2_b01` 653/815 片、`f3_05` 8/255 片、`f4b04` 71/93 片。
3. **Given** 一个未登记的批（如 `f1_b03`），**When** 只读台账不做盘面核对，**Then** 该批 10,543 块会被误判为“未开工”——本故事要求这种情况**不得发生**。

### User Story 2 - 每组一份组级交接书（Priority: P2）

为 F1/F2/F3/F4 各写一份 `_HANDOFF_F{1..4}.md`，内容包括：已闭环批次表、**在途批现场**、挂账移交清单（X1 等级／X2 remap／X3 存疑／fix-db 待 apply）、本组特有坑清单、下一手动作、断点真值口径。

**Why this priority**: 交接书是跨会话、跨并行的唯一“接手入口”。F2/F3/F4 线此前只有零散批报告与 `work/_f2_progress.md`，没有统一的组级交接书。

**Independent Test**: 任取一份交接书，其中“在途批现场”的片数／块数／进度三项，与 `shards/`＋`judgements/` 实算值完全相等；“挂账清单”每条都能指到具体文件（`work/_f3_04_x1_level.json` 之类）或具体报告小节。

**Acceptance Scenarios**:

1. **Given** 一份交接书，**When** 复核人抽查 3 个数字，**Then** 3 个数字均能在磁盘上复现。
2. **Given** 一个挂账项，**When** 按交接书给出的路径打开清单文件，**Then** 文件存在且条目数相符。

### User Story 3 - 每组一份下一批任务书（Priority: P3）

为每组写出**下一批**（在途批之后的那一批）派发书：F1-04、F2-b02、F3-06、F4-b05。每份任务书须给出：批范围（逐宿主路径＋块数）、片数（按 23 块/片或该组既有粒度）、执行八步（清单→fetch→分片→滚动判读→原地入大纲→受控修库→五门禁→台账/报告/提交）、并发纪律、挂账口径、验收标准。

**Why this priority**: 使四组可在在途批收口后**立刻续跑**，不需重新勘察。

**Independent Test**: 按任务书给出的宿主清单跑一遍差集脚本，得到的总块数与任务书标注值一致（±5%）。

**Acceptance Scenarios**:

1. **Given** F1-04 任务书，**When** 对其宿主清单实算待审块，**Then** 得 9,509 块（92.1 单宿主），与标注一致。
2. **Given** F2-b02 任务书，**When** 核对，**Then** 范围等于 `work/_f2_batchplan.json` 的 `f2_b02` 项（184.1／12,919 块）。
3. **Given** F3-06 任务书，**When** 实算第06卷余下宿主，**Then** 得 ≈4,249 块且**不含**在途的 122.9/131.5/121.3，也不含避让 4 文件。
4. **Given** F4-b05 任务书，**When** 实算第02卷余下宿主，**Then** 得 ≈4,460 块且**不含**在途 `f4b04` 的 16 宿主。

### User Story 4 - 主交接书回指（Priority: P4）

在 `_HANDOFF_OAA.md` §九 增补一节，把四份组级交接书与四份任务书登记进去，并刷新 §七数字快照。

**Why this priority**: 保证单一入口不失效；否则接手人仍会只看主交接书而漏掉组级细节。

**Independent Test**: 从 `_HANDOFF_OAA.md` 出发，四份交接书与四份任务书均可在 1 跳内到达。

**Acceptance Scenarios**:

1. **Given** `_HANDOFF_OAA.md`，**When** 按其中链接打开四份交接书，**Then** 四份文件均存在。

### Edge Cases

- **在途批与“下一批”冲突**：若在途批（如 `f1_b03`）尚未登记，其块仍计入 pending。下一批任务书的清理规则必须先**扣除本组在途批宿主**，否则两组会写同一文件。
- **大纲动态增长**：并行会话（H2 等）持续给大纲加锚，同一宿主块数会在数小时内变化（`f1` 一夜 +1,636）。任务书标注的块数是**取量时点实测值**，须注明时点与“开工以浮标实测为准”。
- **避让清单**：第06卷 4 文件（112.10／121.1／121.4／122.10，实测已增至 9,110 块）属“重构2026”并行工作面，F3 不审、不登记、不改动。
- **主库被并行会话独占锁定**：`historical_claims.duckdb` 被 PID 4 锁定时，fix-db 情形①② 的 UPDATE 无法当期执行（F3-04 的 54 条即因此挂账），须留 apply 脚本待放锁后补跑。
- **同名不同序**：批号命名在各组不统一（F1/F3 用 `f1_b03`/`f3_05`，F4 用 `f4b04`），聚合时须按前缀枚举而非假设格式。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 进度 MUST 由“合并台账 ∪ 分片盘面（shards/judgements）”实算得出，MUST NOT 采信任何单方回报。
- **FR-002**: 每组交接书 MUST 含五节：①已闭环批次表 ②在途批现场（宿主/片数/块数/已判片数/进度/续接起点）③挂账移交清单（X1 等级／X2 remap／X3 存疑／fix-db 待 apply，逐项带清单文件路径与条数）④本组特有坑 ⑤下一手动作与断点真值口径。
- **FR-003**: 每份下一批任务书 MUST 给出逐宿主路径＋块数的本批清单、片数（标注每片块数）、并发滚动路数、执行八步、五门禁判据、验收标准、提交规范。
- **FR-004**: 任务书 MUST 显式声明**不得**触碰在途批的 `shards/`、`judgements/`、`processed_fN.jsonl` 与大纲宿主；本批宿主集 MUST 与在途批宿主集互斥。
- **FR-005**: fix-db MUST 按三情形分流——情形①（事实错误，fact_text/claim_text）与情形②（错锚）当场受控修库（备份→UPDATE→provenance_history/update_log 留痕→三表守恒回读）；情形③（等级）不动库，挂账 X1 待主理人批注。
- **FR-006**: F3 任务书 MUST 含避让清单过滤（第06卷 4 文件），避让块不审、不登记、不改动，仅在报告中单列“避让”节。
- **FR-007**: 每批提交 MUST 用 `git commit --gpg-sign -F <msgfile>`，并以 `git log -1 --format=%G?` 复核结果为 `G`；`script/` 全树 gitignore，台账/脚本须 `git add -f`。
- **FR-008**: 每批收工 MUST 写本组分片台账（`oaa_register.py --ledger processed_fN.jsonl`）并 `oaa_beacon.py --refresh` 刷新浮标。
- **FR-009**: 任务书 MUST 注明取量时点，并写明“开工以 `oaa_beacon.py --status` 实测为准”。
- **FR-010**: 主交接书 `_HANDOFF_OAA.md` MUST 登记四份组级交接书与四份任务书的路径，并刷新 §九 现场节。

### Key Entities

- **宿主文件（host）**：`05-卷册大纲/**/*.md` 中承载 ROW_MINE 块的单篇节文件，为**不可拆原子**（不得按库拆分）。
- **ROW_MINE 块**：`<!-- ROW_MINE: <库>.messages.<pk> -->` 锚点标识的一条素材条目，审计的最小单位。
- **分片（shard）**：把一批宿主按固定块数（F1/F2/F3 为 23 块/片，F4 为 50 块/片）切出的 `shards/<前缀>_sNN.jsonl`。
- **判读件（judgement）**：读手对一片的逐块判定，`judgements/<前缀>_sNN.jsonl`，行数与分片行数相等即视为“该片已判”。
- **台账（ledger）**：`processed.jsonl`（基线，只读冻结）与 `processed_f1..f4.jsonl`（各组独占写），唯一键为 `库|pk|宿主相对路径`。
- **浮标（beacon）**：`beacon/beacon.json` ＋ `_BEACON.md`，记录快照、认领清单、各组进度与新增 delta。
- **认领清单（claims）**：`beacon/claims_FN.txt`，逐行一个宿主相对路径，定义组间边界。
- **挂账清单**：`work/_f3_04_x1_level.json` 等，记录不动库的高风险项。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四组待审块数实算值与 `_BEACON.md` 浮标一致，误差 ≤1%（实测：F1 72,791／F2 88,722／F3 57,969／F4 71,545，与浮标 0 差）。
- **SC-002**: 四份组级交接书 ＋ 四份下一批任务书 ＋ 主交接书回指节，合计 9 处产出全部落盘且路径可达。
- **SC-003**: 在途批**零改动**：本特性执行期间不得新增/覆盖任何 `shards/*`、`judgements/*` 或 `05-卷册大纲/**` 文件。
- **SC-004**: 每份任务书本批块数与实算差值 ≤5%（大纲动态增长所致，须注明时点）。
- **SC-005**: 四组在途批进度在交接书中可复现：片数×片块数 与已判块数之比，与 `judgements/` 行数实测一致。
- **SC-006**: 每份挂账清单条目数可从其 JSON 文件复现（如 F3 X1 = 134+203+177+24 = 538 条）。

## Assumptions

- 认领清单 `beacon/claims_FN.txt`（2026-10-01 02:22 刷新）是组间边界的权威定义；卷目录名以磁盘为准（如第12卷＝`第12卷-macos的bsd遗产`，第20卷＝`第20卷-linux社区史与比较研究`），与索引层记载不一致处不予改动。
- 本特性**只写文档**，不改大纲、不改数据库、不重跑判读；fix-db 的库侧执行属各批任务书的职责，不在本特性范围内。
- 组号与批号命名沿用各组既成惯例：F1 用 `F1-04`，F2 用 `F2-b02`，F3 用 `F3-06`，F4 用 `F4-b05`。
- 并行会话（H2、重构2026 等）可能同时改动大纲与在途批；本特性所有取量均为**只读快照**，且以 `_BEACON.md` 刷新时点为界。
- 单批规模沿用该组既有量级：F1 ≈ 9.5–11 k 块，F2 单大宿主，F3 ≈ 4–6 k 块，F4 ≈ 4–6 k 块。
