## 一、核验目标与方法

本卷大纲第 225 章 225.1 节辨析称：“4.2.2 版本被错误 tag 后立即被 4.2.3 替换（含新版 OpenSSL），需在版本时间线中标注此异常”，并登记存疑脚注 id 1674：“4.2.2 错误 tag 的具体原因须经 bsd_commits.db tags 表与 DragonFly 邮件列表核验”。

本地无 bsd_commits.db（此前依赖项未落地），改用**可联网的一手版本历史数据**核验：
1. GitHub 官方镜像 `DragonFlyBSD/DragonFlyBSD` tag 列表 API（https://api.github.com/repos/DragonFlyBSD/DragonFlyBSD/tags）——tag 是否存在、4.2.x 系列完整性。
2. DragonFly 官方 releases 页（https://www.dragonflybsd.org/releases/）——官方发布的 4.2.x 版本清单交叉印证。

## 二、核验结果

### 2.1 GitHub tag 列表（一手，镜像库完整 tag 序列）

调用 tags API（per_page=100，返回 100 个 tag，覆盖 v6.4.2 至 v3.4.1）中 **4.2.x 系列**：

| tag | commit SHA（前 10） |
|-----|--------------------|
| v4.2.0 | 82c070747b09 |
| v4.2.0rc | b1ab41792b77 |
| v4.2.1 | 395405bf74c2 |
| **v4.2.2** | **（不存在）** |
| v4.2.3 | 3d88cc7897f1 |
| v4.2.4 | e844aa7f3a45 |

→ **GitHub 官方镜像 tag 列表中无 v4.2.2**。

### 2.2 DragonFly 官方 releases 页（一手）

releases 页中 4.2.x 版本号出现情况：`4.2.4 ×1`、`4.2.3 ×1`、`4.2.1 ×1`、`4.2.0 ×1`，**无 4.2.2**。

→ **官方 releases 页同样无 4.2.2 发布记录**。

### 2.3 交叉验证结论

- **4.2.2 从未作为正式发布版存在**：官方 releases 页与 GitHub tag 列表双向一致，4.2.x 系列仅 4.2.0 → 4.2.1 → 4.2.3 → 4.2.4（4.2.0rc 为发布候选）。
- 大纲辨析中“4.2.2 版本被错误 tag 后立即被 4.2.3 替换（含新版 OpenSSL）”的叙述：**方向性事实成立**（4.2.2 在官方序列中缺失，紧邻的 4.2.3 为下一正式版），但“被错误 tag”的具体成因（如误打 tag 后撤回）仍属**推断**，无法从 tag 列表与 releases 页直接证明确切成因。
- 依零信任原则：**可确证**的是“4.2.2 不在官方发布序列中”这一事实层；**不伪造**“误 tag 的具体操作细节”，建议大纲表述订正为“4.2.x 官方序列中不存在 4.2.2 发布版，4.2.3 为 4.2.1 之后的下一个正式发布（含新版 OpenSSL）”。
- 横向参照：id 1653（LWKT 首 commit 8ad65e080342，author_date 2003-06-20）已于 round2 经 GitHub commit API 核验；id 1683/1685（vkernel 移除 commit 770134）已于批次二经 DragonFly BSD Digest 2021-01-08 报道核验。
