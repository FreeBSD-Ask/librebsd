## 二、候选格式（硬约束）

三字段 `pk|等级|摘要`，**分隔符是竖线 `|`**，LF 行尾，UTF-8 无 BOM。
- `pk` 必须是本行第一列的**原样数字**，不得改写、不得臆造、不得借用邻行。
- `等级` ∈ `L3`（一般求助／一般问答／一般技术讨论）或
  `L4`（含可考据的技术结论／故障根因／版本行为／移植决定／政策决定）。
- `摘要` **20-80 字，按 70 字落笔、不写满 80**；中文长度只能用 `len()` 实测，
  手估系统性偏高 5-15 字。
- 禁字符：`「` `」` `*` `\` `|`、全角空格、制表符、换行、**任何引号形态**
  （含撇号 `dont` 非 `dont'`）。
- **不得以标点收尾**（含 `。` `，` `：` `；` `？` `！` `、` 与空格）。
- 🔴 **答复型摘要必须带主体名**：凡摘要在陈述「答了什么／给了什么方案／指出了什么根因」，
  开头写「人名：」。**主体错配与漏主体是最贵缺陷**。
- 库内习惯：英文撇号一律省略（`dont` 非 `dont`）；
  不写日期前缀、不写来源尾注。
- 🔴 **禁止改写人名**：拿不准就照抄原字形，一字不改。

## 六、最高危缺陷（历史各批均实证发生过）

1. **引用块内被引者的主张写成本封 FROM 的主张**——最高频缺陷。
   凡摘要中出现的技术串，若在本行 subject/FROM/body 三处全 0 命中，即为臆造 →
   **删而非改**。
2. **跨线程／跨行搬移内容**：把邻行（兄弟线程）的技术细节写进本行摘要。
3. **转引当作自述**：本封自有正文只有一句 `On ... X wrote:`，
   摘要却把 X 的结论写成发句人的结论。
4. **臆造整段**：正文里特征词命中数全 0，摘要却写出一整套细节。
5. **主体漏写**：答复型摘要不带头名，读者无法判断谁给的方案。
6. **人名改写**：为凑字形把原拼写改掉（哪怕原文是拼错的）。
