## 叙述写作规范

- 主语必须是本封 **FROM 发句人**（用英文昵称，如「jhb 指出」「jkh 报告」），
  以「当事人 + 动词」开句：「jhb 自述…」「jkh 提出…」「steve 建议…」
- 一句话到两句话的主句，保留可核实细节：人名与身份、平台名、版本号、函数与接口名、
  实测结论、配置项
- **长度 60–140 字**（宜 85–125），必须用 `len()` 实测；低于 60 或高于 140 判不合格
- **禁止出现**：直角引号「」『』、弯引号 ‘’ “ ”、直引号 ' " `、星号 `*`、竖线 `|`、
  制表符、换行。代码里的星号（`INSTALL_*`、`e_*`）**必须改写成不含星号的表述**
  （如「INSTALL 系列符号」「p_emul 的 e 系列字段」）
- **叙述末尾不得有句号、逗号、分号、冒号、空格、破折号**（脚本会补句号与纪律句）
- **不得以数字开头**；不得含「1997 年」这类日期前缀；不得含 ROW_MINE / 来源： /
  消息列表 / freebsd-hackers.messages 之类的来源尾巴
- 现代汉语，不用文言，不用「据悉」「表示」「该」堆叠

## 🔴 署名归属（本批最高频缺陷，门禁会逐条核）

- 正文行首带 `>` 的是**引用块**，里面的话属于被引者，**不得写成 FROM 的主张**
- `> X wrote:` 里的 X 是**被引用者**；`FROM:` 字段才是本封作者
- 无头引用块（没有 `X wrote:` 引导）若与本发件人语势相反、或属同线程更早邮件，
  按转载处理：只写发件人转述之事，不记为其本人主张
- 无法确证归属时，写「转述」而非记为本人主张；判不了就弃收该断言
- 摘要头名必须在本行 `FROM:` 字段逐字命中；命中不了就不是 FROM 的主张

## 🔴 关键字回查（防臆造）

- 叙述中出现的人名／函数名／平台名／版本号／配置项，**须在正文全文检索**
  （SUBJ 行不算正文，`>` 与 `:` 开头的行也不算）；**0 命中即为臆造，删除该断言**
- 不得改成另一个可能同样不存在的词（那等于二次臆造）
- 版本号形态必须**逐字**出现在本封自有正文里，不能凭常识补全（如不能因为讨论
  2.1 就写 FreeBSD-2.1-RELEASE 而不核对原文字面）
- 「FreeBSD 后接英文普通词」是版本误判陷阱：写「FreeBSD 的稳定版」而非
  「FreeBSD stable release」；确需英文时只能是 current / stable / release /
  prerelease / snapshot / snap / x11 / keltia / www / hackers 等白名单词，
  或后接数字的版本续写
- 摘要与正文实况不符时，**以正文为准**，并在回报里列出该 pk
