# 10 标准先行：开工前标准化文献启发式阅读

> **项目侧增补**（2026-11-14，依 ykla 指令）：本文件不是 WHCode 上游正文，只在本项目生效；上游采纳前按 `NOTICE.md` 版本化回流（TG-016）。本件是“知难行易”的第二体现，与 `08-intent-first.md` 同源互补。

本文件只回答一件事：任务开工之前，公共知识基线（国际标准、国家标准、官方规范、官方文档与官方建议）必须读到什么程度，才允许动手。

## 1. 命题与定位

“知难行易”在本文件中的工程含义是：开工前最贵的认知成本不在“怎么写”，而在两处“知”——

- **知方向**：为什么要做、做到什么算成、什么不做。由意图确证承担，判据见 `流程规则/01-复核与验证.md`“意图确证”节与 `08-intent-first.md`；
- **知边界**：世界已就此事立了哪些公共约定。由本文件承担：先查标准、规范与官方建议，吃透后落为判据，再动手。

方向与边界任一缺失，“行”必然以同一种形态偿还：产物不合规范、与既有约束冲突、重造已有的轮子。命题原文与旁证定位见 `08-intent-first.md` §1（`sacred_sources.duckdb` `files.id=45`／`blocks.id=1848`；总纲 21；§3.7.26），本文件不重复引文。

两个既有条款是本原则的域级先例，本文件将其普适化，不取代它们：

- `04-concurrency-performance.md` §2.2“文献门槛”：并发设计前至少研读 3 篇一手来源——并发域仍按该节执行；
- `00-philosophy.md`“使用原则”第 1 条“先读现有规则”：项目内既有约定先行对齐——项目内对齐之后，再向外对齐公共约定。

## 2. 工程翻译

| 序 | 条目 | 工程含义 |
| -- | ---- | -------- |
| 1 | 知难 | 标准的难处在三件事：不知道它存在（检索缺位）、不知道哪条适用（适用性误判）、不知道版本效力（引用过期或替代关系不明）；AI 会话另有一层：训练记忆里的“标准要求……”可能是幻觉，不查原文即是赌 |
| 2 | 行易 | 按吃透的标准写实现、写判据，是分钟到天量级的直路；吃透之后的“行”不需要创造力，只需要忠实 |
| 3 | 知不立则行不顺 | 边界缺失时，执行不会因为手段先进而变顺：不合规范的产品、评审期返工、与项目规则的冲突，全部是“知”欠下的债 |

结论：**开工次序是“先确证意图，再锁定标准，后动手实现”**。意图确证单答“为什么做”，标准化文献清单答“公共约定已定什么”，二者合成开工前的完整“知”。

## 3. 阅读对象分级

| 级 | 对象 | 项目内实例 |
| -- | ---- | ---------- |
| L1 | 国际标准：ISO、IEEE、IEC、W3C、IETF RFC 等 | Unicode 码位与编码、IEEE 754、RFC 2119/8174 义务级用语 |
| L2 | 国家标准：GB（强制性）、GB/T（推荐性）等 | GB/T 7714-2015（参考文献著录）、GB 18030 |
| L3 | 官方规范：POSIX（IEEE Std 1003.1）、man 手册页、语言与平台官方规范、协议规范 | POSIX.1-2017、FreeBSD man 页、C/C++ 标准草案 |
| L4 | 官方文档：项目官方手册、README／发布说明、权威实现文档 | FreeBSD Handbook、DuckDB 官方文档、Git 官方文档 |
| L5 | 官方建议：BCP、官方 best practice、维护者声明、FAQ | IETF BCP、各项目安全发布页 |

**清单口径**：与本批触发面有交集者入清单；无交集不硬凑，不为满足流程罗列不相关标准。声称“无适用标准”的任务，须留下检索痕迹证明确无（检索了哪些域、用了什么关键词），不得默认跳过。

## 4. 启发式阅读法（四问抽取）

**启发式**＝以判据启发为目的的定向抽取，不是逐字通读；它防两种失败：不读（凭模型内部知识或印象动手）、全读（把通读当交付——违反“知”的有限性，见 `08-intent-first.md` §6.3）。

逐篇按四问记录，答案须落到条款号、版本与出处：

| 问 | 抽取什么 | 落到哪 |
| -- | -------- | ------ |
| 1 适用性 | 该标准／条款是否约束本批？现行有效版本是哪一版，有无被替代 | 清单行的“适用级别”列 |
| 2 约束 | 对本批 FR／NFR、设计与验收的具体约束 | spec 判据、ADR 依据 |
| 3 例外 | 适用条件之外的情形；标准未覆盖的部分明示“标准未覆盖，按项目规则” | spec 非目标、checklist 注记 |
| 4 冲突 | 与项目规则、用户指令或更高位阶规范冲突时的处置 | 位阶处置（见 §5） |

引用必须可定位（标准号＋年份＋条款；URL＋版本），不得只写“业界通常”“一般认为”。二手转述不作依据，须回溯官方原文；史料域的一手优先与联网复核按 `考据规则.md` 执行。

**版本时效**：ISO／IEEE／GB 均有版本演进，引用过期版本或漏核替代关系按缺陷计；GB 区分强制性（GB）与推荐性（GB/T），约束力表述须与属性一致。

## 5. 吃透与落地判据

**吃透＝三可**，逐篇满足；缺任一即未吃透：

| 判据 | 含义 | 证伪方式 |
| ---- | ---- | -------- |
| 可引用 | 条款号／版本／出处可定位，第三方按路径可复核 | 复核者按出处查无此文即 FAIL |
| 可复述 | 能说清适用范围与本批的接合点：哪条约束打在哪个 FR／设计决定上 | 复核者追问“这条约束管什么”，答不出即 FAIL |
| 可判定 | 能写出二值可判的约束条目，不含“应当遵循某某精神”一类空话 | 判据无法写出通过／不通过命令或条件即 FAIL |

**落地＝三转化**，吃透的产出必须至少达成其一，否则视为读而不化：

1. **转化为判据**：FR／NFR 验收判据或 checklist 项；
2. **转化为设计约束**：ADR“现在依据”或设计检查项；
3. **转化为复核判据**：收口核对项（模板 I）。

**位阶处置**：标准与项目规则冲突时，以 `01-规则/` 现行版本为准并登记矛盾（开 TG 或 ADR），不得静默取舍；与用户指令冲突时由 ykla 裁定；标准之间存在位阶（法 > 强制国标 > 推荐国标 > 行业规范 > 建议），按位阶取高。

## 6. 时点、记录与裁剪

- **时点**：G0 立项时锁定清单（分级检索）；G1 需求基线前完成四问抽取；G3 起按三转化勾稽；收口按模板 I 核对。
- **记录**：文献清单与四问记录随批留存——有 spec 的批写在意图确证单之后，无 spec 的小批写在 `tasks.md` 批首；准入审计的“准入证据”可指向清单路径。
- **裁剪**：单次只读查询、单文件小改、格式化可裁为“检索留痕一句”（检索域＋有无适用标准）；裁剪不等于跳过证据。纯内部整理、临时脚本等确无公共约定可循的任务，按裁剪处理并留痕。

## 7. 反模式

| 反模式 | 表现 | 纠正 |
| ------ | ---- | ---- |
| 凭内部知识当依据 | AI 会话凭训练记忆写“标准要求……”而不查原文 | 检索原文，按三可留痕 |
| 二手转述当原文 | 引聚合站、博客转述的标准条文，转述失真不察 | 回溯官方原文；史料域按 `考据规则.md` |
| 过期版本 | 引用已废止版本、漏核替代关系、强制／推荐属性错标 | 版本时效核查写进清单行 |
| 读而不化 | 清单罗列漂亮，判据产出为零 | 三转化缺一即未吃透，退回 §5 |
| 拿标准压项目规则 | 以“国际惯例”“业界共识”推翻项目现行判据 | 位阶处置＋矛盾登记，项目规则优先，除非 ykla 明示改规 |
| 无标准硬凑 | 为满足流程罗列不相关标准 | 无交集不入清单；确无则留检索痕迹 |

## 8. 自反与失效

- **自反**：本件也是形式主义——它只有改变判据、设计决定或收口核对项才成立。若批批产出文献清单却不改变任何 FR／NFR、ADR 依据或 checklist 项，则按 `00-philosophy.md` §9 降级或删除。
- **门禁**：`audit_engineering_practice.py` E13（第二十九件）校验接线（理论件、`13-软件工程/README.md` 登记、`工程实践规则.md` §0.8、`AGENTS.md` 行、模板 I 项）；E13 只验接线，不代替人工判定吃透质量——吃透质量由复核抽查（三可逐篇核）。
- **失效条件**：连续两季文献清单零改变判据（清单不进任何 FR／NFR、ADR 或 checklist）；或全部任务均无公共约定可循且检索留痕证明。
- **复审触发**：2027-02-14 定期复审；E13 连续误报；阅读对象分级（§3）再变更时。
