# 09 反思、理论化与全局回流

> **项目侧增补**（2026-10-29，依 ykla 指令）：本文件不是 WHCode 上游正文，只在本项目生效；上游采纳前按 `NOTICE.md` 版本化回流。适用一切高风险任务、长线战役与结构性变更，不限工程类批次。

本文件只回答一件事：一次任务的教训，怎样才算被真正吸收——不是写在复盘表里，而是提炼成可判定条款、改到全局规则、并成为下一任务的必跑流程。

## 1. 命题与来源

“反思不够深刻”在本文件中的含义是：复盘只停在“这次哪里错了”，没有回答“下次什么条件下必须怎么做、由哪条规则判、由哪个门禁拦”。教训不落到条款与门禁，就只是一次性叙述，下一批仍会重犯。

来源：2026-10-29 本项目 05 大纲小节层重建任务的连续指摘——迁移完成不等于目录成立、标题混在批内导致风格漂移、单一来源定题、批准单位与影响面不匹配、结构加一级却未同步装配与 CI。此前这些只写进任务内“前车之鉴”表，未上升为全局理论，也未成为流程。

## 2. 九条普适原则

每条给“命题→证据→工程含义→判据→反模式→失效条件”。

### 2.1 迁移不是设计

- 命题：把存量对象一对一搬到新容器，只改变位置，不产生新结构；迁移完成不等于设计成立。
- 证据：37,484 个旧子节 1:1 映射到新树后，小节仍是史料桶，题面不合格 68.4%。
- 工程含义：迁移任务与设计任务必须分阶段、分验收；迁移只保证“内容零丢失”，设计另立目标与判据。
- 判据：迁移批的验收是字节守恒与落点存在；设计批的验收是结构可读、题文一致、单元可命名。两套判据不得互相替代。
- 反模式：以“已落盘 15,206 件”证明目录已建成。
- 失效条件：目标结构与被迁移对象同构且无需重新命名时。

### 2.2 多源合成与单源禁令

- 命题：结构、标题、需求等“命名与归属”判断不得由单一来源决定；至少两源，专名类至少三源。
- 证据：只看大纲会造无史料支撑的题；只看史料会复现装箱形态；只看联网会脱离目录边界；只看规则会得到正确但无内容的空题。
- 工程含义：四类来源各司其职——史料定内容，目录分析定层级，联网定专名与年代，规则定体例与术语；冲突按固定层级裁决。
- 判据：每条判断有四源矩阵；单源项不得批准，进例外；缺项须显式标注而非静默。
- 反模式：以“设计优先”为名只看大纲；以“证据充分”为名只看史料；以“官方口径”为名只看联网。
- 失效条件：判断对象无外部事实成分且无结构归属争议时（仍须至少两源）。

### 2.3 意图先于素材

- 命题：先定“要论证什么”，再择“拿什么论证”；素材不得反向定义结构。
- 证据：先读 544 块再拟题，题名必然被首块或最大块绑架；先拟题再读块，才能按论题择取。
- 工程含义：标题、需求、接口等“意图层”先冻结；素材、证据、实现等“手段层”后择取；意图变更走变更控制，不悄悄迁就素材。
- 判据：意图层产物先于素材层产物；素材层不得新增意图层未列出的主题；不匹配素材走挂账或例外。
- 反模式：边读素材边改目标；以“素材里只有这些”为由降低验收判据。
- 失效条件：任务本身是探索性盘点、目标就是“素材里有什么”时（仍须先声明盘点口径）。

### 2.4 批准单位与影响面匹配

- 命题：批准单位应等于一次变更的影响面；影响面是卷、章、模块或批次，就按该单位批准，不按单条、也不按更小的批次。
- 证据：单题批准成本过高且无法看风格一致性；按批批准又跨不过卷边界；卷级批准既能看整卷风格，又能一次放行。
- 工程含义：批准记录须含范围、数量、台账哈希、批准人、时间；台账变动即使批准失效，须重批；执行者不得自批。
- 判据：批准标记与当前台账哈希一致；无标记或哈希不符者不得合并、不得进入下游；变更即失效。
- 反模式：以口头“继续”替代记录；以会话自写标记替代批准；以旧标记覆盖新台账。
- 失效条件：变更影响面小于最小批准单位且风险可忽略时（须在规则中明写裁剪）。

### 2.5 结构变更的涟漪义务

- 命题：文档、目录、数据模型加一级或改一层，必须同批修订所有依赖它的装配器、门禁、镜像、口径、CI 与回归；否则新结构在部分环节假绿。
- 证据：装配器拒绝四级行、注册表忽略缩进行、CI 未收录新门禁——结构未同步时，页面与门禁各自“看起来正常”。
- 工程含义：结构变更的验收不是“源文件改完”，而是“源→装配→页面→门禁→CI→口径→回归”全链一致。
- 判据：列出受影响件清单并逐件核对；任一依赖件未改即不得收口；CI 与 README 闸层清单逐项一致。
- 反模式：只改内容源，把装配器与门禁留到“下一批”；以本地通过替代 CI 通过。
- 失效条件：结构变更不影响任何下游件时（须有依赖图证据）。

### 2.6 门禁假设会过期

- 命题：门禁的判据建立在当时的对象模型上；对象模型变了，门禁的旧假设会失效，继续跑就是假绿或误杀。
- 证据：L2／L3／L11 假定“一源一落点”，新设计允许一源拆多小节；不重审就会阻断正确设计或放过错误落点。
- 工程含义：结构变更须同时做“门禁假设审计”：逐条问“这条判据的前提还成立吗”；不成立者改判据、加模式或登记技术债，不得放任。
- 判据：结构变更批的产物含门禁假设审计表；每条判据标“前提仍成立／已修订／暂挂技术债”。
- 反模式：结构改了、门禁绿了，就认为门禁仍有效；以“先跑通”替代“判据仍成立”。
- 失效条件：结构变更不触及门禁输入模型时。

### 2.7 守恒与可逆

- 命题：删除、清空、重排之前必须先还原或备份；变更须有块级守恒账与字节保真；每批须可回退。
- 证据：旧树“迁出即删”导致 15,206 件只剩 Git 可回溯；先还原再清空才做到零丢失。
- 工程含义：破坏性操作的前置是“可还原”；执行中是“逐件账”；收口是“守恒等式”；回退是 `git revert`，不是手工倒回。
- 判据：还原源可定位；逐件 sha256；入纲＋挂账＋移出＋删除＋未处理＝总量；每批有提交哈希。
- 反模式：先删后想；以“Git 里有”替代可还原验证；以“差不多”替代守恒等式。
- 失效条件：操作可完全再生且无唯一内容时。

### 2.8 共享单文件单写者与并行独立性

- 命题：多个执行者共享一个文件时，必须设单一写者或分片合并；并行单位须在写面上互不相交。
- 证据：121 批并行落盘没有 `outline.txt` 写协议；裸节号在 76 卷重复 74 次，朴素合并不幂等。
- 工程含义：共享文件由合并器单写；执行者只写自己的分片、占锁与完成记录；合并幂等；陈旧锁可接管；提交即断点。
- 判据：写者表明确；同一文件同时只有一个写者；分片与合并双向可验；任意中断可由新执行者按台账续跑。
- 反模式：多会话直接改同一文件；以“冲突很少”替代写协议；以自报完成替代文件系统核验。
- 失效条件：并行单位在写面上完全隔离且无共享汇总件时。

### 2.9 反思即流程

- 命题：反思只有成为流程才成立——教训→普适性判定→条款/ADR/TG→全局回流→门禁接线→下一任务引用。
- 证据：此前“前车之鉴”只写在任务内，未进 `13-软件工程/`，未进 `工程实践规则.md`，下一批仍可绕过。
- 工程含义：高风险任务、长线战役与结构性变更收口后，必须走 G6；普适条款写进理论件与全局规则，项目特定条款写进项目规则；不普适者登记“不回流理由”。
- 判据：G6 产物齐（复盘表、普适性判定、理论件/规则修订、TG 登记、门禁 E9、下一任务引用）；缺一不得标“已完成”。
- 反模式：复盘表只写“本次经验”；把项目特定教训硬说成普适理论；写了条款但不改门禁、不引用。
- 失效条件：任务无新教训且连续两季 G6 零改变决策时（降级为轻量记录）。

## 3. G6 反思与理论化门禁

### 3.1 触发

- 高风险任务（P0、删除、写库、结构变更、平台承诺、规则实质判据）；
- 长线战役的每个收口批；
- 任何“结构加一级/改一层”的变更；
- 任何出现“同类问题第二次发生”的批次。

### 3.2 输入

- 本任务复盘表（教训、证据、影响面）；
- 旧任务复盘与历史缺陷；
- 现行 `13-软件工程/` 与 `工程实践规则.md`；
- 门禁输出与失败记录。

### 3.3 活动

1. 逐条教训问“这是本项目特有，还是可普适？”；
2. 可普适者写成“命题→证据→工程含义→判据→反模式→失效条件”六段；
3. 项目特定者写进项目规则，并登记“不回流理由”；
4. 修订理论件与全局节，登记 `TG-NNN` 与 `NOTICE.md`；
5. 接线门禁（E9）与下一任务引用位；
6. 回写 `AGENTS.md` 与规则索引。

### 3.4 产物

- 复盘表（`01-项目管理/02-工程决策与技术债/任务复核台账.md` 或任务报告）；
- 普适性判定表（每条：普适/特定/不回流理由）；
- 理论件修订（`13-软件工程/`）或项目规则修订；
- `TG-NNN` 登记（`软件工程理论缺口与增补登记.md`）；
- `NOTICE.md` 回流条目；
- 门禁 E9 接线；
- 下一任务 `tasks.md`/`checklist.md` 的引用行。

### 3.5 退出判据

- 每条教训有归属（理论件/项目规则/不回流）；
- 每条普适条款有判据、反模式、失效条件；
- 全局文件与索引已改，门禁 E9 PASS；
- 下一任务已引用新条款；
- 缺一不得标“已完成”。

### 3.6 裁剪

- 普通任务可只做“复盘表＋是否普适”两栏；
- 结构性变更与高风险任务不得裁剪；
- 裁剪不等于跳过证据：仍须留下“为什么不需要修订全局”的一句话。

## 4. 与 G0–G5 的关系

- G6 在 G5 之后，但不是发布后的装饰：它把本任务的教训回灌到 G0（范围）、G1（需求）、G2（设计）、G3（门禁）与 G4（验收）。
- G6 的产物是下一任务的输入；下一任务的 G0 必须读取上一条 G6 的条款。
- G6 失败不得阻止本任务交付，但不得把本任务标为“已完成”；应标“已交付，理论化未收口”，并保留 G6 待办。

## 5. 反模式与失效条件

| 反模式 | 表现 | 纠正 |
| ---- | ---- | ---- |
| 复盘即结项 | 写一张“经验教训”表就归档 | 走 G6 六步，产物齐才算收口 |
| 教训私有化 | 只写进任务报告，不改全局规则 | 普适条款进理论件与全局节 |
| 普适冒充 | 把项目特定做法说成通用理论 | 写“不回流理由”，项目规则承载 |
| 条款空转 | 写了条款但不改门禁、下一任务不引用 | E9 校验接线与引用 |
| 二次复发 | 同类问题第二次出现仍只记录 | 升级为 G6 强制触发 |

失效条件：连续两季 G6 零改变决策、零门禁变化、零下一任务引用；或全部任务均为一次性且无长线。此时按 `00-philosophy.md` §9 降级为轻量复盘，保留 G6 触发条件与记录格式。

## 6. 自反

本文件也是形式主义：它只有在改变理论件、全局规则、门禁或下一任务时才成立。若 G6 只产出复盘表而不改任何条款与门禁，应按 `00-philosophy.md` §9 删除或降级。
