# 工程实践模板说明

本目录存放工程实践的项目化模板。模板不是规则正文，规则正文在 `00-编纂规则与格式规范/01-规则/`；模板只提供可填写的字段与项目路径，避免每次从零起草。

## 模板清单

| 模板 | 用途 | 何时使用 | 对应规则 |
| ---- | ---- | -------- | -------- |
| [模板G-架构决策记录.md](模板G-架构决策记录.md) | 记录架构、门禁、目录、依赖、数据所有权、权限边界、平台承诺与不可逆格式变更 | 新增模块／脚本／门禁／模板／目录、跨层调用、平台或权限承诺变化 | `工程实践规则.md`“ADR 与形式主义审查” |
| [模板H-技术债登记.md](模板H-技术债登记.md) | 登记已接受但未偿还的工程缺口 | 审计发现缺口、本批不修、偿还条件未满足 | `工程实践规则.md`“技术债登记” |
| [模板I-批次提交核对清单.md](模板I-批次提交核对清单.md) | 批次收口前的提交核对 | 每批提交前 | `流程规则.md` G5 与 Git 暂存规则 |
| [模板J-工程实践复审.md](模板J-工程实践复审.md) | 季度或试点后的复审记录 | 复审到期或提前触发 | `工程实践规则.md`“复审与回流” |

## 与教义模板的关系

- 规格、任务、验收：以 `13-engineering-doctrine/templates/spec.template.md`、`tasks.template.md`、`checklist.template.md` 为基线；本项目使用时只补 `change-id`、真实路径、FR/NFR 编号与追溯表，不复制教义正文。
- 形式主义审查：以 `13-engineering-doctrine/templates/philosophy-review.template.md` 为基线；若已使用 ADR，可把审查字段并入 ADR，不重复填写。
- 并发档案：以 `13-engineering-doctrine/templates/concurrency-dossier.template.md` 为基线；仅在 04 专项触发时使用。
- 本目录不重复上述教义模板；若教义模板更新，以教义文件为准，本目录只保留项目化差异。

## 使用纪律

1. 模板中的占位符必须替换为项目真实路径、命令、门禁名；未替换的占位符不得提交。
2. 不把模板当规则；模板字段与规则冲突时，以规则为准并开 ADR 修正。
3. 模板新增或删除须同步 `工程实践规则.md` 的引用与 `audit_engineering_practice.py` 的 E4 判据。
4. 所有模板文件 UTF-8 无 BOM、LF；中文正文引号用“”或‘’。
