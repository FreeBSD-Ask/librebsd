# 批次提交核对清单（模板）

> 每批提交前逐项核对；未实现事项必须明确标记并写明当前行为。本清单是 `13-软件工程/templates/pr-checklist.template.md` 的项目化版本；本项目无 PR 平台，以批次提交替代。

## 1. 范围与需求

- [ ] 需求／缺陷编号与范围明确，`spec.md`、`tasks.md`、`checklist.md` 三件齐备。
- [ ] 意图确证单已写（档 A 六字段／档 B 三要素）：用户原话、目标、非目标、验收判据、手段自由度、未知；目标／手段未倒置。
- [ ] FR／NFR 编号、来源、验收判据、证据位置与证伪条件已填写；追溯链无孤儿。
- [ ] 非目标逐条列出；未实现事项已标注并写明当前行为。
- [ ] 本批适用 G0–G5 阶段与裁剪行已在 `tasks.md` 标明；04／05／06 专项或不适用理由已写明。

## 2. 设计与决策

- [ ] 新增模块／脚本／门禁／模板／目录、跨层调用、权限或不可逆格式变更已有 ADR。
- [ ] ADR 十二项字段齐全；负面成本与承担者写明。
- [ ] 既有规则改动有审计编号、前后对照与迁移指针；删除或合并项有 Git 取证位置（`git show <提交>:<路径>`，不落旁路副本）。
- [ ] 0 信任复核：报错、文档与外部事实有独立复现或交叉验证。

## 3. 实现与验证

- [ ] 正向测试与失败路径测试已更新；失败路径包含超时、取消、权限拒绝或数据缺失等适用项。
- [ ] 脚本改动按 `流程规则.md` 脚本执行安全规程完成复核、演示、再复核与正式执行。
- [ ] 并发／性能改动附并发档案、同夹具前后对比与回退方案；无改动则写明不适用。
- [ ] 安全改动附威胁模型、攻击面、证据、代价与失效条件；凭据未进入日志、夹具、事件或提交。
- [ ] 目录页改动走九件门禁、三套浏览器回归、无障碍与页面资产门禁；未改动则写明不适用。

## 4. 证据与门禁

- [ ] 门禁输出含命令、环境、日期、判据结果与未通过项；未取得证据的项标“阻塞／未取得”。
- [ ] `audit_engineering_practice.py` 已跑；ADR／技术债／模板／规则登记／复审日期均通过或已登记例外。
- [ ] `audit_gate_registry.py` R1–R8 全 PASS；新门禁已有阶段归属。
- [ ] `sync_refactor2026_baseline.py --check`、`_longline_status.py --check` 通过。
- [ ] markdownlint、直角引号、加粗空格、不可见字符、CRLF／BOM 门禁通过。

## 5. 记录与提交

- [ ] `changelog.duckdb` 已登记；写入前跑 `claimdb_guard.py --db <库名>`，并打印库文件 SHA-256＋在 `12-数据库备份/<db>/` 落专项正式备份（不落工作区副本），`id` 为回库实测 `max+1`。
- [ ] 仅暂存相关文件；未加入 `.trae/specs/`、`script/` 临时件、单个大于 5 MB 的文件或被 `.gitignore` 排除的条目。
- [ ] 提交说明符合 `type(scope): 摘要`，正文写“为什么”；GPG 签名绕过按既有裁定留痕。
- [ ] 提交后回报：改了什么、证据在哪、还有哪些未取得。

## 6. 提交后

- [ ] 工作区仅余他线未提交改动；本批暂存区为空。
- [ ] 本批产生的偏差已回流规则／模板／门禁，或登记技术债。
- [ ] 下一批复审日期与触发已登记。
