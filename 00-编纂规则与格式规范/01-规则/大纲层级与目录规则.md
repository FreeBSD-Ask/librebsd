# 大纲层级与目录规则（2026-10-18 立）

> **来源与效力**：本规则由《05-卷册大纲标准化计划书 v5》批 2 设立，取代原 `05-卷册大纲/.writing_rules.md`（2026-09-11 WO-007 版、2026-10-17 目录洁净规则版）。适用树＝`05-新大纲/`（主理人手动原子替换后即 `05-卷册大纲/`，下称"大纲树"）。本规则是大纲层级标准与作业纪律的唯一规则载体。

## 一、层级模型

1. 大纲树四层：卷→章→节→小节。**小节是唯一 .md 文件层**（`N.M.P-slug.md`）；卷、章、节三级一律为纯目录，不得含除子目录外的任何文件（包括 index.md、概述.md、00-总览.md 与任何散件）。
2. 命名法：卷 `第NN卷-slug`（NN 两位零填充，slug 小写，长度不超过 40 字符）；章 `第N章-slug`（全局章号，不补零；章题禁 ABCD、上下等编号后缀）；节 `N.M-slug`；小节 `N.M.P-slug.md`。
3. 结构骨架（允许为空，逐件登记）：每卷固定"卷总览章"（卷首）与"卷末书目述评章"（卷尾，缺失卷建空骨架）；每章第 1 节固定为"章级综合"。骨架空件只登记不撰写（正文编纂红线不变）。
4. 第20卷平铺史料增补件章化后与其他卷同构；重号（154–161、170、171 两族）随分章自然消解。

## 二、编号总纲

1. 章号全局连续唯一，按卷序分块递增；节号章内连续唯一；小节号节内连续唯一。禁止空洞、重号、跳号；历史空洞一律重编闭合。
2. 插入或删除章、节、小节必须全量重排受影响层号，并同步 SUMMARY 镜像与 chapter_keywords.json。
3. 引用改写（"第 N 章""N.M 节""N.M.P"）逐处替换、逐处留痕，禁正则盲替。

## 三、尺寸打散

1. 任何 .md 文件字节数超过 16,797（基线中位数 12,921 B × 1.3，2026-10-18 测定，不中途重算）必须拆分打散重构。
2. 拆分优先沿用既有 `##`／`###` 标题层级；单标题块仍超阈者按段落组判读打散为兄弟小节，禁留尾巴。
3. 拆分不得增删 ROW_MINE／DEEP_ANALYSIS／[DB: 锚总量；引文与逐字保真内容禁改写；正文禁撰写。

## 四、SUMMARY 镜像

1. SUMMARY.md 与 chapter_keywords.json 存放于 `11-元数据接口/03-大纲目录镜像/`（2026-10-18 自大纲树根迁出）。
2. 镜像与大纲树双射：树中每个卷、章、节、小节在镜像恰有一条，缩进四层（卷 0、章 2、节 4、小节 6），显示标题与磁盘名逐字一致；空文件照列；镜像不得含树外条目或死链。
3. 任何结构变动后必须再生镜像并通过双射校验；chapter_keywords.json 的 keys 用新全局章号，subs 字段不得恒空。

## 五、写入幂等（WO-007 续）

1. 任何脚本向大纲树写入内容前必须 import `00-编纂规则与格式规范/01-规则/脚本与命令/wo007_idempotency.py`。
2. 写入前调用 `has_block(text, 块标记)` 检查目标块是否已存在；已存在则跳过或走更新逻辑，禁止重复追加。
3. 写盘统一走 `write_guard(path, text, repo=...)`：库名规范化（*.db→*.duckdb；bsd_commits.db 须给 repo）＋强制 UTF-8 无 BOM＋LF。
4. 违反以上任一步的写入视为生成器缺陷，整批登记并重跑。

## 六、目录洁净（v2）

1. 大纲树根级只允许 24 个卷目录，禁止任何文件（含派生件、索引件、临时件）；派生权威件（SUMMARY 镜像、chapter_keywords.json）置 `11-元数据接口/03-大纲目录镜像/`，临时清单、日志、脚本、压缩包一律置 `script/`。
2. 大纲树标准化战役及后续对大纲树的批量写入禁止创建任何写前／写后备份副本（含 `script/_bak/` 与树内 `.bak` 类后缀或改名副本）——git 历史是唯一留痕与回滚机制（2026-10-18 主理人裁定，替代 prebak 纪律）；其他战役的备份纪律不受本条约束。
3. 违规处置：识别→登记→移出→复验（.md 件数与总字节数守恒）。
4. 换行：写入一律经 `write_guard()` 或显式 `newline="\n"`；兜底判据 `audit_disk_terminology.py` T2（在效面 .md 含 CRLF／孤立 CR＝0，按字节判）。

## 七、作业提交纪律

1. 按批提交：每批完成即 git commit，高破坏批按卷分子波提交、禁大单提交；提交说明一律经消息文件 `git commit -F`（多段 `-m` 传参在本机实测会被 commit-msg 门禁误判为无放行标记而拒收，2026-10-18 实测，禁用）。
2. **暂存即提交（2026-10-18 主理人令）**：任何操作产生暂存区后必须立即以 pathspec 限定本次改动路径提交，禁止暂存跨操作滞留——并发会话与后续提交会把滞留暂存收编进错误的提交（批 4 实测事故：滞留暂存被后续卷提交与他线收编提交三次卷走）。
3. 批前确认 `git status --porcelain` 对大纲树为空并记录批前 HEAD；机器锚三数（ROW_MINE／DEEP_ANALYSIS／[DB:）批前批后断言相等，批后另跑锚 ID 多重集差（集合相等不排除次数变化，须按次数比对）。
4. 回滚一律 `git revert` 或 `git checkout <提交哈希>`，禁手工删改"倒回去"。

## 八、拆并留痕（2026-10-18 批 4 实测补立）

1. 原 index.md／概述.md 的"本章节索引"段与 00-总览.md 的"本卷章目"段**不删除**：段内可载口径说明、编辑注记等实质内容（批 4 实测丢失实例），一律改题为"×××（原样留痕）"后并入章级综合／卷总览作为小节保留。
2. 索引的导航职能由 SUMMARY 镜像承担；留痕段不再是索引，批 6 判读可再行拆并。
