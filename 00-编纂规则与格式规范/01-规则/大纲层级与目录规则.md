# 大纲层级与目录规则（2026-10-18 立）

> **来源与效力**：本规则由《05-卷册大纲标准化计划书 v5》批 2 设立，取代原 `05-卷册大纲/.writing_rules.md`（2026-09-11 WO-007 版、2026-10-17 目录洁净规则版）。适用树＝`05-卷册大纲/`（原 `05-新大纲/`；2026-10-21 已由 ykla 原子替换，下称“大纲树”）。本规则是大纲层级标准与作业纪律的唯一规则载体。

## 一、层级模型

1. 大纲树四层：卷→章→节→小节。**小节是唯一 .md 文件层**（`N.M.P-slug.md`）；卷、章、节三级一律为纯目录，不应含除子目录外的任何文件（包括 index.md、概述.md、00-总览.md 与任何散件）。
2. 命名法：卷 `第NN卷-slug`（NN 两位零填充，slug 小写，长度不超过 40 字符）；章 `第N章-slug`（**卷内章号，一位零填充，每卷永远以第一章开始**，与目录页 `index.html`／`data/outline.txt` 的 `## 第 N 章` 语义一致；章题禁 ABCD、上下等编号后缀）；节 `M.N-slug`（M＝卷内章号）；小节 `M.N.P-slug.md`（P 允许 1—4 位）。
3. 结构骨架（允许为空，逐件登记）：每卷固定“卷总览章”（卷首）与“卷末书目述评章”（卷尾，缺失卷建空骨架）；每章第 1 节固定为“章级综合”。骨架空件只登记不撰写（正文编纂红线不变）。
4. 第20卷平铺史料增补件章化后与其他卷同构；重号（154—161、170、171 两族）随分章自然消解。
5. `data/outline.txt` 四级行语法（2026-11-06 立，`ADR-0020`）：卷＝`# 题名`、章＝`## 第 N 章 题名`、节＝`- M.N 题名`、**小节＝两个前导空格＋`- M.N.P 题名`**（M＝卷内章号、N＝节号、P＝节内小节号，P 自 1 起节内连续唯一，前两段应与父节号一致；题名非空，禁 ABCD 等字母编号后缀）。小节行支持与节行同一套 `@@` 定界注文：前置形 `- 2.3.1 @@〔分工：…〕@@ 题名`、后置形 `- 2.3.1 题名@@〔时间：…〕`；语言标记 `⟦lang:…⟧` 同节行适用。`outline.txt` 小节行的**唯一写者**为合并器 `merge_subsections.py`（卷批并行、幂等合并；只收 `title.ok`／`land.ok` 齐备且 `ledger_sha256` 一致的卷），会话与脚本不应直写四级行。`映射/targets.tsv` 同步注册 `level=subsec` 节点：稳定 ID `SS-` ＋ 7 位零填充全局序号，`sec_no` 列承载 `M.N.P` 三段形态，三级节点与既有 ID 保留不替代。数据落盘前 `outline.txt` 零小节行为合法零态（小节总数 N 由 `doc-metrics` 占位，收口回填）。

## 二、编号总纲

1. **卷内章号连续唯一**（每卷 1..K，2026-10-23 ykla 裁定：每卷永远以第一章开始，章目录号与目录页一致）；节号章内连续唯一；小节号节内连续唯一。不应空洞、重号、跳号；历史空洞一律重编闭合。全书跨卷唯一的章序号仅存于 `映射/targets.tsv` 的稳定 ID（`C-0001`…`C-0nnn`），不进目录名。
2. 插入或删除章、节、小节应全量重排受影响层号，并同步根级三件 `SUMMARY.md`、`chapter_keywords.json`、`theme_index.json`（由 `sync_outline_mirror.py --write` 一次再生）。
3. 引用改写（“第 N 章”“N.M 节”“N.M.P”）逐处替换、逐处留痕，禁正则盲替。

## 三、尺寸打散

1. 任何 .md 文件字节数超过 16 797（基线中位数 12 921 B × 1.3，2026-10-18 测定，不中途重算）应拆分打散重构。
2. 拆分优先沿用既有 `##`／`###` 标题层级；单标题块仍超阈者按段落组判读打散为兄弟小节，禁留尾巴。
3. 拆分不应增删 `ROW_MINE`／`DEEP_ANALYSIS`／`[DB:` 三类锚的总量；引文与逐字保真内容禁改写；正文禁撰写。

## 四、SUMMARY 镜像

1. 根级三件 `SUMMARY.md`、`chapter_keywords.json`（schema `theme-index/4`）、`theme_index.json`（schema `theme-reverse/2`）存放于 `05-卷册大纲/` 根（2026-10-21 ykla 裁定废除 `11-元数据接口/03-大纲目录镜像/`）。**同步／再生一律由 `脚本与命令/sync_outline_mirror.py` 执行**：SUMMARY 由本脚本生成，主题索引委派 `脚本与命令/build_theme_index.py`；`--check` 三件双射与哈希比对，`--write` 一次写三件，`--selftest` 判据非空；原 `sync_gitbook_summary.py`／`sync_chapter_keywords.py` 已停用，不适用于标准化树；其路径硬编码现行 `05-卷册大纲/`，对旧树无效。
2. 镜像与大纲树双射：树中每个卷、章、节、小节在镜像恰有一条，缩进四层（卷 0、章 4、节 8、小节 12），显示标题与磁盘名逐字一致；空文件照列；镜像不应含树外条目或死链。**镜像条目为纯文本缩进行（`- 标题`），禁 Markdown 链接与 URL 编码**（2026-10-27 ykla 裁决去链接化：双射按序位配对判据执行，S_MISSING／S_EXTRA／S_DEAD 由 S_COUNT 与序位题面核对吸收；导航职能由 `index.html` 承担）；生成器与 `parse_summary` 校验器同源同语法，改一处必同批改另一处。
3. 任何结构变动后应再生三件并通过双射／哈希校验；`chapter_keywords.json` 用 schema `theme-index/4`（节／小节键为“卷／章／节”复合键 `V01-C001-1.1`，避免跨章 `N.M` 碰撞），普通节 3—6 词、元节 1—3 词，小节差分与 `subs_sha1` 同步；词质与禁用泛词由 `audit_keyword_index.py` 判定。树内无小节正文（`meta.subsections == 0`）时该件的 C5／C6 条件跳过，详见 `流程规则.md`“新大纲主题词索引规则”。
4. 根级三件（`SUMMARY.md`、`chapter_keywords.json`、`theme_index.json`）的 Git 入库状态由 `脚本与命令/audit_mirror_ingest.py`（第二十五件）校验——存在、已跟踪、不被 `.gitignore` 命中、不在 `git status --ignored` 清单，每次再生或提交前必跑。根 `.gitignore` 全局 `*.json` 规则下，两个 JSON 应保留显式豁免；SUMMARY.md 超过 5 MB 时提交应按 `git_commit_gate.py` G2 带 `APPROVED-BIGFILE:` 放行标记；`audit_mirror_ingest.py` 只判 E1—E4（存在／已跟踪／不被忽略／不在 ignored 清单），不判体积。

## 五、写入幂等（WO-007 续）

1. 任何脚本向大纲树写入内容前应 import `00-编纂规则与格式规范/01-规则/脚本与命令/wo007_idempotency.py`。
2. 写入前调用 `has_block(text, 块标记)` 检查目标块是否已存在；已存在则跳过或走更新逻辑，不应重复追加。
3. 写盘统一走 `write_guard(path, text, repo=...)`：库名规范化（*.db→*.duckdb；bsd_commits.db 应给 repo）＋强制 UTF-8 无 BOM＋LF。
4. 违反以上任一步的写入视为生成器缺陷，整批登记并重跑。

## 六、目录洁净（v2）

1. 大纲树根级除 24 个卷目录外，只允许 2026-10-21 ykla 令的四件；其余文件（含派生件、索引件、临时件、日志、脚本、压缩包）一律不应置根级，临时件置 `script/`。**例外四件**：`05-卷册大纲/` 根级允许并应保留——`SUMMARY.md`、`chapter_keywords.json`、`theme_index.json`、`前后差异细粒度比较表-20261021.md`；前三件由 `sync_outline_mirror.py --write` 同批再生，第四件随复核批次更新。
2. **全库**（不限于大纲树）不应创建任何写前／写后备份副本——含 `script/_bak/`、`prebak-*`、树内 `.bak` 类后缀或改名副本、`.orig`／`.rej`／`~` 残留；Git 历史是唯一留痕与回滚机制，数据库快照唯一走 `12-数据库备份/` 正式槽（2026-10-18 立，2026-10-23 由用户令扩至全库；细则见 `流程规则.md`“临时文件规则”）。
3. 违规处置：识别→登记→移出→复验（.md 件数与总字节数守恒）。
4. 换行：写入一律经 `write_guard()` 或显式 `newline="\n"`；兜底判据 `audit_disk_terminology.py` T2（在效面 .md 含 CRLF／孤立 CR＝0，按字节判）。

## 七、作业提交纪律

1. 按批提交：每批完成即 git commit，高破坏批按卷分子波提交、禁大单提交；提交说明优先经消息文件 `git commit -F`；多段 `-m` 于 2026-10-22 实测可被 commit-msg 门禁接受，不再禁用，但长正文仍推荐 `-F` 以便留全文。
2. **暂存即提交（2026-10-18 ykla 令）**：任何操作产生暂存区后应立即以 pathspec 限定本次改动路径提交，不应暂存跨操作滞留——并发会话与后续提交会把滞留暂存收编进错误的提交（批 4 实测事故：滞留暂存被后续卷提交与他线收编提交三次卷走）。
3. 批前确认 `git status --porcelain` 对大纲树为空并记录批前 HEAD；机器锚三数（ROW_MINE／DEEP_ANALYSIS／[DB:）批前批后断言相等，批后另跑锚 ID 多重集差（集合相等不排除次数变化，应按次数比对）。
4. 回滚一律 `git revert` 或 `git checkout <提交哈希>`，禁手工删改“倒回去”。

## 八、拆并留痕（2026-10-18 批 4 实测补立）

1. 原 index.md／概述.md 的“本章节索引”段与 00-总览.md 的“本卷章目”段**不删除**：段内可载口径说明、编辑注记等实质内容（批 4 实测丢失实例），一律改题为“×××（原样留痕）”后并入章级综合／卷总览作为小节保留。
2. 索引的导航职能由 SUMMARY 镜像承担；留痕段不再是索引；后续如确需拆并，应另批给出对象、判据与期限。

## 九、目标注册表与漂移机制

1. 目标注册表与漂移机制的执行器为 `脚本与命令/outline_registry.py`：由 `05-卷册大纲/目录/data/outline.txt` 派生稳定节点 ID 并生成 `05-卷册大纲/映射/targets.tsv`，`--check`／`--sync` 检测与同步漂移，`--selftest` 自证六类漂移场景。
