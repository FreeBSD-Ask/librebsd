# 主题规则

本文件汇总 FreeBSD 历史书编纂项目中所有与特定主题（合规认证标准叙事、FreeBSD 不持有证书区分、Linux 文化挪用、仅 FreeBSD 内容跨 BSD/UNIX/macOS 扩展）相关的撰写规范。涉及相关主题的撰写须逐条对照本文件执行，不得跳过。

## 合规认证标准叙事要求

涉及 POSIX、C 标准、RFC、FIPS 140、Common Criteria、SSDF Attestation、FISMA、FedRAMP、HIPAA、SOX、GDPR、CCPA、CPRA、PIPL、LGPD、PIPEDA、DPDPA、DORA 等合规认证标准的叙事须遵循 0 信任原则，认证证书编号、标准发布日期、法案生效日期等关键事实须经 NIST CMVP、IEEE Xplore、The Open Group、EUR-Lex 等权威来源交叉验证。

具体执行要求：

- **0 信任原则适用**：所有合规认证标准的叙事须遵循 0 信任原则，不得仅凭单一来源采信。
- **关键事实交叉验证**：认证证书编号、标准发布日期、法案生效日期等关键事实须经以下权威来源交叉验证：
  - **NIST CMVP**（Cryptographic Module Validation Program）：FIPS 140 相关证书验证。
  - **IEEE Xplore**：POSIX、IEEE 标准相关发布信息验证。
  - **The Open Group**：UNIX 03、Common Criteria 相关认证信息验证。
  - **EUR-Lex**：GDPR、DORA、PIPEDA 等欧盟法案原文与生效日期验证。
  - **其他权威来源**：HIPAA（HHS.gov）、SOX（SEC.gov）、CCPA/CPRA（oag.ca.gov）、PIPL（npc.gov.cn）等法案的官方发布机构。
- **覆盖标准范围**：本规则覆盖以下合规认证标准（含但不限于）：
  - **技术标准类**：POSIX、C 标准、RFC、FIPS 140、Common Criteria、SSDF Attestation。
  - **美国合规类**：FISMA、FedRAMP、HIPAA、SOX。
  - **数据保护类**：GDPR（欧盟）、CCPA/CPRA（加州）、PIPL（中国）、LGPD（巴西）、PIPEDA（加拿大）、DPDPA（印度）。
  - **金融合规类**：DORA（欧盟）。
- **关键事实类型**：须交叉验证的关键事实包括认证证书编号、标准发布日期、法案生效日期、版本号、修正案编号等。

## FreeBSD 不持有证书须明确区分

FreeBSD 本身不持有 FIPS 140、Common Criteria、UNIX 03、FedRAMP 等形式认证，叙事中须明确区分“FreeBSD 作为运行环境被列入证书”与“FreeBSD 持有证书”两类事实，不得模糊表述。

具体执行要求：

- **FreeBSD 不持有证书**：FreeBSD 本身不持有 FIPS 140、Common Criteria、UNIX 03、FedRAMP 等形式认证，叙事中须明确这一事实。
- **两类事实区分**：叙事中须明确区分以下两类事实：
  - **FreeBSD 作为运行环境被列入证书**：例如某产品在 FreeBSD 上运行并通过 FIPS 140 认证，证书中标注 FreeBSD 为运行环境。
  - **FreeBSD 持有证书**：例如 FreeBSD 项目本身申请并获得某项认证（实际上不存在此类认证）。
- **禁模糊表述**：不得使用“FreeBSD 通过了 FIPS 140 认证”“FreeBSD 获得 Common Criteria 认证”等模糊表述。
- **正确表述示例**：应表述为“产品 X 在 FreeBSD 13.1 上运行，其 FIPS 140 认证证书（编号 Y）中将 FreeBSD 列为运行环境”。

## Linux 文化挪用研究规范

使用“文化挪用”而非“借鉴/参考/启发”等淡化措辞；遵循 0 信任原则：每个案例须有独立来源交叉验证，不得仅凭单一来源采信；案例考据须留痕：在辨析字段或脚注中记录查证来源、交叉验证方法；已知案例包括但不限于：发行版概念、容器概念、概念文化挪用现象、模式、许可证概念，以及 sudo 最初面向 4.1BSD 等；目标是收集更多 Linux 世界类似的文化挪用现象和模式并整理到对应内容中。

具体执行要求：

- **措辞统一**：使用“文化挪用”一词，不使用“借鉴”“参考”“启发”“受影响”等淡化措辞。
- **0 信任原则适用**：每个文化挪用案例须有独立来源交叉验证，不得仅凭单一来源采信。
- **案例考据留痕**：在辨析字段或脚注中记录查证来源（具体 URL、文献页码）、交叉验证方法（独立来源数量、差异维度）、存疑判定依据。
- **已知案例清单**：已知 Linux 文化挪用案例包括但不限于：
  - **发行版概念**：Linux 发行版概念源自 BSD 的 Ports 与二进制软件包体系。
  - **容器概念**：Linux 容器概念源自 BSD 的 jail 与 chroot 机制。
  - **概念文化挪用现象**：其他被挪用的概念（须个案考据）。
  - **模式**：被挪用的工程模式、设计模式。
  - **许可证概念**：开源许可证相关概念被挪用的情况。
  - **sudo 最初面向 4.1BSD**：sudo 工具最初为 4.1BSD 系统开发，后被 Linux 社区挪用并普遍误认为 Linux 原创。
- **收集目标**：持续收集更多 Linux 世界类似的文化挪用现象和模式，整理到对应章节内容中。
- **考据要求**：每个新增案例须按 0 信任原则考据，提供独立来源交叉验证，并在辨析字段或脚注中留痕。

## 仅 FreeBSD 内容跨 BSD/UNIX/macOS 扩展规则

涉及“仅 FreeBSD”内容（即大纲要点/史料/辨析字段仅出现 FreeBSD 主体叙事而未提及其他 BSD/UNIX/macOS 对应实现的子节）的识别、核查与扩展须遵循本规则。本规则与 `bsd-comparison-os-lag-architecture-research-2026-07-28` 等 spec 互补——spec 产出研究材料（36 条记录，已入库 `research_notes.duckdb`，库内 file_path 为 `04-现代研究文献/14-bsd与其他操作系统比较研究/`；磁盘对应目录为 `04-现代研究文献/13-临时放置文献处理20260806/`），本规则约束大纲补全于 `05-卷册大纲/`。

具体执行要求：

- **识别规则**：对项目已有扫描记录（`jianyi.md`、`逐行大纲缺口清单.md`、`script/逐行缺口_第N卷.md`、第五卷考据记录、第 5 卷大纲全部子节文件、非第 5 卷但可能含“仅 FreeBSD”叙事的卷章）执行查询，按下述三类分类：
  - **强制仅 FreeBSD**：技术为 FreeBSD 独有（如 bhyve、Capsicum、jail、geom、netgraph、pf on FreeBSD、bsdinstall、bsdconfig、geli、gbde、vinum、sppp 等），判定为“不扩展”，跳过。
  - **可扩展候选**：技术在其他 BSD/UNIX/macOS 中有对应实现或演化（如 ZFS 在 OpenZFS 跨项目、DTrace 在 macOS/illumos、LLVM 在 OpenBSD/NetBSD、Subversion→Git 在 OpenBSD/DragonFly BSD 等），进入核查流程。
  - **边界情况**：技术部分适用（如 FreeBSD ports 与 NetBSD pkgsrc 同源、OpenBSD ports 异途），按“部分可扩展”处理，仅扩展适用部分。
- **“大纲是否真实缺少”核查流程**：对每条“可扩展候选”执行三步核查后方可扩展，禁止跳过核查直接扩展：
  - **同卷核查**：检查该子节所在卷的其他章节是否已叙事扩展目标，如已叙事，判定为“已存在”，跳过扩展。
  - **跨卷核查**：检查目标 BSD/UNIX/macOS 对应卷章是否已叙事该技术——第 9 卷 NetBSD（第 172-190 章）、第 10 卷 OpenBSD（第 191-213 章）、第 11 卷 DragonFly BSD（第 214-236 章）、第 12 卷 macOS（第 237-253 章）、第 13 卷 BSD 衍生操作系统（第 254-270 章）与第 14 卷 商业生态与企业案例（第 271-281 章）查其他 UNIX（Linux/Solaris/illumos/AIX/HP-UX 等），如已叙事，判定为"已存在"，跳过扩展。**上述卷号映射为当前 19 卷/355 章磁盘实况**；冻结基准 12 卷/181 章体系下的卷号映射见重构 2026 产出（原 `08-核查报告与多轮复核/重构2026/大纲目录-12卷.md`，已被同目录 `index.html` 取代，旧件归档于 `script/_backup_20260905_大纲目录12卷归档/`）。当前卷号映射以现行口径（重构2026 现行大纲目录 `08-核查报告与多轮复核/重构2026/index.html` 的 doc-metrics 31 卷 293 章 1998 节）与结构重组过渡期 `05-卷册大纲/` 磁盘实况为准（原冻结基准 12 卷 181 章〔01b R47/R48/R49〕已退役，仅作沿革），见 CLAUDE.md 卷章口径声明。
  - **扫描记录核查**：在 `jianyi.md` 与 `逐行大纲缺口清单.md` 中检索目标 BSD/UNIX/macOS 与该技术的组合，如已被识别为缺口（即使标为“待补”），判定为“已识别”，跳过扩展，仅在考据记录中标注。
  - **判定结果**：“真实缺少”进入扩展流程；“已存在/已识别”跳过扩展并在考据记录中标注；“不适用”（目标 BSD/UNIX/macOS 中确无对应实现）跳过扩展并标注“不适用”。
- **按 BSD/UNIX/macOS 三档分别判定**：对每条“真实缺少”候选，按三档独立判定扩展适用性，允许出现“仅扩展 BSD”“仅扩展 UNIX”“仅扩展 macOS”“扩展 BSD+UNIX”“扩展 BSD+UNIX+macOS”等多种组合：
  - **第一档——其他 BSD**（NetBSD/OpenBSD/DragonFly BSD）：判定该技术在 NetBSD/OpenBSD/DragonFly BSD 中是否有对应实现或演化；如有，扩展落点为第 9/10/11 卷对应章节子节五字段补全；如无（如 OpenBSD 拒绝某技术），标注“OpenBSD 拒绝/NetBSD 不采用/DragonFly BSD 未实现”，不扩展。
  - **第二档——其他 UNIX**（Linux/Solaris/illumos/AIX/HP-UX 等）：判定该技术在其他 UNIX 中是否有对应实现或演化；如有，扩展落点为第 13 卷或第 14 卷对应章节子节五字段补全；如无，标注“其他 UNIX 无对应实现”，不扩展。
