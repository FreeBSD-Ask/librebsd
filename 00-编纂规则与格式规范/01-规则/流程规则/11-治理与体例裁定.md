## Frontmatter 元数据一致性规则

**说明**：本节规定 `概述.md` 的 YAML 前置元数据（`chapter`、`id`、`volume` 字段）应与 SUMMARY.md 的当前章号、卷号保持一致，不应遗留重排/重组前的旧编号。

### 字段对应关系

具体执行要求：

- **`chapter` 字段**：应与 SUMMARY.md 中该章的当前章号完全一致（如 SUMMARY 中为“第 21 章”，则 frontmatter 应为 `chapter: 第 21 章`，不应遗留旧编号如“第 161 章”）
- **`id` 字段**：应与当前章号一致（如 SUMMARY 章号为 21，则 frontmatter `id` 前缀应为 `CH21`，不应遗留旧前缀如 `CH161`）
- **`volume` 字段**：应与该章实际所在卷号一致（如章 345 在第十八卷，则 `volume: 第十八卷`，不应遗留旧卷号如“第十二卷”）
- **`cross_ref_ids` 字段**：跨引用中引用的章号应与当前编号体系一致；若涉及跨章引用，应复核被引用章的实际当前编号

### 触发条件

以下情形应触发 frontmatter 一致性检查：

- **章号重编号**：全书或局部章号重排后（如 2026-08-03 历史 1-348 重排）
- **卷重组**：章在卷之间迁移后
- **章拆分/合并**：章拆分或合并后
- **新增补遗章**：新增补遗章时，其 frontmatter 应以当前编号体系为准，不应引用旧编号体系

### 检测与修复流程

- **检测方式**：人工比对全部 `概述.md` 的 frontmatter（`chapter`/`id`/`volume`/`cross_ref_ids` 字段）与 SUMMARY.md 当前章号、卷号——逐章读取 frontmatter 原文，逐项比对
- **修复方式**：对检测到的不一致字段，逐个手动修改：先读取 `概述.md` frontmatter 原文 → 修改 `chapter`/`id`/`volume` 为当前值 → 确认 H1 标题已与 SUMMARY 一致 → 记录修改
- **修复后验证**：重新人工核查全部 `概述.md` frontmatter，确认不一致数为 0

### 例外

无例外。所有 `概述.md` 的 frontmatter 应与当前 SUMMARY 章号/卷号一致，不应保留旧编号。

## AGENTS.md 与规则目录去重规则

**说明**：本小节规定 `AGENTS.md` 与 `规则/*.md` 之间的去重关系，避免规则正文在多处复制导致维护时遗漏同步。

**核心原则**：

- 规则正文仅活在 `规则/*.md` 中
- `AGENTS.md` 仅保留项目级布局、修改记录、已修复问题等独有内容
- 不应在 `AGENTS.md`、memory 文件（`user_profile.md`、`project_memory.md`）中复制规则条目展开内容
- `AGENTS.md` “修改规范”章节每条规则仅一行高层摘要 + 指向 `规则/*.md` 的链接
- `AGENTS.md` “规则调用”章节不含四类规则的高层摘要展开，改为纯引用

**例外**：

- `AGENTS.md` “项目背景”、“文件结构”、“修改记录”、“已修复问题”等独有内容不受此规则约束
- memory 文件可保留项目特定约束（如“硬约束”清单），但不应复制规则正文

**同步更新强制要求**：

- **一切提要规则、关键与重要规则应与 `AGENTS.md` 同步更新**。即在 `规则/*.md` 中新增、修改或废止任何提要性、关键性、重要性规则时，应同步检查 `AGENTS.md` 对应的高层摘要（“修改规范”章节）并更新，保持两处口径一致。
- **适用判定**：规则属于下列任一情形即应同步——①`AGENTS.md`“修改规范”章节已有一行摘要的规则；②影响项目级布局、文件结构、协作流程的关键规则；③用户明确指示为重要规则的条款。
- **执行时机**：规则文件修改完成后立即同步 `AGENTS.md`，不延迟、不批量积压；修改记录（changelog）同步登记。
- **反向一致**：`AGENTS.md` 高层摘要与规则正文冲突时，以规则正文为准并修正 `AGENTS.md` 摘要，不应任其脱节。

## 规则语料单一落点与去重规则（2026-11-06 立，第四十二件）

**说明**：本小节规定规则语料（`01-规则/**`＋`AGENTS.md`＋`13-软件工程/*.md`）内部的单一落点与去重关系，是“AGENTS.md 与规则目录去重规则”的语料内部延伸：上一节划定 AGENTS 与规则正文的边界，本节划定语料内部“同一事实只写一处”的形式纪律。

**核心原则（单一形式落点）**：

- 同一事实、定义、口径、清单只允许一个**形式落点**；其余位置一律以引用指回，不复制正文
- 幻影链接（指向不存在文件的相对链接）＝语料断言不存在之物，与重复复制同属形式缺陷
- 名单型索引表（以路径为键、逐行登记成员者）每键恰一行；新增小节在既有行内追加，不应另起新行重复同一路径
- 新建名单型索引表应随建登记对应门禁（现有范本：`流程规则/00-索引.md` 分册表由第二十九件 E7b 管辖）

**判据（第四十二件 `audit_rule_dup.py`）**：R1 幻影相对 `.md` 链接（剥围栏与行内代码后目标应存在）｜R2 跨文件长行复制（规范化 ≥60 字符非表格行同文现于 ≥2 文件；白名单：分册体例页眉）｜R3 同文件同表重复数据行（各表首行与分隔行豁免）｜R4 同文件同父节重复标题（跨文件同题与不同父节泛名同题合法）。触发面：规则语料任何写入后＋**常备**。

**哲学依据**：`13-软件工程/09-reflection-generalization.md` §2.11“单一形式落点（引用不复制）”——形式主义（重复＝同一事实的两个形式断言，漂移由构造保证）、自反性（门禁语料审视自身）、非存在（幻影链接是无对象的指称）。判据全部来自 2026-11-06 全量扫描实测缺陷（4 处目录化错级链接、1 组跨文件复制行、`00-索引.md` 65 行 11 键），不设臆测判据。

## 条文用语（能愿动词）规则（2026-11-14 立，ykla 裁定）

**依据**：GB/T 1.1-2020 附录 C（条款类型与能愿动词）；ISO/IEC Directives, Part 2:2021 §7；ISO/IEC/IEEE 29148:2018 §5.2.4（避免 must）。本条是项目自行采纳的体例规则，不声称项目文件是标准化文件。

### 一、四档

| 档 | 能愿动词 | 含义 | 项目用法 |
| -- | -------- | ---- | -------- |
| 要求 | 应／不应 | 必须满足，无偏差 | 规则主体、门禁判据、红线 |
| 推荐 | 宜／不宜 | 建议、首选，非强制 | 最佳实践、经验做法 |
| 允许 | 可／不必 | 许可、可不做 | 可选路径、豁免 |
| 陈述 | 能／不能、可能／不可能 | 能力、可能性 | 说明、边界描述 |

### 二、停用与替代

| 停用 | 改用 | 例外 |
| ---- | ---- | ---- |
| 必须 | 应 | 引文、标准原文、书名与法规名称 |
| 须（单字） | 应 | 无须、必须等词形，引文 |
| 不得 | 不应 | 引文、法规原文 |
| 禁止（作要求） | 不应 | 绝对红线清单可保留禁止，同条括注要求型为不应 |
| 严禁 | 不应 | 同上 |
| 务必 | 应 | 引文 |

- 不应把“不可”用作要求用语（GB/T 1.1-2020 附录 C）。
- “应当”“应该”统一为“应”。
- 推荐档不应以“尽量”“尽可能”“建议”代替“宜”；确需表达推荐时用“宜”。
- 陈述能力用“能”，许可用“可”，可能性用“可能”，三者不应互代。

### 三、适用范围与追溯

- 适用：`AGENTS.md`、`01-规则/**/*.md`、`02-操作手册/**/*.md` 的新增与实质修订文本。
- 不适用：`13-软件工程/` 上游正文（`ADR-0001`：正文不直接改，按 `NOTICE.md` 回流）；引文、代码块、行内代码、逐字保真档案；历史归档与既成报告。
- 存量：2026-11-14 全量回改已完成（`01-规则`＋`AGENTS.md`）；此后新增文本按本条执行，不再回改历史层。

### 四、门禁

- 机判：`audit_rule_modality.py` 只检查 `git diff` 新增行中的停用词；`--selftest` 非空。
- 人工：复核时按四档判定条款类型，不应把推荐写成要求、把要求写成陈述。

### 五、自反

本条若不能改变规则写作与复核，按 `13-软件工程/00-philosophy.md` §9 降级或删除。

## ykla 体例与结构裁定（2026-10-22 汇总）

本节汇总 ykla 就目录体例与结构给出的裁定；题面数词条款见“重构大纲目录口径同步规则”内的标题学术化条款，不在此重复。

- **目录层不设附录（2026-09-26 ykla 令“不允许有附录，重写目录”）**：目录层（`index.html`／`data/outline.txt`／`05-卷册大纲`）**不应设附录卷、附录章、附录节**。“附录”二字只允许出现在①体例声明“全书不设附录”②废止记录。原附录 A–G 内容并入正文。**改写后必查**：`grep '^# .*附录' / '^## .*附录' / '^### .*附录'` 为零。
- **合并／删除／拆分的判据是叙事单元，不是章节数（2026-09-26 ykla 裁定“不要管厚薄。重新拟定”）**：合并只合“同一叙事单元被章界切断”（同时期连续／同一物质条件层／同一收束单元）；删除只删“同构复述的体例性内容”与“被既有内容覆盖的建议”；拆分只拆“单章混装两个不同主题分野”。**薄不是理由。**按此判据回检已执行的七组合并，应回退其中按厚薄误判者。
- **美学与文化类章应独立且无依赖**：此类章不合并不删除；其对外的依赖注应改写为**直指一手载体**（ref／mat／档案），每章自足，不把证据外包到其他卷。
- **不应篡改字体**：内嵌字体是 ykla 选定的视觉方案，不应删除、替换或降级为系统字体栈。
- **目录页 metrics 结构**：4 块（总卷／总章／总节／溯源标注）＋ selfcheck 底部块，缺一不可。**面包屑禁省略号**（长题应换行完整显示），且**只展示到卷**，章节层级不进面包屑。
- **书目下载与引擎政策**：搜索引擎侧——维基百科只检索英文（不做多语言／`lang` 参数）；不稳定的密度敏感端点不接入工具链（百度已整体移除）。新增引擎前先判该端点对请求密度是否敏感，学术检索优先开放 API。

**判据非空**：附录条款可由 `grep` 直接验证（实测 2026-10-22 为零）；metrics 与面包屑条款由目录页测试套件（T15／T16 等）覆盖。
