## 意图确证（知难行易；全任务适用；2026-10-29 立）

本节是**意图确证的判据正文**。理论依据见 `13-软件工程/08-intent-first.md`；其余文件（`AGENTS.md`、`工程实践规则.md`、`01-规则/README.md`、模板与门禁脚本）只引用本节，不复制本节正文。判据来源与原文定位：`02-sacred源材料/sacred_sources.duckdb` 的 `files.id=45`（前言）／`blocks.id=1848`（`block_index=50`）。

节引原文（逐字保真，仅引至本句；全文见 `13-软件工程/08-intent-first.md` §1）：

> 开放 rsync 同步只是几分钟的事情。但让他理解其必要性是困难的。知难行易，故而“行”也变得困难。

工程翻译：难在“知”（任务方向、目标与必要性的共识），不在“行”（具体手段）；“知”不立则“行”不顺（“故而‘行’也变得困难”）。故须把意图固化为可判定契约，把手段降为可替换的次要项，并适用于一切任务。

**适用范围（全任务，不限工程类批次）**：内容编纂、考据、数据库、大纲、目录页、归档、一次性小任务、长线续跑、派发子代理，一律适用。工程类批次与非工程任务的差别只在档位选择，不在是否需要确证。

**档 A（全量六字段）**：适用工程类批次、长线批次、跨会话续跑、高风险或不可逆操作（写库、删除、凭据、平台承诺、规则实质判据）、派发子代理。六字段逐项书面写出：①**用户原话**（逐字摘录，不得改写）；②**目标**（可判定的终态）；③**非目标**（明确排除项）；④**验收判据**（可测、可核）；⑤**手段自由度**（允许与禁止更换的工具、设施、技术栈）；⑥**未知／`[待验证]`**（含验证路径）。

**档 B（轻量三要素）**：其余任务（单次只读查询、单文件小改、格式化等）适用。三要素：①**用户原话**；②**目标**；③**完成判据**（二值可判，即达成／未达成）。写于会话首条或任务书一行，须可定位（文件＋小节／行号，或会话消息位置）。**不得以“档 B”名义跳过三问 STOP。**

**升级条款**：一旦出现“手段先于目标”迹象（先试工具、先跑脚本、先改架构、先选技术栈、先沿用既有设施再补说目的），当批即升为档 A；已在执行的写入步骤须停手，补齐意图确证后方可继续。

**三问 STOP**：①**谁在痛**——不做这件事会怎样，代价由谁承担；②**做完算成功吗**——二值判据是什么；③**不做什么**——非目标清单是什么。任一问答不出即停手澄清，**禁止先做后问**；取舍时一律选澄清，澄清成本远低于返工成本。

**手段次位**：不得以既有工具、技术栈、脚本或设施反向裁剪目标。更换手段须同时满足：验收判据不变；理由留痕（批次记录或 ADR）。目标是首要的，手段是次要且可替换的。

**落点**：档 A 写于 `spec.md` 首节、`tasks.md` 批首或长线任务书；档 B 写于任务书或会话记录一行。任务审计台账的准入证据须写明定位路径（文件名＋小节名或行号），不得只写“已确认”。

**子代理**：派发提示须含目标、非目标、验收判据三项；子代理不得自行改写目标，可在验收判据不变的前提下自选手段；子代理自报完成不构成意图确证证据，须由派发方按验收判据复核。

**长线续跑**：以该线任务书与 `01-项目管理/01-编纂规划与报告归档/长线任务总登记表.md` 的“权威源／续跑入口”字段中的既有目标与范围为意图基线；基线变更须记录（任务书或 changelog），不重做已完成批次，不追溯已收口行。

**变更回流与门禁**：意图变更（目标、非目标或验收判据的实质变动）回 G0 重写意图确证单、回 G1 重列需求与验收；工程类批次的接线由 `audit_engineering_practice.py` E8 校验，任务准入由 `audit_task_lifecycle.py` L2 校验；无机器判据的档 B 由复核抽查留痕（`任务复核台账.md`）。

**自反**：“知”不可能完备，确证收敛于最小可判定契约；禁止以“再调研一轮”代替判断，禁止无限调研。本节若不能改变决策或产物，按 `13-软件工程/00-philosophy.md` §9 删除或降级，不得留作空转条文。

## 修改前后复核规则

修改前后各复核一次，确认修改正确无误；允许使用脚本、批量工具等编程手段执行修改，但脚本输出与批量结果须逐项复核，不得默认接受。

具体执行要求：

- **修改前复核**：每次修改前须对原文进行一次复核，确认修改点与上下文一致。
- **修改后复核**：每次修改后须对修改结果进行一次复核，确认修改正确无误。
- **脚本与批量工具**：允许使用脚本（含 Python、sed、awk 等）与批量替换工具执行修改；脚本须放置 `script/` 目录下，文件名须见名知义；脚本运行前后各复核一次。
- **逐行核对**：复核时须逐行核对，不得跳行或简化检查；批量修改后须抽样或全量核对修改结果。
- **机械修改的上下文判断**：脚本规则须结合上下文设计（如正则须避免误匹配标题内实质括号），不得无差别替换；无法修改的内容可以保留原状。
- **阶段裁剪**：复核范围与强度按下文“工程实践生命周期与阶段门禁”的六类变更裁剪表执行；纯文档、缺陷修复、紧急修复不得跳过对应“不可裁剪”项。

## 三轮完整执行规则

上述流程必须完整执行三轮，然后严格、完整的复查一轮，如果还有问题继续执行三轮，依次递归直至无问题。

具体执行要求：

- **三轮完整执行**：上述“修改前后复核 + AutoCorrect 调用 + 逐个核对”流程必须完整执行三轮。
- **复查一轮**：三轮执行完毕后，须严格、完整地复查一轮，确保整体一致。
- **递归执行**：若复查后仍有问题，继续执行三轮，再复查一轮，依次递归直至无问题。
- **留痕**：每轮执行结果须记录，便于追溯。

## 结构性变更后验证清单

**说明**：本节规定任何结构性变更（新增/删除/重命名/迁移章文件夹或节文件、章号重编号、卷重组、SUMMARY 重建）完成后必须执行的逐项验证流程。本清单是“修改前后复核”的补充，专用于结构性变更场景；其阶段归属为 G4，按“工程实践生命周期与阶段门禁”的既有门禁阶段归属选择，不得因“改动很小”跳过本清单或 G4 其他适用项。

### 触发场景

以下任一操作完成时须执行本验证清单：

- 全书或局部章号重排
- 新增或删除章文件夹/节文件
- 章卷之间迁移
- 人工重建 SUMMARY.md 后（原 `_regen_summary_after_renumber.py` 已缺失，按“GitBook 目录同步规则”人工执行；`_gen_06_summary.py` 已停用——禁止编纂正文，06-正式书稿/ 已移除，不再生成书稿 SUMMARY）
- 批量创建/修改节文件后

### 验证清单（逐项执行，不得跳过）

1. **章号连续性**：人工核查 SUMMARY.md 章条目数=现行口径章数（`05-卷册大纲/目录/index.html` 的 doc-metrics 章数现值；结构重组过渡期以 `05-卷册大纲/` 磁盘实况为锚；原冻结基准 12 卷 181 章〔01b R47/R48/R49〕已退役，仅作沿革）、编号范围覆盖现行口径章号区间、无重复、无缺失、严格递增

3. **节号连续性**：人工逐章核查节文件编号与 `概述.md`“本章节索引”，确认无缺口；如有缺口，须按“大纲节号连续性规则”处理（补全或登记为有意跳跃）

6. **磁盘↔SUMMARY 双向吻合**：人工比对，确认 05 磁盘章目录数=SUMMARY 章条目数、无未对应章

## 任务台账口径与不变量（2026-10-22 立）

**背景**：各任务线以 JSON 台账（`script/` 下的 `*_ledger.json` 等，gitignored）记录已判读进度。台账是**派生视图**，与权威源冲突时以权威源为准；但读数口径一旦错，进度与对账会同步失真。

**三条不变量（每条均须全库清零才可判“一致”）**：

| 不变量 | 含义 |
| ------ | ---- |
| `judged == sum(records 区间)` | 已判读量等于各区间长度之和 |
| `spec == judged` | 规格数等于已判读量 |
| `eff == messages → completed` | 有效量等于消息数时才可置 completed |

**口径硬约束**：

- **`read_judged`＝已判读封数**（＝`records` 区间之和），**不是候选条数、也不是入纲块数**。三者混用会得出互相矛盾的进度。
- **批次数须数 tag**，不许按文件数或估算。
- **note 里写百分数须写 `%%`**（否则格式化会吃掉），数字须可独立反查——记账文案不得照抄模板（历史上有把模板占位数字原样落账的先例）。
- **台账行数与 `\n` 计数差 1**：记账以 `git diff --numstat` 为准，核验器断言值须单独换算，两者不可混用。
- **含在途数据的台账整文件排除**，不入库。
- **台账文件可能被并发会话改写**——引用前必查 `mtime`；多处并发写时以“行在账”为准，勿重试补写造成真重复。

**判据非空**：三条不变量可对任一线的台账直接计算验证；`read_judged` 口径可由 `records` 区间和与新判读件数双向核对。
