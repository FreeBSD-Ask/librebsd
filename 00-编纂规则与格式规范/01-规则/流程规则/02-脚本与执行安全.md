## 脚本执行安全规程

执行任何脚本必须经过**四步**，缺一不可：

1. **复核脚本**：执行前审查脚本逻辑——输入源、输出目标、副作用、幂等性、安全边界；确认脚本不会在未授权情况下写正式库/改正式文件。
2. **单独文件夹演示**：在 `script/_staging/<脚本名>/` 下试运行。演示输入必须是真实数据的**只读副本或最小样本**（数据库脚本用 COPY 的临时库；文件脚本用临时目录；输出重定向至 staging 目录）。演示不得触碰正式数据。
3. **再复核演示结果**：比对演示输出与预期（计数、内容、副作用清单），确认行为正确、无越界。
4. **成功才能正式执行**：演示通过后，方可对正式数据执行；执行后仍须按“修改前后复核规则”复核正式结果。

具体执行要求：

- **分类执行**：
  - **只读类脚本**（扫描/统计/报告，无写操作）：第 1 步复核确认“纯只读”后可免演示，直接执行；但输出须抽样复核。
  - **写库/改名/删除/批量修改类脚本**：必须完整四步。演示须以临时副本验证破坏性操作的效果，确认无误再对正式数据执行。
- **演示隔离**：演示输入一律用副本/样本，演示输出一律在 `script/_staging/` 下，不得污染正式目录与正式库。
- **路径参数**：脚本设计时优先支持输出路径/输入路径参数（argv），以便演示时重定向至 staging；无参数的硬编码脚本，演示时使用复制到 staging 的临时版。
- **幂等性**：正式执行前确认脚本幂等（重跑不产生重复/累积效应）；破坏性脚本遵守“备份后一次性更新”原则（防链式污染）。
- **记录**：演示与正式执行的差异、复核结论登记 changelog。

## PowerShell 转 Python 规则

当想使用 PowerShell 时，尽量转成 Python 脚本。

具体执行要求：

- **优先 Python**：需要进行命令行操作时，优先使用 Python 脚本而非 PowerShell。
- **PowerShell 兜底**：仅在 Python 无法完成（如调用 Windows 系统 API）时使用 PowerShell。
- **脚本存放**：Python 脚本须放置在 script 文件夹下，按临时文件规则处理。

## 规则引用脚本与命令独立存储规则

**说明**：本小节规定规则文件（考据规则.md、写作规则.md、流程规则.md、主题规则.md、释读规则.md）引用的所有可执行资源（Python 脚本副本、外部程序命令说明、数据库操作 SQL）须独立存储到 `00-编纂规则与格式规范/01-规则/脚本与命令/` 子目录，与规则文件形成“规则 + 可执行资源”的自洽单元。

具体执行要求：

- **目录路径**：`00-编纂规则与格式规范/01-规则/脚本与命令/`，与规则文件同属 `01-规则/` 目录
- **收录范围**：收录规则文件中明确引用的所有可执行资源，含三类：
  - **脚本副本**（.py）：从 `script/` 目录复制，原文件保持不变
  - **程序命令说明**（.md）：外部程序（如 AutoCorrect、`md-padding@latest`、`markdownlint2`、Tesseract OCR、pandoc）的调用规范、参数说明、规则引用位置
  - **数据库操作 SQL**（.sql）：规则文件中提到的所有数据库操作，含 `changelog.duckdb` 去重查询与 `references_fulltext.duckdb` 多表操作
- **副本关系**：`脚本与命令/` 下所有 .py 副本须与 `script/` 目录中对应源文件内容完全一致（SHA-256 比对），原 `script/` 目录中的源文件保持不变
- **与 `script/` 目录的分工**：
  - `script/` 目录：项目根目录下的临时脚本与中间文件归档（仅放置可临时、随时删除的中间过程产物，不放置长期频繁使用的固定脚本；历史遗留脚本保留原样，不主动清理）
  - `脚本与命令/` 目录：规则文件夹下的规则引用可执行资源副本，仅收录规则文件中明确引用的可执行资源（固定脚本的正式存放位置）
- **索引文件**：`脚本与命令/README.md` 为索引入口，按“脚本文件 / 程序命令 / 数据库操作 SQL / 未实现脚本登记”四类列出所有可执行资源，每条索引含文件名、用途说明、规则引用位置（精确到规则文件名与小节名）
- **未实现脚本登记**：规则文件中以示例或调用形式提及、但 `script/` 目录中实际不存在的脚本，仅在 `脚本与命令/README.md` “未实现脚本登记”小节登记，不创建占位文件
- **新增资源流程**：当规则文件新增引用某脚本、程序命令或数据库操作 SQL 时，须将该资源复制（.py）或新建（.md / .sql）到 `脚本与命令/` 目录，并在 `脚本与命令/README.md` 索引追加条目；同步在 `00-编纂规则与格式规范/01-规则/README.md` “脚本与命令索引”小节更新统计数字
- **索引一致性**：`脚本与命令/README.md` 与 `00-编纂规则与格式规范/01-规则/README.md` “脚本与命令索引”小节的统计数字（.py 副本数、.md 命令数、.sql 数、未实现脚本数）须保持一致
- **文件编码**：`脚本与命令/` 目录下所有文件使用 UTF-8 无 BOM 编码、LF 换行符；所有 .py 副本文件保留原脚本的 shebang 与编码声明（如有）
- **不变性约束**：复制 .py 副本时不得修改源文件内容（含注释、空行、换行符）；`script/` 目录中所有文件的内容、名称、位置均须保持不变

## 脚本执行与进程测量口径（2026-10-22 立）

**范围**：Windows／Git Bash 环境下的批处理编写、进程与内存测量、命令行参数传递。落在本节的原因是这些坑的共同特征是**报错指向 A、真因在 B**，且失败多为静默。

**批处理与 Shell**：

- **cmd 按 GBK 解析批处理**：中文字节会吞掉后续 ASCII（实测出现 `'ecutionPolicy'`／`'wershell'`／`'ho'` 一类残缺 token），且 **LF-only 会静默破坏 `goto`**。批处理一律**纯 ASCII ＋ CRLF**；需要中文输出时改由 Python 承担。
- Git Bash 里调 cmd 用 `cmd //c`（双斜杠）；bash 双引号会吃 `$_`／`$env:TEMP`——这类报错**多为测试装置的假阳，不是交付物错**，须先自证再判数据。
- **`bash for` 遍历含中文的路径会失效**，改用 Python 循环。
- **Windows 端口复用**：`SO_REUSEADDR` 允许多进程绑定同一端口 ⇒ 以 bind 失败为判据的幂等守卫会**完全失效**（实测 3 个实例同时 LISTEN）。服务类脚本须显式关闭该选项，或改用别的手段防重。

**进程与内存测量**：

- **Working Set 会被 OS 裁剪，真实成本看 Private（`PagedMemorySize64`）**。实测同一批 68 个进程，压力大时 WS 3,256 MB、平静后 WS 1,626 MB（进程数未变、纯裁剪），而 Private 稳定在约 3,120 MB。**选型与汇报一律用 Private。**
- **采样必须快于被采样**：以 30 ms 间隔的 PowerShell 采样去测 40 ms 的请求，峰值永远读成 0，得到的是**假值**。改 ctypes 直连 psapi 提采样率后方可信。附两处 ctypes 坑：`OpenProcess.restype` 默认 `int` 会截断 64 位句柄；`WorkingSetSize` 在结构体偏移 16 而非 8。
- **命令行关键词匹配＝自匹配假阳**：以 `powershell -Command "... -like '*target*'"` 找进程时，会把执行该命令的 bash／powershell 自身匹配进去（曾据此误判“进程复活”）。正解＝把模式串拼在脚本内（如 `'chro'+'me-mcp'`），脚本文件执行。
- 大批提交触发 `git gc`→`repack` 时 `pack-objects` 可瞬时占 5 GB 级内存，数分钟后自毕；**错峰建议**＝大批量提交时段避免并发 gc。

**命令行参数**：

- **argparse 的 `nargs="+"` 重复 flag 只保留最后一个**（`--num=A --num=B` 静默丢 A）。多值须写成**单个 flag ＋空格列表**；以破折号开头的取值用等号形式（`--id=<v>`）。**跑后对账磁盘产物数**，不以参数自证。

**判据非空**：批处理 GBK 吞字与 LF 破 `goto` 可造最小 .bat 复现；`SO_REUSEADDR` 可并行起两个实例复现；采样滞后可用固定延迟的探针复现；argparse 覆盖一行即可复现。

## 子代理与并行作业纪律（2026-10-22 立）

**背景**：本工程长期以多路并行子代理推进批次作业（ykla 批准并可随时用满 40 路）。历次战役的净进展几乎全部来自“不信回报、以磁盘为准”。本节把实战沉淀固化为硬纪律；与 `工程实践规则.md` §6 的 TG-008（自报不得作为依据）配套，本节只补操作层判据。

**回报与验收**：

1. **子代理自报一律不采信，以磁盘为准**。实测存在自报“已落盘 10 页”而磁盘全缺、自报 `fabricated` 而实为照录原图的情形；`[Tool execution was interrupted]` 一类中断通知也不可信（实测 34 路报中断而 30 路已落盘）。判完成只看 `ls`／`getsize`／`mtime` 与独立校验脚本。
2. **约半数子代理会在中途提前结束回合且零落盘**（典型停在“现在我来编写脚本”）。处置顺序：**独立校验脚本按磁盘判定 → 以 SendMessage 续跑同一 agent（上下文尚在，成本低于新派）→ 仍空转则由主代理自跑补上**。派发提示词须写明“不输出计划与进度旁白，每步直接调用工具，中途停止＝本批作废”。
3. **`TaskStop` 的 `stopped`／`killed` 只是状态标记，不是进程已终止的证明**。实测 9 条判“0 落盘”中 8 条在停止请求后继续运行 52 分钟、迟到产出 18 页。**判静默须跨分钟级连续窗口（如连续 5×60 秒零改动），终止后等 ≥60 分钟再取快照，交接落盘后 30–60 分钟必须复测 mtime。**
4. **子代理 Bash 的 cwd 继承主会话 cwd，不是 workspace root**。派包提示词须写死每条 Bash 的前缀（如 `cd /d/librebsd &&`），否则相对路径脚本找不到输入。
5. **子代理 Write 会写 CRLF**，须由主代理统一归一；Write 超时重试会造成“整份内容写入两次”（含空白页重复），QC 全绿也抓不到——**唯一判据是行周期检测**。

**并发上限与质量**：

- **本环境 rpm 上限使高并发失败率急剧上升**：实测 40 路时 agent 245–570 秒被杀、失败率 40–60%。**合规性与存活时长强相关、与提示词质量无关**（存活 25–40 分钟者跑到自检上限、超限 0；4–5 分钟被杀者留宽松稿）。故叙述类提示词的**目标长度写区间中值（如 90–115 字），不要贴着上限写**。
- **滚动并发的实操优选 ≤7 路／批最稳**（实测 11 路一批致 11 路全取消）；大规模一次性派发才用满 40 路，且须留补派预算。
- **配额枯竭或滚动重派零净进展时立即停派**，先由 Python 机械层跑全量做红旗筛查（翻倍／前缀／CJK／提示词泄漏／长度异常），**只有红旗才需 LLM 复核**。

**并行写者与进程**：

- **写库前须确认无并发写者**；同一分片不得双写。已多次出现两会话重复提取同一批、并竞争写同一份文档导致状态快照互相覆盖。
- **被取消的前台 Bash 会杀死整个会话进程树**（含后台任务）。监控只用秒级快查，不要长 sleep；`TaskStop` 不杀 Python 子进程（可存活 40+ 分钟），须按命令行 `taskkill`。
- **子代理/会话会各自拉起 MCP 进程且不回收**，长会话越跑越多；批量子代理会话开工后应断开用不到的服务器（见 `会话内 /mcp disconnect`）。

**判据非空**：第 1／2 条可由任一战役的磁盘复核复现；第 3 条可由终止后 mtime 复测复现；第 5 条可用一份刻意重复的产物跑行周期检测复现。

## 常驻授权与回合终结（2026-10-22 立）

**常驻授权**：读到任务线的 `RUNBOOK_*.md`（或线级任务书）即视为开工授权，**全程免逐批确认**；单会话连跑不限批数，直至配额警戒或触发该 RUNBOOK 的中止护栏才停。**不建定时任务、不建自动化**（项目既有禁令）；跨会话接手只靠 RUNBOOK“当前状态”节 ＋ 台账 ＋ git。

**回合终结禁令**：批次收口**不是回合终点**——收口记账后的下一条输出必须是下一批的开工工具调用，不得以总结报告结束回合；待办列表永远保留一条进行中的下一批条目。以“战报”收尾致流水线停摆已明令视为缺陷。

**进度报告构成**（2026-10-08 ykla 令“进度必须报告入大纲进度”）：进度报告必含三项——①引用链收口数（分母明确）；②新增条目数（批号／要点与文献行数／门禁结果）；③入大纲覆盖率（已入纲数 ÷ 已复核数，含缺口说明）。只报上游环节会掩盖下游滞后。
