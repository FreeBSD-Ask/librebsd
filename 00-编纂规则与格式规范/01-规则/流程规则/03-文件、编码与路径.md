## 临时文件规则

临时文件或脚本放置在 script 文件下，不清理；任何临时文件或者脚本或者执行完成后需要删除、清理的文件均放置在 script 文件下，并且不需要进行清理，保持原样即可。

**旁路备份全面禁止（全库，2026-10-23 用户令，替代 2026-10-17“写前备份通则”）**：任何目录内（**含 `script/`**）一律不应创建写前／写后备份副本——`.bak`／`.bak-`／`.bak_`／`.pre`／`.prebak`／`.prebak-*`／`.md.prebak-*`／`-bak`／`.orig`／`.rej`／`~` 等任何后缀、改名副本，以及 `script/_bak/`、`prebak-*` 之类备份目录，**一律不应创建**；留痕与回滚**唯一依赖 Git**（提交、标签、`git show`），数据库快照**唯一依赖** `12-数据库备份/` 三计划任务。违规件处置四步：**识别 → 逐件记录（路径、字节、sha256）→ 删除 → 复扫为零**；需保留内容者先提交 Git 再改。2026-10-23 实测 783 件、17.7 GB 已按此口径清除。**执行器命名与输出目录不应含被清扫模式**（同日实测：清扫脚本自身路径含 `prebak`，运行中自删致台账丢失）。

**script/ 目录定位**：`script/` 目录**仅放置可临时、随时删除的中间过程产物**（一次性修复脚本、调试脚本、批次中间清单、日志、临时 JSON 等）。**长期频繁使用的固定脚本不应放置在 `script/` 下**——此类脚本应放置于正式目录（如 `00-编纂规则与格式规范/01-规则/脚本与命令/` 等），确保固定脚本不被临时清理误伤、便于版本管理与索引。

具体执行要求：

- **临时文件目录**：所有临时文件、脚本、需清理的中间文件均放置在项目根目录下的 script 文件夹中。
- **不清理**：script 文件夹下的文件不需要清理，保持原样即可。
- **不放置其他位置**：不应将临时文件、脚本放置在其他目录（如 规则/、大纲/、操作手册/ 等）。
- **固定脚本不入 script/**：长期频繁使用的固定脚本（如验证/同步/生成类常驻脚本）不应放置于 `script/`，应存放于正式目录（首选 `00-编纂规则与格式规范/01-规则/脚本与命令/`）；`script/` 仅承载临时、一次性、可随时删除的中间产物。
- **一律不入库＋不应 git add -f（2026-10-04 ykla 令）**：`script/` 整树一律不进入 git 跟踪、保留磁盘文件（2026-10-04 起 54 274 件已整树退出跟踪，根 `.gitignore` `/script` 规则接管）。不应对 `script/` 下任何文件执行 `git add`（含 `git add -f`、`git add -A`、`--pathspec-from-file`）；仅当 ykla 显式声明某文件应入库时方可例外，且应先在任务书/交接书留痕。全库任务书与交接书中既有“git add -f”声明一律作废（各文件顶部已加作废横幅，2026-10-04 批量执行 254 份）。
- **固定脚本判定**：满足以下任一条件即为固定脚本——①被规则文件明确引用并纳入 `脚本与命令/README.md` 索引；②需在多轮任务中反复调用；③承担全书级验证/同步/生成职责（如节号缺口验证、SUMMARY 同步等）。此类脚本按“规则引用脚本与命令独立存储规则”存放。
- **脚本执行安全规程优先**：无论脚本存放位置，执行前均应遵循本文件“脚本执行安全规程”小节（复核逻辑 → staging 演示 → 复核结果 → 正式执行）。

## 根目录禁止生成新路径规则

不应在项目根目录下生成新路径（新目录或新文件）。确有必要在根目录生成新路径时，应先主动询问用户并获得确认后，方可执行生成操作。

具体执行要求：

- **根目录新路径一律不应**：项目根目录（D:\librebsd）下不应自动新建任何目录或文件，包括但不限于临时目录（如 `_work_tmp`）、工作目录、交付目录（如 `deliverables`）、日志文件等。
- **先询问后执行**：如确有必要在根目录生成新路径（用户明确要求或任应需），应先向用户说明用途与路径，**获得明确确认后**方可生成；未获确认不应生成。
- **已有标准目录内自由**：根目录下既有标准目录（`script/`、`deliverables/` 已废除、`00-编纂规则与格式规范/`、`03-原始史料库/`、`04-现代研究文献/`、`05-卷册大纲/`、`08-核查报告与多轮复核/` 等）内部按各自规则正常使用，不受本规则限制。
- **已豁免的 Spec Kit 工具链目录（2026-09-30 ykla 批准豁免）**：以下三个根目录路径经明确确认豁免本规则，属已授权路径，不应因本规则被清理或要求迁移：
  - `specs/` —— Spec Kit（GitHub SDD 工具链）的 feature 产出目录（**2026-10-17 ykla 裁决：目录保留可用作工作区，内容不入库**，根 `.gitignore` `/specs` 维持挡新增）（`spec.md`／`tasks.md`／`checklist.md`），由 `/speckit-spec-tasks-check` 等技能与 `specify` 脚本自动创建；目录编号 `NNN-<slug>` 顺序递增。
  - `.specify/` —— Spec Kit 项目状态目录（模板、workflow、宪法 `memory/constitution.md`、PowerShell 脚本），已入库共享；本机状态件（`feature.json` 等）由 `.specify/.gitignore` 自排除。
  - `.zcode/` —— ZCode 工作区目录（`plans/`、`workflow-drafts/`、`workflow-runs/`、`skills/`）；该路径已被根 `.gitignore` 忽略、不入库。其 `skills/` 下含 Spec Kit 上游技能与自建封装技能（自建件入库源在 `.specify/local-skills/`）。
    - `.trae/` —— Trae 工作区目录（含 `specs/` 子目录，223 个 spec 子目录）；**2026-10-17 ykla 裁决：不入库**（根 `.gitignore` `/.trae` 维持挡新增；`AGENTS.md` 根目录表已同步改“不入库”）。
- **变更纪律**：上述路径的**新增子路径与内容**不再逐一询问；但若需在根目录新增这以外的路径，仍按“先询问后执行”办理。
- **历史遗留清理**：根目录下历史遗留的非标准路径（如 `_work_tmp/`、`deliverables/`）一经发现即纳入清理范围，归档至对应标准目录后删除。

## 文件编码规则

统一显示使用 UTF-8 但是不应使用 BOM 标记，换行符统一 LF。

具体执行要求：

- **UTF-8 无 BOM**：所有 markdown 文件统一使用 UTF-8 编码，不应使用 BOM 标记。
- **LF 换行符**：所有文件换行符统一使用 LF（Unix 风格），不使用 CRLF（Windows 风格）。
- **Windows 写盘默认产 CRLF（2026-10-17 立）**：`open(path, 'w', encoding='utf-8')` 在 Windows 上会把 `\n` 翻成 `\r\n`；又因 `core.autocrlf=true` 与 `.gitattributes` 的 `text=auto`，提交时被规范化，工作树中的 CR 在 `git status`／`git diff` 里**完全隐形**（实测 20 个 `.md` 长期带 CRLF 而 git 面无任何提示）。故凡向 `05-卷册大纲/` 写 `.md`，应经 `wo007_idempotency.write_guard()`（已强制 `newline="\n"` 并把 CRLF 归一）或显式使用 `newline="\n"`；兜底判据为 `audit_disk_terminology.py` 的 T2（按字节判在效面 CRLF／孤立 CR = 0）。修复既有 CRLF 时按“先提交 Git（或确认工作树干净） → 字节级 `\r\n`→`\n` → 断言去 CR 后内容不变 → 与 HEAD blob 比对”执行。
- **适用范围**：本规则适用于项目所有文本文件，包括 markdown、Python 脚本、HTML 等。

## 禁止篡改代码块规则

不应篡改代码块。

具体执行要求：

- **代码块原文**：代码块（含 ``` 与 ~~~ 包裹的内容）原文不应篡改。
- **允许修改注释**：代码块内的注释可按“代码块英语注释翻译规则”翻译为中文，但代码逻辑不应修改。
- **不应格式化代码**：不应对代码块进行格式化、缩进调整、引号统一等操作。

## AI 不可见字符清理规则（2026-10-17 立）

**说明**：本节落实“绝对红线·禁 AI 不可见字符”的清理口径与工具链。2026-10-17 首轮全库清理实测：受版本控制 `.md` 共 10 493 件，命中 838 件 10 588 处（U+3000 9 312／U+FFFD 855／U+00A0 369／U+00AD 22／U+202F 16／U+200B 9／U+FEFF 4／U+0601 1），按本节口径写盘 834 件（删除零宽格式符 36 处、合并空格串 9 486 处），复扫零残留（仅 U+FFFD 855 处按口径保留并另报）。

- **清理口径（2026-10-17 ykla 裁定）**：
  - **零宽／格式控制符**：Unicode Cf 全体（含 U+200B—U+200F、U+202A—U+202E、U+2060—U+206F、U+FEFF、U+00AD、U+0601、U+034F 等）及填充符（U+115F／U+1160／U+3164／U+FFA0）——一律删除。
  - **空格类**：Unicode Zs 中除 U+0020 外全体（U+3000 全角空格、U+00A0、U+202F、U+2000—U+200A、U+205F、U+1680 等）——一律改为 1 个半角空格；**含此类字符的极大空白串合并为 1 个半角空格**；位于行首／行尾的此类串整段删除（避免产生 Markdown 缩进或行尾空白）。
  - **U+FFFD 替换字符不属不可见字符**：系编码损坏标记，**默认只报告**；**经 ykla 明示可清理（2026-10-21 令）**——清理应先落台账记录文件、位置与前后文（`script/_fffd_ledger.jsonl` 形态），可确证缺字者恢复原字母（如 `Bien-aimés` 的 é），无从确证者直接删除、**不应臆造字符**。
  - **原始引文豁免的明示解除**：邮件原文与 PDF 引文摘录内的 NBSP、窄不换行空格、软连字符、U+FEFF 属原文残留字符，本应受“引用与代码块逐字保真”红线保护；2026-10-17 ykla 明示一并清除，本条即该次豁免的登记处。
  - **换行形态逐行保留**（LF／CRLF 原样），写盘 UTF-8 无 BOM；`05-卷册大纲/` 写盘前断言无 CR。
- **工具（固定脚本）**：`00-编纂规则与格式规范/01-规则/脚本与命令/scan_md_invisible.py`（全库复扫判据：对 git 跟踪的 `*.md` 逐件扫描，按码位汇总并逐处落明细 `script/_inv_md/`，只读）；`00-编纂规则与格式规范/01-规则/脚本与命令/fix_md_invisible.py`（清理执行器：默认 dry-run，`--apply` 写盘；写盘前逐件断言“去除全部空白与目标字符后逐字相同”，即内容零改动）。

## 磁盘清理安全口径（2026-10-22 立）

**范围**：本机磁盘清理（ZCode 会话／缓存／构建产物、IDE 残留目录、系统盘清理）判据。项目数据侧的删除另有专条（`12-数据库备份/` 与 `03-原始史料库/12-数据库备份/` 删除应 ykla 明示）。

- **删除量以磁盘实测为准**，不用脚本累加器（会双重计数）；`rmtree(ignore_errors=True)` 会静默失败，**删除后应 `ls` 复验**；判“已删”按父目录两次 `os.listdir` 枚举比对。
- **C 盘大量删除后系统还原点（SVI）会涨到与删除量同量级**，吞掉释放出来的空间；`du` 类工具看不到、`vssadmin` 需管理员。**净可用空间是唯一可信口径。**
- **mtime 比较的单位陷阱**：`os.path.getmtime()` 返回**秒**。用它去比毫秒时间戳恒假，会使“今日保护”全线失效（实测曾因此删掉 280 个正在写的日志）。改脚本后应用合成用例验证保护窗。
- **按“今天有更新”判定在跑会话会失效**：长批次线整天在写库，整库都落在保护窗内。应改用按会话 id 定向清理。
- **能力探测先于批量写入**：`VACUUM` 后立即 `getsize` 可能读到替换前的瞬态旧值，判定成功应看 `PRAGMA page_count × page_size` 与文件大小一致 ＋ `freelist_count` 归零。
- **WAL 会自动合并**，`VACUUM` 后可能短暂涨到与主库同量级，checkpoint 后自动截断——**不要手工删 `-wal`**。
- **白名单应显式列凭据与唯一存本**：自动化清理的删除表应先经 dry-run 人工过目，凭据文件（keyblob 等）应显式列入保护；删除任何“疑似陈旧副本”前应确认其唯一存本仍然存在（历史上曾因成品仓库被删而使构建目录成为唯一源码树）。
- **目录名与预期不符是常态**：IDE 与工具的数据目录名常与产品名不同（如 Trae 的数据目录名不含“Work”），按名字找会漏；应以实际扫描结果为准。

**判据非空**：mtime 单位陷阱与保护窗失效可用合成用例（一个昨日 + 一个今日文件）验证；还原点吞差额可由清理前后 `Get-PSDrive` 净可用空间实测。
