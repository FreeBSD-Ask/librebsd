## 文献下载规则

本章节来源于 `annas-archive-chapter-download-2026-07-26` spec 的技术方案整合，是所有文献下载行为的唯一规则来源。上文“书籍资料获取流程”小节为高层概览，本章节为可执行细节。所有文献下载（含 Anna's Archive 三镜像并行下载、OCR 后处理、manifest 管理）须按本章节规则执行。

### Anna's Archive 镜像优先级与故障转移

**镜像列表**（按优先级）：

1. `https://annas-archive.gl`
2. `https://annas-archive.pk`
3. `https://annas-archive.gd`

**故障转移机制**：若主镜像（`.gl`）请求失败（HTTP 5xx、超时、连接拒绝），自动切换至次镜像（`.pk`），再至第三镜像（`.gd`）；每个镜像最多重试 3 次，重试间隔指数退避（1s、2s、4s）。

### 搜索策略与结果筛选

**搜索优先级**（按精确度）：

1. ISBN 搜索：`<mirror>/search?q=<isbn>&ext=pdf&lang=<target_lang>`
2. DOI 搜索：`<mirror>/search?q=<doi>&ext=pdf`
3. 标题+作者搜索：`<mirror>/search?q=<title>+<author>&ext=pdf&lang=<target_lang>`
4. 仅标题搜索（兜底）：`<mirror>/search?q=<title>&ext=pdf`

**结果筛选规则**（按优先级）：

1. 语言匹配 `language_target` 字段（精确匹配优先；若无精确匹配，英文书籍可接受 `en-us`/`en-gb` 等变体）
2. 格式：PDF 优先，EPUB 次之（用户要求“便于识别的格式”，PDF 更通用）
3. 年份：与 `year` 字段一致优先；否则取最新版本
4. 文件大小：书籍 ≥ 1MB，论文 ≥ 50KB（避免下载到错误的小文件）
5. 来源：优先 `Library Genesis`、`Sci-Hub`、`Internet Archive` 标记的条目（这些通常质量较好）

### 文件完整性验证

下载完成后须验证文件完整性：

- **PDF 文件**：须以 `%PDF-` 开头
- **EPUB 文件**：须以 `PK`（ZIP）开头
- **文件大小阈值**：书籍 ≥ 1MB，论文 ≥ 50KB

验证通过后方可移动至目标目录并更新 manifest；验证失败时按“Anna's Archive 镜像优先级与故障转移”小节规则重试下一镜像。

### OCR 后处理

**PDF OCR**：使用 Tesseract 命令 `tesseract <input.pdf> <output_basename> -l eng+chi_sim+fra+deu --psm 1`，输出 Markdown 至对应 `ocr/` 目录，文件名同原 PDF 但扩展名 `.md`。

**文本层优先**：OCR 前须先检测 PDF 文本层（pymupdf `get_text()` 全页提取 >100 字符），**有文本层的矢量 PDF 直接用文本层入库（`pymupdf_textlayer`，ocr_status=verified），不 OCR**；仅纯扫描件才 OCR。

**RapidOCR 替代**：Tesseract 无法安装（winget/choco 权限受限）时改用 **RapidOCR**（`rapidocr_onnxruntime`，纯 Python + onnxruntime，清华镜像安装），流程：pymupdf 渲染 200-250dpi → RapidOCR 识别 → 输出 `ocr/*.md`；8 进程并行 + 每文件独立子进程。完整规范见 [镜像站挖掘与OCR流水线规则.md](镜像站挖掘与OCR流水线规则.md)。

**EPUB 转换**：使用 pandoc 命令 `pandoc <input.epub> -t markdown_strict -o <output.md>`，输出至对应 `ocr/` 目录。

**OCR 校对规则**：按 0 信任原则，OCR 文本须与原 PDF 抽样核对（每 100 页抽 5 页比对），警惕技术术语、版本号、人名错讹；在 manifest `ocr_status` 字段标注：错讹率 < 5% 标 `verified`，≥ 5% 标 `needs_review`。

**OCR 失败处理**：若 Tesseract/pandoc 未安装或失败，标记 `ocr_status=failed`，记录错误，不阻塞下载流程；扫描质量差到无法识别的（如 1 页模糊照片）检索其他转载格式代替（官方重印本/二手文献转录），不强行入库。

### 元数据回写与 manifest 管理

**参考文献回写**：每本书/论文下载成功后，须按 GB/T 7714-2015 格式将其完整著录同步至 `04-现代研究文献/01-参考文献总目/` 对应类别子文件（如哲学类回写至 `哲学与史学理论.md`，BSD 经典回写至 `bsd相关经典著作.md`），附“下载自 Anna's Archive 镜像 `<mirror>` 于 `<date>`”脚注。

**manifest 单一来源真相**：manifest JSON 作为单一来源真相，存储于 `04-现代研究文献/03-文献下载/annas-archive-manifest.json`。

**manifest 必填字段**：`manifest_version`、`created_at`、`updated_at`、`mirrors`、`entries[]`。

**每条 entry 必填字段**：`id`、`title_original`、`title_zh`（如有）、`author`、`author_lastname`、`year`、`publisher`、`isbn`、`doi`、`language_target`、`language_decision_reason`、`format`、`type`、`category`、`chapter_refs[]`、`source_urls[]`、`download_status`、`downloaded_filename`、`downloaded_path`、`downloaded_at`、`downloaded_from_mirror`、`file_size_bytes`、`ocr_status`、`ocr_filename`、`ocr_path`、`ocr_at`、`verification_status`、`verification_notes`、`errors[]`。

**统计报告**：生成 `04-现代研究文献/03-文献下载/annas-archive-stats.md`，含总条目数、已下载数、失败数、待下载数、按类别统计、按章统计、失败条目清单。

### 并行下载与限速

- **并行执行**：使用 `concurrent.futures.ThreadPoolExecutor` 并行下载
- **默认并行度**：`max_workers=3`，可通过 `--workers` 命令行参数调整，最大 5
- **限速**：每镜像每秒最多 2 个请求（`time.sleep(0.5)`）
- **原子性**：manifest 更新使用 `threading.Lock` 保证原子性，无并发写入冲突

### 失败处理与断点续传

- **失败标记**：三镜像全部失败时标记 `download_status=failed`
- **错误记录**：`errors` 数组含每次尝试的镜像、HTTP 状态、错误信息、时间戳
- **不阻塞**：失败不阻塞，继续下一条
- **断点续传**：支持 `--resume` 参数跳过 `download_status=success` 条目
- **重试失败**：支持 `--retry-failed` 参数仅处理 `download_status=failed` 条目（清空 `errors` 后重试）

### 0 信任原则叠加

下载来源（Anna's Archive 镜像）仅作为“获取途径”，不替代内容真实性验证。

- **交叉验证**：下载的 PDF/EPUB 内容须与其他独立来源（出版社官网、Internet Archive、图书馆 OPAC）交叉验证关键信息（ISBN、出版年、作者、页数）
- **OCR 文本核对**：OCR 文本须核对原文警惕错讹
- **严禁臆造**：严禁基于模型记忆臆造文献条目或核查结论；所有条目须来自项目文件真实提取或已三次复查的条目
- **叠加执行**：本章节的 0 信任要求与既有“0 信任原则叠加说明”小节的要求叠加执行，不得以任一方替代另一方

### 文件名格式规则

**文件名模板**：`<year>_<author_lastname_or_surname>_<title_slug>_<lang>.<ext>`

**示例**：

- 英文书籍：`2012_Kuhn_The-Structure-of-Scientific-Revolutions_en.pdf`
- 中文书籍：`2012_库恩_科学革命的结构_zh.pdf`
- 多作者书籍：`1987_Bijker-et-al_The-Social-Construction-of-Technological-Systems_en.pdf`
- 外文论文：`1982_Prown_Mind-in-Matter-An-Introduction-to-Material-Culture-Theory-and-Method_en.pdf`
- 法语原版书籍：`1969_Braudel_Ecrits-sur-l-Histoire_fr.pdf`

**slug 规则**：

- 英文：lowercase，空格→`-`，去除非字母数字字符（保留 `-`），最大 60 字符（超出截断且不在词中间断开）
- 中文：保留中文字符，标点（顿号/逗号/句号/冒号/书名号）→`-`，空格→`-`，最大 40 字符
- 其他外文：保留原文字符，空格/标点→`-`，最大 60 字符

**作者姓氏规则**：

- 英文：取 lastname（如 Kuhn、Bijker、McKusick、Prown）
- 中文：取姓氏（如 库恩、麦克西奇、潘诺夫斯基）
- 多作者（≥3）：第一作者姓氏 + `et-al`
- 法/德/意等：取作者姓氏（如 Braudel、Ginzburg、Latour）
- 日本：取姓氏罗马字（如 村上 Murakami）

**年份规则**：使用所下载版本的出版年（非首版年）。如下载 2012 年 50 周年纪念版则用 2012，下载 1962 首版则用 1962。

**扩展名规则**：`.pdf`、`.epub`。OCR 输出文件同名但扩展名为 `.md`。

**重名冲突处理**：若两书生成相同文件名，附加 `_v2`、`_v3` 后缀；并在 manifest `notes` 字段记录冲突。

## 新增文献自动检测规则

本章节为新增 PDF/EPUB/CAJ 文献自动检测与入库流程的规则来源。当用户向 `04-现代研究文献/03-文献下载/` 目录下新增文献文件时，须按本章节规则执行自动检测入库流程。详细操作步骤见 [00-编纂规则与格式规范/02-操作手册/08-ai逐章生成操作流程.md](../02-操作手册/08-ai逐章生成操作流程.md) 第 8.4 节。

### 自动检测触发条件

具体执行要求：

- **触发时机**：用户向 `04-现代研究文献/03-文献下载/` 目录下 `01-pdf/`、`02-epub/`、`04-caj/` 任一子目录新增 `.pdf`、`.epub`、`.caj` 文件时
- **递归扫描**：扫描须递归进入子目录（如 `01-pdf/01-BSD核心书籍/`）
- **排除目录**：扫描须跳过 `10-无关文件/` 目录及其下所有内容
- **执行命令**（2026-10-24 更正：`references_fulltext` 已升格 DuckDB 主存储层，旧 SQLite 版脚本退役）：`python 00-编纂规则与格式规范/01-规则/脚本与命令/_full_ingest_all.py --dry-run`（仅检测）或去掉 `--dry-run`（入库）
- **单文件入库**：当前由 `_full_ingest_all.py` 的 `--limit 1 --base-dir <目录>` 覆盖；旧 `--file` 单文件模式随 SQLite 版脚本一并退役
- **退役件防呆**：旧 `auto_ingest_new_pdfs.py` 仍留在目录内作历史参照，但对 `references_fulltext.db`（0 字节空壳）**fail-closed exit 2**，避免 `sqlite3.connect` 静默新建空库、把写入丢进空壳；`cleanup_duplicates_and_errors.py` 同法处置，其 DuckDB 化列为 `TD-029`

### 去重执行要求

具体执行要求：

- **SHA-256 精确去重**：每个待入库文件须计算 SHA-256，与 `references` 表 `sha256` 字段比对；相同哈希的文件跳过入库，写入 `reference_duplicates` 表（`dup_type='sha256'`）
- **标题+作者+年份模糊去重**：归一化标题（去除空格、标点、大小写）+ 第一作者姓氏 + 年份三元组与既有记录比对；三元组全同的文件跳过入库，写入 `reference_duplicates` 表（`dup_type='fuzzy'`）
- **重复文件处理**：重复文件不删除原文件，仅在数据库标记跳过；日志记录 `status='skipped'` 与 `error` 字段说明重复类型
- **禁跳过去重**：不得以“文件显然独特”为由跳过去重检查

### 元数据验证标准

具体执行要求：

- **三级回退采集**：元数据采集须按 YAML frontmatter → 文件名模式 → PDF metadata 三级回退，前一级采集成功则不降级
- **必填字段**：`title`、`author`、`year`、`format`、`file_path`、`filename`、`sha256`、`file_size` 八字段必填；无法采集的字段填“未知”（title）/“不详”（author、year）
- **年份规整**：年份须为四位整数；非四位整数的年份字段填“不详”
- **文件完整性验证**：PDF 须以 `%PDF-` 开头，EPUB 须以 `PK` 开头，文件大小须 ≥ 50KB；验证失败的文件不入库，日志标记 `status='failed'`
- **入库前核验**：文件大小、可读性、标题一致性三项核验须全部通过；不通过的文件立即删除后继续流程（详见 `project_memory.md` 硬约束）

### 章节匹配置信度阈值

具体执行要求：

- **高置信度匹配**：关键词重合 ≥ 2 项，`match_confidence ≥ 0.7`，自动入库并写入 `chapter_matches` 表
- **中置信度匹配**：关键词重合 1 项，`0.5 ≤ match_confidence < 0.7`，自动入库但日志标记“需人工复核”
- **低置信度匹配**：关键词重合 < 1 项，`match_confidence < 0.5`，写入 `chapter_matches` 表但 `primary_chapter=0`，日志标记 `status='manual'`，须人工确认
- **匹配依据留痕**：`chapter_matches.match_reason` 字段须记录匹配命中的关键词清单

### 综述追加程序

具体执行要求：

- **追加条件**：仅当 `match_confidence ≥ 0.5` 且对应章节在 `chapter_reviews` 表中存在记录时才执行追加
- **追加内容**：在 `chapter_reviews.revised_review_text` 末尾追加新文献引用段落，含文献著录、与章节议题的关联说明（约 100-300 字）
- **字数约束**：追加后 `revised_word_count` 须在 300-5000 字范围内；超长（>5000 字）时不追加，日志标记“需人工精简”

### 参考文献总目与数据库同步回填（ref_id 机制）

**说明**：`04-现代研究文献/01-参考文献总目/` 各分类 `.md` 的著录条目以 `- [ref_id] 著录文本` 格式存在，其中 `[ref_id]` 即 `references_fulltext.duckdb` 中 `references.id`（总目由 `script/_gen_catalog_30_categories.py` 从数据库导出时生成，含此前缀）。该前缀构成“总目 ↔ 数据库”按 id 精确同步的机制基础。

具体执行要求：

- **同步方向**：数据库 → 总目（`_gen_catalog_30_categories.py` 导出）；总目 → 数据库（回填增强，**单向、只补缺失字段，不覆盖数据库已有值**）。
- **回填范围**：`references` 表中缺失的 `author` / `year` / `publisher` / `isbn_doi` 四个字段，从总目著录文本解析补录。
- **触发时机**：新增文献入库、总目著录被人工增补/修订后，运行 `script/_fix_from_catalog.py` 同步回填；回填结果须复核（dry-run 预览 → 正式执行）。
- **解析规则（0 信任原则）**：
  - `author`：取著录首段作者；**排除**纯大写缩写/文档编号（如 `AA-BG`、`SMM`）、文件名串（含下划线或过长）、期刊期号（如 `JulyAug`）、月份词、工具名/数据库名（Adobe、CNKI 等）；机构作者（FreeBSD Foundation、NASA 等）可保留，无法判定时宁缺勿滥。
  - `year`：仅取独立 4 位年份（1950–2030，前后非数字，排除 8 位日期与 ISBN 串）；优先出版年/会议年/期刊年，规避书名内年份范围（如《ACM图灵奖:1966-2006》取 2008）。**禁止使用 PDF CreationDate 作出版年**（其为文件创建/扫描时间）。
  - `publisher`：`[M]. 出版地: 出版者, 年份` 格式解析。
  - `isbn_doi`：`ISBN:` / `DOI:` 正则提取（如 `10.1145/989.990`、`978-0-201-54777-1`）。
- **留痕**：每次回填须写 `reference_update_log`（`updated_by='catalog_sync'`，记录字段变更与来源）。
- **一致性维护**：总目条目若指向已删除的 `references.id`（孤儿 id），不创建回填记录，标记待人工确认是否恢复文献或清除总目条目。

### 日志核验协议

具体执行要求：

- **日志文件位置**：`script/_auto_ingest_logs/ingest_log.jsonl`，每行一条 JSON 记录
- **必填字段**：`timestamp`、`file_path`、`status`（success/skipped/manual/failed/dry-run）、`reference_id`、`chapter_matched`、`error`
- **看板文件**：`script/_auto_ingest_logs/dashboard.md`，含六项统计（待入库文件数、成功入库数、跳过重复数、失败数、需人工确认数、本次检测时间）
- **入库后核验**：入库完成后须核验日志中 `status='failed'` 与 `status='manual'` 条目，逐条排查原因
- **数据库一致性核验**：核验 `references` 表新条目数 = 日志 `status='success'` 条目数；`chapter_matches` 表新条目数 = 日志 `status='success'` 条目数
- **CSV 一致性核验**：核验 CSV 新增行数 = 日志 `status='success'` 条目数
- **0 信任叠加**：本章节的自动入库不替代既有 0 信任原则与三次复查流程；自动匹配结果须人工抽样复核（每 10 条抽 1 条核对匹配准确性）

### 自动入库与人工复核关系

具体执行要求：

- **自动入库为辅助**：自动入库管线仅为辅助工具，不替代人工判断
- **人工复核保留**：低置信度匹配（`match_confidence < 0.5`）须人工确认章节归属；高置信度匹配须人工抽样复核
- **失败条目处理**：`status='failed'` 条目须逐条排查原因，修复后重跑 `--file` 模式入库
- **数据库修订**：人工确认后须手动更新 `chapter_matches.primary_chapter`、`match_confidence`、`match_reason` 字段
- **综述修订**：人工确认章节后须手动在 `chapter_reviews.revised_review_text` 中追加引用段落，并更新 `revised_word_count`、`revised_at`、`revised_by`（`revised_by='manual'`）
