# 小节建制与题名规则（2026-10-29 立）

> **性质**：本规则是大纲树小节层的唯一判据源，约束小节的建制、题名、四源合成、空骨架、升格与批准。经 ykla 2026-10-29 裁定立规。
> **适用对象**：`05-卷册大纲/` 磁盘树的小节 `.md`，以及 `05-卷册大纲/目录/data/outline.txt` 与装配产物 `index.html` 的第四级小节行。
> **与既有规则的关系**：层级、命名、编号、尺寸、SUMMARY 镜像以《大纲层级与目录规则》为准；题名形态、四源合成、空骨架、升格与卷级批准以本规则为准；术语与标点以《写作规则》与《流程规则/04-大纲结构与编号》为准；史料可信度以《考据规则》为准。冲突时按上述分工裁决。
> **授权依据**：`05-大纲落地Task7-8任务书-20261027.md` §五 Phase 4（小节级聚合／拆分／重构／删除预授权，应逐件复核）；Phase 4b（ykla 撤销“批次一二三”式切块，只按主题重构）。
> **不动节层原则**：节为 `outline.txt` 的既有结构面（76 卷 544 章 3 951 节）；本规则只约束节内小节。确需拆节者走 P1 升格；2.3 的 P1 拆节已由 ykla 2026-10-29 批准，是本次唯一已批例外。

## 一、小节的本质

1. **小节是论题单元，不是史料单元。** 一个 `.md` 承载一个可命名的论题；论题可由一条史料、多条同类史料或多件旧件拆并而成。
2. **题名是论题的名字，不是史料摘要。** 读者只看目录即知本小节论证什么；不必读正文即可定位。
3. **一节的小节集合应构成该节的论证骨架。** 合起来覆盖节题所指范围，分开各有独立论题，互不重复。
4. **设计优先，史料次之。** 小节体系由大纲（卷—章—节）推出：先依节题判定该节应论证哪几个论题，再据此设小节；史料按论题择取填入。不应由存量史料反推小节结构。
5. **史料不足先补证，补证无果建空骨架；史料有余则挂账。** 论题成立而语料无同类块者，先按《DOC_MINE补证块格式规则》§六 跑补证链；穷尽查证无果方建空骨架 `.md` 并在例外台账记 `unresolvable`。一论题可容纳的史料超出 J2 者，择其要者入纲，余者挂 `surplus/<节>.tsv`，源件仍在只读旧树可回溯，不等于删除。

### J4 处置阶梯

逐块择一，落块级台账：

1. **归入**：进入对应论题小节，默认处置。
2. **辑存**：多个低价值块合并为一件，题名标“辑存”与范围，不逐块设小节。
3. **移出**：确属他卷论题者，挂 `ref-unresolved.tsv`，记建议宿主；禁径删。
4. **挂账**：本小节或本节容量已满，块进 `surplus/<节>.tsv`；源件仍在旧树，目录不显。
5. **删除**：仅限零内容块（空块、纯签名、退订启事），逐块记 `rowmine_id` 与 sha256。

## 六、空骨架 `.md`

1. **每个小节应有 `.md`**。有史料者填块；无史料者先跑补证链（§8.2 第 3 步），补证仍无块者方建空骨架。
2. 空骨架只含 H1 与 YAML 全字段，不写正文、不写导语、不写过渡、不写结论。
3. YAML 字段：`status`（`skeleton`／`filled`／`closed`）、`volume`、`chapter`、`section`、`subsection`、`thesis`、`designed_at`；`closed` 另应 `resolution_reason`（`unresolvable`／`merged`／`retired`）、`closed_at`、`closed_ref`。
4. H1 应与题名一致；文件名按 `M.N.P-slug.md`，slug ≤40 字符。
5. 空骨架计入 `doc-metrics` 总小节数、`targets.tsv` subsec 节点、L19 三向双射与 SUMMARY；不应以“无 .md”表示设计级。
6. 有史料后填块时，改 `status: filled`，并按内容一致性判据复核题名。
7. **状态义务**（2026-11-10 立，2026-11-11 修订）：`skeleton` 应与 `design/exceptions/V{NN}.tsv` 对应——待补证者记 `open`／`claimed`；穷尽查证无果者改 `status: closed`＋`resolution_reason: unresolvable`，台账记 `unresolvable`＋`resolution_kind=exhausted`＋`resolution_ref=doubts:<id>`；合并／退役改 `status: closed`＋`resolution_reason: merged`／`retired`，走结构工单并报批。不应以“已建骨架”代替补证结论，不应让已决题留在 `skeleton` 计数。

## 七、批准、批次与全量标题

1. **批准单位是卷。** 每卷两次：标题批准（`approved/V{NN}.title.ok`）→ 内容落盘批准（`approved/V{NN}.land.ok`）。执行者不应自批。
2. **1 卷 1 批；多会话只处理不同卷。** 同一卷同一时刻只允许一个会话写其子树与 fragment；全局文件由合并器单写。
3. **全量标题先完成。** 全部接收卷获 `title.ok` 后，内容批才开工；任一接收卷无 `title.ok`，内容批不应开工。
4. **V01 例外**：2.3 样板有提前 `land.ok`，记 V01 全卷标题台账 hash；V01 其余章最终 `land.ok`。
5. **先裁升格再批标题。** 每卷先裁 P1—P3，再定稿标题、再批标题；批准后改题或改结构即失效重批。
6. **tag**：每卷批收口必打 annotated tag `outline-rollout-<卷>-<YYYYMMDD>`；失败批不打；逐 tag 记 `映射/里程碑tag台账.tsv`。
7. **批准记录**：`映射/title-design/approvals.tsv` 记 `kind（title｜landing）／vol／title_count／ledger_sha256／approved_by／approved_at／note`；标记内 hash 与当前台账不符即拒。
8. **按卷任务组**：全量标题铺开拆为 76 个按卷任务组，组间零写依赖、可并行；注册表与任务卡由 `脚本与命令/build_title_taskgroups.py` 再生（`--check` 判漂移），协议见 `05-卷册大纲/映射/parallel/title/README.md` §七。组只写本卷四件（台账、证据、例外、呈审报告）与 `parallel/title/V{NN}/`；全局批准件由合并者单写。

## 八、作业流程

### 8.1 标题线（独立、提前）

**拟题自检三条**（2026-11-03 增，依据 title3a 战役错误类型学）：①日期类断言应核到“日”级原文方可入题面；②枚举类断言（清单、序次、计数）逐项点数；③缺席命题（“未留下／不存在”类）一律附检索面限定语。比较卷“某系自述”型断言：证据表应各系一行，不应他系转述代证。形态问题对照 §4.4 附表预先规避。

**改题同批三件套**（2026-11-03 增，依据战役尾批 22 件“题已改而论题未改”缺陷）：改题不止于题名——同一批应①改写被推翻断言所在的 `thesis`；②同步 `title-evidence` 中与旧断言相抵的证据行（改引新锚，或标 `conflict=noted` 并在勘误台账记明理由）；③重算 `ledger_sha256` 并同步 `done.json`。采纳器（`_adopt_all.py` 一类）只写题名、指纹与凭据，**不读论题**，故改题后应逐条回读论题与证据：论题仍含被推翻断言者，一律判为**未完成**。

1. 读卷题、章题、节题与 `@@` 注，判定本节应论证的论题骨架。
2. 四源合成 2—12 个标题（中位数 5—7），写 `title-design/V{NN}.tsv` 与 `title-evidence/V{NN}.tsv`。
3. 例外判定：无法归纳、建议独立者逐条进 `exceptions/V{NN}.tsv` 与 `V{NN}-例外报告.md`。
4. 每卷先裁 P1—P3，再定稿标题，呈 ykla 卷级批准。
5. 批准后写 `title.ok`；无史料小节建空骨架 `.md`；全量标题完成前不研读史料。

### 8.2 内容线（标题批准后）

1. 取已批标题台账，核对 `title.ok` 与 `ledger_sha256`。
2. 按节从旧树取候选件，拆 `ROW_MINE` 块，逐块判读并归属。
3. **补证**（2026-11-10 增，ykla 令；2026-11-12 修订）：论题已批而语料无同类块者，不应直接落空骨架；应按《DOC_MINE补证块格式规则》§六 跑 S0—S5 补证链——先以四键查库内既有文献复用，**再逐题联网核验（全 76 卷必经，库内命中不豁免）**；联网所得先入 `references` 与 claim 库，再以 `DOC_MINE` 块入纲；穷尽查证无果者 `exceptions` 标 `unresolvable` 并登记存疑库。
4. 落块级台账 `design/<节>.tsv`：`source_id／rowmine_id／原文件／块序／新小节／处置／理由`；补证块另落 `design/supplement/V{NN}.tsv`。
5. 例外与挂账：无法归纳、建议独立、容量已满者分别进例外报告与 `surplus/<节>.tsv`。
6. 冻结设计卡 `design/<节>.md`：节旨、承载判定、标题表、证据、缺口、例外、升格评估。
7. 呈 ykla 落盘批准，写 `land.ok`；无标记不应写 `.md`、不应合并页面。
8. 写 `.md`：H1＋逐字节块；空骨架写 H1＋YAML；不写导语、过渡、结论。
9. 写 `outline.txt` 第四级行，重装配页面，跑门禁与回归，按卷提交并打 tag。

## 十、禁止事项

- 不撰写正文（红线 1）；空骨架不写正文。
- 不由存量史料反推小节结构。
- 不以单一来源定题；单源题不应批准。
- 不手改 `index.html`；一切走 `assemble_index.py` 与合并器。
- 不用 `.bak`／`.prebak` 等旁路副本；留痕唯一靠 Git。
- 不做自动化与定时任务。
- 不先斩后奏升格；未获批不应改节层。
- 不以“档案节”为名突破 J3 上限 12。
- 不以“语料无同类块”为由停在空骨架：论题已批而语料缺块者，应先按《DOC_MINE补证块格式规则》§六 跑补证链；补证无果方得改 `closed/unresolvable` 并在台账与存疑库登记，不应保留 `skeleton` 冒充已决。
- 不越过 claim 库把联网结论写入小节；不在四键命中后重复入库或重复存全文；不以库内命中为由跳过联网核验。

## 十一、与既有规则的关系

- 层级、命名、编号、尺寸、SUMMARY 镜像承《大纲层级与目录规则》；该规则已定“大纲树四层（卷→章→节→小节）、小节唯一 `.md` 文件层”与 `data/outline.txt` 四级行语法（§一.5，2026-11-06，`ADR-0020`），本规则不重复语法，只补题名建制与门禁。
- 尺寸阈值承同上 §三；本规则 J2 只加“≤12 块”的实用控制。
- 术语与 Port 条承《流程规则/04-大纲结构与编号》“大纲题名术语规则”。
- 史料可信度与 0 信任承《考据规则》。
- 本规则与上述冲突时，层级与尺寸以《大纲层级与目录规则》为准，题名形态与四源、空骨架、升格、卷级批准以本规则为准。
