# 长线任务归档规则

> **立**：2026-10-18（主理人令“把《长线任务总登记表》已经完成的内容独立存档，其下按任务分别新建目录进行拆分”）。本规则约束已收官长线从《长线任务总登记表》向归档目录的迁出与后续维护。

## 一、归档对象与触发条件

1. **对象**：《长线任务总登记表》17 条长线中终态为 `CLOSED`／收官／一次性任务完成的线（终态口径见登记表 §一 状态枚举与归档目录归档件）。
2. **不归档**：`文档源` 仍在推（如 A 线）、`DORMANT`（dragonfly T2、B 线）、`人工维护` 未完成（迁移准备层 T1–T10）、已移出长线范围（Linux 战线 Phase 3）者仍在总登记表。
3. **触发**：归档由主理人明示发起——本规则约束“怎么归档”，不授权“何时归档”。

## 二、归档位置与结构

- **归档目录**：`01-项目管理/01-编纂规划与报告归档/长线任务归档总登记表/`，与《长线任务总登记表》同目录。
- **结构**：目录根一个 `index.md` 总册（归档线清单＋归档口径＋指向关系）；其下**按任务分目录**，命名 `NN-<线名slug>/`，每目录一个 `index.md`。

## 三、归档内容（迁什么／不迁什么）

| 类别 | 处置 |
| ---- | ---- |
| 登记表 §一 该线总览表行 | 快照迁入归档件（总登记表表行保留不删） |
| 该线专属章节全文 | **逐字迁入**归档件；总登记表对应节改写为指针节（终态一句＋归档指针），**不得保留同内容全文**（双源禁止） |
| §一 总览表／文末机读块 | **不迁**（总览表与机读块留在总登记表） |
| §十五 变更记录 | **不整体迁出**，按窗口**轮替**（见 §三之一）：保留近三日窗口，更早条目逐字迁入 07 分册 |
| 在推线的已闭环批次史 | 线不整线迁出；其“`XX_bNNN 已全链闭环（…）`”一类**逐批历史流水**按线拆目录**轮替**（见 §三之二），总登记表对应子线只留当前状态＋指针 |
| 线级任务书／交接书 | 不迁，仍在《任务书迁移登记.md》登记的现路径；归档件内留指针 |
| 机读源（JSON／TSV／DuckDB／脚本） | **绝不迁**（探针与聚合器按原路径读取） |

## 三之一、§十五 变更记录轮替口径（2026-10-19 补）

> **为什么补**：2026-10-19 实测《长线任务总登记表》334,632 B／590 行，§十五 单节 **249,112 B＝74.4%**——
> 编年日志压过登记本职，任何会话接手一条长线都要先读七万多字流水才能定位“真值在哪”。故将上表
> “§十五 不迁”收窄为“**不整体迁出、按窗口轮替**”；§一 总览表与文末机读块仍一律不迁。

1. **窗口**：§十五 只保留**近三日**变更记录（按行首日期判，当日补记亦留在本表）。
2. **触发阈值**（本规则建议值，可随主理人裁定调整）：任一项越线即触发一次轮替——

   | 项 | 阈值 |
   | -- | ---- |
   | §十五 单节字节 | > 60 KB |
   | §十五 条目数 | > 40 条 |
   | 全表字节 | > 150 KB（触发**全表体检**：找出下一个最大单节，不必然轮替 §十五） |

   > **2026-10-19 修订**：原阈值为“§十五 字节占全表比 > 30%”。该比值阈值在第二轮轮替后被证伪——
   > §三 mail2d 从 52,622 B 压到 **6,523 B** 后，全表降到 71,208 B、§十五 31,786 B，**比值反而从 25.7% 升到 44.6%**。“占全表比”随其它节缩小而被动升高，是个自噬的触发器，
   > 故改为**绝对值**＋全表总量体检双闸。

3. **轮替去向**：`01-项目管理/01-编纂规划与报告归档/长线任务归档总登记表/07-登记表变更记录轮替/`，
   与 01–06 各线归档件同目录、独立编号。**07 是轮替件，不是线归档件**：01–06 收纳**已收官长线**的
   登记层全文，07 收纳**已滚出窗口**的变更记录。
4. **逐字保真**：迁入行与源段逐字节一致（行序、格式、加粗、emoji、链接一律不动）；总登记表侧以
   轮替指针行替代，原行零残留。
5. **权威载体**：永久变更记录的唯一载体是 `01-项目管理/00-变更记录/changelog.duckdb`（`entries` 表）；
   §十五 与 07 分册都只是登记层的窗口／留痕，与库冲突时**以库为准**。
6. **续写**：后续轮替在 07 分册内按日期倒序追加新分块，块首标注轮替日期、覆盖区间、条数与字节；
   不得改写既有分块。
7. **操作纪律同 §四**：写前备份、临时脚本锚点定位＋逐处断言、机读块逐字节不变、
   `_longline_status.py --check` 须 PASS、并发写者 mtime 复核。
   **首次轮替（2026-10-19）实测**：迁出 65 条／221,292 B，登记表 334,632 → 115,066 B（−65.6%），
   590 → 528 行；§一～§十四／§十六／机读块零改动，`--check` PASS。

## 三之二、在推线已闭环批次史轮替口径（2026-10-19 续）

> **为什么补**：第一轮轮替后（115,066 B，git 已提交），§三 mail2d 成为最大单节 **52,622 B＝45.7%**。逐行拆开看：
> H1 一行 16,140 字符、H3 6,512、H2 5,570、H4 2,155，内容几乎全是
> `XX_bNNN 已全链闭环（date：offset… → 候选… → register… → 叙述手… → 块入宿主… → bookkeep… → 台账…）`
> 这类**已完成的逐批流水**。流水本身有价值（它是跨批教训与门禁设计的唯一出处），
> 但它**不服务于续跑**——接手一条线只需要“现在到哪、下一站是哪、真值在哪、从哪个文件续”。
> 故把这类流水按任务拆目录轮替出去，登记表只留当前状态与提炼后的跨批教训。

1. **对象判定**：同一条子线里可**同时存在**留表与轮替内容。留表的必须是**续跑必需**——
   库范围、当前进度（台账实测）、下一站、真值源、续跑入口、跨批教训；轮替出去的是
   **已闭环批次的逐批流水**（`XX_bNNN 已全链闭环（…）` 一类）。判定标准一句话：
   **删掉它会不会让接手者无法开始下一批**——不会，就轮替。
2. **去向**：归档目录根下**按任务（子线）分别新建目录**，沿用 `NN-<线名slug>/` 命名，
   紧接在既有 01–07 之后连续编号（本批为 `08-mail2dH1批次史`、`09-mail2dH2批次史`、
   `10-mail2dH3批次史`、`11-mail2dH4批次史`）。分册卷首须标注：轮替日期、来源行号、
   覆盖批次范围、轮替原因、逐字保真口径、进度数字以登记表指针行为准。
3. **逐字保真**：分册正文各行**去掉行首 `> `（1 个 `>`＋1 个空格）即与源行逐字节一致**；
   不删减、不缩写、不重排。
4. **不迁当前状态数字**：分册**不重复登记进度数字**——进度数字的权威源是机读台账，
   登记表指针行与分册都不得另立一份（双源禁止）。
5. **跨批教训留在表内**：流水里的教训须**提炼去重**后留在总登记表（每条子线 2–4 条），
   因为教训是续跑要用的，流水才是归档的。
6. **续写**：该线后续批次闭环后，流水按同格式**追加到对应分册末尾**；登记表指针行的
   批次范围与“下一站”随台账同步更新。**分册只增不改**，不得回改既有流水。
7. **触发阈值**（建议值）：任一子线行 **> 4 KB** 且其中已闭环流水占比 **> 60%**，
   即触发一次该子线轮替；或在推线终态转 `CLOSED` 时整线归档（回到 §一 的常规归档，
   不再留指针行）。
8. **操作纪律同 §四**：写前备份、临时脚本锚点定位＋逐处断言、机读块逐字节不变、
   `_longline_status.py --check` 须 PASS、并发写者 mtime 复核。
   **首次轮替（2026-10-19）实测**：迁出 H1–H4 四行 **50,053 B** 至 08–11 四个分册
   （28,862／10,086／12,634／4,680 B），§三 四行原地替换（不增删行），登记表 §三 从 52,622 B 降到 **6,523 B（9.2%）**；§一～§二／§四～§十六／机读块零改动，
   `--check` PASS。§十五 补一行本批批记后，全表终态 **115,066 → 71,208 B（−38.1%）**、528 → 529 行。

> **顺带发现的口径问题（未在本批修）**：§一 总览表 H4 行仍记 `123,326/459,135＝26.86%`、
> openbsd_mail `42,000`，与台账实测（2026-10-19T19:17）`125,326/459,135＝27.30%`、
> openbsd_mail `44,000` 及内嵌机读块（同值）不一致，属该行维护者滞后台账，已提请 H4 线处理。

## 四、操作纪律

1. **写前备份**：总登记表先落同目录 `长线任务总登记表.md.prebak-<主题>-<日期戳>` 副本。
2. **脚本手术**：登记表改动一律走临时脚本（`script/`，UTF-8 无 BOM＋LF），锚点定位＋逐处断言恰好出现 1 次；**禁在登记表上直接 `open("w")` 截断写**，写盘走同目录临时件 → `os.replace`（SMB 上退避重试，同聚合器纪律）。
3. **机读块勿动**：`LONGLINE_STATUS_BEGIN…END` 之间逐字节不变；改后必跑 `C:/Python314/python.exe 00-编纂规则与格式规范/01-规则/脚本与命令/_longline_status.py --check`（须 PASS）。
4. **逐字保真**：迁入归档件的章节全文与登记表原文逐字一致；归档后总登记表侧以指针替代，原节零残留。
5. **登记**：归档批记 changelog（`id` 动态取 `max+1`）；归档线清单同步更新归档目录根 `index.md`。
6. **并发写者**：总登记表存在并发写者（他会话批次收口即改）——编辑前实测 mtime 与 `git diff`，编辑后断言“仅本批意图段变更”；写入者未收敛（短窗内 mtime 变动）时暂缓手术。
