# 任务轮替与归档规则

> **立**：2026-10-18（ykla 令“把《长线任务总登记表》已经完成的内容独立存档，其下按任务分别新建目录进行拆分”）。
> **2026-10-22 扩展并更名**：原名《长线任务归档规则》，现扩为覆盖长线任务、其他任务与工程批次的统一轮替规则；决策依据 `ADR-0005`。旧文件中历史审计报告里的旧路径为历史记录，不回改。
> **约束范围**：任务从立项到复审的状态迁移，以及任务书、批次史、版本史、变更记录、工程批次规格的轮替与归档；不约束数据库备份轮换、大纲内容版本与正文修订。

## 零、适用范围、任务分类与六态生命周期

### 0.1 任务分类

| 类别 | 对象 | 唯一入口 | 轮替去向 |
| ---- | ---- | -------- | -------- |
| A 长线任务 | 《长线任务总登记表》17 条登记线；未入册但已建任务书目录的线（`gapa662`、`05-大纲标准化`） | 总登记表 §一；未入册线以本目录 `index.md` | 整线归档入 `长线任务归档总登记表/NN-<slug>/`；在推线批次史入 08–11 类分册或任务书 `_历史快照/` |
| B 其他任务 | 阶段性或一次性任务：SenseAudio 四册、login 杂志、usenet、T1／T2、B 线、Linux Phase3、S-me 等 | `任务书迁移登记.md` 登记的线级任务书或交接书 | 任务书目录保留，批次史与版本史入同目录 `_历史快照/`；整任务归档在目录 `index.md` 加 `ARCHIVED` 横幅并登记指针 |
| C 工程批次 | `13-软件工程` 驱动的 `.trae/specs/` 批次 | 该批次 `spec.md`／`tasks.md`／`checklist.md` | 闭口后**复制**三件至 `长线任务归档总登记表/12-工程批次规格归档/NNN-<slug>/`；原目录不迁、不删 |
| D 轮替载体 | 任务书版本块、`_历史快照/`、登记表 §十五、批次史分册（`.prebak-*` 自 2026-10-23 起禁用） | 本规则与各任务书 `index.md` | 见 §三之一至 §三之五 |

**不适用**：数据库备份轮换（`流程规则.md`“数据库备份保留规则”）、大纲内容版本（`大纲层级与目录规则.md`）、正文修订（写作规则）、`script/` 临时件清理（流程规则临时文件规则）。

### 0.2 六态与迁移条件

| 状态 | 含义 | 进入条件 | 退出条件 |
| ---- | ---- | -------- | -------- |
| `REGISTERED` 立项 | 任务已有唯一入口、承担者、下一站与真值源 | 长线入总登记表 §一；其他任务建目录 `index.md` 并登记于 `任务书迁移登记.md` | 开始执行转 `ACTIVE`；撤销须 ykla 书面裁定并留 changelog |
| `ACTIVE` 执行 | 有人在场推进或明确排期 | 有当前进度、下一站与机读源 | 停滞转 `DORMANT`；完成转 `CLOSED` |
| `DORMANT` 挂起 | 暂停但未取消 | ykla 裁定或连续 30 日无推进且写明原因 | 恢复转 `ACTIVE`；取消转 `CLOSED`（写明未完成项与挂账） |
| `CLOSED` 闭口 | 交付物齐备或剩余项全部挂账 | §八 闭口判据全部满足 | 归档转 `ARCHIVED`；重开须 ykla 明示并新建 changelog |
| `ARCHIVED` 归档 | 历史内容已迁出，入口只留指针 | 归档件、索引、指针齐备且 `--check` PASS | 复审转 `REVIEW` |
| `REVIEW` 复审 | 季度或事件触发的复核 | 到期或触发条件成立 | 回到 `ACTIVE`／`CLOSED`／`ARCHIVED`，结论入复审台账 |

**硬规则**：

1. 状态未到 `CLOSED` 不得整任务归档；在推线的**已闭环批次史**不受此限，可按 §三之二先行轮替。
2. 任何状态迁移须有证据：命令输出、文件路径、台账数字或 changelog 条目；无证据的“已完成”不得入表。
3. 闭口不等于删除：闭口只停止推进，历史件按本规则轮替，不删原文。
4. 同一内容只保留一个权威载体；归档件是指针目标，登记表与任务书不得复制同内容全文。
5. 重开已闭口任务须 ykla 明示，并在 changelog 记明重开理由；已归档记录不回改。

## 一、归档对象与触发条件

1. **对象**：
   - A 类长线中终态为 `CLOSED`／收官／一次性任务完成的线（终态口径见登记表 §一 状态枚举与归档目录归档件）；
   - B 类其他任务中已 `CLOSED` 的任务；
   - C 类工程批次中已闭口且完成验收的批次（仅留存规格三件，见 §三之五）。
2. **不归档**：`文档源` 仍在推（如 A 线）、`DORMANT`（dragonfly T2、B 线）、`人工维护` 未完成（迁移准备层 T1–T10）、已移出长线范围（Linux 战线 Phase 3）者仍在总登记表；B 类未闭口任务不整任务归档。
3. **触发**：
   - 整任务归档由 ykla 明示发起——本规则约束“怎么归档”，不授权“何时归档”；
   - 批次史、版本史与 §十五 变更记录按 §三之一至 §三之三的阈值触发，可由主代理提出、ykla 批准后执行；
   - 阈值触发只提议轮替，不自动执行；无批准不得迁出。
4. **未入册线**：`gapa662`、`05-大纲标准化` 等已建任务书目录但不在 17 条登记表的线，按 A 类管理；其入口为本目录 `index.md`，整线归档前须先在 `任务书迁移登记.md` 与归档总表登记，不得直接迁入归档目录。

## 二、归档位置与结构

- **长线整线归档**：`01-项目管理/01-编纂规划与报告归档/长线任务归档总登记表/`，与《长线任务总登记表》同目录。
- **结构**：目录根一个 `index.md` 总册（归档线清单＋归档口径＋指向关系）；其下**按任务分目录**，命名 `NN-<线名slug>/`，每目录一个 `index.md`。
- **其他任务**：任务书目录保留原位；批次史与版本史入同目录 `_历史快照/`，目录 `index.md` 顶部加 `ARCHIVED` 横幅（含闭口日期、闭口判据、指针）；整任务清单登记在 `长线任务归档总登记表/index.md` 的“其他任务归档”表，不混入 01–06 长线归档件。
- **工程批次规格归档**：`长线任务归档总登记表/12-工程批次规格归档/NNN-<slug>/`，只收 `spec.md`／`tasks.md`／`checklist.md` 与一页闭口说明；原 `.trae/specs/<slug>/` 保持原位。
- **任务审计与复核轮替**：`长线任务归档总登记表/13-任务审计与复核轮替/YYYY-QN/`，只收已收口任务的审计与复核逐字轮替件；未收口任务留主表。
- **编号**：归档目录 `NN` 连续编号；`12` 保留给工程批次规格归档，`13` 保留给任务审计与复核轮替；后续新增按现有最大值加一，不跳号、不复用。

## 三之一、§十五 变更记录轮替口径（2026-10-19 补）

> **为什么补**：2026-10-19 实测《长线任务总登记表》334,632 B／590 行，§十五 单节 **249,112 B＝74.4%**——
> 编年日志压过登记本职，任何会话接手一条长线都要先读七万多字流水才能定位“真值在哪”。故将上表
> “§十五 不迁”收窄为“**不整体迁出、按窗口轮替**”；§一 总览表与文末机读块仍一律不迁。

1. **窗口**：§十五 只保留**近三日**变更记录（按行首日期判，当日补记亦留在本表）。
2. **触发阈值**（本规则建议值，可随 ykla 裁定调整）：任一项越线即触发一次轮替——

   | 项 | 阈值 |
   | -- | ---- |
   | §十五 单节字节 | > 60 KB |
   | §十五 条目数 | > 40 条 |
   | 全表字节 | > 150 KB（触发**全表体检**：找出下一个最大单节，不必然轮替 §十五） |

   > **2026-10-19 修订**：原阈值为“§十五 字节占全表比 > 30%”。该比值阈值在第二轮轮替后被证伪——
   > §三 mail2d 从 52,622 B 压到 **6,523 B** 后，全表降到 71,208 B、§十五 31,786 B，**比值反而从 25.7% 升到 44.6%**。“占全表比”随其它节缩小而被动升高，是个自噬的触发器，
   > 故改为**绝对值**＋全表总量体检双闸。

3. **轮替去向**：`01-项目管理/01-编纂规划与报告归档/长线任务归档总登记表/07-登记表变更记录轮替/`，
   与 01–06 各线归档件同目录、独立编号。**07 是轮替件，不是线归档件**：01–06 收纳**已收官长线**的
   登记层全文，07 收纳**已滚出窗口**的变更记录。
4. **逐字保真**：迁入行与源段逐字节一致（行序、格式、加粗、emoji、链接一律不动）；总登记表侧以
   轮替指针行替代，原行零残留。
5. **权威载体**：永久变更记录的唯一载体是 `01-项目管理/00-变更记录/changelog.duckdb`（`entries` 表）；
   §十五 与 07 分册都只是登记层的窗口／留痕，与库冲突时**以库为准**。
6. **续写**：后续轮替在 07 分册内按日期倒序追加新分块，块首标注轮替日期、覆盖区间、条数与字节；
   不得改写既有分块。
7. **操作纪律同 §四**：写前零副本（只打印 SHA-256）、临时脚本锚点定位＋逐处断言、机读块逐字节不变、
   `_longline_status.py --check` 须 PASS、并发写者 mtime 复核。
   **首次轮替（2026-10-19）实测**：迁出 65 条／221,292 B，登记表 334,632 → 115,066 B（−65.6%），
   590 → 528 行；§一～§十四／§十六／机读块零改动，`--check` PASS。

## 三之二、在推线已闭环批次史轮替口径（2026-10-19 续）

> **为什么补**：第一轮轮替后（115,066 B，git 已提交），§三 mail2d 成为最大单节 **52,622 B＝45.7%**。逐行拆开看：
> H1 一行 16,140 字符、H3 6,512、H2 5,570、H4 2,155，内容几乎全是
> `XX_bNNN 已全链闭环（date：offset… → 候选… → register… → 叙述手… → 块入宿主… → bookkeep… → 台账…）`
> 这类**已完成的逐批流水**。流水本身有价值（它是跨批教训与门禁设计的唯一出处），
> 但它**不服务于续跑**——接手一条线只需要“现在到哪、下一站是哪、真值在哪、从哪个文件续”。
> 故把这类流水按任务拆目录轮替出去，登记表只留当前状态与提炼后的跨批教训。

1. **对象判定**：同一条子线里可**同时存在**留表与轮替内容。留表的必须是**续跑必需**——
   库范围、当前进度（台账实测）、下一站、真值源、续跑入口、跨批教训；轮替出去的是
   **已闭环批次的逐批流水**（`XX_bNNN 已全链闭环（…）` 一类）。判定标准一句话：
   **删掉它会不会让接手者无法开始下一批**——不会，就轮替。
2. **去向**：归档目录根下**按任务（子线）分别新建目录**，沿用 `NN-<线名slug>/` 命名，
   紧接在既有 01–07 之后连续编号（本批为 `08-mail2dH1批次史`、`09-mail2dH2批次史`、
   `10-mail2dH3批次史`、`11-mail2dH4批次史`）。分册卷首须标注：轮替日期、来源行号、
   覆盖批次范围、轮替原因、逐字保真口径、进度数字以登记表指针行为准。
3. **逐字保真**：分册正文各行**去掉行首 `>` 及其后一个空格即与源行逐字节一致**；
   不删减、不缩写、不重排。
4. **不迁当前状态数字**：分册**不重复登记进度数字**——进度数字的权威源是机读台账，
   登记表指针行与分册都不得另立一份（双源禁止）。
5. **跨批教训留在表内**：流水里的教训须**提炼去重**后留在总登记表（每条子线 2–4 条），
   因为教训是续跑要用的，流水才是归档的。
6. **续写**：该线后续批次闭环后，流水按同格式**追加到对应分册末尾**；登记表指针行的
   批次范围与“下一站”随台账同步更新。**分册只增不改**，不得回改既有流水。
7. **触发阈值**（建议值）：任一子线行 **> 4 KB** 且其中已闭环流水占比 **> 60%**，
   即触发一次该子线轮替；或在推线终态转 `CLOSED` 时整线归档（回到 §一 的常规归档，
   不再留指针行）。
8. **操作纪律同 §四**：写前零副本（只打印 SHA-256）、临时脚本锚点定位＋逐处断言、机读块逐字节不变、
   `_longline_status.py --check` 须 PASS、并发写者 mtime 复核。
   **首次轮替（2026-10-19）实测**：迁出 H1–H4 四行 **50,053 B** 至 08–11 四个分册
   （28,862／10,086／12,634／4,680 B），§三 四行原地替换（不增删行），登记表 §三 从 52,622 B 降到 **6,523 B（9.2%）**；§一～§二／§四～§十六／机读块零改动，
   `--check` PASS。§十五 补一行本批批记后，全表终态 **115,066 → 71,208 B（−38.1%）**、528 → 529 行。

## 三之三、任务书版本史与历史快照轮替口径（2026-10-22 立）

> **为什么立**：2026-10-22 实测 `_HANDOFF_H3.md` 736,001 B，顶部按倒序累积 v20–v47 版本块；`mail2d任务书与交接书/` 目录 8.6 MB，含多份 `.prebak-*`（该类副本已于 2026-10-23 全库清除并禁止再生成）。版本史是审计线索，但压在任务书顶部会淹没“当前入口”。故把旧版本块按窗口轮替，任务书只留当前版本与前一版。

1. **对象**：任务书顶部的 `> **vNN＝date（…）**` 版本块；已有 `_历史快照/` 目录（`.prebak-*` 快照已禁用，不属轮替对象）。
2. **触发阈值**（建议值，任一越线即提议轮替）：
   - 单任务书 **> 200 KB**；
   - 版本块 **> 8 个**且版本块合计占文件 **> 50%**；
   - 同目录 `.prebak-*` 出现即违规（2026-10-23 起全库禁止，见 `流程规则.md`“临时文件规则”）；
   - `_历史快照/` **> 20 件**。
3. **保留窗口**：任务书只留**当前版本块＋前一版本块**；其余按倒序逐字迁入 `_历史快照/任务书-<线名>-版本史-<轮替日期>.md`。**不再保留任何 `.prebak-*` 副本**（已按 2026-10-23 令清除）。
4. **逐字保真**：版本块迁出时去掉行首引用符 `>` 及其后的一个空格后与源行逐字节一致；块间空行与顺序不动；分册卷首写轮替日期、来源行号、覆盖版本号、轮替原因。
5. **指针**：任务书 `index.md` 的“文件与角色”表须列出新增分册，并标明“存档件，勿采信为现行”。
6. **禁止**：不得删除 `_历史快照/` 文件来“减重”；不得改写已迁出的版本块；不得把版本史复制回任务书正文；**不得以 `.prebak-*` 等旁路副本替代版本块**（2026-10-23 令）。
7. **与批次史的区别**：版本史按**任务书版本**切分，批次史按**执行批次**切分；同一目录可并存，但不得互相混编或重复收录同一内容。

## 三之四、其他任务闭口与归档口径（2026-10-22 立）

1. **闭口判据**（四项全满足方可转 `CLOSED`）：
   - 任务书列明的交付物存在且路径可核；
   - 未完成项为 0，或全部转为技术债／挂账并写明承担者与复审触发；
   - changelog 有闭口条目，含证据路径与提交号；
   - 任务书 `index.md` 写明闭口日期、闭口判据与真值源。
2. **归档动作**：`index.md` 顶部加 `ARCHIVED` 横幅；批次史与版本史按 §三之二、§三之三迁入 `_历史快照/`；任务书正文保留，改指针节；在 `长线任务归档总登记表/index.md` 的“其他任务归档”表登记一行（任务名、目录、闭口日期、真值源）。
3. **不迁机读源**：台账、JSONL、DuckDB、脚本仍留原路径；若原路径在 `script/`（gitignored），须在任务书 `index.md` 写明“可重生成”或“已转存”，否则不得闭口。
4. **重开**：ykla 明示后在 changelog 记明理由，状态改回 `ACTIVE`；已归档分册不回改，新增内容另起分册。

## 三之五、工程批次规格留存口径（2026-10-22 立）

1. **对象**：`.trae/specs/<slug>/` 下的 `spec.md`、`tasks.md`、`checklist.md` 与闭口说明。
2. **留存方式**：批次闭口后**复制**三件至 `01-项目管理/01-编纂规划与报告归档/长线任务归档总登记表/12-工程批次规格归档/NNN-<slug>/`，并写一页 `闭口说明.md`（批次、日期、验收结论、证据路径、提交号）。原目录保持原位，供继续检索。
3. **触发**：批次闭口即执行；未闭口批次不复制。
4. **旧批次**：本规则生效前已存在的 226 个 `.trae/specs/` 目录**不追溯迁移**（2026-10-22 ykla 裁定）；后续按本条规定执行。
5. **保留**：已归档规格永久保留；`12` 分册内按 `NNN` 连续编号，不跳号、不复用；已归档件只增不改。
6. **不入库风险披露**：`.trae/specs/` 受忽略规则约束时，复制到 `12` 分册是唯一可入库载体；若复制失败，批次不得判 `ARCHIVED`。

## 三之六、任务审计与复核台账轮替口径（2026-10-22 立）

> **为什么立**：`任务审计台账.md` 与 `任务复核台账.md` 是生效后新任务的准入、复核与收口主表；若不设轮替，台账会随任务数增长而变成“只增不迁”的堆积，重演 `流程规则.md` 单文件过大的问题。故把两份台账纳入本规则，设阈值、去向、指针与双源禁止。

1. **对象**：`01-项目管理/02-工程决策与技术债/任务审计台账.md` 与 `任务复核台账.md`；以及随附的门禁输出摘要（若写入台账）。
2. **触发阈值**（初值，可在复审中调整；任一越线即触发一次轮替）：
   - 主表数据行 **> 100 行**；
   - 主表文件 **> 200 KB**；
   - **跨季度**：当前季度晚于最近一次轮替覆盖季度。
3. **轮替范围**：只迁**已收口任务**（收口结论 PASS 或 不适用）；未收口任务留在主表。同一任务的全部复核轮次随任务一并迁出，不得只迁审计行。
4. **去向**：`01-项目管理/01-编纂规划与报告归档/长线任务归档总登记表/13-任务审计与复核轮替/YYYY-QN/`，每卷含 `任务审计台账.md`、`任务复核台账.md`、`index.md`；卷首写轮替日期、覆盖季度、迁出任务数、主表指针、changelog。
5. **逐字保真**：迁入行与源表行逐字节一致（列序、空格、加粗、链接一律不动）；主表侧以指针行与统计行替代，原行零残留。
6. **主表指针**：主表新增“轮替记录”行，写轮替日期、覆盖季度、迁出任务数、归档指针、**源行哈希**（迁出前审计行 SHA-256 前 16 位）与 changelog；不得保留已迁任务的全文。门禁 `audit_task_lifecycle.py` L10 以源行哈希逐字核对归档件。
7. **原子写与零副本**：轮替前**不落任何副本**，改为打印源文件 SHA-256 与行数（留痕与回滚由 Git 承担，2026-10-23 令）；写盘走同目录临时件 → 回读断言 → `os.replace`；幂等复跑零差异。
8. **changelog**：轮替批次须在 `changelog.duckdb` 记一条，含轮替日期、迁出任务数、归档指针与校验命令。
9. **禁止**：不得删除未收口任务；不得把归档件全文复制回主表；不得同一次轮替把同一任务留在两处（双源）；不得改写已迁出的历史行。
10. **操作纪律同 §四**：写前打印 SHA-256（零副本）、临时脚本锚点定位＋逐处断言、主表表头不变、`audit_task_lifecycle.py` L9–L10 PASS。

## 四、操作纪律

1. **写前零副本**：总登记表与其他任务书的轮替写盘前，只打印源文件 SHA-256、字节数与行数；**禁止**再落 `长线任务总登记表.md.prebak-*` 或 `.prebak-*` 副本（2026-10-23 用户令，全库封禁口径见 `流程规则.md`“临时文件规则”）。
2. **脚本手术**：登记表与任务书改动一律走临时脚本（`script/`，UTF-8 无 BOM＋LF），锚点定位＋逐处断言恰好出现 1 次；**禁在目标文件上直接 `open("w")` 截断写**，写盘走同目录临时件 → `os.replace`（SMB 上退避重试，同聚合器纪律）。
3. **机读块勿动**：`LONGLINE_STATUS_BEGIN…END` 之间逐字节不变；改后必跑 `"C:/Program Files/Python315/python.exe" 00-编纂规则与格式规范/01-规则/脚本与命令/_longline_status.py --check`（须 PASS）。
4. **逐字保真**：迁入归档件的章节全文与源文逐字一致；归档后源侧以指针替代，原节零残留。
5. **登记**：归档批记 changelog（`id` 动态取 `max+1`）；归档线清单同步更新归档目录根 `index.md`。
6. **并发写者**：总登记表与任务书存在并发写者（他会话批次收口即改）——编辑前实测 mtime 与 `git diff`，编辑后断言“仅本批意图段变更”；写入者未收敛（短窗内 mtime 变动）时暂缓手术。
7. **先判状态**：轮替前先按 §0.2 判定任务状态与对象类别；状态未闭口不得整任务归档，批次史轮替除外。
8. **索引同步**：每次归档或轮替，同步更新源目录 `index.md` 与 `长线任务归档总登记表/index.md`；索引与磁盘目录双向一致方可提交。
9. **不重复收录**：同一内容只能出现在一个归档件；发现双源时先删副本再收口，不得两处并存。
10. **无批准不迁出**：阈值触发只提议；ykla 未批准前，原文不得移动、删除或改写。

## 七、角色与复审

| 角色 | 职责 | 不得做的事 |
| ---- | ---- | ---------- |
| ykla | 批准整任务归档、重开、阈值调整；签收残余风险 | 以口头意见替代 changelog 记录 |
| 主代理 | 判定状态、执行轮替、同步索引、记 changelog | 自批归档；未批准先迁出 |
| 复核子代理 | 只读核对逐字保真、索引双向一致、指针可解析 | 以回报替代磁盘回读 |

- **复审周期**：每季度或每完成一个归档批次，以先到者为准；不创建定时任务。
- **复审内容**：阈值是否仍触发、归档件是否仍被引用、状态是否失真、是否有双源、旧批次是否需补归档。
- **复审记录**：写入 `01-项目管理/02-工程决策与技术债/工程实践复审台账.md`；结论为“通过／有条件通过／不通过／已回流”。
- **失效条件**：任务类型消失、归档目录重构、机读台账改为数据库主存储、或连续两季无轮替需求，须修订本规则并开新 ADR。
