# 44.2 BSD 文档作为教育载体：man pages、手册与论文——BSD man pages 的教育哲学含义、CSRG 发布的各类技术手册作为知识形式主义、4.2BSD Manual 与 4.4BSD Manual 的文档史、BSD 文档的修道度人维度

## 44.2.1 BSD man pages 的教育哲学含义

  **要点**：BSD man pages 的教育哲学含义为：man pages 是 “代码即文档” 传统的具体化，每个命令、系统调用、库函数均有对应 man page，man pages 既是技术参考也是教学文本，其简洁性与精确性体现 BSD 工程哲学，与 GNU info 系统的扩展性形成对比

  | man page 分类 | 含义 | 示例 |
| ----------- | -- | -- |
| **命令 (1)** | 用户命令 | **ls(1)**、**vi(1)**、**csh(1)** |
| **命令 (2)** | 系统调用 | **open(2)**、**read(2)**、**fork(2)** |
| **命令 (3)** | 库函数 | **printf(3)**、**malloc(3)** |
| **命令 (4)** | 设备与特殊文件 | **tty(4)**、**null(4)** |
| **命令 (5)** | 文件格式 | **fstab(5)**、**passwd(5)** |
| **命令 (6)** | 游戏 | **trek(6)**、**rogue(6)** |
| **命令 (7)** | 杂项 | **ascii(7)**、**environ(7)** |
| **命令 (8)** | 系统管理与维护 | **mount(8)**、**fsck(8)** |

**史料**：4.2BSD man pages 原文、CSRG 关于 man pages 编写规范的文档、Unix Programming Manual（Kernighan & Pike 1984） ［B］
  
**史观**：第 2 条形式主义——man pages 的 “命令 (N)” 分类形式逻辑（命令分类）吞并了文档的实质组织，形式分类成为 BSD 文档的标准
  
**辨析**：man pages 的 “教育性” 需核对，部分 man pages 偏技术参考，教学性有限，需区分 “参考文档” 与 “教学文档”
  
**文献**：Kernighan, B. & Pike, R. (1984) “The Unix Programming Environment”；4.2BSD man pages；McKusick, K. (1999) “Twenty Years of Berkeley Unix” ［B］

## 44.2.2 CSRG 技术手册作为知识形式主义

  **要点**：CSRG 发布的技术手册包括 4.2BSD Manual（**1983**）、4.3BSD Manual（**1986**）、4.4BSD Manual（**1994**）、BSD System Manager‘s Manual、BSD User’s Reference Manual、BSD Programmer's Manual，手册作为知识形式主义将 BSD 系统分类为可索引、可检索的知识体系

  | 手册名称 | 出版年 | 分类 |
| ------ | ---- | -- |
| 4.2BSD Manual | **1983** | 系统总手册 |
| 4.3BSD Manual | **1986** | 系统总手册 |
| 4.4BSD Manual | **1994** | 系统总手册 |
| BSD System Manager's Manual | — | 系统管理（Manager） |
| BSD User's Reference Manual | — | 用户参考（User） |
| BSD Programmer's Manual | — | 程序员参考（Programmer） |

**史料**：4.2/4.3/4.4BSD Manual 原文、CSRG 手册编写记录、BSD 手册分类规范 ［A］
  
**史观**：第 2 条形式主义——手册的分类形式逻辑（User/Programmer/Manager）吞并了 BSD 系统的实质组织，形式分类塑造 BSD 知识体系
  
**辨析**：手册的 “形式主义” 需核对，分类有其工程实用性，需区分 “形式逻辑” 与 “实用分类”
  
**文献**：4.2/4.3/4.4BSD Manual；McKusick, K. (1999) “Twenty Years of Berkeley Unix”；CSRG 手册编写规范 ［A］

## 44.2.3 4.2BSD Manual 与 4.4BSD Manual 的文档史

  **要点**：4.2BSD Manual（**1983**）由 Joy、Fabry、Leffler 等编写，约 1000 页，奠定 BSD 文档传统；4.4BSD Manual（**1994**）由 McKusick、Karels、Bostic 等编写，约 2000 页，是 CSRG 最后一份完整文档，两份手册的对比显示 BSD 系统 11 年的演化轨迹

  | 维度 | 4.2BSD Manual | 4.4BSD Manual |
| -- | ----------- | ----------- |
| 出版年 | **1983** | **1994** |
| 主要编写者 | Joy、Fabry、Leffler | McKusick、Karels、Bostic |
| 页数 | 约 1000 页 | 约 2000 页 |
| 历史地位 | 奠定 BSD 文档传统 | CSRG 最后一份完整文档 |
| 演化跨度 | 11 年 BSD 系统演化轨迹 | 同左 |

**史料**：4.2BSD Manual（**1983**）、4.4BSD Manual（**1994**）、CSRG 文档编写记录［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档与公告〕
  
**史观**：第 9 条经验优先——手册演化是 BSD 系统演化的事后文档化，实践先于文档
  
**辨析**：手册页数的 “具体数字” 需核对，避免事后估算，需核对原始手册。经参考文献库核查：4.2BSD Manual（1983）与 4.4BSD Manual（1994）的出版年份与 Salus（1994，reference_id=810）所载 4.2BSD 1983 年发布、dexter（2017，reference_id=596）所载 4.4BSD-Lite2 1995 年时间线相符；但“约 1000 页”“约 2000 页”的具体页数两库无法验证，保留原考据
  
**文献**：4.2BSD Manual（1983）；4.4BSD Manual（1994）；McKusick, K. (1999) “Twenty Years of Berkeley Unix” ［B］

## 44.2.4 BSD 文档的修道度人维度

  **要点**：BSD 文档的修道度人维度为：文档编写是开发者自我修行（修道），文档阅读是后来者学习（度人），两者辩证统一，CSRG 成员通过编写 man pages 与手册实现自我修行，同时通过文档发布帮助后来者学习 BSD

  > 代码即文档，文档即修行；写文档的人度不了别人，但写文档这件事本身就是在修行。

  | 维度 | 修道（自我修行） | 度人（后来者学习） |
| -- | -------------- | ---------------- |
| 主体 | CSRG 成员（文档编写者） | 后来者（文档阅读者） |
| 形式 | 编写 man pages 与手册 | 阅读 man pages 与手册 |
| 关系 | 辩证统一 | 同左 |

**史料**：McKusick 关于文档编写的访谈、CSRG 文档编写规范、BSD 文档用户反馈 ［B］
  
**史观**：第 14 章边缘者——文档编写的 “度人” 维度常被代码开发的 “修道” 维度掩盖，需恢复文档编写的度人价值
  
**辨析**：修道度人的 “哲学深度” 需谨慎，CSRG 成员未必有系统的修道度人思考，需区分 “实践哲学” 与 “理论哲学”
  
**文献**：McKusick, K. (1999) “Twenty Years of Berkeley Unix”；CSRG 文档档案；Unix Programming Manual ［B］

**要点**：

- Callahan 自述 BSD 课程扩张的困境是一个循环：需要更多 BSD 从业者才有人进入教育领域开课，而开设课程才能培养更多从业者；他给出的破局路径包括 BSD 人士主动进高校承担客座讲授、由企业或基金会资助高校课程——并举 Red Hat 向大学捐资开设开源课程、Nexenta 在多所大学设立文件系统研发培养职位的先例——以及以学生社团（如 RPIsec 令 RPI 以计算机安全闻名）等自下而上方式建立 BSD 的校园存在感。（BSD Now EP114，[1215.24-1515.36]，L1）
- Callahan 详述其客座文档实验课的设计：学生从 FreeBSD 手册、网页与 man 页或 OpenBSD FAQ 中任选材料，目标不是学习内容本身而是找出错别字或语法问题，由此顺带学会 SVN/CVS 基本操作、生成 diff 补丁并经 FreeBSD Bugzilla 等正规渠道提交；他认为该设计一举三得——入门非 Git 系版本控制、练习阅读文档这一独立技能、并首次体会成为 BSD 社区一分子的含义。（BSD Now EP114，[2014.16-2098.38]，L1）
- 主持人转述 Netflix 公布的单台设备出流量曲线：一台 FreeBSD 流媒体设备从上线爬坡至约 65 Gbps、快照后继续升至 72-75 Gbps，配置为单路高端 Xeon E5 加双口 40GbE Chelsio T580 网卡与 NVMe/SSD 混合存储（部分 NVMe 读速达 1.7 GB/s），CPU 占用仅约 65%，TLS 加密流量占比 10%-15%；主持人强调此前的 52 Gbps 纪录依赖大量实验性调参，而本次成绩近乎出厂默认设置，凸显 FreeBSD 网络栈的默认扩展性。（BSD Now EP114，[3978.86-4103.00]，L2）
- 主持人转述 Salter 对备份工具的结构性论证：rsync 为找出文件变更必须完整读取两侧文件，而 ZFS 复制只需按块查询自某快照以来变更的块并传输增量，1500 万文件的数据集前者可能耗时数日、后者仅需数秒；并举 FreeBSD 集群将家目录 NFS 从加州迁往纽约时 rsync 反复运行仍需约 20 小时锁服同步的实例，说明文件系统级快照复制在一致性瞬间与增量效率上对文件级同步的优势。（BSD Now EP114，[524.38-616.70]，L2）
- 主持人自 2009 年起在 University of Maine at Augusta 以兼职教师身份教授 UNIX 基础课程；课程源起于所在计算机信息系统系部署 Linux 机器时求助于其任职的 ISP；多年以 Linux 为主、以 Mark Sobel 的 A Practical Guide to Linux 为教材，属通用 UNIX 课程而非 Linux 专属课，全命令行授课并辅以 Apache 虚拟主机配置等系统管理内容。（BSDTalk EP208，[71.76-196.86]，L1）
- 课程长期在多系统间轮换以展示技能可迁移性，曾引入 Solaris、Darwin 与 Silicon Graphics IRIS 工作站；因院系要求压缩教材成本，改用免费的在线 Linux 命令行书，换书导致课程格式全面重排；同期更新 Linux 虚拟机时遭遇 init 体系由传统 init 经 upstart 到 systemd 的更替与包管理工具的分化，最终促使 2011 年把课程重点转为以 BSD 为主、Linux 为辅。（BSDTalk EP208，[190.18-327.54]，L1）
- 选择 OpenBSD 作为主教学平台的理由包括：安装镜像极小，对比 Debian、Fedora 镜像之庞大，三十名学生同时下载不致拖慢课堂；提供完整 UNIX 用户态与编译器栈，X 环境简明；安装器易用；系统行为长期稳定，教学示例不易失效。（BSDTalk EP208，[368.36-486.88]，L1）
- 具体教学法：每节课要求学生重新下载全新虚拟机镜像，以保证全体学生从同一已知良好基准出发，防止学生在 U 盘镜像上自行改动导致环境漂移；借 TWM 极简窗口管理器演示应用程序与窗口管理器的区分、手动窗口管理乃至 X 窗口系统的网络本质；OpenBSD 安装后的 Charlie Root 欢迎邮件、afterboot 手册页与 help 命令教程为学生提供了顺畅的入门引导。（BSDTalk EP208，[402.62-533.24]，L1）
- 与 Linux 对照的主要摩擦点：BSD 的 init 脚本系统长期未变、易于掌握，而 Linux 的快速变迁令教学者产生过时感；网络配置上 OpenBSD 只需在 hostname.if 文件写入 dhcp 即可，而 Linux 的动态设备检测使网卡命名不一致，导致同班学生网络配置时灵时不灵；受访者理解 Linux 的动态化源自 USB 与笔记本时代的设备模型，而 UNIX 传统服务器常年稳定运行的模型更契合 OpenBSD 的静态配置方式。（BSDTalk EP208，[539.48-707.42]，L1）
- 学期以 BSD 为主授课未收到学生的重大抱怨；受访者的教学立场是可迁移性与灵活性——Apache 配置文件位置在 Solaris、Red Hat 与 FreeBSD 上各不相同，关键在于学生会查文档、理解管道组合工具、会读手册页并掌握 sed、awk 等基本原理；学期末把学生分组抛到未曾接触的陌生系统上完成任务，以验证技能的可迁移性。（BSDTalk EP208，[327.54-846.18]，L1）
- 受访者的核心观察是 UNIX 基本原理三十年未变：1970 年代 AT&T System V 老书的目录至今仍然适用；系统不发生脚下变动本身就是教学价值；计划来年夏季重开课程，开发更多 BSD 专属教学资源，甚至自行撰写 Teaching UNIX with BSD 一书。（BSDTalk EP208，[849.62-894.58]，L1）
- mandoc 项目起于约六年前其原作者不满 groff 生成 HTML 手册的输出质量而另起格式化器，项目很快进入 OpenBSD 源码树，至 2010 年前后完成全树手册的构建切换；如今 OpenBSD 与 NetBSD 已采用其替代 groff，FreeBSD 与 DragonFly 正在准备切换并已完成大量筹备工作。　[存疑脚注] 原作者姓名转写音为 Christoph Johnson，据 mandoc 项目通行记载应为 Kristaps Dzonsons（BSDTalk EP243，[84.14-165.10]，L1）
- Schwarze 口述手册页格式语言谱系：Saltzer 于 1964 年实现 runoff 工具（后更名 roff），其语法已有 50 年历史且建基于五十年代末六十年代初 CTSS 的文档传统；Ritchie 与 Thompson 在贝尔实验室以 PDP-7 汇编重写 roff 并立即用于排版第一版 AT&T UNIX 手册；research Unix 演进到第 4 版时出现第一代高级宏，第 7 版 Unix 于七十年代末定型今日的 man 语言；约 1990 年伯克利 CSRG 发明 mdoc，首次支持语义标记并沿用至今。　[存疑脚注] Jerry Saltzer 之名转写音为 Soltzer，据 MIT 通行记载校正（BSDTalk EP243，[199.42-296.74]，L1）
- 语义标记的价值有三层：书写时标注语义角色（作者名、标题、函数名）比记忆物理修饰更直观；同一标记可按需要派生多种输出格式；最关键的是支撑精确检索——以 apropos 按语义字段查询即可列出所有使用 USER 环境变量的工具手册，而物理标记只能得到粗糙的模糊匹配，预格式化手册甚至令 grep 与 apropos 完全失效。（BSDTalk EP243，[325.58-421.54]，L1）
- mandoc 的工程负担源于 man 语言原是建于 groff 之上的宏层，凡 groff 具备的特性迟早会有人用进手册，故为覆盖真实世界文本必须实现完整的 roff 数值处理与条件指令；与此同时新功能持续推进：历时三年开发的增强检索在近期冲刺优化，计划吸收 preconv 以透明处理 UTF-8 的日文、俄文手册，内置的 mdoc 到 man 转换器则让可移植项目能为 Solaris 等二十年间始终没有 mdoc 实现的系统自动分发 man 版本。（BSDTalk EP243，[525.04-756.27]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：BSD 课程与研究的存续并不系于技术优劣，而系于具体的人与偶然条件：访谈双方都亲历 BSD 课程因授课教师离任而整体回退为 Red Hat 教材的案例；RPI 在 1990 年代曾浸染浓厚的 BSD 传统，随着那批懂行者相继离开，继任者失去专门知识便默认转向 Linux——教学内容随个人际遇与经费流向漂移，教育史上只有具体事件与偶然条件，无所谓进步的必然规律。（BSD Now EP114，[1549.20-1602.78]，L1）
- 总纲13 法律与道德是利益分配：许可证选择在争论中显形为利益分配而非纯粹法理：Fink 承认 HP 为让合作伙伴的法律部门签核项目而被迫采用 Apache 2.0，主持人的回应是宽松许可的全部意义正在于替企业规避法律风险，并举 Intel 将网卡与显卡驱动以 GPL/BSD 双许可发布、使 BSD 项目得以持续使用其代码的实例——法律文本的每一次取舍都在为某一方再分配代码使用权与商业化自由，各方以生态利益为真实筹码展开博弈。（BSD Now EP114，[843.28-915.66]，L2）
- 总纲22 知识注定过时：同一时期内两类知识呈现截然不同的时间尺度：Linux 的 init 与包管理体系数年之内历经更替而使教学内容迅速过时，而 UNIX 基础原理三十年保持稳定，说明系统的形式外壳与底层惯例的寿命并不相同。（BSDTalk EP208，[284.58-872.82]，L1）
- 总纲9 经验优先：课程设计的每个决定都来自课堂操作中的实际摩擦——镜像漂移、网卡命名混乱、下载拥堵——而非平台优劣的理论比较，体现以教学现场经验校准技术选择的取向。（BSDTalk EP208，[402.62-663.68]，L1）
- 总纲17 证明世界先于解释和改造世界：课程把会查文档、在陌生系统上完成实际任务视为能力成立的证明，而非预先讲授完备理论，教学评价以可操作的验证为归宿。（BSDTalk EP208，[811.06-846.18]，L1）
- 总纲3 不存在进步，只有权力再分配：文档格式语言的历史并非线性进步史：五十年来许多人试图发明优于 mdoc 的语言而大多失败，重型替代方案屡屡被证明难以为继，最终承担手册格式化的反倒是尊重既有语义传统的轻量实现；groff 到 mandoc 的更替是格式化实现权与维护权的转移，而非语言本身的淘汰更迭。（BSDTalk EP243，[468.58-524.04]，L1）
- 总纲9 经验优先：mandoc 的功能取舍由真实手册语料驱动而非语言理论：只要现实中的手册用了某个 groff 特性，格式化器就必须处理它，哪怕该特性与手册无关；这种以既有文本经验为准绳、而非按理想模型裁剪输入的工程立场，是 BSD 文档工具数十年延续的底层方法。（BSDTalk EP243，[617.94-684.34]，L1）

**辨析**：

- 主持人对 Fink 论证的反驳值得辨析：其一，Fink 以 Apache 许可证项目普遍设有技术委员会、工作组与董事会而 copyleft 项目无需此类结构为由贬低宽松许可，主持人指出这混淆了项目规模与许可证类型——大型项目无论何种许可证都需要治理，小型宽松许可项目亦大量存在；其二，主持人以从未有人因 BSD 许可证被诉、而 GPL 合规之难长存 tendrils 作对比论证，并援引 Kirk McKusick 衡量开源项目强度应视其能经受多少次领导层更迭的说法（771.56-779.28），把许可证之争进一步还原为治理与利益之争——但前一断言本身未经量化，须存疑处理。　[存疑脚注] “从未有人因 BSD 许可证被诉”为主持人单一来源修辞性断言，未见统计支撑；Fink 观点仅经 LWN 转述，未回核原文，证据强度不足。（BSD Now EP114，[722.72-904.04]，L4）
- UNIX 基础三十年未变为修辞性概括，工具选项与手册细节仍在演变；Teaching UNIX with BSD 出书计划为口头意向，有无成书须另行核实；转写讹误：set 应为 sed、gooey 应为 GUI、pop and yum 疑为 Red Hat 包管理工具链之误记，引用前须校正。　[存疑脚注] 三十年未变与老书目录适用的说法系当事人印象式表述，未经逐项核对；本期为主持人独白，无对话者交叉质证。（BSDTalk EP208，[829.94-894.58]，L4）
- Schwarze 转述其与 Eric Raymond 交谈、Raymond 又与 Richard Stallman 交谈的结果，称两人同意弃用 GNU info 并以其他方案替代，而 Stallman 与 Raymond 属意的 AsciiDoc/DocBook 路线被 Schwarze 评为工具链沉重、未必更易用；此说经过两级转述，RMS 的真实立场须以 FSF 原始文献核证，且许多替代尝试皆已失败的判断亦属其个人评断。　[存疑脚注] GNU info 弃用共识系经 Raymond 转述的二手信息，未经 Stallman 本人文本证实（BSDTalk EP243，[447.54-518.64]，L2）
