## 57.4.1 Allman 1979 年 delivermail 到 Sendmail 的演进

  **要点**：Eric Allman 1979 年在伯克利 INGRES 数据库项目中开发 delivermail（ARPANET 邮件传输代理），随 4.0BSD/4.1BSD 分发，delivermail 最初使用硬编码路由表通过 FTP 邮件协议转发；1981-1982 年 Allman 在 4.1cBSD 开发期间改写为 Sendmail 以支持 SMTP（RFC 821 1982）与 UUCP 等多协议路由，引入地址重写规则；Sendmail 1983 年 8 月随 4.2BSD 作为默认邮件传输代理（MTA）发布，Allman 的 delivermail 到 Sendmail 演进反映了互联网邮件协议从 ARPANET（FTP-based）到 SMTP 的转型

  | delivermail/Sendmail 演进时间线 | 时间 | 事件 |
| ----------------------------- | -- | -- |
| delivermail 开发 | **1979 年** | Eric Allman 在伯克利 INGRES 项目中开发 |

## 57.4.2 Sendmail 4.2BSD 集成的历史意义

  **要点**：Sendmail 4.2BSD 集成（1983.8）的历史意义：（1）Sendmail 作为默认 MTA 集成入 BSD，使 BSD 系统开箱即用支持 SMTP 邮件；（2）Sendmail 的部署推动 SMTP 成为互联网邮件事实标准；（3）Sendmail 的开放配置（sendmail.cf）使管理员可定制邮件路由，但也带来配置复杂性；（4）Sendmail 与 BIND 一起使 BSD 成为互联网基础设施的核心

  | Sendmail 4.2BSD 集成历史意义 | 内容 |
| -------------------------- | -- |
| 集成时间 | **1983 年 8 月**（4.2BSD 发布） |
| 默认 MTA | 使 BSD 系统开箱即用支持 SMTP 邮件 |
| 推动 SMTP | Sendmail 的部署推动 SMTP 成为互联网邮件事实标准 |
| 配置开放 | sendmail.cf 使管理员可定制邮件路由，但也带来配置复杂性 |
| 基础设施核心 | Sendmail 与 BIND 一起使 BSD 成为互联网基础设施的核心 |

**史料**：Sendmail 4.2BSD 集成档案（1983.8）、Sendmail.cf 配置文件历史、Sendmail 推动 SMTP 标准化档案［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L1 代码/L3 官方文档〕
  
**史观**：第 9 条经验优先——Sendmail 的实践（BSD 集成）先于 SMTP 标准化，BSD 的 “开箱即用” 使 Sendmail 成为互联网邮件事实标准
  
**辨析**：Sendmail 4.2BSD 集成时间确认为 1983 年 8 月（4.2BSD 1983.8 发布，Sendmail 作为默认 MTA 集成，与第 02 卷 33.1 的 4.2BSD 革命叙事一致）；sendmail.cf 的配置复杂性——Sendmail 使用 M4 宏预处理器生成 sendmail.cf 配置文件，M4 宏简化配置编写但生成的 sendmail.cf 仍为复杂的规则集，管理员须理解地址重写规则（rewriting rules）方能维护，此复杂性是后来 Postfix（1998）以配置简洁性取代 Sendmail 的市场动因；Sendmail 对 SMTP 标准化的推动——Sendmail 作为 4.2BSD 默认 MTA 广泛部署，使 SMTP（RFC 821 1982）成为互联网邮件事实标准，IETF 后续邮件相关 RFC（如 RFC 822 邮件格式、RFC 1869 SMTP 扩展）均以 Sendmail 实现为参考
