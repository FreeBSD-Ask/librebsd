## 57.3.1 BIND 的伯克利起源与四位研究生

  **要点**：BIND（Berkeley Internet Name Domain）由伯克利 CSRG 的四名研究生开发：Douglas Terry、Mark Painter、David Riggle、Songnian Zhou，1984 年基于 Paul Mockapetris（USC ISI）的 DNS 协议设计（RFC 882/883 1983）实现，BIND 作为 4.3BSD 的组成部分发布，是 DNS 协议的首个参考实现，BIND 的伯克利起源使其与 BSD 深度绑定

| ----------------- | -- | -- |
| 1 | Douglas B. Terry | 伯克利 CSRG 研究生 |
| 2 | Mark Painter | 伯克利 CSRG 研究生 |
| 3 | David W. Riggle | 伯克利 CSRG 研究生 |
| 4 | Songnian Zhou（周松年） | 伯克利 CSRG 研究生 |

  | BIND 关键要素 | 内容 |
| ----------- | -- |
| 开发时间 | **1984 年** |
| 基于 | Paul Mockapetris（USC ISI）的 DNS 协议设计（RFC 882/883 **1983**） |

| 历史地位 | DNS 协议的首个参考实现 |

**史料**：BIND 1984 开发档案、四位研究生（Terry/Painter/Riggle/Zhou）的论文与项目记录、Mockapetris DNS RFC 882/883（1983）、4.3BSD BIND 集成记录 ［B］

## 57.3.2 DNS 协议 1983 年 RFC 882/883 定义

  **要点**：DNS（Domain Name System）协议由 Paul Mockapetris（USC ISI）设计，1983 年 11 月发布 RFC 882（“Domain Names: Concepts and Facilities”）与 RFC 883（“Domain Names: Implementation and Specification”），DNS 替代 ARPANET 早期的 HOSTS.TXT 集中文件，采用分层分布式命名系统，DNS 的根域、顶级域（TLD）、二级域结构奠定了互联网命名体系

  | RFC 882/883 要素 | 内容 |
| -------------- | -- |
| RFC 882 | “Domain Names: Concepts and Facilities” |
| RFC 883 | “Domain Names: Implementation and Specification” |
| 发布时间 | **1983 年 11 月** |
| 作者 | Paul Mockapetris（USC ISI） |
| 替代对象 | ARPANET 早期 HOSTS.TXT 集中文件 |
| 设计 | 分层分布式命名系统（根域、顶级域 TLD、二级域） |

  | DNS 与 HOSTS.TXT 对比 | HOSTS.TXT | DNS |
| ------------------- | ------- |---|
| 维护方式 | 集中式（SRI NIC 维护） | 分层分布式 |
| 问题 | 文件过大、更新延迟、单点故障 | 分层解决瓶颈 |

**史料**：RFC 882（Mockapetris, 1983.11）、RFC 883（Mockapetris, 1983.11）、ARPANET HOSTS.TXT 档案、DNS 根域/TLD 结构档案［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档与公告〕
  
**史观**：第 9 条经验优先与第 4 条分离与聚合——DNS 的分层分布式设计（分离的根/TLD/二级域）取代 HOSTS.TXT 的集中式（聚合），分离与聚合的辩证关系塑造互联网命名体系
  
**辨析**：RFC 882/883 的发布时间确认为 1983 年 11 月；Mockapetris 的机构确认为 USC ISI（University of Southern California，Information Sciences Institute）；ARPANET HOSTS.TXT 为 DNS 前的集中式主机名-IP 地址映射文件，由 SRI 的 Network Information Center（NIC）维护，随 ARPANET 节点增长 HOSTS.TXT 的集中维护成为瓶颈（文件过大、更新延迟、单点故障），DNS 的分层分布式设计正是为解决此问题而提出

## 57.3.4 BIND 的全球统治与安全问题

  **要点**：BIND 的全球统治：1990 年代 BIND 运行全球约 90% 的 DNS 服务器，BIND 的统治地位带来安全责任，BIND 安全漏洞史包括：（1）BIND 4.9.x 1990 年代后期多个远程漏洞；（2）BIND 8.2.x 1999 年 NXT 记录等多个漏洞（CERT Advisory CA-1999-14）；（3）BIND 9 的多次 CVE；BIND 的安全问题推动替代品（PowerDNS、Unbound、NSD）的发展，但 BIND 仍是主流 DNS 服务器之一

| BIND 9 | 多次 | 9.x | 多次 CVE |
