# 58.9 重要贡献者与边缘者：互联网基础设施的沉默守护者——BIND 维护者、Sendmail 安全补丁作者、TCP/IP 协议栈的无名优化者等被忽视的互联网基础设施贡献者

## 58.9.1 BIND 维护者与安全响应团队
  - 要点：BIND 维护者与安全响应团队包括：（1）Douglas Terry、Mark Painter、David Riggle、Songnian Zhou 四位伯克利研究生为 BIND 创始者（1984）；（2）DEC 的 Paul Vixie 约 1988 年起接管 BIND 4.8/4.9 维护，后成立 Vixie Enterprises；（3）Internet Software Consortium（ISC，1994 年由 Rick Adams、Paul Vixie 与 Carl Malamud 三人共同创立，后更名为 Internet Systems Consortium）维护 BIND 8/9；（4）ISC 的安全响应团队处理 BIND 安全漏洞；Vixie 作为 BIND 长期维护者是互联网基础设施的关键贡献者

## 58.9.2 Sendmail 安全补丁作者

## 58.9.3 TCP/IP 协议栈的无名优化者
  - 要点：TCP/IP 协议栈的无名优化者包括：（1）BBN 的 Jack Haverty 等实现原始 TCP/IP 代码；（2）CSRG 的 Joy 与 Leffler 优化 4.2BSD TCP/IP；（3）4.3BSD 的网络代码优化贡献者（如 Sam Leffler 的网络驱动优化）；（4）Internet Initiative Japan（IIJ）的 Suzuki 等日本贡献者优化 BSD TCP/IP；（5）这些无名优化者的贡献多隐藏在源码注释与提交记录中

  | TCP/IP 协议栈的无名优化者 | 机构 | 贡献 |
  | --- | --- | --- |
  | Jack Haverty 等 | BBN | 实现原始 TCP/IP 代码 |

## 58.9.4 边缘贡献者的史料辨析
  - 要点：互联网基础设施边缘贡献者的史料辨析：（1）BSD 源码贡献者记录（CHANGELOG、SCCS 日志）是辨识边缘贡献者的主要史料，但 CSRG 时期（1978-1992）记录不完整，4.4BSD-Lite 之后的 CVS/SVN/Git 记录较完整；（2）邮件列表存档（如 IETF 邮件列表、CSRG 内部邮件）可补充源码记录，但存档可能存在截取、邮件丢失、事后编辑，须通过多个独立存档交叉验证；（3）事后回忆（如 Allman、Vixie 的回忆）存在记忆偏差与自利偏差的典型风险，须与代码级 commit 交叉验证后方可采信；（4）史料辨析的 0 信任原则——对所有来源（含一手资料）进行考据验证，不得因来源“一手”即直接采信（参见 规则/考据规则.md）

  | 边缘贡献者史料类型 | 完整性 | 风险 |
  | --- | --- | --- |
  | BSD 源码 CHANGELOG/SCCS 日志（CSRG 时期 1978-1992） | 记录不完整 | — |
  | BSD 源码 CVS/SVN/Git 记录（4.4BSD-Lite 之后） | 较完整 | — |
  | 邮件列表存档（IETF、CSRG 内部） | 可补充源码记录 | 截取、邮件丢失、事后编辑 |
  | 事后回忆（Allman、Vixie 等） | — | 记忆偏差与自利偏差 |

  | 史料辨析方法 | 内容 |
  | --- | --- |
  | 多个独立存档交叉验证 | 邮件列表存档须通过多个独立存档（marc.info、ietf.org 邮件列表存档、邮件列表镜像）交叉验证 |
  | 与代码级 commit 交叉验证 | 事后回忆须与代码级 commit 交叉验证后方可采信 |
  | 0 信任原则 | 对所有来源（含一手资料）进行考据验证，不得因来源“一手”即直接采信（参见 `规则/考据规则.md`） |

  - 史料：BSD 源码 CHANGELOG/SCCS 日志、IETF/CSRG 邮件列表存档、Allman/Vixie 等的事后回忆 ［A］
  - 史观：第 9 条经验优先与第 14 章边缘者——史料辨析的实践（多源交叉）先于形式化的史料理论，边缘贡献者的发掘须基于实践
  - 辨析：源码贡献者记录的完整性——BSD 源码 CHANGELOG 与 SCCS 日志为辨识边缘贡献者的主要史料，但早期（CSRG 时期 1978-1992）记录不完整，4.4BSD-Lite 之后的 CVS/SVN/Git 记录较完整；邮件列表存档的截取情况——IETF 邮件列表与 CSRG 内部邮件存档可能存在截取、邮件丢失、事后编辑，须通过多个独立存档（如 marc.info、ietf.org 邮件列表存档、邮件列表镜像）交叉验证；事后回忆的记忆偏差——Allman、Vixie 等的事后回忆存在记忆偏差与自利偏差的典型风险，须与代码级 commit 交叉验证后方可采信；0 信任原则的适用性——对所有来源（含一手资料）进行考据验证，不得因来源“一手”即直接采信（参见 规则/考据规则.md）
