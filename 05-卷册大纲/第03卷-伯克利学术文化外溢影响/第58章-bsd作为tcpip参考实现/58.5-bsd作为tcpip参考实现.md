# 58.5 BSD 作为 TCP/IP 参考实现——4.2BSD 1983 年首次集成 TCP/IP 协议栈，BSD 网络栈成为互联网协议的事实标准参考实现，Bill Joy 与 Sam Leffler 的 VAX TCP/IP 性能优化，BSD 套接字 API 的跨平台效应

## 58.5.1 4.2BSD 1983 年 TCP/IP 协议栈集成

  **要点**：4.2BSD 1983 年 8 月首次集成完整 TCP/IP 协议栈，TCP/IP 实现最初基于 BBN 的 Rob Gurwitz 于 1981-1982 年开发的代码（集成入 4.1a/4.1cBSD 测试版本），经 CSRG（Joy、Leffler 等）重写优化后性能大幅提升，4.2BSD 的 TCP/IP 集成使 BSD 系统开箱即用支持互联网协议，4.2BSD 发布时间（1983.8）在 ARPANET TCP/IP 切换（1983.1.1）之后约 7 个月，时间上的承接强化了 BSD 与互联网的绑定；socket API 主要由 Sam Leffler 设计实现，成为跨平台网络编程标准接口

  | 4.2BSD TCP/IP 集成关键节点 | 时间 | 事件 |
| ------------------------ | -- | -- |
| BBN TCP/IP 原始代码 | **1981-1982 年** | Rob Gurwitz 开发，集成入 4.1a/4.1cBSD 测试版本 |
| CSRG 重写优化 | 1982-1983 年 | Joy、Leffler 等重写优化后性能大幅提升 |
| 4.2BSD 发布 | **1983 年 8 月** | 首次集成完整 TCP/IP 协议栈 |
| ARPANET TCP/IP 切换 | **1983 年 1 月 1 日** | 4.2BSD 发布在切换之后约 7 个月 |

  | BBN 与 CSRG 的 TCP/IP 代码关系 | 内容 |
| ---------------------------- | -- |
| BBN 原始版本 | Rob Gurwitz 于 1981-1982 年开发 |
| CSRG 重写 | Joy、Leffler 等重写优化 |
| 性能对比 | CSRG 版本性能优于 BBN 原始版本且代码更简洁 |
| 替代时间 | 4.2BSD（1983.8）以 UCB TCP/IP 替代 BBN TCP/IP |
| socket API | 主要由 Sam Leffler 设计实现 |

**史观**：第 9 条经验优先与第 5 条偶然性——4.2BSD 的 TCP/IP 实践（1983.8）紧随 ARPANET 切换（1983.1.1），偶然的时间巧合强化 BSD 与互联网的绑定，实践先于 RFC 标准化的形式理论
  
**辨析**：4.2BSD 发布时间确认为 1983 年 8 月（多源一致，4.2BSD 引入完整 TCP/IP 协议栈、FFS 文件系统、套接字 API）；BBN 与 CSRG 的 TCP/IP 代码关系——根据 McKusick “Twenty Years of Berkeley Unix” 权威记载：BBN 的 Rob Gurwitz 发布 TCP/IP 早期实现后，Joy 集成入系统并调优性能，Joy 与 Leffler 发现新系统需支持多于 DARPA 标准网络协议，故重新设计软件内部结构、精炼接口以同时支持多种网络协议，此系统即 4.1a（**1982 年 4 月** 首次分发供本地使用，非原记“1981-1982”），4.1a 从未预期广泛流传但盗版副本四处扩散；4.1b（1982 年 6 月）加入 McKusick 的 FFS；4.1c（**1983 年 4 月**）为 4.2BSD 完成前的过渡版本；4.2BSD（1983.8）以 UCB TCP/IP 替代 BBN TCP/IP（与 23.1.2、23.10.2 一致）；**4.3BSD BBN 争议（关键事件）**：1985 年 6 月 Usenix 大会上 CSRG 宣布 4.3BSD 将于夏季发布，BBN 指出 4.2BSD 从未更新为 BBN 最终版网络代码，仍使用多年前交给 Berkeley 的“much-hacked initial prototype”，BBN 向 DARPA 投诉称“Berkeley 负责实现接口，BBN 负责实现协议”，要求 4.3BSD 替换为 BBN 实现；Mike Karels 评估 BBN 代码后决定将 BBN 代码中的优良思路合并入 Berkeley 代码库但保留 Berkeley 代码库（因 4.2BSD 广泛分发已获大量测试与改进），并提出在 4.3BSD 中同时包含两套实现让用户自选；DARPA 认为发布两套代码库会导致互操作问题，将两套代码交由 Ballistics Research Laboratory 的 Mike Muuse 作为独立第三方评估，一个月后评估报告结论：**Berkeley 代码效率更高但 BBN 代码处理拥塞更好**，决胜因素为 Berkeley 代码完美通过所有测试而 BBN 代码在某些压力条件下 panic，DARPA 最终决定 4.3BSD 沿用 Berkeley 代码库；ARPANET 1983.1.1 TCP/IP 切换经多源确认（此“Flag Day”标志现代互联网诞生）[考据脚注：4.1a 分发时间以 McKusick “Twenty Years of Berkeley Unix” 原文“first distributed in April 1982”为准，纠正原记“1981-1982 年”的不精确表述；4.2BSD 指导委员会由 DARPA 的 Duane Adams 组建，成员包括 UCB 的 Bob Fabry、Bill Joy、Sam Leffler，BBN 的 Alan Nemeth、Rob Gurwitz，Bell Labs 的 Dennis Ritchie，Stanford 的 Keith Lantz，CMU 的 Rick Rashid，MIT 的 Bert Halstead，ISI 的 Dan Lynch，DARPA 的 Duane Adams 与 Bob Baker，UCLA 的 Jerry Popek，1981 年 4 月至 1983 年 6 月间每半年开会一次]。经参考文献库核查：4.2BSD 1983 年发布经 Salus（1994，reference_id=810）所载“4.2BSD, September 1983—A major system revision, including networking”与 Spinellis（2018，reference_id=633）所载“4.2BSD (Sep 1983)”双重印证，与本节“1983 年 8 月发布”存在 8 月/9 月的月份微差（CSRG 内部完成于 8 月、正式发行说明署 9 月），已在辨析中注明

## 58.5.2 BSD 网络栈作为事实标准参考实现

  **要点**：BSD 网络栈成为互联网协议的事实标准参考实现：（1）4.2BSD 的 TCP/IP 实现被其他操作系统（如 SunOS、Ultrix、AIX）借鉴或移植；（2）BSD 的网络代码作为 RFC 标准的参考实现，IETF 协议设计常以 BSD 实现为基础；（3）BSD 网络栈的影响力持续至 1990 年代，Linux 早期 TCP/IP 实现（NET-2）借鉴 BSD 代码（含 BSD 版权声明）；（4）BSD 网络栈的统治地位反映 BSD 作为互联网基础设施的核心地位

  | BSD 网络代码跨平台扩散 | 操作系统 | 时间 | 关系 |
| -------------------- | ------ | -- | -- |
| SunOS | Sun Microsystems | **1983 年** | 直接基于 4.2BSD 衍生，网络代码源自 BSD |
| Ultrix | DEC | **1984 年** | 基于 4.2BSD 衍生以运行于 VAX 与 DEC 工作站 |
| AIX | IBM | **1986 年** | 早期网络实现借鉴 BSD 套接字 API 与 TCP/IP 栈 |
| Linux NET-2 | Linus Torvalds | 1990 年代 | 早期 TCP/IP 实现借鉴 BSD 代码（含 BSD 版权声明） |

  | BSD 作为 RFC 参考实现的案例 | RFC | 内容 |
| ------------------------- |---| -- |
| RFC 1122 | “Requirements for Internet Hosts”（**1989**） | 以 BSD TCP/IP 实现为参考 |
| BIND/Sendmail | 对应 RFC | BSD 实现成为事实参考 |

**史料**：SunOS/Ultrix/AIX 借鉴 BSD 网络代码档案、BSD 网络代码作为 RFC 参考实现记录、Linux NET-2 借鉴 BSD 代码档案 ［A］
  
**史观**：第 9 条经验优先与第 4 条分离与聚合——BSD 网络栈的实践先于 RFC 标准化，BSD 在协议实现上聚合多家操作系统，分离与聚合的辩证关系塑造互联网实现史
  
**辨析**：SunOS（Sun Microsystems 1983 发布）直接基于 4.2BSD 衍生，网络代码源自 BSD；Ultrix（DEC 1984 发布）基于 4.2BSD 衍生以运行于 VAX 与 DEC 工作站；AIX（IBM 1986 发布）的早期网络实现借鉴 BSD 套接字 API 与 TCP/IP 栈——多源一致确认 BSD 网络代码的跨平台扩散；BSD 作为 RFC 参考实现的案例——RFC 1122“Requirements for Internet Hosts”（1989）以 BSD TCP/IP 实现为参考，BIND/Sendmail 的 BSD 实现成为对应 RFC 的事实参考；Linux NET-2 借鉴 BSD 代码——Linux 早期 TCP/IP 实现（NET-2）包含 BSD 版权声明（多源一致，Linux 网络代码中保留 BSD 版权头文件），USL 诉讼后 Linux 社区逐步重写 BSD 衍生代码但 BSD 套接字 API 的接口设计延续至今
  
**文献**：SunOS/Ultrix/AIX 网络代码档案；RFC 系列中 BSD 参考；Linux NET-2 代码档案 ［A］

## 58.5.4 BSD 套接字 API 的跨平台效应

## 58.5.5 Van Jacobson（范·雅各布森） 拥塞控制与 4.3BSD-Tahoe（1988）

  **要点**：1986 年 10 月互联网首次拥塞崩溃——Lawrence Berkeley Laboratory（LBL）到 UC Berkeley（相距 400 码、两跳 IMP）的数据吞吐量从 32 Kbps 骤降至 40 bps（下降三个数量级），暴露 4.2BSD TCP/IP 在拥塞控制方面的缺陷；Van Jacobson（LBL）与 Michael J. Karels（UC Berkeley）针对此问题设计七个 TCP 算法：（i）往返时间方差估计、（ii）指数退避重传计时器、（iii）慢启动（slow-start，原名 soft-start，John Nagle 1987 年 3 月建议改名）、（iv）更激进的接收方确认策略、（v）拥塞时动态窗口调整（拥塞避免）、（vi）Phil Karn 的钳位重传退避算法（Karn 算法）、（vii）快速重传；Jacobson 与 Karels 在 1988 年 8 月 ACM SIGCOMM '88 研讨会（Stanford）发表 “Congestion Avoidance and Control” 论文（ACM SIGCOMM Computer Communication Review Vol. 18 No. 4 pp. 314-329；修订版 LBL 技术报告日期为 1988 年 11 月）；这些算法集成入 1988 年 6 月发布的 4.3BSD-Tahoe（首个将 BSD 内核分为机器相关与机器无关部分的版本，支持 CCI Power 6/32 “Tahoe” 平台），使 BSD TCP/IP 在拥塞网络中吞吐量提升数倍；快速恢复（fast recovery）算法后由 Jacobson 在 1990 年补充，集成入 4.3BSD-Reno（1990），形成 “Tahoe/Reno” 拥塞控制范式，成为后续三十年互联网 TCP 拥塞控制的基础；统计结论 [C-41] references 表总数 16,867 条，[C-42] 年份提取率 44.42%（7,493/16,867），1988 年 Van Jacobson 论文发表当年 107 条累计 1,255 条（16.75%），1988-1992 年拥塞控制研究期间累计 1,564 条（20.87%），CSRG 时期（1969-1995）累计 1,879 条占比 25.08%——拥塞控制算法集成入 BSD 推动了互联网网络研究文献的产出

## 58.5.6 Sun NFS 网络文件系统与 BSD 集成（RFC 1094）

  **要点**：NFS（Network File System）由 Sun Microsystems 于 1984 年设计，基于 Sun RPC（Remote Procedure Call，RFC 1057，1988 年 6 月）与 XDR（eXternal Data Representation，RFC 1014，1987 年 6 月）构建；NFS Version 2 协议于 1989 年 3 月以 RFC 1094 发布（作者 Sun Microsystems, Inc.，共 27 页），采用无状态服务器设计（服务器不维护客户端协议状态，崩溃恢复简单），提供透明远程文件访问；NFS 客户端与服务器代码集成入 4.3BSD-Tahoe（1988 年 6 月）至 4.3BSD-Reno（1990 年）期间的 BSD 版本 ［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］；NFS 的设计哲学（无状态、跨平台、RPC/XDR 抽象层）深刻影响后续分布式文件系统（如 AFS、SMB/CIFS）；NFSv3 以 RFC 1813 于 1995 年 6 月发布，NFSv4 以 RFC 3010/3530 于 2000/2003 年发布；NFS 成为 UNIX 世界跨平台文件共享的事实标准，Sun 将 NFS 开放实现的决策（与 BSD TCP/IP 类似）推动了其在异构环境中的普及

**要点**：

- McKusick 回忆早期 BSD 谱系：项目最初就是 Bill Joy 的一人工程，发布一些工具程序，首个发行物径称 BSD、后追认 1BSD，历经数个修订仍是工具集而非完整系统；约 1979 年的 3BSD 才是第一个带全部工具的完整系统；1979 年项目声望足以让 Bob Fabry 为系里争取到 DARPA 拨款，DARPA 想要一个所有承包商共用的操作系统基座，Joy 以 Unix 不绑定特定厂商说服对方，主要对手是只运行于 DEC 机器的 VMS——尽管当时 Unix 其实也只在 DEC 设备上运行，这一局面在 80 年代初随包括 Joy 赴创的 Sun 在内的工作站浪潮而迅速改变。（BSDTalk EP18，[77.45-211.79]，L1）
- 关于 TCP/IP 进入 BSD：ARPANET 原用 NCP 协议，仅运行于专用处理器且上限 256 台主机，扩张注定使其失效；伯克利的 DARPA 项目是让新协议 TCP/IP 落地，工作分工为 BBN 编写协议、伯克利定义并构建 API，今天尽人皆知的 socket 接口即伯克利的设计；BBN 交付的代码能打满一台 1 MIPS 处理器的 56 kbps，作为 ARPANET 速度尚称够用，但接上 3 M 以太网仍只有 56 kbps 吞吐，Joy 为使其跑满 3 M 乃至 10 M 以太网做了大量调优，期间与 BBN 产生分歧但最终解决；伯克利版的 API 与 TCP/IP 代码成为至少到 90 年代初几乎所有实现的共同基础。（BSDTalk EP18，[231.97-349.19]，L1）
- BSD 许可证诞生的完整链条：80 年代末以前获取 BSD 发行须先购 AT&T 源码许可证再另付一千美元，AT&T 许可费从两万至五万美元涨到 80 年代中期的二十五万至五十万，小公司无力承担，遂请伯克利单独发放明确属于伯克利的 TCP/IP 代码；伯克利律师想借此收取版税，团队以代码由政府资金开发、伯克利无权收费为由坚持开放；团队也评估过当时刚起步的 GNU 通用公共许可证，因其要求改动及关联代码全部开源——TCP/IP 运行于内核意味着交出整个内核——而否决；既不接受锁死权利的版权模式也不接受要求交出知识产权的 copyleft，他们自称 copy center，随取随拷、不要求回馈但予鼓励，许多厂商最终回赠大量代码，动因不是利他而是不堪每次新版发布后重新合并自有改动的负担；与大学律师反复争论后由律师定稿，即今日的 BSD 许可证，1988 年随 TCP/IP 代码及相关工具一并发布。（BSDTalk EP18，[371.17-547.37]，L1）
- 随后的代码释放与三团体分化：Keith Bostic 决心测试能解放多少代码，除内核外释放了全部有趣部分，CSRG 逐文件甄别内核归属并清除外来部分，尘埃落定时仅余约六个关键内核文件，1989 年发布后不久网络上的黑客便补齐了这六个文件，到 1990 年已出现可独立运行的 BSD；由此分出三支——坚持大学研究风格、保持系统小巧、追求多平台的 NetBSD，全力在 PC 架构上做到用户友好的 FreeBSD，两者目标分化迅速但都保持伯克利式许可证因而代码往来频繁；第三支是走向专有的 Berkeley Software Design Incorporated，整个 90 年代销售该系统，最终被 Wind River Systems 收购并将技术并入其产品。（BSDTalk EP18，[561.23-675.43]，L1）
- McKusick 当下的工作清单：近年持续增强文件系统——soft updates 以类似日志的机制让文件系统既快又稳且可恢复，snapshots 支持活动系统转储与后台文件系统检查；两年前出版 FreeBSD 操作系统设计与实现专著，其后围绕该书开发课件、授课并录像，即将开设一个读约八万行 FreeBSD 内核源码的代码阅读课；未来计划为 FFS 补上日志版本——对部分用户这只是采购清单上的勾选项——并完善 FreeBSD 中已有的 NFSv4 原型；他同时以教授身份厘清概念：UFS 是 Unix 文件系统的统称，FFS 是多数 BSD 系统采用的磁盘布局变体，此外还有日志式与内存式变体用于临时文件系统。（BSDTalk EP18，[683.77-834.79]，L1）
- 该解说把 BSD 概括为伯克利学生对 AT&T Unix 的修改与增强包，最初并非独立操作系统，后成长为独立分支；其最重要的历史贡献是网络：在 1970 年代末与 1980 年代初实现 TCP/IP 协议栈，代码清洁、可靠且开放供研究者研究，互联网扩展出研究实验室后 BSD 网络代码无处不在，早期商业 Unix 与 Windows 网络实现亦大量借鉴，由此获得“构建互联网的 Unix 系统”之称号。（YouTube EP3u8zKO8VTD0，[120.32-192.96]，L2）
- 1980 年代末 AT&T 开始对 Unix 主张知识产权，与加州大学陷入漫长复杂的法律纠纷；法律不确定性恰在 Linux 诞生之际拖慢了 BSD 的采用，Linux 因未直接衍生自 AT&T 代码而避开此问题，最终 BSD 以重写清除残余 AT&T 代码、纠纷了结，但 Linux 已积聚势头，BSD 生态遂分裂为各有目标、哲学与强项的数个重要分支。（YouTube EP3u8zKO8VTD0，[202.96-240.16]，L2）
- 三分支定位在解说中被总结为：FreeBSD 以性能、可扩展与整体性设计见长，内核与用户态一体开发，被 Netflix Open Connect 内容分发网络、Juniper、NetApp 等采用，并较早引入 ZFS；OpenBSD 以“默认安全”为纲，坚持代码审计与正确性优先，孕育 OpenSSH、PF、LibreSSL 等安全工具；NetBSD 以极致可移植性立身，代码库刻意分离机器无关与机器相关组件，故常最先支持冷门硬件。（YouTube EP3u8zKO8VTD0，[240.16-554.48]，L2）
- 在许可证哲学上，解说指出 BSD 宽松许可证允许商业专有产品在极少限制下使用与再分发，促成广泛采纳但不保证企业回馈改进；GPL 的 copyleft 模型则催生大规模共享开发生态。BSD 生态因而更小、更保守、更受核心开发者掌控，价值观上重视稳定性、清晰性与长期设计，与 Linux 的快速迭代形成对照。（YouTube EP3u8zKO8VTD0，[605.44-760.4]，L2）

**史观**：

- 总纲8 本体论上各方平等：McKusick 对竞争格局的判断建立在一个历史类比与一个生态学论证上：当年 PC 被讥为小、弱、难用，却因比大型机便宜十倍而被人找到用法，终至 PC 为王、大型机退居利基——开源相对专有软件正是同样的成本结构，IBM 弃自有操作系统拥抱 Linux、Oracle 访谈当周宣布收购 Sleepycat 并酝酿再购两家开源厂商皆是征兆，Linux 将取代 Windows 的主导地位而 Windows 不会消失；他又论证 Windows 的根本弱点在于它是横跨八成机器的单一一致目标，一个病毒即可通吃，计算生态需要遗传多样性，BSD 的价值恰在于既不是 Linux 也不是 Windows——小到病毒作者不感兴趣、久经岁月而足够防弹，装机数百万、缓慢增长，永不称王却是生态中不可替代的一极。（BSDTalk EP18，[847.61-1111.83]，L1）
- 总纲13 法律与道德是利益分配：McKusick 特别纠正了开源回馈的道德化叙事：厂商向伯克利回赠大量代码并非出于利他，而是每次新版发布都须重新合并自有改动的成本压力使然，把改动交回上游后改动随发行物一起维护反而省力——所谓社区美德话语之下运行的是赤裸裸的利益核算。（BSDTalk EP18，[509.95-525.89]，L1）
- 总纲23 一切历史写作都是基于哲学设定的历史小说：解说以“安静的坚持是其力量的一部分”“重视工艺而非炒作”为 BSD 写传，把三个分支塑造成不追逐潮流、沉默守护互联网的人格化角色，这类叙事本身即是一种带价值预设的历史建构，将技术格局的分化转写为品味与德性的对比，读者应将其视为叙事而非中立事实。（YouTube EP3u8zKO8VTD0，[757.76-790.48]，L2）

**辨析**：

- 转写专名失真须全面校核：BBN 被记作 Bermick and Nguyen，应为 Bolt Beranek and Newman；DSP FAST file system 应为 BSD Fast File System；TreeBSD 应为 FreeBSD；PreBSD 应为 FreeBSD；microstation 应为 workstations；Sleepy Cat 应为 Sleepycat。另有一处年代压缩风险：1989 年发布、黑客补齐六文件、1990 年出现独立 BSD 的叙述把 Net/1、Net/2 与 386BSD 的序列压成约数，精确版本学须对照发行物原件。　[存疑脚注] 年代压缩系当事人约数记忆，须以 Networking Release 1（1989）、Release 2（1991）与 386BSD（1992）的原始发行记录复核。（BSDTalk EP18，[267.67-349.19]，L1）
- 解说称早期 Windows 网络栈“借鉴了 BSD 的思想与代码”，又称 Linux 是受 Unix 启发的净室重实现，两者均为流传甚广的流行说法；前者与 Windows TCP/IP 栈实际授权移植来源的考据结论需核对，后者的“净室”定性亦系标签化表述，均不可直接采信。　[存疑脚注] Windows TCP/IP 栈来源与 Linux 净室定性均须回到一手文献核验；另该期转写为双轨时间戳交错的解说词，无出镜当事人，全部陈述仅可作研究线索。（YouTube EP3u8zKO8VTD0，[222.64-233.12]，L4）
