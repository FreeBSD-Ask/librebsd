# 58.5 BSD 作为 TCP/IP 参考实现——4.2BSD 1983 年首次集成 TCP/IP 协议栈，BSD 网络栈成为互联网协议的事实标准参考实现，Bill Joy 与 Sam Leffler 的 VAX TCP/IP 性能优化，BSD 套接字 API 的跨平台效应

## 57.5.1 4.2BSD 1983 年 TCP/IP 协议栈集成

  **要点**：4.2BSD 1983 年 8 月首次集成完整 TCP/IP 协议栈，TCP/IP 实现最初基于 BBN 的 Rob Gurwitz 于 1981-1982 年开发的代码（集成入 4.1a/4.1cBSD 测试版本），经 CSRG（Joy、Leffler 等）重写优化后性能大幅提升，4.2BSD 的 TCP/IP 集成使 BSD 系统开箱即用支持互联网协议，4.2BSD 发布时间（1983.8）在 ARPANET TCP/IP 切换（1983.1.1）之后约 7 个月，时间上的承接强化了 BSD 与互联网的绑定；socket API 主要由 Sam Leffler 设计实现，成为跨平台网络编程标准接口

## 57.5.2 BSD 网络栈作为事实标准参考实现

  **要点**：BSD 网络栈成为互联网协议的事实标准参考实现：（1）4.2BSD 的 TCP/IP 实现被其他操作系统（如 SunOS、Ultrix、AIX）借鉴或移植；（2）BSD 的网络代码作为 RFC 标准的参考实现，IETF 协议设计常以 BSD 实现为基础；（3）BSD 网络栈的影响力持续至 1990 年代，Linux 早期 TCP/IP 实现（NET-2）借鉴 BSD 代码（含 BSD 版权声明）；（4）BSD 网络栈的统治地位反映 BSD 作为互联网基础设施的核心地位

  | BSD 网络代码跨平台扩散 | 操作系统 | 时间 | 关系 |
| -------------------- | ------ | -- | -- |
| SunOS | Sun Microsystems | **1983 年** | 直接基于 4.2BSD 衍生，网络代码源自 BSD | | |
| Ultrix | DEC | **1984 年** | 基于 4.2BSD 衍生以运行于 VAX 与 DEC 工作站 | | |
| AIX | IBM | **1986 年** | 早期网络实现借鉴 BSD 套接字 API 与 TCP/IP 栈 | | |
| Linux NET-2 | Linus Torvalds | 1990 年代 | 早期 TCP/IP 实现借鉴 BSD 代码（含 BSD 版权声明） | | |

  | BSD 作为 RFC 参考实现的案例 | RFC | 内容 |
| ------------------------- |---| -- |
| RFC 1122 | "Requirements for Internet Hosts"（**1989**） | 以 BSD TCP/IP 实现为参考 | | |
| BIND/Sendmail | 对应 RFC | BSD 实现成为事实参考 | | |

**史料**：SunOS/Ultrix/AIX 借鉴 BSD 网络代码档案、BSD 网络代码作为 RFC 参考实现记录、Linux NET-2 借鉴 BSD 代码档案 ［A］
  
**史观**：第 9 条经验优先与第 4 条分离与聚合——BSD 网络栈的实践先于 RFC 标准化，BSD 在协议实现上聚合多家操作系统，分离与聚合的辩证关系塑造互联网实现史
  
**辨析**：SunOS（Sun Microsystems 1983 发布）直接基于 4.2BSD 衍生，网络代码源自 BSD；Ultrix（DEC 1984 发布）基于 4.2BSD 衍生以运行于 VAX 与 DEC 工作站；AIX（IBM 1986 发布）的早期网络实现借鉴 BSD 套接字 API 与 TCP/IP 栈——多源一致确认 BSD 网络代码的跨平台扩散；BSD 作为 RFC 参考实现的案例——RFC 1122"Requirements for Internet Hosts"（1989）以 BSD TCP/IP 实现为参考，BIND/Sendmail 的 BSD 实现成为对应 RFC 的事实参考；Linux NET-2 借鉴 BSD 代码——Linux 早期 TCP/IP 实现（NET-2）包含 BSD 版权声明（多源一致，Linux 网络代码中保留 BSD 版权头文件），USL 诉讼后 Linux 社区逐步重写 BSD 衍生代码但 BSD 套接字 API 的接口设计延续至今
  
**文献**：SunOS/Ultrix/AIX 网络代码档案；RFC 系列中 BSD 参考；Linux NET-2 代码档案 ［A］

## 57.5.5 Van Jacobson（范·雅各布森） 拥塞控制与 4.3BSD-Tahoe（1988）

  **要点**：1986 年 10 月互联网首次拥塞崩溃——Lawrence Berkeley Laboratory（LBL）到 UC Berkeley（相距 400 码、两跳 IMP）的数据吞吐量从 32 Kbps 骤降至 40 bps（下降三个数量级），暴露 4.2BSD TCP/IP 在拥塞控制方面的缺陷；Van Jacobson（LBL）与 Michael J. Karels（UC Berkeley）针对此问题设计七个 TCP 算法：（i）往返时间方差估计、（ii）指数退避重传计时器、（iii）慢启动（slow-start，原名 soft-start，John Nagle 1987 年 3 月建议改名）、（iv）更激进的接收方确认策略、（v）拥塞时动态窗口调整（拥塞避免）、（vi）Phil Karn 的钳位重传退避算法（Karn 算法）、（vii）快速重传；Jacobson 与 Karels 在 1988 年 8 月 ACM SIGCOMM '88 研讨会（Stanford）发表 "Congestion Avoidance and Control" 论文（ACM SIGCOMM Computer Communication Review Vol. 18 No. 4 pp. 314-329；修订版 LBL 技术报告日期为 1988 年 11 月）；这些算法集成入 1988 年 6 月发布的 4.3BSD-Tahoe（首个将 BSD 内核分为机器相关与机器无关部分的版本，支持 CCI Power 6/32 "Tahoe" 平台），使 BSD TCP/IP 在拥塞网络中吞吐量提升数倍；快速恢复（fast recovery）算法后由 Jacobson 在 1990 年补充，集成入 4.3BSD-Reno（1990），形成 "Tahoe/Reno" 拥塞控制范式，成为后续三十年互联网 TCP 拥塞控制的基础；统计结论 [C-41] references 表总数 16,867 条，[C-42] 年份提取率 44.42%（7,493/16,867），1988 年 Van Jacobson 论文发表当年 107 条累计 1,255 条（16.75%），1988-1992 年拥塞控制研究期间累计 1,564 条（20.87%），CSRG 时期（1969-1995）累计 1,879 条占比 25.08%——拥塞控制算法集成入 BSD 推动了互联网网络研究文献的产出

## 57.5.6 Sun NFS 网络文件系统与 BSD 集成（RFC 1094）

  **要点**：NFS（Network File System）由 Sun Microsystems 于 1984 年设计，基于 Sun RPC（Remote Procedure Call，RFC 1057，1988 年 6 月）与 XDR（eXternal Data Representation，RFC 1014，1987 年 6 月）构建；NFS Version 2 协议于 1989 年 3 月以 RFC 1094 发布（作者 Sun Microsystems, Inc.，共 27 页），采用无状态服务器设计（服务器不维护客户端协议状态，崩溃恢复简单），提供透明远程文件访问；NFS 客户端与服务器代码集成入 4.3BSD-Tahoe（1988 年 6 月）至 4.3BSD-Reno（1990 年）期间的 BSD 版本 [考据完成：2026-07-28 经联网考据 Wikipedia "4.3BSD"条目明确记载 4.3BSD-Reno（1990 年初）包含来自 University of Guelph 的 NFS 实现，作为 Reno 的新功能之一；4.3BSD-Tahoe（1988.6）Release Notes 未提及 NFS。结论：NFS 作为 CSRG 官方集成入 BSD 首次出现在 4.3BSD-Reno（1990），部分来源所称“Tahoe 已含 NFS 代码”可能指 Sun 提供的 NFS 参考实现作为第三方补丁存在，但非 CSRG 主线集成； Tahoe 与 Reno 之间的 NFS 代码继承关系需核对原始源代码与 Release Notes，属史料缺口]；NFS 的设计哲学（无状态、跨平台、RPC/XDR 抽象层）深刻影响后续分布式文件系统（如 AFS、SMB/CIFS）；NFSv3 以 RFC 1813 于 1995 年 6 月发布，NFSv4 以 RFC 3010/3530 于 2000/2003 年发布；NFS 成为 UNIX 世界跨平台文件共享的事实标准，Sun 将 NFS 开放实现的决策（与 BSD TCP/IP 类似）推动了其在异构环境中的普及
