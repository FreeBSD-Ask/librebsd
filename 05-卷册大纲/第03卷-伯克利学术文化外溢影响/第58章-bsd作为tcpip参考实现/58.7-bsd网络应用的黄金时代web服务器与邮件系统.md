# 58.7 BSD 网络应用的黄金时代——Web 服务器与邮件系统

## 58.7.1 Apache 与 sendmail 的 BSD 血缘

**要点**：Apache 最初在 BSD 系统上开发——NCSA httpd 运行于 BSD/OS，Apache 的 prefork 模型直接受益于 BSD fork() 实现效率。sendmail（Eric Allman（埃里克·奥尔曼）, 1981）为 4.1cBSD 开发，是互联网 SMTP 事实标准。

**史料**：Apache HTTP Server 项目历史； Allman 1983 USENIX ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律。

**辨析**：BSD 网络栈的历史叙事常以“参考实现”自居，但需注意同一时期存在多个竞争性网络实现（如 MIT 的 PC/IP、CMU 的 Mach 网络栈）。BSD 网络栈的“标准”地位是事后建构——在 1980 年代它只是众多实现之一。Web 服务器市场的数据受制于 Netcraft 等第三方统计的方法论局限。

**文献**：Apache 历史； Allman 1983 ［A］

**要点**：

- Klara Systems 详解 OpenZFS 2.1 的 dRAID（distributed RAID）：在 RAID-Z 语义上重排数据块使访问均匀铺满全部盘，配合预分配的分布式热备实现快速换盘；其顺序 resilver 仅沿 parity 布局重建目标盘，随后自动触发 healing resilver 补全校验，把传统 scrub 式全池校验拆分为两阶段以适应大容量盘时代；OpenZFS wiki 的 90 盘 16TB 组测试显示换盘时间由约 29 小时缩短至 15 小时余，且单/双/三奇偶校验皆不放大耗时。（BSD Now EP393，[463.28-869.34]，L2）
- 主持人重读 27 年前 Adrian Cockcroft 的 Sun Performance and Tuning：SunOS 4 目录名查找缓存（DNLC）只缓存 14 字符以内文件名、le0 网卡与 SCSI 接口共享 DMA 导致重负载网络拖慢磁盘吞吐等细节，折射 90 年代系统调优的现实约束；书中 VM stat/SAR 的多因素组合测量（六因素四水平即 4096 组合）提醒读者性能实验的组合爆炸与读数陷阱。（BSD Now EP393，[89.12-426.96]，L2）
- Signal 在伊朗遭封锁后给出代理方案，其官方 Docker 镜像内里只是 nginx 配置；社区据此给出 FreeBSD + nginx + acme.sh（Let's Encrypt/ZeroSSL）的等价部署教程，并默认关闭访问日志以避免记录经代理的通信内容。（BSD Now EP393，[1065.54-1311.46]，L2）
- 从 macOS 迁移者的 PDF 需求牵引出 OpenBSD ports 中的 Xournal/Xournalpp（触笔与手指标注、签名、导出只读 PDF）与 OCRmyPDF（对扫描件识别后生成可复制文本），讨论指出这类工具并非 OpenBSD 独有，映射桌面 Unix 在文档工作流上的补课过程。（BSD Now EP393，[1311.46-1662.86]，L2）
- Fabricator 平台的“现在就该做”清单以 Facebook 教训立论：ID 从 2 的 33 次方起跳以杜绝标识符与业务数值混淆（PHP array_slice 重排索引导致渲染错人的案例）、只存有效 UTF-8 以避免文件名跨系统漂移（Bacula 备份还原场景反例）、勿以黑名单构建安全系统（Facebook 的 CSS 黑名单制造了无尽的安全漏洞）、生产环境 SQL 语法错误应当高声报警以充当 SQL 注入的高信号探测器。（BSD Now EP393，[1672.1-1939.58]，L2）
- 反馈环节：Dan Langille 当场实测证明 ZFS 快照彼此独立、可任意删除旧快照而不影响新快照（快照是文件系统时点照片而非增量差分，仅回滚受限于更新快照）；另有听众询问 bhyve 中直通设备与物理盘并存的失败案例，以及多操作系统共享同一 ZFS 池引导的可行性，主持人以 bootfs 参数唯一性与加载器对加密池（GELI）的支持边界作答。（BSD Now EP393，[2438.92-2922.44]，L1）
- Brian Tiemann 的写作路径带有强烈的偶然性：《FreeBSD Unleashed》2001 年出第一版，前两版与 Michael Urban 合著——Urban 本已签约写书，发现工作量超出单人极限，恰好是 Tiemann 所运营 FreeBSD 系统的用户，便直接邀请管理员合写；此版为独著的第三版，目标覆盖 FreeBSD 6.0，预计三月完成作者审阅、五月上架，将是市场最早覆盖 6.0 的书之一；其出版线为 SAMS 的 Unleashed 系列，作者另参与 In a Snap 与 How to Do Everything With 两个系列。（BSDTalk EP19，[42.84-75.27]，L1）
- 他与 FreeBSD 的结缘始于 1994 年进入加州理工学院：校园学生网清一色 Unix 且以 Sun 机器为主，此前只有早期 Windows 与 DOS 经验的朋友把他引向命令行、Pine 邮件与新闻组；当时 FreeBSD 2.2.1 为最新版，因常被称道为高性能 web 服务器平台而入眼——Apache 项目以 FreeBSD 为中心、性能模块参数主要按 FreeBSD 列写，Yahoo 与 Walnut Creek CDROM 在单一 web 服务器时代都以 FreeBSD 商店自豪；他为自己的迪士尼《狮子王》粉丝站 lionking.org 选服务器时，Linux 尚未满 1.0，FreeBSD 好玩的软盘安装流程让他一试成主顾，该站此后十年兼营用户站点、邮件与 PHP 托管；学生集群的集中磁盘与终端接入体验甚至一度让他怀疑单机桌面 PC 的存在意义，工作数年后才理解计算用途因人而异。（BSDTalk EP19，[252.33-554.47]，L1）
- 十年服务器运维见证了安装范式的两次变化：早期安装 FreeBSD 须通过可视化硬件配置器逐项指定 ISA 设备的中断与内存地址，PCI 普及后该流程几乎消失，安装工作量缩减至从前的四分之一并成为单一流程；其托管商现已把 FreeBSD 与三个 Linux 及若干 Windows 并列为磁盘镜像默认安装选项但不含支持；升级方法论上，他只信任 5.4 到 6.0 的二进制升级脚本，认为 4 到 5 的跨越远超脚本可覆盖的配置组织方式，而 5.0 引入的 etc rc.d 目录以标准化脚本统一服务的启停重启；他把最佳升级法总结为备份数据后全量重装，理由是 FreeBSD 把本地软件与配置集中 compartmental 化，使迁移可以绕过配置合并，而车库家用服务器因可承受风险，走同步源码加 make world 的路线。（BSDTalk EP19，[575.31-871.97]，L1）
- 桌面选择上他白日使用 Mac 已约六年：享受 Mac OS X 自发布以来的演进体验，部分原因是其 FreeBSD 基座保留了熟悉的工具、本质是壳下的 Unix；他提及 Eric Levenez 的横向 Unix 历史谱系图（可打印约十六页拼接为墙幅、数月一更）并称 FreeBSD 与 Mac OS X 多年互相滋养是迷人课题，但他用 Mac 的根本理由是用户体验——Apple 是唯一把大量专门努力投入用户界面目标的公司，老手习以为常的邮件与网页小习惯对普通用户是折磨，整个计算业的用户体验远未达到汽车业的成熟度。（BSDTalk EP19，[877.00-1099.57]，L1）
- 为写书重返 BSD 桌面令他惊喜：KDE 进步显著并已有关键链管理器这类他依赖的功能；写作过程中发现刚从 FreeBSD 分出的 PC-BSD——以 KDE 为基座、追求与任何桌面系统同级的透明安装与易用、配备图形化包管理；对照九十年代中期他在慢机器上追捧 Enlightenment 伪透明效果的经历，如今 KDE、窗口管理器与 X11 内置合成功能令他鼓舞——合成不是为好看的怪癖而是真正的功能，Mac 的窗口缩小动效之所以能指示窗口去向，正依赖 Quartz 合成层，同类技术进入 X11 与 GNOME、KDE 各自的界面准则，意味着 Unix 端真正的用户应用有了可期的未来；他也确认 FreeBSD 团队的服务器专注无人否认，图形界面责任多在核心系统之外。（BSDTalk EP19，[1110.35-1351.87]，L1）
- 其日职所在公司制造带宽管理设备，实验室须在各种拓扑间做高强度流量互抛测试，结论是 FreeBSD 在灵活与稳定之间给出最佳平衡：对内核做正确调校后，其 TCP/IP 栈所能压榨出的高端速度超过同级的 Linux 与其他 Unix 机器。（BSDTalk EP19，[366.35-403.41]，L1）

**史观**：

- 总纲22 知识注定过时：27 年前的调优书今日仍被整期研读，其价值不在参数而在方法论；DNLC 14 字符限制等具体知识已彻底过时——技术图书的经典性恰以内容过时为前提，留存下来的是测量学经验。（BSD Now EP393，[89.12-299.56]，L2）
- 总纲5 没有必然性，只有偶然性：Signal 伊朗封锁这一偶然地缘事件催生反审查代理教程：FreeBSD 社区的技术响应方向由外部政治偶然性牵引，而非既定技术路线图。（BSD Now EP393，[1088.66-1102.9]，L2）
- 总纲13 法律与道德是利益分配：Facebook 黑名单 CSS 过滤器的失败史揭示安全机制同样是利益与权力的分配装置：默认允许加枚举坏人的架构把防御成本转嫁给未来，枚举权的失效即秩序的失效。（BSD Now EP393，[1843.98-1866.94]，L2）
- 总纲4 分离聚合是永恒规律：dRAID 把 scrub 的整体校验分离为顺序重建与 healing 补全两阶段再聚合，其设计哲学是让数据布局的分离-聚合服务于修复路径的最小化。（BSD Now EP393，[497.16-704.2]，L2）
- 总纲1 一切真历史都是古代史：对 1994 年图书的认真重读表明：理解当下存储系统行为（预读、缓存、测量偏差）须不断回到“古代”文本，性能史是一部被反复重写的古代史。（BSD Now EP393，[155.36-186.48]，L2）
- 总纲9 经验优先：Tiemann 的升级方法论完全从十年六平台、多托管环境的实操教训中归纳而来：二进制升级脚本的不可信、make world 在生产机上的不可承受、配置合并的易错，最终沉淀为备份加全量重装这一最笨却最可靠的办法——升级正道由运维经验而非理论推演得出，而 FreeBSD 的目录规约恰为这种经验做法提供了结构支撑。（BSDTalk EP19，[811.27-871.97]，L1）
