# 61.6 BSD 数据库生态——MySQL 与 PostgreSQL 的 BSD 谱系

## 61.6.1 PostgreSQL 的 BSD 学术根源与 MySQL 的跨平台策略

**要点**：PostgreSQL 起源于 UC Berkeley POSTGRES 项目（Stonebraker, 1986），运行于 4.3BSD。MySQL 虽源自 Linux 但始终维护 BSD 完整支持，FreeBSD ports 中的 MySQL 端口是数据库-OS 协作的典型案例。

**史料**：Stonebraker & Rowe SIGMOD 1986; MySQL FreeBSD 安装指南 ［A/B］

**史观**：总纲第 1 条——技术谱系的路径依赖。

**文献**：Stonebraker 1986; MySQL 文档 ［A/B］

**观点**：1992 年 7 月，图宾根大学的 Gunther Schadow 汇报他在 386BSD 上的数据库选型尝试：Ingres 8.5 编译可过但“太古老”令他放弃，转向 3.1 版 Postgres——体量约为 Ingres 四倍，在小系统上是 size 限制因素，且须逐一清理 ftime、ecvt、gtty 等过时函数调用。
**邮件来源**：Gunther Schadow，comp.unix.bsd，1992 年 7 月，Message-ID: `zxmsd01.711063005@mailserv`
**史学意义**：这封用户笔记同时记录了 Ingres 与 Postgres 两代伯克利数据库在自由 BSD 上的第一手移植体感与代际差异，是 386BSD 时代数据库谱系交替的基层观察。

**要点**：

- Limelight Networks 是较早以 FreeBSD 为 CDN 基底的企业：公司 2000 年代初创立时沿袭 Solaris 跑在 SPARC 上的互联网惯例，因 TCP 与事件轮询问题转向 FreeBSD，并以廉价 Supermicro 服务器补充容量，使 FreeBSD 从公司创立起即进入其历史。（BSD Now EP241，[2428.8-2520.3]，L1）
- Limelight 曾购入一套专有 TCP 栈，其后该公司被竞争对手收购，过去几年 Limelight 逐步拆解并迁回 FreeBSD 自带 TCP 栈，重新获得源码与治理能力，自述该项目非常成功。（BSD Now EP241，[2536.1-2569.9]，L1）
- Limelight 的缓存节点采用每盘一个 UFS 文件系统、磁盘故障即丢弃的模式，认为 RAID 或 ZFS 会损耗缓存性能与容量；其吞吐依赖 sendfile 零拷贝并复用 Netflix 的内核 TLS 工作以加密发送数据。（BSD Now EP241，[2777.9-2917.6]，L1）
- 节目报道 FreeBSD 合入多项 ZFS 改进：zpool remove 可撤离单一无冗余 vdev 并通过间接映射与 zfs remap 加速、残缺或配置过期的池可两段式导入并回滚到早前事务组、借鉴 Oracle Solaris 的 zpool create -B 可创建 EFI 系统分区并新增 boot size 属性。（BSD Now EP241，[11.8-1244.0]，L2）
- PostgreSQL 开发者 Craig Ringer 与 Thomas Munro 讨论发现：除 FreeBSD 与 illumos 外，Linux XFS 与 OpenBSD、NetBSD 在 fsync 返回 EIO 后重试会清除错误标志并继续，导致此前未落盘数据永久丢失；FreeBSD 在 1999 年由 Kirk McKusick 提交的缓冲保留策略使重试仍有机会成功。（BSD Now EP241，[1448.6-2050.0]，L2）
- Josh Berkus 自述其任 PostgreSQL 核心团队七人小组成员，该团队决定 PostgreSQL 的版本发布时机；Sun Microsystems 决定支持 PostgreSQL 项目并在 Solaris 平台销售支持服务后聘请其为 PostgreSQL 战略负责人。其此前履历包括 OpenOffice.org 项目负责人（为加入 PostgreSQL 核心团队而辞任）、Software in the Public Interest 董事会成员与 O'Reilly 开源大会委员会成员。（BSDTalk EP110，[49.23-95.41, 742.27-801.59]，L1）
- 关于项目接续史的当事人叙述：PostgreSQL 前身 Postgres 于 1986 年在伯克利加州大学启动，作为大学项目运行十年后校方 CS 系失去兴趣；此时校友与互联网社区中的职业使用者已将其投入生产，伯克利决定放手时，包括一位 FreeBSD 操作系统主要贡献者 Marc Fournier 在内的开发者群体将其改造为真正的开源项目并上线 CVS——1995 年开始、1996 年完成，社区遂以 1996 年 7 月 8 日为开源项目诞生日；十周年时在多伦多举办逾百人开发者峰会。 [存疑脚注] 转写作“Mark Fournier”，按 FreeBSD 核心团队与 PostgreSQL 基础设施史应为 Marc G. Fournier，名字拼写以转写存疑待核（BSDTalk EP110，[128.22-221.07]，L1）
- Berkus 的技术栈迁移史完整呈现了 1990 年代小企业咨询市场从专有软件向开源的转换动因：其自立门户服务小企业与非营利客户后，发现专有技术许可费与 MSDN 订阅侵蚀利润，而微软于 1997 至 1998 年停止补贴转向盈利，SQL Server 起步价从约 700 美元跃至 3000 美元；同时 SQL Server 加 COM+ 方案每两三周随机故障，迫使其每两周上门维护；MySQL 当时仍是共享软件且其 2.x 版不支持表连接，无法满足其 SQL 专家标准；转投 PostgreSQL 后，社区对其 SQL 合规性质疑的开放接纳与 MSDN 论坛的封禁文化形成鲜明对照，首周即融入项目——社区文化本身成为技术选型的决定因素。（BSDTalk EP110，[529.11-741.71]，L1）
- Berkus 对数据库生态的定位划分：PostgreSQL 居高端，面向需支撑海量连接、TB 级数据与长事务、以替换 Oracle、DB2、SQL Server 2005 为目标的场景；Derby 与 Sleepy Cat（即 Berkeley DB）一类居嵌入式端；MySQL 居中，规模与扩展性占优但不及 PostgreSQL，对用户数据库知识要求也更低。PostgreSQL 的比较优势包括 BSD 许可证允许与专有软硬件捆绑（其最流行的分发方式之一）、活跃企业用户转化为社区成员从而获得对软件未来的归属感与控制感、独立安全评级（Database Hackers Handbook 中高于 Oracle 与 DB2）、提交即持久的可靠性保证，以及源自对象关系设计的可编程数据库对象——PostGIS 借此成为全球第二大 GIS 数据库系统（仅次于 NavTeq），基因组学领域亦出现以专用数据类型扩展 PostgreSQL 的项目。 [存疑脚注] 基因组项目名转写作“BlastGres”，确切名称待核；NavTeq 为转写原貌，当作 Navteq（BSDTalk EP110，[802.59-1047.13, 884.21-927.73]，L1）
- Langille 自述 2007 至 2008 年的际遇与现职：去年 BSDCan 后南下佛罗里达，旋因工作外包于六周后失去收入，返堪萨斯办妥工作许可后入职 Afilias——费城郊外 Horsham 的一家域名注册局服务商，负责 .org 等顶级域名的域名数据库，whois 信息与各域名的域名服务器列表皆自该库提取；其经手的全部顶级域名数据库均运行于 PostgreSQL。（BSDTalk EP144，[110.06-193.82]，L1）
- Slony-I 复制系统出自 Afilias 内部开发、后以开源释出，为 PostgreSQL 界所熟知且公司自身重度使用；域名库早在 2004 年 BSDCan 出现首个 Slony 演讲之前即已上 PostgreSQL（选型兼顾许可证与性能）；生产规模上单表达数千万行、日交易量巨大，调优得当时数据吞吐飞快，瓶颈通常在磁盘而非数据库本身；系统设定完成后即自行运转，无须持续调优，服务水平协议从未因 PostgreSQL 而失守。（BSDTalk EP144，[193.82-554.90]，L1）
- BSDCan 2008 为第五届、续办于渥太华大学，受邀演讲数量创历年之最：ZFS 文件系统深探（讲者转写不可辨）、Chris Lattner（时与 Apple 相关）讲 BSD 许可证的 C++ 编译器、Bacula 之父 Kern Sibbald 自瑞士与谈（Langille 本人亦是 Bacula 开发者）、Google Summer of Code 讲座、OpenBSD 硬件传感器框架的近期工作、Randall Stewart 讲 SCTP 及其扩展 socket API、X.Org 的未来规划；此外设 hacking、系统管理、嵌入式、虚拟化诸轨与教程，预计与会开发者约六十人（报名三十、惯例至会前翻倍），会前有开发者互讲、晚间设 hacking 房。 [存疑脚注] ZFS 演讲者人名转写不可辨，语境疑为 FreeBSD ZFS 移植者；SCTP 转写作 FCTP（BSDTalk EP144，[743.56-915.26]，L1）

- Bruce Momjian 回顾 Postgres 起点：1996 年代码离开伯克利时是一堆能力出色、前途可期但缺陷众多、学术导向的代码，他是启动基于互联网的协作开发的人之一，前四年以志愿者身份工作，此后受雇于从事 Postgres 业务的公司；近十年间项目从利基爱好成长为获得 Sun 及日美大型企业采用的主流数据库，.org 顶级域的 DNS 数据即由 Postgres 承载，美国国家气象局、大型金融公司与 Ameritrade 亦在使用；截至访谈时 8.1.2 为当前版本，8.2 开发重点转向数据仓库与高可扩展场景。（BSDTalk EP15，[356.75-628.76]，L1）
- Momjian 提出 BSD 许可证的企业友好论证：BSD 许可证没有任何附加条件或被认为没有附加条件，省去企业对开源许可证的律师审查恐惧，向内部推销极为容易；其结果是培育出一批以 Postgres 为业务的公司，出售商业版本、附加组件与支持服务；他把社区与企业的分工讲得直白——社区擅长开发与发版，但没有销售员、没有技术支持电话、没有上门做性能调优的人，而这些恰是许多组织需要的，BSD 许可证使大量公司得以全力支撑 Postgres 用户。（BSDTalk EP15，[467.44-570.88]，L1）
- Windows 原生 port 曾在 Postgres 社区内部引发真实斗争：是否要 Windows port、同一代码库同时容纳 Windows 与 Unix 的代价有多大；Momjian 花约两年与社区成员完成移植，结果是代码经模块化反而比开工前更干净；面对为何推广专有平台的质疑，他的回答是必须先在对方平台上展示开源的能力才能促成向开放操作系统的迁移，而 Windows 市场的实际定位是销售演示与开发者笔记本测试，并非大型服务器。（BSDTalk EP15，[806.95-901.72]，L1）
- 跨大版本就地升级是 Postgres 的结构性困境：子事务、两阶段提交等特性不断改变磁盘格式，一旦格式改变就必须读入并重写数据库的每一页，成本几乎等同转储重灌；Momjian 称这是项目前进太快带来的诅咒——技术上能写就地升级脚本，但每次核对跨版本变化后都显得不切实际；社区现行推荐是 Slony 复制方案，让新旧两版数据库并行运行，切换服务器即完成升级，停机仅一次重启，项目仍在零停机与转储重灌两类用户需求之间权衡是否值得再造第三条升级路径。（BSDTalk EP15，[923.85-1089.19]，L1）

- Morley 于 1998 年高中时期先试 Linux，两三周内转投 FreeBSD 并成为重度用户；未走大学路线，凭 FreeBSD 经验获聘时为 Tier-1 骨干网的 Genuity 之 Tier-2 UNIX 系统管理员；到职后发现 Solaris、IRIX、HP-UX、AIX 等 UNIX 变体底层概念高度相通，BSD 背景使其能“以用户而不仅是管理员”的身份进入角色。（BSDTalk EP59，[67.84-334.8]，L1）
- 游戏服务器实践：因第一人称射击战队需要服务器，先在家中后转托管机房以 FreeBSD 承载；当时游戏服务器仅有勉强可用的 Linux 移植（客户端本为 Windows 专用），经 FreeBSD 的 Linux 模拟层运行并为守候进程编写监控脚本；为满足约 20 名玩家 20-40 毫秒的低延迟预期，他发现机器响应性不及 Windows 机器的体感，遂调整内核 HZ 时钟设置提高中断频率，以更高 CPU 占用换取更低延迟——专机专用使其成为合算权衡，最终取得可观延迟表现。（BSDTalk EP59，[345.72-478.7]，L1）
- 在企业内的渐进替代：其任职的保险行业软件公司入职时为纯 Windows 店，微软代理服务器频繁需重启且因闭源无解；他主动提出架设路由器，此后 FreeBSD 机器逐级承担路由、经防火墙的异地备份、自动化备份脚本、源码目录 diff 与 md5 变更追踪（Windows 上无简易自动化手段，CVS 在 Windows 店中也未被考虑），最终 Web 应用托管迁至 FreeBSD，使其能专注应用而几乎无需操心底层平台——与 Windows 开发中安装注册卸载软件、服务包后系统文件受保护等纠葛形成对照；同事未必理解 BSD 细节，但明确知道机器崩溃更少，甚至忘了 Windows 代理曾需数月一重启，已一年半未重启。（BSDTalk EP59，[482.3-720.26]，L1）
- 补丁与软件可得性：机构网络高度封闭、使用者高度受限，其补丁流程异于一般建议——偏好在本机或中央机保留源码并下载补丁，强调无论二进制更新或自行编译都必须保持系统最新，外部防火墙有意设为不可自外部访问，并经邮件列表获取补丁通知；软件可得性早年确实受限，但如今办公、通信、即时消息与数据安全需求几乎全有开源替代，仅照片处理与交互媒体等最终用户品类仍缺，某些包在 FreeBSD 上缺席只是因为社区兴趣不在于此。（BSDTalk EP59，[720.26-918.78]，L1）
- 生产栈与数据完整性：现役栈为 FreeBSD 加 Apache、PHP 与 MySQL；Web 应用在每次变更后即写库，MySQL 使用强度极高，因为保险业务数据丢失不可容忍（例如一次录入 300 辆车的车队保单），客户端因此永不丢失已录数据，另有备份兜底；曾评估 Windows 方案——按传统本应顺手，但愈评估愈昂贵、愈复杂且后端与托管可靠性存疑；开源系统、Web 服务器、语言、数据库加 HTML/JavaScript 等开放标准使其可自行排障而不必等待厂商更新，微软舍入函数在大量小数与因子精算中的缺陷正是闭源下无法自行修复的隐患，而 PHP 与 MySQL 的庞大活跃社区则使已知问题被主动处置。（BSDTalk EP59，[1097.1-1302.22]，L1）
- 术语立场与人才供给：选 PHP 而非 Python 或 Ruby，部分原因是更容易找到熟悉 PHP 且接触过 MySQL 的开源开发者——PHP 已跨过普及阈值，他称沿街即可找到数名 PHP 开发者（因其免费面向青少年传播）；免费且可靠的工具一旦用惯，便不会回换付费且更不可靠者；他自称作为 BSD 用户“更多是开源心态而非自由软件心态”，并主张在开源已提供有吸引力方案之处不应仅因其是开源而错过；同时承认说服公司转向并非易事，但在多数场景下确为更优平台。（BSDTalk EP59，[1302.22-1449.74]，L1）

**史观**：

- 总纲10 动手者创造历史：Limelight 与 Isilon、Netflix 接力完成 IFLib 网络驱动框架，说明默默动手的企业工程师在塑造 FreeBSD 网络栈，而非仅台前人物。（BSD Now EP241，[3374.9-3449.0]，L1）
- 总纲9 经验优先：Limelight 以缓存数据可丢弃、追求最大 IO 与存储密度的经验判断选择每盘 UFS 而非 ZFS，体现经验优先于存储抽象的技术哲学。（BSD Now EP241，[2777.9-2886.4]，L1）
- 总纲25 逻辑是形式主义而非世界本身的结构：各操作系统对 fsync 返回 EIO 后是否保留脏页的不同实现，是对同一 POSIX 语义的形式化差异，而非文件系统世界本身固有的唯一结构。（BSD Now EP241，[1567.4-1762.9]，L2）
- 总纲13 法律与道德是利益分配：Berkus 描述的商业生态形态展示了宽松许可证下的共生结构：EnterpriseDB（Oracle 兼容函数的专有分支）、Greenplum（基于 PostgreSQL 的专有数据仓库）、Continuent（Sequoia 之上的 UniCluster）、PowerGres（专有分支）等商业衍生品并存，而 PGCon 对商业分支议题持有限开放；与此同时，公开而活跃地使用 PostgreSQL 的公司被吸纳为社区成员而非保持纯商业客户关系。许可证允许专有汲取，社区则以参与感回收忠诚——法律框架在此直接塑造了商业与社区的博弈方式。 [存疑脚注] “Powergrass”转写原貌，应为日本厂商的 PostgreSQL 专有分支 PowerGres，待核（BSDTalk EP110，[391.47-493.45, 884.21-927.73]，L1）
- 总纲20 历史地理塑造思想土壤：BSDCan 的地理惯性自成一例：会议地点并非由社区版图或战略考量决定，而系于创办人的居所变迁、场地与供应商熟悉度这类偶然的物流事实——人移居宾州而会议仍留渥太华，地理的惯性与 familiarity 持续塑造着 BSD 社区的聚集形态。（BSDTalk EP144，[636.40-718.20]，L1）
- 总纲5 没有必然性，只有偶然性：Momjian 自述约 1991 年起接触开源，并把参与 Postgres 归于纯粹的好运——是运气让他撞上这个特定项目；一个此后影响大量企业与机构的基础设施项目，其核心贡献者的加入并无必然路径，只系于个人轨迹中的偶然相遇。（BSDTalk EP15，[405.10-413.29]，L1）
- 总纲6 和解优于斗争：Windows port 之争的化解方式不是阵营间决出胜负，而是把改造成本内部化：移植过程中对代码库大规模模块化，使 Windows 与 Unix 在同一代码基中共存且质量反而提升，同时以先在对方平台证明开源价值的说服逻辑替代对专有系统的拒斥，构成一次以和解与互相渗透收场的路线分歧。（BSDTalk EP15，[820.31-901.72]，L1）
- 总纲10 动手者创造历史：Langille 与主持人一致认为真正的学习来自工作之余亲手构建玩物而非岗位任务本身——14TB ZFS 服务器、Bacula 的 PostgreSQL 后端等个人动手产物既反哺其日常职业，也构成 BSD 与 PostgreSQL 生态中会议、工具与社区的实际支撑。（BSDTalk EP203，[822.77-847.94]，L1）
- 总纲5 没有必然性，只有偶然性：会议的诞生并无总体规划：组织者自述是被“裹挟”而成——总有人提议开会、总举手的是同一批人，一句“我们办个会吧”换来的回应分别是“天哪千万别再办了”与“行吧帮个忙，顶多一年两年”，结果一办八年；NYCBUG 被形容为去中心化的拟蒙实验，多年积累的动能自行推动，总有某个人承接着事务的某一部分。社群活动的延续不依赖蓝图，而是偶然承诺与动能的接力。（BSDTalk EP236，[220.88-301.26]，L1）
- 总纲20 历史地理塑造思想土壤：纽约的技术地理塑造了会议形态：这座城市有健康的 BSD 用户组，“但纽约终究是 Linux 的城市”，故组织者把跨界交叉授粉与更大技术社群的开放共享视为要务；同时人口稠密带来拥挤的日程，让最不缺人的城市反而最难动员出席者。地方的社群结构与生活节奏直接规定了会议的主题取向与组织成本。（BSDTalk EP236，[204.08-220.04]，L1）
- 总纲5 没有必然性，只有偶然性：FreeBSD 在该企业的扩散并非自上而下的平台决策，而是由微软代理服务器反复崩溃这一偶发故障触发：一句“我可以架个路由器”的顺手之举逐级演化为路由、备份、脚本与最终的托管迁移——企业技术替代史由偶发故障与在场者的即兴回应写成。（BSDTalk EP59，[531.68-577.04]，L1）
