**要点**：

- Bruce Momjian 回顾 Postgres 起点：1996 年代码离开伯克利时是一堆能力出色、前途可期但缺陷众多、学术导向的代码，他是启动基于互联网的协作开发的人之一，前四年以志愿者身份工作，此后受雇于从事 Postgres 业务的公司；近十年间项目从利基爱好成长为获得 Sun 及日美大型企业采用的主流数据库，.org 顶级域的 DNS 数据即由 Postgres 承载，美国国家气象局、大型金融公司与 Ameritrade 亦在使用；截至访谈时 8.1.2 为当前版本，8.2 开发重点转向数据仓库与高可扩展场景。（BSDTalk EP15，[356.75-628.76]，L1）
- Momjian 提出 BSD 许可证的企业友好论证：BSD 许可证没有任何附加条件或被认为没有附加条件，省去企业对开源许可证的律师审查恐惧，向内部推销极为容易；其结果是培育出一批以 Postgres 为业务的公司，出售商业版本、附加组件与支持服务；他把社区与企业的分工讲得直白——社区擅长开发与发版，但没有销售员、没有技术支持电话、没有上门做性能调优的人，而这些恰是许多组织需要的，BSD 许可证使大量公司得以全力支撑 Postgres 用户。（BSDTalk EP15，[467.44-570.88]，L1）
- Windows 原生 port 曾在 Postgres 社区内部引发真实斗争：是否要 Windows port、同一代码库同时容纳 Windows 与 Unix 的代价有多大；Momjian 花约两年与社区成员完成移植，结果是代码经模块化反而比开工前更干净；面对为何推广专有平台的质疑，他的回答是必须先在对方平台上展示开源的能力才能促成向开放操作系统的迁移，而 Windows 市场的实际定位是销售演示与开发者笔记本测试，并非大型服务器。（BSDTalk EP15，[806.95-901.72]，L1）
- 跨大版本就地升级是 Postgres 的结构性困境：子事务、两阶段提交等特性不断改变磁盘格式，一旦格式改变就必须读入并重写数据库的每一页，成本几乎等同转储重灌；Momjian 称这是项目前进太快带来的诅咒——技术上能写就地升级脚本，但每次核对跨版本变化后都显得不切实际；社区现行推荐是 Slony 复制方案，让新旧两版数据库并行运行，切换服务器即完成升级，停机仅一次重启，项目仍在零停机与转储重灌两类用户需求之间权衡是否值得再造第三条升级路径。（BSDTalk EP15，[923.85-1089.19]，L1）

**史料**：

- 本期留存 Postgres 贡献者的一手传记材料：Momjian 自 1996 年参与互联网协作开发、志愿四年后转为受雇的路径；他从未将 Postgres 用于任何商业用途、从未存过一行数据的自述；早年使用 Informix 与 Ingres 的数据库经验；其个人运行已消亡的商业 BSDi 系统、并预期一两年内迁往 NetBSD 的环境交代；以及其 2001 年著作与 2001 至 2003 年一波 Postgres 书籍出版史、其中以 Douglas 所著为同类最佳的评论。（BSDTalk EP15，[356.75-786.27]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：Momjian 自述约 1991 年起接触开源，并把参与 Postgres 归于纯粹的好运——是运气让他撞上这个特定项目；一个此后影响大量企业与机构的基础设施项目，其核心贡献者的加入并无必然路径，只系于个人轨迹中的偶然相遇。（BSDTalk EP15，[405.10-413.29]，L1）
- 总纲6 和解优于斗争：Windows port 之争的化解方式不是阵营间决出胜负，而是把改造成本内部化：移植过程中对代码库大规模模块化，使 Windows 与 Unix 在同一代码基中共存且质量反而提升，同时以先在对方平台证明开源价值的说服逻辑替代对专有系统的拒斥，构成一次以和解与互相渗透收场的路线分歧。（BSDTalk EP15，[820.31-901.72]，L1）
