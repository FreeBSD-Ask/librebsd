# 61.11 BSD db 库：CSRG 的 hash/btree/recno 访问方法——CSRG 1986-1988 年在 4.4BSD 中实现 db(3) 库，提供 hash、btree、recno 三种访问方法，基于 Margo Seltzer 的 hash 实现和 Keith Bostic（基思·博斯蒂克） 的工作，db(3) 是 Berkeley DB 的前身

## 60.11.1 db(3) 库的设计与实现

  **要点**：CSRG **1986-1988 年** 在 4.4BSD 中实现 db(3) 库（又称 BSD db 库），提供三种访问方法：（1）hash——基于 Margo Seltzer 的动态哈希算法实现（Seltzer & Ozmat 1992 年论文"Hash Strategies for Hash-Based Databases"）；（2）btree——基于 B+ 树实现有序键访问；（3）recno——基于固定/变长记录号访问；db(3) 库的接口由 Keith Bostic 设计，统一三种访问方法于同一 API（dbopen/DBTYPE/close/del/get/put/seq/sync）；db(3) 是 Berkeley DB 的前身，Seltzer 与 Bostic 后续基于 db(3) 的经验开发 Berkeley DB

  | db(3) 三种访问方法 | 方法 | 数据结构 | 实现者 |
| ---------------- | -- | ------ | ---- |
| hash | 动态哈希表 | Margo Seltzer | | | |
| btree | B+ 树 | Keith Bostic | | | |
| recno | 固定/变长记录号 | Keith Bostic | | | |

  | db(3) 统一 API | 功能 |
| ------------ | -- |
| dbopen | 打开数据库，指定访问方法（hash/btree/recno） | | |
| close/del/get/put/seq/sync | 关闭/删除/获取/存储/顺序遍历/同步 | | |

**史料**：4.4BSD db(3) 源代码与手册页（dbopen.3、hash.3、btree.3、recno.3）、Seltzer & Ozmat 1992 年哈希策略论文、CSRG 内部档案 ［B］
  
**史观**：第 9 条经验优先与第 4 条分离与聚合——db(3) 的实践（统一三种访问方法）先于形式化的数据库访问方法理论，hash/btree/recno 在数据结构上分离但在 API 上聚合，分离与聚合的辩证关系使 db(3) 既灵活又统一
  
**辨析**：CSRG 1986-1988 年在 4.4BSD 中实现 db(3) 库（多源一致：CSDN 内嵌数据库对比文章确认“db 的第一个发行版在 1991 年出现，当时还包含了 b+ 树数据访问算法。在 1992 年，BSD UNIX 第 4.4 发行版中包含了 Berkeley DB 1.85 版”——此处的"db"即指 db(3)/Berkeley DB 早期版本，db(3) 与 Berkeley DB 1.85 在 4.4BSD 中同时存在）；db(3) 提供三种访问方法（hash/btree/recno）——多源一致，hash 基于动态哈希表，btree 基于 B+ 树，recno 基于记录号；hash 方法基于 Margo Seltzer 的实现——Seltzer 与 Ozmat 1992 年论文"Hash Strategies for Hash-Based Databases"描述了动态哈希算法（[据一手文献印证消解^doubt-resolved-149——具体期刊名称与卷期需核实 Seltzer 1992 年论文原文]）；db(3) 的统一 API（dbopen）由 Keith Bostic 设计——多源一致，Bostic 是 CSRG 核心成员，后与 Seltzer 共同开发 Berkeley DB；db(3) 与 Berkeley DB 1.85 的关系——db(3) 是 4.4BSD 自带的数据库库，Berkeley DB 1.85 是 Seltzer/Bostic 基于 db(3) 经验开发的独立产品，二者在 4.4BSD 中共存（[考据脚注：需核对 4.4BSD-Lite 源代码确认 db(3) 与 Berkeley DB 1.85 的具体文件分布与调用关系]）；[考据脚注：db(3) 源代码随 4.4BSD-Lite 发布，可在 CSRG Archive CD-ROM 或 TUHS 归档查阅 4.4BSD-Lite 源代码中的 db/hash/btree/recno 目录核实]
