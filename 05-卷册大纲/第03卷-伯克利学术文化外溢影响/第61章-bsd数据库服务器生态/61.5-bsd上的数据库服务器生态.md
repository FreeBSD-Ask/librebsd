# 61.5 BSD 上的数据库服务器生态——FreeBSD 作为数据库服务器的部署优势（ZFS 存储、Jails 隔离、网络栈性能），FreeBSD 在数据库工作负载中的性能基准，商业数据库（Oracle、IBM DB2）在 FreeBSD 上的支持与缺失

## 61.5.1 FreeBSD 作为数据库服务器的部署优势

  **要点**：FreeBSD 作为数据库服务器的部署优势：（1）ZFS 文件系统于 2007-04-06 由 Pawel Jakub Dawidek 首次引入 freebsd-src（commit f0a75d27“Please welcome ZFS - The last word in file systems.”），FreeBSD 7.0-RELEASE（2008-02-27）正式将 ZFS 作为试验性特性发布，提供数据完整性（校验和、快照、复制）；（2）Jails 机制由 Poul-Henning Kamp（波尔-亨宁·坎普） 于 1999-04-28T11:28:49Z 首次实现 jail 系统调用（commit 02daf150“Add the jail system call.”），同日 11:38:52Z 提交完整 Jail 实现（commit 75c135419），2000-05-29 Kamp 与 Robert N. M. Watson（罗伯特·N·M·沃森） 联合撰写 Jail 论文（commit d15d3eac“The Jail paper, written jointly by rwatson & me.”）存入 share/doc/papers/jail/，论文发表于 SANE 2000 会议；Jails 在 FreeBSD 4.0-RELEASE（2000-03）正式包含；（3）BSD 网络栈（4.4BSD-Lite 衍生）在 1990 年代后期至 2000 年代初在并发连接数与吞吐量上优于同期 Linux；（4）NUMA 优化时间 [据一手文献印证消解^doubt-resolved-142——经 freebsd.duckdb 查询 `SELECT * FROM commits WHERE repo_name='freebsd-src' AND (message_subject LIKE '%NUMA%' OR message_subject LIKE '%numa%')` 返回 0 行，commit_files 表中也无以 numa 命名的文件首次添加记录；FreeBSD 12.0-RELEASE（2018-12-11）Release Notes 提及 amd64 GENERIC 内核配置启用 NUMA 选项，但数据库中无对应代码级 commit 证据，暂保留存疑]

## 61.5.2 FreeBSD 数据库工作负载性能基准

  **要点**：FreeBSD 数据库工作负载性能基准：（1）PostgreSQL on FreeBSD 的性能基准测试在社区邮件列表与个人博客中有零散记录，但系统性学术基准测试文献稀缺；（2）MySQL on FreeBSD 的性能基准以 Yahoo! 1990 年代后期生产环境部署为典型案例（Yahoo! 在 FreeBSD 4.x 时代大规模运行 MySQL）；（3）FreeBSD 的 ULE 调度器由 Jeff Roberson 于 2003-01-26T05:23:15Z 首次提交入 freebsd-src（commit 35e6168f"Add the ule scheduler. This is intended to be a general purpose process scheduler with many SMP benefits. It is still very experimental and should be used only in test environments."），ULE 设计针对 SMP 优化，对数据库工作负载的多核调度有正面影响；ULE 在 FreeBSD 5.x 时代为试验性，FreeBSD 7.0（2008-02-27）成为 amd64 默认调度器；（4）跨平台性能基准的史料辨析存在方法论陷阱——Yahoo! MySQL on FreeBSD 案例为生产环境部署而非受控基准，社区邮件列表中的 PostgreSQL on FreeBSD 基准多为单次测量无重复样本，Phoronix 跨平台基准的硬件配置与编译选项差异使结果不可直接比较；数据库性能基准的史料价值在于定性趋势（如 ULE 对 SMP 数据库工作负载的正面影响）而非定量精确比较

## 61.5.3 商业数据库的 FreeBSD 支持与缺失

  **要点**：商业数据库的 FreeBSD 支持与缺失：（1）Oracle Database 服务器不提供 FreeBSD 原生支持——Oracle 官方支持平台为 Linux、Windows、Solaris 与 Oracle Cloud；但 Oracle 客户端库通过 freebsd-ports 提供：databases/oracle7-client 于 2002-05-28T08:50:14Z by Sergey Skvortsov 引入（commit 79dd3ec0），databases/oracle8-client 于 2005-08-31T19:01:28Z by Max Khon 引入（commit 1e36813e），客户端库允许 FreeBSD 应用连接远程 Oracle 数据库但本机不运行 Oracle 服务器；（2）IBM DB2 服务器不提供 FreeBSD 原生支持，IBM DB2 官方支持平台为 Linux、Windows、AIX、Solaris；（3）Microsoft SQL Server 在 2017 年前仅支持 Windows，2017 年发布 SQL Server for Linux（基于 Linux 容器与 Ubuntu/RHEL/SLES），但仍不支持 FreeBSD；（4）SAP HANA 仅支持 SUSE Linux Enterprise Server 与 Red Hat Enterprise Linux；（5）商业数据库服务器的缺失使 FreeBSD 数据库生态以开源（PostgreSQL、MySQL、SQLite）为主，反映 BSD 在企业数据库市场的边缘地位

## 61.5.4 FreeBSD 数据库生态的现状与挑战

  **要点**：FreeBSD 数据库生态的现状与挑战：（1）现状：FreeBSD 数据库生态以 PostgreSQL、MySQL、SQLite 为核心，freebsd-ports/databases/ 下维护数百个数据库相关 Port；（2）挑战：商业数据库服务器（Oracle Database、IBM DB2、Microsoft SQL Server、SAP HANA）原生缺失使 FreeBSD 在传统企业数据库市场难以与 Linux 竞争；（3）挑战：Linux 容器（Docker 2013、Kubernetes 2014）生态主导云原生数据库部署，FreeBSD Jails 虽早于 Docker 14 年（1999 vs 2013）但生态较小，sysutils/docker Port（2015-07-06T15:37:33Z by Kris Moore）为 FreeBSD 上的 Docker 移植但非原生；（4）挑战：FreeBSD 性能优化资源（开发者数量、企业资金）少于 Linux，使数据库性能优化在硬件新特性支持上滞后；FreeBSD 数据库生态须基于实用主义哲学（开源为主、质量优先）应对挑战

  | FreeBSD 数据库生态现状 | 内容 |
| -------------------- | -- |

| Port 数量 | freebsd-ports/databases/ 下维护数百个数据库相关 Port |

| 容器生态落后 | 云原生数据库 | Linux 容器（Docker 2013、Kubernetes 2014）主导；Jails 早 14 年但生态较小 |
| 性能资源不足 | 硬件新特性 | 开发者数量、企业资金少于 Linux，硬件新特性支持滞后 |
