## 60.2.1 Stonebraker 1986 年 POSTGRES 项目启动

  **要点**：Stonebraker 1986 年在伯克利启动 POSTGRES（Post-Ingres）项目，背景包括：（1）Ingres 1985 年商业化后 Stonebraker 回归学术；（2）Stonebraker 试图解决 Ingres 的局限（无对象支持、无时间旅行查询、无复杂查询优化）；（3）DARPA、ARO、NSF 与 ESL, Inc. 继续资助伯克利数据库研究；（4）POSTGRES 在伯克利 Evans Hall 与 CSRG 共享 VAX 硬件；POSTGRES 实现始于 1986 年，首个演示系统 1987 年可运行，Version 1 于 1989 年 6 月向少量外部用户发布，Version 2 于 1990 年 6 月发布（重写规则系统），Version 3 于 1991 年发布（多存储管理器支持），最终以 Version 4.2 结束伯克利 POSTGRES 项目

  | POSTGRES 版本时间线 | 时间 | 内容 |

| Version 3 | **1991 年** | 多存储管理器支持 |

  | POSTGRES 启动背景要素 | 内容 |
| ------------------- | -- |

## 60.2.2 Postgres 对象关系模型的创新

  **要点**：Postgres 对象关系模型的创新包括：（1）支持用户定义类型（User-Defined Types，UDT）与用户定义函数（User-Defined Functions，UDF）；（2）支持复杂数据类型（数组、集合、时间序列）；（3）支持时间旅行查询（Time Travel Query，基于 Postgres 的时间戳追加机制实现，MVCC 为 PostgreSQL 后续版本引入）；（4）支持规则系统（Rule System）用于视图与触发器；（5）这些创新使 Postgres 成为对象关系数据库的先驱，影响后续 PostgreSQL、IBM DB2、Oracle 等系统

  | Postgres 创新特性 | 内容 | 描述文献 |
| --------------- | -- | ------ |
| UDT/UDF | 用户定义类型与用户定义函数 | Stonebraker 与 Rowe **1986 年** SIGMOD 论文“The Design of POSTGRES” |
| 复杂数据类型 | 数组、集合、时间序列 | — |
| 时间旅行查询 | 元组时间戳追加（POSTGRES 1986-1993 版本） | — |
| 规则系统 | 用于视图与触发器 | Stonebraker **1987 年** 论文“The POSTGRES Rules System” |

  | 时间旅行查询 vs MVCC | 机制 | 引入版本 |
| ------------------ | -- | ------ |
| 时间旅行查询 | 元组时间戳追加 | POSTGRES 1986-1993 版本 |
| MVCC | 多版本并发控制 | PostgreSQL **1999 年 6.5 版本** |

  | 受 Postgres 影响的系统 | 系统 | 影响内容 |
| -------------------- | -- | ------ |
| 1 | PostgreSQL | 直接继承 |
| 2 | IBM DB2 | 对象关系模型 |
| 3 | Oracle | 对象关系模型 |

**史料**：Postgres UDT/UDF 文档、Postgres 时间旅行查询档案、Postgres 规则系统文档、Stonebraker 1986 POSTGRES 论文 ［B］
  
**史观**：第 9 条经验优先——Postgres 的对象关系模型实践（1986）先于形式化的对象关系数据库理论（1990 年代），实践先于理论
  
**辨析**：Postgres UDT/UDF 的具体设计——Stonebraker 与 Rowe 1986 年 SIGMOD 论文“The Design of POSTGRES”详细描述；时间旅行查询的实现机制——Postgres 通过元组时间戳追加实现时间旅行查询（POSTGRES 1986-1993 版本），MVCC 由 PostgreSQL 1999 年 6.5 版本引入（原大纲辨析正确）；规则系统——Stonebraker 1987 年论文“The POSTGRES Rules System”描述

## 60.2.4 PostgreSQL BSD 许可证的延续与效应

  **要点**：PostgreSQL BSD 许可证的延续与影响：（1）PostgreSQL 沿用伯克利的 BSD 许可证，允许商业使用与闭源衍生；（2）BSD 许可证使 PostgreSQL 被 EnterpriseDB（2005 年创立）等公司商业化；（3）BSD 许可证使 PostgreSQL 与 MySQL（GPL）形成许可证对比，PostgreSQL 的宽松许可证鼓励商业采用；（4）PostgreSQL 的 BSD 许可证延续反映伯克利 Ingres/Postgres 遗产的开源延续

  | PostgreSQL vs MySQL 许可证对比 | PostgreSQL | MySQL |
| ---------------------------- | -------- | --- |
| 许可证类型 | BSD 变体（宽松） | GPLv2 + 商业双许可证 |
| 闭源衍生 | 允许 | 不允许（须购买商业许可或开源） |
| 商业采用 | 宽松许可证鼓励商业采用 | 强制回馈或购买商业许可 |
| 商业支持公司 | EnterpriseDB（**2005 年** 创立）等 | MySQL AB / Sun / Oracle |

  | EnterpriseDB 创始人修正 | 原表述 | 修正后 |
| --------------------- | ---- | ---- |
| 创办人 | ~~Ed Boyajian~~ | Astyanax Kanavis、Andrzej Krawczyk、Edward Behrend 等（Boyajian 实为 **2008 年** 加入的 CEO 而非创始人） |

  | PostgreSQL License 法律性质 | 内容 |
| ------------------------- | -- |
| 类型 | BSD 许可证变体 |
| 类似 | BSD 2-Clause |
| 保留 | 版权声明与免责条款 |
| 来源 | postgresql.org/about/licence/ |

**史料**：PostgreSQL BSD 许可证原文、EnterpriseDB 2005 创立档案、PostgreSQL/MySQL 许可证对比文档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档与公告〕
  
**史观**：第 2 条形式主义与第 4 条分离与聚合——PostgreSQL 的 BSD 许可证（宽松）与 MySQL 的 GPL（copyleft）在形式上分离，但在开源数据库生态上聚合，分离与聚合的辩证关系塑造开源数据库谱系
  
**辨析**：PostgreSQL BSD 许可证条款——PostgreSQL License 是 BSD 许可证的变体，与 BSD 2-Clause 类似但保留了版权声明与免责条款（postgresql.org/about/licence/）；EnterpriseDB 2005 年由 Astyanax Kanavis、Andrzej Krawczyk、Edward Behrend 等创立以提供 PostgreSQL 商业支持（多源一致，部分中文来源误记创办人为“Ed Boyajian”，Boyajian 实为 2008 年加入的 CEO 而非创始人）；PostgreSQL/MySQL 许可证对比——PostgreSQL 采用 BSD 变体（宽松、允许闭源衍生），MySQL 采用 GPLv2 + 商业双许可证（强制回馈或购买商业许可），此许可证差异塑造二者商业生态
  
**文献**：PostgreSQL License 原文（postgresql.org/about/licence/）；EnterpriseDB 公司历史档案；MySQL 商业许可证文档 ［B］

**史学意义**：从莫斯科发回的移植成功报告同时见证了伯克利数据库血统经 386BSD 传递到 PC 平台与全球边缘节点，1990 年代初自由 BSD 社区的跨国动员在这封邮件里具象化。

**要点**：

- Josh Berkus 自述其任 PostgreSQL 核心团队七人小组成员，该团队决定 PostgreSQL 的版本发布时机；Sun Microsystems 决定支持 PostgreSQL 项目并在 Solaris 平台销售支持服务后聘请其为 PostgreSQL 战略负责人。其此前履历包括 OpenOffice.org 项目负责人（为加入 PostgreSQL 核心团队而辞任）、Software in the Public Interest 董事会成员与 O'Reilly 开源大会委员会成员。（BSDTalk EP110，[49.23-95.41, 742.27-801.59]，L1）
- 关于项目接续史的当事人叙述：PostgreSQL 前身 Postgres 于 1986 年在伯克利加州大学启动，作为大学项目运行十年后校方 CS 系失去兴趣；此时校友与互联网社区中的职业使用者已将其投入生产，伯克利决定放手时，包括一位 FreeBSD 操作系统主要贡献者 Marc Fournier 在内的开发者群体将其改造为真正的开源项目并上线 CVS——1995 年开始、1996 年完成，社区遂以 1996 年 7 月 8 日为开源项目诞生日；十周年时在多伦多举办逾百人开发者峰会。 [存疑脚注] 转写作“Mark Fournier”，按 FreeBSD 核心团队与 PostgreSQL 基础设施史应为 Marc G. Fournier，名字拼写以转写存疑待核（BSDTalk EP110，[128.22-221.07]，L1）
- Berkus 的技术栈迁移史完整呈现了 1990 年代小企业咨询市场从专有软件向开源的转换动因：其自立门户服务小企业与非营利客户后，发现专有技术许可费与 MSDN 订阅侵蚀利润，而微软于 1997 至 1998 年停止补贴转向盈利，SQL Server 起步价从约 700 美元跃至 3000 美元；同时 SQL Server 加 COM+ 方案每两三周随机故障，迫使其每两周上门维护；MySQL 当时仍是共享软件且其 2.x 版不支持表连接，无法满足其 SQL 专家标准；转投 PostgreSQL 后，社区对其 SQL 合规性质疑的开放接纳与 MSDN 论坛的封禁文化形成鲜明对照，首周即融入项目——社区文化本身成为技术选型的决定因素。（BSDTalk EP110，[529.11-741.71]，L1）
- Berkus 对数据库生态的定位划分：PostgreSQL 居高端，面向需支撑海量连接、TB 级数据与长事务、以替换 Oracle、DB2、SQL Server 2005 为目标的场景；Derby 与 Sleepy Cat（即 Berkeley DB）一类居嵌入式端；MySQL 居中，规模与扩展性占优但不及 PostgreSQL，对用户数据库知识要求也更低。PostgreSQL 的比较优势包括 BSD 许可证允许与专有软硬件捆绑（其最流行的分发方式之一）、活跃企业用户转化为社区成员从而获得对软件未来的归属感与控制感、独立安全评级（Database Hackers Handbook 中高于 Oracle 与 DB2）、提交即持久的可靠性保证，以及源自对象关系设计的可编程数据库对象——PostGIS 借此成为全球第二大 GIS 数据库系统（仅次于 NavTeq），基因组学领域亦出现以专用数据类型扩展 PostgreSQL 的项目。 [存疑脚注] 基因组项目名转写作“BlastGres”，确切名称待核；NavTeq 为转写原貌，当作 Navteq（BSDTalk EP110，[802.59-1047.13, 884.21-927.73]，L1）
- Bruce Momjian 回顾 Postgres 起点：1996 年代码离开伯克利时是一堆能力出色、前途可期但缺陷众多、学术导向的代码，他是启动基于互联网的协作开发的人之一，前四年以志愿者身份工作，此后受雇于从事 Postgres 业务的公司；近十年间项目从利基爱好成长为获得 Sun 及日美大型企业采用的主流数据库，.org 顶级域的 DNS 数据即由 Postgres 承载，美国国家气象局、大型金融公司与 Ameritrade 亦在使用；截至访谈时 8.1.2 为当前版本，8.2 开发重点转向数据仓库与高可扩展场景。（BSDTalk EP15，[356.75-628.76]，L1）
- Momjian 提出 BSD 许可证的企业友好论证：BSD 许可证没有任何附加条件或被认为没有附加条件，省去企业对开源许可证的律师审查恐惧，向内部推销极为容易；其结果是培育出一批以 Postgres 为业务的公司，出售商业版本、附加组件与支持服务；他把社区与企业的分工讲得直白——社区擅长开发与发版，但没有销售员、没有技术支持电话、没有上门做性能调优的人，而这些恰是许多组织需要的，BSD 许可证使大量公司得以全力支撑 Postgres 用户。（BSDTalk EP15，[467.44-570.88]，L1）
- Windows 原生 port 曾在 Postgres 社区内部引发真实斗争：是否要 Windows port、同一代码库同时容纳 Windows 与 Unix 的代价有多大；Momjian 花约两年与社区成员完成移植，结果是代码经模块化反而比开工前更干净；面对为何推广专有平台的质疑，他的回答是必须先在对方平台上展示开源的能力才能促成向开放操作系统的迁移，而 Windows 市场的实际定位是销售演示与开发者笔记本测试，并非大型服务器。（BSDTalk EP15，[806.95-901.72]，L1）
- 跨大版本就地升级是 Postgres 的结构性困境：子事务、两阶段提交等特性不断改变磁盘格式，一旦格式改变就必须读入并重写数据库的每一页，成本几乎等同转储重灌；Momjian 称这是项目前进太快带来的诅咒——技术上能写就地升级脚本，但每次核对跨版本变化后都显得不切实际；社区现行推荐是 Slony 复制方案，让新旧两版数据库并行运行，切换服务器即完成升级，停机仅一次重启，项目仍在零停机与转储重灌两类用户需求之间权衡是否值得再造第三条升级路径。（BSDTalk EP15，[923.85-1089.19]，L1）

**史观**：

- 总纲13 法律与道德是利益分配：Berkus 描述的商业生态形态展示了宽松许可证下的共生结构：EnterpriseDB（Oracle 兼容函数的专有分支）、Greenplum（基于 PostgreSQL 的专有数据仓库）、Continuent（Sequoia 之上的 UniCluster）、PowerGres（专有分支）等商业衍生品并存，而 PGCon 对商业分支议题持有限开放；与此同时，公开而活跃地使用 PostgreSQL 的公司被吸纳为社区成员而非保持纯商业客户关系。许可证允许专有汲取，社区则以参与感回收忠诚——法律框架在此直接塑造了商业与社区的博弈方式。 [存疑脚注] “Powergrass”转写原貌，应为日本厂商的 PostgreSQL 专有分支 PowerGres，待核（BSDTalk EP110，[391.47-493.45, 884.21-927.73]，L1）
- 总纲5 没有必然性，只有偶然性：Momjian 自述约 1991 年起接触开源，并把参与 Postgres 归于纯粹的好运——是运气让他撞上这个特定项目；一个此后影响大量企业与机构的基础设施项目，其核心贡献者的加入并无必然路径，只系于个人轨迹中的偶然相遇。（BSDTalk EP15，[405.10-413.29]，L1）
- 总纲6 和解优于斗争：Windows port 之争的化解方式不是阵营间决出胜负，而是把改造成本内部化：移植过程中对代码库大规模模块化，使 Windows 与 Unix 在同一代码基中共存且质量反而提升，同时以先在对方平台证明开源价值的说服逻辑替代对专有系统的拒斥，构成一次以和解与互相渗透收场的路线分歧。（BSDTalk EP15，[820.31-901.72]，L1）
