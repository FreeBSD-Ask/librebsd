### Internet 诞生与 BSD 时期的当事人采访（1978-1992 时期当事人）

#### 采访 1：Sam Leffler

**字段 1 采访元数据**

- 受访者：Sam Leffler，时任加州大学伯克利分校 CSRG 核心成员，4.2BSD 网络栈主要开发者
- 采访者：ACM Queue 编辑 Gary Powers
- 采访时间：2004-10（ACM Queue 第 2 卷第 8 期发布）
- 采访形式：期刊访谈
- 原始来源：Powers, Gary, “A Conversation with Sam Leffler”, ACM Queue, Vol. 2, No. 8, November 2004。**<https://queue.acm.org/detail.cfm?id=1039535>**
- 存档信息：ACM Queue 文章页经联网检索确认真实存在（访问日期 2026-07-24），未失效

**字段 2 采访摘要**

Leffler 在 ACM Queue 访谈中回顾了 4.2BSD 网络栈如何成为 Internet 协议族的早期试验床，详述了 CSRG 与 DARPA Internet 项目（含 Jon Postel、Paul Mockapetris、Mike Muuss 等人）的协作。访谈涉及 BIND（Berkeley Internet Name Domain）的设计背景、4.2BSD socket API 对 Internet 应用层的影响，以及 BSD 网络代码如何通过学术分发渠道传播到全球研究机构，成为早期 Internet 基础设施的事实标准。

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——据原文第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手。技术的发展使曾经需要数年完成的工作如今数日可成，但问题始终在于是否有人去做”，Leffler 实现 4.2BSD 网络栈、与 Jon Postel 等 DARPA Internet 项目协作，是“问题始终在于是否有人去做”在协议实现层面的具象——BSD 网络代码成为早期 Internet 基础设施的事实标准，不是规划出来的战略地位，而是有人愿意动手把 TCP/IP 写出来并随学术分发渠道扩散出去的结果。但据 14.1 节“决定世界的并非某个阶级，也不是什么经济”，此处“动手者”不可简化为“网络栈开发者”的固定身份——Leffler 作为 CSRG 核心成员实现网络栈，是主体性未被理论遮蔽的状态，与 Jon Postel、Paul Mockapetris 等人的“动手”形态是流变的（参见第 6 章 6.5 节“十年前的人和十年后的人，是两个人”）。
- 总纲 13“法律与道德是利益分配”——据原文第 25 章 总纲 13“任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”，DARPA 合同的法律结构使 BSD 网络代码得以学术分发——这不构成对 DARPA 的道德赞美，而是第 29 章 29.5 节“政治经济理论本身是政治经济斗争的产物。理论不是对现实的客观描述，而是权力斗争的工具”所述的利益分配：DARPA 合同条款是 DARPA IPTO 与 CSRG、BBN 等多方主体利益分配的法律形式，BSD 网络代码的学术分发权限由利益分配界定，而非由“开放”的道德标准界定。
- 总纲 20“历史地理塑造思想土壤”——据原文第 20 章 20.1 节“地理环境不直接决定思想，但地理环境所构成的政治经济条件制约着思想的生长土壤”，伯克利与 DARPA Internet 项目的地理与组织协作塑造了 BSD 网络栈——伯克利作为 Unix 文化中心与 DARPA 作为 Internet 项目资助方的地理与组织邻近性，构成了 BSD 网络栈的土壤。但 20.5 节“中心与边缘”提示：伯克利与 DARPA 在 1980 年代处于 Internet 研发的中心，而其他机构处于边缘，此中心-边缘关系塑造了 BSD 网络代码的传播形态——中心机构的研究得以扩散，而边缘机构的工作难以被记录。
- 总纲 5“没有必然性，只有偶然性”——据原文第 5 章 5.2 节“那种认为‘张三不上李四也会上’的观点，无视了世界上没有必然性只有偶然性这一事实”，BSD 网络代码成为早期 Internet 基础设施的事实标准是偶然条件交汇——若非 DARPA 在 1980 年代选择伯克利作为 Internet 协议试验床，若非 Leffler 愿意动手实现 TCP/IP，若非 CSRG 通过学术分发渠道扩散代码，BSD 网络栈不会以此时序与形态成为事实标准。但 5.3 节“记忆将许多偶然性认识为一种必然性，同时否定了这种偶然性的发生”提示：Leffler 2004 年的回忆可能已将 BSD 网络代码的扩散偶然转为必然，将“BSD 作为 Internet 基础设施”叙述为历史的合力方向。
- 总纲 3“不存在进步，只有权力再分配”——据原文第 25 章 总纲 3“技术演进不是从低级到高级的进步，而是形式主义的诡异曲线”，BSD 网络代码成为 Internet 事实标准并非“技术进步的胜利”，而是第 9 章 9.3 节“不存在绝对的发展。修仙小说设定古法强于今法存在逻辑悖论，但反过来说今法绝对强于古法同样存在问题”所述的形式主义权力再分配——TCP/IP 与其他协议（如 ISO/OSI）的竞争不是“先进”与“落后”的较量，而是形式主义的权力运作。BSD 网络代码的“事实标准”地位不是技术进步的奖赏，而是此权力再分配的具体产物。
- 总纲 19“解释学循环是历史认识的根本条件”——据原文第 25 章 总纲 19“前理解的差异使分歧不可避免。权力与知识在历史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使”，BSD 网络代码在 Internet 历史中的地位是权力与知识共谋的产物——什么被记录为“BSD 网络栈的贡献”，什么被遗忘为“BBN、Jon Postel 等其他主体的贡献”，本身就是权力行使。Leffler 作为网络栈主要开发者的视角，是此前理解下的重构。
- 总纲 9“经验优先”——据原文第 25 章 总纲 9“优先呈现质朴的事实与当事人的直接经验，而非套用复杂框架”，Leffler 作为 4.2BSD 网络栈主要开发者的当事人直接经验，优先于任何事后理论框架。但据第 2 章 2.3 节“记忆的东西从来都是不存在的——那天的偶然性都被转为了必然性，都是不存在的”，其 2004 年的回忆仍是一种形式主义化的重构——BSD 网络代码的扩散过程在回忆中可能已被定格为某种必然叙事，而当日动手实现的具体偶然已不可还原。

**自反性声明**：本释读本身也是一种形式主义化的重构，不声称是对项目统摄史观的客观正确解读。释读中“Leffler 实现 4.2BSD 网络栈是动手去做的具象”的判断本身也是一种形式主义化的工具理性归类，把 Leffler 主体性简化为“协议实现”维度，可能遮蔽其在与 DARPA Internet 项目协作中对协议设计方向的战略性取舍无法被“动手实现”涵盖；释读中“DARPA 合同法律结构使 BSD 网络代码学术分发”的判断本身也是一种形式主义化的法律决定论，把代码分发简化为合同条款的被动产物，可能遮蔽 CSRG 在合同执行中对分发渠道的主动拓展而非被动接受条款；释读中“伯克利与 DARPA 地理与组织协作塑造 BSD 网络栈”的判断本身也是一种形式主义化的地理决定论，把网络栈设计简化为地理邻近性的产物，可能遮蔽 Leffler 在 socket API 抽象层设计中对 UNIX 文件描述符模型的创造性移植而非地理塑造；释读中“BSD 网络代码成为事实标准是偶然条件交汇”的判断本身也参与偶然/必然二元的形式主义运作，可能遮蔽 DARPA IPTO 在 1980 年代初选定伯克利作为协议试验床的主动战略选择而非被动接受偶然；释读中“BSD 成为事实标准是形式主义权力再分配而非技术进步”的判断本身也是一种形式主义化的相对化运作，可能遮蔽 BSD 网络代码在端到端可靠性等可度量维度上相对 ISO/OSI 的实际技术优势；释读中“BSD 网络代码地位是权力与知识共谋的产物”的判断本身也是一种形式主义化的认识论还原论，把历史记录简化为权力运作，可能遮蔽 BBN、Jon Postel 等其他主体的贡献在公开 RFC 档案中实际可查而非被完全遗忘；释读中“Leffler 2004 年回忆仍是形式主义化的重构”的判断本身也是一种形式主义化的时间归因，可能遮蔽 Leffler 作为网络栈主要开发者对 socket API 设计取舍的原始记忆，欢迎被更自反的释读所超越（见 据原文第 27 章 27.2 节）。

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——据原文第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手。技术的发展使曾经需要数年完成的工作如今数日可成，但问题始终在于是否有人去做”，CSRG 网络代码通过学术分发渠道扩散到全球研究机构，是“问题始终在于是否有人去做”的长尾显现——socket API 的长期影响不是规划出来的战略布局，而是有人动手写出网络代码并随 BSD 一起分发出去后自然生出的后果。但据 14.1 节“决定世界的并非某个阶级，也不是什么经济”，此处“动手者”不可简化为“网络代码分发者”的固定身份——CSRG 成员通过学术分发渠道扩散代码，是主体性未被理论遮蔽的状态。

- 总纲 4“分离聚合是永恒规律”——据原文第 4 章 4.1 节“分离聚合是世界发展的规律。分久必合，合久必分，具有必然性”，BSD 网络代码作为聚合点，催生后续 Internet 治理的分离——BSD 网络代码聚合了 DARPA、CSRG、BBN 等多方主体的工作，而后续 IETF、IANA 等 Internet 治理机构的独立是从此聚合中分离出的新形态。但 4.2 节“否定后必然会再次产生，这是社会发展的根本动力”提示：Internet 治理的分离并非 BSD 网络代码的终结，而是通过此分离产生了新的网络治理形态。
- 总纲 11“商品是形式主义”——据原文第 25 章 总纲 11“技术市场的选择不是自然选择，而是形式主义的权力运作。劣币驱逐良币是普遍规律”，BSD 网络代码在 1990 年代商业互联网爆发中的奠基作用是形式主义的权力运作——这不构成对 BSD 的道德赞美，而是项目统摄史观对“商品化”的中性描述。BSD 网络代码作为“事实标准”被商业互联网采纳，不是“技术优秀”的自然选择，而是形式主义的市场权力运作。
- 总纲 3“不存在进步，只有权力再分配”——据原文第 25 章 总纲 3“技术演进不是从低级到高级的进步，而是形式主义的诡异曲线”，socket API 的长期影响并非“网络编程进步”，而是第 9 章 9.3 节“不存在绝对的发展。修仙小说设定古法强于今法存在逻辑悖论，但反过来说今法绝对强于古法同样存在问题”所述的形式主义演化——socket API 在 1980 年代的设计权衡，在现代网络编程中既是基础也是技术债务，不能简单视为“进步”。
- 总纲 18“时间是一种形式主义”——据原文第 25 章 总纲 18“等待、记忆、历史的欣赏都具有时间性。沥青滴落般的时间尺度要求史家具备宏观的时间自觉”，麦库西克 2018 年回望 1980 年代 BSD 网络代码的奠基作用，是沥青滴落式的时间尺度——第 27 章 27.4 节“和解往往取决于等待，或者说，取决于时间。这世间种种的等待，就好像沥青在滴落”提示：socket API 数十年的延续是 BSD 长期主义的体现，但此长期主义非苦难哲学（见总纲 14）。
- 总纲 9“经验优先”——据原文第 25 章 总纲 9“优先呈现质朴的事实与当事人的直接经验，而非套用复杂框架”，麦库西克作为 CSRG 核心成员的当事人直接经验，优先于任何事后理论框架。但据第 2 章 2.3 节“记忆的东西从来都是不存在的——那天的偶然性都被转为了必然性，都是不存在的”，其 2018 年的回忆仍是一种形式主义化的重构——BSD 网络代码的奠基作用在回忆中可能已被定格为某种必然叙事，而当日动手分发代码的具体偶然已不可还原。

**自反性声明**：本释读本身也是一种形式主义化的重构，不声称是对项目统摄史观的客观正确解读。释读中“CSRG 网络代码通过学术分发渠道扩散是动手去做的长尾显现”的判断本身也是一种形式主义化的工具理性归类，把代码扩散简化为“动手分发”的延伸投射，可能遮蔽 BSD 许可证条款对分发权限的法律支撑无法被“动手”涵盖；释读中“BSD 网络代码具体实现过时但 socket API 延续”的判断本身也参与过时/延续二元对立的形式主义运作，可能遮蔽 socket API 部分语义（如阻塞 I/O 模型）在现代异步 I/O 范式下实际失效而非完全延续；释读中“BSD 网络代码作为聚合点催生 Internet 治理分离”的判断本身也是一种形式主义化的循环论归因，把治理演化简化为“聚合—分离”的抽象循环，可能遮蔽 IETF 独立化中 Vint Cerf 等主体的主动组织建构而非抽象的“分离”；释读中“BSD 网络代码在商业互联网爆发中的奠基作用是形式主义权力运作”的判断本身也是一种形式主义化的市场还原论，把商业采纳简化为权力运作，可能遮蔽 BSD 网络代码在协议栈完整性等可度量维度上相对商业专有方案的实际工程优势；释读中“socket API 长期影响是形式主义演化而非网络编程进步”的判断本身也是一种形式主义化的相对化运作，可能遮蔽 socket API 在抽象层统一性上相对早期 per-protocol 接口的可度量进步；释读中“麦库西克 2018 年回望是沥青滴落式的时间尺度”的判断本身也是一种形式主义化的时间浪漫化，可能遮蔽 socket API 数十年延续更源于 BSD 许可证的传播学优势而非抽象的时间累积；释读中“麦库西克 2018 年回忆仍是形式主义化的重构”的判断本身也是一种形式主义化的时间归因，可能遮蔽麦库西克作为长期参与者对 socket API 演化细节的累积性认知，欢迎被更自反的释读所超越（见 据原文第 27 章 27.2 节）。

- ISC 为美国 501(c)(3) 非营利公益组织，维护 BIND、DHCP 及遗留产品 INN，约 40 名员工且半数远程办公，收入主要来自支持合同；Losher 任高级运维架构师，自嘲职责是“让所有人能在家里工作”。F 根服务器实际运行基本是现货软件：99.9% 情况下跑官方 FTP 站的 stock BIND，系统以 FreeBSD 为主、杂有少量 Linux 与 Windows，防火墙以 dummynet 应对 DDoS。（BSDTalk EP206，[45.36-400.88]，L1）
- 根服务器负载史：早期 F 根托管 com、net、org 及军方 mil 等大型区域，须用 DEC Alpha 5U 大机并装载 8GB 内存才能容纳 zone；Verisign 将 com/net 迁往 gTLD 服务器、arpa 区域外移后，根服务器专注于根区域本身。如今 F 根分布式部署逾 50 个节点、以 1U 商品机 4GB 内存即为过剩（签名后的根 zone 不足 300K），十三家根运营者之间刻意保持操作系统、硬件与名字服务器软件的多样性。（BSDTalk EP206，[527.92-682.16]，L1）
- DNSSEC 与 IPv6：根区域签名于此前一年夏天完成，从根运营者视角切换“无可挑剔”，曾担忧的“响应增大三至四倍、穿透不过防火墙”并未成真；ISC 自有区域已签名五年，com/net/org 与主要 ccTLD 已陆续签名，下一步目标是把 DNSSEC 验证能力推进到基础操作系统层而非仅浏览器。ISC 自 2003 年起内部双栈运行 IPv4/IPv6，参与 World IPv6 Day 并向项目提供 IPv6 隧道。（BSDTalk EP206，[682.16-856.78]，L1）
- 商业化与公益的边界：因根服务基础设施属公益免费资源，ISC 长期拒绝企业“帮忙做 secondary”的请求；此后另建由多家 tier-1 提供商组成的全球网络（ISC 运营设备而非自有网络）推出商业 secondary DNS 服务，把 F 根多年运维经验变现。F 根部署扩展则面向发展中世界（斐济、内罗毕、达卡等），并正将平台缩减得更经济、便于运输。（BSDTalk EP206，[856.78-948.80]，L1）
- 主持人梳理 Gopher 脉络：1991 年明尼苏达大学为建设校园范围信息系统而发布，以菜单导航与匿名访问取代此前 Telnet 登录、逐字键入完整地址的体验；1992 年 Veronica 检索引擎问世，1993 年 RFC 1436 将协议定型；它与万维网几乎同时起步（首个 WWW 网站 1990 年），1993 年 CERN 宣布 WWW 自由开放后两者并跑，1994 年 WWW 借 Mosaic 浏览器起跑超越。（BSDTalk EP264，[189.92-384.06]，L2）
- 胜负手在许可与生态而非功能：明尼苏达大学宣布其 Gopher 服务器实现不对商用免费（对大学与其他用户仍免费），被认为打消了部分采用者热情、部分助推了 WWW 增长；该校 1995 年停止积极开发，迟至 2000 年才以 GNU GPL 开源。浏览器阵营则在 IE7 与 Firefox 4 前后以缩减攻击面、精简代码为由移除 Gopher 支持，完成制度性淘汰。（BSDTalk EP264，[254.98-294.54]，L2）
- 转载的 Gopher 开发者访谈给出协议诞生的内部视角：校园委员会的集中式设计“无法编码”被搁置半年，Farhad 另行设计分布式服务器协议；因仅有寥寥数台 NeXT，借其 Digital Librarian 全文检索实现索引与服务的机器分离；协议极简使人人可写服务器与客户端；发布方式是把软件放上 FTP 服务器任人取用，开发者自嘲为“开源故事的翻版”；书签与主页概念由此首创，Gopher+ 补入受图书馆员启发的元数据桶与多带宽替代视图，Veronica 由内华达的 Steve Foster 遍历整个 Gopher 树建成，晚期还实验了 3D 虚拟 Gopher 空间。（BSDTalk EP264，[950.92-1320.18]，L1）
- 主持人实操记录：在 OpenBSD 5.9 i386 上以 pkg_add 安装 BSD 许可的 Gophernicus 服务器（SDF 与 Devious 均采用），经 inetd 启动，系统为其创建专用 _gophernicus 用户而非复用 nobody（延续 OpenBSD 安全惯例），自 /var/gopher 提供服务、拒绝 world-writable 文件、支持虚拟主机与用户 Gopher 空间，部署前须保证主机名可解析；幸存生态还包括 Floodgap 的 Web 代理与浏览器插件、Veronica 2 与 pointloma 的 Veronica 索引。（BSDTalk EP264，[551.30-845.70]，L1）

**史观**：

- 总纲3 不存在进步，只有权力再分配：主持人观察到 IPv6 进入机构议程的动力并非协议技术优势，而是微软市场份额带来的事实标准效应——LINUX、BSD 与苹果系统早已支持 IPv6 却长期无人问津，微软一旦默认启用便使各组织被迫跟进；协议采纳的节奏实为市场权力结构的再分配结果。（BSDTalk EP119，[182.08-205.88]，L1）
- 总纲8 本体论上各方平等：受访者以 DNS 为例指出协议核心简单而细节复杂：三十年历史、实现选择、大量边角案例与对端实现的多样性共同构成工程难度，单一实现垄断与实现多样性之间的张力决定互联网基础设施的脆弱或稳健。（BSDTalk EP176，[702.5-738.2]，L1）
- 总纲13 法律与道德是利益分配：BSD 许可证允许厂商未经告知地吸收代码并被受访者视为有意为之的交换：以放弃署名约束换取标准 DNS 实现渗入专有产品，法律形式的选择直接服务于技术标准的利益分配。（BSDTalk EP176，[473.7-498.7]，L1）
- 总纲8 本体论上各方平等：Losher 明言十三家根运营者间须维持操作系统、硬件与名字服务器软件的多样性——没有人主张 FreeBSD 或 BIND 是唯一正确选择，ISC 亦同时杂用 Linux 与 Windows；多样性被制度化为互联网基础设施的抗脆弱策略，而非某一方的正统性叙事。（BSDTalk EP206，[458.54-505.52]，L1）
- 总纲13 法律与道德是利益分配：Losher 解释 ISC 许可证的价值在于给商业组织以确定性——集成后不强制开放修改源码，回馈与否“留给最终用户决定，不是自上而下强制”；许可证在此并非道德宣言而是利益分配装置，它决定了 Sun、HP、IBM 等厂商是否愿意资助 BIND 9。（BSDTalk EP206，[301.24-341.92]，L1）
- 总纲4 分离聚合是永恒规律：Gopher 开发者自我总结的规律是“拥抱并扩展既有系统”：Gopher 建立在 FTP 与 Usenet 内容之上，而万维网起步时毫无内容，正是坐在 Gopher 内容与简单协议之上才得以起飞——分布式信息系统的更替不是凭空创新，而是对既有内容与协议的吸收再扩展，呈现接续而非断裂的循环。（BSDTalk EP264，[1344.12-1378.94]，L1）
- 总纲3 不存在进步，只有权力再分配：Gopher 与万维网的胜负并非纯技术优劣之辨：明尼苏达大学对商用收费的许可宣示与 CERN 彻底开放的对照，把开发者社区与内容生态推向 WWW；浏览器厂商随后以“缩减攻击面”为由移除 Gopher 支持，完成制度性淘汰——许可安排与机构权力而非协议本身决定了协议的命运。（BSDTalk EP264，[254.98-531.92]，L2）
