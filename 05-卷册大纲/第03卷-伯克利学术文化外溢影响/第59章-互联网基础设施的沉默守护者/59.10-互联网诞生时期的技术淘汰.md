# 59.10 互联网诞生时期的技术淘汰——delivermail→Sendmail、NCP 协议 →TCP/IP 协议栈切换、NCSA httpd→Apache 补丁集演化与 BIND/Sendmail 安全事件后的替代方案兴起（1980-1995）

## 59.10.1 delivermail → Sendmail 邮件传输代理演化（1980-1983）

  **要点**：4.0BSD/4.1BSD 时期（1980-1981）Eric Allman（埃里克·奥尔曼） 在伯克利 INGRES 项目中开发 delivermail 作为 BSD 早期邮件传输代理（MTA，Mail Transfer Agent），delivermail 使用简单配置文件，通过 ARPANET 的 FTP 邮件与 MTP 协议（RFC 780，1981，Mail Transfer Protocol）以及 uucp（Unix-to-Unix Copy Protocol）转发邮件，但 delivermail 缺乏灵活的地址重写与路由机制，无法适应 ARPANET 向互联网转型期的复杂邮件路由需求；1981-1982 年 Allman 在 4.1cBSD 时期重写 delivermail 为 Sendmail，引入 M4 宏配置系统（`sendmail.cf` 配置文件）、灵活的地址重写规则（rewriting rules）、SMTP 协议支持（RFC 821，1982），Sendmail 作为 4.2BSD（1983.8）的默认 MTA 发布；delivermail 在 4.2BSD 中被 “淘汰” 为 Sendmail，后续 Sendmail 长期主导互联网邮件传输市场，1990 年代后期 Sendmail 因 M4 配置复杂性与安全漏洞频发（如 1988 年 Morris 蠕虫利用 sendmail DEBUG 后门、2003 年 sendmail 远程溢出漏洞）面临 Postfix（Wietse Venema 1998 年发布，IBM Public License，原名 VMailer）、qmail（Daniel J. Bernstein 1995 年发布，自定义免费许可 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）、Exim（Philip Hazel 1995 年发布，GPL）等替代品的挑战，但 Sendmail 在 BSD 与 Linux 邮件服务器市场仍保留一定份额

  | delivermail → Sendmail 演化时间线 | 时间 | 事件 |
| ------------------------------- | -- | -- |
| delivermail 开发 | **1979 年** | Eric Allman 在伯克利 INGRES 项目中开发 |
| delivermail 分发 | **1980-1981 年** | 随 4.0BSD/4.1BSD 分发 |

| Sendmail 默认 MTA | **1983 年 8 月** | 随 4.2BSD 作为默认 MTA 发布，delivermail 被淘汰 |

**史观**：第 9 条经验优先——Sendmail 是工程实践驱动而非邮件传输理论先行，M4 宏配置系统是实践中逐步形成的灵活性方案；第 2 条形式主义——Sendmail 的 M4 配置复杂性膨胀为安全漏洞源头，形式便利膨胀为安全风险
  
**辨析**：delivermail 与 Sendmail 的版本关系——delivermail 于 1979 年 INGRES 项目中开发，随 4.0BSD（1980）/4.1BSD（1981）分发；Sendmail 在 4.1cBSD 开发期间（1981-1982）重写，4.2BSD（1983.8）是 Sendmail 首次作为默认 MTA 的正式发布版本，须区分 “开发期替代” 与 “默认发布”；Sendmail 在 BSD 中作为默认 MTA 的具体版本须以 4.2BSD Release Notes 为准；Postfix/qmail/Exim 替代 Sendmail 是 1990 年代后期演化，须区分 “1980-1990 年代 Sendmail 主导” 与 “1990 年代后期替代品兴起”

## 59.10.2 ARPANET NCP 协议 → TCP/IP 协议栈切换（1983.1.1 “Flag Day”）

  **要点**：ARPANET 1969 年建立至 1983 年前使用 NCP（Network Control Program）协议作为网络通信协议，NCP 设计于 1970 年代初期，缺乏可靠的端到端可靠性保证与跨网络互联能力；1974 年 5 月 Vinton Cerf 与 Robert Kahn 在 IEEE Transactions on Communications 发表 “A Protocol for Packet Network Intercommunication” 论文提出 TCP 概念，1981 年 9 月 RFC 791（IP）与 RFC 793（TCP）标准化，1981 年 11 月 RFC 801（NCP/TCP Transition Plan）规划 ARPANET 从 NCP 向 TCP/IP 切换；1983 年 1 月 1 日 ARPANET 正式从 NCP 切换到 TCP/IP（即 “Flag Day”），NCP 协议在 ARPANET 中被 “淘汰” 为 TCP/IP，4.2BSD（1983.8）作为首个集成完整 TCP/IP 协议栈的 BSD 版本，成为互联网协议的事实参考实现；BBN 的 Rob Gurwitz 于 1981-1982 年开发的 TCP/IP 实现集成入 4.1a/4.1cBSD 测试版本，在 4.2BSD 中经 Bill Joy 与 Sam Leffler 重写优化后成为 UCB TCP/IP，4.2BSD TCP/IP 性能优于 BBN 原始版本且代码更简洁；NCP 协议在 ARPANET 中于 1983 年 Flag Day 后被正式弃用，TCP/IP 成为互联网标准协议持续至今

  | ARPANET NCP → TCP/IP 切换时间线 | 时间 | 事件 |
| ----------------------------- | -- | -- |
| ARPANET 建立 | **1969 年** | 使用 NCP（Network Control Program）协议 |
| NCP 设计 | 1970 年代初期 | 缺乏可靠的端到端可靠性保证与跨网络互联能力 |
| TCP 概念提出 | **1974 年 5 月** | Vinton Cerf 与 Robert Kahn 在 IEEE Transactions on Communications 发表 “A Protocol for Packet Network Intercommunication”（Vol. COM-22 No.5，pp.627-641） |
| RFC 791（IP）标准化 | **1981 年 9 月** | — |
| RFC 793（TCP）标准化 | **1981 年 9 月** | — |
| RFC 801 切换规划 | **1981 年 11 月** | NCP/TCP Transition Plan |
| ARPANET Flag Day | **1983 年 1 月 1 日** | ARPANET 正式从 NCP 切换到 TCP/IP，NCP 被淘汰 |
| 4.2BSD 发布 | **1983 年 8 月** | 首个集成完整 TCP/IP 协议栈的 BSD 版本 |

  | BBN TCP/IP 与 UCB TCP/IP 对比 | 内容 |
| --------------------------- | -- |
| BBN 原始版本 | Rob Gurwitz 于 **1981-1982 年** 开发，集成入 4.1a/4.1cBSD 测试版本 |
| UCB 重写版本 | Bill Joy 与 Sam Leffler 重写优化 |
| 性能对比 | 4.2BSD TCP/IP 性能优于 BBN 原始版本且代码更简洁 |
| 集成版本 | 4.2BSD（**1983.8**）以 UCB TCP/IP 替代 BBN TCP/IP |

  | Cerf/Kahn 1974 论文出处 | 内容 |
| --------------------- | -- |

| 卷期 | Vol. COM-22 No.5 |

**史料**：ARPANET NCP 协议文档（1970 年代）；Cerf, V. & Kahn, R. (1974) “A Protocol for Packet Network Intercommunication” IEEE Transactions on Communications Vol. COM-22 No.5 May 1974 pp.627-641；RFC 791（IP，1981 年 9 月）；RFC 793（TCP，1981 年 9 月）；RFC 801（NCP/TCP Transition Plan，1981 年 11 月）；ARPANET 1983.1.1 Flag Day 公告；4.1a/4.1cBSD BBN/Gurwitz TCP/IP 源代码；4.2BSD UCB TCP/IP 源代码 ［A］
  
**史观**：第 4 条分离与聚合——TCP/IP 将网络协议分层分离（IP 网络层与 TCP 传输层），同时聚合为可跨网络互联的协议栈，分离与聚合辩证统一；第 5 条偶然性——ARPANET 1983.1.1 Flag Day 是偶然选择的转换日期，但此偶然标志互联网正式诞生
  
**辨析**：NCP 协议被 “淘汰” 指 ARPANET 主线协议迁移，部分内部网络在 1983 年后仍短暂使用 NCP，须区分 “ARPANET 主线迁移” 与 “内部网络残留”；BBN TCP/IP 被淘汰为 UCB TCP/IP 的具体版本须以 4.2BSD Release Notes 为准，须区分 “BBN TCP/IP 在 4.1BSD 中作为默认” 与 “4.2BSD 中 UCB TCP/IP 替代”；ARPANET Flag Day 的具体时间（1983.1.1）须以 ARPANET 官方公告为准

## 59.10.3 NCSA httpd → Apache 补丁集演化（1993-1995）

  **要点**：1991 年 Tim Berners-Lee 在 CERN 发布万维网（World Wide Web），1993 年 Rob McCool 在伊利诺伊大学 NCSA（National Center for Supercomputing Applications）开发 NCSA httpd 0.1 作为万维网服务器；NCSA httpd 基于 BSD 套接字 API 与 HTTP/0.9 协议（1991），是早期万维网主流服务器；1994 年中期 McCool 离开 NCSA 加入 Netscape，NCSA httpd 开发停滞，社区补丁积压，Brian Behlendorf（布莱恩·贝伦多夫） 等社区成员组织 “NCSA httpd 补丁集” 维护项目；1995 年 2 月 Apache httpd 0.6.2 发布（基于 NCSA httpd 1.3 补丁集，名称 “a patchy server” 双关），Apache 1.0（1995.12）正式独立于 NCSA httpd；NCSA httpd 在 1995 年后被 “淘汰” 为 Apache httpd，Apache 长期主导互联网 Web 服务器市场（1996 年起超越 NCSA httpd，2000 年代占 Web 服务器市场约 60% 份额）；Apache httpd 后被 Nginx（Igor Sysoev 2004 年发布，BSD 许可证）与 lighttpd（Jan Kneschke 2003 年发布，BSD 许可证）等替代品部分挑战，但 Apache 在 BSD 与 Linux Web 服务器市场仍占重要份额

  | NCSA httpd → Apache 演化时间线 | 时间 | 事件 |
| ---------------------------- | -- | -- |
| 万维网发布 | **1991 年** | Tim Berners-Lee 在 CERN 发布万维网 |
| NCSA httpd 0.1 | **1993 年** | Rob McCool 在伊利诺伊大学 NCSA 开发 |
| McCool 离开 NCSA | **1994 年中期** | 加入 Netscape，NCSA httpd 开发停滞 |
| 社区补丁集 | 1994-1995 年 | Brian Behlendorf 等组织 “NCSA httpd 补丁集” 维护 |
| Apache httpd 0.6.2 | **1995 年 2 月** | 基于 NCSA httpd 1.3 补丁集，“a patchy server” 双关 |
| Apache 1.0 | **1995 年 12 月** | 正式独立于 NCSA httpd |
| Apache 超越 NCSA httpd | **1996 年起** | 主导 Web 服务器市场 |
| Apache 市场份额 | 2000 年代 | 约 60% 份额 |

  | NCSA httpd 技术基础 | 内容 |
| ----------------- | -- |
| 套接字 API | BSD 套接字 API |
| 协议 | HTTP/0.9（**1991 年**） |
| 历史地位 | 早期万维网主流服务器 |

  | Apache 替代品 | 时间 | 作者 | 许可证 |
| ----------- | -- | -- | ---- |
| Nginx | **2004 年** | Igor Sysoev | BSD 许可证 |
| lighttpd | **2003 年** | Jan Kneschke | BSD 许可证 |

**史料**：Tim Berners-Lee 1991 年 CERN 万维网公告；NCSA httpd 0.1 源代码（1993）；Rob McCool 离开 NCSA 加入 Netscape 记录；Apache httpd 0.6.2 发布公告（1995.2）；Apache httpd 1.0 发布公告（1995.12）；Nginx 0.1.0 发布记录（2004）；lighttpd 1.0 发布记录（2003） ［A］
  
**史观**：第 9 条经验优先——Apache 是工程实践驱动（补丁集维护）而非 Web 服务器理论先行，“a patchy server” 双关体现社区补丁集的实践起源；BSD 反向影响线——Apache 在 BSD 系统上长期主导 Web 服务器市场，是 BSD 反向影响互联网基础设施的具体呈现
  
**辨析**：NCSA httpd 被 “淘汰” 为 Apache 指 Apache 主线代码基于 NCSA httpd 补丁集演化，但 Apache 1.0（1995.12）后逐步重写大部分代码，须区分 “补丁集阶段”（Apache 0.6.2-0.8.x）与 “独立重写阶段”（Apache 1.0+）；Nginx/lighttpd 替代 Apache 是 2000 年代后演化，须区分 “1995-2000 年代 Apache 主导” 与 “2000 年代后期 Nginx 挑战”；“a patchy server”双关名称来源在不同史料中描述详略不一，腾讯云开发者社区等多源确认“A Patchy Server”与“Apache”为谐音双关，但 Apache 早期邮件列表（apache-httpd-dev 1995 年存档）的原始记录保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 59.10.4 BIND/Sendmail 安全事件后替代方案兴起（1990-2000 年代）

  **要点**：BIND（Berkeley Internet Name Domain，伯克利 CSRG 四名研究生 Terry/Painter/Riggle/Zhou 1984 年开发，DNS 协议 RFC 882/883 1983 年 11 月标准化）与 Sendmail（1983 年随 4.2BSD 正式发布）长期主导互联网 DNS 与邮件传输市场，但 1990 年代后期两者均面临严重安全挑战——BIND 4.9.x 1990 年代后期多个远程漏洞；BIND 8.2.x 1999 年发现 NXT/SIG/SO_LINGER 等多个漏洞（CERT Advisory CA-1999-14）；Dan Kaminsky 2008 年披露的 DNS 缓存投毒漏洞系 DNS 协议设计层缺陷（事务 ID 与源端口可预测性），影响多数 DNS 实现而非仅限于 BIND；BIND 9（2000 年发布，ISC 维护）虽完全重写但仍持续面临安全挑战；Sendmail 1988 年 Morris 蠕虫利用 DEBUG 后门，1990 年代至 2003 年持续发现远程溢出漏洞；BIND/Sendmail 安全事件后替代方案兴起——PowerDNS（1999 年 Bert Hubert 发布，GPL）、Unbound（2007 年 NLnet Labs 发布，BSD 许可证，DNSSEC 验证解析器）、NSD（2003 年 NLnet Labs 发布，BSD 许可证，权威域名服务器）、Postfix（1998 年 Wietse Venema 发布，IBM Public License，原名 VMailer）、qmail（1995 年 Daniel J. Bernstein 发布，自定义免费许可）等；BIND/Sendmail 在 1990 年代后期的 “主导地位” 被 “淘汰” 为多元并存格局，但 BIND 9 与 Sendmail 在 BSD 与 Linux DNS/邮件服务器市场仍保留一定份额；这一多元替代格局后被 Linux 2000 年代后 systemd-resolved（2014 年起，DNS 解析器整合）等部分继承但本质已分化

**辨析**：BIND/Sendmail 被 “淘汰” 指主导地位被多元替代方案挑战，而非完全弃用——BIND 9 与 Sendmail 在 BSD 与 Linux 中仍保留一定份额，须区分 “主导地位退场” 与 “完全弃用”；Dan Kaminsky 2008 年漏洞（CERT VU#800113）是 DNS 协议设计层缺陷（事务 ID 仅 16 位 + 源端口固定），影响所有未实现源端口随机化的 DNS 实现，并非早期 BIND 8.2 漏洞的延续，二者性质不同；Postfix/qmail/Exim 替代 Sendmail 的具体份额在不同年份与不同地区差异显著，须以统计资料为准

**要点**：

- ISC 为美国 501(c)(3) 非营利公益组织，维护 BIND、DHCP 及遗留产品 INN，约 40 名员工且半数远程办公，收入主要来自支持合同；Losher 任高级运维架构师，自嘲职责是“让所有人能在家里工作”。F 根服务器实际运行基本是现货软件：99.9% 情况下跑官方 FTP 站的 stock BIND，系统以 FreeBSD 为主、杂有少量 Linux 与 Windows，防火墙以 dummynet 应对 DDoS。（BSDTalk EP206，[45.36-400.88]，L1）
- 根服务器负载史：早期 F 根托管 com、net、org 及军方 mil 等大型区域，须用 DEC Alpha 5U 大机并装载 8GB 内存才能容纳 zone；Verisign 将 com/net 迁往 gTLD 服务器、arpa 区域外移后，根服务器专注于根区域本身。如今 F 根分布式部署逾 50 个节点、以 1U 商品机 4GB 内存即为过剩（签名后的根 zone 不足 300K），十三家根运营者之间刻意保持操作系统、硬件与名字服务器软件的多样性。（BSDTalk EP206，[527.92-682.16]，L1）
- DNSSEC 与 IPv6：根区域签名于此前一年夏天完成，从根运营者视角切换“无可挑剔”，曾担忧的“响应增大三至四倍、穿透不过防火墙”并未成真；ISC 自有区域已签名五年，com/net/org 与主要 ccTLD 已陆续签名，下一步目标是把 DNSSEC 验证能力推进到基础操作系统层而非仅浏览器。ISC 自 2003 年起内部双栈运行 IPv4/IPv6，参与 World IPv6 Day 并向项目提供 IPv6 隧道。（BSDTalk EP206，[682.16-856.78]，L1）
- 商业化与公益的边界：因根服务基础设施属公益免费资源，ISC 长期拒绝企业“帮忙做 secondary”的请求；此后另建由多家 tier-1 提供商组成的全球网络（ISC 运营设备而非自有网络）推出商业 secondary DNS 服务，把 F 根多年运维经验变现。F 根部署扩展则面向发展中世界（斐济、内罗毕、达卡等），并正将平台缩减得更经济、便于运输。（BSDTalk EP206，[856.78-948.80]，L1）
- 主持人梳理 Gopher 脉络：1991 年明尼苏达大学为建设校园范围信息系统而发布，以菜单导航与匿名访问取代此前 Telnet 登录、逐字键入完整地址的体验；1992 年 Veronica 检索引擎问世，1993 年 RFC 1436 将协议定型；它与万维网几乎同时起步（首个 WWW 网站 1990 年），1993 年 CERN 宣布 WWW 自由开放后两者并跑，1994 年 WWW 借 Mosaic 浏览器起跑超越。（BSDTalk EP264，[189.92-384.06]，L2）
- 胜负手在许可与生态而非功能：明尼苏达大学宣布其 Gopher 服务器实现不对商用免费（对大学与其他用户仍免费），被认为打消了部分采用者热情、部分助推了 WWW 增长；该校 1995 年停止积极开发，迟至 2000 年才以 GNU GPL 开源。浏览器阵营则在 IE7 与 Firefox 4 前后以缩减攻击面、精简代码为由移除 Gopher 支持，完成制度性淘汰。（BSDTalk EP264，[254.98-294.54]，L2）
- 转载的 Gopher 开发者访谈给出协议诞生的内部视角：校园委员会的集中式设计“无法编码”被搁置半年，Farhad 另行设计分布式服务器协议；因仅有寥寥数台 NeXT，借其 Digital Librarian 全文检索实现索引与服务的机器分离；协议极简使人人可写服务器与客户端；发布方式是把软件放上 FTP 服务器任人取用，开发者自嘲为“开源故事的翻版”；书签与主页概念由此首创，Gopher+ 补入受图书馆员启发的元数据桶与多带宽替代视图，Veronica 由内华达的 Steve Foster 遍历整个 Gopher 树建成，晚期还实验了 3D 虚拟 Gopher 空间。（BSDTalk EP264，[950.92-1320.18]，L1）
- 主持人实操记录：在 OpenBSD 5.9 i386 上以 pkg_add 安装 BSD 许可的 Gophernicus 服务器（SDF 与 Devious 均采用），经 inetd 启动，系统为其创建专用 _gophernicus 用户而非复用 nobody（延续 OpenBSD 安全惯例），自 /var/gopher 提供服务、拒绝 world-writable 文件、支持虚拟主机与用户 Gopher 空间，部署前须保证主机名可解析；幸存生态还包括 Floodgap 的 Web 代理与浏览器插件、Veronica 2 与 pointloma 的 Veronica 索引。（BSDTalk EP264，[551.30-845.70]，L1）

**史料**：

- 本访谈为根服务器运维史与 ISC 组织史的一手口述，可提取的事实包括：BIND 9 研发阶段由 Sun、HP、IBM 等大厂资助并以其展示多处理器多线程能力、F 根节点分布于斐济/内罗毕/达卡等地、早期 Alpha 服务器 8GB 内存需求、签名根区小于 300K、BIND 用户仍大量滞留 9.3/9.4 旧版等，均为当事人自述。（BSDTalk EP206，[259.68-447.82]，L1）

**史观**：

- 总纲8 本体论上各方平等：总纲8 本体论上各方平等：Losher 明言十三家根运营者间须维持操作系统、硬件与名字服务器软件的多样性——没有人主张 FreeBSD 或 BIND 是唯一正确选择，ISC 亦同时杂用 Linux 与 Windows；多样性被制度化为互联网基础设施的抗脆弱策略，而非某一方的正统性叙事。（BSDTalk EP206，[458.54-505.52]，L1）
- 总纲13 法律与道德是利益分配：总纲13 法律与道德是利益分配：Losher 解释 ISC 许可证的价值在于给商业组织以确定性——集成后不强制开放修改源码，回馈与否“留给最终用户决定，不是自上而下强制”；许可证在此并非道德宣言而是利益分配装置，它决定了 Sun、HP、IBM 等厂商是否愿意资助 BIND 9。（BSDTalk EP206，[301.24-341.92]，L1）
- 总纲4 分离聚合是永恒规律：Gopher 开发者自我总结的规律是“拥抱并扩展既有系统”：Gopher 建立在 FTP 与 Usenet 内容之上，而万维网起步时毫无内容，正是坐在 Gopher 内容与简单协议之上才得以起飞——分布式信息系统的更替不是凭空创新，而是对既有内容与协议的吸收再扩展，呈现接续而非断裂的循环。（BSDTalk EP264，[1344.12-1378.94]，L1）
- 总纲3 不存在进步，只有权力再分配：Gopher 与万维网的胜负并非纯技术优劣之辨：明尼苏达大学对商用收费的许可宣示与 CERN 彻底开放的对照，把开发者社区与内容生态推向 WWW；浏览器厂商随后以“缩减攻击面”为由移除 Gopher 支持，完成制度性淘汰——许可安排与机构权力而非协议本身决定了协议的命运。（BSDTalk EP264，[254.98-531.92]，L2）
