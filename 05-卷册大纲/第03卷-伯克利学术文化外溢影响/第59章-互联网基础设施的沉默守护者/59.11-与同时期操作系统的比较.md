## 59.11.1 Windows NT 与 IIS 的互联网路径

  **要点**：Windows NT（1993.7 发布 NT 3.1）的互联网路径：（1）IIS（Internet Information Services）1995 年作为 Windows NT 3.51 的免费附加组件发布，1996 年 IIS 2.0 集成入 Windows NT Server 4.0；（2）IIS 的商业生态路径（Microsoft 全栈：Windows Server + IIS + SQL Server + ASP）与 BSD 的开源生态路径形成对比；（3）IIS 在 1990 年代后期与 Apache 竞争 Web 服务器市场，但 Apache 保持领先

| IIS 2.0 集成 | **1996 年** | 集成入 Windows NT Server 4.0 |

  | Windows NT/IIS 与 BSD/Apache 路径对比 | Windows NT/IIS | BSD/Apache |
| ----------------------------------- | ------------ | -------- |
| 生态路径 | 商业全栈（Microsoft） | 开源生态 |

## 59.11.2 Linux 与 Apache 的共生关系

  **要点**：Linux 与 Apache 的共生关系：（1）Linux（1991 年 Linus Torvalds 发布）与 Apache（1995 年发布）在 1990 年代后期形成 LAMP（Linux+Apache+MySQL+PHP）栈；（2）Linux 的 GPL 许可证与 Apache 的宽松许可证在哲学上不同，但在 Web 服务器生态上共生；（3）Linux 在 Web 服务器市场逐步超越 BSD 系统的部署份额，但 Apache 仍运行于 Linux；（4）此共生关系反映开源生态的多元性

  | Linux 与 Apache 共生关系 | 内容 |
| ---------------------- | -- |
| Linux 发布 | **1991 年**（Linus Torvalds） |
| Apache 发布 | **1995 年** |
| LAMP 栈形成 | 1990 年代后期（Linux+Apache+MySQL+PHP） |

  | LAMP 栈组件 | 时间 | 许可证 |
| --------- | -- | ---- |
| Linux | **1991 年** | GPL |
| Apache | **1995 年** | Apache License（宽松） |
| MySQL | **1995 年** | GPL |
| PHP | **1995 年** | GPL（早期）→PHP License（2000 起） |

  | Linux 与 Apache 许可证哲学 | Linux | Apache |
| ------------------------ | --- | ---- |
| 许可证 | GPL | Apache License（宽松） |
| 哲学 | copyleft（强制开源回馈） | 宽松开源（允许闭源衍生） |
| 共生 | 在 Web 服务器生态上共生 | — |

  | Linux/BSD Web 服务器市场份额演变 | 时期 | 趋势 |
| ------------------------------ | -- | -- |
| 1990 年代后期起 | Netcraft 统计 | Linux Web 服务器部署份额逐步超越 BSD |
| Apache 运行平台 | 1990 年代后期起 | Apache 仍运行于 Linux |

**史料**：Linux 1991 发布档案、Apache 1995 发布档案、LAMP 栈形成档案、Linux/BSD Web 服务器部署份额数据［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档与公告〕
  
**史观**：第 4 条分离与聚合——Linux（GPL）与 Apache（宽松许可证）在许可证哲学上分离，但在 Web 服务器生态上聚合，分离与聚合的辩证关系塑造开源生态

## 59.11.3 Solaris 的 Netscape 服务器路径

## 59.11.4 BSD 作为互联网沉默支柱的辨析

  **要点**：BSD 作为互联网沉默支柱的辨析：（1）BSD 的 BIND/Sendmail/TCP/IP 在 1980-1990 年代是互联网基础设施核心，但 BSD 系统的市场份额在 1990 年代后期被 Linux 超越；（2）BSD 的 “沉默” 源于其许可证宽松（无需署名）与基础设施性质（用户不直接接触）；（3）BSD 作为沉默支柱的具体辨析基于实际部署数据——BIND 1990 年代约 90% DNS 市场份额、Sendmail 作为 4.2BSD 默认 MTA 的广泛部署、4.2BSD TCP/IP 作为 RFC 标准参考实现的跨平台扩散（SunOS/Ultrix/AIX 借鉴），而非基于 2000 年代后 Linux 市场份额反向衡量；（4）BSD 的互联网遗产在 Linux 时代仍延续（Linux 借鉴 BSD 代码、Apache 源于 NCSA httpd）

  | BSD 作为互联网沉默支柱的辨析 | 内容 |
| -------------------------- | -- |
| 基础设施核心 | 1980-1990 年代 BSD 的 BIND/Sendmail/TCP/IP 是互联网基础设施核心 |
| 市场份额变化 | BSD 系统的市场份额在 **1990 年代后期** 被 Linux 超越 |
| “沉默” 原因 | BSD 许可证宽松（无需署名）与基础设施性质（用户不直接接触） |
| 辨析方法 | 基于实际部署数据而非 2000 年代后 Linux 市场份额反向衡量 |
| 互联网遗产 | Linux 时代仍延续（Linux 借鉴 BSD 代码、Apache 源于 NCSA httpd） |

  | BSD 互联网基础设施实际部署数据 | 时期 | 数据 |
| ---------------------------- | -- | -- |
| BIND DNS 市场份额 | **1990 年代** | 约 90% |
| Sendmail 部署 | 4.2BSD 默认 MTA | 广泛部署 |
| 4.2BSD TCP/IP 跨平台扩散 | 1980 年代起 | SunOS/Ultrix/AIX 借鉴 |

  | Linux 借鉴 BSD 代码案例 | 内容 |
| --------------------- | -- |
| Linux NET-2 | 借鉴 BSD 网络代码（含 BSD 版权声明） |
| Linux 早期 libc | 含 BSD 衍生函数 |
| Apache 源于 NCSA httpd | NCSA httpd 运行于 BSD 系统 |

**史料**：BSD 互联网基础设施档案（BIND/Sendmail/TCP/IP）、BSD/Linux 市场份额演变数据、Linux 借鉴 BSD 代码档案、Apache 源于 NCSA httpd 档案 ［A］
  
**史观**：总纲第 10 条——动手者创造历史，与第 9 条经验优先——BSD 作为互联网沉默支柱是边缘者（市场份额被超越但基础设施延续），其遗产须基于实践（代码、部署）而非叙事
  
**辨析**：BSD/Linux 市场份额演变——Netcraft 统计显示 1990 年代后期起 Linux Web 服务器部署份额逐步超越 BSD 系统的部署份额（定性趋势确认，定量数据保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）；Linux 借鉴 BSD 代码的具体案例——Linux NET-2 借鉴 BSD 网络代码（含 BSD 版权声明，与 23.5.2 一致）、Linux 早期 libc 含 BSD 衍生函数；Apache 源于 NCSA httpd 经多源确认（与 23.6.3 一致）；“沉默支柱”的描述须基于实际部署数据（BIND/Sendmail/TCP/IP 的 BSD 起源与持续部署），避免事后建构——BSD 的“沉默”源于其许可证宽松（无署名要求）与基础设施性质（用户不直接接触操作系统）
  
**文献**：BSD/Linux 市场份额数据（Netcraft）；Linux 代码档案；Apache 档案；McKusick (1999) “Twenty Years of Berkeley Unix” ［A］

### 史观映射

> 互联网不是从硅谷的车库里诞生的，而是从伯克利的终端室里长出来的。BIND 让全球的域名得以解析，Sendmail 让全球的邮件得以送达，BSD TCP/IP 栈让全球的数据包得以路由——这些技术构成了互联网的神经系统，但写下它们的人从未出现在任何互联网创业的封面上。ARPANET 到 NSFNET 的二十年是互联网从军事实验到学术骨干再到公共基础设施的转型期，而 BSD 系统恰好站在了每一个转折点上——不是作为主角，而是作为那个沉默的、在后台运转的操作系统。当 IETF 说 “rough consensus and running code” 时，他们说的其实就是 BSD 的工程哲学：先跑起来，再谈标准。当万维网从 CERN 传遍全球时，跑着 Apache 的 BSD 服务器已经在为第一批网站提供服务——但它们从未被看见，因为真正的互联网基础设施本就不该被看见
