## 226.1.3 与 FreeBSD 11.x 技术进展的比较
  - 要点：bsd_commits.db 显示 2016-2018 年间四仓库 commit 量对照——2016 年 freebsd-src = 17362、dragonfly-src = 2340；2017 年 freebsd-src = 16157、dragonfly-src = 1888；2018 年 freebsd-src = 14985、dragonfly-src = 1709。FreeBSD 11.0（2016-10-10 发布）引入 arm64 支持、改进 bhyve、改进无线网络栈；DragonFly v4.2.0/v4.4.0（2015）在 GPU 与网络栈改进上有局部进展，但 bsd_commits.db 显示其 commit 量仅为 FreeBSD 同期 13.5%（2016）、11.7%（2017）、11.4%（2018），整体生态与硬件支持仍落后
  - 史料：dragonfly.db 查询 L1.1.1 显示：dragonfly-src 2015 年 commit 量 3,112 条，2016 年 2,340 条，2017 年 1,888 条，2018 年 1,709 条（4.x 时代持续下降趋势）；FreeBSD 11.0 release notes；DragonFly 4.2/4.4 release notes
  - 史观：总纲第 6 条——技术路线分化：bsd_commits.db 数据显示 FreeBSD 与 DragonFly 在硬件支持广度上的分化持续加深——FreeBSD 11.x 时期 arm64 支持、bhyve 改进均属 “扩展技术广度” 的投入，DragonFly 4.x 时期 GPU 与网络栈改进属 “深化既有特性” 的投入；总纲第 17 条——软件工程：commit 量差距（FreeBSD 是 DragonFly 的 7.4-8.6 倍）反映两个项目的工程动员能力差距
  - 辨析：技术比较易被社区情感影响——DragonFly 支持者强调 LWKT 与 HAMMER 哲学优越性，FreeBSD 支持者强调生态与硬件支持，须结合 bsd_commits.db 客观数据辨析；FreeBSD 11.0 的 arm64 支持为 Tier-2（非 Tier-1），Tier-1 在 13.0 才引入；DragonFly 4.x 同期未进入 ARM 市场；【0 信任原则·commit 量不等于质量】dragonfly-src 2015-2018 年 commit 量持续下降（3112→2340→1888→1709）反映开发活跃度递减，但 HAMMER2 等核心子系统仍在持续改进，须结合 commit message 主题词辨析 [存疑脚注：FreeBSD 11.0 arm64 Tier-2 与 13.0 Tier-1 的分级须以 FreeBSD 官方平台文档核验，本轮考据未联网核验]。0 信任原则应用维度：author 字段可伪造（DragonFly 支持者与 FreeBSD 支持者的社区言论属当事人立场，须与 bsd_commits.db 客观数据交叉验证）、tagger_date 与实际发布日期可能偏差（v4.2.0/v4.4.0 tagger 均为 Sherrill，须与 Release Notes 互参）、关键词匹配局限（commit 量比较中 freebsd-src 17,362 条 vs dragonfly-src 2,340 条含不同类型 commit，须以 commit_files 表细分核验）。考据留痕至 `03-原始史料库/06-考据记录/20260730_jianyi缺口补全考据.md` 8ad 节
