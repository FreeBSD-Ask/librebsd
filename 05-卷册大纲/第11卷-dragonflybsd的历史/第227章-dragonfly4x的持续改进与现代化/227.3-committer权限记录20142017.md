# 227.3 committer 权限记录（2014-2017）——本时期 DragonFly 的 committer 权限模型，Dillon 主导的权限管理实践

## 227.3.1 Dillon 主导的权限管理

**要点**：dragonfly.duckdb dragonfly-src 仓库 commits 表按 author_email 分组显示 2014-2017 年间活跃 committer 数稳定在 25-26 人区间（2016 = 25、2017 = 26）。Dillon 作为项目创始人对 committer 权限授予拥有最终决定权，DragonFly 无 Core Team 选举机制、无 Foundation 法律实体（**dragonflybsd.org/foundation/** 页面 404）、无公开 bylaws。dragonfly.duckdb 显示 2016-2018 年间 Dillon（`dillon@apollo.backplane.com` 邮箱）commit 量 398+559+286 = 1243 条，占同期 dragonfly-src 仓库总 commit 量约 18.9%——Dillon 在代码贡献量上居 TOP 2，仅次于 Wildner（1447 条）。Dillon 2014-2018 年按年 commit 量如下：

    | 年份 | Dillon commit 数 | 阶段特征 |
    |---|---|---|
    | 2014 | 323 | 4.x 周期起点 |
    | 2015 | 329 | HAMMER 2 生产部署期 |
    | 2016 | 398 | HAMMER 2 持续改进 |
    | 2017 | 559 | HAMMER2 关键词峰值年 |
    | 2018 | 286 | HAMMER 2 在 v5.0.0 后转入维护 |
**史料**：dragonfly.duckdb dragonfly-src 仓库 commits 表（按 author_email 与 author_date 交叉统计：2014-2017 年活跃 committer 数）；dragonfly.duckdb dragonfly-src 仓库 commits 表（Dillon 2014-2018 年按年统计：323/329/398/559/286）；**dragonflybsd.org/foundation/** HTTP 404；kernel@ 邮件列表中权限相关公告

**史观**：总纲第 5 条——没有必然性，只有偶然性：Dillon 个人主导的权限管理并非必然的制度设计，而是系于创始人持续在场的偶然条件——dragonfly.duckdb 数据显示 2014-2017 年间活跃 committer 数稳定在 25-26 人，即此偶然均衡的呈现，项目随之进入 “稳定维护” 阶段；总纲第 8 条——本体论上各方平等：DragonFly 无 Foundation 法律实体（dragonflybsd.org/foundation/ 404）的个体主导治理与 FreeBSD 的 Core Team+Foundation 治理在本体论上平等并存，企业赞助、法律保护、基础设施资金上的资源差异不构成治理形态的优劣判据

**辨析**：dragonfly.duckdb 显示 2014-2017 年间活跃 committer 数（25-26 人）较 2018-2021 年（24-20 人）略高，反映 4.x 时期是 DragonFly 社区规模的小高峰；Dillon 代码贡献量在 2016-2018 年间居 TOP 2，与 2024-2026 年间退居 TOP 3 形成对照；个人主导的权限管理在小项目中可能更高效，但需结合具体案例辨析其一致性

**文献**：dragonfly.duckdb dragonfly-src 仓库 commits 表与 contributors 表（2014-2017 年活跃 committer 与 Dillon 统计）；dragonflybsd.org/foundation/ 页面 404；DragonFly BSD 邮件列表存档 [EB/OL]. <https://www.dragonflybsd.org/mailinglists/> ［A］

## 227.3.3 与 FreeBSD/OpenBSD 权限模型的比较

**要点**：dragonfly.duckdb 显示 2016-2018 年间四仓库 commit 量对照如下：

    | 年份 | freebsd-src | openbsd-src | netbsd-src | dragonfly-src |
    |---|---|---|---|---|
    | 2016 | 17362 | 9463 | 16600 | 2340 |
    | 2017 | 16157 | 8688 | 13101 | 1888 |
    | 2018 | 14985 | 7279 | 10983 | 1709 |
    FreeBSD 采用 Core Team 选举+Foundation 治理的双重权限模型，OpenBSD 采用 de Raadt 主导+committer 集体讨论的混合模型，DragonFly 采用 Dillon 个人主导的单一模型——commit 量差距反映三种权限模型在社区动员能力上的差异
**史料**：dragonfly.duckdb commits 表四仓库 2016-2018 年对照；FreeBSD Core Team 选举记录档案（**freebsd.org/administration/**）；OpenBSD Foundation 年报（**openbsdfoundation.org/**）；DragonFly 无 Foundation 法律实体〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 5 条——没有必然性，只有偶然性：三种权限模型分别塑造三个项目的不同文化与技术路径并非技术必然，而是各项目创始与演化路径的偶然沉淀——FreeBSD Core Team 集体审议机制支持 GEOM/ZFS/bhyve 等大型子系统的多贡献者协作，freebsd.duckdb 显示 freebsd-src 2016-2018 年年均 commit 量约 16168 条是 DragonFly 的 8.3 倍；OpenBSD de Raadt 主导但有 misc@ 邮件列表公开讨论机制，openbsd.duckdb 显示 openbsd-src 年均 commit 量是 DragonFly 的 3.7 倍；DragonFly Dillon 个人主导无公开审议机制，commit 量最低

**辨析**：commit 量差距非仅由权限模型决定——FreeBSD 与 OpenBSD 均有 Foundation 法律实体接收企业赞助，DragonFly 无 Foundation 法律实体（dragonflybsd.org/foundation/ 404），资金支撑差异与权限模型差异共同影响社区动员能力；权限模型的优劣无绝对标准，须结合项目目标辨析

**文献**：dragonfly.duckdb commits 表（四仓库 2016-2018 年对照）；FreeBSD Foundation. Annual Reports [EB/OL]. <https://freebsdfoundation.org/>；OpenBSD Foundation. Annual Reports [EB/OL]. <https://www.openbsdfoundation.org/> ［A］
