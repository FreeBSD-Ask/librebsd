# 220.6 DragonFly BSD 继承自 FreeBSD 4.8 的 ktrace（跨 BSD/UNIX/macOS 扩展）

## 220.6.1 ktrace 的 fork 时刻定格与 DTrace 缺位

**要点**：DragonFly BSD 自 fork 自 FreeBSD 4.8（**2003-06-20**）起继承 ktrace 子系统，源码位于 **sys/kern/kern_ktrace.c**——此实现未跟随 FreeBSD 5.0（2003）后的 DTrace 引入，保留了 4.x 时代的传统 ktrace 路径。DragonFly BSD ktrace 与 FreeBSD ktrace 在 fork 时刻完全同源，分叉发生在 FreeBSD 7.0（2008）引入 DTrace 后。**ktrace(1)** 与 **kdump(1)** 命令在 DragonFly BSD 中保留至今。

**史料**：DragonFly BSD src 仓库 **sys/kern/kern_ktrace.c**；**ktrace(1)** man page（man.dragonflybsd.org）；DragonFly BSD 1.0 Release Notes；Dillon, M. (2003). *DragonFly BSD Design Goals*.〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 1 条——源头时刻：DragonFly BSD fork 时“冻结”了 ktrace 的 4.x 实现，此即 fork 时刻的“源头定格”；总纲第 2 条——分离与聚合：DragonFly BSD 从 FreeBSD 分离时聚合了 ktrace 子系统；总纲第 6 条——技术选择的代价：DragonFly BSD 选择保留 4.x ktrace 而非引入 DTrace，付出可观测性局限代价，但获得代码路径稳定性；总纲第 10 条——边缘者贡献：ktrace 的最初设计者姓名被遮蔽，Matthew Dillon（马修·狄龙） 的 fork 决策是边缘者贡献的显现；总纲第 17 条——形式与内容：ktrace 作为“形式”（系统调用追踪）保留了 4.4BSD-Lite2 的“内容”（VFS 操作记录）；自反性声明：本释读不预设“DragonFly BSD 中心论”——ktrace 在 NetBSD、OpenBSD、FreeBSD 均有保留或演化。

**辨析**：DragonFly BSD ktrace 与 FreeBSD 5.0+ ktrace 在 fork 时刻同源，分叉发生在 FreeBSD 7.0 引入 DTrace 后——FreeBSD 7.0 同时支持 ktrace 与 DTrace，DragonFly BSD 仅保留 ktrace。DragonFly BSD 未引入 DTrace 的原因主要是社区规模与维护资源限制。

**文献**：DragonFly BSD Project. *DragonFly BSD 1.0 Release Notes*[EB/OL]. (2005-07-24). <https://www.dragonflybsd.org/>; DragonFly BSD Project. *ktrace(1) Manual Page*[EB/OL]. <https://man.dragonflybsd.org/>.
