# 220.5 DragonFly BSD 保留的 nullfs 实现（跨 BSD/UNIX/macOS 扩展）

## 220.5.1 nullfs 的 fork 时刻定格与 GEOM 分叉

**要点**：DragonFly BSD 自 fork 自 FreeBSD 4.8（**2003-06-20**）起保留 nullfs 实现，源码位于 **sys/vfs/nullfs/** 目录——此实现未跟随 FreeBSD 5.0（2003）的 GEOM 框架重构，保留了 4.4BSD-Lite2 时代的传统 layered fs 路径。DragonFly BSD 的 nullfs 用于挂载点别名与 jail 隔离场景，与 FreeBSD 的 **mount_nullfs(8)** 在命令名上相同但代码路径独立。Matthew Dillon（马修·狄龙） 在 DragonFly BSD 1.x（2003-2005）时期保留 nullfs 作为 VFS 框架的基础组件，未做重大重构。

**史料**：DragonFly BSD src 仓库 **sys/vfs/nullfs/** 目录（gitweb.dragonflybsd.org）；DragonFly BSD 1.0 Release Notes（**2005-07-24**）；**mount_nullfs(8)** man page（man.dragonflybsd.org）；Dillon, M. (2003). *DragonFly BSD Design Goals*. dragonflybsd.org 邮件列表存档。

**史观**：总纲第 1 条——源头时刻：DragonFly BSD fork 自 FreeBSD 4.8 时“冻结”了 nullfs 的 4.x 实现，此即 fork 时刻的“源头定格”；总纲第 2 条——分离与聚合：DragonFly BSD 从 FreeBSD 分离时聚合了 nullfs 的 4.x 代码路径，是分离时刻的聚合事件；总纲第 6 条——技术选择的代价：DragonFly BSD 选择保留 4.x nullfs 而非跟随 FreeBSD 5.0 GEOM 重构，付出与 FreeBSD 代码路径分叉的代价，但获得 VFS 框架的稳定性；总纲第 10 条——边缘者贡献：Matthew Dillon 作为 DragonFly BSD 创始人，其保留 nullfs 的决策反映个人工程判断，非委员会决议；总纲第 17 条——形式与内容：nullfs 作为“形式”（VOP 透传）保留了 4.4BSD-Lite2 的“内容”（layered fs 框架）；自反性声明：本释读不预设“DragonFly BSD 中心论”——nullfs 在 NetBSD（layered fs）与 FreeBSD（GEOM 类）有独立演化，本节仅释读 DragonFly BSD 一支。

**辨析**：DragonFly BSD nullfs 与 FreeBSD 5.0+ 的 **mount_nullfs(8)** 在命令名上相同但代码路径独立——FreeBSD 5.0 将 nullfs 重构为 GEOM 类，DragonFly BSD 保留传统 layered fs 路径。与 NetBSD null 层在 4.4BSD-Lite2 前同源，分叉发生在 NetBSD 1.6 layered fs 重构与 DragonFly BSD fork 之后。
