# 220.1 与同时期操作系统的比较：DragonFly 1.x 时代与 LWKT 子系统时期（2004-2007）——与 FreeBSD 5.x/6（SMPng）、NetBSD 2.x/3.x、OpenBSD 3.x、Linux 2.6 的对照

## 220.1.1 FreeBSD 5.x/6（SMPng，2003-2005）

**要点**：FreeBSD 在 DragonFly 1.x 同期为 5.x（2003-2005）/6.0（2005），以 SMPng（细粒度锁）重构内核并发；与 DragonFly 1.x 的 LWKT（轻量内核线程）对照——二者同源于 4.4BSD，DragonFly 放弃 SMPng 的锁路线、改用消息传递/LWKT，体现 fork 后的并发哲学分野。

**史料**：FreeBSD 5.x/6 SMPng 史料（含 Baldwin 2002 SMPng 实现文档、FreeBSD 5.0/5.1/5.2/5.3/6.0 Release Notes）；DragonFly 1.x LWKT 史料；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `03-原始史料库/01-代码仓库史料/05-DragonFlyBSD/db/duckdb/〔原引 01-数据库本体 路径断链，订正〕`，含 LWKT 首引 commit `8ad65e080342` 2003-06-20、token 机制 1.10 引入 2007.8.6、2003-2008 年 LWKT 路径 commit 演化）；DragonFly BSD 邮件列表存档（**DragonFly 邮件列表**（<https://www.dragonflybsd.org/mailinglists/>），含 kernel@、users@ 2003-2008 年间 LWKT/SMPng 讨论档案）；DragonFly BSD Release Notes（<https://www.dragonflybsd.org/releases/>，**1.0-1.12> 版本序列）；Dillon fork 公告（<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>，**2003-07-16，“too> heavily mutexed” 表述）；HAMMER 设计 PDF（<https://www.dragonflybsd.org/hammer/hammer.pdf>，**Dillon> 2008 完整设计文档，B+Tree 写时复制哲学，为 LWKT 工程哲学在文件系统层面的延续）[三角验证：dragonfly.duckdb 代码层 + 邮件列表言论层 + Release Notes 官方层三类来源互参] ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：DragonFly 自 FreeBSD 5.x fork（2003），LWKT 与 SMPng 是 fork 后并发路线分化。

**辨析**：LWKT 的消息传递 vs SMPng 的锁，是两种 SMP 哲学，非技术优劣。具体争议点：1) 版本号核验——DragonFly 1.0 发布日期（**2004.7.12**）经 kernel@ 邮件公告（**lists.dragonflybsd.org/pipermail/kernel/2004-July/212809.html**）与 dragonfly.duckdb dragonfly-src tags 表交叉验证，部分二手来源误载为 2005.3，已修正；2) LWKT 首引时间——dragonfly.duckdb 显示 LWKT 首引 commit `8ad65e080342`（2003-06-20T02:09:59Z）距 fork 首 commit `984263bcb83a`（2003-06-17T02:57:24Z）仅 2 天 19 小时 36 分钟，反映 Dillon 在 fork 前已完成 LWKT 设计，但 commit 量不等于设计完成度；3) SMPng 与 LWKT 性能对比缺乏权威第三方基准 [存疑脚注：LWKT 与 SMPng 性能对比缺乏权威第三方基准，本节不臆造具体性能数字]。0 信任原则应用维度：author 字段可伪造（dragonfly.duckdb author_email 须与 committer 字段交叉验证）、tagger_date 与实际发布日期可能偏差（须与 Release Notes 互参）、关键词匹配局限（sys/sys/lwkt*与 sys/kern/lwkt* 路径匹配可能遗漏散落在 sys/platform/ 下的 IPI 实现）。考据记录归档至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8g 节。

**文献**：FreeBSD. 5.x/6 Release Notes [EB/OL]；DragonFly. 1.x Docs [EB/OL]；Baldwin. FreeBSD SMPng 实现文档；dragonfly.duckdb dragonfly-src 仓库 commits/commit_files 表；Dillon fork 公告（**lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html**）. ［A］

## 220.1.2 NetBSD 2.x/3.x（2004-2005）

**要点**：NetBSD 在 DragonFly 1.x 同期为 2.0（2004）/3.0（2005），以稳定 SMP 与多平台见长；与 DragonFly 1.x 的 LWKT 实验对照——NetBSD 走稳健 SMP 路线，DragonFly 1.x 探索消息传递并发，二者在 BSD 家族内并行。

**史料**：NetBSD 2.x/3.x 发布说明（含 NetBSD 2.0 Release Notes 2004、3.0 Release Notes 2005）；DragonFly 1.x 史料；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `03-原始史料库/01-代码仓库史料/05-DragonFlyBSD/db/duckdb/〔原引 01-数据库本体 路径断链，订正〕`，dragonfly-src 2003-2008 年 commit 演化，含 LWKT/token/SMP 相关 commit）；DragonFly BSD 邮件列表存档（<https://www.dragonflybsd.org/mailinglists/>）；**DragonFly> BSD Release Notes（<https://www.dragonflybsd.org/releases/>）；**Dillon> fork 公告（<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>）；**HAMMER> 设计 PDF（<https://www.dragonflybsd.org/hammer/hammer.pdf>）**[三角验证：dragonfly.duckdb> + 邮件列表 + Release Notes 三类来源互参] ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律：NetBSD 与 DragonFly 同期演进，稳健 vs 实验并发路线分化。

**辨析**：DragonFly 1.x 的 LWKT 尚早期，NetBSD 的 SMP 更成熟稳定。具体争议点：1) NetBSD 2.0/3.0 的 SMP 实现细节（细粒度锁定保守路径）须以 NetBSD 官方 Release Notes 核验，部分二手来源简化为 “NetBSD 无 SMP 创新” 属误读 [存疑脚注：NetBSD 2.x/3.x SMP 实现细节待以 NetBSD 官方文档核验]；2) DragonFly 1.x 与 NetBSD 同期 commit 量对比——dragonfly.duckdb 显示 dragonfly-src 2004 年 3,366 条 commit、netbsd-src 同期数据须单独查询，commit 量不等于技术成熟度。0 信任原则应用维度：author 字段可伪造、tagger_date 与实际发布日期可能偏差、跨仓库 commit 量对比须控制仓库规模与迁移历史混淆变量。考据记录归档至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8i 节。

## 220.1.3 OpenBSD 3.x（2003-2005）

**要点**：OpenBSD 在 DragonFly 1.x 同期为 3.x（2003-2005），以安全审计与稳定著称，SMP 支持有限；与 DragonFly 1.x 的 LWKT 并发实验对照——OpenBSD 3.x 专注安全而非并发创新，DragonFly 1.x 押注 LWKT。

**史料**：OpenBSD 3.x 发布说明（含 3.4-4.3 Release Notes，Big Lock 简化保守路径）；DragonFly 1.x 史料；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `03-原始史料库/01-代码仓库史料/05-DragonFlyBSD/db/duckdb/〔原引 01-数据库本体 路径断链，订正〕`）；DragonFly BSD 邮件列表存档（<https://www.dragonflybsd.org/mailinglists/>）；**DragonFly> BSD Release Notes（<https://www.dragonflybsd.org/releases/>）；**Dillon> fork 公告（<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>）；**HAMMER> 设计 PDF（<https://www.dragonflybsd.org/hammer/hammer.pdf>）**[三角验证：dragonfly.duckdb> + 邮件列表 + Release Notes 三类来源互参] ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律：OpenBSD 与 DragonFly 同期演进，安全 vs 并发实验目标分化。

**辨析**：OpenBSD 3.x 的 SMP 保守，DragonFly 1.x 的 LWKT 前瞻，体现家族路线多元。具体争议点：1) OpenBSD 3.x SMP “保守” 的判定须以 OpenBSD 官方 Release Notes 与设计文档核验，部分二手来源将 “Big Lock 简化” 简化为 “无 SMP 创新” 属误读 [存疑脚注：OpenBSD 3.x SMP 保守路径的具体实现细节待以 OpenBSD 官方文档核验]；2) DragonFly 1.x “前瞻” 判定须警惕目的论叙事——LWKT 路径后续未获主流采纳，“前瞻” 不等于 “成功”。0 信任原则应用维度：author 字段可伪造、tagger_date 与实际发布日期可能偏差、“保守 vs 前瞻” 的价值判断须以项目目标（安全 vs 并发）而非统一标准衡量。考据记录归档至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8k 节。

## 220.1.4 Linux 2.6（2003）

**要点**：Linux 2.6（2003）在 DragonFly 1.x 同期以 O(1) 调度器、抢占式内核与良好 SMP 见长；与 DragonFly 1.x 的 LWKT 对照——Linux 2.6 的 SMP 经锁与抢占实现，DragonFly 1.x 探索消息传递，二者在 2003-2007 形成并发路线对照。

**史料**：Linux 2.6 发布说明（2003，含 2.6.0 Release Notes、O(1) 调度器文档、BKL 渐进移除记录）；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `03-原始史料库/01-代码仓库史料/05-DragonFlyBSD/db/duckdb/〔原引 01-数据库本体 路径断链，订正〕`，dragonfly-src 2003-2008 年 commit 演化）；DragonFly BSD 邮件列表存档（<https://www.dragonflybsd.org/mailinglists/>）；**DragonFly> BSD Release Notes（<https://www.dragonflybsd.org/releases/>）；**Dillon> fork 公告（<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>）；**HAMMER> 设计 PDF（<https://www.dragonflybsd.org/hammer/hammer.pdf>）**[三角验证：dragonfly.duckdb> + 邮件列表 + Release Notes 三类来源互参] ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律：Linux 2.6 的抢占/锁 SMP vs DragonFly LWKT 消息传递，是并发哲学差异。

**辨析**：Linux 2.6 的 SMP 成熟度高于早期 DragonFly 1.x，但后者探索不同路径。具体争议点：1) Linux 2.6 的 BKL（Big Kernel Lock）移除是渐进过程，2003-2008 年间仍保留大量 BKL 用法，完全移除延续至 2011 年后的 2.6.39 与 3.x 系列 [存疑脚注：Linux 2.6 BKL 移除的具体进度须以 LKML 与 Linux Kernel commit log 核验]；2) Linux 2.6 O(1) 调度器与 DragonFly LWKT 调度器的对比须以同硬件同负载基准测试核验，二者目标不同（Linux 通用 SMP vs DragonFly 消息传递并行）。0 信任原则应用维度：跨项目比较须控制硬件/负载/版本混淆变量、“成熟度” 判定须以部署规模与生态而非单一技术指标衡量。考据记录归档至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8n 节。

## 220.1.5 同期 SMP/线程模型总览（2003-2007）

**要点**：2003-2007 并发模型竞争：FreeBSD 5/6 走 SMPng 锁路线，DragonFly 1.x 走 LWKT 消息传递，NetBSD 2/3 稳健 SMP，OpenBSD 3.x 保守，Linux 2.6 抢占/锁成熟；DragonFly 1.x 的 LWKT 是 BSD 家族内少有的 “去锁化” 并发实验。

**史料**：各系统 2003-2007 并发史料（含 FreeBSD SMPng 设计文档、DragonFly LWKT 设计文档、NetBSD 2.x/3.x Release Notes、OpenBSD 3.x Release Notes、Linux 2.6 Release Notes）；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `03-原始史料库/01-代码仓库史料/05-DragonFlyBSD/db/duckdb/〔原引 01-数据库本体 路径断链，订正〕`，dragonfly-src 2003-2008 年 LWKT/token/SMP 路径 commit 演化）；DragonFly BSD 邮件列表存档（<https://www.dragonflybsd.org/mailinglists/>）；**DragonFly> BSD Release Notes（<https://www.dragonflybsd.org/releases/>）；**Dillon> fork 公告（<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>）；**HAMMER> 设计 PDF（<https://www.dragonflybsd.org/hammer/hammer.pdf>）**[三角验证：dragonfly.duckdb> + 邮件列表 + Release Notes 三类来源互参] ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律：DragonFly 的 LWKT 与 FreeBSD SMPng 同源分叉，体现 family 并发哲学多元。

**辨析**：并发路线无绝对优劣——LWKT 的优雅与 SMPng 的实用各有拥趸。具体争议点：1) “优雅” 与 “实用” 的价值判断须以项目目标而非统一标准衡量——DragonFly 追求轻量级内核哲学，FreeBSD 追求主流服务器市场适配，二者目标不同 [存疑脚注：LWKT “优雅” 与 SMPng “实用” 的价值判断属主观工程判断，须以具体部署场景核验]；2) 各路径的长期演化须以 2026 年回溯视角审视——LWKT 未获主流采纳、SMPng 成为 BSD 阵营主流、Linux BKL 完全移除，但 “未获主流采纳” 不等于 “失败”（总纲第 8 条本体论平等）。0 信任原则应用维度：跨项目比较须控制硬件/负载/版本/社区规模混淆变量、“优雅/实用” 判断须以工程实践而非理论美学衡量、长期演化判定须警惕目的论叙事。考据记录归档至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8m 节。

**要点**：

- Dillon 阐明 DragonFly 1.8 最具分量的特性是 vkernel：以普通进程形态运行于真实 DragonFly 内核之上的完整 DragonFly 内核，思路近似 User Mode Linux，但与 Xen 支持多客户系统不同，它只支持 DragonFly 自身的嵌套运行。（BSDTalk EP98，[51.8-65.72]，L1）
- vkernel 的实现仅依赖三项新增的通用机制——信号邮箱（signal mailboxes）、可经 mmap 映射的虚拟页表、以及受用户完全控制的 VM 空间管理；Dillon 明确建议其他 BSD 项目审视并采纳这些机制，而非完全依赖 QEMU/VMware 做内核虚拟化。（BSDTalk EP98，[1202.34-1302.26]，L1）
- 1.8 版本以底层工程为主：缓存一致性管理部分并入内核、命名空间拓扑重构并重写 nullFS 以支持 jail/chroot 场景下的只读挂载、文件系统 API 为 SysLink 协议预作清理、并引入 GCC 4.1 形成以环境变量切换多编译器的体系（基础编译器仍为 3.4），为项目第二阶段的集群目标铺垫。（BSDTalk EP98，[469.1-583.34]，L1）
- Dillon 宣告项目进入下半场：SMP 基础设施基本就绪，第二阶段主线是集群、SysLink 链路协议与新文件系统；他预计 2.0 不会在生产环境携带新特性，2.1 才是真正落地新文件系统的版本，并直言不愿使用 1.10 这类字符串排序混乱的版本号。（BSDTalk EP98，[706.12-743.92]，L1）
- 关于自 FreeBSD 分化后的代码互通，Dillon 给出分层评估：应用层走 pkgsrc 相当省力，缺陷修复在两树之间双向取用几乎无痛，但整块驱动替换（如移植 FreeBSD 新 ATA 驱动）因 DragonFly 驱动基础设施已显著分叉而代价高昂。（BSDTalk EP98，[605.18-674.7]，L1）

**史料**：
