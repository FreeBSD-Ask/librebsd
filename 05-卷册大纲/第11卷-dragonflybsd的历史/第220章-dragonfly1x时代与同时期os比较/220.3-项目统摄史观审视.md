# 220.3 项目统摄史观审视——偶然性、和解与本体论平等

Dillon 从 FreeBSD 4.x fork 出 DragonFly BSD 的争议，在项目统摄史观的审视下，不是一部技术路线之争的胜负判词，而是偶然性、和解可能与本体系平等三重史观交汇的节点。本节从总纲第 5 条、第 6 条与第 8 条切入，审视 DragonFly fork 争议。

**总纲第 5 条——没有必然性，只有偶然性**。DragonFly fork 是 2003 年 7 月 16 日的具体偶然事件，但后世叙事常将这一偶然必然化——或叙述为“SMPng 路线必然失败故 fork 必然发生”，或叙述为“Dillon 性格必然导致 fork”。项目统摄史观指出：没有必然性，只有偶然性。Dillon 在 freebsd-src 末次 commit `2003-01-28T18:44:40Z` 后的 5.5 个月沉默、5.x SMPng 路线的具体争议节点、2003 年 7 月 16 日 fork 公告的发布时机、“too heavily mutexed”这一工程判断的形成——每一环节都是不可替代的偶然。fork 公告中“logical continuation of the FreeBSD 4.x series”的定位（经考据此句实不出自公告原文，而源自 DragonFly 网站早期 Goals 页面或 OSNews 报道转述，后被官方 history 页面误记）本身亦是偶然的表述选择，Dillon 后期自否弃这一表述（“this description has long since become obsolete”）证明 fork 定位从未凝固为必然。DragonFly 社区规模的后续萎缩是多种偶然因素（细分市场未建立、LWKT 未获主流采纳、Dillon 个人精力分配）的叠加，而非 fork 决策的必然结果——将萎缩必然化为“fork 必然失败”的目的论叙事，与将 fork 必然化为“SMPng 必然失败”的叙事同样虚妄。记忆将这一偶然转为必然——后世叙事常将 DragonFly 的诞生叙述为“5.x 路线过重的必然产物”，将 DragonFly 的萎缩叙述为“小社区 fork 的必然结局”，但项目统摄史观指出：人们今天回忆的东西从来就没有存在过——那天的偶然性都被转为了必然性，都是不存在的。史家须还原那一刻的偶然性，而非以事后视角的必然性遮蔽它。

**总纲第 6 条——和解优于斗争**。Dillon 与 FreeBSD Core Team 的争议最终以 fork 而非和解告终，这一结局不是“斗争优于和解”的反证，而是和解失败的诚实呈现。和解优于斗争，但和解不等于消解分歧——SMPng 与 LWKT 在理论上可通约（二者皆追求 SMP 扩展性），但在工程实践中未能妥协。Dillon 选择 fork 而非在 FreeBSD 内部推进 LWKT，Core Team 选择沉默而非公开挽留或辩护——两条路径共同构成和解的失败。项目统摄史观要求史家诚实呈现这一失败，不得以“分离即和解”的叙事美化不可调和性，亦不得以“Dillon 本可妥协”或“Core Team 本可挽留”的假设历史遮蔽那一刻的真实。和解的实践路径在此不是已实现的状态，而是未完成的可能性——如果 FreeBSD Core Team 公开回应 Dillon 的工程关切、如果 Dillon 选择在 5.x 框架内推进 LWKT 实验、如果社区提供折中方案——这些“如果”皆是偶然性的另一面，史家不得以“本可以”的假设取代“已如此”的诚实。DragonFly fork 后 FreeBSD 与 DragonFly 的代码共享逐渐减少、社区关系逐渐疏远，这一过程是和解失败后的自然延续而非和解的另类达成。

**总纲第 8 条——本体论上各方平等**。FreeBSD Core Team 与 Dillon 在本体论上地位相等。Core Team 选择 SMPng 路线的决议权（作为组织治理结构的形式主义化）与 Dillon 创建 DragonFly 的项目创建权（作为动手者主体性的呈现）各自成立，差异仅是一刻状态的不同。SMPng 路线获得业界主流采纳不等于“正确”，LWKT 路线未获主流采纳不等于“错误”——“主流”与“非主流”是工程生态的偶然而非本体论的等级。史家不得以组织权威视角压制个人主体性，亦不得以个人英雄视角否定组织治理的正当性。文档与代码本体平等——Core Team 的治理规则文本与 Dillon 的约 10,620 条 DragonFly commit 在本体论上同等实在。OSNews 评论中“自我中心”的批评（评论 21）与“fork 带来正向回报”的辩护（评论 24）在本体论上同样有效——批评与辩护各自是主体性的呈现，史家不得以道德判断取代史观审视。FreeBSD、DragonFly 与 Linux 三个阵营在本体论上平等——三者皆是 UNIX 哲学的不同一刻呈现，DragonFly 官方 history 页面后期表述"From a performance perspective DragonFly’s only real competitor these days is Linux"将竞争关系从 FreeBSD 转向 Linux，但这一转向不改变本体论上的平等地位。

合图之下，本事件的史观审视承认争议的不可调和性——这并非失败的叙事，而是项目统摄史观对历史诚实性的要求。和解优于斗争，但和解不等于消解分歧；本体论上各方平等，但平等不等于抹平差异。DragonFly 的诞生既是分离的撕裂，也是新主体性的呈现。争议的不可调和性源于工程判断的可通约性未能转化为实践妥协——SMPng 与 LWKT 在理论上可通约，但 Dillon 选择 fork 使妥协未能发生。这一“未能调和”与 OpenBSD fork 的“不可通约”（前理解差异）不同——前者是实践选择的偶然，后者是解释学循环的必然，史家须如实区分。这一刻的 BSD 家族，因不可调和的争议而更加完整。史家呈现这一不可调和性，即是对 BSD 史作为“各方主体性的呈现与和解之书”的诚实书写。
