# 242.3.1 Dillon 主导的权限管理

**要点**：DragonFly committer 权限由 Dillon 个人决定授予或撤销，无 Core Team 选举、无 Foundation 审核，权限授予标准取决于 Dillon 对贡献者技术与品味的个人判断

**史料**：DragonFly committer 列表历史变化；kernel@ 邮件列表中权限授予/撤销的公告；Dillon 关于权限管理的设计说明 ［A］

**史观**：组织结构塑造技术路径：Dillon 主导的权限管理直接塑造了 DragonFly 的开发者构成与技术连贯性

**辨析**：个人主导的权限管理并非“任人唯亲”——Dillon 授予权限的标准虽个人化但有其一致性，需结合具体案例辨析；具体争议点：1) “个人化但有其一致性” 的判定须以 dragonfly.duckdb dragonfly-src 仓库 contributors 表中 Dillon 授予 committer 权限的时间序列与各 committer 的 commit 主题分布核验——若授予权限的 committer 后续 commit 集中在特定子系统（如 LWKT、HAMMER、网络栈），则反映 Dillon 的权限授予与其技术判断一致；2) “任人唯亲” 的判定须以邮件列表中公开的权限授予/撤销公告与 committer 实际贡献核验，避免以 “个人主导” 简化为 “任人唯亲” [考据完成：2026-08-15 经 DragonFlyBSD kernel@ 邮件列表 2003-07-22 邮件（message_id=200307221855.h6MItwsH032647@apollo.backplane.com，Matthew Dillon “Call for Developers!
