## 221.3.1 Dillon 主导的权限管理

**要点**：DragonFly committer 权限由 Dillon 个人决定授予或撤销，无 Core Team 选举、无 Foundation 审核，权限授予标准取决于 Dillon 对贡献者技术与品味的个人判断

**史料**：DragonFly committer 列表历史变化；kernel@ 邮件列表中权限授予/撤销的公告；Dillon 关于权限管理的设计说明 ［A］

**史观**：总纲第 5 条——组织结构塑造技术路径：Dillon 主导的权限管理直接塑造了 DragonFly 的开发者构成与技术连贯性

**辨析**：个人主导的权限管理并非“任人唯亲”——Dillon 授予权限的标准虽个人化但有其一致性，需结合具体案例辨析；具体争议点：1) “个人化但有其一致性” 的判定须以 dragonfly.duckdb dragonfly-src 仓库 contributors 表中 Dillon 授予 committer 权限的时间序列与各 committer 的 commit 主题分布核验——若授予权限的 committer 后续 commit 集中在特定子系统（如 LWKT、HAMMER、网络栈），则反映 Dillon 的权限授予与其技术判断一致；2) “任人唯亲” 的判定须以邮件列表中公开的权限授予/撤销公告与 committer 实际贡献核验，避免以 “个人主导” 简化为 “任人唯亲” [考据完成：2026-08-15 经 DragonFlyBSD kernel@ 邮件列表 2003-07-22 邮件（message_id=200307221855.h6MItwsH032647@apollo.backplane.com，Matthew Dillon “Call for Developers! Userland threading”）一手证据确证：Dillon 明确表示"I would like to hand-out some commit bits for those doing the work“和”I would like to find one developer to act as the head-honcho"，证实 commit bit 授予为项目参与驱动的非正式机制，无成文文档标准]。0 信任原则应用维度：author 字段可伪造（dragonfly.duckdb author_email 须与 committer 字段交叉验证）、权限授予时间须以 commit 首次出现时间核验（非以公告时间）、committer 字段可能因迁移遗漏早期贡献者。考据留痕至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8v 节

**文献**：DragonFly committer 列表；kernel@ 邮件列表档案；DragonFly 项目 FAQ ［A］

## 221.3.3 与 FreeBSD/OpenBSD 权限模型的比较

**要点**：FreeBSD 采用 Core Team 选举+Foundation 治理的双重权限模型；OpenBSD 采用 de Raadt 主导+committer 集体讨论的混合模型；DragonFly 采用 Dillon 个人主导的单一模型，三者各有优劣

**史料**：FreeBSD Core Team 选举记录；OpenBSD committer 权限管理记录；DragonFly committer 权限管理记录 ［A］

**史观**：总纲第 5 条——组织结构塑造技术路径：三种权限模型分别塑造了 FreeBSD 的“社区 + 基金会”文化、OpenBSD 的“安全审计”文化、DragonFly 的“小而美”文化

**辨析**：权限模型的优劣无绝对标准——需结合项目规模、社区文化、技术目标等多维度辨析；具体争议点：1) FreeBSD “Core Team 选举+Foundation 治理” 与 DragonFly “Dillon 个人主导” 的比较须以具体决策案例（如 FreeBSD 5.x SMPng 路线决策 vs DragonFly LWKT 路线决策）核验决策效率与社区接受度，避免抽象 “优劣” 判定；2) OpenBSD “de Raadt 主导+committer 集体讨论” 与 DragonFly “Dillon 个人主导” 的比较须警惕 “de Raadt 主导” 与 “Dillon 主导” 的表面相似性掩盖实质差异——OpenBSD 的 committer 集体讨论机制在 DragonFly 中无对应，二者非同质模型 [存疑脚注：FreeBSD Core Team 选举记录的完整档案须以 FreeBSD Foundation 官方文档核验，部分早期选举记录可能未数字化]。0 信任原则应用维度：Core Team 选举记录可能不完整（须以邮件列表交叉印证）、committer 权限管理记录可能因迁移遗漏（须以 commit log 核验）、“社区文化” 判定属群体特征概括须警惕刻板印象。考据留痕至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8w 节

**文献**：FreeBSD Core Team 选举记录档案；OpenBSD misc@ 邮件列表档案；DragonFly kernel@ 邮件列表档案 ［A］
