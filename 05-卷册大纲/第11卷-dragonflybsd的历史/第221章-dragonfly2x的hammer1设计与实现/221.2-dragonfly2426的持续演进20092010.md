# 220.2 DragonFly 2.4-2.6 的持续演进（2009-2010）——2.4 引入 devfs 改进、2.6 引入 SMP 可扩展性改进


## 220.2.1 devfs 改进
  - 要点：DragonFly 2.4（2009 年发布）对 devfs 进行改进，包括设备命名规则、设备发现机制与权限模型的优化，使设备文件系统更接近现代 BSD 的实现风格

  - 史观：总纲第 17 条——软件工程：devfs 改进反映了 DragonFly 在工程实践层面对设备文件系统抽象的持续优化
  - 辨析：devfs 改进与 FreeBSD 7.x/8.x 同期 devfs 修订的相互影响需考据——DragonFly 与 FreeBSD 4.x 共享代码已逐渐减少，但 devfs 设计理念可能仍有借鉴；【0 信任原则·commit 量不等于质量】2009 年 commit 量 3,748 条为 2.x 时代高位，但 devfs 改进仅占其中一部分，须结合 commit message 主题词核验

## 220.2.2 SMP 可扩展性改进
  - 要点：DragonFly 2.6（2010 年发布）引入 SMP 可扩展性改进，主要在 LWKT 与 token 机制基础上进一步优化多核扩展性，宣称部分场景下线性扩展性优于 FreeBSD 8.x
  - 史料：DragonFly 2.6 release notes；SMP 性能 benchmark 邮件；kernel@ 与 users@ 邮件列表讨论；dragonfly.db 查询 L1.1.1 显示：dragonfly-src 2010 年 commit 量 3,081 条，反映 2.6 发布年开发强度 ［A］
  - 史观：总纲第 7 条——硬件与软件辩证：多核硬件普及推动 DragonFly 在 SMP 可扩展性上的持续投入
  - 辨析：benchmark 方法的争议——测试场景选择、硬件配置、测量指标的不同会导致结论差异，需对照独立第三方测试结果；【0 信任原则·commit 量不等于质量】2010 年 commit 量 3,081 条含 SMP 可扩展性改进的 LWKT/token 优化 commit，性能声称须结合独立 benchmark 核验

## 220.2.3 与 FreeBSD 8.x 技术进展的比较
  - 要点：FreeBSD 8.x（2009-2012）同期引入 SMPng 成熟、ULE 调度器改进、ZFS 集成、DTrace 等技术，DragonFly 2.4-2.6 在多核扩展性上有局部优势，但在生态、驱动支持、用户规模上明显落后
