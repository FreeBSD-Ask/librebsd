# 218.3 与同时期操作系统的比较：2003-2026 年同期 Linux 内核（Linus Torvalds 维持独裁模式，无重大 fork 成功）、OpenBSD（Theo de Raadt（西奥·德·若特） 1995 年从 NetBSD fork，与 DragonFly 形成对照）、NetBSD（被 fork 后仍持续演进）、illumos（2010 年从 OpenSolaris fork）——DragonFly 是 BSD 系 fork 中存活时间较长但效应力有限的项目

## 218.3.1 Linux 内核独裁模式与 fork 失败

**要点**：Linux 内核在 Linus Torvalds 的独裁治理下自 1991 年起 35 年间无成功 fork——主要 fork 尝试包括 GNU Linux-libre（移除非自由固件，1984 哲学差异）、Android AOSP（Google 主导，2005 起，使用 Linux 内核但用户态独立）、linux-next（Stephen Rothwell 维护，集成测试分支非 fork）。Linux 的“不分裂”部分归因于 GPL copyleft 强制回馈（企业贡献回流上游）与 Torvalds 个人权威（“don't break userspace”原则 33 年维持）

**史料**：Linux 内核 fork 尝试记录（kernelnewbies.org/LinuxVersions）；Torvalds 关于 fork 的公开声明（lkml.org 邮件列表存档）；freebsd.duckdb freebsd-src 仓库 tags 表（FreeBSD 5.x-15.x release 序列对照 DragonFly v1.x-v6.4.x）

**史观**：总纲第 3 条——不存在进步只有权力再分配：独裁模式与 fork 倾向的关系——Linux 35 年无成功 fork vs BSD 1996-2003 年间 2 次重大 fork（OpenBSD/DragonFly），差异的原因包括：①GPL copyleft 强制回馈使企业贡献回流 Linux 上游，BSDL 允许企业 fork 后不回馈；②Linux Foundation 2007 年注册提供法律实体支撑，DragonFly 无 Foundation；③Torvalds 33 年单一领导 vs FreeBSD Core Team 9 届换届造成的路线连续性差异

**辨析**：Linux“无成功 fork”是否忽略 Android AOSP——AOSP 使用 Linux 内核但用户态独立，内核层面未 fork，严格意义不属于 Linux 内核 fork；GNU Linux-libre 移除非自由固件但未分化技术路线，属于意识形态分支而非技术 fork；“成功 fork”的判定标准须明确（社区规模、技术分化、独立治理），不得模糊表述。具体争议点：①版本号误载——AOSP 起始年份有 2005 年与 2008 年两种说法（Open Handset Alliance 2007-11 发布 Android SDK 0.1 预览版，2008-09-23 Android 1.0 SDK Release），bsd_commits.duckdb 无 AOSP 仓库 commit 记录，须经 Android Source Project 官方文档核验；②日期差异——Linux-libre 2010 年首发布（由 Alexandre Oliva 维护，FSF Latin America 推广），与 1984 哲学差异表述属意识形态分支而非技术 fork，须以 fsfla.org 邮件列表存档核验；③人物归属分歧——Linux 内核“独裁”治理归因于 Torvalds 个人权威还是 GPL copyleft 法律结构，社区言论属当事人立场，须与 Linux Foundation 治理章程交叉验证 〔存疑：AOSP 起始年份与 Linux-libre 首发布日期未经联网复核〕。0 信任原则应用维度：author 字段可伪造（Linux fork 尝试记录的社区言论属当事人立场，须与 lkml.org 邮件列表存档 committer 字段交叉验证）、tagger_date 与实际发布日期可能偏差（Linux-libre 2010 首发布 tagger 须经 bsd_commits.duckdb 或 fsfla.org 核验，AOSP 早期 tagger_date 须经 Android Source Project 官方 tag 核验）、关键词匹配局限（fork 关键词搜索可能遗漏以 “split” “branch” “divergence” 等同义词为关键词的 lkml.org 邮件讨论，须以邮件列表原文核验）。考据留痕至 `03-原始史料库/06-考据记录/20260730_jianyi缺口补全考据.md` 8av 节

## 218.3.2 OpenBSD 1995 年 fork 的存活对比

**要点**：openbsd.duckdb openbsd-src 仓库 commits 表显示 OpenBSD 自 1995 年（1995-10-18 OpenBSD 1.0）fork 后约 31 年间持续维护，建立安全细分市场领导地位（pledge/unveil 2015 起、LibreSSL 2014 起、OpenSSH 1999 起）。DragonFly 自 2003 年 fork 后 23 年间持续维护但未建立类似明确细分市场——LWKT 消息传递、HAMMER/HAMMER2、vkernel 三大创新均未被业界主流采纳。openbsd.duckdb 显示 OpenBSD 2024 年 commit 5097 条（dragonfly.duckdb 单源同口径统计，未经第二来源交叉；与 DragonFly 2024 年 277 条约为 18.4 倍） vs DragonFly 2024 年 277 条，社区规模差距显著

**史料**：dragonfly.duckdb dragonfly-src/openbsd-src 仓库 commits 表（按年统计对照）；OpenBSD 1995 fork 公告（openbsd.org/）；DragonFly 2003 fork 公告（lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html）；OpenBSD 项目历史（openbsd.org/）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 8 条——本体论上各方平等：fork 后的细分市场定位决定存活——OpenBSD 选择“安全细分市场”（pledge/unveil/LibreSSL/OpenSSH）建立不可替代性，DragonFly 选择“消息传递架构 + 个人主导文件系统”细分市场但未获业界采纳；dragonfly.duckdb 数据反映细分市场选择对社区规模的直接影响

## 218.3.3 illumos 2010 年 fork 的路径比较

**要点**：illumos 2010 年从 OpenSolaris fork（Oracle 关闭 OpenSolaris 后 Garrett D'Amore（加勒特·达莫尔） 创建 illumos），与 DragonFly 类似是个人主导的 fork。illumos 在企业存储市场（OmniOS、SmartOS、OpenIndiana 等发行版）有一定应用——SmartOS 由 Joyent 维护用于云生产部署、OmniOS 由 OmniOS 社区维护用于存储服务器。illumos-gate.duckdb 不包含 illumos 仓库，illumos commit 统计须以 github.com/illumos/illumos-gate 核验

**史料**：illumos 2010 fork 公告（illumos.org/）；OmniOS 项目记录（omnios.org/）；SmartOS 项目记录（smartos.org/）；OpenSolaris 关闭历史（oracle.com 2010-08 公告［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）；dragonfly.duckdb dragonfly-src 仓库 commits 表（DragonFly 2010 年起 commit 序列对照 illumos 同期）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律：fork 后的延续路径多样——illumos fork 后通过企业支持（Joyent/SmartOS）建立生产部署场景，DragonFly fork 后缺乏企业支持（无 Foundation、无企业发行版）未建立类似生产场景；二者 fork 后延续路径差异反映组织支撑对项目存活的影响

**辨析**：illumos 与 DragonFly 的可比性须考虑 Solaris 与 BSD 的生态差异——Solaris 由 Sun Microsystems 企业团队设计（ZFS/DTrace/Zones 均企业级），illumos fork 继承企业级技术资产；DragonFly 由 Dillon 个人设计（LWKT/HAMMER/vkernel 均个人项目），fork 起点技术资产规模不同；二者 fork 路径比较须以“个人主导 fork + 企业支持 vs 个人主导 fork + 无企业支持”为对照维度
