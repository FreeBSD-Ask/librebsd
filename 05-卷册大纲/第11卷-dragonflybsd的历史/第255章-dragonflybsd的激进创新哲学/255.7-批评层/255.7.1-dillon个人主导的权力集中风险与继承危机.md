# 255.7.1 Dillon 个人主导的权力集中风险与继承危机


> 105.1-105.6 节梳理了 DragonFly BSD 激进创新哲学、社区治理、多元贡献、外部批评、重要贡献者与跨项目比较的事实性叙事，本节补足四层辩证链的批评层——外部观察者、被疏远贡献者、FreeBSD/NetBSD/OpenBSD/Linux 社区对 DragonFly 哲学文化与社区的四维批评，确保批评者阵营论点完整呈现。DragonFly 规模小于 OpenBSD，被疏远贡献者的具体公开回应存档更为有限，部分论点标注 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。

**要点**：对 DragonFly Dillon 个人主导模式的批评集中于权力集中与继承危机两个维度——其一，权力集中风险：Dillon 作为 founder 对技术路线拥有最终裁定权，DragonFly 项目未如 FreeBSD Core Team 那样建立制度化的选举与制衡机制（9 人核心团队，2000 年起直选制），亦未如 NetBSD Foundation 那样建立正式的董事会议事规则，亦未如 OpenBSD Foundation 那样于 2007 年注册加拿大非营利法律实体——dragonfly.duckdb dragonfly-src 仓库 commit_files 表显示 sys/kern/lwkt_thread.c 首次引入 commit `8ad65e080342`、sys/vfs/hammer/ 首次引入 commit `8750964d1997`、sys/platform/vkernel/ 首次引入 commit `39619464950a` 等核心子系统首引 commit 均由 Dillon 一人提交，Dillon（合并 10666 条 commit，2003-06-17 至 2026-06-10）在 LWKT、HAMMER、HAMMER2、vkernel 等核心子系统设计中是唯一决策者；其二，继承危机：Dillon 在 FreeBSD Core Team 中曾属边缘者（2003 年因争议失去提交权限触发 fork），在 DragonFly 中转为绝对中心——DragonFly 项目未建立公开的 BDFL 继任机制（对比 Linux Torvalds 公开提及的“副手梯队”或 Python PEP 13 治理委员会），Dillon 退出后 DragonFly 的治理结构与核心子系统维护能力能否维持是未知数；dragonfly.duckdb 显示 Dillon 在 2026 年的 commit 数量较 2005 年峰值已大幅下降，2024 年 277 条年度 commit 中 Dillon 本人贡献占比［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］，须以 commits 表 author_email 按年统计核验；DragonFly 项目资产（域名 dragonflybsd.org、git 仓库 gitweb.dragonflybsd.org、镜像站点）的法律所有权归属不明 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］——dragonflybsd.org/foundation/ 页面截至 2026-07-22 返回 404，无法从官方来源核实 Foundation 注册年份与章程文本

**史观**：总纲第 5 条——没有必然性，只有偶然性：Dillon 个人偏好与历史经验（2003 年被 FreeBSD Core Team 撤权）直接塑造 DragonFly 单一决策核心治理形态，单一领导者的人格与判断偶然地决定了项目的治理结构，而非制度化的集体决策机制；总纲第 13 条——法律与道德是利益分配：committer 权限的授予与撤销、核心技术决策的裁定权本质上是一种利益分配机制，谁获得决策权、谁被排除在决策之外，反映 DragonFly 项目内部权力运作的具体形式

**辨析**：批评的合理性在不同叙事中评估不一——DragonFly 阵营将 Dillon 个人主导视为“决策效率与一致性保障”，批评者将其视为“权力集中与继承风险”，二者难以通约；【0 信任原则·权力集中风险的量化】“权力集中风险”论证须提供具体案例——若 DragonFly 在 23 年间未发生实际的权限滥用事件或大规模 committer 退出潮，则“风险”可能是理论推演而非实践问题，但 dragonfly.duckdb 显示 Sonnenberger（2038 条）2008 年转向 NetBSD、Sepherosa Ziehau（4834 条）2021 年淡出、Hsu（280 条）2007 年停止、Pandya（503 条）2007 年淡出，多位早期贡献者的退出时点与 Dillon 个人决策周期存在相关性 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；【0 信任原则·继承危机的辨析】Dillon 年龄增长是事实，但年龄不等于能力衰退——dragonfly.duckdb 显示 Dillon 2026-06-10 仍有 commit，其持续活跃度须以年度 commit 统计核验而非以年龄推演；【多源交叉验证不可靠性规则】多个 DragonFly 外部观察者对 Dillon 个人主导模式的批评在多个独立来源中一致，但这一一致性可能源于对 BDFL 模式的共同前理解而非独立验证，须对照 DragonFly 实际治理产出（如 23 年 release 节奏、committer 加入退出记录）综合评估
