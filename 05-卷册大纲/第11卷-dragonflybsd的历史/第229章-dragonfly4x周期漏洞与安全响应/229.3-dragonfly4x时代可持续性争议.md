## 229.3.1 批评层——DragonFly 4.x 时代项目可持续性的批评（2014-2017）

**要点**：DragonFly 4.x 时代（2014-11-23 至 2017-08-01）bsd_commits.duckdb dragonfly-src 仓库数据显示三类可持续性批评具有量化基础。其一，“社区规模持续缩小”批评——bsd_commits.duckdb 显示活跃 committer 数从 2014 年 33 人降至 2018 年 24 人（降幅 27.3%），同期 freebsd-src 仓库 commit 量是 dragonfly-src 的 7.0-8.8 倍（2014 年 15435/2205、2017 年 16157/1888、2018 年 14957/1706），Linux 内核同期 commit 量更数倍于 FreeBSD，BSD 阵营与 Linux 阵营均有观察者据此判断 DragonFly 社区已不足以维持长期工程动员。其二，“Matt Dillon 单人维护风险加剧”批评——bsd_commits.duckdb 显示 2016-2018 年间 Dillon（`dillon@apollo.backplane.com` 邮箱）commit 量 1243 条占同期 dragonfly-src 仓库总 commit 量约 18.9%，HAMMER2 关键词 2017 年峰值 119 条 commit 几乎全部由 Dillon 贡献，HAMMER2、LWKT、内核 SMP 可扩展性三大核心子系统均以 Dillon 为设计主导，巴士因子（bus factor）逼近 1；DragonFly 无 Core Team 选举机制、无 Foundation 法律实体（**dragonflybsd.org/foundation/** 返回 HTTP 404），Dillon 个人若停止贡献则上述子系统将面临设计权威真空。其三，“与现代 FreeBSD/Linux 技术差距扩大”批评——bsd_commits.duckdb 显示 DragonFly 4.x 周期未引入类似 FreeBSD 11.0（**2016-09-23** release/11.0.0 tag）的 arm64 Tier-2 支持、bhyve 改进、Clang/LLVM 默认编译器（FreeBSD 10.0 起）等重大新特性，亦未引入类似 OpenBSD 5.9（**2016-03-29** 发布）的 **pledge(2)** 与 OpenBSD 6.4（**2018-10-15** 发布）的 **unveil(2)** 主动安全机制；bsd_commits.duckdb 显示 DragonFly 2016-2018 年间 NVMe 关键词 commit 仅 34 条、UEFI 支持在 v4.6.0（**2016-08-01**）才以 preliminary 形式引入，FreeBSD 同期 UEFI 支持已进入成熟阶段，技术广度差距在 4.x 周期末段进一步显化

## 229.3.2 反批评层——DragonFly 阵营的工程实用主义与多元路径回应（2014-2017）

**要点**：DragonFly 阵营（以 Matt Dillon 的工程实践与 DragonFly 4.6/4.8/5.0 Release Notes 为代表）对三类可持续性批评提出三层回应。其一，“小社区仍能产出高质量代码”回应——dragonfly.duckdb 显示 2014-2017 年间 DragonFly TOP 5 贡献者（Wildner 2391 条、Dillon 1609 条、Kusumi 1151 条、Sepherosa 1105 条、Tigeot 641 条）合计占同期 dragonfly-src 仓库总 commit 量约 70.6%，反映小社区的核心团队稳定输出；DragonFly 4.6 Release Notes 经 WebFetch 一手核验原文记载"home-grown support for NVMe controllers, preliminary EFI support, improvements in SMP and networking performance under heavy load, and a full range of binary packages"，确认 4.x 周期 DragonFly 自研 NVMe 驱动在 2xE5-2620v4 测试服务器上达到约 1.05M IOPS @4K 与约 6.5 GBytes/sec @32K；Dillon 在 2017-02-24 users@ 邮件列表（**lists.dragonflybsd.org/pipermail/users/2017-February/313242.html**）发布的“Update on status of master - NUMA and cache-line locality”一文中明确记载 4.8 周期 NUMA 感知优化在双路 Xeon 16 核 32 线程测试机上实现 13M VM faults/sec、135000 execs/sec、20M stat()/sec、25 GBytes/sec 内存分配与回收，相对 5 个月前合成测试 workload 约 5% 整体改进与 vkernel 在多 CPU 场景下超过 40% 改进，反映小社区在内核 SMP 可扩展性上的工程深度。其二，“HAMMER2 证明创新能力”回应——dragonfly.duckdb 显示 HAMMER2 关键词 2016-2018 年 commit 共 233 条（2016 = 39、2017 = 119、2018 = 75），Dillon 在 2017 年达到 HAMMER2 投入峰值年（119 条 commit）并于 v5.0.0（**2017-10-15** 发布）将 HAMMER2 首次引入可启动状态；DragonFly 5.0 Release Notes 经 WebFetch 一手核验原文记载"DragonFly version 5.0 brings the first bootable release of HAMMER2, DragonFly's next generation file system“与”single-image HAMMER2 support, with live dedup (for cp's), compression, fast recovery, snapshot, and boot support"，确认 HAMMER2 作为 DragonFly 自研的下一代文件系统在 4.x 周期末段进入生产部署起点，体现小社区的工程创新能力——BSD 阵营中 OpenZFS 由跨项目协作维护，HAMMER2 由 DragonFly 自研，二者在本体论上平等。其三，“可持续性不等于市场规模”回应——dragonfly.duckdb 显示 DragonFly 4.x 周期 14 年（2003-2017）持续发布，无中断、无 abandoned 状态；DragonFly 官方历史页面（**<https://www.dragonflybsd.org/history/**>）经 WebFetch 一手核验原文记载"From a performance perspective DragonFly's only real competitor these days is Linux"——DragonFly 阵营以“与 Linux 同级比较”的工程目标替代“与 FreeBSD 同级比较”的市场规模目标，主张可持续性的衡量标准应是“项目能否持续实现自身工程目标”而非“项目能否匹配 FreeBSD/Linux 的工程动员能力”
