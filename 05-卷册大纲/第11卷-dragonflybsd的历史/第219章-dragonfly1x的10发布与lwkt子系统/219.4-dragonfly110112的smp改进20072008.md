# 219.4 DragonFly 1.10-1.12 的 SMP 改进（2007-2008）——1.10 引入 token 机制替代锁、1.12 改进多核性能

## 218.4.1 token 机制的设计与实现

**要点**：DragonFly 1.10（2007-08-06）引入 token 机制替代传统 mutex——token 是 LWKT 框架下的轻量级同步原语，让线程在持有时可被抢占；token 由 Dillon 设计，避免 mutex 的死锁与优先级反转问题；token 是 DragonFly 区别于其他 BSD 的关键同步机制

**史料**：Dillon 的 token 设计文档；DragonFly 邮件列表 token 讨论；DragonFly 源码 sys/sys/lwkt_token.h ［A］

**史观**：总纲第 17 条——软件工程：token 机制是软件工程中“避免锁竞争”哲学的极致实现

**辨析**：token 与 mutex 的性能对比缺乏权威基准——需对照同硬件同负载核验；token 的实际死锁避免效果需考据

**文献**：DragonFly token 设计文档；Dillon 邮件列表发言；DragonFly 源码 ［A］

## 218.4.2 token 与 FreeBSD mutex 的比较

**要点**：FreeBSD mutex 是传统自旋锁/睡眠锁，持有时不可抢占；DragonFly token 是 LWKT 框架下的轻量级同步原语，持有时可被抢占；token 让 DragonFly 在多核扩展性上优于 mutex，但学习曲线较陡

**史料**：FreeBSD mutex 设计文档（FreeBSD kernel mutex(9) 手册页、Baldwin SMPng 实现文档）；DragonFly token 设计文档（Dillon token 设计文档、DragonFly 源码 `sys/sys/lwkt_token.h`）；FreeBSD 与 DragonFly 同步机制对比；bsd_commits.db dragonfly-src 仓库 commits 表与 commit_files 表（路径 `d:\librebsd\03-原始史料库\01-代码仓库史料\01-数据库本体\`，含 token 机制 1.10 引入 2007.8.6、sys/sys/lwkt_token.h 路径 commit 演化）；DragonFly BSD 邮件列表存档（**<https://www.dragonflybsd.org/mailinglists/**，kernel@> 关于 token vs mutex 的讨论）；DragonFly BSD Release Notes（**<https://www.dragonflybsd.org/releases/**，1.10> Release Notes token 部分）；Dillon fork 公告（**<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html**）；HAMMER> 设计 PDF（**<https://www.dragonflybsd.org/hammer/hammer.pdf**）[三角验证：bsd_commits.db> + 邮件列表 + Release Notes] ［A］

**史观**：总纲第 6 条——技术路线分化：mutex 与 token 的根本分歧反映 FreeBSD 与 DragonFly 的技术路线分化

**辨析**：mutex 与 token 的性能对比在不同基准测试中差异较大——需对照同硬件同负载核验；token 的实际采用难度需考据

**文献**：FreeBSD mutex 文档；DragonFly token 文档；BSD 同步机制对比研究[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]

**史料**：DragonFly 1.12 Release Notes SMP 部分；DragonFly 邮件列表 SMP 讨论；CVS commit log ［A］
