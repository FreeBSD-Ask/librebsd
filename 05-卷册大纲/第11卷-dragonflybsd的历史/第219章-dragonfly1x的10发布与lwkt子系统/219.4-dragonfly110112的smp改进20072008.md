# 219.4 DragonFly 1.10-1.12 的 SMP 改进（2007-2008）——1.10 引入 token 机制替代锁、1.12 改进多核性能

## 219.4.1 token 机制的设计与实现

**要点**：DragonFly 1.10（2007-08-06）引入 token 机制替代传统 mutex——token 是 LWKT 框架下的轻量级同步原语，让线程在持有时可被抢占；token 由 Dillon 设计，避免 mutex 的死锁与优先级反转问题；token 是 DragonFly 区别于其他 BSD 的关键同步机制

**史料**：Dillon 的 token 设计文档；DragonFly 邮件列表 token 讨论；DragonFly 源码 sys/sys/lwkt_token.h ［A］

**史观**：总纲第 17 条——软件工程：token 机制是软件工程中“避免锁竞争”哲学的极致实现

**辨析**：token 与 mutex 的性能对比缺乏权威基准——需对照同硬件同负载核验；token 的实际死锁避免效果需考据

**文献**：DragonFly token 设计文档；Dillon 邮件列表发言；DragonFly 源码 ［A］

## 219.4.2 token 与 FreeBSD mutex 的比较

**要点**：FreeBSD mutex 是传统自旋锁/睡眠锁，持有时不可抢占；DragonFly token 是 LWKT 框架下的轻量级同步原语，持有时可被抢占；token 让 DragonFly 在多核扩展性上优于 mutex，但学习曲线较陡

**史料**：FreeBSD mutex 设计文档（FreeBSD kernel mutex(9) 手册页、Baldwin SMPng 实现文档）；DragonFly token 设计文档（Dillon token 设计文档、DragonFly 源码 `sys/sys/lwkt_token.h`）；FreeBSD 与 DragonFly 同步机制对比；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `d:\librebsd\03-原始史料库\01-代码仓库史料\01-数据库本体\`，含 token 机制 1.10 引入 2007.8.6、sys/sys/lwkt_token.h 路径 commit 演化）；DragonFly BSD 邮件列表存档（**<https://www.dragonflybsd.org/mailinglists/**，kernel@> 关于 token vs mutex 的讨论）；DragonFly BSD Release Notes（**<https://www.dragonflybsd.org/releases/**，1.10> Release Notes token 部分）；Dillon fork 公告（**<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html**）；HAMMER> 设计 PDF（**<https://www.dragonflybsd.org/hammer/hammer.pdf**）[三角验证：dragonfly.duckdb> + 邮件列表 + Release Notes] ［A］

**史观**：技术路线分化：mutex 与 token 的根本分歧反映 FreeBSD 与 DragonFly 的技术路线分化

**辨析**：mutex 与 token 的性能对比在不同基准测试中差异较大——需对照同硬件同负载核验；token 的实际采用难度需考据

**要点**：

- DragonFly 1.10（2007 年发布）被 Dillon 概括为无大事件型版本：几乎系统各层面均为清理，包括新 AHCI SATA 驱动与磁盘抽象层、GPT 与 64 位磁盘标签的非引导支持、内核态轻量线程与两套线程库（默认沿用原 BSD 线程库，年末起转向基于轻量线程设施的一对一线程库）、大量新 USB/PCI 与无线驱动及应用、内核、编译器更新；发布同时使 VFS API 更为健壮，可热拔 USB 硬盘并事后卸载而不崩内核，此项工作直接构成用户态 VFS 的前提。（BSDTalk EP125，[63.54-246.44]，L1）
- 对分叉五年（2002-2007）的回顾与自评：1.10 之前的重写皆为设计意图或聚群前提——轻量级线程、内核线程调度器、可插拔用户调度器与调度掩码多出自 Dillon 本人构想，名字缓存拓扑与 VFS 操作改造为实现聚群所必经；组织层面开发者团队过去一年的增长超过此前两年之和，出现更多真正提交代码者，年初以来约一千五百次提交，pkgsrc 兼容性一年间显著改善。他同时坦承进展远慢于当初预期，主因是未能预见工作量之巨、内核内部重构耗时尤甚，且大量时间耗于管理开发者、管理提交与追踪缺陷等辅助事务；DragonFly 不再是实验性分叉——稳定性记录足以支撑生产系统，加上 pkgsrc 提供所需应用，在生产范式下与其他 BSD 及 Linux 大致等价，后续将以新文件系统为先，因为没有聚群文件系统就没有聚群。（BSDTalk EP125，[436.08-633.30]，L1）
- 新文件系统于访谈时刚过基本设计阶段（记录索引方案尚待定）并已开始编码，目标年底完成，定位为 BSD 与 Linux 竞争所急需的拼图。其设计原则：内部记录导向，使流式备份与活镜像的复制算法大为简化；文件系统原生维护全部变更历史，复制数据可直接取自文件系统本身而无需维护独立变更队列，从而可在慢速链路上复制、支持备份目标间歇离线（如周末上线续传）而不在主端积压数据；快照能力因记录结构而近乎免费，设计目标覆盖备份、活镜像、热切换与多主操作，且不因网络故障或慢链路拖慢生产系统。（BSDTalk EP125，[675.05-1058.56]，L1）
- vkernel 被评为开发过程中无价的基础设施：单处理器版早已可用，社区成员提议将其 SMP 化且实现不难，现有版本可构建为 SMP 虚拟内核；虽用于生产运行效率不高，却是调试内核代码与在安全环境中开发内核的利器。关于多处理器现状，Dillon 坦承 1.10 基准预计与 1.8 相当：系统调用路径在触及文件描述符之前已 MP safe（1.10 发布后关闭了两个相关 sysctl），但数据子系统仍受大内核锁保护；内核虽支持 31 个 CPU，大内核锁的串行化使其在四 CPU 以上难以扩展，除非将其彻底移除。（BSDTalk EP125，[284.84-428.52]，L1）

- 主持人片头新闻记载 NetBSD 宣布 2007 年筹款活动，希望至年底至少募集五万美元，为 NetBSD Foundation 当年财务运作的独立旁证史料。（BSDTalk EP125，[31.40-41.64]，L2）
