# 219.1 DragonFly 1.0 的发布（2004.7.12）——Matt Dillon 2003 年 7 月从 FreeBSD 4.8 fork，2004 年 7 月 12 日发布 DragonFly 1.0，确立“轻量级内核”的工程哲学

## 219.1.1 2003 年 fork 动机与 FreeBSD 5.x 分歧

**要点**：2003 年 7 月 Matt Dillon 因与 FreeBSD 5.x SMPng 方向分歧而从 FreeBSD 4.x fork 出 DragonFly——Dillon 认为 SMPng 的细粒度锁路径过于复杂，主张轻量级内核线程与消息传递；fork 时 Dillon 带 FreeBSD 4.x 代码库另起 DragonFly，与 FreeBSD 5.x 平行发展

**史料**：Dillon 在 freebsd-arch@ 关于 SMPng 的讨论；DragonFly fork 公告；FreeBSD Core Team 关于 Dillon 离开的声明；dragonfly.duckdb 查询 L1.1.1 显示：dragonfly-src 2003 年 commit 量 1,007 条（fork 后半年，7-12 月），反映 fork 后开发即刻启动；dragonfly.duckdb 查询 L2.1.Matt_Dillon_forks_DragonFly 显示：fork 后 6 个月（2003-07-01 至 2003-12-31）dragonfly-src 共 953 条 commit（月均 158.8 条），同期 freebsd-src 共 7,045 条 commit（月均 1,174.2 条），DragonFly 月均 commit 量约为 FreeBSD 的 13.5%，反映 fork 后 DragonFly 以小团队启动；dragonfly.duckdb 专门查询 Matt Dillon 个人占比显示：2003 年 Dillon 个人贡献 535 条 commit，占 dragonfly-src 全年 commit 量的 53.13%，反映 fork 初期 Dillon 的绝对主导地位；**统计结论 C-06**——描述性统计.md SubTask 2.1 显示 dragonfly-src 全时段（2003-2026）共 49,280 commits，为 23 仓库中规模较小的 src 仓库；**统计结论 C-19**——推断性统计.md Task 8 SubTask 8.2 配对 Wilcoxon 符号秩检验显示，Matt Dillon fork DragonFly BSD 事件（2003-07）前后各 6 个月 freebsd-src 月度 commit 量存在统计显著差异，前窗（2003-01 至 2003-06）均值 1434.83 高于后窗（2003-08 至 2004-01）均值 1183.33，检验统计量 W = 1.0，p = 0.0464（α = 0.05），效应量 r = 0.8131 属大效应（r > 0.5），统计上拒绝 H₀，即 fork 事件后 FreeBSD 短期 commit 量显著下降；**统计结论 C-27**——推断性统计.md Task 10 Bootstrap 重抽样（B = 2000）显示 dragonfly-src 贡献者 Gini 系数观测值 0.8972，Bootstrap 均值 0.8905，95% CI [0.8517, 0.9187]，CI 宽度 0.0670，反映 dragonfly-src 贡献高度集中于少数开发者（201 位贡献者），Gini 系数在 BSD 4 项目 src 仓库中仅次于 freebsd-src（0.9188），印证 fork 初期 Dillon 个人主导的治理结构特征 ［A］

**史观**：总纲第 4 条——分离与聚合：DragonFly fork 是 BSD 世界中 “分离聚合律” 的又一次重演——技术路线分歧导致组织分离；统计结论 C-19 印证——fork 事件前后 freebsd-src 月度 commit 量统计显著下降（W = 1.0, p = 0.0464, r = 0.8131），反映 Dillon 作为 FreeBSD 核心开发者离开短期内带走了部分 commit 流量，是 “分离” 在 commit 流量层面的量化呈现；统计结论 C-27 印证——dragonfly-src Gini 0.8972 反映 fork 后 DragonFly 贡献高度集中，与 Dillon 个人主导模式互证

**辨析**：fork 的具体动机在不同叙事中存在分歧——技术分歧 vs 个人冲突；Dillon 与 FreeBSD Core Team 的具体矛盾需对照邮件列表核验；【0 信任原则·GitHub 镜像滞后风险】dragonfly-src 为 GitHub 镜像仓库，2003 年 commit 量 1,007 条可能滞后于主仓库（DragonFly 早期使用 CVS，后迁 Git），fork 前 CVS 时代的 commit 在镜像中可能存在日期偏移；【0 信任原则·commit 量不等于质量】L2.1 查询的 953 条 commit 仅反映开发活跃度，fork 后初期 commit 含大量从 FreeBSD 4.x 继承的代码搬运，并非全新开发；【0 信任原则·author 字段可伪造】Dillon 个人占比 53.13% 基于 author_email 字段统计，author 字段可由提交者任意填写，须与 committer 字段交叉验证；【统计显著 ≠ 实际显著·C-19 局限】Wilcoxon 检验仅表明 fork 事件前后 commit 量差异的统计显著性，不证明 fork 事件本身导致差异，须结合邮件列表存档、核心开发者访谈等史实证据交叉验证；【样本量极小】C-19 配对样本仅 6 对（N = 6），p 值与 Z 统计量基于正态近似，小样本下可能不准确；【p 值临界】C-19 p = 0.0464 接近 α = 0.05，若做 Bonferroni 校正（2 事件比较，α'= 0.025），则不拒绝 H₀，结论稳健性较弱；【混淆变量未控制】fork 事件前后的 commit 量变化可能受其他因素影响（如 release 周期、季节性、其他核心开发者变动），Wilcoxon 检验不控制混淆变量；【多重比较风险】C-19 与 C-27 同源 dragonfly.duckdb dragonfly-src 仓库，跨章引用时存在多重比较风险；【Bootstrap CI 假设】C-27 Bootstrap 假设样本对总体有代表性，dragonfly-src 201 位贡献者是否代表 BSD 项目总体须辨析；freebsd-src 与 dragonfly-src 的 Bootstrap CI 略重叠，二者贡献集中度差异不显著

## 219.1.2 1.0 的开发历程与里程碑

**要点**：DragonFly 1.0（2004.7.12 发布）是 fork 后首个正式 release；1.0 包含 LWKT 子系统、token 机制雏形、FreeBSD 4.x 兼容性；开发历时约 12 个月（2003.7-2004.7.12），由 Dillon 个人主导；1.0A 于 2004.7.14 发布作为快速修正版

**史料**：DragonFly 1.0 Release Notes；DragonFly 1.0 RELEASED 公告（**lists.dragonflybsd.org/pipermail/kernel/2004-July/212809.html**，Dillon 2004.7.12，标题“DragonFly-1.0 RELEASED!”）；DragonFly 1.0A 公告（**lists.dragonflybsd.org/pipermail/kernel/2004-July/212852.html**，2004.7.14，1.0 快速修正版）；DragonFly commit log；Dillon 在 users@ 关于 1.0 的发言；dragonfly.duckdb dragonfly-src 仓库无 v1.0 系列 tag，1.0 发布日期 2004.7.12 须与 Dillon 原始公告邮件交叉验证；dragonfly.duckdb 查询 L1.1.1 显示：dragonfly-src 2003 年 commit 量 1,007 条（7-12 月），2004 年 commit 量 3,366 条（全年，1.0 发布于 7 月 12 日），反映 fork 后首年开发强度；据 2026-07-23 公告考据（详见 `原材料/研究/考据记录/20260723_announcements-dragonfly.md`），DragonFly BSD 自 1.0（2004-07-12）至 6.4.2（2025-05-09）共发布 80 条 RELEASE 公告，1.0 公告 URL 经多源交叉验证为 `lists.dragonflybsd.org/pipermail/kernel/2004-July/212809.html` ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界：DragonFly 1.0 的开发体现“实践先于理论”——先 fork 再逐步建立理论框架

**辨析**：经 dragonfly.duckdb dragonfly-src 仓库 tags 表查询，无 v1.0、v1.0.0 或 v1.0A 系列 tag——DragonFly 1.0 时期的 release tag 在数据库 GitHub 镜像中缺失，可能与早期 CVS 仓库迁移至 GitHub 时未完整同步 tag 有关；1.0 发布日期 2004-07-12 经 2026-08-15 邮件列表库双库核查确认——Dillon 在 kernel@ 列表发布 DragonFly-1.0 RELEASED!（Message-ID <200407121832.i6CIWZ0K088095@crater.dragonflybsd.org>），正文称 One year after starting the project as a fork off the FreeBSD-4.x tree。1.0A 存在性经用户报 bug 邮件提及 1.0A release（Message-ID <93B2BF2E-E61D-11D8-85DC-000A95CCCA58@3skel.com>，2004-08-04）获证，精确日期 2004-07-14 须与 DragonFly 官方 Release Notes 交叉验证。1.0 发布日期 2004.7.12 来源于 Dillon 在 kernel@ 邮件列表的 1.0 RELEASED 公告（lists.dragonflybsd.org/pipermail/kernel/2004-July/212809.html），该一手来源可信，但须与 DragonFly 官方 Release Notes 交叉验证；1.0A 于 2004.7.14 发布作为快速修正版（公告 URL **lists.dragonflybsd.org/pipermail/kernel/2004-July/212852.html**），同样无数据库 tag 证据；1.0 与 FreeBSD 4.x 的兼容性程度需考据；【0 信任原则·commit 量不等于质量】2004 年 commit 量 3,366 条仅反映开发活跃度，1.0 的实际功能完整性须结合 Release Notes 与源码核验

## 219.1.3 与 FreeBSD 5.x 同期的对照

**要点**：2003-2005 年间 FreeBSD 5.x 推进 SMPng（细粒度锁）、ULE 调度器、KSE 线程；同期 DragonFly 1.0 选择 LWKT 与 token 机制；两条技术路径在 SMP 设计上根本分歧——SMPng 选择锁，DragonFly 选择消息传递

**史料**：FreeBSD 5.x Release Notes；DragonFly 1.0 Release Notes；SMPng 与 LWKT 设计文档对比［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 8 条——本体论上各方平等：FreeBSD 与 DragonFly 在 SMP 设计上的根本分歧反映两条技术路线的平等并立

**辨析**：SMPng 与 LWKT 的性能对比缺乏权威基准——需对照同硬件同负载核验；ULE 与 DragonFly 调度器的具体差异需考据
