**要点**：

- 2016 年 6 月 29 日录制当日公布 FreeBSD 第九届核心团队选举结果：325 名有资格投票者中 214 人参与，投票率 65.8% 低于往年；Ed Maste 以 84.1% 得票居首，John Baldwin 以 78.5% 回归团队，前九名兼含连任者与新入选者，且人人得票过半；主持人转述章程对第九席出现并列时的特别表决条款，并预告新团队于 7 月 6 日正式接管、卸任成员获公开致谢。（BSD Now EP148，[114.77-321.45]，L2）
- FreeBSD 11.0 发布工程进入冲刺：stable/11 分支创建后 head 切换为 12-CURRENT 并解冻提交，beta1 起可用 freebsd-update 原地升级免于重装，RC1 目标定于 7 月 29 日，首批发布构建将于 8 月下旬开始、公告最早或于 9 月初；主持人指出该时间表较此前版本提前约一个月，并呼吁用户在 alpha/beta 阶段测试冷门硬件以提前暴露缺陷。（BSD Now EP148，[3925.89-4175.32]，L2）
- 容器管理工具 iocage 确认以 Go 重写并计划拆分为提供 JSON API 的 libiocage 与 CLI 前端两个项目，暂无时间表；对听众提出的参照 SmartOS 以单一工具统一管理 jail 与虚拟机之问，直接参与重写的当事人以网络配置相近但启停与磁盘镜像构建逻辑迥异为由持保留态度，倾向待 jail 部分成熟后再评估复用。（BSD Now EP148，[5286.60-5389.42]，L1）
- 1.6 定位以修复为主，修复清单长达两三百条且以文件系统代码居多；基础设施层面完成缓冲缓存的 buffer 与 BIO 拆分（与 FreeBSD 约一年前的做法类似）、彻底废除块编号改用 64 位字节偏移，并将大内核锁显著推进，使多数文件描述符例程已可 MP safe 运行；另含新随机数生成器与 soft updates、NFS、浮点子系统、线程等大量修复。（BSDTalk EP53，[164.24-249.12]，L1）
- Dillon 列出三大目标：userland VFS（允许文件系统作为用户进程运行的 API）、ZFS 移植（依赖 userland VFS，直接移植进内核相当困难）与集群（他称之为最大的一盘棋）；并坦言创立 DragonFly 时未料到集群之前需完成如此大量的内核基础设施工作。（BSDTalk EP53，[293.5-348.74]，L1）
- 集群的正确含义远超 NFS：跨机共享打开文件须做到百分之百缓存一致性，因为单一线程化程序的线程可能分属两台物理机；为此需要类似 SMP 硬件缓存一致性协议的软件机制，把 BSD 传统上对写操作独占整个 v-node 的锁改为按文件的范围锁，由此牵出整条基础设施改造链。（BSDTalk EP53，[354.34-454.78]，L1）
- 部分机制已获实现验证：并行路由表工作正常，线程化网络栈运转良好（性能测试暂不理想，因 MP 锁尚未完全移除）；线程切换时间低于一微秒，进程间消息低于一微秒且可批处理——批模式下首条约一微秒、后续每条仅 10-15 纳秒；这些量化证明使内核能以更模块化、更可调试的方式编写。（BSDTalk EP53，[836.86-894.9]，L1）
- Dillon 自述内核设计立场：既不属于微内核阵营也不属于单整体阵营，支持模块化但承认大型基础设施必须单整体才能获得真实性能，稳定性也要求代码集成于一处——他以 Windows 由五万个厂商提供驱动、兼容性碰运气作反例，自认处于中间地带。（BSDTalk EP53，[895.9-962.0]，L1）

- 总纲3 不存在进步，只有权力再分配：核心团队选举以周期性投票完成治理权力的再分配：连任者与新入选者在同一票池中竞争，交接日期预先公告，权力的存续系于这套形式化程序而非个人威望；投票率低于往年的波动提示参与本身是偶然条件的产物，而非治理制度线性进步的证据。（BSD Now EP148，[157.32-286.22]，L2）
- 总纲10 动手者创造历史：机器人访谈呈现的是边缘实践者驱动的技术扩散：两名自称初学者依靠 IRC 中志愿开发者即时解答与 DTS/FDT 补丁进入基系统，进而反向要求项目补全嵌入式文档、构想设备类 SDK——技术演进由动手者推动，其真实需求构成项目改进的直接动力，而非自上而下的规划。 [订正：原 Bugzilla 报告与 DTS/FDT 补丁（新转写访谈段无 Bugzilla 提及），2026-09-30 SenseAudio 重转核对]（BSD Now EP148，[2682.06-3091.22]，L1）

**辨析**：

- HAMMER 的伪文件系统命名被逐层拆解：@@ 前缀标记伪文件系统或快照，冒号前数字指示主从角色，冒号后为五位数编号；主持人辨析其与 ZFS 数据集概念的错位——HAMMER 以 localization 参数在单棵 B-tree 内切分数据，概念迁移到 ZFS 语汇反而引起混乱，且路径中的冒号会破坏 PATH 环境变量解析，邮件列表已有人提议改换分隔符或引入别名机制。（BSD Now EP148，[3515.45-3905.94]，L2）
- 可复现构建议题上，NetBSD 进度报告达 77.7%、内核已完全可复现，主持人援引该结果并称“所有 BSD 都应尝试做到这一点”（4727.46-4744.98），从安全审计与二进制可溯源出发论证其价值；同时发现 FreeBSD 当周结果异常（0/1 文件），推测是统计页归档故障而非能力缺失，Ed Maste 等人仍在推进。（BSD Now EP148，[4711.29-4783.06]，L2）
- Dillon 自评 1.6 “可能比作为过去稳定性标杆的 FreeBSD 4.x 各版本稳定得多”，该判断出自项目领导者本人，本期无独立基准测试佐证，引用时应视为当事人自评而非第三方测定。 [存疑脚注] 稳定性超越 FreeBSD 4.x 的说法为 Dillon 自我评价，缺乏本期内的可比数据支持。（BSDTalk EP53，[785.14-809.78]，L4）
