# 236.3.1 HAMMER 的 B-tree 写时复制设计

**要点**：HAMMER 文件系统采用 B-tree 结构与写时复制（COW）设计，支持快照、历史记录与数据完整性。dragonfly.duckdb 显示 HAMMER 首引 commit 为 `8750964d1997`（author_date = 2007-10-10T19:37:25Z，Dillon 提交），位于 sys/vfs/hammer/ 目录。其设计目标是在简洁性与功能性之间取得平衡，对比 ZFS 的池化设计与 256MB ARC 最小内存要求，HAMMER 仅需 64MB 内存即可运行

**史料**：Dillon HAMMER 设计文档（dragonflybsd.org/docs/hammer/）；DragonFly 源码 sys/vfs/hammer/ 目录（dragonfly.duckdb commit_files 表 status =‘A’ 首引 commit = 8750964d1997，2007-10-10）；DragonFly mailing list 讨论（lists.dragonflybsd.org，2007-2008 年 HAMMER 开发期）〔L1 代码/构建产物/L2 即时通讯记录/L3 官方文档与公告〕

**史观**：专题语（不设总纲条号）——软件工程文化：HAMMER 的 B-tree + COW 设计在工程上选择 “简洁优先”——64MB 内存最低要求 vs ZFS 256MB ARC，单节点设计 vs ZFS 池化设计，反映 DragonFly 在资源受限场景下的工程取舍；dragonfly.duckdb 显示 HAMMER 由 Dillon 一人首引（commit 8750964d1997），符合 DragonFly “个人主导核心子系统” 的工程文化

**辨析**：HAMMER 与 ZFS 的优劣比较须基于具体工作负载——HAMMER 在单节点、低内存场景下优于 ZFS；ZFS 在多盘池化、高内存场景下优于 HAMMER。dragonfly.duckdb 显示 HAMMER 首引（2007-10-10）早于 ZFS 随 FreeBSD 7.0-RELEASE 的正式引入（2008-02-27），但 HAMMER 设计独立于 ZFS，并非对 ZFS 的简化复制

**文献**：Dillon M. HAMMER File System Design [EB/OL]. 2007. dragonflybsd.org/docs/hammer/；Bonwick J. ZFS: The Last Word in File Systems [C]. USENIX FAST, 2005；dragonfly.duckdb dragonfly-src 仓库 commit_files 表（HAMMER 首引 commit 8750964d1997, 2007-10-10） ［B］
