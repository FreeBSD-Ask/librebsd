## 230.4.2 与 NetBSD tainted code 政策的比较

**要点**：NetBSD 2023 年发布 tainted code policy，明确禁止 AI 生成代码贡献，要求所有 commit 须由人类开发者独立完成；DragonFly 与之形成对照——开放接受 AI 辅助代码，要求人类审核与署名但不禁止。DragonFly 与 NetBSD AI 代码政策对照如下：

    | 维度 | DragonFly | NetBSD |
    |---|---|---|
    | 政策立场 | 开放接受 | 明确禁止 |
    | 发布形式 | Dillon 个人表态 | Core Team 集体审议 |
    | 法律实体 | 无 Foundation | 有 Foundation |
    | 2023 年 commit 量 | 573 条 | — |
    | 考量依据 | 资源约束 + 开发效率 | 法律风险 + 代码质量 |
    | 治理路径 | 个人主导 | 集体审议 |
    两项目政策差异背后的考量：NetBSD 禁止政策基于法律风险（AI 生成代码的版权归属不确定）与代码质量考量（AI 生成代码可能引入隐蔽 bug），DragonFly 开放政策基于资源约束（dragonfly.duckdb 显示 2023 年 commit 量仅 573 条）与开发效率考量
**史料**：NetBSD tainted code policy 公告（netbsd.org 新闻公告 2023）；NetBSD 邮件列表中相关讨论（tech-kern@、source-changes@）；dragonfly.duckdb dragonfly-src 仓库 commits 表（2023 年 commit 量 = 573 条）；DragonFly 邮件列表中相关讨论

**史观**：技术路线分化：freebsd.duckdb 数据显示 DragonFly 2023 年 commit 量 573 条，仅为同期 freebsd-src（14541 条）的 3.9%——资源约束下的开发效率考量是 DragonFly 开放 AI 代码政策的结构性背景；社区治理：NetBSD tainted code policy 经 Core Team 集体审议发布，DragonFly AI 代码政策由 Dillon 个人表态——治理结构差异是政策路径差异的根源

**辨析**：政策差异的考量需考据具体发言——NetBSD 禁止政策的法律风险论证须以 tech-kern@ 邮件列表原文核验 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；DragonFly 开放政策的资源约束论证为推断，Dillon 在 kernel@ 是否明确以资源约束为由开放 AI 代码须单独核验 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；NetBSD tainted code policy 的具体生效日期与执行机制须以 netbsd.org 公告原文为准

## 230.4.3 与 FreeBSD/OpenBSD AI 代码政策的对照

**要点**：FreeBSD 在 2023-2026 年间未发布统一的 AI 代码政策，freebsd.duckdb freebsd-src 仓库 commits 表显示部分 commit 的 message_subject 含‘generated’/‘AI’关键词但未形成政策性标注惯例；OpenBSD 在 misc@ 邮件列表中 de Raadt 与开发者讨论 AI 代码，倾向拒绝 AI 生成代码进入 OpenBSD 主线。四项目 AI 代码政策与 commit 量对照如下：

    | 项目 | AI 代码政策 | 治理结构 | 2024 年 commit 量 | 政策开放度 |

    DragonFly 与 FreeBSD 相对开放，与 OpenBSD 相对保守——dragonfly.duckdb 显示 OpenBSD 2024 年 commit 量 **6512 条** 远高于 DragonFly **277 条**，但 OpenBSD 的保守政策未影响其 commit 量
