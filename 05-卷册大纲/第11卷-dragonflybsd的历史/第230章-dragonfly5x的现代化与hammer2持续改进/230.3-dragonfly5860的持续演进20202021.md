## 229.3.3 与 FreeBSD 13.x/14.x 技术进展的比较

**要点**：bsd_commits.db 显示 2021 年四仓库 commit 量对照如下：

    | 仓库 | 2021 年 commit 量 | 与 DragonFly 比值 |
    |---|---|---|
    | freebsd-src | 18043 | 19.1 倍 |
    | openbsd-src | 5336 | 5.6 倍 |
    | netbsd-src | 2967 | 3.1 倍 |
    | dragonfly-src | 946 | — |
    DragonFly 仅为 FreeBSD 的 **5.2%**、OpenBSD 的 **17.7%**、NetBSD 的 **31.9%**。FreeBSD 13.0（**2021-04-13** 发布）引入 arm64 Tier-1、改进 bhyve、改进 wireless，14.0（**2023-11-20** 发布）引入 Kunai 实验性调度器；DragonFly v5.8.0（**2020-02-29**）与 v6.0.0（**2021-05-07**）在 25GbE/100GbE 网络栈与 SMP 改进上有局部进展，但 bsd_commits.db 显示其 commit 量仅为 FreeBSD 同期 5.2%，整体技术广度与硬件支持仍落后
**史料**：bsd_commits.db commits 表四仓库 2021 年对照（freebsd = 18043、openbsd = 5336、netbsd = 2967、dragonfly = 946）；FreeBSD 13.0/14.0 release notes；DragonFly 5.8/6.0 release notes〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 6 条——技术路线分化：bsd_commits.db 数据显示 FreeBSD 与 DragonFly 在技术广度上的分化持续加深——FreeBSD 13.x/14.x 时期 arm64 Tier-1、bhyve 改进、Kunai 调度器均属“扩展技术广度”的投入，DragonFly 5.x/6.x 时期网络栈与 SMP 改进属“深化既有特性”的投入，两者投入方向不同；总纲第 17 条——软件工程：commit 量差距（FreeBSD 是 DragonFly 的 19.1 倍）反映两个项目的工程动员能力差距，但 DragonFly 在 LWKT/HAMMER/vkernel 三大子系统上的“轻量级内核哲学”投入是 FreeBSD 未涉足的领域

**辨析**：技术比较须结合项目目标——FreeBSD 追求主流服务器市场（arm64 Tier-1、bhyve 改进），DragonFly 追求轻量级内核哲学（LWKT/HAMMER/vkernel），无简单优劣关系；FreeBSD 13.x/14.x 的 Kunai 调度器为实验性，截至 2026-07-22 仍未取代 ULE 为默认调度器 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]；DragonFly 5.8/6.0 的网络栈改进主要在 25GbE/100GbE 驱动层，未涉及 TCP/IP 协议栈核心重构

**文献**：bsd_commits.db commits 表（四仓库 2021 年对照）；FreeBSD 13.0/14.0 release notes [EB/OL]. freebsd.org/releases/；DragonFly 5.8/6.0 release notes [EB/OL]. dragonflybsd.org/release/ ［A］

## 229.3.4 发布说明与 commit 记录考据

**要点**：bsd_commits.db dragonfly-src 仓库 tags 表提供 v5.8.0 与 v6.0.0 的 tagger_date、tagger_name、target_commit_date 字段。v5.8.0 与 v6.0.0 对照如下：

    | tag | tagger_date | target_commit_date | 时间差 | 发布模式 |
    |---|---|---|---|---|
    | v5.8.0 | 2020-02-29T12:19:38-05:00 | 2020-02-29T12:19:38-05:00 | 同日 | 快速发布 |
    | v6.0.0 | 2021-05-07T22:25:43-04:00 | 2021-04-27T21:32:59+02:00 | 10 天 | 长期积累后发布 |
    反映 v5.8.0 为快速发布（commit 与 tag 同日），v6.0.0 为长期积累后发布（commit 准备 10 天后 tag）
**史料**：bsd_commits.db dragonfly-src 仓库 tags 表 v5.8.0/v6.0.0 完整字段序列；DragonFly 5.8/6.0 release notes；kernel@ 邮件列表中发布相关讨论

**史观**：总纲第 25 条——终结与延续：bsd_commits.db tags 表 tagger_date 与 target_commit_date 字段对比是 0 信任原则在版本史研究中的应用——release notes 可能因时区或编辑延迟出现偏差，tagger_date 作为 git tag 创建时间是首选证据；总纲第 2 条——实践先于理论：v5.8.0 commit 与 tag 同日发布反映“实践完成即发布”的工程节奏，v6.0.0 commit 准备 10 天后 tag 反映“实践完成后预留审查期”的工程节奏
