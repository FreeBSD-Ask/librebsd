# 247.4.3 解释学循环与权力知识共谋——以总纲第 19 条审视代码共享叙事

**要点**：代码共享减少事件的叙事建构以总纲第 19 条“解释学循环与权力知识共谋”审视——DragonFly 与 FreeBSD 代码共享减少的叙事在不同立场中呈现显著差异：FreeBSD 阵营叙事强调“DragonFly 自研路线导致代码共享趋近于零是 fork 关系的自然结果”，DragonFly 阵营叙事强调“代码共享减少是 DragonFly 独立演进的工程合理性体现”，Linux/illumos 外部叙事强调“BSD 阵营频繁分裂导致各项目代码共享减少”；三种叙事的前理解（vorverständnis）差异决定其叙事建构的差异——FreeBSD 阵营的前理解是“集体治理与代码共享优于个人主导与独立演进”，DragonFly 阵营的前理解是“技术路线自主性与工程哲学纯粹性优于代码共享与生态协同”，Linux/illumos 阵营的前理解是“统一聚合优于分裂演化”；illumos-gate.duckdb 提供的客观数据（MFC commit 量按年 6/34/37/34/18、活跃 committer 数 33/35/33/33/28、Dillon commit 量 467/567/377/323/335）可部分校正叙事偏差，但数据本身亦非中立——MFC commit 量反映代码共享的频率但不反映代码共享的质量（驱动程序移植 vs 核心子系统移植），活跃 committer 数反映社区规模但不反映社区健康度（活跃 committer 数下降不等于社区衰退，可能是维护效率提升）；权力与知识的共谋体现于叙事建构——FreeBSD 通过 Release Notes、Foundation 年报、Core Team 决议记录建构“集体治理合法性”叙事，DragonFly 通过 commit message、fork 公告、dragonflybsd.org/history 页面建构“技术路线合法性”叙事，两种叙事均以“项目利益”为名但服务于不同的权力诉求；本节（98.4.5-98.4.7、13.5）的辩证链补足与项目统摄史观审视即是试图打破单一叙事的权力垄断，使 FreeBSD 阵营与 DragonFly 阵营的论点对称呈现——解释学循环亦适用于本审视自身——项目统摄史观审视嵌入项目统摄史观的前理解，须自觉呈现这一前理解而非伪装中立，合图（98.4.7）不是辩证链的终结而是阶段性综合，随 DragonFly 与 FreeBSD 代码共享的进一步演化（如 DragonFly 是否在 v5.x-v6.x 时期进一步减少或增加 MFC commit）须重新展开
