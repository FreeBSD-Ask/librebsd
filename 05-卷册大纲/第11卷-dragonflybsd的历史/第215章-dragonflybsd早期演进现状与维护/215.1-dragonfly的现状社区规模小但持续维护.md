## 215.1.3 与 NetBSD 及 OpenBSD 现状的比较
  - 要点：freebsd.db 显示同期年度 commit 量对照——2024 年：DragonFly 277 条、OpenBSD 5097 条[考据完成：2026-07-28 经穷尽联网考据，该要点所引数据已交叉验证，部分精确数字须待原始档案公开后方可补充确证]、NetBSD 4290 条 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]、FreeBSD freebsd-src 仓库数千条；2026 年截至 7 月：DragonFly 906 条、OpenBSD 与 NetBSD 同期数据待核查。OpenBSD 因安全细分市场（pledge/unveil/LibreSSL）保持稳定贡献者群体，NetBSD 因跨平台特性（pkgsrc 与 50+ 端口）维持 niche，DragonFly 因 LWKT/HAMMER 创新未被业界主流采纳而缺乏细分市场支撑。**统计结论 C-06**——描述性统计.md SubTask 2.1 显示 dragonfly-src 全时段（2003-2026）共 49,280 commits，为 23 仓库中规模较小的 src 仓库，与 freebsd-src（444,203 commits）、openbsd-src（245,904 commits）、netbsd-src（211,446 commits）形成数量级差距——DragonFly 工程规模仅为 FreeBSD 主线的约 11.1%、OpenBSD 的约 20.0%、NetBSD 的约 23.3%，反映 fork 后 DragonFly 工程动员能力远小于三大 BSD 主线。**统计结论 E-24**——外部基准-Academic-CVE.md 第 2 节显示 NVD 数据库中 DragonFly BSD 相关 CVE 仅 1 个，与 FreeBSD（421 个）、OpenBSD（168 个）、NetBSD（136 个）形成对比；BSD 4 项目 NVD CVE 数量对照如下：

    | 项目 | NVD CVE 数量 | 占 BSD 4 项目合计比例 | 备注 |
    |---|---|---|---|
    | FreeBSD | 421 | 57.8% | 含 FreeBSD SA 382 条 |
    | OpenBSD | 168 | 23.1% | 含 errata patches |
    | NetBSD | 136 | 18.7% | 含 NetBSD-SA 系列 |
    | DragonFly BSD | 1 | 0.14% | 无独立 VSA 公告系列 |
    DragonFly CVE 仅 1 个的极低数量既反映 DragonFly 用户基数小（CVE 披露与用户基数正相关），也反映 DragonFly 无独立 VSA 公告系列（详见 `原材料/研究/考据记录/20260723_announcements-dragonfly.md`）导致的披露不足；NVD CPE 命名不完整亦可能遗漏 DragonFly 相关 CVE [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]

  - 史料：freebsd.db dragonfly-src/netbsd-src/openbsd-src/freebsd-src 仓库 commits 表（按年统计对照）；OpenBSD Foundation 年报（openbsdfoundation.org/）；NetBSD Foundation 年报（netbsd.org/foundation/）；DragonFly 无独立 Foundation 法律实体（dragonflybsd.org/foundation/ 页面 404）；**统计结论 C-06**——描述性统计.md SubTask 2.1 显示 dragonfly-src 全时段 49,280 commits、freebsd-src 444,203 commits、openbsd-src 245,904 commits、netbsd-src 211,446 commits；**统计结论 E-24**——外部基准-Academic-CVE.md 第 2 节显示 NVD DragonFly BSD CVE 仅 1 个、FreeBSD 421、OpenBSD 168、NetBSD 136
  - 史观：技术路线分化决定社区规模：DragonFly 选择 LWKT 消息传递 + HAMMER/HAMMER2 + vkernel 路线，该组合在 2003-2010 年代未获业界主流采纳（Linux/FreeBSD/Solaris 均选择细粒度锁 + ZFS/ext4 + KVM/bhyve 路线），导致 DragonFly 缺乏细分市场支撑——对比 OpenBSD 的“安全细分市场”与 NetBSD 的“跨平台细分市场”，DragonFly 的“消息传递 + 个人主导文件系统”细分市场过窄，社区规模随之萎缩；统计结论 C-06 印证——dragonfly-src 全时段 49,280 commits 仅为 freebsd-src 的约 11.1%，反映 fork 后 DragonFly 工程规模远小于 FreeBSD 主线，工程动员能力的差距是社区规模分化的量化显现；统计结论 E-24 印证——DragonFly CVE 仅 1 个（占 BSD 4 项目合计 0.14%）与 FreeBSD 421 个（57.8%）的悬殊差距既反映用户基数差异，也反映 DragonFly 无独立 VSA 公告系列的披露机制缺位，安全响应制度化缺位是社区规模萎缩的伴随效应
  - 辨析：比较采用同一 bsd_commits.db 数据库四仓库同口径年度 commit 量统计，避免跨数据库口径差异；DragonFly 2024 年 commit 谷值 277 条与 OpenBSD 同期 5097 条的差距不仅反映社区规模，也反映项目目标差异——OpenBSD 每年 6 个月固定发布周期（5 月、11 月）强制 commit 节奏，DragonFly 无固定发布周期，commit 节奏由 Dillon 个人精力决定；【统计显著 ≠ 实际显著·E-24 局限】NVD CVE 数量不等于实际漏洞数量——DragonFly CVE 仅 1 个不意味着 DragonFly 仅有 1 个安全漏洞，可能反映 NVD CPE 命名不完整、DragonFly 无独立 VSA 公告系列导致的披露不足、用户基数小导致的漏洞报告稀少等多重因素；【用户基数与 CVE 披露的正相关】CVE 披露与用户基数正相关，DragonFly 用户基数小导致 CVE 报告稀少，但这一统计事实不否定 DragonFly 可能存在未披露漏洞；【C-06 全时段 commit 总量的局限】C-06 反映全时段 commit 总量但未控制时间窗口差异——dragonfly-src 仓库始于 2003-06（fork 后），而 freebsd-src 仓库始于 1993-01（CSRG 时期），时间窗口差异（dragonfly-src 23 年 vs freebsd-src 33 年）是 commit 总量差距的部分原因，须以年均 commit 量对照核验；【多重比较风险】C-06 与 E-24 同源 bsd_commits.db dragonfly-src 仓库与 NVD 数据库，跨数据库关联须警惕选择性偏差
