# 244.1.3 OpenBSD 安全审计的对照

**要点**：OpenBSD 3.4-4.8 时期（2003-2010）以安全审计为核心目标，引入 pledge（2015 年后才正式引入，本时期主要是主动审计）、stack protector、W^X 等技术；DragonFly 在安全方面投入较少，主要专注于性能与架构

**史观**：总纲第 6 条——技术路线分化：OpenBSD 选择“安全优先”，DragonFly 选择“架构优先”，二者都是 BSD 哲学的不同侧重

**辨析**：DragonFly 并非完全忽视安全——Dillon 在 fork 时仍继承 FreeBSD 4.x 的安全机制，但未进行 OpenBSD 式的主动审计。具体争议点：1) fork 争议考据须以 Dillon fork 公告原文（**<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html**）逐句核验，不得仅凭> DragonFly 官方 history 页面转述；2) DragonFly 安全机制继承范围须以 dragonfly.duckdb dragonfly-src 仓库 commit message 中引用 FreeBSD SA 编号的记录核验——2003-09-25 Dillon commit `8fd3e627ee2c` 标注 “Apply FreeBSD Security Advisory FreeBSD-SA-03:14.arp”，反映 fork 初期对上游 FreeBSD 安全公告体系的依赖 [存疑脚注：DragonFly 2.x 时期安全机制与 FreeBSD 4.x 继承关系的完整范围待以 commit log 逐条核验]。0 信任原则应用维度：commit message 中的 SA 编号引用须经原始公告交叉印证、author 字段可伪造、fork 公告为当事人单方面声明。考据留痕至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8s 节。
