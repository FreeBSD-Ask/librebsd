## 228.1.5 批评层——BSD 阵营对 DragonFly DRM 背离 FreeBSD 的“代码血缘背离”批评（2014-2015）

**要点**：DragonFly v4.0.0（2014-11-23）完成从 FreeBSD DRM 到 Linux DRM 的切换后，BSD 阵营（尤以 FreeBSD GPU 驱动维护者与 NetBSD 用户为代表）对 DragonFly 的 DRM 路线提出三类批评。其一，“血缘背离”批评——dragonfly.duckdb 显示 sys/dev/drm/ 目录在 2014 年有 197 个 distinct commit、2015 年 310 个，这些 commit 的主体是 Tigeot 对 Linux DRM 的移植而非对 FreeBSD DRM 的维护，BSD 阵营认为 DragonFly 放弃了 BSD 家族共享的 GPU 驱动代码基础，削弱了 BSD 家族在 GPU 驱动上的代码互助传统。其二，“维护负担转移”批评——dragonfly.duckdb 显示 Tigeot（<ftigeot@wolfpond.org>）从 2011-03-06 至 2020-12-19 间共 1346 条 commit，其中 DRM 移植工作集中于 2014-2017 年，BSD 阵营认为 DragonFly 将 GPU 驱动的维护负担从“BSD 内部协作”转移为“跟随 Linux 内核发布周期”，使 DragonFly 的 GPU 支持质量受制于 Linux 内核的发布节奏与 Tigeot 个人移植进度的双重不确定。其三，“MP-safe 适配风险”批评——Linux DRM 设计于 Linux 内核的 Big Kernel Lock 演化路径（BKL → preempt_disable → sleeping spinlocks），与 DragonFly 的 LWKT 轻量级令牌机制在并发模型上存在根本差异，BSD 阵营认为直接移植 Linux DRM 而非通过 FreeBSD DRM 的 MP-safe 适配层，可能在 DragonFly 的 LWKT 上下文中引入难以察觉的竞态条件
