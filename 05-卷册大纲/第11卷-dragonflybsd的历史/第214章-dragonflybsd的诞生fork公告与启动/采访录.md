**字段 2 采访摘要**

DragonFly 3.0 于 2012 年 2 月 22 日发布，因追踪一个 AMD CPU bug 而推迟。release 页面陈述 3.0 的“重大改进”：移除大量“巨锁”（giant kernel lock），多核性能显著提升；VM SMP 工作将 vm_token 拆分为每个 vm_object 的私有 token，并发页面故障可并行推进，Postgres 与 MySQL 等数据库性能优秀；HAMMER 性能因新增“时分复用”方法大幅提升，重负载下公平性与吞吐量改善，HAMMER 在 256MB 内存的极低配置下亦可运行；SMP 内核默认安装。Dillon 以项目创始人身份主导此次 release 的工程方向，VM SMP 改进与 HAMMER 性能改进为 3.x 时期奠定基调。

**字段 2 采访摘要**

DragonFly 3.2 于 2012 年发布，HAMMER2 文件系统进入“主动开发”阶段。HAMMER2 设计页面陈述其特性：块级写时复制、挂载即时恢复、即时快照、可写挂载快照、自动压缩、自动去重、未来主从机制、动态基数树（radix tree）、64 位硬链接计数器、2^63 逻辑文件大小上限、递归校验码以检测损坏。HAMMER2 不支持 atime 字段（因写时复制语义），目录项经半排序哈希算法嵌入基数表 blockref 结构以最大化性能。HAMMER2 的“动态基数树”设计区别于 HAMMER1 的 B+Tree，每项可动态控制截取位数，允许小文件仅占一两个层级。

**字段 3 考据脚注**

本则 HAMMER2 设计页面经联网抓取核实，页面顶部明确陈述"HAMMER2, the successor of HAMMER, is under active development since 2012 and now the official default filesystem for DragonFly"。"since 2012"的起始年份陈述与 bsd_commits.db dragonfly-src 仓库中 sys/vfs/hammer2/ 目录首引 commit 时间序列吻合。bsd_commits.db 显示 dragonfly-src 仓库 HAMMER2 关键词 commit 2012 年 273 条，sys/vfs/hammer2/ 目录 distinct commit 2012 年 101 个，远超 sys/vfs/hammer/ 同期 28 个，反映 Dillon 在 2012 年已将工程重心从 HAMMER1 转向 HAMMER2。3.2 release 页面 URL `https://www.dragonflybsd.org/release32/` 在 WebFetch 抓取时返回非空内容 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]，但具体 release 公告日期须以 bsd_commits.db tags 表 v3.2.0 tagger_date 为准。自利偏差审查：HAMMER2 设计页面属项目自述，对 HAMMER2 成熟度的陈述须以 5.0 release（2017-10-16）"EXPERIMENTAL"标注加以对照——HAMMER2 在 3.x 时期仅为“主动开发”阶段，5.0 才首次可启动发布，正文引用时须区分“开发起始”与“生产就绪”。完整考据过程见 [20260723_announcements-dragonfly.md](../../../原材料/研究/考据记录/20260723_announcements-dragonfly.md) 与 [20260724_dillon-hammer2-design-page.md](../../../原材料/研究/考据记录/20260724_dillon-hammer2-design-page.md)。

**字段 2 采访摘要**
