# 226.1 DragonFly 3.x-4.x 时期的技术淘汰——sendmail 从 base 移除与 DMA 默认 MTA 切换（2007-2015）

## 226.1.1 DMA 的源头与早期开发（corecode 2007.3 首发，Matthias Schmidt 2008.2 增强）

**要点**：2007 年 3 月 corecode（Matt Dillon）在 kernel@ 邮件列表首次发布 DragonFly Mail Agent（DMA），定位为 “小型、简洁、干净” 的 base 内 mailer，目标不是替代 sendmail/postfix 等完整 MTA，而是为 cron、periodic 等本地投递场景提供开箱即用的能力；2008 年 2 月 1 日 Matthias Schmidt 在 submit@ 邮件列表发布 “DragonFly mail agent (round two)”，为 DMA 添加远程投递（直连或经 smarthost）、TLS/SSL 与 STARTTLS、SMTP AUTH（plain SMTP login）、虚拟用户地址重写、IPv6、sendmail 兼容命令行选项等关键能力，man page 由 swildner（Sascha Wildner）撰写，DMA 由此具备 “works-out-of-the-box” 的实用形态

**史料**：corecode 2007.3 kernel@ 邮件 “DragonFly mail agent” 原始公告（<http://leaf.dragonflybsd.org/mailarchive/kernel/2007-03/msg00060.html>）；Matthias Schmidt 2008.2.1 submit@ 邮件 “DragonFly mail agent (round two)”（lists.dragonflybsd.org/pipermail/submit/2008-February/073428.html）；DragonFly BSD Digest 2015.3.9 报道；FreshPorts mail/dma port 元数据（Port Added 2009-02-12，License BSD3CLAUSE，maintainer <garga@FreeBSD.org>）；GitHub corecode/dma 上游仓库 ［A］

**史观**：总纲第 17 条——软件工程：DMA 的演化呈现 “先发布核心，再渐进增强” 的工程节奏，corecode 立柱、Matthias Schmidt 扩展功能、swildner 撰写 man page，三人协作完成 DMA 的可用化

**辨析**：DMA 首次发布日期存在 2007.3 与 2008.2 两种说法——前者为 corecode 原始公告，后者为 Matthias Schmidt 的 “round two” 增强版，需在叙事中明确区分 “首发” 与 “功能完整化” 两个节点；GitHub corecode/dma 仓库的早期 commit 历史与邮件列表时间戳需交叉验证 [存疑脚注：DMA 首次发布日期的两种说法须经 GitHub corecode/dma 仓库早期 commit 历史与 kernel@/submit@ 邮件列表时间戳交叉验证，本轮考据未联网核验 GitHub 仓库 commit 历史]。0 信任原则应用维度：author 字段可伪造（corecode 为 Matt Dillon 别名，须与 <dillon@dragonflybsd.org> 邮箱交叉验证）、tagger_date 与实际发布日期可能偏差（邮件列表时间戳为发信时间，实际功能可用时间可能更早）、关键词匹配局限（commit message 中 “DMA” 缩写可能与 “Direct Memory Access” 混淆，须以 mail/dma 或 libexec/dma 路径核验）。考据留痕至 `03-原始史料库/06-考据记录/20260730_jianyi缺口补全考据.md` 8z 节

## 226.1.2 sendmail 的 “Berkeley Unix 的越南” 包袱与 BSD 阵营移除时间表

**要点**：sendmail 源自 ARPANET 时期 Eric Allman（埃里克·奥尔曼） 在 UC Berkeley 编写的 delivermail，1980 年代重写为 sendmail 后成为 Unix 准标准 MTA，但其配置复杂（m4 宏、.mc 与 .cf 双层抽象）、安全漏洞频发（CERT 周报时代）、《Unix-Haters Handbook》（1994）将其专章命名为 “Berkeley Unix 的越南”（The Vietnam of Berkeley Unix），1990 年代后期逐渐丧失主流地位；BSD 阵营各项目移除时间表如下：

    | 项目 | 引入替代 MTA | 设为默认 | 完全移除 sendmail | 移除路径 |
    |---|---|---|---|---|
    | NetBSD | 1.5（2000.12）引入 Postfix | 2.0（2004.12） | 4.0（2007.12） | 渐进替换 |
    | OpenBSD | — | — | 2014 下半年（5.7/2015.5 确认） | 激进移除 |
    | DragonFly | — | DMA（2015.3） | 2015.3 | 自研替代 |
    | FreeBSD | 2014 起 base 含 DMA 副本（`WITH_DMAGENT`） | — | 至 2022 仍保留 sendmail 为默认 | 保守观察 |
**史料**：Eric Allman sendmail 历史；《Unix-Haters Handbook》sendmail 章节（web.mit.edu/~simsong/www/ugh.pdf）；NetBSD 1.5/2.0/4.0 release notes；OpenBSD 2014 sendmail 移除 commit；DragonFly BSD Digest 2015.3.9 评论中 John 关于 NetBSD/OpenBSD 移除时间表的发言；Ed Maste（埃德·马斯特） 2022.1.27 freebsd-hackers 邮件 “Dragonfly Mail Agent (dma) in the base system”（lists.freebsd.org/archives/freebsd-hackers/2022-January/000801.html） ［A］

**史观**：总纲第 22 条——开源运动：sendmail 在 BSD 阵营的逐步退场是开源运动中 “复杂遗留组件被 minimalist 替代” 的典型，但各项目节奏不同，反映了不同的工程哲学——NetBSD 主动替换、OpenBSD 安全优先、DragonFly 自研替代、FreeBSD 保守保留

**辨析**：DragonFly BSD Digest 评论中 John 关于 “OpenBSD took it out only 6 months ago” 的发言需精确考据——OpenBSD 5.6（2014.10）仍含 sendmail，OpenBSD 5.7（2015.5）发行说明确认移除，与 “2014 下半年” 的描述需交叉验证；NetBSD 在 2000-2007 年间同时维护 sendmail 与 Postfix 两套 MTA 在 base 中，是 “渐进替换” 的特殊案例，需在叙事中说明

**文献**：《Unix-Haters Handbook》；NetBSD 1.5/2.0/4.0 release notes；OpenBSD 5.6/5.7 release notes；DragonFly BSD Digest 2015.3.9 评论；Ed Maste 2022.1.27 freebsd-hackers 邮件 ［A］

## 226.1.4 DragonFly 4.2.0（2015.6.29）发行说明确认与 DMA 的设计哲学

**要点**：DragonFly 4.2.0 于 2015 年 6 月 29 日发布（4.2.1 于 7 月 1 日、4.2.3 于 7 月 13 日、4.2.4 于 8 月 10 日），发行说明 “Big-ticket items” 中 “Sendmail replaced by DMA” 明确记载 “Sendmail 已被自研的 DragonFly Mail Agent（DMA）取代，DMA 不是功能完整的 MTA，仅接受本地 MUA 邮件并即时投递（本地或远程），不监听 25 端口，需要完整 MTA 的用户须从 dports 安装 OpenSMTPD、Postfix 或 sendmail 本身”；DMA 的设计哲学是 “做减法”——剥离 sendmail 的 m4 配置、监听守护、复杂队列管理，仅保留 “本地 MUA 接收 + smarthost 远程投递” 的最小功能集，与 Dillon 在 HAMMER 与 LWKT 上的形式主义化路径一致

**史料**：DragonFly 4.2 release notes（dragonflybsd.org/release42/）；DragonFly 4.2.0 commit 列表（lists.dragonflybsd.org/pipermail/commits/2015-June/418867.html）；linuxfr.org 2015.6.29 DragonFly BSD 4.2 专题报道（linuxfr.org/news/dragonfly-bsd-4-2）；DragonFly BSD Handbook mta 章节 ［A］

**史观**：总纲第 3 条——形式主义膨胀：DMA 是 Dillon “做减法” 哲学的形式主义化——将 “最小 MTA” 理念固化为代码结构，与 HAMMER 2 的 “轻量级写时复制” 形式主义化形成呼应；总纲第 6 条——技术路线分化：DMA 与 sendmail/postfix/opensmtpd 的路线分化是 “极简主义 vs 功能完整主义” 的典型

**辨析**：4.2.2 版本被错误 tag 后立即被 4.2.3 替换（含新版 OpenSSL），需在版本时间线中标注此异常；DMA 不支持 vacation/.forward 功能，需在叙事中明确这一功能边界；“first BSD to do so” 的表述指 GCC 5 而非 DMA 替换，需避免混淆 [存疑脚注（已核验 2026-08-04）：4.2.2 经 GitHub 官方镜像 tag 列表与 dragonflybsd.org/releases/ 双源交叉验证，不在 4.2.x 官方发布序列（官方仅 4.2.0/4.2.1/4.2.3/4.2.4）；“4.2.2 被错误 tag 后立即被 4.2.3 替换（含新版 OpenSSL）”方向性事实成立，但“错误 tag”具体成因仍属推断，建议订正为“4.2.x 官方序列不存在 4.2.2 发布版，4.2.3 为 4.2.1 之后下一个正式发布”；考据留痕 03-原始史料库/06-考据记录/20260804_cvs_核验.md]。0 信任原则应用维度：release notes 中 “first BSD to do so” 表述须区分指 GCC 5 还是 DMA 替换（避免张冠李戴）、tagger_date 与实际发布日期可能偏差（4.2.0-4.2.4 密集发布期间 tag 操作频繁，须与 commit 时间戳互参）、关键词匹配局限（release notes 中 “DMA” 须与 “Direct Memory Access” 区分）。考据留痕至 `03-原始史料库/06-考据记录/20260730_jianyi缺口补全考据.md` 8aa 节

## 226.1.5 与 FreeBSD/NetBSD/OpenBSD sendmail 策略的对照与辨析

**要点**：BSD 阵营 sendmail 策略分化为四条路径——NetBSD 早期（1.5/2000）引入 Postfix 并行，2.0（2004）设为默认，4.0（2007）完全移除 sendmail，是 “先并行后移除” 的渐进路径；OpenBSD 2014 下半年直接移除 sendmail（5.7/2015.5 发行说明确认），是 “激进移除” 路径；DragonFly 2015.3 自研 DMA 替代，是 “自研替代” 路径；FreeBSD 至 2022 年仍保留 sendmail 为默认 MTA，但 2014 年起在 base 中保留 DMA 副本（通过 `WITH_DMAGENT` src.conf 选项启用）作为可选组件，2022.1.27 Ed Maste 在 freebsd-hackers 征求 DMA 作为最小 base MTA 的反馈，是 “保守观察” 路径；四条路径反映了各项目对 “base 应包含什么” 的不同回答。四 BSD sendmail 策略对照如下：

    | 项目 | 策略类型 | 关键节点 | 治理模式 |
    |---|---|---|---|
    | NetBSD | 先并行后移除 | 1.5（2000.12）→ 2.0（2004.12）→ 4.0（2007.12） | Foundation 治理 |
    | OpenBSD | 激进移除 | 5.7（2015.5）发行说明确认 | de Raadt 主导 |
    | DragonFly | 自研替代 | DMA（2015.3）替换 sendmail | Dillon 个人主导 |
    | FreeBSD | 保守观察 | 2014 起 base 含 DMA 副本，2022 仍保留 sendmail 默认 | Core Team + Foundation |
**史料**：NetBSD 1.5/2.0/4.0 release notes；OpenBSD 5.6/5.7 release notes；DragonFly BSD Digest 2015.3.9 评论；FreeBSD src.conf `WITH_DMAGENT` 选项文档；Ed Maste 2022.1.27 freebsd-hackers 邮件；John Baldwin（约翰·鲍德温） 2022.1.27 回复邮件（确认 DMA 在 cron/periodic 邮件场景可用） ［A］

**史观**：总纲第 6 条——技术路线分化：BSD 四个项目在 sendmail 上的四种策略是技术路线分化的极致体现，每种策略都有其合理性；总纲第 23 条——社区治理：策略差异背后的治理差异——DragonFly 个人主导可快速决策自研、NetBSD Foundation 治理可渐进替换、OpenBSD de Raadt 主导可激进移除、FreeBSD Core Team + Foundation 治理倾向于保守保留以兼容既有部署

**辨析**：FreeBSD 2014 起 base 中含 DMA 副本但未默认启用，需明确区分 “在 base 中可用” 与 “默认 MTA” 两个状态；OpenBSD 移除 sendmail 的精确版本（5.6 vs 5.7）需进一步考据 release notes 原文；NetBSD 在 2000-2007 年间同时维护两套 MTA 的资源成本需量化考据
