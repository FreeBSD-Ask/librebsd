# 238.1.2 新用户融入的被冷落现象

**要点**：dragonfly.duckdb contributors 表显示 213 条贡献者记录中 Top 25 贡献者占总 commit 量约 99%（全口径含 DPorts Builder、Automaton 等机器账户，未剔除 bot）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］，反映贡献高度集中于少数核心开发者——新贡献者融入困难。DragonFly 缺乏 FreeBSD Handbook（docs.freebsd.org/en/books/handbook/）规模的系统性新手文档，亦无 OpenBSD FAQ（openbsd.org/faq/）规模的入门指引，新用户提问常无人回应导致用户流失

**史料**：dragonfly.duckdb dragonfly-src 仓库 contributors 表（213 条贡献者记录，Top 25 集中度统计［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）；DragonFly BSD 文档（dragonflybsd.org/docs/，规模与完整性对照 FreeBSD Handbook）；邮件列表中新用户提问的响应记录（lists.dragonflybsd.org 邮件列表存档）

**史观**：总纲第 10 条动手者创造历史：新用户作为边缘者的融入困境——dragonfly.duckdb 显示 213 条贡献者记录中绝大多数仅有 1-10 条 commit 即停止贡献，反映新贡献者融入后的留存率极低；对比 FreeBSD freebsd-src 仓库 contributors 表规模（5,671 条，数倍于 DragonFly），新贡献者留存率差异是社区规模分化的关键

**辨析**：被冷落是主观感受，须基于响应率数据而非个别案例——dragonfly.duckdb 不记录邮件列表响应时间，正式撰写时须以 lists.dragonflybsd.org 邮件列表存档按提问邮件 ID 与首次响应邮件 ID 时间差统计响应率；部分新用户流失可能因 DragonFly 用户基数小（无大规模生产部署场景）而非社区态度，须区分“被冷落”与“自然流失”
