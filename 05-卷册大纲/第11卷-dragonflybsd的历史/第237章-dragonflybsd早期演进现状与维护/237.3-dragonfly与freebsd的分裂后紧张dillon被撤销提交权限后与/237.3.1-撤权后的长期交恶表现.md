# 237.3.1 撤权后的长期交恶表现

**要点**：dragonfly.duckdb 显示 DragonFly fork 首 commit `984263bcb83a`（2003-06-17T02:57:24Z，Dillon）标题“Initial import from FreeBSD RELENG_4”——Dillon 选择自 FreeBSD 4.8 而非 5.x 分叉，本身即对 FreeBSD Core Team 5.x 路线的政治化拒绝。fork 后 DragonFly 与 FreeBSD 的代码共享逐步减少：dragonfly.duckdb dragonfly-src 仓库 commit_files 表显示 2003-2005 年间 DragonFly 仍频繁从 FreeBSD 5.x/6.x 回移驱动与用户态工具，但 2007 年 HAMMER 首引（commit `8750964d1997`）后回移频率显著下降，至 2010 年代两者内核层面已几乎完全独立

**史料**：dragonfly.duckdb dragonfly-src 仓库 commits 表（2003-2005 年间 commit message 中“from FreeBSD”、“sync FreeBSD”、“MFC from”等表述频率统计［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）；dragonfly.duckdb dragonfly-src 仓库 commit_files 表（sys/dev/ 目录文件变更与 freebsd-src 同名文件对照）；dragonfly.kernel 邮件列表存档（lists.dragonflybsd.org）中 2003-2007 年间 FreeBSD 5.x 批评话语

**史观**：校园政治：开源社区的人际政治——Dillon 与 FreeBSD Core Team 的分歧从 5.x 路线争议升级为 fork 事件，再演变为长期不交流的人际政治；dragonflybsd.org 官方 history 页面仅以“forked from FreeBSD 4.8 in June of 2003 by Matthew Dillon（马修·狄龙）”一句记录 fork，未提撤权经过，对比 FreeBSD 官方文档对 fork 事件着墨亦少——双方官方叙事的“沉默”本身即长期交恶的表现
