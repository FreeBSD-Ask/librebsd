# 239.2.2 userland 逐渐分化的历程（2.x-6.x 期间）

**要点**：dragonfly.duckdb dragonfly-src 仓库 commits 表显示 2003-2010 年间 DragonFly userland 经多次差异化重构——2003-06-17 当日移除 UUCP（commit `bec037ae07f0`）、2003-06-17 当日 retarget makesyscalls.sh from FreeBSD to TurtleBSD（commit `efe09d8ced7c`）、2005-08-31 移除旧版 sendmail（commit `deb5649d898b`，Joerg Sonnenberger 执行“Retire old sendmail”）、2007-10-10 引入 HAMMER 文件系统工具（commit `8750964d1997` 同期）。至 2010 年代（v2.10-v2.13 系列）DragonFly userland 与 FreeBSD userland 已显著分化

**史料**：dragonfly.duckdb dragonfly-src 仓库 commits 表（2003-2010 年间 commit message 含“remove”、“retarget”、“retire”、“rewrite”等关键词的 commit 序列）；dragonfly.duckdb dragonfly-src 仓库 commit_files 表（bin/、sbin/、usr.bin/、usr.sbin/ 目录文件在 2003-2010 年间的变更历史）；DragonFly 各版本 release notes〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律：共享状态的逐步终结——DragonFly userland 从 2003 年 fork 初期的“Initial import from FreeBSD RELENG_4”完全共享状态，经 7 年（2003-2010）持续差异化操作，演变为与 FreeBSD userland 显著分化的独立实现；分离过程符合“延续非静态保持而是动态演化”的史观

**辨析**：分化的原因包括主动修改（移除 UUCP、移除 sendmail、retarget makesyscalls.sh）与被动不同步（FreeBSD userland 改动未回移至 DragonFly），二者须区分——dragonfly.duckdb commit message 中“remove”/“retire”/“retarget”等表述明确为主动修改，“sync FreeBSD”表述为回移操作（2003-2005 年间存在、2007 年后基本停止）；2007 年 HAMMER 引入后回移停止的具体时点须以 commit message 频率统计核验
