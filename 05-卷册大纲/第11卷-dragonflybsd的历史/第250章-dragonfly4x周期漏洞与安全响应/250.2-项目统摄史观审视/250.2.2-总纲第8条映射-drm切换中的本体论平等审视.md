# 250.2.2 总纲第 8 条映射——DRM 切换中的本体论平等审视

**要点**：项目史观总纲第 8 条“本体论上各方平等”为审视 DragonFly DRM 切换提供了去中心化视角。dragonfly.duckdb 显示 2014-2017 年间 DragonFly、FreeBSD、Linux 三方在 DRM 子系统上的关系不是“先进-落后”的等级关系，而是各自独立演化的本体论平等主体：DragonFly 的 DRM 移植（Tigeot 1346 条 commit）是 DragonFly 主体性的显现，FreeBSD 维持自有 DRM 栈（sys/dev/drm2/ 目录）是其主体性的显现，Linux 上游 DRM 演化是 Linux 主体性的显现。DRM 切换不是 DragonFly 向 Linux“臣服”，而是 DragonFly 在自身约束下选择与 Linux DRM 主体性进行代码层面的协作。本体论平等审视避免将 DRM 切换叙述为“Linux 同化 DragonFly”的等级叙事，还原为三方主体性在代码层面的对等交往。

**史料**：dragonfly.duckdb dragonfly-src 仓库 contributors 表（Tigeot 1346 条 commit 2011-2020）；dragonfly.duckdb dragonfly-src 仓库 commits 表（DRM 关键词 2016-2018 年 332 条）；freebsd.duckdb freebsd-src 仓库 sys/dev/drm2/ 目录 commit 记录；Linux kernel DRM 演化记录（git.kernel.org）
    - 查证来源：dragonfly.duckdb 与 freebsd.duckdb 数据库查询（dragonfly-src、freebsd-src 两仓库的 contributors 与 commits 表交叉对比）；Linux kernel DRM 演化以 git.kernel.org 公开 commit 为准；DragonFly 与 FreeBSD DRM 子系统目录结构以 commit_files 表 sys/dev/drm/（DragonFly）与 sys/dev/drm2/（FreeBSD）路径核验
    - 交叉验证方法：以三方独立来源（dragonfly.duckdb DragonFly 数据、freebsd.duckdb FreeBSD 数据、git.kernel.org Linux 数据）交叉对比，确认三方在 DRM 子系统上各自独立演化的本体论平等地位；以 DragonFly kernel@ 邮件列表讨论核验 DRM 切换决策的自主性
    - 存疑判定依据：FreeBSD 是否在 2014 年后完全停止 DRM 维护 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］——须以 freebsd-src 仓库 sys/dev/drm2/ 目录 commit 频率核验；Linux DRM 上游演化对 DragonFly 与 FreeBSD 的影响须以邮件列表讨论核验
**史观**：总纲第 8 条——本体论上各方平等；总纲第 6 条——和解优于斗争〔订正：原条目标签“主体性与和解”系自撰变体，权威第 6 条为“和解优于斗争”，依核查报告改权威全称〕：DRM 切换是三方主体性在代码层面的对等交往而非等级臣服

**辨析**：考据过程留痕——【查证来源】dragonfly.duckdb dragonfly-src 仓库 contributors 表 Tigeot 1346 条 commit 2011-2020 经数据库查询核验，为 DragonFly 主体性的显现提供代码级证据；dragonfly.duckdb dragonfly-src 仓库 commits 表 DRM 关键词 2016-2018 年 332 条经数据库查询核验，为 DragonFly DRM 移植的工程投入提供代码级证据；freebsd.duckdb freebsd-src 仓库 sys/dev/drm2/ 目录 commit 记录经数据库查询核验，为 FreeBSD 维持自有 DRM 栈的主体性显现提供代码级证据；Linux kernel DRM 演化记录以 git.kernel.org 公开 commit 为准；02-sacred源材料/shigang.md（sacred 哲学源材料，禁止再改名）经 Read 一手核验，总纲第 8 条原文“本体论上各方平等。FreeBSD、OpenBSD、NetBSD、DragonFly BSD 在本体论上地位相等，差异仅是一刻状态的不同。文档与代码本体平等”（第 12 行）、总纲第 6 条原文“和解优于斗争。历史的动力不是对抗，而是各主体性的呈现与和解。和解是事物真正完整的一刻”（第 10 行）；【交叉验证方法】dragonfly.duckdb dragonfly-src 仓库（DragonFly 主体性证据）与 freebsd.duckdb freebsd-src 仓库（FreeBSD 主体性证据）与 git.kernel.org Linux kernel 仓库（Linux 主体性证据）三方互证，确认三方在 DRM 子系统上各自独立演化的本体论平等地位；以 DragonFly kernel@ 邮件列表讨论核验 DRM 切换决策的自主性；本体论平等审视须避免滑向“相对主义”——承认三方本体论平等不等于否认工程差距（Linux DRM 在功能广度与硬件覆盖上客观领先），但工程差距不构成本体论等级；“主体性”概念须辨析——DragonFly 选择 Linux DRM 是其主体性的显现（自主选择）而非主体性的丧失（被迫臣服），关键在于选择过程的自主性；Dillon 作为 DragonFly 创始人对 Tigeot DRM 移植工作的授权本身既是 DragonFly 主体性的行使，也是 DragonFly 在资源约束下的让步，二者不矛盾；【存疑判定依据】FreeBSD 是否在 2014 年后完全停止 DRM 维护 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］——须以 freebsd-src 仓库 sys/dev/drm2/ 目录 commit 频率核验；Linux DRM 上游演化对 DragonFly 与 FreeBSD 的影响须以邮件列表讨论核验 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；0 信任原则提示：本体论平等审视作为哲学框架不等于事实判定——freebsd.duckdb 数据是客观记录但“主体性”概念是哲学诠释，史家须辨析“事实”与“诠释”的层次差异；不偏袒叙事姿态声明：本节以项目史观总纲第 8 条审视 DRM 切换中的本体论平等时不预设 DragonFly 的 Linux DRM 移植为“主体性丧失”或“主体性显现”任一判断，本体论平等承认工程差距但拒绝将其上升为本体论等级
