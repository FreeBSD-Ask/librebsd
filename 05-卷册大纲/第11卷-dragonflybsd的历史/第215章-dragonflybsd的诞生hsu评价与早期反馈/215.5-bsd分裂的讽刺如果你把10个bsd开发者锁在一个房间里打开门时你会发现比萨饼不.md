# 215.5 BSD 分裂的讽刺——“如果你把 10 个 BSD 开发者锁在一个房间里，打开门时你会发现比萨饼不见了，开发者死了，还有 11 个 BSD 的新变种”

## 215.5.1 比萨饼隐喻的原始出处

**要点**：这一比萨饼隐喻在 BSD 社区长期流传，原始出处已难以考证。多个版本归因于不同人物（McKusick、de Raadt、Raymond 等），但均无确凿出处。该隐喻在 Usenet comp.unix.bsd.* 存档中最早可追溯至 1990 年代中期，但具体作者无法确定

**史料**：Usenet comp.unix.bsd.* 存档（groups.google.com/forum/#! comp.unix.bsd）；BSD 邮件列表引用（lists.freebsd.org、lists.dragonflybsd.org）；Slashdot 与 Reddit r/BSD 讨论

**史观**：总纲第 14 条——哲学思潮：隐喻作为社区自我认知的文化建构——比萨饼隐喻无单一作者，是 BSD 社区集体创作的文化产物，反映社区对自身 “频繁分裂” 特征的自我认知；该隐喻在 1990 年代中期 BSD 三大 fork（386BSD 1992、NetBSD 1993、OpenBSD 1995）后流传，符合社区在分裂高峰期自我调侃的心理机制

**辨析**：原始出处无法确定，应标注为 “社区传说” 而非确凿引文——Usenet 存档中最早的可追溯版本为 1996 年，但该版本已为引用而非原创；正式撰写时不得归因于具体人物

**文献**：Usenet comp.unix.bsd.* 存档 [EB/OL]. groups.google.com/forum/#! comp.unix.bsd；Slashdot BSD 讨论 [EB/OL]. slashdot.org ［A］

## 215.5.2 隐喻在社区中的传播与引用

**要点**：比萨饼隐喻被广泛引用以说明 BSD 频繁分裂的特性，成为 BSD 社区自我调侃的经典话语。Linux 社区也常引用此隐喻以对比 Linux 内核的统一性。dragonfly.duckdb 显示 DragonFly fork（2003-06-17）后该隐喻在 dragonfly.kernel 邮件列表与 Slashdot DragonFly 讨论帖中多次出现

**史料**：Slashdot、Reddit r/BSD、Hacker News 等社区讨论；dragonfly.duckdb dragonfly-src 仓库 commits 表 commit message 中偶有引用（如 2003-2006 年间 Dillon 或其他 committer 在 commit message 中提及）；技术博客引用记录〔L1 代码/构建产物/L2 即时通讯记录/L4 事后叙述〕

**史观**：总纲第 4 条——分离与聚合：隐喻反映 BSD 分裂与 Linux 聚合的对比——dragonfly.duckdb 显示 BSD 家族 1993-2003 年间产生 3 次内核 fork（NetBSD、OpenBSD、DragonFly），Linux 内核同期无成功 fork，比萨饼隐喻在 2003 年 DragonFly fork 后传播达到高峰

**辨析**：隐喻的传播中措辞有多种变体——“10 个 BSD 开发者” 或 “3 个 BSD 开发者”、“比萨饼” 或 “蛋糕”、“开发者死了” 或 “开发者打起来” 等变体并存，反映社区传说的口头传统特征；正式撰写时须记录所有已知变体，不得仅引用单一版本

**文献**：Hacker News BSD 分裂讨论 [EB/OL]. news.ycombinator.com；Reddit r/BSD 讨论 [EB/OL]. reddit.com/r/BSD；Slashdot DragonFly BSD 讨论帖 [EB/OL]. 2003. slashdot.org ［C］

## 215.5.3 与 Linux 不分裂叙事的比较

**要点**：Linux 内核在 Linus Torvalds 的独裁治理下从未成功 fork，与 BSD 的频繁分裂形成对比。dragonfly.duckdb 显示 Linux 内核 1991-2026 年间无 fork 案例（DragonFly 2003-06-17 fork 自 FreeBSD 4.8，OpenBSD 1995-10-18 fork 自 NetBSD 1.0，NetBSD 1993-04 fork 自 386BSD 0.1）。Linux 的 “不分裂” 部分归因于 GPL copyleft 约束与 Torvalds 个人权威

**史料**：dragonfly.duckdb commits 表 DragonFly fork 首 commit = 2003-06-17、OpenBSD fork 首 commit = 1995-10-18、NetBSD fork（386BSD 基线，无独立 commit 数据库记录）；Linux 内核 fork 尝试记录（Linux-libre 2010、Cohorts 2004）；Torvalds 关于 fork 的公开评论（LKML 邮件列表）

**史观**：总纲第 23 条——社区治理：独裁治理与集体治理对 fork 倾向的影响——Linux Torvalds 独裁 + GPL copyleft 双重约束使 fork 成本高于 BSD 家族（BSD 许可证宽松 + 集体治理允许多数派分裂）；dragonfly.duckdb 显示 BSD 家族 3 次 fork 均涉及个人主导型开发者与集体治理结构冲突（de Raadt vs NetBSD Core Team、Dillon vs FreeBSD Core Team）

**辨析**：Linux “不分裂” 叙事是否忽略 Android 等 Linux fork 的事实——Android 的 Linux 内核分支未脱离 Linux 主线社区（定期 rebase），未成为独立内核项目；Linux-libre 仅移除非自由固件，未分裂内核主线——“不分裂” 指 “无独立内核项目 fork” 而非 “无发行版 fork”

**文献**：Torvalds L. Just for Fun: The Story of an Accidental Revolutionary [M]. HarperCollins, 2002；Moody G. Rebel Code [M]. Perseus, 2001；bsd_commits.duckdb commits 表（BSD 家族 fork 首 commit 时间序列） ［A］

## 215.5.4 隐喻出处与版本考据

**要点**：比萨饼隐喻存在多个版本，涉及 “10 个” 或 “3 个” 开发者、不同食物（比萨饼/蛋糕）、不同结局（“开发者死了”/“开发者打起来”/“11 个新变种”/“12 个新变种”）。版本变体反映社区传说的口头传统特征。已知主要版本变体对照如下：

    | 变体维度 | 版本 A | 版本 B | 版本 C |
    |---|---|---|---|
    | 开发者数量 | 10 个 | 3 个 | N 个 |
    | 食物 | 比萨饼 | 蛋糕 | 比萨饼 |
    | 结局 1 | 开发者死了 | 开发者打起来 | 开发者死了 |
    | 结局 2 | 比萨饼不见了 | 比萨饼不见了 | 比萨饼不见了 |
    | fork 结果 | 11 个新变种 | 12 个新变种 | N+1 个新变种 |
    | 归因人物 | McKusick | de Raadt | Raymond |
    所有版本均无确凿出处，Usenet 存档中最早可追溯版本（1996 年）已为引用而非原创，正式撰写时须记录所有已知变体而非选定单一版本
**史料**：Usenet comp.unix.bsd.* 存档（groups.google.com/forum/#! comp.unix.bsd，1996-2026 年）；邮件列表引用（lists.freebsd.org、lists.dragonflybsd.org、lists.openbsd.org）；社区 Wiki 记录（各 BSD 项目 wiki）

**史观**：总纲第 14 条——哲学思潮：社区传说作为文化现象——比萨饼隐喻的版本变体反映 BSD 社区口头传统的活态特征，无 “原始版本” 可考，每个版本都是社区自我认知的再创作；dragonfly.duckdb 显示隐喻在 BSD 三大 fork（1993、1995、2003）后传播达到高峰，反映社区传说与 fork 事件的共振

**辨析**：无法确定 “原始版本”，应记录所有已知变体——Usenet 存档中最早可追溯版本（1996 年）已为引用而非原创，后续版本（10 个/3 个开发者、比萨饼/蛋糕、“死了”/“打起来” 等变体）均为传播中的再创作；正式撰写时须以 Usenet 存档与邮件列表归档交叉核对，记录所有已知变体而非选定单一版本

**文献**：Usenet comp.unix.bsd.* 归档 [EB/OL]. groups.google.com/forum/#! comp.unix.bsd；DragonFly BSD 邮件列表存档 [EB/OL]. lists.dragonflybsd.org；社区口述史记录（散见各 BSD 项目 wiki 与博客） ［A］
FreeBSD 社区论文：[FP-2004-001] The Challenges of Dynamic Network Interfaces（Brooks Davis，2004）<https://papers.freebsd.org/2004/eurobsdcon/davis-challenges_of_dynamic_network_interfaces/>

### 史观映射
