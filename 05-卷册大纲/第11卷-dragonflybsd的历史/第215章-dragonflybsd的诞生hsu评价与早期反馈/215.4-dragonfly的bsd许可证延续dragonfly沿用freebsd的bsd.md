# 214.4 DragonFly 的 BSD 许可证延续——DragonFly 沿用 FreeBSD 的 BSD 许可证


## 214.4.1 许可证继承的法律机制
  - 要点：DragonFly fork 时自动继承 FreeBSD 的 BSD 2-Clause 许可证。BSD 许可证允许 fork 后保持相同许可证，fork 不改变许可证，只改变版权持有者。bsd_commits.db 显示 dragonfly-src 首 commit `984263bcb83a`（2003-06-17）标题 "Initial import from FreeBSD RELENG_4"——继承即通过 Initial import 完成
  - 史料：DragonFly COPYING 文件（github.com/DragonFlyBSD/DragonFlyBSD/blob/master/COPYRIGHT）；FreeBSD COPYING 文件（github.com/freebsd/freebsd-src/blob/main/COPYRIGHT）；BSD 2-Clause 原文（opensource.org/licenses/BSD-2-Clause）；bsd_commits.db dragonfly-src 仓库 commits 表首 commit = 984263bcb83a（2003-06-17, message_subject = "Initial import from FreeBSD RELENG_4"）
  - 史观：总纲第 24 条——许可证：BSD 许可证的法律结构使 fork 在许可证层面无缝——bsd_commits.db 显示 dragonfly-src 首 commit 即 "Initial import from FreeBSD RELENG_4"，无须重新协商许可证即完成继承，反映 BSD 2-Clause 允许 fork 后保持相同许可证的法律特性
  - 辨析：fork 后新增代码的版权归属与许可证——bsd_commits.db 显示 DragonFly 23 年间新增代码均采用 BSD 2-Clause，无许可证变更记录；个别文件（如第三方 contributed 文件）可能保留原始许可证 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]，须以 commit_files 表逐文件核验

## 214.4.2 DragonFly 许可证实践与 FreeBSD 一致性
  - 要点：DragonFly 在许可证实践上与 FreeBSD 保持一致，所有基本系统代码均采用 BSD 2-Clause 许可证。bsd_commits.db 显示 DragonFly 23 年间无 BSD 化的特殊争议（对比 FreeBSD 早期 AT&T 代码清理），因 fork 时（2003-06）FreeBSD 已完成 BSD 化（1994-1995 年加州大学伯克利分校 vs Novell 和解后）
  - 史料：DragonFly 源码中的 COPYRIGHT 文件（github.com/DragonFlyBSD/DragonFlyBSD/blob/master/COPYRIGHT）；DragonFly 邮件列表中的许可证讨论（lists.dragonflybsd.org，2003-2026 年）；bsd_commits.db dragonfly-src 仓库 commits 表（23 年间无许可证变更 commit）
  - 史观：总纲第 24 条——许可证：许可证的惯性延续——DragonFly fork 自 FreeBSD 4.8（2003-06）时 FreeBSD 已完成 BSD 化（1994-1995 和解），无须重复 BSD 化过程；bsd_commits.db 显示 DragonFly 23 年间无许可证清理 commit，反映许可证的惯性延续
  - 辨析：是否存在个别文件许可证不一致——bsd_commits.db 不直接记录文件级许可证，须以 commit_files 表逐文件核验；DragonFly 源码中部分第三方 contributed 文件（如 contrib/ 目录下的第三方代码）保留原始许可证 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]
  - 文献：DragonFly BSD. COPYRIGHT [EB/OL]. github.com/DragonFlyBSD/DragonFlyBSD/blob/master/COPYRIGHT；FreeBSD. COPYRIGHT [EB/OL]. github.com/freebsd/freebsd-src/blob/main/COPYRIGHT；bsd_commits.db dragonfly-src 仓库 commits 表 ［A］
## 214.4.3 与 Linux fork 许可证差异的比较
  - 要点：Linux 内核 fork 后必须保持 GPLv2 许可证（GPLv2 §2 衍生作品条款），BSD fork 可保持或更改许可证（BSD 2-Clause 再分发条款允许）。bsd_commits.db 显示 DragonFly fork 自 FreeBSD（2003-06）保持 BSD 2-Clause，OpenBSD fork 自 NetBSD（1995-10）保持 BSD 2-Clause，两者均保持原许可证；Linux 内核无成功 fork 案例，故无可比较的 Linux fork 许可证实践
  - 史料：GPLv2 §2 衍生作品条款（gnu.org/licenses/gpl-2.0.html）；BSD 2-Clause 再分发条款（opensource.org/licenses/BSD-2-Clause）；bsd_commits.db commits 表 DragonFly fork 首 commit = 2003-06-17（保持 BSD 2-Clause）；bsd_commits.db commits 表 OpenBSD fork 首 commit = 1995-10-18（保持 BSD 2-Clause）
  - 史观：总纲第 24 条——许可证：GPL 与 BSD 在 fork 时的法律约束差异——GPLv2 §2 强制衍生作品保持 GPLv2，BSD 2-Clause 允许 fork 后更改许可证（如 Apple 的 BSD 代码改为 APSL）；bsd_commits.db 显示 BSD 家族 fork 均保持 BSD 2-Clause，反映 BSD 许可证的宽松性允许但未强制更改
  - 辨析：GPL fork 的 “必须保持” 与 BSD fork 的 “可选择” 在实际操作中影响有限——BSD 家族 23 年间 fork（NetBSD 1993、OpenBSD 1995、DragonFly 2003）均保持 BSD 2-Clause，无更改许可证的案例；Linux 内核无成功 fork 案例，故 “必须保持 GPLv2” 的约束实际未在 fork 场景中检验
  - 文献：Free Software Foundation. GNU General Public License v2 [EB/OL]. gnu.org/licenses/gpl-2.0.html；Open Source Initiative. BSD 2-Clause License [EB/OL]. opensource.org/licenses/BSD-2-Clause；bsd_commits.db commits 表（DragonFly/OpenBSD fork 首 commit） ［A］
## 214.4.4 DragonFly 许可证文件原文考据
  - 要点：DragonFly 的 LICENSE/COPYRIGHT 文件位于源码根目录，内容与 FreeBSD 的 COPYRIGHT 文件基本一致，仅版权持有者信息不同。bsd_commits.db 显示 DragonFly 首 commit `984263bcb83a`（2003-06-17）即包含 COPYRIGHT 文件的 Initial import
  - 史料：DragonFly git 仓库 COPYRIGHT 文件（github.com/DragonFlyBSD/DragonFlyBSD/blob/master/COPYRIGHT）；FreeBSD git 仓库 COPYRIGHT 文件（github.com/freebsd/freebsd-src/blob/main/COPYRIGHT）；bsd_commits.db dragonfly-src 仓库 commit_files 表 COPYRIGHT 文件首引 commit = 984263bcb83a（2003-06-17）
  - 史观：总纲第 12 条——法律结构：许可证文件是法律结构的文本体现——DragonFly 的 COPYRIGHT 文件继承自 FreeBSD 4.8（2003-06-17 Initial import），反映 BSD 家族许可证文件的法律结构连续性；bsd_commits.db 显示 COPYRIGHT 文件在 fork 首 commit 即引入，无后续重大修订
