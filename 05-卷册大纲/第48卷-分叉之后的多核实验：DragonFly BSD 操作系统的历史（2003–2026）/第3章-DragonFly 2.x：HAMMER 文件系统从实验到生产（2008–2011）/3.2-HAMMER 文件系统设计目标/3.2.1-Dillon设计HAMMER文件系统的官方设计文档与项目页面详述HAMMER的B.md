# 3.2.1 Dillon设计HAMMER文件系统的官方设计文档与项目页面详述HAMMER的B

> Dillon 设计 HAMMER 文件系统的官方设计文档与项目页面，详述 HAMMER 的 B-Tree 结构、历史版本、崩溃恢复、多主复制等设计理念。HAMMER 与 HAMMER2 均为 Dillon 独立设计，与 OpenZFS 走了不同技术路线。该页面是 HAMMER 设计理念的入口索引，须与前述 THE HAMMER FILESYSTEM 完整设计 PDF 互参。

- **FreshPorts. mail/dma port 元数据 [EB/OL]. [2026-07-22]. <https://www.freshports.org/mail/dma/>.**

> FreshPorts mail/dma port 元数据页面，记载 Port Added 2009-02-12、License BSD3CLAUSE、maintainer <garga@FreeBSD.org>。该页面是 DMA 在 FreeBSD Ports 中的元数据一手来源，反映了 DMA 从 DragonFly base system 反哺至 FreeBSD Ports 的技术传播路径，须与 GitHub corecode/dma 上游仓库、DragonFly BSD Digest 2015.3.9 报道交叉印证。

- **GitHub. corecode/dma 上游仓库 [EB/OL]. [2026-07-22]. <https://github.com/corecode/dma>.**

> DMA 的 GitHub 上游仓库，由 Dillon（corecode）维护，包含 DMA 完整源代码与 commit 历史。该仓库是 DMA 源代码与演化历史的最权威一手来源，须与 corecode 2007.3 邮件首发公告、Schmidt 2008.2.1“round two”邮件交叉印证。早期 commit 历史与邮件列表时间戳须经 GitHub commit timestamp 与邮件列表归档时间戳双向核对。

**史料特征**。DragonFly BSD 项目的口述史呈现三大特征：其一，创始人主导性极强——**dragonfly.duckdb** 显示 Dillon 个人在 dragonfly-src 仓库贡献 10,666 条 commit（按作者名统计，统计基准 2026-08-18 增量更新；其中 dillon@apollo.backplane.com 与 dillon@dragonflybsd.org 两主邮箱合计 10,620 条），单一开发者对项目叙事的主导程度在 BSD 家族中罕见，其 fork 公告、设计文档、commit message 构成项目史料的核心；其二，公开采访来源稀缺——主流媒体对 DragonFly BSD 的报道集中于 2003-2004 年 fork 事件前后（ONLamp 2004、OSNews 2003），后续长期跟踪主要依赖 Justin Sherrill 维护的 DragonFly BSD Digest 博客与 Phoronix 性能基准系列；其三，commit 序列作为“代码即自述”——**dragonfly.duckdb** 中 Dillon、Wildner（10,869 条 commit，含 saw@online.de 与 swildner@dragonflybsd.org 两邮箱）、Sherrill（400 条 commit 与 release tag 序列）、Tigeot（1,346 条 commit）、Kusumi（2,084 条 commit）等核心开发者的 commit 序列本身即是工程实践的当事人陈述，须经 commit message 自述与邮件列表原始帖交叉验证。
