# 3.1.1 内核进入自由软件环境的许可前提

<!-- ROW_MINE: ksummit-discuss.messages.347292 -->`
- 【Linux社区】Linus Torvalds：以“自利≠反 GPL”的诊断系统反驳 copyleft 极大主义者，并发出直接呼吁——**“不，我不认为那是那个论证（那肯定不是我的）。我的论证是：我们在谈论开源如何帮助公司合作并生成更好的技术这方面做得很好。人们确实懂了……但如果你看看公司实际在做什么，很多公司仍然主动回避 GPL。为什么？”**；**“Bradley 声称那是因为公司自私，那当然是真的，但那没有任何错。非常非常错的是认为‘自私’意味着‘反 GPL’。那是疯话。而那正是为什么我们应当展示那些 XFS/JFS/RCU 的例子并说：‘不，GPL 其实运作得非常好，并保护你的自私利益，意味着别人不能就这样偷走你绝妙的技术’”**；**“所以 Bradley 字面上是在散布完全错误的论证。他基本上是在说‘公司是自私的，所以 GPL 对它们不管用，所以我们需要强制解决这个问题’。那完全是胡说。但当然，如果你对公司那样说，当它们想选一个项目时，它们已经听过那套疯话，就会说‘好吧，让我们别选 GPL，因为那显然对我们不利——听听这位 Bradley 说的’”**；**“所以我认为，正是因为那些最响亮地谈论 GPL 和 copyleft、以及它如何需要被强制执行的人，正在主动把公司吓走”**；并以 BSD 与 GPL 之争为据 **“还记得所有 BSD 对 GPL 的战争吗？BSD 那帮人憎恶*GPL。他们绝对憎恶 rms。而且相当有理由，我得说……你有一些非常受尊敬的 BSD 人士，他们在开源里做了大量好事，却绝对拒绝与 GPL 有任何关系……所以这甚至不是‘像 Bradley 这样的人把公司从 GPL 吓走’。他们还吓走了那些在开源代码上花了大量心血的真正优秀的个人”**；对 FSF 路线的判断是 **“这就是为什么我看到 Bradley 在他那次 LinuxCon.Au 演讲中复述 FSF 与 rms 那一套时如此厌恶。那是 FSF 关于自由软件是一种道德选择、以及你应当与公司斗争、在业余时间做自由软件、并试图用版权许可证理由接管世界的旧调。这些年只是略微软化了一点。我从开始时就记得那个调子。我当时就觉得它是胡说，现在觉得更胡说。你接管世界的方式是创造世界上最好的技术，而不是试图扩展版权的触及范围并‘胁迫’用户进入”**；其直接呼吁是 **“‘各位，你们真的就是 GPL 正在失败的原因，人们正用其他许可证开始新项目。因为他们关心的是更好的技术，而不是你们的议程。而你们正在让 GPL 看起来糟糕。’请停下。不要把 Linux 当作你们‘社区工作’的工具。如果你的目的是诱骗人们使用你的许可证、而不是创造尽可能最好的技术，那你就不是我的社区。GPL 的意义在于通过让人们想要合作来创造尽可能最好的技术”** `

<!-- ROW_MINE: linux-fsdevel.messages.334729 -->`
- 【Linux社区】Greg Kroah-Hartman 在 copyleft-next-0.3.1 许可证补丁讨论中引述 Tim Bird 的说法，援引 BSD 双许可证被允许的历史先例：“There were good reasons that the original BSD dual-licenses were allowed”，并以此对比，认为此次 copyleft-next 的双许可提交既非源于既有非 GPL 代码、亦无法在非 Linux 项目复用，故无存在必要。Linux 内核许可证治理由此直接引用 BSD 双许可证先例作为可比治理实践。`

- 【Linux社区】Roland Dreier 的 InfiniBand 核心公开头文件补丁随附双许可声明，GPL v2 与 OpenIB.org BSD 条款并列，并完整粘贴 BSD 许可证全文。原句 “OpenIB.org BSD license below:” 显示 BSD 文本直接落入内核树，属 BSD 许可证在内核开发中的早期落地样本。`
