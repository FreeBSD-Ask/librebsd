# 3.2.1 GCC 在内核开发中的地位

<!-- ROW_MINE: rust-for-linux.messages.9278159 -->`
- 【Linux社区】本邮件是对同线程中一条许可证论证的反驳。被引段落先援引 GPL 条款，要求任何分发或发布的衍生作品必须整体按该许可条款免费授予第三方，随后提出论断：使用非 GPL 工具会带来开发并分发 GPL 兼容但带专有成分的内核版本这一后果。作者以反问切入，认为该论证成立的前提是内核被牢牢锁定在完全没有非 GPL 等价物、并且某种程度受保护从而不会获得等价物的工具上，随后列举了可能实现这一锁定方式的具体手段，包括依赖工具未文档化且快速变化的特性、对接口主张版权、软件专利，并质疑描述这类安排所需的观念扭曲程度，认为把它称为自由并不合适，但同时说明幸运的是内核目前远未接近这种处境。作者最后明确表态自己不喜欢 Rust 这门语言、也怀疑它在内核中的价值，但要求不要把某编译器因为采用 GPL 而更好这类主张混入这场讨论，理由是不论 Rust 与否，内核显然并未在所有相关架构上被锁定于某一编译器。 `
