# 4.10.2 2021 Rust 之争

- **要点**：Greg KH 质疑 Rust Ref 类型复用 refcount_t 却缺锁，指并发获取引用与释放最后引用需锁保护，认为其重复 struct kref 逻辑，要求说明锁在何处。Miguel Ojeda 主张编译期检测远胜运行时检测，目标是最大化 safe 代码；每个 unsafe 块须书面论证健全性，纯 Rust 数据结构即刻可用 Miri，或可让 Rust 自管对象所有权以强化静态保证。Andy Lutomirski 要求 Greg 举出内核树中 kref 需外置锁的具体用例，称先锁再 put 模式罕见，并质疑统一“基对象”模型难以覆盖 v4l、input 层等多生命周期交互对象。Andy Lutomirski 以 Weak 升级返回 Option 为例说明求和类型强制判空，主张其价值更胜借用检查，并举页表项 Empty、NextTable、Page 联合类型可杜绝误读大页。Bart Van Assche 以 GCC cleanup 属性宏示例演示 C 语言亦可实现 RAII，回应对驱动 goto 错误路径难维护、Rust 可改进的论点。Miguel Ojeda 强调须澄清 Rust 是对 C++ 的严格改进；自称非信徒，若 C 委员会开放 defer、lambda 等特性愿出力；认可 Laurent 保留“收益是否抵过成本”的质疑。
