# 8.2.8 154.2 治理

- 【Linux社区】Hector Martin 参与关于社群影响力与基础设施去中心化的讨论。针对 Linus Torvalds 认为百分之八十五从 kernel.org 拉取并不意味着集中的观点，Hector 指出这实际上等同于完全集中，任何 kernel.org 宕机都会对社区造成等同影响。他强调应聚焦可恢复性与数据可用性而非单纯去中心化，并区分短期中断与永久丢失两种场景的不同应对策略。该讨论触及 Linux 内核基础设施治理与冗余策略的核心张力。 `<!-- ROW_MINE: rust-for-linux.messages.9268507 -->`
- 【Linux社区】Danilo Krummrich 在 Rust 内核策略讨论中澄清维护者否决权边界。Linus Torvalds 明确表示维护者无权以个人偏好控制 API 的使用者，并称若维护者认为可控制代码使用者则理解错误。Danilo 对此表示认同，并补充维护者对其维护的 API 在被滥用损害内核整体时确实拥有否决权，但该否决权不能基于个人偏好或特定项目排斥。该讨论触及 Linux 内核治理中维护者权限与 API 使用自由的核心张力。 `<!-- ROW_MINE: rust-for-linux.messages.9270159 -->`
- 【Linux社区】Jason Gunthorpe 就 Rust 内核构建策略与顶层维护者治理展开讨论。他指出维护者峰会已就 rc1 构建破坏问题达成共识但未提出改动方案，而 Linus Torvalds 接受 PR 的前提是维护者必须保证 CONFIG_RUST=y 构建通过。当 PR 被拒绝时，维护者面临紧急情况，因为他们对提交者的代码合并负有责任。他引用 Andrew 在上一周期被迫 rebase 并丢弃补丁的案例，强调维护者应提前进行 Rust 构建测试以避免紧急返工，并主张明确向维护者传达这是他们的职责。 `<!-- ROW_MINE: rust-for-linux.messages.9304171 -->`
