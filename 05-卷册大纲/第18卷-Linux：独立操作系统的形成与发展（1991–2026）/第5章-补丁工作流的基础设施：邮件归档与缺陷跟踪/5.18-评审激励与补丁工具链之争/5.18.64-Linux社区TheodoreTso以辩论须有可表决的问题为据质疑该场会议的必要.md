- 【Linux社区】Theodore Ts'o：以“辩论须有可表决的问题”为据质疑该场会议的必要性——**“如果 Conservancy 打算做它要做的事，那么进行一场讨论的目的是什么就不清楚了”**；**“进行一场辩论意味着地板上有一个问题，而至今不清楚那个或那些问题会是什么。是的，你和 Karen 提议的主题是清楚的，Conservancy 的立场也不是什么秘密——但那不是一个可辩论的问题；它不是一个可供审视的具体提案”**；其评估标准是 **“即便我们地板上有一个问题，比如说‘兹决议：黑客只应使用 Emacs 而非 vi’——我们也会从几个维度评估那个问题：‘这个问题是否可以被有益地辩论？’‘有没有办法判定哪一方赢了辩论？’‘辩论的“赢家”能否执行辩论的结果？’‘判定谁赢谁输的人是否有法律/道德上的资格来做这样的决定并约束社区或产业的其余部分？’”**；并以一句调侃收尾 **“为了讨论而讨论的时间多的是，那是在酒吧里 :-)”** `<!-- ROW_MINE: ksummit-discuss.messages.347096 -->`
- 【Linux社区】Josh Triplett：把 Ted 的“无问题可辩”转为一份具体议题清单，为该场会议提供可表决的议程——列出六个问题：**①“处理执法的正确方式是什么？（这个问题最一般的版本没有达成共识的希望，但我怀疑我们能相当容易地就‘我们不希望看到人们做什么’达成共识）”**；**②“对‘错误’的处理执法方式，我们（如果有的话）要做什么回应？我们是否曾在内核层面作出回应，而不只是在某个维护者团队内部（像 netfilter 那样）？是否存在一条界线，一旦某人在法律领域制造了问题，我们就不再接受他的补丁？那条线在哪里？”**；**③“我们当前的开发流程中有哪些使执法变得更容易或更难？”**；**④“我们能否在开发流程中纳入任何改善局面的东西，类似于 DCO？（不是提议现场头脑风暴，而是提议：如果存在这样一个变更的具体提案，内核峰会看起来是讨论它的地方）”**；**⑤“EXPORT_SYMBOL_GPL 与 MODULE_LICENSE。我知道有些历史表明它们在某些案例中起了帮助。但它们是否可能让执法变得更困难？（这也包括非正式或内部的执法/合规努力；例如 EXPORT_SYMBOL_GPL 可能为这类努力提供支持性论据，但反过来 EXPORT_SYMBOL 则可能妨碍这类努力。）”**；**⑥“近来一个提案（附补丁）建议向 MODULE_LICENSE 的许可证表中增加一个（GPL 兼容的）许可证。应当这样做吗？在 MODULE_LICENSE 里采用不同的方式是否有意义，比如只写 ‘GPL-compatible’ 或 ‘GPL and additional rights’？那里任何可能的做法会不会造成问题？”**；并附判断 **“其中一些问题也许在邮件列表上更合适；另一些看起来适合面对面讨论，尤其如果有友好的法律专家能提供研究或答案的话”** `<!-- ROW_MINE: ksummit-discuss.messages.347097 -->`

- 【Linux社区】Greg KH：以长篇回应系统陈述 Linux 社区的执法路线及其反对诉讼的完整因果链——**对 Kuhn 的“要么放弃 GPL、要么上法庭”断言直接回以“我对此嗤之以鼻（I call bullshit on this）。坦率地说，我听腻了，因为它完全错误，并且轻视了成千上万人 25 年多来为维护 GPL 授予我们的权利所做的努力”**；澄清 **“我从未说过我反对‘GPL 执法’，我要说的是我反对你处理这项任务的方式”**；其经验反例是 **“我也多次当面听人说：‘你认为我们必须遵守 GPL？好，那就把我们告上法庭。否则我们不会合规。’猜怎么着，没人把任何人告上法庭，而每一次我最终都拿到了代码[1]”**；其风险立场是 **“如你所深知，当你对某人采取法律行动时，你必须准备好败诉，并接受败诉的后果。坦率地说，我不准备败诉，而且我绝无可能愿意接受那样一场败诉的后果”**；并逐条列出威胁法律行动会引发的五类后果（公司立刻停止与外部开发者沟通、引入更多律师防御性反应、内部推动 Linux 者被视为“错误”而受挫、内部反对 Linux 者被证明正确、律师知道你会接受败诉便会拖长并消耗你）；以 BusyBox 为案例研究 **“看看，我们有一个这样的案例研究：BusyBox。那正是多次发生的事。被你惹恼的某些人/公司有足够资源去创造一个竞争项目来替代它，并确保他们再也不必处理那摊烂事。是的，你‘被证明正确’了，但代价是什么？你拿到了代码，它没用，因为过时、陈旧、不可合并，而且哎呀，你的开发社区已经死了，项目也过时了”**；其正面路线是 **“我们安静地做，与公司合作，从内部说服他们……不是因为它只是法律（公司一直无视法律，这叫风险管理），而是因为从商业角度看这是对的”**；**“一位非常聪明的资深内核开发者多年前在德国一家酒吧里喝着小酒对我说过大意如此的话：‘愚者从外面猛敲想改变一家公司，智者与谋者从公司内部行事，改变它，使它从未察觉发生了什么。’”**；**“看看，这正是我们所做的。我们这些‘朋克’长大了，从内部改变了公司……我们自下而上地接管了世界……而这一切都是靠不起诉任何人做到的”**；并指出对手的处境 **“现在你在这里有个问题。作为若干版权持有人的代表，你只能用法律途径来试图让公司合规。你所拥有的只是诉讼威胁，那会遮蔽你出发的视角（正如你上面那句‘要么执行要么放弃’所显示的）”**；最后回到议题 **“所以回到正题，我认为内核峰会应当留给技术议题以及开发议题（维护者如何工作、发布如何进行、我们最终是否要关掉 bugzilla 等）。让我们把法律和政治的东西排除在外”**；其座右铭是 **“正如你喜欢引用 Linus，我也引用他：‘一旦律师介入，你就输了。’而你可以引用我：‘我不想输。’”**；脚注补充 **“[5] Till 和 Harald 确实把一些人告上法庭，而且那是好事，但那里的问题与你所提议的非常不同，赌注也低得多”** `<!-- ROW_MINE: ksummit-discuss.messages.347103 -->`
- 【Linux社区】Matthew Garrett：以市场实况反驳“合作路线已足够”的经验基础，并给出被忽视的用户群体——**“然而，如果今天你我走进一家商店，我打赌我们能找到比合规的更多侵权的 Linux 例子。在那些确实合规的当中，我强烈怀疑大多数是那些因 BusyBox 被起诉、或非常接近因 BusyBox 被起诉的公司。当然，那不是一个对 Intel 或 IBM 会奏效的做法，但它们只是所售 Linux 中极小的一部分”**；**“如果你的重点主要是‘我们如何最大化投入 Linux 的资金和开发者’，那么是的，你的做法说得通。但那代价是大量用户被留在封闭设备里、被制造商抛弃，等着有人发现我们留在 2.6 里的另一个重大安全缺陷。这些人很重要，我们不该忽视他们的需求”**；**“我们已经有了大量企业投入。别忘了我们许多人之所以在这里，是因为 Linux 给了我们一个办法去折腾那些本来会对我们封闭的设备，让我们尽己所能确保下一代感兴趣的黑客拥有同样的机会”** `<!-- ROW_MINE: ksummit-discuss.messages.347104 -->`
- 【Linux社区】Linus Torvalds：亲自下场支持 Greg KH 并主张以“开发者之间”的方式讨论 GPL 执法、排除律师与 SFC——**开场声明“有人把这场讨论、尤其是 Greg 的答复指给我看，但我不在 ksummit-discuss 邮件列表上，所以想回复我的话请保持抄送我”，并称“我要把 Greg 的邮件全文引用，因为它是一件美的事物”**；对 Greg 那句“我对此嗤之以鼻”回应 **“我可以插一句说‘阿门！’吗”**；其立场是 **“事实上，让我说，我确实认为我们应该在内核峰会上讨论 GPL 执法，因为我认为这是个重要问题，但我们应该以我们讨论其他问题的方式谈论它：在内核开发者之间。除非律师是以实际代码的开发者与维护者身份在场，否则没有律师在场，尤其绝对不包括软件自由保守者协会（SFC）”**；**“我个人认为这种为诉讼游说的行为已经变成一种讨厌的、溃烂的疾病，而 SFC 和 Bradley Kuhn 就是传播这疾病的伤寒玛丽”**；对 SFC 的历史评价是 **“SFC 最辉煌的时刻——嘿，那是维基百科页面上的导语——是为 BusyBox 做 GPL 合规执法。而我们别自欺欺人。那或许是 SFC 的辉煌时刻，但不是 BusyBox 的辉煌时刻”**；**“我不知道除了律师和疯子之外还有谁对 BusyBox 局面的结局感到满意。如果你确实知道不同的情况，请出声。它导致的只是一大堆争吵，以及个人与商业开发者、用户成群逃离。原始维护者和发起诉讼的维护者最终都公开说那是场灾难”**；因此主张 **“所以我认为整个 GPL 执法问题绝对应该被讨论，但讨论时应使用这样的暂定标题：‘律师：对开放有害，对社区有害，对项目有害’”**；其核心判断是 **“让我们诚实且非常清楚地说一会儿。我意识到在谈论法律问题时这很难，但让我们干脆抛开所有废话试一试。事实是，创造开源并使它成功的人，是那些做实际工作的开发者——以及那些我们能够通过展示我们不是 FSF 那种疯狂怪人而拉进来的公司。而毁掉项目的人，是那些声称要‘拯救’这些项目的律师”**；**“让我们把这一点弄得非常非常明显：当 Bradley Kuhn 说‘我们可以全都决定放弃 GPL，或者我们可以在法庭上执行它’时，我们应当看真实的历史，并从中学习。因为 Bradley Kuhn 是如此彻头彻尾地满嘴胡说，以至于这需要被公开说明”**；**“让我们说清楚这一点：诉讼是毁灭。它们不‘保护’。诉讼毁灭社区。它们毁灭信任。它们会毁掉我们多年来靠友善建立起来的所有善意”**；并补上胜负之外的第三重风险 **“这个问题的另一面似乎被人们忽视了。是的，不只有败诉的风险（我和 Karen 谈过这个，每次她说‘但我们需要以某种方式解决问题’我都感到震惊。绝对不要。我们完全没做任何解决就做得很好，谢谢）……但除了法庭上败诉的风险之外，真正的风险是无论你赢还是输、无论你上法庭还是仅仅威胁，都会发生的事：社区的丧失，尤其是那种能够（也确实）帮上忙的社区的丧失。你失去你的朋友”**；其论据是 **“因为诉讼——甚至诉讼威胁——会让公司远不那么可能把你当好人看。即便你在威胁别人，目标周围的每个人也都会变得非常非常坐立不安”**；并以 Oracle 律师的轶事佐证 **“几个月前我和一位 Oracle 律师谈过，告诉他他们的诉讼只是让 Oracle 显得难看。那位律师不以为然，试图解释人们把诉讼当回事是多么愚蠢，并谈到律师理解诉讼不是针对个人的、他们在法庭之外仍是朋友。我确信律师可以‘理解’诉讼实际上根本不是针对个人的事，但律师似乎真的是唯一‘理解’那一点的群体”**；**“事实是，诉讼（以及诉讼威胁）不会造就朋友。你只是看起来像个恶霸”**；最后重申 **“我这就把 Greg 邮件的其余部分引用完，因为我认为它太贴切了，我肯定无法说得更好，我唯一能做的就是喊‘Bravo！’并说我多么强烈地相信 Greg 是对的。我要把话说得更直白：我相信 SFLC（以及现在的 SFC）的路线是毒药。我们当然可以在内核峰会上讨论这个。让我们讨论 Bradley Kuhn 散布的谎言，以及那些 SFLC 和 SFC 用他们的‘帮助’杀死并撒上盐的项目”** `<!-- ROW_MINE: ksummit-discuss.messages.347105 -->`
