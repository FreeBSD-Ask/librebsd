# 5.18.70 Linux社区LinusTorvalds修正Greg的措辞并借开明自利论证反驳企

- 【Linux社区】Linus Torvalds：修正 Greg 的措辞并借“开明自利”论证反驳“企业皆恶”的民粹论——**“所以我认为 Greg 可能措辞不当。是的，‘唯一原因’那部分显然不成立，但它肯定可以用稍微不同的方式重述：‘只有因为我们主动拥抱公司参与，我们才是今天的样子。’不是说‘只有公司’造就了 Linux 今天的模样——你指出有大量（而且现在仍然有！）个人贡献者显然非常正确。但绝对成立的是：只有通过与公司合作，我们才能像过去那样成功”**；其观感是 **“我刚才花了一些时间看 Bradley 的一些 YouTube 视频，只是为了把他公开的立场与这个线程（以及私人邮件）中随后所声称的作比较，而坦率地说，其中很多是民粹主义的‘公司皆恶’那一套。这在某些圈子里是很流行的情绪，但显然是胡说。公司倾向于大体自私，是的，但个人也如此”**；其核心论证是 **“而问题在于——一个开明自利的社区，人与公司因为都觉得自己从中受益（‘自私’行为）而一起工作，恰恰是我们想要和需要的（而且我主张我们已经拥有）。开源之所以有效，正是因为这套流程对把自身利益放在心上的人有效……没有基本的自利角度，你根本无法达到人与公司共同参与的良性强化循环。所以因为公司‘自私’而妖魔化公司就是纯粹的愚蠢。然而人们就这么做”**；其结论是 **“我们需要做的——也是我们在 Linux 社区里大体一直在做的——正是强调这个事实：开源是一种自私并取得伟大成果的方式。因为那才是合作的真正力量。整套‘专有软件是邪恶的’口号和‘公司天生坏’那一套纯粹是疯话。它是疯狂的、愚蠢的、自我限制的。驳斥那种疯话，无疑是 Linux 今天之所以如此的重大原因之一。这也是为什么 Linux 从来与 FSF 毫无关系。人们给我起过很多称呼，但很少有人叫我愚蠢”** `<!-- ROW_MINE: ksummit-discuss.messages.347182 -->`
- 【Linux社区】Jeremy Allison：把“核按钮是否存在”设为真正的争点，并邀请 Greg 就改许可证发起投票——**“这似乎是你对那个问题的回答：‘你能描述一下你个人认为哪些情形才足以证明就 GPL 不合规提起诉讼是正当的吗？’而你的回答是‘永不’。那是个有效的回答，我尊重它”**；其许可法理陈述是 **“然而，其他 Linux 开发者感觉不同，因为他们加入了 Conservancy 的 Linux 开发者 GPL 合规项目。有些许可证体现了‘不合规无后果’的态度，最流行的当然是 BSD 或 MIT 许可证。确实也有那些许可证下的流行替代内核，我相信你清楚。但它们不是你所拥有的许可证。你拥有的是 GPL。GPL 允许对不合规施以法律惩罚。我们知道这一点，因为已经有过这样的例子”**；其历史追问是 **“你的项目极为成功——比世界上任何其他自由软件项目都更成功。而它是在 GPL 下做到的。你现在似乎想改变大多数贡献者当初提交代码时的条件——改成一个对不合规没有法律惩罚的条件。如果你真的想要那样，我会真心感兴趣看你向 Linux 内核开发者提出这样的提案、并要求他们改变许可证。作为一个内核开发者（除了一些小的 cifsfs 改动之外），我在这件事上没有利害关系，但我会很想看到那次投票的结果，我认为它会很引人入胜（而且我对投票会往哪边倒不做任何预测）”**；其 BSD 对照是 **“我确实觉得应该向你指出，这个策略在 Apple、EMC、Isilon 或 NetApp 身上并没有奏效——他们都有基于 BSD 许可证代码的重要内核，却拒绝向母项目回馈任何有价值的代码。但也许 FreeBSD 的开发者们只是没给它们足够时间、或对它们不够友善、或请求得不够多次”**；最后以调侃收尾 **“与此同时，如果你想在一个符合你偏好的许可证的内核上工作，能否请你修复 FreeBSD 缺失的 per-thread credentials？Samba 已经需要那个好多年了（差不多和我需要 Linux 里的 RichACLs 一样久 :-)”** `<!-- ROW_MINE: ksummit-discuss.messages.347183 -->`
- 【Linux社区】Linus Torvalds：以“执法必须为项目利益而非许可证利益”立论，并公开表示不接受 SFC 代表 Linux 出庭——**“你把那作为一个绝对事实陈述，但没有什么真正支持它。而且如前所述，确实有非常真实的论证反对你的‘事实’”**；**“坦率地说，在看了几个 Bradley 谈论他做什么以及为什么做的视频之后，我真的永远不会想让他或 SFC 在法庭上代表 Linux。永远不会。除非他们非常明确地表明他们的议程已经改变”**；其理由是 **“为什么？因为他解释了他如何觉得‘强 copyleft’本身是好的，而 Linux 是唯一剩下的、足够大、足够有意义、能迫使法律关注 GPL 的项目。换句话说，他公开陈述的许可证合规动机不是为了内核的福祉——而是为了他的许可证执法的福祉”**；**“坦率地说，如果你让那样的人掌管你的法律团队，你是疯了。那是疯狂的。我没疯。我唯一会允许掌管 Linux 相关诉讼的人，是那些把 Linux 的最佳利益放在心上的人。绝对不是有议程、而 Linux 只是其工具的人”**；其原则是 **“我们需要非常清楚这一点。许可证执法唯一可能说得通的情形，是它对项目有好处的时候。而不是它对许可证执法有好处的时候”** `<!-- ROW_MINE: ksummit-discuss.messages.347184 -->`
- 【Linux社区】Jeremy Allison：以 Samba Team 的入团标准回应“只让把 Linux 利益放在心上的人管诉讼”——**“我本可以（事实上我确实看过）看一些你的公开演讲然后说‘如果你让那样的人掌管你的开发者团队，你是疯了’ :-)。每个人都有一些怪癖（引用《Q 大道》：‘每个人有时都有点种族主义’ :-)。你真的必须评判他们的工作，而不是他们的公众形象，我发现”**；其历史依据是 **“那很有趣——tridge 和我当年入选 Samba Team 的原始标准，是能够就 Samba 做出一个违背你雇主利益的决定。当我们第一次看到 IBM 员工这样做时，我们非常兴奋”**；对“执法须为项目利益”则 **“所以我 100% 同意这一点。这就是为什么当 Conservancy 代表我们时，它只在咨询项目开发者与利益相关方并达成共识之后才行动（并非所有利益相关方都写代码——我们有代表这一点的 ‘Samba Team’ 邮件别名）。人们可以有个人的议程，然后在该上班时把它放到一边。我见过 Bradley 那样做——不过再说一次，我认识他很久了”** `<!-- ROW_MINE: ksummit-discuss.messages.347185 -->`
- 【Linux社区】Matthew Garrett：就“项目利益”的定义向 Linus 提出界定性追问——**“你能否澄清一下，你是否认为：那些运行 Linux 的设备的所有者能够获得源码（即便厂商选择不参与上游）——是你认为对项目有好处的事情？”** `<!-- ROW_MINE: ksummit-discuss.messages.347186 -->`
- 【Linux社区】Jeremy Allison：以“开明自利”框架解释 SFC 与项目的关系——**“所以我认为你在这里漏掉的是你自己关于开明‘自利’的那个论证。是的，Bradley 和 Conservancy 有议程。当那个议程与自利与我们的一致时，他们代表我们（Samba）。当它们不一致时，什么都不会发生（记住他们只代表我们行动）。这就像开发一样——他们想要一件法律上的事，你想要另一件。只有当两者一致时你们才一起工作。到目前为止它运作得非常好（就像 Linux :-)”** `<!-- ROW_MINE: ksummit-discuss.messages.347187 -->`
- 【Linux社区】Linus Torvalds：以“诉讼威胁的实际外溢伤害”与“中国飞检公司”案例反问诉讼的项目收益——**“那个问题毫无意义。没有一个实际的案例，无法判断上行和下行，你的问题就是愚蠢的。你已经清楚地表明你不在乎下行。你似乎不认为这重要：是的，公司在诉讼面前会非常紧张，即便它们自己不是目标”**；其事实依据是 **“因为我确实知道一个事实：有些公司仅仅因为那些诉讼就停止使用 BusyBox。它们不是目标，它们没有滥用它，它们只是认定‘那是个爱打官司的项目，根本不值得冒险’”**；**“而你会获得的源码是什么？只是标准内核源码吗？要对项目有好处，诉讼就必须有要点——不只是某个技术细节。例如，有相当多（主要是中国的）飞检式公司，它们似乎只是把 Linux 装到自己的设备上、然后生产一次性产品。去追这样一家甚至没有修改源码、或只做了一两行蠢改动的公司，项目能得到什么？”**；**“我知道有些人绝对急切地想看看版权在中国到底如何运作，我一点也不怀疑如果你想要一个测试案例，那里会有案子。但是否真的有什么非常有意思的事情在发生？还是你只是想要一个在中国（或别处）的测试案例？还是只是有一个你不喜欢的专有模块，你想不顾我们多年接受它们的现实把它弄成衍生作品？这些是一个关心项目的人应该问的问题。你的问题看起来是那些把合规放在第一位的人会问的问题。看出区别了吗？”** `<!-- ROW_MINE: ksummit-discuss.messages.347188 -->`

- 【Linux社区】Theodore Ts'o：以 GSoC 指导的 ROI 数据给出爱好者指导的期望管理——**“也许值得考虑的是给考虑做 GSoC 导师的人的标准建议——你需要在指导职责上至少花 6-8 小时——而在那之后，大约 25% 的受指导者最终会留下来、对项目的贡献超过投入在其身上的时间；另外约 25% 在时间 ROI 上大致打平，然后其余 50% 最终在投入时间上是净亏损[1]。而这还是针对一个拿钱全职工作几个月的学生”**；**“这意味着，做指导的人应当带着‘搞成事’之外的其他目标去做。导师也许是想鼓励更多女性参与开源，例如。就像初创公司的股票期权，如果它在其他方面有回报，那纯属意外之喜——但不该指望它”**；其对比是 **“一般说来，新员工至少需要 3 个月、有时更多，学习如何使用构建和调试环境，之后才能真正指望他们有实质贡献。而这还是针对一个全职工作的员工！”**；**“从维护者的角度看，爱好者的挑战在于：完全无法保证任何一个特定的爱好者会留下来。而且不同于暑期实习生或新员工，爱好者一般不会全职工作。因此，指望大多数维护者花像实习生导师一样多的时间根本说不通；因为一个跑来找帮助的爱好者的预期回报，很可能远低于暑期实习生”**；其自述是 **“我会说，极难找到一个足够自主、能在最小协助下、以兼职方式开始折腾某个子系统或任何开源项目的人，而那些维护者毕竟在努力确保自己能恰当扩展”**；**“我从爱好者起步。但我在空闲时间每周至少花 20+ 小时学习 Linux——周末 12 小时左右，加上每个晚上或清晨的 2-3 小时。我基本没从项目得到任何‘支持’（当时项目就是 Linus 和像我这样的少数几个人）。Linus 没有为支持我这个爱好者做任何特别的事，除了在补丁是好补丁时接受它们。毕竟他当时自己也是个爱好者！:-)”**；**“与 1991 年的情况唯一的差别是内核变得复杂得多，所以一个人从零起步确实比我当时难得多。（虽然就我而言，我在作为有偿学生系统程序员时也有几年 BSD 4.3 开发经验、向 perl 和 tcsh 贡献过补丁、并且是 Kerberos 的技术负责人——所以就开源爱好者而言，我承认即便在开始做 Linux 之前也处于相当优越的位置。）”**；最后以自利算式收束 **“不过，在时间与投资回报方面的动态没有改变。从纯粹自利的角度看，如果你可以选择把时间投在某个被指派全职为你子系统工作的人身上（也许在你公司，也许在别的公司），还是把同样的时间投在一个爱好者身上——从理性的、经济自利的角度看，哪个选择说得通？”**（KS2014 档案） `<!-- ROW_MINE: ksummit-discuss.messages.347190 -->`
- 【Linux社区】Linus Torvalds：以“先公开羞辱与穷尽其他手段”的程序要求回应安全更新困境——**“那么你为什么不点名并非常公开地羞辱它们、先尝试其他一切办法？如果那家厂商还存在、还在卖别的设备，就把事闹大。听起来你私下已经跟他们谈过了，但为什么你现在开始谈想起诉他们的时候，还称他们为‘某家厂商’？”**；**“因为不那样做，答案永远会是绝对的不，仅仅因为那个‘绝对最后选项’的事”**；其效果质疑是 **“而你谈你如何帮助用户，但实际有多少人会真的升级？即便升级是自动的，最终升级固件的人也很少，更不用说那会意味着他们改用 OpenWRT 或 DD-WRT 之类（因为大概现有的固件最终含有大量即便打官司也拿不到的、非 GPL 的源码）？”**；**“换句话说，你说那是‘为了用户’，但在我看来它仍然闻起来像是实际上‘为了诉讼’。就实际效果而言，那会怎样帮助 Linux？”**；最后表态 **“我能理解被惹恼。我也被坏公司惹恼。但我也在说，诉讼不是自动的解决方案，你真的必须问自己是否值得。而且你必须先做很多其他事情”** `<!-- ROW_MINE: ksummit-discuss.messages.347191 -->`
