# 5.18.69 Linux 社区 Greg KH 以律师在场即风险的机理反对该场会议并纠正 LF 工具工作归属

- 【Linux社区】Greg KH：以“律师在场即风险”的机理反对该场会议，并纠正关于 LF 工具工作的归属——**“正如我之前所说，我不认为内核峰会是讨论这个的好地方，因为它涉及法律问题，而内核峰会是关于技术问题的。但是，我确实喜欢 Linus 那个‘只有开发者’在房间里谈这类事情的主张。没有律师、经理或‘代表’在场。那可能会很‘有趣’”**；其法律风险机理是 **“如你所深知，律师很容易因为在客户的律师不在场时与别人的客户讨论事情而被吊销执照，即便是在‘友好的情形’下。鉴于我们的公司归属，我们几乎所有人已经是其他律师的客户，而客户不能放弃在与其他律师谈话时要求自己的法律顾问在场的权利。所以提出像你这样的会议，对在场的任何人来说看起来都是巨大的风险。除非你指望我们都拖着自己的律师来，而再说一次，我不想参加一个被迫那样做的内核峰会”**；对工具归属则指出 **“那与 James 所指的工具大不相同。LF 一直在做的工作不是基于 CCFinder，而且（在我看来）强大得多，能提供关于作品归属和所有代码改动来自何处的更多信息。Daniel 的工作在巴塞罗那的一次会议上被展示过，我想你参加了，还有许多其他法律开源人士。工具的更新版本及其能力也于本周在 LinuxCon 向所有人展示……如你所知，学者对归属非常认真，请不要暗示你一直在与 Daniel 和 Kate 一起做这个项目，而就我所知，SFC 没有人这样做”** `<!-- ROW_MINE: ksummit-discuss.messages.347174 -->`
- 【Linux社区】Greg KH：以 Allwinner 的转变与 LCA 演讲引文给出“诉讼即失败”的完整论证——**“正如我之前所说，你不知怎么在说，如果我们不在法庭上‘捍卫’GPL，我们就得放弃它。而这完全不是真的”**；其对 Kuhn 演讲的转述是 **“你过去一年的 LCA 演讲，在网上有，你谈了很多关于 BusyBox 诉讼如何收场（导致了 Toybox 的诞生）、LLVM 如何出现（因公司不想与 FSF 和 GPLv3 打交道而获得支持），以及唯一剩下的可以‘争斗’的东西就是 Linux。我不想争斗。因为当你像这样开始争斗时，你就已经输了，正如我和现在的 Linus 一直在指出的”**；其 Allwinner 案例是 **“有人在关于这次邮件对话的 reddit 帖子里，试图引用 Linus，说了类似‘核选项早该对 Allwinner 用上’的话。而那恰恰证明了我的观点。Allwinner 曾长期是个麻烦。但作为开发者，并通过 Linux 基金会和 Linaro 许多人的努力，Allwinner 现在是内核的贡献者，并积极赞助开发者为其芯片写 GPLv2 代码。所以，如果在像你那样的谈话（在一位内核版权持有人代表与公司之间）破裂之后，你被迫采取法律行动。那我们就输了，即便你会‘赢’那场诉讼”**；**“说真的，这不是做事的方式。这些年来，是的，我的立场已经从看到设备出厂却不带其改动的代码时生气，转变为意识到我实际上能做的比任何律师都多得多。我能把那些开发者变成我们自己项目的一部分，确保我们能存活下去”**；其关键引文指控是 **“还有，在你的 LCA 演讲里你谈到 Linux 内核模块，如果我引错了请告诉我：‘而我们将不得不实际上对此作出裁决，我们现在别无选择。我过去回避这个，因为它被认为太有争议，但如果我们没有这场对抗，我们就不会有 copyleft。’”**；据此 **“那是一种非常危险的说法或做法。因为再说一次，如果你想裁决这个，那就意味着你愿意输。我去年在爱尔兰 LinuxCon 的大堂里、在一张有许多其他人在场的桌旁对你说过这个。你重视 GPL 甚于 Linux，而我重视 Linux 甚于 GPL。你愿意拿 Linux 去冒险，以便以某种方式验证 GPL。我完全不愿意为任何如此愚蠢的事拿 Linux 冒险。而我当时在一小群听众面前那么说了，现在也愿意在更大得多的听众面前这么说”**；**“你和 Karen 都说‘我们必须知道并捍卫这个’，但那正是把 Busybox 烧成灰、也正在威胁 gcc 未来的东西。Samba 在这种执法努力下存活下来是好事，但正如 Jeremy 所指出的，他主要是靠直接与公司合作、而不是让法律人士介入来做到这一点的。所以谢谢 Jeremy 证明了我的观点 :)”**；其结论是 **“让我们坚持那些把我们带到今天的东西，不要变成通过让律师介入来对我们的用户和开发者粗鲁无礼、不尊重。那样我们知道会导致我们失败。我经常说，唯一会导致 Linux 失败的东西就是我们自己做出愚蠢的事……我把这件事视为我们可能对自己做的那种极其愚蠢的事情之一……看看 Intel（在我们社区的成员非常努力地转变他们之前，他们曾是 GPL 最严重的违规者之一）、Allwinner 和 RockChip（越来越多参与我们的社区）乃至微软（如今通过运行 Linux 获得巨额收入，并因此赞助内核开发）。把今天你看到的那些厂商不看作‘违规者’，而看作‘我们社区的潜在成员’，并那样对待他们。这是我们继续存活和成长的方式。不这样做，就是扼杀我们自己的未来。你知道下一个作为 Linux 开发者巨额企业赞助者、对我们未来不可或缺的‘Intel’会是谁吗？我当然不知道，但我确实知道，用律师对待违规者，你就确保他们永远不会成为那种支持者”** `<!-- ROW_MINE: ksummit-discuss.messages.347175 -->`

- 【Linux社区】Julia Lawall：以学术审稿人视角反驳“发表压力导致工具不公开”的解释——**“作为学者，我看不出这个问题。我从未因为工具已经开源而拒绝一篇论文。相反，审稿人越来越多地抱怨工具不可获得、因而看不到它如何工作。我不知道 dmg 是谁、或他想在哪个社区发表，但更典型的让工具不可获得的理由是作者对当前状态不满意、没时间把它整理到自己引以为傲的状态、或目前没有资源来管理外部贡献。我猜非学术语境下也会发生同样的事。也许这个人担心如果工具可获得，别人就能收集他想收集的数据。但通常只有工具开发者最初才拥有以有趣方式收集和解读数据所需的时间、动力、愿景等”** `<!-- ROW_MINE: ksummit-discuss.messages.347178 -->`
- 【Linux社区】Hans Verkuil：指出新人留存的两道鸿沟并把问题归结为“是我们在赶人还是本来就难找”的开放性追问——**“它肯定不会有害，但我不确定这真的能解决多少问题。一般来说你只需找到你感兴趣的子系统的邮件列表（或子系统维护者的邮箱）并发邮件表示愿意帮忙。通常总有需要做的工作”**；其经验判断是 **“不过我的经验是，在表示愿意做某项工作与真正去做之间有很大鸿沟，而从提交一个补丁到成为常规贡献者之间的鸿沟至少一样大”**；其成因分析是 **“一个问题可能是，作为‘新手’，你最初能处理的问题往往是简单且常常相当无聊的（代码清理、sparse 修复等）。对核心代码的任何工作往往需要大量经验。而对特定驱动的任何工作则需要能接触到正确的硬件，而这通常安排起来很贵、或者干脆很难找到。我猜这可能就是为什么大多数常规贡献者最初都是从尝试支持自己或自己公司的硬件开始的。那往往是一个难度合适的项目：有挑战但通常不会太难，而且你会对子系统（软件、流程和人）学到很多”**；并以 media 子系统为例 **“在我工作的 media 子系统里，有足够多的驱动需要大量关照、会是新手的理想起点。但他们如何获得硬件来测试，他们又是否会有兴趣为一个 5 年前就已过时、更别说今天已经过时的硬件写驱动？”**；其核心追问是 **“我想我的观点是，我怀疑真正的问题是什么：是我们在赶走新手、因为自己这边的一些糟糕做法，还是说仅仅就是很难找到合格且有动力的开发者？答案请写在明信片上……”**（KS2014 档案） `<!-- ROW_MINE: ksummit-discuss.messages.347179 -->`
