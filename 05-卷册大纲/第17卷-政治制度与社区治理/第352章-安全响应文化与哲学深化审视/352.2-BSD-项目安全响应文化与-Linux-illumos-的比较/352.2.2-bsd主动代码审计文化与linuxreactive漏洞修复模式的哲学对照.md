# 352.2.2 BSD 主动代码审计文化与 Linux reactive 漏洞修复模式的哲学对照

  **要点**：OpenBSD 自 1996 年起践行主动代码审计（proactive auditing）文化，Theo de Raadt（西奥·德·若特） 主张“漏洞应在被发现前消除”，openbsd.duckdb 查询 L3.1.1.audit 显示 openbsd-src 中含 `audit` 关键词的 commit 自 1996 年起持续活跃，与 OpenBSD errata 563 条记录共同构成“审计-修复-加固”循环；FreeBSD 安全团队采用 reactive 漏洞响应模式，freebsd.duckdb 查询显示 freebsd-src 1791 条 CVE commit 中绝大多数为漏洞披露后修复，主动审计类 commit 较少；Linux kernel 采用 reactive 模式，依赖 CVE 报告与外部安全研究者提交补丁，2024 年成为 CNA 后 CVE 编号分配速度提升但主动审计投入有限；illumos 继承 Solaris 的安全审计传统但社区规模萎缩，freebsd.duckdb 查询 L7.4.1 显示 illumos-gate 中 ZFS 路径 commit 仅 22 条结果反映其活动量较低
  **史料**：OpenBSD 主动代码审计文化档案（openbsd.org 2026-07-22 直接访问确认"Only two remote holes in the default install, in a heck of a long time!"标语）、Theo de Raadt 演讲存档、FreeBSD Security Team 文档、Linux kernel security 文档、illumos-gate.duckdb 查询 L3.1.1.audit（OpenBSD `audit` 关键词 commit 演化）、illumos-gate.duckdb 查询 L7.4.1（illumos-gate ZFS 路径 commit 历史，22 行结果）［A］
  **史观**：总纲第 4 条——分离与聚合，OpenBSD 主动审计文化与 Linux reactive 模式是两种分离的安全哲学；延续与终结，OpenBSD 审计文化延续 CSRG 代码审查传统，Linux reactive 模式终结了 Unix 时代的代码审查
  **辨析**：“Only two remote holes”标语的具体起始年份需查 OpenBSD 官方页面历史存档（2007 年首次出现）；OpenBSD 主动审计的实际效果是否优于 reactive 模式须以漏洞密度（每千行代码漏洞数）对比，但 BSD 与 Linux 代码规模差异使该指标难以直接计算；illumos 社区规模萎缩是否导致安全审计投入下降需查 illumos-gate commit 时间序列；【0 信任原则·关键词匹配局限】L3.1.1.audit 查询以 `audit` 为关键词，可能匹配非安全审计语境（如 filesystem audit），须与 commit message 原文交叉验证
