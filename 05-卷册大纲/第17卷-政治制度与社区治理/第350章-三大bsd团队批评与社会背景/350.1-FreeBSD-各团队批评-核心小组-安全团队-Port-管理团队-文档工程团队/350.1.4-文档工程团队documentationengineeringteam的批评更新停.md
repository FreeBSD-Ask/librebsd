# 350.1.4 文档工程团队（Documentation Engineering Team）的批评：更新停滞、翻译项目荒废与工具链复杂

  **要点**：FreeBSD 文档工程团队（Documentation Engineering Team，简称 doceng）长期面临以下批评——FreeBSD Handbook 更新停滞，部分章节内容停留在 FreeBSD 12.x/13.x 时代，新特性（如 OpenZFS 2.x 新功能、boot  loader 改进）未及时文档化；多语言翻译项目近乎荒废，中文、日文、俄文、德文、西班牙文等翻译版本严重滞后于英文原版，部分语言的翻译停留在 FreeBSD 7.x/8.x 时代；文档工具链过于复杂，基于 DocBook + Hugo + Git 的构建流程门槛高，新贡献者难以参与；文档与代码的同步机制缺失，代码变更后文档往往不更新，导致文档与实际功能脱节；参见相关章节 FreeBSD 文档项目的事实搁置部分与文档贡献者相关内容部分
  **史料**：FreeBSD Handbook 各章节最后更新时间统计；多语言翻译项目状态与进度数据；doceng 邮件列表存档；文档构建工具链配置与贡献指南；新文档贡献者数量统计（按年度） ［A］
  **史观**：总纲第 15 条——文化即形式主义（原“社区与文明历史哲学”系伪名目，按族例改挂，存疑），文档工程团队的困境反映社区对文档价值的低估；总纲第 4 条——分离聚合是永恒规律（原“终结中的延续”系伪名目，按族例改挂），文档项目的“事实搁置”是文明传承的断裂
  **辨析**：“更新停滞”须区分核心章节与次要章节，核心章节更新相对及时；翻译项目荒废是全球开源项目的普遍现象，还是 FreeBSD 特有问题须比较；工具链复杂是技术选择问题还是资源投入问题须厘清
  **文献**：FreeBSD Handbook 历史版本；doceng 邮件列表存档；文档构建系统文档；多语言翻译项目页面 ［A］
