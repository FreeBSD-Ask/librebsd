# 254.8 BSD 与 Linux 的 Kernel 和用户空间 ABI 稳定问题

## 254.8.1 Linux 内核 ABI 稳定承诺：用户空间永不破坏
  - 要点：Linux 内核长期承诺“用户空间 ABI 永不破坏”（we don't break userspace），即新内核版本必须能运行为旧内核编译的用户空间程序。这一承诺由 Linus Torvalds 个人坚持，成为 Linux 内核开发的核心原则之一。Linux 内核 ABI 稳定承诺的工程后果是——旧用户空间程序可在新内核上运行（向后兼容），但内核内部 API 可以频繁变化（内核模块须针对每个内核版本重新编译）。这一承诺使 Linux 在企业市场具有强竞争力——企业可升级内核而不必重新编译所有用户空间程序。
  - **Linus Torvalds"we don't break userspace"原则引文**：

> We don't break userspace.
>
> ——Linus Torvalds，LKML 多次发言

- **Linux 内核 ABI 稳定承诺工程后果表**：

| 维度 | 内容 |
| --- | --- |
| 用户空间 ABI | 跨版本稳定（向后兼容） |
| 内核内部 API | 频繁变化（内核模块须重新编译） |
| 企业市场竞争力 | 强（升级内核不必重新编译用户空间） |
| 技术债务 | 累积（旧 ABI 不能移除） |

## 254.8.2 FreeBSD 内核 ABI 政策：大版本内稳定，跨大版本不保证
  - 要点：FreeBSD 内核 ABI 政策为“大版本内稳定，跨大版本不保证”——同一大版本（如 FreeBSD 14.x）内的内核 ABI 稳定，跨大版本（如 FreeBSD 13.x → 14.x）的内核 ABI 不保证稳定。这一政策使 FreeBSD 在大版本升级时常需要重新编译内核模块与部分用户空间程序。FreeBSD 的 ABI 政策比 Linux 保守——Linux 承诺用户空间 ABI 跨版本稳定，FreeBSD 仅承诺大版本内稳定。FreeBSD ABI 政策的工程后果是——FreeBSD 在大版本升级时较痛苦，但内核内部 API 可以在跨大版本时进行必要的重构。
  - **FreeBSD 与 Linux 内核 ABI 政策对照表**：

| 维度 | Linux | FreeBSD |
| --- | --- | --- |
| 大版本内 ABI | 稳定 | 稳定 |
| 跨大版本 ABI | 稳定 | 不保证稳定 |
| 大版本升级影响 | 用户空间无须重新编译 | 常需重新编译内核模块与部分用户空间 |
| 内核内部 API | 频繁变化 | 跨大版本可进行必要重构 |
| 企业市场竞争力 | 强 | 较弱（大版本升级痛苦） |

## 254.8.3 OpenBSD ABI 政策：每版本可破坏 ABI
  - 要点：OpenBSD ABI 政策最为激进——每个大版本（每 6 个月）都可以破坏 ABI，开发者无须维持 ABI 稳定。这一政策使 OpenBSD 能够进行激进重构（如 `pledge`/`unveil`、signal API 调整），但使用户必须每版本重新编译所有程序。OpenBSD ABI 政策反映 Theo de Raadt（西奥·德·若特） 的工程哲学——“代码清洁优先于用户便利”。OpenBSD 的激进 ABI 政策使其在企业市场几乎无竞争力（企业无法接受每 6 个月重新编译所有程序），但使其在安全研究与高安全需求场景中具有独特价值。
  - **OpenBSD ABI 政策工程后果表**：

| 维度 | 内容 |
| --- | --- |
| 大版本周期 | 每 6 个月 |
| ABI 稳定性 | 每版本可破坏 ABI |
| 工程哲学 | 代码清洁优先于用户便利 |
| 激进重构能力 | 强（如 `pledge`/`unveil`、signal API 调整） |
| 用户成本 | 每版本须重新编译所有程序 |
| 企业市场竞争力 | 几乎无（企业无法接受每 6 个月重新编译） |
| 安全研究价值 | 独特 |

## 254.8.4 NetBSD ABI 政策与 DragonFly BSD ABI 政策
  - 要点：NetBSD ABI 政策介于 FreeBSD 与 OpenBSD 之间——大版本内 ABI 稳定，跨大版本 ABI 不保证稳定，与 FreeBSD 类似；NetBSD 的特色是保证二进制兼容性在不同硬件平台间，这是 NetBSD 可移植性哲学的体现。DragonFly BSD ABI 政策由 Matt Dillon 个人主导，每个版本可破坏 ABI，与 OpenBSD 类似；DragonFly BSD 的 HAMMER 文件系统 ABI 在 HAMMER1→HAMMER2 转换时彻底改变，用户须迁移数据。
  - **NetBSD 与 DragonFly BSD ABI 政策对照表**：

| 项目 | 大版本内 ABI | 跨大版本 ABI | 特色 |
| --- | --- | --- | --- |
| NetBSD | 稳定 | 不保证稳定 | 保证二进制兼容性在不同硬件平台间（可移植性哲学） |
| DragonFly BSD | 每版本可破坏 | 每版本可破坏 | HAMMER1→HAMMER2 转换时彻底改变，用户须迁移数据 |

## 254.8.5 ABI 稳定问题的史观辨析：用户便利与代码清洁的根本张力
  - 要点：ABI 稳定问题反映开源操作系统的根本张力——用户便利（ABI 稳定）与代码清洁（ABI 可变）不可兼得。Linux 选择用户便利（ABI 稳定），获得企业市场竞争力但累积技术债务（旧 ABI 不能移除）；OpenBSD 选择代码清洁（ABI 可变），获得技术债务清理但失去企业市场；FreeBSD 介于两者之间，大版本内稳定跨版本可变，平衡用户便利与代码清洁。这一张力是开源操作系统的根本问题，无法通过工程优化彻底解决，只能在用户便利与代码清洁间动态平衡。
  - **BSD 与 Linux ABI 政策与工程哲学对照表**：

| 项目 | ABI 政策 | 工程哲学 | 企业市场竞争力 | 技术债务 |
| --- | --- | --- | --- | --- |
| Linux | 用户空间 ABI 跨版本稳定 | 用户便利优先 | 强 | 累积（旧 ABI 不能移除） |
| FreeBSD | 大版本内稳定，跨大版本可变 | 平衡 | 中等 | 中等（跨版本可重构） |
| OpenBSD | 每版本可破坏 ABI | 代码清洁优先 | 几乎无 | 持续清理 |
| NetBSD | 大版本内稳定，跨大版本不保证；跨平台二进制兼容 | 可移植性优先 | — | — |
| DragonFly BSD | 每版本可破坏 ABI | Matt Dillon 个人主导 | — | — |
