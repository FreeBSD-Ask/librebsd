# 262.4 GhostBSD 与 MidnightBSD 漏洞史与上游 FreeBSD 漏洞处置差异

## 262.4.1 ghostbsd-src 仓库的 592 个去重 CVE 与桌面 BSD 的被动同步模式
  - 要点：freebsd.db 查询显示 ghostbsd-src 仓库共 792 条 CVE 相关 commit、592 个去重 CVE，merge commit 比例在 2015 年为 2.1%（543/25,675）、2017 年 2.9%（601/20,562）、2022 年 1.1%（151/14,032），长期维持在 1-3% 水平；GhostBSD 作为桌面 BSD fork，其 CVE 修复完全依赖上游 FreeBSD 安全公告的被动同步——GhostBSD 本地团队不进行独立安全审计，而是通过 merge FreeBSD 安全分支获取修复；2022 年 merge commit 比例降至 1.1% 可能反映 GhostBSD 转向直接派生 FreeBSD 13.x 后同步节奏的变化；ghostbsd-src 的 592 个去重 CVE 与 FreeBSD 上游高度重叠，本地特有的安全 commit 极少

## 262.4.2 midnightbsd-src 仓库的 152 个去重 CVE 与 FreeBSD 6.x 基底的历史包袱
  - 要点：freebsd.db 查询显示 midnightbsd-src 仓库共 240 条 CVE 相关 commit、152 个去重 CVE，数量显著低于 ghostbsd-src（592 个）与 pfsense-src（567 个）；此差异源于 MidnightBSD fork 自 FreeBSD 6.x（2007 年），其代码库规模与上游同步频率均低于 fork 自较新 FreeBSD 版本的 GhostBSD；MidnightBSD 的 152 个去重 CVE 中包含 FreeBSD 6.x 时代的历史漏洞修复，这些漏洞在较新 FreeBSD 版本中早已修复但 MidnightBSD 因 fork 时间早而需独立跟踪；FreeBSD 6.x 系列 2005 年发布、2013 年停止支持，MidnightBSD 继承的 6.x 基底意味着其安全维护须覆盖上游已停止支持的版本周期

- 史观：总纲第 16 条——经济周期与资金约束，MidnightBSD 作为个人维护的小众桌面 BSD，其安全维护能力受限于 Lucas Holt 个人精力与社区规模，反映 fork 项目的结构性脆弱
- 辨析：midnightbsd-src 的 152 个去重 CVE 数量低于 ghostbsd-src 不必然意味着 MidnightBSD 更安全，更可能反映其 commit 追踪不完整或上游同步滞后——fork 自 FreeBSD 6.x 的代码库可能存在未被 commit message 显式标注 CVE 的已知漏洞；FreeBSD 6.x 停止支持（2013 年）后 MidnightBSD 是否独立 backport 安全修复须以项目 commit 记录与公告为准，不得仅凭 CVE commit 数量推断；MidnightBSD 的 fork 时间（2007 年）与 FreeBSD 6.x 发布时间（2005 年）须以项目官方文档核实
