# 263.2 JunOS 的演进与 FreeBSD 同步（2005-2026）

## 263.2.1 持续的控制平面 BSD 基础
  - 要点：JunOS 历次大版本（如 2000 年代至 2020 年代）维持 FreeBSD 控制平面，later 引入 Linux 兼容层（以运行现代工具），但核心仍为 BSD；具体版本对应 FreeBSD 基底须以 Juniper 文档核实。
  - 史料：JunOS 版本发布说明、Juniper 技术博客。 ［C］
  - 史观：总纲第 25 条——终结中的延续，BSD 控制平面在 JunOS 长期延续；统计结论印证：C-54（跨数据库关联分析 Task 28）显示 BSD 衍生 fork 项目 commit 时间序列呈强正相关（ghostbsd-src ~ pfsense-src rho = 0.9355），而 JunOS 作为商业闭源 fork 其 commit 不在公开仓库 Spearman 相关矩阵中，反映商业闭源 fork 与社区开源 fork 在工程可观测性上的结构性差异——社区 fork 的 commit 节奏可被统计分析，商业闭源 fork 的内部安全补丁回灌清单不可审计，0 信任原则适用：JunOS 内部 fork 的 FreeBSD 版本同步滞后（5.x 至 14.x 长期基于 FreeBSD 6.x）须以 Juniper 官方发行说明逐一核验，不得以无法核验即推论未回灌
  - 辨析：JunOS 引入 Linux 兼容层不意味放弃 BSD，须准确描述混合结构。
  - 文献：作者不详. Juniper JunOS 版本发布说明与官方文档[EB/OL]. 年份不详 ［B］

## 263.2.3 外部贡献者
  - 要点：JunOS 依赖 FreeBSD 网络栈贡献者与 Juniper 工程师；FreeBSD 网络社区对 JunOS 的间接贡献（如 `pf`、路由守护进程）须以 commit 记录（freebsd.duckdb）核实。
  - 史料：FreeBSD 网络贡献记录、Juniper 工程档案；freebsd.duckdb 查询 L7.2.1 显示：衍生项目贡献者在 freebsd-src 的回馈 commit 前 30 名（≥5 次）中，未出现 @juniper.net 或 @juniper.com 邮箱域名的贡献者，反映 Juniper 员工向 freebsd-src 上游直接回馈 commit 量未达前 30 名阈值（即 <5 次）或 Juniper 员工未使用企业邮箱提交；与 iXsystems 员工合计回馈约 715 次、LLNL <behlendorf1@llnl.gov> 单人 2,603 次形成对比，Juniper 对 freebsd-src 上游的直接回馈显著低于 OpenZFS 跨公司协作格局中的 iXsystems/LLNL/Delphix［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L1 代码/构建产物/L3 官方文档与公告〕
  - 史观：总纲第 10 条。
  - 辨析：具体贡献者须以公开记录核实；freebsd.duckdb 查询 L7.2.1 的“未出现 @juniper.net 邮箱贡献者”不等于 Juniper 零回馈——Juniper 员工可能使用 @freebsd.org 邮箱（被查询排除条件过滤）、个人邮箱或通过第三方（如 IronPort 被 Cisco 收购后邮箱变更）提交，且 Juniper 可能通过内部 fork 维护而非直接推送 freebsd-src 上游，须与 Juniper 工程档案、FreeBSD 提交权限记录、JunOS 发布说明中致谢名单交叉验证
  - 文献：freebsd.duckdb 查询 L7.2.1（衍生项目贡献者在 freebsd-src 的回馈 commit，≥5 次，前 30 名）；原材料/研究/bsd 仓库分析/数据分析/衍生项目与跨项目对比分析.md §L7.2；Juniper 档案。 ［A］
