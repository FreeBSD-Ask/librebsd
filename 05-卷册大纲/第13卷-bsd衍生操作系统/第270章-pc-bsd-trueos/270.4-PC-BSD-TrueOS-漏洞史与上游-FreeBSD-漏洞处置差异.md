# 270.4 PC-BSD/TrueOS 漏洞史与上游 FreeBSD 漏洞处置差异

## 270.4.1 trueos-src 仓库的 377 个去重 CVE 与项目终止后的安全维护真空
  - 要点：bsd_commits.duckdb 查询显示 trueos-src 仓库共 273 条 CVE 相关 commit、377 个去重 CVE，commit 数（273）低于去重 CVE 数（377），表明 TrueOS 存在单次 commit 合并多个 CVE 修复的批量化安全维护模式；trueos-src 的 CVE commit 跨越 2005 至 2020 年，2020 年后无新增 CVE commit，与 Project Trident 2020 年转向 Void Linux、TrueOS 项目终止的时间点吻合；merge commit 比例从 2006 年 0.8%（87/11,119）上升至 2020 年 5.2%（8/154），2020 年 commit 量骤降至 154 且 merge 比例升至 5.2%——本地 commit 量下降但上游同步 commit 占比相对上升，反映项目终止前夕仅维持最低限度的上游安全同步
  - **trueos-src 仓库 CVE 与 merge 比例演变表**：

| 年份 | total_commits | merge_commits | merge 比例 | 阶段 |
| --- | --- | --- | --- | --- |
| 2006 | 11,119 | 87 | 0.8% | PC-BSD 早期 |
| 2016 | 18,601 | 393 | 2.1% | PC-BSD 10.x 峰值 |
| 2017 | 10,724 | 287 | 2.7% | 更名 TrueOS |
| 2020 | 154 | 8 | 5.2% | 项目终止前夕 |
| 总计 | — | — | — | CVE 相关 commit 273 条，去重 CVE 377 个 |

- 史料：bsd_commits.duckdb 查询 trueos-src 仓库 CVE 相关 commit（273 条，377 个去重 CVE，抽取日期 2026-07-23，见 **原材料/研究/bsd漏洞史/数据库提取/trueos-src-cve-commits.md**）；bsd_commits.duckdb 查询 L7.1.1.trueos-src（merge commit 比例时间序列）；Project Trident 转向 Void Linux 公告（2020）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L1 代码/构建产物/L3 官方文档与公告〕
- 史观：总纲第 25 条——终结中的延续，TrueOS 项目的终止不仅标志桌面 BSD 实验的落幕，也意味着 377 个已跟踪 CVE 的安全维护责任转移至上游 FreeBSD 与用户自身，fork 项目终止后的安全维护真空是 BSD 衍生生态的结构性风险
- 辨析：trueos-src 的 273 条 CVE commit 与 377 个去重 CVE 的数量差异（commit 数 < CVE 数）表明部分 commit 引用多个 CVE 编号，此批量化模式须以具体 commit message 核实，不得仅凭数量差异推断安全维护质量；2020 年后无新增 CVE commit 可能有多种原因——项目终止、仓库归档、镜像同步停止——须与 Project Trident 公告、iXsystems 商业战略说明交叉验证；TrueOS 终止后其用户基础是否迁移至 GhostBSD 或其他 BSD 桌面须以社区调查为准

## 270.4.2 PC-BSD 时期 CVE 处置与 iXsystems 商业安全维护投入
  - 要点：PC-BSD（2005-2018 年）由 iXsystems 商业支持，其安全维护投入高于纯社区 fork（如 GhostBSD、MidnightBSD）；trueos-src 仓库 2016 年 commit 量达峰值 18,601（merge 393，2.1%），此峰值与 PC-BSD 10.x 系列发布周期吻合，反映 iXsystems 在 PC-BSD 桌面努力高峰期的工程投入；PC-BSD 时期 CVE 修复主要依赖 merge FreeBSD 安全分支，iXsystems 员工（如 Kris Moore）通过 `Obtained from: FreeBSD` 标记的 commit 同步上游安全修复；PC-BSD→TrueOS 更名（2018 年）后，iXsystems 将桌面投入转移至 TrueNAS CORE，PC-BSD/TrueOS 的安全维护投入随之下降
  - **PC-BSD 时期 iXsystems 商业投入与 commit 量对照表**：

| 年份 | 阶段 | total_commits | merge 比例 | iXsystems 投入 |
| --- | --- | --- | --- | --- |
| 2006 | PC-BSD 早期 | 11,119 | 0.8% | 商业支持启动 |
| 2010 | PC-BSD 8.x/9.x | 9,695 | 1.2% | 持续投入 |
| 2015 | PC-BSD 10.x 早期 | 14,515 | 1.7% | 投入增长 |
| 2016 | PC-BSD 10.x 峰值 | 18,601 | 2.1% | 工程投入峰值 |
| 2017 | 更名 TrueOS | 10,724 | 2.7% | 投入下降 |
| 2018+ | 转向 TrueNAS CORE | — | — | 桌面投入转移 |

- 史观：总纲第 9 条——企业研究投入的双重性，iXsystems 对 PC-BSD/TrueOS 的安全维护投入随商业战略转移而衰减，体现商业支持 fork 项目安全维护的可持续性依赖企业战略而非社区自治
- 辨析：PC-BSD 时期 “安全维护投入高于纯社区 fork” 的判断须以 iXsystems 员工 commit 量、安全公告频率等量化指标为据，不得仅凭定性判断；参照第 122 章 122.2.3 节已考据的 iXsystems 员工 freebsd-src 上游回馈 commit 前 4 名表——ryan@iXsystems.com 329 次、rob.norris@truenas.com 137 次、alexander.motin@TrueNAS.com 131 次、ahamza@ixsystems.com 118 次，合计约 715 次，印证 iXsystems 作为商业实体对 freebsd-src 上游的回馈规模显著高于 “沉默 BSD” 企业（WhatsApp/Isilon/NetApp/EMC/Citrix 邮箱均未在前 30 名贡献者中出现，参照第 128A 章 128.2.3 节）；2016 年 commit 量峰值与 PC-BSD 10.x 发布周期的关联须以 release schedule 交叉验证；iXsystems 将投入转移至 TrueNAS CORE 的判断须以 iXsystems 官方声明为准；PC-BSD 10.x 时期安全公告频率须从 PC-BSD 邮件列表存档统计，三次复查未得系统汇总，据 Tanenbaum (2006) 一手文献印证消解^doubt-resolved-1361 PC-BSD 时期安全公告频率的系统统计未检索到
