# 296.1.2 史料谱系

本卷史料基础呈“三支柱”结构：**bsd_commits.db** 量化数据库、厂商官方公告与法律文本、BSD 社区一手技术文献。
第一支柱为 BSD 仓库分析数据库（**bsd_commits.db**，概念性标识，2026-08-25 起已拆分为项目级 DuckDB 库）。该数据库覆盖 trueos-src、ghostbsd-src、hardenedbsd-src、midnightbsd-src、truenas-middleware、opnsense-core、pfsense-src 等 7 个 BSD 衍生 fork 仓库及 freebsd-src、linux-kernel 上游仓库，共 23 个仓库 8,404,397 commits、9,674 tags，为本卷量化考据提供代码级证据。其独特价值在于：通过 merge commit 比例时间序列（L7.1.1）可识别 fork 项目的上游同步节奏与本地分歧量，通过 CVE 相关 commit 抽取（如 pfsense-src-cve-commits）可量化各 fork 项目的安全维护强度，通过商业实体 commit 占比（L3.2.1、L3.2.2）可量化“沉默 BSD”企业的回馈不对称程度。但其局限亦明显：fork 仓库 commit 历史含上游继承部分，本地特有 commit 须经 parent_hashes 交叉验证；邮箱域名识别遗漏使用个人邮箱或 @freebsd.org 提交者；commit 量不等于代码质量或工程投入。
第二支柱为厂商官方公告与法律文本。Sony Interactive Entertainment PS4 OSS 披露页面（2013）证实 Orbis OS 内核基于 FreeBSD，是 PlayStation OS 商业采用争议的“许可证合规”一手法律证据；Juniper JSA10713 安全公告（2015-12-17）由 SVP 兼 CIO Bob Worrall 署名，承认 ScreenOS 中存在“unauthorized code”，对应 CVE-2015-7755（CVSS 3.1 评分 9.8 CRITICAL）与 CVE-2015-7756，揭示 BSD 商业闭源 fork 不可审计的结构性风险；PlayStation.Blog 2010-03-28 PS3 Firmware v3.21 公告以“due to security concerns”为由移除 OtherOS 功能，触发 Ventura v. SCEA 集体诉讼（case no. 4:10-cv-01811，N.D. Cal.，2010-2014）；UC Berkeley 1999-07-22 BSD License Amendment 公告弃用广告条款，是 BSD 许可证扩散力第二次跃升的法律节点。
第三支柱为 BSD 社区一手技术文献。FreeBSD Handbook §1.2.2 是“沉默 BSD”企业谱系识别的官方基准；OSI BSD-2-Clause 与 BSD-3-Clause 定义页面是许可证扩散机制的法律基准；McKusick 等《The Design and Implementation of the 4.4BSD Operating System》（1996）为 BSD 谱系技术史提供版本断代基准；USENIX FAST'21 Looney 主题演讲、SREcon23 Asia/Pacific Suefuji-Miyahara 演讲、HotStorage’13 Godman 演讲、BSDCan 2018 Loewen-Gallatin 演讲构成 BSD 商业采用的一手工程叙事。
二手研究方面，Bonaccorsi-Rossi 2003 年《Research Policy》论文“Why Open Source software can succeed”提出的“利他程序员”与“商业开源”二元模型，是本卷 BSD 许可证扩散力论证的核心理论支撑，直接解释 BSD 生态如何在不强制开源衍生作品的前提下维持商业可持续性。其局限在于 2003 年发表，未覆盖 2010 年代后 TrueNAS SCALE 转 Linux、PlayStation OS 回馈不对称等新议题。FreeBSD Foundation Netflix Case Study 作为基金会宣传材料，对 FreeBSD 商业采用的整体回馈结构缺乏批判性分析，须与 **freebsd.duckdb** 量化数据交叉印证。
