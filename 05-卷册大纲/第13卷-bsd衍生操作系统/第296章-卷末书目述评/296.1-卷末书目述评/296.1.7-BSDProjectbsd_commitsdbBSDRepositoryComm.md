# 296.1.7 BSDProjectbsd_commitsdbBSDRepositoryComm

BSD Project. **bsd_commits.db**: BSD Repository Commit Database [DB/OL]. 本地 DuckDB 数据库集（原 SQLite 库已于 2026-08-25 全库 DuckDB 化时拆分为项目级 DuckDB 库，bsd_commits.db 为概念性标识，实际查询指向各项目级库）。覆盖 trueos-src、ghostbsd-src、hardenedbsd-src、midnightbsd-src、truenas-middleware、opnsense-core、pfsense-src 等 7 个 BSD 衍生 fork 仓库及 freebsd-src、linux-kernel 上游仓库，共 23 仓库 8,404,397 commits、9,674 tags。

> 本卷量化考据的核心数据库，由项目方从 GitHub 镜像抓取构建。其独特价值在于通过 merge commit 比例时间序列（L7.1.1）识别 fork 项目上游同步节奏与本地分歧量，通过 CVE 相关 commit 抽取量化各 fork 项目的安全维护强度，通过商业实体 commit 占比（L3.2.1、L3.2.2）量化“沉默 BSD”企业的回馈不对称程度。局限在于 fork 仓库 commit 历史含上游继承部分，本地特有 commit 须经 parent_hashes 交叉验证；邮箱域名识别遗漏使用个人邮箱或 @freebsd.org 提交者；commit 量不等于代码质量或工程投入。

### 卷末总评

本卷史料以 **freebsd.duckdb** 量化数据库、厂商官方公告与法律文本、BSD 社区一手技术文献三支柱为骨干，二手研究以 Bonaccorsi-Rossi 2003 二元模型为理论支撑，辅以 McKusick 1996 4.4BSD 设计专著与 FreeBSD Foundation Netflix Case Study 案例材料。主要缺口：Juniper、Sony、Netflix 等企业内部决策档案未公开；fork 仓库 commit 元数据存在邮箱域名识别偏差；失败的桌面 BSD 项目口述史严重不足；非英语 BSD 衍生项目史料基础薄弱。未来方向为通过企业合作与 FOIA 申请补全商业内部档案、通过 GitHub API 与 LinkedIn 交叉验证补全 commit 元数据、通过 BSDCan/EuroBSDCon 会议采访补全桌面 BSD 项目口述史、通过多语种学术数据库扩展国际化视角。
