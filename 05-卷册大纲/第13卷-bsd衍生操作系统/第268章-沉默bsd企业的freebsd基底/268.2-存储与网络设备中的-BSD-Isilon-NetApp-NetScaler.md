# 267.2 存储与网络设备中的 BSD（Isilon/NetApp/NetScaler）

## 267.2.1 FreeBSD 在存储/网络设备的基底
  - 要点：EMC Isilon 的 OneFS 基于 FreeBSD；NetApp ONTAP 含 BSD 网络栈渊源；Citrix NetScaler（ADC）基于 FreeBSD；这些设备在企业数据中心广泛部署但 BSD 身份不对外强调。

| 企业 | 产品 | FreeBSD 基底 | BSD 成分范围 | 商品形式名称 |
| --- | --- | --- | --- | --- |

| NetApp | ONTAP | 含 BSD 网络栈渊源 | 网络栈 | Data ONTAP 操作系统 |
| Citrix | NetScaler ADC | 基于 FreeBSD | 应用交付控制器 | NetScaler 操作系统 |

- 史观：总纲第 25 条——终结中的延续，BSD 在企业设备中长期延续但 “沉默”；统计结论印证：C-54（跨数据库关联分析 Task 28）显示 BSD 衍生 fork 项目 commit 时间序列呈强正相关（ghostbsd-src ~ pfsense-src rho = 0.9355），而 Isilon/NetApp/EMC/Citrix 等 “沉默 BSD” 企业作为商业闭源部署其 commit 不在公开仓库 Spearman 相关矩阵中，反映 “沉默 BSD” 企业与社区开源 fork 项目在工程可观测性上的结构性差异——这些企业的 BSD 延续（Isilon OneFS、NetApp ONTAP、Citrix NetScaler 跨越 10-20 年）无法通过 commit 时间序列统计分析验证，须以各厂商架构文档、OneFS/ONTAP/NetScaler 发布说明、致谢名单交叉印证，0 信任原则适用：L3.2.1/L3.2.2 的邮箱域名识别存在局限，Isilon 被 Dell/EMC 收购、EMC 被 Dell 收购、Citrix NetScaler 部门被 TIBCO 收购后员工邮箱迁移导致 commit 量统计低估，且 “沉默 BSD” 企业可能通过内部 fork 维护而不直接推送 freebsd-src 上游
- 辨析：各产品 BSD 成分的具体范围须以官方架构文档确认，避免夸大；openbsd.db 查询 L3.2.1 与 L3.2.2 的 Isilon/NetApp/EMC/Citrix 占比须警惕邮箱域名识别不精确——Isilon 被 Dell/EMC 收购后员工邮箱可能迁移至 @dell.com 或 @emc.com，EMC 被 Dell 收购后邮箱可能迁移至 @dell.com，Citrix NetScaler 部门被 TIBCO 收购后邮箱可能变更，commit 量不等于各企业对 FreeBSD 的依赖程度，须与各厂商架构文档、OneFS/ONTAP/NetScaler 发布说明交叉验证
- 文献：各厂商官方架构文档；openbsd.db 查询 L3.2.1（商业实体 commit 占比随时间变化，含 Isilon @isilon.com、NetApp @netapp.com、EMC @emc.com、Citrix @citrix.com）；openbsd.db 查询 L3.2.2（商业实体 commit 量按仓库分布）；原材料/研究/bsd 仓库分析/数据分析/深层信息挖掘.md §L3.2.1、§L3.2.2。[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]
