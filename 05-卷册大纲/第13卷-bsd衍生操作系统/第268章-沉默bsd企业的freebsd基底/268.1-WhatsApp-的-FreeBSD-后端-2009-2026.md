# 268.1 WhatsApp 的 FreeBSD 后端（2009-2026）

## 268.1.1 Erlang on FreeBSD 的高并发
  - 要点：WhatsApp（2009 起）以 FreeBSD + Erlang 构建后端，单服务器支撑百万级并发连接，是 FreeBSD 在消息基础设施的标志性案例；其架构在行业会议（如 Erlang/FreeBSD 相关）被披露。
  - **WhatsApp/Facebook/Meta 商业实体 commit 占比时间序列表（L3.2.1，全 23 仓库汇总）**：

| 年份 | commercial_commits | total | 占比 |
| --- | --- | --- | --- |
| 2017 | 2,841 | 344,697 | 0.824% |
| 2018 | 3,887 | 336,461 | 1.155% |
| 2020 | 3,820 | 303,425 | 1.260% |

**史料**：WhatsApp 工程演讲（一手来源）、FreeBSD 中与 WhatsApp 相关讨论/commit（bsd_commits.db 若可考）；bsd_commits.db 查询 L3.2.1 显示：WhatsApp 母公司 Facebook/Meta（@facebook.com 邮箱域名）商业 commit 在全 23 仓库汇总的 commercial_commits 中与其他 11 个商业实体合并统计，2017 年 commercial_commits = 2,841/total = 344,697（0.824%）、2018 年 3,887/336,461（1.155%）、2020 年 3,820/303,425（1.260%），Facebook/Meta 单一实体占比须按邮箱域名细分查询；bsd_commits.db 查询 L3.2.2 显示：商业实体 commit 量按仓库分布中 freebsd-src 仓库 907 commits（含 Facebook/Meta 等多实体合计），未单独列出 facebook.com 占比 ［A］

**史观**：总纲第 9 条——企业研究投入的双重性，WhatsApp 以 FreeBSD 实现极端规模效率；统计结论印证：C-54（跨数据库关联分析 Task 28 多元 Spearman 相关矩阵显示 fork 项目 ghostbsd-src ~ pfsense-src rho = 0.9355 强相关）反映 BSD 衍生 fork 项目 commit 时间序列存在工程节奏同源性，而 WhatsApp 作为商业实体其 FreeBSD 后端不在公开 fork 仓库 Spearman 相关矩阵中，且 L3.2.1 显示商业实体 commit 占比不足 1.3%（2020 年 3,820/303,425），反映 WhatsApp 作为 “沉默 BSD” 企业其工程可观测性结构性缺失——WhatsApp 后端的 FreeBSD 定制 commit 不在 bsd_commits.db 23 仓库覆盖范围，0 信任原则适用：L3.2.1 的邮箱域名识别存在局限，WhatsApp 被 Facebook 收购后员工邮箱迁移至 @facebook.com，且 WhatsApp 工程师可能用个人邮箱提交，commit 量不等于 WhatsApp 对 FreeBSD 的依赖程度

**辨析**：WhatsApp 的 FreeBSD 使用细节（如具体版本、调优）部分未公开[考据完成：2026-07-28 经穷尽联网考据，WhatsApp 工程演讲与中文技术媒体（CSDN、biaodianfu.com、toutiao.com）多源印证——WhatsApp 后端使用 FreeBSD 9.2 与 Erlang/OTP，单服务器支撑 200 万并发连接，系统容量大于 8000 核心，每秒 Erlang 消息超 7000 条；技术栈含 Yaws、lighttpd、PHP、BEAM 定制补丁、Mnesia 数据库、深度改造的 ejabberd（以自有协议替代 XMPP）；选择 FreeBSD 的动因是创始团队在 Yahoo 时期积累的 FreeBSD 经验与 FreeBSD 网络栈的可靠性；但具体 FreeBSD 版本演进（从 9.2 后续升级路径）、内核调优参数、Erlang Factory 演讲存档的精确链接等细节 WhatsApp 官方从未系统性公开披露，保留为史料缺口]；openbsd.db 查询 L3.2.1 与 L3.2.2 的 WhatsApp/Facebook 占比须警惕邮箱域名识别不精确——WhatsApp 被 Facebook 收购后员工邮箱可能从 @whatsapp.com 迁移至 @facebook.com，且 WhatsApp 工程师可能用个人邮箱提交，commit 量不等于 WhatsApp 对 FreeBSD 的依赖程度，须与 WhatsApp 工程演讲、Erlang Factory 会议存档交叉验证[双库验证 2026-08-15] WhatsApp 使用 FreeBSD 经参考文献库（FOSDEM 2019 Deb Goodkin "25 Years of FreeBSD" 演讲）确认；WhatsApp 单服务器支撑 200 万并发连接的性能数据在双库中无法直接验证 [存疑脚注]，须以 WhatsApp 工程演讲一手来源交叉验证

**文献**：WhatsApp 工程演讲存档；行业会议资料；openbsd.db 查询 L3.2.1（商业实体 commit 占比随时间变化，含 Facebook/Meta @facebook.com）；openbsd.db 查询 L3.2.2（商业实体 commit 量按仓库分布）；原材料/研究/bsd 仓库分析/数据分析/深层信息挖掘.md §L3.2.1、§L3.2.2。 ［A］

**要点**：

- GNN 阐述 TeachBSD 缘起：他与 Robert Watson 认为操作系统课程教学方式与业界脱节，遂制作开源教学材料并托管 GitHub（接受补丁），目标一是让大学用上 BSD 以获得新开发者，二是以 FreeBSD 的 DTrace 等创新改进教学。（BSD Now EP136，[1830.00-1933.00]，L1）
- GNN 批判三种既有教学范式：给本科生直接改内核的“试炼之火”（百万行代码加八周学制必致挫败）、玩具操作系统（丧失异步性与真实负载）、研究生论文综述课（不写代码）；TeachBSD 以 DTrace 让学生安全地实验真实内核，如推导 TCP 状态机、观测 IO 对缓存的影响。（BSD Now EP136，[2035.00-2293.00]，L1）
- TeachBSD 推广进展：剑桥研究生课已开两轮，实践者课在 AsiaBSDCon 第二次开设；朱拉隆功大学等推广演讲已启动，UC Santa Cruz 的 Darrell Long 与 Ethan Miller 自发将 OS 课程转向 FreeBSD；教学指南与出版社 Pearson 的登录墙合作在规划中。（BSD Now EP136，[2517.00-2758.00]，L1）
- Faces of FreeBSD 的 Scott Long：1992 年在伯克利 FTP 服务器发现 i386BSD 0.1，2000 年获 commit bit，2002 至 2006 任发布工程师负责 5.x 与 6.x，自述早期 5.x 不佳却是 6.x 成功的必要踏脚石；著有 MFI/MPS 存储驱动、UDF 文件系统，并实施 CAM 存储栈的多粒度锁定，现于 Netflix 从事可扩展性工作。（BSD Now EP136，[3462.00-3565.00]，L2）
- 新闻综述：FreeBSD 10.3 发布（延展支持至 2018 年 4 月底，10.2 至 10.3 升级免重编译）；WhatsApp 以 Signal 协议为全平台十亿用户开启端到端加密，仅由约十五名工程师完成，其服务器端运行 FreeBSD；Ed Maste 报告 LLD 已可构建可运行的 FreeBSD 用户态，内核仍用 LD.BFD。（BSD Now EP136，[76.00-1263.00]，L2）
- 愚人节玩笑与史实互证：微软“三亿美元收购 FreeBSD 品牌、仓库与社区”一文故意放大常见误解（基金会拥有源码仓库、OpenBSD/NetBSD 是 FreeBSD 子品牌），主持人逐一澄清仓库归项目所有、基金会只持商标等法人职能，并指出 Windows 的 Linux 子系统反而借用了 FreeBSD Linux 仿真层思路。（BSD Now EP136，[4055.00-4133.00]，L2）
- 本期核心受访者 Aaron Poffenberger 为休斯顿软件开发者，自述其 BSD 之路：1995 年前后朋友创办的 ISP 与相邻 FreeBSD 站点共用一条 T1 线路，此后在任职公司受 FreeBSD 前核心团队成员 Rich Murphy 以 Walnut Creek CD 相引，2002-2003 年因 OpenBSD 3.3 十分钟安装即成与二进制包需求由 Gentoo 转投 OpenBSD 并沿用至今，又因听本节目而决意在 Texas Linux Fest 面向 Linux 用户开讲。（BSD Now EP107，[1338.88-1576.28]，L1）
- 本集新闻以 Wired 报道收束于 FreeBSD 的产业纵深：WhatsApp 以约 50 名工程师支撑 9 亿用户，1980 年代 Ericsson 为电话系统设计的 Erlang 配合 FreeBSD 网络栈维持数百万并发 TCP 连接，被 Facebook 收购后底座未变；主持人并补充 Facebook Messenger 转用 Haskell，Google 与 Mozilla 以 Go 与 Rust 追逐同类部署灵活性。（BSD Now EP107，[1094.84-1224.04]，L2）
- 技术动态层面，主持人转述 Alexander Motin 已将 CTL 高可用实现提交至 FreeBSD 11：双头存储控制器经自定义 TCP interlink 协调磁盘访问，设 active-unavailable、active-standby、active-active、active-proxy 四种模式，因协议不含认证而仅限内部链路使用；早年仅有纸面设计，落地由此次提交完成。（BSD Now EP107，[562.04-792.60]，L2）
- Rick Reed 于 MeetBSD California 2014 自述 WhatsApp 架构与规模：200 台 chat 前端与约 350 台多媒体服务器辅以后端账户数据与离线存储集群，后者仅在消息于收发双方之间传输时暂存数据；当时已逾 6 亿月活用户，峰值 1.4 亿并发连接、每秒 44 万新连接、每秒 110 万条用户消息（含在线状态等事件约每秒 300 万次）、每日图片逾 10 亿；其技术底座为 Erlang actor 模型与 FreeBSD SMP 扩展性——每个手机连接对应一个约 1600 字节的 BEAM 轻量进程，无共享状态、纯消息传递、调度线程逐一绑定 CPU 线程，单机可承载数百万连接；当事人将一台 chat 前端负载加倍实测，CPU 利用率自约 55% 平滑升至 98% 至 99% 并可全天满载，调度器利用率曲线与 CPU 曲线贴合、争用损耗极小，内核经少量调优后几乎不构成障碍，集群曾因节点持续 95% 满载 24 小时而触发过热告警，系统本身仍稳定运行。（BSDTalk EP250，[537.44-1153.74]，L1）
- FreeBSD 选型先于现团队：创始人 Jan Koum 与 Brian Acton 均出身 Yahoo 平台工程，凭其大规模互联网服务经验认定 FreeBSD 的 TCP 栈质量与稳定性突出、发布可预期、文档与内核内部资料齐备，足以支撑预想中的大规模服务；当事人本人在 Yahoo 曾编写内核模块并负责平台库与操作系统之间的接口层，此前任职 Silicon Graphics 从事视频服务。（BSDTalk EP250，[305.48-392.50]，L1）
- 当事人梳理生产版本迁移史：2009 至 2010 年运行 FreeBSD 7，升级 8 后性能改善但遇到 zero-copy socket 导致消息在写入 socket 与发出网卡之间损坏的问题（关闭该特性解决）、IGB 网卡锁死（回移稳定分支驱动修复）与内核拒绝采用稳定的 TSC 时钟源（补丁强制启用）；2011 年优化后单机曾达约 280 万连接；2013 年迁至 FreeBSD 9 后运行近两年，随机 panic 几乎绝迹，仅余机器检查异常与 UFS 因此前崩溃损坏引发的停机。（BSDTalk EP250，[2001.16-2151.66]，L1）
- 存储实践：全线使用 UFS 并以 JBOD 直连磁盘、弃用 RAID 卡（仅视频服务器以 gmirror 提供镜像），文件系统按离线信箱、图片、视频等负载分别定制块大小与 fragment 大小；实测机械盘在持续满负荷下写入上限约每秒 45 至 50 MB（曾与 Kirk McKusick 协作分析），离线消息约半数在写入后 25 秒内即被取走，大量落盘仅服务持久化冗余；调宽 dirty buffer 与拉长 sync 延迟会使 syncer 行为突发化、总体吞吐反降，遂回退默认写穿并以应用层缓存补足读取；崩溃恢复采取三级策略——先以 soft updates 快速恢复上线，再崩溃则并行全量 fsck，必要时顺序 fsck，另以扩容 UFS dirhash 缓存超过 2 GB 的哈希目录树。（BSDTalk EP250，[1891.88-2477.94]，L1）

**史观**：

- 总纲9 经验优先：TeachBSD 以 DTrace 让学生在真实内核上做实验并写出实验报告，GNN 强调学生面对的是企业同款“真实世界工件”，这是以真实经验替代玩具模型的教学取向。（BSD Now EP136，[2263.00-2287.00]，L1）
- 总纲3 不存在进步，只有权力再分配：Scott Long 对早期 5.x 的评价把“失败版本”重构为通往 6.x 成功的必要环节，是对技术史中进步叙事的修正——版本序列并非单调上升而是偶然与代价的链条。（BSD Now EP136，[3526.00-3539.00]，L2）
- 总纲3 不存在进步，只有权力再分配：受访者以 Jails 为例向 Linux 听众论证：这项 1997-1998 年为 ISP 隔离用户而生的 FreeBSD 技术成熟二十年，而 Linux 世界直到 Docker 兴起才重拾进程隔离话题；同一技术的能见度随生态话语权更迭而消长，提示技术史书写不应以先进与否立论，而应追踪解决方案与话语权之间的错位流转。（BSD Now EP107，[1876.42-1934.52]，L1）
- 总纲8 本体论上各方平等：受访者同时立下面向 Linux 社区演讲的伦理底线：不可怀敌意赴会，须承认选择 Linux 有坚实的技术理由，以 drop-in 替代场景展示 BSD 价值而非宣布对方选择错误；生态比较史的书写同样不应滑向贬损叙事，各系统在本体论层面并无高下。（BSD Now EP107，[2309.86-2431.36]，L1）
- 总纲10 动手者创造历史：约 12 人的服务器团队维系 6 亿用户规模的服务：配置管理仅用 make 人工维护、负载分配依赖 DNS 轮询、重大变更先投放到承担约半个百分点流量的单台服务器观察；Erlang 热代码加载使系统可在数百万人在线且满速运行时完成升级，三年间全系统宕机仅一次（Facebook 收购公告之后）。大规模服务的实际承载者是少数动手运维者，而非站在台前的明星开发者。（BSDTalk EP250，[2757.34-3331.58]，L1）
- 总纲5 没有必然性，只有偶然性：关键技术选型皆为具体偶然条件的汇合而非理性推演的必然：Erlang 自创办之初即入选，因其时存在可用的开源 XMPP 服务器、且项目以替代短信为志而电信渊源的 Erlang 显得契合；FreeBSD 则系创始人 Yahoo 经历的自然延续。当事人回忆当年在 Yahoo 视 Erlang 为多余的新语言，直到亲历 WhatsApp 才体会其威力，可见技术路径由具体人事与时机决定。（BSDTalk EP250，[3243.08-3278.70]，L1）

**辨析**：

- 愚人节文本声称基金会出售源码仓库，与事实相反：仓库由项目维护，基金会仅承担商标与合同等需法人实体的职能；该辨析对理解基金会与项目边界具有史料价值。（BSD Now EP136，[4061.00-4099.00]，L2）
- 主持人转述 Ted Unangst 对可复现构建的限定：它不防 Shellshock 类代码级漏洞，也无法对抗 trusting trust 式编译器后门——若编译器全域被攻陷，可复现性只会忠实复现后门；其结论是可复现构建是工具箱中的一件工具而非安全终点，这对 Debian 主导的可复现构建热构成边界辨析。（BSD Now EP107，[4014.74-4277.72]，L2）
- 标题所称“5 亿毫不知情的 FreeBSD 用户”点出沉默使用现象：终端用户无从感知底层操作系统，自由软件的扩散依赖企业生产采用而非用户选择，当事人开场亦以现场举手调查印证知情者寥寥；此为“沉默 BSD 企业”现象的当事人自证，但亦须辨析——企业愿意公开自述者（如本场演讲）恰是沉默群体中的例外，样本代表性有限。（BSDTalk EP250，[178.32-191.12]，L1）
