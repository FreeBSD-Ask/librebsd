# 261.4 pfSense 与 OPNsense 漏洞史与上游 FreeBSD 漏洞处置差异

## 261.4.1 pfsense-src 仓库的 CVE 继承与 pfSense 低频上游同步策略
  - 要点：freebsd.db 查询显示 pfsense-src 仓库共 929 条 CVE 相关 commit、567 个去重 CVE，merge commit 比例在 2016 年为 2.3%（661/28,813）、2017 年 2.4%（629/26,654）、2022 年 1.3%（133/10,179），长期维持在 1-3% 水平，显著低于 hardenedbsd-src 同期 24.3% 的 merge 比例；此差异反映 pfSense 的上游同步策略——pfSense 以 Netgate 商业发布周期为导向选择性合并 FreeBSD 安全修复，而非像 HardenedBSD 那样频繁全量同步上游；pfsense-src 的 567 个去重 CVE 中绝大多数为继承自 FreeBSD 上游的修复 commit，pfSense 本地特有的安全 commit 须通过 parent_hashes 交叉验证识别
  - **pfsense-src 与 hardenedbsd-src 上游同步策略对照表**：

| 维度 | pfsense-src | hardenedbsd-src |
| --- | --- | --- |
| CVE 相关 commit | 929 条 | 1670 条 |
| 去重 CVE | 567 个 | 627 个 |
| 2016 年 merge 比例 | 2.3%（661/28,813） | 24.3%（10,726/44,207） |
| 2017 年 merge 比例 | 2.4%（629/26,654） | 23.6%（9,667/40,943） |
| 2022 年 merge 比例 | 1.3%（133/10,179） | — |
| 上游同步策略 | 选择性合并，以商业发布周期为导向 | 频繁全量同步上游 hardened 分支 |

- 史料：bsd_commits.db 查询 pfsense-src 仓库 CVE 相关 commit（929 条，567 个去重 CVE，抽取日期 2026-07-23，见 `原材料/研究/bsd漏洞史/数据库提取/pfsense-src-cve-commits.md`）；bsd_commits.db 查询 L7.1.1.pfsense-src（merge commit 比例时间序列）；Netgate 安全公告档案〔L1 代码/构建产物/L3 官方文档与公告〕
- 史观：总纲第 9 条——企业研究投入的双重性，Netgate 作为商业防火墙厂商以发布周期为导向选择性同步上游安全修复，体现商业产品安全维护与社区同步节奏的张力
- 辨析：pfsense-src 的 567 个去重 CVE 须区分 “继承自 FreeBSD 上游的修复” 与 “pfSense 本地特有 commit”——fork 仓库的 commit 历史包含上游继承部分，识别本地特有 commit 须通过 merge commit 与 parent_hashes 交叉验证，不可仅凭时间戳判定；merge commit 比例低不必然意味着安全修复滞后，须与 Netgate 官方安全公告、pfSense 发布记录交叉验证——Netgate 可能通过独立分支维护安全补丁而非直接 merge 上游 commit；pfsense-src commit 量从 2016 年 28,813 降至 2022 年 10,179 的下降趋势须与 Netgate 商业战略调整、pfSense Plus 商业版推出等事件交叉验证
- 文献：bsd_commits.db 查询 pfsense-src CVE commit（929 条，567 去重 CVE，2026-07-23）；bsd_commits.db 查询 L7.1.1.pfsense-src；`原材料/研究/bsd漏洞史/数据库提取/pfsense-src-cve-commits.md`；`原材料/研究/bsd仓库分析/数据分析/衍生项目与跨项目对比分析.md` §L7.1。 ［B］

## 261.4.2 CVE-2019-11816 OPNsense 权限提升漏洞与 Web 界面安全
  - 要点：2019 年 5 月 19 日，opnsense-core 仓库记录了 CVE-2019-11816 的修复 commit `03c75f71be88d4d2d930c217377b5ff23f0ecae7`（author Ad Schellevis，committer Franco Fichtner），subject 为 "system: address CVE-2019-11816 privlege escalation bugs"，报告者为 Arnaud Cordier；此漏洞为 OPNsense Web 界面的权限提升，攻击者可利用 Web 管理界面的输入验证缺陷获取更高权限；bsd_commits.db 查询显示 opnsense-core 仓库共 8 条 CVE 相关 commit、4 个去重 CVE，数量远低于 pfsense-src（929 条），反映 OPNsense core 仓库仅承载 OPNsense 自身应用层代码，底层 FreeBSD 基底漏洞由 FreeBSD 上游跟踪

**要点**：

- pfSense 自 1.x 至 2.0 更换了系统几乎每一个部分，2.0 至 2.1 之间最大的工程量投向 IPv6 支持；升级链按配置版本逐级执行转换步骤，即便 2005 年的早期 alpha 安装亦可直取最新稳定版 2.1.3，升级后最常见的故障实为久未重启的硬件问题而非升级本身。（BSDTalk EP242，[147.06-283.24]，L1）
- pfSense 2.1 系列因 FreeBSD 9.0 对其用途缺陷过多而滞留于 8.3 基线，且其 8.3 并非原版——团队从 FreeBSD 10 回移植了 Intel 千兆与万兆驱动等；正在开发的 2.2 改基于 10-STABLE，以贴近上游、更快获得驱动与性能改进并回馈补丁，内核补丁集随之显著缩小。（BSDTalk EP242，[293.20-422.46]，L1）
- Heartbleed 影响 pfSense 2.1 与 2.1.1：所用 OpenSSL 服务于 Web 管理界面与 OpenVPN，Web 界面可被未认证攻击者窃取会话 cookie；OpenVPN 默认配置因启用 TLS 认证而构成部分缓解；2.0 与 1.x 因 OpenSSL 版本较旧而不受该漏洞影响，但按 Buechler 的说法这些旧版积压着大量其他漏洞，升级仍是唯一正解。（BSDTalk EP242，[439.88-527.74]，L1）
- pfSense 的商业形态是软件全部免费可得、在自由软件之上叠加价值：支持服务、官网直销硬件、T 恤与预载 U 盘等周边，以及 Gold 订阅——提供每次变更即加密上云的自动配置备份、随订阅更新的项目书籍与由订阅者投票选题的月度在线交流；主持人将此与其他产品扣留关键功能、逐渐阉割免费版的做法对比并予以肯定。（BSDTalk EP242，[727.62-889.37]，L1）
- pfSense 将许可证自两条款 BSD 改为 OpenSSL 式许可并强化商标执行：对普通用户无实质变化，但约束利用其构建商业产品而不回馈者，引发不满；社区随之出现该项目将彻底闭源的传言，Buechler 作为当事人亲见自己在 Reddit 上被告知其公司将要做什么，并逐条否认。（BSDTalk EP242，[689.60-937.54]，L1）

**史料**：

- 本期为 BSDCan 2014 会期对 Chris Buechler 的访谈，其口述涉及的一手材料包括 store.pfsense.org 直销渠道与 Netgate 硬件、Gold 订阅的自动配置云备份服务与月度 hangout、Reddit 上关于闭源传言的讨论串，以及仍在运行 2005 年 0.7 alpha 的真实部署实例。（BSDTalk EP242，[98.30-846.48]，L1）

**史观**：

- 总纲13 法律与道德是利益分配：许可证变更与商标执行是开源治理中利益再分配的具象现场：同一份代码以许可条款重新划定了谁能商用、是否必须回馈的边界，被约束者以闭源预言施加舆论压力，公司则以在自由软件上叠加价值、软件永不收费的承诺自辩；争论双方争的并非技术优劣，而是利益与信任的分配格局。（BSDTalk EP242，[689.60-978.70]，L1）

**辨析**：

- 主持人承认社区对 pfSense 商业化路径的担忧有合理依据，并举 Vyatta 曾限制 ARP 表条目数以模拟 Cisco 式主机数上限为前例；Buechler 承认担忧合理但断言 pfSense 不会走上同类道路。双方对话呈现了开源项目商业承诺可信度的结构性难题：口头保证无法消除对先例的合理警觉，此断言只能由后续行为检验。（BSDTalk EP242，[938.90-978.70]，L1）
