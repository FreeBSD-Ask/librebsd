# 261.1 pfSense 的 FreeBSD 根基（2004-2014）

## 261.1.1 从 m0n0wall 到 pfSense
  - 要点：pfSense 由 Chris Buechler 与 Scott Ullrich 于 2004 年 9 月自 Manuel Kasper 的 m0n0wall（FreeBSD 嵌入式防火墙）分叉而来，目标是克服 m0n0wall 作为嵌入式系统的可扩展性局限——m0n0wall 功能强大但受限于嵌入式形态，pfSense 旨在提供更完整的 FreeBSD 防火墙发行版；pfSense 沿用 FreeBSD 的 `pf`/`ipfw`、Packet Filter 与 Web 管理，并由 BSD Perimeter（后更名为 Netgate）提供商业支持，是 FreeBSD 在网络防火墙领域的主导产品。m0n0wall 项目于 2015 年 2 月 15 日由 Manuel Kasper 宣布永久终止，Manuel Kasper 在终止公告中鼓励 m0n0wall 用户迁移至 OPNsense，标志 BSD 防火墙谱系中 m0n0wall 时代的终结与 pfSense/OPNsense 双雄格局的最终形成。

- 辨析：pfSense 与 m0n0wall 的分支关系时间点（2004）须以项目历史核实；openbsd.db 查询 L7.1.1.pfsense-src 的 commit 量须警惕 fork 分歧识别局限——pfsense-src 仓库 1993 年起的 commit 是 fork 自 FreeBSD 继承的上游历史，非 pfSense 项目本地 commit，识别 pfSense 本地特有 commit 须通过 merge commit 与 parent_hashes 交叉验证，不可仅凭时间戳；commit 量下降可能反映 Netgate 商业战略调整或镜像同步滞后，须与 Netgate 公告、pfSense 发布记录交叉验证[双库验证 2026-08-15] pfSense 在 BSD 安全工具中的位置经参考文献库（vBSDCon 2017 网络安全工具论文）确认；OPNsense 经参考文献库（2024 网络安全培训系统论文）确认；m0n0wall 于 2015 年 2 月 15 日终止与 pfSense 于 2004 年 9 月发起的精确日期在双库中无法验证 [存疑脚注]

**要点**：

- 2015 年 1 月，荷兰 Deciso 公司工程师 Jos Schellevis 以 OPNsense 核心团队身份受访，说明该项目从 pfSense 分叉的缘由：公司商业产品原以 pfSense 为基础，曾尝试改用 Linux 开发新品线，最终认定 BSD 在既有功能与系统稳定性上更具优势，遂回归 FreeBSD 基座另立门户；项目名取“Open Makes Sense”之意，主张技术结构、社区协作与透明三项原则，认为多数开源项目欠缺工程化的结构约束，单靠个人难以长期维系。　[存疑脚注] 转写将受访者记作 Joss Shellevis、项目记作 OpenSense，当为 Jos Schellevis 与 OPNsense，系依 2015 年 1 月 pfSense 分叉事件链推断（BSD Now EP72，[1395.70-1479.82]，L1）
- OPNsense 的工程路线呈现为对继承物的系统性重构：Captive Portal 已整体重写以摆脱 pfSense 遗留补丁，其余特性逐个迁移；架构上把需要 root 权限的功能移入基于 Phalcon 框架的后端守护进程，PHP 仅保留给无需特权的 Web 前端；发布采取半年周期并配日期版本号与大鸟代号（现版 Ascending Albatross，下一版预告 Rocketing Robin），并强调代号仅为便于用户记忆的参照。（BSD Now EP72，[1767.94-2041.20]，L1）
- 基座维护策略揭示了分叉项目的上游同步难题：OPNsense 15.1 基于 FreeBSD 10.0，而后者 2015 年 2 月即终止支持，下一代 15.7 却要等到 7 月，期间依靠安全补丁回移维持；系统内建升级走 FreeBSD pkg 包系统，计划结合 pkg audit 实现安全更新的定向强制升级，且明确将快速发布周期置于长期支持方案之前。（BSD Now EP72，[1523.22-1679.90]，L1）
- 本期新闻记录了 OpenBSD 安全机制的演进节点：将 W^X（同一内存页不可同时可写与可执行）从用户态扩展至内核，使注入代码无法执行而只能触发崩溃，既阻断利用又暴露异常；内核态实现容错空间远小于用户态、调试更难，AMD64 与 SPARC64 因 MMU 硬件支持获得额外优势，技术细节见 CVS 提交。（BSD Now EP72，[515.52-616.44]，L2）
- 听众问及经多国运输的商业 CD 套装是否可能被情报机构截获篡改，节目转引 OpenBSD 邮件列表回复：常规做法并不拦截替换 CD，且可用 signify 工具校验镜像完整性；Theo de Raadt 戏称 CD 标签以“放射性颜料”印刷、在全球邮政系统中更易寻获（4675.76-4683.92），以反讽回应阴谋式担忧。　[存疑脚注] 转写将校验工具记作 Sinify，当为 signify（OpenBSD 5.5 起引入的签名校验工具），系上下文推断（BSD Now EP72，[4592.50-4692.86]，L2）
- John-Mark Gurney 自述 1994 年经同学影响接触 A/UX 与 Unixware 后，在 Slackware（目录硬性布局）、NetBSD（当年安装文档难懂）与 FreeBSD 之间选择后者，以 230KB 引导块完成 1.1.5.1 安装；高中时期提交 fsck 指定文件系统参数的约五六十行补丁并持续撰写工具与 SCSI man page，1997 年初获 commit bit。　[存疑脚注] 转写记为 AUX、fisk、MS-TOS，分别应为 A/UX、fsck 及待核的 DOS 变体；引其入 commit bit 的 George 具体所指待核。（BSD Now EP61，[900.66-1115.64]，L1）
- IPsec 现代化项目由 Netgate（pfSense 开发商）的 Jim Thompson 发起、经 FreeBSD Foundation 资助 Gurney 执行：FreeBSD opencrypto 框架长期缺失 AES-CTR 与 AES-GCM 模式，未利用 AES-NI 与 PCLMULQDQ 指令，项目目标是在廉价商用硬件上经 pfSense 实现约 10Gb/s 加密转发，而彼时软件加密仅数百 MB/s。（BSD Now EP61，[1117.88-1264.12]，L1）
- 当事人给出密码学工程论证：CBC 加密因块间数据依赖无法流水线化（解密方向可反向并行），CTR 以加密计数器异或明文消除依赖；GCM 作为 AEAD 将加密与认证合一提升吞吐；ChaCha20-Poly1305 尚处草案但其软件性能适合无 AES 指令的设备；Gurney 自写的新 GCM 软件实现性能优于 OpenBSD 版并计划反馈；他主张密码学实现应从五个收敛为两三个以便修错与复核，并指出 OpenBSD 版本缺少 FreeBSD 的 SMP 锁但差异仅数行。（BSD Now EP61，[1355.10-1662.62]，L1）
- 主持人转述 OpenBSD 5.6（2014 年 11 月 1 日发布）要点：作为六个学期准时发布周期的延续，5.6 是首个正式搭载 LibreSSL 的版本，新增休眠至全加密文件系统的能力；移除 AltQ 插件式流量整形框架（研究使命完成，HFSC 直用并简化配置），并处于服务栈过渡期——Apache 已由 Nginx 替代、下版再由 httpd 接替，Sendmail、BIND 分别让位 OpenSMTPD 与 Unbound，Kerberos、Bluetooth、TCP wrappers 同时移除；发行歌与 CD 套装销售为 OpenBSD Foundation 主要收入。　[存疑脚注] 转写将 httpd 记为 HDBD、OpenSMTPD 记为 open SMTBD，须以 5.6 官方 changelog 复核。（BSD Now EP61，[479.30-754.10]，L2）
- pfSense是2004年前后创立的开源防火墙发行版，以FreeBSD为基底并完全通过Web界面管理，当事人将其定位为Cisco ASA、SonicWall、WatchGuard等商业防火墙的可比替代。（BSD Now EP25，[837.28-868.96]，L1）
- 当事人回顾其IT从业经历，称约2000年因对Linux发行版不满而转向BSD，此后主要基于FreeBSD运行服务器、路由器与防火墙，并在2004年参与pfSense的创建。（BSD Now EP25，[807.72-845.60]，L1）
- 2004年选择FreeBSD而非OpenBSD的理由包括：当时FreeBSD PF更快、OpenBSD无线支持明显不足，且pfSense代码始于m0n0wall、部分功能依赖FreeBSD特有的IPFW以按MAC地址过滤实现captive portal。（BSD Now EP25，[1306.32-1396.40]，L1）
- 采访当时pfSense的2.2版本正基于FreeBSD 10开发，目标是获得更好的SMP可扩展性与硬件支持；此前2.1基于FreeBSD 8.3，并曾在8.1结束生命周期后继续回移必要安全更新。（BSD Now EP25，[1447.56-1513.84]，L1）
- 当期新闻提及FreeBSD 10可运行于Ubiquiti EdgeRouter Lite等低成本嵌入式设备，该设备采用MIPS64处理器、512MB内存，可作为消费级路由器替代。（BSD Now EP25，[212.76-241.04]，L2）
- 本期为 bsdtalk 第 157 期，主持人以感冒沙哑嗓音独自播报，开篇即澄清“不是换新主持”（0.0-16.0）；他承认上月仅产出一期节目、远低于自我目标，频率从创刊期的每周一至两期回落至约两周一期，并向长期沉默期间仍订阅的听众致歉（61.8-75.56、321.3-330.04）。此自述为社区播客生产的可持续性问题留下当事人一手旁证。（BSDTalk EP157，[0.0-75.56]，L1）
- 当事人口述学区 BSD 运维实况：一台 NetBSD 机器长期运行于 Cobalt 硬件，承担 MRTG 流量图与部分 NetFlow 分析，但未深入核心基础设施（82.4-94.32）；学区正筹划改造 DHCP 与 DNS 服务以增强冗余——一条路线是支持同步的 dhcpd 第三版，另一条是 OpenBSD 新近引入、复用其防火墙状态同步机制的补丁，能否进入 4.4 版本尚不确定（94.32-129.96）；现役 DNS 服务器中仍有三百兆赫兹级老旧机器且硬盘开始衰竭，亟待更换（129.96-142.96）。（BSDTalk EP157，[82.4-142.96]，L1）
- NYCBSDCon 2008 定于 10 月举行、报名开放与讲者名单公布的消息之后（151.3-163.26），主持人宣布会议期间每天固定时段做约一小时现场直播，并自认不擅长以独白填充空档、宁以提问让与会者畅谈各自如何使用 BSD（171.9-198.98）；他向听众征询 BSD 友好的直播客户端与服务器软件：提及 Linux Live CD Dyne:bolic 的成功先例与架设 Icecast 服务端的思路（205.86-218.46），希望借 iXsystems 解决 BSD 硬件选型问题，并主张在 BSD 会议上以 BSD 软硬件完成直播才属妥当（232.62-254.58）。（BSDTalk EP157，[163.26-254.58]，L1）
- 主持人入手一台 Soekris 5501——无移动部件、以闪存盘作存储、带四个 10/100 以太口的 AMD 系小型机，常被用作防火墙；因学区已升级至可峰值千兆的 Internet 2 连接，此机无法胜任校内防火墙（254.58-284.18）；他点名 m0n0wall 及基于其派生的项目（286.62-295.82），并征询除此之外的非常规用途，自设选项包括 Asterisk 小型语音服务器、家用应答机与家用防火墙，同时认定防火墙仍是此类设备的典型应用（299.62-321.3）。（BSDTalk EP157，[254.58-321.3]，L1）
- 核心团队成员回顾 7.x 系列的市场反馈：SMP 扩展性改进兑现为大规模性能提升，用户得以在高速多核服务器上完成服务器整合，把原本需要多台机器的负载并入一机，同时降低空间与能耗开销；大量基于 6.x 的企业与设备厂商正加速向 7.x 迁移，实际升级远不如其担忧的那样痛苦；7.2 定位为 7.x 线的精炼版本。（BSDTalk EP173，[309.9-364.8]，L1）

- 关于 pfSense，核心团队将其定位为面向防火墙场景的嵌入式 FreeBSD 衍生发行版，配以 web 管理界面；该产品直接集成 8.x 的虚拟接入点支持，使单块无线网卡可承载多个 SSID 与属性各异的网络，并吸纳了在 FreeBSD 社区搁置已久的 NAT-T 补丁；其大规模部署为这些代码提供了额外的实战检验，反馈回流使代码回归 base 树时更成熟，pfSense 团队亦因此受邀参加开发者峰会，带来与既有 PR 渠道不同的用户需求清单。（BSDTalk EP173，[1460.4-1553.9]，L1）
