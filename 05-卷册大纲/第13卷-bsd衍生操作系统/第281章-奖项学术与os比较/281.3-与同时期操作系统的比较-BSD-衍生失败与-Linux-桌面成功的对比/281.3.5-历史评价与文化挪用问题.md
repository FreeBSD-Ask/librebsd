# 281.3.5 历史评价与文化挪用问题

  - 要点：Linux 桌面成功背后的 BSD 文化挪用问题是历史评价的核心维度。Linux 桌面生态的诸多 “原生” 要素实际源自 BSD：发行版概念（Linux 发行版概念源自 BSD 的 Ports 与二进制软件包体系，386BSD patchkit 1992 → Slackware 1.0 1993-07、Debian 0.91 1994-01）、容器概念（Linux 容器概念源自 BSD 的 **jail(2)** 与 **chroot(2)** 机制，PHK 1999 jail → LXC 2008、Docker 2013）、文件系统设计（FFS 1984 → ext2 1993 间接路径）、网络栈（Berkeley sockets API 1983 → Linux 0.96 1992-05 直接沿用）、软件包管理（BSD ports 1994-1995 → dpkg 1994-01、apt 1998-03、yum 1999、pacman 2002）、系统调用（**kqueue(2)** 2000-07 → Linux **epoll(7)** 2002-10）、安全机制（Capsicum 2012 → Linux Landlock 2021）、手册页格式（BSD man 文化 → Linux man/GNU info 文化）。Linux 桌面 “成功” 叙事在建构自身 “原生性” 的同时，系统性地遮蔽了 BSD 端的先验贡献，构成文化挪用的典型样本。但须警惕简单化的 “BSD 是原创者，Linux 是挪用者” 叙事——文化挪用研究的目的不是建构新的 “BSD 受害叙事”，而是通过考据揭示 “Linux 原生” 叙事的建构性，使被遮蔽的 BSD 端先验贡献重新生成于历史叙事之中。这种历史评价须保留双方的主体性，避免阵营对立的形式主义化。
  - **Linux 桌面成功背后的 BSD 文化挪用典型样本表**：

| 挪用维度 | BSD 端先验 | Linux 端挪用 | 挪用模式 |
| --- | --- | --- | --- |
| 发行版概念 | 386BSD patchkit 1992 | Slackware 1.0 1993-07、Debian 0.91 1994-01 | 淡化源头 + 社区重塑 |
| 容器概念 | FreeBSD **jail(2)** 2000-03 | LXC 2008、Docker 2013、Podman 2018 | 概念更名 + 商业重塑 |
| 文件系统设计 | FFS 1984（McKusick） | ext2 1993 间接路径 | 重写即归属 |
| 网络栈 | Berkeley sockets API 1983 | Linux 0.96 1992-05 直接沿用 | 淡化源头 |
| 软件包管理 | BSD ports 1994-1995 | dpkg 1994-01、apt 1998-03、yum 1999 | 概念更名 |
| 系统调用 | **kqueue(2)** 2000-07 | Linux **epoll(7)** 2002-10 | 淡化源头 + 重写即归属 |
| 安全机制 | Capsicum 2012（Watson/Anderson） | Linux Landlock 2021 | 淡化源头 + 社区重塑 |
| 手册页格式 | BSD man 文化 | Linux man/GNU info 文化 | 文化重塑 |

- 史观：总纲第 15 条——文化即形式主义（见 据原文第 20 章 20.2 节 “BSD 之于 Linux，犹如农耕文明之于工商业文明——并非落后，而是不同的形式主义选择”），BSD 端的 “ports 文化”、“jail 文化”、“man 文化” 在 Linux 端 “形式主义化” 过程中被遮蔽与重构，文化即形式主义，传统在更名与重构中被遮蔽；总纲第 21 条——革命与改革是历史方法论的分歧（见 据原文第 21 章 21.1 节 “Linux 的发展依靠不断的革命与彻底否定（或在其基础上再发展），而 BSD 这里只是不断的改革。改革的困难远高于革命，但确实带来了稳定和好处”），BSD 端 “改革”（rc.d 框架的渐进演化、jail 概念的渐进扩展）与 Linux 端 “革命”（systemd 的革命性重构、Docker 的革命性重命名）构成 “历史方法论的分歧”；总纲第 11 条——商品是形式主义（见 据原文第 8 章 8.1 节 “商品本身是一种形式主义。不是人们在追求商品，而是商品在召唤人们”），Linux 桌面 “成功” 叙事通过商品化形式主义的权力运作反向剥夺了 BSD 端的 “历史记忆与归属权”；总纲第 19 条——历史解释学与权力（见 据原文第 19 章 19.3 节 “什么是‘重要的’历史事件，什么被记录，什么被遗忘，什么被视为‘错误’，什么被视为‘进步’——这些判断背后都有权力的运作。历史书写中的选择本身就是一种权力行使”），Linux 桌面 “成功” 叙事中的 “什么被记录，什么被遗忘” 本身就是权力行使；总纲第 22 条——知识注定过时（见 据原文第 22 章 22.1 节 “今天书写的技术史，可能在出版之日就已过时”），Linux 桌面 “原生” 叙事作为 “今天的知识” 注定过时，BSD 端被遮蔽的 “历史存在” 在数字档案中既面临 “被遗忘” 的威胁，也面临 “被重新发现” 的机遇
