## 259.4.1 CVE-2007-3798 **tcpdump(1)** 缓冲区溢出与 HardenedBSD stack protector 的防御纵深
  - 要点：2007 年 8 月 1 日，FreeBSD 上游（freebsd-src）记录了 CVE-2007-3798 的修复 commit `faeb38d111efa1ecad5565f314581e95ce3ac7f8`（author Simon L. B. Nielsen），对应 FreeBSD-SA-07:06.tcpdump，修复 **tcpdump(1)** 中的缓冲区溢出，HardenedBSD 经同步继承该修复；HardenedBSD 在同步此上游修复的同时，其 hardened 编译标志（含 `-fstack-protector-strong`）为此类栈缓冲区溢出提供了运行时检测层——当溢出覆盖 stack canary 时触发 `__stack_chk_fail` 终止进程而非放任代码执行；freebsd.duckdb 查询显示 hardenedbsd-src 仓库共 1670 条 CVE 相关 commit、627 个去重 CVE，merge commit 比例在 2016 年达 24.3%（10,726/44,207），显著高于 ghostbsd-src（2.1%）、pfsense-src（2.3%）同期水平，反映 HardenedBSD 频繁同步 FreeBSD 上游安全修复的工程节奏

## 259.4.2 CVE-2017-5715 Spectre 漏洞与 HardenedBSD ASLR 的有限缓解
  - 要点：CVE-2017-5715（Spectre Variant 2，分支目标注入）于 2018 年 1 月披露，hardenedbsd-src 仓库记录了相关修复 commit；HardenedBSD 的 ASLR（基于 PIE 的地址空间布局随机化）对此类 CPU 侧信道攻击的缓解效果有限——ASLR 随机化内存布局以增加 ROP 攻击难度，但 Spectre 利用 CPU 微架构层面的分支预测机制，ASLR 无法阻止推测执行的信息泄露；此案例揭示编译期与运行时缓解机制对硬件层漏洞的边界，HardenedBSD 仍须依赖微码更新与 Retpoline 编译技术（`-mretpoline`）来缓解 Spectre，与上游 FreeBSD 的处置路径一致
  - **CVE-2017-5715 Spectre 与 HardenedBSD 缓解机制边界对照表**：

| 披露方 | Google Project Zero |
| HardenedBSD 缓解机制 | ASLR（基于 PIE 的地址空间布局随机化） |

| 漏洞利用层面 | CPU 微架构层面（分支预测机制） |
