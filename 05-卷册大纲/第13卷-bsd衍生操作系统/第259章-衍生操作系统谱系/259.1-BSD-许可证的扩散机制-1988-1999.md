# 259.1 BSD 许可证的扩散机制（1988-1999）

## 259.1.1 宽松许可与专有再分发
  - **要点**：BSD 许可证（1988 年 UCB 文本、1999 年精简为 2/3 条款）允许代码在保留版权声明前提下用于专有产品，使 BSD 成为网络设备与嵌入式系统的首选基底；此机制是 BSD 谱系扩散的法律根源。
  - **BSD 许可证演变与谱系扩散机制表**：

| 年份 | BSD 许可证文本 | 关键变化 | 谱系扩散意义 |
| --- | --- | --- | --- |
| 1988 | UCB 文本 | 含广告条款 | — |
| 1999 | 精简为 2/3 条款 | 弃用广告条款 | 进一步降低专有再分发门槛 |

- 史观：总纲第 24 条——许可证直接决定代码扩散形态；统计结论印证：C-54（跨仓库 Spearman 相关分析 ghostbsd-src ~ pfsense-src rho = 0.9355 p = 9.154e-184）反映 BSD 衍生项目在 commit 时间序列上存在强正相关，体现 BSD 许可证扩散下衍生谱系的工程节奏同源性——多个 fork 项目同步跟随 FreeBSD 上游的发布周期与安全公告节奏，0 信任原则适用：Spearman 秩相关仅反映时间序列共动性，不等于因果关联，且强相关可能由共同的上游 FreeBSD 同步行为驱动而非 fork 间的直接工程影响［存疑脚注：rho = 0.9355、p = 9.154e-184 的显著性量级与年度序列样本规模（约 33 年）不匹配，待复核统计口径］
- 辨析：BSD 许可与 GPL 的“扩散哲学”差异（最大化再使用 vs 最大化自由回馈）须客观论述，避免价值优劣判断；**freebsd.duckdb** 查询 L1.1.1 的 commit 量仅反映开发活跃度，须结合 commit 规模（additions/deletions）与 message 质量综合判断，且 GitHub 镜像仓库 commit 量可能滞后于主仓，衍生项目时间序列的“分化”判断须与各项目公告、邮件列表交叉验证
