# 284.7.2 总纲4分离聚合是永恒规律见据原文第25章总纲4UNIX与BSDBSD各分支之间的

- 总纲 4“分离聚合是永恒规律”（见 据原文第 25 章 总纲 4）——“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”。pfSense 2004 年从 m0n0wall 分叉、2014 年 OPNsense 从 pfSense 分叉，是 BSD 衍生谱系分离聚合循环的连续呈现。Buechler 详述 pfSense 选择 m0n0wall 而非 FreeBSD 主线作为基础，是一次“分叉的分叉”，体现分离聚合循环的多层级递归结构——衍生项目本身亦可成为下一轮分离聚合的起点。
- 总纲 11“商品是形式主义”（见 据原文第 25 章 总纲 11）——“技术市场的选择不是自然选择，而是形式主义的权力运作。劣币驱逐良币是普遍规律”。Buechler 对 pfSense 商业化的辩护——pfSense 公司的商业化为社区版提供持续工程资源——揭示 BSD 商业化项目中商品形式主义与社区资源再分配的辩证关系：商业化并非纯粹对开源的背叛，社区版亦非纯粹对商业的超越，二者皆是商品形式主义化过程中的形式主义化呈现。须辩证看待：Buechler 的辩护与 Fichtner 的批评形成对照，但二者皆非对商品形式主义的超越。
- 总纲 13“法律与道德是利益分配”（见 据原文第 25 章 总纲 13）——“任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”。Buechler 与 Fichtner 对 pfSense 商业化方向的争议，本质上是 pfSense 社区内部利益分配的争议，而非“封闭开发”vs“开源纯洁”的道德二元对立。Buechler 强调商业化为社区版提供工程资源，Fichtner 强调商业化损害社区驱动——二者皆是利益分配形式主义化的具体呈现，须以利益分配而非道德判断的视角理解。
- 自反性声明：本释读本身也是一种形式主义化的重构，不声称是对项目统摄史观的客观正确解读。释读中“pfSense 与 OPNsense 互为分叉体现分离聚合递归结构”的判断本身也是一种形式主义化的对称化处理，可能遮蔽 pfSense 2004 年从 m0n0wall 分叉与 OPNsense 2014 年从 pfSense 分叉两次事件中社区动力学的不可化约差异；释读中“Buechler 与 Fichtner 争议本质上是利益分配而非道德二元对立”的判断本身也参与将道德判断与利益分析二元对立化的形式主义运作，可能遮蔽 Buechler 辩护中真实存在的工程伦理维度；释读中“pfSense 2.4 至 2.5 迁移须以利益分配视角理解”的判断本身也是一种形式主义化的还原，可能遮蔽 Netgate 工程师在迁移过程中对 FreeBSD ABI 稳定性的真实工程判断，欢迎被更自反的释读所超越（见 据原文第 27 章 27.2 节）。

- FreeSBIE 的定位：基于 FreeBSD 的 Live 操作系统，无须安装即可从 CD 介质运行，当时最新稳定版 1.1 基于 FreeBSD 5.3；用途是为试驾 FreeBSD 与在安装前测试硬件兼容性；项目另设 toolkit 开发分支，用于生成 CD、U 盘或 CompactFlash 等可启动介质，2.0 版 toolkit 已被 pfSense、DesktopBSD、PC-BSD 等项目采用，成为制作可启动 BSD 系统的标准化工具。（BSDTalk EP37，[194.64-266.6]，L1）
- 2.0 版的技术转折与 unionfs 危机：当事人于 2005 年 Google Summer of Code（FreeBSD 项目之一）期间重写 toolkit，使其可工作于 CompactFlash、U 盘等多种环境；但 FreeBSD 6 引入的变更使 unionfs 损坏（彼时已有人积极修复）——unionfs 作为二级文件系统，以内存文件系统叠加在 FreeBSD 5 引入的只读压缩文件系统容器之上，为用户营造可写介质的错觉，其失效严重拖慢新版本开发；团队预计两周内给出候选版本，并计划在 FreeBSD 6.1 发布之后正式发布。（BSDTalk EP37，[338.34-473.26]，L1）
- XFCE 折中与默认应用集：从 CD 运行的速度天然低于硬盘，硬盘上称轻量的环境在光驱上即显沉重，XFCE 因此成为灵活性与观感之间的轻量折中；团队将继续采用 XFCE（6.0.2）并施以自制图标主题等定制，同时为不要桌面环境的用户提供更轻的平台；默认应用上，i386 版收录 OpenOffice.org 而 amd64 因无可用包改用 AbiWord，另配带 GTK2 界面补丁的 GMPlayer、XMMS，以及大量安全评估与渗透测试工具、文件系统与系统恢复工具——使 LiveCD 亦可用于抢救损坏系统。（BSDTalk EP37，[473.26-682.34]，L1）
