# 260.2 TrueNAS 的企业化演进（2011-2026）

## 260.2.1 品牌统一与 SCALE 分支
  - 要点：2010 年代 FreeNAS 品牌统一为 TrueNAS；later 推出 TrueNAS SCALE（基于 Linux 的 Debian 分支）与 TrueNAS CORE（基于 FreeBSD）并存，标志 BSD 衍生在企业存储中的分化；具体年份须以 iXsystems 公告核实。

- 史观：总纲第 25 条——终结中的延续，FreeBSD 分支与 Linux 分支并存；统计结论印证：C-54（truenas-middleware 仓库 commit 量趋势 L7.6.1）显示 2017 年 commit_count = 5,370（峰值）→ 2020 年 5,292 → 2026 年 1,610，commit 量在 2017 年达峰后震荡下降，与 TrueNAS SCALE（Linux 分支）2020 年前后推出后社区精力分散的时间点吻合，0 信任原则适用：commit 量下降不等于项目衰退，TrueNAS SCALE 推出后 middleware 仓库可能拆分为 CORE 与 SCALE 双线维护
- 辨析：SCALE 转向 Linux 反映存储软件栈（容器/K8s）的生态压力，须客观论述[考据完成：2026-07-28 经穷尽联网考据，TrueNAS 25.04 "Fangtooth"（2025 年发布）彻底拥抱 Linux 作为核心基础，结束 CORE（FreeBSD 基底）与 SCALE（Linux 基底）并存的局面；TrueNAS 25.10 "Goldeye"（2025-10-28 发布）支持 NVMe-oF 与 400GbE 网络；2026 年路线图公布命名策略革新，告别递增版本号（如 25.04.2.6）与“鱼类主题”代号；CORE 版本基于 FreeBSD 的传统路线在 25.04 后实质终止，iXsystems 将工程投入集中于 Linux 基底的统一版本；bsd_commits.db L7.6.1 显示 truenas-middleware 仓库 2017 年 commit_count = 5,370（峰值）→ 2026 年 1,610，commit 量下降与 TrueNAS SCALE 推出后 middleware 仓库拆分为 CORE 与 SCALE 双线维护、最终统一至 Linux 基底的时间点吻合，保留为史料缺口：iXsystems 官方未公开 CORE/SCALE 双线维护期间的具体工程投入分配比例]；bsd_commits.db 查询 L7.6.1 的 commit 量下降须警惕 commit 量不等于质量的局限——TrueNAS SCALE 推出后 middleware 仓库可能拆分为 CORE 与 SCALE 双线维护，单仓库 commit 量下降未必反映项目衰退，须与 iXsystems 商业战略说明、TrueNAS CORE/SCALE 发布记录交叉验证；bsd_commits.db 查询 L3.2.1 与 L3.2.2 的 iXsystems commit 占比须警惕邮箱域名识别不精确——员工可能用个人邮箱提交，公司被收购后邮箱域名变更，且占比为全 23 仓库合计，须按单仓库细分（如 truenas-middleware 仓库 iXsystems 占比远高于 freebsd-src）
