# 400.3.2 197.1 Link尾注之争

- **要点**：Randy Dunlap 指出 Link: 尾注以“#”分隔注释是多年惯例，Thorsten 引 process/5.Posting.rst 示例无“#”，主张一致；此一字之差成为 Link 文档补丁主要分歧。H. Peter Anvin 认为 Message-ID 缺 List-ID 几乎无用，维护者直接收补丁时看不到 List-ID 须手工补，反对以裸 Message-ID 取代 Link:。Laurent Pinchart 发现“b4 dig”本身以 Message-Id 为参数，质疑弃用 Link 标签的提案自相矛盾，公开追问该方案究竟要解决什么问题。Greg KH 概括 Linus 方案为“直接应用且未改动则不加 Link、改动才补加”，抱怨加重维护者负担且 git hook 需联网，要求“设好即忘”方案；称网络与 DRM 是最大提交来源。Konstantin Ryabitsev 提议以 Message-Id: 尾注取代 Link: 表补丁来源：patch-id 因 diff 算法与上下文行数差异而匹配不可靠；新法可消歧 Link、供 b4 与 patchwork 自动化、助 stable 追踪系列归属。Geert 指出 Link 指南已在 v6.18-rc1 提交 944df7a31452f75b 移除、改用不可点击的 Message-ID 标签；Rafael 建议以通用形式恢复，并把 patch.msgid.link 域名定为强制。
