## 217.1 【Linux社区】BSD 安全谱系与 Linux 能力模型（6 条）

- 【Linux社区】1997年6月 Darren Reed 在“[ADVISORY] 4.4BSD Securelevels (fwd)”中 转发 Thomas H. Ptacek 对 4.4BSD securelevel 的漏洞公告，“securelevel”是 BSD 内核提权约束机制的源头 `<!-- ROW_MINE: freebsd-hackers.messages.2589830 -->`
- 【Linux社区】1999年7月 Garance A Drosihn 在“Re: OpenBSD's strlcpy(3) and strlcat(3)”中 引述 Todd Miller 与 Theo de Raadt 的 USENIX 1999 论文，“strlcpy”是 OpenBSD 推出的字符串安全函数 `<!-- ROW_MINE: freebsd-hackers.messages.2620105 -->`
- 【Linux社区】2015年8月 David Drysdale 在“fs: add O_BENEATH flag to openat(2)”中 移植 FreeBSD 的 O_BENEATH 路径约束到 Linux openat，“O_BENEATH”是 Capsicum 谱系进入 Linux 系统调用层的一手证据 `<!-- ROW_MINE: linux-fsdevel.messages.443266 -->`
- 【Linux社区】2017年5月 Mickaël Salaün 在“new ...at() flag: AT_NO_JUMPS”线程中 记录 Jann Horn 揭示的 TOCTOU 漏洞，“AT_NO_JUMPS”是 Linux 对 FreeBSD AT_BENEATH 方案的主动分叉 `<!-- ROW_MINE: linux-fsdevel.messages.303021 -->`
- 【Linux社区】2022年10月 Mickaël Salaün 在“landlock: truncate(2) support”线程中 为 Günther Noack 的 truncate 补丁回信并推进讨论，“restrictable file system operations”是 Landlock 与 FreeBSD Capsicum 的能力模型类比证据 `<!-- ROW_MINE: linux-fsdevel.messages.675313 -->`
- 【Linux社区】2022年3月 Mathieu 在“Re: curtain: WIP sandboxing mechanism with pledge()/unveil() support”中 说明其为 FreeBSD 实现 pledge()/unveil()、可沙箱任意未改造程序，“curtain”是这一原型沙箱 `<!-- ROW_MINE: freebsd-hackers.messages.2535215 -->`

## 217.2 【Linux社区】BSD 安全技术反向输出与 Linux 采纳（7 条）

- 【Linux社区】2015年7月 Holger Levsen 在“[Reproducible-builds] reproducible builds of FreeBSD in a chroot on Linux”中讨论在 Linux chroot 内构建 FreeBSD 时 mktemp 语义差异，是 BSD 生态在 Linux 上构建的现实案例。 `<!-- ROW_MINE: freebsd-hackers.messages.1320440 -->`
- 【Linux社区】2016年 Martin Brandenburg 在“[PATCH 2/3] orangefs: strncpy -> strlcpy”中 将 orangefs 的路径名、符号链接目标与服务器名改用 strlcpy，“strlcpy”是 OpenBSD 引入的安全拷贝函数 `<!-- ROW_MINE: linux-fsdevel.messages.590217 -->`
- 【Linux社区】2016年4月 Mike Marshall 在“Re: [PATCH 2/3] orangefs: strncpy -> strlcpy”中 指出 strscpy 已于上年合入、strlcpy 转换不再必要，“strscpy”是 Linux 对 OpenBSD strlcpy 的替代实现 `<!-- ROW_MINE: linux-fsdevel.messages.626206 -->`
- 【Linux社区】2016年 Pavan Teja 在“Advantages of kdbus with enhanced capabilities feature”中提议把 Linux capabilities 作为 kdbus 连接的主令牌以放宽访问策略——与 Capsicum 的最小权限令牌哲学直接呼应，是 BSD 安全思想在 Linux 话题里的横向借用。 `<!-- ROW_MINE: freebsd-hackers.messages.1322707 -->`
- 【Linux社区】2017年7月 Linus Torvalds 在“Re: [GIT PULL] Please pull NFS client changes for Linux 4.13”中回复 Daniel Micay 关于参数语义的争议，“strlcpy 是彻底的垃圾”是 Linux 拒绝 BSD 安全字符串函数的标志性判词。 `<!-- ROW_MINE: linux-fsdevel.messages.594848 -->`
- 【Linux社区】2019年 Mickaël Salaün 在“[PATCH bpf-next v10 00/10] Landlock LSM: Toward unprivileged sandboxing”中 提交 Landlock 第十轮补丁、改用哈希表 inode 映射，“Capsicum”是 Landlock 对照的 FreeBSD 能力模型 `<!-- ROW_MINE: linux-fsdevel.messages.472924 -->`
- 【Linux社区】2023年 Azeem Shaikh 在“[PATCH] vfs: Replace all non-returning strlcpy with strscpy”中批量替换 VFS 层非返回值用法，“彻底移除 strlcpy”是 KSPP 将 BSD 安全函数逐出 Linux 内核的执行动作。 `<!-- ROW_MINE: linux-fsdevel.messages.307630 -->`
