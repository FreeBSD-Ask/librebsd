# 395.13.5 Linux社区2002年GeoffreyLee就connect到端口0的行为询问

- 【Linux社区】2002 年 Geoffrey Lee 就 connect() 到端口 0 的行为询问 LKML，明确陈述 FreeBSD 与 Solaris 均返回 EADDRNOTAVAIL 而 Linux 接受端口 0，请求列表判定此为 Linux 语义漏洞还是 BSD 系统错误，构成 Linux socket 语义向 BSD 收敛的边界问题一手证据 `<!-- ROW_MINE: lkml.messages.2083020 -->`
- 【Linux社区】2017 年 Michal Hocko 就 MADV_WIPEONFORK 补丁 v2 讨论回复，针对 Rik van Riel 明确将新语义类比 OpenBSD minherit syscall with MAP_INHERIT_ZERO 并注明 man.openbsd.org/minherit.2 链接，Hocko 质疑 madvise 语义“an advise and as such it can be ignored/not implemented and that shouldn't have any correctness effects”主张用 MAP_$FOO 标志而非 madvise；正文 BSD 词命中 2 处，是 Linux 内存管理新 API 由 OpenBSD minherit 直接触发的完整讨论链 <!-- ROW_MINE: lkml.messages.6412275 -->`
- 【Linux社区】2008 年 Matthew Wilcox 就 preadv/pwritev 系统调用 v2 补丁讨论回复 Gerd Hoffmann，后者指出参数顺序沿用 NetBSD“It is the argument ordering used by NetBSD, thats why I used that too”，Wilcox 随即反驳“NetBSD have approximately 0% market share. We shouldn't let them lock us into making a bad decision”并追问是否还有其他系统引入过这些 syscalls；正文 BSD 词命中 3 处（全部 NetBSD），是 Linux 内核新增系统调用直接继承 BSD API 设计引发争议的一手证据 <!-- ROW_MINE: lkml.messages.2245550 -->`
- 【Linux社区】2001 年 Chris Evans 就 Unix socket socketpair 对端关闭检测行为报告 Linux 与 FreeBSD 语义差异，明确称 Linux 2.2 上 close(socketpair[0]) 后 read(socketpair[1],...) 会无限阻塞而 FreeBSD 4.2 返回 ECONNRESET 才是预期行为，附完整 C 复现代码；正文 BSD 词命中 3 处，是 BSD socket 语义在 Unix socket 场景作为 Linux 参考基准的一手证据 `<!-- ROW_MINE: lkml.messages.1886011 -->`
- 【Linux社区】2017年2月Ben Greear在ath10k remove ath10k_vif_to_arvif()补丁串中反驳Kalle Valo风格批评：“Surely the code compiles to the same thing, so why add a patch that makes it more difficult for Adrian”，Adrian Chadd（adrian@freebsd.org）此前明确“Removing this method makes the diff to FreeBSD larger, as ”vif“ in FreeBSD is a different pointer. (Yes, I have ath10k on freebsd working and I'd like to find a way to reduce the diff moving forward.)”；Valo提议“I think backports project is doing it right... Maybe FreeBSD could do something similar?”，Linux上游ath10k风格重排与FreeBSD下游diff成本直接冲突。 `<!-- ROW_MINE: lkml.messages.6424401 -->`
