# 395.7.3 Linux社区Linux地址空间随机化RFC讨论中作者以OpenBSD的mmap

- 【Linux社区】Linux 地址空间随机化 RFC 讨论中，作者以 OpenBSD 的 mmap 随机化实现作为保守方案的直接对标，讨论碎片化与性能代价取舍。原文引语：“The OpenBSD randomized mmap is a fairly conservative implementation to avoid causing excessive fragmentation”。属 BSD 与 Linux 安全加固实现的明确对比记录。`<!-- ROW_MINE: linux-mm.messages.804020 -->`
- 【Linux社区】无磁盘节点交换内存问题讨论结尾，作者以成熟系统的可靠性作对照，点名 NetBSD 与 SunOS、Solaris 并列评价。原文引语：“neither SunOS, Solaris or NetBSD are infallible, they just never fail for any normal situation”。此处 NetBSD 作为内存管理稳健性的参照基准出现，属 BSD 衍生系统的间接技术评价。`<!-- ROW_MINE: linux-mm.messages.804280 -->`
- 【Linux社区】linuxsuperpages 项目讨论中，转发文本明确指出该项目是把 Rice University 的 Superpages FreeBSD 原型移植到 Linux 2.6 内核，覆盖 IA64、x86-64 与 x86-32。原文引语：“Superpages FreeBSD prototype that has been ported to the 2.6 Linux kernel”。这是 BSD 系统内存管理研究向 Linux 移植的直接谱系证据。`<!-- ROW_MINE: linux-mm.messages.804845 -->`
- 【Linux社区】Terry Lambert 在负载控制与进程换页讨论中系统批评 FreeBSD 的反抖动保护机制，认为大量管理式限制设置不合理，属 FreeBSD 内存管理实践被直接拿来与 Linux 对比的实质证据。原文：“I have a lot of problems with most of FreeBSD's anti-thrash”。`<!-- ROW_MINE: linux-mm.messages.760984 -->`

- 【Linux社区】bert hubert 在 cacheinfo 页缓存位图项目讨论中被追问 mincore() 系统调用，回复承认从未听说该接口，并称其自 BSD 4.4 起即已存在，是 mincore 谱系可追溯至 BSD 的文本证据。原文：“I'd never heard of mincore() although it's been around since BSD4.4”。`<!-- ROW_MINE: linux-mm.messages.761189 -->`

- 【Linux社区】在 bdev 回收与文件系统 shutdown 路径讨论中，Ted Ts'o 指出 Linux 当前实现在读操作上不关闭访问，因而不是真正的 BSD 系 revoke(2) 语义，论断经 Aleksa Sarai 与 Jan Kara 邮件转引留存，属跨平台接口事实的证伪式引用。原文：“operations that might result in _reads_ are not shutdown, so it's not a true revoke(2) functionality”。`<!-- ROW_MINE: linux-mm.messages.763298 -->`
