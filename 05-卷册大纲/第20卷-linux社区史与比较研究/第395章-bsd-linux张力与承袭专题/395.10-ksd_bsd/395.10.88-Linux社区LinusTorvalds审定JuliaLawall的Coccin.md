- 【Linux社区】Andrei Vagin：发起 netlink 引擎议题并全文引用 Lutomirski 的重构提案——议题动机是 **“netlink 接口证明了自己是做基于描述符的内核/用户空间通信的好办法……通信协议简单优雅，还允许在不破坏向后兼容的情况下扩展消息格式”**；其第一大问题是凭据——**“用户空间进程打开新文件描述符时，内核把打开者的凭据保存到 file 结构体的 f_cred 字段。之后对该 fd 的每次访问都以保存的凭据检查。这本质上允许进程以 root 身份打开文件描述符、然后丢弃 capabilities。用 netlink socket，没法实现这种访问方案”**；并引 taskstats 的坏例与 task_diag 的被阻塞；所引 Lutomirski 原文要点为 **“netlink 曾有、可能仍然有大量涉及检查 send() 调用者凭据的严重安全 bug。我几年前找到并修过几个。再重复一次：send() 无法安全地使用调用者凭据（我觉得我每隔几周就要说一次这个。都陈了）”**、其副作用四条（**诱使人们依赖 send() 调用者凭据 / 与 seccomp 结合很惨 / 与命名空间配合不好 / 让 task_diag 这种与网络无关的东西缠上网络**）；其提案核心是 **“int issue_kernel_command(int ns, int command, const struct iovec *iov, int iovcnt, int flags); ——ns 是真实的命名空间 fd 或 KERNEL_COMMAND_CURRENT_NETNS/CURRENT_PIDNS 等特值；返回一个可以 read/readv 读响应的 fd，它不是 socket；read() 的实现承诺不看调用者凭据；返回的 fd 无条件 cloexec——都 2016 年了，唉”** `<!-- ROW_MINE: ksummit-discuss.messages.347374 -->`
