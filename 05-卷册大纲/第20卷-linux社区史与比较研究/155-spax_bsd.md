## 155.1 BSD谱系

- 【Linux社区】Mark Cave-Ayland 用 QEMU 仿真 sunhme 卡时发现，内核 sunhme.h 中 GREG_STAT 与 GREG_IMASK 的偏移同 STP2002QFP 数据手册不一致。手册给出状态寄存器位于偏移 0x100、中断屏蔽寄存器位于 0x104，而 sunhme.h 分别写成 0x108 与 0x10c。他说明自己已核对 NetBSD 源码，那边与数据手册一致，因此 Linux 侧取值可疑。David Miller 回应说若这些偏移量确实错误，那么这个驱动居然还能工作属实惊人，因为这意味着从未真正编程过中断屏蔽寄存器。Miller 核对手中的手册后确认偏移量确实有误，并坦言不知这些数值当初从何而来，随即请 Cave-Ayland 提交修正补丁并表示会合入。该记录呈现了 BSD 系实现被当作第三方参照用于裁决 Linux sparc 驱动寄存器布局缺陷的完整过程。 `<!-- ROW_MINE: sparclinux.messages.9319717 -->`

- 【Linux社区】Mark Fortescue 在 sparc sun4c 支持是否应退役的讨论中提问该变更将进入 3.4 还是 3.5 版本，以便在远程构建主机网络恢复前取得最后一个仍支持 sun4c 的内核版本。邮件主体转引 Sam Ravnborg 对整条线程的总结：有人出于情感原因希望保留 sun4c 的内核支持，但 sun4c 已经过时，真正想在 sun4c 机器上运行系统的用户转向 BSD 系变体反而能获得更好性能，加上 sun4c 支持已破损多时，还有几项待合并改动会让 sun4c 的存在使实现更复杂而非更简单，因此决定放弃 sun4c 支持。Ravnborg 另附说明，核查中发现 sun4m 在单处理器模式下会错误调用 sun4c 的 NMI 中断陷阱。该邮件把 BSD 系系统的相对性能表现写入 Linux 内核平台退役的公开理由。 `<!-- ROW_MINE: sparclinux.messages.9320228 -->`

- 【Linux社区】Arnd Bergmann 就新增 TIOCGPTPEER ioctl 的补丁提出该接口必须同时纳入兼容层处理，并给出两种方案。方案一是比照 pty_unix98_ioctl 的其它 ioctl，继续向 fs/compat_ioctl.c 的清单追加条目，缺点是必须随时核对清单与驱动保持同步，否则容易遗漏。方案二是从 fs/compat_ioctl.c 移除全部专属于 pty_unix98_ioctl 与 pty_bsd_ioctl 的兼容处理，改在 master_pty_ops_bsd 与 ptm_unix98_ops 操作结构体内直接挂载 compat_ioctl 回调指针。Bergmann 推荐方案二，理由是它从结构上避免日后再次遗漏，代价是前期改造量更大，应作为独立准备补丁先行完成。他另指出这些 ioctl 在 32 位与 64 位用户空间之间本就兼容，无需特殊地址转换。 `<!-- ROW_MINE: sparclinux.messages.9321579 -->`
