# 401.3.4 28.3 【Linux社区】glibc 三则与回归定义（7 例）

**要点（判定表逐字）**：Carlos O'Donell 以 glibc 实务立三则——用户可见 bug 须有编号、能测则须带回归测试、不能测则扩框架（已用 kernel namespaces 造隔离配置），并谓时间表以年计；Carlos 答 Rostedt——内核无好用 bug 编号系统、多数开发者（含 Linus）讨厌 bugzilla；提议用 XMLRPC 接口，硬件专属测试标 UNSUPPORTED，并授以对熟人和生人宽严不同的督促法；Carlos 区分审阅与运行回归测试，谓提交者自测通过即可；glibc 借 namespaces 解决复杂网络与文件系统测试，并指为硬件之上代码造驱动 HAL／模拟器是另一难问题；Carlos 反问 Rostedt 何以断言不为单一特定硬件写测试，称用户态测各类硬件确有价值；Carlos 对 Greg 从小处着手之策回以 +1 赞同，并附 Cheers 落款；Rostedt 答 Carlos 不为单硬件写测试之虑——虑及 bit rot，数百针对极特定硬件的测试若无以数据表呈现之好基础设施则价值递减；Bottomley 厘清所答即 Rostedt 之是否属回归一问，界定回归为损及 k+1 可用性而 k 中本无之行径，并谓 SCSI 测试有无是别线程之题
