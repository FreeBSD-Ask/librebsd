## 207.1 【Linux社区】BSD 与 GPL：许可证冲突与双许可辩论（续）

- 【Linux社区】2023 年 2 月 Matt Hsiao（HPE）就 HPE iLO 驱动 GPL→MIT/GPL 双许可补丁回复 Greg KH 对 GPL-only 内核符号的质疑，明确动因「We want to maintain one hpilo driver between Linux and OpenBSD, and dual-licensing of hpilo driver's existing codebase and all the future bug fixes are the requirements for it. Therefore, we requested all other copyright owners of Linux hpilo driver to accept dual-licensing (MIT/GPL-2.0) for their respective contributions」，是 HPE 为容纳 OpenBSD 移植而在 Linux 侧推动 GPL 独占条款松绑的一手证据 `<!-- ROW_MINE: lkml.messages.3231614 -->`
- 【Linux社区】2002 年 10 月 Aaron Lehmann 在 BitKeeper NGROUPS 补丁讨论中就 BSD 广告条款发问：「Ahem. Since the copyright holder appears to be the Regents of the University of California, you have permission to remove this (ftp://ftp.cs.berkeley.edu/pub/4bsd/README.Impt.License.Change)」，并以 NetBSD INSTALL 文档为佐证「Not only is the advertising clause incompatible with the GPL, but imagine what a pain it would be to include this acknowledgement in any sort of advertisement. If you think I'm overreacting, check out this lovely cruft from NetBSD's INSTALL document」，是 4.4BSD-Lite 广告条款解除与 GPL 兼容在 Linux 补丁讨论中留下的一手证据 `<!-- ROW_MINE: lkml.messages.1910481 -->`
- 【Linux社区】2023 年 10 月 Mellanox 无线与存储驱动负责人 Jason Gunthorpe 在 mlx5ctl misc 驱动补丁串中主张 400 余文件的 Mellanox 驱动栈维持 GPL/BSD 双许可，理由直陈「I could easily see the work Saeed has done here finding its way into FreeBSD. We significantly support FreeBSD employing maintainers and develop a sophisticated Mellanox driver over there. This would not be possible without the Linux driver being dual licensed」，Greg KH 坚决反对：「Yes it would, you can take the work that you all do and license it under the BSD license and put it into FreeBSD just fine」并主张新文件保持单一许可；Mellanox 反驳称十年十万提交的现状使双许可是必要策略，是 BSD/GPL 双许可在主流硬件厂商驱动栈中的当代正面冲突。 `<!-- ROW_MINE: lkml.messages.3646316 -->`
- 【Linux社区】2008 年 WolfMountainGroup 在 lkml 发出 forenfs「Forensic File System」补丁公告，明确说明补丁提交动机源于 GPL 与 BSD 生态分裂：「First commercial shipment will occur on FreeBSD due to commercial use and distribution restrictions imposed by the GPL」，补丁本体为 FreeBSD 派生代码通过 GPL 抽象层挂入 Linux 内核，测试数据以 FreeBSD 为基准参照（Linux raw I/O 快 8 个百分点，FreeBSD VFS 快 5 个百分点），构成 GPL 强制条款阻塞商业 BSD 派生代码反向移植至 Linux 的一手叙事。 `<!-- ROW_MINE: lkml.messages.2416000 -->`
- 【Linux社区】2007 年 9 月 Adrian Bunk（SUSE）在 lkml 回复转发自 OpenBSD misc@ 的 Reyk Floeter 邮件 That whole Linux stealing our code thing，Floeter 坚持「I will not release or agree to release my code under either the GPL or any kind of a dual-license」且「The ISC-style license must remain including the copyright notice and even the warranty term」，Bunk 澄清「The patch that mistakenly changed BSD-only code to GPL has never ever been in the Linux tree」并引 Theo de Raadt 于 lkml 转发邮件指控选单一许可即 break the law，形成 2007 Sam Leffler 双许可撤除风波的 BSD 阵营直接回应链，与 205 章 205.2 Leffler 自陈构成同 thread 后续。 `<!-- ROW_MINE: lkml.messages.2206469 -->`
- 【Linux社区】2007年9月Jonathan Gray在lkml转发OpenBSD开发者Reyk Floeter的声明，直面2007年8月末ath5k/GPL-BSD许可证冲突事件。Reyk原话「I will not release or agree to release my code under either the GPL or any kind of a dual-license」并保留ISC版权通知与免责条款；同一封邮件转引Theo de Raadt 8月31日公开声明：「It is illegal to modify a license unless you are the owner/author, because it is a legal document. If there are multiple owners/authors, they must all agree」，直指Alan Cox在http://lkml.org/lkml/2007/8/28/157「advising people to break the law」，将Eben Moglen在幕后斡旋与Jiri Slaby/Luis Rodriguez提议修改双许可文件的法律争议公开化。 `<!-- ROW_MINE: lkml.messages.3 -->`
- 【Linux社区】2004年9月DRM/fbdev合并讨论中Jon Smirl直面GPL/BSD许可证壁垒，原话「We're going to have to work out a GPL/BSD solution for the fbdev merge. There are 80,000 lines of code in the fbdev directory. It is impractical to rewrite them. It's probably also impractical to relicense the fbdev code BSD since we would have to locate all of the coders」，提出三目录方案：drm/shared与drm/bsd用BSD许可，drm/linux用GPL；Dave Airlie追问X许可与专有驱动边界，Smirl自陈仅知三位FreeBSD DRM用户「I don't think DRM CVS will even compile currently on FreeBSD. I think I broke it a week ago and no one has said anything」，是BSD代码向Linux DRM迁移早期的一次系统性许可与工程决策辩论。 `<!-- ROW_MINE: lkml.messages.4 -->`
- 【Linux社区】2007年9月5日ath5k/GPL-BSD许可证冲突当事作者Reyk Floeter以「request for information about the ath5k licensing」为主题向lkml公开发函，自陈OpenHAL作者身份：「I'm the author of the free hardware driver layer for wireless Atheros devices in OpenBSD, also known as OpenHAL」，指控Linux ath5k分支以「a prepended GPL and an invalid copyright on top of it」将其排除合作；他列出与madwifi移植者的既往协作并附OpenBSD ISC许可证原文，明确警告「I also strongly disagree with the concept of adding a new copyright and/or a GPL license on top of it - it is still a derived work and a few stylistic changes, some code shuffling, and some bug fixes don't allow to change the copyright」，与row 3 Floeter转发、row 18 Espie声援构成同thread完整链。 `<!-- ROW_MINE: lkml.messages.5 -->`
- 【Linux社区】2001年8月FreeBSD/QLogic光纤通道工程师Matthew Jacob在QLogic/FC固件讨论中披露BSD版权标签的政治缘起：「The BSD copyright in the f/w I have from QLogic is there only because Theo Deraadt threatened to pull QLogic from the 2.7 OpenBSD release. I'd been pleading with them for over a year to do something」，并坦言当年未采用无广告条款的BSD许可是遗憾「I should have done a BSD license w/o the advert clause, but, oh, well」；他向Alan Cox请求推动QLogic将2100/2200/2300 FC固件以GPL发布以便Linux使用，是BSD厂商关系与固件授权谈判的直接一手叙述。 `<!-- ROW_MINE: lkml.messages.6 -->`
- 【Linux社区】2024年11月Hyperbola项目成员sk-alexis向MAINTAINERS提交HyperBK介绍信，宣布HyperbolaBSD项目下的HyperBK为「a copyleft hard-fork of OpenBSD-kernel, v7.0」；说明团队自2017年起已将Xenocara、LibreSSL等从OpenBSD移植到Arch/Parabola系统分发，正在执行源代码许可证完整审计并将BSD系代码改写为copyleft强授权，其技术栈采用FreeBSD make(1)与HyperRC、HyperBLibC、hyperman等自研组件。这是BSD家族内部首次系统性向Linux社区公开展示BSD内核硬分叉并转为copyleft许可的行动，兼具BSD谱系断裂与GPL兼容方向双重史学意义。 `<!-- ROW_MINE: lkml.messages.17 -->`

## 207.2 【Linux社区】BSD 人物在 LKML 的出场（续）

- 【Linux社区】2024 年 1 月 Jeff Xu（Chromium）在 mseal() PATCH v7 串中回应 Theo de Raadt 关于 PROT_SEAL 的 OpenBSD 立场，自陈「I'm sorry, I have never looked at one line of openBSD code, prototype or not, nor did I install openBSD before」，并解释「For PROT_SEAL in mmap(), I see it as a good and reasonable suggestion raised during the RFC process, and incorporate it into the patch set」，是 OpenBSD 创始人 Theo 在 lkml 内核设计讨论中直接发声、Linux 开发者据其意见修订补丁的一手证据 `<!-- ROW_MINE: lkml.messages.3827779 -->`
- 【Linux社区】2023 年 10 月 OpenBSD 创始人 Theo de Raadt 在 mseal() RFC PATCH v1 讨论中直接介入：「mseal() is a clone of mimmutable(2), but with an extremely over-complicated API based upon dubious arguments. I designed mimmutable(2) [1] in OpenBSD, it took about a year to get all the components working correctly. There were many intermediate API during development, but in the end the API is simply: int mimmutable(void *addr, size_t len)」「Very simple semantics. The only case where the immutable marker is ignored is during address space teardown as a result of process termination」，Jeff Xu 随即就 mimmutable 是否覆盖 mlock/madvice 场景发问，是 OpenBSD 作者以 API 设计权威身份反向审视 Linux mseal 语义的一手证据 `<!-- ROW_MINE: lkml.messages.3584118 -->`
- 【Linux社区】2003 年 1 月 NetBSD 核心开发者 Bill Studenmund（wrstuden@netbsd.org）在 lkml 就「Technical Differences of *BSD and Linux」新手提问做系统性回应，以 BSD 家族资深视角直陈历史与格局：「*BSD kernels were derived from 4.4-Lite, and Linux was derived, I believe, from Minix」，并给出三族分工口诀——「FreeBSD wants to make kick-ass servers, NetBSD wants to support lots and lots of hardware, and OpenBSD is concerned all about security」，进一步说明「There is a lot of polination between BSDs」与「der Mouse pointed out the GPL issue, which is one where I think the BSD and Linux folks will just agree to disagree」，是 BSD 家族工程师对 BSD/Linux 谱系分裂的第一方陈述。 `<!-- ROW_MINE: lkml.messages.2016458 -->`
