### FreeBSD 创始团队的当事人自述与演讲（1993-1994 时期）

#### 采访 1：Jordan K. Hubbard

**字段 1 采访元数据**

- 受访者：Jordan K. Hubbard，FreeBSD 三位 patchkit 协调员之一，1993 年 FreeBSD 项目共同创始人，后期任 FreeBSD Core Team 成员与 Apple Inc. 工程技术总监
- 采访者：BSD Now 播客主持人 Allan Jude（艾伦·裘德） 与 Benno Rice（本诺·赖斯）
- 采访时间：2014 年左右 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］——具体期数与日期须三次复查核实

- 原始来源：BSD Now Episode archive. **<https://www.bsdnow.tv/>**（具体期数待三次复查核实［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）
- 存档信息：原始 URL 经联网抓取可访问（BSD Now 网站），未失效；互联网档案馆存档链接待补充

**字段 2 采访摘要**

Hubbard 在 BSD Now 播客访谈中陈述 FreeBSD 起源故事的核心情节：1993 年初他与 Nate Williams（内特·威廉姆斯）、Rodney Grimes 三人作为 386BSD patchkit 最后的协调员，因补丁积压严重与 Bill Jolitz 沟通不畅，决定 fork 386BSD 0.1 + patchkit 为新项目。Hubbard 陈述他联系 Walnut Creek CDROM 改善 FreeBSD 分发渠道，David Greenman（大卫·格林曼） 创造“FreeBSD”项目名称。Hubbard 对“386BSD 停滞迫使 fork”的归因与 FreeBSD Handbook 1.3.1 节官方叙事一致，构成 FreeBSD 阵营对起源事件的标准陈述。

**字段 3 考据脚注**

本则采访的 BSD Now 播客原始 URL 经联网抓取可访问。Hubbard 作为 FreeBSD 三位 patchkit 协调员之一，其身份经 FreeBSD Handbook 1.3.1 节（**<https://docs.freebsd.org/en/books/handbook/introduction/#history>**）明确记载"the Unofficial 386BSDPatchkit's last 3 coordinators: Nate Williams, Rod Grimes and Jordan Hubbard"交叉确认。Hubbard 关于 David Greenman 命名 FreeBSD、Hubbard 联系 Walnut Creek CDROM、三人共同决定继续项目的陈述与 FreeBSD Handbook 1.3.1 节官方叙事一致，构成 FreeBSD 阵营内部立场的一致性印证。须作自利偏差审查：Hubbard 作为 fork 决策当事人，有动机将 fork 描述为“被迫自救”而非“主动选择”，其叙事与 Jolitz 夫妇“完全虚构”反控形成对立，史家引用时须回到 bsd_commits.duckdb commit 历史、386BSD 0.1 源码树、邮件列表原始帖等一手史料，不得仅凭当事人自述采信。BSD Now 播客作为 BSD 社区独立媒体（与 FreeBSD Project 官方文档为不同载体），与 FreeBSD Handbook 构成“不同作者、不同载体、不同社区”中至少两项差异。完整考据过程见 20260724_jordan-hubbard-bsdnow-freebsd-birth.md。

**字段 4 与本章节内容的关联**

- 为子节 26.1（1993 年初 FreeBSD 创建——Williams/Grimes/Hubbard 三位 patchkit 协调人发起，Greenman 命名）提供 FreeBSD 阵营当事人对创建决策的直接陈述
- 为子节 26.1.2（创始团队的构成与分工）提供三人分工的当事人记忆（Hubbard 联系 Walnut Creek CDROM、Greenman 命名、三人共同决定继续项目）
- 为子节 26.2（名称之争——从“386BSD 0.5/Interim”到“FreeBSD”的命名过程）提供 David Greenman 命名 FreeBSD 的当事人引证

**字段 5 史观映射**

- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离；而各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”，Hubbard 与 Williams、Grimes 三人 fork 386BSD 0.1 + patchkit 为新项目，构成 BSD 在 PC 平台的“分离”环节；但 4.1 节同时指出“分合循环，永无止息”——三人 fork 后仍持续吸纳 386BSD 与 4.4BSD-Lite 的代码，构成“聚合”的另一面。fork 不是分离的终点，而是分离聚合循环中的一刻。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.2 节“将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，FreeBSD 的诞生不是“BSD 必然分裂”的展开，而是 Jolitz 停滞、补丁积压、USL 诉讼未决、Walnut Creek CDROM 可用、Hubbard 个人决策等偶然条件交汇下的具体决策；若三人选择继续与 Jolitz 协商而非 fork，FreeBSD 可能不会在 1993 年 6 月诞生。Hubbard 的“被迫自救”叙事本身须经 0 信任审查——fork 既是被动响应亦是主动选择。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”，Hubbard 的 FreeBSD 阵营自述与 Jolitz 夫妇的 386BSD 阵营“完全虚构”反控在本体论上地位平等。14.7 节的“去中心化悖论”提示：三人 fork 形成 FreeBSD Core Team 这一新中心，与 Jolitz 夫妇的“一人一图”中心形成对称——两个中心都声称代表 BSD 在 PC 平台的正统，史家引用时须保持双方发声空间的对称。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”，Hubbard 作为 386BSD patchkit 最后的协调员之一，其 fork 决策基于补丁积压、与 Jolitz 沟通不畅等具身工程经验，而非抽象的“BSD 应当如何”理论规划；但 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”提示：Hubbard 联系 Walnut Creek CDROM 改善分发渠道、Greenman 命名“FreeBSD”等“外围形式主义”工作，与代码本身具有本体平等——经验优先不限于代码经验。
- 总纲 10“动手者创造历史”——14.3 节“中心化的社区本就是大团体里的小团体”为审视三人 fork 决策提供了新的角度：Hubbard、Grimes、Williams 三人作为 patchkit 协调员本即是 386BSD 大团体中的小团体，fork 是这一小团体从潜在走向显在的临界点。14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”在此获得具体意涵：三人 fork 后声称的“开放协作”不是对 386BSD 单一 commit 权限结构的否定，而是新中心的建立——FreeBSD Core Team 的形成即是这一新中心的制度化。但 14.2 节“问题始终在于是否有人去做”不因此失效：三人接管补丁包维护、联系 Walnut Creek CDROM、fork 386BSD 0.1 + patchkit 的具体行动是“动手”，fork 决策本身亦是“动手”——只是这一“动手”的后果是新的形式主义化封闭结构的诞生，而非封闭结构本身的消除。
- 总纲 19“解释学循环与权力-知识共谋”——据第 19 章 19.2 节“不同文化背景、不同技术背景、不同时代背景的读者，对同一史事的前理解截然不同”，Hubbard 在 BSD Now 播客中陈述的“386BSD 补丁积压迫使 fork”叙事，与 Jolitz 夫妇“工程美学被忽视”叙事构成解释学循环中的双方前理解冲突。Handbook 1.3.1 节将 Hubbard 的当事人陈述固化为项目官方叙事，本身即 19.3 节所述“什么被记录、什么被遗忘”的权力行使——FreeBSD 阵营通过 Handbook 掌握了 fork 事件的“记录权”。

#### 采访 2：Rodney W. Grimes（罗德尼·W·格赖姆斯）

**字段 1 采访元数据**

- 受访者：Rodney W. Grimes，FreeBSD 三位 patchkit 协调员之一，1993 年 FreeBSD 项目共同创始人，freebsd.duckdb 显示其在 freebsd-src 仓库 1993 年累计 340 commits，时间跨度 1993-06-12 至 1993-12-24
- 采访者：邮件列表公开 commit message（非外部采访者）
- 采访时间：1993-06-12（首条 commit“Initial import, 0.1 + pk 0.2.4-B1”时间戳）
- 采访形式：邮件列表存档与 commit message 当事人公开陈述
- 原始来源：freebsd.duckdb 数据库（freebsd-src 仓库 commit_hash `9002c02abc587664acb357c6879d8ca08664dd0b`，author Rodney W. Grimes `<rgrimes@FreeBSD.org>`，author_date 1993-06-12T14:49:13Z）；FreeBSD 仓库镜像 **<https://git.freebsd.org/src.git>**
- 存档信息：原始 commit 经 freebsd.duckdb 数据库直接查询确认，commit_hash 与 freebsd-src 仓库镜像一致；互联网档案馆存档链接不适用（git commit 本身为不可篡改档案）

**字段 2 采访摘要**

Grimes 在 1993-06-12T14:49:13Z 提交 freebsd-src 仓库首条 commit“Initial import, 0.1 + pk 0.2.4-B1”（commit_hash `9002c02abc587664acb357c6879d8ca08664dd0b`），将 386BSD 0.1 + patchkit 0.2.4-B1 源码导入新仓库，标志 FreeBSD 项目代码层的正式诞生。8 天后 1993-06-20T13:41:45Z 同一作者提交“Initial import of 386BSD 0.1 othersrc/etc”（commit_hash `1bf9d5d9518e789360439c1db3d568b113caf60d`），证实 FreeBSD 代码库确实包含 386BSD 0.1 源码导入。1993-08-09 Grimes 提交 commit `f9b4e354333706f10123fa5b81e9266d96c199e4`，commit message 明确写"This keeps us from violating Berkeley‘s and Bill Jolitz’s copyrights"，在 FreeBSD 1.0 发布前三个月主动将 CONTRIB.386BSD 与 COPYRIGHT 文件安装至发行版根目录，构成对 Jolitz 版权的直接承认。这些 commit message 是 FreeBSD 阵营起源事件最直接的代码层证据。

**字段 3 考据脚注**

本则“采访”为 commit message 形式的当事人公开陈述，是 FreeBSD 阵营起源事件最权威的代码层一手史料。commit_hash `9002c02abc587664acb357c6879d8ca08664dd0b`、`1bf9d5d9518e789360439c1db3d568b113caf60d`、`f9b4e354333706f10123fa5b81e9266d96c199e4` 均经 freebsd.duckdb 数据库直接查询确认，并与 freebsd-src 仓库镜像（**<https://git.freebsd.org/src.git>**）一致。Grimes 作为 FreeBSD 三位 patchkit 协调员之一的身份经 FreeBSD Handbook 1.3.1 节明确记载交叉确认。须作 0 信任原则·committer_date 可能被重写审查：commit 的 author_date 与 committer_date 字段在 CVS-to-Git 迁移过程中可能被 svn2git 工具重写，但 freebsd.duckdb 显示 rgrimes 在 1993 年累计 340 commits，时间跨度 1993-06-12 至 1993-12-24，与首条 commit 的 1993-06-12 时点一致，时序连续性印证 commit 时间未被重写。commit `f9b4e354333706f10123fa5b81e9266d96c199e4` 的版权承认表述须与 COPYRIGHT.386BSD 文件纳入、Handbook 官方叙事、Contributors 专节三类独立证据交叉验证，不得仅凭 commit message 采信 FreeBSD 阵营对版权承认的单方陈述。完整考据过程见 20260724_rodney-grimes-commits-freebsd-birth.md。

- 为子节 26.1（1993 年初 FreeBSD 创建——Williams/Grimes/Hubbard 三位 patchkit 协调人发起，Greenman 命名）提供 FreeBSD 仓库首条 commit 的代码层时间戳证据（1993-06-12T14:49:13Z）

**字段 5 史观映射**

- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离；而各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”，Grimes 于 1993-06-12T14:49:13Z 提交“Initial import, 0.1 + pk 0.2.4-B1”（commit_hash `9002c02abc587664acb357c6879d8ca08664dd0b`），是 FreeBSD 从 386BSD 0.1 + patchkit 分离的代码层时间戳证据；但同一作者 8 天后又提交“Initial import of 386BSD 0.1 othersrc/etc”，fork 后仍持续吸纳 386BSD 源码，构成“聚合”的另一面——4.1 节“分合循环，永无止息”在此表现为同一作者名下的连续导入。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.2 节“将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，FreeBSD 仓库首条 commit 落在 1993-06-12 是偶然；若三位 patchkit 协调人未在此时决定导入，或导入对象不是 386BSD 0.1 + patchkit 0.2.4-B1，FreeBSD 代码层的诞生时点与工程基础将不同。史家引用该时间戳时不可反向将其读作“FreeBSD 必然于 1993 年诞生”的证据。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”，Grimes 的 commit 记录与 Jolitz 夫妇的 386BSD 阵营陈述在本体论上地位平等：前者是代码层档案，后者是当事人自述，二者不可互相替代；14.7 节的“去中心化悖论”提示：以 commit 权限为载体的新中心（FreeBSD 仓库）在 fork 中形成，而其正当性正取自“接管积压补丁”的开放姿态。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”与 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”，Grimes 在 1993 年累计 340 commits（时间跨度 1993-06-12 至 1993-12-24，本块字段 1 已记）是 FreeBSD 创建期最直接的工程经验记录，优于任何事后回忆；但 14.5 节提示 commit message、COPYRIGHT 文件的安装等“外围形式主义”与源码本体具有本体平等——本块字段 2 所记 1993-08-09 主动承认版权归属的那条 commit message，正是外围形式主义进入代码层档案的实例。
- 总纲 10“动手者创造历史”——14.3 节“中心化的社区本就是大团体里的小团体”为审视 Grimes 的位置提供了角度：三位 patchkit 协调员本即是 386BSD 大团体中的小团体，首条 commit 是这一小团体把“接管补丁包”的意向落成仓库事实的一刻。14.2 节“问题始终在于是否有人去做”在此具体化为：导入 386BSD 0.1 + patchkit 0.2.4-B1 这一动作本身罕有人去做，Grimes 的提交是其填补；但该“动手”同时诞生了新的形式主义化结构，而非消除既有结构。
- 总纲 19“解释学循环与权力-知识共谋”——据第 19 章 19.2 节“不同文化背景、不同技术背景、不同时代背景的读者，对同一史事的前理解截然不同”，Grimes 的 commit message 与 Jolitz 夫妇“工程美学被忽视”的陈述构成解释学循环中的双方前理解冲突：一方以“补丁积压须有人接管”为前理解，一方以“维护节奏被外力打断”为前理解；FreeBSD 阵营通过 commit message 与 Handbook 记载掌握了 fork 事件的记录权，史家引用时须呈现双方前理解，不得将代码层时间戳误读为对 fork 正当性的裁定。
