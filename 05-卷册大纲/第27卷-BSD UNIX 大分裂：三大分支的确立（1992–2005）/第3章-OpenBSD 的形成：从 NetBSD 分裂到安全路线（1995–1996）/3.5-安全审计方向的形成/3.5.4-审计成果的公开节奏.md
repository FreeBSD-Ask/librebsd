# 3.5.4 审计成果的公开节奏

<!-- MAIL_INSIGHT: 9609042100.AA12246@theos.com -->
**观点**：1996 年 9 月 4 日，Theo de Raadt 本人介入上述争论，回应“想了解安全修复去查 CVS 日志”的建议：承认“日志现在已有 4MB，安全修复的内容淹没在其他改动之间”——既接受 CVS 日志作为公开路径，又坦承其可读性问题。
**邮件来源**：Theo de Raadt，freebsd-chat，1996 年，Message-ID: `9609042100.AA12246@theos.com`
**史学意义**：当事人对“安全修复可见性”争议的亲自回应，同时呈现了 72.1.4 批评（信息不透明）与 72.1.5 反批评（有公开路径）两方论点各自的原始依据，是独裁模式争议的最早期一手对话记录。

**要点**：

- Theo de Raadt 亲述 OpenBSD 起源：386BSD 停滞、NetBSD 成立后他作为首批四人之一加入；随后因与 NetBSD 的冲突失去仓库访问权，最终另立仓库，OpenBSD 由此诞生。（BSD Now EP6，[508.09-609.45]，L1）
- CSRG 遭入侵事件使其重新转向安全，此后 OpenBSD 建立全代码审计传统；审计后又认识到审计还不够，继而引入 ProPolice 等防护机制。（BSD Now EP6，[594.81-721.24]，L1）
- OpenBSD 几乎不设正式政策，开发者各自在领域内推进，de Raadt 自称最后的协调者；项目不维护分支，开发者与用户同处一条前进的代码路径，并鼓励用户运行快照。（BSD Now EP6，[845.54-908.82]，L1）
- de Raadt 主题演讲论述 64 位 time_t 的必要性：32 位与 16 位嵌入式系统仍将长期存在，SCADA 等关键基础设施升级周期缓慢，须尽早跨越 Y2038 时间曲线。（BSD Now EP6，[1131.78-1233.30]，L1）

- 问答环节陈述两项制度细节：其一，OpenBSD 对典型 Unix 安全问题五至七年的修复已足够彻底，旧版本几乎不存在需回推安全补丁的理由，其家中无线路由器运行 OpenBSD 3.8 即无需升级，以此消解多分支维护的合法性；其二，共享库版本号采取激进的 major/minor 策略——API 增加即升 minor、API 变更或消失即升 major，包树亦弃用 vendor 版本号而自记版本，且明确拒绝 ELF symbol versioning，认为其不可用。（YouTube EPi7pkyDUX5uM，[1626.36-1785.08]，L1） [订正：新转写核对不符——youtube_subs_20261001 对 EPieLN_5j7G1g 的转写为另一主题（FreeBSD core team 报告：团队月报、透明度、开发者问卷、行为准则与开发者摩擦等，全长约 16 分钟），与本条目所述 Theo de Raadt OpenBSD 发布工程主题完全不符，且原时间戳多超出该转写实际范围（约 36-965 秒）；本条内容暂保留待重新归属，未经人工核裁不得引用] [订正：重归属——本条内容经逐段核对与 EPi7pkyDUX5uM（AsiaBSDCon 2009: The OpenBSD Release Process）转写逐字相符，原 EPieLN_5j7G1g 引用系错配（该期转写实为 FreeBSD core team 报告），来源改挂 EPi7pkyDUX5uM，内容复核 2026-10-03] [订正：依 senseaudio 新转写（任务书3 tb2 战役）核验，时间戳未变内容核符；模型 senseaudio-asr-stream-1.5-260910]

- 〔AsiaBSDCon 2019〕FreeBSD core 团队成员以项目现状报告对照 de-Raadt 模式：选举产生的 core 以五大工作方向汇报治理现状——透明度（工作组成果公开、GitHub meetings repository 公开会议纪要、与 release engineering/security officer 等 "hats" 沟通）、行为准则更新滞后（Jeff Robertson 主导调查、参考 GoLang/LLVM 模板、因生活变故停滞）、打击项目内毒性、开发者调查（EuroBSDCon 2018 起草、Sean 整理约 200 小时发布）、新支持模型宣布延迟（上游项目提速与行业期望变化）——与 OpenBSD 无正式政策、de Raadt 自称最后协调者的模式形成对照：FreeBSD 走选举 core＋工作组＋流程透明路线，仍自陈“起步即停滞”需扩展工作组（如引入 bug bashing 活跃者）并降低开发者摩擦。（YouTube EPieLN_5j7G1g，[32.0-735.1]，L1）
