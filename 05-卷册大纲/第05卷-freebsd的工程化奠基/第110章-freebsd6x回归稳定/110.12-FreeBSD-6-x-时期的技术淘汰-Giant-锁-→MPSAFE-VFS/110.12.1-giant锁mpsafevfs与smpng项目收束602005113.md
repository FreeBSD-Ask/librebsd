# 110.12.1 Giant 锁 → MPSAFE VFS 与 SMPng 项目收束（6.0，2005.11.3）

  **要点**：FreeBSD 5.x 时期启动 SMPng 项目，旨在分解 Giant lock（单一内核大锁）为细粒度锁；FreeBSD 6.0-RELEASE（2005.11.3，release/6.0.0 tagger_date = 2005-11-03T00:35:26Z，tagger = cvs2svn）引入 MPSAFE VFS（Multi-Processor Safe VFS）——VFS 层大部分代码路径不再需要 Giant 锁；6.0 同时引入大量 MPSAFE 网络栈路径（IPv4、IPv6、UNIX domain sockets、NetGraph）；SMPng 项目在 6.0 标记为 “完成”——大部分内核已无 Giant 锁依赖，但部分设备驱动与 NFS 组件仍保留 Giant；6.0-6.4 期间继续清理 Giant 残余，NFS、AGP、**scsi(4)** 部分代码在 6.x 时期移除 Giant 依赖；SMPng 完成使 FreeBSD 在 4-32 CPU 服务器上获得线性扩展性，与 5.x 时期相比性能显著提升
  
**史料**：FreeBSD 6.0-RELEASE Release Notes；Robert Watson “FreeBSD SMPng Project SMP Network Stack”（2005 演讲）；freebsd-smp 邮件列表 2005-2008 年讨论；CVS commit log 中 MPSAFE 相关 commit；freebsd.duckdb freebsd-src 仓库 tags 表 release/6.0.0 的 tagger_date = 2005-11-03T00:35:26Z（target_commit_hash = 3d215489fe03c6c5cecc3b5ed9ea39118e6ce379） ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：Giant 锁分解付出工程复杂度代价（细粒度锁设计与验证困难），但获得多核扩展性；总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：锁粒度形式的改变：锁粒度作为 “形式” 改变 “内容”（内核并发执行能力）
