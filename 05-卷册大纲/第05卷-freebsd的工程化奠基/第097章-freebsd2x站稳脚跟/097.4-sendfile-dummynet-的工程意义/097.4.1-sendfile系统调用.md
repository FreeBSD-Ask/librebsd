# 097.4.1 sendfile 系统调用

  **要点**：**sendfile(2)** 由 David Greenman（大卫·格林曼） 于 1998 年 11 月 5 日引入 FreeBSD 3.0-CURRENT（commit dd0b2081f452c0339a44a9647866cf9990111086），允许内核直接在文件描述符与套接字之间零拷贝传输数据，避免了传统 read/write 路径的用户态-内核态数据拷贝，显著提升了静态文件服务的吞吐量；旧叙事称 “1997 年引入 FreeBSD 2.2” 有误，已依据 commit log 修正
  
**史料**：SVN 仓库 sys/kern/sys_socket.c 与 sys/sys/syscall.h 中 sendfile commit 日志、Greenman 在 freebsd-hackers 1997-1998 年的提案邮件、Apache 与 thttpd 对 sendfile 的适配记录；freebsd.duckdb `commits` 表 sendfile 首次 commit：author = David Greenman <dg@FreeBSD.org>，author_date = 1998-11-05T14:28:26Z，committer_date = 1998-11-05T14:28:26Z，commit_hash = dd0b2081f452c0339a44a9647866cf9990111086，message = “Implemented zero-copy TCP/IP extensions via sendfile(2) - send a file to a stream socket”（2026-09-14 订正：半角直引号改弯引号）；次日（1998-11-06）commit bd81f199b5072e8638e93a18b2ebf099e2db3bea 添加非阻塞 socket 支持 ［A］
  
**史观**：工程需求倒逼内核 API 演进（专题语，不设总纲条号；2026-09-14 订正：原伪挂“总纲第 19 条——信息技术”按权威表去号），sendfile 是 Web 服务器性能需求倒逼操作系统内核 API 创新的典型案例
  
**辨析**：经 freebsd.duckdb `commits` 表验证，sendfile 首次 commit 在 1998-11-05，对应 FreeBSD 3.0-CURRENT 时期（3.0-RELEASE 于 1998-10-16 发布，sendfile 在 3.0-RELEASE 后合入 -CURRENT 分支，将进入 3.1-RELEASE 与 2.2.8-STABLE 后续分支），旧叙事 “1997 年引入 FreeBSD 2.2” 误植，应修正为 1998 年 3.x 时期；sendfile 的发明权存在争议，Linux 在 2.2(1999) 也引入了 sendfile，FreeBSD 3.x 时期（1998.11）早于 Linux 2.2(1999.1)，谁先提出概念需查邮件列表
  
**文献**：Greenman “sendfile: Zero-Copy File Transmission”(BSDCon 1998)；Stevens《UNIX Network Programming》(1998)；Apache 性能调优文档；David Greenman.
