# 097.8.2 2014 年 6 月 3 日 GNATS→Bugzilla 迁移中的 PR 历史断裂

  **要点**：FreeBSD 项目于 2014 年 6 月 3 日开始从 GNATS 系统迁移至 Bugzilla，由 David Chisnall（戴维·奇斯纳尔）（<theraven@FreeBSD.org>）代表 Core 团队发布公告；GNATS 数据库被冻结为迁移起点，`send-pr` 作为兼容接口继续工作但需要手动步骤导入新提交的 bug；工作流发生显著变化（Eitan Adler 绘制的状态转移图 people.freebsd.org/~eadler/bugrelocation/workflow.html），原有的 PR 编号体系与 Bugzilla bug 编号体系不完全一一对应；2014 年 9 月 30 日 GNATS URL 被重定向至 Bugzilla，2016 年 3 月 19 日 commit r411397/r411398 才从 commit 模板中移除 GNATS 引用——历史包袱持续近两年；部分 1994-2014 年间的 PR 在迁移中因分类字段不匹配或元数据缺失而无法被精确对应，存在 PR 历史断裂
  
**史料**：freebsd-announce 邮件列表 2014.6.3 David Chisnall 公告；freebsd-ports 邮件列表 2014.6.3 讨论；Bug 194040（2014.9.30 Rene Ladan 报告 GNATS URL 重定向）；Bug 205692（2015.12.29 Matthias Andree 报告 commit 模板中残留 GNATS 引用）；cdnmirror.com 上的 GNATS 数据库冻结 README ［A］
  
**史观**：软件工程，bug 追踪系统的迁移不仅是工具更替，更是历史叙事载体的一次重构，1990 年代至 2010 年代初的 PR 上下文在新系统中被部分剥离
  
**辨析**：［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 迁移过程中实际丢失的 PR 数量在公开档案中无明确统计，David Chisnall 公告中称 “some disruption” 但未量化；部分 PR 在 GNATS 中以纯文本邮件附加形式存在，迁移至 Bugzilla 后附件格式与可搜索性变化，需通过 Internet Archive 与 cdnmirror.com 上的 GNATS 冻结快照交叉验证；经 freebsd.duckdb 验证（2026-07-22 查询）：数据库共 9 张表（branches/commit_branches/commit_files/commits/contributors/db_meta/repos/sqlite_sequence/tags），无 GNATS PR 数据表，commit_files 与 commits 表无法提供 PR 丢失数量证据；freebsd.duckdb freebsd-doc 仓库 2014-05-31 至 2014-06-08 期间含 30 条 GNATS/Bugzilla 迁移相关 commit（如 Rene Ladan 2014-05-31 “nl/htdocs/send-pr.xml: MFen r44980 (disable the GNATS form)”、Peter Wemm 2014-06-04 "Along the lines of r44999, hack redirection for a few more gnats references.“、Eitan Adler 2014-06-08 ”During the temporary period, drop the footer on the gnats PRs."），反映迁移工程进展，但不反映 PR 丢失数量；0 信任原则提示：commit message 仅记录工程动作，不记录 PR 数据迁移完整性；存疑保留，待 GNATS 冻结快照与 Bugzilla 数据库的系统性比对审计方可量化
