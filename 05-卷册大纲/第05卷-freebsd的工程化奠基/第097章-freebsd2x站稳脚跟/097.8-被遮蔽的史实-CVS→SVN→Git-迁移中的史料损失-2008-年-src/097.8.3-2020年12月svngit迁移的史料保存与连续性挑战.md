# 097.8.3 2020 年 12 月 SVN→Git 迁移的史料保存与连续性挑战

  **要点**：FreeBSD 项目于 2020 年 12 月启动 SVN→Git 迁移，doc 仓库 2020 年 12 月 5-8 日迁移完成，src 仓库 2020 年 12 月 23 日前后迁移完成，ports 仓库推迟至 2021 年 3-4 月迁移；迁移由 Warner Losh（沃纳·洛什） 与 Ed Maste（埃德·马斯特） 领导的 git conversion working group 主导；迁移后 SVN 仓库变为只读，但 stable/11、stable/12 及相应 releng 分支的 MFC 仍被重放到 SVN 作为过渡辅助；迁移过程中移除了 `$FreeBSD$` 关键字标记（reviews.freebsd.org D27678，rene@ 2020.12.19 提交），RCS 风格的版本标记彻底退出历史；git 的 SHA-1 哈希与 SVN 的递增 revision number 无法直接对应，老文档中引用 SVN rXXXXXX 的位置需通过 git notes 维护映射
  
**史料**：bsdsec.net 2020.12.3 FreeBSD-doc Subversion to Git migration 公告；forums.freebsd.org 2020.12.17 "HEADS UP: FreeBSD changing from Subversion to Git this weekend" Warner Losh 帖子；reviews.freebsd.org D27678（rene@ 2020.12.19 提交的 build infrastructure 更新）；github.com/bsdimp/freebsd-git-docs 迁移文档；wiki.freebsd.org/git 迁移日程页面 ［A］
  
**史观**：总纲第 25 条——终结中的延续，SVN→Git 迁移虽保留 commit 历史，但 `$FreeBSD$` 标记的移除象征一个版本的 “档案铭文” 传统终结，commit hash 取代 revision number 成为新的史料引用单位
  
**辨析**：［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ git notes 中维护的 SVN-Git 映射在迁移初期的完整性需独立验证，部分边角 commit（如 vendor 分支导入）的映射关系存在争议；Warner Losh 在公告中称 "will preserve much of the current FreeBSD development workflow"，但 stable/11、stable/12 的 MFC 重放机制的实际运行时长与终止日期在公开档案中未明确记录；经 freebsd.duckdb 验证（2026-07-22 查询）：数据库 schema 中无 git notes 元数据表，commit_files 表仅记录 file_path/status/additions/deletions，无法反映 git notes 内容；freebsd.duckdb freebsd-src/freebsd-doc/freebsd-ports 三仓库 2020-11 至 2021-06 期间含 24 条 SVN→Git 迁移相关 commit（如 Dimitry Andric 2021-01-26 "Change links from svnweb to cgit, and remove sys/sys/param.h subpaths“、Ed Maste 2021-01-29 ”Cirrus-CI: remove svn2git remnant“、Warner Losh 2021-03-16 ”Merge in the migration from subversion / github"），反映迁移后清理工作，但不反映 git notes 完整性；0 信任原则提示：commit message 仅记录链接替换与 CI 清理，不记录 git notes ref 的内容完整性；存疑保留，待 FreeBSD git 仓库 git notes ref（refs/notes/*）的独立审计方可验证
