# 109.3.3 要点5x时期第三方软件变更的核心特征是引入而非替换PF引入是与IPFilter并

  **要点**：5.x 时期第三方软件变更的核心特征是 “引入而非替换”——PF 引入是与 IPFilter 并存而非替代，sendmail 延续默认地位而非被替换。这种 “新旧并存” 的过渡模式是 FreeBSD 5.x 时期 “激进内核改造 + 保守用户空间” 策略的体现：内核层面（SMPng、GEOM、KSE、ULE）进行激进重写，但用户空间层面（sendmail、BIND、GCC 2.95/3.x）保持稳定，避免内核和用户空间同时变动给用户带来过大冲击。真正的大规模第三方软件替换发生在 10.x 时期（2014 年），届时 Clang 替换 GCC、Unbound 替换 BIND、bsdinstall 替换 sysinstall 等多项变更在一到两个版本内集中完成。
  
**史料**：FreeBSD 5.x Release Notes、FreeBSD 10.x Release Notes、freebsd-hackers 邮件列表 ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：5.x 时期的第三方软件策略揭示了一个规律——系统软件的 “替换” 往往不是在一个版本内完成的，而是经历 “引入共存 → 默认切换 → 旧者移除” 三个阶段，而 5.x 对 PF/IPFilter、sendmail 的策略处于第一阶段（引入共存），旧者移除（IPFilter 移除）发生在 10.x（2014 年），sendmail 替换发生在 14.0（2023 年，详见 100.17.2）
  
**辨析**：不能因为 5.x 时期没有发生大规模第三方软件替换就认为 5.x “保守”——5.x 在内核层面的激进改造（SMPng、KSE、GEOM、ULE、MAC）是整个 FreeBSD 历史上最剧烈的架构变更，用户空间保持稳定是明智的工程权衡；“引入而非替换” 的策略降低了 5.x 的升级风险——用户可以在 5.x 选择使用 PF 或继续使用 IPFilter，可以选择使用 UFS2 或继续使用 UFS1，无需被迫立即迁移
