# 109.3.2 sendmail 作为默认 MTA 的延续

  **要点**：FreeBSD 5.x 全系列中 sendmail 仍为 base system 的默认 MTA（Mail Transfer Agent），版本为 sendmail 8.12.x-8.13.x。sendmail 自 4.1cBSD 起（〔存疑：纳入 4.1cBSD 的确切年份未经 TUHS 档案核验，姑系于 1982 年前后〕；Eric Allman（埃里克·奥尔曼） 在 UC Berkeley 开发）即为 BSD 系统的标准 MTA，在 FreeBSD 2.0-13.x 长达 30 年间持续作为默认。需特别注意：Postfix 从未进入 FreeBSD base system——Postfix 由 Wietse Venema 于 1997 年在 IBM T.J. Watson 研究中心开发，作为 sendmail 的安全替代品，但 FreeBSD 始终将其保留在 ports（mail/postfix）中供用户自行安装，从未纳入 base。关于 FreeBSD 默认 MTA 从 sendmail 替换为其他软件的实际发生时间，不是 5.x 时期（Postfix 从未进入 base），不是 10.x 时期（DMA 仅存在于 ports），而是 FreeBSD 14.0（2023 年 11 月 20 日）将 DMA（DragonFly Mail Agent）设为默认 MTA 替换 sendmail。5.x 时期用户对 sendmail 配置复杂、安全性历史方面虽有关切，但 FreeBSD 社区选择保留 sendmail 而非引入 Postfix 到 base，这一决策延续了 20 年。
  
**史料**：FreeBSD 5.0-5.4 Release Notes（sendmail 版本更新记录）、FreeBSD 14.0 Announcement（DMA 成为默认 MTA）、Venema W. Postfix 设计文档、Allman E. sendmail 历史［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕
  
**史观**：总纲第 22 条——知识注定过时：sendmail 是 BSD 系统中旧知识长期存续、终被更替的典型代表——其 sendmail.cf 配置文件语法以晦涩难懂著称，安全性历史上多次出现严重漏洞（如 1988 年 Morris 蠕虫利用 sendmail 漏洞），但因其 “够用” 且替换成本高（所有系统邮件脚本、cron 输出、第三方软件依赖其行为），在 base 中保留了 30 年；总纲第 13 条——法律与道德是利益分配：Postfix 使用 IBM Public License（后改为 EPL），sendmail 使用 sendmail License（BSD 风格），许可证差异不是 Postfix 未进入 base 的原因（Postfix 许可证兼容），而是 FreeBSD 社区认为 “sendmail 虽不完美但足够” 的保守主义决策
  
**辨析**：关于 “sendmail vs Postfix” 的争论在 2000 年代初期（5.x 时期）的 FreeBSD 社区邮件列表讨论中持续存在，但 FreeBSD Core Team 从未正式讨论过将 Postfix 纳入 base 替换 sendmail 的提案；DMA 来自 DragonFly BSD 项目，由 Matthias Schmidt 开发，专为 “无需完整邮件服务器的桌面/客户端系统” 设计，仅负责本地邮件投递与通过外部 smarthost 转发，不能替代 sendmail 的完整 MTA 功能——当 14.0 将 DMA 设为默认时，意义在于 “默认情况下大部分 FreeBSD 系统不需要完整 MTA” 而非 “DMA 在功能上等价于 sendmail”
