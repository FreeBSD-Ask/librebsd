# 109.6.2 OpenSSL PKCS #1 与 CAN-2004-0079 拒绝服务漏洞群——5.x 时期加密库安全响应与 vendor branch 同步模型

  **要点**：FreeBSD 5.x 版本周期内 OpenSSL 共发生两次重大安全事件——2003-03-20 Chris D. Faulhaber 提交 PKCS #1 安全修复（commit `8786792504af176f14878c00d689a1a17bfac4bd`，引用 OpenSSL 2003-03-19 安全公告 secadv_20030319.txt，同日 MFC 至 RELENG_4 与 RELENG_5_0 分支 commit `07bfbcd1ccdd006a8890f604ed5c0a7b6826c76e`、`78f9ef7a8f8181b7afdd558b419f5d1b2b4a0c94`、`f8bf448616afe936884fe770757cc09c5c035312`）；2004-03-17 Jacques Vidrine 提交 OpenSSL 拒绝服务漏洞修复（commit `81ac585294418460a598ae2c6d3eeaf0d993b18a`，明确标注 CAN-2004-0079，并连续 5 条 MFC commit `0e4e5b966c79797ad0adbe5e5e72c78f9d58881a`、`aa606d7a1638e5032b64759fb701c745fbc9ed82`、`bdc9df456b5149782731e3630aa369fa0b678723`、`6ab589eba7d6b6200f46d695f3944a5d3b1ead37`、`58a6c81357cb5d6d002658909408bac49cfc9cb0` 将修复回溯至 RELENG_4_9、RELENG_4_8、RELENG_4_7、RELENG_5_2、RELENG_5_1 分支）；两次 OpenSSL 漏洞响应均采用 “vendor branch 同步 + 多分支 MFC 回溯” 模型——即先从 OpenSSL 上游 vendor branch 合并修复，再向多个受影响 release 分支回溯，体现 5.x 时期 FreeBSD 安全响应已建立成熟的多分支维护机制
  
**史料**：freebsd.duckdb freebsd-src 仓库 commits 表（8786792504af176f14878c00d689a1a17bfac4bd、07bfbcd1ccdd006a8890f604ed5c0a7b6826c76e、78f9ef7a8f8181b7afdd558b419f5d1b2b4a0c94、f8bf448616afe936884fe770757cc09c5c035312、81ac585294418460a598ae2c6d3eeaf0d993b18a、0e4e5b966c79797ad0adbe5e5e72c78f9d58881a、aa606d7a1638e5032b64759fb701c745fbc9ed82、bdc9df456b5149782731e3630aa369fa0b678723、6ab589eba7d6b6200f46d695f3944a5d3b1ead37、58a6c81357cb5d6d002658909408bac49cfc9cb0）；OpenSSL secadv_20030319.txt 公告；CAN-2004-0079 NVD 条目 ［A］
  
**史观**：专题语（不设总纲条号）——密码学：OpenSSL 作为 5.x 时期 FreeBSD 加密栈核心组件，其安全响应质量直接影响 SSL/TLS 服务可用性；专题语（不设总纲条号）——软件工程：vendor branch 同步 + 多分支 MFC 模型是 FreeBSD 安全响应工程的成熟化标志
  
**辨析**：CAN-2004-0079 无 CVSS 评分（NVD 未收录 v3.x 评分），按 OpenSSL 公告描述的 DoS 影响估算约对应 Medium 级别；PKCS #1 漏洞无 CAN/CVE 编号但被 OpenSSL 官方公告收录；【0 信任原则·commit 量比较公平性】5.x 版本周期 22 个月内 80 条 security fix commit（月均 3.64 条/月）高于 4.x 版本周期 35 个月的 108 条（月均 3.09 条/月），但 commit 量上升不必然等同于安全质量提升——5.x 引入 GEOM/UFS2/MAC/KSE/SMPng 等多项新组件扩大了攻击面，commit 量上升可能反映新组件引入初期的安全基线建立而非响应能力增强；【commit hash 完整性】所有引用 commit hash 均为 40 字符完整 hash，CVS-to-SVN/SVN-to-Git 迁移可能重写 hash 但 2020 年迁移后 hash 应稳定
