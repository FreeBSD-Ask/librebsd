# 115.11.1 4BSD 调度器 → ULE 调度器默认化与持续优化（7.1 默认后 8.x 时期 ULE 成熟）

  **要点**：FreeBSD 5.0-RELEASE（2003.1）由 Jeff Roberson 设计并引入 ULE 调度器，作为对传统 4BSD 调度器的现代化替代——ULE 采用 O(1) 算法、每 CPU 独立运行队列、CPU 亲和性、SMT 感知等现代设计；但 5.x 时期 ULE 稳定性问题严重，5.2 短暂默认后 5.3 完全禁用，6.x 时期仅作为实验性选项保留，4BSD 仍为默认；FreeBSD 7.1-RELEASE（release/7.1.0 tagger_date = 2008-12-31T22:57:14Z，tagger = Ken Smith，target_commit_hash = a1fc2b0c89a1dd2ca090ae990ab45b21363ab76e；官方公告日期 2009 年 1 月 4 日）正式将 ULE 设为 amd64/i386 默认调度器，标志 4BSD 主导地位结束；8.x 时期 ULE 持续优化——包括交互性评分改进、负载均衡算法完善、nice 值处理优化、调度切片调整等；4BSD 调度器在 8.x 时期仍作为编译时可选选项（`options SCHED_4BSD`）保留，用于 HPC 等特定场景与对照测试；ULE 默认化使 FreeBSD 在多核 SMP 与 SMT 环境下的调度性能显著提升，与 Linux CFS（2.6.23，2007.10）形成同期对标
  
**史料**：FreeBSD 7.1-RELEASE Release Notes（ULE 默认化条目）；Jeff Roberson“ULE: A Modern Scheduler for FreeBSD”（BSDCon 2003 论文）；freebsd-hackers 邮件列表 2008-2011 年 ULE 相关讨论；FreeBSD 8.0/8.1/8.2 Release Notes 中 ULE 改进条目；`sys/kern/sched_ule.c` 与 `sys/kern/sched_4bsd.c` commit log；freebsd.duckdb freebsd-src 仓库 commits 表 ia64 启用 ULE 默认 commit（commit_hash = 495168ba8dad73b7e97ba48402bc69141d53c473，committer_date = 2008-04-15T05:02:42Z，author = Marcel Moolenaar，message_subject ="Support and switch to the ULE scheduler: o Implement IPI_PREEMPT, o Set td_lock for the thread being switched out, o For ULE & SMP, loop while td_lock points to blocked_lock for the thread being switched in, o Enable ULE by default in GENERIC and SKI"）；freebsd.duckdb freebsd-src 仓库 commits 表 7.1 Release Notes ia64 ULE 条目 commit（commit_hash = 3ad30671f1906bb03a3e58a316ee6e3e22526366，committer_date = 2008-04-20T18:17:33Z，author = Hiroki Sato（佐藤広生），message_subject ="New release notes: ULE scheduler enabled by default in GENERIC for ia64, **fdopendir(3)** added, and **tcgetsid(3)** added."）；freebsd.duckdb freebsd-src 仓库 tags 表 release/7.1.0（tagger_date = 2008-12-31T22:57:14Z，tagger = Ken Smith） ［A］
  
**史观**：技术选择的代价：ULE 付出工程复杂度代价（算法复杂、调试困难）获得多核扩展性，4BSD 简单稳定但无法适应 SMP 时代；总纲第 17 条——形式与内容：调度器作为内核“形式”的改变重塑了系统并发执行的“内容”
  
**辨析**：经 freebsd.duckdb commits 表验证，ULE 在 7.1 默认化的架构范围比旧叙事更广——除了 amd64/i386 外，ia64 架构也在 7.1-RELEASE 周期将 ULE 设为 GENERIC 默认：2008-04-15T05:02:42Z Marcel Moolenaar commit_hash = 495168ba8dad73b7e97ba48402bc69141d53c473“Enable ULE by default in GENERIC and SKI”（SKI 为 ia64 模拟器），2008-04-20T18:17:33Z Hiroki Sato commit_hash = 3ad30671f1906bb03a3e58a316ee6e3e22526366 在 7.1 Release Notes 中明确“ULE scheduler enabled by default in GENERIC for ia64”；因此旧叙事称“仅 amd64/i386 默认”不准确，正确表述应为“amd64/i386/ia64 默认”，其他架构（pc98/powerpc/sparc64 等）仍以 4BSD 为默认；ULE 在 8.x 时期的性能改进幅度在不同负载下结论不同，部分 HPC 场景下 4BSD 仍优于 ULE（如 Steve Kargl 2008 年报告的 OpenMPI 案例，2026 年仍在 freebsd-hackers 讨论）；4BSD 调度器直到 FreeBSD 15 仍未完全移除，反映了“淘汰”在 BSD 文化中的渐进性
