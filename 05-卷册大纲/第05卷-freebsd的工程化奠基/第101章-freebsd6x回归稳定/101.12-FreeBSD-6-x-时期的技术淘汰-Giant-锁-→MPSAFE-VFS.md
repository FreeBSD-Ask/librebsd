# 101.12 FreeBSD 6.x 时期的技术淘汰——Giant 锁 →MPSAFE VFS 与 SMPng 收束、KSE M: N→libthr 1:1 起步、GBDE→GELI 磁盘加密、ULE 调度器实验性回归、4BSD 调度器保持默认（2005-2008）

## 101.12.1 Giant 锁 → MPSAFE VFS 与 SMPng 项目收束（6.0，2005.11.3）

  **要点**：FreeBSD 5.x 时期启动 SMPng 项目，旨在分解 Giant lock（单一内核大锁）为细粒度锁；FreeBSD 6.0-RELEASE（2005.11.3，release/6.0.0 tagger_date = 2005-11-03T00:35:26Z，tagger = cvs2svn）引入 MPSAFE VFS（Multi-Processor Safe VFS）——VFS 层大部分代码路径不再需要 Giant 锁；6.0 同时引入大量 MPSAFE 网络栈路径（IPv4、IPv6、UNIX domain sockets、NetGraph）；SMPng 项目在 6.0 标记为 “完成”——大部分内核已无 Giant 锁依赖，但部分设备驱动与 NFS 组件仍保留 Giant；6.0-6.4 期间继续清理 Giant 残余，NFS、AGP、**scsi(4)** 部分代码在 6.x 时期移除 Giant 依赖；SMPng 完成使 FreeBSD 在 4-32 CPU 服务器上获得线性扩展性，与 5.x 时期相比性能显著提升
  
**史料**：FreeBSD 6.0-RELEASE Release Notes；Robert Watson “FreeBSD SMPng Project SMP Network Stack”（2005 演讲）；freebsd-smp 邮件列表 2005-2008 年讨论；CVS commit log 中 MPSAFE 相关 commit；freebsd.duckdb freebsd-src 仓库 tags 表 release/6.0.0 的 tagger_date = 2005-11-03T00:35:26Z（target_commit_hash = 3d215489fe03c6c5cecc3b5ed9ea39118e6ce379） ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：Giant 锁分解付出工程复杂度代价（细粒度锁设计与验证困难），但获得多核扩展性；总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：锁粒度形式的改变：锁粒度作为 “形式” 改变 “内容”（内核并发执行能力）

## 101.12.2 KSE M: N 线程模型 → libthr 1:1 线程模型起步（6.x 时期过渡）

  **要点**：FreeBSD 5.0-RELEASE（2003.1.16，release/5.0.0 tagger_date = 2003-01-16T16:56:23Z）引入 KSE（Kernel Scheduled Entities）M: N 线程模型，由 Daniel Eischen 等设计；KSE 设计为 M 个用户线程映射到 N 个内核调度实体，理论上可减少内核开销；但 KSE M: N 实现复杂、性能不及预期、调试困难；同期 libthr（1:1 线程库）作为替代方案由 David Xu 等开发，每个用户线程对应一个内核线程，实现简单但开销较高；FreeBSD 5.3-RELEASE（2004.11.4，release/5.3.0 tagger_date = 2004-11-04T19:12:42Z）将 KSE 设为默认线程库，libthr 作为可选；6.x 时期社区逐步倾向 libthr——John Baldwin（约翰·鲍德温） 等在 freebsd-arch 邮件列表 2007 年讨论在 7.0 将 libthr 设为默认，8.0 完全移除 KSE 内核支持；libthr 在 7.0-RELEASE（2008.2.24，release/7.0.0 tagger_date = 2008-02-24T05:45:17Z）正式成为默认线程库，KSE 内核数据结构在 8.0-RELEASE（2009.11.21，release/8.0.0 tagger_date = 2009-11-21T06:13:29Z）移除，libkse 用户态库目录在 2014.4 由 Brooks Davis 完全删除
  
**史料**：FreeBSD 5.0/6.0/7.0 Release Notes 线程部分；Daniel Eischen 在 freebsd-arch 邮件列表 2001-2005 年关于 KSE 设计的讨论；John Baldwin 在 freebsd-arch 2007 年关于 libthr 默认化的 RFC；Brooks Davis 2007.11.20 关于 libkse*.a 移除的 patch；CVS commit log 中 libkse 与 libthr 相关 commit；freebsd.duckdb freebsd-src 仓库 tags 表 release/5.0.0 的 tagger_date = 2003-01-16T16:56:23Z、release/5.3.0 的 tagger_date = 2004-11-04T19:12:42Z、release/7.0.0 的 tagger_date = 2008-02-24T05:45:17Z、release/8.0.0 的 tagger_date = 2009-11-21T06:13:29Z ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：KSE M: N 模型付出工程复杂度代价（M: N 调度器实现困难），最终被 1:1 简单模型取代，反映 “简单胜过聪明” 的工程哲学；总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：学院派 M: N 与工业派 1:1 的路线之争：KSE → libthr 反映 “学院派 M: N” vs “工业派 1:1” 的技术政治选择

## 101.12.3 GBDE → GELI 磁盘加密框架（6.0，2005.11.3）

  **要点**：FreeBSD 5.x 时期由 Poul-Henning Kamp（波尔-亨宁·坎普） 设计 GBDE（GEOM-Based Disk Encryption），作为 GEOM 框架的一个 class 提供 4KB 扇区级磁盘加密；GBDE 设计简单但加密能力有限——使用固定密钥、缺少密钥衍生函数（KDF）、不支持多密码、加密元数据简单；FreeBSD 6.0-RELEASE（2005.11.3，release/6.0.0 tagger_date = 2005-11-03T00:35:26Z，tagger = cvs2svn）引入 **geli(8)** 与 **geli(4)**，由 Pawel Jakub Dawidek 设计；GELI 首次 commit 于 2005-07-27T21:43:37Z（commit_hash = c58794debd2bfe8cfe8b69483080d0e7b3fcb3ed，committer = Pawel Jakub Dawidek，message_subject = "Add GEOM_ELI class which provides GEOM providers encryption. For features list and usage see manual page: geli(8)."），早于 6.0-RELEASE 约 3 个月，属 6-CURRENT 开发周期；GELI 同样基于 GEOM 框架，但引入 AES-XTS/AES-CBC 加密、PBKDF2 密钥衍生、密钥文件与密码组合认证、加密元数据冗余、引导时加密根文件系统支持；GELI 在功能与安全性上全面优于 GBDE，成为 6.x 时期默认磁盘加密方案；GBDE 在 6.x 时期保留但被标记为 deprecated；7.0 起社区强烈推荐使用 GELI 替代 GBDE
  
**史料**：FreeBSD 6.0-RELEASE Release Notes；Pawel Jakub Dawidek 在 freebsd-geom 邮件列表 2005 年关于 GELI 设计的讨论；man **geli(8)** 与 **geli(4)** 历次版本；Poul-Henning Kamp GBDE 设计文档（phk.freebsd.dk）；freebsd.duckdb freebsd-src 仓库 commits 表 GELI 首次 commit 为 2005-07-27T21:43:37Z（commit_hash = c58794debd2bfe8cfe8b69483080d0e7b3fcb3ed，author = Pawel Jakub Dawidek）；freebsd.duckdb freebsd-src 仓库 tags 表 release/6.0.0 的 tagger_date = 2005-11-03T00:35:26Z（target_commit_hash = 3d215489fe03c6c5cecc3b5ed9ea39118e6ce379） ［A］
  
**史观**：总纲第 10 条——动手者创造历史：Pawel Jakub Dawidek 作为相对边缘的贡献者，GELI 设计影响后续 FreeBSD 全盘加密生态；总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：GELI 引入付出向后兼容性代价（GBDE 加密卷需转换），但获得更强安全性

## 101.12.4 ULE 调度器实验性回归与 4BSD 调度器保持默认（6.x 时期）

  **要点**：FreeBSD 5.0-RELEASE（2003.1.16，release/5.0.0 tagger_date = 2003-01-16T16:56:23Z）引入 ULE 调度器，由 Jeff Roberson 设计，目标取代 4BSD 调度器；ULE 设计支持每 CPU 运行队列、CPU 亲和性、SMT 支持、O(1) 调度复杂度；FreeBSD 5.2-RELEASE（2004.1.10，release/5.2.0 tagger_date = 2004-01-10T05:53:29Z）ULE 短暂成为默认调度器，Jeff Roberson 2004.1.24 在 freebsd-current 公告 "ULE has entered into its probationary period as the default scheduler"；但 ULE 在 5.3-RELEASE（2004.11.4，release/5.3.0 tagger_date = 2004-11-04T19:12:42Z）因稳定性问题被完全禁用——5.3 errata 公开声明 "The ULE scheduler described in the release notes has been completely disabled to discourage its use because it has stability problems"；6.0-RELEASE（2005.11.3，release/6.0.0 tagger_date = 2005-11-03T00:35:26Z）ULE 作为实验性调度器保留但默认禁用，man **sched_ule(4)** 6.0 版本明确称 "As an experimental scheduler, sched_ule is not enabled by default due to a number of known issues, including weak performance with several known workloads, and reports of instability"；6.x 时期 Jeff Roberson 持续改进 ULE，ULE 2.0 在 7.0-RELEASE（2008.2.24，release/7.0.0 tagger_date = 2008-02-24T05:45:17Z）合入并大幅改进但 4BSD 仍为默认（7.0 公告明确 "ULE scheduler is vastly improved...the 4BSD scheduler is still the default for 7.0 but ULE may become the default for 7.1"），ULE 直到 7.1-RELEASE（2008.12.31，release/7.1.0 tagger_date = 2008-12-31T22:57:14Z）才成为 amd64 与 i386 GENERIC 内核默认；6.x 时期 4BSD 调度器保持默认，ULE 为实验性选项
  
**史料**：FreeBSD 5.0/5.3/6.0/7.0 Release Notes；Jeff Roberson “ULE: A Modern Scheduler For FreeBSD”（BSDCon 2003 论文）；Jeff Roberson 2004.1.24 freebsd-current 公告；5.3 errata 2004.11.1；man **sched_ule(4)** 6.0 版本（2005.4.7）；Marshall Kirk McKusick（马歇尔·柯克·麦库西克） “Thread Scheduling in FreeBSD 5.2”（; login: 2004）；freebsd.duckdb freebsd-src 仓库 tags 表 release/5.0.0 的 tagger_date = 2003-01-16T16:56:23Z、release/5.2.0 的 tagger_date = 2004-01-10T05:53:29Z、release/5.3.0 的 tagger_date = 2004-11-04T19:12:42Z、release/6.0.0 的 tagger_date = 2005-11-03T00:35:26Z、release/7.0.0 的 tagger_date = 2008-02-24T05:45:17Z、release/7.1.0 的 tagger_date = 2008-12-31T22:57:14Z ［A］
  
**史观**：总纲第 5 条——没有必然性，只有偶然性：ULE 在 5.3 因稳定性问题被禁用是偶然事件，但其推迟使 6.x 时期 4BSD 调度器保持主导，反映 “稳定优先” 哲学；总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：ULE 实验性引入付出工程代价（5.x 时期 ULE 工作需在 6.x 重新评估），但最终在 7.0 成熟
