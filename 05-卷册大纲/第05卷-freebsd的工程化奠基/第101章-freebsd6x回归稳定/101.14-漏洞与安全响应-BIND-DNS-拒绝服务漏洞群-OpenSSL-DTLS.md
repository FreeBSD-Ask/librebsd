# 101.14 漏洞与安全响应——BIND DNS 拒绝服务漏洞群、OpenSSL DTLS 整数溢出与 tcpdump 缓冲区溢出、MAC/Jails/devfs/gbde/OpenBSM 安全修复合并（2005-2008）

## 101.14.1 BIND DNS 拒绝服务漏洞群——CVE-2006-2937/CVE-2006-2940/CVE-2007-2925/CVE-2007-2926 与 FreeBSD-SA-07:07.bind 的多分支回溯

  **要点**：FreeBSD 6.x 版本周期（2005-11-01 至 2008-02-01）内，BIND 是受 CVE 影响最密集的第三方组件，4 个去重 CVE 均指向 DNS 协议层面的拒绝服务向量。CVE-2006-2937 与 CVE-2006-2940 由 ISC 于 2006 年 10 月 31 日公告，均属 BIND 9.3.2-P1 之前版本的拒绝服务缺陷——前者针对递归解析器在处理特定 DNS 查询时的高 CPU 占用，后者针对同一逻辑路径的资源耗尽变体；FreeBSD 6.x 的修复路径为 Doug Barton 于 2006-11-04 提交的 vendor import `a02f92e875d0d48c46103eef0fbea835048a278b`，将 BIND 升级至 9.3.2-P2，对应官方公告 FreeBSD-SA-07:07.bind。CVE-2007-2925 与 CVE-2007-2926 由 ISC 于 2007 年 7 月公告，BIND 9.4.1-P1 与 9.3.4-P1 修复——前者涉及动态更新消息处理中的断言失败，后者涉及 AXFR 区域传输中的资源耗尽；Doug Barton 同日（2007-07-25）执行三条 commit 完成多分支回溯：vendor import `56a78b52117fceacbf4282cd41826ca9fb72dd07`（9.4.1-P1 入 HEAD 与 RELENG_6）、`f6a07f4614ef564e91053ec56336c84239607086`（9.3.4-P1 入 RELENG_6_2）、`58a7459b817ff9c684f42fd811dc4d8ded9c3b45`（9.3.4-P1 入 RELENG_6_1），覆盖 6.0/6.1/6.2 三个稳定分支。BIND 漏洞修复模式体现了 FreeBSD 6.x 时期 vendor branch 同步模型——上游 ISC 发布补丁后，FreeBSD 通过 vendor import 直接合并至 contrib/bind9，再经 MFC 流程向多个 RELENG_6_X 分支回溯
  
**史料**：ISC BIND 9.3.2-P2 公告（2006-11-02）；ISC BIND 9.4.1-P1/9.3.4-P1 公告（2007-07-24）；FreeBSD-SA-07:07.bind（2007-03-27 修订至 2007-07-25）；freebsd.duckdb freebsd-src 仓库 commit `a02f92e875d0d48c46103eef0fbea835048a278b`（Doug Barton，2006-11-04，"Update to version 9.3.2-P2, which addresses the vulnerability announced by ISC d..."）、`56a78b52117fceacbf4282cd41826ca9fb72dd07`（Doug Barton，2007-07-25，"Vendor import of 9.4.1-P1, which has fixes for the following:"）、`f6a07f4614ef564e91053ec56336c84239607086`（Doug Barton，2007-07-25，“Update to 9.3.4-P1, which fixes the following:”）、`58a7459b817ff9c684f42fd811dc4d8ded9c3b45`（Doug Barton，2007-07-25，“Update to 9.3.4-P1, which fixes the following:”） ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：BIND 作为事实标准 DNS 实现的便利性换来频繁的安全响应工程投入；总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：DNS 作为互联网基础设施，其漏洞响应成本是公共物品式的利益分配；总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：6.x 时期的多分支同步反映 5.x 转型后稳定分支维护体系的成熟
  
**辨析**：4 个 BIND CVE 的 CVSS v3 评分在 NVD 元数据中均未提取，无法在版本周期文件中给出数值化严重程度——但这不意味着低危，BIND 拒绝服务在 2006-2007 年仍属高影响事件；ISC 公告日期（2006-10-31 与 2007-07-24）与 FreeBSD commit 日期（2006-11-04 与 2007-07-25）的间隔仅 3-4 天，反映 6.x 时期 BIND 安全响应的及时性；CVE-2007-2926 在三条 commit 中的重复对应同一逻辑修复在不同分支的 MFC 回溯，而非三次独立修复；Doug Barton 作为 BIND maintainer 在 6.x 时期的所有 BIND vendor import 均经 freebsd.duckdb 交叉验证，author 与 committer 一致，无可疑篡改痕迹
  
**文献**：ISC BIND Security Advisories（isc.org/ops/advisories）；FreeBSD-SA-07:07.bind；freebsd.duckdb freebsd-src 仓库 BIND 相关 commit（2006-11 至 2007-07） ［A］

## 101.14.2 OpenSSL DTLS 整数溢出（CVE-2007-4995）与 tcpdump 缓冲区溢出（CVE-2007-3798）——High 级别独立叙述

  **要点**：OpenSSL CVE-2007-4995 与 tcpdump CVE-2007-3798 是 6.x 版本周期内技术机制最严重的两条漏洞，前者涉及 DTLS 协议实现的整数溢出，后者涉及网络抓包工具的缓冲区溢出，二者虽未提取 CVSS v3 评分，但从技术机制（整数溢出与缓冲区溢出均为可利用漏洞原型）与组件角色（OpenSSL 为加密库核心、tcpdump 为运维基础工具）看，均属 High 级别潜在影响。CVE-2007-4995 由 OpenSSL 项目 2007 年 10 月公告，DTLS 协议在处理特定握手消息时存在整数溢出，可导致堆内存破坏；FreeBSD 修复路径为 Simon L. B. Nielsen 于 2007-10-18 提交的 vendor import `a0ddfe4e7233d81e88a86217b7653708db2720fa`，从 OpenSSL_0_9_8-stable 分支导入修复，同步通过 `c4d356d3b5c3e04758514a5276a1ee560c4f8ad7`（2007-10-18，"MFC: Import DTLS security fix from upstream OpenSSL_0_9_8-stable branch."）回溯至 RELENG_6，对应 FreeBSD-SA-07:08.openssl。CVE-2007-3798 由 tcpdump 项目 2007 年 7 月公告，特定构造的 RADIUS 抓包数据可触发缓冲区溢出；FreeBSD 修复路径为 Simon L. B. Nielsen 于 2007-08-01 提交的 `faeb38d111efa1ecad5565f314581e95ce3ac7f8`（“Correct buffer overflow in tcpdump(1).”），对应 FreeBSD-SA-07:06.tcpdump。两条漏洞的修复时间间隔仅 6 周，反映 6.x 时期 OpenSSL 与网络工具的同步响应能力
  
**史料**：OpenSSL CVE-2007-4995 公告（2007-10）；tcpdump CVE-2007-3798 公告（2007-07）；FreeBSD-SA-07:06.tcpdump（2007-08-01）；FreeBSD-SA-07:08.openssl（2007-10-18）；freebsd.duckdb freebsd-src 仓库 commit `faeb38d111efa1ecad5565f314581e95ce3ac7f8`（Simon L. B. Nielsen，2007-08-01）、`a0ddfe4e7233d81e88a86217b7653708db2720fa`（Simon L. B. Nielsen，2007-10-18）、`c4d356d3b5c3e04758514a5276a1ee560c4f8ad7`（Simon L. B. Nielsen，2007-10-18） ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：FreeBSD 对 OpenSSL 与 tcpdump 等第三方组件的依赖使其安全响应节奏受制于上游；总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：OpenSSL 作为加密栈核心，其漏洞响应义务与成本分配不同于一般组件
  
**辨析**：CVE-2007-4995 的 DTLS 漏洞在 OpenSSL 项目侧已通过 OpenSSL_0_9_8-stable 分支发布，FreeBSD 采用 vendor import 而非自研补丁，符合 vendor branch 同步规范；tcpdump 作为 base system 组件的修复路径与 BIND/OpenSSL 不同——tcpdump 直接在 FreeBSD 源树内打补丁而非 vendor import，反映 6.x 时期 tcpdump 的 vendor branch 同步策略与 BIND/OpenSSL 存在差异；CVE-2007-3798 的 commit `faeb38d111efa1ecad5565f314581e95ce3ac7f8` 在 commit_subject 中未明确说明是否同步回上游 tcpdump 项目，需对照 tcpdump 仓库 commit 历史核验
  
**文献**：OpenSSL Security Advisory（2007-10）；tcpdump ChangeLog（2007-08）；FreeBSD-SA-07:06.tcpdump；FreeBSD-SA-07:08.openssl；freebsd.duckdb freebsd-src 仓库 OpenSSL/tcpdump 相关 commit（2007-07 至 2007-10） ［A］

## 101.14.3 MAC/Jails/devfs/gbde/OpenBSM/libarchive/gtar 安全修复合并叙述——6.x 时期 base system 安全加固

  **要点**：6.x 版本周期内 22 条 security fix commit（无 CVE 编号）覆盖 MAC 框架、Jails、devfs、gbde、OpenBSM、libarchive、gtar 等多个 base system 组件。MAC 框架方面，Christian S.J. Peron 于 2006-01-24 提交 `ca1e983adfa8d07f70fecd2e0b512d5467458afc`（“MFC the security.mac.biba.interfaces_equal sysctl variable”），将 MAC/biba 策略的 interfaces_equal sysctl 从 HEAD 回溯至 RELENG_6，扩展 MAC/biba 对网络接口的等价处理。Jails 方面，Maxim Konovalov 于 2006-05-17 提交 `faf72da5bb5e08c4b48c96259e983856ef86235f`，文档化 `security.jail.jailed` 与 `security.jail.list` sysctl；Simon L. B. Nielsen 于 2006-05-28 提交 `6ad01cde4efac3de004a6e49195f0f42358fc50b`，撤销先前 devfs jail mount 的 MFC——commit_subject 明确 "mounting devfs without a devfs ruleset inside a jail is a very bad idea security wise"，反映 6.x 时期对 jail 内 devfs 暴露面的安全收紧。gbde 方面，Colin Percival 于 2006-02-14 提交 `a5e9d3ad0cdaaa2eb16b52cefe47a865c619bf84`，为 **gbde(8)** 增加 key file 支持，减少对 passphrase 的单一依赖。OpenBSM 方面，Robert Watson 于 2006-09-02 提交 `1181d11733c8593f30e6d62e57edb2b4cd25a849`，将 OpenBSM 1.0 alpha 10 从 HEAD MFC 至 RELENG_6，commit_subject 强调 "OpenBSM is the user space portion of the TrustedBSD audit subsystem"，是 6.x 时期 TrustedBSD 审计子系统稳定化的关键节点。libarchive 与 gtar 方面，Tim Kientzle 于 2007-08-25 提交 `cb43e1fdfee1d975ace60eecc3370a1a7e4cd833`，用 libarchive 的新安全检查替代 **tar(1)** 内的旧实现；John Baldwin（约翰·鲍德温） 于 2007-11-29 提交 `7d396c5f9cab1f0aa7d16ea25fb06cd59b3df775`，修复 gtar 目录遍历漏洞
  
**史料**：freebsd.duckdb freebsd-src 仓库 commit `ca1e983adfa8d07f70fecd2e0b512d5467458afc`（Christian S.J. Peron，2006-01-24）、`faf72da5bb5e08c4b48c96259e983856ef86235f`（Maxim Konovalov，2006-05-17）、`6ad01cde4efac3de004a6e49195f0f42358fc50b`（Simon L. B. Nielsen，2006-05-28）、`a5e9d3ad0cdaaa2eb16b52cefe47a865c619bf84`（Colin Percival，2006-02-14）、`1181d11733c8593f30e6d62e57edb2b4cd25a849`（Robert Watson，2006-09-02）、`cb43e1fdfee1d975ace60eecc3370a1a7e4cd833`（Tim Kientzle，2007-08-25）、`7d396c5f9cab1f0aa7d16ea25fb06cd59b3df775`（John Baldwin，2007-11-29） ［A］
  
**史观**：总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：base system 组件的安全加固是长期工程，单条 commit 的影响分摊于整个用户群；总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：6.x 时期 MFC 流程的规范化使 security fix 能快速从 HEAD 同步至稳定分支
  
**辨析**：22 条 security fix commit 的 commit_subject 均含 “security” 或 “Security:” 标签，但部分 commit（如 `7d396c5f9cab1f0aa7d16ea25fb06cd59b3df775` 的 gtar 目录遍历）可能涉及未公开 CVE，需对照 NVD 数据库核验是否漏标；devfs jail mount revert 的 `6ad01cde4efac3de004a6e49195f0f42358fc50b` 是罕见的 “撤销 MFC” 操作，反映 6.x 时期 jail 安全策略的迭代式收紧——先在 HEAD 引入 devfs 自动挂载以方便 jail 用户，发现安全隐患后立即在稳定分支撤销；OpenBSM 1.0 alpha 10 的 MFC 时点（2006-09-02）与 TrustedBSD 审计子系统的稳定化时间线需对照 TrustedBSD 项目页面核验；security fix commit 中有 7 条由 Bruce A. ## 101.14.4 架构关联总结——libthr 1:1/GELI/MPSAFE VFS 三大架构收束下的安全基线稳定

  **要点**：6.x 版本周期共 29 条 commit（7 CVE + 22 security fix），月均约 1.07 条/月，显著低于 5.x 的 3.64 条/月（80 条/22 个月）——这一降幅不能简单解读为 “6.x 更安全”，而是反映三重结构因素：其一，5.x 时期 SMPng/GEOM/MAC 三大新架构的安全基线已在 80 条 commit 中建立，6.x 受益于先发投入；其二，6.x 时期 libthr 1:1 取代 KSE M: N 线程模型，消除了 M: N 模型在内核线程调度路径上的复杂竞态面，线程相关安全修复需求随之下降；其三，6.x 时期 GELI 取代 GBDE 作为推荐磁盘加密方案，Colin Percival 提交的 gbde key file 修复 `a5e9d3ad0cdaaa2eb16b52cefe47a865c619bf84` 是 GBDE 维护期的尾声产物，GELI 的更严谨密钥派生模型（PBKDF2 + HMAC-SHA512）降低了后续密钥处理漏洞的暴露面。MPSAFE VFS 收束方面，John Baldwin 在 7.x 时期 `7f307a7ee8bd205f347128834017f3667adcde0b`（2009-03-10，MPSAFE sysctl 标记）的工作可追溯至 6.x 后期的 VFS Giant 锁退出路线，6.x 时期 VFS 路径的安全修复（如 devfs jail revert）需在 MPSAFE 化的语境下理解——devfs 自动挂载被撤销部分原因是 MPSAFE 化尚未完成的过渡期对竞态的容忍度更低。整体看，6.x 的安全响应节奏标志着 FreeBSD 从 5.x 架构转型期的 “高强度安全基线建设” 过渡到 “稳定维护期” 的工程节奏
  
**史料**：freebsd.duckdb freebsd-src 仓库 6.x 版本周期 commit 统计（29 条 security-related commit / 27 个月）；5.x 版本周期 commit 统计（80 条 / 22 个月，月均 3.64）；commit `a5e9d3ad0cdaaa2eb16b52cefe47a865c619bf84`（gbde key file，2006-02-14）；commit `7f307a7ee8bd205f347128834017f3667adcde0b`（7.x MPSAFE sysctl，2009-03-10，用于架构关联对照） ［A］
  
**史观**：总纲第 5 条——没有必然性，只有偶然性：5.x 架构转型的安全代价在 6.x 兑现为稳定红利；总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：libthr/GELI/MPSAFE VFS 三大架构收束的工程投入通过降低安全响应频率得到部分回报；总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：稳定期的安全响应成本分摊不能作为 “安全质量” 的直接指标，需结合架构变化语境
  
**辨析**：5.x 与 6.x 的 commit 月均对比（3.64 vs 1.07）须谨慎解读——5.x 的 80 条中部分为 4.x MFC 回溯（约 30 条），扣除后 5.x 本身新增约 50 条（月均 2.27 条/月），仍高于 6.x 的 1.07，但差距收窄；6.x 的 22 条 security fix commit 中有 7 条为 Bruce A. Mah 的文档维护类 commit（非代码修复），扣除后 6.x 代码级安全修复约 15 条/27 个月 ≈ 0.56 条/月，与 5.x 扣除文档后的 1.91 条/月（约 42 条/22 个月）对比更合理；6.x 时期 OpenBSM 1.0 alpha 10 的 MFC 是 TrustedBSD 审计子系统从研究项目转向生产可用的关键节点，但 alpha 阶段的稳定性需对照 OpenBSM 1.0 正式版（2007-04-28）发布时间核验；GELI 在 6.x 时期作为新引入磁盘加密方案，其本身的安全响应记录（无 CVE）可能与采用率较低有关，需对照 6.x 时期 GELI 部署统计核验
  
**文献**：freebsd.duckdb freebsd-src 仓库 5.x/6.x 版本周期 commit 统计对比；FreeBSD 6.x Release Notes；OpenBSM 项目 Release History；GELI 设计文档（Pawel Jakub Dawidek，BSDCan 2005） ［A］
