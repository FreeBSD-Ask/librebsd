# 100.19 与同时期操作系统的比较：2002-2003 年同期操作系统——Linux 2.4/2.5、Windows XP/2003、NetBSD 1.6、OpenBSD 3.x、Solaris 9——FreeBSD 5.x 的 SMPng 转型坐标

## 100.19.1 Linux 2.4（2001）/ 2.5 开发线（2002-2003）

  **要点**：Linux 2.4（2001.1）是稳定的服务器内核，2.5 开发线（2002-2003）引入 O(1) 调度器、抢占式内核、反向映射 VM 等，演进为 2.6（2003.12）；2002-2003 年 Linux 在内核可扩展性上快速进步，而 FreeBSD 5.x 的 SMPng（细粒度 SMP）仍在整合期，性能与稳定性波动较大，社区出现 “5.x 不如 4.x 快” 的批评。
  
**史料**：Linux 2.4/2.6 发布说明（2001/2003）；2.5 变更日志（O(1) 调度器等）［B］；FreeBSD 5.x 性能讨论邮件列表 ［C］
  
**史观**：总纲第 5 条——没有必然性，只有偶然性：SMP 现代化不存在必然的单一路径——FreeBSD 5.x 的长期阵痛与 Linux 2.5→2.6 的相对平滑，均系各自人力分布与架构债务等偶然条件的产物（原挂“总纲第 25 条——终结与延续”，基线第 25 条为“逻辑是形式主义而非世界本身的结构”，按权威表改挂——2026-09-12 整改）。
  
**辨析**：将 5.x 早期性能问题等同于 “FreeBSD 衰落” 是片面——5.x 的架构债务清理为 6.x/7.x 的性能回升奠定基础；Linux 2.5 同样经历开发期不稳定。
  
**文献**：Torvalds L. Linux 2.6 ChangeLog [EB/OL]. 2003；McKusick M K, Neville-Neil G. The Design and Implementation of the FreeBSD Operating System [M]. Addison-Wesley, 2004. ［B］

## 100.19.2 Windows XP（2001）/ Windows Server 2003

  **要点**：Microsoft Windows XP（2001.10）统一了消费与商业桌面，Windows Server 2003（2003.4）强化了服务器能力；二者基于 NT 内核，拥有成熟的企业支持但与 FreeBSD 5.x 的开源 SMP 路线无直接竞争，主要在 x86 服务器市场占有率上重叠。
  
**史料**：Microsoft Windows XP / Server 2003 发布文档（2001/2003）［A］
  
**史观**：总纲第 8 条——本体论上各方平等：闭源 NT 内核的 “企业支持” 与 FreeBSD 5.x 的 “开源 SMP 现代化” 代表两种服务器 OS 路线，市场重叠但哲学对立，二者在本体论上地位相等、无高下之判（原挂“总纲第 6 条——技术路线分化”，基线第 6 条为“和解优于斗争”，按权威表改挂——2026-09-12 整改）。
  
**辨析**：Windows 与 FreeBSD 5.x 竞争主要在 x86 服务器份额，而非技术路线；FreeBSD 5.x 的 SMPng 主要服务其自有生态而非对标 Windows。
  
**文献**：Microsoft. Windows Server 2003 Technical Reference [Z]. 2003. ［A］

## 100.19.3 NetBSD 1.6（2002）

  **要点**：NetBSD 1.6（2002.9）带来 SMP 改进（如新的锁框架）与广泛的平台支持；与 FreeBSD 5.x 的 SMPng 类似，NetBSD 也在 2002 年前后推进多处理器支持，但 NetBSD 更渐进、更侧重可移植性，未经历 FreeBSD 5.x 式的剧烈架构震荡。
  
**史料**：NetBSD 1.6 发布说明（2002）；NetBSD SMP 文档 ［B］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：NetBSD 与 FreeBSD 同期推进 SMP，是 BSD 分支各自解决同类问题的并行演化，而二者的代码与经验互鉴即聚合面的呈现（原挂“总纲第 7 条——BSD 谱系”，基线第 7 条为“理论必须自反”，按权威表改挂——2026-09-12 整改）。
  
**辨析**：NetBSD 1.6 的 SMP 路径更平稳，并非 “技术更优”——而是优先级不同（可移植性优先、x86 SMP 次之）；FreeBSD 5.x 的激进来源于对多核未来的预判。
  
**文献**：NetBSD Project. NetBSD 1.6 Release Notes [Z]. 2002. ［B］

## 100.19.4 OpenBSD 3.x（2002-2003）

  **要点**：OpenBSD 3.0-3.3（2002-2003）持续强化安全（如 W^X 雏形、特权分离），对 SMP 关注较少，保持单处理器为主的简洁设计；与 FreeBSD 5.x 的 SMP 重心形成对照——OpenBSD 宁可牺牲多核扩展性也要维持安全与简洁。
  
**史料**：OpenBSD 3.x 发布说明（2002-2003）［A］
  
**史观**：总纲第 8 条——本体论上各方平等：OpenBSD 的 “安全/简洁优先” 与 FreeBSD 5.x 的 “可扩展性优先” 是 BSD 家族内部的目标分叉，两种工程优先级在本体论上地位相等（原挂“总纲第 6 条——技术路线分化”，按权威表改挂——2026-09-12 整改）。
  
**辨析**：OpenBSD 在 2002-2003 未全力投入 SMP 并非技术落后，而是工程优先级选择；其单处理器安全模型反而降低了攻击面。
  
**文献**：OpenBSD Project. OpenBSD 3.x Release Notes [Z]. 2002-2003. ［A］

## 100.19.5 Solaris 9（2002）

  **要点**：Sun Solaris 9（2002.5）是成熟的 SMP 企业 UNIX，拥有成熟的线程与扩缩能力；与 FreeBSD 5.x 的 SMPng 目标相似（多处理器扩展）但实现成熟度高得多，代表了商业 UNIX 在 SMP 上的标杆，也反衬出 FreeBSD 5.x 转型期的青涩。
  
**史料**：Sun Solaris 9 发行文档（2002）［A］；Solaris SMP 架构白皮书 ［B］
  
**史观**：总纲第 9 条——经验优先：Solaris 9 的成熟 SMP 是 FreeBSD 5.x 想达成的目标之一；5.x 以开源方式参照商业 UNIX 已验证的 SMP 经验路线演进（原挂“总纲第 25 条——终结与延续”，按权威表改挂——2026-09-12 整改）。
  
**辨析**：Solaris 9 的 SMP 成熟源于数十年投入，FreeBSD 5.x 的青涩源于开源社区的有限资源；二者不可直接比成熟度，应比路线正确性。
  
**文献**：Sun Microsystems. Solaris 9 Documentation [Z]. 2002.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
