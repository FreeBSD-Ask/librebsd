# 100.20 漏洞与安全响应：FreeBSD 5.x 时期的 mksnap_ffs 权限缺陷、OpenSSL DoS、telnet 缓冲区溢出与 SSL 版本回滚漏洞群及 GEOM/MAC 架构关联（2003-2005）

## 100.20.1 **mksnap_ffs(8)** 权限检查缺陷与 FFS 快照机制漏洞（CAN-2004-0099/FreeBSD-SA-04:01.mksnap_ffs）——5.x GEOM/UFS2 架构引入初期的文件系统快照安全基线建立

  **要点**：FreeBSD-SA-04:01.mksnap_ffs（2004-01-30 发布，CAN-2004-0099，公告原文以 CAN 前缀引用——2004 年 CVE 体系已建立但 CAN 前缀仍作为候选编号使用至 2005 年）披露 **mksnap_ffs(8)** 命令在创建 FFS 文件系统快照时存在权限检查缺陷，本地用户可读取快照中其他用户的文件内容；该漏洞直接影响 FreeBSD 5.1 与 5.2，恰好处于 5.0 引入 UFS2 与文件系统快照改进（100.16.2 节所载 UFS2 取代 UFS1 为默认文件系统）之后的版本周期内；mksnap_ffs 漏洞的技术机制是快照创建时未正确验证调用者对被快照文件系统的访问权限，使任意本地用户可对任意挂载点创建快照并通过读取快照设备节点获取其他用户文件内容——这是 FFS 快照机制引入新能力时未同步建立对应权限检查的典型案例，与 5.x 批量引入 GEOM/UFS2/MAC 等新组件但安全基线尚未完善的工程语境相关
  
**史料**：FreeBSD-SA-04:01.mksnap_ffs 公告（<https://www.freebsd.org/security/advisories/FreeBSD-SA-04:01.mksnap_ffs.asc>，2004-01-30 发布）、CAN-2004-0099 NVD 条目、早期漏洞补遗 `原材料/研究/bsd漏洞史/早期漏洞补遗/freebsd-早期漏洞.md` ［A］
  
**史观**：总纲第 22 条——知识注定过时：mksnap_ffs 漏洞是 5.x 批量引入新组件（100.16.5 节所载 “批量引入与渐进退役并行” 特征）的副产品——新能力（FFS 快照）引入时安全基线未同步建立；专题语（不设总纲条号）——软件工程：快照机制的权限检查缺陷反映 5.x 转型期 “功能优先、安全跟进” 的工程节奏
  
**辨析**：CAN-2004-0099 无 CVSS 评分（NVD 未收录评分），无法按 Critical/High/Medium/Low 分类，但因其影响范围为本地任意用户可读取其他用户文件，按现代 CVSS v3.1 估算约对应 Medium 级别（本地权限、低攻击复杂度、机密性影响）；mksnap_ffs 漏洞与 GEOM 框架无直接关联——快照机制位于 UFS2 层而非 GEOM 层，但二者同属 5.0 引入的存储栈改造，安全基线建立节奏一致；【0 信任原则·commit 与 SA 交叉】freebsd.duckdb freebsd-src 仓库 commits 表 2004-01-30 前后未检索到与 mksnap_ffs 直接对应的 commit，可能因修复 commit 的 message_subject 未含 “security fix” 正则匹配关键字，须以 SA 公告所附补丁为准
  
**文献**：FreeBSD-SA-04:01.mksnap_ffs [Z/OL]. 2004-01-30. <https://www.freebsd.org/security/advisories/FreeBSD-SA-04:01.mksnap_ffs.asc>；CAN-2004-0099. NVD [DB/OL]. <https://nvd.nist.gov/vuln/detail/CAN-2004-0099>；原材料/研究/bsd 漏洞史/早期漏洞补遗/freebsd-早期漏洞.md ［A］

## 100.20.5 MAC 框架安全检查修复与 5.x 架构关联——41.5 节所载 MAC 框架引入初期的安全基线补强

  **要点**：FreeBSD 5.0 引入的 MAC 框架（41.5 节〔存疑：旧 41 章节号，现行结构无对应节，重挂待考〕所载 Robert Watson 主导）在 5.x 版本周期内即发现安全检查覆盖不完整问题——2005-05-18 Christian S.J. Peron 提交 MAC check_vnode_mmap 入口点修复（commit `4818dd318bb3f760971f76b1e88c85ec2062d52a`，将 MAC check_vnode_mmap 入口点从 MAP_SHARED 专属扩展至所有 mmap 调用，使入口点覆盖 MAP_PRIVATE 等其他映射类型）；该修复直接关联 5.0 引入 MAC 框架时的设计缺陷——初始实现仅对 MAP_SHARED 映射执行 MAC 策略检查，遗漏 MAP_PRIVATE 映射，使 MAC 策略无法对私有内存映射强制执行访问控制；这一修复发生在 5.x 版本周期末段（2005-05-18，距 5.5-RELEASE 2006.5 约 1 年），反映 MAC 框架引入后安全基线需经实际部署才能完善；同期 2005-03-14 Bruce A. Mah 提交 jail(8) chflags_allowed 与 **ipfw(8)** debug 相关 commit（commit `f667ed26071cc2097d9e39883a4024dfdaf78de3`），反映 MAC/Jails/ipfw 三类安全机制的协同改进
  
**史料**：freebsd.duckdb freebsd-src 仓库 commits 表（4818dd318bb3f760971f76b1e88c85ec2062d52a、f667ed26071cc2097d9e39883a4024dfdaf78de3）；mac(4) 手册页；Watson BSDCon 2001 MAC 演讲 ［A］
  
**史观**：专题语（不设总纲条号）——形式主义膨胀与抽象克制：MAC 框架作为 5.0 引入的抽象层，其安全检查入口点的覆盖完整性需经实际部署验证——这是抽象层引入初期的典型工程代价；专题语（不设总纲条号）——软件工程：MAC 框架的安全基线建立不是一次性完成，而是随实际部署发现缺口逐步补强
  
**辨析**：MAC check_vnode_mmap 修复无 CAN/CVE 编号，但 commit message 明确说明修复目的（"Move MAC check_vnode_mmap entry point out from being exclusive to MAP_SHARED"），按 0 信任原则可采信；【架构关联】MAC 框架作为 5.0 引入的核心安全架构（41.5 节〔存疑：旧 41 章节号，现行结构无对应节，重挂待考〕），其安全检查入口点的覆盖完整性直接影响 MAC 策略模块（如 mac_biba/mac_mls/mac_seeotheruids）的强制能力——check_vnode_mmap 入口点遗漏 MAP_PRIVATE 使策略模块无法对私有映射强制执行机密性/完整性策略，是 MAC 框架引入初期的结构性缺陷；【GEOM 关联】5.x 版本周期内 GEOM 框架（41.3/100.16.1 节〔存疑：41.3 系旧 41 章节号，重挂待考〕所载）本身未发现直接安全漏洞，但 GEOM class 链（如 geli 加密 class）的安全性依赖上层 MAC 框架的访问控制——MAC check_vnode_mmap 修复间接强化了 GEOM 加密设备的访问控制覆盖；【commit 量比较公平性】5.x 版本周期内 MAC 框架相关 security fix commit 仅 1-2 条，反映 MAC 框架引入初期部署范围有限，安全基线完善需更长周期
  
**文献**：Christian S.J. Peron. Move MAC check_vnode_mmap entry point out from being exclusive to MAP_SHARED. freebsd-src [DB/OL]. 2005-05-18. 4818dd318bb3f760971f76b1e88c85ec2062d52a；Robert N. M. Watson（罗伯特·N·M·沃森）. BSDCon 2001 MAC Framework 演讲；mac(4) 手册页 ［A］

## 100.20.6 FreeBSD 5.x 安全响应的架构关联——SMPng/GEOM/MAC 三大新架构的协同安全基线建立

  **要点**：FreeBSD 5.x 版本周期 80 条 security fix commit（月均 3.64 条/月，高于 4.x 的 3.09 条/月）的分布反映三大新架构引入初期的安全基线建立节奏——SMPng 细粒度锁改造（41.2 节〔存疑：旧 41 章节号，现行结构无对应节，重挂待考〕）扩大网络栈并发暴露面，syncookies 与 TCP RST 处理改进（100.20.4 节）是对新暴露面的响应；GEOM 框架（41.3/100.16.1 节〔存疑：41.3 系旧 41 章节号，重挂待考〕）本身未直接发现安全漏洞，但其引入的 FFS 快照机制（UFS2 配套）产生 mksnap_ffs 权限检查缺陷（100.20.1 节）；MAC 框架（41.5 节〔存疑：旧 41 章节号，现行结构无对应节，重挂待考〕）引入初期的 check_vnode_mmap 入口点覆盖不完整（100.20.5 节）反映抽象层安全基线需逐步完善；5.x 时期 OpenSSL vendor branch 同步 + 多分支 MFC 回溯模型（100.20.2 节）的成熟化，为后续 6.x/7.x 时期安全响应工程奠定基础；5.x 版本周期末段 telnet 缓冲区溢出（CAN-2005-0468）与 SSL 版本回滚漏洞（100.20.3 节）的集中爆发，反映 5.x 转型期社区工程资源集中于架构改造而既有网络服务安全债务积累的代价
  
**史料**：freebsd.duckdb freebsd-src 仓库 commits 表 5.x 版本周期查询结果（80 条 security fix commit）；FreeBSD-SA-04:01.mksnap_ffs 公告；CAN-2004-0079、CAN-2005-0468 NVD 条目 ［A］
  
**史观**：总纲第 22 条——知识注定过时：5.x 时期三大新架构（SMPng/GEOM/MAC）的引入是新债务的源头，80 条 security fix commit 是新债务的偿还；专题语（不设总纲条号）——软件工程：5.x 安全响应工程的成熟化（vendor branch 同步 + 多分支 MFC）为后续版本周期奠定基础
  
**辨析**：【0 信任原则·commit 量不等于质量】80 条 commit 中约 30 条涉及 4.x 分支 MFC 回溯，5.x 本身的新增安全修复约 50 条，月均 2.27 条/月低于 4.x 的 3.09 条/月——这一下降可能反映 5.x 转型期社区工程资源集中于 SMPng/GEOM/KSE 等架构改造而非安全响应，但亦可能反映 5.x 用户基数较小（因 5.x 早期不稳定）致漏洞报告数量下降；【架构关联完整性】三大新架构中 SMPng 与 MAC 均有直接安全修复 commit，GEOM 未直接发现安全漏洞但其配套 UFS2 快照机制产生 mksnap_ffs 漏洞——三者安全基线建立节奏不一，反映新架构引入初期的安全基线完善是非同步过程；【CAN/CVE 编号缺位】5.x 版本周期内仅 3 条 CAN 编号（CAN-2004-0099/CAN-2004-0079/CAN-2005-0468），其余 77 条 security fix commit 无 CAN/CVE 编号，按 0 信任原则须以 commit message 与 SA 公告交叉验证
