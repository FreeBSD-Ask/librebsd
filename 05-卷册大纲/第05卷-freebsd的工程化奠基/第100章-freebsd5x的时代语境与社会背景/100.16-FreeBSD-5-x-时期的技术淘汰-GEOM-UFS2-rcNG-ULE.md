# 100.16 FreeBSD 5.x 时期的技术淘汰——GEOM、UFS2、rcNG、ULE 的并行引入与取代

## 99.16.1 GEOM 框架取代旧式 disk 子系统

  **要点**：FreeBSD 5.0-RELEASE（2003 年 1 月 16 日，release/5.0.0 tagger_date = 2003-01-16T16:56:23Z）引入 GEOM（Geometric Modular Disk Framework）框架，由 Poul-Henning Kamp（波尔-亨宁·坎普） 设计实现，取代 4.x 时代分散的 disk 子系统（包括旧式 disklabel、slice、BSD disklabel、Vinum）；GEOM 采用模块化 class 与 provider/consumer 模型，把磁盘 I/O 抽象为可堆叠的 transformation 链——如 gmirror（镜像）、gstripe（条带）、gconcat（连接）、geli（加密）、gbde（块加密）、gjournal（日志）、gpart（分区）等 class 各自提供独立功能；GEOM 取代旧式 disk 子系统的原因是 4.x 时代的 disk 子系统过于分散，难以支持现代存储需求（如软 RAID、加密、多路径）；GEOM 至今仍是 FreeBSD 的标准磁盘抽象层，Vinum 在 FreeBSD 5.0 被移植到 GEOM 之上（gvinum），最终在 FreeBSD 15.0（2025 年 9 月）完全移除
  
**史料**：FreeBSD 5.0-RELEASE Release Notes (2003.1) GEOM 章节、Kamp BSDCon 2002 "GEOM" 演讲、geom(4) 手册页、FreeBSD Handbook "GEOM" 章节；freebsd.db freebsd-src 仓库 tags 表 release/5.0.0 的 tagger_date = 2003-01-16T16:56:23Z（target_commit_hash = 47227ef0ef663b7abb81ab5a60a450da9a93d24b） ［A］
  
**史观**：总纲第 4 条——分离与聚合：GEOM 通过模块化 class 分离存储功能，通过 provider/consumer 链聚合为完整磁盘 I/O 路径；总纲第 17 条——软件工程：GEOM 的可堆叠设计是软件工程对存储子系统模块化的典型实现
  
**辨析**：经 bsd_commits.db tags 表验证，5.0-RELEASE 的 tagger_date 为 2003-01-16（非旧叙事 2003.1.19，误差 3 天，可能为公告日期与 tag 日期差异）；GEOM 是否真正 “取代” 旧 disk 子系统需考据——5.0 引入但 4.x 的 disk 子系统仍保留兼容直至 7.x；GEOM 与 Linux device mapper（2002 年随 2.5 内核引入）的设计差异需对照论文核实
  
**文献**：FreeBSD 5.0-RELEASE Release Notes (2003.1)；Kamp, P.-H. 2002 BSDCon "GEOM—Modular Disk Framework"；geom(4) 手册页；FreeBSD Handbook "GEOM" Chapter；release/5.0.0. freebsd-src 仓库 tag [DB/OL]. 2003-01-16T16:56:23Z. tag: release/5.0.0; commit: 47227ef0ef663b7abb81ab5a60a450da9a93d24b ［A］

## 99.16.2 UFS2 取代 UFS1 成为默认文件系统

  **要点**：FreeBSD 5.0-RELEASE（2003 年 1 月 16 日，release/5.0.0 tagger_date = 2003-01-16T16:56:23Z）引入 UFS2（Second Extended UFS），由 Marshall Kirk McKusick（马歇尔·柯克·麦库西克） 设计实现，取代 UFS1（即 4.2BSD FFS）成为默认文件系统；UFS2 的主要改进包括：原生 64 位块地址（支持大于 1TB 文件系统）、内建 ACL（access control list）支持、内建扩展属性（extended attributes）、文件系统快照（snapshot）改进、动态 inode 分配；UFS1 仍保留兼容支持直至现代 FreeBSD 版本；UFS2 在 FreeBSD 5.0-CURRENT 中于 2003 年 4 月 21 日成为默认创建类型，自 5.1-RELEASE（2003 年 6 月 9 日）正式作为安装默认；UFS2 的设计吸取了 LFS（日志结构文件系统）与 NTFS 的部分思想，但延续 FFS 的柱面组模型而非完全重写
  
**史料**：FreeBSD 5.0-RELEASE Release Notes (2003.1) UFS2 章节、McKusick 2003 BSDCon "UFS2" 演讲、FreeBSD 5.1-RELEASE Release Notes (2003.6) UFS2 默认条目、McKusick et al. 2004 "The Design and Implementation of the FreeBSD Operating System" 第 8 章；bsd_commits.db freebsd-src 仓库 tags 表 release/5.0.0 的 tagger_date = 2003-01-16T16:56:23Z ［A］
  
**史观**：总纲第 25 条——终结中的延续：UFS2 取代 UFS1 但延续 FFS 设计哲学，体现 “演化而非革命”；总纲第 17 条——软件工程：UFS2 的 64 位扩展是软件工程对 2000 年代存储容量增长的响应
  
**辨析**：经 bsd_commits.db tags 表验证，5.0-RELEASE 的 tagger_date 为 2003-01-16（非旧叙事 2003.1.19）；UFS2 是否真正 “取代” UFS1 需考据——UFS1 仍保留兼容支持，“取代” 应理解为 “成为默认”；UFS2 与同期 ext3（2001 年 Linux）、ReiserFS（2001）的对比存在学术争议
  
**文献**：FreeBSD 5.0-RELEASE Release Notes (2003.1)；McKusick, M. K. 2003 BSDCon "UFS2"；McKusick, M. K. & Neville-Neil, G. ## 99.16.3 rcNG（rc.d）取代旧式 rc 脚本

  **要点**：FreeBSD 5.0-RELEASE（2003 年 1 月 16 日，release/5.0.0 tagger_date = 2003-01-16T16:56:23Z）默认采用 rcNG（Next Generation rc，即 rc.d 系统），取代 4.x 时代的单文件 /etc/rc 启动脚本；rcNG 由 Mike Makonnen 等设计实现，采用 rcNG 风格的 rc.d/ 目录脚本，每个服务一个独立脚本（如 /usr/local/etc/rc.d/apache.sh），通过 **rcorder(8)** 解析依赖关系，支持并行启动、依赖管理、PROVIDE/REQUIRE/BEFORE 关键字；rcNG 在 FreeBSD 5.0 成为默认，4.x 仍使用旧 rc 直至 4.11（2004 年）；NetBSD 1.5（2000 年 12 月）已先于 FreeBSD 引入类似 rc.d 系统，FreeBSD rcNG 设计借鉴 NetBSD 但增加 /etc/rc.conf.d/ 模块化配置；rcNG 至今仍是 FreeBSD 标准启动系统，与 systemd（Linux 2010 年起）路径形成对照
  
**史料**：FreeBSD 5.0-RELEASE Release Notes (2003.1) rcNG 章节、Makonnen 2002 "rcNG Design" 邮件列表文档、rc(8) 与 rcorder(8) 手册页、NetBSD 1.5-RELEASE Release Notes (2000.12) rc.d 章节；bsd_commits.db freebsd-src 仓库 tags 表 release/5.0.0 的 tagger_date = 2003-01-16T16:56:23Z ［A］
  
**史观**：总纲第 4 条——分离与聚合：rcNG 把单文件 rc 分离为独立服务脚本，通过 rcorder 聚合为依赖有序的启动序列；总纲第 17 条——软件工程：rc.d 系统是软件工程对启动管理的模块化设计
  
**辨析**：经 bsd_commits.db tags 表验证，5.0-RELEASE 的 tagger_date 为 2003-01-16（非旧叙事 2003.1.19，误差 3 天，可能为公告日期与 tag 日期差异）；rcNG 与 NetBSD rc.d 的关系需辨析——FreeBSD 借鉴 NetBSD 但实现不同；rcNG 与 systemd 的对比存在工程争议——前者简洁但功能有限，后者复杂但功能强大；rcNG 与 systemd 的哲学分野参见 BSD init 发展史相关章节
  
**文献**：FreeBSD 5.0-RELEASE Release Notes (2003.1)；rc(8) 手册页；rcorder(8) 手册页；NetBSD 1.5-RELEASE Release Notes (2000.12)；release/5.0.0. freebsd-src 仓库 tag [DB/OL]. 2003-01-16T16:56:23Z. tag: release/5.0.0; commit: 47227ef0ef663b7abb81ab5a60a450da9a93d24b ［A］

## 99.16.5 FreeBSD 5.x 时期淘汰史的辨析

  **要点**：FreeBSD 5.x 时期的技术淘汰具有 “批量引入与渐进退役并行” 的特征——5.0 同时引入 GEOM、UFS2、rcNG、KSE、MAC 等多项新组件，但 4BSD 调度器、UFS1、旧 rc、Giant Lock 等老组件的退役持续至 7.x/8.x；这一批量引入模式使 5.x 用户面临巨大兼容性挑战，是 5.x 早期不稳定的根源之一；需警惕将 5.x 叙事为 “现代 FreeBSD 起点” 的回溯性建构——彼时 5.x 的多项创新（KSE M: N 模型）后续被证明失败
  
**史料**：FreeBSD 5.x Release Notes、freebsd-stable 与 freebsd-current 邮件列表 2003-2006 年讨论、FreeBSD Project Status Reports 2003-2006 ［A］
  
**史观**：总纲第 25 条——终结中的延续：5.x 批量引入的新组件中部分延续（GEOM、UFS2、rcNG），部分失败（KSE）；总纲第 3 条——形式主义膨胀：5.x 的批量引入部分源于 “研究优先” 的形式主义，忽视生产稳定性
  
**辨析**：5.x 是否真正 “成功” 在史料中评价不一——技术上引入多项创新但 4.x 用户长期抗拒；KSE M: N 模型的失败是否归因于设计缺陷还是工程实施不足需辨析
  
**文献**：FreeBSD 5.x Release Notes；freebsd-hackers 邮件列表 2003-2006 存档；FreeBSD Project Status Reports 2003-2006 ［A］
