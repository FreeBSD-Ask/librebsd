## 94.3.1 OS 级虚拟化的概念起源

  **要点**：OS 级虚拟化概念（多实例共享内核）可追溯至 1979 年 chroot，但 Jails（2000）首次实现生产级安全隔离，Solaris Zones（2004）、OpenVZ（2005）、LXC（2008）、Docker（2013）均晚于 Jails

  **要点**：Jails（2000）比 Docker（2013）早 13 年，比 Solaris Zones（2004）早 4 年，比 LXC（2008）早 8 年；但 Docker 的镜像与编排生态使其市场认可远超 Jails

**要点**：

- iocage 的演化路径是一份典型的个人工具史：作者约 2009 至 2010 年间在 FreeBSD 上初用 ZFS 时，先写 Python 核心脚本自用，开源到 SourceForge 后因社区对语言选型的抱怨，于 2014 年前后用 shell 整体重写——理由朴素而关键：shell 在 base 系统中，脚本可直接投放运行。命名上刻意避开当时“某某 jail”式 Manager 的命名惯性，以示新工具的独立身份，并从 SourceForge 迁往 GitHub，随即获得核心贡献者的密集反馈与大量提交请求，工程方向在社群推动下快速收敛。（BSD Now EP102，[1556.66-1685.02]，L1）
- iocage 最具辨识度的设计是把 jail 的全部配置存为 ZFS 数据集的用户属性：没有独立配置文件，运行 iocage 即可枚举并重建全部 jail 状态；跨机迁移时配置随 send/receive 原子复制。同时可在 jail 内部委托 ZFS 快照、克隆与新建数据集的权限，外部以配额、预留等资源约束兜底，实现把管理能力下放而不危及宿主的分层治理。作者还刻意模仿 ZFS 命令行语法（自定义字段列表、排序、剥离表头、制表符输出），视其为面向系统管理员的接口设计范本。（BSD Now EP102，[1806.06-1977.48]，L1）
- 面对 2015 年 Docker 带动的容器化热潮，访谈给出 FreeBSD 的清点式回应：jail、VNet 独立网络栈、rctl 资源控制等构件均已存在，缺的只是粘合层与镜像分发体验。作者列出路线图——跨节点透明 send/receive、镜像化部署、REST API，并计划整合 beehive 类虚拟机管理与 UCL 配置互导。主持人当场构想把 ZFS 镜像压缩后置于网络，用户以 curl 接 zfs receive 的方式替代常见的 curl 接 bash 脚本安装，浓缩了 BSD 阵营当时的容器想象：安全边界早已备好，缺的是封装与易用性。（BSD Now EP102，[2086.96-2216.32]，L1）
- sysjail 2.0 是对其基于 systrace 的轻量级虚拟化系统的完全重写，面向 OpenBSD 与 NetBSD，原生支持 Compat Linux 与 Compat FreeBSD；借助二进制接口兼容而非在 Xen 实例中启动整个内核，可在 SSH 登录下把 BSD 主机呈现为完整的 Fedora 式 Linux 环境，并遵循 FreeBSD jail 的约定。（BSDTalk EP128，[123.83-159.75]，L1）
- Robert Watson 的论文与演讲揭示系统调用包装器这一整类技术（systrace、ptrace 及一切拦截系统调用的机制）的潜在漏洞：UNIX 模型中子进程可修改父进程内存，恶意进程可在受检前 fork 并保存进程信息副本，再由子进程以原始信息重装父进程，绕过已被 systrace 设备放行的检查；后果轻则拒绝服务，重则任意系统调用得逞。Watson 早在 2006 年米兰 EuroBSDCon 即当面警告过其理论性。（BSDTalk EP128，[173.15-496.88]，L2）
- 短期修复方案由 systrace 原作者建议的 look-aside buffer 构成：将进程信息保存进 systrace 设备或内核空间，fork 发生时弃用保存副本而保留经设备核准的原始信息；Kristaps 与 Dexter 希望在当周 EuroBSDCon 前做出原型，并需为此剥离 systrace 诸多未暴露于前端的冷门功能。（BSDTalk EP128，[499.83-576.39]，L1）
- 长期方向为重写内核上半部并自始为多重性设计：取消 root 与全局网络实例概念，使对系统的访问总是表现为另一个实例，而非在一个全局实例下伪造众多实例；该提案获里加大学与 KTH 斯德哥尔摩的积极回应，尚处规划阶段、未选定工作内核，Dexter 希望保持与源内核下半部的同步而不倾向 fork。（BSDTalk EP128，[778.64-884.08]，L1）
- Dexter 断言几乎一切虚拟化系统（FreeBSD jail、sysjail、Xen、VMware、Parallels、自建 chroot jail、Linux vServer）都是 hack，是让单机呈现多系统外观的笨拙手段；多重性难题随硬件廉价化循环重演——多用户、多磁盘与 RAID、多显示器、SMP 依次成为挑战，DragonFly 项目即为解决 SMP 问题而分叉，且极少有议题被彻底解决。（BSDTalk EP128，[605.27-733.79]，L1）[订正：原 Solaris Zones，2026-09-29 SenseAudio 重转核对]
- Dzonsons 在瑞典皇家理工学院与拉脱维亚大学合作框架下主持 MULT 研究，主张大量应用场景只需要与宿主同构的 POSIX 环境而非完整内核虚拟化，故将系统定位为单内核上同时运行成千上万个可精细配置、互不可见的操作实例，与 Xen、QEMU 及即将出现的 DragonFly BSD vkernel 等运行整个内核的重量级方案划清界限；系统不使用 VT-x/AMD-V 等处理器虚拟化扩展，且可与 NetBSD 的 Xen 支持叠加组合（Xen 客户机内再跑 MULT 实例），仅触及内核上半部因而宣称平台无关。（BSDTalk EP140，[187.94-223.30]，L1）
- 对 FreeBSD jail 的核心批评是：jail 名副其实地“监禁”一组进程，防护在执行时于内核边界施加，外部可见 jail 内部而 jail 看不见外部；进程表在内核中仍是全局单份，跨 jail 不允许重复进程号，资源隔离只在功能性层面而非结构层面成立。MULT 的应对是把进程表、挂载表、SysV IPC、网络接口等内核全局结构逐一收集为实例私有结构（其称逻辑隔离），故各实例可运行完整 init 树、进程号可跨实例重复，ps 只见本实例进程而以 instps 工具旁观他者；自述已实测启动逾十万实例，计划月底发布面向大规模启停的开发版。（BSDTalk EP140，[231.42-341.00]，L1）
- 资源划分按三阶段推进：先内部软资源（进程表、文件描述符、kqueue 与 knotes、SysV IPC，大半完成），再伪设备等“软硬件”（PTY、klog 等），最后硬件设备拟采两阶段方案——先以类似 Linux udev 的机制连贯命名设备，再由管理员经访问模块决定实例可得哪些设备并配 DevFS；自认网络与终端是最难啃的部分，硬盘按主从节点分配已可行。对虚拟主机与集群计算两种场景，他承认无实测数据、仅属推测：前者实例长期常驻、重在按需实时调配资源，后者重在秒级启停即弃、实例整体迁移与可迁移文件系统，未来拟支持 PUFFS 用户态文件系统、NFS 根文件系统，并指出 DNS 难以应对亚秒级的地址轮换。 [存疑脚注] 双场景运行时差异系当事人自认的推测（原话自陈无硬性测量支撑），迁移与 PUFFS/NFS 支持属规划而非已实现（BSDTalk EP140，[592.50-741.02]，L1）
- PC-BSD 8将PBI浏览器整合进软件与更新工具：在统一界面内浏览、排队下载、安装、更新与移除软件（以Amarok为例），无须再赴PBI Dir网站手动下载；PBI构建服务器自动由ports树构建PBI并定期更新；Kris Moore为PBI工具添加挂钩使其可被调用，该工具于2010年2月前后随8系列beta推出。（BSDTalk EP185，[119.76-191.74]，L1）
- Life Preserver是rsync的图形前端，支持整机（非仅用户主目录）向本地或远程备份与还原；配合PC-BSD 8的DVD安装器，可从Life Preserver备份直接安装复原整个系统，当事人称此为可供宣传的完整回滚路径。（BSDTalk EP185，[191.74-238.46]，L1）
- Port Jail针对“用户构建port时依赖连锁可能毁坏系统”的老问题：将ports树置于jail内任意安装构建，替代以往dual local bases的权宜做法；X应用与声音须额外配置方能工作，当事人以Sauerbraten在jail内运行验证可行，视为困扰已久的构建隔离问题的解法。（BSDTalk EP185，[261.66-301.38]，L1）
- PC-BSD 8令64位桌面首次实用化：64位NVIDIA驱动到位，经修整32位库后32位Wine PBI可运行于64位系统，当事人随即安装Steam并以Assassin's Creed验证（Dragon Age图形仍有瑕疵），并断言以缺乏Wine或3D为由否认BSD有64位桌面的批评不再成立。（BSDTalk EP185，[313.50-394.14]，L1）

- 本期一手口述史料包括：当事人iXsystems网站管理员兼PC-BSD committer身份、其在用户组讲解PC-BSD 8三件新工具（新软件与更新工具、Life Preserver、Port Jail）的演讲、iXsystems赞助KDE Camp及Kris Moore的PC-BSD桌面演讲、owncloud.org数据主权运动的主题演讲内容、以及Dru Lavigne当时正在撰写的PC-BSD著作。（BSDTalk EP185，[45.64-301.38]，L1）

**史观**：

- 总纲4 分离聚合是永恒规律：iocage 本身是分离聚合节律的一个切片：ZFS 数据集、VNet 独立协议栈、rctl 资源控制各自作为独立构件先后成熟，聚合为单一管理界面的时机并非工程必然，而系作者自用场景与社区反馈在偶然时刻的汇合。作者自陈距 VNet 加虚拟机组合生产可用只差约 5%，而这 5% 的缺口正等待更多使用者以 bug 报告的形式回流；构件的再聚合与再分离（计划中的 IOHive、UCL 互导）使工具史呈循环流转而非单向进步。（BSD Now EP102，[1797.06-2080.48]，L1）
- 总纲9 经验优先：Peter Toth 从 Linux 拥护者转投 FreeBSD 的自述把技术迁徙归于身体经验而非抽象论证：室友一句“很多人说 FreeBSD 更好”激起怀疑，数日盘桓后他选择读官方文档自验，被其条理性与用户态设计的逻辑性说服，最终把全部机器重装为 FreeBSD。验证先于信服，一手经验优先于任何现成的优劣叙事；这一从怀疑到亲验再到转向的次序，恰是技术史中个体选择机制的真实样本。（BSD Now EP102，[1443.86-1537.74]，L1）
- 总纲4 分离聚合是永恒规律：多重性议题（多用户、多磁盘、多显示器、多核 SMP、多实例）随硬件成本下降而循环重演且从未被彻底解决，虚拟化即让单一系统分离出多系统外观再聚合为多实例的技术形态，印证分离聚合的循环结构而非线性进步。（BSDTalk EP128，[654.15-733.79]，L1）
- 总纲13 法律与道德是利益分配：许可证是利益分配的形式化装置而非人性改造工具：Dexter 以“许可证不改变人性”“路由器厂商被要求也不会交出 GPL 代码”而 BSD 用户无强制条款仍自愿回馈为据，主张简明协议优于复杂法律构造，法律设计的正当性在于可理解与可辩护而非道德强制。（BSDTalk EP128，[1209.31-1244.14]，L1）
- 总纲21 革命与改革是历史方法论的分歧：GPL 的 copyleft 强制路径与 BSD 的自愿回馈路径构成许可证方法论的根本分歧；Dexter 预言 GPLv3 的专利条款与复杂性将引发诉讼乱局，反而反衬 BSD 式简明协议的优势，这是以对手的激进改革为参照系确认自身演化路线的历史判断。 [存疑脚注] GPLv3 将成为 BSD 二十年来最好的事系 Dexter 个人预言，属单一来源推断，2007 年时点无法验证（BSDTalk EP128，[1100.96-1191.35]，L4）
- 总纲8 本体论上各方平等：长期提案取消 root 与全局网络实例，让一切系统访问都以平权实例的形态存在，而非全局特权之下伪造的从属实例——这在本体论层面消解了全局与局部实例的等级差序。（BSDTalk EP128，[813.39-833.27]，L1）
- 总纲5 没有必然性，只有偶然性：基座选 NetBSD 而弃 Linux，理由是上手速度与个人代码品味而非任何工程必然性；MULT 本身则自承是 sysjail 在 systrace 缺陷下受挫的衍生物——技术路线由个人经验约束与先前项目的偶然挫败共同塑形，而非被某种历史规律决定。（BSDTalk EP140，[396.94-469.02]，L1）
- 总纲10 动手者创造历史：全部内核上半部全局结构的实例化由当事人一人重写、一人自测十万实例，并以招募测试者、招揽硕士生写论文的方式扩产，呈现的是动手者以原型先行、以自用代论证的工程书写，而非机构化研发叙事。（BSDTalk EP140，[826.54-909.56]，L1）
- 总纲15 文化即形式主义：KDE Camp与会者对PC-BSD的接受度以一句“唯一的问题是我的朋友们不用它”作结，当事人亦观察到KDE社区以Linux为中心、甚至谈及Windows而绝口不提BSD；桌面操作系统的采用在此呈现为由同伴网络与社区惯例等文化形式所支配，而非单纯技术优劣的权衡。（BSDTalk EP185，[735.74-768.18]，L1）
- 总纲3 不存在进步，只有权力再分配：当事人转述的owncloud运动被表述为“夺回信息的控制权”——将 Gmail、Google 文档等由平台托管的数据收回自有服务器；这一诉求实为对Web 2.0平台权力集中的再分配要求，与开放桌面规范（Attica）整合个人数据流的设想同属一脉。（BSDTalk EP185，[658.14-697.46]，L2）

**辨析**：

- 同期两则安全公告呈现两种弃用节奏：OpenSSH 7.0 一次性将 SSH 协议 1、1024 位 DH group1、v00 证书格式移出默认，root 登录语法改为 prohibit-password 且仅允许密钥登录，但旧语法 without-password 仍被接受，以免升级后锁死管理员——先禁后删、留兼容回退；LibreSSL 则随 OpenBSD 5.8 周期逐项清除 SSLv3 支持与 IE6 兼容 workaround，默认 DH 参数升至 2048 位，并吸收 Coverity 扫描发现的大批死代码、内存泄漏与逻辑错误修复。主持人把 OpenSSH 的动机概括为“不想让 SSH 成为下一个 SSL”（1111.64-1115.96）。两者一为一次性重设默认值、一为随周期逐项清除，构成 2015 年遗留特性治理的两条路径。 [存疑脚注] 转写把 OpenBSD 5.8 开发周期与库版本号混书（LibreSSL 当时实际为 2.2.x 系），Coverity 系失真拼写，具体修复清单须以 OpenSSH 7.0 与 LibreSSL 官方公告复核。（BSD Now EP102，[1091.52-1163.26]，L2）
- Dexter 声称 systrace 不存在远程漏洞，前提是攻击者已能在本机写入并执行自己的二进制与进程，并把暴露程度留给运维者自行判断；此为受影响项目维护者的单方风险评估，未经独立第三方复核。 [存疑脚注] 当事人自评的风险边界判断，无外部验证（BSDTalk EP128，[268.59-315.55]，L4）
- 转写存在双声道交错与重复（repetition_detected），人名多有讹写：Neal's provost 应为 systrace 原作者 Niels Provos，Kristaps 未含姓氏（sysjail 作者为 Kristaps Dzonsons），CISCATOES 为 syscalls、colonel 为 kernel 之类转写讹误需按领域通行拼写还原。 [存疑脚注] 专名经转写讹误校正，校正依据为领域通行拼写而非录音原文（BSDTalk EP128，[43.52-513.71]，L4）
- sysjail 的安全失效被归因于 systrace 的固有缺陷（自 OpenBSD 4.1 时代起），故其仅可作受控 chroot 式软件测试环境而不可作安全边界；当事人并称 MULT 正源于“容器应当整洁优雅”这一理念在 sysjail 上的失败教训。此为单方陈述，systrace 缺陷的技术细节与 OpenBSD 侧的处置史须与他源核证。（BSDTalk EP140，[1441.64-1593.28]，L1）
