# 94.1 2000 年 phk

## 94.1.1 phk 与 Jails 的诞生

  **要点**：Poul-Henning Kamp（波尔-亨宁·坎普）(phk) 于 1999 年 4 月 28 日在 FreeBSD 4.0-CURRENT 开发周期内提交 Jails 初始实现（早于 4.0-RELEASE 2000.3.20 约 11 个月），起源是为一家托管客户提供安全隔离环境，发现 chroot 不够用，遂在一天下午写了 **jail(2)** 系统调用；Jails 随 4.0-RELEASE 2000.3.20 正式发布；Jails 比 Docker 早 13 年

  phk 在提交完整实现时的 commit message：

  > This Implements the mumbled about ‘Jail’ feature.
  >
  > ——Poul-Henning Kamp, commit `75c13541908625d7ee0894cc03f96ab773f7dae2`, 1999-04-28T11:38:52Z

**史料**：phk 的 Jails commit、jail(2) 手册页、phk 在 BSDCon 2000 的 Jails 演讲、freebsd-hackers 2000.3 邮件；freebsd.duckdb freebsd-src 仓库 commits 表 jail 首次 commit 为 1999-04-28T11:28:49Z Poul-Henning Kamp（commit 02daf150a4434305b9181b0ac9150762afb4c8ce，subject = “Add the jail system call.”），同日 11:38:52 提交完整实现（commit 75c13541908625d7ee0894cc03f96ab773f7dae2，subject = “This Implements the mumbled about ‘Jail’ feature.”），sys/sys/jail.h 与 sys/kern/kern_jail.c 同日首次引入 ［A］
  
**史观**：总纲第 1 条——偶然性改写历史，phk 因托管客户需求偶然发明 Jails
  
**辨析**：经 freebsd.duckdb commits 表与 commit_files 表交叉验证，Jails 的确切诞生日为 1999-04-28（commit 02daf150a4434305b9181b0ac9150762afb4c8ce），旧叙事 “2000.3.14 与 2000.3 两种说法” 均不准确，2000.3.20 为 4.0-RELEASE 发布日期而非 Jails commit 日期，存疑已解决；经邮件列表库验证通过（fact-check 2026-08-14），freebsd-current 1999-01-29 已有《Re: “JAIL” code headed for -current.》讨论（Sean Eric Fagan 转引 phk 于 1999-01-27 的说明），phk 本人 1999-03-26 再回复同主题，佐证 jail 代码在 1999 年初即进入 -current 讨论与合并流程，与 commit 1999-04-28 的时间线一致
  
**文献**：Kamp “Jails: Confining the Omnipotent Root”(BSDCon 2000)；jail(2) 手册页；phk 个人网站；Poul-Henning Kamp. Add the jail system call. freebsd-src [DB/OL]. 1999-04-28T11:28:49Z. 02daf150a4434305b9181b0ac9150762afb4c8ce ［A］

## 94.1.2 2000 年的工程语境

  **要点**：2000 年互联网泡沫期 ISP 托管需求激增，共享主机需要安全隔离，chroot 仅隔离文件系统不隔离网络与进程，phk 的托管客户需要 “每个客户独立 IP 与进程视图”，催生 Jails
  
**史料**：phk 的 BSDCon 演讲、freebsd-isp 邮件列表托管需求讨论、2000 年 ISP 托管市场报告 ［A］
  
**史观**：总纲第 9 条——企业研究双重性，Jails 源于企业托管需求
  
**辨析**：托管客户的具体身份 phk 未公开，需查 BSDCon 演讲
  
**文献**：Kamp BSDCon 演讲；freebsd-isp 邮件列表；ISP 托管市场报告 ［A］

## 94.1.3 Jails 的设计动机

  **要点**：phk 的设计动机是 “让 root 不那么全能”，通过 **jail(2)** 限制 root 权限 (如禁止修改网络配置、禁止加载内核模块)，使 jailed 进程即使被攻破也无法影响主机
  
**史料**：jail(2) 手册页、phk 的 BSDCon 论文、sys/kern/kern_jail.c 注释 ［A］
  
**史观**：总纲第 2 条——实践先于理论，Jails 源于 “chroot 不够用” 的实践痛点
  
**辨析**：Jails 的安全模型是否 “完全” 安全存在争议，后续发现多个逃逸漏洞
  
**文献**：jail(2) 手册页；Kamp 论文；安全审计报告 ［A］
