# 117.8.2 版本控制选择比较

  **要点**：选择比较维度：(1) 分布式（Git/Mercurial）vs 集中式（SVN/CVS）；(2) 性能（SVN 全局版本号 vs Git 对象数据库）；(3) 工具链生态（cvs2svn 成熟度）；(4) 学习曲线；FreeBSD 选择 SVN 的核心理由是迁移成本低、与 CVS 心智模型相近
  
**史料**：freebsd-hackers 邮件（2000-2008）、cvs2svn 文档、SVN vs Git 性能基准（2007） ［A］
  
**史观**：专题语（不设条号）：SVN 比 CVS 复杂但比 Git 简单——复杂度的中间路线是工程务实取舍（原“第 9 条——简洁与复杂的辩证”与基线第 9 条“经验优先”不符，按 R2140 先例——批次 C163 问题 2）
  
**辨析**：迁移成本应优先于技术先进性是工程务实的选择——FreeBSD 选择 SVN 的核心理由是与 CVS 心智模型相近、迁移成本低、cvs2svn 工具成熟；若 2008 年选 Git，社区须重新学习分布式工作流，迁移成本高于 SVN；但 2019 年再迁 Git 证明 Git 的技术先进性最终成为不可忽视的因素
  
**文献**：SVN 书《Version Control with Subversion》；Pro Git（Scott Chacon） ［A］
