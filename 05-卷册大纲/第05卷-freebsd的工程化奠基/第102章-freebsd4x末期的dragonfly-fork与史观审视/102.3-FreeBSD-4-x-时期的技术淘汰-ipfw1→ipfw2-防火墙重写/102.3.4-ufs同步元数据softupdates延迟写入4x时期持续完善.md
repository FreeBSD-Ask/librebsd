# 102.3.4 UFS 同步元数据 → Soft Updates 延迟写入（4.x 时期持续完善）

  **要点**：传统 UFS（Unix File System）使用同步写入保证元数据一致性——创建文件时需同步写入 inode 与目录项，文件系统操作以磁盘速度而非处理器速度进行；Marshall Kirk McKusick（马歇尔·柯克·麦库西克） 与 Greg Ganger、Yale N. Patt〔原作 Craig Patt 疑误，通行署名为 Greg Ganger 与 Yale N. Patt（CMU-CS-94-221），待复核〕 等设计的 Soft Updates 于 1998 年 3 月在 FreeBSD 3.0-CURRENT 时期合入主干（3.0-RELEASE 1998.10.16 已含），4.x 时期（2000-2003）持续完善；Soft Updates 使用延迟写入（write-back caching）记录元数据更新依赖，回写时按依赖顺序执行，确保崩溃后文件系统一致性；Soft Updates 通过 per-pointer 依赖跟踪避免块级循环依赖，块可按任意顺序写入，仍依赖的更新在写前回滚、写后回放；4.x 时期 Soft Updates 与同期商业 UNIX 的 journaling 文件系统（如 Solaris UFS logging、IBM JFS、SGI XFS）形成对比——Soft Updates 不需要日志但提供类似一致性保证
