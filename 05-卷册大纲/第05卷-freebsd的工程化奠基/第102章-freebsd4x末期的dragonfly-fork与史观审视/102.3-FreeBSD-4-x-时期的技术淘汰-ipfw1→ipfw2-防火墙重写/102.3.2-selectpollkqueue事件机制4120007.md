# 102.3.2 select/poll → kqueue 事件机制（4.1，2000.7）

  **要点**：传统 UNIX **select(2)** 与 **poll(2)** 系统调用使用线性扫描文件描述符表，性能随描述符数量增长而下降，无法高效处理数千并发连接（C10k 问题）；FreeBSD 4.1-RELEASE（2000.7.26）引入 **kqueue(2)** 与 **kevent(2)** 系统调用，由 Jonathan Lemon 设计；kqueue 首次 commit 于 2000 年 4 月 16 日（4.0-RELEASE 2000.3.20 之后，4.1-RELEASE 2000.7.26 之前），属 4.1-CURRENT 开发周期内合入；kqueue 使用内核事件表，应用程序注册感兴趣的事件类型（读、写、信号、定时器、子进程状态等），内核仅在事件发生时通知应用程序；kqueue 设计支持 O(1) 事件查询，可处理数万并发连接；kqueue 后续移植到 NetBSD（1.6）、OpenBSD（2001-03-01 完成移植，对应 OpenBSD 3.0 于 2001-12 首发〔原作 3.7 系版本错置，经 openbsd.duckdb 实查订正〕）、macOS（10.3 Panther）；kqueue 是 FreeBSD 4.x 时期对 UNIX 事件机制最持久的贡献，影响后续 Linux epoll（2002.10 Linux 2.6）与 Solaris /dev/poll 的设计
  
**史料**：FreeBSD 4.1-RELEASE Release Notes；Jonathan Lemon “Kqueue: A Generic and Scalable Event Notification Facility”（USENIX BSDCon 2000 论文）；Jonathan Lemon 在 freebsd-arch 邮件列表 2000 年关于 kqueue 设计的讨论；man **kqueue(2)** 历次版本；freebsd.duckdb freebsd-src 仓库 commits 表 kqueue 首次 commit 为 2000-04-16T18:53:38Z Jonathan Lemon（commit cb679c385ef325d11f162e09b604df7532fc8009，subject = "Introduce kqueue() and kevent(), a kernel event notification facility"），**sys/sys/event.h** 同日首次引入（commit 3ee12e4fe3c884db74bc236f6f76dfb7539eb0d1） ［A］
  
**史观**：总纲第 10 条——动手者创造历史（原“边缘者贡献”系伪名目，按权威表正名）：Jonathan Lemon 作为相对边缘的贡献者，kqueue 设计影响后续多个 BSD 项目与商业 OS；专题语（不设总纲条号）——形式与内容（原挂总纲第 17 条系自创名目，删条号）：kqueue 作为 “形式”（事件通知接口）改变 “内容”（高并发服务器架构）
  
**辨析**：经 freebsd.duckdb commits 表验证，kqueue 首次 commit 为 2000-04-16（4.0-RELEASE 2000.3.20 之后，4.1-RELEASE 2000.7.26 之前），属 4.1 开发周期内合入主干，故 “4.1 引入” 与 “4.1-RELEASE 合入” 两种叙事均正确，存疑已解决；kqueue 与 Linux epoll 的设计差异需对照源码核验（kqueue 支持多种事件类型，epoll 早期仅支持文件描述符）；kqueue 在 FreeBSD 4.x 时期的实际采用率缺乏权威统计
