# 95.1 Jonathan Lemon 设计 kqueue/kevent

## 95.1.1 Lemon 的设计动机

  **要点**：Jonathan Lemon 在 2000 年向 freebsd-hackers 提交 kqueue 提案，动机是 **select(2)**/**poll(2)** 在高并发连接下的 O(N) 扫描成本与状态丢失，无法支撑 Yahoo!/Hotmail 级别的事件驱动服务器；kqueue 首次 commit 于 2000 年 4 月 16 日（4.0-RELEASE 2000.3.20 之后，4.1-RELEASE 2000.7.26 之前）
  
**史料**：Lemon 的 freebsd-hackers 2000.7 邮件 “kqueue - kernel event notification”、kqueue(2) 手册页原始版本；freebsd.duckdb freebsd-src 仓库 commits 表 kqueue 首次 commit 为 2000-04-16T18:53:38Z Jonathan Lemon（commit cb679c385ef325d11f162e09b604df7532fc8009，subject = "Introduce kqueue() and kevent(), a kernel event notification facility."），sys/sys/event.h 同日 19:02:08 首次引入（commit 3ee12e4fe3c884db74bc236f6f76dfb7539eb0d1） ［A］
  
**史观**：实践先于理论，select/poll 的工程瓶颈催生 kqueue 设计而非理论驱动
  
**辨析**：经 freebsd.duckdb commits 表验证，kqueue 首次 commit 为 2000-04-16（非旧叙事 2000.7.5），属 4.1-CURRENT 开发周期内合入主干，4.1-RELEASE 2000.7.26 正式发布；经邮件列表库验证通过（fact-check 2026-08-14），Jonathan Lemon 2000-06-22《Re: tail after kqueue changes》（freebsd-current，Message-ID `<no-id-freebsd-current-798100dde2fde2f6>`）与 2000-10-25《Re: kqueue microbenchmark results》（freebsd-hackers，署名 <jlemon@flugsvamp.com>）两条一手邮件佐证 Lemon 于 2000 年作为 kqueue 作者的活跃期，与 commit 时间线一致；Lemon 的雇主关系存在争议，部分来源称其受 Yahoo! 工作驱动，需查 commit metadata 与邮件签名确认
  
**文献**：Lemon “Kqueue: A Generic and Scalable Event Notification Facility”(USENIX BSDCon 2000)；kqueue(2) 手册页；Jonathan Lemon. Introduce kqueue() and kevent(), a kernel event notification facility. freebsd-src [DB/OL]. 2000-04-16T18:53:38Z. cb679c385ef325d11f162e09b604df7532fc8009 ［A］

## 95.1.2 kevent 的系统调用设计

  **要点**：**kqueue(2)** 返回一个文件描述符，**kevent(2)** 通过 kevent 结构体 {ident, filter, flags, fflags, data, udata} 实现一次性注册与返回，filter 概念将事件源抽象为 EVFILT_READ/EVFILT_WRITE/EVFILT_AIO/EVFILT_VNODE/EVFILT_PROC/EVFILT_SIGNAL/EVFILT_TIMER 七类

  kqueue 七类 filter 与事件源对照：

  | filter | 事件源 | 用途 |
| ---- | ---- | -- |
| `EVFILT_READ` | 文件描述符 | socket/pipe 可读通知 |
| `EVFILT_WRITE` | 文件描述符 | socket/pipe 可写通知 |
| `EVFILT_AIO` | 异步 IO | AIO 完成通知 |
| `EVFILT_VNODE` | 文件系统 | 文件变更/删除/重命名通知 |
| `EVFILT_PROC` | 进程 | 进程 exit/fork/exec 通知 |
| `EVFILT_SIGNAL` | 信号 | 信号到达通知 |
| `EVFILT_TIMER` | 定时器 | 周期/一次性定时通知 |

**史料**：kqueue(2) 手册页、Lemon BSDCon 2000 论文第 2-3 节、FreeBSD sys/sys/event.h 原 v1.1 ［A］
  
**史观**：形式主义膨胀与抽象克制，kqueue 用 filter 抽象取代多套 API 是抽象克制的典范
  
**辨析**：filter 中心化设计与 epoll 的 composable 设计的优劣争议，Conill 2021 批评称 filter 中心化导致技术债务
  
**文献**：Lemon BSDCon 2000 论文；Banga & Mogul “Scalable Kernel Performance for Internet Servers”(USENIX 1998) 作对比 ［B］

## 95.1.3 设计意义分析

  **要点**：kqueue 是 BSD 路线对 select/poll 性能瓶颈的回应，比 Linux epoll(2.5.44, 2002.10) 早 2 年，比 Solaris event ports(Solaris 10, 2005.1) 早 5 年，确立 BSD 在事件通知领域的先发优势
  
**史料**：Linux kernel 2.5.44 changelog、Solaris 10 release notes、Banga 1998 早期 /dev/poll 方案［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L1 代码；L3 官方文档〕
  
**史观**：总纲第 1 条——偶然性改写历史，若 Lemon 未在 2000 提交 kqueue，BSD 路线可能在事件通知上长期落后
  
**辨析**：Banga 的 /dev/poll 与 Lemon 的 kqueue 是否独立发明，需对比时间线与论文互引
  
**文献**：Banga et al. USENIX 1998；Lemon BSDCon 2000 ［B］

## 95.1.4 设计史料辨析

  **要点**：kqueue 设计史料的争议点包括：(1) Lemon 是否独立于 Banga 的 /dev/poll 工作；(2) 设计灵感是否部分来自 Solaris /dev/poll；(3) commit 时间与 BSDCon 论文时间的先后
  
**史料**：FreeBSD svn r61973(2000.7.5) commit、BSDCon 2000 论文 (2000.10)、Banga /dev/poll(1998) ［A］；freebsd.duckdb 查询 L2.2.1.sys_kern 显示：freebsd-src sys/kern/ 年度 commit 量——1999 年 2,506 条/130 文件、2000 年 2,154 条/143 文件、2001 年 2,182 条/148 文件、2002 年 3,495 条/164 文件，kqueue 引入的 2000 年 sys/kern commit 量（2,154 条）较 1999 年（2,506 条）略有下降，反映 kqueue 作为单个特性未显著改变 sys/kern 整体 commit 规模；freebsd.duckdb 数据库交叉印证——统计结论 C-03 freebsd-src 仓库总 commit 数 444,203 条（`SELECT COUNT(*) FROM commits WHERE repo_name='freebsd-src'`），kqueue 首次 commit（2000-04-16）至 4.1 发布（2000-07-26 公告）期间约 3 个月的 commit 分布为此累计量的早期段；统计结论 C-12 freebsd-src 变点检测 1999-08（Pettitt 与 BUISHAND 双检验一致 p < 0.001），距 2020-01 SVN-to-Git 迁移 245 个月，判定为非迁移伪变点，1999-08 距 kqueue 首次 commit（2000-04-16）约 8 个月，变点反映 kqueue 开发期所属的 3.x 维护期向 4.x 黄金时期切换的工程节律结构性转变，为 kqueue 的孕育与发布提供了 commit 时序上的工程背景；Python 脚本 `script/phase2_inferential.py` Task 6（Pettitt 自实现 + BUISHAND R 自实现），查询日期 2026-07-27 ［B］

## 95.1.5 同期 KSE 论文对 kqueue() 的采纳信号（2000）

  **要点**：Jason Evans 2000 年 11 月 KSE 论文（Kernel-Scheduled Entities for FreeBSD）提及，将异步 I/O 集成进 libc_r 需先稳定 AIO 实现，再把基于 **poll(2)** 的事件循环切换为基于 **kqueue(2)** 的事件循环，以在同一循环中集成 I/O 完成通知（Evans, 2000）——显示 kqueue 在首次 commit（2000-04-16）后不足一年内，已被 FreeBSD 核心开发者视为替代 poll() 的事件通知接口，构成 kqueue 早期采用的同期证据
  
**史料**：Evans. Kernel-Scheduled Entities for FreeBSD [R]. 2000-11-07. references_fulltext ref 498 ［A］
  
**史观**：实践先于理论，kqueue 的采用由 libc_r 线程库的工程需求驱动
  
**辨析**：KSE 论文中的“poll()-based event loop”指 libc_r 现状，Evans 是否实际完成切换须对照 libc_r 后续 commit 核验；该信号反映开发者意图而非已合入状态
  
**文献**：Evans. Kernel-Scheduled Entities for FreeBSD [R]. 2000 ［A］
