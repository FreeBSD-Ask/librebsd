- **新闻摘要**：事件通知机制三大主流实现的对应关系为：evport（Solaris 10 event ports）= epoll（Linux）= kqueue（FreeBSD/OS X），三者均具有 O(1) 描述符选择算法，select 通常作为跨平台 fallback。kqueue（2000）早于 epoll（2002 年 Linux 2.5.44）与 Solaris event ports（2005 年 Solaris 10），是三大实现中最早成熟的。Linux epoll 的设计者 Davide Libenzi 于 2001 年 7 月独立解决了 Linux 的相同问题，受 kqueue 设计影响明显。
- **与本章主题的关联说明**：kqueue 在三大事件通知机制中的时间领先地位是本章“事件通知革命”叙事的核心，须明确 kqueue 早于 epoll 与 event ports 的时间优势。
- **与官方史料的交叉验证结论**：kqueue（2000）早于 epoll（2002）与 Solaris event ports（2005）的时间节点与公认历史一致。Davide Libenzi 作为 epoll 设计者由 Linux 内核历史确认。但 epoll 是否直接受 kqueue 设计影响须与 Linux 内核邮件列表（LKML）2001-2002 年讨论对照确认，［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。

- **新闻标题（中英）**：Jonathan Lemon 为 FreeBSD 设计 kqueue/kevent 高性能事件通知接口（Jonathan Lemon designs kqueue/kevent high-performance event notification facility for FreeBSD）
- **新闻来源**：learnku Nginx 工作模式文章 + 掘金 epoll 简介文章 + 发布日期 2000（kqueue 于 FreeBSD 4.0 时代由 Jonathan Lemon 设计开发）+ URL：<https://juejin.cn/post/7351399718909526043> + 存档 URL：［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］：原始 FreeBSD kqueue 设计文档与 Jonathan Lemon USENIX 论文须通过 usenix.org 与 web.archive.org 检索
- **新闻摘要**：2000 年，Jonathan Lemon 通过设计和构建 kqueue/kevent 为 FreeBSD 4.3 解决了 select/poll 在大量文件描述符下性能低效的问题，使 BSD 成为高性能网络的早期选择。kqueue 与 epoll 非常相似，注册一批 socket 描述符到 kqueue 后，当描述符状态发生变化时，kqueue 一次性通知应用程序哪些描述符就绪，避免了 select/poll 的 O(n) 轮询开销。
- **与本章主题的关联说明**：kqueue 引入是 FreeBSD 在高性能网络 I/O 领域的里程碑，使 FreeBSD 成为互联网高峰期（2000 年泡沫期）高并发服务器的首选平台之一。
- **与官方史料的交叉验证结论**：Jonathan Lemon 作为 kqueue 设计者由多个独立来源确认。kqueue 引入版本存在争议：部分来源标注 FreeBSD 4.3（2001-04），但 FreeBSD 4.0-RELEASE（2000-03）已包含 kqueue 早期版本。［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］：kqueue 引入的精确版本与提交时间须与 FreeBSD commit 数据库（`freebsd.duckdb`）中 sys/kern/kern_event.c 与 sys/sys/event.h 的首次提交记录对照确认。

- **新闻摘要**：kqueue 是针对传统 select/poll 处理大量文件描述符性能低效而开发的高性能事件通知接口。注册一堆描述符到 kqueue 后，当描述符状态发生变化时，kqueue 将一次性通知应用程序哪些描述符就绪。kqueue 不仅支持 socket 文件描述符，还支持普通文件、管道、信号、定时器、进程状态变化等多种事件类型，相比 select/poll 仅支持文件描述符的设计更为通用。
- **与本章主题的关联说明**：kqueue 相比 select/poll 的技术优势是本章核心技术叙事，须清晰说明 kqueue 在事件类型通用性与性能上的双重突破。
- **与官方史料的交叉验证结论**：kqueue 作为 select/poll 替代品的定位由 FreeBSD kqueue(2) 手册页确认。kqueue 支持多种事件类型（socket、文件、管道、信号、定时器、进程状态）的能力由手册页与多个技术教程确认，与官方史料一致。
