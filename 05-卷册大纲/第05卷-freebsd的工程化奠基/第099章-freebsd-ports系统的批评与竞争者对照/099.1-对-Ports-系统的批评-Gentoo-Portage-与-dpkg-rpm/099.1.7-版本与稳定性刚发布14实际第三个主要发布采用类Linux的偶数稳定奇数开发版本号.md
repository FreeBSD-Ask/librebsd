# 099.1.7 版本与稳定性刚发布14实际第三个主要发布采用类Linux的偶数稳定奇数开发版本号

- 版本与稳定性：刚发布 1.4（实际第三个主要发布），采用类 Linux 的偶数稳定、奇数开发版本号，1.5 约在六七月转为 1.6；迄今工作多为内核内部大手术、用户可见变化刚开始浮现；1.4 是迄今最稳定的系统，堪比以稳定著称的 4.x。团队规模：约 12 人做显著内核贡献、另四五人做文档，外围贡献者在 DragonFly 与 NetBSD、OpenBSD、FreeBSD 各树之间双向搬运 bug 修复。透明集群目标预计还需约两年，年底开始出现用户可见部件——内部重构已足以着手多机环境所需的缓存架构。（BSDTalk EP22，[301.40-431.56]，L1）
- 采纳 pkgsrc 的决策链：项目初创时 Jordan Hubbard 建议第一要务是包系统，但包系统整合极难——包往往面向特定系统、大量面向 Linux，即便命令集同源仍有可移植性问题，上千包的规模更放大难度。最初在 ports 上加 shim 与 overlay 打小补丁，但从无长期维护之意。选 pkgsrc 的理由：它是同期起步、已趋成熟的多平台努力；FreeBSD ports 若有可移植尝试，本质上仍是 FreeBSD 专用系统、并非为 DragonFly 设计，长期必成维护负担；更关键的是数名 DragonFly 开发者同时是 pkgsrc committers 并在做积极开发——不能指望无人开发、无人修 bug、无人深知它的包系统能长期维持，人的因素是决定性考量。（BSDTalk EP22，[628.28-801.04]，L1）
- 对开源生态的结构判断：须区分内核中心项目（Linux、FreeBSD、NetBSD、OpenBSD 内核）与应用集——后者由编写应用的人代表而非打包系统，GIMP、KDE、OpenOffice 等可轻松移植到几乎任何类 Unix 环境，不少新包虽面向 Linux 编写仍可移植；Linux 从 Unix 继承了大量应用集。开源在公众眼中的增长实际是应用集的增长，与内核与核心工作几乎无关，且将长期如此；因此媒体所谓 Linux 正在碎片化、内核太多的报道不实——内核可以很多，KDE 只有一个。（BSDTalk EP22，[1182.76-1295.62]，L1）
- 组织概况：Mark Kane 为 MK Productions 创始人，运营三家网络电台——Mix94.1（首站、覆盖多种风格）、Party 107（2003 年创办，面向 trance 与 techno 电子乐，有约二三十至四十名全球常驻 DJ 提交混音、以连续混音形式播放）、Rock 101.9 The Edge（2004 年创办，摇滚另类金属，节目由他人管理）——以及一个公开 IRC 网络，电子音乐圈的名DJ用它主持官方节目聊天；IRC 服务器分布于世界各地，多数跑 FreeBSD、少数跑 Linux，皆由长期喜爱该项目的支持者捐赠。（BSDTalk EP26，[61.36-611.32]，L1）
- 版权与格式限制：在线电台须向版税组织付费，当事人经由网络上的联合广播服务按月付费、由其按播放内容向各组织分发，简化了流程；但因所用的版税公司限制，只能使用 Shoutcast（MP3 或 AAC+），无法改用开放的 Ogg Vorbis。主持人补充：MP3 编码受专利拖累，桌面系统难以默认附带支持，用户须另行获取编码器；Ogg 开放且低码率音质好，但播放器支持面不足，尚待普及。（BSDTalk EP26，[152.72-546.48]，L1）
- 基础设施与资金：Party 107 的自动化系统除 Shoutcast 服务守护进程外纯用开源软件——Icecast 作后端、其上加播放列表软件，开发者 Brian 编写大量定制代码与脚本，Perl 自动化系统跑在 FreeBSD 5.4-RELEASE（双处理器）上完成串流；资金靠捐赠：网站收款、托管公司与大带宽持有者捐赠流媒体服务器与带宽，仅承载曲库的主服务器自费维持。（BSDTalk EP26，[192.60-298.48]，L1）
- 转向 FreeBSD 的动机与桌面体验：从 Linux 实验起步，不满其包管理系统与第三方应用安装之难；经人介绍 FreeBSD 后下载安装并渐熟悉，喜欢其运作方式——钟爱 ports 系统、稳定性与热心相助的开发者和用户社区；从未遇内核恐慌，除主动关机或更换硬件从不重启。桌面为 FreeBSD AMD64 版（Athlon 64 3000），IRC、Firefox、邮件与媒体播放器一应俱全，唯一遗憾是 Flash 无法工作；桌面环境为轻快的 XFCE；音频剪辑在 FreeBSD 桌面上用 Audacity 完成。（BSDTalk EP26，[313.42-449.48]，L1）
- PC-BSD 于 2006 年 5 月发布 1.0，项目启动逾一年；Moore 将其定义性特征归纳为图形安装器、KDE 3.5.2 桌面环境与 PBI 软件包体系三者，并明确定位为基于 FreeBSD 的桌面操作系统而非分叉——不改 FreeBSD 默认系统，系统管理员与高级用户可无损使用 ports 与 packages，PBI 与之完全并行。（BSDTalk EP40，[403.02-446.20]，L1）
- PBI 以 QT 编写，模仿 Windows 下 InstallShield 式自解压自安装体验：每个包自带全部运行库、装入独立目录，从而消除不同库依赖软件互装互卸时的冲突；其代价是包体积因重复捆绑库而增大，Moore 判断对最终用户而言可用性优先于若干兆字节的磁盘开销。（BSDTalk EP40，[188.50-241.02]，L1）
- Moore 自述十六岁（约十年前）进入 ISP 行业，FreeBSD 承载互联网托管是其最初接触；此后工作辗转 Linux 却始终回归 FreeBSD，理由是 ports 与系统整体布局更连贯、各部件咬合更好，而其体感是 Linux 生态中大量工具与工具之间并非为彼此协作而设计，呈碎片化状态。（BSDTalk EP40，[893.10-931.50]，L1）
- PBI 立项动因出自 Moore 对普通用户的观察：初学者在 Linux 与 Unix 桌面上无法自行安装软件，即便借助易用的图形包管理器，卸载或变更软件时也会触发库依赖问题乃至破坏系统；故选择 95% 用户熟悉的自解压自安装文件作为突破口。（BSDTalk EP40，[931.50-967.10]，L1）
- 商业模式上 Moore 参照 Red Hat 与 SUSE 以企业服务求生的路径，拟通过在线商店与付费电话、邮件支持使 PC-BSD 自给自足，进而雇佣全职开发者、投入营销与 Apple 及 Microsoft 竞争；同时明确承诺不闭源、不对下载收费。（BSDTalk EP40，[565.36-617.12]，L1）
- 主持人以发布当日新闻切入：NetBSD 3.0 于 2005 年 12 月 23 日发布，较上一版 2.1 带来 Xen 虚拟机监视器集成、以可选项引入 OpenBSD 的 packet filter 防火墙组件及大量驱动更新，成为该期软件管理主题的时代注脚。（BSDTalk EP2，[27.60-62.74]，L2）
- 主持人概括 BSD 软件管理的双轨结构：ports 为源码编译路线，以目录结构与 make 文件自动抓取源码、打补丁适配当前 BSD 版本并递归解决依赖（如 Firefox 对 X Window 的依赖），规模约六千至一万个条目，远多于几百至几千个预编译 packages；packages 走 pkg_add 等 pkg 工具的预编译快速路线。NetBSD 因将 port 一词保留给架构移植而不再称 ports，术语差异折射各项目概念体系的分化。（BSDTalk EP2，[240.18-369.94]，L2）
- 主持人介绍 Gentoo Linux 因偏爱 ports 机制而以 BSD packages and ports 体系作为发行版根基，社区以 GCC screensaver 戏称源码编译路线的漫长等待；他自陈管理多机时倾向点击式更新，但也承认自动更新系统在问题定位上的脆弱，呈现两种工程文化的效用权衡。（BSDTalk EP2，[454.96-518.88]，L1）
- 主持人转述 OpenBSD 包系统的克制路线：依邮件列表信息，开发者致力于添加清晰简单的基础层再逐步扩功能而非堆砌特性；包安装须指定精确版本、安全更新后需手动卸旧装新，OpenBSD 3.8 才开始就地升级尝试。他提出辩证问句——这是落后于曲线还是追求稳固系统——拒绝以单一进步标尺评判功能差异。（BSDTalk EP2，[562.10-641.52]，L1）
- 主持人讲解 base 系统更新三路径：逐个下载补丁重编所需部分、以 CVS 跟踪 stable 分支整体重编（FreeBSD 术语 make world，指重编全部形成内聚整体）、跟踪 current 获取前沿特性但他告诫勿用于生产机；在低速小容量硬件上重编困难催生跨机编译再迁移的社区方案，整体不如 Linux 发行版点击式便捷，他直言这就是 BSD 的运作方式。（BSDTalk EP2，[757.76-960.16]，L2）
