- FreeBSD 成为 Perlstein 的立身之本：1999 年经 Paul Saab 引导将 Yahoo 的 accept filters 推入系统，配合当时新出现的 kqueue，在单颗 Pentium 400 上实现每秒 1500 连接的 web 追踪服务；受雇 Apple 内核团队解决 NFS 断连导致系统挂起的问题；在 Juniper 把 Junos（FreeBSD 改版）部署到高速线卡并做粗粒度线程化；任 OkCupid CTO 期间全栈运行 FreeBSD；后来还赞助 libuinet 用户态网络栈用于安全设备并期望其合回主线。（BSD Now EP142，[1923.76-2127.04]，L1）
- John Baldwin 的入行路径呈现 1990 年代中期学术环境如何孕育系统级开发者：他就读的高校以 FreeBSD 为桌面 Unix 并迟至其毕业后才迁移 Linux，他用 2.1.7 起步、以 2.2.2 在宿舍楼 10Base2 同轴网络中自建路由共享串口拨号，高中时便与友人构想过类 UFS 文件系统的自制操作系统，大四获文档提交权限，毕业后经 Mike Smith 选拔进入 Walnut Creek CDROM 专职开发 FreeBSD，原定 IA-64 方向未果，转而在夜间 IRC 中投身 SMP 内核开发。[存疑脚注] 转写将版本号记作 217/222，按 FreeBSD 版本序列推断为 2.1.7 与 2.2.2；Walnut Creek CDROM 转写作 Water Creek CD-ROM。　[存疑脚注] 版本号与机构专名系转写失真，按上下文复原为 2.1.7、2.2.2 与 Walnut Creek CDROM，引用前宜核对。（BSD Now EP125，[1479.72-1704.86]，L1）
- 关于 FreeBSD SMP 的起源叙事：Baldwin 称 SMP 工作始于一次来自 BSD/OS 的代码 drop，其早期贡献是剥离 i386 特定化使 SMP 机器无关，以容纳 alpha 平台；Doug Rabson 提供了 alpha 上的 SMP 补丁，Baldwin 将其收尾完成。这段自述把 SMP 多平台化的功劳链从舞台中央延伸到接手收尾的工程师，恰是无名贡献者谱系的典型样态。[存疑脚注] 转写将 SMP 记作 S&P，BSD/OS 记作 BSDOS，Doug Rabson 记作 Doug Rapson。　[存疑脚注] SMP、BSD/OS、Doug Rabson 三个专名均系转写失真，语义可辨但引用时须复原原名。（BSD Now EP125，[1766.48-1792.66]，L1）

**史料**：

- 本期提及的一手与二手材料：Damien Miller 在 OpenSSH 开发邮件列表发布的协议 1 弃用公告，称该协议已处于各阶段弃用近十年、编译期禁用约一年，计划 2016 年 8 月 SSH 7.4 发布后先移除服务器端、2017 年 6 月全部删除（4403.08-4493.32）；荷兰高校关于 SROP（信号返回导向编程）的学术论文及 OpenBSD 的缓解补丁草案，采用 kbind 技巧、魔术 cookie 与信号蹦床页随机化（4093.44-4302.98）；GitHub 上 .NET CoreCLR 对 NetBSD 的移植 pull request（3986.98-4076.00）；2000 年 Salon 杂志的 BSD 起源长文（1021.42-1060.26）；iX Systems 为客户交付约 360 台服务器、合计约 10PB 存储的部署订单（1352.26-1433.92）。（BSD Now EP142，[4403.08-4493.32]，L2）

**史观**：

- 总纲10 动手者创造历史：主持人转述的 2000 年 Salon 文章给出与英雄史观相反的判断：对 Bill Joy 的过度聚焦是一种圣徒传式叙事，遮蔽了更大的图景——“伯克利最重要的贡献不是软件本身，而是创造软件的方式”（1076.64-1104.68）——一个任何时刻不超过四人的核心小组，把不断扩张的远方志愿程序员网络协调成渐进发布、稳步改进的流水线。技术史的真正主角是协作结构的发明，而非站在台前的个人。（BSD Now EP142，[1045.86-1104.68]，L2）
- 总纲5 没有必然性，只有偶然性：Perlstein 走向 FreeBSD 开发者的每一步都系于偶然：恰好在 MS-DOS 时代自学汇编，恰好被同学讥讽而另寻出路，恰好学校采用 FreeBSD 作教学平台，恰好邮件列表给出令他折服的长篇答复。没有哪一环是历史必然，一个行动者的转向由一连串具体偶然事件串联而成。（BSD Now EP142，[1561.38-1617.20]，L1）
- 总纲10 动手者创造历史：Baldwin 对 core 团队职责的界定颠覆了治理光环叙事：核心的最大职能是发现“fallen through the cracks”无人问津之事并推动其完成，而这些事恰恰因为无人想做而滞留，“如果你竞选 core 却不愿去做这类事，那你竞选的是错误的职位”。项目的延续依赖愿意承担非光鲜工作的动手者，而非英雄叙事中的决策者。（BSD Now EP125，[4244.16-4282.66]，L1）
- 总纲13 法律与道德是利益分配：Baldwin 的许可证立场可读作利益分配哲学的自觉表达：他坦言被 BSD 许可证吸引源于“我喜欢用户拥有自由，包括偶尔做出愚蠢选择的自由”，承认十年前全 BSD 许可工具链曾被视为不可逾越，Clang/LLVM 的成熟才使其可行；他主张 GCC 与 Clang 长期并存、以竞争互促，反对许可证纯洁化压缩 FreeBSD 的应用场景，同时坚持默认基座不搭载 GPLv3、以 opt-in 机制照顾 Clang 未成熟平台。许可证在此不是道德立场，而是关于用户选择权与生态利益的分配安排。（BSD Now EP125，[2677.62-2788.22]，L1）

**辨析**：

- Perlstein 对 FreeBSD 上手体验提出一组可检验的批评：pkg install Django 直接报无包，而真实包名是 py27-django 这类带版本前缀的命名；学会 Subversion 与 Phabricator 的技能难以外溢到 Git/GitHub 主流生态；仓库过大令新手克隆即卡壳。他主张举办“反向安装马拉松”——不给新手帮助，只记录他们在何处卡住——甚至公开抛出为项目改名的争议建议（3051.12-3136.92），理由是连大会讲者与他的母亲都念错 FreeBSD。这些均为当事人单一来源立场，尚待社区实践检验。（BSD Now EP142，[2686.14-2922.74]，L1）
- Phoronix 三 BSD 对十 Linux 基准的主持人辨析揭示方法论陷阱：表面比较系统实则在比较编译器版本（PCBSD 用 Clang、OpenBSD 用陈旧 GCC 4.2.1、Clear Linux 用新版 GCC），不同发行版各自调优编译开关使测量对象漂移；DragonFly Hammer 文件系统在磁盘事务测试垫底被解读为 fsync 数据安全语义更严格而 Linux 略有取巧，OpenBSD 旧版 FFS 缺软更新致同步写代价更高。全部为节目内单一来源推断，须以原始基准数据与文件系统文档交叉验证。[存疑脚注] 转写将 Phoronix 记作 Pharonix/Fortnix。　[存疑脚注] 基准结论属单一来源推断且专名转写失真，引用前须核对 Phoronix 原文与当期基准配置。（BSD Now EP125，[5898.28-5991.98]，L4）
- 英国 Register 报道的退役服务器（200MHz Pentium、32MB 内存、4GB SCSI-2 硬盘、持续运行近 19 年的 FreeBSD 2.2.1）被主持人转述为系统可靠性的例证，并称当事人 Ross 在报道中解释了不升级的原因。该叙事经媒体二手传播进入节目，硬件参数与当事人引语的准确性未在节目内核实，作为物质文化与运行寿命史料使用时须回溯原始报道；与节目另一音轨提及的 ScaleEngine 自有服务器 1867 天 uptime 应区分，避免混同为同一系统。[存疑脚注] 当事人 Ross 全名、报道日期与机器所在地未在转写中给出。　[存疑脚注] 二手媒体转述且关键当事人信息缺失，引用前须核对 The Register 原始报道。（BSD Now EP125，[116.48-141.00]，L2）
