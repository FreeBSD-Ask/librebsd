# 91.5 外部批评与反对者 ：（1） Valerie Aurora（LWN 2009）对 soft updates 的批评——Aurora 在 LWN.net 2009 年 7 月 1 日发表的 “Soft updates, hard problems” 一文中直言 "soft updates are, simply put, too hard to understand, implement, and maintain to be part of the mainstream of file system development"，从 Linux/Solaris/OS X/AIX 主流文件系统开发者视角指出 soft updates 虽学术优雅却工程复杂度极高，是 “为何 Linux 不学 BSD soft updates” 的根本原因

## 91.5.1 Valerie Aurora 对 soft updates 的批评

  **要点**：Valerie Aurora(原名 Val Henson) 在 LWN.net 2009.7.1 发表 “Soft updates, hard problems”，从 Linux/Solaris/OS X/AIX 主流文件系统开发者视角批评 soft updates：

  > soft updates are, simply put, too hard to understand, implement, and maintain to be part of the mainstream of file system development
  >
  > ——Valerie Aurora, “Soft updates, hard problems”, LWN.net, 2009-07-01

  是 Linux 不学 BSD soft updates 的根本原因
  
**史料**：Aurora 在 LWN.net 2009.7.1 的文章、Aurora 个人博客、freebsd-fs 邮件列表对批评的回应 ［A］
  
**史观**：技术路线分化，Aurora 的批评体现了 Linux 与 BSD 在文件系统路线上的分化
  
**辨析**：Aurora 的批评是否 “客观” 存在争议，其立场为 Linux 开发者，需区分技术批评与立场批评
  
**文献**：Aurora “Soft updates, hard problems”(LWN 2009.7.1)；Aurora 个人博客；freebsd-fs 邮件列表 ［A］

## 91.5.2 Dong 与 Chen 的学术再批评

  **要点**：Dong 与 Chen 在学术论文中对 soft updates 的依赖追踪机制提出 “不可维护” 批评，认为依赖图的复杂度随元数据操作增长而不可控，是 soft updates 难以主流化的结构性原因
  
**史料**：Dong & Chen 的学术论文、freebsd-fs 邮件列表对该论文的讨论 ［A］
  
**史观**：基础科学，学术批评体现了 soft updates 的理论局限性
  
**辨析**：Dong & Chen 的论文需查具体发表年份与期刊，可能存在多个版本
  
**文献**：Dong & Chen 的 soft updates 批评论文；freebsd-fs 邮件列表讨论 ［A］

## 91.5.3 批评的形式主义分析

  **要点**：对 soft updates 的批评可能存在形式主义，即以 “Linux 不采用” 为标准评判 “BSD 采用” 的工程选择，忽略了两条路线的不同语境
  
**史料**：Aurora 文章、Dong & Chen 论文、BSDCon 文件系统辩论 ［B］
  
**史观**：总纲第 3 条——形式主义膨胀，以 “主流” 标准评判 “非主流” 选择是形式主义
  
**辨析**：批评的形式主义不等于批评错误，需结合技术语境分析
  
**文献**：Aurora 文章；Dong & Chen 论文；BSDCon 辩论 ［B］

## 91.5.4 批评的史料辨析

  **要点**：soft updates 批评史料保存较好，Aurora 文章与 Dong & Chen 论文完整，但 BSD 社区的反驳散落在邮件列表中
  
**史料**：Aurora 文章、Dong & Chen 论文、freebsd-fs 邮件列表反驳 ［A］
  
**史观**：软件工程，批评史料的保存需包含正反双方
  
**辨析**：部分反驳未系统整理，需从邮件列表挖掘
  
**文献**：Aurora 文章；Dong & Chen 论文；freebsd-fs 邮件列表 ［A］
