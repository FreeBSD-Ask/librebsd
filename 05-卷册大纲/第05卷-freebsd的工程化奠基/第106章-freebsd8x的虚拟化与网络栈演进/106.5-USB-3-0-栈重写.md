# 106.5 USB 栈重写（8.0 集成 newusb；USB 3.0 xHCI 支持系后续版本）

## 106.5.1 USB 栈重写的工程过程

  **要点**：FreeBSD 8.0 集成重写的新 USB 栈（newusb，由 Hans Petter Selasky 主导），首期支持 USB 2.0（EHCI/OHCI/UHCI）；USB 3.0 xHCI 驱动系 FreeBSD 12.0（2018）才合入 base，与 8.0 重写相隔约八年；新栈采用模块化设计，替代旧的 USB 栈
  
**史料**：FreeBSD 8.0 Release Notes、Selasky 的 EuroBSDCon 演讲［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档；L4 事后叙述〕
  
**史观**：专题语（不设总纲条号）：重写是对旧栈工程问题的回应
  
**辨析**：重写是否必要，需查旧栈的具体问题——PODCAST_REVIEW 块（BSDTalk EP267）载 Selasky 一手自述：旧栈回调前无引用计数、回调直接在中断处理器内执行并阻塞其他中断处理，且内核转向多处理器互斥锁架构后 ISDN 栈须摆脱 Giant 锁，重写动机即在于此
  
**文献**：FreeBSD 8.0-RELEASE Release Notes；Selasky, H. P. New USB Stack for FreeBSD EuroBSDCon 2009 talk；FreeBSD USB wiki page (wiki.freebsd.org) ［B］

## 106.5.2 新栈的设计与效应

  **要点**：新 USB 栈的设计：(1) 模块化驱动；(2) USB 2.0（EHCI/OHCI/UHCI）全量支持，USB 3.0 xHCI 系后续版本（FreeBSD 12.0 合入 base）；(3) 改善设备兼容性；(4) 性能提升
  
**史料**：commit log、Release Notes ［A］
  
**史观**：专题语（不设总纲条号）：模块化增加灵活但增加复杂度
  
**辨析**：性能提升幅度，需查基准测试——PODCAST_REVIEW 块载实测：大容量存储新栈与 Linux 相当、旧栈落后约 2-5%；USB Ethernet 凭 IO 向量突破中断率瓶颈；正式撰写仍须对照基准测试
  
**文献**：FreeBSD 8.0 src/sys/dev/usb/ commit log；Selasky, H. P. EuroBSDCon 2009 USB talk；FreeBSD 8.0-RELEASE Release Notes ［A］

**要点**：

- BSDCan 2016 于渥太华大学举行、265 人参会；OpenBSD 会后集中公开论文与幻灯（Zen 半虚拟化 HVM 驱动、双向转发检测 BFD 新路由协议、rc.d 系统研讨、OpenFlow 实现 switchd 等）；FreeBSD 开发者峰会以占满整面黑板的 FreeBSD 11 已交付成果清单开场，再进入 have-want-need 议程，以实物盘点纠正社区惯有的“毫无进展”错觉。（BSD Now EP146，[45.9-665.6]，L2）[订正：原 [45.08-647.80]，2026-09-30 SenseAudio 重转核对]
- 微软以发布者而非 FreeBSD Foundation 的名义在 Azure 市场发布附带技术支持的 FreeBSD 10.3 定制镜像：以 stock 10.3 为基础补入错过发布周期的 Hyper-V/Azure 优化补丁（多数已上游化），并以承担构建、测试与维护之责满足企业级 SLA；Foundation 主席 Justin Gibbs 称“对 FreeBSD 社区与微软发布受支持的 Azure 镜像而言，这是一个相当重要的里程碑”（840.08-851.82）；Register、Inquirer、InfoWorld 多源报道将其夸大为微软自创发行版，主持人以镜像实质逐条澄清。（BSD Now EP146，[773.38-967.00]，L3）
- Ted Unangst 对 OpenBSD select() 实现的内核考据：man page 警告“在内核内部，当多个进程等待同一文件描述符时 select 与 pselect 工作不佳”（1011.26-1022.90）；追查发现 selinfo 结构在首次 select 时记录等待进程 PID，无碰撞时内核仅唤醒单一等待者、collision 标志置位才退回全体唤醒，且 kern.nselcoll 计数器实测极少（Ted 笔记本 43 次、高 uptime 服务器为零），表明“看似低效”的直觉须以测量裁决，是否需要替代方案取决于 select 与 epoll/kqueue 之间的软件存量。（BSD Now EP146，[1004.9-1169.7]，L2）[订正：原 [1011.26-1161.57]，2026-09-30 SenseAudio 重转核对]
- Selasky 自述十二三岁在挪威与朋友用 QBasic 合写小游戏，因买到的商业图形工具包与其显卡不兼容且遭拒退而转向自由软件；循 X11 驱动发现 FreeBSD 后，用 Windows 95 机器经 ISDN 以软盘逐张下载 FreeBSD 3.4 全部发行版，逐盘校验坏扇区，最终在 486 级 233MHz、32MB 内存的机器上完成安装；靠 PDF 文档自学 shell，首个编辑器是 ee 而非 vi 且沿用至今。（BSDTalk EP267，[158.24-391.94]，L1）
- 因 FreeBSD 缺少其 ISDN 适配器的驱动，他结识多年为 FreeBSD 编写 ISDN 驱动的汉堡开发者 Helmut Michaelis（项目 ISDN for BSD，即 i4B）；研读代码后为德国 Cologne Chip 的 HFC 卡写出首个 ISDN 驱动——该厂罕见地公开芯片文档；继而认为 i4B 其余部分过度设计且含缺陷，重构欧洲通行的 DSS1/Euro-ISDN 信令，产出完整但非增量的补丁集，终未被 FreeBSD i4B 接受；他回顾认为拒收是正确决定，因为那是他第一个大型 C 项目。（BSDTalk EP267，[391.94-545.82]，L1）
- 为同时维护十三至十五张 ISDN 卡驱动并应对频繁的 API 变更，他发明“宏布尔”技术：以保留或吞掉参数表达真伪的 yes/no/not 三宏构成比较电路，一个头文件即可切换各卡代码路径，改动只需一处；项目团队普遍不喜欢宏，且他先写码后补风格、挨过繁重评审，因而建议新人先读 man style(9) 再投稿。（BSDTalk EP267，[545.82-745.04]，L1）
- 进入 USB 领域源于想支持 ISDN USB 适配器，恰逢 FreeBSD 从单处理器中断优先级架构转向多处理器互斥锁架构：为让 ISDN 栈摆脱 Giant 锁，必须先有 Giant-free 的 USB 栈；他发现旧栈回调前无引用计数、回调直接在中断处理器内执行且会阻塞其他中断处理，新栈因此引入引用计数与 start/stop/drain 三函数 API（受 callout API 启发），并把回调从中断上下文改为通知独立进程执行，显著改善 SMP 扩展性；当时正处在合入 FreeBSD 8 的提交流程中。（BSDTalk EP267，[747.34-981.10]，L1）
- 性能方面：大容量存储实测新栈与 Linux 相当、旧栈落后约百分之二至五；USB Ethernet 提升显著，关键在 USB IO 向量——可排队多个以太网帧、末尾仅一次中断，突破主机控制器每秒一千至八千次的中断率瓶颈；相较 Linux 的 pumping 方案，他选择变长 IO 向量以降低内存与系统调用开销，且支持控制传输分段（Linux 亦无）；并补齐 FreeBSD 5/6/7 在高速外置集线器下缺失的 isochronous 传输，使摄像头与音频设备得以工作；该栈已移植 NetBSD，或有一日进入 OpenBSD 与 DragonFly，另经 FreeBSD 模拟层运行于非 BSD 平台且性能不逊专业 USB 栈。（BSDTalk EP267，[981.10-1409.36]，L1）

**史料**：

- 当事人一手自述（Hans Petter Selasky 访谈）：16 岁为写游戏寻找显卡与输入驱动而接触 Xorg，因许可证哲学选择 FreeBSD——“GPL 说你改了什么就必须回馈，而 BSD 更合我意”（1369.96-1386.08）；经挪威 ISDN 逐张软盘下载发行版；自 i4b ISDN 驱动补丁起步，乘内核由 SPL 走向 mutex 的多线程化浪潮改写 giant-free ISDN 栈，继而重写 USB 栈并以邮件列表连年推送补丁，终获 commit bit；现受雇 Mellanox 优化 100G 网卡驱动，曾因高速网络暴露内核定时器子系统竞争而写漏洞利用式概念验证以自证。　[存疑脚注] 转写专名失真：i4b 被听作“Ice Jam”（1482.66-1491.26），FreeBSD 多处被听作“3BSD/3DSD/VSD”，引用须回原音轨核对（BSD Now EP146，[1337.9-1736.4]，L1）[订正：原 [1338.14-1715.50]，2026-09-30 SenseAudio 重转核对]

**史观**：

- 总纲10 动手者创造历史：动手者叙事的当代表达：Selasky 从软盘安装的少年业余者成长为自称内核“全领域通才”的当事人，其路径由补丁、驱动与栈重写铺就而非职位与头衔；结语劝勉听众“闭上嘴写代码”（3059.92-3068.72），需要的是更多开发者与测试者而非批评者，并称“到 FreeBSD 来调试 Linux 内核，用户空间调试远好于内核空间”（3117.54-3121.38）——历史动力来自动手者的具体劳作，而非台前言论。（BSD Now EP146，[3026.12-3107.72]，L1）
- 总纲6 和解优于斗争：Linux KPI 的架桥哲学：为让网卡厂商以 BSD 许可证发布混合驱动，FreeBSD 侧以 mutex、线程、字符设备、kobject 等包装层使 Linux 网络代码近乎原样编译，同时刻意不保留 Linux 代码注释、不直接复制代码以规避许可证冲突；Selasky 明言“我们并非独自存在于世界，我认为架桥是件好事”（2895.44-2903.44），并期待跨平台经验催生更通用的驱动——以桥接与和解替代许可证阵营的对抗叙事。（BSD Now EP146，[2776.7-2919.9]，L1）[订正：原 [2785.30-2916.46]，2026-09-30 SenseAudio 重转核对]
- 总纲10 动手者创造历史：Selasky 的路径完全由动手实物驱动：为打游戏找驱动、为上网写 ISDN 驱动、为甩掉 Giant 锁重写 USB 栈；他对少年听众直言“年龄不是问题”，买一块适配器、一把电烙铁就能入门。同一个先后被 i4B 拒收、又被 FreeBSD 8 接纳新栈的作者，其历史位置由可运行的代码而非资历或评审好感决定。（BSDTalk EP267，[1682.20-1706.84]，L1）
