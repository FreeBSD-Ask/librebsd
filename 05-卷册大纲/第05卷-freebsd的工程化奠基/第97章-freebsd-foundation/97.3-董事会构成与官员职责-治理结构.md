# 97.3 董事会构成与官员职责——治理结构

## 96.3.1 董事会构成与官员职责

  **要点**：Foundation By-Laws（Colorado Nonprofit Corporation Act）规定董事会由 3-9 名董事组成，官员包括 President、Vice President、Secretary、Treasurer，任期与改选程序明确；Section 4.1 明确 "No Members"（无会员制），即 Foundation 不设社区会员制，治理权完全由董事会行使；Article 5 规定董事职责；首届董事会 (2000) 包括 Justin Gibbs(President)、Kirk McKusick 等
  
**史料**：FreeBSD Foundation By-Laws 全文 PDF（2026-07-22 访问，<https://freebsdfoundation.org/wp-content/uploads/2015/12/FoundationBylaws-1.pdf>）、首届董事会名单、Gibbs 个人回忆 ［A］
  
**史观**：总纲第 8 条——文档史与代码史并重，By-Laws 反映治理结构演化
  
**辨析**：董事会规模上限 9 是从哪一版本 By-Laws 开始的，需查修订历史；"No Members" 条款是 FreeBSD Foundation 与 Apache Software Foundation（个人会员制）的关键治理差异——Foundation 不设社区会员层级，社区参与通过 Core Team 选举与 committer 权限实现，而非通过 Foundation 会员身份
  
**文献**：FreeBSD Foundation. By-Laws [Z/OL]. Colorado Nonprofit Corporation Act. <https://freebsdfoundation.org/wp-content/uploads/2015/12/FoundationBylaws-1.pdf>（访问日期 2026-07-22）；董事会会议记录 ［A］

## 96.3.2 会议规则与修订程序

  **要点**：By-Laws 规定董事会会议至少每年一次，特别会议可由 President 或多数董事召集；By-Laws 修订需经全体董事 2/3 多数同意；会议记录须保存归档
  
**史料**：By-Laws 第 4-5 条、董事会会议记录 (部分公开) ［A］
  
**史观**：总纲第 8 条——文档史与代码史并重，会议规则决定治理透明度
  
**辨析**：会议记录的公开范围是否一致，需查不同年度披露情况
  
**文献**：By-Laws；公开的董事会会议记录 ［A］

## 96.3.3 By-Laws 的治理辨析

  **要点**：By-Laws 治理辨析：(1) 董事会规模 3-9 在不同时期实际人数；(2) 官员职责的实际履行与 By-Laws 是否一致；(3) 修订频率反映治理演化
  
**史料**：By-Laws 各版本、董事会组成历史、freebsd-foundation 邮件 ［A］
  
**史观**：总纲第 6 条——形式主义膨胀与抽象克制，By-Laws 修订应避免膨胀
  
**辨析**：By-Laws 修订是否曾引发社区争议，需查邮件列表
  
**文献**：By-Laws 修订历史；freebsd-foundation 邮件 ［A］

## 96.3.4 By-Laws 史料辨析

  **要点**：By-Laws 史料疑点：(1) 原始 By-Laws(2000) 与当前版本的差异；(2) 修订是否完整记录；(3) 各版本签署人是否一致
  
**史料**：By-Laws 各版本 PDF、科罗拉多州务卿备案记录 ［A］
  
**史观**：总纲第 4 条——0 信任原则，对基金会自保管文件需独立核对州务卿备案
  
**辨析**：州务卿备案是否包含完整 By-Laws，需查科罗拉多州备案规则
  
**文献**：科罗拉多州务卿档案；Foundation By-Laws ［A］

**要点**：

- Benedict 回顾加入 FreeBSD 基金会董事会的过程：Erwin Lansing 在 AsiaBSDCon 私下接洽，动因是基金会希望加强德奥瑞等欧洲国家的布局；他在电话面试中自陈是文档人不懂内核，而 Kirk McKusick 回应董事会已有足够源码提交者、需要多样性。（BSD Now EP138，[1601.00-1689.00]，L1）
- Benedict 阐明基金会定位：不干预项目技术政策，而是提供资金、资助开发者与发布工程师、经营企业关系（iX、Netflix 等）并在会议设摊；其个人任务包括发掘欧洲赞助者与进入非 BSD 会议 outreach。（BSD Now EP138，[1789.00-1851.00]，L1）

- Benedict 的日常工作：达姆施塔特应用科学大学的 Big Data 教学集群（Dell C6220 多节点），以 bhyve 给学生发放 Ubuntu 虚拟机与密歇根大学两千行级电影评分数据集，学生持 root 且以 ZFS 快照随时回滚；他从 Ubuntu 逐步迁往 FreeBSD，并把学校 25 分钟的 FI 安装器替换为自己十分钟完成的 ZFS/GPT 脚本。（BSD Now EP138，[2268.00-2652.00]，L1）
- Benedict 与 Drew 在 AsiaBSDCon 开设三小时文档教程：建立 bug 账号、review 系统、IRC，并演示新的 PO gettext 翻译流程，学员当场完成 LeapSeconds 一文的日语翻译；翻译记忆与 Pootle 化为长期目标。（BSD Now EP138，[2659.00-2830.00]，L1）
- 新闻综述：Colin Percival 提出“有立场的变通”实践——仅在触发缺陷的特定系统上应用 workaround 并大声抱怨，并举 Heartbleed 源于 OpenSSL 为规避个别慢平台而全局自建内存管理；NetBSD calendar 因未降权执行外部命令而可被本地用户提权，影响几乎所有历史版本；FreeBSD 11.0 为 package base 推迟一个月。（BSD Now EP138，[3364.00-3479.00]，L2）
- Capsicum 被界定为面向应用沙箱化的能力框架：既有安全机制或以用户彼此隔离为模型，或依赖顶层密级策略，均不适配应用内部组件失效的场景；Capsicum 令进程进入 capability mode 后无法访问文件系统、System V 共享内存等全局命名空间，并以文件描述符承载类似 object capability 的不可伪造引用，实现细粒度权限传递，从而把进程受损后的可破坏范围压缩到最小。（BSD Now EP39，[1017.09-1141.35]，L1）
- 访谈以 tcpdump 为标杆案例说明沙箱收益：该工具须以 root 运行、携带大量不以安全为设计目标的协议解析器、又常在疑似受攻击时启用，构成特权、脆弱性与攻击窗口的三重叠加；Capsicum 化后其先完成特权初始化再入沙箱，即便被攻破，注入代码也仅能破坏指定输出文件，而无法打开任意文件、改动口令、启用其他网络接口或执行改变网卡行为的 ioctl。（BSD Now EP39，[1157.11-1258.40]，L1）
- Casper 守护进程（命名取自动画角色“Casper the Friendly Ghost”，亦即本期标题“友好沙箱”的出处）作为能力服务提供者，代沙箱内进程完成 DNS 解析等依赖全局命名空间的操作：应用经由初始套接字向 Casper 请求 DNS 服务句柄，取得所需服务后即可切断与 Casper 的连接，再进入不可信数据处理阶段，使沙箱内代码保留查询能力而丧失滥用解析设施的权限。（BSD Now EP39，[1259.67-1389.83]，L1）
- 集成态势方面，Capsicum 内核 API 自 FreeBSD 10 起默认启用；OpenSSH 上游接受改动，使任何支持 Capsicum 的平台上的 OpenSSH 均可受益；FreeBSD 基本系统中 Chromium、dhclient、gzip 等已采用，gzipped 手册页查看即在沙箱中运行；Google 力推移植 Linux，DragonFly BSD 与 OpenBSD 亦有关注；但 API 推广面临“无平台则无应用、无应用则无平台”的双向冷启动困境，团队同时在平台与应用两端推进。（BSD Now EP39，[1264.64-1586.33]，L1）
- 进行中的后续工作包括改进运行时链接器，使更大更复杂的应用能在沙箱内定位库文件，最终目标是构建通用能力 shell，令未感知沙箱的应用经命令行参数推断所需权限后即可在沙箱中不加修改地运行，作为对 jails 等重型机制的基础性补充。（BSD Now EP39，[1462.46-1508.18]，L1）
