**要点**：

- Deb Goodkin 时任 FreeBSD Foundation 运营总监；她拥有计算机工程本科与电机工程硕士学位，长期在 IBM 存储行业从事固件与软件工作并做过约十年顾问；2005 年经 Justin Gibbs 公司一位与其私交甚好的 HR 介绍与 Gibbs 会面，先以顾问身份试用数月，2006 年 1 月正式受雇，是基金会的首位专职员工；入职前她对 FreeBSD 了解有限，靠自行研究与 Gibbs 的热忱讲述建立认知。（BSDTalk EP211，[89.88-278.36]，L1）
- 基金会使命是支持 FreeBSD 项目与全球社区，具体分三大领域：其一，资助全球会议并补贴开发者差旅，每年最多约八个会议；其二，项目资助为最大支出，历史上由开发者主动提交提案、基金会评估可行性与资金后决定；其三，法律支持——基金会为法人实体而项目本身只是志愿者群体、无法人地位，基金会代为签署许可协议、为开发者签署 NDA 以获取受限资料，并提供法律咨询。（BSDTalk EP211，[278.36-432.46]，L1）
- 法律实体的具体作用举例：基金会曾与 Sun 签署 Java 许可协议并逐年续签，加入 PCI-SIG 为开发者获取规范，通过自建 NDA 让开发者接触受限资料；若项目志愿者遭遇诉讼威胁或需要法律意见，也由基金会出面处理。（BSDTalk EP211，[385.14-432.46]，L1）
- 资金完全来自捐赠：2011 年筹得 42.8 万美元、超出 40 万目标，前一年约 28 万，三年累计逾百万美元；2012 年把募款目标提高至 50 万美元、为史上最雄心，并把募款活动从年末冲刺提前为全年展开，以摆脱不确定性——2011 年 12 月 1 日时仅完成约半数目标，年末才靠捐款人凑齐。（BSDTalk EP211，[441.38-575.33]，L1）
- 捐赠进单一资金池、不设限定用途捐赠，但基金会通过捐赠附言了解用户需求以指引支出方向；2011 年收到 807 笔个人捐赠，多为小额（含按月五十美元级的持续捐助者），大额主要来自大公司并居于官网捐赠名单前列；项目取舍由董事会月会讨论表决，董事全部是亲手参与系统开发的 hands-on 人员，对不熟悉的项目派董事向社区调查真实需求与金额合理性，支出保持保守；每年公开征集提案一两次、随时接受提案。（BSDTalk EP211，[613.38-760.68]，L1）
- 会议资助分层：主力为 EuroBSDCon、BSDCan 与 AsiaBSDCon 三大会议；对基辅等 FreeBSD 尚不流行地区的小型会议给予小额资助，视为扩张用户基盘的手段；另有 MeetBSD（加州与波兰）及纽约、华盛顿特区的会议；上一年举办两次 vendor summit，基金会计划开始赞助此类活动。（BSDTalk EP211，[765.68-856.12]，L1）
- 2012 年新方向是基金会主动发起大型项目：先雇人撰写项目规格与实施框架、连同预算（十万美元或二十五万美元量级）公布在官网，再据此雇开发者实施；企业可看到具体项目与金额后捐款支持（非限定捐赠形式）；目标项目包括 Event and Fault Management Framework、System Regression Test Infrastructure 与 ports 打包安装升级改进等；已宣布资助的项目为 auditd 实现与 IPv6 性能分析，第三个刚批准待公布。（BSDTalk EP211，[1019.54-1189.12]，L1）
- 营销与企业关系方面：基金会正制作面向会议发放的 BSD 通用与 FreeBSD 9 两种手册；推动与企业的联合营销，设计类似 BSD inside 的口号让使用 FreeBSD 的企业公开表态，并收集企业 testimonial 同步到基金会与项目官网；过去一两年开始登门拜访使用 FreeBSD 的公司，双向受益并促成企业向项目输送开发者与 committer；同时收集受资助开发者与普通用户的使用故事。（BSDTalk EP211，[1288.70-1402.18]，L1）
- McKusick 口述基金会创立的初衷是充当法律实体：由基金会出面签署保密协议，开发者得以在其伞下自由交换信息而不必各自承担法律风险。他强调 FreeBSD 是先于基金会存在、自我运转的开源项目，基金会只是侧翼的辅助机构，不主导技术方向。（BSDTalk EP224，[326.60-385.24]，L1）
- 2012 年度募款目标 50 万美元，因一笔 25 万美元的挑战性配捐最终募得逾 75 万美元；基金会据此决定把完成过项目的开发者转为全职或半职受薪人员，承担发布工程、机器管理等原先纯靠志愿者的工作。McKusick 称这些人是项目而非基金会的雇员，行政开销仍仅一人，并提及首批两名全职人员位于东欧、两人全职总成本低于美国或西欧雇一人。（BSDTalk EP224，[1212.34-1293.46]，L1）
- McKusick 以 unmapped I/O 项目说明基金会的立项逻辑：写文件时数据先从用户缓冲区拷入内核缓冲区，传统做法还须把该缓冲区映射进内核地址空间，多处理器系统上每次映射变更都需处理器间中断通知所有 CPU，开销巨大；取消映射、直接告知设备物理页位置后，可用的 I/O 提速约 25%。该优化在单一架构上已有原型，但跨架构与跨子系统收尾需约半个 man-year，无单一公司愿意投入，基金会遂资助专人完成。（BSDTalk EP224，[879.62-1063.68]，L1）
- Goodkin 界定 FreeBSD Foundation 与项目的关系：基金会是独立法人，项目并不隶属其下，她明确否认伞形组织定位，基金会无权指挥项目；其职能限于服务——持有 FreeBSD 商标、签署许可协议与保密协议、雇佣专职软件工程师实现功能、修复缺陷与复核变更，补足志愿者无人问津的领域，并为有定制需求的企业牵线可承接的公司。（FLOSS Weekly EP662，[661.0-878.0]，L1）
- 基金会资金百分之百来自捐款：个人用户之外主要为企业捐助者，如 Netflix、Juniper、NetApp、Google、Backblaze 等，捐款不指定用途，财务报告与 IRS 990 表公开，另有 grants 补充，Goodkin 称募款是她工作中最难的部分。治理形态上基金会未设技术顾问委员会，也未采用 Linux Foundation 式会员制，即使出于筹资考虑也不愿改变模式。（FLOSS Weekly EP662，[908.0-1233.0]，L1）
- FreeBSD Foundation 是依美国税法注册的 501(c)(3) 公益组织，与作为行业协会的 501(c)(6) Linux Foundation 形成对照；基金会成立于 2000 年，项目本身则是志愿者的社群，基金会使命定位为服务项目与社区，二者互不隶属。（FLOSS Weekly EP662，[710.0-769.0]，L1）
- Goodkin 回顾 macOS 的 FreeBSD 渊源：Apple 起初从 BSD 取用组件，随后多年以 FreeBSD 组件逐步替换，因此常被视为 FreeBSD 系操作系统；她将这一底子追溯到 Apple 收购的 NeXT——收购后 Apple 以 NeXT 操作系统为 macOS 的基础。（FLOSS Weekly EP662，[576.0-609.0]，L2）
- Goodkin 以亲历者回忆其在数据存储业界与 NeXT 的合作：NeXT 采用其雇主的磁盘驱动器，她需上门确保应用与驱动兼容；她据此强调 NeXT 属于 BSD 阵营，Apple 收购 NeXT 并以其操作系统为基础，构成 macOS 至今携带 BSD 与 FreeBSD 底层的由来。（FLOSS Weekly EP662，[3327.0-3380.0]，L1）
- Goodkin 回顾 BSD daemon 吉祥物史：Beastie 是对 Unix 后台进程 daemon 的双关，其图形出自后来供职迪士尼的动画师（她在访谈中忆为 John Lasseter），商标由伯克利元老 Kirk McKusick 持有；因形象近于魔鬼一度引发顾虑，各 BSD 项目相继更换标识，FreeBSD 改用红色圆球造型；2005 年前后社区举办图形竞赛选出现行官方 logo 并由基金会持有，Beastie 至今仍常被误作 FreeBSD 专属标识。　[存疑脚注] 转写将动画师姓名转作 John Lazider 等多种拼法且 Goodkin 自述记忆不确定；logo 更换的年代与动因均系口述转述，需与 daemon 词源考察及基金会档案核对（FLOSS Weekly EP662，[1894.0-2078.0]，L2）

- 总纲10 动手者创造历史：基金会用钱的逻辑是让动手者收尾：开发者自雇时迫于生计只能把移植做到大致可用，基金会以约六个月的资助使其得以全职把剩余的收尾做完。McKusick 的说法是前 90% 完成后还有剩下 90%，资助正是为跨越这最后的鸿沟——历史由动手完成收尾的人推动，而非由提出想法的人推动。（BSDTalk EP224，[818.86-849.84]，L1）
- 总纲3 不存在进步，只有权力再分配：McKusick 转述纽约 BSD 用户组一位用户对 8 到 9 升级难度陡增的抱怨，并承认项目扩张后变更速度过快，自嘲这是重演 Linux 当年的成功灾难：变化多到令用户沮丧。项目规模的膨胀并非线性进步，而是把劳动从志愿者重新分配到受薪岗位、把变更成本重新分配给用户的过程，需要专门角色来抹平边缘。（BSDTalk EP224，[1342.02-1404.20]，L1）
