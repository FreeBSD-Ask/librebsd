# 97.2 501(c)(3) 免税资质——IRS 裁定书

## 97.2.1 IRS 裁定书的具体条款

  **要点**：IRS 于 2000.12.7 签发 Determination Letter 授予 FreeBSD Foundation 501(c)(3) 公共慈善实体身份 (509(a)(1))，条款要求基金会遵守：(1) 仅用于免税目的；(2) 不参与政治竞选；(3) 无私人利益分配；(4) 解散时资产转交同类组织
  
**史料**：IRS Determination Letter 全文、Form 1023 申请材料、Foundation 501(c)(3) 资格公开文件［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕
  
**史观**：总纲第 7 条——BSD 与 UNIX 谱系的连续性，501(c)(3) 身份使基金会可比拟其他开源基金会
  
**辨析**：501(c)(3) 与 509(a)(1) 的区别需准确表述，前者是免税类别后者是公共慈善子类
  
**文献**：IRS Publication 557；Foundation Determination Letter［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 97.2.2 四年观察期的法律约束

  **要点**：IRS 509(a)(1) 身份附带四年观察期 (2000-2004)，要求基金会在此期间证明公众支持比例达 1/3 以上 (IRC Section 170(b)(1)(A)(vi))，否则将转为私人基金会并受更严格约束
  
**史料**：IRC Section 170(b)(1)(A)(vi)、Form 1023 Schedule A、Foundation 2000-2004 年度报告 ［B］
  
**史观**：总纲第 2 条——实践先于理论，四年观察期源于实际筹款需求
  
**辨析**：观察期内基金会是否真达到 1/3 公众支持，需查年报数据
  
**文献**：IRC 170(b)(1)(A)(vi)；IRS Form 1023 Schedule A［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 97.2.3 公共慈善身份的辨析

  **要点**：公共慈善身份与私人基金会的区别：(1) 公众支持比例要求；(2) 捐赠者扣税额度更高；(3) 年度强制支出比例不同；(4) 治理结构要求不同；FreeBSD Foundation 选择公共慈善身份反映其社区属性
  
**史料**：IRS Publication 557 第 3 章、Foundation 公开审计报告［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕
  
**史观**：总纲第 8 条——文档史与代码史并重，税务文件反映治理哲学
  
**辨析**：公共慈善身份是否限制了基金会的商业活动，需查 unrelated business income 规则
  
**文献**：IRS Pub 557；Foundation 审计报告［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 97.2.4 IRS 身份史料辨析

  **要点**：IRS 身份史料疑点：(1) Determination Letter 签发日期的精确性；(2) 是否曾因公众支持不足被警告；(3) 2004 观察期结束的延续流程
  
**史料**：IRS Determination Letter 原件、Foundation 2004 年度报告、freebsd-foundation 邮件 ［A］
  
**史观**：总纲第 4 条——0 信任原则，IRS 文件需对照 Foundation 自述

**要点**：

- Gibbs 自述基金会的起源：2000 年他结束 core team 任期后，试图为操作系统实用部署所必需但缺乏吸引力的增强寻找额外资金，遂注册非营利组织创立 FreeBSD Foundation；因 IRS 要求至少三名官员，最初只有他一人，另寻两人凑足注册要求。（BSDTalk EP149，[94.68-146.46]，L1）
- 基金会的发展节点：早期即已支持开发者峰会、开发者差旅与资助开发；2004 年资金达到关键规模后雇用第一名带薪员工，此后社区支持与资助开发显著扩张；Gibbs 称 2007 年为分水岭，基金会接触到更多产品中未公开使用 FreeBSD 的厂商，并因此获得可观捐赠。（BSDTalk EP149，[154.78-226.38]，L1）
- 向基金会而非直接向项目捐赠的理由：美国捐赠者可享 501(c)(3) 免税；更关键的是商业用户需要与年年相同的法人实体打交道——FreeBSD 志愿者来去不定且多数不具可签约的公司法人地位，基金会因而成为企业与志愿者社区之间的稳定对接层，可代为寻找开发者承接性能或平台迁移需求。（BSDTalk EP149，[235.54-296.06]，L1）
- 资助工作的具体实例：与 Sun Microsystems 达成 Java 再分发协议是基金会最知名的动作之一，当时正尝试以同样方式解决 Flash 授权；Gibbs 以其非技术背景的妻子为例说明 Flash 是家庭 FreeBSD 桌面仅存的障碍，并区分最终用户层级——后端部署者重视 Java 与服务器及网络性能，开发者桌面用户则要求 GUI 实用性，基金会同时在服务器层（网络栈性能、网络栈虚拟化、服务器虚拟化、存储）与桌面层资助改进。（BSDTalk EP149，[301.46-404.94]，L1）
- 捐赠结构与运营透明度：基金会并非会员组织，会员待遇近似向地方公共电视台捐款的荣誉感；提供个人支票、Google Checkout、Groundspring 与 PayPal 四种捐赠渠道，逾 20 美元捐赠者可在 BSDCan 获赠基金会棒球帽；财务信息全部公开于网站且管理开销极低；硬件捐赠如 Cisco 提供的网络性能集群（首次真实模拟大型后端环境的万兆测试）与 NetApp 捐赠的存储 filer 均用于填补特定开发者需求；营销预算很小，仅按成本效益在 FreeBSD 书籍与技术杂志投放小幅广告。（BSDTalk EP149，[410.38-657.84]，L1）
- McKusick 口述基金会创立的初衷是充当法律实体：由基金会出面签署保密协议，开发者得以在其伞下自由交换信息而不必各自承担法律风险。他强调 FreeBSD 是先于基金会存在、自我运转的开源项目，基金会只是侧翼的辅助机构，不主导技术方向。（BSDTalk EP224，[326.60-385.24]，L1）
- 2012 年度募款目标 50 万美元，因一笔 25 万美元的挑战性配捐最终募得逾 75 万美元；基金会据此决定把完成过项目的开发者转为全职或半职受薪人员，承担发布工程、机器管理等原先纯靠志愿者的工作。McKusick 称这些人是项目而非基金会的雇员，行政开销仍仅一人，并提及首批两名全职人员位于东欧、两人全职总成本低于美国或西欧雇一人。（BSDTalk EP224，[1212.34-1293.46]，L1）
- McKusick 以 unmapped I/O 项目说明基金会的立项逻辑：写文件时数据先从用户缓冲区拷入内核缓冲区，传统做法还须把该缓冲区映射进内核地址空间，多处理器系统上每次映射变更都需处理器间中断通知所有 CPU，开销巨大；取消映射、直接告知设备物理页位置后，可用的 I/O 提速约 25%。该优化在单一架构上已有原型，但跨架构与跨子系统收尾需约半个 man-year，无单一公司愿意投入，基金会遂资助专人完成。（BSDTalk EP224，[879.62-1063.68]，L1）

**史料**：

- 本期为 BSDCan 2008 渥太华会议现场对 FreeBSD Foundation 创始人 Justin Gibbs 的一手口述访谈，保留基金会 2000 年创立过程、2004 年首名带薪员工、2007 年厂商捐赠扩张、Sun Java 再分发协议与 Flash 授权尝试、Cisco 万兆集群与 NetApp filer 捐赠等可核查线索；可对照基金会网站公开财务与年报交叉验证。（BSDTalk EP149，[26.44-67.56]，L1）
- 基金会早期资助案例之一是对 ARM 台式机与笔记本移植的资助：McKusick 提到 Alexander Rybalko 的代码已进入 head 分支，基金会提供了约 200 美元的设备供核心协作者测试，McKusick 本人担任该移植的技术评审并携带样机参加 Asia BSDCon 等会议演示。　[存疑脚注] 转写将设备厂商记作 Genesee、机型记作 Efica，疑为 Genesi 的 Efika MX，需以原始音频与产品文档复核。（BSDTalk EP224，[54.28-77.92]，L1）
- Neville-Neil 口述基金会承担的硬件与基础设施角色：东海岸托管商 NYI 提供四个机架及电力与网络，基金会以新购硬件补足捐赠旧硬件的短板；另由一家加拿大 FreeBSD 企业提供场地、电力与网络建立网络测试设施，用于 10GbE 网卡与交换机测试，基金会出资购置部分设备。　[存疑脚注] 转写将加拿大测试设施所在企业记作 Centex，疑为 Sentex，该实验室的准确名称、地点与合作时间待考。（BSDTalk EP224，[1102.12-1200.36]，L1）

**史观**：

- 总纲13 法律与道德是利益分配：Gibbs 解释 IRS 非营利法规关注捐赠集中度：若单一企业巨头注入巨款并接管基金会方向，基金会将沦为非营利门面，因此特定时期须专门动员个人小额捐赠以维持比例——法律与税收制度直接塑造了基金会的行为形态，免税资质与合规约束本质上是利益分配的制度装置。（BSDTalk EP149，[509.02-542.26]，L1）
- 总纲10 动手者创造历史：基金会用钱的逻辑是让动手者收尾：开发者自雇时迫于生计只能把移植做到大致可用，基金会以约六个月的资助使其得以全职把剩余的收尾做完。McKusick 的说法是前 90% 完成后还有剩下 90%，资助正是为跨越这最后的鸿沟——历史由动手完成收尾的人推动，而非由提出想法的人推动。（BSDTalk EP224，[818.86-849.84]，L1）
- 总纲3 不存在进步，只有权力再分配：McKusick 转述纽约 BSD 用户组一位用户对 8 到 9 升级难度陡增的抱怨，并承认项目扩张后变更速度过快，自嘲这是重演 Linux 当年的成功灾难：变化多到令用户沮丧。项目规模的膨胀并非线性进步，而是把劳动从志愿者重新分配到受薪岗位、把变更成本重新分配给用户的过程，需要专门角色来抹平边缘。（BSDTalk EP224，[1342.02-1404.20]，L1）
- 总纲13 法律与道德是利益分配：基金会的双重法律安排实质是利益分配机制：一端以法律实体吸收 NDA 等法律风险换取开发者间信息自由流动，另一端受 IRS 规制而不能由企业捐赠主导，必须维持大量个人捐赠者以保住免税资质。法律框架决定了资金来源结构与开发者行动空间。（BSDTalk EP224，[344.74-385.24]，L1）
