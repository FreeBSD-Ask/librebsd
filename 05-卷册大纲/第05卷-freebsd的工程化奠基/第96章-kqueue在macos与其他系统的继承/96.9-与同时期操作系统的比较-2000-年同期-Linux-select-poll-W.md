# 96.9 与同时期操作系统的比较：2000 年同期 Linux select/poll、Windows IOCP、Solaris /dev/poll、FreeBSD kqueue 的事件通知机制对比

## 96.9.1 select/poll 与 kqueue 的比较

  **要点**：2000 年前后 select/poll 与 kqueue 的比较维度：(1) 复杂度 O(N) vs O(1)；(2) FD_SETSIZE 限制 vs 无限制；(3) 状态保持 vs 每次注册；(4) filter 抽象 vs 原始 fd
  
**史料**：Lemon BSDCon 2000 论文对比表、Stevens《UNIX Network Programming》第 6 章、FreeBSD kqueue(2) 手册页 ［A］
  
**史观**：总纲第 2 条——实践先于理论，kqueue 的 stateful 设计源于实际 Web 服务器场景
  
**辨析**：Lemon 论文的 select/poll 测试是否在同一硬件上，需查测试环境

## 96.9.2 IOCP 与 /dev/poll 的比较

  **要点**：Windows IOCP(1995 NT 3.5) 采用线程池 + 完成端口模型，Solaris /dev/poll(1998)在内核维护就绪列表，二者均为 kqueue 的同期竞争者；IOCP 走异步 IO 路线，/dev/poll 与 kqueue 走同步事件通知路线
  
**史料**：Windows NT IOCP 文档、Banga /dev/poll 论文、Lemon BSDCon 2000 论文对比 ［B］
  
**史观**：总纲第 7 条——BSD 与 UNIX 谱系的连续性，/dev/poll 与 kqueue 同属 UNIX 谱系但路线分野
  
**辨析**：IOCP 与 kqueue 是否可比，需区分异步 IO 与事件通知两个不同模型
  
**文献**：MSDN IOCP 文档；Banga USENIX 1998 ［B］

## 96.9.3 跨机制对比分析

  **要点**：跨机制对比的核心维度：(1) 同步 vs 异步；(2) 水平触发 vs 边沿触发；(3) stateful vs stateless；(4) filter 中心化 vs composable；kqueue 与 IOCP 是同步 vs 异步两端，/dev/poll 与 epoll 是 stateful vs stateless 两端

  2000 年同期事件通知机制跨平台对照：

  | 机制 | 操作系统 | 引入年份 | 同步/异步 | 触发模式 | 状态保持 | 设计路线 |
| -- | ------ | ------ | ------- | ------ | ------ | ------ |
| `select`/`poll` | BSD/AT&T | 1983/1997 | 同步 | 水平 | stateless | 原始 fd |
| IOCP | Windows NT | 1995 | 异步 | —— | stateful | 完成端口 + 线程池 |
| `/dev/poll` | Solaris | 1998 | 同步 | 水平 | stateful | 内核就绪列表 |
| kqueue | FreeBSD | 2000 | 同步 | 水平 + 边沿 | stateful | filter 中心化 |
| epoll | Linux | 2002 | 同步 | 水平 + 边沿 | stateful | composable |

**史料**：Provos 2002 论文跨机制对比、Lemon 2000 论文、Libenzi 2002 论文 ［B］
  
**史观**：总纲第 9 条——简洁与复杂的辩证，各机制在设计空间中的权衡
  
**辨析**：跨机制对比是否考虑了硬件特性 (网卡中断、CPU 缓存)，需查 Provos 论文细节
