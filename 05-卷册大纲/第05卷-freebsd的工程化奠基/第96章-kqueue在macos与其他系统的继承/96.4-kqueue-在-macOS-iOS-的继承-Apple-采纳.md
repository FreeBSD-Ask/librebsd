# 96.4 kqueue 在 macOS/iOS 的继承——Apple 采纳

## 96.4.1 macOS 的 kqueue 集成

  **要点**：Apple 在 Mac OS X 10.3 Panther(2003.10) 将 kqueue 移植到 Darwin 内核，10.4 Tiger(2005.4) 扩展 EVFILT_USER 与 EVFILT_MACHPORT 支持 Mach 端口，10.5 Leopard(2007.10) 增加 EVFILT_FS 文件系统事件

  macOS kqueue 演化时间线：

  | Mac OS X 版本 | 发布时间 | kqueue 扩展 | 新增 filter |
| ----------- | ------ | --------- | --------- |
| 10.3 Panther | 2003-10 | kqueue 移植到 Darwin 内核 | 基础七类 filter |
| 10.4 Tiger | 2005-04 | 支持 Mach 端口与用户事件 | `EVFILT_USER`、`EVFILT_MACHPORT` |
| 10.5 Leopard | 2007-10 | 文件系统事件 | `EVFILT_FS` |

**史料**：Darwin xnu 源码 bsd/sys/event.h、Apple Developer Documentation kqueue 章节、Mac OS X 10.3 release notes ［A］
  
**史观**：总纲第 7 条——BSD 与 UNIX 谱系的连续性，macOS 通过 kqueue 延续 BSD 事件通知传统
  
**辨析**：Apple 是否对 kqueue API 做过私有扩展，需对比 Darwin 与 FreeBSD 的 event.h 差异
  
**文献**：Apple Developer Documentation；Darwin xnu 源码 ［A］

## 96.4.2 iOS 的继承路径

  **要点**：iOS 自 1.0(2007.6) 即继承 macOS 的 kqueue/kevent 实现，因 iOS 内核基于 Darwin，所有 BSD 子系统 (包括 kqueue) 被一并移植，但 iOS 沙盒限制第三方 App 直接调用 kqueue，主要通过 libdispatch/GCD 间接使用
  
**史料**：iOS 系统架构文档、libdispatch 源码中 kevent 调用、Apple Developer iOS App Sandbox 指南 ［A］
  
**史观**：总纲第 1 条——偶然性改写历史，iOS 继承 kqueue 是 Darwin 内核选择的副产品而非主动决策
  
**辨析**：iOS 沙盒是否完全禁止第三方 kqueue 调用，需查 sandboxd 配置

## 96.4.3 Apple 采纳的效应分析

  **要点**：Apple 采纳 kqueue 的影响：(1) kqueue 通过 macOS/iOS 进入消费市场；(2) libdispatch/GCD 底层使用 kqueue，使得 iOS App 开发者间接受益于 BSD 事件通知；(3) Apple 持续维护 kqueue 为 FreeBSD 上游贡献补丁
  
**史料**：libdispatch 源码、Apple 开源贡献记录、FreeBSD commit log 中 @apple.com 邮箱 ［A］
  
**史观**：总纲第 13 条——边缘者的作用，Apple 作为非 BSD 操作系统但采纳 kqueue 的边缘参与者
  
**辨析**：Apple 是否反向贡献 kqueue 改进到 FreeBSD，需查 FreeBSD commit log
  
**文献**：FreeBSD commit log；Apple Open Source ［A］

## 96.4.4 Apple 采纳史料辨析

  **要点**：Apple 采纳史料的争议：(1) Apple 是在哪个 Mac OS X 版本首次集成 kqueue(有 10.3 与 10.4 两种说法)；(2) Apple 是否因 kqueue 早于 epoll 而选择；(3) iOS 1.0 是否已包含 kqueue
