# 105.9 FreeBSD 7.x 时期的技术淘汰——ULE 成为默认、Alpha 架构退役与 ip6fw 移除

## 105.9.1 ULE 调度器在 7.1 成为 amd64/i386 默认

  **要点**：FreeBSD 7.1-RELEASE（release/7.1.0 tagger_date = 2008-12-31T22:57:14Z，tagger = Ken Smith，target_commit_hash = a1fc2b0c89a1dd2ca090ae990ab45b21363ab76e；官方公告日期 2009 年 1 月 4 日）将 ULE 调度器设为 amd64 与 i386 架构 GENERIC 内核的默认调度器，正式取代自 FreeBSD 1.0 起沿用的 4BSD 调度器；至此 ULE 从 5.0（2003）引入、5.x 默认禁用、6.0（2005）部分版本默认、7.0（release/7.0.0 tagger_date = 2008-02-24T05:45:17Z，tagger = cvs2svn；官方公告日期 2008-02-27）大幅改进但仍以 4BSD 为默认，至 7.1 完成六年漫长过渡；7.0 公告明确“ULE 大幅改进，但 7.0 仍以 4BSD 为默认，ULE 可能在 7.1 成为默认”；4BSD 调度器仍可作为内核配置选项 `SCHED_4BSD` 启用，未从源码树移除
  
**史料**：FreeBSD 7.1-RELEASE Announcement、7.0-RELEASE Announcement、freebsd-stable 邮件列表 2009.1 关于 ULE 锁死问题的报告（“Big problems with 7.1 locking up”）、7.1 Release Notes、Kinsella 2009.5 Intel 白皮书 Profiling and Debugging the FreeBSD Kernel；freebsd.duckdb freebsd-src 仓库 tags 表 release/7.0.0（tagger_date = 2008-02-24T05:45:17Z）与 release/7.1.0（tagger_date = 2008-12-31T22:57:14Z）；freebsd.duckdb freebsd-src 仓库 commits 表 ULE 首次 commit（commit_hash = 35e6168fcdc76ba3ff2927279f9a48aa5ac3157d，committer_date = 2003-01-26T05:23:15Z，author = Jeff Roberson） ［A］
  
**史观**：实践先于理论，ULE 用六年实践验证才成为默认；技术债务与代码考古，4BSD 调度器自 1980 年代沿用的 O(n) 设计债务终于在 7.1 偿还
  
**辨析**：7.1 发布后 freebsd-stable 邮件列表仍报告 ULE 在 DualCore Atom 等特定工作负载下“锁死”问题，部分用户回退至 4BSD，需查原始邮件判断 ULE 是否真已成熟；7.0 公告与 7.1 公告对 ULE 状态的表述差异（“vastly improved”vs“default”）需对照；经 freebsd.duckdb tags 表验证，7.0-RELEASE 与 7.1-RELEASE 的 tagger_date 均早于官方公告日期数日（7.0 tag = 2008-02-24，公告 = 2008-02-27；7.1 tag = 2008-12-31，公告 = 2009-01-04），叙事中须明确区分“tag 创建时间”与“公告发布时间”两类时间点，避免混淆

## 105.9.2 Alpha 架构在 7.0 退役

  **要点**：Alpha 架构在 FreeBSD 7.0-RELEASE（release/7.0.0 tagger_date = 2008-02-24T05:45:17Z，tagger = cvs2svn，target_commit_hash = ba209d619d07461cc752dcdd596ab0d9b50e847a；官方公告日期 2008-02-27）正式退役，不再作为支持架构；John Baldwin（约翰·鲍德温） 于 2006 年 5 月 11 日在 freebsd-alpha 邮件列表发布 HEADSUP 公告“Alpha support is being retired in 7.0”，理由为：(1) Alpha 端口长期无活动维护；(2) Alpha 发布质量低于其他支持架构且持续退化；(3) DEC Alpha 处理器已被其 creator（Compaq/HP）“killed”——HP 于 2004 年宣布 Alpha 终止生产；FreeBSD 6.x 仍提供 Alpha 维护以让用户过渡，7.0 起源码保留于 CVS 历史但不再构建发布；Alpha 是 FreeBSD 首个非 x86 架构（1995 年由 Wilko Bulte 等移植，4.0-1999 首次正式支持），其退役标志 1990 年代 RISC 工作站时代的结束
  
**史料**：John Baldwin 2006.5.11 freebsd-alpha 邮件 HEADSUP、FreeBSD 7.0-RELEASE Announcement、7.0 Release Notes、freebsd-alpha 邮件列表 2006.5 归档、Wilko Bulte Alpha 移植历史；freebsd.duckdb freebsd-src 仓库 tags 表 release/7.0.0（tagger_date = 2008-02-24T05:45:17Z，tagger = cvs2svn，target_commit_hash = ba209d619d07461cc752dcdd596ab0d9b50e847a） ［A］
  
**史观**：BSD 与 UNIX 谱系的连续性，Alpha 移植使 FreeBSD 摆脱 i386 中心主义，但硬件 EOL 必然导致软件退役；总纲第 1 条——偶然性改写历史，Alpha 退役为后续 sparc64（11.0）、ia64（10.0）等架构退役奠定模式
  
**辨析**：Alpha 退役的具体时间需区分“公告时间”（2006.5.11）与“实际生效时间”（7.0-RELEASE tagger_date = 2008-02-24T05:45:17Z，官方公告日期 2008-02-27）；7.0 公告列出的支持架构为 amd64/i386/ia64/pc98/powerpc/sparc64，未列 Alpha；NetBSD/alpha 仍维护，用户被引导迁移至 NetBSD/alpha 或继续使用 FreeBSD 6.x，需对照 NetBSD 状态；经 freebsd.duckdb tags 表验证，release/7.0.0 tag 创建于 2008-02-24T05:45:17Z（cvs2svn 执行 SVN tag 创建），target_commit_date = 2008-02-24T05:45:16Z，FreeBSD 官方公告日期 2008-02-27 晚于 tag 创建 3 天，叙事中须明确区分“tag 创建时间”与“公告发布时间”
  
**文献**：John Baldwin 2006.5.11 freebsd-alpha HEADSUP 邮件；FreeBSD 7.0-RELEASE Announcement；7.0 Release Notes；release/7.0.0. freebsd-src 仓库 tag [DB/OL]. 2008-02-24T05:45:17Z. tag: release/7.0.0; commit: ba209d619d07461cc752dcdd596ab0d9b50e847a ［A］

## 105.9.3 ip6fw 防火墙移除

  **要点**：FreeBSD 7.0-RELEASE 移除了 IP6 firewall 守护进程 **ip6fw(8)**，废弃自 FreeBSD 4.0（2000）起沿用的早期 IPv6 防火墙机制；ip6fw 设计仿照 IPv4 **ipfw(8)**，但仅支持 IPv6 且功能受限，2003 年起 IPFilter（ipf，由 Darren Reed（达伦·里德） 维护）、PF（OpenBSD 移植，2004 年 5.3 引入）相继提供 IPv6/IPv4 双栈支持，使 ip6fw 失去存在意义；FreeBSD 6.x 期间 ip6fw 已标记 deprecated，7.0 正式从源码树移除；用户被引导迁移至 ipfw2（IPv4/IPv6 通用）、IPFilter 或 PF；移除 commit 由 Max Laier 于 2006-05-12T20:39:23Z 完成（commit_hash = 656faadcb88cf47fe5c782ea3947a60639e3e07c，message_subject ="Remove ip6fw.  Since ipfw has full functional IPv6 support now and - in contrast to ip6fw - is properly lockes, it is time to retire ip6fw.“），次日凌晨 Max Laier 又提交两个跟进 commit：2006-05-13T05:51:52Z”Update for ip6fw removal."（commit_hash = 0794df7c7331e8306c022e8eea14e3384835e3e3）与 2006-05-13T06:08:25Z"Update UPDATING and bump **FreeBSD_version for the ip6fw removal."（commit_hash = a0a9755e0991a11c5924b16cdcdb4705f17cf224）；** FreeBSD_version bump 至 700017 标志 ip6fw 移除生效

## 105.9.4 7.x 时期淘汰史辨析

  **要点**：7.x 时期淘汰史辨析：(1) ULE 取代 4BSD 标志 FreeBSD 调度器现代转型的完成，但 4BSD 仍保留为可选项，未从源码移除，体现 BSD 渐进淘汰传统；(2) Alpha 退役是首个 FreeBSD 主动退役而非因架构消亡而退役的案例（先前 386BSD 谱系架构因衍生项目分裂自然离开），奠定了后续 ia64/sparc64 等 RISC 架构退役的程序模式；(3) ip6fw 移除是 IPv4/IPv6 分治设计向双栈统一演化的必然结果，与 OpenBSD 早期对 IPv6 防火墙的整合路径形成对照；(4) 三类淘汰（调度器、架构、防火墙）共同体现 7.x 时期的“工程清理”特征——5.x 引入新技术、6.x 稳定、7.x 清理旧技术
  
**史料**：7.0/7.1 Release Notes、freebsd-alpha/freebsd-ipfw/freebsd-stable 邮件列表、Baldwin 2006.5.11 HEADSUP、commit log ［A］
  
**史观**：总纲第 9 条——简洁与复杂的辩证，淘汰是简洁化工程但伴随阵痛；总纲第 25 条——终结与延续，淘汰不是终结而是新技术的延续
  
**辨析**：ULE 在 7.1 成为默认但 7.x 后续版本是否真“完全成熟”需查 8.0/9.0 release notes 与 EPFL 2018 USENIX ATC 批评；Alpha 退役是否加速 FreeBSD 在 RISC 工作站市场的衰落需对照 NetBSD/alpha 与 OpenBSD/alpha 状态；三类淘汰的相互独立性需评估
  
**文献**：7.0/7.1 Release Notes；freebsd-alpha/freebsd-ipfw 邮件；EPFL USENIX ATC 2018 论文；NetBSD/alpha 文档 ［A］
