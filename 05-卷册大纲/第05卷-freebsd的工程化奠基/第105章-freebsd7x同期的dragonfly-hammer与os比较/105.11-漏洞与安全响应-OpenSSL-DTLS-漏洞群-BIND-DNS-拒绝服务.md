# 105.11 漏洞与安全响应——OpenSSL DTLS 漏洞群、BIND DNS 拒绝服务、amd64/drm/i915 内核拒绝服务、ntpq/db(3)/FILE 缓冲区溢出与信息泄漏（2008-2009）

## 105.11.1 OpenSSL DTLS 漏洞群——CVE-2009-1377/CVE-2009-1378/CVE-2009-1379/CVE-2009-1387 与 FreeBSD-SA-10:10.openssl 的 vendor branch 同步

  **要点**：FreeBSD 7.x 版本周期（2008-02-01 至 2009-11-01）内，OpenSSL 是受 CVE 影响最密集的加密组件，4 个去重 CVE 均指向 DTLS 协议实现的不同缺陷类型——CVE-2009-1377 为拒绝服务、CVE-2009-1378 为拒绝服务、CVE-2009-1379 为释放后使用（use-after-free）、CVE-2009-1387 为空指针解引用。这 4 条 CVE 由 OpenSSL 项目 2009 年 8 月公告，均涉及 DTLS 协议在处理特定碎片化握手消息时的缺陷，其中释放后使用与空指针解引用两类机制在理论上具有代码执行潜力（取决于堆布局与指针指向可控性），但因 DTLS 部署范围远窄于 TLS，实际可利用性受限。FreeBSD 7.x 的修复路径为 Simon L. B. Nielsen 于 2009-08-23 同日提交的 5 条 commit：4 条 vendor 分支独立 import `b7421a6928c470446c8bd74218149745b1c1db16`（CVE-2009-1377）、`f8f8fb827d260bb6161b82bb67de04c0a4c9868c`（CVE-2009-1378）、`58c74b7534a4526075de41fd4b24bc769866523a`（CVE-2009-1379）、`f0c2a617dfb432d01bc5a716eb18dae12e6b45e3`（CVE-2009-1387），以及 1 条 vendor-crypto/openssl/dist 合并 commit `2f1ff7669c16de65bd70a0316ddc269a1cf54aea`（“Merge DTLS fixes from vendor-crypto/openssl/dist:”，同时关联 4 条 CVE）；6 天后（2009-08-29）通过 `eb2feeeeb98675d86f98eeba7015386c5e842acc` 执行 MFC r196474，回溯至 7.x 稳定分支，对应 FreeBSD-SA-10:10.openssl。这一修复模式体现 7.x 时期 OpenSSL vendor branch 同步的成熟流程——先在 vendor-crypto 分支分别 import 各 CVE 修复，再以合并 commit 同步至 HEAD，最后 MFC 至稳定分支
  
**史料**：OpenSSL 2009 年 8 月 DTLS 安全公告；FreeBSD-SA-10:10.openssl（2010-01-14 发布，涵盖 7.x 周期 OpenSSL 修复）；freebsd.duckdb freebsd-src 仓库 commit `b7421a6928c470446c8bd74218149745b1c1db16`（Simon L. B. **史观**：总纲第 4 条——分离聚合是永恒规律（原“技术选择的代价”系伪名目，按论旨就近重挂）：FreeBSD 对 OpenSSL 的依赖使加密库安全响应节奏受制于上游；专题语（不设总纲条号）——加密库组件的修复优先级（原“加密库的特殊地位”系伪名目）：DTLS 虽部署范围窄于 TLS，但作为 OpenSSL 核心代码路径之一，其漏洞修复须保持与 TLS 同等优先级；专题语（不设总纲条号）——vendor branch 流程的工程纪律（原“回溯策略的工程纪律”系伪名目）：4 条 CVE 同日 import + 1 条合并 commit + 6 天后 MFC 的节奏反映 7.x 时期 OpenSSL vendor branch 流程的成熟
  
**辨析**：4 条 CVE 的 CVSS v3 评分在 NVD 元数据中均未提取，但从技术机制（释放后使用与空指针解引用属 High 潜在等级）与 OpenSSL 安全公告分级看，应按 High 级别独立叙述；FreeBSD-SA-10:10.openssl 的发布日期（2010-01-14）晚于 commit 日期（2009-08-23/29）约 5 个月，反映 7.x 时期 SA 发布与代码修复的时序分离——代码修复先行入树，SA 文档化滞后发布，需对照 freebsd-security 邮件列表核验 SA 延迟发布原因；CVE-2009-1379 的“释放后使用”机制在 DTLS 上下文下是否可被远程利用需对照 OpenSSL 漏洞分析报告核验；commit `2f1ff7669c16de65bd70a0316ddc269a1cf54aea` 作为合并 commit 同时关联 4 条 CVE，应理解为汇总性 commit，不应重复计入 4 条独立修复 commit 的统计

## 105.11.2 BIND DNS 拒绝服务漏洞群——CVE-2008-1447 与 CVE-2009-0696 的 7.x 多分支回溯

  **要点**：BIND 在 7.x 版本周期内继续作为 DNS 拒绝服务漏洞的高发组件，2 条去重 CVE 由 ISC 分别于 2008 年 7 月与 2009 年 7 月公告。CVE-2008-1447 是 2008 年影响范围最广的 DNS 漏洞之一——Kaminsky DNS 缓存投毒漏洞，DNS 事务 ID 熵不足使攻击者可伪造应答污染递归解析器缓存，主危害为缓存投毒而非拒绝服务，BIND 9 经 9.4.2-P1 等版本修复并以源端口随机化等 0x20 加固缓解（原表述“0x20 编码查询缺陷触发拒绝服务”系机制错置，已按 ISC 9.4.2-P1 公告口径订正）；FreeBSD 修复路径为 Doug Barton 于 2008-07-12 提交的 vendor import `2e5453748ec4bd5770f7ed571b07fb9ea97fc54a`（"Merge from vendor/bind9/dist as of the 9.4.2-P1 import, including the patch from..."），同日通过 `cdab7b52f72ad118224fcf37167d386c9e1a6b63` 执行 9.3 分支同步（“Merge from vendor/bind9/dist-9.3 as of the 9.3.5-P1 import.”），对应 FreeBSD-SA-09:12.bind。CVE-2009-0696 由 ISC 2009 年 7 月公告，BIND named(8) 在处理动态更新消息时存在拒绝服务缺陷；FreeBSD 修复路径为 Simon L. B. Nielsen 于 2009-07-29 同日提交的 4 条 commit `e8c0497d6897110bc83bda93cc1eb51d54d45dc1`、`b00ac27ba5bfab50fde32290c7c2f29dd64f09f0`、`7cc4540e3901660a7899288dbae64b5440777100`、`1a56c1b168772f74301239ff3595a39388124d36`（commit_subject 均为“Fix BIND named(8) dynamic update message remote DoS.”），覆盖 HEAD 与多个稳定分支，对应 FreeBSD-SA-10:01.bind。两条 BIND CVE 的修复模式延续 6.x 时期的 vendor branch 同步规范，但 7.x 时期的多分支回溯节奏更紧凑——CVE-2009-0696 的 4 条同日 commit 显示 ISC 公告当日即完成所有分支同步
  
**史料**：ISC BIND 9.4.2-P1 公告（2008-07-08）；ISC BIND 9.6.1-P1 公告（2009-07-29）；FreeBSD-SA-09:12.bind；FreeBSD-SA-10:01.bind；freebsd.duckdb freebsd-src 仓库 commit `2e5453748ec4bd5770f7ed571b07fb9ea97fc54a`（Doug Barton，2008-07-12）、`cdab7b52f72ad118224fcf37167d386c9e1a6b63`（Doug Barton，2008-07-12）、`e8c0497d6897110bc83bda93cc1eb51d54d45dc1`（Simon L. B. Nielsen，2009-07-29）、`b00ac27ba5bfab50fde32290c7c2f29dd64f09f0`（同前）、`7cc4540e3901660a7899288dbae64b5440777100`（同前）、`1a56c1b168772f74301239ff3595a39388124d36`（同前） ［A］
  
**史观**：总纲第 13 条——法律与道德是利益分配（原“基础设施的安全负担”系伪名目，按论旨就近重挂）：DNS 作为互联网基础设施，其漏洞响应具有公共物品属性；专题语（不设总纲条号）——多分支同步的工程纪律（原“回溯策略的工程纪律”系伪名目）：7.x 时期 BIND 多分支同步的紧凑节奏反映 ISC-FreeBSD 协同机制的成熟
  
**辨析**：CVE-2008-1447 在版本周期文件中标为“bind”组件但未列技术机制类型，需对照 ISC 公告核验——根据 ISC 描述为“DNS 查询处理中的拒绝服务”，与 6.x 时期的 BIND DoS 漏洞属同一技术机制大类；CVE-2009-0696 的 4 条同日 commit 中，commit_subject 完全相同，需通过 commit_files 表区分各自回溯的分支；CVE-2008-1447 在 7.x 版本周期（2008-02-01 起）内修复于 2008-07-12，距 7.0-RELEASE（2008-02-24）仅约 5 个月，反映 7.x 初期 BIND 安全响应的及时性

## 105.11.3 amd64 与 drm/i915 内核拒绝服务——CVE-2008-2464 与 CVE-2008-3831 的 7.x 内核安全响应

  **要点**：7.x 版本周期内 2 条去重 CVE 直接涉及内核子系统层面的拒绝服务，反映 7.x 时期内核攻击面的扩展。CVE-2008-2464 由 Bjoern A. Zeeb 于 2008-09-03 提交修复 `bf0d5f8e166626d5874eaa412e87863e9a0ad700`（"Fix a bug, when a specially crafted ICMPV6 MLD packet could lead to an integer d..."），针对 IPv6 多播监听发现协议（MLD）处理中的整数下溢缺陷——特定构造的 ICMPv6 MLD 报文可触发内核整数下溢，导致系统崩溃或拒绝服务，对应 FreeBSD-SA-08:07.amd64；同日 Bjoern A. Zeeb 提交 2 条 MFC commit `67bc00ba260b141ca9f5c7f67351e8a9bde3ffab` 与 `e4b3b2d4296df1a5c3317c3984327e92939b0526`（commit_subject 均为“MFC: svn 182713, cvs rev. 1.35 mld6.c”）完成稳定分支回溯。CVE-2008-3831 由 Robert Noland 于 2008-10-25 提交修复 `bee8d4f213e6c63efc321c0f942d4d7fe6900a1c`（"drm/i915: fix ioremap of a user address for non-root (CVE-2008-3831)"），针对 Direct Rendering Manager（DRM）i915 驱动中的 ioremap 缺陷——非 root 用户通过特定 ioctl 可触发内核将用户态地址误映射为 I/O 端口，导致内核空间污染或权限提升，无对应 FreeBSD SA 编号但 commit_subject 直接引用 CVE。这两条漏洞的技术机制不同——CVE-2008-2464 是网络协议栈的整数下溢（DoS 路径），CVE-2008-3831 是图形驱动栈的权限边界突破（潜在 LPE 路径），但均属 7.x 时期内核子系统攻击面扩展的体现
  
**史料**：FreeBSD-SA-08:07.amd64（2008-09-03）；CVE-2008-3831 NVD 条目；freebsd.duckdb freebsd-src 仓库 commit `bf0d5f8e166626d5874eaa412e87863e9a0ad700`（Bjoern A. Zeeb，2008-09-03）、`67bc00ba260b141ca9f5c7f67351e8a9bde3ffab`（Bjoern A. Zeeb，2008-09-03）、`e4b3b2d4296df1a5c3317c3984327e92939b0526`（Bjoern A. Zeeb，2008-09-03）、`bee8d4f213e6c63efc321c0f942d4d7fe6900a1c`（Robert Noland，2008-10-25） ［A］
  
**史观**：专题语（不设总纲条号）——功能扩展的攻击面代价（原“技术选择的代价”系伪名目）：IPv6 与 DRM 子系统的功能扩展引入新攻击面，安全响应需同步跟进；总纲第 13 条——法律与道德是利益分配（原“基础设施的安全负担”系伪名目，按论旨就近重挂）：内核网络栈与图形栈的漏洞响应直接影响 entire userbase；专题语（不设总纲条号）——子系统响应流程差异（原“回溯策略的工程纪律”系伪名目）：CVE-2008-2464 的同日 MFC 节奏与 CVE-2008-3831 的无 SA 仅 commit 直修形成对比，反映不同子系统的安全响应流程差异
  
**辨析**：FreeBSD-SA-08:07.amd64 的 SA 编号虽含“amd64”但实际漏洞位于 ICMPv6 MLD 协议栈（sys/netinet6/），SA 命名可能源于该漏洞在 amd64 平台上的高影响——需对照 SA 全文核验；CVE-2008-3831 在版本周期文件中无对应 SA 编号，反映 7.x 时期 DRM 子系统漏洞响应流程的不一致——部分漏洞经 SA 正式发布，部分仅以 commit 形式入树；CVE-2008-2464 的 commit_subject 摘要“integer d...”（疑为“integer underflow”或“integer decrement”）需对照完整 commit message 核验；CVE-2008-3831 的“non-root”触发条件需对照 i915 ioctl 接口权限模型核验是否已通过其他机制（如 devfs ruleset）部分缓解
  
**文献**：FreeBSD-SA-08:07.amd64；CVE-2008-2464 NVD 条目；CVE-2008-3831 NVD 条目；freebsd.duckdb freebsd-src 仓库 amd64/drm/i915 相关 commit（2008-09 至 2008-10） ［A］

## 105.11.4 ntpq/db(3)/FILE 缓冲区溢出与信息泄漏合并叙述——CVE-2008-0122/CVE-2009-0159/CVE-2009-0590/CVE-2009-1515

  **要点**：7.x 版本周期内 4 条去重 CVE 涉及 base system 工具与库的中低级别漏洞，按技术机制类型分为缓冲区溢出类与信息泄漏类两组。缓冲区溢出类包含 3 条 CVE：CVE-2008-0122 由 Doug Barton 于 2008-06-03 提交修复 `10e8d52e884dd8d7592baddbb08a4cf7547d5c1e`（"Update to version 9.3.5. It contains the latest bug fixes, updates to root serve..."），对应 BIND 9.3.5 vendor import，版本周期文件中标技术机制为“整数溢出/越界”但 commit_subject 显示为 BIND 综合更新——具体漏洞细节需对照 ISC 9.3.5 Release Notes 核验；CVE-2009-0159 由 Ollivier Robert 于 2009-04-19 提交修复 `8c0610b9602c2bdb6f856c0808ad655599ad68f6`（"Prevent a buffer overflow in ntpq. Patch taken from the PR database after being..."），针对 **ntpq(1)** 在处理特定响应时的缓冲区溢出，同日通过 `0963cc7dac321263e6f595192d7e75b40e6a889e` 完成合并；CVE-2009-1515 由 Xin LI 于 2009-05-18 提交修复 `b873e82fedb8026ff397a976c38d4182a21da706`（“Virgin import of Christos Zoulas（克里斯托斯·祖拉斯）'s FILE 5.03.”），通过 vendor import FILE 5.03 修复缓冲区溢出，同日通过 `70b95ceeab5bd5d57083730a2e42e540584aa7ce` 完成合并。信息泄漏类包含 1 条 CVE：CVE-2009-0590 由 Colin Percival 于 2009-04-22 提交修复 `57895cdc764809ad29336431ee6b43c68fe15f15`（"Don't leak information via uninitialized space in db(3) records. [09:07]"），针对 **db(3)** 库在写入记录时未初始化填充字节的信息泄漏缺陷——攻击者可通过读取未初始化字节获取敏感数据残留，同日 Colin Percival 提交 7 条同 commit_subject 的 MFC commit（`5186ccc403b38db31bf42f14e5c68ca8142200b2`、`3d389dec20be1a2d8523e288debae0cee93201a2`、`60a77caa53044fa73ad877fc932f07490a9f7ab9`、`580e89b3bf883799f480ef10d52ae83d8cc6c5fe`、`62309d46fc630a899fdca5ddfe81435579b8f347`、`52521a3ba52b62d40d99eb07f57afd3189f3d061`、`e55ab0a54b06a1f09099d92989dc5dade6fec89f`）覆盖多个稳定分支，对应编号 [09:07] 提示为 FreeBSD-SA-09:07 系列的一部分。这 4 条 CVE 的修复模式体现 7.x 时期 base system 工具与库的多路径修复——vendor import（BIND/FILE）、自研补丁（ntpq）、base system 库修复（db(3)）三种路径并存

## 105.11.5 架构关联总结——ULE 默认化、Superpage、DTrace 引入下的安全响应节奏

  **要点**：7.x 版本周期共 40 条 commit（29 CVE + 11 security fix），月均约 1.90 条/月，介于 6.x 的 1.07 条/月与 5.x 的 3.64 条/月之间。这一回升不能简单解读为“7.x 安全质量下降”，而是反映三重架构因素：其一，7.x 时期 ULE 在 7.1-RELEASE（2008-12-31）成为 amd64 与 i386 GENERIC 内核默认，ULE 的每 CPU 运行队列与 CPU 亲和性引入新的调度路径——但 ULE 本身未直接产生 CVE，反映 Jeff Roberson 在 5.x/6.x 长期迭代后的代码成熟度；其二，7.x 时期 Superpage 大页支持扩展了虚拟内存子系统（VM）的页表管理路径，但 VM 层在 7.x 版本周期内未直接产生 CVE，反映 Superpage 设计的稳健性；其三，7.x 时期 DTrace 引入（John Birrell 移植自 Solaris）作为观测工具，本身非攻击面扩展，但 DTrace 引入过程中对内核 hook 点的扩展可能间接影响其他子系统的安全审计路径——CVE-2008-3831 的 drm/i915 漏洞虽与 DTrace 无直接关联，但 DTrace 引入后的内核可观测性提升有助于此类漏洞的发现与修复。11 条 security fix commit 中，Bjoern A. Zeeb 于 2008-03-08 提交的 `c4b41bd9226bc9d70a77e82be6abf50f91f03189`（"MFC rev. 1.15 ipsec_input.c Though we are only called for the three security protocols we can..."）涉及 IPsec 输入路径的安全检查加固，与 7.x 时期 IPv6 网络栈扩展（CVE-2008-2464 的 MLD 缺陷）属同一网络栈安全响应脉络；Robert Watson 于 2008-12-25 提交的 `9c232f86cabc28c011046d7d2e8ba7f6a5f80866`（"Following the recent security advisory, add a comment describing our invariants and approach for pro..."）是 SA 后续的代码注释加固，反映 7.x 时期 Security Officer 团队对代码可读性与安全 invariant 文档化的重视；John Baldwin（约翰·鲍德温） 于 2009-03-10 提交的 `7f307a7ee8bd205f347128834017f3667adcde0b`（"MFC: Add a flag to tag individual sysctl leaf nodes as MPSAFE. Tag the following nodes as MPSAFE: -"）是 MPSAFE sysctl 标记的扩展，延续 6.x 时期的 MPSAFE VFS 收束路线。整体看，7.x 的安全响应节奏标志着 FreeBSD 进入“架构稳定 + 第三方组件密集响应”的阶段——架构本身的 CVE 数量下降，但 OpenSSL/BIND 等第三方组件的 CVE 密度上升
  
**史料**：freebsd.duckdb freebsd-src 仓库 7.x 版本周期 commit 统计（40 条 security-related commit / 21 个月）；6.x 版本周期 commit 统计（29 条 / 27 个月，月均 1.07）；5.x 版本周期 commit 统计（80 条 / 22 个月，月均 3.64）；commit `c4b41bd9226bc9d70a77e82be6abf50f91f03189`（Bjoern A. Zeeb，2008-03-08）、`9c232f86cabc28c011046d7d2e8ba7f6a5f80866`（Robert Watson，2008-12-25）、`7f307a7ee8bd205f347128834017f3667adcde0b`（John Baldwin，2009-03-10）；FreeBSD 7.1-RELEASE Release Notes（ULE 默认化）；John Birrell DTrace 移植 commit 历史 ［A］
  
**史观**：总纲第 5 条——没有必然性，只有偶然性（原“偶然性改写历史”系伪名目，按权威表重挂）：ULE 在 5.3 因稳定性问题被禁用，6.x 实验性保留，7.1 终成默认，这一路径使 ULE 的安全响应在 7.x 时期进入“成熟期”而非“转型期”；专题语（不设总纲条号）——新特性的审计复杂度代价（原“技术选择的代价”系伪名目）：DTrace 引入提升内核可观测性但扩展 hook 点，Superpage 引入扩展 VM 路径，二者均未直接产生 CVE 但增加工程审计复杂度；总纲第 13 条——法律与道德是利益分配（原“基础设施的安全负担”系伪名目，按论旨就近重挂）：稳定期架构本身的 CVE 下降不等于安全负担减轻，第三方组件的安全响应成为主要工程投入
  
**辨析**：7.x 的 commit 月均（1.90）介于 5.x（3.64）与 6.x（1.07）之间，须谨慎解读——5.x 高位源于架构转型期的新代码密集审计，6.x 低位源于架构稳定后的低响应需求，7.x 回升主要源于 OpenSSL DTLS 漏洞群（4 条 CVE 同日修复）与 BIND 多分支回溯（CVE-2009-0696 的 4 条同日 commit）的统计放大；扣除 OpenSSL DTLS 漏洞群后 7.x 月均约 1.65 条/月，与 6.x 的 1.07 接近；ULE 在 7.x 版本周期内未直接产生 CVE，反映 ULE 在 6.x 实验性阶段的迭代投入已收敛其代码风险；DTrace 在 7.x 版本周期内未直接产生 CVE，但 DTrace 引入过程中的内核 hook 点扩展是否间接影响其他子系统的安全审计路径需对照 freebsd-hackers 邮件列表核验；Superpage 在 7.x 版本周期内未直接产生 CVE，反映 Superpage 设计的页表管理路径与已有 VM 子系统兼容性良好；11 条 security fix commit 中有 4 条为 Antoine Brodin 与 Marc Fonvieille 的文档/工具类 commit（`47a54f59de945d901288a464f680dd0efc3fb9e8`、`11442758108b337bb1967efcdccf42d9ac91d6e1`、`c4f7dce098d812d78d6abe962ce3c6b91df482b6`、`387424df40d26125deb66790003549747d706da7`、`ae8b993a1e6fa3468d9df04f043fbc5c30881cac`、`ad0a35bedafc1426d53fccc60d3749785b9170b8`、`0df811a678955f88546d8479f0efb3659b9a970b`），扣除后 7.x 代码级安全修复约 7 条/21 个月 ≈ 0.33 条/月，远低于 CVE commit 的 1.38 条/月，反映 7.x 时期安全响应以 CVE 驱动为主
