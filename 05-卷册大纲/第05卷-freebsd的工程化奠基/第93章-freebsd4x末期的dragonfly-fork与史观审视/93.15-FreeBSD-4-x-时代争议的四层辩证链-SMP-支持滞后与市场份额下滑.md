# 93.15 FreeBSD 4.x 时代争议的四层辩证链——SMP 支持滞后与市场份额下滑

## 93.15.1 批评层：SMP 支持滞后与市场份额下滑的批评

  **要点**：对 FreeBSD 4.x 时代的批评集中于两点——SMP 支持滞后与市场份额下滑。SMP 支持层面，FreeBSD 4.x 全系列沿用 Giant lock（单一内核大锁）模型，任何时刻仅一个 CPU 可在内核态运行，多核扩展性受限；4BSD 调度器为 O(n) 算法，无 CPU 亲和性、无 SMT 支持。同期 Linux 2.4（2001.1）已引入改进的 SMP 支持，Linux 2.6（2003.12）进一步以 O(1) 调度器与细粒度内核抢占大幅提升多核性能。FreeBSD 的 SMPng（SMP Next Generation）项目虽 2001 年启动，但直至 5.0-RELEASE（2003.1.16）才引入初步架构，4.x 全系列未能受益。市场份额层面，Linux 2.4 成熟后蚕食 FreeBSD 在 ISP 与企业市场的份额，Red Hat Enterprise Linux（2003）进一步加速这一趋势；4.x 代码冻结期间部分用户因 5.x 不稳定、4.x 不再更新而转向 Linux。批评者将 4.x 时代定性为 “工程成功但商业失败”——Jails、kqueue 等技术领先未转化为市场优势，归因于 BSD 许可证的宽松、营销不足、Linux 商业生态的资本投入。
  
**史料**：FreeBSD 4.0-RELEASE 公告（2000.3.14，Jordan K. Hubbard（乔丹·哈伯德） 发布，经 WebFetch 一手核验 <https://www.freebsd.org/releases/4.0R/announce/>）；FreeBSD 4.11-RELEASE 公告（2005.1.25，Ken Smith 发布，明确称 "This is expected to be the last release from the RELENG_4 branch"，经 WebFetch 一手核验 <https://www.freebsd.org/releases/4.11R/announce/>）；freebsd.duckdb freebsd-src 仓库 commits 表 ULE 调度器首次 commit 为 2003-01-26 Jeff Roberson（5.0-RELEASE 之后），印证 4.x 全程沿用 4BSD 调度器；Linux 2.4 ChangeLog；Red Hat Enterprise Linux 发布公告（2003）；本章 37.12.5 节 Giant 锁与 4BSD 调度器考据 ［A］
  
**史观**：总纲第 16 条——经济周期，Linux 2.4 成熟期与互联网泡沫后企业成本压力叠加；总纲第 11 条——商品是形式主义，“市场成功” 本身是形式主义的权力运作
  
**辨析**：考据过程留痕——【查证来源】FreeBSD 4.0-RELEASE 公告日期 2000.3.14 与 4.11-RELEASE 公告日期 2005.1.25 均经 WebFetch 一手核验；4.x 全系列沿用 Giant lock 与 4BSD 调度器经 freebsd.duckdb freebsd-src 仓库 commits 表 ULE 首次 commit 时间（2003-01-26，5.0-RELEASE 之后）反证；Linux 2.4 SMP 改进的具体基准测试数据未在批评层史料中直接引用，需对照 Linux 2.4 ChangeLog 与同期基准测试报告核验；【交叉验证方法】FreeBSD 4.0/4.11 公告（一手发布文档）、freebsd.duckdb freebsd-src commits 表（代码级证据）、Linux 2.4 ChangeLog（一手发布文档）三方互证——4.x 版本周期（2000.3 至 2005.1）与 Linux 2.4（2001.1）/2.6（2003.12）发布时序吻合，SMP 支持差距在 2001 至 2003 年窗口确凿存在；【0 信任原则·“市场份额下滑” 的量化困境】批评层所称 “市场份额下滑” 缺乏权威量化数据，Netcraft Web Server Survey 统计的是 Web 服务器软件（Apache/nginx/IIS）而非操作系统，FreeBSD 作为 Apache 后端操作系统的份额需从 Apache 部署统计间接推断，且 BSD 系统广泛部署于路由器、存储设备、嵌入式场景，此类场景不在 Netcraft 统计范围内，故 “市场份额下滑” 的量化判断须以具体市场细分（Web 服务器、ISP、企业桌面、嵌入式）为据，不得笼统断言；【存疑判定依据】“工程成功但商业失败” 的定性本身带有前理解——以 “市场成功” 作为评判标准，这一标准本身是争议焦点，批评层的归因（BSD 许可证、营销不足、Linux 商业生态）均需对照具体企业迁移案例核验
  
**文献**：FreeBSD 4.0-RELEASE Announcement [EB/OL]. 2000-03-14. <https://www.freebsd.org/releases/4.0R/announce/>；FreeBSD 4.11-RELEASE Announcement [EB/OL]. 2005-01-25. <https://www.freebsd.org/releases/4.11R/announce/>；freebsd.duckdb freebsd-src 仓库 commits 表（ULE 首次 commit 2003-01-26）；Linux 2.4 ChangeLog；Red Hat Enterprise Linux 发布公告（2003）［A］

## 93.15.2 反批评层：FreeBSD 阵营的反批评

  **要点**：FreeBSD 阵营对上述批评的反驳集中于三点——稳定性优势、SMP 重构的工程难度、BSD 的服务器市场定位不同于 Linux 的桌面市场。稳定性层面，4.x 因 Giant lock 保护下内核路径简单而成为 ISP 与 Web 托管提供商的 “黄金时代”，Yahoo!（1998 至 2000 年大规模部署）与 Hotmail（Microsoft 收购后部分保留至 2000 年代初）的超大规模部署证明 4.x 能支撑生产级 Web 服务；4.11-RELEASE 公告明确称 4.x 为 “Errata Branch”，安全修复与功能性修复在 RELENG_4_11 分支持续至 2006 年，证明 4.x 的长期稳定价值。SMP 重构的工程难度层面，SMPng 不是简单的锁拆分，而是对整个内核子系统的细粒度锁重构，涉及网络栈、文件系统、调度器、驱动模型的全面改造，5.0 至 5.2 的性能倒退恰恰证明 SMPng 路线的工程代价——细粒度锁竞争导致 cacheline 抖动，部分场景下 SMP 性能反不如 4.x Giant lock 模型。服务器市场定位层面，FreeBSD 的核心用户群是 ISP 与 Web 托管提供商，而非桌面用户，以桌面市场份额指标衡量 FreeBSD 是范畴错误；BSD 系统广泛部署于路由器（如 JunOS）、存储设备、嵌入式场景，此类部署不计入传统市场份额统计。
  
**史料**：FreeBSD 4.11-RELEASE 公告（Ken Smith 明确称 “Errata Branch” 与 “last release from the RELENG_4 branch”，Yahoo! 列入致谢名单，经 WebFetch 一手核验）；Yahoo! BSDCon 2000 演讲与 Jeremy Zawodny 工程博客（本章 37.5.1 节考据）；Hotmail 架构文档（本章 37.5.2 节考据）；Dillon 2003-07-16 DragonFly BSD 公告中关于 5.x “too heavily mutexed” 的判断（本章 37.9.2 节考据）；freebsd-performance 邮件列表 2003 至 2004 年关于 5.x 性能倒退的讨论；JunOS BSD 内核渊源文档 ［A］
  
**史观**：总纲第 7 条——技术选择即政治选择，4.x 选择 “Giant 锁与 4BSD 调度器” 反映 “稳定性优先” 的技术政治选择；总纲第 2 条——实践先于理论，Yahoo! 与 Hotmail 的超大规模部署是 4.x 稳定性的实践证明
  
**辨析**：考据过程留痕——【查证来源】4.11-RELEASE 公告中 “Errata Branch” 与 “last release from the RELENG_4 branch” 表述经 WebFetch 一手核验（<https://www.freebsd.org/releases/4.11R/announce/>），Yahoo! 列入 4.11 致谢名单（"Many companies donated equipment, network access, or man-hours to finance the release engineering activities for 4.11 including The FreeBSD Mall, Hewlett Packard, Yahoo!, Sentex Communications, and NTT/Verio"）经一手核验，印证 Yahoo! 在 4.x 末期的持续参与；5.x 性能倒退的判断经 Dillon 2003-07-16 公告（本章 37.9.2 节一手核验）与 freebsd-performance 邮件列表讨论互证；【交叉验证方法】4.11 公告（一手发布文档）、Yahoo! 致谢记录（一手发布文档）、Dillon 公告（一手邮件列表存档）三方互证——4.x 在 2005 年仍有 Yahoo! 等大型企业支持，与 “市场份额下滑” 的批评叙事形成张力；【0 信任原则·“稳定性优势” 的非量化性】反批评层所称 “稳定性优势” 同样缺乏量化基准测试数据，“黄金时代” 的称谓部分来自社区记忆而非严格的平均故障间隔统计，史家须区分 “社区声誉” 与 “量化稳定性”；JunOS 等 BSD 衍生部署的具体规模需对照厂商公开文档核验，不得以 “广泛部署” 笼统断言；【存疑判定依据】“服务器市场定位不同于桌面市场” 的论证在 2003 年后因 Linux 以 RHEL 进入服务器市场而部分失效，反批评层的论证在 4.x 末期（2004 至 2005）的说服力较 4.x 早期（2000 至 2001）有所下降
  
**文献**：FreeBSD 4.11-RELEASE Announcement [EB/OL]. 2005-01-25. <https://www.freebsd.org/releases/4.11R/announce/>；Yahoo! BSDCon 2000 演讲；Matthew Dillon（马修·狄龙）. Annoucning DragonFly BSD! [EB/OL]. 2003-07-16. <https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>；freebsd-performance 邮件列表存档 ［A］

## 93.15.3 再回应层：批评方的再回应

  **要点**：批评方对反批评的再回应指出，反批评的三点论证在长期视角下均被削弱。稳定性优势的侵蚀——Linux 2.6（2003.12）以 O(1) 调度器、内核抢占、细粒度 SMP 锁成熟后，FreeBSD 4.x 的稳定性优势在 Linux 2.6 的工程化成熟中被追平，而 4.x 的 SMP 劣势无法通过稳定性弥补；Yahoo! 在 2000 年代后期逐步引入 Linux 与自研系统，Hotmail 在 2000 年代初完成 Windows 迁移，4.x 的超大规模部署案例随时间衰减。SMP 重构工程难度论证的对称性——Linux 同样面临从 2.4 到 2.6 的 SMP 重构工程难度，但 Linux 以更短的时间完成，说明工程难度不是充分的辩护；FreeBSD 5.x 的性能倒退（2003 至 2005）恰恰暴露 SMPng 路线的执行问题，而非单纯的客观难度。服务器市场定位论证的失效——Red Hat Enterprise Linux（2003）与 SUSE Linux Enterprise Server 进入服务器市场后，“BSD 服务器与 Linux 桌面” 的二元区分不再成立，Linux 在 ISP 与企业服务器市场直接竞争 FreeBSD。批评方进一步指出，BSD 许可证的宽松允许 Apple（Darwin）、Sony（PS3）等商业使用而未强制回馈，“代码散逸” 使 FreeBSD 的技术贡献未能转化为社区资源积累，这是 BSD 相对 GPL 的结构性劣势。
  
**史料**：Linux 2.6 ChangeLog（2003.12）；Red Hat Enterprise Linux 发布公告（2003）；SUSE Linux Enterprise Server 文档；Yahoo! 2000 年代后期架构演化报告；Hotmail Windows 迁移完成报告（本章 37.5.2 节考据）；Apple Darwin 源码与许可证；Sony PS3 操作系统文档；BSD vs GPL 比较论文（本章 37.13.3 节考据） ［B］
  
**史观**：总纲第 22 条——知识注定过时，4.x 稳定性优势在 Linux 2.6 成熟后部分过时；总纲第 3 条——不存在进步，只有权力再分配，“Linux 完成更快” 的判断本身是权力话语
  
**辨析**：考据过程留痕——【查证来源】Linux 2.6 发布时间（2003.12）与 RHEL 发布时间（2003）经公开文档核验；Yahoo! 2000 年代后期架构演化的具体细节部分来自企业内部报告，部分未公开，需对照公开演讲与媒体报导；Apple Darwin 与 Sony PS3 的 BSD 代码使用经各自公开源码与文档核验；【交叉验证方法】Linux 2.6 ChangeLog（一手发布文档）、RHEL 发布公告（一手发布文档）、Apple Darwin 源码（一手代码）三方互证——Linux 在 2003 年同时完成 SMP 成熟与企业市场进入，与 FreeBSD 5.x 性能倒退形成对照；【0 信任原则·“Linux 完成更快” 的归因困境】批评方称 “Linux 以更短时间完成 SMP 重构” 的归因涉及多重因素——Linux 商业资本投入（IBM、Red Hat 雇佣开发者）、内核架构差异、社区规模差异，不得简化为 “BSD 工程能力不足”；“代码散逸” 的判断需区分 “未强制回馈”（BSD 许可证事实）与 “未回馈”（实际可能存在部分回馈），Apple Darwin 的部分代码确实回流至 FreeBSD 社区，Sony PS3 的 BSD 使用因封闭生态无法回馈；【存疑判定依据】Yahoo! 与 Hotmail 的具体迁移时间线部分依赖媒体报导与企业内部报告，量化数据难以获取；“结构性劣势” 的定性本身带有 GPL 阵营前理解，BSD 阵营不认同 “代码散逸” 为劣势
  
**文献**：Linux 2.6 ChangeLog；Red Hat Enterprise Linux 发布公告（2003）；Apple Darwin 源码与许可证；Sony PS3 操作系统文档；BSD vs GPL 比较论文 ［B］

## 93.15.4 合图层：从项目统摄史观审视争议

  **要点**：综合三方立场，FreeBSD 4.x 时代 SMP 支持滞后与市场份额下滑的争议并非可通过对一方判定 “正确” 而消解，而是 BSD 谱系在 “稳定性与扩展性” “服务器与桌面” “改革与革命” 多重张力下的结构性呈现。批评层与反批评层各自的前理解均内部自洽——批评层以 “市场成功” 为评判标准，故 4.x 是 “工程成功但商业失败”；反批评层以 “生产稳定性” 为评判标准，故 4.x 是 “黄金时代”。两种前理解的不可通约使争议不可调和。合图层不判定 “谁对谁错”，而承认争议的不可调和性——4.x 的稳定性优势与 SMP 劣势是同一枚硬币的两面，Giant lock 既保护了稳定性又限制了扩展性，二者无法在 4.x 架构内同时实现；SMPng 路线的长期成熟（7.x 后）与 5.x 短期性能倒退是同一工程选择的时序分裂，短期代价与长期收益无法在 2003 年时点同时呈现。BSD 许可证的宽松既是 “代码散逸” 的结构性劣势，也是 “商业采用” 的结构性优势，二者是同一许可证哲学的两面。项目统摄史观提醒史家：争议的不可调和性本身是历史真实的一部分，和解不等于消解分歧，而是承认分歧的结构性呈现。
  
**史料**：上述 37.15.1 至 37.15.3 节综合史料；项目史观总纲第 25 章（据原文第 25 章，第 13、19、21 条）；FreeBSD 5.x/6.x/7.x Release Notes ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律，4.x 的稳定性与 5.x 的扩展性是分离后的各自聚合；总纲第 8 条——本体论上各方平等，批评层与反批评层的评判标准在本体论上无高下；总纲第 6 条——和解优于斗争，合图层呈现的是结构性和解而非逻辑裁决
  
**辨析**：考据过程留痕——【查证来源】本节史料综合 37.15.1 至 37.15.3 节一手与二手史料；项目史观总纲第 13、19、21 条原文经 Read 一手核验（据原文第 25 章，第 17 行第 13 条 “法律与道德是利益分配”，第 23 行第 19 条 “解释学循环是历史认识的根本条件”，第 25 行第 21 条 “革命与改革是历史方法论的分歧”）；【交叉验证方法】项目史观总纲原文（一手哲学源材料）、FreeBSD 4.x/5.x/7.x Release Notes（一手发布文档）、freebsd.duckdb 代码级证据三方互证——总纲第 4 条与 4.x/5.x 架构分离互证，总纲第 8 条与双方评判标准对等互证；【0 信任原则·合图层的立场中立】合图层须严格保持双方对称呈现，不得因 Linux 后续市场主导即判定批评层 “正确”，亦不得因 FreeBSD 4.x 的 “黄金时代” 声誉即判定反批评层 “正确”——“成功” 与 “失败” 的判定标准本身是回溯性建构，史家须以 2000 至 2005 年时点的技术语境判断双方立场的合理性；“不可调和性” 的判断须以双方前理解的不可通约为据，而非以 “双方都有道理” 的折中主义敷衍；【存疑判定依据】“结构性呈现” 的判断须以 BSD 谱系长期演化的多案例（如 OpenBSD fork 自 NetBSD、DragonFly fork 自 FreeBSD）对照核验，若 BSD 谱系长期呈现 “稳定性与扩展性” 张力，则 “结构性” 判断成立

### 93.15.5 项目统摄史观审视：许可证哲学、解释学循环与革命改革

FreeBSD 4.x 时代 SMP 支持滞后与市场份额下滑的争议，从项目史观总纲第 13、19、21 条切入审视，呈现三层哲学意涵。

总纲第 13 条 “法律与道德是利益分配” 在此争议中得到深刻印证。批评层将 4.x 定性为 “工程成功但商业失败”，归因之一是 BSD 许可证的宽松允许 “代码散逸”——Apple Darwin、Sony PS3 等商业使用未强制回馈。但项目统摄史观提醒史家：BSD 与 GPL 的差异不是道德优劣，而是利益分配机制的政治选择。BSD 许可证将利益分配给商业采用者（Apple、Sony 获得代码使用权），GPL 许可证将利益分配给社区（强制回馈保证代码回流）。“代码散逸” 的批评本身是 GPL 阵营前理解下的利益分配偏好，BSD 阵营则将同一事实命名为 “商业采用的自由”。“市场份额下滑” 的批评同样涉及利益分配——市场份额是商业资本（IBM、Red Hat 对 Linux 的投入）与社区劳动（FreeBSD 志愿者贡献）之间的利益分配结果，而非纯粹的技术优劣裁决。4.x 时代的 “黄金时代” 声誉与 “商业失败” 定性，是同一事实在不同利益分配框架下的两种呈现，二者在本体论上平等。

总纲第 19 条 “解释学循环是历史认识的根本条件” 在此争议中显现于双方前理解的不可通约。批评层的前理解是 “市场成功等于技术成功的衡量标准”，故 4.x 的 SMP 滞后与市场份额下滑是 “失败”；反批评层的前理解是 “生产稳定性等于技术成功的衡量标准”，故 4.x 的 Giant lock 与长期维护是 “黄金时代”。两种前理解各自内部自洽，且都无法被对方的论证说服——这正是解释学循环的体现，分歧不是逻辑错误而是前理解的不可通约。权力与知识的共谋在历史书写中显现：Linux 的市场胜利被 “记录” 为 “技术进步的必然”，FreeBSD 在路由器、存储设备、嵌入式场景的隐性部署被 “遗忘” 为 “不计入市场份额”；4.x 的 “黄金时代” 声誉被 “记录” 为 “稳定性传奇”，5.x 的性能倒退被 “遗忘” 为 “过渡期的阵痛”。何种事实被 “记录” 为争议的核心，何种事实被 “遗忘” 为边缘，本身就是史家权力的行使——这一权力无法消除，但须自反地显化。合图层承认争议不可调和，这一承认本身是解释学循环的诚实表达，而非逻辑裁决。

总纲第 21 条 “革命与改革是历史方法论的分歧” 在此争议中映射于 SMP 路线的选择。Linux 选择 “革命” 路径——从 2.4 到 2.6 以 O(1) 调度器与细粒度 SMP 锁重写内核同步机制，短期内付出工程代价但快速获得多核扩展性；FreeBSD 选择 “改革” 路径——SMPng 在 4.x 基础上渐进重构，保留 Giant lock 作为兜底，逐步引入细粒度锁，长期内保持稳定性但短期内多核扩展性滞后。项目统摄史观明确指出 “改革的困难远高于革命”——SMPng 须在不破坏 4.x 稳定性的前提下逐步替换锁模型，每一步改造都须保证向后兼容，这一约束使改革路径的工程代价远高于革命的推倒重来。但改革路径的长期收益是 4.x 在 2000 至 2005 年的 “黄金时代” 稳定性，这一稳定性是革命路径无法在短期内获得的。“破山中贼易，破心中贼难”——Linux 的革命路径破除了 2.4 时代的 SMP 限制（山中贼），但 FreeBSD 的改革路径须破除 “稳定性与扩展性不可兼得” 的工程心智模型（心中贼），后者的困难远高于前者。项目统摄史观提醒史家：革命与改革是方法论分歧而非优劣判断，4.x 的 “改革” 在 2003 年时点显得滞后，但在 2000 至 2005 年的 “黄金时代” 中证明了其稳定性价值，两种路径各有其代价与收益。

**要点**：本节从项目史观总纲第 13、19、21 条切入，审视 FreeBSD 4.x 时代 SMP 支持滞后与市场份额下滑争议，呈现三层哲学意涵——总纲第 13 条“法律与道德是利益分配”揭示 BSD 与 GPL 的差异是利益分配机制的政治选择而非道德优劣，“代码散逸”与“商业采用的自由”是同一事实在不同利益分配框架下的两种命名；总纲第 19 条“解释学循环是历史认识的根本条件”揭示批评层与反批评层前理解的不可通约，何种事实被“记录”为争议核心、何种事实被“遗忘”为边缘，本身就是史家权力的行使；总纲第 21 条“革命与改革是历史方法论的分歧”映射于 SMP 路线选择——Linux 的“革命”路径与 FreeBSD 的“改革”路径各有代价与收益，改革的困难远高于革命
