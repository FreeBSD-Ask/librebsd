# 93.12 FreeBSD 4.x 时期的技术淘汰——ipfw1→ipfw2 防火墙重写、select/poll→kqueue 事件机制、chroot→jail 容器化雏形、UFS 同步元数据 →Soft Updates 延迟写入、4BSD 调度器保持主导与 Giant 锁延续（2000-2003）

## 92.12.1 ipfw1 → ipfw2 防火墙重写（4.6/4.7 时期，2002.7）
  - 要点：FreeBSD 3.x 时期使用 ipfw1 防火墙（基于 Luigi Rizzo 1996 年原始 ipfirewall 实现），规则语法简单但缺少状态检测、dummynet 流量整形与 keep-state 机制的完善支持；ipfw2 防火墙由 Luigi Rizzo 重新设计，首次 commit 于 2002 年 7 月 9 日（4.6-RELEASE 2002.7.3 之后，4.7-RELEASE 2002.10.8 之前），2002 年 7 月 24 日 MFC 至 -stable 分支；ipfw2 引入更灵活的规则语法（基于规则集与动作分类）、内置 dummynet 流量整形、keep-state 状态检测、IP 协议无关规则（IPv4/IPv6 统一）；ipfw2 替代 ipfw1，但 ipfw1 接口在兼容性考虑下保留一段时间；4.x 时期 ipfw2 是默认防火墙，与同期 OpenBSD pf（2001 年 OpenBSD 3.0 引入）形成竞争
  - 史料：FreeBSD 4.6/4.7-RELEASE Release Notes；Luigi Rizzo 在 freebsd-ipfw 邮件列表 1999-2000 年关于 ipfw2 设计的讨论；man **ipfw(8)** 历次版本；bsd_commits.db freebsd-src 仓库 commits 表 ipfw2 首次 commit 为 2002-07-09 Luigi Rizzo（commit c7ea6831353b20a8dac2dbcb65f6932a25598158，subject = "Change one variable to make it easier to switch between ipfw and ipfw2"），2002-07-24 MFC 至 -stable（commit 489e451968935d9b0494271a82e41bef54210157，subject = "Bring ipfw2 into the -stable tree"） ［A］
  - 史观：总纲第 6 条——技术选择的代价：ipfw1 → ipfw2 重写付出规则兼容性代价（旧 ipfw1 规则需重写），但获得状态检测与流量整形能力；总纲第 17 条——形式与内容：防火墙规则语法作为 “形式” 改变 “内容”（网络管理员可用的策略表达能力）
  - 辨析：经 bsd_commits.db commits 表验证，ipfw2 首次 commit 为 2002-07-09（4.6-RELEASE 2002.7.3 之后），MFC 至 -stable 为 2002-07-24，故 ipfw2 实际引入版本为 4.6/4.7 时期而非旧叙事所称的 4.0 或 4.1，存疑已解决；ipfw2 与 ipfw1 共存期约 2002.7-2003 年（4.6-4.9 期间），4.10 起基本为默认；ipfw2 与同期 OpenBSD pf（2001）的设计哲学差异需对照源码核验

## 92.12.2 select/poll → kqueue 事件机制（4.1，2000.7）
  - 要点：传统 UNIX **select(2)** 与 **poll(2)** 系统调用使用线性扫描文件描述符表，性能随描述符数量增长而下降，无法高效处理数千并发连接（C10k 问题）；FreeBSD 4.1-RELEASE（2000.7.26）引入 **kqueue(2)** 与 **kevent(2)** 系统调用，由 Jonathan Lemon 设计；kqueue 首次 commit 于 2000 年 4 月 16 日（4.0-RELEASE 2000.3.20 之后，4.1-RELEASE 2000.7.26 之前），属 4.1-CURRENT 开发周期内合入；kqueue 使用内核事件表，应用程序注册感兴趣的事件类型（读、写、信号、定时器、子进程状态等），内核仅在事件发生时通知应用程序；kqueue 设计支持 O(1) 事件查询，可处理数万并发连接；kqueue 后续移植到 NetBSD（1.6）、OpenBSD（3.7）、macOS（10.3 Panther）；kqueue 是 FreeBSD 4.x 时期对 UNIX 事件机制最持久的贡献，影响后续 Linux epoll（2002.10 Linux 2.6）与 Solaris /dev/poll 的设计
  - 史料：FreeBSD 4.1-RELEASE Release Notes；Jonathan Lemon "Kqueue: A Generic and Scalable Event Notification Facility"（USENIX BSDCon 2000 论文）；Jonathan Lemon 在 freebsd-arch 邮件列表 2000 年关于 kqueue 设计的讨论；man **kqueue(2)** 历次版本；bsd_commits.db freebsd-src 仓库 commits 表 kqueue 首次 commit 为 2000-04-16T18:53:38Z Jonathan Lemon（commit cb679c385ef325d11f162e09b604df7532fc8009，subject = "Introduce kqueue() and kevent(), a kernel event notification facility"），sys/sys/event.h 同日首次引入（commit 3ee12e4fe3c884db74bc236f6f76dfb7539eb0d1） ［A］
  - 史观：总纲第 10 条——边缘者贡献：Jonathan Lemon 作为相对边缘的贡献者，kqueue 设计影响后续多个 BSD 项目与商业 OS；总纲第 17 条——形式与内容：kqueue 作为 “形式”（事件通知接口）改变 “内容”（高并发服务器架构）
  - 辨析：经 bsd_commits.db commits 表验证，kqueue 首次 commit 为 2000-04-16（4.0-RELEASE 2000.3.20 之后，4.1-RELEASE 2000.7.26 之前），属 4.1 开发周期内合入主干，故 “4.1 引入” 与 “4.1-RELEASE 合入” 两种叙事均正确，存疑已解决；kqueue 与 Linux epoll 的设计差异需对照源码核验（kqueue 支持多种事件类型，epoll 早期仅支持文件描述符）；kqueue 在 FreeBSD 4.x 时期的实际采用率缺乏权威统计
  - 文献：Jonathan Lemon "Kqueue" USENIX BSDCon 2000 论文；FreeBSD 4.1-RELEASE Release Notes；man **kqueue(2)**；Dan Kegel "The C10K Problem"（1999）；Jonathan Lemon. ## 92.12.3 chroot → jail 容器化雏形（4.0，2000.3）
  - 要点：传统 UNIX **chroot(2)** 自 4.4BSD 时代起提供文件系统根目录隔离，但缺少进程隔离、网络隔离、用户隔离、设备隔离；chroot 容易被 root 用户逃逸，无法作为真正的安全容器；FreeBSD 4.0-RELEASE（2000.3.20）引入 **jail(2)** 系统调用与 **jail(8)** 管理工具，初始实现由 Poul-Henning Kamp（波尔-亨宁·坎普） 于 1999 年 4 月 28 日提交（早于 4.0-RELEASE 近一年，属 4.0-CURRENT 开发周期），Robert Watson 后续在 4.x 时期贡献安全增强；jail 在 chroot 基础上增加进程隔离（jail 内进程无法访问 jail 外进程）、网络隔离（jail 绑定特定 IP 地址）、用户隔离（jail 内 root 权限受限）、设备隔离（jail 内无法访问原始设备节点）；jail 早于 Linux 容器（LXC，2008）与 Docker（2013）近十年，被视为现代容器化的先驱；jail 在 4.x 时期被 Yahoo! 等大规模部署用于共享主机服务
  - 史料：FreeBSD 4.0-RELEASE Release Notes；Poul-Henning Kamp 与 Robert Watson 在 freebsd-arch 邮件列表 1999-2000 年关于 jail 设计的讨论；man **jail(2)** 与 **jail(8)** 历次版本；Robert Watson "Jails on FreeBSD"（2001 BSDCon 论文）；bsd_commits.db freebsd-src 仓库 commits 表 jail 首次 commit 为 1999-04-28T11:28:49Z Poul-Henning Kamp（commit 02daf150a4434305b9181b0ac9150762afb4c8ce，subject = "Add the jail system call."），同日 11:38:52 提交完整实现（commit 75c13541908625d7ee0894cc03f96ab773f7dae2，subject = "This Implements the mumbled about ‘Jail’ feature."），sys/sys/jail.h 与 sys/kern/kern_jail.c 同日首次引入 ［A］
  - 史观：总纲第 10 条——边缘者贡献：jail 设计影响后续 Linux 容器、Solaris Zones（2004）、illumos Zones；总纲第 17 条——形式与内容：jail 作为 “形式”（轻量级隔离原语）改变 “内容”（系统管理员可用的部署架构）
  - 辨析：经 bsd_commits.db commits 表与 commit_files 表交叉验证，jail 初始实现由 Poul-Henning Kamp 独立完成（1999-04-28 两次 commit，引入 sys/sys/jail.h 与 sys/kern/kern_jail.c），Robert Watson 的贡献在后续 4.x 时期安全增强，存疑已解决；jail 与 Solaris Zones 的设计差异需对照源码核验（Solaris Zones 提供更完整的资源控制，jail 更轻量）；jail 在 4.x 时期的实际部署规模需考据
  - 文献：FreeBSD 4.0-RELEASE Release Notes；Robert Watson "Jails on FreeBSD" BSDCon 2001；man **jail(2)** 与 **jail(8)**；Poul-Henning Kamp. Add the jail system call. freebsd-src [DB/OL]. 1999-04-28T11:28:49Z. 02daf150a4434305b9181b0ac9150762afb4c8ce ［A］
## 92.12.4 UFS 同步元数据 → Soft Updates 延迟写入（4.x 时期持续完善）
  - 要点：传统 UFS（Unix File System）使用同步写入保证元数据一致性——创建文件时需同步写入 inode 与目录项，文件系统操作以磁盘速度而非处理器速度进行；Marshall Kirk McKusick（马歇尔·柯克·麦库西克） 与 Greg Ganger、Craig Patt 等设计的 Soft Updates 于 1998 年 3 月在 FreeBSD 3.0-CURRENT 时期合入主干（3.0-RELEASE 1998.10.16 已含），4.x 时期（2000-2003）持续完善；Soft Updates 使用延迟写入（write-back caching）记录元数据更新依赖，回写时按依赖顺序执行，确保崩溃后文件系统一致性；Soft Updates 通过 per-pointer 依赖跟踪避免块级循环依赖，块可按任意顺序写入，仍依赖的更新在写前回滚、写后回放；4.x 时期 Soft Updates 与同期商业 UNIX 的 journaling 文件系统（如 Solaris UFS logging、IBM JFS、SGI XFS）形成对比——Soft Updates 不需要日志但提供类似一致性保证
  - 史料：FreeBSD 3.x 与 4.x Release Notes Soft Updates 部分；Margo Seltzer 等 "Journaling versus Soft Updates: Asynchronous Meta-data Protection in File Systems"（USENIX 2000）；Greg Ganger 与 Craig Patt "Soft Updates: A Solution to the File-System Update Problem"（CMU-CS-94-221）；Marshall Kirk McKusick 在 BSDCon 1999 关于 Soft Updates 的演讲；bsd_commits.db freebsd-src 仓库 commits 表 soft updates 首次相关 commit 为 1998-03-09T14:46:57Z Eivind Eklund（commit 3bfd185367a11c4ede7b6bb0b9871939e17b36b5，subject = "Make this compile after soft updates integration."），softdep 相关 commit 1998-03-19 Bruce Evans（commit d2ca4e981b30dfdf0543eef2c7d00cbd5342cf87），1998-03-27 Peter Wemm（彼得·韦姆） 启用根文件系统 softdep 模式（commit 26cf9c3b7546e6bc02e96d1fbfc44114cc6ee294） ［A］
  - 史观：总纲第 6 条——技术选择的代价：Soft Updates 选择非日志路径，付出崩溃恢复复杂度代价（需 background fsck），但获得更高性能与更低磁盘开销；总纲第 17 条——形式与内容：元数据依赖跟踪作为 “形式” 改变 “内容”（文件系统的一致性保证机制）
  - 辨析：经 bsd_commits.db commits 表验证，Soft Updates 在 1998-03-09 即已合入主干（早于 3.0-RELEASE 1998.10.16 约 7 个月），故 “3.0-3.2 引入实验性支持” 的叙事不准确，应为 “3.0-CURRENT 时期合入，3.0-RELEASE 已含”，“3.3 起为默认” 的叙事需进一步对照 Release Notes 核验，存疑已部分解决；Soft Updates 与同期 Linux ext3 journaling（2001）的性能对比在不同基准测试中差异较大，需对照同硬件同负载核验；Soft Updates 的 "background fsck" 机制在 4.x 时期的实际可用性需考据

## 92.12.5 4BSD 调度器保持主导与 Giant 锁延续（4.x 时期架构局限）
  - 要点：FreeBSD 4.x 时期内核调度器沿用 4.3BSD 调度器（4BSD scheduler），基于 estcpu（CPU 使用估计）与 nice 值计算优先级，使用全局运行队列；4BSD 调度器算法 O(n)（n 为系统进程数），在数千进程系统中性能下降，无 CPU 亲和性、无 SMT 支持；4.x 时期 SMP 支持仍使用 Giant lock（单一内核大锁）模型，任何时刻仅一个 CPU 可在内核态运行，多核扩展性受限；SMPng（SMP Next Generation）项目 2001 年启动，但 5.0-RELEASE（2003.1.16）才引入初步 SMPng 架构，4.x 时期仍为 Giant-locked 内核；Giant 锁与 4BSD 调度器是 4.x 时期的技术债务，但带来稳定性收益——4.x 因 “Giant 锁保护下简单” 而成为 ISP 与 Web 托管提供商的 “黄金时代”
  - 史料：FreeBSD 4.x Release Notes；Robert Watson "FreeBSD SMPng Project SMP Network Stack"（2005 演讲）；freebsd-smp 邮件列表 2001-2003 年 SMPng 讨论；Jeff Roberson "ULE: A Modern Scheduler For FreeBSD"（BSDCon 2003）；bsd_commits.db freebsd-src 仓库 commits 表 ULE 调度器首次 commit 为 2003-01-26 Jeff Roberson（5.0-RELEASE 2003.1.16 之后），印证 4.x 时期 ULE 尚未合入，4.x 全程沿用 4BSD 调度器 ［A］
  - 史观：总纲第 6 条——技术选择的代价：Giant 锁选择付出多核扩展性代价，但获得稳定性收益；总纲第 7 条——技术选择即政治选择：4.x 时期 FreeBSD 选择 “Giant 锁 + 4BSD 调度器” 反映 “稳定性优先” 的技术政治选择
  - 辨析：经 bsd_commits.db commits 表验证，ULE 调度器首次 commit 为 2003-01-26（5.0-RELEASE 之后），印证 4.x 时期 4BSD 调度器主导地位确凿，存疑已解决；Giant 锁在 4.x 时期的具体性能影响仍需对照基准测试核验（4 CPU 瓶颈 vs 2 CPU 瓶颈），bsd_commits.db 无对应性能数据，仅能确认架构事实；SMPng 项目在 4.x 时期的具体进展需考据（2001 年启动但未在 4.x 时期合入）；4BSD 调度器与 4.x 时期 Linux O(1) 调度器（Ingo Molnar，2002）的对比需对照源码核验
  - 文献：FreeBSD 4.x Release Notes；Robert Watson "FreeBSD SMPng Project" 演讲；Jeff Roberson "ULE: A Modern Scheduler For FreeBSD" BSDCon 2003；Michael W.
