## 98.10.2 Torvalds 对 VM 的辱骂性批评——四层辩证（批评—反批评—再批评—合图）

  **要点**：【批评层】Linus Torvalds 据传曾在 Linux 内核邮件列表（LKML）中辱骂 FreeBSD VM 开发者为 “incompetent idiots”（不胜任的白痴），反映 BSD 与 Linux 社区在虚拟内存子系统设计哲学上的长期张力；该辱骂被 FreeBSD 社区长期记忆，成为 BSD 与 Linux 关系史中的标志性话语事件。需特别辨析：任务描述中提及的 “Alan Cox” 实为 Linux 内核长期维护者（Linux 2.4 系列维护者），并非 FreeBSD VM 开发者；John Baldwin（约翰·鲍德温） 才是 FreeBSD SMPng 核心开发者（freebsd.duckdb freebsd-src 仓库 <jhb@FreeBSD.org> commit 记录证实）。任务描述将二者并列为 “FreeBSD VM 开发者” 系角色混淆——史家须以代码级证据与 Linux 内核 MAINTAINERS 文件历史版本裁决身份归属，Alan Cox 应归为 Linux 一方，John Baldwin 应归为 FreeBSD 一方。【反批评层】FreeBSD 社区对 Torvalds 言论的回应集中于两点——其一，FreeBSD VM 子系统（包括 Dillon 的 VM 重写与后续 5.x 的 VM 改造）有其独立的设计哲学，与 Linux 的 Buddy 系统加 page cache 路线不同，二者在页面置换算法、交换管理、内存映射策略上各有取舍，Torvalds 以 Linux 路线为标准评判 FreeBSD VM 属于 “以己度人”；其二，Torvalds 的辱骂风格本身不构成技术论证，“incompetent idiots” 的措辞是话语权力而非技术证据。【再批评层】对 FreeBSD 回应的再批评指出，Torvalds 虽措辞粗暴但其技术批评可能触及真实问题——5.x 时期 FreeBSD VM 确实经历性能倒退，部分场景下 SMP 性能反不如 4.x，而同期 Linux 2.6 的 VM 子系统在 O(1) 调度器与 NPTL 线程模型配合下表现稳健；再批评者认为，FreeBSD 社区以 “设计哲学不同” 回避性能差距的事实，本身是一种话语防御。【合图层】综合四方立场，Torvalds 的辱骂（若属实）与 FreeBSD 的回应呈现 BSD 与 Linux 话语权不对等下的技术路线分歧——Torvalds 作为 Linux 的事实领袖拥有远超任何 FreeBSD 开发者的话语影响力，其一句辱骂的传播效应远超 FreeBSD 社区的任何技术辩护；但话语权不对等不等于技术判断对等，FreeBSD VM 与 Linux VM 的设计分歧是真实的工程选择，而非 “胜任” 与 “不胜任” 的二元对立。合图层不判定 VM 设计 “谁优谁劣”，而呈现辱骂事件作为 BSD 与 Linux 社区张力的话语症候
  
**史料**：LKML 邮件归档（lore.kernel.org <https://lore.kernel.org/lkml/>、marc.info <https://marc.info/?l=linux-kernel>）；freebsd-hackers 邮件列表讨论；Phoronix 早期 FreeBSD 5.x VM 性能基准测试；Linux 2.6 VM 子系统文档；freebsd.duckdb freebsd-src 仓库 John Baldwin（<jhb@FreeBSD.org>）VM/SMPng 相关 commit；Linux 内核源码 MAINTAINERS 文件历史版本（Alan Cox 作为 Linux 2.4 维护者的角色核实） ［A/C］
  
**史观**：总纲第 14 条——话语权与边缘者，Torvalds 的话语影响力远超 FreeBSD 开发者；总纲第 8 条——本体论上各方平等，FreeBSD VM 与 Linux VM 设计在本体论上地位相等；总纲第 19 条——解释学循环与权力知识共谋，话语权不对等下 “辱骂” 与 “辩护” 的传播效应差异本身是权力行使；总纲第 4 条——0 信任原则，对 “incompetent idiots” 言论须以一手 LKML 来源裁决
