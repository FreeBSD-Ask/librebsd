# 98.3 KSE 线程模型的实现与放弃——一次失败的工程实验

## 98.3.1 KSE 设计目标与最终废弃

**要点**：M:N 线程模型（2000-2005）暴露了严重复杂性与性能问题——线程激活机制在 CPU 密集型负载下产生大量开销，2005 年改为 1:1 线程模型。

**史料**：KSE 设计文档； FreeBSD 线程模型档案 ［A］；经参考文献库验证通过（fact-check 2026-08-14），reference_id=498（standalone.evans-kse-paper, 2000）《Kernel-Scheduled Entities for FreeBSD》署名 Jason Evans <jasone@freebsd.org>、2000-11-07，印证 KSE 论文于 2000 年发表，与要点“M:N 线程模型（2000-2005）”时间线一致；2005 年改为 1:1 线程模型（libthr）两库无法直接验证，属代码库与发行说明范围

**史观**：总纲第 22 条——知识注定过时：KSE 的复杂设计在多线程需求成熟后被更简单的 1:1 模型（libthr）取代，是为知识过时的工程注脚。

**文献**：KSE 文档； 7.0 发行说明 ［A］

**辨析**：KSE 的“失败”定性须区分三个层面：技术层面，M:N 模型在 CPU 密集负载下的激活开销确有其事，libthr 的 1:1 路线最终胜出是工程证据；叙事层面，“失败的工程实验”是事后重构，KSE 的调度实体设计理念部分延续于后续调度器工作；文献层面，Evans 的 KSE 论文（2000）与 5.1-RELEASE roadmap 的“2003-06 前须完成否则 ENOSYS 降级”警告互证其成熟度压力——三层证据须交叉使用，不得以单一定性盖棺。
