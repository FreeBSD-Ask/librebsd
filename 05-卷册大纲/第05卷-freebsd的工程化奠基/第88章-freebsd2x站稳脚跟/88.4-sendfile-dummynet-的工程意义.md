# 88.4 sendfile/dummynet 的工程意义

## 88.4.1 sendfile 系统调用

  **要点**：**sendfile(2)** 由 David Greenman（大卫·格林曼） 于 1998 年 11 月 5 日引入 FreeBSD 3.0-CURRENT（commit dd0b2081f452c0339a44a9647866cf9990111086），允许内核直接在文件描述符与套接字之间零拷贝传输数据，避免了传统 read/write 路径的用户态-内核态数据拷贝，显著提升了静态文件服务的吞吐量；旧叙事称 “1997 年引入 FreeBSD 2.2” 有误，已依据 commit log 修正
  
**史料**：SVN 仓库 sys/kern/sys_socket.c 与 sys/sys/syscall.h 中 sendfile commit 日志、Greenman 在 freebsd-hackers 1997-1998 年的提案邮件、Apache 与 thttpd 对 sendfile 的适配记录；freebsd.duckdb `commits` 表 sendfile 首次 commit：author = David Greenman <dg@FreeBSD.org>，author_date = 1998-11-05T14:28:26Z，committer_date = 1998-11-05T14:28:26Z，commit_hash = dd0b2081f452c0339a44a9647866cf9990111086，message = “Implemented zero-copy TCP/IP extensions via sendfile(2) - send a file to a stream socket”（2026-09-14 订正：半角直引号改弯引号）；次日（1998-11-06）commit bd81f199b5072e8638e93a18b2ebf099e2db3bea 添加非阻塞 socket 支持 ［A］
  
**史观**：工程需求倒逼内核 API 演进（专题语，不设总纲条号；2026-09-14 订正：原伪挂“总纲第 19 条——信息技术”按权威表去号），sendfile 是 Web 服务器性能需求倒逼操作系统内核 API 创新的典型案例
  
**辨析**：经 freebsd.duckdb `commits` 表验证，sendfile 首次 commit 在 1998-11-05，对应 FreeBSD 3.0-CURRENT 时期（3.0-RELEASE 于 1998-10-16 发布，sendfile 在 3.0-RELEASE 后合入 -CURRENT 分支，将进入 3.1-RELEASE 与 2.2.8-STABLE 后续分支），旧叙事 “1997 年引入 FreeBSD 2.2” 误植，应修正为 1998 年 3.x 时期；sendfile 的发明权存在争议，Linux 在 2.2(1999) 也引入了 sendfile，FreeBSD 3.x 时期（1998.11）早于 Linux 2.2(1999.1)，谁先提出概念需查邮件列表
  
**文献**：Greenman “sendfile: Zero-Copy File Transmission”(BSDCon 1998)；Stevens《UNIX Network Programming》(1998)；Apache 性能调优文档；David Greenman. Implemented zero-copy TCP/IP extensions via sendfile(2) - send a file to a stream socket. freebsd-src [DB/OL]. 1998-11-05T14:28:26Z. dd0b2081f452c0339a44a9647866cf9990111086 ［A］

## 88.4.2 dummynet 流量整形

  **要点**：dummynet 由 Luigi Rizzo 设计并实现，作为 ipfw 规则的 action 实现 bandwidth/delay/queue/loss 等网络仿真与流量整形，其设计目标是 “在内核中用最小代码量实现生产级 QoS”。Rizzo 在 BSDCon 1998 论文中首次公开介绍 dummynet，dummynet 首次合入 FreeBSD 源码树的实际时间是 1998 年 9 月 12 日（commit 2655eb498feb45c6df513a4a4a4f5871ba2bb572 “Bring in new files for dummynet support”），对应 3.0-CURRENT 时期，而非旧叙事所称 “2.2.5-RELEASE（1997.10.22）”
  
**史料**：Rizzo 在 sys/netinet/ip_dummynet.c 的初始 commit、dummynet(4) 手册页、Rizzo 的 dummynet 论文手稿、FreeBSD 2.2.5-RELEASE Announcement（Jordan K. Hubbard（乔丹·哈伯德） 1997.10.22 发布，freebsd.org/releases/2.2.5R/announce/）；freebsd.duckdb `commit_files` 表 sys/netinet/ip_dummynet.c 首次引入：author = Luigi Rizzo，author_date = 1998-09-12T22:03:21Z，commit_hash = 2655eb498feb45c6df513a4a4a4f5871ba2bb572，message = “Bring in new files for dummynet support”；freebsd.duckdb `tags` 表 `release/2.2.5` tagger_date = 1997-10-21T01:56:05Z，证明 2.2.5 发布早于 dummynet 合入近一年 ［A］
  
**史观**：实践先于理论（专题语，不设总纲条号；2026-09-14 订正：原伪挂“总纲第 2 条”按权威表去号），dummynet 不是从 QoS 理论推演而来，而是 Rizzo “需要在生产环境模拟慢链路” 的工程产物
  
**辨析**：经 freebsd.duckdb `commits` 表与 `commit_files` 表验证（2026-09-14 订正：bsd_commits.duckdb 系拆分前旧库名，统一现行库），dummynet 首次 commit 在 1998-09-12（3.0-CURRENT 时期），2.2.5-RELEASE 的 tagger_date 为 1997-10-21，二者相差近一年，旧叙事 “dummynet 于 1998 年引入 2.2.5” 中的版本号 “2.2.5” 误植，正确版本应为 3.0-CURRENT/3.1-RELEASE；Rizzo 在 BSDCon 1998 论文中首次公开介绍 dummynet 与首次 commit 时间（1998.9）一致；dummynet 的初始版本是否支持 WFQ 存在争议，Rizzo 在论文中称早期版本仅支持 FIFO 与 RED，WFQ 在 1999 年才加入；经参考文献库检索（fact-check 2026-08-14），Rizzo dummynet 论文（reference_id=493）库中年份标为 1997，与本章“BSDCon 1998 首次公开介绍”存在年份表述差异，需核实技术报告版（1997）与会议版（1998）之别；dummynet 首次合入时间 1998-09-12 两库无法直接验证（邮件列表库 1998 年 dummynet 关键词无有效命中）
  
**文献**：Rizzo “dummynet: a simple approach to traffic shaping”(BSDCon 1998)；Rizzo “Dummynet and Network Emulation”(2000)；FreeBSD Handbook 中 dummynet 章节；FreeBSD 2.2.5-RELEASE Announcement（1997.10.22）；Luigi Rizzo. Bring in new files for dummynet support. freebsd-src [DB/OL]. 1998-09-12T22:03:21Z. 2655eb498feb45c6df513a4a4a4f5871ba2bb572；release/2.2.5. freebsd-src 仓库 tag [DB/OL]. 1997-10-21T01:56:05Z. tag: release/2.2.5; commit: 58fda9eaaeb697cef01d825dfe2b6f045659c15c ［A］

## 88.4.3 工程意义的辨析

  **要点**：sendfile 与 dummynet 共同体现了 2.x 时期 FreeBSD “用最小侵入解决生产痛点” 的工程哲学，前者优化数据路径，后者扩展网络策略，二者均为后续 4.x 时期大规模部署 (如 Yahoo!) 奠定了性能基础
  
**史料**：Yahoo! 工程团队 1999-2000 年 FreeBSD 部署报告、Apache sendfile 性能基准测试、dummynet 在 ISP 中的部署案例［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档；L5 二手研究〕
  
**史观**：总纲第 9 条——经验优先（2026-09-14 订正：原自创名目“企业研究双重性”按权威表改正），sendfile/dummynet 既是学术研究产物又直接服务于企业生产，体现 BSD 研究与商业的双重性
  
**辨析**：sendfile 的性能提升幅度在不同硬件上差异巨大，从 10% 到 300% 不等，需对照具体基准测试环境
  
**文献**：Yahoo! Performance Engineering “FreeBSD at Yahoo!”(BSDCon 2000)；Rizzo 的 dummynet 性能报告；thttpd 性能白皮书［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
