# 87.1 1994-1998 年 2.0

## 87.1.1 FreeBSD 2.0 发布与特性
  - 要点：FreeBSD 2.0 于 1994 年 11 月 22 日发布，基于 4.4BSD-Lite 代码清理而成，彻底解决 1.x 时代与 AT&T USL 的法律纠纷，确立以 4.4BSD-Lite 为代码基线的工程路线，引入了对 ISA/EISA 总线与初步 PCI 设备的支持
  - 史料：FreeBSD 2.0 Release Notes、SVN 仓库 releng/2.0 分支标签、Jordan Hubbard 在 1994 年 11 月 freebsd-announce 邮件列表发布的公告、McKusick 个人档案中 4.4BSD-Lite 授权文件；freebsd.db `tags` 表 `release/2.0` 与 `release/2.0_cvs` 双 tag 的 tagger_date 均为 1994-11-22T10:58:58Z，target_commit_hash 分别为 324ec40db3d437d18da21aa07a7ae4d4ecd9c157 与 140932d6d85b561ad06abe5006a5e973a7713c45 ［A］
  - 史观：总纲第 2 条——实践先于理论，2.0 是 1.x 数年实践积累后对 4.4BSD-Lite 基线的理论化整合，不是从架构蓝图出发而是从法律和解与代码清理的实践出发
  - 辨析：经 freebsd.db `tags` 表验证，`release/2.0` tag 的 tagger_date = 1994-11-22T10:58:58Z，`release/2.0_cvs` 同时刻 tagger_date 一致，两 tag 指向不同 commit hash 但同一时间戳，确认 FreeBSD 2.0 发布日期为 1994 年 11 月 22 日，"1994.12" 说法不成立；该 tagger_date 由 FreeBSD SVN-to-Git 迁移（2020）从 SVN 时代保留，依据 0 信任原则，SVN 时代 release 公告署名（Jordan Hubbard 1994.11 freebsd-announce 邮件）作为交叉验证；2.0 是否完全清除 386BSD 残留代码仍有争议，部分驱动仍含 386BSD 注释，需对照源码核验
  - 文献：McKusick & Neville-Neil《The Design and Implementation of the FreeBSD Operating System》(2004)；Lehey《The Complete FreeBSD》(1995 初版)；Nikitchenko 等 "FreeBSD 2.0 Release Engineering"(BSDCon 1994)；release/2.0. freebsd-src 仓库 tag [DB/OL]. 1994-11-22T10:58:58Z. tag: release/2.0; commit: 324ec40db3d437d18da21aa07a7ae4d4ecd9c157 ［A］
## 87.1.2 2.0 至 2.2.x 的演进
  - 要点：2.1(1996.1.1)、2.1.5(1996.10.6)、2.1.7(1997.3.11)、2.2.0(1997.3.17)、2.2.x 系列延续至 1999.1.21（2.2.8-RELEASE），期间逐步引入 sendfile、dummynet、IPFW 第二代规则语法，并稳定了 SCSI 子系统与 PCI 总线支持，是 FreeBSD 从研究性系统转向生产级系统的关键演进期

## 87.1.3 2.x 时期的社区演进
  - 要点：2.x 时期 FreeBSD 社区从核心团队扩展至数百名 committer，freebsd-hackers 与 freebsd-current 邮件列表成为技术讨论主战场，Walnut Creek CDROM 提供镜像分发与商业支持，BSDCon 与 Usenix 技术会议成为面对面交流节点
  - 史料：freebsd-hackers 邮件列表 1994-1998 年归档、Core Team 选举记录 1996/1998、Walnut Creek CDROM 商业合同副本、BSDCon 1997/1998 会议议程；bsd_commits.db 查询 L1.1.1 显示：freebsd-src 仓库 1996 年 7,948 commits（占 4 大 BSD src 合计 27.18%）、1997 年 11,046 commits（占 24.49%）、1998 年 10,035 commits（占 25.02%），三年间 commit 量增长 26.2% 反映 2.x 时期 FreeBSD 开发活跃度持续上升；bsd_commits.db 查询 L1.2.1 显示：1996 年新增贡献者 82 人、1997 年 125 人、1998 年 149 人，连续三年净增长反映社区扩张 ［A］
  - 史观：总纲第 23 条——社区治理，2.x 时期 Core Team 的精英评审模式从默契走向成文，CVS 提交权限的授予标准在此期间形成事实规范
  - 辨析：Core Team 早期选举记录不完整，1996 年选举的具体候选人与票数需考据；Walnut Creek CDROM 对 FreeBSD 项目的经济贡献占比存在 “过半” 与 “约三成” 两种估计；【0 信任原则·commit 量局限】L1.1.1 与 L1.2.1 数据基于 freebsd-src 仓库 author_date 字段，未剔除 cvs2svn 自动生成 commit（参见 34.8.1 节），实际人工 commit 量可能低于统计值；【0 信任原则·author 字段可伪造】git author 字段可由提交者任意填写，1996-1998 年部分 commit 作者邮箱在 2008 年 CVS→SVN 迁移中已失真，新增贡献者数可能存在同一人多计或化名误计
  - 文献：Nikitchenko "A History of FreeBSD"(BSD Magazine 2009)；Walnut Creek CDROM 商业档案；Hubbard "FreeBSD Status Report"(USENIX 1997) ［B］；freebsd.db L1.1.1 查询：23 仓库 1993-2026 年每年 commit 量时间序列 [R]. 2026-07-22 查询；freebsd.db L1.2.1 查询：每年新增贡献者数 [R]. 2026-07-22 查询
## 87.1.4 2.x 版本史料辨析
  - 要点：2.x 时期的史料主要包括 Release Notes、CVS 提交日志、邮件列表归档与早期 BSDCon 论文，但 CVS 仓库在 2008 年迁移至 SVN 时部分元数据丢失，部分提交者邮箱与时间戳需交叉验证
  - 史料：FreeBSD SVN 仓库迁移日志 (2008)、CVS-to-SVN 转换脚本输出、Internet Archive 缓存的 freebsd.org 1996-1998 年快照 ［A］；freebsd.db 数据库交叉印证——统计结论 C-03 freebsd-src 仓库总 commit 数 444,203 条（`SELECT COUNT(*) FROM commits WHERE repo_name='freebsd-src'`），2.x 时期（1994-1999）的 commit 分布为此累计量的早期段；统计结论 C-12 freebsd-src 变点检测 1999-08（Pettitt 与 BUISHAND 双检验一致 p < 0.001），距 2020-01 SVN-to-Git 迁移 245 个月，判定为非迁移伪变点，即 1999-08 前后 commit 节律发生结构性转变，恰好位于 2.x 系列终结（2.2.8-RELEASE 1999-01-21）与 3.x/4.x 兴起过渡期，反映 FreeBSD 项目从 2.x 维护期向 3.x SMP 时代转移的工程节律切换；Python 脚本 `script/phase2_inferential.py` Task 6（Pettitt 自实现 + BUISHAND R 自实现），查询日期 2026-07-27 ［B］
  - 史观：总纲第 17 条——软件工程，CVS 到 SVN 的迁移本身构成 2.x 史料保存的工程问题，版本控制工具的更替意味着开发记忆载体的转移；统计结论印证——C-12 变点 1999-08 反映 2.x 至 3.x 工程节律的结构性切换，与项目史观总纲第 25 条 “分离聚合是永恒规律” 映射：2.x 系列的终结（分离）与 3.x SMP 时代的兴起（聚合）在 commit 时序上形成可检测的变点，统计变点检测为史观中的 “分离聚合” 提供量化印证
  - 辨析：2.x 时期部分 commit log 在迁移中丢失作者信息，需对照 freebsd-committers 邮件列表人工修复；2.2.8 与 2.2.8-STABLE 的区别常被混淆；**统计局限性标注**——统计显著 ≠ 实际显著，C-12 变点 p < 0.001 仅反映 commit 时序存在结构性断点，不等于 2.x 至 3.x 转型在工程上 “必然” 发生；C-12 双检验一致性（Pettitt 与 BUISHAND）降低单一方法偏差但不可消除方法学局限；变点距 2020-01 SVN-to-Git 迁移 245 个月，已排除迁移伪变点假设，但 1999-08 仍可能受 Y2K 准备期、互联网泡沫期 ISP 需求激增等同期外部因素干扰，单一归因于 2.x/3.x 转型存在简化风险；0 信任原则适用——`bsd_commits.db` 1993+ 起，2.x 时期（1994-1999）commit 数据完整但 2008 CVS→SVN 与 2020 SVN→Git 两次迁移可能引入日期偏差与作者归属错误，须与 SVN 时代邮件列表存档交叉验证；多重比较风险——本卷 16 章跨章引用 C-03 与 C-12 时存在多重比较风险，已在辨析字段标注
