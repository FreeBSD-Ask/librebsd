# 87.8 被遮蔽的史实：CVS→SVN→Git 迁移中的史料损失——2008 年 src 仓库迁移与 2014 年 GNATS→Bugzilla PR 历史断裂

## 87.8.1 2008 年 5 月 31 日 src 仓库 CVS→SVN 迁移的元数据损失
  - 要点：FreeBSD src 仓库于 2008 年 5 月 31 日由 CVS 迁移至 Subversion，首个真实 SVN commit 为 r179447，迁移由 Peter Wemm（Yahoo! 开发者）使用 cvs2svn 工具主导；CVS 的文件级版本控制与 SVN 的原子提交模型存在结构性差异，迁移过程中部分 commit 被自动合并并生成 “this commit was generated by cvs2svn to compensate for changes in rXXXXXX, which included commits to RCS files with non-trunk default branches” 的占位注释，原始 commit 作者邮箱、时间戳与分支语义部分丢失；doc/www 仓库 2012 年 5 月 19 日迁移（首 commit r38821），ports 仓库 2012 年 7 月 14 日迁移（首 commit r300894），均存在类似元数据损失
  - 史料：FreeBSD Committers Guide 10.2-RELEASE “Subversion Primer” 章节；gihyo.jp 2008.6.6 FreeBSD Daily Topics 报道；cvs2svn 项目代码库；cgit.freebsd.org 仓库中 cvs2svn 自动生成的 commit 注释样本（如 contrib/ncurses 历史中的 b285ba36300f06712f14be242197280f060bf05b）；bsd_commits.db `commits` 表中保存的 cvs2svn 自动生成 commit 样本：最早一条为 Jordan K. ## 87.8.2 2014 年 6 月 3 日 GNATS→Bugzilla 迁移中的 PR 历史断裂
  - 要点：FreeBSD 项目于 2014 年 6 月 3 日开始从 GNATS 系统迁移至 Bugzilla，由 David Chisnall（<theraven@FreeBSD.org>）代表 Core 团队发布公告；GNATS 数据库被冻结为迁移起点，`send-pr` 作为兼容接口继续工作但需要手动步骤导入新提交的 bug；工作流发生显著变化（Eitan Adler 绘制的状态转移图 people.freebsd.org/~eadler/bugrelocation/workflow.html），原有的 PR 编号体系与 Bugzilla bug 编号体系不完全一一对应；2014 年 9 月 30 日 GNATS URL 被重定向至 Bugzilla，2016 年 3 月 19 日 commit r411397/r411398 才从 commit 模板中移除 GNATS 引用——历史包袱持续近两年；部分 1994-2014 年间的 PR 在迁移中因分类字段不匹配或元数据缺失而无法被精确对应，存在 PR 历史断裂
  - 史料：freebsd-announce 邮件列表 2014.6.3 David Chisnall 公告；freebsd-ports 邮件列表 2014.6.3 讨论；Bug 194040（2014.9.30 Rene Ladan 报告 GNATS URL 重定向）；Bug 205692（2015.12.29 Matthias Andree 报告 commit 模板中残留 GNATS 引用）；cdnmirror.com 上的 GNATS 数据库冻结 README ［A］
  - 史观：总纲第 17 条——软件工程，bug 追踪系统的迁移不仅是工具更替，更是历史叙事载体的一次重构，1990 年代至 2010 年代初的 PR 上下文在新系统中被部分剥离
  - 辨析：[考据完成：2026-07-28 该处辨析所涉存疑点经穷尽联网考据，属史料缺口，详见上下文分析] 迁移过程中实际丢失的 PR 数量在公开档案中无明确统计，David Chisnall 公告中称 “some disruption” 但未量化；部分 PR 在 GNATS 中以纯文本邮件附加形式存在，迁移至 Bugzilla 后附件格式与可搜索性变化，需通过 Internet Archive 与 cdnmirror.com 上的 GNATS 冻结快照交叉验证；经 bsd_commits.db 验证（2026-07-22 查询）：数据库共 9 张表（branches/commit_branches/commit_files/commits/contributors/db_meta/repos/sqlite_sequence/tags），无 GNATS PR 数据表，commit_files 与 commits 表无法提供 PR 丢失数量证据；bsd_commits.db freebsd-doc 仓库 2014-05-31 至 2014-06-08 期间含 30 条 GNATS/Bugzilla 迁移相关 commit（如 Rene Ladan 2014-05-31 “nl/htdocs/send-pr.xml: MFen r44980 (disable the GNATS form)”、Peter Wemm 2014-06-04 “Along the lines of r44999, hack redirection for a few more gnats references.”、Eitan Adler 2014-06-08 “During the temporary period, drop the footer on the gnats PRs.”），反映迁移工程进展，但不反映 PR 丢失数量；0 信任原则提示：commit message 仅记录工程动作，不记录 PR 数据迁移完整性；存疑保留，待 GNATS 冻结快照与 Bugzilla 数据库的系统性比对审计方可量化

## 87.8.3 2020 年 12 月 SVN→Git 迁移的史料保存与连续性挑战
  - 要点：FreeBSD 项目于 2020 年 12 月启动 SVN→Git 迁移，doc 仓库 2020 年 12 月 5-8 日迁移完成，src 仓库 2020 年 12 月 23 日前后迁移完成，ports 仓库推迟至 2021 年 3-4 月迁移；迁移由 Warner Losh 与 Ed Maste 领导的 git conversion working group 主导；迁移后 SVN 仓库变为只读，但 stable/11、stable/12 及相应 releng 分支的 MFC 仍被重放到 SVN 作为过渡辅助；迁移过程中移除了 `$FreeBSD$` 关键字标记（reviews.freebsd.org D27678，rene@ 2020.12.19 提交），RCS 风格的版本标记彻底退出历史；git 的 SHA-1 哈希与 SVN 的递增 revision number 无法直接对应，老文档中引用 SVN rXXXXXX 的位置需通过 git notes 维护映射
  - 史料：bsdsec.net 2020.12.3 FreeBSD-doc Subversion to Git migration 公告；forums.freebsd.org 2020.12.17 “HEADS UP: FreeBSD changing from Subversion to Git this weekend” Warner Losh 帖子；reviews.freebsd.org D27678（rene@ 2020.12.19 提交的 build infrastructure 更新）；github.com/bsdimp/freebsd-git-docs 迁移文档；wiki.freebsd.org/git 迁移日程页面 ［A］
  - 史观：总纲第 25 条——终结中的延续，SVN→Git 迁移虽保留 commit 历史，但 `$FreeBSD$` 标记的移除象征一个版本的 “档案铭文” 传统终结，commit hash 取代 revision number 成为新的史料引用单位
  - 辨析：[考据完成：2026-07-28 该处辨析所涉存疑点经穷尽联网考据，属史料缺口，详见上下文分析] git notes 中维护的 SVN-Git 映射在迁移初期的完整性需独立验证，部分边角 commit（如 vendor 分支导入）的映射关系存在争议；Warner Losh 在公告中称 “will preserve much of the current FreeBSD development workflow”，但 stable/11、stable/12 的 MFC 重放机制的实际运行时长与终止日期在公开档案中未明确记录；经 bsd_commits.db 验证（2026-07-22 查询）：数据库 schema 中无 git notes 元数据表，commit_files 表仅记录 file_path/status/additions/deletions，无法反映 git notes 内容；bsd_commits.db freebsd-src/freebsd-doc/freebsd-ports 三仓库 2020-11 至 2021-06 期间含 24 条 SVN→Git 迁移相关 commit（如 Dimitry Andric 2021-01-26 “Change links from svnweb to cgit, and remove sys/sys/param.h subpaths”、Ed Maste 2021-01-29 “Cirrus-CI: remove svn2git remnant”、Warner Losh 2021-03-16 “Merge in the migration from subversion / github”），反映迁移后清理工作，但不反映 git notes 完整性；0 信任原则提示：commit message 仅记录链接替换与 CI 清理，不记录 git notes ref 的内容完整性；存疑保留，待 FreeBSD git 仓库 git notes ref（refs/notes/*）的独立审计方可验证

## 87.8.4 三次迁移累积史料损失对 FreeBSD 史学研究的效应
  - 要点：FreeBSD 在 2008 年（CVS→SVN）、2014 年（GNATS→Bugzilla）、2020 年（SVN→Git）发生三次重大基础设施迁移，每次迁移都引入新的元数据模型并部分舍弃旧模型；累积效应是 1993-2008 年 CVS 时代的部分 commit 上下文（作者邮箱、分支语义、RCS 文件级版本号）在 SVN 中被压缩为原子 commit，再在 Git 中被进一步映射为 SHA-1 哈希，原始上下文层层剥离；1994-2014 年 GNATS 系统中的部分 PR 与邮件列表讨论的关联在 Bugzilla 中断裂；史学研究需同时检索 cgit.freebsd.org（Git）、svnweb.freebsd.org（SVN 只读镜像）、GNATS 冻结快照（cdnmirror.com）、邮件列表归档（lists.freebsd.org/pipermail/）以及 Internet Archive 缓存才能完整重建任一具体事件的史料链
  - 史料：cgit.freebsd.org Git 仓库；svnweb.freebsd.org SVN 只读镜像；cdnmirror.com/FreeBSD/development/gnats-archive/ GNATS 数据库冻结快照；lists.freebsd.org 邮件列表超文本归档；Internet Archive web.archive.org 缓存 ［A］
  - 史观：总纲第 17 条与第 25 条的张力——软件工程的工具演进是必然，但每次演进都伴随不可逆的史料损失；“工具中立” 在史学研究视角下不成立，工具选择本身即是对未来史家可访问性的预先决定
  - 辨析：[考据完成：2026-07-28 该处辨析所涉存疑点经穷尽联网考据，属史料缺口，详见上下文分析] 三次迁移的具体史料损失量化需建立专门的 “FreeBSD 史料保存审计” 项目，目前无公开的系统性审计报告；本节所述损失基于工具差异的推断与零星案例，需在脚注中说明并保留修正空间；经 bsd_commits.db 验证（2026-07-22 查询）：数据库共 9 张表，无专门记录迁移损失的元数据表；bsd_commits.db 中 freebsd-src 仓库 earliest_commit_date = 1993-06-12，含 cvs2svn 自动生成 commit 样本（最早一条 Jordan K.
