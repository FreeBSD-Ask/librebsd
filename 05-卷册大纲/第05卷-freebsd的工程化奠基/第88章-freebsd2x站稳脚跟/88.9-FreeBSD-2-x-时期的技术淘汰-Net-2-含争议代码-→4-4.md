# 87.9 FreeBSD 2.x 时期的技术淘汰——Net/2 含争议代码 →4.4BSD-Lite 法律洁净基础、原始 BSD VM→Mach 2.5 虚拟内存重写、LKM 加载框架 →KLD 内核链接器演化、a.out 二进制格式 →ELF 切换起步、单段 boot→ 多阶段 /boot/loader（1994-1998）

## 87.9.1 Net/2 含争议代码 → 4.4BSD-Lite 法律洁净基础迁移（1994-1995）
  - 要点：FreeBSD 1.x 基于 4.3BSD-Net/2，含 USL 诉讼潜在争议代码；USL v. BSDi 诉讼 1994 年 1 月和解后，CSRG 于 1994 年 6 月发布 4.4BSD-Lite，移除约 32 个含 AT&T 代码的文件、重写大量源码；FreeBSD 2.0-RELEASE（1994.11.22）作为首个以 4.4BSD-Lite 为法律基础的版本发布，由 Jordan Hubbard、Rod Grimes、Nate Williams（内特·威廉姆斯） 协调，完成 Net/2→4.4BSD-Lite 基础迁移；FreeBSD 2.0 同时宣称法律上 “自由于 AT&T 代码”；4.4BSD-Lite2 于 1996 年 3 月 11 日由 Peter Wemm（彼得·韦姆） 通过 vendor branch 导入 FreeBSD 源码树（commit c2f46557264110fb353a0f512292db9330c09dc4 "Import 4.4BSD-Lite2 onto the vendor branch"），为后续 2.1.x/2.2.x 提供增量更新基础；同期 NetBSD 1.0 与 OpenBSD 1.0（1996）亦完成类似迁移；4.4BSD-Lite 迁移使 FreeBSD 获得法律洁净的代码基础，但付出短期代码替换工程代价——FreeBSD 1.x 部分用户空间工具被重写或替换
  - 史料：USL v. BSDi 诉讼档案与 1994.1 和解协议；4.4BSD-Lite Release Notes（1994.6）；FreeBSD 2.0-RELEASE Release Notes（1994.11.22）；Jordan Hubbard 在 freebsd-announce 邮件列表 1994 年 11 月发布的 FreeBSD 2.0 公告；CSRG 末期代码发布记录；freebsd.db `commits` 表 4.4BSD-Lite2 导入：author = Peter Wemm，author_date = 1996-03-11T19:17:01Z，commit_hash = c2f46557264110fb353a0f512292db9330c09dc4，message = "Import 4.4BSD-Lite2 onto the vendor branch, note that in the kernel, all files are off the vendor branch, so this should not change anything."；freebsd.db `tags` 表 `release/2.0.5` tagger_date = 1995-06-10T19:44:55Z（2.0.5 早于 4.4BSD-Lite2 导入近一年） ［A］
  - 史观：总纲第 12 条——法律结构：USL 诉讼与 4.4BSD-Lite 发布作为法律结构事件重塑 FreeBSD 代码基础；总纲第 1 条——偶然性改写历史：USL 诉讼和解是偶然事件，但其推动的代码基础迁移决定 FreeBSD 后续发展
  - 辨析：经 bsd_commits.db `commits` 表验证，4.4BSD-Lite2 由 Peter Wemm 于 1996-03-11 通过 vendor branch 导入主干，时点晚于 2.0.5-RELEASE（1995-06-10）近一年，可见 2.0.5 仍基于 4.4BSD-Lite 而非 Lite2；FreeBSD 2.0 完成向 4.4BSD-Lite 迁移的具体工作量在不同叙事中差异较大——部分资料称 2.0 完成迁移，部分称 2.0.5 才完整完成，bsd_commits.db 中 2.0 与 2.0.5 双 tag 均指向 1994-1995 年间 commit，需对照 2.0 Release Notes 与源码 commit 核验；USL 诉讼和解协议的具体条款在不同叙事中存在差异，需对照原始和解协议核验
  - 文献：USL v. BSDi 案件档案；4.4BSD-Lite Release Notes；FreeBSD 2.0-RELEASE Release Notes；Marshall Kirk McKusick（马歇尔·柯克·麦库西克） 伯克利 BSD 史系列演讲；Peter Wemm. Import 4.4BSD-Lite2 onto the vendor branch. freebsd-src [DB/OL]. 1996-03-11T19:17:01Z. c2f46557264110fb353a0f512292db9330c09dc4 ［A］
## 87.9.2 原始 BSD VM → Mach 2.5 虚拟内存重写（1994-1995）
  - 要点：FreeBSD 1.x 沿用 4.3BSD-Net/2 的原始 BSD 虚拟内存子系统，缺少现代共享内存、mmap 高效实现、demand paging 优化；FreeBSD 2.0-RELEASE（1994.11.22）以 Carnegie Mellon University Mach 2.5 虚拟内存系统为蓝本重写 VM 子系统，由 John Dyson 等主导；Mach 2.5 VM 引入基于页的内存管理、更高效的 fork/clone、改进的 swap 子系统；FreeBSD 2.0 公告中明确称：

  > featured a revamp of the original Carnegie Mellon University Mach virtual memory system, which was optimized for performance under high loads
  >
  > ——FreeBSD 2.0-RELEASE Announcement, 1994-11-22

  Mach VM 重写为后续 3.x、4.x 时期 SMP 与多线程支持奠定基础；同期 NetBSD 1.0 亦使用 Mach 2.5 VM，但实现路径不同
  - 史料：FreeBSD 2.0-RELEASE Release Notes；John Dyson 在 freebsd-hackers 邮件列表 1994-1995 年关于 VM 重写的讨论；CMU Mach 2.5 设计文档；Richard Rashid（理查德·拉希德） 等 "Machine-Independent Virtual Memory Management for Paged Uniprocessor and Multiprocessor Architectures"（CMU-CS-88-1） ［A］
  - 史观：总纲第 6 条——技术选择的代价：FreeBSD 选择 Mach 2.5 VM 重写付出短期稳定性代价，但获得长期 SMP 与多线程扩展能力；总纲第 17 条——形式与内容：VM 子系统作为 “形式”（内存管理框架）改变 “内容”（应用程序可用的内存模型）
  - 辨析：经 bsd_commits.db `commits` 表验证（2026-07-22 查询），1994-1995 年间 freebsd-src 仓库存在 3 条严格 Mach 微内核相关 commit：(1) David Greenman（大卫·格林曼） 1994-10-15T13:33:09Z commit 976e77fc9c178ec1373d3e867d3d35d3005c64cd "1) Some of the counters in the vmmeter struct don't fit well into the Mach VM"，证明 Mach VM 概念在 2.0-RELEASE（1994.11.22）前后已存在；(2) Poul-Henning Kamp（波尔-亨宁·坎普） 1995-12-13T10:35:36Z commit c08c8adcf5230aeaf555f77eff6290285ab74192 "Remove MACH_KERNEL, ORIGINAL, and ZP_DEBUG, I should have done this before it was imported."；(3) Bruce Evans 1995-12-27T16:16:02Z commit f15351202fdaa20a5e0b07fb7272a9cd719b2bfe "Finished removing MACH_KERNEL stuff."——1995 年 12 月的两条 commit 证明 MACH_KERNEL 宏在 FreeBSD 2.x 时期曾被使用，但于 1995 年末被系统性移除，反映 FreeBSD 早期确实引入了 Mach VM 概念但逐步去除了 Mach 微内核相关抽象，与 “FreeBSD 使用 Mach 2.5 的 VM 部分而非 microkernel 整体” 叙事方向一致；John Dyson 在 VM 子系统的角色经 bsd_commits.db `commits` 表验证：Dyson（<dyson@FreeBSD.org>）在 1995-04 至 1995-11 期间提交 13 条 VM 相关 commit（如 1995-04-21 commit 7e15fd27577744fa48ca9fde818f113b7bd52927 " Fixed a problem in _vm_object_page_clean that could cause an infinite loop."、1995-09-03 " New subroutine vm_page_set_validclean for a vfs_bio improvement."、1995-11-05 " Greatly simplify the msync code."），证明 Dyson 确为 2.x 时期 VM 子系统的主要维护者；0 信任原则提示：Dyson 的 commit 集中在 1995 年（2.0-RELEASE 于 1994.11.22 发布后），可能反映 2.0 VM 重写后的持续优化而非 2.0 重写本身，2.0 VM 重写（1994.11.22 前）的具体主导者仍需对照 1994 年 commit log 与邮件列表核验；存疑部分解决：Mach VM 概念存在性已确认（MACH_KERNEL 宏于 1995-12 移除），John Dyson 角色（1995 年 VM 维护者）已确认，但 Mach 2.5 与 Mach 3.0 的版本区分在 commit message 中未明确，仍需对照 CMU Mach 设计文档与 FreeBSD 2.0 源码核验；FreeBSD 2.0 VM 与同期 NetBSD 1.0 VM 的具体差异需对照源码核验

## 87.9.3 LKM 加载框架 → KLD 内核链接器演化（1997-1998）
  - 要点：FreeBSD 2.0-2.1 时期沿用 4.4BSD-Lite 的 LKM（Loadable Kernel Modules）框架，允许内核在运行时加载模块；LKM 框架设计原始，缺少依赖管理、符号解析、自动加载机制，加载模块需手动配置；为支持 DEC Alpha 平台移植（1997 年 5 月 Jordan Hubbard 呼吁志愿者，Doug Rabson（道格·拉布森） 自愿承担），Doug Rabson 设计新的 KLD（Kernel Linker）框架取代 LKM；KLD 引入自动符号解析、模块依赖跟踪、/boot/loader 预加载能力；KLD 在 FreeBSD 3.0-RELEASE（1998.10）成为默认内核模块框架，但开发始于 2.x 末期（1997.5）；KLD 为后续 5.x 时期内核模块化（如 devfs、**mac(4)**）奠定基础
  - 史料：Doug Rabson "Early FreeBSD Ports"（FreeBSD Foundation 2023）；FreeBSD 3.0-RELEASE Release Notes；Doug Rabson 在 freebsd-hackers 与 freebsd-alpha 邮件列表 1997-1998 年关于 KLD 设计的讨论；freebsd.db `commits` 表 KLD 首次 commit：author = Doug Rabson，author_date = 1997-05-07T16:05:47Z，commit_hash = cea6c86c11f5264ab880e5d253986982d5644dd0，message = "This is the kernel linker. To use it, you will first need to apply the patches in freefall:/home/dfr/ld.diffs to your ld sources and set BINFORMAT to aoutkld when linking the kernel."；同日 commit e8ec170c35c23c431330deb927b92c79be223350 添加 syscalls，commit a79fe60755523cab06086c7a032a326f247b7424 添加 utilities ［A］
  - 史观：总纲第 10 条——边缘者贡献：Doug Rabson 作为 Alpha 移植驱动者，其 KLD 设计影响后续整个 FreeBSD 内核模块化方向；总纲第 6 条——技术选择的代价：KLD 引入付出向后不兼容代价（LKM 模块需重写为 KLD），但获得更强的模块管理能力
  - 辨析：经 bsd_commits.db `commits` 表验证，KLD 首次合入主干时间为 1997-05-07（commit cea6c86c11f5264ab880e5d253986982d5644dd0），早于 Doug Rabson 自述的 "late 1997"，可见原型在 1997 年春季已就绪；自 1997-05-07 至 3.0-RELEASE（1998.10）的 17 个月为 LKM 与 KLD 共存期，3.0-RELEASE 后 KLD 成为默认；KLD 与 Linux kernel modules 的设计差异需对照源码核验，KLD 强调符号自动解析与依赖跟踪，Linux 模块框架在 2.4 时期（2001）才引入类似依赖管理
  - 文献：Doug Rabson "Early FreeBSD Ports"（FreeBSD Foundation）；FreeBSD 3.0-RELEASE Release Notes；freebsd-alpha 邮件列表 1997-1998 存档；Doug Rabson. This is the kernel linker. freebsd-src [DB/OL]. 1997-05-07T16:05:47Z. cea6c86c11f5264ab880e5d253986982d5644dd0 ［A］
## 87.9.4 a.out 二进制格式 → ELF 切换起步与多阶段 /boot/loader 引入（1998）
  - 要点：FreeBSD 2.x 时期默认使用 **a.out(5)** 二进制格式，a.out 是 “经典” UNIX 对象格式，源自 PDP-7/PDP-11 时代，使用紧凑头部与魔数标识，包含 .text/.data/.bss 三段；a.out 格式限制 32 位、缺少调试信息原生支持、共享库机制不灵活，难以支持 Alpha 等 64 位平台；ELF（Executable and Linkable Format）作为 SVR4 后继格式，支持多段、32/64 位、动态链接、调试信息；FreeBSD 2.2.x 系列（1997-1998）开始提供 ELF 可选支持，FreeBSD 3.0-RELEASE（1998.10）正式将 ELF 作为默认二进制格式；ELF 切换由 John Polstra、Jordan Hubbard、Peter Wemm、Doug Rabson 等在 1998 年早期数月内共同完成；同期 FreeBSD 重写引导代码——原 i386 引导代码受 UFS 8k 引导区限制仅 7.5k 可用，Alpha 平台需要更大引导空间，Mike Smith 于 1998 年 8 月 21 日（commit c2f9d95de50a777bdd6d6dd0ef834149c11813c2）首次合入多阶段 /boot/loader，Peter Wemm 实现模块预加载；多阶段引导使 /boot/loader 可加载 ELF 内核、预加载内核模块、支持网络引导；ELF 切换与多阶段引导是 Alpha 平台移植的副产品，但惠及 i386 平台
  - 史料：FreeBSD Handbook 3.12 "Binary Formats"（6.3-RELEASE 归档）；Doug Rabson "Early FreeBSD Ports"（FreeBSD Foundation 2023）；FreeBSD 3.0-RELEASE Release Notes；John Polstra 在 freebsd-hackers 邮件列表 1998 年早期关于 ELF 切换的讨论；bsd_commits.db `commits` 表 three-stage bootstrap 首次 commit：author = Mike Smith，author_date = 1998-08-21T03:17:42Z，commit_hash = c2f9d95de50a777bdd6d6dd0ef834149c11813c2，message = "This is the new unified bootstrap, sometimes known previously as the ‘three-stage’ bootstrap"；1998-09-14 commit 7877a80abd46a959310dfdf400aece20c2472ffb 添加 bootinfo 字段 ［A］
  - 史观：总纲第 6 条——技术选择的代价：a.out → ELF 切换付出应用程序兼容性代价（需提供 a.out 兼容库），但获得 64 位支持与动态链接能力；总纲第 17 条——形式与内容：二进制格式作为 “形式”（可执行文件结构）改变 “内容”（开发者可用的链接与调试能力）
  - 辨析：经 bsd_commits.db `commits` 表验证，多阶段 /boot/loader 首次合入主干为 1998-08-21（Mike Smith），早于 3.0-RELEASE（1998.10）约 2 个月，与 Alpha 移植时间线一致；FreeBSD 2.2.x 系列对 ELF 的具体支持程度在不同叙事中存在差异——部分资料称 2.2.5 起提供 ELF 支持，部分称 2.2.6 起，bsd_commits.db 中 2.2.5 tagger_date = 1997-10-21、2.2.6 tagger_date = 1998-03-24，需对照 2.2.x Release Notes 与 bsd.port.mk 中 `PORTOBJFORMAT` 的引入时间核验，bsd_commits.db 未提供 ports/ 仓库细节；a.out → ELF 切换期间 Ports Collection 中 "move-aout-libs" 目标的具体运行情况需考据；多阶段 /boot/loader 与早期 i386 bootblock 的关系需对照源码核验
