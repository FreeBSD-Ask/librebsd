# 88.10 与同时期操作系统的比较：1994-1998 年同期 Linux 2.0-2.2 内核开发、Windows NT 4.0、Solaris 2.4-2.6 的网络栈成熟度

## 88.10.1 Linux 2.0-2.2

  **要点**：Linux 2.0(1996.6) 引入 SMP 支持 (粗粒度大内核锁)、2.2(1999.1) 改进 SMP 与网络栈，引入防火墙 ipchains，但内核仍保留 BKL，调度器为 O(n)；同期 FreeBSD 2.x 在网络栈成熟度与 sendfile/dummynet 等专用功能上领先
  
**史料**：Linux 2.0/2.2 内核源码与 ChangeLog、Torvalds 在 linux-kernel 邮件列表的 SMP 讨论、Linux Weekly News 1998-1999 年技术回顾 ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律（原“技术路线分化”挂第 6 条系伪名目，按论旨改挂），Linux 与 FreeBSD 在网络栈与 SMP 上走出不同路径，Linux 优先驱动支持，FreeBSD 优先网络栈稳定性
  
**辨析**：Linux 2.2 与 FreeBSD 2.2.x 的网络性能对比在不同负载下结论不同，需对照具体基准测试
  
**文献**：Beck 等《Linux Kernel Internals》(1998)；Linux 2.2 Release Notes；Mosberger “Linux Kernel Performance”(1999)［考据注：2026-07-28 联网核验留痕；语义以正文与所引来源为准］

## 88.10.2 Windows NT 4.0

  **要点**：Windows NT 4.0(1996.7) 将图形驱动移入内核以提升性能，引入 IIS 2.0 与 TCP/IP 栈改进，但其网络栈仍为微内核设计且缺乏 sendfile 等零拷贝 API，在静态 Web 服务场景下吞吐量低于 FreeBSD
  
**史料**：Microsoft Windows NT 4.0 Resource Kit、IIS 2.0 文档、Windows NT 4.0 网络架构白皮书［考据注：2026-07-28 联网核验留痕；语义以正文与所引来源为准］ 〔L3 官方文档〕
  
**史观**：专题语（不设总纲条号）——硬件与软件辩证（原挂总纲第 7 条系自创名目，删条号），NT 4.0 将图形移入内核是硬件性能压力下的妥协
  
**辨析**：NT 4.0 与 FreeBSD 2.x 的 Web 服务性能对比受 IIS 与 Apache 实现差异影响，难以纯操作系统层面比较
  
**文献**：Custer《Inside Windows NT》(2nd ed., 1998)；Microsoft TechNet NT 4.0 文档；SPECweb96 基准测试报告 [考据脚注：Helen Custer《Inside Windows NT》（Microsoft Press, 1998, 2nd ed.）经多源出版信息确认。]

## 88.10.3 Solaris 2.4-2.6

  **要点**：Solaris 2.4(1994.11)、2.5(1995.11)、2.6(1997.5) 在企业级网络栈成熟度上领先，2.6 引入 IPv6 与 sendfilev，UFS Logging 在 2.6 后期出现，但 Solaris 的商业授权与硬件绑定限制了其在 ISP 场景的采用
  
**史料**：Solaris 2.4/2.5/2.6 Release Notes、Sun Microsystems 网络架构白皮书、Solaris Internals 文档［考据注：2026-07-28 联网核验留痕；语义以正文与所引来源为准］ 〔L3 官方文档〕
  
**史观**：总纲第 13 条——法律与道德是利益分配（原“法律结构”挂第 12 条系错配，按授权利益分配论旨改挂），Solaris 的商业授权模式与 FreeBSD 的开源模式形成对照，ISP 倾向 FreeBSD 的许可证自由
  
**辨析**：Solaris 与 FreeBSD 在 2.x 时期的网络性能对比鲜有公开基准，需查 Sun 内部测试报告
  
**文献**：Cockcroft & Pettit《Sun Performance and Tuning》(1998)；Mauro & McDougall《Solaris Internals》(2000)；Sun White Paper “Solaris Networking” [考据脚注：Adrian Cockcroft & Richard Pettit《Sun Performance and Tuning》（Sun Microsystems Press, 1998, 2nd ed.）与 Jim Mauro & Richard McDougall《Solaris Internals》（Sun Microsystems Press, 2001）经多源出版信息交叉验证确证。]

## 88.10.4 比较的辨析

  **要点**：三方比较存在硬件差异、负载差异、测试工具差异三大变量，且不同操作系统版本发布时间相差数月，难以做到 “同时期同硬件同负载” 的严格对比
  
**史料**：SPECweb96/SPECweb99 基准测试结果库、Mindcraft 1999 年 Linux vs NT 测试报告、各操作系统的官方性能白皮书［考据注：2026-07-28 联网核验留痕；语义以正文与所引来源为准］ 〔L3 官方文档；L5 二手研究〕
  
**史观**：总纲第 9 条——经验优先（原“软件工程”挂第 17 条系伪名目，基准测试属实证经验论旨，按 9 改挂），基准测试本身是工程问题，测试方法的选择影响结论
  
**辨析**：Mindcraft 测试引发的争议 (1999) 显示操作系统性能比较的政治性，需警惕厂商赞助测试的偏见
  
**文献**：Mindcraft 1999 测试报告；Linux Weekly News 对 Mindcraft 测试的分析；SPEC 基准测试方法论文档 ［B］
