# 88.11 漏洞与安全响应：FreeBSD 2.x 时期的 LAND/smurf/F00F/suidperl 漏洞群与 MFC 安全回溯模型（1995-1998）

## 88.11.1 LAND 攻击与 smurf ICMP 放大——FreeBSD 2.2.x 网络栈远程拒绝服务漏洞群

  **要点**：FreeBSD-SA-98:01.land（1997 年 12 月事件披露，1998 年 1 月公告编号发布）记录 LAND 攻击——攻击者构造源地址与目的地址相同的伪造 TCP SYN 包，导致受攻击系统进入死循环消耗资源，受影响版本为 FreeBSD 2.1.*、2.2.0R、2.2.1R、2.2.5R，该漏洞后被追溯编号为 CVE-1999-0016；FreeBSD-SA-98:06.icmp（1998 年 6 月 10 日）记录 smurf 攻击相关 ICMP 漏洞——系统响应广播 ICMP 请求导致被用作放大攻击中介，受影响版本为 FreeBSD 2.2.*；FreeBSD-SA-98:05.nfs（1998 年 6 月 4 日）记录 NFS 服务器漏洞——恶意构造的 NFS 请求可导致系统崩溃，受影响版本为 FreeBSD 2.2.*；上述三类漏洞同属远程拒绝服务类技术机制，集中于 1998 年上半年发布，反映 FreeBSD 2.2.x 网络栈在面临伪造数据包攻击时的防御基线不足——LAND 攻击利用 TCP 协议栈对源/目地址相同包的处理缺陷，smurf 利用 ICMP 广播响应放大，NFS 漏洞利用远程请求处理缺陷
  
**史料**：FreeBSD-SA-98:01.land 公告（freebsd.org/security/advisories/FreeBSD-SA-98:01.land.asc）、FreeBSD-SA-98:05.nfs 公告、FreeBSD-SA-98:06.icmp 公告、CVE-1999-0016 NVD 条目；freebsd.duckdb 数据库证据——freebsd-src 仓库 1997 年 12 月至 1998 年 6 月期间多条 security fix commit，包括 1998-02-15 Jordan K. Hubbard（乔丹·哈伯德） 连续 MFC 安全修复（commit `5c0822d91159e3d6fd341b34f2227cf890c903b8`、`46923adadad4b174d913387e4d66b419818fb585`、`e336171dc166407ee462e267cf3c40b1cc05b8d5` 等）［A］
  
**史观**：密码学与信息安全：LAND/smurf/NFS 远程拒绝服务漏洞群反映 FreeBSD 2.2.x 网络栈在伪造数据包防御上的基线不足；技术路线分化：FreeBSD 以 ipfw 防火墙作为网络层防御补充，与同期 Linux ipchains 形成路径分化
  
**辨析**：LAND 攻击的 CVE-1999-0016 编号为 CVE 体系 1999 年 1 月建立后追溯编号，公告原文未引用 CVE，史家须区分 “公告原文无 CVE” 与 “漏洞无 CVE” 两类事实；smurf 攻击的精确 ICMP 广播响应行为须对照 FreeBSD 2.2.x 内核网络栈源码核实；NFS 漏洞的具体触发路径须对照 FreeBSD-SA-98:05.nfs 公告原文核实；【0 信任原则·CVE 追溯编号】CVE-1999-0016 为事后追溯编号，漏洞实际披露于 1997 年末，CVE 编号时间与披露时间存在时差，史家不得以 CVE 编号年份推论披露年份；【0 信任原则·security fix commit 正则匹配】freebsd.duckdb 的 40 条 security fix commit 通过正则匹配 commit subject 中 “security fix” 字样识别，部分 commit（如 Jordan K. Hubbard 1998-02-15 多条 MFC commit）subject 包含 “security fixes” 但实际为批量 MFC 操作，史家须区分 “专门安全修复” 与 “MFC 中附带安全修复” 两类 commit
  
**文献**：FreeBSD-SA-98:01.land 公告；FreeBSD-SA-98:05.nfs 公告；FreeBSD-SA-98:06.icmp 公告；CVE-1999-0016 NVD 条目；freebsd.duckdb freebsd-src 仓库 security fix commit 记录；本项目。原材料/研究/bsd 漏洞史/版本周期/freebsd-2.x.md；本项目。原材料/研究/bsd 漏洞史/早期漏洞补遗/freebsd-早期漏洞.md ［A］

## 88.11.2 F00F Pentium 指令缺陷与 suidperl CERT 通告——硬件层与解释器层安全响应

  **要点**：FreeBSD-SA-97:06.f00f（1997 年 12 月 9 日）记录 Pentium 处理器 F00F 指令缺陷——用户态程序执行 F00F 锁前缀指令可导致 CPU 停机，FreeBSD 内核须通过 IDT（Interrupt Descriptor Table）重映射 workaround 修复，受影响版本为 FreeBSD 2.1.*、2.2.*，公告原文未引用 CVE 编号（F00F bug 在 CVE 体系建立后未追溯编号）；CERT Advisory CA-96.12 记录 suidperl 漏洞——1996 年 6 月 26 日 Nate Williams（内特·威廉姆斯） 连续提交两条修复 commit（`11b7f01b8fbaa99da74ec36fd63b5937b8d54bad` 与 `9295078e30f92862d02403f2f8a3255c2f4b7698`，commit subject 均为 “Fix for CERT Advisory CA-96.12 - Vulnerability in suidperl”），suidperl 为 Perl 的 setuid 副本，存在权限提升缺陷；上述两类漏洞分属硬件层（F00F 为 Intel Pentium 处理器设计缺陷）与解释器层（suidperl 为 Perl setuid 机制缺陷），反映 FreeBSD 2.x 安全响应须覆盖从硬件到用户态解释器的全栈漏洞面
  
**史料**：FreeBSD-SA-97:06.f00f 公告（freebsd.org/security/advisories/FreeBSD-SA-97:06.f00f.asc）、CERT Advisory CA-95:03（telnet 加密漏洞，1995 年 2 月 17 日 Dima Ruban commit `399e5b4411babf281130cb33fa563b4d701de467`）、CERT Advisory CA-96.12（suidperl 漏洞）；freebsd.duckdb 数据库证据——freebsd-src 仓库 1996-06-26 Nate Williams 两条 suidperl 修复 commit 完整记录 ［A］
  
**史观**：密码学与信息安全：F00F 与 suidperl 漏洞反映 FreeBSD 2.x 安全响应须覆盖硬件层与解释器层的全栈漏洞面；总纲第 6 条——硬件与软件辩证：F00F 为 Intel Pentium 处理器设计缺陷，FreeBSD 以内核 IDT 重映射 workaround 修复，体现软件层对硬件缺陷的补偿
  
**辨析**：F00F bug 影响所有 Intel Pentium 处理器（P5 架构），FreeBSD 的 IDT 重映射 workaround 为内核层修复，须对照 FreeBSD 2.1.*/2.2.* 内核源码核实修复路径；suidperl 漏洞的精确权限提升路径须对照 CERT Advisory CA-96.12 原文与 Perl 源码核实；CERT Advisory CA-95:03（telnet 加密漏洞）由 Dima Ruban 于 1995 年 2 月 17 日修复（commit `399e5b4411babf281130cb33fa563b4d701de467`），为 FreeBSD 2.x 时期最早的安全修复 commit 之一，须对照 CERT 原始通告核实漏洞机制；【0 信任原则·F00F 无 CVE 追溯】F00F bug 在 CVE 体系建立后未被追溯编号，不等于漏洞不存在 CVE——可能因 CVE 编号分配策略或时间窗口导致未追溯，史家不得以 “无 CVE” 推论 “漏洞不重要”
  
**文献**：FreeBSD-SA-97:06.f00f 公告；CERT Advisory CA-95:03；CERT Advisory CA-96.12；freebsd.duckdb freebsd-src 仓库 security fix commit 记录（Dima Ruban 1995-02-17、Nate Williams 1996-06-26）；本项目。原材料/研究/bsd 漏洞史/版本周期/freebsd-2.x.md ［A］

## 88.11.3 syslogd/master.passwd/procfs 漏洞与 MFC 安全回溯模型——服务层与权限层中低风险漏洞群

  **要点**：FreeBSD-SA-96:08.syslog（1996 年 4 月 21 日）记录 **syslogd(8)** 守护进程漏洞可能导致系统日志服务异常，受影响版本为 FreeBSD 2.0、2.0.5；1997 年 2 月 8 日 John Polstra 提交 commit `f5491fc795b1f44ac01ab139a3fd53ffc6070457`（"Security fix. Strip the encrypted passwords out of the master.passwd diff output"——从 master.passwd diff 输出中剥离加密密码，防止密码泄漏）；1997 年 8 月 25 日 Guido van Rooij 提交 commit `83dea3e840ff107d01337374c6547e99294d1967`（“MFC: procfs security patch. 2.1's not dead! Long live 2.1 ;-”——procfs 安全补丁 MFC 回溯至 2.1 分支，commit subject 中的感叹反映 2.1 分支仍被维护的事实）；1996 年 4 月 26 日 Joerg Wunsch 提交 commit `711e38f8ed0a78cbe86f57d7a59d31eebb7d67c3`（"/etc/skeykeys was basically suffering from the same vulnerability as any non-shadowed /etc/passwd"——S/Key 密钥文件存在与非影子 /etc/passwd 相同的漏洞）；上述漏洞覆盖日志服务（syslogd）、密码文件（master.passwd）、进程文件系统（procfs）、认证密钥（skeykeys）四类组件，属于中低风险级别，通过 MFC（Merge From Current）机制从 -current 分支回溯至 2.1/2.2 稳定分支
  
**史料**：FreeBSD-SA-96:08.syslog 公告、freebsd.duckdb freebsd-src 仓库 security fix commit 记录（John Polstra 1997-02-08、Guido van Rooij 1997-08-25、Joerg Wunsch 1996-04-26）［A］
  
**史观**：密码学与信息安全：syslogd/master.passwd/procfs/skeykeys 漏洞群覆盖服务层与权限层，反映 FreeBSD 2.x 安全基线的多层缺陷；组织结构塑造技术路径：MFC 回溯机制是 FreeBSD 2.x 安全响应的工程基础
  
**辨析**：syslogd 漏洞的具体机制须对照 FreeBSD-SA-96:08.syslog 公告原文核实——公告仅称 “可能导致系统日志服务异常”，未详细说明触发路径；master.passwd diff 密码剥离修复的上下文须对照 John Polstra 1997-02-08 commit diff 核实——该修复针对 master.passwd 变更输出中加密密码的泄漏风险；procfs 安全补丁的具体内容须对照 Guido van Rooij 1997-08-25 commit diff 核实——commit subject 仅称 “procfs security patch” 未说明漏洞机制；【0 信任原则·MFC 回溯的时序】MFC commit 的 author_date 为 MFC 操作时间而非原始修复时间，原始修复须在 -current 分支中查找对应 commit，史家须区分 “原始修复时间” 与 “MFC 回溯时间” 两个时点；【0 信任原则·commit subject 信息量限制】部分 commit subject（如 “YAMFC (security enhancements)”、“YAMFC (security fixes and buffer overruns)”）仅标注为 YAMFC（Yet Another MFC）附带安全修复，未说明具体漏洞机制，史家须对照 commit diff 核实
  
**文献**：FreeBSD-SA-96:08.syslog 公告；freebsd.duckdb freebsd-src 仓库 security fix commit 记录（John Polstra 1997-02-08、Guido van Rooij 1997-08-25、Joerg Wunsch 1996-04-26）；本项目。原材料/研究/bsd 漏洞史/版本周期/freebsd-2.x.md ［A］

## 88.11.4 FreeBSD 2.x 安全响应的架构关联——ipfw 防火墙引入、4.4BSD-Lite 基线与 MFC 回溯机制

  **要点**：FreeBSD 2.x 时期（1995-1998）的安全响应模型呈现 “Security Advisory 被动响应 + MFC 回溯 + ipfw 网络层防御” 三层结构——Security Advisory 以公告形式发布漏洞与补丁，MFC 机制将 -current 分支的安全修复回溯至 2.1/2.2 稳定分支，ipfw 防火墙（1994 年 Ugen J.S. Antsilevich 引入）作为网络层防御补充为 LAND/smurf 等远程攻击提供过滤能力；该模型与同期 OpenBSD 2.0/2.1（全代码审计主动识别 + errata 补丁回溯）与 NetBSD 1.1/1.2（pullup 模型回溯修复）形成对照——FreeBSD 以 MFC 与 SA 被动响应为主，无系统全代码审计，但 ipfw 防火墙为 BSD 阵营首个内核级包过滤防火墙，提供网络层防御维度；4.4BSD-Lite 作为 FreeBSD 2.x 的法律洁净基础（替代 Net/2 含争议代码），其继承的 securelevel 内核安全等级机制为漏洞响应提供纵深防御；FreeBSD 2.x 版本周期内 freebsd.duckdb 记录 40 条 security fix commit（无 CVE 编号），其中 1997 年 2 月出现密集的 YAMFC（Yet Another MFC）安全修复期——Joerg Wunsch、Eivind Eklund、Mark Murray 等开发者在 1997 年 2 月 6 日至 24 日期间连续提交十余条安全修复 MFC commit，反映 2.2-RELEASE（1997 年 3 月）发布前的安全加固集中期
  
**史料**：FreeBSD-SA-96:08/97:06/98:01/98:05/98:06 公告、freebsd.duckdb freebsd-src 仓库 40 条 security fix commit 完整记录、ipfw 防火墙引入历史（Ugen J.S. Antsilevich 1994 年）、4.4BSD-Lite securelevel 机制文档 ［A］
  
**史观**：密码学与信息安全：MFC 回溯机制是 FreeBSD 2.x 安全响应的工程基础，ipfw 防火墙为 BSD 阵营首个内核级包过滤防火墙；组织结构塑造技术路径：FreeBSD 的 -current/稳定分支双轨制决定 MFC 回溯模型的形成
  
**辨析**：ipfw 防火墙对 LAND/smurf 攻击的实际防御效果须对照 ipfw 规则语法与 FreeBSD 2.2.x 默认配置核实——ipfw 提供过滤能力但默认配置可能未启用，史家须区分 “防火墙能力存在” 与 “默认启用” 两个维度；MFC 回溯机制的覆盖率须逐 SA 核实——部分 SA 的修复可能未 MFC 回溯至所有受影响稳定分支，史家不得以 “MFC 机制存在” 推论 “所有漏洞均已回溯”；4.4BSD-Lite 的 securelevel 在 FreeBSD 2.x 时期的默认启用状态须对照内核配置核实——概念存在与默认启用为不同维度；【0 信任原则·commit 量不等于安全质量】40 条 security fix commit 反映开发活跃度但不等于安全响应质量，FreeBSD 2.x 的安全响应质量须结合 SA 公告内容与补丁覆盖范围综合判断；【0 信任原则·与 OpenBSD/NetBSD 对照的公平性】将 FreeBSD MFC+SA 模型与 OpenBSD 全代码审计对照时须注意——FreeBSD 2.x 时期的安全工程目标以功能完善与性能优化为优先，全代码审计尚未成为独立工程目标
