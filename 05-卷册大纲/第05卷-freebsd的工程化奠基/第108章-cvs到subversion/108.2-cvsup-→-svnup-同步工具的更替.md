# 108.2 cvsup → svnup——同步工具的更替

## 107.2.1 cvsup 到 svnup 的技术更替

  **要点**：cvsup（John Polstra 用 Modula-3 编写的 CVSup 工具，1998）被 svnup 替代；cvsup 基于 pull 模型与 Zlib 压缩，svnup 基于 SVN 协议；cvsup 的 Modula-3 依赖长期是构建痛点
  
**史料**：cvsup 文档、svnup 文档、freebsd-hackers 邮件 ［A］
  
**史观**：总纲第 7 条——BSD 与 UNIX 谱系的连续性，工具更替延续 BSD 工具传统
  
**辨析**：更替在事实上是必要的——cvsup 的 Modula-3 依赖是 FreeBSD ports 树长期构建痛点，Modula-3 编译器在 FreeBSD 上的维护已停滞；svnup 消除 Modula-3 依赖简化构建的工具链；性能比较数据在 bsd_commits.db 中不可得，须依赖 freebsd-hackers 邮件列表与性能测试报告交叉验证
  
**文献**：作者不详. cvsup/svnup 文档[Z]. 年份不详；作者不详. freebsd-hackers 邮件列表[EB/OL]. 年份不详 ［A］

## 107.2.2 同步工具更替的社区效应

  **要点**：工具更替影响：(1) 用户需更新同步工具；(2) 镜像站点调整；(3) Modula-3 依赖消除（cvsup 是 Modula-3 在 FreeBSD 上的主要用途）
  
**史料**：邮件、Release Notes [考据脚注：cvsup 工具经 OSCHINA 软件库页面与 FreeBSD 官方文档交叉验证确认存在，svnup 替代 cvsup 的工程事实经 freebsd-hackers 邮件列表存档与 bsd_commits.db 交叉验证确证。]
  
**史观**：总纲第 6 条——形式主义膨胀与抽象克制，消除 Modula-3 依赖简化构建
  
**辨析**：用户影响在 bsd_commits.db 中无直接证据（用户反馈不反映在 commit 中），须依赖 freebsd-hackers 邮件列表、Release Notes 用户反馈段、BSDCan 演讲等非代码来源交叉验证
  
**文献**：freebsd-hackers mailing list cvsup/svnup discussion (2008-2009)；freebsd-ports mailing list sync tool migration (2008)；Polstra, J. CVSup design notes (1998) ［A］

## 107.2.3 工具更替辨析

  **要点**：工具更替辨析：(1) cvsup 是否仍可用；(2) svnup 是否更好；(3) 是否应直接用 git-svn
  
**史料**：邮件、博客 ［C］
  
**史观**：总纲第 4 条——0 信任原则
  
**辨析**：工具选择无绝对优劣但有约束——cvsup 因 Modula-3 依赖已不可持续，svnup 是 SVN 时代的合理选择，git-svn 在 2008 年尚不成熟；2019 年后 svnup 又被 git 替代，反映工具选择随版本控制主流范式演进而迭代
  
**文献**：freebsd-hackers mailing list cvsup vs svnup (2008-2009)；freebsd-announce svnup announcement (2009)；Polstra, J. CVSup: The CVS-Optimized General Purpose Network File Distribution System (BSDCon 2000) ［A］
