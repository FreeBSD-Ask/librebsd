# 108.1 2008-2009 年 CVS → SVN 迁移的工程过程

## 108.1.1 CVS 到 SVN 迁移的工程步骤

  **要点**：FreeBSD 于 2008 年 5 月底完成从 CVS 到 Subversion 的迁移（src 仓库 2008-05-31 切换，FreeBSD committers-guide 载明首个实质 SVN 提交为 r179447），由 Peter Wemm（彼得·韦姆） 主导；迁移步骤包括：(1) 评估 SVN vs Git vs Mercurial；(2) CVS 到 SVN 仓库转换（cvs2svn 工具）；(3) 镜像切换；(4) 文档更新
  
**史料**：FreeBSD 邮件列表、commit log、SVN 迁移公告；freebsd.duckdb tags 表验证迁移时间窗口——freebsd-src 仓库 release tag 的 tagger_name 在 2008-02-24 之前均为 “cvs2svn”（如 release/7.0.0 tagger_date = 2008-02-24T05:45:17Z tagger_name = cvs2svn），自 2008-11-26 起变为 “Ken Smith”（如 release/7.1.0 tagger_date = 2008-12-31T22:57:14Z tagger_name = Ken Smith），说明 CVS-to-SVN 迁移发生在 2008-02-24 至 2008-11-26 之间，与 “2008 年 5 月底完成迁移（2008-05-31 切换）” 的官方口径吻合；freebsd.duckdb freebsd-src 仓库 commits 表 2008-07-12 Doug Barton commit `82b3dc06d3dc` message_subject = "Update this file to reflect how things are done in subversion-land"（committer_date = 2008-07-12T08:52:11Z），证明迁移完成后 2008 年 7 月 freebsd-src 已在使用 Subversion；freebsd.duckdb freebsd-src 仓库 commits 表 2008-07-07 David Malone commit `0d1532e0ef82` message_subject = "Update man page for addition of BIOCSETFNR. Subversion didn't want to commit this at the same time for some reason."（committer_date = 2008-07-07T09:27:02Z），进一步佐证迁移完成后 7 月已在使用 SVN；freebsd.duckdb freebsd-src 仓库 2008 年 6 月至 12 月月度 commit 数显示 2008-08 commit 数量达 1430（2008-06 的 644 条的 2 倍多），可能反映 SVN 迁移后开发效率提升或迁移过程本身产生的批量 commit；freebsd.duckdb contributors 表 Peter Wemm（<peter@FreeBSD.org>）在 freebsd-src 仓库共 6923 条 commit，首末活动 1995-07-05 至 2023-05-24，活跃年份包含 2008 年，与 “Peter Wemm 主导迁移” 的叙事吻合 ［A］；freebsd.duckdb 查询 L1.1.1 显示：freebsd-src 2008 年年度 commit 量在宏观趋势统计报告中被截断未显示（L1.1.1 共 572 行仅显示前 30 行），须直接查询 freebsd.duckdb 获取完整数据；可从 L1.3.2 文件操作数据间接反映开发活跃度——freebsd-src 2008 年 files_modified = 109,042、files_added = 21,331、files_deleted = 61,755，files_deleted 为 2005-2007 年均值的约 6 倍，反映 CVS-to-SVN 迁移过程中可能涉及大量文件重构或元数据变更；freebsd.duckdb 查询 L2.1.svn_migration 显示：中观模式挖掘报告中 L2.1 事件查询仅覆盖 Theo_de_Raadt_leaves_NetBSD（1994-12）、Matt_Dillon_forks_DragonFly（2003-07）、FreeBSD_SVN_to_Git_migration（2020-01）三项，无 2008 年 CVS-to-SVN 迁移事件专项查询，迁移前后 commit 量对比须直接查询 freebsd.duckdb 获取（建议查询条件：event_date =‘2008-07-01’，repos = [‘freebsd-src’]，months_before = 6，months_after = 6） ［A］

## 108.1.2 迁移的工程效应

  **要点**：迁移影响：(1) 提交速度提升；(2) 分支/标签改进（SVN 的全局版本号）；(3) 原子提交；(4) 工具链变化（cvsup → svnup）
  
**史料**：Release Notes、邮件 [考据脚注：FreeBSD 8.0-RELEASE Release Notes 与 freebsd-hackers 邮件列表存档经联网检索确认存在，SVN 迁移工程效应经 freebsd.duckdb 与上述一手来源承重验证；FreeBSD 大败局（头条，2022）仅作线索性来源、不作承重依据。]
  
**史观**：总纲第 25 条——逻辑是形式主义，SVN 比 CVS 复杂但功能更强
  
**辨析**：影响幅度在 freebsd.duckdb 中可通过月度 commit 数间接验证——freebsd-src 仓库 2008-08 commit 数量达 1430（2008-06 的 644 条的 2 倍多），但开发者主观反馈（提交速度感、分支管理体验）在 commit 中不可见，须依赖 freebsd-hackers 邮件列表与 BSDCan 演讲等非代码来源交叉验证
  
**文献**：FreeBSD 8.0-RELEASE Release Notes；Wemm, P. FreeBSD SVN Migration Announcement (2008)；freebsd-hackers SVN migration feedback (2008) ［A］

## 108.1.3 迁移辨析

  **要点**：迁移辨析：(1) 是否应选 Git 而非 SVN（2008 年 Git 已成熟）；(2) SVN 是否过时；(3) 迁移是否过早/过晚
  
**史料**：邮件、博客 ［C］
  
**史观**：总纲第 9 条——经验优先
  
**辨析**：2008 年选择 SVN 而非 Git 不是战略失误而是路径依赖的合理选择——FreeBSD CVS 仓库的提交习惯、分支模型与 CVS 心智模型深度耦合，SVN 的集中式模型与 CVS 心智模型相近，迁移成本最低；Git 的分布式模型虽技术先进但要求社区重新学习工作流，2008 年社区对 Git 的接受度不足以支撑整体迁移；2019 年迁 Git 是 Git 已成为行业事实标准后的顺势而为，与 2008 年的判断不可同日而语
  
**文献**：freebsd-hackers mailing list SVN vs Git discussion (2007-2008)；freebsd-arch mailing list VCS selection (2008)；LWN.net FreeBSD VCS migration (2008) ［A］

**要点**：

- FreeBSD 7.1 的特性包由当事人现场列明：ULE 调度器在 7.0 已随附但未设默认，7.1 起将开关翻转；John Baldwin 将 cpuset 自 8-CURRENT 回移以利计算密集应用；7.1 是首个包含 DTrace 支持的发行版；网络栈多处理器改造使 BIND 在高负载下并行性能大幅提升；Chelsio 万兆网卡的全 TCP offload 亦自 8 回移，使整个网络栈可下沉到网卡硬件运行。（BSDTalk EP164，[392.42-455.34]，L1）
- 当事人以升级体验刻画版本策略的效果：4 到 6 的迁移因 GCC 2 升 GCC 3 的 ABI 断裂与共享库版本号变更而极其痛苦，是大规模部署者的创伤记忆；6 到 7 虽同样更换编译器，但 ABI 相对稳定，配合符号版本化锁定内核与模块接口，成为平顺的增量升级。6.4 被定性为 6.x 系列近乎收官的一版，发布流程近乎自动导航；而 7.0 被评价为项目历史上最成功的点零版本之一，打破了点零发布必出问题的成见。（BSDTalk EP164，[962.70-1058.62]，L1）
- 虚拟化被确认为 8-CURRENT 的头号议题。2008 年夏在剑桥召开的开发者峰会是首次脱离大型会议独立举办的四天峰会，二十至三十名开发者集体通读数千行虚拟化代码。其中的网络栈虚拟化工作使每个 jail 拥有独立的防火墙、IPsec、路由、虚拟网络接口与限速， jail 内管理员可管理自己的栈实例，这是既有 jail 功能无法做到的。（BSDTalk EP164，[1098.78-1170.74]，L1）
- Peter Wemm 一手还原源代码控制迁移的决策史：替换 CVS 的讨论可追溯至 1997 年，历时约十一年；期间评估过 Bitkeeper、Perforce、PCVS、PRCS、Darcs、Mercurial 等候选，Perforce 曾长期承载项目分支，但其客户端状态集中于服务器导致数据库膨胀、维护纪律要求过高而不可持续；CVS 的致命缺陷是分支提交会永久丢失文件来源等元数据且不可恢复；由于无人能说服彼此，最终以行政决定选择 Subversion——作为 CVS 的逻辑后继保留既有工作流，并把分散于多个仓库的开发收拢回单一可见仓库。（BSDTalk EP164，[1500.56-1737.68]，L1）
- 迁移工程本身由 Peter Wemm 个人承担：花四至六个月修复历年积累的 RCS 文件微妙损坏，编写数千行脚本、配置与大量手写符号标签转换表，并依赖个人记忆与邮件列表存档找回仓库中已无记录的 5-STABLE 分支起点，迁移期间仓库停机数日。当事人定义的成功标准是全部开发者直接向 Subversion 提交 base 树、利用 merge info 追踪跨分支合并；同时明确过渡态：ports 与 doc 树仍留 CVS，用户继续经 CVSup 获取导出，6.x 与 7.x 发行周期在 CVS 内维护，8 是否直接自 Subversion 发行尚待决定，Perforce 项目分支预期逐步迁出收尾。（BSDTalk EP164，[1785.24-2030.32]，L1）

**史观**：

- 总纲第 10 条——动手者创造历史：被社区公认为“无法转换”的 FreeBSD 仓库最终得以后转，靠的不是制度安排而是一个人的数月劳动：Peter Wemm 自愿承担修复、记忆考订与停机转换的全部风险。这一转折点由一线动手者的个体劳动与个人记忆撬动，工程史的关键节点往往系于愿意“站出来把它做成”的具体个人。（BSDTalk EP164，[1888.04-1905.64]，L1）
- 总纲第 6 条——和解优于斗争：FreeBSD 被当事人自认为开源世界中少有的民选领导层项目：选举允许领导层渐进更替，人来人往而项目延续，避免过度依赖单一个人导致的倦怠与断档。2008 年选举中上届成员几乎全员连任、仅一人退出、两名新人加入，被在场者解读为开发者对项目现状的信任投票；权力以周期性同意而非斗争方式完成再分配。（BSDTalk EP164，[281.78-334.66]，L1）

**辨析**：

- 转写存在系统性误植，须按上下文考订：Zen 应为 Xen（6.4 与 7.1 支持以客户操作系统身份运行于 Xen，补丁来自 Kip Macy，当时未全量入 base 树，8 已全部合入）、yearly scheduler 应为 ULE 调度器、de-trace 应为 DTrace、Macurial 应为 Mercurial、user offering system 应为 guest operating system。另转写将两条录音线交错排列且说话人归属时有错乱，“两名新成员是我和 Peter”一语与 Peter Wemm 自称首届选举即任 core team 相互矛盾，新成员身份细节须以会议纪要与邮件列表复核。[存疑脚注] 本期说话人归属及个别新成员身份无法自转写内证确证。　[存疑脚注] 转写交错排列致说话人归属存疑；Zen、ULE 等均为按上下文与同期 FreeBSD 开发史所作考订，待会议纪要交叉验证。（BSDTalk EP164，[301.66-324.66]，L4）
