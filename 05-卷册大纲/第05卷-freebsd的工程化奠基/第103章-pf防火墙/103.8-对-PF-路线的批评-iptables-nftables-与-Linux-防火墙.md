# 103.8 对 PF 路线的批评：iptables/nftables 与 Linux 防火墙——对 PF 路线在 iptables/nftables 与 Linux 防火墙竞争下被工程否定的批评

## 103.8.1 Linux 自建替代的工程否定

**要点**：Linux netfilter 社区自建 nftables 而非移植 PF，是对 PF 路线的工程否定；理由包括内核耦合度（PF 与 OpenBSD 内核紧密耦合）、许可证偏好（GPL 生态对 BSD 代码的排斥）、社区习惯（netfilter 维护者倾向自研）

**史观**：总纲第 14 条——话语权与边缘者，Linux 的份额优势使其工程否定具有话语权效应

## 103.8.2 PF 路线被边缘化

**要点**：PF 路线在 Linux 生态被边缘化，仅在 BSD 生态（OpenBSD/FreeBSD/NetBSD/DragonFly BSD）使用；Linux 的份额优势使 PF 的话语权受限，nftables 成为更主流的 “现代” 防火墙

**史料**：各 OS 采用数据、邮件［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**史观**：总纲第 14 条——话语权与边缘者，PF 在 Linux 生态被边缘化体现话语权不对等

**辨析**：边缘化程度，需查各 OS 防火墙采用数据

**文献**：Netcraft/BSD usage surveys (2008-2012)；freebsd-security mailing list PF adoption discussion；netfilter-devel mailing list nftables adoption (2014) ［A］

## 103.8.3 批评的形式主义分析

**要点**：批评形式主义分析：(1) 工程否定是否公平（技术 vs 非技术因素）；(2) 边缘化是否可逆；(3) 批评是否促进 PF 改进

**史料**：邮件、博客 ［C］

**史观**：形式主义膨胀与抽象克制
