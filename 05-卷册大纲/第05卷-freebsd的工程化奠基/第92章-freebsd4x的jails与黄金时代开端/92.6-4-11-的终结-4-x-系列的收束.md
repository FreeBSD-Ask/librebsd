# 91.6 4.11 的终结——4.x 系列的收束

## 91.6.1 4.11 终结决策
  - 要点：FreeBSD Core Team 宣布 4.11(2005.1 公告 / release/4.11.0 tagger_date = 2005-01-21T13:12:42Z) 为 4.x 系列最后版本，4.x 代码冻结，开发资源转向 5.x/6.x；4.11-RELEASE 与 4.11-STABLE 双轨维护至 2006 年
  - 史料：freebsd-announce 4.11 公告、Core Team 决策记录、Release Engineering 文档；bsd_commits.db freebsd-src 仓库 tags 表 release/4.11.0 的 tagger_date = 2005-01-21T13:12:42Z（tagger = cvs2svn，target_commit_hash = a84f9c8c4d27），release/4.11.0_cvs 同日创建，双 tag 一致 ［A］
  - 史观：总纲第 25 条——终结与延续，4.11 终结 4.x 系列，延续至 5.x/6.x
  - 辨析：4.11 是否 “被迫” 终结存在争议，5.x 不稳定是因素之一；经 bsd_commits.db tags 表验证，release/4.11.0 tag 的 tagger_date 为 2005-01-21T13:12:42Z（tagger: cvs2svn），属 SVN 时代 cvs2svn 转换记录的 tag 时间，原大纲日期 2005.1（公告）正确；4.11 公告日期通常晚于 tagger_date 数日，属 FreeBSD 发布工程正常流程；【0 信任原则·committer_date 异常】L1.4.1 的 release tag 间隔数据基于 tagger_date 字段，但 tagger_date 反映 2020 年 SVN-to-Git 迁移期 tag 重打时间而非原始 release tag 时间，4.x 系列 release tag 间隔（如 4.0→4.1 为 31 天、4.1→4.2 为 55 天、4.2→4.3 为 152 天、4.3→4.4 为 289 天、4.4→4.5 为 0 天、4.5→4.6 为 148 天、4.6→4.7 为 54 天）须以官方公告日期为准而非 tagger_date；L1.4.2 排除了_cvs/_RC/_BETA/_ALPHA tag，仅保留正式 release tag 共 150 行，反映 FreeBSD release 策略从 2.x 的 “频繁小版本” 向 4.x 的 “稳定大版本” 演化
  - 文献：4.11 Release Notes；Core Team 公告；Release Engineering 文档；release/4.11.0. freebsd-src 仓库 tag [DB/OL]. 2005-01-21T13:12:42Z. tag: release/4.11.0; commit: a84f9c8c4d27 ［A］；bsd_commits.db 查询 L1.4.1：freebsd-src release tag 间隔数据（4.x 系列 release/4.0.0→4.11.0 各版本 tagger_date 与间隔天数）[DB/OL]. 原材料/研究/bsd 仓库分析/数据分析/宏观趋势统计.md；bsd_commits.db 查询 L1.4.2：FreeBSD release 策略演变（排除_cvs/_RC/_BETA/_ALPHA 后的正式 release tag，共 150 行）[DB/OL]. 原材料/研究/bsd 仓库分析/数据分析/宏观趋势统计.md
## 91.6.2 保守派与革新派对立
  - 要点：4.x 代码冻结争议中，保守派 (优先 4.x 稳定性) 与革新派 (推动 5.x 新架构) 长期对立，保守派认为 5.x 不稳定不应迫使 4.x 用户迁移，革新派认为 4.x 技术债务阻碍发展
  - 史料：freebsd-current 与 freebsd-stable 邮件列表辩论、Core Team 选举立场 ［A］
  - 史观：总纲第 6 条——技术路线分化，保守派与革新派分化是工程选择的张力
  - 辨析：两派的具体成员需查邮件列表，部分成员立场可能变化
  - 文献：freebsd-current/stable 邮件列表；Core Team 选举记录 ［A］
## 91.6.3 冻结对社区的效应
  - 要点：4.x 冻结导致部分用户转向 Linux (如 Red Hat Enterprise Linux)，因 5.x 不稳定且 4.x 不再更新；社区信心受损，直至 6.0(2005) 稳定后才恢复
  - 史料：用户迁移案例、freebsd-questions 邮件列表讨论、社区调查 ［A］
  - 史观：总纲第 16 条——经济周期，冻结期的用户流失与 Linux 2.6 成熟期经济压力叠加
  - 辨析：用户流失的量化数据难以获取
  - 文献：用户迁移案例；freebsd-questions 邮件列表；社区调查 ［A］
