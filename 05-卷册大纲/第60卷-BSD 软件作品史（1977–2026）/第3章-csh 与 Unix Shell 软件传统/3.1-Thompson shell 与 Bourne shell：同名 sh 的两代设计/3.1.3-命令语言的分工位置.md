# 3.1.3 命令语言的分工位置

<!-- MAIL_INSIGHT: ucbvax.3188 -->
**观点**：1981 年 9 月，贝尔实验室的 Joe Steffen 在 comp.unix.wizards 写道，贝尔 UNIX 支持组“绝无可能”改用 csh，因为从 Mashey shell 迁到 Bourne shell 已太过痛苦，故只能考虑给 Bourne shell 加 history 等交互特性。
**邮件来源**：Joe Steffen（贝尔实验室），comp.unix.wizards，1981 年，Message-ID: `ucbvax.3188`
**史学意义**：从贝尔实验室内部视角解释 csh 未能成为默认 shell 的路径依赖原因——shell 迁移成本高于语法优劣。
<!-- /MAIL_INSIGHT -->

<!-- MAIL_INSIGHT: ucbvax.3255 -->
**观点**：1981 年 9 月，Mark Horton 总结 csh 最有用的两个特性是 history 与 alias，job control 也有用但需大量内核修改；并称 Bourne 本拟加入 history 却因认为其应属虚拟终端驱动层而作罢。
**邮件来源**：Mark Horton（cbosgd!mark），comp.unix.wizards，1981 年，Message-ID: `ucbvax.3255`
**史学意义**：同期开发者将 csh 特性分解为交互层与内核层需求，说明 csh 与 sh 的路线差异根植于系统分层观念。
