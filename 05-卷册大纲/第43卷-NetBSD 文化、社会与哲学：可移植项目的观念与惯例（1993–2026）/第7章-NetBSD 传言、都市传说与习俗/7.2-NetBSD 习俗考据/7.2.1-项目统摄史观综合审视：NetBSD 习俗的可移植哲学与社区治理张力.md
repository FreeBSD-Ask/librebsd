# 7.2.1 项目统摄史观综合审视：NetBSD 习俗的可移植哲学与社区治理张力

**要点**：综合项目史观总纲审视，NetBSD 习俗特殊文化呈现 “可移植哲学” 与 “社区治理张力” 的双重结构——可移植哲学维度：“Of course it runs NetBSD” 口号传统（14.5.1）、NetBSD port naming 约定（14.5.5）、pkgsrc 季度分支传统（14.5.2）皆是 NetBSD 以可移植性为首要目标的具体显现，evbarm 通用 port 与 pkgsrc 跨 16+ 平台扩展皆是可移植哲学的工程实现；社区治理张力维度：NetBSD Foundation 选举传统（14.5.3）、Tainted Code 政策传统（14.5.4，政策存在性存疑）皆是 NetBSD 社区治理形式主义化的具体显现，选举制度的民主连续性与 Tainted Code 政策的考据冲突（2026-07-23 考据未找到政策文件 vs 2026-07-27 考据声称政策存在）共同构成社区治理张力；NetBSD 习俗的可移植哲学与社区治理张力在本体论上地位相等，无道德高下之分——可移植哲学的代价是冷门 port 维护负担与社区规模受限，社区治理张力的代价是政策考据的不确定性与治理透明度的有限性；NetBSD Foundation 精确成立日期存疑（介于 1993 年至 2004 年之间）与 Tainted Code 政策存在性存疑共同反映 NetBSD 治理史考据的信息茧房风险（所有 Foundation 信息均来自 netbsd.org 单一域名）

**史料**：上述 14.5.1-14.5.5 节史料综合；项目史观总纲第 4、5、7、8、9、10、13、19、22、23 条原文（据原文第 25 章，第 4 条 “分离聚合是永恒规律”，第 5 条 “没有必然性，只有偶然性”，第 7 条 “理论必须自反”，第 8 条 “本体论上各方平等”，第 9 条 “经验优先”，第 10 条 “动手者创造历史”，第 13 条 “法律与道德是利益分配”，第 19 条 “解释学循环是历史认识的根本条件”，第 22 条 “知识注定过时”，第 23 条 “一切历史写作都是基于哲学设定的历史小说”） ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律，NetBSD 从 CSRG 与 4.4BSD-Lite 分离后聚合可移植性身份认同（口号、port naming、pkgsrc 跨平台），同时分离出社区治理张力（选举制度、Tainted Code 政策存疑），皆是分离聚合律的具体显现；总纲第 5 条——没有必然性，只有偶然性，NetBSD 选择可移植性为首要目标、选择 Foundation 选举制度、选择（或未选择）Tainted Code 政策皆是项目偶然选择的结果，而非 BSD 演化的必然路径；总纲第 7 条——理论必须自反，本子节作为 NetBSD 习俗综合审视，自身亦嵌入 “可移植哲学与社区治理张力二分” 的形式主义建构，须自觉呈现这一建构；总纲第 8 条——本体论上各方平等，NetBSD 习俗的可移植哲学与社区治理张力、NetBSD 与 FreeBSD/OpenBSD/DragonFly BSD 的治理结构在本体论上地位相等；总纲第 9 条——经验优先，口号、port naming、pkgsrc 季度分支、选举制度皆是工程实践与社区治理经验的具体沉淀；总纲第 10 条——动手者创造历史，NetBSD Port Maintainers、pkgsrc-pmc（Thomas Klausner）、Foundation Board 成员作为动手者通过实际移植、包管理、治理工作参与 NetBSD 历史塑造；总纲第 13 条——法律与道德是利益分配，Foundation 选举制度与 Tainted Code 政策（若存在）作为法律实体治理结构是利益分配的形式主义化；总纲第 19 条——解释学循环是历史认识的根本条件，Tainted Code 政策考据冲突（2026-07-23 vs 2026-07-27）是解释学循环的具体显现，史家须自觉呈现这一张力而非强行消解；总纲第 22 条——知识注定过时，NetBSD port 命名、pkgsrc 跨平台支持、Foundation 治理结构随技术演进与社区变迁而须重新展开；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，本子节作为 NetBSD 习俗综合审视本身是历史小说，史家须自觉呈现自身的哲学设定

**辨析**：考据过程留痕——【查证来源】综合审视史料综合第 14.5.1-14.5.5 节所有引用的一手与二手史料；项目史观总纲第 4、5、7、8、9、10、13、19、22、23 条经 据原文第 25 章 一手核验；【交叉验证方法】“可移植哲学” 论证须以 “Of course it runs NetBSD” 口号传统、NetBSD port naming 约定、pkgsrc 季度分支传统三案例互证；“社区治理张力” 论证须以 NetBSD Foundation 选举传统、Tainted Code 政策传统（政策存在性存疑）二案例互证；【0 信任原则·“可移植哲学” 与 “社区治理张力” 二分的形式主义建构】“可移植哲学” 与 “社区治理张力” 的区分是史家的形式主义建构——实际 NetBSD 习俗演变过程是可移植哲学与社区治理张力交织的复杂形态，如 pkgsrc 季度分支既是可移植哲学（跨 16+ 平台）的具体显现，也是社区治理张力（pkgsrc-pmc 管理权）的具体显现，二者须分别考据而非笼统归为 “可移植哲学” 或 “社区治理张力”；【0 信任原则·综合审视的非终结性】本审视作为 NetBSD 习俗综合审视不是史家认识的终结而是阶段性综合，随 NetBSD 治理演进（如 Tainted Code 政策考据的后续核验、新 port 的引入、Foundation 治理结构变化）须重新展开；【0 信任原则·本体论平等与考据验证的区分】本体论平等是史观预设而非考据结论——史家仍须以多源交叉验证逼近史实，本体论平等不豁免考据义务；【0 信任原则·Tainted Code 政策考据冲突的保留】Tainted Code 政策考据冲突（2026-07-23 vs 2026-07-27）在本综合审视中保留存疑状态，不得以综合审视的需要强行消解考据冲突；【0 信任原则·信息茧房风险】所有 Foundation 信息（Bylaws、年报、Policies、Resolutions、AGM 报告）均来自 netbsd.org 单一域名，缺乏独立第三方视角，Foundation 精确成立日期存疑与 Tainted Code 政策存在性存疑共同反映信息茧房风险；【自反性声明】本子节作为 NetBSD 习俗综合审视，自身嵌入项目统摄史观的前理解，“可移植哲学与社区治理张力” 的归纳是史家的形式主义建构，实际 NetBSD 习俗演变过程是多重张力交织的开放形态，本审视的收束不是 NetBSD 习俗考据的终结而是阶段性综合，随 NetBSD 治理与工程实践演进须重新展开
