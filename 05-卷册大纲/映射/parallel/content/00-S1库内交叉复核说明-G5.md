# Task 8.2 · G5-S1 库内交叉复核清单说明（2026-11-11）

**目的**：G5（V41—V50）开工第一步——把四库现有材料先对一遍，避免重复采集与重复立 claim；产出逐卷“库内可用未用”候选清单，供 S2／S3 按 A→B→C 顺序消耗。与 G1-S1 同法同参数（同一脚本），本件只记 G5 实测与差异。

## 意图确证（档 B）

- **方向**：只读四库扫描，产出候选清单；不写库、不落大纲、不判读挂账池。
- **目标**：`映射/parallel/content/V41–V50/s1-库内交叉复核.tsv` 十件；覆盖率与分层统计可复核、可二跑。
- **不做**：不联网（归 S2 另批）、不动 `surplus` 挂账块（归 P1 旧大纲前置轮另批）、不派子代理、不碰其他在途会话的件。

## 语料（四库）

本组实测 24,247 文档、136,238 个 bigram 键：

| 来源 | 库表 | 说明 |
| ---- | ---- | ---- |
| references_fulltext | `key_facts`／`summaries`／`references` 题名 | 事实／综述／题录三类候选 |
| historical_claims | `claim.claim_text` | LIKE 粗召回＋精度闸 |
| 释疑库 | `doubts_to_resolve`（`resolution_status=open`） | 并案候选 |
| sacred_sources | `blocks` | 仅史观参照，**不作证据** |

## 方法

1. 题面与语料均取中文二元组，去高频虚词组合；
2. 非 claims 语料建 bigram 倒排，按 **IDF 加权余弦**打分（`score < 0.22` 丢弃），每源每卷保留前 3；
3. claims 侧 DuckDB `LIKE` 粗召回至多 80 行，再以精度闸过滤：命中占比 ≥0.75 **或** 与题面最长公共子串 ≥5 汉字；
4. 分层：`A`＝共享 ≥6 汉字长串（claims 为 ≥5）／`B`＝余弦 ≥0.30／`C`＝其余；S2 按 A→B→C 消耗。
