## 二、取证要点

1. **3.4.3 风险管理**：`We notice & resolve new upstream bugs that impact us immediately`（即时发现解决）＋`Much easier to upstream code and collaborate with upstream developers`（回提与协作）。管理方式是持续观察＋即时修复，**替代版本冻结**。
2. **3.4.5 分支与设备配合**：`UFS for content / ZFS for root`（单用途的文件系统分工）＋`Run FreeBSD-current`（设备本身跑 current）。激进跟进之所以可行，前提是失效面被单用途定位限定。
3. **3.6.2 定制与基本系统分界**：`We moved bulk crypto into the kernel (from nginx) to preserve the sendfile pipeline.`（通用改动入内核）＋`KTLS is a technology that moves the processing of TLS…from user applications to the operating system kernel.`（机制面向通用场景）。分界判据＝**可复用价值**，非厂商身份。
