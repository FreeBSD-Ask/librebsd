## 二、联网核查口径（本组新增，2026-11-11）

依 ykla 增令，G5 的联网核查从“库内不足时的补充”升为**每卷必做工序**，与 G1 的“全卷联网核查”同口径：

1. 每卷在 P1（库内四库＋旧大纲挂账）之后，**必须**跑一轮 P2 联网核查，覆盖该卷全部残余 open 题（含 P1 未命中题）；不得以“库内已有候选”为由跳过 P2。
2. 联网所得一律**先入 claim 库再入大纲**：`raw_source → evidence → claim` 顺序，写前 `claimdb_guard --db historical_claims／references_fulltext` PASS＋专项备份槽＋`register_waterlock probe→acquire→register→release`。
3. 每条 claim ≥2 个独立来源（不同域名或不同文献），0 信任评级，三次交叉复核（同会话分轮、独立清单、冷却间隔，不得同批自审）。
4. 查重四键（sha256／isbn_doi／source_url／题名＋首作者＋年份）与 `references_fulltext`、`doubts_standalone` 逐条对照，重合即弃并留痕。
5. 禁引来源（维基／百度百科／CSDN／百家号／HandWiki 及镜像等）不得进入 P3。
6. 已落纲但仅凭库内单一来源的块，若其题面涉可联网复核的事实（日期／人名／版次／合同号），P2 轮须回补第二来源；回补不得改动已批题面。

## 四、本组特有口径与披露

1. **挂账池 disposition 与 C 台账不同粒度**：C 台账记落盘动作（归入／挂账／移出／辑存／删除，`_land_ok.py` 只读 C1／C2），surplus 记挂账终局判读（归入／拒收／辑存／移出／删除）。V50 的 114 条 surplus 判为**拒收**，其 C 台账行仍为挂账——两账粒度不同，非漏改。
2. **拒收 ≠ 史料无效**：V50 的 114 块绝大多数是 DragonFly 技术问答与运维记录，判语为“同节 open 兄弟题题面不对应”，块体仍在只读旧树可回溯。判据与 G4 同标准（G4 记“同题佳料满配判辑存、PR 流转／端口排障／内核问答判拒收”）：**同题佳料而宿主满配者才记辑存，技术问答与运维记录记拒收**。
3. **5.1.1 的证据边界**：点亮该题的两块（2012 年归档测试与归档恢复）证明“官方归档可用并曾补入丢失邮件”，未直接证明题面所涉“自 2003 年起覆盖各组”的起点；起点由邮件存档自身覆盖范围支撑，P2 联网轮须回补第二来源或改判题面归属。
4. **本组不动旧树**：162 号文 §五 P5.4 与 §十三 反模式 6——旧树清理属 Task 9。
