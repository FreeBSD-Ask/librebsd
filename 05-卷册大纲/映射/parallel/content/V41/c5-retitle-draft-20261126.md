## 三、拟题纪律与风险披露

1. **不臆造**：全部实义锚取自本稿所引官方文档、man 页、发行公告、BSDCon 论文与 NetBSD 源码（GitHub 官方镜像，见证据稿披露）。
2. **不越级**：卷／章／节题（“第5章-NetBSD 构建与发布机制（1993–2026）”与六个节名）一字未动。
3. **题面弱化断言**：5.3.4 与 5.6.4 仅取单一来源可证的部分（-u 增量、按分支逐日重跑）；不写“发布门槛／养护代价”一类未获官证的判断。5.6.5 的题面为中性名词短语，实质结论留待证据补齐后再定。
4. **术语形态**：`build.sh`／`sys/arch`／`tests.tgz`／`pull-up`／`releng` 按官方写法直书；未造缩写、未汉译专名。
5. **待主会话裁定**：5.2.3 与 5.2.5 用端口表日期作实锚，若主会话要求年份入题需再核 README 修订历史；5.4.5 的“十一人”为 2026-11-26 现况名录，属动态数，入册宜标时点；5.6.4／5.6.5 若判 `needs_more`，题面可先冻结但不得据以填块。
