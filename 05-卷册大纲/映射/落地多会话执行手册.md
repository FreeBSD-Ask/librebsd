# 落地多会话并行执行手册（2026-10-27 立）

> **适用**：05 大纲落地 Task 7 Phase 5／6 与 Task 8 落盘段（15,206 件内容迁移）。本手册是**多会话并行交接件**：任意会话按本手册自取批次、独立执行、随时中断续上。执行规格以 `01-项目管理/01-编纂规划与报告归档/05-大纲落地Task7-8任务书-20261027.md` Phase 5／6 为准，本手册只管**并行协调协议**。

## 一、体系（三个文件，零耦合）

| 件 | 路径 | 性质 | 写者 |
| --- | --- | --- | --- |
| 批次清单 | `05-卷册大纲/映射/落地批次.tsv` | 只读基础（121 批／15,206 件；卷级批＋超 800 件卷按章拆；最大批 919） | 生成器一次性产出，执行期禁改 |
| 会话文件 | `05-卷册大纲/映射/落地会话/<batch>.claim`／`<batch>.done.json` | 占锁与完成记录（每批两件，文件名唯一） | **各会话只写自己批次的这两件** |
| 全局总账 | `05-卷册大纲/映射/落地总账.tsv` | **派生视图**（status：pending／claimed／done） | **只由合并器重生成，禁任何会话直写** |

合并器＝`script/_landing_task7_20261027/landing_ledger.py`（工作区工具，不入库；用法见 §四）。

## 二、会话章程（五步）

1. **选批**：`python script/_landing_task7_20261027/landing_ledger.py --status` → 读总账取一个 `pending` 批（自取，不指定归属）。
2. **占锁**：`… --claim <batch_id> --session <会话标签>`（原子创建 claim 文件；已占用即拒（exit 1）。旧锁 >24 小时且无 done 时可自动接管并留痕）。
3. **执行**（按任务书 Phase 5／6，**仅限本批目录子树**）：布局切片 → 7.4 内容变换（H1 编号改写、旧号引用逐处改写、逐处写 `ref-rewrite.tsv`）→ 7.5 反演校验（逐字节）→ `--plan` 差异审 → 落盘（一律 `git mv`／同盘 rename；批准的结构操作除外）→ 批内门禁（`audit_outline_landing.py --check` L1–L17、锚三数守恒、镜像双射）→ **提交（pathspec 限定本批路径＋本会话文件；>5 MB 带 `APPROVED-BIGFILE:`）**。
4. **落账**：`… --done <batch_id> --session <标签> --files <已落件数> --commit <提交哈希>`（件数须与清单 planned 一致，否则合并器断言拦截）→ `… --write` 重生成总账 → 随批提交。
5. **失败与中断**：失败**不写 done**、claim 留痕在案；批内断点＝git 提交（已落盘件由落盘器按目标存在性幂等跳过）；接续会话对陈旧锁（>24h 无 done）自动接管。

## 三、独立性契约（四不）

1. **不跨批写**：一批只写自己的目录子树＋自己的 claim／done 两件＋自己的分片台账（ref-rewrite 分片按批命名）。
2. **不直写总账**：总账是派生视图；会话只写自己的 drop 文件，合并由任意会话跑 `--write` 完成。
3. **不同批同锁**：claim 文件即排他锁；发现 BUSY 即换批（禁抢锁、禁删他人 claim）。
4. **不越权改结构**：落盘期禁改 outline／targets／mapping 结构面（Phase 4 已定稿）；内容变换仅按 7.4 范围。

## 八、题名纠正协议（2026-10-27 ykla 令：SUMMARY 小节题违规反馈会话代理改正）

> **背景**：落盘小节题沿 7.2“标准化标题原文”带入旧树 H1 题面，实测 11,455 条中 **10,145 条违规**（中英无空格 9,489／截断起头 7,033／连写挤压 1,924／过短 608／杂质残留 4，口径有交叠）。纠正清单＝`映射/题名纠正.tsv`（10,145 行，含 Tier 与 batch_dir 路由；408 行路由未中者由会话经 mapping target 自行解析）。

**会话作业流程**（并入各会话批内或批后执行）：

1. **认领**：纠正包按 `batch_dir`（卷/章）归组，沿用 §二 claim 协议（`落地会话/<dir>.claim`）；落盘批未完成者，纠正随其落盘批同批执行。
2. **Tier 1（机械）**：`new_name` 已预计算（CJK-Latin／CJK-数字空格补齐），逐件 `git mv` 落新名＋同步 `layout.tsv` 该行＋`layout-full.tsv`。
3. **Tier 2（判读）**：截断起头（“年X月…”缺年份）——读旧树正文取完整日期恢复题首；连写挤压（“TandyRadioShack1977年…”）——按词界拆分补空格。
4. **Tier 3（判读）**：过短（“导言”）与杂质残留（数据库/台账名）——按内容语义拟题（忠于正文，禁臆造）。
5. **收口**：纠正批完成→`--done` 落账→SUMMARY 由合并器统一再生（会话禁直写 SUMMARY）；改名不增删锚与内容（逐字节保真）。
