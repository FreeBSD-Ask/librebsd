**要点**：

- 节目解读 OpenBSD 的 pledge 机制：程序在完成启动阶段所需的特权操作后调用 pledge 承诺此后仅使用特定资源，违约即由内核以 SIGABRT 终止；execpromises 可为子进程单独设定承诺集，error 标志使违约返回错误而非杀死进程。（BSD Now EP236，[0.0-463.3]，L2）
- 一篇博客通过把 ArcPiece 漏洞示例从 FreeBSD 8 i386 移植到 FreeBSD 11.1 amd64，说明 32 位平台经栈传递 syscall 参数、64 位平台经寄存器与 struct syscall_args 传递的差异，并指出 Linux 32 位用寄存器而非栈。（BSD Now EP236，[509.4-857.8]，L2）
- FreeBSD 源代码库越过 330000 次提交，第 330001 次提交是 Patrick Kelsey 在 Limelight Networks 赞助下完成的 TCP Fast Open 客户端实现，其服务端若干年前为 Verisign 的 DNS over TCP 需求而写，可缩短高频连接的三次握手延迟。（BSD Now EP236，[4559.8-4701.3]，L2）
- 博客讲解 cd 命令：cd 是 shell 内建命令，由标准 Unix 的 chdir 函数发起 chdir 系统调用，内核执行并校验目录权限；/usr/bin/cd 是供无内建实现的 shell 使用的脚本包装，实际 shell 不会去执行它。（BSD Now EP236，[3430.9-3872.6]，L2）
- Warner Losh 宣布 FreeBSD 引入 Lua bootloader：源自 2014 年编程之夏（Google Summer of Code），经 Pedro Souza、Reeve Hallow、Pedro Arthur 与基金会 co-op 学生 Zachary Neve Zinger 等推进，与 Forth loader 共存，在 11.2 中可选、12 中计划默认。（BSD Now EP236，[2221.4-2702.9]，L2）
- Delphix 的 George Wilson 阐明 Compressed ARC 的设计路线：放弃业界通行的内存换出前压缩方案，利用磁盘块本已压缩的事实，让内存始终保持压缩形态、仅在读取瞬间解压，即“uncompressing data is a heck of a lot faster than compressing it”（2309.42-2314.38）。第一轮激进实现（跨文件系统共享块加回调通知机制）在完成约百分之九十五时暴露重大架构缺陷而中止，第二轮简化方案成为最终交付版本，计划于 2016 年 1 月进入 OpenZFS；实测 ARC 有效容量膨胀约 2.5 至 3 倍，128K 块解压读取约 200 微秒，单核解压吞吐 1.8-2 GB/s，不可压缩块经 shared ARC 共享指针免二次拷贝。（BSD Now EP116，[2258.47-2443.30]，L1）
- Wilson 回顾池恢复工作的起点：入职 ZFS 团队后的首个任务即排查一起客户存储池损坏，通过解析全盘 DD 镜像中的文件头，最终发现损坏根源是一名管理员误将池中磁盘重新分区为 Linux 盘，与 ZFS 本身无关；此后约完成百余次池恢复，多数归因于用户误操作或其他软件的编程错误。他将池恢复视为超越本职、观察用户真实用法的窗口，此叙事呈现了维护者隐性运维经验的生成过程。（BSD Now EP116，[3839.40-3959.18]，L1）

**史观**：

- 总纲25 逻辑是形式主义而非世界本身的结构：cd 的语义由 shell 内建命令与内核 chdir 系统调用共同完成，目录权限由内核强制而非信任用户程序，说明命令语义是经系统调用形式化的产物。（BSD Now EP236，[3777.2-3821.5]，L2）
- 总纲10 动手者创造历史：Lua bootloader 从编程之夏（GSoC）学生 Pedro Souza 起步，经多位提交者与基金会 co-op 学生接力才进入 FreeBSD，说明默默动手者接力塑造系统基础设施。（BSD Now EP236，[2232.8-2360.0]，L2）
- 总纲9 经验优先：allocation throttle 反转了跨设备均分分配的理论预设，以客户环境与内部系统的实际观测为准：池碎片化后各设备分配速度分化，索性“why not give more work to devices that are actually responding faster”（2193.18-2199.20），按响应能力倾斜工作负载使快设备保持满载。这一设计出自运维经验而非抽象公平原则，印证经验观测优先于理论均分的工程认识论。（BSD Now EP116，[2145.16-2202.86]，L1）
- 总纲4 分离聚合是永恒规律：Compressed ARC 衍生出 compressed send/receive 复制（由其同事 Dan Kimmel 完成接收端关键工作），后续 ABD 内存表示（以散布-聚集页表取代 KMEM 缓存）源于 Linux 侧设计并回流惠及全部平台，L2ARC 元数据精简则复用块指针校验和以获得 SHA-256/512 级校验。代码在 Illumos/Delphix、Linux、FreeBSD 等平台间分离又聚合，恰是 OpenZFS 时代跨平台分叉之后走向再聚合的活体样本。（BSD Now EP116，[2949.82-3055.54]，L1）
- 总纲10 动手者创造历史：Theo de Raadt 的 pledge 状态更新显示 600 个基本系统 ELF 二进制中 368 个已完成改造，并区分不值得列出的平凡工具与 reboot、mount、perl 等无法 pledge 的顽固组件，主张“low hanging fruit first”（715.35-717.25）。pledge 的历史不是安全理论史，而是无数默默改造工具的手工劳动史——默默做事的转换工作而非台前宣言构成 OpenBSD 安全路线的实体。（BSD Now EP116，[539.38-590.78]，L2）
- 总纲22 知识注定过时：主持人翻检 2002 年 Unix 开发者桌面截图：Dennis Ritchie 运行 Windows NT 4、Richard Stallman 使用 X 与 GNOME、Jordan Hubbard 身在 Apple 而用 OS X、多位开发者与 FreeBSD、NetBSD 桌面同框；当年前沿的图形环境如今看来粗糙过时，而当事人各自的选择亦充满偶然。技术在当下总显新颖、注定沦为过时之物，历史书写须与这种过时性共处而非以今日标准追认优劣。（BSD Now EP116，[5743.24-5979.92]，L2）

**史家判断**（证据等级：L2，来源：`sacred_sources.duckdb.blocks.319`）

FreeBSD 是少数人的选择，是“百分之一的生活”。选择是自由的，无可指摘。BSD 家族整体上处于操作系统的边缘地位，被 Linux 的市场占有率所淹没。国内企业大多视野有限，社会责任感有待加强，对开源项目的支持往往浅尝辄止。而反观国外企业的软件大多全平台支持，也不存在系统歧视问题。

**要点**：

- DragonFly BSD Digest 的起源由当事人自述：2003 年 Matt Dillon 自 FreeBSD 4 分叉出 DragonFly 时他注意到项目启动，想贡献却不愿以写 C 为业，而 BSD 项目几乎所有互动都在邮件列表上进行，遂决定做一份摘编网站替人筛选要闻；他先默默试运行约一周确认能坚持，再公开宣布，至访谈时已持续约五年。（BSDTalk EP169，[91.60-158.72]，L1）
- Digest 之外的社区建设包括：将 FreeBSD Handbook 转换为 DragonFly 版并自 SGML 体系迁移至今日的 wiki、搭建 DragonFly 网站的邮件列表存档、推动 wiki 与主站整合；计划次年为 DragonFly 设立非营利法人，以摆脱互联网散兵游勇状态——法人实体便于美国捐赠者移交硬件、也能提供章程焦点。他盛赞 FreeBSD Foundation 的示范：送开发者赴会、推动项目完成，年度 30 万美元募款目标接近达成。关于社区健康度，他坦承 DragonFly 仍然很小，愿意做操作系统的人数增长远不及互联网，热点在 Twitter、WordPress 式应用开发；DragonFly 的吸引力恰在人少而无既有结构，可以说事情可以这样办、没有必须沿袭的包袱，代价是谁发声谁干活。（BSDTalk EP169，[158.72-402.22]，L1）
- 他长期以 DragonFly 自用：Digest 网站本身运行于 DragonFly 机器多年；系统应用以 pkgsrc 安装，pkgsrc 对频繁升级不友好但可忍受；他在 packagebox.dragonflybsd.org 上对 pkgsrc 季度发布做约 8000 个包的 bulk build，实测这是给文件系统施压的极好方式，该机器当前即运行 HAMMER 文件系统，尽管他个人并未在其他场合使用 HAMMER。（BSDTalk EP169，[402.22-476.42]，L1）
- 他对 BSD 哲学的被吸引点做了非宗教式表述：1998 至 1999 年在旧东家因同事偶语而装上 FreeBSD 4 尝试，相较 Linux，吸引他的不是许可证立场，而是一种以质量为本的做事方式——写代码因为它是该做的对事、是高质量的做法，而非软件必须自由的信仰宣示；他认为这种 quality-based 的取向让工作本身更有趣。（BSDTalk EP169，[493.30-573.38]，L1）
- Digest 的编辑理念被他上升为氧气论：一个操作系统需要其周围的气氛，胜过其他一切。主流科技博客以轻快语调追逐硬件与游戏，不追问计算机史从何而来、BSD 为何重要；而每个计算机系三年级学生都能写一个操作系统，写完却会发现无事可做，因为操作系统真正需要的是周边生态与身份氛围。他引述某个他记不清归属者的说法，认为 FreeBSD Diary、BSD Talk 与 Digest 的工作正是定义“说自己是 BSD 用户意味着什么”，这也是 advocacy 的实质。（BSDTalk EP169，[573.38-789.40]，L1）

- 总纲13 法律与道德是利益分配：嵌入式厂商的许可证选择被当事人还原为利益分配而非哲学立场：GPL 的强制公开条款改变了源码的利益归属，BSD 许可证保留了厂商的商业秘密空间，于是法律文本成为技术之外决定操作系统胜负的变量——许可证之争本质是利益分配之争。（BSDTalk EP74，[416.70-439.08]，L1）
