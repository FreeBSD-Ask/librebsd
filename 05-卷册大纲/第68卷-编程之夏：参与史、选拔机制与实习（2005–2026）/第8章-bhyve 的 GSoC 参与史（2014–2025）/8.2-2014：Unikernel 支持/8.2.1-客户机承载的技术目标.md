**要点**：

- Brian Callahan 自 2013 年成为 OpenBSD 开发者，在 Rensselaer Polytechnic Institute 任教，并已向 OpenBSD 移植约四五十个编译器与解释器。（BSD Now EP422，[72.2-123.8]，L1）[订正：原 [82.26-112.86]，2026-09-30 SenseAudio 重转核对]
- 他在信息安全课程中让学生登录其托管的 OpenBSD 机器，讲授 strlcpy、pledge 与 unveil 等机制，并以现代二进制利用课程反向印证这些安全设计的价值。（BSD Now EP422，[1140.2-1525.8]，L1）[订正：原 [1152.74-1504.02]，2026-09-30 SenseAudio 重转核对]
- NYC*BUG 是纽约 BSD 用户组，约于 2003 至 2004 年成立，自称最古老的 BSD 用户组之一，疫情后成功转为线上活动。（BSD Now EP422，[2076.1-2336.1]，L1）[订正：原 [2083.8-2321.72]，2026-09-30 SenseAudio 重转核对]
- FreeBSD 文档团队 Benedict Reuschling 自述进入路径与当下工作：原为 Debian 用户，实习时经 FreeSBIE live CD 发现 FreeBSD（虚拟终端切换明显更快、handbook 把文档集中一处），与 Debian 并行安装数周后完全转换；硕士论文写作的漫长枯燥期读到 FreeBSD 德语文档项目招募新血的博客，回复后成为唯一响应者，由奥地利的 Johann Kois 担任导师学会文档编辑与提交规范，数月后获得完整 docs commit bit；如今一边追赶德语树的翻译积压，一边与 Alan Jude 在独立分支重写 handbook 的 ZFS 章，并坦言文档 committer 人数稀少、积压是常态，他以 mentoring 回馈自己受指导的经历，把积极贡献者培养为文档提交者。（BSD Now EP41，[978.92-1261.60]，L1）
- Benedict 的大学场景实践：为母校计算机系建设教职员与学生按需开虚拟机的教学云，评估 OpenStack 与 OpenNebula 以替代免费版 ESXi，倾向以 ZFS 作后端（虚拟机备份在 ZFS 上远比数千欧元的存储或 VMware 付费快照组件容易）；接管一门内容停留在 Linux 2.4 时代的过时 Unix 课程，全面重做并加入 BSD、ZFS 专题讲座与 sed、grep、awk 脚本课；作业不限定操作系统，让学生凭充分信息自主选择，明确表示不推销特定系统，因为 FreeBSD 并非总能解决一切问题；系里因关键业务依赖 Linux 而对引入 BSD 存在阻力。（BSD Now EP41，[1270.92-1678.12]，L1）
- 对开源协作的人类学观察与会议速修轶事：做了近 15 年 BSD 用户，此前只见过 commit message 与邮件地址，见面才发现对年龄与性格的想象常全错；邮件列表与 IRC 的技术分歧常夹杂性格冲突，纯文本难以化解，面对面通常轻松解决并找到共同基础。例证：受访者在马耳他 BHyve 虚拟机内建 ZFS pool 触发断言崩溃，45 分钟后收到修复补丁；Olivier 想要的安装器特性一夜之间出现；OpenBSD 开发者与 BHyve 开发者被安排同处一室六小时，数日内 OpenBSD 得以在 BHyve 启动——平时分处不同时区、数周数月甚至不会发生的协作，在会场被压缩为当场解决。会议还为长期纯线上奉献者“给 BSD 电池充电”，缓解只身贡献的孤独感，有人甚至按会议日程安排假期。（BSD Now EP41，[1845.48-2173.20]，L1）
- 本期标题的由来（片头预告的特别惊喜）：Benedict 以半戏谑的“处理过度提交者案例”口吻宣布，文档团队与文档工程团队一致认定，对付 excessively 提交文档树改动的 Alan Jude 的最佳方式，就是授予其 documentation commit bit；由 Warren Block、Eitan Adler 与 Benedict 三人因时区差异共同担任导师，指导其补丁流程，数月内（或更快）成为 FreeBSD 完整文档提交者——commit bit 的授予过程在听众面前全程呈现。（BSD Now EP41，[2260.60-2332.20]，L1）
- 同期新闻要点：FreeBSD 官方缺陷跟踪自 GNATS 迁移至 Bugzilla（BSDCan 期间决定立即执行、随后数周末完成，PR 编号不变，bugs.freebsd.org 提供永久 URL，迁入后缺陷关闭数量随即大涨，主持人称 GNATS 的退役“已谈了约 17 年”）；DragonFly 3.8 发布并宣布为最后一个 32 位版本，3.8.1 快速点版本随即带 OpenSSL 修复，bin 与 sbin 动态链接以启用 PAM 与 NSS，USB4BSD 成为默认，自 FreeBSD 移植 i915 驱动至 HD 4000，并采用 FreeBSD 包系统（dports），其维护者常驻 FreeBSD ports 频道工作、改进反哺 ports 树并使其更 OS 无关；OpenZFS 欧洲会议 2014 的演讲视频与幻灯上线，开发者峰会定于 11 月旧金山并特意避开与其他会议撞期。（BSD Now EP41，[65.00-797.04]，L2）
- BSD 认证组在 2011 年底的 LISA 大会现场接受访谈时仍在稳定运转：BSDA（BSD Associate）考试自 2008 年在洛杉矶 SCALE 首次施考，此后持续在美国、欧洲与加拿大的各会议提供；考试为一百题、约九十分钟，面向约六个月 BSD 经验的入门级系统管理员，考生可来自 Linux、Solaris 等背景或直接出自学术界。（BSDTalk EP209，[99.72-185.42]，L1）
- BSDA 的命题理念是不考具体命令开关而考对 BSD 系统运作的理解，例如层级文件系统布局与 Linux 的差异；受访者称 BSD 世界的命令相对各 Linux 发行版之间的分裂更为同质化，考试据此覆盖四个 BSD 系统的共同性，但建议考生考前尽量熟悉全部四系统（FreeBSD 与 DragonFly BSD 同源，NetBSD 与 OpenBSD 同源），否则可能失分。（BSDTalk EP209，[185.74-525.16]，L1）
- 认证组已与计算机化考试公司 Schroeder Measurement Technologies 签订两年合同，在美国与欧洲三百余个考点提供机考版 BSDA，考生无需等待会议临近即可付费即时考试；此举被期望显著扩大认证的全球可得性。（BSDTalk EP209，[318.42-368.30]，L1）
- BSDP（BSD Professional）面向资深系统管理员，计划由笔试或机考与动手实验考试两部分构成，对标大型网络公司的高端实验类认证，目标是确证候选人具备职场上岗所需的实际技能；该考试开发进度慢于预期，受访者估计约在 2012 年底推出；心理测量师 Dr. Sandra Dolan 持续负责考试质量的追踪。（BSDTalk EP209，[120.74-293.42]，L1）
- 备考资源完全公开：考试目标文档可免费下载，考生据此自学即可备考，无强制培训费用；study guide DVD 为 El Torrito 可启动光盘，集成 FreeBSD、NetBSD、OpenBSD 与 DragonFly BSD 四系统，可从盘中启动 FreeBSD 并以 QEMU 与 AQEMU 搭建虚拟环境同时研习四系统；DVD 销售收入用于支付心理测量师与运杂费用，是认证组的主要自我造血渠道。（BSDTalk EP209，[380.46-777.62]，L1）
- 对于认证是否会促成 BSD 各系统统一琐碎差异（同一功能使用不同开关字母）的提问，受访者认为让 BSD 社区达成此类一致超出认证组的能力；考试设计上刻意回避各系统的个体差异，聚焦功能层面的理解。（BSDTalk EP209，[539.88-596.38]，L1）
- 认证组的新方向包括：考虑为 PF 防火墙单独设立认证，理由是 PF 功能强大却在企业环境采用受限，障碍来自对支持承诺缺失的感知，认证有望推动 PF 与 BSD 的企业采用；BSDP 目标文档制定后新出现的虚拟化技术正被纳入考纲更新；当前志愿者需求集中在网站向 Plone 迁移与新增考题内容。（BSDTalk EP209，[596.38-954.64]，L1）
