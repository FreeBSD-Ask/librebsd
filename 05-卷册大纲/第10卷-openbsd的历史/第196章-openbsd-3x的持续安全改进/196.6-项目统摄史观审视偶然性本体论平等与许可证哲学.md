# 196.6 项目统摄史观审视——偶然性、本体论平等与许可证哲学

## 196.6.1 偶然性视角下的 IPFilter 许可证变更与 PF fork——以总纲第 5 条审视

**要点**：OpenBSD 3.x 时代 PF fork 事件的偶然性体现于多个具体环节——Darren Reed（达伦·里德） 在 2001 年 5 月 30 日选择在 IPFilter 3.4.31 中修改许可证的具体时点具有偶然性，该时点恰逢 OpenBSD 3.0 开发周期末期（OpenBSD 3.0 于 2001-12 发布），时间窗口的紧迫性迫使 de Raadt 必须在 6 个月内完成 PF 替代品的开发；Daniel Hartmeier（丹尼尔·哈特迈尔） 作为 PF 设计者的参与具有偶然性——Hartmeier 在 IPFilter 许可证变更前已在 OpenBSD 邮件列表贡献 IPFilter 配置示例，其从 IPFilter 用户转向 PF 设计者的角色转换是偶然性的具体显现；PF fork 后迅速被 FreeBSD（2003 年起）与 NetBSD 移植的扩散路径具有偶然性——FreeBSD 在 2003 年选择移植 PF 而非继续维护 IPFW 或选择 Linux iptables 移植，该选择与 FreeBSD 5.x 时代防火墙需求演化相关；openbsd.duckdb 显示 OpenBSD 3.x 时期（2001-2004）commit 量分别为 2001 = 11084、2002 = 9758（参见 85.1.4 中 L1.1.2 查询数据），3.x 周期开发活跃度处于 fork 后高位，PF fork 是该高位期的主要工程产出之一

**史料**：IPFilter 3.4.31 LICENSE 文件变更原始记录（2001-05-30）；OpenBSD 3.0 Release Notes（PF 首次发布，2001-12）；Daniel Hartmeier 个人 pf 历史文章（Hartmeier 角色转换记录）；openbsd.duckdb openbsd-src 仓库 commits 表（2001-2004 年度统计）；原材料/哲学/项目统摄史观/第 25 章.md（总纲第 5 条偶然性原文）〔L1 代码/构建产物/L3 官方文档与公告/L4 事后叙述〕

**史观**：总纲第 5 条——偶然性改写历史：IPFilter 许可证变更时点、Hartmeier 角色转换、PF 移植扩散路径等偶然性节点共同构成 PF fork 事件的因果网络，openbsd.duckdb 提供的时间戳数据可精确还原这些偶然性节点的时序；OpenBSD 对 BSD 许可证纯洁性的坚守是长期累积的结构性条件，而非超历史的“必然”——结构性条件本身亦由偶然性事件（4.4BSD-Lite 和解协议、NetBSD fork 时的许可证选择、de Raadt 个人许可证哲学的强化）累积而成，不存在独立于偶然性的“结构性必然”

**辨析**：【偶然性 vs 结构性的辩证边界】IPFilter 许可证变更的具体时点（2001-05-30）具有偶然性，OpenBSD 对 BSD 许可证纯洁性的坚守是长期累积的结构性条件——结构性条件本身亦由偶然性事件累积而成，不存在独立于偶然性的“必然”；【Hartmeier 角色转换的偶然性局限】Hartmeier 从 IPFilter 用户转向 PF 设计者的角色转换虽具偶然性，但 OpenBSD 社区对 PF 设计者的需求是长期累积的结构性条件——偶然性的人物（Hartmeier）回应了长期累积的结构性需求（PF 设计者），而非“偶然性满足必然性”；【openbsd.duckdb 数据的偶然性局限】openbsd.duckdb 提供的 commit 量反映开发活跃度但不反映 PF fork 决策过程，决策过程须以邮件列表与个人声明核验；【总纲第 5 条的引用边界】总纲第 5 条“偶然性改写历史”不等于“历史由偶然性决定”，须对照原文核验避免断章取义

## 196.6.2 本体论平等视角下的 PF 与 IPFilter、IPFW、iptables——以总纲第 8 条审视

**要点**：以总纲第 8 条“本体论上各方平等”审视 PF 与 IPFilter、FreeBSD IPFW、Linux iptables 的设计哲学平等——PF（OpenBSD，状态跟踪与简洁语法）、IPFilter（Darren Reed，跨平台部署）、IPFW（FreeBSD，性能优先）、iptables（Linux，灵活性优先）四种防火墙设计哲学在本体论上地位平等，无任何一方构成对其他方的本体论优越或劣等；de Raadt 在 IPFilter 许可证变更后选择 fork 而非协商的“对抗性路径”与 Darren Reed 修改许可证的“商业化路径”在本体论上地位平等——de Raadt 维护 BSD 许可证纯洁性的诉求与 Darren Reed 维护 IPFilter 商业控制权的诉求均有其历史语境与合理性，无须以“对错”二元裁决；openbsd.duckdb 显示 OpenBSD 3.x 时期 commit 量 2001 = 11084、2002 = 9758 反映 PF fork 后开发活跃度高位，但 commit 量不等于代码质量亦不等于设计哲学优越性

**史料**：原材料/哲学/项目统摄史观/第 25 章.md（总纲第 8 条原文）；IPFilter 3.4.31 LICENSE 文件；OpenBSD CVS commit log（PF 相关 commit）；FreeBSD CVS/Git commit log（IPFW 与 PF 移植相关）；Linux iptables 文档；openbsd.duckdb openbsd-src 仓库 commits 表（2001-2002 年度统计）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 8 条——本体论上各方平等：PF、IPFilter、IPFW、iptables 四种防火墙设计哲学在本体论上地位平等，无任何一方构成对其他方的本体论优越或劣等；de Raadt 与 Darren Reed 的许可证争议是平等主体间的分歧，争议本身不否定任何一方的本体论地位

**辨析**：【本体论平等的引用边界】“本体论上各方平等”不等于“各方设计哲学无差异”——PF 的状态跟踪与 IPFW 的性能优先在设计哲学上有差异，本体论平等不否定设计哲学差异；【commit 量与设计哲学优越性的辨析】openbsd.duckdb 显示的 commit 量反映开发活跃度但不等于代码质量亦不等于设计哲学优越性，commit 量高的项目不必然优于 commit 量低的项目；【de Raadt vs Darren Reed 的本体论平等边界】de Raadt 与 Darren Reed 在本体论上地位平等，但 OpenBSD 项目对 BSD 许可证纯洁性的坚守是其工程哲学的组成部分，Darren Reed 对 IPFilter 商业控制权的维护是其个人选择——本体论平等不否定工程哲学差异，亦不否定对工程哲学的合理性判断；【总纲第 8 条的引用边界】总纲第 8 条“本体论上各方平等”不等于“各方立场无差异”，须对照原文核验避免断章取义

## 196.6.3 法律与道德是利益分配——以总纲第 13 条审视 IPFilter fork 与撤权

**要点**：以总纲第 13 条“法律与道德是利益分配”审视 IPFilter fork 与 de Raadt 撤权决定——IPFilter fork 的形式是“许可证冲突下的工程必要”，实质是 OpenBSD 与 Darren Reed 在许可证纯洁性利益分配上的冲突：OpenBSD 维护 BSD 许可证纯洁性的工程哲学利益，Darren Reed 维护 IPFilter 商业控制权的个人利益，二者的利益分配无法通过协商调和，fork 是 OpenBSD 以工程权力（开发替代品）排除许可证冲突的终极手段；de Raadt 撤权决定的形式是“组织权限调整”，实质是 de Raadt 与被撤权者在 OpenBSD 工程方向上的利益分配冲突：de Raadt 维护“安全至上”工程方向的主导权，被撤权者维护其在 OpenBSD 工程中的贡献权益，二者的利益分配无法通过 OpenBSD 内部审议机制调和（OpenBSD 无正式审议机制），撤权是 de Raadt 以个人权力排除异见的终极手段；openbsd.duckdb 显示 OpenBSD 3.x 时期 de Raadt 的 commit 量［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］（须以 commits 表 author_email = <deraadt@openbsd.org> 核验）反映其在 OpenBSD 工程中的主导地位，该主导地位是撤权决定的工程权力基础

**史料**：原材料/哲学/项目统摄史观/第 25 章.md（总纲第 13 条原文）；IPFilter 3.4.31 LICENSE 文件；OpenBSD CVS commit log（de Raadt 与被撤权者的 commit 时间分布）；de Raadt 与 Darren Reed 邮件列表争论存档（2001 年 5 月 IPFilter 许可证变更期间）；openbsd.duckdb openbsd-src 仓库 commits 表（de Raadt 的 commit 量统计［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］）

**史观**：总纲第 13 条——法律与道德是利益分配：IPFilter fork 与撤权决定均以“项目利益”为名（OpenBSD 的“许可证纯洁性”与“安全至上”工程方向），但“项目利益”的界定本身即利益分配的争议焦点——OpenBSD 界定的“项目利益”是 BSD 许可证纯洁性与安全至上，被撤权者界定的“项目利益”是其贡献权益的维护，二者无客观裁决标准，须以多元利益框架审视

**辨析**：【利益分配的多维性】IPFilter fork 与撤权决定的利益分配冲突须区分工程哲学利益（BSD 许可证纯洁性 vs 商业控制权）、组织利益（de Raadt 主导权 vs 被撤权者贡献权益）、社区利益（OpenBSD 安全至上 vs 被撤权者多元主张）三个维度，不得简化为单一维度；【fork 与撤权的法律形式 vs 实质】IPFilter fork 的法律形式是“许可证冲突下的工程必要”，但实质是 OpenBSD 以工程权力排除 Darren Reed 的许可证控制权；撤权决定的法律形式是“组织权限调整”，但实质是 de Raadt 以个人权力排除异见——法律形式与实质的差异须分别评估；【总纲第 13 条的引用边界】总纲第 13 条“法律与道德是利益分配”不等于“法律与道德无客观性”，须对照原文核验——该条强调法律与道德的形式服务于利益分配，但不否定利益分配本身的合理性判断

## 196.6.4 解释学循环与权力知识共谋——以总纲第 19 条审视 PF 叙事

**要点**：以总纲第 19 条“解释学循环与权力知识共谋”审视 PF fork 与撤权事件的叙事建构——PF fork 事件的叙事在不同立场中呈现显著差异：OpenBSD 阵营叙事强调“IPFilter 许可证冲突下的工程必要”，Darren Reed 阵营叙事强调“de Raadt 的意识形态优先于工程实用”，FreeBSD 阵营叙事强调“PF 移植至 FreeBSD 是 BSD 许可证自由的体现”；三种叙事的前理解（vorverständnis）差异决定其叙事建构的差异——OpenBSD 阵营的前理解是“BSD 许可证纯洁性是工程哲学基础”，Darren Reed 阵营的前理解是“许可证修改是作者权利”，FreeBSD 阵营的前理解是“BSD 许可证允许下游自由修改”；openbsd.duckdb 提供的客观数据（commit 时间戳、贡献者统计、tag 序列）可部分校正叙事偏差，但数据本身亦非中立——commit 量反映开发活跃度但不反映代码质量，tag 序列反映 release 节奏但不反映 release 质量；权力与知识的共谋体现于叙事建构——de Raadt 通过 fork 公告与 commit message 建构“工程必要”叙事，Darren Reed 通过许可证声明建构“作者权利”叙事，两种叙事均以“工程利益”为名但服务于不同的权力诉求

**史料**：原材料/哲学/项目统摄史观/第 25 章.md（总纲第 19 条原文）；IPFilter 3.4.31 LICENSE 文件；de Raadt 与 Darren Reed 邮件列表争论存档（2001 年 5 月）；OpenBSD 3.0 Release Notes（PF fork 官方叙事）；Daniel Hartmeier 个人 pf 历史文章（PF 设计者叙事）；openbsd.duckdb openbsd-src 仓库 commits 表（客观数据 vs 主观叙事的对照）

**史观**：总纲第 19 条——解释学循环与权力知识共谋：PF fork 事件的三种叙事（OpenBSD 阵营/Darren Reed 阵营/FreeBSD 阵营）的前理解差异决定其叙事建构的差异，openbsd.duckdb 提供的客观数据可部分校正叙事偏差但数据本身亦非中立；权力与知识的共谋体现于叙事建构——de Raadt 通过 fork 公告建构“工程必要”叙事，Darren Reed 通过许可证声明建构“作者权利”叙事，两种叙事均服务于各自的权力诉求

**辨析**：【解释学循环的前理解核验】三种叙事的前理解须以各自的原始文本核验——OpenBSD 阵营前理解以 OpenBSD 3.0 Release Notes 与 de Raadt 邮件列表发言为准，Darren Reed 阵营前理解以 IPFilter LICENSE 文件与 Darren Reed 邮件列表发言为准，FreeBSD 阵营前理解以 FreeBSD Release Notes 与 FreeBSD 邮件列表发言为准，不得以二手转述替代原始文本；【客观数据的中立性边界】openbsd.duckdb 提供的客观数据可校正叙事偏差但本身亦非中立——commit 量反映开发活跃度但不反映代码质量，tag 序列反映 release 节奏但不反映 release 质量，数据的中立性须以多元数据源交叉验证；【权力知识共谋的辨析边界】de Raadt 与 Darren Reed 的叙事建构均以“工程利益”为名但服务于不同的权力诉求，须区分“工程利益”的话语策略与实质——de Raadt 的“工程利益”实质是 BSD 许可证纯洁性的维护，Darren Reed 的“工程利益”实质是 IPFilter 商业控制权的维护；【总纲第 19 条的引用边界】总纲第 19 条“解释学循环与权力知识共谋”不等于“所有叙事均无客观性”，须对照原文核验——该条强调叙事建构的前理解差异与权力诉求，但不否定客观数据的校正作用

## 196.6.5 综合结论—— PF fork 与撤权事件的历史意义与多元史观审视

**要点**：OpenBSD 3.x 时代 PF fork 与 de Raadt 撤权事件的历史意义须以多元史观综合审视——以总纲第 5 条（偶然性）审视，IPFilter 许可证变更时点、Hartmeier 角色转换、PF 移植扩散路径等偶然性节点共同构成 PF fork 事件的因果网络，OpenBSD 对 BSD 许可证纯洁性的坚守是长期累积的结构性条件，不可将其叙述为超历史的“必然”；以总纲第 8 条（本体论平等）审视，PF、IPFilter、IPFW、iptables 四种防火墙设计哲学在本体论上地位平等，de Raadt 与 Darren Reed 的许可证争议是平等主体间的分歧，争议无须以“对错”二元裁决；以总纲第 13 条（法律与道德是利益分配）审视，IPFilter fork 与撤权决定均以“项目利益”为名但服务于不同的利益分配诉求，“项目利益”的界定本身即争议焦点；以总纲第 19 条（解释学循环与权力知识共谋）审视，PF fork 事件的三种叙事（OpenBSD 阵营/Darren Reed 阵营/FreeBSD 阵营）的前理解差异决定其叙事建构的差异，openbsd.duckdb 提供的客观数据可部分校正叙事偏差但数据本身亦非中立；综合四条总纲审视，PF fork 与撤权事件的历史意义在于——它是 BSD 阵营内部对许可证纯洁性、工程效率、程序正义等多元议题的多元回应之一，无须以单一史观裁决其正当性，而应以多元史观承认其历史复杂性的具体显现

**史料**：原材料/哲学/项目统摄史观/第 25 章.md（总纲第 5、8、13、19 条原文）；openbsd.duckdb openbsd-src 仓库 commits/contributors/tags 表（PF fork 与撤权事件客观数据）；IPFilter 3.4.31 LICENSE 文件；OpenBSD 3.0-3.6 Release Notes；FreeBSD CVS/Git 仓库（PF 移植相关）；de Raadt 与 Darren Reed 邮件列表争论存档

**史观**：综合总纲第 5 条（偶然性）、第 8 条（本体论平等）、第 13 条（法律与道德是利益分配）、第 19 条（解释学循环与权力知识共谋）——四条总纲从不同维度审视 PF fork 与撤权事件，承认其历史复杂性的多元显现，无须以单一史观裁决其正当性；多元史观的综合审视不等于取消史观判断，而是要求史观判断须以多元维度为基础，避免单一视角的偏颇

**辨析**：【多元史观的边界】综合四条总纲审视不等于取消史观判断——多元史观要求承认 PF fork 与撤权事件的历史复杂性，但亦要求承认其客观影响（PF 成为 OpenBSD/FreeBSD/NetBSD 三大 BSD 默认防火墙，撤权决定塑造 OpenBSD 个人主导治理模式）；【史观综合的方法论】四条总纲的综合审视须以多元维度为基础，避免单一视角的偏颇——总纲第 5 条审视偶然性、第 8 条审视本体论平等、第 13 条审视利益分配、第 19 条审视叙事建构，四者维度不同须分别评估后综合；【综合结论的开放性】综合结论不构成对 PF fork 与撤权事件正当性的最终裁决，而是为后续史观审视提供多元框架——PF fork 与撤权事件的历史意义须在后续 BSD 历史叙事中持续审视与重构

## 196.6.6 综合审视——以总纲第 13、19、21 条审视“代码掠夺”与“排他性”争议

**要点**：以项目史观总纲第 13 条（法律与道德是利益分配）、第 19 条（解释学循环与权力知识共谋）、第 21 条（革命与改革是历史方法论的分歧）综合审视“代码掠夺”与“排他性”争议——以总纲第 13 条审视，“代码掠夺”批评的形式是“工程伦理指控”，实质是 OpenBSD 与 FreeBSD pf 移植维护者在工程投入与回馈义务利益分配上的冲突：OpenBSD 维护“上游权威”的工程信誉利益，FreeBSD 维护“下游自主”的工程演进利益，二者的利益分配无法通过 BSD 许可证条款（法律形式）完全调和——BSD 许可证允许下游自由修改但未规定回馈义务，“回馈”是工程伦理而非法律义务，利益分配的冲突须以工程协商（如上游-下游同步机制）补充；“排他性”批评的形式是“安全文化指控”，实质是 OpenBSD 安全审计文化与其他 BSD/Linux 安全模型在“安全合法性”利益分配上的冲突：OpenBSD 维护“全代码审计”的安全叙事主导权，FreeBSD TrustedBSD 与 Linux SELinux 维护各自安全模型的合法性，二者的利益分配无法通过“默认安装安全”等量化指标完全调和——量化指标的选择本身就是利益分配的争议焦点；以总纲第 19 条审视，“代码掠夺”与“排他性”争议的叙事建构受各方前理解差异决定——OpenBSD 阵营的前理解是“BSD 许可证纯洁性与上游权威是工程哲学基础”，FreeBSD pf 移植维护者阵营的前理解是“BSD 许可证自由允许下游自主演进”，Linux 阵营的前理解是“安全实践的多元性优于单一审计文化”；三种前理解的差异决定各方对“代码掠夺”与“排他性”的叙事建构差异——OpenBSD 阵营将 FreeBSD pf 移植建构为“未回馈上游的工程汲取”，FreeBSD 阵营将同一事件建构为“许可证自由的工程实践”，Linux 阵营将 OpenBSD 安全文化建构为“排他性 monoculture”；openbsd.duckdb 提供的客观数据（commit 时间戳、代码 diff）可部分校正叙事偏差，但数据本身亦非中立——commit 量反映开发活跃度但不反映代码质量，代码 diff 反映分化程度但不反映分化原因（架构差异 vs 工程恶意）；以总纲第 21 条审视，“代码掠夺”与“排他性”争议亦反映“革命与改革”方法论的分歧——OpenBSD 的“全代码审计”是“改革”方法论的具体显现：自 1996 年 fork 起以“逐行审计-逐步修复”的渐进改革方式构建安全基本系统，是“破心中贼难”的改革路径；FreeBSD 的 pf 移植策略亦是“改革”方法论：以“取用-改造-集成”的渐进改革方式替代 IPFW 的不足，是“破山中贼易”的改革路径；Linux 阵营的 SELinux 是“革命”方法论：以“类型强制”模型从零构建强制访问控制框架，2003 年合入 Linux 2.6 内核主线，是“推翻旧模型-建立新模型”的革命路径；“代码掠夺”争议实质是“改革方法论”内部的分歧——OpenBSD 与 FreeBSD 同属“改革”路径但改革节奏与方向不同，OpenBSD 以“上游权威”维护改革方向，FreeBSD 以“下游自主”调整改革节奏；“排他性”争议实质是“改革”（OpenBSD 全代码审计）与“革命”（Linux SELinux）方法论的分歧——OpenBSD 的“改革”路径强调“默认安装安全”，Linux 的“革命”路径强调“访问控制框架”，两条路径各有其工程代价，改革的困难远高于革命——OpenBSD 自 1996 年起持续 6 个月发布周期内的全代码审计反映改革的持续工程投入；综合三条总纲审视，“代码掠夺”与“排他性”争议的历史意义在于——它是 BSD 阵营内部对许可证哲学、工程伦理、安全实践合法性、革命与改革方法论等多元议题的多元回应之一，无须以单一史观裁决其正当性，争议本身的不可调和性反映 BSD 阵营内部工程哲学的多元性，和解史观要求承认多元立场的并存而非强制统一

**辨析**：【总纲第 13 条的引用边界】“法律与道德是利益分配”不等于“法律与道德无客观性”，须对照原文核验——该条强调法律与道德的形式服务于利益分配，但不否定利益分配本身的合理性判断；【总纲第 19 条的引用边界】“解释学循环与权力知识共谋”不等于“所有叙事均无客观性”，须对照原文核验——该条强调叙事建构的前理解差异与权力诉求，但不否定客观数据的校正作用；【总纲第 21 条的引用边界】“革命与改革是历史方法论的分歧”不等于“革命与改革无优劣”——该条强调“改革的困难远高于革命”，须对照原文核验避免断章取义，亦不得以“改革优于革命”为名否定革命方法论的历史合理性；【革命与改革的方法论判断边界】OpenBSD 的“全代码审计”是否构成“改革”而非“革命”须以具体工程实践核验——OpenBSD 未推翻 NetBSD 代码基础而是审计改造，符合“改革”定义；Linux 的 SELinux 是否构成“革命”而非“改革”须以具体工程实践核验——SELinux 从零构建类型强制模型，符合“革命”定义；【“代码掠夺”争议的方法论定位】PF 移植至 FreeBSD 的争议是“改革方法论”内部的工程节奏分歧而非“革命 vs 改革”的方法论分歧，须以 OpenBSD 与 FreeBSD 同属“改革”路径为前提审视；【综合审视的开放性】综合三条总纲审视不构成对“代码掠夺”与“排他性”争议正当性的最终裁决，而是为后续史观审视提供多元框架
