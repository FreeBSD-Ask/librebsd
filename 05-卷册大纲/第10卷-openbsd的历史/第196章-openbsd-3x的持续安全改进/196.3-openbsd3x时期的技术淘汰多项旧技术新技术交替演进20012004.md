# 196.3 OpenBSD 3.x 时期的技术淘汰——多项旧技术 → 新技术交替演进（2001-2004）

**技术淘汰时间线**：

| 时期 | 旧技术 | 新技术 | 说明 |
| --- | --- | --- | --- |
| 2001.12 | IPFilter（限制性许可证） | pf 防火墙 | Darren Reed（达伦·里德） 修改 IPFilter 许可证，de Raadt 决定由 Hartmeier 主导开发 pf 替代 |
| 1999-2001 | SSH 1.x 商业版 | OpenSSH 默认集成 | Ylönen 商业化 SSH，OpenBSD fork SSH 1.2.12 开发 OpenSSH |
| 3.x 时期 | tcp_wrappers 独立工具 | OpenBSD 内置 tcpd 集成 | Wietse Venema 的 tcp_wrappers 被集成为基本系统组件 |
| 3.1-3.3 | 朴素栈保护 | ProPolice/SSP 与 W^X 内存保护 | W^X（3.1）与 SSP（3.3）完成从被动修补到主动防御的跃迁 |

## 196.3.1 IPFilter → pf 防火墙引入（OpenBSD 3.0，2001.12）

**要点**：Darren Reed 2001 年 5 月 30 日在 IPFilter 3.4.31 中修改许可证，加入限制性条款（“不得修改或重新分发”等），与 OpenBSD 的 BSD 许可证传统冲突；de Raadt 决定由 Daniel Hartmeier（丹尼尔·哈特迈尔） 主导开发 pf（Packet Filter）替代 IPF；pf 1.0 随 OpenBSD 3.0（2001.12）发布，采用 BPF 字节码与状态跟踪机制，设计强调简洁性与可扩展性；pf 迅速成为 OpenBSD 默认防火墙并被 FreeBSD/NetBSD 移植，完成“商业许可证防火墙 →BSD 许可证防火墙”的替代

**史料**：IPFilter 3.4.31 LICENSE 文件变更；Darren Reed 与 de Raadt 邮件列表争论；OpenBSD 3.0 Release Notes pf 部分；Daniel Hartmeier 个人 pf 历史文章 ［A］

**史观**：总纲第 12 条——法律结构；总纲第 24 条——许可证；总纲第 2 条——分离与聚合：IPFilter 许可证变更作为法律结构变化催生 pf fork，pf 作为独立防火墙框架与 OpenBSD 内核聚合

**辨析**：IPFilter 许可证变更的具体条款在不同叙事中存在差异——部分资料称“不得用于商业用途”，部分称“不得修改”，需对照 IPFilter 3.4.31 原始 LICENSE 文件核验；Darren Reed 的动机（商业 vs 个人）需考据；pf 1.0 的具体发布日期存在 2001.12.1 与 2001.12.3 两种说法，需对照 OpenBSD 官方公告核验；经 bsd_commits.db openbsd-src commits 表验证，openbsd-src tag_count = 0，无 OpenBSD 3.0 release commit 直接证据（commits 表无 release 模式匹配），数据库可证实的是 OpenBSD 3.5 相关 commit 为 2004-03-28（"Revise for OpenBSD 3.5"），pf 1.0 与 3.0 的具体发布日期须与 OpenBSD 官方公告与 CVS 仓库交叉验证，保留 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]

## 196.3.2 SSH 1.x 商业版 → OpenSSH 默认集成（1999.12 引入，3.x 持续演进）

**要点**：Tatu Ylönen 1999 年宣布 SSH 商业化并将后续版本改为非自由许可证；OpenBSD 团队 1999.10 fork SSH 1.2.12 开发 OpenSSH 1.0；至 OpenBSD 3.x 时期（2001-2004），OpenSSH 已成为基本系统默认 SSH 实现，支持 SSH 协议 2（OpenSSH 2.0，2000）、DSA 公钥认证与 AES 加密；OpenSSH 完成“商业 SSH→ 自由 OpenSSH”的替代并成为 Unix 生态标准

**辨析**：SSH 1.2.12 的具体许可证在不同叙事中存在差异——部分资料称 BSD，部分称“自由但非 BSD”，需对照原始源码 LICENSE 文件核验；OpenSSH 2.0 的具体发布日期在不同来源中存在差异，需对照 OpenBSD 官方公告核验；OpenSSH 在 3.x 时期的具体功能演进（协议 2、AES 等）需对照 Release Notes 核验

## 196.3.3 Wietse Venema tcp_wrappers → OpenBSD 内置 tcpd 集成

**要点**：Wietse Venema 的 tcp_wrappers（**tcpd(8)**）是 1990 年代 Unix 生态广泛使用的访问控制工具，通过 LD_PRELOAD 或 inetd.conf 包装网络服务；OpenBSD 3.x 时期将 tcp_wrappers 集成为基本系统组件，提供基于 **hosts.allow(5)** 与 **hosts.deny(5)** 的访问控制；后续因 inetd 模型本身被替代（OpenBSD 后期移除 tcpd 直接集成），tcp_wrappers 在 OpenBSD 中逐步淡出，但其访问控制思想被 pf 与 sshd 配置继承；可视为“独立 tcp_wrappers 工具 →OpenBSD 内置访问控制机制”的演进

**史料**：Wietse Venema tcp_wrappers 项目文档；OpenBSD 3.x Release Notes tcpd 部分；man **tcpd(8)**、**hosts.allow(5)**、**hosts.deny(5)** 历次版本；OpenBSD 邮件列表关于 tcpd 集成的讨论 ［A］

**史观**：总纲第 2 条——分离与聚合；总纲第 10 条——边缘者贡献：tcp_wrappers 作为 Venema 的边缘贡献被 OpenBSD 聚合至基本系统

**辨析**：tcp_wrappers 在 OpenBSD 中的具体集成时间在不同叙事中存在差异——部分资料称始于 2.x，部分称始于 3.0，需对照 Release Notes 与 man pages 核验；tcp_wrappers 后续在 OpenBSD 中的淡出时间需考据；inetd 模型本身被替代的具体版本需考据

**文献**：tcp_wrappers 项目文档；OpenBSD Release Notes；man **tcpd(8)**、**hosts.allow(5)**[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]

## 196.3.4 朴素栈保护 → ProPolice/SSP 与 W^X 内存保护（3.1-3.3）

**要点**：OpenBSD 3.1（2002.5）引入 W^X（Write XOR Execute）内存保护机制，由 Niels Provos（尼尔斯·普罗沃斯） 主导，利用 i386 与 amd64 的 NX bit 等硬件特性使栈与堆内存不可执行；OpenBSD 3.3（2003.5）引入 stack protector（ProPolice/SSP），由 Hiroaki Etoh 与 IBM Tokyo Research Lab 贡献，在函数返回地址前插入 canary 检测栈溢出；两者完成“朴素可执行栈 → 不可执行栈”与“无栈保护 →canary 保护”的替代，成为 OpenBSD 对缓冲区溢出攻击的根本性防御，后被 Linux/FreeBSD/NetBSD 效仿

**史料**：OpenBSD 3.1 Release Notes W^X 部分；OpenBSD 3.3 Release Notes SSP 部分；Provos W^X 设计文档；ProPolice/SSP 设计文档；IBM Tokyo Research Lab 论文 ［B］

**史观**：总纲第 10 条——边缘者贡献；总纲第 17 条——形式与内容：W^X 与 SSP 作为形式主义化安全机制改变程序内容的安全特性

**辨析**：OpenBSD W^X 与 Linux PaX、FreeBSD exec shield 的关系需考据——PaX 项目更早但未集成至 Linux 主线；i386 不支持 NX bit 的硬件（如 Pentium III）的兼容性需考据；SSP 的具体实现细节（canary 类型、函数选择）在不同来源中存在差异，需对照源码核验；SSP 的性能开销在不同工作负载上差异较大

**文献**：OpenBSD 3.1/3.3 Release Notes；Provos W^X 文档；ProPolice 文档；IBM Tokyo Research Lab 论文；PaX 项目文档 ［B］

**要点**：

- Brighton Chilli 是当事人对 BSD 倡导的实践答案：一张基于 FreeBSD 的 live CD，开箱即含 radius 服务器、web 服务器与 PF 防火墙，承载完整的受管 ChilliSpot 热点；其定位不是替代性发行版，而是让人零风险评估后迈出安装完整 BSD 发行版的第一步；开发过程得益于 FreeSBIE 项目——对方不仅提供 IRC 帮助还主动种子其 ISO；后续计划包括类似 OpenBSD 安装器的全自动引导、面向 Soekris 与 WRAP 单板机及 CF 转 IDE 旧 PC 的固件镜像。（BSDTalk EP73，[90.92-230.14]，L1）
- ChilliSpot 生态与本地部署实况：ChilliSpot 本是 Linux 阵营的 Wi-Fi 热点管理工具，以强制门户配合 radius 认证，可经 PHP My Prepaid 类工具实现付费热点，典型场景为酒店与咖啡店；布莱顿组织 Peer2Peer 以之支撑覆盖全市及夏季音乐节的免费无线网络；当地已知的主要部署 KZPR 已从 PC 方案转向在 WRT54G 路由器上运行 ChilliSpot 的嵌入式路线；当事人另与科威特用户合作排查三台大服务器高并发下 ChilliSpot 反复崩溃的问题，彼时社区尚缺大规模部署反馈。（BSDTalk EP73，[104.24-166.26]，L1）
- 跨 BSD 移植的协作细节：ChilliSpot 由前人完成从 Linux 到 FreeBSD 的移植后，当事人完成 OpenBSD 初始补丁、约一个月后另一社区成员补齐缺失部分，NetBSD 亦理论上可用；补丁除 tun 接口一处外并不侵入；但上游主开发者一度失联约四个月，补丁合并进下个版本的时间悬而未决；NetBSD 4.0 将 freeradius 收入 ports 树，改善了 radius 配套的可得性。（BSDTalk EP73，[321.30-408.38]，L1）
- 当事人的 BSD 结缘与使用图景：Slashdot 上一条 FreeBSD 5 发布消息促成其在 Alpha 机上从号称针对 Alpha 优化的 Red Hat 7.2 转投 FreeBSD 5，体验反差巨大，handbook 文档直白顺畅，与此前 Linux 发行版笨拙且文档匮乏的印象形成对照；此后按场景分派——办公环境中安全、邮件与 DNS 用 OpenBSD，web 服务器用 FreeBSD，主力桌面为 PowerBook G4 上的 OS X；键盘导向的 Ion 窗口管理器、研习 vi，又因入手 IBM Workpad 掌上设备转向 NetBSD。（BSDTalk EP73，[516.06-594.42]，L1）
- 2006 年 BSD 无线硬件的实战经验：服务器端 Raylink 系列卡开箱即用但天线功率偏弱，客户端 Cisco Aironet 350 凭 100 mW 天线带来显著覆盖优势却价格高昂；Brighton Chilli 当时不支持 Atheros 芯片卡，仅覆盖部分支持 HostAP 模式的卡，全自动化安装被列于后续版本。（BSDTalk EP73，[478.30-516.06]，L1）
- OpenBSD spamd 的跨阵营实战证词：当事人服务的客户以 Red Hat 承载高流量邮件，在以 spamd 前置该服务器后，垃圾邮件处理难题大体消解，邮件流程被彻底改观——OpenBSD 3.x 时期诞生的反垃圾工具在 Linux 生产环境中直接发挥效用，是其最愿向 BSD 开发者致谢的功能。（BSDTalk EP73，[737.40-776.90]，L1）
