# 199.1 OpenBSD 5.8-5.9 的 pledge 雏形（2015-2016）——5.8 开发周期引入 tame(2) 子系统，2015-10-09 重命名为 pledge(2)，5.8 中禁用，5.9 正式启用

## 198.1.1 **pledge(2)** 的设计与实现

**要点**：**pledge(2)** 的前身是 tame(2) 子系统，由 de Raadt 于 2015-07-19 commit `586b470f3a48` 引入（"tame(2) is a subsystem which restricts programs into a ‘reduced feature operating model’"）；2015-10-09 de Raadt commit `350b464c5787` 将 tame() 重命名为 pledge()（"Rename tame() to pledge(). This fairly interface has evolved to be more strict than anticipated"）；pledge 在 OpenBSD 5.8（2015-10-29 发布）中存在但被禁用——2015-10-12 schwarze commit `cfe38e1d85ad` 明确记载"pledge wasn't called pledge in 5.8, and it was disabled"；pledge 在 OpenBSD 5.9（2016-03-29 发布）中正式启用；pledge 让进程自愿放弃特定权限（如网络、文件系统访问），进程在程序启动时调用 `pledge("stdio rpath", NULL)` 即可限制权限

  **pledge/tame 演进关键 commit 时间线**：

  | 日期 | commit hash | 作者 | 说明 |
  | --- | --- | --- | --- |
  | 2015-07-19 | `586b470f3a48` | deraadt | tame(2) 引入——restricts programs into a ‘reduced feature operating model’ |
  | 2015-10-09 | `350b464c5787` | deraadt | 将 tame() 重命名为 pledge() |
  | 2015-10-12 | `cfe38e1d85ad` | schwarze | 明确 pledge 在 5.8 中被禁用 |
  | 2016-03-29 | — | OpenBSD | 5.9 正式启用 pledge(2) |

**史料**：bsd_commits.db openbsd-src 仓库 commit `586b470f3a48`（2015-07-19 deraadt "tame(2) is a subsystem..."）、commit `350b464c5787`（2015-10-09 deraadt "Rename tame() to pledge()"）、commit `cfe38e1d85ad`（2015-10-12 schwarze"pledge wasn't called pledge in 5.8, and it was disabled"）；OpenBSD 5.9 Release Notes pledge 部分；**pledge(2)** 手册页（<https://man.openbsd.org/pledge.2>）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 17 条——软件工程：pledge 是“最小权限”原则的系统调用化实现——进程自愿声明所需权限子集，内核据此拒绝越权系统调用，这一设计将安全约束从外部沙箱转移至程序自身声明，是软件工程中“白名单优先于黑名单”原则在操作系统接口层的实践

**辨析**：[2026-08-15 邮件列表库验证通过]：2015-10 openbsd-tech/openbsd-bugs 多条邮件确认 pledge 在 2015 年 10 月已进入广泛测试阶段（2015-10-30 "syscall 96 in top(1) on renice"、2015-10-31 "pledge(2) and pselect(2)"、2015-10-09 Kevin Reay 提及"new pledge syscall"），与 5.8 开发周期时间线一致；pledge 的引入版本在不同叙事中存在分歧——部分资料称 5.9 正式引入，部分称 5.8 已有雏形；经 bsd_commits.db 核查，tame() 于 2015-07-19 引入（5.8 开发周期），2015-10-09 重命名为 pledge()，但在 5.8 中被禁用（schwarze commit cfe38e1d85ad 明确记载），5.9 正式启用；原大纲称“5.4 引入 pledge 雏形”系误记——5.4（2014）时 tame/pledge 均不存在，tame 的最早 commit 为 2015-07-19

**文献**：bsd_commits.db openbsd-src 仓库 commit 586b470f3a48、350b464c5787、cfe38e1d85ad；OpenBSD 5.9 Release Notes [EB/OL]. <https://www.openbsd.org/59.html>；**pledge(2)** 手册页 [EB/OL]. <https://man.openbsd.org/pledge.2> ［A］

## 198.1.2 pledge 的工程哲学

**要点**：pledge 的设计哲学是“让程序员轻松做正确的事”——程序自愿声明权限而非被动接受沙箱，声明接口简洁（`pledge("stdio rpath", NULL)` 一行即可），避免 Linux seccomp 的复杂 BPF 过滤器；de Raadt 在 tech@ 邮件列表中主张 pledge 应简化至程序员愿意主动使用的程度；pledge 最初用于 OpenBSD 自带的用户态工具（如 **tcpdump(1)**、**nc(1)**），后续扩展至更多基本系统程序

**史料**：de Raadt 在 tech@ 关于 pledge 哲学的发言（<https://marc.info/?laccopenbsd-tech>）；OpenBSD pledge 设计文档；**pledge(2)** 手册页 DESIGN 部分（<https://man.openbsd.org/pledge.2>）；bsd_commits.db openbsd-src 仓库 pledge 相关 commit（2015-10-09 起 deraadt、semarie、benno 等的 commit）〔L1 代码/构建产物/L2 即时通讯记录/L3 官方文档与公告〕

**史观**：总纲第 17 条——软件工程：pledge 的设计哲学是 OpenBSD 对软件工程的独特理解——安全机制的可采用性取决于接口简洁度，复杂的沙箱接口（如 seccomp BPF）因使用门槛高而采用率低，pledge 以“一行声明”降低采用门槛，使安全约束成为程序员的主动选择而非被动负担

**辨析**：pledge 与 seccomp 的工程哲学比较——两者设计目标不同，seccomp 以 BPF 过滤器提供细粒度系统调用控制但配置复杂，pledge 以预定义权限类别提供粗粒度控制但配置简洁；pledge 的“自愿”特性是否导致使用率不足——OpenBSD 基本系统中 pledge 覆盖率以 Release Notes 与 commit log 中 pledge 相关 commit 计数为准，基本系统主要用户态工具已普遍采用 pledge

**文献**：de Raadt 邮件列表发言 [EB/OL]. <https://marc.info/?laccopenbsd-tech>；OpenBSD **pledge(2)** 手册页 [EB/OL]. <https://man.openbsd.org/pledge.2>；Linux seccomp 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html> ［A］

## 198.1.3 与 Linux seccomp/Capsicum 的比较

**要点**：Linux seccomp 使用 BPF 过滤器限制系统调用，灵活但复杂；FreeBSD Capsicum 提供能力模式与沙箱，设计精巧但采用率低；OpenBSD pledge 简洁但功能受限——三者设计哲学各自合理，pledge 以极简声明降低采用门槛，seccomp 以 BPF 灵活覆盖细粒度场景，Capsicum 以能力句柄提供细粒度资源控制

  **pledge/seccomp/Capsicum 三大沙箱机制对比**：

  | 机制 | 项目 | 接口形式 | 粒度 | 采用门槛 | 运行时开销 |
  | --- | --- | --- | --- | --- | --- |
  | pledge | OpenBSD | 声明式（`pledge("stdio rpath", NULL)`） | 粗粒度（系统调用类别） | 最低（一行声明） | 最低（系统调用入口检查） |
  | seccomp | Linux | BPF 过滤器 | 细粒度（单系统调用 + 参数） | 最高（BPF 配置） | 中（BPF 过滤器执行） |
  | Capsicum | FreeBSD | 能力句柄（`cap_rights_init()`） | 细粒度（资源 fd） | 中（多步调用） | 最高（能力句柄管理） |

**史料**：Linux seccomp 文档（<https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html>）；FreeBSD Capsicum 设计文档（<https://www.freebsd.org/cgi/man.cgi?query=capsicum>）；OpenBSD **pledge(2)** 手册页（<https://man.openbsd.org/pledge.2>）〔L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：三个项目选择不同的权限限制机制是各自对“安全与易用性权衡”的不同政治回应——OpenBSD 以“可采用性优先”为预设选择 pledge，Linux 以“灵活性优先”为预设选择 seccomp，FreeBSD 以“细粒度控制优先”为预设选择 Capsicum

**辨析**：三者的性能对比以同硬件同负载的 Phoronix 等基准测试为准——pledge 的运行时开销最低（仅系统调用入口检查），seccomp 次之（BPF 过滤器执行），Capsicum 最高（能力句柄管理）；Capsicum 在 FreeBSD 中的实际采用率以 FreeBSD 源码树中 cap_enter() 与 cap_rights_init() 的调用计数为准——Capsicum 主要被用于 FreeBSD 基本系统的少数服务（如 dhclient、casperd），采用率低于 pledge 在 OpenBSD 中的覆盖

**文献**：Linux seccomp 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html>；FreeBSD Capsicum 文档 [EB/OL]. <https://www.freebsd.org/cgi/man.cgi?query=capsicum>；OpenBSD **pledge(2)** 手册页 [EB/OL]. <https://man.openbsd.org/pledge.2> ［A］

## 198.1.4 pledge commit 记录与文档考据

**要点**：pledge 的 CVS commit log 与 **pledge(2)** 手册页历次版本是研究 pledge 演进的核心史料；openbsd.db openbsd-src 仓库中 pledge 相关 commit 自 2015-10-09 起（deraadt"Rename tame() to pledge()"），后续 semarie、benno、millert 等 committer 持续扩展 pledge 覆盖范围；pledge 的功能扩展过程以 commit log 中 message_subject 含"pledge"关键字的 commit 为索引；统计结论印证——openbsd.db openbsd-src 仓库总 commit 数 245,904（统计结论 C-05），6.x 时期（2015-2020）commit 量处于 fork 后的中后期阶段；openbsd.db openbsd-src 仓库 Mann-Kendall 趋势检验（统计结论 C-10）显示 1993-2026 年月度 commit 量呈下降趋势 slope = −0.24/月 p = 0.0358 95% CI [−0.46, −0.016]，反映 OpenBSD 在 6.x 时期从 fork 后的工程节奏继续向稳态收敛——pledge/unveil 等安全机制的引入作为离散工程事件叠加于下降趋势之上

**史料**：openbsd.db openbsd-src 仓库 pledge 相关 commit（2015-10-09 起 deraadt、semarie、benno、millert 等）；**pledge(2)** 手册页历次版本（<https://man.openbsd.org/pledge.2>）；tech@ 邮件列表 pledge 讨论（<https://marc.info/?laccopenbsd-tech>）；openbsd.db 查询 L1.1.1（经 L1.1.2 交叉验证）显示 openbsd-src 仓库 2015-2019 年逐年 commit 量与占 4 大 BSD src 合计百分比数据未在报告前 30 行中显示（L1.1.2 查询结果共 124 行，报告仅显示前 30 行覆盖 1995-2002 年），须以数据库直接查询补全；openbsd.db openbsd-src 仓库 ARIMA 模型（统计结论 C-31：ARIMA(5,0,5) AIC = 176.47，Python statsmodels.tsa.arima.model.ARIMA 实现，查询日期 2026-07-27）；openbsd.db openbsd-src 仓库预测精度指标（统计结论 C-35：MAPE = 45.21% RMSE = 187.96 coverage = 84.21%，Python 自实现 MAPE/RMSE 计算，查询日期 2026-07-27） ［A］

**史观**：总纲第 25 条——0 信任原则：pledge 考据是 0 信任原则在安全机制史研究中的实践——commit log 中的 pledge 相关 commit 须以 message_subject 与 file_path（lib/libc/sys/pledge.2、regress/sys/kern/pledge/）交叉筛选方可定位，仅凭 message_subject 关键字可能遗漏未标注"pledge"但实际扩展 pledge 覆盖的 commit；统计结论印证——C-31 ARIMA(5,0,5) 模型以工程节奏的统计刻画印证“分离聚合是永恒规律”（总纲第 4 条），6.x 时期 pledge/unveil 的离散工程事件叠加于 ARIMA 刻画的趋势分量之上；C-35 MAPE = 45.21% 反映“实践先于理论”（总纲第 2 条）的统计显现——ARIMA 模型对 OpenBSD commit 量的预测能力有限，说明 pledge/unveil 等离散事件对开发节奏的扰动难以被线性模型完全捕捉

**辨析**：pledge 演进的具体里程碑以 Release Notes 与 commit log 交叉验证为准——Release Notes 记录用户可见的 pledge 覆盖扩展，commit log 记录具体代码变更；commit log 中的 pledge 相关 commit 以 file_path 含"pledge"或 message_subject 含"pledge"为筛选条件，bsd_commits.db commit_files 表中 lib/libc/sys/pledge.2 与 regress/sys/kern/pledge/ 路径下的 commit 为权威索引；bsd_commits.db 查询 L1.1.1 局限：L1.1.1 报告仅显示 23 仓库 572 行结果中的前 30 行（全为 dragonfly 仓库），openbsd-src 逐年数据须经 L1.1.2 查询交叉验证获取，但 L1.1.2 报告亦仅显示 124 行中的前 30 行（覆盖 1995-2002 年），2015-2019 年 openbsd-src 份额数据须以数据库直接查询补全；openbsd-src 为 GitHub 镜像，commit 量可能滞后于 OpenBSD CVS 主仓；commit 量反映开发活跃度但不等于代码质量；bsd_commits.db 查询 L2.3.1.pledge 与 L2.3.1.unveil 在中观模式挖掘报告中均不存在（报告仅含 L2.3.1.ZFS、L2.3.1.Capsicum、L2.3.1.bhyve、L2.3.1.Clang、L2.3.1.ARM64、L2.3.1.RISC-V 等 FreeBSD 特性查询，未覆盖 OpenBSD pledge/unveil 子系统），pledge/unveil 相关子系统级 commit 数据须以 bsd_commits.db 直接查询 file_path 维度（如 lib/libc/sys/pledge.2、lib/libc/sys/unveil.2、regress/sys/kern/pledge/、regress/sys/kern/unveil/）补全；**统计局限性标注**——C-35 MAPE = 45.21% 高于行业基准（通常 < 30%），coverage = 84.21% 低于其余 3 BSD src 仓库（freebsd-src 94.74%、netbsd-src 94.74%、dragonfly-src 89.47%），反映 openbsd-src 月度 commit 量波动较大，ARIMA 模型预测能力有限，6.x 时期 pledge/unveil 等离散工程事件作为结构性冲击构成 ARIMA 模型未捕捉的异方差性来源；C-31 ARIMA(5,0,5) 的 AIC = 176.47 在 4 BSD src 仓库中居中（freebsd-src 107.39、netbsd-src −79.34、dragonfly-src 233.80），AIC 仅用于同序列内模型比较，不得跨仓库直接比较模型优劣；0 信任原则适用：统计显著 ≠ 实际显著，Mann-Kendall 趋势（C-10）与 ARIMA 模型（C-31）均刻画 openbsd-src 下降趋势，但二者基于不同统计假设，趋势方向一致性不构成模型验证，仅反映数据生成过程的稳健性
