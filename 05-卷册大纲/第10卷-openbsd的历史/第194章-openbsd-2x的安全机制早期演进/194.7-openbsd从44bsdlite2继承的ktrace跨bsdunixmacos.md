# 194.7 OpenBSD 从 4.4BSD-Lite2 继承的 ktrace（跨 BSD/UNIX/macOS 扩展）

## 194.7.1 ktrace 的继承与 systrace 协同

**要点**：OpenBSD 自 fork 自 NetBSD 1.0（**1996 年 10 月**）起继承 ktrace 子系统，提供 **ktrace(1)** 命令与 **ktrace(2)** 系统调用——其实现路径与 NetBSD ktrace 在 fork 时刻同源，但 OpenBSD 在 2.x 时期（1996-2002）对其进行了安全审计与代码清理。man page 见 **man.openbsd.org/ktrace.1**。OpenBSD ktrace 的关键演化是在 3.0（2001）引入 systrace 时与之协同——systrace 提供系统调用拦截与策略决策，ktrace 提供系统调用记录，二者构成 OpenBSD 系统调用观测的完整工具链。

**史料**：OpenBSD 2.0 Release Notes（**1996-10-18**）；**ktrace(1)** man page（man.openbsd.org/ktrace.1）；OpenBSD src 仓库 **sys/kern/kern_ktrace.c** 源码；Provos, N. (2002). *Improving Host Security with System Call Policies*. USENIX Security 2002——systrace 设计论文。〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 1 条——源头时刻：OpenBSD fork 时“冻结”了 ktrace 的 NetBSD 实现，此即 fork 时刻的“源头定格”；总纲第 2 条——分离与聚合：OpenBSD 从 NetBSD 分离时聚合了 ktrace 子系统，是分离时刻的聚合事件；总纲第 6 条——技术选择的代价：OpenBSD 选择保留 ktrace 并引入 systrace 协同，付出维护两套观测机制的代价，但获得审计与策略决策的双重能力；总纲第 10 条——边缘者贡献：ktrace 的最初设计者姓名被遮蔽，systrace 的设计者 Niels Provos（尼尔斯·普罗沃斯） 在 OpenBSD 社区获得署名；总纲第 17 条——形式与内容：ktrace 与 systrace 共同构成“形式”（观测+策略），覆盖了系统调用的“内容”（行为）；自反性声明：本释读不预设“OpenBSD 中心论”——ktrace 在 NetBSD、FreeBSD、DragonFly BSD 均有保留，systrace 是 OpenBSD 独有扩展。

**辨析**：OpenBSD ktrace 与 NetBSD ktrace 在 fork 时刻同源，分叉发生在 OpenBSD 3.0（2001）引入 systrace 后；systrace 在 OpenBSD 5.4（2013）后被弃用并移除，ktrace 保留至今。与 Linux strace 无代码共享。

**文献**：OpenBSD Project. *OpenBSD 2.0 Release Notes*[EB/OL]. (1996-10-18). <https://www.openbsd.org/>; OpenBSD Project. *ktrace(1) Manual Page*[EB/OL]. <https://man.openbsd.org/ktrace.1>; Provos, N. (2002). *Improving Host Security with System Call Policies*. USENIX Security 2002.
