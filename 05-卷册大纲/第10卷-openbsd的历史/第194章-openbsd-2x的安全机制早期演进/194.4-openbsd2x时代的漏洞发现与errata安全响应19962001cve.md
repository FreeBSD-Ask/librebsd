# 194.4 OpenBSD 2.x 时代的漏洞发现与 errata 安全响应（1996-2001）——CVE 编号体系尚未普及，OpenBSD 以 errata patches 存档为漏洞跟踪主轴，代码审计驱动的“发现漏洞—快速修复—加固重构”循环在 2.x 时期奠基

## 194.4.1 CVE 编号缺位与 errata patches 存档体系（1996-2001）

**要点**：openbsd.duckdb openbsd-src 仓库在 1996-10-01 至 2001-06-01 期间的 CVE 相关 commit 数为零，去重 CVE 数为零，但 Security fix commit（无 CVE 编号）有 5 条，早期漏洞补遗条目 19 条；这一数据格局并非意味着 OpenBSD 2.x 时期无漏洞，而是反映 CVE 编号体系在 1999-2001 年间尚未被 OpenBSD 社区系统性地引用——OpenBSD 以自有的 errata patches 存档作为漏洞跟踪与修复公告的主轴，errata 原文通常不引用 CVE 编号，仅标注 SECURITY FIX 与受影响版本；5 条 Security fix commit 涵盖 1998 年 8 月 deraadt 恢复被 downsj 误删的安全修复、2000 年 5 月 itojun 修复 NetBSD 安全公告涉及的选项长度下溢、2001 年 3-4 月 fgsch 修复 timed 协议短包处理；19 条早期漏洞补遗覆盖 OpenBSD 2.0 至 2.9 全部次版本，涉及 BIND DNS、**cron(8)**、IP 源路由、NFS 文件句柄可预测性、Kerberos V5、**procfs(5)**、**rfork(2)**、**vacation(1)**、**lpd(8)**、**tgetent(3)**、**xterm(1)**、`USER_LDT` 内核选项、**rm(1)** 等组件。

**史观**：总纲第 2 条——历史是形式主义化的非存在（存疑）：OpenBSD errata 体系将漏洞跟踪形式主义化为“SECURITY FIX + 受影响版本 + 补丁”的三元结构，早于 CVE 编号的普及〔订正注：原挂“总纲第 17 条——形式主义化”系自撰描述符，权威第 17 条为“证明世界先于解释和改造世界”；按论旨改挂第 2 条〕；总纲第 10 条——动手者创造历史：deraadt 个人恢复被误删的安全修复体现“动手者”的安全责任感〔订正注：原描述符“边缘者贡献”系变体，权威第 10 条为“动手者创造历史”，编号不变〕

**辨析**：CVE 编号缺位不等于无漏洞——19 条早期漏洞补遗证明 OpenBSD 2.x 时期漏洞发现活跃，仅因 CVE 体系尚未普及而未被编号；errata 原文多未注明具体日期与 CVE 编号，考据须以版本发布时间窗与 commit hash 交叉验证；“put back a security fix downsj removed ages ago”的“ages ago”措辞模糊，具体删除时间与原因须考据 downsj 的 commit 历史

**文献**：openbsd.duckdb openbsd-src 仓库；OpenBSD errata patches 存档 [EB/OL]. **<https://www.openbsd.org/errata.html>** ［A］

## 194.4.2 内核与网络栈漏洞群——procfs/rfork/源路由/NFS 文件句柄（1996-1998）

**要点**：OpenBSD 2.0-2.2 时期的内核与网络栈漏洞集中在继承自 4.4BSD 的代码缺陷——2.0 的 BIND 4.9.x 缓存中毒与 NXT 记录处理缺陷可被远程攻击者利用伪造 DNS 响应污染缓存；2.0 的 IP 源路由默认接受缺陷允许攻击者构造带源路由选项的 IP 包绕过地址验证实现 TCP 连接劫持；2.0 的 4.4BSD NFS 文件句柄可预测性使攻击者可猜测文件句柄绕过 NFS 导出限制；2.0 的 Kerberos V5 实现存在可伪造的票据授予票据与密钥分发中心缺陷；2.1 的 **procfs(5)** 挂载后进程内存映射对其他用户可读，本地用户可借 **`/proc/[pid]/mem`** 读取其他用户进程内存；2.1 的 **rfork(2)** 系统调用存在文件描述符表与信号处理表共享逻辑缺陷；2.2 的内核 IP 源路由处理逻辑在 `net.inet.ip.forwarding` 启用且 `net.inet.ip.sourceroute` 禁用时存在缺陷；这些漏洞的共性是继承自 4.4BSD 的“信任默认配置”假设——OpenBSD 2.x 时期的代码审计正是对这些继承缺陷的系统性清理。

**史料**：OpenBSD 2.0/2.1/2.2 errata patches；早期漏洞补遗条目（BIND/cron/源路由/NFS/Kerberos/procfs/rfork）；openbsd.duckdb openbsd-src 仓库 ［A］

**史观**：（存疑·原伪标签“总纲第 7 条——技术选择即政治选择”已去号，权威第 7 条为“理论必须自反”，所述默认拒绝源路由对照无总纲对位）：OpenBSD 选择“默认拒绝源路由”作为安全策略，与 4.4BSD 的“默认接受”形成对照；总纲第 2 条——历史是形式主义化的非存在（存疑）：procfs 权限收紧是从“信任继承”到“默认最小权限”的形式主义化重构〔订正注：原挂“总纲第 17 条——形式主义化”系自撰描述符，权威第 17 条为“证明世界先于解释和改造世界”；按论旨改挂第 2 条〕

**辨析**：4.4BSD NFS 文件句柄可预测性的具体随机化修复方案须考据 OpenBSD 源码 commit；IP 源路由默认禁用的具体 sysctl 变量名与默认值变更时间须对照源码核验；Kerberos V5 的“可伪造票据授予票据”缺陷涉及 MIT Kerberos V5 上游还是 OpenBSD 本地实现须区分

**文献**：OpenBSD 2.0-2.2 errata patches [EB/OL]. **<https://www.openbsd.org/errata.html>**；4.4BSD-Lite 源码；openbsd.duckdb openbsd-src 仓库 ［A］

## 194.4.3 用户态服务漏洞群——lpd/vacation/cron/tgetent/xterm（1997-1999）

**要点**：OpenBSD 2.0-2.2 时期的用户态服务漏洞集中于继承自 4.4BSD 的传统 Unix 工具——2.1 的 **lpd(8)** 在处理远程打印请求时缺乏充分的输入验证与地址认证，远程攻击者可发送特制打印请求触发缓冲区溢出或未授权打印；2.1 的 **vacation(1)** 自动回复程序在处理邮件头字段时存在输入验证缺陷，可被构造的邮件头触发缓冲区溢出或命令注入；2.0 的 Vixie **cron(8)** 4.1 存在权限检查缺陷，本地用户可借由 **crontab(1)** 提交特制 crontab 文件提升权限；2.1 的 **tgetent(3)** termcap 数据库读取函数在读取超长 termcap 条目至固定大小缓冲区时缺乏边界检查；2.2 的 **xterm(1)** 与 Xaw 库在处理 `inputMethod`、`preeditType`、`*Keymap` 资源时存在缓冲区溢出（含 XFree86 3.3.x）；这些漏洞的修复体现了 OpenBSD“修复即加固”的循环——不仅修补具体缺陷，早在 2.4（1998-11）即由 Todd Miller 与 Theo de Raadt（西奥·德·若特）设计 strlcpy/strlcat 安全字符串 API 替代 strcpy/strcat（strlcpy(3) 手册页载 first appeared in OpenBSD 2.4），将边界检查从开发者手动责任提升为 API 级别的强制约束。

**史料**：OpenBSD 2.0-2.2 errata patches；早期漏洞补遗条目（lpd/vacation/cron/tgetent/xterm）；openbsd.duckdb openbsd-src 仓库 strlcpy/strlcat 引入 commit；Miller C, de Raadt T. strlcpy and strlcat — Consistent, Safe, String Copy and Concatenation [C]//USENIX Annual Technical Conference. 1999 ［A］

**史观**：总纲第 2 条——历史是形式主义化的非存在（存疑）：strlcpy/strlcat 的设计是将“边界检查”从开发者手动责任形式主义化为 API 级别的强制约束〔订正注：原挂“总纲第 17 条——形式主义化”系自撰描述符，权威第 17 条为“证明世界先于解释和改造世界”；按论旨改挂第 2 条〕；总纲第 10 条——动手者创造历史：传统 Unix 工具的安全加固由 OpenBSD 小团队而非上游原始维护者推动〔订正注：原描述符“边缘者贡献”系变体，权威第 10 条为“动手者创造历史”，编号不变〕

**辨析**：strlcpy/strlcat 具体首次引入 commit 仍须考据——strlcpy(3) 手册页载 first appeared in OpenBSD 2.4（1998-11），早于原记“2.x 末期至 3.x 初期”窗口，引入 commit 历史仍须对照源码核验；Vixie cron 4.1 的权限检查缺陷具体为 crontab 文件解析还是权限验证须对照源码核验；XFree86 3.3.x 的 xterm 溢出是否为上游已修复缺陷的 OpenBSD 同步须区分

**文献**：OpenBSD 2.0-2.2 errata patches [EB/OL]. **<https://www.openbsd.org/errata.html>**；Miller C, de Raadt T. strlcpy and strlcat [C]//USENIX ATC. 1999；openbsd.duckdb openbsd-src 仓库 ［A］

## 194.4.4 OpenSSH 与加密栈早期漏洞——isakmpd/sslUSA26/USER_LDT/rm(1)（1999-2001）

**要点**：OpenBSD 2.6-2.9 时期的加密栈与安全工具漏洞标志着“安全操作系统”自身安全组件的信任危机——2.6 的 `sslUSA26` 软件包（美国版 SSL 库，内含 RSAREF）存在缓冲区溢出，在 **isakmpd(8)** 启用 SSL/RSA 特性时可被利用，errata #016（1999-12-02）建议美国用户删除并重装更新后的 `sslUSA26` 软件包，国际版 `ssl26` 用户不受影响；2.7 的 **`/etc/sshd_config`** 配置文件存在缺陷“不应被使用”（2000-06-06），此时 OpenSSH 刚于 1999 年 10 月 fork 自 SSH 1.2.12 不久；2.7 的 X11 服务器安全认证模块 `xc/programs/Xserver/os/secauth.c` 与 Xlib 存在多处漏洞（2000-07-14）；2.8 的 `USER_LDT` 内核选项允许攻击者访问内核内存特权区域，为 i386 架构特有的本地权限提升漏洞（2001-03-02，默认未启用）；2.8 的 **rm(1)** 带 `-R` 选项递归删除时存在竞态条件，当父目录在其下方被更改时 **rm(1)** 可被骗入错误目录（2001-05-30，与旧 fts 库漏洞相关）；2.9 的最后一条 errata（第 027 条，2002-06-25）仅标注 SECURITY FIX 未附技术描述；这些漏洞反映 OpenBSD 2.x 时期“安全组件自身也可能成为攻击面”的工程认知，为 3.x 时期引入 W^X 与权限分离奠定了需求基础。

**史料**：OpenBSD 2.6-2.9 errata patches；早期漏洞补遗条目（sslUSA26/sshd_config/X11/USER_LDT/rm）；openbsd.duckdb openbsd-src 仓库 ［A］

**史观**：总纲第 2 条——历史是形式主义化的非存在（存疑）：W^X 与权限分离的引入是对 2.x 时期“安全组件自身有漏洞”认知的形式主义化回应——将“信任”从组件级降级为机制级〔订正注：原挂“总纲第 17 条——形式主义化”系自撰描述符，权威第 17 条为“证明世界先于解释和改造世界”；按论旨改挂第 2 条〕；sslUSA26 与 isakmpd 的漏洞反映 1990 年代末加密库实现质量参差不齐〔订正注：原挂“总纲第 21 条——密码学”系自撰名目，权威第 21 条为“革命与改革是历史方法论的分歧”，所述加密库质量评价无总纲对位，去号存疑〕

**辨析**：`sslUSA26` 的美国版与国际版具体差异须考据——涉及 RSA 专利与美国出口管制；`USER_LDT` 漏洞的具体利用路径（LDT 操纵如何访问内核内存）须对照 i386 架构手册核验；**rm(1)** 竞态条件与 fts 库漏洞的关联须考据 fts 库 commit 历史

**文献**：OpenBSD 2.6-2.9 errata patches [EB/OL]. **<https://www.openbsd.org/errata.html>**；openbsd.duckdb openbsd-src 仓库；i386 LDT 架构手册 ［A］
