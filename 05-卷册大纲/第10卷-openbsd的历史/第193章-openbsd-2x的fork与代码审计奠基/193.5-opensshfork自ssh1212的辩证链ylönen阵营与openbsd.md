## 193.5.1 批评——Ylönen 阵营对 OpenSSH fork 的立场

**要点**：Tatu Ylönen 于 1995 年发布 SSH 1.0 并持续投入数年开发，1999 年将 SSH 1.2.13+ 转为商业许可证（SSH Communications Security 公司运营）是维持开发的商业决策。从 Ylönen 阵营视角，OpenBSD fork SSH 1.2.12（“最后一个自由许可版本”）存在三重张力——（1）投资回报断裂：Ylönen 数年开发投入的商业回报因 OpenSSH 免费提供同等功能而被削弱，SSH Communications Security 的商业模式受到直接冲击，商业 SSH 逐步退出主流市场后转向企业级特权访问管理领域；（2）“最后自由版本”的漏洞利用叙事：OpenBSD 选择 1.2.12 作为 fork 起点并称其为“最后一个自由到足以复用的版本”（the last one free enough for reuse），Ylönen 阵营可论证此举利用了许可证变更的时间窗口——1.2.12 发布时 Ylönen 尚未决定商业化，fork 实质上以“早期版本的自由许可”对抗“后续版本的商业许可”；（3）“解放 SSH”叙事的道德定位问题：OpenSSH 官方历史以“freeing SSH”与“cleaning up the license mess”定位 fork 动机，将 Ylönen 的商业决策重构为“限制”，将 OpenBSD 的 fork 重构为“解放”，这一叙事框架将 Ylönen 定位为限制者而非创造者

## 193.5.2 反批评——OpenBSD 阵营的 fork 正当性论证

**要点**：OpenBSD 阵营的 fork 正当性论证沿四条线索展开——（1）许可证权利的合法行使：SSH 1.2.12 以自由许可发布，fork 是对自由许可权利的合法行使，Ylönen 在发布 1.2.12 时授予复用权，后续版本的商业许可不影响 1.2.12 的许可状态；（2）许可证递进限制的实证：OpenSSH 官方历史记载，1.2.12 之后的 SSH 版本“带有逐步更严格的许可证”（bore successively more restrictive licenses）——“第一个限制性许可证禁止制作 Windows 或 DOS 版本”（forbade people from making a Windows or DOS version），“后来的许可证限制了 ssh 在商业环境中的使用，要求公司向 Datafellows 购买昂贵版本”（restricted the use of ssh in a commercial environment, instead requiring companies to buy an expensive version from a company called Datafellows）——许可证递进限制使 SSH 的自由使用范围逐步收窄；（3）GPL 违规的技术困境：OpenSSH 官方历史记载，1.2.12 之后的版本仍包含 libgmp（GPL 许可），但商业许可证与 GPL 不兼容，“这实际上使 SSH 成为 GPL 违规”（That effectively made SSH a GPL violation）——OpenBSD 阵营可论证 Ylönen 的商业许可变更不仅在道德上“限制自由”，在法律上亦与 GPL 组件产生冲突；（4）社区需求驱动：OpenBSD 需要在 2.6 发行版中集成 SSH，但商业许可使集成不可能，fork 是满足社区对自由 SSH 实现的需求的必要路径

**史料**：OpenSSH 项目历史页面（<https://www.openssh.com/history.html>，记载“bore successively more restrictive licenses”、“forbade people from making a Windows or DOS version”、“restricted the use of ssh in a commercial environment”、“That effectively made SSH a GPL violation”）；OpenSSH LICENCE 文件（<https://cvsweb.openbsd.org/src/usr.bin/ssh/LICENCE>，记载各组件许可证组合）；openbsd.duckdb openbsd-src 仓库 commit 84959968510b（1999-09-26 deraadt 初始导入）、commit bf74e864c129（1999-10-01 deraadt“OpenSSH-1.0”）；参见 OpenSSH 专章诞生与许可证纯洁化记录 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配（原“法律结构”挂第 12 条系错配，按许可证利益论旨改挂）：OpenBSD 阵营的 fork 正当性基于法律结构——SSH 1.2.12 的自由许可授予复用权，后续版本的商业许可不影响已发布版本的许可状态；总纲第 4 条——分离聚合是永恒规律（原“分离与聚合”挂第 2 条系编号错挂，正名）：OpenSSH 从 SSH Communications Security 的闭源实现分离后聚合入 OpenBSD 源码树，分离以法律结构（自由许可）为基础

## 193.5.3 再回应——批评方对 OpenBSD 反批评的再回应与许可证纯洁化争议深化

**要点**：针对 OpenBSD 阵营在 193.5.2 节提出的四条反批评论证（许可证权利合法行使、许可证递进限制实证、GPL 违规技术困境、社区需求驱动），批评方（Ylönen 阵营及其同情者）的再回应沿三条线索展开，并与许可证纯洁化争议深化交织——（0）再回应总纲：Ylönen 阵营可论证 OpenBSD 阵营的四条反批评均以“自由许可”为单一预设，但 SSH 1.2.12 的自由许可是 Ylönen 在 1995 年尚未决定商业化时的临时状态，而非 Ylönen 对“软件自由”价值观的承诺——以“自由许可”对抗“商业许可”是将作者的“未决状态”重构为“价值观承诺”，这一重构使 OpenBSD 阵营占据道德高地的论证基础本身值得审视；Ylönen 阵营亦可再回应“GPL 违规”论点——GPL 违规的判定权在 GPL 许可证持有者（FSF 与 libgmp 作者 T. Granlund）而非 OpenBSD 阵营，OpenBSD 阵营以“GPL violation”论证 fork 正当性存在法律越位风险，且“移除 GPL 组件”与“指控 Ylönen 的 SSH 1.2.13+ 为 GPL 违规”是两个不同层面，前者是技术必要、后者是法律判断，两者不得混淆；OpenSSH fork 后的“许可证纯洁化”（license purification）工作——de Raadt 移除非可移植代码、Provos 赴加拿大移除加密与 GPL 组件（libgmp）、Friedl 替换 SSH 1.3 协议为 1.5、Beck 处理 Makefile 避开 RSA 专利——在再回应层引发三重争议——（1）“纯洁化”叙事的道德预判：“cleaning up the license mess”（清理许可证混乱）与“purification”（纯洁化）措辞隐含道德预判——将 Ylönen 的 SSH 1.2.12 定位为“混乱”（mess）与“不纯”（impure），将 OpenBSD 的工作定位为“清理”（cleaning up）与“纯洁化”（purification），这一叙事框架使 Ylönen 的原创贡献在“纯洁化”过程中被重构为“需要被清理的遗留物”；但 SSH 1.2.12 是 Ylönen 的原创作品，其许可证组合（Ylönen 自有许可 + GPL'd libgmp）是当时的合法状态，“混乱”是 OpenBSD 阵营的事后定性而非客观事实；（2）GPL 组件移除的动机辨析：Provos 移除 libgmp（GPL 组件）被叙述为“纯洁化”，但移除 GPL 组件的动机可能混合了法律约束（美国密码出口管制要求 Provos 赴加拿大工作）与许可证意识形态（使 OpenSSH 可在 BSD 许可下发布，避免 GPL 传染）——若动机主要是法律约束，则“纯洁化”是法律驱动的技术必要；若动机主要是许可证意识形态，则“纯洁化”是 BSD 阵营对 GPL 的意识形态排斥；两类动机须经 Provos 赴加拿大的具体工作记录与 OpenBSD misc@ 邮件列表讨论交叉验证；（3）“纯洁化”与文化挪用的类比：OpenSSH 的“纯洁化”叙事与“重写即归属”模式（参见相关章节）存在结构相似性——OpenBSD 重写 SSH 1.2.12 的 GPL 组件与非可移植代码后，OpenSSH 以“纯洁化版本”自我定位，Ylönen 的原创贡献在“纯洁化”叙事中被弱化为“需要被清理的起点”，这一弱化与文化挪用中“重写即归属”的结构相似但非同一——OpenSSH 官方历史确实承认"OpenSSH is a derivative of the original free ssh 1.2.12 release from Tatu Ylönen“与”Parts of OpenSSH still bear Tatu's license"，归属承认的存在使“纯洁化”不同于完全的文化挪用

## 193.5.4 合图——OpenSSH fork 的辩证综合

**要点**：合图层综合 Ylönen 阵营与 OpenBSD 阵营的论点，指出二者非对立而是互补——（1）双方权利的对称合法性：Ylönen 将 SSH 1.2.13+ 转为商业许可是对其软件的商业决策权行使，OpenBSD fork SSH 1.2.12 是对自由许可权利的合法行使——两方在法律层面均正当，“商业可持续性”与“软件自由”是两种合法但不同的价值观；（2）贡献的互补性：Ylönen 的数年开发创造了 SSH 的技术基础（协议设计、核心实现、安全架构），OpenBSD 团队的审计与纯洁化创造了 OpenSSH 的安全标准（代码审计、许可证合规、privilege separation 架构）——OpenSSH 成为全球标准是双方贡献叠加的结果而非单方成就，Ylönen 的原创与 OpenBSD 的审计缺一不可；（3）“纯洁化”叙事的辩证定位：合图层不否定“纯洁化”工作的技术价值（移除非可移植代码确实提升可审计性、移除 GPL 组件确实使 OpenSSH 可在 BSD 许可下发布），但指出“纯洁化”叙事的道德预判须经 Ylönen 阵营的对称呈现后方可评估——“纯洁化”是法律与技术层面的正当工作，但“纯洁化”叙事在道德层面不应将 Ylönen 定位为“限制者”而将 OpenBSD 定位为“解放者”，双方均为各自价值观的合法行使者；（4）合图不追求“消除分歧”：Ylönen 阵营与 OpenBSD 阵营的前理解差异（总纲第 19 条）使分歧不可避免——Ylönen 阵营以“商业可持续性”为预设，OpenBSD 阵营以“软件自由”为预设，两套预设基于不同价值观，合图不是“消除分歧”而是“在分歧中呈现各主体性”

**史料**：OpenSSH 项目历史页面（记载"derivative of the original free ssh 1.2.12 release from Tatu Ylönen“与”Parts of OpenSSH still bear Tatu's license"——归属承认的存在）；参见 OpenSSH 专章诞生、纯洁化、全球部署与比较记录；SSH Communications Security 商业产品页面（<https://www.ssh.com/>）；参见“结构与偶然的合图”方法论相关章节 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：OpenSSH 从 SSH Communications Security 的商业实现分离后聚合入 OpenBSD 源码树，再从 OpenBSD 聚合入 FreeBSD、NetBSD 与各 Linux 发行版——分离以法律结构（自由许可）为基础，聚合以 BSD 许可证为法律基础；总纲第 19 条——解释学循环是历史认识的根本条件：合图层承认 Ylönen 阵营与 OpenBSD 阵营的前理解差异使 fork 争议的分歧不可避免，合图不是“消除分歧”而是“在分歧中呈现各主体性”——“权力与知识在历史书写中共谋”：什么被记录为“解放 SSH”、什么被记录为“fork SSH”，本身就是权力行使；总纲第 21 条——革命与改革是历史方法论的分歧：Ylönen 的商业化是“革命”（以新许可证模型替换自由许可），OpenBSD 的 fork 是“改革”（在 SSH 1.2.12 基础上渐进审计与纯洁化而非从零重写）——“改革的困难远高于革命”，OpenBSD 的渐进审计与纯洁化比 Ylönen 的许可证革命更具工程复杂度

## 193.5.5 项目统摄史观审视——从总纲第 13、19、21 条审视 fork 争议

**要点**：本子节从项目史观总纲第 13 条（法律与道德是利益分配）、第 19 条（解释学循环与权力知识共谋）、第 21 条（革命与改革）切入，对 193.5.1-193.5.4 的四层辩证链进行哲学审视，作为 3.5 节的哲学收尾——（1）总纲第 13 条审视：fork 争议表面上是“软件自由 vs 商业可持续性”的道德论辩，本质上是三方利益分配的政治产物——Ylönen 阵营的商业利益（SSH Communications Security 的商业模式依赖 SSH 许可证商业化）、OpenBSD 阵营的工程利益（OpenBSD 2.6 发行版需集成 SSH 以提升安全工程完整性）、第三方采用者的免费获取利益（FreeBSD、NetBSD、Linux 各发行版、Cisco、Apple、IBM 等从 BSD 许可证免费获取 SSH 实现且不要求回馈）均以道德话语为形式主义包装，三种道德话语均是利益分配的形式主义政治产物；合图层所指“双方权利对称合法性”在利益分配审视下呈现为“三方利益不对称”——OpenBSD 项目承担 OpenSSH 维护成本而商业公司“搭便车”，这一利益不对称是 BSD 许可证的结构性后果而非任何一方的道德过错；（2）总纲第 19 条审视：Ylönen 阵营与 OpenBSD 阵营的前理解差异——前者以“商业可持续性”为预设，后者以“软件自由”为预设——使 fork 争议的分歧不可避免；OpenSSH 官方历史以“freeing SSH”与“cleaning up the license mess”定位 fork 动机，将 Ylönen 的商业决策重构为“限制”，将 OpenBSD 的 fork 重构为“解放”，这一“什么被记录为解放、什么被记录为限制”的分配本身就是权力与知识在历史书写中的共谋；本子节不追求“消除共谋”而是“暴露共谋”——暴露本身亦是一种循环，与古代史中“史家重写”无本质区别（总纲第 1 条：一切真历史都是古代史）；（3）总纲第 21 条审视：Ylönen 的商业化是“革命”（以新许可证模型替换自由许可，SSH 1.2.13+ 用户被迫接受商业许可或停止升级），OpenBSD 的 fork 与纯洁化是“改革”（在 SSH 1.2.12 基础上渐进审计与纯洁化而非从零重写，保留 SSH 1.2.12 的代码骨架与协议实现）——“改革的困难远高于革命”，Provos 须赴加拿大移除加密与 GPL 组件以规避美国出口管制、Friedl 须替换 SSH 1.3 协议为 1.5 以避开专利约束、Beck 须处理 Makefile 以避开 RSA 专利，这一“心中贼”远比 Ylönen 的“山中贼”（自由许可）难以“破除”；但“破除”本身非目的，在保留技术传统的同时实现许可证合规才是 OpenBSD 改革的哲学；两种方法论各有代价——Ylönen 的革命为 SSH 持续开发提供了商业回报但强迫用户接受商业许可，OpenBSD 的改革保留了自由许可但 OpenBSD 项目从 OpenSSH 获得的商业回报有限；本子节为 193.13 节详细哲学审视提供简短收尾，不重复 193.13 节的展开
