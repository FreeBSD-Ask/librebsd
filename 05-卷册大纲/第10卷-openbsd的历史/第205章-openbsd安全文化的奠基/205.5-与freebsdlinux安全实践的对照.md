# 205.5 与 FreeBSD/Linux 安全实践的对照

**要点**：FreeBSD 1990 年代后期建立 Security Officer 制度（如 Warner Losh（沃纳·洛什）、Kris Kennaway 等任职）但未系统性代码审计，安全修复以反应式（收到报告后修复）为主；Linux 1990 年代缺乏系统性审计，依赖用户与厂商报告，1999 年 Linux Security Audit Project 由 Daniel Stone 等发起但规模有限；OpenBSD 是 1990 年代唯一系统性代码审计的 Unix 系统；三者安全实践的差异具体表现为——OpenBSD 主动逐行审计基本系统，FreeBSD 依赖 Security Officer 制度处理报告，Linux 依赖各发行版与内核维护者各自为政

**史料**：FreeBSD Security Advisories 1996-2000（<https://www.freebsd.org/security/advisories/>）；Linux Security Audit 项目文档（<https://www.linux.org.au/lsec/>）；OpenBSD Security Advisories 1996-2000（<https://www.openbsd.org/security.html>）；cross-BSD 安全协调邮件列表

**史观**：总纲第 8 条——社区文化即技术资产：OpenBSD 的 “审计文化” 与 FreeBSD/Linux 的 “反应式安全” 是两种不同的文化资产——前者以主动逐行审计为预设，将安全质量内建于代码提交流程；后者以被动响应报告为预设，将安全质量交由外部报告者驱动；总纲第 7 条——技术选择即政治选择：OpenBSD 选择主动审计、FreeBSD 选择 Security Officer 制度、Linux 选择发行版各自为政——三者各自以不同的治理成本换取不同的安全覆盖范围

**辨析**：三者安全实践的 “严格程度” 对比缺乏权威量化评估——OpenBSD Security Advisories 与 FreeBSD Security Advisories 的 advisory 数量可通过各自页面计数，但 advisory 数量受多个因素影响（审计范围、披露政策、版本发布频率等），不能直接作为安全质量排名依据；“反应式安全” 与 “主动审计” 的界定——OpenBSD 自 1996 年起的逐行审计是主动审计，FreeBSD Security Officer 制度在收到报告后组织修复是反应式安全，Linux 各发行版在收到 CVE 后各自打包修复也是反应式安全，二者区分的关键在于安全发现是内生于审计流程还是外生于用户报告

**文献**：FreeBSD Security Advisories 1996-2000 [EB/OL]. <https://www.freebsd.org/security/advisories/>；Linux Security Audit Project [EB/OL]. <https://www.linux.org.au/lsec/>；OpenBSD Security Advisories [EB/OL]. <https://www.openbsd.org/security.html> ［A］

**OpenBSD/FreeBSD/Linux 1990 年代安全实践对比**：

| 维度 | OpenBSD | FreeBSD | Linux |
| --- | --- | --- | --- |
| 安全模型 | 主动逐行审计 | Security Officer 制度（反应式） | 各发行版各自为政（反应式） |
| 审计范围 | 基本系统（src/ 与 sys/） | 无系统性审计 | 1999 年 Linux Security Audit Project（规模有限） |
| 关键人物 | de Raadt、Brauer、millert 等 | Warner Losh、Kris Kennaway 等 | Daniel Stone 等 |
| 安全发现来源 | 内生于审计流程 | 外生于用户报告 | 外生于用户与厂商报告 |
| 跨项目扩散 | strlcpy/strlcat、arc4random、OpenSSH | Security Advisories 标注 OpenBSD fix | 各发行版各自打包修复 |
