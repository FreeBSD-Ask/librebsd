# 205.6 审计记录考据方法论

**要点**：OpenBSD commit log 中审计 commit 通常以 “fix” 或 “audit” 为前缀，仅凭 message_subject 无法与一般 commit 区分——部分审计 commit 的 message_subject 仅写 “fix [漏洞描述]” 而无明确 audit 标签，须交叉引用 Security Advisory 中的 commit hash 方可确认其为审计 commit；OpenBSD Security Advisories 数据库（<https://www.openbsd.org/security.html>）每条 advisory 均含 CVE 编号、影响版本、修复 commit hash，是审计 commit 识别的权威索引；统计结论印证——openbsd.duckdb openbsd-src 仓库总 commit 数 245,904（统计结论 C-05），审计 commit 占其中一部分，反映 OpenBSD 安全审计文化自 fork 起的工程节奏；openbsd.duckdb openbsd-ports 仓库总 commit 数 210,982（外部基准 E-16），反映 OpenBSD ports 子系统作为安全审计文化的延伸——ports commit 中亦含安全修复（如 ports 中 OpenSSL/LibreSSL 版本更新），与 openbsd-src 审计 commit 构成安全审计的源码与 ports 双轨证据

**史料**：OpenBSD CVS commit log（<https://cvsweb.openbsd.org/>）；OpenBSD Security Advisories 数据库（<https://www.openbsd.org/security.html>，含 CVE 编号与修复 commit hash）；BUGTRAQ 档案（<https://seclists.org/bugtraq/>）；openbsd.duckdb openbsd-ports 仓库 commit 总量（外部基准 E-16:210,982 commits，SQL `SELECT COUNT(*) FROM commits WHERE repo_name='openbsd-ports'`，查询日期 2026-07-27，来源：外部基准-StackOverflow-PackageEcosystem.md 第 3.2 节）〔L1 代码/构建产物/L2 即时通讯记录/L3 官方文档与公告〕

**史观**：总纲第 25 条——0 信任原则：审计记录与 commit log 本身也须 0 信任——部分 commit 在 CVS 到 Git 迁移过程中可能丢失 audit 标签或 metadata，advisory 中的 commit hash 须与仓库实际历史交叉验证方可确认；总纲第 8 条——社区文化即技术资产：OpenBSD 通过 advisory + commit hash 双重索引机制将审计劳动物化为可追溯的社区资产，任何修复均可通过 advisory→commit hash→ 源码修订版本链条追溯；统计结论印证——C-05 openbsd-src 总 commit 数 245,904 与 E-16 openbsd-ports 总 commit 数 210,982 的对照反映“分离聚合是永恒规律”（总纲第 4 条）的工程显现——src 与 ports 两个子系统的 commit 量接近，反映 OpenBSD 安全审计文化在内核源码与用户态软件包两个层面均以工程节奏持续推进

**辨析**：审计 commit 与一般 commit 的区分——OpenBSD commit log 中部分 commit 明确标注 “audit” 或 “security”，部分仅写 “fix” 须交叉引用 advisory 中的 commit hash 方可确认；advisory 中的 commit hash 是权威识别依据——若某 commit hash 出现在 advisory 中则确认为审计 commit，否则视为一般 commit；**advisory 与 commit 的一对多/多对一关系**——一条 advisory 可能对应多个 commit（如 OpenSSH 2002 年远程漏洞修复涉及多条 commit 分别修补不同代码路径，advisory 列出多个 commit hash），亦可能多条 advisory 对应同一 commit（如同一次代码审计发现的多个 CVE 在同一 commit 中一并修复，advisory 各自列出该 commit hash），这一多对多对应关系使 advisory→commit 的映射非平凡，须以 advisory 页面原始 HTML 为准逐一核验，不可假定一对一关系；CVS 到 Git 迁移对审计记录的影响——OpenBSD 从 CVS 迁移至 Git（2022 年完成）过程中 commit hash 变化，但 advisory 页面已更新为新 hash，旧 CVS 修订版本号仍保留在 commit message 中作为交叉验证依据；**统计局限性标注**——E-16 openbsd-ports 总 commit 数 210,982 包含安全修复与非安全修复，无法仅凭 commit 总量推断安全审计在 ports 子系统中的占比，安全审计占比须以 advisory 中的 ports 相关 commit hash 与 openbsd.duckdb openbsd-ports 仓库 commit_files 表 JOIN 方可确认；0 信任原则适用：统计显著 ≠ 实际显著，C-05 与 E-16 的 commit 总量仅反映工程活跃度，不等于安全审计质量——commit 量高可能反映频繁的代码变更（含 bug 引入），commit 量低可能反映稳定的代码质量，二者须结合 advisory 数量与 CVE 修复时延综合评估
