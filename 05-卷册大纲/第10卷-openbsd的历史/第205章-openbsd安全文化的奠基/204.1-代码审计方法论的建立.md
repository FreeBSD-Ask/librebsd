# 204.1 代码审计方法论的建立

- 要点：OpenBSD 代码审计方法论由 de Raadt 主导自 1996 年 fork 后逐步建立，核心实践为逐行审查基本系统源码，重点关注缓冲区溢出与格式化字符串漏洞、信任边界与权限提升；审计流程为发现问题 → 修复 →commit log 详细记录 →security advisory；OpenBSD Security Advisories 自 1996 年起在 <www.openbsd.org/security.html> 持续发布，每条 advisory 记录漏洞技术细节、影响范围、修复 commit hash 与对应 CVS 修订版本
- 史料：OpenBSD Security Advisories 1996-2000（<https://www.openbsd.org/security.html>）；OpenBSD CVS commit log 中 audit 相关 tag（<https://cvsweb.openbsd.org/>）；OpenBSD 手册页 **security(8)**（<https://man.openbsd.org/security.8>）与 **afterboot(8)**（<https://man.openbsd.org/afterboot.8>）
- 史观：总纲第 8 条——社区文化即技术资产：代码审计作为社区文化资产是 OpenBSD 区别于其他 BSD 的核心——de Raadt 在 1996 年 fork 后将 “逐行审查基本系统源码” 确立为社区共识，这一共识通过 commit log 中的详细记录与 security advisory 的持续发布物化为可追溯的技术资产，任何贡献者提交的代码均须经审计流程检验方可入树；总纲第 5 条——组织结构塑造技术路径：OpenBSD 的扁平化组织结构（de Raadt 作为 BDFL + 核心开发者小组）使审计决策无需经过委员会审批即可执行，与 FreeBSD Core Team 投票决策模式相比审计响应更快
- 辨析：审计方法论在不同叙事中存在差异——部分资料强调 “逐行审查”（de Raadt 在 misc@ 邮件列表多次提及 “audit every line”），部分强调 “分类审查”（按漏洞类型如 buffer overflow、format string、integer overflow 分类扫描），二者非互斥而是互补——逐行审查是方法论基础，分类审查是针对特定漏洞类型的专项扫描；审计范围限定为基本系统（src/ 与 sys/ 目录），ports 树（ports/ 目录）由各 port 维护者自行负责，OpenBSD 核心团队不系统性审计 ports；openbsd.db 查询 L3.1.1.audit 在深层信息挖掘报告中不存在（报告仅含 L3.1.1.MFC、L3.1.1.Fix、L3.1.1.Add、L3.1.1.Refactor 等跨 22 仓库关键词分析，未覆盖 “audit” 关键词的 commit 模式挖掘），审计相关 commit 模式数据须以 openbsd.db 直接查询 message_subject/message_body 含 “audit”、“security”、“fix” 等关键词补全，并须与 OpenBSD Security Advisories 页面（<https://www.openbsd.org/security.html>）的 commit hash 交叉验证
