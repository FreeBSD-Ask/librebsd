# 205.3 早期重大漏洞发现与修复（1996-2000）

**要点**：OpenBSD 1996-2000 年间通过代码审计发现并修复大量安全漏洞，包括缓冲区溢出（如 ftpd、telnetd 远程溢出）、格式化字符串漏洞（如 wu-ftpd Format String Vulnerability CVE-2000-0573，2000-06 披露）、信任边界问题；部分漏洞在审计前已被利用（如 1999 年 BIND NXT 漏洞 CVE-1999-0833），部分是审计发现的新型漏洞；OpenBSD Security Advisories 页面（<https://www.openbsd.org/security.html>）逐条记录了 1996 年至 2000 年间的所有 advisory，每条含 CVE 编号、影响版本、修复 commit hash，advisory 总数在该页面可直接计数

**史料**：OpenBSD Security Advisories 1996-2000（<https://www.openbsd.org/security.html>，逐条记录 advisory）；CVS commit log（<https://cvsweb.openbsd.org/>）；BUGTRAQ 邮件列表档案（<https://seclists.org/bugtraq/>）；CVE-2000-0573 wu-ftpd 格式化字符串漏洞；CVE-1999-0833 BIND NXT 漏洞

**史观**：总纲第 10 条——边缘者贡献：OpenBSD 作为边缘项目通过审计贡献安全成果至整个 Unix 生态——审计发现的漏洞修复经 cross-BSD 协调反馈至 FreeBSD/NetBSD，部分修复被 Linux 发行版移植，OpenBSD 的审计劳动为整个 Unix 生态提供了免费的安全质量保证服务；总纲第 25 条——0 信任原则：OpenBSD 审计方法论对基本系统源码保持 0 信任——即使是一手代码（如 CSRG 遗留代码、NetBSD 继承代码）也逐行审查，不因来源可信而免检，这一原则在 1996-2000 年间通过发现并修复 BIND NXT、ftpd 溢出等已存在多年的漏洞得到验证

**辨析**：“数千个漏洞” 的具体数字——OpenBSD Security Advisories 页面（<https://www.openbsd.org/security.html>）逐条记录了 1996 年至今的 advisory，1996-2000 年间的 advisory 可直接在该页面计数；advisory 数量与实际修复的漏洞数量非一一对应——一条 advisory 可能修复多个相关漏洞，一个漏洞的修复可能跨多个 commit；“数千个漏洞” 的表述可能源于 OpenBSD 团队在邮件列表与宣传材料中的概括性说法，精确数字应以 advisory 页面计数为准 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；wu-ftpd 格式化字符串漏洞（CVE-2000-0573）的披露时间为 2000-06 而非 1997，格式化字符串漏洞作为漏洞类别在 1999-2000 年间被广泛认知（Proneys 1999 年工作与 Tymm Twillman 2000 年工作奠定），部分资料将 wu-ftpd 格式化字符串漏洞误记为 1997 年

**文献**：OpenBSD Security Advisories [EB/OL]. <https://www.openbsd.org/security.html>；OpenBSD CVS 仓库 [EB/OL]. <https://cvsweb.openbsd.org/>；BUGTRAQ 邮件列表存档 [EB/OL]. <https://seclists.org/bugtraq/>；CVE-2000-0573 [EB/OL]. <https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2000-0573>；CVE-1999-0833 [EB/OL]. <https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-1999-0833> ［A］
