## 195.2.1 W^X 的设计与效应

**要点**：OpenBSD 3.1（2002.5）引入 W^X（Write XOR Execute）内存保护机制，由 Niels Provos 主导；W^X 利用 i386 与 amd64 的 NX bit 等硬件特性，使栈与堆内存不可执行；W^X 是 OpenBSD 对缓冲区溢出攻击的根本性防御，后被 Linux/FreeBSD/NetBSD 效仿

**史料**：OpenBSD 3.1 Release Notes W^X 部分；Provos W^X 设计文档；CVS commit log ［A］

**史观**：总纲第 10 条——边缘者贡献：OpenBSD 作为边缘项目率先引入 W^X，影响整个 Unix 安全实践

**辨析**：OpenBSD W^X 与 Linux/FreeBSD 类似机制（如 PaX、OpenBSD exec shield）的关系需考据——PaX 项目更早但未集成至 Linux 主线；i386 不支持 NX bit 的硬件（如 Pentium III）的兼容性需考据

**文献**：OpenBSD 3.1 Release Notes；Provos W^X 文档；PaX 项目文档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 195.2.2 stack protector 的工程实践

**要点**：OpenBSD 3.3（2003.5）引入 stack protector（ProPolice/SSP），由 Hiroaki Etoh 与 IBM Tokyo Research Lab 贡献；SSP 在函数返回地址前插入 canary，检测栈溢出；SSP 默认启用让 OpenBSD 基本系统获得栈保护能力

**史料**：OpenBSD 3.3 Release Notes SSP 部分；ProPolice/SSP 设计文档；IBM Tokyo Research Lab 论文 ［B］

**史观**：总纲第 10 条——边缘者贡献：IBM Tokyo Research Lab 贡献 SSP，体现商业研究对开源项目的边缘贡献

**辨析**：SSP 的具体实现细节（如 canary 类型、函数选择）在不同来源中存在差异——需对照源码核验；SSP 的性能开销在不同工作负载上差异较大

**文献**：OpenBSD 3.3 Release Notes；ProPolice 文档；IBM Tokyo Research Lab 论文 ［B］

## 195.2.3 权限分离与 swap encryption

**要点**：OpenBSD 3.4（2003.11）改进权限分离（privilege separation），应用于 OpenSSH、tcpdump、dump 等工具；权限分离将特权进程与非特权进程隔离，降低漏洞影响；OpenBSD 3.6（2004.11）引入 swap encryption，默认加密交换分区，防止物理攻击读取内存

**史料**：OpenBSD 3.4/3.6 Release Notes；OpenSSH privilege separation 设计文档；CVS commit log ［A］

**史观**：总纲第 17 条——形式与内容：权限分离作为“形式”（进程隔离架构）改变工具“内容”（安全特性）的能力

**辨析**：OpenSSH privilege separation 的具体设计（如特权与非特权进程的通信）需考据；swap encryption 对性能的影响在不同硬件上差异较大

**文献**：OpenBSD 3.4/3.6 Release Notes；OpenSSH privilege separation 文档；CVS commit log ［A］

#### 195.2.5 “默认安装仅两个远程漏洞”口号的演变——OpenBSD 提出“在默认安装中 6 年仅两个远程漏洞”的口号，该口号长期受批评，批评者认为计数依赖于严格定义

- 85.3.1 口号的提出与演变

**要点**：OpenBSD 提出“在默认安装中 6 年仅两个远程漏洞”口号，最初由 de Raadt 在 OpenBSD 网站上宣称；口号中的“远程漏洞”指默认安装下可被远程攻击者利用的漏洞；口号随时间演变，至 2000 年代中期改为“多年无远程漏洞”

**史料**：OpenBSD 官网“Security”页面历史快照（Wayback Machine）；OpenBSD 邮件列表讨论；de Raadt 公开演讲 ［A］

**史观**：总纲第 17 条——形式与内容：口号作为“形式”（量化指标）反映 OpenBSD 安全“内容”（实际漏洞数），但形式与内容之间存在张力

**辨析**：“两个远程漏洞”的具体指代在不同叙事中存在差异——部分资料称是 OpenBSD 2.6 之前的两个漏洞，部分称是历史漏洞，需对照 OpenBSD 官网核验

**文献**：OpenBSD 官网 Security 页面；Wayback Machine 快照；de Raadt 演讲［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

- 85.3.2 批评者的论点与依据

**要点**：批评者（如 CVE 数据库研究者、Linux 社区成员）指出 OpenBSD 口号依赖于严格定义——“默认安装”排除了 ports 与第三方软件，“远程漏洞”排除了本地漏洞与权限提升漏洞；批评者认为 OpenBSD 实际安全记录虽有改进，但口号夸大宣传

**史料**：CVE 数据库 OpenBSD 条目；Bugtraq 与 Full Disclosure 邮件列表批评帖；OpenBSD 邮件列表反驳 ［A］

**史观**：总纲第 25 条——0 信任原则：批评者的论点需考据——需对照 CVE 数据库核验 OpenBSD 实际漏洞记录

**辨析**：批评者的代表性需考据——单一批评者不等于社区共识；“严格定义”的具体范围（如是否包括本地漏洞）需对照 OpenBSD 官网核验

- W^X 被界定为一种内存保护策略而非执行机制：同一内存页不得同时可写与可执行，其效力取决于页表在硬件层面的实际强制；Larkin 指出该机制在 OpenBSD 中可追溯至 2001/2002 年、至 2015 年仍在改进，并坦承它“只是攻击者必须绕过的又一道障碍”（969.70-974.92）；除防御外，它还能把“先写后执行”这类程序错误在攻击者利用之前暴露为用户可见的缺陷（983.34-1019.14）。（BSD Now EP89，[915.64-1019.14]，L1）
- Pascal Stumpf 在专访中自述 OpenBSD 静态 PIE 的实现：PIE 使可执行文件可映射到随机内存偏移，是 ASLR 全景（栈随机化、随机 mmap、库位置随机化）中“完整随机地址空间的最后一块”（1291.18-1303.74）；在“严格 W 异或 X 策略——任何内存不可同时可写与可执行”（1315.10-1327.10）之下，攻击者无法跳入被覆盖缓冲区执行 shellcode，只能复用可执行文件与 libc 中以 ret 结尾的 gadget，PIE 随机化令 gadget 地址不可预测；静态二进制没有 `ld.so` 的运行时重定位，重定位须在链接进每个可执行文件的 C 启动代码中完成；实现归功于 Theo de Raadt、Kurt Miller 与 Mark Kettenis，Kettenis 写大部分代码、Stumpf 承担推动，向其他架构的移植在数日至一周内完成。　[存疑脚注] 转写将 Mark Kettenis 记作 Mark Katanis，依 OpenBSD 开发者名录与 PIE 工作语境校正为 Mark Kettenis；另 1535.68-1537.68 处活动名转写作 Azure PSDCon，疑为 vBSDcon，未能确证。（BSD Now EP85，[1182.5-1531.9]，L1）
- Solaris 与 PF 的新闻浓缩了许可证重塑防火墙格局的因果链：Oracle 因一封提交给 OpenBSD 的 bug 报告“意外泄露”Solaris 12 将以 PF 为自带防火墙（78.80-84.32），11.3 中 PF 先以可选防火墙身份出现，而 IP filter 被判入“death row”（126.08-131.84）；主持人回顾 PF“实际是因许可证问题在 OpenBSD 上作为 IP filter 的替代品而生”，且 Solaris 正是 IPF 的原始开发平台，故此番采纳“算是兜了一圈回到主场地盘”（133.80-150.40），并称 PF“正在到处扩散”（182.16-184.40）；FreeBSD 树中残留的 IP filter 则被认为“可能需要死在那里”。（BSD Now EP85，[70.4-170.9]，L2）
- PackageNG 1.50 发布被主持人视为包管理变革的关键节点：provides/requires 框架进入正式版，使依赖协商可按能力而非具体包名进行（以 Perl 版本替换为例）；升级比较忽略大小写、支持以 `pkg -r` 安装至指定根目录、求解器会明确解释重装、移除或升级每个包的理由，并开始支持 OS X 等平台；路线图上的 cherry-picking 升级、MariaDB 与 MySQL 的互替声明、直接管理 CentOS 仓库 RPM 的 Linux 包后端、同仓库多版本共存、下载断点续传与文件 immutable 标志，被明确与 base 系统打包的推进相勾连。　[存疑脚注] 转写作 Edge BSD 的平台名可辨性弱，疑指 pkgng 的 EdgeBSD 支持条目，暂不确证。（BSD Now EP85，[2288.3-2619.5]，L2）
- 访谈于 OpenCon 2007 之后在威尼斯 Bar Piccolo Martini 进行，对象为 Peter Hansteen；其著作 The Book of PF（No Starch Press，OpenBSD 防火墙实务指南）定于 2007 年 12 月 15 日出版，OpenCon 上私印样书已拍卖，亚马逊与出版社渠道可预订，会上已有人洽谈多语种翻译；作者称读者仅需基础 TCP/IP 知识，内容从规则集求值逐步进阶。（BSDTalk EP136，[220.79-901.72]，L1）
- 其转向 PF 的经历：为小公司管理网络时平台先以 Linux 为主、渐转 FreeBSD，但防火墙始终在 Linux 上，iptables 维护渐成苦役；旧防火墙硬件烧毁后改用 OpenBSD 加 pf，“再未回头”。（BSDTalk EP136，[253.15-296.63]，L1）
- PF 的可读性哲学：向 iptables 用户展示配置时对方常难以相信规则能如此简单——“这不是 shell 脚本”；装好系统的机器上五到十行 pf.conf 置于网络与世界之间即可工作。宏以符号名为服务列表（ssh、domain、www、https 等）提供可读简称；表是专为 IP 地址与网段设计的高效数据结构，支持 CIDR 与取反、可自命令行操纵，配合锚点使外部程序与规则集交互；“PF 不能动态改规则”的质疑至多部分成立。（BSDTalk EP136，[296.63-446.16]，L1）
- CARP（Common Address Redundancy Protocol）的诞生部分是对一个故障切换协议在 IETF 冲向标准途中被发现牵涉约三百余项专利的回应，OpenBSD 团队遂自行撰写替代；CARP 作为虚拟网络接口让一组机器共享对外 IP，一主多备，主机故障时备份近乎透明地接管——凌晨三点主防火墙宕机无需短信叫醒管理员，半年一次的 OpenBSD 升级可挪至工作时间完成，主机恢复后备机再行交还。（BSDTalk EP136，[458.44-546.15]，L1）
- hoststated 由 Reyk Floeter 与另一开发者（转写姓氏不可辨）写成，经 PF 表与规则集集成：对外发布单一 IP 与主机名并以轮询重定向到后端机器表，守护进程检测后端存活、将死机移出地址池，从而令服务更可靠；至 OpenBSD 4.2，hoststated 已能较好处理 SSL 连接。（BSDTalk EP136，[546.15-621.95]，L1）
- 抗 DDoS 的状态追踪选项源自一次拒绝服务受害者的通用化追问，于 OpenBSD 3.7 前后加入：规则中可限定单主机最大并发连接数与时间窗内连接速率，超限者落入专门表；处置方式从直接封锁（配合 flush global）到借 ALTQ 队列给超限者极小带宽任其排队。（BSDTalk EP136，[626.33-689.28]，L1）
- spamd 与灰名单：spamd 约于 OpenBSD 3.5 引入，最初对黑名单来源的 SMTP 连接以每字节一次的应答拖延至对方放弃；同期出现的灰名单基于对 SMTP 规范“临时错误须在合理时间内重试”的较真解读——垃圾邮件多出自被劫持 Windows 机器上的简易软件、从不检查返回码亦不重试，真实邮件服务器则会在约半小时内回来；五年后灰名单仍能当场消灭约 95% 的垃圾邮件；spamd 消除的是低垂果实，最精明的发件者或借开放中继者仍可能通过；spamd 亦伪装成开放中继诱捕不校验投递的中继检查器，其灰名单中可见上万封从未投递的转发尝试。（BSDTalk EP136，[695.52-840.75]，L1）
- 结语立场：支持 OpenBSD 请购买 OpenBSD 用品，支持作者请购买其书；并以略带激烈的方式断言——不运行 OpenBSD 或未在其他 BSD 上运行 PF 的管理员“错失良多，把事情做得比必要的更难”。（BSDTalk EP136，[903.76-928.32]，L1）
- 主播两周年回顾：BSDTalk 首期发布于 2005 年 12 月 20 日；两年间 NetBSD 自 3.0（2005 年 12 月 23 日发布）演进至 4.0，PC-BSD 从未及 1.0 到今日，FreeBSD 7.0 正筹备候选版本；主播感谢社区与听众在时间、金钱、主机与精力上的捐助。（BSDTalk EP136，[119.63-183.73]，L2）
- CARP（Common Address Redundancy Protocol）最初出现于 OpenBSD 操作系统，其基本构想是主备两机充当同一网络的防火墙并共享一个虚拟地址：主机失效时备机瞬时接管全部流量，主机恢复后备机退回备份角色；对防火墙这类网络关键部件进行升级时，可先在备机上构建新内核，即便升级出错也有主机兜底，从而显著降低维护风险。（BSDTalk EP28，[77.64-123.72]，L1）
- 当事人 Liam Foy 于 2006 年将 CARP 移植到 NetBSD 内核：patch 已发布并收到社区反馈，修复了其中一处错误后运行良好，已获基本认可、等待正式提交进官方树；同期 CARP 已可在 FreeBSD 中使用，他亦在推进向 DragonFly BSD 的移植，并称 CARP 与各主要 BSD 上运行良好。（BSDTalk EP28，[366.66-403.46]，L1）
- 当事人偶然发现其就读大学的整个网络完全构建于 NetBSD 与 OpenBSD 机器之上，承载 NFS、邮件等服务，服务约五千名学生与全部教职员，并为约三千名住宿学生提供网络接入；以此作为 BSD 在生产环境中沉默而广泛部署的一手经验证据。（BSDTalk EP28，[790.7-823.34]，L1）
- BSDPortal 网站的诞生过程显示 2005-2006 年 BSD 在线资源生态的自发协作：当事人大学期间为在一处聚合各 BSD 站点的 RSS 而建站，先托管于运行 OpenBSD 的免费主机，因 PHP 资源限制迁移至 SDF freeshell，再迁至友人服务器；发起购域名请求后一天内收到六人响应，域名由社区成员捐购，RSS 源亦由社区反馈持续扩充。（BSDTalk EP28，[532.72-706.1]，L1）
