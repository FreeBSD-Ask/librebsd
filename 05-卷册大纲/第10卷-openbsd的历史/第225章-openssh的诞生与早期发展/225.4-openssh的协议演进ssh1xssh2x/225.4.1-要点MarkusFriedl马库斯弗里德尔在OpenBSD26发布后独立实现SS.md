# 225.4.1 要点MarkusFriedl马库斯弗里德尔在OpenBSD26发布后独立实现SS

**要点**：Markus Friedl（马库斯·弗里德尔） 在 OpenBSD 2.6 发布后独立实现 SSH 2 协议支持，OpenSSH 2.0（commit 81c34fa6419b，2000-04-26 markus“OpenSSH-2.0”）首次支持 SSH 2.x 协议，随 OpenBSD 2.7 于 2000-06-15 发布——OpenSSH 2.0 单一软件同时支持 SSH 1 与 SSH 2 协议；SSH 2.x 协议基于 IETF RFC 4250-4256，采用 DH 密钥交换与 DSA/RSA 签名，架构比 SSH 1.x 更安全；OpenSSH 7.4（2016-12-19）移除服务端 SSH v.1 协议支持（openbsd.duckdb commit 3d9665d37aa5，2016-08-13 markus“remove ssh1 server code”），并在发布声明中预告“约 2017 年 8 月移除剩余 SSH v.1 协议支持（仅客户端，当前编译时禁用）”；OpenSSH 7.6（2017-10-03）完全删除 SSH 协议版本 1 支持（客户端代码、配置选项、文档一并删除，openbsd.duckdb commit 6c99a5ed578d，2017-04-30 djm“remove SSH1 make flag and associated files”），SSH 1.x 协议自此从 OpenSSH 代码库彻底移除

**史料**：openbsd.duckdb openbsd-src 仓库 commit 81c34fa6419b（2000-04-26 markus“OpenSSH-2.0”）、commit 3d9665d37aa5（2016-08-13 markus“remove ssh1 server code”）、commit 6c99a5ed578d（2017-04-30 djm“remove SSH1 make flag and associated files”）；OpenSSH 7.4 Release Notes（<https://www.openssh.com/txt/release-7.4>，记载“This release removes server support for the SSH v.1 protocol”与未来弃用预告）；OpenSSH 7.6 Release Notes（<https://www.openssh.com/txt/release-7.6>，记载"ssh(1): delete SSH protocol version 1 support, associated configuration options and documentation"）；IETF RFC 4251（SSH 协议架构）、RFC 4253（SSH 传输层协议）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：OpenSSH 7.4（2016-12）移除服务端 SSH1、7.6（2017-10）完全删除 SSH1 是以“安全性优先于兼容性”为预设的政治选择——宁可切断与遗留 SSH1 客户端的互操作也要消除协议本身的安全缺陷（SSH1 协议设计存在插入攻击等结构性漏洞），与商业 SSH 实现长期维持 SSH1 兼容以保留遗留用户的路线截然不同；0 信任原则：OpenSSH 移除 SSH1 是 0 信任原则在协议层面的实践——SSH1 协议本身被视为不可信，无论遗留用户规模多大都不保留

**辨析**：SSH1 移除时间线经 OpenSSH 官方 Release Notes 与 openbsd.duckdb 双重核实——7.4（2016-12-19）移除服务端 SSH1，7.6（2017-10-03）完全删除客户端 SSH1（含配置选项与文档），部分二手资料将“OpenSSH 8.2（2020-02-14）”误记为 SSH1 移除版本，但 8.2 Release Notes 实际记载的是 FIDO/U2F 支持（ecdsa-sk、ed25519-sk 公钥类型）与 ssh-rsa 算法弃用预告，与 SSH1 移除无关；SSH 2.x 协议的实现差异——OpenSSH 2.0（2000-04-26）至 2.3.0（2000-11）间逐步完善 SSH 2.x 协议实现，SFTP 子协议服务端由 Friedl 在 2.3.0（2000-11）实现，SFTP 客户端由 Damien Miller（达米安·米勒） 在 2.5.0 实现
