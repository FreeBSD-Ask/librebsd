# 201.3 项目统摄史观审视：LibreSSL fork 与 RETGUARD 的本体论平等

## 201.3.1 本体论平等视角下的 LibreSSL 与 OpenSSL、RETGUARD 与 LLVM CFI

**要点**：从项目史观总纲第 8 条“本体论上各方平等”审视，LibreSSL 与 OpenSSL 在本体论上地位相等，二者皆是 TLS 实现的特定阶段状态，差异仅是工程哲学的不同而非本体等级的高下——LibreSSL 的“极简安全”（删除 dead code、简化 API、ISC 许可证）与 OpenSSL 的“功能全面”（保留向后兼容、持续新增功能、Apache 许可证）各自在其生态内具有合理性；RETGUARD 与 LLVM CFI、Microsoft CFG 在本体论上地位相等，三者皆是控制流防护机制的特定阶段状态——RETGUARD 以 per-function 随机 canary 防护返回地址，LLVM CFI 以控制流完整性图防护间接调用，Microsoft CFG 以目标地址验证防护间接调用，三者差异是工程哲学的不同而非本体等级的高下；文档与代码本体平等——LibreSSL fork 公告文本与 openbsd.duckdb commit log 在本体论上地位相等，前者塑造 fork 的叙事认知，后者记录 fork 的实际代码变更，二者共同构成 LibreSSL fork 的完整本体；RETGUARD 的设计文档与编译器实现代码在本体论上地位相等，前者塑造 RETGUARD 的设计哲学叙事，后者记录 RETGUARD 的工程实现，二者共同构成 RETGUARD 的完整本体；OpenBSD 阵营（Beck、de Raadt、Mortimer 等）与 OpenSSL 阵营（OpenSSL 维护者、下游应用维护者）在本体论上地位相等，二者的叙事须对称呈现

**史料**：项目史观总纲第 8 条原文（据原文第 25 章）、LibreSSL 与 OpenSSL 综合对比研究、RETGUARD 与 LLVM CFI/Microsoft CFG 综合对比研究、openbsd.duckdb openbsd-src 仓库 LibreSSL/RETGUARD 相关 commit、LibreSSL fork 公告与 RETGUARD 设计文档〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 8 条——本体论上各方平等：LibreSSL 与 OpenSSL、RETGUARD 与 LLVM CFI/Microsoft CFG、OpenBSD 阵营与 OpenSSL 阵营在本体论上地位相等

**辨析**：本体论平等不等于价值中立——史家仍须呈现 LibreSSL fork 与 RETGUARD 的具体效应（工程自主与生态碎片化、安全加固与性能开销），但不得以“极简优于全面”或“全面优于极简”的前理解预先判定；【0 信任原则·本体论平等的非相对主义】本体论平等不意味着所有机制无差别，而是意味着差异是特定阶段状态的不同而非本体等级的高下；【0 信任原则·本体论平等与考据验证的区分】本体论平等是史观预设而非考据结论——史家仍须以多源交叉验证逼近史实，本体论平等不豁免考据义务

**文献**：项目史观总纲第 8 条；LibreSSL 与 OpenSSL 综合对比研究；RETGUARD 与 LLVM CFI/Microsoft CFG 综合对比研究；openbsd.duckdb openbsd-src 仓库 LibreSSL/RETGUARD 相关 commit ［A］

## 201.3.2 文化即形式主义视角下的 LibreSSL fork 叙事与 RETGUARD 加固叙事

**要点**：从项目史观总纲第 15 条“文化即形式主义”审视，LibreSSL fork 叙事与 RETGUARD 加固叙事皆是形式主义化的传统——LibreSSL fork 的“许可证纯洁性”动机在形式主义化过程中被固化为 OpenBSD 项目意识形态的标志，fork 的工程动机（dead code 清理）与意识形态动机（ISC 许可证偏好）在形式主义化过程中被简化为单一叙事；RETGUARD 的“安全优先于性能”哲学在形式主义化过程中被固化为 OpenBSD 工程文化的核心，5-10% 的性能开销在形式主义化过程中被重构为“安全代价的必要支付”而非“工程折中的权衡成本”；文化即形式主义意味着 LibreSSL fork 与 RETGUARD 的“传统”并非自然传承而是权力运作的形式主义重构——什么被记录为“OpenBSD 安全创新”（如 LibreSSL fork、RETGUARD 引入）、什么被遗忘（如 fork 的生态成本、RETGUARD 的架构覆盖局限），本身就是权力行使；知音难觅同样适用于技术社区——OpenBSD 阵营以“工程自主”与“安全优先”为知音共识，OpenSSL 阵营以“生态完整”与“功能全面”为知音共识，二者知音网络不重叠，未被纳入对方知音网络的叙事即被形式主义地边缘化

**史料**：项目史观总纲第 15 条原文、LibreSSL fork 公告与 OpenBSD 阵营声明（fork 叙事的形式主义化产物）、RETGUARD 设计文档与 tech@ 邮件列表讨论（加固叙事的形式主义化产物）、OpenSSL 阵营对 LibreSSL 的批评（被边缘化的叙事）、RETGUARD 性能开销与架构覆盖局限的批评（被边缘化的叙事）

**史观**：总纲第 15 条——文化即形式主义：LibreSSL fork 叙事与 RETGUARD 加固叙事是形式主义化的传统，其“自然性”须被解构

**辨析**：文化即形式主义不意味着叙事是虚假的——LibreSSL fork 与 RETGUARD 在工程产出上具有实际效应（如 LibreSSL 的低 CVE 频率、RETGUARD 的 ROP 防护），但这一实际效应不否定其叙事的形式主义性质；【0 信任原则·叙事权力的维度】“OpenBSD 安全创新”叙事须被审视——谁在定义创新（OpenBSD 阵营）、谁的成本被遗忘（OpenSSL 阵营与下游应用维护者），本身就是权力行使；【0 信任原则·形式主义化的动态性】形式主义化是持续过程——LibreSSL fork 从 2014 年的工程回应演化为 2026 年的 OpenBSD 意识形态标志，RETGUARD 从 2018 年的编译时加固演化为 OpenBSD 安全哲学的核心象征，这一演化本身须被考据记录

**文献**：项目史观总纲第 15 条；LibreSSL fork 公告；RETGUARD 设计文档；OpenBSD tech@ 邮件列表存档；OpenSSL 阵营批评文献 ［A］

## 201.3.4 偶然性视角与利益分配视角下的 LibreSSL fork 及 RETGUARD

**要点**：从项目史观总纲第 5 条“没有必然性，只有偶然性”与总纲第 13 条“法律与道德是利益分配”审视，LibreSSL fork 与 RETGUARD 皆非“安全必然性”的产物，亦非纯粹的工程道德选择，而是偶然事件与利益分配的交汇。总纲第 5 条指出，每一次 fork、每一个技术决定都是不可替代的偶然——Heartbleed 于 2014 年 4 月 7 日披露是偶然事件，OpenBSD 团队当日即由 djm 提交 `af0b15b8442f` 修复是偶然的即时响应，Beck 于 4 月 14 日开始移除 Atalla/AEP 引擎、jsing 同日开始应用 KNF 格式化是偶然的分工，LibreSSL 作为独立库的首次 commit 于 2014 年 7 月 12 日由 jsing 提交 `b6553af36068` 是偶然的时间节点；RETGUARD 由 Mortimer 于 2018 年 6 月 6 日提交 `e688c2b0648a` 引入，2018 年 6 月 6 日前 OpenBSD 已有 KARL 等安全机制，RETGUARD 的引入时点与覆盖架构（amd64 先行、arm64 后续）皆是偶然的工程节奏。将这一偶然必然化——无论叙述为“OpenBSD 必然 fork OpenSSL”还是“RETGUARD 必然成为编译时安全标准”——都是机械的错误。总纲第 13 条指出，任何道德问题本质上是利益问题——LibreSSL fork 的“许可证纯洁性”叙事以道德语言（“纯洁”与“污染”）包装 ISC 许可证与 Apache 许可证之间的利益分配，fork 的许可证动机（OpenBSD 偏好 ISC 的宽松与无 attribution 要求）与 OpenSSL 当时所用的 OpenSSL/SSLeay 旧许可证（含广告条款，即 OpenBSD 当年主张的 attribution 负担）之别本质是两个项目对代码流向与署名权益的不同利益定位〔订正：原作"与 OpenSSL 的 Apache 许可证（含 attribution 要求）差异"系许可证时代错置——2014 年 fork 时 OpenSSL 尚用 OpenSSL/SSLeay 旧许可证，Apache-2.0 系 2021 年 OpenSSL 3.0 起才采用，2026-09-14 依核查报告订正，Apache 许可证对比移至 2021 年后时段另述〕；RETGUARD 的“安全优先于性能”哲学以道德语言（“安全至上”与“性能妥协”）包装 OpenBSD 在服务器市场的利益定位——OpenBSD 以性能代价换取安全细分市场，这一选择在 OpenBSD 生态内自洽但在高性能服务器场景下构成市场利益的结构性取舍。社区治理亦是形式主义的政治产物——OpenBSD Core Team 对 LibreSSL 维护者（beck、jsing、tb）的 commit 权限安排、对 RETGUARD 架构扩展优先级（amd64/arm64 优先、其他架构延后）的决策，皆是组织内部利益再分配的形式主义化

**史料**：项目史观总纲第 5 条原文（据原文第 25 章 行 9：“5. **没有必然性，只有偶然性**。每一个关键人物、每一次 fork、每一个技术决定，都是不可替代的偶然。替代品的无限性不能否定事物的独特价值。”）；项目史观总纲第 13 条原文（据原文第 25 章 行 17：“13. **法律与道德是利益分配**。任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物。”）；项目史观总纲第 5 章偶然性论述（据原文第 5 章 行 5：“规律具有偶然性，规律是由大大小小的无序物质意识组合而成的偶然条件。世界上没有必然性，只有偶然性。”）；openbsd.duckdb openbsd-src 仓库 LibreSSL/RETGUARD 相关 commit（`af0b15b8442f`、`9eac5592c816`、`b6553af36068`、`e688c2b0648a`）；LibreSSL fork 公告（<https://www.libressl.org/>）；OpenSSL Apache 许可证与 LibreSSL ISC 许可证文本对比〔存疑：2014 年 fork 动机对比应为 OpenSSL/SSLeay 旧许可证（含广告条款），Apache 许可证对比仅适用于 2021 年后，2026-09-14 依核查报告标注〕 ［A］

**史观**：总纲第 5 条——没有必然性，只有偶然性：LibreSSL fork 与 RETGUARD 的诞生皆是对偶然事件的偶然回应，不得以目的论叙事遮蔽偶然性；总纲第 13 条——法律与道德是利益分配：LibreSSL fork 的许可证争议与 RETGUARD 的性能取舍以道德语言包装利益分配，社区治理是形式主义的政治产物
