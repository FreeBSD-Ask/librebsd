# 201.1 与同时期操作系统的比较：OpenBSD 6.x 时代与 pledge/unveil 安全机制时期（2017-2021）——与 FreeBSD 11/12（Capsicum）、Linux 4.x/5.x（seccomp）、Windows 10（AppContainer）、macOS（Sandbox）的对照

## 201.1.1 FreeBSD 11/12（Capsicum，2017-2020）

**要点**：FreeBSD 在 OpenBSD 6.x 同期为 11.x/12.x（2017-2020），以 Capsicum 能力沙箱（自 10 起）与 jail 著称；与 OpenBSD 6.x 的 pledge/unveil 对照——Capsicum 以细粒度能力句柄见长，pledge/unveil 以“声明式最小权限”简洁著称，二者在应用沙箱上殊途同归

**史料**：FreeBSD Capsicum 文档（<https://www.freebsd.org/cgi/man.cgi?query=capsicum>）；FreeBSD 11/12 Release Notes；OpenBSD 6.x pledge/unveil 文档（<https://man.openbsd.org/pledge.2>、<https://man.openbsd.org/unveil.2>）〔L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：FreeBSD Capsicum 与 OpenBSD pledge 同期演进，是 BSD 家族内沙箱路线分化与互鉴的具体显现——Capsicum 以能力句柄提供细粒度资源控制，pledge 以声明式权限类别提供粗粒度系统调用控制

**辨析**：Capsicum 的句柄能力与 pledge 的 syscall 白名单是两种沙箱范式，各适其场景——Capsicum 适用于需要细粒度资源控制的场景（如数据库服务器），pledge 适用于需要快速部署沙箱的场景（如网络服务）

**文献**：FreeBSD Capsicum 文档 [EB/OL]. <https://www.freebsd.org/cgi/man.cgi?query=capsicum>；FreeBSD 11/12 Release Notes；OpenBSD 6.x Release Notes [EB/OL]. <https://www.openbsd.org/plus.html> ［A］

## 201.1.2 Linux 4.x/5.x（seccomp，2017-2021）

**要点**：Linux 在 OpenBSD 6.x 同期以 seccomp（seccomp-bpf）与 SELinux/AppArmor 提供沙箱；与 OpenBSD 6.x 的 pledge/unveil 对照——seccomp 以 BPF 过滤 syscall 见长，pledge 以简洁声明著称，二者在“限制系统调用”思路上各自独立发展（seccomp 早在 Linux 2.6.12 即 2005 年引入、2012 年 Linux 3.5 加入 BPF 过滤模式，pledge 则于 2015 年方引入，时间上 seccomp 早于 pledge 约十年）

**史料**：Linux seccomp 文档（<https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html>）；Linux 4.x/5.x Release Notes；OpenBSD 6.x 文档〔L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：seccomp 的 BPF 灵活与 pledge 的极简声明，是 Linux 与 BSD 沙箱哲学差异的具体显现——Linux 以“灵活性优先”为预设选择 BPF 过滤，OpenBSD 以“可采用性优先”为预设选择声明式权限

**辨析**：pledge 的“一键最小权限”降低采用门槛，seccomp 的表达力更强但复杂——pledge 在 OpenBSD 基本系统中的覆盖率以 openbsd.duckdb commit 计数为准（基本系统主要用户态工具已普遍采用），seccomp 在 Linux 中的覆盖率以各发行版配置为准 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**文献**：Linux seccomp 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/userspace-api/seccomp_filter.html>；OpenBSD 6.x Release Notes [EB/OL]. <https://www.openbsd.org/plus.html> ［B］

## 201.1.3 Windows 10（AppContainer，2017-2021）

**要点**：Microsoft 在 OpenBSD 6.x 同期以 AppContainer（UWP/Edge 沙箱）与 WSL 提供隔离；与 OpenBSD 6.x 的 pledge/unveil 对照——AppContainer 以 SID/令牌隔离见长且闭源，pledge 以开源极简著称，二者目标重叠但机制不同

**史料**：Microsoft AppContainer 文档（<https://learn.microsoft.com/en-us/windows/win32/secauthn/appcontainer-isolation>）〔L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：闭源 AppContainer 与开源 pledge 在 2017-2021 年间是两种不同的安全哲学——前者以“商业机密优先”为预设闭源，后者以“代码可审计为可信来源”为预设开源

**辨析**：AppContainer 与 pledge 均限制应用权限，但闭源使 Windows 沙箱不可审计——AppContainer 的设计文档以 Microsoft 官方文档为准，pledge 的实现以 OpenBSD 源码为准

**文献**：Microsoft AppContainer 文档 [EB/OL]. <https://learn.microsoft.com/en-us/windows/win32/secauthn/appcontainer-isolation>［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ ［B］

## 201.1.4 macOS（Sandbox，2017-2021）

**要点**：Apple macOS 在 OpenBSD 6.x 同期以 Sandbox（基于 TrustedBSD MAC，seatbelt 配置）提供应用隔离；与 OpenBSD 6.x 的 pledge/unveil 对照——macOS Sandbox 源于 Darwin/BSD 谱系，pledge 的极简影响部分沙箱设计，二者共享 BSD 安全传统

**史料**：Apple macOS Sandbox 文档（<https://developer.apple.com/library/archive/documentation/Security/Conceptual/SecureCodingGuide/>）〔L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：macOS Sandbox 承 Darwin/BSD 安全传统，与 OpenBSD pledge 同源异构——二者均源于 BSD 安全哲学，但 macOS Sandbox 以配置文件驱动，pledge 以代码内声明驱动

**辨析**：macOS Sandbox 的 seatbelt 配置复杂，pledge 的极简是其对照参照——macOS Sandbox 以 seatbelt 配置文件定义权限，pledge 以代码内 `pledge()` 调用声明权限，二者采用门槛不同

**文献**：Apple macOS Sandbox 文档 [EB/OL]. <https://developer.apple.com/library/archive/documentation/Security/Conceptual/SecureCodingGuide/>［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ ［B］

## 201.1.5 同期应用沙箱机制总览（2017-2021）

**要点**：2017-2021 应用沙箱：OpenBSD 6.x 的 pledge/unveil 以极简声明引领，FreeBSD Capsicum 以能力句柄深入，Linux seccomp 以 BPF 灵活，Windows AppContainer 与 macOS Sandbox 闭源/半开源；OpenBSD 6.x 的极简沙箱影响行业（如部分思路入 Linux）

**2017-2021 同期应用沙箱机制对比**：

| 项目 | 机制 | 接口形式 | 开源状态 | 采用门槛 |
| --- | --- | --- | --- | --- |
| OpenBSD 6.x | pledge/unveil | 声明式（`pledge()` + `unveil()`） | 开源 | 最低 |
| FreeBSD 11/12 | Capsicum | 能力句柄（`cap_rights_init()`） | 开源 | 中 |
| Linux 4.x/5.x | seccomp | BPF 过滤器 | 开源 | 最高 |
| Windows 10 | AppContainer | SID/令牌隔离 | 闭源 | 中 |
| macOS | Sandbox | seatbelt 配置文件 | 半开源 | 中 |

**史料**：各系统 2017-2021 沙箱史料（OpenBSD pledge/unveil、FreeBSD Capsicum、Linux seccomp、Windows AppContainer、macOS Sandbox 文档）〔L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：OpenBSD pledge 的极简哲学外溢至 Linux 等，是 BSD 安全创新扩散的具体显现——pledge 的“声明式权限”思想被 seccomp 社区讨论，unveil 的“路径级访问限制”被部分 Linux 沙箱借鉴

**辨析**：沙箱“简洁 vs 灵活”是设计权衡——pledge 的采用门槛最低（一行 `pledge()` 调用），seccomp 的表达力最强（BPF 过滤器可定义任意系统调用过滤规则），Capsicum 的粒度最细（能力句柄可绑定至单个文件描述符）；且各方优势互不可替代——seccomp 依托 Linux 生态覆盖面最广，AppContainer 在 Windows 商业环境的集成度最高，macOS Sandbox 对 Apple 平台应用分发生态适配最深，比较应以场景适配为准，不预设单一优劣排序

**文献**：OpenBSD 6.x Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>；各系统沙箱文档 ［B］
