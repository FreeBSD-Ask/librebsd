# 212.5 pf 与 IPFW/iptables/nftables 的防火墙对照

**要点**：OpenBSD pf 由 Daniel Hartmeier（丹尼尔·哈特迈尔） 主导开发，2001 年随 OpenBSD 3.0（2001-12-01 发布）引入——openbsd.duckdb openbsd-src 仓库 commit 148b55c022b1（2001-06-24 kjell 引入 sys/net/pf.c 与 sys/net/pfvar.h）证实代码引入时间早于 3.0 发布约 5 个月；pf 替代因许可证问题被移除的 ipf（deraadt 于 2001-05-30 commit 345de70aec27 删除 sbin/ipf/）；pf 强调状态跟踪（stateful inspection）与简洁语法（如 `pass in on $ext_if proto tcp to any port 22`）；FreeBSD IPFW 由 Ugen J.S. Antsilevich 等维护，自 FreeBSD 2.0 起作为默认防火墙，强调性能与可配置性；Linux iptables（2001 年随 Linux 2.4）后继 nftables（2014 年随 Linux 3.13，统一替代 iptables/ip6tables/arptables/ebtables）；pf 于 2004 年（5.3 周期）移植至 FreeBSD——freebsd.duckdb freebsd-src 仓库记录 Daniel Hartmeier 本人 2004-05-02 至 2007-11-21 期间向 FreeBSD 提交 20 条 commit；NetBSD 自 2.0（2004-12）起集成 pf；OpenBSD 主页声称 pf 是 “the most copied firewall in the world”

**史料**：Daniel Hartmeier 个人 pf 历史文章（<https://www.benzedrine.ch/pf.html>）；OpenBSD 3.0 Release Notes（<https://www.openbsd.org/30.html>）；FreeBSD IPFW 手册页 **ipfw(8)** 与 FreeBSD 5.3 Release Notes pf 移植记录；Linux nftables 项目主页（<https://www.netfilter.org/projects/nftables/>）与 man pages；openbsd.duckdb openbsd-src commit 148b55c022b1（pf.c 首次引入）与 345de70aec27（ipf 删除）；openbsd.duckdb contributors 表 <dhartmei@openbsd.org>（591 commits, 2001-06-24 至 2007-12-02）与 freebsd.duckdb contributors 表 <dhartmei@FreeBSD.org>（20 commits, 2004-05-02 至 2007-11-21）〔L1 代码/构建产物/L3 官方文档与公告/L4 事后叙述〕

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：设计取向挂第 13 条系权宜映射，取 ipf 许可争议迫使 pf 诞生的利益分配语境〕：三种防火墙设计是三种不同取舍——pf 简洁优先（约 30 个规则关键字）、IPFW 性能优先（早期 ipfw 1.x 不含状态跟踪直至 IPFW2）、iptables/nftables 灵活优先（nftables 提供 Turing-complete 规则语言）；总纲第 4 条——分离聚合是永恒规律：pf 从 OpenBSD 分离并向 FreeBSD/NetBSD 聚合，是 BSD 间的代码流动——Hartmeier 本人在 2004-2007 年间向 FreeBSD 主线提交 pf 移植与维护 commit

**辨析**：三者性能对比缺乏权威基准——多数公开基准（Phoronix、Calomel.org）存在配置不等价问题（如未对齐规则数量、状态表大小、conntrack 模块）；FreeBSD 默认仍提供 IPFW/IPF/pf 三选项（编译时选择），NetBSD 自 7.0（2015-09）起 NPF 取代 pf 作为默认防火墙（<https://man.netbsd.org/npf.7>）

**要点**：

- OpenBSD 基金会董事 Ken Westerback 在访谈中阐明该组织的独特形态：它是纯粹的资金管道，不持有 OpenBSD 的商标与知识产权，不出售周边商品，不雇佣也不指挥开发者，只接收社区的资助申请并按可用资金拨款；这与同期将所有权与知识产权注入基金会的其他 BSD 项目基金会形成鲜明对照。（BSD Now EP78，[1584.57-1636.25]，L1）
- hackathon 作为 OpenBSD 的开发制度早于 Westerback 本人加入项目：2001 年在波士顿与 USENIX 年会并行举行的 C2K1 是其参加的首次活动；早期年度大会固定于 Calgary 并常借用 Theo de Raadt 住所举办社交活动，后因场地与吸引新开发者的需要迁往 Edmonton，再因欧洲开发者抱怨跨洋成本改为加拿大与欧洲交替举办（布达佩斯、卢布尔雅那等），并在常规大会之外发展出路由、ports、网络等十余人的专题 mini-hackathon；基金会为此承担场地、住宿乃至关键开发者的差旅。（BSD Now EP78，[1825.61-1985.55]，L1）
- OpenBSD 于 2014 年首次参加 Google 编程之夏，解决一系列 paperwork 问题后获五个项目，其中 Capsicum 移植可行性调查的结论是“不可行”，但基金会仍视其为成功——障碍被识别、测试已完成，负结果本身具有价值；2015 年已再度申请，结果待同年 3 月 2 日公布。（BSD Now EP78，[1998.21-2068.91]，L1）
- Heartbleed 催生的核心基础设施倡议由多家大企业出资，为 OpenSSL 雇佣程序员清理代码，并按 OpenBSD 网络工作的实际开支向基金会定向拨款；Westerback 将 OpenSSH 与 LibreSSL 列为最需要长期投入的核心基础设施，但吸引一名承诺两年以上的专职开发者至今无人签字，暴露出小额捐助模式难以支撑长周期代码整理的结构性困境。（BSD Now EP78，[2101.87-2236.47]，L1）

**史观**：

- 总纲13 法律与道德是利益分配：基金会的治理形态并非源于项目自身的技术意志，而是由捐赠方的利益分配需求塑造：企业无法直接向一位开发者个人汇款，需要纸质凭证与正式法人实体以通过内部财务合规，基金会正是为满足这种会计与法务要求而设；Heartbleed 之后企业资金按领域定向流入开源基础设施，可视为同一分配逻辑在更宏观层面的延伸。（BSD Now EP78，[1473.26-1496.52]，L1）

**辨析**：

- Superfish 事件展示了 SSL 拦截正当性边界由主体身份而非技术本身划定：预装自签根证书、在用户浏览器信任链内伪造站点证书并注入广告，在消费产品上属恶意行为；同样的中间人架构置于企业网络边缘并取得员工知情同意，则可能是合法的内容审查，relayd 的证书拼接功能正以企业部署为设计前提，并提醒各国对未告知监控的法律限制不同。　[存疑脚注] 转写将 Reyk Floeter 失真作“rake floiter”、OPNsense 失真作“OpenSense”、LibreSSL 失真作“Libra SSL”，引用时须以原始博文与发布公告为准。（BSD Now EP78，[649.11-838.61]，L2）
- PC-BSD 将默认防火墙由 PF 切向 IPFW 的决策链条中，主持人转述 Luigi Rizzo 曾重写 IPFW 使其大幅提速，并与 vimage jail 兼容性（PF 搭配 vimage 曾长期导致内核恐慌）、显式规则号、免重编译内核的模块化加载等理由并列；但“Luigi 重写 IPFW”所指的具体版本与年代在节目中未展开，且该说法仅系主持人单一回忆，引用前须回查 FreeBSD 源码提交记录与当时基准测试。　[存疑脚注] “Luigi 重写 IPFW”版本与年代未经节目中其他信息确证；转写亦存在人名与项目名失真，涉及专名处以 FreeBSD 源码与原始发布为准。（BSD Now EP78，[2884.13-2960.21]，L4）
