# 206.5 OpenSSH 对全球远程管理安全的广泛影响

**要点**：OpenSSH 取代了不安全的 telnet/rsh/rlogin 等明文远程管理协议，成为互联网基础设施的关键组件；OpenSSH 安全漏洞影响全球系统——CVE-2016-0777（2016-01-14 披露）是 OpenSSH 客户端 5.4 至 7.1 版本中未公开说明的 roaming 功能导致的信息泄露漏洞，攻击者可构造恶意 SSH 服务器窃取客户端内存中的私钥，伴随 CVE-2016-0778（roaming_common.c 堆缓冲区溢出）；CVE-2024-6387（regreSSHion，2024-07-01 披露）是 OpenSSH 服务端 sshd 信号处理程序竞争条件远程代码执行漏洞，影响基于 glibc 的 Linux 系统（OpenBSD 因使用 pledge 限制信号处理程序行为而不受影响）；Niels Provos（尼尔斯·普罗沃斯） 编写的 scanssh 工具（<https://www.monkey.org/~provos/scanssh/>）用于扫描 SSH 服务器版本与协议支持，为 SSH 部署统计提供工具基础

**史料**：CVE-2016-0777 漏洞公告（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2016-0777>，2016-01-14 披露，影响 OpenSSH 客户端 5.4-7.1）；CVE-2016-0778 漏洞公告（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2016-0778>，roaming_common.c 堆缓冲区溢出）；CVE-2024-6387 漏洞公告（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2024-6387>，2024-07-01 披露，regreSSHion）；OpenSSH Security Advisories（<https://www.openssh.com/security.html>）；Qualys CVE-2016-0777 技术分析（<https://www.qualys.com/2016/01/14/cve-2016-0777-cve-2016-0778/openssh-cve-2016-0777-cve-2016-0778.txt>）；scanssh 工具（<https://www.monkey.org/~provos/scanssh/>）〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 10 条——边缘者贡献：OpenSSH 从 OpenBSD 这一边缘项目扩散至全球基础设施——2024 年 CVE-2024-6387 披露时全球基于 glibc 的 Linux 系统上的 sshd 均受影响，这一影响范围表明 OpenSSH 已成为互联网远程管理事实标准；总纲第 25 条——0 信任原则：CVE-2024-6387 中 OpenBSD 因 pledge 机制限制 sshd 信号处理程序行为而不受影响，是 0 信任原则在安全实践中的回报——OpenBSD 自身的安全机制（pledge）在其产出的工具（OpenSSH）遭遇漏洞时提供了额外防护层

**辨析**：CVE-2016-0777 与 CVE-2016-0778 均源于 OpenSSH 客户端 roaming 功能（未公开说明的功能，5.4 引入、7.1 仍存在），2016-01-14 由 Qualys 披露，影响范围覆盖 OpenSSH 客户端 5.4 至 7.1（约 2010-2016 年间的所有版本）；CVE-2024-6387（regreSSHion）影响范围限于基于 glibc 的 Linux 系统上的 sshd，OpenBSD 与 FreeBSD 因不使用 glibc 或使用 pledge 而不受影响或影响有限——漏洞技术细节为 sshd 在接收到客户端连接后信号处理程序与定时器交互存在竞争条件，可被远程攻击者利用实现未认证远程代码执行；OpenSSH 全球部署规模的具体统计数据口径不一——Shodan 等互联网扫描平台显示 SSH 端口 22 在 IPv4 地址上的占比持续高于 80%，但该统计包含所有 SSH 实现（OpenSSH、Dropbear、商业 SSH 等），OpenSSH 在类 Unix 系统中的市场份额据各发行版包管理器统计占绝对主导 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
