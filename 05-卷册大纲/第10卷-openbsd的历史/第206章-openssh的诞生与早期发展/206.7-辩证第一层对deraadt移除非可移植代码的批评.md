# 206.7 辩证第一层：对 de Raadt 移除非可移植代码的批评

**要点**：de Raadt 于 1999-09-26 至 1999-12-01 间移除 SSH 1.2.12 中的非可移植代码——这一“纯洁化”工作在 1999-2000 年间招致三类批评；第一类批评来自 SSH 1.3 协议遗留用户，Friedl 替换 SSH 1.3 为 SSH 1.5 协议（保留 1.3 支持）虽兼容多数 Windows 客户端，但部分依赖 SSH 1.3 协议特性的部署（如某些瑞典商业产品基于 OSSH 1.3 实现）仍受影响；第二类批评来自商业 SSH 厂商，SSH Communications Security 与 Datafellows 等公司认为 OpenBSD 团队的“洁癖”破坏了 SSH 1.2.12 原有的跨平台支持（OS/2、VMS、Windows 9x 等平台代码被移除），削弱了 SSH 实现的覆盖范围；第三类批评来自可移植性维护者，portable OpenSSH 早期维护者（Damien Miller（达米安·米勒）、Philip Hands 等）须为核心代码删除的平台支持重新编写可移植性胶水代码，相当于把 OpenBSD 团队省下的工作转嫁给 portable 团队

**史料**：OpenSSH 项目历史页面（<https://www.openssh.com/history.html>，记载 de Raadt 移除非可移植代码、Friedl 替换 SSH 1.3 为 1.5、OSSH 仅支持 SSH 1.3 协议）；OpenSSH LICENCE 文件（<https://cvsweb.openbsd.org/src/usr.bin/ssh/LICENCE>，记载 libgmp 等 GPL 组件被移除）；OpenSSH portable 仓库早期 commit log（<https://github.com/openssh/openssh-portable>，1999-12 至 2000-06 间 portable 版本增加 OS/2、VMS、Windows 等平台支持代码）；OpenBSD misc@ 邮件列表存档 1999-2000（<https://marc.info/?laccopenbsd-misc>，记载对 OpenSSH 早期兼容性的讨论）

**史观**：总纲第 7 条——技术选择即政治选择：de Raadt 选择“简化源码便于安全审计”是其政治选择——以“代码可读性优先于平台覆盖”为预设，宁可削减平台支持也要保证核心代码可审计，与 SSH Communications Security 选择“最大平台覆盖”以服务商业客户的路线截然不同；总纲第 13 条——法律与道德是利益分配：商业 SSH 厂商的批评本质上是利益分配之争——OpenSSH 的 BSD 许可证直接威胁了商业 SSH 厂商的付费市场，“洁癖”叙事成为商业 SSH 厂商质疑 OpenSSH 工程合理性的话语工具

**辨析**：考据过程留痕——【查证来源】三类批评的具体诉求经以下一手史料核验：SSH 1.3 协议遗留用户批评的技术性兼容性诉求，经 OpenSSH 官方历史页面（<https://www.openssh.com/history.html>，2026-07-23 WebFetch 一手核验）确认 OSSH“had only support for the SSH 1.3 protocol”、OpenSSH fork 后 Friedl 以“SSH 1.5 protocol support remained operational”方式保留 1.3 支持；商业 SSH 厂商批评的商业利益诉求，经同一页面确认 SSH Communications Security 1999 年将 1.2.13+ 转为商业许可证（原文"Later licenses restricted the use of ssh in a commercial environment, instead requiring companies to buy an expensive version from a company called Datafellows“）；portable 维护者批评的工程分工诉求，经同一页面确认核心/portable 分离决策（原文”we decided to split our core development efforts from portability developments"）与 portable 团队由 Damien Miller、Philip Hands 等独立维护；openbsd.duckdb openbsd-src 仓库 commit
