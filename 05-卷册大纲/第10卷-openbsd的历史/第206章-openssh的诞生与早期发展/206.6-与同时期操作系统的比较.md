# 206.6 与同时期操作系统的比较

**要点**：同期其他 SSH 实现各有定位——Lsh（GNU 项目，Niels Möller 主导，GPLv2）仅实现 SSH 2 协议，因实现复杂度高、社区规模小、无 SSH 1 兼容性而未被主流发行版采纳；PuTTY（Simon Tatham 主导，MIT 许可）专注 Windows 客户端，无服务端实现，填补了 Windows 平台 SSH 客户端空白但不与 OpenSSH 服务端构成竞争；Dropbear（Matt Johnston 主导，MIT 许可）面向嵌入式系统与小内存设备，代码量约为 OpenSSH 的 1/10，在路由器、嵌入式 Linux 中广泛部署但功能精简；SSH Communications Security 商业版本（Tatu Ylönen 的公司）因 OpenSSH 免费提供同等功能而逐步退出主流市场，2000 年后转向企业级特权访问管理（PAM）领域；OpenSSH 在许可证（BSD，允许商业使用无需付费）、安全性（继承 OpenBSD 审计文化，privilege separation 架构由 Provos 2001 年设计）、可移植性（portable 版本支持 Linux/Solaris/AIX/HP-UX 等）三方面均优于同期实现——BSD 许可证使 FreeBSD/NetBSD/macOS 可直接集成入基础系统，privilege separation 架构将 sshd 拆分为特权与无特权进程降低提权风险，portable 版本由 Damien Miller（达米安·米勒） 长期维护覆盖 10+ 操作系统

**史料**：Lsh 项目主页（<https://www.lysator.liu.se/~nisse/lsh/>，GNU 项目 SSH 2 实现）；PuTTY 项目主页（<https://www.chiark.greenend.org.uk/~sgtatham/putty/>，Simon Tatham 维护，MIT 许可）；Dropbear 项目主页（<https://matt.ucc.asn.au/dropbear/dropbear.html>，Matt Johnston 维护，面向嵌入式）；SSH Communications Security 商业产品（<https://www.ssh.com/>，Tatu Ylönen 创立）；OpenSSH privilege separation 设计文档（Provos 2001 年设计，2002-03-14 至 2002-03-18 系列 commit 实现于 OpenSSH）〔L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：Lsh 选择 GPLv2 与仅 SSH 2 协议是其政治选择——以“协议纯洁性”为预设，宁可放弃 SSH 1 兼容性也不维护遗留协议，但这一选择导致 Lsh 无法兼容当时仍广泛部署的 SSH 1 客户端/服务端，社区规模因此受限；PuTTY 选择 MIT 许可与 Windows-only 是其政治选择——以“填补 Windows 平台空白”为预设，专注客户端而非全栈实现；OpenSSH 选择 BSD 许可与双协议支持（SSH 1+2 至 2017 年）是其政治选择——以“最大兼容性 + 自由许可”为预设，既兼容遗留又允许商业使用；总纲第 12 条——法律结构：OpenSSH 的 BSD 许可证允许各发行版自由集成无需付费，Lsh 的 GPLv2 要求衍生作品同样开源，SSH Communications Security 的商业许可证要求付费——三种许可证结构直接塑造了各实现的市场命运

**辨析**：各 SSH 实现的功能对比——OpenSSH 提供完整客户端 + 服务端+SFTP+ 密钥管理工具链，Lsh 提供客户端 + 服务端但无 SFTP 子协议的早期版本，PuTTY 仅提供 Windows 客户端+PSFTP+ 密钥工具，Dropbear 提供轻量客户端 + 服务端但无 SFTP 独立工具；OpenSSH 相对其他实现的优势具体表现为三方面——许可证优势（BSD 允许 FreeBSD/NetBSD/macOS/iOS 等系统直接集成入基础系统，Lsh 的 GPLv2 阻止了这一点），安全性优势（OpenBSD 审计文化产出的代码质量经多次 CVE 验证为同行最高水平之一，privilege separation 架构将 sshd 拆分为特权与无特权进程降低提权风险），可移植性优势（portable OpenSSH 由 Damien Miller 长期维护，支持 10+ 操作系统，Lsh 与 Dropbear 的可移植性范围较窄）；“事后叙事化”风险——OpenSSH 的主导地位并非预先设计，2000 年时 Lsh、PuTTY、商业 SSH 均有各自市场，OpenSSH 的胜出是 BSD 许可证（允许各系统自由集成）、OpenBSD 审计文化（代码质量经得起 scrutiny）、portable 维护（Damien Miller 持续投入）三因素叠加的结果

**文献**：Lsh 项目 [EB/OL]. <https://www.lysator.liu.se/~nisse/lsh/>；PuTTY 项目 [EB/OL]. <https://www.chiark.greenend.org.uk/~sgtatham/putty/>；Dropbear 项目 [EB/OL]. <https://matt.ucc.asn.au/dropbear/dropbear.html>；SSH Communications Security 商业产品 [EB/OL]. <https://www.ssh.com/>；OpenSSH privilege separation 设计 [EB/OL]. <https://www.openssh.com/txt/privsep-provos.c> ［A］

**同期 SSH 实现对比**：

| 实现 | 主导者 | 许可证 | 协议支持 | 平台覆盖 | 市场定位 |
| --- | --- | --- | --- | --- | --- |
| OpenSSH | OpenBSD 团队 | BSD | SSH 1+2（至 2017）→ 仅 SSH 2 | 10+ 操作系统（portable） | 全栈客户端 + 服务端+SFTP |
| Lsh | Niels Möller（GNU） | GPLv2 | 仅 SSH 2 | Linux/Unix | 客户端 + 服务端，未主流采纳 |
| PuTTY | Simon Tatham | MIT | SSH 1+2 | Windows-only | 客户端+PSFTP，填补 Windows 空白 |
| Dropbear | Matt Johnston | MIT | SSH 2 | 嵌入式/Linux | 轻量客户端 + 服务端，代码量约 OpenSSH 1/10 |
| 商业 SSH | Tatu Ylönen（SSH Communications Security） | 商业 | SSH 1+2 | 多平台 | 2000 年后转向企业级 PAM |
