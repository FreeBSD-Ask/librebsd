# 206.8 辩证第二层：OpenBSD 阵营的反批评

**要点**：OpenBSD 阵营对第一层批评的反驳可归纳为三点；第一，de Raadt 在 OpenSSH 官方历史页面明确说明移除非可移植代码的目的——“the goal being simpler source code, so that security holes and other issues could be spotted easier”（简化源码，使安全漏洞与其他问题更易被发现），这不是“洁癖”而是审计文化的工程必要——代码可读性是安全审计的前提，非可移植代码（如平台特定的 workaround、过时的 OS/2 与 VMS 支持）会遮蔽安全漏洞；第二，Friedl 替换 SSH 1.3 为 SSH 1.5 协议时“以兼容仅支持 SSH 1.5 的 Windows 客户端”为决策依据，且“SSH 1.3 protocol support remained operational”——即 1.3 支持被保留而非完全删除，第一类批评夸大了兼容性损失；第三，核心/portable 分离是 OpenBSD 团队有意为之的工程政治选择，官方历史页面明确记载——“we decided to split our core development efforts from portability developments”，目的是避免可移植性包袱污染核心代码，portable 团队承担额外工作是这一架构的必然代价而非 OpenBSD 团队的责任转嫁

**史料**：OpenSSH 项目历史页面（<https://www.openssh.com/history.html>，明确记载移除非可移植代码的目的、SSH 1.3 与 1.5 并存决策、核心/portable 分离决策）；OpenBSD misc@ 邮件列表存档 1999-2000（<https://marc.info/?l=openbsd-misc>，记载 de Raadt、Provos 等对批评的回应）；OpenSSH portable 仓库早期 commit log（<https://github.com/openssh/openssh-portable>，证实 portable 团队由 Damien Miller（达米安·米勒）、Philip Hands 等独立维护）

**史观**：总纲第 8 条——社区文化即技术资产：OpenBSD 阵营的反批评揭示审计文化作为社区资产的具体运作方式——代码可读性被预设为安全性的前提，移除非可移植代码不是“洁癖”而是审计文化的物化；专题语（不设条号）——0 信任原则：de Raadt 移除非可移植代码是 0 信任原则在工程层面的实践——非可移植代码本身被视为不可信（因遮蔽安全漏洞），无论其覆盖多少平台都不保留；总纲第 9 条——经验优先：OpenBSD 阵营的反批评优先呈现当事人的直接经验（de Raadt、Provos、Friedl 等的具体工作），而非套用商业 SSH 厂商的“市场覆盖”框架

**辨析**：考据过程留痕——【查证来源】OpenBSD 阵营反批评的三点论据经以下一手史料核验：第一点（de Raadt 移除非可移植代码的目的），经 OpenSSH 官方历史页面（<https://www.openssh.com/history.html>，2026-07-23 WebFetch 一手核验）确认原文“Theo de Raadt（西奥·德·若特） (CANADA) started by removing non-portabilities which made the code harder to read — the goal being simpler source code, so that security holes and other issues could be spotted easier”；第二点（Friedl 保留 SSH 1.3 支持），经同一页面确认原文“He added SSH 1.5 protocol support in such a way that SSH 1.3 protocol support remained operational”，且经 openbsd.duckdb openbsd-src 仓库 commit `33fe18e4e13b`（markus，1999-10-14T18:17:41Z，message_subject 节选“fix old connect() race security-bug for ssh-agent and agent-forwarding by removing the connect() junk, with the following restrictions: 1) change the version to“OpenSSH-1.1””）验证 Friedl 在 fork 早期即活跃贡献；第三点（核心/portable 分离决策），经同一页面确认原文“we decided to split our core development efforts from portability developments. This has worked out very well for us. (As a case in point, compare the number of lines of code between the baseline and portable versions)”；【交叉验证方法】OpenSSH 官方历史页面（一手，OpenBSD 团队自述）与 OpenSSH portable 仓库（<https://github.com/openssh/openssh-portable>，代码级证据）双向互证——portable 仓库由 Damien Miller、Philip Hands 等独立维护的 commit log 证实核心/portable 分离的工程架构属实，与官方历史页面记载一致；Friedl 保留 SSH 1.3 支持的论据经 OpenSSH **LICENCE** 文件（<https://cvsweb.openbsd.org/src/usr.bin/ssh/LICENCE>）与 commit `33fe18e4e13b` 互证，但须注意 `33fe18e4e13b` 的 message_subject 主要记载的是 ssh-agent 竞争条件修复而非 SSH 1.3 保留本身，SSH 1.3 保留的代码级证据须以协议实现文件（如 ssh1.c 或 compat.c）的 commit 历史补全；【存疑判定依据】0 信任原则提示：OpenSSH 官方历史页面作为 OpenBSD 团队自述存在自利偏差风险，三点论据须与独立来源交叉验证——第一点（移除非可移植代码的目的是“便于审计”）是当事人自辩，［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；第二点论据成立——SSH 1.3 支持确实被保留，第一类批评夸大兼容性损失的判定经官方历史页面原文证实；第三点反驳（“portable 团队承担额外工作是必然代价”）存在循环论证风险——核心/portable 分离架构本身是 OpenBSD 团队的决策，将该决策的代价归为“必然”而非“OpenBSD 团队选择”是话语策略，92.9 节将展开对这一循环论证的再批评
