# 206.10 辩证第四层：合图

**要点**：四层辩证在 OpenSSH 长期演进中达成合图——核心/portable 分离架构最终被证明是成功的工程决策，portable OpenSSH 由 Damien Miller（达米安·米勒） 长期维护覆盖 10+ 操作系统，至 2010 年代 portable 版本与核心版本的差距已显著缩小；OpenSSH 7.4（2016-12-19）移除服务端 SSH1、7.6（2017-10-03）完全删除 SSH1 协议支持，证明 OpenBSD 团队“简化优先”路线在长期是正确的——SSH1 协议本身的安全缺陷（插入攻击等结构性漏洞）最终被全行业放弃；OpenSSH 7.0（2015-08）将默认拒绝旧 DSA 密钥、弃用 SSH-RSA 算法预告，进一步印证审计文化的预防性价值；2000-2024 年间 OpenSSH 安全记录优于同期商业 SSH 与 Lsh 等实现（该比较缺乏同行评审研究，详见辨析），privilege separation 架构（Provos 2001 年设计）与 pledge 沙箱机制（2015 年引入）系两项不同机制，在 CVE-2024-6387（regreSSHion）中 OpenBSD 因 pledge 机制不受影响，该结果与 privilege separation 架构的作用须分别评估——这一系列事实既验证了 OpenBSD 阵营的审计文化论点，也部分回应了再批评对 portable 版本早期问题的关切；合图并非“OpenBSD 全胜”——核心/portable 分离的工程代价确实由 portable 团队与下游发行版承担，但这一代价在 OpenSSH 成为事实标准后被行业消化

**史料**：OpenSSH 7.4 Release Notes（<https://www.openssh.com/txt/release-7.4>）；OpenSSH 7.6 Release Notes（<https://www.openssh.com/txt/release-7.6>）；OpenSSH 7.0 Release Notes（<https://www.openssh.com/txt/release-7.0>，记载 DSA 默认拒绝与 SSH-RSA 弃用预告）；CVE-2024-6387 漏洞公告（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2024-6387>，OpenBSD 因 pledge 不受影响）；OpenSSH portable 仓库（<https://github.com/openssh/openssh-portable>，Damien Miller 长期维护记录）；openbsd.duckdb openbsd-src 仓库 commit 3d9665d37aa5（2016-08-13 markus“remove ssh1 server code”）、commit 6c99a5ed578d（2017-04-30 djm“remove SSH1 make flag and associated files”）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 6 条——和解优于斗争：合图不是“OpenBSD 胜利”而是各方立场在长期演进中的和解——OpenBSD 阵营的审计文化论点被 SSH1 移除等事实部分验证，portable 团队的工程代价被行业消化，商业 SSH 厂商的市场份额虽被 OpenBSD 取代但其企业级 PAM 领域仍存；总纲第 4 条——分离聚合是永恒规律：OpenSSH 从 SSH 1.2.12 分离后聚合入 OpenBSD 源码树，再从 OpenBSD 聚合入 FreeBSD、NetBSD、Linux 各发行版——分离与聚合的循环是 OpenSSH 全球扩散的根本结构；总纲第 21 条——革命与改革是历史方法论的分歧：OpenSSH 的 fork 是革命路线（彻底移除非可移植代码），商业 SSH 厂商的渐进改良是改革路线，二者在长期演进中并非“一方胜利”而是各自主体的呈现与和解

**辨析**：考据过程留痕——【查证来源】合图“成功”判定的各项事实经以下一手史料核验：SSH1 移除时间线，经 OpenSSH 7.4 Release Notes（<https://www.openssh.com/txt/release-7.4>，2026-07-23 WebFetch 一手核验）确认原文“This release removes server support for the SSH v.1 protocol”，经 OpenSSH 7.6 Release Notes（<https://www.openssh.com/txt/release-7.6>，2026-07-23 WebFetch 一手核验）确认原文"ssh(1): delete SSH protocol version 1 support, associated configuration options and documentation"，并经 openbsd.duckdb openbsd-src 仓库 commit `3d9665d37aa5`（markus，2016-08-13T17:47:40Z，message_subject“remove ssh1 server code; ok djm@”）与 commit `6c99a5ed578d`（djm，2017-04-30T23:17:37Z，message_subject“remove SSH1 make flag and associated files ok markus@”）SQL 查询验证真实存在，三方互证；CVE-2024-6387 中 OpenBSD 因 pledge 不受影响，经 CVE-2024-6387 漏洞公告（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2024-6387>）与 OpenBSD pledge 机制公开文档互证；OpenSSH 7.0 DSA 默认拒绝与 SSH-RSA 弃用预告，参照第 16 章 16.10 节史料字段已引用的 OpenSSH 7.0 Release Notes（<https://www.openssh.com/txt/release-7.0>，本次考据未单独 WebFetch 该页面，沿用第 92 章 92.4 节已核验的 OpenSSH Release Notes 系列页面访问路径）

【交叉验证方法】OpenSSH 7.4/7.6 Release Notes（一手，OpenBSD 团队发布）与 openbsd.duckdb openbsd-src 仓库 commits 表（代码级证据）双向互证——7.4 Release Notes 记载的服务端 SSH1 移除与 commit `3d9665d37aa5` 的 message_subject“remove ssh1 server code”在时序与内容上一致（commit 日期 2016-08-13 早于 release 日期 2016-12-19 约 4 个月，符合 commit 后经测试再 release 的常规节奏），7.6 Release Notes 记载的客户端 SSH1 完全删除与 commit `6c99a5ed578d` 的 message_subject“remove SSH1 make flag and associated files”在时序与内容上一致（commit 日期 2017-04-30 早于 release 日期 2017-10-03 约 5 个月）；合图“成功”判定须避免事后叙事化——OpenSSH 在 2000 年时的胜出并非预先设计，BSD 许可证、审计文化、portable 维护三因素叠加才使其在 2010 年代成为事实标准；SSH1 移除（2016-2017）虽印证 OpenBSD 路线，但移除时 SSH1 全球部署率已降至极低水平，实际切断的遗留用户规模有限——这一事实既支持“简化优先”的工程论点，也削弱了“OpenSSH 移除 SSH1 是大胆革命”的话语强度
