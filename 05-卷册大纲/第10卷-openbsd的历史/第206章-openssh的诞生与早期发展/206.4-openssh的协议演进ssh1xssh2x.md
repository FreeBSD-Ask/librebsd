# 206.4 OpenSSH 的协议演进（SSH 1.x → SSH 2.x）

**要点**：Markus Friedl（马库斯·弗里德尔） 在 OpenBSD 2.6 发布后独立实现 SSH 2 协议支持，OpenSSH 2.0（commit 81c34fa6419b，2000-04-26 markus“OpenSSH-2.0”）首次支持 SSH 2.x 协议，随 OpenBSD 2.7 于 2000-06-15 发布——OpenSSH 2.0 单一软件同时支持 SSH 1 与 SSH 2 协议；SSH 2.x 协议基于 IETF RFC 4250-4256，采用 DH 密钥交换与 DSA/RSA 签名，架构比 SSH 1.x 更安全；OpenSSH 7.4（2016-12-19）移除服务端 SSH v.1 协议支持（openbsd.duckdb commit 3d9665d37aa5，2016-08-13 markus“remove ssh1 server code”），并在发布声明中预告“约 2017 年 8 月移除剩余 SSH v.1 协议支持（仅客户端，当前编译时禁用）”；OpenSSH 7.6（2017-10-03）完全删除 SSH 协议版本 1 支持（客户端代码、配置选项、文档一并删除，openbsd.duckdb commit 6c99a5ed578d，2017-04-30 djm“remove SSH1 make flag and associated files”），SSH 1.x 协议自此从 OpenSSH 代码库彻底移除

**史料**：openbsd.duckdb openbsd-src 仓库 commit 81c34fa6419b（2000-04-26 markus“OpenSSH-2.0”）、commit 3d9665d37aa5（2016-08-13 markus“remove ssh1 server code”）、commit 6c99a5ed578d（2017-04-30 djm“remove SSH1 make flag and associated files”）；OpenSSH 7.4 Release Notes（<https://www.openssh.com/txt/release-7.4>，记载“This release removes server support for the SSH v.1 protocol”与未来弃用预告）；OpenSSH 7.6 Release Notes（<https://www.openssh.com/txt/release-7.6>，记载"ssh(1): delete SSH protocol version 1 support, associated configuration options and documentation"）；IETF RFC 4251（SSH 协议架构）、RFC 4253（SSH 传输层协议）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：OpenSSH 7.4（2016-12）移除服务端 SSH1、7.6（2017-10）完全删除 SSH1 是以“安全性优先于兼容性”为预设的政治选择——宁可切断与遗留 SSH1 客户端的互操作也要消除协议本身的安全缺陷（SSH1 协议设计存在插入攻击等结构性漏洞），与商业 SSH 实现长期维持 SSH1 兼容以保留遗留用户的路线截然不同；总纲第 25 条——0 信任原则：OpenSSH 移除 SSH1 是 0 信任原则在协议层面的实践——SSH1 协议本身被视为不可信，无论遗留用户规模多大都不保留

**辨析**：SSH1 移除时间线经 OpenSSH 官方 Release Notes 与 openbsd.duckdb 双重核实——7.4（2016-12-19）移除服务端 SSH1，7.6（2017-10-03）完全删除客户端 SSH1（含配置选项与文档），部分二手资料将“OpenSSH 8.2（2020-02-14）”误记为 SSH1 移除版本，但 8.2 Release Notes 实际记载的是 FIDO/U2F 支持（ecdsa-sk、ed25519-sk 公钥类型）与 ssh-rsa 算法弃用预告，与 SSH1 移除无关；SSH 2.x 协议的实现差异——OpenSSH 2.0（2000-04-26）至 2.3.0（2000-11）间逐步完善 SSH 2.x 协议实现，SFTP 子协议服务端由 Friedl 在 2.3.0（2000-11）实现，SFTP 客户端由 Damien Miller（达米安·米勒） 在 2.5.0 实现

**要点**：

- Rod Grimes 自述 1970 年代初在 Oregon Museum of Science and Industry 的 PDP-11/45 上，利用夜间时段重新引导系统运行早期 AT&T Research Unix，白天机器则运行博物馆业务用的分时系统，并使用 Tektronix 4000 系列图形终端。（BSD Now EP172，[1331.76-1442.94]，L1）
- FreeBSD 创建时期，Rod Grimes 主要用 386BSD 做 SLIP 路由器以避开拨号 BBS 的 shell 上网方式，并借此获取 SPICE 等电子工程软件，时间约为 1992 年。（BSD Now EP172，[1487.16-1557.9]，L1）
- Rod Grimes 用 dd 反复读取坏块做磁盘数据恢复，指出 FreeBSD 在 ATA 或 SCSI 设备被卡住时不像其他系统那样锁死，因此长期用于路由器、LAMP 服务器与批量邮件系统。（BSD Now EP172，[1600.96-1667.48]，L1）
- FreeBSD 创始团队并未以竞争产品心态出发，只是出于必要与愿望；当时担心的并非被击垮，而是与 386BSD、BSDI、NetBSD 的关系，Linux 仅被视为另一份开源软件。（BSD Now EP172，[1807.66-1906.68]，L1）
- Rod Grimes 自认不适合仁慈独裁者角色，因自己观点强硬且无法掌握操作系统全部细节，并认为独裁模式长期会分裂团队，FreeBSD 实际采用接近 CSRG 伯克利团队的合作模式。（BSD Now EP172，[1900.99-2003.26]，L1）
- Rod Grimes 认为 FreeBSD 做得正确的包括系统性能、网络栈、ports collection，以及开源带来的可观察性，使系统状态易于查看。（BSD Now EP172，[2184.6-2295.72]，L1）
- Rod Grimes 认为项目早期过度锁定 x86 架构，使后来支持 MIPS 与 ARM 更困难；同时宣传不足，FreeBSD 虽很早运行于 Raspberry Pi 3，但快照未公开、网络与图形缺失，削弱了在 ARM64 嵌入式市场的影响。（BSD Now EP172，[2303.2-2494.7]，L1）
- Rod Grimes 希望 2017 年推进 GPL 代码移除（GPL clean release 为 12.0 目标）、ARM 与 MIPS 升至 Tier 1，并推进 bhyve 的 hypervisor 能力与 GPU passthrough。（BSD Now EP172，[2640.04-2725.56]，L1）
- Rod Grimes 与 Michael Dexter 合作推进 bhyve GPU passthrough，已能在 bhyve 内看到 PCI GPU 设备的 probe 与 I/O 映射，但内存块尚缺失，预期 2017 年初可见工作原型。（BSD Now EP172，[2726.62-2836.32]，L1）
- OpenSSH 7.4 由 Damien Miller 发起公开测试，移除 SSH v1 服务器支持与 3DES-CBC 默认密码，禁用预认证压缩与 UseLogin，并新增受 PuTTY 启发的 proxy multiplexing 与 curve25519-sha256 密钥交换。（BSD Now EP172，[94.39-364.48]，L2）
- Ingo Schwarze 在 Toulouse 的 LibreSSL hackathon 中完成 libcrypto 剩余 130 页手册的 pod2mdoc 转换，使全部文档可用 mdoc 检索，并回顾了 2014 年以来 Anthony Bentley 等人的转换史。（BSD Now EP172，[3495.94-3681.4]，L2）
- Matthew Garrett 批评 Canonical 的 IP 政策：若按政策理解，分发基于 Ubuntu 的作品即使不称 Ubuntu 也可能需向 Canonical 付费，这超出商标保护范围，故 Ubuntu 不是自由软件。（BSD Now EP172，[3872.04-4203.14]，L2）
- DEMOS 是 1982 年诞生于莫斯科原子能研究所的 Unix 类操作系统，源自 MNOS 对 Unix v6 的克隆，1986 至 1990 年各版本合并为 DEMOS 2，运行于 SM4、SM1600 及 VAX 克隆与 Motorola 6820 微机，后转向 Relcom。（BSD Now EP172，[4550.66-4645.46]，L2）
