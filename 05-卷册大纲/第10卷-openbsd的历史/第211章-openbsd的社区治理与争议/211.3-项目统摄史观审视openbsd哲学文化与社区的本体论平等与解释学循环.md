# 211.3 项目统摄史观审视——OpenBSD 哲学文化与社区的本体论平等与解释学循环

## 211.3.1 偶然性视角下的 de Raadt 主导与 OpenBSD 哲学文化形态

**要点**：从项目史观总纲第 5 条“没有必然性，只有偶然性”审视，OpenBSD 哲学文化与社区的具体形态是偶然性的产物——de Raadt 1994 年被 NetBSD Core Team 疏远本身即是一个具体的人的具体决定（Adam Glass（亚当·格拉斯） 1994-12-23 通知邮件），但这一具体决定直接催生 OpenBSD 项目；de Raadt 在 OpenBSD 中建立的 BDFL 治理模式并非预先设计，而是其在 NetBSD Core Team 冲突中形成的个人经验（“被委员会制排斥”的反向投射）的偶然产物——若 de Raadt 未被 NetBSD 疏远，OpenBSD 项目与 BDFL 模式均不会出现，哲学文化将以 NetBSD Core Team 模式延续；“安全至上”哲学的具体形态亦是偶然性产物——OpenBSD 选择“默认安全”而非“功能优先”是 de Raadt 个人对 NetBSD 代码审计不足的反向投射，这一选择在 1995 年 fork 时并非必然，而是 de Raadt 个人经验与工程判断的偶然汇合；排外性文化的具体形态同样是偶然性产物——misc@ 邮件列表的“RTFM”传统与 de Raadt 个人风格直接相关，若 OpenBSD 由风格温和的领导者主导，邮件列表文化将呈现不同形态；商业支持缺位亦是偶然性产物——2003 年 DARPA 撤资事件（约 230 万 USD 资助被撤销）是偶然事件，但这一事件直接塑造 OpenBSD 转向社区募捐模式的资金结构

**史观**：总纲第 5 条——没有必然性，只有偶然性：de Raadt 个人偏好与历史经验直接塑造 OpenBSD 哲学文化与社区形态，单一领导者的人格与判断偶然地决定了项目的治理结构、工程哲学、文化氛围与资金模式

## 211.3.2 本体论平等视角下的 BDFL 模式、Core Team 选举制与 Foundation 董事会治理

**要点**：从项目史观总纲第 8 条“本体论上各方平等”审视，OpenBSD BDFL 模式、FreeBSD Core Team 选举制、NetBSD Foundation 董事会治理在本体论上地位相等，三者皆是 BSD 治理结构的一刻状态，差异是工程哲学的不同而非本体等级的高下——BDFL 以“个人权威优先”为预设，Core Team 选举制以“集体审议优先”为预设，Foundation 董事会治理以“法律合规优先”为预设；“安全至上”哲学与 FreeBSD 的“性能与功能平衡”哲学、Linux 的“快速迭代”哲学在本体论上地位相等，三者皆是工程哲学的一刻状态，差异是工程目标的不同而非本体等级的高下；OpenBSD 阵营（de Raadt、Beck、Friedl、Schwarze、Lindqvist 等）与批评者阵营（被疏远贡献者、外部观察者、FreeBSD/NetBSD/Linux 社区）在本体论上地位相等，二者的叙事须对称呈现；OpenBSD 的 pledge/unveil 路线、FreeBSD 的 Jails+Capsicum 路线、Linux 的 cgroups+namespaces 路线在本体论上地位相等，三者皆是沙箱机制的一刻状态，差异是工程哲学的不同而非本体等级的高下

## 211.3.3 法律与道德是利益分配视角下的 committer 权限、资金模式与排外性文化

**要点**：从项目史观总纲第 13 条“法律与道德是利益分配”审视，OpenBSD 哲学文化与社区的具体形态本质上是利益分配机制——committer 权限的授予与撤销决定了谁有资格直接向 OpenBSD 仓库提交代码，这一资格直接影响个人在 BSD 社区中的声誉、职业发展机会与项目决策参与权；de Raadt 主导的权限管理以“代码可审计为可信来源”为预设，但这一预设本身是利益分配的形式——“已被 OpenBSD 核心圈认可的持续贡献者”获得了 commit 权，而“与 de Raadt 个人风格不合但工程能力合格的贡献者”被排除，这一排除是权力行使而非纯粹的工程考量；“安全至上”哲学亦是利益分配——OpenBSD 以“默认安全”为预设排除了接受 binary blob 的硬件厂商、追求性能优先的用户、容器生态的采用者，这一排除在 OpenBSD 工程哲学下具有合理性但亦是权力行使；资金模式是利益分配——OpenBSD 的志愿模式使志愿开发者以无偿贡献换取技术决策的独立性，这一交换在 OpenBSD 工程哲学下具有合理性但亦是利益分配；排外性文化是利益分配——“RTFM”传统与“公开斥责”风格使风格温和的贡献者、初学者、非英语母语者在邮件列表互动中处于劣势，这一劣势是文化氛围的利益分配效应

## 211.3.4 解释学循环与权力知识共谋视角下的 OpenBSD 哲学文化叙事

**要点**：从项目史观总纲第 19 条“解释学循环是历史认识的根本条件”审视，OpenBSD 哲学文化与社区的评估受前理解差异制约——OpenBSD 阵营以“治理效率”与“安全至上”为前理解，批评者以“继承风险”与“排外文化”为前理解，被疏远贡献者以“个人经历”为前理解，外部观察者以“治理多样性”为前理解，四者难以通约；解释学循环意味着 OpenBSD 哲学文化的历史认识不存在中立旁观者——任何叙事都嵌入特定前理解，史家的任务不是消除前理解而是自觉呈现前理解；权力与知识在 OpenBSD 哲学文化的历史书写中共谋——OpenBSD 官方叙事（如 de Raadt 的 misc@ 发言、OpenBSD Release Notes、OpenBSD Foundation 年报、OpenBSD goals.html 经 WebFetch 核验载明的"Pay attention to security problems and fix them before anyone else does"）与批评者叙事（如被疏远贡献者的公开回应、FreeBSD/NetBSD/Linux 社区的观察评论）在“什么被记录、什么被遗忘”上本身就是权力行使，本节（94.7-94.9、94.10）的辩证链补足与项目统摄史观审视即是试图打破单一叙事的权力垄断，使 OpenBSD 阵营与批评者阵营的论点对称呈现；解释学循环亦适用于本审视自身——项目统摄史观审视嵌入项目统摄史观的前理解，须自觉呈现这一前理解而非伪装中立，合图（94.9.5）不是辩证链的终结而是阶段性综合，随 OpenBSD 哲学文化演进（如 de Raadt 退出后的继任机制建立、资金模式的可能变化、社区文化的可能演变、被疏远贡献者视角的更多史料公开）须重新展开；文化即形式主义化的传统亦适用于 OpenBSD 哲学文化叙事——“BDFL 模式是 OpenBSD 工程一致性的保障”在形式主义化过程中被固化为 OpenBSD 项目意识形态的核心，继承风险与排外性文化在形式主义化过程中被简化为“必要代价”而非“结构性张力”，“安全至上”哲学在形式主义化过程中被重构为“不可质疑的预设”而非“可辩证的工程选择”

## 211.3.5 许可证哲学、解释学循环与革命改革路径的综合审视

**要点**：从项目史观总纲第 13 条（法律与道德是利益分配，许可证哲学是其具体显现）、第 19 条（解释学循环与权力知识共谋）、第 21 条（革命与改革是历史方法论的分歧）综合审视，OpenBSD 哲学文化争议的本质是许可证哲学选择、叙事权力知识共谋与革命改革路径分歧的交织——其一，许可证哲学维度：OpenBSD **policy.html** 经 WebFetch 一手核验载明"OpenBSD strives to provide code that can be freely used, copied, modified, and distributed by anyone and for any purpose. This maintains the spirit of the original Berkeley Software Distribution.“，明确选择 ISC 许可证为首选（”The ISC copyright is functionally equivalent to a two-term BSD copyright with language removed that is made unnecessary by the Berne convention. This is the preferred license for new code incorporated into OpenBSD.“），并将 GPL 排除在新代码之外（OpenBSD **goals.html** 经 WebFetch 一手核验载明”ISC or Berkeley style licences are preferred, the GPL is not acceptable when adding new code, NDAs are never acceptable.“）；OpenBSD 对 GPL 的批评载于 **policy.html**——”While this may superficially look like a noble strategy, it is a condition that is typically unacceptable for commercial use of software. So in practice, it usually ends up hindering free sharing and reuse of code and ideas rather than encouraging it. As a consequence, no additional software bound by the GPL terms will be considered for inclusion into the OpenBSD base system.“；OpenBSD 对 Apache 2 许可证的批评亦载于 **policy.html**——”A license can only be considered fully permissive if it allows use by anyone for all the future without giving up any of their rights. If there are conditions that might terminate any rights in the future, or if you have to give up a right that you would otherwise have, even if exercising that right could reasonably be regarded as morally objectionable, the code is not free.“——这一许可证选择是利益分配的具体显现，OpenBSD 以”anyone can use for ANY PURPOSE, with no restrictions"为预设排除了 GPL 阵营的 copyleft 路径，使商业使用者获得无限制使用代码的权利，但同时也使代码贡献者放弃了通过 copyleft 强制下游开源的权利；其二，解释学循环与权力知识共谋维度：OpenBSD 许可证哲学的叙事（**policy.html** 载明的“the spirit of the original Berkeley Software Distribution”与"the battles which they and others fought to create a Unix source distribution un-encumbered by proprietary code and commercial licensing"）将 CSRG 的伯克利传统重构为“自由软件等于无限制许可”的形式主义化叙事，这一叙事在形式主义化过程中遮蔽了 GPL 阵营对“自由”的另一种定义（自由等于强制下游开源以保障用户权利），二者对“自由”的前理解差异使许可证争议难以通约；权力与知识在 OpenBSD 许可证叙事中共谋——OpenBSD 官方叙事（**policy.html**、**goals.html**、de Raadt 在 <misc@openbsd.org> 的发言）将 ISC/BSD 许可证塑造为“真正的自由”，GPL 阵营的官方叙事将 copyleft 塑造为“真正的自由”，二者在“什么被记录、什么被遗忘”上本身就是权力行使；其三，革命与改革路径维度：OpenBSD 的工程方法论是“改革”而非“革命”——OpenBSD 1995-10-18 fork 自 NetBSD 后持续进行代码审计与渐进式重写（pledge/unveil 2015、LibreSSL 2014 fork 自 OpenSSL、mandoc 重写 man 工具），这一路径符合总纲第 21 条“BSD 靠改革”的判定；Linux 的工程方法论是“革命”——Linux 内核通过快速迭代、大规模重构、频繁 ABI 破坏实现功能扩展，这一路径符合总纲第 21 条“Linux 靠革命”的判定；总纲第 21 条原文载明“改革的困难远高于革命。破山中贼易，破心中贼难。”——OpenBSD 的改革路径在工程一致性上具有优势（6 个月发布周期 31 年未中断、安全机制的一致性），但在功能扩展速度上落后于 Linux 的革命路径（硬件支持滞后 1-2 年、容器生态边缘化）；OpenBSD 选择 fork + 重写而非 patch 是改革路径的具体显现——LibreSSL fork 自 OpenSSL 是“破心中贼”的工程实践，OpenBSD 阵营认为 OpenSSL 的代码质量无法通过 patch 修复，必须 fork 后重写，这一选择是改革路径的极端形式
