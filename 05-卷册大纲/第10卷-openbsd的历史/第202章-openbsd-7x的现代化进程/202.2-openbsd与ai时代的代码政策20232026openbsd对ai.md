## 202.2.1 OpenBSD 对 AI 代码的态度

**要点**：2023 年后 AI 代码生成工具（如 GitHub Copilot、ChatGPT）普及，OpenBSD 社区对此持谨慎态度——de Raadt 在 <misc@openbsd.org> 邮件列表中表示 AI 生成代码的版权归属无法考据，拒绝接受 AI 生成代码贡献；OpenBSD committer 政策要求 commit 注明作者且可考据，AI 代码不符合此要求 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**史料**：de Raadt 在 <misc@openbsd.org> 关于 AI 代码的发言（<https://marc.info/?l=openbsd-misc>）；OpenBSD committer 政策文档；tech@ 邮件列表 AI 代码讨论 ［A］

**史观**：总纲第 25 条——0 信任原则：OpenBSD 对 AI 代码的谨慎态度是 0 信任原则在代码来源审查中的实践——AI 生成代码的 “作者” 为大语言模型而非可考据的人类贡献者，其训练数据来源不透明，故 OpenBSD 以 “版权不可考据即不接受” 为预设，将 AI 代码视为不可信来源

**辨析**：OpenBSD 关于 AI 代码的具体政策在 <misc@openbsd.org> 邮件列表讨论中以 de Raadt 的发言为基准——de Raadt 作为 BDFL 的发言具有政策效力，但 OpenBSD 未如 NetBSD 那样在 committer 指南中正式写入 AI 代码条款，而是通过现有的 “commit 须注明作者且可考据” 政策间接限制 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；openbsd.duckdb 查询 L3.1.1.ai 在深层信息挖掘报告中不存在（报告仅含 L3.1.1.MFC、L3.1.1.Fix、L3.1.1.Add、L3.1.1.Refactor 等跨 22 仓库关键词分析，未覆盖 “AI” 或 “ai-generated” 关键词的 commit 模式挖掘），AI 代码政策相关的 commit 模式数据须以 openbsd.duckdb 直接查询 message_subject/message_body 含 “AI”、“Copilot”、“ChatGPT”、“tainted” 等关键词补全【代码级证据·openbsd.duckdb openbsd-src 仓库·2026-07-30 查询】以 message_subject LIKE ‘%AI%’/’%Copilot%’/‘%ChatGPT%’/’%tainted%’/'%LLM%’ 五组关键词查询 openbsd-src 仓库 commits 表，结果为：‘AI’ 关键词匹配均为 false positive（“available”、“fail”、“mainbus”、“detail” 等含 “ai” 子串的无关 commit），‘Copilot’/‘ChatGPT’/‘LLM’ 关键词无任何匹配，‘tainted’ 关键词仅匹配 1 条 2011-04-18 Perl CVE-2011-1487 安全修复 commit（与 AI 代码政策无关）——证实 OpenBSD 仓库中无 AI 代码政策相关的 commit，OpenBSD 的 AI 代码政策完全通过 misc@ 邮件列表 de Raadt 发言与 committer 社会共识执行，未在 commit log 或 committer 指南中留下书面文本痕迹；**【2026-07-30 第二轮考据·7ad 条目】**经 WebSearch 检索 "de Raadt OR deraadt openbsd-misc AI Copilot ChatGPT mailing list 2023 2024"，搜索结果均为微软 Copilot 相关新闻报道（与 OpenBSD 邮件列表无关），未检索到 <misc@openbsd.org> 邮件列表中 de Raadt 关于 AI 代码的具体发言帖子 URL；marc.info openbsd-misc 列表搜索接口（**<https://marc.info/?l=openbsd-misc>**）为交互式动态接口，WebFetch 不可达——de Raadt 关于 AI 代码的具体发言帖子 URL 与日期须以 <misc@openbsd.org> 邮件列表完整存档为最终核实路径，本轮考据因 marc.info 接口限制与 WebSearch 检索无果标存疑。

## 202.2.2 与 NetBSD tainted code 政策的比较

**要点**：NetBSD Foundation 于 2024-05-17 在 NetBSD Commit Guidelines 第 2 条正式加入 “tainted code” 条款——“由大语言模型或类似技术（如 GitHub/Microsoft Copilot、OpenAI ChatGPT、Facebook/Meta Code Llama）生成的代码被视为受污染代码（tainted code），未经 Core Team 事先书面批准不得提交”；NetBSD 政策比 OpenBSD 更正式化——以书面条款写入 Commit Guidelines；OpenBSD 通过 committer 政策与 de Raadt 的 misc@ 发言间接限制 AI 代码，未形成正式书面条款

  **三大 BSD AI 代码政策对比**：

  | 项目 | 政策形式 | 治理机制 | 严格程度 | 可考据性 |
  | --- | --- | --- | --- | --- |
  | OpenBSD | 非正式（BDFL 发言） | BDFL 制（de Raadt） | 间接限制（commit 须注明可考据作者） | 弱（须检索邮件列表存档） |
  | NetBSD | 正式书面条款（Commit Guidelines 第 2 条） | Core Team 委员会制 | 正式禁止（未经书面批准不得提交） | 强（可查阅文档） |
  | FreeBSD | 无明确条款 | Core Team 选举制 | 允许自行判断（committer 负责） | 无（无政策文本） |

**史料**：NetBSD Commit Guidelines 第 2 条（<https://www.netbsd.org/developers/commit-guidelines.html>，"Code generated by a large language model or similar technology, such as GitHub/Microsoft‘s Copilot, OpenAI’s ChatGPT, or Facebook/Meta's Code Llama, is presumed to be tainted code, and must not be committed without prior written approval by core "）；IT 之家 2024-05-17 报道（<https://cloud.tencent.com.cn/developer/news/1400568>）；OpenBSD committer 政策文档〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 3 条——不存在进步，只有权力再分配：NetBSD 通过 Core Team 委员会决策将 AI 代码禁令正式写入 Commit Guidelines，OpenBSD 通过 de Raadt 个人发言间接限制——两种治理机制（委员会制 vs BDFL 制）对同一问题（AI 代码）的不同回应，实质是政策制定权在委员会集体与个人权威之间的权力再分配差异的显现

**辨析**：NetBSD tainted code 政策的执行情况以 NetBSD Commit Guidelines 页面文本为准——该条款于 2024-05-17 经 IT 之家报道后为公众所知，具体写入时间可能早于报道日期 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；两个政策的实际效果对比无权威统计 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；**【2026-07-30 三次复查·互联网档案馆快照交叉验证·7af 条目】**经 WebFetch 互联网档案馆 Wayback Machine 三次复查：（1）2024-01-01 快照（**<https://web.archive.org/web/20240101000000/https://www.netbsd.org/developers/commit-guidelines.html>**）第 2 条 “Do not commit tainted code to the repository.” 仅含 “If you commit code that was not written by yourself...” 一段，**无** "Code generated by a large language model or similar technology..." 段；（2）2024-05-18 快照（**<https://web.archive.org/web/20240518000000/https://www.netbsd.org/developers/commit-guidelines.html>**）第 2 条已含 "Code generated by a large language model or similar technology, such as GitHub/Microsoft‘s Copilot, OpenAI’s ChatGPT, or Facebook/Meta's Code Llama, is presumed to be tainted code, and must not be committed without prior written approval by core." 一段；（3）2024-06-01 快照（**<https://web.archive.org/web/20240601000000/https://www.netbsd.org/developers/commit-guidelines.html>**）亦含该段——三源交叉印证 LLM 段添加时间在 2024-01-01 至 2024-05-17 之间（含），与 12.2.2 节“2024-05-17 正式加入”表述一致；NetBSD CVS Web 接口（**<https://cvsweb.netbsd.org/bsdweb.cgi/htdocs/developers/commit-guidelines.xml>**）启用 Anubis 反爬虫机制，WebFetch 不可达；GitHub 镜像 NetBSD-www/htdocs 仓库 commits 接口返回 404——故精确 commit hash 与写入日期无法直接获取，须以 NetBSD CVS/Git 仓库中该页面修订历史为最终核实路径，本轮考据因 CVS Web 接口与 GitHub 镜像均不可达标存疑。

## 202.2.3 与 FreeBSD AI 代码政策的对照

**要点**：FreeBSD 对 AI 代码的态度较 OpenBSD/NetBSD 宽松——FreeBSD Committer's Guide 未明确禁止 AI 代码，但要求 committer 对贡献负责；FreeBSD 政策允许 committer 自行判断 AI 代码的可接受性；三个 BSD 项目的 AI 代码政策差异——NetBSD 正式禁止（tainted code 条款）、OpenBSD 间接限制（committer 政策 + BDFL 发言）、FreeBSD 允许自行判断（无明确条款）

**史料**：FreeBSD Committer's Guide（<https://docs.freebsd.org/en/articles/committers-guide/>）；FreeBSD Core Team 关于 AI 代码的发言；FreeBSD 邮件列表 AI 代码讨论 ［A］

**史观**：总纲第 3 条——不存在进步，只有权力再分配：三项目对 AI 代码的不同态度是各自治理文化中权力分配方式的显现——NetBSD 的委员会制将政策制定权集中于 Core Team 集体，OpenBSD 的 BDFL 制将政策制定权集中于个人权威，FreeBSD 的 Core Team 选举制将判断权下放给 committer 自行行使

**辨析**：FreeBSD 关于 AI 代码的具体实践以 FreeBSD Committer's Guide 为准——该指南未包含 “AI 代码” 或 “tainted code” 条款；**【2026-07-30 FreeBSD Committer's Guide AI 条款考据·7ag 条目】**经 WebFetch FreeBSD Committer's Guide 实时页面（**<https://docs.freebsd.org/en/articles/committers-guide/>**）全文检索，以 `\b(AI|tainted|Copilot|ChatGPT|LLM|artificial intelligence|machine learning|large language model)\b` 关键词正则匹配，结果为无匹配——证实 FreeBSD Committer's Guide 当前版本（版权声明 “Copyright © 1999-2022 The FreeBSD Documentation Project”）未含任何 AI 代码政策条款；经 GitHub API `freebsd/freebsd-doc` 仓库 `commits?path=documentation/content/en/articles/committers-guide/&per_page=5` 查询最近 5 次 commit（2026-06-18 至 2026-07-24），commit message 分别为 “add Watchgoose benefit”、“Harmonize the cross repo advice”、“Use macros for branch examples”、（2026-06-26 commit）、“Remove sectnumlevels”——均与 AI 代码政策无关，证实 FreeBSD Committer's Guide 在 2026-07 仍未加入 AI 代码条款；三个政策的实际效果对比无权威统计
