# 210.3 OpenBSD 的发行文化与 CD/海报传统

**要点**：OpenBSD 自 2.0（1997-06-01 发布）起保持每年 5 月与 11 月 6 个月固定发布周期传统——OpenBSD 7.9（2026-05-19 发布）是第 60 个 release，从未出现因外部事件推迟发布的情况（OpenBSD 各版本发布日期均见 <https://www.openbsd.org/> 各版本页面）；CD 封面艺术（每版由不同艺术家创作，如 3.4 的 Puffy Hood 由 Tyson Ads 创作）与 release song（发布歌曲，3.4 为"The Legend of Puffy Hood"）构成独特的发行文化；该传统自 2.x 系列延续至 7.x 系列

**史料**：OpenBSD 各版本 CD 封面艺术与 release song 存档（<https://www.openbsd.org/lyrics.html>）；OpenBSD Release Notes（<https://www.openbsd.org/plus.html>）；OpenBSD 邮件列表中关于发行传统的讨论（<https://marc.info/?laccopenbsd-misc>）；OpenBSD 3.4 Release Page（<https://www.openbsd.org/34.html>，明确发布日期 Nov 1, 2003）

**史观**：总纲第 8 条——社区文化即技术资产：发行文化是 OpenBSD 社区文化资产——CD 封面艺术与 release song 将工程发布升格为文化仪式，使每次 release 成为社区认同的强化节点；总纲第 5 条——组织结构塑造技术路径：6 个月固定发布周期塑造 OpenBSD 的开发节奏——所有功能须在 cutoff 日期前合入，否则顺延至下个 release

**辨析**：原叙事中“2003 年因 Iraq War 推迟 3.4 发布”的说法与官方记录不符——OpenBSD 3.4 于 2003-11-01 按期发布（<https://www.openbsd.org/34.html>），与 Iraq War（2003-03-20 开始）无推迟关系；DARPA 撤资事件发生于 2003-04，亦未影响 3.4 发布；6 个月发布周期自 OpenBSD 2.0（1997-06-01）起确立，至 2026-05-19 的 7.9 共 60 个 release，时间间隔稳定

**要点**：

- PC-BSD 发布 1.0 的第二候选版：本质是将 FreeBSD 6.0 打包为单 CD 的桌面导向系统，预装 KDE 3.5，全程图形化安装并默认创建普通用户与自动登录，明确面向家用场景。其区别于普通 FreeBSD 加 KDE 之处在于自研包管理器：以单个文件夹容纳应用的程序、库与配置，以双击式安装器交付并请求 root 密码安装，库彼此隔离以避免依赖冲突；当事人梳理此应用包理念的前史为 Acorn 的 RISC OS 与 NeXT，经 Apple 的 Darwin 推广。批评者指其制造冗余膨胀，当事人认为在单用户桌面系统上代价可接受；系统另提供在线更新，免除传统 make world 升级流程；因 1.0 正式版未至，当事人认为此时难作定评。（BSDTalk EP8，[55.22-316.42]，L1）
- 当事人盘点五项免费 BSD shell 账户服务：GNUK（转写亦作 gnooc）与 metawire.org 基于 OpenBSD，arbornet.org 基于 FreeBSD，freeshell.org 基于 NetBSD，此类社区服务多在低配硬件上勉强维持；另有惠普的 HP Test Drive 提供 FreeBSD、NetBSD、Tru64 UNIX、OpenVMS 与 Linux 的 shell，硬件规模远超社区服务（含 16 CPU 系统、GB 级内存），其 NetBSD 已是 3.0 版。当事人注册 GNUK.org 实测获当天技术支持响应，账户按使用年限与捐赠硬件分级、可申请提升配额；并警告挂 IRC 机器人、拒绝服务攻击、骚扰等滥用会毁掉此类免费服务。（BSDTalk EP8，[389.20-605.24]，L1）
- 对 HP Test Drive 以 Telnet 接入一事，当事人批评 OpenSSH 作为 BSD 许可的安全 Telnet 替代品早已人人可用，Telnet 继续被使用不可原谅；并推测 HP 或有意以不安全协议劝阻用户将测试机当重要系统使用。（BSDTalk EP8，[559.26-605.24]，L1）
- OpenBSD 发行传统：自 3.0 版起每版附带一首发布歌曲，当事人以其中一首作为本期节目开场音乐。（BSDTalk EP8，[42.72-51.34]，L1）
- SpamD 是一个小型邮件延迟守护进程：对 SMTP 连接或以 450/451 应答令对方稍后重试，或经调整 PF 表放行；兼具 tarpitting 与灰名单两类用途。其设计目标之一是与 Theo 商定确保在一台 SPARCstation IPC 上过滤一个大网络——守护进程不 fork，而是一个读大量套接字、跟踪全部连接状态并与 PF 通话的状态机；对邮件内容不做任何判断（不做正文统计词频分析），只依据 SMTP 连接本身的性质——是否符合标准、是否有规避反垃圾措施的迹象——作判断，故可跑在内存极小的机器上。在阿尔伯塔大学约八万个账户的中央邮件环境里，受访者把 SpamD 放在 Exchange 服务器之前，配合较激进的灰名单，五封 SMTP 消息约四封被挡下、仅一封进入实际处理，显著减轻主邮件处理器负载。（BSDTalk EP68，[77.8-496.0]，L1）
- 运行观察驱动默认行为：SpamD 初期对每个连接前 10 秒以极低速应答后恢复正常，受访者观察日志发现大量连接在三秒即断——垃圾邮件软件以此探测 tarpitting——遂把 10 秒初始延迟设为默认且不设旋钮；对发件方还可启用把 TCP 窗口压到极小、令其分片重传的“残忍”选项以考验对方 TCP 栈（代价是带宽，默认关闭）；对 SMTP auth 场景建议不用 25 端口提交，而以 465 的 SMTPS 与 587 的 mail submission 端口加 SSL 认证解决，必要时可用 PF 重定向规则整网豁免；对早期灰名单担心的出站邮件服务器地址池问题，其经验是一般不构成障碍——可预置 graylisting.org 公布的大站白名单，小池子重试终会通过，出入站共用地址会因 SpamD 观察外发而逐步白名单化，大型站点约两个月才需一次人工干预；相较之下 Sendmail Milter 负载高且按发件人-收件人-IP 三元组粒度过激，不适合大学站点，SpamD 以整 IP 白名单加进出双向观察更为合用。（BSDTalk EP68，[252.24-496.0]，L1）
- greytrapping 机制与轶事：把站点内已公开且弃用的邮件地址设为陷阱，凡向陷阱地址发信的机器即被阻塞 24 小时并遭低速应答，纵使一次投递百封也全数不通；受访者的陷阱名单甚至包括其历年写进软件文档的示例假地址。其举的 bigbutts@obtuse.com 一例成为蠕虫式扩散的活教材：文章发表前先布入陷阱，数日内即有垃圾邮件命中；数月后统计脚本发现命中暴涨，用 Google 一查，某 BSD 期刊的 OpenBSD 文章被色情站点爬虫抓取并在隐藏标签中复制全文，垃圾邮件发送者再爬色情站点把地址再次拾取——清理者与滥用者的食物链在陷阱地址上叠印。（BSDTalk EP68，[673.06-895.48]，L1）
- 社区体验与多重贡献：受访者形容 OpenBSD 社区是一群高强度但自得其乐的人——hackathon 通宵、技术讨论时大喊大叫上蹿下跳，留下来是因为“有趣且对我们有用”；其本人自认什么 都碰：重写过 SpamD（不满意即推倒重来）、近期在拆解 SCSI 层——多数 BSD 的磁带机与磁带库 changer 支持基本残废，遂对 SCSI 层、磁带驱动与 changer 驱动作内核级修整；参与各处的修复、测试与发布验证，运营 orders 网站（藏在其公司机器与自家地下室）；自嘲“样样通样样松”，并强调自己不是 OpenBSD 狂热者而只是一个 UNIX 用户——用其所善、避其所短。（BSDTalk EP68，[897.92-1020.56]，L1）
- 缘起故事：约 1995 年，受访者与合伙人写防火墙软件并在咨询业务中营销，以把它移植到一切平台为乐（含内核修改）；当时无线买不起联网可用机，弄到一台 SPARCstation 后发现 NetBSD 的 SPARC 移植完全不可用，而 OpenBSD 正在起步——安全正对其胃口，也不管社区恩怨只问“能不能用”；下载 SPARC 发行版果然能跑且修掉了一批旧 bug；当年网站还是 Theo 的个人页，写着“喜欢就打这个电话”——竟是卡尔加里一家比萨店的号码，身在三小时车程外埃德蒙顿的他打电话订比萨遭拒后转而向 Theo 抱怨，两人在汉堡店见面，他买下一张 CD，从此入伙。（BSDTalk EP68，[1020.56-1118.98]，L1）
- 桌面、家庭与文化参与：受访者笔记本、桌面与孩子的机器都跑 OpenBSD（孩子双启 Windows 只为游戏）；其桌面是极简的 fvwm，但承认近年 ports 收集安装体验进步惊人，孩子用全套 KDE 加 Linux 兼容层跑 OpenOffice 与教育、游戏软件，女儿用 MSN 客户端、儿子玩 Blender，全家充当 ports 的发布测试“小白鼠”；家中防火墙以 PF 的操作系统指纹特性只放行 Windows 走 80 端口以隔绝病毒。发行文化方面：4.0 已分支并开放预购，预购者常在 FTP 放开前拿到 CD；本次除 CD 套装外首推收录 3.0 至 4.0 全部发行歌曲加彩蛋曲目的音频 CD；受访者为 3.5 的“鱼执照”歌曲写过歌词（自认 Monty Python 粉丝玩过火）；制作水准主要来自卡尔加里的 Ty Semaka 与 Jonathan Lewis（乐队 Plaid Tongued Devils），他自己也在一曲中与 Theo、Peter Valchev 及儿子 Calvin 合唱“酒吧合唱”；收尾呼吁买 CD、T 恤、捐款——强调 OpenBSD 反哺众多项目、直接间接被广泛使用，募款并非乞讨。（BSDTalk EP68，[1159.18-1535.58]，L1）

**史观**：

- 总纲15 文化即形式主义：OpenBSD 每版附发行歌的做法，把版本发布这一纯技术事件转化为可感知的文化仪式：例行发布程序被赋予音乐形式而成为社区文化产品，显示技术社群如何以仪式性形式维系自我认同与传播节奏。（BSDTalk EP8，[42.72-51.34]，L1）
- 总纲9 经验优先：受访者把“三秒即断”的日志观察直接固化为默认且无旋钮的行为，把 OpenBSD 社区“我们讨厌旋钮”的立场说成减少误配的工程伦理——默认值不是理论推演而是从生产邮件环境的 disconnect 剖面里读出来的；这种以运维现场经验而非参数表驱动设计的取向，是经验优先原则在安全工程中的具体形态。（BSDTalk EP68，[456.36-484.24]，L1）

**辨析**：

- 免费 shell 服务的 OpenBSD 系站点域名在转写中出现 gnooc.org 与 GNUK.org 两种拼写，实名待考；引用该服务名录前须核对域名实名。当事人对 HP 采用 Telnet 的动机解释（有意以不安全协议劝阻重度使用）是其自承的猜测，无 HP 方面证据支撑，Telnet 接入的事实本身可信，但动机解释仅可作推测对待。[存疑脚注] 域名拼写不一致且企业动机无一手佐证。　[存疑脚注] gnooc.org 与 GNUK.org 拼写不一致，需与 2006 年免费 shell 服务名录核对；HP 采用 Telnet 的动机为当事人推测。（BSDTalk EP8，[389.20-605.24]，L4）
- 转写专名失真须回核音频：Spamdy/spam log D/BAMD 均应为 SpamD，Tai Samaka 应为 Ty Semaka，Plattongue Devils 应为 Plaid Tongued Devils，FBWM 应为 fvwm；“Diffsin TCP”与“Lowcore.S”疑为“diffs in tcp”与“locore.s”，无法确证；bigbutts@obtuse.com 轶事及所涉 BSD 期刊名称为受访者单方追述，期刊与色情站点放大链条须另行核实。　[存疑脚注] 发行歌曲参与人员姓名转写失真；TCP/locore.s 提交细节与 bigbutts 轶事的传播链均待音频与外部材料核实（BSDTalk EP68，[1304.22-1417.98]，L5）
