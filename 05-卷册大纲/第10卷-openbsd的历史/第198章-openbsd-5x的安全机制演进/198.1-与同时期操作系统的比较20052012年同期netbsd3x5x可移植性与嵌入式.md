# 198.1 **与同时期操作系统的比较**：2005-2012 年同期 NetBSD 3.x-5.x（可移植性与嵌入式）、FreeBSD 6.x-9.x（ULE/ZFS/bhyve）、Linux 2.6.x-3.x（CFS/内核抢占/cgroups）、Solaris 10/11（ZFS/DTrace/Zones）——OpenBSD 以“安全至上与 6 个月周期”为定位

## 197.1.1 NetBSD 可移植性的对照

**要点**：2005-2012 年间 NetBSD 3.x-5.x 持续推进可移植性——支持 50+ 硬件平台，从嵌入式设备到大型机；OpenBSD 同期支持约 10-15 个平台，专注于主流架构（i386、amd64、sparc64、arm 等）；NetBSD 在嵌入式与教育市场占据 BSD 优势地位，OpenBSD 在安全领域占优

**史料**：NetBSD 3.x-5.x Release Notes 平台支持列表（<https://www.netbsd.org/releases/formal-3/>、<https://www.netbsd.org/releases/formal-5/）；OpenBSD> 4.x-5.x Release Notes 平台支持列表（<https://www.openbsd.org/plus.html>）；bsd_commits.db netbsd-src 与 openbsd-src 仓库 contributors 表对比 ［A］

**史观**：总纲第 6 条——技术路线分化：NetBSD 与 OpenBSD 的平台支持策略分化各有适配——NetBSD“支持一切硬件”的路线适配其可移植性导向，OpenBSD“主流架构优先”的路线适配其安全审计资源约束（平台越多安全审计负担越重）

**辨析**：NetBSD 平台数量的具体定义以 NetBSD Release Notes 平台支持列表为准——部分平台仅为实验性支持（Tier-2/Tier-3）；OpenBSD 平台裁撤的具体时间点以 Release Notes 为准——OpenBSD 在 5.x 周期裁撤了部分 Tier-3 平台以集中资源

**文献**：NetBSD Release Notes [EB/OL]. <https://www.netbsd.org/releases/>；OpenBSD Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>；bsd_commits.db netbsd-src 与 openbsd-src 仓库 ［A］

## 197.1.2 FreeBSD ULE/ZFS 的技术进展

**要点**：FreeBSD 6.x-9.x 时期 ULE 调度器（Jeff Roberson 设计）逐步成熟，SMP 性能大幅提升；FreeBSD 7.0 引入 ZFS 移植，8.0 引入 bhyve 虚拟化，9.0 引入 Capsicum 沙箱；同期 OpenBSD 5.0/5.1 仍专注安全与网络栈，未引入类似大规模特性

**史料**：FreeBSD 6.x-9.x Release Notes（<https://www.freebsd.org/releases/>）；bsd_commits.db tags 表 release/9.0.0 tagger_date = 2012-01-02T18:59:55Z（tagger: Ken Smith）；ULE 调度器设计文档；OpenBSD 5.0/5.1 Release Notes（<https://www.openbsd.org/50.html>、<https://www.openbsd.org/51.html）［A］>

**史观**：总纲第 6 条——技术路线分化：FreeBSD 选择性能与虚拟化路线（ULE/ZFS/bhyve），OpenBSD 选择安全路线（KARL/ASLR/pledge）——分化是各自社区价值观的技术显现，二者非互斥但资源分配的零和博弈使同期能投入的方向有限

**辨析**：ULE 与 4BSD 调度器的性能对比以 FreeBSD 邮件列表中的基准测试为准——ULE 在多核场景优于 4BSD，4BSD 在单核场景略优；ZFS 在 FreeBSD 上的稳定性以 FreeBSD ZFS 邮件列表讨论为准——早期移植存在内存占用与兼容性问题，后续版本逐步改善

**文献**：FreeBSD Release Notes [EB/OL]. <https://www.freebsd.org/releases/>；bsd_commits.db tags 表 release/9.0.0；ULE 设计文档；OpenBSD Release Notes [EB/OL]. <https://www.openbsd.org/plus.html> ［A］

## 197.1.3 Linux cgroups 对容器生态的效应

**要点**：Linux 2.6.x（2003 起）引入 cgroups 机制，3.x 时代 Docker（2013）建立于 cgroups 与 namespaces 之上；cgroups 让 Linux 在容器生态占据垄断地位；同期 BSD 项目均未提供同等容器原语，OpenBSD 的 pledge/unveil 是不同方向的沙箱机制

**史料**：Linux 2.6.x cgroups 设计文档（<https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2/>）；Docker 早期文档（<https://docs.docker.com/>）；Linux Kernel mailing list 关于 cgroups 的讨论（<https://lore.kernel.org/lkml/>）［A］

**史观**：总纲第 6 条——技术路线分化：Linux 选择 cgroups 容器化路线（资源隔离优先），OpenBSD 选择 pledge 沙箱路线（权限限制优先）——分化塑造不同生态，Linux 的容器生态支撑了云原生时代，OpenBSD 的 pledge/unveil 支撑了进程级安全硬化

**辨析**：cgroups 与 Docker 的关系以 Docker 官方文档为准——Docker 基于 namespaces + cgroups + UnionFS 三个内核机制，并非仅基于 cgroups；BSD 缺乏容器原语的原因以各 BSD 项目的邮件列表讨论为准——资源约束与路线选择是主因

**文献**：Linux cgroups 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2/>；Docker 早期文档 [EB/OL]. <https://docs.docker.com/>；BSD 邮件列表讨论 [EB/OL]. <https://marc.info/?laccopenbsd-tech> ［A］

## 197.1.4 各项目发布数据与市场份额考据

**要点**：2005-2012 年间各 BSD 项目与 Linux 的发布数据与市场份额是研究 BSD 边缘化的核心史料；FreeBSD Release 周期约 18-24 个月，OpenBSD 6 个月，NetBSD 不规律；Linux 发行版市场份额远超 BSD，但 BSD 在服务器、嵌入式、安全领域仍有存在感

**史料**：各 BSD 项目 Release Notes（<https://www.openbsd.org/plus.html>、<https://www.freebsd.org/releases/、https://www.netbsd.org/releases/）；bsd_commits.db> tags 表各项目 release tag tagger_date；Linux 发行版发布记录 ［A］

**史观**：总纲第 25 条——0 信任原则：发布数据与市场份额考据是 0 信任原则在 BSD 边缘化研究中的应用——市场份额统计须以多源交叉验证，单一来源（如 DistroWatch）不足以反映实际部署

**辨析**：市场份额统计无权威数据源——DistroWatch 排名仅反映桌面用户关注度，不反映服务器部署；BSD 实际部署规模以厂商报告（如 Juniper JunOS 基于 FreeBSD、NetApp ONTAP 基于 FreeBSD）与调查为准 [考据完成：2026-07-28 BSD 实际部署规模无单一权威统计，厂商报告仅覆盖商业用户]

**文献**：各 BSD 项目 Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>、<https://www.freebsd.org/releases/；bsd_commits.db> tags 表；Linux 发行版统计[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]
