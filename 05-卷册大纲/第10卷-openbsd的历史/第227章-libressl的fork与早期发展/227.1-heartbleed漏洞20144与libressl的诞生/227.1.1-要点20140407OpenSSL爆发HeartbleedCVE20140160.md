# 227.1.1 要点20140407OpenSSL爆发HeartbleedCVE20140160

**要点**：2014-04-07 OpenSSL 爆发 Heartbleed（CVE-2014-0160）严重漏洞，允许远程攻击者通过 TLS heartbeat extension 读取服务器内存（最多 64KB/请求），影响全球约 17% 的 HTTPS 站点；OpenBSD 项目于 2014-04-14 在 <misc@openbsd.org> 邮件列表发起 LibreSSL fork，由 de Raadt、Bob Beck、Joel Sing（乔尔·辛） 等主导——openbsd.duckdb openbsd-src 仓库 commit b6553af36068（2014-07-12 jsing 提交的 lib/libressl/Makefile、ressl.c、ressl.h 等文件）系新建的 libressl API 库初始版本；fork 本身自 2014-04-14 宣告当日起即在源码树内就地改造 libssl/libcrypto

**史料**：CVE-2014-0160 漏洞公告（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2014-0160>）；OpenSSL Heartbleed 安全通告（<https://www.openssl.org/news/secadv/20140407.txt>）；OpenBSD 邮件列表中 LibreSSL fork 宣告（<https://marc.info/?l=openbsd-misc>）；de Raadt 关于 LibreSSL 的公开声明；openbsd.duckdb openbsd-src commit b6553af36068（2014-07-12 LibreSSL 首次引入）

**史观**：总纲第 5 条——没有必然性，只有偶然性：Heartbleed 偶然催生 LibreSSL——若无 2014-04-07 漏洞曝光，OpenBSD 不会在 2014-04-14 当周即决定 fork OpenSSL，LibreSSL 项目可能延后数年或永不存在；总纲第 13 条——法律与道德是利益分配（存疑）：OpenSSL 治理结构问题（OpenSSL 项目当时由 OpenSSL Software Foundation 管理，资金紧缺导致代码审计不足）是其 fork 的结构性因素

**辨析**：Heartbleed 漏洞的技术细节经 CVE-2014-0160 公告确认——漏洞位于 OpenSSL 1.0.1 至 1.0.1f 的 tls1_process_heartbeat 函数，因缺少边界检查导致缓冲区过读；LibreSSL fork 的动机是“代码质量”与“治理结构”双重——de Raadt 在 2014-04 的 misc@ 邮件列表宣告中明确批评 OpenSSL 代码质量（“OpenSSL is dead to us”），但治理结构问题（OpenSSL 项目长期资金紧缺、缺乏审计）亦是 fork 决策的关键因素。经 [邮件列表库] 验证通过（来源：openbsd-announce 2014-07-11 Bob Beck “First release of LibreSSL portable is available.” 确认 LibreSSL 2.0.0 发布；openbsd-announce 2014-07-13 至 2014-10-16 连续发布公告确认 LibreSSL 2.0.1-2.1.1 密集发布；openbsd-tech 2014-04-27 miod@ 讨论 Heartbleed 后修复，证实 LibreSSL fork 在 2014 年 4-6 月间活跃于邮件列表）。

**文献**：CVE-2014-0160 [EB/OL]. <https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2014-0160>；OpenSSL Heartbleed 安全通告 [EB/OL]. <https://www.openssl.org/news/secadv/20140407.txt>；LibreSSL fork 宣告 [EB/OL]. <https://marc.info/?l=openbsd-misc>；LibreSSL 项目主页 [EB/OL]. <https://www.libressl.org/>；OpenBSD commit b6553af36068 [G/OL]. <https://github.com/openbsd/src/commit/b6553af36068> ［A］
