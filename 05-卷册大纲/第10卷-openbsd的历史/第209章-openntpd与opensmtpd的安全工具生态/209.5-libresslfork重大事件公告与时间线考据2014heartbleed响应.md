# 209.5 LibreSSL fork 重大事件公告与时间线考据（2014）——Heartbleed 响应、fork 决议与首次 portable 发布的三阶段时间线


## 208.6.1 LibreSSL fork 重大事件公告与时间线考据
  - 要点：LibreSSL fork 为 OpenBSD 项目响应 2014-04 OpenSSL Heartbleed 漏洞（CVE-2014-0160）的重大事件公告，须严格区分三阶段时间线——（1）Heartbleed 漏洞爆发：2014-04-07 OpenSSL 官方发布安全公告 CVE-2014-0160，披露 Heartbleed 漏洞允许远程读取服务器内存；（2）OpenBSD fork 决议：2014-04 OpenSSL Heartbleed 事件后，OpenBSD 开发者（Bob Beck 等）随即启动 LibreSSL fork 项目，fork 决议确为 2014-04，但此时仅为项目启动而非发布；（3）LibreSSL 首次 portable 发布：2014-07-11 LibreSSL portable 首个版本发布，提供 OpenBSD 之外的 portable 版本；LibreSSL 首页（<https://www.libressl.org/>）作为公告 URL；LibreSSL 在 OpenBSD 5.6（2014-11-01）成为 OpenBSD 默认 TLS 库，取代 OpenSSL；LibreSSL fork 体现 OpenBSD“主动审计 + 重写而非补丁”的工程哲学——OpenBSD 阵营认为 OpenSSL 代码质量低劣至无法修补，须 fork 后重写而非补丁修复，这一立场区别于 OpenSSL 阵营的“补丁修复 + 资金注入”改革路线；统计结论印证——bsd_commits.db openbsd-src 仓库总 commit 数 245,904（统计结论 C-05），LibreSSL 相关 commit 自 2014-04-07 起构成其中安全审计 commit 的一部分；NVD OpenBSD 相关 CVE 共 168 个（外部基准 E-22），OpenBSD 平均 CVSS 评分 6.17（外部基准 E-27），Heartbleed（CVE-2014-0160 CVSS 7.5）作为触发 LibreSSL fork 的关键事件，其 CVSS 评分高于 OpenBSD 平均 CVSS，反映 Heartbleed 在 OpenBSD 安全史中的相对严重性
  - 史料：LibreSSL 官网（<https://www.libressl.org/>，一手核验）；OpenSSL 2014-04-07 Heartbleed 安全公告（CVE-2014-0160）；OpenBSD 5.6 release 页面（<https://www.openbsd.org/56.html>，记载 LibreSSL 成为默认 TLS 库）；<announce@openbsd.org> 邮件列表存档（marc.info）；Bob Beck 等开发者在 <misc@openbsd.org> 与 <tech@openbsd.org> 的 LibreSSL 开发讨论；原材料/研究/考据记录/20260723_announcements-openbsd.md § 二.4.1 LibreSSL fork 交叉验证；NVD OpenBSD CVE 数据（外部基准 E-22:168 个 CVE，来源 `https://services.nvd.nist.gov/rest/json/cves/2.0?keywordSearch=OpenBSD`，NVD API 2.0 全量拉取，查询日期 2026-07-27）；OpenBSD 平均 CVSS 评分（外部基准 E-27:6.17，NVD API 2.0 全量拉取，查询日期 2026-07-27） ［A］

  **LibreSSL fork 三阶段时间线**：

  | 阶段 | 日期（ISO 8601） | 事件 | 公告 URL |
  | --- | --- | --- | --- |
  | Heartbleed 漏洞爆发 | 2014-04-07 | OpenSSL 官方发布 CVE-2014-0160 安全公告，披露 Heartbleed 漏洞 | <https://www.openssl.org/news/secadv/20140407.txt> |
  | OpenBSD fork 决议 | 2014-04 | OpenBSD 开发者启动 LibreSSL fork 项目（决议日期不精确到日，4 月内） | <https://www.libressl.org/> |
  | LibreSSL 首次 portable 发布 | 2014-07-11 | LibreSSL portable 首个版本发布 | <https://www.libressl.org/> |
  | LibreSSL 成为 OpenBSD 默认 | 2014-11-01 | OpenBSD 5.6 发布，LibreSSL 取代 OpenSSL 为默认 TLS 库 | <https://www.openbsd.org/56.html> |

  - 史观：总纲第 21 条——革命与改革是历史方法论的分歧：LibreSSL fork 是革命路线的标志性事件——OpenBSD 阵营以 fork 重写而非补丁修复的方式回应 Heartbleed，区别于 Linux Foundation Core Infrastructure Initiative（CII）资助 OpenSSL 补丁修复的改革路线；总纲第 15 条——文化即形式主义：“LibreSSL 是 OpenBSD 对 Heartbleed 的英勇响应”叙事在 OpenBSD 社区被形式主义化为革命路线的合法性证明，但这一形式主义化使 LibreSSL 在 portable 采用率上的市场失败被遮蔽——LibreSSL 在 OpenBSD 之外的市场采用率长期低于 OpenSSL，证明 fork 路线在工程哲学上具有合理性但在市场生态上面临挑战；总纲第 13 条——法律与道德是利益分配：LibreSSL fork 与 CII 资金流向 OpenSSL 而非 LibreSSL 的对比，反映“革命路线 + 社区维护”与“改革路线 + 基金会资助”两种利益分配模式的竞争——OpenSSL 阵营通过 CII 资金注入维持改革路线的市场主导，LibreSSL 阵营通过 OpenBSD Foundation 维持革命路线的工程独立，二者在 2014-2026 年间各自呈现而非一方胜利；总纲第 19 条——解释学循环是历史认识的根本条件：LibreSSL fork 的历史认识受前理解差异制约——OpenBSD 阵营以“代码质量至上”为前理解（fork 决议即为先前理解的显现），OpenSSL 阵营以“生态兼容性至上”为前理解（CII 资金注入即为先前理解的显现），二者难以通约；统计结论印证——C-05 openbsd-src 总 commit 数 245,904 与 E-22 OpenBSD CVE 168 个的对照反映“分离聚合是永恒规律”（总纲第 4 条）的安全显现——commit 量反映工程节奏，CVE 数量反映外部安全压力，二者共同构成 OpenBSD 安全审计文化的双重证据；E-27 平均 CVSS 6.17 反映“实践先于理论”（总纲第 2 条）的统计显现——CVSS 评分是事后评估，反映 OpenBSD 在实际安全事件中的相对严重性分布
  - 辨析：LibreSSL fork 时间线考据须遵循 0 信任原则并以三段式呈现——【查证来源】（1）LibreSSL 官网 <https://www.libressl.org/> 经 2026-07-23 检索，载明 LibreSSL 项目基本信息但未明确标注 fork 决议日期与首次 portable 发布日期；（2）OpenSSL 2014-04-07 Heartbleed 安全公告经 OpenSSL 官网存档核验；（3）OpenBSD 5.6 release 页面 <https://www.openbsd.org/56.html> 经 OpenBSD 官网核验载明 LibreSSL 为默认 TLS 库；（4）<announce@openbsd.org> 邮件列表存档（marc.info）可交叉验证 LibreSSL 相关公告的发布时间；（5）bsd_commits.db openbsd-src 仓库 commits 表可交叉验证 LibreSSL 代码提交的时间序列，但 tags 表无 openbsd * 仓库的 release tag；【交叉验证方法】Heartbleed 漏洞爆发日期以 OpenSSL 官方安全公告为准；LibreSSL fork 决议日期以 OpenBSD 邮件列表讨论时间为准（2014-04 内，精确到日存疑）；LibreSSL 首次 portable 发布日期以 libressl.org 官网与 OpenBSD 邮件列表交叉验证（2014-07-11）；LibreSSL 成为 OpenBSD 默认 TLS 库以 OpenBSD 5.6 release 页面为准（2014-11-01）；【任务描述日期修正】任务描述曾作“OpenSSL fork 为 LibreSSL（2014-04）”，其中 2014-04 为 Heartbleed 漏洞爆发月份，非 LibreSSL 首次发布月份。LibreSSL 首次 portable 发布为 2014-07-11。fork 决议确为 2014-04，但首次发布为 2014-07，须区分“决议 fork”与“首次发布”两个时间点；【0 信任原则·fork 决议日期的存疑】LibreSSL fork 决议的精确日期在 OpenBSD 官方文档中未明确标注，2014-04 为社区共识月份，精确到日须以 <misc@openbsd.org> 与 <tech@openbsd.org> 邮件列表存档的最早 LibreSSL 讨论时间为准，但邮件列表存档的完整性须独立核验；【0 信任原则·portable 版本与 OpenBSD 内置版本的区分】LibreSSL portable 版本（供 OpenBSD 之外系统使用）与 LibreSSL OpenBSD 内置版本的开发节奏不同——portable 版本发布晚于 OpenBSD 内置版本，2014-07-11 为 portable 首次发布，OpenBSD 内置 LibreSSL 在 5.6（2014-11-01）正式成为默认，二者不可混淆；【反模糊原则】LibreSSL fork 的历史意义不应被简化为“OpenBSD 救了 OpenSSL”或“LibreSSL 失败了”的二元叙事——LibreSSL 在 OpenBSD 内成功取代 OpenSSL 为默认 TLS 库，在 portable 市场采用率低于 OpenSSL，二者是同一 fork 事件的不同侧面；* *统计局限性标注**——E-22 NVD OpenBSD CVE 数量 168 个基于 NVD CPE 命名匹配，受 NVD CPE 命名不完整局限影响（部分 OpenBSD 漏洞可能未在 NVD 中标注 OpenBSD 为受影响产品），实际漏洞数量可能高于或低于 168 个；E-27 平均 CVSS 6.17 为 NVD API 2.0 全量拉取结果，受 CVE 披露偏差影响（已披露 CVE 偏向严重漏洞，未披露漏洞不进入统计），平均 CVSS 不等于实际漏洞严重性分布；0 信任原则适用：统计显著 ≠ 实际显著，CVSS 评分是 NVD 评估而非实际可利用性评估，Heartbleed CVSS 7.5 与 OpenBSD 平均 CVSS 6.17 的对比仅反映 NVD 评分维度，不等于实际攻击难度或影响范围；【存疑判定依据】（1）LibreSSL fork 决议的精确日期存疑：2014-04 为社区共识月份，精确到日待 <misc@openbsd.org> 邮件列表存档核验；（2）LibreSSL 首次 portable 发布的精确版本号存疑：2014-07-11 为社区共识日期，具体版本号（如 2.0.0 或其他）须以 libressl.org 官网存档为准 [考据完成：2026-07-28 LibreSSL fork 决议的精确日期与首次 portable 发布的具体版本号须以 OpenBSD 邮件列表存档与 libressl.org 官网存档交叉核验]
