# 209.4 项目统摄史观审视续：从总纲第 13、19、21 条看三大 fork 的许可证哲学与利益分配

**要点**：本节从项目史观总纲第 13 条（法律与道德是利益分配）、第 19 条（解释学循环是历史认识的根本条件）、第 21 条（革命与改革是历史方法论的分歧）切入，补充前此从第 15、19、21 条切入的三大 fork 辩证链审视（原引旧大纲章号 93.10，结构重组后宿主节待回源定位），重点在许可证哲学与利益分配维度；总纲第 13 条揭示三大 fork 的许可证选择与资金流向构成利益分配的具体显现——三者中仅 LibreSSL 系 OpenSSL 的真 fork（fork 后保留 OpenSSL 原始许可证并附加 ISC 许可证条款），OpenNTPD 系 Henning Brauer 作为 OpenBSD 项目一部分的全新实现（OpenNTPD 主页明确“freely usable and re-usable by everyone under a BSD license”），OpenSMTPD 系 Gilles Chehade、Eric Faurot 自 2007 年起的全新 SMTP 实现（与 OpenBSD 工程传统一致），三者均选择宽松许可证，但所面对或替代的上游与既有实现许可证各异——LibreSSL 面对的上游 OpenSSL 已于 2017 年宣告重授权、自 3.0.0（2021 年）起实际适用 Apache 2.0 许可证（提供专利保护条款），被 OpenNTPD 替代的 NTP Classic 采用 NTP License（University of Delaware 1992-2015 + Network Time Foundation 2011-2020 双重版权，含广告条款限制，即“the name University of Delaware not be used in advertising or publicity pertaining to distribution of the software without specific, written prior permission”），被 OpenSMTPD 替代的 sendmail 采用 Sendmail License；CII 资金流向 OpenSSL 而非 LibreSSL，反映资金方对“原项目 + 改革路线”的偏好——利益分配通过资金机制实现，“资助原项目”的改革路线偏好本身就是利益分配的形式主义化；总纲第 19 条从许可证角度审视解释学循环——OpenBSD 阵营以“宽松许可证促进社区贡献”为前理解（ISC/BSD 许可证选择即为先前理解的显现），上游或被替代方以“特定许可证保护商业利益与专利风险”为前理解（OpenSSL 重授权并切换 Apache 2.0 即为先前理解的显现），两类前理解的差异使许可证选择成为争议焦点；权力与知识在许可证叙事中共谋——LibreSSL 阵营通过“ISC 许可证最宽松”叙事建构道德优势，OpenSSL 阵营通过“Apache 2.0 提供专利保护”叙事建构法律优势，Network Time Foundation 通过“NTP License 保护参考实现地位”叙事建构权威优势，三者均为形式主义化的非存在，不宣称呈现历史本身；总纲第 21 条在许可证层面显现革命与改革的张力——三大 fork 选择新许可证是革命路线的一部分，其中仅 LibreSSL 与上游许可证构成真断裂（OpenNTPD、OpenSMTPD 系全新实现的功能替代），但许可证革命不等于代码革命——LibreSSL 在许可证上选择 OpenSSL/ISC 但在 API 上仍保留 OpenSSL 兼容（portable 版本），OpenSMTPD 在许可证上选择 ISC 但在协议上仍遵循 SMTP（RFC 5321），OpenNTPD 在许可证上选择 BSD 但在协议上仍遵循 NTP（RFC 5905），革命路线在许可证层面彻底（更换许可证相对简单）但在协议层面妥协（改变协议生态依赖需长期工作），反映“破山中贼易（更换许可证）但破心中贼难（改变协议生态依赖）”的辩证

**史观**：总纲第 13 条——法律与道德是利益分配：三大 fork 的许可证选择与资金流向构成利益分配的具体显现——LibreSSL 的 OpenSSL/ISC 许可证、OpenNTPD 的 BSD 许可证、OpenSMTPD 的 ISC 许可证均选择宽松许可证，但所面对或替代的上游与既有实现许可证各异（OpenSSL Apache 2.0、NTP Classic NTP License、sendmail Sendmail License；其中仅 LibreSSL 与上游 OpenSSL 构成真 fork 关系），许可证差异影响各实现的商业采用——OpenSSL 的 Apache 2.0 提供专利保护条款使其更受企业青睐，OpenNTPD 的 BSD 许可证最宽松但仍未获得商业 NTP 厂商青睐，证明许可证并非市场采用的唯一决定因素；CII 资金流向 OpenSSL 而非 LibreSSL 反映“资助原项目”的改革路线偏好，Network Time Foundation 依靠捐赠维持 NTP Classic 与 NTS 标准化，Chrony 由 Red Hat 资助维护——利益分配通过资金机制实现，“改革路线 + 基金会资助”的利益分配模式在 OpenSSL/NTP Classic 案例中取得市场主导，“革命路线 + 社区维护”的利益分配模式在 LibreSSL/OpenNTPD/OpenSMTPD 案例中仅在 OpenBSD 生态内成功；总纲第 19 条——解释学循环是历史认识的根本条件：许可证选择本身即是前理解的显现——OpenBSD 阵营以“宽松许可证促进社区贡献”为前理解（ISC/BSD 许可证选择即为先前理解的显现），OpenSSL 阵营以“Apache 2.0 提供专利保护”为前理解（2017 年宣告重授权、2021 年 3.0.0 起实际适用即为先前理解的显现），Network Time Foundation 以“NTP License 保护参考实现地位”为前理解（University of Delaware 版权延续即为先前理解的显现），三类前理解不可通约使许可证选择成为争议焦点；权力与知识在许可证叙事中共谋——LibreSSL 阵营通过“ISC 许可证最宽松”叙事建构道德优势，OpenSSL 阵营通过“Apache 2.0 提供专利保护”叙事建构法律优势，Network Time Foundation 通过“NTP License 保护参考实现”叙事建构权威优势，各方叙事均倾向自身立场，本节的“合图”亦须按自反原则审视其形式主义性质；总纲第 21 条——革命与改革是历史方法论的分歧：三大 fork 选择新许可证是革命路线的一部分，其中仅 LibreSSL 与上游许可证构成真断裂（OpenNTPD、OpenSMTPD 系全新实现的功能替代），但许可证革命不等于代码革命——LibreSSL 在许可证上选择 OpenSSL/ISC 但在 API 上仍保留 OpenSSL 兼容（portable 版本），OpenSMTPD 在许可证上选择 ISC 但在协议上仍遵循 SMTP（RFC 5321），OpenNTPD 在许可证上选择 BSD 但在协议上仍遵循 NTP（RFC 5905）；革命路线在许可证层面彻底（更换许可证相对简单）但在协议层面妥协（改变协议生态依赖需长期工作），改革路线在许可证层面渐进（OpenSSL 从原始许可证到 Apache 2.0 的切换）但在协议层面稳定（NTP/SMTP 协议本身未变），二者在 2014-2026 年间各自呈现——这不是“一方胜利”而是各自主体的呈现与和解
