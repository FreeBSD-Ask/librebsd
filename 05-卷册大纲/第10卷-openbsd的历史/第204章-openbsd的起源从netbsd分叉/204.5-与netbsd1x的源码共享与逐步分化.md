# 204.5 与 NetBSD 1.x 的源码共享与逐步分化

**要点**：OpenBSD fork 自 NetBSD 1.0，早期代码与 NetBSD 共享比例较高，至 2.x 系列逐步分化；OpenBSD 2.0（1996-10）后逐步引入 `strlcpy`/`strlcat`（1998-07-01 millert commit 1dc0268a4106，见第 91 章考据）、`arc4random` 等 OpenBSD 专有 API，源码共享比例持续下降；两个项目的分化路径是 “安全审计” 与 “可移植性” 两条 BSD 哲学方向的具体显现——OpenBSD 投入工程资源逐行审计基本系统源码，NetBSD 投入工程资源移植至更多硬件平台

**史料**：OpenBSD 1.x 与 NetBSD 1.x Release Notes（<https://www.openbsd.org/plus.html>、<https://www.netbsd.org/releases/formal.html>）；两项目 CVS 源码对照（<https://cvsweb.openbsd.org/>、<https://cvsweb.netbsd.org/>）；openbsd.duckdb openbsd-src 仓库 commit 1dc0268a4106（1998-07-01 millert “add strlcpy/strlcat”，lib/libc/string/strlcpy.c 与 strlcat.c 首次引入）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 19 条——解释学循环是历史认识的根本条件：OpenBSD 选择 “安全至上”（投入工程资源逐行审计基本系统源码），NetBSD 选择 “可移植至上”（投入工程资源移植至更多硬件平台），二者的技术选择各自扎根于不同的前理解预设——前者以 “代码可审计为可信来源” 为预设，后者以 “运行于一切硬件为自由之基” 为预设，前理解的差异使两条路线的分歧不可避免；总纲第 4 条——分离聚合是永恒规律：OpenBSD 从 NetBSD 1.0 分离后逐步聚合自有的安全 API（strlcpy/strlcat、arc4random），这些 API 后续又从 OpenBSD 分离并聚合入 FreeBSD、NetBSD、glibc 等其他系统——分离与聚合的方向随时间反转，OpenBSD 从 NetBSD 的接收者变为向 NetBSD 的贡献者

**辨析**：代码共享比例 “约 90%” 在不同叙事中存在差异——该数字为早期二手资料的概括性估计，精确比例须以 OpenBSD 1.x 与 NetBSD 1.x 源码 diff 为准 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；OpenBSD fork 自 NetBSD 1.0 而非 1.1——openbsd.duckdb 显示 openbsd-src 仓库最早 commit 为 1995-10-18 “initial import of NetBSD tree”，NetBSD 1.0 发布于 1994-10，NetBSD 1.1 发布于 1995-11，fork 时间在 NetBSD 1.1 发布前，故 fork 基础为 NetBSD 1.0

**文献**：OpenBSD 1.x Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>；NetBSD 1.x Release Notes [EB/OL]. <https://www.netbsd.org/releases/formal.html>；OpenBSD CVS 仓库 [EB/OL]. <https://cvsweb.openbsd.org/>；NetBSD CVS 仓库 [EB/OL]. <https://cvsweb.netbsd.org/>；openbsd.duckdb openbsd-src 仓库 commit 1dc0268a4106（1998-07-01 strlcpy/strlcat 引入） ［A］
