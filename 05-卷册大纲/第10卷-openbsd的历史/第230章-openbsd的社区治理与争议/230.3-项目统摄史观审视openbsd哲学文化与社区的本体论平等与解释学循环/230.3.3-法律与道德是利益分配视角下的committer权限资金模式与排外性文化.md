# 230.3.3 法律与道德是利益分配视角下的 committer 权限、资金模式与排外性文化

**要点**：从项目史观总纲第 13 条“法律与道德是利益分配”审视，OpenBSD 哲学文化与社区的具体形态本质上是利益分配机制——committer 权限的授予与撤销决定了谁有资格直接向 OpenBSD 仓库提交代码，这一资格直接影响个人在 BSD 社区中的声誉、职业发展机会与项目决策参与权；de Raadt 主导的权限管理以“代码可审计为可信来源”为预设，但这一预设本身是利益分配的形式——“已被 OpenBSD 核心圈认可的持续贡献者”获得了 commit 权，而“与 de Raadt 个人风格不合但工程能力合格的贡献者”被排除，这一排除是权力行使而非纯粹的工程考量；“安全至上”哲学亦是利益分配——OpenBSD 以“默认安全”为预设排除了接受 binary blob 的硬件厂商、追求性能优先的用户、容器生态的采用者，这一排除在 OpenBSD 工程哲学下具有合理性但亦是权力行使；资金模式是利益分配——OpenBSD 的志愿模式使志愿开发者以无偿贡献换取技术决策的独立性，这一交换在 OpenBSD 工程哲学下具有合理性但亦是利益分配；排外性文化是利益分配——“RTFM”传统与“公开斥责”风格使风格温和的贡献者、初学者、非英语母语者在邮件列表互动中处于劣势，这一劣势是文化氛围的利益分配效应

**史观**：总纲第 13 条——法律与道德是利益分配：committer 权限的授予与撤销、“安全至上”哲学的工程选择、资金模式的志愿哲学、排外性文化的邮件列表氛围在本体论上皆是利益分配机制的一刻状态

**辨析**：利益分配审视不意味着否定工程合理性——de Raadt 主导的权限管理、“安全至上”哲学、志愿模式、直接风格在 OpenBSD 工程目标下具有合理性，但这一合理性不豁免其作为利益分配机制的性质；【0 信任原则·利益分配与工程合理性的区分】“利益分配”与“工程合理性”是同一治理实践的不同命名，二者不互相否定——OpenBSD 的权限管理既是工程合理性也是利益分配，二者共生而非对立；【0 信任原则·被疏远贡献者视角的对称呈现限度】被疏远贡献者的公开回应存档有限，“利益分配失败”的具体案例须以邮件列表存档与个人公开声明交叉验证，不得以理论推演替代事实考据；【查证来源】项目史观总纲第 13 条原文经 据原文第 25 章 Read 一手核验载明“法律与道德是利益分配”；OpenBSD committer 政策文档与 <misc@openbsd.org> 邮件列表存档经 <https://marc.info/?laccopenbsd-misc> 核验；de Raadt 关于权限管理与资金模式的发言经 <https://marc.info/?laccopenbsd-misc> 核验；被疏远贡献者的公开回应经多源检索（OpenBSD <misc@openbsd.org> 邮件列表存档、互联网档案馆 web.archive.org 的 OpenBSD 邮件列表镜像、各被疏远贡献者个人博客或公开声明）核验；第 94.7-94.10 节辩证链补足史料与辨析字段已核验的一手来源；【交叉验证方法】对照 OpenBSD committer 权限的授予与撤销记录与被疏远贡献者的公开回应的差异，对照“安全至上”哲学的工程选择与被排除群体（接受 binary blob 的硬件厂商、追求性能优先的用户、容器生态的采用者）的诉求差异，对照志愿模式的技术决策独立性与资金紧缺的工程代价的张力，对照“RTFM”传统与“公开斥责”风格的文化氛围与被排斥群体（风格温和的贡献者、初学者、非英语母语者）的体验差异，对照项目史观总纲第 13 条“法律与道德是利益分配”的哲学预设与 OpenBSD 哲学文化社区的具体利益分配机制；【存疑判定依据】被疏远贡献者的公开回应存档有限，“利益分配失败”的具体案例须以邮件列表存档与个人公开声明交叉验证，不得以理论推演替代事实考据；“工程合理性”与“利益分配”的共生关系是史家的形式主义建构而非史料自然呈现 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
