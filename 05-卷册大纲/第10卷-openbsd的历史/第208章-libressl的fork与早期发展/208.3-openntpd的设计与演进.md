# 208.3 OpenNTPD 的设计与演进

**要点**：OpenNTPD 由 Henning Brauer（亨宁·布劳尔） 主导开发，于 OpenBSD 3.6（2004-11-01）首次集成——bsd_commits.db openbsd-src 仓库 henning 于 2004-06-18 commit a66b0f8292c9 添加 ntpd.conf.5，时间早于 3.6 发布约 5 个月；OpenNTPD 作为 ntpd（Network Time Protocol Daemon）的安全替代，强调简洁配置（约 10 行 vs NTP Classic 复杂配置）与安全默认（chroot 与 privilege separation）；OpenNTPD 6.2p1（2017）后 portable 版本由 OpenBSD Foundation 维护

**史料**：OpenNTPD Release Notes（<https://www.openntpd.org/>）；OpenNTPD 手册页 **ntpd(8)**（<https://man.openbsd.org/ntpd.8>）；OpenBSD 邮件列表中 OpenNTPD 相关讨论（<https://marc.info/?laccopenbsd-misc>）；OpenNTPD portable 版本记录（<https://github.com/openntpd-portable/>）；bsd_commits.db openbsd-src commit a66b0f8292c9（2004-06-18 ntpd.conf.5 首次添加）

**史观**：总纲第 8 条——社区文化即技术资产：OpenNTPD 的“简洁配置”文化继承自 OpenBSD 工程传统——约 10 行配置文件对应 OpenBSD“默认安全 + 简洁优先”的双重取向；总纲第 7 条——技术选择即政治选择：OpenNTPD 选择简洁性优先于功能完整性——不支持 NTP Classic 的部分高级功能（如 broadcast/multicast 模式早期不支持），以减少攻击面

**辨析**：OpenNTPD 与 NTP Classic 的功能差异——OpenNTPD 早期不支持 broadcast/multicast 模式、reference clock 驱动较少，至 6.0（2016）后才逐步补齐；OpenNTPD 的时间同步精度争议——NTP Classic 在理想条件下可达微秒级精度，OpenNTPD 因简化算法早期精度为毫秒级，6.0 后通过 constraint 改进提升至接近 NTP Classic 水平；OpenNTPD portable 版本（6.2p1 起）在 Linux 上的兼容性较好但采用率仍低（2024 年统计 Linux 发行版默认 NTP 实现仍为 systemd-timesyncd、chrony 或 NTP Classic）；bsd_commits.db 查询 L2.3.1.openntpd 在中观模式挖掘报告中不存在（报告仅含 L2.3.1.ZFS、L2.3.1.Capsicum、L2.3.1.bhyve、L2.3.1.Clang、L2.3.1.ARM64、L2.3.1.RISC-V 等 FreeBSD 特性查询，未覆盖 OpenBSD OpenNTPD 子系统），OpenNTPD 相关子系统级 commit 数据须以 bsd_commits.db 直接查询 file_path 维度（如 usr.sbin/ntpd/）补全

**文献**：OpenNTPD 项目主页 [EB/OL]. <https://www.openntpd.org/>；OpenNTPD 手册页 **ntpd(8)** [EB/OL]. <https://man.openbsd.org/ntpd.8>；OpenBSD 3.6 Release Notes [EB/OL]. <https://www.openbsd.org/36.html>；OpenNTPD portable 仓库 [EB/OL]. <https://github.com/openntpd-portable/>；bsd_commits.db 查询 L2.3.1.openntpd（来源：原材料/研究/bsd 仓库分析/数据分析/中观模式挖掘.md §L2.3.1，数据缺口） ［A］

**要点**：

- 受访者自述 1997 年末或 1998 年初在新西兰惠灵顿因 ADSL 铺开而需要防火墙，经渔业部同僚赠机与光盘装上 BSD 并在 IRC 提问起步；他坚持记录排错笔记并贴上个人网站，笔记演化成 FreeBSD Diary，并成为日后 FreshPorts 与 BSDCan 的声望起点；2004 年他失业旅居渥太华，目睹本地大型 Linux 会议后受同侪一句“这个家伙能办你也能办”鼓动而创办 BSDCan。　[存疑脚注] 受访者姓名转写失真（Dan LeGuehl/LeGueil），据 FreeBSD Diary、FreshPorts、BSDCan 创办语境判定为 Dan Langille（BSD Now EP70，[1077.28-1321.90]，L1）
- 主持人转述 OpenSSH 的两项安全演进：主机公钥指纹拟由 MD5 十六进制改为 base64 编码的 SHA-256，字符串更短且碰撞空间更小（MD5 对椭圆曲线类易生成密钥的碰撞风险尤高），并新增 FingerprintHash 配置项且串自此区分大小写；同时引入要求同时提交 RSA 与 ED25519 等多把不同类型公钥方可登录的选项，作为对单一密钥体系不完全信任时的双因子加固，两项均计划随 6.8 版本落地。（BSD Now EP70，[736.12-877.52]，L2）
- 主持人补述 OpenBSD 已在基系统与 ports 默认启用 PIE 与 ASLR，使动态链接程序内存布局不可预测，但 /bin、/sbin 等静态链接程序不在其列，反而成为攻击者可预测布局的例外缺口；OpenBSD 5.7（2015 年 5 月发布）引入静态自重定位予以补齐，静态二进制由防护盲区转为受保护对象，防护曲线以补例外的方式继续延伸。（BSD Now EP70，[275.06-348.38]，L2）
- FreeBSD 基金会半年报揭示基金会模式的运转细目：会长信函以降低入门门槛、鼓励学生与新开发者为主线；已资助完成新版视频控制台、集群日志审计分发、更多 ARM 支持与 OpenCrypto 等项目；斥资十万美元为每周包构建购置硬件，并将基础设施自加州 ISC、雅虎机房扩展至纽约 NYI 形成东西海岸全量冗余；发放十八笔差旅资助促成面对面协作；FreeBSD 与 OpenBSD 基金会均超额完成年度募捐目标、NetBSD 接近达标，主持人并观察到捐赠高度集中于年末、倡议年初错峰捐赠。（BSD Now EP70，[389.68-720.46]，L2）

**史料**：

- 期内可回溯的一手材料包括：Dan Langille 关于 BSDCan 创办与 FreeBSD Diary 起源的口述；Theo de Raadt 在 OpenBSD tech 邮件列表比较 ISC NTPD 与 OpenNTPD 的帖子原文引读（含 OpenNTPD 由 Henning Brauer 应 Theo 之请从零编写的自述）；Poul-Henning Kamp 关于 ntimed 重写决策的邮件与博客；Alfred Perlstein 在 FreeBSD 邮件列表提出的 OVA 虚拟机镜像封装提案与 em0 读法玩笑；FreeBSD 基金会半年报；另有 AsiaBSDCon 历年视频与 BSDTalk 第 68 期 Bob Beck 谈 spamd 的旧档指引。（BSD Now EP70，[4452.10-4702.76]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：BSDCan 的诞生链条没有一处结构必然：新西兰 ADSL 铺设的时机、渔业部一位 BSD 爱好者的偶然赠机、美国 BSD 会议停办留下空窗、USENIX 附设轨道“不等于真正拥有 BSD 会议”、渥太华 Linux 会议组织者恰好现身本地用户组、失业带来的大量空余时间，环环皆为具体事件与偶然条件的串联；口述者对成事的交代仅止于“people came”，未提供任何趋势性或规律性论证。（BSD Now EP70，[1077.28-1295.96]，L1）
- 总纲10 动手者创造历史：本期把叙事重心交给维持系统运转的一线实践者：写排错日记者促成社区声望与会议创办，受访者用 Ansible、ZFS 与 jails 把六十余个监牢的升级压缩进一个晚上，poudriere 私有包仓库使 Puppet 部署从四十五分钟缩至六分钟；主持人补述在宿主机以 fail2ban 配 IPFW 观察各监牢日志并统一封禁。会议组织者、写日记者、运维者而非发布宣言的领袖，构成这期口述的历史主体。（BSD Now EP70，[2201.28-2286.60]，L1）

**辨析**：

- “重写优于修补”在本期呈现为一条贯穿的工程判断：Theo 称 OpenNTPD 不足五千行而 ntpd.org 代码已从十万行膨胀至三十万行且大量为无人维护的陈年补丁，类比 OpenSSL“人人添砖、无人清扫”的困境；PHK 在 Linux 基金会资助（心脏出血事件催生的核心基础设施应对背景）下判定修补旧 NTPD 不如从零写 ntimed，预期 2015 年第一季度给出生产级版本；但“六十六倍体积并不等于六十六倍精度”“真正在意精度者做时间分发而非接收”属当事者单方论证，客户端“大致正确即可”的适用边界未经中立检验，且行数对比缺乏独立核验。　[存疑脚注] 代码行数与膨胀史为 Theo 邮件单方陈述，转写未附原帖链接；66 倍对比与精度论断均未独立核验（BSD Now EP70，[4546.84-4687.82]，L1）
