# 207.4 OpenSMTPD 的设计与演进


- 要点：OpenSMTPD 由 Gilles Chehade、Eric Faurot、Charles Longeau 等主导开发，2008 年发起项目作为 sendmail/Postfix 的安全替代；OpenSMTPD 于 OpenBSD 4.6（2009-11）首次集成；2013 年 5.4 版本起默认使用，采用简洁配置语法与 privilege separation 安全默认；OpenSMTPD 历史上有多个本地提权漏洞（如 CVE-2020-8794）——须区分 OpenSMTPD（2008 年发起的 mail transfer agent）与早期 Obtuse smtpd（bsd_commits.db 显示 beck 于 1997-12-12 commit acd4d1eb0a4d"Obtuse smtpd v 2.0 source tree import"，二者仅名字相近但非同一项目）
- 史料：OpenSMTPD Release Notes（<https://www.opensmtpd.org/>）；OpenSMTPD 手册页 **smtpd(8)**（<https://man.openbsd.org/smtpd.8>）；OpenBSD 邮件列表中 OpenSMTPD 相关讨论（<https://marc.info/?l=openbsd-misc>）；OpenSMTPD 安全漏洞记录；bsd_commits.db openbsd-src commit acd4d1eb0a4d（1997-12-12 Obtuse smtpd v2.0 import，与 OpenSMTPD 不同）
- 史观：总纲第 8 条——社区文化即技术资产：OpenSMTPD 的“简洁配置语法”继承自 OpenBSD 工程传统——smtpd.conf 约 20 行 vs sendmail.cf 数百行的复杂配置，是 OpenBSD“默认安全 + 简洁优先”取向的具体显现；总纲第 7 条——技术选择即政治选择：OpenSMTPD 选择 privilege separation 架构（将 smtpd 进程分为 unprivileged parent、privileged child、control process 等多个进程）是其政治选择——以“最小权限”为预设，宁可以进程间通信开销换取安全
- 辨析：OpenSMTPD 与 Postfix/sendmail 的功能对比——OpenSMTPD 不支持 sendmail 的 milter 接口、Postfix 的部分高级过滤功能，但在基础 SMTP 收发场景下功能完备；OpenSMTPD 的生产部署案例较少——OpenBSD 默认使用 OpenSMTPD，但 FreeBSD/Linux 默认仍为 Postfix 或 sendmail，OpenSMTPD portable 版本采用率不足 1%；CVE-2020-8794 是 OpenSMTPD 远程命令执行漏洞（CVSS 9.8），于 2020-03 修复，是 OpenSMTPD 历史上最严重的安全漏洞；bsd_commits.db 查询 L2.3.1.opensmtpd 在中观模式挖掘报告中不存在（报告仅含 L2.3.1.ZFS、L2.3.1.Capsicum、L2.3.1.bhyve、L2.3.1.Clang、L2.3.1.ARM64、L2.3.1.RISC-V 等 FreeBSD 特性查询，未覆盖 OpenBSD OpenSMTPD 子系统），OpenSMTPD 相关子系统级 commit 数据须以 bsd_commits.db 直接查询 file_path 维度（如 usr.sbin/smtpd/）补全
- 文献：OpenSMTPD 项目主页 [EB/OL]. <https://www.opensmtpd.org/>；OpenSMTPD 手册页 **smtpd(8)** [EB/OL]. <https://man.openbsd.org/smtpd.8>；OpenBSD 4.6 Release Notes [EB/OL]. <https://www.openbsd.org/46.html>；CVE-2020-8794 [EB/OL]. <https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2020-8794>；bsd_commits.db 查询 L2.3.1.opensmtpd（来源：原材料/研究/bsd 仓库分析/数据分析/中观模式挖掘.md §L2.3.1，数据缺口） ［A］
