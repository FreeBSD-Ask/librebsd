# 208.4 OpenSMTPD 的设计与演进

**要点**：OpenSMTPD 由 Gilles Chehade、Eric Faurot、Charles Longeau 等主导开发，2008 年发起项目作为 sendmail/Postfix 的安全替代；OpenSMTPD 于 OpenBSD 4.6（2009-11）首次集成；2013 年 5.4 版本起默认使用，采用简洁配置语法与 privilege separation 安全默认；OpenSMTPD 历史上有多个本地提权漏洞（如 CVE-2020-8794）——须区分 OpenSMTPD（2008 年发起的 mail transfer agent）与早期 Obtuse smtpd（openbsd.duckdb 显示 beck 于 1997-12-12 commit acd4d1eb0a4d“Obtuse smtpd v 2.0 source tree import”，二者仅名字相近但非同一项目）

**史料**：OpenSMTPD Release Notes（<https://www.opensmtpd.org/>）；OpenSMTPD 手册页 **smtpd(8)**（<https://man.openbsd.org/smtpd.8>）；OpenBSD 邮件列表中 OpenSMTPD 相关讨论（<https://marc.info/?laccopenbsd-misc>）；OpenSMTPD 安全漏洞记录；openbsd.duckdb openbsd-src commit acd4d1eb0a4d（1997-12-12 Obtuse smtpd v2.0 import，与 OpenSMTPD 不同）

**史观**：总纲第 8 条——社区文化即技术资产：OpenSMTPD 的“简洁配置语法”继承自 OpenBSD 工程传统——smtpd.conf 约 20 行 vs sendmail.cf 数百行的复杂配置，是 OpenBSD“默认安全 + 简洁优先”取向的具体显现；总纲第 7 条——技术选择即政治选择：OpenSMTPD 选择 privilege separation 架构（将 smtpd 进程分为 unprivileged parent、privileged child、control process 等多个进程）是其政治选择——以“最小权限”为预设，宁可以进程间通信开销换取安全

**辨析**：OpenSMTPD 与 Postfix/sendmail 的功能对比——OpenSMTPD 不支持 sendmail 的 milter 接口、Postfix 的部分高级过滤功能，但在基础 SMTP 收发场景下功能完备；OpenSMTPD 的生产部署案例较少——OpenBSD 默认使用 OpenSMTPD，但 FreeBSD/Linux 默认仍为 Postfix 或 sendmail，OpenSMTPD portable 版本采用率不足 1%；CVE-2020-8794 是 OpenSMTPD 远程命令执行漏洞（CVSS 9.8），于 2020-03 修复，是 OpenSMTPD 历史上最严重的安全漏洞；openbsd.duckdb 查询 L2.3.1.opensmtpd 在中观模式挖掘报告中不存在（报告仅含 L2.3.1.ZFS、L2.3.1.Capsicum、L2.3.1.bhyve、L2.3.1.Clang、L2.3.1.ARM64、L2.3.1.RISC-V 等 FreeBSD 特性查询，未覆盖 OpenBSD OpenSMTPD 子系统），OpenSMTPD 相关子系统级 commit 数据须以 openbsd.duckdb 直接查询 file_path 维度（如 usr.sbin/smtpd/）补全

**文献**：OpenSMTPD 项目主页 [EB/OL]. <https://www.opensmtpd.org/>；OpenSMTPD 手册页 **smtpd(8)** [EB/OL]. <https://man.openbsd.org/smtpd.8>；OpenBSD 4.6 Release Notes [EB/OL]. <https://www.openbsd.org/46.html>；CVE-2020-8794 [EB/OL]. <https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2020-8794>；openbsd.duckdb 查询 L2.3.1.opensmtpd（来源：原材料/研究/bsd 仓库分析/数据分析/中观模式挖掘.md §L2.3.1，数据缺口） ［A］

**要点**：

- OpenSMTPD 的起点是 OpenBSD 基础系统中缺乏 BSD 许可的 SMTP 服务器；Gilles Chehade 因 sendmail 过于复杂、无法修补而自行编写简单 SMTP 服务器。（BSD Now EP3，[653.72-703.80]，L1）
- OpenSMTPD 的配置语法受 PF 规则语言启发，以逐行规则、首次匹配求值的方式描述邮件路由，追求简洁可读与安全默认值。（BSD Now EP3，[1231.08-1383.62]，L1）
- PackageNG 由 Baptiste Daroussin 开发，在旧 pkg_* 工具之上提供升级、仓库签名与 SQLite 包数据库，并以 pkg install、pkg upgrade 等命令替代旧式安装流程。（BSD Now EP3，[1820.78-1889.22]，L1）
- OpenZFS 在 LinuxCon 上宣布成立，FreeBSD、ZFS on Linux、illumos 等各方协作维护开源 ZFS，并以特性标志与版本统一降低各实现差异。（BSD Now EP3，[2935.46-3032.28]，L2）

**史料**：

- 当事人 Gilles Chehade 自述 2000 年前后开始使用 OpenBSD（约 2.8 版），2007 年成为开发者，先后参与 RelayD 与 OpenSMTPD。（BSD Now EP3，[559.32-641.36]，L1）
- 当事人 Eric Faurot 自述其以编写异步 DNS 库切入 OpenSMTPD，数小时内即被整合，后持续清理与维护代码库。（BSD Now EP3，[710.20-785.76]，L1）
- 当事人提及 Charles Longeau 编写可移植层，使 OpenSMTPD 得以在 Linux、FreeBSD、NetBSD 等系统运行，并带来更大的测试与使用者覆盖。（BSD Now EP3，[804.20-811.20]，L1）

**史观**：

- 总纲9 经验优先：OpenSMTPD 源于 Gilles Chehade 在实际维护邮件系统时遭遇 sendmail 无法修补的具体困境，是经验先行、因需而作的工程起点。（BSD Now EP3，[653.72-703.80]，L1）
- 总纲4 分离聚合是永恒规律：Oracle 关闭 OpenSolaris 源码后，各平台分散的 ZFS 实现以 OpenZFS 重新聚合为统一治理结构，是分离与聚合的具体呈现。（BSD Now EP3，[2935.46-3032.28]，L2）
- 总纲8 本体论上各方平等：OpenSMTPD 通过可移植层与回注队列的接口兼容第三方工具，使不同平台与不同邮件软件处于平等可接入的位置。（BSD Now EP3，[804.20-890.16]，L1）

**辨析**：

- OpenSMTPD 过滤 API 当时尚未发布，开发者为避免 API 未定型即被采用而延迟推出，其最终形态与发布时间未定。　[存疑脚注] OpenSMTPD 过滤 API 的发布时间在当时仅属路线图计划，须以后续正式发布为准。（BSD Now EP3，[1106.32-1221.56]，L4）
