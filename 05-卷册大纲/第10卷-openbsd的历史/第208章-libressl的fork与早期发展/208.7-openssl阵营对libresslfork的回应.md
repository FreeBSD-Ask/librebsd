# 208.7 OpenSSL 阵营对 LibreSSL fork 的回应

**要点**：OpenSSL 阵营对 LibreSSL fork（2014-04-14 宣告）的回应可归纳为四条线索；第一，OpenSSL Software Foundation 主席 Steve Marquess 于 2014-04 在 OpenSSL 官方博客发文反思 Heartbleed 暴露的资金紧缺问题——OpenSSL 项目长期每年仅约 2000 美元捐款、仅雇佣一名全职开发者（Stephen Henson），Marquess 呼吁“至少应有六名无商务缠身的专职 OpenSSL 开发成员”，这是 OpenSSL 阵营对 fork 的间接回应——承认问题但拒绝 LibreSSL 的 fork 路线，主张通过资助原项目解决问题；第二，OpenSSL 项目于 2014-07 在官方网站发布路线图（roadmap），承认缺乏代码审查、不一致的编码风格、糟糕的文档记录、没有平台战略、没有定期发布周期等问题，但批评外界认为 OpenSSL“发展非常缓慢并且孤立”的观点，这是 OpenSSL 阵营对 LibreSSL 阵营（Ted Unangst 在 EuroBSDCon 2014 演讲“LibreSSL: More Than 30 Days Later”中对 OpenSSL 代码质量的系统性批评）的官方回应；第三，Linux Foundation 联合 Red Hat、Google、Microsoft、Facebook、IBM、Intel、Cisco、AWS 等公司于 2014-04 发起 Core Infrastructure Initiative（CII），每年向 OpenSSL 等关键开源项目提供数百万美元资助，OpenSSL 阵营借此进行代码重构——这是 OpenSSL 阵营以“改革路线”回应 LibreSSL 阵营“革命路线”的具体实践；第四，OpenSSL 阵营的隐性批评者通过 LibreSSL portable 版本早期问题质疑 fork 路线——安全研究员 Andrew Ayer 于 2014-10 前后发现 LibreSSL portable 在 Linux 上的伪随机数生成器（PRNG）实现存在“灾难性失败”（因 16 位 PID 在多进程间重复导致 PRNG 状态可预测），被 OpenSSL 阵营解读为 LibreSSL 在非 OpenBSD 平台上“水土不服”的证据

**史料**：Steve Marquess 2014-04 OpenSSL 官方博客 Heartbleed 反思文（OpenSSL Blog，原始链接 <https://www.openssl.org/blog/>，互联网档案馆存档须查询）；OpenSSL 项目 2014-07 路线图（OpenSSL 官方网站 <https://www.openssl.org/about/>，原始 roadmap 页面经 51CTO 2014-07-04 编译报道证实存在）；Linux Foundation Core Infrastructure Initiative 官方页面（<https://www.coreinfrastructure.org/>，记载发起方公司与资助金额）；LibreSSL EuroBSDCon 2014 演讲“LibreSSL: More Than 30 Days Later”by Ted Unangst（<https://www.openbsd.org/papers/eurobsdcon2014-libressl.html>，LibreSSL 阵营对 OpenSSL 代码质量的系统性批评，含 FIONBIO、socklen_t、optionmania、SRP timeline 等具体案例分析）；Andrew Ayer 关于 LibreSSL PRNG 漏洞的报告（Ars Technica 2014 报道，原始漏洞公告须查询 LibreSSL 邮件列表存档 <https://marc.info/?l=libressl>）

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧：LibreSSL fork 是革命路线（彻底删除 70,000 行代码、移除 SSLeay 兼容层、新建 libtls API），OpenSSL CII 资助 + 路线图重构是改革路线（保留代码库、渐进改善代码审查与发布周期），二者构成历史方法论分歧——革命路线破山中贼易（一次性删除代码）但破心中贼难（让 Linux 发行版接受 LibreSSL），改革路线破山中贼难（在原代码库上渐进改善）但破心中贼易（保留与下游的兼容性）；总纲第 12 条——法律结构：OpenSSL 的 Apache 2.0 许可证（2018 年起）与 LibreSSL 的 OpenSSL/ISC 许可证、CII 资金流向 OpenSSL 而非 LibreSSL——法律与资金结构共同塑造了二者的市场命运，CII 选择资助 OpenSSL 而非 LibreSSL 反映了“资助原项目”的改革路线偏好；总纲第 13 条——法律与道德是利益分配：OpenSSL 阵营“承认问题但拒绝 fork 路线”的姿态本质上是利益分配之争——fork 后 OpenSSL Software Foundation 的资金来源与影响力将受威胁，CII 资金的分配亦依赖 OpenSSL 项目的持续存在

**辨析**：考据过程留痕——【查证来源】Ted Unangst EuroBSDCon 2014 演讲“LibreSSL: More Than 30 Days Later”经 <https://www.openbsd.org/papers/eurobsdcon2014-libressl.html> 一手核验，演讲中 FIONBIO、socklen_t、optionmania、SRP timeline 等具体案例批评确实存在；Linux Foundation Core Infrastructure Initiative 官方页面经 <https://www.coreinfrastructure.org/> 一手核验，记载发起方公司与资助机制；Andrew Ayer 关于 LibreSSL PRNG 漏洞的报告经 WebSearch 核验（Ayer 身份为 Opsmate 创始人，将漏洞称为“伪随机数生成器的致命缺陷”），Ars Technica 2014 报道与中文编译（阿里云开发者文章）互证；openbsd.duckdb openbsd-src 仓库 commit b6553af36068（2014-07-12 jsing 引入 lib/libressl/）证实 LibreSSL 在 OpenBSD 源码树内的实现路径，LibreSSL 在 OpenBSD 上使用 arc4random 一致实现不受 portable 版本 PRNG 漏洞影响；【交叉验证方法】四条回应线索各自独立评估——第一条 Marquess 反思与 OpenSSL 后续行动（CII 资助后增加开发者与代码审查）互证，部分印证反思的真诚度；第二条 OpenSSL 路线图承认的五个问题（缺乏代码审查、不一致编码风格、糟糕文档、无平台战略、无定期发布周期）与 Ted Unangst 演讲中的具体案例批评高度对应，证实 LibreSSL 阵营的批评并非空穴来风；第三条 CII 资助与 OpenSSL 1.1.0 重构、1.1.1 LTS、3.0 重构成果互证，2014-2018 年间 OpenSSL 代码质量显著改善，改革路线取得实质成果；第四条 Andrew Ayer PRNG 漏洞仅限 LibreSSL portable 早期 Linux 版本，LibreSSL 在 OpenBSD 上使用 arc4random 一致实现不受影响，故该批评成立但适用范围有限，不可推广为“LibreSSL 在所有平台都不安全”；【存疑判定依据】Steve Marquess 2014-04 OpenSSL 官方博客 Heartbleed 反思文与 OpenSSL 2014-07 路线图的原始链接须查询互联网档案馆存档确认——OpenSSL 官方网站经多次重构，2014
