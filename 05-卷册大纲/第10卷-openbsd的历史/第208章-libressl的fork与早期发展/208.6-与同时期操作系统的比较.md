# 208.6 与同时期操作系统的比较

**要点**：加密库方面，FreeBSD 自 2000-01-18（Kris Kennaway commit 1180a889cf8b“Bump __FreeBSD_version due to openssl import”）起将 OpenSSL 作为基础系统加密库，至 FreeBSD 14.0（2023-11-20）仍使用 OpenSSL 3.0.12（官方公告 <https://www.freebsd.org/releases/14.0R/announce/>），LibreSSL 仅作为 ports 可选；Linux 各发行版（Debian、RHEL、Ubuntu）全程默认 OpenSSL，Heartbleed 后 Red Hat 与 Linux Foundation 于 2014-04 发起 Core Infrastructure Initiative 资助 OpenSSL 重构；OpenBSD 自 5.6（2014-11）起独家使用 LibreSSL；NTP 方面，FreeBSD 基础系统附带的 ntpd 为 NTP Classic 参考实现（David Mills 主导，freebsd.duckdb 显示 freebsd-src 仓库最早 ntpd 相关 commit 在 1990 年代后期），至 2026 年未切换至 OpenNTPD（freebsd.duckdb 查询 freebsd-src 仓库无 usr.sbin/ntpd/ OpenNTPD 引入记录）；Linux 多用 Chrony（RHEL/Fedora 默认）或 NTP Classic（Debian 默认）；OpenBSD 独家采用 OpenNTPD；MTA 方面，FreeBSD 自 1993 年起默认 sendmail（freebsd.duckdb 显示 1993-07-20 Rodney W. Grimes（罗德尼·W·格赖姆斯） 最早 sendmail 相关 commit），2014-02-20 Baptiste Daroussin（巴蒂斯特·达鲁桑） commit c48517e8d3cc“Import dma 89702b7f14 (2013-02-13) into vendors”将 dma（DragonFly Mail Agent）引入 vendor 树，FreeBSD 14.0（2023-11-20）dma 取代 sendmail 成为默认 MTA；Linux 多用 Postfix（Debian/Ubuntu 默认）或 sendmail（RHEL 早期）；OpenBSD 独家采用 OpenSMTPD

**史料**：freebsd.duckdb freebsd-src 仓库 commit 1180a889cf8b（2000-01-18 OpenSSL import 版本 bump）、commit c48517e8d3cc（2014-02-20 dma vendor import）、commit 855ff27c8c84（2015-10-09 dma 目录重组）；freebsd.duckdb freebsd-src 仓库无 lib/libressl 路径文件引入记录（证明 FreeBSD 未将 LibreSSL 引入基础系统）；freebsd.duckdb freebsd-src 仓库无 usr.sbin/ntpd/ OpenNTPD 引入记录（证明 FreeBSD 未引入 OpenNTPD）；FreeBSD 14.0-RELEASE 公告（<https://www.freebsd.org/releases/14.0R/announce/>，明确 OpenSSL 3.0.12）；Linux Foundation Core Infrastructure Initiative（<https://www.coreinfrastructure.org/>）；Chrony 项目（<https://chrony.tuxfamily.org/>）；Postfix 项目（<http://www.postfix.org/>）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 7 条——技术选择即政治选择：FreeBSD 选择继续使用 OpenSSL（而非 fork 或切换至 LibreSSL）是其政治选择——以“兼容性与生态稳定”为预设，宁可通过 CII 资助 OpenSSL 重构也不愿承担 fork 后的维护成本，与 OpenBSD 选择 fork LibreSSL 的路线不同——前者保留上游并资助重构，后者 fork 后精简代码库；OpenBSD 选择独家使用 OpenNTPD/OpenSMTPD（而非沿用 NTP Classic/sendmail）是以“代码可审计为可信来源”为预设，与 FreeBSD/Linux 选择主流实现的路线不同——前者自建工具以牺牲生态成熟度换取代码可审计性，后者沿用主流工具以换取生态成熟度；总纲第 12 条——法律结构：OpenSSL 的 Apache 2.0 许可证（2018 年起）与 LibreSSL 的 OpenSSL/ISC 许可证、OpenSSH 的 BSD 许可证、sendmail 的 Sendmail License 与 dma 的 BSD 许可证——许可证差异影响各系统选型，如 FreeBSD 选择 OpenSSL 而非 LibreSSL 部分原因是 OpenSSL 生态更完整且 CII 资金支持使其维护可持续

**辨析**：各系统安全工具选型的具体差异——FreeBSD 在加密库上选择“保留 OpenSSL + 资助重构”路线（2014 年 CII 资助后 OpenSSL 代码质量显著改善），OpenBSD 选择“fork + 激进清理”路线（LibreSSL 删除 70,000 行代码），二者各自适合其社区规模与维护能力——FreeBSD 有 Foundation 全职员工与企业赞助可跟进 OpenSSL 上游，OpenBSD 仅靠志愿者无法承担 OpenSSL 全量维护故选择 fork 后精简；NTP 方面 FreeBSD 未切换至 OpenNTPD 的原因是 NTP Classic 在精度（微秒级 vs OpenNTPD 早期毫秒级）与功能（broadcast/multicast 模式、reference clock 驱动数量）上更完整，且 FreeBSD 用户群对时间精度需求较高（如金融交易场景）；MTA 方面 FreeBSD 14.0 才将 dma 设为默认（2023-11-20），比 OpenBSD 2009 年集成 OpenSMTPD 晚 14 年——FreeBSD 选择 dma（DragonFly BSD 的轻量实现）而非 OpenSMTPD，原因是 dma 与 sendmail 兼容性更好且代码量更小，OpenBSD 选择从头编写 OpenSMTPD 是其“自给自足”工程传统的延续

**各 BSD/Linux 安全工具选型对比**：

| 组件 | OpenBSD | FreeBSD | Linux（Debian/RHEL） |
| --- | --- | --- | --- |
| 加密库 | LibreSSL（自 5.6 起） | OpenSSL 3.0.12（14.0 起） | OpenSSL（CII 资助重构） |
| NTP | OpenNTPD（自 3.6 起） | NTP Classic | Chrony（RHEL/Fedora）/NTP Classic（Debian） |
| MTA | OpenSMTPD（自 4.6 集成，5.4 默认） | dma（14.0 起默认，2023-11-20）/sendmail（1993 起） | Postfix（Debian/Ubuntu）/sendmail（RHEL 早期） |
| SSH | OpenSSH（自 2.6 起） | OpenSSH（自 4.0 起） | OpenSSH（portable，各发行版） |

**LibreSSL vs OpenSSL 横向对照**：

| 维度 | LibreSSL | OpenSSL |
| --- | --- | --- |
| 设计哲学 | fork 后激进清理（删除 70,000 行代码），“代码可审计为可信来源” | 保留上游代码库，渐进重构（CII 资助后增加开发者与代码审查） |
| 配置复杂度 | 简化（移除 SSLeay 兼容层、新建 libtls API） | 复杂（保留历史兼容性、庞大 API 表面） |
| 安全模型 | 默认禁用不安全算法、arc4random 一致实现 | 逐步禁用不安全算法、引擎/提供者机制 |
| 采用率 | OpenBSD 基本系统独家采用；portable 版本采用率低 | FreeBSD/Linux/macOS 默认；业界事实标准 |
| 许可证 | OpenSSL/ISC 许可证 | Apache 2.0 许可证（2018 年起） |
| 起源 | 2014-04 Heartbleed 后 OpenBSD 发起 fork | 1998 年起 Eric Young/Stephen Henson 主导 |
