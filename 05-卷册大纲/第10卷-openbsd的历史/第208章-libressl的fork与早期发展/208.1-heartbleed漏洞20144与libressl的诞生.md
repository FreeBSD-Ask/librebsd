# 208.1 Heartbleed 漏洞（2014.4）与 LibreSSL 的诞生

**要点**：2014-04-07 OpenSSL 爆发 Heartbleed（CVE-2014-0160）严重漏洞，允许远程攻击者通过 TLS heartbeat extension 读取服务器内存（最多 64KB/请求），影响全球约 17% 的 HTTPS 站点；OpenBSD 项目于 2014-04-14 在 <misc@openbsd.org> 邮件列表发起 LibreSSL fork，由 de Raadt、Bob Beck、Joel Sing（乔尔·辛） 等主导——openbsd.duckdb openbsd-src 仓库 commit b6553af36068（2014-07-12 jsing 提交的 lib/libressl/Makefile、ressl.c、ressl.h 等文件）系新建的 libressl API 库初始版本；fork 本身自 2014-04-14 宣告当日起即在源码树内就地改造 libssl/libcrypto

**史料**：CVE-2014-0160 漏洞公告（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2014-0160>）；OpenSSL Heartbleed 安全通告（<https://www.openssl.org/news/secadv/20140407.txt>）；OpenBSD 邮件列表中 LibreSSL fork 宣告（<https://marc.info/?l=openbsd-misc>）；de Raadt 关于 LibreSSL 的公开声明；openbsd.duckdb openbsd-src commit b6553af36068（2014-07-12 LibreSSL 首次引入）

**史观**：总纲第 5 条——没有必然性，只有偶然性：Heartbleed 偶然催生 LibreSSL——若无 2014-04-07 漏洞曝光，OpenBSD 不会在 2014-04-14 当周即决定 fork OpenSSL，LibreSSL 项目可能延后数年或永不存在；总纲第 13 条——法律与道德是利益分配（存疑）：OpenSSL 治理结构问题（OpenSSL 项目当时由 OpenSSL Software Foundation 管理，资金紧缺导致代码审计不足）是其 fork 的结构性因素

**辨析**：Heartbleed 漏洞的技术细节经 CVE-2014-0160 公告确认——漏洞位于 OpenSSL 1.0.1 至 1.0.1f 的 tls1_process_heartbeat 函数，因缺少边界检查导致缓冲区过读；LibreSSL fork 的动机是“代码质量”与“治理结构”双重——de Raadt 在 2014-04 的 misc@ 邮件列表宣告中明确批评 OpenSSL 代码质量（“OpenSSL is dead to us”），但治理结构问题（OpenSSL 项目长期资金紧缺、缺乏审计）亦是 fork 决策的关键因素。经 [邮件列表库] 验证通过（来源：openbsd-announce 2014-07-11 Bob Beck “First release of LibreSSL portable is available.” 确认 LibreSSL 2.0.0 发布；openbsd-announce 2014-07-13 至 2014-10-16 连续发布公告确认 LibreSSL 2.0.1-2.1.1 密集发布；openbsd-tech 2014-04-27 miod@ 讨论 Heartbleed 后修复，证实 LibreSSL fork 在 2014 年 4-6 月间活跃于邮件列表）。

**要点**：

- Brent Cook 一手自述其入社路径：1998 年前后在得克萨斯大学以 FreeBSD 1/2 运行 web 服务器约三四年，其后在嵌入式公司用 FreeBSD 制作专用防火墙 appliance；在 Boundary 公司的跨平台 agent 中嵌入 OpenSSL 长期受构建缓慢与 API 混乱之苦，Heartbleed 事件后转向替代方案。他以业余时间搭建自动构建环境测试 LibreSSL portable 版约两个月，期间 Theo de Raadt 主动邮件联系他讨论 PRNG 改动，并邀其赴斯洛文尼亚参加 hackathon，最终成为正式 OpenBSD developer。（BSD Now EP48，[1166.52-1321.73]，L1）
- portable 化工程路径：Cook 模仿 BSD makefiles 建立构建框架，选 autoconf/automake 以覆盖 HP-UX 等长尾平台；最大难点在 PRNG——libBSD 的 arc4random 实现不达 OpenBSD 安全标准，libottery 方案亦被 Theo 否定；最终推动 getentropy(2) 新系统调用进入多个平台，使其他操作系统无需模拟 OpenBSD 的 sysctl 接口，内存分配保护等亦重构为可移植层。初版全用 C 而非汇编，其基准测试显示在 Ubuntu 上 LibreSSL 的 C 版块密码反而比 OpenSSL 快近两倍，引入汇编时将按现代编译器能力批判性评估，不再为旧编译器绕弯。（BSD Now EP48，[1404.57-1675.71]，L1）
- Bob Beck 致节目邮件指出：FreeBSD 内置 arc4random 为陈旧实现（仅依赖 RC4 流程、随机性强度不足），OpenBSD 版本在其移植后已重写且行为不同，故 FreeBSD 目前并非受支持的 LibreSSL 运行平台；Ted Unangst 已提交更新 FreeBSD arc4random 的补丁，当时正由 FreeBSD 安全团队评审，通过后方能正式支持 LibreSSL。　[存疑脚注] 转写存在语音识别误差（如 R4Random、Ted Unanks 等），函数与人名细节以邮件原文为准。（BSD Now EP48，[3346.28-3436.28]，L2）
- pkg 1.3.0 发布：历时九个月、新增约 6.7 万行代码、29 位贡献者；引入真正的 SAT 求解器自动处理 Perl、PHP 等多版本升级冲突，不再需要手工 pkg set -o；引入 Capsicum 沙箱代码使多数操作在受控环境执行；重写安装流程以正确处理 SCHG 系统不可变标志；更细粒度的锁提升并行度；扩大 libUCL 使用并简化 API。7 月 23 日发布 1.3.0 后连发 1.3.1、1.3.2、1.3.3 修复，poudriere 仓库构建亦多核化。（BSD Now EP48，[710.35-834.96]，L2）
- 2014 年 4 月 Heartbleed 漏洞披露后，OpenBSD 团队导入 OpenSSL 1.0.1g 并启动 fork：彻底禁用引发漏洞的 heartbeat 扩展，删除约五点五万行针对 VMS、Windows 等平台的移植代码与过时 DES 加密支持，并将内核常规格式（KNF）统一应用于整个代码库以改善可维护性；主持人预期约一年内会出现可移植版本，使其 fork 可用于 FreeBSD 等其他系统。（BSD Now EP33，[849.5-1160.12]，L2）

**史观**：

- 总纲10 动手者创造历史：portable LibreSSL 的发布、测试与集成实际由 Cook（每周约 10 小时的业余投入）与 Bob Beck 两人支撑，改进建议来自 GitHub 议题与各类论坛的散点反馈，Windows 支持长期悬置等待认领者；安全关键基础设施的日常运转依赖少数默默投入的个体，而非有组织的团队。（BSD Now EP48，[1756.61-1830.54]，L1）
- 总纲9 经验优先：可移植性策略的反转：面对 musl libc 提议用条件编译绕过 glibc 保护代码，Cook 拒绝基于运行时检测的变通——不存在安全可靠的方式检测特权环境（进程可能运行在错误内核上）——转而与 musl 开发者合作在上游实现 issetugid 系统调用，结果比任何变通更安全。portable 版不再堆叠兼容层，而是把正确修复推进操作系统与 libc 本体，与 OpenSSL“忍受操作系统所给的一切”的哲学形成对照；其论证是开源项目有能力让正确修复进入上游。（BSD Now EP48，[1892.33-1975.85]，L1）
- 总纲15 文化即形式主义：主持人在复盘 heartbeat 扩展进入 OpenSSL 与 IETF 的过程时指出：Hacker News 用户考据 IETF 邮件列表档案发现提案当年即有反对声音，但标准化结果并不取决于技术逻辑，而取决于邮件列表的参与结构——推动者必然积极发言，认为不必需者通常无意长期参与辩论，因此可疑特性容易通过；技术标准由此是被参与文化塑造的形式产物。（BSD Now EP33，[876.82-922.22]，L2）
- 总纲3 不存在进步，只有权力再分配：OpenBSD 对 OpenSSL 的 fork、大规模删码与全库格式重整，不宜单纯叙述为技术进步：其实质是把加密库的维护权、审计权与规范制定权从既有上游及其缺陷追踪机制收回，重新分配给一个坚持自身工程标准的社区；Heartbleed 事件只是这种权力再分配的触发契机。（BSD Now EP33，[980.74-1160.12]，L2）
