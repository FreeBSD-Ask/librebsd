# 207.5 OpenBSD 安全工具生态的整体格局


- 要点：OpenSSH（deraadt 1999-10-01 commit bf74e864c129“OpenSSH-1.0”，fork 自 SSH 1.2.12）、LibreSSL（jsing 2014-07-12 commit b6553af36068 引入 lib/libressl/，fork 自 OpenSSL）、OpenNTPD（henning 2004-06-18 commit a66b0f8292c9 引入 ntpd.conf.5，从头编写替代 NTP Classic）、OpenSMTPD（2008 年发起，OpenBSD 4.6/2009-11 首次集成，从头编写替代 sendmail/Postfix）四个工具覆盖远程管理、加密、时间同步、邮件传输四大基础组件，时间跨度 1999-2014；其中 OpenSSH 与 LibreSSL 为 fork 既有实现，OpenNTPD 与 OpenSMTPD 为从头编写，四者均以“减少攻击面 + 简洁配置 + privilege separation”为共同工程取向
- 史料：bsd_commits.db openbsd-src 仓库 commit bf74e864c129（1999-10-01 OpenSSH-1.0）、commit b6553af36068（2014-07-12 LibreSSL 引入）、commit a66b0f8292c9（2004-06-18 OpenNTPD ntpd.conf.5）、commit acd4d1eb0a4d（1997-12-12 Obtuse smtpd v2.0 import，与 OpenSMTPD 不同）；OpenBSD 各工具官方主页（<https://www.openssh.com/>、https://www.libressl.org/、https://www.openntpd.org/、https://www.opensmtpd.org/）；de Raadt 关于 OpenSSH fork 的 misc@ 邮件列表发言（<https://marc.info/?l=openbsd-misc>）
- 史观：总纲第 8 条——社区文化即技术资产：OpenSSH 的 privilege separation（Provos 2001 年设计）、LibreSSL 删除 70,000 行代码、OpenNTPD 约 10 行配置文件、OpenSMTPD 的进程分离架构——四者共享 OpenBSD“默认安全 + 简洁优先”的工程传统，该传统自 1996 年代码审计文化起一脉相承，是社区认同的物化产物；总纲第 2 条——分离与聚合：OpenSSH 从 SSH Communications Security 的闭源实现分离后聚合入 OpenBSD 源码树，LibreSSL 从 OpenSSL AGPL 化的治理结构分离后聚合入 OpenBSD 源码树——两次 fork 均因许可证或治理结构与上游分离，OpenNTPD 与 OpenSMTPD 则是从头编写后聚合入 OpenBSD
- 辨析：四个工具的 fork/编写动机存在具体差异，不可统一归因——OpenSSH fork 的直接原因是 Tatu Ylönen 1999 年对 SSH 1.x 收紧许可证（ssh-1.2.12 之前版本为自由许可证，之后版本加入商业使用限制），OpenBSD 由此 fork ssh-1.2.12 最后一个自由版本；LibreSSL fork 的直接原因是 2014-04-07 Heartbleed 漏洞（CVE-2014-0160）暴露 OpenSSL 代码质量问题与治理结构缺陷（OpenSSL 项目当时资金紧缺、缺乏审计），双重动机促成 fork；OpenNTPD 并非 fork 而是 Henning Brauer（亨宁·布劳尔） 从头编写，动机是 NTP Classic 配置复杂（数百行配置文件）且历史安全漏洞较多（如 CVE-2001-0414）；OpenSMTPD 同样从头编写，动机是 sendmail.cf 配置文件过于复杂且 sendmail 历史安全漏洞众多（如 1988 年 Morris 蠕虫利用 sendmail 漏洞）——“安全工具生态”作为事后归纳的分析框架，其内部动机差异远大于统一叙事所暗示的同质性
