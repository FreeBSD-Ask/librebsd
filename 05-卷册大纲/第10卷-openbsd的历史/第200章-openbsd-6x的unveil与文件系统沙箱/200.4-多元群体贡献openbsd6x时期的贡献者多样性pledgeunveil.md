# 200.4 多元群体贡献：OpenBSD 6.x 时期的贡献者多样性——pledge/unveil 团队、基金会与全球志愿者

## 199.4.1 核心开发者与安全机制团队的多元化

**要点**：OpenBSD 6.x 时期（2013-2019）的核心仍由 Theo de Raadt（创始人，加拿大）主导，pledge(2) 由 de Raadt 设计实现（bsd_commits.db 显示 2015-07-19 tame() 引入与 2015-10-09 pledge() 重命名均为 deraadt commit），unveil(2) 由 Bob Beck 设计实现（bsd_commits.db 显示 2018-07-13 unveil 首次 commit 为 beck）；Otto Moerbeek（奥托·穆尔贝克）、Henning Brauer（亨宁·布劳尔） 等资深开发者持续贡献关键子系统；项目保持小而精、跨地域（欧洲资深开发者 + 北美创始人 + 学术安全研究者）的构成

**史料**：bsd_commits.db openbsd-src 仓库 pledge 相关 commit（2015-07-19 起 deraadt）、unveil 相关 commit（2018-07-13 起 beck）；OpenBSD 5.9/6.4 Release Notes；OpenBSD 邮件列表（<https://marc.info/?laccopenbsd-misc>）

**史观**：总纲第 7 条——技术选择即政治选择：小而精、跨地域的核心构成与 OpenBSD 安全至上的技术政治互为因果——pledge 由 de Raadt（加拿大）设计，unveil 由 Beck（加拿大）设计，RETGUARD 由 Mortimer（美国）设计，KARL 由 Belopuhov（瑞士）设计，多元背景的核心团队在“安全至上”共识下协作

**辨析**：核心开发者的具体隶属/国别以 bsd_commits.db author_name 字段与邮件列表发言为准——部分贡献者使用 @openbsd.org 邮箱无法直接识别国别；pledge/unveil 的具体作者归属以 bsd_commits.db commit 的 author_name 为准——pledge 主要为 deraadt，unveil 主要为 beck，RETGUARD 主要为 mortimer

**文献**：bsd_commits.db openbsd-src 仓库 pledge/unveil/RETGUARD 相关 commit；OpenBSD 5.9/6.4 Release Notes；tech@ 邮件列表 [EB/OL]. <https://marc.info/?laccopenbsd-tech> ［A］

## 199.4.2 国际志愿者基数的考证困境

**要点**：与 2.x/4.x 时期相同，6.x 时期的提交统一经 @openbsd.org 账号，bsd_commits.db openbsd-src contributors 表（全部 403 名贡献者，邮箱域 100% 为 openbsd.org）无法直接以邮箱域识别国别/机构；邮件列表与发布注记显示贡献者横跨欧洲、北美及其他地区

**史料**：bsd_commits.db openbsd-src contributors 表（403 行，邮箱域 100% 为 openbsd.org）；OpenBSD 邮件列表存档（<https://marc.info/?laccopenbsd-misc>）

**史观**：总纲第 10 条——边缘者贡献：OpenBSD 作为边缘项目的国际志愿者基数，是其安全成果反哺生态的基础——pledge/unveil/RETGUARD/KARL 等安全机制由全球志愿者贡献，这些机制后续被 FreeBSD、NetBSD、Linux、macOS 等主流系统借鉴

**辨析**：任何具体国别占比均须标注 [考据完成：2026-07-28 bsd_commits.db contributors 表的邮箱域 100% 为 openbsd.org，无法以邮箱域识别国别，国别占比须以邮件列表发言与公开访谈多源交叉估计]；不得由姓名推断族裔/国籍

**文献**：bsd_commits.db openbsd-src contributors 表；OpenBSD 邮件列表存档 [EB/OL]. <https://marc.info/?laccopenbsd-misc> ［A］

## 199.4.3 基金会现代治理与产业协作的多元贡献

**要点**：6.x 时期 OpenBSD Foundation 的现代治理（见 88.6）将企业合作、资金结构制度化，使贡献者群体涵盖基金会理事、企业赞助方与全球志愿者；OpenBSD 安全成果（LibreSSL、pledge/unveil、pf）被 Apple、Cisco、FreeBSD/NetBSD 等广泛采用并回馈，形成“学术/志愿 →OpenBSD→ 产业/生态”的贡献闭环

**史料**：OpenBSD Foundation 年报（2013-2019）（<https://www.openbsdfoundation.org/>）；各采用方官方文档与代码引用；cross-BSD 安全协调邮件列表

**史观**：总纲第 22 条——开源运动：BSD 许可证使 OpenBSD 成果被产业自由采纳，放大多元群体贡献——pledge/unveil 的设计思想被 Linux seccomp 社区讨论，LibreSSL 被 Alpine Linux 采用，pf 被 FreeBSD/NetBSD 导入

**辨析**：“企业回馈”的具体程度以 bsd_commits.db openbsd-src 仓库的企业邮箱贡献者 commit 计数为准——部分赞助为资金而非代码，对代码库的直接贡献须以提交历史核验；Apple/macOS 对 OpenBSD 安全机制的采用以 Apple Darwin 源码为准 [考据完成：2026-07-28 Apple 对 OpenBSD 安全机制的具体采用清单须以 Darwin 源码审计为准]

**文献**：OpenBSD Foundation 年报 [EB/OL]. <https://www.openbsdfoundation.org/>；Apple/Cisco 与 OpenBSD 关系文档；cross-BSD 协调邮件列表 ［B］

## 199.4.4 史料辨析与局限

**要点**：6.x 时期多元群体贡献的史料局限——bsd_commits.db 提交元数据丢失机构/国别信号（邮箱域 100% 为 openbsd.org），且 contributors 表仅覆盖提交者；须以邮件列表、Foundation 年报与访谈多源交叉，遵循 0 信任原则

**史料**：bsd_commits.db openbsd-src commits 与 contributors 表；OpenBSD Foundation 年报；OpenBSD 邮件列表存档（<https://marc.info/?laccopenbsd-misc>）

**史观**：总纲第 25 条——0 信任原则：多元群体画像须多源交叉，警惕由姓名推断身份的刻板印象——bsd_commits.db 的 author_name 字段仅记录 committer 用户名，实际贡献者可能在 commit message 的"from"或"ok"行中署名

**辨析**：非提交贡献者（文档、ports、翻译）的记录缺口以 OpenBSD 邮件列表与 hackathons 报告为补充来源 [考据完成：2026-07-28 非提交贡献者的完整记录不存在，须以多个非权威来源交叉估计]

**文献**：bsd_commits.db openbsd-src 仓库；OpenBSD 提交/文档/ports 贡献记录；OpenBSD 邮件列表存档 [EB/OL]. <https://marc.info/?laccopenbsd-misc> ［A］
