# 218.3.1 **unveil(2)** 的设计与实现

**要点**：**unveil(2)** 是 OpenBSD 6.4（2018-10-25 发布）引入的系统调用，由 Bob Beck 设计实现——openbsd.duckdb 显示 unveil 首次 commit 为 2018-07-13T09:25:22Z beck commit `8b23add8c74b` "Unveiling unveil(2). This brings unveil into the tree, disabled by default"（初始引入时默认禁用，后续在 6.4 release 前启用）；unveil 让进程自愿限制文件系统访问路径，进程调用 `unveil("/etc", "r")` 即可限制仅能读取 /etc 目录；unveil 与 pledge 配合形成双重沙箱——pledge 限制系统调用类别，unveil 限制文件系统访问路径

  **unveil(2) 引入关键 commit 时间线**：

  | 2018-07-13 | `e3a58533f5f8` | beck | Crank minor for unveil |
  | 2018-10-25 | — | OpenBSD | 6.4 release，unveil(2) 正式启用 |

**史料**：openbsd.duckdb openbsd-src 仓库 commit `8b23add8c74b`（2018-07-13 beck “Unveiling unveil(2)”）、commit `e3a58533f5f8`（2018-07-13 beck“Crank minor for unveil”）；OpenBSD 6.4 Release Notes unveil 部分（<https://www.openbsd.org/64.html>）；**unveil(2)** 手册页（<https://man.openbsd.org/unveil.2>）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 17 条——软件工程：unveil 是“最小权限”原则在文件系统访问中的实现——进程自愿声明所需访问的文件路径，内核据此拒绝越权路径访问，这一设计将文件系统安全约束从全局文件系统权限转移至程序自身声明

**辨析**：[2026-08-15 邮件列表库验证通过]：2018-07-13 openbsd-tech Jason McIntyre “typos in unveil(2)” 确认 unveil(2) 手册页已存在，2018-07-17 Bob Beck “unveil: incorrect type flags” 确认 unveil 代码已进入内核，2018-07-26 Theo de Raadt 发布约 37 程序 unveil 用户态 diff，2018-10-18 OpenBSD 6.4 发布公告确认 unveil(2) 随 6.4 正式启用；unveil 的引入版本——openbsd.duckdb 显示 unveil 首次 commit 为 2018-07-13（beck），初始引入时默认禁用（commit message 明确记载“disabled by default”），后续在 6.4 release 前启用，随 OpenBSD 6.4（2018-10-25）正式发布；unveil 的设计者为 Beck 而非 de Raadt——openbsd.duckdb 显示 unveil 的主要 commit 均由 beck 提交（8b23add8c74b、e3a58533f5f8、fe520198e60d 等），deraadt 仅参与 KNF 格式化等辅助 commit
