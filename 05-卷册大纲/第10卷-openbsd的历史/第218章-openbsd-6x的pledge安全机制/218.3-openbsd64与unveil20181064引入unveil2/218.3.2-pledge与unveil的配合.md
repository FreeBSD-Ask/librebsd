# 218.3.2 pledge 与 unveil 的配合

**要点**：pledge 限制系统调用类别（如“stdio”、“rpath”、“wpath”、“inet”等），unveil 限制文件系统访问路径——两者配合形成完整的权限沙箱；OpenBSD 自带工具（如 **tcpdump(1)**、**nc(1)**、**ftp(1)**）普遍使用 pledge+unveil；这种双重沙箱模式在 BSD/Linux 世界中独特——seccomp 仅限制系统调用，namespaces 仅隔离资源，二者均未提供 pledge+unveil 的“声明式双重限制”模式

**史料**：OpenBSD 用户态工具的 pledge+unveil 使用情况（以 openbsd.duckdb openbsd-src 仓库 usr.bin/ 路径下含 pledge/unveil 调用的 commit 为准）；**pledge(2)** 与 **unveil(2)** 手册页 EXAMPLES 部分（<https://man.openbsd.org/pledge.2>、<https://man.openbsd.org/unveil.2）；tech@> 邮件列表 pledge+unveil 讨论（<https://marc.info/?laccopenbsd-tech>）

**史观**：总纲第 17 条——软件工程：pledge+unveil 的配合是“最小权限”原则的完整实现——pledge 从系统调用维度限制权限，unveil 从文件路径维度限制权限，二者正交组合覆盖了进程权限的主要攻击面

**辨析**：pledge+unveil 的实际防护效果以安全研究论文与漏洞披露记录为准——pledge+unveil 在 OpenBSD Security Advisories 中多次被记录为限制漏洞影响范围的关键机制；OpenBSD 自带工具的 pledge+unveil 覆盖率以 openbsd.duckdb openbsd-src 仓库 usr.bin/ 路径下含 pledge() 或 unveil() 调用的源文件计数为准——基本系统主要用户态工具已普遍采用
