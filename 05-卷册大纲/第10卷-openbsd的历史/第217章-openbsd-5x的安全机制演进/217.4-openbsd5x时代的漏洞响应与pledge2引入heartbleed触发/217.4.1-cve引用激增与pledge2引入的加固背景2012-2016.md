# 217.4.1 CVE 引用激增与 pledge(2) 引入的加固背景（2012-2016）

**要点**：openbsd.duckdb openbsd-src 仓库在 2012-05-01 至 2016-09-01 期间有 CVE 相关 commit 56 条，去重 CVE 57 条（全部无 CVSS v3 评分），Security fix commit（无 CVE）8 条，早期漏洞补遗 0 条；与 4.x 时期（26 条 CVE）相比，5.x 时期 CVE 引用量翻倍，反映 2012-2016 年间漏洞披露与 CVE 编号体系已深度融入 OpenBSD 安全响应流程；57 条 CVE 中 OpenSSL 相关漏洞占绝对多数，这一现实直接推动了 OpenBSD 在 2014 年 4 月 Heartbleed 爆发后 fork OpenSSL 为 LibreSSL；5.x 时期的核心加固机制是 **pledge(2)** 系统调用——2016 年 4 月 OpenBSD 5.9 引入，由 de Raadt 设计实现，允许进程在运行时自愿放弃特定系统调用权限（如 `rpath`、`wpath`、`inet`、`exec` 等），将权限分离从架构级（privsep 拆分进程）推进至系统调用级（单进程内自愿约束），这一机制是“发现漏洞—快速修复—加固重构”循环在 5.x 时期的最高形式——不是修补具体漏洞，而是从根本上限制漏洞被利用后的影响范围；8 条 Security fix commit 涵盖 BIND 上游补丁缓解（sthen commit `d4643ec811dde95e1a418e761c847f64440b50b0`，2011-11-17，CVE-2011-4313）等。

  **OpenBSD 5.x 时期 CVE 与 Security fix 统计**：

  | 类别 | 数量 | 备注 |
  | --- | --- | --- |
  | CVE 相关 commit | 56 | 2012-05-01 至 2016-09-01 |
  | 去重 CVE | 57 | 全部无 CVSS v3 评分 |
  | Security fix commit（无 CVE） | 8 | 含 sthen BIND 上游补丁缓解等 |
  | 早期漏洞补遗 | 0 | — |
  | 对比 4.x 时期 CVE | 26 | 5.x 时期 CVE 引用量翻倍 |
  | OpenSSL 相关 CVE 占比 | 绝对多数 | 直接推动 LibreSSL fork |

**史料**：openbsd.duckdb openbsd-src 仓库（CVE commit 数 = 56，Security fix commit 数 = 8，去重 CVE = 57）；commit `d4643ec811dde95e1a418e761c847f64440b50b0`（2011-11-17 sthen）；OpenBSD 5.9 Release Notes；**pledge(2)** 手册页 [EB/OL]. **<https://man.openbsd.org/pledge.2>** ［A］

**史观**：总纲第 12 条——科学是形式主义（原挂“总纲第 17 条——形式主义化”系伪标签，权威第 17 条为“证明世界先于解释和改造世界”；加固深化论旨依 2026-09-14 核查报告酌挂第 12 条）：**pledge(2)** 将“信任进程的系统调用能力”降级为“进程自愿声明最小系统调用集”，是形式主义化安全机制从架构级到系统调用级的深化；密码学（专题语，不设总纲条号；原挂“总纲第 21 条——密码学”系伪标签，权威第 21 条为“革命与改革是历史方法论的分歧”，依 2026-09-14 核查报告去条号留论旨）：OpenSSL 漏洞群在 5.x 时期的爆发是 LibreSSL fork 的直接驱动力——形式主义化的代码重构（fork）是对加密库实现质量不足的最终回应

**辨析**：57 条 CVE 全部无 CVSS v3 评分——NVD 未为其提取 v3 评分，不可臆造评分；**pledge(2)** 的具体首次引入 commit hash 须考据——5.9 开发周期中的具体 commit；**pledge(2)** 在 5.9 中的基本系统覆盖范围须核验——哪些守护进程率先采用 **pledge(2)**
