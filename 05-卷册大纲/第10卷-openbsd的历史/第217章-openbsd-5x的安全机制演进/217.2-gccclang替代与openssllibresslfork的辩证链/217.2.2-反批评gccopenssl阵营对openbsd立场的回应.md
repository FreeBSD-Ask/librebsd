# 217.2.2 反批评：GCC/OpenSSL 阵营对 OpenBSD 立场的回应

**要点**：GCC 与 OpenSSL 阵营对 OpenBSD 立场的回应集中在三个层面。第一层面是 OpenSSL 项目对 LibreSSL fork 的回应——OpenSSL 项目管理委员会（OpenSSL Project Management Committee）在 2014-2015 年间多次声明 LibreSSL fork“分裂社区”，主张集中精力改进 OpenSSL 而非 fork；OpenSSL 后续版本（1.0.1h、1.0.2、1.1.0）修复 Heartbleed 并重构代码库，OpenSSL 1.1.0（2016-08-25 发布）大规模重构 API 与代码结构，被解读为对 LibreSSL 批评的回应；第二层面是 Linux 与多数项目仍使用 OpenSSL 的事实——OpenSSL 仍是事实标准，LibreSSL 部署规模有限；第三层面是 GCC/FSF 阵营对 clang/LLVM 是 Apple 主导项目的批评——FSF 与部分 GCC 维护者主张 clang/LLVM 由 Apple 公司主导（Apple 是 LLVM 项目最大资金来源），非社区中立，OpenBSD 选择 clang 替代 gcc 是“从一个公司控制转向另一个公司控制”；OpenSSL 阵营部分成员（如 OpenSSL 长期维护者 Stephen Henson 等）在邮件列表主张 LibreSSL 的 API 简化破坏向后兼容性

**史料**：OpenSSL 项目管理委员会关于 LibreSSL fork 的声明（<https://www.openssl.org/blog/>）；OpenSSL 1.1.0 Release Notes（<https://www.openssl.org/news/openssl-1.1.0-notes.html>）；Linux 各发行版 OpenSSL/LibreSSL 选择记录；FSF 关于 clang/LLVM 的官方立场；Apple 与 LLVM 项目关系文档 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：OpenSSL 项目对 LibreSSL fork“分裂社区”的批评本质是 OpenSSL 项目对治理权流失的担忧——fork 使 OpenSSL Project Management Committee 失去对部分代码路径的控制权，所谓“集中精力改进 OpenSSL”的主张背后是 OpenSSL 项目的利益分配；FSF 对 clang/LLVM 是 Apple 主导的批评本质是 FSF 对 LLVM 生态（非 FSF 控制）扩张的担忧

**辨析**：考据过程留痕——【查证来源】OpenSSL 项目对 LibreSSL fork 的官方回应以 OpenSSL 项目博客（<https://www.openssl.org/blog/>）与 openssl-dev 邮件列表存档为原始来源，OpenSSL Project Management Committee 在 2014-2015 年间多次发布声明，具体声明文本须以 openssl-dev 邮件列表 marc.info 存档原始帖子为准；OpenSSL 1.1.0（2016-08-25 发布）重构的具体范围以 OpenSSL 1.1.0 Release Notes（<https://www.openssl.org/news/openssl-1.1.0-notes.html>）为准——重构包括 API 简化（移除 SSLv2、SSLv3 默认支持）、master 头文件引入（`#include <openssl/openssl.h>` 单一头文件）、线程支持改进（Thread-Safe Error Handling 重构）等；FSF 对 GCC 与 clang/LLVM 的立场以 FSF 官方 GCC 项目页面（<https://www.gnu.org/software/gcc/>）为原始来源——经 WebFetch 一手核验，该页面表述 GCC 为“the compiler for the GNU operating system”“100% free software, free in the sense that it respects the user’s freedom”，由 GCC steering committee 治理，但该页面未直接出现“clang/LLVM 是 Apple 主导”字样，所谓 FSF 将 clang/LLVM 定性为“Apple 主导”的表述须追溯至 FSF 早期对 LLVM 的评论文章或邮件列表发言；Apple 与 LLVM 项目关系以 LLVM 官方文档与 Chris Lattner 公开发言为准——Chris Lattner 2005 年加入 Apple 后主导 LLVM 项目，Apple 是 LLVM 项目早期最大资金来源；【交叉验证方法】openbsd.duckdb openbsd-src 仓库 commit log 与 OpenSSL 1.1.0 Release Notes、LibreSSL 官网三方交叉验证 OpenSSL 改革路径——OpenSSL 1.1.0 移除 SSLv2/SSLv3 默认支持与 LibreSSL 早期移除 SSLv2/SSLv3 支持在时间上形成对照（LibreSSL 2014 年 fork 后即移除，OpenSSL 1.1.0 于 2016 年移除），可视为 LibreSSL fork 对 OpenSSL 改革的倒逼效应证据；FSF 立场与 OpenBSD 反批评的对照以 FSF GCC 项目页面、OpenBSD misc@ 邮件列表 de Raadt 发言、BSD 各项目 Release Notes 三方交叉验证——FreeBSD 10.0（2014.1）、OpenBSD 5.7（2015.5）、NetBSD 7.0（2015.10）、DragonFly BSD 4.0（2015）均将 clang 作为默认或可选编译器，证明 clang/LLVM 已成为 BSD 社区共识而非 Apple 私有工具；【存疑判定依据】OpenSSL 1.1.0 Release Notes（<https://www.openssl.org/news/openssl-1.1.0-notes.html>）经 WebFetch 尝试核验但因 deadline 超时未取得原文，亦经互联网档案馆（web.archive.org）尝试核验但同样 deadline 超时，OpenSSL 1.1.0 重构的具体范围（API 简化、master 头文件、线程支持）目前基于多方二手报道归纳，须后续补验原始 Release Notes 或查询互联网档案馆存档版本；FSF 对 clang/LLVM“Apple 主导”的具体批评原文未在 FSF GCC 官方页面直接出现，此 attribution 须追溯至 FSF 早期评论文章或邮件列表发言，2010 年代的批评与 2020 年代的批评侧重点不同，具体批评内容随时间变化 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；OpenSSL Project Management Committee 对
