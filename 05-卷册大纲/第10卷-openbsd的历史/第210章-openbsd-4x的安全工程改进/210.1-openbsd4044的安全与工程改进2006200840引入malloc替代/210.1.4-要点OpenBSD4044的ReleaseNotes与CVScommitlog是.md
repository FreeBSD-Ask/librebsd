# 210.1.4 要点OpenBSD4044的ReleaseNotes与CVScommitlog是

**要点**：OpenBSD 4.0-4.4 的 Release Notes 与 CVS commit log 是研究此时期安全与工程改进的核心史料；openbsd.duckdb openbsd-src 仓库 2005-2010 年间贡献者以 deraadt@（5416 条）、jmc@（3921 条）、miod@（3760 条）、brad@（2728 条）、kettenis@（2271 条）为主；OpenBSD 4.0 release 的开发周期起点以 2006-09-17 steven commit e8d7e8373d3b “4.0-current” 为标识；统计结论印证——openbsd.duckdb openbsd-src 仓库总 commit 数 245,904（统计结论 C-05），4.x 时期（2005-2010）处于 Pettitt 检验变点 2001-01（统计结论 C-14）之后的工程节奏阶段，反映 OpenBSD 从 fork 后的高位 commit 量向稳态工程节奏的持续收敛

**史料**：openbsd.duckdb openbsd-src 仓库 2005-2010 commit 统计（deraadt 5416、jmc 3921、miod 3760、brad 2728、kettenis 2271）；commit e8d7e8373d3b（2006-09-17 steven “4.0-current”）；OpenBSD 4.0-4.4 Release Notes（<https://www.openbsd.org/40.html> 至 <https://www.openbsd.org/44.html>）；OpenBSD 邮件列表档案（<https://marc.info/?laccopenbsd-tech>）；openbsd.duckdb openbsd-src 仓库 commits 表（统计结论 C-05 总 commit 数 245,904，SQL `SELECT COUNT(*) FROM commits WHERE repo_name='openbsd-src'`；查询日期 2026-07-27）；openbsd.duckdb openbsd-src 仓库变点检测（统计结论 C-14：Pettitt 检验变点 2001-01 / BUISHAND 检验变点 2017-09，Python Pettitt 自实现 + BUISHAND R 自实现；查询日期 2026-07-27）；openbsd.duckdb 查询 L1.1.1（经 L1.1.2 交叉验证）显示 openbsd-src 仓库 2005-2010 年逐年 commit 量与占 4 大 BSD src 合计百分比数据未在报告前 30 行中显示（L1.1.2 查询结果共 124 行，报告仅显示前 30 行覆盖 1995-2002 年），须以数据库直接查询补全 ［A］

**史观**：总纲第 25 条——0 信任原则：Release Notes 与 commit log 的交叉验证是 0 信任原则在版本史研究中的实践——Release Notes 仅记录 “重要的和用户可见的变更”（<https://www.openbsd.org/plus.html>），部分内部代码重构（如 tedu@ 的 malloc 分配器拆分）可能在 Release Notes 中简化描述但可在 commit log 中定位完整变更；统计结论印证——C-14 Pettitt 变点 2001-01 反映 “分离聚合是永恒规律”（总纲第 4 条）的工程节奏显现：4.x 时期（2005-2010）处于 2001-01 变点之后的工程节奏阶段，OpenBSD 从 fork 后的高位 commit 量（2.x-3.x 时期的 pf fork、W^X、SSP 集中引入）向稳态工程节奏（4.x 时期的 malloc 替代、softraid 加密、pf 语法持续改进）过渡，commit 量层面的变点与工程节奏转换在 2001-01 时点形成可检测的工程节点

**辨析**：Release Notes 的完整性以 plus.html 页面为准——该页面仅记录用户可见变更，内部代码重构需以 commit log 补充；OpenBSD 仓库无 release tag（OpenBSD 使用 CVS 而非 git tag 标记 release），故 release 日期以 OpenBSD 官方网站公告为准 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；openbsd.duckdb 查询 L1.1.1 局限：L1.1.1 报告仅显示 23 仓库 572 行结果中的前 30 行（全为 dragonfly 仓库），openbsd-src 逐年数据须经 L1.1.2 查询交叉验证获取，但 L1.1.2 报告亦仅显示 124 行中的前 30 行（覆盖 1995-2002 年），2003-2010 年 openbsd-src 份额数据须以数据库直接查询补全；openbsd-src 为 GitHub 镜像，commit 量可能滞后于 OpenBSD CVS 主仓；commit 量反映开发活跃度但不等于代码质量；**统计局限性标注**——C-05 总 commit 数 245,904 包含 1995-10 fork 后至 2026 年全部 commit，非 4.x 时期专属，跨期引用时须结合时间窗口切片；C-14 变点检测的 Pettitt 与 BUISHAND 两检验变点时点不一致（2001-01 vs 2017-09），反映变点检测方法的方法学敏感性——Pettitt 检验对中段变点敏感，BUISHAND 检验对全样本变点敏感，两检验变点不一致不等于 “变点不存在” 而反映 “不同检验对变点位置的统计推断差异”；统计显著 ≠ 实际显著，Pettitt 2001-01 变点须与 OpenBSD 3.0（2001-12-01）发布、IPFilter 许可证争议（2001-05）、pf fork（2001）等工程事件交叉验证后方可归因；多重比较风险——C-14 与 C-12（freebsd-src 变点 1999-08）、C-13（netbsd-src 变点 2011/2012）、C-15（dragonfly-src 变点 2016/2017）跨项目对比时须按 Bonferroni 校正；0 信任原则适用——变点检测基于月度 commit 量序列，commit 量本身无法区分审计 commit 与功能 commit，变点的工程归因须以 commit message 与 release event 交叉验证
