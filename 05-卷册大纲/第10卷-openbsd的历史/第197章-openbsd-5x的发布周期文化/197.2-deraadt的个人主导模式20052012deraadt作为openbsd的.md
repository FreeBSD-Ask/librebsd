# 197.2 de Raadt 的个人主导模式（2005-2012）——de Raadt 作为 OpenBSD 的"benign dictator"，所有重大架构决策由 de Raadt 拍板，与 Linus Torvalds 模式各有侧重


## 196.2.1 de Raadt 主导的治理结构特征
  - 要点：de Raadt 作为 OpenBSD 的"benign dictator"，所有重大架构决策由其拍板；OpenBSD 无 Core Team 选举，committer 直接对 de Raadt 负责；de Raadt 的权威来自其创始贡献与持续主导（bsd_commits.db 显示 deraadt 自 1995 年 fork 起持续提交至 2024 年），而非正式职衔
  - 史料：OpenBSD 治理结构文档（<https://www.openbsd.org/faq/faq0.html>）；de Raadt 在 misc@、tech@ 的决策性发言（<https://marc.info/?l=openbsd-misc>、https://marc.info/?l=openbsd-tech）；bsd_commits.db openbsd-src 仓库 deraadt commit 记录 ［A］
  - 史观：总纲第 23 条——社区治理：de Raadt 的个人主导模式是 OpenBSD 社区治理的核心特征——这一模式的优势是决策效率与技术方向一致性（如 pledge/unveil 从设计到落地仅需 de Raadt 批准），风险是巴士因子极低
  - 辨析：de Raadt 的权威边界以 misc@、tech@ 邮件列表中 de Raadt 的决策性发言为准——技术细节由领域负责人主导（如 pf 由 Brauer 维护、OpenSSH 由 Friedl 维护），重大架构决策（如 gcc→clang 切换、LibreSSL fork）由 de Raadt 拍板；committer 权限的撤销以 OpenBSD CVS access log 为准，部分撤销事件在邮件列表公开讨论
  - 文献：OpenBSD 治理结构文档 [EB/OL]. <https://www.openbsd.org/faq/faq0.html>；de Raadt 邮件列表发言 [EB/OL]. <https://marc.info/?l=openbsd-misc>；bsd_commits.db openbsd-src 仓库 deraadt commit ［A］
## 196.2.2 与 Linus 模式及 Dillon 模式的比较
  - 要点：de Raadt、Linus Torvalds、Matt Dillon 三人均为"benign dictator"模式，但风格各异——Linus 通过 lieutenant 体系管理 Linux 内核，Dillon 几乎独自维护 DragonFly，de Raadt 介于两者之间；Linus 在公开场合激烈批评但接受贡献者意见，de Raadt 在邮件列表直接拒绝不合格 patch，Dillon 几乎不参与公开讨论
  - 史料：Linux Kernel mailing list（<https://lore.kernel.org/lkml/>）；DragonFly users@ 邮件列表（<https://www.dragonflybsd.org/mailinglists/>）；OpenBSD misc@、tech@ 邮件列表（<https://marc.info/?l=openbsd-misc>）［A］
  - 史观：总纲第 23 条——社区治理：三种个人主导模式各有适配——Linus 模式适配 Linux 内核的规模（数千贡献者需分层管理），Dillon 模式限制 DragonFly 扩展（单人维护难以规模化），de Raadt 模式确保 OpenBSD 一致性（小团队 + BDFL 决策确保技术方向不分裂）
  - 辨析：三种模式的具体差异以三个项目的邮件列表记录为准——Linus 在 LKML 中的"review-and-merge"流程、de Raadt 在 misc@/tech@ 中的"reject-or-accept"流程、Dillon 在 DragonFly users@ 中的"commit-and-announce"流程，三者决策风格在邮件列表档案中有直接记录
  - 文献：Linux Kernel 邮件列表档案 [EB/OL]. <https://lore.kernel.org/lkml/>；OpenBSD 邮件列表档案 [EB/OL]. <https://marc.info/?l=openbsd-misc>；DragonFly 邮件列表档案 [EB/OL]. <https://www.dragonflybsd.org/mailinglists/> ［A］
## 196.2.3 个人主导的风险与优势
  - 要点：个人主导模式的优势在于决策效率高、技术方向一致、避免委员会政治；风险在于巴士因子极低——若 de Raadt 退出，OpenBSD 可能陷入治理真空；de Raadt 通过培养核心 committer（如 Brauer、Beck、guenther）部分缓解巴士因子风险
  - 史料：OpenBSD committer 名单与权限记录（<https://www.openbsd.org/developers.html>）；bsd_commits.db openbsd-src 仓库贡献者活跃度统计；OpenBSD hackathons 记录（<https://www.openbsd.org/hackathons.html>）［A］
  - 史观：总纲第 10 条——边缘者贡献：guenther、Brauer、Beck 等核心 committer 作为“边缘者”分担 de Raadt 的治理负担——guenther 负责 libc 与系统调用层、Brauer 负责 pf、Beck 负责 LibreSSL，三人的领域分工使 OpenBSD 在 de Raadt 之外仍有技术延续性
  - 辨析：巴士因子的评估以 bsd_commits.db openbsd-src 仓库贡献者活跃度为准——deraadt 的 commit 数量在仓库中排名前列，但 guenther、miod、art 等核心 committer 亦持续活跃；继任计划以 de Raadt 在 misc@ 的发言为准——de Raadt 公开表态未指定继任者，但 OpenBSD Foundation 的存在为项目延续提供法律框架 [考据完成：2026-07-28 OpenBSD 的实际巴士因子无权威评估，commit 数量分布可从 bsd_commits.db 查询但 commit 数量不等于关键知识独占度]【代码级证据·openbsd.db openbsd-src 仓库】前 20 名 committer 的 commit 计数（全仓库，截至 2026 年）：1. deraadt 27182、2. miod 9646、3. jmc 9154、4. jsg 8661、5. millert 8315、6. kettenis 7837、7. tb 7172、8. espie 6103、9. mickey 5836、10. schwarze 5777、11. claudio 5572、12. nicm 5242、13. dlg 4995、14. krw 4622、15. jsing 4404、16. djm 3908、17. henning 3585、18. brad 3575、19. tedu 3533、20. mpi 3530——deraadt 以 27182 条 commit 占全仓库约 15%-20%，commit 数量分布呈长尾，前 20 名 committer 合计覆盖仓库绝大多数 commit，但 commit 数量不等于关键知识独占度（如内核子系统、驱动栈、用户态工具的领域知识分布在各 committer 中），巴士因子评估须以关键子系统知识独占度而非 commit 计数为最终判断依据
  - 文献：OpenBSD committer 记录 [EB/OL]. <https://www.openbsd.org/developers.html>；bsd_commits.db openbsd-src 仓库贡献者统计；OpenBSD hackathons 记录 [EB/OL]. <https://www.openbsd.org/hackathons.html> ［A］
## 196.2.4 治理相关邮件与发言考据
  - 要点：de Raadt 在 misc@、tech@ 邮件列表的发言是研究 OpenBSD 治理模式的核心史料；de Raadt 的发言风格直接、不留情面，常引发争议——bsd_commits.db 中 deraadt 的 commit message 风格同样简洁直接（如 2015-07-19 commit 586b470f3a48"tame(2) is a subsystem which restricts programs..."）
