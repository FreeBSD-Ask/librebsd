## 故障类

### 新闻条目 1

- **新闻标题（中英）**：KARL - kernel address randomized link + RETGUARD, the OpenBSD next level in exploit mitigation, is about to debut（KARL 内核地址随机化链接 + RETGUARD 返回值保护即将登场）
- **新闻来源**：undeadly.org + 编辑署名 + 2017-06-13 / 2017-08-19 + URL: <https://undeadly.org/cgi?action=article;sid=20170613041706> + <https://undeadly.org/cgi?action=article;sid=20170819230157> + 存档 URL: 待补
- **新闻摘要**：undeadly.org 报道 OpenBSD 在 2017-06-13 引入 KARL（Kernel Address Randomized Link），通过在每次内核构建时随机化内核链接顺序，使内核函数地址在每次构建间不同，增强对抗内核 ROP（Return-Oriented Programming）攻击的能力。随后 2017-08-19 报道 RETGUARD 即将登场，这是 OpenBSD 下一级漏洞利用缓解技术，在每个函数返回点插入随机化 canary 检查。两者共同构成 OpenBSD 6.x 时期漏洞利用缓解体系的核心支柱。
- **与本章主题的关联说明**：本章叙述 OpenBSD 6.x 时期，KARL 与 RETGUARD 是本章 “OpenBSD 6.x 安全缓解技术演进” 叙事的核心节点，延续 OpenBSD 自 2003 年 W^X 以来的主动安全路线。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD source-changes@ 邮件列表 2017-06 KARL commit、2017-08 RETGUARD commit 一致；与 Theo de Raadt（西奥·德·若特） 2017-07-01 "Kernel relinking status" 邮件列表说明互证；与 OpenBSD 6.2 changelog（plus62.html）中 KARL/RETGUARD 条目一致。一致采纳。

## 里程碑事件类

### 新闻条目 1

- **新闻标题（中英）**：OpenBSD 6.1 Released（OpenBSD 6.1 发布）+ OpenBSD 6.1 Song Released
- **新闻来源**：undeadly.org + 编辑署名 + 2017-04-11 / 2017-04-27 + URL: <https://undeadly.org/cgi?action=article;sid=20170411132956> + <https://undeadly.org/cgi?action=article;sid=20170427041445> + 存档 URL: 待补
- **新闻摘要**：undeadly.org 报道 OpenBSD 6.1 于 2017-04-11 正式发布，随后 2017-04-27 发布配套歌曲。OpenBSD 6.1 是 6.x 系列首个版本，引入 syspatch(8) 二进制补丁机制（替代此前的源码补丁），改进 dhclient、slaacd(8)（IPv6 地址自动配置守护进程）、vmm(4)/vmd(8) 虚拟化子系统。syspatch 机制大幅降低系统安全补丁的部署门槛，是 OpenBSD 运维现代化的关键里程碑。
- **与本章主题的关联说明**：本章叙述 OpenBSD 6.x 时期，6.1 发布是 6.x 系列起点，syspatch 二进制补丁机制是本章 “OpenBSD 6.x 运维现代化” 叙事的核心节点。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD 6.1 changelog（plus61.html）一致；syspatch 引入与 OpenBSD 6.1 release notes 互证；与 2017-05-03 undeadly.org "Errata and (First) Binary Patches Announced" 报道形成时序链。一致采纳。

### 新闻条目 2

- **新闻标题（中英）**：clang(1) added to base on amd64 and i386 + Default compiler switched to clang on amd64 and i386（clang 加入 base 并成为 amd64/i386 默认编译器）
- **新闻来源**：undeadly.org + 编辑署名 + 2017-04-21 / 2017-07-27 + URL: <https://undeadly.org/cgi?action=article;sid=20170421001933> + <https://undeadly.org/cgi?action=article;sid=20170727055820> + 存档 URL: 待补
- **新闻摘要**：undeadly.org 报道 OpenBSD 在 6.1 发布后（2017-04-21）将 clang(1) 加入 amd64 与 i386 的 base 系统，随后在 2017-07-27 将默认编译器从 GCC 切换为 clang。这是 OpenBSD 编译器栈现代化的关键一步，与 FreeBSD 2012-2014 年的 GCC-to-Clang 迁移形成跨 BSD 历史呼应。clang 的 BSD 兼容许可证也是 OpenBSD 选择它的重要考量。
- **与本章主题的关联说明**：本章叙述 OpenBSD 6.x 时期，clang 进入 base 并成为默认编译器是本章 “OpenBSD 6.x 工具链现代化” 叙事的核心事件，与第 5 卷 FreeBSD 58 章 Clang/LLVM 迁移形成跨卷对照。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD -current source-changes@ 邮件列表 2017-04 / 2017-07 clang 相关 commit 一致；与 OpenBSD 6.2 changelog（plus62.html）中 clang 默认编译器条目互证。一致采纳。

### 新闻条目 3

- **新闻标题（中英）**：arm64 platform now officially supported [and has syspatch(8)]（arm64 平台正式支持并具备 syspatch）
- **新闻来源**：undeadly.org + 编辑署名 + 2017-12-08 + URL: <https://undeadly.org/cgi?action=article;sid=20171208082238> + 存档 URL: 待补
- **新闻摘要**：undeadly.org 报道 OpenBSD 在 2017-12-08 正式宣布 arm64（AArch64）平台成为官方支持平台，并具备 syspatch(8) 二进制补丁能力。这是 OpenBSD 自 1996 年创建以来首次将 ARM 64 位架构提升为官方支持平台（此前 armv7 为社区支持），为后续 OpenBSD 7.0（2021）支持 Apple Silicon 奠定基础。Patrick Wildt（帕特里克·维尔特） 在 a2k17 hackathon 报告中详述 arm64 移植工作。
- **与本章主题的关联说明**：本章叙述 OpenBSD 6.x 时期，arm64 正式支持是本章 “OpenBSD 6.x 架构扩展” 叙事的关键里程碑，标志 OpenBSD 向 ARM 生态进军。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD 官方 plat.html 平台页面一致；与 a2k17 hackathon 报告 Patrick Wildt on arm64 port（2017-01-31）互证；与 OpenBSD 6.3（2018-04）release notes 中 arm64 首次作为正式 release 平台一致。一致采纳。

- **新闻摘要**：undeadly.org 报道 OpenBSD 6.2 于 2017-10-09 正式发布，集成 KARL、RETGUARD、clang 默认编译器、arm64 持续改进等 6.x 时期核心技术。同时 2017-10-15 报道 syspatch(8) 二进制补丁机制调整为仅支持最新 release 版本（此前曾尝试支持多版本），这是 OpenBSD 在补丁运维策略上的务实选择——集中资源维护单一 release 的二进制补丁。
- **与本章主题的关联说明**：本章叙述 OpenBSD 6.x 时期，6.2 发布是 KARL/RETGUARD/clang 等技术首次集中亮相的版本，syspatch 策略调整是本章 “OpenBSD 6.x 补丁运维策略定型” 叙事的关键节点。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD 6.2 changelog（plus62.html）一致；syspatch 策略调整与 OpenBSD 官方 syspatch(8) 手册页及 errata62.html 互证。一致采纳。
