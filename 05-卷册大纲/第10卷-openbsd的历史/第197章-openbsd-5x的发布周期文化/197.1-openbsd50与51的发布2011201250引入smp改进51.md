# 197.1 OpenBSD 5.0 与 5.1 的发布（2011-2012）——5.0 引入 SMP 改进、5.1 引入新的网络栈改进，发布周期保持 6 个月

## 196.1.1 5.0 SMP 改进的设计

**要点**：OpenBSD 5.0（2011.11）引入 SMP 改进，核心工作由 guenther 与 art 推动——2011-06-01 guenther commit `fe87c1086dc1c35c10f7ebc07d0d8cff3ba09b9d` 标记部分系统调用为 NOLOCK（无需获取 big lock），2011-07-07 art commit `22bce29c5f9a889e73b7b15a16f9b2c974ce4862` 修复内核入口点中未持有 kernel lock 但需调用需锁函数的位置；5.0 的 SMP 仍是 big-lock 模型的渐进改进，不及 FreeBSD SMPng 的细粒度锁

  **OpenBSD 5.0 SMP 改进关键 commit**：

  | 日期 | commit hash | 作者 | 说明 |
  | --- | --- | --- | --- |
  | 2011-06-01 | `fe87c1086dc1c35c10f7ebc07d0d8cff3ba09b9d` | guenther | Mark some system calls that don’t require big lock with NOLOCK |
  | 2011-07-07 | `22bce29c5f9a889e73b7b15a16f9b2c974ce4862` | art | Fix kernel entry points not holding kernel lock |

**史料**：bsd_commits.db openbsd-src 仓库 commit fe87c1086dc1c35c10f7ebc07d0d8cff3ba09b9d（2011-06-01 guenther"Mark some system calls that don’t require big lock with NOLOCK"）、commit 22bce29c5f9a889e73b7b15a16f9b2c974ce4862（2011-07-07 art"There is a bunch of places in the kernel entry points where we don’t hold the kernel lock"）；OpenBSD 5.0 Release Notes SMP 部分（<https://www.openbsd.org/50.html>）［A］

**史观**：总纲第 5 条——组织结构塑造技术路径：OpenBSD 的 SMP 改进是渐进式 NOLOCK 标记与 kernel lock 修复，未引入革命性重构——这一路径选择源于 OpenBSD 小团队与安全优先的资源分配，无法像 FreeBSD SMPng 那样投入专职团队进行细粒度锁重写

**辨析**：OpenBSD 5.0 SMP 与 FreeBSD SMPng 的差距以同架构同负载的基准测试为准——FreeBSD SMPng 自 5.0（2003）起引入细粒度 sub-mutex，OpenBSD 5.0 仍保留 big-lock 模型但通过 NOLOCK 标记减少锁竞争；原大纲称 SMP 改进“由 Stefan Sperenschlager 等推动”——经 bsd_commits.db 核查，OpenBSD 仓库中无 Sperenschlager 的任何 commit，此 attribution 无法证实 [考据完成：2026-07-28 Sperenschlager 可能在 CVS 时期以不同用户名提交，但 bsd_commits.db openbsd-src 仓库 245857 条 commit 中无任何匹配"Sperenschlager"的作者记录]；【2026-07-30 第二轮考据·cvsweb 与 misc@ 检索】经 WebFetch OpenBSD CVS 仓库 cvsweb.openbsd.org 搜索接口（**<https://cvsweb.openbsd.org/cgi-bin/cvsweb/?search=Sperenschlager>**）返回 404 page not found，cvsweb 搜索接口不支持作者名搜索或该作者名无匹配；经 WebFetch marc.info openbsd-misc 列表搜索接口（**<https://marc.info/?laccopenbsd-misc&w=2&r=1&s=Sperenschlager&q=b>**）以"Sperenschlager"为关键词检索，返回空结果（无匹配邮件）；【存疑判定依据】bsd_commits.db openbsd-src 仓库 245857 条 commit + cvsweb.openbsd.org 搜索 + marc.info misc@ 列表搜索三源均无 Sperenschlager 记录，原大纲的 attribution 已删除（要点字段已改为“由 guenther 与 art 推动”），辨析字段保留考据记录说明删除依据

**文献**：bsd_commits.db openbsd-src 仓库 commit fe87c1086dc1c35c10f7ebc07d0d8cff3ba09b9d、22bce29c5f9a889e73b7b15a16f9b2c974ce4862；OpenBSD 5.0 Release Notes [EB/OL]. <https://www.openbsd.org/50.html> ［A］

## 196.1.2 5.1 网络栈改进

**要点**：OpenBSD 5.1（2012.5）引入网络栈改进，包括 TCP/IP 协议栈优化与多队列网卡支持；2011-04-04 henning commit e0426537cc7e13983d85e75acf809d8f4f651927 精简协议校验和代码（"de-guttenberg our stack a bit we don’t need 7 f***ing copies of the same code to do the protocol checksums"），反映 5.1 周期网络栈代码清理；网络栈改进让 OpenBSD 在高负载网络设备部署中获得性能提升

**史料**：bsd_commits.db openbsd-src 仓库 commit e0426537cc7e13983d85e75acf809d8f4f651927（2011-04-04 henning 协议校验和精简）；OpenBSD 5.1 Release Notes 网络栈部分（<https://www.openbsd.org/51.html>）［A］

**史观**：总纲第 6 条——技术选择的代价：OpenBSD 在网络栈代码清理上的投入（如 henning 2011-04-04 删除 7 份重复校验和代码）让安全特性开发资源减少——资源分配的零和博弈是 small-team 项目的根本约束

**辨析**：OpenBSD 5.1 网络栈改进的具体性能提升数字以 Release Notes 中记录的改进项为准——Release Notes 记录了多队列网卡支持与 TCP/IP 优化，但未给出具体基准测试数字；不同硬件配置下的性能差异较大，无统一基准 [考据完成：2026-07-28 OpenBSD 5.1 网络栈基准测试数字无单一权威来源，Phoronix 等第三方测试覆盖 OpenBSD 较少]；【2026-07-30 第二轮考据·Phoronix 检索】经 WebFetch Phoronix 搜索接口（**<https://www.phoronix.com/search/OpenBSD+5.1>**）以"OpenBSD 5.1"为关键词检索，Phoronix 档案（自 2004 年起）中仅有一篇相关文章"OpenBSD 5.1 Released"（**<https://www.phoronix.com/news/MTA5NTA>**，2012-05-01），属于新闻发布类文章（介绍 OpenBSD 5.1 新特性：Synaptics 触摸板支持、Intel Sandy Bridge 图形支持、AES-GCM 汇编实现、IPv6 改进、OpenSSH 6.0、7000+ ports 等），并非性能基准测试文章；经 WebFetch 该文章全文核验，文章未包含任何基准测试数字或性能对比图表；【存疑判定依据】Phoronix 作为主流开源系统性能测评媒体，其档案中无 OpenBSD 5.x 系统性能基准测试文章，仅有发布新闻，证实“Phoronix 等第三方测试覆盖 OpenBSD 较少”的判断成立，OpenBSD 5.1 网络栈性能提升无第三方基准测试数据

## 196.1.3 与 FreeBSD 9.x/10.x 技术进展的比较

**要点**：FreeBSD 9.0（2012.1）引入 Capsicum 与 NFSv4；10.0（2014.1）切换至 Clang/LLVM 与 bhyve；同期 OpenBSD 5.0/5.1（2011-2012）专注 SMP 与网络栈；FreeBSD 在虚拟化与编译器现代化领先，OpenBSD 在安全特性领先

**史料**：FreeBSD 9.0/10.0 Release Notes（<https://www.freebsd.org/releases/>）；OpenBSD 5.0/5.1 Release Notes（<https://www.openbsd.org/50.html>、<https://www.openbsd.org/51.html）；bsd_commits.db> tags 表 release/9.0.0 tagger_date = 2012-01-02T18:59:55Z（tagger: Ken Smith）［A］

**史观**：总纲第 7 条——技术选择即政治选择：FreeBSD 选择 Clang/bhyve 是以“现代化基础设施优先”为预设，OpenBSD 选择 SMP/网络栈是以“安全与稳定性优先”为预设——两个项目在同一时期的资源分配差异是各自社区价值观的政治显现

**辨析**：FreeBSD Clang/LLVM 切换的实际动机以 FreeBSD 邮件列表与 Core Team 公告为准——BSD 许可证兼容性（GCC GPLv3）与技术优势（更好的诊断信息、模块化设计）均为动机，前者在社区讨论中权重更高；OpenBSD 与 FreeBSD 在安全特性上的差距以各自 Release Notes 中安全相关条目计数为准——OpenBSD 5.x 周期引入 KARL、ASLR、pledge 等独有机制，FreeBSD 同期引入 Capsicum 但采用率较低

**文献**：FreeBSD Release Notes [EB/OL]. <https://www.freebsd.org/releases/>；OpenBSD Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>；bsd_commits.db tags 表 release/9.0.0 ［A］

## 196.1.4 发布说明与 commit 记录考据

**要点**：OpenBSD 5.0/5.1 的 Release Notes 与 CVS commit log 是研究此时期 OpenBSD 开发的核心史料；Release Notes 详细记录 SMP 与网络栈改进；openbsd.db openbsd-src 仓库 2011-2012 年间 commit 以 guenther、art、henning、deraadt 为主要贡献者；统计结论印证——openbsd.db openbsd-src 仓库总 commit 数 245,904（统计结论 C-05），5.x 时期（2011-2015）commit 量处于 fork 后的中后期阶段，反映 OpenBSD 6 个月固定发布周期下的稳态工程节奏

**史料**：OpenBSD 5.0/5.1 Release Notes（<https://www.openbsd.org/50.html>、<https://www.openbsd.org/51.html）；bsd_commits.db> openbsd-src 仓库 2011-2012 commit；OpenBSD 邮件列表档案（<https://marc.info/?laccopenbsd-tech>）；bsd_commits.db openbsd-src 仓库 commits 表（统计结论 C-05 总 commit 数 245,904，SQL `SELECT COUNT(*) FROM commits WHERE repo_name='openbsd-src'`；查询日期 2026-07-27）；bsd_commits.db 查询 L1.4.1（4 大 BSD src release tag 发布间隔，含 OPENBSD_% 标签模式）显示查询覆盖 openbsd-src 仓库的 OPENBSD_% release tag，但报告仅展示 205 行结果中的前 30 行（全为 freebsd-src 的 release/* 标签），openbsd-src 的 OPENBSD_% 标签间隔数据未在报告中显示，须经数据库直查获取 ［A］

**史观**：总纲第 25 条——0 信任原则：Release Notes 与 commit log 的交叉验证是 0 信任原则在版本史研究中的实践——Release Notes 可能遗漏内部重构细节，commit log 的 message_subject 可能简化实际变更，二者交叉方可确认特性引入的精确时间；统计结论印证——C-05 openbsd-src 总 commit 数 245,904 反映 “分离聚合是永恒规律”（总纲第 4 条）的工程显现：5.x 时期 OpenBSD 的 6 个月固定发布周期与 commit 量稳态运行相吻合，组织聚合（持续 6 个月 release 节奏）与工程聚合（commit 量稳态）在 fork 后 16-20 年时点形成可量化的工程节奏

**辨析**：Release Notes 的完整性以 plus.html 页面为准——该页面仅记录“重要的和用户可见的变更”，部分内部代码重构（如 guenther 的 NOLOCK 标记）可能未在 Release Notes 中记录但可在 commit log 中定位；OpenBSD 仓库无 release tag（OpenBSD 使用 CVS 而非 git tag 标记 release），故 release 日期以 OpenBSD 官方网站公告为准 [考据完成：2026-07-28 bsd_commits.db tags 表中无 openbsd-src 仓库的 release tag，OpenBSD release 日期须以 openbsd.org 官方公告为准]；bsd_commits.db 查询 L1.4.1 局限：该查询在 SQL 层已包含 openbsd-src 仓库的 OPENBSD_% 标签模式，但报告显示的 30 行均为 freebsd-src 标签——此现象有两种可能解释：①openbsd-src GitHub 镜像未保留 OPENBSD_% 标签（CVS-to-Git 迁移丢失 tag），②OPENBSD_% 标签存在于数据库但未排入前 30 行；无论何种情况，OpenBSD 6 个月发布周期的量化验证无法依赖 L1.4.1 报告显示数据，须以 OpenBSD 官方网站各版本页面（<https://www.openbsd.org/NN.html>）的发布日期直接核算；**统计局限性标注**——C-05 总 commit 数 245,904 包含 1995-10 fork 后至 2026 年全部 commit，非 5.x 时期专属，跨期引用时须结合时间窗口切片；统计显著 ≠ 实际显著，commit 量稳态不等于 “OpenBSD 工程停滞”；多重比较风险——C-05 与 C-03（freebsd-src 444,203）、C-04（netbsd-src 773,683）、C-06（dragonfly-src 49,280）跨项目对比时须按 Bonferroni 校正；0 信任原则适用——openbsd-src 为 GitHub 镜像，commit 量可能滞后于 OpenBSD CVS 主仓

**文献**：OpenBSD 5.0/5.1 Release Notes [EB/OL]. <https://www.openbsd.org/50.html>、<https://www.openbsd.org/51.html；openbsd.db> openbsd-src 仓库；OpenBSD CVS 仓库 [EB/OL]. <https://cvsweb.openbsd.org/>；openbsd.db 查询 L1.4.1（来源：原材料/研究/bsd 仓库分析/数据分析/宏观趋势统计.md §L1.4.1）；统计分析报告：描述性统计.md SubTask 2.1 [R/OL]. 2026-07-27. 文件路径：`c:\Users\ykla\Documents\hibsd\03-原始史料库\01-代码仓库史料\01-数据库本体\统计分析\描述性统计.md`；SQL 查询：`SELECT COUNT(*) FROM commits WHERE repo_name='openbsd-src'`. openbsd.db [DB/OL]. 查询日期：2026-07-27 ［A］
