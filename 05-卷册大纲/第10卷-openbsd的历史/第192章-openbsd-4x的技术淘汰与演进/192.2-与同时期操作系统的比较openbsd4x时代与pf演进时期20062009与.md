# 192.2 与同时期操作系统的比较：OpenBSD 4.x 时代与 pf 演进时期（2006-2009）——与 FreeBSD 5.x/6.x/7.x（pf 移植）、NetBSD 4.x、Linux 2.6（iptables/netfilter）、Windows（基础防火墙）的对比

## 192.2.1 FreeBSD 5.x/6.x/7.x（pf 移植，2004-2008）

**要点**：FreeBSD 在 OpenBSD 4.x 同期为 5.x/6.x/7.x（2004-2008），将 pf 防火墙从 OpenBSD 移植——freebsd.duckdb 显示 FreeBSD 于 2004-02-26 由 Max Laier commit 5c45a928b954 "Vendor import of OpenBSD's packet filter (pf) as of OpenBSD 3.4" 首次移植 pf（5.3 周期；FreeBSD 5.3 发布于 2004-11），后续 pf 3.5 于 2004-06-16 import（commit 32b30983561e），pf 3.7 于 2005-05-03 import（commit f0d663ded81d）；FreeBSD 同时保留 ipfw 与 ipfilter，三者并存；原大纲称 “FreeBSD 6.x/7（2005-2008）将 pf 防火墙从 OpenBSD 移植（2005 起）” 系误记——FreeBSD pf 移植始于 5.3 周期（2004-02-26 vendor import；5.3 发布 2004-11），非 6.x（2005）

**史料**：freebsd.duckdb freebsd-src 仓库 commit 5c45a928b954（2004-02-26 Max Laier "Vendor import of OpenBSD's packet filter (pf) as of OpenBSD 3.4”）、commit 32b30983561e（2004-06-16 Max Laier “Import pf from OpenBSD 3.5”）、commit f0d663ded81d（2005-05-03 Max Laier ”Import pf from OpenBSD 3.7"）；FreeBSD 5.3/6.x/7.x Release Notes；OpenBSD 4.x pf 演进 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：pf 从 OpenBSD 流向 FreeBSD 是 BSD 许可证 “允许 fork 不强制回馈” 特性的具体显现——FreeBSD 可自由移植 pf 而无需 OpenBSD 许可，但 FreeBSD 须自行维护移植版本的同步与本地化

**辨析**：FreeBSD 的 pf 与 ipfw 并存，OpenBSD 4.x 以 pf 为唯一防火墙——FreeBSD 选择多防火墙并存（pf/ipfw/ipfilter）以适配不同用户需求，OpenBSD 选择 pf 独占以简化维护与确保一致性，二者策略各有适配

**文献**：freebsd.duckdb freebsd-src 仓库 commit 5c45a928b954、32b30983561e、f0d663ded81d；FreeBSD Release Notes [EB/OL]. <https://www.freebsd.org/releases/>；OpenBSD 4.x Release Notes [EB/OL]. <https://www.openbsd.org/plus.html> ［A］

## 192.2.2 NetBSD 4.x（2007）

**要点**：NetBSD 在 OpenBSD 4.x 同期为 4.0/4.0.x（2007.12 release），以 NPF（后引入）前的 ipf/PF 支持与多平台见长；NetBSD 4.x 也移植 pf，但 OpenBSD 4.x 是 pf 的创新与维护中心

**史料**：NetBSD 4.x Release Notes（<https://www.netbsd.org/releases/formal-4.0.html>）；NetBSD 4.x 防火墙支持文档；OpenBSD 4.x pf ［B］

**史观**：总纲第 13 条——法律与道德是利益分配：NetBSD 与 OpenBSD 同期共享 pf 代码，是 BSD 家族内代码自由流动的体现——NetBSD 选择移植 pf 与 ipf 并存以适配其多平台导向，OpenBSD 选择 pf 独占以适配其安全优先导向

**辨析**：NetBSD 4.x 的防火墙生态以 NetBSD 文档为准——NetBSD 4.x 支持 ipf（IPFilter，Darren Reed（达伦·里德） 维护）与 pf，二者并存；NPF（NetBSD Packet Filter）由 Mindaugas Rasiukevicius 在 NetBSD 6.0（2012）引入，不在 4.x 时期

**文献**：NetBSD 4.x Release Notes [EB/OL]. <https://www.netbsd.org/releases/formal-4.0.html>；NetBSD pf 指南；OpenBSD pf 指南 [EB/OL]. <https://www.openbsd.org/faq/pf/> ［B］

## 192.2.3 Linux 2.6（iptables/netfilter，2006-2009）

**要点**：Linux 2.6（2003.12 起）在 OpenBSD 4.x 同期以 iptables/netfilter 为事实防火墙，模块化解包与状态检测；iptables 语法复杂但生态广，pf 以简洁规则与锚点著称，二者在 2006-2009 形成防火墙哲学差异——iptables 以 Netfilter 框架的钩子链表组织规则，pf 以配置语言的规则集与 anchors 组织规则

**史料**：Linux iptables/netfilter 文档（<https://www.netfilter.org/documentation/>）；OpenBSD **pf.conf(5)** 手册页（<https://man.openbsd.org/pf.conf.5>） ［B］

**史观**：总纲第 5 条——没有必然性只有偶然性：iptables 模块化与 pf 简洁规则是 Linux 与 BSD 防火墙哲学差异的具体显现——iptables 的模块化提供灵活性但增加配置复杂度，pf 的简洁规则降低配置门槛但限制灵活性

**辨析**：pf 后被多数 BSD 采用（FreeBSD/NetBSD/DragonFly BSD），iptables 在 Linux 主导；nftables 于 Linux 3.13（2014）引入作为 iptables 的现代替代，统一 Linux 侧防火墙配置

**文献**：Linux netfilter/iptables 文档 [EB/OL]. <https://www.netfilter.org/documentation/>；OpenBSD **pf.conf(5)** 手册页 [EB/OL]. <https://man.openbsd.org/pf.conf.5> ［B］

## 192.2.4 Windows（无 pf / 基础防火墙，2006-2009）

**要点**：Microsoft 在 OpenBSD 4.x 同期以 Windows Firewall（XP SP2/Server 2003 起）提供基础包过滤，无 pf 概念、闭源不可审计；Windows 防火墙功能基础、闭源，pf 以开源、强大规则语言著称——二者的差异是闭源商业产品与开源社区项目在防火墙领域的不同路径选择

**史料**：Microsoft Windows Firewall 文档（<https://learn.microsoft.com/windows/security/threat-protection/windows-firewall/>） ［B］

**史观**：总纲第 5 条——没有必然性只有偶然性：闭源基础防火墙与开源强大 pf 在 2006-2009 形成差异——Windows 防火墙以 “开箱即用” 为预设（功能基础、配置简单），pf 以 “可审计与可编程” 为预设（功能强大、配置需学习）

**辨析**：Windows 防火墙后期增强（Windows Vista 起 的 Windows Firewall with Advanced Security），但 pf 的规则表达力与开源审计仍领先——pf 的 anchors 机制允许动态规则替换，Windows 防火墙无等价机制

**文献**：Microsoft Windows Firewall 文档 [EB/OL]. <https://learn.microsoft.com/windows/security/threat-protection/windows-firewall/> ［B］

## 192.2.5 同期防火墙技术总览（2006-2009）

**要点**：2006-2009 防火墙格局：OpenBSD 4.x 的 pf 为 BSD 事实标准（流向 FreeBSD/NetBSD/DragonFly BSD），Linux 以 iptables/netfilter 主导，Windows 基础防火墙闭源；pf 的简洁锚点规则影响后续 BSD 防火墙设计，成为 OpenBSD 4.x 的工程标志

**史料**：各系统 2006-2009 防火墙史料；freebsd.duckdb freebsd-src 仓库 pf import commit；OpenBSD 4.x Release Notes ［B］

**史观**：总纲第 13 条——法律与道德是利益分配：pf 自 OpenBSD 4.x 外溢至 FreeBSD/NetBSD/DragonFly BSD，是 BSD 许可证促进跨 BSD 代码流动的具体显现——pf 的 BSD 许可证允许其他 BSD 项目自由移植与修改，无需 OpenBSD 许可

**辨析**：防火墙选择受生态与许可影响——pf 的 BSD 许可促进跨 BSD 流动，iptables 的 GPL 许可限制其向 BSD 项目回流；OpenBSD 4.x 的 pf 创新源地位以 openbsd.duckdb openbsd-src 仓库 pf 相关 commit 的 author_date 与 freebsd-src 仓库 pf import commit 的 tagger_date 交叉确认

**文献**：OpenBSD pf 指南 [EB/OL]. <https://www.openbsd.org/faq/pf/>；freebsd.duckdb freebsd-src 仓库 pf import commit；BSD 防火墙比较文档 ［B］
