# 192.5 **OpenBSD 4.x 时代的漏洞响应与 malloc.c 随机化加固循环（2006-2012）**——CVE 引用增长至 26 条（仍全部无 CVSS v3 评分），tedu 引入 malloc.c 随机化将“发现漏洞—快速修复—加固重构”循环推向堆利用防御层面

## 191.6.1 CVE 引用增长与 malloc.c 随机化的加固背景（2006-2012）

**要点**：openbsd.db openbsd-src 仓库在 2006-11-01 至 2012-05-01 期间有 CVE 相关 commit 25 条，去重 CVE 26 条（全部无 CVSS v3 评分），Security fix commit（无 CVE）5 条，早期漏洞补遗 0 条；与 3.x 时期（4 条 CVE）相比，4.x 时期 CVE 引用量显著增长，反映 CVE 编号体系在 2006-2012 年间已成为 OpenBSD commit message 中越来越常用的漏洞标识——但仍有大量安全修复以无 CVE 的 Security fix commit 形式存在（5 条），errata patches 存档仍为主渠道；4.x 时期的核心加固机制是 tedu 于 2006 年 10 月引入的 malloc.c 随机化替代——通过随机化堆块布局、添加 guard page、返回时清零等策略，使传统堆溢出漏洞的利用难度大幅提升，这一机制使 OpenBSD 4.x 时期的堆溢出类漏洞（如 CVE-2007-1536 file(1) 堆溢出、CVE-2010-3864 OpenSSL 缓冲区溢出）即使在漏洞存在的情况下也更难被实际利用；5 条 Security fix commit 涵盖 krw 修复 disklabel 整数溢出（commit `b9e7b3cf9c028c790c11ad9aa24bf02bab03c7cd`，2008-08-10）、claudio 修复 pf 规则从用户态拷贝至内核时的指针验证（commit `04523091a16553628956e63cc3d1b31f792bdfe6`，2010-12-15）等。

**史料**：openbsd.db openbsd-src 仓库（CVE commit 数 = 25，Security fix commit 数 = 5，去重 CVE = 26）；commit `b9e7b3cf9c028c790c11ad9aa24bf02bab03c7cd`（2008-08-10 krw）、`04523091a16553628956e63cc3d1b31f792bdfe6`（2010-12-15 claudio）；tedu malloc.c 随机化引入 commit（2006-10）［A］

**史观**：总纲第 17 条——形式主义化：malloc.c 随机化将“信任堆布局”降级为“随机化堆布局”，是形式主义化安全机制对堆利用技术的系统性回应——不修补具体漏洞，而是改变漏洞利用的基础假设；总纲第 10 条——边缘者贡献：malloc.c 随机化由 tedu 一人设计实现，非由安全研究机构或大厂商团队推动

**辨析**：26 条 CVE 全部无 CVSS v3 评分——NVD 未为其提取 v3 评分，不可臆造评分；malloc.c 随机化的具体首次引入 commit hash 须考据——CLAUDE.md 提及"tedu@ 2006-10-24 commit 66e23c51"但须对照 openbsd-src 仓库核验完整 40 字符 hash；malloc.c 随机化对实际漏洞利用的抑制效果缺乏公开量化评估，须避免过度声称其防御能力
