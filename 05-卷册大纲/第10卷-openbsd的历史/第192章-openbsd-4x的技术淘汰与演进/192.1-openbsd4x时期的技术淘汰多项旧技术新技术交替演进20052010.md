## 191.1.1 XFree86 → X.org 转换（OpenBSD 4.1-4.2，2007）

**要点**：XFree86 项目因 2004 年 1 月 XFree86 4.4.0 许可证变更（加入类似 “广告条款” 的限制性条款）引发社区分裂，X.Org 基金会 fork 形成 X.org 服务器；bsd_commits.db 显示 OpenBSD 在 4.x 时期完成从 XFree86 到 X.org 的转换——2005-05-04 jaredy commit 8462c87f5bf9 "change XFree86 -> X.Org" 标识手册页转换，2007-03-26 matthieu commit fcb4a8a3b89b "Switch X build instructions to xenocara. ok deraadt@ jmc@ mbalmer@" 标识 xenocara 构建框架首次引入（4.1 周期）；xenocara 是 OpenBSD 对 X.org 的定制构建框架，整合 X server、驱动、字体等组件；原大纲称 “为后续 xenocara 重组（6.0）奠定基础” 系误记——xenocara 于 4.1（2007.5）引入，非 6.0（2015.10）

**史料**：bsd_commits.db openbsd-src 仓库 commit 8462c87f5bf9（2005-05-04 jaredy "change XFree86 -> X.Org"）、commit fcb4a8a3b89b（2007-03-26 matthieu "Switch X build instructions to xenocara"）；XFree86 4.4.0 LICENSE 文件变更；X.Org 基金会成立公告；OpenBSD 4.1 Release Notes X11 部分 ［A］

**史观**：总纲第 24 条——许可证：XFree86 4.4.0 许可证变更（加入广告条款）催生 X.org fork，OpenBSD 通过 xenocara 聚合 X.org 完成替代——这一路径是 OpenBSD 许可证纯洁性哲学的实践，OpenBSD 拒绝接受含广告条款的 XFree86 4.4.0，选择 fork 后的 X.org

**辨析**：OpenBSD 从 XFree86 切换到 X.org 的具体版本以 commit log 与 Release Notes 交叉确认——2005-05-04 jaredy commit 标识手册页转换，2007-03-26 matthieu commit 标识 xenocara 构建框架引入，二者间隔约 2 年，反映 X.org 切换是渐进过程；XFree86 4.4.0 许可证变更的具体条款以原始 LICENSE 文件为准——新增条款要求所有文档与广告材料中提及 XFree86 项目

**文献**：bsd_commits.db openbsd-src 仓库 commit 8462c87f5bf9、fcb4a8a3b89b；XFree86 4.4.0 LICENSE 文件；X.Org 基金会公告；OpenBSD 4.1 Release Notes [EB/OL]. <https://www.openbsd.org/41.html> ［A］

## 191.1.2 gcc → pcc 尝试与 clang/LLVM 转向前期（2010 起）

**要点**：OpenBSD 4.x 时期（2005-2010）仍以 gcc 4.x 为默认编译器；2007 年起 de Raadt 对 gcc GPLv3 许可证与代码质量不满，开始探索替代方案；OpenBSD 团队曾尝试集成 pcc（Portable C Compiler）作为 gcc 替代，但因 pcc 功能不足（不支持 C99 完整特性、缺乏优化）放弃——bsd_commits.db openbsd-src 仓库中无 pcc（Portable C Compiler）实际集成 commit，pcc 探索主要在邮件列表讨论；至 4.x 末期（2010-2011）OpenBSD 开始评估 clang/LLVM 作为最终替代，为 5.7（2014.5）完全切换至 clang/LLVM 奠定基础

**史料**：de Raadt 关于 gcc GPLv3 的邮件列表发言（<https://marc.info/?l=openbsd-tech>）；pcc 项目文档（<http://pcc.ludd.ltu.se/>）；OpenBSD tech@ 邮件列表关于 pcc/clang 的讨论；bsd_commits.db openbsd-src 仓库 pcc 相关 commit（数据库中 "pcc" 关键字搜索结果均为 pccons/pccom 误匹配，无 Portable C Compiler 实际集成记录） ［A］

**史观**：总纲第 24 条——许可证：gcc GPLv3 许可证争议是 OpenBSD 探索编译器替代的根本动因——OpenBSD 的 ISC 许可证偏好与 gcc GPLv3 的 copyleft 要求存在张力，这一张力推动 OpenBSD 评估 pcc（失败）与 clang/LLVM（成功）作为替代

**辨析**：OpenBSD 尝试 pcc 的具体时间以 tech@ 邮件列表讨论存档为准——pcc 探索主要在 2007-2008 年的邮件列表讨论中进行，未进入 openbsd-src 主干；pcc 放弃的具体原因以 de Raadt 与其他开发者的邮件列表发言为准——pcc 不支持 C99 完整特性、缺乏现代优化器；gcc 到 clang/LLVM 的切换动机以 OpenBSD 5.7 Release Notes 与 de Raadt 的公告为准——GPLv3 担忧与技术优势（更好的诊断信息、模块化设计）均为动机

**文献**：pcc 项目文档 [EB/OL]. <http://pcc.ludd.ltu.se/>；OpenBSD tech@ 邮件列表档案 [EB/OL]. <https://marc.info/?l=openbsd-tech>；de Raadt 关于 gcc 的发言；clang/LLVM 项目文档 ［A］

## 191.1.3 yplib/ypcat → ypldap 替换（NIS → LDAP）

**要点**：NIS（Network Information Service，原 Yellow Pages）是 Sun Microsystems 1980 年代设计的网络目录服务，OpenBSD 早期通过 **yplib(3)**、**ypcat(1)**、**ypmatch(1)** 等工具支持；NIS 因安全设计缺陷（无认证、明文传输）逐步被 LDAP 取代；bsd_commits.db 显示 ypldap 首次 commit 为 2008-06-26 pyr commit f624240892b9 "ypldap -- Intended to be a drop-in replacement for ypserv, gluing in a LDAP directory a..."（4.4 周期，2008.11 release），2008-10-14 deraadt commit 33b8cba20fd2 "enable ypldap. serious development needs it to be enabled." 在 4.5 周期正式启用——原大纲称 “5.x 时期成熟” 系误记，ypldap 在 4.4-4.5 周期（2008-2009）已引入并启用；ypldap 作为 NIS 与 LDAP 的桥接，让 NIS 客户端可查询 LDAP 目录

**史料**：bsd_commits.db openbsd-src 仓库 commit f624240892b9（2008-06-26 pyr "ypldap -- Intended to be a drop-in replacement for ypserv"）、commit 33b8cba20fd2（2008-10-14 deraadt "enable ypldap"）；Sun NIS 文档；OpenBSD **ypldap(8)** 手册页（<https://man.openbsd.org/ypldap.8>） ［A］

**史观**：总纲第 19 条——信息技术：NIS 作为 1980 年代的网络目录信息技术被 LDAP 聚合替代——ypldap 的引入是 OpenBSD 对网络目录服务从 NIS 向 LDAP 迁移趋势的响应，但 OpenBSD 选择桥接（ypldap）而非直接取代（删除 ypserv）的渐进路径

**辨析**：ypldap 在 OpenBSD 中的引入版本以 bsd_commits.db commit log 为准——2008-06-26 pyr@ 首次引入（4.4 周期），2008-10-14 deraadt@ 启用（4.5 周期），原大纲称 “4.5 或更早” 与 “5.x 时期成熟” 均不准确；ypldap 与传统 ypserv 的关系以 **ypldap(8)** 手册页为准——ypldap 模拟 ypserv 协议让 NIS 客户端透明查询 LDAP，二者并存而非替代；NIS 在 OpenBSD 中的实际部署规模无权威统计 [考据完成：2026-07-28 NIS 在 OpenBSD 部署中的占比无公开调研]

**文献**：bsd_commits.db openbsd-src 仓库 commit f624240892b9、33b8cba20fd2；Sun NIS 文档；OpenBSD **ypldap(8)** 手册页 [EB/OL]. <https://man.openbsd.org/ypldap.8> ［A］

## 191.1.4 OpenSSL 集成与磁盘加密演进（softraid 加密等）

**要点**：OpenBSD 3.0（2001.12）引入 vnd 块设备的加密模式 svnd，使用 Blowfish 算法；OpenBSD 4.x 时期持续改进加密栈——softraid 加密于 2007-11-27 tedu commit f18dcc9c26b1 首次引入（4.2 周期），2008-06-14 hshoexer commit 79cdc9424edb 完整启用（4.4 周期），支持 AES-XTS，取代 svnd 成为推荐的磁盘加密方案；4.x 时期的 OpenSSL 集成为后续 LibreSSL fork（2014 年 4 月 Heartbleed 后）积累了 OpenSSL 工程实践——但 LibreSSL fork 发生在 5.6 周期（2014.11），与 4.x 时期（2005-2010）相隔约 4 年，二者不构成直接的 “前期演进” 关系

**史料**：bsd_commits.db openbsd-src 仓库 commit f18dcc9c26b1（2007-11-27 tedu "split crypto functions"）、commit 79cdc9424edb（2008-06-14 hshoexer "enable softraid crypto"）；OpenBSD 3.0 Release Notes vnd 部分；OpenBSD 4.2/4.4 Release Notes softraid 部分；OpenBSD **softraid(4)**、**bioctl(8)** 手册页 ［A］

**史观**：总纲第 21 条——密码学：加密栈从 svnd（Blowfish）到 softraid（AES-XTS）的演进是 OpenBSD 对密码学最佳实践变化的响应——AES-XTS 作为 NIST SP 800-38E 推荐的磁盘加密模式取代 Blowfish，这一路径是密码学标准演进对操作系统实现的具体塑造

**辨析**：svnd 与 softraid 的关系以 bsd_commits.db commit log 为准——softraid 首次 commit 为 2007-03-19 dlg commit 98855ba5cdbc "attach softraid to the root of the device tree"，是新的 RAID 框架，加密是其子功能；AES-XTS 支持的具体引入版本以 **softraid(4)** 手册页与 commit log 为准——softraid 加密自 2008 年启用即支持 AES-XTS；4.x 时期 OpenSSL 集成的具体版本以 OpenBSD Release Notes 为准

**文献**：bsd_commits.db openbsd-src 仓库 commit 98855ba5cdbc、f18dcc9c26b1、79cdc9424edb；OpenBSD Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>；OpenBSD **softraid(4)** 手册页 [EB/OL]. <https://man.openbsd.org/softraid.4> ［A］

### 史观映射

OpenBSD 4.x 时期是项目统摄史观中 “形式主义化” 与 “修道度人” 在网络安全领域的双重实践。6 个月发布周期作为形式主义化结构（总纲第 17 条——软件工程），将时间固化为不可动摇的规则——krw@ 与 espie@ 的 release engineering 工作严格遵循 5 月与 11 月的节奏，这一形式化结构带来稳定性与可预测性，但也限制了单周期内的重大架构重构。pf 的持续演进是 “修道度人” 的工程实践（总纲第 17 条——软件工程）——claudio@ 与 henning@ 在 2005-2010 年间持续改进 pf，让 pf 守护着无数网络的边界，但 pf 的作者们很少在公众视野中出现。CARP 冗余协议的开发是对法律结构障碍的重新设计（总纲第 12 条——法律结构）——当 VRRP 协议的 Cisco 专利 US 5,473,599 成为障碍时，OpenBSD 选择重新设计协议（CARP）而非寻求专利授权，这一选择是法律结构对技术实现的直接塑造。malloc 替代（tedu@ 2006-10-24 commit 66e23c51）是 “边缘者承担安全关键基础设施” 的具体显现（总纲第 10 条——边缘者贡献）——OpenBSD 的 malloc 安全替代由单一开发者响应安全研究社区的漏洞披露而实现，非由大厂商团队推动。softraid 加密的引入（tedu@ 2007-11-27 commit f18dcc9c26b1 至 hshoexer@ 2008-06-14 commit 79cdc9424edb）是密码学标准演进对操作系统实现的具体塑造（总纲第 21 条——密码学）——AES-XTS 作为 NIST SP 800-38E 推荐模式取代 Blowfish。de Raadt 的个人主导模式是 “动手者” 存在主义的体现——一个人在不被理解中坚持自己的工程哲学，BDFL 治理（总纲第 23 条——社区治理）使 OpenBSD 在 4.x 时期保持技术方向一致性。
