## 192.6.1 OpenBSD 4.0-4.9 RELEASE 公告清单与 release song

**要点**：OpenBSD 4.x 时期共发布 10 次 release（4.0 至 4.9），发布周期严格遵循 6 个月节奏；4.x 时期 release song 延续 3.x 时期的“Puffy 系列”叙事传统——4.0“Puff the Magic OpenBSD”、4.2“Puffy's Smoke”、4.3“Puff the Daddy”、4.6“Puff the Magic OpenBSD II”、4.9“Puffy's Garden”——同时引入非 Puffy 主题的 release song（4.1“Distribution of the Few”、4.4“100% Pure Cheese”、4.5“The Slow Bravado”、4.7“Game Over”、4.8“The World's Most Committed Code”），反映 release song 主题从单一 Puffy 形象向多元主题扩展；4.6（2009-10-18）为 4.x 时期唯一在 10 月发布的 release（其余均在 5 月或 11 月），呼应 OpenBSD 每年 5 月/10 月的发布周期传统

**要点**：

- 发布模型的自述：OpenBSD 开发不为赶特性出库，而是在特定时点把代码树整备可用——四到五个月向树中投入开发，每六个月强制停止添加新东西、再花约一个月测试修复后发布；不设特性清单，被概括为演化而非革命，版本号只是快照语义，4.0 并不比 3.9 更重大；4.0 的主题被当事人定义为按自己的方式做事而非追随业界方向，重申其工作的独特性。（BSDTalk EP79，[142.30-255.80]，L1）
- MPT 驱动重写的工程逻辑：LSI MPT Fusion 固件接口把光纤通道、并行 SCSI、SAS 及 iSCSI 变体抽象成统一界面，本应单一驱动通吃；旧驱动写于仅两类总线存在之时、硬编码类型且结构混乱；当事人选择重写而非修补——重写后修复 64 位清洁、总线字节序清洁、支持缓存一致架构、覆盖除未获测试的 iSCSI 外全部总线类型且更快。（BSDTalk EP79，[278.44-374.42]，L1）
- 重写哲学对业界常态的批评：MPT 驱动从约一万至一点一万行收缩到约五千行、还支持了更多硬件；问题根源在于人们往仍能工作的旧代码旁贴补丁——不重思流程、在外围悬挂补丁，复杂度与体积随之增长；退一步重新设计才有机会大幅缩减。主持人点出这是逆行业加特性加行数加复杂度潮流而动的趋势。（BSDTalk EP79，[416.00-482.58]，L1）
- 厂商文档困境与逆向路径：LSI 不提供文档、获取其 SCSI 与 RAID 控制器文档须签 NDA，当事人与 Marco Peereboom 合作、以 Linux 与 FreeBSD 驱动为参考推定 IO 路径命令，Marco 因工作中大量接触而署名；4.0 新写的 Areca RAID 控制器 ARC 驱动同样无厂商文档——厂商可能根本没有——改用 FreeBSD 驱动加芯片开源规格；完成 ARC 后当事人一度倦怠。（BSDTalk EP79，[375.32-416.00]，L1）
- bio/bioctl 框架扩张与 RAID 卡不特殊论：3.9 仅 AMI MegaRAID 一个驱动受 bio 支持，4.0 已有四个驱动带 bioctl 支持——证明 RAID 卡并非特殊设备，理应有一个工具监控并控制所有 RAID 卡；MPT 是纯 SCSI 控制器暂不需 bio 钩子（其 RAID 特性待接入），ARC 已能查看卷与磁盘状态；当事人偏爱的卡是 MFI 驱动支持的 LSI MegaRAID SAS，且明确偏好 SAS 与 SATA 替代并行 SCSI，MFI 亦由 Marco Peereboom 在 4.0 完成。（BSDTalk EP79，[517.98-602.14]，L1）
- SCSI 中层的结构性性能瓶颈：控制器 opening 数被中层按总线上可能的目标数均分——光纤通道按 256 目标把 1024 个命令均分后每设备仅剩四个未决命令，而实际总线上仅挂三四个盘、每盘本可接受百余个；未决命令过少使磁盘无法有效重排操作，最坏情形性能折半；另一限制是每事务 64KB 上限而现代 SCSI 设备可达 32MB，推高该值牵动大量内核子系统，暂未着手。（BSDTalk EP79，[751.30-858.58]，L1）
- SCSI 与 SATA 的走向判断：SCSI 协议活得很好，其先进性长期领先 ATA；未来可能是 SCSI 反向吞并 SATA——业界趋势已是一切存储都呈 SCSI 形态，Linux 内核把 ATA 控制器呈现为 SCSI 设备、RAID 卡厂商把控制器做成 SCSI 卡；SCSI 已是内核与存储对话的事实语言，OpenBSD 未来也想如此。（BSDTalk EP79，[858.58-912.82]，L1）
- 4.1 计划与 4.0 亮点：VMware 虚拟接口驱动重写耗时两天接近完成、确定进入 4.1，另与 Marco 修复 SCSI 中层问题；4.0 带来五个新无线驱动与 SDMMC 支持。（BSDTalk EP79，[604.14-635.38]，L1）
- 澳大利亚的孤独开发者：当事人自称布里斯班唯一 hardcore OpenBSD 用户，雇主 Chris Pascoe 拥有 commit 权限，本人性格内向、不参与 Unix 用户组社交，本地用户因其设备支持工作以午饭相邀；工作环境以 OpenBSD 承载防火墙（大量工作由 Chris Pascoe 完成）与 DNS、代理、SSL 包装，重负载在 Solaris 与 Windows 服务器；家中以 OpenBSD shell 机、桌面与多台开发服务器自足。（BSDTalk EP79，[654.38-743.30]，L1）

**史料**：

- 该期留存的一手史料线索：OpenBSD 4.0 中的 MPT 重写、ARC 与 MFI 新驱动及 3.9 到 4.0 的 bio 支持驱动数量对比；为其 4.1 预备的 VMware 虚拟接口驱动重写；月底葡萄牙硬件 hackathon 与威尼斯 OpenCON 的两场报告安排；当事人以 Linux 与 FreeBSD 驱动为参考逆向 LSI 命令路径的工作方法。（BSDTalk EP79，[489.10-652.38]，L1）

**史观**：

- 总纲25 逻辑是形式主义而非世界本身的结构：旧驱动的硬编码结构是早期硬件假设的形式固化，业界在旧形式上不断贴补丁使复杂度成为纯粹的积累物；OpenBSD 的重写实践承认既有结构只是历史形式而非必然——推倒重建后以约一半的代码覆盖更多硬件，形式被还原为可以重写的构造。（BSDTalk EP79，[450.12-482.58]，L1）
- 总纲8 本体论上各方平等：RAID 卡不特殊的论断把厂商刻意营造的设备特殊性还原为普通 SCSI 设备的一般性：在 bio 框架之下各类控制器本体论地位平等，理应由同一工具监控控制——特殊待遇只是形式主义的差别化建构，4.0 的四个驱动以事实证明了这一点。（BSDTalk EP79，[561.10-578.10]，L1）
