# 191.3 OpenBSD 与加密学的深度结合（2005-2012）——OpenBSD 将加密视为基本系统核心组件，集成 OpenSSL、disk encryption、network encryption 的全面支持

## 191.3.1 加密集成的工程哲学

**要点**：OpenBSD 在 2005-2012 年间将加密作为基本系统的核心组件而非可选模块——OpenSSH 默认启用、IPSec 栈集成、SSL/TLS 库与磁盘加密均随系统发布；de Raadt 在 misc@ 与 tech@ 邮件列表多次主张 “加密不是可选项”，与 Linux/FreeBSD 将加密作为可加载模块的工程哲学不同——Linux 的加密算法作为内核模块（crypto subsystem）按需加载，FreeBSD 的 GEOM_ELI 作为可选模块加载，OpenBSD 的加密固化为基本系统不可分割的一部分

**史料**：OpenBSD Release Notes 3.0-5.x 加密相关条目（<https://www.openbsd.org/plus.html>）；de Raadt 在 misc@ 与 tech@ 邮件列表的发言（<https://marc.info/?l=openbsd-misc>、<https://marc.info/?l=openbsd-tech>）；OpenBSD 加密设计文档（<https://www.openbsd.org/faq/faq14.html>） ［A］

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：原挂第 7 条“技术选择即政治选择”系伪标签，按核查报告处方重挂待终核〕：将加密默认启用是技术选择也是利益分配格局的呈现——OpenBSD 以 “默认安全” 对抗 “默认可用”，这一选择使 OpenBSD 在部署便利性上落后于 Linux/FreeBSD（后者默认不启用加密减少性能开销），但在安全基线上领先

**辨析**：“加密默认启用” 的具体时间点以 Release Notes 为准——OpenBSD 3.0（2001.12）起将 OpenSSH 作为默认远程登录，IPSec 栈在 2.7（2000.7）起集成；IPSec 集成的具体贡献者以邮件列表记录为准——OpenBSD IPSec 代码部分源自 NRL（Naval Research Laboratory）的研究实现，部分由 OpenBSD 团队重写，二者的代码血缘以 commit log 的 author_name 与 message_body 交叉确认

**文献**：OpenBSD 3.0-5.x Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>；de Raadt 邮件列表发言 [EB/OL]. <https://marc.info/?l=openbsd-misc>；OpenBSD 加密 FAQ [EB/OL]. <https://www.openbsd.org/faq/faq14.html> ［A］

## 191.3.2 disk encryption 的实现

**要点**：OpenBSD 3.0（2001.12）引入 vnd 块设备的加密模式 svnd，使用 Blowfish 算法——openbsd.duckdb 显示 svnd 最早可追溯至 1997-05-14 niklas commit `fa8fd3804712` “Use svnds and remove ugly cache flushing”，但加密模式在 3.0 周期正式启用；softraid 加密于 2007-11-27 tedu commit `f18dcc9c26b1` "split crypto functions out into their own file, so softraid.c is not such a jungle" 将加密函数独立成文件（4.3 周期；该 commit 系函数拆分重构而非加密功能引入），2008-06-14 hshoexer commit `79cdc9424edb` "Update bioctl(8) and softraid(4) to recent changes and enable softraid crypto. It's still..." 首次完整启用（4.4 周期）——原大纲称 “5.4（2013.10）引入 softraid 加密” 系误记，softraid 加密在 4.3-4.4 周期（2007-2008）完成铺垫并启用；softraid 加密支持 AES-XTS，取代 svnd 成为推荐的磁盘加密方案；与 FreeBSD **geli(8)**/GEOM_ELI 相比，OpenBSD softraid 与系统启动流程深度集成

  **softraid 加密 commit 时间线**：

  | 日期 | commit hash | 作者 | 说明 |
  | --- | --- | --- | --- |
  | 1997-05-14 | `fa8fd3804712` | niklas | Use svnds and remove ugly cache flushing |
  | 2007-03-19 | `98855ba5cdbc` | dlg | attach softraid to the root of the device tree |
  | 2007-11-27 | `f18dcc9c26b1` | tedu | split crypto functions out into their own file |
  | 2008-06-14 | `79cdc9424edb` | hshoexer | enable softraid crypto |

**史料**：openbsd.duckdb openbsd-src 仓库 commit fa8fd3804712（1997-05-14 niklas “Use svnds”）、commit f18dcc9c26b1（2007-11-27 tedu “split crypto functions”）、commit 79cdc9424edb（2008-06-14 hshoexer “enable softraid crypto”）；OpenBSD 3.0 Release Notes vnd 部分；OpenBSD 4.2/4.4 Release Notes softraid 部分；OpenBSD **softraid(4)**、**bioctl(8)** 手册页 ［A］

**史观**：总纲第 3 条——不存在进步，只有权力再分配〔存疑：原挂第 6 条“技术选择的代价”系伪标签，按核查报告处方重挂待终核〕：OpenBSD 选择与系统启动集成的 softraid 方案，牺牲了灵活性换来了一致性与安全性——softraid 加密卷可在引导阶段解锁（通过 boot prompt），无需额外 initramfs，这一设计简化了部署但限制了加密卷的动态管理

**辨析**：svnd 与 softraid 的关系——softraid 并非 svnd 的简单替代，而是新的 RAID 框架（openbsd.duckdb 显示 softraid 首次 commit 为 2007-03-19 dlg commit 98855ba5cdbc “attach softraid to the root of the device tree”），加密是其子功能之一；AES-XTS 支持的具体引入版本以 **softraid(4)** 手册页历次版本与 commit log 为准——softraid 加密自 2008 年启用即支持 AES-XTS

**文献**：openbsd.duckdb openbsd-src 仓库 commit 98855ba5cdbc、f18dcc9c26b1、79cdc9424edb；OpenBSD **softraid(4)** 手册页 [EB/OL]. <https://man.openbsd.org/softraid.4>；OpenBSD **bioctl(8)** 手册页 [EB/OL]. <https://man.openbsd.org/bioctl.8> ［A］

## 191.3.3 network encryption 的全面支持

**要点**：OpenBSD 网络加密主要由 IPSec 栈（与 NRL 合作）、**isakmpd(8)**（IKE 密钥协商，1998-11-15 niklas commit 2040585efcaf “Initial import of isakmpd” 首次导入）、OpenSSH 默认远程登录、**ssl(8)** SSL/TLS 库组成；**iked(8)** 于 2010-06-28 reyk commit 54a1861596 "Add iked to rc/rc.conf, you can enable it on boot with the iked_flags = var" 首次引入（4.8 周期，2010.11），作为 isakmpd 的现代替代——iked 与 isakmpd 在 4.8 后并存，isakmpd 未立即弃用；OpenBSD 网络加密的 “默认安全” 哲学让其在 VPN 与边界设备部署中获得存在感

**史料**：openbsd.duckdb openbsd-src 仓库 commit 2040585efcaf（1998-11-15 niklas “Initial import of isakmpd”）、commit 54a1861596（2010-06-28 reyk “Add iked to rc/rc.conf”）；OpenBSD Release Notes IPSec 部分；NRL IPSec 文档；OpenBSD **isakmpd(8)**、**iked(8)**、**ipsec(4)** 手册页 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：原描述符“组织结构塑造技术路径”系伪标签，按核查报告处方重挂待终核〕：OpenBSD 与 NRL 的合作让 IPSec 路径固化于基本系统——NRL IPSec 代码作为研究实现被 OpenBSD 集成，后续由 OpenBSD 团队持续维护与重写，这一路径使 OpenBSD IPSec 与 Linux/FreeBSD 的 IPSec 实现产生分化

**辨析**：NRL IPSec 与 OpenBSD IPSec 的代码血缘以 commit log 的 author_name 与 message_body 交叉确认——部分文件保留 NRL 版权头，部分由 OpenBSD 重写；**iked(8)** 取代 **isakmpd(8)** 的过程是渐进的——iked 于 4.8（2010.11）引入，isakmpd 在后续 release 中仍保留，二者并存至 5.x 周期

**文献**：openbsd.duckdb openbsd-src 仓库 commit 2040585efcaf、54a1861596；NRL IPSec 文档；OpenBSD **ipsec(4)** 手册页 [EB/OL]. <https://man.openbsd.org/ipsec.4>；OpenBSD **iked(8)** 手册页 [EB/OL]. <https://man.openbsd.org/iked.8> ［A］
