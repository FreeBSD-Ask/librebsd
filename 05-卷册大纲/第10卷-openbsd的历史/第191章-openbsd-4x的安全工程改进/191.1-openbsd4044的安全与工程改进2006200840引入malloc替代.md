# 190.1 OpenBSD 4.0-4.4 的安全与工程改进（2006-2008）——4.0 引入 malloc 替代、4.1 改进 pf 语法、4.2 引入 softraid 加密雏形、4.4 完整启用 softraid 加密


## 190.1.1 malloc 替代的安全设计
  - 要点：OpenBSD 4.0（2006.11）开发周期引入 malloc 替代实现，核心工作由 tedu@（Ted Unangst）推动——2006-10-24 tedu commit `66e23c51d017082140fbe2ea4dc683819862f8c9` "respond to ben hawkes's ruxcon presentation. create special allocators for pg..."，针对 Ben Hawkes 在 RUXCON 2006 演示的堆漏洞利用，引入分页级独立分配器、guard page 与 free 后填充等安全特性；otto@（Otto Moerbeek）在 4.x 周期持续维护 malloc 子系统（bsd_commits.db 显示 otto@ 2005-01-03 至 2010-12-22 共 1020 条 commit）；malloc 替代让堆溢出与 use-after-free 攻击更难利用

  **malloc 替代关键 commit**：

  | 日期 | commit hash | 作者 | 说明 |
  | --- | --- | --- | --- |
  | 2006-10-24 | `66e23c51d017082140fbe2ea4dc683819862f8c9` | tedu@ | respond to ben hawkes's ruxcon presentation, create special allocators |
  | 2005-01-03 至 2010-12-22 | （多条） | otto@ | malloc 子系统持续维护，共 1020 条 commit |

  - 史料：bsd_commits.db openbsd-src 仓库 commit 66e23c51d017082140fbe2ea4dc683819862f8c9（2006-10-24 tedu "respond to ben hawkes's ruxcon presentation. create special allocators..."）；OpenBSD 4.0 Release Notes malloc 部分（<https://www.openbsd.org/40.html>）；Ben Hawkes RUXCON 2006 演讲档案；bsd_commits.db openbsd-src 仓库 otto@ 2005-2010 commit 统计 ［A］
  - 史观：总纲第 10 条——边缘者贡献：tedu@ 作为 OpenBSD 核心开发者对 malloc 安全替代的工程实现，是 “边缘者承担安全关键基础设施” 的具体显现——OpenBSD 的 malloc 替代不是由大厂商团队推动，而是由单一开发者响应安全研究社区的漏洞披露（Ben Hawkes 的 RUXCON 演讲）而实现
  - 辨析：OpenBSD malloc 与 FreeBSD phk malloc、Linux SLAB 的性能对比无单一权威基准——OpenBSD 以安全（guard page、随机化）为优先，FreeBSD phk malloc（Poul-Henning Kamp（波尔-亨宁·坎普） 设计）以性能为优先，Linux SLAB/SLUB 以多核扩展性为优先，三者的设计目标不同使性能对比须明确测试维度；malloc 替代对实际漏洞利用的防御效果以 OpenBSD CVE 历史记录中堆相关漏洞的可利用性变化为准——2010 年后 OpenBSD 堆相关 CVE 数量低于同期 Linux，但因果关系无学术研究证实 [考据完成：2026-07-28 OpenBSD malloc 替代与 CVE 数量下降的因果关系无同行评审研究]
  - 文献：bsd_commits.db openbsd-src 仓库 commit 66e23c51d017082140fbe2ea4dc683819862f8c9；OpenBSD 4.0 Release Notes [EB/OL]. <https://www.openbsd.org/40.html>；phk malloc 论文；Linux SLAB/SLUB 文档 ［A］
## 190.1.2 pf 语法的改进与扩展
  - 要点：OpenBSD 4.1（2007.5）改进 pf 语法，2005-05-22 henning commit a60c9213a0df 引入 interface groups 匹配（"allow pf to match on interface groups pass on mygroup..."），让 pf 规则可按接口组而非单一接口匹配；4.2（2008.11）扩展 anchors 与 tables 语法；bsd_commits.db 显示 2005-2010 年间 pf 相关 commit 以 claudio@（198 条）与 henning@（169 条）为主，原大纲称 “Henning Brauer（亨宁·布劳尔）、Reyk Flöter、Daniel Hartmeier（丹尼尔·哈特迈尔） 等是主要贡献者”——Daniel Hartmeier 是 pf 的原始作者（2001 年首次引入），但 4.x 时期的主要维护者是 claudio@ 与 henning@
  - 史料：bsd_commits.db openbsd-src 仓库 commit a60c9213a0df（2005-05-22 henning "allow pf to match on interface groups"）；OpenBSD 4.1-4.3 Release Notes pf 部分（<https://www.openbsd.org/41.html>、https://www.openbsd.org/42.html、https://www.openbsd.org/43.html）；bsd_commits.db openbsd-src 仓库 2005-2010 pf 相关 commit 贡献者统计（claudio 198、henning 169、mcbride 52） ［A］
  - 史观：总纲第 17 条——软件工程：pf 语法作为接口契约的演进——interface groups 匹配让 pf 规则从 “按接口名硬编码” 升级为 “按接口组抽象”，这一变更将运维需求（多接口环境下的规则复用）转化为语法特性，是软件工程中 “抽象层次提升” 在防火墙配置语言层的实践
  - 辨析：pf 语法在不同 OpenBSD 版本中的具体变化以 **pf.conf(5)** 手册页历次版本与 Release Notes 交叉为准——Release Notes 记录用户可见的语法变更（如 interface groups），**pf.conf(5)** 手册页记录完整语法规范；anchors 与 tables 的语义差异以 **pf.conf(5)** 手册页为准——anchors 是命名规则块可动态替换，tables 是命名地址集合可动态更新，二者用途不同
  - 文献：bsd_commits.db openbsd-src 仓库 commit a60c9213a0df；OpenBSD 4.1-4.3 Release Notes [EB/OL]. <https://www.openbsd.org/41.html>；OpenBSD **pf.conf(5)** 手册页 [EB/OL]. <https://man.openbsd.org/pf.conf.5> ［A］
## 190.1.3 与 FreeBSD malloc/Linux SLAB 的比较
  - 要点：FreeBSD 使用 phk malloc（Poul-Henning Kamp 1995 年设计），Linux 使用 SLAB/SLUB 分配器；OpenBSD malloc 强调安全（guard page、随机化、free 后填充），FreeBSD phk malloc 强调性能与 per-CPU 缓存，Linux SLAB/SLUB 强调多核扩展性与内存回收效率；三者设计哲学反映各自社区优先级——OpenBSD 安全优先、FreeBSD 性能优先、Linux 扩展性优先

  **三大 malloc 实现对比**：

  | 项目 | 设计者 | 设计优先级 | 关键特性 | 性能开销 |
  | --- | --- | --- | --- | --- |
  | OpenBSD malloc | tedu@（2006 替代） | 安全优先 | guard page、随机化、free 后填充 | 约 5-10% |
  | FreeBSD phk malloc | Poul-Henning Kamp（1995） | 性能优先 | per-CPU 缓存 | 接近原生 |
  | Linux SLAB/SLUB | Jeff Bonwick（杰夫·邦威克） 等 | 扩展性优先 | 多核扩展、内存回收 | 接近原生 |

  - 史料：phk malloc 论文（Poul-Henning Kamp, "You're Doing It Wrong", 2010, ACM Queue）；Linux SLAB/SLUB 文档（<https://www.kernel.org/doc/html/latest/mm/slab.html>）；OpenBSD malloc 文档（<https://man.openbsd.org/malloc.3>）；openbsd.db openbsd-src 仓库 tedu@ malloc 相关 commit ［A］
  - 史观：总纲第 7 条——技术选择即政治选择：三个项目 malloc 设计反映各自政治选择——OpenBSD 以 “安全为不可妥协之预设” 选择 guard page 与随机化（性能开销为代价），FreeBSD 以 “性能为部署之基” 选择 per-CPU 缓存（安全特性为可选），Linux 以 “扩展性为规模化之钥” 选择 SLAB/SLUB（安全特性由 SELinux 等外部机制承担）
  - 辨析：三者性能对比以同硬件同负载的 SPECint 等基准测试为准——OpenBSD malloc 的 guard page 与随机化带来约 5-10% 性能开销（OpenBSD 邮件列表讨论估算，无同行评审基准），FreeBSD phk malloc 与 Linux SLUB 性能接近；安全特性的防御效果以 CVE 历史与漏洞利用研究为准——OpenBSD malloc 的 guard page 可检测部分堆溢出，但对堆内 off-by-one 溢出无防御效果
  - 文献：Poul-Henning Kamp. You're Doing It Wrong [J]. ACM Queue, 2010；Linux SLAB/SLUB 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/mm/slab.html>；OpenBSD **malloc(3)** 手册页 [EB/OL]. <https://man.openbsd.org/malloc.3> ［A］

  - 史观：总纲第 25 条——0 信任原则：Release Notes 与 commit log 的交叉验证是 0 信任原则在版本史研究中的实践——Release Notes 仅记录 “重要的和用户可见的变更”（<https://www.openbsd.org/plus.html>），部分内部代码重构（如 tedu@ 的 malloc 分配器拆分）可能在 Release Notes 中简化描述但可在 commit log 中定位完整变更；统计结论印证——C-14 Pettitt 变点 2001-01 反映 “分离聚合是永恒规律”（总纲第 4 条）的工程节奏显现：4.x 时期（2005-2010）处于 2001-01 变点之后的工程节奏阶段，OpenBSD 从 fork 后的高位 commit 量（2.x-3.x 时期的 pf fork、W^X、SSP 集中引入）向稳态工程节奏（4.x 时期的 malloc 替代、softraid 加密、pf 语法持续改进）过渡，commit 量层面的变点与工程节奏转换在 2001-01 时点形成可检测的工程节点
  - 辨析：Release Notes 的完整性以 plus.html 页面为准——该页面仅记录用户可见变更，内部代码重构需以 commit log 补充；OpenBSD 仓库无 release tag（OpenBSD 使用 CVS 而非 git tag 标记 release），故 release 日期以 OpenBSD 官方网站公告为准 [考据完成：2026-07-28 openbsd.db tags 表中无 openbsd-src 仓库的 release tag，OpenBSD release 日期须以 openbsd.org 官方公告为准]；openbsd.db 查询 L1.1.1 局限：L1.1.1 报告仅显示 23 仓库 572 行结果中的前 30 行（全为 dragonfly 仓库），openbsd-src 逐年数据须经 L1.1.2 查询交叉验证获取，但 L1.1.2 报告亦仅显示 124 行中的前 30 行（覆盖 1995-2002 年），2003-2010 年 openbsd-src 份额数据须以数据库直接查询补全；openbsd-src 为 GitHub 镜像，commit 量可能滞后于 OpenBSD CVS 主仓；commit 量反映开发活跃度但不等于代码质量；**统计局限性标注**——C-05 总 commit 数 245,904 包含 1995-10 fork 后至 2026 年全部 commit，非 4.x 时期专属，跨期引用时须结合时间窗口切片；C-14 变点检测的 Pettitt 与 BUISHAND 两检验变点时点不一致（2001-01 vs 2017-09），反映变点检测方法的方法学敏感性——Pettitt 检验对中段变点敏感，BUISHAND 检验对全样本变点敏感，两检验变点不一致不等于 “变点不存在” 而反映 “不同检验对变点位置的统计推断差异”；统计显著 ≠ 实际显著，Pettitt 2001-01 变点须与 OpenBSD 3.0（2001-12-01）发布、IPFilter 许可证争议（2001-05）、pf fork（2001）等工程事件交叉验证后方可归因；多重比较风险——C-14 与 C-12（freebsd-src 变点 1999-08）、C-13（netbsd-src 变点 2011/2012）、C-15（dragonfly-src 变点 2016/2017）跨项目对比时须按 Bonferroni 校正；0 信任原则适用——变点检测基于月度 commit 量序列，commit 量本身无法区分审计 commit 与功能 commit，变点的工程归因须以 commit message 与 release event 交叉验证
