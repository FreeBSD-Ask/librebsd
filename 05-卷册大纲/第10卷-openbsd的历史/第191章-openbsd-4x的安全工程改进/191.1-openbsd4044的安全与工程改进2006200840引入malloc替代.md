# 191.1 OpenBSD 4.0-4.4 的安全与工程改进（2006-2008）——4.0 引入 malloc 替代、4.1 改进 pf 语法、4.2 引入 softraid 加密雏形、4.4 完整启用 softraid 加密

## 191.1.1 malloc 替代的安全设计

**要点**：OpenBSD 4.0（2006.11）开发周期引入 malloc 替代实现，核心工作由 tedu@（Ted Unangst）推动——2006-10-24 tedu commit `66e23c51d017082140fbe2ea4dc683819862f8c9` "respond to ben hawkes's ruxcon presentation. create special allocators for pg..."，针对 Ben Hawkes 在 RUXCON 2006 演示的堆漏洞利用，引入分页级独立分配器、guard page 与 free 后填充等安全特性；otto@（Otto Moerbeek）在 4.x 周期持续维护 malloc 子系统（openbsd.duckdb 显示 otto@ 2005-01-03 至 2010-12-22 共 1020 条 commit）；malloc 替代让堆溢出与 use-after-free 攻击更难利用

  **malloc 替代关键 commit**：

  | 日期 | commit hash | 作者 | 说明 |
  | --- | --- | --- | --- |
  | 2006-10-24 | `66e23c51d017082140fbe2ea4dc683819862f8c9` | tedu@ | respond to ben hawkes's ruxcon presentation, create special allocators |
  | 2005-01-03 至 2010-12-22 | （多条） | otto@ | malloc 子系统持续维护，共 1020 条 commit |

**史料**：openbsd.duckdb openbsd-src 仓库 commit 66e23c51d017082140fbe2ea4dc683819862f8c9（2006-10-24 tedu "respond to ben hawkes's ruxcon presentation. create special allocators..."）；OpenBSD 4.0 Release Notes malloc 部分（<https://www.openbsd.org/40.html>）；Ben Hawkes RUXCON 2006 演讲档案；openbsd.duckdb openbsd-src 仓库 otto@ 2005-2010 commit 统计 ［A］

**史观**：总纲第 10 条——边缘者贡献：tedu@ 作为 OpenBSD 核心开发者对 malloc 安全替代的工程实现，是 “边缘者承担安全关键基础设施” 的具体显现——OpenBSD 的 malloc 替代不是由大厂商团队推动，而是由单一开发者响应安全研究社区的漏洞披露（Ben Hawkes 的 RUXCON 演讲）而实现

**辨析**：OpenBSD malloc 与 FreeBSD phk malloc、Linux SLAB 的性能对比无单一权威基准——OpenBSD 以安全（guard page、随机化）为优先，FreeBSD phk malloc（Poul-Henning Kamp（波尔-亨宁·坎普） 设计）以性能为优先，Linux SLAB/SLUB 以多核扩展性为优先，三者的设计目标不同使性能对比须明确测试维度；malloc 替代对实际漏洞利用的防御效果以 OpenBSD CVE 历史记录中堆相关漏洞的可利用性变化为准——2010 年后 OpenBSD 堆相关 CVE 数量低于同期 Linux，但因果关系无学术研究证实 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 191.1.2 pf 语法的改进与扩展

**要点**：OpenBSD 4.1（2007.5）改进 pf 语法，2005-05-22 henning commit a60c9213a0df 引入 interface groups 匹配（“allow pf to match on interface groups pass on mygroup...”），让 pf 规则可按接口组而非单一接口匹配；4.2（2008.11）扩展 anchors 与 tables 语法；openbsd.duckdb 显示 2005-2010 年间 pf 相关 commit 以 claudio@（198 条）与 henning@（169 条）为主，原大纲称 “Henning Brauer（亨宁·布劳尔）、Reyk Flöter、Daniel Hartmeier（丹尼尔·哈特迈尔） 等是主要贡献者”——Daniel Hartmeier 是 pf 的原始作者（2001 年首次引入），但 4.x 时期的主要维护者是 claudio@ 与 henning@

**史料**：openbsd.duckdb openbsd-src 仓库 commit a60c9213a0df（2005-05-22 henning “allow pf to match on interface groups”）；OpenBSD 4.1-4.3 Release Notes pf 部分（<https://www.openbsd.org/41.html>、<https://www.openbsd.org/42.html、https://www.openbsd.org/43.html）；openbsd.duckdb> openbsd-src 仓库 2005-2010 pf 相关 commit 贡献者统计（claudio 198、henning 169、mcbride 52） ［A］

**史观**：总纲第 17 条——软件工程：pf 语法作为接口契约的演进——interface groups 匹配让 pf 规则从 “按接口名硬编码” 升级为 “按接口组抽象”，这一变更将运维需求（多接口环境下的规则复用）转化为语法特性，是软件工程中 “抽象层次提升” 在防火墙配置语言层的实践

**辨析**：pf 语法在不同 OpenBSD 版本中的具体变化以 **pf.conf(5)** 手册页历次版本与 Release Notes 交叉为准——Release Notes 记录用户可见的语法变更（如 interface groups），**pf.conf(5)** 手册页记录完整语法规范；anchors 与 tables 的语义差异以 **pf.conf(5)** 手册页为准——anchors 是命名规则块可动态替换，tables 是命名地址集合可动态更新，二者用途不同

**文献**：openbsd.duckdb openbsd-src 仓库 commit a60c9213a0df；OpenBSD 4.1-4.3 Release Notes [EB/OL]. <https://www.openbsd.org/41.html>；OpenBSD **pf.conf(5)** 手册页 [EB/OL]. <https://man.openbsd.org/pf.conf.5> ［A］

## 191.1.3 与 FreeBSD malloc/Linux SLAB 的比较

**要点**：FreeBSD 使用 phk malloc（Poul-Henning Kamp 1995 年设计），Linux 使用 SLAB/SLUB 分配器；OpenBSD malloc 强调安全（guard page、随机化、free 后填充），FreeBSD phk malloc 强调性能与 per-CPU 缓存，Linux SLAB/SLUB 强调多核扩展性与内存回收效率；三者设计哲学反映各自社区优先级——OpenBSD 安全优先、FreeBSD 性能优先、Linux 扩展性优先

  **三大 malloc 实现对比**：

  | 项目 | 设计者 | 设计优先级 | 关键特性 | 性能开销 |
  | --- | --- | --- | --- | --- |
  | OpenBSD malloc | tedu@（2006 替代） | 安全优先 | guard page、随机化、free 后填充 | 约 5-10% |
  | FreeBSD phk malloc | Poul-Henning Kamp（1995） | 性能优先 | per-CPU 缓存 | 接近原生 |
  | Linux SLAB/SLUB | Jeff Bonwick（杰夫·邦威克） 等 | 扩展性优先 | 多核扩展、内存回收 | 接近原生 |

**史料**：phk malloc 论文（Poul-Henning Kamp, “You're Doing It Wrong”, 2010, ACM Queue）；Linux SLAB/SLUB 文档（<https://www.kernel.org/doc/html/latest/mm/slab.html>）；OpenBSD malloc 文档（<https://man.openbsd.org/malloc.3>）；openbsd.duckdb openbsd-src 仓库 tedu@ malloc 相关 commit ［A］

**史观**：总纲第 7 条——技术选择即政治选择：三个项目 malloc 设计反映各自政治选择——OpenBSD 以 “安全为不可妥协之预设” 选择 guard page 与随机化（性能开销为代价），FreeBSD 以 “性能为部署之基” 选择 per-CPU 缓存（安全特性为可选），Linux 以 “扩展性为规模化之钥” 选择 SLAB/SLUB（安全特性由 SELinux 等外部机制承担）

**辨析**：三者性能对比以同硬件同负载的 SPECint 等基准测试为准——OpenBSD malloc 的 guard page 与随机化带来约 5-10% 性能开销（OpenBSD 邮件列表讨论估算，无同行评审基准），FreeBSD phk malloc 与 Linux SLUB 性能接近；安全特性的防御效果以 CVE 历史与漏洞利用研究为准——OpenBSD malloc 的 guard page 可检测部分堆溢出，但对堆内 off-by-one 溢出无防御效果

**文献**：Poul-Henning Kamp. You're Doing It Wrong [J]. ACM Queue, 2010；Linux SLAB/SLUB 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/mm/slab.html>；OpenBSD **malloc(3)** 手册页 [EB/OL]. <https://man.openbsd.org/malloc.3> ［A］

- 受访者自述 hoststated（Host State Demon）源于一个快速的临时实现：OpenBSD 当时没有任何监控主机状态并把存活主机放入 PF 表的工具，他写了一个执行 TCP 连接检查、将存活主机置于 PF 表中、使重定向规则永不指向宕机主机的程序。与 round-robin DNS 相比，DNS 负载均衡无从得知主机死活、依赖客户端自行切换到下一主机（多数浏览器会如此、并非全部）；hoststated 则借 PF 的三层目的地址重写对客户端完全透明。典型部署为服务器池置于负载均衡器之后，DNS 将连接指向均衡器，PF 以 RDR 规则把连接分发到池内机器。（BSDTalk EP97，[62.86-198.28]，L1）
- hoststated 实为围绕 PF 的包装器，以非阻塞方式检查主机响应是否足够快；他仿照 OSPFD 实现了配套的 hoststated ctl，管理员可借此查看在线主机、并在维护或升级时禁用某台。检查方法包括 ICMP（对 IPv6 主机用 ping6）、TCP 连接检查、HTTP 检查（校验指定 URL 的返回码与页面内容的 SHA1 摘要），以及通用的 send/expect 方法——向连接发送一段数据并期待特定回应（如 SMTP banner 可只期待不发送），初以正则实现后改用 fnmatch；SSL 代码可用，所有 TCP 类检查方法均可包裹于 SSL。（BSDTalk EP97，[198.28-365.8]，L1）
- 关于演进方向：按服务器负载加权的均衡是计划中的目标——但加权所需的代码在内核中与 PF 绑定，须在 PF 侧实现方可让某些主机被查询得更少；团队的长期目标是功能完整的负载均衡器。初始可用版本的目标已然达成，他希望 hoststated 能赶在 4.1 之前链入 build（否则将于 4.1 打标签后的早期 snapshot 提供）。测试环境为笔记本电脑加上家与单位各一组负载均衡测试机器，另有一台由他自管、带真实均衡器与专用主机的准生产部署用于大改动验证，并尽量实现每种场景以测试回归。（BSDTalk EP97，[365.8-498.68]，L1）
- 受访者澄清负载均衡的一个常见误解：PF 式的基本负载均衡只重写目的地址、不重写源地址，因此 Web 服务器日志中记录的是真实的客户端信息，站点统计仍然准确；只有当均衡器与 Web 主机不在同一网段时才须同时重写源地址——此场景下若无七层负载均衡介入则丢失客户端信息（服务器只见来自均衡器的连接），做七层时通常附加 X-Forwarded 头。多数部署不采用该场景，源地址得以保留。（BSDTalk EP97，[517.96-600.4]，L1）
- 与 CARP 冗余防火墙的配合及可移植性：两台防火墙各自运行 hoststated、分别维护 PF 表，CARP 切换时备份机上的表处于良好状态；代价是须在 CARP 设备与底层接口上共预留三个 IP、双机都要运行，略显过度。hoststated ctl 暂只支持本地连接。依赖方面只要操作系统支持 PF 与 C 库即可——有人尝试在 FreeBSD 上编译且据称顺利（需要 3.5 之后版本的 PF ioctl 及 strlcpy 等函数），虽此后未再收到回音，据他所见可以运行。（BSDTalk EP97，[600.4-716.24]，L1）

- 总纲10 动手者创造历史：hoststated 的进入路径是运维痛点驱动的个体劳动案例：作者在工作中对既有工具不满，以复用 OSPFD 代码与设计范式的方式为自身需求造轮，先以 port 交付、再经核心开发者因共同需要而接洽，最终获得 commit 权限并链入官方 build。工具的正规化不是自上而下规划的结果，而是动手者的局部方案被社区需求放大的过程。（BSDTalk EP97，[804.24-895.88]，L1）
