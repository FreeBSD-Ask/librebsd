# 191.2 pf 防火墙的持续演进（2005-2012）——pf 从 4.0 到 5.2 持续改进，引入 synproxy、state tracking、ALTQ（队列调度）、CARP（冗余协议）等特性


## 190.2.1 synproxy 与 state tracking 的设计
  - 要点：pf 引入 synproxy 状态以防御 SYN flood 攻击，代理 TCP 三次握手——synproxy 让 pf 在客户端与服务器之间插入代理，仅当三次握手完成才向服务器转发连接请求；state tracking 机制跟踪连接状态，自动关闭空闲连接；synproxy 与 Linux SYN cookies 设计思路不同——SYN cookies 在服务器端无状态地编码连接状态至 SYN-ACK 序列号，synproxy 在防火墙端有状态地代理握手，前者节省服务器资源但牺牲 TCP 语义完整性，后者保留 TCP 语义但需防火墙维护状态
  - 史料：OpenBSD **pf.conf(5)** 手册页 synproxy state 部分（<https://man.openbsd.org/pf.conf.5>）；OpenBSD CVS commit log 中 synproxy 相关 commit；Linux SYN cookies 文档（<https://www.kernel.org/doc/html/latest/networking/syncookies.html>） ［A］
  - 史观：总纲第 17 条——软件工程：synproxy 作为状态机代理改变 pf 的 DoS 防御能力——synproxy 将防火墙从 “无状态包过滤” 升级为 “有状态握手代理”，这一设计将 DoS 防御从服务器端（SYN cookies）转移至网络边界（pf synproxy），是软件工程中 “职责分离” 在网络安全层的实践
  - 辨析：synproxy 与 Linux SYN cookies 的具体差异以 **pf.conf(5)** 手册页与 Linux 文档对比为准——synproxy 是 pf 的可选状态模式（`set state defaults synproxy`），SYN cookies 是 Linux 内核的 sysctl 开关（`net.ipv4.tcp_syncookies`）；state tracking 的状态机以 **pf.conf(5)** 手册页 "Stateful Filtering" 部分为准——pf 维护 TCP/UDP/ICMP 的连接状态表，默认空闲超时由协议决定
  - 文献：OpenBSD **pf.conf(5)** 手册页 [EB/OL]. <https://man.openbsd.org/pf.conf.5>；Linux SYN cookies 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/networking/syncookies.html> ［A］
## 190.2.2 ALTQ 队列调度的工程效应
  - 要点：ALTQ（Alternate Queuing）是 OpenBSD 集成至 pf 的流量整形框架，由 Kenjiro Cho（kjc@）等在 1990 年代末设计；ALTQ 支持 CBQ、HFSC、PRIQ 等队列调度算法；bsd_commits.db 显示 kjc@ 在 openbsd-src 仓库 2002-05-31 commit 0b32f0e6892eb "define ALTQ_NOPCC if i386 and ! I586_CPU and ! I686_CPU" 反映 ALTQ 在 4.x 周期前的早期维护；ALTQ 让 pf 在企业网络流量管理领域获得部署
  - 史料：bsd_commits.db openbsd-src 仓库 commit 0b32f0e6892eb（2002-05-31 kjc "define ALTQ_NOPCC"）；ALTQ 项目文档（<http://altq.sourceforge.net/>）；Kenjiro Cho 论文（Kenjiro Cho, "A Framework for Alternate Queueing: Towards Traffic Management Beyond PFIFO", 1999, INQIE）；OpenBSD 4.x Release Notes ALTQ 部分 ［B］
  - 史观：总纲第 10 条——边缘者贡献：Cho 作为日本裔研究者在 1990 年代末设计的 ALTQ 框架，后续被 OpenBSD 集成为 pf 的流量整形子系统——这一路径是 “学术研究 → 开源集成” 的典型，ALTQ 从研究原型（Cho 在东京大学的博士工作）演变为生产系统组件
  - 辨析：ALTQ 与 Linux tc（traffic control）的设计差异——ALTQ 集成于 pf 规则语言，配置与防火墙规则统一；Linux tc 独立于 netfilter，配置需单独的 tc 命令，二者抽象层次不同；ALTQ 在企业部署的实际规模无权威统计 [考据完成：2026-07-28 ALTQ 部署规模无单一权威统计，企业网络设备厂商的采用数据不公开]
  - 文献：ALTQ 项目文档 [EB/OL]. <http://altq.sourceforge.net/>；Kenjiro Cho. A Framework for Alternate Queueing [R]. 1999；bsd_commits.db openbsd-src 仓库 commit 0b32f0e6892eb ［B］
## 190.2.3 CARP 冗余协议的开发
  - 要点：CARP（Common Address Redundancy Protocol）由 OpenBSD 开发作为 VRRP（Virtual Router Redundancy Protocol，RFC 3768）的替代，因 VRRP 涉及 Cisco 持有的美国专利 US 5,473,599（1995 年申请，2005 年到期）；CARP 由 Reyk Flöter（reyk@）等设计，bsd_commits.db 显示 reyk@ 在 openbsd-src 仓库 2005-01-03 至 2010-12-22 共 1004 条 commit；CARP 随 OpenBSD 3.5（2004.5）发布——bsd_commits.db 中 2004-03-28 millert commit `2897e1ed6a948` "Revise for OpenBSD 3.5" 提及 3.5 release 上下文；CARP 让 OpenBSD 在高可用性网络部署中获得存在感

  **CARP 与 VRRP 对照**：

  | 维度 | VRRP | CARP |
  | --- | --- | --- |
  | 协议规范 | RFC 3768 | OpenBSD 自研 |
  | 专利状态 | Cisco US 5,473,599（1995 申请，2005 到期） | 无专利负担 |
  | OpenBSD 引入版本 | 未引入（专利期内） | 3.5（2004.5） |
  | 兼容性 | — | 不兼容 VRRP（协议头不同） |
  | 功能等价 | 是 | 是 |

  - 史料：bsd_commits.db openbsd-src 仓库 reyk@ 2005-2010 commit 统计（1004 条）；commit 2897e1ed6a948（2004-03-28 millert "Revise for OpenBSD 3.5"）；CARP 设计文档（<https://www.openbsd.org/faq/pf/carp.html>）；VRRP 专利 US 5,473,599（USPTO）；RFC 3768 VRRP ［A］
  - 史观：总纲第 12 条——法律结构：VRRP 专利作为法律结构障碍催生 CARP fork——Cisco 持有的 US 5,473,599 专利使 OpenBSD 无法自由实现 VRRP，OpenBSD 选择重新设计协议（CARP）而非寻求专利授权，这一选择是法律结构（专利制度）对技术实现（协议设计）的直接塑造
  - 辨析：VRRP 专利 US 5,473,599 的具体范围以 USPTO 专利文本为准——该专利于 1995 年 6 月申请，2005 年 6 月到期，覆盖 “虚拟路由器冗余协议” 的核心机制；CARP 与 VRRP 的兼容性以协议规范对比为准——CARP 不兼容 VRRP（协议头不同），但功能等价；Cisco 在专利到期后（2005 年后）未公开追究 CARP 实现
  - 文献：CARP 设计文档 [EB/OL]. <https://www.openbsd.org/faq/pf/carp.html>；USPTO 专利 US 5,473,599；RFC 3768 VRRP；bsd_commits.db openbsd-src 仓库 reyk@ commit ［A］
