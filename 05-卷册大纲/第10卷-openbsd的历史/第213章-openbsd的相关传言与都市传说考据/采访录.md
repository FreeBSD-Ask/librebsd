## 第 95 章 不同时期人员的采访录

> 本子节为第 95 章“OpenBSD 与同时期操作系统的比较”的配套采访录，覆盖 OpenBSD 与 Linux、FreeBSD、NetBSD 比较时期 2 位关键人员的公开陈述与学术产出。所有来源均经联网核实；考据过程另见 `原材料/研究/考据记录/` 下对应文件。编纂格式遵 `script/采访录编纂规范.md`。

### OpenBSD 比较视角的阐述者（1995-2026 时期当事人）

#### 采访 1：Theo de Raadt（西奥·德·若特）

**字段 1 采访元数据**

- 受访者：Theo de Raadt，时任 OpenBSD 项目创始人
- 采访者：无（OpenBSD 官方文档、邮件列表与 release song commentary 公开陈述）
- 采访时间：1995-2026（项目全程持续产出）
- 采访形式：官方文档 + 邮件列表公开陈述 + release song commentary
- 原始来源：OpenBSD Project. OpenBSD Goals [EB/OL]. [2026-07-23]. **<https://www.openbsd.org/goals.html**>；OpenBSD security page** <https://www.openbsd.org/security.html**>；OpenBSD lyrics archive **<https://www.openbsd.org/lyrics.html**>；<misc@openbsd.org> 与 <tech@openbsd.org> 邮件列表存档
- 存档信息：原始 URL 经联网核实可访问，未失效

**字段 2 采访摘要**

de Raadt 在 OpenBSD 官方文档、邮件列表与 release song commentary 中持续阐述 OpenBSD 与 Linux、FreeBSD、NetBSD 的比较立场。OpenBSD 的差异化定位为“安全至上”与“代码正确性优先”，与 Linux 的“功能至上”与 FreeBSD 的“性能至上”形成对照。de Raadt 对 Linux 内核代码质量的批评、对 FreeBSD 安全模型的评论、对 NetBSD 可移植性的回应，构成 OpenBSD 阵营对同时期操作系统的比较叙事。

**字段 3 考据脚注**

本则采访基于 de Raadt 在 OpenBSD 官方文档、邮件列表与 release song commentary 中的公开陈述。de Raadt 对其他操作系统的批评属 OpenBSD 阵营单方陈述，已作自利偏差审查：对 Linux 内核代码质量的批评须经 Linux 内核社区（如 LKML）的回应交叉验证；对 FreeBSD 安全模型的评论须经 FreeBSD 安全团队的回应交叉验证；对 NetBSD 可移植性的回应须经 NetBSD Core Team 的陈述交叉验证。release song commentary 中对其他操作系统的嘲讽性表述属非正式风格，须与技术性比较文档区分。完整考据过程见 [20260724_theo-deraadt-openbsd-cultural-gene.md](../../../原材料/研究/考据记录/20260724_theo-deraadt-openbsd-cultural-gene.md)。

**字段 4 与本章节内容的关联**

- 为子节 95.1（OpenBSD vs Linux 的安全哲学比较）提供 OpenBSD 阵营对 Linux 安全模型的批评视角
- 为子节 95.2（OpenBSD vs FreeBSD 的工程哲学比较）提供“安全至上”与“性能至上”的对照
- 为子节 95.3（OpenBSD vs NetBSD 的设计哲学比较）提供“安全至上”与“可移植至上”的分化叙事

**字段 5 史观映射**

- 总纲 23“历史叙事与虚构”——据第 23 章 23.1 节“一切历史写作都是基于某种哲学设定的历史小说”，23.2 节“史家以为自己在书写历史，但历史人物可能正在藉着史家书写他们自己的故事”，OpenBSD、Linux、FreeBSD、NetBSD 的不同技术选择背后是不同社区的哲学设定与利益分配。de Raadt 对其他操作系统的批评属 OpenBSD 阵营单方陈述，不是“客观历史”，而是当事人借助史家书写自己故事的体现，须与 Linux、FreeBSD、NetBSD 阵营陈述互参。
- 总纲 27“自反”——据第 27 章 27.2 节“真正的理论体系应该是自反的”，27.2 节进一步指出“任何理论本身的发展，最后都会变成八股文，变成最反动的，因为他没有勇气否定自己”，de Raadt 对 Linux 内核代码质量的批评、对 FreeBSD 安全模型的评论、对 NetBSD 可移植性的回应，皆须经自反性审视。比较叙事本身蕴含立场偏差，须通过多源交叉验证予以校准，而非视为客观真理。
- 总纲 18“时间哲学”——据第 18 章 18.2 节“只有在花落下，发霉的时候才能发现花是美的”，release song commentary 中对其他操作系统的嘲讽性表述属非正式风格的叙事选择，须与技术性比较文档区分。18 章史学含义指出“BSD 史不应以一种‘事后诸葛亮’式的现时视角来书写”——嘲讽性表述本身蕴含特定时刻的立场，须尊重历史本身的时间性，而非以现时视角予以简单评判。

#### 采访 2：Bob Beck

**字段 1 采访元数据**

- 受访者：Bob Beck，时任 OpenBSD 核心开发者，LibreSSL 发起人
- 采访者：无（BSDCan/EuroBSDcon 会议演讲）
- 采访时间：2014-2026（LibreSSL 与 pledge 时期持续产出）
- 采访形式：会议演讲
- 原始来源：Beck B. 多次 BSDCan/EuroBSDcon 演讲。OpenBSD events 页面 **<https://www.openbsd.org/events.html>** 收录。代表性演讲包括 BSDCan 2014 LibreSSL、BSDCan 2018 pledge、EuroBSDcon 2018 unveil
- 存档信息：OpenBSD events 页面经联网核实可访问

**字段 2 采访摘要**

Beck 的会议演讲从工程实践视角阐述 OpenBSD 安全哲学与同时期操作系统的比较。在 LibreSSL 演讲中，Beck 将 OpenBSD 的“安全审计优先”工程流程与 OpenSSL 的“功能优先”开发模式对比，解释 Heartbleed 漏洞的深层原因。在 pledge/unveil 演讲中，Beck 将 OpenBSD 的“声明式权限放弃”与 Linux 的 seccomp/BPF 过滤器、FreeBSD 的 Capsicum 能力模型对比，讨论各机制在易用性与安全性的权衡。

**字段 3 考据脚注**

本则采访基于 Beck 在 BSDCan/EuroBSDcon 的会议演讲。Beck 对其他操作系统安全机制的比较属 OpenBSD 阵营单方陈述，已作自利偏差审查：pledge 与 seccomp/Capsicum 的机制比较须经独立安全研究验证；LibreSSL 与 OpenSSL 的安全性比较须经独立安全审计验证。BSDCan 2014、BSDCan 2018、EuroBSDcon 2018 演讲经 OpenBSD events 页面核实可访问。完整考据过程见 [20260724_bob-beck-openbsd-security-response.md](../../../原材料/研究/考据记录/20260724_bob-beck-openbsd-security-response.md)。

**字段 4 与本章节内容的关联**

- 为子节 95.4（安全机制的技术比较）提供 pledge 与 seccomp/Capsicum 的机制比较
- 为子节 95.5（开发模式的比较）提供 OpenBSD“审计优先”与 OpenSSL“功能优先”的对比
- 为子节 95.6（易用性与安全性的权衡）提供各安全机制在易用性维度的工程评估

**字段 5 史观映射**

- 总纲 22“知识的过时”——据第 22 章 22.1 节“如今翻开当年的甲种本、乙种本，甚至在你正学习的那一刻，知识便已过时”，Beck 从工程实践视角阐述 OpenBSD 安全哲学与同时期操作系统的比较，回应了安全知识的累积性过时。22.2 节指出“技术债务是历史设计的代价”——OpenSSL 的“功能优先”开发模式即是历史设计代价，Beck 的“审计优先”比较视角是对这一代价的回应。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“分离聚合是世界发展的规律。分久必合，合久必分”，pledge 的“声明式权限放弃”与 seccomp/BPF 过滤器、Capsicum 能力模型的不同设计，是分离聚合规律在安全机制架构中的具体呈现。但须区分：不同机制对权限分离的不同聚合方式，是辩证动态而非静态结构——pledge 通过声明聚合，seccomp 通过过滤聚合，Capsicum 通过能力聚合。
- 总纲 27“自反”——据第 27 章 27.2 节“真正的理论体系应该是自反的”，Beck 对其他操作系统安全机制的比较属 OpenBSD 阵营单方陈述，须经自反性审视。27.2 节指出“反对形式主义很难，必须走个形式，而反对之要点就是用形式反对形式主义”——pledge 与 seccomp/Capsicum 的机制比较须经独立安全研究验证，不信任任何单方的声称，包括 OpenBSD 阵营自身的声称。
