# 207.1 项目统摄史观审视：从总纲第 15、19、21 条看 OpenSSH 的辩证链

**要点**：本节以项目史观总纲第 15、19、21 条为框架，审视第 92 章 92.7-92.10 节的 OpenSSH 四层辩证；核心结论有三：OpenBSD 审计文化在 fork 过程中被物化为非可移植代码移除、SSH 1.3→1.5 协议替换、核心/portable 分离等具体工程决策；各方前理解（审计文化、工程分工、市场覆盖）的不可通约使批评与反批评的分歧不可避免；OpenSSH fork 的革命路线与商业厂商渐进改良的改革路线在 1999-2017 年间各自呈现，最终随 OpenSSH 成为事实标准而达成和解——逐条映射论述见史观字段，考据留痕见辨析字段

**史料**：项目史观总纲第 15、19、21 条（**02-sacred源材料/01-一刻哲学**，总纲原文已入库 sacred_sources.duckdb）；OpenSSH 项目历史页面（<https://www.openssh.com/history.html>）；第 92 章 92.7-92.10 节引用的全部史料；openbsd.duckdb openbsd-src 仓库 commit 84959968510b（1999-09-26 deraadt 初始导入）至 commit 6c99a5ed578d（2017-04-30 djm 完全删除 SSH1）间的演进记录〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 15 条——文化即形式主义：OpenBSD 审计文化作为社区传统，在 OpenSSH fork 过程中被形式主义化为具体的工程决策（移除非可移植代码、协议替换、核心/portable 分离），文化在形式主义化过程中被遮蔽为“工程必要”——de Raadt 的“简化源码便于安全审计”叙事本身即是文化形式主义化的产物，文化（审计传统）被重构为工程（代码可读性）的话语；总纲第 19 条——解释学循环是历史认识的根本条件：四层辩证中的每一方都站在自身前理解中——OpenBSD 阵营以“审计文化”为前理解，portable 维护者以“工程分工”为前理解，商业 SSH 厂商以“市场覆盖”为前理解，三类前理解的差异使分歧不可避免，权力与知识在历史书写中共谋（OpenSSH 官方历史页面由 OpenBSD 团队书写，自然倾向于审计文化叙事）；总纲第 21 条——革命与改革是历史方法论的分歧：OpenSSH fork 是革命路线（一次性移除非可移植代码、协议重构、portable 架构新建），SSH Communications Security 的渐进改良是改革路线（保留商业许可证、逐步收紧功能），改革的困难远高于革命——OpenSSH 7.6（2017-10）完全删除 SSH1 是革命的延续（一次性切断遗留协议），而商业 SSH 厂商让遗留用户接受新协议的改革工作则持续近二十年仍未完全完成；破山中贼易（删除代码）与破心中贼难（改变用户习惯）的张力贯穿 OpenSSH 全部演进

**辨析**：考据过程留痕——【查证来源】项目统摄史观审视的史料基础经以下核验：项目史观总纲第 15 条（“文化即形式主义”）、第 19 条（“解释学循环是历史认识的根本条件”）、第 21 条（“革命与改革是历史方法论的分歧”）原文经本书原材料核验（**02-sacred源材料/01-一刻哲学**，sacred_sources.duckdb，2026-07-23 Read 工具一手核验，三条总纲均载于“二十五、总纲”节，分别为第 15、19、21 条）；OpenSSH 历史事实经第 92 章 92.7-92.10 节已核验的一手史料（OpenSSH 官方历史页面 <https://www.openssh.com/history.html> WebFetch 一手核验、openbsd.duckdb openbsd-src 仓库 commits 表 SQL 查询验证）

【交叉验证方法】项目史观总纲原文（哲学层一手史料）与 OpenSSH 历史事实（工程层一手史料）双向映射——总纲第 15 条“文化即形式主义。传统在形式主义化过程中被遮蔽与重构”映射至 OpenBSD 审计文化在 fork 过程中被物化为“移除非可移植代码”“SSH 1.3→1.5 协议替换”“核心/portable 分离”等具体工程决策，文化（审计传统）被重构为工程（代码可读性）话语，映射关系经第 92 章 92.7-92.8 节已核验的 OpenSSH 官方历史页面原文（"the goal being simpler source code, so that security holes and other issues could be spotted easier"）证实；总纲第 19 条“前理解的差异使分歧不可避免。权力与知识在历史书写中共谋”映射至四层辩证中各方前理解的不可通约性，经第 92 章 92.7-92.10 节辩证链本身证实——OpenBSD 阵营以“审计文化优先”为前理解，portable 维护者以“工程分工公平”为前理解，商业 SSH 厂商以“市场覆盖”为前理解，三类前理解的差异使第 92 章 92.9 节再批评不可避免；总纲第 21 条“Linux 靠革命，BSD 靠改革。改革的困难远高于革命。破山中贼易，破心中贼难”映射至 OpenSSH fork（革命路线，一次性移除非可移植代码）与 SSH Communications Security 渐进改良（改革路线，保留商业许可证逐步收紧）的方法论分歧，经第 92 章 92.7 节已核验的 fork 路径（SSH 1.2.12 → OSSH → OpenSSH）与第 92 章 92.10 节已核验的 SSH1 完全移除时间线（commit `6c99a5ed578d`，2017-04-30）互证——“破山中贼易”对应删除代码（1999-09-26 至 2017-10-03 间多次移除），“破心中贼难”对应改变用户习惯（商业 SSH 用户接受 BSD 许可证开源实现的改革工作持续近二十年）

【存疑判定依据】0 信任原则与自反原则（总纲第 7 条——理论必须自反）叠加提示：本审视以“文化即形式主义”等总纲条目为前理解，本身即是形式主义化的非存在，不宣称呈现历史本身；总纲第 19 条的“权力与知识共谋”在本审视中亦有显现——选择总纲第 15、19、21 条（而非其他条目）切入本身即是史家的形式主义选择，本可选取第 8 条（本体论上各方平等）或第 25 条（0 信任原则）切入，不同选择将呈现不同的 OpenSSH 历史；总纲第 21 条的“革命 vs 改革”框架应用于 OpenSSH 时须警惕二元化简化——OpenSSH fork 既含革命成分（移除非可移植代码、协议重构）又含改革成分（保留 SSH 1.3 支持、portable 渐进成熟），二者并非完全对立而是同一过程的不同侧面；［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
