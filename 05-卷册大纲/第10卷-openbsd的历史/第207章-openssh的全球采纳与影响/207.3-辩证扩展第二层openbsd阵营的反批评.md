# 207.3 辩证扩展第二层：OpenBSD 阵营的反批评

**要点**：OpenBSD 阵营对 92.12 节三类批评的反驳可归纳为三点；第一，Provos 赴加拿大移除加密与 GPL 组件不是“为许可证纯洁化牺牲功能完整性”而是修复既有的许可证违规——OpenSSH 官方历史页面明确记载 SSH 1.2.12 内置的 libgmp 在 1999 年为 GPL 许可证（原文"versions of that era were under the regular GNU Public License“），而 SSH 1.2.12 后续版本带有商业限制性许可证却仍包含 libgmp，”that effectively made SSH a GPL violation"（这实际上使 SSH 成为 GPL 违规），Provos 移除 libgmp 是消除既有的许可证违规而非引入新风险，OpenSSL 的 libcrypto 替代在长期被证明是正确的选择——OpenSSL 后续成为全球加密事实标准；第二，Friedl 替换 SSH 1.3 为 1.5 不存在“纯洁性叙事的内在矛盾”——OpenSSH 的“纯洁化”指许可证纯洁化（移除 GPL 与专利组件），不指协议纯洁化，Friedl 保留 SSH 1.3 支持同时增加 1.5 支持是“兼容性扩展”而非“纯洁化让步”，且“兼容 Windows 客户端”是工程实用性考量而非商业利益考量，OpenBSD 团队从未以“协议纯洁性”为叙事核心；第三，Beck 处理 Makefile 避免 RSA 专利不是“法律风险向用户转嫁”而是美国专利法约束下的唯一合法路径——OpenBSD 2.6 发布时（1999-12-01）RSA 专利仍未过期（2000-09-20 方过期），OpenBSD 团队不能合法地在 CD 中包含 RSA 算法，FTP/HTTP 替换机制是当时的标准做法（FreeBSD 4.0 同期亦采用 RSAREF 检测机制处理 RSA 专利约束），且官方历史页面明确记载“Luckily this kind of hackery is no longer needed”表明 OpenBSD 团队将这一机制视为临时应急而非长期方案

**史料**：OpenSSH 项目历史页面（<https://www.openssh.com/history.html>，明确记载 libgmp 在 1999 年为 GPL 许可证、SSH 1.2.12 后续版本的 GPL 违规、Friedl 保留 SSH 1.3 支持的决策、Beck 处理 Makefile 的法律约束与临时性质）；OpenSSH LICENCE 文件（<https://cvsweb.openbsd.org/src/usr.bin/ssh/LICENCE>，记载 libgmp 移除后的许可证组合）；OpenBSD 2.6 Release Notes（<https://www.openbsd.org/26.html>，记载 RSA 专利约束下的发布策略）；FreeBSD 4.0 Release Notes（<https://www.freebsd.org/releases/4.0R/announce.html>，对照 FreeBSD 同期的 RSAREF 处理机制）；OpenBSD misc@ 邮件列表存档 1999-2000（<https://marc.info/?laccopenbsd-misc>，记载 de Raadt、Provos 等对批评的回应）

**史观**：总纲第 13 条——法律与道德是利益分配：OpenBSD 阵营的反批评揭示三项纯洁化工作的法律驱动本质——Provos 移除 libgmp 是修复 GPL 违规的法律必要，Beck 处理 Makefile 是遵守美国专利法的法律必要，“纯洁化”叙事本身是法律结构驱动的工程决策在话语层面的合理化；社区文化即技术资产：OpenBSD 阵营的反批评揭示审计文化作为社区资产的具体运作方式——许可证审计（识别 libgmp 的 GPL 违规）是代码审计的延伸，审计文化不仅覆盖安全漏洞亦覆盖许可证合规；0 信任原则：Provos 移除 libgmp 是 0 信任原则在许可证层面的实践——libgmp 的 GPL 约束被视为不可信，无论其功能多关键都须移除

**辨析**：考据过程留痕——【查证来源】OpenBSD 阵营反批评的三点论据经以下一手史料核验：第一点（Provos 移除 libgmp 是修复既有 GPL 违规），经 OpenSSH 官方历史页面（<https://www.openssh.com/history.html>，2026-07-24 WebFetch 一手核验）确认原文"Rapidly after Tatu's 1.2.12 release, newer versions bore successively more restrictive licenses, even though libgmp was still included and necessary for using the software. That effectively made SSH a GPL violation"，证实 SSH 1.2.12 后续版本因包含 libgmp 而构成 GPL 违规，Provos 移除 libgmp 是修复这一违规；第二点（Friedl 保留 SSH 1.3 支持是兼容性扩展非纯洁化让步），经同一页面确认原文"He added SSH 1.5 protocol support in such a way that SSH 1.3 protocol support remained operational“，且 OpenSSH 的“纯洁化”叙事在历史页面中明确指向”freeing SSH, cleaning up the license mess"（许可证清理）而非协议纯洁化，“纯洁性叙事的内在矛盾”批评基于对“纯洁化”范围的扩大化解读；第三点（Beck 处理 Makefile 是法律约束下的唯一合法路径），经同一页面确认"Because OpenBSD 2.6 was shipping before the RSA patent expiration date, we needed to ship our CD with libssl and libcrypto shared libraries which lacked RSA“，且”Luckily this kind of hackery is no longer needed"表明临时性质，经 FreeBSD 4.0 Release Notes（<https://www.freebsd.org/releases/4.0R/announce.html>，2026-07-23 WebFetch 一手核验）确认 FreeBSD 4.0（2000-03-14）同期亦采用 RSAREF 检测机制处理 RSA 专利约束（freebsd.duckdb freebsd-src 仓库 commit `636e8b707b47`，2000-03-13 Kris Kennaway MFC RSAREF 检测至 4-STABLE），证实 RSA 专利约束是当时全行业共同面临的法律结构而非 OpenBSD 单独决策；【交叉验证方法】OpenSSH 官方历史页面（一手，OpenBSD 团队自述）与 FreeBSD 4.0 Release Notes（一手，FreeBSD 团队发布）双向互证——两者均记载 RSA 专利约束下的特殊处理机制，证实 Beck 的 Makefile 处理是行业通行做法而非 OpenBSD 独创；OpenSSH LICENCE 文件（一手，代码级许可证声明）与历史页面记载的 libgmp 移除在内容上一致；openbsd.duckdb openbsd-src 仓库 commit `84959968510b`（deraadt，1999-09-26）至 commit `bf74e864c129`（deraadt，1999-10-01）间的 commit 历史经 SQL 查询验证存在 Provos、Friedl、Beck 三人的活跃贡献记录，与历史页面记载的团队分工一致；【存疑判定依据】0 信任原则提示：OpenSSH 官方历史页面作为 OpenBSD 团队自述存在自利偏差风险——第一点（libgmp 移除是修复 GPL 违规）的论据成立，但“SSH 1.2.12 后续版本 GPL 违规”的判定基于 OpenBSD 团队单方面陈述，SSH Communications Security 是否承认其版本构成 GPL 违规须对照其原始许可证声明最终核验，［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；第二点（“纯洁化”指许可证纯洁化非协议纯洁化）的论据成立，但 OpenBSD 团队在 1999-2000 年邮件列表中是否曾以“协议纯洁性”为叙事需对照邮件原文核验——若存在则以“许可证纯洁化”为限的反批评不完整，［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；第三点（Beck 处理是法律约束下唯一合法路径）的论据成立，但“唯一合法路径”的判定需评估是否存在替代方案（如不发布 RSA 相关功能、延后发布至 RSA 专利过期后），［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
