**要点**：

- Honeynet Project 的组织形态：1999 年正式立项，2001 年于伊利诺伊州注册非营利并获联邦 501(c)3 认定，以志愿者为主的非营利安全研究组织，目标是不收公众费用提升互联网安全，路径为研究坏人工具与战术并共享全部所学；2002 年前后各国陆续成立镜像使命的分支——德国、法国、巴西、中国、新加坡、巴基斯坦等 honeynet 项目——赋予其全球互联网视角。（BSDTalk EP49，[56.56-134.08]，L1）
- 高交互 honeynet 的架构与工具链：honeynet 只是高交互 honeypot——由真实计算机与应用组成、供坏人与恶意软件入侵以观察全程的网络；部署核心是 HoneyWall 网关这一进出流量访问控制设备，约半小时可建成，配合 HoneyWall CD-ROM（基于 Fedora）将整套数据捕获与数据控制功能集成；主机侧数据捕获由内核态的 Sebek 完成、设计同时支持 SPARC 与 Intel 平台并以四条款 BSD 许可发布，分析界面 Walleye 亦出自印第安纳大学团队；部署耗时已从数日缩至约一小时，而组织的研究重心已整体转向数据分析。（BSDTalk EP49，[186.64-258.50]，L1）
- 开放悖论的自觉承担：项目全面开源、与社区共享一切，坏人因此可以下载其工具、逆向并发展反制——如同一场向对手亮出底牌的扑克；但 Spitzner 明言不愿改变，因为要开放、没有秘密，开放本身放大了创意共享与研究能力。（BSDTalk EP49，[317.02-345.34]，L1）
- 部署策略与攻击自动化的转折：过去部署默认老旧未打补丁的系统以观察入侵并捕获 botnet、IRC 命令控制信道等恶意软件，如今开始向金融部门试水更现代、加固到位的高价值 honeynet；手工攻击早在三五年前已被自动化取代——按键犯错与藏匿踪迹的时代过去，有组织者自设研发部门开发新工具，一切复归投资回报逻辑，连隐藏行踪都常属多余；而月度扫描分析挑战的停办本身即是趋势证据——四五年来入侵手法并无新意，创新全部集中于 botnet 与恶意软件的工具能力增强。（BSDTalk EP49，[355.54-393.78]，L1）
- 自身风险模型与下线原则：honeypot 唯一目的是收集信息，而坏人通常不在乎被观察——他们拥有数千台肉鸡、也不自认有被追查的风险，真正招致报复的是直接影响其收入的行为，如被分布式拒绝服务攻击打垮的反垃圾邮件公司；每个 honeynet 均配数据控制机制（出站连接计数、IPS）以缓解而非消除对外危害；在线与否的判据是学习价值——尚有新东西可学就保持在线，否则拔线，有时人与活动依旧、新的只是恶意代码样本。（BSDTalk EP49，[565.30-624.94]，L1）
- bsdtalk088（2006-12-20）为主持人单口周年回顾：节目首期播出于 2005-12-20；一年间获得社区的多方支持，包括捐赠、翻译、访谈线索与人引、长途电话、网站托管乃至代购域名；最近一期（第 87 期）下载约 2500 次，其中 mp3 约 1975 次、ogg 约 532 次，且下载量持续增长。这些数字是播客作为 BSD 传播媒介在 2006 年实际规模的直接证据。（BSDTalk EP88，[47.24-135.88]，L1）
- 主持人陈述 spamd 灰名单部署的三级扩散链：其公司约百人因运行于灰名单模式的 spamd 反垃圾守护进程而显著少受垃圾邮件困扰；他随后说服一所学校的网络管理员朋友把 spamd 置于 FirstClass 邮件协作服务器之前，效果显著，促使该管理员自发将其推广到自己的个人邮件与 Web 服务器，以及一家深受垃圾邮件之害的儿童公益组织。BSD 安全工具的扩散由此经由终端用户的口碑传递，而非官方推广。（BSDTalk EP88，[208.0-250.64]，L1）
- 主持人自述公司网站托管于 OpenBSD 的选择逻辑：因其运行 Joomla 内容管理系统而需要默认即以 chroot 运行 Apache 的系统，OpenBSD 满足此点且为其熟悉之系统；从把 BSD 当作偶尔安装的业余爱好系统，到把公司网站押于其上，他视之为对自己信心的标志。此外他还为一无所有的朋友以 300MHz 旧笔记本（128MB 内存）加装 OpenBSD 与 blackbox 窗口管理器，改装为开机即入 Firefox、关闭即关机的专用 Web 终端。（BSDTalk EP88，[139.6-205.52]，L1）
- 主持人对其节目使命的自觉陈述：此前访谈多为开发者，而终端用户故事同样重要——他援引对 Yahoo 与 Google 的访谈说明大公司愿意以 BSD 许可发布软件，又举 NVIDIA、杀毒厂商与 Opera 等投入资源使非自由软件支持 BSD 为例，主张“人们不应害怕 BSD 许可证”、商业公司愿意支持 BSD，并认为这类故事必须被讲述。（BSDTalk EP88，[384.12-422.7]，L2）
- 受访者以约 40 人软件公司 IT 经理的身份口述其 OpenBSD 环境：约 12 台 OpenBSD 服务器分别承担防火墙、VPN 网关、DNS 与 DHCP、面向 Windows 与 Mac 用户的文件服务、Web 服务以及执行反垃圾与反病毒扫描的 MTA 等角色；他自 3.7 版入场，此后每个新版本发布后不久即升级，访谈时已全面运行 OpenBSD 4.0。（BSDTalk EP90，[79.08-172.24]，L1）
- 替换史：受访者入职时公司几乎全为 Linux；他选择熟悉的 OpenBSD 并获“只要能工作可装任何系统”的授权，替换过程对终端用户完全透明——升级在下班时间完成、用户所用应用毫无变化，Linux 上能用的在 OpenBSD 上同样可用且多出新功能（如此前不存在的反垃圾与反病毒能力）。服务层的运维选择与用户桌面层解耦，是其得以透明换血的结构前提。（BSDTalk EP90，[107.68-157.04]，L1）
- 受访者讲解冗余与网络架构：两台约 1GHz、512MB 内存的普通机器以 CARP 互为防火墙冗余——既有廉价硬件加 CARP 的组合胜过购置内置冗余的高价设备；总部网络划为 LAN（用户与内部服务器）、DMZ（Web 服务器与演示机）与开发网络（快速装机服务器）三区，防火墙决定区间流量。另有两台 sparc64 专作 MTA 并以 CARP 做故障转移，曾在一次机器故障中即插即换、无缝接管。（BSDTalk EP90，[181.56-235.5]，L1）
- 邮件栈：以 Sendmail 为 MTA、利用其 libmilter 功能自研过滤口，接入 ClamAV 与 SpamAssassin，再将邮件投递给内网 Exchange——Exchange 因此不直接暴露于互联网，垃圾与病毒在入口即被滤除；另有 spamd 以黑名单模式屏蔽特定来源。灰名单因新客户首次邮件会被延迟半小时的顾虑暂未获公司批准，他设想以已知客户白名单等变通方式证明其价值。（BSDTalk EP90，[245.48-320.0]，L1）
- 升级实践：每个 release 用 OpenBSD 安装介质的 upgrade 选项进行，以 mergemaster 合并 /etc 变更；版本之间则采用 Gerardo Santana 的二进制补丁系统——编译补丁、比对受影响的二进制与文件、打包升级。他自陈许多开发者不赞成此类方案，但从运维角度合理：同一服务器上多个服务共存时，httpd 获补丁后无需停摆其他服务、只须重启受影响者。jail 的取舍遵循同样权衡——静态 HTML 站点因须把 Perl 等依赖复制进沙箱反而不再使用 jail。（BSDTalk EP90，[711.7-770.18]，L1）

**辨析**：
