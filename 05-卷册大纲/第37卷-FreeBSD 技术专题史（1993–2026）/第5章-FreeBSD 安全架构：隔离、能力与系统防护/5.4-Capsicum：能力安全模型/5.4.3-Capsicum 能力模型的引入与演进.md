# 149.2.2 Capsicum 能力模型的引入与演进

**要点**：Capsicum 能力模型由剑桥大学 罗伯特·N. M. 沃森 团队设计，核心论文发表于 USENIX Security 2010，FreeBSD 9.0-RELEASE（2012 年 1 月 12 日）首次在 GENERIC 内核中集成 Capsicum 框架（options CAPABILITIES 和 options CAPABILITY_MODE）；Pawel Jakub Dawidek 在 FreeBSD 基金会与 Google 开源计划办公室联合资助下（2013 年 4 月公告）完成了 Capsicum 从研究原型到产品级代码的工程化，开发了 **casperd(8)** 服务守护进程和 **libcapsicum(3)**/**libcasper(3)** 库；FreeBSD 基本系统中首批 Capsicum 化工具包括 **tcpdump(1)**、**dhclient(8)**、**kdump(1)**、**killall(1)**、**timeout(1)**、**dd(1)** 等；Capsicum 的核心创新是对象能力模型——进程通过 **cap_enter(2)** 进入能力模式后丧失所有全局命名空间访问权，仅能通过已持有的能力文件描述符访问资源

**史观**：技术路线分化：Capsicum 代表了 FreeBSD 在安全模型上与 Linux 的路线分化——Linux 采用 LSM 框架（SELinux/AppArmor）+ seccomp-bpf 的标签式安全策略 + 系统调用过滤方案，FreeBSD 则通过 TrustedBSD MAC（类似 LSM）+ Capsicum 对象能力模型的双层架构；Capsicum 的 “自愿进入沙箱” 设计与 jail 的 “管理员强制隔离” 形成互补——jail 从外部施加隔离边界，Capsicum 允许进程自行收缩权限边界；这一分化体现了 BSD 社区对 “安全不是一刀切” 原则的坚持

**辨析**：原大纲称 “Capsicum 在 FreeBSD 10.0 引入” 系版本号错误——经 FreeBSD 9.0 Release Notes 和 SVN 历史交叉验证，Capsicum 框架首次出现在 FreeBSD 9.0（2012 年 1 月），10.x 是 casperd 和更多 Capsicum 化工具的成熟期；数据库作者分布证据进一步精确化：Watson 首条 Capsicum commit 可追溯至 2009-09-30（早于 2010 USENIX Security 论文约 9.5 个月），Dawidek 首条 commit 为 2011-01-24（早于 FreeBSD 9.0-RELEASE 约 11.5 个月），反映 Capsicum 从学术原型到工程化到正式集成的三阶段时间线；“Capsicum 替代传统 UNIX 权限模型” 说法不准确——Capsicum 是混合模型（hybrid capability system），未进入能力模式的进程仍运行在传统 DAC 模型下，能力模式是进程可选择进入的附加约束态；参见相关章节 Capsicum 与 CHERI 部分，本节不再重复技术细节；[双库核查：2026-08-14] 本节要点“Capsicum 核心论文发表于 USENIX Security 2010”经参考文献库验证通过（检索词“Capsicum”命中 reference_id=206《Capsicum: practical capabilities for UNIX》，Watson 等，2010，作者含 Robert N.
