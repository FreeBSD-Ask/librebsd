Paolo Bonzini 在 FreeBSD Capsicum 安全框架 RFC 讨论中回应 David Drysdale：可改用按 O_RDONLY/O_WRONLY 方式打开文件来区分读写，或对每个 iocb 以合成系统调用号运行描述符的 seccomp-bpf 程序；他追问 Capsicum 能力究竟关联 file descriptor 还是 description，若是后者则是模型的重要可用性问题；认为带过滤器 fd 跨架构传递的问题与用 seccompv2 限制子进程相同，须由 libseccomp 解决；并建议把 thread id 作为 seccomp-bpf 的特殊参数以支持只许向自身发信号的约束。以上为邮件列表当事人一手自述，属过程性证据，不得单独引为定论。

在 preadv/pwritev 系统调用的补丁讨论中，Matthew Wilcox 担心 NetBSD 的市场份额约为 0%、不应让它锁死我们的决定，并问除 NetBSD 外还有谁加过这两个系统调用。Gerd Hoffmann 补充答复：FreeBSD 和 OpenBSD 也有该接口；Solaris 他只找到一个功能请求，不知道 MacOS/Darwin 的情况，并反问还有没有其他如今重要的 un*x 系统（原文："Free- and OpenBSD have it too. For Solaris I've found a feature request only. Dunno about MacOS/Darwin. Other un*xes which are important these days?"）。Jennifer Pioch 则追问那个 Solaris 功能请求的编号。即该接口在多个 BSD 发行版中已存在，而 Linux 侧的讨论焦点是是否值得为它们增补系统调用。
