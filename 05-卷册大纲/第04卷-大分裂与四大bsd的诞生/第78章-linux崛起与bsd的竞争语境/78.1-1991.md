# 77.1 1991-1996 年 Linux 崛起的时间线——关键版本与社区事件

## 77.1.1 Linux 崛起的关键版本
  - 要点：**1991-1996 年** Linux 崛起的关键版本包括 0.01（**1991.9**）、1.0（**1994.3**）、2.0（**1996.6**）——版本迭代速度快于 BSD，吸引开发者与商业资源。Linux vs BSD 早期版本时间线对照如下：

| 项目 | 版本 | 发布时间 | 备注 |
| --- | --- | --- | --- |
| Linux | 0.01 | **1991.9** | Torvalds 首次公开发布 |
| 386BSD | 0.0 | **1992.2** | Jolitz 公告，晚于 Linux 0.01 约 5 个月 |
| 386BSD | 0.1 | **1992.7** | Jolitz 释出，后续维护停顿 |
| NetBSD | 0.8 | **1993.4** | 首个公开发布版本 |
| FreeBSD | 1.0 | **1993.11.1** | FTP 发布，CD-ROM 同年 12 月 |
| Linux | 1.0 | **1994.3** | 早于 FreeBSD 2.0 约 8 个月 |
| 4.4BSD-Lite | — | **1994.6** | CSRG 最终发布 |
| FreeBSD | 2.0 | **1994.11.22** | 完成 4.4BSD-Lite 迁移后重建 |
| Linux | 2.0 | **1996.6** | 正值 BSD 阵营完成 4.4BSD-Lite 迁移后约 2 年 |

- 史料：Linux 0.01/1.0/2.0 发布声明、Linux 内核邮件列表历年存档、Torvalds 公开声明 ［A］；bsd_commits.db 查询 L7.3.1 显示：1993 年 BSD 4 大 src 仓库合计 15,375 commits、73 位贡献者，Linux kernel 仓库无数据（Linux kernel GitHub 镜像 1993 年无 commit 记录，Linux 早期开发经邮件列表与 FTP 分发未进入 git 仓库）；1994 年 BSD 4 大 src 仓库合计 21,943 commits、88 位贡献者；1995 年 BSD 4 大 src 仓库合计 20,656 commits、113 位贡献者；1996 年 BSD 4 大 src 仓库合计 29,245 commits、177 位贡献者，Linux kernel 仓库仅 1 commit、1 位贡献者（Linux kernel GitHub 镜像 1996 年仅有 1 条 commit 记录，远低于 BSD 阵营 29,245 commits）；反映 1993-1996 年 BSD 阵营虽经历 USL 诉讼与 4.4BSD-Lite 重建，commit 量与贡献者数仍持续增长，Linux kernel 仓库的早期数据缺失反映 Linux 早期开发尚未进入 git 版本控制
- 史观：总纲第 9 条——偶然性改写历史：Linux 关键版本的发布时点是 BSD 阵营法律不确定期的偶然窗口
- 辨析：版本发布时点的具体意义经 Linux 内核邮件列表（lkml.org）历年存档与 Linux 0.01/1.0/2.0 发布声明对照核实——Linux 0.01（1991.9）早于 386BSD 0.0（1992.2）约 5 个月，Linux 1.0（1994.3）早于 FreeBSD 2.0（1994.11.22）约 8 个月，Linux 2.0（1996.6）正值 BSD 阵营完成 4.4BSD-Lite 迁移后约 2 年；【0 信任原则·commit 量不等于质量】L7.3.1 的 BSD/Linux commit 量对比反映开发活跃度分布但不等于项目质量或市场份额，Linux kernel 1996 年仅 1 commit 反映 GitHub 镜像数据缺失而非 Linux 实际开发停滞，Linux 早期开发经邮件列表与 FTP 分发未进入 git 仓库；【0 信任原则·CVS-to-Git 迁移风险】BSD 4 大 src 仓库中 netbsd-src 与 openbsd-src 均为 CVS 主仓的 GitHub 镜像，CVS-to-Git 转换可能重写 author 字段或 commit_date，1993-1996 年 commit 量基线须与各项目官方档案交叉验证；【0 信任原则·GitHub 镜像滞后】Linux kernel GitHub 镜像 1993-1996 年数据缺失反映 Linux 早期开发未进入 git 仓库，L7.3.1 早期对比数据的解释须谨慎——Linux kernel 仓库的 “无数据” 不等于 Linux 实际无开发活动，BSD 仓库的 “有数据” 也不等于 BSD 开发活跃度高于 Linux；【0 信任原则·release tag 间隔不等于开发周期】L7.3.1 的 commit 量按年份聚合，release tag 间隔与实际开发周期非同一维度，须结合 release notes 与邮件列表公告交叉验证
- 文献：Linux 0.01/1.0/2.0 发布声明；Torvalds 公开声明[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]；本项目。bsd_commits.db 数据分析报告：衍生项目与跨项目对比分析 [R/OL]. 2026.
## 77.1.2 Linux 崛起的社区事件
  - 要点：Linux 崛起的社区事件包括 comp.os.linux 创建（**1991**）、Linux Journal 创刊（**1994**）、Linux 商业发行版出现（**1994-1995**）等——社区事件推动 Linux 用户基数与商业资源汇聚。Linux 崛起关键社区事件时间线如下：

| 事件 | 时间 | 影响 |
| --- | --- | --- |
| comp.os.linux 创建 | **1991** | Linux 早期用户交流平台 |
| SLS 发行版 | **1992** | 首个 Linux 商业发行版 |
| Yggdrasil 发行版 | **1992** | 早期商业发行版 |
| Linux Journal 创刊 | **1994** | Linux 媒体曝光渠道 |
| RedHat 发行版 | **1994** | 后续商业模式奠基 |
| Caldera 发行版 | **1994** | 商业化载体 |

- 史料：comp.os.linux Usenet 存档、Linux Journal 历年文章、Linux 商业发行版发布声明 ［A］
- 史观：总纲第 8 条——社区文化即技术资产：社区事件是 Linux 崛起的文化资产
- 辨析：社区事件的具体影响经 comp.os.linux Usenet 存档、Linux Journal 历年文章与 Linux 商业发行版发布声明对照核实——comp.os.linux 1991 年创建为 Linux 早期用户提供交流平台，Linux Journal 1994 年创刊为 Linux 媒体曝光提供渠道，Linux 商业发行版（SLS 1992、Yggdrasil 1992、RedHat 1994、Caldera 1994）出现为 Linux 商业化提供载体
- 文献：comp.os.linux Usenet 存档；Linux Journal 历年文章 ［A］
## 77.1.3 Linux 与 BSD 的时间线交叉
  - 要点：Linux 与 BSD 时间线交叉——**1991 年** Linux 0.01 与 386BSD 同期发布，**1993 年** Linux 1.0 与 FreeBSD 1.0/NetBSD 0.8 同期，**1994-1995 年** USL 诉讼期间 Linux 趁机扩张；交叉时点决定后续竞争力格局。1991-1996 年 Linux 与 BSD 时间线交叉节点对照如下：

| 年份 | Linux 节点 | BSD 节点 | 交叉意义 |
| --- | --- | --- | --- |
| **1991** | Linux 0.01（**1991.9**） | 386BSD 0.0（**1992.2**） | Linux 早约 5 个月 |
| **1993** | Linux 0.99 系列迭代 | FreeBSD 1.0（**1993.11.1**）、NetBSD 0.8（**1993.4**） | BSD 在 USL 诉讼期间仍发布 |
| **1994** | Linux 1.0（**1994.3**） | 4.4BSD-Lite（**1994.6**）、FreeBSD 2.0（**1994.11.22**） | Linux 早于 FreeBSD 2.0 约 8 个月 |
| **1995** | Linux 1.2 系列扩张 | OpenBSD 创建（**1995.10.18**） | OpenBSD 起步阶段规模远小于前两者 |
| **1996** | Linux 2.0（**1996.6**） | 三足鼎立格局正式形成 | Linux 正值 BSD 完成 4.4BSD-Lite 迁移后约 2 年 |

- 史料：Linux 与 BSD 项目发布历史、USL v. BSDi 诉讼时间线、Salus "A Quarter Century of UNIX" (1994)；bsd_commits.db 数据库证据（2026-07-21 复核）：FreeBSD 1.0 release tag `release/1.0.0_cvs` 标注 1993-11-01（commit_hash `8503f4f13f77abf7adc8f7e329c6f9c1d52b6a20`，tagger svn2git 迁移工具），与大纲记载 FreeBSD 1.0（1993.11）一致，早于 Linux 1.0（1994.3）约 4 个月；FreeBSD src 首条 commit 1993-06-12T14:49:13Z（Rodney W. Grimes（罗德尼·W·格赖姆斯）, "Initial import, 0.1 + pk 0.2.4-B1", commit_hash `9002c02abc587664acb357c6879d8ca08664dd0b`），NetBSD src 首条 commit 1992-07-13T16:18:24Z（srcmastr, "initial empty check-in", 仅为仓库初始化，实际 386BSD 0.1 源码导入为 cgd 1993-03-21T09:45:37Z）；FreeBSD 1993 年 868 个 commit、1994 年 4,217 个 commit，NetBSD 1993 年 14,507 个 commit、1994 年 17,726 个 commit，反映 BSD 阵营在 USL 诉讼期间（1992-1994）仍保持高强度开发 ［A］；bsd_commits.db 查询 L1.1.2 显示：1993 年 4 大 BSD src 仓库 commit 量相对比例为 netbsd-src = 14,507 commits（94.35%）、freebsd-src = 868 commits（5.65%），openbsd-src 尚未 fork（1995.10 才创建）；1994 年比例为 netbsd-src = 17,726 commits（80.78%）、freebsd-src = 4,217 commits（19.22%），FreeBSD 份额增长约 3.4 倍；1995 年比例为 netbsd-src = 12,163 commits（58.88%）、freebsd-src = 7,723 commits（37.39%）、openbsd-src = 770 commits（3.73%），三足鼎立格局初步显现；1996 年比例为 netbsd-src = 16,057 commits（54.91%）、freebsd-src = 7,948 commits（27.18%）、openbsd-src = 5,240 commits（17.92%），OpenBSD 份额增长约 4.8 倍，三足鼎立格局正式形成
- 史观：总纲第 9 条——偶然性改写历史：时间线交叉的偶然节点决定 BSD 阵营竞争力格局
- 辨析：交叉时点的具体影响经 Linux 与 BSD 项目发布历史、USL v. BSDi 诉讼时间线与 Salus《A Quarter Century of UNIX》(1994) 多方原始文档核实；bsd_commits.db 中 FreeBSD 1.0.0 release tag 由 svn2git 迁移工具标注（1993-11-01），非 Jordan K. Hubbard（乔丹·哈伯德） 本人标注（与 FreeBSD 2.0 tag 由 Jordan K. Hubbard 本人标注不同），可能存在 SVN-to-Git 迁移过程中的日期偏差，经 FreeBSD 1.0 Release Announcement（1993.11.1 FTP / 1993.12 CD-ROM）交叉验证后采信 1993.11.1 为 FTP 发布日期；【0 信任原则·commit 量不等于质量】L1.1.2 的 BSD src 比例反映开发活跃度分布但不等于项目质量，1993-1994 年 NetBSD commit 占比超 80% 反映 NetBSD 早期开发活跃但不应直接等同于 NetBSD 质量或市场份额高于 FreeBSD；【0 信任原则·CVS-to-Git 迁移风险】netbsd-src 与 openbsd-src 均为 CVS 主仓的 GitHub 镜像，CVS-to-Git 转换可能重写 author 字段或 commit_date，1993-1996 年 commit 量比例须与各项目官方档案交叉验证；【0 信任原则·GitHub 镜像滞后】netbsd-src 与 openbsd-src 的 GitHub 镜像可能滞后于 CVS 主仓，1993-1996 年 commit 量比例的精度须以官方档案为准
