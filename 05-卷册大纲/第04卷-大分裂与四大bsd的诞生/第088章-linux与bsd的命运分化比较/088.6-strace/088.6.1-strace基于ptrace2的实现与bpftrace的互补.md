# 088.6.1 strace 基于 **ptrace(2)** 的实现与 bpftrace 的互补

**要点**：strace 原为 Paul Kranenburg 1991 年为 SunOS 所写的系统调用追踪器（受 Sun 自带 trace 实用程序启发），1992 年年初经 comp.sources.sun 发布；Branko Lankester 将其移植至 Linux 并撰写内核侧支持，1992 年 11 月发布 Linux 版，其后经 Rick Sladkey 等合并增强——其 Linux 实现基于 **ptrace(2)**：父进程通过 ptrace 附加至目标进程，捕获其系统调用入口/出口事件并记录。strace 与 BSD ktrace 在功能上类似但实现独立，无代码共享。strace 在 Linux 社区长期作为标准调试工具；基于 eBPF 的 bpftrace 属不同层次的追踪手段，与 strace 在部分场景互补。

**史料**：strace 源码仓库（github.com/strace/strace，版权头载 Kranenburg 1991—1992、Lankester 1993、Sladkey 1993—1996）；**strace(1)** 手册 HISTORY 段（man7.org/linux/man-pages/man1/strace.1.html）；Kranenburg, P. strace 1.5/2.5 原始发布声明（comp.sources.sun 第三卷，1991—1992）；Love, R. (2010). *Linux Kernel Development* (3rd ed.). Addison-Wesley. Chapter 3——ptrace 机制。 〔L1 代码/L3 官方文档/L5 二手研究〕

**史观**：总纲第 4 条——分离聚合是永恒规律：strace 与 BSD ktrace 从共同的 UNIX 调试实践中分离而出，又各自在 Linux 与 BSD 阵营内聚合为标准调试工具，呈现分离—聚合的流转而非单线进步；总纲第 5 条——没有必然性，只有偶然性：Linux 选择复用 ptrace 而非新建独立系统调用，是具体历史条件下的偶然路径而非必然最优，其性能代价亦系这一选择的具体后果；总纲第 8 条——本体论上各方平等：ptrace 的用户态附加路径与 BSD 谱系的独立 **ktrace(2)** 系统调用是两条平等的工程路径，各有代价与收益，无优劣之分；总纲第 10 条——动手者创造历史：Kranenburg 与 Lankester 作为 strace 最初开发者，其姓名在 Linux 主线叙事中常被遮蔽；自反性声明：本释读不预设“Linux 中心论”——strace 与 BSD ktrace 是同期独立出现的工程解决方案，本节仅释读 Linux 一支。

**辨析**：strace 与 BSD ktrace 的关键差异——前者基于 **ptrace(2)**，后者基于独立 **ktrace(2)**；开销方面，ptrace 机制每次被追踪的系统调用至少引入两次上下文切换，对系统调用密集型程序可造成数量级级别的减速（此系 Wu 与 Yap 2005 年 ACSAC 论文微基准对 ptrace 机制的量化结论），ktrace 由内核直接记录，无需逐调用停止—恢复被追踪进程，机制上避免了逐调用上下文切换，与 ptrace 的量化对比须依 BSD 手册与实测研究另行考据，不作无来源断言；bpftrace 基于 eBPF，属与 strace 不同层次的追踪手段，在部分场景与 strace 互补，“strace 在 Linux 5.x 后逐步被 bpftrace 取代”缺乏来源支撑，不采信；ktrace 在 BSD 谱系中仍保留。
