# 81.15 项目统摄史观审视——总纲第 13、19、21 条的深入切入

## 81.15.1 总纲第 13 条切入——许可证哲学作为利益分配

  **要点**：从总纲第 13 条（法律与道德是利益分配）切入，Linux vs BSD 许可证之争本质是利益分配问题——GPL 强制回馈条款将商业公司的衍生作品贡献强制回流公共池，形成 “贡献循环”；BSD 许可证允许商业公司自由使用、修改、再分发而不强制回馈，形成 “散逸效应”；两套许可证哲学背后的利益分配机制不同，不得以 “GPL 优于 BSD” 或 “BSD 优于 GPL” 的道德判断简化；FSF 与 Stallman 在 2000 年代多场公开演讲中将 BSD 描述为 “less free than GPL”，建构 “GPL 是严格 free software，BSD 是 permissive” 的阵营对立叙事，这一 “道德问题” 本质上是 FSF 阵营对 BSD 阵营的 “利益分配” 问题。GPL 与 BSD 利益分配机制对照如下：

| 维度 | GPL（Linux 内核） | BSD（FreeBSD/NetBSD/OpenBSD） |
| -- | --------------- | --------------------------- |
| 利益流向 | 公共池与贡献者 | 商业公司与最终用户 |
| 强制回馈 | 是——衍生作品须以 GPL 发布 | 否——允许 proprietary 衍生品 |
| 道德叙事 | “GPL 严格 free software” | “BSD permissive” |
| 利益分配本质 | 商业公司贡献强制回流 | 商业公司自由使用不回馈 |

**史料**：BSD 许可证原文（BSD 3-Clause **1990**）、GPL v2 许可证原文（**1991**）、GPL v3 许可证原文（**2007**）；Stallman 公开演讲存档（FSF 网站）；Torvalds 关于 GPL 的公开声明（lkml.org 邮件列表存档）；BSD 衍生产品统计（macOS、PlayStation、Netflix、Juniper、NetApp） ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：GPL 与 BSD 许可证之争本质是利益分配问题，GPL 强制回馈条款将商业公司的衍生作品贡献强制回流公共池，BSD 许可证允许商业公司自由使用而不强制回馈，两套许可证哲学背后的利益分配机制不同；FSF 与 Stallman 建构的 “GPL 严格 free software，BSD permissive” 叙事本质上是 FSF 阵营对 BSD 阵营的 “利益分配” 问题

**辨析**：总纲第 13 条的切入须区分三个维度——法律维度（GPL 强制回馈条款与 BSD 散逸效应是法律结构差异）、道德维度（“GPL 优于 BSD” 或 “BSD 优于 GPL” 的道德判断是形式主义误读）、利益分配维度（GPL 与 BSD 背后的利益分配机制不同，GPL 利益流向公共池与贡献者，BSD 利益流向商业公司与最终用户）；【0 信任原则·道德判断考据】Stallman 公开演讲中 “BSD less free than GPL” 的表述须经 FSF 网站存档与 lkml.org 邮件列表存档交叉验证，不得仅凭道听途说即采信；【0 信任原则·利益分配非道德判断】GPL 与 BSD 的利益分配机制差异是法律结构差异，不得以 “GPL 更道德” 或 “BSD 更道德” 的道德判断简化——二者各有其哲学前提（GPL 以强制回馈保障公共池，BSD 以自由散逸承认人类有限性）

**文献**：BSD 与 GPL 许可证原文；Stallman 公开演讲存档；Torvalds 公开声明 ［A］

## 81.15.2 总纲第 19 条切入——解释学循环与权力知识共谋

  **要点**：从总纲第 19 条（解释学循环是历史认识的根本条件）切入，Linux vs BSD 争议中 “什么被记录、什么被遗忘” 本身就是权力行使——Linux 端主流叙事通过 man page、官方文档、培训教材、社区话语等渠道，将 BSD 端的一手作者、起源日期、概念先验地位系统性隐去，使读者形成 “该工具或概念起源于 Linux 端” 的误判；BSD 端的 “先验存在” 在 Linux 端主流叙事中被 “遗忘”，这一 “遗忘” 不是 “自然遗忘” 而是 “权力与知识共谋” 的产物；批评方与反批评方的前理解差异使分歧不可避免，合图非 “消除分歧” 而是 “在分歧中呈现各主体性”；“什么被记录、什么被遗忘” 的三类典型表现如下：

| 案例 | BSD 端一手作者 | Linux 端主流叙事的 “遗忘” |
| -- | ------------ | ----------------------- |
| sudo | Coggeshall 与 Spencer **1980 年**（编写；1985-12 经 net.sources 公开） | LPI 认证以 “Todd C. Miller（托德·C·米勒） 1994” 为起点 |
| BIND | Terry 等 4 人 **1984 年** | BIND 9 官方文档不点明 4 人姓名 |
| Capsicum | Watson 与 Laurie 等 **2010 年**（论文；2012 年随 FreeBSD 9.0 集成） | Linux man **landlock(7)** 不点明作者姓名〔订正注：原记“Watson 与 Anderson 2012 年”，归属与年份双错置，经行 109 自引论文订正〕 |

**史料**：〔存疑：原引 原材料/研究/linux 文化挪用/ 下 79 项案例文件与模式总结.md，该目录经查全项目不存在，出处无从对证〕；Coggeshall 与 Spencer **1985-12** net.sources sudo 公告、4.2BSD **1983-08** Release Notes、UCB/CSD-84-182 BIND 论文、4.4BSD-Lite **1994-06** Release Notes、FreeBSD 9.0-RELEASE **2012-01-12** Capsicum 公告；Linux man page 与培训教材档案 ［A］

**史观**：总纲第 19 条——解释学循环是历史认识的根本条件：Linux vs BSD 争议中 “什么被记录、什么被遗忘” 本身就是权力行使，Linux 端主流叙事的 “内部一致性” 是权力与知识共谋的产物；前理解的差异使 BSD 与 Linux 两端的分歧不可避免，合图非 “消除分歧” 而是 “在分歧中呈现各主体性”

**辨析**：总纲第 19 条的切入须经具体案例的 “什么被记录、什么被遗忘” 考据——Coggeshall 与 Spencer **1980 年** sudo 起源被 “遗忘”（Linux man **sudo(8)** 不回溯 4.1BSD 起源）、Terry 等 4 人 **1984 年** BIND 起源被 “遗忘”（BIND 9 官方文档不点明 4 人姓名）、Watson 与 Laurie 等 **2010 年**（USENIX Security 论文；2012 年随 FreeBSD 9.0 集成）Capsicum 起源被 “遗忘”（Linux man **landlock(7)** 不点明作者姓名〔订正注：原记“Watson 与 Anderson 2012 年”系归属与年份双错置——Capsicum 论文（本文件行 109 自引）作者为 Robert Watson 与 Ben Laurie 等，2012 年系 FreeBSD 9.0 集成之年而非论文年〕），这一 “遗忘” 须经一手档案与主流叙事的比对交叉验证；【0 信任原则·共谋须经考据】“权力与知识共谋” 须经 Linux 端主流叙事的 “内部一致性”（man page 与培训教材的一致性）与 BSD 端一手档案的 “被遮蔽” 比对交叉验证，不得仅凭推测即断定 “共谋”；【0 信任原则·前理解差异非对立】批评方与反批评方的前理解差异使分歧不可避免，但前理解差异非 “对立” 而是 “不同视角”，合图须在分歧中呈现各主体性而非消除分歧

## 81.15.3 总纲第 21 条切入——革命与改革的方法论分歧

  **要点**：从总纲第 21 条（革命与改革是历史方法论的分歧）切入，Linux 靠革命（systemd 重构、Docker 重命名、eBPF 扩展），BSD 靠改革（rc.d 渐进演化、jail 渐进扩展、BPF 渐进扩展），“改革的困难远高于革命”，“破山中贼易，破心中贼难”——Linux 端革命的 “心中贼”（建构 Linux 原生叙事）远比 “山中贼”（具体技术重写）难以破除；Linux 的革命模式在快速迭代与商业推广上占优，BSD 的改革模式在长期稳定与向后兼容上占优，二者非对立而是不同方法论的选择。Linux 革命与 BSD 改革的对照如下：

| 维度 | Linux 革命模式 | BSD 改革模式 |
| -- | ------------ | ---------- |
| init 系统 | systemd **2010 年** 重构 | rc.d **1994-1998 年** 渐进演化 |
| 容器 | Docker **2013 年** 重命名 | jail **1999-2000 年** 渐进扩展 |
| 包过滤 | eBPF **2014 年** 扩展超越 | BPF **1993 年** 渐进演化 |
| 优势 | 快速迭代与商业推广 | 长期稳定与向后兼容 |

**史料**：Poettering **2010-03-30** 首次 commit systemd 与 **2010-04-30** 博客承认借鉴 NetBSD rc.d；PHK **1999 年** FreeBSD 主线 jail commit 与 FreeBSD 4.0-RELEASE **2000-03-14** 公告；McCanne 与 Van Jacobson（范·雅各布森） **1993 年** USENIX BPF 论文与 Alexei Starovoitov **2014 年** eBPF 扩展；rc.d 框架系 NetBSD 创新（Luke Mewburn 设计，NetBSD 1.5/2000-11 全面落地，USENIX 2001 论文可证），FreeBSD 5.0（2003）移植引入；NetBSD 1.3 **1998-01-04** **rcorder(8)** 重构〔订正注：原记“4.4BSD-Lite 1994-06 rc.d 框架”系时代错置——4.4BSD-Lite（1994-06）仍为 /etc/rc 单体脚本，不含 rc.d〕 ［A］

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧：Linux 靠革命（systemd、Docker、eBPF），BSD 靠改革（rc.d、jail、BPF），“改革的困难远高于革命”；Linux 的革命模式在快速迭代与商业推广上占优，BSD 的改革模式在长期稳定与向后兼容上占优

**辨析**：总纲第 21 条的切入须区分两个维度——技术维度（Linux 的 systemd、Docker、eBPF 是革命性重构，BSD 的 rc.d、jail、BPF 是渐进性演化）与叙事维度（Linux 端革命的 “心中贼”——建构 Linux 原生叙事——远比 “山中贼”——具体技术重写——难以破除）；“破山中贼易，破心中贼难” 在 Linux vs BSD 争议中的体现是：破除 Linux 端具体技术重写的 “山中贼”（如证明 Docker 重写 jail）相对容易，破除 Linux 端主流叙事的 “心中贼”（如证明 “container 是 Linux 原生概念” 是建构）远比破除 “山中贼” 困难；【0 信任原则·革命与改革须时序比对】“革命” 与 “改革” 的区分须经具体技术演化的时序比对交叉验证——systemd **2010-03-30** 首次 commit 是革命性重构（替代传统 init），rc.d **1994-06** 至 **1998-01-04** 是渐进性演化（从 4.4BSD-Lite 框架到 NetBSD **rcorder(8)** 重构），二者非同一形态；【0 信任原则·方法论非优劣】革命与改革各有代价，Linux 革命的代价是向后兼容性受损（如 systemd 替代传统 init 引发的社区分裂），BSD 改革的代价是迭代速度较慢，不得以 “革命优于改革” 或 “改革优于革命” 简化

**文献**：Poettering 2010 systemd commit 与博客；PHK 1999 jail commit；McCanne 与 Van Jacobson 1993 BPF 论文；4.4BSD-Lite 与 NetBSD 1.3 发布记录 ［A］

## 81.15.4 三条总纲的合图——争议的不可调和性与和解路径

  **要点**：总纲第 13、19、21 条的合图显示，Linux vs BSD 争议的不可调和性源于三条总纲的交织——许可证哲学（第 13 条）的利益分配差异、解释学循环（第 19 条）的前理解差异、革命与改革（第 21 条）的方法论差异，三者共同构成争议的不可调和性；合图层指出和解路径——承认 BSD 与 Linux 各有其主体性，许可证哲学差异不得以道德判断简化，解释学循环差异不得以 “消除分歧” 回避，革命与改革差异不得以 “胜负” 衡量；和解不是 “消除争议” 而是 “在争议中呈现各主体性”

**史观**：总纲第 6 条——和解优于斗争：合图层以 “和解” 姿态审视争议，承认 BSD 与 Linux 各有其主体性；总纲第 13 条——法律与道德是利益分配：许可证哲学差异是利益分配问题，不得以道德判断简化；总纲第 19 条——解释学循环是历史认识的根本条件：前理解差异使分歧不可避免，合图非 “消除分歧” 而是 “在分歧中呈现各主体性”；总纲第 21 条——革命与改革是历史方法论的分歧：Linux 革命与 BSD 改革各有代价，不得以 “胜负” 衡量
  
**辨析**：三条总纲的合图须区分 “不可调和性” 与 “和解路径”——不可调和性源于三条总纲的交织（许可证利益分配、解释学前理解、革命与改革方法论），三者共同构成争议的结构性张力；和解路径不是 “消除争议” 而是 “在争议中呈现各主体性”，承认 BSD 与 Linux 各有其评价标准与存在价值；【0 信任原则·不可调和性须考据】“不可调和性” 与 “和解路径” 的区分须经具体争议案例（如 sudo、jail、rc.d 等文化挪用案例）的考据验证，不得仅凭理论推演即断定；【0 信任原则·和解非折中】和解路径非 “双方都有道理” 的折中主义，而是基于一手档案与第三方数据的多因素叠加分析，合图须以考据为前提
