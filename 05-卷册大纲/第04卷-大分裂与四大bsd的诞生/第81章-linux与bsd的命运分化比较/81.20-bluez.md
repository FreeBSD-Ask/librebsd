# 81.20 BlueZ：Linux 的蓝牙协议栈（跨 BSD/UNIX/macOS 扩展）

## 80.20.1 BlueZ 的传统协议栈实现与内核模块化

  **要点**：Linux BlueZ 由 Maxim Krasnyansky 于 **1999 年**发起，**2001 年**合入 Linux 2.4.6——其核心机制是采用传统协议栈实现，HCI、L2CAP、RFCOMM 等协议层作为内核模块。BlueZ 在 Linux 社区长期作为标准蓝牙栈，源码仓库见 **github.com/bluez/bluez**。BlueZ 与 FreeBSD/NetBSD 蓝牙栈在功能上类似但实现独立，无代码共享。
  
**史料**：BlueZ 源码仓库（github.com/bluez/bluez）；Linux 2.4.6 Release Notes（**2001-06-08**）；Krasnyansky, M. (1999). *BlueZ: Linux Bluetooth Stack*. 原始发布声明；Holtmann, M. (2004). *Bluetooth on Linux*. Linux Symposium 2004. 〔L1 代码/L3 官方文档/L4 事后叙述〕
  
**史观**：总纲第 1 条——源头时刻：BlueZ 是 Krasnyansky 面对 Linux 蓝牙需求的工程洞察；总纲第 2 条——分离与聚合：BlueZ 在 Linux 2.4.6 中聚合入主线，是 Linux 蓝牙生态的聚合时刻；总纲第 6 条——技术选择的代价：Linux 选择传统协议栈实现而非 Netgraph 节点图，付出灵活性代价，但获得与传统内核架构的兼容性；总纲第 7 条——技术选择即政治选择：Linux 选择 BlueZ 反映其“内核原生 + 模块化”的技术政治选择，与 BSD 谱系的“Netgraph 节点图”形成对照；总纲第 10 条——边缘者贡献：Krasnyansky 作为 BlueZ 最初开发者，其姓名在 Linux 主线叙事中常被遮蔽；自反性声明：本释读不预设“Linux 中心论”——BlueZ 与 BSD 蓝牙栈是独立演化的实现，本节仅释读 Linux 一支。
  
**辨析**：BlueZ 与 BSD 蓝牙栈的关键差异——前者采用传统协议栈实现，后者采用 Netgraph 节点图；BlueZ 在 Linux 桌面与嵌入式市场占主导地位；macOS IOBluetooth 与 BlueZ 无源码关系。
  
**文献**：BlueZ Project. *BlueZ Source Code Repository*[EB/OL]. <https://github.com/bluez/bluez>; Linux Kernel Project. *Linux 2.4.6 Release Notes*[EB/OL]. (2001-06-08). <https://www.kernel.org/>; Holtmann, M. (2004). *Bluetooth on Linux*. Linux Symposium 2004.
