# 81.21 ALSA：Linux 的音频子系统（跨 BSD/UNIX/macOS 扩展）

## 81.21.1 ALSA 取代 OSS 与内核驱动框架

**要点**：Linux ALSA（Advanced Linux Sound Architecture）由 Jaroslav Kysela 于 **1998 年**发起。

**要点**：**2002 年**并入 Linux 2.5 开发线，**2003-12-17** 随 Linux 2.6 发布成为默认音频子系统，取代 OSS（Open Sound System）；核心机制是提供内核驱动框架与用户态库（alsa-lib），支持 PCM、MIDI、混音器、序列器等。

**要点**：ALSA 在 Linux 社区长期作为标准音频子系统，源码仓库见 **github.com/alsa-project/alsa-lib**。

**要点**：ALSA 与 BSD **audio(4)** 在功能上类似但实现路径独立；两者间“无代码共享”不作绝对化表述，跨系统代码流动〔存疑：待专项考据（含 FreeBSD 声音子系统兼容 OSS API 之说）〕。
  
**史料**：ALSA 源码仓库（**github.com/alsa-project/alsa-lib**）；Linux 2.6 Release Notes（**2003-12-17**）；Kysela, J.（1998）：《ALSA Project Launch》原始发布声明（全文与 URL 待补）；ALSA Project：《ALSA Documentation》（<https://alsa-project.org/>）——以源码与官方文档为主
  
**史观**：总纲第 5 条——没有必然性，只有偶然性：ALSA 起于 Kysela 面对 OSS 局限的工程选择；总纲第 4 条——分离聚合是永恒规律：ALSA 在 Linux 2.6 中聚合为默认音频子系统；总纲第 13 条——法律与道德是利益分配：弃 OSS 取 ALSA 的向后兼容代价（需 ALSA-OSS 兼容层）由应用与发行方分摊，换取更丰富的 API；总纲第 3 条——不存在进步，只有权力再分配：“内核原生 + 用户态库”路线与 BSD 谱系“设备无关接口”的对照是话语权再分配而非优劣判定；总纲第 10 条——动手者创造历史：Kysela 以个人开发者身份发起并长期维护 ALSA；自反性声明：本释读不预设“Linux 中心论”——ALSA 与 BSD **audio(4)** 是独立演化的实现，本节仅释读 Linux 一支。
  
**辨析**：ALSA 与 BSD **audio(4)** 的关键差异——前者提供更丰富的 API（含 MIDI、混音器、序列器），后者仅提供基本音频接口；ALSA 在 Linux 桌面与嵌入式市场占主导地位；macOS CoreAudio 与 ALSA 无源码关系。
