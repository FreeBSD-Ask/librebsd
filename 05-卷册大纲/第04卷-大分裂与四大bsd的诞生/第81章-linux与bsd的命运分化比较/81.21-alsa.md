# 81.21 ALSA：Linux 的音频子系统（跨 BSD/UNIX/macOS 扩展）

## 80.21.1 ALSA 取代 OSS 与内核驱动框架

  **要点**：Linux ALSA（Advanced Linux Sound Architecture）由 Jaroslav Kysela 于 **1998 年**发起，**2002 年**随 Linux 2.6 起取代 OSS（Open Sound System）成为默认音频子系统——其核心机制是提供内核驱动框架与用户态库（alsa-lib），支持 PCM、MIDI、混音器、序列器等。ALSA 在 Linux 社区长期作为标准音频子系统，源码仓库见 **github.com/alsa-project/alsa-lib**。ALSA 与 BSD audio(4) 在功能上类似但实现独立，无代码共享。
  
**史料**：ALSA 源码仓库（github.com/alsa-project/alsa-lib）；Linux 2.6 Release Notes（**2003-12-17**）；Kysela, J. (1998). *ALSA Project Launch*. 原始发布声明；ALSA Project. *ALSA Documentation*. alsa-project.org。 〔L1 代码/L3 官方文档〕
  
**史观**：总纲第 1 条——源头时刻：ALSA 是 Kysela 面对 OSS 局限性的工程洞察；总纲第 2 条——分离与聚合：ALSA 在 Linux 2.6 中聚合为默认音频子系统，是 Linux 音频生态的聚合时刻；总纲第 6 条——技术选择的代价：Linux 选择 ALSA 而非保留 OSS，付出向后兼容代价（需 ALSA-OSS 兼容层），但获得更丰富的 API；总纲第 7 条——技术选择即政治选择：Linux 选择 ALSA 反映其“内核原生 + 用户态库”的技术政治选择，与 BSD 谱系的“设备无关接口”形成对照；总纲第 10 条——边缘者贡献：Kysela 作为 ALSA 最初开发者，其姓名在 Linux 主线叙事中常被遮蔽；自反性声明：本释读不预设“Linux 中心论”——ALSA 与 BSD audio(4) 是独立演化的实现，本节仅释读 Linux 一支。
  
**辨析**：ALSA 与 BSD audio(4) 的关键差异——前者提供更丰富的 API（含 MIDI、混音器、序列器），后者仅提供基本音频接口；ALSA 在 Linux 桌面与嵌入式市场占主导地位；macOS CoreAudio 与 ALSA 无源码关系。
  
**文献**：ALSA Project. *ALSA Source Code Repository*[EB/OL]. <https://github.com/alsa-project/alsa-lib>; Linux Kernel Project. *Linux 2.6 Release Notes*[EB/OL]. (2003-12-17). <https://www.kernel.org/>; ALSA Project. *ALSA Documentation*[EB/OL]. <https://alsa-project.org/>.
