# 80.22 Linux Audit Subsystem：Linux 的独立审计框架（跨 BSD/UNIX/macOS 扩展）

## 80.22.1 Linux Audit 基于 netlink 与 auditd 的实现
  - 要点：Linux Audit Subsystem 由 Steve Grubb（Red Hat）维护，用户态项目主页 **people.redhat.com/sgrubb/audit/**，源码仓库 **github.com/linux-audit/audit-userspace**——其核心机制是内核侧 kauditd 通过 netlink 与用户态 auditd 通信，记录系统调用、文件访问、用户登录等安全事件。Linux Audit 与 FreeBSD OpenBSM 完全独立演化，无源码关系。内核侧 kauditd 在 Linux 2.6.x 系列引入。
  - 史料：Linux Audit 项目主页（people.redhat.com/sgrubb/audit/）；GitHub 仓库（github.com/linux-audit/audit-userspace）；Linux 2.6 Release Notes；Grubb, S. (2015). *Linux Audit Framework*. Red Hat Summit 2015.
  - 史观：总纲第 1 条——源头时刻：Linux Audit 是 Grubb 面对 Linux 安全审计需求的工程洞察，与 FreeBSD TrustedBSD 独立演化；总纲第 2 条——分离与聚合：Linux Audit 在 Linux 2.6 中聚合入主线，是 Linux 安全生态的聚合时刻；总纲第 6 条——技术选择的代价：Linux 选择独立实现而非移植 OpenBSM，付出与 BSD 谱系审计工具不兼容的代价，但获得与 Linux 安全模块（LSM）的深度集成；总纲第 7 条——技术选择即政治选择：Linux 选择独立 Audit 反映其“内核原生 + LSM 集成”的技术政治选择，与 FreeBSD 的“OpenBSM 框架”形成对照；总纲第 10 条——边缘者贡献：Grubb 作为 Linux Audit 长期维护者，其姓名在 Linux 主线叙事中常被遮蔽；自反性声明：本释读不预设“Linux 中心论”——Linux Audit 与 FreeBSD OpenBSM 是独立演化的实现，本节仅释读 Linux 一支。
  - 辨析：Linux Audit 与 FreeBSD OpenBSM 的关键差异——前者基于 netlink 与 auditd 通信，后者基于 BSM 格式与 auditd 通信；Linux Audit 与 SELinux/AppArmor 等 LSM 协同，OpenBSM 独立运作；macOS BSM 审计框架是 OpenBSM 的移植，与 Linux Audit 无源码关系。
  - 文献：Grubb, S. *Linux Audit Project Home Page*[EB/OL]. https://people.redhat.com/sgrubb/audit/; Linux Audit Project. *audit-userspace Source Code Repository*[EB/OL]. https://github.com/linux-audit/audit-userspace; Grubb, S. (2015). *Linux Audit Framework*. Red Hat Summit 2015.
