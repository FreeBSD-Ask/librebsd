# 81.17 OverlayFS：Linux 对 union 语义的独立演化（跨 BSD/UNIX/macOS 扩展）

## 80.17.1 OverlayFS 的 copy_up 机制与容器场景优化

  **要点**：Linux OverlayFS 由 Miklos Szeredi（Red Hat）设计，**2014 年 12 月 7 日**随 Linux 3.18 合入主线——其核心机制是"copy_up"：下层文件系统保持只读，写操作触发文件向上层复制后再修改，针对容器镜像分层场景优化。OverlayFS 与 FreeBSD unionfs/NetBSD union 在语义上同源（叠加挂载）但实现独立，无代码共享。OverlayFS 的合入使 Docker 等容器工具获得了原生的镜像分层支持，成为容器生态的事实标准。
  
**史料**：Linux Kernel 3.18 Release Notes（kernel.org）；OverlayFS 设计文档（github.com/torvalds/linux/blob/master/Documentation/filesystems/overlayfs.rst）；Miklos Szeredi 在 LWN.net 的设计文章（lwn.net/Articles/576631/）；Mauerer, W. (2010). *Professional Linux Kernel Architecture*. Wrox. Chapter 12. 〔L1 代码/L3 官方文档/L4 事后叙述/L5 二手研究〕
  
**史观**：总纲第 1 条——源头时刻：OverlayFS 的 copy_up 机制是 Szeredi 面对容器镜像分层场景的工程洞察，与 BSD unionfs 的“传统 stack 语义”形成对照；总纲第 2 条——分离与聚合：OverlayFS 在 Linux 3.18 聚合入主线，是容器生态需求驱动下的聚合时刻；总纲第 6 条——技术选择的代价：Linux 选择重写 OverlayFS 而非移植 BSD unionfs，付出独立维护代价，但获得与 VFS 框架的深度集成；总纲第 7 条——技术选择即政治选择：Linux 选择 OverlayFS 反映其“内核原生 + 容器优先”的技术政治选择，与 BSD 谱系的“传统 stack 语义保留”形成对照；总纲第 22 条——开源运动：OverlayFS 的合入得益于 Docker（2013 年开源）推动的容器浪潮，此即开源协作驱动的技术演进；自反性声明：本释读不预设“Linux 中心论”——OverlayFS 是 union 语义的独立演化，BSD 谱系保留的传统 union 实现仍有其工程价值。
  
**辨析**：OverlayFS 与 FreeBSD unionfs 的关键差异——前者采用 copy_up 机制（写时复制整个文件到上层），后者采用传统 stack 语义（写操作直接落在上层，不复制）；OverlayFS 针对容器场景优化，unionfs 针对传统系统管理场景设计。早期 Linux 曾有 unionfs 实现（2006 年 unionfs.org 项目），但因稳定性问题未合入主线，OverlayFS 取代之。macOS 无 OverlayFS。
  
**文献**：Torvalds, L. *Linux 3.18 Release Notes*[EB/OL]. (2010). *Professional Linux Kernel Architecture*. Wrox. Chapter 12.
