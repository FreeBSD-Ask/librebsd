# 81.19 lsof：Linux 对打开文件列表的独立演化（跨 BSD/UNIX/macOS 扩展）

## 81.19.1 lsof 基于 /proc 的实现与跨平台特性

**要点**：Linux lsof（List Open Files）由 Vic Abell（Purdue University）开发，**1991 年**经 comp.sources.unix 首次发布，**1994 年**移植至 Linux——其核心机制是遍历 **/proc** 与内核数据结构，列出所有进程打开的文件、socket、管道等。lsof 与 BSD fstat 在功能上类似但实现独立，无代码共享。lsof 在 Linux 社区长期作为标准调试工具，被 macOS 移植作为 fstat 的标准替代。

**史料**：lsof 源码仓库（github.com/lsof-org/lsof）；lsof man page（man7.org/linux/man-pages/man8/lsof.8.html）；Abell, V. (1991). *lsof: List Open Files*. comp.sources.unix 发布声明；Bovet, D. P., & Cesati, M. (2005). *Understanding the Linux Kernel* (3rd ed.). O'Reilly. Chapter 12. 〔L1 代码/L3 官方文档/L5 二手研究〕

**史观**：源头时刻（本章专题语，未对应总纲 25 条单一条目，故不设条号）：lsof 是 Abell 面对大型主机调试需求的工程洞察，与 BSD fstat 在 1988 年后独立演化；总纲第 4 条——分离聚合是永恒规律：lsof 在 Linux 社区聚合为标准调试工具，是 Linux 工程哲学的聚合时刻；技术选择的代价（本章专题语，未对应总纲 25 条单一条目，故不设条号）：Linux 选择 lsof 而非移植 BSD fstat，付出独立维护代价，但获得跨平台兼容性（lsof 支持多种 UNIX）；技术选择即政治选择（本章专题语，未对应总纲 25 条单一条目，故不设条号）：Linux 选择 lsof 反映其“用户态工具 + **/proc**”的技术政治选择，与 BSD 谱系的“kvm(3) 读取内核”形成对照；总纲第 10 条——动手者创造历史：Abell 作为 lsof 长期维护者，其姓名在 Linux 主线叙事中常被遮蔽；自反性声明：本释读不预设“Linux 中心论”——lsof 与 BSD fstat 是独立演化的工具，本节仅释读 Linux 一支。

**辨析**：lsof 与 BSD fstat 的关键差异——前者基于 **/proc** 与遍历内核数据结构，后者基于 kvm(3) 读取内核内存；lsof 支持列出所有进程打开的文件，fstat 仅列当前进程；lsof 跨平台（Linux、macOS、Solaris、AIX 等），fstat 仅 BSD 谱系。
