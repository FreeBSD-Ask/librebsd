# 第76章 三足鼎立的形成与bsd格局分化

## 要点

- **1996 年** BSD 格局形成——FreeBSD、NetBSD、OpenBSD 三项目定位分化，共享 4.4BSD-Lite 遗产但走向不同方向；背景涉及 386BSD 中断、三项目创建与定位选择。三项目首条 commit 时间节点对照如下：
- FreeBSD 选择 x86 性能定位——聚焦 i386 平台性能优化与 Walnut Creek CDROM 商业绑定；定位选择决定 FreeBSD 后续发展路径
- NetBSD 选择可移植定位——聚焦多平台移植，扩展至 50+ 平台；定位选择决定 NetBSD 后续工程方向；freebsd.duckdb 统计结论 C-04 显示：netbsd-src 总 commit 数 774,061（SQL 查询 `SELECT COUNT(*) FROM commits WHERE repo_name='netbsd-src'`）〔订正注：原 773,683 系统计结论漂移，依核查报告按三库实测统一更新〕，为四 BSD 项目 src 仓库中累计 commit 量最高者——与 C-03 freebsd-src 总 commit 数 445,203、C-05 openbsd-src 总 commit 数 246,535 对照〔订正注：原 444,203/245,904 同上，C-03 差恰 1,000 疑位数误植〕，NetBSD 累计 commit 量约为 FreeBSD 的 1.74 倍、OpenBSD 的 3.15 倍，反映 NetBSD 在更多平台移植目标（50+ 平台）下的累计工程产出规模最大，可移植定位的工程代价体现为单平台深度优化 commit 的分散
- OpenBSD 选择安全定位——聚焦全代码审计与安全默认配置；定位选择决定 OpenBSD 后续工程方向。三项目定位分化对照如下：
- BSD 4 条款许可证包括版权声明、许可证声明、免责声明与“广告条款”（所有广告材料须提及原始作者）；4 条款是 BSD 许可证原始形态，影响后续演化

**要点**：

- Lucas 的最新著作 Absolute FreeBSD 是其处女作 Absolute BSD 的重写；书名与成书方式的分化源于 BSD 家族的趋异：2000 至 2001 年写 Absolute BSD 时各 BSD 相同点多于差异，熟悉其一即可操作其余，而此后各分支走出独特方向——NetBSD 直指可移植性并为嵌入式开发者提供便利，另一分支（转写作 3BSD，疑为 FreeBSD）深耕 SMP、内核锁与高性能——以致每个分支都值得单独成书，他希望最终为各 BSD 各著一本。（BSDTalk EP153，[114.84-214.22]，L1）
- 其写作理念是在纯信息（如源代码打印稿）与纯装饰之间取细线平衡：技术正确且有用之外还须可读；不只讲 how 更讲 why——为什么网络配置必须正确、为什么文件系统分区布局重要；他以 Red Hat 默认单一分区覆盖全盘为例，指出这种默认灵活但带风险，使用者应当理解风险所在。（BSDTalk EP153，[443.88-513.48]，L1）
- 出版生态的竞争压力：Absolute BSD 热卖后，其他出版社紧盯其出版商并抢先推出同题材书籍，Absolute OpenBSD 亦遭此遇；他批评赶工出版的书是废纸，坚持一年一书的节奏，且并非全职作者，搬家等变故即打乱写作日程。（BSDTalk EP153，[335.66-369.12]，L1）
- 应对时效与协作方法：Absolute OpenBSD 交稿数小时后 PF 宣布大批新特性，他恳求出版商宽限两三周补写章节；写作前先读邮件列表存档与 man 帕吉做足功课，开发者乐于受访，会直言某节应暂缓撰写并纠正错误；他举例就 Absolute FreeBSD 中 freebsd-update 一节向作者 Colin Percival 求证其在邮件列表中自贬早期源码为羞于示人之作的说法，获复已重写。（BSDTalk EP153，[529.68-703.54]，L1）
- FreeBSD 的直接前驱是 386BSD patchkit：Bill Jolitz 的 386BSD 发行版 0.0 已出约一年、0.1 已出三四个月，社区开始汇集大量代码变更、新驱动与构建工具；patch kit 由 Terry Lambert 创建、Nate Williams 为早期协调人之一、Jordan Hubbard spin 过一两个，发言人自 Terry 工作期间接手并为其大量测试、亦 spin 出数个 patch kit；Walnut Creek CDROM 介入后购置 486 DX2 硬件并提供 T1 互联网连接，该机因 cache 芯片故障反复 panic 被寄往波特兰修复，重装 386BSD 加 patchkit 后成为 freefall——主机名取自发言人的跳伞经历，他本人则在 Walnut Creek 机房地板上睡了近两年。[订正：原“发言人与 Bill Jolitz 协作测试、以邮件列表协调 0.0 与 0.1 版分发”→新转写证实发言人是为 Terry Lambert 测试并接手 spin patch kit，邮件列表与 Usenet 为当时主要沟通渠道]（YouTube EP4OvLlKazFV4，[225.72-266.63]，L1）
- 项目命名经邮件列表与 Usenet 公开讨论，David Greenman 第一个发帖提议，候选名经集体投票定为 FreeBSD；几天内发言人在此前只用过 RCS 与 SCCS 的情况下被指定搭起 CVS 仓库并接入邮件列表，成为唯一从未获得 commit bit 的创始人；USL 诉讼后现行仓库被放弃重建，导致 1.x 与 2.5 release 在仓库中共享 1.1/1.1.1 版本号，早期提交历史的可追溯性由此受损。（YouTube EP4OvLlKazFV4，[289.07-396.54]，L1）
- 创建 core team 是对“仁慈独裁者”模式的制度性拒绝：发言人基于业界观察认为独裁者项目多不长寿，且自认知识面广而不深、无法覆盖全部组件，遂征集约七人组成核心团队，同时为自己保留退出通道；二十五年后回看认为该决策正确，并明言不喜欢 Linux 的治理模型但承认其成就。（YouTube EP4OvLlKazFV4，[2294.63-2366.66]，L1）
- 1.0 版在约九个月开发后于 1993 年 11 月发布，传播速度远超预期；项目早期曾与 NetBSD 方代表在 Walnut Creek 会谈三四次讨论两项目合并，结论是人员差异下合并将不利于双方而作罢；发言人回看认为分叉反而是好事，BSD 阵营的分叉数量远少于 Linux 阵营的庞大谱系。（YouTube EP4OvLlKazFV4，[597.0-696.62]，L1）
- USL/Novell 诉讼中止了开发进程并阻断社区对代码库的采纳，因为潜在使用者无法在前景不确定时投入资源；和解协议有多份且大多含保密条款，加州大学所签版本因其公共实体身份经 Kirk McKusick 通过信息自由法程序公开、可在互联网获取且并不复杂；问答环节发言人梳理 UNIX 版权链为 AT&T 到 USL 再到 Novell，诉讼名称亦随权利转移而变化。（YouTube EP4OvLlKazFV4，[697.1-868.15]，L1）
- 该解说把 BSD 概括为伯克利学生对 AT&T Unix 的修改与增强包，最初并非独立操作系统，后成长为独立分支；其最重要的历史贡献是网络：在 1970 年代末与 1980 年代初实现 TCP/IP 协议栈，代码清洁、可靠且开放供研究者研究，互联网扩展出研究实验室后 BSD 网络代码无处不在，早期商业 Unix 与 Windows 网络实现亦大量借鉴，由此获得“构建互联网的 Unix 系统”之称号。（YouTube EP3u8zKO8VTD0，[120.32-192.96]，L2）
- 1980 年代末 AT&T 开始对 Unix 主张知识产权，与加州大学陷入漫长复杂的法律纠纷；法律不确定性恰在 Linux 诞生之际拖慢了 BSD 的采用，Linux 因未直接衍生自 AT&T 代码而避开此问题，最终 BSD 以重写清除残余 AT&T 代码、纠纷了结，但 Linux 已积聚势头，BSD 生态遂分裂为各有目标、哲学与强项的数个重要分支。（YouTube EP3u8zKO8VTD0，[202.96-240.16]，L2）
- 三分支定位在解说中被总结为：FreeBSD 以性能、可扩展与整体性设计见长，内核与用户态一体开发，被 Netflix Open Connect 内容分发网络、Juniper、NetApp 等采用，并较早引入 ZFS；OpenBSD 以“默认安全”为纲，坚持代码审计与正确性优先，孕育 OpenSSH、PF、LibreSSL 等安全工具；NetBSD 以极致可移植性立身，代码库刻意分离机器无关与机器相关组件，故常最先支持冷门硬件。（YouTube EP3u8zKO8VTD0，[240.16-554.48]，L2）
- 在许可证哲学上，解说指出 BSD 宽松许可证允许商业专有产品在极少限制下使用与再分发，促成广泛采纳但不保证企业回馈改进；GPL 的 copyleft 模型则催生大规模共享开发生态。BSD 生态因而更小、更保守、更受核心开发者掌控，价值观上重视稳定性、清晰性与长期设计，与 Linux 的快速迭代形成对照。（YouTube EP3u8zKO8VTD0，[605.44-760.4]，L2）
