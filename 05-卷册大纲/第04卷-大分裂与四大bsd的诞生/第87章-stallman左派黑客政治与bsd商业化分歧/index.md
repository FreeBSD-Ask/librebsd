# 第 87 章 Stallman 左派黑客政治与 BSD 商业化分歧

> 〔编号缺口登记〕本章磁盘现存 87.12、87.13、87.14 三节，87.1-87.11 共 11 节暂缺；现存节号系第 04 卷节号跨章连续承接设计（87.12 承接第 86 章末节 86.11），非编号错误。缺口节属新增内容，其设立须主理人确认后由专项处理，不属本轮逐文件整改范围，此处仅作登记说明。

## 要点

- 1990 年代分裂时期黑客社区对 Stallman 政治立场的反应呈现多元图景——BSD 社区内部政治立场分化（部分开发者倾向 BSD 许可证的 “自由市场” 路径，部分认同 copyleft 理念）；OSI 1998 年创立 “作为对 FSF 左派政治的反动” 叙事须辨析；黑客社区政治立场不应简化为 “左派 FSF vs 右派 BSD/OSI” 二元，须按 0 信任原则对照 BSD 邮件列表政治讨论存档与 OSI 创立档案交叉验证
- BSD 分裂的文化叙事由 FreeBSD 阵营（Handbook 官方叙事、Contributors 文章）、NetBSD 阵营（Core Team 决策记录）、OpenBSD 阵营（de Raadt 公开演讲与访谈表述）三方并置构成，须分别对照各自一手档案核验，不得以单一阵营叙事替代整体图景
- 文化比较的辨析需区分 “有依据的文化差异”（如开发模式、治理结构）与 “刻板印象”（如 “BSD 精英主义”、“Linux 混乱”）；前者有助于理解，后者需警惕

## 史观

- 总纲第 19 条——解释学循环是历史认识的根本条件：分裂时期的文化图景须经解释学循环审视，Handbook 官方叙事、Contributors 文章、Core Team 决策记录与 de Raadt 公开演讲各自构成叙事层，须与史实层（提交记录、决策邮件、组织档案）循环往复对读——什么被记录、什么被遗忘，本身就是权力行使
- 总纲第 4 条——分离聚合是永恒规律：分裂不是文化差异的原因，而是文化差异的结果——FreeBSD 的务实、NetBSD 的精英、OpenBSD 的偏执，这些气质在分裂之前就已存在，分裂只是让它们各自找到了自己的容器
- 总纲第 2 条——历史是形式主义化的非存在：三项目的文化是形式主义的产物——谁先占据某个定位，谁就获得了那个定位的话语权，后来者只能选择剩余的位置；每一个标签都在遮蔽更复杂的真相
- 总纲第 20 条——历史地理塑造思想土壤：地理在其中扮演了沉默的塑造者——FreeBSD 在加州的商业土壤中生长，OpenBSD 在卡尔加里的寒冷中被推向偏执的极致，NetBSD 在全球散点中维持着精英的幻觉
- 总纲第 8 条——本体论上各方平等：三者在本体论上平等，但平等不意味着相同
- 章级史观依《一刻哲学》25 条总纲权威表回填（总纲原文出处为第 25 章）；子节史观见 87.12、87.13、87.14 各节史观字段

## 辨析

- 分裂时期黑客社区政治立场的 “左派 vs 右派” 二元叙事在二手文献中流传甚广，但须按 0 信任原则对照 BSD 邮件列表政治讨论存档与 OSI 创立档案交叉验证——BSD 社区与 FSF 的政治分歧更多是许可证策略与商业路径之争，而非系统性左右翼政治对立；OSI 1998 创立 “作为对 FSF 左派政治的反动” 这一叙事主要源自 Raymond 一方表述，须对照 FSF 一方档案与第三方研究者；〔口径统一说明〕章题沿用“左派黑客政治”这一二手叙事框架，正文将其作为被检视对象而非既定结论，本条辨析据此给出“许可证策略与商业路径之争”的限定，章题与辨析的口径在章级统一于“以一手档案检视二手框架”；章题本身与目录名绑定，改动涉文件重命名，须主理人确认后专项处理
- 解释学循环审视的限度——承认叙事的建构性不等于否定史实的可考据性，**bsd_commits.duckdb** 中的 commit 记录、tag 信息、文件引入时间是不可篡改的史实层；解释学循环审视针对的是“叙事层”（如 Handbook“创建者”叙事、Contributors 专节位置）而非“史实层”（如 commit hash、tagger_date）；不得因解释学循环而陷入虚无主义，亦不得因史实可考据而忽视
- 文化比较的边界需明确——文化是动态的，不同时期的文化特征不同；不得以某一时期的文化特征概括整个项目

**要点**：

- Lawrence Teo 的开发者入职路径浓缩了 OpenBSD 的贡献者遴选逻辑：遵“shut up and hack”（1800.24-1813.92）准则多年只发附带补丁的邮件（2004 年修改 MD5 工具、为 IBM 鼠标上报 USB ID），后因 libpcap 与主线脱节且无人认领而独自以约五个工作周完成同步，巨型 diff 一度无人跟进，直至数月后重提才获邀进入开发者私有频道并于 2012 年 5 月获得提交权——身份由持续产出与在任开发者接纳共同决定，而非自荐申请。（BSD Now EP81，[1792.90-1929.90]，L1）[订正：原 [1793.16-1861.10]，2026-09-30 SenseAudio 重转核对]
- Calyptix 的产品形态是 2015 年 OpenBSD 商用可行性的个案证据：面向无 UNIX 经验的微软系管理员提供基于 OpenBSD 的防火墙设备，尽量沿用 base 系统与通用内核（PF、IPsec/iked，LibreSSL 自 2014 年 12 月起生产环境使用，坚持 stock ksh 而不用 bash 使 Shellshock 几无影响），并以全自动更新应对中小机构无力运维的现实；客户覆盖律所、学校、医院、银行乃至 NASCAR 车队与路边广告牌，Teo 以“I'm living proof that it is”（2852.18-2857.62）回应 OpenBSD 是否已可商用。（BSD Now EP81，[2551.84-2857.62]，L1）
- OpenSSH 6.8 显示上游重构与下游发行版同步的摩擦成本：内部代码库化重构使 FreeBSD portable 版既有补丁全部失效、进入 ports 的时点推迟；同期新增 SHA-256 base64 主机指纹并设为默认、UseDNS 默认值由 yes 改为 no、实验性主机密钥轮换与多公钥认证，以及不依赖 OpenSSL/LibreSSL 的构建选项（仅保留 ED25519 与 ChaCha20 等新算法套件）——安全快速迭代与发行版移植节奏之间的张力在 2015 年已清晰可见。（BSD Now EP81，[1036.18-1192.06]，L2）

**史观**：

- 总纲10 动手者创造历史：主持人转述的 OpenBSD 六个月发布节奏（三个月开发、三个月稳定化）与大锁拆解进度（约 220 个系统调用中仅 20 余个脱离 giant lock）呈现技术系统演进的累积形态：SMP 化不依赖一次性蓝图跃进，而由动手者在周期约束下一次次局部解锁累积而成，外界可见的只是每期数十个调用的渐进增量与 long-term 的隐性重排。（BSD Now EP81，[5010.00-5072.28]，L2）
