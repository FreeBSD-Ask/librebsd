- 总纲 2“历史是形式主义化的非存在”——据第 2 章 2.3 节“现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆”，Grimes 的 commit message 作为 1993-06-12 时点的工程记录，其史料价值在于它是当下时点的形式主义化档案，而非“真实 FreeBSD 起源”的客观呈现；commit_hash `9002c02abc587664acb357c6879d8ca08664dd0b` 本身不可篡改，但其在 BSD 史学中被赋予的意义是后续主体重构的结果——同一 commit 在 1993 年是工程动作，在 2026 年是“FreeBSD 起源事件最直接的代码层证据”，这一意义转换本身即形式主义化的非存在。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“UNIX 分裂出各种 BSD，BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离”，Grimes 的首条 commit `9002c02abc587664acb357c6879d8ca08664dd0b`“Initial import, 0.1 + pk 0.2.4-B1”是 386BSD 与 FreeBSD 分离的代码层时间戳证据；但 4.1 节同时指出“各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”——commit `f9b4e354333706f10123fa5b81e9266d96c199e4` 主动承认 Jolitz 与 Berkeley 版权，构成 FreeBSD 与 386BSD/4.4BSD-Lite 在谱系上的“聚合”姿态，分离与聚合在同一 commit 群中并存。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.6 节“开源软件许可证最重要的一条就是开发者无论如何都不负责”，commit `f9b4e354333706f10123fa5b81e9266d96c199e4` 的版权承认表述"This keeps us from violating Berkeley‘s and Bill Jolitz’s copyrights"在本体论上承认 Jolitz 与 Berkeley 的版权，体现 FreeBSD 阵营对 386BSD 与 4.4BSD-Lite 在谱系中的本体论平等地位。但 14.6 节提示“人人都有责任，那就是等于人人都没有责任”——版权承认的 commit message 在法律层保护 FreeBSD 阵营，亦在道德层建构其“尊重先驱”的叙事姿态，二者不可分离。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”，Grimes 的 commit message 是 FreeBSD 起源事件最直接的工程经验记录，优于任何事后回忆或叙事重构；但 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”提示：commit message 作为“外围形式主义”与代码本体具有本体平等——commit_hash 本身不可篡改，但其史料价值依赖史家的释读，释读即形式主义化。
- 总纲 10“动手者创造历史”——14.5 节“文档与代码本体平等”在此获得了最具体的工程呈现：Grimes 的首条 commit f9b4e354333706f10123fa5b81e9266d96c199e4 中，代码变更与 commit message 中对 Jolitz 与 Berkeley 版权的主动承认在本体论上地位平等——commit message 不是代码的附属说明，而是“动手”本身的不可分割组成部分。14.8 节“不说话即死亡”在此意涵明确：若 Grimes 提交代码而不留下 commit message，该 commit 即在社区意义上“死亡”——无人知晓其来源、无人知晓其依据。commit message 的简洁直接不是“无形式主义”，而是 14.1 节“没有多余形式主义的老实人”在工程动作中的具体呈现：承认版权这一形式主义本身是必要的，只是没有多余的形式主义。
- 总纲 13“法律与道德是利益分配”——据第 11 章 11.1 节“任何法律问题都是政治问题，任何政治问题都是利益分配问题”与第 8 章 8.3 节“利益分配是目的，维稳是手段”，commit `f9b4e354333706f10123fa5b81e9266d96c199e4` 的版权承认在法律层是 USL v. BSDi 诉讼背景下 FreeBSD 阵营的自我保护，在道德层是“尊重先驱”的姿态建构，在利益层是 FreeBSD 阵营对 386BSD 谱系的合法汲取。11.1 节提示法律的最大作用不是公平正义而是维稳——Grimes 的版权承认 commit 在 FreeBSD 阵营与 Jolitz 夫妇的张力中起到“维稳”作用，使 fork 后的代码汲取获得合法性。但 14.6 节同时警示“某些声称开源的项目，其开发过程实际上相当封闭”——版权承认不等于开发过程的开放，二者须经分别考察。

**字段 5 史观映射**

- 总纲 2“历史是形式主义化的非存在”——据第 2 章 2.3 节“现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆”与 2.5 节“谁试图诠释历史，谁就在篡改历史。讨论真假无非是在争夺自己的话语权”，Handbook 1.3.1 节载明“the name FreeBSD coined by David Greenman”是 FreeBSD 项目对 1993 年命名事件的官方重构；Greenman 本人公开陈述的缺失使该记载成为 FreeBSD 阵营对命名事件的单方陈述，史家引用时须承认其重构性，不得作为“真实命名过程”的客观呈现。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.2 节“将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，“FreeBSD”名称的创造是 Greenman 个人的偶然选择；若 Greenman 未参与或选择不同名称（如备选的“386BSD 0.5/Interim”），FreeBSD 的身份认同建构将走另一条路。命名不是“必然”而是“偶然”——5.2 节警示“被认定为代表历史合力方向的人，获得了不可质疑的合法性”，Handbook 将命名贡献归于 Greenman 一人，本身即对偶然性的形式主义化重构。
- 总纲 7“理论必须自反”——据第 6 章 6.3 节“真正的理论体系应该是自反的。一个理论越宣称自己怎样，它在实质上就越不怎样，这是一种辩证的自反”与第 27 章 27.2 节“反对得好就不是形式主义”，Handbook 1.3.1 节作为 FreeBSD 项目官方叙事，其自身即形式主义化建构；但 Handbook 通过明确记载命名贡献的归属（Greenman），在形式主义化的同时呈现最低限度的诚实性——这与项目统摄史观的自反姿态同构：承认自身是形式主义，而非伪装超越形式主义。
- 总纲 15“文化即形式主义”——据第 7 章 7.1 节“文化是人类自己强加于自己的形式。文化的一切要素——语言、文字、习俗、礼仪、节日——都是形式主义的建构”，“FreeBSD”名称作为 FreeBSD 项目的文化形式主义建构，将“Free”与“BSD”组合明确标识项目的自由软件属性与 BSD 谱系归属；7.1 节指出“语言和文字在本体论上不可分”，名称一旦确立即成为项目身份认同的不可分割部分——但 7.4 节“文化记忆的虚妄不在于它被重构，而在于它被伪装为不可重构的传统”提示：命名叙事在 Handbook 中被记载后，逐渐固化为“FreeBSD 命名必然如此”的传统，这一固化本身即文化记忆的虚妄。
- 总纲 19“解释学循环与权力-知识共谋”——据第 19 章 19.3 节“什么是‘重要的’历史事件，什么被记录，什么被遗忘，什么被视为‘错误’，什么被视为‘进步’——这些判断背后都有权力的运作”，Greenman 本人公开陈述的缺失与 Handbook 官方叙事的存留，构成解释学循环中的权力不对称：FreeBSD Project 通过 Handbook 掌握了命名事件的“记录权”，而 Greenman 一方的当事人陈述因邮件列表存档可访问性有限而失语。什么被记录、什么被遗忘本身就是权力行使——史家引用时须呈现这一不对称，不得将 Handbook 官方叙事误读为“客观命名过程”。
