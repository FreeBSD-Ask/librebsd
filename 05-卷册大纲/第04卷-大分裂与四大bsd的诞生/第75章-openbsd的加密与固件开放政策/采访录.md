**字段 2 采访摘要**

de Raadt 在 OpenBSD 项目早期（1996-2001 年）通过 <misc@openbsd.org> 邮件列表与项目官方文档持续阐述 OpenBSD 安全文化的核心理念：默认安全（secure by default）、全代码审计（comprehensive code audit）、不背书条款的 ISC 许可证（ISC license without endorsement clause）。de Raadt 的公开陈述强调 OpenBSD 与 NetBSD、FreeBSD 在安全哲学上的根本差异——OpenBSD 将安全作为首要承诺，而非次要目标。OpenBSD FAQ 历史章节载明 OpenBSD 从 NetBSD 1.0 分叉后的安全审计工程：从 1996 年 OpenBSD 1.2 至 2001 年 OpenBSD 2.9，每六个月发布周期内持续进行全代码审计，形成 OpenBSD 独有的安全响应模型。

**字段 5 史观映射**

- 总纲 2 “历史是形式主义化的非存在”——据第 2 章 2.3 节 “现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆” 与 2.5 节 “谁试图诠释历史，谁就在篡改历史。讨论真假无非是在争夺自己的话语权”，OpenBSD FAQ 历史章节与 <misc@openbsd.org> 邮件列表存档对 1996-2001 年安全文化奠基的记载，是 OpenBSD Project 对该时期安全审计工程的官方重构；de Raadt 本人对安全文化奠基的独立长篇公开陈述或采访的具体措辞未见三次复查命中，使 FAQ 与邮件列表存档成为 OpenBSD 阵营对安全文化起源的单方陈述。史家引用时须承认其重构性——“默认安全” “全代码审计” “ISC 许可证” 三大核心理念的具体形成过程、时点、决策语境均无独立档案可证，不得作为 “真实 OpenBSD 安全文化起源” 的客观呈现。
- 总纲 4 “分离聚合是永恒规律”——据第 4 章 4.1 节 “BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离；而各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”，OpenBSD 从 NetBSD 1.0 分叉是 BSD 谱系中 “分离” 环节的代码层证据，而安全文化的奠基则是 OpenBSD 与 NetBSD 在安全哲学层面的二次分离——NetBSD 采取 “按需响应” 安全模型，OpenBSD 采取 “默认安全 + 全代码审计” 模型，二者在 fork 后逐渐分道。但 4.1 节 “分合循环，永无止息” 提示：OpenBSD 全代码审计的对象仍是 NetBSD 1.0 衍生的代码基础，分离与聚合在同一审计工程中并存——OpenBSD 通过审计 NetBSD 代码而确立自身安全身份，这一辩证关系不可简化为 “OpenBSD 安全文化优于 NetBSD” 的线性叙事。
- 总纲 5 “没有必然性，只有偶然性”——据第 5 章 5.1 节 “世界上没有必然性，只有偶然性” 与 5.2 节 “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，OpenBSD 安全文化的奠基不是 “安全必然成为操作系统首要承诺” 的展开，而是 de Raadt 被逐 NetBSD、fork OpenBSD、选择安全审计作为项目差异化定位等一系列偶然条件交汇的具体结果；若 de Raadt 未被逐出 NetBSD，或选择性能、可移植性、商业化等其他方向作为 OpenBSD 的差异化定位，OpenBSD 独有的安全文化可能不会在 1996-2001 年形成。5.2 节警示 “被认定为代表历史合力方向的人，获得了不可质疑的合法性，这实质上是一种变相的君权神授”——史家引用 FAQ 记载时不可反向将其神化为 “OpenBSD 必然成为安全操作系统” 的证据，亦不可将 de Raadt 神化为 “安全哲学的先知”。
- 总纲 6 “和解优于斗争”——据第 6 章 6.2 节 “唯一的事情只有和解与接纳，与自己和解，与自己接纳” 与 6.7 节 “真正的和解不是打倒敌人，而是认识到敌人本身并不存在——存在的是时间，是流变，是不可避免的分离”，de Raadt 通过安全文化的奠基将 OpenBSD 与 NetBSD 的差异从 “被逐事件” 的治理冲突转化为 “安全哲学” 的技术分歧，这一转化本身具有双重性：一方面是 de Raadt 与自身被逐经历的 “和解”——通过证明 OpenBSD 路径的正当性来消解被逐的创伤；另一方面是未达成和解的延续——安全文化的差异化建构本身就是对 NetBSD 治理正当性的持续质疑。6.7 节提示 “真正的敌人是时间”——de Raadt 与 NetBSD Core Team 的冲突若不能回到时间的维度来理解，就只是偷懒；史家审视 OpenBSD 安全文化奠基时不可强行选择 “安全文化是技术进步” 或 “安全文化是报复 NetBSD” 任一方叙事，而应承认其双重性本身即是分离聚合规律（总纲 4）的时间性呈现。
- 总纲 8 “本体论上各方平等”——据第 14 章 14.5 节 “文档与代码本体平等” 与 14.7 节 “声称去中心化者，恰恰是试图建立新的中心的人”，de Raadt 的 OpenBSD 阵营安全文化自述与 NetBSD、FreeBSD 阵营对同期安全响应模型的陈述在本体论上地位平等；14.7 节的 “去中心化悖论” 提示：OpenBSD 以 “默认安全” 作为去中心化的安全承诺，但 de Raadt 作为 OpenBSD 项目终身领导形成新的中心——安全审计团队的权威、commit 权限的集中、errata 发布的最终决定权，皆以 “安全” 为名行使中心化权力。史家引用时须保持 OpenBSD 与 NetBSD、FreeBSD 三方发声空间的对称，不得因 OpenBSD 安全文化的差异化定位而将其天然正当化，亦不得因 de Raadt 的终身领导身份而将其安全哲学判定为 “独裁产物”——后者是道德化的简化。
- 总纲 9 “经验优先”——据第 14 章 14.2 节 “真正的问题不在于技术发展的程度，而在于是否动手” 与 14.5 节 “真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”，de Raadt 的邮件列表公开陈述与 FAQ 历史章节是 OpenBSD 安全文化奠基最直接的工程经验记录，优于任何事后回忆或叙事重构；全代码审计工程是 de Raadt 与 OpenBSD 核心开发者亲手逐行审计 NetBSD 1.0 衍生代码的具身经验产物。但 14.5 节 “这些代码没有个几年就完全没用了” 提示：安全文化作为 “外围形式主义” 与代码本体具有本体平等——“默认安全” “全代码审计” 等标语的形式主义化存留，与具体漏洞修复的 commit 历史共同构成 OpenBSD 安全文化的档案，二者不可偏废。
- 总纲 10“动手者创造历史”——14.5 节“文档与代码本体平等”在 OpenBSD 全代码审计工程中获得了最激进的实践：审计将每一行代码——无论出自核心开发者还是外围贡献者——视为同等值得审视的对象，这正是本体论平等在工程动作中的具体化。6.6 节“度人难度己更难”为审视 de Raadt 的终身领导地位提供了新的角度：全代码审计不是“审计别人”的权力行使，而是“审计自己代码”的自反性实践——审计他人代码易，审计自己参与编写的代码难。但 14.2 节“问题始终在于是否有人去做”不因此失效：从 1996 年 OpenBSD 1.2 至 2001 年 OpenBSD 2.9，每六个月发布周期内持续进行的代码审计，是“没有停下”这一具体行动的时间性呈现——不是“安全精英 vs 普通开发者”的阶级范畴，而是“动手”本身跨越了身份差异。
- 总纲 13 “法律与道德是利益分配”——据第 11 章 11.1 节 “任何法律问题都是政治问题，任何政治问题都是利益分配问题” 与 11.5 节 “他把分配问题转成了道德问题。任何道德问题本质上是利益问题”，OpenBSD 选择 ISC 许可证（不背书条款）而非 BSD 许可证或 GPL，本质上是 BSD 谱系内部利益分配的政治产物——ISC 许可证的 “不背书” 条款剥夺了贡献者的署名权诉求，将 BSD 传统中的 “致谢” 形式主义化重新分配为 OpenBSD 项目的中心化控制。11.5 节提示 “神圣化和道德化自己只会反噬自身”——OpenBSD 通过 “默认安全” 的道德化叙事建构自身 “安全先锋” 形象，将 BSD 谱系内部的安全响应差异转化为 “OpenBSD 道德优先” 的叙事，本身即利益分配的政治产物。史家引用时须区分 “安全工程”（技术层）与 “安全道德叙事”（利益分配层）两个层次。
- 总纲 15 “文化即形式主义”——据第 7 章 7.1 节 “文化是人类自己强加于自己的形式。文化的一切要素——语言、文字、习俗、礼仪、节日——都是形式主义的建构” 与 7.4 节 “文化记忆的虚妄不在于它被重构，而在于它被伪装为不可重构的传统”，OpenBSD 安全文化作为 BSD 谱系中的文化形式主义建构，将 “默认安全” “全代码审计” “ISC 许可证” 三大要素从具体工程实践固化为项目身份认同的不可分割部分——7.1 节 “语言和文字在本体论上不可分” 在此体现为 “secure by default” 标语与 OpenBSD 项目身份的本体论绑定。但 7.4 节提示 “文化记忆的虚妄不在于它被重构，而在于它被伪装为不可重构的传统”——OpenBSD 安全文化在 FAQ 与邮件列表的持续记载中逐渐固化为 “OpenBSD 历史必然如此” 的传统，这一固化本身即文化记忆的虚妄。史家引用时须承认安全文化的形式主义性质，不得将其伪装为 “客观技术演进”。
- 总纲 19 “解释学循环与权力-知识共谋”——据第 19 章 19.2 节 “不同文化背景、不同技术背景、不同时代背景的读者，对同一史事的前理解截然不同” 与 19.3 节 “什么是‘重要的’历史事件，什么被记录，什么被遗忘，什么被视为‘错误’，什么被视为‘进步’——这些判断背后都有权力的运作”，de Raadt 的 OpenBSD 阵营以 “安全是首要承诺” 为前理解，NetBSD/FreeBSD 阵营以 “安全是次要目标，按需响应” 为前理解，构成解释学循环中的双方前理解冲突；OpenBSD FAQ 与 <misc@openbsd.org> 邮件列表通过持续记载掌握了 “OpenBSD 安全文化起源” 的 “记录权”——什么被记录为 “OpenBSD 安全文化的奠基事件”、什么被遗忘为 “NetBSD 同期的安全响应工作”，本身就是权力行使。史家引用时须呈现这一解释学循环中的前理解差异，不得将 OpenBSD 安全文化叙事误读为 “客观 BSD 安全史”。
- 总纲 23 “一切历史写作都是基于哲学设定的历史小说”——据第 23 章 23.1 节 “一切历史写作都是基于某种哲学设定的历史小说” 与 23.2 节 “史家以为自己在书写历史，但历史人物可能正在藉着史家书写他们自己的故事”，OpenBSD FAQ 历史章节基于 “OpenBSD 安全文化起源正当性” 的哲学设定，本身即一部历史小说；de Raadt 藉着 FAQ 与邮件列表公开陈述书写自身在 OpenBSD 安全文化奠基中的核心地位，构成 23.2 节所述 “作者与人物的权力倒转”——de Raadt 以为在记录 OpenBSD 安全文化历史，但 OpenBSD 安全文化历史可能正在藉着 de Raadt 的公开陈述书写强化其作为 “安全哲学奠基者” 的文化形象。史家引用时须承认这一自反性——当事人陈述不是安全文化起源的客观呈现，而是历史小说中的一段对白。

- 总纲 2 “历史是形式主义化的非存在”——据第 2 章 2.3 节 “现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆” 与 2.5 节 “谁试图诠释历史，谁就在篡改历史。讨论真假无非是在争夺自己的话语权”，OpenBSD errata 页面对 OpenBSD 2.6/2.7/2.8/2.9 时期 OpenSSH、isakmpd、USER_LDT 漏洞群的响应记载，是 OpenBSD Project 对该时期安全响应工程的官方重构；Beck 本人对安全响应工程的独立长篇公开陈述或采访的具体措辞未见三次复查命中，使 errata 页面与 commit 历史成为 OpenBSD 阵营对 Beck 贡献的单方陈述。史家引用时须承认其重构性——同一漏洞修复 commit 在 1999-2001 年是工程动作，在 2026 年是 “OpenBSD 安全响应工程成熟” 的代码层证据，这一意义转换本身即形式主义化的非存在。
- 总纲 5 “没有必然性，只有偶然性”——据第 5 章 5.1 节 “世界上没有必然性，只有偶然性” 与 5.2 节 “那种认为‘张三不上李四也会上’的观点，无视了世界上没有必然性只有偶然性这一事实”，OpenSSH 早期漏洞、isakmpd 漏洞、USER_LDT 漏洞的发现时点与严重程度均为偶然；若这些漏洞未在 OpenBSD 2.6/2.7/2.8/2.9 周期内被 Beck 等安全响应团队成员发现与修复，OpenBSD errata 机制的成熟路径将不同。5.2 节警示 “被认定为代表历史合力方向的人，获得了不可质疑的合法性”——史家引用 errata 页面记载时不可反向将 Beck 神化为 “OpenBSD 安全响应必然成熟” 的代言人，亦不可将 OpenSSH 漏洞群的神化发现过程视为 “OpenBSD 必然成为安全操作系统” 的证据——漏洞发现是偶然，修复响应是具体决策。
- 总纲 8 “本体论上各方平等”——据第 14 章 14.5 节 “文档与代码本体平等” 与 14.7 节 “声称去中心化者，恰恰是试图建立新的中心的人”，Beck 的 OpenBSD 安全响应团队立场与 FreeBSD 安全响应团队（FreeBSD Security Team）、NetBSD Security Officer 的立场在本体论上地位平等；14.7 节的 “去中心化悖论” 提示：OpenBSD 安全响应团队以 “默认安全” 为名形成新的中心——errata 发布的最终决定权、漏洞严重性评级的标准制定权、修复时机的裁定权，皆以 “安全” 为名集中行使。史家引用时须保持 OpenBSD 与 FreeBSD、NetBSD 三方安全响应团队发声空间的对称，不得因 OpenBSD errata 机制的差异化定位而将其天然正当化，亦不得因 Beck 的核心开发者身份而将其他 BSD 项目的安全响应工作判定为 “落后”——后者是道德化的简化。
- 总纲 9 “经验优先”——据第 14 章 14.2 节 “真正的问题不在于技术发展的程度，而在于是否动手” 与 14.5 节 “真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”，Beck 的 commit 历史是 OpenBSD 安全响应工程最直接的工程经验记录，优于任何事后回忆或叙事重构；OpenSSH、isakmpd、USER_LDT 漏洞的修复 commit 是 Beck 与安全响应团队亲手定位、分析、修补的具身经验产物。但 14.5 节 “这些代码没有个几年就完全没用了” 提示：漏洞修复 commit 作为 “外围形式主义” 与 errata 页面的叙事描述具有本体平等——commit_hash 本身不可篡改，但其在 BSD 史学中被赋予的 “OpenBSD 安全响应工程成熟” 意义是后续主体重构的结果，释读即形式主义化。
- 总纲 10“动手者创造历史”——14.8 节“不说话即死亡”在安全响应领域获得了最紧迫的意涵：漏洞本身即是一种“沉默”——未公开的漏洞在社区意义上“不存在”，而 errata 的发布是将这一“沉默”打破的“说话”行为。Beck 修复 OpenSSH、isakmpd、USER_LDT 漏洞的 commit 与 errata 发布，构成 14.8 节意义上的“说话”——使漏洞从“不存在”走向“存在”的“动手”。6.2 节“和解优于斗争”在此具体化：安全响应不是“消灭漏洞”的斗争，而是与漏洞“和解”——承认漏洞的不可避免性，通过补丁与 errata 实现临时接纳。但 14.5 节“这些代码没有个几年就完全没用了”提示：errata 机制本身是一种形式主义化的临时应对，不是永恒解决方案——这一观察不作悲观判定，而作对人类有限性的诚实承认。
- 总纲 19 “解释学循环与权力-知识共谋”——据第 19 章 19.2 节 “我们往往预设了读者与作者享有相同的‘前理解’与‘前意识’” 与 19.3 节 “什么是‘重要的’历史事件，什么被记录，什么被遗忘，什么被视为‘错误’，什么被视为‘进步’——这些判断背后都有权力的运作”，OpenBSD 阵营以 “漏洞必须被全代码审计发现” 为前理解，FreeBSD/NetBSD 阵营以 “漏洞按需响应即可” 为前理解，构成解释学循环中的双方前理解冲突；OpenBSD errata 页面通过持续记载掌握了 “OpenBSD 安全响应工程” 的 “记录权”——什么被记录为 “OpenBSD 主动审计发现的漏洞”、什么被遗忘为 “其他 BSD 同期也修复但未被记载的漏洞”，本身就是权力行使。Beck 作为安全响应团队成员的具体决策（如漏洞披露时机）无独立档案可证，这一档案缺失本身就是权力-知识共谋的具体化——errata 页面的 “客观漏洞列表” 形式遮蔽了安全响应团队的内部决策过程。史家引用时须呈现这一档案不对称，不得将 errata 页面误读为 “客观漏洞史”。
- 总纲 22 “知识注定过时”——据第 22 章 22.1 节 “今天书写的技术史，可能在出版之日就已过时” 与 22.3 节 “数字信息的易逝性——链接失效、服务关停、格式淘汰——使历史保存面临新的威胁”，OpenBSD 2.6/2.7/2.8/2.9 时期的 OpenSSH、isakmpd、USER_LDT 漏洞群在今天看来已过时——这些漏洞的具体技术细节、利用方式、修复方法在今天的技术语境下已无直接意义，但其作为 OpenBSD errata 机制成熟路径的史料价值并未过时。22.3 节提示数字档案既是机遇也是威胁——errata 页面的持续存留与 <misc@openbsd.org> 邮件列表原始帖的存档可访问性有限，构成数字档案威胁的具体案例；22.4 节 “在互联网上最孤独的是，你发现自己的疑惑别人早在几年前、几十年前就提出过，但是，没有人解决，甚至无人回复” 亦提示：OpenBSD errata 页面记载的已修复漏洞只是冰山一角，无数被提出但从未被回应的安全问题构成 “沉默的档案”——它们不是历史的空白，而是历史本身。
