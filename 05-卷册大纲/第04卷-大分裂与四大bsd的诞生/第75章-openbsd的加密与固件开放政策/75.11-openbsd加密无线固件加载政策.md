## 75.11.5 fw_update(8) 机制与固件许可证分流

  **要点**：OpenBSD 对固件许可证持严格立场——厂商为节省成本不再在芯片内固化固件、改由操作系统加载后，固件分发许可证冲突显现；OpenBSD 把可自由再分发的固件纳入 base 系统，许可证不兼容的固件经 `fw_update(8)` 从端口单独分发，多数为 WiFi、显卡与 Intel 芯片组（afresh1, 2024）。
  
**史料**：afresh1《Why rewrite fw_update(8)?》BSDCan 2024 演讲（ref 62）；OpenBSD 固件政策页 `policy.html` ［A］
  
**史观**：总纲第 15 条——文化即形式主义：固件许可证分流是 OpenBSD 源码开放文化对厂商成本考量的制度回应
  
**辨析**：OpenBSD 的严格许可证立场与硬件厂商的省钱考量构成持续冲突——rtwn(4)/urtwn(4) 固件经 kevlo 联系 Realtek 去除专利条款后移入 base，是许可证谈判成功的少数案例；多数不兼容固件仍须经 `fw_update(8)` 分发（afresh1, 2024）。
  
**文献**：afresh1, 2024《Why rewrite fw_update(8)?》BSDCan 2024 演讲

**要点**：

- OpenBGPD 的缘起：BGP 即边界网关协议，依 RFC 定义，用于 ISP 之间互宣网络可达性——各 ISP 向对端宣告自有网络与客户网络，形成巨型对等 mesh，互联网路由表由此建立。当事人此前用当时人人使用的 Zebra，其 KAME 系代码有趣但问题多：事件模型错误、忙时会丢弃 BGP 会话、越忙越糟直至离线；他到处修改以提高可靠性，勉强可用但从未满意。某天重读 RFC 觉得并不复杂，受够之后坐下动手实现会话处理，九天后即有自认为完整可用的会话引擎（后来发现若干 bug 但基础正确）；2004 年末致信 Claudio Jeker 等相关者；此后项目稳步成长，如今已有相当多站点使用，通常比其他实现更快更可靠。（BSDTalk EP23，[333.28-490.80]，L1）
- BGP 会话保护：BGP 会话一旦丢失即告离线，会话是天然攻击面，保护至关重要而多数运维者毫无作为；TCP MD5 签名对任务而言可用但不优秀、聊胜于无；其他实现从不支持，因为问题的另一半在内核、只在应用层处理便失去意义。OpenBSD 很早实现了健壮的 TCP MD5，另提供他处不易获得的 IPsec，并自称是唯一以 isakmpd 做动态密钥 IPsec 的实现——其场景下零配置：拷贝密钥、启动 isakmpd，bgpd 自行完成其余协商。（BSDTalk EP23，[501.80-561.84]，L1）
- 随机化哲学：对 TCP、IP 及其上层协议，寻找 RFC 要求插入时间戳等半静态信息之处并验证能否以完全随机值替代——如完全随机的临时源端口（OpenBSD 随机选取，据其所知其他系统均为单调递增）；当年即知是好主意却无法证明，七八年后 Paul Watson 于 2004 年发表针对长生命周期 TCP 会话的注入攻击研究，随机源端口使此类攻击难得多，七年后才终于明白当初为何那样做。进程 ID、IP ID、初始序列号、DNS 查询 ID 皆正确随机化。所有需要随机数的子系统调用 arc4random 从内核熵池取数，众多来源使取数时机本身不可预测，即便熵池被单调计数器稀释仍能保持良好随机性。安全始终在开发者的头脑中：寻找可随机化之处、三思暴露什么——例如默认 Apache 1.3 暴露版本指纹，他们不删除该信息而以随机值替代。（BSDTalk EP23，[572.24-816.16]，L1）
- blob 批评（3.9 发布主题）：blob 即二进制大对象——硬件厂商隐瞒硬件 API 实属愚蠢，以太网芯片数十种、技术早已无秘密；厂商不给文档只给链接进内核的目标文件（NVIDIA 在此恶名昭著）。后果有三：内容不可知、可能藏有恶意；绑死厂商愿支持的架构，x86 目标文件无法用于 AMD64、SPARC64 或 alpha；厂商对系统影响力过大，且在内核空间运行不可信代码使安全问题遍地。这与二十年前伯克利清除 AT&T 专有代码是同一本质问题——依赖大公司，而公司利益很少与自由社会一致；为 OpenBSD 维护 blob 不可接受，直接给出文档即可；此前争取无线芯片组文档的成功是可行先例。（BSDTalk EP23，[913.68-1058.02]，L1）
- PF 取代 IPF 的始末：IPF 作者以所谓澄清为名修改许可证（当事人认为原措辞本就意在让人误读），最终明确禁止发布修改版——荒谬之处在于 IPF 问题不断、OpenBSD 修复过其中一些，许可证却禁止发布修复；意识到后一天之内 IPF 即被移出树。许可证只是压垮骆驼的最后一根稻草，此前对 IPF 早已不满；Daniel Hartmeier 随之起手编写 PF，3.0 首个随带 PF 的发布虽功能不及 IPF 全、大规模部署有问题，但已相当可用；长期看，其他曾用 IPF 的系统纷纷导入 PF，大量 IPF 用户在其他操作系统上也转向 PF，如今 PF 强大得多、其他系统基本皆已改用 PF。（BSDTalk EP23，[1059.82-1167.26]，L1）
- OpenCON 是首个专门面向 OpenBSD 的会议，2004 年由意大利威尼斯本地人首创；其成长轨迹清晰——2004 年九场报告中仅三场出自开发者、到场发言的开发者仅 Henning Brauer 一人，2005 年九场中六场出自七位开发者，2006 年十四场报告出自十位开发者，多数报告已由官方开发者承担；会议前一周在里斯本举行 mini hackathon，开发者顺势短途飞抵威尼斯；2006 年 12 月 2 日至 3 日举行、会议完全免费，首日晚宴兼作 OpenBSD 十周年派对仅收象征费用。（BSDTalk EP76，[109.96-235.20]，L1）
- 会议后勤与收入结构：场地 2004 年设于威尼斯技术门户 VEGA，2005 年迁至潟湖小岛——水城交通全赖船只且船费高昂，把会议服务运上小岛近乎历险，2006 年移至机场附近才恢复便利；赞助方包括欧洲 OpenBSD 支持商 KD85.com、CD 与海报 T 恤销售商、本地互联网服务提供商及 O'Reilly，组委会全部志愿工作；会上销售 CD-ROM 与 T 恤、海报免费发放，CD-ROM 销售是 OpenBSD 项目除捐款外的主要收入来源。（BSDTalk EP76，[271.08-432.20]，L1）
- 当事人从 Linux 转向 OpenBSD 的运维逻辑：其公司长期维护 Unix 系统，在 Linux 热潮期间采用 Linux 却屡遭黑客入侵，遂先把 DNS 服务器等关键平台迁至 OpenBSD，数年后全面铺开；公司承接巴塞尔公立学校、图书馆与动物园的 IT 服务，直接用户数千——仅公立学校系统即约一万名学生、三千五百名教师、每年约一千人进出；文件服务与邮件服务均由 OpenBSD 承载，其称许 ports 与 packages 体系真正可用，软件维护比 Linux 容易。（BSDTalk EP76，[444.00-633.04]，L1）
- 大规模部署的运维纪律：全部生产机坚持 stable 分支，以保证各服务器软件状态一致、可管理——跑 current 技术上可行但会造成各机版本漂移，商业环境不可接受；公司自备构建机按需构建发行版与软件包，全部生产机跟随 OpenBSD 发布周期每半年统一升级一次；个人笔记本与家用机则运行 current，以致其对 4.0 新特性已无新鲜感。（BSDTalk EP76，[684.38-742.68]，L1）
- 当事人的技术贡献清单：已在 OpenBSD 落地 NMEA 支持（GPS 设备）与时间信号站接收器支持，正扩展两者功能；维护 PostgreSQL、OpenLDAP、Samba 等多个 ports。（BSDTalk EP76，[83.10-103.50]，L1）
- 进行中的合作项目瞄准 OpenBSD 的结构性短板——缺少现代中央用户数据库：YP 时代之后系统无此能力，公立学校系统万级用户的账号管理亟需集中化；当事人与 Claudio Jeker、Chris Kuethe 合作推进，目标是让 Samba 等服务可对接 LDAP 式中央认证，免除在每台服务器本地建户。（BSDTalk EP76，[603.72-684.38]，L1）
- 固件再分发斗争的立场陈述：呼吁用户购买 CD-ROM 支持项目，并向拒不授予二进制固件再分发许可的硬件厂商施压；其诉求刻意设为最低限度——不要求无线设备固件的源代码，只要求把二进制固件放入 CD-ROM 随发行版再分发的权利；近期与厂商的相关谈判相当艰难，undeadly.org 是跟踪其动向的公开窗口。（BSDTalk EP76，[779.80-830.88]，L1）

**史观**：

- 总纲13 法律与道德是利益分配：IPF 许可证事件是法律文本作为利益分配工具的微观标本：作者以所谓澄清之名调整措辞，修改词序之间软件能否被修复、能否随系统发布即被重新划定——一条许可证条款的改写直接决定了一条防火墙代码在树中的存亡，技术问题最终由法律文本的措辞裁决。（BSDTalk EP23，[1077.06-1112.62]，L1）
- 总纲9 经验优先：当事人全部技术判断源自运维经验而非理论宣言：被黑客入侵的切肤之痛促成关键平台迁移，万级用户的真实管理需求催生中央用户库项目，半年升级节奏决定 stable 策略——平台选择的标准被表述为朴素的一个基本可用且安全的系统。（BSDTalk EP76，[444.00-526.04]，L1）
- 总纲3 不存在进步，只有权力再分配：固件再分发之争的实质是硬件厂商与开源社区之间对固件控制权的再分配：OpenBSD 明确不求固件源码、只求二进制再分发权，把诉求压缩到最低限度以换取厂商让步的可能——这一谈判姿态本身就是权力边界协商的操作化表达。（BSDTalk EP76，[805.88-820.12]，L1）
