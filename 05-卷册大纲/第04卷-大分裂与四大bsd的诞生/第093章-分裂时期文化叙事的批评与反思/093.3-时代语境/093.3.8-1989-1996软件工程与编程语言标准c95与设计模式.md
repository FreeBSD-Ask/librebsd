# 093.3.8 1989-1996 软件工程与编程语言标准：C95 与设计模式

  **要点**：**1989-1996 年** 软件工程与编程语言标准——C95（ISO/IEC 9899:1990 Amendment 1）、设计模式（Gamma/Helm/Johnson/Vlissides《设计模式》**1994**）、CORBA、UML；编程语言与软件工程进步塑造 BSD 代码风格
  
**史料**：C95 标准档案；Gamma 等人《设计模式》**1994**；CORBA 与 UML 标准［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档/L5 二手研究〕
  
**史观**：总纲第 6 条——形式主义膨胀。项目史观总纲第 1 章 1.5 节载 “文明的一切制度、习俗、技术、法律，都是形式主义的累积与层叠”——BSD 选择 C 语言与 Unix 风格是形式主义层叠的一例，“付出技术选择的代价但保持简洁” 是形式主义化的两面（1.6 节 “形式主义可以促进社会发展，形式主义也可以毁灭社会”）；须自反（总纲第 7 条 “理论必须自反”）：“BSD 必然选择 C 语言” 的归因须对照具体工程决策（如 C 语言可移植性、性能、生态成熟度）而非笼统断言
  
**辨析**：编程语言标准对 BSD 的影响——C95（ISO/IEC 9899:1990 Amendment 1）主要新增宽字符与多字节字符支持，对 BSD 代码的具体影响在国际化/本地化模块（如 setlocale、wchar_t 类型）；设计模式（Gamma 等人 1994《设计模式》）对 BSD 代码风格的影响有限，BSD 代码长期保持 Unix 风格（简短函数、文本配置）而非面向对象设计模式 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
