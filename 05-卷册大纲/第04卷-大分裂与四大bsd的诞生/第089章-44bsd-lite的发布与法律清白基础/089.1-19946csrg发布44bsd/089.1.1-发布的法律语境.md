# 089.1.1 发布的法律语境

  **要点**：**1994.6** 4.4BSD-Lite 发布的法律背景是 USL v. BSDi 诉讼和解——**1994 年 2 月 4 日** USL v. BSDi（BSDI 公司案）达成庭外和解（Rob Kolstad 1994-02-07 公告邮件确认）；USL v. UC Berkeley（加州大学案）为 1994 年 1 月框架和解[考据完成：2026-08-04 权威：USL v. Regents 1994-01 框架和解 vs USL v. BSDI 1994-02-04 正式和解（Rob Kolstad 公告）]，要求 Net/2 中删除 3 个 System V 共享内存/信号量相关文件、约 70 个文件添加 USL 版权声明（仍可自由再分发），CSRG 发布不含争议代码的 4.4BSD-Lite，Novell 承诺不起诉任何基于 4.4BSD-Lite 的组织或个人；4.4BSD-Lite 是法律和解产物。USL v. BSDi 和解协议关键条款如下：

| 条款 | 具体内容 | 法律效果 |
| -- | ------ | ------ |
| 完全删除文件 | 3 个 System V 共享内存/信号量相关文件 | 彻底消除争议代码 |
| 添加版权声明 | 约 70 个文件添加 USL 版权声明 | 文件本身为伯克利代码，仍可自由再分发 |
| Novell 不起诉承诺 | 不起诉任何基于 4.4BSD-Lite 的组织或个人 | 法律洁净保证 |
| 代码总量 | Net/2 共 18,000 文件中仅 3 个被完全删除 | 法律影响范围有限 |

**史料**：USL v. BSDi 和解协议 1994.1；4.4BSD-Lite Release Notes 1994.6；McKusick 1999《Twenty Years of Berkeley Unix》当事人一手叙述；CSRG 内部讨论邮件存档 ［A］；bsd_commits.duckdb 查询 L3.6.1 显示：含 license/copyright/patent/BSD 关键词的 commit 时间分布呈持续增长趋势——1992 年仅 3 commits/2 位贡献者，1993 年升至 1,719 commits/45 位贡献者，1994 年（USL 诉讼和解年）3,005 commits/62 位贡献者，1995 年（4.4BSD-Lite2 发布年）4,055 commits/95 位贡献者，1996 年 6,473 commits/149 位贡献者；1994-1996 年 license/copyright/patent/BSD 关键词 commit 量与贡献者数持续增长，反映 USL 诉讼和解后 BSD 阵营对许可证与版权议题的关注度提升，4.4BSD-Lite 的法律洁净催生了大量与许可证相关的代码提交（如版权声明添加、许可证条款更新、BSD 许可证标准化等）

**史观**：总纲第 13 条——法律与道德是利益分配：法律结构（和解协议）直接决定技术内容（4.4BSD-Lite 的代码组成）

**辨析**：删除代码的具体范围需准确区分——经 McKusick 当事人一手记载，Net/2 共 18,000 文件中仅 3 个文件被完全删除（System V 共享内存/信号量相关）、约 70 个文件添加 USL 版权声明（文件本身为伯克利代码且可自由再分发）；“75% 源文件需重写或删除” 说法无一手来源支持，属夸大叙事；【0 信任原则·关键词匹配可能误报】L3.6.1 的关键词匹配基于 message_subject LIKE ‘%license%’ OR ’%copyright%’ OR ‘%patent%’ OR ’%BSD%’，LIKE 默认大小写不敏感，可能将包含 “BSD” 一词但与许可证无关的 commit（如 “BSDCon” 会议相关、含 “BSD” 项目名但无许可证内容的 commit）误报为许可证相关 commit，1994-1996 年的 3,005-6,473 commits 量级须结合手动抽样核实关键词匹配精度；【0 信任原则·commit 量不等于质量】L3.6.1 的 license/copyright 关键词 commit 量增长反映开发者对许可证议题的关注度但不等于许可证清理工作的实际质量，部分 commit 可能仅是版权声明格式微调而非实质性许可证变更；【0 信任原则·CVS-to-Git 迁移风险】BSD 4 大 src 仓库中 netbsd-src 与 openbsd-src 均为 CVS 主仓的 GitHub 镜像，CVS-to-Git 转换可能重写 message_subject 字段，1994-1996 年关键词 commit 量基线须与各项目官方档案交叉验证
