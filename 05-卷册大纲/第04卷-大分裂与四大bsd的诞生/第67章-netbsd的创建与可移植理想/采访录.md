**字段 5 史观映射**

- 总纲 2“历史是形式主义化的非存在”——据第 2 章 2.3 节“现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆”，NetBSD 官方历史页面将 Demetriou 列为四位共同创始人之一，是 NetBSD Project 对 1993 年项目起源事件的官方重构；Demetriou 本人对项目起源的独立公开陈述未见三次复查命中，使官方页面记载成为 NetBSD 阵营对起源事件的单方陈述。史家引用时须承认其重构性，不得作为“真实 NetBSD 起源”的客观呈现。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离”，Demetriou 的 cgd 账号在 1993-03-21T09:45:37Z 提交“initial import of 386bsd-0.1 sources”（commit_hash `0d110d127c41d7aeb2b1bfdc71964c5a496eabf9`），是 NetBSD 从 386BSD 分离的代码层时间戳证据；该 commit 早于 FreeBSD 仓库首条 commit（1993-06-12）约三个月，证实 BSD 在 PC 平台的分离不是单一事件，而是多线并发的分离聚合过程。4.1 节“分合循环，永无止息”提示：NetBSD fork 后仍持续吸纳 386BSD 与 4.4BSD-Lite 的代码，分离与聚合在同一 commit 群中并存。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.1 节“世界上没有必然性，只有偶然性”与 5.2 节“那种认为‘张三不上李四也会上’的观点，无视了世界上没有必然性只有偶然性这一事实”，NetBSD 早于 FreeBSD 三个月 fork 是偶然；若 386BSD 补丁质量问题未在 1993 年初激化，或 Demetriou、de Raadt、Glass、Hannum 四人未在此时达成 fork 共识，NetBSD 可能不会在 1993 年 3 月诞生。5.2 节警示“被认定为代表历史合力方向的人，获得了不可质疑的合法性，这实质上是一种变相的君权神授”——史家引用官方页面“四位共同创始人”记载时，不可反向将其神化为“NetBSD 必然诞生”的证据。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”，NetBSD 官方历史页面记载的 Demetriou 创始人身份与 FreeBSD Handbook 1.3.1 节记载的 FreeBSD 创始团队在本体论上地位平等；14.7 节的“去中心化悖论”提示：NetBSD 四位创始人形成 Core Team 这一新中心，与 Jolitz 夫妇的“一人一图”中心形成对称——两个中心都声称代表 BSD 在 PC 平台的正统，史家引用时须保持双方发声空间的对称。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”，Demetriou 的 cgd commit 是 NetBSD 起源事件最直接的工程经验记录，优于任何事后回忆或叙事重构；但 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”提示：commit message 作为“外围形式主义”与代码本体具有本体平等——commit_hash 本身不可篡改，但其史料价值依赖史家的释读，释读即形式主义化。
- 总纲 10“动手者创造历史”——14.2 节“即使是复制粘贴，如此简单的事情也罕有人去做”为审视 Demetriou 导入源码的 commit 行为提供了具体角度：在 386BSD patchkit 积压的条件下，“导入源码”这一看似简单的操作本身即罕有人去做，Demetriou 的 commit 是这一“罕有人去做”的具体填补。但 14.4 节“FreeBSD 是少数人的选择，是‘百分之一的生活’”提示：NetBSD 作为可移植性理想的载体，其本身即“百分之一”的选择——fork 不是“可移植性必然胜利”的展开，而是少数人在补丁质量问题激化时做出的偶然回应。14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”在 NetBSD 案例中具体化：NetBSD Core Team 形成后的可移植性理想声称开放，但 Core Team 本身即是新的中心——这一观察不作道德判定，而作结构性呈现。

**字段 5 史观映射**

- 总纲 2“历史是形式主义化的非存在”——据第 2 章 2.3 节“现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆”与 2.5 节“谁试图诠释历史，谁就在篡改历史。讨论真假无非是在争夺自己的话语权”，NetBSD 官方历史页面将 Hannum 列为四位共同创始人之一，是 NetBSD Project 对 1993-1995 年项目早期架构建设的官方重构；Hannum 本人对项目可移植性理想的独立公开陈述或长篇自述未见三次复查命中，使官方页面记载成为 NetBSD 阵营对 Hannum 贡献的单方陈述。史家引用时须承认其重构性，不得作为“真实 Hannum 贡献”的客观呈现。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离；而各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”，Hannum 在 netbsd-src 仓库 1993-1995 年累计 commits 是 NetBSD 从 386BSD 分离后的工程层证据；但其后 de Raadt 被逐事件（1994-12-23）使 NetBSD 与未来的 OpenBSD 构成新的分离，Hannum 作为 Core Team 成员参与此分离决策。4.1 节“分合循环，永无止息”提示：Hannum 的 commit 历史既是 NetBSD 分离的工程证据，亦是后续 OpenBSD 分离的前置条件——分离与聚合在同一 commit 群中并存。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.2 节“将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，Hannum 作为 NetBSD 早期核心架构师的身份是偶然；若 Hannum 未参与 NetBSD 或选择不同架构路径，NetBSD“runs on everything”理想的工程基础将走另一条路。5.2 节警示“被认定为代表历史合力方向的人，获得了不可质疑的合法性”——史家引用官方页面“四位共同创始人”记载时，不可反向将其神化为“NetBSD 可移植性必然由 Hannum 奠基”的证据。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”，Hannum 的 NetBSD 阵营自述与 de Raadt 的 OpenBSD 阵营自述在本体论上地位平等；14.7 节的“去中心化悖论”提示：Hannum 作为 Core Team 成员参与 de Raadt 被逐决策，构成 NetBSD Core Team 这一中心的权力行使——史家引用时须保持 NetBSD 阵营与后续 OpenBSD 阵营发声空间的对称，不得因 Hannum 的创始人身份而压制 de Raadt 一方陈述。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”，Hannum 的 commit 历史是 NetBSD 可移植性理想最直接的工程经验记录，优于任何事后回忆或叙事重构；但 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”提示：可移植性理想作为“外围形式主义”与代码本体具有本体平等——“NetBSD runs on everything”标语的存留与 commit 历史的存留，二者共同构成 NetBSD 可移植性理想的形式主义化档案。
- 总纲 10“动手者创造历史”——6.7 节“真正的敌人是时间”为审视 Hannum 参与 de Raadt 被逐决策提供了不同于“动手者 vs 旁观者”框架的切入角度：Hannum 作为核心架构师“动手”建设可移植性架构，与作为 Core Team 成员“动手”参与 de Raadt 被逐决策，构成 NetBSD 早期历史的两个面向——但二者的冲突不在人物性格，而在时间节奏：可移植性架构需要长期协作，de Raadt 的沟通节奏与 Core Team 的决策节奏在时间维度上无法和解。6.2 节“唯一的事情只有和解与接纳”在此呈现为未达成的和解：Core Team 选择了驱逐而非接纳，这一选择本身即是总纲 6 所述“和解优于斗争”的反面案例。但 14.7 节“去中心化是一种话语策略”提醒：NetBSD Core Team 的决策不是“可移植性开放 vs 治理封闭”的二元对立，而是任何去中心化组织在形式主义化过程中必然产生的中心化张力。

**要点**：

- 开源作为硬条件的形成史：受访者自 4.1c BSD 起接触，历经 4.3 前后的全源码工作环境；工作场所转用 SunOS 3.x 后数年无源码的挫折使其确立信条——不给源码的操作系统一概出局；其后为手中 SPARCstation 寻觅系统时，NetBSD 是其所能找到的唯一可运行于该硬件的开源 OS，自此与 NetBSD 缔结十余年关系。（BSDTalk EP45，[500.60-546.32]，L1）
- 可移植理想的个人实测：其日常使用 SPARC、i386 与 Sun 3 三种架构，MacPPC、Mac68k、Alpha 机器则定期开机构建软件以验证可移植性，next68k 与 Vax 属半弃用状态——合计 8 个 ports 跨 6 种 CPU 架构；这一私人机队将 NetBSD 的多架构承诺落实为日常运维实况。（BSDTalk EP45，[430.64-494.52]，L1）
- 版本策略与使用习惯呈两轨：自有机器长年运行基于 NetBSD 1.4T 断续修改的私人分支，工作机器则跟进 2.0、3.0 等较新版本；桌面以 SPARCstation 跑 X，但屏幕内容几乎只有文字与几个时钟——名义上的图形环境实为命令行工作流的容器。（BSDTalk EP45，[552.08-616.76]，L1）
- 对专有系统保持工具性距离：曾动念装 Windows 运行媒体中心类软件而终未成行；偶尔在隔离机器上安装 Solaris 等厂商系统以验证硬件本身完好，作为撰写 FreeBSD 驱动时的排障参照；其原则是离开开源便做不到的事一般索性不做。（BSDTalk EP45，[628.44-680.06]，L1）
- BSDCan 2006 的与会观察：整体氛围与前一年相仿而更熟稔；其判断技术会议的最大价值不在正式报告而在走廊与社交场合的相遇；论文分布上 FreeBSD 占据主导、OpenBSD 居次、NetBSD 沦为陪跑——他对此不满，但认为出路只在社区投出更多 NetBSD 论文，别无他法；各项目提交者间未见特别的跨项目社交混合。（BSDTalk EP45，[124.46-200.36]，L1）
- 工具谱系的守旧与偏爱：C 为其使用最多之语言，但严格说是 GCC 加自身扩展的方言；编辑器为 1980 年代起自维护至今的 Gosling Emacs 老变体；若论最爱编程环境，则是在曾供职实验室的 Lisp 机器上的 Lisp 系统胜过一切。（BSDTalk EP45，[680.06-730.62]，L1）

- 运维方法论：受访者力主以 CFEngine、Puppet 等配置管理工具实现自动化，理由是减少人为差错、便于系统复制、留有审计轨迹并压缩管理时间；同类服务器共享基础镜像加客户端微调的模式，与 UNIX 传统上以配置文件为中心的管理方式互为表里。（BSDTalk EP63，[720.82-788.76]，L1）
