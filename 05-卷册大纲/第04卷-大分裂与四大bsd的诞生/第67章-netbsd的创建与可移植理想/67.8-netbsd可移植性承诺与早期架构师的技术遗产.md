**要点**：

- Jun Ebihara（转写讹作 Jun Ibehara）自述其 BSD 缘起与社区参与：1987 年二十岁时在大学以 Sony News 工作站上的 4.2BSD 入门，并用 YACC 编写 BASIC 解释器；1993 年脱离富士通集团创办 SOM 公司后，应友人建议创建日本 NetBSD 邮件列表，二十年累计约 872 名订阅者与上万封邮件；其友人、NetBSD 核心成员萩野纯一郎（itojun）构成其进入开发者社群的直接纽带。这一自述为日本 BSD 社区起源提供了少见的当事人证词。　[存疑脚注] 转写将姓名讹作 Jun Ibehara、Hagi no Junichiro，正文依语音与语境分别推断为 Jun Ebihara 与 itojun（萩野纯一郎），引用前宜核对原始音轨。（BSD Now EP96，[1353.92-1484.82]，L1）
- 访谈核心展示环节：Ebihara 逐一演示运行 NetBSD 的边缘设备——夏普智能手机（W-ZERO3 系）、夏普 Zaurus PDA（StrongARM 处理器）、NetWalker 掌上终端与 Raspberry Pi 2，并提及运行 NetBSD 的 SH4 处理器迷你机器人；他强调同一份 ARM 二进制可跨设备运行，同一操作系统覆盖从掌机到工作站的全部形态因子，其公司主业即将 NetBSD 移植到电视、路由器、打印机与网络相机等嵌入式产品。　[存疑脚注] 设备专名在转写中失真（讹作 003、Xaos、Species 等），W-ZERO3、Zaurus、SH4 机器人等均依语音与语境推断，引用前宜核对原始音轨。（BSD Now EP96，[1493.82-1730.24]，L1）
- Ebihara 以英国 Goodwood 老车赛车节修复法拉利、莲花等经典赛车的文化类比计算机收藏圈：爱好者挖掘旧机器、更换电容与电源单元，让欧姆龙 Luna 等老工作站运行 NetBSD 7 等当前系统并运转良好；在他口中这既是乐趣也是手艺，把“过时”硬件重新纳入可用的技术世界而非博物馆式封存，这一表述正呼应本期以冷门技术为主题的编辑取向。　[存疑脚注] “Omron”“Luna”依转写语音推断为欧姆龙 Luna 工作站，引用前宜核对原始音轨。（BSD Now EP96，[1747.14-1836.94]，L1）
- 开源作为硬条件的形成史：受访者自 4.1c BSD 起接触，历经 4.3 前后的全源码工作环境；工作场所转用 SunOS 3.x 后数年无源码的挫折使其确立信条——不给源码的操作系统一概出局；其后为手中 SPARCstation 寻觅系统时，NetBSD 是其所能找到的唯一可运行于该硬件的开源 OS，自此与 NetBSD 缔结十余年关系。（BSDTalk EP45，[500.60-546.32]，L1）
- 可移植理想的个人实测：其日常使用 SPARC、i386 与 Sun 3 三种架构，MacPPC、Mac68k、Alpha 机器则定期开机构建软件以验证可移植性，next68k 与 Vax 属半弃用状态——合计 8 个 ports 跨 6 种 CPU 架构；这一私人机队将 NetBSD 的多架构承诺落实为日常运维实况。（BSDTalk EP45，[430.64-494.52]，L1）
- 版本策略与使用习惯呈两轨：自有机器长年运行基于 NetBSD 1.4T 断续修改的私人分支，工作机器则跟进 2.0、3.0 等较新版本；桌面以 SPARCstation 跑 X，但屏幕内容几乎只有文字与几个时钟——名义上的图形环境实为命令行工作流的容器。（BSDTalk EP45，[552.08-616.76]，L1）
- 对专有系统保持工具性距离：曾动念装 Windows 运行媒体中心类软件而终未成行；偶尔在隔离机器上安装 Solaris 等厂商系统以验证硬件本身完好，作为撰写 FreeBSD 驱动时的排障参照；其原则是离开开源便做不到的事一般索性不做。（BSDTalk EP45，[628.44-680.06]，L1）
- BSDCan 2006 的与会观察：整体氛围与前一年相仿而更熟稔；其判断技术会议的最大价值不在正式报告而在走廊与社交场合的相遇；论文分布上 FreeBSD 占据主导、OpenBSD 居次、NetBSD 沦为陪跑——他对此不满，但认为出路只在社区投出更多 NetBSD 论文，别无他法；各项目提交者间未见特别的跨项目社交混合。（BSDTalk EP45，[124.46-200.36]，L1）
- 工具谱系的守旧与偏爱：C 为其使用最多之语言，但严格说是 GCC 加自身扩展的方言；编辑器为 1980 年代起自维护至今的 Gosling Emacs 老变体；若论最爱编程环境，则是在曾供职实验室的 Lisp 机器上的 Lisp 系统胜过一切。（BSDTalk EP45，[680.06-730.62]，L1）
- Jason Thorpe 自 1993 年起使用 NetBSD，其 BSD 缘起于俄勒冈州立大学机房的 HP 9000/300 机器：当时混跑 HP-UX 与犹他大学的 HPBSD（基于 4.3BSD 并含向 Sun 购买授权的 NFS 扩展）；他在该校计算机系任职期间从事 CCD 驱动（4.4BSD 中实验性的简易 RAID 实现）移植，把 CCD 在 NetBSD/HP300 上跑通，视之为自己第一份重要的付费 BSD 内核工作。（BSDTalk EP64，[106.22-194.88]，L1）
- 职业线三段：在 NASA 艾姆斯研究中心数值航空航天模拟部门，受访者参与把运行于 Convex 3820 的大型分层存储管理（HSM）系统迁至 DEC AlphaServer 8200/8400，期间为 NetBSD 完成向大型 Alpha 服务器的移植（Chris Demetriou 早在卡内基梅隆奠定原始 Alpha 移植基础），涉及网络栈、VM、驱动与 SCSI 基础设施，并以 HIPPI 800 兆位并行网络向 Cray 超算传输数据；NASA 之后续于 Zembu Labs（NetBSD 基础的网络基础设施设备，毁于网络泡沫）再到 Wasabi Systems，完成 Intel XScale I/O 处理器上的 iSCSI 移植系列，即后来 Wasabi Storage Builder 产品的前身。（BSDTalk EP64，[205.08-440.6]，L1）
- Alpha 移植的技术史细节：受访者称 Alpha 是“做对了的 MIPS”，其 PAL code 把逐处理器低层机制（TLB 管理、中断处理）从操作系统剥离，并有 OpenVMS、UNIX、Windows NT 三种风味，VMS PAL code 还以子程序形式补足 VAX 指令集的互锁队列操作；DEC 对文档高度开放——芯片与 CoreLogic 芯片组文档可下载，AlphaServer 8200 仅凭纸面文档即无负担地完成移植启动，NetBSD 网站长期收藏相关 PDF/PostScript 文档；架构演进上 EV4 靠高主频取胜，EV56/PCA56 才补入字节读写指令，由此造成 PCI 地址空间按字节隔离的稀疏布局，`bus_space`/`bus_dma` API 在内核内屏蔽了这一差异，但用户态 X 服务器因 `X386` 代码的地址空间假设长期拖累 PCI Alpha 的图形支持，而 TurboChannel 机型反而更好用；Alpha 还是最早稳定支持多处理器的平台之一，他与 Bill Sommerfeld 之间以谁先跑通多用户为 friendly competition；至访谈时 Alpha 移植已与其余平台功能对等。（BSDTalk EP64，[458.6-1011.22]，L1）
- 内核现代化双轨工程：其一是已入库并将随 NetBSD 4.0 发布的 proplib——替代旧属性 API，属性可嵌套为子属性，设计仿 Mac OS X Core Foundation 的属性表，支持数组与字典容器，以 XML 文本为内核与用户态之间的外部化表示，从而获得 ABI 稳定、自版本化、免于结构体版本管理的可扩展接口，蓝牙栈已用其保存设备配置，下一步拟用于磁盘分区布局描述并逐步替换扁平二进制 ioctl；其二是数年前依 Solaris Internals 一书撰写的 Solaris 锁实现克隆（互斥体与读写锁），意在替换慢、僵化、内存开销大且需手工操纵中断优先级的旧锁 API，使多处理器环境从保护代码转向保护数据结构，现由 Andy Doran 推进整理并在 tech-kern 邮件列表公开讨论设计。受访者并谈及老平台分层（tiering）设想与 NetBSD 历史上仅删除过一个端口的纪录。（BSDTalk EP64，[1259.46-1761.1]，L1）
- 许可证立场：受访者认为 BSD 许可证比 GPL 给予开发者更多自由；以亲身商业实践佐证——NASA 时期代码全部回馈社区，而 Zembu 与 Wasabi 时期部分机器相关代码因客户要求与专有硬件保密而未回馈；若用 Linux（GPL），硬件厂商一旦接触二进制即须开放源码，可能转投 VxWorks 之类专有系统，而 BSD 许可证使硬件厂商通过雇佣 Wasabi 间接支持开源，故其商业友好属性对各方都有利。（BSDTalk EP64，[1761.1-1905.32]，L1）
- 受访者为 NetBSD 开发者、PReP 端口负责人，并兼做 NetBSD 其他 PowerPC 工作。PReP 是 IBM 与 Motorola 联合开发的参考平台，属于首批 PCI 级 PowerPC 机器的最早整系统设计，后为采用 Open Firmware 接口的 CHRP（Common Hardware Reference Platform）取代；硬件谱系包括 IBM 早期基于 PReP 的 PCI RS/6000、早期 Motorola PowerPC 机器、Motorola 的 MVME VME 机箱与后续 CompactPCI 机箱，以及小厂商生产的少量嵌入式 VME 板；CPU 以 PowerPC 601、603、604 为主，后期 Motorola 嵌入式机型较新但罕见；AIX 长期几乎是唯一在其上运行的系统，Linux 可运行，Motorola 嵌入式环境或为 VxWorks；Apple 曾参与最初的参考平台规划且硬件文档有提及，但据其所知从未按该规范产机。其概括 PReP 是“装了 PowerPC 芯片的 PC”——PCI 总线、ISA 总线与各芯片与 PC 几乎相同，规格志在取代 PC 而未成，遂被迅速替代；CPU 数无明确上限但未见过超两路，内存疑有 2GB 上限，最快约 375MHz 的机型罕见。（BSDTalk EP70，[46.28-346.64]，L1）
- 移植缘起与远程调试实践：受访者最初想写 AIX 仿真层以在 NetBSD 上运行 AIX 二进制，因没有 PowerPC 机器而在 eBay 购入一台 PReP 级的 E20；该机彼时不受支持，遂决定移植——三五年前首次尝试失败，近年回头补齐最后几处后成功。PReP 平台文档相当完备（数册大型手册），仅有个别缺漏。近期移植 F40 时并无实机在手：一位用户愿意提供机器并接好串口，受访者以邮件请其按电源重启，往内核布满调试打印、上传内核经网络引导 F40、再从串口观察失败点；因无法自行重启，约十次尝试才解决问题，并总结远程移植须逐字细读输出、本地则可随手试错。这是其首次操作系统移植：NetBSD 是学习移植的好系统——计算机尤其老机器少有全新设计，时钟芯片之类器件总能在别的端口找到现成代码，照做再加少量架构适配即可；现状上声卡驱动与 X 窗口尚未完成（非优先级），F40 还缺一条 PCI 总线的访问，其余基础设备基本齐备。（BSDTalk EP70，[352.4-628.2]，L1）
- BSD 缘起：386BSD 发布时受访者曾安装但并不喜欢——其当时最想要的是 MS-DOS 文件系统支持，而 386BSD 没有，只有一堆补丁；初学 UNIX 的他评估后觉得补丁难以应用，打听到 NetBSD 已集成该补丁及更多改进，安装后沿用至今。（BSDTalk EP70，[633.6-679.68]，L1）
- 全线 NetBSD 生活方式：其所有机器皆跑 NetBSD——主力桌面与 Web 服务器为 i386，DNS 服务器为 SPARC，防火墙为小 PC，另有 i386 PC 群、一台运行 WinCE 的 NEC 掌上 MIPS 机、几台 SPARC，以及一台正在安装的 HP700；桌面用 X 加 fvwm2，自四 MB 内存年代沿用至今；因长期不用 Flash、Java 等多媒体组件，家中桌面干脆不装，工作机才以 Linux 仿真跑带 Flash 的 Mozilla，且直言厌恶 Flash；编辑器偏好 XEmacs，但重度编辑之外多用 pico 或 VI。（BSDTalk EP70，[681.38-810.42]，L1）
- 进行中的新工程：在 PReP 之外，受访者正把 NetBSD 移植到老式 MCA 架构的 RS/6000（如 7012、7011 一类机型），并已着手移植型号 390——一台 POWER2 机器，进展未达预期但在推进。（BSDTalk EP70，[810.42-839.78]，L1）

**史观**：

- 总纲10 动手者创造历史：Ebihara 的叙事结构本身即是一份史学立场声明：历史由当事人经验构成——二十年邮件列表的 872 人、1999 年以来约 50 名用户组成员维护日本 FTP 镜像与网页、在千余人规模的开源会议上演示 2GB Raspberry Pi 镜像并借 pkgsrc 推广打包生态——这些默默做事的移植工程师、打包者与镜像维护者而非明星黑客构成叙事主体；同时 Zaurus、NetWalker 与工作站被本体论上平等对待，不存在“先进平台淘汰落后平台”的进步等级，只有同一系统在不同机器上的流转。（BSD Now EP96，[1925.08-2108.62]，L1）
- 总纲4 分离聚合是永恒规律：Oracle 为下一代 Solaris 采用 OpenBSD 的 PF 并将 SMP 补丁以概念验证形式交回上游，主持人顺势设想 FreeBSD 与 OpenBSD 两条 PF 路线未来或可重新统一；PF 自 2001 年诞生后经历 OpenBSD 与 FreeBSD 的分离、多年独立演进、再向商业系统流转，其代码在各方之间不断分离与聚合，权力与实现随之再分配——这呈现的不是防火墙技术的单向进步，而是同一形式在多个阵营间的循环流动。（BSD Now EP96，[604.76-713.94]，L2）
- 总纲10 动手者创造历史：其自我呈现是沉默动手者的典型样本：自称拥有提交权限却从不活跃、仅提交过零星小改，却数十年自维护 Gosling Emacs 变体、为 GCC 添自制扩展、维护 1.4T 私人分支、独立实现 SSH 与 mail shim——项目的实际运转依赖这类不居功的基础设施维护者，而非只有台前的活跃面孔。（BSDTalk EP45，[86.86-98.42]，L1）
- 总纲13 法律与道德是利益分配：受访者把 BSD 与 GPL 之争以及雇佣法约束都处理为利益分配问题而非道德命题：BSD 许可证的价值在于让硬件厂商的商业利益与开源生态的扩张相互成就，加州劳动法则以“晚餐时的灵感不归雇主”在雇佣关系与创新者个人之间划界；许可证与法律在这里是分配装置，各方依其处境各取所需，恰印证法律与道德本质上是利益分配的制度化形式。（BSDTalk EP64，[1761.1-1978.18]，L1）
- 总纲5 没有必然性，只有偶然性：PReP 的命运并无必然：一个志在取代 PC 的联合参考平台因产业博弈迅速让位 CHRP，硬件遂成遗物；而 NetBSD 对它的支持系于个体开发者在 eBay 上偶得一台 E20 的偶然事件——平台的兴废、移植议程的启动，都由具体的人与具体的偶然条件决定，而非技术演进的必然规律。（BSDTalk EP70，[253.96-400.68]，L1）

**辨析**：

- 由 Ted Unangst 关于 OpenBSD 工具重写与精简的文章引出的“软件最佳使用期限”之辨：bzip2 上一次发布还是 2006 年针对一个 CVE 的修复，主持人追问“没有已知 bug 不等于没有未知 bug”，并引文章观点——重写的目标不是修复“当前有 bug 的代码状态”，而是针对“预期未来的有 bug 状态”，即修复未知错误（约 101-112 秒处）；可辨析处在于：维护停滞的依赖库风险如何评估、重写是否必然优于继续维护，以及“过期”隐喻对软件生命周期的解释力与局限。　[存疑脚注] 文章作者转写讹作 Ted Ewing，依语境推断为 Ted Unangst，引用前宜核对原始音轨。（BSD Now EP96，[384.00-426.68]，L2）
