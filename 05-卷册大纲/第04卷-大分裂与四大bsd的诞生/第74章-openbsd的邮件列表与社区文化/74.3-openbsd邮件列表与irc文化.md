## 73.3.1 邮件列表的言辞文化

  **要点**：openbsd-misc、openbsd-tech、openbsd-bugs 等邮件列表长期以 “言辞激烈、不留情面” 著称——de Raadt 本人在列表中常以 "this is stupid"、"you have no idea what you are talking about" 等措辞回应；文化是 OpenBSD 精英主义的具体体现。de Raadt 典型言辞示例如下：

> this is stupid
>
> you have no idea what you are talking about

上述措辞在 OpenBSD 邮件列表历年存档中反复出现，构成 OpenBSD 精英主义文化的标志性表达

**要点**：

- Ike 回顾其 BSD 入圈：九十年代末因 Linux 不合意而转向 BSD，称 FreeBSD 4.5 上下是其第一个不内核恐慌的版本；他强调当时系统管理员文化里没有开发者与非开发者之分，“你是 Unix hacker”身份鼓励他至今不取 commit bit 而以贡献补丁为日常纪律。（BSD Now EP141，[1388.00-1553.00]，L1）
- Ike 介绍其 OpenSense 工作：与日本协作者重建国际化翻译（pfSense 时期成果因许可证疑虑消失，fork 后以 PO 文件从零重来）；架构上把 OpenSense 组件从操作系统剥离，HardenedBSD 之上亦可构建；未来设想包括 RPC 管理服务、可换 OpenBSD 底座与对标商业产品的负载均衡功能。（BSD Now EP141，[1776.00-2117.00]，L1）
- Ike 以运行 ISP 时的 SSH 零日为转折点，主张任何加密组件终会被攻破，因此能够在 LibreSSL 与 OpenSSL 之间切换重启的模块化系统是关键能力，并因此构建 IPsec 之外的备用通道。（BSD Now EP141，[2242.00-2320.00]，L1）
- Ike 描述 NYCBUG 的治理哲学：非营利、无资产可争的“朋克后台”结构使组织免于内耗，每月例会以从业者演讲带动酒吧讨论；他力主让系统管理员上台分享日常，因为开发者与用户的双向反馈最有价值。（BSD Now EP141，[2427.00-2670.00]，L1）
- 新闻综述：Trendly 项目以 FreeBSD jail 加 manifest 文件方式提供预构建容器，因 GPLv3 引发社区争议后改以 MIT 再发布；NetBSD 自 OpenBSD 移植 NVMe 驱动，单设备可达读三千八百兆每秒；PC-BSD 五月镜像改用 package base 安装约四百余个包。（BSD Now EP141，[3194.00-3380.00]，L2）
- PC-BSD 侧披露的 package base 早期缺陷与处置：setuid 位在 ZFS 上丢失（pkg 1.8 修复中）、时区文件缺失、以 make distribution 变通补 /etc，以及一次 install world 覆盖 etc/passwd 导致用户被清空的事故与回滚讨论。（BSD Now EP141，[3905.00-4111.00]，L2）
- Brooks Davis 定义 CHERIBSD：为 DARPA 资助的研究处理器（MIPS64 加空间/时间内存安全扩展）维护的 FreeBSD 分叉，纯能力模式下消除缓冲区溢出；CPU 可不加改动地运行传统二进制，内核改动很小，并支持逐指针能力化的混合模式，构成从旧代码到纯能力代码的谱系。（BSD Now EP139，[1444.00-1630.00]，L1）
- CHERI 的合并策略与平台评估：纯正确性改动（如以 intptr_t 取代裸长整型操作指针）已积极合并回 FreeBSD；移植 Linux 可行但内核以 long 操作指针是主要障碍；时间内存安全特性依赖大地址空间，在 32 位上不可行。（BSD Now EP139，[1642.00-2003.00]，L1）
- CHERI 团队约二十人（SRI 与剑桥），silicon 尚需数年；目标市场除服务器外特别看好手机——应用商店统一重编译的模式使生态转型成本远低于 Intel 三十年向后兼容负担；CHERI 已有 QEMU 移植用于持续集成。（BSD Now EP139，[1916.00-2044.00]，L1）
- ZFS 问答要点：销毁同前缀多数据集须逐个进行（zfs destroy 只接受单数据集，channel programs 尚未完成），最佳实践是建父数据集统一管理；boot environment 的“回滚”实为对旧快照做克隆，新旧版本可并存互拷；同池内跨数据集移动文件因文件系统边界与快照引用必须整段复制。（BSD Now EP139，[3254.00-3876.00]，L2）
- 读者 Thomas（Tor 中继维护者）问答披露：Raspberry Pi 上的 freebsd-update 大概率永不支持，未来由 package base 接替；安全包重建滞后两三天（LibreSSL 级更新可触发一万两千包重编，集群全量约二十小时）；ASLR 已有实现落地 current。（BSD Now EP139，[3405.00-3664.00]，L2）
- 新闻综述：OpenBSD 5.9 因支持 EFI 帧缓冲而可在无二进制 blob 的 LibreBoot 上运行（含 X220 换无线网卡被 BIOS 白名单拒绝的实证）；Undeadly 拟 HTTPS-only 引发可访问性争论；FreeBSD Journal 教学专刊收录 GNN 与 Watson 的追踪教学、Brooks Davis 的 CHERI、McKusick 的快速文件系统简史。（BSD Now EP139，[683.00-1060.00]，L2）
- Chris Simmins（多伦多大学）的 Dwicky 文章辨析文件持久性：ext4 上仅 fsync 文件不保证目录项落盘，须再 fsync 目录；ZFS 的写时复制在系统崩溃后保证得到完整旧文件或完整新文件，而非半新半旧的混合。（BSD Now EP139，[484.00-670.00]，L2）

**史观**：

- 总纲6 和解优于斗争：OpenSense 从 pfSense 分叉后不与母项目对抗而是按自身路线重建（国际化、架构解耦），Ike 视上游化与模块化为把对抗转为并行的做法。（BSD Now EP141，[1955.00-2020.00]，L1）
- 总纲5 没有必然性，只有偶然性：Ike 的 pfSense 日语翻译成果因上游许可证工具变动而一夜归零，OpenSense 分叉才使其重见天日——技术存续取决于许可证与组织结构的偶然事件而非代码本身优劣。（BSD Now EP141，[1805.00-1848.00]，L1）
- 总纲21 革命与改革是历史方法论的分歧：CHERI 采取先合并纯正确性修正、再等硅片推进能力特性的增量路线，节目将其概括为“把历史偶然写正确”的渐进改革而非推倒重来。（BSD Now EP139，[1642.00-1696.00]，L1）
- 总纲5 没有必然性，只有偶然性：X220 换 Intel 7260 无线网卡被旧 BIOS 白名单拒绝的遭遇说明硬件可用性取决于固件策略这类偶然门槛，而 LibreBoot 的意义正是移除该偶然性。（BSD Now EP139，[808.00-828.00]，L2）

**辨析**：

- Trendly 改 MIT 的直接动因是社区对 GPLv3 与“基于 FreeBSD”宣传相悖的批评，节目归功于外部贡献尚少使再许可可行，但这只是主持人推断，项目方动机未经当事人证实。　[存疑脚注] 改许可证的确切决策过程与时间点未见一手声明（BSD Now EP141，[3347.00-3377.00]，L4）
- Undeadly HTTPS-only 提案的支持与反对并存：HSTS 可防降级攻击，但强制 HTTPS 会把无法建立该连接的地区读者挡在门外；salt 随代码公开一事经解释并非漏洞，但暴露其口令存储未采用每用户盐的惯例。（BSD Now EP139，[758.00-880.00]，L2）
