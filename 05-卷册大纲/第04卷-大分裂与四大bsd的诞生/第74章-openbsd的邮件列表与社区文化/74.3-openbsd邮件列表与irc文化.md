- 总纲10 动手者创造历史：Cody 的贡献观强调社区史由动手者的多种劳动共同构成：他因不提交代码而选择为 Undeadly 写故事，把五行文本的配置经验、VLAN 上 DHCP 或 pf binat 的用法写成稿件帮助他人；OpenBSD 社区被指敌意，但他认为索取而不贡献者遭遇冷淡是投入产出的自然结果，帮助用户、提供硬件访问与代码、捐赠同为贡献形态，动手与分享才是社区存续的实体。（BSDTalk EP151，[605.64-757.78]，L1）

**辨析**：

- Trendly 改 MIT 的直接动因是社区对 GPLv3 与“基于 FreeBSD”宣传相悖的批评，节目归功于外部贡献尚少使再许可可行，但这只是主持人推断，项目方动机未经当事人证实。　[存疑脚注] 改许可证的确切决策过程与时间点未见一手声明（BSD Now EP141，[3347.00-3377.00]，L4）
- Undeadly HTTPS-only 提案的支持与反对并存：HSTS 可防降级攻击，但强制 HTTPS 会把无法建立该连接的地区读者挡在门外；salt 随代码公开一事经解释并非漏洞，但暴露其口令存储未采用每用户盐的惯例。（BSD Now EP139，[758.00-880.00]，L2）
- systemd 驱动 Linux 用户迁移 BSD 的归因须谨慎：来信确有“一次 systemd 升级失败就重装为 PC-BSD”的戏言，但同批叙事也承认 BSD 在笔记本硬件支持（Intel 显卡驱动缺失）与桌面易用性上的短板；且样本来自 BSD 听众的自选择，存在幸存者偏差，个案叙事不能直接推为 2014 年前后的用户迁移总体趋势。　[存疑脚注] 迁移归因仅为来信者主观陈述与主持人讨论，缺乏用户留存率等量化数据；另转写专名失真多处：HardenedBSD 贡献者人名疑为 Shawn Webb、Rick Fleuter 与 Roadster Maracle 等无法确证、BSDTalk 第 208 集被转写为 episode 208 等，引用须回源核对（BSD Now EP69，[731.82-748.46]，L4）
- 转写存在数字与术语缺陷：温尼伯数据量先后记为 70 与 80 TB、多处专名误转（3ware、Soekris、OS X、softflowd），引用须以原始音频核对；OpenBSD 文件服务性能不足的判断出自其以 Samba 为主的特定负载，属个案经验，不宜泛化为对 OpenBSD 存储栈的整体评价。　[存疑脚注] 数据规模转写不一致，性能判断为单一个案负载经验。（BSDTalk EP151，[124.12-146.84]，L4）
