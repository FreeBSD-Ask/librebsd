# 74.5 OpenBSD 基金会（OpenBSD Foundation）的内部张力——OpenBSD Foundation 为加拿大非营利组织（2007 年注册成立，原依据 Canada Corporations Act Part II 注册，后依据 Canada Not-For-Profit Corporations Act S.C. 2009 续存），但 de Raadt 对 “基金会化” 长期持保留态度，担心 “商业逻辑入侵技术决策”

## 74.5.1 OpenBSD Foundation 的成立

  **要点**：OpenBSD Foundation 为加拿大非营利组织——作为 OpenBSD 项目的法律实体与资金管理机构，支持 OpenBSD、OpenSSH、OpenBGPD、OpenNTPD、OpenSMTPD、LibreSSL、mandoc、rpki-client 等相关项目；成立背景涉及 OpenBSD 长期资金不足与法律保护需求；2007 年注册成立，原依据 Canada Corporations Act Part II 注册，后依据 Canada Not-For-Profit Corporations Act S.C. 2009 续存 [考据脚注：经互联网档案馆 2007-2008 年快照交叉验证，Foundation 于 2007 年注册成立，2008 年 7 月前已全面运营。Bylaws 引用 S.C. 2009 系后续法律续存。]
  
**史料**：OpenBSD Foundation Bylaws、官方网站关于基金会的说明、OpenBSD 各 hackathon 资助记录、互联网档案馆 web.archive.org 2007-2008 年快照 [考据脚注] 〔L3 官方文档与公告〕
  
**史观**：总纲第 13 条——法律与道德是利益分配（法律结构）：OpenBSD Foundation 的成立是 BSD 项目法律结构发展的关键节点
  
**辨析**：Bylaws 引用 2009 年加拿大联邦非营利公司法（S.C. 2009，2011 年生效），但 Foundation 实际成立于 2007 年（互联网档案馆确证），系原依据 Canada Corporations Act Part II 注册后于新法生效后续存——此法律续存机制是加拿大非营利组织的常见实践，非 “成立时间冲突”

**要点**：

- OpenBSD 基金会董事 Ken Westerback 在访谈中阐明该组织的独特形态：它是纯粹的资金管道，不持有 OpenBSD 的商标与知识产权，不出售周边商品，不雇佣也不指挥开发者，只接收社区的资助申请并按可用资金拨款；这与同期将所有权与知识产权注入基金会的其他 BSD 项目基金会形成鲜明对照。（BSD Now EP78，[1584.57-1636.25]，L1）
- hackathon 作为 OpenBSD 的开发制度早于 Westerback 本人加入项目：2001 年在波士顿与 USENIX 年会并行举行的 C2K1 是其参加的首次活动；早期年度大会固定于 Calgary 并常借用 Theo de Raadt 住所举办社交活动，后因场地与吸引新开发者的需要迁往 Edmonton，再因欧洲开发者抱怨跨洋成本改为加拿大与欧洲交替举办（布达佩斯、卢布尔雅那等），并在常规大会之外发展出路由、ports、网络等十余人的专题 mini-hackathon；基金会为此承担场地、住宿乃至关键开发者的差旅。（BSD Now EP78，[1825.61-1985.55]，L1）
- OpenBSD 于 2014 年首次参加 Google 编程之夏，解决一系列 paperwork 问题后获五个项目，其中 Capsicum 移植可行性调查的结论是“不可行”，但基金会仍视其为成功——障碍被识别、测试已完成，负结果本身具有价值；2015 年已再度申请，结果待同年 3 月 2 日公布。（BSD Now EP78，[1998.21-2068.91]，L1）
- Heartbleed 催生的核心基础设施倡议由多家大企业出资，为 OpenSSL 雇佣程序员清理代码，并按 OpenBSD 网络工作的实际开支向基金会定向拨款；Westerback 将 OpenSSH 与 LibreSSL 列为最需要长期投入的核心基础设施，但吸引一名承诺两年以上的专职开发者至今无人签字，暴露出小额捐助模式难以支撑长周期代码整理的结构性困境。（BSD Now EP78，[2101.87-2236.47]，L1）
- 维护者 Kjell Wooding 阐明 mg 的定位：这是一个极小的 Emacs 风格编辑器，与 Emacs 本质不同——后者是恰好附带编辑器的 Lisp 解释器，而 mg 首先是编辑文件的工具，不内嵌编程语言、不提供游戏或浏览器式扩展，只为满足 Emacs 用户的键位肌肉记忆；他并非原作者，而是在维护过程中偶然接手，mg 于 2000 年进入 OpenBSD 基本系统。（BSDTalk EP200，[60.04-157.16]，L1）
- mg 的历史与可移植性：Wooding 回忆该编辑器 1986 年即已问世、早于 OpenBSD 存在；多年来被社区自发移植至 Debian、Mac OS X 等环境，维护者至今仍收到 Debian 用户的 bug 报告；项目并无独立便携版仓库，获取最新源码的正规途径始终是 OpenBSD 源树。（BSDTalk EP200，[359.88-401.88]，L1）
- 许可证工程：mg 初入项目时约九成代码即属 public domain，团队随后逐个联系在树作者，将全部补丁释放进 public domain，如今仅 theo mode 一个文件仍持 BSD 许可——该模式仿照 Emacs 中 ELIZA 式对话实验，输出 Theo de Raadt 多年来的言论语录，属社区自嘲文化产物；Wooding 同时指出 public domain 在瑞典等法域仍有法律适用问题。（BSDTalk EP200，[691.08-751.56]，L1）
- Wooding 的参与路径与角色变迁：他曾经营安全公司 Code Talker Communications，与一巷之隔的 Secure Networks 公司一次喝啤酒闲谈中得知 OpenBSD 开发者住在自己的家乡 Calgary，遂联系并加入项目；最初职责是维护旧 IPF 防火墙代码并整合 Darren Reed 的改动，亲历该代码被整体移出源树、代之以 PF 的大分裂；此后其贡献呈游牧状，在 hackathon 间隙深入源码各处修 bug，如 pfsync 与冗余代码问题。（BSDTalk EP200，[412.48-526.32]，L1）
- 维护哲学与状态：Wooding 的长期目标是让代码行数越来越少，通过迭代清理与简化逼近；mg 仍存在积年未修的设计缺陷，修复通常依赖某份 bug 报告将维护者唤醒；他曾在 hackathon 中专门重写文档，如今手册页可能比源码本身更长，呼应 OpenBSD 对完整 man page 的自豪传统；另曾于愚人节发布可用的 vi 模式补丁。（BSDTalk EP200，[654.32-801.48]，L1）

**史观**：

- 总纲13 法律与道德是利益分配：基金会的治理形态并非源于项目自身的技术意志，而是由捐赠方的利益分配需求塑造：企业无法直接向一位开发者个人汇款，需要纸质凭证与正式法人实体以通过内部财务合规，基金会正是为满足这种会计与法务要求而设；Heartbleed 之后企业资金按领域定向流入开源基础设施，可视为同一分配逻辑在更宏观层面的延伸。（BSD Now EP78，[1473.26-1496.52]，L1）
- 总纲13 法律与道德是利益分配：mg 的授权重构过程——逐个接洽在树作者、把分散的版权利益统一收束为 public domain——显示许可证选择在开源工程中本质上是围绕项目利益的法律形式安排，而非抽象的道德立场。（BSDTalk EP200，[116.68-137.44]，L1）
- 总纲10 动手者创造历史：Wooding 自述数年间漫游源码树、依 bug 报告唤醒注意、以 hackathon 间隙零星修复的维护方式，表明 OpenBSD 的日常演化由大量此类默默动手的个体贡献累积而成。（BSDTalk EP200，[493.80-521.64]，L1）

**辨析**：

- Superfish 事件展示了 SSL 拦截正当性边界由主体身份而非技术本身划定：预装自签根证书、在用户浏览器信任链内伪造站点证书并注入广告，在消费产品上属恶意行为；同样的中间人架构置于企业网络边缘并取得员工知情同意，则可能是合法的内容审查，relayd 的证书拼接功能正以企业部署为设计前提，并提醒各国对未告知监控的法律限制不同。　[存疑脚注] 转写将 Reyk Floeter 失真作“rake floiter”、OPNsense 失真作“OpenSense”、LibreSSL 失真作“Libra SSL”，引用时须以原始博文与发布公告为准。（BSD Now EP78，[649.11-838.61]，L2）
