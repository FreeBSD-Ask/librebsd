# 第 74 章 openbsd的邮件列表与社区文化

## 要点

- OpenBSD 反向工程引发伦理争议——部分观点视为合法逆向，部分视为侵犯知识产权；de Raadt 长期批评闭源固件，主张源码必须开放；争议反映开源社区对闭源固件的不同立场
- OpenBSD 邮件列表与 Linux 内核邮件列表（LKML）在言辞文化上存在对照——两者均以 “言辞激烈” 著称，但 OpenBSD 更强调精英主义，LKML 更强调技术辩论；对照反映两个项目的社区文化差异
- OpenBSD hackathon 长期运行形成 “元老网络”——多次参与 hackathon 的核心开发者形成非正式决策圈，影响项目长期方向；元老网络是 OpenBSD 治理结构的非正式层面
- OpenBSD Foundation 董事会与 de Raadt 核心圈子存在人员重叠——部分核心开发者同时担任董事会成员；重叠既是协调优势也是治理隐患
- OpenBSD 基金会（2007 年成立）在 2007-2014 年间未公开财务报告，2014 年 Theo de Raadt（西奥·德·若特） 澄清后改善。2014 年电费断供暴露了小型开源项目财务管理的系统脆弱性。

- 本期标题所指的 1980 年代线索来自嘉宾 Scott Courtney 的自述：他于 20 世纪 80 年代半途接手一台运行 SVR3 的 AT&T 3B2 服务器的系统管理员工作而入行 Unix，此后经 Solaris 等商业 Unix 接触到源自 BSD 的 TCP/IP 等特性；约在 2015 年前的六七年，他在 VeriSign 主管架构时，因 .com 域名平台与根 DNS 产品在攻击负载下的可扩展性瓶颈而转向 FreeBSD，并采取 FreeBSD 与某一 Linux 变体并行的异构部署策略以对冲零日漏洞风险。（BSD Now EP105，[1054.36-1119.66]，L1）
- OpenBSD 在本期呈三线推进：其一，tame() 用户态集成由 Theo de Raadt 以百余个小 diff 的形式落地，多数程序仅两三行改动，路径白名单留待后续；其二，UEFI 与 GPT 初始支持开始合入，帧缓冲结构暴露给 wsdisplay 后端，GPT 重构将取代为绕过 MBR 单盘 2 TB 限制而设的 disklabel 变通，UEFI-only 的设备（如 VIO-Z Canvas）由此获得启动 OpenBSD 的可能；其三，LibreSSL 自上游开始禁用 SSLv3，先从 openssl 命令行工具关闭，ports 中的 Apache 等依赖仍待适配，IETF 亦有禁用 SSLv3 的 RFC 草案在途；同一周内 FreeBSD 的多路径 TCP 0.5 补丁集与 DragonFly 的 Intel 显卡更新共同构成 2015 年 9 月初的跨分支技术图景。（BSD Now EP105，[2680.64-2822.08]，L3）
- Daroussin 阐明 base 打包化的三重动机：freebsd-update 跨大版本升级缓慢且自建更新服务器困难；需要精确追踪 base 系统每个文件并在升级时清理旧文件；拆分为多包后嵌入式等场景可按需取用子集实现最小安装。初期方案先用极少数包整体承载 base，再逐步细分。（BSD Now EP84，[1535.16-1601.32]，L1）
- 技术补齐细节：pkg 1.4 已能处理 base 系统文件的不可变标志，但缺少清单声明手段，遂在清单中新增声明并注入脚本环境变量以支持非 root 与跨字节序安装；为升级 etc 配置文件，从 Fossil 版本控制系统提取三方合并代码改造进 pkg 1.5，合并失败则保留冲突文件交用户处理；1.5 引入 -R 选项，不做 chroot、仅前缀目标目录，为跨架构安装、jail 供给、mtree 清单与 makefs 镜像铺路；时间表定为 BSDCan 前可测、EuroBSDCon 出 beta、11.0 约于 2016 年夏正式。　[存疑脚注] 转写专名多处失真：mtree 误作 m3.5、Poudriere 多种变体、AsiaBSDCon 误作 token BSD，均按语义复原，待与原始音频核对。（BSD Now EP84，[1790.44-2211.36]，L1）
- PC-BSD/TrueOS 一侧的主持者以分发者身份陈述痛点：freebsd-update 需在虚拟机中以时间戳对比方式重复构建并手动上传签名，每次安全更新负担沉重；实际运维中 base 与第三方并存两套包系统。pkg base 许诺单一升级入口与单一事实来源，build world 一次即可产出，安全团队无须为每个支持版本重复构建，补丁周转有望加快，自定义仓库与滚动跟踪 CURRENT 的门槛同步降低。（BSD Now EP84，[2467.62-2644.92]，L1）
- Lawrence Teo 的开发者入职路径浓缩了 OpenBSD 的贡献者遴选逻辑：遵“shut up and hack”（1800.24-1813.92）准则多年只发附带补丁的邮件（2004 年修改 MD5 工具、为 IBM 鼠标上报 USB ID），后因 libpcap 与主线脱节且无人认领而独自以约五个工作周完成同步，巨型 diff 一度无人跟进，直至数月后重提才获邀进入开发者私有频道并于 2012 年 5 月获得提交权——身份由持续产出与在任开发者接纳共同决定，而非自荐申请。（BSD Now EP81，[1793.16-1861.10]，L1）
- Calyptix 的产品形态是 2015 年 OpenBSD 商用可行性的个案证据：面向无 UNIX 经验的微软系管理员提供基于 OpenBSD 的防火墙设备，尽量沿用 base 系统与通用内核（PF、IPsec/iked，LibreSSL 自 2014 年 12 月起生产环境使用，坚持 stock ksh 而不用 bash 使 Shellshock 几无影响），并以全自动更新应对中小机构无力运维的现实；客户覆盖律所、学校、医院、银行乃至 NASCAR 车队与路边广告牌，Teo 以“I'm living proof that it is”（2852.18-2857.62）回应 OpenBSD 是否已可商用。（BSD Now EP81，[2551.84-2857.62]，L1）
- OpenSSH 6.8 显示上游重构与下游发行版同步的摩擦成本：内部代码库化重构使 FreeBSD portable 版既有补丁全部失效、进入 ports 的时点推迟；同期新增 SHA-256 base64 主机指纹并设为默认、UseDNS 默认值由 yes 改为 no、实验性主机密钥轮换与多公钥认证，以及不依赖 OpenSSL/LibreSSL 的构建选项（仅保留 ED25519 与 ChaCha20 等新算法套件）——安全快速迭代与发行版移植节奏之间的张力在 2015 年已清晰可见。（BSD Now EP81，[1036.18-1192.06]，L2）
- 本期教程演示 SSH 链式连接：先以 ProxyCommand 指定经堡垒主机（bastion host）逐跳登录内网机器，再把主机别名、登录用户、密钥文件与跳板参数沉淀进 .ssh/config，使一条短命令即可完成多跳；HostKeyAlias 可将同一服务器的多个 known_hosts 条目合并为一以消除指纹误报；配置支持 host1/host2/host3 形式的递归串联与 Host * 通配默认跳板，且对 rsync、scp 等一切基于 SSH 的工具透明生效。（BSD Now EP42，[4676.64-5026.70]，L2）
- Sean Webb（彼时尚非 FreeBSD committer）推进 FreeBSD 的 PIE 支持以实现 ASLR：常规 ELF 可执行文件向内核声明固定加载地址，而以 PIE 编译者可被加载至任意地址，随机化由此可行；基础系统应用尚未默认以 PIE 编译，需在 make.conf 或 src.conf 置 WITH_PIE=yes 重编，i386、amd64、sparc64 与 arm 等架构均在支持计划内；该工作现处 11-CURRENT、尚未回移 10，项目即将发布测试征召，需要开发者清理代码风格、审查并给出 sign-off 以确认不破坏既有负载。（BSD Now EP42，[76.36-215.26]，L2）

- 总纲5 没有必然性，只有偶然性：漏洞披露的混乱被归结为多方偶然失序而非单一阴谋，呼应没有必然性、只有偶然性的判断。（BSD Now EP230，[1201.3-1356.9]，L2）
- 总纲10 动手者创造历史：全期的叙事重心置于不显眼的劳作之上：主持人称赞 LibreSSL 移除 SSLv3 与 Tarsnap 安全赏金这类“吃力不讨好的工作”（2442.82-2445.26），指出删除特性并承受其连锁反应是不被看见的贡献，正因如此才要感谢源码树后的清理者；节目又在两周年之际向幕后编者 TJ 致敬，将其每周整理的 show notes 与选题组织确认为节目得以存在的隐形基底——书写对象由此从发布会与版本号转向维持系统运转的动手者。（BSD Now EP105，[2442.82-2464.44]，L2）
- 总纲8 本体论上各方平等：各 BSD 分支在同一时段的多线并进构成本体论平等的经验呈现：DragonFly BSD 合入 Linux 3.17 的 Intel 显卡栈更新并辅以 3.19 的稳定性修复，其图形进度反令 FreeBSD 侧主持人自嘲羡慕；OpenBSD 独立推进 tame() 沙箱、UEFI 启动与 SSLv3 清除；FreeBSD 侧则以 bhyve、多路径 TCP 补丁集与 11 CURRENT 应对——没有任何单一分支被叙述为普遍进步的主线，呈现的只是不同努力在各自曲线上的流转。（BSD Now EP105，[740.84-749.74]，L2）
- 总纲21 革命与改革是历史方法论的分歧：pkg base 以改革姿态出现：不改写 base 与第三方的结构边界，仅替换升级工具链，用最小的本体论让步换取运维层面的变革；对照听众的 Linux 化疑虑可见，工程社区靠明确区分这是换工具而非换结构来消解变革阻力。（BSD Now EP84，[3919.82-3985.84]，L2）
- 总纲10 动手者创造历史：Matt Ahrens 粗算 ZFS 蕴含逾百工程年的积累，据此判定任何新实现从零追赶在可见期限内不可行；pkg 作者亦以近五年持续打磨工程细节回应路线图之问。技术史的走向由长时段的默默积累决定，而非发布节点上的宏大宣言。（BSD Now EP84，[1278.02-1332.40]，L2）
- 总纲10 动手者创造历史：主持人转述的 OpenBSD 六个月发布节奏（三个月开发、三个月稳定化）与大锁拆解进度（约 220 个系统调用中仅 20 余个脱离 giant lock）呈现技术系统演进的累积形态：SMP 化不依赖一次性蓝图跃进，而由动手者在周期约束下一次次局部解锁累积而成，外界可见的只是每期数十个调用的渐进增量与 long-term 的隐性重排。（BSD Now EP81，[5010.00-5072.28]，L2）
- 总纲22 知识注定过时：针对观众“生产服务器是否应移除编译器”之问，主持人指出该做法源自主机独占、用户别无他机的旧时代安全惯例，在任何人可随手起虚拟机编译再回拷二进制的当下已无任何安全收益，securelevel 提升与文件不可变标志等内核级约束才是有效防线，并以 Varnish 内置编译器处理配置语言为反例佐证；同段还呼应 Michael W. Lucas 在 FreeBSD hackers 邮件列表引发约五百封邮件的 gpart 与 fdisk、disklabel 之辨——安全教条与工具惯性皆随运行环境变迁而失效，具体知识注定过时，唯环境条件决定其效力。（BSD Now EP42，[4409.24-4471.84]，L2）
- 总纲5 没有必然性，只有偶然性：Bryce 以亲历者身份断言 shell 服务已无利可图：这一行当的黄金年代系于拨号上网、IRC bouncer 需求与 Hotmail、Gmail 尚不提供 IMAP 等偶然技术条件——用户需要一台永远在线、带固定上游带宽的机器；宽带普及与免费邮箱补齐能力后市场随之消亡，仅剩十余年前的少数大厂仍在运营（Brian Callahan 亦供职于其中之一）；BSD shell 服务的兴衰并非 BSD 本身的命运，而是外部通信条件偶然组合的函数，历史进程不可化约为项目内因。（BSD Now EP42，[2630.30-2712.26]，L1）

- Colin Percival 对 Google、Intel 与 Linux 社区的批评系其个人立场，节目转述时未提供对立方的回应。　[存疑脚注] 系单一来源的个人立场表述（BSD Now EP230，[1201.3-1218.3]，L4）
- 本期最具考据价值的片段是当事人自纠：听众 Mason 来信指认主持人在上期约 1 小时 56 分钟处声称 X 进入基本系统的最大障碍是许可证不利于 BSD，并指出 X 许可证与 BSD 许可证几乎无异、NetBSD 与 OpenBSD 携带 X 已近二十年；Allan Jude 随即更正，澄清真正的障碍并非许可证，而是 FreeBSD 项目不愿为跨 FreeBSD 10 的五年生命周期维持 ABI 稳定而在基本系统内维护 X 的分支，X 的定位始终是 port；他同时透露 FreeBSD 正延续将组件移出基本系统的路线——Perl 自 FreeBSD 4 起已移除，OpenSSL 拟改为仅内部私用、用户态依赖自 ports 获取以加快补丁节奏。（BSD Now EP105，[3272.78-3362.70]，L1）
- 围绕 NextBSD 移植 LaunchD 的争议呈现流言与澄清的典型结构：一篇评论文章主张 FreeBSD 不应采用 LaunchD，Reddit 上正反意见交锋并引来大量社区邮件；Allan Jude 澄清所谓 XML 配置的恐惧源自过去某设备厂商对 launchd2 的 FreeBSD 移植，而 NextBSD 实际使用的版本改用 JSON 且更为精简，提醒听众核对正确版本再作评判；工程层面，Kip Macy 正在修复安装器以便发布可试用的 NextBSD ISO，Jordan Hubbard 与 Kip Macy 均已同意接受访谈但需待 EuroBSDCon 之后，PC-BSD 下一版将基于 FreeBSD 11 CURRENT 与 NextBSD 构建并集成 launchd，且计划按月发布镜像、或与 HardenedBSD 合流。（BSD Now EP105，[589.64-628.86]，L2）
- 是否 Linux 化的分歧被摆上台面：听众来信以 base 与附加软件的清晰区隔正是 FreeBSD 区别于任意包集合式 Linux 发行版之处为由质疑打包化方向；主持人与访谈者反复申明 base 与第三方以 usr/local 为界的结构不变、world 与 kernel 仍一体化开发，pkg 只是升级与分发载体。争议实际落在工具链变更与本体论边界的混淆上。（BSD Now EP84，[3885.96-3985.84]，L2）
- 企业存在与治理文化的双重辨析：主持人断言 Juniper 设备几乎皆基于 FreeBSD、多数 Cisco 防火墙亦然，PF 已内置于 OS X 与 iOS，以此论证 BSD 技能的职场价值；另以 OpenBSD 提交日志末尾的 OK 署名对照 FreeBSD 的 Reviewed by 与 Approved by 机制，展示两项目代码评审治理的同构与差异。　[存疑脚注] 多数 Cisco 防火墙基于 FreeBSD 的说法为主持人单方断言，本期未给出处，未经交叉验证；Juniper 基于 FreeBSD 属可查事实但同样未当期举证。（BSD Now EP84，[4197.66-4389.78]，L2）
- 安全叙事存在单源与转写双重风险：Teo 以 Michal Zalewski 对各操作系统随机性的可视化研究作为其选择 OpenBSD 的关键论据，属当事人回忆中的单一二手引用（1693.70-1715.22）；HardenedBSD 的完整性强制机制仅有主持人转述，其与 NetBSD Veriexec 的类比、SHA-1/SHA-256 哈希清单机制及未来 X.509 ELF 签名计划均未经他源核证，细节可信度有限。　[存疑脚注] 机制名与专名转写失真（如“IntegraForce”“VeraExec”疑为 Veriexec，Zalewski 姓名拼写存疑），且均为主持人单一转述，待与 HardenedBSD 官方公告核证（BSD Now EP81，[3070.24-3159.92]，L4）
- 听众 Robert 的迁移个案为 2015 年 BSD 桌面生态提供正反两面当事人证词：因 PulseAudio 整合混乱与对 systemd 缺乏信心而离开 Linux，PC-BSD 10.1.1 实现硬件即插即用并带来“回到有理智 shell 的类 UNIX 环境”的体验（3793.64-3835.46）；但无线网卡仅 a/b/g 模式、可查文档仅有三年前 wiki 清单，以及大文件拷贝时的内存占用观感问题（后被澄清为 inactive memory 误读），暴露无线驱动支持与内存统计认知层面的生态短板。（BSD Now EP81，[3793.64-3856.78]，L1）
- Devious 案例呈现工具理性与共同体认同的真实张力：受访管理员承认 FreeBSD 的 jail、ZFS 数据集、sysctl 隐藏 UID 与 rctl 资源控制、IPFW 用户匹配规则更适合作共享 shell 主机，且曾认真考虑迁移，但遭用户抵制——用户要的不是任意 BSD 而是 OpenBSD 本身，其中不乏 OpenBSD 开发者，平台一致性正是其开发体验的一部分；访谈同时点出 FreeBSD 项目自身提供项目级 shell 资源而 OpenBSD 架构上缺位，Devious 恰好填补此空白；功能最优解让位于共同体归属，是理解 BSD 分支生态分化的一把钥匙。（BSD Now EP42，[1727.20-1790.04]，L1）
