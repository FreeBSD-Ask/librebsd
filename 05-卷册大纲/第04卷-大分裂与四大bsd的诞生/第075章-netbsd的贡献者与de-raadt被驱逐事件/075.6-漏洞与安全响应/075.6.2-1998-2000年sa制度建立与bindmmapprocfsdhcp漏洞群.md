# 075.6.2 1998-2000 年 SA 制度建立与 BIND/mmap/procfs/DHCP 漏洞群

  **要点**：NetBSD 于 **1998 年** 建立正式 Security Advisory 制度，首个 SA 为 **NetBSD-SA1998-001**（BIND 4.9.6 DNS 缓存污染与 NXT 记录处理缺陷，CVE-1999-0833），标志 NetBSD 安全响应从 pullup commit + 邮件列表通知模式升级为正式 SA + 补丁分发模式；1998-2000 年间共发布 8 条 SA（NetBSD-SA1998-001 至 NetBSD-SA2000-017），漏洞群集中于三类技术机制——远程网络服务缓冲区溢出（BIND DNS 缓存污染 SA1998-001、telnetd 与 Kerberos 5 库 **libkrb** 交互溢出 SA2000-017）、本地权限提升与信息泄露（**mmap(2)** 设备驱动权限检查缺陷 SA1998-005、**procfs(5)** 权限检查缺陷 SA2000-001）、远程拒绝服务（IP 选项处理触发内核 panic SA2000-002）；其中 **NetBSD-SA2000-008**（**dhclient(8)** 远程代码执行）危害等级最高——恶意 DHCP 服务器可构造畸形响应导致客户端执行任意代码，影响 **NetBSD 1.4.x** 与 **1.5**，该漏洞是 DHCP 协议层面首次被公开披露的远程代码执行漏洞之一；BSD 数据库中对应时期的 security fix commit 包括 1998-05-10 mrg 两条“reject attempts to map an immutable or append-only file”（对应 SA1998-005 mmap 漏洞修复，commit_hash `6b11eea5b20922bfa9a7982565b03e5a1b5de72d`、`54409bc78ace63768d2134ae3990edd6195c68cc`）与 1998-11-23 cgd 两条"Fix many real and potential security problems with character device driver mmap routines"（commit_hash `2ceac3b23b095efc02b8b4ebded75b7eec9032bd`、`f5d1f91cc342176b4d6a179528f5047da08d39fc`），以及 2000-02-28 he 四条“Fix a critical typo in the earlier procfs security fix”（对应 SA2000-001 procfs 漏洞修复的修正版，commit_hash `a685050c3f4b3919cc804eea7792397efc311b4e` 等），反映 procfs 安全修复存在初版缺陷须二次修正的工程实践；2000-07-20 mellon 四条“Final (I hope) DHCP client security fix”（对应 SA2000-008 dhclient 漏洞修复，commit_hash `26ffec0f97ae40085d61c141125aadb170ab4132` 等），commit subject 中“I hope”措辞反映开发者对修复完整性的不确定。NetBSD 1.x 时期重要 SA 列表如下：

| SA 编号 | 发布年份 | 漏洞类型 | 涉及组件 |
| ----- | ------ | ------ | ------ |
| NetBSD-SA1998-001 | 1998 | 远程网络服务缓冲区溢出 | BIND 4.9.6 DNS 缓存污染 |
| NetBSD-SA1998-005 | 1998 | 本地权限提升 | **mmap(2)** 设备驱动权限检查 |
| NetBSD-SA2000-001 | 2000 | 本地信息泄露 | **procfs(5)** 权限检查 |
| NetBSD-SA2000-002 | 2000 | 远程拒绝服务 | IP 选项处理触发内核 panic |
| NetBSD-SA2000-008 | 2000 | 远程代码执行 | **dhclient(8)** DHCP 协议层 |
| NetBSD-SA2000-017 | 2000 | 远程网络服务溢出 | telnetd/**libkrb** |

**史料**：NetBSD 官方 Security Advisories 存档（`<https://ftp.netbsd.org/pub/NetBSD/security/advisories/`，NetBSD-SA1998-00>1 至 NetBSD-SA2000-017）；netbsd.duckdb `commits` 表（netbsd-src, 1998-05-10 至 2000-11-19, security fix commit）；NVD CVE-1999-0833 元数据；netbsd-announce 邮件列表 1998-2000 年存档 ［A］

**史观**：SA 制度的建立是 NetBSD 安全响应从“社区自发 pullup”到“制度化漏洞披露”的工程升级，pullup 机制本身保留但增加 SA 公告层；NetBSD 1.x 时期多平台移植优先策略的代价是安全修复须在多平台验证后方可 pullup，安全响应速度受 MI/MD 架构约束

**辨析**：NetBSD-SA1998-001 的 CVE-1999-0833 编号系 CVE 体系（1999 年建立）事后追溯，1998 年发布 SA 时原文未引用 CVE 编号，须区分“漏洞披露时间”（1998 年 SA 发布）与“CVE 追溯时间”（1999 年）；NetBSD-SA2000-001 procfs 漏洞修复的“critical typo”修正（2000-02-28 he 四条 commit）表明初版 procfs 安全修复存在关键拼写错误导致修复无效，史家须以修正版而非初版作为修复完成标志——此模式与 FreeBSD 1.x 时期 isprint() 修复的“初版-修正版”模式一致，反映 BSD 项目早期安全修复质量控制的共性缺陷；NetBSD-SA2000-008 dhclient 漏洞是 DHCP 协议层面的远程代码执行漏洞，须区分“协议设计缺陷”与“实现缺陷”——该漏洞属于 **dhclient(8)** 实现层面的缓冲区溢出而非 DHCP 协议本身的设计缺陷；【0 信任原则·SA 公告仍须交叉验证】NetBSD 官方 SA 虽为一手史料，但修复 commit 的实际完整性须对照 netbsd-src 仓库 diff 核验，mellon 的“I hope”措辞提示修复可能不完整
