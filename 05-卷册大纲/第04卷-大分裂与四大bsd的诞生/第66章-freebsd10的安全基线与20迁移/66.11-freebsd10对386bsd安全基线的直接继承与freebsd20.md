# 66.11 FreeBSD 1.0 对 386BSD 安全基线的直接继承与 FreeBSD 2.0 rebase 后的迁移（1993-1995）

## 66.11.1 FreeBSD 1.0 基于 386BSD 0.1 补丁集对 386BSD 安全基线的直接继承

  **要点**：FreeBSD 1.0（1993-11-01）由 Nate Williams（内特·威廉姆斯）、Rod Grimes、Jordan Hubbard 等在 386BSD 0.1 补丁集基础上 fork 发布，同时继承 U.C. Berkeley 的 4.3BSD-Lite（“Net/2”）磁带——FreeBSD 1.0 的安全基线来自 Net/2（即 4.3BSD-Reno 网络栈）经 386BSD 0.1 移植至 80386 平台，未引入新的安全机制；继承的安全基线包括 root/超级用户二元特权模型、文件权限 rwx 三段式结构、setuid/setgid 机制、基于 DES 的 **crypt(3)** 密码散列、Net/2 密码文件布局（公开可读的 `/etc/passwd` 与仅 root 可读的 `/etc/master.passwd` 并存，pwd_mkdb(8) 生成的 `/etc/spwd.db`/`/etc/pwd.db` 双数据库实现口令分离——shadow 机制随 Net/2 继承而非 FreeBSD 新增）；FreeBSD 1.0 因基线较早未直接继承 securelevel（4.4BSD-Lite 才引入），securelevel 须通过 FreeBSD 2.0（1994-11-22）rebase 至 4.4BSD-Lite 后方能进入 FreeBSD；FreeBSD 1.0 的安全补丁维护从此由 FreeBSD Core Team 集体治理，脱离 386BSD 单人维护模式
  
**史料**：FreeBSD 1.0 Release Announcement (1 Nov 1993)（明确说明基于 U.C. Berkeley‘s 4.3BSD-Lite (’Net/2') tape distribution）；386BSD 0.1 Release Notes (14 July 1992)；`freebsd-hackers` 邮件列表存档（1993-1994）；FreeBSD Handbook “A Brief History of FreeBSD” ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：FreeBSD 1.0 fork 386BSD 是分离后产生的新聚合，安全补丁维护从 386BSD 单人模式转为 FreeBSD Core Team 集体治理；总纲第 4 条——分离聚合是永恒规律（BSD 反向影响线）：FreeBSD 1.0 直接继承 386BSD 安全基线，是 BSD UNIX 安全基因在 FreeBSD 分支得以延续的直接史源
  
**辨析**：FreeBSD 1.0 的安全基线继承须区分 “Net/2 基础” 与 “386BSD 0.1 补丁集基础”——FreeBSD 1.0 同时继承 Net/2 与 386BSD 0.1 补丁集，安全基线来自 Net/2（即 4.3BSD-Reno 网络栈）经 386BSD 0.1 移植至 80386 平台；FreeBSD 1.0 未继承 securelevel 的考据基于 4.4BSD SMM: 16《On the Security of UNIX》（securelevel 于 4.4BSD 引入）与 FreeBSD 1.0 源代码的对照，FreeBSD 1.0 源代码中未发现 securelevel 相关代码；FreeBSD 1.0 的安全补丁维护须区分 “代码继承”（来自 386BSD 0.1）与 “补丁维护”（fork 后由 FreeBSD Core Team 独立维护）
  
**文献**：FreeBSD 1.0 Release Announcement (1 Nov 1993)；386BSD 0.1 Release Notes (14 July 1992)；FreeBSD Handbook “A Brief History of FreeBSD”；4.4BSD SMM: 16《On the Security of UNIX》 ［A］

## 66.11.2 FreeBSD 1.0 安全基线的具体内容与 4.3BSD 网络栈远程漏洞面

  **要点**：FreeBSD 1.0 继承的 386BSD 安全基线中，4.3BSD 网络栈远程漏洞面是 FreeBSD 1.0 时期最活跃的安全风险面——sendmail DEBUG 命令允许远程执行任意命令（Morris 蠕虫 1988 年利用的漏洞之一，在 4.3BSD 网络栈中持续存在）、fingerd 缓冲区溢出（Morris 蠕虫另一利用路径）、`~/.rhosts` 信任链允许无密码远程登录；FreeBSD 1.0 继承 Net/2 的密码文件布局——公开可读的 `/etc/passwd` 与仅 root 可读的 `/etc/master.passwd` 并存，pwd_mkdb(8) 生成的 `/etc/spwd.db`（含加密口令）与 `/etc/pwd.db`（口令字段以 `*` 占位）构成 shadow 机制，非 root 进程经 getpwnam(3)/getpwuid(3) 取得的口令字段为 `*`（pwd_mkdb(8) 手册页 HISTORY：首现于 4.3BSD Net/2；System V 的对应机制是 `/etc/shadow`）；基于 DES 的 **crypt(3)** 密码散列（继承自 UNIX v7）在 1993 年已显陈旧，DES 56 位密钥长度易受暴力破解，但 FreeBSD 1.0 未引入更强的密码散列算法
  
**史料**：FreeBSD 1.0 源代码中 sendmail 配置与 fingerd 实现；Morris 蠕虫技术分析（Spafford 1989 年三部分析论文）；4.3BSD 网络栈安全相关邮件列表存档；FreeBSD 1.0 `/etc/passwd` 格式文档 ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律（技术选择的代价）：FreeBSD 1.0 继承 386BSD 安全基线的代价是继承 4.3BSD 网络栈的全部远程漏洞面，这一代价在 FreeBSD 1.0 时期（1993-1994）通过社区补丁逐步缓解，但根本性解决须等待 FreeBSD 2.0 rebase 至 4.4BSD-Lite 后的 securelevel 机制与后续安全加固；0 信任原则：4.3BSD 网络栈远程漏洞面的考据须对照 FreeBSD 1.0 源代码与 Morris 蠕虫技术分析交叉验证
  
**辨析**：sendmail DEBUG 命令在 FreeBSD 1.0 中的具体状态须对照源代码核验——Morris 蠕虫 1988 年利用的 sendmail DEBUG 漏洞在 4.3BSD 后续版本中可能已修复，但 sendmail 本身作为网络服务持续暴露远程攻击面；fingerd 缓冲区溢出在 FreeBSD 1.0 中的具体状态须对照源代码核验；`~/.rhosts` 信任链是 4.3BSD 网络栈的设计特性而非漏洞，但在互联网化场景中成为安全风险；FreeBSD 1.0 时期 DES **crypt(3)** 的暴力破解风险在 1993 年已受关注但未立即引发算法替换——据 FreeBSD 4.0-RELEASE Handbook（Chapter 8.1 “DES, MD5, and Crypt”）与 FreeBSD 3.0-RELEASE FAQ（§2.22）印证：FreeBSD 1.x 及部分 2.0 前的快照使用 Nate Williams 编写的非管制散列函数，FreeBSD 2.0 起默认口令散列改为 RSA Data Security MD5 单向散列（`$1$` 前缀，Mark Murray 开发的 md5crypt）；具体散列实现仍须对照 FreeBSD 1.x 与 2.0 源代码及 release notes 核实
  
**文献**：FreeBSD 1.0 源代码；Spafford E H. The Internet Worm Program: An Analysis [J]. ACM SIGCOMM Computer Communication Review, 1989, 19(1): 17-57；4.3BSD 网络栈文档；FreeBSD 1.0 `/etc/passwd` 格式文档 ［A］

## 66.11.3 FreeBSD 2.0 rebase 至 4.4BSD-Lite 后的安全基线迁移

  **要点**：FreeBSD 2.0（1994-11-22 网络公告，12 月 CD-ROM 分发）是首个完全基于 4.4BSD-Lite 的版本，消除 Net/2 争议代码的法律风险，同时引入 4.4BSD-Lite 的新安全机制——securelevel 内核安全等级机制（level 0 不安全模式、level 1 安全模式禁止 `/dev/mem` 访问与原始磁盘写入并强制 **chflags(2)** 不可变标志、level 2 高安全模式进一步限制系统时间修改），securelevel 一旦提升至非零级即不可降级，须重启方能恢复至 level 0；FreeBSD 1.1.5.1（1994-07-01）作为 1.x 系列最后版本（过渡版），仍基于 Net/2 代码，未继承 securelevel；FreeBSD 1.x 与 4.4BSD-Lite 的基线差异导致安全补丁须在 2.0 rebase 时重新合并，Rodney W. Grimes（罗德尼·W·格赖姆斯） 于 1994-05-24/25 提交的 4.4BSD-Lite 源码导入 commit（`59deaec541ae8baaa58daf6c5a2196ea7de180c3`、`df8bae1de4b67ccf57f4afebd4e2bf258c38910d`、`26f9a76710a312a951848542b9ca1f44100450e2`）标志 FreeBSD 2.0 安全基线迁移的开始
  
**史料**：FreeBSD 2.0 Release Announcement (22 Nov 1994)（Jordan Hubbard 原始公告）；FreeBSD 1.1.5.1 RELEASE Announcement (5 Jul 1994)；4.4BSD-Lite Release Notes (1994.6)；4.4BSD SMM: 16《On the Security of UNIX》；4.4BSD PSD: 5《Berkeley Software Architecture Manual (4.4 Edition)》；bsd_commits.duckdb `tags` 表（release/2.0_cvs tagger_date 1994-11-22T10:58:58Z, Jordan K. Hubbard）与 `commits` 表（4.4BSD-Lite 导入 commit） ［A］
  
**史观**：总纲第 2 条——历史是形式主义化的非存在：FreeBSD 2.0 rebase 是 “形式（法律洁净的 4.4BSD-Lite）压倒内容（386BSD 安全基线的延续）” 的转折，securelevel 等 4.4BSD-Lite 新机制通过 rebase 进入 FreeBSD；总纲第 13 条——法律与道德是利益分配：USL v. BSDi 1994.1 和解协议（法律结构）直接决定 FreeBSD 2.0 的安全基线迁移（技术路径）
  
**辨析**：FreeBSD 2.0 rebase 至 4.4BSD-Lite 的安全基线迁移须区分 “法律洁净” 与 “安全机制升级”——前者是 rebase 的直接动机（USL 诉讼和解要求），后者是 rebase 的附带收益（securelevel 等 4.4BSD-Lite 新机制进入 FreeBSD）；securelevel 的具体级别与约束须对照 4.4BSD SMM: 16 与 PSD: 5 核实，本节叙述基于研究底稿的考据结论；FreeBSD 1.1.5.1（1994-07-01）与 FreeBSD 2.0（1994-11-22）间隔约 4 个月 22 天，须区分 “1.x 系列最后版本” 与 “2.0 系列首个版本” 的安全基线差异；【0 信任原则·commit 量不等于质量】bsd_commits.duckdb 中 4.4BSD-Lite 导入 commit 反映 rebase 工程规模但不等于安全机制迁移质量，securelevel 的实际集成状态须对照 FreeBSD 2.0 源代码核验
  
**文献**：FreeBSD 2.0 Release Announcement (22 Nov 1994)；FreeBSD 1.1.5.1 RELEASE Announcement (5 Jul 1994)；4.4BSD-Lite Release Notes (1994.6)；4.4BSD SMM: 16《On the Security of UNIX》；4.4BSD PSD: 5《Berkeley Software Architecture Manual (4.4 Edition)》；bsd_commits.duckdb `tags` 表与 `commits` 表 ［A］
