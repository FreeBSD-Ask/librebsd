# 82.6 对 4.4BSD-Lite 的批评：法律妥协与技术遗留——对 4.4BSD-Lite 法律妥协与技术遗留问题的批评

## 82.6.1 法律妥协的批评

  **要点**：对 4.4BSD-Lite 法律妥协的批评包括——删除 USL 代码导致 BSD 失去 18 个月技术窗口、和解协议条款过于模糊留下后续法律争议（如 2003 年 SCO 诉讼）、BSD 阵营被迫接受 “无 AT&T 代码” 的严格定义；法律胜利（Novell 不起诉承诺、4.4BSD-Lite 法律洁净）与市场失败（Linux 1.0 1994.3 早于 FreeBSD 2.0 1994.11.22 约 8 个月、18 个月窗口损失）的平衡经 bsd_commits.duckdb tags 表 release/2.0_cvs tagger_date 与 Linux 1.0 发布日期对照可量化

## 82.6.2 技术遗留的批评

  **要点**：对 4.4BSD-Lite 技术遗留的批评包括——4.4BSD-Lite 无法直接启动运行（需各项目补充缺失代码）、部分系统调用与库函数缺失、文档与代码不一致；技术遗留使各 BSD 项目（FreeBSD、NetBSD）需大量重建工作
  
**史料**：4.4BSD-Lite Release Notes；FreeBSD 2.0 与 NetBSD 1.0 重建档案；CSRG 内部讨论邮件［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
  
**史观**：技术选择的代价：删除 USL 代码的代价是各 BSD 项目需付出大量重建工作
  
**辨析**：技术遗留的批评——具体缺失内容与重建工作量在不同叙事中差异较大，须对照 4.4BSD-Lite 源码与 FreeBSD 2.0/NetBSD 1.0 源码 diff 核实
