# 82.1 1994.6 CSRG 发布 4.4BSD-Lite 的法律意义——不含 AT&T 代码的 “清白” 基础

## 82.1.1 发布的法律语境

  **要点**：**1994.6** 4.4BSD-Lite 发布的法律背景是 USL v. BSDi 诉讼和解——**1994 年 2 月 4 日** USL v. BSDi（BSDI 公司案）达成庭外和解（Rob Kolstad 1994-02-07 公告邮件确认）；USL v. UC Berkeley（加州大学案）为 1994 年 1 月框架和解[考据完成：2026-08-04 权威：USL v. Regents 1994-01 框架和解 vs USL v. BSDI 1994-02-04 正式和解（Rob Kolstad 公告）]，要求 Net/2 中删除 3 个 System V 共享内存/信号量相关文件、约 70 个文件添加 USL 版权声明（仍可自由再分发），CSRG 发布不含争议代码的 4.4BSD-Lite，Novell 承诺不起诉任何基于 4.4BSD-Lite 的组织或个人；4.4BSD-Lite 是法律和解产物。USL v. BSDi 和解协议关键条款如下：

| 条款 | 具体内容 | 法律效果 |
| -- | ------ | ------ |
| 完全删除文件 | 3 个 System V 共享内存/信号量相关文件 | 彻底消除争议代码 |
| 添加版权声明 | 约 70 个文件添加 USL 版权声明 | 文件本身为伯克利代码，仍可自由再分发 |
| Novell 不起诉承诺 | 不起诉任何基于 4.4BSD-Lite 的组织或个人 | 法律洁净保证 |
| 代码总量 | Net/2 共 18,000 文件中仅 3 个被完全删除 | 法律影响范围有限 |

**史料**：USL v. BSDi 和解协议 1994.1；4.4BSD-Lite Release Notes 1994.6；McKusick 1999《Twenty Years of Berkeley Unix》当事人一手叙述；CSRG 内部讨论邮件存档 ［A］；bsd_commits.duckdb 查询 L3.6.1 显示：含 license/copyright/patent/BSD 关键词的 commit 时间分布呈持续增长趋势——1992 年仅 3 commits/2 位贡献者，1993 年升至 1,719 commits/45 位贡献者，1994 年（USL 诉讼和解年）3,005 commits/62 位贡献者，1995 年（4.4BSD-Lite2 发布年）4,055 commits/95 位贡献者，1996 年 6,473 commits/149 位贡献者；1994-1996 年 license/copyright/patent/BSD 关键词 commit 量与贡献者数持续增长，反映 USL 诉讼和解后 BSD 阵营对许可证与版权议题的关注度提升，4.4BSD-Lite 的法律洁净催生了大量与许可证相关的代码提交（如版权声明添加、许可证条款更新、BSD 许可证标准化等）

**史观**：总纲第 13 条——法律与道德是利益分配：法律结构（和解协议）直接决定技术内容（4.4BSD-Lite 的代码组成）

**辨析**：删除代码的具体范围需准确区分——经 McKusick 当事人一手记载，Net/2 共 18,000 文件中仅 3 个文件被完全删除（System V 共享内存/信号量相关）、约 70 个文件添加 USL 版权声明（文件本身为伯克利代码且可自由再分发）；“75% 源文件需重写或删除” 说法无一手来源支持，属夸大叙事；【0 信任原则·关键词匹配可能误报】L3.6.1 的关键词匹配基于 message_subject LIKE ‘%license%’ OR ’%copyright%’ OR ‘%patent%’ OR ’%BSD%’，LIKE 默认大小写不敏感，可能将包含 “BSD” 一词但与许可证无关的 commit（如 “BSDCon” 会议相关、含 “BSD” 项目名但无许可证内容的 commit）误报为许可证相关 commit，1994-1996 年的 3,005-6,473 commits 量级须结合手动抽样核实关键词匹配精度；【0 信任原则·commit 量不等于质量】L3.6.1 的 license/copyright 关键词 commit 量增长反映开发者对许可证议题的关注度但不等于许可证清理工作的实际质量，部分 commit 可能仅是版权声明格式微调而非实质性许可证变更；【0 信任原则·CVS-to-Git 迁移风险】BSD 4 大 src 仓库中 netbsd-src 与 openbsd-src 均为 CVS 主仓的 GitHub 镜像，CVS-to-Git 转换可能重写 message_subject 字段，1994-1996 年关键词 commit 量基线须与各项目官方档案交叉验证

**文献**：USL v. BSDi 和解协议 1994.1；4.4BSD-Lite Release Notes 1994.6；McKusick M K. Twenty Years of Berkeley Unix [M]//DiBona C, Ockman S, Stone M. Open Sources: Voices from the Open Source Revolution. Sebastopol: O'Reilly Media, 1999 ［B］；本项目。bsd_commits.duckdb 数据分析报告：深层信息挖掘 [R/OL]. 2026.

## 82.1.2 4.4BSD-Lite 的内容

  **要点**：4.4BSD-Lite 包含 4.4BSD 的核心内核、虚拟文件系统、网络协议栈（含 TCP/IP、ISODE）、用户空间工具，但删除了所有涉及 USL 版权的代码；新增 LFS（日志结构文件系统）、Kerberos V4 客户端、ISO 9660 文件系统；总代码量约 **200 MB**。4.4BSD-Lite 内容组成如下：

| 组件 | 来源 | 说明 |
| -- | -- | -- |
| 核心内核 | 4.4BSD 继承 | 删除涉及 USL 版权的代码 |
| 虚拟文件系统 | 4.4BSD 继承 | 含 VFS 抽象层 |
| 网络协议栈 | 4.4BSD 继承 | 含 TCP/IP、ISODE |
| 用户空间工具 | 4.4BSD 继承 | 删除涉及 USL 版权的工具 |
| LFS | 4.4BSD-Lite 新增 | 日志结构文件系统 |
| Kerberos V4 客户端 | 4.4BSD-Lite 新增 | 网络认证协议 |
| ISO 9660 文件系统 | 4.4BSD-Lite 新增 | CD-ROM 文件系统 |

**史料**：4.4BSD-Lite Release Notes 1994.6；CSRG 4.4BSD-Lite 源码档案；McKusick 等人《4.4BSD 的设计与实现》；FreeBSD Handbook 含 4.4BSD-Lite 迁移历史叙述（参考文献库 ref 60）；anoncvs-paper（Cranor & de Raadt）系 OpenBSD 匿名 CVS 论文〔存疑：ref 171 “Anonymous CVS 机制源自 4.4BSD 代码分发需要”的跨项目关联待核〕 ［A］

**史观**：总纲第 5 条——没有必然性，只有偶然性：删除 USL 代码的代价是 4.4BSD-Lite 无法直接启动运行，需各项目补充缺失代码

**辨析**：4.4BSD-Lite 的具体内容在不同版本（4.4BSD-Lite 与 4.4BSD-Lite2）有差异；需区分两个版本

**文献**：4.4BSD-Lite Release Notes；McKusick《4.4BSD 的设计与实现》 ［B］

## 82.1.3 法律意义的辨析

  **要点**：4.4BSD-Lite 的法律意义是双重的——一方面 BSD 阵营获得 “无 USL 代码” 的法律洁净版本，可自由分发；另一方面删除代码的代价使 BSD 在与 Linux 竞争中失去约 18 个月技术窗口；法律意义在技术胜利（法律洁净、Novell 不起诉承诺）与市场失败（18 个月窗口损失、Linux 1.0 **1994.3** 早于 FreeBSD 2.0 **1994.11.22** 约 8 个月）之间形成张力。法律意义双重性对照如下：

| 维度 | 技术胜利 | 市场失败 |
| -- | ------ | ------ |
| 法律地位 | Novell 不起诉承诺 | — |
| 代码洁净 | 无 USL 代码 | 删除代码导致无法直接启动 |
| 时间窗口 | — | Linux 1.0 早于 FreeBSD 2.0 约 8 个月 |
| 长期影响 | BSD 法律基础确立 | 18 个月窗口损失叙事形成 |

**史料**：USL v. BSDi 和解协议；4.4BSD-Lite 分发许可；Linux 1.0 同期发展记录［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档与公告〕

**史观**：专题语（不设总纲条号）：法律意义的形式（和解协议）压倒内容（代码洁净），形成 BSD 历史的关键转折

**辨析**：法律意义的解释力存在边界——部分学者认为夸大了 18 个月窗口的长期影响（Linux 1.0 1994.3 发布时 FreeBSD 2.0 1994.11.22 发布仅晚 8 个月，且 FreeBSD 2.0 在法律洁净基础上保留了 386 硬件支持与性能优化，技术窗口损失有限）；“18 个月窗口” 说法采信度较低——诉讼从 1992.12 至 1994.1 和解约 13 个月，FreeBSD 实际重建 5 个月

**文献**：USL v. BSDi 和解协议分析；BSD 法律史研究［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 82.1.4 法律意义的史料辨析

  **要点**：4.4BSD-Lite 法律意义的史料辨析须区分 “和解协议条款” 与 “实际执行情况”——协议要求删除 USL 代码，但实际执行中部分代码的归属认定存在模糊；辨析须对照 USL v. BSDi 和解协议原文（1994.1）与 4.4BSD-Lite 源码 diff——经 McKusick 1999 当事人一手记载确认仅 3 个文件被完全删除、约 70 个文件添加 USL 版权声明，实际执行情况与协议条款一致
  
**史料**：USL v. BSDi 和解协议原文；4.4BSD-Lite 源码与 4.4BSD 源码 diff ［A］
  
**史观**：专题语（不设总纲条号）：和解协议条款（1994.1 Novell-UC Berkeley 和解协议）须对照 4.4BSD-Lite 源码与 4.4BSD 源码 diff 交叉验证——实际执行情况经 McKusick 1999 当事人一手记载确认仅 3 个文件被完全删除、约 70 个文件添加 USL 版权声明
  
**辨析**：法律意义的史料在不同叙事中差异较大——部分强调 “无 USL 代码” 的彻底性（采信 4.4BSD-Lite Release Notes 1994.6 与 Novell 不起诉承诺），部分指出实际执行的模糊性（采信 McKusick 1999 当事人一手记载关于 3 个文件被完全删除、约 70 个文件添加 USL 版权声明的具体范围）——经 USL v. BSDi 和解协议原文（1994.1）与 4.4BSD-Lite 源码 diff 逐项对照，“无 USL 代码” 的彻底性在文件删除维度成立，“实际执行的模糊性” 在版权声明添加维度成立（约 70 个文件仍含 USL 版权声明但可自由再分发），两种叙事非对立而是互补
  
**文献**：USL v. BSDi 和解协议；4.4BSD-Lite 源码档案 ［A］
