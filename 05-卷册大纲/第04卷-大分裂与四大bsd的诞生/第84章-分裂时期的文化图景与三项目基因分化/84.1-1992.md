# 84.1 1992-1996 年的文化图景——分裂时期 BSD 社区的文化特征，从 CSRG 单一中心向 FreeBSD/NetBSD/OpenBSD 三足鼎立的文化分化，三项目的文化基因差异（FreeBSD 的务实商业绑定、NetBSD 的可移植精英主义、OpenBSD 的安全审计独裁）在分裂初期的形成

## 84.1.1 文化图景的语境

  **要点**：**1992-1996 年** BSD 分裂时期的文化图景背景——386BSD、NetBSD、FreeBSD、OpenBSD 四大项目并存，各项目继承 4.3BSD-Reno 与 CSRG 文化但发展出差异化文化基因；同时期 Linux 崛起、Internet 商业化、USL 诉讼悬而未决，构成文化图景的多重张力

**史观**：总纲第 10 条——动手者创造历史。BSD 社区史的核心不是技术演进，而是人的参与与退出——文化图景作为社区主体性呈现的场域，塑造各项目的技术路径与组织模式；文化形式（slogan、邮件列表风格、社区仪式）与技术内容（代码、架构）在本体论上地位相等（总纲第 8 条 “本体论上各方平等”），不得因文化形式 “非代码” 而降格
  
**辨析**：文化图景的描述经 bsd_commits.duckdb 验证精确化——“四大项目并存” 的具体时间窗口为 1995-10-18 至 1996 年（OpenBSD 首条 commit 在 1995-10-18，但首个公开发布版本为 1.2，1996.7），1992-1995 年为 “386BSD/NetBSD/FreeBSD 三项目并存期”，1995.10 之后才进入 “四大项目并存期”；OpenBSD 1996 年的说法指首个公开发布版本 1.2 的时间，与代码层面 fork 时间 1995-10-18 不同，须区分 “代码 fork” 与 “公开发布” 两个节点

## 84.1.2 三项目的文化基因差异

  **要点**：FreeBSD、NetBSD、OpenBSD 三大项目的文化基因差异——FreeBSD 偏实用主义（与商业紧密结合）、NetBSD 偏可移植性至上（“of course it runs NetBSD”）、OpenBSD 偏安全至上（“free, functional, secure”）；文化基因差异源于创始人（Hubbard、Glass、de Raadt）的个人风格。三项目文化基因差异对照如下：

| 项目 | 文化基因 | 创始人 | 项目 slogan |
| -- | ------ | ---- | --------- |
| FreeBSD | 务实主义（与商业结合） | Jordan Hubbard | — |
| NetBSD | 可移植性至上 | Chris Demetriou、Adam Glass、Charles Hannum 等 | “of course it runs NetBSD” |
| OpenBSD | 安全至上 | Theo de Raadt（西奥·德·若特） | “free, functional, secure” |

**史观**：总纲第 5 条——没有必然性，只有偶然性。项目史观总纲第 5 章 5.1 节载 “世界上没有必然性，只有偶然性”——三项目的文化基因差异并非 “创始人风格必然塑造文化基因” 的规律展开，而是创始人风格（Hubbard、Glass、de Raadt）与项目目标（商业、可移植、安全）等偶然条件组合的层叠；5.3 节 “记忆将许多偶然性认识为一种必然性” 警示事后叙事可能将此偶然组合回溯为 “创始人风格决定文化基因” 的必然规律，须还原偶然性的根基

## 84.1.3 文化图景的形式与内容关系

  **要点**：文化作为形式要素承载技术内容——FreeBSD 的 “freebsd.cdrom.com” FTP 站点与 Walnut Creek CDROM 商业绑定形式塑造了其 Ports 系统优先服务商业用户的决策路径；NetBSD 的 “of course it runs NetBSD” 口号形式塑造了其 MI/MD 分层架构优先移植而非深度优化的工程方向；OpenBSD 的 “free, functional, secure” 标语形式塑造了其全代码审计优先于功能扩展的发布策略
  
**史料**：FreeBSD 1.0 公告中 freebsd.cdrom.com FTP 站点记录（1993.11.1）；NetBSD 1.0 Release Announcement（1994.11.8，Demetriou 明确列出 5 个二进制平台）；OpenBSD security.html 官方页面记载 “We have been auditing since the summer of 1996” ［A］
  
**史观**：总纲第 15 条——文化即形式主义：三项目的文化形式（商业绑定、可移植口号、安全标语）与各自的技术内容（Ports 系统、MI/MD 架构、代码审计）形成对应关系——形式要素在该章叙事中是技术路径选择的前置约束而非事后标签
  
**辨析**：形式与内容的关系在不同叙事中评估不一——McKusick《Twenty Years of Berkeley Unix》(1999) 强调技术决策的独立性，而 Levy《Hackers》修订版（2010）强调文化形式对技术路径的塑造；采信后者因其在 386BSD patchkit 分裂事件中有具体证据支撑
  
**文献**：FreeBSD 1.0 RELEASE Announcement (1 Nov 1993)；Demetriou C G. NetBSD 1.0 Release Announcement (8 Nov 1994)；OpenBSD security.html［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 84.1.4 文化图景的史料辨析

  **要点**：文化图景的史料辨析需区分 “文化描述” 与 “文化影响”——前者可考据（项目 slogan、邮件列表风格），后者需谨慎评估（文化对技术路径的具体影响）；辨析需平衡描述与影响
  
**史料**：BSD 邮件列表文化档案；项目 slogan 与宣言；文化影响研究文献 ［A］
  
**史观**：0 信任原则（考据规则）：文化史料（项目 slogan、邮件列表风格）可经 bsd_commits.duckdb commit 信息与邮件列表存档交叉验证，文化影响的归因须与具体技术决策（如 FreeBSD Ports 系统优先服务商业用户）对照而非笼统断言
  
**辨析**：文化史料的价值在 “描述” 维度有据可循（项目 slogan 如 FreeBSD 的 “freebsd.cdrom.com” FTP 站点记录、NetBSD 1.0 公告 5 个二进制平台列表、OpenBSD “free, functional, secure” 标语均可考据），但在 “影响” 维度须谨慎——文化对技术路径的具体影响须通过具体技术决策（如 FreeBSD 1.0 公告中 freebsd.cdrom.com FTP 站点记录与 Ports 系统优先服务商业用户的对应关系）而非笼统量化 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
