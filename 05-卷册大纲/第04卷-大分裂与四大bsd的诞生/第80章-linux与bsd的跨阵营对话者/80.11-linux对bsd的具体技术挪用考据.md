# 80.11 Linux 对 BSD 的具体技术挪用考据

## 80.11.1 概述——79 项考据案例与 4 种挪用模式

  **要点**：本节基于 79 项文化挪用案例（60 项 BSD 直接挪用 + 18 项非 BSD 系统挪用 + 1 项许可证概念挪用）的考据事实，从 [31.1](../../第02卷-伯克利的岁月/第31章-3bsd与vax/31.1-19791980年3bsd首次在vax上运行完整bsd.md) 至 31.6 的 “结构性对比” 向 “具体技术证据” 作纵深扩展，选取 18 项代表性案例归纳为 4 种模式——淡化源头模式、重写即归属模式、概念更名模式、发行版与社区文化重塑模式；4 种模式并非相互排斥而是经常在同一案例中相互渗透，形成 “叠加效应”；“平行演化与扩展超越” 作为 4 种模式的混合形态，在 BSD 与 Linux 同期演化的工具中尤为常见。4 种挪用模式归纳如下：

| 模式 | 核心机制 | 典型案例 |
| -- | ------ | ------ |
| 淡化源头 | man page、官方文档、培训教材、社区话语四渠道隐去 BSD 端一手作者与起源日期 | sudo、Berkeley sockets、BIND、sysctl、Capsicum、MCS 锁 |
| 重写即归属 | 对 BSD/UNIX 既有工具实质性重写（通常 GPL 许可），原作者被替换为重写者 | BSD Make → GNU Make、FFS → ext2/ext3/ext4、sendmail → Postfix、patch → GNU patch |
| 概念更名 | 对 BSD 端既有概念重新命名，新名称更通俗化或更具商业品牌感 | jail → container、rc.d → systemd unit、ports → package manager、devfs → devtmpfs |
| 发行版与社区文化重塑 | 在治理结构、社区协作、基金会治理、商业化路径四维度整体性重塑 | 386BSD patchkit → 发行版群、BIND → ISC → Linux Foundation、sendmail → Sendmail Inc → Proofpoint、MAC → SELinux/AppArmor |
| 混合形态 E | 平行演化与扩展超越 | BPF → eBPF、PF → nftables、syslog → rsyslog |

**史料**：原材料/研究/linux 文化挪用/ 下 8 个 BSD 直接案例子文件、案例-非 bsd.md、案例-许可证.md、模式总结.md、史学映射.md、嵌入建议.md；一手学术论文（McKusick 1984 SOSP FFS 论文、McCanne 与 Van Jacobson（范·雅各布森） 1993 USENIX BPF 论文、Killian 1984 USENIX《Processes as Files》论文）；CSRG 档案（4.4BSD-Lite Release Notes 1994-06）；设计者一手公告（PHK 1999 FreeBSD 主线 commit、Watson 与 Anderson 剑桥大学 Capsicum 项目页面）；**man7.org** / **freebsd.org** 一手手册页；互联网档案馆存档 ［A］

**史观**：总纲第 11 条——商品是形式主义：4 种挪用模式本质上是 BSD 端技术经 Linux 端“形式主义化”后封装为“开源软件商品”的权力运作过程；总纲第 17 条——证明世界先于解释和改造世界：考据的首要任务是“证明 BSD 端的先验存在”；总纲第 22 条——知识注定过时：Linux 端主流叙事建构的“Linux 原生”知识“注定过时”，数字档案将持续证明 BSD 端的先验存在

**辨析**：本节遵循 0 信任原则与三次复查流程，所有事实以一手学术论文、CSRG 档案、设计者一手公告、**man7.org** / **freebsd.org** 一手手册页、互联网档案馆存档为交叉锚，禁用维基百科与百度百科；案例编号引用规则——BSD 直接案例以“BSD 案例 N”标注（编号 1-60），非 BSD 系统案例以“非 BSD 案例 N”标注（编号 1-18），许可证概念案例以“许可证案例 N”标注（编号 1）；本节不使用“Linux 是掠夺者”“Linux 盗窃 BSD”等道德判断性表述，以考据证据呈现文化挪用现象；本节的“文化挪用”概念指 Linux 端主流叙事通过 man page、官方文档、培训教材、社区话语等渠道，将 BSD 端的一手作者、起源日期、概念先验地位系统性遮蔽的形式主义权力运作，非道德意义上的“盗窃”；此外，文化挪用现象可从两个互补维度分类——“挪用方式”维度关注 Linux 端如何从 BSD 端获取技术，可归纳为直接代码移植（如 BSD 案例 14 Berkeley sockets→Linux 网络栈、BSD 案例 50 **select(2)** API 直接沿用）、API/接口复制（如 BSD 案例 51 **fcntl(2)**、BSD 案例 55 **ioctl(2)** TIOC 操作码体系、BSD 案例 10 kqueue/kevent→epoll）、设计理念借鉴（如 BSD 案例 7 jail→container、BSD 案例 24 BPF→eBPF、BSD 案例 36 PF→nftables、BSD 案例 13 rc.d→systemd unit）、文档/术语挪用（如 BSD 案例 1 sudo man page 不回溯 4.1BSD 起源、BSD 案例 23 BIND 官方文档不点明 Terry 等 4 人姓名、BSD 案例 56 Capsicum→Landlock 不点明 Watson 与 Anderson 姓名）四类；“遮蔽方式”维度关注 Linux 端如何遮蔽 BSD 端的先验存在，归纳为淡化源头、重写即归属、概念更名、发行版与社区文化重塑四类（详见 31.11.8）；两个维度的分类非对立而是互补——“挪用方式”回答“如何拿”，“遮蔽方式”回答“如何忘”，同一案例可同时归属两个维度的多个类别

**文献**：原材料/研究/linux 文化挪用/ 全部案例文件与模式总结、史学映射、嵌入建议；一手学术论文与 CSRG 档案 ［A］

## 80.11.2 淡化源头模式典型案例

  **要点**：淡化源头模式指 Linux 端主流叙事通过 man page、官方文档、培训教材、社区话语四个渠道，将 BSD 端的一手作者、起源日期、概念先验地位系统性隐去，使读者形成“该工具或概念起源于 Linux 端”的误判；本目选取 BSD 案例 1（sudo）、BSD 案例 14（Berkeley sockets）、BSD 案例 23（BIND）、BSD 案例 57（sysctl）、BSD 案例 56（Capsicum）、BSD 案例 16（MCS 锁）6 项典型案例
  
**史料**：BSD 案例 1——Bob Coggeshall 与 Cliff Spencer 1980 年在 SUNY/Buffalo 4.1BSD VAX-11/750 平台首次设计实现 sudo，1985-12 net.sources 公告，Linux man **sudo(8)** 与 sudo.ws 官方历史页均承认 1980 SUNY/Buffalo 起源，但 LPI 认证、Red Hat RHCSA 教材、Linux Foundation 培训以“Todd C. Miller（托德·C·米勒） 1994”作为事实起点；BSD 案例 14——Bill Joy 与 Sam Leffler 1983-08 在 4.2BSD 主导的 Berkeley sockets API 被 Linux 0.96 1992-05-29 直接沿用，结构体（`struct sockaddr_in`、`struct in_addr`）与协议族编号（`PF_INET=2`、`PF_UNIX=1`）一致，但 Linux man **socket(2)** 仅以“POSIX sockets”署名；BSD 案例 23——Douglas Terry、Mark Painter、David Riggle、Songnian Zhou 1984-05 UCB/CSD-84-182 论文与 4.3BSD 1986-06 集成是 BIND 的源头，Terry 等 4 人姓名在 BIND 9 官方文档、Linux Foundation DNS-WG 培训中完全缺席；BSD 案例 57——**sysctl(2)** 系统调用与 **sysctl(8)** 命令首次出现于 4.4BSD 1994-06，Linux man-pages **sysctl(2)** 手册页“HISTORY”段明确记载“4.4BSD, Linux 1.3.57”，是 Linux 端承认 BSD 源头的罕见案例，但 procps-ng 项目文档不点明 BSD 源头；BSD 案例 56——Robert N. M. Watson（罗伯特·N·M·沃森） 与 Jonathan Anderson 2010-2011 在剑桥大学主导设计的 Capsicum，2012-01-12 FreeBSD 9.0-RELEASE 实验性集成，Mickaël Salaün 2016-2021 推进 Landlock 至 2021-06-27 Linux 5.13 合入主线，Linux man **landlock(7)** 主流叙事中 Watson 与 Anderson 姓名几近缺席；BSD 案例 16——Mellor-Crummey 与 Scott 1991-04 ACM TOCS 论文是 MCS 锁的权威学术公开，Waiman Long 2017-10 的 qspinlock patch 实际为 MCS 锁的简化优化版，但 kernelnewbies.org、LWN、Red Hat 培训材料以“derived from MCS lock”一笔带过 ［A］
  
**史观**：同 79.11.1 总述，总纲第 17 条——证明世界先于解释和改造世界：淡化源头模式的考据正是“证明 BSD 端的先验存在”，将 Linux 端 man page、官方文档、培训教材、社区话语四渠道隐去的一手作者与起源日期重新显化于历史叙事之中
  
**辨析**：淡化源头模式的考据须警惕“多源交叉验证一致”的简化陷阱——Linux man page 与培训材料的“内部一致性”恰恰是叙事建构的产物，须以一手学术论文、CSRG 或 SCCS 档案、设计者一手公告作交叉锚；6 项案例的“先验存在”均经一手档案印证——Coggeshall 与 Spencer 1985-12 net.sources 公告印证 sudo 1980 起源、4.2BSD 1983-08 Release Notes 印证 sockets 起源、UCB/CSD-84-182 论文印证 BIND 1984 起源、4.4BSD-Lite 1994-06 Release Notes 印证 sysctl 起源、FreeBSD 9.0-RELEASE 2012-01-12 公告印证 Capsicum 起源、Mellor-Crummey 与 Scott 1991-04 ACM TOCS 论文印证 MCS 锁起源；【0 信任原则】部分案例存在 Linux 端承认 BSD 源头的罕见样本（如 **sysctl(2)** 手册页“HISTORY”段），但承认不等于主流叙事已还原——procps-ng 文档与 Linux 培训叙事仍将 sysctl 视为 Linux 原生机制
  
**文献**：BSD 案例 1、14、23、57、56、16 案例文件；Coggeshall 与 Spencer 1985-12 net.sources 公告；4.2BSD Release Notes 1983-08；UCB/CSD-84-182 论文 1984-05；4.4BSD-Lite Release Notes 1994-06；FreeBSD 9.0-RELEASE 公告 2012-01-12；Mellor-Crummey 与 Scott 1991-04 ACM TOCS 论文 ［A］

## 80.11.3 重写即归属模式典型案例

  **要点**：重写即归属模式指 Linux 或 FSF 端对 BSD 或 UNIX 端既有工具进行实质性重写（通常采用 GPL 许可证）后，主流叙事将原作者替换为重写者，原作者姓名、机构、公告日期等关键归属信息被抹去或退居次要位置；本目选取 BSD 案例 11（BSD Make → GNU Make）、BSD 案例 15（FFS → ext2/ext3/ext4）、BSD 案例 22（sendmail → Postfix）、BSD 案例 17（patch → GNU patch）4 项典型案例
  
**史料**：BSD 案例 11——Stuart Feldman 1976 在 Bell Labs 设计 Make，Adam de Boor 1986-1987 编写 pmake（BSD Make），Richard Stallman 与 Roland McGrath 1988 起为 FSF 重写 GNU Make，1993 GNU Make 3.0 公开，Feldman 1976 起源与 pmake 1986 扩展在 GNU Make 官方手册中被弱化为“早期 Make 历史”；BSD 案例 15——Marshall Kirk McKusick（马歇尔·柯克·麦库西克） 1983-08 随 4.2BSD 设计并发布 FFS（cylinder group、block size 4K、rotation optimization），1984 SOSP 论文权威学术公开，Rémy Card 1993-01 提交 ext2 至 Linux 0.99.x，Stephen Tweedie 1999-11 引入 ext3 journal，Theodore Ts'o 2006-10 ext4 experimental、2008-10-24 Linux 2.6.28 ext4 stable，FFS cylinder group 哲学在 Linux Foundation 培训中被淡化为“类似设计”；BSD 案例 22——Eric Allman（埃里克·奥尔曼） 1979 在 UCB 编写 delivermail 随 BSD 4.0 释出，1983 sendmail 1.0 随 4.1cBSD 释出，1996 年约 80% 公网邮件服务器运行 sendmail，Postfix 1997 Wietse Venema 在 IBM T.J. Watson Research Center 编写、1998-12-14 首次发布，qmail 1995-12 Daniel J. Bernstein 起编写、1.03 1998-06-15 final，Eric Allman 1983 BSD 起源在 Postfix 与 qmail 官方文档中不被点明；BSD 案例 17——Larry Wall 1984 起编写 patch 工具，1985-05-08 mod.sources 公告 patch 1.3（<wall@sdcrdcf.UUCP>），FSF 1990 年代初 fork 出 GNU patch，Wall 1985-05-08 公告日期与 <wall@sdcrdcf.UUCP> 在 Linux 端主流叙事中几近消失，构成“无更名的事实更名”——代码同名但归属被替换 ［A］
  
**史观**：同 79.11.1 总述，总纲第 11 条——商品是形式主义：重写即归属是 BSD 端技术经 GPL 重写后封装为“开源软件商品”的典型权力运作；总纲第 22 条——知识注定过时，重写者建构的“Linux 原生”叙事终将被代码血缘考据证伪
  
**辨析**：重写即归属模式的考据须警惕“工程量大即原创性强”的简化陷阱——重写者在重写过程中确实投入大量工程量，但“工程量大”不等于“原创性强”，须以重写 commit 中的“代码血缘”（关键函数签名、blame 历史、SCCS 或 CVS 起点）作交叉验证；4 项案例的“代码血缘”均有据可循——GNU Make 的变量扩展与模式规则承袭 Feldman 1976 Make 与 pmake 1986 扩展、ext4 的 cylinder group 哲学承袭 McKusick 1983 FFS、Postfix 的 mail queue 与 MTA 架构承袭 Allman 1983 sendmail、GNU patch 的 context diff 与 unified diff 逻辑承袭 Wall 1985 patch；【0 信任原则】重写版的“重新设计”自我定位须经代码血缘比对验证，不得仅凭重写者自述即采信
  
**文献**：BSD 案例 11、15、22、17 案例文件；Feldman 1976 Make 论文；McKusick 1984 SOSP FFS 论文；Allman 1983 sendmail 4.1cBSD 发布记录；Wall 1985-05-08 mod.sources patch 1.3 公告 ［A］

## 80.11.4 概念更名模式典型案例

  **要点**：概念更名模式指 Linux 端对 BSD 端既有概念进行重新命名，新名称更通俗化或更具商业品牌感，使概念源头在新的命名下被遮蔽；本目选取 BSD 案例 7（jail → container）、BSD 案例 13（rc.d → systemd unit）、BSD 案例 5（ports → package manager）、BSD 案例 58（devfs → devtmpfs）4 项典型案例
  
**史料**：BSD 案例 7——Poul-Henning Kamp（波尔-亨宁·坎普） 1999 年设计 **jail(2)** 并 commit 进 FreeBSD 主线，2000-03-14 随 FreeBSD 4.0-RELEASE 首次公开发布（“OS-level virtualization”概念原型），Linux 端 LXC 2008-08-06（IBM 主导）、Docker 2013-03-20（Solomon Hykes）、Podman 2018（Red Hat）均以“container”自我标榜，主流第三方源偶有“similar to FreeBSD jails”式比附一笔带过；BSD 案例 13——V7 Unix 1979-01 Ken Thompson 释出 **/etc/rc** 单文件脚本，4.4BSD-Lite 1994-06 释出基于目录的 **/etc/rc.d/** 框架，NetBSD 1.3 1998-01-04 Luke Mewburn（卢克·缪伯恩） 重构（引入 **rcorder(8)** 与 rc.subr 与 PROVIDE 与 REQUIRE 元数据），Lennart Poettering（伦纳特·珀特林） 2010-03-30 首次 commit systemd，将“init script”重新命名为“unit”（`.service`、`.socket`、`.target`、`.mount`、`.timer`、`.path`），Poettering 2010-04-30 博客明确承认借鉴 NetBSD rc.d 与 Mac OS X launchd，但 systemd 主流叙事以“现代 init 设计”自我标榜；BSD 案例 5——FreeBSD 1.0 1993-11 将 BSD `pkg_add` 与 `pkg_delete` 与 `pkg_info` 与 `pkg_create` 工具集纳入基础系统，并以“ports”作为用户态源码包管理框架（FreeBSD ports 系统定型于 1994 至 1995），Debian 0.91 1994-01 释出 dpkg、1998-03-31 apt 公开，Red Hat 1995 rpm 释出，Linux 端软件包管理器均以“package manager”自我标榜，将 BSD“ports”概念更名为“package manager”；BSD 案例 58——Dima Dorfman 设计的 devfs 以“内核动态维护设备节点”哲学取代传统静态 **/dev** 目录与用户态 `mknod` 命令，FreeBSD 5.0-RELEASE 2003-01-19 首次以默认文件系统形式引入，Kay Sievers 2009-04-30 向 LKML 提交 devtmpfs patch，Linux 2.6.32 2009-12 首次将 devtmpfs 合入主线，“devfs”概念在 Linux 端被更名为“devtmpfs”以与 systemd 与 udev 体系绑定 ［A］
  
**史观**：同 79.11.1 总述，总纲第 11 条——商品是形式主义：概念更名以更通俗或更具商业品牌感的新名称将 BSD 端既有概念重新封装为“开源软件商品”，遮蔽概念源头
  
**辨析**：概念更名模式的考据须警惕“功能差异即原创”的简化陷阱——更名后概念的功能可能确实有差异，但功能差异不等于哲学原创；“container 不等于 jail”的差异（cgroup 与 namespace 对 **jail(2)**）是工程实现差异，不是哲学原创；4 项案例的“先验存在”均经一手档案印证——PHK 1999 FreeBSD 主线 commit 与 FreeBSD 4.0-RELEASE 2000-03-14 公告双源印证 jail 起源、4.4BSD-Lite 1994-06 **/etc/rc.d/** 框架与 NetBSD 1.3 1998-01-04 **rcorder(8)** 印证 rc.d 起源、FreeBSD 1.0 1993-11 `pkg_add` 工具集印证 ports 起源、FreeBSD 5.0-RELEASE 2003-01-19 公告印证 devfs 起源；【0 信任原则】Poettering 2010-04-30 博客承认借鉴 NetBSD rc.d 是“和解”的碎片，但主流叙事的整体倾向仍以“现代 init 设计”自我标榜
  
**文献**：BSD 案例 7、13、5、58 案例文件；PHK 1999 FreeBSD 主线 commit；FreeBSD 4.0-RELEASE 公告 2000-03-14；4.4BSD-Lite Release Notes 1994-06；NetBSD 1.3 1998-01-04 release notes；FreeBSD 1.0 1993-11 release notes；FreeBSD 5.0-RELEASE 公告 2003-01-19 ［A］

## 80.11.5 发行版与社区文化重塑模式典型案例

  **要点**：发行版与社区文化重塑模式指 Linux 端不仅挪用 BSD 端的具体技术，更在“项目治理结构、社区协作模式、基金会治理、商业化路径”四个维度对 BSD 模式进行整体性重塑——既吸收 BSD 端“开放治理加学术共享加社区维护”的核心要素，又通过基金会化、商业化、商标认证、供应商化等机制封装为可销售、可估值、可并购的“开源软件商品”；本目选取 BSD 案例 2-4（386BSD patchkit → 发行版群）、BSD 案例 23（BIND → ISC → Linux Foundation 式治理）、BSD 案例 22（sendmail → Sendmail Inc → Proofpoint）、BSD 案例 59（MAC 框架 → SELinux/AppArmor）4 项典型案例
  
**史料**：BSD 案例 2-4——386BSD 由 Bill Jolitz 与 Lynne Jolitz 夫妇 1992-03-12 在 comp.unix.bsd 公告 0.0 版、1992-07-14 释出 0.1 版，patchkit 协作模式（社区维护者收集 bug 修复后回向原作者提交）成为 1990 年代 BSD 社区典型的分布式协作模式，Slackware 1.0 由 Patrick Volkerding 1993-07-17 在 MSU FTP 发布、Debian 0.91 1994-01 Ian Murdock 在 Purdue University 释出，Debian Manifesto 1993-08-16 明确宣布“社区化开源发行版”定位，但 Linux 主流叙事将该模式归因于“Linus Torvalds 开放开发文化”或“FSF 自由软件精神”，淡化 386BSD patchkit 模式与 CSRG 学术共享传统的承袭；BSD 案例 23——Paul Vixie 1988 接管 BIND 4.9，1994 创立 Internet Software Consortium（ISC，与 Rick Adams 与 Carl Malamud 共同创立，1998 改组为非营利组织），ISC 模式（单一项目加非营利组织加长期维护者）实质上是 NetBSD Foundation 1994-04 治理模式的“商业变体”，为后续 Linux Foundation 2007 治理模式提供模板；BSD 案例 22——Eric Allman 1999-10 创立 Sendmail Inc.（商业公司），2013-10-01 被 Proofpoint Inc. 收购，sendmail 是 BSD 系软件最早实现“开源到商业公司到被收购”完整商业化路径的样本；BSD 案例 59——TrustedBSD 项目的 MAC（Mandatory Access Control）框架由 Robert Watson 与 Chris Costello 与 others 1999-2002 在 FreeBSD 主导设计，2003-01-19 FreeBSD 5.0-RELEASE 首次集成 MAC 框架，SELinux 由 NSA 与 SCC 与 MITRE 2000 起开发、2003-08 在 Linux 2.6.0-test3 合入主线，AppArmor 由 Immunix 1998 起编写、2006 由 Novell 主导，SELinux 与 AppArmor 在 Linux 端通过 Red Hat 与 Novell 商业发行版绑定形式化为“Linux 安全标准”，MAC 框架的 FreeBSD 起源与 TrustedBSD 学术传统被弱化为“早期的尝试” ［A］
  
**史观**：同 79.11.1 总述，总纲第 11 条——商品是形式主义：发行版与社区文化重塑在项目治理结构、社区协作模式、基金会治理、商业化路径四维度整体性重塑 BSD 模式，是“形式主义化”权力运作的最高层级
  
**辨析**：发行版与社区文化重塑模式的考据须警惕“独立演化即无承袭”的简化陷阱——模式四的“重塑”往往伴随真实的公司治理演进（如 Red Hat 1993 → IBM 2019），不能简单等同于“挪用”，须以“治理结构、决策机制、知识产权归属”三个维度区分“独立演化”与“承袭后重塑”；4 项案例的“承袭后重塑”均有据可循——386BSD patchkit 1992-07 协作模式先于 Debian Manifesto 1993-08-16“社区化开源发行版”定位约 13 个月、ISC 1994 创立先于 Linux Foundation 2007 治理模式约 13 年、Sendmail Inc 1999-10“开源到商业公司”路径先于 Docker Inc 2013“container 商业化”路径约 14 年、FreeBSD MAC 框架 2003-01-19 先于 SELinux 2003-08 合入 Linux 主线约 7 个月；【0 信任原则】ISC 模式与 NetBSD Foundation 1994-04 治理传统的承袭关系须经 ISC 创立档案与 NetBSD Foundation 章程交叉验证，不得仅凭时序相近即断定承袭
  
**文献**：BSD 案例 2-4、23、22、59 案例文件；386BSD 0.0/0.1 comp.unix.bsd 公告 1992-03-12/1992-07-14；Debian Manifesto 1993-08-16；ISC 创立记录 1994；NetBSD Foundation 1994-04 章程；Sendmail Inc 创立记录 1999-10；Proofpoint 收购公告 2013-10-01；FreeBSD 5.0-RELEASE 公告 2003-01-19；Linux 2.6.0-test3 SELinux 合入记录 2003-08 ［A］

## 80.11.6 平行演化与扩展超越（混合形态 E）

  **要点**：平行演化与扩展超越是 4 种模式的混合形态——平行演化指同一时期两个生态独立开发功能相似的工具，但设计理念相互借鉴，最终 Linux 版本因市场或生态优势成为事实标准，BSD 平行方案被边缘化；扩展超越指 Linux 端在 BSD 原创基础上进行重大工程扩展，扩展部分的巨大成功反向建构“Linux 原创”叙事，BSD 原始贡献被弱化为“灵感来源”或“历史脚注”；本目选取 BSD 案例 24（BPF → eBPF）、BSD 案例 36（PF → nftables）、BSD 案例 31（syslog → rsyslog）3 项典型案例
  
**史料**：BSD 案例 24——Steven McCanne 与 Van Jacobson（LBL）1992 至 1993 设计 BPF，论文《The BSD Packet Filter: A New Architecture for User-level Packet Capture》发表于 USENIX Winter 1993（1993-01），随 4.4BSD 1994-06 集成进 BSD 内核，Alexei Starovoitov 与 Daniel Borkmann 2014 年起将 BPF 扩展为 eBPF，从“数据包过滤虚拟机”扩展为支持网络、跟踪、安全、性能分析的通用内核虚拟机（Linux 3.18 2014-12 雏形、Linux 4.1 2015-06 成熟），eBPF 在虚拟机核心设计（累加器、寄存器、指令集、辅助函数调用约定）上承袭自经典 BPF 1993，但在 CNCF 与 eBPF Foundation 营销材料中常被描述为“Linux 内核革命性技术”，McCanne 与 Van Jacobson 1993 原创被弱化为“BPF 起源于 BSD”；BSD 案例 36——Daniel Hartmeier（丹尼尔·哈特迈尔） 主导 OpenBSD 团队 2001 年开发 PF，随 OpenBSD 3.0 2001-12-01 首次公开发布，Rusty Russell 与 Harald Welte 团队 2000 至 2001 开发 netfilter 与 iptables（Linux 2.4 2001-01 稳定），比 PF 早 11 个月，属于平行演化，Patrick McHardy 与 Pablo Neira Ayuso 团队 2014 年发布 nftables（Linux 3.13 2014-01-19），引入“sets”（类似 PF tables）、“chains in tables”（类似 PF anchors），netfilter 核心开发者 Pablo Neira Ayuso 在多个场合承认 PF 的设计对 nftables 的启发，但 nftables 官方文档将 nftables 建构为“iptables 的下一代演进”，PF 作为平行方案的影响被最小化；BSD 案例 31——Eric Allman 1980 至 1983 年在 CSRG 为 sendmail 设计 syslog，随 4.2BSD 1983-08 首次公开发布（库接口）、4.3BSD 1986-06 包含完整 syslogd 守护进程，RFC 3164 2001-08 明确记载"originally developed in the 1980s by Eric Allman for the sendmail project"，Rainer Gerhards 2004 年从 sysklogd fork 出 rsyslog，增加 TCP 与 TLS 传输、RELP 可靠传输、Kafka 与 Elasticsearch 输出、结构化日志、过滤规则等，成为 RHEL 与 CentOS 与 Ubuntu 默认 syslog 实现，rsyslog 官方文档将自身描述为“rocket-fast system for log processing”，对 sysklogd 起源与 BSD syslog 根源仅以简短“based on sysklogd”带过 ［A］
  
**史观**：同 79.11.1 总述，总纲第 17 条——证明世界先于解释和改造世界：平行演化案例仍须先“证明 BSD 端的先验存在”；总纲第 22 条——知识注定过时，Linux 端“扩展超越”建构的“Linux 原创”叙事注定过时
  
**辨析**：平行演化与扩展超越的考据须区分“核心设计承袭”与“工程实现扩展”——扩展规模大不等于原创性强，须以虚拟机核心设计、辅助函数签名、API 兼容性等具体血缘作交叉锚；3 项案例的“核心设计承袭”均有据可循——eBPF 在累加器、寄存器、指令集、辅助函数调用约定上承袭 BPF 1993、nftables 在 sets 与 chains 设计上承袭 PF 2001（Pablo Neira Ayuso 本人承认）、rsyslog 在 facility 与 severity 双层分类与 **syslog(3)** API 上承袭 BSD syslog 1983；【0 信任原则】“平行演化”与“扩展超越”的区分须经设计理念比对与时序比对交叉验证——iptables 2001-01 比 PF 2001-12 早 11 个月属平行演化，eBPF 2014 比 BPF 1993 晚 21 年属扩展超越，二者非同一形态
  
**文献**：BSD 案例 24、36、31 案例文件；McCanne 与 Van Jacobson 1993 USENIX BPF 论文；4.4BSD 1994-06 集成记录；OpenBSD 3.0 2001-12-01 PF 发布记录；Linux 2.4 2001-01 netfilter/iptables 发布记录；Linux 3.13 2014-01-19 nftables 发布记录；RFC 3164 2001-08；4.2BSD 1983-08 syslog 发布记录 ［A］

## 80.11.7 GEOM → device-mapper 与四种模式的相互渗透

  **要点**：BSD 案例 60（GEOM Framework → Linux device-mapper）展示四种模式在同一案例中的相互渗透——GEOM 由 Poul-Henning Kamp 与 Pawel Jakub Dawidek 在 FreeBSD 5.0-RELEASE 2003-01-19 引入，以“模块化存储栈分层”哲学取代传统静态磁盘驱动，Linux device-mapper 由 Joe Thornber 2001-10 在 Linux 2.4.19 首次引入（比 GEOM 早约 15 个月，属平行演化），但 device-mapper 在 LVM2 与 dm-crypt 与 dm-multipath 的工程扩展上承袭 GEOM 的“provider 与 consumer 分层”哲学，GEOM 起源在 Linux device-mapper 主流叙事中被淡化（模式一），device-mapper 以“Linux 原生存储栈”自我标榜（模式三：概念更名），经 Red Hat 商业发行版绑定形式化为“Linux 存储标准”（模式四：社区重塑）
  
**史料**：BSD 案例 60——Poul-Henning Kamp 与 Pawel Jakub Dawidek 设计的 GEOM Framework 以“模块化存储栈分层”哲学（provider 与 consumer 分层、taste 机制、class 与 geom 与 consumer 三层抽象）取代传统静态磁盘驱动，FreeBSD 5.0-RELEASE 2003-01-19 首次引入 GEOM；Joe Thornber 2001-10 在 Linux 2.4.19 首次引入 device-mapper（比 GEOM 早约 15 个月），device-mapper 在 LVM2 与 dm-crypt 与 dm-multipath 的工程扩展上承袭 GEOM 的“provider 与 consumer 分层”哲学，但 device-mapper 官方文档与 Red Hat 培训材料以“Linux 原生存储栈”自我标榜，GEOM 与 FreeBSD 5.0 起源在 device-mapper 主流叙事中被淡化 ［A］
  
**史观**：同 79.11.1 总述，总纲第 11 条——商品是形式主义：GEOM → device-mapper 单案例内淡化源头、概念更名、社区重塑三模式叠加渗透，是“形式主义化”权力运作的浓缩样本
  
**辨析**：GEOM → device-mapper 案例的考据须注意时序复杂性——device-mapper 2001-10 比 GEOM 2003-01 早约 15 个月，属“平行演化”而非“BSD 先验、Linux 后仿”的简单形态；但 device-mapper 在 LVM2 与 dm-crypt 与 dm-multipath 的工程扩展中承袭 GEOM 的“provider 与 consumer 分层”哲学，这一承袭关系须经 GEOM 设计文档与 device-mapper 源码比对交叉验证，不得仅凭时序相近即否定承袭；【0 信任原则】“平行演化”与“承袭后重塑”可同时存在——device-mapper 2001-10 与 GEOM 2003-01 在“模块化存储栈”概念上属平行演化，但 device-mapper 后续工程扩展中承袭 GEOM 的“provider 与 consumer 分层”哲学属“承袭后重塑”，二者非互斥
  
**文献**：BSD 案例 60 案例文件；FreeBSD 5.0-RELEASE 公告 2003-01-19；Linux 2.4.19 device-mapper 发布记录 2001-10；GEOM 设计文档；device-mapper 源码与文档 ［A］

## 80.11.8 四种模式的归纳与考据留痕

  **要点**：4 种模式（淡化源头、重写即归属、概念更名、发行版与社区文化重塑）并非相互排斥，而是经常在同一案例中相互渗透——BSD 案例 7（jail → Docker → OCI）同时展示模式一（PHK **1999 年** 设计被淡化）、模式二（Docker 重写为 libcontainer 与 runc）、模式三（“jail”被更名为“container”）、模式四（OCI **2015-12-08** 加入 Linux Foundation 托管）四种模式的叠加效应；BSD 案例 13（rc.d → systemd）同时展示模式二（systemd 重写 rc.d）、模式三（“init script”被更名为“unit”）、模式四（systemd 经 Red Hat 商业发行版与 freedesktop.org 治理重塑）三种模式的叠加；本节 18 项代表性案例覆盖 4 种模式与混合形态 E，完整 79 项案例详见原材料/研究/linux 文化挪用/ 索引
  
**史料**：原材料/研究/linux 文化挪用/ 全部 79 项案例文件与模式总结.md 的 4 种模式归纳与混合形态 A 至 E 分析 ［A］
  
**史观**：总纲第 11 条——商品是形式主义：4 种模式本质上是 BSD 端技术经 Linux 端“形式主义化”后封装为“开源软件商品”的权力运作过程；总纲第 17 条——证明世界先于解释和改造世界：考据的首要任务是“证明 BSD 端的先验存在”，使被遮蔽的“BSD 存在”重新生成于历史叙事之中；总纲第 22 条——知识注定过时：Linux 端主流叙事建构的“Linux 原生”知识“注定过时”，数字档案（互联网档案馆、CSRG 档案、一手论文、一手公告）将持续证明 BSD 端的先验存在
  
**辨析**：4 种模式的归纳遵循“非穷尽性、非排他性、非客观性”原则——非穷尽性指每条模式仅列举典型案例，79 项案例中至少 30 项以上可作淡化源头模式的候选；非排他性指同一案例可同时归属多种模式（如 BSD 案例 7 jail → Docker 同时归属模式一、二、三、四）；非客观性指本归纳基于项目统摄史观，是项目统摄史观视角下的“形式主义化”建构，不宣称“客观真实”；考据过程留痕见原材料/研究/linux 文化挪用/ 各案例文件中的一手来源标注与互联网档案馆存档 URL；【0 信任原则】本节不宣称“穷尽考据”，而是坦承“考据过程的有限性”——部分一手档案可能在未来被编辑、修订、删除（如 Linux Foundation 与 Red Hat 与 Docker Inc 等商业实体的官方档案），部分案例存在 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］，穷尽考据后仍无法确证的允许保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
