- 被遗忘的贡献者辨析须识别两类——“技术贡献被低估”（如补丁作者、文档作者，其工作可经 bsd_commits.db commit 数与邮件列表补丁提交记录量化）与“非技术贡献被忽视”（如组织者、翻译者、调解者，其工作须从 BSD 大会组织档案与非英语 BSD 社区档案挖掘）；两类贡献者的史料都须从原始档案主动挖掘，不得仅依赖主流叙事
- 边缘贡献者的史料辨析须经三类史料交叉验证——技术贡献（bsd_commits.db 代码提交、BSD 邮件列表补丁提交记录）、文化贡献（BSD 教程存档如 Dru Lavigne FreeBSD 新闻网教程、BSD 文档如 Handbook 与 FAQ、BSDCon 演讲存档）、组织贡献（BSD 大会组织记录、非英语 BSD 文档翻译项目、社区调解邮件存档）；三类史料须交叉验证，不得仅依赖代码提交记录评估贡献
- 本节基于 79 项文化挪用案例（60 项 BSD 直接挪用 + 18 项非 BSD 系统挪用 + 1 项许可证概念挪用）的考据事实，从 31.1 至 31.6 的 “结构性对比” 向 “具体技术证据” 作纵深扩展，选取 18 项代表性案例归纳为 4 种模式——淡化源头模式、重写即归属模式、概念更名模式、发行版与社区文化重塑模式；4 种模式并非相互排斥而是经常在同一案例中相互渗透，形成 “叠加效应”；“平行演化与扩展超越” 作为 4 种模式的混合形态，在 BSD 与 Linux 同期演化的工具中尤为常见。4 种挪用模式归纳如下：
