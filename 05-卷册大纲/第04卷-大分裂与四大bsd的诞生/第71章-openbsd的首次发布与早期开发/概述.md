### 观点

- (vbsdcon, 2017)：Vixie 指出，自 Morris 蠕虫以来 BSD 已大幅现代化，包括追踪 ANSI C 与 POSIX LibC；可移植性被视为保持相关性与成功所必需，但“早该做出一些艰难但明智的选择——包含什么、模拟什么、抛弃什么、直接下毒”。此观点可与 68.8 节全代码审计方法论的建立相互印证，揭示 OpenBSD 安全驱动的底层哲学动因。（单一文献支撑，需后续交叉验证）

### 说明

- (vbsdcon, 2017)：1988 年 11 月 2 日 Morris 蠕虫爆发时的起始条件——`inetd` 默认处处开启、`fingerd` 默认处处开启、防火墙尚未发明、`fingerd` 使用 `gets()`；Robert T. Morris 编写的演示蠕虫中包含非演示性 bug，导致“一切失控”。这为 68.11 节 OpenBSD 早期安全驱动淘汰史——从 r-commands 到 telnetd 的逐步退役——提供了直接的史源背景。（单一文献支撑，需后续交叉验证）
- (bsdcan, 2018)：Stucchi 指出 BSD 路由器（FreeBSD、OpenBSD、pfSense）广泛部署于家庭与边缘网络，IPv6 渗透率在印度与比利时已超 50%、德国与乌拉圭与美国与希腊约 40%。这为 68.12 节与同时期操作系统的比较中 OpenBSD 的网络定位提供了后续演化的参照点。（单一文献支撑，需后续交叉验证）

### 批评

- (vbsdcon, 2017)：Vixie 批评 C 语言缺乏边界检查“太简单了”——“比 PDP-11 汇编好”是低门槛；ANSI C 必须尽可能保留既有代码，因此不兼容性被限制，直到 C11 才移除任何内容；`gets()` 在 C89 中存在，在 C++11 中仍然存在。`strlcpy()` 与 `strlcat()` 虽增加边界检查、确保 `\0` 终止，但截断仍可能是未定义结果。此批评为 68.8 节全代码审计方法论提供了审计对象的史源依据。（单一文献支撑，需后续交叉验证）

### 褒奖

- (vbsdcon, 2017)：FreeBSD 对 `gets()` 问题的响应——链接时产生警告"this program uses gets(), which is unsafe"，运行时再次警告，体现了 BSD 系统对不安全接口的主动防御态度。此褒奖可与 OpenBSD 的全代码审计方法论（68.8 节）形成跨项目对照，揭示两条不同的安全路径：链接时警告 vs 源码级审计。（单一文献支撑，需后续交叉验证）
