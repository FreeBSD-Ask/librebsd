# 71.7 1995 年 10 月 CVS 仓库初始导入与 1996 年 7 月 OpenBSD 1.2 首次发布

## 71.7.1 OpenBSD 项目的启动

  **要点**：OpenBSD 项目启动于 1995 年——基于 NetBSD 1.0 源码分叉，de Raadt 与早期开发者进行全代码审计与安全加固；1995 年 10 月 18 日完成 CVS 仓库初始导入，标志项目正式启动；开发过程强调代码质量与安全性
  
**史料**：OpenBSD CVS 历史早期记录（1995.10.18 初始导入）、de Raadt 个人主页自述；openbsd.duckdb 数据库证据——openbsd-src 仓库首条 commit 为 deraadt 1995-10-18T08:37:01Z “initial import of NetBSD tree”（commit_hash `df930be708d50e9715f173caa26ffe1b7599b157`），author_date 与 committer_date 完全一致，与大纲记载 1995 年 10 月 18 日 CVS 仓库初始导入完全吻合；OpenBSD src GitHub 镜像 1995-10 月共 30 个 commit，全部由 deraadt 提交，commit message 内容包括 “initial import of NetBSD tree”（首条）、"initial import of pica stuff (a few theo modifications already in here)“（第 2 条）、”mvme68k port by me. some parts by dale rahn."（第 3 条）等，证实 fork 后立即进行多平台代码 import；deraadt（Theo de Raadt）在 netbsd-src 末次 commit 为 1994-12-17T23:12:41Z（commit_hash `699d2a37b0e3c0c6ff29ea0d407c3feeba5642b4`，subject “correct ie [1234] addreses”），与其被 NetBSD 核心团队撤销 commit bit 的时间吻合；deraadt 在 openbsd-src 首次 commit（1995-10-18T08:37:01Z）与 netbsd-src 末次 commit（1994-12-17T23:12:41Z）间隔约 304 天（约 10 个月），此期间为 Theo de Raadt 筹备 OpenBSD 项目的筹备阶段；deraadt 在 openbsd-src 共 27181 个 commit，末次 commit 为 2026-07-16T22:03:31Z，是 OpenBSD 项目最长持续贡献者 ［A］

## 71.7.2 OpenBSD 1.2 的首次公开发布

  **要点**：**OpenBSD 1.2** 于 **1996 年 7 月** 发布——作为 OpenBSD 项目首个正式公开版本；发布标志 OpenBSD 作为独立 BSD 项目正式进入公众视野；**1996 年 10 月** 发布 **OpenBSD 2.0**，确立每 6 个月一个大版本的发布节奏。OpenBSD 早期版本发布时间线如下：

| 版本 | 发布日期 | 备注 |
| -- | ------ | -- |
| OpenBSD 1.0/1.1 | 1995-1996 年内部 | 从未公开发布 |
| OpenBSD 1.2 | 1996-07 | 首次公开发布 |
| OpenBSD 2.0 | 1996-10 | 确立 6 个月发布节奏 |

**史料**：OpenBSD 1.2 发布声明（1996.7）、OpenBSD 2.0 发布声明（1996.10）、OpenBSD 官方 FAQ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；openbsd.duckdb 查询 L1.1.1 显示：openbsd-src 1995 年仅 770 commits（占当年 4 大 BSD src 仓库总量 20,656 的 3.73%），反映 1995.10.18 fork 后至年底的启动阶段 commit 活跃度有限；1996 年 openbsd-src = 5,240 commits（占当年 4 大 BSD src 仓库总量 29,245 的 17.92%），较 1995 年增长约 6.8 倍，反映 OpenBSD 1.2 发布当年开发活跃度大幅提升，与 OpenBSD 1.2 首次公开发布（1996.7）的工程节奏吻合

**史观**：总纲第 2 条——分离与聚合：OpenBSD 1.2 的发布标志 BSD 阵营的新聚合

**辨析**：OpenBSD 1.0/1.1 为内部开发版本，从未公开发布；首个公开版本为 1.2（1996.7），此点常被误述为 1.0（1995.10）；【0 信任原则·commit 量不等于质量】L1.1.1 的 1995-1996 openbsd-src commit 量（770→5,240）反映开发活跃度但不等于代码质量，OpenBSD 1.2 的 “全代码审计” 质量须结合 commit message 主题词与安全公告记录综合判断；【0 信任原则·CVS-to-Git 迁移风险】openbsd-src 主仓为 CVS（anoncvs.openbsd.org），GitHub 为只读 git 镜像，CVS-to-Git 转换可能引入日期偏差或作者归属错误，1995-1996 年 commit 时间戳须与 OpenBSD 官方公告交叉验证；【0 信任原则·GitHub 镜像滞后】openbsd-src GitHub 镜像可能滞后于 CVS 主仓，1995-1996 年的早期 commit 可能存在缺失；【L1.4.1 release tag 信息缺失】openbsd.duckdb 查询 L1.4.1 结果显示 openbsd-src GitHub 镜像无 OPENBSD_ 前缀的 release tag 条目，无法通过 tag 间隔验证 OpenBSD 1.0/1.1/1.2/2.0 发布节奏，OpenBSD 发布时间须以官方公告为准；【L7.1.1.openbsd-src 查询不存在】openbsd.duckdb 数据分析报告《衍生项目与跨项目对比分析.md》中 L7.1.1 系列仅含 ghostbsd-src、hardenedbsd-src、trueos-src、pfsense-src 四个 FreeBSD 衍生项目的 merge commit 比例查询，无 openbsd-src 专用查询，OpenBSD 从 NetBSD fork 的分歧路径识别须通过 commit_hash 与 parent_hashes 的手动比对补全，不可凭空引用；另经两库核查：OpenBSD 1.2（1996-07）与 2.0（1996-10）的具体发布公告在 openbsd 邮件库 1996 年无命中（检索“OpenBSD 1.2”仅命中 2014 年 dmesg 噪声帖，该库 1996 年发布公告缺失）、参考文献库 facts 模式亦无对应条目，两库无法验证，仍以 OpenBSD 官方发布声明为准

**要点**：

- Cappuccio 幼年从叔叔处得到一台可运行 CP/M 或 Microsoft Xenix 的 TRS-80 Model 16B，九十年代初转入 386BSD 与 Linux，1995 年因 Theo 在 FTP 站点放出首个 SPARC 内核而开始使用 OpenBSD 并沿用至访谈时近二十年；早期记忆包括修复后的 SCSI 驱动将传输速率从每秒一百千字节提升到一兆字节。（BSDTalk EP229，[66.47-135.72]，L1）
- FlashRD 是把 OpenBSD 封装为只读系统的脚本：以 RAM disk 引导、经 CrunchGen 压缩工具集、装入完整通用内核而非功能受限的精简系统，把运行中系统封装为 VND 文件并支持换文件升级；其动机是闪存介质固有不可靠，当事人引 USENIX 会议实验称十五块受测闪存盘有十三块在写入断电时发生中度以上数据丢失乃至整体故障。（BSDTalk EP229，[190.13-246.25]，L1）
- 项目谱系：flashdist 需手工指定命令清单与闪存几何参数，在引导器仅支持 CHS 的年代以伪造几何参数立足；当 OpenBSD 引导器转向 LBA 且内核不再接受外部几何后其存在理由消失，flashboot 引入 RAM disk 使系统可整体升级，2009 年 flashrd 成型；作者同时观察到小型项目呈博客或邮件列表提及后热度与贡献短暂聚集、随后冷却的周期。（BSDTalk EP229，[574.35-754.16]，L1）
- NSH 源起于 2001 年作者用 WI 网卡搭建无线网络、面对熟悉 Cisco 命令行的同事需要降低 OpenBSD 路由器门槛的实操场景；它取材 telnet、ftp、ifconfig、route、arp 等常用工具思路，以单一简洁语法封装 PF、BGPD、SNMPD、OSPFD、DHCPd、smtpd 等守护进程配置，并用 SQLite 数据库区分内核自动状态与用户显式意图，写出单一 rc 风格配置文件。（BSDTalk EP229，[313.98-419.14]，L1）
- 设计哲学上作者曾计划把 pfctl 重写为共享库，因 PF 持续快速变动而放弃；NSH 改为只封装不重写既有配置语法，懂 PF 的用户无需学习第二套方言；后续方向是 Web 界面与 relayd URL 过滤文档，总目标是让不熟悉 vi 与文件系统细节的人也能使用 OpenBSD。（BSDTalk EP229，[1169.21-1263.43]，L1）
- 生产环境层面，作者长期在约二十余台异构机器（PC Engines ALIX、Super Micro Core 2 等）上运行 FlashRD，坚持最少可动部件原则，称 FlashRD 加 NSH 的组合可长期无人值守运行。（BSDTalk EP229，[769.16-815.33]，L1）
- SpamD 是一个小型邮件延迟守护进程：对 SMTP 连接或以 450/451 应答令对方稍后重试，或经调整 PF 表放行；兼具 tarpitting 与灰名单两类用途。其设计目标之一是与 Theo 商定确保在一台 SPARCstation IPC 上过滤一个大网络——守护进程不 fork，而是一个读大量套接字、跟踪全部连接状态并与 PF 通话的状态机；对邮件内容不做任何判断（不做正文统计词频分析），只依据 SMTP 连接本身的性质——是否符合标准、是否有规避反垃圾措施的迹象——作判断，故可跑在内存极小的机器上。在阿尔伯塔大学约八万个账户的中央邮件环境里，受访者把 SpamD 放在 Exchange 服务器之前，配合较激进的灰名单，五封 SMTP 消息约四封被挡下、仅一封进入实际处理，显著减轻主邮件处理器负载。（BSDTalk EP68，[77.8-496.0]，L1）
- 运行观察驱动默认行为：SpamD 初期对每个连接前 10 秒以极低速应答后恢复正常，受访者观察日志发现大量连接在三秒即断——垃圾邮件软件以此探测 tarpitting——遂把 10 秒初始延迟设为默认且不设旋钮；对发件方还可启用把 TCP 窗口压到极小、令其分片重传的“残忍”选项以考验对方 TCP 栈（代价是带宽，默认关闭）；对 SMTP auth 场景建议不用 25 端口提交，而以 465 的 SMTPS 与 587 的 mail submission 端口加 SSL 认证解决，必要时可用 PF 重定向规则整网豁免；对早期灰名单担心的出站邮件服务器地址池问题，其经验是一般不构成障碍——可预置 graylisting.org 公布的大站白名单，小池子重试终会通过，出入站共用地址会因 SpamD 观察外发而逐步白名单化，大型站点约两个月才需一次人工干预；相较之下 Sendmail Milter 负载高且按发件人-收件人-IP 三元组粒度过激，不适合大学站点，SpamD 以整 IP 白名单加进出双向观察更为合用。（BSDTalk EP68，[252.24-496.0]，L1）
- greytrapping 机制与轶事：把站点内已公开且弃用的邮件地址设为陷阱，凡向陷阱地址发信的机器即被阻塞 24 小时并遭低速应答，纵使一次投递百封也全数不通；受访者的陷阱名单甚至包括其历年写进软件文档的示例假地址。其举的 bigbutts@obtuse.com 一例成为蠕虫式扩散的活教材：文章发表前先布入陷阱，数日内即有垃圾邮件命中；数月后统计脚本发现命中暴涨，用 Google 一查，某 BSD 期刊的 OpenBSD 文章被色情站点爬虫抓取并在隐藏标签中复制全文，垃圾邮件发送者再爬色情站点把地址再次拾取——清理者与滥用者的食物链在陷阱地址上叠印。（BSDTalk EP68，[673.06-895.48]，L1）
- 社区体验与多重贡献：受访者形容 OpenBSD 社区是一群高强度但自得其乐的人——hackathon 通宵、技术讨论时大喊大叫上蹿下跳，留下来是因为“有趣且对我们有用”；其本人自认什么 都碰：重写过 SpamD（不满意即推倒重来）、近期在拆解 SCSI 层——多数 BSD 的磁带机与磁带库 changer 支持基本残废，遂对 SCSI 层、磁带驱动与 changer 驱动作内核级修整；参与各处的修复、测试与发布验证，运营 orders 网站（藏在其公司机器与自家地下室）；自嘲“样样通样样松”，并强调自己不是 OpenBSD 狂热者而只是一个 UNIX 用户——用其所善、避其所短。（BSDTalk EP68，[897.92-1020.56]，L1）
- 缘起故事：约 1995 年，受访者与合伙人写防火墙软件并在咨询业务中营销，以把它移植到一切平台为乐（含内核修改）；当时无线买不起联网可用机，弄到一台 SPARCstation 后发现 NetBSD 的 SPARC 移植完全不可用，而 OpenBSD 正在起步——安全正对其胃口，也不管社区恩怨只问“能不能用”；下载 SPARC 发行版果然能跑且修掉了一批旧 bug；当年网站还是 Theo 的个人页，写着“喜欢就打这个电话”——竟是卡尔加里一家比萨店的号码，身在三小时车程外埃德蒙顿的他打电话订比萨遭拒后转而向 Theo 抱怨，两人在汉堡店见面，他买下一张 CD，从此入伙。（BSDTalk EP68，[1020.56-1118.98]，L1）
- 桌面、家庭与文化参与：受访者笔记本、桌面与孩子的机器都跑 OpenBSD（孩子双启 Windows 只为游戏）；其桌面是极简的 fvwm，但承认近年 ports 收集安装体验进步惊人，孩子用全套 KDE 加 Linux 兼容层跑 OpenOffice 与教育、游戏软件，女儿用 MSN 客户端、儿子玩 Blender，全家充当 ports 的发布测试“小白鼠”；家中防火墙以 PF 的操作系统指纹特性只放行 Windows 走 80 端口以隔绝病毒。发行文化方面：4.0 已分支并开放预购，预购者常在 FTP 放开前拿到 CD；本次除 CD 套装外首推收录 3.0 至 4.0 全部发行歌曲加彩蛋曲目的音频 CD；受访者为 3.5 的“鱼执照”歌曲写过歌词（自认 Monty Python 粉丝玩过火）；制作水准主要来自卡尔加里的 Ty Semaka 与 Jonathan Lewis（乐队 Plaid Tongued Devils），他自己也在一曲中与 Theo、Peter Valchev 及儿子 Calvin 合唱“酒吧合唱”；收尾呼吁买 CD、T 恤、捐款——强调 OpenBSD 反哺众多项目、直接间接被广泛使用，募款并非乞讨。（BSDTalk EP68，[1159.18-1535.58]，L1）
