# 71.13 OpenBSD 1.0 对 386BSD 安全基线的间接继承与 4.4BSD-Lite 替代（1995-1996）

## 71.13.1 OpenBSD 1.0 经 NetBSD 1.0 间接继承 386BSD 安全基线

  **要点**：OpenBSD 1.0（1995 年 10 月 18 日 CVS 仓库初始导入，1996 年 7 月 OpenBSD 1.2 首次公开发布）由 Theo de Raadt（西奥·德·若特） 从 NetBSD 1.0（1994 年 10 月 26 日 release）fork，NetBSD 1.0 已于 1994 年 rebase 至 4.4BSD-Lite，故 OpenBSD 1.0 经 NetBSD 1.0 间接继承 386BSD 安全基线——386BSD 0.1 的安全机制（root/超级用户二元特权模型、文件权限 rwx、setuid/setgid、DES **crypt(3)** 密码散列、单文件 `/etc/passwd`、4.3BSD 网络栈远程漏洞面）经 NetBSD 0.8/0.9 → NetBSD 1.0 rebase → OpenBSD 1.0 fork 路径间接传递；同时，NetBSD 1.0 rebase 至 4.4BSD-Lite 时引入的 securelevel 内核安全等级机制亦经 OpenBSD 1.0 fork 直接继承，OpenBSD 后世演化为 **securelevel(7)**；OpenBSD 1.0 的安全基线因此呈现 “386BSD 遗留基因 + 4.4BSD-Lite 新机制” 的双重继承特征，与 FreeBSD 1.0（1993 年直接继承 386BSD 0.1）和 NetBSD 0.8/0.9（1993 年直接继承 386BSD 0.1）的直接继承路径不同
  
**史料**：OpenBSD CVS 历史早期记录（1995.10.18 初始导入）、de Raadt 个人主页自述、NetBSD 1.0 Release Announcement（1994.10.26）；openbsd.duckdb 数据库证据——openbsd-src 仓库首条 commit 为 deraadt 1995-10-18T08:37:01Z “initial import of NetBSD tree”（commit_hash `df930be708d50e9715f173caa26ffe1b7599b157`），commit message 明确记载 “initial import of NetBSD tree”，证实 OpenBSD 1.0 fork 自 NetBSD 1.0 而非直接 fork 自 386BSD 0.1，与 “OpenBSD 经 NetBSD 1.0 间接继承 386BSD 安全基线” 的叙事完全吻合；deraadt 在 netbsd-src 末次 commit 为 1994-12-17T23:12:41Z（commit_hash `699d2a37b0e3c0c6ff29ea0d407c3feeba5642b4`），与被 NetBSD 核心团队撤销 commit bit 的时间吻合；deraadt 在 openbsd-src 首次 commit（1995-10-18T08:37:01Z）与 netbsd-src 末次 commit（1994-12-17T23:12:41Z）间隔约 304 天，此期间为 de Raadt 筹备 OpenBSD 项目的阶段 ［A］
  
**史观**：总纲第 11 条——分离与聚合：OpenBSD 从 NetBSD 1.0 分离后聚合为独立项目，安全基线经 NetBSD 1.0 间接继承 386BSD 遗留基因并直接继承 4.4BSD-Lite 新机制；总纲第 25 条——终结中的延续：386BSD 作为 OpenBSD 间接安全基线的地位经 NetBSD 1.0 中转，其安全基因在 OpenBSD 主线延续
  
**辨析**：OpenBSD 1.0 的安全基线继承路径须严格区分——386BSD 0.1 → NetBSD 0.8/0.9 → NetBSD 1.0 rebase → OpenBSD 1.0 fork，而非 386BSD 0.1 → OpenBSD 1.0 直接继承；OpenBSD 1.0 fork 时 NetBSD 1.0 已完成 4.4BSD-Lite rebase，故 OpenBSD 1.0 同时继承 386BSD 遗留安全基因（经 NetBSD 0.8/0.9 中转）与 4.4BSD-Lite 新机制（securelevel 等）；OpenBSD 1.0 与 FreeBSD 1.0（1993 年直接继承 386BSD 0.1）的安全基线在 1995-1996 年时点已显著分化——前者包含 securelevel，后者因基线较早未获直接继承须待 FreeBSD 2.0（1994.11.22）rebase 至 4.4BSD-Lite 方能引入；0 信任原则提示：openbsd-src 为 GitHub 只读镜像，主仓为 CVS（anoncvs.openbsd.org），CVS-to-Git 转换可能引入日期偏差或作者归属错误，1995 年 10 月的 commit 时间戳须与 OpenBSD 官方公告与 de Raadt 个人声明交叉验证

## 71.13.2 4.4BSD-Lite 替代 386BSD 成为 OpenBSD 直接基线与 securelevel 引入

  **要点**：OpenBSD 1.0 fork 自 NetBSD 1.0 时，NetBSD 1.0 已 rebase 至 4.4BSD-Lite，故 4.4BSD-Lite 实际成为 OpenBSD 直接基线，386BSD 作为 OpenBSD 直接基线的地位在 1994 年 NetBSD 1.0 rebase 时即被取代（早于 OpenBSD 1.0 fork 一年）；4.4BSD-Lite 引入的 securelevel 内核安全等级机制经 NetBSD 1.0 → OpenBSD 1.0 路径直接继承——level 0 不安全模式、level 1 安全模式禁止 `/dev/mem` 访问与原始磁盘写入并强制 **chflags(2)** 不可变标志、level 2 高安全模式进一步限制系统时间修改，securelevel 一旦提升至非零级即不可降级须重启方能恢复至 level 0；securelevel 在 OpenBSD 后世演化为 **securelevel(7)** 手册页，是 OpenBSD 安全至上的核心机制之一；386BSD 0.1 时期未引入的 securelevel、chroot 安全沙箱用途、shadow password 等机制经 4.4BSD-Lite 替代后方能进入 OpenBSD 主线，OpenBSD 后续（如 OpenBSD 3.x 起）进一步主动加固 securelevel 与权限分离机制
  
**史料**：4.4BSD SMM: 16《On the Security of UNIX》securelevel 描述、4.4BSD PSD: 5《Berkeley Software Architecture Manual (4.4 Edition)》securelevel 相关系统调用接口、McKusick et al. 1996 设计与实现一书第 9 章、OpenBSD **securelevel(7)** 手册页历史版本、NetBSD 1.0 Release Announcement（明确记载 "based on 4.4BSD Lite and Berkeley Networking Release 2 sources"）；openbsd.duckdb 数据库证据——deraadt 在 openbsd-src 共 27,181 个 commit，末次 commit 为 2026-07-16T22:03:31Z，是 OpenBSD 项目最长持续贡献者，反映 de Raadt 自 1995-10-18 fork 起持续主导 OpenBSD 安全至上路径 ［A］
  
**史观**：总纲第 11 条——分离与聚合：4.4BSD-Lite 替代 386BSD 成为 OpenBSD 直接基线是从 386BSD 安全基线分离后聚合至 4.4BSD-Lite 新基线；总纲第 21 条——密码学与信息安全：securelevel 经 4.4BSD-Lite → NetBSD 1.0 → OpenBSD 1.0 路径继承，是 OpenBSD 安全至上路径的工程基础
  
**辨析**：4.4BSD-Lite 替代 386BSD 作为 OpenBSD 直接基线的时间点须严格区分——NetBSD 1.0 rebase 至 4.4BSD-Lite 于 1994 年 10 月 26 日完成，早于 OpenBSD 1.0 fork（1995 年 10 月 18 日）约一年，故 OpenBSD 1.0 fork 时即直接基于 4.4BSD-Lite 而非 386BSD；securelevel 在 4.4BSD-Lite 中为概念雏形，OpenBSD 后续主动加固并演化为 **securelevel(7)** 手册页，与 FreeBSD 的 `kern.securelevel` sysctl 形成路径分化；OpenBSD 1.0/1.2 时期 securelevel 的实际启用状态需对照源码与 release notes 核实，概念雏形与默认启用为不同维度

## 71.13.3 OpenBSD 全代码审计对 386BSD 遗留安全基线的重构

  **要点**：OpenBSD 1.0/1.2 时期（1995-1996）de Raadt 与早期开发者对 NetBSD 1.0 源码进行全代码审计，逐行审查 386BSD 经 NetBSD 0.8/0.9 中转传递的安全相关代码——root/超级用户二元特权模型、文件权限 rwx、setuid/setgid 二进制清单、`/etc/passwd` 格式、4.3BSD 网络栈远程漏洞面（sendmail DEBUG、fingerd 缓冲区溢出、`~/.rhosts` 信任链）；审计结果修复潜在安全漏洞，强化默认安全配置（如默认禁用 r-commands、逐步禁用 telnetd），并主动加固 securelevel 与权限分离机制；OpenBSD 全代码审计方法论是 “安全至上” 工程路径的核心，与 FreeBSD 1.0（1993 年直接继承 386BSD 0.1 未做系统审计）与 NetBSD 0.8/0.9（1993 年直接 fork 未做系统审计）形成鲜明对照——OpenBSD 1.0/1.2 是首个对 386BSD 遗留安全基线进行系统审计与重构的 BSD 项目；OpenBSD 1.2（1996 年 7 月首次公开发布）发布后，386BSD 遗留的 4.3BSD 网络栈远程漏洞面在 OpenBSD 中得到首次系统性修复，标志 BSD 安全文化从被动响应转向主动审计
  
**史料**：OpenBSD CVS 历史早期记录（1995-1996 全代码审计 commit 序列）、OpenBSD 1.2 Release Notes (1996.7) 安全章节、OpenBSD 官方 FAQ 关于全代码审计方法论的说明、de Raadt 关于审计的公开声明；openbsd.duckdb 数据库证据——openbsd.duckdb 查询 L1.1.1 显示：1996 年 openbsd-src = 5,240 commits（占当年 4 大 BSD src 仓库总量 29,245 的 17.92%），较 1995 年 770 commits 增长约 6.8 倍，反映 OpenBSD 1.2 发布当年（含全代码审计期）开发活跃度大幅提升，与全代码审计方法论的工程投入吻合 ［A］
  
**史观**：总纲第 5 条——组织结构塑造技术路径：de Raadt 个人主导的全代码审计方法论决定 OpenBSD 的工程方向；总纲第 21 条——密码学与信息安全：全代码审计是 OpenBSD 从被动安全响应转向主动安全审计的关键工程实践
  
**辨析**：OpenBSD 全代码审计的起始时间需考据——审计可能在 fork 后立即开始（1995 年 10 月起），亦可能在 OpenBSD 1.2 发布前集中进行（1996 年上半年），需对照 CVS 历史核实；【0 信任原则·commit 量不等于质量】L1.1.1 的 1995-1996 openbsd-src commit 量（770→5,240）反映开发活跃度但不等于代码质量，OpenBSD 1.2 的 “全代码审计” 质量须结合 commit message 主题词与安全公告记录综合判断；OpenBSD 全代码审计对 386BSD 遗留安全基线的重构须与 FreeBSD 1.0（直接继承未审计）与 NetBSD 0.8/0.9（直接 fork 未审计）形成对照，避免将 OpenBSD 1.0/1.2 的审计方法论回溯性套用于 FreeBSD 1.0 与 NetBSD 0.8/0.9 时期——彼时两项目仍以功能完善与平台扩展为优先，安全审计尚未成为独立工程目标
