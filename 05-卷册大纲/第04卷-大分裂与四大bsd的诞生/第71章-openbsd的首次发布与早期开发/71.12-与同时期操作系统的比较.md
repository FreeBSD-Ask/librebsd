# 71.12 与同时期操作系统的比较：1995-1996 年同期操作系统——NetBSD 1.1/1.2、FreeBSD 2.1/2.2、Linux 1.2/1.3、Windows 95/NT 3.51、Solaris 2.5——OpenBSD 以安全为首要承诺的独特定位

## 71.12.1 NetBSD 1.1（1995）/ 1.2（1996-10-04）

  **要点**：NetBSD 1.1（1995.11）与 1.2（1996-10-04）延续 NetBSD 的 “极致可移植” 路线，支持从 VAX 到 ARM 的广泛平台；OpenBSD 正是由此派生——1995 年 10 月 Theo de Raadt（西奥·德·若特）因与 NetBSD 核心团队的治理分歧而分叉，OpenBSD 1.0（1996.7）基于 NetBSD 1.0 但重写了大量安全相关代码。二者共享 BSD 谱系，但在优先级上分道：NetBSD 重 “可移植”、OpenBSD 重 “安全”。
  
**史料**：NetBSD 1.1/1.2 发布说明；OpenBSD 1.0 公告（1996.7）与 de Raadt 分叉公开信 ［A］；NetBSD 邮件列表分叉讨论归档 ［B］；freebsd.duckdb 查询 L1.1.2 显示：1995 年 4 大 BSD src 仓库 commit 量相对比例为 netbsd-src = 12,163 commits（58.88%）、freebsd-src = 7,723 commits（37.39%）、openbsd-src = 770 commits（3.73%），反映 OpenBSD fork 当年（1995.10）commit 份额极低；1996 年比例变为 netbsd-src = 16,057 commits（54.91%）、freebsd-src = 7,948 commits（27.18%）、openbsd-src = 5,240 commits（17.92%），OpenBSD 份额增长约 4.8 倍，反映 OpenBSD 1.2 发布后逐步在 BSD 阵营中占据独立位置，但仍远低于 NetBSD 与 FreeBSD
  
**史观**：总纲第 7 条——BSD 谱系：OpenBSD 是 NetBSD 的直接派生，证明 BSD 许可证允许自由分叉以追求不同工程优先级；这一 fork 是 BSD 家族 “各自独立发展” 的典范。
  
**辨析**：OpenBSD 并非 “优于” NetBSD——二者目标不同；分叉源于治理与文化分歧而非技术优劣，OpenBSD 继承了 NetBSD 的代码基础与可移植框架；【0 信任原则·commit 量不等于质量】L1.1.2 的 1995-1996 BSD src 比例反映开发活跃度分布但不等于项目质量，OpenBSD 3.73%→17.92% 的份额增长须结合 commit message 主题词与安全审计记录综合判断；【0 信任原则·CVS-to-Git 迁移风险】netbsd-src 与 openbsd-src 均为 CVS 主仓的 GitHub 镜像，CVS-to-Git 转换可能重写 author 字段或 commit_date，1995-1996 年 commit 量基线须与 NetBSD/OpenBSD 官方档案交叉验证；【0 信任原则·GitHub 镜像滞后】netbsd-src 与 openbsd-src 的 GitHub 镜像可能滞后于 CVS 主仓，1995-1996 年 commit 量比例的精度须以官方档案为准；【勘误·经[邮件列表库]验证】本文要点原记 “1.2（1996.12）” 系日期误差，应修正为 **1996-10-04**：NetBSD 1.2 实际由 J.T. Conklin（<jtc@NetBSD.ORG>）于 1996-10-04 在 netbsd-announce 公告发布（Message-ID `no-id-netbsd-announce-199610-04-0000`，subject“Announcing the release of NetBSD 1.2.”）
  
**文献**：NetBSD Project. NetBSD 1.2 Release Notes [Z]. 1996；de Raadt T. OpenBSD Announcement [EB/OL]. 1996. ［A］；本项目。bsd_commits.duckdb 数据分析报告：宏观趋势统计 [R/OL]. 2026.

## 71.12.2 FreeBSD 2.1（1995）/ 2.2（1996）

  **要点**：FreeBSD 2.1（1995）与 2.2（1996，Lite-2 整合）聚焦 x86 服务器与工作站，强调性能与 Ports 生态；与 OpenBSD 同期但路线不同——FreeBSD 重 “实用部署”、OpenBSD 重 “安全审计”。二者均源自 4.4BSD-Lite，但 OpenBSD 的 proactive security（默认安全、权限分离）在 1995-1996 尚无对应物。
  
**史料**：FreeBSD 2.1/2.2 发布说明（1995-1996）［A］；FreeBSD Handbook 早期版本 ［B］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：FreeBSD 与 OpenBSD 在 1990 年代中期由共同 BSD 基础分离后各自聚合，形成 “性能/生态 vs 安全/审计” 的路线分叉，BSD 家族内部差异化竞争。
  
**辨析**：FreeBSD 与 OpenBSD 非竞争而是互补——共享代码基础（如许多安全修复双向流动），目标用户群（通用服务器 vs 高安全场景）不同。
  
**文献**：FreeBSD Project. FreeBSD 2.2 Release Notes [Z]. 1996；FreeBSD Documentation. FreeBSD Handbook [EB/OL]. ［B］

## 71.12.3 Linux 1.2（1995）/ 1.3（1995-1996 开发线）

  **要点**：Linux 1.2（1995.3）是功能完整但规模尚小的 UNIX 内核，1.3 为开发主线（后演进为 2.0）；1995-1996 年 Linux 处于 “功能追赶” 阶段，社区以功能与移植为主，尚未形成系统性的安全审计文化。OpenBSD 的 proactive security 理念在 Linux 界当时几乎不存在，直到多年后 grsecurity/SELinux 才出现类似关注。
  
**史料**：Linux 1.2 发布说明（1995.3）；Torvalds 邮件列表公告 ［B］；Linux 1.3 变更日志 ［C］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：Linux 的 “大规模协作功能开发” 与 OpenBSD 的 “小团队安全审计” 由同源开源运动分离后各自聚合，代表两种开源开发哲学，1995-1996 年二者安全成熟度差距显著。
  
**辨析**：Linux 当时并非 “不安全”——而是缺乏 OpenBSD 式的制度化安全流程；将 OpenBSD 视为对 Linux 的安全批判是事后视角，当时二者关注点本就不同。
  
**文献**：Torvalds L. Linux 1.2 Release Notes [Z]. 1995；Linus Torvalds et al. Linux Kernel Archives [EB/OL]. ［B］

## 71.12.4 Windows 95（1995）/ Windows NT 3.51（1995）

  **要点**：Microsoft Windows 95（1995.8）是面向消费者的 16/32 位混合桌面系统，NT 3.51（1995.5）是面向服务器的 32 位微内核架构；二者均为闭源商业系统，无公开源代码安全审计，其安全模型（用户权限、NT 的 ACL）与 OpenBSD 的 “默认拒绝/权限分离” 哲学迥异。OpenBSD 的开源审计模式在闭源 Windows 世界无对应物。
  
**史料**：Microsoft Windows 95 / NT 3.51 发布文档（1995）［A］；NT 安全架构白皮书 ［B］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：闭源商业系统的 “黑盒安全” 与 OpenBSD 的 “公开审计安全” 由共同的安全工程需求分离后各自聚合，形成根本方法论对立，这一对立延续至今。
  
**辨析**：Windows NT 的 ACL 模型与 OpenBSD 的 permission separation 目标相似（最小权限）但实现路径不同（闭源 vs 开源审计）；将 Windows 简单视为 “不安全” 忽视了 NT 的企业安全设计。
  
**文献**：Microsoft. Windows NT 3.51 Resource Kit [Z]. 1995；Custer H. Inside Windows NT [M]. 1993. ［B］

## 71.12.5 Solaris 2.5（1995）

  **要点**：Sun Solaris 2.5（1995）是基于 SVR4 的 UNIX，运行于 SPARC 与 x86，面向企业服务器与工作站台；作为商业 UNIX，Solaris 拥有成熟的企业安全特性但无 OpenBSD 式的公开代码审计文化。OpenBSD 在 1995-1996 以 “开源 + 主动安全” 开辟了一个商业 UNIX 与 Linux 都未占据的细分市场。
  
**史料**：Sun Solaris 2.5 发行文档（1995）［A］；Solaris 安全特性文档 ［B］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：商业 UNIX（Solaris）的 “企业安全功能” 与 OpenBSD 的 “开源审计安全” 由同源 UNIX 传统分离后各自聚合发展，代表企业化与社区化两条安全路线。
  
**辨析**：Solaris 与 OpenBSD 目标用户重叠有限（企业 vs 高安全/研究）；OpenBSD 的价值不在企业特性丰富度，而在可验证的安全流程。
