# 070.3.4 要点386BSD0119927发布后因Jolitz单人维护补丁积压1993年6月

  **要点**：386BSD 0.1（1992.7）发布后因 Jolitz 单人维护补丁积压，**1993 年 6 月 19 日** FreeBSD 项目 fork 386BSD 创建（Nate Williams、Rodney Grimes、Jordan Hubbard、David Greenman 4 人组），**FreeBSD 1.0**（1993.11）发布，主攻 Intel x86 PC 平台；**1993 年 4 月** NetBSD 0.8 发布（Chris Demetriou、Theo de Raadt、Adam Glass（亚当·格拉斯）、Charles Hannum 4 人组），主攻多平台移植（SPARC、Alpha、PowerPC、m68k 等），虽基于 386BSD 部分代码但更早脱离 386BSD 单人维护模式；**1995 年 10 月** OpenBSD 从 NetBSD 1.0 fork（Theo de Raadt 因与 NetBSD Core Team 冲突被驱逐后创建），主攻安全审查与代码质量；386BSD 单人维护模式在 1993-1995 年被 “淘汰” 为 FreeBSD/NetBSD/OpenBSD 三大 BSD fork 演化路径，386BSD 本身因 Jolitz 维护停滞而逐步衰落，1995 年后基本停止开发；FreeBSD/NetBSD/OpenBSD 三大 fork 形成 BSD 三大分支格局，分别主攻 PC 性能（FreeBSD）、多平台移植（NetBSD）、安全审查（OpenBSD），延续至 21 世纪；386BSD → 三大 fork 的演化路径是 BSD 从 “单一项目” 到 “多元分支” 的关键转型，后被 DragonFly BSD（2003 年从 FreeBSD 4.x fork，Matthew Dillon（马修·狄龙） 创建）等进一步分化。三大 BSD fork 首条 commit 时间对照如下：

**史观**：第 4 条分离聚合是永恒规律——386BSD → 三大 fork 是 BSD 从 “单一项目聚合” 分离为 “三大分支多元演化”，分离是聚合的前提；第 5 条没有必然性，只有偶然性——FreeBSD/NetBSD/OpenBSD 三大 fork 的具体时间点（1993.4/1993.6/1995.10）是偶然的，但此偶然叠加 Jolitz 单人维护停滞，使 fork 成为必然

**辨析**：386BSD 被 “淘汰” 为三大 fork 指 386BSD 单人维护模式主导地位退场，386BSD 代码本身部分被 FreeBSD 1.0 继承（基于 386BSD 0.1 + 4.4BSD-Lite），须区分 “维护模式退场” 与 “代码继承”；NetBSD 0.8（1993.4）与 FreeBSD 1.0（1993.11）的关系需核对——两者均基于 386BSD 但 NetBSD 更早脱离 386BSD 单人维护模式；DragonFly BSD（2003）从 FreeBSD 4.x fork 是 BSD 三大分支格局的进一步分化，须区分 “三大 fork” 与 “后续分化”；freebsd.duckdb 验证结论——freebsd-src/netbsd-src/openbsd-src 三仓库首条 commit 时间与各项目 fork 公告日期基本一致，偏差在 1 周内，属 fork 公告前的代码 import 阶段；0 信任原则提示：FreeBSD SVN-to-Git 迁移（2020）可能引入 commit hash 重新计算，1993-1995 年间的 commit 时间戳须与邮件列表公告交叉验证；netbsd-src 首条 commit 显示为 1992-07-13T16:18:24Z（srcmastr “initial empty check-in”），但此为仓库初始化脚本 commit，**非 NetBSD 项目实际成立时间**，NetBSD 项目实际起步以 1993-03-21 cgd 的 386bsd-0.1 import 为标志；【0 信任原则·commit 量不等于质量】commit 量仅反映开发活跃度，须结合 commit 规模与 message 质量综合判断 fork 项目的实际进展；【0 信任原则·SVN-to-Git 迁移风险】FreeBSD 2020 年 SVN-to-Git 迁移可能引入 commit_date 偏差，1993-1995 年 commit 时间戳须与邮件列表公告交叉验证；【0 信任原则·GitHub 镜像滞后】netbsd-src/openbsd-src 为 GitHub 镜像，commit 量可能滞后于主仓（CVS/Mercurial），1993-1995 年 commit 基线须以 NetBSD/OpenBSD 官方档案为准；【0 信任原则·release tag 间隔不完全等于开发周期】release tag 间隔包含发布工程、文档准备、镜像同步等非开发时间，须区分 “开发周期” 与 “发布间隔”
