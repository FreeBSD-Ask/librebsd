# 65.6 FreeBSD 创立的社区动力学——补丁守护者的权威来源

## 65.6.1 patchkit 协调人的合法性与权力基础

**要点**：Jordan Hubbard、Rod Grimes、David Greenman（大卫·格林曼） 等的权力基础来自技术贡献积累而非正式选举——他们维护的 386BSD patchkit 被社区广泛采用，构成事实上的‘官方’补丁集。

**史料**：FreeBSD 早期邮件列表（1993）; Hubbard 等访谈 ［A］

**史观**：第 10 条动手者创造历史（存疑）——非正式权力结构的形成。

**辨析**：社区分裂的叙事需要区分“建设性分叉”和“破坏性分裂”——前者是开源生态的正常现象（如 OpenBSD 从 NetBSD 分叉后独立发展），后者是社区治理失败的结果。分裂事件的历史记录往往由胜出方书写，分裂方的视角和贡献可能被系统性低估。
**文献**：FreeBSD 邮件存档 ［A］

**要点**：

- Julian Elischer 一手自述其 BSD 起点：1990 年入职 TRW，在基于 VME 总线 68030 的图像处理服务器群上运行 BSD 4.3；公司为降级到 x86 工作站而采用 Mach 系统——即 CMU 将其微内核研究成果嫁接 BSD 4.3 之上、保留原文件系统与网络栈的产物；x86 与 68030 的大小端差异令他迅速领教网络栈中字节序转换函数存在的理由。因 Mach 无 SCSI 支持，他为 Mach 编写了 SCSI 子系统，随后将其移植入 386BSD，该代码成为 FreeBSD SCSI 子系统的基础，后由 Justin Gibbs 等人重写；他声称其残留文件与署名至今仍存于 FreeBSD、NetBSD 与 OpenBSD 之中。（BSDTalk EP165，[508.86-588.84]，L1）
- 386BSD patchkit 时期的协作形态由当事人还原：Bill Jolitz 与 Lynn Jolitz 因家庭危机淡出后，开发者群体自行维护官方补丁集，无版本控制工具，参与者复制源码树制作 diff 汇入补丁集；Julian 在 TRW 金融系统的外部网络上架设服务器，向所有愿意工作的人开放账号。1993 年他返澳期间 Jordan Hubbard 等人分叉出 FreeBSD，他将其定性为组织性争论而非技术争论；NetBSD 更早分叉、性质偏技术，诉求是获得 CVS 树与更好的支持结构。Jolitz 夫妇最终因家庭变故（他提及 Bill 父亲去世等）彻底退出，FreeBSD 从此自立。（BSDTalk EP165，[359.28-477.40]，L1）
- Whistle Communications（1996 至 1999）是其总结的“以 BSD 解决问题、开发成果回流 FreeBSD”模式的典型：小企业一体机被当事人称为盒装 IT 部门，公司被 IBM 收购后产品线遭整体关停，当事人形容为花费约 1.2 亿美元买下再关掉的怪异决策；该时期回流 FreeBSD 的成果包括以合同委托 McKusick 移植的 soft updates、Divert Sockets、NetGraph 子系统与 AppleTalk 栈。对“BSD 许可证纵容企业只取不予”的担忧，他以跨公司经验给出系统性反驳：回馈即由社区维护、代码保鲜，NetGraph 首次提交仅约 12 个模块、如今 50 至 60 个模块大多出自他人之手，回馈即省钱；竞争对手若已自行实现同类功能，将己方代码回馈入主线会抬高对手门槛，拖延三年则可能错失窗口——对手正解决同一问题，谁先回馈谁的定义成为事实标准，故总有理由尽快回馈。（BSDTalk EP165，[884.96-1081.76]，L1）
- TRW 分部管理层强推 COTS（商用现货）路线的教训由当事人痛陈：以改用 Windows NT 与 Sun 服务器、把工程师从百人裁至五十人为诱饵的论证，被其斥为似是而非——采用 COTS 即接受所有公司共有的 COTS 局限，公司从能做出差异化产品的 vendor 沦为 me-too vendor。此前自研系统曾以 15.5K 巨型帧穿过作局部总线用的以太网、专用驱动将包直接写入内存缓冲馈入磁盘、几乎无 CPU 干预，一台 68030 即可打满六七条以太网；自造成本 1.5 万美元售 7 万美元，而改用 Sun 方案后需三倍硬件，24 万美元的 Sun 设备以 18 万美元亏本竞标。管理层的省钱承诺从未兑现。（BSDTalk EP165，[1223.02-1367.42]，L1）
- IronPort（2005 年加入，后被 Cisco 收购）延续同一人群与同一模式：设备为 Dell 硬件，其 AsyncOS 即标准 FreeBSD 加一层异步事件驱动、协作式线程的 Python 运行时；内部沿用 Whistle 时代的引导块实现双 root 分区、下载写入备用分区失败即回退的升级机制，当事人认为其在该功能上仍优于现行 FreeBSD 引导块。因所有改动回流主线，公司升级路径顺畅：4.8、6.1、6.3、再到等待中的 7.1，自研补丁先入 current 再回稳定分支，抵达新分支时补丁已在其中；反例是 Nokia 因对 FreeBSD 魔改过深而长期困守 2.0，待需 SMP 升级至 6.0 时付出巨大代价。（BSDTalk EP165，[1497.22-1710.10]，L1）
- Cisco 收购后的组织生态由当事人描述：IronPort 并入安全技术业务单元 STBU，原 IronPort 首席执行官接管 STBU，被当事人形容为一场宫廷政变，STBU 现近乎 IronPort 的放大版。收购消息令 Linux 工程师担心被迫转 BSD、BSD 工程师担心被迫转 Linux，管理层回答均为否定；BSD 在 Cisco 内部渐获尊重。当事人还透露 Cisco 内部曾有项目考虑采用 BSD，被 Linux 派以政治手段阻止，理由包括采用 BSD 会“验证 Juniper 选择 BSD 的正确性”；Cisco 设有开源监督流程，要求报告所用开源组件并核验许可证，其对 Cisco 大量采用 Linux 的 GPL 合规持保留态度。（BSDTalk EP165，[1790.74-1888.62]，L1）
- Baldwin 回忆 FreeBSD 的诞生脉络：UC Berkeley 在 90 年代初收束研究工作后将 BSD 成果以开源形式发布，Bill Jolitz 在 Dr. Dobb's Journal 连载文章，将 4.3BSD 移植到 386 PC 而成 386BSD；围绕其补丁集在 Usenet 上自发形成收集与维护补丁的社区，因 Jolitz 周期性消失、新版本遥遥无期，社区先分裂出 NetBSD，再组建成 FreeBSD，以伯克利代码加上全球贡献的补丁合成首个发行版。（Software Engineering Daily EP1914，[364.0-476.0]，L2）
- Baldwin 叙述诉讼的起因与后果：BSDi 把 1-800-ITS-UNIX 电话号码用作营销策略，尽管 UNIX 商标由 AT&T 持有，此举激怒 AT&T 律师并引发对伯克利的大型诉讼；诉讼悬置期间社区前景不明，开发者担心源代码被判定受版权负担，转投没有此类不确定性的 Linux，BSD 在早期开发者心智份额竞争中受损；到他 90 年代中期接触 FreeBSD 时诉讼虽已解决，心智份额的伤害已经造成。（Software Engineering Daily EP1914，[548.0-650.0]，L2）
- 据 Baldwin 回忆，Sony 在 PS4 之前每代主机均自行拼装操作系统，C 库、TCP/IP 栈与共享库取自不同来源，等于同时身陷操作系统业务，PS4 立项时决定改用现成系统为起点；评估期恰逢 GPLv3 发布，其专利授权条款令 Sony 法务不安，BSD 许可证成为选定 FreeBSD 的决定性因素。Sony 的采用伴随对上游回馈：内核 AVX 支持直接来自 PlayStation 团队，Sony 更在 LLVM 链接器尚不成熟时向 LLD 投入大量工程，使 FreeBSD 得以在全部平台以 Clang 与 LLD 为默认工具链，据称 FreeBSD 15 的 base 系统仅剩一个 GPL 二进制。　[存疑脚注] GPLv3 顾虑系 Baldwin 转述与 Sony 工程师会谈的回忆，未见 Sony 一手材料佐证（Software Engineering Daily EP1914，[1277.0-1440.0]，L2）
- Baldwin 以 Netflix 合同工程师身份亲述：Open Connect CDN 节点运行 FreeBSD，在 ISP 本地以数百 Gbps 的 TLS 加密流量服务数千个链路质量参差的客户端；TLS 破坏了 sendfile 的内核零拷贝路径，每连接会话密钥不同使内核页共享失效，用户态加密引入多次拷贝与内存、PCIe 带宽的连锁消耗。Netflix 遂将 TLS 处理移入内核并主动上游化，认为加密并非其商业秘诀；Baldwin 继而受 Chelsio 雇为承包人扩展该框架，使 TLS 加密下沉到 SmartNIC 在线完成，数据恢复单份内存拷贝，该项目由 Netflix 需求、Chelsio 在 NDA 下开放的硬件文档与 Baldwin 的居中设计三方协作完成。（Software Engineering Daily EP1914，[1457.0-1796.0]，L1）
- 视频将 UNIX 的诞生置于 Multics 的失败阴影之下：贝尔实验室、MIT 与 GE 三方合作的 Multics 是为 GE 645 大型机设计、引入动态链接、多处理器支持与层次文件系统等重要特性的早期分时系统，但在贝尔实验室管理层终止全部操作系统研发后，Ken Thompson 与 Dennis Ritchie 转而借助实验室一台闲置的 DEC PDP-7 延续其系统构想，其后又以向 AT&T 专利局交付文字处理程序为交换条件获得全新 PDP-11；Dennis Ritchie 发明 C 语言并以之重写 UNIX 主体，使系统具备可移植性，UNIX 及其源代码由此得以授权给 AT&T 以外的机构使用。（YouTube EPY0ixYwLd9Pg，[82.2-256.3]，L2）[订正：原 [84.4-254.47]，2026-10-02 SenseAudio 重转核对]

- 随着 BSD 日趋自成一体，因使用 BSD 须持有价格逐年攀升的 AT&T 许可证，伯克利发起移除专有代码的运动，先后发布可依宽松许可自由分发的 Net/1 与更完整的 Net/2；Net/2 成为向 Intel 386 架构移植的基础，同时衍生出 Jolitz 夫妇自 1989 年开始的自由开源 386BSD 与 BSDi 销售的专有 BSD/386，后者以 1-800-ITS-UNIX 的订购电话招徕客户，却引来持有 UNIX 名称版权的 AT&T Unix System Laboratories 注意并于 1991 年提起诉讼，BSD 系合法性因此受质疑，客观上为 Linux 争取了发展窗口；1994 年和解的条件是发布移除争议文件的 4.4BSD-Lite，已归 Novell 所有的 USL 亦须为 UNIX 中源自 BSD 的文件附加伯克利版权声明，新转写其后反称任何基于 4.4BSD-Lite 的操作系统「在法律上仍属不清」，与前文清白化叙事方向相反，疑为口述或转写之误。（YouTube EPY0ixYwLd9Pg，[374.2-544.6]，L2）〔订正：原 [376.15-548.55]→[374.2-548.55]，内容复核；本次重锚至 [374.2-544.6]，原「基于 Lite 的衍生系统自此在法律上归于清白，视频称其结果近乎双赢」据新转写改写——新转写 538.5-544.6 作 legally unclear，535.8-537.7 处为不可解的 It wasn't mostly you, I mean，双赢之说无可核文本〕
- 386BSD 因免费开源且可运行于廉价个人计算机而流行，但补丁散布于早期网络的各 Usenet 服务器难以检索，Terry Lambert 创建的非官方 patchkit 日后膨胀至难以维护；补丁协调人 Nate Williams、Rod Grimes 与 Jordan Hubbard 计划取 386BSD 快照、套用全部相关补丁并清理代码后以独立版本发布，因 Bill Jolitz 撤回支持而受阻，遂更名 FreeBSD 继续推进，Walnut Creek CD-ROM 公司为其提供高速互联网接入与光盘发行渠道，1993 年 FreeBSD 正式问世，并在诉讼结束后迁移至 4.4BSD-Lite 基座；其后 FreeBSD 先后进入 Sony PlayStation 3 与 4 主机、Netflix 内容分发网络与 Yahoo 服务器，一度支撑互联网多数 Web 服务器后被 Linux 超越。（YouTube EPY0ixYwLd9Pg，[567.2-798.8]，L2）

**史观**：

- 总纲9 经验优先：当事人反复以工程师经验对抗管理层的抽象成本论证：COTS 转型的纸上省钱方案在他看来完全站不住脚，因为真实性能、可维护性与差异化能力只存在于一线动手者的实践 knowledge 之中；TRW 由领先者沦为跟随者的过程，正是管理层以公式化推理覆盖工程经验的后果。技术决策的正当性来自动手者的经验，而非报表上的论证。（BSDTalk EP165，[1265.06-1292.04]，L1）
- 总纲4 分离聚合是永恒规律：386BSD 补丁社区先后分立为 NetBSD 与 FreeBSD 两支，说明早期 BSD 谱系并非按预定计划展开，而是补丁协调权威周期性缺位下的社群自组织：当唯一的发布者长期消失，社区以分离的方式重新聚合，各自另立门户延续伯克利遗产。（Software Engineering Daily EP1914，[364.0-476.0]，L2）
- 总纲5 没有必然性，只有偶然性：Baldwin 以亲历者视角强调，决定 BSD 与 Linux 竞争格局的转折完全发生在技术领域之外：单个开发者无法控制的商业与法律事件，加上偶然与运气，左右了操作系统的命运；技术史的走向并不由代码优劣必然决定，法律环境的扰动足以重塑整个生态的归属。（Software Engineering Daily EP1914，[548.0-650.0]，L2）
- 总纲4 分离聚合是永恒规律：全片叙事呈现分离与聚合的循环：UNIX 自 Multics 废墟中分离而出，BSD 经 Net/1、Net/2 与 4.4BSD-Lite 逐级剥离 AT&T 代码，FreeBSD 又自 386BSD 分离，NetBSD、OpenBSD 相继分立；与此同时伯克利网络栈被几乎所有现代操作系统吸收，各分支项目延续同一传统，分离之后在各处再聚合，BSD 系统的生命力恰由不断分离而非单一谱系所维系。（YouTube EPY0ixYwLd9Pg，[903.3-908.5]，L2）
- 总纲5 没有必然性，只有偶然性：视频将 UNIX 的诞生归结为具体偶然条件与需求的凑合而非必然进程：管理层终止项目、PDP-7 恰好闲置、专利局恰需文字处理器，诸条件先后相遇方使系统在无人支持的环境中存活并繁荣，结尾以“如凤凰自 Multics 灰烬中重生”作喻，实际上否定了技术演进的必然性叙事。（YouTube EPY0ixYwLd9Pg，[878.1-890.2]，L2）
