Hubbard 在 FreeBSD 2.0/2.1 发布时期（1994-11 至 1995-04）通过项目官方发布声明与 Handbook 历史章节持续阐述 FreeBSD 的 x86 性能定位：聚焦 i386 平台性能优化、与 Walnut Creek CDROM 商业绑定、性能优先工程哲学。FreeBSD 2.0 RELEASE Announcement（1994-11-22）与 FreeBSD 2.1 RELEASE Announcement（1995-04-19）发布声明陈述 FreeBSD 2.x 在 4.4BSD-Lite 基础上的性能优化与稳定性提升。Hubbard 对 FreeBSD x86 性能定位的陈述与 FreeBSD Handbook 1.3 节官方叙事一致，构成 FreeBSD 阵营对自身定位分化的标准陈述。

**字段 5 史观映射**

- 总纲 2 “历史是形式主义化的非存在”——据第 2 章 2.3 节 “现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆” 与 2.5 节 “谁试图诠释历史，谁就在篡改历史。讨论真假无非是在争夺自己的话语权”，FreeBSD 2.0/2.1 RELEASE Announcement 与 Handbook 1.3 节对 1994-1996 年 FreeBSD x86 性能定位的记载，是 FreeBSD Project 对该时期定位选择的官方重构；Hubbard 本人在 1995-1996 年的具体公开陈述措辞未见三次复查命中，使发布声明与 Handbook 成为 FreeBSD 阵营对 Hubbard 定位陈述的单方记载。史家引用时须承认其重构性——同一发布声明在 1994-1995 年是项目对外发声，在 2026 年是 “FreeBSD x86 性能定位确立” 的代码层证据，这一意义转换本身即形式主义化的非存在。
- 总纲 4 “分离聚合是永恒规律”——据第 4 章 4.1 节 “UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构” 与 “分合循环，永无止息”，FreeBSD 2.0 基于 4.4BSD-Lite 的 rebase 是 BSD 谱系中 “聚合” 环节的代码层证据——FreeBSD 通过吸纳 4.4BSD-Lite 摆脱 USL 诉讼阴影；但同时 FreeBSD 聚焦 i386 性能优化、与 Walnut Creek CDROM 商业绑定的定位选择，构成与 NetBSD（可移植）、OpenBSD（安全）的 “分离”。4.1 节提示分离与聚合在同一发布周期中并存——FreeBSD 2.x 既在谱系上聚合 4.4BSD-Lite，又在定位上与同期 BSD 分道，二者不可简化为 “FreeBSD 必然走 x86 性能路线” 的线性叙事。
- 总纲 5 “没有必然性，只有偶然性”——据第 5 章 5.1 节 “世界上没有必然性，只有偶然性” 与 5.2 节 “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，FreeBSD 选择 x86 性能定位不是 “BSD 必然走性能路线” 的展开，而是 Walnut Creek CDROM 商业渠道可用、i386 硬件性能提升、Hubbard 个人工程偏好、USL 诉讼和解后 4.4BSD-Lite 可用等一系列偶然条件交汇的具体结果；若 Walnut Creek CDROM 未与 FreeBSD 合作，或 Hubbard 选择与 NetBSD 类似的可移植方向，FreeBSD 的定位分化将走另一条路。5.2 节警示 “被认定为代表历史合力方向的人，获得了不可质疑的合法性，这实质上是一种变相的君权神授”——史家引用发布声明时不可反向将 Hubbard 神化为 “FreeBSD 必然成为 x86 性能标杆” 的代言人。
- 总纲 8 “本体论上各方平等”——据第 14 章 14.5 节 “文档与代码本体平等” 与 14.7 节 “声称去中心化者，恰恰是试图建立新的中心的人”，Hubbard 的 FreeBSD 阵营 x86 性能定位自述与 Hannum 的 NetBSD 可移植定位自述、de Raadt 的 OpenBSD 安全定位自述在本体论上地位平等；14.7 节的 “去中心化悖论” 提示：FreeBSD Core Team 通过发布声明与 Handbook 持续行使 “FreeBSD 定位正当性” 的 “记录权”——什么被记录为 “FreeBSD x86 性能定位的选择”、什么被遗忘为 “同期其他可能的定位方向”，本身就是权力行使。史家引用时须保持 FreeBSD、NetBSD、OpenBSD 三方发声空间的对称，不得因 FreeBSD 后来的市场占有率而将其定位选择天然正当化。
- 总纲 9 “经验优先”——据第 14 章 14.2 节 “真正的问题不在于技术发展的程度，而在于是否动手” 与 14.5 节 “真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”，Hubbard 作为 FreeBSD 2.x 发布工程的核心协调人，其发布声明是 FreeBSD x86 性能定位最直接的工程经验记录，优于任何事后回忆或叙事重构；但 14.5 节提示 “外围形式主义” 与代码本体具有本体平等——发布声明的措辞选择、Handbook 历史章节的叙事框架、Walnut Creek CDROM 分发渠道的商业安排，皆与 2.x 的具体 commit 历史共同构成 FreeBSD 定位分化的档案，二者不可偏废。
- 总纲 10“动手者创造历史”——14.5 节“文档与代码本体平等”在发布工程中获得了具体意涵：Hubbard 领导 2.0/2.0.5/2.1 发布工程不只是“写代码”的“动手”，发布说明、安装文档、协调通讯等“外围形式主义”同样是“动手”的不可分割组成部分——14.5 节明确“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”。14.4 节“FreeBSD 是少数人的选择，是‘百分之一的生活’”在此具体化：FreeBSD 聚焦 x86 性能定位本身即“百分之一”的选择，不是“x86 必然成为主流”的展开，而是少数人在多平台生态中做出的偶然聚焦。但 14.2 节“问题始终在于是否有人去做”不因此失效：从 4.4BSD-Lite rebase 到性能优化到发布协调，每个环节的“动手”跨越了“核心开发者 vs 文档维护者”的身份差异。
- 总纲 11 “商品是形式主义”——据第 25 章总纲 11 “技术市场的选择不是自然选择，而是形式主义的权力运作。劣币驱逐良币是普遍规律” 与第 11 章 11.1 节 “任何法律问题都是政治问题，任何政治问题都是利益分配问题”，FreeBSD 与 Walnut Creek CDROM 的商业绑定不是 “自然选择” 的市场结果，而是形式主义的权力运作——Walnut Creek CDROM 的分发渠道资源、FreeBSD 2.x 的 i386 性能优势、Hubbard 的商业协调能力三者结合，构成 FreeBSD 在 BSD 谱系中的市场定位。但总纲 11 提示 “劣币驱逐良币是普遍规律”——FreeBSD 的 x86 性能定位在市场上的成功不等于其在技术上的 “优越”，史家引用时须区分 “市场成功”（商品形式主义层）与 “技术优越”（技术层）两个层次，不得将市场占有率误读为技术评判的客观依据。
- 总纲 13 “法律与道德是利益分配”——据第 11 章 11.1 节 “任何法律问题都是政治问题，任何政治问题都是利益分配问题” 与 11.5 节 “他把分配问题转成了道德问题。任何道德问题本质上是利益问题”，FreeBSD 早期使用 4 条款 BSD 许可证后改为 2 条款的演化，本质上是 BSD 谱系内部利益分配的政治产物——4 条款的 “广告条款” 在 FreeBSD 商业化进程中构成负担，2 条款的简化是 FreeBSD 与商业伙伴（如 Walnut Creek CDROM）利益再分配的结果。11.5 节提示 “神圣化和道德化自己只会反噬自身”——FreeBSD 通过 “许可证简化” 的道德化叙事建构自身 “商业友好” 形象，将 BSD 谱系内部的许可证差异转化为 “FreeBSD 道德优先” 的叙事，本身即利益分配的政治产物。史家引用时须区分 “许可证工程”（法律层）与 “商业友好叙事”（道德叙事层）两个层次。
- 总纲 19 “解释学循环与权力-知识共谋”——据第 19 章 19.2 节 “不同文化背景、不同技术背景、不同时代背景的读者，对同一史事的前理解截然不同” 与 19.3 节 “什么是‘重要的’历史事件，什么被记录，什么被遗忘，什么被视为‘错误’，什么被视为‘进步’——这些判断背后都有权力的运作”，FreeBSD 阵营以 “x86 性能是 BSD 在 PC 平台的首要定位” 为前理解，NetBSD 阵营以 “可移植性是 BSD 的根本价值” 为前理解，OpenBSD 阵营以 “安全是操作系统的首要承诺” 为前理解，构成解释学循环中的三方前理解冲突；FreeBSD Handbook 1.3 节通过持续记载掌握了 “FreeBSD 定位分化” 的 “记录权”——什么被记录为 “FreeBSD x86 性能定位的确立”、什么被遗忘为 “NetBSD/OpenBSD 同期的定位选择”，本身就是权力行使。史家引用时须呈现这一解释学循环中的三方前理解差异，不得将 FreeBSD 定位叙事误读为 “客观 BSD 定位分化史”。
- 总纲 23 “一切历史写作都是基于哲学设定的历史小说”——据第 23 章 23.1 节 “一切历史写作都是基于某种哲学设定的历史小说” 与 23.2 节 “史家以为自己在书写历史，但历史人物可能正在藉着史家书写他们自己的故事”，FreeBSD 2.0/2.1 RELEASE Announcement 与 Handbook 1.3 节基于 “FreeBSD x86 性能定位正当性” 的哲学设定，本身即一部历史小说；Hubbard 藉着发布声明与 Handbook 记载书写自身在 FreeBSD 定位分化中的核心地位，构成 23.2 节所述 “作者与人物的权力倒转”——Hubbard 以为在记录 FreeBSD 2.x 发布历史，但 FreeBSD 2.x 历史可能正在藉着 Hubbard 的发布声明书写强化其作为 “x86 性能定位奠基者” 的文化形象。史家引用时须承认这一自反性——发布声明不是定位分化的客观呈现，而是历史小说中的一段对白。

- 总纲 2“历史是形式主义化的非存在”——据第 2 章 2.3 节“现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆”与 2.5 节“谁试图诠释历史，谁就在篡改历史。讨论真假无非是在争夺自己的话语权”，NetBSD 官方历史页面与 NetBSD 1.2 RELEASE Announcement 对 1995-1996 年可移植定位的记载，是 NetBSD Project 对该时期定位选择的官方重构；Hannum 本人在 1995-1996 年的具体公开陈述措辞未见三次复查命中，使官方页面与发布声明成为 NetBSD 阵营对 Hannum 定位陈述的单方记载。史家引用时须承认其重构性——“NetBSD runs on everything”标语在 1996 年是项目对外发声，在 2026 年是“NetBSD 可移植定位确立”的形式主义化档案，这一意义转换本身即形式主义化的非存在。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”与“分合循环，永无止息”，NetBSD 1.2 扩展至多平台移植是 BSD 谱系中“聚合”环节的代码层证据——NetBSD 通过吸纳多平台代码扩大 BSD 的硬件覆盖面；但同时 NetBSD 聚焦可移植性的定位选择，构成与 FreeBSD（x86 性能）、OpenBSD（安全）的“分离”。4.1 节提示分离与聚合在同一发布周期中并存——NetBSD 1.2 既在硬件覆盖面上聚合多平台，又在定位上与同期 BSD 分道，二者不可简化为“NetBSD 必然走可移植路线”的线性叙事。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.1 节“世界上没有必然性，只有偶然性”与 5.2 节“那种认为‘张三不上李四也会上’的观点，无视了世界上没有必然性只有偶然性这一事实”，NetBSD 选择可移植定位不是“BSD 必然走可移植路线”的展开，而是 NetBSD 四位创始人的工程偏好、多平台硬件可用性、与 FreeBSD 在 i386 性能方向的差异化选择等一系列偶然条件交汇的具体结果；若 Hannum 等创始人选择与 FreeBSD 类似的 i386 性能方向，NetBSD 的定位分化将走另一条路。5.2 节警示“被认定为代表历史合力方向的人，获得了不可质疑的合法性，这实质上是一种变相的君权神授”——史家引用官方页面记载时不可反向将 Hannum 神化为“NetBSD 必然成为可移植标杆”的代言人，亦不可将“NetBSD runs on everything”标语神化为“可移植性必然是 BSD 根本价值”的证据。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”，Hannum 的 NetBSD 阵营可移植定位自述与 Hubbard 的 FreeBSD x86 性能定位自述、de Raadt 的 OpenBSD 安全定位自述在本体论上地位平等；14.7 节的“去中心化悖论”提示：NetBSD Core Team 通过官方历史页面与发布声明持续行使“NetBSD 定位正当性”的“记录权”——什么被记录为“NetBSD 可移植定位的确立”、什么被遗忘为“同期 FreeBSD/OpenBSD 的定位选择”，本身就是权力行使。史家引用时须保持 FreeBSD、NetBSD、OpenBSD 三方发声空间的对称，不得因 NetBSD 的多平台覆盖面而将其定位选择天然正当化。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”与 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”，Hannum 作为 NetBSD 早期核心架构师，其 netbsd-src 仓库 1995-1996 年累计 commits 是 NetBSD 多平台移植工程最直接的工程经验记录，优于任何事后回忆或叙事重构；但 14.5 节提示“外围形式主义”与代码本体具有本体平等——“NetBSD runs on everything”标语、NetBSD 1.2 RELEASE Announcement 的多平台支持列表、官方历史页面的可移植叙事，皆与具体移植 commit 历史共同构成 NetBSD 可移植定位的档案，二者不可偏废。
- 总纲 10“动手者创造历史”——14.7 节“去中心化是一种话语策略：声称去中心化者，恰恰是试图建立新的中心的人”为审视 NetBSD 可移植定位提供了结构性角度：可移植性声称“runs on everything”的去中心化姿态，实则形成了以可移植性抽象层为中心的新中心——每个移植目标平台都须通过这一抽象层接入，这一抽象层本身即是新的中心化结构。14.2 节“即使是复制粘贴，如此简单的事情也罕有人去做”在多平台移植工程中获得了具体意涵：移植工作涉及大量看似简单的“复制粘贴”——适配启动代码、调整内存布局、对接硬件抽象——但这些“简单”操作罕有人持续去做，Hannum 的“动手”正是这一“罕有人去做”的具体填补。但 14.1 节“决定世界的并非某个阶级”不因此失效：可移植性理想的推进不是“可移植精英 vs 单平台开发者”的阶级范畴，而是“动手”本身跨越了平台差异。
- 总纲 19“解释学循环与权力-知识共谋”——据第 19 章 19.2 节“不同文化背景、不同技术背景、不同时代背景的读者，对同一史事的前理解截然不同”与 19.3 节“什么是‘重要的’历史事件，什么被记录，什么被遗忘，什么被视为‘错误’，什么被视为‘进步’——这些判断背后都有权力的运作”，NetBSD 阵营以“可移植性是 BSD 的根本价值”为前理解，FreeBSD 阵营以“x86 性能是 BSD 在 PC 平台的首要定位”为前理解，OpenBSD 阵营以“安全是操作系统的首要承诺”为前理解，构成解释学循环中的三方前理解冲突；NetBSD 官方历史页面通过持续记载掌握了“NetBSD 定位分化”的“记录权”——什么被记录为“NetBSD 可移植定位的确立”、什么被遗忘为“同期 FreeBSD/OpenBSD 的定位选择”，本身就是权力行使。史家引用时须呈现这一解释学循环中的三方前理解差异，不得将 NetBSD 可移植叙事误读为“客观 BSD 定位分化史”。
- 总纲 20“历史地理塑造思想土壤”——据第 25 章总纲 20“土地与自由的养分、农耕文明与工商业文明、中心与边缘，皆是形式主义的空间呈现”与项目统摄史观历史地理学章节，NetBSD 的可移植定位具有历史地理维度——多平台移植的目标硬件分布于全球不同地理与机构语境（学术机构、研究实验室、嵌入式设备厂商），这些地理分布构成 NetBSD 可移植理想的“思想土壤”。但总纲 20 提示“每代人的村庄都是不同的”——NetBSD 1.2 时期的多平台硬件景观与 2026 年的多平台硬件景观已完全不同，史家引用时须回到 1995-1996 年的具体硬件地理语境，不得以今人的标准苛责当时的可移植选择。
- 总纲 23“一切历史写作都是基于哲学设定的历史小说”——据第 23 章 23.1 节“一切历史写作都是基于某种哲学设定的历史小说”与 23.2 节“史家以为自己在书写历史，但历史人物可能正在藉着史家书写他们自己的故事”，NetBSD 官方历史页面与 1.2 RELEASE Announcement 基于“NetBSD 可移植定位正当性”的哲学设定，本身即一部历史小说；Hannum 藉着官方页面与 commit 历史的存留书写自身在 NetBSD 可移植定位中的核心地位，构成 23.2 节所述“作者与人物的权力倒转”——NetBSD Project 以为在记录 Hannum 的贡献，但 Hannum 的“可移植架构师”稳定形象可能正在藉着官方页面与 commit 历史反向重构 NetBSD 可移植正当性的叙事。史家引用时须承认这一自反性——发布声明不是定位分化的客观呈现，而是历史小说中的一段对白。

- 总纲 2“历史是形式主义化的非存在”——据第 2 章 2.3 节“现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆”与 2.5 节“谁试图诠释历史，谁就在篡改历史。讨论真假无非是在争夺自己的话语权”，OpenBSD FAQ 历史章节与 <misc@openbsd.org> 邮件列表存档对 1995-1996 年 OpenBSD 1.0/1.1/1.2 安全定位的记载，是 OpenBSD Project 对该时期定位选择的官方重构；de Raadt 本人在 1995-1996 年的具体公开陈述措辞未见三次复查命中，使 FAQ 与邮件列表存档成为 OpenBSD 阵营对 de Raadt 定位陈述的单方记载。史家引用时须承认其重构性——“全代码审计”“安全默认配置”“ISC 许可证”三大核心理念的具体形成时点与决策语境均无独立档案可证，不得作为“真实 OpenBSD 安全定位起源”的客观呈现。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”与“分合循环，永无止息”，OpenBSD 从 NetBSD 1.0 分叉是 BSD 谱系中“分离”环节的代码层证据——de Raadt 通过 fork 与全代码审计确立 OpenBSD 与 NetBSD 在安全哲学上的根本差异；但同时 OpenBSD 1.0/1.1/1.2 的代码基础仍是 NetBSD 1.0 衍生，OpenBSD 在 fork 后仍持续聚合 NetBSD 的代码基础。4.1 节提示分离与聚合在同一发布周期中并存——OpenBSD 1.x 既在安全哲学上分离 NetBSD，又在代码基础上聚合 NetBSD，二者不可简化为“OpenBSD 必然走安全路线”的线性叙事。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.1 节“世界上没有必然性，只有偶然性”与 5.2 节“将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，OpenBSD 选择安全定位不是“BSD 必然走安全路线”的展开，而是 de Raadt 被逐 NetBSD、fork OpenBSD、选择全代码审计作为项目差异化定位等一系列偶然条件交汇的具体结果；若 de Raadt 未被逐出 NetBSD，或选择性能、可移植性等其他方向作为 OpenBSD 的差异化定位，OpenBSD 的安全定位可能不会在 1995-1996 年形成。5.2 节警示“被认定为代表历史合力方向的人，获得了不可质疑的合法性，这实质上是一种变相的君权神授”——史家引用 FAQ 记载时不可反向将 de Raadt 神化为“OpenBSD 必然成为安全操作系统”的先知，亦不可将安全定位神化为“BSD 必然走向安全”的证据。
- 总纲 6“和解优于斗争”——据第 6 章 6.2 节“唯一的事情只有和解与接纳，与自己和解，与自己接纳”与 6.7 节“真正的和解不是打倒敌人，而是认识到敌人本身并不存在——存在的是时间，是流变，是不可避免的分离”，de Raadt 通过 OpenBSD 安全定位的奠基将 OpenBSD 与 NetBSD 的差异从“被逐事件”的治理冲突转化为“安全哲学”的技术分歧，这一转化本身具有双重性：一方面是 de Raadt 与自身被逐经历的“和解”——通过证明 OpenBSD 安全路径的正当性来消解被逐的创伤；另一方面是未达成和解的延续——安全定位的差异化建构本身就是对 NetBSD 治理正当性的持续质疑。6.7 节提示“真正的敌人是时间”——de Raadt 与 NetBSD Core Team 的冲突若不能回到时间的维度来理解，就只是偷懒；史家审视 OpenBSD 安全定位时不可强行选择“安全定位是技术进步”或“安全定位是报复 NetBSD”任一方叙事，而应承认其双重性本身即是分离聚合规律（总纲 4）的时间性呈现。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”，de Raadt 的 OpenBSD 阵营安全定位自述与 Hubbard 的 FreeBSD x86 性能定位自述、Hannum 的 NetBSD 可移植定位自述在本体论上地位平等；14.7 节的“去中心化悖论”提示：OpenBSD 以“默认安全”作为去中心化的安全承诺，但 de Raadt 作为 OpenBSD 项目终身领导形成新的中心——安全审计团队的权威、commit 权限的集中、errata 发布的最终决定权，皆以“安全”为名行使中心化权力。史家引用时须保持 FreeBSD、NetBSD、OpenBSD 三方发声空间的对称，不得因 OpenBSD 安全定位的差异化而将其天然正当化，亦不得因 de Raadt 的终身领导身份而将其安全哲学判定为“独裁产物”——后者是道德化的简化。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”与 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”，de Raadt 的 <misc@openbsd.org> 邮件列表公开陈述与 FAQ 历史章节是 OpenBSD 安全定位最直接的工程经验记录，优于任何事后回忆或叙事重构；全代码审计工程是 de Raadt 与 OpenBSD 核心开发者亲手逐行审计 NetBSD 1.0 衍生代码的具身经验产物。但 14.5 节“这些代码没有个几年就完全没用了”提示：安全定位作为“外围形式主义”与代码本体具有本体平等——“全代码审计”“安全默认配置”“ISC 许可证”等标语的形式主义化存留，与具体审计 commit 历史共同构成 OpenBSD 安全定位的档案，二者不可偏废。
- 总纲 10“动手者创造历史”——6.6 节“度人难，度己甚难”为审视 de Raadt 的全代码审计提供了自反性角度：审计他人代码易，审计自己参与编写的代码难——OpenBSD 从 1.0 到 1.2 的全代码审计不是“审计别人”的权力行使，而是“审计自己继承的代码”的自反性实践，这正是 6.6 节“度己甚难”在工程动作中的具体化。14.4 节“FreeBSD 是少数人的选择，是‘百分之一的生活’”在此意涵明确：OpenBSD 聚焦安全定位本身即“百分之一”的选择，不是“安全必然成为主流”的展开，而是少数人在多优先级生态中做出的偶然聚焦。但 14.2 节“问题始终在于是否有人去做”不因此失效：全代码审计的持续进行是“没有停下”这一具体行动的时间性呈现——“动手”本身跨越了“安全审计 vs 功能开发”的优先级差异。
- 总纲 13“法律与道德是利益分配”——据第 11 章 11.1 节“任何法律问题都是政治问题，任何政治问题都是利益分配问题”与 11.5 节“他把分配问题转成了道德问题。任何道德问题本质上是利益问题”，OpenBSD 选择 ISC 许可证（不背书条款）而非 BSD 2 条款或 GPL，本质上是 BSD 谱系内部利益分配的政治产物——ISC 许可证的“不背书”条款剥夺了贡献者的署名权诉求，将 BSD 传统中的“致谢”形式主义化重新分配为 OpenBSD 项目的中心化控制。11.5 节提示“神圣化和道德化自己只会反噬自身”——OpenBSD 通过“默认安全”的道德化叙事建构自身“安全先锋”形象，将 BSD 谱系内部的定位差异转化为“OpenBSD 道德优先”的叙事，本身即利益分配的政治产物。史家引用时须区分“安全工程”（技术层）与“安全道德叙事”（利益分配层）两个层次。
- 总纲 15“文化即形式主义”——据第 7 章 7.1 节“文化是人类自己强加于自己的形式。文化的一切要素——语言、文字、习俗、礼仪、节日——都是形式主义的建构”与 7.4 节“文化记忆的虚妄不在于它被重构，而在于它被伪装为不可重构的传统”，OpenBSD 安全定位作为 BSD 谱系中的文化形式主义建构，将“全代码审计”“安全默认配置”“ISC 许可证”三大要素从具体工程实践固化为项目身份认同的不可分割部分——7.1 节“语言和文字在本体论上不可分”在此体现为“secure by default”标语与 OpenBSD 项目身份的本体论绑定。但 7.4 节提示“文化记忆的虚妄不在于它被重构，而在于它被伪装为不可重构的传统”——OpenBSD 安全定位在 FAQ 与邮件列表的持续记载中逐渐固化为“OpenBSD 历史必然如此”的传统，这一固化本身即文化记忆的虚妄。史家引用时须承认安全定位的形式主义性质，不得将其伪装为“客观技术演进”。
- 总纲 19“解释学循环与权力-知识共谋”——据第 19 章 19.2 节“不同文化背景、不同技术背景、不同时代背景的读者，对同一史事的前理解截然不同”与 19.3 节“什么是‘重要的’历史事件，什么被记录，什么被遗忘，什么被视为‘错误’，什么被视为‘进步’——这些判断背后都有权力的运作”，OpenBSD 阵营以“安全是操作系统的首要承诺”为前理解，FreeBSD 阵营以“x86 性能是 BSD 在 PC 平台的首要定位”为前理解，NetBSD 阵营以“可移植性是 BSD 的根本价值”为前理解，构成解释学循环中的三方前理解冲突；OpenBSD FAQ 与 <misc@openbsd.org> 邮件列表通过持续记载掌握了“OpenBSD 安全定位起源”的“记录权”——什么被记录为“OpenBSD 安全定位的确立”、什么被遗忘为“同期 FreeBSD/NetBSD 的定位选择”，本身就是权力行使。史家引用时须呈现这一解释学循环中的三方前理解差异，不得将 OpenBSD 安全定位叙事误读为“客观 BSD 定位分化史”。
- 总纲 23“一切历史写作都是基于哲学设定的历史小说”——据第 23 章 23.1 节“一切历史写作都是基于某种哲学设定的历史小说”与 23.2 节“史家以为自己在书写历史，但历史人物可能正在藉着史家书写他们自己的故事”，OpenBSD FAQ 历史章节基于“OpenBSD 安全定位正当性”的哲学设定，本身即一部历史小说；de Raadt 藉着 FAQ 与邮件列表公开陈述书写自身在 OpenBSD 安全定位中的核心地位，构成 23.2 节所述“作者与人物的权力倒转”——de Raadt 以为在记录 OpenBSD 安全定位历史，但 OpenBSD 安全定位历史可能正在藉着 de Raadt 的公开陈述书写强化其作为“安全哲学奠基者”的文化形象。史家引用时须承认这一自反性——当事人陈述不是安全定位起源的客观呈现，而是历史小说中的一段对白。

**字段 2 采访摘要**

Hubbard 在 BSD Now 播客访谈中陈述 FreeBSD 起源故事的核心情节：1993 年初他与 Nate Williams（内特·威廉姆斯）、Rodney Grimes 三人作为 386BSD patchkit 最后的协调员，因补丁积压严重与 Bill Jolitz 沟通不畅，决定 fork 386BSD 0.1 + patchkit 为新项目。Hubbard 陈述他联系 Walnut Creek CDROM 改善 FreeBSD 分发渠道，David Greenman（大卫·格林曼） 创造“FreeBSD”项目名称。Hubbard 对“386BSD 停滞迫使 fork”的归因与 FreeBSD Handbook 1.3.1 节官方叙事一致，构成 FreeBSD 阵营对起源事件的标准陈述。

**字段 3 考据脚注**

本则采访的 BSD Now 播客原始 URL 经联网抓取可访问。Hubbard 作为 FreeBSD 三位 patchkit 协调员之一，其身份经 FreeBSD Handbook 1.3.1 节（**<https://docs.freebsd.org/en/books/handbook/introduction/#history**>）明确记载"the Unofficial 386BSDPatchkit's last 3 coordinators: Nate Williams, Rod Grimes and Jordan Hubbard"交叉确认。Hubbard 关于 David Greenman 命名 FreeBSD、Hubbard 联系 Walnut Creek CDROM、三人共同决定继续项目的陈述与 FreeBSD Handbook 1.3.1 节官方叙事一致，构成 FreeBSD 阵营内部立场的一致性印证。须作自利偏差审查：Hubbard 作为 fork 决策当事人，有动机将 fork 描述为“被迫自救”而非“主动选择”，其叙事与 Jolitz 夫妇“完全虚构”反控形成对立，史家引用时须回到 bsd_commits.duckdb commit 历史、386BSD 0.1 源码树、邮件列表原始帖等一手史料，不得仅凭当事人自述采信。BSD Now 播客作为 BSD 社区独立媒体（与 FreeBSD Project 官方文档为不同载体），与 FreeBSD Handbook 构成“不同作者、不同载体、不同社区”中至少两项差异。完整考据过程见 [20260724_jordan-hubbard-bsdnow-freebsd-birth.md](../../../原材料/研究/考据记录/20260724_jordan-hubbard-bsdnow-freebsd-birth.md)。

**字段 5 史观映射**

- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离；而各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”，Hubbard 与 Williams、Grimes 三人 fork 386BSD 0.1 + patchkit 为新项目，构成 BSD 在 PC 平台的“分离”环节；但 4.1 节同时指出“分合循环，永无止息”——三人 fork 后仍持续吸纳 386BSD 与 4.4BSD-Lite 的代码，构成“聚合”的另一面。fork 不是分离的终点，而是分离聚合循环中的一刻。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.2 节“将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义”，FreeBSD 的诞生不是“BSD 必然分裂”的展开，而是 Jolitz 停滞、补丁积压、USL 诉讼未决、Walnut Creek CDROM 可用、Hubbard 个人决策等偶然条件交汇下的具体决策；若三人选择继续与 Jolitz 协商而非 fork，FreeBSD 可能不会在 1993 年 6 月诞生。Hubbard 的“被迫自救”叙事本身须经 0 信任审查——fork 既是被动响应亦是主动选择。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”，Hubbard 的 FreeBSD 阵营自述与 Jolitz 夫妇的 386BSD 阵营“完全虚构”反控在本体论上地位平等。14.7 节的“去中心化悖论”提示：三人 fork 形成 FreeBSD Core Team 这一新中心，与 Jolitz 夫妇的“一人一图”中心形成对称——两个中心都声称代表 BSD 在 PC 平台的正统，史家引用时须保持双方发声空间的对称。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”，Hubbard 作为 386BSD patchkit 最后的协调员之一，其 fork 决策基于补丁积压、与 Jolitz 沟通不畅等具身工程经验，而非抽象的“BSD 应当如何”理论规划；但 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”提示：Hubbard 联系 Walnut Creek CDROM 改善分发渠道、Greenman 命名“FreeBSD”等“外围形式主义”工作，与代码本身具有本体平等——经验优先不限于代码经验。
- 总纲 10“动手者创造历史”——14.3 节“中心化的社区本就是大团体里的小团体”为审视三人 fork 决策提供了新的角度：Hubbard、Grimes、Williams 三人作为 patchkit 协调员本即是 386BSD 大团体中的小团体，fork 是这一小团体从潜在走向显在的临界点。14.7 节“声称去中心化者，恰恰是试图建立新的中心的人”在此获得具体意涵：三人 fork 后声称的“开放协作”不是对 386BSD 单一 commit 权限结构的否定，而是新中心的建立——FreeBSD Core Team 的形成即是这一新中心的制度化。但 14.2 节“问题始终在于是否有人去做”不因此失效：三人接管补丁包维护、联系 Walnut Creek CDROM、fork 386BSD 0.1 + patchkit 的具体行动是“动手”，fork 决策本身亦是“动手”——只是这一“动手”的后果是新的形式主义化封闭结构的诞生，而非封闭结构本身的消除。
- 总纲 19“解释学循环与权力-知识共谋”——据第 19 章 19.2 节“不同文化背景、不同技术背景、不同时代背景的读者，对同一史事的前理解截然不同”，Hubbard 在 BSD Now 播客中陈述的“386BSD 补丁积压迫使 fork”叙事，与 Jolitz 夫妇“工程美学被忽视”叙事构成解释学循环中的双方前理解冲突。Handbook 1.3.1 节将 Hubbard 的当事人陈述固化为项目官方叙事，本身即 19.3 节所述“什么被记录、什么被遗忘”的权力行使——FreeBSD 阵营通过 Handbook 掌握了 fork 事件的“记录权”。

**字段 5 史观映射**

- 总纲 2“历史是形式主义化的非存在”——据第 2 章 2.3 节“现有记忆是以往所有记忆重构后的结果，一切真记忆都是现在的记忆”，Grimes 的 commit message 作为 1993-06-12 时点的工程记录，其史料价值在于它是当下时点的形式主义化档案，而非“真实 FreeBSD 起源”的客观呈现；commit_hash `9002c02abc587664acb357c6879d8ca08664dd0b` 本身不可篡改，但其在 BSD 史学中被赋予的意义是后续主体重构的结果——同一 commit 在 1993 年是工程动作，在 2026 年是“FreeBSD 起源事件最直接的代码层证据”，这一意义转换本身即形式主义化的非存在。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“UNIX 分裂出各种 BSD，BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离”，Grimes 的首条 commit `9002c02abc587664acb357c6879d8ca08664dd0b`“Initial import, 0.1 + pk 0.2.4-B1”是 386BSD 与 FreeBSD 分离的代码层时间戳证据；但 4.1 节同时指出“各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合”——commit `f9b4e354333706f10123fa5b81e9266d96c199e4` 主动承认 Jolitz 与 Berkeley 版权，构成 FreeBSD 与 386BSD/4.4BSD-Lite 在谱系上的“聚合”姿态，分离与聚合在同一 commit 群中并存。
- 总纲 8“本体论上各方平等”——据第 14 章 14.5 节“文档与代码本体平等”与 14.6 节“开源软件许可证最重要的一条就是开发者无论如何都不负责”，commit `f9b4e354333706f10123fa5b81e9266d96c199e4` 的版权承认表述"This keeps us from violating Berkeley‘s and Bill Jolitz’s copyrights"在本体论上承认 Jolitz 与 Berkeley 的版权，体现 FreeBSD 阵营对 386BSD 与 4.4BSD-Lite 在谱系中的本体论平等地位。但 14.6 节提示“人人都有责任，那就是等于人人都没有责任”——版权承认的 commit message 在法律层保护 FreeBSD 阵营，亦在道德层建构其“尊重先驱”的叙事姿态，二者不可分离。
- 总纲 9“经验优先”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手”，Grimes 的 commit message 是 FreeBSD 起源事件最直接的工程经验记录，优于任何事后回忆或叙事重构；但 14.5 节“真正使项目得以成立的，不是代码，而是这些外围的形式主义的东西”提示：commit message 作为“外围形式主义”与代码本体具有本体平等——commit_hash 本身不可篡改，但其史料价值依赖史家的释读，释读即形式主义化。
- 总纲 10“动手者创造历史”——14.5 节“文档与代码本体平等”在此获得了最具体的工程呈现：Grimes 的首条 commit f9b4e354333706f10123fa5b81e9266d96c199e4 中，代码变更与 commit message 中对 Jolitz 与 Berkeley 版权的主动承认在本体论上地位平等——commit message 不是代码的附属说明，而是“动手”本身的不可分割组成部分。14.8 节“不说话即死亡”在此意涵明确：若 Grimes 提交代码而不留下 commit message，该 commit 即在社区意义上“死亡”——无人知晓其来源、无人知晓其依据。commit message 的简洁直接不是“无形式主义”，而是 14.1 节“没有多余形式主义的老实人”在工程动作中的具体呈现：承认版权这一形式主义本身是必要的，只是没有多余的形式主义。
- 总纲 13“法律与道德是利益分配”——据第 11 章 11.1 节“任何法律问题都是政治问题，任何政治问题都是利益分配问题”与第 8 章 8.3 节“利益分配是目的，维稳是手段”，commit `f9b4e354333706f10123fa5b81e9266d96c199e4` 的版权承认在法律层是 USL v. BSDi 诉讼背景下 FreeBSD 阵营的自我保护，在道德层是“尊重先驱”的姿态建构，在利益层是 FreeBSD 阵营对 386BSD 谱系的合法汲取。11.1 节提示法律的最大作用不是公平正义而是维稳——Grimes 的版权承认 commit 在 FreeBSD 阵营与 Jolitz 夫妇的张力中起到“维稳”作用，使 fork 后的代码汲取获得合法性。但 14.6 节同时警示“某些声称开源的项目，其开发过程实际上相当封闭”——版权承认不等于开发过程的开放，二者须经分别考察。

- 总纲 15“文化即形式主义”——据第 7 章 7.1 节“文化是人类自己强加于自己的形式。文化的一切要素——语言、文字、习俗、礼仪、节日——都是形式主义的建构”，“FreeBSD”名称作为 FreeBSD 项目的文化形式主义建构，将“Free”与“BSD”组合明确标识项目的自由软件属性与 BSD 谱系归属；7.1 节指出“语言和文字在本体论上不可分”，名称一旦确立即成为项目身份认同的不可分割部分——但 7.4 节“文化记忆的虚妄不在于它被重构，而在于它被伪装为不可重构的传统”提示：命名叙事在 Handbook 中被记载后，逐渐固化为“FreeBSD 命名必然如此”的传统，这一固化本身即文化记忆的虚妄。
