# 68.13 与同时期操作系统的比较：1993 年同期 Linux 1.0 路径、FreeBSD 1.0 路径、386BSD 1.0 路径

## 68.13.1 Linux 1.0 路径的比较

  **要点**：1993-1994 年 Linux 1.0 路径与 NetBSD 同期发布，Linux 选择 GPL 许可证与单平台优先（i386），快速吸纳商业资源；NetBSD 选择 BSD 许可证与多平台优先，路径分化决定后续竞争力差距
  
**史料**：Linux 1.0 发布声明（1994.3.14）、NetBSD 0.8/0.9 发布声明、Linus Torvalds 与 Hannum 在 comp.os.linux 与 comp.unix.bsd 的早期帖［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L2 即时通讯/L3 官方文档〕
  
**史观**：组织结构塑造技术路径：许可证与平台策略的选择是路径分化的关键节点
  
**辨析**：路径优劣在不同时期叙事中评价反转——早期 Linux 商业优势被视为胜出，后期 BSD 许可证灵活性被视为优势；需对照 1990 年代中期商业叙事核实
  
**文献**：Torvalds“Linux 1.0”发布声明；NetBSD 0.8/0.9 发布声明；Salus“A Quarter Century of UNIX” (1994)［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 68.13.2 FreeBSD 1.0 路径的比较

  **要点**：NetBSD 0.8（1993 年 4 月）早于 FreeBSD 1.0（1993 年 11 月网络公告，12 月 CD-ROM）约 7 个月发布；FreeBSD 聚焦 i386 性能与 Walnut Creek CDROM 商业绑定，快速积累用户基数；NetBSD 初期同样以 i386 为唯一平台，后续版本逐步转向多平台移植优先，用户基数增长缓慢
  
**史料**：FreeBSD 1.0 发布声明（1993.11.1）、NetBSD 0.8 发布声明（1993.4.19）、Jordan Hubbard 与 Demetriou 早期邮件列表发言 ［A］
  
**史观**：商业与社区的张力：FreeBSD 的商业绑定与 NetBSD 的纯社区路径形成对比，影响后续工程投入
  
**辨析**：NetBSD 0.8（1993.4）明确早于 FreeBSD 1.0（1993.11）约 7 个月，两项目为同期从 386BSD 分叉的并行项目而非先后派生；NetBSD 0.8 仅支持 i386 平台，“多平台优先”是后续版本（0.9/1.0）逐步确立的方向
  
**文献**：FreeBSD 1.0 RELEASE Announcement (1 Nov 1993)；Demetriou C G. NetBSD 0.8 Release Announcement (19 Apr 1993)；Hubbard“FreeBSD History”访谈 ［B］

## 68.13.3 386BSD 1.0 路径的比较

  **要点**：1993-1994 年 386BSD 1.0 路径因 Jolitz 停止维护而中断，剩余用户分流至 FreeBSD 与 NetBSD；386BSD 的中断是 BSD 阵营分裂的直接诱因
  
**史料**：386BSD 1.0 补丁发布（1994）、comp.unix.bsd 1993-1994 年存档、Jolitz“Porting UNIX to the 386”后续连载 ［A］
  
**史观**：总纲第 9 条——偶然性改写历史：Jolitz 停止维护的个人决定是 BSD 阵营分裂的偶然诱因
  
**辨析**：Jolitz 停止维护的具体诱因存在不同叙事——部分归因于精力耗尽，部分归因于社区冲突；需对照 Jolitz 夫妇公开自述核实
  
**文献**：Jolitz & Jolitz“Porting UNIX to the 386”DDJ 1991-1992 连载；comp.unix.bsd 1993-1994 年存档 ［A］

## 68.13.4 三路径的命运分化

  **要点**：Linux、FreeBSD、NetBSD、386BSD 四路径在 1993-2000 年间命运分化——Linux 商业资源汇聚，FreeBSD 聚焦 i386 与服务器市场，NetBSD 坚守多平台移植，386BSD 中断；分化决定后续竞争力格局。四路径分化对照如下：

| 项目 | 许可证 | 平台策略 | 商业绑定 | 后续命运 |
| -- | ---- | ------ | ------ | ------ |
| Linux | GPL | 单平台优先（i386） | 商业资源汇聚 | 商业胜出 |
| FreeBSD | BSD | i386 性能优先 | Walnut Creek CDROM | 服务器市场立足 |
| NetBSD | BSD | 多平台移植优先 | 较少 | 嵌入式与边缘平台 |
| 386BSD | BSD | 单平台 | 无 | 维护中断，用户分流 |

**史料**：四项目 1993-2000 年发布历史、商业赞助记录、用户基数统计［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档与公告〕

**史观**：组织结构塑造技术路径：四路径的命运分化是许可证、平台策略、商业绑定与社区治理的综合结果

**辨析**：命运分化的主因存在不同叙事——Linux 派归因于 GPL，BSD 派归因于商业绑定差异；需对照多项目交叉数据核实

**文献**：四项目 1993-2000 年发布历史；BSD vs Linux 商业赞助记录［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

### 史观映射

> “of course it runs NetBSD”——这句自嘲背后是一个严肃的立场：没有哪个平台天生比另一个更重要。在 NetBSD 的世界里，每块硬件都是一个等待被移植的平等主体。但这种平等是有代价的：当你的资源分散到数十个平台，每个平台都只能得到最少的关注。可移植的理想是一种对有限性的抵抗——人的精力有限，但 NetBSD 假装这种有限性不存在，结果是在每一个平台上都活着，但在每一个平台上都活得不够好
