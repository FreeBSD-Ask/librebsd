# 68.14 NetBSD 0.8/0.9 对 386BSD 安全基线的直接继承与 NetBSD 1.0 rebase 后的迁移（1993-1994）

## 68.14.1 NetBSD 0.8/0.9 对 386BSD 0.1 + 0.2.2 patch kit 安全基线的直接继承

  **要点**：**NetBSD 0.8**（**1993-04-19** 公告）以 386BSD 0.1 为基础并应用 0.2.2 patch kit，集成 Berkeley Networking Release 2（Net/2）中 386BSD 缺失的程序，直接继承 386BSD 0.1 的安全基线——root/超级用户二元特权模型、文件权限 rwx 三段式结构、setuid/setgid 机制、基于 DES 的 **crypt(3)** 密码散列、单文件 `/etc/passwd`（未引入 shadow password）、4.3BSD 网络栈远程漏洞面（sendmail DEBUG、fingerd 缓冲区溢出、`~/.rhosts` 信任链）；这一安全基线本质上是 4.3BSD-Reno 安全机制在 80386 平台的移植，未引入新的安全机制，亦未引入 securelevel（4.4BSD-Lite 才引入）、chroot 安全沙箱用途（4.4BSD-Lite 时期仍为构建隔离用途）、shadow password（System V 才有 `/etc/shadow`）。NetBSD 0.8/0.9 安全基线机制对照如下：

| 机制 | 来源 | 引入版本 |
| -- | -- | ------ |
| root/超级用户二元特权模型 | Research UNIX v4 | 386BSD 0.1 继承 |
| 文件权限 rwx 三段式结构 | UNIX v4/v6 | 386BSD 0.1 继承 |
| setuid/setgid 机制 | UNIX v6（1972 年 丹尼斯·里奇（Dennis Ritchie）） | 386BSD 0.1 继承 |
| 基于 DES 的 **crypt(3)** 密码散列 | UNIX v7（1976 年 Morris/Thompson） | 386BSD 0.1 继承 |
| 单文件 `/etc/passwd` | UNIX 传统 | 386BSD 0.1 继承 |
| 4.3BSD 网络栈远程漏洞面 | 4.3BSD-Reno | 386BSD 0.1 继承 |
| securelevel | 4.4BSD-Lite | **NetBSD 1.0** rebase 后引入 |
| chroot 安全沙箱用途 | 4.4BSD-Lite | **NetBSD 1.0** rebase 后引入 |
| shadow password（`/etc/shadow`） | System V | 未引入 |

**史料**：Demetriou 0.8 原始公告（1993.4.19，明确记载"based heavily on 386BSD 0.1, patched with the 0.2.2 patch kit"）、NetBSD 0.8 Installation Notes、386BSD 0.0/0.1 源码与 release notes、CSRG 邮件列表存档；netbsd.duckdb 数据库证据——netbsd-src 仓库首条 commit 为 cgd（Chris Demetriou）1993-03-21T09:45:37Z“initial import of 386bsd-0.1 sources”（commit_hash `0d110d127c41d7aeb2b1bfdc71964c5a496eabf9`），证实 NetBSD 项目以 386BSD 0.1 源码 import 为代码起步，与公告中“based heavily on 386BSD 0.1”的叙事完全吻合 ［A］

**史观**：总纲第 4 条——分离与聚合：NetBSD 从 386BSD 分离后聚合为独立项目，但安全基线经 fork 直接继承；总纲第 17 条——软件工程：386BSD 0.1 + 0.2.2 patch kit 的代码继承是 BSD 工程传统的延续

**辨析**：NetBSD 0.8 仅支持 i386 平台（ISA/EISA 系统），多平台支持在后续版本中逐步实现，“可移植理想”是 0.9/1.0 及后续版本逐步确立的方向，安全基线在 0.8 时点完全继承自 386BSD 0.1；386BSD 0.1 基线中包含的 4.3BSD 网络栈远程漏洞面（sendmail DEBUG、fingerd 缓冲区溢出）经 NetBSD 0.8/0.9 直接传递至 NetBSD 早期版本，这些漏洞面在 NetBSD 1.0 rebase 至 4.4BSD-Lite 后方被部分缓解；0 信任原则提示：netbsd-src GitHub 镜像可能滞后于 CVS 主仓，1993-03-21 的 import commit 须与 NetBSD 官方档案与 0.8 公告交叉验证

## 68.14.2 NetBSD 0.8/0.9 安全基线内容：4.3BSD-Reno 安全机制在 80386 平台的完整移植

  **要点**：NetBSD 0.8/0.9 安全基线的内容为 4.3BSD-Reno 安全机制在 80386 平台的完整移植——root/超级用户二元特权模型（继承自 Research UNIX v4）、文件权限 rwx 三段式结构（继承自 UNIX v4/v6）、setuid/setgid 机制（继承自 UNIX v6，1972 年丹尼斯·里奇引入）、基于 DES 的 **crypt(3)** 密码散列（继承自 UNIX v7，1976 年 Robert Morris（罗伯特·莫里斯） 与肯·汤普森（Ken Thompson）引入）、单文件 `/etc/passwd`（密码散列存于 `/etc/passwd`，未引入 shadow password 分野）、4.3BSD 网络栈远程漏洞面（sendmail DEBUG、fingerd 缓冲区溢出、`~/.rhosts` 信任链）；与 FreeBSD 1.0 同期 fork 自 386BSD 0.1 的安全基线高度重合，二者共享 4.3BSD-Reno 网络栈远程漏洞面这一共同安全起点；NetBSD 0.8 公告中明确记载加密组件 **crypt(3)** 因法律原因需从美国境内站点单独获取，反映 1990 年代初美国密码出口管制对 BSD 安全基线的影响
  
**史料**：NetBSD 0.8 Installation Notes（完整列出支持硬件、分发集合、系统需求，明确提及加密组件法律限制）、NetBSD 0.8 源码树、4.3BSD-Reno release notes、CSRG 邮件列表存档 ［A］
  
**史观**：信息技术：FTP 分发与密码出口管制是 1990 年代初开源项目安全机制分发的物质约束；法律结构：美国密码出口管制法律直接塑造 BSD 安全基线的分发模式
  
**辨析**：NetBSD 0.8/0.9 与 FreeBSD 1.0 的安全基线高度重合，二者均继承 386BSD 0.1 的 4.3BSD-Reno 安全机制，差异主要体现在工程方向（NetBSD 多平台优先 vs FreeBSD i386 性能优先）而非安全基线；4.3BSD 网络栈远程漏洞面在 1993-1994 年仍是 NetBSD 与 FreeBSD 共同面临的活跃威胁，Morris 蠕虫（1988）的攻击向量在 NetBSD 0.8/0.9 中仍潜在存在，直至 NetBSD 1.0 rebase 至 4.4BSD-Lite 后方部分缓解

## 68.14.3 NetBSD 1.0 rebase 至 4.4BSD-Lite 后的 securelevel 引入与 386BSD 安全基线地位被取代

  **要点**：NetBSD 1.0（1994 年 10 月 26 日 release tag，1994 年 11 月 8 日 Demetriou 公告）正式 rebase 至 4.4BSD-Lite，公告明确记载"based on 4.4BSD Lite and Berkeley Networking Release 2 sources"，386BSD 作为 NetBSD 直接安全基线的地位被 4.4BSD-Lite 取代；4.4BSD-Lite 引入 securelevel 内核安全等级机制（level 0 不安全模式、level 1 安全模式禁止 `/dev/mem` 访问与原始磁盘写入并强制 **chflags(2)** 不可变标志、level 2 高安全模式进一步限制系统时间修改），securelevel 一旦提升至非零级即不可降级须重启方能恢复至 level 0；securelevel 通过 4.4BSD-Lite 直接被 NetBSD 1.0 继承，是 NetBSD 后世安全机制（如 `kern.securelevel` sysctl）的直接祖先；386BSD 0.1 时期未引入的 securelevel、chroot 安全沙箱用途、shadow password 等机制须通过 NetBSD 1.0 rebase 至 4.4BSD-Lite 方能进入 NetBSD 主线
  
**史料**：Demetriou 1.0 原始公告（8 Nov 1994，明确记载"based on 4.4BSD Lite and Berkeley Networking Release 2 sources"）、NetBSD 1.0 Release Notes、4.4BSD SMM: 16《On the Security of UNIX》securelevel 描述、4.4BSD PSD: 5《Berkeley Software Architecture Manual (4.4 Edition)》securelevel 相关系统调用接口、McKusick et al. 1996 设计与实现一书第 9 章；netbsd.duckdb 数据库证据——<christos@NetBSD.org> 在 netbsd-src 首次 commit 为 1994-10-26T11:58:24Z，与 NetBSD 1.0 release tag 日期完全一致，间接印证 NetBSD 1.0 发布日期；NetBSD 1.0 release tag 无法经 netbsd.duckdb 直接验证（netbsd-src GitHub 镜像无 tag 信息），发布日期须以 NetBSD 官方档案为准 ［A］
  
**史观**：总纲第 11 条——分离与聚合：NetBSD 1.0 rebase 至 4.4BSD-Lite 是从 386BSD 安全基线分离后聚合至 4.4BSD-Lite 新基线；总纲第 25 条——终结中的延续：386BSD 作为 NetBSD 直接安全基线的地位终结，但其通过 386BSD 0.1 → NetBSD 0.8/0.9 路径传递的安全基因在 NetBSD 主线延续
  
**辨析**：NetBSD 1.0（1994.10.26）发布早于 FreeBSD 2.0（1994.11.22）约一个月，两项目同期 rebase 至 4.4BSD-Lite，386BSD 作为直接安全基线的地位在 1994 年下半年被 4.4BSD-Lite 同时取代；securelevel 在 4.4BSD-Lite 中为概念雏形，其完整机制在后世 BSD（如 FreeBSD 的 `kern.securelevel` sysctl、OpenBSD 的 **securelevel(7)**）中持续演化；4.4BSD-Lite 引入 securelevel 后，386BSD 时期遗留的 4.3BSD 网络栈远程漏洞面（sendmail DEBUG、fingerd 缓冲区溢出）在 4.4BSD-Lite 中部分修复但未完全消除，仍需 NetBSD 后续版本持续修补
