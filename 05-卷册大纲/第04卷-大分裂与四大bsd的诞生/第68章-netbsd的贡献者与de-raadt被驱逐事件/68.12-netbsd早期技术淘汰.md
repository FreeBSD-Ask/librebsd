# 68.12 NetBSD 早期技术淘汰——UVM 取代 4.4BSD VM 与 pkgsrc 取代 ports

## 68.12.1 UVM 取代 4.4BSD Mach-based 虚拟内存系统

  **要点**：NetBSD 1.4（1999 年 5 月 12 日正式发布）正式引入 UVM（Universal Virtual Memory）虚拟内存系统，取代 4.4BSD 继承自 Mach 的旧 VM 系统；UVM 由 Charles D. Cranor 与 Gurudatta M. Parulkar 在圣路易斯华盛顿大学（Washington University in St. Louis）设计实现，首篇学术论文于 1999 年 USENIX 年度技术会议（USENIX ATC 1999）发表；UVM 重新设计 page daemon、引入 amap（anonymous memory map）抽象、优化 mmap 性能、改进页面替换算法、提供面向 SMP 的并发支持；UVM 取代旧 VM 的原因是 4.4BSD Mach-based VM 设计陈旧，难以适应 1990 年代后期大内存、SMP、mmap 密集型应用的需求；UVM 在 NetBSD 中延续至今，OpenBSD 亦移植 UVM 取代旧 VM；FreeBSD 5.0（2003 年 1 月）则选择完全重写的全新 VM 系统，未采用 UVM
  
**史料**：Cranor & Parulkar 1999 USENIX ATC“The UVM Virtual Memory Management System”论文、Cranor 1999 IEEE TSE“The UVM Virtual Memory System”论文、NetBSD 1.4 Release Notes (1999.5) UVM 章节、Cranor 个人 UVM 页面（华盛顿大学存档） ［A］
  
**史观**：总纲第 6 条——和解优于斗争：NetBSD/OpenBSD 选择 UVM 路径、FreeBSD 选择自行重写路径，是不同方案并行求和解的分化而非零和冲突；总纲第 17 条——证明世界先于解释和改造世界：UVM 的 amap 抽象先以实现证明可行，再形成对匿名内存管理的解释
  
**辨析**：UVM 是否真正“取代”旧 VM 在不同版本中时间不一——NetBSD 1.4（1999 年 5 月）默认启用，但部分平台仍保留旧 VM 直至 1.5；UVM 与 FreeBSD 5.0 全新 VM 的性能对比在公开基准中数据有限；OpenBSD 移植 UVM 的具体版本需考据
  
**文献**：Cranor, C. D. & Parulkar, G. M. 1999 USENIX ATC“The UVM Virtual Memory Management System”；Cranor, C. D. 1999 IEEE TSE“The UVM Virtual Memory System”Vol. 45 No. 3；NetBSD 1.4 Release Notes (1999.5) ［B］

## 68.12.2 pkgsrc 取代早期 ports 系统演化

  **要点**：NetBSD 早期 ports 系统（NetBSD 1.0 起的“packages collection”）在 1997-1998 年由 Alistair G. Crooks（阿利斯泰尔·克鲁克斯） 与 Hubert Feyrer（胡贝特·费雷尔） 等正式重写并更名为 pkgsrc；pkgsrc 引入 bsd.pkg.mk 框架、依赖关系图、多平台兼容性（不仅限于 NetBSD，亦可在 Linux、Solaris、IRIX、Darwin 等上运行）；pkgsrc 设计灵感部分来自 FreeBSD Ports（Jordan Hubbard 1994 年设计），但目标定位为跨平台软件包管理；pkgsrc 至今仍由 NetBSD 项目维护，并成为 Joyent SmartOS、DragonFly BSD 等系统的可选软件包管理器
  
**史料**：Crooks & Feyrer 1998 pkgsrc 设计文档、NetBSD 1.3.2 Release Notes (1998.5) pkgsrc 章节、Hubert Feyrer“pkgsrc: The NetBSD Packages Collection”论文、pkgsrc 源代码历史 commit 日志 ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律：pkgsrc 从 NetBSD ports 分离后聚合为跨平台软件包管理器；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说：将 pkgsrc 的跨平台特性叙述为“可移植理想”的体现，是基于特定哲学设定的叙事化处理
  
**辨析**：pkgsrc 与 FreeBSD Ports 的关系需辨析——pkgsrc 借鉴 FreeBSD Ports 的 bsd.port.mk 框架但目标定位不同；pkgsrc 是否真正“取代”早期 ports 需考据——早期 ports 在 NetBSD 1.3 之前已存在但功能简化
  
**文献**：Crooks, A. G. & Feyrer, H. 1998“pkgsrc: The NetBSD Packages Collection”；NetBSD 1.3.2 Release Notes (1998.5)；Feyrer, H. “pkgsrc: A Guide to the NetBSD Packages Collection”［史料缺口：部分原始档案未公开数字化或须付费访问，待原始档案公开后方可补充确证］

## 68.12.3 早期平台退役的开端

  **要点**：NetBSD 早期支持的诸多平台在 1990 年代末至 2000 年代开始退役——包括 amiga、atari、hp300、mvme68k、sun3 等 m68k 平台在 NetBSD 1.5（2000 年 12 月 6 日）后逐步降级为“orphaned”状态；这些平台退役反映 1990 年代后期硬件格局的变化——RISC（SPARC、MIPS、Alpha）与 x86 成为 UNIX 主流，m68k 平台随 Apple 转向 PowerPC 而边缘化；NetBSD 的“移植到一切平台”理想在实践上受硬件维护成本制约
  
**史料**：NetBSD 1.5/1.6 Release Notes 平台退役章节、NetBSD Port 页面历史快照（archive.org）、NetBSD 邮件列表 port-maintainers 讨论 ［A］
  
**史观**：总纲第 7 条——理论必须自反：“移植到一切平台”的口号本身也须接受硬件格局的反向检验，平台退役正是理论自反的体现；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说：平台“orphaned”与“退役”的措辞选择本身已预设了某种叙事立场
  
**辨析**：NetBSD“of course it runs NetBSD”口号在平台退役语境下需辨析——并非所有平台都能永久运行；早期平台退役的具体时间在史料中措辞不一，需对照 Release Notes 与 port-maintainers 邮件
  
**文献**：NetBSD 1.5 Release Notes (2000.12)；NetBSD 1.6 Release Notes (2002.9)；NetBSD Port Pages Archive［史料缺口：部分原始档案未公开数字化或须付费访问，待原始档案公开后方可补充确证］

## 68.12.4 NetBSD 早期淘汰史的辨析

  **要点**：NetBSD 早期技术淘汰具有“研究性引入与实践性退役并行”的特征——UVM 作为研究性引入取代旧 VM，而早期平台作为实践性退役退出支持；这一双重特征反映 NetBSD 项目“研究优先”与“维护负担”的张力；需警惕将 NetBSD 叙事为“小而美”的回溯性建构——彼时 NetBSD 面临严重的维护资源不足，平台退役部分源于社区贡献者流失
  
**史料**：NetBSD Foundation 1999-2002 年度报告、NetBSD Core Team 1999-2002 内部备忘录 ［A］
  
**史观**：总纲第 25 条——逻辑是形式主义而非世界本身的结构：“研究性引入与实践性退役并行”的分析框架是叙事逻辑的构造，并非硬件演化世界本身的结构；总纲第 9 条——经验优先：NetBSD 平台取舍以维护实践的经验证据为准，无实证支撑的保留判断难以成立
  
**辨析**：UVM 引入是否真正“成功”需长期考据——UVM 至今仍是 NetBSD 的 VM 系统，但其设计是否适应 2020 年代的大内存多核场景存在争议；平台退役是否为“主动选择”还是“被动接受”需考据
  
**文献**：NetBSD Foundation Annual Reports 1999-2002；NetBSD Core Team Internal Memos 1999-2002 ［A］
