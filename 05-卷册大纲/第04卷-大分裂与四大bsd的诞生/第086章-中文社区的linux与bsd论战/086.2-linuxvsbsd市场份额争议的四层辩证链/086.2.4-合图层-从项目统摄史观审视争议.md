# 086.2.4 合图层——从项目统摄史观审视争议

  **要点**：合图层综合批评方与反批评方，指出 BSD 与 Linux 的争议本质是 “广度胜出”（Linux）与 “深度保留”（BSD）的差异化路径之争，非 “胜负” 之争；合图层承认争议的不可调和性——批评方以市场份额为标准，反批评方以技术影响力与长期生态为标准，两套标准基于不同评价体系，不得以单一标准衡量；合图层指出和解路径——承认 BSD 与 Linux 各有其主体性，BSD 在 CDN/路由器/嵌入式领域的深耕与 Linux 在桌面/企业/移动领域的广度胜出非对立而是互补，二者共同构成开源生态的多样性
  
**史料**：项目史观总纲第 6 条（和解优于斗争）、第 8 条（本体论上各方平等）、第 19 条（解释学循环是历史认识的根本条件）；Linux 与 BSD 三十年发展对比研究；bsd_commits.duckdb 贡献者结构数据 ［A］
  
**史观**：总纲第 6 条——和解优于斗争：合图层以 “和解” 姿态审视争议，承认 BSD 与 Linux 各有其主体性，争议的不可调和性源于前理解差异；总纲第 8 条——本体论上各方平等：BSD 与 Linux 在本体论上地位相等，差异仅是一刻状态的不同；总纲第 19 条——解释学循环是历史认识的根本条件：批评方与反批评方的前理解差异使分歧不可避免，合图非 “消除分歧” 而是 “在分歧中呈现各主体性”
  
**辨析**：合图的解释力经具体历史场景评估——**1991-2026 年** BSD 与 Linux 三十年发展路径显示，二者在不同领域各有优势（BSD 在 CDN/路由器/嵌入式，Linux 在桌面/企业/移动），非 “胜负” 关系而是 “差异化路径”；合图层承认争议的不可调和性——批评方与反批评方的评价标准（市场份额 vs 技术影响力）基于不同评价体系，不得以单一标准衡量；合图层指出和解路径——承认 BSD 与 Linux 各有其主体性，二者共同构成开源生态的多样性；【0 信任原则·合图须以考据为前提】合图层不追求 “消除分歧”，而是承认前理解的差异使分歧不可避免，合图须以考据为前提，不得以 “合图” 为名回避立场；【0 信任原则·和解非折中】和解路径非 “双方都有道理” 的折中主义，而是基于一手档案与第三方数据的多因素叠加分析
  
**文献**：项目史观总纲第 6、8、19 条；Linux 与 BSD 三十年发展对比研究 ［A］
