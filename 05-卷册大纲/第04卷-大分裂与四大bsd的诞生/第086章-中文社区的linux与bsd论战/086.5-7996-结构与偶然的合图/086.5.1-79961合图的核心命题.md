# 086.5.1 79.9.6.1 合图的核心命题

  **要点**：合图层综合结构因素与偶然事件，指出二者非对立而是互补——结构因素（GPL、BDFL、RedHat 模式）提供长期趋势，偶然事件（Linus 个人偏好、USL 诉讼时机、RedHat 1995 年决策）决定具体转折点；合图不追求“唯一正确归因”，而是在具体历史场景下评估多重因素的叠加效应
  
**史料**：Linux 与 BSD 三十年发展关键节点时间线；USL v. BSDi 诉讼档案；RedHat IPO 招股说明书；bsd_commits.duckdb 贡献者结构数据 ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配：合图层审视“Linux 取代 BSD 是进步”的叙事，指出所谓“进步”是权力再分配的话语建构，技术演进非从低级到高级的线性进步，Linux 在桌面与企业市场的“胜出”与 BSD 在 CDN/路由器/嵌入式领域的“深耕”非同一维度；总纲第 5 条——没有必然性，只有偶然性：合图层承认结构因素的存在但不将其必然化，结构因素本身亦是偶然条件下的产物——GPL v2 1991 释出是偶然，Linus 选择 GPL 是偶然，RedHat 1995 年商业模式决策是偶然；总纲第 11 条——商品是形式主义：合图层审视 Linux 端将 BSD 技术经“形式主义化”封装为“开源软件商品”的过程，RedHat 订阅模式、IBM 背书、风险资本偏好均是商品形式主义的体现，定量指标的“参考价值”不等于“唯一评判标准”；总纲第 15 条——文化即形式主义：合图层审视 Linux 端将 BSD“ports 文化”“rc.d 文化”“man 文化”经形式主义化遮蔽与重构的过程，文化传统在更名与重构中被遮蔽；总纲第 19 条——解释学循环是历史认识的根本条件：合图层承认 BSD 阵营与 Linux 阵营的前理解差异使分歧不可避免，合图非“消除分歧”而是“在分歧中呈现各主体性”；总纲第 21 条——革命与改革是历史方法论的分歧：Linux 靠革命（systemd 重构、Docker 重命名、eBPF 扩展），BSD 靠改革（rc.d 渐进演化、jail 渐进扩展、BPF 渐进扩展），革命与改革各有代价；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说：合图层审视“Linux 必胜”“GPL 必然取代 BSD”等叙事的历史小说化，史家以为自己在书写历史，但历史人物可能正在藉着史家书写他们自己的故事，合图本身亦是一次循环，与古代史中“史家重写”无本质区别
  
**辨析**：合图的解释力经具体历史场景评估——1991-1994 年窗口期内，结构因素（BSD 法律不确定性、Linux GPL 法律明确性）与偶然事件（USL 诉讼时机、Linus 个人魅力）叠加形成“相对优势扩大”而非“绝对无竞争”；1995-2000 年窗口期内，结构因素（RedHat 商业模式、IBM 背书）与偶然事件（VA Linux IPO 当日涨幅 698%、风险资本集中投入）叠加形成“商业生态分化”；2000-2026 年窗口期内，结构因素（Linux Foundation 多项目治理、企业贡献占比）与偶然事件（Android 2008 年崛起、IBM 2019 年收购 RedHat）叠加形成“广度胜出”；三个窗口期的合图均显示结构因素与偶然事件非对立而是互补，单一归因（许可证决定论、商业模式决定论、治理决定论）均不足以解释三十年命运分化
  
**文献**：Linux 与 BSD 三十年发展对比研究；USL v. BSDi 诉讼档案；bsd_commits.duckdb 数据分析报告 ［A］

### 79.9.6.2 合图的辨析边界

  **要点**：合图的辨析边界在于——合图不追求“消除分歧”，而是承认 BSD 阵营与 Linux 阵营的前理解差异使分歧不可避免（解释学循环）；合图须区分“有史料支撑的合图”（基于一手档案与第三方数据的多因素叠加分析）与“无史料支撑的折中”（为回避立场而强行调和的折中主义），前者须保留，后者须剔除
  
**史料**：解释学循环理论文献；Linux 与 BSD 阵营前理解差异记录；多因素叠加分析的一手史料 ［A］
  
**史观**：总纲第 19 条——解释学循环是历史认识的根本条件：合图层承认前理解的差异使 BSD 与 Linux 两端的分歧不可避免，合图不是“消除分歧”而是“在分歧中呈现各主体性”；0 信任原则（方法论，不设总纲条号）：合图须考据——有史料支撑的合图（基于 USL 诉讼档案、RedHat IPO 招股说明书、bsd_commits.duckdb 等一手数据的多因素叠加分析）与无史料支撑的折中（为回避立场而强行调和的折中主义）须明确区分
  
**辨析**：合图的辨析边界经“多因素叠加分析”与“折中主义”的区分考据——多因素叠加分析须逐项标注每个因素的一手史料来源（如 GPL 聚拢效应经 Linux 内核贡献统计与 GPL v2 原文交叉验证、USL 诉讼窗口期经诉讼档案与 Linux 0.96-1.0 发布时间线交叉验证、RedHat 商业模式经 IPO 招股说明书与 IBM 2000 年投资公告交叉验证），折中主义则以“双方都有道理”回避具体考据；合图须以考据为前提，不得以“合图”为名回避立场
