## 73.2.5 OpenBSD 从 NetBSD 分叉的批评——对 Theo de Raadt 被逐出 NetBSD 核心团队与 OpenBSD 分叉造成 BSD 社区分裂的批评（批评层）

  **要点**：对 1994 年 12 月 Theo de Raadt 被撤销 NetBSD commit bit 与 1995 年 10 月 18 日 OpenBSD 从 NetBSD 1.0 分叉事件的批评集中于三点——其一，NetBSD 核心团队撤销 de Raadt commit bit 的程序透明度不足，未公开具体的冲突事实与决策记录，仅以“难以合作”为由即剥夺贡献者权限，违反开源社区治理的程序正义；其二，分叉造成 BSD 阵营资源分散，OpenBSD 与 NetBSD 在可移植性、驱动支持、用户空间工具等领域的重复劳动削弱 BSD 阵营整体竞争力，加速 Linux 阵营的市场扩张；其三，分叉的人事成本长期未被消化——de Raadt 对 Hannum、Demetriou 的公开敌意延续数十年，BSD 三项目间形成持久隔阂。netbsd.duckdb 数据库证据显示：deraadt 在 netbsd-src 末次 commit 为 1994-12-17T23:12:41Z（commit_hash `699d2a37b0e3c0c6ff29ea0d407c3feeba5642b4`），与 1994 年 12 月被撤销 commit bit 事件时序一致；deraadt 在 openbsd-src 首条 commit 为 1995-10-18T08:37:01Z（commit_hash `df930be708d50e9715f173caa26ffe1b7599b157`，commit message 为“initial import of NetBSD tree”），二者间 10 个月的间隔反映分叉前的准备期。批评三层论点如下：

| 论点 | 核心主张 | 证据 |
| -- | ------ | -- |
| 程序正义论 | 撤销 commit bit 缺乏公开决策记录与申诉机制 | NetBSD 官方未发布正式声明 |
| 资源分散论 | 分叉导致 BSD 阵营重复劳动 | OpenBSD 与 NetBSD 在可移植性领域并行维护 |
| 人事成本论 | 隔阂延续数十年阻碍跨项目协作 | de Raadt 对 Hannum、Demetriou 的公开敌意 |

**史料**：NetBSD core team 历年成员页（<https://www.netbsd.org/people/core.html>，de Raadt 列为 former member）、OpenBSD 官方 5.8 release song“20 years ago today”（<https://www.openbsd.org/lyrics.html>，确认 1995-10-18 CVS import）、netbsd.duckdb netbsd-src 与 openbsd-src 仓库 deraadt 贡献者记录；de Raadt 关于被逐出 NetBSD 的公开声明、NetBSD 核心团队（Charles Hannum、Chris Demetriou）相关邮件列表存档 ［A］

**史观**：0 信任原则：分叉史料需考据验证，NetBSD 与 OpenBSD 双方叙事均不免检；没有必然性，只有偶然性：分叉是具体人事冲突的偶然产物，非结构性必然

**辨析**：考据过程留痕——【查证来源】NetBSD 官方 core.html 经 <https://www.netbsd.org/people/core.html> 一手核验，页面将 de Raadt 列为“Theo de Raadt”并标注为 former member，但未说明离队原因与时点，撤销 commit bit 的具体程序与决策记录在 NetBSD 官方文档中无公开存档；OpenBSD 官方 lyrics.html 经 <https://www.openbsd.org/lyrics.html> 一手核验，OpenBSD 5.8（2015 年）歌曲“20 years ago today”歌词明确提及“twenty years ago today”与“CVS import”，与 1995-10-18 首次 CVS import 时点一致；openbsd.duckdb openbsd-src 仓库首条 commit（`df930be708d50e9715f173caa26ffe1b7599b157`，deraadt, 1995-10-18T08:37:01Z, “initial import of NetBSD tree”）与 netbsd-src 仓库 deraadt 末次 commit（`699d2a37b0e3c0c6ff29ea0d407c3feeba5642b4`，1994-12-17T23:12:41Z）经数据库 commit_hash 表核验；【交叉验证方法】de Raadt 关于被逐出 NetBSD 的自述（一手当事人叙事）与 NetBSD 官方 core.html 的“former member”标注（一手官方记录）与 netbsd.duckdb commit 时间戳（一手技术记录）三方互证——de Raadt 自述称 1994 年 12 月被撤销 commit bit，netbsd.duckdb 显示其 netbsd-src 末次 commit 为 1994-12-17，时序一致；NetBSD 官方未公开撤销原因，“难以合作”等具体表述多见于 de Raadt 单方自述与 BSD 社区二手转述，须谨慎评估其自利偏差；【存疑判定依据】NetBSD 核心团队撤销 de Raadt commit bit 的具体程序记录（会议纪要、投票记录、正式声明）在 NetBSD 官方文档中未公开存档，撤销原因的详细叙述主要依赖 de Raadt 单方自述与 BSD 社区二手转述，史家须明确标注此为存疑——程序正义批评的力度可能因程序记录缺失而被放大，亦可能因 NetBSD 一方沉默而被歪曲；【多源交叉验证不可靠性规则】多个 BSD 社区二手来源在“de Raadt 因人际冲突被逐出”叙述上一致，但这一一致性可能源于对同一批 de Raadt 自述的反复转引而非独立验证；0 信任原则提示：de Raadt 作为当事人其自述须警惕自我美化与责任转嫁，NetBSD 一方的沉默亦不等于默认，史家须呈现双方叙事的张力而非采信一方

**文献**：NetBSD core.html [EB/OL]. <https://www.netbsd.org/people/core.html>；OpenBSD lyrics.html [EB/OL]. <https://www.openbsd.org/lyrics.html>；netbsd.duckdb netbsd-src deraadt 末次 commit `699d2a37b0e3c0c6ff29ea0d407c3feeba5642b4`（1994-12-17T23:12:41Z）；openbsd.duckdb openbsd-src 首条 commit `df930be708d50e9715f173caa26ffe1b7599b157`（deraadt, 1995-10-18T08:37:01Z, “initial import of NetBSD tree”）；de Raadt 关于被逐出 NetBSD 的公开声明 ［A］

## 73.2.6 对分叉批评的反批评——NetBSD 阵营与部分 BSD 史家的辩护（反批评层）

  **要点**：对分叉批评的反批评集中于三点——其一，“程序正义”论证忽视了 1994 年 NetBSD 核心团队治理结构的初创性质，彼时开源社区治理规范尚未成型，以 2020 年代的标准追溯评判 1994 年的程序合规性属时代错置；其二，“资源分散”论证忽视了分叉的创造性效应——OpenBSD 在安全审计、密码学清理、privilege separation 等领域的贡献是 NetBSD 治理结构下难以产生的，分叉后的差异化定位反而扩大了 BSD 阵营的整体影响力；其三，“人事成本”论证将个人敌意等同于社区隔阂，但 BSD 三项目的隔阂有更深的许可证、目标受众与硬件支持差异根源，de Raadt 个人敌意只是表征而非根因。反批评三层论点如下：

| 论点 | 核心主张 | 证据 |
| -- | ------ | -- |
| 时代错置论 | 1994 年开源治理规范未成型 | 对照同期 Linux 内核治理结构 |
| 创造性分叉论 | OpenBSD 安全贡献是分叉产物 | OpenBSD security.html 审计起始 1996 年夏 |
| 表征非根因论 | 个人敌意非社区隔阂根因 | BSD 三项目目标定位差异 |

**史料**：NetBSD 阵营关于分叉的公开声明、BSD 治理结构演变研究、同期（1993-1995）开源社区治理规范考据、OpenBSD security.html（<https://www.openbsd.org/security.html>，“We have been auditing since the summer of 1996”经一手核验）、BSD 三项目目标定位对照文档 ［A］

**史观**：本体论上各方平等：分叉与不分叉在本体论上地位相等，差异仅是一刻状态的不同；分离聚合是永恒规律：分叉是 BSD 阵营分离聚合循环的常态

**辨析**：考据过程留痕——【查证来源】OpenBSD 官方 security.html 经 <https://www.openbsd.org/security.html> 一手核验，页面明确记载“We have been auditing since the summer of 1996”与"Our security auditing team typically has between six and twelve members"，验证 OpenBSD 安全审计文化的起始时点与团队规模；1993-1995 年开源社区治理规范考据须对照 FSF、Linux 内核、Apache 等同期项目的治理结构文档，但 bsd_commits.duckdb 不含此类治理结构数据，须依赖外部一手史料；【交叉验证方法】“时代错置”论证须对照 1993-1995 年 FSF、Linux 内核、Apache 等同期开源项目的治理结构演变——若同期项目亦缺乏正式撤销贡献者权限的程序，则“程序正义”批评的力度应相应减弱；“创造性分叉”论证须对照 OpenBSD security.html 的审计起始时间与 NetBSD 同期安全审计记录，验证 OpenBSD 安全文化的独特性是否确为分叉后产物；“表征非根因”论证须对照 BSD 三项目的 goals.html 与 NetBSD goals 文档，验证目标定位差异是否足以解释社区隔阂；【存疑判定依据】“1994 年开源治理规范未成型”的判断须以同期多项目治理结构文档为据，不可凭模型记忆推断；【多源交叉验证不可靠性规则】NetBSD 阵营的反批评在多个 BSD 史家叙事中一致，但这一一致性可能源于对同一批治理结构演变研究的反复转引；0 信任原则提示：反批评的“创造性分叉”论证具有事后回溯的性质——分叉的实际后果不可用于证立分叉的正当性，否则犯后果主义谬误；“时代错置”论证本身亦须警惕——1994 年已有 FSF 与 Linux 内核的成熟治理实践，“规范未成型”的边界须具体考据而非笼统断言

**文献**：NetBSD 阵营公开声明；OpenBSD security.html [EB/OL]. <https://www.openbsd.org/security.html>；BSD 治理结构演变研究；同期开源社区治理规范考据 ［A］

## 73.2.7 对反批评的再回应——分叉批评阵营的二次反驳（再回应层）

  **要点**：对反批评的再回应集中于三点——其一，“时代错置”论证混淆了“程序规范缺失”与“程序正义不存在”——即使 1994 年开源社区治理规范未成型，公开说明撤销贡献者权限的具体理由仍是基本的程序正义要求，NetBSD 核心团队的沉默不因时代差异而正当化；其二，“创造性分叉”论证的后果主义谬误已遭反批评层自身警示——分叉的实际安全贡献不可用于证立分叉前的人事决策正当性，若以结果论过程则任何人事冲突都可被事后合理化；其三，“表征非根因”论证忽视了 de Raadt 个人敌意对社区文化的塑造作用——OpenBSD 邮件列表中“NetBSD 是笑话”的话语非但不是表征，反而是 OpenBSD 社区身份认同的建构性要素，将个人敌意简化为表征是剥离文化脉络的还原论。再回应三层论点如下：

| 论点 | 反驳对象 | 核心反驳 |
| -- | ------ | ------ |
| 程序正义恒定论 | 时代错置论 | 公开说明撤销理由是跨时代基本要求 |
| 后果主义谬误论 | 创造性分叉论 | 结果不能证立过程正当性 |
| 身份建构论 | 表征非根因论 | 个人敌意是 OpenBSD 身份认同建构要素 |

**史料**：OpenBSD 邮件列表历年存档中关于 NetBSD 的言论、程序正义哲学文献（斯坦福哲学百科“Procedural Justice”条目）、BSD 社区身份认同研究、OpenBSD goals.html（<https://www.openbsd.org/goals.html>，“Focus on being developer-oriented in all senses”经一手核验） ［A］

## 73.2.9 分叉争议的项目统摄史观审视——从总纲第 13、19、21 条切入

  **要点**：分叉争议的项目统摄史观审视从总纲第 13、19、21 条切入——其一，总纲第 13 条“法律与道德是利益分配”揭示分叉的“人际冲突”叙事实质是利益分配问题：de Raadt 被撤销 commit bit 表面是“难以合作”的道德判断，实质是 NetBSD 核心团队内部关于项目方向、贡献者权限、决策权分配的利益再分配，“道德问题本质上是利益问题”——将分叉简化为“人际冲突”遮蔽了 NetBSD 核心团队内部权力结构的实际运作；其二，总纲第 19 条“解释学循环是历史认识的根本条件”揭示分叉史料的解释学循环：de Raadt 自述与 NetBSD 沉默构成不对称的史料分布，“权力与知识在历史书写中共谋”——NetBSD 核心团队的沉默使分叉叙事主要由 de Raadt 单方建构，史家须警惕这一史料不对称如何塑造了后人对分叉事件的前理解；其三，总纲第 21 条“革命与改革是历史方法论的分歧”将 OpenBSD 分叉定位为“改革路径内的二次改革”——OpenBSD 非如 Linux 般以革命姿态对抗 UNIX 传统，而是从 NetBSD 的改革路径中再次分离，“破山中贼易，破心中贼难”——OpenBSD 的安全审计文化是对 BSD 心中贼（代码隐患）的持续破除，而 NetBSD 核心团队的人事决策则是对山中贼（治理冲突）的应对，二者对应改革的不同维度。三条总纲的交叉审视揭示：分叉争议的哲学维度不是单一总纲所能穷尽，须以总纲第 13（利益分配）、第 19（解释学循环）、第 21（革命与改革）三条共同切入方能呈现其完整张力
  
**史料**：项目史观总纲第 25 章总纲第 13、19、21 条原文（原材料/哲学/项目统摄史观/第 25 章.md）、NetBSD core.html、OpenBSD lyrics.html、OpenBSD security.html、OpenBSD goals.html、netbsd.duckdb netbsd-src 与 openbsd-src 仓库 deraadt 贡献者记录 ［A］
  
**史观**：法律与道德是利益分配：分叉的“人际冲突”叙事实质是利益分配问题；解释学循环是历史认识的根本条件：分叉史料的解释学循环与权力知识共谋；革命与改革是历史方法论的分歧：OpenBSD 分叉作为改革路径内的二次改革
  
**辨析**：考据过程留痕——【查证来源】项目史观总纲第 13、19、21 条原文经 原材料/哲学/项目统摄史观/第 25 章.md 一手核验——第 13 条原文为“法律与道德是利益分配。任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”，第 19 条原文为“解释学循环是历史认识的根本条件。前理解的差异使分歧不可避免。权力与知识在历史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使”，第 21 条原文为“革命与改革是历史方法论的分歧。Linux 靠革命，BSD 靠改革。改革的困难远高于革命。破山中贼易，破心中贼难”；NetBSD core.html、OpenBSD lyrics.html、OpenBSD security.html、OpenBSD goals.html 经前述一手核验；bsd_commits.duckdb deraadt 贡献者记录经数据库 commit_hash 表核验；【交叉验证方法】总纲第 13 条的“利益分配”视角须对照 NetBSD 核心团队 1994 年的实际决策结构——若核心团队内部存在关于项目方向或贡献者权限的实质性分歧，则“人际冲突”叙事的遮蔽效应得到验证；总纲第 19 条的“解释学循环”视角须对照 NetBSD 与 OpenBSD 双方关于分叉事件的史料产出量——NetBSD 一方的史料沉默与 OpenBSD 一方的史料丰富构成不对称，史家须呈现这一不对称如何塑造后人的前理解；总纲第 21 条的“改革路径内的二次改革”定位须对照 OpenBSD 安全审计文化（security.html 起始 1996 年夏）与 NetBSD 同期治理结构演变，验证 OpenBSD 的改革维度是否确为“破心中贼”（代码隐患）而非“破山中贼”（治理冲突）；【存疑判定依据】“分叉的实质是利益分配”判断须以 NetBSD 核心团队 1994 年决策记录为据，但该记录在 NetBSD 官方文档中未公开存档，“利益分配”视角的实证基础依赖于对 de Raadt 单方自述与 BSD 社区二手转述的逆向解读，史家须明确标注此为哲学审视层面的解释而非实证确证；“改革路径内的二次改革”定位是哲学层面的方法论判断而非历史事实判断，不可用于消解分叉的具体人事责任；【多源交叉验证不可靠性规则】项目统摄史观三条总纲的交叉审视在哲学层面自洽，但哲学自洽不等于历史实证，史家须区分哲学解释与历史事实；0 信任原则提示：项目统摄史观审视本身嵌入前理解（总纲第 13、19、21 条的理论预设），史家须自觉呈现这一前理解而非伪装中立——审视的目的不是以哲学框架裁决历史事件而是以哲学框架揭示历史事件的多重张力
