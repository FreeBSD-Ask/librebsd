# 073.0.1 要点

- FreeBSD 2.0（1994-11-22 网络公告，12 月 CD-ROM 分发）是首个完全基于 4.4BSD-Lite 的版本，消除 Net/2 争议代码的法律风险，同时引入 4.4BSD-Lite 的新安全机制——securelevel 内核安全等级机制（level 0 不安全模式、level 1 安全模式禁止 `/dev/mem` 访问与原始磁盘写入并强制 **chflags(2)**
- FreeBSD 1.x 版本周期内仅有的安全响应（2 条 isprint() 修复 commit）与回溯影响的栈溢出漏洞（FreeBSD-SA-96:20）共同反映 FreeBSD 1.x 安全基线的架构性缺陷——FreeBSD 1.0 基于 Net/2（4.3BSD 网络栈），未引入 securelevel 内核安全等级机制（securelevel 于 4.4BSD-Lite 引入，FreeBS
- 综合四层辩证，FreeBSD 从 386BSD patchkit fork 争议不能简化为 “窃取 vs 自救” 或 “合法 vs 不道德” 的二元结构——双方叙事都存在选择性记忆。Jolitz 夫妇 “全面窃取” 指控在事实层面部分不成立（用户流失是 386BSD 停滞的自然结果而非 “窃取”，代码继承基于 BSD 许可证合法），但在叙事层面有其合理性（FreeBSD 起源叙事确有简化，“被迫 fork” 叙事遮蔽了 patchkit 群体的主动选择与 Jolitz 夫妇的工程哲学）（据 073.3 节补全原截断）
- FreeBSD fork 既是“革命”又是“改革”——作为“革命”，FreeBSD 脱离 386BSD 单人维护模式，引入 Core Team 集体治理，是对 386BSD 治理结构的否定；作为“改革”，FreeBSD 继承 BSD 工程传统（基于 4.3BSD-Lite Net/2 + 386BSD 组件 + FSF 组件），延续 CSRG 的工程化路径，是对 BSD 工程传统的延续。项目史观总纲第 21 条“Linux 靠革命，BSD 靠改革”在此需要细化——FreeBSD fork 是“改革失败后的革命”：386BSD 单人维护模式在 1993 年初已无法维持社区贡献，patchkit 群体尝试通过“补丁包维护”改革 386BSD 维护模式但未获 Bill Jolitz 接受，fork 决策遂以“革命”方式重构治理结构（据 073.4 节补全原截断）
