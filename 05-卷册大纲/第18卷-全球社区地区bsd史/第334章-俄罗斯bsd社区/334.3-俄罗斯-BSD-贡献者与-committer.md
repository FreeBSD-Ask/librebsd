# 334.3 俄罗斯 BSD 贡献者与 committer

## 333.3.1 俄罗斯 committer 权限授予记录

  **要点**：俄罗斯地区 FreeBSD committer 的权限授予记录须经 FreeBSD 官方提交者名单与 SVN/Git 提交日志核查；俄罗斯 committer 数量在 2000-2010 年达到高峰，俄罗斯 committer 在 FreeBSD 主线中长期有重要贡献
  **史料**：FreeBSD 官方提交者名单（committers FreeBSD.org）、SVN/Git 提交日志、FreeBSD Foundation 年度报告 ［A］；openbsd.db 查询 L3.3.1 显示：22 仓库合计 committer_date 时区偏移分布中，俄罗斯本土时区 +03:00（莫斯科、圣彼得堡）74,576 commit / 3,977 贡献者，+04:00（萨马拉）2,402 / 362，+05:00（叶卡捷琳堡）6,822 / 56，+06:00（鄂木斯克）13 / 3，+07:00（克拉斯诺亚尔斯克）1,377 / 143，+10:00（海参崴）30,414 / 1,809，+11:00（堪察加）13,772 / 1,302，+12:00（彼得罗巴甫洛夫斯克）343 / 61（注：+08:00 与 +09:00 因同时覆盖中国、日本、韩国，不计入俄罗斯），俄罗斯独占时区合计约 129,696 commit / 7,713 贡献者；openbsd.db 查询 L3.3.2 显示：author_email TLD 分布中 .ru 域 7,454 commit / 424 unique emails（俄罗斯 ccTLD），在 ccTLD 中位列 .de/.uk/.fr/.cn 之后
  **史观**：总纲第 10 条——边缘者的贡献被中心叙事遮蔽，俄罗斯 committer 的实际贡献须从提交日志中重建；统计结论印证：统计结论 [L3.3.1] 时区分布俄罗斯独占时区合计约 129,696 commit / 7,713 贡献者（+03:00 莫斯科 74,576 / 3,977、+04:00 萨马拉 2,402 / 362、+05:00 叶卡捷琳堡 6,822 / 56、+06:00 鄂木斯克 13 / 3、+07:00 克拉斯诺亚尔斯克 1,377 / 143、+10:00 海参崴 30,414 / 1,809、+11:00 堪察加 13,772 / 1,302、+12:00 彼得罗巴甫洛夫斯克 343 / 61，不含与中国共用的 +08:00 与与日本韩国共用的 +09:00）与统计结论 [L3.3.2] TLD 分布 .ru 7,454 commit / 424 unique emails 在 ccTLD 中位列 .de/.uk/.fr/.cn 之后共同印证俄罗斯作为 BSD 社区东欧主要贡献区的量化基础，与 146.3.1 节所述“俄罗斯 committer 的实际贡献须从提交日志中重建”在数据层面互证——俄罗斯横跨 11 个时区使独占时区合计 commit 量显著，反映总纲第 10 条边缘者批评的量化印证；freebsd.db L3.3.1/L3.3.2 查询覆盖 freebsd-src 等 22 仓库 commit author_email 时区推断与 TLD 提取
  **辨析**：committer 的地域归属须经提交日志中的机构域名与时区信息推断，不能仅凭姓名判断；“18 个月不活跃自动退休” 条款的实际执行情况须考据；【0 信任原则·地理识别局限】author_email TLD 不等于实际地理位置，.ru 邮箱可由旅俄外籍人员使用，且俄罗斯横跨 11 个时区，部分时区与他国共用（+08:00 与中国共用、+09:00 与日本韩国共用），时区偏移不等于居住地，远程办公、VPN、移民等因素使时区—地理位置映射须慎重；【0 信任原则·committer_date 异常】L3.3.1 基于 committer_date 提取时区偏移，但 GitHub 镜像仓库的 committer_date 可能被重写为同步时间，分析时须改用 author_date 复核；【0 信任原则·author 字段可伪造】L3.3.2 基于 author_email 统计，.ru 域数据仅为下限，部分俄罗斯贡献者因 2022 年制裁后或为规避审查使用 .com 邮箱（如 Gmail）或境外邮箱提交，未计入 .ru 域
  **文献**：FreeBSD committers 列表；FreeBSD SVN/Git 仓库提交日志；FreeBSD Core Team 年度报告 ［A］；openbsd.db 查询 L3.3.1（committer_date 时区偏移分布前 30，22 仓库合计，30 行结果）、L3.3.2（author_email 域名 TLD 分布，22 仓库合计，16 行结果），见 `原材料/研究/bsd仓库分析/数据分析/深层信息挖掘.md` §L3.3.1、§L3.3.2

## 333.3.2 提交者权限的演变过程

  **要点**：俄罗斯 committer 权限演变分三阶段——1995-2005 年的零星授予期、2006-2015 年的稳定增长期、2016 年后的多元化期；2022 年制裁后俄罗斯 committer 权限是否受影响须经 FreeBSD Core Team 公开声明核查
  **史料**：FreeBSD 提交者历史名单、SVN/Git 提交日志统计、FreeBSD Core Team 公开声明 ［A］
  **史观**：总纲第 6 条——技术路线的分化与并行演化，俄罗斯 committer 增长节奏与社区发展节奏不同步
  **辨析**：三阶段划分须经提交日志量化分析核查；2022 年制裁对俄罗斯 committer 的影响须考据
  **文献**：FreeBSD SVN/Git 仓库；FreeBSD Core Team 选举档案与公开声明；freebsd-committers 邮件列表 ［A］

## 333.3.3 俄罗斯 committer 的贡献领域

  **要点**：俄罗斯 committer 因强数学传统在性能优化与安全方向贡献突出；俄罗斯 committer 在 FreeBSD 网络栈、文件系统、安全模块等领域有显著贡献
  **史料**：FreeBSD SVN/Git 提交日志、freebsd-hackers 邮件列表 ［A］
  **史观**：总纲第 10 条——边缘者的贡献被中心叙事遮蔽，俄罗斯 committer 的贡献领域须结合苏联数学教育传统分析
  **辨析**：贡献领域的统计分析须经提交日志量化核查；“强数学传统” 与贡献领域的关系须谨慎表述
