- 本期回顾 BSDCan 2019：开发者峰会含 bhyvecon 与 ZFS 引导代码等工作小组；会议含 Matt Ahrens 的 ZFS 快照、Michael W. Lucas 的 Jails 二十年、CHERI、MQTT 与 NVMe 等演讲。（BSD Now EP300，[209.7-624.64]，L1）
- Allan Jude 的演讲说明 FreeBSD 将把 ZFS 上游从 illumos 仓库切到 OpenZFS（原 Linux 仓库将更名并含各 OS 子目录），以实现单一上游。（BSD Now EP300，[805.52-945.64]，L1）
- 本期转述 iXsystems 博客对 ZFS 池的讲解：磁盘组成 VDEV、VDEV 组成池，镜像可任意加深，RAIDZ2/3 提供双、三重校验。（BSD Now EP300，[1600.86-1821.46]，L2）
- Terry Lambert 在 Quora 回答中把 FreeBSD 桌面市场份额近零归因于 1984 年 X Window System 的设计决策：为在廉价终端上运行而把显示服务与应用在最低图形原语层分离，使高层图形、widget 与窗口管理范式都留在主机侧，导致各应用外观随工具包而异、培训不可迁移，最终令 X 不适合作为统一桌面。（BSD Now EP253，[3063.24-3428.96]，L2）
- Terry Lambert 进一步指出该决策使商业软件供应商难以选择工具包并保证五到八年的持续销售，故而不愿为 X 平台开发；他认为 2012 年出现的 Wayland 正在重犯 X 在 1984 年犯下的同类错误。（BSD Now EP253，[3474.80-3579.92]，L2）
- Mark Johnston 的 BSDCan 2018 报告记录 FreeBSD 开发者峰会内容：Deb Goodkin 介绍基金会工作、在任 Core 团队汇报两年工作、发布工程团队介绍职责，并记录 OpenZFS 讨论中 ZFS on Linux 因改动频繁而使上游定义模糊、ZFS 改动被直接从 ZFS on Linux 移植入 FreeBSD。（BSD Now EP253，[1396.34-1698.40]，L1）
- 报告还记录 Colin Percival 讲解 FreeBSD 内核启动耗时构成及他所添加的测量基础设施，指出遗留的 PS/2 键盘兼容补丁是剩余启动延迟之一，因不确定是否仍需保留而难以移除。（BSD Now EP253，[1713.08-1839.10]，L1）
- FreeBSD 11.2 于 2018 年 6 月 27 日发布，带来 ZFS 压缩发送/接收与设备移除、面向 Intel 集成显卡的 DRM Next Kmod、OpenSSH 7.5p1 与 OpenSSL 1.0.2o 更新、LLVM 6 工具链，以及 Chelsio、Mellanox、Intel IXL 等大量网卡驱动更新。（BSD Now EP252，[63.24-246.32]，L2）
- Robert Watson 在 2008 年的帖子中指出 XNU 并非微内核，但其源码树含约 2100 万行显式标记为 BSD 的代码（主要来自 FreeBSD 并经大量修改）、约 1600 万行 Mach 代码，另有 IOKit 设备驱动与 libkern 等 Apple 自有代码，从而反驳 macOS 只是带 Apple 图形界面的 FreeBSD 这一说法。（BSD Now EP252，[3217.08-3380.68]，L1）
- Dave 的 BSDCan 2018 报告记录 Ben O'Rice 的 systemd 悲剧主题演讲与 Kirk McKusick 的 FreeBSD 治理演进演讲，后者回顾从 Jordan、Phk、Rod Grimes 时代到 Watson 时代的核心团队更替，并讨论 committer 年龄结构与社区新鲜血液。（BSD Now EP252，[2747.78-3215.62]，L1）
- Josh Berkus 自述其任 PostgreSQL 核心团队七人小组成员，该团队决定 PostgreSQL 的版本发布时机；Sun Microsystems 决定支持 PostgreSQL 项目并在 Solaris 平台销售支持服务后聘请其为 PostgreSQL 战略负责人。其此前履历包括 OpenOffice.org 项目负责人（为加入 PostgreSQL 核心团队而辞任）、Software in the Public Interest 董事会成员与 O'Reilly 开源大会委员会成员。（BSDTalk EP110，[49.23-95.41, 742.27-801.59]，L1）
- 关于项目接续史的当事人叙述：PostgreSQL 前身 Postgres 于 1986 年在伯克利加州大学启动，作为大学项目运行十年后校方 CS 系失去兴趣；此时校友与互联网社区中的职业使用者已将其投入生产，伯克利决定放手时，包括一位 FreeBSD 操作系统主要贡献者 Marc Fournier 在内的开发者群体将其改造为真正的开源项目并上线 CVS——1995 年开始、1996 年完成，社区遂以 1996 年 7 月 8 日为开源项目诞生日；十周年时在多伦多举办逾百人开发者峰会。 [存疑脚注] 转写作“Mark Fournier”，按 FreeBSD 核心团队与 PostgreSQL 基础设施史应为 Marc G. Fournier，名字拼写以转写存疑待核（BSDTalk EP110，[128.22-221.07]，L1）
- Berkus 的技术栈迁移史完整呈现了 1990 年代小企业咨询市场从专有软件向开源的转换动因：其自立门户服务小企业与非营利客户后，发现专有技术许可费与 MSDN 订阅侵蚀利润，而微软于 1997 至 1998 年停止补贴转向盈利，SQL Server 起步价从约 700 美元跃至 3000 美元；同时 SQL Server 加 COM+ 方案每两三周随机故障，迫使其每两周上门维护；MySQL 当时仍是共享软件且其 2.x 版不支持表连接，无法满足其 SQL 专家标准；转投 PostgreSQL 后，社区对其 SQL 合规性质疑的开放接纳与 MSDN 论坛的封禁文化形成鲜明对照，首周即融入项目——社区文化本身成为技术选型的决定因素。（BSDTalk EP110，[529.11-741.71]，L1）
- Berkus 对数据库生态的定位划分：PostgreSQL 居高端，面向需支撑海量连接、TB 级数据与长事务、以替换 Oracle、DB2、SQL Server 2005 为目标的场景；Derby 与 Sleepy Cat（即 Berkeley DB）一类居嵌入式端；MySQL 居中，规模与扩展性占优但不及 PostgreSQL，对用户数据库知识要求也更低。PostgreSQL 的比较优势包括 BSD 许可证允许与专有软硬件捆绑（其最流行的分发方式之一）、活跃企业用户转化为社区成员从而获得对软件未来的归属感与控制感、独立安全评级（Database Hackers Handbook 中高于 Oracle 与 DB2）、提交即持久的可靠性保证，以及源自对象关系设计的可编程数据库对象——PostGIS 借此成为全球第二大 GIS 数据库系统（仅次于 NavTeq），基因组学领域亦出现以专用数据类型扩展 PostgreSQL 的项目。 [存疑脚注] 基因组项目名转写作“BlastGres”，确切名称待核；NavTeq 为转写原貌，当作 Navteq（BSDTalk EP110，[802.59-1047.13, 884.21-927.73]，L1）
- 受访者入坑经历：1990 年代末在 Western Digital 的分包商处支持一套专跑 FreeBSD 的硬盘物流系统，除物理盘故障外从未出现问题，其设计被其评价为优雅；此后试用 Linux 因不满 Red Hat 包管理而 FreeBSD ports 从未让他出问题，遂固定使用 FreeBSD 至今。（BSDTalk EP10，[127.86-189.50]，L1）
- 部署概况：加州 Fullerton 学区推行一对一笔记本计划，每名学生配一台底层运行 Darwin 的 Apple iBook，FreeBSD 承担控制全部 iBook 的后台服务器角色；BSD 只作服务器用途、不部署桌面（避免 KDE 等员工培训成本），完全占据服务器机房与各站点计算机；加州教育经费长期紧张，主要靠捐赠设备，BSD 装在捐赠旧硬件上整合入网，形成有钱买 Apple、没钱装 FreeBSD 的弹性组合，两者互操作良好。（BSDTalk EP10，[190.32-261.62]，L1）
- 可管理性与灾备设计：技术部门仅四人，以 OpenLDAP 集中管理全部学生笔记本的权限与账户，且刻意保持 Apple GUI 工具可直接管理 Intel 硬件上的 LDAP，使日常管理无需专家在场；针对管理层被公交撞了网络怎么办的追问，受访者以 sysinstall（其 man 页自认不应再存在）开设安装培训课，并为每台机器编制三环活页夹（配置文件与已装包清单），保证文字资料足以重建系统。（BSDTalk EP10，[283.38-405.98]，L1）
- 运维可靠性与旧硬件性能：以无 GUI 的 cvsup 经 cron 定期更新，除非重大安全问题不强制升级；一台 FreeBSD 4.0 机器在仓库执行简单任务已连续运行数年而无需到场维护；跨版本升级不难，3.x 手册已不再推荐 buildworld 而有二进制升级建议，最坏情况重装并迁移配置文件即可。BSD 可跑低配硬件是其关键优势：一台 Pentium 3 为 1200 台笔记本提供名字服务并承担 7 个 VLAN 的 DHCP，处理器利用率从未低于四成仍稳定运转；FreeBSD 的 PowerPC 支持规模有限，NetBSD 对 PowerPC 的支持成熟得多，学区借此复活大量退役 PowerPC Mac 与 Intel 捐赠机并用。（BSDTalk EP10，[406.58-660.80]，L1）
- Apple 对比与安全管控：若资金充裕，前端设备仍会保持 FreeBSD，阵列存储会选 Apple 因其界面简单；Apple 整机溢价换来后端与笔记本皆不受病毒蠕虫侵扰，省下的运维开支转投学生教育软件。对学术环境是否对网络抱敌意的问题，受访者称学生总体守规矩，曾抓到安装包嗅探程序者，但 OpenLDAP 目录结构将 Apple 笔记本锁定为只能启动事先授权的应用，下载程序即使在其用户空间内也无法获得执行许可。全套服务均构建于 FreeBSD：对外 VPN（可携带分支办公室，用 Stunnel）、RADIUS 认证、Squid 加 SquidGuard、学生行为监控的 LDAP 认证、面向业务办公室的 Samba 文件共享与面向 Apple 客户端的 Netatalk。（BSDTalk EP10，[503.50-701.10]，L1）
- Langille 自述 2007 至 2008 年的际遇与现职：去年 BSDCan 后南下佛罗里达，旋因工作外包于六周后失去收入，返堪萨斯办妥工作许可后入职 Afilias——费城郊外 Horsham 的一家域名注册局服务商，负责 .org 等顶级域名的域名数据库，whois 信息与各域名的域名服务器列表皆自该库提取；其经手的全部顶级域名数据库均运行于 PostgreSQL。（BSDTalk EP144，[110.06-193.82]，L1）
- Slony-I 复制系统出自 Afilias 内部开发、后以开源释出，为 PostgreSQL 界所熟知且公司自身重度使用；域名库早在 2004 年 BSDCan 出现首个 Slony 演讲之前即已上 PostgreSQL（选型兼顾许可证与性能）；生产规模上单表达数千万行、日交易量巨大，调优得当时数据吞吐飞快，瓶颈通常在磁盘而非数据库本身；系统设定完成后即自行运转，无须持续调优，服务水平协议从未因 PostgreSQL 而失守。（BSDTalk EP144，[193.82-554.90]，L1）
- BSDCan 2008 为第五届、续办于渥太华大学，受邀演讲数量创历年之最：ZFS 文件系统深探（讲者转写不可辨）、Chris Lattner（时与 Apple 相关）讲 BSD 许可证的 C++ 编译器、Bacula 之父 Kern Sibbald 自瑞士与谈（Langille 本人亦是 Bacula 开发者）、Google Summer of Code 讲座、OpenBSD 硬件传感器框架的近期工作、Randall Stewart 讲 SCTP 及其扩展 socket API、X.Org 的未来规划；此外设 hacking、系统管理、嵌入式、虚拟化诸轨与教程，预计与会开发者约六十人（报名三十、惯例至会前翻倍），会前有开发者互讲、晚间设 hacking 房。 [存疑脚注] ZFS 演讲者人名转写不可辨，语境疑为 FreeBSD ZFS 移植者；SCTP 转写作 FCTP（BSDTalk EP144，[743.56-915.26]，L1）
- 会议的社交传统与运营哲学：注册自 Royal Oak 酒馆之夜开启（领 T 恤、领资料、喝啤酒），会期该馆 Guinness 销量增至三倍，周五六晚续聚、周日安排观光（核掩体、国会山、铸币厂、国家美术馆、文明博物馆，并新增标注步行可达景点的 Google 地图）；会议刻意维持小而可亲的规模，人人可与心仪开发者攀谈；固守渥太华纯因物流与熟悉度——熟悉校方与供应商降低精力与开销，使 organizer 得专注演讲与讲者质量，参会者亦因熟门熟路而自在。（BSDTalk EP144，[636.40-1015.94]，L1）
- Dan Langille 在会前访谈中阐明 BSDCan 的规模定位：历届总计约 220 人，刻意维持在“大到足以聚齐想见的人、小到可以上前攀谈”之间，并保持友好易接近的氛围；他明确表示技术演讲、BoF 与教程虽好，但任何会议的首要目的都是社交网络一面，即在宿舍共餐与走廊攀谈中结识邮件列表上久闻其名的人并建立工作关系，这种关系网络构成项目协作的坚实基础。（BSDTalk EP172，[222.2-368.4]，L1）
- 关于听众与议程结构，BSDCan 2009 汇聚开发者、系统管理员与普通用户，来自欧洲、美国、澳大利亚与日本，BSD 经验从十五年老兵到入门数月的新人皆有；议程设嵌入式系统、hacking、特邀演讲、系统管理等多个轨道，辅以 BoF、全体演讲、教程及周六晚会、周日渥太华城市观光等社交环节，参观对象包括博物馆、里多运河、议会大厦与 Chateau Laurier，观光环节已成为会议传统组成部分。（BSDTalk EP172，[178.2-454.4]，L1）
- Langille 披露了会议的远程组织模式：他前两年移居美国费城，任职社交网站 myyearbook.com 的运营程序员，居所距渥太华约八小时车程，2009 年届的组织工作完全经由电子邮件完成，尚未打过一通电话；连续六年沿用同一供应商与同一场地极大压缩了组织工作量，且因白天有全职工作、每晚仅有四到五小时可用时间，这种供应商与场地的稳定性成为志愿办会可持续的关键；2009 年会场首次改离原用的 SITE 楼，经由公告列表与网站通知参与者。（BSDTalk EP172，[498.9-580.9]，L1）
- 该届会议的 BoF 安排折射出 2009 年社区的技术议程：FreeBSD ports、FireWire 与固态硬盘三个 BoF 并列，其中 Langille 本人最关注后者——来自 Intel 的 Matthew Wilcox 研究固态硬盘已年余并修复多个性能问题，将在 BSDCan 与 PGCon 双会场主持 SSD BoF，讨论其使用与改进路径；同期同地由 Langille 平行筹办的 PGCon 因大学场地预订原因与 BSDCan 错开一周，且同样更换场地。（BSDTalk EP172，[93.2-736.6]，L1）
- BSDCan 由 Dan Langille 于 2004 年在渥太华创办，直接动因是他结识 Ottawa Linux Symposium 的组织者后认为对方能办成的事自己同样能办成；首届约一百七十余人与会，2005 年约两百人，2006 年预期再增约一成，论文约二十四场分布在两天；正式会议前两天附设 FreeBSD 开发者峰会，第二届延续举办，被视为 FreeBSD 社区支持该会议的标志。（BSDTalk EP14，[481.79-596.82]，L1）
- 渥太华会址具有结构性优势：部分欧洲与会者因赴美参会门槛而选择加拿大，汇率又使北美与会者获益，纽约受访者称往返加四晚住宿的全部开销低于在纽约参加一场会议；面对 BSD 已死的流言，Langille 以持续增长的参会人数与各项目论文供给作为否证。（BSDTalk EP14，[598.64-641.44]，L1）
- 会议论文呈项目间不均衡分布：FreeBSD 篇目最多，NetBSD、DragonFly BSD 与 OpenBSD 依次递补；OpenBSD 多于 NetBSD 的现象被归因于 NetBSD 开发者多困于项目事务、无暇赴会，而 OpenBSD 核心成员多居加拿大且其大型开发者聚会在 BSDCan 前数周举行，形成人员顺势转场的路径。（BSDTalk EP14，[739.21-795.58]，L1）
- 主持人梳理 2006 年 BSD 桌面化的法律与技术障碍：商业软件授权普遍禁止随免费系统再分发；MP3 格式在美国受专利约束，随系统免费分发的编解码器无法支付按设备计的授权费；Windows Media 等格式受数字版权管理封闭；BSD 虽能以 Linux 模拟层运行部分商业软件但兼容性参差，Java 近乎原生却缺乏 Sun 提供的简易安装器；结论是 BSD 的主战场仍在服务器。（BSDTalk EP14，[97.11-263.26]，L2）
