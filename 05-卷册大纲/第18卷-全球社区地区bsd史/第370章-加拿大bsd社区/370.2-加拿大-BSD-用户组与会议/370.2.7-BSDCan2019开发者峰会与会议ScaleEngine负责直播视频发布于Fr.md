- 总纲4 分离聚合是永恒规律：OpenZFS 从各平台分叉走向单一上游仓库的再聚合。（BSD Now EP300，[817.88-916.16]，L1）
- 总纲9 经验优先：BSDCan 以 hallway track 与动手 hackathon 为经验交流主渠道。（BSD Now EP300，[939.76-960.68]，L1）
- 总纲5 没有必然性，只有偶然性：X 窗口系统的显示与应用分离并非技术必然，而是 1984 年研究者不愿对未来研究设定硬约束的偶然决策，其后果却持续塑造桌面生态至今。（BSD Now EP253，[3198.90-3227.34]，L2）
- 总纲25 逻辑是形式主义而非世界本身的结构：X 协议把图形交互形式化为客户端与服务器之间的消息流，这种形式化反过来决定了 widget、窗口管理与外观的宿主侧分布。（BSD Now EP253，[3208.56-3258.98]，L2）
- 总纲8 本体论上各方平等：Robert Watson 既否定 macOS 只是 FreeBSD 加壳的简化说法，又承认 XNU 内核相当部分源自 FreeBSD，双方身份在本体论上被同等且边界分明地对待。（BSD Now EP252，[3241.32-3277.92]，L1）
- 总纲13 法律与道德是利益分配：Berkus 描述的商业生态形态展示了宽松许可证下的共生结构：EnterpriseDB（Oracle 兼容函数的专有分支）、Greenplum（基于 PostgreSQL 的专有数据仓库）、Continuent（Sequoia 之上的 UniCluster）、PowerGres（专有分支）等商业衍生品并存，而 PGCon 对商业分支议题持有限开放；与此同时，公开而活跃地使用 PostgreSQL 的公司被吸纳为社区成员而非保持纯商业客户关系。许可证允许专有汲取，社区则以参与感回收忠诚——法律框架在此直接塑造了商业与社区的博弈方式。 [存疑脚注] “Powergrass”转写原貌，应为日本厂商的 PostgreSQL 专有分支 PowerGres，待核（BSDTalk EP110，[391.47-493.45, 884.21-927.73]，L1）
- 总纲10 动手者创造历史：学区网络的真实形态由一线管理员以捐赠旧硬件、活页夹灾备文档与 LDAP 集成逐步搭建，FreeBSD、NetBSD 与 Apple 的取舍由经费约束、旧硬件复用与运维人手现实决定，而非任何厂商路线图——技术历史在这种日常动手维护中被具体地塑造。（BSDTalk EP10，[190.32-660.80]，L1）
- 总纲20 历史地理塑造思想土壤：BSDCan 的地理惯性自成一例：会议地点并非由社区版图或战略考量决定，而系于创办人的居所变迁、场地与供应商熟悉度这类偶然的物流事实——人移居宾州而会议仍留渥太华，地理的惯性与 familiarity 持续塑造着 BSD 社区的聚集形态。（BSDTalk EP144，[636.40-718.20]，L1）
- 总纲4 分离聚合是永恒规律：这期访谈呈现 BSD 社区以周期性聚合维系协作的运转方式：日常开发分散于全球各地的邮件列表，而 BSDCan 每年一度将分散的动手者重新聚合于渥太华，通过共宿、共餐与观光把线上关系转译为线下信任，再散回各地支撑来年的远程协作。会议的社交优先设计正是对这种分离聚合节律的自觉安排。（BSDTalk EP172，[222.2-271.2]，L1）
- 总纲10 动手者创造历史：主持人以乐高积木作比提出工具本位宣言：自由操作系统效仿的是 Unix 哲学而非 Windows 哲学，其力量不在某个功能齐备的成品应用，而在一切皆文本文件、众多小工具经管道自由组合的构造过程；把 BSD 仅当作免费 Windows 克隆，会错失这套系统真正的力量，使用者必须亲手在命令行中学会拼装。（BSDTalk EP14，[265.45-439.50]，L2）
- 总纲5 没有必然性，只有偶然性：BSDCan 的创建没有任何机构授权或长期规划作为前提，它源于一次个人化的类比行动：Langille 看到相识的 Linux 会议组织者能够办成，便认定自己在渥太华同样可以；社区性制度设施由此从具体个人的偶然模仿中生长出来。（BSDTalk EP14，[490.23-504.44]，L1）
- 总纲10 动手者创造历史：会议组织在 Langille 的叙述中是一份常年亲力亲为的劳动——致电酒店谈团体价、维护网站、协调场地与住宿——如今以每周五六小时的量被拆解移交志愿者；BSD 会议史正是由这类具体而琐碎的组织劳动所构成。（BSDTalk EP181，[630.4-661.3]，L1）
- 总纲6 和解优于斗争：他将会议的最大价值归于面对面：对真正认识、一起喝过啤酒的人很难动怒，合作也更为顺畅——线下共处被视为化解分布式社区冲突、维系协作的机制。（BSDTalk EP181，[714.3-744.4]，L1）
- 总纲9 经验优先：全书的立场可归结为以经验数据治理网络：知道 IPsec 连接来自何处、何时占用多少带宽，才能就带宽采购做出明智决策；网络世界的判断应建立在可回溯的流记录之上，而非印象、会议政治或指示灯的明灭。（BSDTalk EP190，[598.84-631.36]，L1）
- 总纲10 动手者创造历史：其自我呈现是沉默动手者的典型样本：自称拥有提交权限却从不活跃、仅提交过零星小改，却数十年自维护 Gosling Emacs 变体、为 GCC 添自制扩展、维护 1.4T 私人分支、独立实现 SSH 与 mail shim——项目的实际运转依赖这类不居功的基础设施维护者，而非只有台前的活跃面孔。（BSDTalk EP45，[86.86-98.42]，L1）
- 总纲13 法律与道德是利益分配：对大公司介入的期待形态：作为承接项目的承包者，Langille 希望出现的是为既有 BSD 提供支持服务的跨国公司，而非自造 BSD 发行版的公司——如此他方可向客户承诺有巨头兜底；企业本愿支付重金把风险压至可接受水平，而 BSD 目前不提供这一选项；在他看来，商业支持的缺位是风险分配结构的问题，而非技术品质的问题。（BSDTalk EP47，[576.60-630.40]，L1）
- 总纲10 动手者创造历史：受访者以一人之力长期维系文档（FreeBSD Diary）、元数据索引（FreshPorts）与会议（BSDCan）三类社区基础设施，又以业余时间给 Bacula 补上 PostgreSQL 插件；BSD 社区的日常运转并不只靠内核提交，而依赖这类兼具写作者、索引者与组织者身份的动手者，备份这类“无人喝彩但人人依赖”的运维实践亦由其口述得以存史。（BSDTalk EP67，[73.4-136.68]，L1）
