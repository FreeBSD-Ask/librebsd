# 367.3.5 AsiaBSDCon2018在东京举行前两日为FreeBSDDeveloperS

- AsiaBSDCon 2018 在东京举行，前两日为 FreeBSD Developer Summit 与 BeehiveCon（含 NetBSD Summit 和 OpenBSD VMM 更新），后两日为论文演讲；bhyve 相关论文在第二天占满专题时段，议题覆盖 bhyve 的 SmartOS zones 移植、ARMv7/v8、挂起恢复与虚拟中断控制器，另有 FreeBSD VPC 与保存恢复（朝向热迁移的第一步）。（BSD Now EP237，[0.0-997.0]，L1）
- FreeBSD 11.1 stable 合入针对 Meltdown 与 Spectre V2 的缓解：Meltdown 采用 PTI 分离内核与用户页表，Spectre V2 采用依赖微码更新的 IBRS；可通过 vm.pmap.pti 与 hw.ibrs_active 等 sysctl 查看与切换，retpoline 编译器方案仍在评估中。（BSD Now EP237，[1008.2-1502.9]，L2）
- OpenBSD 宣布 syspatch 开始为两个受支持版本（6.1 与 6.2）同时提供二进制补丁，使 6.2 在 6.3 发布后仍可通过 syspatch 获得 Meltdown 缓解，并特别感谢 Robert 与 Antoine Jacoutot 的工作。（BSD Now EP237，[3566.9-3641.5]，L2）
- MidnightBSD 创始人 Lucas Holt 在访谈中说明该桌面导向系统是 FreeBSD 的 fork 而非发行版，拥有自有包管理器 mPort（tar LZMA 包加 SQLite3 清单与索引），启动卷使用 UFS2 并支持 ZFS，提供 2.6.16 内核的 Linux 仿真，计划保留 i386 支持至 1.0 版本。（BSD Now EP237，[1701.7-2136.1]，L2）
- 一篇八个月使用 TrueOS 的报告记述作者因对 Linux 发行版的 systemd 组织方式失望而转向 FreeBSD/TrueOS，赞赏 OpenRC、ZFS 启动环境回滚与手册质量，并由此偏好 BSD 许可证；其未能使用的软件为 Netflix、Google Hangouts 与 Electron 类应用。（BSD Now EP237，[2373.5-2995.7]，L2）
- OpenBSD 开发者 Marc Espié 自述 dpb 为 FreeBSD poudriere 的强化对应物：面向本地集群、可精细控制各端口构建时序、力求并行构建同时收尾；其哲学是拒绝交叉编译、坚持各架构本机构建，以免长期掩盖破坏性回归，如 sparc64 集群每月约构建三千包，覆盖范围直至 VAX。（BSD Now EP94，[2027.10-2148.20]，L1）[订正：原 [2019.35-2131.40]，2026-09-30 SenseAudio 重转核对]
- Espié 详述 dpb 的信任模型翻转：ports 树中工具可信而数以千计的 configure 脚本不可信，他笑称该系统“本来并非为此设计”（2157.08-2170.66）；改造后 dpb 以 root 启动随即降权，抓取源码与构建分属有无网络权限的不同用户，构建环境置于 chroot 且所在分区禁用 SUID，再以 pf 收紧网络面，非特权构建用户已在实战中暴露 configure 脚本的异常行为。（BSD Now EP94，[2157.08-2480.54]，L1）
- 新闻层勾勒 2015 年发行版嵌套图景：PC-BSD 项目 fork HardenedBSD 仓库筹建实验性镜像，主持人称 OPNsense 数周前已开先例；HardenedBSD 开发者 Shawn Webb 以同一构建脚本为 MIPS 路由器出包，其更严格的编译检查反而在 FreeBSD 树中揪出一处缺陷并已修复；同期 xhyve 将 bhyve 移入 macOS 10.10 的 Hypervisor.framework 用户态，嵌套与移植构成当期分发生态主线。（BSD Now EP94，[1132.40-1277.20]，L2）[订正：原 [1151.36-1281.88]，2026-09-30 SenseAudio 重转核对]

- 亚洲 BSD 生态的强度与成因：George Neville-Neil 与日本众多 BSD 开发者互动的总体印象是 Linux 与 BSD 在日本大致处于均势——商业领域 Linux 更流行，而开发者偏爱 BSD；日本 BSD 开发者众多的结构性原因在于嵌入式采用：打印机、电话机、小型便携 DVD 播放器等设备以 BSD 为底，直接把开发者基数做大；亚洲其他地区的 BSD 部署亦相当广泛。（BSDTalk EP74，[338.14-416.70]，L1）
- 许可证被点名为嵌入式采用的决定变量：设备制造商不愿公开源代码，而 GPL 强制公开，BSD 许可证因此在这类应用中通常胜出——操作系统在嵌入式商业场景的胜负手不是纯技术指标，而是源码披露义务所对应的利益结构。（BSDTalk EP74，[416.70-439.08]，L1）
- 文档本地化的双重困境：组织层面，翻译工作对普通开发者吸引力低，专职翻译团队覆盖约八种语言却并不活跃，成员多为用户而非开发者，招译者困难；德语与法语翻译最活跃，中文近期活跃但人手极少。技术层面，用户文档翻译尚可，而消息目录、内核消息与命令行消息的翻译构成硬障碍——翻译需要多种编码，但消息文本通常写死在源代码中，多编码方案无法进入源码。（BSDTalk EP74，[444.56-601.12]，L1）

- FreeBSD 11.1 稳定分支于本期前后合入自 HEAD 下移的投机执行缓解补丁：Meltdown（越障投机执行后经缓存侧信道泄漏特权数据的微架构缺陷）以页表隔离（PTI）应对，Intel 处理器默认启用，系统调用微基准回归显著而多数真实负载影响较小，可经 loader 可调参数 vm.pmap.pti 控制；Spectre v2（分支目标注入）以 IBRS 加 CPU 微码更新缓解，状态经 hw.ibrs_disable 与 hw.ibrs_active sysctl 查验，而依赖新编译器的 retpoline 方案因向 stable 分支合并新版 clang 风险过大仍属评估项，i386 所随代码不含功能性缓解；同集播报 OpenBSD syspatch 首次为 6.1 与 6.2 两个受支持发行版（6.3 发布后 6.2 仍受支持）提供二进制补丁，amd64 用户均获 Meltdown 缓解，公告致谢 Robert 与 Antoine Jacoutot 的补丁工作、TJ 及志愿者测试与 Theo 的总体监督。（YouTube EP_6gNefiY6hU，[1001.3-3636.5]，L2）[订正：原“Theos 的总体监督”→“Theo 的总体监督”，字幕原文为 for Theo for overseeing it all；时间戳原 [1010.39-3640.9]→[1001.3-3636.5]，11.1 缓解补丁段自 1001.3 起、致谢清单止于 3636.5，原边界取自旧转写轴]
