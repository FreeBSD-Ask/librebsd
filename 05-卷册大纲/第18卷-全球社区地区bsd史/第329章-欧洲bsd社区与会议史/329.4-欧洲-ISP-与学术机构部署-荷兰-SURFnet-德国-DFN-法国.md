## 329.4.1 欧洲 ISP 的 FreeBSD 部署实例

  **要点**：荷兰 SURFnet、德国 DFN、法国 RENATER、英国 JANET、瑞典 SUNET 等欧洲学术 ISP 部署 FreeBSD。本章的“原因分析”以分析框架呈现，尚待各国一手部署证据回源支撑：①技术动因——ports/packages 体系对网络服务与镜像站运维的适配；②制度动因——BSDL 与学术机构、国家科研网络的许可与协作亲和；③文化动因——早期 UNIX 在欧洲学术界的既有传承。证据缺口：各国的部署年份、规模、系统版本与文献佐证（SURFnet/DFN/RENATER 年报页码或存档 URL）均待回源，本书不以名录代证据。

## 329.4.2 学术机构部署的演变过程

  **要点**：欧洲学术机构从 1990 年代 FreeBSD 的主流部署到 2000 年代后部分迁移至 Linux；其部署与持续的通用动因包括——ports/packages 体系对网络服务运维的适配、BSDL 与学术环境的许可亲和、以及早期 UNIX 文化传承；各机构的迁移时间与规模证据待回源（见 329.4.4 证据缺口声明）。
  **史料**：学术机构 OS 部署统计、迁移案例、技术报告 〔L5 二手研究〕
  **史观**：总纲第 4 条——分离聚合是永恒规律：学术机构部署从 FreeBSD 向 Linux 的部分迁移，是操作系统谱系的分离聚合过程
  **辨析**：迁移的具体时间需考据；原因需分析
  **文献**：欧洲学术网络 OS 统计；迁移案例研究 ［B］

## 329.4.3 与北美部署模式的比较

  **要点**：欧洲学术 ISP 部署模式与北美（如 ESnet、Internet2）存在差异，欧洲更注重多语言支持；本节的两期播客口述（EP57 米兰 ITSP 以 FreeBSD 承载 VoIP、EP76 巴塞尔服务商以 OpenBSD 承载学校系统）属欧洲中小企业与教育机构部署层证据，与 NREN 国家学术网络层须分开叙述，不能互替。
  **史料**：欧美学术网络对比研究、部署模式分析 ［B］
  **史观**：总纲第 20 条——历史地理塑造思想土壤：欧洲与北美的部署模式差异植根于各自的地域与制度语境
  **辨析**：差异的具体表现需考据；原因需分析

**要点**：

- Stucchi 于两年前在米兰创立三人小公司，定位 ITSP 与网络服务提供商（网页、邮件服务及经合作企业的连接），非完全 ISP；公司全程大量使用 FreeBSD 托管服务，并以之为电话服务的首选交付平台；理由是平台坚如磐石、开发者优秀、遇障可获得良好支持，且既有基础设施已在 FreeBSD 上，转投 Linux 反而是错误选择；ports 系统对软件版本的管理完全可靠，而电话服务部署要求超过百分之百的可靠性，ports 正是达成此目标的手段。（BSDTalk EP57，[81.88-188.72]，L1）
- FreeBSD 开发者 Luigi Rizzo 于访谈前约五六个月加入 Asterisk 项目，对主流应用做了大量修改使其可运行于 FreeBSD；此前 Asterisk 无法在 FreeBSD 上开箱编译，此后不仅可以，且代码路径与 ports 同步，make 文件中更因他而设 FreeBSD 专用选项。（BSDTalk EP57，[190.26-229.58]，L1）
- VoIP 硬件支持主要来自 asterisk-BSD 邮件列表；因 VoIP 演进过快，ports 中的 Asterisk 版本滞后于上游，其惯例是经 ports 安装 Asterisk、再从上游 subversion 仓库安装硬件驱动；约九个月前升级最新 Zaptel 驱动后机器每小时重启，求助消息发出数小时后（凌晨一时）即获回补丁；只要选用 Digium 与 Sangoma 卡即有良好支持，Sangoma 卡有厂商直接支持。（BSDTalk EP57，[234.7-342.82]，L1）
- 商业定位上转向以企业客户为主：VoIP 的价值已不在通话费用（免费市话服务随处可得），而在附加服务——会议、按用户分发的企业语音信箱、IVR 交互式语音应答、与企业管理系统集成，用 Asterisk 加几行 PHP 或 Python 即可任意定制；可靠性方面，传统电话世界的 SS7 协议族（他喻为电话界的 BGP）包含逐线复制的协议，电话业处理冗余已四五十年，而 Asterisk 存在结构性限制——话机注册绑定单机、宕机后注册信息无法与其他机器共享，难以做到完全冗余，用户“拿起听筒必然可用”的习惯预期叠加断线、路由器宕机等变量，构成他所称的 21 世纪挑战。（BSDTalk EP57，[342.82-523.96]，L1）
- 内部系统上，除一台因意大利复杂税制而保留的 Windows 会计机（运行合作者开发的账簿软件）外，从桌面到服务器全部运行 FreeBSD；BSD 平台的 SIP 软电话仍然匮乏：Ekiga（GNOME Meeting 新版，已含 SIP 支持）系朋友测试、其本人未亲验，X-Lite 堪称最佳但仅运行于 Windows。（BSDTalk EP57，[523.96-600.04]，L1）
- OpenCON 是首个专门面向 OpenBSD 的会议，2004 年由意大利威尼斯本地人首创；其成长轨迹清晰——2004 年九场报告中仅三场出自开发者、到场发言的开发者仅 Henning Brauer 一人，2005 年九场中六场出自七位开发者，2006 年十四场报告出自十位开发者，多数报告已由官方开发者承担；会议前一周在里斯本举行 mini hackathon，开发者顺势短途飞抵威尼斯；2006 年 12 月 2 日至 3 日举行、会议完全免费，首日晚宴兼作 OpenBSD 十周年派对仅收象征费用。（BSDTalk EP76，[109.96-235.20]，L1）
- 会议后勤与收入结构：场地 2004 年设于威尼斯技术门户 VEGA，2005 年迁至潟湖小岛——水城交通全赖船只且船费高昂，把会议服务运上小岛近乎历险，2006 年移至机场附近才恢复便利；赞助方包括欧洲 OpenBSD 支持商 KD85.com、CD 与海报 T 恤销售商、本地互联网服务提供商及 O'Reilly，组委会全部志愿工作；会上销售 CD-ROM 与 T 恤、海报免费发放，CD-ROM 销售是 OpenBSD 项目除捐款外的主要收入来源。（BSDTalk EP76，[271.08-432.20]，L1）
- 当事人从 Linux 转向 OpenBSD 的运维逻辑：其公司长期维护 Unix 系统，在 Linux 热潮期间采用 Linux 却屡遭黑客入侵，遂先把 DNS 服务器等关键平台迁至 OpenBSD，数年后全面铺开；公司承接巴塞尔公立学校、图书馆与动物园的 IT 服务，直接用户数千——仅公立学校系统即约一万名学生、三千五百名教师、每年约一千人进出；文件服务与邮件服务均由 OpenBSD 承载，其称许 ports 与 packages 体系真正可用，软件维护比 Linux 容易。（BSDTalk EP76，[444.00-633.04]，L1）
- 大规模部署的运维纪律：全部生产机坚持 stable 分支，以保证各服务器软件状态一致、可管理——跑 current 技术上可行但会造成各机版本漂移，商业环境不可接受；公司自备构建机按需构建发行版与软件包，全部生产机跟随 OpenBSD 发布周期每半年统一升级一次；个人笔记本与家用机则运行 current，以致其对 4.0 新特性已无新鲜感。（BSDTalk EP76，[684.38-742.68]，L1）
- 当事人的技术贡献清单：已在 OpenBSD 落地 NMEA 支持（GPS 设备）与时间信号站接收器支持，正扩展两者功能；维护 PostgreSQL、OpenLDAP、Samba 等多个 ports。（BSDTalk EP76，[83.10-103.50]，L1）
- 进行中的合作项目瞄准 OpenBSD 的结构性短板——缺少现代中央用户数据库：YP 时代之后系统无此能力，公立学校系统万级用户的账号管理亟需集中化；当事人与 Claudio Jeker、Chris Kuethe 合作推进，目标是让 Samba 等服务可对接 LDAP 式中央认证，免除在每台服务器本地建户。（BSDTalk EP76，[603.72-684.38]，L1）
- 固件再分发斗争的立场陈述：呼吁用户购买 CD-ROM 支持项目，并向拒不授予二进制固件再分发许可的硬件厂商施压；其诉求刻意设为最低限度——不要求无线设备固件的源代码，只要求把二进制固件放入 CD-ROM 随发行版再分发的权利；近期与厂商的相关谈判相当艰难，undeadly.org 是跟踪其动向的公开窗口。（BSDTalk EP76，[779.80-830.88]，L1）

**史观**：

- 总纲10 动手者创造历史：小型企业的电话服务可靠性实际上由具体开发者的个人劳动与社区响应构成：Luigi Rizzo 的移植使 Asterisk 得以在 FreeBSD 上开箱编译，Zaptel 驱动故障后凌晨一时的回补丁则展示了邮件列表响应速度对生产系统的直接支撑——基础设施的稳定性史由这些动手环节写成。（BSDTalk EP57，[190.26-324.9]，L1）
- 总纲9 经验优先：当事人全部技术判断源自运维经验而非理论宣言：被黑客入侵的切肤之痛促成关键平台迁移，万级用户的真实管理需求催生中央用户库项目，半年升级节奏决定 stable 策略——平台选择的标准被表述为朴素的一个基本可用且安全的系统。（BSDTalk EP76，[444.00-526.04]，L1）
- 总纲3 不存在进步，只有权力再分配：固件再分发之争的实质是硬件厂商与开源社区之间对固件控制权的再分配：OpenBSD 明确不求固件源码、只求二进制再分发权，把诉求压缩到最低限度以换取厂商让步的可能——这一谈判姿态本身就是权力边界协商的操作化表达。（BSDTalk EP76，[805.88-820.12]，L1）
