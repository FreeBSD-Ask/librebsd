# 339.5 伊朗技术社区与 BSD——伊朗 ISP 与电信公司（Hamrah-e-Aval、Irancell、Telecommunication Company of Iran）的 BSD 部署历史、伊朗大学（德黑兰大学、Sharif 理工大学、Amirkabir 理工大学）的 BSD 教学、伊朗受国际制裁对开源参与的效应、伊朗开源社区的地下演进

## 339.5.1 伊朗 ISP 与大学的 BSD 使用

  **要点**：伊朗 ISP 与电信公司（Hamrah-e-Aval、Irancell、Telecommunication Company of Iran）在 1990 年代至 2000 年代曾部署 BSD 用于网络服务；伊朗大学（德黑兰大学、Sharif 理工大学、Amirkabir 理工大学）曾有零星 BSD 教学；具体部署与教学须通过企业档案与大学课程档案核查
  **史料**：伊朗 ISP 企业档案、伊朗大学课程档案、伊朗技术社区邮件列表 ［A］
  **史观**：总纲第 9 条——企业研究投入的双重性，伊朗 ISP 与大学的 BSD 使用反映企业对稳定性的实用主义选择
  **辨析**：伊朗 ISP 的 BSD 部署因国际制裁限制难以通过常规渠道核查；大学课程的实际情况须通过课程档案核实

## 339.5.2 伊朗 BSD 社区在制裁下的生存演变

  **要点**：伊朗 BSD 社区在国际制裁下通过地下网络获取软件与文档；2010 年代后随制裁加剧，伊朗 BSD 社区进一步孤立；演变须通过社区档案与开发者访谈验证
  **史料**：伊朗技术社区邮件列表、开发者访谈、地下软件分发记录 ［A］
  **史观**：总纲第 12 条——法律结构对技术创新的制约与解放，国际制裁塑造伊朗 BSD 社区的独特生存模式
  **辨析**：地下网络的实际情况因安全限制难以完全核查；开发者访谈须警惕记忆偏差与政治立场
  **文献**：伊朗技术社区邮件列表存档；开发者访谈记录；地下软件分发记录档案 ［A］

## 339.5.3 伊朗与俄罗斯 BSD 社区比较

**要点**：

- Klara Systems 详解 OpenZFS 2.1 的 dRAID（distributed RAID）：在 RAID-Z 语义上重排数据块使访问均匀铺满全部盘，配合预分配的分布式热备实现快速换盘；其顺序 resilver 仅沿 parity 布局重建目标盘，随后自动触发 healing resilver 补全校验，把传统 scrub 式全池校验拆分为两阶段以适应大容量盘时代；OpenZFS wiki 的 90 盘 16TB 组测试显示换盘时间由约 29 小时缩短至 15 小时余，且单/双/三奇偶校验皆不放大耗时。（BSD Now EP393，[463.28-869.34]，L2）
- 主持人重读 27 年前 Adrian Cockcroft 的 Sun Performance and Tuning：SunOS 4 目录名查找缓存（DNLC）只缓存 14 字符以内文件名、le0 网卡与 SCSI 接口共享 DMA 导致重负载网络拖慢磁盘吞吐等细节，折射 90 年代系统调优的现实约束；书中 VM stat/SAR 的多因素组合测量（六因素四水平即 4096 组合）提醒读者性能实验的组合爆炸与读数陷阱。（BSD Now EP393，[89.12-426.96]，L2）
- Signal 在伊朗遭封锁后给出代理方案，其官方 Docker 镜像内里只是 nginx 配置；社区据此给出 FreeBSD + nginx + acme.sh（Let's Encrypt/ZeroSSL）的等价部署教程，并默认关闭访问日志以避免记录经代理的通信内容。（BSD Now EP393，[1065.54-1311.46]，L2）
- 从 macOS 迁移者的 PDF 需求牵引出 OpenBSD ports 中的 Xournal/Xournalpp（触笔与手指标注、签名、导出只读 PDF）与 OCRmyPDF（对扫描件识别后生成可复制文本），讨论指出这类工具并非 OpenBSD 独有，映射桌面 Unix 在文档工作流上的补课过程。（BSD Now EP393，[1311.46-1662.86]，L2）
- Fabricator 平台的“现在就该做”清单以 Facebook 教训立论：ID 从 2 的 33 次方起跳以杜绝标识符与业务数值混淆（PHP array_slice 重排索引导致渲染错人的案例）、只存有效 UTF-8 以避免文件名跨系统漂移（Bacula 备份还原场景反例）、勿以黑名单构建安全系统（Facebook 的 CSS 黑名单制造了无尽的安全漏洞）、生产环境 SQL 语法错误应当高声报警以充当 SQL 注入的高信号探测器。（BSD Now EP393，[1672.1-1939.58]，L2）
- 反馈环节：Dan Langille 当场实测证明 ZFS 快照彼此独立、可任意删除旧快照而不影响新快照（快照是文件系统时点照片而非增量差分，仅回滚受限于更新快照）；另有听众询问 bhyve 中直通设备与物理盘并存的失败案例，以及多操作系统共享同一 ZFS 池引导的可行性，主持人以 bootfs 参数唯一性与加载器对加密池（GELI）的支持边界作答。（BSD Now EP393，[2438.92-2922.44]，L1）

**史料**：

- Klara Systems dRAID 文章与 OpenZFS wiki 的 D-RAID sequential resilver 数据表（90 盘、单分布式热备、100% 池容量、16TB 换盘约 29 小时对照 dRAID 15 小时余），含 zpool create 示例。（BSD Now EP393，[497.16-802.02]，L1）
- Sun Performance and Tuning（Adrian Cockcroft）原文细节与当年 Amazon 三星书评，构成一手图书加二手解读的叠加史料。（BSD Now EP393，[155.36-322.24]，L1）
- Signal 官方关于伊朗封锁的响应与代理部署说明（含 Docker 镜像内为 nginx 包装的事实），一手公告。（BSD Now EP393，[1088.66-1094.34]，L1）
- Fabricator 文中 Facebook 2008 年 SQL 语法错误报警机制的亲历者叙述（系统精炼后作为高信号注入探测），属一手史料。（BSD Now EP393，[1887.7-1908.1]，L1）

**史观**：

- 总纲22 知识注定过时：27 年前的调优书今日仍被整期研读，其价值不在参数而在方法论；DNLC 14 字符限制等具体知识已彻底过时——技术图书的经典性恰以内容过时为前提，留存下来的是测量学经验。（BSD Now EP393，[89.12-299.56]，L2）
- 总纲5 没有必然性，只有偶然性：Signal 伊朗封锁这一偶然地缘事件催生反审查代理教程：FreeBSD 社区的技术响应方向由外部政治偶然性牵引，而非既定技术路线图。（BSD Now EP393，[1088.66-1102.9]，L2）
- 总纲13 法律与道德是利益分配：Facebook 黑名单 CSS 过滤器的失败史揭示安全机制同样是利益与权力的分配装置：默认允许加枚举坏人的架构把防御成本转嫁给未来，枚举权的失效即秩序的失效。（BSD Now EP393，[1843.98-1866.94]，L2）
- 总纲4 分离聚合是永恒规律：dRAID 把 scrub 的整体校验分离为顺序重建与 healing 补全两阶段再聚合，其设计哲学是让数据布局的分离-聚合服务于修复路径的最小化。（BSD Now EP393，[497.16-704.2]，L2）
- 总纲1 一切真历史都是古代史：对 1994 年图书的认真重读表明：理解当下存储系统行为（预读、缓存、测量偏差）须不断回到“古代”文本，性能史是一部被反复重写的古代史。（BSD Now EP393，[155.36-186.48]，L2）

**辨析**：

- 主持人对 dRAID 中“分布式热备”的物理形态存疑（是否存在可指认的专属 parity 盘），文献表述易生歧义，须以 OpenZFS dRAID 手册页与实现代码裁决。（BSD Now EP393，[856.86-883.22]，L2）
- dRAID“数学较复杂”仅为主观印象：重建时间曲线背后的奇偶校验分组模型在对话中未展开，直接引用性能数字须回到 OpenZFS wiki 原始表格。（BSD Now EP393，[984.54-990.94]，L2）
- Fabricator 文章“若早做这些 Facebook 可省巨额成本”系作者的反事实推测，无法核验。[存疑脚注] 该清单的 Facebook 受益估算属推测性表述　[存疑脚注] 清单对 Facebook 的反事实收益估算无法核验（BSD Now EP393，[1744.1-1750.76]，L4）
