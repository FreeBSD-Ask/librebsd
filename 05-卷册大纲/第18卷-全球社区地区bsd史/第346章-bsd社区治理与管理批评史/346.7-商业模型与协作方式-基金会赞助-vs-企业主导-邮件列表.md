# 346.7 商业模型与协作方式——基金会赞助 vs 企业主导、邮件列表 vs GitHub PR、CVS→SVN→Git

- **要点**：BSD 三大分支的商业模型形成基金会赞助与企业主导并存的格局——FreeBSD Foundation（2000 年成立）以企业赞助（Juniper、NetApp、Apple、Netflix 等）与个人捐赠为主要资金来源，NetBSD Foundation（1995 年成立）以捐赠为主，OpenBSD Foundation（2007 年成立）以黑客松活动资助与个人捐赠为主。企业主导案例包括 Apple Darwin/BSD（macOS 底层基于 FreeBSD 用户态与 Darwin 内核）、Sony PlayStation 系列主机操作系统基于 FreeBSD（PS3 至 PS5）、Netflix 使用 FreeBSD 作为流媒体分发平台内核。协作方式演化从 1990 年代 CVS（Concurrent Versions System）到 2000 年代 SVN（Subversion）再到 2020 年代 Git——FreeBSD 于 2020 年 12 月完成从 SVN 到 Git 的迁移，并启用 GitHub 镜像与 PR 流程，引发关于“邮件列表 vs GitHub PR”的协作方式争议。邮件列表传统派认为 GitHub PR 流程削弱了深度讨论，GitHub 拥护派认为 PR 流程降低外部贡献者门槛。社区对商业化协作方式的批评与反批评持续——批评者担忧企业影响项目方向，反批评者认为企业投入是社区可持续性的必要条件。

- **史料**：一手史料包括 FreeBSD Foundation 年度报告（**<https://freebsdfoundation.org/>**），NetBSD Foundation 年度报告，OpenBSD Foundation 年度报告（**<https://www.openbsdfoundation.org/>**），Apple Darwin 开源页面（**<https://opensource.apple.com/>**），Sony PlayStation 系统文档（须通过第三方安全研究交叉验证），Netflix 工程博客关于 FreeBSD 的文章，`freebsd-hackers` 关于 Git 迁移的讨论存档，`freebsd-git` 邮件列表；二手史料包括 Schweik & English (2012)、von Krogh et al. (2003) 关于开源商业模型的研究；互联网档案馆存档的 `phoronix.com`、`lwn.net` 关于 Git 迁移争议的报道 ［A］。

- **史观**：总纲第 11 条（商品是形式主义，见 sacred_sources.duckdb 总纲原文）——企业主导案例（Apple Darwin、Sony PS、Netflix）是技术商品形式主义化的典型，BSD 代码作为商品被企业再分配；总纲第 9 条（经验优先，见 sacred_sources.duckdb 总纲原文）——协作方式从邮件列表到 GitHub PR 的演化以实际使用经验为依据，而非理论预设；总纲第 3 条（不存在进步，只有权力再分配，见 sacred_sources.duckdb 总纲原文）——Git 迁移不是协作方式进步，而是决策权从邮件列表传统派向 GitHub 拥护派的再分配；总纲第 15 条（文化即形式主义，见 sacred_sources.duckdb 总纲原文）——邮件列表 vs GitHub PR 之争是 BSD 社区文化形式主义化的显化，“深度讨论”与“低门槛”是不可通约的文化偏好；总纲第 22 条（知识注定过时，见 sacred_sources.duckdb 总纲原文）——CVS→SVN→Git 的演化是技术债务的历史累积，每一代工具都承载前一代的遗产。

- **辨析**：Apple Darwin 与 FreeBSD 的具体代码共享范围需考据——Darwin 内核与 FreeBSD 用户态的关系在不同叙述中存在差异，须以 Apple 开源页面与 FreeBSD 基金会公告为准；Sony PlayStation 使用 FreeBSD 的具体版本与定制程度须通过第三方安全研究者逆向分析交叉验证，Sony 官方未完整公开〔存疑：具体版本与定制程度待原始档案或更多第三方逆向分析确证〕；Netflix 使用 FreeBSD 的具体场景（流媒体分发内核）须以 Netflix 工程博客为准；【0 信任原则·企业自利陈述】Apple、Sony、Netflix 对自身 BSD 使用的公开陈述均可能存在商业自利偏差，须与第三方独立分析交叉验证；FreeBSD 2020 年 Git 迁移的具体时间节点需考据——决策时间、迁移执行时间、GitHub 镜像启用时间存在差异，以 `freebsd-git` 邮件列表公告为准；邮件列表 vs GitHub PR 之争须呈现双方主体性，禁止以“现代化”叙事压制传统派。
