# 335.2 加拿大 BSD 用户组与会议

147.2 **加拿大 BSD 用户组与会议**———BSDCan（2004 年首届于渥太华大学）是加拿大 BSD 社区的核心会议，Toronto BSD Users Group（TBUG）、Vancouver BSD Users Group 等地方用户组活跃

- Terry Lambert 在 Quora 回答中把 FreeBSD 桌面市场份额近零归因于 1984 年 X Window System 的设计决策：为在廉价终端上运行而把显示服务与应用在最低图形原语层分离，使高层图形、widget 与窗口管理范式都留在主机侧，导致各应用外观随工具包而异、培训不可迁移，最终令 X 不适合作为统一桌面。（BSD Now EP253，[3063.24-3428.96]，L2）
- Terry Lambert 进一步指出该决策使商业软件供应商难以选择工具包并保证五到八年的持续销售，故而不愿为 X 平台开发；他认为 2012 年出现的 Wayland 正在重犯 X 在 1984 年犯下的同类错误。（BSD Now EP253，[3474.80-3579.92]，L2）
- Mark Johnston 的 BSDCan 2018 报告记录 FreeBSD 开发者峰会内容：Deb Goodkin 介绍基金会工作、在任 Core 团队汇报两年工作、发布工程团队介绍职责，并记录 OpenZFS 讨论中 ZFS on Linux 因改动频繁而使上游定义模糊、ZFS 改动被直接从 ZFS on Linux 移植入 FreeBSD。（BSD Now EP253，[1396.34-1698.40]，L1）
- 报告还记录 Colin Percival 讲解 FreeBSD 内核启动耗时构成及他所添加的测量基础设施，指出遗留的 PS/2 键盘兼容补丁是剩余启动延迟之一，因不确定是否仍需保留而难以移除。（BSD Now EP253，[1713.08-1839.10]，L1）
- FreeBSD 11.2 于 2018 年 6 月 27 日发布，带来 ZFS 压缩发送/接收与设备移除、面向 Intel 集成显卡的 DRM Next Kmod、OpenSSH 7.5p1 与 OpenSSL 1.0.2o 更新、LLVM 6 工具链，以及 Chelsio、Mellanox、Intel IXL 等大量网卡驱动更新。（BSD Now EP252，[63.24-246.32]，L2）

- 微软发布自有 FreeBSD 10.3 Azure 镜像，纳入 Hyper-V/Azure 补丁并附微软技术支持；Justin Gibbs 称之为 FreeBSD 社区的重要里程碑。（BSD Now EP146，[773.00-936.00]，L2）
- Hans-Peter Selasky 16 岁经 ISDN 软盘安装 FreeBSD，重写 i4b ISDN 栈与 USB 栈后获 commit bit；其 webcamd 在用户态以 libUSB 兼容层编译 Linux USB 驱动，并从事 Mellanox 100GbE 与 Linux KPI 工作。（BSD Now EP146，[1338.00-1881.00]，L1）
- libexpat 随机数时间线显示 OpenBSD 因早期以 arc4random 替换 rand 而免于相关 CVE；NetBSD 代码膨胀数据与 DistroWatch 就地升级对比亦被提及。（BSD Now EP146，[3253.00-3438.00]，L2）
- 受访者入坑经历：1990 年代末在 Western Digital 的分包商处支持一套专跑 FreeBSD 的硬盘物流系统，除物理盘故障外从未出现问题，其设计被其评价为优雅；此后试用 Linux 因不满 Red Hat 包管理而 FreeBSD ports 从未让他出问题，遂固定使用 FreeBSD 至今。（BSDTalk EP10，[127.86-189.50]，L1）
- 部署概况：加州 Fullerton 学区推行一对一笔记本计划，每名学生配一台底层运行 Darwin 的 Apple iBook，FreeBSD 承担控制全部 iBook 的后台服务器角色；BSD 只作服务器用途、不部署桌面（避免 KDE 等员工培训成本），完全占据服务器机房与各站点计算机；加州教育经费长期紧张，主要靠捐赠设备，BSD 装在捐赠旧硬件上整合入网，形成有钱买 Apple、没钱装 FreeBSD 的弹性组合，两者互操作良好。（BSDTalk EP10，[190.32-261.62]，L1）
- 可管理性与灾备设计：技术部门仅四人，以 OpenLDAP 集中管理全部学生笔记本的权限与账户，且刻意保持 Apple GUI 工具可直接管理 Intel 硬件上的 LDAP，使日常管理无需专家在场；针对管理层被公交撞了网络怎么办的追问，受访者以 sysinstall（其 man 页自认不应再存在）开设安装培训课，并为每台机器编制三环活页夹（配置文件与已装包清单），保证文字资料足以重建系统。（BSDTalk EP10，[283.38-405.98]，L1）
- 运维可靠性与旧硬件性能：以无 GUI 的 cvsup 经 cron 定期更新，除非重大安全问题不强制升级；一台 FreeBSD 4.0 机器在仓库执行简单任务已连续运行数年而无需到场维护；跨版本升级不难，3.x 手册已不再推荐 buildworld 而有二进制升级建议，最坏情况重装并迁移配置文件即可。BSD 可跑低配硬件是其关键优势：一台 Pentium 3 为 1200 台笔记本提供名字服务并承担 7 个 VLAN 的 DHCP，处理器利用率从未低于四成仍稳定运转；FreeBSD 的 PowerPC 支持规模有限，NetBSD 对 PowerPC 的支持成熟得多，学区借此复活大量退役 PowerPC Mac 与 Intel 捐赠机并用。（BSDTalk EP10，[406.58-660.80]，L1）
- Apple 对比与安全管控：若资金充裕，前端设备仍会保持 FreeBSD，阵列存储会选 Apple 因其界面简单；Apple 整机溢价换来后端与笔记本皆不受病毒蠕虫侵扰，省下的运维开支转投学生教育软件。对学术环境是否对网络抱敌意的问题，受访者称学生总体守规矩，曾抓到安装包嗅探程序者，但 OpenLDAP 目录结构将 Apple 笔记本锁定为只能启动事先授权的应用，下载程序即使在其用户空间内也无法获得执行许可。全套服务均构建于 FreeBSD：对外 VPN（可携带分支办公室，用 Stunnel）、RADIUS 认证、Squid 加 SquidGuard、学生行为监控的 LDAP 认证、面向业务办公室的 Samba 文件共享与面向 Apple 客户端的 Netatalk。（BSDTalk EP10，[503.50-701.10]，L1）
- BSDCan 由 Dan Langille 于 2004 年在渥太华创办，直接动因是他结识 Ottawa Linux Symposium 的组织者后认为对方能办成的事自己同样能办成；首届约一百七十余人与会，2005 年约两百人，2006 年预期再增约一成，论文约二十四场分布在两天；正式会议前两天附设 FreeBSD 开发者峰会，第二届延续举办，被视为 FreeBSD 社区支持该会议的标志。（BSDTalk EP14，[481.79-596.82]，L1）
- 渥太华会址具有结构性优势：部分欧洲与会者因赴美参会门槛而选择加拿大，汇率又使北美与会者获益，纽约受访者称往返加四晚住宿的全部开销低于在纽约参加一场会议；面对 BSD 已死的流言，Langille 以持续增长的参会人数与各项目论文供给作为否证。（BSDTalk EP14，[598.64-641.44]，L1）
- 会议论文呈项目间不均衡分布：FreeBSD 篇目最多，NetBSD、DragonFly BSD 与 OpenBSD 依次递补；OpenBSD 多于 NetBSD 的现象被归因于 NetBSD 开发者多困于项目事务、无暇赴会，而 OpenBSD 核心成员多居加拿大且其大型开发者聚会在 BSDCan 前数周举行，形成人员顺势转场的路径。（BSDTalk EP14，[739.21-795.58]，L1）
- 主持人梳理 2006 年 BSD 桌面化的法律与技术障碍：商业软件授权普遍禁止随免费系统再分发；MP3 格式在美国受专利约束，随系统免费分发的编解码器无法支付按设备计的授权费；Windows Media 等格式受数字版权管理封闭；BSD 虽能以 Linux 模拟层运行部分商业软件但兼容性参差，Java 近乎原生却缺乏 Sun 提供的简易安装器；结论是 BSD 的主战场仍在服务器。（BSDTalk EP14，[97.11-263.26]，L2）
- 开源作为硬条件的形成史：受访者自 4.1c BSD 起接触，历经 4.3 前后的全源码工作环境；工作场所转用 SunOS 3.x 后数年无源码的挫折使其确立信条——不给源码的操作系统一概出局；其后为手中 SPARCstation 寻觅系统时，NetBSD 是其所能找到的唯一可运行于该硬件的开源 OS，自此与 NetBSD 缔结十余年关系。（BSDTalk EP45，[500.60-546.32]，L1）
- 可移植理想的个人实测：其日常使用 SPARC、i386 与 Sun 3 三种架构，MacPPC、Mac68k、Alpha 机器则定期开机构建软件以验证可移植性，next68k 与 Vax 属半弃用状态——合计 8 个 ports 跨 6 种 CPU 架构；这一私人机队将 NetBSD 的多架构承诺落实为日常运维实况。（BSDTalk EP45，[430.64-494.52]，L1）
- 版本策略与使用习惯呈两轨：自有机器长年运行基于 NetBSD 1.4T 断续修改的私人分支，工作机器则跟进 2.0、3.0 等较新版本；桌面以 SPARCstation 跑 X，但屏幕内容几乎只有文字与几个时钟——名义上的图形环境实为命令行工作流的容器。（BSDTalk EP45，[552.08-616.76]，L1）
- 对专有系统保持工具性距离：曾动念装 Windows 运行媒体中心类软件而终未成行；偶尔在隔离机器上安装 Solaris 等厂商系统以验证硬件本身完好，作为撰写 FreeBSD 驱动时的排障参照；其原则是离开开源便做不到的事一般索性不做。（BSDTalk EP45，[628.44-680.06]，L1）
- BSDCan 2006 的与会观察：整体氛围与前一年相仿而更熟稔；其判断技术会议的最大价值不在正式报告而在走廊与社交场合的相遇；论文分布上 FreeBSD 占据主导、OpenBSD 居次、NetBSD 沦为陪跑——他对此不满，但认为出路只在社区投出更多 NetBSD 论文，别无他法；各项目提交者间未见特别的跨项目社交混合。（BSDTalk EP45，[124.46-200.36]，L1）
- 工具谱系的守旧与偏爱：C 为其使用最多之语言，但严格说是 GCC 加自身扩展的方言；编辑器为 1980 年代起自维护至今的 Gosling Emacs 老变体；若论最爱编程环境，则是在曾供职实验室的 Lisp 机器上的 Lisp 系统胜过一切。（BSDTalk EP45，[680.06-730.62]，L1）
- BSDCan 2006 复盘：第三届、新场地第二年，组织较前两年从容，组织者本人甚至能一天听四场报告；与会者逾 210 人（高于预期的 180 至 190，日注册数待核）；来源分布为加拿大约 140 人、美国 73 人、日本 6 人、欧洲十余至二十人，合计 14 个国家与 18 个美国州；讲者质量与会者反馈俱佳，会前数周已启动 2007 年筹备。（BSDTalk EP47，[151.24-207.08]，L1）
- 论文征集的结构性困难：程序委员会由各主要项目成员构成，职能是主动征稿与催稿、力求各项目论文均衡；NetBSD 与 OpenBSD 的投稿历来来者皆收却仍不足额——症结在于社区成员不主动投稿；2007 年拟增设 userland 演讲轨道，将讲者扩展至 BSD 开发者与用户之外。（BSDTalk EP47，[238.88-278.72]，L1）
- 演讲者经济模式：讲者或自费、或由雇主承担（雇主随后以赞助者身份获致谢）；组织方尽量补贴住宿与差旅，FreeBSD Foundation 及其他团体时有相助；但坚持不向讲者付酬——付酬将构成在加拿大境内工作，触发移民法障碍，这一约束在跨国学术会议组织中具有决定性。（BSDTalk EP47，[278.72-325.92]，L1）

- Dan Langille 系居渥太华的软件开发者，1998 年起投入 FreeBSD：运营 FreeBSD Diary（大量 how-to 指南集）与 FreshPorts（百分之百自动化、解析 CVS 提交日志构建数据库，定位为 FreeBSD ports 树的 Freshmeat），并创办在渥太华举办的 BSDCan 会议——受访时第三届年会刚结束，2007 年将办第四届；节目新闻时段并提及 FreeBSD 6.2 首个 beta 发布。（BSDTalk EP67，[73.4-136.68]，L1）
- 传统备份工具的边界：dump 被广泛认为最可靠，但仅适于同文件系统往返、跨系统跨磁盘并不可移植；tar 的选项随操作系统而异，跨平台恢复易出问题；rsync 提供镜像并可有快照工具，但替代不了专用备份，受访者仅以之同步大文件再另行备份；少量文件用 SSH/SCP 尚可，规模化的定时备份则需完整方案。其个人起点是每日 cron 任务打包 tar 并 SCP 到中央服务器，可用但在按时间点取回文件时笨拙且磁盘空间告罄——背景是其从惠灵顿迁回渥太华后仍须经互联网备份留在新西兰的机器，遂评估 Amanda，部署过半时经 IRC 他人建议改看 Bacula，因其优点足以令其弃用尚未部署完的 Amanda，入门首事即为 Bacula 编写适配另一数据库的代码。（BSDTalk EP67，[147.4-415.84]，L1）
- Bacula 架构：director 全局调度并取代 crontab，file daemon 安装于每台待备份机、以 root 运行并真正执行备份，storage daemon 落盘数据且对磁带、磁盘、DVD、CD 一视同仁，catalog 以数据库记录各任务备份的文件清单，console 供管理员与 director 通信；四组件加 console 全部经 TCP/IP 互语、可分布于不同机器，便于以高速数据库机与高速归档机组网；file daemon 以共享密钥认证且密文不再明文传递，当期版本已支持传输加密、下一版将加存储加密；系统为 UNIX 而作，Linux、FreeBSD、NetBSD、OpenBSD 可运行，另有 DragonFly BSD 讨论、Mac OS 与 Windows 客户端，且已有开发者把 director 与 storage daemon 移植到 Windows 使服务器端完整可用（尚未到生产级）。（BSDTalk EP67，[381.72-738.9]，L1）
- 恢复与目录机制：卷内数据格式为自定义的“专有但公开”格式（非 dump 亦非 tar），目的是平台无关，使 Solaris 与 FreeBSD 等文件系统之间互转无碍；即便整套 Bacula 尽毁，仅凭 bextract 命令行工具即可从卷中抽取数据；最佳实践是每夜备份后同时备份 catalog，恢复时先还原 catalog 再按索引取任意卷内容，若无索引也可从卷重建目录（过程漫长）；FreeBSD port 开箱即用，默认月初全量、周五增量、其余日差分（受访者自承或记混增量与差分的次序），另有完整调度语言与新版的 migration job（先备到磁盘池再迁移到磁带池）；恢复作业可改写目标客户端与路径，社区即以此完成旧服务器到新服务器的应用迁移；catalog 起初支持 SQLite 或 MySQL，受访者加入后第一时间编写 Postgres 插件，DB2/Oracle 亦只需写插件即可；GUI 方面只有恢复与监控的零散工具，无一体化 GUI，其本人以 Bacula Web 监控、以 b-console 命令行为主力；许可证为略有修改的 GPL2。（BSDTalk EP67，[742.34-1203.02]，L1）
- 笔记本备份难题与路线图：当前 file daemon 无法主动发起备份，变通方案是给客户端受限 console 并以启动脚本等待网络连通后调起作业；file daemon 发起式备份列为项目待办第六项，前五项大多将随下一版本发布；受访者本人以一台 Bacula 服务器每日备份约十台服务器，其中八台在家、两至四台经互联网以 OpenSSL 保护的不可信网络完成。（BSDTalk EP67，[1203.02-1283.46]，L1）
