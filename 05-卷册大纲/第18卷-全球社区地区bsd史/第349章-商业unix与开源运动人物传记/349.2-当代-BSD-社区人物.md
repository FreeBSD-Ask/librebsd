**要点**：

- devio.us 是运行于 OpenBSD 的免费 Unix shell 服务，至受访时约五年历史，除 shell 托管外还提供网站、电邮与 Gopher 接入，自定位为 OpenBSD 上的社交空间；Brian Callahan 补充其教学动机：Unix 课程中学生用虚拟机只能见到自己，而在共享 shell 机器上键入 who 能看到他人在线、可共同游戏，账户的社区维度是虚拟机无法替代的。（BSDTalk EP252，[136.32-203.08]，L1）
- devio.us 的注册模式以人工审核为核心：申请者须先到 Freenode IRC 频道自我介绍并说明用途，管理员逐条阅读每份申请并手动点击接受或拒绝，存疑者由管理团队讨论后裁定；这一流程过滤了约八成的麻烦与恶意行为，但并非完美，仍有人试图骗过审核。团队全员另有全职工作、义务兼职运营，故日常例务尽量自动化，唯注册审核坚持人工。（BSDTalk EP252，[239.46-385.98]，L1）
- 账户制度与规模：注册即终身有效，仅违规遭封禁才注销；申请接受率约三分之一至四成，累计拒信逾万、在册账户约 5700 个；免费账户提供 100 MB 存储并可付费约每月 2 美元升级至 1 GB，付费账户另可 detached 运行进程——后台守护进程监控登录状态，免费用户 detached 超过 5 分钟即被清理进程。（BSDTalk EP252，[399.88-487.06]，L1）
- 硬件极简佐证 shell 负载之轻：devio.us 全部服务运行于单台机龄约十年的四核 Xeon、2 GB 内存服务器（创建服务时它已是旧机器）；当事人此前为学生架设的 shell 机是一台 486，128 MB 内存即支撑 25 个并发用户——纯 shell 接入对资源需求极低，一台旧机器安放数据中心即可自足运转。（BSDTalk EP252，[581.16-633.14]，L1）
- devio.us 与 OpenBSD 开发的互动方向并非由运维问题反哺系统修复，而是把当事人新写、尚未提交评审的 port 先部署到 devio.us，让自己与用户先行试用、观察生产表现，之后再送 ports 邮件列表评审入库——shell 服务实际充当 ports 的准生产试验场；日常系统更新则依赖 M:Tier 的二进制补丁跟踪 -stable 并附带 ports 二进制包，避免在低速机器上自编译，这对 OpenBSD 支持的小型设备尤具价值，也是全员兼职团队的现实选择。（BSDTalk EP252，[634.32-755.02]，L1）
- 桌面倡导：当事人名下所有机器均运行 OpenBSD，且自 2011 年前后以其为唯一操作系统，自认实践“自食其力”的项目文化，桌面场景如浏览器、视频与文档编辑皆可胜任；作为 porter，其维护的 ports 以面向最终用户的桌面应用为主，理由是良好的桌面体验能吸引人把 OpenBSD 带入工作场合展示，从而降低管理层决策采纳的门槛。（BSDTalk EP252，[775.34-843.02]，L1）
- Joshua Stein 自述约 1998 年起使用 OpenBSD，先用其运行 BBS，继而制作 ports 并由其他开发者提交合入；2000 年起运营 RT.fm OpenBSD 镜像并向开发者捐赠硬件；在一家互联网服务商任职期间引入 OpenBSD 替换 Linux 与 OpenVMS 服务器；2001 年获得提交权限，此后以编写驱动等零散工作持续参与。（BSDTalk EP263，[73.12-128.72]，L1）
- Brandon Mercer 自述大学期间（约 2000 年）因 OpenBSD 的安全声誉入门，将其部署为 Web 服务器与防火墙并作为桌面使用；以捐赠硬件支持项目，后从硬件侧入手尝试让 OpenBSD 跑上 ARM，与开发者协作顺畅，获邀参加 hackathon 后正式进入项目，此后持续专注于 ARM 方向。（BSDTalk EP263，[129.46-236.90]，L1）
- 两人均以 OpenBSD 为个人与工作的主力桌面并运营大量服务器；对即将发布的 5.9 的期待包括 EFI 引导支持使其可装上新式仅支持 EFI 的笔记本（Joshua 为自己的新机型编写了 i2c 相关驱动）、网络栈改进与显卡支持；并反驳外界“OpenBSD 硬件支持匮乏”的印象，认为笔记本安装体验已相当顺畅。（BSDTalk EP263，[236.90-378.98]，L1）
- 两人于 2015 年 10 月创办每周五更新的音频播客 Garbage（garbage.fm），定位为坦诚抱怨软件开发现实、呈现企业世界之外的真相，其名言式立场是“技术几乎都是垃圾，而且正在让你的生活更难”；受众为 OpenBSD 开发者、最终用户乃至非 OpenBSD 用户；制作上以 Skype 对录、Audacity 剪辑（因高 DPI 屏幕显示问题在 Mac 上完成），Brandon 把完全在开源 BSD 系统上制作播客列为个人挑战，基于浏览器的录音服务已可在 OpenBSD 的 Firefox 上运行。（BSDTalk EP263，[397.86-737.10]，L1）
- Selasky 自述十二三岁在挪威与朋友用 QBasic 合写小游戏，因买到的商业图形工具包与其显卡不兼容且遭拒退而转向自由软件；循 X11 驱动发现 FreeBSD 后，用 Windows 95 机器经 ISDN 以软盘逐张下载 FreeBSD 3.4 全部发行版，逐盘校验坏扇区，最终在 486 级 233MHz、32MB 内存的机器上完成安装；靠 PDF 文档自学 shell，首个编辑器是 ee 而非 vi 且沿用至今。（BSDTalk EP267，[158.24-391.94]，L1）
- 因 FreeBSD 缺少其 ISDN 适配器的驱动，他结识多年为 FreeBSD 编写 ISDN 驱动的汉堡开发者 Helmut Michaelis（项目 ISDN for BSD，即 i4B）；研读代码后为德国 Cologne Chip 的 HFC 卡写出首个 ISDN 驱动——该厂罕见地公开芯片文档；继而认为 i4B 其余部分过度设计且含缺陷，重构欧洲通行的 DSS1/Euro-ISDN 信令，产出完整但非增量的补丁集，终未被 FreeBSD i4B 接受；他回顾认为拒收是正确决定，因为那是他第一个大型 C 项目。（BSDTalk EP267，[391.94-545.82]，L1）
- 为同时维护十三至十五张 ISDN 卡驱动并应对频繁的 API 变更，他发明“宏布尔”技术：以保留或吞掉参数表达真伪的 yes/no/not 三宏构成比较电路，一个头文件即可切换各卡代码路径，改动只需一处；项目团队普遍不喜欢宏，且他先写码后补风格、挨过繁重评审，因而建议新人先读 man style(9) 再投稿。（BSDTalk EP267，[545.82-745.04]，L1）
- 进入 USB 领域源于想支持 ISDN USB 适配器，恰逢 FreeBSD 从单处理器中断优先级架构转向多处理器互斥锁架构：为让 ISDN 栈摆脱 Giant 锁，必须先有 Giant-free 的 USB 栈；他发现旧栈回调前无引用计数、回调直接在中断处理器内执行且会阻塞其他中断处理，新栈因此引入引用计数与 start/stop/drain 三函数 API（受 callout API 启发），并把回调从中断上下文改为通知独立进程执行，显著改善 SMP 扩展性；当时正处在合入 FreeBSD 8 的提交流程中。（BSDTalk EP267，[747.34-981.10]，L1）
- 性能方面：大容量存储实测新栈与 Linux 相当、旧栈落后约百分之二至五；USB Ethernet 提升显著，关键在 USB IO 向量——可排队多个以太网帧、末尾仅一次中断，突破主机控制器每秒一千至八千次的中断率瓶颈；相较 Linux 的 pumping 方案，他选择变长 IO 向量以降低内存与系统调用开销，且支持控制传输分段（Linux 亦无）；并补齐 FreeBSD 5/6/7 在高速外置集线器下缺失的 isochronous 传输，使摄像头与音频设备得以工作；该栈已移植 NetBSD，或有一日进入 OpenBSD 与 DragonFly，另经 FreeBSD 模拟层运行于非 BSD 平台且性能不逊专业 USB 栈。（BSDTalk EP267，[981.10-1409.36]，L1）

**史观**：

- 总纲10 动手者创造历史：当事人自述其路径：2011 年以学生身份注册 devio.us，初衷只是寻找存放 diff 文件之处，这些文件后来演为其最早的 ports 工作，并由此成为 OpenBSD 开发者；从共享 shell 上的动手者到 port 维护者再到开发者，社区服务的免费账户成为人才与贡献的实际入口，历史由这些在终端里默默动手的人层层累积而成。（BSDTalk EP252，[220.94-236.24]，L1）
- 总纲10 动手者创造历史：两位当事人的进入路径都不是申请与遴选，而是动手积累：做 ports、捐硬件、跑镜像、写驱动、移植 ARM，贡献被社区看见后才经 hackathon 邀请正式入圈——在 OpenBSD 的社区文化中，开发者身份由实际贡献而非资历或组织任命换取。（BSDTalk EP263，[87.16-236.90]，L1）
- 总纲9 经验优先：Garbage 播客的方法论是经验对抗宣传：内容取材于两人每周实际动手所见，指认 Web 框架的虚假宣传、谈论企业话语之外的真实使用感受，Brandon 强调“没有人谈论企业世界之外的现实”，以此让听众知道自己并非唯一对某工具不满的人——一手使用经验成为社区认知的校准基准。（BSDTalk EP263，[433.46-563.10]，L1）
- 总纲10 动手者创造历史：Selasky 的路径完全由动手实物驱动：为打游戏找驱动、为上网写 ISDN 驱动、为甩掉 Giant 锁重写 USB 栈；他对少年听众直言“年龄不是问题”，买一块适配器、一把电烙铁就能入门。同一个先后被 i4B 拒收、又被 FreeBSD 8 接纳新栈的作者，其历史位置由可运行的代码而非资历或评审好感决定。（BSDTalk EP267，[1682.20-1706.84]，L1）
