# 331.9.7 麒麟操作系统 FreeBSD 代码承袭与 BSD 许可证合规性考据

**要点**：麒麟操作系统 1.0 由国防科技大学牵头研制，2002 年立项，作为“十五”国家 863 计划“服务器操作系统内核”重大专项产物发布，其内核基于 FreeBSD 5.0；2006 年 Dancefire 在博客园发布的三篇技术分析通过 `strings` 命令对比 `libpthread-kyth.so` 与 FreeBSD `libpthread.so` 源文件列表，确证 Kylin 2.0 与 FreeBSD 5.3 高度相似，相似度超过 60%。
麒麟官方 2006-02《关于银河麒麟操作系统的说明》经历从“完全自主知识产权”到承认“系统服务层从 SVR4.2 升级到 FreeBSD 5.0”的表态退守；2.0 版本被指在二进制分发与文档中未复现 FreeBSD 项目版权声明，2.1-01 版本被动添加版权声明但通过 `strip` 与引导修改规避相似性分析，BSD 第 2 条 attribution 义务履行存在形式合规而实质规避的争议。
Kylin 3.0（2009）转向 Linux 内核后 FreeBSD 主线承袭退出，但早期代码以历史遗留形式延续的比例因源代码不公开无法精确量化；FreeBSD 社区与海外技术媒体对此事件整体沉默，仅中文社区形成热议。

**史观**：项目史观总纲第 9 条“经验优先”——Dancefire 通过 `strings` 命令提取二进制字符串进行源文件列表对比，是经验优先原则在民间考据中的典型实践，不依赖官方宣称而以反汇编输出为依据，使“完全自主知识产权”的话语建构在经验证据面前崩塌。
总纲第 2 条“历史是形式主义化的非存在”——“60% 相似度”“完全自主知识产权”“系统服务层使用 FreeBSD”等表述均为形式主义化的建构，其“存在”依赖于话语权力的承认；麒麟官方删除网站“自主知识产权”内容的形式主义动作反而确证了承袭关系。
总纲第 3 条“不存在进步，只有权力再分配”——麒麟事件不是技术进步的自然产物，而是 863 体制资源分配、政府采购市场、FreeBSD 社区权益三方权力再分配的冲突；Kylin 3.0 转向 Linux 内核亦非技术优胜劣汰，而是“核高基”专项与“信创”政策下体制资源再分配的结果。
总纲第 7 条“理论必须自反”——“完全自主知识产权”理论若不自反即沦为宣传口号，须以代码与文档实物反验宣称；本节考据承认对 Dancefire 结论的采信本身存在形式主义风险，对“违反 BSD 第 2 条”的判定因缺乏 ISO 实物直接鉴定而保留存疑。
总纲第 11 条“商品是形式主义”——麒麟作为政府采购导向的商品，其市场地位由“国产”形式主义标签与 863 验收指标决定，而非由代码实际来源决定；BSD 许可证允许使用与“国产”叙事的张力不在使用本身，而在 attribution 义务对形式主义合规的最低要求。
总纲第 13 条“法律与道德是利益分配”——BSD 第 2 条表面是中性的法律条款，实质是版权持有人与分发方之间的利益分配契约；麒麟案牵涉 FreeBSD 社区权益、863 验收标准、国防科研经费分配三方利益冲突，“自主可控”叙事本身即是利益分配的形式主义包装。
总纲第 19 条“解释学循环是历史认识的根本条件”——Dancefire 反汇编证据与麒麟官方表态演变构成解释学循环，二者相互阐释，最终指向承袭关系的确证；FreeBSD 社区与海外技术媒体的“双重整体沉默”亦须在 BSD 许可证哲学与英语中心主义的前理解中解释，不能简单等同于“无反响”。
总纲第 20 条“历史地理塑造思想土壤”——2004-2006 年中国“自主创新”国家战略与“国产操作系统”叙事的特定地缘政治土壤塑造了“完全自主”宣称的政治必要性，英语技术媒体对非英语世界事件的覆盖盲区亦根植于语言与地理土壤。
**辨析**：Dancefire 分析的方法论局限方面，2006-05-15 的 `strings` 对比是经验层面的硬证据——`libpthread-kyth.so` 未被 `strip`，其内部字符串表保留完整源文件路径列表，与 FreeBSD `libpthread.so` 源文件列表一一对应（仅前缀 `/root/kyth1.6/` 与 `/usr/src/lib/libpthread/` 不同，文件名 `thr_cancel.c`、`thr_cond.c`、`thr_create.c` 等完全一致），难以用“独立开发巧合”解释；但 2006-04-27 原文中“相似度超过 60%”“函数名相似度 99.45%”等百分比的具体计算方法因原 CSDN 链接失效未能直接核验，仅能作为媒体引述保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］。Dancefire 作为 C 类社区来源，其结论须与 B 类学术论文或 A 类源代码交叉验证后方可采信，截至考据基线日未检索到 IEEE Xplore、ACM Digital Library、知网（CNKI）中关于 Kylin 源代码比对的同行评议学术论文。
麒麟官方表态演变方面，2004 年 1.0 发布期至 2006 年 2 月前完全否认承袭；2006 年 2 月《说明》将承袭范围限定为“系统服务层从 SVR4.2 升级到 FreeBSD 5.0”；2006 年 4 月 Dancefire 分析发布后官方“偷偷将网站内有关麒麟拥有自主知识产权并独立研发的内容完全删除”；2006 年 5 月 2.1 版本在版权声明前加“在系统服务层的部分代码中使用了 FreeBSD”的限定语；2007 年 3.0 后转向 Linux 内核，承袭关系淡化。这一“从完全否认到最小化承认”的渐进退守轨迹本身即是对承袭关系的间接承认，符合解释学循环——承袭证据越确凿，官方表述越收敛；但“系统服务层”的限定语与 Dancefire 反汇编证据（相似性不限于“系统服务层”）存在表述差距，构成对承袭范围的虚假陈述嫌疑。
BSD 第 2 条合规性判定中的存疑事项方面，BSD 2-Clause 与 3-Clause 第 2 条均要求"Redistributions in binary form must reproduce the above copyright notice, this list of conditions and the following disclaimer in the documentation and/or other materials provided with the distribution"，即二进制分发须在文档和/或其他随附材料中复现“版权声明 + 条件清单 + 免责声明”三件套；据 IT168 报道引述，2.0 版本“没有任何地方显示了 Copyright FreeBSD Project，包括文档和程序”，“在内核输出也没有显示 FreeBSD 的版权声明”，若属实则明确构成对第 2 条的违反；但因未直接核验 2.0 版本 ISO 实物，违反判定保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］——所指证据为媒体引述与当事人分析，非 ISO 实物鉴定。2.1 版本形式上添加版权声明满足字面要求，但若仅添加版权声明而未完整复现条件清单与免责声明三件套，仍构成部分违反；具体是否完整复现保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］——需核验 2.1 版本实物版权声明全文。Kylin 3.0/4.0/5.0/6.0/7.0/V10 各版本因源代码不公开，承袭比例无法精确量化，attribution 合规性需后续考据补充实物证据；V10 全面转向 Linux 内核与 Ubuntu 参考，若已完全切断 FreeBSD 承袭则第 2 条不再适用，但仍承袭 FreeBSD 用户态工具或驱动代码的可能性须核验 `/usr/share/doc/*/copyright` 许可证清单。
FreeBSD 社区与海外技术媒体的“双重整体沉默”须谨慎解读：BSD 许可证的设计允许代码使用与修改，从纯许可证角度麒麟使用 FreeBSD 代码不构成“侵权”，故 freebsd-hackers、freebsd-advocacy 等列表未发现系统性讨论，FreeBSD Foundation 与核心成员（Kirk McKusick、Poul-Henning Kamp（波尔-亨宁·坎普）、Jordan Hubbard 等）亦未发表官方表态；七家海外技术媒体（Phoronix、OSNews、LWN、Slashdot、Ars Technica、The Register 及 Hacker News）均未检索到麒麟事件专门报道，反映英语中心主义对非英语世界事件的结构性盲区。这一沉默不构成对麒麟 attribution 违规的无罪推定，仅反映 BSD 文化“轻契约重信用”的执行软约束与英语技术媒体的覆盖盲区；中文社区的主要反响载体是 Dancefire 技术博客、月光博客 FreeBSD 被封调查与 CSDN 社区讨论（仅作线索不采信），形成“中文社区热议、英语社区沉默”的非对称格局。
