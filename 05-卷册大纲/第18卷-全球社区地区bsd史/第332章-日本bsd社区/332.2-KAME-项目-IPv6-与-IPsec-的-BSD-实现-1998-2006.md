## 332.2.1 KAME 项目的发起与组织

  **要点**：KAME 项目 1998 年由 Jun-ichiro itojun Hagino（Keio 大学）、Shoichi Sakane（Yokogawa Electric）、Yoshinobu Inoue（Toshiba）等人发起，得到日本通信综合研究所（CRL）与 WIDE 项目资助，是日本学术界对 BSD 最具影响力的贡献。KAME 名字取自 “KAME”（龟），象征 “龟虽慢但稳”，与 IPv6 的长期部署目标相呼应。

## 332.2.2 IPv6 协议栈的 BSD 实现

  **要点**：KAME 项目在 FreeBSD、NetBSD、OpenBSD 上实现了完整的 IPv6 协议栈，包括邻居发现协议（NDP）、地址自动配置（SLAAC）、IPv6 over IPv4 隧道、多播侦听器发现（MLD）等。KAME 的 IPv6 栈成为 Linux 以外最成熟的 IPv6 实现之一〔订正：原“2002-2004 年逐步合并（FreeBSD 4.0 起）”时间自斥，FreeBSD 4.0-RELEASE 为 2000 年 3 月且已含 KAME IPv6/IPsec 栈，现按 4.0=2000-03 为基准重述〕。KAME 的 IPv6 代码自 FreeBSD 4.0-RELEASE（2000 年 3 月）起即合入 FreeBSD src tree（4.0 已随附 KAME IPv6/IPsec 栈），其后至 2004 年前后随各 FreeBSD 版本持续演进更新，KAME 的 IPv6 栈成为 Linux 以外最成熟的 IPv6 实现之一。

## 332.2.3 IPsec 实现与安全贡献

- Jinmei Tatuya 自述其 KAME 项目共同开发者身份：项目 1998 年启动、2006 年 3 月结束；虽已不再活跃开发，其代码已成为各 BSD 变体的固有组成部分。KAME 定位为 IPv6 参考实现，以开源形态拥有庞大且能干的开发者群体，这正是 Wind River 为 VxWorks 6.0 选定 KAME 作为核心 IPv6 代码的依据。（BSDTalk EP112，[56.92-70.64, 114.76-123.0, 391.28-417.88]，L1）
- Qing Li 完整叙述了书籍工程的起源与经过：2000 年初其在 Wind River Systems 完成 KAME 向 VxWorks 的移植（后发布于 VxWorks 6.0），积累了关于 KAME 实现、数据结构、图示与函数关系的海量笔记，遂决意为 KAME 写一部 Stevens《TCP/IP Illustrated》第二卷式的书，动机兼有自用与自我保存笔记之意；经 itojun 引荐 Jinmei、再由 Jinmei 引荐 Keiichi Shima 组成三人作者团队。项目原计划九个月，因覆盖范围不断扩展，最终耗时近三年半，单卷计划扩为两卷：《IPv6 Core Protocols Implementation》于 2006 年 10 月出版，《IPv6 Advanced Protocols Implementation》于 2007 年 4 月出版，均由 Morgan Kaufmann 发行，英文版之外日文版已在制作中。　[存疑脚注] 转写将引荐人记作“Yuto Jin”，按语境应为 itojun（Jun-ichiro Itoh Hagino）；“two bees at the time”疑为其时任职公司的误转（BSDTalk EP112，[127.66-199.16, 168.04-199.16, 254.86-283.98]，L1）

- IPsec 是作用于 IP 层的安全协议族，最常见用途是建立加密 VPN 隧道；它需要预先配置安全关联，适合端点已知、由网络管理员维护的企业组网，而端点数增长时隧道连接数按 n 乘 n 减一除二快速膨胀；相比之下 SSL 运行于 TCP 之上、依托信任网与证书可与陌生方建立加密，更适合客户端对服务器的 web 业务，两者是场景分工而非替代关系。（BSDTalk EP121，[52.44-307.08]，L1）
- IPsec 与 IPv6 的标准化在九十年代中期并行交织，IPsec 被视为 IPv6 的组成要求；KAME 项目在实现 IPv6 协议栈的同时实现了 IPsec，包含仅做认证的 AH、认证并加密且最常被使用的 ESP，以及严格说并非安全协议却被纳入规范集的 IPComp 压缩协议；这套代码于九十年代中期随 KAME 投放一并进入 FreeBSD 与其他各 BSD。（BSDTalk EP121，[84.76-207.84]，L1）

- 总纲4 分离聚合是永恒规律：KAME 项目作为日本联合研发体完成 IPv6 与 IPsec 实现的历史使命后宣告终结，其代码分离散入各 BSD 并在 FreeBSD 内独立演化，原开发者又以个人身份重新汇入 FreeBSD 开发；一个有边界的项目组织解散后，其技术生命以代码与人的再聚合方式延续。（BSDTalk EP121，[446.66-569.74]，L1）

**辨析**：

- 关于 IPv6 推广的阻碍，itojun 的判断是：厂商端已无障碍——Windows Vista、Mac OS X 与各路由器厂商均已支持 IPv6，且 Juniper 的实现即源自其阵营代码；唯一的阻碍是 IP 从业者与公众缺乏理解，而普通用户只输入 URL 与邮件地址，完全可在无感知中完成 IPv4 到 IPv6 的过渡。其本人的极端实践佐证可行性：日常完全不用 IPv4，访问 Google、Amazon 等 IPv4-only 服务时经 RFC 3142 所述的传输中继转换完成；并指出 APNIC 管辖的亚洲区域地址分配政策远较北美严苛（北美易得整段 B、C 类地址），其自费高额月费的光纤接入仍无原生 IPv6，正持续向 ISP 施压。　[存疑脚注] 其光纤资费与带宽表述转写混乱（“100 million of VPS fiber... only get just $29”），具体数字不可确证（BSDTalk EP115，[290.62-343.42, 467.42-517.22]，L1）
- 他对新代码安全性的自信建立在近一年业余时间的断续审查之上，并自认未做过完整安全审计；同时 FreeBSD 近期未参加跨厂商 IPsec 互操作测试，interop 费用高昂且争取基金会资助困难，互操作性主张缺乏多源验证；其关于一家公司拟将代码集成进下一代产品的说法亦属不具名单一来源。　[存疑脚注] 生产可用性与互操作性均为当事人自评，须待后续安全公告与互操作报告验证。（BSDTalk EP121，[601.74-772.14]，L4）
