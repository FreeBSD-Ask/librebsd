# 332.6 日本 BSD 出版物与翻译

## 332.6.1 FreeBSD 相关日文书籍出版史

  **要点**：日本 BSD 出版物包括《FreeBSD 徹底入門》（1997 年初版，ASCII 出版）、《FreeBSD システム 管理》（1999 年，オライリー・ジャパン）、《FreeBSD ハンドブック》日文翻译版（2000 年起由日本 FreeBSD 社区翻译）。日文 BSD 书籍的出版方包括 オライリー・ジャパン（O'Reilly Japan）、ASCII、秀和 システム、技術評論社等

**要点**：

- Jinmei Tatuya 自述其 KAME 项目共同开发者身份：项目 1998 年启动、2006 年 3 月结束；虽已不再活跃开发，其代码已成为各 BSD 变体的固有组成部分。KAME 定位为 IPv6 参考实现，以开源形态拥有庞大且能干的开发者群体，这正是 Wind River 为 VxWorks 6.0 选定 KAME 作为核心 IPv6 代码的依据。（BSDTalk EP112，[56.92-70.64, 114.76-123.0, 391.28-417.88]，L1）
- Qing Li 完整叙述了书籍工程的起源与经过：2000 年初其在 Wind River Systems 完成 KAME 向 VxWorks 的移植（后发布于 VxWorks 6.0），积累了关于 KAME 实现、数据结构、图示与函数关系的海量笔记，遂决意为 KAME 写一部 Stevens《TCP/IP Illustrated》第二卷式的书，动机兼有自用与自我保存笔记之意；经 itojun 引荐 Jinmei、再由 Jinmei 引荐 Keiichi Shima 组成三人作者团队。项目原计划九个月，因覆盖范围不断扩展，最终耗时近三年半，单卷计划扩为两卷：《IPv6 Core Protocols Implementation》于 2006 年 10 月出版，《IPv6 Advanced Protocols Implementation》于 2007 年 4 月出版，均由 Morgan Kaufmann 发行，英文版之外日文版已在制作中。　[存疑脚注] 转写将引荐人记作“Yuto Jin”，按语境应为 itojun（Jun-ichiro Itoh Hagino）；“two bees at the time”疑为其时任职公司的误转（BSDTalk EP112，[127.66-199.16, 168.04-199.16, 254.86-283.98]，L1）
- 关于书籍定位，两位作者说明其差异化设计：全书面向开发者、以逐行代码注释为主体，每章固定三节——RFC 与规范摘要、带注释与图解的实现剖析（体例类比 Stevens 著作）、KAME 工具用法；成书前的市场调研发现市面已有四五种 IPv6 书均偏规范描述、仅一本偏运维，故有意放弃运维与网络管理员市场而专注开发者；卷二涵盖 DHCPv6（用户态实现并已移植 Linux）、DNS 与移动 IPv6 等 OS 无关内容，对 Linux 侧 USAGI 项目的开发者亦有价值，卷一则更专于 FreeBSD/KAME 实现。（BSDTalk EP112，[199.16-273.74, 707.08-767.72, 785.1-811.06, 925.82-991.54]，L1）
- AsiaBSDCon 定位为面向全 BSD 家族的技术会议，向 NetBSD、OpenBSD、FreeBSD、DragonFly 及 Mac OS X 等 BSD 系平台的使用者与建设者征集论文，2007 年 3 月 10 日至 13 日在东京举行为期四天；Hiroki Sato 任大会主席、George Neville-Neil 任程序委员会主席；主会期之外安排 BOF 与 FreeBSD Dev Summit，并计划全体晚宴；CFP 已发布，官网页面正由日本本地成员重新设计，会后即向各邮件列表广发通知。（BSDTalk EP74，[132.52-207.10]，L1）
- 办会模式与准入政策：AsiaBSDCon 各届由不同地区的团队接手、组织方式各异，上届于两年前在台湾举行并收取少量名义费用；本届延续低价原则，以让全亚洲各地参与者负担得起为约束，会场设在东京大学；是否固化为双年会尚未决定，取决于志愿者供给；会期附近无重叠的同类会议。（BSDTalk EP74，[239.14-333.34]，L1）
- 亚洲 BSD 生态的强度与成因：George Neville-Neil 与日本众多 BSD 开发者互动的总体印象是 Linux 与 BSD 在日本大致处于均势——商业领域 Linux 更流行，而开发者偏爱 BSD；日本 BSD 开发者众多的结构性原因在于嵌入式采用：打印机、电话机、小型便携 DVD 播放器等设备以 BSD 为底，直接把开发者基数做大；亚洲其他地区的 BSD 部署亦相当广泛。（BSDTalk EP74，[338.14-416.70]，L1）
- 许可证被点名为嵌入式采用的决定变量：设备制造商不愿公开源代码，而 GPL 强制公开，BSD 许可证因此在这类应用中通常胜出——操作系统在嵌入式商业场景的胜负手不是纯技术指标，而是源码披露义务所对应的利益结构。（BSDTalk EP74，[416.70-439.08]，L1）
- 文档本地化的双重困境：组织层面，翻译工作对普通开发者吸引力低，专职翻译团队覆盖约八种语言却并不活跃，成员多为用户而非开发者，招译者困难；德语与法语翻译最活跃，中文近期活跃但人手极少。技术层面，用户文档翻译尚可，而消息目录、内核消息与命令行消息的翻译构成硬障碍——翻译需要多种编码，但消息文本通常写死在源代码中，多编码方案无法进入源码。（BSDTalk EP74，[444.56-601.12]，L1）
- 两位当事人的个人使用图景：George Neville-Neil 纯 FreeBSD 阵营——网络与安全研究用的多台服务器、跑 6.1-stable 的生产邮件与 web 服务（6.2 即将发布）、跟踪 head 的实验机、内含大量 BSD 的 Mac 笔记本，此前供职于服务器普遍采用 FreeBSD 的大型互联网公司；Hiroki Sato 在大学维护实验室网络，以 OpenBSD 作为终端与科研仿真环境并为研究领域开发设备驱动，兼用 FreeBSD、NetBSD 及其他多种 Unix，收藏老式系统（含老 Linux 与 SunOS 4）是其爱好。（BSDTalk EP74，[620.00-745.52]，L1）

**史观**：

- 总纲8 本体论上各方平等：面对 KAME 代码被各操作系统吸收并各自改进是否分叉的提问，Jinmei 给出了明确的多实现肯定论：这并非 KAME 特有问题，各 BSD 本就各有特性，IPv6 栈在各系统内按自身道路演化是应然之事，偶尔协同对齐即可；多种实现提供选择并保障互操作性，是好事而非坏事。这一态度在本体论层面平等看待各 BSD 分支的独立演化。（BSDTalk EP112，[557.08-642.44]，L1）
- 总纲10 动手者创造历史：Jinmei 自述参与写书的动机是知识传承的自我意识：其入行时对网络近乎一无所知，几乎所有网络知识习自 Stevens 的著作并深受其启发，故当受邀参与时，希望能为下一代工程师做 Stevens 曾为他做的事；Qing Li 则称 Stevens 的 TCP/IP 系列是网络开发者的“圣经”、承接其衣钵是“要填的大鞋”，二人明确以向社区回馈经验为目标。一线实现者将一手工程经验整理为教材，正是技术共同体知识再生产的方式。（BSDTalk EP112，[1012.54-1104.3]，L1）
- 总纲8 本体论上各方平等：会议的组织原则本身即是 BSD 家族内部多方平等的实践：征文向所有 BSD 分支平等开放，连 Mac OS X 这样的 BSD 系商业平台也被纳入征集对象，不以某一分支为中心；两位当事人分属 FreeBSD 与跨 BSD 的位置，共治一会。（BSDTalk EP74，[132.52-164.42]，L1）
- 总纲13 法律与道德是利益分配：嵌入式厂商的许可证选择被当事人还原为利益分配而非哲学立场：GPL 的强制公开条款改变了源码的利益归属，BSD 许可证保留了厂商的商业秘密空间，于是法律文本成为技术之外决定操作系统胜负的变量——许可证之争本质是利益分配之争。（BSDTalk EP74，[416.70-439.08]，L1）
