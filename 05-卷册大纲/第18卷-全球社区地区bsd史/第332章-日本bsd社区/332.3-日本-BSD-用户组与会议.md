## 332.3.1 JBUG 的用户组历史

  **要点**：日本 BSD 用户组（JBUG，Japan BSD Users Group）1990 年代末成立，由 IIJ 与 WIDE 项目的系统管理员发起，早期东京、大阪、名古屋等城市均有本地用户组。JBUG 的邮件列表（freebsd-users-jp）与 IRC 频道（#bsd-jp）是日本 BSD 用户交流的核心渠道。
  **史料**：JBUG 邮件列表 Archive、freebsd-users-jp 档案、JBUG 早期活动记录 ［A］
  **史观**：总纲第 22 条——日本 BSD 用户组是 BSD 社区去中心化组织结构的重要体现
  **辨析**：JBUG 的确切成立日期需考据；东京/大阪/名古屋各地用户组的活跃时间需分析
  **文献**：freebsd-users-jp Mailing List Archive；JBUG 活动记录 ［A］

**要点**：

- AsiaBSDCon 2018 在东京举行，前两日为 FreeBSD Developer Summit 与 BeehiveCon（含 NetBSD Summit 和 OpenBSD VMM 更新），后两日为论文演讲；bhyve 相关论文在第二天占满专题时段，议题覆盖 bhyve 的 SmartOS zones 移植、ARMv7/v8、挂起恢复与虚拟中断控制器，另有 FreeBSD VPC 与保存恢复（朝向热迁移的第一步）。（BSD Now EP237，[0.0-997.0]，L1）
- FreeBSD 11.1 stable 合入针对 Meltdown 与 Spectre V2 的缓解：Meltdown 采用 PTI 分离内核与用户页表，Spectre V2 采用依赖微码更新的 IBRS；可通过 vm.pmap.pti 与 hw.ibrs_active 等 sysctl 查看与切换，retpoline 编译器方案仍在评估中。（BSD Now EP237，[1008.2-1502.9]，L2）
- OpenBSD 宣布 syspatch 开始为两个受支持版本（6.1 与 6.2）同时提供二进制补丁，使 6.2 在 6.3 发布后仍可通过 syspatch 获得 Meltdown 缓解，并特别感谢 Robert 与 Antoine Jacoutot 的工作。（BSD Now EP237，[3566.9-3641.5]，L2）
- MidnightBSD 创始人 Lucas Holt 在访谈中说明该桌面导向系统是 FreeBSD 的 fork 而非发行版，拥有自有包管理器 mPort（tar LZMA 包加 SQLite3 清单与索引），启动卷使用 UFS2 并支持 ZFS，提供 2.6.16 内核的 Linux 仿真，计划保留 i386 支持至 1.0 版本。（BSD Now EP237，[1701.7-2136.1]，L2）
- 一篇八个月使用 TrueOS 的报告记述作者因对 Linux 发行版的 systemd 组织方式失望而转向 FreeBSD/TrueOS，赞赏 OpenRC、ZFS 启动环境回滚与手册质量，并由此偏好 BSD 许可证；其未能使用的软件为 Netflix、Google Hangouts 与 Electron 类应用。（BSD Now EP237，[2373.5-2995.7]，L2）
- OpenBSD 开发者 Marc Espié 自述 dpb 为 FreeBSD poudriere 的强化对应物：面向本地集群、可精细控制各端口构建时序、力求并行构建同时收尾；其哲学是拒绝交叉编译、坚持各架构本机构建，以免长期掩盖破坏性回归，如 sparc64 集群每月约构建三千包，覆盖范围直至 VAX。（BSD Now EP94，[2019.35-2131.40]，L1）
- Espié 详述 dpb 的信任模型翻转：ports 树中工具可信而数以千计的 configure 脚本不可信，他笑称该系统“本来并非为此设计”（2157.08-2170.66）；改造后 dpb 以 root 启动随即降权，抓取源码与构建分属有无网络权限的不同用户，构建环境置于 chroot 且所在分区禁用 SUID，再以 pf 收紧网络面，非特权构建用户已在实战中暴露 configure 脚本的异常行为。（BSD Now EP94，[2157.08-2480.54]，L1）
- 新闻层勾勒 2015 年发行版嵌套图景：PC-BSD 项目 fork HardenedBSD 仓库筹建实验性镜像，主持人称 OPNsense 数周前已开先例；HardenedBSD 开发者 Shawn Webb 以同一构建脚本为 MIPS 路由器出包，其更严格的编译检查反而在 FreeBSD 树中揪出一处缺陷并已修复；同期 xhyve 将 bhyve 移入 macOS 10.10 的 Hypervisor.framework 用户态，嵌套与移植构成当期分发生态主线。（BSD Now EP94，[1151.36-1281.88]，L2）
- 首届 AsiaBSDCon 定于 2007 年 3 月 8 日至 11 日在东京大学举行，程序委员会从社区投稿中遴选约 16 篇论文并安排两场邀请报告，论文作者覆盖 OpenBSD、NetBSD、FreeBSD 各主要项目，主题以网络与文件系统为主，兼收 FreeBSD 项目运作方式等偏社区的非纯技术论文。（BSDTalk EP99，[420.08-455.28]，L1）
- 组织委员会经讨论后放弃多轨制而取单轨：理由是多轨会把人群拆散、令走廊交流变得困难，而好的会议恰恰依赖走廊交流；这一空间安排折射出 BSD 会议文化把社区互动置于内容密度之上的取向。（BSDTalk EP99，[401.32-424.2]，L1）

- AsiaBSDCon 2008 定于 2008 年 3 月 27 日至 30 日（周四至周日）在东京举行，延续首届格式：前两日教程、后两日正文会议；由上届单轨道改为双轨道，日程更宽松；会址比上届更靠近市中心与公共交通。（BSDTalk EP134，[132.83-195.19]，L1）

- 亚洲 BSD 生态的强度与成因：George Neville-Neil 与日本众多 BSD 开发者互动的总体印象是 Linux 与 BSD 在日本大致处于均势——商业领域 Linux 更流行，而开发者偏爱 BSD；日本 BSD 开发者众多的结构性原因在于嵌入式采用：打印机、电话机、小型便携 DVD 播放器等设备以 BSD 为底，直接把开发者基数做大；亚洲其他地区的 BSD 部署亦相当广泛。（BSDTalk EP74，[338.14-416.70]，L1）
- 许可证被点名为嵌入式采用的决定变量：设备制造商不愿公开源代码，而 GPL 强制公开，BSD 许可证因此在这类应用中通常胜出——操作系统在嵌入式商业场景的胜负手不是纯技术指标，而是源码披露义务所对应的利益结构。（BSDTalk EP74，[416.70-439.08]，L1）
- 文档本地化的双重困境：组织层面，翻译工作对普通开发者吸引力低，专职翻译团队覆盖约八种语言却并不活跃，成员多为用户而非开发者，招译者困难；德语与法语翻译最活跃，中文近期活跃但人手极少。技术层面，用户文档翻译尚可，而消息目录、内核消息与命令行消息的翻译构成硬障碍——翻译需要多种编码，但消息文本通常写死在源代码中，多编码方案无法进入源码。（BSDTalk EP74，[444.56-601.12]，L1）
- 两位当事人的个人使用图景：George Neville-Neil 纯 FreeBSD 阵营——网络与安全研究用的多台服务器、跑 6.1-stable 的生产邮件与 web 服务（6.2 即将发布）、跟踪 head 的实验机、内含大量 BSD 的 Mac 笔记本，此前供职于服务器普遍采用 FreeBSD 的大型互联网公司；Hiroki Sato 在大学维护实验室网络，以 OpenBSD 作为终端与科研仿真环境并为研究领域开发设备驱动，兼用 FreeBSD、NetBSD 及其他多种 Unix，收藏老式系统（含老 Linux 与 SunOS 4）是其爱好。（BSDTalk EP74，[620.00-745.52]，L1）

**史观**：

- 总纲8 本体论上各方平等：AsiaBSDCon 的节目委员会与志愿组织者包括 George Neville-Neil、Hidetoshi Shimokawa、Masanobu Saito 等动手者，会议同时容纳 FreeBSD、NetBSD、OpenBSD、DragonFly 与 illumos 议题，体现本体论上各方平等的社区呈现。（BSD Now EP237，[948.5-997.0]，L1）
- 总纲9 经验优先：TrueOS 用户通过 boot environment 在更新出问题后回滚而不丢失工作，是经验优先于盲目接受更新的操作实践。（BSD Now EP237，[2772.8-2821.0]，L2）
- 总纲10 动手者创造历史：Espié 把 dpb 的成型归功于同侪：naddy 先证明无需 root 的 fake 安装可行，才有后续整体去特权化的设计转向，他直言“如果没有同侪开发者替你试错，你什么都不是”（2745.32-2749.96）——构建基础设施的历史由动手者的日常试错累积而成，而非自上而下的规划。（BSD Now EP94，[2714.40-2749.96]，L1）
- 总纲5 没有必然性，只有偶然性：bhyve 的 Windows 支持是偶然性优先的一例：数月前在日本被问及时开发者还暗示明年才可能，而 BSDCan 当场已能 EFI 引导 Windows Server 2012 并以帧缓冲抓取的 VNC 作救援控制台，当事人自陈“没料到会这么容易”（3231.96-3234.72）——成熟时点由具体补丁与人手等偶然条件拼合，而非路线图必然。（BSD Now EP94，[3217.80-3234.72]，L2）
- 总纲8 本体论上各方平等：从论文覆盖各主要 BSD 项目、四大项目在会议空间内平行召开各自会议、到单轨设计令全体与会者共享同一议程，首届 AsiaBSDCon 的组织形态把各 BSD 分支置于平等对话的位置，体现了各方在本体论上平等对待的社区实践。（BSDTalk EP99，[401.32-424.2]，L1）
- 总纲10 动手者创造历史：会议资助政策的要义不在排场而在把分散的动手者聚到同一时空：差旅、住宿与签证资助构成工程协作的物质条件，开发者面对面聚集被组织者自觉当作会议的最高目的。（BSDTalk EP134，[301.31-331.44]，L1）
- 总纲20 历史地理塑造思想土壤：会议形态深嵌日本地理与文化土壤：会址向市中心与公共交通收敛、依托 JTB 的旅行体系、温泉与传统文化行程作为社区交往的延伸——地理与旅行文化塑造了亚洲 BSD 社区的聚散方式。（BSDTalk EP134，[174.08-483.07]，L1）
- 总纲8 本体论上各方平等：会议的组织原则本身即是 BSD 家族内部多方平等的实践：征文向所有 BSD 分支平等开放，连 Mac OS X 这样的 BSD 系商业平台也被纳入征集对象，不以某一分支为中心；两位当事人分属 FreeBSD 与跨 BSD 的位置，共治一会。（BSDTalk EP74，[132.52-164.42]，L1）
- 总纲13 法律与道德是利益分配：嵌入式厂商的许可证选择被当事人还原为利益分配而非哲学立场：GPL 的强制公开条款改变了源码的利益归属，BSD 许可证保留了厂商的商业秘密空间，于是法律文本成为技术之外决定操作系统胜负的变量——许可证之争本质是利益分配之争。（BSDTalk EP74，[416.70-439.08]，L1）
