**要点**：

- vBSDCon 2019 由 Dan Langille 组织，在弗吉尼亚州 Reston 的 Hyatt Regency 举办，Verisign 为主赞助商，议程涵盖 FreeBSD hackathon、正式会议、开发者峰会与慈善拍卖。（BSD Now EP315，[70.72-221.6]，L1）
- John Baldwin 的演讲回顾 BSD 自 1990 年代 sendfile 以来的内核 TLS 演进，并说明如何将加密会话密钥经 setsockopt 交给内核、再卸载到 Chelsio T6 网卡，同时处理链路聚合下的会话密钥交接。（BSD Now EP315，[828.32-1029.72]，L2）
- 反馈环节解释 FreeBSD 与 OpenBSD 的 PF 已因 VNET/vimage 支持与多核性能改造而大幅分叉，重新移植 OpenBSD 新版 PF 会丧失 FreeBSD 侧特性，因此长期未跟进。（BSD Now EP315，[4269.98-4411.6]，L1）
- 该期转述 Ars Technica 的 Unix 50 年回顾：1969 年 3 月 Multics 被叫停后，Thompson、Ritchie 与 Canaday 在闲置 PDP-7 上先设计文件管理器、再写汇编器与内核，形成 Unix 雏形。（BSD Now EP315，[2395.38-2999.32]，L2）
- OpenBSD 开发者 Marc Espié 自述 dpb 为 FreeBSD poudriere 的强化对应物：面向本地集群、可精细控制各端口构建时序、力求并行构建同时收尾；其哲学是拒绝交叉编译、坚持各架构本机构建，以免长期掩盖破坏性回归，如 sparc64 集群每月约构建三千包，覆盖范围直至 VAX。（BSD Now EP94，[2019.35-2131.40]，L1）
- Espié 详述 dpb 的信任模型翻转：ports 树中工具可信而数以千计的 configure 脚本不可信，他笑称该系统“本来并非为此设计”（2157.08-2170.66）；改造后 dpb 以 root 启动随即降权，抓取源码与构建分属有无网络权限的不同用户，构建环境置于 chroot 且所在分区禁用 SUID，再以 pf 收紧网络面，非特权构建用户已在实战中暴露 configure 脚本的异常行为。（BSD Now EP94，[2157.08-2480.54]，L1）
- 新闻层勾勒 2015 年发行版嵌套图景：PC-BSD 项目 fork HardenedBSD 仓库筹建实验性镜像，主持人称 OPNsense 数周前已开先例；HardenedBSD 开发者 Shawn Webb 以同一构建脚本为 MIPS 路由器出包，其更严格的编译检查反而在 FreeBSD 树中揪出一处缺陷并已修复；同期 xhyve 将 bhyve 移入 macOS 10.10 的 Hypervisor.framework 用户态，嵌套与移植构成当期分发生态主线。（BSD Now EP94，[1151.36-1281.88]，L2）
- 本期教程演示 SSH 链式连接：先以 ProxyCommand 指定经堡垒主机（bastion host）逐跳登录内网机器，再把主机别名、登录用户、密钥文件与跳板参数沉淀进 .ssh/config，使一条短命令即可完成多跳；HostKeyAlias 可将同一服务器的多个 known_hosts 条目合并为一以消除指纹误报；配置支持 host1/host2/host3 形式的递归串联与 Host * 通配默认跳板，且对 rsync、scp 等一切基于 SSH 的工具透明生效。（BSD Now EP42，[4676.64-5026.70]，L2）
- Sean Webb（彼时尚非 FreeBSD committer）推进 FreeBSD 的 PIE 支持以实现 ASLR：常规 ELF 可执行文件向内核声明固定加载地址，而以 PIE 编译者可被加载至任意地址，随机化由此可行；基础系统应用尚未默认以 PIE 编译，需在 make.conf 或 src.conf 置 WITH_PIE=yes 重编，i386、amd64、sparc64 与 arm 等架构均在支持计划内；该工作现处 11-CURRENT、尚未回移 10，项目即将发布测试征召，需要开发者清理代码风格、审查并给出 sign-off 以确认不破坏既有负载。（BSD Now EP42，[76.36-215.26]，L2）
- 首届 DCBSDCon 定于 2009 年 2 月在华盛顿特区举行，由华盛顿地区 BSD 用户组 CAPBUG 主办，筹办者 Jason Dixon 自 OpenBSD committer 朋友 Mike Erdly 起酝酿多年，最终借与 ShmooCon 黑客大会衔接的思路落地：ShmooCon 创始人 Bruce Potter 本身是 BSD 支持者，两会同城衔接可共享既到场的 BSD 倾向听众并获得规模经济。议题征集初以安全为指引主题，因收到大量与安全无关的优秀投稿而改为一般性 BSD 会议；各 BSD 均有代表，唯 MirOS BSD 缺席。（BSDTalk EP167，[65.46-155.38]，L1）
- 会议形态设计为两天单轨、每日约五至六场演讲，节奏仿照纽约 BSD Con（筹办者曾在此演讲），追求内容充实而不疲于奔命的社交友好型安排；注册目标价 50 至 75 美元以保持门槛亲民；现场设 BSDA 认证考试，由 Drew Levine 主理数场；赞助包与志愿者（已自 CAPBUG 召集）陆续落实。已确认的重磅演讲人包括 FFS 与 Soft Updates 之父 Kirk McKusick，以及 OpenNTPD、OpenBGPD 作者兼 OpenBSD PF 主力开发者 Henning Brauer。（BSDTalk EP167，[403.76-563.28]，L1）
- SysAdmin challenge 竞赛源于 CAPBUG 例会演示形式趋于陈旧的自省：筹办者把小学课堂黑板竞赛的组队对抗记忆与电视问答节目的求助环节混合，设计出团队系统管理挑战赛——在一台 VMware 服务器上部署四个 BSD 镜像，各队被投入未必熟悉的 BSD 环境，完成一系列只有主持人知晓的目标，期间可获得求助线；该赛制于数月前在 CAPBUG 试办大获成功，决定搬上首届大会。（BSDTalk EP167，[292.26-397.76]，L1）
- 节目片头新闻记录了一个资源节点：YouTube 上建立了 BSD conferences 频道，开始集中上传本年度与上一年度各 BSD 会议的演讲视频，会议影像自此有了聚合出口。（BSDTalk EP167，[27.10-41.86]，L2）
- 组织者 Matt Olander 回溯 MeetBSD 谱系：会议发端于波兰华沙，因欣赏其氛围而受邀将形式引入美国西海岸，2008 年首届 MeetBSD California 在 Google 园区举办并获成功，2010 年第二届移师 Mountain View 的 Hacker Dojo——一个供黑客与爱好者使用烙铁与网络设施开展创作的仓库式车库空间，湾区 FreeBSD 用户组已常驻其间。（BSDTalk EP198，[63.48-165.16]，L1）
- 2010 年会议刻意混合两种形式：首日采用 unconference，议程由与会者现场自组织——自报议题分组、五分钟闪电演讲、开发者围坐编程、以白板取代固定日程，组织者自嘲其形态是“勉强驯服的混乱”；次日保留传统讲座，以免冲击习惯传统会议者并保证重要报告得以传达。（BSDTalk EP198，[106.28-378.78]，L1）
- 会务组织面向社区可达性设计：注册费仅二十五美元并含餐饮，与一周后的纽约 BSDCon 谈成跨海岸联动折扣，招募志愿者分担会务；会议前两日并行安排 FreeBSD summit、PC-BSD 开发峰会，BSD release engineering 亦将举行正式会议，NetBSD 与 OpenBSD 参与者受邀利用场地自组会议。（BSDTalk EP198，[319.82-588.46]，L1）
- BSDCan 2011 的形式革新：FreeBSD Developer Summit 多年同场举办且逐年扩大，去年成功引入非直接参与 FreeBSD 开发的外部人士后，今年决定将部分 summit 演讲向公众开放，首日演讲并行轨道由三轨增至四轨；教程首日首次并行两场全天教程（SCTP 与 IPv6），次日恢复上午网络、下午防火墙的常规安排，与会者首次须在教程间取舍。（BSDTalk EP203，[82.52-185.16]，L1）

- Langille 的数据库选择史与类比：约 2000 年 9 月因 freshports 项目需要存储过程与关系完整性、而 MySQL 当时不具备，经人建议改用 PostgreSQL 并沿用至今；其背景含 DB2、Oracle、Sybase 等商业数据库，开源数据库比较中 PostgreSQL 明确胜出；他把 PostgreSQL 与 BSD 并论为安静的赢家——支持者众多、被广泛使用、工程质量与性能俱佳，而公众认知不足。（BSDTalk EP203，[594.90-677.34]，L1）
- 个人生产实践：Langille 以 Newegg 商用硬件自行组装 14TB 的 FreeBSD ZFS 服务器，作为其 Bacula 备份体系的主存储，稳定运行约十四个月，期间除一次停电外无故障；他使用 Bacula 近八年，第一步即为其编写 PostgreSQL 后端目录，并估计 Bacula 加 PostgreSQL 的用户或已多于加 MySQL；Bacula 目录记录备份文件清单、来源与去向、大小及 MD5，海量文件备份必须依赖高性能数据库承接目录写入。（BSDTalk EP203，[689.26-777.42]，L1）
- Henning Brauer 自述正在重写 PF 的队列子系统以取代旧 ALTQ：旧实现约九千行代码、带有 32 位上限且使用方式过于困难，新实现按 PF 原生方式重建队列功能；计划保留旧 ALTQ 一至两个发布周期供用户过渡，届时重命名若干冲突关键词，迁移成本基本只是一次配置调整。（BSDTalk EP214，[90.0-179.32]，L1）
- rthreads 是 OpenBSD 5.1 发布后 current 中最重大的变化：一对一的线程实现使用户态每个线程对应一个内核线程，取代此前内核只见单一进程的用户态模拟线程；旧实现要求全部文件描述符置为非阻塞并手工模拟阻塞语义，既无法利用多核又不可能百分之百正确。作者据当事人口述约在 2004 或 2006 年提交首批代码，启用后经过一个完整六个月开发周期除错，主要遗留问题是 CPU 时间统计与文件描述符表锁定。　[存疑脚注] 受访者本人对 rthreads 首批提交年份不确定（2004 或 2006），转写将提交者名转写为 TATU，通常应指 tedu（Ted Unangst），须以仓库提交记录核证（BSDTalk EP214，[2214.26-2427.73]，L1）
- BGPD 是第一个采用 PF 风格配置语言与内部消息传递框架的守护进程，其后 OpenNTPD、OpenSMTPD 等新写守护进程均沿用该框架，重复代码后来收拢为库；设计目标是使仅懂英语者读配置文件即可了解守护进程行为，与 sendmail 需要八百页专著的复杂性形成对照。OpenSMTPD 沿用 OpenBSD 特权分离模型，受访者判断 BSD 许可的邮件服务器在此之前长期缺位。（BSDTalk EP214，[2769.76-2909.16]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：Unix 诞生源于 Multics 被叫停与一台被遗忘的 PDP-7 被 Thompson 找到，是具体偶然条件而非必然演进。（BSD Now EP315，[2627.36-2670.72]，L2）
- 总纲10 动手者创造历史：Thompson 用三周分别写汇编器、编辑器与内核，且文件管理器先于内核成形，体现动手者而非宏大规划的创造路径。（BSD Now EP315，[2939.36-2981.86]，L2）
- 总纲4 分离聚合是永恒规律：PF 从 OpenBSD 移植到 FreeBSD 后因 vimage 与多核改造分叉，双方代码不再对齐，呈现分离聚合的循环。（BSD Now EP315，[4269.98-4411.6]，L1）
- 总纲10 动手者创造历史：Espié 把 dpb 的成型归功于同侪：naddy 先证明无需 root 的 fake 安装可行，才有后续整体去特权化的设计转向，他直言“如果没有同侪开发者替你试错，你什么都不是”（2745.32-2749.96）——构建基础设施的历史由动手者的日常试错累积而成，而非自上而下的规划。（BSD Now EP94，[2714.40-2749.96]，L1）
- 总纲5 没有必然性，只有偶然性：bhyve 的 Windows 支持是偶然性优先的一例：数月前在日本被问及时开发者还暗示明年才可能，而 BSDCan 当场已能 EFI 引导 Windows Server 2012 并以帧缓冲抓取的 VNC 作救援控制台，当事人自陈“没料到会这么容易”（3231.96-3234.72）——成熟时点由具体补丁与人手等偶然条件拼合，而非路线图必然。（BSD Now EP94，[3217.80-3234.72]，L2）
- 总纲22 知识注定过时：针对观众“生产服务器是否应移除编译器”之问，主持人指出该做法源自主机独占、用户别无他机的旧时代安全惯例，在任何人可随手起虚拟机编译再回拷二进制的当下已无任何安全收益，securelevel 提升与文件不可变标志等内核级约束才是有效防线，并以 Varnish 内置编译器处理配置语言为反例佐证；同段还呼应 Michael W. Lucas 在 FreeBSD hackers 邮件列表引发约五百封邮件的 gpart 与 fdisk、disklabel 之辨——安全教条与工具惯性皆随运行环境变迁而失效，具体知识注定过时，唯环境条件决定其效力。（BSD Now EP42，[4409.24-4471.84]，L2）
- 总纲5 没有必然性，只有偶然性：Bryce 以亲历者身份断言 shell 服务已无利可图：这一行当的黄金年代系于拨号上网、IRC bouncer 需求与 Hotmail、Gmail 尚不提供 IMAP 等偶然技术条件——用户需要一台永远在线、带固定上游带宽的机器；宽带普及与免费邮箱补齐能力后市场随之消亡，仅剩十余年前的少数大厂仍在运营（Brian Callahan 亦供职于其中之一）；BSD shell 服务的兴衰并非 BSD 本身的命运，而是外部通信条件偶然组合的函数，历史进程不可化约为项目内因。（BSD Now EP42，[2630.30-2712.26]，L1）
- 总纲15 文化即形式主义：SysAdmin challenge 的设计过程显示社区文化的自觉形式化：当例会演讲仪式失效时，组织者并未增补内容，而是为知识展演另造一套形式——组队、目标保密、求助线与竞赛排名。社区仪式的生命力依赖其形式载体的更新，形式本身即是文化的构件。（BSDTalk EP167，[323.66-360.66]，L1）
- 总纲8 本体论上各方平等：组织者阐明 unconference 的核心理念是让平时只能通过邮件列表与开发者远距互动的用户坐到开发者对面，当面陈述使用痛点与好评，打破会议场景中演讲者与听众的层级结构。（BSDTalk EP198，[630.18-650.54]，L1）
- 总纲20 历史地理塑造思想土壤：会场从 Google 园区迁往 Hacker Dojo 仓库的选址自述——代表硅谷车库式做事方式——显示湾区地理与创客空间文化直接塑造了这届 BSD 会议的组织形态。（BSDTalk EP198，[121.02-168.92]，L1）
- 总纲10 动手者创造历史：Langille 与主持人一致认为真正的学习来自工作之余亲手构建玩物而非岗位任务本身——14TB ZFS 服务器、Bacula 的 PostgreSQL 后端等个人动手产物既反哺其日常职业，也构成 BSD 与 PostgreSQL 生态中会议、工具与社区的实际支撑。（BSDTalk EP203，[822.77-847.94]，L1）
- 总纲9 经验优先：PFSYNC 主主负载分担在技术上不可能真正高效：同步状态表使每条连接的工作量翻倍，防御手段唯有延迟并批量打包同步报文，而这又引入级联延迟；据此作者依据真实运维经验主张生产环境采用平淡的主备两节点配置，认为多节点增加的复杂性本身就在提高失败概率。可靠性来自尽量简单的工程判断，是对炫目特性优先的价值观反驳。（BSDTalk EP214，[1203.64-1429.22]，L1）
- 总纲4 分离聚合是永恒规律：三大 BSD 自 1995 年最后一次分叉后已各自独立开发逾十五年，但当事人观察认为 OpenBSD 与 FreeBSD 在用户视角下的差异小于共享同一代码基础的若干 Linux 发行版之间的差异；BSD 项目间的技术互取被视为理所当然而不必每两周重造轮子。分叉后的再聚合以技术共享而非代码合并的形式延续，呈现分离与聚合的循环结构。（BSDTalk EP214，[3225.86-3283.85]，L1）

- [存疑脚注] 转写片段时间戳前后交错、顺序错乱，部分演讲归属与细节依赖上下文拼合，属节目单源转述，未与会议录像或议程逐条交叉核验。　[存疑脚注] 转写顺序错乱，演讲细节未经会议录像核验（BSD Now EP315，[0.0-57.2]，L4）
- 辨析点：构建沙箱化不等于包更安全——Espié 明确区分 ports 树工具可信与第三方源码不可信，configure 脚本有夹带木马的前例，autoconf 版本变更即可造成万行差异而难以逐行审查；隔离的价值只在防止单包问题横向污染构建机，包产物安全性仍取决于上游；受无 ZFS 与 VAX 等架构约束，隔离以同一分区内约万条链接构造独立 chroot 的技巧实现，而非快照回滚。（BSD Now EP94，[2553.76-2660.32]，L1）
- Devious 案例呈现工具理性与共同体认同的真实张力：受访管理员承认 FreeBSD 的 jail、ZFS 数据集、sysctl 隐藏 UID 与 rctl 资源控制、IPFW 用户匹配规则更适合作共享 shell 主机，且曾认真考虑迁移，但遭用户抵制——用户要的不是任意 BSD 而是 OpenBSD 本身，其中不乏 OpenBSD 开发者，平台一致性正是其开发体验的一部分；访谈同时点出 FreeBSD 项目自身提供项目级 shell 资源而 OpenBSD 架构上缺位，Devious 恰好填补此空白；功能最优解让位于共同体归属，是理解 BSD 分支生态分化的一把钥匙。（BSD Now EP42，[1727.20-1790.04]，L1）
