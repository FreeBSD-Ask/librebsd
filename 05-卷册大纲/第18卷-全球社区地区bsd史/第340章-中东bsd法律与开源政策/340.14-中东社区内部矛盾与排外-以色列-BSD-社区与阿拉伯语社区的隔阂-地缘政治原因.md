# 340.14 中东社区内部矛盾与排外——以色列 BSD 社区与阿拉伯语社区的隔阂（地缘政治原因）——以色列 BSD 社区（以 Check Point、Israel FreeBSD User Group 等为核心）与阿拉伯语 BSD 社区（埃及、海湾国家等）长期无正式合作，部分以色列开发者与阿拉伯开发者在国际邮件列表中因政治话题冲突

## 340.14.1 以色列与阿拉伯社区的隔阂

## 340.14.3 中东与南美社区排外比较

  **要点**：南美 BSD 社区排外现象较轻，主要因南美无类似中东的地缘政治隔阂；中东 BSD 社区排外较重，主要因地缘政治与宗教文化隔阂；比较须控制地缘政治与宗教文化变量
  **史料**：中东与南美 BSD 社区档案、中东与南美地缘政治对比、社区邮件列表历史讨论 ［A］
  **史观**：总纲第 10 条——边缘者的贡献被中心叙事遮蔽，中东社区排外的严重性反映地缘政治的影响
  **辨析**：考据过程留痕——【查证来源】南美 BSD 社区档案（如 FreeBSD Brasil 用户组、Argentina FreeBSD User Group、BSD Peru 等公开邮件列表存档）；中东 BSD 社区档案（Israel FreeBSD User Group、Arabeyes 项目档案）；freebsd.duckdb freebsd-src 仓库中南美 ccTLD（.br/.ar/.pe/.cl 等）与中东 ccTLD（.il/.ae/.sa 等）author_email 分布对比；【交叉验证方法】以南美与中东 BSD 社区公开邮件列表发件人域名分布、社区活动频次、freebsd.duckdb 中两地区 ccTLD commit 量比例为量化指标，验证“排外较轻”与“排外较重”的判断；同时控制经济发展水平、互联网普及率、英语教育水平等变量，避免单一变量归因；【存疑判定依据】“排外较轻/较重”是相对判断，须以量化指标（如新成员加入难度、社区讨论参与度）支撑——南美与中东 BSD 社区档案的完整性与公开访问性差异较大，南美部分社区档案相对完整，中东部分社区档案因政治因素（如伊朗、叙利亚）访问受限；freebsd.duckdb 基于 ccTLD 的代理指标无法识别使用通用域名的贡献者，且南美与中东 ccTLD commit 量均极低（归入 other 类），难以进行精细化对比；保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

- 150.14a 对以色列 BSD 社区与阿拉伯语社区隔阂批评的反批评：地缘政治、语言障碍与文化隔阂的历史合理性（反批评层）
  **要点**：反批评者认为，以色列 BSD 社区与阿拉伯语社区的隔阂在 150.14.1-150.14.4 节所列批评中具有历史合理性——其一，地缘政治对技术社区影响的历史合理性：以色列与阿拉伯语国家的政治对立自 1948 年以色列建国以来持续至今，巴以冲突、阿以战争、海湾战争、阿拉伯之春（2010-2012 年）等地缘政治事件客观上限制了以色列开发者与阿拉伯开发者之间的直接技术合作；美国对伊朗、叙利亚等国的制裁（参见 150.6 节）使这些国家的开发者参与国际开源项目面临法律风险，技术社区的合作渠道受到主权国家政策的客观约束；FreeBSD Foundation 作为美国注册的非营利组织，须遵守美国出口管制条例（EAR），对受制裁国家的贡献者处理存在合规义务，地缘政治对技术社区的塑造是结构性约束而非社区主观选择；其二，语言障碍的历史合理性：希伯来语与阿拉伯语虽同属闪米特语族，但二者的技术词汇体系独立发展——希伯来语技术文档主要在以色列理工学院（Technion）、特拉维夫大学（TAU）、希伯来大学（HUJI）等高校与 Israel FreeBSD User Group 内部积累，阿拉伯语技术文档主要依赖 Arabeyes 项目（2001 年成立的阿拉伯语 Unix 国际化项目，2017 年 1 月 19 日最后编辑，2017 年 2 月 21 日迁移至 GitLab）的翻译工作；两套技术词汇体系的独立发展使以色列开发者与阿拉伯开发者在技术交流中须借助英语这一第三语言，语言障碍客观上增加了合作成本；FreeBSD 官方文档以英语为主，希伯来语与阿拉伯语本地化均不完整，社区成员若不熟悉英语则难以参与国际邮件列表讨论，这一限制对双方均有效；其三，文化隔阂的历史合理性：以色列 BSD 社区以犹太-世俗文化为主，受 8200 部队等技术单位的工程文化影响，强调实用主义与快速原型；阿拉伯语 BSD 社区以伊斯兰文化为主，受海湾国家宗教文化影响，社区讨论中可能涉及宗教礼仪时间安排、性别参与规范等文化差异；文化隔阂的客观存在使社区成员在跨文化合作中须付出额外的文化适应成本，社区内部的同质性偏好是减少协作摩擦的理性选择；反批评者总结认为，三个维度均反映以色列 BSD 社区与阿拉伯语社区隔阂在“地缘政治约束 + 语言词汇独立 + 文化适应成本”上的历史合理性，不应以个别批评推导“BSD 社区排外”的总体结论
  **史料**：Israel FreeBSD User Group 邮件列表存档；Arabeyes 项目历史页面（<https://www.arabeyes.org/> ，最后编辑 2017-01-19，GitLab 迁移 2017-02-21，访问日期 2026-07-23）；FreeBSD Foundation 关于美国出口管制条例（EAR）合规的公开声明；美国财政部海外资产控制办公室（OFAC）对伊朗、叙利亚等国的制裁清单；参见 150.6 节地缘政治对技术交流的效应部分史料；参见 150.4 节阿拉伯语技术社区与文档翻译部分史料 ［A］
  **史观**：总纲第 11 条——法哲学与政治历史哲学：地缘政治对技术社区的塑造是国家间政治关系的形式主义化显现；总纲第 5 条——组织结构塑造技术路径：地缘政治、语言词汇、文化隔阂作为中东 BSD 社区的组织结构塑造了其技术合作路径；总纲第 8 条——本体论上各方平等：以色列 BSD 社区与阿拉伯语 BSD 社区在本体论上地位相等，二者皆是 BSD 谱系在中东地理内的一刻状态
  **辨析**：考据过程留痕——【查证来源】Israel FreeBSD User Group 邮件列表存档；Arabeyes 项目主页（<https://www.arabeyes.org/>，访问日期 2026-07-23）经 WebFetch 一手核验，显示最后编辑 2017-01-19、GitLab 迁移 2017-02-21，与反批评层“Arabeyes 项目存在”陈述一致；Check Point 官方公司概况页面（<https://www.checkpoint.com/about-us/company-overview/>）经 WebFetch 一手核验，确认 1993 年创立与 Gil Shwed 创始人身份，但官方页面未列出 Marius Nacht、Shlomo Kramer 联合创始人身份与“6 月 5 日”具体日期、“拉马特甘”创立地点——此细节须以 Check Point 早期 SEC 上市文件或 Gil Shwed 个人公开陈述核验；FreeBSD Foundation 关于美国出口管制条例（EAR）合规的公开声明经 WebSearch 检索未直接定位专门声明，须以 Foundation 官方公告与年报核验；OFAC 对伊朗、叙利亚等国制裁清单为公开一手来源；《亚伯拉罕协议》公开文本经 CIA World Factbook 与多源公开报道交叉验证，确认 2020 年以色列与阿联酋、巴林、摩洛哥、苏丹关系正常化；【交叉验证方法】以 Israel FreeBSD User Group 邮件列表存档与 Arabeyes 项目档案互证，确认“无正式合作”的事实层面判断；以 FreeBSD 官方文档英语主导地位与希伯来语/阿拉伯语本地化完整度对比，验证“语言障碍客观存在”的论证；以 Linux 内核社区、Apache 社区等大型开源项目中跨文化合作案例为参照，辨析“文化隔阂”是否构成不合作的充分理由；【存疑判定依据】反批评的合理性在不同叙事中评估不一——部分视为有效辩护，部分视为合理化；【0 信任原则·地缘政治归因的限度】“地缘政治约束技术合作”是结构性事实，但具体合作的缺失是否完全归因于地缘政治须以个人层面的合作尝试记录核验，若存在以色列与阿拉伯开发者个人之间的成功合作案例，则“完全归因于地缘政治”是过度简化；【0 信任原则·语言障碍归因的限度】希伯来语与阿拉伯语技术词汇的独立发展是历史事实，但二者皆以英语为中介语言参与国际社区，语言障碍是否构成隔阂的充分原因须以实际合作案例验证，若双方在英语邮件列表中能够顺畅交流，则“语言障碍”是结构性而非决定性因素；【0 信任原则·文化隔阂归因的限度】“文化适应成本”论证须对照其他跨文化开源合作案例——Linux 内核社区中来自不同文化背景的开发者能够合作，反映文化隔阂并非不可逾越，中东 BSD 社区“以文化隔阂为由不合作”可能是事后合理化而非事前决定因素；保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

  **要点**：再批评者指出，反批评的“历史合理性”论证不能掩盖三个当代挑战——其一，地缘政治约束的“碎片化代价”：地缘政治对技术合作的约束是结构性事实，但 FreeBSD 作为开源项目在许可证层面不区分贡献者国籍——BSD 许可证允许任何人使用、修改、分发代码，地缘政治对社区合作的约束是在许可证中性原则下的人为限制；以色列与阿拉伯语社区的长期无正式合作使双方在技术文档翻译、本地化测试、用户反馈等方面错失协同机会——Arabeyes 项目 2017 年后活动趋于停滞（最后编辑 2017-01-19，GitLab 迁移 2017-02-21），阿拉伯语 BSD 文档的更新依赖零星个人贡献，与 Israel FreeBSD User Group 的活跃度形成对照；这一碎片化代价是地缘政治约束的间接成本，不应仅以“地缘政治约束”作为合理化解释；其二，语言障碍的“中介语言不对称”：希伯来语与阿拉伯语技术词汇的独立发展是历史事实，但以色列开发者普遍具备较高的英语熟练度（受以色列高等教育体系与 8200 部队技术训练影响），阿拉伯语开发者的英语熟练度因国家而异（海湾国家普遍较高，部分阿拉伯国家因教育体系限制较低）——这一不对称使“以英语为中介语言”的合作实际偏向以色列一方，阿拉伯语开发者在英语邮件列表中的参与度受英语能力制约；Arabeyes 项目的停滞亦反映阿拉伯语本地化工作缺乏持续志愿者供给，语言障碍的“历史合理性”论证掩盖了资源不对称的实质；其三，文化隔阂的“事后合理化”质疑：文化隔阂客观存在，但 FreeBSD 社区作为技术社区，其核心交流内容是代码、文档、技术决策，文化差异对技术交流的直接影响有限；“文化适应成本”的论证忽视了开源社区中技术能力优先于文化认同的普遍规范——Linux 内核社区、Apache 社区等大型开源项目中来自不同文化背景的开发者能够基于技术能力合作，中东 BSD 社区“以文化隔阂为由不合作”可能是事后合理化而非事前决定因素；将地缘政治、语言、文化作为不合作的理由可能固化既有隔阂，阻碍潜在合作的发生；再批评者总结认为，三个维度均反映“历史合理性不能掩盖当代挑战”——地缘政治、语言、文化隔阂在 1990-2000 年代形成的中东 BSD 社区碎片化格局在 2020 年代全球化开源生态与机器翻译工具普及的条件下可能需要调整，如建立英语中立的区域性技术会议、引入机器翻译辅助跨语言文档协作、鼓励双方开发者在国际邮件列表中以技术能力为标准交流

- 150.14c 合题：中东社区隔阂的辩证综合——地缘政治约束与碎片化代价、语言障碍与中介语言不对称、文化隔阂与事后合理化质疑的张力（合图层）
  **要点**：综合三层辩证，以色列 BSD 社区与阿拉伯语社区的隔阂在 150.14.1-150.14.4 节批评、150.14a 反批评、150.14b 再批评三个层面既具有历史合理性（反批评层）也面临当代挑战（再批评层），二者并非非此即彼——地缘政治约束客观上限制了以色列与阿拉伯语社区的直接合作渠道（反批评层的合理性），但 FreeBSD 作为开源项目在许可证中性原则下的人为限制与碎片化代价是治理成本（再批评层的代价）；语言词汇独立发展与英语中介语言的合作成本客观存在（反批评层的合理性），但以色列与阿拉伯语开发者的英语熟练度不对称使“以英语为中介”的合作实际偏向以色列一方，且 Arabeyes 项目 2017 年后的停滞反映阿拉伯语本地化资源不足（再批评层的代价）；文化隔阂客观存在使跨文化合作须付出额外适应成本（反批评层的合理性），但开源社区中技术能力优先于文化认同的普遍规范使“文化隔阂作为不合作理由”可能是事后合理化（再批评层的代价）；最终评价应区分“历史语境中的合理性”与“当代条件下的适应性”——中东 BSD 社区在 1990-2000 年代地缘政治高压条件下形成的碎片化格局在 2020 年代全球化开源生态、机器翻译工具普及、远程协作工具成熟的条件下可能需要调整，如建立英语中立的区域性技术会议（参照 AsiaBSDCon 在东京的举办模式）、引入机器翻译辅助跨语言文档协作、鼓励双方开发者在国际邮件列表中以技术能力为标准交流、探索 FreeBSD Foundation 在地缘政治中立框架下的中介协调角色；批评、反批评与再批评的辩证过程本身揭示了中东社区隔阂问题的复杂性——任何简单的“BSD 社区排外/地缘政治不可避免”二元判断都不足以涵盖地缘政治、语言、文化三个维度的多维度评价；中东 BSD 社区是否需要合作改革是一个需要社区自身回答的问题——史学分析可以揭示问题但不能替代社区的主体选择，且地缘政治的演化（如 2020 年《亚伯拉罕协议》后以色列与阿联酋、巴林关系正常化对技术社区合作的潜在影响）可能为社区合作打开新的可能性；本体论上，以色列 BSD 社区与阿拉伯语 BSD 社区在本体论上地位相等，二者皆是 BSD 谱系在中东地理内的一刻状态——Check Point 的工程文化与 Arabeyes 的本地化工作各自在其生态内合理，差异是地理与历史语境的不同而非本体等级的高下；地缘政治约束下的合作缺失是历史地理塑造的具体显现，但不构成对任何一方本体地位的贬低
