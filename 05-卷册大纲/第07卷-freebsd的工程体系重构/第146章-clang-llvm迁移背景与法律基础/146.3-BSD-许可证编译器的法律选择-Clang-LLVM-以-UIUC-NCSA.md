# 146.3 BSD 许可证编译器的法律选择——Clang/LLVM 以 UIUC/NCSA 许可证（BSD-like）发布

## 146.3.1 Clang/LLVM 的 UIUC/NCSA 许可证分析

**要点**：LLVM 项目最初采用 University of Illinois/NCSA Open Source License（UIUC/NCSA 许可证），这是一种经 OSI 认证的 BSD 风格宽容许可证。UIUC/NCSA 许可证条款与两条款 BSD 许可证高度相似：要求源代码分发时保留版权声明和许可证文本，明确免责声明（AS IS），不要求衍生作品开源，不施加 copyleft 义务。关键差异在于 NCSA 许可证明确提及 "the University of Illinois at Urbana-Champaign and its contributors"，且专利授权条款在早期版本中表述略有不同，但整体法律效果与 BSD 许可证兼容。LLVM 项目于 2019 年（v9.0.0）重新许可为 Apache License 2.0 with LLVM Exceptions，该许可证包含明确的专利授权条款和终止条款（patent retaliation），但经 LLVM Foundation 法律审查认为与 BSD 生态仍然兼容（因为 Apache 2.0 是宽松许可证，不要求衍生作品开源）。Clang 作为 LLVM 子项目采用相同许可证。

## 146.3.2 BSD-like 许可证编译器的法律效应

**要点**：采用 BSD 风格许可证的 Clang/LLVM 为 FreeBSD 基本系统带来三个关键法律优势：第一，FreeBSD 可以自由修改 Clang/LLVM 源码而不必发布修改后的源码（对比 GPL 要求衍生作品以相同许可证发布）；第二，商业公司（如 Apple、Sony、Microsoft、Google）可以基于 Clang/LLVM 开发专有编译器分支而不触发 copyleft 义务（Apple Xcode、Sony PlayStation 4/5 SDK、Google Chrome 工具链均基于 Clang）；第三，FreeBSD 基本系统整体可以保持 BSD 许可证纯洁性，不再包含 GPLv3 代码，彻底消除了因 GCC 升级引入 GPLv3 的法律风险。这些优势也带来商业生态的正向反馈：Apple 对 LLVM/Clang 的持续投入（2005 年至今雇佣 Chris Lattner 及团队全职开发）实质上补贴了整个开源社区的编译器开发，FreeBSD 作为 LLVM 主要用户直接受益。

**史料**：LLVM 贡献者名单（Apple、Google、Microsoft、ARM、Sony、Intel、AMD 等为主要企业贡献者）、Apple Xcode Clang 分支历史、Sony PlayStation 4 Orbis OS 使用 FreeBSD + Clang 的逆向工程证据（CTurt 越狱分析）、LLVM Foundation 年度报告。 ［B］

**史观**：总纲第 22 条——开源运动：宽容许可证的 Clang/LLVM 形成了一个独特的 “多方商业竞争驱动开源协作” 生态——Apple、Google、Microsoft、Sony、ARM、Intel 等互为竞争对手的公司在 LLVM 项目中协作开发共享基础设施，各自保留专有后端和工具扩展。这与 GCC 由 FSF 主导、主要由 Red Hat 等 GNU/Linux 公司贡献的生态形成鲜明对比。

**辨析**：Clang/LLVM 的商业友好许可证并不意味着没有商业控制风险——Apple 作为最大贡献者（Lattner 为 Apple 员工期间是项目首席架构师）对 LLVM 发展方向拥有事实上的巨大影响力，但 LLVM Foundation 治理结构（多元化董事会）在一定程度上制衡了单一公司控制。

**文献**：Lattner C. LLVM [M]//Brown A, Wilson G. The Architecture of Open Source Applications. Lulu.com, 2011. ISBN: 978-1-257-63801-7；ACM. ACM Software System Award 2012: LLVM [EB/OL]. awards.acm.org. ［B］

## 146.3.3 与 GPL 编译器的法律地位比较

**要点**：GCC（GPLv2/v3）与 Clang/LLVM（UIUC/NCSA→Apache 2.0）的许可证差异直接决定了它们在不同生态中的地位。GCC 的 GPL 许可证要求任何基于 GCC 的衍生作品（包括修改后的编译器本身）必须以 GPL 发布，这意味着：基于 GCC 开发专有编译器分支需要特殊许可（FSF 曾向多个商业伙伴出售此类例外）；GCC 运行时库（libgcc、libstdc++）的 GPL 许可证与例外条款（GCC Runtime Library Exception）允许编译后的程序不受 GPL 传染，但编译器本身的任何改进必须回馈。Clang/LLVM 的宽容许可证则允许完全自由的使用、修改和分发，包括专有分支。这种许可证差异使 Clang/LLVM 成为所有需要在专有产品中嵌入编译器能力的公司的首选——从 Apple Xcode 到 Sony PS SDK 到 NVIDIA CUDA 编译器 到 Google Chrome 到 Rust 编译器（rustc 基于 LLVM）到 Intel oneAPI，LLVM 已成为事实上的通用编译器基础设施。

**史料**：GCC Runtime Library Exception 文本、FSF 关于 GCC 链接例外的说明、各商业公司基于 LLVM 的产品公告（Apple Xcode、Sony PS SDK、NVIDIA CUDA 8+、rustc 基于 LLVM、Intel ICC/ICX 基于 LLVM）。［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：总纲第 12 条——法律结构：许可证选择直接决定技术生态的边界。GCC 的 GPL 许可证保护了 GNU 工具链的 “自由” 但也限制了其在商业专有产品中的应用；LLVM 的宽容许可证使其成为整个软件行业的共享编译器基础设施，但同时也允许 Apple 等公司在不回馈社区的情况下使用 LLVM 技术构建专有商业壁垒。两种模式各有利弊。

**辨析**：“GCC 落后于 Clang” 是一个需要具体语境的说法——在 C++ 标准支持、编译速度、错误诊断、IDE 集成、模块化设计方面 Clang 确实领先或显著优于传统 GCC；但在 Fortran/Ada 等语言支持、特定架构代码生成质量、极端优化场景中 GCC 仍有优势。编译器竞争在 2020 年代已从 “GCC 唯一选项” 变为 “GCC vs Clang 双雄并立”。

**文献**：Free Software Foundation. GCC Runtime Library Exception [Z]. gcc.gnu.org；LLVM Project. LLVM Users and Clients [EB/OL]. llvm.org/Users.html.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

GCC（GPL）与 Clang/LLVM（BSD-like）许可证地位与生态效应对比见下表。

| 维度 | GCC（GPLv3 + Runtime Exception） | Clang/LLVM（UIUC/NCSA→Apache 2.0 with LLVM Exceptions） |
| --- | --- | --- |
| 许可证类型 | 强 copyleft（编译器本体） | 宽容许可证（BSD-like） |
| 衍生作品开源义务 | 修改后的编译器本身必须以 GPL 发布 | 完全自由使用、修改、分发，包括专有分支 |

## 146.3.4 史料辨析

**要点**：LLVM/Clang 许可证历史的一手史料主要是 LLVM 仓库中的 LICENSE.TXT 文件演变历史（从 UIUC/NCSA 到 Apache 2.0 with Exceptions 的切换发生在 2019 年 LLVM 9.0.0 版本）和 LLVM Foundation 关于重新许可的官方决议。需注意：LLVM 重新许可至 Apache 2.0 并非所有代码均完成转换——约 400 个贡献者的代码尚未完成重新许可签署（截至 2022 年 11 月 “Relicensing Long Tail” 报告），但因这些代码比例极小且多为旧版本，项目认为整体可在 Apache 2.0 下分发。

**史料**：LLVM Git 仓库 LICENSE.TXT 变更历史、LLVM Foundation “Relicensing Long Tail” 报告（2022.11）、LLVM Developer Policy 许可证章节。 ［A］

**史观**：形式主义膨胀：许可证转换是大型开源项目的重大法律工程，需要每一位贡献者同意重新许可其代码。LLVM 长达数年的重新许可过程表明，即使在宽容许可证生态中，法律形式的统一也需要巨大协调成本。

**辨析**：FreeBSD base 系统中携带的 LLVM/Clang 版本许可证状态需逐版本核实——FreeBSD 10.0-11.x 使用 UIUC/NCSA 许可的 LLVM/Clang，FreeBSD 12+ 使用 Apache 2.0 with LLVM Exceptions 版本，具体切换点对应导入的 LLVM 版本（约 LLVM 9.0 对应 FreeBSD 12.x 后期）。

**要点**：

- PCC 几乎就是原初的 UNIX C 编译器，主要由 Stephen Johnson 写作，是 1970 年代中后期首个真正可重定目标的编译器；其可移植性设计是当年 UNIX 取得巨大成功的原因之一。该编译器原为 AT&T 授权，直到 2001-2002 年 Caldera 以 BSD 许可证发布后才为公众可得。（BSDTalk EP131，[50.43-92.48]，L1）
- Ragge 复兴 PCC 的偶然路径：他出于对奇异计算机架构的兴趣写过 NetBSD 的 VAX 移植，后受托把 GCC 移植到 PDP-10，却发现 GCC 充满 bug、难以驾驭且远不能为该架构生成合理代码；适逢 Caldera 开放旧 PCC，他判断 1970 年代为奇异架构所写的编译器更易移植，遂将 PCC 移植到 PDP-10 并用它编译 NetBSD 的 PDP-10 版，自 2002 年起作为业余项目持续约五年。（BSDTalk EP131，[102.23-172.27]，L1）
- 工程目标是将这个三十年老编译器改造成小型、可理解、C99 兼容的编译器；已重写寄存器分配器（他自评属当今最佳实现之列），编译器可自举，但开发期间用 GCC 编译 PCC 以免落入自己造成的 bug；当前版本内置大量内部一致性检查以验证生成代码的正确性。（BSDTalk EP131，[174.79-333.31]，L1）
- 性能画像：编译速度约为 GCC 的 10 至 15 倍（同一台机器编译 NetBSD 全源码 GCC 约十小时而 PCC 略超两小时）；生成代码执行速度目前比 GCC 慢 10-20%，但在长整型需双寄存器的 Intel 场景其寄存器分配优于 GCC 3。（BSDTalk EP131，[247.43-362.83]，L1）
- 架构与语言扩展：已有 i386、MIPS、PDP-10 支持（i386 移植仅两天，两小时打出 hello world），PDP-11 与 VAX 旧移植约一天可复活，HPPA 进行中、ARM32 有人启动；PCC 天生前后端分离——语言相关前端经良定义中间格式对接目标相关后端，从旧 BSD 源码复原的 Fortran 77 前端已可直接复用其后端与优化，C++ 前端因日常工作无暇，RISC 所需的延迟加载类交错指令处理尚待补齐。（BSDTalk EP131，[264.59-414.28]，L1）
- 采纳过程：一封宣告邮件引发远超预期的兴趣，OpenBSD 人在数小时内决定将其引入基本系统，NetBSD 导入主源码树，DragonFly BSD 与 MirOS BSD 有人跟进移植；Red Hat 为 Fedora 制作软件包但因许可证条款不能进入主分发版；项目基础设施（网页、wiki、源码树、邮件列表）依托吕勒奥理工大学机房一台旧机器搭建。（BSDTalk EP131，[410.59-631.76]，L1）
- 许可证细节：Caldera 以四条款 BSD 许可证（含广告条款）发布 PCC——随其他产品分发该编译器须在全部广告材料中标注 Caldera 版权；广告条款在 1980 年代即构成使用旧 BSD 代码的实际障碍，现代 BSD 已改用三条款或更少；Red Hat 因无法在主分发版履行广告义务而将 PCC 挪入收录此类许可证软件的独立源码仓库。（BSDTalk EP131，[481.72-550.73]，L1）
- 动机演变与版本策略：Ragge 自承最初并不特别在意许可证（本人即 BSD 用户），只是想让真正的 BSD C 编译器复活；但随着 GPLv3 即将问世且许多人对之不满，BSD 许可证对大量潜在使用者变得极重要；其发布策略为先冻结新开发、打磨 1.0 稳定基线供人编译真实软件，之后再加优化与清理。（BSDTalk EP131，[631.76-767.15]，L1）
- Langille 自述 2007 至 2008 年的际遇与现职：去年 BSDCan 后南下佛罗里达，旋因工作外包于六周后失去收入，返堪萨斯办妥工作许可后入职 Afilias——费城郊外 Horsham 的一家域名注册局服务商，负责 .org 等顶级域名的域名数据库，whois 信息与各域名的域名服务器列表皆自该库提取；其经手的全部顶级域名数据库均运行于 PostgreSQL。（BSDTalk EP144，[110.06-193.82]，L1）
- Slony-I 复制系统出自 Afilias 内部开发、后以开源释出，为 PostgreSQL 界所熟知且公司自身重度使用；域名库早在 2004 年 BSDCan 出现首个 Slony 演讲之前即已上 PostgreSQL（选型兼顾许可证与性能）；生产规模上单表达数千万行、日交易量巨大，调优得当时数据吞吐飞快，瓶颈通常在磁盘而非数据库本身；系统设定完成后即自行运转，无须持续调优，服务水平协议从未因 PostgreSQL 而失守。（BSDTalk EP144，[193.82-554.90]，L1）
- BSDCan 2008 为第五届、续办于渥太华大学，受邀演讲数量创历年之最：ZFS 文件系统深探（讲者转写不可辨）、Chris Lattner（时与 Apple 相关）讲 BSD 许可证的 C++ 编译器、Bacula 之父 Kern Sibbald 自瑞士与谈（Langille 本人亦是 Bacula 开发者）、Google Summer of Code 讲座、OpenBSD 硬件传感器框架的近期工作、Randall Stewart 讲 SCTP 及其扩展 socket API、X.Org 的未来规划；此外设 hacking、系统管理、嵌入式、虚拟化诸轨与教程，预计与会开发者约六十人（报名三十、惯例至会前翻倍），会前有开发者互讲、晚间设 hacking 房。 [存疑脚注] ZFS 演讲者人名转写不可辨，语境疑为 FreeBSD ZFS 移植者；SCTP 转写作 FCTP（BSDTalk EP144，[743.56-915.26]，L1）
- 会议的社交传统与运营哲学：注册自 Royal Oak 酒馆之夜开启（领 T 恤、领资料、喝啤酒），会期该馆 Guinness 销量增至三倍，周五六晚续聚、周日安排观光（核掩体、国会山、铸币厂、国家美术馆、文明博物馆，并新增标注步行可达景点的 Google 地图）；会议刻意维持小而可亲的规模，人人可与心仪开发者攀谈；固守渥太华纯因物流与熟悉度——熟悉校方与供应商降低精力与开销，使 organizer 得专注演讲与讲者质量，参会者亦因熟门熟路而自在。（BSDTalk EP144，[636.40-1015.94]，L1）
- 受访者转述 DTrace 的技术特性：可对系统中任意函数（库或可执行文件内）单独画像、聚合函数调用次数与耗时、语言支持线程局部存储以设条件变量；与 FreeBSD 的 ktrace、truss 等须持续读取内核内存并拖慢全局的工具不同，DTrace 关闭时零开销——它在内核中内置反汇编器、启用时改写指令、只影响被跟踪程序的运行性能；并转述 Bryan Cantrill 的演示：GNOME Terminal 打开一个新窗口竟发起约两千次系统调用。（BSDTalk EP30，[944.34-1076.12]，L1）
- 2006 年 BSD 阵营对脱离 GCC 的可能路径已有零星讨论：受访者借 OpenBSD 3.9 发布与 Theo 不妥协立场的调侃承认当下编译仍离不开 GPL 编译器这一妥协，随即列举替代选项——TinyCC、Intel C 编译器、以 MIT 许可开源的 Plan 9 C 编译器（Ken Thompson 作品，DragonFly 开发者一度关注但须改动内核以支持其目标格式）、以及在研的 TenDRA——结论是未来存在希望。（BSDTalk EP30，[1156.1-1245.58]，L1）
- LinuxWorld 2006 波士顿展会的 BSD 生态见闻：参观者普遍认知匮乏，有人径直询问“这是哪个版本的 Linux”，同时也有大量老用户与挑战者；BitDefender 起初称支持 OpenBSD 随即改口只有 FreeBSD；Coyote Point 为其网络负载均衡设备招募 FreeBSD 开发者；Cluster Resources 的开源自动部署软件希望支持 BSD；嵌入式方向对 NetBSD 兴趣可观。（BSDTalk EP30，[195.34-395.6]，L1）
- 受访者回忆在 Skycache（卫星 Usenet 服务商）的生产部署史：公司先以 NetBSD on SPARC 为上游，经由卫星每日吞吐约 250GB Usenet 流量，其后迁移到 Alpha DS10 上的 FreeBSD，原因是其 TCP 栈在当时表现卓越；受访者本人由此接触 BSD，并因转向安全领域而自然迁移至 OpenBSD。 [存疑脚注] 该段说话人因转写混叠难以确定归属 Dixon 或 O'Dell，公司部署事实本身为受访者一手自述（BSDTalk EP30，[778.04-815.88]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：PCC 的复兴系一连串偶然的叠加：个人对奇异架构的兴趣、GCC 移植到 PDP-10 的受挫、Caldera 开放源码的时点恰好赶在一封邮件引发的社区热情之前——旧编译器重回三大 BSD 基本系统并非技术演进的必然，而是具体事件与条件的偶然汇合。（BSDTalk EP131，[102.23-447.11]，L1）
- 总纲13 法律与道德是利益分配：许可证条款直接决定代码的流通路径：广告条款使 Red Hat 只能将 PCC 放入独立仓库而无法进入主分发版，现代 BSD 删去广告条款后三条款成为流通标准——许可证的文本差异即利益分配机制的差异，其后果由分发者与使用者的实际选择显现。（BSDTalk EP131，[510.47-550.73]，L1）
- 总纲21 革命与改革是历史方法论的分歧：GPLv3 的出台促使 BSD 阵营以引入自主许可的编译器作为路线回应：copyleft 强制路线与 BSD 自愿路线在工具链层面的分歧，经由 OpenBSD 对 PCC 的数小时导入行动具体化。（BSDTalk EP131，[756.64-767.15]，L1）
- 总纲20 历史地理塑造思想土壤：BSDCan 的地理惯性自成一例：会议地点并非由社区版图或战略考量决定，而系于创办人的居所变迁、场地与供应商熟悉度这类偶然的物流事实——人移居宾州而会议仍留渥太华，地理的惯性与 familiarity 持续塑造着 BSD 社区的聚集形态。（BSDTalk EP144，[636.40-718.20]，L1）
