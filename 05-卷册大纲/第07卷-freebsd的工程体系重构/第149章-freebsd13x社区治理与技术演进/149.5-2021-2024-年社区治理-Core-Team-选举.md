# 149.5 2021-2024 年社区治理：Core Team 选举、Security Officer 与 Foundation 资助

## 149.5.1 2021-2024 年 Core Team 选举与成员

**要点**：FreeBSD Core Team 每两年选举一次，2022 年举行了 Core Team 选举；13.0 发布时（2021）的 Core Team 成员经选举产生，2022 年选举后部分成员轮换；Core Team 是 FreeBSD 项目的最高治理机构，负责项目方向、committer 权限管理、争议仲裁等；2021-2024 年期间 Core Team 面临的重大议题包括：WireGuard 争议处理、Git 迁移后工作流调整、COVID-19 疫情下的社区协作、新 committer 招募与多样性改进、与 FreeBSD 基金会的协作

**史料**：FreeBSD Core Team 2020/2022/2024 选举公告（freebsd.org/core/）；core-secretary@ 邮件列表公开决议；FreeBSD 项目章程 ［A］

**史观**：总纲第 23 条——社区治理：Core Team 两年一次的选举制度是 FreeBSD 治理形式化的体现——定期换届防止权力固化，选举过程向所有 committer 开放，这一制度自 FreeBSD 项目早期延续至今

**辨析**：Core Team 成员名单随选举变动，具体成员列表需查阅对应年份的官方公告，本书记载的是制度层面的延续性而非特定个人；Core Team 决策通常采用协商一致（consensus）原则，而非投票表决，这是 BSD 社区的传统治理风格

**文献**：FreeBSD Project. *Core Team Information*. freebsd.org/core/; FreeBSD Project. *Core Team Election Results* (2020, 2022, 2024). freebsd.org. ［A］

## 149.5.2 Security Officer 与安全团队

**要点**：FreeBSD 13.0-RELEASE 时 Security Officer 为 Gordon Tetlow（戈登·泰特洛），Ed Maste（埃德·马斯特） 担任 Security Officer Deputy；Security Officer Team 负责安全漏洞处理、安全公告发布、安全更新协调；13.x 期间 FreeBSD 处理了多个安全漏洞，包括但不限于：CPU 侧信道漏洞（Spectre/Meltdown 系列后续变种）、网络栈漏洞、加密库问题等；WireGuard 争议也促使 Security Team 更早介入新安全功能的审查；FreeBSD 安全公告通过 freebsd-security-notify@ 邮件列表发布

**史料**：FreeBSD 13.0/13.1/13.2/13.3/13.4 公告中 Security Officer 署名；FreeBSD Security Advisories 页面（freebsd.org/security/advisories/）；Security Officer Team 页面［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：总纲第 21 条——安全工程：Security Officer 制度是 FreeBSD 安全工程制度化的体现——安全不是某个开发者的个人责任，而是有专门团队、专门流程、专门通信渠道的系统性工程

**辨析**：Security Officer 任期没有固定限制，通常长期担任以保持安全响应的连续性；Colin Percival 曾长期担任 Security Officer，Gordon Tetlow 在其之后接任

## 149.5.3 FreeBSD Foundation 2021-2024 年资助项目

**要点**：FreeBSD 基金会在 2021-2024 年期间资助了大量 FreeBSD 开发项目，与 13.x 系列直接相关的包括：(1) Git 迁移工作（Ed Maste 等）；(2) WireGuard 重构工作（John Baldwin（约翰·鲍德温） 等）；(3) aarch64/arm64 架构完善；(4) OpenZFS 持续集成与改进；(5) bhyve 虚拟化改进；(6) Linux ABI 兼容层改进；(7) WiFi 驱动改进（基于 LinuxKPI 的 iwlwifi 等驱动）；(8) 持续集成/CI 基础设施建设；(9) 安全改进；基金会资金来源包括个人捐赠、企业赞助（Netgate、Netflix、Google、AWS、Microsoft、iXsystems 等）、培训和服务收入

**史料**：FreeBSD Foundation 2021/2022/2023/2024 年度报告；基金会“资助项目”页面（freebsdfoundation.org/projects/）；基金会季度新闻通讯 ［B］

**史观**：总纲第 22 条——开源运动：FreeBSD 基金会的存在使 FreeBSD 区别于许多纯志愿者驱动的开源项目——基金会提供稳定资金资助关键基础设施和功能开发，雇佣多名全职开发者，这是 FreeBSD 能够持续生产高质量 RELEASE 的重要保障

**辨析**：基金会资助开发者并不意味着基金会“控制”FreeBSD——技术决策仍由 Core Team 和开发者社区做出，基金会主要提供资源支持；这是一种“资源提供与技术决策分离”的治理模式

**文献**：FreeBSD Foundation. (2021-2024). *Annual Reports*. freebsdfoundation.org; FreeBSD Foundation. *Project Portfolio*. freebsdfoundation.org/projects/.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 149.5.4 2021-2022 年 committer 权限状态

**要点**：2021-2024 年期间 FreeBSD 项目未发生公开的、争议性的 committer 权限撤销事件——这与部分其他开源项目形成对比；部分 committer 因个人原因、时间精力等因素主动退役（retire），属于正常的社区人员流动；Git 迁移和 Gerrit 代码审查系统引入后，新 committer 的招募流程更加规范，新贡献者从提交补丁到获得 commit bit 的路径更加清晰；13.x 期间 FreeBSD 持续招募新 committer，包括 aarch64/RISC-V 架构、WiFi、虚拟化、文档等领域的开发者

**史料**：freebsd-committers@ 邮件列表欢迎/退役公告；src/conf/COMMITTERS 文件（committer 名录）；Core Team 关于新 committer 投票的公开记录 ［A］

**史观**：总纲第 23 条——社区治理：committer 权限是 FreeBSD 社区的核心“公民权”，其授予和撤销是社区治理最严肃的决策之一；无公开争议性撤销说明 13.x 时期社区治理相对稳定

**辨析**：“未公开撤销”不排除 Core Team 私下处理个别问题的可能性，但 Core Team 通常仅对公开、重大的问题发布公告；本史书记载的是可公开查证的记录

**文献**：FreeBSD Project. src/conf/COMMITTERS file; freebsd-committers mailing list archives. ［A］
