# 149.9 重要贡献者与社区生态

## 149.9.1 13.x 时期核心开发者与贡献者

**要点**：FreeBSD 13.x 时期的核心贡献者包括（但不限于）：(1) 发布工程：Glen Barber（13.0-13.2 Release Engineer Lead，后卸任）、Colin Percival（13.3-13.4 Release Engineer Lead）、Konstantin Belousov（康斯坦丁·别洛乌索夫） 等；(2) 工具链：Ed Maste（工具链现代化、Git 迁移）、Dimitry Andric（Clang/LLVM 集成）等；(3) ARM64 架构：Andrew Turner 等；(4) ZFS/OpenZFS：Martin Matuska、Allan Jude（艾伦·裘德） 等；(5) WireGuard 重写：John Baldwin（约翰·鲍德温）、Kyle Evans、Matt Dunwoodie；(6) 网络栈与 bhyve：Peter Grehan（彼得·格雷汉）、Gleb Smirnoff 等；(7) 安全：Gordon Tetlow（戈登·泰特洛）（Security Officer）等；(8) 基金会支持：Deb Goodkin（FreeBSD Foundation 执行董事）及基金会团队；(9) Bill Jolitz：386BSD 共同作者，于 2022 年逝世，13.1-RELEASE 专门致敬 Bill Jolitz——“We stand on the shoulders of giants”

**史料**：FreeBSD 13.x Release Notes 致谢章节；FreeBSD Committers 名录（src/conf/COMMITTERS）；FreeBSD 基金会年度报告贡献者名单；13.1 公告中对 Bill Jolitz 的致敬 ［A］

**史观**：总纲第 10 条——边缘者贡献：每个 RELEASE 的致谢列表都很长，但仍有许多贡献者（特别是提交补丁的非 committer、ports 维护者、文档翻译者、测试者）未被充分记录；历史书应记住：FreeBSD 是数百名核心 committer 和数千名贡献者共同劳动的成果

**辨析**：贡献者列表无法穷尽，本节仅列出部分公开可查的代表性人物；将任何一个版本归功于少数几个人是不准确的

**文献**：FreeBSD Project. src/conf/COMMITTERS; FreeBSD Release Engineering Team. (2022-05-16). 13.1-RELEASE Dedication to Bill Jolitz; FreeBSD Foundation. Annual Reports contributor lists. ［A］

## 149.9.2 Git 迁移后新贡献者路径

**要点**：Git 迁移完成后，新贡献者参与 FreeBSD 的路径更加清晰：(1) 在 GitHub 镜像（github.com/freebsd/freebsd-src）提交 Pull Request，或在 reviews.freebsd.org 提交 Gerrit 审查；(2) 经过 committer 审查后代码可被合入；(3) 多次高质量贡献后可申请 committer 权限，由现有 committer 推荐、Core Team 投票；(4) FreeBSD 基金会举办“FreeBSD Friday”等线上活动指导新贡献者；(5) Google 编程之夏（编程之夏）每年接收学生为 FreeBSD 贡献功能；与 svn 时代相比，Git 降低了参与门槛，但 committer 标准并未降低——仍需要展示对 FreeBSD 代码风格、工程文化的理解

**史料**：FreeBSD 开发者手册“Contributing”章节；FreeBSD Foundation 新贡献者指南；编程之夏 FreeBSD 项目页面 ［A］

**史观**：总纲第 22 条——开源运动：参与门槛降低是开源运动“民主化”的体现——Git 和 GitHub 让全世界的开发者都能方便地参与，无需经历 svn 时代较复杂的账号申请流程

**辨析**：“GitHub PR 就能直接合入”是误解——所有代码仍需经过 FreeBSD committer 审查和推送，GitHub PR 是贡献渠道而非自动合入机制；FreeBSD 不使用“PR 合入”的 Linux/GitHub 风格工作流

## 149.9.3 COVID-19 疫情对 FreeBSD 开发模式的效应

**要点**：2021-2022 年 COVID-19 全球大流行持续影响 FreeBSD 开发模式：(1) BSDCan 2020/2021、EuroBSDCon 2020/2021 等线下会议取消或转为线上；(2) 开发者聚会、hackathon 转为线上进行；(3) 开发者本已分布全球（FreeBSD 本就是分布式项目），因此代码开发本身受影响较小；(4) 线上会议反而让一些原本无法差旅的开发者更容易参与；(5) 2023 年起线下会议逐步恢复；疫情也凸显了互联网和开源操作系统的重要性——网络流量暴增（Netflix 等）使 FreeBSD 的性能和稳定性更加关键

**史料**：BSDCan/EuroBSDCon 2020-2023 线上/线下举办公告；FreeBSD 基金会关于疫情期间社区活动的博客；Netflix 疫情期间流量增长公开数据 ［C］

**史观**：总纲第 2 条——实践先于理论：COVID-19 是一次全球范围的“远程协作大实验”，FreeBSD 作为本就分布式开发的项目适应良好，这验证了开源分布式开发模式的韧性

**辨析**：疫情对 FreeBSD 项目没有造成重大中断，这与其本就分布式的开发模式有关；这与许多商业公司被迫突然切换到远程工作形成对比

**文献**：BSDCan/EuroBSDCon Conference Archives (2020-2023); Netflix Technology Blog. (2020). *Traffic growth during COVID-19*. ［B］

## 149.9.4 社区生态史料辨析

**要点**：13.x 时期社区生态的一手史料包括：(1) 各 freebsd-* 邮件列表存档；(2) FreeBSD 论坛（forums.freebsd.org）讨论；(3) IRC/Discord/Slack 等实时交流渠道（但这些通常不存档或难以检索）；(4) FreeBSD 周会（weekly status reports）；(5) 会议录像和幻灯片；社区文化在 Git 迁移后缓慢演进——更开放、对新贡献者更友好，但仍保留了 FreeBSD 特有的技术高标准和直接沟通风格

**史料**：FreeBSD Mailing List Archives; FreeBSD Forums; FreeBSD Weekly Status Reports; BSD Conference YouTube 频道录像 ［B］

**史观**：总纲第 10 条——边缘者贡献：邮件列表和论坛中无数帮助新人、解答问题、报告 bug 的用户是社区的基石，他们的名字不会出现在 Release Notes 中，但他们构成了 FreeBSD 社区的真实面貌

**辨析**：IRC/Discord 等实时交流内容难以作为历史史料，因为通常不存档或检索困难；邮件列表和论坛是更可靠的历史记录来源
