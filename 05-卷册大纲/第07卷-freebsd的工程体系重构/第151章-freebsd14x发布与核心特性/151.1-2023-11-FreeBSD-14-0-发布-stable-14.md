# 151.1 2023.11 FreeBSD 14.0 发布——stable/14 分支的首个版本，献词纪念 Hans Petter Selasky

## 151.1.1 14.0 发布特性集与工程语境

**要点**：FreeBSD 14.0-RELEASE 于 **2023 年 11 月 20 日** 由 Release Engineering Team 正式发布（Release Engineer 为 Colin Percival），是 stable/14 分支的首个版本，也是 2023 年 6 月 19 日 FreeBSD 1.0 发布三十周年之后的首个大版本；14.0 献词给 **Hans Petter Selasky**（hselasky@）——FreeBSD USB 子系统长期维护者与核心开发者，于 2023 年去世；14.0 开发周期跨越两年半（自 13.0 于 2021 年 4 月发布后），集成了超过 25,000 个 commit，代表 FreeBSD 进入现代化成熟期；14.0 支持架构包括 amd64、aarch64、i386、powerpc、powerpc64、powerpc64le、powerpcspe、armv7、riscv64（**注：powerpc64le 与 powerpcspe 在 14.2 起停止提供 RELEASE 镜像**）；amd64 与 arm64 平台支持高达 1024 个 CPU 核心

## 151.1.2 14.0 核心技术特性全景

**要点**：14.0 带来的核心技术变更包括但不限于：① 默认 MTA 从 sendmail 替换为 **dma(8)**（DragonFly Mail Agent），sendmail 仍保留在 base 中但不再默认启用；② OpenSSL 从 1.1.1t 升级至 **3.0.12**（许可证变更为 Apache 2.0，引入 provider 架构与 FIPS 模块支持）；③ ZFS 升级至 **OpenZFS 2.2**，支持 block cloning（块克隆，类似 reflinks 写时复制文件克隆）、zstd 压缩改进、scrub 性能优化、BLAKE3 校验算法；④ 默认编译器升级至 Clang/LLVM 16（14.0 后期跟进至 17）；⑤ **wg(4)** WireGuard VPN 驱动重新集成（由 Netgate/Rubicon Communications 与 FreeBSD Foundation 赞助重写，2021 年争议后的代码经过全面审查）；⑥ KTLS（内核 TLS）新增 TLS 1.3 接收端卸载支持（Netflix 赞助）；⑦ **netlink(4)**——Linux 兼容的 Netlink 协议实现（Alexander V. Chernikov 开发），为运行 Linux 网络管理工具（iproute2 等）提供协议基础；⑧ 64 位可执行文件默认启用 PIE（位置无关可执行文件）与 ASLR（地址空间布局随机化）；⑨ TCP 默认拥塞控制算法从 New Reno 改为 **CUBIC**；⑩ root 用户默认 shell 从 csh/tcsh 改为 **sh(1)**（BSD Bourne Shell，经大幅改进支持交互使用）；⑪ 新增 **fwget(8)** 工具自动获取 Intel/AMD GPU 等设备固件；⑫ bhyve 虚拟化支持 TPM 2.0 passthrough 与 GPU passthrough、解除 16 vCPU 限制；⑬ **boottrace(4)** 启动过程跟踪框架；⑭ 所有平台（包括 i386）启用 **64-bit time_t** 以解决 Y2038 问题；⑮ UFS 文件系统在启用 journaled soft updates 时支持后台文件系统检查（background filesystem checks）；⑯ AWS 与 Azure 提供实验性 ZFS 云镜像

**史料**：FreeBSD 14.0-RELEASE Release Notes 各特性章节；cgit.freebsd.org/src/ commit 历史（wg(4) 重集成 commit 744bfb213144；KTLS TLS 1.3 05a1d0f5d7ac；netlink(4) 系列提交；PIE/ASLR b014e0f15bc7 等）；OpenZFS 2.2.0 Release Notes（2023.10 发布）；OpenSSL 3.0 Migration Guide；DragonFly BSD dma(8) 原始项目文档；Chernikov netlink(4) 开发者邮件列表说明 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：14.0 多项核心特性体现 FreeBSD 在 Linux 生态主导时代的务实路线选择：**netlink(4)** 主动兼容 Linux 网络协议、**fwget(8)** 自动固件获取、默认 shell 切换为更接近 POSIX 标准的 sh、TCP CUBIC 与 Linux 默认拥塞控制对齐——这些不是“屈服于 Linux”，而是在承认 Linux 生态事实标准地位的前提下保持 FreeBSD 技术独立性的工程智慧；WireGuard 的回归则展示了社区从 2021 年争议中吸取教训后的代码审核流程改进〔映射存疑，待主理人审定〕

**辨析**：**wg(4)** 在 14.0 中的状态需精确说明——WireGuard 驱动确实已重新集成进源码树，但 **默认不编译进 GENERIC 内核**，用户仍需通过 `if_wg_load="YES"` rc.conf 配置或 kldload if_wg 手动加载模块；这与 OpenBSD 6.8（2020.10）将 **wg(4)** 编入 GENERIC 的做法不同；**pf(4)** 防火墙在 14.0 中并未取代 **ipfw(8)** 成为默认——ipfw 仍是传统默认防火墙，pf 作为可选替代方案持续完善；**nproc(1)** 工具为 Linux 兼容性新增（GNU coreutils nproc 等价物），类似先前引入 **md5sum(1)** 等命令以兼容 Linux 脚本习惯

## 151.1.3 14.0 与 13.x 版本特性对比

**要点**：相较 13.2-RELEASE（2023.4），14.0 的核心演进方向可归纳为“默认安全化、工具现代化、生态兼容化、64 位纯净化”四大主题：安全默认方面，PIE+ASLR 默认启用标志着 FreeBSD 加入现代操作系统安全基线行列；工具链方面，LLVM 16/17、OpenSSL 3.0、OpenZFS 2.2、OpenSSH 9.5p1 全面跟进上游；生态兼容方面，**netlink(4)**、**nproc(1)**、Linuxulator arm64 与 amd64 对等、NFS over TLS（rpc.tlsclntd/rpc.tlsservd）缩小与 Linux 的功能鸿沟；平台策略方面，i386 仍为 RELEASE 架构但被明确标注为“last major version with 32-bit platform support”；13.0-RELEASE 于 2021.4 发布时 WireGuard 因代码质量问题在 RC 阶段被临时移除，14.0 中 **wg(4)** 经过 Netgate 赞助 John Baldwin（约翰·鲍德温） 团队的完整重写与多轮安全审计后正式回归，这一过程历时约两年半

**史料**：FreeBSD 13.0-13.2 Release Notes；FreeBSD 14.0 Release Notes“Changes Since FreeBSD 13.x”章节；2021 年 WireGuard 移除邮件列表讨论（freebsd-current@ 2021.3）；wg(4) 重写代码评审记录（Phabricator D30000 系列） ［A］

**史观**：总纲第 3 条——不存在进步，只有权力再分配：14.0 对 13.x 的延续体现在：稳定的 API/ABI 兼容性承诺（5 年支持周期至 2028.11）、对 32 位应用程序的运行时兼容（即使平台降级应用仍可运行）、base system 精简化的持续推进；终结体现在：32 位平台 RELEASE 构建的终止准备、sendmail 默认 MTA 地位的终结、New Reno TCP 的退场、csh/tcsh 作为 root 默认 shell 的终结——每一项终结都有明确的替代路径，“终结”在 BSD 历史中始终以“延续”为前提〔映射存疑，待主理人审定〕

**辨析**：需区分“平台 Tier 降级”与“32 位支持完全移除”两类事实——14.x 仍构建 i386 RELEASE 镜像并提供安全更新，**15.0 将是首个不再发布 i386 RELEASE 镜像的大版本**（原计划 14.0 为最后 32 位版本，后调整为 14.x 仍支持但 15.0 起移除）；armv6 在 14.0 前已降级为 Tier 3，armv7 在 14.x 周期内保持 Tier 2；riscv64 在 14.0 中仍为 Tier 2，尚未升为 Tier 1（aarch64 在 13.x 已为 Tier 1）

## 151.1.4 14.0 发布史料辨析

**要点**：14.0 发布工程团队由 Colin Percival（Release Engineering Lead）、Glen Barber（Deputy Lead for 14.0）、Mike Karels 等组成；14.0 在发布前经历了多次 BETA/RC 迭代，原计划发布日期从 2023 年 10 月底推迟至 11 月 20 日；14.0 是 Mike Karels 参与发布工程工作的最后一个大版本之一——他于 2024 年 10 月去世（14.2 献词给他）；FreeBSD 30 周年（2023.6.19）恰在 14.0 发布前五个月，项目未举办大规模官方庆典，但 freebsd-announce 与社区邮件列表有纪念讨论；14.0 发布时同期操作系统生态为：Linux 6.1 LTS（2022.12，含初始 Rust 代码）、Windows 11 22H2（2022.9）、macOS 14 Sonoma（2023.9）、OpenBSD 7.4（2023.10）、NetBSD 10.0 RC 阶段、DragonFly BSD 6.4（2022.12）

**史料**：FreeBSD 14.0 发布工程时间表（freebsd-releng@ 邮件列表）；Colin Percival 发布状态报告；FreeBSD 30 周年纪念讨论（freebsd-announce@ 2023.6 归档）；Mike Karels 讣告（14.2 公告 Dedication 部分） ［A］

**史观**：总纲第 2 条——历史是形式主义化的非存在：14.0 发布公告的固定格式（Date 行、Highlights 列表、Dedication、Availability、Download、Support、Acknowledgments、Checksums）是 BSD 发布工程形式主义成熟的标志——从 1993 年 1.0 发布公告的简单 Usenet 帖子到 2023 年高度结构化的 HTML/ASCII 双格式发布文档，发布流程本身已成为一种形式化仪式，但正是这种形式化保证了 30 年来发布质量的可预测性〔映射存疑，待主理人审定〕

**辨析**：Glen Barber 在 14.0 时为 Deputy Release Engineer，但在 14.1 后由 Mike Karels 接任 Deputy Lead，Mike Karels 去世（2024.10）后由 Ed Maste（埃德·马斯特） 接任 Deputy Lead——发布工程团队人事变动在 14.x 周期内较为频繁；FreeBSD 30 周年“低调纪念”与 Linux 30 周年（2021，Linux 0.01 于 1991.9.17 发布）的大规模庆祝形成对比，反映 BSD 社区与 Linux 社区不同的纪念文化：BSD 更倾向于代码本身的持续演进作为纪念，而非市场性庆典活动
