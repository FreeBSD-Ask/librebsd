# 144.12 重要贡献者群体与边缘者贡献

## 144.12.1 Clang/LLVM 迁移核心贡献者

**要点**：FreeBSD Clang/LLVM 迁移由一批核心 committer 历时多年完成，按主要贡献领域划分：①Roman Divacky（rdivacky@）——先锋探索者，2009 年 2 月首次宣布 Clang 可编译启动 i386/amd64 FreeBSD 内核，是迁移可行性的证明者；②Brooks Davis（brooks@）——项目协调人，2012 年 11 月宣布 x86 默认切换 Clang，长期参与工具链和架构支持工作；③David Chisnall（戴维·奇斯纳尔）（theraven@）——C++ 栈负责人，主导 libc++/libcxxrt 引入和 xlocale 实现，解决 C++11 支持问题；注意其姓名为 David Chisnall，非 “Theresa Chisnall”（这是对 theraven 用户名的误读）；④Dimitry Andric（dim@）——版本维护者，承担了历年 LLVM/Clang 版本导入、ports 兼容性修复和大量 bug 修正工作，是持续时间最长的日常维护者；⑤Ed Schouten（ed@）——早期贡献者，参与 2010-2012 年 Clang 导入和 world/kernel 修复；⑥Andrew Turner（andrew@）——arm64/AArch64 移植负责人，使 FreeBSD 在 ARM64 时代获得 Tier 1 地位；⑦Warner Losh（沃纳·洛什）（imp@）——GCC 4.2.1 退休执行者，推动 sparc64/mips 等旧架构的工具链切换或废弃；⑧Pawel Worach——早期测试和补丁贡献者（2012 Q1 status report 列为联系人之一）；⑨FreeBSD Foundation——资助多个工具链迁移子项目（包括 lld 默认切换、arm64 移植等）。

**史料**：FreeBSD Quarterly Status Report 2012 Q1（Clang 条目列出联系人 Brooks Davis/David Chisnall/Dimitry Andric/Ed Schouten/Pawel Worach/Roman Divacky）、Roman Divacky 2009 内核公告、Brooks Davis 2012 默认切换邮件、Andrew Turner arm64 提交记录、Warner Losh GCC 退休邮件、FreeBSD Foundation 年度报告。 ［B］

**史观**：总纲第 10 条——动手者创造历史：编译器迁移是典型的 “基础设施工程”——没有耀眼的新功能发布，没有媒体关注，只有经年累月的 bug 修复和兼容性调整。Divacky（2009 年首告内核可启动时甚至不是全职 committer）、Andric（做了最多日常版本维护和 bug 修复的无名英雄）、Worach（测试和补丁贡献者）等人的工作往往不在聚光灯下，但他们是迁移真正的基石。

**辨析**：David Chisnall 的姓名错误——原文件和多个中文资料中出现的 “Theresa Chisnall” 是对其用户名 **theraven@** 的误读（theraven → “The Raven” → 误联想为女性名字 Theresa），其 AsiaBSDCon 2014 论文作者署名明确为 David Chisnall，此错误已修正。

**文献**：FreeBSD Quarterly Status Report 2012 Q1 [R]；Chisnall D. LLVM in the FreeBSD Toolchain [C]//AsiaBSDCon 2014（作者署名 David Chisnall）；Divacky R. 2009 kernel announcement [EB/OL]；Davis B. 2012 default announcement [EB/OL].

## 144.12.2 许可证纯洁化其他组件贡献者

**要点**：除编译器外的许可证纯洁化子项目各有其主要贡献者：①bmake——Simon J. Gerraty 等人从 NetBSD 移植，10.0 默认替换 GNU make；②BSD grep——主要由 Gábor Kövesdán（gabor@）等人开发（基于 TRE 正则表达式库）；③BSD sort——Q1 2012 status report 报告为 Tim Kientzle 等人开发（原文件未具体记载，待进一步核）；④BSD patch——Pedro Giffuni（pfg@）移植 OpenBSD 版本，r246074（2013.1.29）导入，r253689 成为默认；⑤mandoc——Ingo Schwarze（英戈·施瓦茨）（OpenBSD）开发，FreeBSD 逐步引入作为 groff 替代；⑥ELF Tool Chain——Kai Wang、Joseph Koshy（约瑟夫·科希） 等人开发的 BSD 许可 ELF 工具；⑦lld/lldb 集成——由 Dimitry Andric、Ed Maste（埃德·马斯特） 等人维护；⑧Unbound——替代 BIND 导入 base；⑨BSD dialog——2024 年完成替换（FreeBSD 15），具体提交者待查。FreeBSD Foundation 资助了多个上述项目（Growing Filesystems Online、auditdistd、NAND 等非工具链项目也获得资助，但工具链迁移同样受益于 Foundation 资助）。

**史料**：FreeBSD 10.0 Announcement（bmake/Unbound 替换）、Pedro Giffuni 2013 WITH_BSD_PATCH 邮件（r246074）、FreeBSD Quarterly Status Report 2012 Q1（BSD-licensed sort 条目）、FreeBSD Foundation 年度报告（历年资助项目清单）。 ［B］

**史观**：总纲第 10 条——动手者创造历史：每个 GNU 工具的替换都是一个独立的小型工程项目，由 1-2 名核心开发者主导，历经数年渐进完成。这些工具替换工作在 Release Notes 中仅占一行，但背后是数百个 commit 和数千小时的测试工作。

**辨析**：BSD sort 的主要开发者在 Q1 2012 status report 中未明确署名（仅列为项目条目），需对照 SVN 历史确认具体贡献者；BSD dialog 的替换提交者和精确 commit hash 需查阅 FreeBSD Git 仓库（2024 年移除）。

**文献**：FreeBSD 10.0-RELEASE Announcement [Z]. 2014-01-20；Giffuni P. [CFT] WITH_BSD_PATCH [EB/OL]. freebsd-current, 2013-01-29；FreeBSD Quarterly Status Report 2012 Q1 [R]. ［A］

## 144.12.3 被忽视的测试者和 ports 贡献者

**要点**：Clang/LLVM 迁移的成功不仅依赖 base 系统 committer，大量 ports 维护者和测试者的工作同样不可或缺。迁移期间需要修复数千个 ports 软件的 Clang 兼容性问题（GCC 扩展依赖、嵌套函数、VLA in struct、特定 builtins、typeof 等），这些工作由数百名 ports committer 逐 port 完成。Ports 集群定期进行 Clang exp-run（全量 ports 树使用 Clang 编译测试），发现并报告编译错误。FreeBSD 10.0 之前的数年中，所有 -CURRENT 和 -STABLE 用户自愿测试 Clang 构建的 world/kernel，报告 bug 并提交补丁。这些测试者和 ports 贡献者构成了迁移的群众基础，但他们的名字大多湮没在邮件列表和 PR 数据库中。

**史料**：FreeBSD GNATS/ Bugzilla 数据库中 Clang 兼容性相关 PR、ports exp-run 报告、freebsd-current/freebsd-ports 邮件列表测试报告。 ［A］

**史观**：总纲第 10 条——动手者创造历史：大型基础设施迁移的真实成本不仅是核心开发者的编码时间，更是整个社区的测试和适配时间。每个修复 GCC 扩展的 ports 补丁、每次 -CURRENT 上的 Clang 构建测试、每一份 bug 报告都是迁移工程的组成部分。

**辨析**：ports 生态 Clang 兼容性修复的完整数量难以统计——FreeBSD ports 树包含约 30,000+ port（2014 年时约 24,000），大量 port 在迁移期间需要不同程度的补丁。

**文献**：FreeBSD Bugzilla [EB/OL]. bugs.freebsd.org（Clang keyword PRs）；FreeBSD Ports Collection [DB/OL]. ports.freebsd.org.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 144.12.4 史料辨析

**要点**：贡献者名单的史料主要来自 Quarterly Status Reports 联系人列表、commit log 作者字段、邮件列表发件人。Q1 2012 status report 的 Clang 条目明确列出 6 位联系人（Davis/Chisnall/Andric/Schouten/Worach/Divacky），这是 Clang 迁移核心团队最权威的一手名单。其他子项目（bmake/BSD patch/BSD grep/mandoc/ELF Tool Chain/lld 等）的贡献者需逐项目通过 SVN/Git 历史追溯，部分项目贡献者记录不完整。

**史料**：FreeBSD Quarterly Status Reports 2010-2014 工具链条目、SVN/Git commit log 作者字段、AsiaBSDCon/BSDCan 会议论文作者署名。 ［A］

**史观**：总纲第 10 条——动手者创造历史：开源历史的 “聚光灯效应” 使项目领导者（如 Lattner、Davis）被铭记，而日常维护者（如 Andric 多年版本导入）和测试者常被遗忘。历史书写应有意识地记录边缘贡献者。

**辨析**：Dimitry Andric（dim@）作为 LLVM/Clang 版本导入和日常维护的主要承担者，在公开演讲和媒体中曝光度远低于其实际贡献，这种 “维护者隐身” 现象在开源项目中普遍存在。

**文献**：FreeBSD Quarterly Status Reports [R]；FreeBSD commit log [DB/OL]. cgit.freebsd.org. ［A］

**要点**：

- TrueOS 宣布把重点转向核心操作系统，Project Trident 接管图形化 FreeBSD 桌面开发；Ken Moore（Lumina 开发者）、JT 等桌面团队成员转入 Trident，TrueOS 核心由 iXsystems 付费开发者继续维护，并以 JSON 清单系统方便他人基于 TrueOS 构建发行版。（BSD Now EP250，[88.90-271.86]，L1）
- BSDCan 2018 开发者峰会复盘记录：Deb Goodkin 介绍基金会工作，Core 团队汇报两年工作，Mariusz Strobl 介绍发布工程并讨论代码冻结策略，峰会还列出 FreeBSD 12 待完成特性并逐项指派责任人，讨论 OpenZFS 上游从 Solaris 仓库转向从各实现择优合入的趋势。（BSD Now EP250，[873.26-2534.62]，L1）
- LLVM 的 LLD 成为 FreeBSD AMD64 默认链接器：Ed Maste 约三年前开设 LLVM 元缺陷跟踪阻碍、约一年半前以 3 万包 exp-run 试编译，历经一年半修复 LLD 与 ports 后达成；特殊感谢 Antoine 反复跑 exp-run 与 Krion 排查 ports 失败并标记 LLD unsafe。（BSD Now EP250，[4500.88-4658.16]，L1）
- HardenedBSD 宣布推进在美国设立 501(c)(3) 非营利组织的计划，已确定六名董事会成员（含 Shawn Webb 等），以使其后的捐赠可获税收抵扣。（BSD Now EP250，[2640.70-2885.64]，L2）
- 两位当事人界定 Clang 与 LLVM 的分工：LLVM 是编译器后端，可承载自有语言与即时编译，Apple 即用它把 OpenGL 表达式现场编译为 SSE2、SSE3 指令以提升性能；Clang 则是 C、C++ 与 Objective-C 的前端解析器，借助 LLVM 生成最终二进制。（BSDTalk EP191，[149.68-210.42]，L1）
- 迁移进行时的实测状态：clangbsd 分支在 amd64 上已可完成 make buildworld 且结果可用，内核构建已稳定运作逾一年，Ed Schouten 自述已有约九个月不用 GCC 构建内核；代码质量约与老旧的 GCC 4.2 相当而尚不及 GCC 4.4、4.5，i386 的残余问题正在会议现场修复，开发者峰会已决议约两周内导入 head。（BSDTalk EP191，[211.42-293.38]，L1）
- 选择 Clang 的理由被概括为：速度快、对用户友好、生成代码质量可与 GCC 比肩、开发活跃，且不受 GCC 所携带的许可证问题困扰；开发者峰会决定其将以 Intel 架构随 FreeBSD 9 默认发布。（BSDTalk EP191，[106.60-135.68]，L1）
- 导入并非终点而是负担的起点：目前仅有五到十人测试 clangbsd 分支，进入 head 后全员测试将带来 bug 报告潮——Clang 产生的警告远多于现有 GCC，代码库并不干净；同时必须紧贴上游，重要修复即便一周两次也要导入，长期滞留同一版本会让 LLVM 开发者无从判断某 bug 是否已在现行代码中修复。（BSDTalk EP191，[584.98-692.94]，L1）
- 关于治理机制，当事人评价开发峰会不解决技术问题，却切实推动政治与决策：clang 导入的决定若非此前专门讨论工具链的峰会便不会发生；同类先例是 vimage 代码在 perforce 中搁置多年，峰会上一旦拍板即整组进入 SVN，表明集体决策场合能把长期僵持的工程变成现实。（BSDTalk EP191，[477.06-565.30]，L1）

- 总纲3 不存在进步，只有权力再分配：从 GCC 到 Clang 的迁移并不构成编译器技术线性进步的叙事——当事人承认 Clang 尚不及新版本 GCC——其真正驱动力是许可证权力结构的再分配：摆脱 GCC 附带的许可证问题，才是工具链权力易手的枢纽。（BSDTalk EP191，[135.68-142.68]，L1）
- 总纲5 没有必然性，只有偶然性：两位当事人进入 FreeBSD 的路径纯属偶然：Roman Divácký 做了半年 Linux 用户后由高中同学递来一张安装 CD 从此停留；Ed Schouten 则因 Eindhoven 大学全楼唯一有无线网的地方是 Unix 用户组而入会，再被周围同城的 FreeBSD 开发者劝动转用并开始提交补丁。宏大的工具链迁移正是由这类偶然个人轨迹汇聚而成。（BSDTalk EP191，[856.42-936.88]，L1）
