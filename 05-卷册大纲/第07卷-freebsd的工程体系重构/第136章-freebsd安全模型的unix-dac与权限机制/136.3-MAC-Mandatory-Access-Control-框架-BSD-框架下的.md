# 136.3 MAC（Mandatory Access Control）框架——BSD 框架下的 Biba、MLS、LOMAC、BSE、UGIDFW 等策略模块的设计与使用场景

## 135.3.1 MAC 框架的核心数据结构与策略接口
  - 要点：TrustedBSD MAC（Mandatory Access Control）框架由 罗伯特·N. M. 沃森（Robert Watson）发起，项目始于 2000 年，作为 DARPA CHATS（Composable High Assurance Trusted Systems）研究项目的一部分，首次在 FreeBSD 5.0-RELEASE（2003 年 1 月）中正式发布；MAC 框架是内核模块化安全策略框架，允许加载多个安全策略模块并通过策略组合（composition）实现复杂安全目标；核心数据结构包括 **mac(4)** 框架定义的 `mac_t` 标签结构（挂接到 inode、proc、socket、mbuf、ipq 等内核对象上）、策略模块的入口点向量（entry points，覆盖系统调用路径上的权限检查点）、标签管理 API（**mac_get(3)**/**mac_set(3)** 等用户态接口）；框架设计允许策略模块以可加载内核模块（KLD）形式动态加载/卸载，无需重新编译内核
  - 史料：TrustedBSD 项目官方网站 trustedbsd.org（记载 MAC 框架开发历史与设计文档）；FreeBSD 5.0-RELEASE Release Notes（2003-01-19，"Early Adopter's Guide" 章节详细记载 MAC 框架）；**mac(4)**、**mac_biba(4)**、**mac_mls(4)** FreeBSD 手册页；Watson 2012 年剑桥博士论文第 5 章详细描述 MAC 框架设计；FreeBSD src/sys/security/mac/ 目录源码（mac_framework.c 为框架核心）；McKusick, Neville-Neil, Watson 2014 DIFBSD2 第 6 章；**bsd_commits.db** `commits` 表 `freebsd-src` 仓库数据库验证——TrustedBSD MAC 框架系统调用号预留 commit 为 `11ffd032ff082eed4a77d28c37952577ea99afb1`，author = 罗伯特·N. ## 135.3.2 Biba/MLS/LOMAC 等策略模块的工程实现
  - 要点：FreeBSD 5.0 及后续版本包含多个 MAC 策略模块，各模块用途与引入时间如下：**mac_biba(4)** 实现 Biba 完整性模型（低水标完整性策略，防止低完整性数据污染高完整性对象），随 MAC 框架在 FreeBSD 5.0 引入；**mac_mls(4)** 实现多级安全（Multi-Level Security，MLS）保密性模型（Bell-LaPadula 模型，基于敏感度标签控制信息流），FreeBSD 5.0 引入；**mac_lomac(4)** 实现 Low-Watermark 完整性策略（LOMAC，与 Biba 类似的浮动标签模型），FreeBSD 5.x 引入；**mac_bsdextended(4)**（即 ugidfw）实现基于文件系统 UID/GID 的扩展 ACL 规则，通过 **ugidfw(8)** 工具管理，FreeBSD 5.x 引入；**mac_ifoff(4)** 提供接口防火墙功能（可动态禁用网络接口）；**mac_partition(4)** 将进程分区到独立的 process view（进程只能看到同分区其他进程）；**mac_portacl(4)** 实现端口 ACL（控制哪些用户/组可绑定到特定端口号）；**mac_seeotheruids(4)** 隐藏其他 UID 的进程（类似 Linux hidepid 选项）；**mac_none(4)**/**mac_stub(4)**/**mac_test(4)** 为测试/占位模块
  - 史料：各 MAC 策略模块手册页（**mac_biba(4)**、**mac_mls(4)**、**mac_lomac(4)**、**mac_bsdextended(4)**、**mac_portacl(4)**、**mac_seeotheruids(4)**、**mac_partition(4)** 等）；FreeBSD src/sys/security/ 目录各模块源码（mac_biba.c、mac_mls.c、mac_lomac.c、mac_bsdextended.c 等）；FreeBSD 5.x-7.x Release Notes 关于 MAC 模块的记录；**ugidfw(8)** 手册页 ［A］
  - 史观：总纲第 23 条——社区治理：MAC 策略模块的多样化反映了 FreeBSD 安全社区对 “安全无万能方案” 的共识——不同场景需要不同安全模型：军事/政府场景需要 MLS（保密性），完整性保护场景需要 Biba/LOMAC，简单服务器加固场景需要 mac_seeotheruids/mac_portacl 等轻量级模块；但这也导致 MAC 框架在通用服务器场景中配置复杂度高、默认不启用，与 OpenBSD pledge/unveil 的 “默认安全” 哲学形成对比
  - 辨析：mac_bsdextended（ugidfw）常被误认为是 ACL 实现，但它是 MAC 策略模块而非文件系统 ACL——FreeBSD 的 POSIX.1e ACL 支持通过 UFS/ext2fs/ZFS 等文件系统的扩展属性实现（**getfacl(1)**/**setfacl(1)**），ugidfw 是基于 MAC 框架的补充性规则引擎；“MLS 模块可直接用于军用分级环境” 说法不准确——mac_mls 提供 MLS 机制，但完整的高保证认证需要形式化验证、审计文档、Covert Channel 分析等大量配套工作，FreeBSD 本身未经过 Common Criteria EAL4+ 或更高等级认证

## 135.3.3 与 Linux LSM/SELinux 的架构比较
  - 要点：FreeBSD TrustedBSD MAC 框架与 Linux LSM（Linux Security Modules）在架构上有相似之处——两者均为内核安全钩子框架，允许加载不同安全策略模块；关键差异包括：(1) 设计起点——MAC 框架由 Watson 为 FreeBSD 从头设计（2000 年启动），LSM 由 Crispin Cowan 等人设计以将 SELinux 接入 Linux 主线（2001 年 LSM 补丁，Linux 2.6 正式合入）；(2) 策略组合——MAC 框架原生支持多策略模块并行加载与组合（MAC Policy Composition），LSM 在早期版本要求排他性加载单模块，直到 Linux 5.x 后才通过 stacking 改进；(3) 默认策略——FreeBSD GENERIC 内核包含 MAC 框架但默认不加载任何策略模块，主流 Linux 发行版（RHEL/CentOS/Fedora、Ubuntu 等）默认启用 SELinux 或 AppArmor；(4) 标签存储——MAC 框架标签可存储在文件系统扩展属性或内存中，SELinux 依赖 xattr 存储安全上下文；Apple macOS 的 Seatbelt（App Sandbox）和 XNU 内核的 MAC 框架源自 FreeBSD TrustedBSD——罗伯特·N. M. 沃森 本人参与了 Apple 的 MAC 框架移植工作
  - 史料：**mac(4)** 手册页 vs Linux **security_modules(7)** 手册页；Cowan C et al. Linux Security Modules: General Security Support for the Linux Kernel [C]. USENIX Security 2002; Watson R N M. The TrustedBSD MAC Framework (BSDCan 2004 演讲)；Apple XNU 源码中 MAC 框架痕迹（XNU 是 Darwin/macOS 内核，基于 FreeBSD 和 Mach）；Wright C et al. Linux Security Module Framework [C]. USENIX Security 2002
  - 史观：总纲第 6 条——技术路线分化：MAC 框架与 LSM 的分化是 FreeBSD 与 Linux 安全哲学差异的缩影——FreeBSD 倾向于 “提供机制而非策略”（mechanism, not policy），让用户/管理员选择是否启用安全模块；Linux 则倾向于 “默认启用合理安全配置”，以 SELinux/AppArmor 作为默认安全层；这一分化可追溯至两个社区的文化差异：BSD 强调用户选择权与系统最小化，Linux 强调开箱即用与安全加固默认值
  - 辨析：“Apple macOS 基于 FreeBSD 所以持有 FreeBSD 的安全认证” 说法是常见误解——macOS/Darwin 确实使用了 FreeBSD 的用户层组件和 TrustedBSD MAC 框架（衍生为 Seatbelt sandbox），但 macOS 作为独立操作系统单独持有 Common Criteria 认证（如 macOS 12 Monterey CC 认证），这些认证与 FreeBSD 本身无关；FreeBSD 项目本身从未持有 FIPS 140、Common Criteria、UNIX 03、FedRAMP 等形式认证，基于 FreeBSD 的产品（如 Apple macOS、TrueNAS、NetApp ONTAP、Juniper Junos、Sony PlayStation OS）的认证是产品级认证而非 OS 上游认证

  - 史料：FreeBSD 邮件列表存档 lists.freebsd.org/archives/freebsd-arch/（2000-2003 年 MAC 框架设计讨论）；TrustedBSD 项目文档 trustedbsd.org/mac/；Watson 2003 ; login: 文章；Watson 2012 博士论文第 5 章；FreeBSD SVN commit 历史（src/sys/security/mac/ 目录） ［A］
  - 史观：总纲第 3 条——形式主义膨胀：MAC 框架在 FreeBSD 5.0 中标记为 experimental（实验性），FreeBSD 5.x 系列是 "New Technology" 预览系列（5.0-5.5），生产环境用户普遍停留在 FreeBSD 4.x stable 分支直到 FreeBSD 6.0（2005 年 11 月）发布；MAC 框架在 FreeBSD 6.x/7.x 中逐步成熟，但始终未成为默认启用的安全层——这与 MAC 框架本身的设计哲学一致：为高安全需求场景提供工具，而非强制所有用户承担配置复杂度
  - 辨析：原大纲本节列入 "CVE-2002-0639" 和 "CVE-2024-6387" 等 OpenSSH 漏洞作为 MAC 框架史料系模板错误，这些漏洞与 MAC 框架无直接关联，已删除；原文献列表中 "Qualys 2024 regreSSHion"、"Lucas 2018 FreeBSD Mastery: Storage Essentials" 等与 MAC 框架无关文献已删除，替换为 MAC 框架专属一手文献；“TrustedBSD 是 NSA 项目” 说法不准确——NSA 是 TrustedBSD 项目资助方之一（通过 DARPA/SPARTA 等渠道），同时也资助了 SELinux，但 TrustedBSD 由 Watson 在社区主导开发
  - 文献：Watson R N M. The TrustedBSD MAC Framework: Extensible Kernel Access Control for FreeBSD 5.0 [J]. ; login:, 2003, 28(4); FreeBSD Project. FreeBSD 5.0 Early Adopter's Guide (2003); FreeBSD Project Mailing Lists. freebsd-arch@, trustedbsd-discuss@ Archives (2000-2005); Watson R N M. TrustedBSD Project Documentation. trustedbsd.org. ［A］
