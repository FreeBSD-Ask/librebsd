# 136.1 传统 UNIX 自主访问控制（DAC）基础——FreeBSD 安全模型的历史起点

## 136.1.1 UNIX 权限模型的核心机制：用户/组/other、读/写/执行、setuid/setgid

**要点**：FreeBSD 的基础安全模型继承自传统 UNIX 自主访问控制（Discretionary Access Control, DAC），该模型由 丹尼斯·里奇（Dennis Ritchie）和 肯·汤普森（Ken Thompson）在 1970 年代初的 UNIX 第一版中设计；核心机制包括：每个文件/目录有 12 个权限位——owner（用户）读/写/执行、group（组）读/写/执行、other（其他）读/写/执行，加上 setuid（设置用户 ID）、setgid（设置组 ID）、sticky bit 三个特殊位；setuid/setgid 机制允许程序以文件所有者（通常是 root）的权限运行，这是 UNIX 权限提升的核心机制，但也是历史上大量本地提权漏洞的来源；root 用户（UID 0）在传统 DAC 模型下拥有对系统的完全控制权，绕过所有权限检查——“root  omnipotent” 是传统 UNIX 安全模型最显著的特征也是最大的安全弱点

**史观**：总纲第 15 条——文化即形式主义：传统 UNIX DAC 是 FreeBSD 安全模型的 “源头时刻”——1970 年代初在 PDP-7/PDP-11 上设计的简单权限模型在五十多年后仍是 FreeBSD（以及所有类 UNIX 系统）安全的基础；这一模型的简单性（9 个基本权限位 +3 个特殊位）是其持久生命力的来源，但其 “root 万能” 的设计假设在网络时代成为严重安全缺陷；FreeBSD 后续所有安全机制（jail、MAC、Capsicum、W^X 等）本质上都是在 DAC 基础上添加约束，以缓解 root 全能模型的安全风险

**辨析**：“FreeBSD 抛弃了传统 UNIX 权限模型” 说法错误——传统 DAC 仍是 FreeBSD 默认且最基础的安全机制，MAC、Capsicum、jail 等是叠加在 DAC 之上的可选安全层，不是替代；“setuid 本身是安全漏洞” 说法不准确——setuid 是一种机制，其安全性取决于 setuid 程序的实现质量；历史上 BSD 对 setuid 程序的安全审计比其他 UNIX 变体更严格，但 setuid 程序仍是本地提权攻击的主要目标之一；[双库核查：2026-08-14] 本节要点所引 Ritchie & Thompson 1974《The UNIX Time-Sharing System》未在参考文献库直接命中（检索词“Time-Sharing System”仅命中 UNIX-HATERS Handbook、AFastFileSystemForUNIX、Reflections on Trusting Trust 等他篇），属两库无法验证，须待原文入库；参考文献库命中 reference_id=55（Kernighan《UNIX 传奇：历史与回忆》2021）可作 UNIX 早期权限模型背景的间接佐证

## 136.1.2 root 用户的全能性与安全限制演进

**要点**：在传统 UNIX DAC 模型中，UID 0（root）是 “超级用户”，内核中所有权限检查对 UID 0 直接放行；FreeBSD 历史上通过多种机制对 root 权限进行限制：**securelevel(7)** 机制（1990 年代初，4.4BSD 时代引入，通过 `kern.securelevel` sysctl 控制系统安全级别，高级别下 root 也无法执行某些操作如修改不可变文件、直接访问原始磁盘、加载内核模块等）；**jail(8)** 将 root 限制在 jail 内部；MAC 框架可进一步限制 root 操作；Capsicum 能力模式下即使是 root 也受能力描述符限制；FreeBSD 的 securelevel 有五个级别[存疑脚注：原文误作“四个级别”；FreeBSD Handbook 明确记载 'The kernel runs with five different security levels’，即 -1/0/1/2/3]：-1（完全禁用）、0（默认，不安全）、1（安全模式，不可修改不可变文件、不能加载模块）、2（高安全，进一步限制磁盘操作和原始套接字）、3（最高安全，与 2 类似但某些计时参数调整也被禁止）

**史料**：**securelevel(7)** 手册页；**security(7)** 手册页；FreeBSD Handbook Security 章节关于 securelevel 的说明；Kamp & Watson 2000 SANE 论文关于 jail 限制 root 的论述；McKusick, Neville-Neil, Watson 2014 DIFBSD2 第 6 章 ［A］

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧：root 全能模型是 1970 年代 UNIX 设计的历史遗产——当时 UNIX 是实验室多用户系统，root 是可信管理员，无需考虑远程攻击；网络时代的到来使 root 全能模型成为安全灾难——远程攻击者只要获得 root 权限就完全控制系统；FreeBSD 对 root 权限的限制演进（securelevel→jail→MAC→Capsicum）反映了操作系统安全从 “信任管理员” 到 “最小权限” 的范式转变

**辨析**：“FreeBSD 已消除 root 全能问题” 说法不准确——默认配置下 root 仍拥有极大权限，上述限制机制需管理员主动启用；securelevel 并非万能——securelevel 1 下仍有大量操作 root 可执行，且 securelevel 只能提升不能降低（除非重启到单用户模式）；“securelevel 越高越安全” 需权衡可用性——securelevel 2/3 会阻止许多正常管理操作；[双库核查：2026-08-14] 本节要点所称 securelevel 五个级别（-1/0/1/2/3）经参考文献库验证通过（检索词“securelevel”命中 reference_id=60《FreeBSD Handbook》，FreeBSD Documentation Project，其记载内核运行于五个安全级别），与本要点已按存疑脚注修正后的“五个级别”一致

- NFS 的安全本质近乎只凭 IP 地址认证：exports 文件限定分享给某个地址或网段即到头；这套模型内嵌了协议诞生年代的组织假设——服务器与计算机极其昂贵、网内任何机器默认由公司统一管理、用户账户处处一致并依赖集中账户系统（原称 Yellow Pages，因电话簿公司商标之争改称 YP、后为 NIS）；UID 数字信任链是其要害：服务器只告知远端某文件属于 UID 1000，把哪个用户对应哪个号码完全交由客户端决定，任何可控的 Unix 笔记本自建 UID 1000 即可冒充他人；叠加不同系统基础账户起始编号不同（有从 1000 有从 500），混用各版 BSD 与 Linux 的归属关系必然错乱。（BSDTalk EP20，[507.80-699.51]，L2）[订正：原 [498.16-699.51]，2026-09-29 SenseAudio 重转核对]
- 由此得出的家庭网络对策是假定全网与全部用户可信：导出一个目录并将其中所有文件设为全员可读写，反而防止把重要内容放进去，也免去了用户权限同步的全部复杂度——想在 NFS 上做真正的用户隔离并非不能，但需要成倍的额外功夫；主持人同时警告绝不要把可能带出门的笔记本身作 NFS 服务器，否则其导出清单会随机器流向外部网络；展望方面，NFSv4 承诺修补早期版本的缺陷，AFS 等分布式文件系统与模仿 Windows 共享模型的 Samba（有人主张将其确立为通用互联网文件系统标准）构成替代选项，主持人拒绝对后一争论表态。（BSDTalk EP20，[700.31-853.97]，L2）
