# 154.13 14.x 时期的技术淘汰与 base system 精简

## 154.13.1 telnetd 移除与远程登录工具演进

**要点**：FreeBSD 14.0 从 base system 中 **完全移除了** telnetd(8)****（Telnet 服务器守护进程），这是 base 系统精简的重要一步；Telnet 协议诞生于 1969 年（RFC 15），是互联网最早的应用层协议之一，但因其明文传输所有数据（包括密码）而被认为本质上不安全；FreeBSD 长期以来默认禁用 telnetd（需在 inetd.conf 中手动启用），但一直保留在 base 中；**telnet(1)** 客户端仍保留在 base 中（因为有时仍需用它调试纯文本协议如 SMTP/HTTP），但 telnetd 服务器已移除；这一移除延续了 FreeBSD 自 10.x/11.x/12.x/13.x 持续精简 base system 的趋势——先前已移除了旧版本 GCC、BSD games、GNU grep、许多老旧工具等

**史料**：FreeBSD 14.0 Release Notes “Removed Utilities” 章节；telnetd 移除 commit 历史；FreeBSD 14.0 UPDATING 文件 ［A］

**史观**：终结与延续：telnetd 的移除标志着一个互联网时代的终结——1980-1990 年代 Telnet 是远程登录 UNIX 主机的标准方式，SSH（Secure Shell）自 1995 年 Tatu Ylönen 发明后逐步取代 Telnet，到 2020 年代 Telnet 已完全退出实际生产使用（仅作为调试工具偶尔使用 telnet 客户端）；FreeBSD 保留 telnet 客户端但移除 telnetd 服务器的决策是务实的——客户端仍有调试价值，服务器无继续保留必要；这一移除也反映了 “base 只包含必要组件，其他通过 ports/pkg 安装” 的小 base 哲学

**辨析**：需要区分 “完全移除” 与 “默认禁用”——telnetd 是完全移除（源码树与安装镜像中都不再包含），而非仅仅默认禁用；用户若仍需要 telnetd 可从 ports 安装（telnetd 存在于 ports 中，或使用 net/telnetd 等替代实现）；OpenSSH 自 FreeBSD 4.0（2000 年）起即已在 base 中作为默认远程登录方式，telnetd 的移除在此后 23 年才发生，体现了 FreeBSD 对向后兼容性的极端重视——给用户二十多年时间迁移到 SSH

**文献**：FreeBSD Project. FreeBSD 14.0-RELEASE Release Notes — Removed Features [EB/OL]. (2023-11-20)[2026-07-19]. <https://www.freebsd.org/releases/14.0R/relnotes/>; Ylönen T. SSH — Secure Login Connections over the Internet [C]. USENIX Security Symposium, 1996; FreeBSD Project. telnet(1) Manual Page [EB/OL]. [2026-07-19]. <https://man.freebsd.org/telnet/1>.

## 154.13.2 其他组件退役与 base system 持续精简

**要点**：除 telnetd 外，14.x 周期内 base system 还有多项精简与组件退役：① 32 位平台 RELEASE 构建在 14.x 后终止（15.0 起不再发布 i386 安装镜像，见 [85.8](../../第04卷-大分裂与四大bsd的诞生/第85章-分裂时期的流行文化呈现/85.8-csrg解散与伯克利后csrg遗产.md)）；② 旧版本工具链组件进一步清理——GCC 早已从 base 移除（12.x/13.x 完成），14.x 完成纯 LLVM 工具链（clang、lld、libc++、libc++abi、libunwind）；③ 某些过时的用户态工具被标记为 deprecated 或在 14.x/15.x 过渡期规划移除；④ ports 中大量老旧无人维护的 port 被标记为 DEPRECATED 或移除，但这属于 ports 范畴而非 base；FreeBSD 14.0 还清理了一些旧的驱动与未维护的硬件支持

**史料**：FreeBSD 14.0 Release Notes “Deprecated Features” 与 “Removed Features” 章节；14.0 UPDATING 文件；src/ObsoleteFiles.inc 文件历史［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L1 代码；L3 官方文档〕

**史观**：总纲第 17 条——软件工程：base system 精简化是 FreeBSD 自 2010 年代以来持续的工程方向——“小 base” 哲学认为：操作系统内核与基础工具应保持精简，仅包含运行系统必需的组件，其他应用软件、服务、工具通过 pkg 安装；这与 Linux 发行版（特别是 RHEL/Debian 等 “大而全” 发行版）形成对比；小 base 的优势是安全攻击面小、升级复杂度低、维护负担轻，劣势是默认安装功能较少、需要用户自行安装更多包

**辨析**：base 精简并非随意删除——每个组件移除前都会经过邮件列表公开讨论、给出迁移路径（使用替代工具或从 ports 安装）、在 UPDATING 与 Release Notes 中提前多个版本预告；telnetd 的移除讨论在 freebsd-arch@ 持续了数年，最终达成共识才执行；某些组件（如 sendmail）虽然不再是默认，但仍保留在 base 中（因为有太多系统依赖它），这与 telnetd 的完全移除性质不同

**文献**：FreeBSD Project. ObsoleteFiles.inc Source File [Z]. cgit.freebsd.org/src/; FreeBSD Project. FreeBSD 14.0-RELEASE UPDATING Notes [EB/OL]. [2026-07-19]. <https://www.freebsd.org/releases/14.0R/relnotes/#upgrade>.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 154.13.3 32 位架构降级路径与平台支持演进

**要点**：架构平台降级在 14.x 周期内持续进行：① i386（32 位 x86）在 14.x 中仍为 Tier 2 并提供 RELEASE 镜像，但已明确预告 15.0 起停止 RELEASE 构建；② armv6 在 14.0 前已降级为 Tier 3；③ armv7 在 14.x 中保持 Tier 2，但未来降级路径已在讨论；④ MIPS 架构在 13.5 为最后支持版本，14.0 起已从源码树移除 [考据脚注：经 FreeBSD 官方 platforms 页面（2026-05-08 更新）确认，MIPS 全系列（mips/mipsel/mipshf/mipselhf/mipsn32/mips64/mips64el/mips64hf/mips64elhf）最后支持版本均为 13.5，14.x 平台列表中已无 MIPS。]；⑤ powerpc（32 位）、powerpcspe 等老旧 PowerPC 架构逐步降级；⑥ riscv64 保持 Tier 2 并持续完善，升 Tier 1 条件尚未成熟；⑦ aarch64（arm64）作为 Tier 1 在 14.x 中持续成熟，支持越来越多的服务器与开发板硬件；架构 Tier 调整由 Core Team 与 re@ 团队根据活跃开发者数量、用户基数、企业赞助等因素综合评估决定，调整前会提前多个版本预告

**史料**：FreeBSD 支持平台页面（freebsd.org/platforms/）；各架构 Tier 调整公告；Core Team 架构支持声明 ［A］

**史观**：硬件与软件辩证：平台支持的兴衰是硬件市场发展的直接反映——Intel/AMD x86 与 ARM 64 位是当前通用计算市场的主导架构，RISC-V 正在崛起，MIPS、32 位 PowerPC、armv6/7、i386 等架构要么市场萎缩、要么生态消亡，OS 不可能无限制支持所有老旧架构；FreeBSD 的 Tier 系统提供了透明的支持级别声明，让用户可以根据架构支持级别做出合理的部署决策

**辨析**：需区分 “平台 Tier 降级” 与 “代码移除”——降级到 Tier 3 意味着不再提供 RELEASE 镜像与安全更新，但代码仍保留在源码树中，感兴趣的开发者可自行编译；代码完全移除是最终步骤，通常发生在降级后多个版本、确认无活跃开发者维护时；相比 Linux 内核仍保留大量老旧架构代码但发行版放弃支持，FreeBSD 的 Tier 系统对用户更透明

**文献**：FreeBSD Project. Supported Architectures and Tier List [EB/OL]. [2026-07-19]. <https://www.freebsd.org/platforms/>; FreeBSD Core Team. Architecture Support Policy [EB/OL]. [2026-07-19]. freebsd-arch@ archives. ［A］

## 154.13.4 技术淘汰史辨析：CSRG 传统与现代精简

**要点**：FreeBSD 的 base 精简哲学与 CSRG 传统一脉相承又有重要区别——4.2BSD/4.3BSD 时代（1980 年代）的 BSD 发行版包含完整的源代码与全套工具，“UNIX 即完整操作系统” 是当时的理念；而现代 FreeBSD 面对的生态环境完全不同——开源软件数量爆炸式增长，一个 OS 不可能在 base 中维护所有软件，通过 pkg 安装第三方软件是主流模式；FreeBSD 的精简不是 “功能缺失”，而是明确的职责划分：base 系统提供一个稳定、安全、自洽的最小基础环境，ports/pkg 提供应用生态；这一哲学与 BSD 许可证的自由度相结合，使 FreeBSD 既保持了内核与基本系统的高质量，又通过 ports 提供了海量软件（超过 40,000 个 port）

**史料**：CSRG BSD 发行版历史；4.3BSD/4.4BSD 发行说明；FreeBSD Porter's Handbook；pkg 项目历史 ［B］

**史观**：技术路线分化：不同 OS 的 base 策略反映了其设计哲学——OpenBSD 倾向于在 base 中包含更多安全关键组件（如 smtpd、httpd、bgpd 等都是 OpenBSD 重写并放入 base），因为 OpenBSD 哲学强调 “自己编写安全关键代码”；Linux 发行版差异很大——Alpine Linux 追求极简 base，Debian/RHEL 追求大而全；FreeBSD 选择中间路线：base 包含内核、C 库、编译器/工具链、核心系统工具、SSH、ZFS、bhyve/Jail 虚拟化等关键组件，应用软件放到 ports

**辨析**：关于 “sendmail 为何仍留在 base 而 telnetd 被移除” 的对比很有启发性——sendmail 虽然不是默认 MTA，但系统工具（如 periodic 脚本、cron 邮件通知）仍依赖 sendmail 命令行接口（即使实际运行的是 dma），直接移除会破坏大量脚本与系统功能；而 telnetd 服务器没有这种系统级依赖——系统本身不需要运行 telnetd，只有主动启用的用户才需要它，因此可以安全移除并让需要的用户从 ports 安装

**文献**：McKusick M K, Bostic K, Karels M J, Quarterman J S. The Design and Implementation of the 4.4BSD Operating System [M]. Addison-Wesley, 1996. ISBN 0-201-54979-4; FreeBSD Project. FreeBSD Porter's Handbook [EB/OL]. [2026-07-19]. <https://docs.freebsd.org/en/books/porters-handbook/>; OpenBSD Project. OpenBSD Base System Components [EB/OL]. [2026-07-19]. <https://www.openbsd.org/>. ［B］
