# 169.1.4 方法论反思

本卷史家在使用上述史料时遵循三条方法论原则，但亦须反思其局限与盲区。
第一，0 信任原则的叠加适用。本卷对所有史料——包括 FreeBSD 官方公告、当事人技术论文、**freebsd.duckdb** 代码档案、邮件列表讨论——均施加 0 信任检视，不因“一手”身份而免检。这一原则的实践路径是“三角验证”：每个关键事实须有至少三类独立来源相互印证。然而 0 信任原则亦有局限：当多个来源均源于同一社区（如 FreeBSD Core Team 的官方公告与 Foundation 年度报告）时，“三角”退化为“两角”，验证效力下降。本卷对 Core Team 内部决策、Foundation 资助策略等议题的叙述因此保持克制，避免在证据薄弱处强作结论。
第二，当事人叙述与档案证据的认识论距离。本卷时间范围内多数关键决策的当事人（Baldwin、Maste、Guzik 等）仍活跃于 FreeBSD 社区，其个人博客、邮件列表回忆、会议演讲构成当事人叙述的密集来源。当事人叙述兼具一手陈述与自利偏差双重性质——作为参与者，其陈述是事件最直接记录；作为当事人，其可能美化个人立场、转嫁责任、重构决策动机。Clang/LLVM 迁移决策的当事人叙述尤其须警惕事后重构动机的风险。
第三，合规认证叙事的概念边界。本卷安全模型章节涉及 Common Criteria、FIPS 140 等合规认证，须严格区分 FreeBSD Project 的安全基础设施与商业产品的合规认证。这一概念边界的维持须以 FreeBSD Project 官方文档与商业产品认证文档双重核对，避免将商业产品认证归功于 FreeBSD Project。
本卷方法论的主要盲区有三：其一，Core Team 内部决策记录的缺位——Clang/LLVM 迁移、GPLv3 争议等决策的 Core Team 内部讨论记录未公开；其二，商业用户认证档案的沉默——pfSense、OPNsense、Junos OS 等商业产品的合规认证档案受商业保密约束；其三，跨系统比较的深度不足——本卷对 FreeBSD 与 Linux、OpenBSD 的安全模型比较偏重技术层面，对合规认证生态的比较有待深化。
