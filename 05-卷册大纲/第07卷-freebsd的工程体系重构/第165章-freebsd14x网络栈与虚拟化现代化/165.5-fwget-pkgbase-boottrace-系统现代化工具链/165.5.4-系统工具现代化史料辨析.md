# 165.5.4 系统工具现代化史料辨析

**要点**：14.0 还包含 NFS-over-TLS 支持（rpc.tlsclntd/rpc.tlsservd 守护进程在 amd64/arm64 默认构建）、**growfs(7)** 启动脚本支持自动添加 swap 分区、hostid 脚本生成随机 UUID、FIB 默认路由支持（defaultrouter_fibN rc.conf 变量）、zfskeys 自动解密 ZFS 加密数据集等实用改进；NLS/C locale 改进——C.UTF-8 locale 作为默认 locale 之一提供更好的 Unicode 支持；LLVM/Clang 作为默认系统编译器（14.0 版本 16/17、14.1 版本 18.1.5、14.3 版本 19.1.7），GCC 不再作为 base 编译器（仅可从 ports 安装）；libc++/libc++abi/libunwind（LLVM C++ 标准库）完全取代旧的 libstdc++/libsupc++；LLD（LLVM 链接器）成为默认链接器，lldb 调试器作为 LLDB 提供

**史料**：FreeBSD 14.0/14.1/14.3 Release Notes Userland/Compiler 部分；LLVM 版本更新 commits；Clang/LLVM 在 FreeBSD 上的历史（自 FreeBSD 10.x 引入 Clang，FreeBSD 13/14 完成向纯 LLVM 工具链的过渡） ［A］

**史观**：软件工程：FreeBSD 从 GCC 到 Clang/LLVM 的完整工具链切换始于 2012 年（FreeBSD 10.0 引入 Clang 作为 amd64 默认编译器），历时约 11 年（2012-2023）在 14.0 中完全完成——这一渐进过程是 FreeBSD 软件工程保守风格的典型：大变更横跨多个大版本，给生态与开发者充足的适应时间

**辨析**：GCC 从 base 移除不代表不能使用 GCC——gcc 与 g++ 仍可通过 ports 安装（lang/gcc 提供最新 GCC），但 base 系统完全由 Clang/LLVM 构建；某些非常老的软件可能依赖 GCC 扩展语法，需要通过 ports 编译时指定 GCC；BSD make（bmake 与 FreeBSD make）与 GNU make（gmake）的差异持续存在——ports 中使用 GNU make 的软件通过 USES = gmake 指定
