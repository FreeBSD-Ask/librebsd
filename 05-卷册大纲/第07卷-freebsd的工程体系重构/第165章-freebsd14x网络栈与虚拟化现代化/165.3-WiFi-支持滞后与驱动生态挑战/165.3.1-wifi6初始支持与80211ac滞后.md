# 165.3.1 WiFi 6 初始支持与 802.11ac 滞后

**要点**：FreeBSD WiFi 支持长期被社区批评为落后于 Linux——14.0 带来了 **WiFi 6（802.11ax）初始支持**，但远未成熟；802.11ac（WiFi 5）支持在 14.0 时仍不完善——Linux 自 2013 年左右就有稳定的 802.11ac 支持，FreeBSD 落后近十年；14.3（2025.6）中 iwlwifi（Intel WiFi）驱动开始支持 802.11ac；14.x 时期 FreeBSD 有三款 WiFi 驱动初步支持 WiFi 6：iwlwifi（Intel AX2xx/BE2xx 系列，基于 Linux iwlwifi 驱动通过 LinuxKPI 层移植）、rtw89（Realtek 8852AE/BE 等，同样基于 LinuxKPI）、mt76（MediaTek MT79xx 系列）；这些驱动通过 LinuxKPI（Linux Kernel Programming Interface）兼容层运行 Linux 驱动代码——FreeBSD 内核提供 Linux 内核 API 的子集实现，允许 Linux 网络驱动以相对较小的改动移植到 FreeBSD；LinuxKPI 层由多个开发者维护，是 FreeBSD 缩短 WiFi 驱动差距的主要工程策略

**史料**：FreeBSD 14.0/14.3 Release Notes WiFi 章节；LinuxKPI 与无线驱动 commits（cgit.freebsd.org/src/ sys/compat/linuxkpi/ 与 sys/dev/iwlwifi/ 目录）；FreeBSD Wiki WiFi 页面；2024-2025 年 FreeBSD 笔记本电脑支持项目进展报告 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：WiFi 驱动差距是 FreeBSD 面临的结构性挑战——WiFi 芯片厂商（Intel、Realtek、Broadcom、MediaTek、Qualcomm）几乎不为 BSD 提供官方驱动或技术文档，所有现代 WiFi 驱动都是从 Linux 内核移植而来；Linux 庞大的用户基础与厂商投入使其成为 WiFi 驱动开发的主战场，FreeBSD 通过 LinuxKPI 共享 Linux 驱动代码是务实的 “搭便车” 策略，但也导致驱动功能滞后于 Linux 主线；这一结构性差距短期内无法消除

**辨析**：需区分 “完全重写 BSD 原生驱动” 与 “通过 LinuxKPI 移植 Linux 驱动” 两种策略——FreeBSD 历史上的 WiFi 驱动（如 ath、iwn）为 BSD 原生驱动，但现代 WiFi 芯片（特别是 Intel AX/BE 系列、Realtek 6GHz 系列）复杂度极高（固件加载、MAC 层处理、MIMO、OFDMA、加密等），完全重写成本极高；LinuxKPI 策略是在资源有限条件下缩小差距的唯一可行方案，但也导致 FreeBSD WiFi 驱动依赖 Linux 内核 API 的兼容性
