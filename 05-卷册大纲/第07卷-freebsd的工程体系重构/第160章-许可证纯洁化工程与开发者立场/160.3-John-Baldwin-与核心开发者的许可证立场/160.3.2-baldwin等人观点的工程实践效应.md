# 160.3.2 Baldwin 等人观点的工程实践效应

**要点**：以 Baldwin、Brooks Davis、Warner Losh（沃纳·洛什）、Dimitry Andric、Ed Schouten 等为代表的当代核心开发者采取工程务实主义立场，这一立场在实践中体现为：推进 Clang 迁移但保留 GCC 支持路径（ports/devel/gcc）；按架构逐个完成 Clang 迁移而非 “一刀切”；在许可证纯洁化过程中重视 ports 生态兼容性；对非 GPLcopyleft 许可证（如 CDDL、MPL、APL）采取宽容态度（DTrace 采用 CDDL 许可，ZFS 采用 CDDL 许可均被接受入 base）。这种务实平衡使得 FreeBSD 既能完成许可证纯洁化，又未像某些更激进的许可证清理项目那样过度伤害生态。Warner Losh 作为 GCC 4.2.1 退休的执行者，在 freebsd-arch 邮件中明确表示 “现在所有受支持的架构都使用 Clang 或依赖外部工具链（来自 ports 的现代 GCC）”，标志着 GCC 从 base 退出的正式完成。

**史料**：Warner Losh 2018 年 GCC 4.2.1 退休邮件（freebsd-arch）、FreeBSD 12.0 Release Notes、FreeBSD src.conf(5) WITHOUT_GCC/WITH_CLANG 选项文档。 ［A］

**史观**：总纲第 3 条——不存在进步，只有权力再分配：Core Team 务实平衡的治理风格是 FreeBSD 能够完成十余年许可证纯洁化工程而未发生社区分裂的关键。对比某些开源项目因许可证争议导致 fork 的案例，FreeBSD 的共识治理模式展现了其成熟度。治理形态的稳定宜作权力再分配结构未生裂变的解读，而非单向进步叙事。

**辨析**：CDDL 许可证的 ZFS/DTrace 在 FreeBSD base 中存在这一事实，证明 FreeBSD 的 “许可证纯洁化” 并非对所有 copyleft 许可证的意识形态排斥，而是针对 GPLv3 特定条款的风险评估——CDDL 是文件级 copyleft 不传染 BSD 代码，经法律审查确认可以共存。

**文献**：Losh W. GCC 4.2.1 retirement announcement [EB/OL]. freebsd-arch mailing list, 2018 (cited in multiple sources)；FreeBSD src.conf(5) man page. ［A］
