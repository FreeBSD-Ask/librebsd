# 155.18 第三方软件变更——sendmail→DMA 默认 MTA 切换与 OpenSSL 3.0

## 155.18.1 sendmail→DMA：默认 MTA 从 sendmail 替换为 DragonFly Mail Agent

**要点**：FreeBSD 14.0-RELEASE（2023 年 11 月 20 日）将 DMA（DragonFly Mail Agent）设为 base system 的默认 MTA，替换自 4.1cBSD（1982 年）起服役 41 年的 sendmail。DMA 由 Matthias Schmidt 为 DragonFly BSD 项目开发，是一款轻量级 MTA，专为无需完整邮件服务器的桌面/客户端系统设计——仅负责本地邮件投递（如 cron 输出、系统通知）与通过外部 smarthost 转发，不具备 sendmail 的完整 MTA 功能（如邮件队列管理、反垃圾邮件、虚拟域等）。14.0 的默认 MTA 切换体现了 “默认情况下大部分 FreeBSD 系统不需要完整 MTA” 的设计哲学——需要完整邮件服务器功能的用户可从 ports 安装 sendmail、Postfix、Exim 等。sendmail 仍可通过 ports（mail/sendmail）安装，14.0 的 /etc/mail/mailer.conf 默认指向 dma 而非 sendmail。这是 FreeBSD 历史上最显著的 “上古组件退役” 事件之一，与 BIND 移除（10.0）、GCC 移除（13.0）并列。

**史料**：FreeBSD 14.0-RELEASE Announcement（2023-11-20，明确 DMA 替换 sendmail 为默认 MTA）、FreeBSD 14.0 Release Notes（Userland Changes 章节）、DragonFly BSD dma 项目主页、sendmail 历史［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：技术债务：sendmail 是 BSD 系统中资历最老的技术债务——其 sendmail.cf 配置语法以晦涩难懂著称，安全性历史上多次出现严重漏洞（如 1988 年 Morris 蠕虫利用 sendmail 漏洞），从社区讨论替换（2000 年代中期）到实际替换（2023 年）历时近 20 年；总纲第 25 条——终结与延续：sendmail 默认地位的终结是 BSD 传统 MTA 时代的终结，但 sendmail 作为 ports 仍可安装，DMA 延续了 “本地邮件投递” 功能，简化了大多数用户的系统配置

**辨析**：需严格区分 “sendmail 从 base 移除” 与 “sendmail 不再是默认 MTA”——14.0 中 sendmail 仍存在于 base 源码树中（作为构建依赖或被其他组件使用），但不再是默认 MTA，DMA 成为默认；DMA 的功能范围远小于 sendmail——DMA 不支持监听外部 SMTP 连接、不支持邮件队列管理、不支持反垃圾邮件，仅适用于 “本地投递 + 外部 smarthost 转发” 场景，需要完整邮件服务器的用户必须从 ports 自行安装 MTA；DMA 来自 DragonFly BSD 项目，14.0 的 DMA 移植由 FreeBSD 开发者完成，是 BSD 家族内部代码共享的又一案例

## 155.18.2 OpenSSL 3.0 引入与许可证变更

**要点**：FreeBSD 14.0-RELEASE 搭载 OpenSSL 3.0.12（14.0）→ 3.0.13（14.1）→ 3.0.14（14.2）→ 3.0.16+（14.3-14.4），这是 FreeBSD 首次将 OpenSSL 从 1.1.1 系列升级至 3.0 系列。OpenSSL 3.0 的主要变化包括：将许可证从 OpenSSL License 改为 Apache 2.0（解决了 20 年的 GPL 兼容性争议）、引入 Provider 架构（模块化加密算法提供者）、FIPS 140-3 模块支持、改进的随机数生成器、新的 API 架构。OpenSSL 3.0 是 LTS 版本，支持至 2026 年 9 月 7 日。14.x 搭载的 OpenSSH 版本从 9.5p1（14.0）升级至 9.8p1（14.4），14.4 默认启用混合后量子密钥交换（<sntrup761x25519-sha512@openssh.com>）。

**史料**：FreeBSD 14.0-14.4 Release Notes（OpenSSL/OpenSSH 版本号）、OpenSSL 3.0 Release Notes、OpenSSL 3.0 License Change 公告［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：许可证：OpenSSL 3.0 的许可证从 OpenSSL License 改为 Apache 2.0 是 2020 年代最重要的开源许可证变更之一——OpenSSL License 与 GPL 兼容性长期存在争议（OpenSSL 在许可证中加入了 “广告条款” 风格的附加限制），Apache 2.0 消除了这一争议，使 OpenSSL 代码可被 GPL 项目无条件使用；软件工程：OpenSSL 3.0 的 Provider 架构是加密库模块化设计的重大进步，允许第三方通过 Provider 插件提供加密算法实现（如硬件加速、后量子算法），无需修改 OpenSSL 核心代码

**辨析**：OpenSSL 3.0 的 API 不向后兼容 1.1.1——从 1.1.1 升级到 3.0 需要修改应用程序代码（如使用新的 EVP 高级 API 替换低级 API 调用），这是 FreeBSD 将 OpenSSL 3.0 升级推迟至 stable/14 而非在 stable/13 中期引入的原因

## 155.18.3 第三方软件变更的史料辨析

**要点**：14.0 的第三方软件变更以 “默认配置现代化” 为主题——sendmail→DMA 默认 MTA 切换、root 默认 shell 从 csh 切换为 sh（/bin/sh）、telnetd 从 base 移除等，这些变更的共同特征是 “将 1980-1990 年代的默认配置替换为 2020 年代更安全、更简洁的默认配置”。14.0 的变更与 10.0 的 “集中换代” 不同——10.0 是 “一整批新组件的引入”，14.0 是 “一整批旧组件的退役或默认地位变更”。这体现了 FreeBSD 项目在 30 周年后对 “何为生产级 OS 的合理默认配置” 的重新审视。

**史料**：FreeBSD 10.0/14.0 Release Notes 对比［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：总纲第 25 条——终结与延续：14.0 的 sendmail 默认地位终结、telnetd 移除、root 默认 shell 切换是 “旧时代的终结”，但 DMA 替换 sendmail 是 “新时代的延续”——FreeBSD 仍然需要本地邮件投递，只是不再需要 1980 年代的完整 MTA；总纲第 9 条——简洁与复杂的辩证：14.0 的默认配置变更是 “做减法”——更少的默认服务、更少的攻击面、更简洁的默认配置，这是安全工程的基本原则

**辨析**：sendmail 的默认地位终结与 GCC 的完全移除（13.0）在性质上不同——sendmail 仍存在于 base 中（非默认），GCC 已从 base 完全移除；telnetd 的移除是 “从 base 移除”（非仅默认地位变更），端口 net/freebsd-telnetd 提供接续路径；root 默认 shell 切换从 csh→sh 是交互式 shell 的变更，sh 作为系统脚本 shell 早已是默认
