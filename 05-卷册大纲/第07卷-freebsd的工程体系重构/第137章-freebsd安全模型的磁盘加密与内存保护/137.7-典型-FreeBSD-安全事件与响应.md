# 137.7 典型 FreeBSD 安全事件与响应

## 137.7.1 2001-2002 年：早期远程漏洞与安全流程正规化

**要点**：FreeBSD 4.x 时代（2000-2003）发生过一系列影响默认服务的高危远程漏洞，包括：ftpd 漏洞（多个远程漏洞，包括 CVE-2001-0053 等）、sendmail 漏洞（sendmail 是 FreeBSD 4.x 默认 MTA）、telnetd 漏洞、以及 CVE-2002-0639 OpenSSH 挑战-应答漏洞；这些漏洞推动了 FreeBSD 安全流程的正规化：Security Officer 角色更明确、安全公告 PGP 签名成为标准、默认服务配置从 “默认开启” 转向 “默认关闭非必要服务”；FreeBSD 在 4.x 早期（crypto 框架期，2000 年前后）即随 USRSA 限制解除将 OpenSSH 纳入 base 系统〔原稿“4.4（2001 年）引入”存疑，纳入版本按 src 历史与 UPDATING 待核〕以替代 telnet/rlogin/rsh 等明文远程登录协议，但 OpenSSH 本身很快就遇到了 CVE-2002-0639 这样的高危漏洞

**史料**：FreeBSD-SA 公告存档 2000-2003 年；FreeBSD 4.x Release Notes 默认服务配置变化；CVE-2001-0053（ftpd）、CVE-2002-0639（OpenSSH）等 MITRE CVE 条目；freebsd-security@ 邮件列表 2001-2002 年档案 ［A］
    FreeBSD 社区论文：[FP-2026-002] Supporting hibernate on FreeBSD（Olivier Certner，2026）<https://papers.freebsd.org/2026/bsdcan/certner-supporting_hibernate_on_freebsd/>
    FreeBSD 社区论文：[FP-2024-012] Scheduling Priorities and FreeBSD: A deep dive (and sweep)（Olivier Certner，2024）<https://papers.freebsd.org/2024/eurobsdcon/certner-scheduling_priorities_and_freebsd/>
    FreeBSD 社区论文：[FP-2024-008] rtprio(2) and POSIX(.1b) priorities, and their FreeBSD implementation: A deep dive (and sweep)（Olivier Certner，2024）<https://papers.freebsd.org/2024/asiabsdcon/certner-scheduling_priorities_in_freebsd/>
    FreeBSD 社区论文：[FP-2003-008] The TrustedBSD MAC Framework: Extensible Kernel Access Control for FreeBSD 5.0（Robert N. M. Watson（罗伯特·N·M·沃森），2003）<https://papers.freebsd.org/2003/rwatson-mac_framework/>

**史观**：总纲第 15 条——文化即形式主义：正如 Morris 蠕虫（1988）催生了 CERT，一系列高危远程漏洞在 2001-2002 年推动了 FreeBSD Security Team 流程的正规化——从松散的志愿者响应转向更有组织的安全公告、协调补丁、多渠道通知；默认服务关闭策略的转变是痛苦但必要的——许多用户依赖默认开启的服务，但互联网环境已从 1980-90 年代的信任网络变为充满攻击的 hostile network

**辨析**：CVE-2002-0639（OpenSSH 远程 root RCE）是 OpenSSH 上游漏洞，非 FreeBSD 独有——所有集成受影响 OpenSSH 版本的 OS 均受影响；参见相关章节计算机安全史部分关于该漏洞及 OpenSSH 安全文化的详述，本节仅聚焦 FreeBSD 响应层面；2002 年 freebsd-update 尚未存在，用户需手动应用源码补丁

**文献**：FreeBSD Project. FreeBSD-SA Archives (2000-2003). security.freebsd.org; MITRE CVE Database: CVE-2001-0053, CVE-2002-0639; 参见相关章节计算机安全史部分。［A］

## 137.7.2 2010 年：Gregory Perry IPsec 后门指控

**要点**：2010 年 12 月 11 日，Gregory Perry（自称前 FBI 技术顾问、NetSec 前 CTO）向 Theo de Raadt（西奥·德·若特） 发送邮件，声称其与 FBI 的保密协议刚到期，FBI 曾通过 NetSec 公司向 OpenBSD 的 OCF（OpenBSD Cryptographic Framework）中植入后门，Jason Wright 等开发者被指参与此事；Theo de Raadt 选择公开该邮件，引发开源安全社区广泛讨论；FreeBSD 作为也采用了 OCF 框架（从 OpenBSD 移植）的操作系统，社区也进行了代码审计和讨论；需要明确的是：Perry 的指控从未提供代码级证据，OpenBSD/FreeBSD 社区进行了独立审计但未发现所谓后门；OCF（OpenBSD Cryptographic Framework）是加密硬件加速框架，FreeBSD 从 OpenBSD 移植了 OCF 用于内核加密加速；FreeBSD 的 IPsec 实现主要源自 KAME 项目（日本 WIDE 计划），而非 OpenBSD 原生 IPsec

**史料**：Gregory Perry 2010-12-11 致 Theo de Raadt 邮件原文（公开转发至 openbsd-tech 等邮件列表）；Theo de Raadt 公开该邮件的回复；FreeBSD 邮件列表 freebsd-security@ 2010 年 12 月关于此事件的讨论；OpenBSD 邮件列表 openbsd-tech 2010 年 12 月讨论；FreeBSD src/sys/opencrypto/ 目录审计记录 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：Perry 后门指控事件触及了开源社区对 “政府干预加密” 的深层焦虑——斯诺登事件（2013 年）三年前，这一指控提前引发了关于开源加密软件是否可能被情报机构植入后门的大讨论；虽然 Perry 的指控没有实据，但它强化了开源社区 “代码可审计是安全的基础” 这一信念，也暴露了 “代码可审计不代表代码被审计” 的开源安全审计局限性

**辨析**：该事件主要围绕 OpenBSD OCF 框架，但 FreeBSD 也使用了从 OpenBSD 移植的 OCF 代码——FreeBSD 社区在事件后对 crypto/ocf 子系统进行了代码审计，未发现后门；Jason Wright 本人公开否认了相关指控；“Perry 指控已被证实” 说法错误——该指控从未提供具体代码证据，社区审计未发现后门，此事最终作为无证据指控平息；参见相关章节计算机安全史部分关于该事件的详述，本节仅聚焦 FreeBSD 视角

**文献**：Perry G. Email to Theo de Raadt (2010-12-11). OpenBSD Mailing List Archives; FreeBSD Project Mailing Lists. freebsd-security@ Archives (Dec 2010); Ars Technica. OpenBSD founder claims FBI planted backdoors in IPsec stack (2010-12-15); 参见相关章节计算机安全史部分。［A］

## 137.7.3 2012 年：项目服务器入侵事件

**要点**：2012 年 11 月 17 日，FreeBSD Security Team 发布公告称两名项目服务器被未授权访问；入侵时间线：攻击者首次访问发生在 2012 年 9 月 19 日，入侵方式是窃取一名开发者的 SSH 密钥，而非利用 FreeBSD 软件漏洞；受影响服务器是用于构建第三方软件包（packages）的基础设施服务器；Security Team 立即关闭受影响服务器，审计了构建环境和二进制包完整性，确认没有对二进制包进行未授权修改，但建议在 9 月 19 日至 11 月 11 日之间下载包的用户核实包完整性；该事件推动了 FreeBSD 基础设施安全改进：强制双因素认证（2FA）、SSH 密钥更新、构建环境隔离增强、包签名机制完善

**史料**：FreeBSD Security Team 2012-11-17 公告 “FreeBSD Project Infrastructure Incident”；LWN.net 2012-11-19 报道 “FreeBSD servers compromised”；Ars Technica 2012-11-19 报道；FreeBSD 后续关于基础设施安全改进的公告 ［C］

**史观**：总纲第 15 条——文化即形式主义：2012 年服务器入侵事件是 FreeBSD 项目历史上一次重要的安全事件——它暴露了项目基础设施安全的漏洞（开发者 SSH 密钥保护不足），但项目的透明处理（公开公告、详细 timeline、影响范围评估）获得了社区认可；事件处理符合负责任的安全事件响应实践：快速检测、隔离、审计、公开披露、改进措施

**辨析**：2012 年事件是服务器入侵，不是 FreeBSD 操作系统漏洞——入侵者窃取了开发者 SSH 密钥，但无证据表明密钥泄露是因为开发者恶意或疏忽；没有 committer 因该事件被撤销权限；“入侵导致 FreeBSD 包被植入后门”——Security Team 审计确认二进制包未被篡改，但无法 100% 保证窗口期内下载的所有包完整性，建议用户核实

**文献**：FreeBSD Security Team. FreeBSD Project Infrastructure Incident Notice (2012-11-17). freebsd.org/news/; LWN.net. FreeBSD servers compromised (2012-11-19). lwn.net; Ars Technica. FreeBSD project says two of its servers hacked (2012-11-19). arstechnica.com.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 137.7.4 2024 年：regreSSHion（CVE-2024-6387）

**要点**：CVE-2024-6387（regreSSHion）由 Qualys Security 于 2024 年 7 月 1 日披露，是 OpenSSH sshd 信号处理程序中的竞争条件（race condition）漏洞；该漏洞源于 sshd 在 SIGALRM 信号处理程序中调用 async-signal-unsafe 函数（如 syslog()），导致在特定时序下可被利用进行远程代码执行，攻击者无需认证即可获得 root 权限；影响版本为 OpenSSH 8.5p1 至 9.7p1（由 9.8p1 修复；原稿“至 10.7p1”系错误——披露时点 2024-07-01 尚无 10.7p1）（FreeBSD 13.x/14.x 所附带的 OpenSSH 版本在此范围内）；FreeBSD Security Team 在漏洞披露同日发布 FreeBSD-SA-24:04.openssh 安全公告，提供了补丁和 freebsd-update 二进制更新；该漏洞需要精确的时序竞争，实际利用难度较高，但理论上可远程利用，被定性为高危漏洞

**史料**：Qualys Security Advisory "regreSSHion: Remote Unauthenticated Code Execution in OpenSSH Server (CVE-2024-6387)"（2024-07-01）；FreeBSD Security Advisory FreeBSD-SA-24:04.openssh（2024-07-01）；OpenSSH 上游修复 commit ［A］

**史观**：总纲第 22 条——知识注定过时：CVE-2024-6387 距 CVE-2008-4109（上一个 OpenSSH 远程 root RCE）相隔约 16 年，是 2008 年以来最严重的 OpenSSH 漏洞；该漏洞在信号处理中的 async-signal-safety 问题是 UNIX 系统编程中经典的安全陷阱类型，反映了即使经过多年审计的成熟代码仍可能存在微妙漏洞；FreeBSD 对该漏洞的快速响应（当日发布补丁+freebsd-update 二进制更新）体现了 Security Team 流程的成熟——从 2002 年（CVE-2002-0639，需手动打源码补丁）到 2024 年（一键 freebsd-update），安全更新能力大幅提升

**辨析**：该漏洞影响 OpenSSH 上游，FreeBSD 与其他 OS 同步受影响；“regreSSHion 使全球 FreeBSD 服务器大规模被入侵” 无公开证据支持；参见相关章节计算机安全史部分关于该漏洞的详述，本节仅聚焦 FreeBSD 响应层面

**文献**：Qualys Security. regreSSHion Advisory (2024-07-01); FreeBSD Project. FreeBSD-SA-24:04.openssh (2024-07-01). security.freebsd.org; 参见相关章节计算机安全史部分。［A］

## 137.7.5 安全事件响应的史料辨析

**要点**：FreeBSD 安全事件的一手史料主要来源：FreeBSD-SA/EN 公告存档（security.freebsd.org）——最权威的官方记录；freebsd-security@ 和 freebsd-announce@ 邮件列表存档——包含讨论和补充信息；CVE/NVD 数据库条目——标准化漏洞信息；第三方安全公司公告（Qualys、ISS X-Force、Google Project Zero 等）——漏洞发现者的技术报告；媒体报道（LWN、Ars Technica 等）作为二手参考；2000 年代初的部分公告可能已迁移至互联网档案馆。本章 137.7.1-137.7.4 涉及的典型 FreeBSD 安全事件时间线汇总见下表。

| --- | --- | --- | --- |
| 2001-2002 | ftpd、sendmail、telnetd、OpenSSH（CVE-2002-0639）等多个远程漏洞 | 上游软件漏洞 | Security Officer 角色明确、PGP 签名公告、默认服务转向 “默认关闭非必要服务”；FreeBSD 4.4 将 OpenSSH 纳入 base |
