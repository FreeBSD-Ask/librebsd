# 137.8 外部批评与跨 OS 安全模型比较

## 136.8.1 林纳斯·托瓦兹（Linus Torvalds）对 OpenBSD 安全文化的争议性评论

**要点**：2008 年 7 月 15 日，林纳斯·托瓦兹 在 Linux 内核邮件列表（LKML）的讨论中发表了对 OpenBSD 安全文化的争议性评论，称 OpenBSD 社区为 "a bunch of masturbating monkeys"，批评其过度专注于安全而忽视其他工程考量；需要明确的是：(1) 该言论针对的是 OpenBSD 而非 FreeBSD——Torvalds 在同一线程中明确点名 "OpenBSD crowd"；(2) 言论背景是 LKML 关于安全补丁的讨论，Torvalds 表达的是他对 “安全至上主义” 工程哲学的不同意见；(3) 该言论引发了开源社区关于安全与功能/性能平衡的长期争论；FreeBSD 社区对此事的反应相对温和，多数开发者认为安全与功能平衡是各项目自主选择

**史料**：林纳斯·托瓦兹 2008-07-15 LKML 原始帖子（lore.kernel.org 存档）；LKML 讨论线程后续回复；LWN.net 2008 年 7 月对该事件的报道；Ars Technica 等科技媒体报道 ［A］

**史观**：总纲第 14 条——哲学思潮：Torvalds 的言论是 Linux 与 BSD 社区安全哲学长期分歧的一次情绪化表达——Linux 社区（尤其是 Torvalds 本人）倾向于 “安全重要但不应窒息创新和性能”，OpenBSD 倾向于 “安全优先，必要时牺牲性能/功能/易用性”，FreeBSD 处于中间立场——提供丰富安全机制但默认不全部启用，由管理员根据需求选择；这种分歧至今仍存在于开源安全讨论中

**辨析**：“Torvalds 批评的是包括 FreeBSD 在内的所有 BSD”——不准确，原文明确点名 "OpenBSD crowd"；“masturbating monkeys 言论证明 Linux 比 BSD 安全/不安全”——两者均无逻辑关联，该言论是情绪化表达而非技术论证；参见相关章节计算机安全史部分关于该事件的记录，本节仅简述其对 FreeBSD 社区的关联；[双库核查：2026-08-14] 本节要点所述 2008-07-15 林纳斯·托瓦兹于 LKML 的"masturbating monkeys"言论属 Linux 内核邮件列表内容，不在本任务可用的 FreeBSD/BSD/Usenet 邮件库检索范围内，参考文献库亦未命中该 LKML 帖子或 LWN 报道原文，故属两库无法验证，保留（该事件已由既有联网考据记录存档）

**文献**：Torvalds L. LKML Post (2008-07-15). lore.kernel.org; LWN.net. Linus and the security monkeys (2008-07-16). lwn.net; 参见相关章节计算机安全史部分。[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]

## 136.8.2 Linux SELinux/AppArmor/seccomp-bpf 对比

**要点**：FreeBSD 与 Linux 安全机制对比：(1) MAC 框架——FreeBSD TrustedBSD MAC（2003，多模块并行，默认不启用）vs Linux LSM（2003，最初单模块，后支持堆叠；SELinux 默认于 RHEL/Fedora，AppArmor 默认于 Ubuntu/SUSE）；(2) 沙箱/能力——FreeBSD Capsicum（2012，对象能力模型，cap_enter+ 能力 fd）vs Linux seccomp-bpf（2012，系统调用过滤，BPF 程序白名单）；(3) 进程隔离——FreeBSD **jail(8)**+VNET（2000/2008）vs Linux namespaces+cgroups（2008+，LXC/Docker 基础）；(4) 内存保护——OpenBSD W^X（2003）最早，FreeBSD/Linux 后续跟进；(5) 默认安全——OpenBSD 最激进（大量安全加固默认启用），FreeBSD 中间（提供机制但默认保守），Linux 因发行版差异大（RHEL 默认 SELinux，Ubuntu 默认 AppArmor，部分发行版默认禁用 MAC）；Apple macOS 的 Seatbelt（App Sandbox）和 XNU 内核的 MAC 框架源自 FreeBSD TrustedBSD——罗伯特·N. M. 沃森（Robert Watson）本人参与了 Apple 的 MAC 框架移植工作

**史料**：**mac(4)** vs **security_modules(7)** 手册页；**capsicum(4)** vs **seccomp(2)** 手册页；**jail(8)** vs **namespaces(7)** 手册页；Cowan C et al. Linux Security Modules (USENIX Security 2002); Watson et al. Capsicum (USENIX Security 2010) ［A］

**史观**：总纲第 6 条——技术路线分化：Linux 和 FreeBSD 安全模型的分化是两个社区文化差异的系统体现——Linux 安全机制更多由安全公司和发行版厂商驱动（NSA 贡献 SELinux、Novell/SUSE 贡献 AppArmor、Chrome 团队推动 seccomp-bpf），FreeBSD 安全机制更多由学术研究和个人开发者驱动（TrustedBSD/DARPA/剑桥/Capsicum）；Linux 路径获得了更大的工业部署（Android、RHEL、云原生生态），FreeBSD 路径在安全研究界有更大影响力（Capsicum 影响 WASI、CHERI 影响硬件安全）

**辨析**：“Linux 比 FreeBSD 安全” 或反之——简单比较没有意义，取决于具体版本、配置、使用场景；“SELinux 是 MAC 框架”——SELinux 是 LSM 的一个安全策略模块（实现 FLASK/TE 模型），非框架本身，类似 FreeBSD 的 mac_mls+mac_biba 等模块而非 **mac(4)** 框架本身；seccomp-bpf 与 Capsicum 技术路线完全不同——前者是系统调用号白名单/过滤器，后者是对象能力系统

**文献**：Cowan C et al. Linux Security Modules (USENIX Security 2002); Watson et al. Capsicum (USENIX Security 2010); FreeBSD/Linux manual pages. ［B］

## 136.8.3 OpenBSD pledge/unveil 与内存保护对比

**要点**：OpenBSD 安全机制与 FreeBSD 对比：(1) W^X（Write XOR Execute）——OpenBSD 在 2003 年（OpenBSD 3.3）最早在 i386 上默认启用 W^X，FreeBSD 自 13.x 左右在 amd64/arm64 上默认启用 W^X 和页表执行保护（NX/XD bit）[考据完成：2026-08-17 FreeBSD W^X 机制经 mitigations(7) 手册页确认，kern.elf64.allow_wx 默认强制（=0）于 13.x 生效]；(2) pledge/unveil——OpenBSD **pledge(2)**（5.9，2016）和 **unveil(2)**（6.4，2018）由 Ted Unangst 等开发，提供系统调用族承诺和文件系统路径可见性限制；Capsicum 是对象能力模型，pledge 是系统调用白名单 + 承诺模型，两者哲学不同但目标类似（最小权限沙箱）；(3) 默认安全——OpenBSD 默认启用大量安全加固（W^X、ASLR、PIE、RELRO、pledge 化基础系统程序等），FreeBSD 默认保守，需管理员主动启用；(4) 安全审计文化——OpenBSD 以 proactive 全树审计著称，FreeBSD 更侧重 reactive 响应 + 模块化安全机制

**史料**：OpenBSD **pledge(2)**、**unveil(2)** 手册页；OpenBSD 3.3/5.9/6.4 Release Notes；Unangst T. pledge 设计文档和演讲 ［A］

**史观**：总纲第 6 条——技术路线分化：OpenBSD 与 FreeBSD 的安全哲学差异是 BSD 家族内部最显著的路线分化之一——OpenBSD 采取 “安全激进主义”：宁可牺牲兼容性、性能、易用性也要默认启用最强安全；FreeBSD 采取 “安全自由主义”：提供一流的安全工具箱，但让管理员根据场景选择，默认保持通用性；这一分化可追溯至 Theo de Raadt（西奥·德·若特） 1995 年因内部冲突从 NetBSD/FreeBSD 社区分叉创立 OpenBSD 的历史

**辨析**：“pledge 是抄袭 Capsicum” 或 “Capsicum 是抄袭 pledge”——两者独立开发，技术路线完全不同，pledge 出现在 Capsicum 之后但系统调用承诺模型与对象能力模型差异显著；“FreeBSD W^X 比 OpenBSD 晚了 10 年是因为不重视安全”——FreeBSD 确实在 W^X 等内存保护默认启用方面落后于 OpenBSD，但 FreeBSD 较早引入了 MAC 框架、Capsicum、jail 等更高级别的安全机制，两个项目优先级不同

**文献**：OpenBSD Project. **pledge(2)**, **unveil(2)** Manual Pages; OpenBSD Project. OpenBSD Release Notes 3.3, 5.9, 6.4; Unangst T. pledge presentations (BSDCan/EuroBSDCon).[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]

## 136.8.4 macOS/Windows 安全模型与认证澄清

**要点**：FreeBSD 与 macOS/Windows 安全模型对比及关键认证澄清：(1) macOS——Apple macOS 基于 Darwin（FreeBSD + Mach 混合内核），XNU 内核中的 MAC 框架源自 FreeBSD TrustedBSD，衍生为 Seatbelt（App Sandbox）；System Integrity Protection（SIP/rootless，OS X is Capitan 10.11，2015）限制 root 用户修改系统文件和内核扩展，类似 FreeBSD securelevel 但更细粒度；macOS 持有 Common Criteria 认证，但这是 macOS 产品认证，与 FreeBSD 上游无关；(2) Windows——Windows 安全模型以 NT ACL、Mandatory Integrity Control（MIC）、Windows Defender、UAC、Patch Tuesday、AppContainer 沙箱等为核心，与 FreeBSD 架构差异极大；(3) 重要澄清——FreeBSD 项目本身从未持有 FIPS 140、Common Criteria、UNIX 03、FedRAMP 等形式认证；Apple macOS、TrueNAS、NetApp ONTAP、Juniper Junos、Sony PlayStation OS 等产品基于或衍生自 FreeBSD，但这些产品的安全认证是产品级认证，不是 FreeBSD 操作系统本身持有认证

**史料**：Apple Platform Security 指南（support.apple.com/guide/security/）；XNU 源码中 MAC/Seatbelt 实现（Apple Open Source 仓库）；Microsoft Windows 安全文档；Common Criteria 认证产品查询页面；The Open Group UNIX 认证目录 ［A］

**史观**：总纲第 9 条——企业研究双重性：FreeBSD 作为 BSD 许可的通用操作系统，被多家商业公司作为产品基础，但这些公司的安全认证和加固通常不回馈到 FreeBSD 上游——Apple 将 MAC 框架衍生为 Seatbelt 但大量改动为私有；Juniper、NetApp 使用 FreeBSD 作为网络/存储设备基础但内核改动多为私有；这是宽松许可证的 “代价”——公司可以自由使用和修改，但无义务回馈

**辨析**：“macOS 是 FreeBSD 所以 macOS 的安全就是 FreeBSD 的安全”——这是极其常见的误解；macOS/Darwin 仅在用户层和部分 API 层面源自 FreeBSD，XNU 内核是 Mach + FreeBSD 紧密混合，安全机制（SIP、Seatbelt、Code Signing、Notarization、Secure Enclave）均为 Apple 私有技术；“FreeBSD 没有 Common Criteria 认证所以不安全”——CC 认证是过程/文档认证，不是安全性的直接度量；OpenBSD 也没有 CC 认证，但被普遍认为是最安全的通用 OS 之一

**文献**：Apple Inc. Apple Platform Security. support.apple.com/guide/security/; Apple Inc. XNU Source Code (opensource.apple.com); The Open Group. Common Criteria Portal. commoncriteriaportal.org; The Open Group. UNIX Certification Directory. opengroup.org. ［A］
