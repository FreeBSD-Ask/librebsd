# 153.12 2023-2026 社区治理：Core Team、Security Team 与 Foundation 资助

## 153.12.1 Core Team 选举与成员变动（2023-2026）

**要点**：FreeBSD Core Team 每两年由活跃 committer 选举产生，是项目的 “董事会”，负责项目整体方向与重大决策；截至 2026 年 7 月，Core Team 成员为：Adam Weinberger（adamw@）、Adrian Chadd（adrian@）、Baptiste Daroussin（巴蒂斯特·达鲁桑）（bapt@）、Gleb Smirnoff（glebius@）、Hiroki Sato（佐藤広生）（hrs@；原 ch85 草稿误记其逝世与献词，考据结论详见本节辨析）、Warner Losh（沃纳·洛什）（imp@）、Joseph Mingrone（jrm@）、Kyle Evans（kevans@）、Olivier Cochard-Labbé（olivier@）；2024 年 Core Team 选举中部分成员连任、部分更替——Core Team 选举为秘密投票，当选名单在 freebsd-core@ 与项目公告中发布；Core Team Secretary 职位在 14.x 周期内空缺

**史料**：FreeBSD Project Administration 页面（freebsd.org/administration/）；Core Team 选举公告邮件列表存档；Core Team 月度状态报告 ［A］

**史观**：总纲第 8 条——本体论上各方平等：FreeBSD Core Team 选举制度是开源社区 “代议民主” 治理模式的典范——9 名核心成员由 committer 民主选举产生，任期两年，可连任；这一制度既避免了 BDFL（仁慈独裁者）模式的个人依赖风险，也避免了完全开放投票的民粹化倾向（只有具有代码提交记录的活跃开发者才有投票权）；Core Team 权力受项目章程约束，具体技术决策交由各领域团队（re@、secteam、portmgr 等）负责

**辨析**：Hiroki Sato（hrs@）在 FreeBSD 社区地位崇高——他是文档项目负责人、亚洲 BSD 社区（特别是日本 BSD 用户组）的核心组织者、担任 Core Team 成员多年；原 ch85 草稿称他于 2022 年逝世且 13.1-RELEASE 献词给他，**经核实 13.1-RELEASE 实际献词给 Bill Jolitz**（386BSD 共同创建者），而非 Hiroki Sato——这一点在 154.15.3 中已详细辨析；Hiroki Sato 的实际状态经核验为在世且仍列官方管理页面与 Core Team 名单 [考据完成：2026-08-17 Hiroki Sato（hrs@）仍在官方管理页面与 Core Team 名单中，无逝世证据]——“2022 年逝世” 之说经核验无据，此前疑虑排除

## 153.12.2 Security Officer 任期与安全团队演进

**要点**：截至 2026 年 7 月，FreeBSD Security Officer 为 **Gordon Tetlow（戈登·泰特洛）**（gordon@），Deputy Security Officer 为 Ed Maste（埃德·马斯特）（emaste@）；Security Officer Emeritus（荣誉安全官）包括 Xin Li（delphij@）与 Dag-Erling Smørgrav（des@）；安全团队其他成员包括 Allan Jude（艾伦·裘德）（Core Team Liaison）、Pierre Pronchery（皮埃尔·普龙谢里）、Mark Johnston（马克·约翰斯顿）、Mariusz Zaborski、Philip Paeps（菲利普·佩普斯） 等；Security Team 负责 base 系统安全漏洞处理，发布 Security Advisory（SA）与 Errata Notice（EN）；Ports Collection 安全问题由独立的 Ports Security Team 处理；Colin Percival 曾担任 Security Officer 多年（2005-2015 左右），后转任 Release Engineering Lead，Dag-Erling Smørgrav、Xin Li、Gordon Tetlow 先后接任 Security Officer

**史料**：FreeBSD Security Team 页面；Security Officer 交接历史邮件列表公告；安全团队成员名单 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：FreeBSD Security Team 是开源项目中历史最悠久、最受尊敬的安全响应团队之一——自 1990 年代末成立以来，它建立了成熟的漏洞响应流程、PGP 签名公告制度、负责任披露规范；Security Officer 职位的平稳交接（Colin→des→delphij→Gordon）体现了项目治理的成熟度——安全团队的领导力不依赖于个人，而是制度化的团队能力

**辨析**：Security Officer 与 Release Engineering Lead 之间的协作关系紧密——安全补丁需要在所有支持的 release/STABLE 分支及时合并，这要求 re@ 与 secteam 密切协调；Dag-Erling Smørgrav（des@）作为 FreeBSD 历史上任职时间最长的 Security Officer 之一，在任期间建立了许多延续至今的安全响应规范；Xin Li（delphij@）在任期间处理了多项重大安全事件，同时兼任 Release Engineering Team Liaison

## 153.12.3 FreeBSD Foundation 2023-2026 资助项目全景

**要点**：FreeBSD Foundation（FreeBSD 基金会）是 501(c)(3) 非营利组织，为 FreeBSD 项目提供资金、法律与开发资源支持；2023-2026 年基金会资助的重点项目包括但不限于：① WiFi 驱动与 LinuxKPI 层改进（改善笔记本/桌面体验，资助金额约 75 万美元的多年项目）；② 64-bit time_t Y2038 修复（Ed Maste 主导）；③ WireGuard 驱动重写（John Baldwin（约翰·鲍德温） 团队，Netgate 配合赞助）；④ pkgbase 开发与成熟；⑤ bhyve 虚拟化改进（TPM/GPU passthrough、vCPU 扩展）；⑥ **makefs(8)** ZFS 支持；⑦ boottrace 启动跟踪框架；⑧ OpenZFS 持续集成与性能优化；⑨ 安全改进（PIE/ASLR、KASAN、安全审计）；⑩ LLVM/Clang 工具链跟进与优化；基金会同时资助开发者参加 BSDCan、EuroBSDCon、vDevCon 等会议，提供法律支持（如商标、许可证问题），并协调与商业公司的合作；主要赞助商包括 Netflix、Google、Microsoft、Amazon AWS、Netgate/iXsystems、Stormshield、Beckhoff Automation、Open Sats Initiative、Ampere Computing 等

**史料**：FreeBSD Foundation 2023、2024、2025 年度报告；Foundation 资助项目页面；季度/月度状态报告；赞助商名单 ［B］

**史观**：总纲第 13 条——法律与道德是利益分配：FreeBSD Foundation 在项目生态中扮演了独特的角色——它不是 Linux Foundation 那样庞大的行业协会，也不是单一公司控制的项目（如 Redis/MongoDB），而是一个相对小型、专注的非营利组织，2020 年代年度预算约数百万美元；Foundation 的存在解决了 BSD 许可证的一个结构性问题：BSD 许可证允许公司自由使用代码而不必回馈，基金会通过自愿赞助汇聚资源，资助那些商业公司不愿单独投入但对整个生态至关重要的基础工作（如 WiFi 驱动、Y2038 修复、安全改进）

**辨析**：FreeBSD Foundation 与 Core Team 的关系需厘清：Core Team 是项目的技术治理机构，由开发者选举产生；Foundation 是独立的非营利法人，由董事会管理，向项目提供资金与资源支持但不直接干预技术决策；两者之间有 Liaison 沟通机制，但保持组织独立；这一 “技术治理与资金支持分离” 的模式是 FreeBSD 项目结构的重要特征，避免了 “谁出钱谁决定技术路线” 的问题

## 153.12.4 社区治理史料辨析：re@ 团队变动与发布工程成熟

**要点**：FreeBSD Release Engineering Team（re@）在 14.x 周期内经历了值得注意的人事变动：14.0 时 Colin Percival 任 Lead，Glen Barber（格伦·巴伯） 任 Deputy Lead；Glen Barber（gjb@，长期担任发布工程师，负责 FreeBSD 10-13 多个版本的发布工程）在 14.0 后离开 re@ 团队；Mike Karels（mike@）接任 Deputy Lead，但不幸于 2024 年 10 月逝世，14.2 献词给他；Ed Maste（emaste@）随后接任 Deputy Lead 并任职至今；14.4 时 re@ 团队进一步变动——Konstantin Belousov（康斯坦丁·别洛乌索夫）（kib@）、John Hixson、Doug Rabson（道格·拉布森）、Mahdi Mokhtari 等离开，新增 Sergio Carlavilla Delgado、Jake Freeland、Craig Leres、Vladlen Popolitov、Lexi Winter、Alexander Ziaee 等新成员；Antoine Brodin 继续负责 Package Building；Colin Percival 自 13.x 起担任 re@ Lead，是 FreeBSD 历史上任职时间较长的发布工程负责人之一，14.x 稳定的 6 个月发布节奏体现了其领导下的工程成熟度

**史料**：FreeBSD 14.0-14.4 发布公告中的 re@ 名单；Glen Barber 离职邮件；Mike Karels 逝世公告与纪念文章［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**史观**：总纲第 4 条——分离聚合是永恒规律：Mike Karels 的逝世是 BSD 第一代开发者群体逐渐谢幕的标志——他是 CSRG 核心成员（《The Design and Implementation of the 4.3/4.4BSD Operating System》合著者），从 1980 年代 4.xBSD 到 2020 年代 FreeBSD 14.x，持续贡献 BSD 四十年；他在生命最后阶段仍担任 Deputy Release Engineer 参与 14.2 发布工作，这种 “代码即生命” 的精神是 BSD 社区最珍贵的遗产；发布工程团队的新老交替（Glen Barber 离开、新成员加入）也体现了社区延续性——re@ 作为制度化团队，个人离开不会导致发布流程中断

**辨析**：发布工程团队成员的增加（从 14.0 约 7-8 人到 14.4 约 11 人）反映了 FreeBSD 发布工程工作量的增长——支持架构增加、云镜像/OCI 镜像/VM 镜像等多种发布格式、安全补丁频率增加，都需要更多人力；Colin Percival 同时也是 FreeBSD 历史上的 Security Officer Emeritus、FreeBSD Update（**freebsd-update(8)**）作者、知名的安全研究者（他在 2005 年发现了著名的 AES cache timing 攻击）
