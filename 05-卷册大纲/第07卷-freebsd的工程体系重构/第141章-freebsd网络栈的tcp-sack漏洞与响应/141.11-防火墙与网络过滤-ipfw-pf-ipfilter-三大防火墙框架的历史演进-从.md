# 141.11 防火墙与网络过滤：ipfw、pf、ipfilter 三大防火墙框架的历史演进——从 1990 年代的 ipfilter 到 ipfw 原生防火墙，再到 OpenBSD pf 的移植

## 141.11.1 ipfw：FreeBSD 原生防火墙框架

**要点**：**ipfw(8)**（IP Firewall）是 FreeBSD 原生的防火墙和包过滤框架，最初由 Ugen J. S. Antsilevich 开发，随 FreeBSD 1.0（1993 年）即已存在，是 FreeBSD 历史最悠久的防火墙；**dummynet(4)** 流量整形系统由 Luigi Rizzo 于 1998 年设计并集成到 ipfw 框架，提供带宽限制、延迟模拟、丢包模拟、队列管理等功能，成为学术研究（TCP 协议研究）和网络仿真的标准工具；ipfw 采用经典的“规则列表匹配”模型——数据包按照规则编号顺序匹配，支持：IP/TCP/UDP/ICMP 层过滤、状态跟踪（keep-state、limit）、NAT（通过 **ipfw_nat(4)** 或 **ng_nat(4)**）、dummynet 流量整形、table 查找（高效 IP 集匹配）、fwd 规则（策略路由）；ipfw 的用户态工具是 **ipfw(8)** 命令；FreeBSD 10 之后 ipfw 还集成了 pfil 钩子和 VNET 支持

**史料**：**ipfw(8)**、**dummynet(4)**、**dnctl(8)** 手册页；Rizzo, L. 1998 dummynet 论文（ACM CCR）；FreeBSD Handbook 防火墙章节；ipfw 源码 sys/netpfil/ipfw/ ［A］
    FreeBSD 社区论文：[FP-2025-004] Re-decentralizing the Internet with BSD（Christos Margiolis（克里斯托斯·马焦利斯），2025）<https://papers.freebsd.org/2025/eurobsdcon/margiolis-re-de-centralizing-the-internet-with-bsd/>
    FreeBSD 社区论文：[FP-2019-068] Netflix and FreeBSD: Using Open Source to Deliver Streaming Video（Jonathan Looney，2019）<https://papers.freebsd.org/2019/fosdem/looney-netflix_and_freebsd/>
    FreeBSD 社区论文：[FP-2016-014] Looking Backwards -- The coming decades of BSD（George Neville-Neil，2016）<https://papers.freebsd.org/2016/eurobsdcon/gnn-the_coming_decades_of_bsd/>

**史观**：总纲第 1 条——项目统摄史观：ipfw 从 FreeBSD 1.0 起就存在，是极少数从项目成立延续至今仍在活跃维护的子系统——它见证了 FreeBSD 从 386BSD 后裔到现代操作系统的完整历史；dummynet 被全球网络研究者使用了 25 年，体现了好的工程设计的长久生命力

**辨析**：ipfw 作者——Ugen Antsilevich 是 ipfw 最初作者（1993），Luigi Rizzo 设计了 dummynet（1997-1998），后来 Gleb Smirnoff 等人做了大量现代化改进（支持 SMP、IPv6、VNET）；ipfw 是“第一代防火墙”吗？从技术上 ipfw 是 stateless 防火墙起家，后来添加了 keep-state 状态跟踪，现在是有状态防火墙；dummynet 是否只能和 ipfw 一起用——dummynet 现在可以通过 **pfil(9)** 钩子与 pf 一起使用，也可以通过 netgraph 集成，但最初设计是 ipfw 的一部分

## 141.11.2 pf：从 OpenBSD 移植的现代防火墙

**要点**：**pf(4)**（Packet Filter）最初由 Daniel Hartmeier（丹尼尔·哈特迈尔） 为 OpenBSD 开发，于 OpenBSD 3.0（2001 年 12 月）发布，用于替代因许可证问题从 OpenBSD 移除的 IPFilter；pf 设计目标是替代 ipfilter，提供更简洁的语法、更好的 SMP 性能、集成的 QoS（ALTQ）、状态跟踪、NAT、PBR（策略路由）等功能；pf 于 FreeBSD 5.3（2004 年 11 月）首次作为可加载模块引入 FreeBSD ports，在 FreeBSD 5.4/6.0 左右移入基础系统；**ALTQ(9)**（Alternate Queuing）是 Kenjiro Cho 开发的 QoS 框架，最初为 BSD 家族设计，后与 pf 深度集成，提供 CBQ、PRIQ、HFSC 等队列调度算法；FreeBSD 上的 pf 持续从 OpenBSD 移植改进，但也有 FreeBSD 特有的增强（如更好的 SMP 支持、VNET jail 集成）；**pfsync(4)** 和 **carp(4)** 是与 pf 配套的高可用协议——pfsync 在多防火墙之间同步状态表，carp 提供 IP 地址冗余（类似 Cisco HSRP/VRRP，但无专利问题）

**史料**：**pf(4)**、**altq(9)**、**pfsync(4)**、**carp(4)**、**pfctl(8)** 手册页；OpenBSD pf 设计文档（Hartmeier 2001）；FreeBSD 5.3/5.4 Release Notes pf 章节；CARP 设计文档（OpenBSD，因为 Cisco HSRP 专利问题） ［A］

**史观**：总纲第 12 条——法律结构：pf 的诞生直接源于 IPFilter 许可证危机——OpenBSD 因 ipfilter 许可证条款不明确而被迫移除 ipfilter，Hartmeier 在几个月内从头编写了 pf；这说明法律/许可证问题可以直接催生技术创新，pf 最终成为比 ipfilter 更成功的防火墙，“危机”催生了更好的技术

**辨析**：pf 引入 FreeBSD 的精确版本——部分资料称 5.3，部分称 5.4——pf 代码在 FreeBSD 5.3 时期存在但标记为实验性，在 FreeBSD 5.4/6.0 正式支持［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］；CARP 引入版本——CARP 与 pfsync 在 FreeBSD 5.4-RELEASE（2005 年 5 月）引入，经 FreeBSD 5.4 Release Notes 一手核验；pf 在 FreeBSD 上的性能与 OpenBSD 相比——FreeBSD pf 做了 SMP 优化，多核心性能可能更好，但某些功能（如最新的 pf 语法）可能落后于 OpenBSD；ALTQ 作者——Kenjiro Cho，不是 OpenBSD 团队，ALTQ 是独立开发后与 pf 集成的

**文献**：Hartmeier, D. (2001-2002). *PF: Packet Filter for OpenBSD*. OpenBSD Project; FreeBSD Project. ## 141.11.3 ipfilter：早期的跨 BSD 防火墙与许可证争议

**要点**：**ipfilter(5)**（IPFilter，常简称 ipf）由 Darren Reed（达伦·里德） 开发，是 1990 年代到 2000 年代初包括 FreeBSD 在内的多个 BSD 系统的默认防火墙；ipfilter 提供了有状态包过滤、NAT 等功能，在当时比 ipfw 功能更完善；2001 年发生了著名的 IPFilter 许可证危机——Darren Reed 对 ipfilter 许可证条款做了修改，使得分发修改后的版本存在法律不确定性，OpenBSD 团队认为这不符合开源精神，将 ipfilter 从 OpenBSD 3.0 中移除，由此催生了 pf；FreeBSD 对 ipfilter 许可证问题的处理不同——FreeBSD 没有立即移除 ipfilter，但将其从默认安装中移除，改为用户可选择安装；ipfilter 至今仍存在于 FreeBSD 源码树中（sys/contrib/ipfilter/），但已不再是推荐的防火墙，pf 和 ipfw 是首选

**史料**：**ipf(5)**、**ipnat(8)** 手册页；OpenBSD 2001 年移除 ipfilter 的声明邮件（Theo de Raadt（西奥·德·若特） 邮件列表帖子）；FreeBSD Release Notes 关于 ipfilter 状态变更的说明；ipfilter 许可证争议邮件列表档案 ［A］

**史观**：总纲第 24 条——许可证：ipfilter 许可证危机是开源史上的重要事件——它证明了模糊的许可证条款比宽松许可证或 copyleft 许可证更危险；Reed 本人的代码是优秀的，但许可证条款的不明确性导致整个 BSD 世界不得不寻找替代方案，这个事件直接催生了 pf

**辨析**：ipfilter 许可证问题的本质——Darren Reed 并没有“闭源”ipfilter，他只是修改了许可证，要求修改版本不能以"ipfilter"名义分发或必须经过他批准，这与 OpenBSD 对自由软件的理解冲突；FreeBSD 为何不像 OpenBSD 那样立即移除——FreeBSD 核心团队认为只要代码可用且许可证允许基本使用就保留，但不再默认启用或积极开发；今天还有人用 ipfilter 吗？极少量遗留系统使用，新部署几乎都使用 pf 或 ipfw

**文献**：Reed, D. (1990s-2000s). *IPFilter Documentation*. ipfilter.org; de Raadt, T. (2001-05). *IPFilter Removal Announcement*. openbsd-misc@; FreeBSD Project. (2001-2006). *Release Notes (IPFilter status)*. freebsd.org; A Look at the IPFilter License Controversy (2001). Slashdot/OSNews coverage. ［A］

## 141.11.4 三大防火墙框架的比较与史料辨析

**要点**：FreeBSD 三大防火墙对比：① 历史——ipfw（1993-）、ipfilter（~1995-2006 主流）、pf（2004-，现代首选）；② 功能——三者都支持状态过滤、NAT、IPv6，pf 语法最简洁现代，ipfw+dummynet 流量整形最强大，ipfilter 功能基本冻结；③SMP 性能——pf 在 FreeBSD 上做了较好的 SMP 优化，ipfw 在现代版本也支持细粒度锁，ipfilter SMP 支持最差；④ 推荐场景——pf 是通用防火墙首选（尤其 pfSense/OPNsense 基于 pf），ipfw+dummynet 适合流量整形和网络仿真，ipfilter 仅用于兼容遗留配置；防火墙历史的有趣循环：ipfw 是 FreeBSD 原生、ipfilter 是跨平台引入、pf 是从 OpenBSD 移植——FreeBSD 最终同时提供三种选择。三大防火墙框架关键维度对比见下表。

| 维度 | **ipfw(8)** | **ipfilter(5)**（ipf） | **pf(4)** |
| --- | --- | --- | --- |
| 起源 | FreeBSD 1.0（1993）原生 | Darren Reed 开发，~1995 起跨 BSD 平台 | Daniel Hartmeier 为 OpenBSD 开发，OpenBSD 3.0（2001.12）首发 |
| FreeBSD 引入版本 | FreeBSD 1.0（1993）即存在 | 1990 年代引入；2001 年许可证争议后从默认安装移除 | FreeBSD 5.3（2004.11）作为可加载模块引入；5.4/6.0 移入基础系统 |
| 主要作者 | Ugen J. S. Antsilevich（初始）；Luigi Rizzo（dummynet）；Gleb Smirnoff（现代化） | Darren Reed | Daniel Hartmeier（OpenBSD 原创）；Max Laier（FreeBSD 移植，2004-06-16 vendor import） |
| 语法风格 | 规则编号顺序匹配 | 类自然语语法 | 最简洁现代，类自然语语法 |
| 状态过滤 | 支持（keep-state、limit） | 支持 | 支持（默认有状态） |
| NAT | 通过 **ipfw_nat(4)** 或 **ng_nat(4)** | 通过 **ipnat(8)** | 集成 NAT |
| 流量整形 | **dummynet(4)** 最强大（CBQ、PRIQ、HFSC、延迟/丢包模拟） | 较弱 | **ALTQ(9)** 集成（CBQ、PRIQ、HFSC） |
| IPv6 支持 | 支持 | 支持 | 支持 |
| SMP 性能 | 现代版本支持细粒度锁 | SMP 支持最差 | FreeBSD 上做了较好的 SMP 优化 |
| 高可用 | 通过 **carp(4)**/**pfsync(4)** | 较弱 | **pfsync(4)**/**carp(4)** 配套（OpenBSD 因 Cisco HSRP 专利问题设计） |
| VNET/Jail 集成 | 支持 | 较弱 | 支持 |
| 推荐场景 | 流量整形、网络仿真、学术研究 | 仅兼容遗留配置 | 通用防火墙首选（pfSense/OPNsense 基于 pf） |
| 当前状态 | 活跃维护 | 仍存在于 `sys/contrib/ipfilter/` 但不再推荐 | 最活跃开发，现代首选 |

**史料**：FreeBSD Handbook 防火墙比较章节；pfSense/OPNsense 文档（为什么基于 pf）；三个防火墙的性能对比测试（2010s BSDCan 演讲） ［B］

**史观**：总纲第 6 条——技术路线分化：三个防火墙在 FreeBSD 中并存体现了 BSD 世界的“选择哲学”——不强制用户使用某个“官方答案”，而是提供多个经过验证的选项，让用户根据场景选择；这与 Linux 世界从 iptables 到 nftables 的强制迁移形成对比

**辨析**：“pf 是 FreeBSD 默认防火墙”——严格来说 FreeBSD 基础系统没有默认启用任何防火墙，用户需要自行配置和启用；但 pfSense/OPNsense 等防火墙发行版默认使用 pf，pf 也是目前最活跃开发的防火墙；ipfw 是否被弃用——没有，ipfw 和 dummynet 仍在活跃维护和使用，dummynet 在学术研究中地位不可替代；三大防火墙可以同时使用吗？技术上可以通过 pfil 钩子链实现，但不推荐，会导致性能问题和配置复杂性

**文献**：FreeBSD Foundation. *FreeBSD Handbook: Firewall Choices*. freebsd.org; Lucas, M. W. (2014). *FreeBSD Mastery: PF*. Tilted Windmill Press; PfSense Project. *Why PF? Documentation*. pfsense.org; Biancuzzi, F. (2005). *Interview with Daniel Hartmeier*. onlamp.com. ［B］
