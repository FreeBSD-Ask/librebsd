# 141.9 本时期网络栈相关的 committer 权限变动——经核验本时期（2010-2026）网络栈核心维护者（包括 Gleb Smirnoff、Hiren Panchasara、Michael Tuexen 等）未发生公开的权限撤销事件

## 141.9.1 网络栈核心维护者权限状态核查

**要点**：FreeBSD 网络栈的长期核心维护者包括：Gleb Smirnoff（网络栈锁定、TCP/IP 优化、多部分工作）、Andre Oppermann（2004-2008 网络栈重写关键人物，后来活动减少）、Hiren Panchasara（TCP 栈维护，2010 年代）、Michael Tuexen（SCTP 协议维护）、John Baldwin（KTLS、iflib、WireGuard 重写）、Andrew Gallatin（Netflix，TCP/KTLS/性能优化）、Randall Stewart（SCTP 和 RACK TCP）、Bjoern Zeeb（VNET、网络虚拟化）、罗伯特·N. M. 沃森（Robert Watson）（TrustedBSD、VNET、网络安全）、Matt Macy（iflib、网络驱动，2020 年代初活动减少）；经核查 FreeBSD Core Team 公告和 committer 列表，2010-2026 年间这些核心网络维护者没有发生公开的 committer 权限撤销事件；部分开发者活动减少（如 Oppermann）属于自然的开发者参与度变化，不是权限撤销

**史料**：FreeBSD Project 活跃 committer 列表；FreeBSD Core Team 公告（2010-2026）；git/svn commit 历史（显示活跃开发者）；FreeBSD 开发者维基 ［D］ 〔L1 代码；L3 官方文档〕

**史观**：总纲第 23 条——社区治理：committer 权限是 FreeBSD 社区的核心治理机制——获得 committer 权限意味着获得对源码仓库的直接写入权，需要经过 mentorship 和投票；权限撤销极其罕见且通常会公开说明原因，2010-2026 年间网络子系统没有发生此类事件，说明网络栈维护团队整体稳定

**辨析**：“committer 离开” 不等于 “权限撤销”——开发者可能因为工作变动、兴趣转移、时间限制等原因减少或停止提交，这是正常的开源生命周期，committer 权限通常保留以备回归；Matt Macy 在 WireGuard 事件后活动减少，但没有公开证据显示其权限被撤销；Andre Oppermann 在 2008 年后提交减少，但这是正常的贡献节奏变化

**文献**：FreeBSD Project. *Active Committers List*. freebsd.org; FreeBSD Core Team. *Public Announcements Archive*. freebsd.org/news; FreeBSD Project. *Commit History*. cgit.freebsd.org. ［A］

## 141.9.2 2010-2026 年间网络栈贡献者动态记录

**要点**：2010-2026 年间 FreeBSD 网络栈贡献者呈现 “核心稳定、持续有新贡献者加入” 的态势：①2010-2015——Gleb Smirnoff 持续网络栈 SMP 优化，Hiren Panchasara 加入 TCP 维护，Bjoern Zeeb 完成 VNET 稳定化；②2015-2020——Netflix 团队（Gallatin、Stewart、Duleba）开始大规模贡献 RACK/BBR/KTLS，John Baldwin 完成 iflib 框架，Matt Macy 贡献新一代网卡驱动；③2020-2026——新 WireGuard 实现完成，100Gbps/200Gbps 网卡性能优化，持续 SMP 性能改进；网络栈 committer 群体没有出现大规模新老交替冲突，采用 FreeBSD 标准的 mentorship 模式培养新 committer

**史料**：FreeBSD 源码仓库提交统计（按作者）；BSDCan/EuroBSDCon 演讲者名单（显示活跃贡献者）；FreeBSD 季度状态报告 ［A］

**史观**：总纲第 22 条——开源运动：FreeBSD 网络栈维护者群体体现了开源项目的 “代际传承”——从 1990 年代的 David Greenman（大卫·格林曼）、Julian Elischer，到 2000 年代的 Andre Oppermann、罗伯特·N. M. 沃森，到 2010 年代的 Gleb Smirnoff，再到 2020 年代 Netflix 团队和新一代贡献者，代码和知识通过邮件列表、代码审查、会议演讲持续传承

**辨析**：Netflix 贡献者是否 “控制” 了 FreeBSD 网络栈——不，Netflix 贡献了大量代码但不控制开发方向，核心决策仍由 FreeBSD 网络团队集体做出；Netflix 的贡献符合 FreeBSD 的工程标准，且经过正常代码审查流程；“Netflix 只关心 CDN 性能”——Netflix 贡献的 RACK/BBR/KTLS 对所有 FreeBSD 用户都有益，不只是 CDN 场景

**文献**：FreeBSD Project. *Quarterly Status Reports* (2010-2026). freebsd.org/news/status; FreeBSD Foundation. *Annual Reports*. freebsdfoundation.org; cgit.freebsd.org. *Commit Author Statistics*. ［A］

## 141.9.3 与其他子系统权限变动的比较参考

**要点**：对比 FreeBSD 其他子系统，网络栈的 committer 团队相对稳定；安全子系统和 Ports 子系统历史上有过一些公开的权限变动和社区争议，但网络栈（除了 WireGuard 事件的流程争议外）没有发生重大治理危机；这可能因为：① 网络栈代码成熟，架构稳定，不需要大规模重写；② 维护团队有长期服务的核心成员；③ 网络栈的技术决策更多基于工程标准而非意识形态争议；需要注意，committer 权限变动记录只反映公开的正式治理动作，私人协商的开发者退出或退休不会出现在公开记录中

**史料**：FreeBSD Core Team 所有公开公告；其他 BSD 社区类似事件的对比分析（仅作背景参考） ［A］

**史观**：总纲第 23 条——社区治理：网络栈维护团队的稳定性是 FreeBSD 网络栈质量的重要保障——长期维护者带来代码的深度理解和架构一致性；相比之下，某些快速迭代的子系统可能因为核心维护者变更导致架构不稳定

**辨析**：本节不应对其他子系统的权限事件做未经核实的断言，只陈述网络栈本身的情况；“没有公开权限撤销” 不等于 “没有任何争议”——WireGuard 事件虽然没有导致权限撤销，但确实是重大争议事件；核心维护者平稳传承是 FreeBSD 网络栈的优势，但也可能被批评为 “维护者圈子封闭”

**文献**：FreeBSD Core Team. *All Public Announcements*. freebsd.org/news; FreeBSD Project. *Developer's Handbook (Committer Process)*. freebsd.org. ［A］

## 141.9.4 网络栈维护者记录的史料辨析

**要点**：FreeBSD committer 记录的公开信息包括：committer 加入日期、mentor 信息、提交历史、Core Team 公告的权限变更；不公开的信息包括：committer 之间的私人邮件讨论、Core Team 非公开会议内容、权限撤销的具体原因（除非公开声明）；网络栈历史贡献者的完整名单无法通过单一来源确定——除了核心维护者，还有数百名贡献者提交过 bug 修复、驱动更新和小功能改进；历史书写应当关注核心维护者，但不应忘记大量匿名或一次性贡献者

**史料**：FreeBSD 开发者维基 committer 分类页面；cgit.freebsd.org 作者统计；FreeBSD 贡献者名单（RELEASE CREDITS 文件） ［D］ 〔L1 代码；L3 官方文档〕

**史观**：总纲第 10 条——边缘者贡献：网络栈历史上有大量 “边缘贡献者”——报告 bug 的用户、测试新版本的管理员、提交小补丁的开发者——他们的名字大多不为人知，但每一个 bug 修复和改进都让网络栈更稳定；历史书写聚焦于核心人物，但应该承认边缘贡献的存在

**辨析**：不要假设 “没有公开权限变动” 等于 “没有任何冲突”——开源社区中冲突是常态，大部分冲突通过邮件列表讨论和技术决策解决，不需要动用权限撤销；Core Team 公开的权限撤销是非常极端的措施，过去十年中在整个 FreeBSD 项目中都非常罕见，不只是网络栈

**文献**：FreeBSD Project. *FreeBSD Release Credits*. src/RELEASE-CREDITS in source tree; FreeBSD Developer Wiki. *Committers by Area*. wiki.freebsd.org; FreeBSD Foundation. *Contributor Recognition*. freebsdfoundation.org. ［A］
