# 164.4.2 ZFS 在 FreeBSD 14.x 中的持续演进

**要点**：OpenZFS 2.2 在 14.x 周期内持续通过小版本更新获得 bug 修复与性能优化：14.1（2024.6）升级至 OpenZFS 2.2.4，包含重要的 bug 修复与稳定性改进；14.2（2024.12）升级至 2.2.6，修复 block cloning 在特定边缘场景下的数据完整性问题（该问题未造成已知数据丢失，但需要 scrub 修复元数据）；14.4（2026.3）升级至 2.2.9，包含从 OpenZFS 2.3 向后移植的部分修复（OpenZFS 2.3 已发布但未在 14.x 引入；**[事实修正]** 经 FreeBSD 15.0-RELEASE Announcement 核实，15.0 实际升级至 OpenZFS **2.4.0-rc4** 而非原稿所述的 2.3.x，OpenZFS 2.3 系列的功能作为 2.4.0-rc4 的功能集提供）；FreeBSD 14.0 开始在 AWS 和 Azure 上提供实验性 ZFS 云镜像，root-on-ZFS 引导支持已完全成熟（ZFS 根从 FreeBSD 9.0 开始支持，14.x 时期安装程序默认提供 ZFS 作为选项）；zfskeys rc 脚本自动解密 ZFS 原生加密数据集

**史观**：终结与延续：ZFS 在 FreeBSD 上的故事是延续性的经典案例——从 2007 年 Pawel Jakub Dawidek 移植 ZFS 到 FreeBSD 7.0（标记为 experimental），到 2023 年 OpenZFS 2.2 成为默认文件系统，16 年间 ZFS 从实验性功能变成 FreeBSD 最具竞争力的技术资产之一；没有任何一个开源文件系统项目拥有如此长的连续演进历史和跨平台代码库

**辨析**：14.2 升级至 2.2.6 时包含的 block cloning 元数据修复需 Release Notes 中明确提示用户在升级后执行手动 scrub 以验证文件系统完整性——这是 ZFS 历史上较少见的需要显式用户操作的文件系统修复，但因为 ZFS 的写时复制与校验架构，没有已知的数据丢失案例；OpenZFS 2.3（2024 年发布）包含 RAID-Z expansion（RAID-Z 设备逐个添加扩容，用户长期期待的功能）、fast dedup 等改进，但此功能未进入 14.x，原计划在 15.0 中提供；**[事实修正]** 经 FreeBSD 15.0-RELEASE Announcement 核实，15.0 实际升级至 OpenZFS **2.4.0-rc4**（而非 2.3.x），15.0 中 OpenZFS 2.3 系列的功能（RAID-Z expansion、fast dedup）作为 2.4.0-rc4 的功能集提供
