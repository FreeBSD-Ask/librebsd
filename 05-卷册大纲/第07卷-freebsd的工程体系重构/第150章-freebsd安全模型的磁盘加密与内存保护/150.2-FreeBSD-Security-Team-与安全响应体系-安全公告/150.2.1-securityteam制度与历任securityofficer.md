# 150.2.1 Security Team 制度与历任 Security Officer

**要点**：FreeBSD Security Team 由 Security Officer 领导，是负责接收安全漏洞报告、协调修复、发布安全公告的专门志愿者团队；Security Officer 职位自 FreeBSD 项目早期即存在，正式的 Security Team 流程在 2000-2002 年间逐步正规化，部分归因于 CVE-2002-0639 等高危漏洞事件的推动；历任 Security Officer（公开记录可查部分）：Colin Percival（任期约 2005-2012）——他同时是 **freebsd-update(8)**、**portsnap(8)**、scrypt 密钥派生函数、Tarsnap 备份服务的作者；Dag-Erling Smørgrav [存疑精确任期]——长期 FreeBSD committer，参与多项安全和基本系统工作；Simon L. Nielsen[考据完成：2026-08-17 Simon L. Nielsen 曾任 FreeBSD Security Officer（其后与 Colin Percival 同列 Security Officer Emeritus）]；Gordon Tetlow（戈登·泰特洛）[考据完成：2026-08-17 现任 Security Officer（freebsd.org/security/reporting 一手确认）]；Ed Maste（埃德·马斯特）[考据完成：2026-08-17 现任 Deputy Security Officer（freebsd.org/security/reporting 一手确认）]（活跃于 2010s-2020s，同时供职于 FreeBSD Foundation）；Security Team 的职责包括：维护 security-officer@ 和 secteam@ 私有协调邮件列表、管理安全报告 PGP 密钥、为每个安全漏洞分配内部跟踪编号、协调上游补丁和 FreeBSD 补丁开发、发布 FreeBSD-SA（Security Advisory）和 FreeBSD-EN（Errata Notice）公告、维护安全分支（releng/*）的安全补丁合并；Security Team 成员同时也是 FreeBSD src committer

**史料**：FreeBSD Security Team 官方页面 freebsd.org/security/（列有现任成员）；Security Officer PGP 密钥历史记录；freebsd-security@ 邮件列表公告中的 Security Officer 署名；Colin Percival 个人网站和演讲中关于 freebsd-update 和 Security Officer 经历的叙述；FreeBSD Core Team 公告中 Security Team 成员变动记录 ［A］

**史观**：总纲第 15 条——文化即形式主义：FreeBSD Security Team 的志愿者模式是开源安全治理的典型代表——与 Red Hat Product Security、Microsoft MSRC、Apple Product Security 等全职厂商安全团队不同，FreeBSD Security Team 成员大多是志愿者或半志愿者（部分由 FreeBSD Foundation 或其雇主资助），在有限时间内协调全球数百名开发者和数百万用户的安全响应；这一模式既体现了开源社区的奉献精神，也面临可持续性挑战

**辨析**：历任 Security Officer 的完整名单和精确任期在公开资料中并不完整——早期 Security Officer 记录分散在邮件列表公告中，部分任期边界模糊；Colin Percival 的任期经其个人简历和邮件列表记录确认为约 2005-2012，但前后任的精确日期需逐份查阅公告核实 [存疑脚注：2026-08-17 历任 Security Officer 精确任期须逐份查阅任命公告，联网仅能确认身份与大致顺序，无法确证精确日期]；现任 Security Team 成员名单在 freebsd.org/security/ 页面公开；“Security Team 负责所有 ports 安全”——不准确，ports 漏洞通过 VuXML 文档记录和 pkg audit 处理，基本系统漏洞才由 Security Team 直接负责 SA/EN
