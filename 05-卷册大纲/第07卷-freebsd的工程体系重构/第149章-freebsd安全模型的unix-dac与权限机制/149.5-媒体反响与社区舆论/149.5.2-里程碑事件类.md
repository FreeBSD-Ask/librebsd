# 149.5.2 里程碑事件类

### 新闻条目 1

- **新闻标题（中英）**：FreeBSD.org 已被攻破（FreeBSD.org Has Been Penetrated）
- **新闻来源**：Phoronix + Michael Larabel + 2012-11-17 + <https://www.phoronix.com/news/MTIzMTI> + <https://web.archive.org/web/2012/https://www.phoronix.com/news/MTIzMTI>
- **新闻摘要**：2012 年 11 月 FreeBSD 官方宣布 freebsd.org 基础设施遭遇入侵，攻击者通过 compromised 开发者账户获取了对集群的访问权限。FreeBSD 安全团队启动应急响应，重置所有开发者凭证并审计 commit 历史。这一事件是 FreeBSD 项目安全治理史上的重大事件，促使项目加强基础设施访问控制与多因素认证。
- **与本章主题的关联说明**：本章记述 FreeBSD 安全模型在基础设施层面的演进，2012 年 freebsd.org 入侵事件是 FreeBSD 安全治理从开发者信任模型向强制访问控制转型的关键节点。
- **与官方史料的交叉验证结论**：FreeBSD 官方安全公告（2012-11-17）与 Phoronix 报道交叉验证，事件描述与官方声明一致。

### 新闻条目 2

- **新闻标题（中英）**：FreeBSD 15.1-RC1 发布：修复中发现更多 AI 发现的安全问题（FreeBSD 15.1-RC1 Released: Fixes With Now Seeing More AI-Discovered Security Issues）

- **新闻摘要**：2026 年 5 月 FreeBSD 15.1-RC1 发布，包含多项由 AI/LLM 驱动的安全研究工具发现的安全修复。Phoronix 报道指出 FreeBSD 已开始接收通过 AI 工具发现的安全报告，这反映了 2020s 末安全研究方法的范式转变。
- **与本章主题的关联说明**：本章记述 FreeBSD 安全模型对新兴安全研究方法的响应，AI 驱动漏洞发现是 2026 年安全审计的新常态。
- **与官方史料的交叉验证结论**：FreeBSD 15.1-RC1 发行说明与 Phoronix 报道交叉验证，AI 发现的安全问题已在官方 errata 中列出。

### 新闻条目 3

- **新闻标题（中英）**：Linux 内核可能采用 FreeBSD 的 Capsicum 安全框架（The Linux Kernel Might Use FreeBSD's Capsicum Security Framework）
- **新闻来源**：Phoronix + Michael Larabel + 2014-07-07 + <https://www.phoronix.com/news/MTczNjM> + <https://web.archive.org/web/2014/https://www.phoronix.com/news/MTczNjM>
- **新闻摘要**：2014 年 7 月 Linux 内核社区讨论采用 FreeBSD 的 Capsicum 安全框架。Capsicum 是 FreeBSD 安全模型的核心组件之一，提供基于能力的沙箱框架。Linux 社区的讨论反映了 FreeBSD 安全模型设计对跨平台操作系统安全的影响。
- **与本章主题的关联说明**：本章记述 FreeBSD 安全模型的核心组件（Capsicum、Jails、MAC 框架等），Capsicum 的跨平台影响是 FreeBSD 安全设计输出的关键标志。
- **与官方史料的交叉验证结论**：Capsicum 论文（USENIX Security 2010）与 FreeBSD 9.0-RELEASE 发行说明可交叉验证；LKML 2014 年讨论可验证 Linux 社区意向。
