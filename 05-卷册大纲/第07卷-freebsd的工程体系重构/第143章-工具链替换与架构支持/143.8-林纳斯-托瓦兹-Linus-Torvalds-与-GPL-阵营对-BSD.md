# 143.8 林纳斯·托瓦兹（Linus Torvalds）与 GPL 阵营对 BSD 许可证的态度

## 143.8.1 Torvalds 对 BSD 许可证批评的观点梳理

**要点**：林纳斯·托瓦兹 作为 Linux 创始人，在 1990 年代至 2000 年代的 LKML 和访谈中多次对 BSD 许可证提出批评，核心观点是：BSD 许可证允许公司获取代码并将其闭源商业化而不回馈社区，这意味着 “你辛苦写的代码可能被别人拿走赚钱却不给你任何回报”；GPL 通过 copyleft 机制确保代码始终保持自由，防止 “搭便车” 行为；Linux 选择 GPLv2 是因为它在 “保护自由” 和 “允许商业使用” 之间取得了正确平衡。Torvalds 明确拒绝将 Linux 内核升级到 GPLv3（2007 年），认为 GPLv3 的反 tivoization 条款过于极端，这使他在 GPL 阵营内部处于独特的中间立场——支持 GPLv2 copyleft 但反对 GPLv3 的扩展。

**史料**：林纳斯·托瓦兹 LKML 帖子（1990s-2000s 关于许可证的讨论）、Torvalds 访谈（如 2000s 初 Linux 与 BSD 比较的言论）、Torvalds 2006-2007 年关于 GPLv3 的公开声明（明确拒绝升级）。 ［B］
    FreeBSD 社区论文：[FP-2019-014] LLVM and the state of sanitizers on BSD（David Carlier，2019）<https://papers.freebsd.org/2019/asiabsdcon/carlier-llvm_and_the_state_of_sanitizers_on_bsd/>

**史观**：总纲第 6 条——技术路线分化：Torvalds 的许可证立场直接塑造了 Linux 生态的基因——GPLv2-only（Linux 内核明确标注 GPLv2 only，不采用 “any later version” 条款），这使 Linux 内核既保持 copyleft 特性又不被 GPLv3 绑定，形成独特的生态定位。

**辨析**：Torvalds 虽然批评 BSD 许可证，但他并不反对 Clang/LLVM 技术本身——Linux 内核在 2020 年代已正式支持 Clang 编译（Android 长期以来一直使用 Clang 编译内核），他的批评集中于许可证哲学而非技术质量。

## 143.8.2 Torvalds 观点与 Linux 生态的关联

**要点**：Torvalds 的许可证立场决定了 Linux 内核的许可证身份：GPLv2 only（NOT “or any later version”）。这一决策在 2007 年 GPLv3 发布时产生了深远影响：Linux 内核没有像 GCC 那样升级到 GPLv3，因此避免了 FreeBSD 所面临的 GPLv3 危机——Linux 内核继续使用 GCC（GCC 4.3+ 为 GPLv3，但 GCC 运行时例外条款允许编译 GPLv2 代码）；内核社区认为 GCC 作为编译工具其 GPLv3 许可证不传染被编译的代码（这是 FSF 明确的立场），因此 GCC 升级不构成法律问题。Clang/LLVM 在 Linux 生态中的角色是额外选项而非必需替代——Android/ChromeOS 因 Google 技术战略选择 Clang，但主线 Linux 发行版仍以 GCC 为默认编译器。

**史料**：Linux 内核 COPYING 文件（明确 GPLv2 only）、GCC Runtime Library Exception 文本、LLVMLinux 项目文档、Android NDK Clang 切换历史。［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：总纲第 24 条——许可证：Torvalds 在 2006 年拒绝 “or any later version” 条款的决策被证明是极具远见的——它使 Linux 内核避免了 2007 年 GPLv3 发布时被迫升级或拒绝升级的法律危机，保持了 GPLv2 下的稳定许可证身份。这与 FreeBSD 在 GCC 升级问题上的被动局面形成对比。

**辨析**：“GCC GPLv3 编译 GPLv2 代码是否构成衍生作品” 是一个有争议的法律问题，但 FSF 和 Linux 内核社区均持 “编译器作为工具不传染输出” 的立场（通过 GCC Runtime Library Exception 明确），这一法律共识使 Linux 可以安全使用 GCC 4.3+ 而不引发许可证危机。

## 143.8.3 与 BSD 社区回应的比较

**要点**：BSD 社区对 Torvalds 批评的典型回应包括：①GPL 的 “保护自由” 实际上是 “强制自由”，剥夺了代码作者选择分发方式的自由——如果你想将自己的代码以 BSD 发布，GPL 强制你不能这么做（如果链接了 GPL 代码）；② 大公司为 BSD 代码做出贡献的案例不胜枚举（Apple 贡献 Clang/LLVM、Netflix 贡献 KTLS/网络栈优化、Juniper 贡献路由改进等），“搭便车论” 忽略了这种非强制回馈；③BSD 许可证的 “自由” 包括闭源使用的自由，这是真正的自由——不应强迫他人以你喜欢的方式使用代码；④Linux 的成功更多归功于时机（1991 年 386 芯片普及、BSD 受 USL 诉讼困扰）而非 GPL 许可证优势。

**史料**：FreeBSD 邮件列表对 Torvalds 言论的回应、McKusick/Kamp 等 BSD 核心人物关于许可证的公开言论、Theo de Raadt（西奥·德·若特）（OpenBSD）对 GPL 的批评。 ［A］

**史观**：总纲第 22 条——开源运动：BSD 与 GPL 的许可证辩论已持续三十余年（自 1980 年代 GNU 项目成立和 BSD 网络发布以来），双方均未说服对方，两大生态并行发展证明两种模式在软件生态中均有生存空间。

**辨析**：辩论双方都倾向于选择性使用证据——GPL 方常引用 “BSD 代码被用在微软产品中不回馈” 等案例，BSD 方常引用 “Apple/Netflix 回馈” 等案例，实际上两种回馈模式均存在。

**文献**：DiBona C, Ockman S, Stone M. Open Sources: Voices from the Open Source Revolution [M]. Sebastopol: O'Reilly, 1999. ISBN: 1-56592-582-6（含 Linus Torvalds、Richard Stallman、Paul Vixie 等多方观点）.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 143.8.4 史料辨析

**要点**：Torvalds 的许可证言论主要散布在 LKML 邮件和媒体访谈中，没有系统的专著。他的观点随时间演变——1990 年代的言论更为尖锐，2010 年代后他对 LLVM/Clang 持更为实用主义的态度（接受 Clang 可编译 Linux 内核）。二手引用常简化其立场为 “GPL 好 BSD 坏” 的刻板印象。

**史料**：LKML 存档、Torvalds 媒体访谈。 ［A］

**史观**：总纲第 3 条——形式主义膨胀：技术创始人的言论常被抽离语境成为意识形态旗帜，Torvalds 和 Hubbard 各自的 GPL/BSD 言论在 30 年传播中已被简化为口号，原始语境中的细微差别被丢失。

**辨析**：Torvalds 拒绝 GPLv3 的立场使他在 FSF 眼中并非 “GPL 正统”——Stallman 曾对 Torvalds 拒绝升级许可证表示失望。这表明 GPL 阵营内部也存在显著分歧。
