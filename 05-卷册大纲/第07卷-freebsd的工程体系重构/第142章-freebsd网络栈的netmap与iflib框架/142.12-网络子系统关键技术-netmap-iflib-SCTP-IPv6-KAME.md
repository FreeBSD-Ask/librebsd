# 142.12 网络子系统关键技术：netmap、iflib、SCTP、IPv6/KAME——高速包处理、新一代驱动框架、传输协议演进、IPv6 原生支持

## 141.12.1 netmap：高速线速包 I/O 框架

**要点**：**netmap(4)** 是 Luigi Rizzo（比萨大学，同时也是 FreeBSD 长期贡献者、dummynet 作者）设计的高速网络包 I/O 框架，论文发表于 SIGCOMM 2011；netmap 的核心思想是：通过将网卡环形缓冲区和内核包内存直接映射到用户态，绕过传统的 **mbuf(9)** 分配和协议栈处理，实现线速（wire speed）包处理——在 10Gbps 网卡上可以实现 14.88 Mpps（百万包每秒）的收发性能，仅占用单个 CPU 核的一小部分；VALE 是 netmap 附带的虚拟软件交换机，可作为虚拟机和 jail 之间的高速虚拟交换机；netmap pipes 实现高性能包管道；netmap 于 FreeBSD 10.0（2014 年 1 月）正式合入 FreeBSD 基础系统，Linux 也有 netmap 移植；与 DPDK（Intel 开发的用户态包处理框架）相比，netmap 更轻量、代码更小、与内核协议栈更好地集成（可以实现网卡拉分流——一部分流量走 netmap 用户态、一部分走内核协议栈），DPDK 生态更丰富但完全绕过内核

**史料**：**netmap(4)** 手册页；Rizzo, L. 2012 SIGCOMM 论文 "netmap: A Novel Framework for Fast Packet I/O"；FreeBSD 10.0 Release Notes netmap 章节；Rizzo netmap 主页（info.iet.unipi.it/~luigi/netmap/）；VALE 虚拟交换机论文；**bsd_commits.db** `commits` 表 `freebsd-src` 仓库数据库验证——netmap 首次完整引入 commit 为 `68b8534bdfeb5078e84d668124e7585e43b03502`，author = Luigi Rizzo，author_date = 2011-11-17T12:17:39Z，committer_date = 2011-11-17T12:17:39Z，subject = "Bring in support for netmap, a framework for very efficient packet I/O from userspace, capable of line rate at 10G, see"；此 2011-11-17 的 commit 时间点处于 FreeBSD 9.x 开发周期内（FreeBSD 9.0-RELEASE 为 2012-01-12，约 2 个月后），印证原大纲 “netmap 代码在 FreeBSD 9.x 时代通过开发分支可获取” 的判断；数据库另显示 netmap 相关准备工作可追溯至 2011-06-14（Rizzo 提交 `c9d658e9f7ea84b09d07d805589de6f7e9b0fc59`，"Grab one of the ifcap bits for netmap, and enable printing in ifconfig."，为 netmap 预留 ifcap 位），2011-07-17（Bjoern A. ## 141.12.2 iflib：下一代网络接口驱动框架

**要点**：**iflib(4)**（interface library）是 FreeBSD 的新一代网络接口驱动框架，由 John Baldwin（约翰·鲍德温） 和 Matt Macy 设计，于 FreeBSD 11.0（2016 年 10 月）引入，在 FreeBSD 12.0（2018 年）成为推荐的网卡驱动编写框架；iflib 出现之前，FreeBSD 网卡驱动直接与 **ifnet(9)** 层交互，每个驱动独立实现多队列、MSI-X 中断、校验和卸载、TSO/LRO 等功能，代码大量重复且容易出错；iflib 将这些通用功能抽象到公共框架中，驱动只需实现硬件相关操作（初始化、发送/接收队列操作、中断处理等），大大减少了代码重复并提升了多队列性能；FreeBSD 11/12/13 中越来越多网卡驱动迁移到 iflib，包括 Intel **ixl(4)**（10G/25G/40G/100G）、Mellanox **mlx5(4)**（10G-200G+）、Broadcom **bnxt(4)** 等现代高速网卡驱动；iflib 天然支持多队列分发、RSS（Receive Side Scaling）、硬件 offload、校验和、TSO/LRO、VLAN 卸载

**史料**：**iflib(4)**、**iflib(9)** 手册页；Baldwin, J. 和 Macy, M. iflib 设计文档；FreeBSD 11.0/12.0 Release Notes iflib 章节；FreeBSD 源码 sys/net/iflib.c 实现 ［A］
    FreeBSD 社区论文：[FP-2018-025] Improving netdump hardware support and performance with iflib（Sam Gwydir，2018）<https://papers.freebsd.org/2018/bsdcan/gwydir-improving_netdump_hardware_support_and_performance_with_iflib/>

**史观**：总纲第 17 条——软件工程：iflib 是软件架构中 “抽象重复模式” 的经典案例——当多个驱动重复实现相同的多队列、中断、offload 逻辑时，就应该将这些逻辑抽成公共框架；这一重构大大降低了新网卡驱动的编写难度，提升了驱动质量一致性

**辨析**：iflib 引入版本——iflib 在 FreeBSD 11.0 存在但早期采用率低，FreeBSD 12 开始大多数新驱动基于 iflib 编写；“所有驱动都必须用 iflib”——不，旧驱动（如 Intel em/igb、Realtek re）仍使用旧 ifnet 接口，新驱动才强制要求 iflib；iflib 是否提高了性能——是的，iflib 的多队列和锁设计比大多数旧驱动更好，在多 CPU 系统上网络性能显著提升；John Baldwin 和 Matt Macy 的角色——Macy 做了初始框架设计和早期驱动移植，Baldwin 做了大量代码审查、框架改进和 bug 修复

## 141.12.3 SCTP、IPv6/KAME 与无线驱动支持

**要点**：SCTP（Stream Control Transmission Protocol，RFC 4960）是一个现代传输层协议，支持多流（multi-streaming）、多宿主（multi-homing），最初为电信信令设计但也用于通用网络；FreeBSD SCTP 实现主要由 Randall Stewart 和 Michael Tuexen 维护，于 FreeBSD 7.0（2008 年）正式合入基础系统，是业界质量最高的 SCTP 实现之一；IPv6 支持来自日本 KAME 项目——KAME 是 1998-2006 年日本多家公司和研究机构（NEC、Toshiba、Hitachi、IIJ、Keio University、WIDE 项目）合作的 BSD IPv6/IPsec 参考实现项目；FreeBSD 4.0（2000 年）引入 KAME IPv6 栈，是最早原生支持 IPv6 的主流操作系统之一；无线驱动方面 FreeBSD 支持多种无线网卡：**ath(4)**（Atheros，Sam Leffler 维护，质量最好）、**iwn(4)**/**iwm(4)**（Intel Wireless）、**urtw(4)**/**rtwn(4)**（Realtek USB WiFi）、**wpi(4)**（Intel 3945）等；无线子系统和 **wlan(4)** 802.11 层主要由 Sam Leffler 开发和维护

**史料**：**sctp(4)**、**inet6(4)**、**wlan(4)**、**ath(4)**、**iwm(4)** 手册页；KAME 项目官网（kame.net 存档）；Stewart, R. SCTP 相关 RFC 和 FreeBSD 实现文档；FreeBSD 4.0/7.0 Release Notes IPv6/SCTP 章节；Leffler, S. 无线子系统设计文档 ［A］

**史观**：总纲第 22 条——开源运动：KAME 项目是国际开源协作的典范——日本多家公司和大学联合开发 IPv6 栈并贡献给所有 BSD 系统；在 1998-2005 年全球 IPv6 采用早期，KAME 代码是最成熟的 IPv6 实现，被 FreeBSD、NetBSD、OpenBSD、DragonFly 和 Mac OS X 采用

**辨析**：SCTP 引入版本——FreeBSD 7.0（2008）正式合入，6.x 时可作为补丁和内核选项实验性使用；IPv6 引入——FreeBSD 4.0（2000）包含 KAME IPv6，但更早的 FreeBSD 3.x 有 experimental IPv6 支持；KAME 项目结束时间——2006 年 3 月项目正式结束，代码已完整并入各 BSD 系统；无线驱动质量——FreeBSD 无线支持不如 Linux 全面，主要因为无线厂商很少提供开源驱动文档，尤其是最新的 802.11ac/ax 网卡支持滞后；Sam Leffler 在 FreeBSD 无线子系统的角色非常重要

## 141.12.4 网络子系统关键技术的史料辨析

**要点**：netmap、iflib、SCTP、KAME IPv6 这几个子系统有一个共同点：它们都是由特定领域专家长期维护的 “专业级” 代码——Rizzo 的 netmap/dummynet、Stewart/Tuexen 的 SCTP、Baldwin/Macy 的 iflib、KAME 团队的 IPv6、Leffler 的无线子系统；FreeBSD 网络栈不是由某个统一团队 “设计” 的，而是在 30 年间由不同领域的专家持续贡献和维护形成的有机整体；netmap 的一个常被忽视的特点：它的 API 设计同时支持内核模块和用户态程序，内核模块可以直接使用 netmap API 实现高速包处理（如软件交换机、防火墙）。FreeBSD 网络子系统关键技术演进汇总见下表。
