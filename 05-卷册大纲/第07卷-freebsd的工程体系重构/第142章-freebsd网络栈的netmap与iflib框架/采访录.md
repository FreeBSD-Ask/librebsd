#### 采访 1：Hans Petter Selasky

**字段 1 采访元数据**

- 受访者：Hans Petter Selasky，FreeBSD 开发者，新 USB 子系统与 iflib 框架作者
- 采访者：自述，无采访者（会议演讲）
- 采访时间：2016-05
- 采访形式：会议演讲（BSDCan 2016）
- 原始来源：Selasky, BSDCan 2016 USB/iflib 演讲。YouTube BSDCan 频道 **<https://www.youtube.com/@BsdcanOrg/playlists>**

**字段 2 采访摘要**

Selasky 在 BSDCan 2016 演讲中介绍了 FreeBSD 新 USB 子系统的设计理念与 iflib 网络接口框架的集成路径，详述新 USB 栈从旧式 USB 子系统的迁移历程、iflib 抽象层对网络驱动统一化的设计决策。他还讨论了新 USB 栈在 FreeBSD 8.x 中的首次集成与后续性能优化。

**字段 3 考据脚注**

BSDCan 2016 录像经联网检索 BSDCan YouTube 频道核实。Selasky 作为新 USB 子系统作者的身份经 FreeBSD 源码仓库 commit 历史与 FreeBSD 邮件列表存档交叉验证。自利偏差审查：Selasky 对新 USB 栈优越性的表述须对照旧 USB 子系统维护者的异见。完整考据过程见 [20260724_selasky-usb-iflib-bsdcan2016.md](../../../原材料/研究/考据记录/20260724_selasky-usb-iflib-bsdcan2016.md)。

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——据第 14 章 14.2 节“真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者”，Selasky 从旧 USB 栈痛点出发重写子系统，是老实人的动手实践；其工作不是“动手 vs 理论”的二元对立（项目统摄史观批评此类不辩证的二元）——iflib 抽象层设计是理论活动，USB 栈重写是动手活动，二者并进恰是辩证实践，不可简化为“重写者 vs 维护者”的二元。
- 总纲 4“分离聚合是永恒规律”——据第 25 章总纲 4“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”，新 USB 栈从旧式 USB 子系统的迁移，是分合循环中“新代旧”的一例；这不是“技术演进”的进步叙事，而是分离聚合的诡异曲线，与总纲 3“不存在进步，只有权力再分配”同构。
- 总纲 22“知识注定过时”——据第 25 章总纲 22“今天书写的技术史，可能在出版之日就已过时”，USB 协议演进推动 USB 栈持续重写，2016 年演讲所述新 USB 栈在今天即成历史遗产；这正是“技术债务是历史遗产”的具现，而非“USB 栈现代化”的进步叙事。
- 总纲 7“理论必须自反”——据第 25 章总纲 7“理论字数越多越不值钱”与第 6 章 6.3 节“真正的理论体系应该是自反的”，USB 硬件规范演进反映的并非“硬件反塑软件”的单向因果（项目统摄史观批评此类决定论），而是理论在硬件演进面前的自反性——USB 栈设计须随规范演进而否定重构，与总纲 22“知识注定过时”同构。

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——据第 14 章 14.1 节“没有多余形式主义的人就是老实人”与 14.4 节“FreeBSD 是少数人的选择，是‘百分之一的生活’”，Stewart 从电信传输痛点出发实现 SCTP，是少数人的选择；其工作不可简化为“协议设计者 vs 代码工人”的二元对立（项目统摄史观批评此类不辩证的二元），而是主体性的一刻呈现。
- 总纲 4“分离聚合是永恒规律”——据第 25 章总纲 4“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”，SCTP 与 TCP 选择不同可靠性路线，是分合循环中分离的一例；这不是“技术路线分化及其代价”的工具论叙事，而是分离聚合的诡异曲线，与总纲 3“不存在进步，只有权力再分配”同构。
- 总纲 8“本体论上各方平等”——据第 25 章总纲 8“FreeBSD、OpenBSD、NetBSD、DragonFly BSD 在本体论上地位相等，差异仅是一刻状态的不同”，SCTP 与 TCP 在本体论上地位相等；Stewart 讨论“可靠性差异”不暗示 SCTP“进步于”TCP，而是一刻状态的不同。
- 总纲 11“商品是形式主义”——据第 25 章总纲 11“技术市场的选择不是自然选择，而是形式主义的权力运作。劣币驱逐良币是普遍规律”，SCTP 在电信信令场景的部署实践反映的是市场权力运作而非技术优劣；SCTP 未在 Web 主流普及，是“劣币驱逐良币”的具现，与“协议优越性”的道德叙事无关。

**要点**：

- Randall Stewart 以 Cisco 杰出工程师与 SCTP 共同发明人身份受访：他常驻 IETF 从事传输协议工作，声明以个人立场发言，但 Cisco 确实资助其在 BSD 栈上的 SCTP 开发。（BSDTalk EP102，[59.8-80.16]，L1）
- SCTP 的设计针对 TCP 的四项根本缺陷：字节流语义迫使应用自行分帧而多数应用交换的是消息；绝对有序造成队头阻塞，网页多图下载与信令传输皆受其害，SIGTRAN 呼叫控制放弃 TCP 的主因即呼叫建立消息一旦丢失便阻塞全程；TCP 固有单宿、连接由四元组定义而无故障容忍；以及约每千万包漏检一次的弱校验和，有对互联网 TCP 流的实测研究支撑。（BSDTalk EP102，[483.48-864.42]，L1）
- SCTP 的对应设计：以 association（两端 IP 地址集合加端口）取代四元组连接，接口或线路故障时连接不坠，他自述家中双 DSL 时期一条中断另一条自动续传、仅见一次重传超时；消息导向保留消息边界，TCP 兼容应用只需两次读调用，专为 SCTP 编写的应用一次读即得完整消息；采用强校验和并在四次握手中内置 cookie 与 verification tag 以抵御 SYN 洪泛与盲目注入。 [存疑脚注] 本条综合多段转写（1081.72-1123.2、1346.2-1495.72、876.1-909.1）重建，末段音频有损（BSDTalk EP102，[909.1-911.78]，L1）
- 他论证端主机多宿优于路由层冗余：路由收敛可致一至十分钟流量黑洞，链路汇聚于同一交换机仍是单点故障，ISP 入口过滤又阻断 TCP 的本地绕行；向互联网注入主机路由以通告备用线路会令全局路由表近乎指数增长，威胁默认路由区的可扩展性。（BSDTalk EP102，[1026.58-1174.56]，L1）
- FreeBSD 集成史：2001 年起与 KAME 项目合作，在其快照上构建 SCTP 并参加多次互操作测试；KAME 结束后经 George Neville-Neil 与 Robert Watson 引荐获得指导与临时提交权限，适应 style(9) 风格指南；7-CURRENT 时期约六个月的模块化与密集测试后代码趋于稳定，加拿大 MPI 团队、特拉华大学实验室与 macOS 平台均有使用与测试，另有公司基于该代码开发产品；6.0/6.1 提供补丁，内核默认不启用。（BSDTalk EP102，[1501.72-1669.72]，L1）
- 标准化经验之谈：SCTP（当时称 MDTP）被带入 IETF 时恰逢 SigTRAN 工作组启动，IETF 罕见地愿意接纳新传输协议，其提案获选后经多方共同作者反复修改；他称标准制定的关键词是妥协，并推荐 Marshall Rose 的《The Open Book》第 16 章作为理解标准组织运作的经典。（BSDTalk EP102，[1714.08-1813.9]，L1）
- 部署障碍与迁移路径：纯路由器只读 IP 头故 SCTP 穿越无碍，真正的障碍是防火墙与 NAT，他家中的 NAT 设备迫使其只能从 DMZ 使用 SCTP，他寄望 FreeBSD 将 NAT 与防火墙认知内建（FreeBSD PF 圈的 Max Laier 或将着手）；应用迁移仅需把 socket 调用改为 IPPROTO_SCTP；特拉华大学硕士生的 socket 层 shim 可令二进制 TCP 应用透明获得 SCTP 优先回退 TCP 的双栈能力；ADD-IP 与 authentication 扩展即将成为 RFC，支持动态增删地址与主地址切换，他 2002 年已在芝加哥院中演示过跨地址的移动漫游。 [存疑脚注] 转写将 Max Laier 误识别为 Max Lear、shim 项目基于 FreeBSD 4.11 等细节置信度中等，引用前须核对原始音频（BSDTalk EP102，[434.24-483.48]，L1）

**史观**：

- 总纲9 经验优先：SCTP 的核心设计动机来自呼叫控制信令的真实工程困境——信令消息按序重传会阻塞整通电话，而非抽象的协议美学；协议形态由 SIGTRAN 的实际业务需求塑造，是经验优先于理论推演的一手例证。（BSDTalk EP102，[740.26-767.3]，L1）
- 总纲5 没有必然性，只有偶然性：SCTP 获选 SigTRAN 传输协议的关键在于偶然时机：恰逢 IETF 启动 SigTRAN 且罕见地愿意评审新传输协议，其提案恰好在窗口内送达；新协议的命运系于历史窗口而非纯技术优劣，成败中充满偶然。（BSDTalk EP102，[1714.08-1785.8]，L1）
