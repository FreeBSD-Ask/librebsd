# 148.3 Git 迁移完成（2021.4.6）——Subversion 到 Git 的迁移（详见相关章节）

## 148.3.1 SVN→Git 迁移的工程过程与时间线

**要点**：FreeBSD 从 Subversion（svn）到 Git 的迁移工作持续约两年，2021 年 4 月 6 日正式完成，Git 成为 FreeBSD src、ports、doc 仓库的官方版本控制系统；迁移关键节点：(1) 2019 年 FreeBSD 基金会资助 Git 迁移工作组启动；(2) 2020 年逐步开展镜像测试、committer Git 培训；(3) 2020 年 12 月 src 仓库 Git 镜像开始同步；(4) 2021 年 3 月冻结 svn 提交；(5) **2021 年 4 月 6 日 Git 仓库成为权威仓库**，svn 仓库转为只读镜像；Ed Maste（埃德·马斯特） 担任迁移工作组负责人，Glen Barber（格伦·巴伯）、Bryan Drewery（布莱恩·德鲁里）、Colin Percival 等参与迁移工程；迁移保留了完整的 commit 历史（从 1993 年至今）

**史料**：Git 迁移工作组 2021 年 4 月 6 日公告；FreeBSD 基金会 Git 迁移项目页面；Ed Maste 在 EuroBSDCon 2020 的“FreeBSD Git Migration”演讲；src/CHANGES 中 Git 迁移相关说明 ［A］

**史观**：终结与延续：2021 年 4 月 6 日标志着 FreeBSD 使用了 20 年（2001-2021）的 CVS/SVN 时代终结，Git 时代开始；这不是简单的工具替换，而是开发工作流的深刻变革——Gerrit 代码审查、GitHub Pull Request 镜像、CI/CD 集成等现代开发实践成为可能

**辨析**：“13.0 是 Git 迁移后第一个 RELEASE”是准确的——svn 在 2021 年 3 月冻结提交，13.0 构建在 Git 迁移完成后进行；但 13.0 的开发周期大部分时间仍在 svn 上进行，13.1 才是完全在 Git 工作流下开发的第一个版本；迁移并非“所有人都满意”——部分老 committer 对 Git 工作流不适应，但社区整体接受了迁移

**文献**：FreeBSD Project. (2021-04-06). *Git Migration Complete Announcement*. freebsd.org; Maste, E. (2020). *FreeBSD Git Migration*. EuroBSDCon 2020; FreeBSD Foundation. (2021). Git Migration Project Retrospective. ［A］

## 148.3.2 Git 迁移对开发模式的效应

**要点**：Git 迁移对 FreeBSD 开发模式产生多方面深远影响：(1) 代码审查：引入 Gerrit 代码审查系统（reviews.freebsd.org），改变了过去“直接 commit 到主干”的模式，新贡献者代码强制审查；(2) 分支管理：Git 轻量级分支使得 feature branch 开发更便捷，稳定分支管理更灵活；(3) 外部贡献：GitHub 镜像（github.com/freebsd/freebsd-src）降低了新贡献者参与门槛，Pull Request 成为贡献渠道之一；(4) CI/CD：基于 GitHub Actions 和 Cirrus CI 的持续集成成为可能，构建和测试自动化程度提高；(5) 子模块：Git submodule 替代了 svn vendor branch 机制，用于管理第三方代码（如 OpenZFS、LLVM）；(6) 提交信息规范：强制执行提交信息格式、Signed-off-by 等要求

**史料**：reviews.freebsd.org Gerrit 使用文档；FreeBSD 开发者手册“Git”章节；FreeBSD GitHub 仓库统计数据；commit log 中 Submitted-by、Reviewed-by、MFC-after 标签使用规范 ［A］

**史观**：开源运动：Git 迁移使 FreeBSD 开发基础设施与当代开源生态（GitHub、GitLab 等）接轨，降低了年轻开发者参与 FreeBSD 的门槛——熟悉 Git 的开发者无需学习 svn 即可参与贡献

**辨析**：Git 迁移并非“完全抛弃 svn 时代的工作流”——FreeBSD 仍保留了 committer 直接推送权限（并非所有项目都强制 PR+ 审查）、MFC（Merge From Current）稳定分支合并流程等自身特色；“Git 使 FreeBSD 开发更快”这一说法需辩证看待——审查流程增加了单个 commit 的合并时间，但提高了整体代码质量

**文献**：FreeBSD Project. *Committer's Guide* (Git chapter). freebsd.org/doc; FreeBSD Project. reviews.freebsd.org Gerrit Documentation. ［A］

## 148.3.3 与其他 OS 版本控制策略比较

**要点**：同期其他操作系统的版本控制迁移情况：(1) Linux 内核从 2005 年起使用 Git（林纳斯·托瓦兹（Linus Torvalds）为管理 Linux 内核开发亲自创建 Git），从未使用 svn；(2) OpenBSD 长期使用 CVS，直到 2024 年仍在使用 CVS（OpenBSD 开发者认为 CVS 足够简单可靠）；(3) NetBSD 于 2015 年从 CVS 迁移到 Git；(4) DragonFly BSD 较早使用 Git；(5) illumos 从 Mercurial 迁移到 Git；FreeBSD 是主要 BSD 系统中较晚迁移到 Git 的，这与其代码库规模大、保守的工程文化有关

**史料**：OpenBSD CVS 使用说明（openbsd.org/cvs.html）；NetBSD Git 迁移公告（2015）；Linux 内核 Git 历史；各 BSD 项目官网仓库信息 ［A］

**史观**：总纲第 6 条——技术路线分化：版本控制系统选择体现了各项目的工程哲学：OpenBSD 坚持 CVS 体现了“够用就好、不盲目追新”的保守哲学；FreeBSD 经过多年评估和测试才迁移，体现了“不破坏开发者体验”的工程原则；Linux 最早迁移并创建 Git 本身，体现了“自主研发工具”的黑客精神

**辨析**：“OpenBSD 不迁移 Git 是因为技术落后”是一种误解——OpenBSD 开发者多次公开表示 CVS 满足其需求，Git 的复杂性对 OpenBSD 项目规模而言不必要；工具选择应服务于项目需求，而非反过来

**文献**：OpenBSD Project. *CVS Usage*. openbsd.org; NetBSD Project. (2015). *NetBSD Switches to Git*. netbsd.org; Torvalds, L. (2005). *Git: The Stupid Content Tracker*. Linux Kernel Mailing List.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 148.3.4 Git 迁移史料辨析

**要点**：Git 迁移的一手史料包括：(1) FreeBSD 基金会 2019-2021 年关于迁移的博客文章和公告；(2) freebsd-git 邮件列表存档；(3) Ed Maste、Glen Barber 等在会议上的演讲；(4) src 仓库中 Subversion→Git 转换的 commit 记录（注意：Git 转换保留了 svn 时代的作者信息和提交时间）；迁移过程中遇到的主要技术挑战包括：svn 到 Git 的作者映射、vendor branch 转换为 Git submodule、提交签名验证、大型仓库性能优化等

**史料**：<freebsd-git@freebsd.org> 邮件列表存档；git.freebsd.org 仓库统计；FreeBSD 基金会 2020-2021 年度报告中 Git 迁移相关章节 ［A］

**史观**：总纲第 3 条——形式主义膨胀：版本控制系统迁移本质上是开发基础设施的“形式化升级”——Git 本身是更强大、更形式化的版本控制工具，它强制实施更多工作流规则，这在提高协作效率的同时也增加了形式化负担

**辨析**：svn 仓库只读镜像的寿命——FreeBSD 项目承诺长期保留 svn 镜像供历史查询，但所有新开发必须在 Git 上进行；部分旧文档和教程仍引用 svn 命令，需注意更新

**文献**：FreeBSD Project. freebsd-git Mailing List Archives; FreeBSD Foundation. (2021). *2021 Annual Report* (Git Migration chapter). ［A］
