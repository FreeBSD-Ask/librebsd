# 138.13 与同时期操作系统的比较：FreeBSD 安全模型——DAC+MAC+Jail+Capsicum——与 Linux、OpenBSD、Windows、macOS、illumos 的对照

## 138.13.1 Linux LSM / SELinux / AppArmor

**要点**：Linux 通过 LSM 框架提供 MAC（SELinux 标签化、AppArmor 路径化），配合传统 UNIX DAC 与用户命名空间（user namespace，提供轻量隔离）；FreeBSD 的 MAC 框架（含 Biba、MLS、mac_portacl 等模块）+ Jail + Capsicum 构成类似但更早成体系的组合，二者在 “DAC 之上的强制层” 上思路一致。

**史料**：Linux LSM/SELinux/AppArmor 文档；FreeBSD MAC 框架手册（mac(4) 等）［A］

    FreeBSD 社区论文：[FP-2019-025] mac_grantbylabel: Securely controlled privilege escalations via maclabel（Simon Gerraty，2019）<https://papers.freebsd.org/2019/bsdcan/gerraty-mac_grantbylabel/>
    FreeBSD 社区论文：[FP-2010-005] Capsicum: practical capabilities for UNIX（Robert N. M. Watson（罗伯特·N·M·沃森），2010）<https://papers.freebsd.org/2010/rwatson-capsicum/>

    FreeBSD 社区论文：[FP-2000-001] Jails: Confining the omnipotent root（Poul-Henning Kamp（波尔-亨宁·坎普）; Robert N. M. Watson，2000）<https://papers.freebsd.org/2000/phk-jails/>

**史观**：总纲第 6 条——技术路线分化：Linux 以 LSM 可插拔 MAC、FreeBSD 以原生 MAC 框架+Jail，体现两种 UNIX 安全架构的组织方式差异。

**辨析**：FreeBSD MAC 与 SELinux 功能重叠但 FreeBSD 的 Jail 提供比 Linux user namespace 更早成熟的轻量虚拟化隔离；将二者优劣简单对比忽略历史时序。

## 138.13.2 OpenBSD 默认安全

**要点**：OpenBSD 以 “默认安全” 哲学著称——W^X（写或执行不可兼得）、特权分离、pledge/unveil、ssp 栈保护等；其安全模型不以 MAC 为中心，而以防守性代码实践与最小权限原语为核心，与 FreeBSD 的 “框架化 MAC+Jail” 形成对照。

**史料**：OpenBSD 安全特性文档（W^X、pledge 等）［A］

**史观**：总纲第 7 条——BSD 谱系：OpenBSD 与 FreeBSD 同源 4.4BSD-Lite，安全路线却分叉——OpenBSD 重 “代码级防御”、FreeBSD 重 “框架级隔离”，体现 BSD 家族内部的安全哲学分化。

**辨析**：OpenBSD 不依赖 MAC 不等于 “安全弱”——其纵深防御（W^X+pledge+ 特权分离）在实战中成效显著；两种模型各有适用场景。

**文献**：OpenBSD. Security Features [EB/OL]；Provos N, Chapman R. Countermeasures [EB/OL]. ［A］

## 138.13.3 Windows DACL / 完整性级别

**要点**：Windows 以 DACL（自主访问控制列表）+ 完整性级别（IL，提供类似 MAC 的强制层）+ AppContainer 构成安全模型；与 FreeBSD 的 UNIX DAC+MAC+Jail 在概念上对应，但基于 NT 内核的 token/ACL 体系，且闭源不可审计。

**史料**：Microsoft Windows 安全架构文档（DACL/IL）［A］

**史观**：总纲第 6 条——技术路线分化：NT 的 ACL 模型与 FreeBSD 的 UNIX 权限+MAC 在 “主体-客体” 控制上殊途同归，但开源可审计性是 FreeBSD 的结构性优势。

**辨析**：Windows IL 提供类似 MAC 的强制层，但其闭源使安全研究依赖微软披露；FreeBSD 的开源允许独立审计（如 Project Zero 等）。

## 138.13.4 macOS / XNU Sandbox

**要点**：macOS 基于 XNU（Mach+BSD）与 TrustedBSD MAC 框架提供 Sandbox（App Sandbox）与 SIP（系统完整性保护）；其安全模型融合 BSD 权限与 Mach 隔离，是 BSD 安全技术经 Apple 改造的商业实现。

## 138.13.5 illumos / Solaris RBAC

**要点**：illumos（OpenSolaris 衍生）与 Solaris 提供 RBAC（基于角色的访问控制）、特权分割（privileges）与 zones（轻量虚拟化隔离）；其特权模型与 FreeBSD 的 MAC+Jail 在 “最小权限 + 隔离” 上思路相近，zones 与 Jail 更是一对对照概念。

**史料**：illumos/Solaris RBAC 与 zones 文档 ［B］

**史观**：总纲第 6 条——技术路线分化：Solaris zones 与 FreeBSD Jail 是 2000 年代轻量虚拟化的两条并行路线，illumos 延续了 Solaris 的特权模型。

**辨析**：zones 比早期 Jail 功能更完整（独立网络/文件系统视图），但 Jail 更轻量且 BSD 许可；二者反映不同工程权衡。

**文献**：Sun/Oracle. Solaris RBAC and Zones [Z]；illumos. Documentation [EB/OL]. ［B］
