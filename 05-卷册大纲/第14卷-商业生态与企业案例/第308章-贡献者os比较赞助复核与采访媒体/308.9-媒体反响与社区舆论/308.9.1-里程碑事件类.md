- **新闻摘要**：FreeBSD Foundation 官方 Netflix 案例研究，详细记载 Netflix 采用 FreeBSD-CURRENT 作为 Open Connect CDN 操作系统的历程。案例研究披露：2012 年 Netflix 在原生 FreeBSD 9.0-RELEASE 与 nginx 上启动概念验证 CDN，配备单个 10 Gbit/s 接口的服务器；Netflix 关键贡献包括优化 `sendfile` 操作、内核 TLS（KTLS）支持、RACK TCP 栈（Randall Stewart 开发）；Netflix 实现了 400 Gb/s 吞吐量与全球首个 100 Gbit/s 生产 CDN 服务器。关键工程师包括 Gleb Smirnoff、Drew Gallatin、Scott Long、Randall Stewart、Hans Petter Selasky。
- **与本章主题的关联说明**：此为 Netflix 与 FreeBSD 关系最权威的官方案例研究，是本章核心一手史料。
- **与官方史料的交叉验证结论**：此为 FreeBSD Foundation 官方一手史料。Netflix 使用 FreeBSD 9.0-RELEASE 起步与 FreeBSD 9.0 RELEASE notes（2012-01-12）一致。关键工程师姓名与 FreeBSD commit log 交叉验证：Gleb Smirnoff、Drew Gallatin、Randall Stewart 均为长期 FreeBSD committer。

### 新闻条目 3

- **新闻标题（中英）**：内核 TLS（KTLS）——Netflix、Chelsio、Mellanox 的社区协作
- **新闻来源**：FreeBSD Foundation Netflix 案例研究 + 多位贡献者 + 发布日期 2024-11-01 + URL <https://freebsdfoundation.org/end-user-stories/netflix-case-study/> + KTLS 论文 <https://freebsdfoundation.org/wp-content/uploads/2020/07/TLS-Offload-in-the-Kernel.pdf>
- **新闻摘要**：Netflix 案例研究详述内核 TLS（KTLS）的发展历程。Scott Long 首先提议将 TLS 集成到内核；他与 Randall Stewart 共同开发了基础软件 TLS 传输机制；Drew Gallatin 引入外部页 mbufs 与 M_NOTREADY mbufs，并开发可插拔接口。FreeBSD 相关记录（详情见存疑库）通过 sendfile 与内核 TLS，我们可以消除许多内存带宽瓶颈。”

- **与本章主题的关联说明**：KTLS 是 Netflix 对 FreeBSD 社区最重要的技术贡献之一，体现了 Netflix-Chelsio-Mellanox 三方社区协作模式，是 Netflix 回馈 FreeBSD 社区的核心证据。
- **与官方史料的交叉验证结论**：KTLS 代码与 FreeBSD commit log、FreeBSD 13.0 RELEASE notes 交叉验证。Hans Petter Selasky 为 FreeBSD committer（已故），其贡献与 FreeBSD 讣告帖子交叉验证（<https://forums.freebsd.org/threads/in-memoriam-hans-petter-william-sirevag-selasky.89697/>）。
