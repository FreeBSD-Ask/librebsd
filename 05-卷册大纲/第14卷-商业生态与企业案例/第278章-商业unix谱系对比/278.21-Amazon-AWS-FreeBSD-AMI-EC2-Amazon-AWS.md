# 278.21 Amazon（AWS、FreeBSD AMI、EC2）——Amazon AWS 2006 年起 EC2 服务支持 FreeBSD AMI

## 278.21.1 FreeBSD on EC2 项目的启动与维护

**要点**：**Colin Percival** 于 2011 年起启动 **FreeBSD on EC2** 项目，发布官方 **AMI** 快照，2014 年获 **FreeBSD Foundation** 资助持续维护。

**史料**：**Percival** 邮件列表公告、**FreeBSD Foundation** 2014 年报、**AWS** **EC2** **FreeBSD** 镜像目录 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑挂靠〕：个人维护者与基金会资助的结合并非单纯协作叙事——Percival 自述多年 FreeBSD/EC2 业余维护依赖 Patreon 资助才能持续（BSD Now EP396），基金会资助、个人业余劳动与社区捐赠三种资源形态在此叠加，其间利益结构须经 Foundation 年报与捐赠记录核验〔订正注：原挂“总纲第 9 条——商业与社区协作”系伪标签，权威第 9 条为“经验优先”，按内容改挂第 13 条并存疑〕

**辨析**：**AMI** 维护责任在 **Percival** 个人与 **Foundation** 之间的转移节点

**文献**：Percival 2011 `freebsd-cloud` 邮件；FreeBSD Foundation 2014 Annual Report ［A］

## 278.21.2 AWS FreeBSD AMI 的官方支持范围

**要点**：**AWS** **Marketplace** 自 2015 年正式收录 **FreeBSD** 官方 **AMI**，但仅支持 **FreeBSD** `10.x` 及后续版本，**arm64** 支持在 2020 年后才完善。

**史料**：**AWS** **Marketplace** **FreeBSD** 页面、**FreeBSD** **AWS** Wiki、**Percival** 项目年度报告 ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律〔存疑挂靠〕：**x86** 到 **arm64** 的扩展是镜像供给方收录节奏与 FreeBSD 平台成熟度两侧条件交汇的结果，“arm64 支持在 2020 年后才完善”的时点断言须以 AWS 官方公告与 FreeBSD release 公告双向核验〔订正注：原挂“总纲第 22 条——架构演化”系伪标签，权威第 22 条为“知识注定过时”，按内容改挂第 4 条并存疑〕

**辨析**：**AWS** 对 **FreeBSD** 的支持级别——是否算 “Tier 1” 平台

**文献**：AWS Marketplace FreeBSD 页面；FreeBSD Wiki AWS ［B］

## 278.21.3 与 Azure 及 GCP 部署 FreeBSD 的比较

**要点**：**AWS** 通过社区驱动的 **AMI** 提供 **FreeBSD**，**Azure** 通过 **Microsoft**-**Foundation** 合作提供官方镜像，**GCP** 则需用户自制镜像，三家模式不同。

  | 云厂商 | FreeBSD 镜像来源 | 维护主体 |
  |---|---|---|
  | **AWS** | 社区驱动 **AMI** | **Percival** 个人+**Foundation** |
  | **Azure** | 官方合作镜像 | **Microsoft**+**Foundation** |
  | **GCP** | 用户自制镜像 | 用户自管 |
**史料**：三大云厂商镜像目录、**FreeBSD** Cloud 平台矩阵［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律〔存疑挂靠〕：云厂商对 **BSD** 的不同支持模式（社区驱动 AMI／官方合作镜像／用户自制）实为三种不同的商业利益分配结构——BSD 许可证允许厂商不回馈源代码而提供商业镜像，模式优劣须以镜像更新频率与上游回馈 commit 数据比较，不得仅凭模式描述判断〔订正注：原挂“总纲第 7 条——商业形态分化”系伪标签，权威第 7 条为“理论必须自反”，按内容改挂第 4 条并存疑〕

**辨析**：哪种模式更利于 **FreeBSD** 在云场景的长期采用
