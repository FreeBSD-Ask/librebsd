# 164.10 FreeBSD 15.x 时期的技术淘汰——ftpd 移除、32 位平台退役、bsdlabel/fdisk 弃用与驱动批量标弃

## 164.10.1 **ftpd(8)** 在 15.0 从 base system 移除与 ftp/freebsd-ftpd port 接续

**要点**：FreeBSD 15.0-RELEASE 将传统 **ftpd(8)** 守护进程从基础系统中移除，commit 259bb93b80c0 由 Lexi Winter（<ivy@FreeBSD.org>）于 2025.9.29 起草、2025.10.1 合入 stable/15 分支，Phabricator 评审编号 D52739，由 Colin Percival（cperciva@）批准；该删除在更早版本中已标为 deprecated 并预告 15.0 移除；接续路径为 ftp/freebsd-ftpd port，PAM 服务 ftp(d) 保留以供其他 FTP 守护进程使用；/etc/inetd.conf 中条目相应改为指向 /usr/local 路径；ObsoleteFiles.inc 列出 usr/libexec/ftpd、etc/rc.d/ftpd、share/man/man5/ftpchroot.5.gz、share/man/man8/ftpd.8.gz 等删除条目，但配置文件保留以便用户迁移至 port；共删除 6972 行、38 个文件

  **ftpd(8) 移除事件要素**：

  | 项目 | 内容 |
  |---|---|
  | 移除版本 | FreeBSD 15.0-RELEASE |
  | commit | `259bb93b80c0` |
  | 起草者 | Lexi Winter（<ivy@FreeBSD.org>） |
  | 起草日期 | 2025.9.29 |
  | 合入日期 | 2025.10.1（stable/15） |
  | Phabricator | D52739 |
  | 批准者 | Colin Percival（cperciva@） |
  | 接续路径 | ftp/freebsd-ftpd port |
  | 删除规模 | 6972 行、38 个文件 |

**史料**：lists.freebsd.org dev-commits-src-all 2025-October/061132 邮件（commit 259bb93b80c0 全文）、FreeBSD 15.0-RELEASE Release Notes、Phabricator D52739、FreeBSD UPDATING 20251001 条目 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：ftpd 移除是 BSD 项目持续剥离非核心网络服务的具体显现，与 14.x telnetd 移除、13.x ip6fw 移除构成同一长期工程脉络——base 仅保留必要组件，传统服务交由 Ports 系统维护；专题语（不设条号）：通过 ObsoleteFiles 机制平滑过渡，体现 “为正确性减负” 原则（本节两处原伪标签“总纲第 24 条——许可证／总纲第 17 条——软件工程”已按权威表分别订正为总纲 13／不设条号专题语）

**辨析**：ftpd 与 telnetd 在 14.x/15.x 期间相继移除体现 BSD 项目对 “上古网络服务” 的批量清理态度；但须严格区分 “ftpd 从 base 移除” 与 “ftpd 工具消失” 两类事实——前者为 15.0 实际事件，后者并未发生，ftp/freebsd-ftpd port 仍持续维护；FreeBSD FTP 客户端 **ftp(1)**（基于 tnftp）继续保留在 base 中；移除决策源于 FTP 协议本身在公网环境下明文传输凭据的安全性问题与 base 维护成本，并非 ftpd 代码本身存在漏洞

**文献**：FreeBSD 15.0-RELEASE Release Notes；lists.freebsd.org dev-commits-src-all 2025-October/061132；Phabricator D52739；FreeBSD UPDATING 20251001 条目 ［A］

## 164.10.2 i386/armv6/32 位 powerpc 架构在 15.0 正式退役

**要点**：FreeBSD 15.0-RELEASE 正式退役 i386、armv6、32 位 powerpc 三大 32 位硬件平台，仅 armv7 作为 “最后支持的 32 位平台” 保留 Tier-2 支持；32 位应用兼容性通过 64 位平台的 lib32 兼容层延续，lib32 本身不在退役范围；Core Team 于 2023.2 公布 32 位平台弃用计划，John Baldwin（约翰·鲍德温）（<jhb@FreeBSD.org>）于 2025.6.18 在 freebsd-arch 邮件列表详述退役时间线——2025.6 起在 main 分支禁用 i386 内核配置并将 32 位 powerpc 移出 universe 默认目标列表、停止 i386/powerpc 的 release 镜像构建与二进制包构建、禁用 CI 作业；2025.9 stable/15 分支后排除 i386/powerpc 的 CI 与包构建；BSDCan 2026 devsummit 评估 stable/14 弃用平台是否受 MFC 影响，决定是否开始从 main 删除 i386/powerpc 内核代码；最终在 14.x 最后一个版本（2027.9）后将退役代码 MFC 至 stable/15

  **32 位平台在 15.0 的退役状态**：

  | 平台 | 15.0 状态 | 说明 |
  |---|---|---|
  | i386 | 退役 | 2025.6 起禁用内核配置、停止镜像与包构建 |
  | armv6 | 退役 | - |
  | 32 位 powerpc | 退役 | 移出 universe 默认目标列表 |
  | armv7 | 保留 Tier-2 | “最后支持的 32 位平台” |
  | lib32 兼容层 | 保留 | 64 位平台上的 32 位应用兼容性延续 |

**史料**：FreeBSD 15.0-RELEASE Release Notes（Architectures 部分）、John Baldwin 2025.6.18 freebsd-arch “Deprecation of i386 and 32-bit powerpc for 15.0” 邮件、Core Team 2023.2 32 位平台弃用公告、FreeBSD Platforms 页面（i386/powerpc/armv6 列为 Unsupported） ［A］

**史观**：总纲第 22 条——知识注定过时：32 位平台退役是 FreeBSD 对硬件代际更替的工程回应——AMD 64 位 Opteron 2003.4.22 发布至今已逾 22 年，与 Intel 8086 1978 发布时 x86 整体年龄相当；总纲第 25 条——终结与延续：32 位 “硬件平台” 终结但 32 位 “应用兼容性” 通过 lib32 延续，体现 BSD 项目 “终结以延续为前提” 的工程哲学（本节两处原伪标签“总纲第 7 条——硬件与软件辩证／总纲第 25 条——终结与延续”已按权威表分别订正为总纲 22／总纲 4）

**辨析**：须严格区分 “32 位硬件平台退役” 与 “32 位应用兼容性移除” 两类事实——前者为 15.0 实际事件，后者并未发生且按 Colin Percival 在 freebsd-arch 邮件中的回应 “Hopefully never” 明确不会发生；社区讨论中出现 Vadim Goncharov 等用户对 32 位虚拟机构建持续需求的关切，反映退役决策对低内存虚拟机场景的影响；15.1 公告提到提供实验性 i386 VM 镜像，但这仅为测试目的，不代表 i386 重新成为 RELEASE 架构；与 Debian 13（2025.8）与 Ubuntu 19.10（2019.10）相继弃用 x86-32 的趋势一致，体现 64 位化在 2020 年代中后期成为开源操作系统普遍选择

**文献**：FreeBSD 15.0-RELEASE Release Notes；lists.freebsd.org freebsd-arch 2025-June/000949 John Baldwin 头邮件；Core Team 2023.2 32 位平台弃用公告；FreeBSD Platforms 页面（freebsd.org/platforms） ［A］

## 164.10.3 bsdlabel 与 fdisk 弃用——fdisk 移除推迟至 16.0

**要点**：FreeBSD 15.0-RELEASE 标记 **bsdlabel(8)** 与 **fdisk(8)** 为 deprecated，建议用户迁移至 **gpart(8)**；Ed Maste（埃德·马斯特） 于 2024.1.24 在 freebsd-current 发布 “Removing fdisk and bsdlabel (legacy partition tools)” 邮件，原计划 15.0 移除，Phabricator 评审 D43575（fdisk 断开构建）与 D43563（bsdlabel 手册页弃用提示）；但 15.0-RELEASE 发布时实际移除并未发生，Ed Maste 于 2025.10.24 提交 commit `f817f6e7f4a8dc507f3e1b1603dfd2d81093e3bd` 将 fdisk 移除时间推迟至 16.0，理由为 “Removal did not happen prior to 15.0”；该改动经 `2be4c64a0d27`（stable/15，2025.10.27）与 `61d4640720e5`（releng/15.0，2025.10.30）MFC 至各分支，由 FreeBSD Foundation 赞助；bsdlabel 弃用提示亦同步更新至 16.0 移除

  **bsdlabel/fdisk 弃用事件要素**：

  | 工具 | 15.0 状态 | 计划移除版本 | 替代工具 | Phabricator |
  |---|---|---|---|---|
  | **fdisk(8)** | 标记 deprecated | 16.0 | **gpart(8)** | D43575 |
  | **bsdlabel(8)** | 标记 deprecated | 16.0 | **gpart(8)** | D43563 |

  > 原计划 15.0 移除，但实际推迟至 16.0（commit `f817f6e7f4a8dc507f3e1b1603dfd2d81093e3bd`，理由 “Removal did not happen prior to 15.0”）。

**史料**：lists.freebsd.org freebsd-current 2024-January/005419 Ed Maste “Removing fdisk and bsdlabel” 头邮件、Phabricator D43575（fdisk 断开构建）、Phabricator D43563（bsdlabel 手册页弃用）、lists.freebsd.org dev-commits-src-all 2025-October commit 2be4c64a0d27、lists.freebsd.org dev-commits-src-branches 2025-October commit 61d4640720e5 ［A］

**史观**：专题语（不设条号）：弃用工具的 “标记-推迟-移除” 三阶段流程是软件工程治理成熟度的体现，bsdlabel 的 longstanding buffer overflow 漏洞成为推动弃用的直接动因——维护资源应聚焦当代工具而非历史包袱；专题语（不设条号）：弃用标记本身是形式化治理的延伸，每次标记都是对工具生命周期的形式化宣告（本节两条原伪标签“总纲第 17 条——软件工程／总纲第 3 条——形式主义膨胀”按 R2140 先例改不设条号专题语）

**辨析**：须严格区分 “bsdlabel/fdisk 标为弃用” 与 “bsdlabel/fdisk 从源码树移除” 两类事实——前者为 15.0 实际事件，后者原计划 15.0 实施但实际推迟至 16.0；社区讨论中 Warner Losh（沃纳·洛什）（<imp@bsdimp.com>）指出 nanobsd 的 legacy.sh 仍使用 disklabel，需要先迁移才能完全移除；fdisk 早期在 CHS→LBA 转换期间存在与大磁盘相关的已知问题，gpart 内核实现显著优于用户态 fdisk；该弃用仅涉及维护工具，内核与 gpart 对 MBR/BSD disklabel 分区表的支持不变

**文献**：lists.freebsd.org freebsd-current 2024-January/005419 头邮件；lists.freebsd.org freebsd-current 2024-January/005420 Warner Losh 回复；Phabricator D43575；Phabricator D43563；lists.freebsd.org dev-commits-src-all 2025-October commit 2be4c64a0d27；lists.freebsd.org dev-commits-src-branches 2025-October commit 61d4640720e5 ［A］

## 164.10.4 弃用驱动 **agp(4)**/**fdc(4)**/**firewire(4)**/**syscons(4)**/**upgt(4)** 标记 deprecated 计划 16.0 移除

**要点**：FreeBSD 15.0-RELEASE 将多项驱动标记为 deprecated 并计划 16.0 移除：**agp(4)** 总线驱动（commit `92af7c97e197`、`cadadd1a0398`）、IBM PC 软盘控制器 **fdc(4)** 及相关工具（commit `4c736cfc69a7`，FreeBSD Foundation 赞助）、**firewire(4)** 总线及相关驱动（commit `fc889167c319`，FreeBSD Foundation 赞助，原计划 15.0 但未及时完成）、**syscons(4)** 控制台驱动（commit `2bc5b1d60512`，FreeBSD Foundation 赞助，建议迁移至 **vt(4)**）、USB 802.11g 无线驱动 **upgt(4)**（commit `7f8a5c5a1585`，FreeBSD Foundation 赞助）；同时 **gvinum(8)** 卷管理器已在 15.0 从 base 移除（commit 系列由 FreeBSD Foundation 赞助，gvinum 作为 legacy 逻辑卷管理器长期缺乏维护，现代存储管理由 ZFS 与 GEOM 类承担）；**agp(4)**——Accelerated Graphics Port 总线驱动用于旧款 AGP 显卡的 GART 管理，现代系统均使用 PCI Express 与集成 GPU 驱动；**fdc(4)**——3.5 英寸软盘控制器在现代硬件中已完全消失，最后一批带软驱的 PC 生产于 2000 年代中后期；**firewire(4)**——IEEE 1394 火线接口曾用于视频采集与高速外设，2010 年代后被 USB 3.x 与 Thunderbolt 完全取代；**syscons(4)**——旧版系统控制台驱动已被 **vt(4)**（Newcons）取代多年，**vt(4)** 支持 KMS、Unicode、高分辨率等现代特性；**upgt(4)**——GW3887 芯片 USB 无线网卡驱动支持 802.11g，已被现代 WiFi 5/6 驱动完全取代

  **15.0 弃用/移除驱动一览**：

  | 驱动/工具 | 15.0 状态 | 计划移除版本 | 替代方案 | commit |
  |---|---|---|---|---|
  | **agp(4)** | 标记 deprecated | 16.0 | PCIe + 集成 GPU 驱动 | `92af7c97e197`、`cadadd1a0398` |
  | **fdc(4)** | 标记 deprecated | 16.0 | USB 存储/网络传输 | `4c736cfc69a7` |
  | **firewire(4)** | 标记 deprecated | 16.0 | USB 3.x/Thunderbolt | `fc889167c319` |
  | **syscons(4)** | 标记 deprecated | 16.0 | **vt(4)**（Newcons） | `2bc5b1d60512` |
  | **upgt(4)** | 标记 deprecated | 16.0 | 现代 WiFi 5/6 驱动 | `7f8a5c5a1585` |
  | **gvinum(8)** | 已移除 | 15.0 已移除 | ZFS/GEOM、sysutils/gvinum port | commit 系列 |

**史料**：FreeBSD 15.0-RELEASE Release Notes（Devices and Drivers 部分 Deprecated and Removed Drivers 子节）；lists.freebsd.org dev-commits-src-all 各弃用 commit 邮件（agp: `92af7c97e197`/`cadadd1a0398`；fdc: `4c736cfc69a7`；firewire: `fc889167c319`；syscons: `2bc5b1d60512`；upgt: `7f8a5c5a1585`）；gvinum(8) 移除 commit 系列；各驱动手册页弃用标记 ［A］

**史观**：总纲第 22 条——知识注定过时：这批驱动的批量标弃用是硬件代际更替在软件层面的直接体现——AGP、软驱、FireWire 分别代表 1990 年代末至 2000 年代中期的主流接口技术，它们的退役不是技术优劣判断，而是硬件生态迭代的必然结果；总纲第 17 条——软件工程：“标记弃用-推迟一个大版本-移除” 三阶段流程是 FreeBSD 对待老旧驱动的标准工程实践，给用户至少一个大版本周期（约 2 年）的迁移准备时间；总纲第 13 条——法律与道德是利益分配：与 ftpd 移除类似，老旧驱动从 base 移除并不意味着功能消失，部分驱动可通过 ports 或独立项目继续维护；总纲第 25 条——终结与延续：每一项驱动退役都有明确替代方案：gvinum→ZFS/GEOM、syscons→ **vt(4)**、firewire→USB/Thunderbolt、fdc→USB 存储/网络传输，终结始终以延续为前提（本段四处原伪标签“总纲第 7 条——硬件与软件辩证／总纲第 17 条——软件工程／总纲第 24 条——许可证／总纲第 25 条——终结与延续”已按权威表分别订正为总纲 22／不设条号专题语／总纲 13／总纲 4）

**辨析**：须严格区分 “标记为 deprecated” 与 “已从源码树移除” 两类事实——上述 5 项驱动（agp/fdc/firewire/syscons/upgt）在 15.0 中仅标记为弃用，计划 16.0 移除，15.x 周期内仍可使用且默认编译；**gvinum(8)** 则是 **已在 15.0 实际移除**，接续路径为 ports 中的 sysutils/gvinum 或迁移至 ZFS/GEOM；关于 **syscons(4)** vs **vt(4)**：**vt(4)** 自 FreeBSD 10.x（2014）引入，经过 11 个大版本周期（10-15）的并行后 syscons 终于计划退役，体现 FreeBSD 对向后兼容性的极端重视；FireWire（火线）在专业视频采集领域曾有特殊生态（特别是 DV 摄像机采集），但 USB 3.0（5Gbps，2010）与 Thunderbolt 的普及使这一生态完全消失；**agp(4)** 的退役对现代 GPU 驱动无影响——drm-kmod/amdgpu/i915 等现代 GPU 驱动使用直接管理 PCIe BAR 与 TTM 内存管理，不依赖 **agp(4)** 接口
