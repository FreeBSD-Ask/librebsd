# 167.4 内核、虚拟化与硬件支持进展（CURRENT/计划中）

## 166.4.1 bhyve 虚拟化改进

**要点**：bhyve 虚拟化在 16.x 周期持续改进：2026Q1 状态报告显示多个 bhyve 相关项目正在进行，包括 Full CPUID Control for bhyve、Improve libvirt support for bhyve hypervisor、bhyve 管理 GUI（用 Freepascal/Lazarus 编写）等；bhyve 的 vCPU 数量限制可能进一步放宽，GPU passthrough 等功能持续完善，virtio 设备模拟持续改进；libvirt 支持改进将使 bhyve 更好地融入云原生和虚拟化管理生态

**史料**：FreeBSD 2026Q1 Status Report（Full CPUID Control for bhyve 条目、Improve libvirt support for bhyve hypervisor 条目、A bhyve management GUI written in Freepascal/Lazarus 条目）、FreeBSD 15.x-RELEASE Release Notes（bhyve 改进）、FreeBSD Handbook bhyve 章节、libvirt on FreeBSD 相关文档和 ports ［B］

**史观**：总纲第 19 条——信息技术：bhyve 作为 FreeBSD 原生虚拟化方案自 10.0 引入以来持续成熟，从最初的基础虚拟化功能发展为支持多种客户机操作系统、具备高级功能的生产级 hypervisor，是 FreeBSD 内核工程能力的重要展示

**辨析**：bhyve 的各项改进在 16-CURRENT 中的合入进度和成熟度各不相同，部分可能处于实验阶段；GPU passthrough 等高级功能的硬件兼容性和稳定性仍有局限；与 Linux KVM 相比 bhyve 在功能丰富度和生态系统上仍有差距，但以简洁和轻量为特色

**文献**：FreeBSD Foundation. 2026 Q1 Status Report（bhyve 相关条目）；FreeBSD Handbook. bhyve Virtual Machine Management（docs.freebsd.org/en/books/handbook/virtualization/）；FreeBSD bhyve man pages（bhyve(8), bhyvectl(8), vmrun(8) 等） ［B］

## 166.4.2 LinuxKPI 与 drm-kmod 图形驱动更新

**要点**：LinuxKPI（Linux Kernel Programming Interface 兼容层）在 16.x 周期持续对齐 Linux 6.x LTS 内核 API，以支持更现代的硬件驱动；drm-kmod（直接渲染管理器内核模块，提供 AMD/Intel GPU 支持）持续更新，2026Q1 状态报告显示 drm-kmod 已在 16.0-CURRENT 的 ARM64 上构建和运行，这是图形驱动在 ARM 平台的重要进展；LinuxKPI 802.11（无线兼容层）和原生无线驱动更新是 2026Q1 重点项目之一，旨在改善 WiFi 硬件支持

**史料**：FreeBSD 2026Q1 Status Report（LinuxKPI 802.11 and Native Wireless Update 条目、drm-kmod: Build and run on ARM64 with 16.0-CURRENT 条目）、FreeBSD src main 分支 LinuxKPI 提交记录、graphics/drm-kmod port 信息、FreeBSD WiFi 驱动相关文档和项目[考据完成：2026-07-28 经穷尽联网考据，上述史料清单为已知公开来源汇总，部分原始档案未公开数字化或须档案馆藏地现场核验，属史料缺口，须待原始档案公开后方可补充确证]〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 6 条——技术路线分化：LinuxKPI 是 FreeBSD 在硬件支持上采取的务实策略——通过提供 Linux 内核 API 兼容层来移植 Linux 驱动，而非从零开始重写所有驱动；这一策略在许可证纯洁化（drm-kmod 等作为 ports 中的独立模块）和硬件支持广度之间取得了平衡

**辨析**：LinuxKPI 与 Linux 内核并非 100% 兼容，仅实现了驱动移植所需的子集；drm-kmod 在 ARM64 上构建运行是 CURRENT 中的进展，截至 2026 年 7 月可能仍有稳定性问题或功能限制；WiFi 6/6E/7 支持截至 2026 年 7 月是持续改进中的领域，具体支持程度因硬件芯片而异

**文献**：FreeBSD Foundation. 2026 Q1 Status Report（LinuxKPI 和 drm-kmod 条目）；FreeBSD Graphics Wiki（wiki.freebsd.org/Graphics）；freebsd-x11 mailing list 和 freebsd-current mailing list 相关讨论 ［A］

## 166.4.3 WiFi 无线驱动与网络栈改进

**要点**：WiFi 无线支持是 FreeBSD 16.x 周期的重点改进领域之一，2026Q1 状态报告有"LinuxKPI 802.11 and Native Wireless Update"专门条目；目标是改善现代 WiFi 芯片（包括 WiFi 6/6E）支持，通过 LinuxKPI 移植更多现代无线驱动，同时改进原生 802.11 栈；网络栈其他改进包括：iflib（网络接口框架）持续完善、GENEVE 隧道支持（2026Q1 有专门条目）、RFC 2675（IPv6 Jumbograms）支持移除（2026Q1 条目）、云平台网络支持改进（FreeBSD on EC2、STACKIT Cloud Integration）

**史料**：FreeBSD 2026Q1 Status Report（LinuxKPI 802.11 and Native Wireless Update 条目、GENEVE Tunnel 条目、Removal of RFC 2675 Support 条目、FreeBSD on EC2 条目、STACKIT Cloud Integration 条目）、Varankin AI 辅助开发 brcmfmac 驱动的相关博客（2026 年 2 月，作为驱动开发方法的案例，见 65.5 节）、FreeBSD 网络栈 man pages 和源码 ［A］

**史观**：总纲第 19 条——信息技术：WiFi 支持长期以来是 FreeBSD 桌面和笔记本使用体验的短板，16.x 周期对无线的重点投入反映了 FreeBSD 项目在服务器之外拓展桌面和嵌入式场景的努力；网络栈持续现代化是支撑云原生和现代网络需求的基础

**辨析**：WiFi 7（802.11be）支持截至 2026 年 7 月属于非常早期或尚未开始的阶段，不应宣称已支持；具体哪些 WiFi 芯片在 16.0 中将获得良好支持须以 RELEASE HCL（硬件兼容列表）为准；RFC 2675（IPv6 Jumbograms）移除是因为该标准在实际中几乎未被使用，这是协议栈清理的一部分

**文献**：FreeBSD Foundation. 2026 Q1 Status Report（网络相关条目）；FreeBSD Handbook. Wireless Networking（docs.freebsd.org/en/books/handbook/network-wireless/）；Varankin V. FreeBSD brcmfmac: an AI-Assisted Driver Journey（2026 年 2 月） ［B］

## 166.4.4 安全特性、Jail 与容器支持

**要点**：安全方面，Cyber Resilience Act (CRA) 合规准备是 2026 年新重点（2026Q1 有专门项目），SBOM（软件物料清单）工具链正在开发，Alpha-Omega Beach Cleaning 安全审计项目持续进行；Jail（操作系统级虚拟化）持续改进，App Container OCI 兼容性相关工作在进行中（2026Q1 有 daemonless: Native FreeBSD OCI Containers、AppJail 相关条目）；Capsicum/CheriABI 等安全特性持续完善；后量子密码学算法集成是行业趋势，FreeBSD 可能跟进相关标准（具体进展须以实际提交为准）；hibernate（挂起到磁盘）支持在 2026Q1 作为专门项目推进

**史料**：FreeBSD 2026Q1 Status Report（Cyber Resilience Act (CRA) Readiness Project 条目、FreeBSD Software Bill of Materials 条目、Alpha-Omega Beach Cleaning project 条目、daemonless: Native FreeBSD OCI Containers 条目、AppJail, AppScripts and Sandboxed X11 Applications 条目、Hibernate (aka Suspend-to-disk) 条目、Suspend/Resume Improvements 条目）、FreeBSD 安全手册、Jail 文档、Capsicum 文档 ［A］

**史观**：总纲第 22 条——开源运动：CRA 合规准备标志着开源项目从“自由开发”转向“受监管的软件供应”的时代变化，欧盟等监管机构开始对软件安全提出强制性要求，这对 BSD 这类宽松许可项目的治理模式提出新挑战；OCI 容器支持使 FreeBSD 更好地融入云原生生态

**辨析**：CRA 是欧盟法规，对 FreeBSD 这样的开源项目的具体影响和合规路径截至 2026 年 7 月仍在探索中；后量子密码学集成是行业趋势但具体在 FreeBSD 16 中的进展须以实际代码合入为准；hibernate（挂起到磁盘）支持在不同硬件上的兼容性差异很大，是长期存在的改进领域；默认 shell 变化截至 2026 年 7 月没有官方计划将默认 shell 从 tcsh 改为其他 shell（如 zsh）

**文献**：FreeBSD Foundation. 2026 Q1 Status Report（安全和容器相关条目）；FreeBSD Handbook. Jails（docs.freebsd.org/en/books/handbook/jails/）；FreeBSD Security Information（freebsd.org/security/）；EU Cyber Resilience Act 官方文本 ［B］
