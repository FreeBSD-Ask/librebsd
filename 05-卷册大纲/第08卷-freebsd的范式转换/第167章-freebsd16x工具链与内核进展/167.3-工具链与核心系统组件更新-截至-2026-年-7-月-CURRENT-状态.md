## 167.3.2 Rust 进 base 系统讨论进展

**要点**：FreeBSD 社区自 2024 年初开始讨论 Rust 编程语言进入 base system 的可能性，Alan Somers 等开发者发起相关讨论；截至 2026 年 7 月，Rust 主要通过 ports 提供（ports/lang/rust，2026Q1 版本为 1.94.0），是否以及何时进入 base system 仍在社区讨论和评估中，尚未有正式的合入时间表；讨论中的主要顾虑包括：构建时间显著增加（需编译 rustc 及相关组件）、Rust 快速发布周期与 FreeBSD base 系统稳定性要求的协调、Rust 对 LLVM 的依赖与现有 LLVM 工具链的集成等；Linux 内核已开始接受 Rust 编写的内核模块，这一趋势也影响着 FreeBSD 社区的讨论

**史料**：freebsd-hackers 邮件列表 2024 年 1 月 Rust in base 讨论线程（lists.freebsd.org/archives/freebsd-hackers/2024-January/002823.html）、Ports Collection 2026Q1 状态报告（Rust 1.94.0）、Alan Somers 等开发者的相关提案和讨论、Linux Kernel Rust 支持进展（作为外部参照） ［A］

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧〔存疑：原挂总纲第 6 条系伪标签，依核查报告改挂第 21 条，语境适配未经总纲原文逐字复核〕：Rust 是否进入 base 系统的讨论反映了 FreeBSD 工程哲学中“稳定保守”与“拥抱新技术”之间的张力；Linux 选择相对激进地引入 Rust，FreeBSD 则采取更为谨慎的评估路径，这一分歧与两个项目的治理模式和用户基础差异相关

**辨析**：截至 2026 年 7 月，Rust 尚未进入 base system，所有相关讨论均为社区讨论性质，不应表述为“FreeBSD 16 将包含 Rust”；Rust for kernel modules 的进展（如果有）同样属于实验或讨论阶段；将 Rust 纳入 base 会显著增加构建时间和系统复杂性，这一决策需要核心团队达成共识，短期内（16.0 周期）可能性较低

**文献**：freebsd-hackers mailing list. Rust in base system discussion（2024 年 1 月，lists.freebsd.org/archives/freebsd-hackers/2024-January/002823.html）；Ports Collection. 2026 Q1 Status Report（Rust 1.94.0）；The Register. FreeBSD developers consider Rust for base system（2024 年相关报道） ［A］

## 167.3.3 OpenSSL、OpenZFS 与存储栈更新

**要点**：FreeBSD 16.0-CURRENT 将包含更新版本的 OpenSSL 和 OpenZFS；FreeBSD 15.0 已包含 OpenZFS 2.3.x 系列，16.x 预计跟进 OpenZFS 2.4 或更新版本；ZFS block cloning（块克隆）功能在 15.x 周期已引入并持续稳定化；OpenSSL 版本持续跟进上游 LTS 版本，同时可能包含 FreeBSD 特定的安全加固和性能优化；pkgbase（将 base 系统拆分为 pkg 包）项目持续推进，2026Q1 状态报告有“More robust pkgbase conversion”专门条目

## 167.3.4 64-bit time_t 完成与架构支持变化

**要点**：FreeBSD 在 13.x-15.x 周期已完成 64-bit time_t 在所有主要架构上的转换（Y2038 问题修复），16.x 周期将在此基础上继续完善；32 位架构支持持续调整——部分老旧 32 位架构可能进一步降级或废弃，以集中资源支持现代架构；RISC-V（riscv64）架构支持持续改进，drm-kmod 已在 16.0-CURRENT 的 ARM64 上构建和运行（2026Q1 状态报告条目），RISC-V 升 Tier 1 的计划截至 2026 年 7 月尚未有明确时间表；amd64 FRED（Flexible Return and Event Delivery）支持正在开发中（2026Q1 有专门条目）；Allwinner H616 等 ARM SoC 支持持续完善
