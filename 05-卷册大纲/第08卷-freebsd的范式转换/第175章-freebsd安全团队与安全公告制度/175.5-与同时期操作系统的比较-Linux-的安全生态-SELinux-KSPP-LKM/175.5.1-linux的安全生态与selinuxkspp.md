# 175.5.1 Linux 的安全生态与 SELinux/KSPP

**要点**：梳理 Linux 安全生态的发展脉络——2000 年 12 月美国国家安全局（NSA）发布 Security-Enhanced Linux（SELinux），基于犹他大学与 Secure Computing Corporation 联合设计的 Flask 架构，实现强制访问控制（MAC）；2001 年 3 月 NSA 在 Linux Kernel Summit 展示 SELinux，促使 林纳斯·托瓦兹（Linus Torvalds）发起 Linux Security Modules（LSM）项目以提供通用安全框架；2003 年 12 月 SELinux 随 Linux 2.6 合入内核主线；2004 年 5 月 Fedora Core 2 成为首个官方支持 SELinux 的发行版，同年 11 月 Fedora Core 3 引入 targeted 策略并默认启用 SELinux；2010 年代后 Linux 安全版图扩展至 Kernel Self Protection Project（KSPP，内核自我保护项目）、seccomp 沙箱、AppArmor、Smack、TOMOYO 等多个并行路线

**史料**：NSA 2000 年 12 月 SELinux 开源发布公告、2001 年 Linux Kernel Summit 会议记录、Flask 架构原始论文（Spencer et al.）、James Morris 2008 年 OLS 论文《Have You Driven an SELinux Lately?》、Linux Kernel Self Protection Project 创立记录、LSM 内核文档历史版本 ［A］

**史观**：总纲第 14 条——哲学思潮：Linux 的安全生态是 “ Cathedral 与 Bazaar” 在安全领域的投射——SELinux 代表自上而下的、体系化的、NSA 主导的安全设计（大教堂模式），而 KSPP、grsecurity、PaX 等则代表自下而上的、分布式的、社区驱动的安全探索（集市模式），多种路径并行竞争演化

**辨析**：SELinux 的历史常被简化为 “NSA 给 Linux 加安全”，但实际 Flask 架构的思想源头可追溯至 1980 年代的高安全操作系统研究（Multics、Secure Xenix、DTOS）；SELinux 合入主线的过程充满争议，林纳斯·托瓦兹 最初持怀疑态度，LSM 框架的建立是多方妥协的结果；SELinux 虽技术上强大，但因配置复杂度高，长期以来在桌面和服务器场景的实际使用率有限
