# 184.2.3 分阶段迁移策略的工程设计

**要点**：Git 工作组设计了精密的三阶段渐进迁移策略，以最小化对开发和发布流程的干扰：**第一阶段：doc 仓库（2020 年 12 月初）**——文档仓库规模最小、提交频率较低，作为试点验证迁移流程和工具链；**第二阶段：src 仓库（2020 年 12 月中下旬）**——核心代码仓库，风险最高，选择在 13.0 发布前的过渡窗口期迁移〔原稿“代码冻结窗口期”存疑：src 迁移（2020-12）时 13.0 尚未进入代码冻结期（冻结始于 2021 年初），按当时公告核正〕；**第三阶段：ports 仓库（2021 年 3-4 月）**——规模最大（超过 4 万个 port）、提交最频繁，留待最后且在 src 迁移经验基础上进行；每个仓库迁移都遵循相似流程：预先公告 → 提交冻结 → 最终转换 → 只读验证 → 开启写权限 → 镜像同步 → 事后复盘；迁移期间为 committer 提供了多轮培训、文档更新和实时支持

  **SVN→Git 三阶段迁移策略**：

  | 阶段 | 仓库 | 时间 | 特点 |
  |---|---|---|---|
  | 第一阶段 | doc | 2020.12 初 | 规模最小、风险最低，试点验证 |
  | 第二阶段 | src | 2020.12 中下旬 | 核心代码，13.0 代码冻结窗口期 |
  | 第三阶段 | ports | 2021.3-4 | 规模最大（4 万 + port），最后迁移 |

**史料**：Git Transition Wiki 三仓库详细时间表（精确到小时）；freebsd-announce 迁移公告邮件；Ed Maste EuroBSDCon 2020“FreeBSD Git Migration”演讲；Git 工作组迁移后复盘报告 ［A］

**史观**：总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：三阶段渐进迁移是大型基础设施变更的典范实践——从低风险到高风险、从试点到全面推广、每一步都有验证和回退预案，这体现了 FreeBSD 发布工程团队的专业素养

**辨析**：“渐进式迁移”并不意味着“拖延”——从 2019 年工作组成立到 2021 年 4 月全面完成历时约两年，这期间进行了大量工具开发、测试转换、committer 培训工作；ports 仓库因规模巨大（30 万 + 提交历史）确实遇到了未预见的技术挑战，导致比原计划略有推迟
