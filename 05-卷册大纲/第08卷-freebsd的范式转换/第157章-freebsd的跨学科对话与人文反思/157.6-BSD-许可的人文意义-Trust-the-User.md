# 157.6 BSD 许可的人文意义：Trust the User

## 157.6.1 BSD 许可证的哲学：信任与自由

**要点**：BSD 许可证的人文意义远超法律文本本身：(1) **BSD 许可证的历史演变**——最初的 4-clause BSD license（广告条款）源自 UC Berkeley 1980 年代，要求所有广告材料提及 “本产品包含由加州大学伯克利分校及其贡献者开发的软件”；1999 年 7 月 22 日，William Hoskins（UC Berkeley 技术许可办公室主任）正式宣布删除广告条款（第 3 条），形成 3-clause BSD license；2-clause BSD license（又称 FreeBSD license，简化版）进一步删除了 “不允许用贡献者名字背书” 条款；FreeBSD 自 2000 年代起采用 2-clause BSD license 作为新代码的默认许可证；(2) **“Trust the user” 哲学**——BSD 许可证的核心不是 copyleft 的 “强制保持开放”，而是 “信任用户会做正确的事”——你可以自由使用、修改、甚至闭源分发 BSD 代码，只要保留版权声明和免责声明；这种模式基于对人的信任，而非基于法律强制；(3) **与 GPL 的人文对比**——GPL 是 “自由的捍卫者”：通过 copyleft 确保代码永远保持自由；BSD 是 “自由的给予者”：我给你自由，你可以用它做任何事，包括闭源；这不是谁对谁错，而是两种不同的自由观——GPL 更接近积极自由（有权利做什么），BSD 更接近消极自由（不被干涉做什么）；(4) **BSD 许可的实际影响**——BSD 代码被融入了几乎所有现代操作系统：Linux（部分驱动和工具）、macOS/iOS（大量代码）、Windows（TCP/IP 栈历史上受 BSD 影响，现代 Windows 也包含 BSD 代码）、PlayStation、Juniper Junos、Netflix Open Connect 等等

**史料**：UC Berkeley Office of Technology Licensing. (1999, July 22). *BSD License Advertising Clause Delete Announcement* (official letter from William Hoskins); FreeBSD Project. *FreeBSD License Text*. freebsd.org/copyright/freebsd-license.html; Open Source Initiative. *The 3-Clause BSD License* (opensource.org/licenses/BSD-3-Clause); Free Software Foundation. *Various Licenses and Comments about Them*. gnu.org/licenses/license-list.en.html ［A］

**史观**：总纲第 14 条——哲学思潮：BSD 许可的 “Trust the user” 是自由意志主义哲学在软件领域的体现——相信技术使用者的判断权，不预设他们会滥用自由；这与 1.md 项目统摄史观中 “信任个体体验” 的立场有深层共鸣：自由不是被授予的，而是被承认的

**辨析**：常见误解称 “BSD 许可不保护自由”——这是用 GPL 的自由观来评判 BSD；BSD 认为真正的自由包括选择闭源的自由——如果我只能以特定方式使用代码，那不是真自由；当然，这也意味着 BSD 代码可能被 “夺走” 并变成专有软件，但 BSD 社区认为这是自由的代价，而且从长期看，开放协作的价值会胜出（这一点已被 40 年历史部分验证）

## 157.6.2 CSRG 传统的延续：Bostic、Karels、Leffler 等人的科学精神

**要点**：CSRG（Computer Systems Research Group）的科学精神通过代码和文化传承给了 FreeBSD：(1) **Keith Bostic（基思·博斯蒂克）**——CSRG 核心成员，主导了 Net/2 重写（1991 年为应对 USL 诉讼，带领团队重写了所有 AT&T 代码）、nvi 编辑器（原 vi 许可证问题的重写版）、Berkeley DB 等项目；Bostic 的工作体现了 “为了自由重写一切” 的决心；(2) **Mike Karels**——CSRG 技术领导（1983 年后与 McKusick 共同领导），4.2BSD/4.3BSD 主要架构师之一，后加入 BSDi；Karels 以对代码质量的苛刻要求和细致的代码审查著称；(3) **Sam Leffler**——4.2BSD 技术主管（1982-1983），TCP/IP 栈实现的主要作者之一；1983 年离开 CSRG 加入 Lucasfilm（John Lasseter 正是通过 Leffler 的关系为 4.3BSD 画了 daemon！），后创立 Silicon Graphics 的 BSD 部门，再后创建 Whistle Communications（嵌入式 BSD 产品）；Leffler 是典型的 “从学术到工业” 的桥梁人物；(4) **CSRG 的同行评审传统**——在互联网时代之前，CSRG 就已经在实施类似现代 code review 的实践——所有代码提交都要经过 Karels 或 McKusick 的审查；(5) **可重复实验精神**——CSRG 发布的不仅是代码，还有完整的文档、论文和设计说明（如 4.3BSD 设计书），使得其他人可以理解、复现、改进他们的工作

**史料**：McKusick, M. K. (1999). *Twenty Years of Berkeley Unix*. in Open Sources; Salus, P. H. (1994). *A Quarter Century of UNIX*. Addison-Wesley; Leffler, S. J., McKusick, M. K., Karels, M. J., & Quarterman, J. S. (1988). *The Design and Implementation of the 4.3BSD UNIX Operating System*. Addison-Wesley; Bostic, K. (1990s). *Net/2 Source Tree Release Notes*. CSRG, UC Berkeley ［B］

**史观**：总纲第 25 条——终结与延续：CSRG 的科学精神没有随 CSRG 1995 年解散而消失——它通过 FreeBSD、NetBSD、OpenBSD、Darwin 等后代项目延续至今；FreeBSD 的 code review 流程、release engineering 纪律、文档传统都是 CSRG 精神的直接继承者

**辨析**：需要区分 “CSRG 神话” 与历史真实——CSRG 不是完美的理想国，他们也有代码 bug、内部政治、截止日期压力、人为错误；但他们确实建立了一套在当时非常先进的工程实践，为后来的开源运动提供了参考模型

**文献**：McKusick, M. K. (1999). Twenty Years of Berkeley Unix. In *Open Sources: Voices from the Open Source Revolution*. O'Reilly; Salus, P. H. (1994). *A Quarter Century of UNIX*. Addison-Wesley. ISBN 0-201-54777-5; Bostic, K. (1991). *BSD Networking Release 2 (Net/2) Release Notes*. CSRG, UC Berkeley, June 1991; Leffler, S. J. (2000s). Personal recollections of the CSRG era（私人博客和访谈）. ［B］

## 157.6.3 从广告条款到信任原则：许可证文本作为公共契约的历史叙事

从 4-clause BSD 到 3-clause、再到 2-clause FreeBSD 简化版，许可证文本的每一次削减都不止于法务操作，而是一次公共契约的重写——最初的四条款要求所有再分发材料必须提及「This product includes software developed by the University of California, Berkeley and its contributors」，把学术机构身份焊入商业分发的强制署名条款一直延续了 15 年，直到 1999 年 7 月 22 日 William Hoskins（UC Berkeley 技术许可办公室主任）签发删除函，这条强制项才让位给 3-clause，随后 FreeBSD 自 2000 年代起采用 2-clause 变体，进一步删除「不得用贡献者名义做背书」的限制，把 BSD 语义推到极致：我给你一切，只请你保留版权声明与免责声明，每一次条款削减都像在剥掉一层法律强制的皮，露出下面那个更脆弱的东西——信任

真正的转折发生在 1994 年——UNIX System Laboratories 从 Sun 手中收购 AT&T 版权后向 Berkeley 发难，CSRG 无法再合法分发 AT&T 代码，Keith Bostic 带领团队发起 Net/2 重写，把内核中所有 AT&T 代码用 BSD 重新实现，用工程行动回应法律胁迫；Bostic 之后的 CSRG 解散（1995）没有让这种「为了自由重写一切」的精神消失，Sam Leffler 转投 Lucasfilm 与 Silicon Graphics，Mike Karels 加入 BSDi，而 CSRG 的 code review 传统通过 FreeBSD 的 Reviewed-by 与 Approved-by 字段延续至今

BSD 与 GPL 的分歧不只是许可证条款的技术选择，而是两种自由观的正面碰撞——GPL 通过 copyleft 强制派生作品同样开放，是「自由捍卫者」，BSD 允许闭源再分发，是「自由的给予者」；2022 年 G. Branden Robinson 在 linux-man 邮件列表上与 Ingo Schwarze 关于「Under this umbrella, the Linux kernel is effectively under the BSD license」的争论，把这一分歧重新拉回台面——Ingo 反驳称自由软件项目无法从 Linux 复制代码，「that's quite a big BUT since allowing everybody to copy the code for any purpose is the central idea of the BSD license」，并指出「GPL code is far from as free as if it were under a BSD license」，因为 BSD 让渡了伯尔尼公约下所有可转让权利，只保留本不可让渡的道德权

Alejandro Colomar 用一段对偶概括了这场非对称性——「the kernel is BSD-licensed to big corporations paying to the FSF, but GPL to free software programmers」，「BSDs are BSD for everyone」，Branden Robinson 干脆断言「The BSD camp did ultimately win the copyleft argument after all」，这一判断并非空谈，而是被 Linux 内核社区四十年的双许可实践部分验证——2004 年 altq HFSC 移植时原作者的立场「they removed the advertising clause, but they did not want to release the code under the GPL」（DSLXC-14842），2012 年 if_ppp.h 清理时 Paul Mackerras 承认「the license on include/linux/if_ppp.h is the old BSD-style license with advertising clause」（DSLXC-15340），2015 年 David Woodhouse 在 Kernel Summit 讨论 GPL 执法光谱时观察到「basically wanting to act as if it's a BSD licence, in order to avoid scaring commercial users away」（DSLXC-17181），BSD 的宽松许可已经成为 Linux 内核治理中不可回避的参照系

2025 年 G. Branden Robinson 在 linux-man 的 AI 贡献政策讨论中把这一哲学张力推向当下——「projects that employ copyleft licenses foreclose contributions from people who hold that BSD-style licenses, or dedication to the public domain, are "the only true free[dom]"」（DSLXC-11717），而在更早的 1999 年 9 月 18 日 JF Martinez 已警告「BSD licensed software can be reused legally」（DSLXC-16431），Alan Cox 2007 年回应「Linux stealing our code」指责时辩护「BSD code is being used according to the BSD licence」（DSLXC-15440），Manfred Schwarb 更直白地表态「a BSD Licence is open source. In fact, it is more liberal than GPL」——这些散落四十年的英文引语共同勾勒出 BSD 许可证作为公共契约的独特位置：它不是最强硬的自由主义者，却是最慷慨的自由主义者，不是最成功的自由捍卫者，却是把自由真正交还给用户的那一份

「Trust the user」这四个字的力量，正在于它拒绝用法律文本去预设用户会做错误的事——BSD 假设使用者是理性的、负责任的、有能力做出正确选择的成年人，FreeBSD 的 code review 文化、CSRG 的可重复实验传统、Bostic 为了自由重写一切的决绝，都是这一假设在不同尺度上的兑现；当 Netflix 的 100Gbps CDN、PlayStation 的主机、Juniper 的路由器、现代 macOS 的 TCP/IP 栈与 Linux 内核中的双许可代码在同一时刻运行同一份或同一血统的 BSD 代码时，「信任」不再是一句许可文本的口号，而是数十年来工程师用代码本身书写的实践证据

## 157.6.4 从伯克利行政删条款到 AI 政策争论：BSD 公共契约的四十年时序

1999 年 7 月 22 日，加州大学伯克利分校技术许可办公室主任 William Hoskins 签发删除函，把四条款 BSD 许可证中要求所有再分发材料提及 UC Berkeley 及其贡献者的广告条款取消，从此进入 3-clause 时代——这是一个伯克利官僚系统里看似行政性的动作，却在接下来的二十五年间重塑了全球软件的许可版图

仅仅两个月后，1999 年 9 月 18 日，Jean Francois Martinez 在 linux-mm 邮件列表上写下第一声警告：「BSD licensed software can be reused legally」——BSD 的宽松条款确实允许任何人把代码合法地重新包装为专有软件，这不是漏洞，而是 BSD 语义的原生后果

## 157.6.5 当信任遇到执法：KS2016 辩论的一手数据与文档移植的许可漂移

**叙述**：157.6.3 与 157.6.4 分别从许可证文本削减与四十年时序两个方向叙述了 BSD 公共契约的生成，本节换一个角度——把"信任用户"放进执法与移植的具体现场去检验。这条线索在 man-pages 项目的一条普通邮件里开始：2008 年 10 月 Mike Frysinger 提议从 FreeBSD 导入 queue(3) 手册页，理由是 glibc 的 queue.h 及相关头文件本身即来自 FreeBSD、文档应随之补齐；Christopher Hellwig 指出 man-pages 已有的 queue(3) 是他在 Andries Brouwer 维护时期基于 FreeBSD 页提交的、但现用版本仍是旧的 4.4BSD 版而现代 BSD 已大幅变动（linux-man.messages.725934）——glibc 头文件与 BSD 现代版本之间的漂移，由此成为 BSD 移植史的最小样本

紧邻其后的 2009 年 1 月，移植的另一面出现了：Petr Baudis 提交 getifaddrs(3) 手册页时声明 "I'm open to relicensing to any of the standard licences, this one should be compatible even with the classic BSD licence"，Michael Kerrisk 则判断 "By now, I think little, if any, of the BSD page remains. I'd be inclined to switch to the verbatim license?"，Baudis 只回 "sure"（linux-man.messages.725290）——一次 BSD 移植因原文留存极少而改换许可证，"信任用户"在此的具体形态是：作者不阻拦使用者重定规则，但也因此不保证 BSD 血统的延续

BSD 由边缘参照变成并列选项，是 2015 年 7 月 Christoph Lameter 在内核峰会议题中提出的重许可之问：infiniband 栈近期出现 "a couple of license changes recently from GPL to \"pick onee GPL or BSD\""（原文如此，拼写亦如此）让他惊讶，并追问版权人的判定标准究竟为何——文件头提及就算？只改过一行呢？他请 Linux Foundation 律师澄清（ksummit-discuss.messages.345453）；这次追问的直接后果，是把 BSD 从外部对照拉进内核许可证的核心议题

真正密集的一手数据出现在 2016 年 8 月 26 日至 30 日 ksummit-discuss 列表的 GPL 执法 CORE TOPIC 辩论。David Woodhouse 8 月 26 日给出贯穿全场的核心论断："Without the option of a lawsuit, there *is* no negotiation. The GPL has certain requirements and they are backed up by law. If you don't have that, you might as well have a BSD licence"，并以 BSD 场景作模拟："You won't get far in negotiating with someone to release their modifications if the code in question is under a BSD licence and you start the conversation by saying 'You need to release the changes you made or... we'll be sad'. And that's *precisely* the same as the GPL if you state up front that you'll never sue. You'll just get laughed at"（ksummit-discuss.messages.347159）；Jeremy Allison 8 月 27 日把 BSD 与 MIT 定性为体现 "no consequence for non compliance" 态度的许可，指出这一策略在 Apple、EMC、Isilon、NetApp 身上"并没有奏效"——四者都拥有基于 BSD 代码的重要内核，却拒绝向母项目回馈任何有价值的代码，最后他以调侃收尾，请对方若想用偏好的许可证工作，先修复 FreeBSD 缺失的 per-thread credentials（ksummit-discuss.messages.347183）；8 月 28 日 Woodhouse 补出被广泛引用的等式："if we added a clause to the kernel's COPYING file which made it says that 'legally you have to release source... but we promise we'll never sue if you don't', then that basically *turns* it into a BSD licence for most purposes"（ksummit-discuss.messages.347209）——承诺永不起诉在法律效果上等于 BSD，同日他另以三组专有替代品论证违规并非无受害者："Without OpenAFS, we'd have got true AFS support in the kernel much sooner. Without the nVidia driver, we'd have have much faster progress on nouveau"（ksummit-discuss.messages.347215）

gpl-violations.org 创始人 Harald Welte 8 月 29 日带来本轮辩论中唯一的一手量化数据："During the active time of the project, we had some ~ 300 GPL violation cases, out of which the large majority could be resolved out of court. IIRC, less than 10 had to go to court"——庭上执法全部成功，且全部限于 cease + desist、无一涉及损害赔偿；他直言 "Using the GPL and not doing enforcement is useless, and you should have gone for BSD/MIT instead, if that's the goal"（ksummit-discuss.messages.347247）。Rik van Riel 同日从商业逻辑反面立论："It is worth remembering why XFS, JFS, and RCU were made available only under the GPL, and not under eg. a BSD license. Linux got access to that code because of the GPL's obligation that further improvements be made available to the whole community. Companies like IBM and SGI started participating in Linux because they knew no competitor would run off with their code"（ksummit-discuss.messages.347263）。Linus Torvalds 给出反向论证：LLVM 的成功部分源于 gcc 从未拥有好的外部可见 IR，"a large part of it was also a _political_ decision for strong copyleft reasons. rms did not want an open IR, because rms did not want those external plugins"；他称在 dronecode 项目中 "the GPL is being actively pushed away in favor of the BSD-licensed code"，并断言 "I think a hard-liner attitude ends up really hurting projects technically. If you want to use the license as a 'weapon' to expand your reach, it can and does back-fire"（ksummit-discuss.messages.347270）。Luis R. Rodriguez 8 月 30 日自承责任："I'll admit I am partly to blame for the proliferation of a new age of permissive license proliferation in the kernel, this all started with a joint effort to help the BSDs when we took the openhal for ath5k, then ath9k.. etc... My days of the whole BSD camp - kumbaya are over, as I've seen the danger with that"（ksummit-discuss.messages.347311）——GPL 阵营内部对 BSD 的信任从未缺席，裂缝也由此显形

回到文档传统本身，Ingo Schwarze 在 2022 年 7 月 26 日回复 man-pages 项目 CAVEATS 章节文档化的补丁讨论时，给出一组精确到版本与日期的一手考证（linux-man.messages.725591）：最早的 `.SH CAVEATS` 见于 4.2BSD 的 execve(2)，时间为 1983-09，随后是 4.3BSD-Tahoe 的 patch(1)（Larry Wall）、4.3BSD-Reno 的 amd(8)（Jan-Simon Pendry）、4.4BSD 的 strftime(3)（Arnold Robbins）；作者多为外部贡献者而非 CSRG 成员，唯一可明确归入 CSRG 的是 4.4BSD-Lite1 realpath(3) 的 Keith Bostic，彼时该章节形式已在 UNIX 手册中沿用十余年，甚至可上溯至 AT&T System III UNIX 的 man(7)（1982）；NetBSD 直到 2002 年才在 tech-userlevel 讨论后由 YAMAMOTO Takashi 写入 mdoc.template 完成标准化，OpenBSD 则由 Jason McIntyre 迅速采纳。这条谱系把 157.6.1 所论的"信任用户"落实为一条可核查的制度实践：手册页主动列出限制、陷阱与失效条件，把风险判断交给使用者，而不是由作者代为兜底。同周 7 月 27 日至 29 日，Schwarze 与 Alejandro Colomar 在 linux-man 的 BSD/GPL 争论中隔信回应——Colomar 的非对称结构概括见 157.6.3，而 Schwarze 在此给出本章少见的反向判断，他把这一格局判为 lose-lose："in practice, the GPL fails to attain the goals RMS designed it for, and i say that all the same, it has some serious and (hopefully) unintended detrimental side effects"，因为 BSD 依伯尔尼公约让渡了所有可转让权利、只保留本不可转让的道德权；Colomar 自陈仍用 GPL 正因不接受 lose-lose，同时声明意图优先于许可证、开源使用者可向他请求例外，非开源场景仍严格受限（linux-man.messages.725566）。2024 年 4 月 Colomar 又描述 shadow 项目改用 NetBSD 的 strtoi/u(3) 后，测试自身实现与 libbsd 的实现时发现在某个未文档化边角用例上行为不同并确认为原始设计缺陷，最终融合 shadow 内部函数 getlong() 与 NetBSD strtoi(3) 设计出带类型安全的新 API，又因 Fedora 等系统拒纳 libbsd 依赖而自建 strtoi(3) 并独立为托管于 kernel.org 的 liba2i 库（linux-man.messages.725241）——信任让代码跨生态流动，也让回馈与否完全取决于使用者自身意愿

从 2008 年的 queue(3) 到 2024 年的 liba2i，"Trust the User" 在工程现场的具体形态是一次又一次的许可漂移、一次一次又一次的执法谈判、一次又一次的重新署名：CAVEATS 把风险判断留给使用者，getifaddrs(3) 的重授权把署名义务留给使用者，KS2016 那 300 起违规案把回馈与否的选择留给使用者；而 GPL 阵营四十年来反复提出的反问——没有法律后果的自由究竟是否还是自由——同样构成 BSD 许可的人文重量所在，因为答案从来不由许可证文本单独决定，而由使用者在每一具体情境中的判断累积而成

**要点**：

- Ike Levy 在纽约城 BSD 用户组的演讲刻意不谈近十余年往事而回到 UNIX 最早根源，其历史观是：历史可用于显示哪些问题早已被解决、解释现状何以如此，开发者与 IT 管理者的日常困境大多有前解，若前人做得更好就没有理由不沿用其路径。（BSDTalk EP120，[158.96-234.26]，L1）
- 他将 UNIX 的持久成功归因于诞生环境的偶然开放：在开源一词出现之前，法律与机构环境已迫使 UNIX 成为研究者真正拥有的可移植系统，大学可自由教学使用，人类第一次得到人人可拥有并可构建其上的计算基础；他以 Unix Haters Handbook 及 Dennis Ritchie 所作滑稽前言说明这种归因并不否认 UNIX 的缺陷。（BSDTalk EP120，[449.92-565.16]，L1）
- 他以 PLATO 为镜像对照：该系统由伊利诺伊大学与军方合作开发，具备线程化邮件、交互聊天等今日常见应用，运行于 Control Data 公司建造并拥有的主机上，因闭源与昂贵专线订阅模式而未能赢得黑客、研究者与工程师的心智投入；开放与否决定了同等技术复杂度的两个系统的相反命运。　[存疑脚注] 受访者对 PLATO 起始年代的口述不确定，且转写将主机名误录，具体年代与机型须以文献考据为准。（BSDTalk EP120，[575.2-677.64]，L1）
- 从 Open Group 商标视角看 UNIX 只是名字、商标与源码，但其真正延续至今的内核是哲学与方法论，即 McIlroy 概括的做好一件事、组件模块化、令失败优雅发生，这套方法论持续影响今日软件的成败判断，并在 BSD 系统上体现得最为显著。（BSDTalk EP120，[754.6-824.52]，L1）
- 他批评当代西方已无 Bell Labs 式研究环境：当年研究职位不预设成果的市场价值与应用角色，允许失败与搁置（晶体管即在此环境中产生并被搁置多年后重启），而一切伟大想法正源于这种空间；如今商业机构竞相以 labs 自称以抬高股价，实际并无真实研究，只是在消耗研究机构时代积累的知识产权储蓄，他呼吁问责但反对拆毁这些仍为开源开发者做事的机构。（BSDTalk EP120，[856.64-1155.8]，L1）
- 其个人 UNIX 历程：九十年代纽约 dot-com 兴盛期从街头废弃机器上自学 UNIX，最初体验为运行于 Mach 内核配 Red Hat 用户态的 MK Linux，回顾起来相当糟糕；在家庭与工作环境屡受 Linux 配置问题困扰后首次安装 FreeBSD，因清晰、简洁与 man pages 而从此不再回头；他并认为慢速旧硬件反而逼出更好的软件。　[存疑脚注] 受访者将 MK Linux 记忆为乔布斯重返苹果后的 Mach 实验，此归因与项目史实存在出入，须与文献交叉核实。（BSDTalk EP120，[1164.2-1346.54]，L1）

**史观**：

- 总纲1 一切真历史都是古代史：他强调 1974 年论文所描述的 UNIX 除资源需求外与今日日常使用的系统几乎完全相同，是同一个系统，这使得 UNIX 最古老的历史与当下直接相关；而 UNIX 历史最迷人之处在于所有使用者每天都在为它增添新的历史。（BSDTalk EP120，[1424.5-1508.54]，L1）

**辨析**：

- 将 UNIX 成功几乎完全归于早期开放性、将 PLATO 失败完全归于闭源，属受访者一家的归因框架：八十年代商业 UNIX 闭源售卖同样取得巨大成功，说明开放性并非成功的充分条件；此归因须与 USL 诉讼及同意令史料交叉验证后方可采信。　[存疑脚注] 开放性单一归因为当事人个人推断，未排除市场时机、贝尔实验室品牌与学术网络等其他变量。（BSDTalk EP120，[449.92-677.64]，L4）
