# 163.6 与同时期操作系统的比较——Linux 6.x、OpenBSD 7.x、NetBSD 10/11、Windows 11 24H2/Server 2025、macOS 15/16

## 163.6.1 Linux 6.12-6.18：Rust for Linux、sched_ext BPF 调度器与 AI 时代的 Linux 演进

**要点**：15.x 同期（2025-2026）Linux 内核持续演进：Linux 6.12（2024.11）合入 **sched_ext** 框架（BPF 可编程调度器），允许通过 eBPF 程序在用户态编写自定义调度策略；Linux 6.14（2025.3.24）标记 sched_ext 为稳定、同时标记 **Rust for Linux** 为 “可用于新驱动开发”（即 Rust 支持从实验性升级为可用，但仅推荐用于新驱动而非重写现有代码）；Linux 6.18（2025.11）是 2025 年最后一个主要版本；Linux 持续在 eBPF 生态、云原生支持（容器、Kubernetes 优化）、新硬件支持（Intel/AMD/NVIDIA GPU、NPU/AI 加速器）、内存安全（Rust 驱动）等领域快速迭代；Linux 6.6 LTS（2023.11）仍是多数企业发行版采用的 LTS 版本，6.12 是较新的 LTS 版本

  **15.x 同期 Linux 内核版本时间线**：

  | 版本 | 发布时间 | 关键特性 |
  |---|---|---|
  | Linux 6.6 LTS | 2023.11 | 多数企业发行版采用的 LTS |
  | Linux 6.12 LTS | 2024.11 | **sched_ext** BPF 可编程调度器 |
  | Linux 6.14 | 2025.3.24 | sched_ext 稳定、**Rust for Linux** 标记可用于新驱动 |
  | Linux 6.18 | 2025.11 | 2025 年最后一个主要版本 |

**史料**：Linux 6.12/6.14/6.18 Release Notes（kernel.org）；林纳斯·托瓦兹（Linus Torvalds）内核发布公告；LWN 内核报道；sched_ext 文档与示例 ［C］

**史观**：总纲第 4 条——分离聚合是永恒规律（原“技术路线分化”系伪名目，按族例改挂）：Linux 与 FreeBSD 在 2020 年代的技术路线分化日益明显：Linux 走 “快速迭代、拥抱新功能、Rust 渐进引入、BPF 可编程一切” 路线；FreeBSD 走 “保守稳定、小 base 哲学、Ports 提供新软件、审慎评估 Rust” 路线；两种路线各有适用场景——Linux 主导云原生、AI 训练、新硬件支持领域；FreeBSD 在网络设备（Juniper、Netgate）、存储（TrueNAS、Netflix CDN）、嵌入式等领域保持强势

**辨析**：“Rust for Linux 稳定” 不等于 “Linux 内核大量使用 Rust”——截至 2026.7，Linux 内核中 Rust 代码量仍非常有限（主要是一些示例驱动与基础设施），绝大多数核心内核仍为 C 代码；sched_ext 是一个有趣的实验，但生产环境中绝大多数 Linux 系统仍使用默认调度器（EEVDF 或 CFS）；FreeBSD 的 kern.sched.name（15.1 引入）与 Linux sched_ext 目标不同——前者是内核内调度器模块选择，后者是 BPF 可编程调度器框架

## 163.6.2 OpenBSD 7.7-7.8：保守安全、TCP SACK 漏洞修复与 AI 发现漏洞

**要点**：同期（2025-2026）OpenBSD 版本：OpenBSD 7.7（2025.4 发布）、OpenBSD 7.8（2026.3 发布）；OpenBSD 7.8 最重要事件是 2026.3.25 发布 errata 025_sack.patch 修复 TCP SACK 远程 DoS 漏洞——该漏洞自 1998/1999 年存在，由 Anthropic Claude Mythos Preview AI 模型自主发现（详见 86.3.3）；OpenBSD 持续其 “默认安全” 哲学、频繁发布、最小化 base、自行重写关键组件（OpenSMTPD、OpenBGPD、OpenNTPD、rpki-client 等）；OpenBSD 对 AI 生成代码持怀疑态度但未发布正式禁令；OpenBSD 7.x 持续改进硬件支持但 LinuxKPI 式策略不是 OpenBSD 的方向——OpenBSD 坚持编写原生驱动或不支持硬件

**史料**：OpenBSD 7.7/7.8 Release Notes；OpenBSD errata 025_sack.patch（2026.3.25）；Anthropic Mythos 报告（2026.4）；**openbsd.duckdb** `openbsd-src` 仓库数据库查询未得 release tag 与版本 branches——OpenBSD 主仓为 CVS，GitHub 镜像可能未导入 release tag，与 NetBSD/FreeBSD 的 Git 仓库结构差异显著；OpenBSD 发布工程采用 CVS tag 机制（如 OPENBSD_7_8 等 CVS tag），在 Git 镜像中不表现为 annotated tag，须与 OpenBSD 官方公告（openbsd.org/{77,78}.html）交叉验证 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律（原“技术路线分化”系伪名目，按族例改挂）：OpenBSD 的路线与 FreeBSD/Linux 形成鲜明对比——OpenBSD 不追求硬件广泛支持或性能极致，而是将安全性、代码审计、极简主义置于最高优先级；FreeBSD 选择通过 LinuxKPI 兼容获取现代硬件驱动，OpenBSD 选择 “没有合适的驱动就不支持该硬件”——这是哲学选择而非能力问题

**辨析**：OpenBSD 的 “安全” 叙事需要准确理解——OpenBSD 的安全优势主要在于：默认安装最小化（攻击面小）、proactive 安全审计、代码简洁、exploit mitigation 技术（W^X、ASLR、RETGUARD 等）；但 OpenBSD 也存在安全漏洞（如 2026 年 SACK 漏洞即存在 27 年），“默认安全” 不等于 “无漏洞”；FreeBSD 与 OpenBSD 在安全技术上多有互相借鉴（如 pf 防火墙来自 OpenBSD，后被 FreeBSD 采纳并改进）。**数据库验证结论**：经 openbsd.duckdb `openbsd-src` 仓库查询未得 release tag 数据（查询条件：`SELECT tag_name, tagger_date FROM tags WHERE repo_name='openbsd-src'` 返回空集），暂无法用 commit/tag 证据验证 OpenBSD 7.7/7.8 发布日期；考据审慎提示：OpenBSD 主仓为 CVS，GitHub 镜像可能滞后或未导入 CVS tag，故此处采信 OpenBSD 官方公告日期（7.7: 2025.4，7.8: 2026.3）作为权威来源；OpenBSD 7.7/7.8 发布日期仍保留为官方公告日期，待 CVS 主仓或更完整的镜像数据可获得时再行补充验证

## 163.6.3 NetBSD 10.1/11.0 RC 与 DragonFly BSD

## 163.6.4 Windows 11 24H2、Windows Server 2025 与 macOS 15/16

**要点**：15.x 同期商业 OS：**Windows 11 24H2**（2024 下半年发布）引入 AI 功能（Copilot+ PC、NPU 支持）、改进安全功能（Intel CET、AMD Shadow Stack）、WiFi 7 支持；**Windows Server 2025**（2024 年底发布）强调安全（Secured-core Server、Hyper-V 改进）、Azure 混合云集成、容器与 Kubernetes 支持、热补丁；**macOS 15 Sequoia**（2024.9）引入 iPhone Mirroring、Apple Intelligence（AI 功能）、Safari 改进；**macOS 16**（2025 秋/WD 2026）持续 Apple Intelligence 深化与 Apple Silicon 优化；Apple Silicon M4 系列（2024.5 发布，3nm N3E）持续推动 ARM PC 生态

**史料**：Microsoft Windows 11 24H2/Server 2025 官方文档；Apple macOS 15/16 与 M4 发布公告 ［B］

**史观**：专题语（不设总纲条号）——AI 集成路线的政策差异（原挂总纲第 11 条系自撰名目，删条号保留分析）：商业 OS 在 2025-2026 年的共同主题是 “AI 集成”——Windows Copilot、Apple Intelligence 都将大语言模型深度集成入 OS；但 AI 集成在开源 OS（FreeBSD/Linux）中进展较慢——开源社区在 AI 隐私、本地推理、伦理问题上有更多顾虑；FreeBSD 在 AI 浪潮中的定位更偏向 “AI 工作负载的运行平台”（通过 Linux 二进制兼容运行 AI 框架、ZFS 存储 AI 数据集、Jail/bhyve 隔离 AI 工作负载）而非 “AI 功能集成入 OS 桌面”

**辨析**：FreeBSD 与 macOS 的关系需要准确理解——macOS 基于 Darwin 内核（Mach + BSD 混合），其中 BSD 部分源自 FreeBSD（用户态工具、C 库、网络栈等），但 macOS 已与 FreeBSD 分道扬镳超过 20 年（从 NeXTSTEP/Rhapsody 算起更长），内核架构（Mach 微内核 vs BSD 宏内核）、驱动模型（I/O Kit vs FreeBSD NEWBUS）、用户态生态都已大不相同；FreeBSD 不能原生运行 macOS 应用，macOS 也不兼容 FreeBSD 二进制
