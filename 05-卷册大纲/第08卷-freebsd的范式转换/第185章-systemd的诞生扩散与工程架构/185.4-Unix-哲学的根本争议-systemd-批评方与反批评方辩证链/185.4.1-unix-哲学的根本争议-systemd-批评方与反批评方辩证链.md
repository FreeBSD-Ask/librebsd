# 185.4.1 Unix-哲学的根本争议-systemd-批评方与反批评方辩证链

**要点**：批评方四论点：其一，违背 Unix 哲学“do one thing well”——systemd 集成日志（`systemd-journald`）、网络（`systemd-networkd`）、DNS（`systemd-resolved`）、时间同步（`systemd-timesyncd`）、登录（`systemd-logind`）、容器（`systemd-nspawn`）、引导加载（`systemd-boot`）、密码（`systemd-homed`）等多功能于同一代码库；其二，Red Hat 垄断——systemd 由 Red Hat 员工 Poettering 主导，IBM 2019-07-09 完成 340 亿美元收购 Red Hat 后垄断加深；其三，Poettering 个人主导——Poettering 26,600 commits 占全仓库历史 29.3%，强势风格压制异议；其四，bug 多发与安全漏洞——经 NVD 一手验证的 5 个 systemd CVE 包括 CVE-2013-4392（符号链接 TOCTOU，MEDIUM 5.0）、CVE-2017-18078（硬链接本地提权，HIGH 7.8）、CVE-2018-15688（dhcp6 堆缓冲区溢出，HIGH 8.8）、CVE-2019-3842（pam_systemd 授权绕过，HIGH 7.0）、CVE-2021-33910（unit-name.c 内存分配崩溃，MEDIUM 5.5）。反批评方四论点：其一，SysV init 局限性——串行启动、依赖管理混乱、shell 脚本脆弱；其二，现代初始化的必要性——并行启动、cgroups 集成、命名空间集成、容器友好；其三，Poettering 工程合理性——systemd 解决了真实工程问题；其四，BSD 阵营也在演化——OpenBSD 4.9（2011-05-01）引入 **rc.d(8)** 证明 init 必须演化。

**史料**：批评方第一论点（违背 Unix 哲学）的史料基础为 systemd 源码本身：`src/` 下 129 个组件子目录涵盖 init（`core/`）、日志（`journal/`、`journal-remote/`）、网络（`network/`、`resolve/`）、登录（`login/`）、引导（`boot/`、`bootctl/`）、容器（`nspawn/`）、密码（`home/`、`cryptenroll/`、`cryptsetup/`）、内核安装（`kernel-install/`）、命名空间（`nsresourced/`）、内存（`oom/`）、PCI（`pcrextend/`、`pcrlock/`）、分区（`repart/`）、系统更新（`sysext/`、`sysupdate/`）、用户（`userdb/`）、虚拟化（`vmspawn/`）等多种功能。Unix 哲学“do one thing well”的经典表述见 Kernighan & Pike 1984 年《The UNIX Programming Environment》与 Raymond 2003 年《The Art of Unix Programming》。

批评方第二论点（Red Hat 垄断）的史料基础：systemd 主要贡献者 Top 5 中 Poettering、Sievers（早期）均为 Red Hat 员工；IBM 2018-10-28 宣布以 340 亿美元收购 Red Hat（`redhat.com/en/about/press-releases/ibm-acquire-red-hat-completely-changing-cloud-landscape-and-becoming-worlds-1-hybrid-cloud-provider`），2019-07-09 完成收购（`redhat.com/en/about/press-releases/ibm-closes-landmark-acquisition-red-hat-34-billion-defines-open-hybrid-cloud-future`）。两份官方公告均确认收购金额 340 亿美元、每股 190 美元、全现金交易。

批评方第三论点（Poettering 个人主导）的史料基础为 systemd 仓库 `git shortlog -sn`：Poettering 26,600 commits 占全仓库 90,782 commits 的 29.3%，是第二名 Yu Watanabe（15,983）的 1.66 倍。

批评方第四论点（bug 多发与安全漏洞）的史料基础为 NVD NIST.gov 一手页面：

- CVE-2013-4392（`nvd.nist.gov/vuln/detail/CVE-2013-4392`）：NVD 发布日期 2013-10-28，CVSS v3.1 5.0 MEDIUM（CISA-ADP 评估），影响 systemd 至 v238，修复 v239，CWE-59 Improper Link Resolution Before File Access，漏洞描述“systemd 在更新文件权限时允许本地用户通过符号链接攻击修改任意文件的权限与 SELinux 安全上下文”。一手参考包括 `bugs.debian.org/cgi-bin/bugreport.cgi?bug=725357`、`openwall.com/lists/oss-security/2013/10/01/9`、`bugzilla.redhat.com/show_bug.cgi?id=859060`。

- CVE-2017-18078（`nvd.nist.gov/vuln/detail/CVE-2017-18078`）：NVD 发布日期 2018-01-29，CVSS v3.1 7.8 HIGH，影响 systemd 至 v236，修复 v237，CWE-59，漏洞描述“systemd v237 之前的 systemd-tmpfiles 即使在 fs.protected_hardlinks sysctl 关闭时仍尝试支持硬链接文件的所有权/权限更改，允许本地用户通过硬链接绕过预期访问限制，可修改 /etc/passwd 文件所有权”。一手参考包括 `github.com/systemd/systemd/issues/7736`、`openwall.com/lists/oss-security/2018/01/29/3`、`exploit-db.com/exploits/43935/`。受影响发行版：Debian 8.0、openSUSE Leap 42.3。

- CVE-2018-15688（`nvd.nist.gov/vuln/detail/CVE-2018-15688`）：NVD 发布日期 2018-10-26，CVSS v3.1 8.8 HIGH，影响 systemd 至 v239，修复 v240+，CWE-120 Buffer Copy without Checking Size of Input，漏洞描述“systemd 的 dhcp6 客户端存在缓冲区溢出漏洞，允许恶意 dhcp6 服务器覆盖 systemd-networkd 的堆内存”。一手参考包括 `github.com/systemd/systemd/pull/10518`、`access.redhat.com/errata/RHSA-2018:3665`、`access.redhat.com/errata/RHSA-2019:0049`、`lists.debian.org/debian-lts-announce/2018/11/msg00017.html`、`security.gentoo.org/glsa/201810-10`、`usn.ubuntu.com/3806-1/`、`usn.ubuntu.com/3807-1/`。受影响发行版：Debian 8.0、Ubuntu 16.04 LTS、Ubuntu 18.04 LTS、Ubuntu 18.10、RHEL 7.0 系列。CNA 为 Canonical Ltd.。

- CVE-2019-3842（`nvd.nist.gov/vuln/detail/CVE-2019-3842`）：NVD 发布日期 2019-04-09，CVSS v3.1 7.0 HIGH（NIST 评估）/ 4.5 MEDIUM（Red Hat 评估），影响 systemd 至 v241 及 v242-rc1/rc2/rc3，修复 v242-rc4，CWE-863 Incorrect Authorization（NIST）/ CWE-285 Improper Authorization（Red Hat），漏洞描述“systemd v242-rc4 之前的 pam_systemd 在使用 XDG_SEAT 变量前未正确清理环境。攻击者在特定配置下可设置 XDG_SEAT 环境变量，使命令通过 polkit 策略的‘allow_active’元素而非‘allow_any’进行检查”。一手参考包括 `bugzilla.redhat.com/show_bug.cgi?id=CVE-2019-3842`、`lists.debian.org/debian-lts-announce/2019/04/msg00022.html`、`exploit-db.com/exploits/46743/`。受影响发行版：RHEL 7.0、Fedora 30、Debian 8.0。CNA 为 Red Hat, Inc.。

- CVE-2021-33910（`nvd.nist.gov/vuln/detail/CVE-2021-33910`）：CVSS v3.1 5.5 MEDIUM，影响 systemd prior to 246.15、247.8、248.5、249.1，漏洞描述“systemd 上述版本之前的 basic/unit-name.c 存在内存分配过度大小值问题（涉及 strdupa 与 alloca 处理由本地攻击者控制的路径名），导致操作系统崩溃”。攻击向量 AV: L/AC: L/PR: L/UI: N/S: U/C: N/I: N/A: H。

反批评方第四论点（BSD 也在演化）的史料基础：OpenBSD 4.9（2011-05-01 发布）首次引入 **rc.d(8)** 与 **rc.subr(8)**——OpenBSD 4.9 release 页 `openbsd.org/49.html` “What's New”节原文："New rc.d(8) for starting, stopping and reconfiguring package daemons: The rc.subr(8) framework allows for easy creation of rc scripts. This framework is still evolving. Only a handful of packages have migrated for now. rc.local can still be used instead of or in addition to rc.d(8).“；OpenBSD **rc.d(8)** 手册页 HISTORY 节确认“The /etc/rc.d directory first appeared in OpenBSD 4.9.”。

**史观**：项目史观总纲第 21 条“革命与改革是历史方法论的分歧”在本节叙事中具体体现为：批评方第一论点“违背 Unix 哲学”与反批评方第一论点“SysV init 局限性”实质上是同一方法论分歧的两面——批评方坚持 Unix 哲学的“小工具协作”改革路径，反批评方坚持“PID 1 重新设计”的革命路径，二者不可调和。项目史观总纲第 6 条“和解优于斗争”在本节叙事中具体体现为：批评与反批评须对称呈现，禁止“systemd 是 evil”或“rc.d 落后”等道德判断性表述——systemd 与 rc.d 在本体论上各有其工程合理性与局限性，本章不偏袒任何一方。项目史观总纲第 8 条“本体论上各方平等”在此体现为：systemd 与 rc.d 在叙事中地位相等，批评方与反批评方的史料数量与篇幅大致对称（允许 ±20% 浮动）。

**辨析**：［考据注：初稿任务源数据曾误列 CVE-2015-3407（任意文件覆盖）为 systemd CVE，经 NVD 一手核验系 Perl 模块 Module::Signature 的漏洞，与 systemd 无关，已以 5 个经核验 CVE 替换；NVD 实录："Module::Signature before 0.74 allows remote attackers to bypass signature verification for files via a signature file that does not list the files."，受影响软件配置为 `cpe:2.3:a:module-signature_project:module-signature:*:*:*:*:*:*:*:*` Up to (including) 0.73，以及 Ubuntu 12.04/14.04/14.10/15.04（因 Ubuntu 默认携带该 Perl 模块），详见文献 [6]］

5 个 CVE 中 CVE-2013-4392 与 CVE-2017-18078 均指向 systemd-tmpfiles 的符号链接/硬链接处理缺陷，反映该组件为 systemd 安全高频出问题区域。CVE-2018-15688 与 CVE-2019-3842 的 CNA 分别为 Canonical Ltd. 与 Red Hat, Inc.，两家独立 CNA 对同一 systemd 产品的漏洞分别登记，构成发行版层面的交叉印证。

CVE 修复 commit 在 systemd 仓库中有 23 个不同 CVE 的修复 commit 可追溯（`git log --grep="CVE-"` 实测），证明修复响应及时。但“修复响应及时”不能等同于“安全质量高”——代码规模 799,726 行本身即扩大了攻击面，这是批评方第四论点的工程基础。

反批评方第四论点（OpenBSD 4.9 引入 **rc.d(8)**）的史实经 `openbsd.org/49.html` 与 OpenBSD **rc.d(8)** 手册页 HISTORY 节双重印证。但须注意：OpenBSD **rc.d(8)** **仅用于 package 守护进程**，base 系统由 `/etc/rc` 直接启动，不使用 **rcorder(8)** 依赖排序——这与 FreeBSD/NetBSD 的 rc.d 系统有本质差异（详见 BSD init 发展史一节）。核查源数据旧说“OpenBSD 2014-2015 简化重写”与官方文档不符——OpenBSD **rc.d(8)** 自 4.9（2011）引入即采取简化设计，5.6（2014-11）/5.7（2015-05）changelog 中 `rc.d` 仅有小修补（`_rc_do`/`_rc_wait` 重命名等），非“重写”。
