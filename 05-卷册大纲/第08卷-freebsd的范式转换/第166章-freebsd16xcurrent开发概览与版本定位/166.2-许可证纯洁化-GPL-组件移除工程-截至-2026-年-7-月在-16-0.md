## 166.2.2 gnu/ 目录退役与 GNU 构建基础设施清理

**要点**：截至 2026 年 7 月，在 dialog 移除同期，FreeBSD 16.0-CURRENT 分支中专用的 gnu/目录已被整体退役，同步删除剩余 GNU 专用构建文件、测试、许可文件及相关基础设施；这是 FreeBSD 历史上首次将整个 gnu/子目录从源码树中移除，标志着自 4.4BSD-Lite2（1993 年）以来继承的 GNU 工具集成范式在 base system 层面的终结；该清理工作通过代码审查流程（类似 D55425 等审查票）进行

**史料**：FreeBSD src repository cgit 提交记录（gnu/目录移除提交，截至 2026 年 7 月）、Phoronix 2026 年 7 月 15 日相关报道（标题提及 FreeBSD 16 Goes GPL-Free，注意该报道发布时 16.0 尚未发布，应指 16-CURRENT）、OpenNET 2026 年 7 月 15 日俄文报道"Базовая система FreeBSD-CURRENT избавлена от компонентов под лицензией GPL"、FreeBSD 4.4BSD-Lite2 源码树 gnu/目录历史记录 ［A］

**史观**：许可证〔订正注：原误挂总纲第 24 条，权威 24=美是消解性的体验，许可证论旨非总纲条目，去号〕：gnu/目录作为 FreeBSD 源码树中 GNU 软件的物理容器，其整体退役不仅是法律意义上的许可清理，更是 BSD 项目对自身身份认同的形式化重构——从此 FreeBSD 源码树不再为 GNU 软件保留专属空间

**辨析**：gnu/目录退役不等于 FreeBSD 与 GNU 生态完全割裂——GCC、GDB、Emacs、Bash、coreutils 等 GNU 工具仍通过 Ports 和 pkg 提供，且将继续得到良好支持；该清理仅针对 base system（内核、系统库、命令行工具、安装器、基础管理工具）；部分媒体报道将“16-CURRENT 移除 GPL”简化为“FreeBSD 16 已 GPL-free”，这种表述不够准确，须明确分支状态

## 166.2.3 dpv 三件套 Ports 化延续与 bsdpv 重写

**要点**：在 base system 移除 dialog/dpv/libdpv/libfigpar 之前，相关组件已预先在 Ports 集合中创建以延续功能：devel/libfigpar、devel/libdpv、sysutils/dpv 三个新 ports 于 2026 年 6 月 29-30 日创建，devel/libfigpar 与 devel/libdpv 维护者为 Devin Teske（<dteske@FreeBSD.org>），sysutils/dpv 维护者为 Dag-Erling Smørgrav（<des@FreeBSD.org>）〔订正注：原误作三件套维护者均为 Devin Teske，与 166.2.6 辨析修正同步〕，许可证为 BSD-2-Clause；同时存在在 bsddialog 之上重写 dpv 为 bsdpv 的工程（审查票类似 D58133），将公共 API 从 dpv_*重命名为 bsdpv_* 以标记与 GNU dialog 依赖的彻底决裂，并修复原 dpv 的若干 bug；该“先 port 化延续、再 base 移除、再 BSD 许可重写”模式是 FreeBSD 渐进式淘汰工程哲学的体现

**史料**：FreeBSD FreshPorts 记录（devel/libfigpar、devel/libdpv、sysutils/dpv 三个 ports 添加时间 2026 年 6 月 30 日前后，维护者 dteske）、FreeBSD Phabricator/Reviews 相关审查票（ports 创建审查、bsdpv 重写审查）、类似 14.0 net/freebsd-telnetd、15.0 ftp/freebsd-ftpd 的“port 接续”模式历史记录 ［A］

**史观**：终结与延续〔订正注：原误挂总纲第 25 条，权威 25=逻辑是形式主义而非世界本身的结构，去号〕：FreeBSD 从未采用“一刀切”式淘汰策略，而是遵循“引入替代 → 验证成熟 →port 化延续 →base 移除 → 原生重写”的渐进路径；这一路径既保证了许可证纯洁化目标的实现，又最大限度减少了对现有用户的破坏

**辨析**：ports 创建时间（2026 年 6 月底）早于 base 移除时间（2026 年 7 月），表明该工程是事先规划而非临时补救；bsdpv 重写工程截至 2026 年 7 月可能处于审查或已提交但尚未完全稳定状态，是否最终合入 16.0-RELEASE 仍需以 RELEASE 时的源码状态为准；dpv 等工具属于较为边缘的系统工具，多数普通用户可能不会直接使用，但作为系统组件的延续体现了对兼容性的重视

**文献**：FreeBSD FreshPorts. devel/libfigpar, devel/libdpv, sysutils/dpv 条目（freshports.org）；FreeBSD Phabricator. 相关 ports 创建与 bsdpv 审查票（reviews.freebsd.org）；FreeBSD 14.0-RELEASE Release Notes（net/freebsd-telnetd port 化）；FreeBSD 15.0-RELEASE Release Notes（ftp/freebsd-ftpd port 化） ［A］

## 166.2.5 辩证链第一层（批评层）——GPL/GNU 阵营对 dialog 移除与 GPL 代码清零的批评

**要点**：GPL/GNU 阵营对 BSD 许可证纯洁化工程的批评可归纳为三点。**其一，法律必要性存疑**：GPLv2 允许与 BSD 许可证代码共存，dialog 作为 LGPL/GPL 组件在 FreeBSD base 中存在 20 余年未引发许可证冲突，移除 dialog 的法律必要性存疑——GPL 软件进入 base 不迫使 FreeBSD 改变自身许可证；FSF 官方许可证评论页面（gnu.org/licenses/license-list.html）将 FreeBSD 许可证归类为“松散的、纵容型、非 copyleft 的自由软件许可证，兼容 GNU GPL”，承认 BSD 与 GPL 在法律层面可共存，移除 GPL 组件并非许可证兼容性所必需。**其二，“重新发明轮子”的资源浪费批评**：bsddialog 作为 dialog 的 BSD 许可替代，需重复实现 dialog 已成熟的功能（如菜单、表单、进度条、文件选择器等 TUI 控件），开发者资源本可用于更有价值的工程任务，如驱动开发、性能优化、新硬件支持；FSF 在许可证评论中虽承认“修改版 BSD 许可证并不差”，但同时“更推荐 Apache 2.0 许可证”，这一立场隐含对 BSD 路径的保留态度——FSF 倾向 copyleft 路径，dialog 移除强化了非 copyleft 路径，与 FSF 推荐方向相反。**其三，兼容性风险**：bsddialog 虽力求 API 兼容，但 GNU dialog 的部分高级特性与 `.dialogrc` 配置支持可能存在差异，依赖这些特性的脚本可能受影响——dialog 的 `.dialogrc` 文件允许用户自定义颜色、属性、阴影等界面元素，bsddialog 的兼容程度需逐一验证。这些批评共同指向“过度纯洁化”质疑：FreeBSD 是否在追求许可证纯洁的工程中偏离了“实用主义”传统，将许可证标签置于功能完整性之上。

## 166.2.6 辩证链第二层（反批评层）——FreeBSD 阵营对批评的回应与许可证纯洁化工程必要性论证

**要点**：FreeBSD 阵营对 GPL/GNU 阵营批评的回应可归纳为三点。**其一，BSD 许可证纯洁化不是“法律必要性”问题而是“工程原则”问题**：FreeBSD Licensing Policy（docs.freebsd.org/en/articles/license-guide/）明确偏好 BSD-2-Clause 许可证——“The FreeBSD Project uses this text as the preferred license”——base system 作为操作系统核心应保持许可证一致性，这是项目身份认同的形式化表达；法律必要性论证局限于“是否被强制”，但工程原则论证扩展至“是否应当”，二者属不同论证层次，FreeBSD 选择后者。**其二，bsddialog 非“重新发明轮子”而是“基于 FreeBSD 基础库的重新实现”**：bsddialog 由 Alfonso S. ## 166.2.7 辩证链第三层（再回应层）——GPL/GNU 阵营对 FreeBSD 反批评的再回应

**要点**：GPL/GNU 阵营对 FreeBSD 反批评的再回应可归纳为两点。**其一，“工程原则”论证可能遮蔽实际利益结构**：BSD 许可证纯洁化的主要受益者是商业厂商（如 iXsystems、Netgate、Juniper、Apple 等），这些厂商可无义务地将 base system 用于专有产品——BSD 许可证允许商业再分发而不要求开源衍生作品，这一“无义务”特性使厂商可在 base system 之上构建闭源商业产品（如 Netgate pfSense、iXsystems TrueNAS）；GPL 移除的“原则”叙事服务于“商业友好”的实际利益，“工程原则”作为修辞策略将利益结构问题转化为技术哲学问题。**其二，bsddialog 的“充分验证”需经独立第三方审计确认**：3,123 次 commit 与 7 个 release 的数量指标不等于代码质量——commit 数量反映开发活跃度，但不直接证明代码的安全性与可维护性；dialog 作为 GNU 项目多年维护的成熟软件，其代码审计深度可能超过 bsddialog——dialog 经历了 Linux 发行版、GNU/Hurd、其他 BSD 项目多年的实战验证，而 bsddialog 的部署范围主要限于 FreeBSD 生态。这一再回应指向“原则 vs 利益”与“数量 vs 质量”两组元层面的诘难：FreeBSD 阵营的反批评在论证层次上回应了 GPL/GNU 阵营的批评，但 GPL/GNU 阵营的再回应将争议提升至元层面——“原则”叙事本身是否是利益结构的遮蔽，“充分验证”的判断标准如何确立。

**史料**：FreeBSD Foundation 2024 Annual Report（freebsdfoundation.org/our-donors/，企业赞助者名单含 iXsystems、Netgate、Juniper、Apple 等）；bsddialog 项目页面（gitlab.com/alfix/bsddialog，3,123 commits/7 releases/18 tags，但无独立第三方安全审计报告）；GNU dialog 项目维护历史（FSF GNU 项目档案，dialog 作为 GNU 项目多年维护的成熟软件）；FreeBSD 16.0-CURRENT base system 许可证扫描（须以 cgit.freebsd.org/src/ 实时源码与许可证扫描工具输出为准）；Linuxiac 2026-07-17 报道（确认 4 年迁移工程，但未涉及独立安全审计）；freshports.org misc/dialog port（GNU dialog 仍可通过 Ports 安装）〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 13 条——法律与道德是利益分配：GPL/GNU 阵营“原则遮蔽利益”再回应印证“任何道德问题本质上是利益问题”——BSD 阵营“工程原则”叙事与 GPL 阵营“利益遮蔽”批评背后是两套利益分配机制的对立：BSD 许可证服务商业厂商无义务使用的利益（iXsystems、Netgate、Apple 等），GPL 许可证服务上游回馈的利益（FSF、GNU 项目、原创者社区）；总纲第 19 条——解释学循环是历史认识的根本条件〔订正注：原名目“解释学循环与权力知识共谋”系权威名目增衍，统一为权威全称〕：GPL/GNU 阵营“数量 vs 质量”诘难指向“什么被视为充分验证”的解释学循环——commit 数量与 release 数量作为“验证”的形式主义指标，遮蔽了“独立第三方审计”这一更高验证标准的缺失

**辨析**：考据过程留痕——【查证来源】(1) FreeBSD Foundation 2024 Annual Report 经 freebsdfoundation.org/our-donors/ 一手核验，确认企业赞助者名单含 iXsystems、Netgate、Juniper 等，但企业赞助金额与 BSD 许可证偏好之间的直接因果关系无法考据——二者存在结构性亲和但非线性因果 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；(2) bsddialog GitLab 项目页面经一手核验，确认无独立第三方安全审计报告，“充分验证”表述来自 bsddialog 项目自身与 FreeBSD 社区；(3) Linuxiac 报道经一手核验，确认“4 年迁移工程”表述但未涉及代码质量评估。【交叉验证方法】FreeBSD Foundation 企业赞助者名单与 FreeBSD Licensing Policy BSD-2-Clause 偏好交叉验证“商业友好”利益结构——BSD-2-Clause 允许商业厂商无义务使用 base system，这一许可证特性是企业赞助 FreeBSD Foundation 的重要动机之一；bsddialog 项目页面与 GNU dialog 维护历史交叉验证“代码审计深度”差异——dialog 经多年多项目实战验证，bsddialog 部署范围较窄。【存疑判定依据】(1) bsddialog 与 dialog 的代码质量对比无独立第三方审计结论，本节“dialog 代码审计深度可能超过 bsddialog”为合理推论而非确证 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；(2) “原则遮蔽利益”是 GPL 阵营的论证策略，BSD 阵营可反向批评 GPL 阵营“利益遮蔽原则”——GPL copyleft 同样服务 FSF 与 GNU 项目的机构利益，二者均为利益诉求表达；**不偏袒叙事姿态声明**：本再回应层既不将 BSD 阵营塑造为“原则捍卫者”，也不将 GPL/GNU 阵营塑造为“批评者”，两方论点对称呈现，史家的职责是呈现而非裁判

## 166.2.8 辩证链合图层——dialog 移除与 GPL 代码清零的史观审视

**要点**：dialog 移除与 GPL 代码清零的合图不在“一方正确、一方错误”的二元判定中，而在 FreeBSD 选择的“base 纯洁化 + ports 多元化”双层架构中——base system 保持 BSD 许可证一致性满足工程原则与商业友好需求，Ports 集合保留 GPL 软件（含 GNU dialog）满足功能兼容与用户选择需求。这一双层架构使“BSD 纯洁化”与“GPL 软件可用”两个看似矛盾的诉求在分层架构中得到和解。Devin Teske 创建的 `devel/libfigpar`、`devel/libdpv`（维护者 <dteske@FreeBSD.org>）与 `sysutils/dpv`（维护者 <des@FreeBSD.org>，即 Dag-Erling Smørgrav）三个 Port（2026 年 6 月 29-30 日由 <des@FreeBSD.org> 提交）与 bsdpv 重写工程体现了“不抛弃旧用户”的兼容性承诺。这一合图印证总纲第 6 条“和解优于斗争”——和解不是 GPL 阵营放弃批评，也不是 BSD 阵营放弃纯洁化，而是双方在“base 与 ports 分层”的架构中找到各自位置。但合图不等于完美——bsddialog 与 GNU dialog 的功能差异仍可能影响部分用户，GPL 阵营的“资源浪费”批评仍成立（bsddialog 确实重复实现了 dialog 的功能），这印证总纲第 2 条“历史是形式主义化的非存在”——所谓“GPL 清零”只是当下主体对形式的重构，下一刻的争议（如 Rust 是否进入 base、AI 生成代码的许可证问题）正在形成。16.0-CURRENT 作为“可能性的集合”（参见 65.6 史观映射），其 GPL 清零不是 FreeBSD 历史的终点，而是新的形式主义化过程的起点。

**史料**：FreeBSD Ports 中 GNU 软件列表（misc/dialog port、lang/gcc port、misc/gnuls port 等，freshports.org 一手核验）；bsddialog 与 GNU dialog 功能差异（`.dialogrc` 配置支持等，须以 bsddialog 项目文档为准）；FreeBSD FreshPorts 三个 ports（devel/libfigpar、devel/libdpv、sysutils/dpv，2026-06-29/30）；FreeBSD 16.0-CURRENT 开发状态（截至 2026 年 7 月，main 分支处于 Open 状态）；FreeBSD Licensing Policy（docs.freebsd.org/en/articles/license-guide/，BSD-2-Clause 偏好条款）；Linuxiac 2026-07-17 报道与 IT 之家 2026-07-18 报道（dialog 移除事件三源交叉验证）

**史观**：总纲第 6 条——和解优于斗争〔订正注：原条号 6 下混写“分离聚合是永恒规律”（系第 4 条名目），拆分错配〕：dialog 移除的合图层印证“和解是事物真正完整的一刻”——危机不是历史的终点，`gnu/` 目录的移除看似“GNU 时代终结”，实则是 FreeBSD 与 GNU 生态在新架构（base/ports 分层）中的重新定位；总纲第 2 条——历史是形式主义化的非存在：合图不等于完美，下一刻的争议正在形成，史家须以自反姿态承认本书自身的形式主义性质；总纲第 8 条——本体论上各方平等：BSD 阵营的“工程原则”与 GPL 阵营的“资源浪费”批评在本体论上地位相等，二者皆是各主体性呈现的利益诉求表达，差异仅是一刻状态的不同，史家不得以“原则”或“利益”任一视角压制另一方

**辨析**：考据过程留痕——【查证来源】(1) FreeBSD Ports 中 misc/dialog port 经 freshports.org/misc/dialog/ 一手核验，确认 GNU dialog 仍可通过 Ports 安装，“base 纯洁化 + ports 多元化”双层架构在 Ports 层面成立；(2) FreeBSD FreshPorts 三个 ports 经一手核验，确认 dpv 三件套在 Ports 中延续，“不抛弃旧用户”承诺在 port 化层面成立；(3) FreeBSD 16.0-CURRENT main 分支状态经 freebsd.org/releng/ 一手核验，处于 Open 状态，dialog 移除工作截至 2026 年 7 月仍在 CURRENT 分支状态。【交叉验证方法】FreeBSD Licensing Policy BSD-2-Clause 偏好与 Ports 多元化共存模式交叉验证“base 纯洁化 + ports 多元化”双层架构的可行性；Linuxiac、IT 之家、Phoronix 三源交叉验证 dialog 移除事件的一致性；bsddialog 项目页面与 GNU dialog 维护历史交叉验证“功能差异仍可能影响部分用户”的合理性。【存疑判定依据】(1) 16.0-CURRENT base system 是否完全无 GPL/LGPL 组件须以 cgit.freebsd.org/src/ 实时源码与许可证扫描工具输出为准 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；(2) bsdpv 重写工程是否最终合入 16.0-RELEASE 须以 RELEASE 时的源码状态为准；(3) “合图不等于完美”是史家的诚实性表述——合图层不强行归并争议，承认“资源浪费”批评仍成立与“工程原则”论证仍成立同时为真；**不偏袒叙事姿态声明**：合图层既不美化“BSD 胜利”，也不否定“GPL 批评”，而是承认双方在本体论上的平等地位与争议的部分不可调和性——base/ports 分层架构是有限和解，而非彻底共识
