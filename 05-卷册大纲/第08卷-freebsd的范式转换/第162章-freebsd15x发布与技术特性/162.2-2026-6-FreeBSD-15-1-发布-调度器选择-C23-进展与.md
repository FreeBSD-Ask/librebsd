## 162.2.2 15.1 核心技术更新

**要点**：15.1 的关键改进包括：① **iwlwifi(4)** 与其他基于 LinuxKPI 的无线网络驱动升级至基于 **Linux v7.0** 内核版本（WiFi 6/6E 支持显著改进）；② 使用 pkgbase 的云镜像现在默认包含 **pkg(8)**，并支持首次启动时自动更新基础系统包；③ 新增 **kern.sched.name loader tunable**，允许在启动时选择内核调度器（为未来调度器框架模块化奠定基础）；④ **C23 编程语言标准支持取得重大进展**（编译器与库跟进 C23 特性）；⑤ Unicode 支持更新至 **Unicode 17.0.0 与 CLDR 48**，新增 4,803 个字符；⑥ 持续的安全修复、驱动更新与稳定性改进

  **FreeBSD 15.1 核心技术更新清单**：

  | 序号 | 特性 | 说明 |
  |---|---|---|
  | ① | **iwlwifi(4)** 等 WiFi 驱动 | 基于 LinuxKPI 的无线驱动升级至 **Linux v7.0** 基线，WiFi 6/6E 支持改进 |
  | ② | pkgbase 云镜像 | 默认包含 **pkg(8)**，支持首次启动自动更新基础系统包 |
  | ③ | **kern.sched.name** loader tunable | 启动时可选内核调度器，为调度器框架模块化奠基 |
  | ④ | C23 标准支持 | 编译器与库跟进 C23 特性，取得重大进展（非完整支持） |
  | ⑤ | Unicode 17.0.0 与 CLDR 48 | 新增 4,803 个字符 |
  | ⑥ | 安全与稳定性 | 持续安全修复、驱动更新与稳定性改进 |

**史料**：FreeBSD 15.1-RELEASE Announcement Highlights 部分；FreeBSD 15.1-RELEASE Release Notes；Clang/LLVM C23 支持状态文档；Unicode 17.0 发布公告（2025.9）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕

**史观**：总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：可启动时选择的调度器框架（kern.sched.name）看似不起眼的 tunable，实际上是内核调度器模块化的重要一步——FreeBSD 历史上调度器（ULE 等）是静态编译进内核的，运行时可选择调度器为未来引入新调度算法（如针对延迟敏感工作负载、实时场景、异构 big.LITTLE 架构的调度器）打开了大门

**辨析**：C23 支持 “重大进展” 不等于 “完整支持”——15.1 中 C23 标准的部分可选特性仍未实现，完整 C23 支持预计在 16.0 周期内完成；LinuxKPI 驱动从 Linux 6.x 升级至 Linux 7.0 基线是 FreeBSD WiFi/GPU 驱动持续上游跟进策略的体现，但这并不意味着所有 Linux 7.0 驱动功能都已可用——仅表示兼容层 API 已对齐至 Linux 7.0 水平

## 162.2.3 15.x 分支生命周期与 15.2+ 展望

**要点**：截至 2026 年 7 月，FreeBSD 15.x 分支的规划为：15.0（2025.12.2，支持至 2026.9.30）、15.1（2026.6.16，支持至 2027.3.31），预计后续还将有 15.2（可能在 2026 年底或 2027 年初）等小版本，整个 stable/15 分支将持续获得安全更新与关键错误修复直至 **2029 年 12 月 31 日**；16.0-RELEASE（current/16 分支）预计在 2027 年底或 2028 年初发布，将是下一个大版本；16.0 规划中的可能变化包括：Rust 语言进入 base system 的可能性（仍在社区讨论中）、pkgbase 成为默认安装方式、distribution sets 传统安装方式移除、fdisk/bsdlabel 等传统工具移除、更多驱动基于 LinuxKPI 移植、armv7 可能降级或退役、进一步的 C23/C2x 支持、持续的性能优化与安全加固

**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：15.x 分支的五年支持周期（2025-2029）体现了 FreeBSD 对企业级用户稳定性承诺的延续——每个 major 分支五年支持的政策自 FreeBSD 4.x 时代以来基本保持一致；16.0 的规划则延续了 “稳步演进、不急于求成” 的 BSD 工程哲学——Rust 进入 base、pkgbase 成为默认等变化都经过多年讨论与测试后才会落地

**辨析**：**截至 2026 年 7 月 19 日，15.2 及以后的 15.x 小版本尚未发布，具体发布日期与特性集均未确定**——本节所述 15.2+ 时间线与特性均为基于 FreeBSD 发布工程惯例的合理推测，不构成官方承诺；Rust 进入 base system 的讨论自 Alan Somers 2024.1 提出以来持续两年多，截至 2026.7 仍未达成共识，16.0 是否包含 Rust 组件尚无定论

## 162.2.4 15.x 发布周期史料辨析

**要点**：FreeBSD 15.0 原计划发布时间为 2025 年 11 月，因 pkgbase 集成与发布工程流程重构（无 root 构建）的复杂性略有推迟，最终于 12 月 2 日发布；15.1 按常规 6 个月 minor release 节奏于 2026 年 6 月发布；15.0/15.1 的发布工程团队延续了 Colin Percival 自 13.x 以来担任 Release Engineer 的稳定性，Lexi Winter 作为 pkgbase wrangler 是 15.x 周期新增的重要角色；Colin Percival（Tarsnap 创始人、FreeBSD Security Officer 前任）自 2010 年代以来持续主导 FreeBSD 发布工程，其 “保守但可靠” 的发布风格在 15.x 周期延续

  **FreeBSD 历史大版本间隔对照**：

  | 大版本过渡 | 起始版本（发布日期） | 结束版本（发布日期） | 间隔（月） | 备注 |
  |---|---|---|---|---|
  | 11.x → 12.x | 11.0（2016.10，10-10 发布〔原表 2016.09 偏差按 RELEASE 日期订正〕） | 12.0（2018.12） | 约 27 | - |
  | 12.x → 13.x | 12.0（2018.12） | 13.0（2021.04） | 约 28 | - |
  | 13.x → 14.x | 13.0（2021.04） | 14.0（2023.11） | 约 31 | - |
  | 14.x → 15.x | 14.0（2023.11） | 15.0（2025.12） | 约 25 | pkgbase 集成、32 位退役、无 root 构建 |

  > 14.0（2023.11）至 15.0（2025.12）间隔约 25 个月，确实长于历史上 12-18 个月的大版本间隔，但这与 pkgbase 引入、32 位平台退役、无 root 构建等大规模基础设施重构有关，属于 “大重构后首个版本” 的正常延迟。

**史料**：freebsd-releng@ 邮件列表发布时间表与状态更新；Colin Percival 个人博客与发布工程状态报告；各 releng 分支提交历史 ［A］

**史观**：总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕：FreeBSD 发布公告的固定格式（Date 行、Highlights、Dedication、Availability、Download、Support、Acknowledgments、Checksums）自 4.x/5.x 时代以来已高度形式化，15.0/15.1 公告严格遵循这一格式；这种形式化不是僵化，而是工程可预测性的保证——用户与系统管理员看到公告的结构就能迅速找到关键信息

**辨析**：关于 “FreeBSD 发布节奏变慢” 的批评需客观看待——14.0（2023.11）至 15.0（2025.12）间隔约 25 个月，确实长于历史上 12-18 个月的大版本间隔，但这与 pkgbase 引入、32 位平台退役、无 root 构建等大规模基础设施重构有关，属于 “大重构后首个版本” 的正常延迟；12.x-13.x（2018.12-2021.4，28 个月）和 11.x-12.x（2016.9-2018.12，27 个月）的间隔也类似
