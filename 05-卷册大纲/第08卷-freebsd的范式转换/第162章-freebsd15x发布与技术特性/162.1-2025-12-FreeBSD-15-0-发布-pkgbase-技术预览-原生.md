# 161.1 2025.12 FreeBSD 15.0 发布——pkgbase 技术预览、原生 inotify 与 32 位平台正式退役

## 161.1.1 FreeBSD 15.0 发布特性集与工程语境
  - 要点：FreeBSD 15.0-RELEASE 于 **2025 年 12 月 2 日** 由 Release Engineering Team 正式发布（Release Engineer 为 Colin Percival），是 stable/15 分支的首个版本；15.0 是 FreeBSD 历史上首个 **不为 i386、armv6、32 位 powerpc 提供 RELEASE 安装镜像** 的大版本，标志着 FreeBSD 正式进入 64 位纯净时代；15.0 开发周期自 14.0 于 2023 年 11 月发布后历时约两年，集成了大量基础设施改进；15.0 支持架构为 **amd64、aarch64、armv7、powerpc64、powerpc64le、riscv64**（armv7 为最后保留的 32 位 Tier 2 平台）；15.0 的一项里程碑式工程成就是：**所有发布制品（安装镜像、VM 镜像等）均无需 root 权限构建**，这为可重现构建与 CI/CD 现代化奠定了基础；15.0-RELEASE 将支持至 **2026 年 9 月 30 日**，整个 15.x 稳定分支将支持至 **2029 年 12 月 31 日**

## 161.1.2 15.0 核心技术特性全景
  - 要点：15.0 带来的核心技术变更包括但不限于：① **pkgbase（打包基础系统）** 作为技术预览引入——基础系统可通过 **pkg(8)** 软件包管理器安装与管理，**bsdinstall(8)** 提供 “Distribution Sets（传统方式）” 与 “Packages（pkgbase 新方式）” 两种安装选项，传统方式计划在 16.0 移除，pkgbase 是 VM 镜像与公有云镜像的默认方式；② **原生 ** inotify(7)** 实现**——不再依赖 Linux 兼容层的 inotify 模拟，原生实现简化了 Linux 桌面应用移植与目录监控；③ OpenZFS 升级至 **2.4.0-rc4**（含 RAIDZ expansion 在线扩容、vdev initialization、fast dedup、zstd 快压缩改进、contiguous dirty dnodes 等长期需求特性）；④ OpenSSL 升级至 **3.5.4 LTS**——支持 QUIC 协议与已标准化的后量子算法（ML-KEM、ML-DSA、SLH-DSA）；⑤ OpenSSH 升级至 **10.0p2**——**默认启用后量子密钥交换**（ML-KEM-512 混合密钥交换），这是主流 OS 中首批默认启用抗量子计算密钥交换的系统之一；⑥ 默认工具链 Clang/LLVM 升级至 **19.x**（15.1 将跟进至更高版本）；⑦ 所有平台（包括 32 位兼容层）完成 **64-bit time_t** 转换，彻底解决 Y2038 问题；⑧ LinuxKPI（Linux Kernel API 兼容层）大幅改进，对齐 Linux 6.x API，以支持从 Linux 移植的现代 GPU 驱动（drm-kmod）与 WiFi 驱动（iwlwifi/rtw88/rtw89）；⑨ KTLS（内核 TLS）TLS 1.3 发送/接收双向卸载默认完善；⑩ **pf(4)** 防火墙改进（syncookie 默认、dummynet 集成等）；⑪ bhyve 虚拟化改进（Intel AMX 支持、更多设备模拟、**p9fs(4)** Plan 9 文件系统共享在 15.1 完善）；⑫ **makefs(8)** 成熟支持 ZFS 镜像无需 root 构建；⑬ **fwget(8)**/**fwctl(8)** 固件管理框架完善；⑭ Linux 兼容层（Linuxulator）改进，支持 Ubuntu 24.04/Debian 12 用户态，Wine/Proton 兼容性持续提升

  - 史观：总纲第 17 条——软件工程：pkgbase 的引入是 FreeBSD 基础系统软件包管理范式的根本转变——自 1993 年以来，FreeBSD 基础系统一直通过 “distribution sets”（tar 分发软件包）与 **freebsd-update(8)** 管理，pkgbase 将基础系统与第三方软件包统一到同一个软件包管理框架下；这一转变的工程意义不亚于 2012 年 **pkg(8)** 取代旧 pkg_* 工具——那次是第三方软件包管理现代化，这次是基础系统本身的软件包管理现代化；无需 root 的构建流程则是现代软件工程 “最小权限原则” 在发布工程中的具体实践
  - 辨析：关于 “默认 shell 从 tcsh 改为 sh” 的说法需精确澄清——14.0 已将 **root 用户默认 shell 从 csh/tcsh 改为 /bin/sh**（BSD Bourne Shell），15.0 延续了这一改变并进一步改进了 /bin/sh 的交互使用体验，但 **并非 15.0 新引入的变化**；**wg(4)** WireGuard 驱动状态——14.0 已集成 **wg(4)** 但未默认编入 GENERIC，15.0 中 **wg(4)** 持续完善但仍需手动加载；OpenZFS 版本为 **2.4.0-rc4** 而非某些来源所说的 2.3——2.4 系列包含 RAIDZ expansion 等 2.3 没有的重大特性，但标记为 rc 表明某些边缘功能仍在稳定化过程中；**后量子密码学默认启用** 是 15.0 最具前瞻性的安全特性——OpenSSH 10.0p2 默认使用 <sntrup761x25519-sha512@openssh.com> 混合密钥交换（结合 X25519 与 ML-KEM-768 近似版本），确保即使量子计算机出现也能保证 SSH 连接的前向安全性

## 161.1.3 LinuxKPI、WiFi 6 与 GPU 驱动——基于 Linux API 兼容层的硬件支持现代化
  - 要点：15.0 中 LinuxKPI（Linux Kernel Programming Interface 兼容层）的大幅改进是 FreeBSD 硬件支持战略的关键转向——通过提供与 Linux 内核 API 兼容的头文件与封装层，FreeBSD 可以相对低成本地移植 Linux 中的现代硬件驱动；15.0/15.1 中基于 LinuxKPI 的驱动包括：① **WiFi 驱动**：**iwlwifi(4)**（Intel WiFi 6/6E）、**rtw88(4)**（Realtek 802.11ac）、**rtw89(4)**（Realtek WiFi 6）、**mt76(4)**（MediaTek WiFi 6）——15.1 中这些驱动已升级至基于 **Linux 7.0** 内核版本；② **GPU 驱动**：drm-kmod 系列包括基于 Linux 5.15 LTS 的 drm-515-kmod 与基于 Linux 6.1 LTS 的 drm-61-kmod，支持 Intel i915（12 代/13 代/14 代核显）、AMD AMDGPU（RDNA 2/RDNA 3 显卡）；③ **网络驱动**：部分现代 10G/25G/100G 网卡驱动通过 LinuxKPI 移植；LinuxKPI 战略使 FreeBSD 能够利用 Linux 生态中庞大的驱动开发资源，而不必为每款新硬件从零编写驱动——这是 FreeBSD 在 Linux 主导硬件驱动生态时代的务实工程选择

  **LinuxKPI 驱动分类**：

  | 类别 | 驱动 | 说明 |
  |---|---|---|
  | WiFi 驱动 | **iwlwifi(4)** | Intel WiFi 6/6E |
  | WiFi 驱动 | **rtw88(4)** | Realtek 802.11ac |
  | WiFi 驱动 | **rtw89(4)** | Realtek WiFi 6 |
  | WiFi 驱动 | **mt76(4)** | MediaTek WiFi 6 |
  | GPU 驱动 | drm-515-kmod | 基于 Linux 5.15 LTS，Intel i915（12-14 代核显） |
  | GPU 驱动 | drm-61-kmod | 基于 Linux 6.1 LTS，AMD AMDGPU（RDNA 2/RDNA 3） |
  | 网络驱动 | 10G/25G/100G 网卡 | 现代高速网卡驱动通过 LinuxKPI 移植 |
  | 15.1 升级 | WiFi 驱动整体 | 升级至基于 **Linux 7.0** 内核版本 |

  - 史料：FreeBSD 15.0/15.1 Release Notes Wireless Networking 与 Device Drivers 章节；freebsd-wireless@ 邮件列表 iwlwifi/rtw88/rtw89 状态更新；drm-kmod 项目（GitHub freebsd/drm-kmod）；FreeBSD Foundation 2024-2026 资助项目列表（LinuxKPI 与 WiFi 驱动为重点资助领域）；Bjoern Zeeb（bz@）、Adrian Chadd（adrian@）等开发者的 LinuxKPI 提交 ［A］
  - 史观：总纲第 6 条——技术路线分化：LinuxKPI 战略不是 “屈服于 Linux” 或 “变成 Linux”，而是在承认 Linux 已成为硬件驱动事实标准生态的前提下，保持 FreeBSD 内核独立性与 BSD 哲学的工程智慧；这与 **netlink(4)** 在 14.0 引入（兼容 Linux 网络配置协议）属于同一思路——不重新发明轮子，在非核心差异化领域兼容生态事实标准，将有限的开发者资源集中在 FreeBSD 真正有差异化优势的领域（ZFS、Jail、bhyve、网络栈性能、小包处理等）
  - 辨析：LinuxKPI 驱动与 “原生 FreeBSD 驱动” 的区别需澄清——基于 LinuxKPI 的驱动在内核中运行，通过 LinuxKPI 兼容层调用 FreeBSD 原生内核功能，性能与稳定性接近原生驱动，但代码来自 Linux 上游；这与 Linuxulator（Linux 二进制兼容层，运行 Linux 用户态程序）性质不同——LinuxKPI 是内核态 API 兼容，Linuxulator 是用户态 ABI 兼容；NVIDIA 专有驱动（nvidia-driver）不使用 LinuxKPI，而是 NVIDIA 官方提供的 FreeBSD 原生内核模块；nouveau（NVIDIA 开源驱动）在 FreeBSD 中的支持仍不完善；WiFi 6E（6GHz 频段）支持在 15.x 中持续完善，具体地区监管域合规需进一步确认

## 161.1.4 15.0 与 14.x 的技术对比与发布工程团队
  - 要点：相较 14.4-RELEASE（2026.3，14.x 最后一个版本），15.0 的核心演进方向可归纳为 “基础系统软件包管理化、64 位平台纯净化、加密后量子化、硬件支持 LinuxKPI 化、构建流程现代化” 五大主题；15.0 发布工程团队由 Colin Percival（Release Engineering Lead，15.0/15.1 Release Engineer）、Ed Maste（埃德·马斯特）（Deputy Lead）、Antoine Brodin（Package Building）、Lexi Winter（pkgbase wrangler）、Xin Li（Security Team Liaison）等组成；15.0 发布前经历了多个 ALPHA/BETA/RC 迭代周期；15.0 发布时同期操作系统生态为：Linux 6.12 LTS（2024.11，sched_ext BPF 调度器）、Linux 6.14（2025.3，Rust for Linux 标记可用于新驱动）、Windows 11 24H2、Windows Server 2025、macOS 15 Sequoia（2024.9）、macOS 16（2025 秋/WD 2026）、OpenBSD 7.7（2025.4）、OpenBSD 7.8（2025.10，修复 27 年 TCP SACK 漏洞）［ 注：依 OpenBSD 半年发布节奏，2026.4 预估已出 7.9，成书前宜复核最新稳定版 ］、NetBSD 10.1（2024.12，现行稳定版）、NetBSD 11.0（截至 2026.7 处于 RC6 阶段未发布）、DragonFly BSD 6.4+

  **15.0 vs 14.4 五大演进主题**：

  | 主题 | 14.4 状态 | 15.0 演进 |
  |---|---|---|
  | 基础系统软件包管理化 | distribution sets 传统方式 | pkgbase 技术预览，VM/云镜像默认 |
  | 64 位平台纯净化 | i386/armv6/32 位 powerpc 仍提供 RELEASE 镜像 | 不再为这些平台提供 RELEASE 镜像 |
  | 加密后量子化 | OpenSSL 3.0/3.5 早期、OpenSSH 9.x | OpenSSL 3.5.4 LTS、OpenSSH 10.0p2 默认 PQC |
  | 硬件支持 LinuxKPI 化 | LinuxKPI 对齐 Linux 5.x | LinuxKPI 对齐 Linux 6.x，15.1 升至 7.0 |
  | 构建流程现代化 | 部分制品仍需 root | 所有发布制品无需 root 构建 |
