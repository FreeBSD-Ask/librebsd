# 186.1.1 年BSD阵营维护rcd的commit总数2289FreeBSD940NetBSD

#### 要点

2010-2026 年 BSD 阵营维护 rc.d 的 commit 总数 2289（FreeBSD 940、NetBSD 566、OpenBSD 574、DragonFly 209），证明 BSD 阵营在 systemd 争议全程持续坚守 rc.d 路径。FreeBSD/OpenBSD/NetBSD/DragonFly BSD 均无公开立场声明——BSD 普遍沉默的技术原因有三：systemd 依赖 Linux 内核特性（cgroups、特定 namespace 行为）无法移植 BSD 内核；BSD 自 2000 年（NetBSD 1.5）/2003 年（FreeBSD 5.0）/2011 年（OpenBSD 4.9）起即有成熟 rc.d 系统；init 之争对 BSD 阵营无实际影响。systemd 争议的不可调和性——革命派（systemd）与改革派（BSD rc.d）的方法论分歧是根本性的，无法通过工程优化解决；但本体论上各方平等——systemd 与 rc.d 各有其工程合理性与局限性。项目史观总纲第 6 条“和解优于斗争”指引——和解不等于妥协或归并，而是“各主体性的呈现与和解”，systemd 与 rc.d 可并存于不同发行版/操作系统，各自演化。

#### 史观

项目史观总纲第 21 条“革命与改革是方法论分歧”在本节叙事中具体体现为：systemd 选择革命路径（推翻 SysV init 重新设计 PID 1 + 整合多功能），BSD rc.d 选择改革路径（持续在 shell 脚本基础上引入 rcorder、rc.subr、依赖排序）——这两种方法论分歧是根本性的，无法通过工程优化解决。systemd 不会“演化”为 rc.d，rc.d 也不会“演化”为 systemd，二者各自遵循自身的工程逻辑。

项目史观总纲第 6 条“和解优于斗争”在本节叙事中具体体现为：和解不等于妥协或归并——systemd 与 rc.d 不会“和解”为统一系统，而是“各主体性的呈现与和解”，systemd 在 Linux 阵营演化，rc.d 在 BSD 阵营演化，二者并存于不同操作系统。BSD 阵营的坚守（2289 个 rc.d 维护 commit）本身即“各主体性的呈现”——BSD 不批评 systemd，亦不采纳 systemd，只是持续维护自身的 rc.d 系统，这种沉默的坚守是“和解”的另一种形式。

项目史观总纲第 8 条“本体论上各方平等”在本节叙事中具体体现为：systemd 与 rc.d 在本体论上地位相等——systemd 有其工程合理性（并行启动、cgroups 集成、容器友好）与局限性（代码规模大、攻击面扩大、单体化事实），rc.d 有其工程合理性（shell 脚本可读、文本配置可编辑、演化稳定）与局限性（串行启动、依赖管理弱、shell 脚本脆弱）。本章禁止“systemd 是 evil”或“rc.d 落后”等道德判断性表述，批评与反批评须对称呈现。

项目史观总纲第 7 条“理论必须自反”在本节叙事中具体体现为：本章叙事承认自身在 systemd 与 rc.d 争议重构中的形式主义化性质——史家将“systemd vs rc.d”建构为“革命 vs 改革”的方法论对立，但这一对立本身是史家选择的分析框架，systemd 与 rc.d 的物理存在本身并不自我宣称为“革命”或“改革”，标签是史家赋予的。本章合图层不强行归并争议，承认争议的不可调和性，这是自反性在叙事中的体现。

#### 项目统摄史观审视（第 13、19、21 条切入）

**第 13 条“法律与道德是利益分配”——许可证哲学维度**：systemd 采用 LGPL 2.1+（仓库根目录 `LICENSE.LGPL2.1`，GNU LESSER GENERAL PUBLIC LICENSE Version 2.1, February 1999），BSD rc.d 采用 BSD 许可证（宽松许可证）。两种许可证代表不同的利益分配机制：LGPL 2.1 要求衍生库源代码公开（copyleft），体现 FSF/Red Hat 的利益分配机制——要求衍生作品回馈源代码，形成“开源-回馈”循环；BSD 许可证允许专有软件使用、修改、闭源，体现 BSD 阵营的利益分配机制——允许任何人自由使用，不强制回馈。Poettering 在《The Biggest Myths》Myth 8 中提到 Upstart 的“licensing/contribution agreement mess”作为放弃 Upstart 的原因之一，暴露了许可证哲学的工具主义态度——许可证作为法律工具，本质上是利益分配的形式主义化（第 13 条“法律与道德是利益分配”）。Poettering 对 Upstart CLA（Canonical 贡献者协议）的批评与对自身 LGPL 2.1+ 的接受并不矛盾，因为二者服务于不同的利益主体：Upstart 的 CLA 服务于 Canonical（要求贡献者将版权转让给 Canonical），systemd 的 LGPL 2.1+ 服务于 FSF/Red Hat（要求衍生库源代码公开）。许可证哲学的分歧本质上是利益分配机制的分歧——BSD 阵营选择宽松许可证（允许任何人自由使用，包括专有软件），Linux 阵营选择 copyleft 许可证（要求衍生作品回馈源代码），二者各有其利益分配逻辑，无“先进 vs 落后”之分。IBM 2018-10-28 宣布以 340 亿美元收购 Red Hat、2019-07-09 完成收购，使 Red Hat 成为 IBM 子公司——商业资本通过雇佣开发者（Poettering 为 Red Hat 员工）推动 systemd 工程化扩张，LGPL 2.1+ 许可证在这一语境下成为商业资本与开源社区之间的利益分配工具，而非纯粹的技术选择。

**第 19 条“解释学循环是历史认识的根本条件”——权力知识共谋维度**：systemd 争议中“现代 init 必然性”话语的建构与解构构成解释学循环——采纳 systemd 后，各发行版 release notes、技术博客、社区讨论逐渐将 systemd 描述为“现代 Linux 的必然选择”，这一话语反过来塑造了新发行版的采纳决策，形成解释学循环。批评方与反批评方的前理解差异使分歧不可避免：systemd 阵营的前理解是“现代 Linux 需要并行启动 + cgroups 集成 + 容器友好”，BSD 阵营的前理解是“shell 脚本可读 + 文本配置可编辑 + 演化稳定”。前理解差异不是“谁对谁错”的问题，而是“不同主体性的呈现”。权力与知识在 systemd 争议史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使（第 19 条“权力与知识在历史书写中共谋”）。systemd 仓库的 90,782 commits 被详细记录，BSD rc.d 的 2,289 个维护 commit（2010-2026）在 systemd 争议期间被主流技术媒体忽视；Poettering 的《The Biggest Myths》博客被广泛传播，批评方的再回应（如 Roger Leigh 的批评信、Veteran Unix Admins 的 fork 公告）却很少被主流技术媒体引用；Debian CTTE 4:4 平局后 Bdale Garbee 投决定性票通过 systemd 这一偶然性事件被主流叙事建构为“技术必然”，而 Ian Jackson 辞职、Devuan fork 等抵抗事件被边缘化。这种记录与遗忘的不对称本身就是权力行使——systemd 作为“胜利者”获得了历史书写的主导权，BSD rc.d 作为“沉默者”的历史贡献被低估。本章叙事承认自身亦参与这一权力知识共谋——史家选择将 systemd 与 rc.d 并置审视，本身是权力行使的一种形式，无法超越解释学循环。

**第 21 条“革命与改革是方法论分歧”——革命路径与改革路径的不可调和维度**：systemd 选择革命路径——不改造 SysV init 而是从 PID 1 重新设计，且明确将日志、网络、DNS、时间同步等功能整合进同一代码库，这一路径的工程代价是代码规模膨胀（1,111,090 行）、攻击面扩大（经 NVD 一手验证的 5 个 CVE）、运行时耦合加深（`shared` 库被所有二进制链接）；BSD rc.d 选择改革路径——持续在 shell 脚本基础上引入 rcorder、rc.subr、依赖排序，自 NetBSD 1.5（2000）至 FreeBSD 5.0（2003）至 OpenBSD 4.9（2011）至 DragonFly BSD（2003）逐步演化，这一路径的工程代价是串行启动、依赖管理弱、shell 脚本脆弱。第 21 条“革命与改革是方法论分歧”在此体现为：两条路径各有其工程合理性与局限性，分歧是根本性的——systemd 不会“演化”为 rc.d，rc.d 也不会“演化”为 systemd，二者各自遵循自身的工程逻辑。革命路径的优势是“从零设计”可摆脱历史包袱（Poettering 在《Rethinking PID 1》中直陈 SysV init 的串行性与依赖管理混乱），劣势是“推倒重来”带来代码规模与攻击面的扩张；改革路径的优势是“持续演化”保持向后兼容与稳定（BSD rc.d 自 2000 年至 2026 年 2,289 个维护 commit 的连续性），劣势是“渐进改良”难以根本解决 shell 脚本的固有局限。方法论分歧不可调和——这不是“谁对谁错”的工程判断，而是“不同主体性的呈现”：systemd 的革命路径体现 Linux 阵营“推翻重来”的工程文化，BSD rc.d 的改革路径体现 BSD 阵营“持续演化”的工程文化，二者各有其历史脉络与社区共识，无法通过工程优化或话语辩论解决。

**合图层结论——争议的不可调和性与和解路径**：systemd 与 BSD rc.d 的争议不可调和——方法论分歧（第 21 条：革命 vs 改革）+ 许可证哲学分歧（第 13 条：LGPL copyleft vs BSD 宽松）+ 解释学循环（第 19 条：前理解差异 + 权力知识共谋）三者叠加，使争议无法通过工程优化或话语辩论解决。但本体论上各方平等（第 8 条）——systemd 与 rc.d 各有其工程合理性与局限性，二者并存于不同操作系统是“各主体性的呈现与和解”（第 6 条）。和解不等于妥协或归并——systemd 在 Linux 阵营演化，rc.d 在 BSD 阵营演化，二者并存于不同操作系统。本章合图层承认争议的不可调和性，同时指出和解路径：不是“谁说服谁”，而是“各主体性的呈现与和解”——这是第 6 条“和解优于斗争”在 systemd 争议中的具体指引。

#### 辨析

“BSD 阵营坚守 rc.d”的判断须有具体 commit 数据支持——`bsd_init_db_report.md` 查询 6 提供 2289 个 commit 总数（2010-2026），但须注意：(1) commit 量仅反映开发活跃度，不等于 rc.d 系统质量；(2) FreeBSD 2019 年后 commit 骤降与 SVN-to-Git 迁移有关，非 rc.d 维护停止；(3) 早期 svn-to-git 迁移可能合并为单次 commit，2003 年前的数据须谨慎使用；(4) 2010-2026 年维护统计须排除纯格式化、批量重命名等非功能性 commit，须人工抽样核查 `message_subject`。

BSD 各项目“无公开立场声明”的判断须谨慎——“未找到”不等于“不存在”，仅表示本次考据范围内未发现。检索限制：(1) FreeBSD 仅检索了 `freebsd-hackers` 邮件列表 5 个月的 thread subject，未检索邮件正文，未覆盖 systemd 争议全部时段（2011-2016）；(2) OpenBSD `marc.info` 检索接口不稳定，undeadly.org 触发反爬虫 CAPTCHA；(3) NetBSD Board 与 DragonFly BSD Matt Dillon 的检索范围有限。可能的解释：BSD 项目对 systemd 沉默是技术原因（systemd 不可移植、BSD 已有 rc.d、init 之争对 BSD 无影响），非政治原因。本节禁止臆测任何 BSD 项目或个人对 systemd 的“隐含立场”。

“systemd 争议不可调和”的判断须辨析——方法论分歧（革命 vs 改革）是不可调和的，但工程层面的相互借鉴是可能的（如 systemd 借鉴 rc.d 的依赖排序理念，rc.d 借鉴 systemd 的并行启动尝试）。本节采信“方法论分歧不可调和 + 工程层面可相互借鉴”的双层判断。
