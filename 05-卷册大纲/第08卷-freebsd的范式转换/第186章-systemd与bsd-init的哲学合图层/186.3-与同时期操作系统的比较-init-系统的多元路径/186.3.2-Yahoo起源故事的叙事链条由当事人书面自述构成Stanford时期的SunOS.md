# 186.3.2 Yahoo起源故事的叙事链条由当事人书面自述构成Stanford时期的SunOS

- Yahoo 起源故事的叙事链条由当事人书面自述构成：Stanford 时期的 SunOS 机器无法承受不断膨胀的 HTTP 请求，团队先后测试 IRIX、Linux 与 BSDi 均因性能与稳定性不佳而放弃，最终从网站下载软盘启动镜像安装 FreeBSD，数日内即有可用系统并加入 web 服务器集群，当事人自述“几周的实验之后，我们被说服了”（956.14-958.82），此后 FreeBSD 成为 Yahoo 生产与开发环境的专属平台。（BSD Now EP118，[787.20-998.66]，L2）
- Mark Heily 在访谈中自述 relaunchd 的动机与路线：受 Jordan Hubbard 等人 NextBSD 计划将 launchd 引入开源世界的消息触动，但认为 launchd 深度依赖 Mach IPC、移植性差且外围依赖链复杂，遂决定从零实现可移植版本，配置由 XML 转为 JSON，主张“init 系统应当非常简单、易于理解”（1911.12-1918.10）；原型先用 Ruby 数日完成验证，因社区反馈不愿以 Ruby 进程充当 PID 1 而改写为 C，并把原型阶段视为理解 launchd 各部件如何协作的教学过程。（BSD Now EP118，[1799.46-2040.72]，L1）
- VBSDCon 2015 由 VeriSign 主办，于 9 月 11 日至 13 日在弗吉尼亚州 Reston 的 Sheraton 酒店举行，票价 100 美元、规模限制约 125 人；其定位有三：美国东海岸唯一的大型 BSD 会议、聚焦在敌对条件下支撑互联网运行的关键基础设施、面向系统管理员与运维团队而非开发者。VeriSign 采用邀请制遴选演讲者而非公开征稿，并刻意给 FreeBSD、OpenBSD、NetBSD 三个社区以大体均衡的议程曝光；2015 届改进包括专业级录像、以闪电演讲取代上一届的 speed geeking 环节、以及把会场移近餐馆密集的 Reston Town Center。（BSD Now EP105，[1225.42-1324.68]，L1）
- 本期标题所指的 1980 年代线索来自嘉宾 Scott Courtney 的自述：他于 20 世纪 80 年代半途接手一台运行 SVR3 的 AT&T 3B2 服务器的系统管理员工作而入行 Unix，此后经 Solaris 等商业 Unix 接触到源自 BSD 的 TCP/IP 等特性；约在 2015 年前的六七年，他在 VeriSign 主管架构时，因 .com 域名平台与根 DNS 产品在攻击负载下的可扩展性瓶颈而转向 FreeBSD，并采取 FreeBSD 与某一 Linux 变体并行的异构部署策略以对冲零日漏洞风险。（BSD Now EP105，[1054.36-1119.66]，L1）
- OpenBSD 在本期呈三线推进：其一，tame() 用户态集成由 Theo de Raadt 以百余个小 diff 的形式落地，多数程序仅两三行改动，路径白名单留待后续；其二，UEFI 与 GPT 初始支持开始合入，帧缓冲结构暴露给 wsdisplay 后端，GPT 重构将取代为绕过 MBR 单盘 2 TB 限制而设的 disklabel 变通，UEFI-only 的设备（如 VIO-Z Canvas）由此获得启动 OpenBSD 的可能；其三，LibreSSL 自上游开始禁用 SSLv3，先从 openssl 命令行工具关闭，ports 中的 Apache 等依赖仍待适配，IETF 亦有禁用 SSLv3 的 RFC 草案在途；同一周内 FreeBSD 的多路径 TCP 0.5 补丁集与 DragonFly 的 Intel 显卡更新共同构成 2015 年 9 月初的跨分支技术图景。（BSD Now EP105，[2680.64-2822.08]，L3）
- No Starch Press 与 BSD 社区的纽带始于 Michael Lucas 书系：Absolute BSD 广受社区好评，Absolute OpenBSD 一脉相承，Absolute FreeBSD 第二版令人期待；Lucas 身为开发者兼 committer，其书以社区同侪深度评审著称——同侪建言、充实章节，显著提升了成书质量；Peter Hansteen 的 The Book of PF 则由其在各 BSD 会议的教程与线上教程扩编而来，会议教学被验证有效后转为书籍构想，经扩展改编成书。（BSDTalk EP145，[185.08-254.40]，L1）
- The Book of PF 的评审闭环在两三个月内完成：技术评审由 PF 核心开发者 Henning Brauer 担纲，其专业与响应速度俱佳；因书中含 FreeBSD 与 NetBSD 的 PF 配置且此部分准确性攸关，Brauer 主动建议引入对两平台更活跃者把关，遂请 Greg Lehey 复核配置，获其首肯后方告定稿；终稿送 OpenBSD Foundation，由 Theo de Raadt 审读并给予信任背书，Bob Beck 撰序并着意突出 OpenBSD 在 PF 发展中的角色。（BSDTalk EP145，[259.56-345.76]，L1）
- 出版路线图：在版书稿为 Building a Server with FreeBSD 7，采自助餐式组章——读者不求 Michael Lucas 式的内核内幕，只想为个人网站或小型数据库架服务器，可按项目自选章节、按需扩展；拟约选题有二：高可用 BSD 服务器（Peter 似已认领）与 BSD 内核开发书——对标已获成功的 Linux 内核开发书，并作为 Joseph Kong 设计 BSD rootkit 一书（2007 年出版）的互补；公开征稿经 nostarch.com 提案表或编辑邮箱。 [存疑脚注] 作者名转写 Brian Hong 之姓氏待核；牵线人 Drew Levine 身份待考（BSDTalk EP145，[345.76-437.66]，L1）
- 主持人 Will 的教学叙事构成对 init 多元路径的同期证词：新人学员被某 Linux 发行版的启动脚本绕晕，他备好 System V 运行级与 chkconfig 的讲稿，却发现该发行版已弃用旧法改采事件驱动的 upstart——插上网卡即按事件自动响应；他承认 upstart 愿景有其道理，但对初学者而言讲解吃力，转而展示 BSD：rc.conf 单一文件对服务逐项回答 yes 或 no，服务器场景下恰如其分，由此赞叹 BSD 的一致性与简洁对新人友善。（BSDTalk EP145，[80.64-163.76]，L1）

**史观**：

- 总纲9 经验优先：Yahoo 采纳 FreeBSD 的决策过程是经验优先的典型样本：价格固然诱人，但当事人明言决定性因素是稳定性、性能与源代码可得性；关键判据不是基准测试而是日常运维事实——核心 Perl 脚本在 Linux 上反复崩溃而在 FreeBSD 上持续运行（1149.90-1170.77），动手运维者以自身经验完成裁决，任何理论性的操作系统优劣论证在此都退居其次。（BSD Now EP118，[962.62-1170.77]，L2）
- 总纲5 没有必然性，只有偶然性：Yahoo 与 FreeBSD 的结缘并无技术必然性可言：当事人自述当时公司无人了解 FreeBSD，只是“看到相关引用后决定一试”（849.54-858.54），一次偶然尝试叠加 Perl 崩溃差异的偶然事实，偶然地奠定了门户时代最大站点之一的生产基座；此后多次迁移计划均未完成，Yahoo.com 首页至 2015 年仍由 FreeBSD 服务，历史路径由偶然而非规律写成。（BSD Now EP118，[849.54-998.66]，L2）
- 总纲10 动手者创造历史：全期的叙事重心置于不显眼的劳作之上：主持人称赞 LibreSSL 移除 SSLv3 与 Tarsnap 安全赏金这类“吃力不讨好的工作”（2442.82-2445.26），指出删除特性并承受其连锁反应是不被看见的贡献，正因如此才要感谢源码树后的清理者；节目又在两周年之际向幕后编者 TJ 致敬，将其每周整理的 show notes 与选题组织确认为节目得以存在的隐形基底——书写对象由此从发布会与版本号转向维持系统运转的动手者。（BSD Now EP105，[2442.82-2464.44]，L2）
- 总纲8 本体论上各方平等：各 BSD 分支在同一时段的多线并进构成本体论平等的经验呈现：DragonFly BSD 合入 Linux 3.17 的 Intel 显卡栈更新并辅以 3.19 的稳定性修复，其图形进度反令 FreeBSD 侧主持人自嘲羡慕；OpenBSD 独立推进 tame() 沙箱、UEFI 启动与 SSLv3 清除；FreeBSD 侧则以 bhyve、多路径 TCP 补丁集与 11 CURRENT 应对——没有任何单一分支被叙述为普遍进步的主线，呈现的只是不同努力在各自曲线上的流转。（BSD Now EP105，[740.84-749.74]，L2）
- 总纲10 动手者创造历史：BSD 图书的生产方式本身即是动手者共同体的实践：作者多为 committer 或教程实践者，评审者为项目核心开发者，审定权部分落在项目基础机构（如 OpenBSD Foundation 审读背书）——出版不是外在于社区的产业链，而是动手者彼此校验、共同署名的延伸。（BSDTalk EP145，[210.72-228.88]，L1）
- 总纲21 革命与改革是历史方法论的分歧：Will 的对照呈现两种系统演化方法的分岔：Linux 侧以 upstart 一类新范式整体替换运行级传统，能力跃进而教学连续性断裂；BSD 侧守成 rc.conf 的声明式简明，牺牲部分自动化想象而保住一致性与可授性——革命与改革之别在服务管理的日常教学中显影。（BSDTalk EP145，[111.12-148.92]，L1）

**辨析**：

- 主持人补充的后续线索称 Yahoo 内部长期运行拼装混合的私有分支，掺杂 4.x、7.x 与 11.x 的代码片段，并流传 FreeBSD 4 二进制源码遗失、只能靠旧快照二进制维持运转的轶事（1197.18-1256.62）；该线索指向大公司私有分支与上游社区脱节的典型现象，但细节全凭转述与道听途说，不能作为直接史实引用。 [存疑脚注] YahooBSD 混合版本构成与 FreeBSD 4 二进制源码遗失轶事仅来自主持人转述 Hacker News 讨论及个人见闻，具体版本号与 Peter Wemm 快照故事细节均无一手文献佐证，本卡仅作线索存档（BSD Now EP118，[1197.18-1256.62]，L4）
- 访谈现场即时暴露了 relaunchd 的工程张力：主持人 Alan 当场指出以 system 拼接用户输入调用 rm 的命令注入风险与用 asprintf 拼出 shell 命令建目录的做法（2113.96-2124.72），Heily 承认初期 C 代码存在粗糙之处并明确警告不宜用于生产（2097.08-2104.40）；jail 内 socket 继承以免除 NAT 的设计被追问与 Capsicum 先初始化后锁定的权限模型存在冲突（2483.76-2527.08），说明把沙箱语义编入 init 配置在 2015 年仍是未经实践检验的新概念。（BSD Now EP118，[2061.88-2527.08]，L2）
- Syncthing 事件呈现边缘社区在数据时代的可见性困境：匿名使用统计默认关闭，而 OpenBSD 用户的隐私文化使其更倾向拒绝上报，项目方据“只有三名 OpenBSD 用户”的统计关闭了 /proc 路径错误的跨平台 bug 报告并让用户自行提交补丁（3737.82-3743.26）；博客作者随后开启自有全部机器的上报使 OpenBSD 用户数即时翻倍（3842.42-3847.54），计数基础设施的统计失真与社区“以可见性对抗不可见性”的抗争策略在同一事件中并置。（BSD Now EP118，[3686.46-3847.54]，L2）
- 本期最具考据价值的片段是当事人自纠：听众 Mason 来信指认主持人在上期约 1 小时 56 分钟处声称 X 进入基本系统的最大障碍是许可证不利于 BSD，并指出 X 许可证与 BSD 许可证几乎无异、NetBSD 与 OpenBSD 携带 X 已近二十年；Allan Jude 随即更正，澄清真正的障碍并非许可证，而是 FreeBSD 项目不愿为跨 FreeBSD 10 的五年生命周期维持 ABI 稳定而在基本系统内维护 X 的分支，X 的定位始终是 port；他同时透露 FreeBSD 正延续将组件移出基本系统的路线——Perl 自 FreeBSD 4 起已移除，OpenSSL 拟改为仅内部私用、用户态依赖自 ports 获取以加快补丁节奏。（BSD Now EP105，[3272.78-3362.70]，L1）
- 围绕 NextBSD 移植 LaunchD 的争议呈现流言与澄清的典型结构：一篇评论文章主张 FreeBSD 不应采用 LaunchD，Reddit 上正反意见交锋并引来大量社区邮件；Allan Jude 澄清所谓 XML 配置的恐惧源自过去某设备厂商对 launchd2 的 FreeBSD 移植，而 NextBSD 实际使用的版本改用 JSON 且更为精简，提醒听众核对正确版本再作评判；工程层面，Kip Macy 正在修复安装器以便发布可试用的 NextBSD ISO，Jordan Hubbard 与 Kip Macy 均已同意接受访谈但需待 EuroBSDCon 之后，PC-BSD 下一版将基于 FreeBSD 11 CURRENT 与 NextBSD 构建并集成 launchd，且计划按月发布镜像、或与 HardenedBSD 合流。（BSD Now EP105，[589.64-628.86]，L2）
- 转写人名须校正：The Book of PF 作者应作 Peter Hansteen（转写 Hensstein），技术评审应作 Henning Brauer（转写 Brower），跨平台复核者应作 Greg Lehey（转写 Lehy）；Will 所述 upstart 案例未指明具体发行版，无从核验其版本细节；对 No Starch 选题计划的陈述属 2008 年 4 月时点的意向，成书与否须以实际出版记录复核。（BSDTalk EP145，[234.56-238.84]，L2）
