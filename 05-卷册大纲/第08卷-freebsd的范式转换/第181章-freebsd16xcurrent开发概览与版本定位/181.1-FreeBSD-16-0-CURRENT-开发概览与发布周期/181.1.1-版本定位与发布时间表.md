# 181.1.1 版本定位与发布时间表

**要点**：截至 2026 年 7 月，FreeBSD 16.0-RELEASE 尚未发布，预计 2027 年 12 月正式发布；当前 main 分支为 16.0-CURRENT 活跃开发分支，15.x 系列为最新 STABLE 分支（15.1 于 2026 年 6 月 16 日发布），14.x 系列为生产环境 LEGACY 分支（14.4 于 2026 年 3 月 10 日发布）；16.x 系列将延续 FreeBSD 自 10.0 以来约两年一个主要版本的发布节奏，是自 15.0（2025 年 12 月 2 日发布）之后的下一个主要版本分支

  **FreeBSD 当前分支状态（截至 2026.7）**：

  | 分支系列 | 角色 | 最新版本 | 发布日期 |
  |---|---|---|---|
  | 16.x | CURRENT 开发分支 | 16.0-CURRENT | 预计 2027.12 |
  | 15.x | 最新 STABLE 分支 | 15.1 | 2026.6.16 |
  | 14.x | 生产环境 LEGACY 分支 | 14.4 | 2026.3.10 |
  | 15.0 | 前一主要版本 | 15.0-RELEASE | 2025.12.2 |

GROUP BY month`）获取月度趋势；(4) L1.1.1 查询覆盖 freebsd-src 单仓库，未含 ports/doc 等其他仓库；**16.0-CURRENT 开发节奏参照**：15.0-RELEASE 于 2025-12-02 发布后，main 分支进入 16.0-CURRENT 开发阶段，截至 2026-07-21 查询时已运行约 8 个月；Cluster Administration Team 2026Q1 状态报告显示集群已有 42 台物理机运行 16.x（CURRENT）快照、6 个 jail 运行 CURRENT，反映 16.0-CURRENT 开发与测试基础设施已建立但尚未进入代码冻结阶段 ［A］

**史观**：总纲第 2 条——历史是形式主义化的非存在（存疑）〔订正注：原挂“总纲第 3 条——形式主义膨胀”系伪标签，权威第 3 条为“不存在进步，只有权力再分配”，按论旨改挂第 2 条〕：FreeBSD 严格的发布周期和版本编号体系本身就是形式主义工程哲学的体现，CURRENT/STABLE/RELEASE 三分支模型将“开发中”与“稳定”的边界以版本号形式进行形式化划分

**辨析**：必须严格区分“16.0-CURRENT 分支已合入”与“FreeBSD 16.0 已发布”两个概念；截至 2026 年 7 月，所有 16.x 相关变更均在 main 分支（16.0-CURRENT）进行，不得表述为“FreeBSD 16.0 已实现”或“FreeBSD 16 已发布”；releng 页面时间表为目标日期，实际发布日期可能因工程进度调整。**数据库验证结论**：15.1/15.0/14.4 三个 release tag 的 tagger_date 均早于公开公告日期 4 日，偏差一致，反映 FreeBSD Git 时代发布工程的稳定节奏（commit-tag 同步创建、UTC 标准化时区标记）；0 信任原则提示：三个 tag 均为 Git 时代原生 annotated tag，tagger_date 与 target_commit_date 均为原生 Git 元数据，可信度高；Colin Percival 同时为三个 tag 的 tagger 与 Release Engineer Lead，身份一致性验证通过；15.1 的 target_commit_date 与 tagger_date 时差约 6 小时 22 分钟（跨时区，commit 在 PDT，tag 在 UTC），15.0 与 14.4 的 target_commit_date 与 tagger_date 完全一致（均为 UTC）；**16.0 tag 缺失的辨析**：经 `freebsd.duckdb` 查询未得 `release/16.0.0` tag（截至 2026-07-21 查询时），此结论与 FreeBSD 官方 releng 页面时间表“December 2027: FreeBSD 16.0”一致，验证 16.0 尚处于 CURRENT 开发阶段的客观状态；0 信任原则提示：16.0 tag 缺失不是“FreeBSD 项目放弃 16.0”，而是发布时间未到的正常现象，不应作任何“16.0 取消”或“16.0 跳票”的推论
