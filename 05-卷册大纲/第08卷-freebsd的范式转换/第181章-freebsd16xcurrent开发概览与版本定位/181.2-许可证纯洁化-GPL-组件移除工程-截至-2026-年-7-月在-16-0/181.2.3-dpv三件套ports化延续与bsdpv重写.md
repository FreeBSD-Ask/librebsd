# 181.2.3 dpv 三件套 Ports 化延续与 bsdpv 重写

**要点**：在 base system 移除 dialog/dpv/libdpv/libfigpar 之前，相关组件已预先在 Ports 集合中创建以延续功能：devel/libfigpar、devel/libdpv、sysutils/dpv 三个新 ports 于 2026 年 6 月 29-30 日创建，devel/libfigpar 与 devel/libdpv 维护者为 Devin Teske（<dteske@FreeBSD.org>），sysutils/dpv 维护者为 Dag-Erling Smørgrav（<des@FreeBSD.org>）〔订正注：原误作三件套维护者均为 Devin Teske，与 166.2.6 辨析修正同步〕，许可证为 BSD-2-Clause；同时存在在 bsddialog 之上重写 dpv 为 bsdpv 的工程（审查票类似 D58133），将公共 API 从 dpv_*重命名为 bsdpv_* 以标记与 GNU dialog 依赖的彻底决裂，并修复原 dpv 的若干 bug；该“先 port 化延续、再 base 移除、再 BSD 许可重写”模式是 FreeBSD 渐进式淘汰工程哲学的体现

**史料**：FreeBSD FreshPorts 记录（devel/libfigpar、devel/libdpv、sysutils/dpv 三个 ports 添加时间 2026 年 6 月 30 日前后，维护者 dteske）、FreeBSD Phabricator/Reviews 相关审查票（ports 创建审查、bsdpv 重写审查）、类似 14.0 net/freebsd-telnetd、15.0 ftp/freebsd-ftpd 的“port 接续”模式历史记录 ［A］

**史观**：终结与延续〔订正注：原误挂总纲第 25 条，权威 25=逻辑是形式主义而非世界本身的结构，去号〕：FreeBSD 从未采用“一刀切”式淘汰策略，而是遵循“引入替代 → 验证成熟 →port 化延续 →base 移除 → 原生重写”的渐进路径；这一路径既保证了许可证纯洁化目标的实现，又最大限度减少了对现有用户的破坏

**辨析**：ports 创建时间（2026 年 6 月底）早于 base 移除时间（2026 年 7 月），表明该工程是事先规划而非临时补救；bsdpv 重写工程截至 2026 年 7 月可能处于审查或已提交但尚未完全稳定状态，是否最终合入 16.0-RELEASE 仍需以 RELEASE 时的源码状态为准；dpv 等工具属于较为边缘的系统工具，多数普通用户可能不会直接使用，但作为系统组件的延续体现了对兼容性的重视
