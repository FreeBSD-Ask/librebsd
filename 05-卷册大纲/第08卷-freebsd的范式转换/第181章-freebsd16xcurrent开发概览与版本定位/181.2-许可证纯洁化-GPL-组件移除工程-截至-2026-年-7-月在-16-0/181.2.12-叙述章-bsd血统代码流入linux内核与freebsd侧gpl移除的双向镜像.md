# 181.2.12 叙述章——BSD 血统代码流入 Linux 内核与 FreeBSD 侧 GPL 移除的双向镜像

2003 年 8 月，Christoph Hellwig 在 linux-scsi 列表讨论 scsi_mid_low_api.txt 文档许可证时留下维护者共识 we agreed that GFDL is not suitable，Douglas Gilbert 将其 SCSI 文档从 GNU 自由文档许可证改为 GPL 兼容条款；这一事件在 GPLv3 争议发酵前已埋下 GPL 阵营对文档许可证形态的关注。2004 年 2 月，Paul E. McKenney 在 linux-mm 关于 invalidate_mmap_range 非 GPL 导出之争中做了一次全盘托出 in the spirit of full disclosure, the wrapper is actually distributed under the bsd license，同时澄清 GPFS 工程师口中的 gpl 实为 gpfs portability layer 缩写，许可证由此首次以技术实体身份进入内核合法性论证

2005-2006 年 BSD 血统代码开始以零散补丁形式渗入 Linux 内核。2005 年 8 月，Patrick McHardy 在 ppp SC_MUST_COMPRESS 补丁中把 if_ppp.h 注释整体替换为 CMU 来源的 BSD 许可证文本，立即招致追问 Why do you change the license, especially to something GPL-incompatible?，BSD 许可证作为 GPL 替代物的争论从 SCSI 文档一路延伸到网络协议栈。2005 年 11 月，Jiri Slaby 在 ath5k 崩溃线程中指出 madwifi goes through ported bsd net80211；2006 年 8 月，Michael Wu 在 Linux 802.11x 支持差距讨论中转述 madwifi has a fairly complete 802.11 stack, ported from netbsd。

BSD 血统代码此后在 Linux 内核中不断加深渗透。Sowmini Varadhan 两次指出 struct ip is a BSD-ism, intended to be used if you were porting some BSD app，把 Linux 内核中的 struct ip 定性为仅为可移植性垫片；2011 年 8 月，Adrian Chadd 在 BQL 缓冲讨论中同时维护两端 I'm porting the atheros 802.11n TX aggregation code to FreeBSD；2013 年 4 月，Vegard Nossum 质疑 Kconfig 帮助文本时留下 IPsec tools ported from KAME，其底层 PF_KEY socket family compatible to KAME ones，KAME 源自 FreeBSD 与 NetBSD 的谱系由此确认；2007 年 Rick Jones 把 Linux 的 ip_local_port_range 小值区间归为 variations on the old BSD defaults theme，BSD 血统代码已渗入网络子系统的默认值层

2016 年 8 月 Linux Kernel Summit 上，GPL 阵营的立场在 BSD 迁移面前显性化。Greg Kroah-Hartman 反对 Bradley Kuhn 把诉讼作为唯一出路 If you don't defend the GPL in courts, we need to give up on it，援引 BusyBox 诉讼催生 Toybox、LLVM 因规避 FSF 与 GPLv3 而生的案例；两天后 Guenter Roeck 援引前雇主经历指 most new projects ended up using BSD or Apache licenses to avoid the pitfalls of GPL，GPL 阵营的公开表态与 BSD 迁移的实证首次在同一场会议中被并列陈述。同一时期 BSD 血统代码在内核中的可见度亦达高峰：2016 年 11 月 John W. Linville 在 wireless-next 拉取请求中点名 addition of the ar5523 driver, ported from an original FreeBSD driver，2016 年 7 月 Dexuan Cui 的 Hyper-V VM Sockets AF_HYPERV cover letter 明确 by the traditional BSD-style socket APIs，新传输层被定位为 BSD socket 语义之上以保持应用可移植性

2020 年代 BSD 可移植性成为内核 UAPI 改动的隐性约束条件。2020 年 8 月，James Bottomley 在 IPE/IMA 元数据能否进入 NFS 标准及 IETF 规范之争中反驳 Chuck Lever 关于 GPL 束缚格式的说法，界定贡献路径的法律边界 IETF contributions occur under a BSD-style license incompatible with the GPL，GPL 是代码许可证而非数据或文档许可证；2022 年 3 月，Carlos Llamas 为 FUSE UAPI 整数类型提议 BSD 可移植垫片 the best way to accommodate this while still conforming with the __u32 types，援引 DRM 先例 commit 1a95916f5465；2026 年 1 月，Bernd Schubert 与 Arnd Bergmann 以 BSD 用户态为 FUSE UAPI 改动的可移植性测试台，前者称 I would expect the patch to not have changed anything for BSD，后者澄清 not defining __linux__ makes it use the stdint types after all；2021 年 7 月，Tom Herbert 反驳 AF_PACKET 校验和卸载的可移植性担忧，称 The portability to BSD for AF_PACKET is a non-issue，BSD 侧行为差异在 Linux 生态内被显式判定不构成阻碍

与此同时 FreeBSD 16.0-CURRENT 分支正在执行反向的许可证工程。2026 年 6 月 30 日，Dag-Erling Smørgrav 创建 devel/libfigpar、devel/libdpv、sysutils/dpv 三个 ports（commits 10594b0、f6a8a82、278661a）作为 base system 移除的前置延续；随后 2026 年 7 月，dialog/dpv/libdpv/libfigpar 从 base 移除，专用 gnu/ 目录整体退役，Phoronix 于 7 月 15 日首发、Linuxiac 于 7 月 17 日深度报道、IT 之家于 7 月 18 日中文转载三源交叉印证 FreeBSD Base System No Longer Contains Any GPL-Licensed Software；从 GCC 到 Clang、从 GNU grep 到 bsdgrep、从 GNU binutils 到 LLVM、从 GNU dialog 到 bsddialog，这一十余年的渐进替代在 16.0-CURRENT 完成最后一环

从 2003 年 Christoph Hellwig 的 we agreed that GFDL is 起，BSD 血统代码沿 SCSI、网络、无线、文件系统、内存管理、UAPI 六条路径渗入 Linux 内核；而从 2007-2010 年 GPLv3 争议起，FreeBSD 侧沿 GCC→Clang、dialog→bsddialog、gnu/ 目录退役完成 GPL 清零；这两个方向的工程看似分立，实为同一历史时刻的双向镜像——Linux 内核中 BSD 血统代码的规模恰是 FreeBSD 侧许可证纯洁化的外部支撑条件，两者共同印证了跨越三十余年的许可证与血统迁移的历史脉络
