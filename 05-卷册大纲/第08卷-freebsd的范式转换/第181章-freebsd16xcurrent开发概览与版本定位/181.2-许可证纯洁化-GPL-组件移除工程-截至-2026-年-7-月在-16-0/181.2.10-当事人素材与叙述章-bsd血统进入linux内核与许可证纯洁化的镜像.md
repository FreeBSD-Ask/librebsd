# 181.2.10 当事人素材与叙述章——BSD 血统进入 Linux 内核与许可证纯洁化的镜像

2003 年 8 月，Douglas Gilbert 主持维护的 scsi_mid_low_api.txt 文档卷入一场许可证事件，维护者达成一致判定 GFDL 不适合作文档许可证，建议将文档重新许可为 GPL 兼容条款并折叠进 scsi_mid_low_api.txt，补丁将 GNU 自由文档许可证替换为 GNU 通用公共许可证 v2 或更高版本，维护者共识记录为 "we agreed that GFDL is"，这场小型事件在 GPLv3 争议正式发酵前已埋下 GPL 阵营对文档许可证形态的关注

到 2010 年代，BSD 血统代码大规模进入 Linux 内核——Jiri Slaby 指出 madwifi 走的是移植来的 BSD net80211 实现 "madwifi goes through ported bsd net80211"，Michael Wu 在 Linux 802.11x 支持差距讨论中转述 "Madwifi has a fairly complete 802.11 stack (ported from netbsd)"，Andriy Korud 在开放硬件无线卡讨论中重申 "madwifi Linux driver with MAC layer ported from xBSD"；IPsec 工具链的谱系同样清晰，Vegard Nossum 在 Kconfig 帮助文本中留证 "PF_KEYv2 socket family, compatible to KAME ones" 与 "IPsec tools ported from KAME"，KAME 源自 FreeBSD 与 NetBSD；文件系统工具的移植谱系更为古老，Dave Chinner 在 hfsplus 维护困境讨论中点明 "ported from the open source Darwin code drops"，而 Darwin 内核源自 4.x BSD；Andrew Morton 在 UFS 目录与页缓存改造讨论中回忆早年尝试移植 BSD ufsutils 失败 "I had a go at porting BSD ufsutils a few years ago and nearly died"，Jan Engelhardt 追问时留下"几年前移植 BSD ufsutils 几乎丧命"的相同表述，Al Viro 审阅 Linux UFS 端口时把 OpenBSD 6.1 的 Newfs 与 fsck 作为权威交叉核查基线 "pass fsck on OpenBSD"；内存管理领域，linuxsuperpages 项目讨论文本明确 "Superpages FreeBSD prototype that has been ported to the 2.6 Linux kernel"，把 Rice University 在 FreeBSD 上的原型移植到 2.6 内核覆盖 IA64、x86-64 与 x86-32

2016 年 7 月 15 日，Dexuan Cui 的 Hyper-V VM Sockets（AF_HYPERV）cover letter 把新传输层定位在 BSD socket 语义之上，理由是以相同 socket 调用保持应用可移植性，直录引语 "by the traditional BSD-style socket APIs"；同一时期 linux-fsdevel 线程中，Indan Zupancic 反对 Linux-only 的 sys_syncfs 添加，要求同时加入 BSD 版本 "at least ad it together with BSD so it's slightly portable"，而 Eric Dumazet 在 BPF 模运算讨论中反问 "What about the other OS - eg all the BSDs?"，David Laight 追问 BPF 是否"本应是合理可移植的"；netdev 线程中 Luis Rodriguez 明确 "BSD folks can simply use the external unified tree now to port the driver to BSD"，同时承认受 "license divergence" 限制

2018 年 util-linux v2.35 发布公告中，Carlos Santos 因 GPLv3 引入对嵌入式部署的影响直接提议改用 BSD 等更宽松许可证移植同类代码，原文 "An alternative approach would be porting a similar code using a more liberal license, e.g. BSD"，这是 BSD 许可证作为 GPL 替代方案最直接的正面主张；同期 util-linux 2.28-rc1 与 2.28-rc2 两次发布公告都把"移植到非 Linux 系统（BSD、XOs/OSX）"作为改进项公开留痕，英文原文 "portable to non-Linux systems (BSD, XOs)" 与 "The package build system and code have been improved to be more portable to non-Linux systems (BSD, OSX)"

2021-2022 年间，IPE 与 IMA 元数据格式能否进入 NFS 标准及 IETF 规范之争浮现了 GPL 与 BSD 许可证边界的实质冲突，James Bottomley 反驳 Chuck Lever 关于 GPL 束缚格式的说法，指出 GPL 是代码许可证而非数据或文档许可证，而 IETF 贡献采用与 GPL 不兼容的 BSD 风格许可证，原文 "IETF contributions occur under a BSD-style license incompatible with the GPL"，非 Linux 实现者依赖该流程规避许可索赔；同一时期 netdev 上 McHardy 在 ppp SC_MUST_COMPRESS 补丁里把 if_ppp.h 头文件注释整体替换为 CMU 来源的 BSD 许可证文本，立即引发对其 GPL 兼容性的追问 "Why do you change the license, especially to something GPL-incompatible?"

GPL 阵营对 BSD 迁移趋势的公开表态最早清晰见于 Linux Kernel Summit 场合——Greg KH 反对 Bradley Kuhn 把诉讼当作唯一出路，声称 "If you don't defend the GPL in courts, we need to give up on it"，并援引 BusyBox 诉讼催生 Toybox、LLVM 因规避 FSF 与 GPLv3 而生的案例，称无意开战；Guenter Roeck 在同一议题中援引其此前雇主经历，判断多数新项目改用 BSD 或 Apache 许可证以规避 GPL 隐患，原文 "most new projects ended up using BSD or Apache licenses to avoid the pitfalls of GPL"

2026 年 7 月 FreeBSD 完成 GPL 移除工程之时（dialog/dpv 移除与 `gnu/` 目录退役，Linuxiac 2026-07-17、IT 之家 2026-07-18、Phoronix 2026-07-15 三源印证），Linux 内核邮件列表内部关于 BSD 血统代码的持续追溯才第一次获得系统性呈现——BSD 血统代码在 Linux 内核中已分布至 madwifi、ar5523（John W. Linville 在 wireless-next 拉取请求中说明 "addition of the ar5523 driver, ported from an original FreeBSD driver"）、IPsec tools、KAME 移植、UFS 工具、Superpages 内存管理、BSD socket 语义、OpenBSD 网络随机化补丁（补丁主题即 "OpenBSD Networking-related randomization port"）、madwifi 完整 802.11 栈等多个子系统，且 BSD 许可证在 Linux 生态内被显式承认是规避 GPL 的主流替代路径——BSD 许可证的"纯洁化"（把 GPL 从 base 剔除）与 BSD 血统代码的"流动性"（Linux 内核持续吸收 BSD 派生实现）在同一历史过程中互为镜像，Linux 内核内部 BSD 派生代码的规模恰是 FreeBSD 侧许可证纯洁化工程的外部支撑条件

**史观**：总纲第 6 条——和解优于斗争：BSD 许可证的纯洁化（把 GPL 从 FreeBSD base 剔除）与 BSD 血统代码的流动（Linux 内核持续吸收 BSD 派生实现）并非对立的两条线，而是同一个历史过程中互为镜像的两个面向——前者是"从 GNU 生态剥离"的工程原则，后者是"在 GNU 生态之外建立替代生态"的实际结果，二者共同验证 BSD 阵营的"深原则回避传染性 GPL"信条在跨越三十余年的时间尺度上产生了可测量的技术效应

**辨析**：考据过程留痕——【查证来源】(1) madwifi 与 ar5523 与 IPsec tools 与 KAME 谱系的英文引语均出自 linux-fsdevel 与 netdev 邮件列表，claim_id 与 source_ref 已一一对应；(2) Superpages FreeBSD 原型移植至 2.6 内核的两次独立记录（linux-mm.messages.804845 与 linux-mm.messages.1015279）交叉印证；(3) Greg KH 与 Guenter Roeck 的 KSummit 表态出自 ksummit.messages.440 与 ksummit.messages.8007，属 2007-2008 年前后 GPLv3 争议高峰期的直接记录；(4) 2018 年 Carlos Santos 的 BSD 替代主张出自 util-linux v2.35 发布公告文本；(5) James Bottomley 关于 IETF 与 BSD 风格许可证的表述出自 linux-fsdevel.messages.481824，与 James Bottomley 在 NFSv4 IETF 工作组的公开角色一致；(6) 2003 年 SCSI 文档许可证事件出自 linux-scsi.messages.1348685，Douglas Gilbert 作为 scsi_mid_low_api.txt 主维护者的身份可交叉印证。【存疑判定依据】(1) "BSD 血统代码在 Linux 内核中分布至多个子系统"是基于十余封邮件引语的归纳判断，子系统覆盖的完整性须以 kernel.org 的 git blame 与 COPYING 文件为准；(2) madwifi 的 802.11 栈在 Linux 内核中已被 mac80211/ath9k 等重写替代，"BSD 血统"的当下有效程度须以内核树最新状态复核；(3) "BSD 许可证是 Linux 生态规避 GPL 的主流替代路径"基于 Guenter Roeck 的雇主经验陈述，属过程性证据而非全局统计；(4) 本节将 FreeBSD 侧许可证纯洁化与 Linux 侧 BSD 血统代码流动并置，两者的因果关系为"共时性镜像"而非"直接因果"，具体传导机制（如 Clang/LLVM 的开发动机与 BSD 阵营关联）另节讨论
