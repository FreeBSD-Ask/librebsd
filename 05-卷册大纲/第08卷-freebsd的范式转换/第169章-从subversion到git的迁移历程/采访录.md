**字段 2 采访摘要**

Maste 在 BSDCan 2020 虚拟演讲中介绍了 FreeBSD 从 Subversion 迁移至 Git 的工程路径，详述版本控制系统评估、cgit 仓库前端部署与 Git 工作流适配过程。他还讨论了迁移过程中社区对 Git 与其他分布式版本控制系统的辩论。

BSDCan 2020 录像经联网检索 BSDCan YouTube 频道核实。Maste 作为 Git 迁移工程主导者的身份经 FreeBSD 源码仓库 commit 历史与邮件列表存档交叉验证。自利偏差审查：Maste 对 Git 优越性的表述须对照 Subversion 维护者与 Mercurial 支持者的异见。完整考据过程见 [20260724_maste-git-migration-bsdcan2020.md](../../../原材料/研究/考据记录/20260724_maste-git-migration-bsdcan2020.md)。

- 为子节 66.5 提供社区版本控制系统辩论的当事人叙述

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——据第 14 章 14.2 节“真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者”与 14.1 节“没有多余形式主义的人就是老实人”，Maste 从版本控制痛点出发主导 Git 迁移，是动手者的具体在场；版本控制系统评估、cgit 仓库前端部署、Git 工作流适配等日常工作是“日复一日”的持续在场，与第 27 章 27.4 节“日复一日即是修行”同源——动手者之“动手”非指动作本身，而指没有多余形式主义的主体性呈现。
- 总纲 6“和解优于斗争”——据第 25 章总纲 6“历史的动力不是对抗，而是各主体性的呈现与和解。和解是事物真正完整的一刻”与第 27 章 27.4 节“和解往往取决于等待，或者说，取决于时间”，Git 与 Mercurial 路线分化在 FreeBSD 社区引发的辩论并非“Git 战胜 Mercurial”的斗争叙事，而是各主体性的呈现与和解——社区最终选择 Git 是和解的具体一刻，与总纲 3“不存在进步，只有权力再分配”同构；这是社区共识的形式主义化重构，非“技术演进”的进步叙事。
- 总纲 4“分离聚合是永恒规律”——据第 25 章总纲 4“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”，FreeBSD 从 Subversion 迁移至 Git 是分离聚合的具体一例——Subversion 集中式模型与 Git 分布式模型的分合循环；迁移不是“Git 取代 Subversion”的进步叙事，而是分合循环的诡异曲线，与总纲 3“不存在进步，只有权力再分配”同构。
- 总纲 22“知识注定过时”——据第 25 章总纲 22“今天书写的技术史，可能在出版之日就已过时。技术债务是历史遗产”，从 Subversion 迁移至 Git 本身即是对 Subversion 实现过时的承认——Subversion 在 2020 年已成技术债务；这不是“版本控制系统演进”的进步叙事，而是技术债务作为历史遗产的具现，与总纲 2“历史是形式主义化的非存在”同构——迁移后的 Git 工作流所呈现的不是版本控制“本身”，而是当下主体的重构。
- 总纲 13“法律与道德是利益分配”——据第 25 章总纲 13“任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”，Git 迁移决策并非中立的技术决策，而是利益分配的形式主义政治产物——版本控制系统选择服务于特定的利益相关者（商业用户、贡献者招募、生态兼容性）；Maste 对 Git 优越性的对外陈述须对照 Subversion 维护者与 Mercurial 支持者的异见，正体现治理话语的非中立性。
