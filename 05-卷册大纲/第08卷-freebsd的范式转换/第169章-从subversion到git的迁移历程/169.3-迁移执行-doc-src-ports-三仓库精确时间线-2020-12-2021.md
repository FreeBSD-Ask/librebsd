## 169.3.4 迁移里程碑与关键技术细节辨析

**要点**：Git 迁移的核心技术细节包括：(1) **转换工具**：使用基于 **svn-all-fast-export/svn2git** 的定制化转换工具链，由 Ulrich Spörlein 维护，包含专门为 FreeBSD 仓库结构编写的规则文件；(2) **历史完整性**：完整保留了从 1993 年到 2021 年的全部提交历史（包括 CVS→SVN 转换时保留的历史），总计约 30-50 万次提交（三大仓库合计）；(3) **作者映射**：创建了完整的 authors.txt 文件，将 SVN 用户名映射到 Git 格式的作者名和邮箱（包括已退役 committer）；(4) **分支与标签处理**：SVN 的 branches/、tags/、vendor/ 目录结构正确映射为 Git 分支和标签，stable/N、releng/N.N 等命名约定在 Git 下继续保留；(5) **head→main 重命名**：SVN 的主干目录 **head** 在 Git 下重命名为 **main**，这是唯一的命名变更；(6) **vendor 分支处理**：SVN 时代的 vendor 分支机制在 Git 下部分转换为 Git submodule（如 LLVM、OpenZFS 等第三方代码）

**史料**：Ulrich Spörlein 的 SVN→Git 转换工具和规则文件（github.com/freebsd 仓库）；authors.txt 作者映射文件；转换前后 commit 数量校验日志；freebsd-git 邮件列表转换技术讨论 ［A］

**史观**：历史转换是数字时代的“档案抢救”工程——每一次 commit 的作者、时间、内容、提交信息都准确保留，这确保了 FreeBSD 28 年开发史的可追溯性；工具可以更替，但集体记忆必须保存〔订正注：原挂“总纲第 25 条——终结与延续”系伪标签，权威表第 25 条为“逻辑是形式主义”，依核查报告去条号留中性论旨〕

**辨析**：转换完整性验证采用了多种方法——commit 数量比对、文件树哈希校验、分支标签数量统计、随机抽样历史提交对比等；官方虽未发布完整的正式验证报告，但从邮件列表讨论和开发者使用反馈来看，转换质量很高，几乎没有历史信息丢失；CVS 时代（1993-2008）的历史在 CVS→SVN 转换时已保留，此次 SVN→Git 二次转换未造成明显额外损失
