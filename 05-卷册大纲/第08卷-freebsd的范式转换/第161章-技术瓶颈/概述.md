# 第 161 章 技术瓶颈

### 核心内容

本章围绕 FreeBSD 范式转换期的技术瓶颈展开，共 12 个子节：161.1 从 4.4BSD 的规模限制（32 位地址空间与进程表极限）切入；161.2-161.3 还原 SMPng 大内核锁移除的开发困境与 FreeBSD 5.x 稳定性危机（双轨制与技术债务）；161.4-161.7 依次考察 32 位到 64 位的 AMD64 架构适配、多核时代的 NUMA 与调度器优化、网络栈 C10K 问题与现代替代方案、ZFS 内存消耗争议与性能权衡；161.8 汇集社区内部诊断与改进路线；161.9 引入 Linux 与 Windows NT 竞争者视角对技术瓶颈叙事作批评性辨析；161.10-161.12 补以外部贡献者、重要贡献者与边缘者及同时期操作系统的比较，呈现瓶颈突破与形式主义积累相互交织的工程史。

### 史观映射

> 技术瓶颈不是偶然的失败，而是形式主义积累的必然——当代码规模膨胀到一定程度，其自身的复杂性就会变成无法逾越的墙；而突破瓶颈的每一次尝试，从 SMPng 到大内核锁移除，从 32 位到 64 位转型，从 ULE 调度器到 NUMA 优化，本身就是技术史中形式主义不断自我否定与自我超越的循环——每一次突破都意味着新形式的诞生，而新形式终将积累成新的瓶颈
