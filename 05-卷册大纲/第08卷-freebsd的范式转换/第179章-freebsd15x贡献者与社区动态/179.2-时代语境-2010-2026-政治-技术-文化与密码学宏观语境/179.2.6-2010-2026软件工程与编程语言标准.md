# 179.2.6 2010-2026 软件工程与编程语言标准

**要点**：2010-2026 软件工程与编程语言标准演进：① C 语言标准——C11（2011，ISO/IEC 9899:2011）、C17（2018，缺陷修复）、**C23**（2024 正式发布，FreeBSD 15.1 显著进展）；② C++ 标准——C++11（2011）、C++14（2014）、C++17（2017）、C++20（2020）、C++23（2023）、C++26 进行中；③ Rust 1.0（2015）发布后快速成熟，成为系统编程领域 C/C++ 的主要竞争者；④ LLVM/Clang 成为与 GCC 并列的主流编译器工具链（FreeBSD 自 10.x 起默认 Clang）；⑤ 形式化验证、模糊测试（fuzzing）、静态分析在安全关键软件开发中普及；⑥ eBPF 推动内核可编程性；⑦ 内存安全成为行业焦点（NSA/CISA/Google 等 2022-2023 纷纷呼吁转向内存安全语言）

  **2010-2026 软件工程与编程语言标准演进**：

  | 序号 | 领域 | 演进 |
  |---|---|---|
  | ① | C 语言标准 | C11（2011）、C17（2018）、**C23**（2024，FreeBSD 15.1 显著进展） |
  | ② | C++ 标准 | C++11/14/17/20/23，C++26 进行中 |
  | ③ | Rust | 1.0（2015）发布后快速成熟，成为 C/C++ 主要竞争者 |
  | ④ | LLVM/Clang | 成为与 GCC 并列的主流编译器（FreeBSD 自 10.x 起默认 Clang） |
  | ⑤ | 形式化验证/模糊测试 | 在安全关键软件开发中普及 |
  | ⑥ | eBPF | 推动内核可编程性 |
  | ⑦ | 内存安全 | NSA/CISA/Google 等 2022-2023 呼吁转向内存安全语言 |

**史观**：软件工程：FreeBSD 从 GCC 切换到 Clang/LLVM（10.x 完成，2014 年）是 2010 年代最重要的编译器决策——Clang 的 BSD 许可证、更模块化的架构、更好的诊断信息、与 LLVM 工具链的集成使 FreeBSD 摆脱了对 GPLv3 许可的 GCC 4.2.1（FreeBSD 长期使用的最后一个 GPLv2 GCC 版本）的依赖；C23 标准支持在 15.1 取得进展体现 FreeBSD 对标准合规的重视；Rust 争论则是内存安全需求与 C 语言传统之间张力的体现

**辨析**：C 语言仍是 FreeBSD 内核与 base 的主导语言，C++ 主要用于少量用户态工具（如 LLDB、某些第三方库），Rust 在 base 中的引入仍在讨论；C23 的主要新特性（`constexpr`、`typeof`、`_BitInt(N)`、移除过时特性等）对内核代码的影响需要逐步评估——内核通常禁用 C 标准的部分特性以确保可预测性
