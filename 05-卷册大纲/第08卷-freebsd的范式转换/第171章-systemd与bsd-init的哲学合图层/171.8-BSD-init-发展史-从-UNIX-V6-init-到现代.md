# 171.8 BSD init 发展史——从 UNIX V6 init 到现代 BSD rc.d 谱系

#### 要点

BSD init 谱系演化呈现“演化而非革命”的连续路径：UNIX V6 init（1975-05-14，tuhs.org `V6/usr/source/s1/init.c`，3058 字节单一 C 程序，`execl(shell, shell, runc, 0)` 调用 `/etc/rc` 脚本）→ 4BSD `/etc/rc`（1980-11-11，1380 字节单一 shell 脚本，顺序硬编码执行 fsck→swapon→mount→daemons，**无依赖排序，无 rc.local**）→ 4.2BSD `/etc/rc.local`（1983-08-28，910 字节，rc.local **首次出现于 4.2BSD**，4BSD 尚无此文件）→ NetBSD 1.5 rc.d（2000-12-06 release，Luke Mewburn（卢克·缪伯恩） 设计，commit `22218340f1e94809e817d9d187ebd2a53b46cffd` [2000-03-10，lukem@NetBSD.org，“rc.d scripts derived from /etc/rc”]，独立 `/etc/rc.d/*` 脚本 + **rcorder(8)** 依赖排序，论文 USENIX ATC 2001 FREENIX Track）→ FreeBSD 5.0 rcNG（2003-01-19 公告，2003-01-16 tag `075695dcc77a30908e583b10a4ba0917784c3f61`，commit `9d62501fd8278c7cde01dcb4d0f2b3c7c757bf86` [2001-06-16，obrien@FreeBSD.org，“Import the NetBSD 1.5 RC system”]，借鉴 NetBSD rc.d，社区俗称 rcNG，FreeBSD 5.0 release notes 正文未出现此字样）→ OpenBSD **rc.d(8)**（首次出现于 OpenBSD 4.9，2011-05-01，**rc.subr(8)** 与 **rc.d(8)** 同时引入，截至 2025-08-15 仍存在于 OpenBSD-current，自 4.9 引入即采取简化设计：仅用于 package 守护进程，base 系统由 `/etc/rc` 直接启动，不使用 **rcorder(8)**）→ DragonFly BSD（2003-06-17 commit `984263bcb83ad82313113c6ac840d99124d8f90c`，<dillon@dragonflybsd.org>，“Initial import from FreeBSD RELENG_4”，fork 时继承 FreeBSD 4.x 旧 rc；2003-07-24 commit `9c600e7dc7d49484402b035e0603d6447f88d960`，“Bring RCNG in from 5.x”主动引入 RCNG）。**[重要更正]** 任务描述中“OpenBSD 2014-2015 简化重写”与官方文档不符——OpenBSD 5.6（2014-11）/5.7（2015-05）changelog 中 rc.d 仅有小修补（`_rc_do`/`_rc_wait` 重命名等），非“重写”；OpenBSD rc.d 自 4.9 引入即采取简化设计。

**BSD init 谱系演化时间线（1975-2011）**：

| 时间 | 节点 | 关键文件 / commit | 设计特点 |
|---|---|---|---|
| 1975-05-14 | UNIX V6 init | `V6/usr/source/s1/init.c`（3058 字节 C 程序） | `execl(shell, shell, runc, 0)` 调用 `/etc/rc` |
| 1980-11-11 | 4BSD `/etc/rc` | `4BSD/etc/rc`（1380 字节 shell 脚本） | 顺序硬编码 fsck→swapon→mount→daemons，无依赖排序、无 rc.local |
| 1983-08-28 | 4.2BSD `/etc/rc.local` | `4.2BSD/etc/rc.local`（910 字节） | rc.local 首次出现于 4.2BSD |
| 2000-03-10 / 2000-12-06 release | NetBSD 1.5 rc.d | commit `22218340f1e94809e817d9d187ebd2a53b46cffd` | 独立 `/etc/rc.d/*` + **rcorder(8)** 依赖排序（Luke Mewburn 设计） |
| 2001-06-16 / 2003-01-19 公告 | FreeBSD 5.0 rcNG | commit `9d62501fd8278c7cde01dcb4d0f2b3c7c757bf86` | 借鉴 NetBSD rc.d，社区俗称 rcNG |
| 2003-06-17 / 2003-07-24 | DragonFly BSD RCNG | commit `9c600e7dc7d49484402b035e0603d6447f88d960` | fork 时继承 FreeBSD 4.x，后主动引入 5.x RCNG |
| 2011-05-01 | OpenBSD **rc.d(8)** | OpenBSD 4.9 release | 自引入即简化设计：仅 package 守护进程，base 由 `/etc/rc` 启动 |

#### 史料

UNIX V6 init 源码一手来源：tuhs.org 存档 `https://www.tuhs.org/cgi-bin/utree.pl?file=V6/usr/source/s1/init.c`，文件路径 `V6/usr/source/s1/init.c`，文件大小 3058 字节，文件日期 1975-05-14。关键代码摘录：

```c
char	runc[]	“/etc/rc”;
char	init[]	“/etc/init”;
char	ifile[]	“/etc/ttys”;
...
main()
{
	...
	if(getcsw() != single) {
		i = fork();
		if(i == 0) {
			open(“/”, 0);
			dup(0);
			dup(0);
			execl(shell, shell, runc, 0);
			exit();
		}
		while(wait() != i);
		...
	}
	...
}
```

V6 init 是单一 C 程序（约 3058 字节），编译后位于 `/etc/init`，启动多用户模式时 fork 子进程，子进程 `execl(shell, shell, runc, 0)` 即以 `/bin/sh` 执行 `/etc/rc`。V6 中 `/etc/rc` 是 shell 脚本，由 init 调用；init 本身是 C 程序，承担进程 1 与终端管理职责。

4BSD `/etc/rc` 一手来源：tuhs.org 存档 `https://www.tuhs.org/cgi-bin/utree.pl?file=4BSD/etc/rc`，文件路径 `4BSD/etc/rc`，文件大小 1380 字节，文件日期 1980-11-11。关键内容摘录：

```sh
HOME=/; export HOME
if [ $1 = autoboot ]
then
	echo Automatic reboot in progress... >/dev/console
	date >/dev/console
	/etc/fsck -p >/dev/console
	...
else
	date >/dev/console
fi
...
/etc/swapon -a							>/dev/console
/etc/mount -a							>/dev/console
			echo preserving editor files 	>/dev/console
(cd /tmp; /usr/lib/ex3.6preserve -a)
...
		echo -n starting daemons:	>/dev/console
/etc/update;			echo -n ‘ update’		>/dev/console
/etc/cron;			echo -n ‘ cron’			>/dev/console
/etc/accton /usr/adm/acct;	echo -n ‘ accounting’		>/dev/console
sh /usr/net/bin/start &		echo -n ‘ network’		>/dev/console
/etc/comsat;			echo -n ‘ mail’			>/dev/console
...
exit 0
```

4BSD `/etc/rc` 是单一 monolithic shell 脚本（1380 字节），顺序执行 fsck → swapon → mount → preserve editor files → clear /tmp → start daemons，守护进程启动顺序硬编码（update、cron、accton、network、comsat），**无依赖排序机制**，**无 rc.local**（4BSD 的 `/etc/` 目录下无 rc.local 文件）。

4.2BSD `/etc/rc.local` 一手来源：tuhs.org 存档 `https://www.tuhs.org/cgi-bin/utree.pl?file=4.2BSD/etc/rc.local`，文件路径 `4.2BSD/etc/rc.local`，文件大小 910 字节，文件日期 1983-08-28。rc.local **首次出现于 4.2BSD**（1983-08-28），4BSD（1980）尚无此文件——tuhs.org 4BSD/etc 目录列表确认 4BSD 仅有 rc，无 rc.local；tuhs.org 4.2BSD/etc 目录列表确认 4.2BSD 同时有 rc（2005 字节）与 rc.local（910 字节）。

Mewburn 论文一手来源：USENIX 官方论文页 `https://www.usenix.org/legacy/publications/library/proceedings/usenix01/freenix01/mewburn.html` + 论文 PDF `http://www.mewburn.net/luke/papers/rc.d.pdf`。论文标题“The Design and Implementation of the NetBSD rc.d system”，作者 Luke Mewburn，署名机构 Wasabi Systems, Inc.，作者邮箱 `lukem@wasabisystems.com`，发表会议 USENIX Annual Technical Conference 2001 FREENIX Track，USENIX 页面最后修改 2002-02-13。论文摘要原文："In this paper I cover the design and implementation of the rc.d system start-up mechanism in NetBSD 1.5, which replaced the monolithic /etc/rc start-up file inherited from 4.4BSD. Topics covered include a history of various UNIX start-up mechanisms (including NetBSD prior to 1.5), design considerations that evolved over six years of discussions, implementation details, an examination of the human issues that occurred during the design and implementation, as well as future directions for the system.“。论文 2.1 节”4.4BSD“原文：”4.4BSD has a rather simple start-up sequence. When booting multi-user, the kernel runs init (located in /sbin/init), which spawns a shell (/bin/sh) to run /etc/rc, which contains commands to check the consistency of the file-systems, mount the disks, start up system processes, etc."。论文关键事实：署名机构 Wasabi Systems, Inc.、发表时间 USENIX ATC 2001 FREENIX Track、NetBSD 1.5 发布时间 December 2000、设计讨论时长 six years（约 1994-2000 年讨论）。

NetBSD 1.5 release notes 一手来源：`https://www.netbsd.org/releases/formal-1.5/NetBSD-1.5.html`，release 日期 2000-12-06。“System administration and user tools”节原文："Conversion of the rc(8) system startup and shutdown scripts to an ‘rc.d’ mechanism, with separate control scripts for each service, and appropriate dependency ordering provided by rcorder(8)."。

NetBSD 1.5 rc.d 引入 commit 来自 `bsd_commits.duckdb`：commit `22218340f1e94809e817d9d187ebd2a53b46cffd`，author_date 2000-03-10T11:53:23Z，author_email `lukem@NetBSD.org`，message_subject“rc.d scripts derived from /etc/rc”——这是 NetBSD 仓库中首批 rc.d 脚本的引入 commit。

FreeBSD 5.0 一手来源：release announcement `https://www.freebsd.org/releases/5.0R/announce/`，release 日期 2003-01-19（announcement 邮件时间戳“Sun, 19 Jan 2003 10:03:42 -0700”，发布者 Scott Long `<scottl@FreeBSD.org>`）；**rc(8)** 手册页 `https://www.freebsd.org/cgi/man.cgi?query=rc&sektion=8&manpath=FreeBSD+5.0-RELEASE`。FreeBSD 5.0-RELEASE **rc(8)** 手册页原文："The rc utility is the command script which controls the automatic boot process after being called by init(8). ... The rc.d/ directories contain scripts which will be automatically executed at boot time and shutdown time.“；”Operation of rc“节：”1. Source /etc/rc.subr to load various rc.subr(8) shell functions to use. 2. If autobooting, set autoboot = yes and enable a flag (rc_fast = yes), which prevents the rc.d/ scripts from performing the check for already running processes (thus speeding up the boot process). 3. Invoke rcorder(8) to order the files in /etc/rc.d/ that do not have a ‘nostart’ keyword (refer to rcorder(8)'s -s flag), and assign the result to a variable. 4. Call each script in turn using run_rc_script() (from rc.subr(8)), which sets $1 to ’start', and sources the script in a subshell."。

FreeBSD 5.0 rcNG 引入 commit 来自 `freebsd.duckdb`：commit `9d62501fd8278c7cde01dcb4d0f2b3c7c757bf86`，author_date 2001-06-16T07:16:14Z，author_email `obrien@FreeBSD.org`，message_subject“Import the NetBSD 1.5 RC system.”——FreeBSD 自 NetBSD 1.5 主动引入 RC 系统。FreeBSD 2002-12-22 commit `eb7bf003063f225217f11b267f044e253343145c`（<dillon@FreeBSD.org>）明确提到“RCNG case”——证明“RCNG”是当时社区使用的名称。FreeBSD 2003-01-16 commit `075695dcc77a30908e583b10a4ba0917784c3f61` 是 RELENG_5_0_0_RELEASE tag。

OpenBSD **rc.d(8)** 一手来源：OpenBSD 4.9 release 页 `https://www.openbsd.org/49.html`，发布日期 2011-05-01。“What's New”节原文："New rc.d(8) for starting, stopping and reconfiguring package daemons: The rc.subr(8) framework allows for easy creation of rc scripts. This framework is still evolving. Only a handful of packages have migrated for now. rc.local can still be used instead of or in addition to rc.d(8).“。OpenBSD **rc.d(8)** 手册页 HISTORY 节：”The /etc/rc.d directory first appeared in OpenBSD 4.9."。截至 2025-08-15 OpenBSD-current 手册页仍引用 **rc.subr(8)**，FILES 节明确列出 `/etc/rc.d/rc.subr`——证明 **rc.subr(8)** 未被移除。

OpenBSD 5.6（2014-11-01）changelog `https://www.openbsd.org/plus56.html` 中 rc.d 相关变更仅为小修补："Properly evaluate rc.d(8) values only after running _rc_quirks(), because these can modify flags.“；”In rc.d(8) debug mode, properly sort and drop duplicate entries to make output less confusing.“；”Unbroke rc.d(8) script for smapd(8) after the rc_do->_rc_do and rc_wait->_rc_wait renaming."。OpenBSD 5.7（2015-05-01）changelog `https://www.openbsd.org/plus57.html` 中 rc.d 相关变更仅一条："Made rcctl(8) properly access all rc.d(8) scripts and ignore anything irrelevant in /etc/rc.d."。

OpenBSD rc.d 与 NetBSD/FreeBSD rc.d 的关键差异：OpenBSD **rc.d(8)** **仅用于 package 守护进程**，base 系统守护进程由 `/etc/rc` 直接启动；OpenBSD **不使用 **rcorder(8)** 依赖排序**，package 守护进程启动顺序由 **rc.conf(8)** 中 `pkg_scripts` 变量显式指定；OpenBSD 的设计哲学是“保持简单”，避免 NetBSD/FreeBSD rcNG 的依赖图复杂性。这种“简化”是 OpenBSD rc.d **自 4.9 引入时的初始设计**，而非 2014-2015 的“重写”。

OpenBSD rc 简化时间窗口 2014-07 集中爆发（对应 OpenBSD 5.6 开发周期，5.6 于 2014-11 发布），代表 commit `8799e9c877093a6c8cab0864613896a160b0c87a`（2014-07-12，<robert@openbsd.org>，"Make rc.conf a parsed configuration file and stop sourcing it as a shell script"）、`e6e1e0799a3fc0c129c95f72dfc955a50f57d021`（2014-07-14，<deraadt@openbsd.org>，“rc.{local, securelevel, shutdown} become examples”）——但这些是 rc.conf 解析方式调整与 rc.local/rc.securelevel/rc.shutdown 角色调整，非 rc.d 系统本身的重写。

DragonFly BSD 一手来源：`dragonfly.duckdb` dragonfly-src 仓库 commit `984263bcb83ad82313113c6ac840d99124d8f90c`（2003-06-17，<dillon@dragonflybsd.org>，“Initial import from FreeBSD RELENG_4”）—— fork 时继承 FreeBSD 4.x 旧 rc；commit `9c600e7dc7d49484402b035e0603d6447f88d960`（2003-07-24，<dillon@dragonflybsd.org>，"Bring RCNG in from 5.x and adjust config files and scripts accordingly. Bring in the 5.x mergemaster. Bring in the 5.x rcorder. Adjust Makefile's and mtree to deal with /etc/rc.d"）—— DragonFly BSD 主动从 FreeBSD 5.x 引入 RCNG。

#### 史观

项目史观总纲第 7 条“理论必须自反”在本节叙事中具体体现为：BSD init 谱系与 UNIX 谱系的连续性——V6 init（1975）→ 4BSD rc（1980）→ 4.2BSD rc.local（1983）→ NetBSD 1.5 rc.d（2000）→ FreeBSD 5.0 rcNG（2003）→ OpenBSD 4.9 rc.d（2011）→ DragonFly BSD RCNG（2003）——这一谱系呈现“演化而非革命”的连续路径，每个节点都在前一个节点基础上引入有限改进，无任何节点推翻前序设计重新开始。这与 systemd 选择“推翻 SysV init 重新设计 PID 1”的革命路径形成根本方法论对照。

项目史观总纲第 17 条“证明世界先于改造世界”在本节叙事中具体体现为：BSD init 的物理存在（V6 init.c 源码、4BSD rc 源码、4.2BSD rc.local 源码、Mewburn 论文、各版本 release notes、bsd_commits.duckdb commit 记录）先于“BSD init 谱系”的话语建构——史家将分散的版本节点串联为“谱系”，但这一谱系是史家赋予的叙事框架，源码本身并不自我宣称为“演化”或“改革”。

项目史观总纲第 25 条“逻辑是形式主义”在本节叙事中具体体现为：rc.d 取代单文件 rc 但延续 shell 脚本哲学——NetBSD 1.5 rc.d 将 monolithic `/etc/rc` 拆分为 `/etc/rc.d/*` 独立脚本，但每个脚本仍是 shell 脚本，依赖排序由 **rcorder(8)** 提供（基于脚本头部 `REQUIRE`/`PROVIDE` 关键字），整体设计延续 Unix 哲学的“小工具协作”。这是“终结中的延续”——形式上 rc.d 终结了 monolithic rc，实质上 shell 脚本哲学延续。

#### 辨析

UNIX V6 init 源码须以 tuhs.org 存档为准——tuhs.org 是 UNIX 早期版本源码的权威存档，由 The Unix Heritage Society 维护。源码中 `execl(shell, shell, runc, 0)` 与 `char runc[] "/etc/rc"` 直接证明 init 调用 `/etc/rc`。OpenBSD **rc(8)** 手册页 HISTORY 节确认“The rc command appeared in Version 4 AT&T UNIX”，与 V6 已有 `/etc/rc` 一致。

Mewburn 论文署名机构 Wasabi Systems, Inc. 的考据结论——Wasabi Systems 是 2000 年代 NetBSD 商业支持公司，Mewburn 当时为 Wasabi Systems 员工，论文 PDF 第一页明确署名 `lukem@wasabisystems.com`。Wasabi Systems 后期倒闭，但论文著作权归属在 USENIX 论文页与 mewburn.net 个人 PDF 内容一致。

FreeBSD 5.0 rcNG 引入的具体 commit 须以 `freebsd.duckdb` 核查——commit `9d62501fd8278c7cde01dcb4d0f2b3c7c757bf86`（2001-06-16，<obrien@FreeBSD.org>，“Import the NetBSD 1.5 RC system.”）是 FreeBSD 主动引入 NetBSD 1.5 RC 系统的 commit，commit `075695dcc77a30908e583b10a4ba0917784c3f61`（2003-01-16）是 RELENG_5_0_0_RELEASE tag。两个 commit 时间差约 19 个月，反映 FreeBSD 自 2001-06 引入 NetBSD RC 系统后至 2003-01 FreeBSD 5.0 RELEASE 期间的持续集成工作。

**［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］** “rcNG”是社区俗称，FreeBSD 5.0 release notes 正文未出现此字样——**rc(8)** 手册页确认了新 rc.d 机制，但未使用“rcNG”名称；FreeBSD 2002-12-22 commit `eb7bf003063f225217f11b267f044e253343145c`（<dillon@FreeBSD.org>）message 中出现“RCNG case”，证明“RCNG”是当时社区使用的名称。本节采信“rcNG 是社区俗称，非官方术语”。

**[重要更正]** 任务描述中“OpenBSD 2014-2015 简化重写”与官方文档不符——OpenBSD **rc.d(8)** 首次出现于 OpenBSD 4.9（2011-05-01），**rc.subr(8)** 与 **rc.d(8)** 同时引入，截至 2025-08-15 仍存在于 OpenBSD-current。OpenBSD 5.6（2014-11）/5.7（2015-05）changelog 中 rc.d 仅有小修补（`_rc_do`/`_rc_wait` 重命名等），非“重写”。OpenBSD rc.d 自 4.9 引入即采取简化设计：仅用于 package 守护进程，base 系统由 `/etc/rc` 直接启动，不使用 **rcorder(8)**。

rc.d 与 System V init 的关系须辨析——rc.d 是 BSD 对 System V init 的借鉴与改造，但二者并非派生关系。System V init 使用 `/etc/init.d/` + `/etc/rc*.d/`（运行级别目录）+ `inittab` 配置，rc.d 使用 `/etc/rc.d/` + **rcorder(8)** 依赖排序 + `rc.conf` 配置——二者均为 shell 脚本启动系统，但依赖管理机制不同。

**要点**：

- Rob Pike 在一封 TUHS 邮件中自述，1977 年前后在多伦多大学动态图形实验室为 nroff 编写绘图仪输出程序，被 Dennis Ritchie 面试时问及为何重复 Berkeley 已做的工作，Pike 答曰自己先写而 Berkeley 后来才署名，Ritchie 相信了他，这一经历可能助其获得贝尔实验室职位。（BSD Now EP478，[1016.14-1237.96]，L1）
- FreeBSD rc 系统谱系可追溯至 4.0BSD（1980 年）的 rc 工具，NetBSD 于 2000 年引入 rc.d 目录与 rcorder 以现代化启动子系统，FreeBSD 5.0 三年后导入这一改进。（BSD Now EP478，[808.44-873.12]，L2）
- Peter Hansteen 以 SolarWinds 供应链攻击与 node-ipc 组件事件为例，破除开源软件天然更安全、足够多眼球即无深缺陷两类断言，强调安全取决于实际审查者的能力与投入。（BSD Now EP478，[423.52-644.98]，L2）
- Hubbard 回顾 FreeBSD 二十一年的生态变迁：1993 年 11 月 2 日的首版邮件与软盘分发时代（1.2 或 1.44 兆媒体、230KB 分块文件）、1600 美元一 GB 的硬盘；彼时 ISP 是头号用户群，SOHO 服务器与拼装 ISA 网卡的 DIY 防火墙遍地，Yahoo 与 Hotmail 是招牌用户而后者被收购后尽快摆脱 FreeBSD；ports 从最初 70 个增至逾 24000 个，committer 数百人；早期以学界为主、商业参与者被视作怪人，如今怪人接管，商业主导带来长期资金，Gibbs 领导的基金会使职员岗位与自由实验的资助成为可能，而他自嘲自己早年的商业化尝试彻底失败。（BSDTalk EP247，[362.44-629.08]，L1）
- Hubbard 指出二十年前 Windows 将全胜、主流设备再见 Unix 的预言已被现实推翻：iPhone 等最大规模的 Unix 部署按台数计是手机，OS X 虽是混合技术体却默认装有终端、可作 Unix 开发机；与此同时 FreeBSD 正在隐形化——路由器、负载均衡、安全监控设备、pfSense 与 FreeNAS 等软件 appliance 重新品牌化后身份属于 appliance 而非 FreeBSD，流行游戏主机以其为基座 OS，甚至线缆两端的小型 ARM 处理器也运行完整软件栈，因为与其以 RTOS 模拟用户态不如直接放入 Unix。（BSDTalk EP247，[503.40-822.74]，L1）
- Hubbard 描述 GPLv3 的柔道效应：业界本以为自己与 GPL 达成了交易，却被 GPLv3 掀翻在地，这一变故促使众多法务与工程部门认真重估 BSD，为 FreeBSD 带来此前未有的商业关注；他特别提及 Linus Torvalds 以充分理由拒绝 GPLv3，并以“抱歉 RMS，你成功了”作反讽式致谢。　[存疑脚注] GPLv3 驱动商业转向 BSD 的判断系 Hubbard 单方观察，未提供量化证据，亦未排除云计算兴起等同期因素（BSDTalk EP247，[641.20-694.72]，L1）
- Hubbard 提出乐高化处方：在自动化批量供应主机、配置集中于外部数据库的时代，操作系统的本质已是一组乐高积木，BSD 社区应改变酷的定义、享受制造积木；具体到配置问题，他主张统一配置文件格式并提供单一访问库，承认 YAML、XML、JSON 之争经年无果，务实路径是先就 API 与库达成一致、最终择一接受足够好，届时 LibC 将首次拥有读写配置数据的 API；他以 Apple 全线统一于 XML PLIST DTD 与 preferences API 的实践为可行先例。（BSDTalk EP247，[1033.88-1524.06]，L1）
