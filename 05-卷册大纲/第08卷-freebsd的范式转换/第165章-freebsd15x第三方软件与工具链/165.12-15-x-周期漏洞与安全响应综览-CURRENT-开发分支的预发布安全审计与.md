## 165.12.1 15.x 周期安全态势总览——-CURRENT 状态下的数据特征与无 SA 披露的特殊性

## 165.12.2 64-bit time_t 强制过渡的代价——32 位平台退役与新攻击面出现

**要点**：15.0 强制 64-bit time_t（不再支持 32 位平台）是 FreeBSD 历史上最重大的 ABI 变更之一——这一过渡消除了 Y2038 漏洞类（32 位 time_t 在 2038 年溢出），但同时引入新的边界条件 bug；**CVE-2026-0915**（**2026 年 1 月 27 日** 由 Jessica Clarke 修复，4 个 commit）是 64-bit 过渡期的典型样本——`getnetbyaddr()` 与 `getnetbyaddr_r()` 在参数为 0 时使用未初始化字符串进行 DNS 查询，这一 bug 在 32 位时代可能因栈布局巧合未触发，64-bit 过渡的代码审查暴露了潜在的内存安全问题；**CVE-2025-10263**（**2026 年 5 月 28 日** 由 Andrew Turner 修复，7 个 commit）是 arm64 处理器 errata workaround——arm64 是 15.x 支持的主要 64 位架构之一（amd64、aarch64、riscv64、powerpc64），errata 修复反映 15.x 对 64 位硬件生态的深度依赖；**CVE-2026-6386**（**2026 年 3 月 31 日** 由 Mark Johnston 修复，8 个 commit）是 pkru 子系统对 1GB 大页内存映射的处理错误，反映 64 位时代大页内存管理的复杂性

  **64-bit time_t 过渡期典型 CVE**：

  | CVE | 修复日期 | 修复者 | commit 数 | 性质 |
  |---|---|---|---|---|
  | CVE-2026-0915 | 2026.1.27 | Jessica Clarke | 4 | `getnetbyaddr()` 未初始化字符串（64-bit 审查暴露历史 bug） |
  | CVE-2025-10263 | 2026.5.28 | Andrew Turner | 7 | arm64 处理器 errata workaround |
  | CVE-2026-6386 | 2026.3.31 | Mark Johnston | 8 | pkru 1GB 大页内存映射处理错误 |

**史料**：**freebsd.duckdb** `commits` 表 freebsd-src 仓库 CVE-2026-0915 修复 commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND message_subject LIKE '%CVE-2026-0915%'` 结果 4 条（Jessica Clarke，2026-01-27，commit hash `2b22e05b1747` 等）；CVE-2025-10263 arm64 errata 修复 commit `9d9d6c6e6081` 等（Andrew Turner，2026-05-28）；CVE-2026-6386 pkru largepage 修复 commit `a2f6f2d00125` 等（Mark Johnston，2026-03-31） ［A］

**史观**：总纲第 7 条——硬件与软件辩证：64-bit time_t 强制过渡是 FreeBSD 对 Y2038 问题的根本性回应——不同于 Linux glibc 的 “提供 64-bit time_t API 但保留 32 位兼容” 的双轨方案，FreeBSD 15.x 选择 “彻底切断 32 位” 的单轨方案；这一决策的工程代价是失去 i386、armv6、32 位 powerpc 等架构支持，但收益是内核与用户态的 time_t 一致性；新攻击面出现在 64 位整数运算的边界条件——64 位指针宽度改变了栈布局与结构体对齐，使原本被巧合掩盖的内存安全 bug 浮现

**辨析**：**需精确说明 32 位平台退役的范围**：15.0 退役的是 i386、armv6、32 位 powerpc 等纯 32 位架构，但 powerpc64（64 位大端）、powerpc64le（64 位小端）、armv7（最后保留的 32 位 Tier 2 平台）仍受支持；**CVE-2026-0915 的辨析**：该漏洞不是 64-bit time_t 直接导致的 bug，而是 64-bit 过渡期间的代码审查发现的历史遗留问题——**getnetbyaddr(0)** 使用未初始化内存的 bug 在 32 位时代已存在，64-bit 过渡的代码审查暴露了它；**arm64 errata 的性质**：CVE-2025-10263 是 ARM 处理器硬件 errata 而非 FreeBSD 软件 bug，Andrew Turner 的 commit 是软件层面的 workaround——这反映 15.x 周期 arm64 作为主要架构的维护负担

## 165.12.6 实验性 CHERI、WireGuard 回归与 Wayland 引入的安全债务——新代码与新攻击面

**要点**：15.x 周期的三个实验性或新引入子系统带来新的安全债务——① **实验性 CHERI 支持**：CHERI（Capability Hardware Enhanced RISC Instructions）是剑桥大学与 SRI International 的硬件 capability 模型，15.x 在 arm64 上提供实验性 CHERI 支持（Morello 架构）；CHERI 的硬件 capability 在概念上与 Capsicum 软件 capability 互补，但实验性状态意味着代码成熟度低于生产子系统；② **WireGuard 真正回归**：WireGuard 在 14.x 周期因内核 API 变更被移除，15.x 周期重新引入——新引入的 **if_wg(4)** 代码需重新审计；③ **Wayland 实验性支持**：15.x 引入 Wayland 实验性支持，新增 wayland-protocols、wlroots 相关代码——图形栈新代码带来新攻击面；这三个子系统的共同特征是 “实验性”——尚未被 Security Team 全面审计，可能在后续周期暴露漏洞；同期 iconv 漏洞集中修复（CVE-2026-58081/58082，Taylor R Campbell 与 Mark Johnston，**2026 年 6 月 22 日至 23 日**，共约 21 个 commit）反映 base 系统中 “被忽视的老代码” 也是安全债务来源——iconv 自 5.x 引入，多字节编码转换逻辑长期未审计

**史观**：总纲第 23 条——社区治理：15.x 周期 “-CURRENT 阶段预发布审计” 模式标志着 FreeBSD 安全文化的进一步成熟——Security Team 在 -CURRENT 阶段密集修复 CVE，将漏洞消灭在发布前；这一模式与 OpenBSD 的 “-current 审计 → release 稳定” 流程趋同，但 FreeBSD 的 -CURRENT 周期更长（通常 2 至 3 年），审计窗口更大；核心贡献者的高度集中（Mark Johnston 一人约 150 条 commit）反映 Security Team 的人力资源瓶颈——这一瓶颈在 14.x 周期已显现，15.x 周期进一步加剧；dma(8) 替代 sendmail 与 pkgbase 推进是 “减法” 与 “加法” 并行的架构现代化——减法消除历史 CVE 来源，加法改进安全更新分发

## 165.12.8 freebsd-src 趋势统计与 FreeBSD 15.x -CURRENT 开发阶段的定量印证

**要点**：**统计分析印证**——`freebsd.duckdb` freebsd-src 仓库 1993-2026 年 commit 月度量 Mann-Kendall 趋势检验结果为显著上升趋势（Sen's slope =+1.40/月，p < 0.001，95% CI [1.11, 1.69]）（统计结论 C-03）；Pettitt 与 BUISHAND R 双变点检验一致判定 freebsd-src 变点为 1999-08（p < 0.001，距 2020-01 SVN-to-Git 迁移 245 个月，判定非迁移伪变点）（统计结论 C-08、C-12）；ARIMA(5,0,5) 模型拟合 AIC = 107.39（统计结论 C-29），预测精度 MAPE = 24.56% RMSE = 456.55 coverage = 94.74%（统计结论 C-33），表明 freebsd-src commit 月度量可由 ARIMA 模型较好刻画；FreeBSD 15.x 周期（2026-01-01 至 2026-07-22）仍处于 15.0-CURRENT 开发阶段，半年内 freebsd-src CVE 相关 commit 383 条、去重 CVE 115 个，月均密度约为 14.x 周期的 2.7 倍；该时期 freebsd-src 趋势持续上升，未因 -CURRENT 阶段密集审计或 64-bit time_t 强制过渡而中断 commit 增长趋势，统计结论支持 15.x 周期 -CURRENT 开发阶段高强度安全审计与开发活跃度正相关

**史料**：`freebsd.duckdb` `commits` 表 freebsd-src 仓库 commit 月度量与 CVE commit 查询；SQL 查询 `SELECT strftime('%Y-%m', committer_date) AS month, COUNT(*) AS commit_count FROM commits WHERE repo_name='freebsd-src' GROUP BY month ORDER BY month`；Python 脚本 `script/phase3_inferential_stats.py` Task 5-6（Mann-Kendall 趋势检验 + Pettitt/BUISHAND R 变点检验）；Python 脚本 `script/phase4_time_series.py` Task 14-15（ARIMA 建模与预测）；统计结论编号 C-03、C-08、C-12、C-29、C-33；查询日期 2026-07-27 ［A］

**史观**：总纲第 22 条——赓续而非断裂：freebsd-src 趋势检验显示 15.x 周期 -CURRENT 阶段密集审计前后 commit 量均呈上升趋势，未出现因 64-bit time_t 过渡或 CHERI 实验性支持引入导致的 “开发断裂”——统计数据印证 FreeBSD 在 -CURRENT 阶段的激进变革中赓续 CSRG 未竟事业而非中断主线开发；总纲第 17 条——软件工程：15.x 周期审计密度约为 14.x 的 2.7 倍，freebsd-src 持续上升趋势为这一 “预发布审计” 工程模式的统计印证；总纲第 7 条——硬件与软件辩证：64-bit time_t 强制过渡与 CHERI 实验性支持反映 15.x 周期硬件能力对软件架构的塑造，freebsd-src 趋势检验显示这一硬件-软件协同演进未导致 commit 量显著下降

**辨析**：**统计局限性标注**——(1) 统计显著 ≠ 实际显著：Mann-Kendall 趋势检验 p < 0.001 表明 freebsd-src commit 量存在统计学显著上升趋势，但 15.x 周期 -CURRENT 阶段的实际工程意义须结合 64-bit time_t 过渡的具体代码变更综合判断；(2) 变点归因存疑：1999-08 变点距 15.x 周期约 27 年，归因单一化风险高，变点本身与 15.x 时期 -CURRENT 开发事件无直接因果关系；(3) ARIMA 模型局限：ARIMA(5,0,5) AIC = 107.39 为 freebsd-src 整体 commit 序列拟合结果，未单独建模 -CURRENT 阶段 commit 子序列或 CHERI/64-bit time_t 相关 commit 子序列，64-bit 过渡对整体趋势的贡献率未单独量化；(4) 多重比较风险：本结论与第五卷其他章节引用相同 freebsd-src 趋势统计存在多重比较风险，Bonferroni 校正后显著性可能降低；(5) 0 信任原则适用：15.x 周期 383 条 CVE commit 的高密度部分源于 14.x 周期遗留 CVE 的集中清理，不全是 15.x 新引入代码的漏洞，commit 量与开发活跃度的正相关不等于因果关系；(6) 数据窗口期局限：15.x 周期尚未结束（截至 2026-07），2026 年下半年数据未纳入，趋势判断可能随完整数据而调整
