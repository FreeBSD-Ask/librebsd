# 172.1.3 从广告条款到信任原则：许可证文本作为公共契约的历史叙事

从 4-clause BSD 到 3-clause、再到 2-clause FreeBSD 简化版，许可证文本的每一次削减都不止于法务操作，而是一次公共契约的重写——最初的四条款要求所有广告材料必须提及“This product includes software developed by the University of California, Berkeley and its contributors”，把学术机构身份焊入商业分发的强制署名条款一直延续了 15 年，直到 1999 年 7 月 22 日 William Hoskins（UC Berkeley 技术许可办公室主任）签发删除函，这条强制项才让位给 3-clause，随后 FreeBSD 自 2000 年代起采用 2-clause 变体，进一步删除“不得用贡献者名义做背书”的限制，把 BSD 语义推到极致：我给你一切，只请你保留版权声明与免责声明，每一次条款削减都像在剥掉一层法律强制的皮，露出下面那个更脆弱的东西——信任

真正的转折分两步：1992 年 1 月 UNIX System Laboratories 起诉 CSRG 与 BSDi，禁令冻结了 Net/2 的分发，CSRG 无法再合法分发 AT&T 代码；但工程行动其实在先——Keith Bostic 早在 1990 年前后发起 Net/2 重写，把内核中所有 AT&T 代码用 BSD 重新实现，4.4BSD-Release 已于 1991 年 6 月发行，比诉讼早三年；1993 年 7 月 Novell 从 AT&T 收购 USL 后倾向在市场竞争而非法庭竞争，1994 年 1 月双方和解，同年 6 月 4.4BSD-Lite 释出并可自由再分发——重写的成果最终成了法律风险的出口；Bostic 之后的 CSRG 解散（1995）没有让这种“为了自由重写一切”的精神消失，Sam Leffler 转投 Lucasfilm 与 Silicon Graphics，Mike Karels 加入 BSDi，而 CSRG 的 code review 传统通过 FreeBSD 的 Reviewed-by 与 Approved-by 字段延续至今

BSD 与 GPL 的分歧不只是许可证条款的技术选择，而是两种自由观的正面碰撞——GPL 通过 copyleft 强制派生作品同样开放，是“自由捍卫者”，BSD 允许闭源再分发，是“自由的给予者”；2022 年 G. Branden Robinson 在 linux-man 邮件列表上与 Ingo Schwarze 关于“Under this umbrella, the Linux kernel is effectively under the BSD license”的争论，把这一分歧重新拉回台面——Ingo 反驳称自由软件项目无法从 Linux 复制代码，“that's quite a big BUT since allowing everybody to copy the code for any purpose is the central idea of the BSD license”，并指出“GPL code is far from as free as if it were under a BSD license”，因为 BSD 让渡了伯尔尼公约下所有可转让权利，只保留本不可让渡的道德权

Alejandro Colomar 用一段对偶概括了这场非对称性——“the kernel is BSD-licensed to big corporations paying to the FSF, but GPL to free software programmers”，“BSDs are BSD for everyone”，Branden Robinson 干脆断言“The BSD camp did ultimately win the copyleft argument after all”，这一判断并非空谈，而是被 Linux 内核社区四十年的双许可实践部分验证——2004 年 altq HFSC 移植时原作者的立场“they removed the advertising clause, ... but they didn't want to release the code under the GPL”（DSLXC-14842），2012 年 if_ppp.h 清理时 Paul Mackerras 承认“the license on include/linux/if_ppp.h is the old BSD-style license with advertising clause”（DSLXC-15340），2015 年 David Woodhouse 在 Kernel Summit 讨论 GPL 执法光谱时观察到“basically wanting to act as if it's a BSD licence, in order to avoid scaring commercial users away”（DSLXC-17181），BSD 的宽松许可已经成为 Linux 内核治理中不可回避的参照系

2025 年 G. Branden Robinson 在 linux-man 的 AI 贡献政策讨论中把这一哲学张力推向当下——“projects that employ copyleft licenses foreclose contributions from people who hold that BSD-style licenses, or dedication to the public domain, are "the only true free[dom]"”（DSLXC-11717），而在更早的 1999 年 9 月 18 日 JF Martinez 已警告“BSD licensed software can be reused legally”（DSLXC-16431），Alan Cox 2007 年回应“Linux stealing our code”指责时辩护“BSD code is being used according to the BSD licence”（DSLXC-15440），Manfred Schwarb 更直白地表态“a BSD Licence is open source. In fact, it is more liberal than GPL”——这些散落四十年的英文引语共同勾勒出 BSD 许可证作为公共契约的独特位置：它不是最强硬的自由主义者，却是最慷慨的自由主义者，不是最成功的自由捍卫者，却是把自由真正交还给用户的那一份

“Trust the user”这四个字的力量，正在于它拒绝用法律文本去预设用户会做错误的事——BSD 假设使用者是理性的、负责任的、有能力做出正确选择的成年人，FreeBSD 的 code review 文化、CSRG 的可重复实验传统、Bostic 为了自由重写一切的决绝，都是这一假设在不同尺度上的兑现；当 Netflix 的 100Gbps CDN、PlayStation 的主机、Juniper 的路由器、现代 macOS 的 TCP/IP 栈与 Linux 内核中的双许可代码在同一时刻运行同一份或同一血统的 BSD 代码时，“信任”不再是一句许可文本的口号，而是数十年来工程师用代码本身书写的实践证据

**史观**：总纲第 14 条——哲学思潮：BSD 许可的 "Trust the user" 是自由意志主义哲学在软件领域的体现——相信技术使用者的判断权，不预设他们会滥用自由；这与 1.md 项目统摄史观中“信任个体体验”的立场有深层共鸣，自由不是被授予的，而是被承认的；总纲第 4 条——分离聚合是永恒规律，BSD 许可证文本从 4-clause 到 3-clause 到 2-clause 的削减历程是“分离”（不断剥离强制条款）与“聚合”（自由语义在 FreeBSD/Linux/macOS 中不断扩展）的辩证展现；总纲第 5 条——没有必然性，只有偶然性，1999 年 7 月 22 日 William Hoskins 签发删除函的那一刻是伯克利官僚系统的偶然行为，却在四十年间重塑了全球软件的许可版图；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，“BSD 许可体现信任哲学”的叙事本身是史家基于当下邮件列表史料的形式主义建构，实际 BSD 许可证的工程效应须与 BSD 代码被“夺走”并变为专有软件的事实并置审视

**辨析**：常见误解称“BSD 许可不保护自由”——这是用 GPL 的自由观来评判 BSD；BSD 认为真正的自由包括选择闭源的自由——如果我只能以特定方式使用代码，那不是真自由；当然，这也意味着 BSD 代码可能被“夺走”并变成专有软件（JF Martinez 1999 年已警告 "BSD licensed software can be reused legally"），但 BSD 社区认为这是自由的代价，从长期看开放协作的价值会胜出——这一点已被 Branden Robinson 2022 年“The BSD camp did ultimately win the copyleft argument after all”的判断与 Linux 内核四十年的双许可实践部分验证；本小节引用的邮件列表当事人为 Colomar、Ingo Schwarze、Branden Robinson、Mackerras、Cox、McHardy、Woodhouse、Schwarb 等 Linux 内核社区参与者，其论断反映的是 Linux 侧对 BSD 许可的理解与再解读，Berkeley 与 FreeBSD 社区自身对 "Trust the user" 的自我阐释须以 FreeBSD Foundation 官方文本与 CSRG 一手文献交叉核验
