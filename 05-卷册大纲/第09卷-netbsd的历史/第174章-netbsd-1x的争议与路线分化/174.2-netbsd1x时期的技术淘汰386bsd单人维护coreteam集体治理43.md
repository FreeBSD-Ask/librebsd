## 174.2.1 386BSD 单人维护 → NetBSD Core Team 集体治理（1993-1994）

**要点**：386BSD 由 Bill Jolitz 单人维护，1992 年后因 Jolitz 个人原因长期停滞，补丁积压、新硬件支持缺失；1993.4 Chris Demetriou、Adam Glass（亚当·格拉斯）、Charles Hannum 等伯克利学生从 386BSD 0.1 fork 创建 NetBSD，建立 Core Team 集体决策机制与 committer 治理结构；NetBSD Core Team 由创始成员协商产生，首批包括 Demetriou、Glass、Hannum、Theodore Ts'o 等；从单人维护到集体治理的过渡使 NetBSD 摆脱 386BSD 的“单点故障”，奠定项目长期延续的组织基础

## 174.2.2 4.3BSD-Net/2 基础 → 4.4BSD-Lite 基础迁移（1994-1995）

**要点**：386BSD 基于 4.3BSD-Reno 与 Net/2，含 USL 诉讼潜在争议代码；NetBSD 0.8 初期仍基于 Net/2，1994 年 USL 诉讼和解后 CSRG 发布 4.4BSD-Lite（1994.6）与 4.4BSD-Lite2（1995.5）；NetBSD 1.0 完成向 4.4BSD-Lite 基础的迁移，移除 Net/2 争议代码；同期 FreeBSD 亦完成类似迁移；4.4BSD-Lite 迁移使 NetBSD 获得法律洁净的代码基础，但付出短期代码替换工程代价

**史料**：USL v. BSDi 诉讼档案与 1994.1 和解协议；4.4BSD-Lite Release Notes（1994.6）；NetBSD 1.0 Release Notes 迁移说明；CSRG 末期代码发布记录 ［A］

**史观**：总纲第 12 条——法律结构：USL 诉讼与 4.4BSD-Lite 发布作为法律结构事件重塑 BSD 代码基础；总纲第 1 条——偶然性改写历史：USL 诉讼和解是偶然事件，但其推动的代码基础迁移决定 NetBSD 后续发展

**辨析**：NetBSD 完成向 4.4BSD-Lite 迁移的具体版本存在叙事分歧——部分资料称 1.0 完成，部分称 1.1 完成，需对照 1.0 Release Notes 与源码 commit 核验；4.4BSD-Lite 与 4.4BSD-Lite2 的差异在 NetBSD 迁移中的具体作用需考据

**文献**：4.4BSD-Lite Release Notes；USL v. BSDi 案件档案；NetBSD 1.0 Release Notes［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 174.2.3 补丁包发布 → CVS 版本控制引入（1993-1994）

**要点**：386BSD 采用补丁包（patchkit）发布模式，补丁由 Jolitz 个人整合，难以追溯版本历史；NetBSD 1993 年创建后即引入 CVS 作为版本控制系统，建立 commit log、分支、标签机制；CVS 引入使 NetBSD 开发过程可追溯、可回溯、可协作，告别补丁包时代；CVS 仓库托管于 anoncvs.netbsd.org，通过 anoncvs 协议公开访问；NetBSD 是早期采用 CVS 的开源项目之一，与 FreeBSD 共同推动 CVS 在 BSD 生态的普及

**史料**：NetBSD CVS 仓库早期 commit log；anoncvs.netbsd.org 早期访问记录；386BSD 补丁包发布档案；NetBSD 1993-1994 邮件列表 CVS 讨论帖 ［A］

**史观**：总纲第 17 条——形式与内容：CVS 作为“形式”（版本控制框架）改变了开发“内容”（代码协作方式）；总纲第 8 条——社区文化即技术资产：CVS 公开访问机制作为社区文化资产降低了贡献门槛

**辨析**：NetBSD 引入 CVS 的具体时间存在叙事分歧——部分资料称 1993.4 项目创建即引入，部分称 1993 年中期引入，需对照最早 commit log 核验；CVS 与同期 RCS、SCCS 的选择动机需考据

**文献**：NetBSD CVS 仓库归档；386BSD 补丁包档案；Brian Berliner“CVS II: Parallelizing Software Development”（1990）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 174.2.4 单一 NetBSD 项目 → OpenBSD 独立 fork（1994.12-1996.7）

**要点**：Theo de Raadt（西奥·德·若特） 作为 NetBSD 创始成员之一，1994.12.23 被 Core Team 以“沟通风格问题”为由通过投票撤销 commit 权限；de Raadt 此后无法继续贡献 NetBSD，1995 年下半年开始筹备 fork，1996 年 7 月正式发布 OpenBSD 1.2（首个正式发行版）；OpenBSD 从 NetBSD 1.0 代码基础 fork，专注于代码审计与安全；fork 使 BSD 生态从 NetBSD/FreeBSD 两强格局演变为三足鼎立；从单一项目到独立 fork 的“淘汰”是社区治理失败的产物，亦是 BSD 多元化的契机

**史料**：de Raadt 撤权事件邮件存档（core 与 tech 邮件列表）；NetBSD Core Team 1994.12.23 决议记录；OpenBSD 创建公告（1996 年）；de Raadt 公开演讲与回应；OpenBSD 官方 changelog（openbsd.org/plus.html）；netbsd.duckdb netbsd-src 仓库 commits 表 deraadt 活动验证（首条 1993-04-02 commit 355265a86628，末条 1994-12-17 commit 699d2a37b0e3，共 2757 条 commit，末条早于 1994.12.23 决议 6 天）；openbsd.duckdb openbsd-src 仓库 commits 表最早 commit 1995-10-18T08:37:01Z（commit df930be708d5，author = deraadt），当日 deraadt 连续提交 10+ 条 commit（10:39、10:42、10:52、10:54、10:58、11:03、11:05、12:19、12:22 等），可视为 OpenBSD 仓库正式启动的代码级证据 ［A］

**史观**：总纲第 2 条——分离与聚合：撤权事件触发分离，OpenBSD 创建体现分离与聚合的辩证；总纲第 10 条——边缘者贡献：de Raadt 作为被边缘者通过 OpenBSD 获得新的贡献空间；总纲第 25 条——0 信任原则：fork 叙事需考据，撤权原因在不同叙事中差异较大

**辨析**：撤权的具体原因在不同叙事中差异较大——部分归因于沟通风格，部分归因于技术分歧，部分归因于项目治理分歧；OpenBSD 首次正式发布日期在不同叙事中存在分歧——部分早期资料误作 1996.5，部分资料区分 OpenBSD 1.1 CVS 标签（1995.10.18）与 OpenBSD 1.2 首次正式发行（1996.7），需对照 OpenBSD 官方档案进一步核验。经 openbsd.duckdb openbsd-src 仓库 commits 表验证：1995.10.18 实为 openbsd-src 仓库首条 commit 时间（即 fork 实际启动日），与 OpenBSD 1.1 CVS 标签日期 1995.10.18 的叙事吻合，但此非 OpenBSD 1.1 发布日期；OpenBSD 1.1 是 fork 后首个公开版本（依 OpenBSD 官方档案，1996 年 1 月发布），OpenBSD 1.2 于 1996 年 7 月发布；故“1995.10.18”对应 fork 启动，“1996.1”对应 1.1 发布，“1996.7”对应 1.2 发布，三者各自指代不同事件，非混用；deraadt 在 netbsd-src 末条 commit 1994-12-17 与 1994.12.23 决议日期吻合（差 6 天），deraadt 在 openbsd-src 首条 commit 1995-10-18 与“1995 年下半年开始筹备 fork”叙事吻合，存疑已解决；但撤权原因的“沟通风格/技术分歧/治理分歧”三分法仍需对照原始邮件存档最终核验；OpenBSD 与 NetBSD 1.0 的代码 diff 需考据
