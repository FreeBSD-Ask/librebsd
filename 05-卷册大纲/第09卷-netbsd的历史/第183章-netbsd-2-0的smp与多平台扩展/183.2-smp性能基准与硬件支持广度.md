# 183.2 SMP 性能基准与硬件支持广度

**要点**：NetBSD 2.x/3.x 时期 SMP 性能基准在 2-8 核机器上较 FreeBSD 5.x/6.x 落后，但在嵌入式 ARM/MIPS 多核场景占优；硬件支持广度（ports 数量）是同期 BSD 中最广；NetBSD 的跨平台能力不仅体现在 src 仓库的 ports 数量上，亦体现在 pkgsrc 跨平台包管理系统的规模上——pkgsrc 作为 NetBSD 的跨平台包管理系统，可独立于 NetBSD 操作系统运行于 Linux、macOS、IRIX、Solaris、FreeBSD 等多种平台，是 NetBSD “of course it runs NetBSD” 文化在包管理层面的延伸

**史料**：Phoronix、BSD News 等第三方基准测试；NetBSD/doc/PLATFORMS 文件；tech-perform 邮件列表；**bsd_commits.db** 查询 L1.1.1 显示：netbsd-src 2004 年 commit_count = 37,918，2005 年 = 30,344，2006 年 = 30,561，2007 年 = 28,670，2008 年 = 26,543，2004-2008 年间 commit 量从 37,918 降至 26,543（累计降幅 30.0%），反映 2.x-3.x 时期社区投入持续收缩；**bsd_commits.db** 查询 L2.3.1.smp 显示：netbsd-src 2005 年 SMP 相关 commit = 15，2006 年 = 8，2007 年 = 38（峰值），2008 年 = 24（较 2007 年下降 36.8%），SMP commit 量波动反映 SMP 工作的阶段性投入而非持续线性投入；统计结论 [E-15]: netbsd-pkgsrc 仓库总 commit 数 1,222,307（截至 2026-07-27 查询），为 4 大 BSD ports/pkg 仓库中 commit 累计最高者（freebsd-ports 784,191、openbsd-ports 210,982、dragonfly-dports 606,813），反映 pkgsrc 作为 NetBSD 跨平台包管理系统的长期工程投入规模，本章时期（2003-2008）的 pkgsrc commit 活动构成此总量的中段 ［A］

**史观**：总纲第 14 条商业与社区的张力，性能落后反映资源分散，但广度优势反映社区价值观；统计结论印证：E-15（netbsd-pkgsrc 总 commit 数 1,222,307 为 4 BSD ports/pkg 仓库最高）反映 NetBSD 的跨平台能力不仅体现在内核 ports 数量上，亦体现在 pkgsrc 包管理系统的工程规模上——pkgsrc 的跨平台特性（Linux、macOS、IRIX、Solaris 等多平台支持）与本章“硬件支持广度”叙事形成数据层面呼应，0 信任原则适用：commit 量反映工程投入规模，不等于包质量或用户采用率

**辨析**：基准测试的硬件配置差异需对照原始测试脚本核验，不得直接采信结论。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2004-2008 年 commit 量可能不完整；commit 量持续下降与“性能落后”叙事方向一致，但 commit 量下降不等于性能下降——性能取决于关键路径优化而非 commit 总数；L2.3.1.smp 查询基于 message_subject LIKE 匹配，2004-2008 年 SMP commit 数字均为下限，实际涉及 SMP 的 commit 可能更多；2007 年 SMP commit 峰值（38）需对照 tech-smp 邮件列表核验具体项目。统计结论 [E-15] 局限性继承：netbsd-pkgsrc 总 commit 数 1,222,307 为全期累计值，本章时期（2003-2008）的 pkgsrc commit 量仅为此总量的一部分，累计值不反映本章时期 pkgsrc 开发活跃度；pkgsrc commit 量高于 freebsd-ports（784,191）反映 pkgsrc 仓库的 commit 粒度可能更细（如单个软件包更新即产生一次 commit），不等于 pkgsrc 软件包数量或质量优于 freebsd-ports；pkgsrc 的跨平台支持范围（Linux、macOS 等）与 freebsd-ports 主要服务 FreeBSD 的定位不同，commit 量对比须结合仓库定位差异解读
