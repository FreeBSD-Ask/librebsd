# 177.3 NetBSD 嵌入式市场时期的技术淘汰——商业 UNIX 嵌入式 →NetBSD 开源嵌入式、单平台嵌入式 → 多平台嵌入式、传统嵌入式 RTOS→NetBSD 嵌入式、Wasabi Systems 商业支持模式（1998-2004）

## 177.3.1 商业 UNIX 嵌入式 → NetBSD 开源嵌入式（1998-2004）

**要点**：1990 年代嵌入式市场由商业 UNIX（如 QNX、VxWorks、pSOS、LynxOS）与商业 BSD（如 BSD/OS）主导，许可证费用高昂；NetBSD 凭借 BSD 许可证与可移植性优势进入嵌入式市场，1998-2004 年间在 Dreamcast、Zaurus、Cobalt Qube 等设备部署；从商业 UNIX 嵌入式到 NetBSD 开源嵌入式的 “淘汰” 降低嵌入式设备开发成本，但 NetBSD 缺乏商业支持体系

**史料**：NetBSD 嵌入式部署列表（www.netbsd.org/gallery/in-where.html）；tech-embed 邮件列表 1998-2004；Dreamcast/Zaurus/Cobalt Qube 部署档案；BSD/OS 商业模式衰退记录；netbsd.duckdb 查询 L3.2.1 显示：1993-2004 年间（即 NetBSD 1.x 嵌入式市场拓展期）4 大 BSD src 仓库的商业实体 commit 占比 commercial_pct 全部为 0.00%（1998 年 commercial_commits = 0/total = 113,492，2000 年 = 0/195,667，2002 年 = 0/264,813，2004 年 = 0/280,209；〔存疑：上述 total 值与 4 库 src 口径复算值 47,333/94,116/122,394/150,661 存在差异，查询口径未标注，待复核〕），2005 年方首次出现非零商业实体 commit（commercial_commits = 153/total = 267,087，约 0.057%），反映 “1998-2004 年 NetBSD 嵌入式市场商用部署” 在代码层面前期主要表现为厂商内部使用而非回流上游，BSD 许可证不强制回馈的特性使嵌入式厂商贡献长期为零；netbsd.duckdb 查询 L3.3.1 显示：4 大 BSD src 仓库 committer_date 时区分布前 5 为 -07:00（788,356 commit/17,719 贡献者）、+02:00（426,606/16,727）、-08:00（381,184/11,405）、+01:00（380,019/15,941）、-04:00（181,933/9,386），反映 BSD 贡献者主要集中在北美（-07/-08/-04/-05 时区，对应美国/加拿大）与欧洲（+01/+02 时区，对应西欧/中欧），与嵌入式厂商主要分布（北美/日本/欧洲）的地理格局吻合〔存疑：库内 committer_date 后缀实查全为 Z（UTC），且前 5 时区计数合计超出库总量，该时区分布数据来源待核对〕；统计结论 [C-04]: netbsd-src 仓库总 commit 数 773,683（截至 2026-07-27 查询），为 4 大 BSD src 仓库中 commit 累计最高者，本章时期（1998-2004）的 commit 活动构成此总量的早期部分；统计结论 [C-09]: netbsd-src 月度 commit 量 Mann-Kendall 趋势检验呈显著下降趋势（Sen's slope=−7.27/月，p<0.001，95% CI [−8.15, −6.42]），本章时期（1998-2004）处于该长期下降趋势的中段，反映 NetBSD 在嵌入式市场拓展期主仓开发活跃度的结构性收敛 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：重挂待复核〕：NetBSD 开源嵌入式与商业 UNIX 嵌入式的张力体现商业-社区张力；总纲第 13 条——法律与道德是利益分配：BSD 许可证允许商业使用而不强制回馈，塑造 NetBSD 嵌入式市场模式

**辨析**：NetBSD 在嵌入式市场的具体部署数量缺乏权威统计——需对照厂商产品文档与 firmware 拆解核验；BSD/OS 衰退的具体时间需对照 BSDi 与 Wind River 收购档案核验；L3.2.1 查询的商业实体识别基于固定邮箱域名列表（Netflix/Juniper/NetApp/EMC/Google/Apple/Microsoft 等），1993-2004 年 commercial_pct = 0.00% 反映此时期 BSD src 仓库无上述大公司邮箱域名的 commit，但嵌入式厂商（如 Dreamcast 的 Sega、Cobalt 的 Sun/Cobalt Networks、Zaurus 的 Sharp）的工程师可能使用个人邮箱或公司未列入识别列表的邮箱提交，故 0.00% 不等于 “无商业参与”，仅反映 “无可识别大公司邮箱 commit”；L3.3.1 查询基于 committer_date 时区，但 GitHub 镜像 committer_date 存在被同步重写的风险（如 netbsd-src GitHub 镜像 committer_date 异常），故时区分布应与 author_date 时区交叉验证；时区不等于地理位置，远程办公者可能用时区不反映实际所在地。统计结论 [C-09] 局限性继承：Mann-Kendall 趋势检验 p < 0.001 显著仅反映 netbsd-src 月度 commit 量存在统计学显著的下降趋势，不等于该下降趋势在 1998-2004 年本章时期内单调递减——Sen's slope = −7.27/月是全期（1993-2026）平均斜率，本章时期内年度 commit 量可能存在波动（如 2000 年与 2002 年的峰值），须结合 L1.1.1 年度 commit 量数据交叉验证；趋势检验不区分 “开发衰退” 与 “开发模式转型”（如向 Mercurial 迁移的过渡期影响），下降原因须结合 commit message 主题词与文件路径分析

**文献**：NetBSD 嵌入式部署页面；BSD/OS 商业史；嵌入式 RTOS 市场报告 1998-2004；netbsd.duckdb 数据分析·深层信息挖掘.md §L3.2.1（商业实体 commit 占比 1993-2004 年）、§L3.3.1（committer_date 时区偏移分布前 30 时区）；netbsd.duckdb 数据分析·推断性统计.md Task 5 SubTask 5.2（统计结论 C-09：netbsd-src Mann-Kendall 趋势下降 Sen's slope = −7.27/月 p < 0.001 95% CI [−8.15, −6.42]，Python: pymannkendall 1.4.3）〔存疑：所引《netbsd.duckdb 数据分析·深层信息挖掘.md》《netbsd.duckdb 数据分析·推断性统计.md》两份分析文档全库未检出，断链待补〕［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 177.3.2 单平台嵌入式 → 多平台嵌入式（Dreamcast/Zaurus/Cobalt Qube）

**要点**：传统嵌入式设备多采用单平台定制 RTOS，新硬件需重写整个系统；NetBSD 凭借 MI/MD 分层架构，新平台仅需编写 MD 代码即可移植；1998-2004 年间 NetBSD/dreamcast（Hitachi SH-4）、NetBSD/zaurus（StrongARM/XScale）、NetBSD/cobalt（MIPS）等端口展示多平台嵌入式能力；从单平台嵌入式到多平台嵌入式的 “淘汰” 使 NetBSD 成为 “硬件无关” 嵌入式 OS 候选

**史料**：NetBSD/dreamcast 移植档案；NetBSD/zaurus 移植档案；NetBSD/cobalt 移植档案；MI/MD 分层架构文档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕

**史观**：总纲第 3 条——不存在进步，只有权力再分配〔存疑：重挂待复核〕：多平台嵌入式付出维护成本，但获得硬件无关性；总纲第 15 条——文化即形式主义：MI/MD 分层作为 “形式” 使嵌入式 “内容”（具体平台）可替换

**辨析**：各嵌入式端口的具体发布时间需考据——NetBSD/dreamcast、NetBSD/zaurus、NetBSD/cobalt 的具体 Release Notes 需对照核验；MI/MD 分层在嵌入式场景的实际工程收益需对照 commit log 核验

**文献**：NetBSD 嵌入式移植史料；MI/MD 分层设计文档；Dreamcast/Zaurus/Cobalt Qube 硬件文档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 177.3.3 传统嵌入式 RTOS → NetBSD 嵌入式（1998-2004）

**要点**：传统嵌入式 RTOS（VxWorks、pSOS、QNX）提供实时性与确定性，但缺乏网络协议栈与文件系统丰富度；NetBSD 提供完整 BSD 网络栈（TCP/IP、IPv6、IPSec）、文件系统（FFS、ext2fs、CD9660）、用户空间工具，适合需要 “类 UNIX” 功能的嵌入式设备；从传统 RTOS 到 NetBSD 的 “淘汰” 是功能丰富度与实时性的权衡——NetBSD 牺牲实时性换取功能丰富度

**史料**：NetBSD 网络协议栈与文件系统文档；VxWorks/QNX/pSOS 功能对比档案；嵌入式 RTOS 市场报告 1998-2004［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：重挂待复核〕：NetBSD 与传统 RTOS 的不同选择反映功能丰富度与实时性的政治选择；总纲第 3 条——不存在进步，只有权力再分配〔存疑：重挂待复核〕：NetBSD 选择功能丰富度付出实时性代价

**辨析**：NetBSD 与传统 RTOS 的性能对比需注意场景——实时性场景 RTOS 占优，网络与文件系统场景 NetBSD 占优；NetBSD 是否提供实时扩展（如 KURT 类补丁）需考据

**文献**：嵌入式 RTOS 比较研究；NetBSD 网络协议栈文档；Wind River VxWorks 产品资料［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 177.3.4 无商业支持体系 → Wasabi Systems 商业支持模式（2000 起）

  > Hello. Did YOU know that * This product includes software developed for the NetBSD Project by Wasabi Systems...
  >
  > ——jhawk, netbsd-src 仓库，2001-11-24T23:53:18Z

**要点**：NetBSD 缺乏商业支持体系是嵌入式市场应用的障碍；2000 年 Wasabi Systems 成立，提供 NetBSD 商业支持、定制开发、咨询与培训；Wasabi 模式借鉴 Red Hat 商业模式但规模较小，主要客户为嵌入式设备厂商；Wasabi 贡献了 NetBSD 嵌入式移植（PPC405GP walnut 端口等）、嵌入式优化等代码；Wasabi 模式是 NetBSD 早期商业-社区平衡的尝试，但因规模有限未能持续
