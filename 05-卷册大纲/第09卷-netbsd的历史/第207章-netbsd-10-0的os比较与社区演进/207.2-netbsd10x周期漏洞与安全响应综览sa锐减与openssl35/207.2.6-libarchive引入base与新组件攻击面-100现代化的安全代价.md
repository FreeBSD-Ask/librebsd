# 207.2.6 libarchive 引入 base 与新组件攻击面——10.0 现代化的安全代价

**要点**：NetBSD 10.x 周期 base 系统首次出现 libarchive 的 CVE 批量修复 commit（libarchive 组件本身自 2007 年 7 月 29 日即已在树中）——christos **2024 年 10 月 17 日** commit `0027e4741198090e484d64453c8e6188cf472274` “Import libarchive-3.7.7 (previous was 3.7.4)”将 libarchive 3.7.7 引入 base，处理 CVE-2024-20696 与 CVE-2024-26256；此后 libarchive 经历 3.8.3 升级（christos **2026 年 1 月 30 日** commit `75a373931726ec8acb5341934f94665c5f945ca8` “Import libarchive-3.8.3 (previous was 3.7.7)”，处理 CVE-2024-57970、CVE-2025-1632、CVE-2025-25724、CVE-2025-5914、CVE-2025-5915、CVE-2025-5916、CVE-2025-5917、CVE-2025-5918 等 8 个 CVE）；10.x 周期 libarchive 相关 CVE 至少 10 个，其中 CVE-2025-5914（CVSS 7.8 High）是 10.x 周期 libarchive 中评分最高的漏洞——这是一个 7.8 评分的 High 级漏洞，涉及 libarchive 库中的特定缺陷；**libarchive 在 9.x 周期未出现在 base CVE commit 中**——这表明 10.x 周期首次出现 libarchive 的 CVE 批量修复 commit，与 FreeBSD base 长期包含 libarchive（FreeBSD 14.x 周期 libarchive 是主要 CVE 来源之一）形成对比；**10.0 Wayland 实验性支持的攻击面**——NetBSD 10.0 引入 Wayland 实验性支持作为现代化硬件支持的一部分，但 Wayland 合成器与客户端协议栈作为新代码引入新攻击面［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］——netbsd.duckdb netbsd-src 仓库中 Wayland 相关 CVE commit 暂未在版本周期文件中体现，须对照源码核验

**史料**：**netbsd.duckdb** `commits` 表 netbsd-src 仓库 libarchive CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='netbsd-src' AND author_date>='2023-04-01' AND author_date<'2026-07-22' AND message_subject LIKE '%libarchive%' AND (message_body LIKE '%CVE-%' OR message_subject LIKE '%CVE-%') ORDER BY author_date ASC`——结果 christos 2024-10-17 commit `0027e4741198090e484d64453c8e6188cf472274` 与 `c0434ef09f56837f124152afe51846c6e10f54bd`（libarchive 3.7.7，CVE-2024-20696、CVE-2024-26256）、christos 2026-01-30 commit `75a373931726ec8acb5341934f94665c5f945ca8` 与 `f85a2b0cd72eb8a8b399642518267aa1a3dbec17`（libarchive 3.8.3，8 个 CVE）；NetBSD 10.0 Release Notes libarchive 与 Wayland 部分；libarchive Project. libarchive 3.7/3.8 Security Advisories ［A］

**史观**：技术选择的代价：libarchive 引入 base 是 10.0 现代化的代价——libarchive 提供归档格式支持（tar、cpio、zip 等），是现代软件包管理的基础组件，但引入 base 即引入新攻击面；这与 FreeBSD 14.x 周期 base 长期包含 libarchive（Heimdal、xz 等贡献组件）的“base 集成 + 贡献组件治理”哲学在路径上趋同，但 NetBSD 的 libarchive 引入时间晚于 FreeBSD；软件工程：10.0 Wayland 实验性支持作为新代码引入，其攻击面须在未来版本中持续审计——Wayland 协议栈涉及 IPC、图形缓冲区管理等复杂子系统，是新攻击面的潜在来源

**辨析**：**需精确说明 libarchive 引入 base 的时间与性质**：① **libarchive 引入时间**——版本周期文件显示 libarchive 3.7.4 是 10.x 周期前已存在的版本（commit message“previous was 3.7.4”表明 3.7.4 已在 base 中），3.7.7 是 10.x 周期内的首次升级而非首次引入；libarchive 首次引入 base 的时间经实测收口：netbsd-src 最早 libarchive 导入为 2007-07-29（“Import libarchive-2.2.5”，4b1264622e 前缀，libarchive 主题 commit 共 203 条） ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；② **libarchive CVE-2025-5914 的严重程度**——CVE-2025-5914 CVSS 7.8 High，是 10.x 周期 libarchive 中评分最高的漏洞，涉及 libarchive 库中的特定缺陷，攻击向量可能需要恶意归档文件；③ **与 FreeBSD 14.x 周期 libarchive 的对比**——FreeBSD 14.x 周期 libarchive 是 base 中主要 CVE 来源之一（SA-24:06.libarchive 等），NetBSD 10.x 周期 libarchive CVE 同样通过 vendor import 同步修复，未获 SA 编号；④ **Wayland 实验性支持的攻击面考据**——NetBSD 10.0 引入 Wayland 实验性支持，但 netbsd.duckdb netbsd-src 仓库中 Wayland 相关 CVE commit 暂未在版本周期文件中体现——可能 Wayland 实验性支持的代码量有限，或其漏洞尚未被审计发现 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；⑤ **新组件引入的工程伦理**——libarchive 与 Wayland 作为 10.0 新引入组件，其安全审计资源投入须与新代码量匹配，但 10.x 周期 SA 发布停滞（2025-2026 零 SA）可能反映审计资源不足 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
