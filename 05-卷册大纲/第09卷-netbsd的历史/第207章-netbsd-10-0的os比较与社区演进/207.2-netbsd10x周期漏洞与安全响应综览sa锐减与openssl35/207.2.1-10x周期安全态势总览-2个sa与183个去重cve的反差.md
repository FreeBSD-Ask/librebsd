**要点**：NetBSD 10.x 周期（**2023 年 4 月 1 日** 至 **2026 年 7 月 22 日**，覆盖 10.0 发布前后主流与稳定分支维护期）共发布 **仅 2 个 NetBSD-SA**——**NetBSD-SA2024-001**（**utmp_update(8)** 用户主机名验证不足）与 **NetBSD-SA2024-002**（OpenSSH CVE-2024-6387 regreSSHion）；官方存档中 **完全没有 NetBSD-SA2025 与 NetBSD-SA2026 条目**——这意味着 10.x 周期后两年（2025-2026）NetBSD 未发布任何官方安全公告；与此同时，**netbsd.duckdb** `commits` 表 netbsd-src 仓库统计显示 10.x 周期共 **93 条 CVE 相关 commit** 与 **6 条无 CVE 的 Security fix commit**，对应 **183 个去重 CVE**——这一“2 个 SA vs 183 个 CVE”的反差是 10.x 周期最显著的安全治理特征；NVD 元数据中 10.x 周期有 CVSS v3.x 评分的 CVE 仅 34 个（**0 个 Critical、21 个 High、9 个 Medium、4 个 Low**），其余 149 个 CVE 在本地 cvelistV5 镜像中无 CVSS v3 评分——无评分 CVE 占比 81.4%，远高于 9.x 周期的 76.1%（83/109），反映 10.x 周期大量 CVE 来自 OpenSSL 3.5 与 BIND 9.20 等新版本上游批量导入，NVD 评分滞后；**2 个 SA 均发布于 2024 年**——SA2024-001 针对 NetBSD 自有代码（**utmp_update(8)**），SA2024-002 针对贡献组件 OpenSSH regreSSHion，2025-2026 两年零 SA 发布反映 NetBSD Security Officer Team 进入“SA 发布停滞+vendor import 持续”的工作模式

**史料**：**netbsd.duckdb** `commits` 表 netbsd-src 仓库 10.x 周期 CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject, message_body FROM commits WHERE repo_name='netbsd-src' AND author_date>='2023-04-01' AND author_date<'2026-07-22' AND (message_subject LIKE '%CVE-%' OR message_body LIKE '%CVE-%') ORDER BY author_date ASC` 结果 93 条；NetBSD Security Advisories 官方存档 `原材料/研究/bsd漏洞史/官方公告/netbsd-sa.md` Grep 验证：查询 `NetBSD-SA2024` 结果 2 条（SA2024-001、SA2024-002），查询 `NetBSD-SA2025` 与 `NetBSD-SA2026` 结果均为 0 条——证实 2025-2026 两年零 SA 发布；版本周期文件 `原材料/研究/bsd漏洞史/版本周期/netbsd-10.x.md` 整理日期 2026-07-22，去重 CVE 数 183 ［A］

**史观**：总纲第 17 条——软件工程：10.x 周期“2 个 SA vs 183 个 CVE”的反差是 NetBSD 安全治理模式根本性转变的表征——从 9.x 周期的“SA 驱动 + 架构覆盖优先”模式转向“vendor import 驱动+SA 停滞”模式；这一转变与 FreeBSD 14.x 周期“主动审计 + 批量披露”（80 个 SA）模式形成两极对照——FreeBSD 在 14.x 周期主动扩大 SA 覆盖面，NetBSD 在 10.x 周期收缩 SA 发布至近乎停滞；社区治理：SA 发布停滞不等于安全维护停滞——10.x 周期 93 条 CVE commit 表明 Security Officer Team 仍持续通过 vendor import 同步上游修复，但 SA 作为“面向用户的正式安全公告”渠道近乎关闭，管理员须自行跟踪 commit log 而非依赖 SA 获知漏洞信息

**辨析**：**需严格区分**：① “SA 发布停滞”不等于“安全维护停滞”——10.x 周期 93 条 CVE commit 与 6 条 Security fix commit 证明安全维护仍在持续，但维护方式从“SA+ 二进制补丁”转向“vendor import commit”；② **2 个 SA 的归属辨析**——SA2024-001 针对 NetBSD 自有代码 **utmp_update(8)**，SA2024-002 针对贡献组件 OpenSSH regreSSHion（CVE-2024-6387），前者是 NetBSD 本地漏洞，后者是上游漏洞同步——两个 SA 的性质不同，但共同点是均发布于 2024 年，此后无新 SA；③ **与 9.x 周期 18 个 SA 的对比须考虑四个因素**：其一，10.x 周期 base 中贡献组件经 OpenSSL 3.5 与 BIND 9.20 激进升级后漏洞面虽扩大但由 vendor import 同步修复，未触发 SA 流程；其二，NetBSD Security Officer Team 在 2025-2026 年间可能将大量 CVE 修复视为“上游修复 + 下游同步”而非“NetBSD 特有漏洞”，故不发布 SA；其三，10.x 周期 NetBSD 自有代码漏洞披露率确实降低——除 SA2024-001 外无其他自有代码 SA；其四，SA 发布停滞可能反映 Security Officer Team 人力资源约束而非策略调整 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；④ **无评分 CVE 占比 81.4% 的归因**——149 个无评分 CVE 中相当部分来自 OpenSSL 3.5 系列（2025-2026 年新发布版本，NVD 评分滞后）与 BIND 9.20 系列，这是数据采集时差而非漏洞实际严重程度低
