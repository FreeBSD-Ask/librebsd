## 175.4.1 CVE 编号体系普及与 NetBSD 2.x 安全治理转型（2000-2006）

**要点**：NetBSD 2.x 版本周期（2000-12-01 至 2006-12-01）恰逢 CVE 编号体系在 BSD 项目中系统化普及——netbsd.db netbsd-src 仓库查询显示此周期内 89 条 CVE commit 与 161 条 Security fix commit，去重 CVE 16 条（全部无 CVSS v3 评分，反映 NVD 对 2006 年前 CVE 的评分回填滞后），3 条早期漏洞补遗覆盖 2004-2006 年；与 1.x 时期 “SA 驱动” 模式不同，2.x 时期 commit message 开始显式引用 CVE 编号（如 yamt 2004-03-11 commit `aad9f63765c96a39eb18f32b8427fb5f1e697078` 直接标注 "CVE-2002-0429"），反映 NetBSD 安全治理从 “SA 公告驱动” 向 “CVE 编号驱动” 的渐进转型；此时期 pkgsrc 早期发展（1997-2004）与 NetBSD 2.x 版本周期重叠，pkgsrc 跨平台软件包分发使漏洞修复须在 NetBSD 主仓与 pkgsrc 软件包树两处同步推进

**史料**：netbsd.db netbsd-src 仓库 commits 表（2000-2006 年 CVE commit 89 条、Security fix commit 161 条）；早期漏洞补遗归档（原材料/研究/bsd 漏洞史/版本周期/netbsd-2.x.md）；yamt commit `aad9f63765c96a39eb18f32b8427fb5f1e697078`（2004-03-11，CVE-2002-0429 修复） ［A］

**史观**：总纲第 17 条——软件工程：CVE 编号体系在 NetBSD 2.x 时期的普及是安全治理形式主义化的关键一步——将 “漏洞标识” 从项目内部 SA 编号统一为跨项目通用编号，使漏洞修复的可追溯性从 NetBSD 社区内部扩展至整个安全生态；总纲第 8 条——社区文化即技术资产：commit message 显式引用 CVE 编号的习惯养成是 NetBSD 安全文化从 “自洽” 走向 “开放协作” 的标志

**辨析**：89 条 CVE commit 与 16 条去重 CVE 的差距反映 “同一 CVE 多分支 pullup” 的工程实践——NetBSD 维护 netbsd-2-0、netbsd-2-1、netbsd-3 等多个稳定分支，同一漏洞修复须在多分支重复提交；16 条去重 CVE 全部无 CVSS v3 评分系 NVD 对 2006 年前 CVE 的评分回填滞后所致，本节不臆造评分；【0 信任原则·CVSS 评分缺失】无评分不等于低风险——CVE-2002-0429（权限提升）与 CVE-2006-5794（权限提升）的 “权限提升” 机制类型本身暗示较高风险，但具体评分须待 NVD 回填或对照 CVSS v2 评估

**文献**：bsd_commits.db netbsd-src 仓库 commits 表；早期漏洞补遗归档 netbsd-2.x.md ［A］

## 175.4.2 IPsec/PPP 漏洞群与 NetBSD 2.x 网络栈安全（2006）

**要点**：NetBSD 2.x 后期网络栈漏洞集中在 IPsec 与 PPP 子系统——CVE-2006-0905（IPsec 重放序列号处理缺陷，攻击者可绕过重放保护伪造已接收的 IPsec 数据包，bsd_commits.db 显示 rpaulo 2006-03-23 主仓 commit `51a2954a4da7db96e86a7364da01c209e7e16dcd`，riz 2006-03-28 至 03-30 多次 pullup 至 netbsd-2-0、netbsd-3 分支 commit `c047d4b2f8485ad052bb82cec4d05eccd893896c`、`db756ebe5a82afb9bf1342ac34145c28f330416a` 等，commit subject 明确引用 "FreeBSD SA-06:11 and CVE-2006-0905"，反映 NetBSD 与 FreeBSD 在 IPsec 实现上的代码共享与漏洞协同修复）；CVE-2006-4304（内核 PPP 代码缓冲区溢出，与 ISDN PPP 接口共享同一 PPP 实现，adrianp 2006-08-23 commit `3d8cbc06bac2eec7eff2e941a02d16f2b121c09e`，tron 同日多次 pullup commit `ee6be1e5c2479dfd8e97a410943129710a20ae66` 等）；此时期 NetBSD 网络栈与 FreeBSD、OpenBSD 存在代码共享，IPsec 实现源自 KAME 项目，PPP 实现的历史代码共享导致同源漏洞跨项目传播

**史料**：netbsd.db netbsd-src 仓库 rpaulo commit `51a2954a4da7db96e86a7364da01c209e7e16dcd`（2006-03-23，CVE-2006-0905）；riz pullup commit `c047d4b2f8485ad052bb82cec4d05eccd893896c`（2006-03-28，CVE-2006-0905 netbsd-2-0 分支）；adrianp commit `3d8cbc06bac2eec7eff2e941a02d16f2b121c09e`（2006-08-23，CVE-2006-4304 PPP）；FreeBSD SA-06:11 公告原文 ［A］

**史观**：总纲第 17 条——软件工程：IPsec/PPP 漏洞群揭示 “代码共享双刃剑”——KAME IPsec 与历史 PPP 代码在 BSD 项目间的共享加速了功能传播，但也使同源漏洞跨项目扩散，FreeBSD SA-06:11 与 NetBSD CVE-2006-0905 修复的协同体现 BSD 家族的代码互鉴；总纲第 7 条——BSD 谱系：NetBSD commit subject 显式引用 FreeBSD SA 编号反映 BSD 家族安全响应的协作传统

**辨析**：CVE-2006-0905 的 commit subject "FreeBSD SA-06:11 and CVE-2006-0905: update the replay sequence number" 表明 NetBSD 该漏洞修复直接借鉴 FreeBSD SA-06:11 公告，但两项目 IPsec 实现是否完全共享代码须对照源码 diff 核验——KAME 项目是 FreeBSD/NetBSD/OpenBSD IPsec 实现的共同源头，但各项目在 KAME 基础上的本地化修改可能使漏洞影响范围不同；CVE-2006-4304 的 PPP 漏洞涉及 ISDN PPP 接口，反映 NetBSD 在嵌入式与通信设备市场的 PPP/ISDN 代码维护压力；【0 信任原则·CVSS 评分缺失】两条 CVE 均无 CVSS v3 评分，但 “绕过重放保护” 与 “内核缓冲区溢出” 的机制类型本身暗示较高风险

**文献**：netbsd.db netbsd-src 仓库 rpaulo、riz、adrianp、tron commit 记录；FreeBSD SA-06:11 公告；CVE-2006-0905、CVE-2006-4304 NVD 条目 ［A］

## 175.4.3 游戏与用户态工具漏洞群（2006）

**要点**：NetBSD 2.x 时期一批游戏与用户态工具漏洞被披露并修复——CVE-2006-1539（**tetris(6)** 游戏分数文件读取越界，drochner 2006-06-01 commit `3f13a4cf7b1bc96d4abe7fee82708310fd238bf7`，commit subject "Better check data read from tetris.scores before use as array indices"，tron 2006-06-08 多次 pullup 至稳定分支）；CVE-2006-1744（**sail(6)** 游戏缓冲区溢出，drochner 2006-04-20 commit `d8da09bdafc783cfa2e3861e01daf1c86b9ad07e`，commit subject "fix buffer overflow (CVE-2006-1744), from Debian"，snj 2006-04-25 至 04-26 多次 pullup）；这些漏洞虽影响有限（游戏程序通常不用于生产环境），但反映 NetBSD 2.x 时期对基本系统中所有 setuid/setgid 程序的系统性安全审计，与 OpenBSD 同期的全面代码审计文化形成呼应

**史料**：netbsd.db netbsd-src 仓库 drochner commit `3f13a4cf7b1bc96d4abe7fee82708310fd238bf7`（2006-06-01，CVE-2006-1539 tetris）；drochner commit `d8da09bdafc783cfa2e3861e01daf1c86b9ad07e`（2006-04-20，CVE-2006-1744 sail）；tron pullup commit `1b2544f35aaafffc0d442fa7a0c1e625b76fa7e6`（2006-06-08，CVE-2006-1539 netbsd-2-0 分支）；snj pullup commit `b6ebe409abdb3b9d1189aa467b125b5cdb2cdb9a`（2006-04-25，CVE-2006-1744 netbsd-2-0 分支） ［A］

**史观**：总纲第 17 条——软件工程：游戏程序漏洞的修复反映 NetBSD 安全审计的 “无死角” 原则——即使是低权限游戏程序也须遵循边界检查规范，此与项目统摄史观 “形式主义化” 在安全治理中的体现一致——将安全检查从 “高风险组件” 扩展至 “全部代码” 的形式主义化实践；总纲第 8 条——社区文化即技术资产：NetBSD 对游戏程序漏洞的修复态度与 OpenBSD 的全面代码审计文化同源

**辨析**：CVE-2006-1744 的 commit subject "fix buffer overflow (CVE-2006-1744), from Debian" 表明 NetBSD 该修复借鉴自 Debian 项目，反映跨发行版安全协作——NetBSD 与 Debian 在用户态工具代码上存在共享（如 GNU 工具），同源漏洞须跨发行版协同修复；CVE-2006-1539 的 tetris 分数文件越界漏洞虽影响有限，但揭示 “信任本地文件内容” 的通用风险——任何读取用户可写文件的程序都须验证数据完整性；【0 信任原则·CVSS 评分缺失】两条 CVE 均无 CVSS v3 评分，但游戏程序漏洞的实际风险较低（通常无 setuid 权限）

**文献**：netbsd.db netbsd-src 仓库 drochner、tron、snj commit 记录；CVE-2006-1539、CVE-2006-1744 NVD 条目 ［A］

## 175.4.4 内核权限提升与 httpd 漏洞群（2002-2006）

**要点**：NetBSD 2.x 时期内核权限提升与用户态守护进程漏洞并行——CVE-2002-0429（**PSL_NT** 标志位清理缺陷，yamt 2004-03-11 commit `aad9f63765c96a39eb18f32b8427fb5f1e697078`，commit subject "before resuming from failure during return to user mode, clear PSL_NT. it can"，本地用户可利用系统调用失败恢复路径中的标志位残留获取内核权限，反映 NetBSD 2.x 对 i386 架构返回用户态路径的深度审计）；一批 httpd 相关漏洞（CVE-2006-2937、CVE-2006-2940、CVE-2006-3738、CVE-2006-4343，均由 tron 2006-09-29 commit `897b34d36dc3e0cbe4b31f2d4a1a8d00b2fab107` 统一修复，反映 “同组件多漏洞合并修复” 实践）；CVE-2006-5794（httpd 权限提升，1be366570b9fd1861a64526dc60281a17d031b94，2006-11-14）；这些漏洞反映 NetBSD 2.x 时期对内核返回用户态路径与基本系统 httpd 守护进程的系统性安全审计

**史料**：netbsd.db netbsd-src 仓库 yamt commit `aad9f63765c96a39eb18f32b8427fb5f1e697078`（2004-03-11，CVE-2002-0429 PSL_NT）；tron commit `897b34d36dc3e0cbe4b31f2d4a1a8d00b2fab107`（2006-09-29，CVE-2006-2937/2940/3738/4343 httpd 群）；commit `1be366570b9fd1861a64526dc60281a17d031b94`（2006-11-14，CVE-2006-5794 httpd 权限提升） ［A］

**史观**：总纲第 17 条——软件工程：CVE-2002-0429 的 PSL_NT 标志位缺陷揭示 “系统调用失败恢复路径” 作为安全审计盲区——失败路径中的状态清理不完整可被利用获取权限，此为 “错误处理代码本身包含错误” 的典型范式；总纲第 25 条——0 信任原则：httpd 漏洞群反映 “基本系统守护进程” 作为攻击面的持续存在——NetBSD 基本系统自带的 httpd 虽功能简陋但仍须遵循安全规范

**辨析**：CVE-2002-0429 的 CVE 编号年份（2002）与修复 commit 日期（2004-03-11）相差近 2 年，反映该漏洞可能在 2002 年即被披露但修复延迟至 2004 年，或 CVE 编号系事后回溯分配——具体时序须对照 NetBSD-SA 公告与 NVD 条目核验；httpd 漏洞群（CVE-2006-2937/2940/3738/4343）由同一 commit `897b34d36dc3e0cbe4b31f2d4a1a8d00b2fab107` 修复，反映 “同组件多漏洞合并修复” 的工程效率，但该 commit 是否完全修复所有子漏洞须对照 NVD 条目逐一核验；【0 信任原则·CVSS 评分缺失】全部 CVE 均无 CVSS v3 评分，但 “内核权限提升”（CVE-2002-0429）与 “httpd 权限提升”（CVE-2006-5794）的机制类型本身暗示较高风险

**文献**：netbsd.db netbsd-src 仓库 yamt、tron commit 记录；CVE-2002-0429、CVE-2006-2937/2940/3738/4343/5794 NVD 条目 ［A］
