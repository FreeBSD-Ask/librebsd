# 187.7 NetBSD 习俗特殊文化考据

本节内容与相关章节关于 NetBSD 习俗特殊文化考据的论述高度重合，为避免重复，本节不重复展开该考据，仅保留与操作系统比较视角相关的补充要点。

### 核心内容

以下四类习俗的详细五字段考据见相关章节关于 NetBSD 习俗特殊文化考据的讨论，本节从操作系统比较视角列其要点：

- 187.7.1 “Of course it runs NetBSD” 口号传统与 port naming 约定（i386、amd64、evbarm、sparc64、vax、pmax、hp300、mac68k、amiga、atari 等 50+ ports）
- 187.7.2 pkgsrc 季度分支传统（1997-08 启用，2003-12-02 pkgsrc-pmc 成立，扩展至 Solaris/Linux/Darwin/FreeBSD/OpenBSD/DragonFlyBSD 等 16+ 平台）
- 187.7.3 NetBSD Foundation 选举传统（1995 年注册，2 年任期，Board of Directors 由 NetBSD Developer 社区选举，IRC 召开 AGM）
- 187.7.4 Tainted Code 政策传统：AI 生成代码的伦理边界（2024-05 修订 CoC 引入 “tainted code” 概念，借鉴 Linux 内核 “tainted kernel”）

## 187.7.5 项目统摄史观综合审视：NetBSD 习俗的可移植性哲学与制度创新（操作系统比较视角）

**要点**：综合项目史观总纲审视，从操作系统比较视角看，NetBSD 习俗特殊文化呈现 “可移植性哲学” 与 “制度创新” 的双重结构——可移植性哲学维度：50+ ports 命名传统、“Of course it runs NetBSD” 口号、pkgsrc 跨平台扩展皆是 NetBSD “在所有硬件上运行” 哲学的具体显现，这一哲学是 NetBSD 自 1993 年项目成立即确立的核心定位；制度创新维度：pkgsrc-pmc（2003 年成立）、Foundation 董事会选举（2 年任期）、Tainted Code 政策（2024 年 5 月引入，政策存在性存疑 [存疑脚注]）皆是 NetBSD 在治理制度上的早期创新，Tainted Code 政策更是 BSD 项目对 AI 时代代码伦理的最早制度化回应；NetBSD 习俗的可移植性哲学与制度创新在本体论上地位相等，无道德高下之分——可移植性哲学的代价是维护开销（50+ ports 维护负担），制度创新的代价是适应成本（如 Tainted Code 政策的执行复杂度）

**史料**：上述 187.7.1-187.7.4 节史料综合；项目史观总纲第 4、5、7、8、13、22、23 条原文（据原文第 25 章，第 4 条 “分离聚合是永恒规律”，第 5 条 “没有必然性，只有偶然性”，第 7 条 “理论必须自反”，第 8 条 “本体论上各方平等”，第 13 条 “法律与道德是利益分配”，第 22 条 “知识注定过时”，第 23 条 “一切历史写作都是基于哲学设定的历史小说”） ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律，NetBSD 50+ ports 与 pkgsrc 16+ 平台扩展皆是分离聚合律的具体显现；总纲第 5 条——没有必然性，只有偶然性，NetBSD 可移植性哲学的确立与 Tainted Code 政策的引入皆是项目偶然选择的结果；总纲第 7 条——理论必须自反，本子节作为 NetBSD 习俗综合审视，自身亦嵌入 “可移植性哲学与制度创新二分” 的形式主义建构，须自觉呈现这一建构；总纲第 8 条——本体论上各方平等，NetBSD 习俗的可移植性哲学与制度创新、50+ ports 与 Tainted Code 政策在本体论上地位相等；总纲第 13 条——法律与道德是利益分配，NetBSD Foundation 选举、pkgsrc-pmc、Tainted Code 政策皆是利益分配机制的具体显现；总纲第 22 条——知识注定过时，Tainted Code 政策作为对 AI 时代代码伦理的早期回应，随 AI 技术演进而须重新展开；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，本子节作为 NetBSD 习俗综合审视本身是历史小说，史家须自觉呈现自身的哲学设定

**辨析**：本节为操作系统比较视角的综合审视，与相关章节关于 NetBSD 习俗特殊文化考据的 “可移植哲学” 与 “社区治理张力” 双重结构框架互补——该考据聚焦 NetBSD 习俗内部结构与考据冲突（如 Tainted Code 政策存在性的两份考据记录冲突），本节聚焦 NetBSD 习俗与其他 BSD 项目的比较定位；【0 信任原则·“可移植性哲学” 与 “制度创新” 二分的形式主义建构】“可移植性哲学” 与 “制度创新” 的区分是史家的形式主义建构——实际 NetBSD 习俗演变过程是可移植性哲学与制度创新交织的复杂形态，如 pkgsrc 跨平台扩展既是可移植性哲学的具体显现，也是制度创新（pkgsrc-pmc 成立）的具体显现，二者须分别考据而非笼统归为 “可移植性” 或 “制度创新”；【自反性声明】本子节作为 NetBSD 习俗综合审视，自身嵌入项目统摄史观的前理解，“可移植性哲学与制度创新” 的归纳是史家的形式主义建构，实际 NetBSD 习俗演变过程是多重张力交织的开放形态，本审视的收束不是 NetBSD 习俗考据的终结而是阶段性综合，随 NetBSD 治理与工程实践演进须重新展开

**文献**：上述 187.7.1-187.7.4 节所有文献综合；项目史观总纲第 4、5、7、8、13、22、23 条；相关章节关于 NetBSD 习俗特殊文化考据的详细考据 ［A］
