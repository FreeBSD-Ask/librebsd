## 188.4.1 NetBSD 7.x 周期 CVSS 评分体系成熟与高危 CVE 首现（2014-2018）

**要点**：NetBSD 7.x 版本周期（2014-07-01 至 2018-05-01）是 NetBSD 历史上首次出现 Critical 与 High 级别 CVE 的版本周期——netbsd.duckdb netbsd-src 仓库查询显示此周期内 365 条 CVE commit、55 条 Security fix commit、217 条去重 CVE，其中 1 条 Critical（CVE-2017-1000374，CVSS v3 9.8）、7 条 High（CVE-2017-12836、CVE-2017-3135/3137/3143/3145/3141、CVE-2018-5732）、7 条 Medium、1 条 Low、201 条无评分；CVE commit 量较 6.x 周期（113 条）增长 223%，反映 NetBSD 7.x 周期（约 4 年）较长且 CVE 编号引用习惯进一步固化；NetBSD 7.0（2015.9）改进 ARM 多核支持、引入 RPI2 树莓派支持〔存疑：RPI3 支持进入 7.0 系初版公告抑或 7.1 补充，待核〕、64-bit 时间戳迁移，架构变化使 ARM 平台攻击面扩大——ARM 架构的缓存一致性、内存管理单元（MMU）差异可能引入新的内核漏洞

**史料**：netbsd.duckdb netbsd-src 仓库 commits 表（7.x 周期 365 条 CVE commit、55 条 Security fix commit、217 条去重 CVE，CVSS 分布 Critical 1/High 7/Medium 7/Low 1/无评分 201）；NetBSD 7.0 Release Notes（2015.9）；早期漏洞补遗归档（原材料/研究/bsd 漏洞史/版本周期/netbsd-7.x.md） ［A］

**史观**：总纲第 3 条（不存在进步，只有权力再分配）：CVSS v3 评分体系的成熟使 NetBSD 7.x 周期首次能够量化漏洞严重程度——Critical（9.8）与 High（7.0-7.5）级别的出现不等于 NetBSD 7.x 周期漏洞 “更严重”，而是 NVD 对 2014 年后 CVE 的 CVSS v3 评分回填覆盖率提升所致；专题语（不设总纲条号）：CVE commit 量增长 223% 反映 NetBSD 7.x 周期安全响应的 “统计显性化”——commit message 普遍引用 CVE 编号使安全响应可量化追踪

**辨析**：“首次出现 Critical 与 High CVE” 的论断须限定为 “首次在 netbsd.duckdb 查询结果中出现 CVSS v3 评分的 Critical/High CVE”——早期版本周期（1.x-6.x）的 CVE 全部无 CVSS v3 评分，不代表这些周期无 Critical/High 级别漏洞，仅代表 NVD 未回填评分；217 条去重 CVE 中 201 条无评分（92.6%）反映 NVD 对 2014-2018 年 CVE 的 CVSS v3 回填仍不完整；【0 信任原则·CVSS 评分来源】CVSS v3 评分来自 NVD，须对照 NVD 条目逐一核验，不得依赖 netbsd.duckdb 单一来源

**文献**：netbsd.duckdb netbsd-src 仓库 commits 表；NetBSD 7.0 Release Notes；NVD CVE-2017-1000374 条目 ［A］

## 188.4.2 CVE-2017-1000374 大溢出——NetBSD 7.x 周期唯一 Critical 漏洞（2017）

**要点**：CVE-2017-1000374（CVSS v3 9.8 Critical，远程代码执行）是 NetBSD 7.x 周期唯一 Critical 级别漏洞——该漏洞由 Qualys 研究团队发现，存在于 NetBSD 与 FreeBSD 共享的 **execve(2)** 系统调用栈对齐处理路径中，攻击者可利用栈对齐缺陷触发栈溢出获取 root 权限；netbsd.duckdb 显示 NetBSD 2017-06-19 commit `5bcc4a51d6e9fd2627e9741423995e5738a24031` 修复该漏洞；该漏洞的特殊性在于其影响 NetBSD 与 FreeBSD 两大 BSD 项目（FreeBSD 对应 CVE-2017-1083），反映两项目在 **execve(2)** 实现上的代码共享历史——4.4BSD-Lite 基础代码的祖先共享使同源漏洞跨项目传播；CVE-2017-1000374 的 CVSS v3 评分 9.8（Critical）使其成为 NetBSD 历史上评分最高的 CVE 之一，攻击者仅需本地访问即可获取 root 权限，攻击复杂度低且无需特权

**史料**：netbsd.duckdb netbsd-src 仓库 commit `5bcc4a51d6e9fd2627e9741423995e5738a24031`（2017-06-19，CVE-2017-1000374 Critical 9.8）；Qualys 安全研究公告；NVD CVE-2017-1000374 条目（CVSS v3 9.8 Critical） ［A］

**史观**：专题语（不设总纲条号）：CVE-2017-1000374 揭示 “历史代码共享” 的长期安全债务——4.4BSD-Lite 基础代码在 NetBSD 与 FreeBSD 中的共享使同源漏洞在两项目同时存在，此为 “代码复用双刃剑” 的典型范式；总纲第 4 条（分离聚合是永恒规律）：NetBSD 与 FreeBSD 协同修复 CVE-2017-1000374 体现 BSD 家族在安全响应中的协作传统

**辨析**：CVE-2017-1000374 是否同时影响 OpenBSD 须考据——OpenBSD 可能因独立的代码审计已提前修复相关缺陷，须对照 OpenBSD errata 核验；Qualys 研究团队的漏洞披露时序须考据——Qualys 是否在公开披露前协调 NetBSD 与 FreeBSD 同步修复须对照披露公告核验；CVSS v3 评分 9.8 来自 NVD，须对照 NVD 向量字符串核验攻击向量（本地/远程）、攻击复杂度、权限要求、用户交互、影响范围等维度；CVE-2017-1000374 与 FreeBSD 对应的 CVE-2017-1083 系不同 CNA 独立评分（NetBSD/FreeBSD），9.8 Critical 与 7.5 High 的不对称源于此；本地/远程攻击向量表述须分别限定——Qualys stack clash 系本地提权族，NVD 对 FreeBSD 版标注 AV:N 网络向量，两口径并存；【0 信任原则·CVSS 评分核验】CVSS v3 9.8 评分须以 NVD 官方条目为准

**文献**：netbsd.duckdb netbsd-src 仓库 commit `5bcc4a51d6e9fd2627e9741423995e5738a24031`；Qualys 安全研究公告；NVD CVE-2017-1000374 条目 ［A］

## 188.4.3 BIND 9 漏洞群与 CVE-2017-3135/3137/3143/3145/3141（2017）

**要点**：NetBSD 7.x 周期 BIND 9 漏洞群在 2017 年集中爆发——CVE-2017-3135（CVSS v3 7.5 High，BIND 9 空指针解引用，commit `5b35098fd9e045c13fc55d3092ad4c8923b54f47`，2017-02-09）、CVE-2017-3137（CVSS v3 7.5 High，BIND 9 远程代码执行，commit `b6f711f503a307284b729bfffba2d46865b6d342`，2017-04-13）、CVE-2017-3143（CVSS v3 7.5 High，BIND 9，commit `650b8a694041001335a1c6c12d525889656433e1`，2017-06-30）、CVE-2017-3145（CVSS v3 7.5 High，BIND 9 释放后使用，commit `64b0a7bda9e5d71949761ea68c85482d8e71d564`，2018-04-07）、CVE-2017-3141（CVSS v3 7.2 High，BIND 9 权限提升，commit `1fcdb8f1f690ba8de81e0253b84c927ae7f266fe`，2017-06-15）；这 5 条 High 级别 BIND 9 CVE 反映 BIND 9 在 2017 年的安全压力——DNS 协议的复杂性与 BIND 9 代码库的规模使其持续成为漏洞高发组件；CVE-2017-3141 的 “权限提升” 机制类型较为罕见（BIND 漏洞通常为拒绝服务或远程代码执行），须对照 NVD 条目核验具体技术机制

**史料**：netbsd.duckdb netbsd-src 仓库 commit `5b35098fd9e045c13fc55d3092ad4c8923b54f47`（2017-02-09，CVE-2017-3135 BIND 9 High 7.5）；commit `b6f711f503a307284b729bfffba2d46865b6d342`（2017-04-13，CVE-2017-3137 BIND 9 High 7.5）；commit `650b8a694041001335a1c6c12d525889656433e1`（2017-06-30，CVE-2017-3143 BIND 9 High 7.5）；commit `64b0a7bda9e5d71949761ea68c85482d8e71d564`（2018-04-07，CVE-2017-3145 BIND 9 High 7.5）；commit `1fcdb8f1f690ba8de81e0253b84c927ae7f266fe`（2017-06-15，CVE-2017-3141 BIND 9 High 7.2）；NVD CVE-2017-3135/3137/3143/3145/3141 条目 ［A］

**史观**：专题语（不设总纲条号）：BIND 9 漏洞群在 2017 年的集中爆发反映 “DNS 协议复杂性” 作为长期工程风险的持续——DNSSEC 扩展、DDNS（动态 DNS）、TSIG（事务签名）等特性的叠加使 BIND 9 代码库复杂度持续增长；专题语（不设总纲条号）：BIND 9 作为全球 DNS 基础设施，其漏洞影响整个互联网的域名解析，须以最高安全标准审计

**辨析**：5 条 High 级别 BIND 9 CVE 的 CVSS v3 评分均来自 NVD，须对照 NVD 向量字符串核验攻击向量与影响范围；CVE-2017-3141 的 “权限提升” 机制须对照 NVD 条目核验——BIND 9 漏洞通常为远程拒绝服务或代码执行，“权限提升” 可能指 BIND 守护进程内部的权限边界突破（如从 named 用户到 root），须对照公告原文核验；CVE-2017-3145 的修复日期（2018-04-07）晚于 CVE 编号年份（2017），反映该漏洞可能在 2017 年即被披露但修复延迟至 2018 年，或 CVE 编号系事后回溯分配；【0 信任原则·CVSS 评分核验】全部 CVSS v3 评分须以 NVD 官方条目为准

**文献**：netbsd.duckdb netbsd-src 仓库 BIND 9 相关 commit 记录；NVD CVE-2017-3135/3137/3143/3145/3141 条目；ISC BIND 9 安全公告 ［A］

## 188.4.4 CVE-2017-12836 注入漏洞与 CVE-2018-5732 ISC DHCP 缓冲区溢出（2017-2018）

**要点**：NetBSD 7.x 周期其余 High 级别 CVE 包括——CVE-2017-12836（CVSS v3 7.5 High，注入漏洞，commit `74e8c71cd1136230728133034816cf03b1f4af1f`，2017-08-22）、CVE-2018-5732（CVSS v3 7.5 High，ISC DHCP 缓冲区溢出，commit `097731dea099250bc460a975c393fc370c283a95`，2018-04-07）；CVE-2018-5732 影响 ISC DHCP 客户端与中继代理，攻击者可构造恶意 DHCP 响应触发缓冲区溢出，导致 DHCP 客户端崩溃或潜在代码执行——此漏洞对 NetBSD 嵌入式设备（依赖 DHCP 获取网络配置）构成特殊风险，嵌入式设备在不可信网络（如公共 Wi-Fi）中易受恶意 DHCP 服务器攻击；netbsd.duckdb 显示 CVE-2018-5732 与 CVE-2018-5733（Medium 5.9，ISC DHCP 拒绝服务）由同一 commit `097731dea099250bc460a975c393fc370c283a95` 修复，反映 “同组件多漏洞合并修复” 实践

**史料**：netbsd.duckdb netbsd-src 仓库 commit `74e8c71cd1136230728133034816cf03b1f4af1f`（2017-08-22，CVE-2017-12836 High 7.5）；commit `097731dea099250bc460a975c393fc370c283a95`（2018-04-07，CVE-2018-5732 High 7.5 与 CVE-2018-5733 Medium 5.9 ISC DHCP）；NVD CVE-2017-12836、CVE-2018-5732、CVE-2018-5733 条目 ［A］

**史观**：专题语（不设总纲条号）：CVE-2018-5732 的 ISC DHCP 缓冲区溢出揭示 “网络配置协议” 作为攻击面的工程风险——DHCP 协议设计假设可信网络环境，其实现中的缓冲区溢出可被恶意 DHCP 服务器利用攻击客户端，此为 “信任假设失效” 的典型范式；NetBSD 嵌入式设备依赖 DHCP 获取网络配置，使 DHCP 客户端漏洞对嵌入式场景构成特殊风险

**辨析**：CVE-2017-12836 的 “注入漏洞” 机制须对照 NVD 条目核验具体注入类型（SQL 注入、命令注入、代码注入等）——netbsd.duckdb 仅标注 “注入” 而未细分，须对照 NVD CWE 分类核验；核查留痕：该 CVE 与 NetBSD phnum/process64 ioctl 的栈碰撞问题相关（Qualys stack clash 系列），具体注入类型仍以 NVD 条目为准；CVE-2018-5732 与 CVE-2018-5733 由同一 commit 修复的论断须对照 commit subject 核验——该 commit 可能同时修复 ISC DHCP 的多个子漏洞；【0 信任原则·CVSS 评分核验】全部 CVSS v3 评分须以 NVD 官方条目为准

**文献**：netbsd.duckdb netbsd-src 仓库 commit `74e8c71cd1136230728133034816cf03b1f4af1f`、`097731dea099250bc460a975c393fc370c283a95`；NVD CVE-2017-12836、CVE-2018-5732、CVE-2018-5733 条目；ISC DHCP 安全公告 ［A］
