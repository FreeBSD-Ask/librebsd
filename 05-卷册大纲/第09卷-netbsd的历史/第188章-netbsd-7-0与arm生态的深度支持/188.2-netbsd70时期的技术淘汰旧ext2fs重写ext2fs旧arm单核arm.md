# 188.2 NetBSD 7.0 时期的技术淘汰——旧 ext2fs→ 重写 ext2fs、旧 ARM 单核 →ARM 多核、32-bit 时间戳 →64-bit 时间戳（2013-2015）

## 187.2.1 旧 ext2fs 实现 → 重写 ext2fs 引入（2015）

**要点**：NetBSD 7.0（2015.10）由 Taylor R Campbell 等重写 ext2fs（ext2/3/4 兼容）文件系统实现；旧 ext2fs 实现存在性能与可维护性问题，重写后支持 ext4 特性（extent、huge_file 等）；重写让 NetBSD 在与 Linux 文件系统互操作上获得现代能力；旧 ext2fs 实现作为分离路径在过渡期保留，体现 “终结中的延续”

**史料**：NetBSD 7.0 Release Notes 文件系统部分；tech-file-system 邮件列表；CVS commit log 中 ext2fs 重写 commit ［A］

**史观**：总纲第 6 条——形式主义膨胀：旧 ext2fs 的形式主义膨胀（兼容性包袱）促使重写，体现 “在虚假中寻找仅存的真实”；总纲第 25 条——终结中的延续：旧实现作为过渡期保留是终结中的延续

**辨析**：7.0 重写 ext2fs 的具体范围（是否完整支持 ext4）需对照源码核验；与 FreeBSD ext2fs 实现的关系需考据；重写后的性能提升缺乏权威基准

**文献**：NetBSD 7.0 Release Notes；tech-file-system 邮件列表；Campbell 设计文档 ［A］

**史料**：NetBSD 7.0 Release Notes ARM 部分；tech-port-arm 邮件列表；CVS commit log 中 evbarm 相关 commit；netbsd.db netbsd-src 仓库 branches 表验证：origin/netbsd-7-0 branch commit_date = 2020-05-07T12:03:47Z（commit f76d427f5b4c，远晚于 7.0 发布 2015.10 约 4 年 7 个月，属分支末次维护更新时间，非发布时间），origin/netbsd-7-1 branch commit_date = 2020-05-07T12:07:13Z（commit 327ce71f43e8，远晚于 7.1 发布 2016.10 约 3 年 7 个月），两 branch commit_date 均为分支末次维护更新时间非发布时间，与 6.x 系列模式一致；netbsd.db netbsd-src 仓库 commits 表 aarch64 验证：joerg 2013-02-04 引入 LLVM/Clang AArch64 后端（commit 96fc3e30a7c3），matt 2013-10-29 添加 AARCH64 定义（commit f4eee7a46719），matt 2014-01-29 添加 latent AArch64 支持后又于同日删除（commit 25b6650f1bb1 与 8e5b387ff0e4），反映 7.0 时期 aarch64 在主分支处于反复状态；netbsd.db 查询 L1.1.1 显示：netbsd-src 2013 年 commit_count = 19,460，2014 年 = 20,949（较 2013 年增长 7.6%），2015 年 = 17,365（7.0 发布年，较 2014 年下降 17.1%），2014 年 commit 量增长反映 7.0 开发中段 ARM 多核移植与 aarch64 准备的工程投入，2015 年发布年 commit 量下降反映进入发布收尾阶段；netbsd.db 查询 L2.3.1.arm 显示：netbsd-src 2013 年 ARM 相关 commit = 854（开发峰值），2014 年 = 670，2015 年 = 464（7.0 发布年），2013 年 ARM commit 峰值与 aarch64 后端首次引入时序吻合，反映 2013 年是 ARM 生态深度支持的核心开发年，2015 年发布年 ARM commit 量下降反映 ARM 移植已趋稳定；统计结论 [C-04]: netbsd-src 仓库总 commit 数 773,683（截至 2026-07-27 查询），为 4 大 BSD src 仓库中 commit 累计最高者，本章时期（2013-2015）的 commit 活动构成此总量的后段；统计结论 [C-13]: netbsd-src 月度 commit 量 Pettitt 检验变点为 2012-04、BUISHAND R 检验变点为 2011-09（10,000 次 Monte Carlo），两检验变点均早于本章时期（2013-2015）约 1-2 年，反映本章时期处于 netbsd-src 长期下降趋势变点后的延续阶段，CVS 迁移至 Mercurial 的过渡期影响已基本消化；统计结论 [C-30]: netbsd-src ARIMA(2,1,4) 模型 AIC=−79.34（4 BSD 项目 src 仓库中最低，反映 netbsd-src 月度序列经一阶差分后模型拟合优度最佳），本章时期（2013-2015）的 commit 量数据纳入 ARIMA 建模样本；统计结论 [C-34]: netbsd-src ARIMA 模型预测 MAPE=25.65%、RMSE=109.44、coverage=94.74%，MAPE 在 4 BSD 项目中处于中等水平（低于 openbsd-src 45.21% 与 dragonfly-src 70.88%，略高于 freebsd-src 24.56%），反映 netbsd-src 月度序列的可预测性较好但本章时期 ARM 移植高峰带来的 commit 量波动可能贡献了部分预测误差 ［A］

**史观**：总纲第 5 条——偶然性：树莓派的爆发是偶然事件，NetBSD 抓住机会投入 ARM 多核支持改写自身在嵌入式市场的地位；总纲第 14 条——社区与文明历史哲学：嵌入式爱好者社区的参与体现社区文明的扩展

## 187.2.3 旧 CGD 加密机制 → CGD 加密改进（2015）

**要点**：NetBSD 7.0（2015.10）改进 CGD（Cryptographic Device）加密磁盘机制，引入对新加密算法的支持与性能优化；旧 CGD 实现存在 AES-XTS 等现代算法缺失问题，7.0 改进让 CGD 与现代加密标准对齐；CGD 框架延续但加密算法集合更新，体现 “终结中的延续”

**史料**：NetBSD 7.0 Release Notes CGD 部分；tech-crypto 邮件列表；**cgd(4)** 手册页 ［A］

**史观**：总纲第 19 条——信息技术：加密技术作为信息技术的安全基石，其演进体现 “终结中的延续”——旧算法退役但 CGD 框架延续；总纲第 24 条——许可证：CGD 代码 BSD 许可证让加密改进无许可证障碍

**辨析**：7.0 CGD 改进的具体算法列表需对照源码核验；与 OpenBSD softraid 加密、FreeBSD geom_eli 的对比需考据；CGD 默认算法在 7.0 中的变化需对照 Release Notes 核验

**文献**：NetBSD 7.0 Release Notes；**cgd(4)** 手册页；tech-crypto 邮件列表 ［A］

## 187.2.4 旧 32-bit 时间戳 → 64-bit 时间戳改进（2015）

**要点**：NetBSD 7.0（2015.10）改进内核时间戳从 32-bit 到 64-bit 的迁移，应对 2038 年问题（Y2038）；旧 32-bit time_t 在文件系统、网络协议、用户态 ABI 中广泛存在，7.0 引入 64-bit time_t 内核支持；此改进早于 FreeBSD 与 OpenBSD 的类似迁移，体现 NetBSD 在 Y2038 准备上的前瞻性

**史料**：NetBSD 7.0 Release Notes Y2038 部分；tech-kern 邮件列表讨论；CVS commit log 中 time_t 相关 commit ［A］

**史观**：总纲第 25 条——终结中的延续：32-bit 时间戳的退役是 Y2038 终结威胁下的延续，体现技术前瞻性；总纲第 19 条——信息技术：时间戳作为信息技术的基础组件，其位宽演进体现 “会者定离”

**辨析**：7.0 是否完整迁移到 64-bit time_t 在不同叙事中存在分歧——内核侧与用户态侧进度可能不同，需对照源码核验；与 FreeBSD/OpenBSD Y2038 准备的对比需考据；32-bit time_t 在 7.0 中是否仍可作为兼容选项保留需考据

**文献**：NetBSD 7.0 Release Notes；tech-kern 邮件列表；Y2038 问题文档 ［A］
