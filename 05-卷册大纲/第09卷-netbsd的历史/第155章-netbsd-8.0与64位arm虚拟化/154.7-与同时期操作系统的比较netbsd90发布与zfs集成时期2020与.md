# 181.3 **与同时期操作系统的比较**：NetBSD 9.0 发布与 ZFS 集成时期（2020）——与 FreeBSD 12/13、OpenBSD 6.6、Linux 5.x（ZFS on Linux）、Windows Server 2019/ReFS 的对照

## 181.3.1 FreeBSD 12/13（ZFS 原生，2020）
  - 要点：FreeBSD 在 NetBSD 9.0 同期为 12.1/13-CURRENT（2020），以 ZFS 原生整合（OpenZFS 移植）、bhyve 与 ARM64 见长；与 NetBSD 9.0 的“ZFS 集成（移植 OpenZFS）”对照——FreeBSD 的 ZFS 整合更早更深，NetBSD 9.0 在 2020 补上 ZFS 短板，二者均基于 OpenZFS 上游。
  - 史料：FreeBSD 12/13 发布说明（2020）；NetBSD 9.0 发布说明（2020.2）［A］
  - 史观：总纲第 7 条——BSD 谱系：FreeBSD 与 NetBSD 同期采用 OpenZFS，体现 BSD 家族共享上游、并行整合。
  - 辨析：NetBSD 9.0 的 ZFS 晚于 FreeBSD 但同源于 OpenZFS，整合深度持续追赶。
  - 文献：FreeBSD. 12/13 Release Notes [EB/OL]；NetBSD. 9.0 Release Notes [EB/OL]. ［A］
## 181.3.2 OpenBSD 6.6（2020）
  - 要点：OpenBSD 在 NetBSD 9.0 同期为 6.6（2019.10）与 6.7（2020.5），以安全机制（pledge/unveil 成熟）著称，未整合 ZFS（倾向简单文件系统）；与 NetBSD 9.0 的“ZFS 集成”分野——OpenBSD 坚持 softraid + FFS 的简洁安全路线，NetBSD 9.0 选择 ZFS 以补存储能力。
  - 史料：OpenBSD 6.6/6.7 发布说明 ［A］
  - 史观：总纲第 7 条——BSD 谱系：OpenBSD 与 NetBSD 同期演进，安全简洁 vs ZFS 能力目标分化。
  - 辨析：OpenBSD 不采用 ZFS 是基于安全审计与简洁考量，非技术劣势。
  - 文献：OpenBSD. 6.6/6.7 Release Notes [Z]. ［A］
## 181.3.3 Linux 5.x（ZFS on Linux，2020）
  - 要点：Linux 5.x（2020）在 NetBSD 9.0 同期以原生文件系统（ext4/btrfs）为主，ZFS 经 ZFS on Linux（OpenZFS 内核模块，非主线）提供；与 NetBSD 9.0 的 ZFS 集成对照——Linux 的 ZFS 以树外模块存在，NetBSD 9.0 与 FreeBSD 将 OpenZFS 整合进基树，体现 BSD 对 ZFS 的更紧密接纳。
  - 史料：Linux 5.x 发布说明（2020）；OpenZFS/ZoL 文档 ［B］
  - 史观：总纲第 6 条——技术路线分化：Linux 树外 ZFS vs BSD 基树整合，反映许可与整合策略差异。
  - 辨析：Linux 主线拒 ZFS 主因 CDDL/GPL 许可冲突，非技术；BSD 许可允许基树整合。
  - 文献：Linux Kernel. 5.x Release Notes [EB/OL]；OpenZFS Docs [EB/OL]. ［B］
## 181.3.4 Windows Server 2019 / ReFS
  - 要点：Microsoft 在 NetBSD 9.0 同期以 Windows Server 2019 与 ReFS（弹性文件系统）提供企业存储，ReFS 为 CoW 但闭源、功能受限；与 NetBSD 9.0 的 ZFS 集成对照——ReFS 与 ZFS 同属现代 CoW 存储但闭源不可审计，NetBSD 9.0 的 ZFS 开源可验证。
  - 史料：Microsoft Windows Server 2019/ReFS 文档 ［B］
  - 史观：总纲第 6 条——技术路线分化：闭源 CoW（ReFS）vs 开源 ZFS 在 2020 形成对照。
  - 辨析：ReFS 的闭源使故障排查依赖微软，ZFS 的开源使 BSD 可完全审计。
  - 文献：Microsoft. ReFS Docs [EB/OL].[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]
## 181.3.5 同期 ZFS/CoW 文件系统总览（2020）

  **2020 年同期 ZFS/CoW 文件系统对照表**：

  | 操作系统 | 主版本（2020） | ZFS/CoW 集成方式 | 整合深度 | 许可证 | 备注 |
  | --- | --- | --- | --- | --- | --- |
  | NetBSD | 9.0（**2020.2.14**） | OpenZFS 移植（从 FreeBSD SVN r315983） | 基树整合，实验性 | CDDL（与 NetBSD 内核聚合） | chs 2018-05-28 首次大批量导入 |
  | FreeBSD | 12.1/13-CURRENT | OpenZFS 原生整合 | 基树整合，成熟稳定 | CDDL（基树整合） | 7.0（2008.2）起即引入 ZFS，领先 12 年 |
  | OpenBSD | 6.6（2019.10）/6.7（2020.5） | 无 ZFS（FFS + softraid） | 拒绝 ZFS | BSD-licensed FFS | 安全审计与简洁考量 |
  | Linux | 5.x | ZFS on Linux（ZoL）树外模块 | 树外模块，非主线 | CDDL/GPL 冲突 | 主线拒 ZFS 因许可证冲突 |
  | Windows Server | 2019 | ReFS（弹性文件系统） | 闭源 CoW，功能受限 | 闭源 | ReFS 不可审计 |
  | illumos/Solaris | 持续维护 | ZFS 原创 | 原生 ZFS | CDDL | ZFS 发源地 |

  - 要点：2020 年 CoW 文件系统格局：FreeBSD 12/13 与 NetBSD 9.0 深度整合 OpenZFS，Linux 经 ZoL 树外提供，illumos/Solaris 持 ZFS 原创，OpenBSD 坚持 FFS/softraid，Windows 用 ReFS；NetBSD 9.0 的 ZFS 补齐使其存储能力与 FreeBSD 对齐。
  - 史料：各系统 2020 文件系统史料 ［B］
  - 史观：总纲第 7 条——BSD 谱系：NetBSD 9.0 与 FreeBSD 共享 OpenZFS 上游，体现家族存储能力收敛。
  - 辨析：ZFS 的 BSD 整合度高，证明 BSD 许可对大型存储栈的友好。
  - 文献：McKusick M K, Neville-Neil G. The Design and Implementation of the FreeBSD Operating System [M]. 2nd ed. Addison-Wesley, 2015. ［B］
