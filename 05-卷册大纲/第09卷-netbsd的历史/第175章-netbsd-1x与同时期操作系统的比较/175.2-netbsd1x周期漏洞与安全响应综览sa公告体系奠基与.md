## 175.2.1 NetBSD-SA 公告体系的建立与早期安全治理（1998-2004）

  **netbsd.duckdb 安全修复 commit 查询示例**：

  ```sql
  -- 查询 netbsd-src 仓库 1993-2000 年间的 Security fix commit
  SELECT commit_hash, author, commit_date, message_subject
  FROM commits
  WHERE repo_name = ‘netbsd-src’
    AND commit_date BETWEEN ‘1993-01-01’ AND ‘2000-12-31’
    AND (message_subject LIKE ‘%security%’
      OR message_subject LIKE ‘%Security fix%’
      OR message_subject LIKE ‘%merge in security%’
      OR message_subject LIKE ‘%Pullup%Fixes a security bug%’)
  ORDER BY commit_date;
  ```

**要点**：NetBSD 1.x 时期是 NetBSD Security Officer 制度与 SA（Security Advisory）公告体系的奠基阶段；netbsd.duckdb netbsd-src 仓库查询显示 1993-2000 年间 0 条 CVE 编号 commit，但 50 条 Security fix commit 以“merge in security fixes”“Pullup...Fixes a security bug”等 subject 标识，反映此时期安全修复以 SA 公告驱动而非 CVE 编号驱动；28 条早期漏洞补遗覆盖 1998-2004 年，以 NetBSD-SA1998-001 至 NetBSD-SA2004-007 编号发布，公告托管于 **ftp.netbsd.org/pub/NetBSD/security/advisories/**；此时期 NetBSD 尚无 VERIEXEC、pkg_signatures、kauth、NPF、kernel ASLR 等后续安全机制，安全防线依赖传统权限模型与 SA 响应

## 175.2.2 BIND 漏洞群与 DNS 安全基础设施的持续修补（1998-2003）

**要点**：BIND 是 NetBSD 1.x 时期漏洞密度最高的组件，28 条早期漏洞补遗中至少 5 条直接涉及 BIND——NetBSD-SA1998-001（CVE-1999-0833，BIND 4.9.6 DNS 缓存污染与 NXT 记录处理缺陷，远程攻击者可构造恶意 DNS 响应破坏缓存完整性）、NetBSD-SA2001-001（CVE-2001-0010、CVE-2001-0011，BIND 4 与 BIND 8 NXT/SIG 记录处理缺陷，远程任意代码执行）、NetBSD-SA2002-029（CVE-2002-1219、CVE-2002-1221，BIND 8 TSIG 事务签名缺陷，远程拒绝服务与代码执行）；netbsd.duckdb 显示 itojun（Jun-ichiro itojun Hagino）主导 BIND 安全升级，如 `1a7fc7b68704635813deaeea8afb03e3993957ee`（2001-01-27，"upgrade to BIND 8.2.3. the upgrade is critical (security fixes)"）、`815ede9ef4ed3c21a49fb90e61ec89c161bcb842`（2002-01-15，gzip 安全修复附带 BIND 维护）；BIND 漏洞群的持续出现反映 1990 年代末 DNS 协议实现安全性的系统性薄弱

**史料**：NetBSD-SA1998-001 公告（CVE-1999-0833，BIND 4.9.6）；NetBSD-SA2001-001 公告（CVE-2001-0010、CVE-2001-0011，BIND NXT/SIG）；NetBSD-SA2002-029 公告（CVE-2002-1219、CVE-2002-1221，BIND 8 TSIG）；netbsd.duckdb netbsd-src 仓库 itojun BIND 相关 commit（`1a7fc7b68704635813deaeea8afb03e3993957ee` 等，2001-01-27） ［A］

**史观**：总纲第 10 条——边缘者贡献：itojun 作为日本籍 BSD 贡献者在 BIND/DNS 安全维护中的核心角色体现边缘者对基础设施安全的贡献；总纲第 17 条——软件工程：BIND 漏洞群的反复出现揭示“协议复杂性 → 实现缺陷 → 安全修补”的工程循环

**辨析**：NetBSD-SA1998-001 引用的 CVE-1999-0833 编号在 NVD 中对应 BIND 4.9.6 多漏洞，但 NVD 记录的 CVSS v2 评分与 NetBSD 公告描述的技术机制需交叉核验——公告原文未引用 CVSS 评分，本节不臆造评分；CVE-2001-0010 与 CVE-2001-0011 在 NVD 中分别对应 BIND NXT 记录与 SIG 记录漏洞，NetBSD-SA2001-001 将二者合并于同一公告，反映当时“同源漏洞合并公告”的实践；【0 信任原则·SA 公告完整性】NetBSD SA 公告以 .txt.asc 签名格式发布，签名验证须对照 NetBSD Security Officer 公钥

**文献**：NetBSD-SA1998-001、NetBSD-SA2001-001、NetBSD-SA2002-029 公告原文；netbsd.duckdb netbsd-src 仓库 itojun commit 记录 ［A］

## 175.2.3 远程守护进程溢出群与 OpenSSH 集成安全（2001-2004）

**要点**：NetBSD 1.x 后期远程守护进程缓冲区溢出是另一高发类别——NetBSD-SA2001-005（CVE-2001-0240，**ftpd(8)** 远程缓冲区溢出，匿名或认证用户可构造超长路径名触发溢出执行任意代码）、NetBSD-SA2001-018（CVE-2001-0670，**lpd(8)** 远程缓冲区溢出，攻击者可构造恶意打印作业请求获取 root 权限）、NetBSD-SA2001-012（**telnetd(8)** 选项协商缓冲区溢出）、NetBSD-SA2003-009（CVE-2003-0161，**sendmail(8)** prescan 地址解析器溢出）；OpenSSH 集成引入新型安全风险——NetBSD-SA2002-005（CVE-2001-1483，OpenSSH 协议版本 2 challenge-response 认证模块缺陷，远程攻击者可绕过认证以任意用户身份登录包括 root）、NetBSD-SA2001-003（SSH 守护进程漏洞与 **rnd(4)** 随机数设备默认配置熵源不足导致密钥可预测）；netbsd.duckdb 显示 itojun 2001-02-08 commit `7f8fa38080fdccd83f8a06e70b3a77abc8c2e435` 标注"authentication mistake in SSHv2 + pubkey, from markus. REBUILD AND RESTART SSHD NOW"，反映 OpenSSH 漏洞修复的紧迫性

**史料**：NetBSD-SA2001-005 公告（CVE-2001-0240，ftpd）；NetBSD-SA2001-018 公告（CVE-2001-0670，lpd）；NetBSD-SA2002-005 公告（CVE-2001-1483，OpenSSH challenge-response）；NetBSD-SA2003-009 公告（CVE-2003-0161，sendmail）；netbsd.duckdb netbsd-src 仓库 commit `7f8fa38080fdccd83f8a06e70b3a77abc8c2e435`（itojun，2001-02-08，SSHv2 pubkey 认证修复） ［A］

**史观**：总纲第 17 条——软件工程：远程守护进程溢出群反映 1990 年代末 C 语言无边界检查的系统性风险在 BSD 基本系统中的集中爆发；总纲第 12 条——法律结构：OpenSSH 的 BSD 许可证让 NetBSD 得以自由集成并快速响应安全漏洞，与 SSH 商业版的闭源形成对照

**辨析**：CVE-2001-0240（ftpd）与 CVE-2001-0670（lpd）均为远程 root 级溢出，但 NVD 未提供 CVSS v3 评分，不得臆造；NetBSD-SA2002-005 引用的 CVE-2001-1483 编号在 NVD 中对应 OpenSSH challenge-response 绕过，但该 CVE 的影响范围（仅 OpenSSH 2.x/3.x vs 所有 OpenSSH）需对照公告原文核验；commit `7f8fa38080fdccd83f8a06e70b3a77abc8c2e435` 的 commit subject 中“REBUILD AND RESTART SSHD NOW”反映当时安全修复的紧急程度，但该 commit 是否对应特定 CVE 编号须与 SA 公告交叉验证

**文献**：NetBSD-SA2001-005、NetBSD-SA2001-018、NetBSD-SA2002-005、NetBSD-SA2003-009 公告原文；netbsd.duckdb netbsd-src 仓库 itojun SSH 修复 commit ［A］

## 175.2.4 内核安全与权限模型缺陷（1998-2004）

**要点**：NetBSD 1.x 时期内核安全缺陷集中在权限边界与竞态条件——NetBSD-SA1998-005（**mmap(2)** 系统调用在设备驱动实现中存在权限检查缺陷，本地用户可映射设备内存访问任意物理内存区域导致权限提升）、NetBSD-SA1999-001（TCP 服务器 **select(2)** 与 **accept(2)** 之间竞态条件，攻击者可触发文件描述符泄漏或拒绝服务）、NetBSD-SA1999-008（VFS 层锁定逻辑缺陷，并发文件系统操作可触发内核态死锁或 panic）、NetBSD-SA2000-001（**procfs(5)** 权限检查缺陷，本地用户可读取其他进程内存映射与命令行信息）、NetBSD-SA2001-009（SUID 程序执行与 **ptrace(2)** 竞态条件，本地用户可在 setuid 程序执行过程中附加调试器获取 root）、NetBSD-SA2004-007（Systrace 沙箱 **systrace_exit()** 权限检查缺陷，本地用户可在被监控进程退出时利用竞态条件获取 root）；netbsd.duckdb 显示 he（Havard Eidnes）主导 2000-02-28 procfs 安全修复 commit `a685050c3f4b3919cc804eea7792397efc311b4e`（“Fix a critical typo in the earlier procfs security fix”），反映内核安全修复的迭代性

**史料**：NetBSD-SA1998-005 公告（mmap 设备驱动权限）；NetBSD-SA1999-001 公告（TCP select/accept 竞态）；NetBSD-SA2000-001 公告（procfs 权限）；NetBSD-SA2001-009 公告（SUID/ptrace 竞态）；NetBSD-SA2004-007 公告（Systrace 权限提升）；netbsd.duckdb netbsd-src 仓库 he commit `a685050c3f4b3919cc804eea7792397efc311b4e`（2000-02-28，procfs 安全修复补丁） ［A］

**史观**：总纲第 17 条——软件工程：内核权限边界缺陷的反复出现揭示“权限检查分散于各子系统”的工程风险——每个系统调用、每个文件系统操作、每个设备驱动都须独立验证权限，任何遗漏即成漏洞；总纲第 25 条——0 信任原则：Systrace 作为沙箱机制本身存在权限提升漏洞，揭示“安全机制本身也可能成为攻击面”的悖论

**辨析**：NetBSD-SA1998-005 的 **mmap(2)** 缺陷与 FreeBSD 同期类似缺陷是否存在代码共享须考据——两项目 fork 自同一 4.4BSD-Lite 基础，设备驱动 mmap 实现可能共享祖先代码；NetBSD-SA2004-007 的 Systrace 漏洞揭示沙箱机制的元安全风险，但该漏洞是否影响 Systrace 在 NetBSD 2.0 中的采用决策须对照邮件列表核验；he 的 procfs 修复 commit `a685050c3f4b3919cc804eea7792397efc311b4e` 标注“Fix a critical typo in the earlier procfs security fix”，说明此为对先前修复的补丁，反映内核安全修复的迭代性——首次修复可能引入新缺陷

**文献**：NetBSD-SA1998-005、NetBSD-SA1999-001、NetBSD-SA2000-001、NetBSD-SA2001-009、NetBSD-SA2004-007 公告原文；netbsd.duckdb netbsd-src 仓库 he procfs 修复 commit ［A］

## 175.2.5 加密库漏洞与 OpenSSL 集成安全（2001-2003）

**要点**：OpenSSL 集成引入的加密库漏洞群在 NetBSD 1.x 后期集中显现——NetBSD-SA2001-013（OpenSSL PRNG 实现弱点，熵池初始化不充分导致会话密钥可预测）、NetBSD-SA2002-009（CVE-2002-0655，OpenSSL ASN.1 解析器缓冲区溢出与 SSL v2 弱密钥协商，远程攻击者可利用恶意证书或 SSL 握手触发任意代码执行）、NetBSD-SA2003-017（CVE-2003-0543、CVE-2003-0544、CVE-2003-0545，OpenSSL ASN.1 解析器双重释放与空指针解引用，远程攻击者可构造恶意证书触发任意代码执行或拒绝服务）；netbsd.duckdb 显示 itojun 主导 OpenSSL 安全升级，如 `e9316c885883f1b0613d7046e1b0cf53b2bcd8b5`（2002-07-30，"apply patch supplied with OpenSSL Security Advisory [30 July 2002]"）、`1e8891b392f18bcded939ba980db7b7220adbb8a`（2002-07-30，“OpenSSL 0.9.6e. includes major security fixes”）、`042428eaf426e96fd227e8cf2f6b2456af1f6412`（2002-08-08，“openssl 0.9.6f, with security fixes”），反映 OpenSSL 漏洞修复的高频迭代

**史料**：NetBSD-SA2001-013 公告（OpenSSL PRNG）；NetBSD-SA2002-009 公告（CVE-2002-0655，OpenSSL ASN.1）；NetBSD-SA2003-017 公告（CVE-2003-0543/0544/0545，OpenSSL 双重释放）；netbsd.duckdb netbsd-src 仓库 itojun OpenSSL 相关 commit（`e9316c885883f1b0613d7046e1b0cf53b2bcd8b5` 等，2002-07-30；`042428eaf426e96fd227e8cf2f6b2456af1f6412`，2002-08-08） ［A］

**史观**：总纲第 17 条——软件工程：OpenSSL 漏洞群的高频出现揭示“复杂加密协议实现”的工程风险——ASN.1 解析器作为协议复杂度的集中体现成为反复爆出漏洞的温床；总纲第 10 条——边缘者贡献：itojun 作为 DNS/IPsec/OpenSSL 多领域维护者体现边缘者在加密基础设施安全中的关键角色

**辨析**：CVE-2002-0655 在 NVD 中对应 OpenSSL 多漏洞，NetBSD-SA2002-009 将其与 SSL v2 弱密钥协商合并公告，但 NVD 记录的子漏洞编号须逐一核验；CVE-2003-0543/0544/0545 三个 CVE 编号对应 OpenSSL ASN.1 解析器的不同缺陷路径，NetBSD-SA2003-017 将三者合并于同一公告，反映“同组件多漏洞合并公告”的实践；itojun 的 OpenSSL 升级 commit 频率（2002 年 7-8 月至少 3 次重大升级）反映 OpenSSL 0.9.6 系列的安全压力，但 commit 量不等于漏洞严重程度
