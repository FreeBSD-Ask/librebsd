# 179.1 NetBSD 6.0 的发布与多核改进（2012.10.17）——6.0 引入新的线程调度器、改进的 SMP 支持、NPF（NetBSD Packet Filter）防火墙，发布周期再次延长至约 3 年 6 个月（自 5.0 于 2009.4.29 发布起算）

## 179.1.1 6.0 线程调度器的设计

  **netbsd-src 仓库 2010-2012 年度 commit 量与 SMP 相关 commit 量统计**：

  | 年份 | 年度 commit_count | SMP 相关 commit | 备注 |
  | --- | --- | --- | --- |
  | 2010 | 21,916 | 14 | 6.0 开发早期 |
  | 2011 | 25,959 | 18 | 开发峰值，较 2010 年增长 18.5% |
  | 2012 | 19,358 | 26 | 6.0 发布年（**2012.10.17**），SMP commit 峰值 |

  - 要点：NetBSD 6.0（**2012.10.17**）继续由 Andrew Doran（安德鲁·多兰） 改进的线程调度器，引入更细粒度的优先级继承与多核负载均衡；6.0 的 SMP 改进特别针对 8 核以上机器优化；调度器设计延续 5.0 渐进式路径，未引入革命性重构
  - 史料：NetBSD 6.0 Release Notes；tech-kern 邮件列表 Doran 设计帖；CVS commit log；netbsd.db netbsd-src 仓库 branches 表验证：origin/netbsd-6-0 branch commit_date = 2018-07-02T14:40:25Z（commit 5b641b39b45a，远晚于 6.0 发布 2012.10.17 约 5 年 9 个月，属分支末次维护更新时间，非发布时间）；origin/netbsd-6-1 branch commit_date = 2018-07-02T14:39:15Z（commit 796dca000579，与 6.0 分支末次更新同期，反映 6.x 系列共同维护至 2018.7）；netbsd.db 查询 L1.1.1 显示：netbsd-src 2010 年 commit_count = 21,916，2011 年 = 25,959（开发峰值，较 2010 年增长 18.5%），2012 年 = 19,358（6.0 发布年，较 2011 年下降 25.4%），2011 年的 commit 量峰值反映 6.0 开发周期中段（2010-2012）的工程投入集中，2012 年发布年 commit 量下降反映进入发布收尾阶段；netbsd.db 查询 L2.3.1.smp 显示：netbsd-src 2010 年 SMP 相关 commit = 14，2011 年 = 18，2012 年 = 26（6.0 发布年，较 2011 年增长 44.4%），2012 年 SMP commit 增长反映 6.0 发布前最后的 SMP 调度器优化集中投入；统计结论 [C-04]: netbsd-src 仓库总 commit 数 773,683（截至 2026-07-27 查询），为 4 大 BSD src 仓库中 commit 累计最高者，本章时期（2010-2012）的 commit 活动构成此总量的中后段；统计结论 [C-13]: netbsd-src 月度 commit 量 Pettitt 检验变点为 2012-04、BUISHAND R 检验变点为 2011-09（10,000 次 Monte Carlo），两检验变点均落在本章时期（2010-2012）内，反映本章时期是 netbsd-src 长期下降趋势的结构性转折区间，变点事件对应 NetBSD 主仓由 CVS 迁移至 Mercurial 的过渡期 ［A］
  - 史观：总纲第 5 条——组织结构塑造技术路径：NetBSD 调度器的“渐进式”路径延续，体现组织结构对技术路径的塑造
  - 辨析：6.0 调度器相比 5.0 的具体改进幅度在不同来源中差异较大——部分基准显示显著提升，部分显示微小改进，需对照同硬件测试核验。经 netbsd.db netbsd-src 仓库 branches 表验证：origin/netbsd-6-0 与 origin/netbsd-6-1 的 commit_date 均为 2018-07-02（前后相差仅 1 分钟），反映 6.x 系列分支在 2018.7 同期停止维护，与 NetBSD 8.0（2018.7）发布时序吻合（8.0 发布后 6.x 系列进入 EOL）；6.0 发布日期 2012.10.17 仍须以 NetBSD 官方公告为准。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2010-2012 年 commit 量可能不完整，2011 年的峰值可能因镜像同步延迟而与主仓实际数据存在偏差；L2.3.1.smp 查询基于 message_subject LIKE '%SMP%’ 匹配，14/18/26 这组数字是 SMP 相关 commit 的下限，实际涉及线程调度器改进的 commit 可能更多（如 subject 中含"scheduler""thread""preemption""runqueue"但未含"SMP"的 commit 未被统计）。统计结论 [C-13] 局限性继承：Pettitt 检验变点 2012-04 与 BUISHAND R 检验变点 2011-09 相差约 7 个月，反映两检验对序列尾部敏感度差异，非数据矛盾；变点事件对应 NetBSD 主仓由 CVS 迁移至 Mercurial 的过渡期，但变点检测不区分 “版本控制迁移影响” 与 “实际开发活动结构性变化”，变点成因须结合 commit message 与文件路径分析；10,000 次 Monte Carlo 模拟提供 p 值近似，但小样本（netbsd-src 月度序列仅约 400 个月）下变点位置的 95% 置信区间较宽，变点年份判定存在不确定性

## 179.1.2 NPF 防火墙的引入

  **NPF 首次导入 commit 原文**：

  > Import NPF - a packet filter. Some features: ...
  >
  > ——rmind (Mindaugas Rasiukevicius), netbsd-src 仓库，commit `2e6f2099c639`, 2010-08-22T18:56:18Z

  - 要点：NetBSD 6.0 引入 NPF（NetBSD Packet Filter）作为新防火墙框架，由 Mindaugas Rasiukevicius 设计；NPF 提供 IPF（IPFilter）与 PF（OpenBSD 移植）的现代替代品，支持状态跟踪、NAT、流量整形；NPF 设计强调可扩展性与性能，使用 BPF 字节码
  - 史料：NPF 设计文档与 man npf(7)；tech-net 邮件列表讨论；CVS commit log 中 npf 相关 commit；netbsd.db netbsd-src 仓库 commits 表 NPF 首次引入 commit 验证：rmind（Mindaugas Rasiukevicius）2010-08-22T18:56:18Z"Import NPF - a packet filter. Some features: ..."（commit 2e6f2099c639，NPF 首次导入，含部分特性描述），rmind 2010-08-24T23:55:04Z"Move npf.conf(5-8) into the correct section, hence npf.conf(5)."（commit 3b6fdb92e58e，NPF 配置手册页修正）；NPF 首次导入时间 2010-08-22 早于 6.0 发布 2012.10.17 约 2 年 2 个月，反映 NPF 在 6.0 发布前已在主分支开发约 2 年；netbsd.db netbsd-src 仓库 branches 表验证：origin/netbsd-6-0 branch commit_date = 2018-07-02T14:40:25Z（commit 5b641b39b45a，远晚于 6.0 发布 2012.10.17 约 5 年 9 个月，属分支末次维护更新时间，非发布时间） ［A］
  - 史观：总纲第 2 条——分离与聚合：NPF 作为独立防火墙框架与 NetBSD 内核聚合，但与 IPF/PF 在概念上分离，体现工具独立哲学
  - 辨析：NPF 与 OpenBSD PF 的关系存在叙事分歧——部分资料称 NPF 借鉴 PF 设计，部分称独立设计，需对照源码核验；NPF 的实际采用率（与 IPF/PF 共存情况）需考据。经 netbsd.db netbsd-src 仓库 commits 表验证：NPF 首次导入 commit 2010-08-22T18:56:18Z 由 rmind（Mindaugas Rasiukevicius）提交，与“NPF 由 Mindaugas Rasiukevicius 设计”叙事作者归属吻合；NPF 首次导入时间（2010.8.22）早于 6.0 发布（2012.10.17）约 2 年 2 个月，反映 NPF 在 6.0 发布前已在主分支开发约 2 年，与“6.0 引入 NPF”叙事时序吻合（NPF 在 6.0 开发周期内启动，随 6.0 正式发布）；存疑已解决（NPF 作者归属与首次引入时间得到代码级确认）

## 179.1.3 与 FreeBSD 9.x/10.x 技术进展的比较
  - 要点：FreeBSD 9.0（2012.1）引入 Capsicum 沙箱、softdep 改进、NFSv4；10.0（2014.1）切换至 Clang/LLVM 默认编译器、引入 bhyve 虚拟化；同期 NetBSD 6.0（2012.10）专注 SMP 与 NPF；FreeBSD 在虚拟化与编译器现代化领先，NetBSD 在跨平台与防火墙设计有特色
  - 史料：FreeBSD 9.0/10.0 Release Notes；NetBSD 6.0 Release Notes；BSD 基准测试对比[考据完成：2026-07-28 经穷尽联网考据，上述史料清单为已知公开来源汇总，部分原始档案未公开数字化或须档案馆藏地现场核验，属史料缺口，须待原始档案公开后方可补充确证]〔L3 官方文档与公告/L5 二手研究〕
  - 史观：总纲第 7 条——技术选择即政治选择：FreeBSD 选择 Clang/LLVM 与 bhyve，NetBSD 选择 NPF 与跨平台——选择即政治
  - 辨析：FreeBSD 切换至 Clang/LLVM 的实际动机（GPLv3 担忧 vs 技术优势）在不同叙事中存在分歧，需对照 FreeBSD 邮件列表核验；bhyve 与 NVMM 的相对性能缺乏权威对比
