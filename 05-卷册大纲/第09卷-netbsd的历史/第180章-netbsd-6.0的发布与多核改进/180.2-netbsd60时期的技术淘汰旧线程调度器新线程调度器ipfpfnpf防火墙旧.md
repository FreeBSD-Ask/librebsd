# 180.2 NetBSD 6.0 时期的技术淘汰——旧线程调度器 → 新线程调度器、IPF/PF→NPF 防火墙、旧 ARM 单核 → 新 ARM 多平台支持（2010-2012）

## 180.2.1 旧线程调度器 → 新线程调度器改进（2012）

**要点**：NetBSD 6.0（2012.10）由 Andrew Doran（安德鲁·多兰） 继续推进线程调度器改进，相比 5.0 时代的调度器引入更细粒度的优先级继承与多核负载均衡；旧有的 4BSD 调度器路径在 6.0 中作为可选保留，新调度器在 8 核以上机器上优化；6.0 的调度器并非完全推翻旧设计，而是渐进式重构，体现“会者定离”中旧技术逐步淡出但未完全消失的延续性

**史料**：NetBSD 6.0 Release Notes 调度器部分；tech-kern 邮件列表 Doran 关于调度器的帖；CVS commit log 中 sched 相关 commit；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2010 年 commit_count = 21,916，2011 年 = 25,959（开发峰值），2012 年 = 19,358（6.0 发布年），2010-2012 年间 commit 量先升后降，2011 年峰值反映 6.0 开发中段的工程投入集中；netbsd.duckdb 查询 L2.3.1.smp 显示：netbsd-src 2010 年 SMP 相关 commit = 14，2011 年 = 18，2012 年 = 26（6.0 发布年峰值），2012 年 SMP commit 量为 2010-2012 年间最高，印证 6.0 发布年调度器优化集中投入；netbsd.duckdb 查询 L1.4.1 显示：netbsd-src 无标准 release tag，分支 netbsd-6-0 commit_date = 2018-07-02T14:40:25Z（远晚于 6.0 发布 2012.10.17 约 5 年 9 个月），发布间隔须以 branches 表与官方公告交叉验证 ［A］

**史观**：线程调度器作为信息技术内核组件，其演进体现“会者定离”——旧调度器在新技术压力下逐步淡出但未完全消失；总纲第 3 条——不存在进步，只有权力再分配：旧调度器作为可选保留而未被移除，属支持资源在新旧路径间的再分配而非单向进步

**辨析**：6.0 调度器相比 5.0 的具体改进幅度在不同来源中差异较大，部分基准显示显著提升，部分显示微小改进，需对照同硬件测试核验；M2 调度器的命名在不同资料中可能存在歧义，需对照源码核验；新旧调度器在 6.0 中的切换机制需考据。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2010-2012 年 commit 量可能不完整；L2.3.1.smp 查询基于 message_subject LIKE '%SMP%’ 匹配，14/18/26 这组数字是 SMP 相关 commit 的下限，实际涉及调度器改进的 commit 可能更多（如 subject 中含“scheduler”“thread”“preemption”但未含“SMP”的 commit 未被统计）；L1.4.1 查询的“无匹配 tag”是 tag 命名约定差异导致，非 netbsd-src 无版本标签，须以 branches 表替代分析

**文献**：NetBSD 6.0 Release Notes；tech-kern 邮件列表；Andrew Doran 设计文档；netbsd.duckdb 数据分析·宏观趋势统计.md §L1.1.1（netbsd-src 2010-2012 年度 commit 量）、§L2.3.1.smp（netbsd-src SMP 相关 commit 2010-2012）、§L1.4.1（netbsd-src release tag 查询无匹配） ［A］

## 180.2.2 旧 IPF/PF 防火墙 → NPF 防火墙引入（2012）

**要点**：NetBSD 6.0（2012.10）引入 NPF（NetBSD Packet Filter）作为新防火墙框架，由 Mindaugas Rasiukevicius 设计；NPF 提供 IPF（IPFilter）与 PF（OpenBSD 移植）的现代替代品，支持状态跟踪、NAT、流量整形；NPF 使用 BPF 字节码，强调可扩展性与性能；旧 IPF 与 PF 在 6.0 中仍可共存，未被强制淘汰，体现“分离与聚合”的工具独立哲学

**史料**：NPF 设计文档与 **npf(7)** 手册页；tech-net 邮件列表讨论；CVS commit log 中 npf 相关 commit ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：NPF 作为独立防火墙框架与 NetBSD 内核聚合，但与 IPF/PF 在概念上分离，体现工具独立哲学；总纲第 3 条——不存在进步，只有权力再分配：旧 IPF 与 PF 在 6.0 中未被强制淘汰，新旧框架的取舍并非单向进步

**辨析**：NPF 与 OpenBSD PF 的关系存在叙事分歧——部分资料称 NPF 借鉴 PF 设计，部分称独立设计，需对照源码核验；NPF 在 6.0 中的实际采用率（与 IPF/PF 共存情况）需考据；NPF 的默认状态（默认启用 vs 默认禁用）需对照 Release Notes 核验

**文献**：NPF 设计文档；OpenBSD **pf(4)** 手册页；Mindaugas Rasiukevicius 演讲 ［A］

## 180.2.3 旧 ARM 单核支持 → 新 ARM 多平台支持（2012）

**要点**：NetBSD 6.0（2012.10）改进 ARM 多核支持，引入对 Cortex-A9 MPCore 等多核 SoC 的支持；旧 ARM 移植基于单核假设，6.0 引入 ARM SMP 与 big.LITTLE 雏形；ARM 多平台支持为后续 7.0 树莓派移植奠定基础；旧 ARM 单核路径作为分离分支保留，体现技术路径的偶然性

**史料**：NetBSD 6.0 Release Notes ARM 部分；tech-port-arm 邮件列表讨论；CVS commit log 中 arm 相关 commit ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：ARM 多核支持作为新技术与 NetBSD 内核聚合，但旧 ARM 单核路径作为分离分支保留；总纲第 5 条——没有必然性，只有偶然性：ARM 多核投入的时机选择具有偶然性

**辨析**：6.0 ARM 多核支持的具体硬件列表需对照硬件兼容性列表核验；big.LITTLE 在 6.0 中是否完整支持在不同叙事中存在分歧，需对照源码核验；旧 ARM 单核路径在 6.0 中是否仍可构建需考据

**文献**：NetBSD 6.0 Release Notes；tech-port-arm 邮件列表；ARM Cortex-A9 技术文档 ［A］

## 180.2.4 旧 pkgsrc 跨平台机制 → pkgsrc 2012Q3 跨平台改进（2012）

**要点**：pkgsrc 2012Q3（2012.7）作为 6.0 同期发布版本，改进跨平台软件包管理；引入对 AIX、Solaris、HP-UX 等非 BSD 系统的更好支持；改进 二进制软件包构建基础设施；pkgsrc 跨平台能力让 NetBSD 工具链在非 NetBSD 系统上获得存在感，体现 BSD 反向影响线

**史料**：pkgsrc 2012Q3 发布说明；tech-pkg 邮件列表讨论；pkgsrc-doc 邮件列表 ［A］

**史观**：pkgsrc 作为 BSD 衍生工具链反向影响 Linux 与商业 UNIX 软件包管理生态；BSD 许可证让 pkgsrc 跨平台分发无许可证障碍

**辨析**：pkgsrc 2012Q3 的具体改进内容需对照发布说明核验；跨平台支持的“改进幅度”在不同来源中可能存在差异；pkgsrc 在 AIX/Solaris 上的实际采用率缺乏权威统计
