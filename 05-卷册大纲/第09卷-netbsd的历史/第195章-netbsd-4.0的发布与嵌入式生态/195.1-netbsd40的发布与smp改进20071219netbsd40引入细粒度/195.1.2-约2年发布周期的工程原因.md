# 195.1.2 约 2 年发布周期的工程原因

  **NetBSD 3.x-5.x 版本发布时间线与分支维护期**：

  | 版本 | 官方公告发布日期 | 对应分支 | 分支末次更新时间 | 末次更新 commit | 分支维护期 |
  | --- | --- | --- | --- | --- | --- |
  | 3.0 | **2005.12.23** | `netbsd-3-0` | 2009-04-30T20:36:52Z | `99f7cbea021b` | 约 3 年 4 个月 |
  | 4.0 | **2007.12.19** | `netbsd-4-0` | 2012-11-14T20:26:54Z | `e8a6796c553c` | 约 4 年 11 个月 |
  | 5.0 | **2009.4.29** | `netbsd-5-0` | 2014-12-25T23:54:07Z | `f0717457fc3b` | 约 5 年 8 个月 |

**要点**：NetBSD 4.0（**2007.12.19**）距 3.0（**2005.12.23**）约 2 年发布周期的工程原因——细粒度锁改造工程量大、多平台测试复杂、Core Team 资源有限；2 年周期反映 NetBSD 多平台策略的代价

**史料**：NetBSD 4.0 Release Notes；Core Team 发布周期讨论邮件；NetBSD 官方发布历史页面（netbsd.org/releases/formal.html）；netbsd.duckdb netbsd-src 仓库 branches 表验证：origin/netbsd-3-0 branch commit_date = 2009-04-30T20:36:52Z（commit 99f7cbea021b，晚于 3.0 发布 2005.12.23 约 3 年 4 个月），origin/netbsd-4-0 branch commit_date = 2012-11-14T20:26:54Z（commit e8a6796c553c，晚于 4.0 发布 2007.12.19 约 4 年 11 个月），两 branch commit_date 均非发布时间，但 branch 创建时序与版本演进顺序一致；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2005 年 commit_count = 30,344（3.0 发布年），2006 年 = 30,561，2007 年 = 28,670（4.0 发布年），3.0 至 4.0 期间（2006-2007）commit 量从 30,561 降至 28,670（降幅约 6.2%），与 “细粒度锁改造工程量大、多平台测试复杂导致发布周期延长至 2 年” 叙事在 commit 活跃度下降上得到间接印证；netbsd.duckdb 查询 L1.4.1 显示：netbsd-src 在标准 release tag 过滤条件下（tag_name LIKE ‘release/%’ OR ’%-RELEASE’ OR 'OPENBSD_%’）无匹配 tag，NetBSD 采用 CVS/HG tag 命名约定（如 `netbsd-4-0` 分支），与 FreeBSD `release/12.0.0` 命名约定不同，故 L1.4.1 查询不适用于 netbsd-src，发布间隔须以 branches 表与官方公告交叉验证 ［A］

**史观**：技术选择的代价：多平台策略付出发布周期代价

**辨析**：先前叙事中称 ~~“3 年发布周期”~~ 系误传——3.0（**2005.12.23**）至 4.0（**2007.12.19**）实际间隔约 2 年；具体原因需考据——细粒度锁改造与多平台测试的具体影响需对照 commit 日志核实。经 netbsd.duckdb netbsd-src 仓库 branches 表验证：3.0 与 4.0 的 branch 最后更新时间（2009-04-30 与 2012-11-14）相隔约 3 年 7 个月，反映两版本分支的持续维护期重叠且 4.0 分支维护期更长，与 “4.0 引入细粒度锁改造导致发布周期延长至 2 年” 的叙事在分支维护期长度上得到间接印证；但发布日期间隔仍须以官方公告为准（3.0 为 **2005.12.23**，4.0 为 **2007.12.19**，间隔约 1 年 11 个月，与 “约 2 年” 叙事吻合）。L1.1.1 查询的 commit 量下降趋势（2006 年 30,561→2007 年 28,670）须注意 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像，主仓 Mercurial **hg.NetBSD.org** 的实际 commit 量可能更高，降幅可能被镜像同步延迟放大；L1.4.1 查询的 “无匹配 tag” 不等于 “netbsd-src 无版本标签”，而是 tag 命名约定差异导致查询条件不匹配，须以 branches 表（`netbsd-3-0`、`netbsd-4-0` 等）替代分析
