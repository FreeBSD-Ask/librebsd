# 179.3 NetBSD 与开源社区的关系（2005-2009）——NetBSD Foundation 与 FreeBSD Foundation 的合作与竞争、NetBSD 在 Google 编程之夏 中的参与、NetBSD 与学术机构的研究合作

## 179.3.1 与 FreeBSD Foundation 的合作与竞争

**要点**：NetBSD Foundation（1994 年签署成立文件，Delaware 注册；501(c)(3) 免税资格 2004 年获 IRS 批准；1997 年法人地位曾失效、2002 年重组）与 FreeBSD Foundation（2000.3 Delaware 501c3）同为非营利组织，共享 BSD 许可证传统；两 Foundation 在 2005-2009 年间合作开展法律防御（如应对 SCO 诉讼余波）、联合参加 Google 编程之夏；竞争体现在 committer 流失（部分 NetBSD committer 转向 FreeBSD）与媒体关注度差异

**史料**：NetBSD Foundation 与 FreeBSD Foundation 501c3 IRS 文件；两 Foundation 2005-2009 年度报告；邮件列表合作记录 ［A］

**史观**：总纲第 4 条（分离聚合是永恒规律）：两 Foundation 的合作基于共享的 BSD 文化，竞争源于不同的工程哲学与社区治理模式

**辨析**：两 Foundation 的资金规模在 2005-2009 年间差距扩大——FreeBSD Foundation 因商业赞助（Yahoo、Juniper、NetApp）规模显著扩大，NetBSD Foundation 收入相对停滞；具体数字需对照 IRS 990 文件核验

**文献**：NetBSD Foundation IRS 990 表；FreeBSD Foundation IRS 990 表；两 Foundation 年度报告 2005-2009 ［B］

## 179.3.2 编程之夏参与与学生贡献

**要点**：NetBSD 自 2005 年首届 Google 编程之夏起持续参与，2005-2009 年间共接受约 30-50 名学生参与〔估算，未注来源〕；学生项目涉及 SMP、ARM 移植、pkgsrc 工具等；编程之夏是 NetBSD 引入年轻开发者的关键渠道，但学生留存率（成为长期 committer 的比例）各来源不一（约 10%-15%，另有 12% 与 15%-20% 两说，见辨析）

**史料**：Google 编程之夏 2005-2009 项目档案；NetBSD 编程之夏项目列表与导师分配；学生最终报告［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕

**史观**：总纲第 10 条（动手者创造历史）：编程之夏学生作为“边缘开发者”为 NetBSD 贡献代码，部分成为长期 committer

**辨析**：NetBSD 编程之夏学生留存率在不同来源中差异较大——Google 官方报告称 BSD 项目整体留存率约 12%，NetBSD 邮件列表称 15%-20%，需对照 committer 列表核验

**文献**：Google 编程之夏 项目档案 2005-2009；NetBSD 编程之夏项目页面；编程之夏学生最终报告［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 179.3.3 与学术机构的研究合作

**要点**：NetBSD 与剑桥大学（Andrew Doran）、MIT CSAIL（部分研究项目）、东京大学（Jun Ebihara（海老原純） 等 ARM 移植）有持续研究合作；学术合作产出的论文与技术报告为 NetBSD 工程实践提供理论支撑

**史料**：剑桥大学计算机实验室 2006-2009 年度报告；MIT CSAIL 操作系统组论文列表；日本学术机构 NetBSD 研究档案 ［B］

**史观**：专题语（不设总纲条号）：学术合作为 NetBSD 提供了“学院派”声望资产，但学术周期与工程节奏存在张力

**辨析**：剑桥 NetBSD 研究与剑桥 FreeBSD 研究（罗伯特·N. M. 沃森等）的相对规模存在叙事分歧——剑桥计算机实验室同时容纳两个 BSD 项目的研究，需对照实验室年度报告核验；MIT CSAIL 与 NetBSD 的合作深度常被高估

**文献**：剑桥大学计算机实验室年度报告；MIT CSAIL 论文档案；东京大学 NetBSD ARM 研究论文 ［B］

**要点**：

- NetBSD 6.0 的 LVM 支持源于 Google Summer of Code 项目：用户态基本直接导入 Linux 工具并加兼容层，使标准 Linux 卷管理命令可直接操作，而内核侧因许可证问题必须另行实现，与用户态接口完全不同；引入动机是既有 ccd、RAIDframe、vnd、VINUM 各有局限而用户长期需要逻辑卷管理，且熟悉的命令能降低 Linux 用户的迁移成本。　[存疑脚注] LVM 内核侧重写与用户态兼容层的具体边界为受访者转述 GSoC 成果，须对照 NetBSD 源码树中 dm 与 lvm2 组件核证（BSDTalk EP215，[412.54-583.56]，L2）
- 6.0 时期内核多处理能力由受资助的有偿工作推动：Andrew Doran 完成部分线程化内核与细粒度锁，使部分子系统脱离大内核锁，受访者明确承认 FreeBSD 在此领先而 NetBSD 正在追赶；Xen 的多处理器支持同样是有偿工作，发布前数月才进入代码树。此外 6.0 引入线程局部存储、可在用户空间运行多个 IP 栈，并以 64 位 time_t 提前规避 2038 年问题。（BSDTalk EP215，[1104.3-1216.26]，L1）
- NetBSD 发布历来以功能而非时间表驱动：主分支切出发布分支后开发者在树顶投入大特性，6.0 含四十五个以上新驱动与 MIPS64 支持；向后移植到稳定分支取决于用户需求与人手，受访者坦言多数用户只关心在稳定版上运行新硬件。6.0 首次以政策形式确立自动化测试：受访者为测试体系发起人，另一开发者推动新政策，自动系统每日从空白机器完成构建、安装并运行测试，配合短提交窗口使问题在引入后数小时内暴露。（BSDTalk EP215，[638.84-739.38]，L1）
- 多架构支持的实际收益超越罕见硬件本身：受访者论证为众多架构构建的纪律使代码整体更干净，仅用 i386 与 amd64 的用户同样受益；嵌入式企业选择 NetBSD 是因为对应 CPU 的编译器、总线、芯片组与驱动已现成可用，且 build.sh 单命令交叉构建可加快开发周期。Clang 与 PCC 被引入构建体系但仅覆盖其支持的架构子集，Clang 背后的商业与开源动力被预期持续推动其扩张。（BSDTalk EP215，[739.38-935.94]，L1）

**史料**：

- 本期构成 NetBSD 社区结构的一手口述：受访者一为 David Maxwell，曾任安全官五年并任基金会董事，自述于上世纪九十年代加入项目并发起测试项目；受访者二自述为 LFS 与 ATF 作者、现任董事会成员并正在编写 ATF 的替代品；受访者三为十多年项目成员与维护者。转写将后两位人名记作 Julio Marino 与 Brett Lim，与 NetBSD 开发者 Julio Merino、Brett Lymn 的履历特征吻合，采信时以仓库提交记录核证为宜。　[存疑脚注] 转写将受访者人名记录为 Julio Marino 与 Brett Lim，推断分别为 Julio Merino 与 Brett Lymn，须以提交记录与会议名录核证（BSDTalk EP215，[43.16-91.08]，L1）

**史观**：

- 总纲10 动手者创造历史：需要长期专注的系统性工程无法指望开发者业余时间：基金会由此转向为重大工作设定悬赏或接受提案的资助模式，内核多处理与 Xen 多进程支持均以此完成并赶在发布前进入代码树。动手者的持续投入以经济基础为前提，志愿者模式与资助模式在项目中并存的分工由此成型。（BSDTalk EP215，[1165.3-1212.78]，L1）
- 总纲8 本体论上各方平等：受访者陈述的多架构哲学在本体论上平等对待各平台：罕见架构不因用户稀少而被视为二等，反而作为推荐安装流程的一环承担新发布在真实硬件上的验证职能；用户在冷门机器上运行测试并回报缺陷清单，与主流平台用户的反馈被同等采信。平台多样性与社区运行代码的义务互为条件。（BSDTalk EP215，[884.38-1031.42]，L1）

**辨析**：

- 受访者之间对 amd64 支持最多二百五十六核究竟是 6.0 还是 current 的特性说法不一：一人称 6.0 已含，另一人记忆中发布树最多三十二核，第三人引提交说明为证但承认不确定是否赶上发布。该版本归属须以 6.0 发布公告与 sysarch 头文件历史核证，不能仅凭访谈定论。　[存疑脚注] 256 核上限进入 6.0 还是 current 在受访者间存在分歧，属单一来源记忆冲突（BSDTalk EP215，[1104.3-1125.29]，L4）
