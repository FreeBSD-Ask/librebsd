# 185.1 NetBSD 的极简主义哲学与代码美学

**要点**：NetBSD 长期坚持“干净、可读、可维护”的代码美学，强调机制与策略分离、接口最小化、避免过度工程化；这一哲学源自 CSRG 传统，在 4.4BSD-Lite 之后由 Core Team 严格守护

**史料**：NetBSD Developer's Documentation；style(9) 手册页；tech-kern 邮件列表中关于代码风格的讨论；Core Team 公开声明

**史观**：组织结构塑造技术路径，极简主义不是审美偏好而是社区治理结构的产物

**辨析**：“极简主义”标签是事后叙事化的产物，需考据开发者本人的原始表述

**文献**：NetBSD style(9) 手册页 [EB/OL]. <https://man.netbsd.org/style.9>；NetBSD Developer's Documentation [EB/OL]. <https://www.netbsd.org/docs/>；tech-kern 邮件列表代码风格讨论 [EB/OL]. <https://mail-index.netbsd.org/tech-kern/> ［A］

#### 184.2"Of course it runs NetBSD"：可移植性作为文化认同

**netbsd-src 仓库可移植性 commit 量阶段对比（openbsd.db §L3.1.1.portable）**：

| 年份/阶段 | 可移植性 commit 量 | 阶段特征 | 备注 |
| --- | --- | --- | --- |
| **1993** | **1,260** | 立项首年高强度移植扩张 | 反映 NetBSD 立项首年即有大量可移植性投入 |
| 1990 年代后期—2000 年代初期 | 持续高位 | 新平台扩张期 | 多个新架构移植集中投入 |
| **2022** | **401** | 维护既有平台模式 | 较 1993 年下降 **68.2%** |
| 1993-2022 年 | 每年均有记录 | 持续存在 | 与口号文化延续形成数据层面呼应 |

**要点**："Of course it runs NetBSD"口号自 1990 年代末在社区流传，成为 NetBSD 文化认同的核心；该口号反映可移植性不仅是技术目标，更是社区身份建构

**史料**：NetBSD 社区口号档案；NetBSD Foundation 营销材料；mail-index.netbsd.org 中口号首次出现的讨论；netbsd.db 查询 L3.1.1.portable 显示：netbsd-src 可移植性相关 commit 在 1993 年 = 1,260，反映 NetBSD 立项首年即有大量可移植性投入；可移植性 commit 量在 1990 年代后期至 200 年代初期持续高位，2022 年 = 401（较 1993 年下降 68.2%），反映可移植性工作从初期的“高强度移植扩张”转向后期的“维护既有平台”模式；可移植性 commit 的持续存在（1993-2022 年每年均有记录）与"Of course it runs NetBSD"口号的文化延续形成数据层面的呼应 ［A］

**史观**：技术选择即政治选择，可移植性作为身份标识塑造了社区的边界

**辨析**：口号的首次出现时间与作者需考据，部分叙事将口号归于特定人物缺乏证据。L3.1.1.portable 查询基于 message_subject LIKE 匹配可移植性相关关键词（如"port""portable""platform""arch"等），1993-2022 年的 commit 数字均为下限，实际涉及可移植性的 commit 可能更多；可移植性 commit 量从 1,260 降至 401 的下降趋势与“可移植性作为文化认同”叙事方向一致，但 commit 量下降不等于可移植性文化衰退——可移植性工作的性质从“新增平台”转向“维护既有平台”，commit 量自然下降；GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），1993-2022 年 commit 量可能不完整

**文献**：NetBSD 口号档案 [EB/OL]. <https://www.netbsd.org/gallery/slogans.html>（原始链接失效，互联网档案馆无存档）；NetBSD Foundation 营销材料 [EB/OL]. <https://www.NetBSD.org/foundation/>；mail-index.netbsd.org 邮件列表存档 [EB/OL]. <https://mail-index.netbsd.org/>；bsd_commits.db 数据分析·深层信息挖掘.md §L3.1.1.portable（netbsd-src 可移植性相关 commit 1993-2022） ［A］

**要点**：

- Christos Zoulas 的 Unix 渊源、加入动因与代码质量文化：1984 年起使用 Unix（4.2BSD），大学环境中因各厂商 Unix 提供免费硬件而接触大量异构平台；1992/93 年被 NetBSD 吸引，核心愿景是同一份代码不经 ifdef 式改写与各种 hack 即可运行于所有机器；他以亲历者身份确认项目“实现不当就不合入”的取舍——补丁搁置数年、即便大量硬件依赖与用户抱怨也不放行，并承认项目因此“受损”，但视之为对代码质量与清晰度的有意坚持。（BSDTalk EP257，[95.08-220.72]，L1）
- NetBSD 7 的两大支柱：其一，x86 平台引入现代 DRM/KMS 图形栈，团队选择基于原始 Linux 代码重新开发移植而非复制 FreeBSD/OpenBSD 的做法，历时约一年半，数以千行计的复杂图形驱动入内核，主要由 Taylor R. Campbell（转写仅作“Taylor”）完成；其二，ARM 生态跃进——支持 Odroid、BeagleBone Black、Raspberry Pi 等开发板，引入 EABI、全面支持多核，并按有无硬件浮点、大小端、ABI 版本逐一产出优化二进制，构建农场负担大增。（BSDTalk EP257，[384.56-508.60]，L1）
- 交叉编译体系与双编译器策略：NetBSD 源码树 tools 子目录收纳构建系统所需的全部工具（make、编译器工具链、lex/yacc、文档生成工具乃至 file 程序），工具链不依赖目标系统的本地设施，除 amd64 外全部交叉编译；Joerg Sonnenberger（转写讹作 York Sonnenberg）将 Clang 移植进 base 成为 NetBSD 7 亮点，虽其架构覆盖不及 NetBSD 全谱系，但双编译器可暴露不可移植代码、发现编译器与汇编器缺陷，并互为绕行备胎。（BSDTalk EP257，[519.08-667.08]，L1）
- 发布工程与碎片化贡献：NetBSD 7 发布前夕 RC1/RC2 已出、自 current 向 7 的 pull-up 近千次、构建状态转绿，RC 用户反馈发现了开发团队手中没有的硬件相关缺陷，印证公开发布候选的社区测试价值；受访者育有两子并兼大学行政文书职务，以“这里几小时、那里几小时”的碎片方式贡献——维护 blacklistd、将 GDB 升级至 FSF 最新版并做系统调用适配、实现 wait6 及相关 sysctl、改进 DTrace。（BSDTalk EP257，[721.40-819.56]，L1）

**史料**：

- 本访谈构成一手史料：NetBSD 开发者 Christos Zoulas 于 2015 年 9 月 27 日 vBSDCon 第二天（Reston, Virginia）受访，自述其 1984 年 4.2BSD 以来经历、加入 NetBSD 动因、NetBSD 7 发布状态、DRM/KMS 移植决策及个人贡献清单。（BSDTalk EP257，[50.20-95.08]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：当事人加入 NetBSD 并无必然性可言：大学机群的异构性、厂商 Unix 送来的免费硬件、“受够了 ifdef”的具体困扰，这些偶然条件共同把一个 1984 年的 4.2BSD 用户推向可移植性事业——个人路径由具体际遇而非规律注定。（BSDTalk EP257，[145.44-186.60]，L1）
- 总纲10 动手者创造历史：一位兼做行政文书、育有两子的开发者以零散几小时的碎片劳动维系 GDB、DTrace、wait6 等子系统的适配，NetBSD 全架构构建农场正是由无数此类不出名的动手者拼合运转。（BSDTalk EP257，[296.04-365.64]，L1）
