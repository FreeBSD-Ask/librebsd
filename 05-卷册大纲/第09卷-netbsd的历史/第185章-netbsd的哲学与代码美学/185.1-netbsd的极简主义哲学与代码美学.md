# 185.1 NetBSD 的极简主义哲学与代码美学

**要点**：NetBSD 长期坚持“干净、可读、可维护”的代码美学，强调机制与策略分离、接口最小化、避免过度工程化；这一哲学源自 CSRG 传统，在 4.4BSD-Lite 之后由 Core Team 严格守护

**史料**：NetBSD Developer's Documentation；style(9) 手册页；tech-kern 邮件列表中关于代码风格的讨论；Core Team 公开声明

**史观**：总纲第 15 条——文化即形式主义〔存疑：重挂待复核〕：组织结构塑造技术路径，极简主义不是审美偏好而是社区治理结构的产物

**辨析**：“极简主义”标签是事后叙事化的产物，需考据开发者本人的原始表述

**文献**：NetBSD style(9) 手册页 [EB/OL]. <https://man.netbsd.org/style.9>；NetBSD Developer's Documentation [EB/OL]. <https://www.netbsd.org/docs/>；tech-kern 邮件列表代码风格讨论 [EB/OL]. <https://mail-index.netbsd.org/tech-kern/> ［A］

## 185.1.1 “Of course it runs NetBSD”：可移植性作为文化认同

**netbsd-src 仓库可移植性 commit 量阶段对比**：

| 年份/阶段 | 可移植性 commit 量 | 阶段特征 | 备注 |
| --- | --- | --- | --- |
| **1993** | **1,260** | 立项首年高强度移植扩张 | 反映 NetBSD 立项首年即有大量可移植性投入 |
| 1990 年代后期—2000 年代初期 | 持续高位 | 新平台扩张期 | 多个新架构移植集中投入 |
| **2022** | **401** | 维护既有平台模式 | 较 1993 年下降 **68.2%** |
| 1993-2022 年 | 每年均有记录 | 持续存在 | 与口号文化延续形成数据层面呼应 |

**要点**：“Of course it runs NetBSD”口号自 1990 年代末在社区流传，成为 NetBSD 文化认同的核心；该口号反映可移植性不仅是技术目标，更是社区身份建构

**史料**：NetBSD 社区口号档案；NetBSD Foundation 营销材料；mail-index.netbsd.org 中口号首次出现的讨论；netbsd.duckdb 查询 L3.1.1.portable 显示：netbsd-src 可移植性相关 commit 在 1993 年 = 1,260，反映 NetBSD 立项首年即有大量可移植性投入；可移植性 commit 量在 1990 年代后期至 2000 年代初期持续高位，2022 年 = 401（较 1993 年下降 68.2%），反映可移植性工作从初期的“高强度移植扩张”转向后期的“维护既有平台”模式；可移植性 commit 的持续存在（1993-2022 年每年均有记录）与“Of course it runs NetBSD”口号的文化延续形成数据层面的呼应 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：重挂待复核〕：技术选择即政治选择，可移植性作为身份标识塑造了社区的边界

**辨析**：口号的首次出现时间与作者需考据，部分叙事将口号归于特定人物缺乏证据。L3.1.1.portable 查询基于 message_subject LIKE 匹配可移植性相关关键词（如“port”“portable”“platform”“arch”等），1993-2022 年的 commit 数字均为下限，实际涉及可移植性的 commit 可能更多；可移植性 commit 量从 1,260 降至 401 的下降趋势与“可移植性作为文化认同”叙事方向一致，但 commit 量下降不等于可移植性文化衰退——可移植性工作的性质从“新增平台”转向“维护既有平台”，commit 量自然下降；GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 CVS **cvs.netbsd.org**，Mercurial **hg.NetBSD.org** 系转换镜像），1993-2022 年 commit 量可能不完整

**文献**：NetBSD 口号档案 [EB/OL]. <https://www.netbsd.org/gallery/slogans.html>（原始链接失效，互联网档案馆无存档）；NetBSD Foundation 营销材料 [EB/OL]. <https://www.NetBSD.org/foundation/>；mail-index.netbsd.org 邮件列表存档 [EB/OL]. <https://mail-index.netbsd.org/>；netbsd.duckdb 数据分析·深层信息挖掘.md §L3.1.1.portable（netbsd-src 可移植性相关 commit 1993-2022） ［A］

**要点**：

- Christos Zoulas 的 Unix 渊源、加入动因与代码质量文化：1984 年起使用 Unix（4.2BSD），大学环境中因各厂商 Unix 提供免费硬件而接触大量异构平台；1992/93 年被 NetBSD 吸引，核心愿景是同一份代码不经 ifdef 式改写与各种 hack 即可运行于所有机器；他以亲历者身份确认项目“实现不当就不合入”的取舍——补丁搁置数年、即便大量硬件依赖与用户抱怨也不放行，并承认项目因此“受损”，但视之为对代码质量与清晰度的有意坚持。（BSDTalk EP257，[95.08-220.72]，L1）
- NetBSD 7 的两大支柱：其一，x86 平台引入现代 DRM/KMS 图形栈，团队选择基于原始 Linux 代码重新开发移植而非复制 FreeBSD/OpenBSD 的做法，历时约一年半，数以千行计的复杂图形驱动入内核，主要由 Taylor R. Campbell（转写仅作“Taylor”）完成；其二，ARM 生态跃进——支持 Odroid、BeagleBone Black、Raspberry Pi 等开发板，引入 EABI、全面支持多核，并按有无硬件浮点、大小端、ABI 版本逐一产出优化二进制，构建农场负担大增。（BSDTalk EP257，[384.56-508.60]，L1）
- 交叉编译体系与双编译器策略：NetBSD 源码树 tools 子目录收纳构建系统所需的全部工具（make、编译器工具链、lex/yacc、文档生成工具乃至 file 程序），工具链不依赖目标系统的本地设施，除 amd64 外全部交叉编译；Joerg Sonnenberger（转写讹作 York Sonnenberg）将 Clang 移植进 base 成为 NetBSD 7 亮点，虽其架构覆盖不及 NetBSD 全谱系，但双编译器可暴露不可移植代码、发现编译器与汇编器缺陷，并互为绕行备胎。（BSDTalk EP257，[519.08-667.08]，L1）
- 发布工程与碎片化贡献：NetBSD 7 发布前夕 RC1/RC2 已出、自 current 向 7 的 pull-up 近千次、构建状态转绿，RC 用户反馈发现了开发团队手中没有的硬件相关缺陷，印证公开发布候选的社区测试价值；受访者育有两子并兼大学行政文书职务，以“这里几小时、那里几小时”的碎片方式贡献——维护 blacklistd、将 GDB 升级至 FSF 最新版并做系统调用适配、实现 wait6 及相关 sysctl、改进 DTrace。（BSDTalk EP257，[721.40-819.56]，L1）
- Taylor R Campbell 在开场自陈身份：NetBSD 核心团队成员，社区行名为 riastradh，使用 NetBSD 约十五年、任开发者约十二年，工作横跨网络、文件系统、并发与图形等领域；其入坑动因系一段计算自主权个案——2007 至 2008 年前后 Apple 决定禁止在调试器下运行 iTunes，他视之为对自己计算机自主权的剥夺，强调通用计算机本可执行任意计算、运行何种软件应由用户而非厂商决定；恰逢 Apple 弃用 PowerPC，他为手头闲置的 PowerBook G4 寻找尊重用户自主且能从源码构建的系统，在考察 Linux 与多家 BSD 后认定唯 NetBSD 使从源码构建并掌控所运行内容变得真正容易，遂于 2008 年迁移。（YouTube EPgm-F3GnM8yM，[41.28-395.64]，L1）
- 其新人历程由两个案例构成：一是安装后数周内在适配 stunnel TLS 隧道时复现一个内核级 bug——POSIX cmsg 辅助数据 API 的对齐判据疑似比较符写错，在严格对齐的 PowerPC 上出错而 x86 无碍，他循调用路径读内核源码并在 netbsd-users 邮件列表提出一行修复，数日内经 Christos Zoulas 提交入库，事后证明该修复并不完整、问题数年后才彻底解决，此事使从未做过内核编程的他确信自己可以参与开发；二是受此鼓舞后承接 Broadcom AirPort Extreme 驱动移植，以 OpenBSD 代码为底本、对照 FreeBSD 与 DragonFly 的实现，按编译、链接、运行的次序迭代数月至当年 9 月可用，其间依赖双机工作流——在 32 位 Intel MacBook 上交叉编译、经 FireWire Target Disk Mode 向 PowerBook G4 直送新内核，并评价 Broadcom 硬件与文档对开发者极不友好。　[存疑脚注] cmsg 对齐 bug 的比较符与分支细节系十五年后回忆，演讲人自认记忆不确，且修复非其一人完成，具体提交须以 2008 年邮件列表存档与 CVS 记录核验。（YouTube EPgm-F3GnM8yM，[402.55-845.52]，L1）
- 演讲主体系统演示 NetBSD 构建工作流：源码可经 CVS、git 或 Mercurial 检出，主库为 CVS，Mercurial 自动转换滞后数小时，官方明言近期将弃用 CVS 但尚未发生；build.sh 以 -O 收拢构建产物、-U 非特权构建（他主张本应为默认，1980 年代以来以 root 全程构建的传统今日观之并不妥当）、-u 增量更新、-m 指定架构、-N 与 -j 控制冗长与并行；release 目标一次产出交叉工具链、分发集、DESTDIR 阶段安装与各内核，且除非刻意配置，每次构建皆为交叉构建，从而把构建与宿主环境隔离、避免结构体定义失配；kernel=GENERIC 适用于多数端口，64 位 ARM 与 RISC-V 为 GENERIC64，evbppc、evbarm 等评估板端口按板裁剪内核，他以 Alpha、VAX 交叉构建与尚未完成的 PDP-10 移植玩笑展示架构覆盖之广。（YouTube EPgm-F3GnM8yM，[849.84-1231.64]，L1）
- 调试与测试底座的演示覆盖一条完整工具链：以 QEMU virt 虚机（附 virtio RNG 熵源与网卡）引导 arm64 镜像，经 vnd 将普通文件暴露为块设备以便挂载根文件系统更新内核；借 netbsd.gdb 符号文件与 -s 选项以 GDB 观察活内核数据结构，build.sh -V MKCROSSGDB 可产出交叉 GDB，宿主非提权状态下甚至可直接调试本机内核；崩溃后由转储设备保存核心，crash(8)——内核调试器 DDB 的用户态版本——负责解读栈回溯，串口 hw.cnmagic 与 sysctl crashme 旋钮分别用于陷入调试器与强制 panic 验证转储可用性，另有关中断死循环的每 CPU 卡死检测；测试侧以 atf-run 接 atf-report 运行数千项自动测试，特权运行覆盖内核路径而免权运行跳过危险用例，输出含崩溃栈回溯与单行摘要，发布工程站点持续运行自动化测试供新架构 bring-up 参照；2023 年他的实况工作台为 ThinkPad 运行 -current 内核加 NetBSD 9 用户态 chroot，在该 chroot 中验证发往 NetBSD 8、9、10 分支的 pull-up（安全补丁与特性回移），单机无需虚拟机，彼时 NetBSD 10 发布候选在即，团队刚完成 OpenSSL 升级至 3 的迁移，他直言大版本迁移皆是痛苦、差别仅在痛苦的风味，并答问指出 LibreSSL 已弃 VAX 支持且无法交叉构建，而 OpenSSL 在 NetBSD 上仍可交叉构建至 VAX。　[存疑脚注] OpenSSL 在 VAX 上 Ed448 用例失败的归因（GCC 误编译抑或实现 bug）为演讲现场未经验证的猜想。（YouTube EPgm-F3GnM8yM，[1297.60-2342.16]，L1）
- 设备驱动部分以去神秘化为纲：驱动并非公众印象中的黑魔法，而是与倔强硬件打交道的普通程序，困难常在缺少数据手册时须对硬件本身做科学探究；autoconf 框架经 PCI 总线、设备树与 ACPI 枚举硬件，驱动以 softc 持有状态（其词源连讲解人也不知，现场戏拟为软件副本）、经 CFATTACH_DECL 历代宏声明（参数累加的产物，终将迁往 C99 指定初始化器），match 函数比对 PCI vendor/product ID 与设备树 compatible 并返回优先级，attach 分配缓冲、互斥与线程，detach 处理热拔（他援引自己 EuroBSDcon 2022 的 detach 专题演讲）；用户态界面经由字符设备——主设备号路由操作逻辑，cloning 设备按次打开分配独立状态，音频混音器与用于 USB 栈测试的 vhc 虚拟主机控制器为实例；硬件访问层 bus_space 以 tag 与 handle 封装 I/O 端口与内存映射寄存器窗口，BIT、BITS、SHIFTIN、SHIFTOUT 宏使驱动近乎直译数据手册（以 Rockchip 加密引擎 TRNG 控制寄存器为例），bus_dma 则免去 memcpy 并以 bounce buffer 抽象地址限制；rump 内核允许在用户态进程运行内核组件，VFS 测试在 chroot 内以 ATF 驱动并可挂 GDB，他自述借此完成 rename 系统调用一类棘手文件系统问题的调试。（YouTube EPgm-F3GnM8yM，[2486.79-3383.56]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：当事人加入 NetBSD 并无必然性可言：大学机群的异构性、厂商 Unix 送来的免费硬件、“受够了 ifdef”的具体困扰，这些偶然条件共同把一个 1984 年的 4.2BSD 用户推向可移植性事业——个人路径由具体际遇而非规律注定。（BSDTalk EP257，[145.44-186.60]，L1）
- 总纲10 动手者创造历史：一位兼做行政文书、育有两子的开发者以零散几小时的碎片劳动维系 GDB、DTrace、wait6 等子系统的适配，NetBSD 全架构构建农场正是由无数此类不出名的动手者拼合运转。（BSDTalk EP257，[296.04-365.64]，L1）
- 总纲10 动手者创造历史：全场以第一人称示范了动手者如何进入并留在系统开发之中：从邮件列表一行修复、Wi-Fi 驱动移植到文件系统调试，NetBSD 的技术史由具体提交、调试与文档迭代的动手行为续写，演讲本身即一位核心团队成员向后来者传授动手路径的现身说法，历史主体不是台前名人而是每日构建与测试的实践者。（YouTube EPgm-F3GnM8yM，[658.76-703.96]，L1）
- 总纲3 不存在进步，只有权力再分配：演讲人把 2007 至 2008 年 Apple 禁止在调试器下运行 iTunes 的决定理解为对用户计算机主权的剥夺，其出走并非宣称 NetBSD 技术更优，而是控制权归属之争——对通用计算机的支配从厂商手里移回用户手里；个人计算平台的迁移史在此呈现为用户与供应商之间权力关系的再分配，而非单纯的技术进步叙事。（YouTube EPgm-F3GnM8yM，[238.35-306.60]，L1）
