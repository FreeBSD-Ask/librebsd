**要点**：

- core group 的职能与项目定位：core 提供项目技术方向、决定特性增删与聚焦领域、裁决社区僵局争执、确定发布时机与内容，本质是技术项目管理，非技术事务另归独立董事会；NetBSD 的自我概括是“它当然能跑 NetBSD”——高度可移植的 BSD 系操作系统、无 GNU 许可顾虑，从 4 至 8MB 内存的小型嵌入式系统一直覆盖到 AMD64、Alpha、SPARC 大型服务器；全部架构共用一个集成源码树，无单独内核树或用户态树，各架构支持水平差异仅源于志愿工作量，项目几乎全靠志愿者、没有企业金主。（BSDTalk EP35，[76.8-232.72]，L1）
- 当事人的用途画像：本人主要将 NetBSD 用作嵌入式系统与复古计算——找不到操作系统的旧机器“过时了就跑 NetBSD”；桌面使用者虽存在但他本人用 OS X；嵌入式工作的优势在于源码树完全集成、易于裁去不需要的部分，且全 BSD 许可使企业无需担忧 GPL 义务；他所在公司的施乐复印机说明书即载明其内部使用 NetBSD。（BSDTalk EP35，[236.24-312.56]，L1）
- 3.x 与 4.x 的路线：3.0 系列引入 PAM、显著改进 AMD64 支持并以原生线程实现 pthread，同时 3.0 的维护性小版本即将开始；4.0 计划升级 GCC 与 binutils，并以 OS X 的内核授权机制为蓝本替换标准内核授权设施；当事人强调 NetBSD 没有 not-invented-here 的毛病，其他操作系统的好想法只要合理可用就会采纳。（BSDTalk EP35，[312.56-397.24]，L1）
- 平台持久性承诺：NetBSD 恪守继续支持厂商已放弃架构的传统，Apple 转向 Intel 后其旧 PowerPC 硬件仍将由 NetBSD 支持且当事人看不出停止的理由；NetBSD 历史上仅放弃过一个平台，原因是该 port 所面向的两颗处理器被物理销毁，此外所有被移植过的平台至今仍存在于源码树中。（BSDTalk EP35，[638.68-682.54]，L1）
- 桌面笔记本短板与 pkgsrc 广度：NetBSD 已有 ACPI 支持与辅助睡眠的电源守护进程但未达理想，SpeedStep 与增强型 SpeedStep 仍在改进；瓶颈在于 ACPI 实现数量庞大且普遍带有缺陷、须逐机型添加 quirk，耗时费力；pkgsrc 由 NetBSD 首创、是传统 BSD ports 之外的路径，现已支持 Solaris、Linux、HP-UX 等操作系统并包含 OS X，应用数量与 NetBSD ports 相当而目标广度更大——可能没有全部 port，但运行在比以往 BSD ports 更多的硬件目标上。（BSDTalk EP35，[682.54-790.66]，L1）
- 参与门槛与捐赠生态：当事人坦言 NetBSD 代码质量标准很高（自称此说听来精英主义），大量志愿工程师相当资深，外部贡献常达不到标准，新人须比其他项目获得更多指导，建议路径是认领未决缺陷、通过修缺陷学习代码并以既有代码为范本；NetBSD Foundation 为经认证的 501(c)(3) 非营利组织、捐款可抵税，主要用于改进构建与测试平台且总体开支不大；文档与网页改进建议受欢迎，硬件捐赠则视实用性——古怪的小型嵌入式板卡有人认领，需整机架的大家伙无人问津。（BSDTalk EP35，[797.74-969.98]，L1）

**史料**：

- 当事人二十余年 BSD 履历的一手自述：80 年代早期在 Digital 从 4.2BSD 开始，该系统演化为 Ultrix 32 与 Ultrix，他参与将 Ultrix 移植到 MIPS 处理器，其后演化为仍基于 4.3BSD 的 DEC OSF/1 并延伸至 Alpha；在 Digital 面对公司各类网卡起意“为自由操作系统写驱动有多难”，遂以编写网卡驱动进入 BSD 世界，离开 Digital 后日益投入 NetBSD 并不断购置硬件；2001 年加入一家以 PowerPC 与 NetBSD 构建嵌入式系统的初创公司（20 颗 PPC、数 GB 内存的非典型嵌入式环境），因当时 PowerPC 支持不足而重写 PMAP 模块、重做大量中断代码，使 NetBSD 的 PowerPC 支持稳定成熟。（BSDTalk EP35，[473.8-637.68]，L1）

**辨析**：

- 内核许可证纪律与 GPL 排斥的实例：NetBSD 内核几乎全部 BSD 许可，当前内核中已无非 BSD 许可内容；用户态则保留一批 GNU 工具，因为无处可得能运行于数十种架构的编译器；当事人举例称很想引入 SGI 为 Linux 编写的 XFS 支持，但该代码仅以 GPL 发布、与 BSD 许可不兼容而只得放弃，若有双许可本可两全；至于大公司只发 GPL 代码，要求其改用 BSD 许可意味着多付律师费做额外工作，并不现实。（BSDTalk EP35，[397.24-473.6]，L1）
