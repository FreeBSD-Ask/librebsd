## 173.1.5 NetBSD 从 4.4BSD-Lite2 继承的 union 文件系统（跨 BSD/UNIX/macOS 扩展）

**要点**：NetBSD 自 1.0（**1994-10-26**）起从 4.4BSD-Lite2 继承 union stack 文件系统，提供 **mount_union(8)** 命令——其核心机制是将上层目录与下层目录叠加挂载，上层接收写操作，下层保持只读，与 FreeBSD unionfs 的“复制向上”语义同源。NetBSD 的 union 实现随 4.4BSD-Lite2 整合进入 NetBSD 1.0 与 1.1 系列，man page 见 **man.netbsd.org/mount_union.8**。此实现与 FreeBSD unionfs 在 on-disk 格式上同源，但 NetBSD 在 1.6 后期逐步转向可堆叠文件系统框架（layered fs）重构，与 FreeBSD unionfs 的代码路径分叉。

**史料**：NetBSD 1.0 Release Notes（netbsd.org/releases/formal-1.0.html）；**mount_union(8)** man page（man.netbsd.org/mount_union.8）；NetBSD src 仓库 **sbin/mount_union/** 目录源码；McKusick, M. K. et al. (1996). *The Design and Implementation of the 4.4BSD Operating System*. Addison-Wesley, Chapter 7——4.4BSD-Lite2 union 文件系统设计。〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 2 条——分离与聚合：union 文件系统在 4.4BSD-Lite2 中聚合入 NetBSD 1.0，是 CSRG 遗产与 NetBSD 工程哲学的聚合时刻；总纲第 6 条——技术选择的代价：NetBSD 选择保留 union 而非重写为更现代的 unionfs-overlay 框架，付出维护复杂度代价，但获得与 4.4BSD-Lite2 的代码连续性；总纲第 10 条——边缘者贡献：union stack 最初由 CSRG 工程师设计，其姓名在 NetBSD man page 中被遮蔽，仅保留“4.4BSD-Lite2”集体署名；总纲第 17 条——形式与内容：union 作为“形式”（叠加挂载语义）统一了上层与下层文件系统的“内容”（数据与元数据）；总纲第 25 条——终结中的延续：NetBSD 在 1.6 后期转向 layered fs 框架，union 实现逐步被重构，但 **mount_union(8)** 命令作为“延续”的形式保留至今；自反性声明：本释读基于 union 文件系统在 NetBSD 1.x 的代码史实，不预设“BSD 谱系中心论”——union 在 Linux（OverlayFS）与 macOS（firmlinks）有独立演化路径，本节仅释读 NetBSD 一支。

**辨析**：NetBSD union 与 FreeBSD unionfs 在 4.4BSD-Lite2 前完全同源，分叉发生在 NetBSD 1.6（2002）后的 layered fs 重构；与 Linux OverlayFS（2013 年合入 3.18）的实现完全不同——OverlayFS 采用“copy_up”机制且针对容器场景优化，union 采用传统 stack 语义。macOS 无 unionfs，使用 APFS firmlinks（2017 年 macOS 10.13 High Sierra 起）实现类似但语义不同的根卷叠加。

## 173.1.6 NetBSD 从 4.4BSD-Lite2 继承的 null 层文件系统（跨 BSD/UNIX/macOS 扩展）

**要点**：NetBSD 自 1.0（**1994-10-26**）起从 4.4BSD-Lite2 继承 null 层文件系统，提供 **mount_null(8)** 命令——其核心机制是将一个目录树“透明地”映射到另一个挂载点，所有 VOP 操作透传至下层，不修改数据。null 层在 4.4BSD-Lite2 中作为可堆叠文件系统框架（layered fs）的基础组件，与 union 层、umap 层共享相同的 VFS 层叠加机制。NetBSD 的 null 实现保留至今，man page 见 **man.netbsd.org/mount_null.8**。

**史料**：NetBSD 1.0 Release Notes；**mount_null(8)** man page（man.netbsd.org/mount_null.8）；NetBSD src 仓库 **sbin/mount_null/** 与 **sys/miscfs/nullfs/** 目录源码；McKusick et al. (1996). *The Design and Implementation of the 4.4BSD Operating System*. Chapter 7——4.4BSD-Lite2 layered fs 框架。〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 2 条——分离与聚合：null 层在 4.4BSD-Lite2 中聚合入 NetBSD 1.0，是 CSRG layered fs 框架的延续；总纲第 6 条——技术选择的代价：NetBSD 选择保留 null 层作为 layered fs 基础，付出抽象层复杂度代价，但获得 VFS 操作透传的工程便利；总纲第 10 条——边缘者贡献：null 层的最初设计者姓名在 4.4BSD-Lite2 文档中被遮蔽，仅保留“CSRG”集体署名；总纲第 17 条——形式与内容：null 层作为“形式”（透传 VOP）保留了下层文件系统的“内容”（数据与元数据）；总纲第 25 条——终结中的延续：NetBSD 1.6 后期 layered fs 框架重构，null 层作为基础组件被保留，是“延续”的显现；自反性声明：本释读不预设“BSD 中心论”——null 层在 DragonFly BSD（fork 自 FreeBSD 4.8）有独立演化，Linux 无 nullfs 但 OverlayFS 提供类似功能。

**辨析**：NetBSD null 层与 FreeBSD nullfs 在 4.4BSD-Lite2 前完全同源，分叉发生在 FreeBSD 5.0（2003）GEOM 框架引入后——FreeBSD nullfs 被重构为 GEOM 类，NetBSD null 层保留为传统 layered fs 组件。Linux 无 nullfs，OverlayFS 提供类似但语义不同的叠加挂载。macOS 无 nullfs。DragonFly BSD 在 **sys/vfs/nullfs/** 目录保留 nullfs 实现（fork 自 FreeBSD 4.x，未跟随 GEOM 重构）。

## 173.1.7 NetBSD 从 4.3BSD-Reno/4.4BSD-Lite2 继承的 ktrace 系统调用追踪（跨 BSD/UNIX/macOS 扩展）

**要点**：NetBSD 自 0.9（**1993-08**）起从 4.3BSD-Reno 继承 ktrace 子系统，提供 **ktrace(1)** 命令与 **ktrace(2)** 系统调用——其核心机制是启用内核追踪后，将指定进程的系统调用、信号、I/O 操作记录至 ktraceout 文件，供 **kdump(1)** 回放分析。NetBSD ktrace 与 FreeBSD ktrace 在 4.3BSD-Reno 前完全同源，man page 见 **man.netbsd.org/ktrace.1**。ktrace 是 BSD 谱系最早的系统调用追踪机制，早于 Linux strace（1989 年 Paul Kranenburg 首发）与 Solaris truss（1990 年代初）。

**史料**：NetBSD 0.9 Release Notes；**ktrace(1)** 与 **ktrace(2)** man page（man.netbsd.org/ktrace.1、man.netbsd.org/ktrace.2）；NetBSD src 仓库 **sys/kern/sys_ktrace.c** 源码；McKusick et al. (1996). *The Design and Implementation of the 4.4BSD Operating System*. Chapter 3——ktrace 设计。〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 1 条——源头时刻：ktrace 是 4.3BSD-Reno 时期（1990 年）CSRG 工程师面对调试需求的工程洞察，奠定了 BSD 谱系系统调用追踪的基础；总纲第 2 条——分离与聚合：ktrace 在 4.3BSD-Reno 中聚合入 NetBSD 0.9，是 CSRG 遗产与 NetBSD 工程哲学的聚合时刻；总纲第 6 条——技术选择的代价：NetBSD 选择保留 ktrace 而非重写为更现代的 DTrace 框架，付出功能局限代价，但获得与 4.3BSD-Reno 的代码连续性；总纲第 10 条——边缘者贡献：ktrace 的最初设计者姓名在 4.3BSD-Reno 文档中被遮蔽，仅保留“CSRG”集体署名；总纲第 17 条——形式与内容：ktrace 作为“形式”（系统调用追踪）统一了不同进程的“内容”（系统调用行为）；自反性声明：本释读不预设“BSD 中心论”——ktrace 在 Linux（strace）、Solaris（truss）、macOS（kdebug）有独立演化路径，本节仅释读 NetBSD 一支。

**辨析**：NetBSD ktrace 与 FreeBSD ktrace 在 4.3BSD-Reno 前完全同源，分叉发生在 NetBSD 1.6 后期的 layered fs 重构；与 Linux strace 的关键差异——strace 基于 ptrace(2) 系统调用，ktrace 基于独立的 ktrace(2) 系统调用，二者无代码共享；macOS ktrace/kdebug 子系统在 Mojave（10.14）及之前版本 man page 可见，Catalina（10.15）之后逐步收紧，但仍可通过 Instruments 工具使用。

**文献**：NetBSD Project. *NetBSD 0.9 Release Notes*[EB/OL]. (1993-08). <https://www.netbsd.org/releases/formal.html>; NetBSD Project. *ktrace(1) Manual Page*[EB/OL]. <https://man.netbsd.org/ktrace.1>; McKusick, M. K. et al. ## 173.1.8 NetBSD 从 4.3BSD-Tahoe 继承的 fstat(1)（跨 BSD/UNIX/macOS 扩展）

**要点**：NetBSD 自 0.8（**1993-04-20**）起从 4.3BSD-Tahoe（**1988 年 6 月**）继承 **fstat(1)** 命令——其核心机制是通过 **kvm(3)** 库读取内核内存，列出指定进程打开的文件描述符、socket、管道等。**fstat(1)** 早于 Linux lsof（Vic Abell 1982 年起维护，但 Linux 移植在 1990 年代）。man page 见 **man.netbsd.org/fstat.1**。NetBSD fstat 与 FreeBSD fstat 在 4.3BSD-Tahoe 前完全同源，分叉发生在 NetBSD 1.0 后的独立维护。

**史料**：NetBSD 0.8 Release Notes；**fstat(1)** man page（man.netbsd.org/fstat.1）；NetBSD src 仓库 **sbin/fstat/** 目录源码；McKusick et al. (1996). *The Design and Implementation of the 4.4BSD Operating System*. Chapter 4——fstat 设计。〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 1 条——源头时刻：fstat 是 4.3BSD-Tahoe 时期 CSRG 工程师面对文件描述符调试需求的工程洞察；总纲第 2 条——分离与聚合：fstat 在 4.3BSD-Tahoe 中聚合入 NetBSD 0.8，是 CSRG 遗产的延续；总纲第 6 条——技术选择的代价：NetBSD 选择保留 fstat 而非引入 lsof，付出功能局限代价（fstat 仅列当前进程，lsof 列所有进程），但获得与 4.3BSD-Tahoe 的代码连续性；总纲第 10 条——边缘者贡献：fstat 的最初设计者姓名被遮蔽，仅保留“CSRG”集体署名；总纲第 17 条——形式与内容：fstat 作为“形式”（文件描述符列表）统一了不同进程的“内容”（打开的文件）；自反性声明：本释读不预设“BSD 中心论”——fstat 在 Linux 无对应命令（lsof 提供类似功能），在 macOS 也无 fstat(1)。

**辨析**：NetBSD fstat 与 FreeBSD fstat 在 4.3BSD-Tahoe 前完全同源；与 Linux lsof 的关键差异——fstat 基于 kvm(3) 读取内核内存，lsof 基于遍历 /proc 与内核数据结构，二者无代码共享；macOS 无 fstat(1)，提供 lsof 作为标准替代。

**文献**：NetBSD Project. *NetBSD 0.8 Release Notes*[EB/OL]. (1993-04-20). <https://www.netbsd.org/releases/formal.html>; NetBSD Project. *fstat(1) Manual Page*[EB/OL]. <https://man.netbsd.org/fstat.1>; McKusick, M. K. et al. (1996). *The Design and Implementation of the 4.4BSD Operating System*. Addison-Wesley. Chapter 4.
