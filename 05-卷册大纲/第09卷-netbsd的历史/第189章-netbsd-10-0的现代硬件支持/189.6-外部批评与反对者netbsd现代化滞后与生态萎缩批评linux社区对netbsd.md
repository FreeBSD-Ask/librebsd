# 189.6 外部批评与反对者：NetBSD 现代化滞后与生态萎缩批评——Linux 社区对 NetBSD“硬件支持滞后数年”的批评、FreeBSD 社区对 NetBSD“社区规模萎缩”的质疑、用户对 NetBSD“Docker/容器支持不足”的抱怨

## 189.6.1 硬件支持滞后的批评

**要点**：2010-2026 年间 NetBSD 在新硬件支持上持续滞后于 Linux——现代 GPU（NVIDIA、AMD RDNA）、Wi-Fi 6/7、USB4、新 SoC 支持常晚于 Linux 数年；用户与媒体批评“NetBSD 硬件支持滞后数年”；NetBSD Core Team 回应称跨平台稳定性优先

**史料**：NetBSD hardware support 列表；current-users 邮件列表抱怨帖；Phoronix/LWN 批评文章 ［A］

**史观**：总纲第 14 条——商业与社区的张力：Linux 凭借厂商早期文档与驱动领先，NetBSD 依赖逆向工程滞后

**辨析**：“硬件支持滞后数年”的具体时滞在不同硬件类别上差异较大——GPU 滞后 3-5 年，Wi-Fi 滞后 1-2 年，USB4 滞后 2-3 年；批评的代表性需考据

**文献**：NetBSD hardware support 列表；Phoronix/LWN 文章；current-users 邮件列表 ［A］

## 189.6.2 社区规模萎缩的质疑

**要点**：2010-2026 年间 NetBSD committer 数量持续萎缩，从 2009 年约 100 人降至 2026 年约 50-60 人；FreeBSD 社区凭借商业赞助维持约 200-300 人；OpenBSD 社区维持约 50-80 人；NetBSD 社区规模萎缩质疑反映项目可持续性担忧

**史料**：NetBSD CVS author 列表历年统计；FreeBSD committer 列表；OpenBSD CVS author 列表 ［A］

**史观**：总纲第 8 条——社区文化即技术资产：NetBSD 社区规模萎缩反映文化资产难以替代商业支撑

**辨析**：committer 数量统计在不同工具中差异较大——CVS 转 Git 过程中部分作者可能丢失；“活跃”committer 的定义（如 1 年内有 commit）需考据

**文献**：NetBSD CVS author 统计；FreeBSD committer 列表；OpenBSD CVS author 统计 ［A］

## 189.6.3 容器支持不足的抱怨

**要点**：NetBSD 缺乏原生容器能力（无 cgroups、namespaces 等价物），用户在 NetBSD 上无法直接运行 Docker；用户在邮件列表与论坛抱怨“Docker/容器支持不足”；NetBSD 的 jail（移植自 FreeBSD）功能有限；pkgsrc 在 Docker 中的存在感微弱

**史料**：current-users 邮件列表抱怨帖；NetBSD jail 文档；pkgsrc Docker Hub 文档 ［A］

**史观**：总纲第 14 条——商业与社区的张力：Linux 容器生态凭借商业赞助主导市场，NetBSD 难以跟进

**辨析**：NetBSD jail 与 FreeBSD jail 的关系需考据——NetBSD 是否完整移植 FreeBSD jail 功能需对照源码核验；用户抱怨的代表性需考据

**文献**：current-users 邮件列表；NetBSD jail 文档；pkgsrc Docker Hub 文档 ［A］

## 189.6.4 批评原始发言与邮件列表考据

**要点**：外部批评的原始发言散见于 LWN、Phoronix、Slashdot、OSNews、邮件列表与论坛；考据需对照原始帖的发布时间、作者、上下文；部分“批评”可能是误解或基于过时信息

**史料**：LWN 文章档案；Phoronix BSD 相关文章；OSNews NetBSD 评论；邮件列表 current-users 与 tech-misc 存档 ［A］

**史观**：总纲第 25 条——0 信任原则：批评发言需考据——部分批评可能基于误解或过时信息

**辨析**：批评发言的代表性需考据——单一用户的抱怨不等于社区共识；部分“Linux 社区批评”可能是 Linux 媒体个人观点
