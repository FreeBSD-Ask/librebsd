# 189.3 NetBSD 与 AI 时代的“被污染代码”政策（2023-2026）——NetBSD 2023 年率先明确将 AI 生成代码定性为“被污染的代码”（tainted code），禁止直接合入主线，须人工审查后方可提交

## 189.3.1 tainted code 政策的出台语境

**要点**：NetBSD 2023 年率先明确将 AI 生成代码（如 GitHub Copilot、ChatGPT 生成的代码）定性为“被污染的代码”（tainted code），禁止直接合入主线；背景包括 GitHub Copilot 版权诉讼、Free Software Foundation 对 AI 代码的版权担忧；NetBSD Core Team 在 tech-kern 邮件列表发布政策讨论

**史料**：NetBSD Core Team 关于 tainted code 的公告；tech-kern 邮件列表讨论；GitHub Copilot 版权诉讼档案 ［A］

**史观**：总纲第 25 条——0 信任原则：tainted code 政策是 NetBSD 对 AI 时代“真实性困境”的哲学回应，体现 0 信任原则在代码层面的实践

**辨析**：tainted code 政策的具体条款（如“AI 生成代码须审查哪些方面”）在不同叙事中存在差异——需对照 Core Team 公告原文核验；政策出台的具体时间（2023 年中 vs 2023 年底）需考据

**文献**：NetBSD Core Team 公告；tech-kern 邮件列表；GitHub Copilot 版权诉讼档案 ［A］

## 189.3.2 政策的具体条款与执行

**要点**：tainted code 政策条款包括：AI 生成代码须明确标注来源、须由人类开发者逐行审查、不得直接粘贴；执行依赖 committer 自我声明与 peer review；政策未引入自动化检测工具（因 AI 检测技术不可靠）

**史料**：NetBSD tainted code 政策文档；tech-kern 邮件列表执行讨论；committer 自我声明样本 ［A］

**史观**：总纲第 17 条——形式与内容：政策作为“形式”（条款与流程）保障代码“内容”（人工审查的真实性）

**辨析**：政策执行的实际效果缺乏公开统计——需对照 commit log 中 AI 代码标注比例核验；“AI 生成代码”的定义（如完全 AI 生成 vs AI 辅助）在政策中可能存在模糊

**文献**：NetBSD tainted code 政策文档；tech-kern 邮件列表 ［A］

## 189.3.3 与 FreeBSD/OpenBSD AI 代码政策的比较

**要点**：FreeBSD 2023-2026 年间对 AI 代码政策相对宽松，允许 AI 辅助但要求人类审查；OpenBSD 由 de Raadt 主导对 AI 代码持强烈怀疑态度，但未出台正式政策；NetBSD 是三大 BSD 中唯一明确出台 tainted code 政策的项目

**史料**：FreeBSD Committer's Guide 关于 AI 代码的章节；OpenBSD 邮件列表 de Raadt 关于 AI 的发言；NetBSD tainted code 政策 ［A］

**史观**：社区文化即技术资产：三大 BSD 对 AI 代码的不同态度反映各自社区文化——NetBSD 谨慎、FreeBSD 务实、OpenBSD 怀疑

**辨析**：FreeBSD 与 OpenBSD 的“AI 代码政策”在不同叙事中存在差异——部分资料称两者均无正式政策，部分称有非正式指导，需对照官方文档核验；OpenBSD de Raadt 的私人观点与 OpenBSD 官方立场需区分

**文献**：FreeBSD Committer's Guide；OpenBSD 邮件列表；NetBSD tainted code 政策 ［A］
