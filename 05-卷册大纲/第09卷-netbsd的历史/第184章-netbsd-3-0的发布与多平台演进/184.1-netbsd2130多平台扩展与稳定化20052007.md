# 184.1 NetBSD 2.1/3.0 多平台扩展与稳定化（2005-2007）

**NetBSD 3.0 发布 commit 原文**：

> Welcome to NetBSD 3.0 release.
>
> ——netbsd-src 仓库，commit 2005-12-18T14:11:21Z

**要点**：NetBSD 2.1（2005.11）与 3.0（2005.12）以稳定化为主，扩展新平台支持（如 AMD64、ARM 多变体）；3.0 强化 SMP 支持在嵌入式与服务器场景的可用性

**史料**：NetBSD 2.1/3.0 Release Notes；NetBSD Foundation 2005-2007 年度报告；tech-kern 邮件列表稳定化讨论；netbsd.duckdb netbsd-src 仓库 commit 证据（“Add configurations for the NetBSD 2.1 release” commit_hash 见 netbsd-src 2005-10-22；“Welcome to NetBSD 3.0 release.” commit 2005-12-18；“Add that NetBSD 2.0 was released on December 09, 2004” commit 2005-03-12）；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2005 年 commit_count = 30,344（2.1/3.0 双发布年），2006 年 = 30,561（较 2005 年微增 0.7%），2007 年 = 28,670（较 2006 年下降 6.2%），反映 2.x-3.x 时期社区投入趋于稳定但增长乏力；netbsd.duckdb 查询 L2.3.1.smp 显示：netbsd-src 2005 年 SMP 相关 commit = 15，2006 年 = 8（较 2005 年下降 46.7%），2007 年 = 38（较 2006 年增长 375.0%，2.x-3.x 时期 SMP 峰值），反映 SMP 工作在 2007 年有明显集中投入 ［A］

**史观**：技术选择的代价，多平台扩展付出维护成本，但巩固了 “of course it runs NetBSD” 的品牌定位

**要点**：

- 2006 年 1 月 ShmooCon 大会（华盛顿特区）上发布名为 Anonymous OS 的 live CD，基于 OpenBSD 3.8 并集成 Tor 匿名加密代理网络，供用户经开放无线接入点匿名上网；该项目获 Wired 杂志报道，主持人认为此类报道有助于提升 BSD 的公众可见度。（BSDTalk EP6，[26.52-58.90]，L2）
- 该匿名系统项目随附的演示文稿分别评述加固 Windows、Linux 与 macOS 的路径：Linux 侧需叠加大量内核补丁方能实现栈溢出保护等能力，而这些能力在 OpenBSD 中已经内置；文稿未明言选型理由，但对比本身说明了 OpenBSD 安全设计的先天优势。（BSDTalk EP6，[116.16-153.64]，L2）
- 主持人以周末实验完成 FreeBSD、NetBSD、OpenBSD 三系统三重引导：先用 NetBSD 安装器以菜单驱动方式切分磁盘并标记各 slice 的系统类型，再装 NetBSD bootloader 作引导菜单，随后各系统安装器均能凭 slice 类型标记自动定位安装目标。（BSDTalk EP6，[210.90-392.84]，L1）
- 在仅数 GB 的旧笔记本硬盘上，FreeBSD 的自动分区默认值导致根分区过小，主持人改用单个根分区加交换空间的手动方案；最终三系统均可引导，其实验结论是 NetBSD 安装器防呆且安装介质小巧易得，推荐以 NetBSD 安装器与 bootloader 完成此类多系统布局。（BSDTalk EP6，[392.84-477.04]，L1）
- 受访者入坑经历：1990 年代末在 Western Digital 的分包商处支持一套专跑 FreeBSD 的硬盘物流系统，除物理盘故障外从未出现问题，其设计被其评价为优雅；此后试用 Linux 因不满 Red Hat 包管理而 FreeBSD ports 从未让他出问题，遂固定使用 FreeBSD 至今。（BSDTalk EP10，[127.86-189.50]，L1）
- 部署概况：加州 Fullerton 学区推行一对一笔记本计划，每名学生配一台底层运行 Darwin 的 Apple iBook，FreeBSD 承担控制全部 iBook 的后台服务器角色；BSD 只作服务器用途、不部署桌面（避免 KDE 等员工培训成本），完全占据服务器机房与各站点计算机；加州教育经费长期紧张，主要靠捐赠设备，BSD 装在捐赠旧硬件上整合入网，形成有钱买 Apple、没钱装 FreeBSD 的弹性组合，两者互操作良好。（BSDTalk EP10，[190.32-261.62]，L1）
- 可管理性与灾备设计：技术部门仅四人，以 OpenLDAP 集中管理全部学生笔记本的权限与账户，且刻意保持 Apple GUI 工具可直接管理 Intel 硬件上的 LDAP，使日常管理无需专家在场；针对管理层被公交撞了网络怎么办的追问，受访者以 sysinstall（其 man 页自认不应再存在）开设安装培训课，并为每台机器编制三环活页夹（配置文件与已装包清单），保证文字资料足以重建系统。（BSDTalk EP10，[283.38-405.98]，L1）
- 运维可靠性与旧硬件性能：以无 GUI 的 cvsup 经 cron 定期更新，除非重大安全问题不强制升级；一台 FreeBSD 4.0 机器在仓库执行简单任务已连续运行数年而无需到场维护；跨版本升级不难，3.x 手册已不再推荐 buildworld 而有二进制升级建议，最坏情况重装并迁移配置文件即可。BSD 可跑低配硬件是其关键优势：一台 Pentium 3 为 1200 台笔记本提供名字服务并承担 7 个 VLAN 的 DHCP，处理器利用率从未低于四成仍稳定运转；FreeBSD 的 PowerPC 支持规模有限，NetBSD 对 PowerPC 的支持成熟得多，学区借此复活大量退役 PowerPC Mac 与 Intel 捐赠机并用。（BSDTalk EP10，[406.58-660.80]，L1）
- Apple 对比与安全管控：若资金充裕，前端设备仍会保持 FreeBSD，阵列存储会选 Apple 因其界面简单；Apple 整机溢价换来后端与笔记本皆不受病毒蠕虫侵扰，省下的运维开支转投学生教育软件。对学术环境是否对网络抱敌意的问题，受访者称学生总体守规矩，曾抓到安装包嗅探程序者，但 OpenLDAP 目录结构将 Apple 笔记本锁定为只能启动事先授权的应用，下载程序即使在其用户空间内也无法获得执行许可。全套服务均构建于 FreeBSD：对外 VPN（可携带分支办公室，用 Stunnel）、RADIUS 认证、Squid 加 SquidGuard、学生行为监控的 LDAP 认证、面向业务办公室的 Samba 文件共享与面向 Apple 客户端的 Netatalk。（BSDTalk EP10，[503.50-701.10]，L1）
- SDF 的起源链完整可考：Ted Uelman 于 1987 年以 Apple II BBS 起家，用户圈为达拉斯-沃斯堡本地 BBS 社区的日本动漫爱好者，当时运行 ProDOS 并追求更命令行化的界面；1989 年 Stephen Jones 加入，先后弄到 Unix 克隆 Coherent 与移植到 386 的 System V；转折发生在 1990 年 2 月——本地公共访问 Unix 系统 Killer（killer.dallas.tx.us，Charlie Boykin 运营）在 Operation Sun Devil 中被美国特勤局查封，起因是泄露的 AT&T E911 文档据报存于该站；两人决意自建系统取而代之，初期被本地 Unix 管理员视为惹事的孩子而处处受阻，随后 Killer 老用户陆续迁入，Apple II BBS 遂被彻底放弃。（BSDTalk EP21，[88.93-271.01]，L1）
- 联网路径上，SDF 先以 UUCP 经由南卫理公会大学与 Adaptec 等本地中心交换邮件与新闻，1991 年加入 LoneStar.org（该域名 1989 年注册，加入时约五百台主机，成员从跑邮件与新闻的公司 Unix 到在家运行 3B2、3B1 的个人），因而沿用 sdf.lonestar.org 而未自注域名；1992 年两位创始人路线分歧：Ted 希望附带营利商业计划，理想主义且反企业的 Jones 坚持系统完全自由不受限，Ted 遂与部分用户另立 Texas Metronet，成为达拉斯-沃斯堡地区的第一个 ISP，而 SDF 保持非商业路线直至 2001 年才注册为非营利组织。（BSDTalk EP21，[284.01-404.93]，L1）
- 进入 BSD 世界靠两位引路人：1993 年在超导超级对撞机项目工作的 Charles Chang 送他一套 386BSD，运行 UUCP 中心与 SLIP 连接的 Eric Schnobel 介绍他接触当时的 BSD 1.1 并说服其在另一台机器上运行，但 SDF 主系统仍坚守 System V 直到 1997 年前后 PC 的性能与可靠性追平 AT&T 3B2；迁移目标选定 NetBSD——Hurd 远未可用、Linux 被他贬为 SVR4 式的符号链接噩梦，既非纯 BSD 亦非纯 System V，与他对极简系统的要求不合；他的论证旁证是替澳大利亚电子乐团 Severed Heads 运营的 sevcom.com 邮件列表、FTP 与网站自 1993 年起一直跑 NetBSD。（BSDTalk EP21，[406.13-547.77]，L1）
- 迁移的最大技术障碍是密码数据库：NetBSD 以 Berkeley DB 管理口令，与 System V 的做法迥异，而公共访问系统每天大量创建删除账户导致频繁重建，一万五千用户规模下重建一次约一分钟，调整 pwd_mkdb 的哈希参数也仅压到三十秒；2000 年他连同架构更换全力转向 NetBSD/Alpha，以把密码文件置入 MFS 内存文件系统的办法把 Berkeley DB 构建速度提高数倍，不久后 NetBSD 官方也优化了 pwd_mkdb，问题就此消解。（BSDTalk EP21，[561.91-750.44]，L1）
- 运维形态随硬件两度演进：早期两三台机器以 NFS 互相依赖被他自嘲为近亲式文件共享，后改为中央文件服务器加准无盘客户端——本地盘只放临时与交换区、系统文件与工具全赖 NFS；如今是一整排 DS-10L 与 DS-20L 刀片，上架接控制台、走本地 NFS 安装，十五分钟即可使一台系统就绪，控制台可远程开关机使他三年多不必亲赴达拉斯；生产运行 NetBSD 2.1——他称其为 Alpha 上首个稳定的 SMP 内核，CS20 测试机已试 3.0 并配两 TB Fibre Channel 阵列；Alpha 平台的存续判断是 OpenVMS 的大客户群使厂商继续供应零件，他甚至期待三年后在路边捡到理论上可扩至 512 处理器的 HP 顶级 Alpha 机器来跑 SDF。（BSDTalk EP21，[811.15-1424.97]，L1）
- SDF 的用户与治理结构：约两万活跃用户以三个月内登录为活跃标准，空间紧张时按此清理账户、终身会员豁免；提供哪些服务由成员投票决定，涵盖 Gopher、web、FTP、SSH、SSH 隧道与端口转发、screen、cron 等，并虚拟托管约两百个域名、在三个网络上做主辅 DNS 冗余；Gopher 拥有狂热的用户群（包括 Floodgap 一系的人），在复古计算展会 Vintage Computer Festival 上常有人认出他是 SDF 的人；其拨号服务据称是唯一允许拨入 shell 而非 PPP 会话的全国性 ISP；会员分免费、ARPA（1994 年设立以支付账单，名称源于当年含 telnet 与 ftp 的 ARPA 工具包）与 MetaARPA 三级，后者享有更多信任、可跑 cron 与独享服务器，而 telnet 登录后以 new 开户的方式十六年未变；文化生态上还有年度音乐合辑（第四年）、源于 Usenet 贴码的 ASCII 游戏复兴、一款在作者沉寂十五年后复活的多人 Rogue 类游戏、以卢卡斯电影 THX 1138 为主题的自有 MUD，以及经请求板接受安装申请的软件机制，PHP 5 与 MySQL 5 的迁移因 Pine 曾数个版本严重缺陷的教训而格外谨慎。（BSDTalk EP21，[886.00-1290.74]，L1）
- CARP（Common Address Redundancy Protocol）最初出现于 OpenBSD 操作系统，其基本构想是主备两机充当同一网络的防火墙并共享一个虚拟地址：主机失效时备机瞬时接管全部流量，主机恢复后备机退回备份角色；对防火墙这类网络关键部件进行升级时，可先在备机上构建新内核，即便升级出错也有主机兜底，从而显著降低维护风险。（BSDTalk EP28，[77.64-123.72]，L1）
- 当事人 Liam Foy 于 2006 年将 CARP 移植到 NetBSD 内核：patch 已发布并收到社区反馈，修复了其中一处错误后运行良好，已获基本认可、等待正式提交进官方树；同期 CARP 已可在 FreeBSD 中使用，他亦在推进向 DragonFly BSD 的移植，并称 CARP 与各主要 BSD 上运行良好。（BSDTalk EP28，[366.66-403.46]，L1）
- 当事人偶然发现其就读大学的整个网络完全构建于 NetBSD 与 OpenBSD 机器之上，承载 NFS、邮件等服务，服务约五千名学生与全部教职员，并为约三千名住宿学生提供网络接入；以此作为 BSD 在生产环境中沉默而广泛部署的一手经验证据。（BSDTalk EP28，[790.7-823.34]，L1）
- BSDPortal 网站的诞生过程显示 2005-2006 年 BSD 在线资源生态的自发协作：当事人大学期间为在一处聚合各 BSD 站点的 RSS 而建站，先托管于运行 OpenBSD 的免费主机，因 PHP 资源限制迁移至 SDF freeshell，再迁至友人服务器；发起购域名请求后一天内收到六人响应，域名由社区成员捐购，RSS 源亦由社区反馈持续扩充。（BSDTalk EP28，[532.72-706.1]，L1）
- 主持人以发布当日新闻切入：NetBSD 3.0 于 2005 年 12 月 23 日发布，较上一版 2.1 带来 Xen 虚拟机监视器集成、以可选项引入 OpenBSD 的 packet filter 防火墙组件及大量驱动更新，成为该期软件管理主题的时代注脚。（BSDTalk EP2，[27.60-62.74]，L2）
- 主持人概括 BSD 软件管理的双轨结构：ports 为源码编译路线，以目录结构与 make 文件自动抓取源码、打补丁适配当前 BSD 版本并递归解决依赖（如 Firefox 对 X Window 的依赖），规模约六千至一万个条目，远多于几百至几千个预编译 packages；packages 走 pkg_add 等 pkg 工具的预编译快速路线。NetBSD 因将 port 一词保留给架构移植而不再称 ports，术语差异折射各项目概念体系的分化。（BSDTalk EP2，[240.18-369.94]，L2）
- 主持人介绍 Gentoo Linux 因偏爱 ports 机制而以 BSD packages and ports 体系作为发行版根基，社区以 GCC screensaver 戏称源码编译路线的漫长等待；他自陈管理多机时倾向点击式更新，但也承认自动更新系统在问题定位上的脆弱，呈现两种工程文化的效用权衡。（BSDTalk EP2，[454.96-518.88]，L1）
- 主持人转述 OpenBSD 包系统的克制路线：依邮件列表信息，开发者致力于添加清晰简单的基础层再逐步扩功能而非堆砌特性；包安装须指定精确版本、安全更新后需手动卸旧装新，OpenBSD 3.8 才开始就地升级尝试。他提出辩证问句——这是落后于曲线还是追求稳固系统——拒绝以单一进步标尺评判功能差异。（BSDTalk EP2，[562.10-641.52]，L1）
- 主持人讲解 base 系统更新三路径：逐个下载补丁重编所需部分、以 CVS 跟踪 stable 分支整体重编（FreeBSD 术语 make world，指重编全部形成内聚整体）、跟踪 current 获取前沿特性但他告诫勿用于生产机；在低速小容量硬件上重编困难催生跨机编译再迁移的社区方案，整体不如 Linux 发行版点击式便捷，他直言这就是 BSD 的运作方式。（BSDTalk EP2，[757.76-960.16]，L2）

**史料**：
