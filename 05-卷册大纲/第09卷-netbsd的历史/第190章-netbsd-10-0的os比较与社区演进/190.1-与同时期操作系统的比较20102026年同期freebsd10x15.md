## 190.1.1 FreeBSD 10.x-15.x 的技术进展对比

**要点**：FreeBSD 10.0（2014.1）切换至 Clang/LLVM 默认编译器、引入 bhyve；11.0（2016.10）改进 Capsicum；12.0（2018.12）引入 OpenZFS 2.0 雏形；13.0（2021.4）引入 Lua 引导、改进 ARM；14.0（2023.11）引入改进的 WiFi 与音频；同期 NetBSD 9.0/10.0 在虚拟化与文件系统方面落后，但在 ARM 与 Apple Silicon 移植领先

**史观**：总纲第 6 条——技术选择的代价：FreeBSD 选择 Clang/LLVM 与 bhyve 付出许可证与生态代价，NetBSD 选择 ARM 与 Apple Silicon 付出性能代价

## 190.1.2 OpenBSD 安全文化的对照

**要点**：OpenBSD 6.x-7.x（2016-2023）继续推进 **pledge(2)** 与 **unveil(2)** 等进程权限控制；OpenBSD relayd 与 httpd 等服务器组件代码审计严格；NetBSD 同期引入 tainted code 政策与 NPF 防火墙，但未引入与 pledge/unveil 类似的进程权限控制

**史料**：OpenBSD 6.x/7.x Release Notes；OpenBSD pledge(2)/unveil(2) 手册页；NetBSD NPF 文档 ［A］

**史观**：总纲第 8 条——社区文化即技术资产：OpenBSD 的“安全即文化”与 NetBSD 的“可移植性即文化”是两种文化资产的不同路径

**辨析**：NetBSD 是否曾考虑引入类似 pledge/unveil 的机制缺乏公开讨论记录——需对照 tech-kern 邮件列表核验；OpenBSD pledge 在第三方应用中的采用率需考据

**文献**：OpenBSD 6.x/7.x Release Notes；OpenBSD pledge(2)/unveil(2) 手册页；NetBSD NPF 文档 ［A］

## 190.1.3 Linux 容器生态的垄断格局

**要点**：Linux 3.x-6.x（2011-2026）凭借 cgroups、namespaces、Docker（2013）、Kubernetes（2014）主导云原生市场；NetBSD 缺乏原生容器能力（无 cgroups 等价物）被边缘化；pkgsrc 在 Docker 中的存在感微弱；FreeBSD 通过 jail 与 bhyve 部分应对，但仍不及 Linux

**史料**：Linux 3.x-6.x changelog；Docker 项目历史；Kubernetes 项目历史；FreeBSD jail 文档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 14 条——商业与社区的张力：Linux 容器生态凭借商业赞助（Docker Inc.、Red Hat OpenShift）主导市场，BSD 整体被边缘化

**辨析**：FreeBSD jail 与 Linux 容器的“等价性”在不同叙事中存在分歧——jail 是 OS 级虚拟化，cgroups+namespaces 是轻量级虚拟化，技术路径不同；NetBSD 是否曾考虑实现 cgroups 等价物缺乏公开记录

## 190.1.4 各项目发布数据与市场份额考据

**要点**：2010-2026 年间市场份额数据——Linux 服务器市场占有率约 70%-80%（云时代主导），FreeBSD 约 1%-2%，NetBSD 不足 0.1%，OpenBSD 不足 0.1%；BSD 整体在云时代被 Linux 进一步挤压
