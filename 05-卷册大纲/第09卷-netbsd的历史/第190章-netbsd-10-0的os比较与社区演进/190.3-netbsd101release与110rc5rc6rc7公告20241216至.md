## 190.3.1 NetBSD 10.1-RELEASE 公告（2024-12-16）

**要点**：NetBSD 10.1 于 **2024 年 12 月 16 日** 正式发布，是 10.x 系列首个点版本（10.0 于 2024-03-28 发布，相隔约 8 个月 20 天）；10.1 作为 10.0 的维护性更新，主要整合 10.0 发布后约 8 个月内的稳定化修复、安全补丁（含 SA2024-001 utmp_update 与 SA2024-002 regreSSHion 修复）与新硬件支持改进；截至 2026-07-23，10.1 是 NetBSD 最新正式 RELEASE，NetBSD Releases 主页（**<https://www.netbsd.org/releases/>**）仍将其列为最新版本；formal.html 历史页面（** <https://www.netbsd.org/releases/formal.html**>）链接到独立形式发行说明页 **<https://www.netbsd.org/releases/formal-10/NetBSD-10.1.html>**；10.1 的发布巩固了 10.x 系列作为当前受支持分支的地位（与 9.x 系列并行维护）

**史料**：NetBSD Releases 主页（**<https://www.netbsd.org/releases/>**，访问日期 2026-07-23，内容为“the latest formal release is NetBSD 10.1”）；NetBSD Formal Releases 历史页面（** <https://www.netbsd.org/releases/formal.html**>，访问日期 2026-07-23，列 0.8 至 10.1 全部 RELEASE 日期）；NetBSD 10.1 形式发行说明页（**<https://www.netbsd.org/releases/formal-10/NetBSD-10.1.html>**，访问日期 2026-07-23）；考据记录 20260723_announcements-netbsd.md § 一 -1.10 §A.1 第 3 条 ［A］

**史观**：发布节奏专题：10.1 作为 10.x 系列点版本，体现“发布后稳定化”的工程节奏——10.0 引入 Apple Silicon M1/M2 等新特性后，10.1 整合修复与改进，是“终结中的延续”在版本治理上的体现；0 信任原则（考据规则）：10.1 发布日期经 NetBSD 官方 formal.html 与 Releases 主页双向印证，避免单一来源风险

**辨析**：经考据记录 20260723_announcements-netbsd.md § 交叉验证方法-一验证：10.1 发布日期 2024-12-16 经 NetBSD Releases 主页与 formal.html 历史页面双向印证，两个页面均为 NetBSD 官方维护但 URL 路径不同（releases/ vs releases/formal.html），内容互相一致，存疑风险低；netbsd.duckdb 的 tags 表不含 NetBSD 仓库 release tag（commits 表含 netbsd-src 773,687 条提交记录），无法通过数据库 tag 交叉验证 10.1 RELEASE 日期，但 commits 表可用于验证 10.x 分支的开发活跃度时间序列；10.1 的具体改进列表（如新硬件支持、安全补丁清单）须对照 10.1 形式发行说明页核验；10.1 与 10.0 的具体差异（如 Apple Silicon 支持是否扩展、Spectre/Meltdown 缓解是否改进）需对照源码核验

2025 年 5 月 23 日，Hans Rosenfeld 在“I/O bus reset to fix CMD MSCP controllers (and probably others)”跟帖中宣布已根因定位：顽疾由 `uba_mainbus.c` r1.11 新增 Qbus/Unibus 内存扫描引入——从 MSCP 控制器引导时引导器会设置 Qbus map，供控制器在内存中安放小型命令/响应环用于 I/O，而内核加载、`uba(4)` 附着期间扫描内存的代码将该映射清除，“sudden loss of access”令 CMD 控制器固件骤然失联；控制器不再按规范在 100 毫秒内响应 IP 寄存器重初始化，`uda(4)` 的 `udamatch()` 等待 10 秒通常仍等不到其苏醒，内核遂因找不到引导设备而启动失败。修复分两层：内核侧在 Qbus 内存检测后恢复 Qbus map 寄存器原值（所需代码早已存在、仅被注释，取消注释即可）作为过渡；正解是引导器独立 `ra.c` 驱动补 `close()` 入口以复位控制器，使内核加载时固件复归复位态、不再被 `uba(4)` 的初始化所惑。他公布内核 workaround 与引导器正解两个补丁，拟下周提交并申请 pullup 入 -10。这是寄存器级行为根因分析的教科书案例：同一缺陷横跨引导器、内核与控制器固件三层，版本迭代中“引导器—内核契约”被无声打破又完整还原。以上为当事人自述，属 L4 级证据，补丁能否如期入 -10 与 CMD 固件的个体差异须以源码树和实机复现互证，不作为修复完备性的定论。
