# 182.3 **与同时期操作系统的比较**：NetBSD 9.0 发布与 ZFS 集成时期（2020）——与 FreeBSD 12/13、OpenBSD 6.6、Linux 5.x（ZFS on Linux）、Windows Server 2019/ReFS 的对照

## 182.3.1 FreeBSD 12/13（ZFS 原生，2020）

**要点**：FreeBSD 在 NetBSD 9.0 同期为 12.1/13-CURRENT（2020），以 ZFS 原生整合、bhyve 与 ARM64 见长（2020 年基树 ZFS 仍为其 illumos 衍生的 CDDL ZFS，2021 年 13.0-RELEASE 起方并入 OpenZFS）；与 NetBSD 9.0 的“ZFS 集成”对照——FreeBSD 的 ZFS 整合更早更深，NetBSD 9.0 在 2020 补上 ZFS 短板（官方口径为“首个 ZFS 可日常使用”的发行版，非首次引入 ZFS），二者 2020 年的树内 ZFS 并非同出 OpenZFS 上游。

**史料**：FreeBSD 12/13 发布说明（2020）；NetBSD 9.0 发布说明（2020.2）［A］

**史观**：总纲第 4 条（分离聚合是永恒规律）——FreeBSD 与 NetBSD 各自将 ZFS 整合进基树（FreeBSD 为其 illumos 衍生自有实现，NetBSD 2018 年起同步自 FreeBSD），家族内部上游共享与独立演进并行。

**辨析**：NetBSD 9.0 的 ZFS 起点晚于 FreeBSD 且非 OpenZFS（2018 年起同步自 FreeBSD 的 CDDL ZFS），整合深度持续追赶；FreeBSD 基树 ZFS 至 2021 年 13.0 方并入 OpenZFS。

**文献**：FreeBSD Project. FreeBSD 12.1-RELEASE Release Notes [EB/OL]. [2026-09-12]. <https://www.freebsd.org/releases/12.1R/relnotes/>；NetBSD Project. NetBSD 9.0 Release Announcement [EB/OL]. [2026-09-12]. <https://www.netbsd.org/releases/formal-9/NetBSD-9.0.html>. ［A］

## 182.3.2 OpenBSD 6.6（2020）

**要点**：OpenBSD 在 NetBSD 9.0 同期为 6.6（2019.10）与 6.7（2020.5），以安全机制（pledge/unveil 成熟）著称，未整合 ZFS（倾向简单文件系统）；与 NetBSD 9.0 的“ZFS 集成”分野——OpenBSD 坚持 softraid 与 FFS 的简洁安全路线，NetBSD 9.0 选择 ZFS 以补存储能力。

**史料**：OpenBSD 6.6（2019.10）/6.7（2020.5）官方发布页 ［A］

**史观**：总纲第 4 条（分离聚合是永恒规律）——OpenBSD 与 NetBSD 同期演进，安全简洁路线与 ZFS 能力目标分化，同源而异途。

**辨析**：OpenBSD 不采用 ZFS 是基于安全审计与简洁考量，非技术劣势。

**文献**：OpenBSD Project. OpenBSD 6.6 Release Notes [EB/OL]. [2026-09-12]. <https://www.openbsd.org/66.html>；OpenBSD Project. OpenBSD 6.7 Release Notes [EB/OL]. [2026-09-12]. <https://www.openbsd.org/67.html>. ［A］

## 182.3.3 Linux 5.x（ZFS on Linux，2020）

**要点**：Linux 5.x（2020）在 NetBSD 9.0 同期以原生文件系统（ext4/btrfs）为主，ZFS 经 ZFS on Linux（OpenZFS 内核模块，非主线）提供；与 NetBSD 9.0 的 ZFS 集成对照——Linux 的 ZFS 以树外模块存在，NetBSD 9.0 与 FreeBSD 将 ZFS 整合进基树（2020 年两者树内均非 OpenZFS 代码：NetBSD 同步自 FreeBSD 的 CDDL ZFS，FreeBSD 为其 illumos 衍生实现），体现 BSD 对 ZFS 的更紧密接纳。

**史料**：Linux 5.x 发布说明（2020，kernel.org 官方发布存档）；OpenZFS/ZoL 官方文档 ［B］

**史观**：总纲第 5 条（没有必然性，只有偶然性）——Linux 树外 ZFS 与 BSD 基树整合的分野并非技术必然，而是 CDDL/GPL 许可冲突与各自治理选择交叠的偶然结果。

**辨析**：Linux 主线拒 ZFS 主因 CDDL/GPL 许可冲突，非技术；BSD 许可允许基树整合。

**文献**：Linux Kernel Project. Linux 5.x Kernel Releases [EB/OL]. [2026-09-12]. <https://www.kernel.org/>；OpenZFS Project. OpenZFS Documentation [EB/OL]. [2026-09-12]. <https://openzfs.github.io/openzfs-docs/>. ［B］

## 182.3.4 Windows Server 2019 / ReFS

**要点**：Microsoft 在 NetBSD 9.0 同期以 Windows Server 2019 与 ReFS（弹性文件系统）提供企业存储，ReFS 为 CoW 但闭源、功能受限；与 NetBSD 9.0 的 ZFS 集成对照——ReFS 与 ZFS 同属现代 CoW 存储但闭源不可审计，NetBSD 9.0 的 ZFS 开源可验证。

**史料**：Microsoft Windows Server 2019/ReFS 官方文档 ［B］（完整著录见本子节文献行）

**史观**：总纲第 4 条（分离聚合是永恒规律）——闭源 CoW（ReFS）与开源 ZFS 在 2020 年构成 CoW 存储路线的两支分化形态。

**辨析**：ReFS 的闭源使故障排查依赖微软，ZFS 的开源使 BSD 可完全审计。

**文献**：Microsoft. Resilient File System (ReFS) Overview [EB/OL]. [2026-09-12]. <https://learn.microsoft.com/en-us/windows-server/storage/refs/refs-overview>.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 182.3.5 同期 ZFS/CoW 文件系统总览（2020）

  **2020 年同期 ZFS/CoW 文件系统对照表**：

  | 操作系统 | 主版本（2020） | ZFS/CoW 集成方式 | 整合深度 | 许可证 | 备注 |
  | -------- | -------------- | ---------------- | -------- | ------ | ---- |
  | NetBSD | 9.0（**2020.2.14**） | 树内 CDDL ZFS（2018-05-28 起同步自 FreeBSD svn r315983） | 基树整合，实验性 | CDDL（与 NetBSD 内核聚合） | chs 2018-05-28 自 FreeBSD 大批量同步导入（上游厂商自 OpenSolaris 改记 FreeBSD），非 OpenZFS |
  | FreeBSD | 12.1/13-CURRENT | CDDL ZFS 基树整合（illumos 衍生自有实现） | 基树整合，成熟稳定 | CDDL（基树整合） | 7.0（2008.2）起即引入 ZFS，领先 12 年；2021 年 13.0 起方并入 OpenZFS |
  | OpenBSD | 6.6（2019.10）/6.7（2020.5） | 无 ZFS（FFS 与 softraid） | 拒绝 ZFS | BSD-licensed FFS | 安全审计与简洁考量 |
  | Linux | 5.x | ZFS on Linux（ZoL）树外模块 | 树外模块，非主线 | CDDL/GPL 冲突 | 主线拒 ZFS 因许可证冲突 |
  | Windows Server | 2019 | ReFS（弹性文件系统） | 闭源 CoW，功能受限 | 闭源 | ReFS 不可审计 |
  | illumos/Solaris | 持续维护 | ZFS 原创 | 原生 ZFS | CDDL | ZFS 发源地 |

**要点**：2020 年 CoW 文件系统格局：FreeBSD 12/13 与 NetBSD 9.0 均将 ZFS 整合进基树（2020 年两者树内均非 OpenZFS 代码：FreeBSD 为其 illumos 衍生的 CDDL ZFS、2021 年 13.0 起方并入 OpenZFS，NetBSD 同步自 FreeBSD 的 CDDL ZFS），Linux 经 ZoL 树外提供，illumos/Solaris 持 ZFS 原创，OpenBSD 坚持 FFS/softraid，Windows 用 ReFS；NetBSD 9.0 的 ZFS 补齐使其存储能力与 FreeBSD 对齐。

**史料**：本节对照表各系统官方发布页与文档（NetBSD 9.0 发布页、FreeBSD 12.1 Release Notes、OpenBSD 6.6/6.7 发布页、Linux kernel 官方发布存档、Microsoft ReFS 文档、OpenZFS 官方文档，详见下方文献行） ［B］

**史观**：总纲第 4 条（分离聚合是永恒规律）——2020 年 NetBSD 与 FreeBSD 的树内 ZFS 各有所本（NetBSD 自 2018 年起同步自 FreeBSD 的 CDDL ZFS，FreeBSD 为其 illumos 衍生自有实现、2021 年 13.0 起方并入 OpenZFS），家族存储路线呈分合循环而非单一上游收敛。

**辨析**：ZFS 在 NetBSD 的基树整合未因 CDDL 与 BSD 式内核许可证的聚合而阻断，属具体工程与治理选择的结果，不能据此证明 BSD 许可对大型存储栈有一般性友好；CDDL 与 GPL 的聚合冲突（Linux 主线拒 ZFS 的主因）在 BSD 侧同样存在，只是本项目的治理选择未使其构成阻断。

**文献**：OpenZFS Project. OpenZFS Documentation [EB/OL]. [2026-09-12]. <https://openzfs.github.io/openzfs-docs/>；NetBSD Project. NetBSD 9.0 Release Announcement [EB/OL]. [2026-09-12]. <https://www.netbsd.org/releases/formal-9/NetBSD-9.0.html>. ［B］
