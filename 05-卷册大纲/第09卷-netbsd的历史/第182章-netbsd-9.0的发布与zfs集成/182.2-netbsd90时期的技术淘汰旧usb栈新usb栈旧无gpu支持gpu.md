# 182.2 NetBSD 9.0 时期的技术淘汰——旧 USB 栈 → 新 USB 栈、旧无 GPU 支持 →GPU 支持、旧文件系统 →F2FS/ext2fs 改进（2018-2020）

## 182.2.1 旧 USB 栈 → 新 USB 栈引入（2020）

**要点**：NetBSD 9.0（2020.2.14）改进 USB 栈，引入 USB 3.x 支持与性能优化；旧 USB 栈存在对 USB 3.x xHCI 控制器支持不完整问题，9.0 重写部分 xHCI 驱动；改进让 NetBSD 在现代笔记本（如 Intel Tiger Lake）上获得 USB 外设连接能力；旧 USB 2.0 栈作为兼容路径保留，体现“终结中的延续”

**史料**：NetBSD 9.0 Release Notes USB 部分；tech-kern 邮件列表；CVS commit log 中 usb/xhci 相关 commit ［A］

**史观**：总纲第 19 条——信息技术：USB 栈作为信息技术外设接口，其演进体现“终结中的延续”——旧栈退役但 USB 框架延续；总纲第 25 条——终结中的延续：旧 USB 2.0 路径保留是终结中的延续

**辨析**：9.0 USB 3.x 支持的具体硬件兼容性需对照硬件兼容性列表核验；与 FreeBSD USB 栈的对比需考据；xHCI 驱动重写的具体范围需对照源码核验

**文献**：NetBSD 9.0 Release Notes；tech-kern 邮件列表；USB 3.x 规范 ［A］

## 182.2.2 旧无 GPU 支持 → GPU 支持引入（2020）

**要点**：NetBSD 9.0（2020.2.14）引入改进的 GPU 支持，特别是 Intel i915 DRM（Direct Rendering Manager）与 AMDGPU 的初步支持；GPU 支持由 Taylor R Campbell 等推动；9.0 的 GPU 支持仍落后 Linux 数年，但相比 8.0 有显著进步；旧 NetBSD 几乎无现代 GPU 支持，依赖简单 framebuffer，9.0 引入 DRM 框架是技术路径的重大转变

**史料**：NetBSD 9.0 Release Notes GPU 部分；tech-kern 邮件列表讨论；CVS commit log 中 drm 相关 commit ［A］

**史观**：总纲第 14 条——商业与社区的张力：Linux GPU 支持凭借厂商早期文档领先，NetBSD 依赖逆向工程与移植滞后；总纲第 22 条——BSD 反向影响线：NetBSD 移植 Linux DRM 代码体现 BSD 与 Linux 的双向影响

**辨析**：NetBSD 9.0 GPU 支持的具体硬件列表（哪些 Intel/AMD GPU 可用）需对照硬件兼容性列表核验；NVIDIA GPU 在 NetBSD 上的支持几乎为零，需考据；DRM 代码从 Linux 移植的具体版本与许可证兼容性需考据

**文献**：NetBSD 9.0 GPU 文档；Intel i915 DRM 文档；tech-kern 邮件列表 ［A］
