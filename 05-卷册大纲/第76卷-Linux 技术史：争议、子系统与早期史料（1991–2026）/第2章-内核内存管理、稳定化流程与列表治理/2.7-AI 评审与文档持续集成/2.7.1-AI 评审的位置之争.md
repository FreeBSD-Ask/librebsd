# 2.7.1 AI 评审的位置之争

<!-- ROW_MINE: lkml.messages.2078900 -->`
- 【Linux社区】2006 年 7 月 Evgeniy Polyakov 在 lkml 发出 [RFC 0/4] kevent 通用内核事件处理子系统公告，明确“incorporates several AIO/kqueue design notes and ideas”并将 user 数据结构直接定位为“It is similar to FreeBSD's kqueue”；设计覆盖 socket 通知、网络 AIO（aio_send/aio_recv/aio_sendfile）、inode 通知、通用 poll/select 通知与定时器通知，测试对比显示“It was tested against FreeBSD kqueue and Linux epoll and showed very noticeable performance win”；这是继 2002 年 sysevq 之后 Linux 侧借鉴 FreeBSD kqueue 设计的最系统的一次事件通知子系统尝试，与同年的 Polyakov kevent API 评审构成完整 RFC 链。 

<!-- ROW_MINE: lkml.messages.7084295 -->`
- 【Linux社区】2001年9月FreeBSD核心团队成员Warner Losh（imp@harmony.village.org）就Slashdot“BSD-Linux FlameWar over SoftRAID”报道公开发言，以1992年ObjectBuilder for Linux老资历背书，直面Soren Schmidt SoftRAID代码被Linux直接拷贝：“The fact of the matter is that the code was copied from FreeBSD verbatim, or with minor alterations. That's not a problem at all, since our license allows for that. The problem came in that Soren's name was removed from the headers”，区分attribution与license问题，声明“FreeBSD's core team has never issued any statements on this issue”，主张“Healthy code and concept sharing between Linux and FreeBSD... is in everyone's best interest”；BSD核心团队对Linux采用BSD代码的治理立场声明，与2007 ath5k/GPL-BSD冲突（205.x）形成前后里程碑。 `
