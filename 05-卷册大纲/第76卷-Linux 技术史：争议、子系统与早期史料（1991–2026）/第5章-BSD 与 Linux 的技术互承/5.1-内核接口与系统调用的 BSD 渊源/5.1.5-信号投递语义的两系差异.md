# 5.1.5 信号投递语义的两系差异

- 【Linux社区】2006 年 1 月 Suleiman Souhlal（FreeBSD 组织）在 LKML“soft update vs journaling?”线程中反驳 Diego Calleja 断言 FreeBSD“getting rid of softupdates”的说法，公开回应“You read the message wrong: We're not getting rid of softupdates”，为 BSD softupdate 策略在 Linux 社区留下明确立场——FreeBSD 在 UFS 上引入 journaling 的同时仍保留 softupdate 机制，展示 BSD 文件系统策略演进的公开锚点 `

<!-- ROW_MINE: lkml.messages.2138036 -->`
- 【Linux社区】Ted Ts'o (tytso@mit.edu) 就 suspend block api 补丁线程回帖，回忆早年指出主线 PCMCIA 代码弹出时 10% 概率崩溃，NetBSD 自豪宣称代码 iron-clad 任何时候弹出都正确处理，但 NetBSD PCMCIA 比 Linux 晚 3 年可用，Ts'o 感慨“我们曾是技术务实派，Linus 至今仍是务实派，而其他人则是极端完美主义”，并称“近来 NetBSD 态度已开始感染 LKML 而这是不幸的”，以 Linus 曾以“merge or kill”决定结束过长讨论作结。BSD/Linux 文化态度冲突的直接表达。

- 【Linux社区】2001 年 10 月 Matthias Andree 在 Rik van Riel“2.4.10 vs. 2.4.10-ac2 与 qsort”线程中，就 Rik 建议改试 merge sort 时直接给出“Just rip it off NetBSD and there you go”，并对比 FreeBSD 与 NetBSD 的 merge.c 实现差异——“FreeBSD's breaks on machines like SPARC, NetBSD's does not”，附 de.freebsd.org 上的 NetBSD libc/stdlib/merge.c rev1.10 源码链接。这是 BSD libc merge sort 被 LKML 明确点名引入 Linux 内核 VM 讨论的早期证据。 

<!-- ROW_MINE: lkml.messages.2083020 -->`
- 【Linux社区】2017 年 Michal Hocko 就 MADV_WIPEONFORK 补丁 v2 讨论回复，针对 Rik van Riel 明确将新语义类比 OpenBSD minherit syscall with MAP_INHERIT_ZERO 并注明 man.openbsd.org/minherit.2 链接，Hocko 质疑 madvise 语义“an advise and as such it can be ignored/not implemented and that shouldn't have any correctness effects”主张用 MAP_$FOO 标志而非 madvise；正文 BSD 词命中 2 处，是 Linux 内存管理新 API 由 OpenBSD minherit 直接触发的完整讨论链
