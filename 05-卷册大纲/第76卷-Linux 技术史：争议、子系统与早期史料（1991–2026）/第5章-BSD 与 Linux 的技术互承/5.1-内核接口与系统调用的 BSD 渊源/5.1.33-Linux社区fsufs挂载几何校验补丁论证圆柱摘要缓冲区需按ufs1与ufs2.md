# 5.1.33 Linux社区fsufs挂载几何校验补丁论证圆柱摘要缓冲区需按ufs1与ufs2

- 【Linux社区】fs/ufs 挂载几何校验补丁论证圆柱摘要缓冲区需按 ufs1 与 ufs2 共同的 32 位字段结构推算，并校验 newfs 写入的 fragroundup 尺寸，涉及 BSD UFS 格式细节。英文引语：“four 32 bit fields for both ufs1 and ufs2”`<!-- ROW_MINE: linux-fsdevel.messages.706012 -->`

- 【Linux社区】FreeBSD fusefs 贡献者提出扩展 FUSE 协议以携带 chflags 文件标志与 st_birthtime，因协议缺失导致 FreeBSD fusefs 无法暴露或保留这些属性，属 BSD 反向影响 Linux 协议演进。英文引语：“FreeBSD supports file flags modification with chflags(2)”`<!-- ROW_MINE: linux-fsdevel.messages.706123 -->`
- 【Linux社区】讨论 fs/ufs 现状时 Luis Henriques 直言不清楚如今谁还在用该驱动，理由是每个 BSD 各有自己的实现且以读写模式挂载很可能有风险；Ali Ahmet Memis 回应称风险确实不小，并列举 fs/ufs 误处理合法文件系统的多处缺陷，本条触及 BSD UFS 生态分化与 Linux 驱动存废。原文：“each BSD has it's own thing”`<!-- ROW_MINE: linux-fsdevel.messages.706713 -->`
- 【Linux社区】fuse iomap 补丁串中 Darrick J. Wong 解释 fuse4fs 为 lowlevel 服务器、fuse2fs 为高层服务器，并说明 fuse4fs 是 fuse2fs 的继任者（至少在 Linux 与 BSD 上如此）；Joanne Koong 据此决定只读 fuse4fs，本条牵出跨平台用户态文件系统栈的对照。原文：“fuse4fs is the successor to fuse2fs, at least on Linux and BSD.”`<!-- ROW_MINE: linux-fsdevel.messages.706737 -->`
- 【Linux社区】O_CREAT 与 O_DIRECTORY 组合的讨论再次引用 BSD 家族差异：被引的 Pedro Falcato 以 POSIX 未定义该组合语义为前提，列出 FreeBSD 与 NetBSD 各自不同的语义并自问谁还在意 BSD，随后回顾 Linux 从返回目录或创建普通文件、到恒返回 ENOTDIR、再到 2023 年改为 EINVAL 的三段行为漂移。原文：“cannot rely on _any_ common behavior between platforms”`<!-- ROW_MINE: linux-fsdevel.messages.706763 -->`
- 【Linux社区】fs/ufs 挂载路径加固补丁串提出两个健壮性修复，均可由挂载构造的 UFS 镜像触发：一是把根 dentry 的创建移到柱面组元数据加载之后，避免失败拆除时的空指针，二是在缓存前校验柱面组索引与转子位置，挡住越界写入与位图偏移回绕；两者已在未打补丁内核上以 KASAN 复现。原文：“reachable by mounting a crafted UFS image”`<!-- ROW_MINE: linux-fsdevel.messages.707172 -->`
