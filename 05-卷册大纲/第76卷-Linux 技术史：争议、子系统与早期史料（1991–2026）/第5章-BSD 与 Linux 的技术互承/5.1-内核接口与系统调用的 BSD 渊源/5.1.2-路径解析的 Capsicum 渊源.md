# 5.1.2 路径解析的 Capsicum 渊源

<!-- ROW_MINE: lkml.messages.5429709 -->`
- 【Linux社区】2019年11月Aleksa Sarai提交openat2系列中LOOKUP_BENEATH补丁（v15 4/9），直接在补丁背景章节声明“FreeBSD spun out O_BENEATH from their Capsicum project, so it also seems reasonable to implement similar functionality for Linux”，将Linux openat2的scoped resolution追溯到FreeBSD的Capsicum能力安全框架D2808/D17547评审；实现细节上他刷新了Al Viro的AT_NO_JUMPS补丁集（本身派生自David Drysdale的O_BENEATH补丁，后者又基于Capsicum项目），Jann Horn提出的安全顾虑触发对“..”路径组件的阻断，magic-link跳跃亦因可跨越查找起始点而被阻断。 

<!-- ROW_MINE: lkml.messages.2085122 -->`
- 【Linux社区】Brent Cook (bcook@openbsd.org) 就 [RFC] 用 getrandom() 包装 getentropy 给 LibreSSL 的补丁回帖，OpenBSD 工程师建议通过 syscall(SYS__getrandom) 谨慎处理 Linux getrandom(2) 接口的额外返回码，避免未读够字节（EINTR 未处理）导致 CSPRNG 未播种；补丁 diff 直接引用 OpenBSD CVS 中 Theo de Raadt 2014 年与 kettenis 后续修改的 getentropy_linux.c 版权行与 SYS__getrandom=317/354 定义。BSD 密码学 API 反向进入 Linux 直接证据。 `

<!-- ROW_MINE: lkml.messages.1914560 -->`
- 【Linux社区】2004年8月 Helge Hafting(helge.hafting@hist.no) 在“Re: PATCH: cdrecord: avoiding scsi device numbering for ide devices”串中 回应 Joerg Schilling 关于 libscg 跨平台稳定性，指认 FreeBSD 与 OpenBSD 皆运行于 libscg 的 CAM 抽象之上，“the vast majority does not allow the adressing method the people on LKML seem to prefer recently”，是 BSD 血统 libscg SCSI 抽象层以 FreeBSD CAM 承载其跨 OS 成熟度、与 Linux 内核 /dev 偏好形成张力的一例 `

<!-- ROW_MINE: ob-213086 -->`
- 【Linux社区】2015年12月 Ingo Feinerer (feinerer@logic.at) 在“Update V4L2 API (sys/videoio.h)”串中 提交同步 Linux 视频 API 至 OpenBSD 的补丁并明示跳过 GPL2 头文件，是 BSD 项目处理 Linux 头文件时的 GPL 过滤惯例 ``which was reverted because of GPL2 considerations` `

<!-- ROW_MINE: sparclinux.messages.9320228 -->`
- 【Linux社区】Aleksa Sarai 提交 openat2 系统调用的 v17 版补丁系列，随附新增的手册页一并送审。手册页 CONFORMING TO 小节明确写出两点：该系统调用是 Linux 特有实现；RESOLVE_BENEATH 标志的语义参照 FreeBSD 的 O_BENEATH 实现。补丁说明同时交代引入动机，即主要需求来自容器运行时，其打开不可信容器内路径时须在用户态做符号链接限定，并列举 CVE-2017-1002101、CVE-2018-15664 等一批本可由该机制缓解的路径逃逸缺陷。该系列历经十余轮返工，v17 还补入 path_is_under 检查作为完整路径遍历的最后一道防线，以防止路径解析缺陷破坏该调用的语义契约。这条记录把 Linux 新增路径解析限制标志的设计来源直接锚定到 FreeBSD 的既有同名机制，是追踪 Linux 路径遍历接口谱系的一条明确线索。
