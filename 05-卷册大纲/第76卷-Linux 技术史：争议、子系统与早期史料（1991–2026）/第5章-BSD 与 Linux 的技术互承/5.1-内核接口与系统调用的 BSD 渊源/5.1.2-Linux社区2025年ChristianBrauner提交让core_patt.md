- 【Linux社区】2025 年 Christian Brauner 提交让 core_pattern 走 AF_UNIX 套接字的 coredump socket 补丁集，为解决 core_pattern 处理器需要特殊套接字 cookie 的问题，方案是改造 BSD 风格路径名套接字的查找函数，使其能在初始挂载命名空间与相应凭据下定位该套接字。BSD 风格的 Unix 路径名地址在 Linux 中至今仍是实现该能力的落点，属 BSD 地址族语义谱系。原文: 'Simply massage unix_find_bsd() to be able to handle this'。 `<!-- ROW_MINE: linux-fsdevel.messages.643892 -->`
- 【Linux社区】2013 年围绕 revoke(2) 与 remove_proc_entry 泛化处理的 RFC 讨论中，Greg KH 提议让 revoke(2) 要求传入有效文件句柄，并追问是否有必须遵循的 POSIX 规范；Al Viro 以 BSD 实现作为既定事实回应，称 BSD 的 revoke 采用路径名且所有衍生实现皆然。Greg KH 随后承认 BSD 先行只能接受，转而追问 BSD 如何解决该类型竞态条件，并怀疑其因使用稀少而未加防护。这段往复记录了 revoke 接口在 Linux 设计时以 BSD 语义为基准的情形。原文：“BSD one takes a pathname and so do all derived ones”。`<!-- ROW_MINE: linux-fsdevel.messages.643896 -->`
- 【Linux社区】2008 年 Szabolcs Szakacsits 宣布一套主要检查 POSIX 合规性的文件系统测试集，明确说明其同时适用于 FreeBSD、Solaris 与 Linux，覆盖 UFS、ZFS、ext3 与 NTFS-3G 等文件系统，共含约一千九百五十个回归测试。Joel Becker 随后以该套件验证 ocfs2 在 ext3 兼容模式下的表现，是 FreeBSD 与 Linux 共享同一 POSIX 测试基线的记录。原文：“works for FreeBSD, Solaris, and Linux with UFS, ZFS, ext3, and NTFS-3G file systems”。`<!-- ROW_MINE: linux-fsdevel.messages.644143 -->`
- 【Linux社区】2006 年讨论 NFSv4 与 pNFS 的 POSIX I/O 标准时，Latchesar Ionkov 提议让文件系统在一次 lookup 中解析多个路径分量以提升远端文件系统深层遍历效率，Christoph Hellwig 将该提议对号入座为 4.4BSD 的 namei 接口风格，即 VOP_LOOKUP 拿到剩余整条路径并自行解析尽可能多的分量，并指出该做法会给 lookup 状态管理带来混乱。原文: 'the 4.4BSD namei interface where the VOP_LOOKUP routine get the entire remaining path'。 `<!-- ROW_MINE: linux-fsdevel.messages.644435 -->`
- 【Linux社区】2021 年 Al Viro 就 unix_bind() 在失败时回滚 mknod 的重构补丁集列出提交清单，其中显式拆分 BSD 与 abstract 两种地址情形，新增两条地址各自的辅助函数，并把原 unix_mknod() 折叠进 unix_bind_bsd()，再将该函数内的 done_path_create() 调用后移到处理 bindlock 之后。这是 Linux AF_UNIX 在实现层面区分 BSD 路径名地址与 Linux 扩展抽象地址的谱系证据。原文: 'fold unix_mknod() into unix_bind_bsd()'。 `<!-- ROW_MINE: linux-fsdevel.messages.644751 -->`
- 【Linux社区】2019 年评审 pidfd 增加轮询支持补丁时，Christian Brauner 讨论返回值选择，指出 FreeBSD 在进程退出时返回 POLLHUP 而非 POLLIN，认为该做法同样合理，建议 Linux 返回 POLLIN 与 POLLHUP 的组合，理由是内核在 tty 代理场景已有类似做法。这是 pidfd 事件语义与 FreeBSD 实现直接对照并据此调整 Linux 接口的一手记录。原文: 'FreeBSD is using POLLHUP on process exit which I think is nice as well'。 `<!-- ROW_MINE: linux-fsdevel.messages.644867 -->`
