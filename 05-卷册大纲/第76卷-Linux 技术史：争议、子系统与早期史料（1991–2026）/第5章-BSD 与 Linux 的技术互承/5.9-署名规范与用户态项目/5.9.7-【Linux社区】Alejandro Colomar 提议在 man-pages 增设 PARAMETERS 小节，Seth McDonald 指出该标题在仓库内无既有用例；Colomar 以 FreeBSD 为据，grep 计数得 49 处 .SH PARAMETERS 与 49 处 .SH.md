- 【Linux社区】Alejandro Colomar 提议在 man-pages 增设 PARAMETERS 小节，Seth McDonald 指出该标题在仓库内无既有用例；Colomar 以 FreeBSD 为据，grep 计数得 49 处 .SH PARAMETERS 与 49 处 .SH ARGUMENTS，认为 parameters 技术上更准确，故引入该惯例。 <!-- ROW_MINE: linux-man.messages.753697 -->`
- 【Linux社区】Ingo Schwarze 表示“I would no doubt like to see mdoc(7) used more in Linux contexts”，赞 Cynthia 在简洁、助记与语义标记间取得平衡；Michael Kerrisk 解释 man-pages 未采纳：继承代码库逾 95% 为 man 格式，混入的 mdoc 页面在早期全局自动排版编辑时造成额外摩擦。 <!-- ROW_MINE: linux-man.messages.753871 -->`
- 【Linux社区】Petr Baudis 提交 getifaddrs(3)/freeifaddrs(3) 页，说明“based on the original BSD manpage (with licence as it appears on the top of the file)”但已按 Linux man-pages 标准大幅重写，并称“open to relicensing”且与 classic BSD licence 兼容；Michael Kerrisk 认为“little, if any, of the BSD page remains”，建议改换 verbatim 许可。 <!-- ROW_MINE: linux-man.messages.754166 -->`
- 【Linux社区】Andi Kleen 反对在 Linux 手册 standards.7 中引用 W. Richard Stevens 旧版著作：“He describes original BSD sockets, which at times is quite different from Linux or POSIX sockets”，故不宜将其列为 Linux 读者的权威参考。 <!-- ROW_MINE: linux-man.messages.754181 -->`
- 【Linux社区】Brian F. G. Bidulock 为 netdevice.7 补充缺失的 SIOC 系列 ioctl，说明 SIOCSIFPFLAGS/SIOCGIFPFLAGS 为 Linux 独有，其余“are standard BSD ioctls that have always been implemented by Linux”，并以 Linux 2.6.25 头文件与 netdevice.c 源码核验取值；Michael Kerrisk 接受并于 3.40 合入。 <!-- ROW_MINE: linux-man.messages.754437 -->`
- 【Linux社区】G. Branden Robinson 依 McKusick“20 Years of Berkeley Unix”修订 BSD/AT&T/POSIX 谱系图：指出 Unix 32/V（移植至 DEC VAX）是“the common ancestor of all AT&T and BSD Unices”，2BSD 仅支持 PDP-11 且 2.11BSD 至 2025 年仍在演进，并纠正 Colomar 图中“4.3BSD Lite”实为 4.4BSD-Lite、其后 CSRG 解散。 <!-- ROW_MINE: linux-man.messages.754512 -->`
- 【Linux社区】Alejandro Colomar 解释 ioctl(2) 系列手册页新增的 LIBRARY 小节（如 stat(2) 的“Standard C library (libc, -lc)”），回应 Theodore Ts'o 关于既有条目为何无此说明，明言该惯例“based on FreeBSD's man pages”，并指 man-pages 仓库近一年无发布故 git 中已普遍落地。 <!-- ROW_MINE: linux-man.messages.754581 -->`
- 【Linux社区】G. Branden Robinson 自纠 2.11BSD 与 4BSD 年代关系：UNIX 32/V 移植至 32 位 VAX-11 却“did not implement demand paging”，继续整进程换页；3BSD 才实现 demand paging，4BSD 引入 curses 库并经 ncurses 重实现沿用至今。 <!-- ROW_MINE: linux-man.messages.754633 -->`
- 【Linux社区】Colin Watson 报告 gethostid/sethostid 虽由 glibc 而非内核实现却仍置于 section 2；Michael Kerrisk 认为属历史遗留，“in the original BSD docs, these interfaces were documented in Section 2, although I see FreeBSD for example now has them in Section 3”，遂迁至 section 3 并保留 .so 链接使 man 2 继续可用。 <!-- ROW_MINE: linux-man.messages.754642 -->`
- 【Linux社区】Ingo Schwarze 建议 Linux man-pages 停止分发已过时的 mdoc.samples(7)（Cynthia Livingston 早期版本），改为纳入 groff_mdoc(7)（含 Werner Lemberg 等人的改进）或 mandoc 的 mdoc(7)，并指出“Both are BSD-style licensed, so there should be no licensing issues”；他提醒若 man-pages 与 groff 同时分发 groff_mdoc(7) 可能引发发行版打包冲突。 <!-- ROW_MINE: linux-man.messages.754705 -->`
- 【Linux社区】新增 LIBRARY 章节的 45 补丁集明确声明“It is based on (mostly cloned from) FreeBSD's man pages, as I liked that section from them”，用于将此前散落在 NOTES/SYNOPSIS/DESCRIPTION 注释中或缺失的库信息规范化。 <!-- ROW_MINE: linux-man.messages.754715 -->`
- 【Linux社区】在 WG14 讨论中主张恢复 realloc(p,0) 的传统 BSD 语义，称 C17 以无实际影响名义的改动破坏了 realloc(p,0) 的标准定义，“the only way forward is to go back to the traditional BSD specification”；并论证 NULL 与零元素数组不可等同，因对零元素数组持有指向首元素的指针合法而 NULL 是无效指针。 <!-- ROW_MINE: linux-man.messages.755082 -->`
- 【Linux社区】向 WG14 提交 alx-0097r1 提案，建议让 mem*() 函数回到 <memory.h> 中声明，以纠正 C89 将它们塞入 <string.h> 的错误。他追溯 mem*() 1983 年在 System V 引入并声明于独立的 <memory.h>，1986 年 4.3BSD 为兼容 System V 也在 <memory.h> 中采纳，{Free,Net,Open}BSD、glibc、musl 至今保留该头文件；他称 C89 的改动是“a huge mistake”，提案抄送了 Keith Bostic 等人。 <!-- ROW_MINE: linux-man.messages.755130 -->`
- 【Linux社区】Ingo Schwarze 回忆曾试图说服 FHS 维护者把各 BSD 惯例纳入标准，但 FHS 社区“very firmly entrenched as ‘Linux only’”，拒绝将 /usr/ 用于基本系统、/usr/local/ 用于软件包等数十年 BSD 惯例，转而推广他视为“firmly a Linux-only invention”的 /opt/；Schwarze 因此退出并称其他 OpenBSD 开发者嘲笑他“Why do you even care about that Linux-only crap?”。Colomar 致谢，并引用 Branden 的说法称 /opt/ 并非 Linux 专属。 <!-- ROW_MINE: linux-man.messages.755394 -->`
- 【Linux社区】Linux realpath(3) 手册页作者说明页中关于 Solaris 的注记源自 4.4BSD-Lite 的 realpath.3（1994-02-16）；Casper Dik 回应称，他注意到该注记同时存在于 BSD 与 Linux 手册页，原以为二者之一抄自对方，遂按所能找到的第一个地址联系这位 1999 年撰写该页的作者请求移除。 <!-- ROW_MINE: linux-man.messages.755566 -->`
- 【Linux社区】Kerrisk 对 Baudis 提交的 getifaddrs.3（基于 1995 年 Berkeley Software Design 手册页）做了大幅编辑并重写示例程序，认为“little, if any, of the BSD page remains”，建议将原有的 BSD 许可切换为 verbatim 许可；修订页保留 BSD（1995, 1999）版权声明，Baudis 称自己未实际在 BSD 系统上测试，仅凭其“chaotic documentation”推断行为与 glibc 一致。 <!-- ROW_MINE: linux-man.messages.756018 -->`

- 【Linux社区】Langstraat 总结推动 htobe64()/betoh64() 宏跨 OpenBSD、Linux、FreeBSD 统一的失败：OpenBSD 不愿放弃 <sys/endian.h> 改用 glibc 的 <endian.h>（因 glibc 对内核 API 与用户态 C 库的区分比各 BSD 更严）；glibc 的 Ulrich Drepper 采用自命名 be64toh 而非原始 OpenBSD 命名 betoh64；FreeBSD 几乎无兴趣。他自评“I clearly didn't hit the right notes to interest anybody in adopting a standard”。 <!-- ROW_MINE: linux-man.messages.757007 -->`
