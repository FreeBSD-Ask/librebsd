- 【Linux社区】Chris Newport 就内核崩溃转储设计建议在 SPARC 上借鉴 Solaris 的做法，主张把该崩溃转储机制引入 Linux。Linus Torvalds 明确拒绝，称 Solaris 很差，其决策建立在控制硬件的模式上，多数崩溃会让系统处于脆弱状态，此时写盘是最不该做的事，Linux 做对了事即尽量让 bug 不致命。Newport 澄清这并非 Solaris 的特性而是 OpenBoot PROM 的特性，多个厂商都在使用；OpenBoot PROM 知道如何写盘，在崩溃函数中只需设置几个寄存器并发起 prom 中断，内核此时已不参与。他还提到 SunOS 的 debug 程序可用 debug 加转储文件参数调用并直接定位故障点，如同跟踪文件。这封邮件记录了 Solaris 与 OpenBoot 的崩溃转储机制被提议引入 Linux、又被维护者以可靠性理由否决的完整论据。 <!-- ROW_MINE: sparclinux.messages.9333583 -->`

- 【Linux社区】David Miller 回应关于改进 Sparc-Linux 移除 Cypress 处理器支持时提示信息措辞的建议。列表成员建议把报错信息改成邀请 Cypress 用户联系 sparclinux 邮件列表的写法，Calaby 认为这一写法更好，但 Miller 明确表示完全没有把 Cypress 支持重新放回内核树的打算。他给出的理由是使用者可以直接转去使用 BSD 家族的内核，或者改用基于更早内核版本的发行版。这段话记录了 sparc32 低端 Cypress 分支在 Linux 与 BSD 之间的分流：Linux 主动放弃老旧 SPARC 硬件支持，把这部分用户导向 BSD 发行版，两个项目在硬件生命周期末端的支持策略因此出现分工。Miller 作为 sparc 架构维护者做出的这一决定，同时确立了 Linux 不再以兼容最老一代 SPARC 处理器为目标的工作立场。 <!-- ROW_MINE: sparclinux.messages.9334489 -->`
- 【Linux社区】David Laight 在 kernel_clone 引入与 _do_fork 废弃的补丁系列讨论中，提出 Linux 是否拥有常数时间的 pid 分配器，质疑其是否必须做线性扫描来寻找空档。他以自己在 NetBSD 中的实现作答：把 pid 分配器与查找改为按 pid 与掩码取索引访问 pid_array，再检查高若干位是否匹配，分配时递增；并通过未使用表项串成先进先出空闲链。他认为这套方案很容易推广。这段发言记录了他把 NetBSD 上的 pid 分配器设计经验带入 Linux 内核进程标识分配讨论的过程，属于 BSD 工程实践向 Linux 流动的技术转移，也反映了 BSD 系内核开发者参与 Linux 架构评审时的经验注入方式。 `<!-- ROW_MINE: sparclinux.messages.9334621 -->`
- 【Linux社区】Andi Kleen 回答关于能否依赖各 Linux 版本 errno 编号一致的问题，明确回答不能。他解释 errno 最初的设计目的是与该平台上的原生 Unix 保持兼容，以便更容易运行其二进制程序，而在 SPARC 平台上该原生系统就是 SunOS 与 Solaris。因此 Linux 在 SPARC 上的错误码编号遵循 BSD 派生 Unix 的约定而非跨平台统一，这是历史兼容约束造成的后果。这条回答是 Linux 为支持 BSD 派生二进制兼容性而做出错误码设计决策的直接证词，说明 errno 语义差异并非疏漏而是刻意为二进制移植所做的安排，对理解 BSD 与 Solaris 在 SPARC 上对 Linux 的技术塑造有史料价值。 `<!-- ROW_MINE: sparclinux.messages.9336163 -->`
- 【Linux社区】James Bottomley 与 Alan Cox 就 BSD 许可模块能否与 GPL 内核结合分发展开技术法律讨论。Cox 主张以 BSD 许可编译模块并只交付二进制而拒绝给出源码，在字面上即符合 BSD 许可证要求。Bottomley 反驳称 BSD 与 GPL 兼容，但若假定二进制模块构成 Linux 的演绎作品，分发该二进制组合即落入 GPLv2 的演绎作品条款，即使模块仅有 BSD 许可也必须提供对应源码。他进一步指出唯一已知的规避途径是让使用者自行编译该二进制。他还区分双重 BSD/GPL 许可与 GPL 附加权利两种模式，认为双重许可下适用许可取决于允许该行为的许可，源码可被粘贴进 BSD 代码而不带 GPL 传染性。讨论触及 BSD 模块在内核树中的许可定位与传染性边界。 `<!-- ROW_MINE: sparclinux.messages.9336311 -->`

- 【Linux社区】Ameer Hamza 在提交 O_EMPTY_PATH 标志的补丁说明中，明确指出现有 Linux openat 与 open 系统调用新增的 O_EMPTY_PATH 功能与 FreeBSD 的 O_EMPTY_PATH 标志非常相似。其用途是在路径为空时打开由文件描述符所引用的文件，这样能避免为 samba 容器等场景授予 proc 访问权限，从而以无竞争的方式重新打开文件以修改标志。David Laight 质疑该补丁究竟实现了什么，除了给公共内核代码路径增加代码之外没有意义，Hamza 回答它可以把一个 O_PATH 描述符转换成适合读写工作的描述符，从而绕开通过 procfs 打开文件再读写的做法。这是 BSD 内核的开放系统调用语义被 Linux 采纳的记录。 `<!-- ROW_MINE: sparclinux.messages.9337044 -->`

- 【Linux社区】Alan Cox 在审查 sections 泛化 RFC 时反对为代码引入 copyleft-next 新许可证标签。对方表示该标签已获 Rusty Russell 批准为 GPL 兼容，并经过三名律师审查，其中两名来自 SUSE。Cox 反驳称无需新标签，应使用 GPL 或 GPL 附加权利，因为与内核结合后必然是 GPLv2，唯一完全兼容的方式是内核社区以 GPL 许可衍生作品。他给出第二个理由涉及 clause 8：不希望有人以该许可证创建模块，声称其是开源，十五年后以仅二进制形式发布而仍保留被视为 GPL 兼容的 copyleft-next 标签。他明确说明内核不设置 BSD 标签而采用 GPL 附加权利，正是为了阻止模块标签被滥用。他还质疑对方许可证的条款是否允许把贡献补丁并入专有版本。 `<!-- ROW_MINE: sparclinux.messages.9337749 -->`
