# 5.7.15 207.3 【Linux社区】BSD 治理智慧反哺 Linux（续）

- 【Linux社区】2018 年 Richard Weinberger 与 David Laight 就 Linux x32 支持是否应该移除讨论，Kevin Easton 明确引用 OpenBSD 与 NetBSD 在 32 位系统上已使用 64 位 time_t 四五年的历史，Richard 起初反驳称 BSD 可以 flag-day 破坏兼容而 Linux 不行，Laight 反击指出 NetBSD 二进制兼容性“比 Linux 更好”、通过新增系统调用号与更新 libc/头文件实现 time_t 64 位迁移；正文 BSD 词命中 7 处，是 BSD 系统 ABI 迁移经验反照 Linux x32 治理讨论的一手材料 `<!-- ROW_MINE: lkml.messages.7084295 -->`
- 【Linux社区】2001年9月FreeBSD核心团队成员Warner Losh（imp@harmony.village.org）就Slashdot“BSD-Linux FlameWar over SoftRAID”报道公开发言，以1992年ObjectBuilder for Linux老资历背书，直面Soren Schmidt SoftRAID代码被Linux直接拷贝：“The fact of the matter is that the code was copied from FreeBSD verbatim, or with minor alterations. That's not a problem at all, since our license allows for that. The problem came in that Soren's name was removed from the headers”，区分attribution与license问题，声明“FreeBSD's core team has never issued any statements on this issue”，主张“Healthy code and concept sharing between Linux and FreeBSD... is in everyone's best interest”；BSD核心团队对Linux采用BSD代码的治理立场声明，与2007 ath5k/GPL-BSD冲突（205.x）形成前后里程碑。 `<!-- ROW_MINE: lkml.messages.2012421 -->`
- 【Linux社区】2008年Cyrus Massoumi在Nick Piggin报告PostgreSQL 2.6.25-rc5运行队列饱和后吞吐线性塌方串中, 援引Kris Kennaway维护的people.freebsd.org/~kris/scaling基准页(含MySQL/PostgreSQL/BIND/NSD/SPECjbb/ebizzy), 指出"FreeBSD 7"相对Linux 2.6.23+调度器的持续优势, 并追问"Does anybody even do this at all for Linux?", 是FreeBSD基准驱动持续回归测试治理文化向Linux社区反向审视的一手材料。 `<!-- ROW_MINE: lkml.messages.2335730 -->`
- 【Linux社区】2001年Michael C. Wu(keichii, FreeBSD核心开发者, keichii@freebsd.org, 署名"Yes, BSD is a conspiracy")将Rik van Riel从freebsd-hackers转发到LKML, 内含NetBSD自由人Dennis(dennis@etinc.com)对Linux SMP的尖锐反问"Does 2.4 have something similar to spl levels or does it still require the ridiculous MS-DOSish spin-locks to protect every bit of code?", 并致歉"Deep humble apologies for troll migration", 是BSD维护者跨内核论坛公开批评Linux SMP设计并经BSD核心转呈的一手存档。 `<!-- ROW_MINE: lkml.messages.2084903 -->`
