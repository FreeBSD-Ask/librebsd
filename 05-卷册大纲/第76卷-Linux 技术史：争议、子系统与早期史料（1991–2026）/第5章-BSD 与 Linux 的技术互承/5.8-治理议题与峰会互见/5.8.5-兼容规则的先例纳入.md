# 5.8.5 兼容规则的先例纳入

<!-- ROW_MINE: lkml.messages.1763181 -->`
- 【Linux社区】2004年8月 Albert Cahalan(albert@users.sf.net) 在“Re: dynamic /dev security hole?”串中 批评 Linux PAM 权限模型，指出“Linux still doesn't have this system call. It's been in BSD since 4.3BSD-Reno”，是 BSD 血统 revoke() 系统调用缺席 Linux 内核、被 lkml 明确点名为安全缺陷的张力例证 `

<!-- ROW_MINE: fb-6314 -->`
- 【Linux社区】2003年8月 Chuck Yerkes(chuck+obsd@2003.snew.com) 在“Re: Some Newbie Questions”串中 指出 OpenBSD 与所有 BSD 从源构建内核与用户空间、Linux 发行版则是内核加多源用户空间组合“OpenBSD (all BSDs) come with source for the kernel and the whole userland”，是 BSD 系统完整性相对 Linux 内核加多源用户空间组合的谱系对比、维护者视角评价 Linux 的 BSD/Linux 张力叙事 `

<!-- ROW_MINE: ksummit.messages.2131 -->`
- 【Linux社区】2014年5月 Andy Lutomirski(luto@amacapital.net) 在“Re: [Ksummit-discuss] [CORE TOPIC] Dealing with 2038”串中以 CONFIG_COMPAT_VDSO 为例追问 Linux 兼容治理的规则，原文“it would be nice if there were a clear mostly-applicable rule for how this should work”把 John Stultz 开篇援引的 NetBSD 与 OpenBSD time_t ABI 破例纳入 Linux 的兼容治理议程 `

<!-- ROW_MINE: ksummit.messages.6941 -->`
- 【Linux社区】2014年5月 John Stultz(john.stultz@linaro.org) 在“[Ksummit-discuss] [CORE TOPIC] Dealing with 2038”串中开题并把 NetBSD 与 OpenBSD 的 ABI 破例方案作为直接先例，原文“NetBSD and OpenBSD have recently broken their ABI, converted their time_t to long long”将 BSD 时间方案写进 Linux 2038 议程，是 BSD 对 Linux 兼容性治理最直白的技术参照 `

<!-- ROW_MINE: freebsd-hackers.messages.2640164 -->`
- 【Linux社区】2001年6月 Peter(fbsdq@yahoo.com) 在“Re: Query:  How to tell if Microsoft is using BSD TCP/IP code?”串中 分析Bill Gates反GPL立场，“Microsoft isn't anti open-source, it's anti GPL”是 BSD与GPL在企业软件战略层面的张力代表 `

<!-- ROW_MINE: linux-fsdevel.messages.697152 -->`
