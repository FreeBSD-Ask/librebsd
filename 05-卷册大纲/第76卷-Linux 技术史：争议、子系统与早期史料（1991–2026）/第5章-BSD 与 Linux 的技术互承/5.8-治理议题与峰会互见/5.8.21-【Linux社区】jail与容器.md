# 5.8.21 【Linux社区】jail与容器

- 【Linux社区】2002 年 7 月 Ville Herva（HUT）在 LKML“防止 chroot(2) 逃逸”（Re: prevent breaking a chroot() jail?）线程中系统对照 FreeBSD jail(2) 文档：“Jail thwarts these... Jail takes care of this by only allowing 35 operations for jailed root (out of the 260 allowed for normal root)”，指出 FreeBSD jail 通过 p_trespass() 阻断跨 jail 的 ptrace 与跨进程内存共享，限制 jailed 进程单一 IP，是 BSD 沙箱机制被逐项引入 Linux 社区安全讨论的直接证据 <!-- ROW_MINE: lkml.messages.1730888 -->`
- 【Linux社区】2002 年 7 月 Ville Herva 在同一 jail() 系统调用讨论串中回应 David Wagner 关于 fd-passing 与端口绑定的担忧，援引 FreeBSD jail(2) 手册：“In FreeBSD, INADDR_ANY is explicitly translated to jail's IP. Many daemons use INADDR_ANY routinely, so I think it makes sense”，并指出“jailed root is supposed to be safe. So if something is jailed - and has the necessary privileges - it can bind to the jail ip (each jail has its own ip). But it can't bind to any other ip's of the box”，坐实 FreeBSD jail 单 IP 强制绑定语义在 Linux 讨论中的采纳动因 <!-- ROW_MINE: lkml.messages.2097378 -->`
- 【Linux社区】2002 年 10 月 Shaya Potter 就 Bernd Eckenfels 转引并反驳的“FreeBSD 允许 chroot'ed 进程在初始 chroot 子目录内再次 chroot”一说（Eckenfels 认为其要点实为 FreeBSD 已解决逃逸问题）发问，直指其究竟指 FreeBSD 的 jail() 系统调用还是指 chroot() 本身可嵌套，把 Linux chroot 安全讨论直接锚定到 FreeBSD 的 jail 机制上，FreeBSD jail 作为 Linux chroot 讨论的直接参照。 <!-- ROW_MINE: lkml.messages.1652772 -->`
