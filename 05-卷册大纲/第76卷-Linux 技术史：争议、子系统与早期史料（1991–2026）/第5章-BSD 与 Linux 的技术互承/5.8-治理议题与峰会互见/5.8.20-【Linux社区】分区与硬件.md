- 【Linux社区】2021 年 5 月 OpenBSD 系统工程师 Mark Kettenis（kettenis@openbsd.org）在 lkml 提交 Apple PCIe 主机控制器 dt-bindings 补丁，SPDX 头明确标 (GPL-2.0-only OR BSD-2-Clause) 双许可，正文与 Rob Herring 讨论 Apple Silicon Mac 与 iPhone/iPad 上 DWC PCIe 控制器的属性继承与扩展，是 BSD 阵营工程师直接参与 Apple Silicon 硬件抽象层 Linux 内核建模的证据，也是 BSD-2-Clause 在 Linux dt-bindings 层的双许可实践案例。 `<!-- ROW_MINE: lkml.messages.2767631 -->`
- 【Linux社区】2025 年 8 月 David Woodhouse（dwmw@amazon.co.uk）在 lkml 提交 v4 补丁 x86/bhyve: Detect FreeBSD Bhyve hypervisor，补丁明确写出 FreeBSD 15.0 将支持 15 位 MSI enlightenment 以支持超过 255 个 vCPU，并附 FreeBSD 15.0 上游 commit 313a68ea 链接；Kconfig 新增 BHYVE_GUEST 选项，说明该选项让 Linux 识别自身作为 guest 运行于 Bhyve 宿主机之下并在此情形下支持超过 255 个 vCPU；此前内核对 Bhyve 的识别仅是启动时打印提示，此补丁首次赋予其功能意义，构成 Linux x86 虚拟机栈纳入 FreeBSD Bhyve 宿主机功能性识别的直接证据。 <!-- ROW_MINE: lkml.messages.4552248 -->`
- 【Linux社区】2016年5月Intel ACPI工程师Lv Zheng在ACPICA硬件寄存器访问位宽优化补丁串中，将FreeBSD社区报告的旧版寄存器描述翻译缺陷作为Linux侧驱动修复的动因：补丁说明记录acpi_tb_init_generic_address()将旧寄存器描述的access_width填充为0，导致acpi_hw_get_access_bit_width()在16位IO端口上回归，报告者John Baldwin（jhb@freebsd.org）、测试者Jung-uk Kim（jkim@freebsd.org），修复者Lv Zheng；此案例显示FreeBSD ACPICA用户报告反向滋养Linux内核ACPI硬件抽象层，与205章2020年ACPICA UBSAN同主题形成上下游证据链。 `<!-- ROW_MINE: lkml.messages.6295754 -->`
- 【Linux社区】2019年10月12日，Gentoo/MIPS 维护者 Joshua Kinard（kumba@gentoo.org）在 [PATCH] MIPS: add support for SGI Octane (IP30) 线程中回复 Christoph Hellwig 关于 ip30-pci.c 与 ip27 应共享实现的建议，指出 SGI Octane IP30 的 BRIDGE 控制器仅能访问 31 位 DMA 可达内存区（xbridge(4) 的 IOMU 特性受限），Linux 上需在 __phys_to_dma() 内做等价约束；他直接引用 OpenBSD 源码 bxr.su/OpenBSD/sys/arch/sgi/sgi/ip30_machdep.c 第 144-150 行的 dma_constraint.ucr_low = 0; dma_constraint.ucr_high = (1UL << 31) - 1 作为参考实现，并指出 OpenBSD 对 IP27 施加同样限制但 Onyx2 8GB RAM 却能启动，怀疑是 IP30 专属硬件 bug。此为 Linux 内核 MIPS 架构新增 SGI Octane 支持时直接参照 OpenBSD 实现的一手 BSD→Linux 代码移植证据。 `<!-- ROW_MINE: lkml.messages.7143506 -->`
- 【Linux社区】2018 年 Richard Narron 的修复经 4.15-stable 审查补丁合并（上游 commit 5f15684b），修复 block/partitions/msdos.c 的 parse_bsd 函数：新版 FreeBSD 10/11 的 UFS 子分区改用相对寻址，而旧版 FreeBSD 与 OpenBSD/NetBSD 沿用绝对寻址，代码需在 FreeBSD 分区上检测 C 子分区 offset 为零才施加相对寻址修正；附 bugzilla #197733，是 Linux 内核 BSD 分区表兼容性工程随 BSD 自身演进同步演进的一手代码证据。 <!-- ROW_MINE: lkml.messages.6859331 -->`
- 【Linux社区】2015 年 Citrix 的 Julien Grall 就同一 EFI stub/FDT 参数标准化线程回复（承接 Roger Pau Monné 关于 FreeBSD Dom0 启动的说明），指出 Xen 已在 ARM 有基于设备树的 multiboot，为 FreeBSD 另设存储 metadata 的 module 并做 Xen trampoline 可行，但设备树/ACPI/UEFI blob 属于 metadata 的一部分而需随之改动，除非其稳定否则无法在 Xen 中使用；正文转引 Roger 完整回复；与 row 7 同 thread <!-- ROW_MINE: lkml.messages.6216257 -->`
- 【Linux社区】2015年6月Ross Lagerwall提交partitions/msdos Support relative offset BSD partitions补丁，处理FreeBSD磁盘标签使用相对偏移（bsdlabel relative / sysinstall absolute）导致Linux读取disklabel时“the partitions fail the sanity checks and are considered invalid or they use the wrong offset and data corruption ensues”的问题；补丁说明“The idea comes from the FreeBSD patch for GRUB”，以分区c（BSD_WHOLE_DISK）偏移量判别relative还是absolute，保留flavours[]数组区分FLAVOUR_BSD/FLAVOUR_NETBSD/FLAVOUR_OPENBSD三系统；FreeBSD GRUB磁盘标签补丁正式落到Linux block/partitions/msdos.c的完整链路。 <!-- ROW_MINE: lkml.messages.6409560 -->`
- 【Linux社区】2000年12月Linux ATA维护者Andre Hedrick（CTO Timpanogas Research Group）就Raymond Carney关于HPT370 RAID支持的提问正面回应：Carney 提问中引述 FreeBSD ata-raid.c（Soren Schmidt sos@freebsd.org）与 OpenBSD/NetBSD pciide 驱动（Chris Cappuccio、Manuel Bouyer）的工作，Hedrick 自述数日前已致信 Soren 询问 RAID 签名解码方式未获回复，自称掌握阵列内容与 RAID 引擎设计但无法为 Linux 推导出合理用法，并明确不亲自移植：“FreeBSD use a CAM layer so they can do some things that Linux can not but they have a perfoamance price that Linux does not have. You take CAM->SCSI->ATA and back and you see how nasty that crap is in the performance market. If you want to tear into FreeBSD and extract the information for me go for it”；Linux ATA维护者对FreeBSD CAM层的否定定性，成为2000年代Linux ATA层与FreeBSD CAM分离的决策依据。 <!-- ROW_MINE: lkml.messages.1945574 -->`
