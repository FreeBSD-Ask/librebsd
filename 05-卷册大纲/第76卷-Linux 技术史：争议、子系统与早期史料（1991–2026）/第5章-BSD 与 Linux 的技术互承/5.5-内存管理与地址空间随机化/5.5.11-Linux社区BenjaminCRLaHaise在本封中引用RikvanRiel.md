- 【Linux社区】Benjamin C.R. LaHaise 在本封中引用 Rik van Riel 的建议 “If you want a real improvement, you should port over some of the (very nice) FreeBSD algorithms for I/O clustering and assorted stuff”，即建议为获得实质改进而移植 FreeBSD 的 I/O 聚类等算法；随后 Benjamin 自述已开始阅读 FreeBSD，并称阅读其内部实现 “it doesn't feel nearly as readable as Linux code”。`<!-- ROW_MINE: linux-mm.messages.957721 -->`
- 【Linux社区】Daniel Phillips 反对 BSD 式页表过程接口，认为其分解方式不适合 Linux、无法支持批量处理：“The BSD interface just doesn't accomodate this”；将这类过程式接口溯至 “the BSD pmap and SVR4 HAT layers” 的提问则出自 William Lee Irwin III。`<!-- ROW_MINE: linux-mm.messages.958166 -->`
- 【Linux社区】Alan Cox 指出 “Historically BSD tackled some of this by actually swapping processes out once pressure got very high”，并认为早在现代存储之前，避免抖动的需求就已塑造了 BSD 的内存管理取舍。`<!-- ROW_MINE: linux-mm.messages.958633 -->`
- 【Linux社区】Matthew Dillon（后来创办 DragonFly BSD）将 FreeBSD 的对象模型与 Linux 方案并置，称 “vm_map_entry, vm_object under FBsd, VMA in Jamie's scheme” 这类聚合结构根本不会带来按页计的内存开销。`<!-- ROW_MINE: linux-mm.messages.958728 -->`
- 【Linux社区】Andrea Arcangeli 回应 Alan Cox 所述 “I can run a matrox meteor on netbsd,freebsd,openbsd,windows95, nt but not Linux”，并提出为 2.2 时代 Linux 获取连续物理页的变通实现方案。`<!-- ROW_MINE: linux-mm.messages.958847 -->`
- 【Linux社区】Rik van Riel 援引 FreeBSD 的做法：“FreeBSD has a neat solution for this”，即内存对象在用时把页移入 inactive 列表、否则移入 cache 列表，分别对应 Linux 的 inactive_dirty 与 inactive_clean。`<!-- ROW_MINE: linux-mm.messages.958882 -->`
- 【Linux社区】2001年5月16日，Rik van Riel 在 “on load control / process swapping” 线程回复 Matt Dillon 的引文，以 FreeBSD 的连续访问检测启发式作为 Linux 内存管理策略设计的跨内核先例。引文原文：“FreeBSD has a sequential detection heuristic which does a pretty good job preventing cache blow-aways”。Rik 进而论证 drop-behind 惩罚机制连正在被二次三次读取的驻留数据一并降权，提出只在为 vnode 真正分配新内存时启用 drop-behind，并自评此举 “could introduce some different fairness issues”。该件呈现 BSD 谱系实现被直接征引为 Linux 参数设计与公平性权衡的对照样本。`<!-- ROW_MINE: linux-mm.messages.969672 -->`
- 【Linux社区】2009年6月15日，Alan Cox 在 HWPOISON v5 补丁线程中转述 Andi Kleen 的论断：Linux 传统上 always tried to keep things running if possible instead of panicing，故 ext3 或 block 遇 IO 错误不默认 panic，Kleen 并以 oops does not panic by default like on BSDs 把 oops 行为与 BSD 并举；Alan 以生产部署经验反驳，称一线运维普遍开启 panic 加 reboot，原因是 the web server is running but not logging transactions 这类静默故障会骗过监控软件。该件记录 Linux 在错误处理默认策略上延续 keep-things-running 传统的一面。`<!-- ROW_MINE: linux-mm.messages.970469 -->`
- 【Linux社区】2017年12月19日，David Laight 在 MAP_FIXED_SAFE 命名讨论中要求 “match the prior art”：Edward Napierala 曾引 FreeBSD 的 mmap(2) 文档，称 MAP_EXCL “was introduced in FreeBSD”，即地址范围内已有映射则 mmap 失败。Michal Hocko 回应 MAP_EXCL 在 FreeBSD 只是 MAP_FIXED 修饰符，Linux 语义不同，同名 “would be more confusing than helpful”。这是 BSD API 先例直接进入 Linux 接口命名的证据。`<!-- ROW_MINE: linux-mm.messages.971942 -->`
- 【Linux社区】Andrea Arcangeli 在 madvise() 语义讨论中明确以 FreeBSD 应用兼容性作为拒绝方案的理由：“merging MADV_REMOVE into MADV_FREE apparently would break freebsd apps that might expect a noop instead”。他认为 FreeBSD 把该调用当作 noop，因此 Linux 应坚持 noop 语义并把 MADV_REMOVE 单独保留，避免与 BSD 及 Solaris 派生的既有实现产生行为差异。这是 BSD 用户态 ABI 约束 Linux madvise 接口演进的直接留痕。`<!-- ROW_MINE: linux-mm.messages.940814 -->`
- 【Linux社区】1998 年 11 月关于 2.1 内存管理文档的讨论中，用户询问 “Are there plans for implementing the swapping of whole processes a la BSD?”，即是否计划实现类似 BSD 的整进程换页。Rik van Riel 答称 “Yes, there are plans. The plans are quite detailed too”。他以 BSD 作为参照系定位 Linux VM 的演进方向，属 BSD 谱系对内核页换出机制的直接参照。`<!-- ROW_MINE: linux-mm.messages.941084 -->`
- 【Linux社区】Rik van Riel 在进程挂起机制讨论中做了历史溯源：“when paging was introduced in 3bsd, process suspension under heavy load was preserved”。他解释这样做的目的是让系统重载时继续前进而不必抖动停摆，并补充 “the 'minimal working set' idea Stephen posted was also in 3bsd”，另追溯到 Bell Labs v5 Unix。该条目把 Linux VM 的负载挂起与最小工作集思路明确挂到 3BSD 谱系上，是 BSD 谱系溯源的最清晰例证之一。`<!-- ROW_MINE: linux-mm.messages.941230 -->`
- 【Linux社区】Suleiman Souhlal 在 MADV_FREE 与 MADV_DONTNEED 语义讨论中给出 FreeBSD 的实测行为描述：“in FreeBSD, MADV_DONTNEED is not destructive”，该调用并不销毁数据，只是让页面更可能被换出；另 “FreeBSD's MADV_FREE only works on anonymous memory”，对 vnode 支撑内存是 noop，并先标记页面干净再移入 inactive 队列，据此主张把这些行为引入 Linux 以与其他系统对齐。这是 BSD 实现对 Linux madvise 语义设计的实质输入。`<!-- ROW_MINE: linux-mm.messages.941402 -->`
- 【Linux社区】1999 年 9 月 Rik van Riel 在主题为 Need ammo against BSD Fud 的线程中正面承认：“The BSD VM system _is_ better than the Linux one, but AFAIK that's about the only part where we lag”。他把 BSD 视为 Linux VM 唯一落后到能被察觉的环节，并主张 “The first part would be a real zoned memory allocator”，以分区内存分配器起步弥补缺口。这是 BSD 与 Linux VM 能力对照及后续设计动机的原始讨论。`<!-- ROW_MINE: linux-mm.messages.941733 -->`
