# 5.5.3 Linux社区2001年AlanCox在无盘节点swap讨论的回复帖中引有nei

- 【Linux社区】2001 年 Alan Cox 在无盘节点 swap 讨论的回复帖中引有“neither SunOS, Solaris or NetBSD are infallible”的乐观论断，以及机器死机时用户被告知什么、可否用 ping -f 耗尽原子内存的反问；Cox 回应称对简单情形可停止向用户套接字排队数据但这未必是解药、反可能造成假性 OOM，并举无默认路由却做 BGP4 路由、以 NFS 为 swap 的机器作为不可解问题的极端例证，说明优先级顺序对内核不可知。`<!-- ROW_MINE: linux-mm.messages.1007966 -->`
- 【Linux社区】2018 年 mmap 地址随机化 RFC 讨论中，Daniel Micay 提及后续不排除 OpenBSD mmap 式的随机支点切换，原话为 “switches between random pivots like OpenBSD mmap, etc.”；Ilya Smith 则主张保留一个系统级内核开关并另设 ioctl，让确需超大内存的应用可以关闭随机化。`<!-- ROW_MINE: linux-mm.messages.1008075 -->`
- 【Linux社区】2018 年 Steven Rostedt 与 Linus Torvalds 就 4.14 stable 的 AUTOSEL 回移政策展开争论：Rostedt 质疑 AUTOSEL 补丁收入前是否应有 ack 签署，Linus 答称 “requiring active participation for the steady flow of normal stable patches is almost pointless”，Rostedt 则坚持任何非平凡回移都须经可信之人把关。`<!-- ROW_MINE: linux-mm.messages.1008168 -->`
- 【Linux社区】Rik van Riel 于 2017 年提出 MADV_WIPEONFORK，使 VMA 在 fork 后的子进程中地址有效但内容清空，并明言以 OpenBSD 接口为参照，原话为 “This is similar to the OpenBSD minherit syscall with MAP_INHERIT_ZERO”，补丁附 OpenBSD 手册页链接，用例为 glibc 与 OpenSSL 的 fork 后 PRNG 重播种以及 systemd、PKCS#11 的 API 检查。`<!-- ROW_MINE: linux-mm.messages.1008880 -->`
- 【Linux社区】2004 年 msync(MS_ASYNC) 行为讨论中，Stephen C. Tweedie 报告跨系统实测，指出 FreeBSD 与 Tru64 一样对 MS_ASYNC 不立即启动 IO，原话为 “The same appears to be true on FreeBSD”；Linus Torvalds 由 Solaris 立即启动 IO 的表现推想 Linux 可用 TestSetPageLocked 加 BIO_RW_AHEAD 实现写前发，但认为当时尚不宜采用。`<!-- ROW_MINE: linux-mm.messages.1008884 -->`
- 【Linux社区】2006 年 MADV_FREE 与 MADV_DONTNEED 差异讨论中，Suleiman Souhlal 记述 FreeBSD 语义，原话为 “in FreeBSD, MADV_DONTNEED is not destructive, and just makes pages ... more likely to get swapped out”；他还指出 FreeBSD 的 MADV_FREE 仅作用于匿名内存，Andrea Arcangeli 认同此举可使 Linux 与其他系统行为看齐。`<!-- ROW_MINE: linux-mm.messages.1009052 -->`
- 【Linux社区】2009 年 Rik van Riel 质疑以进程挂起加长时间片取代 LRU token 的回收方案，并引 BSD 策略在 Linux 的屡次失败为据，原话为 “BSD style process suspension has been tried many times on Linux and it never seemed to work right”；他申明若有证明确实更优并不反对替换，但要求先证明方案可扩展到超大内存系统。`<!-- ROW_MINE: linux-mm.messages.1009163 -->`
- 【Linux社区】2002 年围绕为何不采用反向映射的讨论中，Christian Smith 主张拆分通用 VM 层与 pmap 层，并以 BSD 为比较基准，原话为 “Looking at Linux VM performance against any of the BSDs and SysV”；他断言拆分后的分层在重负载条件下更易优化也更好维护。`<!-- ROW_MINE: linux-mm.messages.1009762 -->`
- 【Linux社区】2001 年 2.4.10 前夕 VM 崩坏讨论中，Eric W. Biederman 为 Linux 不设反向映射的取舍辩护，并明确以 BSD 设计为对照，原话为 “In linux we have avoided reverse maps (unlike the BSD's)”；他估计加入反向映射会使 fork 需复制的内容增至三倍，Alan Cox 则质疑这一成本被高估。`<!-- ROW_MINE: linux-mm.messages.1010375 -->`
- 【Linux社区】2019 年讨论把 sys_mincore 设为特权调用时，Matthew Wilcox 追溯 mincore 的来源并发现 BSD 一系的传承线索，原话为 “FreeBSD claims to have a manpage from SunOS 4.1.3 with mincore”，他逐字引述该 SunOS 4.1.3 手册描述，动摇了此 API 约在 2000 年随 Linux 2.3.52pre3 才出现的说法。`<!-- ROW_MINE: linux-mm.messages.1010675 -->`
- 【Linux社区】1998 年 12 月 swapin 预读补丁讨论中，Chris Evans 以 FreeBSD 为对照指出 Linux 交换吞吐差距，原话为 “This is one area in which FreeBSD stomps on us.” 他建议以预读把页面按磁盘速度拉入 RAM，并追问低内存大交换场景下的 boot 基准。属 Linux VM 早期性能对标 FreeBSD 的史料。`<!-- ROW_MINE: linux-mm.messages.900321 -->`
- 【Linux社区】2001 年 7 月 bert hubert 推介基于 mincore() 查询内核页缓存的工具 cinfo，其跨平台范围原话为 “Supports Linux, FreeBSD, OpenBSD, Solaris and Mac OS X.” mincore() 是页缓存可见性的 Unix 接口，该工具把它做成多系统兼容实现。属 BSD 平台作为页缓存接口语义参照。`<!-- ROW_MINE: linux-mm.messages.900506 -->`
- 【Linux社区】2020 年 10 月 mprotect 与 arch_validate_prot ABI 讨论中，Catalin Marinas 援引 FreeBSD 实现作为先例，原话为 “FreeBSD seems to do a first pass to check for violations”，即先做一次完整校验再执行，并附 FreeBSD vm_map.c 的源码链接。属 Linux 内存保护接口与 BSD 实现对照。`<!-- ROW_MINE: linux-mm.messages.901082 -->`
- 【Linux社区】2008 年 11 月 page_fault 重试补丁讨论中，Nick Piggin 把 Linux 的 mmap_sem 竞争问题与 BSD 侧讨论串关联，原话为 “shown up in that FreeBSD MySQL thread”；他认为在私有 futex 出现之前，内核与 glibc 曾共同修复 malloc 的 mmap_sem 问题。属 BSD 侧对同一 Linux 缺陷的讨论证据。`<!-- ROW_MINE: linux-mm.messages.901372 -->`
- 【Linux社区】2000 年 5 月 Rik van Riel 讨论 2.4 内核分区均衡方案时，直接把 BSD 作为实现先例，原话为 “active and inactive list a'la BSD, etc”；他说 Linus 在做保守而简单的方案，自己则尝试更激进的实现。属 Linux 早期 VM 主动清单设计向 BSD 取经的史料。`<!-- ROW_MINE: linux-mm.messages.901511 -->`
- 【Linux社区】1999 年 1 月 MM 死锁讨论中，Alan Cox 主张连续大块物理内存分配是 2.3 的问题清单，Gerard Roudier 反驳并点名 BSD 族系统，原话为 “FreeBSD does not guarantee the malloc_contig() function will succeed every time”；他反对任何要求单页以上物理连续内存的做法，认为那会破坏简单性。属 Linux 连续分配设计与 BSD 语义对照。`<!-- ROW_MINE: linux-mm.messages.902087 -->`
- 【Linux社区】2000 年 10 月页分配讨论中，Eric Lowe 以 BSD 为对照说明 Linux 内核身份映射的选择，原话为 “Linux has access to kernel memory without mapping it below 1GB all the time”，并解释高内存访问只需临时映射，随后说明映射增删因 TLB 刷新而代价高。属 Linux 内核地址空间设计与 BSD 对照。`<!-- ROW_MINE: linux-mm.messages.902371 -->`
- 【Linux社区】Minchan Kim 推进 madvise(MADV_FREE) 补丁，援引 jemalloc 作者 Jason Evans 的论证：jemalloc 在除 Linux 外的各平台（各 BSD 系、OS X、Windows、Solaris）均已使用 MADV_FREE 或等价机制，Linux 的缺失迫使 jemalloc 退回一整套愈发复杂的启发式方案。Kim 自述原话为 “jemalloc/tcmalloc already have supported the feature for other OS(ex, FreeBSD)”。`<!-- ROW_MINE: linux-mm.messages.1004746 -->`
- 【Linux社区】2.4.10-pre9 VM 崩坏讨论中，Eric W. Biederman 道出 Linux 与 BSD 的分歧：Linux 刻意避开反向映射而 BSD 采用，换取常见路径更快，代价是内存压力下换页更难处理。Daniel Phillips 追问反向映射成本。原文引语为 “In linux we have avoided reverse maps (unlike the BSD's)”。`<!-- ROW_MINE: linux-mm.messages.1005599 -->`
- 【Linux社区】Christian Smith 提议用 UVM 替换 Linux MM，Rik van Riel 回应称不想要 Mach 的 pmap 层，但在更简单的反向映射之上重写 BSD 内存管理的换出部分会容易得多，并给出补丁链接。这是 Linux 2.4 时代开发者主动把 BSD 换页实现当作移植蓝本的留痕。原文引语为 “reimplement the pageout parts of the BSD memory management on top of a simpler reverse mapping system”。`<!-- ROW_MINE: linux-mm.messages.1006481 -->`
- 【Linux社区】KOSAKI Motohiro 在 fadvise DONTNEED 讨论中回应原帖关于缺少 FADV_NOREUSE 使 fadvise 效用受限的抱怨，并汇总各操作系统实现状态：NetBSD 为空操作、与 Linux 相同，FreeBSD、DragonFlyBSD、OpenBSD 则根本没有 posix_fadvise 接口。属 BSD 家族与 Linux 接口覆盖对照。原文引语为 “NetBSD: no-op (as linux) FreeBSD/DragonflyBSD/OpenBSD: don't exist posix_fadvise(2)”。`<!-- ROW_MINE: linux-mm.messages.1006514 -->`
- 【Linux社区】2000 年 Linux 2.3/4 VM 队列设计讨论中，Matthew Dillon 以跨系统视角为 Linux 换页分配方案定位。原文引语为 “I don't think anyone (linux, freebsd, solaris, or anyone else) has yet written the definitive swap allocation algorithm”，把 Linux 与 Solaris 并列点名 freebsd，属 linux-mm 中罕见的明确以 FreeBSD 为参照系的技术自评，亦是 BSD 作者对 Linux VM 演进的直接介入记录。`<!-- ROW_MINE: linux-mm.messages.1026285 -->`
- 【Linux社区】Rik van Riel 提交 2.4.1-ac19 的 page_launder 改进补丁，diff 中保留了 Linux 内核源码对 FreeBSD 的直接谱系致谢。原文引语：“This code is heavily inspired by the FreeBSD source code. Thanks go out to Matthew Dillon.”该注释明确记载 Linux 页扫描换出逻辑派生自 FreeBSD 源码并指名 FreeBSD 作者 Matthew Dillon，属 BSD 代码与作者谱系流入 Linux 内存管理的最强硬证据，建议优先入档。`<!-- ROW_MINE: linux-mm.messages.1027441 -->`
- 【Linux社区】memcg 多页 stock 补丁的提交信息保留了原作者的 FreeBSD 机构邮箱，原文引语：“From: Suleiman Souhlal <ssouhlal@FreeBSD.org>”，同一署名者随后改以 Google 邮箱继续提交并被多人 Acked，构成 FreeBSD 生态人员流向 Linux 内核内存管理方向的可追溯人物证据，可用于梳理 BSD 贡献者的跨内核迁移轨迹。`<!-- ROW_MINE: linux-mm.messages.1028222 -->`
- 【Linux社区】Theodore Ts'o 讨论文件系统 shutdown 路径能否下沉为 VFS 通用接口时，以 BSD 的 revoke 语义作基准批评 Linux 实现不彻底，原文引语：“it's not a true revoke(2) functionality”，并指出 Linux 只阻断可能修改文件系统的调用而不阻断只读访问，属 BSD 系统调用谱系对 Linux 内核设计完备性的对照评价，同时提出以类 vhangup 的文件描述符级断开接口作为泛化方向的取舍。`<!-- ROW_MINE: linux-mm.messages.1028286 -->`
- 【Linux社区】KAMEZAWA Hiroyuki 2011 年 10 月 17 日就 Suleiman Souhlal 提交的 memcg slab 内核内存核算补丁系列追问性能数据，该系列提出者署名邮箱为 FreeBSD 官方域 FreeBSD.org，属 BSD 阵营项目人员向 Linux 内存管理子系统直接输入工作。`<!-- ROW_MINE: linux-mm.messages.1035658 -->`
