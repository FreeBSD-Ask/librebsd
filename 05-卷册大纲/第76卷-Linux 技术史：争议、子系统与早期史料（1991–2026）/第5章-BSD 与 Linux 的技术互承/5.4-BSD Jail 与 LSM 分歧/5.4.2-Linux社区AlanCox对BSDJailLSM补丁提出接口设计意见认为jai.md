# 5.4.2 Linux社区AlanCox对BSDJailLSM补丁提出接口设计意见认为jai

- 【Linux社区】Alan Cox 对 BSD Jail LSM 补丁提出接口设计意见，认为 jail 场景下应当允许同时挂载 ipv4 与 ipv6 接口，并进一步质疑用 bind 或 connect 时机的 netfilter 链能否覆盖全部选择接口的需求 “could be addressed by netfilter chains run at bind/connect time”`<!-- ROW_MINE: netdev.messages.8012449 -->`
- 【Linux社区】Changli Gao 发布 synproxy iptables 目标实现，自述其与 OpenBSD pf 的 SYNPROXY 机制类似，仅在首个连接经 syncookies 建立之前不保留状态；Patrick McHardy 回应称给出好用例即可考虑进主线，并坦言自己不熟 pf synproxy “It is much like the SYNPROXY implementation in pf of OpenBSD”`<!-- ROW_MINE: netdev.messages.8012648 -->`
- 【Linux社区】David Miller 在 ipv4 组播补丁讨论中表态，凡是 RFC 或规范未把语义写死的情形，只要 BSD 那样做就应当视为应当如此，理由是它本身就是 BSD socket API，把 BSD 行为抬为 Linux 语义判据 “whatever BSD does is effectively the definition of what should happen”`<!-- ROW_MINE: netdev.messages.8012704 -->`
- 【Linux社区】Steve Rago 考证 recvmsg 附加数据的缓冲区语义来源，指出 CMSG_LEN 与 CMSG_SPACE 出自 RFC 2292 且已被 RFC 3542 取代，而历史上 BSD 系平台根本没有这两个宏、空间不足时直接不返回附加数据 “Historically, BSD-based platforms never had these macros”`<!-- ROW_MINE: netdev.messages.8012944 -->`
- 【Linux社区】Baruch Siach 的补丁说明指出 uClibc 与 musl 等 C 库已自带兼容 BSD 的 strlcpy，建议经 configure 探测并在库已提供时避免重复定义 strlcpy 与 strlcat，Stephen Hemminger 回复致谢 “provide BSD compatible strlcpy”`<!-- ROW_MINE: netdev.messages.8013100 -->`
- 【Linux社区】John Stultz 系统对照 Linux 的 timex 模式位与 BSD 的定义差异，说明 ADJ_TICK 等于 FreeBSD 的 MOD_CLKB，Linux 另设 ADJ_OFFSET_SINGLESHOT 与 ADJ_OFFSET_SS_READ 以便 adjtimex 行为贴近原始 ntp_adjtime “which is MOD_CLKB in FreeBSD”`<!-- ROW_MINE: netdev.messages.8013481 -->`
- 【Linux社区】讨论 listen 积压语义变更时，Venkat Venkatsubra 称 BSD 曾把积压重置为传入值的 3/2 倍（如 2 变 3），并问 Linux 在旧的 backlog+1 判定下是否同样行为 “In BSD I think the backlog used to be reset to 3/2 times that passed by the user”`<!-- ROW_MINE: netdev.messages.8013805 -->`
- 【Linux社区】发帖人比较各平台关闭 TCP 延迟确认的途径，Windows 通过注册表修改 TCPAckFrequency，FreeBSD 与 Mac OS X 则用同一个 sysctl 键，但该键在 Linux 上并不存在 “net.inet.tcp.delayed_ack”`<!-- ROW_MINE: netdev.messages.8013881 -->`

- 【Linux社区】讨论 netlink af_key 的 SA 与 SP 转储时，David Miller 纠正 Timo Teräs：racoon 由日本 KAME 项目作为 BSD 协议栈附加件写成、后被加入 BSD，另有 OpenBSD 人员编写的 BSD 系 IPSEC 守护进程；Timo 说明本意即最初为 BSD 而写 “Racoon was written as an addon to the BSD stack by an IPV6/IPSEC project in Japan named KAME”`<!-- ROW_MINE: netdev.messages.8014357 -->`
