# 5.4.23 Linux社区RolandDreier的InfiniBandMAD补丁与其系列补

- 【Linux社区】Roland Dreier 的 InfiniBand MAD 补丁与其系列补丁一样携带双重许可选择：GPL 之外提供“OpenIB.org BSD license below”，并以“Redistributions of source code must retain the above”作为 BSD 义务。BSD 许可随补丁逐个进入内核树。 `<!-- ROW_MINE: netdev.messages.8379467 -->`
- 【Linux社区】Luis Rodriguez 说明 ar5k HAL 的治理模式：“We are basing our openhal on OpenBSD's ar5k”，且“the GPL does not allow us to commit changes on the GPL version back to”，故非 Linux 的 HAL 增强须提交给 Reyk Floeter，主树按其要求保持 BSD。这是罕见的明示 BSD 上游、Linux 下游的案例。 `<!-- ROW_MINE: netdev.messages.8379477 -->`
- 【Linux社区】Changli Gao 把 RPS 定位为对齐 FreeBSD 的工作：“Now linux also can dispatch packets as FreeBSD does via netisr.”，并追问能否走得更远、支持加权分发；反问“May I ask why ? What would be the goal ?”的是 Eric Dumazet。FreeBSD 的 netisr 在此是 Linux 收包转向工作的直接参照。 `<!-- ROW_MINE: netdev.messages.8379995 -->`
- 【Linux社区】David Miller 为 URG 处理辩护时直接引用 BSD：“In TCP/IP Volume 2, the original BSD code is even more ignorant of this situation, it simply sets the difference into the field as-is”，并给出“ti->ti_urp = htons((u_short) (tp->snd_up - tp->snd_nxt));”。BSD 源码在此成为 Linux 网络决策的引用证据。 `<!-- ROW_MINE: netdev.messages.8380139 -->`
- 【Linux社区】David Miller 以 BSD 权威裁断 getsockname 语义：“If you read the language Richard Stevens uses when describing both the usage and implementation of getsockname and getpeername in BSD”，即可明了这两个接口的用途。Linux 以文字引用的方式采纳 BSD 语义，这正是 BSD 实践进入内核的路径。 `<!-- ROW_MINE: netdev.messages.8380761 -->`
- 【Linux社区】David Miller 报告一桩仍在生效的 BSD 4.2 兼容负担：“there are still some Windows 2000 machines out there emitting BSD 4.2 style keepalives (one garbage byte instead of an empty out-of-window probe frame)”，Linux 既不确认这类报文，也无法改动 tcp_sequence() 去拒收。这套 BSD 4.2 时代的行为在 2010 年仍约束着 Linux 的 tcp_sequence()。 `<!-- ROW_MINE: netdev.messages.8380828 -->`
