# 3.1.4 11.2 【Linux社区】Driver/module 版本号政策之争

**要点**：Leon 开题：稳定流 bump driver/module version 的补丁让邮件负担剧增，可在 CodingStyle 加政策避免；例子 Succeeded vs Failed；问：能否统一政策？能否全移除 + MODULE_VERSION 全部改指内核版？这算不算“UAPI changes”类禁区？；Linus：政策其实“已经有”——版本号不重要、不存在、不被更新；前后向兼容，因为不接受用户空间破坏；版本化反而害人（暗示“可以改接口”）；feature mask 属例外（只能加接口，让空间检查存在性），用得非常非常谨慎；Leon：并非全知道该政策——“被接受”的例子不是 RDMA 的（RDMA 内部我禁这类补丁，patchwork 9735855）；我在别子系统强制失败（lkml 2016-07-15）；客户 cargo cult 照样要求更新版本；提案：禁这类补丁 + drivers/* 完全消除暴露；Linus：我猜只是没在别处惹麻烦；grep MODULE_VERSION/DRIVER_VERSION 比预想多些，但几百不是几千（死代码 ATA 或玩笑名 usb）；Leon：观不同——新驱动多的子系统里相当活跃；但你说政策存在，对我够了（收）；Belloni：早前我把 RTC 子系统版本号全删了；Leon（对 Belloni）：你指的是 fa5691131a87“rtc: remove useless DRV_VERSION”？看类似补丁在 RDMA、netdev 社区会怎样被接受；Greg：公司要几年才意识到版本号无意义——给时间自慢；或一次性全删掉一了百了；Leon 对 Greg：好，先小规模试点只限 MODULE_VERSION——patchwork 9808651 已发；Geert：唯一要紧的版本是 CONFIG_LOCALVERSION_AUTO=y
