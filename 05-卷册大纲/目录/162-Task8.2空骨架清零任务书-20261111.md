## 二、状态机（2026-11-11 改规则）

| 状态 | 含义 | 必备字段 | 台账义务 | 块 |
| ---- | ---- | -------- | -------- | -- |
| `skeleton` | 执行态：题已立、证据未落 | `volume/chapter/section/subsection/thesis/designed_at` | `design/exceptions` 同行 `open` 或 `claimed` | 0 块 |
| `filled` | 终态：有证据块 | 同上 | 若有台账行，须 `supplemented` | ≥1 块 |
| `closed` | 终态：不再补证 | 另须 `resolution_reason`、`closed_at`、`closed_ref` | 见下三因 | 0 块 |

`closed` 三因：

1. `unresolvable`：S1＋P1＋P2 穷尽仍无一手／权威二手；台账记 `unresolvable`＋`resolution_kind=exhausted`＋`resolution_ref=doubts:<id>`，并在 `doubts_standalone.duckdb` 记 `resolution_status=open`。
2. `merged`：题面与其他题实质重复，合并后不再单列；须结构工单与报批；台账记 `supplemented`＋`resolution_kind=structure`＋`resolution_ref=<approval 文号>`。
3. `retired`：题面对象已退役，不再单列；同上。

**不变量**：

- `skeleton` ⇔ 台账 `open/claimed`；`filled` ⇔ 有块；`closed/unresolvable` ⇔ 台账 `unresolvable`。
- `filled` 与 `closed` 互斥；`closed` 不得留块。
- 终态恒等式：`19,461 − merged − retired ＝ filled ＋ closed/unresolvable`；`skeleton ＝ 0`。
- 台账恒等式（S0 后）：`16,341 ＝ open 16,306 ＋ supplemented 34 ＋ unresolvable 1`。

## 十一、台账与路径契约

### 11.1 题号与路径

- 题号：`V{NN}.{chapter}.{section 末段}.{subsection 末段}`，如 `V64.4.10.2`；与 `design/exceptions` 的 `subsection_id` 一致。
- 树路径：`05-卷册大纲/第{NN}卷-*/第{C}章-*/{M}.{N}-*/{M}.{N}.{P}-*.md`。
- 批次号：内容 `supp-V{NN}-bNNN`；结构 `struct-V{NN}-bNNN`。

### 11.2 台账表头

`design/exceptions/V{NN}.tsv`（10 列）：

`subsection_id	kind	reason	proposal	status	resolution_kind	resolution_ref	resolution_claim_id	registered_date	date_src`

- `status` ∈ `open`／`claimed`／`supplemented`／`unresolvable`。
- `resolution_kind` ∈ `none`／`doc_mine`／`row_mine`／`exhausted`／`structure`。
- `resolution_ref`：doc_mine 为 `ref:<REF_ID>`；row_mine 为 `ROW_MINE:<source>` 或 `MAIL_INSIGHT:<msgid>`；exhausted 为 `doubts:<id>`；structure 为 approval 文号。

`design/supplement/V{NN}.tsv`（10 列）：

`subsection_id	kind	ref_id	claim_id	source_type	tier	block_type	batch	status	note`

- `status` 只允许 `claimed`／`supplemented`；其他值一律判非法。
- `block_type` 只允许 `D1`／`D2`。

`design/surplus/V{NN}*.tsv`（9 列）：

`rowmine_id	subsection_id	source_file	block_seq	orig_reason	disposition	judged_at	batch	host_subsection`

- `disposition` ∈ `归入`／`拒收`／`辑存`／`移出`／`删除`（空＝未判读）。

### 11.3 树内 YAML

`skeleton`／`filled` 用既有字段；`closed` 另须：

```yaml
status: closed
resolution_reason: unresolvable  # 或 merged / retired
closed_at: 2026-11-11
closed_ref: design/exceptions/V01.tsv#V01.2.8.1
```

## 十三、回滚五步与反模式

**回滚五步**（任一批失败）：

1. 删除本批新增块（逐块按锚定位，不整文件重写）。
2. 树内状态回退（filled→skeleton；closed→skeleton）。
3. 删除本批 `supplement` 行。
4. 台账状态回退（supplemented→open；unresolvable→open）。
5. claim／ref 保留（append-only），在批记注明“已建未用”。

**反模式**：

1. 禁整卷重建脚本（会丢“要点／史料／语义复核范围”非块层）。
2. 禁越线补证（非缺口题不得顺手填块）。
3. 禁半成品滞留（删块／改状态／删台账须同批完成）。
4. 禁旁路备份副本；留痕唯一靠 Git。
5. 禁以“存疑”代替查证，禁以 `closed` 掩盖未查。
6. **禁在 Task 8.2 内删除、改名或移动旧树任何一件**；旧树清理只能由 Task 9 在 §五 P5.5 五项放行判据全满足后执行，且须 ykla 明示。
