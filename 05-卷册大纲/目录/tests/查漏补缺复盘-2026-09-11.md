# 查漏补缺复盘：为何以前测试未发现对齐与隐藏问题

- 日期：2026-09-11
- 原因分类：测试盲区三层

## 1 为什么以前没发现“图标未对齐”

| 层 | 盲区 | 本轮修复 |
| -- | ---- | -------- |
| 断言层 | 此前的视觉几何断言只测“单个控件不溢出”，从未断言“多个右缘控件的右缘距视口相等”——对齐是相对关系，单控件断言天然失效 | 新增 `rightGaps` 全等断言（三控件） |
| 视口层 | 以前只有 393/402/412 三档手机 + 1024/1200/1920 桌面抽测；断点 820/1099/1140 附近（如 840、1080）从未覆盖 | 27 档全宽扫描（320→1920），含全部断点前后 |
| 认知层 | 工具钮新增时只改了它自己的 right 值，没查“同侧其他控件的右缘基线” | 同侧控件右缘基线统一 18px |

## 2 为什么“黄色字无法隐藏”被漏判

- 现象：`.src` 早就 `display:none` 默认隐藏——**测试安卓爪机用了 `body.notes-all`（全显）后的残留 localStorage 状态**，误报了“无法隐藏”。
- 教训：**状态残留是比代码缺陷更隐蔽的测试盲区**。任何持久化偏好（sme-mode/sme-notes/主题）在跨场景测试时必须先清 localStorage，否则上一步的状态污染下一步的断言。

## 3 已补的测试盲区 → 落地物

1. `fullsize_regression.mjs`：27 档全宽（320→1920，覆盖 560/820/1099/1140 全部断点前后）断言“右缘对齐 + 无横向滚动 + 无 JS 错误”；
2. `align_check.mjs`：三控件右缘相等 + 工具钮与主题开关纵向堆叠间隙断言；
3. `final5b.mjs`：手机默认阅读版黄字隐藏、桌面研究版默认断言。

## 4 结论

“任何网页尺寸”承诺现在由 27 档全宽 + 断点前后双保险覆盖；从此每轮修改后跑 `visual_final_test.mjs`（17 断言）+ `fullsize_regression.mjs`（27 宽度）双套件。
