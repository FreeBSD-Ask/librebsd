## 第一部分 六项质量指标（第三十八阶段）

### 1.1 总则：指标的对象与反数量铁律

**指标对象**：一章（或一卷）的**研究质量**——即该章历史主张的证据学处境，不是该章引用了多少条材料。

**反数量铁律**（用户任务书本阶段核心禁令"禁止以资料数量替代研究质量"的六条操作化）：

1. **计数不等于质量**：一条 L5 级直接代码证据的价值高于十条 L1 级相关性材料；指标计算一律先分层后计数，禁止裸计数。
2. **体量不等于密度**：350-400 万字规模（R1）的意义只在"单位篇幅的证据密度"——指标一律以**每千主张字数**或**每主张**为分母，不以章为粗单位平均掉内部空洞。
3. **重复引用只计一次**：同一 Original Document 在同一 Claim 下多次出现只计一次；同一来源的不同段落是不同 Evidence 但只算一条来源链（独立性按链计，见 EQ2）。
4. **回填前不封顶**：v3 基线的 47%/52%/30% 是审计事实，但指标测量时须先执行 13 号文 2.6 节的"锚定-文献失配专项核"，把映射缺口与真实空洞分开——用零证据假象惩罚章节，与用资料数量粉饰章节，是同一种错误的两个方向。
5. **指标不生产叙事**：六项指标只输出数字与等级，不输出"本章质量良好"类修辞结论；叙事性结论只能来自争议系统与审稿程序。
6. **指标可被更自反的指标超越**（P62）：本部分全部权重与阈值为操作性建构，首轮全量测量后按分布形态校准并登记修订记录（见 4.3）。

### 1.2 六项指标定义

> 通用记号：章 c 的主张集合 Claim(c)（来自 16 号文 claims 表，claim_type 词表：factual/causal/interpretive/evaluative/counterfactual/priority/motive）；证据集合 Ev(c)；来源链集合 SrcChain(c)；原始史料实体 OD(c)。全部指标可由 traceability.db + references_fulltext.db 半自动计算。

#### 指标一：Evidence Quality（证据质量，EQ）

**测量问题**：支撑本章主张的证据，平均处于哪一档证据等级？

**计算**：对每条已建链 Claim，取其支撑证据中的**最高等级**（一条主张的证据质量按最强证据定档，但若最弱证据与最强证据矛盾，按争议系统状态降档）：

| 等级 | 定义（沿用 07 号文 §2.3 五级证据） | 权重 |
| :--: | :--------------------------------- | :--: |
| L5 | 直接代码来源证据（commit/vendor/版权头链） | 1.0 |
| L4 | 当事人明确陈述（须配当时文本校验，P41） | 0.8 |
| L3 | 技术文档/论文明确记载 | 0.6 |
| L2 | 强技术对应但缺直接证明 | 0.3 |
| L1 | 仅历史相关性/相似性 | 0.1 |

```
EQ(c) = Σ(claim 最高证据等级权重) / |已建链 Claim(c)|      ∈ [0,1]
未建链 Claim 按 0 计入分母（惩罚断链，与 16 号文断链审计联动）
```

**等级判读**：EQ≥0.8 优；0.6-0.79 良；0.4-0.59 中（须列入回填观察）；<0.4 差（该章主张体系主要由弱证据承载）。
**反数量挂钩**：EQ 与引用条数无相关性设计——十条 L1 材料把 EQ 拉在 0.1，一条 L5 即达 1.0。

#### 指标二：Evidence Independence（证据独立性，EI）

**测量问题**：本章主张是否依赖单一来源链？（单源依赖=一损俱损的脆弱论证）

**计算**：以**独立来源链**为单位——两条证据独立当且仅当它们的 Source 不同作者、不同机构、非同一底本转引（判定标准沿用 13 号文 L4 级定义）。

```
EI(c) = 1 -（依赖单一来源链的 Claim 数 / |已建链 Claim(c)|）
```

另设**脆弱点清单**副产物：凡某主张的全部证据归于一条来源链，逐条列出（这是研究队列的直接线索源）。
**等级判读**：EI≥0.85 优；0.7-0.84 良；0.5-0.69 中；<0.5 差（章内过半主张单源，对应 13 号文 L4 级"只有单一来源"处境）。

#### 指标三：Historical Coverage（历史覆盖度，HC）

**测量问题**：本章应当覆盖的历史对象与时间轴节点，实际覆盖了多少？

**计算**：以问题树与对象表为分母（分母不是资料量，是"该章挂载的问题要求它覆盖什么"）：

```
HC(c) = (章内实际出现并登记的历史对象数 + 覆盖的时间轴节点数)
        / (该章挂载的问题树节点所要求的对象数 + 节点数)
```

**分母生成规则**：第 10 步章节装配时，每章的"应覆盖清单"由问题树节点自动导出并冻结——防止事后以"这不在本章范围"推诿。
**与信息黑洞的关系**（R2）：应覆盖而无史料可覆盖的对象/节点，不计入缺口而计入**显式黑洞登记**（正文以信息黑洞标注呈现）——HC 区分"未覆盖"与"已声明的黑洞"，前者扣分，后者不扣分但强制标注。

#### 指标四：Interpretive Coverage（解释覆盖度，IC）

**测量问题**：本章承载的历史解释是否齐全——该问题树节点下存在的主要解释方向，章内是否都有卡片承载？

**计算**：

```
IC(c) = 章内解释卡片覆盖的解释方向数 / 该章挂载问题节点登记的解释方向总数
```

解释方向来自 13 号文第 9 步解释卡片库：每个枝问题在卡片库登记时同时登记"已知解释方向枚举"（含被否定的方向——被否定方向须有否定卡片，"没人提过"与"提过但被证否"是两种状态）。
**反数量挂钩**：IC 测的是解释的**多样性与完备性**，与字数无关——一章可以写得很长而只承载单一解释方向（这正是"资料堆积"的解释学形态）。

#### 指标五：Controversy Coverage（争议覆盖度，CC）

**测量问题**：与本章相关的已知争议，是否全部在章内辨析字段呈现并登记于争议簿？

**计算**：

```
CC(c) = (章内呈现且正确登记的争议数) / (争议登记簿中与本章关联的争议总数)
```

**呈现合格判据**（对接 09 号文系统五）：每个呈现的争议须满足——双方立场具名、每方来源层级标注、暂定判断用自反句式（"编纂者基于……倾向……，但承认……"）、no_final_verdict 固定标注。缺一即该争议计为"未合格呈现"。
**特例**：关联争议总数为 0 的章，CC 记为"不适用"而非满分——"没有争议"本身须由 Skeptic 确认（可能是争议未被发现，见 13 号文 G8 关卡）。

#### 指标六：Primary Source Coverage（一手来源覆盖度，PS）

**测量问题**：本章主张中，有多大比例挂接到一手史料实体（Original Document 层的一手项）？

**计算**：

```
PS(c) = (有一手 OD 支撑的 Claim 数) / |已建链 Claim(c)|
```

一手判定沿用 R9 史料分层（lishidagang §1.2.1 五层级）：当事人邮件、commit、当时文档、采访原始记录为一手；事后回忆、转述、综述为二手及以下。**二手来源不被禁止，但 PS 测量其占比**——二手主导的章在 13 号文八级分类中落 L3，写作可继续但章末强制"史料透明"标注。
**与数据库的接口**：OD 实体的一手/二手属性登记在 traceability.db（16 号文 OD 层字段），references_fulltext.db 的 source_tier（51.9% 空值，见 02 号盘点）须在回填中补齐，否则该来源在 PS 中按"层级未定"计（不入分子）。

### 1.3 合成与报告

**章级质量卡**（六值向量，不做加权总分——六项不可通约，强行合成会掩盖偏科）：

```
QualityCard(c) = { EQ, EI, HC, IC, CC, PS }   各 ∈ [0,1] 或"不适用"
```

**短板规则**：任一项 <0.4 即触发该章**质量观察名单**；任两项 <0.4 或单项 <0.2，该章冻结定稿（与争议冻结同效力），进入回填或重铸程序。
**卷级与全书级**：按章数分布报告（中位数、四分位、短板章清单），不报告"卷均分"——平均数会掩盖连续崩塌（v3 审计：V17 连续 9 章双零，卷均分对此失明）。
**报告文件**：`重构2026/18-质量测量报告/QualityCards-{日期}.md`（章级向量表）+ `.json`（机读）+ 短板清单与分布图。

## 第二部分 三层书稿结构（第三十九阶段）

### 2.1 设计动机：一部书，三种读者，一条链

本书规模 350-400 万字（R1），读者至少三类：**通读读者**（要叙事连贯）、**研究读者**（要出处可查）、**未来编纂者/审计者**（要主张可重验）。单一文本层同时服务三者必然顾此失彼——正文塞满出处则叙事碎，出处尽省则不可查。三层书稿的解法：**同一历史内容在三个层上以不同形态存在，层间由引用回溯链（16 号文五层链）强制互连，任一层任一条目可双向追溯**。

### 2.2 三层定义

| 层 | 名称 | 内容 | 载体 | 读者界面 |
| -- | :--- | :--- | :--- | :------- |
| T1 | **正文层** | 叙事本身：五（六）段式章内结构（P48）、偶然性脚注、信息黑洞标注、章末结构性关联注记（13 号文 §3.4 规则 2） | GitBook 章文件（现行 `05-卷册大纲/第XX卷/第NNN章/` 的节文件体系） | GitBook 线性目录，唯一面向通读读者的界面 |
| T2 | **学术注释层** | 每个 Claim 的出处三元组（lishidagang §3.2.1：来源类型+获取方式+时间戳）、辨析字段、争议呈现、多版本并置、史观映射字段 | 章内脚注/尾注 + traceability.db 的 sentences/claims 表可读导出 | 研究读者的查核界面；以"注释卷"形态随正文出版 |
| T3 | **研究数据库层** | 五层链全量数据：claims（含类型与状态）、evidences（含 quote）、sources、original_documents、争议簿、影响主张库、语境快照、队列状态 | traceability.db（16 号文 §1.3）+ 各既有数据库（references_fulltext.db、资料数据库.db、doubts_standalone.db 等，经 OD 层打通） | 审计者与未来编纂者的重验界面；机读优先 |

### 2.3 层间追溯契约（核心规则）

三层不是三份独立文档，是**一条链的三个截面**。契约五条：

1. **向上可读**（T3→T2→T1）：T3 中每个已建链 Claim 必须能导出为 T2 的一条注释，且该注释必须锚定在 T1 的某个 Sentence（sentence_id 互指）。T3 有而 T1/T2 无的主张=未发表研究存货，允许存在但标记 `unpublished`，不计入书稿质量测量。
2. **向下可追**（T1→T2→T3）：T1 中每个 claim_bearer 型 Sentence 必须有 T2 注释；每条 T2 注释必须解析到 T3 的 Claim ID；Claim 必须挂 ≥1 条 Evidence 且 Evidence 附 quote（16 号文摘录完整规则）。任何一环断裂=断链，进入断链审计报告（16 号文 G 关卡）。
3. **改句必联动**：T1 语句修改 → text_sha256 变化 → 触发该句下全部 Claim 的复核（主张是否仍被原文承载）；T3 证据推翻 → 触发 T1 对应语句的修订义务（P50 回溯义务的执行通道）。三层同步是强制的，"只改正文不改库"视为断链。
4. **层间不越权**：T1 不出现数据库字段名、表名、ID 编码（面向读者的交付物，对接 CLAUDE.md 名称禁止使用规则与 R4 裁决精神）；T3 不出现叙事修辞（数据库只存命题与证据）。T2 是翻译层，唯一允许同时出现"读者友好表述+机读 ID"的位置。
5. **密度指标分层计算**：第一部分的六项指标在 T3 层计算；T1 层的对应健康度是**断链率**（断链 Sentence / 全部 claim_bearer Sentence）与**黑洞标注率**（应标注未标注 / 应标注总数），两者与 T3 指标联合构成交付质量门槛。

### 2.4 三层书稿的交付形态

| 交付物 | 构成 | 用途 |
| :----- | :--- | :--- |
| 读者版 | T1 全集（GitBook/印刷） | 通读 |
| 学术版 | T1 + T2（注释卷，随章对应） | 研究引用与查核 |
| 审计版 | T3 全库 + 断链报告 + 质量卡报告 | 验收、重验、后续编纂 |
| 复现包 | T3 库文件 + schema 说明 + 构建/查询脚本 + README | 第三方独立复现（学术惯例落点） |

### 2.5 与现行文件体系的迁移对接

现行 `05-卷册大纲/` 章文件内已含概述、节文件、DATA_VERIFY_BLOCK、"史观映射/辨析"字段——迁移规则：

1. 现有节文件的叙事段落 → T1；节内"史观映射/辨析/存疑"字段 → T2 的注释原料；DATA_VERIFY_BLOCK 数值 → 迁入 T3 作为 v0 基线数据（只读存档，不作为新指标数据源——其统计口径未分层，见 v3 审计对其局限性的记录）。
2. 既有 348/354 章中 30% 双零章在三层结构中的合法状态是：**T1 可暂存（标信息黑洞），T2 注释缺位须显式声明，T3 中该章 Claim 数为 0**——三层结构不强迫无米之炊，但强迫"无米"被如实登记。
3. T3 的库位置、schema、ID 方案一律以 16 号文为准，本文件不重复定义，只定义三层的截面关系与交付形态。

## 第三部分 最终验收标准映射：两类问题的系统应答路径

用户任务书要求为两类质疑设计**系统应答路径**——验收不是答辩词，是沿既定数据结构的查询程序。两类问题分别检验书稿的"立"与"舍"：立得是否稳（为什么认为 X 是转折），舍得是否明（为什么没写 Y）。

### 3.1 第一类问题："为什么认为 X 是转折？"（定性主张的验证路径）

**问题性质**：对书中任一关键定性（转折点、里程碑定性、动机归因、因果判断）要求给出理由。对应 Claim 类型：causal / interpretive / evaluative / motive / priority。

**应答路径（七步查询程序）**：

| 步 | 动作 | 数据结构 | 应答产物 |
| -- | :--- | :------- | :------- |
| 1 | 定位：X 的定性出现在 T1 何处 | sentences 表（按卷章节检索） | Sentence ID 列表 |
| 2 | 析出：该定性承载的 Claim | claims 表（claim_type + claim_text） | Claim ID 与其类型 |
| 3 | 举证：支持该 Claim 的证据 | evidences 表（含 quote） | 证据摘录清单 + 等级分布（EQ 输入） |
| 4 | 溯源：证据的原始实体 | sources → original_documents | OD 实体清单（一手/二手占比=PS 值） |
| 5 | 验独：来源链是否独立 | SrcChain 分组 | 独立链数（EI 值；单链即脆弱点） |
| 6 | 查争：该定性是否涉争议、反方是否呈现 | 争议簿（controversy_id 关联）+ 强制反对意见记录（16 号文 Phase 36） | 争议呈现状态（CC 值）；无反对意见记录的定性主张视为未过审 |
| 7 | 对门禁：定性措辞与证据等级是否匹配 | 07 号文 §2.3 措辞门禁表 | 越档即应答失败——L1/L2 证据支撑的"转折"定性本身违规 |

**应答合格判据**：七步全部可执行且第 3/5/6/7 步非空合格。任一步断链 → 该定性主张进入断链审计与再审队列（16 号文 requires_rebuttal 通道）。
**示范**：以第 13 号文 §3.3 示范链 T9（"USL 和解 → 法律/许可证问题成为中心议题"）为例——应答时沿 T9 边取 mechanism(m3)+证据指引，落至第 180 章协议原文翻译（一手 OD），再查争议簿中和解动因争议条目：路径完整即"为什么认为这是转折"成立。

### 3.2 第二类问题："为什么没写 Y？"（省略决策的验证路径）

**问题性质**：对书中未包含的对象/事件/人物/分支要求给出 omission 理由。传统修史的省略多为无意识偏差；本体系要求**每一次省略都是有记录的决策**。

**应答路径（六步查询程序）**：

| 步 | 动作 | 数据结构 | 应答产物 |
| -- | :--- | :------- | :------- |
| 1 | 查对象：Y 是否在历史对象登记表 | S03 对象表 | 在/不在。不在 → Y 从未进入研究视野，应答转入"发现程序"（见步 6） |
| 2 | 查问题：Y 挂载的问题树节点 | S02 问题树 | Y 回答什么问题；无挂载 → 省略理由=无叙述必要性（HN 删除测试全空），记录留档 |
| 3 | 查决策：Y 的处置记录 | S10b 新旧映射表 + HN 评分卡 | Y 被合并入哪章 / 降级 / 废除（附评分与裁决理由）——"没写"实为"并入他处写"或"评分后舍弃" |
| 4 | 查缺口：Y 是否因史料缺位未写 | Research Queue（章号+缺口类型+优先级） | 若 Y 在队列 → 应答="已知缺口，P× 级，检索线索如下"——省略是暂时的且可追踪 |
| 5 | 查黑洞：Y 是否以信息黑洞形态显式存在于 T1 | 正文黑洞标注索引 | 已标注 → 省略被如实呈现（R2 合规）；应标未标 → 应答失败，触发补标 |
| 6 | 发现程序：Y 完全不在任何记录中 | 全库反查（对象表/问题树/队列/争议簿四查皆空） | 承认遗漏，现场建对象条目 → 按 13 号文第 2 步规则决定挂载或入队；**禁止**以"不重要"口头打发四查皆空的 Y |

**应答合格判据**：Y 的省略必须落在步 2/3/4/5 之一的**书面记录**上；落在步 6 的必须当场建档。"没写 Y"的合法答案只有四种：**并入他章**（附映射记录）、**评分舍弃**（附 HN 卡）、**史料缺口**（附队列条目）、**显式黑洞**（附正文标注）。
**反偏差功能**：第二类问题是对 Anti-Bias 审查（lit-reviewer，Task #13）的验收接口——系统性省略某分支/地区/人群的偏差，会在六步查询中暴露为"步 3 评分理由空洞 + 步 4 队列缺位"的组合形态。

### 3.3 验收执行形态

1. **抽样验收**：验收方从全书随机（或定向）抽取 N 条第一类问题与 M 条第二类问题，按上述程序逐条执行；应答合格率即验收分数。建议首验 N=M=20，定向抽样须覆盖 v3 审计最弱卷（V9-V11、V15、V17）。
2. **全量自检**：第一类问题的步 2-4 可全自动跑（断链审计），步 6-7 半自动（措辞门禁扫描，07 号文附录 B 既有设计）；第二类问题的步 1-4 可全自动跑（对象/问题/映射/队列四库联查），步 5-6 人工。
3. **验收留痕**：每次验收问答全程落盘为 `重构2026/18-质量测量报告/验收记录-{日期}.md`（问题、七/六步执行结果、判定、失败项去向）——验收本身是可回溯对象，进入 traceability.db files/blocks 登记（16 号文 §1.3.1 已为此预留）。
4. **与最终汇编的接口**：验收合格率、六项指标分布、队列消化率三项进入 Task #21 最终汇编的"实施路线图·验收章节"。

## 补遗：第七项质量指标 JA（2026-08-12 增补，v3.1）

### JA: Justification Adequacy（解释选择论证完整度）

**依据**：新版编纂总纲 §7 验收问题四——"有没有其他解释？为什么选择这一解释？"

**测量问题**：本章在选择某一解释方向时，是否给出了选择理由？是否记录了被排除的解释及排除原因？

**计算**：
JA(c) = (有选择理由声明的被选解释数 + 有排除原因记录的被排除解释数) / (被选解释总数 + 被排除解释总数)

**判读**：JA≥0.8 优（解释选择透明）；0.5-0.79 中（部分缺乏论证）；<0.5 差（解释选择不透明——读者无法判断编纂者为何选此解释而非彼解释）。

**与 IC 的分工**：IC（解释覆盖度）测量"覆盖了多少解释方向"，JA 测量"选择某一解释的论证过程是否透明"——二者互补，不可互相替代。

**实施**：JA 作为第七项质量指标，与既有六项指标同批测量。任一项 <0.4 触发质量观察名单（与 §1.3 短板规则一致）。
