# 第〇部分 设计总纲

## 0.1 为什么本书特别需要反偏见审查

本书以 BSD 为主题。**主题选择本身即制造系统性引力**：一部 350-400 万字、以某一对象为主角的史书，其撰写者（无论人类还是模型）会天然地把叙述对象置于因果网络的中心、把与主题无关的世界压缩为背景板。用户任务书第十八阶段对此有明确判断："由于本书以 BSD 为主题，模型天然容易产生 BSD 中心主义。"

同时，本书的编纂思想（dagang.md / lishidagang.md）**已经预先与主流技术史叙事的四大组织方式决裂**：进步叙事、苦难叙事、天才叙事、斗争叙事（01-编纂原则清单.md 问题 5 归纳的八类禁用叙事）。这意味着本书不仅要防"偏袒 BSD"这一种引力，还要防整个技术史书写传统内嵌的另外八种引力——它们中的多数（Linux 中心主义、GNU 中心主义、商业决定论）结构上恰好是**贬抑或边缘化 BSD** 的。

## 0.2 对称性声明（本体系的第一原则）

**十类偏见中既有偏袒 BSD 的，也有贬抑 BSD 的。本审查体系是双向对称的，不是单向辩护。**

- 偏袒方向（夸大 BSD）：BSD 中心主义；
- 贬抑方向（贬低/边缘化 BSD）：Linux 中心主义、GNU 中心主义、商业决定论（以市场成败论历史意义时，市场份额较小的 BSD 自动失重）；
- 内部扭曲方向：Berkeley 中心主义（把 BSD 史压扁成一个机构的故事，使 CSRG 之外的分支与贡献者隐形）；
- 结构/时间方向（两个方向都可作用）：英雄史观、技术决定论、许可证决定论、后见之明。

**审查目标不是把"贬 BSD"的文本改成"挺 BSD"的文本，而是把两个方向都改成：对称、有条件、有史料、标注时间位置的叙述。** 这是 dagang.md 总纲 6（和解史观，非斗争叙事）与总纲 8（本体论上各方平等）的直接要求。

## 0.4 两套体系的关系（一句话）

Anti-Bias Review 是**向内**的审查（查本书自己的文本），Narrative Comparison Matrix 是**向外**的参照（登记外部世界如何叙述同一事件）。二者互为校验：矩阵登记了外部叙事的位置与动机，审查时就能判断本书文本是否不加标注地复制了某一外部叙事的立场；审查中发现的偏见，往往可以追溯到某一条未登记或未批判性处理的外部叙事。

# 第一部分 Anti-Bias 审查体系

## 1.0 使用方法与判定等级

每类偏见给出四个组件：**定义与本书语境含义**、**检测规则**（逐条可回答的检查问题）、**文本信号词**（触发警惕的表述模式）、**正例/反例**。

- **判定等级**（对齐 lishidagang.md §5.1.2）：通过 / 存疑 / 未通过。
- **信号词规则**：信号词只是触发器，命中≠违规；命中后须回到检测规则做语境判定。
- **引文豁免**：出现在直接引语、史料引文中的信号词不算作者偏见，但引文须标注来源层级（L1-L5）与说话人立场；引用第四层（事后叙述）材料中的必然性表述时，仍建议加偶然性脚注。
- **体系开放**：任务书要求"至少检查九类"。实践中发现第十类、第十一类偏见时，按本文格式增补并归档（见第三部分 3.3）。

## 1.1 偏见类型一：BSD 中心主义（方向：偏袒）

### 定义与本书语境含义

因为本书以 BSD 为主题，不自觉地把 BSD 的因果权重、影响范围和历史重要性放大：把 BSD 写成相关历史的主线，把非 BSD 行动者（ARPANET 社群、GNU、商业 UNIX 厂商、硬件厂商）写成背景板或注脚，甚至做无史料的夸大归因（"X 源于 BSD"）。

本书语境下的特殊含义：**书名是主题声明，不是重要性声明。** 总纲 8（多方平等）不只适用于 BSD 各分支之间，也适用于"BSD 整体"与更大的 UNIX/操作系统/互联网世界之间。本书写的是"从 BSD 看世界"，不是"世界围绕 BSD 转"。同时须警惕中心主义的受害形态："BSD 被掠夺/被亏待"的悲情叙事同样是把 BSD 置于世界中心（并违反总纲 6 和解史观）。

### 检测规则（检查问题清单）

1. 本章中 BSD 之外的事件（ARPANET 演化、GNU 计划、商业 UNIX 竞争、硬件降价）的因果是否被压缩为"为 BSD 做了铺垫"？
2. 外部行动者是否只在"与 BSD 互动"时才出场？他们是否拥有自身动机的独立叙述空间？
3. 影响声明（"X 源自 BSD""X 借鉴了 BSD"）是否有第一/二层史料（代码对比、邮件、commit、当事人即时陈述）支撑，还是无注推断？
4. 是否出现"我们/我方/我们 BSD"式的主体位置？（本书不是 BSD 的辩护人）
5. 是否出现"BSD 被掠夺/被亏待/被夺走荣誉"的受害化表述？（受害化是中心主义的镜像，且违反总纲 6）
6. 涉及 BSD 的章节之外，是否为外部对象（Multics、GNU、Linux、商业 UNIX）保留了不按 BSD 需求裁剪的独立叙述？
7. 当使用"操作系统世界""业界"等全称框架时，参照系是否被悄悄替换成了 BSD？

### 文本信号词

"真正的正统""唯一的继承者""BSD 催生了（无史料）""没有 BSD 就没有 X""被掠夺""被窃取""抄袭 BSD""BSD 的胜利""为 BSD 讨回公道""BSD 终于被承认""整个业界都（实际只有部分）"

### 正例（合规）与反例（违规）

> **反例**："Linux 的网络栈全部学自 BSD，可以说没有 BSD 就没有今天的互联网。"
> （问题：无史料的全称归因 + 把互联网史压缩为 BSD 影响史）

> **正例**："Linux 早期吸收了 BSD 套接字 API 的接口设计〔注：此处引 commit/邮件/当事人陈述，标明层级〕。这一代码与设计的流动是分离聚合循环的一个相位——同期 Linux 社区也在独立发展自身的驱动与调度实现。互联网基础设施的形成是多方行动者共同作用的结果，BSD 的贡献是其中之一。"

## 1.2 偏见类型二：Linux 中心主义（方向：贬抑/重要性倒置）

### 定义与本书语境含义

因为 Linux 后来取得了巨大的市场与生态成功，**用事后知道的结果倒排 1990 年代的历史重要性**：把 Linux 写成自由/开源操作系统史的主线、把 BSD 写成铺垫或失败者，甚至以 Linux 的时间节点做分期坐标。

本书语境下的特殊含义：这是总纲 18“朝花夕拾”的直接违反——"一个技术、一个项目、一个人的价值，往往在其消亡之后才被认识……主体的时间位置决定了'什么看起来重要'"（01-清单问题 7 第 10 条）。1991-1996 年间，Linux 与 BSD 的相对重要性是当时无人能知的开放问题；标准 5 第 3 款要求"若比较 BSD 与 Linux，对称呈现双方立场和理由，不简单褒贬"；总纲 6 编纂指令明确禁止"Linux 战胜 BSD"式斗争叙事。

### 检测规则（检查问题清单）

1. 1991-1996 年的两个系统是否被**对称呈现**（各自的条件、选择、理由），还是 Linux 为主角、BSD 为背景？
2. 是否出现"输给 Linux""错失良机""被 Linux 击败"等败局修辞？（本书的 BSD 相对收缩是"循环相位"，不是战败——总纲 6）
3. "如果 BSD 没被诉讼拖累，Linux 可能不会出现"式反事实，是被当作**lament（哀叹/论证）**还是当作**偶然性反事实（§2.3.1 第 6 段，标注"不是为了证明必然，而是为了揭示偶然"）**？前者违规。
4. 分期与章序是否以 Linux 节点为界（"前 Linux 时代/后 Linux 时代"）？本书分期以 BSD 史的分离聚合相位为准（§1.3.2）。
5. 2000 年后 BSD 史（OpenSSH、PF、安全审计、Netflix 等）的叙述密度是否与同期 Linux 史相称，还是被压缩成"Linux 时代的余波"？
6. 比较是否只选 Linux 占优的指标（用户数、生态），而无视双方目标函数不同（可移植性/安全性 vs 单平台生态扩张）？
7. Linux 的成功是否被写成单因（天才/时机/品质）？对 Linux 同样必须执行偶然性标准 4——对别人家的历史也要反必然化。

### 文本信号词

"输给 Linux""错失窗口期""被 Linux 的光芒掩盖""Linux 取代了 BSD""失败者""前 Linux 时代""Linux 时代""历史选择了 Linux""Linux 的胜利""如果 BSD 没被诉讼拖累……（作为结论而非脚注）"

### 正例（合规）与反例（违规）

> **反例**："1993 年，BSD 阵营还在诉讼泥潭里内耗，Linux 抓住了历史机遇。最终，BSD 输给了 Linux。"
> （问题：败局修辞 + 斗争框架 + 事后结果倒灌 + "历史机遇"必然化）

> **正例**："1993-1994 年间，BSD 社区处于诉讼冻结状态，Linux 社区则在同期以另一条路径积累用户与开发者。两个社区面对不同的条件（法律风险 vs 硬件时机 vs 工具链可得性）做出了不同选择。从当时当事人的视野看，两者前景均属未知〔偶然性脚注：今日之格局是事后分布，非当时可知〕。"

## 1.3 偏见类型三：GNU 中心主义（方向：边缘化）

### 定义与本书语境含义

把自由软件的全部历史解释为 GNU 运动的展开：BSD 的共享文化被写成 GNU 理念的下游或回声，BSD 行动者的动机被默认"受斯托曼影响"，许可证故事被写成"GPL 为主角、BSD 许可证为变体"。

本书语境下的特殊含义：CSRG 的磁带共享文化成形于 1970 年代末的学术环境，早于 GNU 计划（1983 年宣布）；两者关切有重叠但各有独立起源。把 BSD 史挂到 GNU 叙事之下，既是经验错误（违反标准 6 经验优先：动机须有同时代史料），也是总纲 13 的违反——许可证与自由软件运动应按**利益分配方案**分析，而不是按"理念传播史"叙述。同时防止反向偏差：以 Berkeley 为中心无视 GNU 的实际作用，同样违规。

### 检测规则（检查问题清单）

1. BSD 的共享/发布文化之起源，是否只经由"GNU/自由软件理念"来解释？（须检查 1976-1983 年 CSRG 自身的学术与制度语境）
2. BSD 人物的动机是否被写成"受自由软件理念影响"？如是，须有第一/二层史料；否则改为"动机待考"或呈现当事人自己的说法。
3. 许可证故事是否以 GPL 为叙事主角、BSD 许可证为"宽松变体"？（总纲 13：每种许可证是一种利益分配方案，无主从）
4. GNU 自身的曲折（HURD 长期未完成、GNU 工具被 BSD/Linux 双方采用）是否获得同等密度的呈现，还是只作为背景？
5. "自由软件"章节的代表人物是否只有斯托曼一人？
6. "GNU 工具 + Linux 内核"的流行叙事框架，是否遮蔽了"完整 BSD 系统自带用户态"这一事实？
7. 术语使用是否历史化："free software""open source"等词在所述年代是否已被当事人使用？（防止用后来的词倒灌当时的自我理解——问题 7 第 9 条）

### 文本信号词

"GNU 运动开启了（一切）""没有斯托曼就没有自由软件""BSD 的共享是 GNU 精神的回声""自由软件理念传到伯克利（无史料）""GNU 阵营 vs 商业阵营""开源世界是 GNU 的遗产""BSD 开发者受到自由软件思想的感召"

### 正例（合规）与反例（违规）

> **反例**："在斯托曼发起的自由软件思想影响下，伯克利的开发者们逐渐接受了共享软件的理念。"
> （问题：理念传播史倒灌 + 无史料动机归因 + 时间错误：CSRG 共享实践早于 GNU 计划宣布）

> **正例**："CSRG 的磁带发布与共享实践成形于 1970 年代末的大学环境〔注：release notes / 信件，L2-L3〕，早于 GNU 计划宣布（1983）。两种传统在 1980 年代后半期开始互动（如 GNU 工具进入 BSD 磁带、围绕版权与分发的讨论），但各有独立起源；其动机差异在许可证的利益分配结构上表现得最清楚（总纲 13，详见第 X 卷）。"

## 1.4 偏见类型四：Berkeley 中心主义（方向：内部扭曲）

### 定义与本书语境含义

把"BSD 的历史"简化成"Berkeley 一个机构的故事"：CSRG 之外——386BSD 的 Jolitz 夫妇、BSDi 的商业尝试、四个现代分支各自的社区、衍生系统（macOS 的 BSD 层、嵌入式 BSD 等）、以及所有非 Berkeley 出身的贡献者——全部沦为脚注。

本书语境下的特殊含义：这是总纲 8（多方平等）与总纲 10（动手者叙事）的复合违反。01-清单综合推断明确指出："任何'正统继承'式叙述均违反总纲 8 与标准 5"——Berkeley 是 BSD 史的第一次大聚合场所，但不是血统颁发机构。本书的循环结构（总纲 4）恰恰要求把"分离之后各分支的独立生命"写成与 Berkeley 时期同等重要的相位，而不是把 1995 年 CSRG 解散当作 BSD 史的"高潮已过"。

### 检测规则（检查问题清单）

1. CSRG 解散（1995）之后，本章的叙事密度是否断崖式下降？（检查是否存在"后 Berkeley 时代是余波"的隐含判断）
2. 386BSD、四大现代分支、衍生系统是否各自拥有独立章节与独立的因果叙事，还是只在"与 Berkeley 遗产的关系"中出现？
3. 人物传记是否集中于 Berkeley 出身者？非 Berkeley 人物（Jolitz 夫妇、NetBSD/OpenBSD/DragonFly 的创始人群、无数非 committer 贡献者）是否满足标准 12（每章至少 2 位非核心人物及具体行动）？
4. 是否出现"Berkeley 正统""CSRG 嫡系""正统血脉"类表述？（标准 5 第 2 款明令禁止"正统/旁支"）
5. 技术贡献归属是否一律归于 Berkeley？（如把社区后续改进记在 CSRG 名下）
6. "BSD"一词的使用范围：叙述 1995 年后事件时，是否仍用"BSD"统称而不指明具体分支/社区，从而把多中心压回单中心？
7. 机构叙事是否遮蔽了个人与小组的具体行动？（CSRG 的决定落实到具体的人、邮件、补丁了吗？）

### 文本信号词

"Berkeley 正统""CSRG 嫡系""正统血脉""伯克利的遗产（作为后续一切的总因）""后 Berkeley 时代（暗示衰落）""BSD 黄金时代（定位在 CSRG 期）""CSRG 之后的 BSD 们""学院派的延续"

### 正例（合规）与反例（违规）

> **反例**："随着 1995 年 CSRG 解散，BSD 的黄金时代结束了，此后各分支不过是 Berkeley 遗产的看守者。"
> （问题：机构中心 + 黄金时代修辞（进步/衰落叙事）+ 把四个分支写成看守者，违反总纲 8、标准 5）

> **正例**："CSRG 于 1995 年完成最后一项发布后解散〔注：release/公告，L3〕。这标志着分离聚合循环的一次相位转换：此后的 FreeBSD、NetBSD、OpenBSD（及更晚的 DragonFly BSD）各自建立治理结构、发布节奏与技术路线，彼此之间以代码共享与人员流动维持聚合（总纲 4）。各分支的历史从此起笔，而非作为 Berkeley 时期的尾声。"

## 1.5 偏见类型五：英雄史观（方向：结构遮蔽，双向）

### 定义与本书语境含义

把集体技术劳动写成少数天才的创造：把团队工作归于单一个体，用"天才/远见/大师"解释技术突破，按"重要性"给人物分级排序。

本书语境下的特殊含义：§3.1.2 明令"人物不神化——不将个体叙述为'天才''远见卓识者''时代英雄'"；dagang.md §4.2 禁用叙事表第二条给出了标准替代句式。总纲 10 要求"动手者叙事"：历史由"动手去做"的老实人推动，且"观察者通过观看参与了事件的构成，记录者通过记录参与了历史的创造"——英雄史观的对称反面不是"无名群众"，而是**具体的、有名字的普通行动者与记录者的群像**（标准 12）。英雄史观在两个方向都运作：既造神（"McKusick 的天才"），也造魔（"de Raadt 的疯狂"）——把治理冲突写成性格剧，同样违规。

### 检测规则（检查问题清单）

1. 技术突破的解释是否落在个人品质（天才、直觉、远见）上？如是，能否替换为条件分析（可用资源、前人代码、制度环境、偶然时机）？
2. 复数贡献者的工作是否被单数主语化（"他发明了"而非"团队在……中完成了"）？
3. 人物出场是否只写台前人物？本章是否满足标准 12（≥2 位非核心贡献者 + 具体行动描述）？
4. 是否按"重要性"给人物分级（P0/P1/P2 进入正文）？（分级只可用于研究资源分配，禁止进入正文）
5. 人物评价是否道德化/性格化（"疯狂""偏执""高尚"）？治理冲突是否被写成性格冲突而非利益与制度冲突（总纲 13）？
6. 是否出现"即使没有他，也会有别人"式替代必然论？（标准 4 第 3 款明令禁止——独特性原则：偶然行动一旦发生即不可替代）
7. 对负面人物的处理是否对称？（不为尊者讳，也不为贬抑而造"反英雄"）

"天才""远见卓识""大师""灵魂人物""一人之力""凭一己之力""时代英雄""开山鼻祖""疯狂的天才""偏执造就伟大""没有他就没有 X""他一手缔造""传奇人物"

### 正例（合规）与反例（违规）

> **反例**："凭借天才般的直觉，Joy 为 BSD 引入了 vi 和虚拟内存，一手奠定了 BSD 的技术基础。"
> （问题：天才归因 + 单数化团队工作 + "一手奠定"夸大）

> **正例**："Bill Joy（1954- ，在世）在 1970 年代末为 2BSD 贡献了 vi 与相关工具〔注：release notes/man pages，L1-L3〕。这些工作建立在前人代码与 PDP-11 社区已有的积累之上；同期 CSRG 的其他成员承担了系统其余部分的大量改造。Joy 后来离开 Berkeley 参与创办 Sun Microsystems，是 1980 年代 BSD 人才流动（聚合的另一形式）的个案之一。"

## 1.6 偏见类型六：技术决定论（方向：结构遮蔽，双向）

### 定义与本书语境含义

认为技术属性自然导致社会结果："因为 X 更先进/更优雅，所以 X 赢了"；用技术优劣解释市场与生态结果；把技术更替写成自然演进而非权力与利益的重排。

本书语境下的特殊含义：这是 dagang.md 的三重违反——总纲 3（不存在进步，只有权力再分配：技术更替伴随维护者更替、话语权转移、社区重组）、总纲 5（偶然性优先："UNIX 的成功是必然的，因为它简洁"正是被点名的反面教材）、总纲 11（良币结构论：BSD 在市场中的位置是形式主义化市场的**结构性选择**，不是"劣胜优汰"的道德悲剧，更不是"技术不够好"的自我归因）。§3.1.5 明确："商业成功不叙述为'技术优秀的结果'。"

### 检测规则（检查问题清单）

1. 某个技术/系统的扩散、采用或收缩，是否被归因于其技术品质（简洁、优雅、先进、健壮）？如是，须改写为多因素分析（制度、法律、商业、社区、偶然条件）。
2. "更先进/更优雅/更完善"是否被用作解释项？（标准 3：技术更替呈现为形式主义配置的转换）
3. BSD 在市场中的相对收缩，被解释为"技术不够好/不够努力"（自我归因），还是按总纲 11 的结构分析（形式主义化市场的选择机制）？
4. 商业 Unix/Linux 的扩张是否被写成"技术自然演进"？（应分析召唤机制：品牌、生态、标准如何召唤用户——总纲 11）
5. 工具更替（CVS→SVN→Git、make→其他构建系统）是否写成"进步"而非"权力再分配"（维护者更替、话语权转移）？
6. "安全""性能"等技术指标是否被当作天然的善？（应呈现为特定社区在特定条件下的目标选择——标准 6 经验优先）
7. 反方向同样检查：是否出现"技术决定社会形态"的镜像（"互联网技术必然带来开放社会"类）？

### 文本信号词

"更先进""更优雅""技术上更胜一筹""技术优势决定了""因为更健壮所以胜出""自然演进""技术规律""技术潮流""先进取代落后""性能决定命运""架构决定命运""更好的技术理应获胜"

### 正例（合规）与反例（违规）

> **反例**："Linux 之所以战胜 BSD，是因为其内核架构更先进、迭代更快——技术优势最终决定了市场格局。"
> （问题：技术决定论 + 斗争叙事 + 事后结果倒灌三重叠加）

> **正例**："Linux 与 BSD 在 1990 年代的不同处境，是法律条件（USL 诉讼冻结了 BSDi 与 4.4BSD 的发布节奏）、硬件时机（x86 降价与 386 的可得性）、工具链条件（GCC 的可得性）与社区组织方式差异的聚合结果〔注：各条件分别标注史料〕。把差异归结为'内核优劣'，是把多重偶然条件压缩为单一技术解释——本书拒绝这种压缩（标准 4）。"

## 1.7 偏见类型七：商业决定论（方向：贬抑，双向）

### 定义与本书语境含义

以市场成功为技术历史意义的唯一度量："赢了市场才配被写进历史"；把商业成败当作历史分期的坐标；把未被市场选中的系统写成无足轻重。

本书语境下的特殊含义：总纲 8 编纂指令直接命中："FreeBSD 不因为用户多就比 NetBSD'更成功'——'成功'的衡量标准本身就是形式主义的建构（用用户数量衡量操作系统的成功=用形式主义化的指标替代对事物本身的判断）"。总纲 11 进一步要求：市场分析必须呈现"召唤机制"（品牌、生态、标准）与"取而不回"的结构性特征（卷 14 关键张力），而不是道德评判。对 BSD 史，商业决定论的具体伤害是双重的：对外把 BSD 写成"市场失败者"，对内把 FreeBSD（商业化程度较高）凌驾于 NetBSD/OpenBSD/DragonFly 之上——后者是标准 5 的等级制变体。

### 检测规则（检查问题清单）

1. "成功"一词出现时，其度量标准是什么？（用户数/装机量/营收=形式主义指标，须标注为"以 X 指标衡量"而非裸用）
2. 未商业化的系统（早期 NetBSD、DragonFly BSD、各类嵌入式 BSD）是否获得了与其史料丰度成比例的叙述篇幅？（标准 5 第 4 款：篇幅按史料丰度，不按"重要性"）
3. FreeBSD 是否因商业化程度高而在卷章分配、笔墨密度上获得隐性优先？
4. 商业采用（Apple、Netflix、Sony 等）是否被写成"BSD 技术优秀的证明"？（§3.1.5 明令禁止；应写成结构性互惠/不对称分析）
5. BSDi、商业 Unix 的失败是否被写成"市场自然淘汰"？（应分析具体条件与利益结构）
6. "开源商业化""商业可持续"是否被当作天然目标？（须呈现为特定时期特定群体的目标选择）
7. 反方向：是否出现"商业即堕落"的镜像价值判断？（本书不做道德评判，只做结构分析——总纲 11"这不是道德判断，而是结构描述"）

### 文本信号词

"市场选择了""商业上失败""没有商业价值""市场验证了""用户数证明""成功的产品""失败的操作系统""被市场淘汰""叫好又叫座""商业价值不高（所以不重要）""主流市场不认可"

### 正例（合规）与反例（违规）

> **反例**："尽管 NetBSD 技术精湛，但商业上的失败注定了它只能是小众系统，历史意义有限。"
> （问题：商业决定论 + "注定"（违反标准 4）+ 以市场指标裁剪历史意义（违反总纲 8））

> **正例**："NetBSD 的'支持尽可能多平台'策略，最初是对 386BSD 局限于 i386 架构的技术反应〔注：早期邮件/release notes，L1-L2；此处为事后总结，非当时'远见'——§2.3.2〕。以装机量衡量，NetBSD 的份额不大；但'可移植性优先'的目标函数本身构成一种独立的历史形态，其贡献者网络、移植实践与文档构成了不可还原的记录（总纲 8：'成功'指标是形式主义建构）。"

## 1.8 偏见类型八：许可证决定论（方向：倒灌，双向）

### 定义与本书语境含义

把后来的许可证政治（GPL vs BSD 之争、"开源 vs 自由软件"话语、企业合规焦虑）倒灌到早期历史：假定 CSRG 时代的人们已经在按"许可证阵营"思考；把一切技术史事件都解释为许可证选择的后果；把许可证之争还原为"自由理念的冲突"。

本书语境下的特殊含义：总纲 13 编纂指令："分析 BSD 许可证与 GPL 之争时，不将其还原为'自由理念的冲突'，而是揭示每种许可证背后的利益分配方案。"01-清单问题 7 第 9 条明确："'自由'（许可证语境）不得倒灌——不得用今日的'开源自由'话语倒灌当事人的实际利益考量。"同时须注意历史事实：BSD 许可证的条款本身在历史上被修改过（4.3BSD-Reno 时期为应对 USL 诉讼风险而调整措辞），许可证不是超历史的理念载体，而是随利益格局变化的文本。

### 检测规则（检查问题清单）

1. 早期事件（1990 年以前）的分析中是否出现"开源""自由软件""copyleft"等当时当事人未使用的词汇作为解释框架？（术语须历史化）
2. CSRG 的发布决策是否被解释为"选择了宽松许可证理念"？（应还原为大学法务、AT&T 许可条件、磁带分发惯例等当时的制度约束）
3. 1992 年后的分支选择是否被事后简化为"BSD 许可证 vs GPL 的选择决定了命运"？（多因分析：诉讼、硬件、社区组织、时机）
4. 许可证比较是否以"自由理念的冲突"框架呈现？（须改为利益分配方案分析：每种许可证把利益分配给谁、排除谁）
5. "宽松"与"copyleft"是否被赋予道德色彩（宽松=更自由/更好，或反之）？（须去道德化）
6. 是否出现"BSD 许可证的伟大/缺陷在于……"式本质化表述？（许可证文本是被修改的历史对象）
7. 反方向：是否出现镜像倒灌——把早期 AT&T 许可的商业逻辑用今天的"开源商业模式"话语解释？

### 文本信号词

"开源精神从一开始就（倒灌）""BSD 选择了自由（道德化）""copyleft 阵营""开源世界""宽松许可证的胜利/失败""GPL 污染""自由 vs 专有的斗争（早期语境）""许可证决定了两者的命运""开源理念的胜利"

### 正例（合规）与反例（违规）

> **反例**："从一开始，BSD 社区就秉持着开源自由的许可证精神，这与后来 GNU 的 copyleft 理念形成了鲜明对比，两种自由观的冲突塑造了此后的操作系统史。"
> （问题："开源"词汇倒灌 1970 年代 + 理念冲突框架（违反总纲 13）+ 许可证决定论）

> **正例**："CSRG 磁带在 1970 年代末至 1980 年代的分发，受制于 AT&T 的源码许可条款与大学的分发惯例〔注：license 文本/通信，L1-L3〕。BSD 许可证的条款在 1989-1990 年间经历修改，与 USL 诉讼风险直接相关〔注：相关公告/邮件，L2-L3〕。把这两种许可证安排理解为'理念的冲突'，会遮蔽它们作为利益分配方案的实际功能：BSD 许可证将再分发利益开放给所有使用者（含不以源码回馈的商业方），GPL 则将再分发限制在愿意回馈源码的链条中（总纲 13）。"

## 1.9 偏见类型九：后见之明（方向：时间扭曲，双向）

### 定义与本书语境含义

用今天知道的结果解释过去：把事后才知道的格局当作当时的已知条件，把当事人的选择用其结果来辩护或谴责，把今天的术语、价值排序、问题意识投射到历史现场。

### 检测规则（检查问题清单）

1. 该段叙述中，作者知道而当事人不知道的信息，是否被当作当事人的行动理由？
2. "标志""新纪元""转折点"是否标注了回溯性脚注？（§2.3.2 标注示例二：4.4BSD-Lite 在当时是诉讼压力下的应急产物，参与者并未视之为"新纪元"）

4. 问题意识是否倒灌："当时人们为何没做 X"（X 是事后才出现的问题）类问题是否出现？
5. 分期与标题是否使用了事后坐标（"前 XX 时代""XX 前夜"）？
6. 人物传记是否用其最终命运解释其早期选择？
7. 引文检查：是否用后来的回忆录（第四层）作为当时心态的主要证据，而缺少即时史料（第一/二层）佐证？
8. 反方向自检：作者是否把**本书的价值判断**（如"边缘位置生产独特品质"）投射为当事人的自我理解？（当事人未必如此自觉——须标注为编纂者的分析而非当事人的意识）

### 正例（合规）与反例（违规）

> **反例**："1991 年 Torvalds 宣布 Linux 时，没有人意识到，这个爱好项目注定会超越所有 BSD，成为自由操作系统的最终赢家。"

## 1.10 偏见类型十：主体错置（方向：归因错置，双向）

### 定义与本书语境含义

**主体错置**：把本属某一历史主体的行为、成就、资产或责任，记到另一主体名下。本书的四类历史主体为——**操作系统（制品）／项目（共同体事业）／基金会（法人）／团队与职位（授权结构）**（判准见 `00-编纂规则与格式规范/01-规则/写作规则.md`“历史主体四分与称谓纪律”，理论件见 `00-编纂规则与格式规范/04-史学方法论/09-对象与主体：本书历史书写的双层坐标.md`）。

本书语境下的三种典型形态：①**制品／项目错置**——把项目共同体的决策、人事或资源写作“系统”的行为（如“FreeBSD 系统决定采用 Clang”）；②**项目／法人错置**——把法人资产、财务或法律安排写作项目的成就（如把基金会的筹资与资助写作“项目完成了移植”）；③**机构／个人错置**——把个人行动写作机构行动，或反之（如把 Dillon 的个人路线选择写作“项目决定”）。

本类与类型五（英雄史观）**互补而非重复**：类型五防**夸大个体**，本类防**错置主体**——同一句话既不神化个人、也不混淆主体，方为合规。

### 检测规则（检查问题清单）

1. 该句的行为主体是谁？落笔前先答**判准三问**（主体／变迁单位／档案归属）。
2. “项目／系统／基金会／团队”四词是否指同一实体？若句内出现两词互代，是否为有意的对照（若是，须显式说明两者关系）？
3. 资产、财务、注册、商标类陈述，其主体是否为**法人**？
4. 版本、发行、代码树类陈述，其主体是否为**制品（操作系统）**或**项目**（须辨明）？
5. 任免、选举、职权类陈述，其主体是否为**团队与职位**？

### 文本信号词

“系统决定／系统选择／操作系统宣布”（涉决策面）｜“项目注册／项目财务／项目商标／项目资产”（涉法人面）｜“基金会开发了／基金会发布了 X.Y 版”（涉制品面）｜“项目任命／项目改选”（涉职位面）｜“FreeBSD 项目发行了”（分发主体不明）。

### 正例（合规）与反例（违规）

> **反例**：“2000 年 FreeBSD 基金会的成立使项目得以资助更多移植工程，项目当年发布了 4.0。”（法人、项目、制品三主体混作一句，“项目发布”主体不明。）

> **正例**：“2000 年 FreeBSD 基金会成立（法人侧节点，见第四十五卷第 2 章 2.2）；此前项目的资源形态见同卷第 2 章 2.1。4.0 版由发布工程团队于 2000-03 释出（制品侧，见第二十一卷第 4 章）。〔法人／项目／制品三主体分列〕”

# 第二部分 Narrative Comparison Matrix（叙事对照矩阵）

## 2.0 设计意图

用户任务书第十九阶段要求："主动收集并比较以下叙事……建立 Narrative Comparison Matrix，研究同一个事件为什么会产生不同解释。用户原话：'这比简单增加参考书数量更有价值。'"

本部分的理论根据是 lishidagang.md §1.2.3c："同一事件在不同史料中呈现不同面貌——这不意味着'有一个真实的版本被某些史料扭曲了'，而意味着'不同的史料本身就是不同的形式主义建构'。我们的任务不是找出'真相'，而是呈现这种多面性本身。" 矩阵就是把"多面性本身"制度化为可填写、可归档、可对照的工作表格。

**矩阵不裁决谁对谁错。矩阵的功能是：**（a）登记每个叙事源的位置与动机，使其偏见可被命名；（b）在章节撰写前预先暴露"此事必有分歧"，防止作者无意识地采纳单一叙事；（c）为第一部分的偏见审查提供外部参照——正文若不加标注地复制某叙事源的立场，即可被检出。

## 2.3 矩阵模板

**矩阵 M = 事件（行）× 叙事源（列）× 解释单元格。** 单元格为最小记录单位，格式如下：

```markdown
### 单元格 [E#事件] × [N#叙事源]

- **解释要点**：该叙事源对此事件说了什么（1-3 句，忠实转述，不改写）
- **代表载体**：具体到书/页/文档/邮件（真实存在，标注层级 L1-L5）
- **解释动机**：该叙事源为什么这样说（1-2 句，归入 2.6 的归因分类）
- **归因编码**：[利益/时间/信息/框架]（可多选，见 2.6）
- **本书处理**：[采纳（须标位置）/ 对照呈现 / 拒绝（说明理由）/ 存疑待查]
```

填表操作守则：

1. **忠实转述优先**：先如实记录该叙事源怎么说，再分析其动机；禁止在"解释要点"里夹带本书评判（评判只进"解释动机"与"本书处理"字段）。
2. **缺格也是信息**：某叙事源对某事件**沉默**（从不提及、或一笔带过），应填"沉默/略过"并分析沉默的动机——沉默往往比言说更能暴露立场（与"谁没有说话"方法论同构）。
3. **每格必问**：若该叙事源写于事件多年之后，其解释中是否含有当时不可知的信息？（与偏见类型 9 的检查规则 7 联动：引文层级检查）
4. **归档**：填好的矩阵单元格归档至 `08-核查报告与多轮复核/09-比较史研究/叙事对照矩阵/E#事件编号.md`（每事件一文件），文件名即事件编号，便于章级"史观映射"字段反向引用。

## 2.4 示范填充一：E7 USL v. BSDi 诉讼与和解（1992-1994）

> **示范说明**：以下单元格展示矩阵的填法与深度。"解释要点"记录的是各叙事源的**典型立场倾向**，所引事实（诉讼时间线、和解结果等）在正式章节撰写时须逐条按五层级核验并注明出处；此处标注〔核验〕者为示范中未做现场核验、正式填表时必须补证的项。事件基线事实（供对照）：BSDi（Berkeley Software Design, Inc.）基于 Net/2 推出商业产品 BSD/386；USL（UNIX System Laboratories，AT&T 子公司）于 1992 年起诉 BSDi 及加州大学董事；加州大学提出反诉；案件于 1994 年初和解，多数代码被认定不受 AT&T 版权约束，少数文件需修改或移除；4.4BSD-Lite 作为"无 AT&T 代码"版本于 1994 年发布〔以上时间线核验〕。

3. **回写正文**：本书写 USL 诉讼的章节，须按 §4.4e 做四维（技术/法律/社区/商业）整合，并在"辨析"字段呈现上述三种矛盾解释及其归因——这就是矩阵对正文的直接产出。

## 2.5 示范填充二：E11 Linux 与 BSD 的命运分化（1991-1996）

> **事件界定**：1991 年 Linux 内核发布时，BSD 系已有十年积累与完整系统；到 1996 年，Linux 在用户与开发者规模上显著超过各 BSD 分支，且此差距持续扩大。"命运分化"是**事后描述**——矩阵的首要任务正是拆解各叙事源如何解释这一分化，以及哪些解释把事后结果倒灌成了事前原因。

**示范分析：**

1. **解释的考古层次**：E11 的解释可以分三层——（i）条件层（硬件时机、工具链可得、法律冻结：可核验、可并置）；（ii）模式层（集市胜大教堂、许可证决定论：框架性概括，须标注为理论建构）；（iii）命运层（"Linux 注定赢"：事后倒灌，拒绝）。矩阵的价值是让三层不混淆。本书正文只允许（i）直接陈述，（ii）作为被标注的理论呈现，（iii）进入反例清单。
2. **对称性检查**：本事件最易滑入偏见类型 2。填表后自检：N4/N5/N6 三格是否各自成篇（不是作为 N8 的陪衬）？本书相应章节的篇幅分配是否按史料丰度而非按分化结果？
3. **偶然性脚注落点**：1993 年时点——"此刻没有任何记录显示当事人认为 Linux 将超过 BSD"——应作为本章偶然性脚注的标准落点（标准 4）。

## 2.6 解释分歧归因：四源分类法

矩阵每个"解释动机"字段须归入以下四类之一（可多编码）。四类即用户任务书指定的归因维度；每类给出操作定义与检出问题。

| 归因编码 | 名称 | 操作定义 | 检出问题（判断分歧是否源于此类） | 对应偏见类型 |
| -------- | ---- | -------- | -------------------------------- | ------------ |
| **A** | 利益位置 | 叙事者在事件中有物质/制度/声誉利害关系（商业利益、机构正当性、社区认同、个人声誉），解释方向与其利益方向一致 | "如果换一个对该叙事者不利的解释，谁的利益受损？受损者是否恰好是该解释的反对者？" | 类型 1、7（利益驱动的中心主义与商业决定论） |
| **B** | 时间位置 | 叙述产生时点与事件时点之间的距离允许事后信息渗入；越晚的叙述越可能把结果当作已知条件（总纲 18："主体的时间位置决定了'什么看起来重要'"） | "该解释是否使用了事件当时不可得的信息？若把该解释放到事件当年说出，是否成立？" | 类型 9（后见之明的直接来源）、类型 2 |
| **C** | 信息差异 | 叙事者能接触的记录集不同（在场者 vs 局外人；邮件列表参与者 vs 二手读者；有内部档案 vs 只有公开材料），解释差异反映可见证据的差异而非立场差异 | "该叙事者声称知道的场景/决策，其有接触相应记录的可能吗？沉默是否因为记录不可见？" | 类型 4（信息集中于 Berkeley 的机构视角）、类型 5 |
| **D** | 意识形态框架 | 叙事者的先在理论承诺（自由伦理、市场绩效、进步史观、英雄史观、制度经济学）决定了事件被归入何种故事类型 | "若事件结果相反，同一框架会产出什么解释？该框架是否对两种结果都'解释得通'（即框架先行而非证据先行）？" | 类型 3、6、8（框架先行型偏见） |

**使用规则：**

1. **编码可叠加**：多数解释分歧是多源的，填"A+B"式复合编码，并标明主次。
2. **归因不是贬斥**：四类归因描述的是**一切叙事的普遍处境**——本书自身的叙事同样可以被他人按 ABCD 编码。因此归因结论必须写成中性分析（"此解释与其机构正当性诉求一致"），禁止写成道德指控（"他们在撒谎"）。这与总纲 6（和解史观）一致：分析利益可以尖锐，指认动机不作道德审判。
3. **归因 → 证据义务**：某解释若归因为 A 或 D（利益/框架驱动），本书采纳它时须附加低层级史料佐证；若归因为 B（时间位置），须加时间位置标注（"此判断成形于事件 N 年后"）；若归因为 C（信息差异），须核对其记录接触范围并标注证据边界。
4. **归档要求**：每事件的归因分析以小节形式附在矩阵文件末尾（`E#事件.md` 的"分歧归因分析"节），作为章级"辨析"字段的直接素材。

# 第三部分 两套体系的集成

## 3.1 Anti-Bias Review 在编纂流程中的插入位置

lishidagang.md 的撰写与复核流程（"如何使用本文"表：搭五段式框架 → 撰写 → 六维评估 → 修订，最多两轮）中，反偏见审查在**三个节点**介入，检查重点各不相同，避免重复劳动：

### 节点一：章节撰写后（作者自检，必选）

**时机**：作者完成章节初稿（五/六段式齐备）后、提交复核前。
**检查内容**（快速扫描档，约九问）：

1. 逐段扫信号词总表（附录 A），命中的词回查上下文；
2. 本章涉及的每个历史对象（人物/分支/外部系统），问一句：它的因果权重是否被放大或压缩？（类型 1/2/3/4）
3. 本章每个"解释"（为什么 X 发生），问一句：这是条件分析还是品质/天才/理念归因？（类型 5/6/8）
4. 本章所有"成功/失败/重要"判断，问一句：度量标准是什么？是当时的还是今天的？（类型 7/9）
5. 输出**自检记录**（格式见 3.3），随稿提交。
**不做的事**：不做全矩阵对照（矩阵是卷级/事件级工具，不是每章全量跑）。

### 节点二：六维评估中的哲学符合度维度（复核者执行，必选）

**时机**：章节进入六维评估（§5.1.1），评估类型=哲学符合度时。
**检查内容**（完整档）：

1. 按附录 B 的映射表，将本章涉及的偏见类型逐条跑完整检测规则（每类 7 问）；
2. 对照本事件（若属于 E1-E15）的已填矩阵：本章文本是否不加标注地复制了某一叙事源的立场？（矩阵的"本书处理"字段是标准答案的对照基线）
3. 对称性核验：本章若批评了某一方（如 Linux 生态的问题），是否同时检查了对己方（BSD 各分支）的同类问题？（对称审查的操作定义：**同一检测规则必须双向适用**）
4. 判定输出：每类偏见给 通过/存疑/未通过，写入评估记录的对应清单。
**判定标准**：

- **未通过**：出现未豁免、未标注的违规表述（反例型），且属解释性正文（非史料引文）；
- **存疑**：表述可两解；或依赖第四/五层史料的解释性陈述未标注时间位置；或涉及未填矩阵格的事件；
- **通过**：无命中；或命中均已按偶然性脚注/立场标注/归因标注处理。

### 节点三：最终审稿（卷级/全书级，抽样+专项）

**时机**：卷定稿前与全书定稿前各一次。
**检查内容**（专项档，不全量）：

1. **卷级专项**：每卷按其主题选 2-3 类高发偏见做全卷扫描（例：卷 2-3 CSRG 期主查类型 4、8；卷 5-11 分支卷主查类型 4、7；卷 14-18 横向专题主查类型 1、6、7）；
2. **跨卷对称审计**：同一事件在不同卷的叙述是否对称？（如 E11 在 Linux 相关章节与 BSD 各分支卷中的篇幅与基调比较——与六维评估的"跨卷一致性"维度联动）；
3. **信号词机械扫描**：用附录 A 词表对全书电子稿做正则扫描，人工复核命中段（机械扫描不替代人工判定，只负责不漏）；
4. **矩阵缺口报告**：E1-E15 中哪些事件的矩阵仍未填？未填事件涉及的章节是否已完成偏见审查？（未填矩阵的事件，其相关章节的"哲学符合度"判定降为存疑档）；
5. **审查者自省**（本体系的自反义务，见 3.4）。

### 三节点的分工逻辑

| 节点 | 执行者 | 深度 | 类比 |
| ---- | ------ | ---- | ---- |
| 节点一 | 章节作者 | 九问速扫 + 信号词 | 提交前的 lint |
| 节点二 | 复核者（评估人） | 完整规则 + 矩阵对照 + 对称核验 | 代码评审 |
| 节点三 | 审稿组 | 专项扫描 + 跨卷对称 + 机械扫描 + 缺口报告 | 发布前审计 |

## 3.2 与 lishidagang.md 六维评估框架的对接

六维评估的第四维"哲学符合度"原有评估问题为："叙事是否违反禁止叙事？偶然性是否优先？进步叙事是否被拒绝？"（lishidagang.md §5.1.1 表）。本文档是该维度的**操作化展开**，对接关系如下：

| 六维评估维度 | 与本文档的关系 |
| ------------ | -------------- |
| 事实准确性（总纲 9） | 偏见类型 1 的"无史料影响声明"检查、类型 2 的"流失证据"检查归入本维度的史料核验——**偏见审查发现的"无证据主张"首先移交事实准确性维度处理**，不在哲学维度空谈 |
| 叙事连贯性（总纲 4） | 类型 4（Berkeley 中心主义）的"CSRG 后叙事断崖"检查与此维度联动：断崖既是偏见也是连贯性缺陷 |
| 跨卷一致性（总纲 8） | 节点三的跨卷对称审计归入此维度；同一事件在不同卷的偏见判定必须一致 |
| **哲学符合度（25 总纲）** | **本文档是此维度的检查表**：十类偏见 + 对称核验 + 矩阵对照构成完整操作规程；评估方式从"对照禁止叙事清单"扩展为"对照禁止叙事清单 + 十类偏见检测规则 + 事件矩阵" |
| 同源互证 | 教材前言哲学段落不得用作史料的规定（P3）同样适用于叙事对照矩阵：矩阵的"代表载体"若引用教材正文史实，按二手史料处理并交叉验证 |
| 可读性 | 偏见标注（偶然性脚注、立场标注、时间位置标注）不得损害段落可读性；标注密度与标准 8 的自反标注义务统筹，防止脚注通胀 |

**对接规则**：偏见审查不新增第七个维度，而是作为哲学符合度维度的执行层。评估记录中，"哲学符合度"一项的通过/存疑/未通过须能回溯到具体的偏见类型编号与检测问题编号（可追溯性要求）。

## 3.4 审查体系自身的自反性义务（防止审查变成新的教条）

本书的哲学框架要求理论自反（总纲 7）与"发现山洞"（P8）：审查体系本身也是一套形式主义装置，须防三种自我异化——

1. **审查教条化**：把十类偏见的检测规则当作机械清单逐字执行，产出大量"为合规而改写"的平庸文本。对策：信号词命中必须回到语境判定；合规的目标是诚实而非干净。
2. **对称性的虚无化**：以"双向都要查"为名对真实的证据不对称视而不见——若某方确实有更多第一/二层史料，对称呈现不等于虚构对方的证据。对称是**程序对称**（同等检查力度、同等史料收集义务），不是**结论对称**。
3. **矩阵的真理化**：把叙事对照矩阵当作"真相分布图"，以为填完矩阵就穷尽了多面性。对策：矩阵永远有未填格与未登记叙事源；每个卷首自反性声明须承认本卷的矩阵覆盖率及其局限。

> **体系开放声明**：本审查体系（十类偏见、13 叙事源、15 事件、四源归因）是编纂者基于现有原则清单与任务书的一次建构。执行中如发现第十类偏见、第十四个叙事源、更富分歧的事件，应按 3.3 的增补程序纳入并修订本文档——欢迎被更好的体系超越（对齐 dagang.md 自反性声明的措辞精神）。
