## 0. 五系统的共同哲学地基

五个系统不是独立的工具，而是同一组编纂原则在不同对象上的落地。先声明每个系统的原则锚点，再给 schema 与操作规则。

| 系统 | 核心原则锚点（《原则清单》编号） | 解决的编纂问题 |
| ---- | -------------------------------- | -------------- |
| ①历史语境数据库 | P15（总纲 5 偶然性）、P28（总纲 18 时间位置）、§2.3.2（禁现代倒灌） | 防止用今天的信息倒灌当时的处境 |
| ②术语历史 | P15（总纲 5）、P25（总纲 15 自然化）、§3.1.7（文化形式主义） | 防止用现代词义倒灌历史词义 |
| ③历史记忆史 | P28（总纲 18 朝花夕拾）、§1.2.1（第四层事后叙述）、P42（记忆重构） | 区分"当时"与"事后"两种叙述 |
| ④反事实检查系统 | P15（总纲 5）、§2.3.1 第六段、标准 4、§4.1 映射表 | 揭示偶然性，禁止必然性表述 |
| ⑤争议系统 | §3.2.4（多版本并置不给定论）、节五字段"辨析"、标准 2 | 呈现争议多面性，不强行定论 |

**总约束**〔原文锚定〕：五系统全部服从两条最高原则——

1. **诚实而非客观**（lishidagang.md §1.2.3b）：五系统都是"诚实标注局限"的装置，不是"给出客观答案"的装置。
2. **建构受硬边界约束**（总纲 23）：五系统产出的任何判断，都须能回溯到史料（邮件、commit、文档）硬边界之内。

## 系统一：历史语境数据库（Context Snapshot）

### 1.1 原则锚定

〔原文〕总纲 5："任何历史叙事中出现的'必然''注定''不可避免'……都是事后建构。UNIX 成功是因为 PDP-7 恰好可用、汤普森恰好想玩游戏……"
〔原文〕总纲 18"朝花夕拾"："一个技术、一个项目、一个人的价值，往往在其消亡之后才被认识……主体的时间位置决定了'什么看起来重要'。"
〔推断〕据此，语境数据库的功能是：**为每个时期固化"当时能看到什么"，使撰写者无法用后来才知道的信息倒灌**。它把"禁止现代意义倒灌"（《原则清单》问题 7）操作化为一个可查询的数据结构。

### 1.2 分期方案

〔任务指定分期〕1975-79 / 1980-84 / 1985-89 / 1990-94 / 1995-99 / 2000-04 / 2005-09 / 2010-14 / 2015-19 / 2020-25（每 5 年一快照，可依重大偶然事件微调边界）。
〔推断〕分期边界以偶然事件标记而非"进步阶段"标记（lishidagang.md §1.3.2c）——快照是"认识论切片"，不是"发展阶段"。

### 1.3 Context Snapshot schema

每个时期一条记录，字段如下：

| 字段 | 说明 | 示例（1990-94） |
| ---- | ---- | --------------- |
| `period_id` | 时期标识 | 1990-94 |
| `visible_tech` | 当时**已存在且可见**的技术 | 4.3BSD-Reno、386BSD、Linux 0.x、Windows 3.x |
| `invisible_tech` | 当时**尚未出现/不可见**（禁止倒灌项） | Git(2005)、GitHub(2008)、Docker(2013) |
| `available_resources` | 当时能获得/使用的资源 | Usenet、邮件列表、FTP、4.3BSD tape |
| `concerns` | 当时人们**担心什么** | USL 诉讼、AT&T 版权、386 移植可行性 |
| `understandings` | 当时人们**如何理解**关键概念 | "free software" 当时含义、"open" 尚未流行 |
| `absent_concepts` | 当时**不存在的概念** | "open source"(1998 才出现) |
| `power_configuration` | 当时的权力配置 | AT&T/USL 持版权、伯克利学术主导 |
| `sources` | 本快照的史料依据 | 邮件列表时间戳、发布公告日期 |

### 1.4 操作规则

1. **撰写前置查询**：撰写某时期章节前，须先调取该时期 Context Snapshot；凡正文出现 `invisible_tech` 或 `absent_concepts` 中的项，须标注为"后见之明"或移至分析段（分析段可带当下视角，但须自反标注）。
2. **倒灌检测**：复核时以 `invisible_tech` 清单为黑名单扫描正文——出现即违规（对应《约束矩阵》G3 扫描）。
3. **快照自反**：每个快照末尾声明"本快照本身是编纂者基于现有史料的重构，非当时全貌"（§3.2.3）。

## 系统二：术语历史（Term History）

### 2.1 原则锚定

〔原文〕总纲 15："文化让形式主义'感觉起来像自然'……文化是最成功的形式主义。"术语的自然化是文化形式主义的核心机制——今天的词义被当作"历来如此"。
〔原文〕§2.3.2：禁止把事后意义倒灌为当时意义。
〔推断〕术语史的功能是：**为每个关键词固化"历史含义 vs 现代含义"，防止词义倒灌**。

### 2.2 术语清单（任务指定 + 扩展）

任务指定：Unix / BSD / distribution / free software / open source / open systems / software sharing / license / copyright / kernel / operating system / community / hacker / port / package / Internet / TCP/IP。
〔推断补充〕建议增加：hacker 之外的 cracker、open core、fork、upstream/downstream、committer、ports tree、jail——这些是 BSD 史特有且词义易倒灌者。

### 2.3 Term History schema

| 字段 | 说明 | 示例（"open source"） |
| ---- | ---- | --------------------- |
| `term_id` | 术语标识 | open_source |
| `historical_meaning` | 历史含义（当时） | 1998 年前不存在；早期用 "free software" |
| `first_use` | 首次使用（时间+出处+史料层级） | 1998，OSI 成立前后（L2 邮件/L3 公告） |
| `semantic_shift` | 语义变化轨迹 | 从"free software"分化，去政治化 |
| `modern_meaning` | 现代含义 | 泛指源代码可获取的开发模式 |
| `anachronism_risk` | 倒灌风险等级（高/中/低） | 高——常把 1998 后词义用于 1970s |
| `bsd_specific_note` | BSD 语境特殊说明 | BSD 社区对 "free" vs "open" 的立场 |
| `sources` | 史料依据 | 首次使用邮件、术语论文献（L5 作参照） |

### 2.4 操作规则

1. **首次出现标注**：正文中术语首次出现须标注历史含义；若该词在当时不存在（如 1970s 用 "open source"），须改为当时用词或加引号自反标注。
2. **自然化解构**：对 `anachronism_risk=高` 的术语，正文须至少一处揭示其"被建构"过程（何时、由谁、为何固定下来）——落实总纲 15 反自然化。
3. **与争议系统联动**：术语的语义分歧（如 free vs open）本身是争议，须同时在系统五登记。

## 系统三：历史记忆史（Event Memory）

### 3.1 原则锚定

〔原文〕lishidagang.md §1.2.1 第四层史料："事后叙述（会议演讲、采访录、回忆录）……受记忆重构影响。"
〔原文〕总纲 18"朝花夕拾"：价值判断具有时间性，"主体的时间位置决定了'什么看起来重要'"。
〔原文〕总纲 23："神话人物在藉着作者本身书写他们自己的故事"——记忆是当事者藉叙述重构自身。
〔推断〕记忆史的功能是：**把"事件本身"与"事件的记忆"立为两个独立对象，追踪记忆如何被放大/遗忘/重新命名/重新归因**。这是"多版本并置"在时间维度上的展开。

### 3.2 Event Memory schema（双对象）

**对象 A：Event（事件）**

| 字段 | 说明 |
| ---- | ---- |
| `event_id` | 事件标识 |
| `event_date` | 发生时间 |
| `contemporary_record` | 当代记录（L1/L2，事件当时） |
| `contemporary_framing` | 当时的叙述框架（当时人们如何称呼/理解它） |

**对象 B：Event Memory（事件记忆）**

| 字段 | 说明 |
| ---- | ---- |
| `memory_id` | 记忆标识（关联 event_id） |
| `memory_date` | 记忆产生时间（事后多久） |
| `memory_source` | 记忆来源（采访/回忆录/纪念演讲，L4） |
| `memory_framing` | 事后的叙述框架 |
| `distortion_type` | 变形类型：放大 / 遗忘 / 重新命名 / 重新归因 |
| `delta` | 当代记录与事后记忆的差异点 |
| `sources` | 两类来源的史料标注 |

### 3.3 操作规则

1. **双对象强制分离**：凡涉及关键事件（4.4BSD-Lite、各 fork、USL 和解），须同时建立 Event 与 Event Memory 两条记录，不得混用。
2. **记忆层级降权**：Event Memory 属第四层史料，不得独立支撑事实性陈述（lishidagang.md §1.2.1"从不以第五层为唯一来源"类推；记忆须配 L1/L2 佐证）。
3. **变形类型标注**：发现"重新归因"（如把当时偶然决定事后说成"远见"）时，须按 §2.3.2 偶然性标注规范处理。
4. **多版本并置**：同一事件的不同记忆版本并置呈现，不给"真实记忆"定论（§3.2.4）。

## 系统四：反事实检查系统（Counterfactual）

### 4.1 原则锚定

〔原文〕dagang.md §4.1 映射表："偶然性 → 反事实呈现 → 在关键节点标注'假如不'的条件。"
〔原文〕§2.3.1 第六段："标注'假如条件 A 不成立，事件会如何发展'——不是为了证明'必然'，而是为了揭示'偶然'。"
〔原文〕标准 4："在 2 个以上关键节点标注偶然性脚注。"
〔推断〕反事实系统的功能是：**把"偶然性脚注"从零散义务升级为可登记的系统**——每个关键节点登记其偶然条件与反事实，供复核时清点密度。

### 4.2 Counterfactual schema

| 字段 | 说明 | 示例（386BSD） |
| ---- | ---- | -------------- |
| `node_id` | 关键节点标识 | 386bsd_birth |
| `event` | 节点事件 | 386BSD 发布（1992） |
| `contingent_conditions` | 实际聚合的偶然条件 | 386 处理器普及、Net/2 可用、Jolitz 夫妇个人兴趣 |
| `counterfactual` | "假如不"表述 | 若 386 未普及/Net/2 不可用，则…… |
| `purpose_note` | 固定为"揭示偶然，非证明必然" | （模板句） |
| `footnote_location` | 偶然性脚注落位（章/节） | 第 61 章 |
| `sources` | 条件成立的史料依据 | L1/L2 |

### 4.3 操作规则

1. **关键节点清单**：先登记全书关键节点（建议：Multics 退出、UNIX 诞生、BSD tape 发行、TCP/IP 入 4.2BSD、Net/2、USL 诉讼、各分支 fork、4.4BSD-Lite、Git 迁移等），每节点建一条反事实记录。
2. **密度核查**：每卷复核时清点偶然性脚注数，不足 2 处/关键节点者不满足标准 4。
3. **目的锁定**：反事实字段固定注明"揭示偶然"，禁止被读作"证明本可更好/更坏"的价值判断。
4. **与语境库联动**：反事实的"偶然条件"须取自该时期 Context Snapshot 的 `visible_tech`/`available_resources`，不得引入当时不存在的条件。

## 系统五：争议系统（Controversy）

### 5.1 原则锚定

〔原文〕§3.2.4 多版本并置："不选择'最可信'的版本——呈现多版本本身……不给'定论'——读者自行判断。"
〔原文〕节五字段"辨析"："争议与考据点，存在学术/社区争议时呈现正反论点。"
〔原文〕标准 2："不回避争议——若存在学界/社区争议，须在'辨析'中呈现正反双方论点。"
〔推断〕争议系统的功能是：**把散见各章的"辨析"字段汇聚为全书级争议登记簿**，统一争议的处理格式与"暂定判断"的自反性质。

### 5.2 Controversy schema

| 字段 | 说明 | 示例（OpenBSD fork 动因） |
| ---- | ---- | ------------------------- |
| `controversy_id` | 争议标识 | openbsd_fork_motive |
| `question` | 争议问题 | OpenBSD 从 NetBSD 分叉的主要动因是什么？ |
| `position_A` / `_B` / `_C` | 各方观点（至少正反，可多方） | A：安全理念分歧；B：治理/人际冲突；C：技术路线 |
| `sources_per_position` | 每方观点的来源与层级 | A：L2 邮件；B：L4 采访；C：L1 代码 |
| `evidence_strength` | 每方证据强度评级 | 按五层级+一致性 |
| `academic_status` | 当前学术/社区状态 | 尚无定论 / 社区分歧 |
| `book_tentative` | 本书**暂定判断**（自反标注，非定论） | "编纂者基于 L2 邮件倾向 A，但承认 B 有 L4 支撑" |
| `no_final_verdict` | 固定标注"不给定论" | （模板句） |

### 5.3 操作规则

1. **争议强制登记**：凡章内"辨析"字段出现争议，须同步登记到全书争议簿，标注 `controversy_id`，供跨卷一致性核查（同一争议在不同卷不得给出矛盾的暂定判断）。
2. **暂定判断的自反性**：`book_tentative` 必须以"编纂者基于……倾向……，但承认……"句式书写（§3.2.3 替代表述），禁止写成"真相是……"。
3. **证据强度分层**：`evidence_strength` 按史料五层级与来源一致性评级；低层级证据支撑的观点须显式标注。
4. **多方平等**：争议各方观点按标准 5 对称呈现，不因某方"主流"而加权。

## 6. 五系统的协同与数据流

〔推断〕五系统不是孤立的，其数据流如下：

```
Context Snapshot（系统一）
    │  提供"当时可见项"黑名单
    ├──→ 反事实系统（系统四）：偶然条件取自快照
    └──→ 术语史（系统二）：术语的历史含义锚定在快照时期

术语史（系统二）
    └──→ 争议系统（系统五）：术语语义分歧登记为争议

Event Memory（系统三）
    ├──→ 争议系统（系统五）：当代记录 vs 事后记忆的差异 = 争议来源
    └──→ 反事实系统（系统四）：记忆重构中的"重新归因" = 待反事实标注点

争议系统（系统五）
    └──→ 全书"辨析"字段 + 跨卷一致性核查
```

**与下游接口**：

- **→ Task #10（史料分层 schema）**：五系统的 `sources` 字段统一使用 Task #10 的史料层级编码（L1-L5）。
- **→ Task #11（因果链）**：反事实系统的"偶然条件"与争议系统的"暂定判断"是因果链拆解的输入。
- **→ Task #15（三版大纲重构）**：五系统作为"基础设施层"，独立于目录树/问题树，供三版大纲共用。
