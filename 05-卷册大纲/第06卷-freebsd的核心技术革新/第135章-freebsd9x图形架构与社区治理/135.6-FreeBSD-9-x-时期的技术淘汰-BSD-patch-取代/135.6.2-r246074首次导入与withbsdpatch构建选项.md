# 135.6.2 r246074 首次导入与 WITH_BSD_PATCH 构建选项

**要点**：2013 年 1 月 29 日 17:03 由 Gabor Kovesdan（gabor@）提交 svn revision r246074，首次将 BSD-licensed patch 导入 FreeBSD 10-CURRENT 源码树，commit 信息明确表述 "Add a BSD-licensed patch, ported by Pedro F. Giffuni (pfg) from DragonflyBSD and install it as bsdpatch. WITH_BSD_PATCH makes it default and installs GNU patch as gnupatch."；该 commit 添加 **usr.bin/patch/** 目录及其全部源文件、修改 **UPDATING**、**gnu/usr.bin/patch/Makefile**、**share/mk/bsd.own.mk**、**usr.bin/Makefile**，并新增 **tools/build/options/WITH_BSD_PATCH** 构建选项；初始状态为 BSD patch 安装为 `bsdpatch`，WITH_BSD_PATCH 选项启用时成为默认 `patch`，同时 GNU patch 改名安装为 `gnupatch`

**史料**：svn revision r246074（gabor 2013.1.29 17:03 提交）、commit log 完整文件变更清单（含 **usr.bin/patch/** 14 个文件添加、5 个文件修改）、Pedro Giffuni 2013.1.29 18:42 邮件公告、FreeBSD Quarterly Status Report 2012 Q4（2013.3.4 发布）“BSD-licenced **patch(1)**” 条目 ［A］

**史观**：总纲第 24 条——许可证：BSD patch 作为可选构建选项（WITH_BSD_PATCH）首次引入而非立即默认，体现 FreeBSD 项目 “先并行存在、验证成熟后再切换默认” 的渐进式淘汰工程哲学；GNU patch 改名 gnupatch 而非立即删除，保留向后兼容过渡期

**辨析**：r246074 的提交者是 gabor 而非 pfg——pfg 是移植者与提议者，gabor 因有 “将这类珍宝引入源码树的经验” 而承担实际 commit 操作；该分工是 FreeBSD 工程师社群常见的 “提议者-执行者” 配对；**tools/build/options/WITH_BSD_PATCH** 文件的添加表明该选项被纳入 **src.conf(5)** 体系，是正式的构建系统选项而非临时 hack；FreeBSD Quarterly Status Report 2012 Q4 中 “BSD-licenced **patch(1)**” 作为独立条目出现，与 BHyVe、Native iSCSI Target 等并列，表明该项目被官方认可为 2012 Q4 重要工程进展
