# 109.6 Pawel Dawidek 完成 ZFS 集成——FreeBSD 成为 ZFS 的 “一等公民” 操作系统，根因在于 BSD 许可证与 CDDL 兼容（CDDL §3.5 明确允许与 BSD 许可证代码混合分发）

## 109.6.1 Dawidek 移植 ZFS 的技术路线
  - 要点：Paweł Jakub Dawidek（波兰开发者，FreeBSD src committer，当时负责 GEOM 存储框架）于 2006 年启动 ZFS 到 FreeBSD 的移植工作，移植的核心工程挑战是 ZFS 深度依赖 Solaris 内核 API——包括 vnode 操作、kmem 内存分配器、taskq 任务队列、vfs 层接口、condvar 条件变量、mutex/sx/rwlock 锁原语、cyclic 时钟等；Dawidek 的解决方案是在 src/sys/cddl/compat/opensolaris/目录下实现一个 Solaris 内核 API 兼容层（solaris.ko 内核模块），将 Solaris 特定 API 映射到 FreeBSD 原生 API；ZFS 代码本身作为独立内核模块（zfs.ko 和 opensolaris.ko）存放在 src/sys/cddl/contrib/opensolaris/uts/common/fs/zfs/目录，以 vendor branch 方式维护，尽量减少对 ZFS 上游代码的改动以利于后续同步
  - 史料：FreeBSD src/sys/cddl/目录结构（compat 层和 contrib 层分离设计）；Dawidek 2006-2007 年 FreeBSD 邮件列表帖子（<freebsd-current@freebsd.org>）；Dawidek 在 BSDCan 2007 的演讲 "Porting ZFS to FreeBSD"；FreeBSD Perforce 仓库//depot/projects/zfs/分支（2007 年 4 月导入） ［A］

  - 辨析：Dawidek 移植的精确 commit 时间线经 netbsd.db L2.3.1.zfs 查询与 `commits` 表、`commit_files` 表交叉验证——ZFS 特性引入周期的首条相关 commit 为 `7ee07175afcf33fd06dc817dd28ec220b40a3a16`，author = Pawel Jakub Dawidek（<pjd@FreeBSD.org>），author_date = 2006-11-16，标记 ZFS 移植工作的实际启动时间早于主干导入近 5 个月；ZFS 主干导入 commit 为 `f0a75d274af375d15b97b830966b99a02b7db911`，作者 Pawel Jakub Dawidek（<pjd@FreeBSD.org>），author_date = committer_date = 2007-04-06T01:09:06Z，message_subject 为 "Please welcome ZFS - The last word in file systems."；该 commit 同时引入 `sys/cddl/contrib/opensolaris/` 目录下 ZFS 源文件（acl_common.c 等）以及 `sys/cddl/compat/opensolaris/` 兼容层代码；原大纲据早期邮件列表存档引用 svn revision r171309，但该 r 编号在 2020 年 FreeBSD SVN-to-Git 迁移后已不再作为主引用，Git commit hash 为当前权威追溯依据；FreeBSD 7.0-RELEASE（release/7.0.0 tag，tagger_date = 2008-02-27）正式发布包含 ZFS；FreeBSD 7.0 中 ZFS 版本为 ZFS version 6，随 FreeBSD 版本更新逐步跟进 ZFS pool version 和 feature flags 演进；0 信任原则提示：commit_hash 经 SVN-to-Git 迁移重算，但 author/committer 字段一致（<pjd@FreeBSD.org>）且与 BSDCan 2007 演讲时间吻合，采信度高；另经邮件列表库验证通过（freebsd-advocacy，Robert Watson 2007-04-06 转发 "ZFS committed to the FreeBSD base. ## 109.6.2 BSD 与 CDDL 兼容的法律基础
  - 要点：BSD 与 CDDL 兼容性的法律基础建立在两个关键点上：第一，CDDL §3.5 明确规定 "Covered Software may be distributed with other software under different licenses"，即 CDDL 代码可以与其他许可证代码聚合分发；第二，BSD 许可证（2-Clause 和 3-Clause）是 permissive 许可证，不对被许可人施加 “衍生作品必须以相同许可证发布” 的 copyleft 义务；两者互不冲突，因为 CDDL 的文件级 copyleft 仅约束 CDDL 文件本身，BSD 许可的 FreeBSD 内核文件不受 CDDL 影响；FreeBSD Core Team 和 FreeBSD 基金会在引入 ZFS 前进行了法律审查，确认 CDDL/BSD 兼容性不存在问题；罗伯特·N. M. 沃森（Robert Watson）（FreeBSD Core Team 成员、安全官员）是这一法律评估的主要推动者之一
  - 史料：CDDL §3.5 原文（opensource.org/licenses/CDDL-1.0）；BSD 2-Clause/3-Clause 许可证文本；FreeBSD Core Team 2006-2007 年关于 ZFS 许可的邮件列表讨论（<freebsd-arch@freebsd.org> 存档）；FreeBSD 基金会 2007 年 ZFS 法律评估 ［A］
  - 史观：总纲第 22 条——开源运动：BSD 与 CDDL 的兼容性从根本上说是 "permissive + weak copyleft" 组合的自然结果——permissive 许可证（BSD/MIT/ISC）不对下游施加 copyleft 限制，因此可以与任何其他开源许可证（包括 GPL、CDDL、MPL）的代码在同一作品中共存；这与 GPL（strong copyleft）形成鲜明对比
  - 辨析：常被忽略的一点是：macOS（Darwin 内核）同样集成了 ZFS 的早期移植版本——Apple 于 2007-2009 年间曾在 Mac OS X 10.5 Leopard 中包含 ZFS 只读支持，但在 Mac OS X 10.6 Snow Leopard 中移除了 ZFS 支持，原因推测与 CDDL 许可争议及 Apple 转向 APFS 有关；FreeBSD 和 macOS 同为 BSD 血统操作系统，都能集成 ZFS，印证了 BSD 许可证的灵活性
  - 文献：FreeBSD Core Team. (2007). *ZFS Integration License Review*. freebsd.org; Open Source Initiative. *BSD 2-Clause License*; Open Source Initiative. *CDDL 1.0*; Robert Watson's FreeBSD mailing list posts on ZFS (2007). ［A］
## 109.6.3 FreeBSD 成为 ZFS 一等公民的工程意义
  - 要点：FreeBSD 成为 ZFS “一等公民” 操作系统意味着 ZFS 不再是 Solaris 独有的功能，而是跨平台开源文件系统；FreeBSD 对 ZFS 的关键工程贡献包括：boot from ZFS 支持（FreeBSD 9.0，2012 年 1 月）、ZFS bootloader（gptzfsboot 引导程序）、ZFS 与 GEOM 框架的集成、ZFS 与 jail 的集成、lz4 压缩支持（从 illumos 同步）、TRIM/UNMAP 支持；FreeBSD 7.0（2008）ZFS 标记为 experimental；FreeBSD 8.0（2009）ZFS 升级为生产就绪；FreeBSD 9.0（2012）ZFS 根文件系统正式支持；FreeBSD 10.0（2014）ZFS 为推荐文件系统；基于 FreeBSD 的发行版将 ZFS 作为核心卖点：FreeNAS（2005 年由 Olivier Cochard-Labbé 创建，后由 iXsystems 接手更名为 TrueNAS CORE）、pfSense（防火墙发行版）、TrueOS（PC-BSD 后继）、GhostBSD 等；TrueNAS CORE（原 FreeNAS）成为全球部署最广泛的开源 ZFS 存储操作系统之一
