## 116.3.1 BSD 2-Clause 对 Capsicum 的法律保障

## 116.3.2 BSD 许可证与 CDDL/GPL 的兼容比较

**要点**：Capsicum 的 BSD 2-Clause 许可证与 GPLv2/GPLv3/LGPL/CDDL 均兼容：(1) 与 BSD 许可证的兼容性——显然完全兼容，FreeBSD 基础系统本身以 BSD 类许可证为主；(2) 与 CDDL 的兼容性——BSD 2-Clause 是宽松许可（permissive），对与之聚合分发的代码无任何许可要求，因此 BSD 许可的 Capsicum 代码可与 CDDL 许可的代码共存；(3) 与 GPL 的兼容性——BSD 2-Clause 是 GPL 兼容的宽松许可证，FSF 明确确认 BSD 2-Clause 与 GPL 兼容（可被 GPL 项目包含）；这与 ZFS/DTrace 使用的 CDDL 形成鲜明对比——CDDL 的文件级 copyleft 与 GPL 的作品级 copyleft 互斥，导致 ZFS/DTrace 无法进入 Linux 主线；Capsicum 因其 BSD 许可，Google 可自由开发 capsicum-linux（BSD 许可内核模块可被 Linux 加载），不存在许可证壁垒

**史料**：FSF 许可证列表 BSD 2-Clause 条目（gnu.org/licenses/lic-list.en.html#ModifiedBSD）；Google capsicum-linux 仓库（BSD 许可）；FreeBSD src 树中 Capsicum 代码位置（sys/kern/ 而非 sys/cddl/contrib/opensolaris/） ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：Capsicum（BSD）与 ZFS（CDDL）在 FreeBSD 中不同的目录放置位置（sys/kern/ vs sys/cddl/contrib/opensolaris/）是许可证差异的直接工程体现——BSD 许可代码可直接融入内核主树，CDDL 代码需放在 contrib 目录以保持许可证边界清晰；但许可证兼容性并未使 Capsicum 在 Linux 上获得比 ZFS 更大的成功——capsicum-linux 长期处于实验状态，最终 Chrome 团队选择了 seccomp-bpf（参见 74.6 节），这证明许可证壁垒只是技术采纳的因素之一，生态惯性与技术集成成本同等重要

**辨析**：capsicum-linux 的许可证状态需精确核实——Google 在 github.com/google/capsicum-linux 发布的 Linux 内核 Capsicum 移植补丁以 BSD 2-Clause 许可发布，但 Linux 内核本身是 GPLv2（仅），BSD 许可的内核模块可加载进 GPL 内核（因为 BSD 与 GPL 兼容），但如果 Capsicum 代码被合入 Linux 主线则需以 GPLv2 发布；Google 从未尝试将 Capsicum 补丁向上游 LKML 提交合并，capsicum-linux 一直作为独立分支维护

## 116.3.3 许可证选择对安全研究传播的效应

**要点**：BSD 许可证选择对 Capsicum 传播的影响是双向的：(1) 积极影响——FreeBSD 9.0 直接在 GENERIC 内核中包含 Capsicum 框架（无需单独安装或加载模块），DragonFly BSD 存在 Capsicum 内核补丁，Google 开发了 capsicum-linux 移植，CloudABI（基于 Capsicum 的跨平台 ABI）得以自由开发并在 FreeBSD 中集成，学术界可自由将 Capsicum 用于安全研究项目；(2) 局限性——许可证开放不等于生态采纳：Capsicum 在 FreeBSD 基础系统中的应用长期限于少量工具（tcpdump、dhclient 等），第三方应用对 Capsicum 的沙箱化改造进展缓慢，Linux 主流发行版从未正式采用 Capsicum（Chrome 选择 seccomp-bpf），macOS 使用基于 TrustedBSD MAC 的 Seatbelt 而非 Capsicum；这表明安全机制的传播不仅取决于许可证开放度，更取决于 API 设计、开发者心智模型、以及操作系统厂商的战略投入

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：原挂“企业研究双重性”不在 25 条总纲权威表，按商业与社区利益关系语义暂挂第 13 条〕：Google 对 Capsicum 的态度体现了企业参与开源安全研究的双重性：Google 资助了 Capsicum 研究（员工 Ben Laurie 参与设计、Google Open Source Program Office 联合资助 Dawidek 的开发工作）、使用 Capsicum 作为 Chrome 沙箱在 FreeBSD 上的原型、发布了 capsicum-linux 移植，但最终在 Chrome 主平台（Linux）上选择了自研的 seccomp-bpf 沙箱而非推进 Capsicum 进入 Linux 主线；企业对学术研究的支持与其产品战略决策之间不存在必然的延续性
