# 131.4 无线网络、硬件驱动与嵌入式支持

## 131.4.1 **iwm(4)** Intel 无线驱动与 802.11n 改进

**要点**：FreeBSD 11.x 时期无线网络硬件支持显著进步。**iwm(4)** 驱动支持 Intel Wireless 7265、8260 等 802.11n/ac 无线网卡（Intel Dual Band Wireless-AC 系列），这些网卡基于 Intel 7000/8000 系列无线芯片，是 2015-2017 年笔记本电脑的主流配置。**iwm(4)** 是从 OpenBSD 移植的驱动（OpenBSD 的 iwm 驱动由 Stefan Sperling（斯特凡·施佩林） 等人开发），与较早的 **iwn(4)**（Intel 4965/5000/6000 系列）共同构成 Intel 无线驱动栈。11.0 中多个无线驱动获得 802.11n MIMO 改进；默认无线监管域（regulatory domain）从之前的无默认改为默认 FCC（美国联邦通信委员会）规则（r300738），新创建的无线接口默认应用 FCC 频率与功率限制，减少违反各国无线电管制规定的风险；**wpa_supplicant(8)**/**hostapd(8)** 更新至 2.4（11.0）。其他无线驱动如 **ath(4)** Atheros、**run(4)** Ralink、**urtw(4)** Realtek〔订正注：2026-09-14 原“urtw(8)”手册节号错置，urtw 系 RTL8187B 网络驱动，应同段 iwm(4)/iwn(4)/ath(4) 为第 4 节〕等也持续改进。Adrian Chadd（adrian@）是 FreeBSD 无线网络栈的长期维护者。

**史料**：FreeBSD 11.0-RELEASE Announcement（"Additional wireless support for 802.11n has been added to several drivers“、”default regulatory domain to FCC"）、11.x Release Notes Network Drivers 章节、iwm(4)/iwn(4)/ath(4) 手册页、svn commit r300738（默认 FCC 监管域）。 ［A］

**史观**：〔订正注：2026-09-14 原挂“总纲第 21 条——硬件支持”系自造名目，权威第 21 条为“革命与改革是历史方法论的分歧”，与硬件决策论旨无涉，依核查报告去条号留论旨〕默认监管域设为 FCC 是一个有趣的工程决策——FCC 规则是全球最严格的无线电管制之一，默认使用 FCC 意味着无线网卡在大多数国家不会以非法频率/功率发射，但也意味着在其他国家（如 EU、JP）用户需手动调整监管域以获得合法的信道与功率。这一决策反映了 FreeBSD 作为美国发源的项目，默认值选择倾向于保守合法。

**辨析**：**iwm(4)** 在 11.x 支持 Intel 7265/8260 但不支持更新的 Intel 9000/AX200 系列——这些后续型号的驱动在 12.x/13.x 才加入；802.11ac（Wi-Fi 5）支持在 11.x 为初步状态，稳定性与性能不如 802.11n；802.11ax（Wi-Fi 6）在 11.x 完全不支持。FreeBSD 无线驱动整体仍落后 Linux 约 3-5 年，主要原因是无线芯片厂商（Intel、Broadcom、Realtek、Qualcomm）极少直接提供 FreeBSD 驱动支持，多数驱动由社区从 OpenBSD/Linux 移植或逆向工程实现。

**文献**：FreeBSD iwm(4)/iwn(4)/ath(4) Manual Pages [Z]；FreeBSD 11.0-RELEASE Announcement [Z]. 2016.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 131.4.2 DRM/KMS 图形驱动与桌面支持

**要点**：11.x 时期 DRM/KMS（Direct Rendering Manager/Kernel Mode Setting）图形驱动持续由 Jean-Sébastien Pédron（dumbbell@）等人维护与移植。11.x 的 DRM 代码基于 Linux 内核 DRM 子系统（通行记载 11.x 系 Linux 3.8/3.18 基底，Pédron 的 radeon/i915 更新线；Linux 4.x 基底 DRM——linuxkpi，Linux 4.9——系 12-CURRENT 起由 Matt Macy 等引入）〔存疑注：2026-09-14 按核查报告标注——原文作“基于 Linux 4.x”，与通行记载不符，具体基底须以 11.0-RELEASE Notes 原文核验后订正〕，支持 Radeon（AMD GCN 1-3 代）与 Intel（Haswell/Broadwell/Skylake 代）GPU 的 KMS 模式设置与 2D/3D 加速。11.0 中 DRM 代码与 **vt(4)** 新控制台集成良好，可实现高分辨率控制台与 Xorg 平滑切换。但 FreeBSD 的 DRM 驱动始终落后于 Linux 内核主线——Linux 4.x DRM 在 2015-2016 年发布，FreeBSD 11.x 在 2016-2020 年使用对应的移植版本。NVIDIA 显卡通过 ports 中 nvidia-driver 提供闭源驱动支持（由 NVIDIA 官方维护 FreeBSD 版本）。桌面环境方面，11.x ports 提供 GNOME 3.18/3.28、KDE 4.14/5.15、Xfce、MATE 等，但这些均通过 ports/pkg 安装而非 base 系统组件。11.2 引入 **dwatch(1)** DTrace 监控工具对调试图形与系统问题有帮助。

**史料**：FreeBSD 11.x Release Notes Contributed Software/Graphics 章节、Jean-Sébastien Pédron freebsd-x11 邮件列表状态报告、FreeBSD Quarterly Status Reports X11 章节。 ［A］

**史观**：总纲第 22 条——知识注定过时〔订正注：2026-09-14 原挂“总纲第 5 条——技术债务与代码考古”系自创名目，权威第 5 条为“没有必然性，只有偶然性”，按论旨（Linux DRM API 快速变化致移植成为持续技术债务）改挂第 22 条〕：FreeBSD DRM 驱动移植是一项持续的技术债务——由于 Linux 内核 DRM API 持续快速变化，每次跟随升级都需要大量适配工作（GPL 代码与 BSD 内核的 API 不兼容）。Pédron 等人的工作本质上是“追着 Linux 跑”，这种模式在人力有限的情况下注定难以在桌面市场与 Linux 竞争。FreeBSD 在服务器/虚拟化/存储领域的优势与在桌面领域的弱势形成鲜明对比。

**辨析**：11.x 没有 AMDGPU（AMD 新一代 GCN 4+ 显卡支持，RX 400/500 系列及更新）——AMDGPU 驱动移植在 FreeBSD 12.x/13.x 才完成（由 Matt Macy 等人推动）；11.x 的 drm 代码仅支持 Radeon KMS（旧版 GCN 1-3）；Intel 显卡支持在 11.x 截至 Skylake（第 6 代酷睿），Kaby Lake/Coffee Lake 支持在后期版本改进。Wayland 显示服务器在 11.x 可通过 ports 安装但处于实验状态，Xorg 仍是默认且唯一稳定的显示服务器。

**文献**：Pédron J-S. FreeBSD Graphics Status Reports [EB/OL]. freebsd-x11 mailing list, 2016-2020；FreeBSD 11.x Release Notes [Z]. ［A］

## 131.4.3 Raspberry Pi 与嵌入式 ARM 平台

**要点**：11.x 时期 FreeBSD/ARM 支持显著改善。armv6（32 位 ARMv6/v7）在 10.x 已加入发布支持，11.x 持续改进稳定性与驱动支持。arm64/AArch64 11.0 正式发布后支持的开发板逐步增多：Raspberry Pi 3（BCM2837，四核 Cortex-A53）的 arm64 支持在 11.x 逐步完善（RPi 3 既可运行 armv7 32 位镜像也可运行 aarch64 64 位镜像）；Raspberry Pi 2（BCM2836/BCM2837，Cortex-A7/A53）armv7 支持持续稳定；BeagleBone Black/BeagleBone AI、Pine64、SoftIron Overdrive 等开发板支持改进；SD 卡镜像持续提供并优化。11.x 还支持多种嵌入式网络与存储设备。嵌入式场景下，FreeBSD 的轻量级（base 系统可裁剪至数 MB）、GEOM 存储框架、ZFS 可靠性、网络栈性能是其相对于 Linux 嵌入式发行版的优势。

**史料**：FreeBSD 11.x Release Notes ARM Support 章节、FreeBSD/arm 邮件列表、Raspberry Pi FreeBSD 镜像文档、FreeBSD Quarterly Status Reports ARM 章节。 ［A］

**史观**：总纲第 10 条——动手者创造历史〔订正注：2026-09-14 原挂“总纲第 10 条——边缘者贡献”系名目非权威，权威第 10 条为“动手者创造历史”；条号可成立按权威名目正名〕：ARM 平台支持长期由少数核心开发者（Andrew Turner、Ian Lepore、Oleksandr Tymoshenko 等）推动，属于“边缘架构”持续改进。与 amd64 由多家公司赞助不同，ARM 支持更多依赖社区志愿贡献与 FreeBSD Foundation 部分赞助。Raspberry Pi 作为全球最流行的单板计算机，其 FreeBSD 支持主要由社区完成而非 Raspberry Pi Foundation 官方支持。

**辨析**：Raspberry Pi 3 的内置 Wi-Fi/蓝牙在 11.x 支持不完善——部分组件需要额外的 firmware 与驱动配置，支持状态因版本而异；Raspberry Pi 4 不在 11.x 支持范围内（RPi 4 于 2019 年发布，支持在 12.x/13.x 完善）；Raspberry Pi 0/0 W/1 在 11.x 通过 armv6 镜像支持但性能有限。

**文献**：FreeBSD arm(4)/aarch64(4) Platform Notes [Z]；FreeBSD 11.x Release Notes ARM Support chapters [Z].［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 131.4.4 VMware、Xen 与云平台驱动

**要点**：11.x 时期虚拟化平台驱动持续改进：VMware 方面——**vmx(4)** VMXNET3 网络驱动在 10.0 从 OpenBSD 移植后 11.x 持续改进性能与稳定性；**vmblock(4)**/**vmmouse(4)**/**vmhgfs(4)** 等 VMware guest 驱动持续更新；VMware SVGA 图形驱动配合 Xorg 可实现自适应分辨率。Xen 方面——DomU（客户机）支持在 10.x 已稳定，11.x 持续优化；Dom0（控制域/宿主机）支持持续改进但 11.x 仍不建议生产使用（Dom0 生产就绪在更晚版本）；Xen PVHVM 半虚拟化驱动在 GENERIC 内核中默认启用。Hyper-V 方面——11.1 加入 Generation 2 虚拟机支持是里程碑式改进（Gen2 使用 UEFI 引导、SCSI 启动、合成设备，性能远优于 Gen1）。云平台方面：Amazon EC2 获得 **ena(4)** 增强网络驱动（11.1）；Azure 正式进入 Marketplace（11.1）；Google Compute Engine 镜像持续提供；Vagrant 官方镜像持续更新。

**史料**：FreeBSD 11.x Release Notes Virtualization/Hardware/Network Drivers 章节、vmx(4)/ena(4)/hv_netvsc(4) 等驱动手册页、Hyper-V Gen2 支持提交记录。 ［A］

**史观**：〔订正注：2026-09-14 原挂“总纲第 22 条——开源运动”系名目非权威且论旨与权威第 22 条“知识注定过时”无涉，依核查报告去条号留论旨〕Hyper-V Gen2 支持是 Microsoft 与 FreeBSD 合作深化的标志——Microsoft 在 2012 年后成立 Open Source Technology Center 积极向 Linux 与 FreeBSD 贡献驱动代码，Azure 上 FreeBSD 虚拟机的稳定支持是企业用户采用 FreeBSD 的重要前提。云厂商对 FreeBSD 的正式支持意味着 FreeBSD 已不再是“极客小众 OS”而是公有云认可的生产级操作系统。

**辨析**：Xen Dom0 在 11.x 确实有改进但 FreeBSD 11.x Release Notes 未将其列为 production-ready 特性；VMware 的 open-vm-tools 通过 ports 提供（emulators/open-vm-tools）而非 base 系统组件；VirtualBox 兼容在 11.x 时期存在已知的 panic 问题（11.1 Announcement 专门提到 VirtualBox 升级时的 guest additions 重建警告）。
