# 143.1.3 WPA2 KRACK 与 802.11 协议层清算——13 个 CVE 的协议级缺陷

**要点**：**SA-17:07.wpa**（**2017 年 10 月 17 日** 发布）修复 WPA2 协议层的 KRACK（Key Reinstallation Attacks）漏洞群——由 Mathy Vanhoef（imec-DistriNet, KU Leuven）发现并披露，共影响 **13 个 CVE**（CVE-2017-13077、CVE-2017-13078、CVE-2017-13079、CVE-2017-13080、CVE-2017-13081、CVE-2017-13082、CVE-2017-13086、CVE-2017-13087、CVE-2017-13088，以及 CVE-2017-13077 之外的额外变体）；Gordon Tetlow 提交修复 commit `a2063804a2b8` "Update wpa_supplicant/hostapd for 2017-01 vulnerability release“（注意 commit message 中”2017-01“应为”2017-10"的笔误，反映 SA 发布过程的紧急性），后续 MFC commit `cfaed0fa41d7`、`746aa8b814b2` 将修复回溯至 stable/11 与 stable/10；KRACK 漏洞的技术机制为：WPA2 四次握手中的第三次消息（Message 3）可被攻击者重放，导致客户端重新安装已在使用中的密钥——重置密钥计数器与重放计数器，使攻击者可解密、重放、伪造加密流量；**SA-18:11.hostapd**（**2018 年 8 月 14 日**）修复 CVE-2018-14526，由 Cy Schubert 提交 commit `765ef8a7642d` “WPA: Ignore unauthenticated encrypted EAPOL-Key data”，Xin Li 完成 MFC commit `90c403d54f22`——这是 KRACK 之后 WPA 协议层的又一次安全响应；11.x 周期 WPA 相关 SA 共 3 个（SA-17:07.wpa、SA-18:11.hostapd、SA-19:03.wpa），形成连续的 802.11 协议层清算

**史观**：专题语（不设总纲条号）——信息技术：KRACK 漏洞是 11.x 周期最具协议级影响的安全事件——与 FreeBSD 内核 bug 或 OpenSSL 实现错误不同，KRACK 是 WPA2 协议规范本身的缺陷，任何遵循协议规范的实现（包括 FreeBSD、Linux、macOS、Windows、Android、iOS）都受影响；这使得 11.x 周期的安全响应从“修复 FreeBSD 代码”扩展为“修复 FreeBSD 实现的协议符合性”——commit `a2063804a2b8` 的 message_subject"Update wpa_supplicant/hostapd for 2017-01 vulnerability release“中的”vulnerability release"措辞表明这是上游 wpa_supplicant 项目的官方修复发布，FreeBSD 通过 vendor import 同步；KRACK 事件也暴露了 802.11 协议设计中“信任客户端状态机”的根本缺陷——后续 WPA3 协议（2018 年发布）的部分改进正是对 KRACK 的回应

**辨析**：**严格区分 KRACK 与以往 WPA 漏洞**：① KRACK 是协议层漏洞（WPA2 四次握手规范缺陷），所有实现均受影响；② 以往 WPA 漏洞（如 2017 年前的 WPA 漏洞）多为实现 bug，仅特定供应商产品受影响；③ KRACK 的 13 个 CVE 中，CVE-2017-13077/13078/13079 影响客户端 wpa_supplicant，CVE-2017-13080 影响服务端 hostapd，CVE-2017-13081/13082 影响 TDLS（Tunneled Direct Link Setup），CVE-2017-13086/13087/13088 影响特定实现——FreeBSD base 同时包含 wpa_supplicant(8) 与 hostapd(8)，因此 13 个 CVE 全部需要修复；**commit message 中“2017-01”笔误的辨析**：commit `a2063804a2b8` 的 message_subject"Update wpa_supplicant/hostapd for 2017-01 vulnerability release“中”2017-01“应为”2017-10"——这反映 SA-17:07 发布过程的紧急性，commit message 在 KRACK 公开披露次日（2017-10-17）即提交，可能未经过严格 review；**KRACK 实际威胁的辨析**：KRACK 攻击需要攻击者位于受害客户端与 AP 的无线信号范围内，且只能解密少量加密流量（不能直接获取 Wi-Fi 密码）——中文安全媒体中“Wi-Fi 密码被破解”的报道不准确；**与 802.11 漏洞清算的关联**：11.x 周期 3 个 WPA SA（SA-17:07/18:11/19:03）反映 802.11 协议层在 2017-2019 年间经历了系统性清算，这与 KAME 项目 IPv6 协议栈在 2010 年代后期的清算（导致 14.x 周期 rtsold CVE-2025-14558）是平行的“协议实现老化”现象 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
