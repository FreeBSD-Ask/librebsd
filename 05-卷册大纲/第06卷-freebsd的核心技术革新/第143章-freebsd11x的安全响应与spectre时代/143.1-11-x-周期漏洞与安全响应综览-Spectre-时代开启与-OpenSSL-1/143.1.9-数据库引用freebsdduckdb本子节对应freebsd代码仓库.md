**要点**：

- 节目介绍在 DragonFly BSD 上以 LUKS 兼容加密层对磁盘加密后搭建 HAMMER 主从文件系统，展示 HAMMER 作为可跨多台机器的分布式文件系统的特性，并提示 LUKS 提供的安全性与同步复制取舍。（BSD Now EP251，[66.84-354.00]，L2）
- Intel FPU 推测执行漏洞被确认：OpenBSD 的 Philip Guenther 于 7 月 5 日提交从惰性切换到主动切换的变更，Colin Percival 根据 Theo de Raadt 演讲披露的信息约五小时写出概念验证并通知 Intel，促使 Intel 提前公布；FreeBSD 2015 年 3 月的邮件列表曾有人建议为性能做同样变更。（BSD Now EP251，[3176.16-3380.00]，L1）
- BSDCan 2018 复盘记录 Ben O'Rice 的 systemd 悲剧主题演讲，他主张不应仅因批评就否定 systemd 的合理意图，BSD 社区可吸收其优点而不必照搬；并记录 Kirk McKusick 的 FreeBSD 治理演进演讲，回顾核心团队每两年改选、从 Jordan 时代到 Watson 时代再到当代的交替。（BSD Now EP251，[831.08-2315.32]，L1）
- 节目考据多个 Unix 命令名词源：awk 取自 Aho、Weinberger、Kernighan 姓氏首字母；grep 源自 ed 的 g/re/p（全局正则表达式打印）；cat 是 concatenate 的缩写；GECOS 字段源自 Honeywell 的 General Electric Comprehensive Operating Supervisor；rc 可追溯至 1965 年 MIT CTSS 的 runcom。（BSD Now EP251，[3944.18-4195.44]，L2）
- Mitchell Horne 的实习总结描述新手常见误区：误以为 FreeBSD 由少数 rockstar committer 包办一切，实则数百名低频贡献者提交的错误报告、补丁与反馈同样重要；他反思自己不应与资深 committer 对比而贬低自身工作，强调从小处着手并在学习新事物的过程中获得满足。（BSD Now EP247，[53.00-765.02]，L1）
- Mitchell 指出 FreeBSD 的审查与推进机制对新人存在门槛：提交的工作须经至少两人审查，但要找到人查看自己的补丁需要自我倡导与主动催促，文档与手册页对新手价值巨大。（BSD Now EP247，[372.36-532.24]，L1）
- FreeBSD 在 AMD64、ARM64、i386、PowerPC、SPARC64 上默认启用内核崩溃转储的加密、压缩与网络转储支持，网络转储代码起源久远；节目同时报道 Intel 微码拆分工具与 Speculative Store Bypass 的 hw.spec_store_bypass_disable 控制。（BSD Now EP247，[770.36-1151.44]，L1）
- 节目解释 FreeBSD 治理为选举制：每两年由过去一年内提交过代码的 committer 从候选人中选出 9 人 Core 团队，形成共识式民主而非仁慈独裁；2018 年选举有 16 名候选人，投票于 6 月 20 日截止。（BSD Now EP247，[1283.72-1474.54]，L1）
- 节目报道 Alex Wilson 记录的 SmartOS/illumos KPTI 开发历程：Spectre/Meltdown 公开披露后，团队参照 Matthew Dillon 为 DragonFly BSD 写的第一批 BSD 内核页表隔离补丁，并与 OpenBSD 的 Philip Guenther、Mike Larkin 保持协作，最终选择每 CPU 页表而非 Linux 的每进程每 CPU 方案，借助 x86 IST 特性简化中断跳板。（BSD Now EP238，[617.6-1878.2]，L2）
- 访谈对象 Ryan Zezeski 早年以 Windows 与 Solaris 为背景，在 AOL 期间用 Erlang 将 13.4 万行 C# 广告竞价系统重写为约 4500 行并成为 Riak 核心开发者三年半，后离开数据库领域自学 Solaris 内核并转入 SmartOS/illumos 底层开发。（BSD Now EP238，[2445.6-3227.0]，L1）
- Ryan Zezeski 近一年专注 SmartOS 网络性能，为 ixgbe（Intel 10Gb）等网卡实现 VLAN 硬件分类，使 Triton 云的 vNIC 与链路聚合可将 VLAN 过滤下放到 NIC 硬件并启用轮询模式，计划扩展至 Fortville（i40e）与 Chelsio T4/T5/T6。（BSD Now EP238，[4211.3-4448.4]，L1）
- John Carmack 利用周末闭关在纯 OpenBSD 基本系统上用 C++ 从零实现多层神经网络，感慨 95% 时间用于基本 vi/make/gdb 操作，发现基本系统的 GCC 不支持 C++11、LLVM C++ 与 GDB 配合不佳，并反思 C++ 是否仍为净正面。（BSD Now EP238，[4968.0-5394.8]，L2）
- Lumina 桌面 2.0 宣布以 QML 重写图形界面并合并为单一多线程二进制，移除 fluxbox、xscreensaver 与 Compton 依赖；NomadBSD 1.0 发布为 FreeBSD 11 的 live USB 版本，支持 GELI 加密家目录与 NVIDIA 驱动自动识别。（BSD Now EP238，[0.0-603.0]，L2）
- AsiaBSDCon 2018 在东京举行，前两日为 FreeBSD Developer Summit 与 BeehiveCon（含 NetBSD Summit 和 OpenBSD VMM 更新），后两日为论文演讲；bhyve 相关论文在第二天占满专题时段，议题覆盖 bhyve 的 SmartOS zones 移植、ARMv7/v8、挂起恢复与虚拟中断控制器，另有 FreeBSD VPC 与保存恢复（朝向热迁移的第一步）。（BSD Now EP237，[0.0-997.0]，L1）
- FreeBSD 11.1 stable 合入针对 Meltdown 与 Spectre V2 的缓解：Meltdown 采用 PTI 分离内核与用户页表，Spectre V2 采用依赖微码更新的 IBRS；可通过 vm.pmap.pti 与 hw.ibrs_active 等 sysctl 查看与切换，retpoline 编译器方案仍在评估中。（BSD Now EP237，[1008.2-1502.9]，L2）
- OpenBSD 宣布 syspatch 开始为两个受支持版本（6.1 与 6.2）同时提供二进制补丁，使 6.2 在 6.3 发布后仍可通过 syspatch 获得 Meltdown 缓解，并特别感谢 Robert 与 Antoine Jacoutot 的工作。（BSD Now EP237，[3566.9-3641.5]，L2）
- MidnightBSD 创始人 Lucas Holt 在访谈中说明该桌面导向系统是 FreeBSD 的 fork 而非发行版，拥有自有包管理器 mPort（tar LZMA 包加 SQLite3 清单与索引），启动卷使用 UFS2 并支持 ZFS，提供 2.6.16 内核的 Linux 仿真，计划保留 i386 支持至 1.0 版本。（BSD Now EP237，[1701.7-2136.1]，L2）
- 一篇八个月使用 TrueOS 的报告记述作者因对 Linux 发行版的 systemd 组织方式失望而转向 FreeBSD/TrueOS，赞赏 OpenRC、ZFS 启动环境回滚与手册质量，并由此偏好 BSD 许可证；其未能使用的软件为 Netflix、Google Hangouts 与 Electron 类应用。（BSD Now EP237，[2373.5-2995.7]，L2）

- FreeBSD 11.1 稳定分支于本期前后合入自 HEAD 下移的投机执行缓解补丁：Meltdown（越障投机执行后经缓存侧信道泄漏特权数据的微架构缺陷）以页表隔离（PTI）应对，Intel 处理器默认启用，系统调用微基准回归显著而多数真实负载影响较小，可经 loader 可调参数 vm.pmap.pti 控制；Spectre v2（分支目标注入）以 IBRS 加 CPU 微码更新缓解，状态经 hw.ibrs_disable 与 hw.ibrs_active sysctl 查验，而依赖新编译器的 retpoline 方案因向 stable 分支合并新版 clang 风险过大仍属评估项，i386 所随代码不含功能性缓解；同集播报 OpenBSD syspatch 首次为 6.1 与 6.2 两个受支持发行版（6.3 发布后 6.2 仍受支持）提供二进制补丁，amd64 用户均获 Meltdown 缓解，公告致谢 Robert 与 Antoine Jacoutot 的补丁工作、TJ 及志愿者测试与 Theo 的总体监督。（YouTube EP_6gNefiY6hU，[1001.3-3636.5]，L2）[订正：原“Theos 的总体监督”→“Theo 的总体监督”，字幕原文为 for Theo for overseeing it all；时间戳原 [1010.39-3640.9]→[1001.3-3636.5]，11.1 缓解补丁段自 1001.3 起、致谢清单止于 3636.5，原边界取自旧转写轴]

- 一位 2001 年起使用各 Linux 发行版、2009 年至 2017 年长期使用 Arch Linux 的用户因 systemd 的推行方式与发行版组织哲学（进程日益不透明、共同开发的应用集合被机制耦合）决意脱离 Linux，先在朋友推荐下于 FreeBSD 11 服务器运行 Postgres、RabbitMQ、nginx 与 JVM 进程约三个月，再因笔记本芯片组驱动缺口选中承接 PC-BSD 血统、基于 FreeBSD 12-CURRENT 并集成最新驱动的 TrueOS；八个月体验中其留下的理由是 OpenRC 熟悉且有完善文档（本人两小时写出 Postgres 10 脚本）、ZFS boot environments 的回滚能力（由此确信 ZFS 价值）、base 系统与应用分离的文件系统布局（认为做 “怪异之事” 的是 Linux 发行版一方）、Handbook 文档质量与 Telegram/Discourse 社区的友好（核心开发者常驻）；同时坦承 Netflix、Google Hangouts 与 Electron 应用不可用系上游而非 TrueOS 之过，并称迁移带来哲学转变——在 BSD 许可证与 GPL 之间更认同前者，因其 “更实用”。（YouTube EP_6gNefiY6hU，[2515.8-2972.7]，L1）[订正：原“2009 年后长期使用 Arch Linux”→“2009 年至 2017 年长期使用 Arch Linux”，字幕明确 until twenty seventeen；原“OpenRC 的可文档化”→“OpenRC 熟悉且有完善文档”，字幕原文为 the init system that is familiar and well documented，原译方向反了；时间戳原 [2516.53-2969.63]→[2515.8-2972.7]，Linux 发行版使用史段自 2515.8 起、BSD 许可证更实用结论止于 2972.7，原终点截入该段中部]

**史料**：
