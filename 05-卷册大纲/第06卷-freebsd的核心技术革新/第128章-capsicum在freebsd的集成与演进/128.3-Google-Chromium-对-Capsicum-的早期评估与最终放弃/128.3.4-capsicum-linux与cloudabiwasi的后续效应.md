# 128.3.4 Capsicum-Linux 与 CloudABI/WASI 的后续效应

**要点**：Capsicum 对 Linux 生态的直接影响有限，但其思想通过 CloudABI 和 WASI 产生了间接影响：CloudABI 由荷兰开发者 Ed Schouten（Nuxi 公司）于 2015 年前后开发，是基于 Capsicum 能力模型的跨平台 POSIX 派生 ABI——CloudABI 提供“POSIX 减去全局命名空间”的精简接口，程序编译为 CloudABI 二进制后可在 FreeBSD（natively 支持）、Linux、macOS 上运行，天然具有沙箱属性；CloudABI 于 2020 年 3 月正式宣布弃用（deprecated），原因是社区兴趣不足，开发者 Ed Schouten 转而支持 WebAssembly System Interface（WASI）；WASI（WebAssembly System Interface）是 W3C 社区组标准，为 WebAssembly 提供系统接口抽象，其能力模型设计（以 capabilities/handles 为核心，无全局命名空间访问）继承自 CloudABI/Capsicum 思想；这一演进路径为：Capsicum（FreeBSD OS 原语）→ CloudABI（跨平台纯能力 ABI）→ WASI（WebAssembly 标准化能力系统接口）

**史料**：CloudABI 官方项目 github.com/NuxiNL/cloudabi（README 中 2020-03-30 标记 deprecated 并指向 WASI）；LWN.net 2016-02-10 Neil Brown 文章“CloudABI”（lwn.net/Articles/674770/）；WASI 官方文档 wasi.dev；Ed Schouten 关于 CloudABI→WASI 过渡的说明 ［D］

**史观**：总纲第 4 条——分离聚合是永恒规律〔存疑：原挂“第 25 条——终结与延续”系伪标签，权威表第 25 条为“逻辑是形式主义而非世界本身的结构”，待主理人审定〕：CloudABI 的弃用和 WASI 的兴起标志着能力安全模型从内核级机制向通用运行时抽象的迁移——Capsicum 证明了对象能力模型可以在 UNIX 中产品化，但 OS 级能力模型面临应用改造门槛高、跨平台支持难的问题；WASI 将能力模型提升到语言/运行时层面（WebAssembly 作为平台无关的执行环境），避免了内核改造的门槛，且天然契合 Web 浏览器沙箱需求；Capsicum 的直接部署规模有限，但其设计思想通过 WASI 进入了更广阔的生态系统

**辨析**：原大纲本节标题为“Google 放弃 Capsicum-Linux 与 ANU 质疑”——ANU（Australian National University）的 CHERI/Capsicum 相关“质疑”经检索未找到明确的一手文献对应［据 standalone (2019) 一手文献印证消解 doubt-resolved-640：此处事实待多源交叉验证］；如果指的是 CHERI 硬件能力绕过攻击的学术论文，那属于 CHERI 范畴（74.11 节），与 Capsicum 软件能力模型无直接关系；将“ANU 质疑”作为 Chromium/Capsicum 关系的要点缺乏可靠来源支持，本节改写为“Capsicum-Linux 与 CloudABI/WASI 的后续影响”以反映真实技术演进脉络
