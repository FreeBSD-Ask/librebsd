# 118.8 CHERI 的法律基础——BSD 许可证与硬件合作协议——CHERI ISA 以 BSD 风格许可证发布，但 ARM Morello 原型板（2021-2022 年交付）的硬件设计文档受 ARM 商业许可约束，形成“开源 ISA + 专有硬件”的混合治理结构

## 118.8.1 CHERI ISA 的 BSD 许可证保障

**要点**：CHERI 指令集架构（ISA）规范由剑桥大学和 SRI International 以 BSD 风格的开放许可证发布，允许学术研究、商业实现和开源项目自由使用 CHERI 架构思想；这一许可策略覆盖 CHERI-MIPS、CHERI-RISC-V、CHERI-AArch64（Morello）的 ISA 规范文档、硬件 RTL 代码（CHERI-Piccolo/CHERI-Flute/CHERI-Toooba 等开源 RISC-V 核心在 GitHub 以 BSD 许可发布）、CheriBSD 操作系统（BSD 许可）；CHERI ISA 开放许可的直接成果包括：Codasip 2023 年发布首个商业 CHERI-RISC-V 处理器 IP 核（X730，2024 年正式发布）、Microsoft CHERIoT 嵌入式 CHERI-RISC-V 方案（2023 年 MICRO 论文）、lowRISC Sonata FPGA 开发板（开源硬件）、Google 作为创始成员加入 CHERI Alliance（2024 年 11 月）

**辨析**：CHERI 不同组件的许可证状态需区分：(1) CHERI ISA 规范本身——BSD 风格开放许可；(2) CHERI 开源硬件实现（Piccolo/Flute/Toooba 在 GitHub）——BSD 许可；(3) CheriBSD 软件——BSD 许可；(4) ARM Morello SoC 和开发板硬件设计——ARM 专有，需要商业许可或通过 DSbD 计划获取；(5) CHERIoT（Microsoft 主导的嵌入式 CHERI-RISC-V）——开源但部分组件许可条款需查阅具体仓库 ［据 03-15 (2024) 一手文献印证消解 doubt-resolved-641：此处事实待多源交叉验证］

## 118.8.2 ARM Morello 硬件许可约束分析

**要点**：ARM Morello 是 UKRI DSbD（Digital Security by Design）计划资助的 CHERI-AArch64 原型芯片和开发板，Morello SoC 是 ARM AArch64 架构的超集（superset），实现了 CHERI 压缩能力（128 位）和原型扩展特性；Morello 计划由 ARM 主导，剑桥大学提供架构支持，于 2019 年左右公布，2021-2022 年开始向学术研究者和合作伙伴交付 Morello 开发板；Morello 开发板支持 CheriBSD、Android 和 Linux 的 CHERI 分支版本；但 Morello 是研究原型（research prototype）而非商业产品——ARM 明确将 Morello 定位为评估 CHERI 特性的实验平台，Morello SoC 和硬件设计文档受 ARM 商业许可约束，非完全开源；这意味着：研究者可以获得 Morello 板进行实验，但不能自由制造或修改 Morello 芯片设计

**史料**：Arm Morello Program 官方页面 arm.com/architecture/cpu/morello；The Register 2022-08-26 文章"How Arm popped CHERI architecture into Morello Program hardware"；CheriBSD 22.05 Release Notes（首个正式支持 Morello 的 CheriBSD 版本，2022 年 5 月）；UKRI DSbD 计划页面 ukri.org（£70M UKRI + £100M industry） ［D］ 〔L3 官方文档；L5 二手研究〕

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：原挂“第 12 条——法律结构”系伪标签，权威表第 12 条为“科学是形式主义”〕：Morello 的“开放 ISA 规范 + 专有硬件原型”治理结构折射出半导体行业的特殊约束——芯片制造需要巨大的资本投入（现代 SoC 设计成本数千万至数亿美元），完全开源硬件（如 RISC-V 开源核心）目前主要在 FPGA 或低性能场景可行；ARM 通过 DSbD 公私合作模式承担 Morello 原型芯片制造成本，以有限开放（提供开发板、允许研究使用但保留芯片设计 IP）方式支持 CHERI 生态培育，这是商业芯片厂商参与开源安全架构研究的务实路径

**辨析**：Morello 板的“2021 年发布”时间点需精确——ARM 于 2021 年宣布 Morello 板可用，但大规模交付研究者在 2022 年（CheriBSD 22.05 于 2022 年 5 月发布，正式支持 Morello）；Morello 是否是 ARM 官方产品——Morello 是研究原型板，非商业 ARM CPU 产品，截至 2025 年 ARM 尚未宣布将 CHERI 特性加入商业 ARMv9 处理器内核（Armv9-A 的 MTE（Memory Tagging Extension）与 CHERI 功能有重叠但非 CHERI）

**文献**：Arm Limited. Arm Morello Program. arm.com/architecture/cpu/morello; Robinson, D. (2022-08-26). How Arm popped CHERI architecture into Morello Program hardware. The Register; CheriBSD Project. ## 118.8.3 开源 ISA 与专有硬件的治理比较

**要点**：CHERI 生态中的“开源 ISA + 多种硬件实现（部分开源、部分专有）”格局可与 RISC-V 生态类比：(1) CHERI-RISC-V 方向——RISC-V 本身是开放 ISA，CHERI-RISC-V 扩展正在 RISC-V 国际基金会进行标准化进程（CHERI Ratification Plan），开源 CHERI-RISC-V 核心（Piccolo/Flute/Toooba/CHERIoT/Sonata）以 BSD/Apache 风格许可发布，Codasip 等商业公司提供商业级 CHERI-RISC-V IP 核；(2) CHERI-AArch64/Morello 方向——AArch64 是 ARM 专有 ISA，Morello 原型芯片是 ARM 专有产品；(3) CHERI-MIPS——MIPS 架构本身在 2020 年后转向 RISC-V（MIPS 公司转型），CHERI-MIPS 主要作为早期原型，不再积极发展；对比：RISC-V CHERI 路线有望提供从开源硬件核心到商业 IP 的全开放链条，ARM Morello 路线提供基于主流移动/服务器 ISA 的高性能实验平台但受 ARM 许可约束

**史料**：RISC-V CHERI Ratification Plan（lf-riscv.atlassian.net）；低 RISC Sunburst 项目（lowrisc.org），Sonata 开发板；CHERIoT 项目 cheriot.org（治理组织说明）；Codasip 2024-10-21 公告"Codasip enables secure Linux by donating CHERI RISC-V SDK to the CHERI Alliance"［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：原挂“第 22 条——开源运动”系伪标签，权威表第 22 条为“知识注定过时”，待主理人审定〕：CHERI 的开放 ISA + 多种实现模式代表了硬件安全架构在开源时代的新治理范式——与 1980 年代 Intel iAPX 432（完全专有、商业失败）或 2000 年代 ARM TrustZone（半封闭生态）不同，CHERI 通过开放 ISA 规范建立跨厂商共识，同时允许商业厂商在开放规范基础上开发专有实现（如 ARM Morello、Codasip IP）和开源实现（如 CHERI-RISC-V 开源核心）；CHERI Alliance（2024 年 11 月成立，Google 等为创始成员）旨在加速这一生态系统发展

**辨析**：原大纲本节标题“开源 ISA 与专有硬件的治理比较”准确，但原模板内容空洞无实质技术分析；原文献列表中“Lucas Storage Essentials”等无关文献已替换为 CHERI Alliance、Codasip、CHERIoT、Sonata 等 2023-2024 年最新进展史料；需注意：尽管 CHERI 有 RISC-V 方向的开源实现，但截至 2025 年尚无商用量产的 CHERI 处理器，Morello 和 CHERI-RISC-V FPGA 板均为研究原型

## 118.8.4 CHERI 许可策略史料考证

**要点**：CHERI 许可策略的一手史料可在 CTSRD-CHERI GitHub 各仓库的 LICENSE 文件、CHERI 官方网站 cheri-cpu.org 的使用条款、CheriBSD 源码仓库的版权声明中查阅；CHERI 项目采用的许可证体系整体上是 BSD 风格的宽松许可，但需注意不同组件的细微差别：(1) CHERI ISA 规范文档和技术报告——Cambridge 开放发布，允许学术引用和实现；(2) CHERI 硬件 RTL（Piccolo/Flute 等）——BSD 许可；(3) CheriBSD——BSD 许可（作为 FreeBSD 分支，继承 FreeBSD 的 BSD 许可体系）；(4) LLVM/GCC CHERI 扩展——BSD/Apache 风格许可（继承 LLVM/GCC 的原始许可）；(5) ARM Morello 硬件设计——ARM 专有；CHERI Alliance 2024 年 11 月成立后将扮演产业协调角色，类似于 RISC-V International 在 RISC-V 生态中的角色，但 Alliance 不拥有 CHERI IP，IP 由各成员和学术机构持有

**史料**：CTSRD-CHERI GitHub 组织各仓库 LICENSE 文件（github.com/CTSRD-CHERI）；CHERI Alliance 官方网站 cheri-alliance.org（成立于 2024 年 11 月）；CheriBSD 源码仓库版权头；Cambridge/SRI CHERI 技术报告版权声明 ［A］

**史观**：总纲第 15 条——文化即形式主义〔存疑：原挂“第 3 条——形式主义膨胀”系伪标签，权威表第 3 条为“不存在进步，只有权力再分配”，待主理人审定〕：CHERI 的许可体系在 ISA 规范层面是开放的，但硬件实现层面存在“开源核心（RISC-V）”和“专有实现（ARM Morello、未来商业芯片）”的双轨结构；这种双轨结构与 RISC-V 生态高度类似（RISC-V 国际基金会管理开放标准，商业公司如 SiFive/Andes/Codasip 提供商业 IP，学术界提供开源核心）；关键区别在于：CHERI 作为安全扩展尚未到达 RISC-V 那样的标准化成熟度，RISC-V CHERI 扩展仍在标准化过程中

**辨析**：原大纲本节称“CHERI ISA 以 BSD 许可证发布”需更精确表述——CHERI ISA 规范不是单一许可证文件覆盖的软件项目，而是技术文档和架构规范；具体实现代码（硬件 RTL、软件）使用 BSD 许可，规范本身由 Cambridge/SRI 以允许自由实现的条款发布；“ARM Morello 原型板的硬件设计文档受 ARM 商业许可约束”这一表述准确，但研究者可以通过 DSbD 计划免费获得 Morello 板用于学术研究
