# 144.4.4 2022.12.5 FreeBSD 12.4-RELEASE——riscv64 加入、sparc64 退役与 12.x 终章

**要点**：FreeBSD 12.4-RELEASE 于 2022 年 12 月 5 日发布，是 stable/12 第五个也是最后一个版本（“fifth release”，12.x 系列终版）。核心更新：LLVM 工具链套件升级至 13.0.0（跨度极大——从 12.3 使用的 10.x 直接跳到 13.0.0）；OpenSSL 1.1.1q；OpenSSH 9.1p1；**ena(4)** Amazon ENA 驱动更新至 2.6.1；**if_epair(4)** 支持多核并行流量处理；**unbound(8)** 更新至 1.16.3；**dma(8)** DragonFly Mail Agent 更新至 2022-01-27 快照；**telnetd(8)** 标记为废弃（deprecated）；**tcpdump(1)** 支持为规则设置编号以在 pflog 头中暴露；**file(1)** 更新至 5.43；**libarchive(3)** 更新至 3.6.0。架构列表重大调整：新增 riscv64 与 powerpc64le（小端 PowerPC 64 位），sparc64 正式从发布列表移除——共 10 种架构：amd64、i386、powerpc、powerpc64、powerpc64le、powerpcspe、armv6、armv7、aarch64、riscv64。powerpcspe 重新获得发布镜像。Release Team 精简：Bryan Drewery、Marius Strobl、Remko Lodder、Rodney Grimes、Marc Fonvieille、Hiroki Sato（佐藤広生）、Gleb Smirnoff 等人不再在列，保留 Glen Barber（Lead）、Colin Percival（Deputy Lead）、Konstantin Belousov（康斯坦丁·别洛乌索夫）、Antoine Brodin、Xin Li、Ed Maste。sparc64 退役的主要原因：Oracle 停止 SPARC 处理器开发、Marius Strobl 等主要维护者退出、Clang/LLVM 对 sparc64 后端支持不足。12.4 是 stable/12 终版，EOL 为 2023 年 12 月 31 日。

**史料**：FreeBSD 12.4-RELEASE Announcement（2022-12-05，明确 Clang 13.0.0、riscv64 加入、sparc64 移除、telnetd deprecated、dma 更新、EOL 至 2023.12.31）、FreeBSD 12.4-RELEASE Release Notes、FreeBSD Unsupported Releases 页面确认 EOL 日期；**freebsd.duckdb** `tags` 表 `freebsd-src` 仓库 release tag 数据库验证——`release/12.4.0` tagger_date = 2022-12-05T14:35:22-05:00，tagger_name = Glen Barber，target_commit_hash = `f2877ac4fb03265070b1cf97a07eb0e265bcaff9`，target_commit_date = 2022-11-29T19:02:48-05:00，tag_type = annotated，tag_message =“Tag 12.4-RELEASE”，与公开声明日期 2022-12-05 同日（即 tag 创建当日即正式发布，是 12.x 系列中 tag 与公告日期完全一致的版本之一，反映 12.4 发布过程顺畅）；target_commit_date = 2022-11-29T19:02:48-05:00 早于 tagger_date 约 6 日，反映 tag 指向的 commit 与 tag 创建之间存在 Git 操作延迟（12.4 为 Git 时代发布的版本，时区标记为 -05:00 EST） ［A］

**史观**：总纲第 25 条——终结与延续：12.4 作为 12.x 终版呈现了“新旧交替”的特征——riscv64 的加入代表 RISC-V 开源架构时代的开启，sparc64 的退役标志着 Sun/Oracle SPARC 工作站时代的彻底终结。telnetd 的废弃则呼应了网络安全实践的演进——Telnet 以明文传输密码，自 1990 年代起即被 SSH 取代，标记其废弃是历史必然。

**辨析**：12.4 的 Clang 版本从 10.0.1（12.3）直接跳到 13.0.0，是 12.x 系列中跨度最大的编译器升级，因 stable/12 采用 MFC（Merge From Current）策略选择性合并重要更新；**dma(8)** 在 12.4 更新但 dma 并非默认 MTA——sendmail 仍是 12.x 默认邮件传输代理，dma 作为轻量级替代通过 mta = mailer.conf 可选启用。riscv64 在 12.4 作为 Tier 3 架构首次提供发布镜像，但支持仍为实验性（best-effort），正式 Tier 2 支持在 FreeBSD 13.x/14.x 逐步完善。**数据库验证结论**：`release/12.4.0` tagger_date = 2022-12-05T14:35:22-05:00（EST 时区）与公开声明日期 2022-12-05 完全一致（同日），与 12.1（偏差 0 日）并列 12.x 系列中偏差最小的版本；0 信任原则提示：12.4 为 Git 时代发布的版本（2020 年 12 月 SVN-to-Git 迁移后），tagger_date 为 Git 原生元数据，可信度极高；target_commit_date = 2022-11-29T19:02:48-05:00 早于 tagger_date 约 6 日，反映 tag 指向的 commit 与 tag 创建之间存在 Git 操作延迟，可能与 release engineering 流程中 release branch 冻结后的最终验证有关

**要点**：

- FreeBSD 12.2 引入 special VDEV（metadata classes）：可把元数据（目录内容、时间戳、文件大小等）与可选的小数据块存入专用 SSD VDEV，数据块留在机械盘，从而加速 find、rsync 等元数据密集操作；使用时须镜像元数据 VDEV（丢失元数据则数据近乎无用），且加入既有池后仅新写入文件的元数据迁移过去，需以 send/receive 或等待数据自然修改来迁移。（BSD Now EP376，[569.22-679.88]，L2）
- 12.2 的已知问题：IPFW forward 规则向同一接口多 IP 转发时存在栈损坏导致的随机端口问题，修复将随 12.2-p1 发布；zfs receive 在期待删除旧快照时也有问题并将修复；BeagleBone 因 SD 卡 IO 异常缓慢而暂未提供 12.2 镜像；DVD 安装器内附带的 GDM 版本损坏，需在安装后从上游镜像升级。（BSD Now EP376，[686.3-800.7]，L2）
- 用户空间与基础设施改进：rc.conf 新增 linux_mounts_enable（依赖 linux_enable 挂载 Linux 专用文件系统）；cron 新增 -n 与 -q（成功时不发邮件、不记日志）；dd 新增 conv=fsync/fdatasync/sync 与 iflag=fullblock 等选项；fsck 支持 ms-dosfs；showmount 支持长选项；mountd 修正 map root/map all 的组列出；sesutil 新增面向人读的 show 子命令；jail 工具支持在 jail 内运行 Linux 程序；read 系统调用默认禁止读目录，可用 security.bsd.allow_read_dir 恢复。（BSD Now EP376，[84.16-477.1]，L2）[订正：原 map root/map all 的根目录列出、security.bsd.allow_readdir，2026-09-30 SenseAudio 重转核对]
- certctl 项目由 Alan Jude 发起：把 Mozilla CA 根证书包拆分为单个证书随系统分发，并允许管理员额外信任自签证书或显式不信任某些证书，满足企业在 SSL 拦截设备、管理系统中信任自有证书的需求，由 Kyle Evans 完成落地；virtio 块驱动新增 trim 支持，使 FreeBSD 作为 guest 删除数据时能向 hypervisor 释放空间，bhyve 侧 zvol 也能相应释放。（BSD Now EP376，[234.84-295.3]，L1）
- ZFS per-dataset kstats：kstat.zfs.<pool>.dataset 下按 object ID 为每个数据集提供读写次数与字节数，计数自重启或导入后从零累计，可定位哪个客户或虚拟机在制造磁盘负载；升级时还须更新池与池的 boot 部分。（BSD Now EP376，[485.72-554.12]，L1）
- Klara Systems 的 ZFS 最佳实践研讨会于 11 月 18 日举行，由 Alan Jude 主持，内容覆盖存储阵列硬件选择、RAID-Z 与镜像取舍、special metadata VDEV、随数据增长的规划与池扩展/收缩（device evacuation），以及 dataset 与属性，强调建池早期的决策决定日后能否扩展或收缩。（BSD Now EP376，[822.68-947.34]，L1）
- NetBSD 的 GSoC 2020 最终报告：Ayush Sharma 开发 sys2z 工具链，用 extractor、bear.py、c2xml.py、description.py 四个步骤从 C 设备驱动源码自动提取 ioctl 命令及参数并生成 syscaller 描述文件，以减少手工错误、扩大 syscaller 覆盖；未来工作包括宏检测自动化与函数类型描述，导师为 William Caldwell、Siddharth Muralee、Santosh Raju 与 Kamil Rytarowski。（BSD Now EP376，[958.04-1225.66]，L2）
- OpenBSD stable 包构建基础设施（dataswamp.org）：2019 年夏获 Theo de Raadt 提供硬件后搭建，仅约 110 行 shell；各架构机器每日三次以 cron 更新 CVS ports 树，用 CVS rdiff 求自 release 以来变更的 port 列表，查 SQL ports 数据库展开 flavor/subpackage/multipackage，清理环境后以 make package 编译（dpb 因对 release-stable delta 包构建效果不佳而不适用），送交签名团队人工签名（自动构建者不接触签名密钥），再以 rsync 输出与邮件通知；新设计由一台机器汇总各架构输出、并在构建前统一下载 distfiles 以避免 NFS 并发抓取失败。（BSD Now EP376，[1233.08-1588.12]，L2）[订正：原 清理环境后用 dpb 编译，2026-09-30 SenseAudio 重转核对]
- OPNsense 20.7.4 发布：完成近期的 netmap 内核改动与测试、更新 Realtek 厂商驱动及 kernel、libxml、openssl、php、suricata、syslog-ng、unbound 等第三方组件，并感谢 Sunny Valley Networks 持续把 netmap 修复送入 FreeBSD；WebGUI 支持地址选择、网关组件 API 化、接口 MTU 上限升至 65535（依 RFC 791），防火墙部分新增网络排除/别名类型与 pfInfo 页面。（BSD Now EP376，[1591.02-1720.44]，L2）
- 其他项目动态：DragonFly BSD 把 binutils 回退至 2.34 并暂时改回 ld.bfd，以解决 ld.gold 不尊重 section merge 链接脚本导致 boot1.efi/loader.efi 构建失败的问题（可设 WORLD_LDVER=ld.gold 恢复默认）；NetBSD 的 GitHub 贡献图自 1992 年延续 28 年、1996 年才明显繁忙；OpenBSD 无蓝牙支持，可用 Creative Labs BT-W2 这类把自己呈现为 USB 音频设备的桥接器；社区有基于 FreeBSD/bhyve、CBSD 与 netmap VALE 的 Kubernetes 集群方案，约一分钟 bootstrap，支持 PV/PVC 快照。（BSD Now EP376，[1720.44-2013.24]，L2）
- 反馈环节：Sean 询问 Poudriere 能否全局给 C/C++ 编译器传 -fsanitize 参数，Alan 说明可在 /usr/local/etc/poudriere.d/ 下按 make.conf 层级（全局、包集、ports 树及组合）设置 CFLAGS/CXXFLAGS，从最不特定到最特定拼接，个别必须用 GCC 的 port 可用条件判断排除；Thierry 询问树莓派 loop 挂载镜像的延迟问题，Alan 解释 ZFS 默认 128K record 在 4K 小改时产生读-改-写放大，建议把存放镜像的数据集 record size 调小（如 8K）。（BSD Now EP376，[2189.46-2722.88]，L1）

**史观**：

- 总纲4 分离聚合是永恒规律：special VDEV 把元数据与数据块分离存放、再以池聚合，用布局的分离换取元数据路径的加速，体现存储系统以分离-聚合应对硬件差异的设计。（BSD Now EP376，[579.08-641.7]，L2）
- 总纲13 法律与道德是利益分配：OpenBSD 把签名权留给人工、自动构建者不接触密钥，信任被刻意分配在人与机器之间：安全不是技术自动化的结果，而是权限结构的人为安排。（BSD Now EP376，[1467.38-1480.46]，L2）
- 总纲13 法律与道德是利益分配：certctl 的动机来自企业要信任自签证书以运行 SSL 拦截设备的实际需求：信任存储的设计由部署现场的利益格局反向塑造。（BSD Now EP376，[234.84-264.14]，L1）
- 总纲10 动手者创造历史：NetBSD 28 年贡献图自 1992 年起、1996 年才繁忙，个体贡献者有活跃期与干涸期、有人来去：社区史由无数动手者的断续劳动而非均匀的“进步”曲线构成。（BSD Now EP376，[1778.88-1849.42]，L2）
- 总纲5 没有必然性，只有偶然性：DragonFly 因 ld.gold 的链接脚本处理差异而回退 binutils，工具链“升级”被 EFI bootloader 的现实失败打断：所谓进步被具体硬件的偶然约束重新拉回。（BSD Now EP376，[1738.68-1771.74]，L2）
