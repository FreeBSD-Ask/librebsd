# 125.2.3 D 语言与 awk/C/BPF 程序比较

**要点**：D 语言在语法层面大量借鉴 C：变量声明、类型系统、运算符（算术、逻辑、位运算）、结构体/指针操作、`->` 成员访问等均遵循 C 语义；在程序结构层面借鉴 awk：probe/predicate/action 三元组对应 awk 的 pattern/action 模式；D 与 Linux eBPF 的比较：D 语言专为追踪设计，内置聚合、speculative tracing（推测追踪）、栈跟踪等高级原语；eBPF 是通用内核虚拟机，程序用 C 编写并编译为 eBPF 字节码，功能更通用（网络、安全、追踪）但追踪专用原语需通过 helper 函数实现；D 语言的局限性：不支持用户自定义函数（D 程序只有内联 action，无函数调用抽象）、无循环（只能用条件截断）、无浮点运算（内核中避免浮点状态切换）

**史料**：Cantrill 2004 论文 D Language 节；Gregg 2014-2016 年关于 DTrace vs eBPF 的博客文章；Alexei Starovoitov eBPF 设计文档（Linux 内核源码 Documentation/bpf/ 目录）；Brendan Gregg《BPF Performance Tools》（2019，Addison-Wesley）第 1-2 章（eBPF 与 DTrace 比较） ［A］

**史观**：技术路线分化：D 语言与 eBPF 的设计差异体现了专用语言与通用虚拟机的技术路线分化——D 是追踪专用语言，为追踪场景做了深度优化（聚合、推测追踪、消费者-生产者模型）；eBPF 是通用执行引擎，通过 helper 函数扩展到网络、安全、追踪等多场景；这一分化决定了二者的应用边界

**辨析**：Brendan Gregg 对 eBPF 的评价需精确引用——他在 2014 年《DTrace to eBPF》演讲中梳理了 DTrace 对 eBPF 的技术启发路径，但并非简单称 bpftrace 为“DTrace 2.0”；Gregg 后续积极参与 eBPF 生态开发并著《BPF Performance Tools》，但他多次强调 DTrace 在生产环境追踪方面仍有优势（如任意内核位置的动态追踪）；bpftrace 是 Alastair Robertson 于 2018 年前后开发的基于 eBPF 的追踪工具，语法受 D 语言启发，但 Gregg 称其为“DTrace 2.0”更多是一种定位叙事而非严格技术判断
