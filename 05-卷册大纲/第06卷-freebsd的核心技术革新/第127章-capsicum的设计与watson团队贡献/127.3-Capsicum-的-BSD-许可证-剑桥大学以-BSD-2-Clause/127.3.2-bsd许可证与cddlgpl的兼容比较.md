# 127.3.2 BSD 许可证与 CDDL/GPL 的兼容比较

**要点**：Capsicum 的 BSD 2-Clause 许可证与 GPLv2/GPLv3/LGPL/CDDL 均兼容：(1) 与 BSD 许可证的兼容性——显然完全兼容，FreeBSD 基本系统本身以 BSD 类许可证为主；(2) 与 CDDL 的兼容性——BSD 2-Clause 是宽松许可（permissive），对与之聚合分发的代码无任何许可要求，因此 BSD 许可的 Capsicum 代码可与 CDDL 许可的代码共存；(3) 与 GPL 的兼容性——BSD 2-Clause 是 GPL 兼容的宽松许可证，FSF 明确确认 BSD 2-Clause 与 GPL 兼容（可被 GPL 项目包含）；这与 ZFS/DTrace 使用的 CDDL 形成鲜明对比——CDDL 的文件级 copyleft 与 GPL 的作品级 copyleft 互斥，导致 ZFS/DTrace 无法进入 Linux 主线；Capsicum 因其 BSD 许可，Google 可自由开发 capsicum-linux（BSD 许可内核模块可被 Linux 加载），不存在许可证壁垒

**史料**：FSF 许可证列表 BSD 2-Clause 条目（gnu.org/licenses/lic-list.en.html#ModifiedBSD）；Google capsicum-linux 仓库（BSD 许可）；FreeBSD src 树中 Capsicum 代码位置（sys/kern/ 而非 sys/cddl/contrib/opensolaris/） ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：Capsicum（BSD）与 ZFS（CDDL）在 FreeBSD 中不同的目录放置位置（sys/kern/ vs sys/cddl/contrib/opensolaris/）是许可证差异的直接工程体现——BSD 许可代码可直接融入内核主树，CDDL 代码需放在 contrib 目录以保持许可证边界清晰；但许可证兼容性并未使 Capsicum 在 Linux 上获得比 ZFS 更大的成功——capsicum-linux 长期处于实验状态，最终 Chrome 团队选择了 seccomp-bpf（参见 081.4 节），这证明许可证壁垒只是技术采纳的因素之一，生态惯性与技术集成成本同等重要

**辨析**：capsicum-linux 的许可证状态需精确核实——Google 在 github.com/google/capsicum-linux 发布的 Linux 内核 Capsicum 移植补丁以 BSD 2-Clause 许可发布，但 Linux 内核本身是 GPLv2（仅），BSD 许可的内核模块可加载进 GPL 内核（因为 BSD 与 GPL 兼容），但如果 Capsicum 代码被合入 Linux 主线则需以 GPLv2 发布；Google 从未尝试将 Capsicum 补丁向上游 LKML 提交合并，capsicum-linux 一直作为独立分支维护
