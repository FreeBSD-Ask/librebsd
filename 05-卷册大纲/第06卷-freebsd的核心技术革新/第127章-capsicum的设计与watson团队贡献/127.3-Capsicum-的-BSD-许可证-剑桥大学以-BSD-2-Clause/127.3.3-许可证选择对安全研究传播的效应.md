# 127.3.3 许可证选择对安全研究传播的效应

**要点**：BSD 许可证选择对 Capsicum 传播的影响是双向的：(1) 积极影响——FreeBSD 9.0 直接在 GENERIC 内核中包含 Capsicum 框架（无需单独安装或加载模块），DragonFly BSD 存在 Capsicum 内核补丁，Google 开发了 capsicum-linux 移植，CloudABI（基于 Capsicum 的跨平台 ABI）得以自由开发并在 FreeBSD 中集成，学术界可自由将 Capsicum 用于安全研究项目；(2) 局限性——许可证开放不等于生态采纳：Capsicum 在 FreeBSD 基本系统中的应用长期限于少量工具（tcpdump、dhclient 等），第三方应用对 Capsicum 的沙箱化改造进展缓慢，Linux 主流发行版从未正式采用 Capsicum（Chrome 选择 seccomp-bpf），macOS 使用基于 TrustedBSD MAC 的 Seatbelt 而非 Capsicum；这表明安全机制的传播不仅取决于许可证开放度，更取决于 API 设计、开发者心智模型、以及操作系统厂商的战略投入

**史观**：总纲第 13 条——法律与道德是利益分配〔存疑：原挂“企业研究双重性”不在 25 条总纲权威表，按商业与社区利益关系语义暂挂第 13 条〕：Google 对 Capsicum 的态度体现了企业参与开源安全研究的双重性：Google 资助了 Capsicum 研究（员工 Ben Laurie 参与设计、Google Open Source Program Office 联合资助 Dawidek 的开发工作）、使用 Capsicum 作为 Chrome 沙箱在 FreeBSD 上的原型、发布了 capsicum-linux 移植，但最终在 Chrome 主平台（Linux）上选择了自研的 seccomp-bpf 沙箱而非推进 Capsicum 进入 Linux 主线；企业对学术研究的支持与其产品战略决策之间不存在必然的延续性

**辨析**：“Capsicum 是 FreeBSD 对世界开源安全的重大贡献”这一说法在技术层面成立，但需修正一个误判：Capsicum 的思想影响力（对象能力模型在主流 OS 中的产品化实验）超过其直接部署规模；Capsicum 对后续安全技术的间接影响包括：WASI（WebAssembly System Interface，继承 CloudABI/Capsicum 的能力模型思想，参见 081.4 节辨析）、CHERI 硬件能力架构（为 Capsicum 类沙箱提供硬件强制保护，参见 081.5 节）
