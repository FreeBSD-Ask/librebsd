# 134.11.1 Clang/LLVM 导入与 GCC 4.2.1 作为默认

**要点**：9.0-RELEASE 中 LLVM 编译器基础设施与 Clang 已导入 base 系统（**clang(1)**、**llc(1)** 等工具可用），但 GCC 4.2.1 仍是默认 C/C++ 编译器；GCC 4.2.1 是 GPLv2 许可的最后一个 GCC 版本，FreeBSD 项目因 GPLv3 许可证条款不可接受而无法升级至 GCC 4.3+；9.0 中 Clang 已可编译内核与 world，但作为可选项而非默认；9.1 新增可选 C++11 栈（LLVM libc++ 与 libcxxrt）；**10.0-RELEASE（2014.1.20）才是 Clang 成为默认编译器、GCC 不再默认安装的版本**——9.x 全程 GCC 为默认

**史料**：FreeBSD 9.0/9.1/10.0 Release Notes、FreeBSD Quarterly Status Report 2012 Q1（Clang 默认计划）、David Chisnall（戴维·奇斯纳尔） AsiaBSDCon 2014 论文 “LLVM in the FreeBSD Toolchain” ［B］

**史观**：许可证：Clang/LLVM 替代 GCC 是 FreeBSD 许可证纯洁化工程中规模最大、影响最深远的项目；9.x 两年过渡期为 ports 与第三方软件提供了修复 Clang 兼容性问题的时间窗口；BSD 许可的工具链使 FreeBSD base 系统摆脱了 GPL 许可证代码依赖

**辨析**：原文件和早期一些中文技术文章误称 “9.0 将采用 Clang 取代 GCC”——实际 9.0 Clang 仅作为可选编译器导入，10.0 才默认切换；这一事实混淆源于 2012 年状态报告中 “Clang 将成为 10.0 默认” 的规划被提前误传为 9.0 实现；GCC 4.2.1 是 GPLv2 版本的最后一个 GCC，这是许可证纯洁化的关键事实基础

**文献**：FreeBSD 9.0 Release Notes（Compiler 章节）；FreeBSD 10.0-RELEASE Announcement（明确说明 "GCC is no longer installed by default on architectures where clang is the default compiler"）；Chisnall D. LLVM in the FreeBSD Toolchain [C]//AsiaBSDCon 2014. Tokyo, 2014
