# 134.6.1 ZFS v28 与 dedup、raidz3 支持

**要点**：9.0-RELEASE 将 ZFS 更新至 SPA（Storage Pool Allocator）version 28（zpool version 28），这是 OpenSolaris 时代最后一个开源 ZFS 版本（Oracle 在收购 Sun 后闭源了 ZFS 后续开发）；ZFS v28 新增特性包括：数据重复数据删除（dedup）、三重奇偶校验 RAIDZ（raidz3）、snapshot holds、log device removal、zfs diff、zpool split、zpool import `-F`（强制导入）、只读 zpool import 等；ZFS boot（从 ZFS 根文件系统引导）在 9.0 中技术上可行但需手动配置，bsdinstall 尚未提供自动 ZFS root 安装选项

**史料**：svn r219089（ZFS v28 导入）、FreeBSD 9.0 Release Notes、OpenSolaris ZFS v28 文档、FreeBSD ZFS 邮件列表讨论 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配（原“许可证”系伪名目，按论旨改挂）：ZFS v28 成为 FreeBSD（以及后来整个开源社区）ZFS 演进的基础版本具有历史决定性——Oracle 闭源后，illumos 成为 ZFS 开源开发的主力，FreeBSD 从 illumos 持续移植改进；v28 作为 CDDL 许可的最后共同祖先版本，奠定了 BSD/Linux/macOS ZFS 生态的技术基础

**辨析**：ZFS v28 在 FreeBSD 9.0 中状态为 “Production 但非默认根文件系统”——作为数据存储卷使用已相当稳定，但作为 root 文件系统仍需大量手动调整，不适合普通用户；10.0 时期 bsdinstall 才逐步加入自动 ZFS root 配置
