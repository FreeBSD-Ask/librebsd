# 117.7 CHERI 指令集扩展——2010 年起剑桥大学与 SRI International 联合项目，DARPA CRASH 计划资助，扩展 RISC 指令集实现硬件级能力安全

## 117.7.1 CHERI 指令集扩展的技术原理

**要点**：CHERI（Capability Hardware Enhanced RISC Instructions）是剑桥大学计算机实验室与 SRI International 联合开发的硬件能力架构，始于 2010 年 DARPA CRASH（Clean-slate design of Resilient, Adaptive, Secure Hosts）计划；CHERI 的核心思想是在现有 RISC 指令集（MIPS-64、AArch64/Morello、RISC-V）中添加硬件支持的能力（capability）类型——每个指针被替换为一个“能力”（Capability），后者在 64 位架构上以 128 位或 256 位压缩表示（CHERI Concentrate 压缩方案将能力压缩至 128 位），包含：基地址（base）、长度/界限（length/bounds）、权限位（permissions，读/写/执行/系统等权限）、对象类型（object type，用于密封能力）和标记位（tag bit，1 位标记该内存位置是否持有有效能力）；标记位受硬件保护，任何对能力的非法修改（如指针算术越界、伪造能力）都会使标记位清零，该能力即变为无效；CHERI 硬件在每次加载/存储/跳转时检查能力权限和边界，从芯片层面防止缓冲区溢出、use-after-free 等内存安全漏洞

**史料**：Woodruff et al. 2014 ISCA 论文"The CHERI capability model: Revisiting RISC in an age of risk“（CHERI 架构首篇 ISCA 论文）；Watson et al. 2015 IEEE S&P 论文”CHERI: A Hybrid Capability-System Architecture for Scalable Software Compartmentalization“；Woodruff et al. 2019 IEEE TC 论文”CHERI Concentrate: Practical Compressed Capabilities"（128 位压缩）；CHERI 官方网站 cheri-cpu.org ［D］ 〔L4 事后叙述；L5 二手研究〕

**史观**：总纲第 1 条——项目统摄史观：CHERI 是硬件安全架构的“范式时刻”——它将软件层面难以彻底解决的内存安全问题（C/C++ 程序中约 70% 安全漏洞源于内存安全问题，Microsoft 2019、Chrome 2020 数据）上移到硬件指令集层解决，这是自 1980 年代 capability architectures（CAP computer、Intel iAPX 432）失败以来，能力硬件架构首次在主流 RISC 指令集上获得工业界（Arm、Microsoft、Google、Codasip）的严肃投入；CHERI 与 Capsicum 分别代表能力模型的硬件层和软件层实现，二者互补

**辨析**：CHERI 不是“新指令集架构”而是“指令集扩展”——CHERI 扩展现有 ISA（MIPS、AArch64、RISC-V），保留原有非能力指令的完整支持，可运行未修改的传统二进制（但无安全收益）；软件必须重新编译为纯能力 ABI（如 CheriABI）才能获得完整内存安全保护；Cambridge 团队研究表明，移植约 600 万行 C/C++ 代码到 CHERI 仅需修改 0.026% 的源代码行（Watson et al. 2021 Capabilities Ltd 报告）

## 117.7.2 剑桥与 ARM 及 SRI 的合作过程

**要点**：CHERI 项目起源于 2010 年 DARPA CRASH 计划——CRASH（Clean-slate design of Resilient, Adaptive, Secure Hosts）是 DARPA 在 2010 年启动的安全研究项目，旨在从头重新设计安全计算机系统；剑桥大学（罗伯特·N. M. 沃森（Robert Watson）领导，Simon W. Moore 负责硬件，Jonathan Woodruff 负责 ISA 设计）与 SRI International（Peter G. Neumann 共同 PI，Peter Neumann 是 1960 年代 Multics 项目的贡献者，也是 PSOS 能力系统参与者，被誉为计算机安全领域的泰斗）联合团队获得 DARPA 资助；最初 CHERI 原型在 MIPS-64 上实现（2012 年 RESoLVE 研讨会论文报道早期原型，2014 年 ISCA 论文报道完整能力模型，同年演示运行 FreeBSD）；Arm 于 2015 年加入项目并提供关键反馈——Arm 指出将指针大小从 64 位增至 256 位（四倍）不可接受，但增至 128 位（两倍）尚可接受，这直接推动了 CHERI Concentrate 压缩方案（128 位能力）的开发；Morello 板（Arm CHERI 原型 SoC）是 UKRI DSbD（Digital Security by Design）计划（2020 年启动，£70M UKRI + £100M 工业投资）的核心成果，2021-2022 年开始交付

**史料**：DARPA CRASH 项目页面 darpa.mil/research/programs/clean-slate-design-of-resilient-adaptive-secure-hosts；Woodruff et al. 2012 RESoLVE 研讨会论文；Woodruff et al. 2014 ISCA 论文（MIPS 原型）；UKRI DSbD 项目页面 ukri.org；Arm Morello Program 页面 arm.com/architecture/cpu/morello；The Register 2022-08-26 文章"How Arm popped CHERI architecture into Morello Program hardware" ［D］ 〔L3 官方文档；L5 二手研究〕

**史观**：企业研究双重性：CHERI 项目是学术界（Cambridge）、政府研究机构（SRI）、国防资助机构（DARPA）、商业芯片厂商（Arm）协作的典型案例：DARPA 提供高风险高回报的长期基础研究资助，Cambridge/SRI 完成核心架构与软件设计，Arm 提供产业视角和硬件实现反馈，UKRI DSbD 资助推动 Morello 原型板制造；这一模式与 1960-70 年代 ARPANET/Multics/TCP/IP 的研发模式一脉相承——政府资助长期基础研究，工业界参与原型验证和产品化

**辨析**：原大纲标题称“2012 年起剑桥大学与 ARM 合作的研究项目，2015 年 SRI International 加入”有事实错误：SRI 是 CHERI 创始合作伙伴，2010 年项目启动时即参与（Peter G. Neumann 是 SRI 资深科学家、共同 PI），Arm 于 2015 年加入；原标题时间线颠倒，已修正为“2010 年起剑桥大学与 SRI International 联合项目，DARPA CRASH 计划资助，Arm 2015 年加入并推动 Morello 原型”；Morello 板交付时间——Arm 于 2019 年前后公布 Morello 计划，2021 年底/2022 年初开始向研究者交付 Morello 开发板

Digital Security by Design Programme. ukri.org; Arm Limited. Morello Program. arm.com/architecture/cpu/morello; Robinson, D. (2022-08-26). ## 117.7.3 CHERI 与纯软件安全方案的比较

**要点**：CHERI 硬件能力架构与纯软件内存安全/沙箱方案（ASLR、Stack Canaries、Control-Flow Integrity CFI、软件沙箱如 Capsicum/seccomp-bpf/pledge、AddressSanitizer 等）的根本差异在于：软件方案通常是“概率性防御”或“攻击面缩减”，可被绕过；CHERI 提供确定性（deterministic）硬件强制保护——能力越界访问、非法指针伪造、use-after-free（配合回收机制如 Cornucopia）在硬件层面被直接阻止；关键数据：Microsoft 2019 年 Security Response Center 分析显示 CHERI 可缓解其产品中约 70% 的内存安全漏洞（MSRC 2020-10-14 博客）；Chrome/Google 2020 年报告称其 70% 的严重安全漏洞是内存安全问题（ZDNET 2020-05-22）；但 CHERI 需要硬件支持——在非 CHERI 硬件上无法获得这些保护；软件方案（如 Capsicum 沙箱、seccomp-bpf、W^X、ASLR）无需新硬件，可在现有 CPU 上部署

**史料**：Microsoft Security Response Center 2020-10-14 博客“Security Analysis of CHERI ISA”（msrc.microsoft.com/blog/2020/10/security-analysis-of-cheri-isa/）；ZDNET 2020-05-22 报道“Chrome: 70% of all security bugs are memory safety issues”；Filardo et al. 2020 IEEE S&P 论文“Cornucopia: Temporal Safety for CHERI Heaps”（use-after-free 防护）；Watson et al. 2024 IEEE Security & Privacy 论文“CHERI: Hardware-Enabled C/C++ Memory Protection at Scale” ［B］

**史观**：总纲第 6 条——技术路线分化：CHERI 代表“以硬件变革解决软件安全问题”的激进路线，软件安全方案代表“以软件工程缓解硬件架构缺陷”的渐进路线；两条路线长期并行——在 CHERI 硬件普及之前（可能需要十年或更长时间），软件沙箱和内存安全语言（Rust、Go、Java、C# 等）将继续承担主要防御角色；CHERI 与 Rust 的关系也需关注：Rust 通过编译器类型系统在软件层面保证内存安全（无数据竞争的内存安全），CHERI 通过硬件在指令集层保证内存安全，二者可互补

**辨析**：对 CHERI 的常见误解需纠正：(1) “CHERI 让软件不可被攻击”——不准确，CHERI 主要解决内存安全漏洞（空间/时间内存安全），不直接解决逻辑漏洞、权限配置错误、侧信道攻击等其他安全问题；(2) “CHERI 需要完全重写软件”——不准确，CheriABI 支持逐进程混合运行纯能力程序和传统程序，且源代码修改量极小（0.026%）；(3) “CHERI 性能开销巨大”——早期 256 位能力设计确有开销，但 CHERI Concentrate（128 位）和微架构优化后典型开销在个位数百分比范围（具体数值因工作负载而异）

**要点**：

- Brooks Davis 自述 CHERI 是剑桥大学与 SRI International 开发的能力硬件扩展，以不可伪造的 capability 替代裸指针，为分配空间附加边界与标签，从而在架构层阻断缓冲区溢出，并抑制大部分时序内存安全漏洞。（BSD Now EP486，[419.69-546.33]，L1）
- Morello 是由 UKRI“Digital Security by Design”计划与 ARM 共同出资的全尺寸原型芯片，在 ARM N1（Amazon Graviton 所用核型）上加入 CHERI，从架构到 tape out 仅用一年，制造成本逾一亿英镑；其目标之一是打破软件界不愿面向不存在硬件编程、硬件界不愿制造无人使用硬件的僵局。（BSD Now EP486，[583.47-774.5]，L1）
- Brooks Davis 称 CheriBSD 是首个在 Morello 上开发的操作系统；团队十年前从 64 位 MIPS 起步将 FreeBSD 移植为 CheriBSD，此后并行开展 RISC-V 与 ARM 端口，并自动化了 FreeBSD 兼容层创建，使新增系统调用时只需正确标注即可判断是否需要兼容函数。（BSD Now EP486，[821.15-999.65]，L1）
- Olivier Cochard-Labbé 自述 2005 年为搭建家用 NAS 修补 m0n0wall 防火墙时偶然发现其底层并非 Linux 而是 FreeBSD，遂将防火墙配置替换为 Samba 配置，由此创建 FreeNAS；FreeNAS 最初只是面向家庭文件共享的 PHP Web 界面加 gvinum RAID 方案。（BSD Now EP486，[1225.45-1346.59]，L1）
- Olivier 自述 FreeNAS 迅速被社区广泛采用，甚至被巴西城市用于存储监控视频，超出其业余维护能力，最终将项目交给 iXsystems；此后他创立强调命令行接口、贴近原生 FreeBSD 的 BSD Router Project，并在约四年前进入 Netflix 从事网络性能基准工作。（BSD Now EP486，[1606.01-1909.91]，L1）

**史观**：

- 总纲12 科学是形式主义：Brooks Davis 提出 CHERI 的“intentional use”原则，认为程序员分配对象时的意图应被固化到硬件能力中，而非退化为普通内存数字，反映技术设计是对既有编码意图的形式化表达。（BSD Now EP486，[546.33-581.32]，L1）
- 总纲5 没有必然性，只有偶然性：Olivier 的 FreeNAS 并非出于商业计划，而是个人为家用 NAS 修补 m0n0wall 的副产品，其成功具有明显偶然性。（BSD Now EP486，[1225.45-1346.59]，L1）
- 总纲9 经验优先：Olivier 创建 BSD Router Project 的动机是让熟悉 FreeBSD 的管理员无需学习 Web 界面即可复用既有经验，坚持命令行操作，体现经验优先的开发取向。（BSD Now EP486，[1752.81-1793.76]，L1）
- 总纲6 和解优于斗争：CHERI 的混合过渡模型体现了新旧范式之间的和解路径：历史上的能力系统虽能杜绝缓冲区溢出与对象误用，却缺乏向后兼容故事，而 CHERI 的处理器可不加修改地运行常规混合二进制，内核改动保持很小，再以注解方式逐指针升级为受边界检查的能力，形成从未修改 MIPS 代码到纯能力代码的谱系，使新硬件范式不以致断裂的方式替代旧生态。（BSD Now EP139，[1554.3-1645.5]，L1）[订正：原 [1568.26-1629.54]，2026-09-30 SenseAudio 重转核对]
- 总纲22 知识注定过时：主持人转述的博客文章以 OpenBSD 为例主张软件知识必然老化：与 Unix 同龄的手册页处理被重写得更简单安全，doas 以覆盖 sudo 的绝大多数使用场景而更易用更安全，1993 年加入基础系统的工具同样可以成为重写候选；同时重写须有节制，不应效仿 JavaScript 生态的频繁重造，而应瞄准 Hadoop 或浏览器这类层层叠加的臃肿系统，简化重写由此成为技术史上持续发生的常态而非线性进步的注脚。（BSD Now EP139，[2580.1-2747.8]，L2）[订正：原 [2594.16-2741.76]，2026-09-30 SenseAudio 重转核对]
