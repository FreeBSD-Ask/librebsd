# 112.14 重要贡献者与边缘者：ZFS 早期移植者与 OpenZFS 协调者

## 112.14.1 ZFS 早期移植者的贡献梳理
  - 要点：ZFS 在各平台的早期移植者：（1）Pawel Dawidek（pjd@）——FreeBSD ZFS 移植的核心开发者，波兰开发者，FreeBSD committer，2006-2007 年完成 ZFS 到 FreeBSD 的移植，包括 Solaris API 兼容层（solaris/ directory），commit r177621（2008 年 3 月）是关键里程碑；（2）Brian Behlendorf（布莱恩·贝伦多夫）——ZFS on Linux（ZoL）创始人，2008 年启动 Linux 移植，LLNL（Lawrence Livermore National Laboratory）雇员，其工作使 ZFS 在 Linux 上可用，ZoL 后来成为 OpenZFS 2.0 的基础代码库；（3）illumos 社区——2010 年 Oracle 关闭 OpenSolaris 后，Garrett D'Amore（加勒特·达莫尔） 等人发起 illumos fork，维护 OpenSolaris 代码继续发展，成为 ZFS 上游的重要来源；（4）Matt Ahrens——ZFS 联合设计者，Bonwick 离开 Sun/Oracle 后 Ahrens 成为 OpenZFS 社区技术领袖之一，Delphix 公司雇员，持续贡献 ZFS 代码至今；（5）其他重要移植者：Adam Leventhal（Delphix）、George Wilson（Delphix/Oracle）、Andriy Gapon（FreeBSD ZFS 维护者）、Martin Matuska（FreeBSD ZFS，后加入 OpenZFS 协调）

  - 史观：总纲第 25 条——终结与延续：ZFS 的延续不是由 Sun/Oracle 决定的，而是由一群分散在不同公司和社区的开发者共同维系的——Dawidek 在波兰、Behlendorf 在 LLNL、Ahrens 在 Delphix、illumos 社区独立 fork，这些 “边缘者” 的努力使得 ZFS 在 Oracle 闭源后得以延续和发展
  - 辨析：ZFS 移植的历史常被简化为 “Pawel Dawidek 移植到 FreeBSD”，但实际上早期 ZFS 移植是多人协作：Dawidek 是核心人物，但罗伯特·N. M. 沃森（Robert Watson）、Kip Macy 等人也参与了早期工作；ZoL 早期并非 “官方” 移植，而是 Behlendorf 的个人/LLNL 项目，直到 2010 年代中期才获得广泛认可

## 112.14.3 许可证壁垒对贡献者的效应
  - 要点：CDDL-GPL 不兼容对 ZFS 贡献者生态产生了深远影响：（1）Linux 内核开发者无法直接贡献 ZFS 代码——Linux 内核主线（GPLv2）无法接受 CDDL 代码，因此内核开发者不会参与 ZFS 开发，反之亦然；（2）发行版面临法律风险选择——Red Hat 等商业发行版选择不支持 ZFS 以规避法律风险，Ubuntu 选择通过 DKMS 方式支持但承担争议；（3）贡献者分流——ZFS 贡献者主要集中在 FreeBSD/illumos/OpenZFS 社区，Linux 内核社区几乎不参与 ZFS 开发；（4）双轨开发——OpenZFS 2.0 之前 FreeBSD 和 ZoL 各自维护独立的移植层，重复劳动严重；（5）人才流动限制——受雇于 Linux 公司（如 Red Hat）的工程师难以参与 OpenZFS 开发，受雇于 BSD/存储公司（如 iXsystems、Delphix、LLNL）的工程师可以自由参与；这一许可证壁垒是 ZFS 无法在 Linux 上获得与 FreeBSD 同等地位的根本原因
  - 史料：CDDL §3.2 与 GPLv2 §2(b) 条款对比；FSF 2005 年不兼容声明；Ubuntu 2016 年 ZFS 决议；Red Hat 不支持 ZFS 声明；OpenZFS 贡献者统计[考据完成：2026-07-28 经穷尽联网考据，上述史料清单为已知公开来源汇总，部分原始档案未公开数字化或须档案馆藏地现场核验，属史料缺口，须待原始档案公开后方可补充确证]
  - 史观：总纲第 24 条——许可证：CDDL-GPL 的许可不兼容不仅是法律文本问题，更直接塑造了开发者社区的边界——一个工程师是否能为 ZFS 贡献代码，很大程度上取决于其雇主所支持的生态系统和许可立场；这验证了 “许可证条款决定代码流动边界” 的历史规律
  - 辨析：需区分 “公司政策” 和 “法律强制”：Red Hat 不支持 ZFS 主要是法律风险规避和商业策略（Red Hat 有自己的存储产品 Stratis），而非明确的法律裁决从未认定 ZFS on Linux 违法；Canonical（Ubuntu）选择支持 ZFS 是基于 SFLC 的法律意见（二进制模块分发不构成衍生作品），但这一意见并非法庭判决；两个发行版的不同选择反映了法律灰区中的商业判断

## 112.14.4 贡献者记录的史料辨析
  - 要点：ZFS 贡献者记录中的几个关键辨析点：（1）Jeff Bonwick（杰夫·邦威克） 是 ZFS 的发明者和架构师，但他在 2010 年 Oracle 收购 Sun 后离开 Oracle，此后较少参与 OpenZFS 开发，当前 OpenZFS 开发由 Matt Ahrens 等人主导——不应将 ZFS 完全等同于 Bonwick 的个人项目；（2）Pawel Dawidek 虽然是 FreeBSD ZFS 移植的核心，但 2010 年代中期后他的工作重心转向其他 FreeBSD 子系统，FreeBSD ZFS 维护后续由 Martin Matuska、Andriy Gapon 等人接手；（3）Brian Behlendorf 不是 Apache Web 服务器的 Brian Behlendorf（同名同姓的两个不同开发者——Apache 的 Brian Behlendorf 是开源软件的早期先驱，ZoL 的 Brian Behlendorf 是 LLNL 的工程师，这一混淆在中文资料中很常见）；（4）许多 ZFS 贡献者来自商业公司（Delphix、iXsystems、LLNL、Joyent），他们的工作是公司雇佣劳动的一部分，不是 “业余志愿者贡献”；（5）illumos 社区在 2010-2020 年间是 OpenZFS 的事实上游，所有平台（包括 FreeBSD 和 ZoL）都从 illumos 同步代码，直到 OpenZFS 2.0 实现统一代码库后这一模式才改变
  - 史料：OpenZFS GitHub commit 统计（github.com/openzfs/zfs/graphs/contributors）；FreeBSD SVN commit log；illumos commit log；LinkedIn/公司博客确认各贡献者身份 ［A］
