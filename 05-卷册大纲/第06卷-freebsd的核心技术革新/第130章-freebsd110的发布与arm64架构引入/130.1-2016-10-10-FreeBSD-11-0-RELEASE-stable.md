# 130.1 2016.10.10 FreeBSD 11.0-RELEASE——stable/11 分支起点与 arm64 引入

## 129.1.1 发布工程语境与核心特性

**要点**：FreeBSD 11.0-RELEASE 于 2016 年 10 月 10 日由 Release Engineering Team 正式发布，是 stable/11 分支首个版本，Release Engineering Lead 为 Glen Barber（格伦·巴伯）（gjb@），Marius Strobl 任 Deputy Lead。11.0 支持 amd64、i386、powerpc、powerpc64、sparc64、armv6、aarch64 共七种架构，正式移除 IA-64（Itanium）架构支持（commit `e7d939bda22b` "Remove ia64."由 Marcel Moolenaar 于 2014-07-07T00:27:09Z 提交，11.0 生效；前置 commit `50f73640baa7` "Remove ia64 from the list of known architectures and add an entry to UPDATING."由 Marcel Moolenaar 于 2014-07-02T22:34:06Z 提交；Glen Barber 于 2014-07-08T14:42:44Z 提交 `d9fa41e1a175` "Document r268351, end of ia64 support."在 relnotes 中正式记录此变更）。核心编译器升级至 Clang/LLVM 3.8.0（r296417，由 Steven Kreuzer 于 2016-04-21T14:20:45Z 在 `b8df8f9a8df79fe6282e4c0f0cdd5c6f7e267a91` "Document r296417, clang, llvm, etc. updated to upstream 3.8.0"中正式记录），OpenSSH 更新至 7.2p2（默认禁用 DSA 密钥生成、移除 SSH Protocol 1 支持）。献词页纪念五位逝去的社区成员：Stefan Farfeleder、Juergen Lock、Ben Perrault、Paul Schenkeveld、Volker Werth。11.0 发布时因最后时刻发现问题重建镜像，**uname(1)** 显示为 11.0-RELEASE-p1，从早期镜像升级的用户须立即应用补丁。

## 129.1.2 **vt(4)** Newcons 默认控制台替换 **syscons(4)**

**要点**：**vt(4)**（Newcons 项目）在 FreeBSD 11.0 正式成为默认控制台驱动，替换了自 BSD 时代沿用近三十年的 **syscons(4)**。**vt(4)** 主要开发者包括 Ed Schouten（ed@）、Marius Strobl（marius@）等人，FreeBSD Foundation 赞助了部分开发工作。10.x 时期 **vt(4)** 已合并但需通过 `kern.vty=vt` loader 变量手动启用，11.0 起此变量默认即为 vt，**syscons(4)** 仍保留但不再是默认。**vt(4)** 核心优势：原生支持 KMS（Kernel Mode Setting）驱动，可与 **drm2(4)** Radeon/Intel GPU 驱动配合实现高分辨率控制台；完善的 Unicode/UTF-8 终端支持；多显示器支持；与 Xorg 图形系统更平滑的切换；支持集成到 bhyve 图形 framebuffer 中。**syscons(4)** 因架构设计局限无法支持现代 GPU 的 KMS 模式切换，其退役是图形栈现代化的必然步骤。

**史料**：FreeBSD 11.0-RELEASE Release Notes（Kernel Configuration 章节关于默认控制台的说明）、vt(4) 手册页、Ed Schouten BSDCan 2013"Newcons: FreeBSD's New Console Driver"演讲、svn commit 记录中 GENERIC 内核配置文件关于 `kern.vty` 默认值变更的提交。 ［A］

**史观**：总纲第 5 条——技术债务与代码考古：**syscons(4)** 代表了 1980 年代 Unix 控制台的设计范式——文本模式、VGA 兼容、单显示器假设；**vt(4)** 则面向 2010 年代的硬件现实——高分辨率显示、多显示器、GPU 加速、Unicode 全球化。这种“默认值切换”看似简单，但从 **vt(4)** 项目启动（约 2008 年）到默认启用历时近八年，体现了 BSD 项目对核心基础设施变更的极度审慎——**syscons(4)** 是用户每次登录都要交互的组件，任何回归都将影响所有用户。

**辨析**：部分资料称“**syscons(4)** 在 11.0 被移除”——经 GENERIC 内核配置与 Release Notes 核实，**syscons(4)** 仍保留在 11.x 内核源码中，用户可通过 `kern.vty=sc` 切换回旧控制台；**syscons(4)** 从 GENERIC 中移除发生在更晚版本（FreeBSD 13.0 前后）。另有说法称“**vt(4)** 在 10.3 默认启用”——经 10.3 Release Notes 与 10.x GENERIC 配置核实，10.x 全系列默认仍为 **syscons(4)**，**vt(4)** 需手动启用；默认切换至 **vt(4)** 确为 11.0。

**文献**：Schouten E. Newcons: FreeBSD's New Console Driver [C]//BSDCan 2013. Ottawa, 2013；FreeBSD vt(4)/syscons(4) Manual Pages [Z]；FreeBSD 11.0-RELEASE Release Notes [Z]. 2016.

## 129.1.3 arm64/AArch64 正式支持与架构 Tier 体系

**要点**：FreeBSD 11.0 首次正式支持 AArch64（又称 arm64）架构，由 Andrew Turner（andrew@）等开发者主导移植，FreeBSD Foundation 持续赞助开发。与 10.x 时期 arm64 仅存在于 -CURRENT 分支不同，11.0 为 aarch64 提供正式发布镜像（ISO/memstick/SD 卡/VM 镜像）、预构建 pkg 包、安全更新与勘误支持，列为 Tier 2 架构。arm64 移植工作始于约 2014 年，11.0 发布时已支持 SMP 多核、UEFI 引导、GICv3 中断控制器、PCIe、virtio 虚拟化设备等核心功能，可运行在 QEMU 虚拟机、SoftIron Overdrive 1000 开发板、Raspberry Pi 3（后续 11.x 完善）等平台。Andrew Turner 在 BSDCan 2016 发表"FreeBSD on ARM64"演讲系统介绍了移植过程。amd64 与 i386 为 Tier 1 架构（由 Release Engineering Team 完全支持、blocker 级别处理问题），arm64、armv6、powerpc、powerpc64、sparc64 为 Tier 2（best-effort 支持）。arm64 升级为 Tier 1 发生在 FreeBSD 13.0-RELEASE（2021 年 4 月）。ARM 公司于 2014 年决定赞助 FreeBSD Foundation 并动员包括 Cavium 在内的厂商参与，以推动 ARMv8 在 FreeBSD 上获得 Tier 1 架构支持（ARM, 2016）；硅片厂商 Cavium 向 Semihalf 提供早期开发板，并向 Sentex 托管设施捐赠初始开发服务器，使更多开发者能接触服务器硬件（ARM, 2016）。
