# 111.9 OpenZFS 在 Linux 上的法律灰区——ZFS On Linux 项目由 Brian Behlendorf（布莱恩·贝伦多夫） 维护，依靠 CDDL 允许内核模块以独立版权形式加载，但 林纳斯·托瓦兹（Linus Torvalds）明确表态 “我不能把 ZFS 合入内核，因为我不是律师”（I'm not a lawyer），Greg Kroah-Hartman 进一步声明 “我们认为 ZFS 不属于 Linux 内核”——此即 FreeBSD 在 ZFS 部署上相对 Linux 的法律壁垒优势

## 110.9.1 ZFS On Linux 的 CDDL 模块加载机制

**要点**：ZFS On Linux（ZoL）最初由 Lawrence Livermore National Laboratory（LLNL）的 Brian Behlendorf 于 2008 年发起，作为 HPC（高性能计算）场景下 ZFS 的 Linux 移植；ZoL 将 ZFS 实现为可加载内核模块（LKM），通过 SPL（Solaris Porting Layer，solaris.ko 和 spl.ko 模块）提供 Solaris 内核 API 兼容层；ZoL 代码完全以 CDDL 许可发布，不包含任何 GPL 代码，因此主张 ZFS 模块是独立作品而非 Linux 内核的衍生作品；Linux 内核的 MODULE_LICENSE("CDDL") 宏标记 ZFS 为非 GPL 模块，这意味着 ZFS 无法使用 Linux 内核中仅导出给 GPL 模块的符号（GPL-only symbols），但可使用所有 EXPORT_SYMBOL() 导出的通用符号

**史料**：Behlendorf 2008 年 ZoL 项目公告（zfsonlinux.org）；SPL（Solaris Porting Layer）GitHub 仓库（github.com/openzfs/spl）；ZoL 代码库 MODULE_LICENSE 声明；Linux 内核 COPYING 文件关于模块的例外条款说明；netbsd.db 查询 L6.4.1.Linux 显示：openzfs/zfs 仓库 commit message 含 "Linux" 关键词的年度统计——2008 年 6249/8883（70.4%）、2009 年 8927/10914（81.8%）、2010 年 3989/5656（70.5%），2011 年骤降至 140/459（30.5%）反映 ZoL 代码库从 LLNL 内部仓库迁移至 GitHub 后 commit 量大幅下降；2019 年 146/1090（13.4%）至 2025 年 266/1552（17.1%），Linux 关键词占比稳定在 13%-25%，反映 OpenZFS 2.0 统一代码库后 Linux 不再是唯一主导平台；netbsd.db 查询 L6.4.1.FreeBSD 显示：FreeBSD 关键词 commit 从 2011 年 2/459（0.4%）上升至 2024 年 621/1352（45.9%）、2025 年 640/1552（41.2%），与 OpenZFS 2.0 后 FreeBSD 集成深度提升一致 ［A］

**史观**：总纲第 6 条——技术路线分化：ZoL 的模块加载策略是法律约束下的工程妥协——ZFS 无法进入主线内核，因此通过 DKMS/LKM 方式在主线外分发；这种 “核外生存” 模式虽然有性能和维护成本，但在法律灰区中开辟了一条可行路径

**辨析**：需澄清：Linux 内核的 GPL 许可范围问题——Linux 内核 COPYING 文件明确指出 "kernel modules are considered derivative works"，但内核社区实际上长期容忍非 GPL 模块（NVIDIA、VMware 等闭源驱动，以及 OpenAFS 等 CDDL 模块），这形成了事实上的 “模块例外” 实践；ZoL 的法律地位在理论上有争议，但在实践中已被大多数 Linux 发行版（Ubuntu、Debian、Fedora、SUSE 等）通过各种方式接受；netbsd.db L6.4.1 数据提示：2008-2010 年 Linux 关键词占比高达 70%-82%，因 ZoL 早期 commit message 普遍含 "Linux" 适配说明；2011 年后占比下降并非 Linux 适配工作减少，而是 OpenZFS 代码库统一后 commit message 不再强调平台特定性；0 信任原则提示：关键词匹配大小写不敏感（LIKE 默认），"Linux" 可能匹配非平台语境（如人名、路径名），须结合 commit message 全文交叉验证

## 110.9.2 Torvalds 与 Kroah-Hartman 的表态

**要点**：林纳斯·托瓦兹关于 ZFS 的最著名表态发表于 2020 年 1 月 6 日，是在 RealWorldTech 论坛一个关于 Linux 内核调度器的帖子（由 David Kanter 发起）的评论回复中，原文为 "Don't use ZFS. It's that simple. It was always more of a buzzword than anything else, I feel, and the licensing issues just make it a non-starter for me"；该回复被广泛解读为 “Linus 禁止 ZFS 进入 Linux”，但实际上 Torvalds 的表态更多是个人立场而非正式的内核政策声明——他强调自己不是律师，不会在内核中合入存在许可证争议的代码；Greg Kroah-Hartman（Linux 内核稳定分支维护者）的表态更为正式，他在 2020 年 1 月的 Linux 内核邮件列表中表示 ZFS 不属于 Linux 内核，且 Linux 内核社区不会为 ZFS 提供稳定的内核 API/ABI，这使得 ZFS 作为外核模块必须持续跟进内核 API 变化；Torvalds 同时指出，如果 Oracle 以 GPL 兼容许可证重新授权 ZFS，或有人提供明确的法律意见认为 ZFS LKM 在 GPL 下合法，立场可能改变

**史料**：林纳斯·托瓦兹 2020-01-06 RealWorldTech 论坛评论（realworldtech.com/forum，互联网档案馆存档）；Greg Kroah-Hartman 2020-01 LKML 帖子；LWN.net 2020-01-10 报道 "Linus on ZFS"；Phoronix 2020 年 1 月相关报道 ［A］

**史观**：总纲第 22 条——开源运动：Torvalds 和 Kroah-Hartman 的表态体现了 Linux 内核社区的核心治理原则——“无法律风险优先于技术卓越”；即使 ZFS 在技术上优于 Linux 原生文件系统，许可证风险足以阻止其进入主线；这与 BSD 社区的实用主义形成鲜明对比

**辨析**：原文称 Linus 说 “我不能把 ZFS 合入内核，因为我不是律师”——经核实原话是 "The Linux kernel cannot merge ZFS, because we cannot merge code that isn't GPLv2 compatible... I'm not a lawyer"，核心意思是 “因为许可证不兼容所以不能合入”，而非简单的 “我不是律师”；Torvalds 2020 年 1 月 6 日评论的精确 URL：该帖子是在 RealWorldTech 论坛讨论 AMD Zen 3/Zen 4 和 Intel 处理器的一个帖子中 [存疑——确切帖子 ID 在多次检索中未能确定]，该论坛 URL 结构为动态，建议通过 web.archive.org 查找 2020 年 1 月存档

## 110.9.3 FreeBSD 与 Linux ZFS 法律地位比较

**要点**：FreeBSD 与 Linux 在 ZFS 法律地位上的根本差异：FreeBSD 内核采用 BSD-2-Clause 许可证（permissive），CDDL 文件可以直接放入内核源码树分发，不存在 copyleft 冲突；Linux 内核采用 GPLv2（strong copyleft），CDDL 文件无法合入主线，只能通过 DKMS/LKM 方式单独分发；这一差异导致的实际后果：FreeBSD 从 7.0（2008 年）起即在内核中包含 ZFS，FreeBSD 13.0（2021 年 4 月）将 OpenZFS 2.0 作为默认文件系统；Linux 上 ZFS 始终是外核模块，发行版支持情况不一（Ubuntu 20.04+ 可选安装、Debian contrib 源、Fedora 不官方支持、NixOS 原生支持）；FreeBSD 可以通过 pkg 升级 ZFS 版本，也可在启动时选择不同 ZFS 版本；Linux ZFS 升级通常需要重新编译内核模块（DKMS 自动处理）

## 110.9.4 法律灰区争议的史料辨析

**要点**：CDDL-GPL 兼容性争议的法律意见分为三派：FSF/GPL 阵营认为 CDDL 与 GPL 不兼容（FSF 许可证列表分类、Eben Moglen 多次讲话）；SFLC（Software Freedom Law Center）2016 年意见认为通过 DKMS 分离分发 ZFS 在 GPL 下可能合法（mere aggregation 解释）；Canonical/Ubuntu 法务团队认为在 Ubuntu 中分发 ZFS DKMS 包是合法的；Linux 内核社区主流立场（Torvalds、Kroah-Hartman）认为 ZFS 不能合入主线，但不阻止他人作为外核模块分发；截至 2025 年，没有任何法院就 CDDL-GPL 兼容性或 ZFS LKM 合法性做出判决，所有讨论均为法律意见；Ubuntu 2016 年决定在 16.04 中包含 ZFS 是发行版中的标志性事件，SFLC 为其出具了法律支持意见

**史料**：FSF 许可证列表 CDDL 条目（gnu.org）；SFLC 2016 年法律意见书（softwarefreedom.org）；Ubuntu Technical Board 2016-02 决议；Torvalds/Kroah-Hartman 2020 年公开声明；LWN.net 2016-2020 年 ZFS 法律报道系列 ［C］

**史观**：总纲第 3 条——形式主义膨胀：长达 20 年的 CDDL-GPL 争议没有法律结论，这本身就是开源法律生态的一个重要特征——开源许可证的执行主要靠社区规范和商业审慎，而非司法判决；这种 “灰区共存” 模式使得技术可以在法律不确定的情况下继续发展

**辨析**：FSF 关于 CDDL 不兼容的精确日期和文档：原文称 “FSF 2005 年 12 月声明”，经 gnu.org 许可证列表互联网档案馆存档查证，FSF 在 2006 年初已在许可证列表中标注 CDDL 为 "GPL-incompatible free software license"，但未发布专门的 “声明” 文档；FSF 对 CDDL 的立场是通过持续更新的许可证列表表达的，而非一次性声明，因此精确日期标注为 ［ 存疑脚注：此处事实待多源交叉验证 ］
