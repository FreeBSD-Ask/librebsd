# 141.3.3 ZFS、GELI 与存储栈

**要点**：11.x 时期 ZFS 持续演进：①ZFS feature flags 继续完善——支持新的 feature flags 如异步销毁、空间映射历史等；②ZFS 压缩数据缓存（11.1）——压缩后的 ARC 缓存减少内存占用、提高缓存有效容量；③ZFS 并行挂载（11.3）——大幅加速大量数据集场景下的挂载速度；④ZFS 书签重命名（11.4）——ZFS bookmark 管理功能增强；⑤Resilver 修复改进——替换磁盘时的重建过程可靠性提升；⑥TRIM/UNMAP 支持持续优化——SSD 空间回收性能改进。GELI(8) 加密方面：11.3 将 geli 引导支持扩展到所有架构；11.3/11.4 增加弱加密算法弃用警告，引导用户迁移到 AES-XTS 等现代算法；数据完整性验证（HMAC）持续完善。此外，11.0 引入 **fstyp(8)** 文件系统检测工具；CAM（Common Access Method）存储层持续改进；**ctl(4)** CAM Target Layer（iSCSI target）高可用配置支持在 10.3 引入后 11.x 持续优化；**nvme(4)** NVMe SSD 驱动持续改进。

**史料**：FreeBSD 11.x 各版本 Release Notes Storage/ZFS 章节、zfs(8)/geli(8) 手册页、FreeBSD Quarterly Status Reports 文件系统章节、OpenZFS 发布历史与 FreeBSD 同步情况。 ［A］

**史观**：总纲第 25 条——逻辑是形式主义而非世界本身的结构：ZFS 作为功能极其丰富的文件系统（卷管理、快照、克隆、压缩、去重、RAID-Z、发送/接收、加密等）与 FreeBSD“简洁”哲学形成张力——但 ZFS 的复杂性被封装在文件系统层，base 系统的其他部分仍保持简洁。FreeBSD 选择 ZFS 而非 Linux 的 Btrfs 作为下一代主要文件系统，部分原因是 ZFS 的许可协议（CDDL）与 BSD 许可兼容性更好，且 ZFS 的工程成熟度在 2010 年代显著高于 Btrfs。

**辨析**：ZFS 加密（ZFS native encryption）在 11.x 尚未集成——OpenZFS 原生加密在 OpenZFS 2.0（对应 FreeBSD 13.0）才正式引入；11.x 时期加密仍依赖 GELI(8) 块级加密层。ZFS 去重（dedup）在 11.x 已支持但生产环境使用仍需谨慎（内存开销大）。
