# 124.10 图形与驱动——Intel KMS/GEM 与新硬件支持

## 123.10.1 9.1 Intel GPU GEM/KMS 驱动

**要点**：9.1-RELEASE 新增 Intel GPU 驱动支持 GEM（Graphics Execution Manager）与 KMS（Kernel Mode Setting），这是 FreeBSD 图形栈现代化的重要一步；KMS 将显示模式设置从用户态 X 服务器移入内核，支持更快的 VT 切换、更稳定的图形性能和 suspend/resume；Radeon KMS 支持在 9.x 尚未完成，10.x 之后才引入

**史料**：FreeBSD 9.1-RELEASE Release Notes、Konrad Witaszczyk（Intel KMS 移植主要开发者）commit log ［A］

**史观**：总纲第 10 条——边缘者贡献：FreeBSD 图形驱动开发长期依赖少数志愿者（如 Konstantin Belousov（康斯坦丁·别洛乌索夫）、Konrad Witaszczyk 等）从 Linux 移植 DRM/KMS 代码，是项目中资源相对匮乏但需求广泛的领域；图形栈的延迟成熟是 FreeBSD 桌面体验落后于 Linux 的重要原因

**辨析**：9.1 Intel KMS 仅支持较旧的 Intel GPU（Ironlake/Sandy Bridge 时期），Ivy Bridge 及更新 GPU 支持在后续版本添加；Radeon/NVIDIA KMS 在 9.x 不可用

**文献**：FreeBSD 9.1-RELEASE Release Notes（Graphics Drivers 章节）；**drm(4)**、**i915kms(4)** man pages（9.1 版本） ［B］

- 图形栈跨项目移植呈现两条互不兼容的路线：DragonFly 引入 Linux 兼容层承接 DRI 代码从而快速跟进新硬件，FreeBSD 则将 DRI 代码 BSD 化以深度融入内核；前者更新因此难以回流后者，Adrian Chadd 明言 FreeBSD 追平新图形硬件的前提是先建成更完整的 Linux 兼容层（OFED 更新正在进行中）——路线分歧成为后续演化路径依赖的直接来源。（BSD Now EP101，[2864.64-2910.02]，L1）
- VeriSign 同时使用 BSD、Linux、Solaris 等操作系统作多样性冗余的说法为主持人转述，其根服务器内部各系统的具体比例未获官方资料核验。　[存疑脚注] VeriSign 各操作系统在根服务器中的具体占比属单一播客转述，须以官方资料交叉验证。（BSD Now EP1，[460.01-478.53]，L4）
