# 114.3 DTrace 的 CDDL 许可证——与 ZFS 同为 Sun 2004 年开源成果，受同样的 CDDL 1.0 条款约束

## 114.3.1 CDDL 1.0 对 DTrace 的法律约束

**要点**：DTrace 源码由 Sun Microsystems 于 2005 年随 OpenSolaris 以 CDDL 1.0 许可证发布；CDDL 1.0 基于 MPL 1.1，采用文件级 copyleft——所有源自 OpenSolaris 的 DTrace 源文件必须保持 CDDL 许可，但 CDDL 文件可与 BSD 许可证文件聚合分发；CDDL §3.1 授予"perpetual, worldwide, non-exclusive, no-charge, royalty-free, irrevocable"版权与专利许可；§3.2 分发义务——CDDL 覆盖文件的修改版也必须以 CDDL 发布；§3.5 明确允许与其他许可证的代码聚合分发；CDDL 对 DTrace 的约束与对 ZFS 的约束完全相同（CDDL 条款本身统一）

**史料**：CDDL 1.0 官方文本（opensource.org/licenses/CDDL-1.0）；OSI 2005 年 1 月 CDDL 审批公告；FreeBSD src/sys/cddl/ 目录结构（CDDL contrib 代码与 BSD compat 代码分离）；Oracle 2017 年 8 月 GPLv2+ 重新许可公告（Mark J. Wielaard 博客 2018-02-14） ［A］

**史观**：总纲第 24 条——许可证：CDDL 文件级 copyleft 的法律结构决定了 DTrace 的跨平台流动边界：FreeBSD/macOS/NetBSD/Windows 可合法包含 DTrace（因 CDDL 与 BSD/类 BSD 许可证兼容），Linux 则因 CDDL 与 GPLv2 作品级 copyleft 冲突，无法将 DTrace 直接合入主线内核（Oracle Linux DTrace 采用内核模块方式分发）

**辨析**：CDDL 对 DTrace 的约束与 ZFS 完全相同——二者均源自 OpenSolaris，使用同一 CDDL 许可证文本；2017 年 8 月 Oracle 将 DTrace 内核代码以 GPLv2+ 许可发布（用户态为 GPLv2+UPL），这一许可变更仅适用于 Oracle 随后发布的 Linux DTrace 代码，OpenSolaris/illumos 分支的 DTrace 代码仍为 CDDL；FreeBSD 中的 DTrace 代码源自 OpenSolaris CDDL 分支，仍保持 CDDL 许可

**文献**：Open Source Initiative. CDDL 1.0 Full Text. opensource.org/licenses/CDDL-1.0; FreeBSD Source Repository. src/sys/cddl/ directory structure; Wielaard, M. J. (2018-02-14). dtrace for linux; Oracle does the right thing. gn u.wildebeest.org/blog/mjw/ ［C］

## 114.3.2 与 ZFS 共享 CDDL 的法律后果

**要点**：DTrace 与 ZFS 共享 CDDL 许可证的直接后果是二者在 FreeBSD 中采用完全相同的导入模式：src/sys/cddl/contrib/opensolaris/ 存放未修改的 OpenSolaris 源码（vendor branch），src/sys/cddl/compat/opensolaris/ 提供 Solaris 内核 API 兼容层（solaris.ko 模块）；这种分离设计允许 FreeBSD 以最小的本地改动同步上游 DTrace/ZFS 更新，同时保持许可证边界清晰——contrib 下为 CDDL，compat 和 src 其他部分为 BSD；DTrace 在 FreeBSD 中的法律地位与 ZFS 相同：作为独立内核模块加载，不构成 BSD 内核的衍生作品（因 CDDL §3.5 允许聚合分发）

**史料**：FreeBSD src/sys/cddl/contrib/opensolaris/uts/common/dtrace/ 目录（DTrace 核心源码）；FreeBSD src/sys/cddl/compat/opensolaris/ 目录（Solaris API 兼容层）；FreeBSD 基金会关于 CDDL 代码兼容性的声明（与 ZFS 声明一致）；FreeBSD src/COPYRIGHT 文件中关于 cddl/ 目录的许可证说明；**freebsd.duckdb** `commits` 表代码级证据——commit `d5768a7a5b2a48b4092dacd73cfbdbd396a9f81e`（2006-11-21，author = John Birrell）的 commit message 原文记录了 CDDL 约束对 FreeBSD DTrace 集成路径的直接工程影响："Remove the KDTRACE option because I can't implement it the way I intended due to licensing restrictions. I had intended that it would be defaulted on, with opt-out possible for companies that don't accept the CDDL. The FreeBSD GENERIC kernel has to be entirely BSD licensed, so the only alternative would have been to make KDTRACE an opt-in option. That isn't a design I favour."；该 commit 证明 CDDL 文件级 copyleft 与 FreeBSD“GENERIC 内核仅含 BSD 许可代码”政策的直接冲突，使 DTrace 无法像 BSD 原生代码那样默认编译进 GENERIC 内核，只能以可加载内核模块形式分发 ［A］

**史观**：总纲第 25 条——终结与延续：DTrace 与 ZFS 共享 CDDL 许可证这一事实，使 FreeBSD 在 2007-2009 年间同时获得了企业级文件系统和企业级动态追踪两大关键技术，这两大技术的引入是 FreeBSD 7.x/8.x 时代“企业级成熟”的重要标志

**辨析**：DTrace 在 FreeBSD 中的 compat 层比 ZFS 的 compat 层薄——DTrace 对 Solaris 特有 API 的依赖相对较少（主要依赖 cyclic、kmem、taskq 等基础内核原语），因此 FreeBSD DTrace 的兼容性较好，provider 支持较完整；但 pid provider（用户态任意函数追踪）的支持曾长期落后于 Solaris，这与 FreeBSD 链接器和运行时链接编辑器的差异有关；**CDDL 约束的代码级验证**——commit `d5768a7a5b2a48b4092dacd73cfbdbd396a9f81e`（2006-11-21）是 CDDL 法律约束直接影响 FreeBSD DTrace 工程路径的一手证据，Birrell 在 commit message 中明确陈述了三点：(1) 他原本计划将 KDTRACE 选项默认启用（opt-out 模式），但因 CDDL 约束无法实现；(2) FreeBSD GENERIC 内核必须全部为 BSD 许可代码，CDDL 代码不能进入 GENERIC；(3) 最终只能选择 opt-in 模式，但这不符合他的设计偏好；这一工程决策的代码留痕与 FreeBSD Foundation 公开声明的 CDDL-BSD 兼容性立场、CDDL §3.5 聚合分发条款三方交叉验证一致；0 信任原则提示：commit subject 是 Birrell 自述，但与 FreeBSD 项目长期维持的 GENERIC BSD-only 政策一致，采信度高

Remove the KDTRACE option because I can't implement it the way I intended due to licensing restrictions. freebsd-src [DB/OL]. 2006-11-21T08:23:20Z. d5768a7a5b2a48b4092dacd73cfbdbd396a9f81e. ［A］

## 114.3.3 CDDL 与 GPL 不兼容的效应辨析

**要点**：CDDL 与 GPLv2 不兼容的核心冲突与 ZFS 同源：CDDL §3.2 要求 CDDL 文件保持 CDDL 许可，GPLv2 §2(b) 要求衍生作品整体以 GPL 发布，二者互斥；这一不兼容性对 DTrace 的影响：Linux 主线内核无法直接包含 DTrace 代码；Oracle 于 2011 年 10 月宣布将 DTrace 移植到 Oracle Linux（作为独立内核模块分发，UEK R2 中技术预览），2012 年 12 月 12 日正式 GA（General Availability），采用 GPLv2 许可的模块封装层；dtrace4linux 项目（Paul Fox 等人维护，2008 年起）以独立内核模块方式提供 DTrace，标注内核为“tainted”；Linux 社区长期无法获得原生 DTrace 支持，这为 eBPF 的诞生和发展提供了生态空间

**史料**：CDDL §3.2 原文；GPLv2 §2(b) 原文；Oracle Linux Blog 2012-12-12《Announcement: DTrace for Oracle Linux General Availability》（Zeynep Koch）；Wim Coekaerts 2011-10-09《Trying out dtrace》Oracle 博客；dtrace4linux 项目主页（github.com/dtrace4linux/linux）；LWN.net 2007-08-07《On DTrace envy》 ［C］

**史观**：总纲第 24 条——许可证：CDDL-GPL 不兼容性对 Linux 追踪生态的影响深远——无法直接使用 DTrace 迫使 Linux 社区发展出独立的追踪技术路线：从早期的 SystemTap（Red Hat 主导，2005 年起）到最终的 eBPF（Alexei Starovoitov 2014 年并入内核）；许可证壁垒在阻碍代码流动的同时，也催生了技术创新——eBPF 最终发展为比 DTrace 更通用的内核可编程平台

**辨析**：Oracle 2017 年 8 月以 GPLv2+ 许可发布 DTrace Linux 内核代码的事件，并未改变 FreeBSD/macOS DTrace 的许可状态——FreeBSD 使用的是 illumos/OpenSolaris 分支的 CDDL 代码，非 Oracle 的 GPL 分支；“CDDL 与 GPL 不兼容导致 Linux 没有 DTrace 所以才有了 eBPF”这一叙事有一定道理但过于简化——eBPF 的前身 classic BPF（cBPF）自 1997 年起就在 Linux 中用于包过滤，Alexei Starovoitov 的扩展（eBPF）始于 2011-2013 年，最初用于网络过滤优化，后扩展为通用虚拟机，追踪只是其应用场景之一

**文献**：Koch, Z. (2012-12-12). Announcement: DTrace for Oracle Linux General Availability. Oracle Linux Blog; Coekaerts, W. (2011-10-09). Trying out dtrace. blogs.oracle.com/wim; Fox, P. dtrace4linux Project. github.com/dtrace4linux; Corbet, J. (2007-08-07). On DTrace envy. LWN.net. lwn.net/Articles/244536/ ［C］

## 114.3.4 Sun 许可策略的一手史料

**要点**：Sun 选择 CDDL 许可 OpenSolaris（含 DTrace 和 ZFS）的历史背景是 Sun 2004-2005 年的开源战略转型：Sun CEO Scott McNealy 推动 OpenSolaris 以对抗 Linux 在服务器市场的崛起；CDDL 由 Simon Phipps（Sun 首席开源官）和 Sun 法务团队基于 MPL 1.1 起草，2004 年 12 月 1 日提交 OSI，2005 年 1 月获批准；Sun 选择 CDDL 而非 GPL 的商业动机：文件级 copyleft 允许 Sun 将开源代码与商业版 Solaris 的闭源组件结合分发，同时避免 GPL 的“传染性”迫使 Sun 公开全部专利技术；DTrace 是 OpenSolaris 中首个单独开源的组件，源码在 OpenSolaris 全面发布前即已提供

**史料**：OSI 2004-2005 年 CDDL 审批邮件列表存档；Simon Phipps 2005 年博客《Why We Chose CDDL》（webmink.com 存档）；Sun Microsystems 2005 年 1 月 OpenSolaris 公告；Sun 2005 年 6 月 14 日 OpenSolaris Launch 新闻稿；Cantrill 在博客中关于 DTrace 开源的回忆 ［A］

**史观**：总纲第 22 条——开源运动：Sun 的 CDDL 许可策略是开源史上最具争议的许可证选择之一——它创造了一个独特的“文件级 copyleft”中间路线，但该路线与 GPL 的不兼容性也导致了 OpenSolaris 技术（ZFS、DTrace）与 Linux 生态长达二十年的割裂

**辨析**：原文将“Sun 许可策略”与 Jolitz DDJ 文章相关联系错误；Sun 是否故意选择 CDDL 以阻止 ZFS/DTrace 进入 Linux 是一个长期争议——Sun 方（Phipps、Cooper）多次否认，称 CDDL 是基于 MPL 的合理许可证选择；GPL 阵营（FSF、Eben Moglen）则认为 CDDL 是故意设计为 GPL 不兼容；从技术史角度，这一争议无法在缺乏 Sun 内部决策文档的情况下定论；Oracle 2017 年将 DTrace Linux 代码以 GPLv2+ 发布可视为对这一争议的某种回应，但 Oracle 的动机更多是商业竞争（推广 Oracle Linux）而非历史和解

**文献**：Phipps, S. (2005). Why We Chose CDDL. webmink.com; Open Source Initiative. CDDL Approval Archives (2004-12/2005-01). opensource.org; Sun Microsystems. (2005-06-14). OpenSolaris Launches. Press Release［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
