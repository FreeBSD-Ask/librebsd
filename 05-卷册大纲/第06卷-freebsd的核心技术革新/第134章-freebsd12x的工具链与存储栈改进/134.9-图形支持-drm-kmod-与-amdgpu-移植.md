# 133.9 图形支持——drm-kmod 与 amdgpu 移植

## 133.9.1 drm-kmod 图形栈与 amdgpu 移植
  - 要点：FreeBSD 12.x 时期图形驱动（DRM/KMS）继续通过 ports 中的 drm-kmod 套件（graphics/drm-kmod）提供，而非纳入 base 系统。drm-kmod 由 Jean-Sébastien Pédron（dumbbell@）、Matt Macy（mmacy@）等人维护，基于 Linux 内核 DRM 子系统代码通过 LinuxKPI 兼容层移植到 FreeBSD 内核。12.0 时期 drm-kmod 提供基于 Linux 4.11 与 Linux 4.16 DRM 代码的版本（drm-fbsd12.0-kmod），支持 Intel（Haswell/Broadwell/Skylake/Kaby Lake/Coffee Lake 代）GPU、AMD Radeon（GCN 1-3 代，即 HD 7000-RX 200/300/500 系列中旧卡）以及 AMDGPU（GCN 4+ 代，即 RX 400/500/Vega 系列）的初步支持。NVIDIA 显卡闭源驱动（x11/nvidia-driver）继续由 NVIDIA 官方维护 FreeBSD 版本，支持最新 NVIDIA GPU。
  - 史料：FreeBSD 12.0-RELEASE Announcement（"Various improvements to graphics support for current generation hardware"）、FreeBSD Quarterly Status Reports X11/Graphics 章节、Jean-Sébastien Pédron freebsd-x11 邮件列表状态报告、graphics/drm-kmod ports 目录、Matt Macy amdgpu 移植提交。 ［A］
  - 史观：总纲第 5 条——技术债务与代码考古：FreeBSD DRM 驱动本质上是通过 LinuxKPI 兼容层“追着 Linux 跑”——Linux 内核 DRM API 持续快速变化，每次跟进都需大量适配工作。将 DRM 驱动保持在 ports 而非 base 的决策，允许图形驱动独立于 FreeBSD 基础系统发布周期更新，但也意味着图形支持不被视为操作系统的核心功能。这与 Linux 将 GPU 驱动纳入内核主线的策略形成对比。
  - 辨析：AMDGPU 支持在 12.x drm-kmod 中为初步状态——稳定性、性能与功能完整度不如 Linux；HDMI/DP 音频、GPU 视频编解码（VA-API）在部分卡上支持不完善；Intel Ice Lake/Tiger Lake 等新架构在 12.x 不支持；Wayland 显示服务器在 12.x 可通过 ports 安装但稳定性有限，Xorg 仍是唯一推荐的显示服务器。
  - 文献：Pédron J-S. FreeBSD Graphics Status Reports [EB/OL]. freebsd-x11 mailing list, 2018-2022；FreeBSD Quarterly Status Reports Graphics chapters [R]；graphics/drm-kmod ports entry [Z]. ［A］
## 133.9.2 LinuxKPI 兼容层的工程效应
  - 要点：LinuxKPI（Linux Kernel Programming Interface）兼容层是使 Linux DRM 驱动能在 FreeBSD 内核上运行的关键基础设施，提供 Linux 内核 API（如 kthread、workqueue、timer、mutex、DMA-BUF、device model 等）的 FreeBSD 内核实现。LinuxKPI 在 FreeBSD 11.x 开始用于 DRM 驱动移植，12.x 时期大幅扩展以支持更完整的 Linux DRM 子系统。LinuxKPI 不仅用于图形驱动——Mellanox **mlx5(4)** 100Gb 网卡驱动、部分无线驱动也通过 LinuxKPI 移植。LinuxKPI 主要由 Hans Petter Selasky（hps@）、Matt Macy 等人开发。
  - 史料：LinuxKPI 源码（sys/compat/linuxkpi/）、Hans Petter Selasky LinuxKPI 演讲、FreeBSD Quarterly Status Reports LinuxKPI 章节、**mlx5(4)** 驱动 commit log。 ［A］
  - 史观：总纲第 22 条——开源运动：LinuxKPI 是 FreeBSD 应对“GPU/网络驱动厂商只为 Linux 编写驱动”现实的工程策略——与其劝说厂商重写 BSD 原生驱动，不如提供兼容层使 Linux 驱动能在 FreeBSD 上重新编译运行。这一策略虽务实，但也引发了关于“FreeBSD 内核是否会被 Linux API 侵蚀”的哲学争议。
  - 辨析：LinuxKPI 仅提供内核 API 兼容——Linux 内核中的系统调用 ABI（Linuxulator）与内核内部 API（LinuxKPI）是两个独立的兼容层；LinuxKPI 不允许直接加载 Linux 内核模块，驱动代码需经过适配与重编译；通过 LinuxKPI 移植的驱动与原生 FreeBSD 驱动在性能上理论无差异，但在稳定性与代码风格上存在争议。
  - 文献：Selasky H P. LinuxKPI: Running Linux Drivers Natively on FreeBSD [C]//BSDCan various years；FreeBSD src/sys/compat/linuxkpi/ source code [Z].
