# 139.2.1 BIND 移除与 Unbound 替代

**要点**：FreeBSD 10.0 将 ISC BIND（Berkeley Internet Name Domain）从 base system 移除。BIND 自 4.3BSD Tahoe（1988）起即为 BSD 系统的标准 DNS 服务器，最初由 Kevin Dunlap 与 Douglas Terry 等在 Berkeley 开发，后由 ISC（Internet Systems Consortium）维护为 BIND 9 系列。BIND 在 2000 年代多次出现严重安全漏洞（最著名的是 2008 年 Dan Kaminsky DNS 缓存投毒漏洞），且代码体量庞大复杂度高。10.0 移除 BIND 后，以 NLnet Labs 的 Unbound（递归 DNS 解析器，BSD 许可证，Wouter Wijngaards 开发）+ LDNS（DNS 解析库）组合替代作为本地缓存 DNS 解析器。重要区分：Unbound 是递归解析器而非权威 DNS 服务器——需要运行权威 DNS 的用户需从 ports 安装 dns/bind9 *或其他 DNS 服务器（如 NSD、Knot DNS）。随 BIND 一起移除的还有 nslookup 与 dig 工具——base 中改为提供* *host(1)* *与* **drill(1)**（来自 LDNS），nslookup/dig 可通过安装 dns/bind-tools port 获取。

**史观**：总纲第 24 条——许可证与安全：BIND 移除是许可证纯洁化（ISC 许可证虽为 BSD 风格但代码体量大）与安全债务清算的共同结果——BIND 8/9 在 FreeBSD base 中存在多年但安全补丁频率高，维护负担重。Unbound 作为模块化、专为递归解析设计的 DNS 实现，代码量远小于 BIND 且攻击面更小，更适合作为本地缓存解析器。

**辨析**：部分资料称 “10.0 用 Unbound 完全替代 BIND”——需明确：Unbound 仅替代 BIND 的 “本地递归解析器” 功能，不替代 BIND 的 “权威 DNS 服务器” 功能，base 中不再包含权威 DNS 服务器软件，这是有意的设计决策——权威服务器场景多样不应强制放入 base；nslookup/dig 工具移除给习惯传统 DNS 工具的用户带来不便，**drill(1)** 作为 LDNS 提供的替代工具命令行参数与 dig 差异较大。
