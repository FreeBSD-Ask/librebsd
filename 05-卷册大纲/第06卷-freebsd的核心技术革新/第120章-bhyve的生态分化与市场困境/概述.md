## 章节概述

本子章承载 bhyve 项目自 2014 年随 FreeBSD 10.0-RELEASE 正式发布后的生态分化、市场困境、外部批评、committer 记录、同期虚拟化技术比较与核心贡献者梳理共七节内容，覆盖 bhyve ARM64 移植探索、与 Linux KVM 的市场份额对比、TrueNAS 双版本策略冲击、illumos/macOS 分支传播、管理工具生态碎片化以及 bhyve 在虚拟化战争中“生不逢时”的关键历史脉络。

bhyve ARM64 支持的探索始于 2015-2016 年，Mihai Carabaș 与 Peter Grehan（彼得·格雷汉） 在 BSDCan 2016 发表 “Porting bhyve on ARM” 演讲，但 x86 VMX/SVM 与 ARM VE 在 CPU 虚拟化模型、中断虚拟化、内存管理架构上差异巨大，FreeBSD 13.0（2021 年）才提供 bhyve on arm64 的初步实验性支持。市场份额方面，Linux KVM 凭借随 Linux 内核主线分发的天然优势、Red Hat 等商业厂商的持续投入、OpenStack/libvirt/virt-manager 管理工具生态成熟度成为云虚拟化事实标准，bhyve 未进入任何主流公有云核心虚拟化方案，市场主要集中在 FreeBSD/TrueNAS 部署、illumos 生态（SmartOS/Triton）与特定嵌入式场景。

iXsystems 于 2020 年宣布开发基于 Debian Linux 的 TrueNAS SCALE，使用 KVM/QEMU + LXC/Incus 而非 bhyve 提供虚拟化功能，与基于 FreeBSD + bhyve + ZFS 的 TrueNAS CORE 并行存在；这一双版本策略导致 iXsystems 工程资源分流，但并未终止 TrueNAS CORE 产品线。bhyve 的技术批评主要集中在客户机操作系统支持范围、实时迁移与内存 ballooning 等高级功能成熟较晚、管理工具碎片化（vm-bhyve、iohyve、CBSD、libvirt bhyve 驱动等多个独立工具无统一标准）；但 bhyve 被 illumos（Pluribus Networks、Joyent SmartOS/Triton）与 macOS（xhyve/HyperKit）成功移植，证明 BSD 许可证使其能跨越 BSD/illumos/macOS 三个不同内核生态传播。

2011-2026 年同期虚拟化技术对照显示，bhyve 进入虚拟化市场时（2014 年），KVM 已获 Red Hat 全力支持、Xen 已被 AWS 大规模采用、VMware 已统治企业虚拟化市场、Hyper-V 已随 Windows Server 占据服务器市场——hypervisor 市场格局在 2010 年代初已基本锁定，bhyve 作为晚到者即使技术优秀也难以打破既有网络效应。核心贡献者方面，Neel Natu（尼尔·纳图）（nneul@）完成初始架构设计，Peter Grehan（grehan@）承担长达十余年的维护、扩展与社区建设，John Baldwin（约翰·鲍德温）（jhb@）负责 AMD SVM/PCI 直通等重要功能，Mihai Carabaș 主导 ARM64 移植；bhyve 展示了开源项目中“创始开发者”与“维护者”角色分离的典型模式。
