# 120.9 TrueNAS 双版本策略对 bhyve 生态的效应

## 120.9.1 TrueNAS SCALE 基于 Linux 的语境与效应

**要点**：iXsystems 于 2020 年宣布开发 TrueNAS SCALE，这是一个基于 Debian Linux 的独立 TrueNAS 版本，面向超融合基础设施（HCI）场景，使用 KVM/QEMU + LXC/Incus 而非 bhyve 提供虚拟化功能；TrueNAS CORE 继续作为基于 FreeBSD + bhyve + ZFS 的存储操作系统版本进行开发与维护，两个版本并行存在、针对不同使用场景；iXsystems 开发 SCALE 的核心动机包括：Linux 容器（Docker/Kubernetes）生态更成熟、对超融合与容器编排的需求增长、部分用户对 Linux 平台的偏好；这一双版本策略导致 iXsystems 的工程资源分流，对 FreeBSD 与 bhyve 的上游贡献有所减少，但并未终止 TrueNAS CORE 产品线

**史料**：iXsystems TrueNAS SCALE 官方公告（2020 年）；TrueNAS CORE/SCALE 版本对比文档；iXsystems 官方博客与论坛讨论 ［A］

**史观**：总纲第 7 条——商业形态分化与 BSD 许可证结构性后果：iXsystems 能在保持 FreeBSD 产品线的同时推出 Linux 版本，本身就是 BSD 许可证 “自由选择” 特性的体现——公司可以根据市场需求选择技术栈，而不受 copyleft 许可证限制；但这也揭示了 BSD 生态的一个结构性弱点：商业厂商可以利用 BSD 代码开发产品，但遇到生态短板时可以自由切换到 Linux，没有许可证机制强制回馈或锁定

**辨析**：原文 “2025 年 TrueNAS 28.04 转向 Linux Kernel” “TrueNAS 放弃 FreeBSD” 是严重事实错误，需明确纠正：TrueNAS CORE 截至 2026 年仍在积极开发与发布新版本（如 TrueNAS CORE 13.0、24.04 等），并未转向 Linux；TrueNAS SCALE 是独立的 Linux 版本，从项目启动之初就基于 Debian，并非从 FreeBSD “转向” Linux；原文引用的 Blocks & Files 2024 年 4 月报道与 iXsystems 高管采访的语境需准确理解——Kristen Kennedy（iXsystems 产品副总裁）讨论的是 TrueNAS SCALE 的开发动机，并非宣布 CORE 版本终止；“过去 15 年如果有人想推动 FreeBSD 前进，他们早就动手了”（Kris Moore（克里斯·摩尔） 语）的引述需放在特定语境中理解，这是关于 FreeBSD 项目治理与开发节奏的批评，并非对 bhyve 技术的否定；bhyve 失去其 “最大商业用户” 的说法不准确——bhyve 在 TrueNAS CORE 中仍被大量部署使用，同时在 illumos/SmartOS 等其他场景也有商业应用
