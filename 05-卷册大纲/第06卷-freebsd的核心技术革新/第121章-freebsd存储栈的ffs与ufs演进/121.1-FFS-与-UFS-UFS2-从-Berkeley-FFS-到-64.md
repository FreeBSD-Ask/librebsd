# 121.1 FFS 与 UFS/UFS2——从 Berkeley FFS 到 64 位块指针的文件系统演进

## 121.1.1 麦库西克（Marshall Kirk McKusick）与 FFS 的设计（1984 年 4.2BSD）

**要点**：Fast File System（FFS）由 麦库西克 在 Berkeley 读研期间设计，核心创新在于引入柱面组（cylinder group）概念，将磁盘划分为若干个柱面组，每个柱面组包含自己的超级块备份、inode、数据块，将相关数据和元数据局部化在同一柱面组，大幅减少磁头寻道时间；块大小从传统 UNIX 的 512 字节提升至 8KB，同时引入片段（fragment，1KB）机制减少小文件空间浪费；FFS 论文 “A Fast File System for UNIX” 于 1984 年 8 月发表于 ACM Transactions on Computer Systems（Vol.2 No.3），合作者包括 比尔·乔伊（Bill Joy）、Samuel Leffler、Robert Fabry；4.1b BSD（1983 年试验版）已包含 FFS 原型，正式随 4.2BSD 于 1983 年 8 月发布，而非 1984 年；FFS 是现代 BSD UFS 的直接前身

**史料**：McKusick et al. 1984 “A Fast File System for UNIX” ACM TOCS 论文；McKusick 1999 “Open Sources: Voices from the Open Source Revolution” 中 FFS 开发回忆；4.2BSD 发行手册（1983 年 8 月）；McKusick, Bostic, Karels, Quarterman 1996《The Design and Implementation of the 4.4BSD Operating System》第 7 章 ［A］

**史观**：总纲第 1 条——一切真历史都是古代史（原“项目统摄史观”系自创名目，按权威表正名；FFS“源头时刻”内容与第 1 条主旨相合）：FFS 的柱面组设计是 1980 年代初磁盘性能瓶颈下的 “源头时刻”——McKusick 作为研究生，一个人在实验室里对着磁盘寻道时间发呆时想到的局部化原理，奠定了此后四十年 BSD 文件系统的基本结构；这不是委员会决议的产物，而是一个工程师面对具体问题的洞察

**辨析**：FFS 正式发布日期存在混淆——McKusick 论文发表于 1984 年 8 月，但 FFS 代码随 4.2BSD 于 1983 年 8 月即已发布，试验版更早出现在 4.1b BSD（1982 年末至 1983 年初）；论文发表是在系统发布之后，这是 BSD 时代 “先实现后写论文” 的典型模式；比尔·乔伊 作为合作者常被忽略——Joy 当时已离开 Berkeley 加入 Sun，但仍参与了 FFS 的早期设计讨论

**文献**：McKusick, M. K., Joy, W. N., Leffler, S. J., & Fabry, R. S. (1984). *A Fast File System for UNIX*. ACM Transactions on Computer Systems, 2(3), 181-197; McKusick, M. K. et al. (1996). *The Design and Implementation of the 4.4BSD Operating System*. Addison-Wesley; McKusick, M. K. (1999). *The History of the Fast File System*. Open Sources: Voices from the Open Source Revolution. ［B］

## 121.1.2 UFS 的形成与 Soft Updates 机制（1990 年代）

**要点**：UFS（UNIX File System）作为 FFS 的后代，在 4.3BSD Tahoe（1988 年）和 4.4BSD（1993 年）中逐步演进；McKusick 与 Gregory R. Ganger（CMU）合作设计 Soft Updates 机制，核心思想是通过追踪并强制元数据更新之间的依赖顺序，仅允许不导致文件系统不一致的异步元数据写入，唯一可能的不一致是存储空间泄漏（已标记分配但未被任何文件使用的块），崩溃后无需重放慢速的日志，仅需后台 fsck 回收泄漏空间；Soft Updates 论文 “Soft Updates: A Technique for Eliminating Most Synchronous Writes in the Fast Filesystem” 发表于 1999 年 USENIX Annual Technical Conference；FreeBSD 中 Soft Updates 的具体集成时间在 FreeBSD 3.x 系列（1998-1999 年），由 McKusick 本人完成代码移植

**史料**：McKusick & Ganger 1999 USENIX Soft Updates 论文；Ganger & Patt 1994 OSDI “Metadata Update Performance in File Systems”；McKusick 2002 BSDCon “Running fsck in the Background” 论文；FreeBSD 3.0-RELEASE Release Notes（1998 年 10 月） ［B］

**史观**：总纲第 17 条——证明世界先于解释和改造世界（原“软件工程”系伪名目，按实现与证明为先论旨正名）：Soft Updates 是 “通过顺序保证替代同步写” 这一工程哲学的极致体现——它不记录日志，不做写时复制，而是在写入时动态 “回滚” 依赖未满足的元数据部分，这种设计在理论上极其优雅，但实现复杂度极高；这是 BSD 工程美学中 “宁要复杂的正确，不要简单的通用” 的典型

**辨析**：Soft Updates 引入 FreeBSD 的精确版本需精确——FreeBSD 2.2.x 时代已有外部补丁，正式 MFC 入 -stable 分支在 FreeBSD 3.x 时期，FreeBSD 4.x 开始默认启用；Soft Updates 不是 “没有日志就更快”——它的元数据写入性能确实优于日志文件系统，但崩溃后需要后台 fsck 遍历整个文件系统，大文件系统（TB 级）上该过程可能耗时数小时；NetBSD 6.0（2012 年）、OpenBSD 7.4（2023 年）先后移除了 Soft Updates 支持，转向更简单的日志机制，这从侧面印证了其维护复杂度

**文献**：McKusick, M. K., & Ganger, G. R. (1999). *Soft Updates: A Technique for Eliminating Most Synchronous Writes in the Fast Filesystem*. USENIX ATC '99; Ganger, G. R., & Patt, Y. N. (1994). *Metadata Update Performance in File Systems*. OSDI ’94; Seltzer, M. I. et al. (2000). *Journaling Versus Soft Updates: Asynchronous Meta-data Protection in File Systems*. USENIX ATC '00. ［B］

## 121.1.3 UFS2 与 SUJ：Jeff Roberson 的日志化 Soft Updates（FreeBSD 5.0/9.0）

**要点**：UFS2 由 McKusick 与 Poul-Henning Kamp（波尔-亨宁·坎普） 共同设计，随 FreeBSD 5.0（2003 年 1 月）正式发布，核心改进包括 64 位块指针（支持最大 8 ZiB 即 2^73 字节卷，对比 UFS1 的 32 位块指针——上限远低于此量级〔原“对比 UFS1 的 2^73 字节上限”系自斥笔误，已按 UFS1/UFS2 对照订正〕）、inode 中增加 birthtime（创建时间）字段、扩展属性支持、POSIX.1e ACL 支持、可变大小块（类似 extent）；Jeff Roberson 于 2010 年前后设计 SUJ（Soft Updates Journaling），在 Soft Updates 基础上增加一个小的循环日志记录已分配但可能未完全连接的块，崩溃后通过重放日志即可快速定位泄漏块，无需遍历整个文件系统，从根本上解决了 Soft Updates 在大文件系统上崩溃恢复慢的问题；SUJ 随 FreeBSD 9.0（2012 年 1 月）正式引入并默认启用，标记为 “journaled soft-updates”

**史料**：McKusick 2003 BSDCon “Enhancements to the Fast Filesystem To Support Multi-Terabyte Storage Systems“ 论文；McKusick & Roberson 2010 ”Journaled Soft-updates” 技术白皮书；FreeBSD 5.0-RELEASE Release Notes（2003 年 1 月）UFS2 章节；FreeBSD 9.0-RELEASE Release Notes（2012 年 1 月）SUJ 章节；FreeBSD 源码 ****src/sys/ufs/ufs/**dinode.h** UFS2 dinode 定义 ［A］

**史观**：总纲第 22 条——知识注定过时（原“终结与延续”系伪名目，旧路线谢幕一搏论旨改挂）：SUJ 是 Soft Updates 路线的 “最后一搏”——当整个工业界（Solaris UFS Logging、ext3/ext4、XFS、NTFS）都转向日志时，McKusick 和 Roberson 没有放弃 Soft Updates，而是在其基础上叠加最小化的日志来弥补崩溃恢复缺陷；这是 BSD 工程师对自己技术路线的执念，也是对 “理解复杂度才能驾驭复杂度” 这一信念的坚持

**辨析**：UFS2 不是 “UFS 的第二个版本” 而是一次独立的 on-disk 格式变更——FreeBSD 5.0 之前默认使用 UFS1，FreeBSD 5.0 开始 **newfs(8)** 默认创建 UFS2，但 UFS1 继续被支持用于向后兼容；**gjournal(8)** GEOM 类提供的是块级日志（block-level journaling），与 SUJ 是文件系统级日志（filesystem-level journaling）是两种不同机制——FreeBSD 7.0 引入 gjournal，FreeBSD 9.0 引入 SUJ，二者可独立使用但通常推荐 SUJ；SUJ 的日志默认存放在文件系统内部的空闲空间，而非单独分区

**文献**：McKusick, M. K. (2003). *Enhancements to the Fast Filesystem To Support Multi-Terabyte Storage Systems*. BSDCon '03; McKusick, M. K., & Roberson, J. (2010). *Journaled Soft-updates*. mckusick.com/softdep/suj.pdf; FreeBSD Project. *FreeBSD 5.0 Release Notes* (2003-01); FreeBSD Project. *FreeBSD 9.0 Release Notes* (2012-01); FreeBSD Project. **newfs(8)**, **tunefs(8)**, **gjournal(8)** Manual Pages. ［B］

## 121.1.4 UFS/FFS 演进的史料辨析与错误修正

**要点**：中文网络上关于 UFS/FFS 历史的常见错误包括：FFS 发布年份误作 1984 年（应为 1983 年 8 月随 4.2BSD 发布，论文 1984 年发表）、Soft Updates 引入 FreeBSD 版本误作 5.0（应为 3.x 时期集成，4.x 默认启用）、UFS2 设计者遗漏 Poul-Henning Kamp（McKusick 与 phk 共同设计）、SUJ 引入版本误作 FreeBSD 10（应为 9.0）；一手史料可交叉验证来源包括：FreeBSD 官方 Release Notes 各版本、McKusick 个人网站 mckusick.com 上的论文集、USENIX 会议论文集、FreeBSD 源码仓库提交历史；Valerie Aurora（née Henson）2009 年 LWN 文章 “Soft updates, hard problems” 是对 Soft Updates 路线最著名的外部批评，她作为 ext4 开发者认为 “soft updates are, simply put, too hard to understand, implement, and maintain to be part of the mainstream of file system development”。UFS/FFS 关键演进节点汇总见下表。

**史观**：总纲第 2 条——历史是形式主义化的非存在（原“形式主义膨胀”系伪名目，形式修补累积论旨改挂）：UFS/FFS 四十年演进史本身就是形式主义在文件系统工程中的体现——从 512 字节块到 8KB 块加片段、从同步写到 Soft Updates 再到 SUJ、从 32 位块指针到 64 位，每一次扩展都是在保持 on-disk 格式向后兼容的前提下对原有形式的修补；这种渐进式演进保证了兼容性，但也积累了大量技术债务

**辨析**：需澄清一个常见误解：“UFS 是 FFS 的另一个名字”——在 BSD 术语中，UFS 指上层目录结构和元数据处理代码（**src/sys/ufs/ufs/**），FFS 指下层数据块分配和物理布局代码（**src/sys/ufs/ffs/**），两者共同构成完整的文件系统实现；Solaris UFS、macOS 旧版 UFS 均从 BSD UFS/FFS 衍生但各自有扩展（如 Solaris UFS Logging 在 2000 年左右引入，早于 FreeBSD SUJ）；Dirhash 由 Ian Dowse 开发并集成入 FreeBSD，是 UFS 目录查找加速机制，常被遗漏
