# 121.4 其他存储栈组件：devfs、mdconfig、tmpfs、sendfile、VFS

## 121.4.1 **devfs(5)**：Poul-Henning Kamp（波尔-亨宁·坎普） 设计的动态设备文件系统（FreeBSD 5.0）

**要点**：FreeBSD 5.0 之前，/dev 目录下的设备节点是静态创建的，通过 MAKEDEV 脚本手动运行创建必要的节点，主/次设备号静态分配，新设备驱动需要修改 MAKEDEV 脚本并分配主设备号；**devfs(5)** 由 phk 设计，随 FreeBSD 5.0（2003 年 1 月）正式引入，是一个内核态虚拟文件系统，设备节点由设备驱动自动创建和销毁，无需用户态脚本；devfs 支持规则（rule）机制，可通过 **devfs.conf(5)** 和 **devfs.rules(5)** 配置设备节点权限、所有者、掩码，支持 **jail(8)** 环境下的 /dev 隔离（每个 jail 有独立的 devfs 实例）；FreeBSD 5.0 之后，**mknod(8)** 命令仍保留但手动创建的设备节点不生效，所有设备节点必须由内核 devfs 管理；Linux 在同一时期也经历了 devfs→udev/devtmpfs 的演进，但 Linux 选择了用户态 udev 管理设备节点，FreeBSD（以及 DragonFly BSD、Darwin/macOS）选择内核态 devfs

**史料**：**devfs(5)**, **devfs.conf(5)**, **devfs.rules(5)** 手册页；phk 2002-2003 年 freebsd-arch@ devfs 设计讨论；FreeBSD 5.0 Release Notes devfs 章节；MAKEDEV 脚本历史（FreeBSD 4.x 源码） ［A］

**史观**：总纲第 10 条——边缘者贡献：phk 一个人完成了 devfs 的设计和实现——这不仅是技术工作，更是政治工作：它要求所有设备驱动开发者修改驱动以支持新的设备注册 API，废弃使用了十几年的 MAKEDEV 和静态主/次设备号分配；这种 “大爆炸式” 架构切换在保守的 BSD 项目中非常罕见，只有 phk 这样资历深厚且风格强硬的核心开发者才能推动

**辨析**：一个常见误解是 “devfs 就是把 /dev 变成 tmpfs”——devfs 是专用的虚拟文件系统，不是 tmpfs 上自动创建节点：devfs 节点直接与内核对象关联，节点生命周期与设备驱动绑定，没有持久化状态；另一个比较：“Linux 的 udev 比 devfs 更灵活”——udev 运行在用户态确实可以做更多复杂策略（重命名、自动挂载、触发脚本），但 devfs 的内核态设计更简单、启动更早（在 init 启动前就可挂载）、在 jail/容器中隔离更彻底；**procfs(5)** 在 FreeBSD 中长期不推荐使用（默认不挂载），**linprocfs(5)** 仅用于 Linux 二进制兼容，这与 Linux 大量依赖 /proc 形成对比；FreeBSD 使用 **sysctl(8)** 获取大部分内核状态而非 procfs

**文献**：FreeBSD Project. **devfs(5)**, **devfs.conf(5)**, **devfs.rules(5)**, **mknod(8)** Manual Pages; Kamp, P.-H. (2002). *devfs Architecture Proposal*. freebsd-arch@; FreeBSD Project. *FreeBSD 5.0 Release Notes* (2003-01). ［A］

## 121.4.2 **mdconfig(8)** 内存盘与 vnode 盘

**要点**：**md(4)** 内存盘驱动（memory disk）提供了四种类型的虚拟盘：malloc 类型（使用内核 malloc 内存，适合小内存盘）、vnode 类型（backing store 是普通文件，类似 Linux loop 设备）、swap 类型（内存不足时可换出到交换区，推荐类型）、null 类型（空设备，写入丢弃读返回零，用于测试）；**mdconfig(8)** 是用户态配置工具，可创建、销毁、列出 md 设备；**md(4)** 不是 GEOM 模块，但在 GEOM 引入后与 GEOM 良好集成，md 设备可作为任何 GEOM 模块的 provider；md 驱动在 FreeBSD 4.x 时代引入，在 FreeBSD 5.0 中与 GEOM 框架整合完善；早期 FreeBSD 使用 **vn(4)** 驱动（vnode disk）提供文件虚拟盘功能，**md(4)** 引入后 **vn(4)** 被废弃；mdconfig 比 Linux losetup/loop 功能更丰富，支持直接从文件系统镜像引导（如 FreeBSD 安装镜像使用 md+vnode 作为根文件系统）

**史料**：**md(4)**, **mdconfig(8)** 手册页；FreeBSD 5.0 Release Notes md/GEOM 整合说明；FreeBSD src/sys/dev/md/ 源码；vn(4) 手册页（已废弃） ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界〔订正注：原挂“总纲第 2 条——实践先于理论”系错置（权威第 2 条为“历史是形式主义化的非存在”），2026-09-14 依权威表与核查报告改挂第 17 条，待复核〕：**md(4)** 的设计是 BSD 实用主义的体现——不是为了做一个 “完美的” 虚拟块设备，而是一次性解决所有虚拟盘需求：内存盘、文件-backed 盘、交换支持盘、测试用空盘；Linux 将这些功能分散在 loop（文件-backed）、brd/ramdisk（内存盘）等不同驱动中，FreeBSD 用一个统一驱动解决

**辨析**：时间线错误：“mdconfig 在 FreeBSD 5.0 引入”——**md(4)** 驱动本身在 FreeBSD 4.0 时代已存在，FreeBSD 5.0 中与 GEOM 整合并完善了 mdconfig 工具，**vn(4)** 在 FreeBSD 5.0 之后正式废弃；一个重要功能：md 内存盘支持预加载（preload），**loader(8)** 可在内核启动前将镜像文件加载入内存作为 md 根文件系统，这是 FreeBSD 从内存盘引导和无盘引导的基础功能；**mdmfs(8)** 是一个封装工具，自动配置 md 设备并在其上创建 UFS 文件系统并挂载，相当于 `mdconfig -a` + `newfs` + `mount` 的自动化

**文献**：FreeBSD Project. **md(4)**, **mdconfig(8)**, **mdmfs(8)** Manual Pages; FreeBSD Project. *FreeBSD 4.x/5.x Release Notes* md section.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 121.4.3 **tmpfs(4)**、**sendfile(2)** 与 VFS 层

**要点**：**tmpfs(4)** 内存文件系统由 Rohit Jalan 等人在 Google 编程之夏 项目中开发，后经 Julio Merino 等人完善，随 FreeBSD 7.0（2008 年 2 月）作为实验功能引入，FreeBSD 9.0 之后稳定并推荐使用；tmpfs 将所有文件内容存储在内存/交换区，不涉及磁盘 I/O，适合 /tmp、/var/run 等临时文件系统；与传统的 mfs(md+UFS) 方案相比，tmpfs 更轻量、不使用固定大小的内存盘、无需 newfs、支持动态增长；**sendfile(2)** 系统调用由 David Greenman（大卫·格林曼） 设计，随 FreeBSD 2.2 引入（实现于 1996-1997 年之交；首见版本 2.1.7/2.2 初期两说并存，见辨析），在文件描述符之间或文件到 socket 之间实现零拷贝数据发送——数据直接从文件系统缓存进入 socket 发送队列，无需经过用户态内存拷贝，这是高性能 Web 服务器（如 Apache、Nginx）在 FreeBSD 上性能出色的关键原因之一；VFS（Virtual File System）层源自 SunOS 4.x 的 VFS/Vnode 架构，FreeBSD 从 4.4BSD 继承 VFS 后持续演进，支持 VFS 挂载点、Vnode 操作向量、文件系统独立实现等概念；FUSE（Filesystem in Userspace）支持在 FreeBSD 10.0（2014 年 1 月）正式整合入基础系统（r241519），先前通过 sysutils/fusefs-kmod port 提供

**史料**：**tmpfs(5)**, **sendfile(2)**, **vfs(9)** 手册页；FreeBSD 7.0/8.0 Release Notes tmpfs 章节；Greenman 1996-1997 年 sendfile commit 记录；Rohit Jalan tmpfs Google 编程之夏 项目报告；McKusick et al. 2014 书第 6 章 VFS 部分 ［A］

**史观**：总纲第 10 条——动手者创造历史〔订正注：原挂“总纲第 6 条——技术路线分化”系错置（权威第 6 条为“和解优于斗争”），2026-09-14 依权威表与核查报告改挂第 10 条，待复核〕：**sendfile(2)** 的历史是 FreeBSD 对互联网基础设施贡献的典型案例——在 Apache HTTP Server 占据 Web 服务器主导的 1990 年代末，FreeBSD 因为 sendfile 零拷贝成为高负载 Web 服务器首选平台；Linux、Windows 等后来都引入了类似的 TransmitFile/sendfile 实现，但 FreeBSD 是首创之一；tmpfs 是 FOSS 协作模式的体现——Google 编程之夏 资助学生实现原型，社区后续完善并正式集成

**辨析**：几个关键时间点：**sendfile(2)** 首次出现于 FreeBSD 2.2（1997 年之前，具体为 FreeBSD 2.1.7 或 2.2 初期，1996-1997 年），比 Linux sendfile（Linux 2.2，1999 年）早约两年；tmpfs 引入 FreeBSD 的时间经 FreeBSD Release Notes 交叉验证：tmpfs 在 FreeBSD 7.0（2008 年 2 月）作为实验功能引入，FreeBSD 9.0 之后稳定并推荐使用；FreeBSD 的 FUSE 支持：**fuse(4)** 内核模块最初在 FreeBSD 7.x 通过 sysutils/fusefs-kmod port 提供，FreeBSD 10.0（2014 年）正式整合入内核源码树；**procfs(5)** 在 FreeBSD 中默认不挂载（与 Linux 不同），因为 FreeBSD 用 sysctl 获取进程信息，procfs 仅用于 Linux 二进制兼容和少数传统工具

**文献**：FreeBSD Project. **tmpfs(5)**, **sendfile(2)**, **fuse(4)** Manual Pages; FreeBSD Project. *FreeBSD 7.0, 9.0, 10.0 Release Notes*; Greenman, D. (1996-1997). *sendfile(2) Implementation Commits*. svn.freebsd.org (or cvs.freebsd.org for older); McKusick, M. K. et al. (2014). *The Design and Implementation of the FreeBSD Operating System* (2nd ed.). Chapter 6-7. ［A］

## 121.4.4 NFS 客户端/服务器与异步 I/O（aio）

**要点**：FreeBSD NFS 支持历史：NFSv2 在 BSD 4.3 时代即已引入，NFSv3 在 FreeBSD 3.x/4.x 时期支持，NFSv4 由 Rick Macklem 主导重写，新的 NFSv4 客户端/服务器实现随 FreeBSD 8.2/9.0（2012 年前后）引入，支持 NFSv4.0、NFSv4.1（含 pNFS 部分特性），旧 NFS 实现仍保留为兼容；NFS 实现位于内核 **nfsclient(4)** 和 **nfsserver(4)** 模块，用户态工具包括 **nfsstat(1)**, **mount_nfs(8)**, **gssd(8)**（Kerberos 认证）；异步 I/O（**aio(4)**）在 FreeBSD 3.x 时期引入，支持 POSIX AIO 接口（aio_read/aio_write/lio_listio 等），允许用户态进程发起 I/O 请求后不阻塞继续执行，通过信号或回调通知完成；FreeBSD 的 aio 实现支持文件和 socket 两种类型的异步 I/O；**aio(4)** 在 FreeBSD 5.x/6.x 时期经过重写以支持 SMP 和 kqueue 集成

**史料**：**nfs(5)**, **aio(4)**, **nfsstat(1)**, **mount_nfs(8)** 手册页；Rick Macklem NFSv4 设计文档与提交记录；FreeBSD 9.0 Release Notes NFSv4 章节；McKusick et al. 2014 书第 9 章网络文件系统部分 ［A］

**史观**：总纲第 10 条——动手者创造历史〔订正注：原挂“总纲第 22 条——开源运动”系错置（权威第 22 条为“知识注定过时”），2026-09-14 依权威表与核查报告改挂第 10 条，待复核〕：NFSv4 在 FreeBSD 中的重写是 “社区维护关键基础设施” 的典型——Rick Macklem 作为 University of Guelph 的工作人员，几乎以一己之力完成了 NFSv4 客户端和服务器的重写，并持续维护十余年；没有商业公司资助这一工作，完全是出于学术和社区需求

**辨析**：时间线错误：“NFSv4 在 FreeBSD 8.0 引入”——新 NFSv4 客户端/服务器代码在 FreeBSD 8.2（2011 年 7 月）和 9.0（2012 年 1 月）中正式发布，旧的 NFSv2/v3 实现继续可用，用户可通过 mount 选项选择使用新/旧实现；FreeBSD NFSv4.1/pNFS 支持在 FreeBSD 12/13 中持续完善；**aio(4)** 的一个误区：“FreeBSD aio 是用户态线程模拟”——早期 FreeBSD aio 确实通过用户态 helper 线程池实现（aio daemon），但现代 FreeBSD（6.x+）内核态实现支持原生异步 I/O，对于不支持原生异步的文件系统（如 UFS 某些路径）仍会回退到内核线程池，但对 ZFS 等原生异步支持良好的文件系统性能出色

**文献**：FreeBSD Project. **nfs(5)**, **aio(4)**, **nfsstat(1)** Manual Pages; Macklem, R. (2009-2012). *New NFSv4 Client/Server Implementation Commits*; FreeBSD Project. *FreeBSD 9.0 Release Notes* NFSv4 section; McKusick, M. K. et al. (2014). *The Design and Implementation of the FreeBSD Operating System* (2nd ed.). Chapter 9. ［A］
