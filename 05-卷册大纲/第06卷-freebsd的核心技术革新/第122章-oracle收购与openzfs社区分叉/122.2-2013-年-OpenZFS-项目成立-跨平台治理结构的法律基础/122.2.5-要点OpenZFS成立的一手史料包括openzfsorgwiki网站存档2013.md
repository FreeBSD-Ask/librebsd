# 122.2.5 要点OpenZFS成立的一手史料包括openzfsorgwiki网站存档2013

**要点**：OpenZFS 成立的一手史料包括：openzfs.org/wiki 网站存档（2013 年上线）、第一届 OpenZFS Developer Summit 的演讲视频和幻灯片（YouTube/archive.org 存档）、Matt Ahrens 在 LinuxCon 2013（2013 年 9 月）和 BSDCan 2013 上关于 OpenZFS 的演讲；OpenZFS Developer Summit 自 2013 年起每年举办一届，是 ZFS 社区的主要技术聚会；Bylaws 文档可在 openzfs.org/wiki/Bylaws 查阅；OpenZFS 的商标状态：“OpenZFS” 商标由 OpenZFS 组织持有（非 Oracle），这确保了社区对项目名称的控制权

**史料**：openzfs.org/wiki 网站（互联网档案馆 2013 年起存档）；第一届 OpenZFS DevSummit 演讲视频和幻灯片；Matt Ahrens LinuxCon 2013 演讲；OpenZFS Bylaws 文档 ［A］

**史观**：专题语（不设总纲条号）——形式与内容的张力（原挂总纲第 3 条系伪名目）：Bylaws 的制定和商标的注册是开源项目治理形式化的典型步骤——这些法律文件为社区自治提供了形式基础，但真正的项目凝聚力来自代码贡献和技术共识，而非治理文件本身

**辨析**：OpenZFS 是否于 2013 年 “成立” 存在不同说法——部分来源认为 OpenZFS 在 2013 年 DevSummit 上 “正式宣布成立”，但实际上 “OpenZFS” 这一名称在 2013 年前已被非正式使用（作为 “开源 ZFS 实现” 的统称）；2013 年 DevSummit 的重要性在于正式建立了跨平台治理结构而非简单使用一个名称

**文献**：OpenZFS Project. *Developer Summit Archives*. openzfs.org; Ahrens, M. (2013). *The OpenZFS Project*. LinuxCon NA 2013; OpenZFS Project. *Bylaws*. openzfs.org/wiki/Bylaws. ［B］

**要点**：

- Delphix 的 George Wilson 阐明 Compressed ARC 的设计路线：放弃业界通行的内存换出前压缩方案，利用磁盘块本已压缩的事实，让内存始终保持压缩形态、仅在读取瞬间解压，即“uncompressing data is a heck of a lot faster than compressing it”（2309.42-2314.38）。第一轮激进实现（跨文件系统共享块加回调通知机制）在完成约百分之九十五时暴露重大架构缺陷而中止，第二轮简化方案成为最终交付版本，计划于 2016 年 1 月进入 OpenZFS；实测 ARC 有效容量膨胀约 2.5 至 3 倍，128K 块解压读取约 200 微秒，单核解压吞吐 1.8-2 GB/s，不可压缩块经 shared ARC 共享指针免二次拷贝。（BSD Now EP116，[2258.47-2443.30]，L1）
- Wilson 回顾池恢复工作的起点：入职 ZFS 团队后的首个任务即排查一起客户存储池损坏，通过解析全盘 DD 镜像中的文件头，最终发现损坏根源是一名管理员误将池中磁盘重新分区为 Linux 盘，与 ZFS 本身无关；此后约完成百余次池恢复，多数归因于用户误操作或其他软件的编程错误。他将池恢复视为超越本职、观察用户真实用法的窗口，此叙事呈现了维护者隐性运维经验的生成过程。（BSD Now EP116，[3839.40-3959.18]，L1）
- Hubbard 以当事人身份界定 NextBSD 的性质：它不是又一个分叉，而是一间验证异步服务架构的“实验室”（3553.34-3556.26），先把 launchd、libdispatch、Mach IPC、notifyd 等技术在独立环境打磨成熟，再择机回灌 FreeBSD 主线；他明确不愿重演 DragonFly BSD 式的长期分流，认为现有 BSD 数量已经够多，若其他项目能从 NextBSD 摘取成果反而是造福生态（4573.44-4602.40）。（BSD Now EP113，[3553.34-3565.18]，L1）
- 新闻段记录 OpenBSD 5.8 于项目二十周年当日（10 月 18 日）发布（1008.96-1020.05）：冻结时名为 tame 的权限约束 API 首次随版附送，且“已被更名为 pledge”（1105.34-1107.96）；sudo 移出基本系统、由更精简的 doas 承担提权；file 命令重写并引入沙箱与特权分离；LibreSSL 的 OpenSSL 命令行移除 SSLv3 支持。主持人据此把 5.8 读作 OpenBSD 以年度发布节奏持续收紧默认信任边界的一个节点。（BSD Now EP113，[1008.96-1174.68]，L2）
- 嘉宾自述 20 世纪 90 年代末供职广告公司时，Linux 承载的每日数亿独立 IP 短连接业务频现进程挂死与性能瓶颈；上司从办公桌取一张 Walnut Creek CD 为机器装上 FreeBSD，返工后响应时间下降且故障消失，这次偶然接触使其此后近二十年将 FreeBSD 留在工具箱。入坑叙事以具体偶发事件而非必然趋势呈现，是典型的当事人一手记忆。（BSD Now EP95，[976.92-1048.47]，L1）
- ZFS 救场叙事构成全期最具体的运维证据：一次 zpool scrub 返回非零错误计数，ZFS 检测并自动修复，业务无感；更严重的一次事故中 RAID 卡固件缺陷使其停止响应 IO，团队以 PXE 引导进入 MFS root 用 mfiutil 刷新固件，重启后仅识别八块盘中的六块，再重启方恢复，最终依赖 ZFS 校验和读取出全部数据，嘉宾称之为“没爆炸的炸弹”（1641.90-1648.85）；其背景是早期以 RAID0 卷暴露给 ZFS 而非 HBA 直通的历史教训。（BSD Now EP95，[1470.00-1651.86]，L1）
- 迁移后的性能判断呈总体无差异论：磁盘速度决定吞吐上限，负载大头在用户态，十亿行排序在 Linux 与 FreeBSD 上表现一致；唯一显著的一次约三倍提升来自从 Debian 加 Fusion-IO 卡换到 FreeBSD SSD 加 ZFS 的架构变更，但其归因被谨慎地指向原 Linux 端 RAID 镜像实现问题。价值判断转向可观测性与正确性：“不正确的话快慢毫无意义”（1732.55-1735.20），以 VFS/VOP 层延迟与 physio 请求的 DTrace 分位数测量和 gstat、iostat 基础工具为支撑，并直陈系统缺失直方图导出与内建火焰图。（BSD Now EP95，[1707.49-1944.35]，L1）

- Daroussin 阐明 base 打包化的三重动机：freebsd-update 跨大版本升级缓慢且自建更新服务器困难；需要精确追踪 base 系统每个文件并在升级时清理旧文件；拆分为多包后嵌入式等场景可按需取用子集实现最小安装。初期方案先用极少数包整体承载 base，再逐步细分。（BSD Now EP84，[1535.16-1601.32]，L1）

- OpenZFS 在 LinuxCon 上宣布成立，FreeBSD、ZFS on Linux、illumos 等各方协作维护开源 ZFS，并以特性标志与版本统一降低各实现差异。（BSD Now EP3，[2935.46-3032.28]，L2）
- Ahrens 口述 ZFS 起源：Jeff Bonwick 早于项目一年多即受命为 Solaris 打造下一代文件系统，配有十余名多为 UFS 出身的人手却因迟迟无设计而难以推进，遂向管理层承认原路不通；2001 年他与刚毕业的 Ahrens 以两人小组在雷达之下重启 ZFS，白板推演设计。分工上 Bonwick 深谙 Solaris 内核与大公司政治，负责在需要低调时维持项目隐匿、在有所成果时对外推广，Ahrens 则以新人之姿不设设计成见，二人自认缺一不可。 [存疑脚注] 转写将 Jeff Bonwick 记作 Jeff Bondwick、将 skunkworks 记作 SoundQuirks，均按语境校正。（BSDTalk EP227，[121.88-315.90]，L1）
- 早期时间线：2001 年夏提出基本设计，并以 Ahrens 在校期间所写的文件系统 interposer 层实现用户态原型，约五六个月后的 2001 年万圣节前后跑通，万圣节自此成为 ZFS 的标志性节点；随后引入有 UFS 经验的 Mark Maybee 等人负责 ZPL 层，即实现属主、文件大小、权限、目录与符号链接等真实文件系统语义的部分，约一年后的 2002 年万圣节前后得到可随 Solaris 运行常规工具的内核级完整文件系统。 [存疑脚注] 转写作 Mark Mabee 与 Marcus Schellenbaum，按语境疑为 Sun 的 UFS/ZFS 工程师 Mark Maybee 与 Mark Shellenbaum，须以原始音频与 Sun 时期人员记录复核。（BSDTalk EP227，[392.72-502.08]，L1）
- 开源与信任曲线：2005 年万圣节前后 ZFS 源码随 OpenSolaris 发布，彼时团队约十余名工程师、累计投入近 100 工程年；发布虽引起热望，但用户对把数据托付给新文件系统持保留态度，历经新品亮相、进入 Solaris 10 成受支持产品、客户测试数月乃至一年后进入生产的缓慢爬坡；近两三年 ZFS 经 OpenZFS 运动可用于 FreeBSD、Linux 与 macOS，用户与以其为业的企业数量激增。（BSDTalk EP227，[518.66-610.58]，L1）
- 可移植性源于设计阶段的模块化分层而非移植意图——ZFS 当年深嵌 Solaris：最上层的 ZPL/POSIX 层因须对接各平台 VFS 而差异最大，中部大块代码高度可移植，最底层的磁盘接口既小又易于移植，这种清晰分层同时解释了 ZFS 后来的跨平台扩散能力。（BSDTalk EP227，[724.44-794.26]，L1）
- OpenZFS 伞状项目在 2013 年访谈时点刚刚起步、尚无正式管理结构，目标是把 Illumos/Solaris 衍生、FreeBSD 与 Linux 各平台实现收拢一伞，让各平台的创新彼此可得、避免在每处重复修同一 bug。现状是 Illumos 为上游仓库、改动流向 Linux 与 FreeBSD，但 FreeBSD 开发者向 Illumos 回馈改动因对方社区更小、缺乏便捷的开发测试环境而困难；第一步即降低向 Illumos 集成改动的门槛，Ahrens 正与 FreeBSD 社区的 ZFS 负责人协作推进。 [存疑脚注] 转写将 FreeBSD 侧协作人记作 Powell，按语境疑为曾主持 ZFS 移植 FreeBSD 的 Pawel Dawidek，待原音频复核。（BSDTalk EP227，[858.58-998.08]，L1）
- 对重写问题的回应：ZFS 基础扎实、极易修改与增强，去重即开发晚期干净加入且代码集中于单层，故无需推倒重来，并以 UFS 约三十年的寿命为期许。但若今日重新设计，将面向未来十年以 Flash 为主的硬件：Flash 随机读能力强，或使常开去重变得可行——去重如今依赖巨型哈希表在每次写块时查询，磁盘介质上代价高昂，SSD 化后可望大幅缓解。（BSDTalk EP227，[1115.24-1409.52]，L1）

**史料**：
