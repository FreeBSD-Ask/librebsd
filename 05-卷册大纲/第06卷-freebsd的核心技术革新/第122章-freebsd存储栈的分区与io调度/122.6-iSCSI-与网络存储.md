# 121.6 iSCSI 与网络存储

## 121.6.1 iSCSI target/initiator 演进：iscontrol、istgt、ctld
  - 要点：FreeBSD 的 iSCSI 支持分几个阶段：早期 FreeBSD 7.x/8.x 时代，iSCSI initiator（客户端）使用 **iscontrol(8)** 工具配合 **iscsi_initiator(4)** 内核模块，功能有限且不稳定；iSCSI target（服务器端）长期由 ports 中的 istgt、iscsi-target 等第三方软件提供；FreeBSD 10.0（2014 年 1 月）前后，Edward Tomasz Napierała 从头重写了 iSCSI 栈：新的 **iscsictl(8)** initiator 与 **iscsid(8)** 守护进程替代了旧 iscontrol，内核模块 **iscsi(4)** 实现完整的 iSCSI 协议；同时，新的 **ctld(8)**（CAM Target Layer Daemon）iSCSI target 守护进程随 FreeBSD 10.0 一同引入基础系统，ctld 使用 CAM Target Layer（CTL）作为后端，支持 SPC-3/4、Persistent Reservations、ALUA、VAAI 等企业级存储特性，是性能和功能最完善的 BSD 原生 iSCSI target
  - 史料：**iscsi(4)**, **iscsictl(8)**, **ctld(8)**, **ctl(4)** 手册页；Napierała 2013-2014 年 iSCSI 重写提交记录（r255570）；FreeBSD 10.0 Release Notes iSCSI 章节；FreeBSD Handbook “iSCSI” 章节 ［A］
  - 史观：总纲第 2 条——实践先于理论：FreeBSD iSCSI 从 “第三方 ports 软件凑合用” 到 “内建高性能企业级实现”，走的是典型的 BSD 实用主义路线——先不追求完美，让用户先用起来，当有人（Napierała 受 FreeBSD 基金会资助）有动力重写时，再基于过去十年的使用经验做正确的设计
  - 辨析：关键时间点需精确：新的 **iscsi(4)** initiator 与 **ctld(8)** target 均在 FreeBSD 10.0（2014 年 1 月）正式发布（r255570），同时替代 iscontrol 和第三方 istgt；**ctl(4)**（CAM Target Layer）是 ctld 的内核后端，支持将任意 GEOM provider（磁盘、分区、ZFS zvol、md 内存盘等）导出为 SCSI 目标设备，除 iSCSI 外还支持 Fibre Channel、SAS 等物理传输；旧的 **iscontrol(8)** 在 FreeBSD 10.x 中仍保留用于兼容但不推荐使用
  - 文献：FreeBSD Project. **iscsi(4)**, **ctld(8)**, **ctl(4)** Manual Pages; Napierała, E. T. (2013-2014). *iSCSI Stack Rewrite Commits* (r255570); FreeBSD Project. *FreeBSD 10.0 Release Notes* iSCSI section. ［A］
## 121.6.2 HAST：FreeBSD 原生高可用存储复制
  - 要点：HAST（Highly Available Storage）由 Paweł Jakub Dawidek（GELI 作者）设计，随 FreeBSD 8.0（2010 年 1 月）正式引入基础系统；HAST 通过 GEOM 类 **hast(4)** 实现块级同步复制，在两个 FreeBSD 节点之间同步存储数据，类似于 DRBD（Linux Distributed Replicated Block Device）；HAST 工作在主-从模式下，主节点接受读写并同步到从节点，主节点故障时从节点可提升为主；HAST 使用 **hastd(8)** 守护进程处理网络通信和数据同步，支持同步复制（数据写入两个节点后返回成功）和异步复制模式；HAST 与 CARP（Common Address Redundancy Protocol）、ucarp 等配合可构建完整的高可用存储集群
  - 史料：**hast(4)**, **hastd(8)**, **hastctl(8)** 手册页；Dawidek 2009-2010 年 HAST 设计文档与提交记录；FreeBSD 8.0 Release Notes HAST 章节；FreeBSD Handbook “High Availability Storage” 章节 ［A］
  - 史观：总纲第 2 条——实践先于理论：HAST 是 FreeBSD 生态中 “原生解决高可用存储” 需求的实践——在 HAST 之前，FreeBSD 用户要么依赖商业 NAS/SAN，要么使用复杂的 ggate+ 自定义脚本，Dawidek 作为 GELI 作者将 GEOM 框架的设计哲学延伸到网络复制领域，用一个 GEOM class 解决了问题
  - 辨析：HAST 与 DRBD 的定位类似但技术路线不同：DRBD 长期在 Linux 内核主线外，后并入主线，支持更多复制模式和四节点以上集群；HAST 自 FreeBSD 8.0 起内置于基础系统，但仅支持双节点复制，没有发展出多节点集群功能；HAST 在 FreeBSD 生产环境中使用度远低于 ZFS 复制（zfs send/receive）和外部存储阵列，部分原因是 ZFS 内置复制功能更灵活且与文件系统深度集成；截至 2025 年，HAST 仍随 FreeBSD 发布但新功能开发较少
  - 文献：FreeBSD Project. **hast(4)**, **hastd(8)**, **hastctl(8)** Manual Pages; Dawidek, P. J. (2009-2010). *HAST Design and Commits*. svn.freebsd.org; FreeBSD Project. *FreeBSD 8.0 Release Notes* HAST section. ［A］
## 121.6.3 NFS、ggate 与其他网络存储机制
  - 要点：FreeBSD 网络存储生态除 iSCSI 和 HAST 外，还包括：NFS（Network File System）作为最古老的分布式文件系统协议在 FreeBSD 中有完整的客户端/服务器实现（NFSv2/v3/v4，详见 78.4.4 节）；**ggate(8)**（GEOM Gate）允许用户态程序通过网络导出块设备，是 HAST 和其他用户态 GEOM 模块的基础；**nfsv4(4)** 新客户端/服务器在 FreeBSD 8.2/9.0 引入后持续改进，支持 pNFS 部分特性；SMB/CIFS 客户端和服务器通过 ports 中的 samba 提供，内核态 **smbfs(5)** 支持 SMB 挂载；FreeBSD 还支持 AFS、Ceph 等分布式文件系统通过 FUSE 或 ports 提供
  - 史料：**ggate(4)**, **nfs(5)** 手册页；FreeBSD Handbook 网络文件系统章节；FreeBSD 各版本 Release Notes NFS 改进记录；Samba 项目官方文档 ［A］
  - 史观：总纲第 22 条——开源运动：FreeBSD 网络存储生态的特点是 “提供核心机制，具体方案由用户选择”——内核只提供 GEOM、NFS、iSCSI、ggate 等基础机制，不强制用户使用特定的高可用或分布式存储方案，与 ZFS 这样的 “一体化” 方案形成互补
  - 辨析：FreeBSD 基础系统不包含 Ceph、Gluster 等分布式存储，这些都通过 ports/pkg 提供；这与 Linux 发行版将客户端/服务器全部打包入默认安装不同，体现了 FreeBSD “基础系统最小化、附加软件通过 ports” 的设计哲学；**ggate(8)** 是一个常被忽视但技术上很优雅的设计——它允许用户态进程实现 GEOM provider，这使得 HAST 等网络块设备可以在用户态处理网络协议而不需要全部在内核实现
  - 文献：FreeBSD Project. **ggate(4)**, **ggated(8)** Manual Pages; FreeBSD Project. *FreeBSD Handbook - Network Filesystems*. docs.freebsd.org. ［B］
