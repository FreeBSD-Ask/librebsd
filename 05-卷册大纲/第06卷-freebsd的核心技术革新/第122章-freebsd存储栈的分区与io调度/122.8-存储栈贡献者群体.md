# 121.8 存储栈贡献者群体

## 121.8.1 核心贡献者的个人印记
  - 要点：FreeBSD 非 ZFS 存储栈的核心贡献者带有强烈的个人印记：麦库西克 主导了 FFS/UFS/UFS2/Soft Updates/SUJ 长达四十年的演进，他是 Berkeley CSRG 的资深成员，将 FFS 从 4.2BSD 一路维护到现代 FreeBSD；Poul-Henning Kamp（波尔-亨宁·坎普）（phk）主导了 GEOM、GBDE、devfs、UFS2 共同设计等 FreeBSD 5.0 存储栈现代化核心工作，他是 FreeBSD 最具影响力也最有争议的核心开发者，Varnish 缓存代理作者；Justin T. Gibbs（贾斯廷·T·吉布斯） 设计并实现了 CAM SCSI 子系统，后创立 iXsystems 并发起 FreeBSD 基金会；Paweł Jakub Dawidek 实现了 GELI 加密，也是 ZFS 移植到 FreeBSD 的主要功臣，还参与了 Capsicum 安全框架开发；Jeff Roberson 设计了 SUJ 和 ULE 调度器；Alexander Motin 完成了 ATA/SATA 接入 CAM 的现代化工作；Jim Harris 完成了 NVMe 驱动；Edward Tomasz Napierała 重写了 iSCSI 栈；这不是一个 “社区共识” 驱动的项目，而是一系列个人贡献者在不同历史时期留下的叠加
  - 史料：FreeBSD src 仓库各子系统 MAINTAINER 文件和提交历史；各贡献者的 BSDCan/AsiaBSDCon 演讲；FreeBSD 基金会项目报告；McKusick 口述历史 ［B］
  - 史观：总纲第 10 条——边缘者贡献：FreeBSD 存储栈的历史就是一部 “动手者创造历史” 的历史——McKusick 在 Berkeley 做研究生时写出 FFS、phk 在为报纸做网络基础设施工作之余写出 GEOM、Gibbs 在 Adaptec 工作期间写出 CAM、Dawidek 在波兰写出 GELI；没有一个是规划委员会的产物，都是具体的人在具体的时间解决具体问题的结果
  - 辨析：贡献者统计中的性别和地域偏差——上述核心贡献者全部为男性，主要来自美国（McKusick、Gibbs、Harris、Napierała 等）、北欧（phk 来自挪威）、东欧（Dawidek 来自波兰），缺乏女性和非欧美开发者贡献记录，这反映了 1990-2010 年代开源社区整体的人口结构问题，不是 FreeBSD 独有；但不能因为这种结构偏差就否定个人贡献的价值

## 121.11.5 freebsd-src 趋势统计与非 ZFS 存储栈演进的定量印证
  - 要点：**统计分析印证**——`bsd_commits.db` freebsd-src 仓库 1993-2026 年 commit 月度量 Mann-Kendall 趋势检验结果为显著上升趋势（Sen's slope =+1.40/月，p < 0.001，95% CI [1.11, 1.69]）（统计结论 C-03）；ARIMA(5,0,5) 模型拟合 AIC = 107.39（统计结论 C-29）；非 ZFS 存储栈（GEOM、CAM、GELI、GBDE、UFS2、soft updates、SUJ）作为 freebsd-src 核心子系统，其演进与整体 freebsd-src 趋势一致——存储栈持续重构未中断整体 commit 增长；GEOM 框架由 phk（Poul-Henning Kamp）设计、CAM 由 Justin Gibbs 设计、GELI 由 Pawel Jakub Dawidek 设计，这些子系统在 freebsd-src 中的持续演进反映了 FreeBSD 存储栈的多元化路径
  - 史料：`bsd_commits.db` `commits` 表 freebsd-src 仓库 commit 月度量；SQL 查询 `SELECT strftime('%Y-%m', committer_date) AS month, COUNT(*) AS commit_count FROM commits WHERE repo_name='freebsd-src' GROUP BY month ORDER BY month`；Python 脚本 `script/phase3_inferential_stats.py` Task 5（Mann-Kendall 趋势检验）；Python 脚本 `script/phase4_time_series.py` Task 14（ARIMA 建模）；统计结论编号 C-03、C-29；查询日期 2026-07-27 ［A］
  - 史观：总纲第 22 条——赓续而非断裂：非 ZFS 存储栈（UFS2+SUJ、GEOM、GELI）与 ZFS 在 freebsd-src 中共存而非替代——freebsd-src 趋势检验显示存储栈多元化路径未产生开发断裂；总纲第 10 条——边缘者贡献：phk、Gibbs、Dawidek 等核心工程师对存储栈的个人贡献持续影响 freebsd-src 演进
  - 辨析：**统计局限性标注**——(1) 统计显著 ≠ 实际显著：Mann-Kendall 趋势检验 p < 0.001 表明 freebsd-src commit 量存在统计学显著上升趋势，但存储栈实际演进须结合具体子系统（GEOM、CAM、GELI、UFS2）的版本化分析；(2) 非 ZFS 存储栈贡献率未量化：commit 量统计不区分存储栈相关 commit 与其他子系统 commit，非 ZFS 存储栈作为 freebsd-src 子集其对整体趋势的贡献率未单独量化；(3) ARIMA 模型局限：ARIMA(5,0,5) AIC = 107.39 为 freebsd-src 整体 commit 序列拟合结果，未单独建模存储栈相关 commit 子序列；(4) 多重比较风险：本结论与第五卷其他章节引用相同 freebsd-src 趋势统计存在多重比较风险；(5) soft updates 退出未单独统计：OpenBSD、NetBSD 先后移除 Soft Updates 支持，但 freebsd-src 中 UFS soft updates 仍保留，其 commit 变化未单独建模

### 史观映射

> GEOM 的模块化架构是 phk 一个人对着存储层发呆时想出来的东西——偶然而非必然，一个人的洞察决定了 FreeBSD 存储栈此后二十年的骨骼。CAM 同样是 Gibbs 一个人的手笔，GELI 是 Dawidek 的作品，SUJ 是 Roberson 的补丁。动手者创造历史，不是群体的决议而是具体的人在具体的夜晚写下的代码。但 soft updates 的命运提醒着：一个工程师的执念能支撑一个文件系统四十年——从 McKusick 1983 年的研究生时期到 2012 年 Roberson 的 SUJ 补丁——却无法逆转整个产业的选择。当 Aurora 说 soft updates “过于难以理解、实现和维护”，当 Solaris、ext3/ext4、XFS、NTFS 集体转向日志，当 NetBSD 和 OpenBSD 先后移除 Soft Updates 支持，McKusick 的执念从工程遗产变成了一个时代拒绝放手的美学姿态。FFS 从 1983 年 8KB 块加柱面组开始，一路演进到 UFS2 的 64 位块指针加 SUJ 日志，这不是 “向前兼容” 的保守，而是一个工程师对自己创造物的责任——他没有像 Sun 那样放弃 UFS 转投 ZFS，像 Linux 那样在 ext2/ext3/ext4/Btrfs/XFS 之间反复试错，而是在自己创造的基础上修修补补了四十年。这是 BSD 方式的优点也是缺点：你信任一个聪明人四十年前写的代码能修到今天，你也要承担这份信任带来的历史负担。
