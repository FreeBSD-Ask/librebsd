# 122.10 与同时期操作系统的比较：FreeBSD 非 ZFS 存储栈——GEOM/gvinum/UFS——与 Linux、Windows、illumos、其他 BSD 的对照

## 122.10.1 Linux LVM / btrfs / ext4

**要点**：Linux 存储栈以 LVM（逻辑卷管理）提供卷抽象、ext4 为默认文件系统（含 delayed allocation、journal）、btrfs 提供写时复制与卷管理合一；与 FreeBSD 的 GEOM（模块化存储变换框架）+ UFS（soft updates/journal）形成对照，二者在 “卷管理 vs 文件系统” 的边界划分上思路不同。

**史料**：Linux LVM2/ext4/btrfs 文档；FreeBSD GEOM/UFS 手册（geom(4)、tunefs(8)）［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：Linux 将卷管理（LVM）与文件系统（ext4/btrfs）分层，FreeBSD 以 GEOM 统一存储变换层，体现两种存储架构哲学。

**辨析**：btrfs 的 CoW 与 ZFS 思路相近而非与 UFS 对照；本章限非 ZFS 部分，故侧重 GEOM/UFS 与 LVM/ext4 的架构差异。

**文献**：Rodeh O et al. btrfs Design [EB/OL]；FreeBSD. GEOM Manual [Z]. ［B］

## 122.10.2 Windows Storage Spaces（2012）

**要点**：Windows Server 2012 引入 Storage Spaces，以虚拟化存储池提供镜像/奇偶校验，理念类似软件 RAID；与 FreeBSD 的 gmirror/gstripe/graid 对应，但基于 NT 存储栈与 PowerShell 管理，闭源不可审计。

**史料**：Microsoft Storage Spaces 文档（2012）［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：Storage Spaces 的 “存储池虚拟化” 与 GEOM/graid 的 “模块化 RAID” 目标相似但生态与可审计性不同。

**辨析**：Storage Spaces 与 gmirror 功能重叠，但 Windows 闭源使故障排查依赖微软；FreeBSD 的软 RAID 可完全开源审计。

**文献**：Microsoft. Storage Spaces Overview [Z]. 2012.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 122.10.3 illumos / Solaris ZFS 与 SVM

**要点**：illumos/Solaris 以 ZFS（卷与文件系统合一的 CoW）与早期 SVM（Solaris Volume Manager）著称；ZFS 本为 Solaris 原创，FreeBSD 移植并深度整合（见 ZFS 专章），其 SVM 则对应 FreeBSD 的 GEOM 卷管理；Solaris 存储技术经 ZFS 反哺整个 BSD/Linux 生态。

**史料**：illumos/Solaris ZFS/SVM 文档 ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律：ZFS 由 Solaris 原创、FreeBSD 移植并共同发展，体现 UNIX 存储技术的跨生态流动（非 BSD 原创但被 BSD 吸收）。

**辨析**：SVM 与 GEOM 均为卷管理层但 SVM 较旧；ZFS 已另章专述，此处仅对照非 ZFS 的卷管理层。

**文献**：Sun/Oracle. ZFS/SVM Documentation [Z]；illumos. Documentation [EB/OL]. ［B］

## 122.10.4 其他 BSD 存储（NetBSD RAIDframe、OpenBSD softraid、DragonFly HAMMER）

**要点**：NetBSD 以 RAIDframe 提供软 RAID；OpenBSD 以 softraid(4) 提供加密/RAID 卷；DragonFly 以 HAMMER/HAMMER2 提供 CoW 文件系统（独立于 ZFS）；三者与 FreeBSD 的 GEOM/gmirror 同源 4.4BSD 存储思想，在卷管理与文件系统上并行演进、代码互鉴；OpenBSD 另在 2005 年后对 SCSI 中间层实施重大重构——引入 mpath(4) 多路径虚拟总线与 iopools 资源池、将适配器命令处理器改为回调式 scsi_done API，以改善稳定性、性能与可扩展性，与 FreeBSD 同期 CAM 层的整合路径形成对照（Gwynne & Westerback, 2011）

**史料**：各 BSD 存储文档（RAIDframe/softraid/HAMMER）［B］；Gwynne D, Westerback K R. OpenBSD SCSI Evolution [C]//EuroBSDCon 2011. 2011（详述 OpenBSD SCSI midlayer 重构：mpath(4) 多路径、iopools、scsi_done 回调化）

**史观**：总纲第 4 条——分离聚合是永恒规律：三大 BSD 的存储栈同源、各发展出特色层（GEOM/gmirror、RAIDframe、softraid、HAMMER），体现 BSD 家族 “代码自由流动 + 各自创新”。

**辨析**：软 RAID 实现（gmirror/RAIDframe/softraid）功能类似但 API 与管理工具不同；HAMMER 是 DragonFly 独有能力（CoW 文件系统），与 ZFS/btrfs 同类。

**文献**：NetBSD. RAIDframe Manual [Z]；OpenBSD. softraid(4)[Z]；DragonFly. HAMMER Documentation [EB/OL]. ［B］

## 122.10.5 同期存储栈技术路线总览

**要点**：2010-2020 年存储栈呈现 “卷管理分层（Linux LVM）vs 统一变换层（FreeBSD GEOM）vs 存储池（Windows Storage Spaces）vs CoW 合一（ZFS/btrfs/HAMMER）” 的多路线格局；FreeBSD 的 GEOM 以模块化、可组合著称，UFS 的 soft updates 提供元数据一致性保障，在非 ZFS 领域保持工程简洁性。同期主流操作系统存储栈关键维度对比汇总见下表。

| 操作系统 | 卷管理/变换层 | 默认文件系统 | 一致性机制 | 软 RAID | 磁盘加密 | 可审计性 |
| --- | --- | --- | --- | --- | --- | --- |
| FreeBSD | GEOM（模块化变换框架，2003） | UFS2+SUJ（默认）；ZFS 可选 | Soft Updates+SUJ 日志 | **gmirror(8)**/**gstripe(8)**/**graid3(8)**/**graid(8)** | **gbde(8)**/**geli(8)** | 完全开源 |
| Linux | LVM2+Device Mapper（2002） | ext4（含 delayed allocation、journal） | 日志（journal） | mdadm（MD RAID） | LUKS/cryptsetup | 完全开源 |
| Windows | Storage Spaces（2012） | NTFS（默认）；ReFS 可选 | NTFS 日志；ReFS B+ 树 + 校验 | Storage Spaces 镜像/奇偶校验 | BitLocker | 闭源 |
| illumos/Solaris | SVM（Solaris Volume Manager） | ZFS（卷与文件系统合一） | ZFS CoW+ 校验 | ZFS RAID-Z | ZFS 加密 | illumos 开源；Solaris 闭源 |
| NetBSD | ccd（“gate”疑为笔误，NetBSD 存储驱动无此名，候选 cgd(4) 见加密列） | FFS（UFS）+ WAPBL 日志 | 日志（WAPBL） | RAIDframe | cgd(4) | 完全开源 |
| OpenBSD | softraid(4) | FFS（UFS，已移除 Soft Updates） | 无日志，依赖 fsck　[存疑脚注] 原作“转日志”，日志式 WAPBL 系 NetBSD 机制，OpenBSD 无 FFS 日志实现 | softraid RAID 0/1/5　[存疑脚注] 原作 RAID 0/1/4/5/6，softraid(4) 手册未列 RAID 4/6，以现行 bioctl(8) 为准 | softraid 加密 | 完全开源 |
| DragonFly | dsched（磁盘调度器） | HAMMER/HAMMER2（CoW，独立于 ZFS） | HAMMER CoW+ 校验 | HAMMER2 集群镜像 | HAMMER2 加密 | 完全开源 |

**史料**：各系统存储架构文档（2010-2020）［B］

**史观**：总纲第 22 条——知识注定过时：UFS 的 soft updates 是对 FFS 元数据一致性债务的技术清偿，与 GEOM 的模块化共同构成 FreeBSD 非 ZFS 存储的稳健底座。

**辨析**：不应将 “非 ZFS” 视为 FreeBSD 存储的弱点——GEOM+UFS 在简洁性、可审计性与嵌入式场景仍有价值；ZFS 与 GEOM 在 FreeBSD 中互补共存。

**文献**：McKusick M K, Neville-Neil G. The Design and Implementation of the FreeBSD Operating System [M]. 2nd ed. Addison-Wesley, 2015. ［B］
