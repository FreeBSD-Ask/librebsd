# 123.8 资源限制与追踪——RACCT/RCTL、DTrace 与 HAST

## 123.8.1 RACCT/RCTL 资源审计与限制

**要点**：9.0-RELEASE 新增 RACCT（资源审计）和 RCTL（资源限制）框架，提供比传统 **login.conf(5)** 更细粒度的资源限制能力；RACCT 可按进程、jail、login class 跟踪资源使用，RCTL 允许配置规则在资源使用超过阈值时采取动作（如 SIGXRES 信号发送或进程终止）；**rctl(8)** 是用户态管理工具；RACCT/RCTL 在 9.0 中未默认编译入 GENERIC，需添加内核选项 RACCT/RCTL 并重建世界；核心 commit 为 r220137（RACCT）、r220163（RCTL）

**史料**：svn r220137、r220163 commit、FreeBSD 9.0 Release Notes、**rctl(8)** man page、Edward Napierała（trasz@，主要实现者）邮件列表设计讨论 ［A］

**史观**：总纲第 17 条——软件工程：RACCT/RCTL 填补了 FreeBSD 资源管理的空白——FreeBSD 先前仅有 login.conf 的粗粒度 limits，缺乏 Solaris zones/resource controls 式的细粒度限制；这一框架为 jail 虚拟化（资源隔离）和多用户系统公平性提供了基础设施

**辨析**：RACCT/RCTL 默认不编译的设计反映了 FreeBSD “默认内核最小化” 原则——所有非必需功能都以选项形式提供，由管理员按需定制；到 10.x 时期 RCTL 逐步进入 GENERIC 默认配置

**文献**：FreeBSD 9.0-RELEASE Release Notes（Kernel 章节）；**rctl(8)** man page；Edward Napierała 在 EuroBSDCon 2011 关于 RCTL 的演讲 ［B］

## 123.8.2 DTrace 演进与 9.2 钩子默认启用

**要点**：DTrace 在 FreeBSD 中的移植始于 7.x 时期（Sun 发布 CDDL 许可的 DTrace 源码后），8.x 已有完整 DTrace 支持但需手动加载模块；9.0 新增 User-level DTrace（用户态静态追踪）；9.2-RELEASE 中 DTrace 钩子（hooks）在 GENERIC 内核中默认启用，无需自定义内核即可使用 DTrace；DTrace 版本在 9.2 更新至 1.9.0

**史料**：FreeBSD 9.0/9.2 Release Notes、**dtrace(1)** man page、John Birrell（DTrace 移植先驱）纪念文集 ［B］

**史观**：总纲第 24 条——许可证：DTrace 的 CDDL 许可证与 BSD 许可证的兼容性问题经过法律审查后确认可以共存（CDDL 是文件级 copyleft，不传染 BSD 代码），为 DTrace 在 FreeBSD 基础系统中的集成铺平了道路；DTrace 的引入深刻改变了 FreeBSD 系统可观测性文化

**辨析**：原文件错误称 “DTrace 在 10.0 基础系统默认可用”——实际 8.x 已有 DTrace，9.0 已有 user-land DTrace，9.2 DTrace hooks 默认入 GENERIC；10.0 是持续改进而非首次引入；DTrace 工具（**dtrace(1)**、**dtruss(1)** 等）始终在 base 系统中

**文献**：FreeBSD 9.0/9.2-RELEASE Release Notes；**dtrace(1)** man page；Cantrill B, Shapiro M, Leventhal A. Dynamic Instrumentation of Production Systems [C]//USENIX 2004 ATC

## 123.8.3 HAST 高可用存储框架

**要点**：HAST（Highly Available Storage）框架在 9.0-RELEASE 中提供，允许通过网络同步两台 FreeBSD 机器上的块设备，实现存储级高可用（类似 DRBD）；HAST 由 Pawel Dawidek（pjd@）开发，结合 **hastd(8)** 守护进程、**hastctl(8)** 控制工具和 GEOM gate 类实现；9.3 中 **hastctl(8)** 新增输出当前队列大小的功能

**史料**：FreeBSD 9.0/9.3 Release Notes、**hastd(8)**、**hastctl(8)** man page、Pawel Dawidek HAST 设计文档 ［B］

**史观**：总纲第 24 条——许可证：HAST 作为 FreeBSD 原生高可用存储方案，与 Linux DRBD 功能对等但采用 BSD 许可证；它的存在使 FreeBSD 在存储双活/主备场景中具有竞争力，尤其在 TrueNAS（原 FreeNAS）等商业产品中获得应用

**辨析**：HAST 在 9.x 时期作为 “框架提供” 状态，生产部署需仔细配置和测试；与心跳/故障转移工具（如 ucarp、heartbeat）配合使用才能构成完整高可用方案

**文献**：FreeBSD 9.0-RELEASE Release Notes（Storage 章节）；**hastd(8)**、**hastctl(8)**、**ggate(4)** man pages；Pawel Dawidek HAST 设计文档（FreeBSD Subversion 仓库） ［B］
