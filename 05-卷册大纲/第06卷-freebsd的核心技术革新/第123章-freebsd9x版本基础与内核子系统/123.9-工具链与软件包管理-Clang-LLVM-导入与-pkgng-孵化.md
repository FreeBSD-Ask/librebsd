# 123.9 工具链与软件包管理——Clang/LLVM 导入与 pkgng 孵化

## 123.9.1 Clang/LLVM 导入与 GCC 4.2.1 作为默认

**要点**：9.0-RELEASE 中 LLVM 编译器基础设施与 Clang 已导入 base 系统（**clang(1)**、**llc(1)** 等工具可用），但 GCC 4.2.1 仍是默认 C/C++ 编译器；GCC 4.2.1 是 GPLv2 许可的最后一个 GCC 版本，FreeBSD 项目因 GPLv3 许可证条款不可接受而无法升级至 GCC 4.3+；9.0 中 Clang 已可编译内核与 world，但作为可选项而非默认；9.1 新增可选 C++11 栈（LLVM libc++ 与 libcxxrt）；**10.0-RELEASE（2014.1.20）才是 Clang 成为默认编译器、GCC 不再默认安装的版本**——9.x 全程 GCC 为默认

**史料**：FreeBSD 9.0/9.1/10.0 Release Notes、FreeBSD Quarterly Status Report 2012 Q1（Clang 默认计划）、David Chisnall（戴维·奇斯纳尔） AsiaBSDCon 2014 论文 “LLVM in the FreeBSD Toolchain” ［B］

**史观**：总纲第 24 条——许可证：Clang/LLVM 替代 GCC 是 FreeBSD 许可证纯洁化工程中规模最大、影响最深远的项目；9.x 两年过渡期为 ports 与第三方软件提供了修复 Clang 兼容性问题的时间窗口；BSD 许可的工具链使 FreeBSD base 系统摆脱了 GPL 许可证代码依赖

**辨析**：原文件和早期一些中文技术文章误称 “9.0 将采用 Clang 取代 GCC”——实际 9.0 Clang 仅作为可选编译器导入，10.0 才默认切换；这一事实混淆源于 2012 年状态报告中 “Clang 将成为 10.0 默认” 的规划被提前误传为 9.0 实现；GCC 4.2.1 是 GPLv2 版本的最后一个 GCC，这是许可证纯洁化的关键事实基础

**文献**：FreeBSD 9.0 Release Notes（Compiler 章节）；FreeBSD 10.0-RELEASE Announcement（明确说明 "GCC is no longer installed by default on architectures where clang is the default compiler"）；Chisnall D. LLVM in the FreeBSD Toolchain [C]//AsiaBSDCon 2014. Tokyo, 2014

## 123.9.2 pkgng（pkg）在 ports 中的孵化

**要点**：pkgng（下一代软件包管理，后称 **pkg(8)**）在 9.x 时期以 ports-mgmt/pkg port 形式存在于 ports 树中，Baptiste Daroussin（巴蒂斯特·达鲁桑）（bapt@）主导开发；9.x 全程 base 系统默认软件包管理仍是 pkg_install 工具集（**pkg_add(1)**、**pkg_delete(1)**、**pkg_info(1)** 等）；pkg 1.0 正式版于 2012 年 8 月发布；**10.0-RELEASE 才将** pkg(7)**作为默认软件包管理工具，pkg_add/pkg_delete 等被移除**；2012 年入侵事件后软件包构建基础设施重构加速了 pkgng 与签名软件包的部署

**史料**：pkgng 官方文档、Baptiste Daroussin pkgng 邮件列表公告、FreeBSD 10.0 Release Notes（明确 "**pkg(7)** is now the default package management utility. **pkg_add(1)**, **pkg_delete(1)**, and related tools have been removed."）、ports-mgmt/pkg port Makefile 历史 ［A］

**史观**：总纲第 17 条——软件工程：pkgng 是 FreeBSD 软件包管理从 “shell 脚本 + tarball”（pkg_install）向 “现代二进制软件包管理器”（pkg）的重构；它借鉴了 apt/yum 等 Linux 软件包管理器的特性（依赖解析、仓库签名、增量更新）但保持 BSD 实现；入侵事件中旧软件包基础设施暴露的安全缺陷直接加速了 pkgng 签名软件包功能的设计

**辨析**：pkgng 在 9.x ports 中可用但非默认——用户需通过 ports 安装 pkg 并使用 `pkg2ng` 转换旧数据库；9.x 时期不建议新手使用 pkgng，官方文档仍指导使用 pkg_add；原文件若将 pkg 描述为 9.x 默认则为错误

**文献**：FreeBSD 10.0-RELEASE Announcement [Z]. 2014-01-20；**pkg(7)**、**pkg-add(8)** man pages；pkgng GitHub 仓库历史提交 ［B］

## 123.9.3 bhyve（BHyVe）在 9-CURRENT 的早期开发

**要点**：bhyve（早期称 BHyVe，BSD Hypervisor）由 Peter Grehan（彼得·格雷汉）（grehan@）和 NetApp 赞助开发，在 9-CURRENT 分支中进行早期开发，但 **未包含在任何 9.x RELEASE 版本中**；bhyve 的核心组件（vmm.ko 内核模块、**bhyve(8)** 用户态工具）在 10.0-RELEASE（2014.1.20）正式发布并提供支持；9.x 时期 bhyve 仅在 -CURRENT 分支供开发者测试，不适合生产使用；10.0 同时引入 **virtio(4)** 半虚拟化驱动和 Hyper-V 原生 guest 支持

**史料**：FreeBSD 10.0-RELEASE Announcement（明确列出 "the addition of **bhyve(8)**, **virtio(4)**, and native paravirtualized drivers providing support for FreeBSD as a guest operating system on Microsoft Hyper-V"）、Peter Grehan bhyve 邮件列表讨论、svn commit log（vmm 模块导入时间） ［A］

**史观**：总纲第 6 条——技术路线分化：bhyve 使 FreeBSD 成为第一个内置原生 Type-2 hypervisor 的主流 BSD 系统，与 Linux KVM 形成技术路线平行发展；NetApp 对 bhyve 开发的赞助体现了存储公司对 FreeBSD 虚拟化能力的商业需求

**辨析**：**重要事实纠正——bhyve 不在 9.x RELEASE 中**：原文件或某些材料可能因 bhyve 在 9-CURRENT 时期即开始开发而误将其归入 9.x 特性，但官方 release notes 和 announcement 明确 bhyve 是 10.0 引入的核心新特性；9.0-9.3 RELEASE 公告和 release notes 均未提及 bhyve；用户需注意区分-CURRENT 分支开发与-RELEASE 正式发布的区别

**文献**：FreeBSD 10.0-RELEASE Announcement [Z]. 2014-01-20；**bhyve(8)**、**vmm(4)** man pages；Grehan P. BHyVe: A BSD Hypervisor [C]//BSDCan 2011. Ottawa, 2011
