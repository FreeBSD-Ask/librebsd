# 123.2 bsdinstall——Nathan Whitehorn 主导的新一代安装器，取代 sysinstall

## 123.2.1 bsdinstall 架构设计与实现语境

**要点**：**bsdinstall(8)** 由 Nathan Whitehorn（nwhitehorn@）主导开发，在 9.0-RELEASE 中正式取代使用了近 20 年的 **sysinstall(8)**；bsdinstall 采用 shell 脚本与分布式模块化设计，而非 sysinstall 的单体 C 程序架构；核心设计目标是可扩展性——sysinstall 因硬编码逻辑难以支持新特性（如 ZFS、GPT、UEFI），bsdinstall 通过脚本化架构解决此问题；9.0-RELEASE 的 ISO 镜像默认使用 bsdinstall，但 sysinstall 仍存在于系统中以兼容旧脚本

**史料**：Nathan Whitehorn 在 freebsd-current 邮件列表的 bsdinstall 提案与设计讨论、svn commit log（bsdinstall 导入历史）、FreeBSD 9.0 Release Notes、FreeBSD Handbook 安装章节更新历史 ［A］

**史观**：总纲第 17 条——软件工程：sysinstall 到 bsdinstall 的更替体现了 “单体 → 模块化”、“C 硬编码 → 脚本化组合” 的工程范式迁移；sysinstall 是 1990 年代 BSD 安装器的典型（类 sysconfig 界面、静态菜单），bsdinstall 则面向 ZFS、虚拟化、云部署等 2010 年代新需求设计

**辨析**：bsdinstall 的 “shell 脚本驱动” 常被误解为 “用 Lua 驱动”——bsdinstall 实际主要使用 POSIX shell 脚本配合 **dialog(1)** 提供文本界面，Lua 是在更晚版本（10.x 之后）才逐步引入部分组件；9.0 的 bsdinstall 尚不支持 ZFS root 自动安装（需手动配置），ZFS 引导的官方安装支持在 10.x 才完善

**文献**：FreeBSD 9.0-RELEASE Release Notes [Z]. docs.freebsd.org；Whitehorn N. bsdinstall: A New Installation System for FreeBSD [C]//BSDCan 2011. Ottawa, 2011；**bsdinstall(8)** man page

## 123.2.2 从 sysinstall 到 bsdinstall 的过渡与向后兼容

**要点**：9.0-RELEASE 安装介质默认启动 bsdinstall，但 **sysinstall(8)** 仍保留在 base 系统中供高级用户和脚本使用；sysinstall 的包安装功能在 9.x 时期逐步被废弃，因为 pkg_add 等旧软件包管理工具本身也在被 pkgng 取代；bsdinstall 支持 UFS（默认启用 SUJ）和 ZFS（需手动配置分区）两种根文件系统选项；9.0 安装器自动为新创建的 UFS 文件系统启用 softupdates journaling（SUJ），这是 bsdinstall 默认行为的重要变化

**史料**：FreeBSD 9.0 Installation Guide、**sysinstall(8)** 与 **bsdinstall(8)** man pages、freebsd-current 与 freebsd-stable 邮件列表中用户反馈讨论 ［A］

**史观**：总纲第 22 条——开源运动：“新旧并行” 是 FreeBSD 重大基础设施更替的一贯策略——bsdinstall 引入但 sysinstall 保留，Clang 导入但 GCC 保留，pkgng 在 ports 中可用但 pkg_install 仍为默认；这种保守的渐进式更替降低了用户升级风险，但也延长了过渡期

**辨析**：部分用户批评 bsdinstall 9.0 版本 “功能倒退”——相比成熟的 sysinstall，bsdinstall 在分区灵活性、包选择界面等方面初期确实存在不足；这是重写软件的典型代价，多数批评点在 9.1/9.2 中逐步改进

**文献**：FreeBSD 9.0-RELEASE Installation Instructions [Z]. <www.freebsd.org/releases/9.0R/installation.html；Lucas> M W. Absolute FreeBSD [M]. 3rd ed. San Francisco: No Starch Press, 2018（bsdinstall 使用章节）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**要点**：

- Devin Teske 在 FreeBSD 9.2 中引入约 3.3 万行 shell 的 BSD config，将原 sysinstall 的安装后配置能力脚本化，并为每项功能提供可调用的 API。（BSD Now EP4，[427.81-492.46]，L1）
- sysinstall 已停用，Devin Teske 自述为最后维护者之一，并将其缺失的安装后配置功能以 shell 重写，纳入 bsdinstall 与 BSD config。（BSD Now EP4，[486.58-544.30]，L1）
- sysrc 提供对 rc.conf、rc.conf.d 与 loader.conf 等键值文件的命令行编辑，默认输出键值对、可镜像 sysctl 的输出形式，便于 Puppet 等自动化工具调用。（BSD Now EP4，[650.26-737.72]，L1）
- FDPV 以流式进度条与 Grand Central Dispatch 式并发思想支持并行安装与内联校验，设想与 pkg 结合实现非互依赖包的并发安装。（BSD Now EP4，[898.32-1022.46]，L1）
- iXsystems 开发者 John Hixson 自述其工作路径：从 Kris Moore 为 PC-BSD 编写的 pc-sysinstall 后端出发，先加入 FTP 安装与 FTP 取包支持并使其更贴合 FreeBSD 习惯，继而将同一后端改造为 FreeNAS 的安装器，同时深度参与 ncurses 文本前端开发，使一套安装后端同时服务 PC-BSD、FreeBSD 与 FreeNAS 三个发行版。（BSDTalk EP199，[91.64-167.48]，L1）
- pc-sysinstall 采用前后端分离架构：图形或文本前端只负责生成配置文件，后端读取配置并执行实际安装动作，因此任何语言、任何平台都能编写前端；Hixson 指出传统 sysinstall 在结构上同样如此，只是多数用户未曾察觉。（BSDTalk EP199，[175.08-231.36]，L1）
- 对 sysinstall 的批评集中于两点：其一，代码老化——Jordan Hubbard 早在 1995 年的源码注释里就写明应予重写，此后十六年基本未动；其二，能力落后——不支持 GPT、ZFS root、镜像与 swap 加密等 FreeBSD 多年积累的新特性，配置流程对新用户也不友好。相比之下 pc-sysinstall 默认支持上述现代特性，且完全以 shell 写就，无需 C 语言技能即可阅读与维护。（BSDTalk EP199，[283.26-708.60]，L1）
- 工程现状与路线：pc-sysinstall 已进入 FreeBSD HEAD，Hixson 提交补丁由 Warner Losh 代为 commit；脚本化安装（对标 Solaris Jumpstart、Red Hat Kickstart 与微软应答文件）、修改已安装系统、网络启动等功能均在计划中，但暂无时间表，因为团队当前优先 FreeNAS；最终目标是让社区接纳该工具并逐步淘汰 sysinstall。（BSDTalk EP199，[349.94-815.84]，L1）

**史料**：

- 当事人 Devin Teske 自述 1990 年代起编程，2005 年入职 VyCore（后为 FIS Global），长期维护 FreeBSD bootloader 与 sysinstall。（BSD Now EP4，[114.54-181.50]，L1）
- 当事人自述其通过 TI-89 计算器类比理解 Forth 的逆波兰式，并在此后写出约 1.5 万行 Forth 代码，称其小巧且稳定。（BSD Now EP4，[1297.62-1405.66]，L1）
- 当事人自述 Druid BSD 为基于 sysinstall 与 libdialog 的定制安装与救援系统，混合 ISO 可在 CD、DVD、USB、HDD 与 PXE 上以同一镜像启动。（BSD Now EP4，[1681.68-1849.66]，L1）
- 一手史料包括 Hixson 对 pc-sysinstall 渊源的口述（Kris Moore 初版、FTP 支持、FreeNAS 定制）、对文本安装前端由 Rui 起草的提及、代码进入 FreeBSD HEAD 且由 Warner Losh 代为提交的陈述，以及 BSDCan 期间发布的测试 ISO 之说明；开场栏目由主持人转述 talk 命令最早见于 4.2BSD。（BSDTalk EP199，[34.12-167.48]，L1）

**史观**：

- 总纲4 分离聚合是永恒规律：BSD config 将 sysinstall 的单块式安装功能拆分为各自独立的模块沙箱与 API，以模块化重组替代单一整体。（BSD Now EP4，[358.34-386.42]，L1）
- 总纲10 动手者创造历史：引导加载器与安装器的长期演进由 Devin Teske 等具体动手者以个人方式推进，访谈记录的是具体维护者的工程选择。（BSD Now EP4，[1297.62-1405.66]，L1）
- 总纲4 分离聚合是永恒规律：Hixson 的工作轨迹显示 PC-BSD 衍生项目孕育的安装器技术经改造后回流 FreeBSD 主线并输出至 FreeNAS，呈现 BSD 衍生系统与主线之间技术的分离与再聚合。（BSDTalk EP199，[91.64-167.48]，L1）
- 总纲22 知识注定过时：sysinstall 作为 1995 年即被其作者自注应予重写的组件维持服役十余年，最终仍难逃被新一代安装器更替，印证系统组件的知识形态必然随环境变迁而过时。（BSDTalk EP199，[637.10-708.60]，L1）

**辨析**：

- ZFS on root 与全盘加密的纳入时间在访谈中仅为估计（预计 2014 年一季度开始测试、10.1 首次纳入），其最终落地版本未定。　[存疑脚注] ZFS on root 与全盘加密纳入版本为当事人当时估计，须以正式发布记录为准。（BSD Now EP4，[235.62-358.34]，L4）
- Hixson 称 sysinstall 自 1995 年 Jordan Hubbard 写下应重写注释后基本无人改动，此为当事人概括性论断，其间偶有例外修改，具体改动史须以 FreeBSD CVS/SVN 提交记录交叉验证；转写另存在人名与工具名音误（如将 Kris Moore 记作 Chris Moore、sysinstall 转作 system stall），引用时须回查原音频。　[存疑脚注] 当事人单方论断且转写存在音误，采信前须以版本库历史与原音频复核（BSDTalk EP199，[637.10-652.22]，L4）
