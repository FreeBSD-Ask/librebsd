# 123.7 Capsicum 能力模式——罗伯特·N. M. 沃森（Robert Watson）与 Jonathan Anderson 的沙箱框架

## 123.7.1 Capsicum 能力模型与 9.0 内核支持

**要点**：Capsicum Capability Mode 在 9.0-RELEASE 中首次进入 GENERIC 内核（CAPABILITIES 与 CAPABILITY_MODE 选项），由 罗伯特·N. M. 沃森（rwatson@）、Jonathan Anderson 等在剑桥大学计算机实验室开发，源自 DARPA 资助的安全研究项目；Capsicum 引入 “能力文件描述符”（capability file descriptor）模型，进程在 capability mode 下只能访问显式授予能力的文件描述符，无法访问全局命名空间，是一种细粒度的沙箱机制；9.0 中 Capsicum 标记为实验性（experimental set of features for sandboxing support），核心实现 commit 为 r219129

**史料**：Capsicum 项目官方网站（www.cl.cam.ac.uk/research/security/capsicum/）、svn r219129 commit、FreeBSD 9.0 Release Notes、Watson R N M 等关于 Capsicum 的论文（USENIX Security 2010）；**freebsd.duckdb** `commits` 表与 `commit_files` 表 `freebsd-src` 仓库数据库验证——Capsicum 首次合入 commit 为 `72c35fc69c9f...` "Reserve system call numbers for Capsicum security framework capabilities, capability mode, and process descriptors: cap_getrights(2), cap_enter(2), pdfork(2), pdgetpid(2), pdkill(2), pdwait4(2)"，author = 罗伯特·N. M. 沃森，author_date = 2009-09-30，先于 FreeBSD 9.0 开发周期启动约 1 年；Capsicum Capability Mode 主体实现 commit 为 `96fcc75fdf74...` "Add initial support for Capsicum's Capability Mode to the FreeBSD kernel, compiled conditionally on options CAPABILITY_MODE"，author = 罗伯特·N. M. 沃森，author_date = 2011-03-01，与 FreeBSD 9.0 开发周期（2010 年中至 2012.1）吻合；后续 3 月内 Watson 与 Pawel Jakub Dawidek、Jonathan Anderson 持续添加 commit，包括 `08e6d9fad843`、`fc94e4476b63`、`74b5505e5d95`（均为 2011-03-01）；`a9d2f8d84f69` "Second-to-last commit implementing Capsicum capabilities in the FreeBSD kernel for FreeBSD 9.0“，author = 罗伯特·N. M. 沃森，author_date = 2011-08-11，明确标注为 ”for FreeBSD 9.0"；`历史代码复核/freebsd-目录结构验证.md` 验证显示 `sys/kern/capability.c` 与 `sys/modules/capsicum/` 路径在 release/9.0 至 release/14.3 全部版本中均检测为 “✗ 不存在”，反映 Capsicum 内核实现实际位于 `sys/kern/capability.c` 之外的路径（如 `sys/kern/subr_capability.c` 或 `sys/security/capability/` 等历史路径），目录结构验证脚本对 Capsicum 路径的检测存在覆盖盲区，须以 commit_files 表查询结果为准 ［A］

**史观**：总纲第 22 条——开源运动：Capsicum 是学术研究向开源产品转化的典范——剑桥大学安全研究团队直接将 Capsicum 提交到 FreeBSD 主线，罗伯特·N. M. 沃森 作为 FreeBSD 核心开发者与 committer 同时在剑桥大学从事研究，实现了学术研究与工程实践的无缝衔接；Capsicum 影响了后续 CloudABI、WebAssembly System Interface（WASI）等能力系统的设计

**辨析**：原文件错误称 “Capsicum 在 10.0 作为可选特性首次引入”——实际 9.0 已进入 GENERIC 内核，但作为实验性功能；10.0 是用户态工具和更多沙箱服务的完善；Capsicum 与 Linux capabilities（POSIX capabilities）是不同设计——Capsicum 是纯文件描述符能力模型，不使用 POSIX capabilities 的位掩码权限集；**数据库验证结论**：Capsicum 系统调用号最早于 2009-09-30 由 Watson 提交 commit `72c35fc69c9f` 预留，主体 Capability Mode 实现于 2011 年 3 月密集提交（多个 commit 同日），完成时间标注为 "Second-to-last commit implementing Capsicum capabilities in the FreeBSD kernel for FreeBSD 9.0"（2011-08-11），全部 Capsicum 主体 commit 均在 FreeBSD 9.0 开发周期（2010 年中至 2012.1）内完成，验证 “Capsicum 在 9.0-RELEASE 中首次进入 GENERIC 内核” 的声明；0 信任原则提示：Capsicum 源文件路径在 release tag 中检测为 “不存在” 可能因目录结构验证脚本的路径模式覆盖不全，须以 commit_files 表的 file_path 字段为权威

## 123.7.2 Capsicum 的实际应用与后续演进

**要点**：9.x 时期 Capsicum 主要用于沙箱化基础系统工具（如 casperd 服务守护进程），大型应用程序（如浏览器 Chromium）在 9.x 之后才逐步使用 Capsicum；Capsicum 安全模型的设计对后续 FreeBSD 安全加固和云原生安全有深远影响

**史料**：FreeBSD Quarterly Status Reports 2012-2014 Capsicum 章节、**casper(8)** 相关文档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：总纲第 25 条——终结与延续：Capsicum 是 FreeBSD 安全架构从 “传统 UNIX 权限模型” 向 “细粒度能力沙箱” 演进的关键节点，其思想延续到了现代沙箱与 WebAssembly 能力系统中

**辨析**：9.0 中 Capsicum 的 “experimental” 标签不意味着不可用——核心内核机制已稳定，但 API 在后续版本仍有调整；casper 守护进程用于提供受限系统服务代理

**文献**：**capsicum(4)** man page；FreeBSD Foundation 2013 Annual Report（Capsicum 应用进展章节） ［B］
