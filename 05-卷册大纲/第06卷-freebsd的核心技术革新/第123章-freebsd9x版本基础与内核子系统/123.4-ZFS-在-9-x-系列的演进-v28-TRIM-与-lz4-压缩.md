# 123.4 ZFS 在 9.x 系列的演进——v28、TRIM 与 lz4 压缩

## 122.4.1 ZFS v28 与 dedup、raidz3 支持

**要点**：9.0-RELEASE 将 ZFS 更新至 SPA（Storage Pool Allocator）version 28（zpool version 28），这是 OpenSolaris 时代最后一个开源 ZFS 版本（Oracle 在收购 Sun 后闭源了 ZFS 后续开发）；ZFS v28 新增特性包括：数据重复数据删除（dedup）、三重奇偶校验 RAIDZ（raidz3）、snapshot holds、log device removal、zfs diff、zpool split、zpool import `-F`（强制导入）、只读 zpool import 等；ZFS boot（从 ZFS 根文件系统引导）在 9.0 中技术上可行但需手动配置，bsdinstall 尚未提供自动 ZFS root 安装选项

**史料**：svn r219089（ZFS v28 导入）、FreeBSD 9.0 Release Notes、OpenSolaris ZFS v28 文档、FreeBSD ZFS 邮件列表讨论 ［A］

**史观**：总纲第 24 条——许可证：ZFS v28 成为 FreeBSD（以及后来整个开源社区）ZFS 演进的基础版本具有历史决定性——Oracle 闭源后，illumos 成为 ZFS 开源开发的主力，FreeBSD 从 illumos 持续移植改进；v28 作为 CDDL 许可的最后共同祖先版本，奠定了 BSD/Linux/macOS ZFS 生态的技术基础

**辨析**：ZFS v28 在 FreeBSD 9.0 中状态为 “Production 但非默认根文件系统”——作为数据存储卷使用已相当稳定，但作为 root 文件系统仍需大量手动调整，不适合普通用户；10.0 时期 bsdinstall 才逐步加入自动 ZFS root 配置

**文献**：svn commit r219089；FreeBSD 9.0-RELEASE Release Notes（ZFS 章节）；Lucas M W. FreeBSD Mastery: ZFS [M]. Tilton: Tilted Windmill Press, 2015 ［A］

## 122.4.2 9.2 中 ZFS TRIM 与 lz4 压缩

**要点**：9.2-RELEASE 官方公告明确列出两项 ZFS 新特性："The ZFS filesystem now supports TRIM when used on solid state drives" 和 "The ZFS filesystem now supports lz4 compression"——即 ZFS 正式支持 SSD TRIM 与 lz4 压缩算法；lz4 由 Pawel Dawidek（pjd@）等从 illumos 移植，相比 gzip 提供更高的压缩/解压吞吐量和合理的压缩比，成为 ZFS 推荐的实时压缩算法；10.0-RELEASE 公告也将 TRIM 和 lz4 列为新特性，这是面向从 8.x/9.0-9.1 升级用户的强调而非重复添加

**史料**：FreeBSD 9.2-RELEASE Announcement（官方明确列出 TRIM 与 lz4）、FreeBSD 10.0-RELEASE Announcement、Pawel Dawidek 关于 ZFS lz4 的 commit log 与邮件列表公告 ［A］

**史观**：总纲第 17 条——软件工程：lz4 的引入反映了 ZFS 压缩算法从 “高压缩比优先”（gzip）向 “性能优先透明压缩”（lz4）的范式转变；lz4 成为 FreeBSD ZFS 默认推荐压缩算法，与 Linux btrfs/zfs 同期采纳 lz4 一致

**辨析**：9.2 与 10.0 公告均提及 ZFS TRIM/lz4，原因是 10.0 是新的大版本分支（stable/10），其公告面向所有用户（包括从 8.x 升级或新安装 10.0 的用户）汇总新特性；9.2 的 TRIM/lz4 是 9-STABLE 分支中的引入，10.0 则是将这些特性带入 10-STABLE 分支；TRIM 在 9.2 中的具体支持范围（手动 `zpool trim` vs 自动 TRIM）需对照 release notes 进一步核实

**文献**：FreeBSD 9.2-RELEASE Announcement [Z]. 2013-09-30（明确列出 TRIM 与 lz4）；FreeBSD 10.0-RELEASE Announcement [Z]. 2014-01-20；svn ZFS commit log ［A］

## 122.4.3 9.3 中 ZFS bookmarks 与持续改进

**要点**：9.3-RELEASE 中 ZFS 新增 bookmarks 特性，允许创建不占用空间的快照引用标记，用于 zfs send/recv 增量复制；9.3 作为 9.x 终章汇集了大量 ZFS 稳定性修复与 illumos 反向移植，是生产环境 ZFS 部署的成熟基础。9.x 系列 ZFS 演进关键节点汇总见下表。

| 版本 | ZFS 特性 | 引入方式 | 说明 |
| --- | --- | --- | --- |
| 9.0 | ZFS v28（SPA version 28） | svn r219089 | dedup、raidz3、snapshot holds、log device removal、zfs diff、zpool split、**zpool(8)** import `-F` |
| 9.0 | ZFS boot（手动配置） | —— | 技术上可行，**bsdinstall(8)** 尚未提供自动 ZFS root 安装（10.x 才完善） |
| 9.2 | ZFS TRIM | 9.2-RELEASE 公告 | SSD TRIM 支持（晚于 UFS TRIM 两年） |
| 9.2 | ZFS lz4 压缩 | Pawel Dawidek 从 illumos 移植 | 取代 gzip 成为推荐实时压缩算法，性能/压缩比均衡 |
| 9.3 | ZFS bookmarks | 9.3-RELEASE 公告 | 不占用空间的快照引用标记，用于 **zfs(8)** send/recv 增量复制 |

**史料**：FreeBSD 9.3-RELEASE Announcement、**zfs(8)** man page bookmarks 章节 ［B］

**史观**：总纲第 25 条——终结与延续：9.3 ZFS 是 “v28 + illumos 精选回移” 模式的终态——它既保持了 v28 的稳定性，又回移了关键功能（bookmarks 等）；这种 “稳定主干 + 选择性移植” 的模式是 FreeBSD 维护者在开源 ZFS 生态分裂后探索出的成功路径

**辨析**：ZFS bookmarks 看似小特性，但对自动化 ZFS 复制（zrep、syncoid 等工具）至关重要——它解决了快照命名空间污染问题，使异步增量复制更加健壮

**文献**：FreeBSD 9.3-RELEASE Announcement [Z]. 2014-07-16；**zfs(8)**、**zpool(8)** man pages ［B］
