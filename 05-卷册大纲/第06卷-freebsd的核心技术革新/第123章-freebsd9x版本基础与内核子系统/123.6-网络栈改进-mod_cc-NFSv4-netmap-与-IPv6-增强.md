# 123.6 网络栈改进——mod_cc、NFSv4、netmap 与 IPv6 增强

## 123.6.1 mod_cc 可插拔拥塞控制框架

**要点**：9.0-RELEASE 引入 **mod_cc(9)** 可插拔拥塞控制框架，将 TCP 拥塞控制算法从内核静态编译改为动态可加载内核模块；9.0 默认包含 NewReno、CUBIC、Vegas、H-TCP、HD（Hamilton-Delay）五种算法（官方公告明确列出 “five congestion control algorithm implementations available”），通过 `net.inet.tcp.cc.algorithm` sysctl 设置默认算法，默认仍为 NewReno；**h_ertt(4)** KHELP 模块提供增强 RTT 估计；TCP_CONGESTION 套接字选项允许按连接选择算法

**史料**：svn r216109、r216114、r216115、r218152-218155 系列 commit、FreeBSD 9.0 Release Notes 与官方公告、Lawrence Stewart 关于 mod_cc 的论文与 AsiaBSDCon 演讲 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：mod_cc 将拥塞控制算法从单一内核实现中分离出来、再以可加载模块聚合，使 FreeBSD 成为继 Linux 之后第二个支持可插拔拥塞控制的主流操作系统〔存疑：Windows Vista 2006 年引入 CTCP 算法但无通用可插拔框架，“第二个”以可插拔框架口径为准〕，为后续数据中心拥塞控制（如 DCTCP 等）研究与部署提供了平台基础；框架设计者 Lawrence Stewart 来自澳大利亚 CAIA（Centre for Advanced Internet Architectures），体现了学术研究对 FreeBSD 网络栈的直接贡献

**辨析**：CUBIC 作为 Linux 默认拥塞控制算法虽在 9.0 中提供，但 FreeBSD 到较晚版本才将默认从 NewReno 切换；保守的默认策略与 FreeBSD 一贯的稳定优先原则一致；CHD（CAIA-Hamilton-Delay）算法在 9.0 中是否完整包含需对照 release notes 精确核实，官方公告仅笼统称 “five”

**文献**：FreeBSD 9.0-RELEASE Announcement [Z]. 2012-01-12；Stewart L, et al. A Pluggable Congestion Control Framework for FreeBSD [C]//AsiaBSDCon 2010. Tokyo, 2010；**mod_cc(4)**、**mod_cc(9)**、**cc_cubic(4)**、**cc_vegas(4)** man pages；FreeBSD 9.0-RELEASE Release Notes（Networking 章节）

## 123.6.2 NFSv4 新实现

**要点**：9.0-RELEASE 引入全新 NFS 实现，支持 NFSv4 协议（同时保持 NFSv2/v3 支持）；内核选项从旧的 NFSSERVER/NFSCLIENT 改为 NFSD/NFSCL；NFS 服务器支持 `vfs.nfsd.server_max_nfsvers` 和 `vfs.nfsd.server_min_nfsvers` sysctl 控制协议版本，默认最大版本仍为 3，需显式配置启用 NFSv4；新实现修复了旧 NFS 栈的大量并发问题与性能瓶颈

**史料**：svn r221124 系列 commit、FreeBSD 9.0 Release Notes、Rick Macklem（NFSv4 主要实现者）邮件列表讨论、**nfsv4(4)** man page ［A］

**史观**：总纲第 10 条——动手者创造历史：FreeBSD NFSv4 实现由 Rick Macklem 主要完成，是社区志愿者多年亲手持续工作的结晶；NFSv4 作为 POSIX 标准网络文件系统，其完成使 FreeBSD 在企业存储领域保持竞争力

**辨析**：9.0 NFSv4 服务器默认不启用——需通过 rc.conf 配置明确开启最大版本为 4，默认配置保持 NFSv3 兼容性；这一保守默认策略在用户熟悉新实现并验证稳定性后才逐步调整

**文献**：FreeBSD 9.0-RELEASE Release Notes（NFS 章节）；**nfsd(8)**、**nfsstat(1)**、**nfsv4(4)** man pages；Rick Macklem 在 freebsd-current 的 NFSv4 实施报告 ［A］

## 123.6.3 9.1 **netmap(4)** 高速包 I/O 框架

**要点**：9.1-RELEASE 引入 **netmap(4)** 框架，由 Luigi Rizzo 教授团队开发，提供用户态高性能包 I/O 能力，绕过内核网络栈开销，可实现线速包处理（10Gbps+）；netmap 是 FreeBSD 在软件定义网络（SDN）、网络功能虚拟化（NFV）和高速包处理领域的关键基础设施

**史料**：Luigi Rizzo 关于 netmap 的论文（USENIX ATC 2012）、svn commit log、FreeBSD 9.1 Release Notes、**netmap(4)** man page ［A］

**史观**：总纲第 10 条——动手者创造历史：netmap 源自 Luigi Rizzo 团队的学术研究项目（比萨大学），而非商业公司需求；研究者以亲手实现使成果在 FreeBSD 中落地并持续发展，体现了动手者对开源操作系统的直接塑造，与 Dummynet（Rizzo 早期作品）成为 FreeBSD 网络研究双璧

**辨析**：netmap 在 9.1 中仅支持部分网卡驱动（em/igb/ixgbe 等 Intel 网卡优先支持），覆盖范围在 10.x 及后续版本大幅扩展；9.1 时期 netmap 主要面向研究人员和网络设备开发者，普通用户感知度低

**文献**：Rizzo L. netmap: A Novel Framework for Fast Packet I/O [C]//Proceedings of the 2012 USENIX Annual Technical Conference. Boston, 2012；**netmap(4)** man page；FreeBSD 9.1-RELEASE Release Notes

## 123.6.4 IPv6 增强与 RFC 6106 RDNSS/DNSSL

**要点**：9.0-RELEASE 中 **rtsold(8)**/**rtadvd(8)** 支持 RFC 6106（IPv6 Router Advertisement DNS Configuration）的 RDNSS 和 DNSSL 选项，允许通过路由器公告自动配置 IPv6 DNS 服务器；9.0 新增 **rtadvctl(8)** 控制工具；9.1 大幅改进 IPv6 硬件卸载支持；**ipfw(8)** 在 9.0 中支持 IPv6 fwd 动作和 call/return 动作

**史料**：svn r222732、r224006 等 commit、FreeBSD 9.0/9.1 Release Notes、RFC 6106 ［A］

**史观**：总纲第 22 条——知识注定过时：IPv6 的持续推进与全球 IPv4 地址耗尽（IANA 在 2011.2 分配完最后一批 IPv4 地址）直接相关，以 IPv4 为中心的知识与部署经验注定被 IPv6 迭代取代；FreeBSD 对 IPv6 的重视反映了操作系统必须随网络知识的更新而演进

**辨析**：FreeBSD IPv6 栈自 KAME 项目集成以来一直走在前列，但在 9.x 时期仍有部分工具和守护进程对 IPv6 支持不完整，这种 “内核层支持完整、用户态工具逐步跟进” 的模式持续了多个版本

**文献**：FreeBSD 9.0/9.1-RELEASE Release Notes；**rtsold(8)**、**rtadvd(8)**、**rtadvctl(8)** man pages；RFC 6106: IPv6 Router Advertisement Options for DNS Configuration ［B］

**要点**：

- 《The Design and Implementation of the FreeBSD Operating System》第二版于 2014 年春完稿、同年秋由 Pearson 出版，作者为 Marshall Kirk McKusick、George Neville-Neil 与新加入的 Robert Watson（剑桥大学），三人协作数年；出版须对齐大学秋季学期，纸质书的截止日期远比软件来得硬；新版覆盖 FreeBSD 10 并少量触及 11，而上一版覆盖 5.2；自完稿到面市约六个月内系统本身仍在演变，作者的目标是让书在约十年内保持相关——此系列约十年一版。写作期间 Kirk 明令禁止中途修改代码以迁就书稿，否则书永远写不完。（BSDTalk EP253，[79.96-330.30]，L1）
- 新版的关键主题之一是 FreeBSD 的锁架构与各子系统加锁时的交互，因为锁机制是程序员与系统打交道的最大难点，锁不正确便出严重问题；上一版选 5.2 正为覆盖 SMP 与锁等长期保持相关的主题，事实证明其贯穿了上一版的整个生命周期；从 5 到 10 之间系统已有多队列网络接口与远比 5 时代细粒度的锁；单核时代趋于终结——ARM32 某些板卡（如初代 Raspberry Pi）仍是单核，但最便宜的设备也已是两核四核，仍执着于单处理器的人并不运行 FreeBSD。（BSDTalk EP253，[331.44-445.22]，L1）
- 新版内容版图：Robert Watson 撰写全新的安全章节，Kirk McKusick 撰写全新的 ZFS 章节，George Neville-Neil 大幅增写网络栈（SCTP——非新协议但在特定环境重要且在 FreeBSD 中已重度使用——与模块化拥塞控制）并新增整节 DTrace；他提出著名的论断：DTrace 本质上是操作系统的 rootkit——它在运行中动态替换指令、启用即以 root 权限运行，对常做安全工作的人而言极其有用却也相当可怕；DTrace 内部此前从未有书籍记载，仅见 Sun 开发者写在源码头文件中的注释，Brendan Gregg 的著作只讲使用，故本书是唯一系统记载 DTrace 内部机制的出版物。（BSDTalk EP253，[568.02-727.28]，L1）
- 写作经历带来对 DTrace 的认识论顿悟：他为理解 NFSv4 而以 DTrace 观察其运行，发现这是理解大型运行系统前所未有的工具——传统的 print 调试缓慢、易错且无法随意开关，而 DTrace 进入 Sun 与 FreeBSD 的每个出货内核，现场排障与课堂演示（如 TCP 状态机的建立、运行与关闭，取代 Stevens 之书或 RFC 中的 ASCII 图）皆可实时呈现；由此他与 Robert Watson 开发面向大学生与从业者的 DTrace 课程，George 在 2015 年 3 月的 Asia BSDCon 讲授，Robert 在剑桥讲授硕士版并在 BeagleBone Black 的 ARM 环境教学；Sun 原班设计者是真正聪明、经验丰富的内核工程师并长期打磨此一问题，将其导入 FreeBSD 的 John Birrell 亦须深谙其理；其他操作系统的重新实现属“重写三次才会对”的路径且远不及 FreeBSD 版详尽，而 DTrace 之于整个操作系统的渗透性远超 SCTP、拥塞控制等其他新特性。　[存疑脚注] 转写作 John Burrell，音近；按 FreeBSD DTrace 移植史应作 John Birrell，仍待文字史料核验（BSDTalk EP253，[1088.58-1296.14]，L1）
- 本书读者定位：面向以 C 编程者、系统程序员与以 FreeBSD 构建产品的厂商——Juniper、Isilon、NetApp 之外还有 WhatsApp 等会议常客，产品团队中总需要有人理解系统内部以诊断问题、优化性能；同时面向能编程的系统管理员——当事人感慨系统管理员一词已经退化，如今多数从业者不会编程，而旧模式下能读代码的管理员才是本书读者；操作系统的设计刻意在引擎盖下遮蔽复杂性、呈现简化的世界图景，NFSv4 协议为维持简单的 open、close、read、write 接口而在内部机巧重重即为例证，一旦系统出问题或被推向极限，深层理解便不可或缺；只想架设 ZFS 阵列的读者则应读 FreeBSD Journal 上 Alan Jude 的文章而非本书。（BSDTalk EP253，[758.60-1015.42]，L1）
