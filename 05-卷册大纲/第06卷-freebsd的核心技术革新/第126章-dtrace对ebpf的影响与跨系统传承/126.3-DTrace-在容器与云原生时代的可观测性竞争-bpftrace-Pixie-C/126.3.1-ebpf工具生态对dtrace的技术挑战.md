# 126.3.1 eBPF 工具生态对 DTrace 的技术挑战

**要点**：2014 年 eBPF 进入 Linux 主线后，基于 eBPF 的可观测性工具生态快速发展：(1) bpftrace——Alastair Robertson 创建的高层追踪语言，语法受 D 语言启发，LLVM IR 编译到 eBPF；(2) BCC（BPF Compiler Collection）——Brendan Gregg 和其他开发者创建的工具集，提供 Python/Lua/C++ 前端编写 eBPF 工具；(3) Pixie——Pixie Labs（后来加入 New Relic）开发的 Kubernetes 原生可观测性平台；(4) Cilium Tetragon——Isovalent（Cilium 背后的公司）开发的基于 eBPF 的安全可观测性和运行时执行工具；(5) 大量其他 eBPF 工具覆盖网络可观测性（Hubble）、性能分析（perf、BCC tools）、安全（Falco）等领域；eBPF 生态在容器/Kubernetes 场景中的深度集成是 DTrace 不具备的优势

**史观**：总纲第 6 条——技术路线分化：eBPF 工具生态在 Linux/容器/云原生领域的兴起，代表了可观测性技术的新一轮分化——DTrace 代表的“操作系统内置统一追踪框架”模式在 BSD/Solaris/macOS 上继续存在，而 Linux 生态发展出了基于通用内核虚拟机的 eBPF 模式，两种模式各有优势

**辨析**：说“eBPF 取代了 DTrace”是不准确的——DTrace 在 FreeBSD、macOS、illumos 上仍是核心动态追踪工具，Netflix 等 FreeBSD 重度用户仍在大规模使用 DTrace；eBPF 主要在 Linux 生态中取代了 DTrace 的位置（Linux 从未原生支持 DTrace）；在 Windows 上，Microsoft 于 2019 年 3 月发布了基于 FreeBSD 移植的 DTrace for Windows 10 Insider builds，并在 Windows Server 2025 中将其作为内置工具
