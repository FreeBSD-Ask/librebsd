# 128.9 ARM 平台进展与架构支持变化

## 128.9.1 armv6 成为 Tier 2 架构

**要点**：FreeBSD 10.1-RELEASE（2014.11.14）正式将 armv6 架构加入发布镜像支持列表，成为 Tier 2 支持架构（10.0 仅支持 amd64/i386/ia64/powerpc/powerpc64/sparc64）。armv6 支持包括：Raspberry Pi（Model A/B，ARM1176JZF-S）、BeagleBone（AM335x Cortex-A8）、PandaBoard（OMAP4430/4460 Cortex-A9）、Wandboard（i.MX6 Cortex-A9）、Chromebook（Exynos 5250 Cortex-A15）、Radxa Rock（RK30xx Cortex-A9）、Colibri/Cosmic（Vybrid Cortex-A5）等开发板。10.1 中 ARM 改进包括：硬件浮点（VFP）默认启用；SMP 在多核 ARM 平台默认启用；C++ 异常处理修复；Superpages 支持（10.0 已加入，r254918）；Raspberry Pi I2C 驱动；TI PRUSS/MBOX/SDHCI/PPS/PWM/ADC 驱动；默认 ABI 切换为 ARM EABI（10.0 已完成，r253396）。10.2-10.4 持续改进 ARM 平台设备支持与稳定性。

**史料**：FreeBSD 10.1 Announcement（armv6 added to supported architectures）、10.0/10.1 Release Notes ARM support 章节、FreeBSD/arm 页面（supported platforms）、freebsd-arm 邮件列表 2014 公告。 ［A］

**史观**：总纲第 10 条——动手者创造历史：ARM 架构从 FreeBSD 6/7 时期的 “实验性移植” 到 10.1 正式成为 Tier 2，历时约 8 年。Raspberry Pi（2012 年发布）的流行极大推动了 FreeBSD/arm 开发——廉价 ARM 开发板的普及使普通开发者能接触 ARM 硬件，这是 ARM 支持成熟的硬件基础。

**辨析**：armv6 在 10.x 为 Tier 2 而非 Tier 1——Tier 1 架构（amd64/i386）有 release engineering 正式支持、包更新及时、安全 advisories 覆盖；Tier 2 架构由社区维护，包更新可能滞后；ia64（Itanium）在 10.x 虽仍发布镜像但实际为垂死架构，Intel 已停止 Itanium 硬件生产，最终在 FreeBSD 11/12 时期淘汰。

**文献**：FreeBSD 10.1-RELEASE Announcement [Z]. 2014；FreeBSD Supported Platforms page [Z]. freebsd.org/platforms/.［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 128.9.2 arm64/AArch64 初导入

**要点**：64 位 ARM（AArch64/arm64）支持在 FreeBSD 10.x 后期开始导入 -CURRENT 开发分支，但未进入 stable/10 分支发布。arm64 移植项目由 Andrew Turner（andrew@）、Ian Lepore（ian@）等核心开发者主导，FreeBSD Foundation 赞助了部分开发工作（Foundation 2015-2016 年度报告明确列为赞助项目）。arm64 初始代码在 2015-2016 年间逐步进入 -CURRENT，可启动单用户模式但功能不完备；正式作为发布架构支持是 FreeBSD 11.0（2016.10.10）。10.x 全系列 RELEASE 版本均不包含 arm64 支持——用户需运行 -CURRENT 才能获得 arm64 支持。

**史料**：FreeBSD Quarterly Status Reports 2015-2016 arm64 条目、Andrew Turner freebsd-arm 邮件列表 arm64 状态报告、FreeBSD Foundation 2015-2016 Annual Reports（arm64 sponsorship）、FreeBSD 11.0 Announcement（arm64 正式支持）。 ［A］

**史观**：总纲第 10 条——动手者创造历史：AArch64 是 ARM 面向服务器市场的 64 位架构（ARMv8-A，2011 年发布），FreeBSD 对 arm64 的响应速度（从架构发布到 OS 支持约 4-5 年）相比 ARMv6 时代快很多，这得益于 ARM 发布前与操作系统厂商的协调以及 FreeBSD 开发者群体对 ARM 生态投入的持续提升。

**辨析**：原文件称 “10.2 中 arm64/AArch64 初导入（project 分支）”——时间点大致正确（2015 年），但需明确初导入发生在 -CURRENT（head 分支）而非 stable/10 分支，10.0-10.4 RELEASE 均无 arm64 发布镜像；FreeBSD arm64 移植不使用 Linux 代码而是独立的 BSD 许可实现，这与 Linux 生态的 arm64 支持并行发展。

**文献**：FreeBSD Foundation. Annual Reports 2015-2016 [R].；Turner A. FreeBSD/arm64 Status Updates [EB/OL]. freebsd-arm mailing list, 2015-2016. ［A］

## 128.9.3 GCC 4.2.1 在非 x86 架构的保留

**要点**：FreeBSD 10.x 全系列中 GCC 4.2.1 仍保留在 base 系统源码树中，用于构建 sparc64、powerpc、powerpc64、mips 等尚未完成 Clang 迁移的架构。Clang/LLVM 在 10.x 时期对这些架构的支持尚不完善：sparc64 Clang 支持存在代码生成 bug 且缺乏持续维护；powerpc/powerpc64 Clang 支持在 10.x 仍为实验性；mips Clang 支持更不成熟。x86（i386/amd64）与 armv6 在 10.0 已默认使用 Clang 构建且不默认安装 GCC，但用户仍可通过 WITHOUT_CLANG_WITH_GCC src.conf 选项启用 GCC 构建（用于 ports 中需要 GCC 的软件也可通过 ports/devel/gcc 安装现代 GCC 版本）。GCC 4.2.1 在 base 中继续存在约 6 年（2014-2020），最终在 FreeBSD 13.0 前后被 Warner Losh（沃纳·洛什）（imp@）等人逐步移除。

**史料**：FreeBSD 10.0 Release Notes Userland Changes（"GCC 4.2.1 and libstdc++ are still built and used by default on... all other platforms where clang is not the default"）、src.conf(5) WITH_GCC/WITHOUT_CLANG 选项文档、Warner Losh freebsd-arch 邮件列表 GCC 退休公告。 ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界：编译器迁移不能 “一刀切”——非 x86 架构的 Clang 支持成熟度不足时继续保留 GCC 是务实工程决策，这也是为什么 GCC 4.2.1 从 “默认” 到 “可选” 到 “完全移除” 历时约 6 年（2014-2020，以 10.0 将 GCC 在 x86 上转为非默认起算）。sparc64 等架构最终因硬件市场萎缩（Oracle 停止 SPARC 服务器开发）与 Clang 支持不足而降级为 Tier 3 或淘汰，GCC 移除加速了这一过程但非唯一原因。

**辨析**：此处再次强调：“10.0 完全移除 GCC” 是常见错误——GCC 4.2.1 在 10.x 全系列 base 中存在并用于非 x86 架构，仅在 x86/arm 默认不安装；sparc64 在 10.x 仍为 Tier 2 架构发布镜像但实际使用人数极少，至 FreeBSD 13 降级为 Tier 3。

**文献**：FreeBSD 10.0-RELEASE Release Notes [Z]. 2014；FreeBSD src.conf(5)[Z]；参见相关章节 GCC 移除时间线部分。［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 128.9.4 Tier 架构支持演变

**要点**：FreeBSD 10.x 时期架构支持层级：①Tier 1：amd64、i386——release engineering 正式支持、安全 advisories 覆盖、包及时更新；②Tier 2：armv6（从 10.1 起）、ia64、powerpc、powerpc64、sparc64——社区维护、发布镜像但包更新可能滞后；③Tier 3：mips、其他 ARM 变种——无正式发布镜像、仅源码树支持。10.x 时期架构支持趋势：armv6 晋升 Tier 2 反映 ARM 生态崛起；ia64（Itanium）虽仍发布但实质垂死；sparc64 使用量持续下降；amd64 成为事实上的服务器主力架构（新特性如 bhyve 最初仅支持 amd64）。Tier 系统的设立使 FreeBSD 项目能合理分配有限的开发资源——Tier 1 架构获得最多关注，Tier 3 架构依赖志愿贡献者。

**史料**：FreeBSD 10.0-10.4 Announcements 支持架构列表、FreeBSD Supported Platforms 页面、Colin Percival/Watson 等人关于 Tier 系统定义的文档。 ［B］

**史观**：总纲第 8 条——本体论上各方平等：Tier 支持层级是 FreeBSD 项目资源分配的治理机制——通过明确定义各架构支持级别，项目避免了 “对所有架构承诺但无法兑现” 的困境。这种务实的治理模式是 FreeBSD 在有限志愿者资源下仍能维持高质量 amd64 支持的关键。

**辨析**：Tier 状态随版本变化——如 ia64 在 FreeBSD 11 中降级，arm64 在 11 成为 Tier 2，在 13 晋升 Tier 1；Tier 2 不代表 “不可用于生产”——许多公司基于 FreeBSD armv6/arm64 嵌入式部署使用，但这些用户需自行承担测试与维护责任。

**文献**：FreeBSD Supported Platforms [Z]. freebsd.org/platforms/；FreeBSD 10.x Release Announcements [Z].［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
