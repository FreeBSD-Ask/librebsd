# 126.2 2014.11.14 FreeBSD 10.1-RELEASE——新控制台与 UEFI 引导

## 126.2.1 发布与主要特性概览
  - 要点：FreeBSD 10.1-RELEASE 于 2014 年 11 月 14 日发布，是 stable/10 分支的第二个版本，Release Engineering Lead 从 Ken Smith 交棒给 Glen Barber（格伦·巴伯）（gjb@），10.1 的 Release Engineer 即为 Glen Barber 本人。此版本新增支持 armv6 架构（10.0 仅支持 amd64/i386/ia64/powerpc/powerpc64/sparc64）。主要亮点特性：**vt(4)** 新控制台驱动（Newcons）从 -CURRENT 合并；**bhyve(4)** 新增 i386 客户机支持与 ZFS 引导支持；amd64 加入初始 UEFI 引导支持（由 FreeBSD Foundation 赞助开发）；**autofs(5)** 自动挂载工具加入；**geli(8)** 支持启动时缓存密码短语；UDP-Lite（RFC 3828）支持加入 IPv4/IPv6 协议栈；OpenSSH 更新至 6.6p1，默认生成 ED25519 主机密钥；Unbound 更新至 1.4.22；**pkg(8)** 更新至 1.3.8；支持生命周期至 2017 年 1 月 1 日。10.1 首次提供 UEFI 可引导镜像（amd64）以及 QCOW2/VHD/VMDK 格式的预构建虚拟机镜像，首次登陆 Microsoft Azure 市场与 Amazon EC2。

## 126.2.2 **vt(4)** Newcons 控制台
  - 要点：**vt(4)**（又称 Newcons）是 FreeBSD 新一代虚拟控制台驱动，旨在替换自 BSD 时代沿用的 **syscons(4)**。**vt(4)** 项目起源于 2000 年代后期，主要开发者包括 Ed Schouten（ed@）、Ed Maste（埃德·马斯特）（emaste@）、Aleksandr Rybalko（ray@）等人（据 **vt(4)** 手册页 AUTHORS 段，commit 5dc400ff452b），FreeBSD Foundation 赞助了部分开发工作（r271128 性能合并标注"Sponsored by The FreeBSD Foundation"），手册页由 Warren Block（wblock@）撰写；**vt(4)** 首次出现于 FreeBSD 9.3（据 HISTORY 段），后合并入 stable/10。**vt(4)** 在 10.1 合并入 stable/10（r262861），核心特性：支持 KMS（Kernel Mode Setting）驱动，可与 **drm2(4)** Radeon/Intel GPU 驱动配合实现高分辨率控制台；支持 Unicode/UTF-8 终端；更好的多显示器支持；与 Xorg 图形系统更平滑的切换。在 10.1 中启用 **vt(4)** 需在 **loader.conf(5)** 中设置 `kern.vty=vt` 或在 loader 提示符下输入；powerpc64 GENERIC64 内核已默认启用 **vt(4)** 用于 Sony PlayStation 3 支持（r271111）。使用 ATI Radeon 显卡配合 **vt(4)** 需要 x11-servers/xorg-server 1.12.4_8 或更新版本。
  - 史料：FreeBSD 10.1-RELEASE Release Notes（Kernel Changes vt(4) 章节、Boot Loader Changes 章节）、vt(4) 手册页、Ed Schouten 历年 Newcons 设计文档与邮件列表公告、svn commit r262861（vt(4) merge from -CURRENT）、r271128（vt(4) performance enhancements，Sponsored by FreeBSD Foundation）。 ［A］
  - 史观：总纲第 17 条——软件工程：**syscons(4)** 作为 1980 年代设计的控制台驱动，无法支持现代显卡的 KMS 模式切换与高分辨率显示，**vt(4)** 替换是 FreeBSD 桌面与图形支持现代化的必要基础工程。这一替换历时近十年（从项目启动到默认启用），体现了 BSD 项目在核心基础设施替换上的极度审慎。
  - 辨析：Newcons 项目名称常被误写为"newcons"或"NewCons"——正式驱动名为 **vt(4)**，"Newcons"是开发期间的项目代号；部分资料称 **vt(4)** 支持 Intel KMS 驱动——10.1 中 drm/i915 驱动已加入硬件上下文支持（r271816）可配合 Mesa 9.2+，但 **vt(4)** 与 Intel KMS 的集成稳定性在 10.x 时期不如 Radeon，至 11/12 才成熟。
  - 文献：FreeBSD vt(4) Manual Page [Z].；Schouten E. Newcons: FreeBSD's New Console Driver [C]//BSDCan 2013. Ottawa, 2013；FreeBSD 10.1-RELEASE Release Notes [Z]. 2014.
## 126.2.3 UEFI 引导初始支持
  - 要点：10.1 的 UEFI 引导支持由 The FreeBSD Foundation 赞助开发（r271135 标注），新增三个 /boot 目录下的 EFI 引导文件：boot1.efi（UEFI 第一阶段引导）、boot1.efifat（含 EFI 系统分区的 FAT 文件系统镜像）、loader.efi（第三阶段引导加载器）。10.1 UEFI 支持特性：串行控制台与 null 控制台支持；但不支持多设备引导、不解析 /boot/config 与 /boot.config、无 GOP/UGA 图形模式设置、不支持 ZFS 引导；这些局限在 10.3 才得到解决。10.1 单独提供 uefi-bootonly/uefi-disc1/uefi-dvd1/uefi-memstick 等镜像变体。
  - 史料：FreeBSD 10.1-RELEASE Release Notes（Boot Loader Changes 章节，明确标注 r271135/r271136/r271880 等 commit 号及"Sponsored by The FreeBSD Foundation"信息）、10.1 Announcement 中"Additional UEFI-capable images are available"说明、loader(8) 手册页 UEFI 章节。 ［A］
  - 史观：总纲第 21 条——硬件支持：BIOS 到 UEFI 的迁移是 PC 硬件架构的世代更替，FreeBSD 对 UEFI 的支持进度落后于 Linux 约 3-5 年（Linux 约 2009-2010 年即有可用 UEFI 引导），但 10.1 开始的支持为后续版本完善奠定了基础，使 FreeBSD 能够运行在 2012 年后预装 Windows 8/10 的 UEFI Secure Boot 硬件上。
  - 辨析：10.1 UEFI 不支持 Secure Boot——Secure Boot 支持在 FreeBSD 13.0 才基本可用；10.1 UEFI 不支持 ZFS 引导——ZFS UEFI 引导在 10.3 才加入；10.1 UEFI 引导为 64 位（amd64）only，i386 UEFI 支持不在计划中。

## 126.2.4 bhyve、ARM 与网络改进
  - 要点：10.1 中 **bhyve(4)** 改进包括：i386 客户机支持（r267399，10.0 仅支持 amd64 客户机）；ZFS 文件系统引导支持（r268932）；XSAVE 虚拟化支持允许客户机使用 AVX 等扩展指令集（r267427）；ACPI S5 软关机支持（r261090）；virtio 随机数驱动 **virtio_random(4)** 加入（r268933）；virtio API 从 32 位扩展到 64 位；post-mortem 调试支持。ARM 架构在 10.1 中大幅改进：armv6 成为正式支持架构（加入发布镜像）；SMP 默认启用在多核 ARM 平台；硬件浮点支持默认启用；C++ 异常处理与 GCC 配合修复；新增对 Raspberry Pi、BeagleBone、PandaBoard、Wandboard、Chromebook（Exynos 5250）、Radxa 等平台的支持；Raspberry Pi I2C 驱动加入。网络方面：UDP-Lite（RFC 3828）支持加入；iSCSI initiator 支持重定向处理与性能优化（FreeBSD Foundation 赞助）；新增 Atheros 11n 无线驱动改进；**cxgbe(4)**  Chelsio T5 40G 网卡 netmap 支持；Intel XL710 网卡 **ixl(4)** 驱动导入。
  - 史料：FreeBSD 10.1-RELEASE Release Notes（Virtualization support、ARM support、Network Interface Support、Network Protocols 各章节）、svn commit r267399（bhyve i386 guest）、r268932（bhyve ZFS boot）、r267427（XSAVE virtualization）。 ［A］
  - 史观：总纲第 6 条——技术路线分化：bhyve 在 10.x 时期的快速演进（单 vCPU→SMP、无 UEFI→UEFI、仅 amd64 客户机 →i386/Windows 客户机）体现了 FreeBSD 在虚拟化领域的独立技术路线——不依赖 KVM/Xen 而是自主开发 Type-2 hypervisor，这与 Linux 生态形成鲜明对比。ARM 支持的进展则是 FreeBSD 应对 ARM 服务器与嵌入式市场崛起的战略布局。
  - 辨析：bhyve 在 10.1 仍不支持 SMP 客户机（多 vCPU）——SMP 客户机支持在 10.3 才加入（10.1 中 bhyve 客户机仅限单 vCPU）；bhyve 在 10.1 仍无 UEFI 固件支持——uefi-edk2-bhyve 端口在 10.x 后期才成熟。
