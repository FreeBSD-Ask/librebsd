# 127.1 2014.1.20 FreeBSD 10.0-RELEASE——stable/10 分支起点

## 127.1.1 发布工程语境与版本特性

**要点**：FreeBSD 10.0-RELEASE 于 2014 年 1 月 20 日由 Release Engineering Team 正式发布（release/10.0.0 tagger_date = 2014-01-16T18:43:50Z，tagger = Glen Barber（格伦·巴伯），公告晚于 tag 4 天），是 stable/10 分支的首个版本，Release Engineer 为 Glen Barber（gjb@），Release Engineering Lead 为 Ken Smith（kensmith@）。10.0 支持 amd64、i386、ia64、powerpc、powerpc64、sparc64 六种架构。这是 FreeBSD 历史上基础系统变动最大的版本之一：Clang 成为 i386/amd64/arm 默认编译器（参见相关章节），**bhyve(8)** 虚拟机监控器正式纳入 base（首入过程参见相关章节），**pkg(8)** 成为默认软件包管理工具（base 内置 **pkg(7)** 引导工具负责首装），sysinstall 被 bsdinstall 完全替换，BIND 从 base 移除，GCC 不再默认安装于 Clang 默认架构，**make(1)** 替换为来自 NetBSD 的 **bmake(1)**，Unbound 作为本地缓存 DNS 解析器导入。支持生命周期原定于 2015 年 1 月 31 日结束。主要赞助企业包括 The FreeBSD Foundation、Yahoo!、NetApp、Internet Systems Consortium、iXsystems、Juniper Networks、NLNet 等。

**辨析**：原文件与部分中文资料误称 10.0 默认 MTA 为 dma（DragonFly Mail Agent）——经 10.0 Announcement、10.0 Release Notes 与 10.1 Announcement（明确记录 “Sendmail has been updated to 8.14.9”）交叉验证，10.0 与 10.1 中 **sendmail(8)** 仍存在于 base 且为默认 MTA；**dma(8)** 作为 DragonFly BSD 项目开发的轻量级 MTA，在 FreeBSD 10.x 全系列中既不在 base 中也非默认配置，其成为 FreeBSD 默认 MTA 发生在 FreeBSD 14.0（2023 年 11 月）；原文件称 “USB4BSD 完成”——USB stack 重写（USB4BSD 项目，由 Hans Petter Selasky 主导）实际在 FreeBSD 8/9 时期已基本完成，10.0 是进一步完善而非首次完成；原文件称 “10.0 根目录可 ZFS（ZFS boot 在 9.0 已支持但 10.0 完善）”——9.0 确实已支持 ZFS 引导，但 **bsdinstall(8)** 中的 Root-on-ZFS 自动安装菜单在 10.0 才首次加入（r256361），这是关键区别。Clang 版本经 Release Notes（r251662）核实为 3.3，而非部分资料所称 3.4；经 freebsd.duckdb tags 表验证，release/10.0.0 tag 的 tagger_date 为 2014-01-16T18:43:50Z（tagger: Glen Barber），公告日期 2014-01-20 晚于 tagger_date 4 天，属 FreeBSD 发布工程正常流程（tag 创建后等待镜像同步与公告准备）；[考据完成：2026-08-15 复核查] 邮件列表库验证通过：freebsd-announce 公告“FreeBSD 10.0-RELEASE Now Available”（Glen Barber，2014-01-20，Message-ID: <20140120162953.GA7750@glenbarber.us>），公告要点含“GCC is no longer installed by default”，与 10.0 发布日及 GCC 不再默认安装一致

## 127.1.2 内核与虚拟化改进

**要点**：10.0 内核层面的主要改进包括：Capsicum 能力模式默认启用（允许沙箱化程序）；amd64/i386 加入 **drm2(4)** Radeon GPU 驱动（移植自 Linux 3.8，支持 Radeon HD 6000 及部分 HD 7000 系列 GPU，r254885）；unmapped VMIO buffers 实现消除了 buffer 创建与复用中的 TLB shootdown，大 SMP 系统上 I/O 密集工作负载可减少 25-30% 系统时间（r248508）；amd64 内核可寻址内存从 1TB 提升至 4TB（r254466）；**ddb(4)** 内核调试器加入输出捕获与脚本支持；RDRAND 指令支持（IvyBridge 及更新 Intel CPU，r240135）；**nvme(4)** NVM Express SSD 驱动加入（r240616）；**netmap(4)** 高性能数据包 I/O 框架加入（r227614）；CARP(4) 重写改进锁与多播处理；**pf(4)** 防火墙支持细粒度锁定提升多 CPU 性能；最多支持 65536 个路由表；基于内核的 iSCSI target 与 initiator 加入（r255570，即 **ctld(8)** 与 **iscontrol(8)** 的后继 **iscsid(8)**）；FUSE 用户态文件系统支持加入 base（r241519）；ZFS 加入 TRIM 支持与 LZ4 压缩、L2ARC 压缩、zio nop-write 优化。

**史料**：FreeBSD 10.0-RELEASE Release Notes（Kernel Changes、Virtualization support、File Systems、ZFS 各章节，带具体 svn revision 号）、svnweb.freebsd.org base 仓库 r245652（bhyve 导入）、r227652（virtio 导入）、r255524（Hyper-V 半虚拟化驱动导入 amd64 GENERIC）、r255744（Xen PVHVM 加入 GENERIC）、r254738（vmx(4) VMXNET3 驱动从 OpenBSD 移植）。 ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界：10.0 内核汇集了 FreeBSD-CURRENT 长达两年的开发成果（从 9.0 发布于 2012.1 到 10.0 于 2014.1），几乎所有子系统都有重大改进。unmapped VMIO buffers 这类底层优化虽不为普通用户感知，但对数据库、存储、网络等 I/O 密集型工作负载性能影响巨大，是 FreeBSD 工程 “沉默改进” 传统的体现。

**辨析**：**virtio(4)** 驱动在 10.0 已完整支持 virtio_blk、virtio_scsi、vtnet 网络、virtio_balloon 内存气球（r227652），这是 clean-room BSD 许可实现，非 GPL 代码移植；Hyper-V 驱动在 10.0 仅加入 amd64 GENERIC，i386 需手动加载模块或编译内核；Raspberry Pi 支持在 10.0 已加入（r239922），但为 Tier 3 状态。

**文献**：FreeBSD 10.0-RELEASE Release Notes [Z]. 2014；Rizzo L. netmap: a novel framework for fast packet I/O [C]//USENIX ATC 2012. Boston, 2012.

## 127.1.3 用户空间与工具链变动

**要点**：10.0 用户空间变动包括：**freebsd-version(1)** 工具加入用于精确查询已安装内核与用户空间版本（r256106）；GNU patch 被 BSD 许可的 **patch(1)** 替换（r255191）；GNU sort 被 BSD 许可 **sort(1)** 替换（r241511）；Berkeley yacc（byacc）替换旧 yacc（r235723）；**lex(1)** 替换为 flex 2.5.37（r250881）；基于 **libarchive(3)** 的 BSD 许可 **ar(1)**/**ranlib(1)** 替换 GNU binutils 版本；**bc(1)**/**dc(1)** 替换为 BSD 许可版本；**cpio(1)** 替换为基于 libarchive 的 BSD 版本（GNU cpio 仍保留为 gcpio）；用户名支持最长 32 字符（原 16 字符限制，r243023）；Capsicum 用户空间工具集更新。需特别注意：GCC 4.2.1 在 10.0 并未从 base 完全移除——Clang 成为 i386/amd64/arm 默认编译器后，sparc64、powerpc、powerpc64、ia64 等架构仍默认使用 GCC 4.2.1 构建，可通过 WITH_GCC/WITHOUT_CLANG src.conf 选项在 x86 上启用 GCC 构建。

**史料**：FreeBSD 10.0-RELEASE Release Notes（Userland Changes 章节）、src.conf(5) 手册页（WITH_GCC/WITHOUT_CLANG 选项说明）、svn commit log r255321（"On platforms where clang is the default compiler, don't build GCC or libstdc++ by default"）。 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：10.0 用户空间的 GNU 工具替换是许可证纯洁化工程（参见相关章节）的关键里程碑，patch/sort/ar/ranlib/bc/dc/cpio/yacc 等工具逐一替换为 BSD 许可实现，这不是单一决策的结果而是持续数年逐点清除的成果。

**辨析**：部分资料称 “10.0 完全移除 GCC”——经官方 Release Notes 与 src.conf 核实，此说不准确：GCC 4.2.1 仍存在于 base 系统源码树中用于非 x86 架构，x86 上默认不安装但可通过 src.conf 选项启用构建；完全移除 GCC 4.2.1 发生在 FreeBSD 13.0 时期（Warner Losh 2018 年后逐步执行）。

## 127.1.4 从 9.x 升级路径与已知问题

**要点**：从 FreeBSD 9.x 升级到 10.0 需特别注意 **freebsd-update(8)** 相关勘误：EN-13:04.freebsd-update 与 EN-13:05.freebsd-update 必须在升级前应用。升级后 pkg_add/pkg_delete 等旧 pkg_*工具不再可用，必须迁移到 **pkg(8)**；sysinstall 不再存在，系统配置需使用 **bsdconfig(8)**；BIND 用户需从 ports 安装 dns/bind9* 或迁移到 Unbound 配置；nslookup/dig 不再在 base 中，需使用 **host(1)**/**drill(1)** 或安装 dns/bind-tools；默认编译器从 GCC 切换到 Clang 可能导致 ports 中依赖 GCC 扩展的软件编译失败。10.0 发布时已知问题包括：某些 UEFI 主板引导问题、bhyve 仅支持单 vCPU 且无 UEFI 固件、某些无线驱动稳定性问题。

**史料**：FreeBSD 10.0-RELEASE Installation Instructions、EN-13:04 与 EN-13:05 Errata Notices、FreeBSD 10.0-RELEASE Errata 文档、FreeBSD Handbook “Updating FreeBSD” 章节。 ［B］

**史观**：总纲第 8 条——本体论上各方平等：10.0 的大规模基础系统更替考验了 FreeBSD 的发布工程流程与社区升级支持能力。Release Engineering Team 在发布公告中明确列出升级前必读的 errata，freebsd-update 工具的存在使二进制升级成为可能，这是 FreeBSD 相较其他 BSD 发行版在工程成熟度上的体现。

**辨析**：10.0 支持周期（原计划至 2015.1.31）实际因后续 10.1/10.2 等版本发布而延长——单个 RELEASE 版本支持周期通常为至下一个次版本发布后一个月，stable/10 分支整体支持至 2018.10.31。
