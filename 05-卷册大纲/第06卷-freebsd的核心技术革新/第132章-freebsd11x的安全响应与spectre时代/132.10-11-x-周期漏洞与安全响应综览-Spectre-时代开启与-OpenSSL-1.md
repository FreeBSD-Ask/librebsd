# 132.10 11.x 周期漏洞与安全响应综览——Spectre 时代开启与 OpenSSL 1.0.2 守旧期的安全债务清算

## 132.10.1 11.x 周期安全态势总览——116 个 SA 与版本周期数据切片

**要点**：FreeBSD 11.x 周期（**2016 年 10 月 10 日** 11.0-RELEASE 发布至 **2021 年 9 月 30 日** stable/11 分支 EOL）共发布 **116 个 FreeBSD-SA**——按年份分布为 SA-16:27-39（13 个，2016 年第四季度）、SA-17:01-12（12 个）、SA-18:01-15（15 个）、SA-19:01-26（26 个）、SA-20:01-33（33 个）、SA-21:01-17（17 个，2021 年 1-8 月）；版本周期文件 `原材料/研究/bsd漏洞史/版本周期/freebsd-11.x.md` 中开发期（**2016 年 10 月 1 日** 至 **2018 年 12 月 1 日**）共记录 **203 条 CVE 相关 commit** 与 **37 条无 CVE 编号的 Security fix commit**，去重后得 **194 个 CVE**；NVD 元数据中 11.x 周期 CVSS v3.x 评分全部缺失（194 个 CVE 均无评分）——这一数据分布反映 2016-2018 年间 NVD 对 FreeBSD 相关 CVE 元数据覆盖不完整，与 14.x 周期 189 个 CVE 中 11 个有 CVSS v3 评分形成对比；11.x 周期 SA 按主题分类：投机执行类 3 个（SA-18:03/07/09）、FreeBSD 内核本土代码类约 35 个、OpenSSL 类 9 个、OpenSSH 类 4 个、WPA/hostapd 类 3 个、bhyve 类 6 个、第三方贡献组件类约 30 个、其余散布于网络栈与文件系统。〔存疑：本要点与史料字段所引数据文件路径“原材料/研究/bsd漏洞史/版本周期/freebsd-11.x.md”“官方公告/freebsd-sa.md”“nvd元数据/cve元数据汇总.md”经 2026-09-13 全库 ls/find 实测不存在（“原材料”顶层目录缺失），实际落盘位置待补录，量化结论复现受阻〕

**史观**：总纲第 17 条——证明世界先于解释和改造世界：116 个 SA 在五年维护周期内的分布不均（2018 年 15 个、2019 年 26 个、2020 年 33 个）反映两个事实：其一，stable/11 分支进入纯维护期后（11.4-RELEASE 于 2020 年 6 月发布后），Security Team 对历史代码的“事后审计”力度加大；其二，2018 年投机执行漏洞群（Spectre/Meltdown/L1TF/Lazy FPU/SSBD）的爆发开启了 CPU 漏洞时代，11.x 周期成为 FreeBSD 历史上第一个需要应对硬件架构级安全缺陷的版本系列——这与 9.x 周期应对 OpenSSL 0.9.8 时代漏洞、10.x 周期应对 sendmail/OpenSSH 历史漏洞的模式完全不同，11.x 周期的安全响应工作量中相当部分消耗在 CPU 微架构层面

**辨析**：**需严格区分**：①“11.x 开发期”（2016-10 至 2018-12，对应 11.0-11.2 发布期，版本周期文件数据范围）与“11.x 维护期”（2016-10 至 2021-09，stable/11 完整生命周期，SA 数据范围）——前者是 CVE commit 数据切片，后者是 SA 数据切片，两者时间范围不同不可混用；②11.x 周期 116 个 SA 中部分 SA 同时修复多个版本分支（如 SA-18:03.speculative_execution 同时发布 11.1/11.2/10.4 补丁），故 SA 数量不等于 11.x 专属漏洞数量；③NVD 元数据 CVSS v3 评分全部缺失这一现象的考据学意义——不能解读为“11.x 周期漏洞不严重”，而是 NVD 在 2016-2018 年间对 BSD 相关 CVE 元数据覆盖滞后，CVE-2017-5715（Spectre v2）与 CVE-2017-5754（Meltdown）在 NVD 中有 CVSS v3 评分（5.6/7.6）但未进入本地 cve 元数据汇总文件，提示本地元数据需补充

## 132.10.2 Spectre/Meltdown 与投机执行漏洞群——CPU 安全时代的开启

**要点**：11.x 周期最具标志性的安全事件是 **投机执行漏洞群** 的爆发——**SA-18:03.speculative_execution**（**2018 年 3 月 14 日** 发布）修复 CVE-2017-5715（Spectre Variant 2，分支目标注入）与 CVE-2017-5754（Meltdown，rogue data cache load），由 Konstantin Belousov（康斯坦丁·别洛乌索夫）（kib@）主导修复，commit `d09c73e6c649` "Add mitigations for two classes of speculative execution vulnerabilities on amd64"是 11.x 周期最重要的单个安全 commit；**SA-18:07.lazyfpu**（**2018 年 6 月 21 日**）修复 CVE-2018-3665（Lazy FPU state restore），由 Konstantin Belousov 修复，commit `701e21017f7a` “Fix Lazy FPU information disclosure”，涉及 i386 与 amd64 双架构；**SA-18:09.l1tf**（**2018 年 8 月 14 日**）修复 CVE-2018-3620（L1 Terminal Fault OS）、CVE-2018-3646（L1TF VMM），由 Konstantin Belousov 提交 commit `c30578feeb82` “Provide part of the mitigation for L1TF-VMM”；此外 **SA-18:06.debugreg**（**2018 年 5 月 8 日**）修复 CVE-2018-8897（x86 debug register POP SS 漏洞），由 Konstantin Belousov 提交 commit `053641bb1cef` “Prepare DB# handler for deferred trigger of watchpoints”——这是与投机执行漏洞同源的 x86 架构语义漏洞；Spectre v2 修复引入 **retpoline(7)**（return trampoline）技术，由 Ed Maste（埃德·马斯特） 提交 commit `481640801657` “add retpoline compiler and linker feature flags”与 commit `e9093b66d54d` “Add kernel retpoline option for amd64”，将 clang/LLVM 6.0.0 的 retpoline 支持反向移植至 stable/11；Meltdown 修复引入 KPTI（Kernel Page Table Isolation），由 Ed Maste 提交 commit `b3327f62f0cd` “Enable KPTI by default on amd64 for non-AMD CPUs”——FreeBSD 的 KPTI 实现默认仅对 Intel CPU 启用，AMD CPU 因架构差异不受 Meltdown 影响而默认关闭，这一差异化策略与 Linux 内核的 KPTI 实现一致

**史料**：FreeBSD-SA-18:03.speculative_execution PGP 签名公告（2018-03-14）；FreeBSD-SA-18:06.debugreg PGP 签名公告（2018-05-08）；FreeBSD-SA-18:07.lazyfpu PGP 签名公告（2018-06-21）；FreeBSD-SA-18:09.l1tf PGP 签名公告（2018-08-14）；**freebsd.duckdb** `commits` 表 `freebsd-src` 仓库投机执行漏洞修复 commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2018-01-01' AND author_date<='2018-09-01' AND message_subject LIKE '%CVE-2017-5715%' ORDER BY author_date ASC`——返回 commit `91fe5fe7e7e4`（Tycho Nightingale，2018-01-15，"Provide some mitigation against CVE-2017-5715 by clearing registers upon returning"）、commit `b3327f62f0cd`（Ed Maste，2018-01-19，“Enable KPTI by default on amd64 for non-AMD CPUs”）、commit `481640801657`（Ed Maste，2018-02-07，“add retpoline compiler and linker feature flags”）、commit `e9093b66d54d`（Ed Maste，2018-02-28，“Add kernel retpoline option for amd64”）、commit `d09c73e6c649`（Gordon Tetlow（戈登·泰特洛），2018-03-14，"Add mitigations for two classes of speculative execution vulnerabilities on amd6"）、commit `3f5cefbce0a5`（Dimitry Andric，2018-03-31，"Merge clang, llvm, lld, lldb, compiler-rt and libc++ 6.0.0 release"）；Jann Horn（Google Project Zero）关于 Meltdown/Spectre 的原始研究报告（2018-01-03）；Anders Fogh（Crowd Strike）关于 L1TF 的原始研究 ［A］

**史观**：专题语（不设总纲条号）——硬件与软件辩证：投机执行漏洞群是 FreeBSD 历史上首次面对“硬件架构层面的安全缺陷”——CPU 微架构实现（投机执行、分支预测、缓存层次）违反了软件层对 ISA（指令集架构）的安全假设，使得任何遵循 ISA 规范的操作系统都暴露在攻击面下；这一事件从根本上改变了 FreeBSD Security Team 的工作模式——以前安全响应针对软件 bug，11.x 之后必须针对“硬件 bug + 软件缓解”的组合，且缓解措施往往带来 5-30% 的性能损耗；Konstantin Belousov 与 Ed Maste 在 11.x 周期内承担了 FreeBSD 投机执行缓解工程的核心工作，他们的 commit 链展示了从紧急响应（1 月 KPTI）到系统性加固（2-3 月 retpoline）再到后续跟进（6 月 Lazy FPU、8 月 L1TF）的完整工程节奏。缓存侧信道攻击并非始于 2018 年——前 FreeBSD Security Officer Colin Percival 早在 2005 年即发表共享 L1 缓存侧信道攻击（针对 Intel 超线程等同步多线程），其 2019 年 EuroBSDCon 演讲“23 years of software side channel attacks”将这一谱系追溯至 Kocher 1996 年计时攻击，并于 2009 年发明密钥派生函数 `scrypt`（Percival, 2019）。

**辨析**：**需精确说明 FreeBSD 投机执行响应的时间线**：① 2018 年 1 月 3 日 Google Project Zero 与 Jann Horn 公开 Spectre/Meltdown 漏洞；② 2018 年 1 月 15 日 Tycho Nightingale 提交 commit `91fe5fe7e7e4` 提供 Spectre v2 初步缓解（清空寄存器）；③ 2018 年 1 月 19 日 Ed Maste 提交 commit `b3327f62f0cd` 启用 KPTI——FreeBSD 比 Linux 内核（2018 年 1 月初 KPTI 已上线）晚约两周；④ 2018 年 3 月 14 日 SA-18:03 正式发布，距漏洞公开约 70 日；⑤ clang/LLVM 6.0.0 升级（commit `3f5cefbce0a5`，2018-03-31）将 retpoline 支持引入 stable/11——这晚于 SA-18:03 发布，意味着 SA-18:03 的 retpoline 缓解依赖 6.0.0 之前的 clang 5.0 分支补丁（commit `c302e70cb98d`，Dimitry Andric，2018-03-19）；**CVE-2018-8897（POP SS）的归属辨析**：CVE-2018-8897 不是投机执行漏洞，而是 x86 架构的“mov/pop ss”指令语义漏洞，但因与投机执行漏洞同期披露且修复路径类似（修改 DB# 异常处理），常被归入“CPU 架构漏洞群”——本节将其与投机执行漏洞并列叙述以反映历史同期性，但需说明技术机制不同；**arm64 SSBD 实现的辨析**：commit `0594061ee6fb`（Andrew Turner，2018-07-31，“Implement the SSBD (CVE-2018-3639) workaround on arm64”）表明 11.x 周期 FreeBSD 在 arm64 也实现了 SSBD 缓解——这与 11.0 引入 arm64 正式支持的战略决策呼应，新架构从一开始就纳入投机执行响应体系 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 132.10.3 WPA2 KRACK 与 802.11 协议层清算——13 个 CVE 的协议级缺陷

**要点**：**SA-17:07.wpa**（**2017 年 10 月 17 日** 发布）修复 WPA2 协议层的 KRACK（Key Reinstallation Attacks）漏洞群——由 Mathy Vanhoef（imec-DistriNet, KU Leuven）发现并披露，共影响 **13 个 CVE**（CVE-2017-13077、CVE-2017-13078、CVE-2017-13079、CVE-2017-13080、CVE-2017-13081、CVE-2017-13082、CVE-2017-13086、CVE-2017-13087、CVE-2017-13088，以及 CVE-2017-13077 之外的额外变体）；Gordon Tetlow 提交修复 commit `a2063804a2b8` "Update wpa_supplicant/hostapd for 2017-01 vulnerability release“（注意 commit message 中”2017-01“应为”2017-10"的笔误，反映 SA 发布过程的紧急性），后续 MFC commit `cfaed0fa41d7`、`746aa8b814b2` 将修复回溯至 stable/11 与 stable/10；KRACK 漏洞的技术机制为：WPA2 四次握手中的第三次消息（Message 3）可被攻击者重放，导致客户端重新安装已在使用中的密钥——重置密钥计数器与重放计数器，使攻击者可解密、重放、伪造加密流量；**SA-18:11.hostapd**（**2018 年 8 月 14 日**）修复 CVE-2018-14526，由 Cy Schubert 提交 commit `765ef8a7642d` “WPA: Ignore unauthenticated encrypted EAPOL-Key data”，Xin Li 完成 MFC commit `90c403d54f22`——这是 KRACK 之后 WPA 协议层的又一次安全响应；11.x 周期 WPA 相关 SA 共 3 个（SA-17:07.wpa、SA-18:11.hostapd、SA-19:03.wpa），形成连续的 802.11 协议层清算

**史观**：专题语（不设总纲条号）——信息技术：KRACK 漏洞是 11.x 周期最具协议级影响的安全事件——与 FreeBSD 内核 bug 或 OpenSSL 实现错误不同，KRACK 是 WPA2 协议规范本身的缺陷，任何遵循协议规范的实现（包括 FreeBSD、Linux、macOS、Windows、Android、iOS）都受影响；这使得 11.x 周期的安全响应从“修复 FreeBSD 代码”扩展为“修复 FreeBSD 实现的协议符合性”——commit `a2063804a2b8` 的 message_subject"Update wpa_supplicant/hostapd for 2017-01 vulnerability release“中的”vulnerability release"措辞表明这是上游 wpa_supplicant 项目的官方修复发布，FreeBSD 通过 vendor import 同步；KRACK 事件也暴露了 802.11 协议设计中“信任客户端状态机”的根本缺陷——后续 WPA3 协议（2018 年发布）的部分改进正是对 KRACK 的回应

## 132.10.5 OpenSSL 1.0.2 守旧期与加密栈债务——EOL 版本自行维护策略

## 132.10.7 11.x 周期安全响应文化评估——Security Officer 交接与投机执行响应的工程范式

**要点**：11.x 周期是 FreeBSD 安全响应文化的“代际交接期”——**2018 年 6 月 28 日** 11.2-RELEASE Announcement 中 Release Team 名单显示 Xin Li（delphij@）转为 Security Officer Emeritus，Gordon Tetlow（gordon@）正式接任 Security Officer，Ed Maste（emaste@）任 Security Officer Deputy；但实际交接是渐进过程——Gordon Tetlow 在 2017 年 11 月 15 日同日发布 SA-17:08/09/10 三个 SA 时已承担 Security Officer 实际职责，Xin Li 在 2017 年 11 月至 2018 年 1 月仍以 Security Officer Emeritus 身份提交 OpenSSL、OpenSSH 等关键安全修复 commit；11.x 周期 Security Officer 交接的特点是“无空档过渡”——Emeritus 头衔使 Xin Li 能够持续参与安全工作，Gordon Tetlow 接任前已积累多年安全团队经验；**投机执行响应的工程范式**——11.x 周期 SA-18:03.speculative_execution 是 FreeBSD 历史上首次需要 CPU 厂商协调的安全响应：① Konstantin Belousov 与 Ed Maste 需要与 Intel、AMD 协调 KPTI 与 retpoline 的微架构细节；② clang/LLVM 升级至 6.0.0（commit `3f5cefbce0a5`，2018-03-31）引入 retpoline 编译器支持，这是 FreeBSD 首次为安全缓解升级编译器版本；③ freebsd-update(8) 二进制补丁分发需要协调 amd64 与 i386 双架构；④ cloud 镜像（EC2/Azure/GCE）需要同步补丁；这一工程范式在 14.x 周期进一步成熟为“主动审计—批量披露”模式，但 11.x 周期的投机执行响应是其雏形；11.x 周期 Security Team 的核心贡献者包括 Gordon Tetlow（Security Officer）、Ed Maste（Deputy）、Konstantin Belousov（投机执行缓解核心开发者）、Xin Li（Emeritus，OpenSSL/OpenSSH 维护）、Martin Matuska（libarchive 维护）、Jonathan T. Looney（网络栈加固）、Cy Schubert（WPA 维护）、Dag-Erling Smørgrav（OpenSSH 维护）

**史观**：总纲第 8 条——本体论上各方平等：11.x 周期 Security Officer 交接是 FreeBSD 安全治理成熟度的关键标志——Colin Percival（2004-2014）建立 FreeBSD 安全响应体系，Dag-Erling Smørgrav/Xin Li（2014-2018）维持体系运转，Gordon Tetlow（2018-）推动体系演进至“主动审计”模式；这一代际交接的关键设计是 Security Officer Emeritus 制度——Emeritus 不是荣誉退休而是“经验保留机制”，使前 Security Officer 的安全工程经验能够在交接后持续注入团队；11.x 周期投机执行响应展示了 FreeBSD 安全治理的“工程师主导”特征——Konstantin Belousov 作为内核架构师而非 Security Team 成员主导 KPTI/retpoline/L1TF 缓解的代码实现，Security Team 负责 SA 发布与多分支回溯，这种“工程师写代码+Security Team 发 SA”的分工模式与 OpenBSD 项目中“开发者即安全官”的模式不同

**辨析**：**Security Officer 交接时间的辨析**：11.2-RELEASE Announcement（2018-06-28）是公开宣布 Gordon Tetlow 接任 Security Officer 的时点，但实际工作交接更早——Gordon Tetlow 在 2017-11-15 发布 SA-17:08/09/10 时已承担 Security Officer 职责（SA 公告通常由 Security Officer 签发），Xin Li 在 2017-11 至 2018-01 期间以 Emeritus 身份继续提交 commit；**“代际交接”提法的辨析**：Colin Percival 正式卸任 Security Officer 在 2010 年代初早于 11.x 时期，11.x 时期是 Dag-Erling Smørgrav/Xin Li→Gordon Tetlow 的交接，并非“四代交接”；**投机执行响应中 clang/LLVM 升级的辨析**：commit `3f5cefbce0a5`（Dimitry Andric，2018-03-31，"Merge clang, llvm, lld, lldb, compiler-rt and libc++ 6.0.0 release"）将 clang/LLVM 升级至 6.0.0，但这晚于 SA-18:03 发布（2018-03-14）——SA-18:03 的 retpoline 缓解依赖 commit `c302e70cb98d`（Dimitry Andric，2018-03-19，"Merge retpoline support from the upstream llvm, clang and lld 5.0 branches"）将 retpoline 支持反向移植至 clang 5.0，clang 6.0.0 升级是后续完善；**11.x 周期与 14.x 周期安全响应文化对比的辨析**：11.x 周期 116 个 SA / 5 年 / 平均每年 23 个 SA，14.x 周期 80 个 SA / 不足 3 年 / 平均每年约 27 个 SA——SA 节奏相近但 14.x 周期“主动审计”特征更明显（SA-26:45.audit 等内部审计主题 SA），11.x 周期则以“响应外部披露”为主（投机执行、KRACK 等均为外部披露后响应）；**与 sendmail→dma 迁移的关联辨析**：11.x 周期 sendmail 仍为默认 MTA，sendmail→dma(8) 迁移发生在 14.x 周期——11.x 周期“守旧”策略（OpenSSL 1.0.2 + sendmail）与 14.x 周期“激进升级”策略（OpenSSL 3.0 + dma）形成鲜明对比，反映 FreeBSD 不同版本周期的工程哲学差异

## 132.10.8 freebsd-src 趋势统计与 FreeBSD 11.x 架构扩展时代的定量印证

**要点**：**统计分析印证**——`freebsd.duckdb` freebsd-src 仓库 1993-2026 年 commit 月度量 Mann-Kendall 趋势检验结果为显著上升趋势（Sen's slope =+1.40/月，p < 0.001，95% CI [1.11, 1.69]）（统计结论 C-03）；ARIMA(5,0,5) 模型拟合 AIC = 107.39（统计结论 C-29），表明 freebsd-src commit 月度量可由 ARIMA 模型较好刻画；FreeBSD 11.x 系列（2016-2018）以 arm64/AArch64 升 Tier-1 架构、vt(4) 默认控制台、Linuxulator 64 位支持等架构扩展为特征，该时期 freebsd-src 趋势持续上升，未因架构扩展而中断 commit 增长趋势，统计结论支持 11.x 时期架构扩展未对 freebsd-src 整体开发活跃度产生负面影响

**史料**：`freebsd.duckdb` `commits` 表 freebsd-src 仓库 commit 月度量；SQL 查询 `SELECT strftime('%Y-%m', committer_date) AS month, COUNT(*) AS commit_count FROM commits WHERE repo_name='freebsd-src' GROUP BY month ORDER BY month`；Python 脚本 `script/phase3_inferential_stats.py` Task 5（Mann-Kendall 趋势检验）；Python 脚本 `script/phase4_time_series.py` Task 14（ARIMA 建模）；统计结论编号 C-03、C-29；查询日期 2026-07-27 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：freebsd-src 趋势检验显示 11.x 时期（2016-2018）架构扩展前后 commit 量均呈上升趋势，未出现因新架构引入导致的 “开发断裂”——统计数据印证 FreeBSD 在 ARM64 时代的架构扩展中赓续了 CSRG 未竟事业而非中断主线开发；专题语（不设总纲条号）——信息技术标准演进与硬件进步同步：arm64/AArch64 升 Tier-1 与 ARM 服务器硬件成熟度同步，freebsd-src 持续上升趋势反映 FreeBSD 在硬件代际更替中保持了开发活跃度

**辨析**：**统计局限性标注**——(1) 统计显著 ≠ 实际显著：Mann-Kendall 趋势检验 p < 0.001 表明 freebsd-src commit 量存在统计学显著上升趋势，但 11.x 时期架构扩展的实际工程意义须结合 arm64 具体代码量与 commit 分布综合判断；(2) ARIMA 模型局限：ARIMA(5,0,5) AIC = 107.39 为 freebsd-src 整体 commit 序列拟合结果，未单独建模 arm64 相关 commit 子序列，arm64 移植对整体趋势的贡献率未单独量化；(3) 多重比较风险：本结论与第五卷其他章节引用相同 freebsd-src 趋势统计存在多重比较风险，Bonferroni 校正后显著性可能降低；(4) commit 粒度变化：11.x 时期仍处于 SVN 时代（2020-01 才迁移至 Git），commit 粒度可能与 Git 时代不同；(5) SVN-to-Git 迁移影响：1993-2020 年 freebsd-src 数据经 SVN-to-Git 迁移重算，commit hash 与 author_date 由迁移脚本回填，可信度较高但非原始 Git 时代记录
