# 114.11 重要贡献者：DTrace 设计者、移植者与 eBPF 阵营对话者

## 114.11.1 DTrace 设计者与移植者的贡献
  - 要点：DTrace 历史上的核心贡献者：(1) Bryan Cantrill（布莱恩·坎特里尔）（1973- ）——首席架构师，Brown 大学 1996 年加入 Sun，与 Jeff Bonwick（杰夫·邦威克） 共事，2005 年 MIT TR35，2010 年离开 Oracle 加入 Joyent（VP Engineering→CTO），2019 年离开 Joyent，联合创立 Oxide Computer Company；(2) Michael W. Shapiro——Sun 资深工程师，DTrace 核心基础设施负责人，后参与 Fishworks 项目；(3) Adam H. Leventhal——Sun 工程师，DTrace 多个 provider 的实现者，2008 年撰写关于 Apple DTrace 问题的著名博客，离开 Sun/Oracle 后加入 Delphix 等公司；(4) John Birrell——澳大利亚 FreeBSD committer，DTrace FreeBSD 移植发起者，2010 年前后去世 [考据完成：2026-08-17 DTrace 由 Bryan Cantrill、Mike Shapiro、Adam Leventhal 三位 Sun 工程师创建（2005-01 随 Solaris 10 以 CDDL 开源），与 Jeff Bonwick 的导师关系经 Cantrill 自述确认]；(5) George V. Neville-Neil（乔治·V·内维尔-尼尔）——FreeBSD DTrace 后续维护者，与 McKusick、Watson 合著 FreeBSD 操作系统设计第二版；(6) Brendan Gregg——DTraceToolkit 作者，DTrace 书籍作者，DTrace 最重要的布道者和实践者

  - 史观：总纲第 10 条——边缘者贡献：DTrace 的发展历程体现了多层次贡献者的协作——核心设计者（Cantrill/Shapiro/Leventhal）提供技术突破，移植者（Birrell 等）实现跨平台，布道者（Gregg）推动普及，每个层次的贡献都不可或缺；John Birrell 作为移植发起者的贡献在他去世后尤其容易被忽视，需要在历史书写中明确记录

## 114.11.2 eBPF 阵营核心人物
  - 要点：eBPF 生态的核心贡献者：(1) Alexei Starovoitov——eBPF 设计者，俄罗斯/美国工程师，最初在 PLUMgrid 工作（后被 Oracle 收购），将经典 BPF 扩展为通用内核虚拟机，2014 年 eBPF 补丁合入 Linux 主线；(2) Daniel Borkmann——eBPF 核心共同维护者，Cilium/Isovalent 公司（后被 Cisco 收购），与 Starovoitov 合作扩展 eBPF 到网络和追踪领域；(3) Brendan Gregg——从 DTrace 阵营转向 eBPF 开发，创作 BCC 工具集多个工具、bpftrace 贡献者，著《BPF Performance Tools》；(4) Alastair Robertson——bpftrace 创建者；(5) Thomas Graf 等 Cilium 团队成员——推动 eBPF 在网络和云原生领域的应用
  - 史料：Linux 内核源码 MAINTAINERS 文件（eBPF 维护者记录）；Starovoitov 和 Borkmann 的 LKML 补丁提交历史；Gregg《BPF Performance Tools》致谢章节；Cilium 项目文档（cilium.io）；bpftrace GitHub 贡献者记录 ［A］
  - 史观：总纲第 10 条——边缘者贡献：eBPF 的成功同样是多人协作的成果——Starovoitov 提供核心虚拟机设计，Borkmann 提供网络和验证器改进，Gregg 提供工具和用户体验，Cilium 团队提供云原生场景落地
  - 辨析：Alexei Starovoitov 的 eBPF 工作最初是为了改进 Linux 网络包过滤性能（classic BPF 已用于 tcpdump/libpcap），追踪功能是后续扩展的方向——eBPF 不是为了“做 Linux 版 DTrace”而设计的，尽管它最终在追踪领域被定位为 DTrace 的对应物；Starovoitov 后来加入 Meta（Facebook），继续从事 eBPF 和内核开发
  - 文献：Linux kernel MAINTAINERS file; Starovoitov, A. & Borkmann, D. LKML patches; Gregg, B. (2019). BPF Performance Tools (Acknowledgments); Cilium Project. cilium.io[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]
## 114.11.3 DTrace 与 eBPF 阵营的对话与互动
  - 要点：DTrace 阵营与 eBPF 阵营之间并非对立关系，而是存在大量建设性对话：(1) Brendan Gregg 同时深度参与 DTrace 和 eBPF 社区，是两个生态之间最重要的桥梁——他在 Netflix 工作期间（2014-2020 前后）同时使用 DTrace（FreeBSD CDN）和 eBPF（Linux 分析），后来加入 Intel 专注 eBPF；(2) Bryan Cantrill 公开承认 eBPF 的成功，在演讲中讨论 DTrace 对 eBPF 的启发和 eBPF 的创新之处；(3) Oracle Linux 同时包含 DTrace 和 eBPF；(4) bpftrace 的语法设计明确借鉴了 D 语言；(5) 两个社区的技术交流在 USENIX LISA、eBPF Summit、BSDCan 等会议上持续进行
  - 史料：Brendan Gregg 在各种会议上关于 DTrace 和 eBPF 的演讲视频；Cantrill 关于 DTrace 历史和 eBPF 的评论（Twitter/X、会议演讲）；bpftrace 文档中关于受 D 语言启发的说明；Oracle Linux 同时支持 DTrace 和 eBPF 的技术文档[考据完成：2026-07-28 经穷尽联网考据，上述史料清单为已知公开来源汇总，部分原始档案未公开数字化或须档案馆藏地现场核验，属史料缺口，须待原始档案公开后方可补充确证]
  - 史观：总纲第 14 条——哲学思潮：DTrace 与 eBPF 阵营的对话体现了技术社区的实用主义精神——工程师们不被许可证和阵营对立束缚，而是根据问题选择最合适的工具，同时好的设计思想跨社区流动
  - 辨析：网上存在“DTrace vs eBPF 圣战”式的讨论，但核心开发者（Cantrill、Starovoitov、Gregg）都避免这种简单对立，他们承认各自技术的优缺点和适用场景；将技术竞争叙述为“你死我活”更多是技术社区粉丝文化的产物，而非核心开发者的立场
  - 文献：Gregg, B. Conference talks (LISA, BSDCan, eBPF Summit); Cantrill, B. Public comments on DTrace/eBPF (Twitter, YouTube talks); bpftrace documentation (language design notes) ［B］
