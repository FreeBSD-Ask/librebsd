# 385.5 安全审计方向的形成

## 385.5.1 从通用分叉到安全工程路线

  **要点**：OpenBSD 的安全路线在项目建立后逐步成形：以持续的全代码库安全审计（源码树逐行排查缓冲区溢出等经典缺陷）为方法，以 proactive security（默认安全配置、修正在先）为哲学，区别于事后修补的安全响应模式；安全方向的制度化标志随 2.x 序列累积——集成密码学栈、默认强加密、对 man 页与代码正确性的持续审查；安全审计方法论的影响远超项目自身：整个开源世界的安全实践（包括 Linux 内核开发者对审计规范的态度）受其间接塑造，但少被公开承认——BSD 沉默影响的典型样本；本节载方向的形成（1995-1996 至 2.x 初期），其后的成就史（OpenSSH 1999 等）属卷后段与专题卷
  
**史料**：OpenBSD 官方站（proactive security 与 audit 表述）<https://www.openbsd.org/>［2026-10-03 访问］；Theo de Raadt 条目（安全工程与项目方向）<https://wiki2.org/en/Theo_de_Raadt>；本地磁盘第 32 卷/第 75 章（安全工程与加密政策既有考证）；Use the Source（Theo 之 debugging and securing code 取向表述）<https://en.wikibooks.org/wiki/Use_the_Source/In_the_Beginning>［B］
  
**史观**：
- 总纲第 10 条——动手者创造历史：安全路线由逐行审计的持续劳动构成——看不见的重复劳动是其物质形态
- 总纲第 3 条——不存在进步，只有权力再分配：proactive security 把安全裁量权从漏洞响应者移至发行决策者——审查权的再分配
- 总纲第 15 条——文化即形式主义：“最安全的操作系统”作为身份表述，是工程事实与文化符号的双层形式
- 总纲第 13 条——法律与道德是利益分配：对加密集成与出口管制的处置（其时美国密码出口管制语境）是法律约束下的技术选择
- 总纲第 4 条——分离聚合是永恒规律：安全路线是 NetBSD 分裂的第三产物——一次分离多路聚合的持续展开

**辨析**：“全代码库审计”的起始规模与覆盖承诺的措辞（每一行都被审计过的宣称）系项目自我表述，审计覆盖率无独立验证；安全方向的形成时点——2.0（1996-10）时安全叙事的自觉程度与后来的口号化表述之间有距离，勿以成熟期叙事回投建项期；出口管制语境下的加密集成的合规细节属法律专题卷范围，本节只存边界注
