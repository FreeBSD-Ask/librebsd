# 3.3.4 复制机制在集群设想中的位置

<!-- ROW_MINE: dragonfly_mail.messages.80 -->
**当事人自述**（证据等级：L4，来源：`historical_claims.duckdb.claim.CL-RM-014728`；2026-09-10 大库战线行级遍历考据采纳）

2009 年 10 月 2 日，Simon“corecode”Schubert 报告旧版 HAMMER 向新版执行 mirror-copy 后 PFS 目录内容为空却照常占用空间，怒斥“这是彻底毁掉全部数据的绝佳机会”。mirror-copy 是 HAMMER 多主机复制机制的核心命令，其跨版本搬迁时的数据可见性缺陷暴露了 HAMMER 1.0 早期复制路径的危险面，也警示该文件系统彼时仍处在“功能先于稳定”的演进阶段。引用时按 L4 纪律：本叙事仅以该邮件原文为限。
