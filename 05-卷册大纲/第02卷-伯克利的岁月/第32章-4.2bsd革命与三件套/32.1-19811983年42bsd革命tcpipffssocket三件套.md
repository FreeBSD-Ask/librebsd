# 32.1 1981-1983 年 4.2BSD 革命——TCP/IP、FFS、socket 三件套


## 32.1.1 4.2BSD 革命的时间语境
- 要点：**4.2BSD** 于 **1983 年 8 月** 发布，是 BSD 历史上最重要的版本之一，引入 TCP/IP、FFS、socket 三件套，奠定了现代互联网的技术基础（McKusick 1999“Twenty Years of Berkeley Unix”原文“In August 1983, the system was released as 4.2BSD”；CSRG 4.2BSD 实际开发时间约 1981.6-1983.8（自 4.1BSD 1981.6 发布后启动 4.2BSD 项目），约 26 个月，与 4.1BSD（1981.6 发布）的 4.1a/4.1b/4.1c interim 版本一脉相承；BSDi 1992 年后商业化发布的 BSD/386 与 4.4BSD-Lite 等 4.x BSD 后续版本不属本章范围）；4.2BSD 开发周期关键里程碑时间线（McKusick 1999 当事人一手叙述）：1981.6 DARPA 授予第二份两年期大额合同（资金接近首份合同五倍）后 4.2BSD 项目启动；1981.7 新系统设施提案初稿在指导委员会内外传阅引发长期讨论；1981 夏 McKusick 加入 CSRG 接手 FFS 实现，Joy 集中实现 IPC 原型；1981 秋 Sam Leffler 以全职 staff 身份加入 CSRG 与 Joy 合作；1981.4-1983.6 DARPA 指导委员会每半年开会一次（由 Duane Adams 召集，成员含 Fabry、Joy、Leffler、Nemeth、Gurwitz、Ritchie、Lantz、Rashid、Halstead、Lynch、Popek 等 12 人）；1982.2《4.2BSD System Manual》文件传阅，含 4.2BSD 拟实现设施的用户接口精简描述；1982.4 4.1a 发布供伯克利本地使用（含 BBN TCP/IP 集成、原型 IPC、r-commands）；1982.6 McKusick 完成 FFS 实现并集成入 4.1a 内核，形成 4.1b（仅在伯克利少数开发机器运行）；1982 春末 Joy 宣布加入 Sun Microsystems；1982 夏 Joy 在 Sun 与伯克利间分配时间，完成 IPC 修订与内核源代码机器依赖隔离重组后离开；1982 夏末 Joy 离开后 Leffler 接任 4.2BSD 项目领导负责收尾；1983.4 4.1c 发布供 DARPA 厂商移植准备（Pauline Schwartz 接手分发职责）；1983.6 Bob Fabry 将 CSRG 行政控制权移交 Domenico Ferrari 与 Susan Graham 两位教授开始休年假；1983.8 Leffler 完成 4.2BSD 发布（实现新信号机制、网络支持扩展、独立 I/O 系统重写、Elz 磁盘配额集成、文档更新、4.1c bug 追踪）；开发周期延长的具体原因与对应工作量（McKusick 1999 当事人一手叙述）：（1）Joy 1982 年春末宣布加入 Sun 后实际离职导致项目失去原始领导，Leffler 接手后须重新评估剩余工作并重新设定优先级（McKusick 1999 原文“Given the time constraints, the work remaining to complete the release was evaluated and priorities were set”）；（2）Joy 在离开前完成内核源代码机器依赖隔离重组工作，此项工作本身耗时巨大但为后续多架构移植奠定基础（原文“reorganizing the Unix kernel sources to isolate machine dependencies”）；（3）虚拟内存增强与最复杂的 IPC 设计部分因时间压力被降级为低优先级并最终完全搁置（原文“relegated to low priority (and later shelved completely)”）——即减项换时间；（4）4.1a 实现一年多后社区期望升高，须组装中间版本 4.1c 供厂商移植准备以“hold people”（原文“it was decided an intermediate release should be put together to hold people until the final system could be completed”），4.1c 本身的发布与维护额外占用 Leffler 时间；（5）4.2BSD 集成的子系统数量多且复杂度高（FFS、TCP/IP、IPC/sockets、新信号机制、独立 I/O 系统重写、磁盘配额），每个子系统均需独立实现、调试与文档化；（6）Leffler 接手后仍须完成新信号机制、网络支持扩展、独立 I/O 系统重写简化安装、Elz 磁盘配额集成、全套文档更新、4.1c bug 追踪等多项收尾工作（McKusick 1999 原文列举 Leffler 完成项）；（7）指导委员会每半年一次的会议本身也占用核心成员时间但确保了 DARPA 研究社区需求被持续回应；统计结果：4.2BSD 发布后 18 个月内颁发超过 1000 份站点许可证，超过此前所有 BSD 发行量总和（McKusick 1999 原文“within eighteen months more than 1,000 site licenses had been issued”），反映开发周期延长换来的质量与功能完整性
- 史料：4.2BSD 发布说明（4.2BSD Release Notes 1983.8）、CSRG 档案、Joy/Leffler 的开发笔记、McKusick 1999“Twenty Years of Berkeley Unix”（O'Reilly Open Sources 官方在线版：<https://www.oreilly.com/openbook/opensources/book/kirkmck.html，当事人一手叙述）> ［B］
- 史观：第 1 条偶然性——4.2BSD 的革命性成就部分源于 DARPA 资助与 Joy 个人能力的偶然相遇
- 辨析：4.2BSD 的发布日期（1983 年 8 月）已由 McKusick 一手史料（1999 Open Sources 第 1 章）与多个独立来源（Klarasystems、infohelp.co.nz）交叉确认为 1983 年 8 月，“1983 年夏”的模糊表述应统一为“1983 年 8 月”；4.2BSD 开发时间应限定为 1981.6-1983.8（约 26 个月），不应上溯至 1979 年（1979 年为 3BSD 发布年，属 4.2BSD 项目前期工作的概念阶段而非正式开发）
- 文献：McKusick, K. (1999) “Twenty Years of Berkeley Unix”（Open Sources 第 1 章）；4.2BSD Release Notes (1983.8) ［B］

## 32.1.2 TCP/IP 协议栈的引入
- 要点：4.2BSD 集成的 TCP/IP 协议栈由 Bill Joy 与 Sam Leffler 在伯克利编写（rejecting BBN 原版后），引入 socket API 作为 IPC 与网络通信的统一抽象（Jim Dempsey 2017 互联网历史邮件列表原文“by Bill Joy and Sam Leffler of Berkeley along with Gurwitz. BBN promptly revised its TCP implementation to use the socket interface, and for about a year there was a battle to determine whose networking code would take precedence. Although the BBN code won some adherents, and was licensed to several computer vendors, the Berkeley code won the battle”），使 BSD TCP/IP 成为互联网协议的事实参考实现（DARPA 后续测试认为 4.2BSD 版本性能优于 BBN 官方实现，4.3BSD 保留 BSD 版本）
- 史料：4.2BSD 网络源代码、Joy/Leffler 的 TCP/IP 实现文档（“4.2BSD Networking Implementation Notes”6.1 节“Socket layer”）、DARPA 测试报告、Jim Dempsey 2017“Re: BBN C-series computers”邮件列表一手回顾 ［A］
- 史观：第 9 条经验优先——Joy/Leffler 的 TCP/IP 实现基于实践需求而非协议理论，实践驱动标准化
- 辨析：4.2BSD TCP/IP 的作者归属需严格考证——网络层代码与 socket API 均为 Bill Joy 与 Sam Leffler 共同设计（BBN 的 Rob Gurwitz 是 BBN 端 TCP/IP 实现者，BSD 端是 Joy 与 Leffler）；“Joy 自行编写”的不准确表述应改为“Joy 与 Leffler 共同编写”；BBN 后续曾重写其实现以采用 socket 接口，但 BSD 版本最终胜出成为互联网参考实现；BBN Gurwitz 原型与 CSRG Joy/Leffler 重写版本的具体性能差异（McKusick 1999《Twenty Years of Berkeley Unix》当事人一手记载 BBN 与 Berkeley TCP/IP 评估全过程，互联网档案馆存档 URL: https://web.archive.org/web/2023/https://www.oreilly.com/openbook/opensources/book/kirkmck.html）：（1）BBN Gurwitz 原型代码状态——Berkeley 在 4.2BSD 中实际集成的并非 BBN 最终版本，而是 BBN 早年交给 Joy 的“much-hacked initial prototype”原型代码（McKusick 1999 原文“we were still using the much-hacked initial prototype that they had given us many years earlier”），Joy 集成时对其进行了性能调优（McKusick 1999 原文“Joy integrated it into the system and tuned its performance”）；（2）CSRG Joy/Leffler 重写版本状态——Joy 与 Leffler 在 BBN 原型基础上重写了内部结构以支持多协议并行（McKusick 1999 原文“redesigned the internal structuring of the software, refining the interfaces so that multiple network protocols could be used simultaneously”），即从 BBN 单一 TCP/IP 协议实现扩展为支持多协议族（AF_INET、AF_UNIX 等）的通用网络子系统；（3）评估时点与背景——1985 年 6 月 USENIX 会议 CSRG 宣布 4.3BSD 将于夏季发布时，BBN 向 DARPA 投诉称合同分工为“Berkeley 实现接口、BBN 实现协议”（McKusick 1999 原文“Berkeley was to implement the interface while BBN was supposed to implement the protocol”），要求伯克利在 4.3BSD 中以 BBN 实现替换现有 TCP/IP 代码；（4）Karels 初步评估——Mike Karels 获取 BBN 更新代码后评估，决定将 BBN 代码中的优秀思想合并入伯克利代码库而非整体替换，理由是伯克利代码已经过 4.2BSD 大规模分发获得充分测试与改进（McKusick 1999 原文“it had gotten considerable testing and improvements from the widespread distribution in 4.2BSD”），作为妥协，Karels 提议 4.3BSD 发行同时包含两套实现让用户自选；（5）DARPA 决策——DARPA 认为发行两套代码库会导致互操作性问题（McKusick 1999 原文“releasing two code bases would lead to unnecessary interoperability problems”），决定只发布一套实现，将两套代码交予 BRL（Ballistics Research Laboratory，美国陆军弹道研究实验室）的 Mike Muuss 作为伯克利与 BBN 双方均认可的独立第三方评估（McKusick 1999 原文“an independent third party”，注：McKusick 1999 原文拼写为“Mike Muuse”单 s，按 0 信任原则以 Muuss 本人 ARL 主页署名“Mike Muuss”双 s 为准，McKusick 1999 的“Mike Muuse”系拼写错误）；（6）Muuss 评估结论——Muuss 经过约一个月评估后提交报告（McKusick 1999 原文“After a month of evaluation, the report came back”）：伯克利代码效率更高（throughput 更优，McKusick 1999 原文“the Berkeley code was more efficient”）、BBN 代码拥塞控制更好（congestion control 更优，McKusick 1999 原文“the BBN code handled congestion better”），最终决定性因素（tie breaker）：伯克利代码在所有测试中无错运行，BBN 代码在部分压力测试下 panic（McKusick 1999 原文“the Berkeley code flawlessly ran all the tests while the BBN code panicked under some stress conditions”）；（7）DARPA 最终决策——4.3BSD 保留伯克利代码库，Karels 整合 BBN 代码中的优秀思想（包括更好的拥塞控制算法），4.3BSD 因此延期至 1986 年 6 ## 32.1.3 FFS 文件系统的引入
- 要点：4.2BSD 引入 Fast File System（FFS，又称 Berkeley Fast File System），由 Marshall Kirk McKusick 主导实现（论文作者为 McKusick、William N. Joy、Samuel J. Leffler、Robert S. Fabry 四人），采用柱面组（cylinder group）、4KB/8KB 大块、旋转优化、可配置碎片（fragment）等设计，吞吐量较原始 UNIX 文件系统显著提升（McKusick 等 1984 论文原文记载性能提升约 10 倍，不同硬件配置下基准测试结果有差异）；FFS 原型于 1982 年 6 月集成入 4.1b 供伯克利本地开发使用，1983 年 8 月随 4.2BSD 正式发布；论文于 1984 年 8 月发表于 ACM Transactions on Computer Systems Vol. 2 No. 3 pp. 181-197（DOI: 10.1145/989.990），晚于代码发布约一年；FFS 成为 BSD 标准文件系统，其设计思想影响了后续 ext2/ext3/ext4、UFS/UFS2 等众多文件系统
- 史料：McKusick, M. K., Joy, W. N., Leffler, S. J., Fabry, R. S. (1984) “A Fast File System for UNIX”, ACM Transactions on Computer Systems, Vol. 2 No. 3, pp. 181-197, Published: 01 August 1984（经 ACM Digital Library 原页面确认出版日期为 1984-08-01），DOI: 10.1145/989.990，ACM Digital Library URL: https://dl.acm.org/doi/10.1145/989.990；4.2BSD FFS 原始实现代码归档——TUHS 4.2BSD 内核源代码目录（URL: https://www.tuhs.org/cgi-bin/utree.pl?file=4.2BSD/usr/src/sys/sys）含 FFS 核心实现文件 12 个 ufs_*.c 源文件：ufs_alloc.c（1983-09-28，块分配，含柱面组分配逻辑）、ufs_bio.c（1983-07-29，缓冲区 I/O）、ufs_bmap.c（1983-07-29，块映射）、ufs_dsort.c（1983-07-29，磁盘排序）、ufs_fio.c（1983-07-29，文件 I/O）、ufs_inode.c（1983-07-29，索引节点管理）、ufs_mount.c（1983-07-29，文件系统挂载）、ufs_nami.c（1983-09-25，路径名查找）、ufs_subr.c（1983-07-29，子程序）、ufs_syscalls.c（1983-10-02，系统调用实现）、ufs_tables.c（1983-07-29，表数据）、ufs_xxx.c（1983-07-29，杂项）；FFS 头文件归档——TUHS 4.2BSD 内核头文件目录（URL: https://www.tuhs.org/cgi-bin/utree.pl?file=4.2BSD/usr/src/sys/h）含 FFS 相关头文件：fs.h（14413 字节，1983-07-29，超级块与柱面组结构定义）、inode.h（4938 字节，1983-07-29，内存中索引节点结构）、dir.h（3014 字节，1983-07-29，目录项结构）、quota.h（4891 字节，1983-07-29，磁盘配额结构）；4.1b 磁带原始存档可查 CSRG Archives（http://www.mckusick.com/csrg/）与 Bancroft Library BSD Records (CU-551) Subseries 2 “4.2 BSD”（1982-1985，Carton 2）；McKusick 1999“Twenty Years of Berkeley Unix”（记载 4.1b 1982.6 集成 FFS 原型）；4.2BSD Release Notes (1983.8) ［A］
- 史观：第 9 条经验优先——FFS 的设计源于实际磁盘性能优化需求，而非文件系统理论；柱面组与旋转优化是针对当时磁盘硬件特性的典型工程优化
- 辨析：FFS 论文作者为四人合著（McKusick/Joy/Leffler/Fabry），非 McKusick 单人设计；FFS 原型集成于 4.1b（1982.6），正式随 4.2BSD（1983.8）发布，论文 1984 年发表于 ACM TOCS 期刊而非 USENIX 会议；FFS 与原始 UNIX 文件系统的关系并非完全取代，而是保留 inode 模型与目录结构，仅替换块分配策略；性能提升“约 10 倍”数据出自 McKusick 等 1984 论文原始基准测试，不同硬件配置下结果有差异，引用时应注明出处
- 文献：McKusick, M. K., Joy, W. N., Leffler, S. J., Fabry, R. S. (1984) “A Fast File System for UNIX”, ACM Transactions on Computer Systems, Vol. 2 No. 3, pp. 181-197. DOI: 10.1145/989.990；McKusick, K. (1999) “Twenty Years of Berkeley Unix”（Open Sources 第 1 章）；4.2BSD Release Notes (1983.8)；4.2BSD FFS 源代码 ［A］

## 32.1.4 socket 接口的设计
- 要点：4.2BSD 引入的 socket API 由 Bill Joy 与 Sam Leffler 共同设计（BSD 端 socket 层作者与 TCP/IP 协议栈作者一致，McKusick 1999 记载 Joy 1981 年夏实现 IPC 原型、Leffler 后续完善），socket 作为 IPC 与网络通信的统一抽象支持 TCP/UDP/UNIX 域等多种协议族（AF_INET、AF_UNIX 等），成为 BSD 网络编程的标准 API，后续被 POSIX 标准化为 POSIX sockets 并被 Windows Winsock 等效借鉴；socket API 将网络端点抽象为文件描述符（file descriptor），遵循 UNIX“一切皆文件”哲学，统一了 read/write/close 等 I/O 接口
- 史料：socket API 设计文档、4.2BSD 网络编程手册、Joy/Leffler 的设计笔记、Leffler et al. (1983) “4.2BSD Networking Implementation Notes”第 6.1 节“Socket layer”、McKusick 1999“Twenty Years of Berkeley Unix”（记载 Joy 1981 年夏实现 IPC 原型）、Stevens 1990s《UNIX Network Programming》对 socket API 历史的记述 ［A］
- 史观：第 9 条经验优先——socket 接口设计源于实际网络编程需求，成为后续 POSIX 标准的基础；将网络通信抽象为文件 I/O 是 UNIX 哲学的典型体现
- 辨析：socket 接口是否受 Xerox NS 协议影响存在争议——BSD socket 设计文献未明确引用 Xerox NS 的“endpoint”概念，但 BSD 对协议族（address family）的抽象与 NS 协议栈有结构相似性；socket API 作者为 Joy 与 Leffler 共同设计，“由 Joy 设计”的不完整表述应改为“由 Joy 与 Leffler 共同设计”（McKusick 1999 记载 Joy 实现原型、Leffler 与 Joy 共同完善）；原引用的 metaphorex.org 站点经核查无法访问，已移除该不可靠来源
