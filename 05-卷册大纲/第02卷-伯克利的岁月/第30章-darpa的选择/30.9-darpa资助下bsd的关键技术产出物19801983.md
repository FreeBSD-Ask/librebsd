## 30.9.1 快速文件系统（FFS/Berkeley Fast File System）

**要点**：快速文件系统（Fast File System, FFS）由 Marshall Kirk McKusick 设计实现，1982 年 6 月集成入 4.1b，随 4.2BSD（1983 年 8 月）正式发布；FFS 将文件系统吞吐量提升至接近磁盘硬件上限，引入柱面组（cylinder groups）、块分段（block fragmentation）、长文件名（255 字符）、符号链接（symbolic links）等创新，成为其后四十年间绝大多数 UNIX 文件系统（包括 ext2/ext3/ext4、UFS/UFS2）的设计原型；FFS 论文由 McKusick、Joy、Leffler、Fabry 四人合著，1984 年发表于 ACM TOCS

**史料**：McKusick et al. (1984) FFS 论文、4.2BSD Release Notes、McKusick 1999 叙述 ［B］

**史观**：第 7 条硬件与软件辩证——FFS 的设计源于对磁盘硬件几何特性（柱面、磁道、旋转延迟）的深入理解，软件设计适配硬件特性是性能突破的关键

**辨析**：FFS 首次随 4.2BSD 正式发布（1983.8），但开发与集成工作在 4.1b（1982.6）即已完成；McKusick 1984 论文晚于实际发布约一年；[2026-08-14 两库核查：经参考文献库验证通过（reference_id=20，McKusick, Joy, Leffler, Fabry 1984 “A Fast File System for UNIX”，ACM Transactions on Computer Systems 2(3):181-197，DOI 10.1145/989.990，作者四人合著与本节一致）]

**文献**：McKusick, M. K., Joy, W. N., Leffler, S. J., Fabry, R. S. (1984) “A Fast File System for UNIX”, ACM Transactions on Computer Systems 2(3): 181-197, DOI: 10.1145/989.990；4.2BSD Release Notes (1983.8) ［B］

## 30.9.2 TCP/IP 协议栈（4.1a→4.2BSD）

**要点**：BSD TCP/IP 协议栈起源于 BBN 的 Rob Gurwitz 交付的早期原型，经 Bill Joy 与 Sam Leffler 在 4.1a（1982.4）中集成、调优与架构重构（支持多协议并行），随 4.2BSD（1983.8）正式发布；4.3BSD（1986.6）前经历 BBN 代码争议，经 DARPA 独立测试后确认 Berkeley 实现更稳定高效而保留；BSD TCP/IP 是互联网的事实参考实现，其套接字 API（socket interface）成为网络编程的工业标准，被包括 Microsoft Windows 在内的几乎所有操作系统采纳

**史料**：4.1a/4.2BSD/4.3BSD Release Notes、McKusick 1999 叙述、Leffler et al. 1989 4.3BSD 设计书 ［B］

**史观**：第 4 条分离与聚合——BBN 的初始原型与 Berkeley 的重构实践最终聚合为 BSD TCP/IP 的统一参考实现，成为互联网基础设施

**辨析**：BSD TCP/IP 并非 Joy “从零开始完全重写”，而是基于 BBN 早期原型进行深度集成、调优与架构重构；4.2BSD 的 TCP/IP 已是经过大幅修改的版本，与 BBN 原始原型差异显著

**文献**：Leffler, S. J., McKusick, M. K., Karels, M. J., Quarterman, J. S. (1989) "The Design and Implementation of the 4.3BSD UNIX Operating System“, Addison-Wesley, ISBN 0-201-06196-1；Comer, D. E. (1988) ”Internetworking with TCP/IP", Prentice-Hall ［B］

## 30.9.3 sendmail（从 delivermail 到 sendmail）

**要点**：sendmail 的前身 delivermail 由 Eric Allman 编写，随 4BSD（1980.10）首次发布（McKusick 1999 记载 4BSD 包含 “an enhanced mail handling system” 即 delivermail）；Allman 随后将其重写为 sendmail，4.2BSD（1983.8）正式包含 sendmail；sendmail 是互联网最早也是最广泛部署的邮件传输代理（MTA），其配置规则与路由逻辑定义了早期互联网邮件的传输范式

**史观**：第 2 条实践先于理论——sendmail 的设计源于跨网络邮件路由的实际工程需求，而非先验的邮件传输理论

**辨析**：delivermail 是 4BSD（1980）中的初始版本，sendmail 作为其重写版在 4.2BSD（1983.8）正式发布；sendmail 在 4.1c（1983.4）预览版中可能已包含但未广泛分发；Costales & Allman (1993) 是 sendmail 权威专著，ISBN 1-56592-056-5 为 O'Reilly 第一版正确 ISBN；[2026-08-14 两库核查：经参考文献库验证通过（reference_id=1156，Allman 1983 Sendmail；reference_id=1550，Allman 1994 SENDMAIL Installation and Operation Guide），另邮件库 usenet 1983-1984 年 comp.unix.wizards 帖（Message-ID 1872@sri-arpa.UUCP、16353@sri-arpa.UUCP）显示 Eric Allman（eric@UCBARPA）在伯克利从事 sendmail/syslog 工作，佐证其作者身份]

## 30.9.4 BIND（Berkeley Internet Name Domain）

**要点**：BIND（Berkeley Internet Name Domain）DNS 服务器最初由 Douglas Terry、Mark Painter、David Riggle、Songnian Zhou 四位伯克利研究生在 DARPA 资助下作为学生项目开发；Ralph Campbell 参与后续工作；DEC 工程师 Kevin Dunlap 于 1985-1987 年借调至 CSRG 对 BIND 进行了为期两年的重大重写，贡献者包括 Doug Kingston、Craig Partridge、BBN 的 David Waitzman、Smoot Carl-Mitchell、Mike Muus、Jim Bloom、Mike Schwartz 等；BIND 4.8.3 及之前版本由 CSRG 维护，之后由 Mike Karels、O. Kure 维护，后由 DEC 的 Paul Vixie 接手；Paul Vixie 于 1994 年与 Rick Adams、Carl Malamud 共同创立 ISC（Internet Systems Consortium）作为 BIND 开发维护的机构；BIND 是互联网上使用最广泛的 DNS 服务器软件

**史料**：ISC 官方 BIND 历史页面（<https://www.isc.org/bindhistory>）、4.3BSD Release Notes、McKusick 1999 叙述 ［B］

**史观**：第 11 条国家政策——DARPA 资助的 DNS 实现成为互联网核心基础设施的关键组件，国家资助研究塑造了互联网技术栈；第 4 条分离与聚合——学生项目、DEC 借调工程师、ISC 机构化维护的聚合使 BIND 从学术原型演进为互联网基础设施

**辨析**：BIND 早期版本（至 4.8.3）在 CSRG 维护期间随 BSD 发布，4.3BSD（1986.6）包含 BIND，但 BIND 开发本身始于 4.3BSD 之前的 1980 年代早中期；Kevin Dunlap 1985-1987 年的重写是 BIND 从学生项目走向成熟软件的关键转折点，先前多数叙事遗漏了这一重要史实；[2026-08-14 两库核查：参考文献库 tech “BIND” 仅命中 ypbind（NIS），未命中 BIND DNS 服务器条目，邮件库 usenet 1981- 无 BIND 早期开发记录，BIND 学生项目（Terry/Painter/Riggle/Zhou）与 Dunlap 重写两库无法验证]

## 30.9.5 套接字 API（socket interface）与 Berkeley r-commands

**要点**：套接字 API（**socket(2)**、**bind(2)**、**listen(2)**、**connect(2)**、**accept(2)** 等）由 Bill Joy 与 Sam Leffler 在 4.1a/4.2BSD 开发期间设计实现，随 **4.2BSD**（**1983.8**）正式发布，成为网络编程的事实标准接口；同期开发的 Berkeley r-commands（`rsh`、`rlogin`、`rcp`、`rwho` 等）提供了基于可信主机的早期远程访问工具，前缀 “r” 表示 “remote”

| r-command | 全称 | 功能 | 后续替代 |
| ------- | -- | -- | ------ |
| rsh | remote shell | 远程执行命令 | SSH（ssh） |
| rlogin | remote login | 远程登录 | SSH（ssh） |
| rcp | remote copy | 远程文件复制 | SCP/SFTP |
| rwho | remote who | 远程用户列表 | — |

**史料**：4.2BSD Release Notes、4.2BSD 系统调用手册页 ［A］

**史观**：第 17 条软件工程——套接字 API 的设计定义了网络编程的抽象范式，其接口简洁性与通用性是其被广泛采纳的关键

**辨析**：套接字 API 的设计借鉴了同期其他系统的网络 API（如 XNS、TCP/IP），但 Berkeley 版本是首个被广泛采用的实现；r-commands 因安全性问题（基于 IP 地址认证而非加密）后来被 SSH 替代

**文献**：4.2BSD Manual Pages (1983.8)；Stevens, W. R. (1990) “UNIX Network Programming”, Prentice-Hall, ISBN 0-13-949876-1［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 30.9.6 4.2BSD 的商业采用与市场主导地位（1983-1986）

**要点**：4.2BSD 于 1983 年 8 月发布后商业采用速度空前——18 个月内颁发超过 1,000 份站点许可证，超过先前所有 BSD 分发版本的总和；绝大多数 UNIX 厂商选择搭载 4.2BSD 而非 AT&T System V，原因是 System V 当时既无网络支持也无快速文件系统（FFS）；BSD 的市场主导地位仅持续数年，当 System V 集成网络与 FFS 后多数厂商回归 System V，但 4.2BSD 的大量创新（TCP/IP、套接字、FFS、可靠信号等）被整合进 System V 并成为 POSIX 标准基础；统计结论 [C-41] references 表总数 16,867 条，[C-42] 年份提取率 44.42%（7,493/16,867），CSRG 时期 1969-1995 年累计 1,879 条占比 25.08%，[C-03] freebsd-src 总 commit 数 444,203 作为 4.2BSD 谱系延续至现代 FreeBSD 的代码规模参照，反映 DARPA 资助下 BSD 谱系的长期工程产出规模
