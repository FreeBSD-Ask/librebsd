# 033.9.6 4.2BSD 的商业采用与市场主导地位（1983-1986）

**要点**：4.2BSD 于 1983 年 8 月发布后商业采用速度空前——18 个月内颁发超过 1,000 份站点许可证，超过先前所有 BSD 分发版本的总和；绝大多数 UNIX 厂商选择搭载 4.2BSD 而非 AT&T System V，原因是 System V 当时既无网络支持也无快速文件系统（FFS）；BSD 的市场主导地位仅持续数年，当 System V 集成网络与 FFS 后多数厂商回归 System V，但 4.2BSD 的大量创新（TCP/IP、套接字、FFS、可靠信号等）被整合进 System V 并成为 POSIX 标准基础；统计结论 [C-41] references 表总数 16,867 条，[C-42] 年份提取率 44.42%（7,493/16,867），CSRG 时期 1969-1995 年累计 1,879 条占比 25.08%，[C-03] freebsd-src 总 commit 数 444,203 作为 4.2BSD 谱系延续至现代 FreeBSD 的代码规模参照，反映 DARPA 资助下 BSD 谱系的长期工程产出规模

**史料**：McKusick “Twenty Years of Berkeley Unix”（1999，当事人一手叙述，明确记载 1000+ 许可证与厂商选择 4.2BSD 的原因）、4.2BSD Release Notes、Quarterman et al. 1985 ACM Computing Surveys；资料数据库.duckdb 文献计量学统计（C-41、C-42）——references 表总数 16,867 条，年份提取率 44.42%（7,493/16,867，正则 `\b(1[89]\d{2}|20[0-2]\d)\b` 提取自 `gbt7714` 字段），CSRG 时期 1969-1995 年累计 1,879 条占比 25.08%，反映 DARPA 资助下 BSD 谱系在文献积累中的整体权重；freebsd.duckdb 数据库统计（C-03）——freebsd-src 总 commit 数 444,203，SQL 查询 `SELECT COUNT(*) FROM commits WHERE repo_name='freebsd-src'`，作为 4.2BSD→FreeBSD 谱系代码规模的现代参照；查询日期 2026-07-27；Python 脚本 `script/phase6_bibliometrics.py` Task 22 与 `script/phase1_descriptive.py` SubTask 2.1，执行日期 2026-07-27 ［B］

**史观**：第 11 条国家政策——DARPA 资助产生的 4.2BSD 凭借技术优势（网络+FFS）短暂主导 UNIX 商业市场，证明国家资助研究可以产出商业竞争力强的技术；第 4 条分离与聚合——BSD 创新最终聚合入 System V 与 POSIX 标准，学术研究产出通过商业渠道扩散为工业标准；统计结论印证——references 表 CSRG 时期 25.08% 占比与 freebsd-src 444,203 commits 反映 DARPA 资助决策催生的 BSD 谱系在文献与代码层面的长期工程产出，与项目史观总纲第 4 条 “分离聚合是永恒规律” 映射：4.2BSD 的创新从伯克利分离后聚合入 System V、POSIX 标准与现代 FreeBSD 谱系

**辨析**：4.2BSD 的市场主导期约为 1983-1986 年（4.3BSD 发布前后），并非长期垄断；McKusick 1999 原文为 "within eighteen months more than 1,000 site licenses had been issued. Thus, more copies of 4.2BSD had been shipped than of all the previous Berkeley software distributions combined."；**统计局限性标注**——references 表 16,867 条中仅 7,493 条（44.42%）成功提取年份，55.58% 文献无年份信息，CSRG 时期 25.08% 占比基于有年份记录计算，存在选择性偏差；netbsd.duckdb 最早 commit 为 1992-07-13（netbsd-src）与 1993-06-12（freebsd-src），4.2BSD 时期（1983-1986）无 commit 数据，freebsd-src 444,203 commits 为 1993-06 起的现代统计而非 4.2BSD 时期实时数据，统计结论限于文献计量学与现代代码累积规模参照，不可外推至 1983-1986 年代码活跃度；统计显著 ≠ 实际显著，25.08% 占比反映本书参考文献中明确标注 CSRG 时期出版的比例，不等于 1969-1995 年实际学术产出强度；0 信任原则适用——`gbt7714` 字段为自由文本，年份正则可能误匹配 ISBN、页码、卷号中的数字（残余风险存在）；多重比较风险——第二卷共 15 章跨章引用相同 SQL 查询时存在多重比较风险，按 Bonferroni 校正后解读

文件系统概念演化大体历经：①顺序/平坦期（1950–1960s）：磁带顺序访问与早期磁盘平面目录；②层次化突破（1960s–1970s）：Multics（始于 1965）首创树状文件目录与路径名，Unix（1970s）以 inode 架构、挂载点、“一切皆文件”简明化并推广层次文件系统；③性能重构期（1980s）：Marshall Kirk McKusick 等为 4.2BSD 设计 Fast File System（FFS/现称 UFS1，1982 年写出、随 4.2BSD 发行），引入柱面组、碎片、软更新，UFS2（2002–2003）改用 64 位块指针扩展至多 TB；④网络化期：Sun Microsystems 1984 年推出网络文件系统 NFS，确立 VFS/vnode 接口；⑤存储与纠错集成期：如 ZFS（2001–2006）将文件系统与卷管理、写时拷贝、校验和集成。

Capsicum 源自剑桥大学计算机实验室 Robert N.M. Watson 与 Jonathan Anderson 的 TrustedBSD 研究项目，受 Google、FreeBSD 基金会与 DARPA 资助。2010 年 12 月 USENIX ;login 刊发《introducing Capsicum: practical capabilities for UNIX》正式公开。原型在 FreeBSD 8.x 开发，2011 年起作为实验特性随 FreeBSD 9.0 提供。其思想可上溯至 Dennis 与 Van Horn 1966 年的 capability 理论。2013 年 Google 与 FreeBSD 基金会联合资助 Pawel Jakub Dawidek 整合改进 API 并开发 Casper 后台服务，Casper 自 FreeBSD 10.1 起提供并用于 tcpdump、kdump 等组件。此后持续移植到 Linux、DragonFlyBSD 等。

GEOM 由 Poul-Henning Kamp 提出构想（早期思想文《Geometry —— an idea》），最原始前身是作者对 Minix 1.2 所做的一个从未发布的 hack。2002 年 Kamp 在 NAI Labs 支持下，于 DARPA/SPAWAR 合同与 DARPA CHATS 研究计划框架内开发成形。2003 年 Kamp 在 BSDCon 发表 GEOM 教程。GEOM 自 FreeBSD 5.0（2003）起提供，明确定义 class/geom/provider/consumer/rank 等拓扑概念，提供分区（FDISK/MBR、GPT、BSD slice）、镜像（geom_mirror）、RAID、UFS 卷标、GBDE/geli 磁盘加密等类，并支持 ggate 用户态网关。至 FreeBSD 13.0，GEOM_BSD、GEOM_MBR、GEOM_SUNLABEL 等过时组件被移除，由 GEOM_PART_* 与 GEOM_LABEL 等替代，框架持续演化。
