# 31.2 虚拟内存管理的实现细节

## 31.2.1 虚拟内存的架构设计

**要点**：3BSD 在 VAX 上实现请求调页式虚拟内存，利用 VAX 硬件的页表与 TLB 支持，使进程拥有独立虚拟地址空间，超越 32V 的简单换页机制；3BSD 虚拟内存的核心设计——请求调页（demand paging）+ 全局 CLOCK 页面置换策略（LRU 近似）+ working set 风格的多道程序度控制，由 Özalp Babaoğlu（厄扎尔普·巴巴奥卢） 主导设计实现、Bill Joy 协助内核集成调试；针对 VAX-11/780 硬件缺乏 reference bit（页引用位）的限制，采用软件检测方案克服，性能开销相对较小；3BSD 内核镜像命名为 `/vmunix`（virtual memory UNIX），此命名延续至 4.4BSD

**史料**：3BSD 虚拟内存源代码（`/sys/vmsystm.c`、`/sys/vm_page.c` 等内核文件）；VAX 硬件手册（DEC VAX-11/780 Hardware User's Guide）；Babaoğlu 博士论文（UCB/ERL M81/92, 1981-11-17，导师 Domenico Ferrari，URL: <https://www2.eecs.berkeley.edu/Pubs/TechRpts/1981/7560.html，PDF>: <https://digicoll.lib.berkeley.edu/record/134368/files/ERL-m-81-92.pdf）；Babaoğlu> & Joy SOSP '81 会议论文（"Converting a swap-based system to do paging in an architecture lacking page-referenced bits", SOSP ’81 Proceedings, pp. 78-86, 1981-12-01, DOI: 10.1145/800216.806595）；Babaoğlu, Joy & Porcar 设计论文（"Design and Implementation of the Berkeley Virtual Memory Extensions to the UNIX Operating System"，Berkeley CS 技术报告，确切编号经考据确认：该文发表于 ASPLOS-I（1982.3）【考据完成：2026-08-02】，PDF: <http://roguelife.org/~fujita/COOKIES/HISTORY/3BSD/design.pdf）［A］>

**史观**：第 7 条硬件与软件辩证——VAX 的硬件虚拟内存支持使 3BSD 的虚拟内存实现成为可能，硬件能力决定软件设计空间；第 17 条软件工程——Babaoğlu 针对 VAX 缺乏 reference bit 的硬件限制设计软件检测方案，是软硬件协同工程的典型案例

**要点**：

- Bryan Cantrill 指出 POSIX 将 madv_dontneed 定义为“近期不再使用此内存”的建议，FreeBSD 与 illumos 将其实现为纯粹的页面置换优先级建议并保留映射，Linux 却将其实现为立即撕毁映射并保证再次访问读到全零，语义与所有其他 Unix 截然不同；Joyent 团队严格按建议语义实现该调用后，依赖 Linux 破坏性语义的 jemalloc（随 Facebook 代码引入）在生产环境于调用栈深处离奇崩溃，且因无帧指针而难以取得栈回溯，排查极为艰难。他还以 mmap 为例说明“撕毁映射要击落 TLB、改写页表”的真实开销，批评依赖未经度量的直觉判断系统性能。（BSD Now EP117，[3446.14-3786.44]，L1）
- Cantrill 阐明 BSD、illumos 与 Linux 对“操作系统”边界的定义分歧：前二者视操作系统为内核、用户态与系统工具的整体，ls 亦属操作系统；Linux 则只是内核，GNU 栈与 glibc 皆属发行版层面，这也解释了 GNU 与 Linux 之争的根源。正因 Linux 将 ABI 僵化地锚定在系统调用层且极不情愿破坏任何应用，SmartOS 得以在 LX 品牌化区域中完整实现 Linux 系统调用表使 Linux 二进制直接运行；该机制原为 Sun 所创、因当年 Linux 演进过快而封存，2014 年由社区成员在区域内跑通 Linux 版 Skype 而意外复活，此后经 2014 至 2015 年推向完成。（BSD Now EP117，[2111.92-2333.50]，L1）
- Cantrill 以航空安全作类比主张事后调试是可靠软件的基石：软件失败时必须留存状态快照，如同驾驶舱语音记录器与飞行数据记录器之于法航 AF447 事故——直到找到记录器才确认空速管结冰与人为失误；拒绝取证如同在被连环杀手肆虐的城市里宣布关闭太平间。他进而批评 Linus Torvalds 约 2001 年表达过的“使系统可调试会让开发者变软”的立场，认为技术者负有尽最大努力构造可靠系统的社会责任，拒绝为此提供机制的态度在伦理上不可接受。（BSD Now EP117，[5215.96-5305.30]，L1）

**史料**：

- 本期可供考据的一手与二手史料包括：Cantrill 对 Joyent 生产环境中 kmem magazine 遍历故障的 DTrace 取证与崩溃转储分析（单次转储达 310 万缓冲区）、其亲历的 Sun 时代 NSE 与 Teamware 及 Larry McVoy 的 NSE Lite 与 BitKeeper 谱系自述、Jeff Bonwick 的 slab 分配器与 2001 年 magazine 层论文、James Mickens 在 LISA 2015 的演讲（将 Git 比作“作为一种服务的《死亡幻觉》，一部关于时间旅行与平行维度的混乱电影”）、Peter Hessler 于 2015 年 11 月 16 至 20 日在布加勒斯特 RIPE 会议的 OpenBGPD 状态报告（OpenNTPD 全项目生命周期零 CVE、导入 56.1 万条规则耗时从 35 分钟降至 30 秒）、Siju George 发表于 BSDMag.org 的 DragonFly BSD 生产使用自述、Larry Cafiero 在 FossForce 上陈述因社区态度而非技术原因转向 BSD 的文章、ACMQ 对 Robert Watson 的 Capsicum 专访视频，以及 FreeBSD Mastery: ZFS（与 Michael Lucas 合著）的读者书评。（BSD Now EP117，[4494.20-4641.90]，L2）

**史观**：

- 总纲10 动手者创造历史：Cantrill 叙述其通过删除代码完成的罕见系统改进：SmartOS 低内存时的 kmem 迁移逻辑会在持有锁的状态下“狩猎”magazine 层数以百万计的缓冲区，使系统陷入无法观测的停顿，统计工具本身亦被锁死；他判定该逻辑与低内存场景自相矛盾而整体删除，diff 全为减号、未新增一条指令，并主张内核函数名中永远不应出现 hunt 之类动词，还要为此补写注释说明为何不再如此。系统史由动手者以手术刀式的删除书写，而非仅由宏大的架构图书写。（BSD Now EP117，[1823.68-1876.66]，L1）
- 总纲21 革命与改革是历史方法论的分歧：Cantrill 断言“Linux 不是被设计的，它是演化的”，任何形似整体设计之物都会激起社区的免疫反应，而 ZFS、DTrace、容器与安全这类复杂构造无法靠演化抵达，必须有人重新思考整体并获准整合大型成果；FreeBSD 与 illumos 的价值恰在于允许这种整体性设计着陆，优秀想法还能在共享价值观的系统间交叉授粉。他将自由软件内部的路线之争表述为革命性整体设计与渐进演化两种历史方法论的分歧，并归因于 Linux 缺乏承担架构方向的责任结构、无人为设定架构方向负责。（BSD Now EP117，[4133.02-4236.92]，L1）
- 总纲15 文化即形式主义：Cantrill 力陈命名即软件的基石而非琐碎细节：名字将被未来世代用于理解、扩展既有设计并判断其做法是否恰当，命名失当如同基石被掀翻在街心，是系统沦为贫民窟、无法起造摩天楼的根源。他举 DNF 包管理器连作者本人都拒答缩写含义、systemd 与 libsystemd 以库之名封装守护进程且边界无限扩张、KVM 之名与机房键盘视频鼠标切换器相冲撞为例，指出命名混乱会迫使真正理解系统的善意聪明人自我怀疑；命名之争的僵局往往暗示存在尚未被想到的第三方案。（BSD Now EP117，[2781.72-2809.82]，L1）

**辨析**：

- 两处关键论断需存疑处理：其一，Cantrill 现场推断 madv_dontneed 的破坏性语义源自 Digital UNIX 与 Tru64，称之为某位“善意的蠢货”添入，属未附提交记录与邮件列表文本的口头归因；其二，他转述 Linus Torvalds 约 2001 年的檄文称“让系统可调试会使开发者软弱”，为二手引述且年份与原文措辞未经核证。节目本身为双音轨交错转写，存在专名失真。 [存疑脚注] Digital UNIX/Tru64 归因系嘉宾现场推断，未见内核提交或邮件列表原文核证；Torvalds 2001 年言论为转述，未核对原始文本；转写存在专名失真，如 Mav donate 应为 madv_dontneed、Lumos/Alumo 应为 illumos、Bonweck 应为 Bonwick、Tridgel 应为 Tridgell。（BSD Now EP117，[3898.60-3924.92]，L4）
