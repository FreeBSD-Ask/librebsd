# 第 39 章 Bostic 发起重写 AT&T 代码运动

## 要点

- 重写运动的目标为：移除所有 AT&T 衍生代码，使 BSD 在 BSD 许可证下完全自由发布；策略为：逐文件核对版权、优先重写用户工具（法律风险低）、保留内核代码原貌（法律风险高）、社区志愿重写、CSRG 审查合并，1991 年 Net/2 实现目标
- Net/2 的历史意义：首个完全自由的 BSD 完整代码发布、为 386BSD（1992）与后续 FreeBSD/NetBSD（1993）提供基础、为 Linux 早期发展提供对比与刺激、触发 USL v. BSDi 诉讼（1992）、最终通过和解确认 BSD 完全自由地位
- 社区贡献者的历史意义：展示开源协作方法论在 1989-1991 年的可行性、为后续 FreeBSD/NetBSD 社区协作奠基、展示 BSD 社区的凝聚力、为 1998 年“开源”概念提供历史先例，社区贡献者集体劳动是 Net/2 成功的关键
- 法律风险预判的后续影响包括：1992-1994 年 USL 诉讼中 CSRG 文件保留政策提供关键证据、1994 年和解后 Net/2 法律地位确认、1994 年后 4.4BSD-Lite 完全自由发布、为后续 FreeBSD/NetBSD/OpenBSD 提供法律安全保障
- Net/2 发行渠道的历史意义包括：① **首次完全自由 BSD 完整代码的正式发行**——Net/2 是首个不含 AT&T 专有代码（除 6 个争议文件外）的 BSD 完整代码发行，标志着 BSD 从“AT&T 混合版权”向“完全自由 BSD 许可证”演化的关键节点；② **多渠道分发模式的奠基**——Net/2 通过 CSRG 直接销售、UUNET 匿名 FTP、386/BSD 自由再分发、BSDi 商业发行等多渠道并行，为后续 FreeBSD/NetBSD 的发行生态奠定了分发格局

## 史观

Net/2 重写运动的总纲定位：总纲10 动手者创造历史——Bostic 在 USENIX 张榜动员外围无名参与者认领重写，系统摆脱 AT&T 专有代码依赖的过程由社区动手者逐一重写累积而成；总纲13 法律与道德是利益分配——为规避许可证而重写 cat 等基础工具，法律边界直接塑造了代码形态；总纲5 没有必然性，只有偶然性——Linux 的诞生窗口系于 USL 诉讼不确定性这一偶然条件；总纲4 分离聚合是永恒规律——虚拟机抽象层次的钟摆式往返；总纲22 知识注定过时——cat 等微小工具历经五十年累积而非推倒重建。

**要点**：

- 文章追溯 cat 的源码史：Ken Thompson 与 Dennis Ritchie 于 1969 年在 PDP-7 上以汇编实现首版 cat，其中 getc 与 putc 的命名早于 C 标准库。（BSD Now EP273，[1440.78-1605.80]，L2）
- cat 的 C 实现迟至第七版 UNIX 才出现，4BSD 增加了一组沿用至今的命令行标志；最终由 Kevin Fall 在 1989 年为 Net/2 完成最后一次重写。（BSD Now EP273，[1651.48-1837.74]，L2）
- CSRG 将仍含 AT&T 代码的工具清单贴在墙上，供成员认领重写；Kevin Fall 认领 cat 与 mknod，其 1989 年版本成为 macOS 与 FreeBSD 现行 cat 的近源。（BSD Now EP273，[1800.70-1864.50]，L2）
- Xorg 服务器存在 CVE-2018-14665 提权漏洞，因命令行参数校验不当可覆盖任意文件；de Raadt 批评 X 维护者未提前告知 OpenBSD，致 6.4 发布即受波及。（BSD Now EP273，[2293.74-2489.74]，L2）
- McKusick 以当事人视角浓缩 BSD 全史：Ken Thompson 身为伯克利校友，1975 年学术休假时把 UNIX 带回校园，一年内吸引了一批研究生；1976 年他离开时 Bill Joy 已接管系统并继续开发，随后把伯克利开发的软件打包，以 Berkeley Software Distributions 之名发行，年度发行延续近十五年，先后由 Joy 与包括 McKusick 本人在内的后来者主持；1980 年代末自由再分发软件的兴趣渐起，伯克利同人着手把 AT&T 专有部分从 BSD 中剥离，到伯克利的最终发行版（转写作 1992 年）整个发行已可自由再分发；此后两支力量接续支撑 BSD——NetBSD 以支持尽可能多的硬件架构为目标，从微波炉到 Cray XMP 皆在其列，其口述时点已支持近六十种架构，FreeBSD 则以在 PC 架构上运行 BSD、支持尽可能广的设备并把系统做得尽量易装以吸引广大开发者为目标；他本人选择主要跟随 FreeBSD 群体，一面做软件，一面与 George Neville-Neil 合著 The Design and Implementation of the FreeBSD Operating System。（YouTube EPnwbqBdghh6E，[39.2-169.9]，L1）
- McKusick 叙述 UNIX 的诞生语境：UNIX 之前的主角是 Multics，由 Honeywell、AT&T 贝尔实验室与 MIT 三方合力建造分时系统，项目愈益宏伟却始终未能进入生产，每学会做一件事便又推倒重构去做下一件；贝尔实验室撤出后，已经习惯坐在 ASR33 电传终端前交互编程的 Ken Thompson 与 Dennis Ritchie 不愿退回打卡片的作业流，从角落里翻出一台废弃的小型机（转写作 PDP-8），写出一个极小的系统即 UNIX，其后迁往 PDP-11；鉴于 Multics 万事求全的教训，两人确立“找出做事的那一种方式”的极简哲学，标识符只保留进程号、用户号与组号寥寥数种，并让同一组标识符兼作计数、保护判定与调度决策之用。[订正：原区间终点 1994.2→1997.41，原终点止于转写“used for counting, used for making”段，“protection decisions, used for scheduling decisions”（保护判定与调度决策）落转写 [1994.2-1997.41] 段，内容复核]（YouTube EPnwbqBdghh6E，[1859.4-1998.3]，L1）[订正：原“（他按读音称 Multix）”——新转写该处为“a thing called Multics”，未见 Multix 读音变体，已删；重锚 [1864.49-1997.41]→[1859.4-1998.3]，内容核符]
- McKusick 把统一描述符空间列为 UNIX 的两大关键观念之一：给定一个描述符即可引用终端、文件、磁盘、管道或套接字等任何 I/O 通道，使用者无须知道它背后是什么便能读写且行为正确；此前各设备各配一套打开、读、写、关闭调用，像 cat 这样的程序必须自行判别输入类型并分派调用，统一之后程序只管读写，新增描述符类型亦不破坏既有程序；他称此后几乎每个操作系统都采纳了这一构造，唯太平洋西北岸一家大公司的系统至今未完全统一，并打趣说 Longhorn 会解决这个问题。（YouTube EPnwbqBdghh6E，[2019.4-2141.5]，L1）
- McKusick 把进程即商品列为另一关键观念：UNIX 之前的系统里进程是重型的贵重资源，IBM MVS 由系统管理员在引导时决定多重处理度数并预先创建定数进程，用户以 JCL 把编译各步写成一叠卡片作业——他称 JCL 是“六十年代的 sendmail 配置文件”，多一个空格或丢一个逗号整个作业即被吐回，且须经操作员换卡重交、等待数小时才能看到结果；UNIX 让这类记账性工作交给机器，按需即时创建进程、以管道相连、用毕即弃——一次编译即把预处理器、多趟编译器、优化器与装载器等七个进程经管道流水串联；他强调这并非进程创建变得廉价（以运行 ls 为例，九成以上成本仍在创建与销毁进程本身），而是省下的编程人力值得付出这份开销；早期内存不足时管道在底层实为文件，今则全在内存中流转。（YouTube EPnwbqBdghh6E，[2190.0-2537.5]，L1）
- Unix 传入伯克利的路径由 Bob Fabry 一人促成：Thompson 与 Ritchie 于 1973 年在 SOSP 报告第四版后，这位伯克利教授主动接触 Thompson，Unix 遂进入伯克利；系里无力独占 PDP-11/45，与数学及统计系各出资三分之一合购，后者坚持运行 DEC 系统并将机器时间切为每日三班轮转，Unix 仅获午夜至八时的时段；这一不可持续的共享安排促使计算机系很快自购 PDP-11/70，Version 6 时期 Thompson 以伯克利校友身份亲自到场安装，并因该机罕见地配有两台 28MB 磁盘而暴露并发访问竞态，由其亲手调试。（YouTube EPbVSXXeiFLgk，[406.51-593.23]，L1）[订正：原 [461.03-557.03]→[406.51-593.23]，内容复核]
- 1978 年伯克利购入第七台 VAX 供运行 Lisp 的 VAXIMA 方程求解项目，而贝尔实验室的 32V 仅是 PDP-11 版的最低限度移植，不使用 VAX 分页硬件且只支持固定数量的进程；Bill Joy 找到以虚拟内存为博士论文方向的 Ozalp Babaoglu，将其分页原型并入 32V，并利用圣诞假期这一全年仅有的独占机时反复迭代，1979 年形成 3BSD——首个包含完整操作系统与库的 BSD 发行；因内嵌大量 AT&T 代码，获取 3BSD 必须持有 AT&T 源码许可，而彼时学生身份的 Joy 兼任发行协调员，许可核验仅凭电话口头询问完成。（YouTube EPbVSXXeiFLgk，[775.03-1071.55]，L1）[订正：原 [775.03-986.15]→[775.03-1071.55]，内容复核]
