# 038.3.5 要点Sun与CSRG的代码共享实为单向取用为主双向回馈有限需精确区分Sun取用B

**要点**：Sun 与 CSRG 的代码共享实为单向取用为主、双向回馈有限，需精确区分 “Sun 取用 BSD 代码” 与 “Sun 回馈 BSD 代码” 两个方向；**Sun 从 CSRG 获取的代码模块**：4.1BSD 内核（虚拟内存、文件系统、进程调度）、4.2BSD 开发版特性（4.1a/4.1b 的 TCP/IP 网络栈、FFS 快速文件系统雏形、IPC 进程间通信），Joy 在 1982 年晚春加入 Sun 后至 1983 年夏季往返于 Sun 与 Berkeley 期间带入 SunOS 1.0；**Sun 回馈 CSRG 的代码模块**：McKusick 1999 明确记载两个关键回馈谈判均未达成——① **虚拟内存系统**：CSRG 在 4.3BSD-Reno 开发期首选 Sun SunOS 的虚拟内存系统，"Although there was some discussion about Sun contributing the code to Berkeley, nothing came of those talks"（虽曾讨论 Sun 向 Berkeley 贡献代码，但谈判无果），CSRG 转而采用卡内基梅隆大学 MACH 操作系统的虚拟内存系统，由犹他大学 Mike Hibler 整合 MACH 核心技术与 4.2BSD 架构手册描述的用户接口（该接口亦为 SunOS 所用）；② **NFS 网络文件系统**：CSRG 在 4.3BSD-Reno 中加入 “Sun-compatible version of the Network Filesystem (NFS)”，但实际 NFS 代码并非由 Sun 贡献，而是由加拿大圭尔夫大学（University of Guelph）Rick Macklem 独立实现，CSRG 仅采用了与 Sun NFS 协议兼容的实现；**代码共享协议条款**：Sun 获取 BSD 代码的依据为 BSD 许可证本身，McKusick 1999 明确记载 BSD 许可证条款——"A licensee could release the code modified or unmodified in source or binary form with no accounting or royalties to Berkeley. The only requirements were that the copyright notices in the source file be left intact and that products that incorporated the code indicate in their documentation that the product contained code from the University of California and its contributors"（被许可方可以源码或二进制形式发布修改或未修改的代码，无需向 Berkeley 报账或支付版税；唯一要求是保留源文件中的版权声明，且使用该代码的产品须在文档中注明包含加州大学及其贡献者的代码），即 Sun 无需单独签订代码共享协议，BSD 许可证本身即授权商业使用与再分发

| 方向 | 代码模块 | 协议依据 | 状态 |
| -- | ------ | ------ | -- |
| CSRG → Sun | 4.1BSD 内核（VM、FS、调度） | BSD 许可证 | 已交付（1982-1983） |
| CSRG → Sun | 4.2BSD 开发版特性（TCP/IP、FFS、IPC） | BSD 许可证 + Joy 双重身份 | 已交付（1982-1983） |
| Sun → CSRG | SunOS 虚拟内存系统 | 谈判未达成 | 未交付（CSRG 改用 MACH） |
| Sun → CSRG | NFS 网络文件系统代码 | 未通过 Sun 贡献 | 未交付（Rick Macklem 独立实现） |

**史料**：McKusick, M. K. (1999) “Twenty Years of Berkeley Unix” O'Reilly Open Sources 官方在线版（CSRG 核心成员当事人一手叙述，逐段核对——关于 Sun VM 谈判无果、NFS 由 Rick Macklem 独立实现、BSD 许可证条款三处关键叙述）；Rick Macklem NFS 实现源代码历史（圭尔夫大学档案）；SunOS 1.0 Release Notes（1983）；4.3BSD-Reno Release Notes（1990） ［A］

**史观**：专题——“Sun 回馈 BSD” 叙事的形式主义简化（不设总纲条号）：将 “Sun 开发了 NFS” 等同于 “Sun 贡献了 NFS 代码给 BSD”，形式逻辑吞并了 “代码实际流向” 的实质；第 10 条动手者创造历史——Rick Macklem（圭尔夫大学）作为 NFS 兼容实现的独立贡献者，其角色常被 “Sun 贡献 NFS” 的叙事边缘化，需在辨析中恢复；第 5 条偶然性——Sun VM 谈判无果是偶然事件，CSRG 转向 MACH 的决定直接塑造了 4.3BSD-Reno 及后续 4.4BSD 的虚拟内存架构，偶然谈判失败影响深远

**辨析**：需精确区分 “协议兼容” 与 “代码贡献”——Sun 开发了 NFS 协议并公开（RFC 1094, 1989），但 BSD 中的 NFS 代码由 Rick Macklem 独立实现，并非 Sun 贡献；需精确区分 “协议开源” 与 “实现开源”——Sun 通过 RFC 公开 NFS 协议规范，但 Sun 的 NFS 参考实现并未开源贡献给 CSRG；需精确区分 “Joy 个人贡献” 与 “Sun 公司贡献”——Joy 在 1982 年晚春加入 Sun 前已是 BSD 核心开发者，其带入 Sun 的 BSD 代码知识是基于其在 CSRG 的工作，而非 Sun 公司对 CSRG 的回馈；“Sun 取用 BSD 代码” 的方向经 McKusick 1999、SunOS 1.0 Release Notes、BSD 许可证条款三重交叉验证确认；“Sun 回馈 CSRG 代码” 的方向经 McKusick 1999 明确记载两个关键回馈（VM、NFS）均未达成，需警惕 “Sun 回馈 BSD” 的简化叙事，此叙事缺乏一手代码贡献记录支持［据一手文献印证消解^doubt-resolved-198：除 VM 与 NFS 外，是否存在 Sun 工程师个人以补丁形式向 CSRG 贡献小量代码（如设备驱动、性能补丁），需核查 CSRG 邮件列表存档与 4.3BSD-Reno/4.4BSD 源代码版权声明中的 Sun 工程师署名］
