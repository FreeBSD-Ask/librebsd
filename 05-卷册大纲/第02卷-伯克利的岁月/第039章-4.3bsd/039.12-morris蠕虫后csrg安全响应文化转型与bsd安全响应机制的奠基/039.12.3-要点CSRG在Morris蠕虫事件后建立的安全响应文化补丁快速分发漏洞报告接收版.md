# 039.12.3 要点CSRG在Morris蠕虫事件后建立的安全响应文化补丁快速分发漏洞报告接收版

**要点**：CSRG 在 Morris 蠕虫事件后建立的安全响应文化——补丁快速分发、漏洞报告接收、版本发布纪律——直接为 1990 年代 FreeBSD、NetBSD、OpenBSD 的安全响应机制奠基；FreeBSD 1.0（1993 年 12 月发布）的安全公告机制即继承自 CSRG 后期的补丁纪律，FreeBSD Security Officer 制度与 FreeBSD 安全公告编号体系（FreeBSD-SA）是 CSRG 补丁分发流程的制度化延续；OpenBSD（1995 年 fork）将 “显式安全审计” 作为项目核心原则，1996 年成立后的全源码审计工程可追溯至 Morris 蠕虫事件后 BSD 社区对安全文化缺失的集体反思；NetBSD 亦建立类似的安全公告机制；这一文化转型是 BSD 前安全史（1969-1992）与 BSD 后安全史（1992 年后四大 BSD CVE 漏洞史）之间的关键过渡

**史料**：FreeBSD 1.0 Release Notes (1993.12) 与 FreeBSD 安全公告档案；NetBSD 0.8/1.0 Release Notes (1993) 与 NetBSD 安全公告档案；OpenBSD fork 公告（1995.10）与 OpenBSD 全源码审计项目记录；CSRG 邮件列表存档中 1988-1992 年间关于安全补丁纪律的讨论；4.4BSD SMM 文档；Salus, P. (1994) “A Quarter Century of UNIX” ［A］

**史观**：第 25 条终结中的延续——CSRG 于 1995 年 6 月 4.4BSD-Lite 2 发布后解散，但其安全响应文化通过 FreeBSD、NetBSD、OpenBSD 的安全公告机制延续；第 5 条偶然性——Morris 蠕虫偶然事件催生的安全响应文化转型，其长期影响（三大 BSD 项目的安全机制）并非 CSRG 的预期，而是多重偶然事件叠加的产物

**辨析**：BSD 安全响应文化对后世 BSD 项目的 “奠基” 须区分 “直接继承” 与 “间接影响”——FreeBSD 安全公告机制直接继承自 CSRG 补丁纪律（FreeBSD 1.0 核心团队包括 CSRG 时期的贡献者），OpenBSD 全源码审计工程间接追溯至蠕虫事件后的集体反思（OpenBSD fork 动机还包括 NetBSD 代码质量问题等因素，须区分 “安全文化延续” 与 “fork 动机多元”）；“BSD 前安全史与 BSD 后安全史的关键过渡” 的叙述须避免线性因果——蠕虫事件是过渡的触发点而非唯一原因，386BSD 安全基线（详见 386BSD 研究底稿）与 4.4BSD-Lite 安全收尾亦为过渡的组成部分；OpenBSD 1996 年全源码审计工程的历史回响须谨慎判断——OpenBSD 的全源码审计是 Theo de Raadt（西奥·德·若特） 个人主导的工程实践，蠕虫事件后的集体反思是其历史背景之一而非直接原因

**文献**：FreeBSD 1.0 Release Notes (1993.12) 与 FreeBSD 安全公告档案；NetBSD 0.8/1.0 Release Notes 与 NetBSD 安全公告档案；OpenBSD fork 公告（1995.10）与 OpenBSD 全源码审计记录；CSRG 邮件列表存档（互联网档案馆）；4.4BSD SMM 文档；Salus P H. A Quarter Century of UNIX [M]. Addison-Wesley, 1994. ISBN 0-201-54777-5 ［A］

GEOM 由 Poul-Henning Kamp 提出构想（早期思想文《Geometry —— an idea》），最原始前身是作者对 Minix 1.2 所做的一个从未发布的 hack。2002 年 Kamp 在 NAI Labs 支持下，于 DARPA/SPAWAR 合同与 DARPA CHATS 研究计划框架内开发成形。2003 年 Kamp 在 BSDCon 发表 GEOM 教程。GEOM 自 FreeBSD 5.0（2003）起提供，明确定义 class/geom/provider/consumer/rank 等拓扑概念，提供分区（FDISK/MBR、GPT、BSD slice）、镜像（geom_mirror）、RAID、UFS 卷标、GBDE/geli 磁盘加密等类，并支持 ggate 用户态网关。至 FreeBSD 13.0，GEOM_BSD、GEOM_MBR、GEOM_SUNLABEL 等过时组件被移除，由 GEOM_PART_* 与 GEOM_LABEL 等替代，框架持续演化。
