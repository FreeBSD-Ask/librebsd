# 039.11.3 rshd 信任传递机制 → 限制与 `.rhosts` 显式管理（1988.11-1990）

**要点**：4.2BSD 与 4.3BSD 早期引入 **rshd(8)**（remote shell daemon）与 `.rhosts` 信任机制——用户可在 `~/.rhosts` 文件列出 “信任主机 + 用户” 对，rshd 接受来自信任主机的远程命令执行而无须密码认证；此机制在 BSD 与 UNIX 学术协作环境中便利跨主机操作，但信任链可跨主机传递（A 信任 B、B 信任 C，蠕虫可通过 A→B→C 链传播），Morris 蠕虫利用 rshd 信任传递作为感染扩散路径之一；Berkeley 修复补丁（1988.11.8 NCSC Worm Postmortem Meeting 同步发布）限制 rshd 信任传递——禁止跨主机信任链、要求 `.rhosts` 显式声明、加入登录日志；4.3BSD-Reno（1990）与 Net/2（1991）进一步引入 `.rhosts` 检查与 hosts.equiv 严格验证；rshd 信任传递的 “淘汰” 是 BSD 安全模型从 “隐式信任” 向 “显式认证” 的迁移起点；现代 BSD 与 Linux 默认禁用 rshd，改用 SSH（Tatu Ylönen 1995 年发布 ssh 1.0）作为加密远程 shell 替代品，rsh/rcp/rlogin 谱系基本被 SSH 谱系淘汰

**史料**：4.3BSD **rshd(8)** 源代码（含信任传递实现）；Morris 蠕虫源代码（rshd 信任利用部分）；BSD 修复补丁（1988.11.8，rshd 信任限制）；4.3BSD-Reno **rshd(8)** 源代码；Ylönen, T. (1995) “SSH - Secure Shell” RFC 系列与 ssh 1.0 发布记录 ［A］

**史观**：第 2 条形式主义——rshd 信任传递是形式主义便利（学术协作便利）吞并安全实质，形式便利膨胀为安全灾难，Morris 蠕虫后形式便利被限制；第 5 条偶然性——Morris 蠕虫偶然事件直接推动 rshd 信任限制，偶然事件触发系统性信任模型改进

**辨析**：rshd 信任传递被 “淘汰” 指信任链跨主机传递被限制而非完全弃用，`.rhosts` 机制在 BSD 中长期保留为可选，须区分 “信任链限制” 与 “完全弃用”；SSH（Ylönen 1995）替代 rsh/rcp/rlogin 谱系是 1990 年代后的演化，须区分 “Morris 蠕虫后的限制”（1988-1990）与 “SSH 替代”（1995 后）；rshd 在现代 BSD 与 Linux 中默认禁用而非完全删除，须区分 “默认禁用” 与 “完全移除”
