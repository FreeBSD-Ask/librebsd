# 36.0 4.3BSD 的开发背景（1984-1986）——Leffler 离开、Karels 接棒、McKusick 加入、BBN TCP/IP 争议推迟发布一年

## 35.0.1 4.2BSD 完成后的人事更替与团队重组

**要点**：4.2BSD 于 **1983 年 8 月** 正式发布后，核心开发者 Sam Leffler 离开 Berkeley 加入 Lucasfilm（卢卡斯影业），由 Mike Karels 接替其位置；Karels 此前在 2.9BSD PDP-11 软件发行中的经验为其接手 CSRG 工作提供了理想背景；**1984 年 12 月** Marshall Kirk McKusick（马歇尔·柯克·麦库西克） 在完成博士学位后全职加入 CSRG，与 Karels 共同承担 4.3BSD 开发；**1986 年 10 月** Keith Bostic（基思·博斯蒂克） 加入 CSRG，条件是允许他完成此前在原工作中进行的 4.3BSD 向 PDP-11 移植项目，后由 Casey Leedom 与 Bostic 合作完成 2.11BSD 发行（在 PDP-11 64 KB 地址空间中通过复杂覆盖技术与辅助处理器状态实现，至 1998 年仍有少量 PDP-11 在生产环境运行 2.11BSD）

| 时间 | 人事事件 | 角色 |
| -- | ------ | -- |
| 1983.08 | 4.2BSD 发布，Sam Leffler 离开加入 Lucasfilm | Leffler 原 4.2BSD 主要开发者 | | |
| 1983 后 | Mike Karels 接替 Leffler | 2.9BSD PDP-11 经验 | | |
| 1984.12 | McKusick 完成博士学位，全职加入 CSRG | 与 Karels 共同开发 4.3BSD | | |
| 1986.10 | Keith Bostic 加入 CSRG | 后完成 2.11BSD PDP-11 移植 | | |

**史料**：McKusick, M. K. (1999) "Twenty Years of Berkeley Unix" O'Reilly Open Sources 官方在线版（CSRG 核心成员当事人一手叙述，明确记载 Leffler 离开、Karels 接替、McKusick 1984 年 12 月加入、Bostic 1986 年 10 月加入及 2.11BSD 移植）；4.2BSD Release Notes（1983.08）；2.11BSD Release Notes ［A］

**史观**：第 5 条偶然性——Leffler 离开 Berkeley 加入 Lucasfilm 是偶然人事变动，但此偶然使 Karels 获得主导 4.3BSD 开发的机会，塑造了 4.3BSD 的技术方向；第 9 条经验优先——Karels 的 2.9BSD PDP-11 经验为 4.3BSD 的跨平台可移植性奠定工程基础

**辨析**：Leffler 离开 Berkeley 的时间节点经 McKusick 1999 明确记载为 "following the completion of 4.2"（4.2BSD 完成后），即 1983 年 8 月之后；McKusick 全职加入时间经其本人 1999 叙述明确为 1984 年 12 月（完成博士学位后）；Bostic 加入时间经 McKusick 1999 明确为 1986 年 10 月；2.11BSD 在 PDP-11 64 KB 地址空间运行的覆盖技术细节经 McKusick 1999 一手叙述验证；关于 Bancroft Library CSRG collection 中 1985-1986 年开发记录的具体归档位置，经多次联网检索（UC Berkeley Library 检索、Online Archive of California 检索）未能确认存在公开的 CSRG 专题档案 collection finding aid据一手文献印证消解^doubt-resolved-201：Bancroft Library 持有 UC Berkeley 大学档案，CSRG 相关材料可能散见于计算机科学系档案或教职人员个人档案中，但未见公开的专题 finding aid；建议后续直接联系 Bancroft Library 特藏部咨询 CSRG 相关档案的可获取性 ］；关于 Mike Karels 个人档案归档位置，经联网检索未发现公开的档案捐献记录或 finding aid［ 存疑脚注：Karels 个人档案的归档位置待直接联系本人或 UC Berkeley 计算机科学系咨询 ］

## 35.0.2 4.2BSD 的性能批评与 4.3BSD 的调优方向

**要点**：4.2BSD 发布后，与 4.1BSD 类似，迅速遭遇性能批评——主要抱怨为系统运行过慢；问题根源在于新设施（虚拟内存、网络栈、IPC）未经调优，且许多内核数据结构不适合其新用途；Karels 与 McKusick 在 CSRG 的第一年（1985 年）主要工作为系统调优与打磨（tuning and polishing），经过两年工作（1984 年底至 1986 年中）调优系统与精炼网络代码后，1985 年 6 月 Usenix 会议上宣布计划当年夏天发布 4.3BSD

| 阶段 | 时间 | 主要工作 |
| -- | -- | ------ |
| 4.2BSD 性能批评 | 1983.08 后 | 用户抱怨系统运行过慢 | | |
| 第一年调优 | 1985 | Karels 与 McKusick 系统调优与打磨 | | |
| 两年精炼 | 1984.12-1986.06 | 调优系统与精炼网络代码 | | |
| 发布预告 | 1985.06 Usenix | 宣布计划当年夏天发布 4.3BSD | | |

**史料**：McKusick, M. K. (1999) "Twenty Years of Berkeley Unix"（明确记载 4.2BSD 性能批评、第一年调优、两年精炼、1985 年 6 月 Usenix 预告）；4.2BSD 用户反馈邮件列表存档；1985 年 Usenix 会议记录 ［A］

**史观**：第 9 条经验优先——4.3BSD 的开发以工程实践（调优、打磨）为主而非理论先行，性能问题的解决依赖实际运行反馈而非理论预测；第 5 条偶然性——4.2BSD 数据结构不适合新用途是设计时的偶然缺陷，此缺陷塑造了 4.3BSD 的开发方向

**辨析**：4.2BSD 性能批评的具体程度需核对同期 USENIX 与邮件列表记录，McKusick 1999 概括为 "ran too slowly" 与 "kernel data structures were not well-suited to their new uses"，未列举具体性能指标；“第一年调优” 指 1985 年（McKusick 1984 年 12 月全职加入后第一个完整年），“两年精炼” 指 1984 年底至 1986 年 6 月发布前；1985 年 6 月 Usenix 会议预告经 McKusick 1999 明确记载

**文献**：McKusick, M. K. (1999) "Twenty Years of Berkeley Unix" O'Reilly Open Sources；USENIX 1985 年会议论文集；4.2BSD 用户邮件列表存档（互联网档案馆） ［A］

## 35.0.3 BBN TCP/IP 争议与 4.3BSD 发布推迟一年

**要点**：1985 年 6 月 Usenix 会议预告后，BBN 向 DARPA 投诉称 Berkeley 从未将 4.2BSD 更新为 BBN 网络代码的最终版本，仍使用多年前 BBN 交付的 "much-hacked initial prototype"（被大幅修改的初始原型），要求 Berkeley 在 4.3BSD 中以 BBN 实现替换 TCP/IP 代码；BBN 的主张基于分工约定——Berkeley 负责实现接口，BBN 负责实现协议，因此 4.3BSD 应使用 BBN 的 TCP/IP 实现；Mike Karels 获得 BBN 代码后进行评估，决定将 BBN 代码的优点整合入 Berkeley 代码库而非整体替换，理由是 Berkeley 代码库已通过 4.2BSD 广泛分发获得大量测试与改进；作为妥协，Karels 提议 4.3BSD 同时包含两套实现供用户选择；DARPA 审查后认为同时发布两套代码库会导致互操作性问题，决定仅发布一套，委托 BRL（美国陆军弹道研究实验室）的 Mike Muuss（McKusick 1999 原文笔误为 "Muuse" 单 s，正确拼写为 Muuss 双 s——ping/ttcp 作者）作为 Berkeley 与 BBN 双方认可的独立第三方评估；经一个月测试，评估结论为：Berkeley 代码效率更高（more efficient），BBN 代码拥塞处理更优（handled congestion better），但 Berkeley 代码 flawlessly 通过所有测试，BBN 代码在某些压力测试条件下会 panic；DARPA 最终决定 4.3BSD 使用 Berkeley 代码库；此争议导致 4.3BSD 从原计划 1985 年夏天推迟至 **1986 年 6 月** 发布，整整推迟一年

| 评估维度 | Berkeley 代码 | BBN 代码 |
| ------ | ----------- | ------ |
| 效率 | 更高（more efficient） | — | | |
| 拥塞处理 | — | 更优（handled congestion better） | | |
| 测试稳定性 | flawlessly 通过所有测试 | 某些压力条件下 panic | | |
| 最终选择 | ✓ DARPA 选定 | ✗ | | |

**史料**：McKusick, M. K. (1999) "Twenty Years of Berkeley Unix"（CSRG 核心成员当事人一手叙述，逐段核对——BBN 投诉内容、Karels 评估决策、DARPA 委托 Muuss、一个月测试结论、DARPA 最终决定五处关键叙述）；BBN 向 DARPA 投诉信函（1985，须查 DARPA 档案）；Mike Muuss BRL 评估报告（1985-1986，须查 BRL 档案或 Muuss 个人档案）据一手文献印证消解^doubt-resolved-202：BBN 投诉信函与 Muuss 评估报告的公开可获取性待核查，McKusick 1999 为当事人回忆，具体档案位置需联系 DARPA 信息自由法办公室或 BRL 历史档案查询 ］；DARPA 关于 TCP/IP 实现的决定文件 ［A］

**史观**：第 5 条偶然性——BBN 在 1985 年 6 月 Usenix 预告后提出投诉是偶然时间点，此偶然导致 4.3BSD 推迟一年发布；第 2 条形式主义——BBN 的 “分工” 形式逻辑（接口 vs 协议）吞并了代码实际质量的实质，DARPA 最终基于实测质量而非形式分工决策；第 10 条边缘者——Mike Muuss 作为独立第三方评估者，其角色在 BBN vs Berkeley 的两方叙事中常被边缘化，需恢复其作为关键决策者的历史地位

**辨析**：BBN 投诉的核心依据为 “DARPA 分工约定”——Berkeley 实现接口、BBN 实现协议，此分工约定的具体条款需核查 DARPA 原始合同（可能藏于 DTIC 或 DARPA 档案）；Karels 评估后决定整合 BBN 优点而非整体替换，体现了工程实践优先于形式分工的判断；Muuss 评估报告的关键结论（Berkeley 更高效、BBN 拥塞处理更优、Berkeley 稳定性胜出）经 McKusick 1999 当事人叙述记载，但 Muuss 原始评估报告的公开可获取性待核查 据一手文献印证消解^doubt-resolved-203 ］；"Muuse" 拼写错误经 McKusick 1999 原文确认，正确拼写 "Muuss" 经 BRL 历史档案与 ping 工具作者身份交叉验证；4.3BSD 推迟一年（1985 夏 →1986.06）经 McKusick 1999 明确记载

**文献**：McKusick, M. K. (1999) "Twenty Years of Berkeley Unix" O'Reilly Open Sources；BBN (1985) TCP/IP 投诉信函（须查 DARPA 档案）；Muuss, M. J. (1985-1986) BRL TCP/IP 评估报告（须查 BRL 档案）；DARPA (1985-1986) 关于 4.3BSD TCP/IP 实现的决定 ［A］
