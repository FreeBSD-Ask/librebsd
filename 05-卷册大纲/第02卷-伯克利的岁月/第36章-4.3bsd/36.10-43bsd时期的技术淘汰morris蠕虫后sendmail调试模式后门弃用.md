# 36.10 4.3BSD 时期的技术淘汰——Morris 蠕虫后 sendmail 调试模式后门弃用、fingerd/rshd 漏洞修复与隐式信任安全模型向显式审计迁移（1986-1989）

## 35.10.1 sendmail DEBUG 命令调试模式后门 → 弃用与默认禁用（1988.11-1989）
- 要点：4.2BSD 与 4.3BSD 早期 sendmail 配置默认开启 DEBUG 命令模式（`-d` 调试标志），DEBUG 命令允许远程主机通过 SMTP `DEBUG` 命令直接调用 sendmail 内置的解释器执行任意 shell 命令，本为开发期调试便利而保留为生产默认配置（4.3BSD sendmail 默认开启 DEBUG 模式，具体版本号 [考据完成：2026-08-17 sendmail DEBUG 后门经 Spafford（CACM 1989）与 FBI 确认、4.3BSD 默认开启；具体版本号各源记载不一（5.59/5.61），不锁定单一版本]）；Morris 蠕虫（**1988 年 11 月 2 日晚 8:30** EST）利用此漏洞作为主要感染路径之一，从 MIT AI Lab 释放后通过 sendmail DEBUG 命令远程感染约 **6000 台** 4BSD/Sun-3 UNIX 机器；Berkeley 与 MIT 团队 **1988 年 11 月 4 日** 起逆向分析蠕虫代码，**1988 年 11 月 8 日** National Computer Security Center 主持 Worm Postmortem Meeting（apricot.net 1997 回顾性编年史料，非一手文档）同步发布修复补丁默认禁用 DEBUG 命令；4.3BSD-Tahoe（**1988 年 6 月** 发布）早于 Morris 蠕虫（**1988 年 11 月**）发布，未包含蠕虫修复补丁；sendmail DEBUG 后门的默认禁用是 Morris 蠕虫事件直接推动的安全改进，标志 BSD 安全模型从 “开发便利优先” 向 “生产安全优先” 的迁移

| 旧机制（4.3BSD 早期） | 新机制（Morris 蠕虫后） | 修复版本 |
| --- | --- | --- |
| sendmail DEBUG 默认开启 | 默认禁用 DEBUG 命令 | 1988.11.8 修复补丁 |
| fingerd 固定 512 字节缓冲区 | 动态分配 + 输入长度检查 | 1988.11.8 修复补丁，4.3BSD-Reno 完善 |
| rshd 跨主机信任链传递 | 禁止跨主机信任链、要求显式 `.rhosts` | 1988.11.8 修复补丁，4.3BSD-Reno/Net/2 完善 |
| 隐式信任安全模型 | 显式审计日志 + CERT/CC 制度化响应 | 4.3BSD-Reno 引入审计，CERT/CC 1988.11.17 成立 |

- 史料：4.3BSD sendmail 源代码（含 DEBUG 命令实现）；Morris 蠕虫源代码（Berkeley 逆向分析版本）；BSD 修复补丁（1988.11.8，禁用 sendmail DEBUG）；Spafford, E. (1989) "The Internet Worm Program"；Eichin, M. & Rochlis, J. (1989) "With Microscope and Tweezers"；CERT/CC CA-1988-01 公告 ［A］
- 史观：第 2 条形式主义——sendmail 调试模式后门是形式主义便利（开发期调试）吞并安全实质，形式便利膨胀为安全灾难，Morris 蠕虫事件后形式便利被淘汰；第 5 条偶然性——Morris 蠕虫偶然事件直接推动 sendmail DEBUG 后门弃用，偶然事件触发系统性安全改进
- 辨析：sendmail DEBUG 命令被 “淘汰” 指默认禁用而非完全删除，管理员仍可显式启用，须区分 “默认禁用” 与 “完全弃用”；据 McKusick 1999 当事人一手叙述确认，4.3BSD-Tahoe 发布于 1988 年 6 月，早于 Morris 蠕虫（1988 年 11 月），故 Tahoe 版本不可能预先包含蠕虫修复补丁；Morris 蠕虫利用 sendmail DEBUG 是主要感染路径还是辅助路径在不同史料中描述详略不一，需核对 Spafford 蠕虫分析原始手稿；4.3BSD sendmail DEBUG 模式具体版本号 [考据完成：2026-07-28 经穷尽联网考据为史料缺口，详见 17.1.2 要点]——经 bsd_commits.db 查询未得明确证据（查询条件：`SELECT * FROM commits WHERE message_subject LIKE '%sendmail%' OR message_subject LIKE '%DEBUG%' OR message_subject LIKE '%4.3BSD%'`，freebsd-src 仓库最早 commit 为 1993-06-12T14:49:13Z by Rodney W. ## 35.10.2 fingerd 缓冲区溢出漏洞 → 修复与 BSD 内存保护改进（1988.11-1989）
- 要点：4.3BSD 的 **fingerd(8)** 守护进程在读取 finger 请求时使用固定大小缓冲区，未检查输入长度，远程攻击者可发送超长输入覆盖返回地址（arstechnica.com 2015-08-26 二手科技媒体叙述称攻击发送了 537 字节 [考据完成：2026-07-28 经穷尽联网考据，arstechnica.com 2015-08-26 文章为二手科技媒体叙述，537 字节数据在中文二手来源中亦有引用但同样非一手。Spafford 1989 "The Internet Worm Program"（Purdue CSD-TR-823）与 Eichin & Rochlis 1989 "With Microscope and Tweezers" 一手论文未在免费公开渠道提供全文。此为史料缺口，精确字节数须待一手论文全文公开后方可补充。]），使 fingerd 执行任意代码（即 stack smashing 攻击的早期实例）；Morris 蠕虫利用此漏洞作为另一主要感染路径，通过 fingerd 缓冲区溢出获取 VAX 4BSD 机器的 shell 权限；Berkeley 修复补丁（1988.11.8 NCSC Worm Postmortem Meeting 同步发布）将 fingerd 缓冲区改为动态分配并加入输入长度检查；4.3BSD-Tahoe（1988 年 6 月发布，早于蠕虫）未包含此修复，4.3BSD-Reno（1990 年 7 月正式发布）及后续版本引入更严格的输入验证；fingerd 缓冲区溢出的修复是 BSD 安全模型从 “信任输入合法性” 向 “显式验证输入” 的迁移起点，后被 Aleph One "Smashing the Stack for Fun and Profit"（Phrack 49, 1996）等正式化的缓冲区溢出研究继承
- 史料：4.3BSD **fingerd(8)** 源代码（含缓冲区溢出漏洞）；Morris 蠕虫源代码（fingerd 利用部分）；BSD 修复补丁（1988.11.8，fingerd 缓冲区修复）；Spafford, E. (1989) "The Internet Worm Program"；Aleph One (1996) "Smashing the Stack for Fun and Profit" Phrack 49 ［A］
- 史观：第 17 条软件工程——fingerd 缓冲区溢出的修复是软件工程中 “输入验证” 机制的引入，从信任输入到显式验证；第 5 条偶然性——Morris 蠕虫偶然事件直接推动 fingerd 漏洞修复，偶然事件触发系统性输入验证改进
- 辨析：fingerd 缓冲区溢出是 stack smashing 攻击的早期实例而非最早实例，需区分 “早期实例” 与 “最早实例”；Aleph One 1996 年 Phrack 49 论文正式化了缓冲区溢出研究，但相关漏洞早在 Morris 蠕虫前已被研究者知晓，须区分 “研究者知晓” 与 “事件显性化”；4.3BSD 后续版本中栈保护机制的具体实现（如 StackGuard 1998、ProPolice 2001）在不同史料中描述详略不一，需核对 BSD 与 GCC 安全特性时间线；arstechnica.com 537 字节数据 [考据完成：2026-07-28 经穷尽联网考据为史料缺口，详见 17.10.2 要点]——经 bsd_commits.db 查询未得明确证据（查询条件：`SELECT * FROM commits WHERE message_subject LIKE '%fingerd%' OR message_subject LIKE '%buffer%' OR message_subject LIKE '%537%' OR message_subject LIKE '%overflow%'`，freebsd-src 仓库最早 commit 为 1993-06-12T14:49:13Z by Rodney W. Grimes，hash 9002c02abc587664acb357c6879d8ca08664dd0b，早于 Morris 蠕虫 1988 年 11 月约 5 年，commit 历史中无 fingerd 缓冲区溢出字节数的代码级证据），已标注为史料缺口
- 文献：4.3BSD **fingerd(8)** 源代码；Morris 蠕虫源代码；BSD 修复补丁（1988.11.8）；Spafford (1989) "The Internet Worm Program"；Aleph One (1996) Phrack 49；CERT/CC CA-1988-01 ［A］

## 35.10.3 rshd 信任传递机制 → 限制与 `.rhosts` 显式管理（1988.11-1990）
- 要点：4.2BSD 与 4.3BSD 早期引入 **rshd(8)**（remote shell daemon）与 `.rhosts` 信任机制——用户可在 `~/.rhosts` 文件列出 “信任主机 + 用户” 对，rshd 接受来自信任主机的远程命令执行而无须密码认证；此机制在 BSD 与 UNIX 学术协作环境中便利跨主机操作，但信任链可跨主机传递（A 信任 B、B 信任 C，蠕虫可通过 A→B→C 链传播），Morris 蠕虫利用 rshd 信任传递作为感染扩散路径之一；Berkeley 修复补丁（1988.11.8 NCSC Worm Postmortem Meeting 同步发布）限制 rshd 信任传递——禁止跨主机信任链、要求 `.rhosts` 显式声明、加入登录日志；4.3BSD-Reno（1990）与 Net/2（1991）进一步引入 `.rhosts` 检查与 hosts.equiv 严格验证；rshd 信任传递的 “淘汰” 是 BSD 安全模型从 “隐式信任” 向 “显式认证” 的迁移起点；现代 BSD 与 Linux 默认禁用 rshd，改用 SSH（Tatu Ylönen 1995 年发布 ssh 1.0）作为加密远程 shell 替代品，rsh/rcp/rlogin 谱系基本被 SSH 谱系淘汰
- 史料：4.3BSD **rshd(8)** 源代码（含信任传递实现）；Morris 蠕虫源代码（rshd 信任利用部分）；BSD 修复补丁（1988.11.8，rshd 信任限制）；4.3BSD-Reno **rshd(8)** 源代码；Ylönen, T. (1995) "SSH - Secure Shell" RFC 系列与 ssh 1.0 发布记录 ［A］
- 史观：第 2 条形式主义——rshd 信任传递是形式主义便利（学术协作便利）吞并安全实质，形式便利膨胀为安全灾难，Morris 蠕虫后形式便利被限制；第 5 条偶然性——Morris 蠕虫偶然事件直接推动 rshd 信任限制，偶然事件触发系统性信任模型改进
- 辨析：rshd 信任传递被 “淘汰” 指信任链跨主机传递被限制而非完全弃用，`.rhosts` 机制在 BSD 中长期保留为可选，须区分 “信任链限制” 与 “完全弃用”；SSH（Ylönen 1995）替代 rsh/rcp/rlogin 谱系是 1990 年代后的演化，须区分 “Morris 蠕虫后的限制”（1988-1990）与 “SSH 替代”（1995 后）；rshd 在现代 BSD 与 Linux 中默认禁用而非完全删除，须区分 “默认禁用” 与 “完全移除”
- 文献：4.3BSD **rshd(8)** 源代码；Morris 蠕虫源代码；BSD 修复补丁（1988.11.8）；4.3BSD-Reno **rshd(8)** 源代码；Ylönen, T. (1995) SSH 发布记录；CERT/CC CA-1988-01 ［A］

## 35.10.4 隐式信任安全模型 → 显式审计与 CERT/CC 制度化响应（1988.11-1990）
- 要点：4.3BSD 早期安全模型为 “隐式信任”——开发者信任用户输入合法性、信任网络主机身份、信任本地用户协作，缺乏显式审计日志与安全事件响应机制；Morris 蠕虫（1988.11.2）暴露此模型的根本缺陷——网络规模扩大后信任链可被滥用传播恶意代码，且缺乏制度化安全事件响应机制；Berkeley 修复补丁（1988.11.8 NCSC Worm Postmortem Meeting 同步发布）引入 fingerd/rshd/sendmail 的登录日志，4.3BSD-Reno（1990）引入更完善的系统审计机制；1988 年 11 月 17 日 DARPA 决定成立 CERT/CC（apricot.net 1997 回顾性编年史料 "November 17, 1988 Defense Advanced Research Projects Agency (DARPA) formed the Computer Emergency Response Team"，事件发生 9 年后整理，非一手文档），由 CMU SEI 运营，1988 年 12 月正式运营，建立互联网安全事件响应标准流程；隐式信任安全模型在 4.3BSD 后期被 “淘汰” 为显式审计与制度化响应模型，CERT/CC 模式后被各国 CSIRT（Computer Security Incident Response Team）继承；OpenBSD（1995 年 fork）将 “显式安全审计” 作为项目核心原则，是 4.3BSD 时期安全模型迁移的延续。统计结论 [C-41] references 表总数 16,867 条，[C-42] 年份提取率 44.42%（7,493/16,867），Morris 蠕虫爆发年 1988 年参考文献 84 条累计 1,564 条（20.87%）、4.3BSD-Reno 发布年 1990 年 65 条累计 1,705 条（22.75%），CSRG 时期（1969-1995）累计 1,879 条占比 25.08%——参考文献累积量在 1988-1990 年间年均增长约 70 条，反映 Morris 蠕虫事件后 BSD 安全研究文献产出的显著增长

- 史观：第 2 条形式主义——隐式信任是形式主义便利（学术协作便利）吞并安全实质，Morris 蠕虫后隐式信任被淘汰；第 5 条偶然性——CERT/CC 的建立是 Morris 蠕虫偶然事件的直接后果，偶然事件催生制度性安全响应机制；统计结论 [C-41] [C-42] 印证——1988-1990 年间 references 表文献累积量从 1,564 条增至 1,705 条（年均增长约 70 条），反映 Morris 蠕虫事件后 BSD 安全研究文献产出的显著增长，与第 5 条偶然性 “Morris 蠕虫偶然事件触发制度性响应” 形成量化印证，但须遵循 0 信任原则——统计显著 ≠ 实际显著，文献累积量增长亦可能受同期学术生态整体扩张影响，不得单凭此数据归因于 CERT/CC 建立的效应
