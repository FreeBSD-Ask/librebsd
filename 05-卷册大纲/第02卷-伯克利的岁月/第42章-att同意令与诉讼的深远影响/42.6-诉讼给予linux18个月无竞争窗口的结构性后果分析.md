# 42.6 诉讼给予 Linux 18 个月无竞争窗口 的结构性后果分析

## 42.6.1 18 个月窗口的形成

**要点**：**1992.4-1994.1** 诉讼期间 BSD 路线法律不确定性高，386BSD 与 NetBSD 0.8 发展受阻、商业厂商谨慎采用 BSD、Linux 0.01-0.99（**1991.9-1994.3**）快速发展，18 个月窗口使 Linux 抢占 BSD 部分市场份额；统计结论 [C-41] references 表总数 16,867 条，[C-42] 年份提取率 44.42%（7,493/16,867），诉讼期间 1992-1994 年参考文献累计 1,564 条（20.87%），CSRG 时期（1969-1995）累计 1,879 条占比 25.08%——诉讼期间文献产出占 CSRG 时期约 83.23%（1,564/1,879），反映法律不确定性虽阻碍 BSD 代码发展但未中断学术研究文献产出

## 42.6.2 Linux 抢占市场份额的过程

**要点**：Linux 抢占市场份额的过程：1992.1 Linux 0.12 发布、1992.12 Linux 0.99 发布、1993.4 Linux 1.0 候选版、1994.3 Linux 1.0 正式发布，期间 Linux 社区快速发展（Linus Torvalds、Alan Cox、Theodore Ts'o 等核心贡献者），Linux 抢占 PC UNIX 市场份额约 30%

**史料**：Linux 0.12-1.0 Release Notes（1992-1994）、Linux 邮件列表存档、1993-1994 年 PC UNIX 市场份额报告 ［A］

**史观**：第 5 条偶然性——Linux 抢占市场份额的速度在 1992 年难以预期，是 BSD 诉讼偶然窗口与 Linux 社区努力叠加的产物

**辨析**：Linux 市场份额 “30%” 需核对，区分 “PC UNIX 市场” 与 “全部 UNIX 市场”，避免事后夸大

## 42.6.3 窗口对 BSD 命运的效应

**要点**：诉讼期间法律不确定性对 BSD 各派生版本的影响：386BSD 0.1（**1992 年**）发布后 Bill Jolitz 因个人原因停止更新，补丁集膨胀后催生 NetBSD 和 FreeBSD 项目；NetBSD 0.8（**1993 年 4 月**）发布但法律不确定性限制商业采用；FreeBSD 1.0 网络公告发布于 **1993 年 11 月 1 日**（Jordan Hubbard 公告原文），CD-ROM 广泛分发在 **1993 年 12 月**，基于 Net/2 发布但受诉讼阴影影响；**1994 年** 和解后所有 BSD 项目需迁移至 4.4BSD-Lite 代码库（FreeBSD 2.0 于 **1994 年 12 月** 完成迁移发布），迁移造成短期开发延迟

**史料**：386BSD 0.1 Release Notes（**1992**）、NetBSD 0.8 Release Notes（**1993.4**）、FreeBSD 1.0 正式公告（**1993.11.1**，Jordan Hubbard 发布）、FreeBSD 2.0 Release Notes（**1994.12**）、FreeBSD Handbook 官方历史、McKusick 1999 当事人回忆 ［B］

**史观**：第 5 条偶然性——法律不确定性使 BSD 各项目在 1992-1994 年发展受阻，是诉讼偶然事件叠加 386BSD 维护中断、Novell 收购等多重因素的产物

**辨析**：FreeBSD 1.0 网络公告日期经 Jordan Hubbard 1993.11.1 原始公告确认为 11 月 1 日，FreeBSD Handbook 记载 “December of 1993” 应指 CD-ROM 正式分发时间；需客观看待 “Linux 抢占市场份额” 叙事——BSD 在服务器、网络设备、嵌入式领域长期保持优势，桌面市场格局受多因素影响，法律不确定性是因素之一但非唯一决定因素；“18 个月窗口” 说法为历史叙事概括，精确时长计算 据一手文献印证消解^doubt-resolved-248：此处事实待多源交叉验证 ］；经 freebsd.duckdb 查询未得明确证据（查询条件：`SELECT * FROM commits WHERE message_subject LIKE '%Linux%' OR message_subject LIKE '%competition%' OR message_subject LIKE '%window%'`，freebsd-src 仓库中无 Linux 竞争窗口相关 commit，commit 历史只能反映 BSD 代码发展时序，无法对 “18 个月窗口” 的精确时长（从 1992.4 起诉至 1994.1 和解约 21 个月，或从 1992.4 至 1993.11 FreeBSD 1.0 发布约 19 个月）提供代码级证据），暂保留存疑

**文献**：386BSD/NetBSD/FreeBSD Release Notes（1992-1994）；McKusick, M. K. (1999) “Twenty Years of Berkeley Unix”；FreeBSD Project. FreeBSD 1.0 RELEASE Announcement（1993-11-01，Jordan Hubbard 一手公告）；FreeBSD Project. “A Brief History of FreeBSD”（FreeBSD Handbook）；Moody, G. (2001) “Rebel Code” ［B］

## 42.6.4 BSD 与 Linux 命运分化的结构性拐点

**要点**：BSD 与 Linux 命运分化的结构性拐点为 1992-1994 年诉讼期间，BSD 法律不确定性使 Linux 抢占市场份额，1994 年和解后 BSD 路线恢复但市场份额难以夺回，1995-2000 年 Linux 在服务器市场超越 BSD，BSD 与 Linux 命运分化长期固化

**史料**：1992-2000 年 BSD 与 Linux 市场份额对比、Linux 1.0-2.4 Release Notes（1994-2001）、FreeBSD/NetBSD/OpenBSD Release Notes（1994-2001）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档 + L5 研究报告〕

**史观**：第 5 条偶然性——1992-1994 年诉讼是命运分化的偶然拐点，但此拐点决定 BSD 与 Linux 长期格局

**辨析**：命运分化的 “结构性” 需核对，避免将短期市场份额等同于长期命运，BSD 在嵌入式与服务器市场仍保持影响力

- 创建 core team 是对“仁慈独裁者”模式的制度性拒绝：发言人基于业界观察认为独裁者项目多不长寿，且自认知识面广而不深、无法覆盖全部组件，遂征集约七人组成核心团队，同时为自己保留退出通道；二十五年后回看认为该决策正确，并明言不喜欢 Linux 的治理模型但承认其成就。（YouTube EP4OvLlKazFV4，[2294.63-2366.66]，L1）
- 1.0 版在约九个月开发后于 1993 年 11 月发布，传播速度远超预期；项目早期曾与 NetBSD 方代表在 Walnut Creek 会谈三四次讨论两项目合并，结论是人员差异下合并将不利于双方而作罢；发言人回看认为分叉反而是好事，BSD 阵营的分叉数量远少于 Linux 阵营的庞大谱系。（YouTube EP4OvLlKazFV4，[597.0-696.62]，L1）
- USL/Novell 诉讼中止了开发进程并阻断社区对代码库的采纳，因为潜在使用者无法在前景不确定时投入资源；和解协议有多份且大多含保密条款，加州大学所签版本因其公共实体身份经 Kirk McKusick 通过信息自由法程序公开、可在互联网获取且并不复杂；问答环节发言人梳理 UNIX 版权链为 AT&T 到 USL 再到 Novell，诉讼名称亦随权利转移而变化。（YouTube EP4OvLlKazFV4，[697.1-868.15]，L1）
- 该期以二手科普口径重述 BSD 起点：1974 年 Unix 应 SOSP 委员 Bob Fabry 之邀进入伯克利，所购 PDP 11/45 因预算紧张与数学、统计组合用，每日仅八小时可运行；次年凭 INGRES 数据库项目经费换装 PDP 11/70。Ken Thompson 休假定伯克利协助安装版本 6 并从事 Pascal 实现，研究生 Chuck Haley 与 Bill Joy 改进文本编辑器，1977 年 Joy 着手汇编首个发行。（YouTube EPtuI2wX3ol2o，[78.42-166.14]，L2）
- 1978 年 3 月 9 日 1BSD 发布，作为版本 6 的附加包而非完整系统，约 30 份拷贝寄出；1979 年 5 月 2BSD 收入 Bill Joy 的 vi 与 csh，其血脉延续为今日的 Vim 与 tcsh。1978 年伯克利装上 VAX，AT&T 的 32V 移植未利用虚拟内存，研究生 Özalp Babaoğlu 大幅重写内核引入虚存，1979 年底 3BSD（又称 VM Unix）问世，BSD 首次在 VAX 上构成完整系统。（YouTube EPtuI2wX3ol2o，[166.14-254.40]，L2）
- 4.3BSD 之后伯克利转向 CCI Power 6/32（代号 Tahoe），平台旋遭其厂商放弃，但移植催动机器相关与机器无关代码的分离、显著增强可移植性，1988 年 6 月 4.3BSD Tahoe 发行；同期 CSRG 开发 OSI 协议栈、改进内核虚存，并与 LBL 的 Van Jacobson 合作设计新 TCP/IP 算法以支撑互联网增长。（YouTube EPtuI2wX3ol2o，[256.92-330.48]，L2）
- AT&T 专有许可费自数百美元至数十万美元不等，外部各方遂对不含 AT&T 代码、可自由再分发的网络版本产生兴趣：1989 年 6 月 Networking Release 1 以 BSD 许可证向非许可持有者开放；Keith Bostic 顺势发起在不使用 AT&T 代码的前提下重写标准 Unix 工具的工程，18 个月内全部替换完成，1991 年 6 月 net/2 作为近乎完整、可自由分发的系统发布。（YouTube EPtuI2wX3ol2o，[350.10-428.88]，L2）
- net/2 之后 386 架构上出现 Bill 与 Lynne Jolitz 的 386BSD 与 BSDi 的专有 BSD/386 两支移植；1992 年 USL 起诉 BSDi，禁令冻结 net/2 发行，法律不确定使 BSD 自由后代停滞近两年，Linux 趁势扩张。1994 年 1 月和解大体有利于伯克利：18000 个文件仅 3 个删除、70 个补 USL 版权声明，USL 承诺不再就伯克利代码起诉；1995 年 4.4BSD-Lite Release 2 收官，CSRG 解散，伯克利开发终止，而 FreeBSD、NetBSD、OpenBSD、DragonFly BSD 及 Windows、Darwin、Solaris 对 BSD 代码的吸收构成其延续的遗产。（YouTube EPtuI2wX3ol2o，[435.96-612.60]，L2）

**史观**：

- 总纲3 不存在进步，只有权力再分配：受访者以亲历者身份描述 FreeBSD 治理：每两年由拥有仓库写权限的提交者选举九人组成 core team，其职能是协调方向、仲裁争论与授予写权限，而非自上而下规定路线，他本人曾任两届；以定期改选的委员会替代单一个人权威，使项目权力以制度化节奏反复再分配，并降低对单个个体倦怠或离场的依赖。（The Changelog EP574，[3971.06-4040.29]，L1）
- 总纲5 没有必然性，只有偶然性：受访者提醒，世纪初 BSD 系统管理员的“硬核”光环与 Linux 的“玩具”标签是可反转的历史建构：当年 BSD 文档反而更完善、托管业务首选 BSD，其后 Linux 经 IBM 数十亿美元投入与对 Red Hat 的收购而成熟，两阵营声望结构在二十年间整体倒置；这一位序变动由诉讼、资本与生态事件等偶然条件叠加而成，并非技术优劣的必然。他另以“Unix 不阻止你做蠢事，因为那也会阻止你做聪明事”概括无护栏设计的代价。（The Changelog EP574，[4680.24]，L2）
- 总纲3 不存在进步，只有权力再分配：诉讼与权力再分配：她提出 1992 年 AT&T 诉 BSDi 与 USL 的诉讼使开发者注意力耗散于法律之争、实质抑制了 BSD 的开发与采用，而 Linux 恰在此窗口诞生，社区因此常以诉讼解释 Linux 的后来居上——技术成败的转折被归于法律环境对开发者精力的再分配，而非代码本身的优劣。（YouTube EPh-gJePs8XDI，[1058.30-1098.03]，L1）
- 总纲8 本体论上各方平等：跨阵营平等对话：她面向 Linux 观众强调两大阵营应相互学习而非争论共同编程，理解彼此不同的编码方法论与哲学方能做出明智的工程决策，并以 FreeBSD 较小的代码库（内核约五百万行对 Linux 约两千六百万行）作为学习操作系统原理的平等对话入口。（YouTube EPh-gJePs8XDI，[3070.44-3131.70]，L1）
- 总纲5 没有必然性，只有偶然性：发言人把 BSD 与 Linux 的增长分化解释为“增长曲线上的平台期恰逢 Linux 出现”的纯粹时机偶然，明确表示这是无法回头更改的历史片段，拒绝将格局结果归因于任何必然规律或优劣判定。（YouTube EP4OvLlKazFV4，[846.56-868.15]，L1）
- 总纲5 没有必然性，只有偶然性：制作者以反事实收束全片：若无 USL 诉讼造成近两年搁置，BSD 很可能占据今日 Linux 的位置。这一表述把 BSD 与 Linux 的命运分野归因于法律纠纷这一偶然事件，而非技术路线的必然优劣，与“没有必然性、只有偶然条件”的历史观相合。（YouTube EPtuI2wX3ol2o，[627.24-641.16]，L2）

**辨析**：

- 受访者给出的最有分量的自我批评是把 FreeBSD 比作乐高积木：构件齐备但缺最后 10% 的成品化——jails 自 2000 年即存在，却始终没有 Docker 式拉取即用的镜像仓库；他辨析其中兼有安全考量（永不更新的镜像存在风险）与许可优势（appliance 厂商借此规避 GPL 合规），这也解释了 BSD 生态以 appliance 形态繁荣的格局，但对该批评是否随容器生态演进而失效未作判断。（The Changelog EP574，[4197.15-4448.05]，L2）
- 两点需辨析：其一，将 Linux 崛起主要归因于 USL 诉讼属社区流行解释，诉讼与 Linux 早期发展时间重叠之外，许可证文化与发行版生态等因素并存，不宜作单一因果归因；其二，转写中将 FreeBSD 与 NetBSD 自 386BSD 分出的年份记为 1983，与其自述的 1993 年 6 月 19 日命名日及二十七年项目史相矛盾，应为口述或转写之误。　[存疑脚注] 转写作 1983 年分出，与 FreeBSD 1993-06-19 命名史实矛盾，年份归属须以 386BSD 0.0（1992 年）与 FreeBSD 1.0（1993 年）等仓库史料复核（YouTube EPh-gJePs8XDI，[992.34-1098.03]，L2）
- 口述存在多处自认的记忆空白：记不全 core team 七人名单、不确定 hub 机器的置入者、自陈不清楚 NetBSD 与 CSRG 的确切关系；转写文本为双轨时间戳交错且人名听写错误明显（如 bill Joel'its 应为 Bill Jolitz、Paul Henning camp 应为 Poul-Henning Kamp），引用本演讲任何细节前须回原视频与邮件列表档案交叉核验。　[存疑脚注] 转写双轨交错、人名多误，口述者亦自承记忆不确定，所有时间点与人名须以原始档案核验。（YouTube EP4OvLlKazFV4，[2213.98-2273.69]，L2）
- 制作者断言 386BSD（1992 年 7 月 14 日发布）是 BSD 家族中首个完整开源操作系统，并称 3BSD、net/1、net/2 因含专有 AT&T 代码而不合现代开源定义；此类“第一”判定取决于对“完整”与“开源”的定义选择——net/2 是否真正清除了 AT&T 代码恰是 USL 诉讼争执的核心，制作者对 Linux 一侧也承认 GNU 工具与内核的结合是渐进过程、日期难定，并转述 1992 年 2 月 3 日 Manchester Computing Center 的 interim Linux（Owen LeBlanc 制作）一说。　[存疑脚注] 386BSD 基于声称不含 AT&T 代码的 net/2，但 USL 诉讼曾质疑其中部分文件的版权归属，是否“完整开源”存在争议；Manchester interim Linux 的日期与制作者身份系视频转述，需以邮件列表存档核实（YouTube EPtuI2wX3ol2o，[643.44-719.16]，L4）
