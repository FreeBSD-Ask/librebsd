# 28.2 C Shell 的语法创新——为什么 csh 没有成为默认 shell

## 28.2.1 csh 的语法创新

**要点**：C Shell（csh）由 Joy 1978 年开发，引入类 C 语法、历史替换（!）、作业控制（jobs/bg/fg）、别名机制、波浪号（~）主目录表示法，是 BSD 的重要用户界面创新；历史替换功能受 INTERLISP 的 redo 功能启发

**史料**：csh 源代码、Joy 的 csh 设计文档、2BSD 用户手册、codearchaeology.dev C Shell 史 ［A］

**史观**：第 2 条实践先于理论——csh 的语法创新源于 Joy 对交互式使用的实践需求，而非编程语言理论

**辨析**：csh 的作业控制与历史替换功能的创新来源已确认——历史机制受 INTERLISP redo 启发，而非完全独立发明；csh 开创的波浪号主目录表示法被后续所有 shell 继承；据 Joy 1980 年 C Shell 入门文档致谢，历史机制的落实源自 Michael Ubell 的关键观察（历史命令可在输入文本的词结构上完成）与原型实现，Eric Allman（埃里克·奥尔曼） 提供评论并协助统一概念，Mike O'Brien 建议路径名哈希机制以加速命令执行，Jim Kulp 添加作业控制与目录栈原语（Joy, 1980）

**文献**：Joy, W. (1978) “An Introduction to the C Shell”；伯克利 CSRG 技术报告；codearchaeology.dev “C Shell” 条目［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 28.2.2 csh 与 Bourne Shell 的差异

**要点**：**csh** 与 **Bourne Shell**（sh，Stephen Bourne 开发）在语法结构（C 风格 vs ALGOL 风格）、交互功能（csh 有历史/别名/作业控制，sh 无）、脚本可移植性（sh 更通用）等方面存在根本差异；Bourne Shell 开发始于 1975 年末/1976 年初，1979 年随 V7 UNIX 正式发布，csh 1978 年开发、随 2BSD 1978 年中发布，二者开发时间重叠但发布时间 csh 略早于 V7

| 维度 | C Shell（csh） | Bourne Shell（sh） |
| -- | ------------ | ---------------- |
| 作者 | Bill Joy（伯克利） | Stephen Bourne（Bell Labs） |
| 开发时间 | 1978 年 | 1975 年末/1976 年初 |
| 首次发布 | 2BSD（1978 年中） | V7 UNIX（1979 年） |
| 语法风格 | C 风格 | ALGOL 风格 |
| 历史替换（`!`） | 有 | 无 |
| 别名机制（`alias`） | 有 | 无 |
| 作业控制（`jobs`/`bg`/`fg`） | 有 | 无 |
| 波浪号（`~`）主目录 | 有 | 无 |
| 脚本可移植性 | 差 | 好 |
| 适用场景 | 交互式 | 脚本式 |

**史料**：csh 与 sh 源代码对比、Bourne 的 shell 设计文档、USENIX 会议论文、V7 UNIX 发布记录 ［A］

**史观**：第 6 条技术路线分化——csh 与 sh 的分化代表了交互式与脚本式两条技术路线的分野

**辨析**：Bourne Shell 的开发始于 1975 年末/1976 年初，正式发布为 1979 年 V7 UNIX，~~先前 1977/1978 年的说法不准确~~（修正：经核实开发始于 **1975 年末/1976 年初**，1979 年随 V7 发布）；Bourne Shell 与 csh 开发同期但独立进行，不存在一方直接影响另一方的证据

**文献**：Bourne, S. (1978) “The UNIX Shell”；Joy, W. (1978) “An Introduction to the C Shell”；qiita.com “Unix シェルの 初期 の 歴史”［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 28.2.3 csh 未成为默认 shell 的原因

**要点**：csh 因脚本语法缺陷（变量作用域、错误处理、可移植性）未成为默认 shell，AT&T UNIX 与 System V 坚持 Bourne Shell，BSD 在交互式场景使用 csh 但脚本仍倾向 sh

**史料**：UNIX 各版本默认 shell 配置、csh 脚本缺陷讨论邮件、USENIX 论文 ［B］

**史观**：第 24 条许可证——csh 作为 BSD 创新未进入 AT&T 默认发行版，反映 BSD 与 AT&T 在默认配置上的分化

**辨析**：csh 未成为默认的具体原因（技术缺陷还是 AT&T 政策）在史料中存在不同侧重，需区分技术因素与商业因素

**文献**：Christiansen, T. (1996) “Csh Programming Considered Harmful”；Bourne, S. (1978) “The UNIX Shell”［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 28.2.4 csh 的历史效应

**要点**：csh 的历史替换与作业控制功能影响了后续 shell 设计——tcsh（Ken Greer **1981 年 12 月** 将 TENEX 风格文件名补全合并入 csh）延续 csh 谱系（Arch Linux man **tcsh(1)** 原文 “Ken Greer, HP Labs, 1981. File name completion.”），bash（Brian Fox **1989 年**）吸收 csh 交互功能，zsh（Paul Falstad **1990 年** 在普林斯顿大学发布于 comp.sources.misc 新闻组）

| Shell | 作者 | 时间 | 谱系关系 | 关键特性 |
| --- | -- | -- | ------ | ------ |
| Thompson shell（sh V1） | Ken Thompson | 1969-1971 | 谱系起点 | 早期 UNIX 默认 shell |
| Bourne shell（sh V7） | Stephen Bourne | 1975 末 -1979 | V7 UNIX 默认 | ALGOL 风格，脚本通用 |
| C Shell（csh） | Bill Joy | 1978 | 2BSD 默认交互 | 类 C 语法、历史替换、作业控制 |
| tcsh | Ken Greer（HP Labs） | 1981.12 | csh 谱系延续 | TENEX 文件名补全 |
| bash | Brian Fox（GNU） | 1989 | 吸收 csh 交互功能 | GNU 默认 shell |
| zsh | Paul Falstad（普林斯顿） | 1990 | 综合性 shell | comp.sources.misc 发布 |

**史料**：tcsh/bash/zsh 源代码、shell 设计文档、USENIX/GNUs 邮件列表 ［A］

**史观**：第 4 条分离与聚合——csh 的创新被后续 shell 分别吸收与聚合，体现技术演化的辩证特征

**辨析**：bash 对 csh 功能的吸收程度在不同 GNU 文档中表述不一，需核对 bash 源代码注释；Ken Greer 1981 年合并 tcsh 至 csh 工作的所属机构在不同来源中表述存在分歧——Arch Linux man tcsh 原文标注 “HP Labs, 1981”（机构为 HP Labs），codearchaeology.dev 与 linux.fandom 等二手来源表述为 “Carnegie Mellon University”；按 0 信任原则以一手 man tcsh 为准，1981 年 12 月合并时 Greer 所属机构为 HP Labs，1970 年代末早期工作可能与 CMU 相关；zsh 首发日期已由 Falstad 原始 comp.sources.misc 发布公告（1990 年）与 zsh.sourceforge.io 项目历史交叉印证；[2026-08-14 两库核查：tcsh（Ken Greer 1981）/bash（Brian Fox 1989）/zsh（Paul Falstad 1990）三者的作者与首发年份两库均无直接条目（参考文献库 facts/people 检索无命中，邮件库 usenet 1981- 未收录 zsh comp.sources.misc 首发公告），两库无法验证，保留存疑]
