# 3.10 与同时期操作系统的比较：CTSS、IBM OS/360、DEC TOPS-10、GEORGE 3 的分时路径

## 3.10.1 CTSS 的分时路径

**要点**：CTSS 1961 年在 IBM 709 上实现，采用内存交换实现多用户分时；虽为分时系统先驱，但内存交换开销大、用户数有限

**史料**：Corbató 1962 AFIPS 论文、CTSS 运行日志 ［A］

**史观**：总纲第 2 条——实践先于理论，CTSS 的工程局限催生 Multics 的系统性改进

**辨析**：CTSS 与达特茅斯 DTSS 谁先实现分时存在争议——CTSS 为研究系统，DTSS 为教学系统，两者目标不同

**文献**：Corbató 1962 AFIPS；Dartmouth 1964 DTSS 报告；国内：计算机分时系统发展综述 ［C］

## 3.10.2 IBM OS/360 的批处理路径

**要点**：IBM 1964 年发布 System/360，配套 OS/360 操作系统；OS/360 以批处理为主，后续 TSO 扩展提供分时能力；OS/360 代码量巨大，软件开发成本超支

**史料**：IBM OS/360 技术手册、Fred Brooks《The Mythical Man-Month》 (19USA ［A］

**史观**：总纲第 3 条——形式主义膨胀的另一案例，OS/360 与 Multics 同期同病

**辨析**：OS/360 的“软件危机”是否直接催生软件工程学科——Brooks 与 Bauer 的叙事侧重不同

**文献**：Brooks 1975“The Mythical Man-Month”；IBM Systems Journal 1964-1968；Bashe et al. “IBM's Early Computers” (1986) ［B］

## 3.10.3 DEC TOPS-10 的分时实现

**要点**：DEC 1966 年为 PDP-10 开发 TOPS-10（原 50 监视器系统），采用内存交换实现分时；TOPS-10 在大学与研究机构广泛使用，为同期 UNIX 的主要竞争者

**史料**：DEC PDP-10/TOPS-10 技术手册、DECUS 用户组文档 ［A］

**史观**：总纲第 6 条——技术路线的分化与并行演化

**辨析**：TOPS-10 与 UNIX 的用户群体重叠度高，但设计哲学截然不同

**文献**：DEC PDP-10 System Reference Manual；DECUS Proceedings 1966-1978 [考据脚注：DEC PDP-10/TOPS-10 为 1966 年开发、在大学与研究机构广泛使用等核心事实经 DEC PDP-10 技术手册与 DECUS 用户组文档交叉验证确证。]

## 3.10.4 GEORGE 3 的多道程序设计

**要点**：英国 ICT/ICL 公司的 GEORGE 3 操作系统，强调多道程序设计与作业调度；为欧洲主流商用操作系统之一

**史料**：ICT/ICL GEORGE 3 技术手册、ICL 公司史 ［A］

**史观**：总纲第 6 条——技术路线的地域分化，欧洲与美国走不同路径

**辨析**：GEORGE 3 与 IBM OS/360 的竞争关系需考据；ICT 与 ICL 的合并历史影响 GEORGE 系列延续

**文献**：ICL“George 3: Technical Description” (1968)；Martin Campbell-Kelly“ICL: A Personal and Corporate Memoir” [考据脚注：GEORGE 3 为英国 ICT/ICL 多道程序设计操作系统、欧洲主流商用系统等核心事实经 ICL 技术手册与 Campbell-Kelly 回忆录交叉验证确证。]
FreeBSD 社区论文：[FP-2020-018] The hidden early history of Unix（Warner Losh（沃纳·洛什），2020）<https://papers.freebsd.org/2020/fosdem/losh-hidden_early_history_of_unix/>

## 3.10.5 Thompson 1984 的跨系统视角：UNIX 流行与小型机转型的耦合

**要点**：Thompson 在 1984 年图灵奖演讲中称，UNIX 的流行是“时机与机缘”与技术价值共同作用的结果，与行业从中央大型机向自主小型机的转变相伴发生；这一自评将 UNIX 的兴起置于硬件转型而非设计优越性的框架下

**史料**：Thompson, K. (1984) “Reflections on Trusting Trust”, Communications of the ACM, 27(8), 761-763（ACM 图灵奖演讲全文） 〔L5 学术论文〕

**史观**：总纲第 6 条——技术路线的分化与并行演化；偶然性优先——UNIX 的流行非“必然规律”，而是与小型机转型时机耦合的具体偶然结果

**辨析**：Thompson 的“时机与机缘”自评与“Multics 反叛 → UNIX 极简”的主流叙事形成张力——他本人更强调行业转型时机而非设计优越性；其特洛伊木马构想另可溯源至一份对 Multics 早期实现安全性的空军批判报告，Thompson 自述无法给出更具体出处，属存疑待考；经参考文献库验证通过（reference_id=22 / reference_id=1158，Thompson 1984“Reflections on Trusting Trust”，全文库含其 ACM 图灵奖演讲全文），演讲题名、作者与 1984 年属实在两库中确证

**文献**：Thompson, K. (1984) “Reflections on Trusting Trust”, Communications of the ACM, 27(8), 761-763 ［B］

**史家判断**（证据等级：L2，来源：`cross_indexes.duckdb.concept_history.14`）

分时思想出现于 1950 年代末：1959 年 Strachey 与 McCarthy 各自提出 time-sharing。1961 年 11 月，Fernando Corbató 与 Robert Daley 等在 MIT 建成并演示 Compatible Time-Sharing System（CTSS），成为首个可运行的分时系统，1963 年发展为稳定大规模系统；其后 CTSS 在 ARPA 支持下演进为 Project MAC（1963 年上线）。1965 年 CMOS 分时设计更上层楼，MIT Project MAC、贝尔电话实验室与通用电气联合启动 Multics（由 Corbató 领导），引入分页、分段存储与树状文件系统；贝尔实验室 1969 年退出，1970 年 GE 计算机业务转售 Honeywell 将其商业化，1985 年被取消。1990 年 Corbató 因在 CTSS 与 Multics 上的开创性工作获 ACM 图灵奖。

**史家判断**（证据等级：L2，来源：`cross_indexes.duckdb.concept_history.17`）

文件系统概念演化大体历经：①顺序/平坦期（1950–1960s）：磁带顺序访问与早期磁盘平面目录；②层次化突破（1960s–1970s）：Multics（始于 1965）首创树状文件目录与路径名，Unix（1970s）以 inode 架构、挂载点、“一切皆文件”简明化并推广层次文件系统；③性能重构期（1980s）：Marshall Kirk McKusick 等为 4.2BSD 设计 Fast File System（FFS/现称 UFS1，1982 年写出、随 4.2BSD 发行），引入柱面组、碎片、软更新，UFS2（2002–2003）改用 64 位块指针扩展至多 TB；④网络化期：Sun Microsystems 1984 年推出网络文件系统 NFS，确立 VFS/vnode 接口；⑤存储与纠错集成期：如 ZFS（2001–2006）将文件系统与卷管理、写时拷贝、校验和集成。

Capsicum 源自剑桥大学计算机实验室 Robert N.M. **史家判断**（证据等级：L2，来源：`cross_indexes.duckdb.concept_history.4`）

1979 年前后（一说 2BSD 时期）引入 chroot(2)，本为构建与测试设计而非安全机制，因可再次 chroot 逃逸而存在已知缺陷。1990 年代末，FreeBSD 开发者 Poul-Henning Kamp 应托管商 Derrick T. Woolworth 付费需求，开发出比 chroot 更强的内核级进程隔离：使每个 jail 拥有独立根文件系统、网络地址与进程空间。jail 随 FreeBSD 4.0（2000-03-14）正式发布，jail(2)/jail(8) API 沿用至今；同月于 SANE 2000 会议发表论文《Jails: Confining the omnipotent root》（Kamp 与 Robert Watson）。后续演进包括 VNET 虚拟网络栈、分层 jail、RCTL 资源限制、ZFS 深度集成，以及 ezjail/iocage/cbsd/Bastille 等管理工具。2013 年 Docker 容器热潮被视为 jail 早已具备的理念。
