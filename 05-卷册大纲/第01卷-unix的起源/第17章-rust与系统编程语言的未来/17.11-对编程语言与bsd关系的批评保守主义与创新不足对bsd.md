# 17.11 对编程语言与 BSD 关系的批评：保守主义与创新不足——对 BSD 社区语言选择保守主义的批评，对 FreeBSD 内核长期拒绝现代语言的工程论证争议，与 Linux 内核 Rust 接纳的对比批评

## 17.11.1 语言保守主义的批评

**要点**：批评者认为 BSD 长期坚守 C 与 shell，对 C++、Rust 等现代语言接纳迟缓，导致内核与基础工具缺乏内存安全与高级抽象

**史料**：freebsd-hackers、freebsd-arch 邮件列表批评性言论、Hacker News 与 Reddit 讨论 ［A］

**史观**：总纲第 3 条与第 4 条——不存在进步只有权力再分配与分离聚合是永恒规律。项目史观总纲第 25 章载 “不存在进步，只有权力再分配”——批评者将 “现代语言必然优于 C” 作为进步叙事本身是一种形式主义膨胀（参第 1 章 1.5 节 “形式主义发展史”）；总纲第 4 条 “分离聚合是永恒规律” 提示 BSD 在 Ports 层语言多样与基本系统保守并存即分离聚合的具体呈现，二者在本体论上地位相等（总纲第 8 条），批评者以 “基本系统保守” 概括 BSD 整体语言态度属范畴错误

**辨析**：批评忽略 “基本系统保守” 与 “Ports 层开放” 的分层——BSD 在 Ports 层提供 C++、Java、Python、Ruby、Rust、Go 等数十种语言，基本系统保守仅为内核与核心工具的语言策略，批评者以 “基本系统保守” 概括 BSD 整体语言态度属范畴错误

**文献**：freebsd-hackers 邮件存档；freebsd-arch 邮件存档；社区博客与论坛讨论 ［A］

## 17.11.2 拒绝现代语言的工程论证争议

**要点**：支持者论证 FreeBSD 基本系统坚持 C 的工程理由：构建依赖最小化、引导编译便利、可移植性、与历史代码兼容；反对者认为这些理由在现代工具链下已可解决

**史料**：freebsd-arch 邮件列表工程讨论、McKusick 著作 ［A］

**史观**：总纲第 17 条与第 23 条——软件工程与社区治理：工程权衡与社区决策的张力

**辨析**：工程论证是否为 “事后合理化”——以 freebsd-arch 邮件列表时序还原决策语境：1990 年代初的 C++ 抵制讨论以 ABI 不稳定为主要理由（GCC 2.7 至 3.x 间 ABI 多次变更），2000 年代的讨论以构建依赖为主要理由，2020 年代的 Rust 讨论以构建时间为主要理由，理由随时代变化但 “保守” 立场一致，说明工程论证与社区保守文化共生而非单方面合理化

**文献**：freebsd-arch 邮件存档；McKusick《Design of 4.4BSD》 (1996)；FreeBSD Source Tree 注释 ［A］

## 17.11.3 与 Linux Rust 接纳的对比批评

**要点**：Linux 2022 年接纳 Rust 入内核，FreeBSD 至 2026 年未跟进；批评者以 Linux 为参照批评 FreeBSD 保守，支持者以 BSD 哲学为由辩护

**史料**：Linux 6.1 Rust 合并、freebsd-arch 对比讨论 ［A］

**史观**：总纲第 4 条与第 25 条——分离聚合与逻辑是形式主义。项目史观总纲第 25 章载 “分离聚合是永恒规律”——Linux 与 FreeBSD 在 Rust 接纳上的路线分化即分离聚合的具体呈现；总纲第 25 条 “逻辑是形式主义而非世界本身的结构” 提示 “BDFL 推动” 与 “Core Team 集体决策” 两种治理结构无本体论高下，二者在本体论上地位相等（总纲第 8 条），事后以 “Linux 接纳 Rust” 为参照批评 FreeBSD 保守是 5.3 节 “记忆将偶然性认识为必然性” 的必然化建构

**辨析**：Linux 接纳 Rust 不构成 FreeBSD 应跟进的充分理由——Linux 采用 BDFL 模式（Torvalds 个人权威推动），FreeBSD 采用 Core Team 集体决策；Linux 内核模块接口（LKM）与 FreeBSD 内核模块接口（kld）设计不同；Linux 有 Red Hat、Google、Microsoft 等大企业投入 Rust 内核工作，FreeBSD 无同等资源；类比论证须先对齐治理结构与资源条件

**文献**：Linux 6.1 Release Notes；freebsd-arch 邮件存档；LWN.net 报道 ［A］

## 17.11.4 批评的形式主义分析

**要点**：从总纲第 3 条形式主义膨胀角度分析，批评本身亦可能陷入 “现代语言必然优于 C” 的形式主义；BSD 的保守或为对另一形式主义的抵抗

**史料**：哲学文献、社区辩论文本 ［B］

**史观**：形式主义膨胀：批评与被批评者皆需警惕形式主义

**辨析**：形式主义分析不消解具体工程争议——哲学层面的 “形式主义膨胀” 批评与工程层面的 “ABI 稳定性” “构建时间” 争议分属不同范畴，前者评估语言选择的哲学立场，后者评估具体技术约束，二者可并行不悖；将形式主义分析误用为工程决策的替代会消解工程争议的具体性，但形式主义分析本身作为哲学审视仍有价值

**文献**：1.md 项目统摄史观；社区辩论存档；McKusick 著作 ［A］
