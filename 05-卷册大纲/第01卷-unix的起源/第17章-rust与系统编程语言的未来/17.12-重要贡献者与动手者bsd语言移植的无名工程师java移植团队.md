# 17.12 重要贡献者与动手者：BSD 语言移植的无名工程师——Java 移植团队、Perl/Python/Ruby Port 维护者、Rust 移植先锋等被忽视的语言生态贡献者

## 17.12.1 Java 移植的无名工程师

**要点**：FreeBSD OpenJDK 移植由 Greg Lewis、Kurt Miller 等社区工程师长期推动，2000 年代起持续维护 OpenJDK 6/7/8/11/17 的 FreeBSD 移植；他们的工作长期被主流叙事遮蔽

**史料**：FreeBSD OpenJDK Port 维护记录、freebsd-java 邮件列表 ［A］

**史观**：总纲第 10 条——动手者创造历史。项目史观总纲第 14 章 14.2 节载 “真正的问题不在于技术发展的程度，而在于是否动手”——Greg Lewis、Kurt Miller 等社区工程师长期维护 FreeBSD OpenJDK 移植即 “动手者” 的主体性在场；其工作 “处于主流叙事边缘” 非因其社会阶层 “边缘”，而是因事后叙事偏向 Core Team 与大幅 commit 的核心开发者（参第 14 章 “史学含义” “史家应记录那些默默做事的老实人，而非只写那些站在台前的大佬”）；14.5 节 “文档与代码的本体平等” 提示 Ports MAINTAINER 字段、freebsd-java 邮件讨论与 OpenJDK 代码本身在本体论上地位相等

**辨析**：贡献者名单以 Ports MAINTAINER 字段与 freebsd-java 邮件列表提交记录交叉核对——Greg Lewis、Kurt Miller 为长期 MAINTAINER，同期贡献者尚有 Jonathan Chen、Bill Fumerola 等，名单不完整因部分早期贡献者已无活跃邮件记录

**文献**：FreeBSD Ports Tree (java/openjdk*)；freebsd-java 邮件存档；提交日志 ［A］

## 17.12.2 Perl/Python/Ruby Port 维护者

**要点**：Perl、Python、Ruby 在 FreeBSD Ports 中的长期维护者包括 Matthew Seaman 等社区工程师；他们处理版本升级、ABI 兼容、安全补丁等琐碎工作

**史料**：FreeBSD Ports Tree MAINTAINER 字段、ports-secteam 邮件列表 ［A］

**史观**：总纲第 10 条与第 23 条——动手者创造历史与社区治理。项目史观总纲第 14 章 14.2 节载 “真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人”——Matthew Seaman 等 Port 维护者处理版本升级、ABI 兼容、安全补丁等琐碎工作即 “动手者” 的主体性在场；14.5 节 “文档与代码的本体平等” 提示 MAINTAINER 字段、提交记录与 port 代码本身在本体论上地位相等；其劳动 “隐性” 非因其社会阶层 “边缘”，而是因事后叙事偏向大幅 commit 的功能新增（参第 14 章 “史学含义”）

**辨析**：维护者署名与实际工作量并非严格对应——部分 port 的 MAINTAINER 字段为 `python@FreeBSD.org`、`ruby@FreeBSD.org` 等团队邮件别名而非个人，实际工作由团队成员分担；个人署名的 port（如早期 lang/perl5 的 Matthew Seaman）工作量集中于版本升级窗口期

**文献**：FreeBSD Ports Tree (lang/perl5、lang/python、lang/ruby)；ports-secteam 邮件存档 ［A］

## 17.12.3 Rust 移植先锋

**要点**：FreeBSD Rust 移植由 Tobias Kortkamp 等社区工程师推动，处理 rustc 与 cargo 在 FreeBSD 上的构建、bootstrap 与架构支持；Rust 移植难度高于传统语言因 bootstrap 链复杂

**史料**：FreeBSD Ports Tree (lang/rust) 提交记录、freebsd-rust 邮件讨论 ［A］

**史观**：总纲第 10 条与第 17 条——动手者创造历史与软件工程。项目史观总纲第 14 章 14.2 节载 “真正的问题不在于技术发展的程度，而在于是否动手”——Tobias Kortkamp 等社区工程师推动 FreeBSD Rust 移植、处理 rustc 与 cargo 的 bootstrap 链即 “动手者” 的主体性在场；其工作 “难度高于传统语言” 非因其社会阶层 “边缘”，而是因 Rust 编译器 bootstrap 链本身的工程复杂性；14.5 节 “文档与代码的本体平等” 提示 freebsd-rust 邮件讨论与 lang/rust 提交记录在本体论上地位相等

**辨析**：Rust 移植未得到 Core Team 专项资源支持——lang/rust 的 MAINTAINER 长期为 Tobias Kortkamp 个人，FreeBSD Foundation 未设立 Rust 移植专项基金，与 Java 移植 2003-2006 年获 Foundation 专项支持形成对照；官方资源有限使 Rust 移植进度依赖个人志愿者

**文献**：FreeBSD Ports Tree (lang/rust)；freebsd-rust 邮件存档；rustc 平台支持文档 ［A］

## 17.12.4 动手者的史料辨析

**要点**：动手者的史料稀缺，多见于 Ports MAINTAINER 字段与提交日志，缺乏自述与访谈；需以提交记录、邮件列表、Ports 历史多重交叉还原其贡献；其姓名散逸非因其社会阶层 “边缘”，而是因事后叙事偏向 Core Team 与大幅 commit 的核心开发者

**史料**：FreeBSD Ports 提交日志、邮件列表、MAINTAINER 字段 ［A］

**史观**：总纲第 10 条与第 5 条——动手者创造历史与没有必然性只有偶然性。项目史观总纲第 14 章 14.2 节载 “真正的问题不在于技术发展的程度，而在于是否动手”，14.1 节载 “什么是老实人？没有多余形式主义的人就是老实人”——Java/Perl/Python/Ruby/Rust 移植维护者的隐性劳动即 “动手者” 的主体性在场，其史料稀缺非因其社会阶层 “边缘”（须严格区分项目统摄史观主张与形式唯物主义批评对象，参第 29 章 29.5 节 “鹿克思” 批评），而是因事后叙事偏向 “台前大佬”（参第 14 章 “史学含义” “史家应记录那些默默做事的老实人，而非只写那些站在台前的大佬”）；总纲第 5 条 “没有必然性，只有偶然性” 提示此类隐性劳动或为历史转折的偶然条件，第 5 章 5.2 节载 “将英雄人物的出现必然化是一种机械的错误”——以史料多寡论英雄即把 “台前大佬” 必然化，无视动手者作为偶然条件的主体性

**辨析**：史料稀缺不等于贡献不重要——以工程影响反推贡献价值：Java 移植使 FreeBSD 在 2000 年代企业 Java 部署中保有一席之地，Perl/Python/Ruby Port 维护使 BSD 系统在 Web 时代保持可用，Rust 移植使 FreeBSD 在 2020 年代 Rust 生态中不缺席；以史料多寡论英雄会系统性低估维护者劳动；须自反地承认 “以工程影响反推贡献价值” 本身亦是一种事后形式主义化的非存在（参第 1 章 1.2 节 “人的一切认识都是形式主义化的非存在”），但此种形式主义化是史家唯一能触及的 “真实”

**文献**：FreeBSD Ports 提交日志；freebsd-java、freebsd-rust 邮件存档；1.md 项目统摄史观 ［A］
