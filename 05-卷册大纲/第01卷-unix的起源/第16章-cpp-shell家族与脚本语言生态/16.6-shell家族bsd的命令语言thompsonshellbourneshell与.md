# 16.6 Shell 家族：BSD 的命令语言——Thompson shell、Bourne shell 与 C shell 的演进，csh/tcsh/bash/ksh/zsh 在 BSD 中的引入与共存

## 16.6.1 Thompson shell 与 Bourne shell：V7 UNIX 的 shell 遗产

**要点**：Ken Thompson 于 1971 年为 First Edition UNIX 编写 Thompson shell（sh），是 UNIX 第一个命令解释器；Stephen Bourne 于 1977-1979 年间在 Bell Labs 为 V7 UNIX（1979）编写 Bourne shell，取代 Thompson shell 成为 AT&T UNIX 默认 shell；Bourne shell 引入了 shell 脚本编程的核心特性：变量、控制结构、函数、here-document 等；早期 BSD（1BSD/2BSD，1978-1979）基于 V6/V7 UNIX，自然继承了 Thompson shell 与 Bourne shell

**史料**：V6 UNIX Manual、V7 UNIX Manual、Bourne S R. An Introduction to the UNIX Shell [J]. Bell System Technical Journal, 1978, 57(6, Part 2): 2797-2822；Mashey J R. The UNIX Shell [J]. Bell System Technical Journal, 1978, 57(6, Part 2): 2823-2838 ［B］

**史观**：总纲第 2 条——实践先于理论：shell 从交互式命令解释需求中演进

**辨析**：Thompson shell 与 Bourne shell 的关系——Bourne shell 并非 Thompson shell 的超集，而是重写；早期 BSD 同时包含 sh（Bourne shell）与新开发的 csh

**文献**：Bourne S R. An Introduction to the UNIX Shell [J]. Bell System Technical Journal, 1978, 57(6): 2797-2822；V7 UNIX Programmer's Manual (1979)；Mashey J R. The UNIX Shell [J]. BSTJ 1978, 57(6): 2823-2838 ［B］

## 16.6.2 C shell（csh）：Bill Joy 与 2BSD 的贡献

**要点**：Bill Joy 于 1978-1979 年间在 Berkeley 为 BSD 开发 C shell（csh），其语法受 C 语言影响，引入了命令历史、别名、作业控制、目录栈等交互特性；csh 首发于 2BSD（1979 年 5 月）；Joy 同时发表《An Introduction to the C shell》（CSRG 技术报告）作为 csh 的入门文档；csh 的历史机制与交互特性使其成为 BSD 用户的首选交互式 shell，与 Bourne shell（脚本编程）形成互补

**史料**：Joy W. An Introduction to the C shell [R]. Berkeley: CSRG, University of California, 1978（2BSD 附带文档）；2BSD Release Notes（1979-05）；Bancroft Library CSRG Archives [考据脚注：经相关权威来源交叉验证。] 〔L3 官方文档〕

**史观**：总纲第 10 条——动手者创造历史。项目史观总纲第 14 章 14.2 节载 “真正的问题不在于技术发展的程度，而在于是否动手”——Joy 1978 年在 2BSD（1979 年 5 月）发布的 csh 开创交互式 shell 新范式即 “动手者” 的主体性在场；事后 csh 因 bash、zsh 兴起而相对式微非因 Joy “边缘”（Joy 在 BSD 史中绝非边缘者），而是因事后叙事偏向 POSIX 标准化后的 shell 生态（参第 5 章 5.3 节 “记忆将许多偶然性认识为一种必然性”）；14.5 节 “文档与代码的本体平等” 提示 csh 的 "An Introduction to the C shell" 文档与 csh 代码本身在本体论上地位相等

**辨析**：csh 的首发版本——Bancroft Library CSRG Archives 与 BSD release notes 多数文献确认 csh 首发于 2BSD（1979 年 5 月），McKusick 2009 年邮件中 "1BSD had Pascal, csh, and ex" 的说法经核对为记忆偏差，csh 实际首发于 2BSD；1BSD 包含 ex 编辑器与 Berkeley Pascal，csh 为 2BSD 新增

**文献**：Joy W. An Introduction to the C shell [R]. UC Berkeley CSRG, 1978；2BSD Release Announcement (May 1979)；McKusick et al. 1996 "The Design and Implementation of the 4.4BSD Operating System" ［B］

## 16.6.3 tcsh、bash、ksh、zsh：多 shell 生态与 Ports

**要点**：tcsh（TENEX C shell）由 Ken Greer 于 1981 年在 CMU 基于 TENEX 命令行特性开发，后经多名贡献者增强，提供命令补全、拼写纠正等增强功能，自 4.3BSD 起可通过 contrib/ 获取，后进入 FreeBSD Ports（shells/tcsh）；Bourne Again shell（bash）由 Brian Fox 于 1989 年为 GNU 项目开发，结合了 Bourne shell 脚本能力与 csh/ksh 交互特性，通过 FreeBSD Ports（shells/bash）提供；Korn shell（ksh）由 David Korn 于 1983 年在 Bell Labs 开发，为 Bourne shell 的超集且加入交互特性，FreeBSD 基础系统自［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 起包含兼容 POSIX 的 pdksh/mksh（shells/ksh）；Z shell（zsh）由 Paul Falstad 于 1990 年开发，功能最为丰富，通过 Ports（shells/zsh）提供；FreeBSD 基础系统长期以 sh（Bourne shell 衍生的 Almquist shell，即 ash/dash 祖先）为 /bin/sh，root 默认 shell；csh/tcsh 长期为 root 与普通用户的默认交互式 shell 选项

## 16.6.4 Shell 脚本与 BSD 系统管理

**要点**：BSD 系统启动脚本（rc.d）、Ports 系统、大量系统工具均使用 Bourne shell 语法（sh）编写；csh 因编程特性缺陷（变量处理、语法不一致）不适合脚本编程，主要用于交互式使用；sh 作为 POSIX 标准 shell 保证脚本可移植性；FreeBSD 基础系统中的 sh 为 Almquist shell 衍生物，轻量且符合 POSIX，不包含 bash 特有扩展

**史料**：FreeBSD rc.d 脚本源码、FreeBSD Porter's Handbook、POSIX 1003.1 Shell Command Language 标准 ［A］

**史观**：总纲第 17 条——软件工程：shell 脚本作为 UNIX/BSD 系统管理的 “胶水语言”

**辨析**：csh 不适合脚本编程——这是 UNIX 社区长期共识，经典论文《Csh Programming Considered Harmful》有详述 [存疑脚注：年份存疑（通行流传版为 1995/1996 年起），引用时以可核验在线版本为准]；系统脚本坚持使用 POSIX sh 是工程与可移植性的选择

**文献**：FreeBSD src/etc/rc.d/ 脚本源码；POSIX 1003.1-2008 Shell Command Language；FreeBSD Porter's Handbook ［A］

- Delphix 的 George Wilson 阐明 Compressed ARC 的设计路线：放弃业界通行的内存换出前压缩方案，利用磁盘块本已压缩的事实，让内存始终保持压缩形态、仅在读取瞬间解压，即“uncompressing data is a heck of a lot faster than compressing it”（2309.42-2314.38）。第一轮激进实现（跨文件系统共享块加回调通知机制）在完成约百分之九十五时暴露重大架构缺陷而中止，第二轮简化方案成为最终交付版本，计划于 2016 年 1 月进入 OpenZFS；实测 ARC 有效容量膨胀约 2.5 至 3 倍，128K 块解压读取约 200 微秒，单核解压吞吐 1.8-2 GB/s，不可压缩块经 shared ARC 共享指针免二次拷贝。（BSD Now EP116，[2258.47-2443.30]，L1）
- Wilson 回顾池恢复工作的起点：入职 ZFS 团队后的首个任务即排查一起客户存储池损坏，通过解析全盘 DD 镜像中的文件头，最终发现损坏根源是一名管理员误将池中磁盘重新分区为 Linux 盘，与 ZFS 本身无关；此后约完成百余次池恢复，多数归因于用户误操作或其他软件的编程错误。他将池恢复视为超越本职、观察用户真实用法的窗口，此叙事呈现了维护者隐性运维经验的生成过程。（BSD Now EP116，[3839.40-3959.18]，L1）

**史观**：

- 总纲25 逻辑是形式主义而非世界本身的结构：cd 的语义由 shell 内建命令与内核 chdir 系统调用共同完成，目录权限由内核强制而非信任用户程序，说明命令语义是经系统调用形式化的产物。（BSD Now EP236，[3777.2-3821.5]，L2）

- 总纲9 经验优先：allocation throttle 反转了跨设备均分分配的理论预设，以客户环境与内部系统的实际观测为准：池碎片化后各设备分配速度分化，索性“why not give more work to devices that are actually responding faster”（2193.18-2199.20），按响应能力倾斜工作负载使快设备保持满载。这一设计出自运维经验而非抽象公平原则，印证经验观测优先于理论均分的工程认识论。（BSD Now EP116，[2145.16-2202.86]，L1）
- 总纲4 分离聚合是永恒规律：Compressed ARC 衍生出 compressed send/receive 复制（由其同事 Dan Kimmel 完成接收端关键工作），后续 ABD 内存表示（以散布-聚集页表取代 KMEM 缓存）源于 Linux 侧设计并回流惠及全部平台，L2ARC 元数据精简则复用块指针校验和以获得 SHA-256/512 级校验。代码在 Illumos/Delphix、Linux、FreeBSD 等平台间分离又聚合，恰是 OpenZFS 时代跨平台分叉之后走向再聚合的活体样本。（BSD Now EP116，[2949.82-3055.54]，L1）
