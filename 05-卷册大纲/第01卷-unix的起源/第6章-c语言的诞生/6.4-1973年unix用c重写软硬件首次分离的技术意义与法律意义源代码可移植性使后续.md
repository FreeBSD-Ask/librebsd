# 6.4 1973 年 UNIX 用 C 重写——软硬件首次分离的技术意义与法律意义（源代码可移植性使后续许可证分发成为可能）

## 6.4.1 1973 年 UNIX 内核用 C 重写的过程

**要点**：**1973 年夏** Ritchie 与 Thompson 用 C 语言重写 UNIX 内核（V4 版本），即 Ritchie's "concerted effort"；Thompson 1978 BSTJ 论文 "UNIX Implementation"（Bell System Technical Journal Vol. 57 No. 6, pp. 1931-1946）中称：

> The UNIX kernel consists of about 10,000 lines of C code and about 1,000 lines of assembly code. The assembly code can be further broken down into 200 lines included for the sake of efficiency (they could have been written in C) and 800 lines to perform hardware functions not possible in C
>
> ——Thompson 1978 "UNIX Implementation" (BSTJ 57.6)

[考据脚注]——按 10000/(10000+1000) ≈ 90.9% C 与 9.1% assembly 的比例，二手文献常概括为 “约 90% C 与 10% 汇编”；Ritchie 1993 HOPL II 论文称 "the bulk of the kernel of the Unix system was rewritten in C during the summer of 1973"；重写前 1972 年夏 Thompson 首次尝试改写内核因协程切换与缺少 `struct` 失败，1972-1973 年 Ritchie 补足语言能力后二人合力完成；保留的约 1000 行汇编用于上下文切换、内存管理等硬件直接操作（其中 200 行本可用 C 但为效率保留，800 行为 C 无法实现的硬件操作）；重写后内核代码量约 11000 行（C+ 汇编合计），比纯汇编内核约增加 30% 但可读性与可移植性显著提升。V4 UNIX 内核代码构成：

| 代码类型 | 行数 | 占比 | 用途 |
| ------ | -- | -- | -- |
| C 代码 | 约 10,000 行 | 90.9% | 内核主体逻辑 | | |
| 效率性汇编 | 约 200 行 | 1.8% | 本可用 C 但为效率保留 | | |
| 必需性汇编 | 约 800 行 | 7.3% | C 无法实现的硬件操作 | | |
| 汇编合计 | 约 1,000 行 | 9.1% | 上下文切换、内存管理等 | | |
| 内核总计 | 约 11,000 行 | 100% | C + 汇编合计 | | |

**史料**：Thompson K 1978 "UNIX Implementation" (Bell System Technical Journal Vol. 57 No. 6, pp. 1931-1946, DOI: 10.1002/j.1538-7305.1978.tb02137.x) [考据脚注]——论文第 1 节 INTRODUCTION 原文 "The UNIX kernel consists of about 10,000 lines of C code and about 1,000 lines of assembly code. The assembly code can be further broken down into 200 lines included for the sake of efficiency (they could have been written in C) and 800 lines to perform hardware functions not possible in C"，经 UC Berkeley CS Prelim 阅读（<https://people.eecs.berkeley.edu/~prabal/resources/osprelim/Tho78.pdf>）与 TUHS V7/usr/doc/implement 文档源码（<https://tuhs.org/cgi-bin/utree.pl?file=V7/usr/doc/implement>）两方独立来源交叉印证，确认引文出自 Thompson 1978 "UNIX Implementation" 而非 Ritchie 1978 "A Retrospective"；早期二手文献常将 “约 90% C 与 10% 汇编” 的二次概括错误归因于 Ritchie 1978 "A Retrospective"，实际 Ritchie 该论文仅讨论 "20 to 40 percent" 的代码膨胀（Ritchie 1993 年 comp.compilers 帖文自述证实，<https://compilers.iecc.com/comparch/article/93-11-018>）；Ritchie 1993 HOPL II 论文（称 "the bulk of the kernel of the Unix system was rewritten in C during the summer of 1973"）；Nokia Bell Labs "From B language to NB to C" 在线史料 ［A］

**史观**：总纲第 1 条与第 19 条——偶然性改写历史：C 重写使 UNIX 从 PDP-11 专属变为可移植系统

**辨析**：[考据脚注] “约 90% C 与 10% 汇编” 数字的来源经多方独立来源交叉印证——该比例源自 Thompson 1978 BSTJ 论文 "UNIX Implementation"（Bell System Technical Journal Vol. 57 No. 6, pp. 1931-1946）第 1 节原文 "The UNIX kernel consists of about 10,000 lines of C code and about 1,000 lines of assembly code"，按 10000/(10000+1000) ≈ 90.9% C 与 9.1% assembly 比例概括为 “约 90% C 与 10% 汇编”；早期二手文献广泛将此引文错误归因于 Ritchie 1978 "A Retrospective" 论文，实际核查发现：(1) UC Berkeley CS Prelim（<https://people.eecs.berkeley.edu/~prabal/resources/osprelim/Tho78.pdf>）公开的 Thompson 1978 论文扫描件第 1 节明确包含此句；(2) TUHS V7/usr/doc/implement 文档源码（<https://tuhs.org/cgi-bin/utree.pl?file=V7/usr/doc/implement>）确认该引文出自 Thompson 1978 论文；(3) Ritchie 本人在 1993 年 comp.compilers 邮件列表（<https://compilers.iecc.com/comparch/article/93-11-018>）明确自述"The only time I recall remarking in print on the relative performance of assembler vs. C was in the BSTJ ‘Retrospective’ paper of 1978 "，引用的 1978 Retrospective 段落是关于" 20 to 40 percent "的代码膨胀，而非 90%/10% 的 C/汇编比例——这进一步印证" 90% C / 10% assembly "的引文并非出自 Ritchie 论文；本节先前将引文归因于 Ritchie 1978" A Retrospective "系错误归因，已修正为 Thompson 1978" UNIX Implementation "；V4 源码本身已不可获取（参见 2.9.2 节），只能依赖 Thompson 1978 与 Ritchie 1978/1993 的事后陈述；“ 1972 失败 ”与“ 1973 成功 ” 是 C 演化的两阶段

**文献**：Thompson K 1978 "UNIX Implementation" (Bell System Technical Journal Vol. 57 No. 6, pp. 1931-1946, DOI: 10.1002/j.1538-7305.1978.tb02137.x)；UC Berkeley CS Prelim 公开扫描件 (<https://people.eecs.berkeley.edu/~prabal/resources/osprelim/Tho78.pdf)>；TUHS V7/usr/doc/implement 文档源码 (<https://tuhs.org/cgi-bin/utree.pl?file=V7/usr/doc/implement)>；Ritchie D M 1978 "UNIX Time-Sharing System: A Retrospective" (Bell System Technical Journal Vol. 57 No. 6, pp. 1947-1969, DOI: 10.1002/j.1538-7305.1978.tb02138.x)；Ritchie D M 1993 "The Development of the C Language" (载于 Bergin T J, Gibson R G 编《History of Programming Languages II》, HOPL II, ACM Press, New York, 1996, ISBN 0-201-89502-1, pp. 671-698; 同时收录于 ACM SIGPLAN Notices Vol. 28 No. 3, 1993)；Ritchie 1993 年 comp.compilers 邮件列表帖文 (<https://compilers.iecc.com/comparch/article/93-11-018)>；Nokia Bell Labs "From B language to NB to C" (<https://www.nokia.com/bell-labs/unix-history/btoc.html>) ［A］

## 6.4.2 软硬件首次分离的技术意义

**要点**：C 重写实现操作系统与特定硬件平台的首次软件抽象分离——UNIX 内核主体可在不同硬件平台重新编译运行，仅少量平台相关代码需重写；此分离为 1977 年 Interdata 832 移植、1978 年 VAX 移植奠定技术基础

**史料**：Johnson & Ritchie 1978 "Portability of C Programs and the UNIX System" (Bell Labs Tech. Journal) ［B］

**史观**：总纲第 4 条——分离是新的聚合的开始：软硬件分离使 UNIX 成为跨平台系统

**辨析**：“首次分离” 的表述需谨慎——Multics 早期也尝试硬件抽象，但 C 重写的彻底性前所未有

**文献**：Johnson, S.C. & Ritchie, D. (1978) "Portability of C Programs and the UNIX System" (Bell System Technical Journal Vol. 57 No. 6) ［B］

## 6.4.3 源代码可移植性对许可证分发的效应

**要点**：C 重写使 UNIX 源代码以可读形式分发成为可能——汇编源码与特定硬件强绑定，C 源码则可在大学间共享与修改；此可移植性成为 1975 年起大学许可证分发的技术前提

**史料**：1975 年 AT&T 大学许可证条款、Bell Labs 内部备忘录、Fiedler 1983 一手来源（原文 "Schools paid $200"指 V5/V6 教育许可证） [考据脚注：AT&T 1975 年大学许可证、仅收约 200 美元介质费等核心事实经 Salus 1994、Kernighan 2019 回忆录与 Fiedler 1983 一手来源三方交叉验证确证；BSD 文献中常见的“150 美元”系部分二手文献对介质费的不同估算（参见 4.3.1 节介质费金额辨析考据脚注）。]

**史观**：总纲第 12 条与第 24 条——法律结构与许可证：源代码可移植性使许可证分发的法律与经济成本大幅降低

**辨析**：源代码可移植性是否为大学许可证的直接技术前提——经济因素（介质费模式）同样关键，需结合 4.3 节分析

**文献**：AT&T 1975 大学许可证条款；Salus 1994 "A Quarter Century of UNIX" [考据脚注：AT&T 大学许可证经 Salus 1994 与 Kernighan 2019 交叉验证确证。]

## 6.4.4 C 重写对 UNIX 传播的推动作用

**要点**：C 重写后 UNIX 在 1974-1978 年间迅速扩散至大学与研究机构，源代码可读性使研究生能够理解与修改操作系统；UNIX 传播速度远超同期汇编操作系统，C 语言成为 UNIX 传播的载体

**史料**：Bell Labs 1974-1978 UNIX 站点列表、Salus 1994 [考据脚注：UNIX 1974-1978 年传播至约 600 个站点等核心事实经 Salus 1994 与 Kernighan 2019 交叉验证确证。] 〔L3 官方文档 + L5 书籍〕

**史观**：总纲第 19 条——信息技术：C 重写作为 UNIX 传播的技术加速器

**辨析**：C 重写与大学许可证何者对传播贡献更大——两者协同，难以单独量化

**文献**：Salus 1994；Kernighan 2019；Ritchie D M 1978 "UNIX Time-Sharing System: A Retrospective" (Bell System Technical Journal Vol. 57 No. 6) ［B］
