## 第 3 章 不同时期人员的采访录

> 本子节为第 3 章“C 语言的诞生”的配套采访录，覆盖 1969-1973 C 语言创生时期 2 位关键人员的自述论文与播客访谈。所有来源均经联网核实，原始 URL 真实可访问；考据过程另见 `原材料/研究/考据记录/` 下对应文件。编纂格式遵 `script/采访录编纂规范.md`。

### C 语言创生者的自述与回忆（1969-1973 时期当事人）

#### 采访 1：丹尼斯·里奇（Dennis M. Ritchie）

**字段 1 采访元数据**

- 受访者：丹尼斯·麦卡利斯泰尔·里奇（Dennis MacAlistair Ritchie），时任贝尔实验室计算科学研究中心研究员，C 语言创始人、UNIX 共同开发者
- 采访者：无（自述论文，为第二届编程语言历史会议 HOPL-II 撰写）
- 采访时间：1993-04（会议宣读），1996 收入论文集
- 采访形式：自述论文（History of Programming Languages 会议论文，后收入论文集）
- 原始来源：Dennis M. Ritchie, "The Development of the C Language", in History of Programming Languages-II, ed. Thomas J. Bergin, Jr. and Richard G. Gibson, Jr., ACM Press (New York) and Addison-Wesley (Reading, Mass.), 1996, ISBN 0-201-89502-1。作者电子版全文 **<https://www.bell-labs.com/usr/dmr/www/chist.html>**
- 存档信息：作者电子版经 WebFetch 抓取可访问（访问日期 2026-07-24），首页明确标注版权声明“Copyright 1993 Association for Computing Machinery, Inc.”与会议信息“presented at Second History of Programming Languages conference, Cambridge, Mass., April, 1993”；互联网档案馆存档链接待补充

**字段 2 采访摘要**

里奇在这篇 HOPL-II 自述中系统回顾了 C 语言的诞生过程：从 BCPL 经 B 语言到 C 的演化路径、1969-1973 年在 PDP-7 与 PDP-11 上的并行开发、类型结构的引入动机，以及 1972 年作为“最有创造力的时期”的关键突破。他详述了 C 语言如何在“微小机器”上作为“改善贫乏编程环境的工具”而诞生，却在日后成为“主导性语言之一”。里奇亦坦承 C 语言的某些设计缺陷（如类型转换的宽松规则）与其历史根源，并对 ANSI X3J11 标准化委员会的工作做了评述。文章涵盖了 1977-1979 年 UNIX 可移植性验证期间的第二波语言变更，以及 1978 年《C 程序设计语言》（K&R）出版的里程碑意义。

**字段 3 考据脚注**

本则自述论文的作者电子版经联网抓取核实，首页明确标注“Copyright 1993 Association for Computing Machinery, Inc.”、会议信息“Second History of Programming Languages conference, Cambridge, Mass., April, 1993”、论文集信息“History of Programming Languages-II ed. Bergin and Gibson, ACM Press and Addison-Wesley, 1996, ISBN 0-201-89502-1”，与 ACM 数字库著录一致。里奇关于 BCPL→B→C 演化路径的陈述，经里奇 1984 年 BLTJ 自述（第 1 章采访 3）中“Unix was born in 1969”及相关语言演化段落交叉验证，时间线一致。其关于 1972 年为“最有创造力的时期”的判断，与克尼汉 2019 年回忆录（第 1 章采访 4）对 1972 年前后 1127 部门创造高峰的描述相互印证。里奇对 C 语言设计缺陷的坦承已作自利偏差审查：当事人主动承认设计不足而非辩护，反而增强了该自述的可信度。完整考据过程见 [20260724_ritchie-hopl2-c-language.md](../../../原材料/研究/考据记录/20260724_ritchie-hopl2-c-language.md)。

**字段 5 史观映射**

- 总纲 2“历史是形式主义化的非存在”——据第 1 章 1.5 节“人类文明历史发展就是形式主义发展史”与 1.5a 节“形式主义即用形式替代具体某个事件”，C 语言从无类型的 BCPL/B 演化出类型结构，恰为形式主义从“非存在”到“存在”的辩证过程。里奇自述展现了类型系统这一形式如何在实践需求中被逐步构建——类型结构非先验存在，而是从 PDP-7 与 PDP-11 的具体硬件约束中被形式主义化出的“非存在”。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.2 节“那种认为‘张三不上李四也会上’的观点，无视了世界上没有必然性只有偶然性这一事实”，C 语言的诞生并行于 UNIX 开发，二者相互塑造；里奇自述中“最有创造力的时期”为 1972 年这一判断，并非暗示某种必然的技术进步，而是偶然条件（PDP-11 的可用性、UNIX 内核重写的需求、类型系统的初步成型）交汇的结果。若坚持“没有里奇也会有另一个人创造 C 语言”，即落入 5.2 节所批之变相君权神授。
- 总纲 9“经验优先”——据第 16 章 16.1 节“越是从经验出发的理解，往往越接近合理性”，里奇自述中 C 语言作为“改善贫乏编程环境的工具”而诞生，并非先有抽象语言理论框架，而是从 PDP-7 与 PDP-11 等“微小机器”的具体硬件约束经验中生发。BCPL→B→C 的演化路径皆为经验驱动的渐进调适，恰为 16.1 节“最质朴、最清楚明白”的认识论模式在语言设计中的呈现。
- 总纲 10“动手者创造历史”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否有人去做”，里奇在 PDP-7 与 PDP-11 上亲手实现 C 编译器与语言定型，是“动手者”在编程语言史中的核心呈现。14.1 节“决定世界的并非某个阶级，也不是什么经济”明确“动手者”不与阶级或经济范畴等同——C 语言的诞生不可归因于某一阶级或经济力量，亦不可简化为“动手做事 vs 理论规划”的二元对立，因里奇本人即是语言设计与编译器实现之合一。然据 14.6 节“某些声称开源的项目，其开发过程实际上相当封闭”，对里奇个人的“动手者”定性须结合其在贝尔实验室享有资源条件加以辩证考察。
- 总纲 11.6“鹿克思：意识形态的虚构”（第 11 章）——据第 11 章 11.6 节“所谓历史唯物主义和辩证唯物主义，是后人编造的，马克思本人连‘物质’都没有定义”，C 语言的诞生不可被叙述为“物质条件（PDP-11 硬件）决定意识（语言设计）”的唯物主义叙事。硬件条件与语言设计互相决定，恰如第 1 章 1.4 节“物质与意识是否依赖或独立取决于具体情况，二者可以相互决定，也可以相互独立”——PDP-11 的字长约束影响了类型系统设计，而 C 语言的设计亦反过来塑造了后续硬件的发展方向。
- 总纲 21“革命与改革是历史方法论的分歧”——据第 21 章 21.1 节“Linux 的发展依靠不断的革命与彻底否定（或在其基础上再发展），而 BSD 这里只是不断的改革”，C 语言的演化路径（BCPL→B→C→ANSI C→C++→C11→C17...）呈改革而非革命之形态。21.3 节“原型先行实际上形成了一种否定之否定的局面，而这实际上是忒修斯之船式的否定——不敢也不能否定主体自身”亦可对照 C 语言长期演化中的兼容性包袱——C 语言至今仍承担 BCPL 时代的某些设计决策，恰为 22.2 节“技术债务是历史设计的代价”之典型案例。
- 总纲 22“知识注定过时”——据第 22 章 22.1 节“今天书写的技术史，可能在出版之日就已过时”与 22.2 节“技术债务是历史设计的代价”，里奇自述中坦承 C 语言的某些设计缺陷（如类型转换的宽松规则）与其历史根源——此即技术债务作为历史遗产在语言层面的呈现。C 语言长期延续并非因其设计完美无瑕，而因其历史遗产被全球数百万用户承担，恰为 22.2 节所述“这一历史遗产至今仍由全球数百万用户承担”。
