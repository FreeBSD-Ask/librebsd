# 6.2 1969-1973 从 B 到 C 的具体演化阶段

## 6.2.1 1969-1970 年 B 语言的早期使用

**要点**：Thompson 1969 年在 PDP-7 上实现 B 语言编译器（circa 1969，精确日期不可考），最初目的是为运行 Space Travel 游戏提供支持；1970 年 Bell Labs 获 PDP-11，B 随之移植到 PDP-11；移植 B 用线程化代码实现，1970 年末 Ritchie 用 TMG 写了一个直接产生 PDP-11 机器码的 B 编译器（替代 Thompson 的线程化代码解释器），使 B 性能提升数倍；B 在 PDP-11 上仍面临根本困境——B 的字寻址模型与 PDP-11 字节寻址不匹配，字符处理效率极低；B 虽用于编写 UNIX 早期实用程序（如 `dc`、早期 `B` 自身编译器），但 PDP-7 内核仍以汇编实现

**史料**：PDP-7 B 编译器源代码（TUHS 存档）、Ritchie 1993 HOPL II 论文、Nokia Bell Labs “From B language to NB to C” 在线史料 ［A］

**史观**：总纲第 7 条——硬件约束的辩证：B 在 PDP-7 上合理但在 PDP-11 上失效

**辨析**：B 语言编写的 UNIX 工具具体清单在不同史料中存在出入；B 是否曾用于编写 PDP-7 内核——答案是否定的，PDP-7 内核以汇编实现；Ritchie 1970 用 TMG 写 B 编译器的具体月份无精确记录，但 Nokia Bell Labs 在线史料明确说 "1970 a PDP-11 was acquired and threaded code was used for the port"

**文献**：Ritchie D M 1993 “The Development of the C Language” (HOPL II)；Nokia Bell Labs “From B language to NB to C” (<https://www.nokia.com/bell-labs/unix-history/btoc.html)>；TUHS V1 源代码档案 ［A］

## 6.2.2 1971-1972 年类型系统的引入

**要点**：Ritchie 1971 年引入 NB（New B）语言，添加字符类型与整数类型区分；1972 年进一步添加 `int`、`char`、`float`、数组与结构体概念，演化为 C 语言雏形；类型引入的核心动机为 PDP-11 字节寻址需要区分字节与字

**史料**：Ritchie 1993 论文、Ritchie 1972-1973 内部备忘录（部分见 Bell Labs Tech. Journal 1978） ［B］

**史观**：实践先于理论：类型系统从硬件约束中生长，而非理论设计

**辨析**：NB 语言是否为正式名称存在争议——Ritchie 在 1993 年论文中称其为过渡性命名

**文献**：Ritchie, D. (1993) “The Development of the C Language” (ACM SIGPLAN Conference HOPL II) ［B］

## 6.2.3 1972-1973 年 C 语言的成型

**要点**：1972 年夏 Thompson 尝试用 C 语言改写 UNIX 内核，因未解决协程切换与缺少 `struct` 数据结构而失败（Ritchie 自述 "the combination of the things caused Ken to give up over the summer"）；1972-1973 年间 Ritchie 增加了 `struct` 数据结构并改进编译器代码生成；1973 年夏二人发起 “concerted effort” 重写整个 UNIX 内核于 C（即 V4 版本），标志着 C 语言成熟并完成自身使命；C 语言演化 “两阶段”——“first phase” 为 B→NB→C 的语言/编译器修改（较快），“second phase” 为内核重写（较慢，因结构体缺失与协程切换问题）——Ritchie 1993 论文与 Nokia Bell Labs “From B language to NB to C” 明确记载此过程

**史料**：Ritchie 1993 HOPL II 论文、Nokia Bell Labs “From B language to NB to C” 在线史料、Ritchie 1975 “C Reference Manual” (Bell Labs CSTR 9) ［B］

**史观**：偶然性中的必然：C 成型是为 UNIX 重写服务的副产品

**辨析**：C 语言 “成型” 的精确时间——Ritchie 自述 "Over the next summer, that was when we made the concerted effort“，1973 年夏为定型；“成型” 前 Ritchie 1972-1973 内部备忘录中已使用 ”C" 名称；Thompson 1972 夏失败为关键转折点

**文献**：Ritchie D M 1993 “The Development of the C Language” (HOPL II, ACM SIGPLAN Notices Vol. 28 No. 3)；Nokia Bell Labs “From B language to NB to C” (<https://www.nokia.com/bell-labs/unix-history/btoc.html)>；Ritchie D M 1975 “C Reference Manual” (Bell Labs CSTR 9) ［B］

## 6.2.4 演化过程中的关键设计决策

**要点**：关键决策包括——保留 B 的简洁语法、引入类型但不强制静态类型检查、数组退化为指针的简化设计、预处理器引入的文本替换机制；每项决策均服务于 UNIX 实现需求而非语言理论完备性

**史料**：Ritchie 1993 论文中对决策的回顾、K&R 1978 第一版、Ritchie 1975 CSTR #31《C Reference Manual》原始技术报告 ［B］

**史观**：总纲第 2 条与第 17 条——实践驱动的工程决策与软件工程理论化的张力

**辨析**：“数组退化为指针” 决策的争议——Ritchie 后来承认此为 “实现妥协”，但部分学者认为此为有意设计。[考据脚注·CSTR #31 数组退化为指针规则的演化痕迹] 其一，Ritchie 1975 年 CSTR #31《C Reference Manual》是 C 语言早期定义的权威一手技术报告，先于 K&R 1978 专著；CSTR #31 记载的 C 语言形态与 Ritchie 1993 HOPL-II 自述在核心演化路径上一致，但对数组与指针关系的原始表述（数组退化为指针的规则）在后续 K&R 1978 专著与 ANSI C 标准中有所修订。其二，这种细节演化本身即是 C 语言从早期形态向标准化演化的证据——CSTR #31 原始表述反映了 PDP-11 字节寻址硬件约束下“数组即指针起点”的工程实用主义考量，K&R 1978 与 ANSI C 标准的修订则体现语言向类型安全方向收敛的演化趋势。其三，按 0 信任原则，Ritchie 1993 自述的硬件决定论叙事（PDP-11 催生类型系统与数组退化规则）可能简化了实际演化过程的多元动因，须与 CSTR #31 同期技术报告与 TUHS V1-V7 代码档案三方互证。其四，CSTR #31 与 K&R 1978 之间数组与指针规则的细节差异，是研究 C 语言从早期形态向标准化演化的关键史料节点（对照卷末书目述评.md 争议二）。

**文献**：Ritchie D M 1975 “C Reference Manual” (Bell Labs Computing Science Technical Report #31)；Ritchie 1993 HOPL II；Kernighan & Ritchie 1978 K&R；Kernighan 2019 [考据脚注：C 语言 “数组退化为指针” 设计决策经 Ritchie 1993 HOPL II 原文与 K&R 1978 交叉验证确证；CSTR #31 数组与指针关系表述的演化痕迹经卷末书目述评.md 争议二史家判断与 CSTR #31、K&R 1978、ANSI C 标准三方对照确证。]
