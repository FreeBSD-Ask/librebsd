# 6.5 C 语言在 Unix 之外的传播与标准化——从学术工具到工业语言

## 6.5.1 C 语言在大学中的传播（1975–1980）

**要点**：随着 V6 与 V7 的大学许可证分发，C 语言作为 UNIX 的系统编程语言一并进入学术机构。1975–1980 年间，UC Berkeley、University of Sydney、University of Toronto、Harvard 等节点成为 C 语言的早期传播中心。1978 年 Brian Kernighan 与 Dennis Ritchie 合著的《The C Programming Language》（K&R C）出版，成为第一本 C 语言标准教材，定义了“K&R C”事实标准。C 语言的语法简洁性与可移植性使其迅速超越 UNIX 生态，进入 CP/M、DOS 等平台。

**史料**：B. W. Kernighan & D. M. Ritchie, “The C Programming Language,” Prentice-Hall, 1978（第 1 版）；Brian Kernighan, “Why Pascal is Not My Favorite Programming Language,” AT&T Bell Labs, 1981（C vs Pascal 语境分析） ［A］

**史观**：总纲第 4 条——技术传播的社会网络效应：C 语言的传播路径与 UNIX 的大学许可证网络高度重合，这是因为 C 最初只能通过 UNIX 许可证获取。这一限制反而加深了 C 与 UNIX 的共生关系。

**辨析**：K&R C 并非 ANSI C 的前身——K&R C 省略了函数原型、void 类型、const 限定符等，其类型安全性远低于现代 C。但正是这种“极简”设计使 C 能够在资源受限的环境中快速实现，推动了其跨平台传播。

**文献**：Kernighan & Ritchie, 1978; Herbert Schildt, “C: The Complete Reference,” 4th ed., 2000（C 语言演化历史附录） ［A］

## 6.5.2 ANSI C 标准化进程（1983–1990）

**要点**：1983 年 ANSI 成立 X3J11 委员会，启动 C 语言标准化工作。该委员会汇集了 AT&T、DEC、IBM、Microsoft、Borland 等厂商的代表，于 1989 年 12 月完成 ANSI X3.159-1989（ANSI C / C89）。1990 年 ISO 采纳为 ISO/IEC 9899:1990（C90）。标准化过程并非一帆风顺——委员会需要调和 K&R C 的既有实践、新兴的 noalias 争议、以及国际化需求（locale、宽字符）。标准化完成后，C 语言正式脱离 UNIX 成为独立的工业标准语言。

**史料**：ANSI X3.159-1989 标准文档；ISO/IEC 9899:1990；P. J. Plauger, “The Standard C Library,” Prentice-Hall, 1992（标准化过程亲历者叙述） ［A］

**史观**：总纲第 3 条——形式主义膨胀的起点：ANSI C 标准化将原本“小巧”的 K&R C 语言扩展为包含百余库函数的形式化规范，这种形式化既保证了跨平台一致性，也为后续 C++/C99 的持续膨胀埋下伏笔。

**辨析**：noalias 争议（1987–1988 年）是标准化进程中最著名的争论——Dennis Ritchie 公开反对委员会提出的 noalias 关键字（认为该语义在 C 的类型系统中不可行），最终委员会撤销了该提案。这一事件揭示了标准化过程中学术权威与委员会政治之间的张力。

**文献**：ANSI/ISO C Standard; P. J. Plauger, 1992; Dennis Ritchie, “noalias” 相关 USENET 帖子（1988，收集于 TUHS 与 comp.lang.c 存档） ［B］

chroot与jail：chroot/jail 容器化概念的演化: 1979 年前后（一说 2BSD 时期）引入 chroot(2)，本为构建与测试设计而非安全机制，因可再次 chroot 逃逸而存在已知缺陷。1990 年代末，FreeBSD 开发者 Poul-Henning Kamp 应托管商 Derrick T.
