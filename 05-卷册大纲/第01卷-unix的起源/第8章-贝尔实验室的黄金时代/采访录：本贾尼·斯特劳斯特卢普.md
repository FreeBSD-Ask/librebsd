#### 采访 1：本贾尼·斯特劳斯特鲁普（Bjarne Stroustrup）

**字段 1 采访元数据**

- 受访者：本贾尼·斯特劳斯特鲁普（Bjarne Stroustrup），时任贝尔实验室计算科学研究中心研究员，C++ 语言创始人与初始实现者
- 采访者：无（自述传记与著作前言）
- 采访时间：持续更新，最近更新 2026-02-11

**字段 2 采访摘要**

斯特劳斯特卢普在其学术主页自述中回顾了自己从丹麦奥胡斯大学到剑桥大学博士、1979 年加入贝尔实验室计算科学研究中心的学术路径。他详述了在贝尔实验室从 Simula 启发到“带类的 C”（C with Classes，1979-1983）再到 C++（1983-）的演化过程，以及《C++ 程序设计语言》四版（1985、1991、1997、2013）伴随语言标准化的成长轨迹。自述中列举了他获得的众多荣誉，包括 2018 年富兰克林研究所 John Scott 奖章、2019 年马德里卡洛斯三世大学名誉博士等，并记录了他从贝尔实验室/AT&T 到德克萨斯 A&M 大学再到哥伦比亚大学的职业变迁。其研究兴趣涵盖分布式系统、设计、编程技术、软件开发工具与编程语言，并长期参与 ANSI/ISO 的 C++ 标准化工作。

**字段 5 史观映射**

- 总纲 2“历史是形式主义化的非存在”——据第 1 章 8.5 节“人类文明历史发展就是形式主义发展史”与 8.6 节“形式主义可以促进社会发展，形式主义也可以毁灭社会”，C++ 在 C 语言之上添加类、继承、多态等形式，恰为形式主义的进一步积累。斯特劳斯特卢普自述展现了面向对象这一形式如何在实践需求（仿真建模）中被逐步引入——此非“非存在”之失败，而是形式主义在工程层面的延续与膨胀。8.6 节提示形式主义两面性：C++ 的形式积累既促进了大型软件组织，亦带来复杂性与编译时延等形式主义毁灭性的一面。
- 总纲 4“分离聚合是永恒规律”——据第 4 章 4.1 节“分离聚合是世界发展的规律。分久必合，合久必分，具有必然性”，C++ 从 C 语言中分离（保留 C 子集但扩展语法）又与之聚合（C++ 至今兼容大多数 C 代码），恰为分离聚合规律在语言演化中的呈现。Simula 的面向对象思想经“带类的 C”聚合入 C 语言谱系，亦为思想聚合之一例。
- 总纲 5“没有必然性，只有偶然性”——据第 5 章 5.2 节“那种认为‘张三不上李四也会上’的观点，无视了世界上没有必然性只有偶然性这一事实”，C++ 的诞生并非面向对象思想演化的必然结果，而是斯特劳斯特卢普在剑桥大学博士阶段接触 Simula、1979 年加入贝尔实验室后因仿真建模需求偶然将二者结合的产物。若坚持“没有斯特劳斯特卢普也会有另一个人创造类似 C++”，即落入 5.2 节所批之变相君权神授。
- 总纲 9“经验优先”——据第 16 章 16.1 节“越是从经验出发的理解，往往越接近合理性”，C++ 的演化并非先有抽象面向对象理论框架，而是从仿真建模的具体经验需求（分布式系统模拟）中生发。“带类的 C”作为改善仿真编程环境的工具，恰为 16.1 节“最质朴、最清楚明白”的认识论模式在语言演化中的呈现。
- 总纲 10“动手者创造历史”——据第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否有人去做”，斯特劳斯特卢普 1979 年加入贝尔实验室后亲手实现“带类的 C”与 C++ 编译器，将 Simula 的面向对象思想在 C 语言之上落地为可用工具，是“动手者”在语言演化史中的呈现。14.1 节“决定世界的并非某个阶级，也不是什么经济”明确“动手者”不与阶级或经济范畴等同——C++ 的诞生不可归因于某一阶级或经济力量，亦不可简化为“动手做事 vs 理论规划”的二元对立。然据 14.6 节“某些声称开源的项目，其开发过程实际上相当封闭”，对斯特劳斯特卢普个人的“动手者”定性须结合其在贝尔实验室享有资源条件与 ANSI/ISO 标准化委员会话语权加以辩证考察。
- 总纲 21“革命与改革是历史方法论的分歧”——据第 21 章 21.1 节“Linux 的发展依靠不断的革命与彻底否定（或在其基础上再发展），而 BSD 这里只是不断的改革。改革的困难远高于革命”，C++ 选择在 C 语言基础上改革（保留兼容性、渐进扩展）而非革命（推翻 C 重新设计），正是 21.1 节所述改革路线的呈现。21.2 节“破山中贼易，破心中贼难”亦可对照 C++ 长期背负的 C 兼容性包袱——改革之困难在于无法彻底摆脱旧形式主义，恰为 21.2 节所述改革者困境。
- 总纲 22“知识注定过时”——据第 22 章 22.1 节“今天书写的技术史，可能在出版之日就已过时”与 22.2 节“技术债务是历史设计的代价”，斯特劳斯特卢普自述中《C++ 程序设计语言》四版（1985、1991、1997、2013）伴随语言标准化的成长轨迹，恰为知识过时与保存之辩证——每一版在出版之时即已落后于语言标准的下一步演化。C++ 长期演化中积累的兼容性包袱（如多重继承的复杂性、模板元编程的不可控膨胀）亦为 22.2 节所述技术债务作为历史遗产的呈现。

**史家判断**（证据等级：L2，来源：`cross_indexes.duckdb.concept_history.4`）

chroot与jail：chroot/jail 容器化概念的演化: 1979 年前后（一说 2BSD 时期）引入 chroot(2)，本为构建与测试设计而非安全机制，因可再次 chroot 逃逸而存在已知缺陷。1990 年代末，FreeBSD 开发者 Poul-Henning Kamp 应托管商 Derrick T. Woolworth 付费需求，开发出比 chroot 更强的内核级进程隔离：使每个 jail 拥有独立根文件系统、网络地址与进程空间。jail 随 FreeBSD 4.0（2000-03-14）正式发布，jail(2)/jail(8) API 沿用至今；同月于 SANE 2000 会议发表论文《Jails: Confining the omnipotent root》（Kamp 与 Robert Watson）。后续演进包括 VNET 虚拟网络栈、分层 jail、RCTL 资源限制、ZFS 深度集成，以及 ezjail/iocage/cbsd/Bastille 等管理工具。2013 年 Docker 容器热潮被视为 jail 早已具备的理念。
