# 8.2 Version 7 的里程碑意义与 Bourne Shell

## 8.2.1 V7 的发布与里程碑意义

**要点**：1979 年 1 月发布 V7（TUHS、gunkies.org 两项独立来源确认为 January 1979），被普遍视为“最后一个研究版 UNIX”；V7 内核约 10,000 行 C 代码 + 1,000 行汇编（Thompson 1978 BSTJ 论文“UNIX Implementation”一手数据，原文"The UNIX kernel consists of about 10,000 lines of C code and about 1,000 lines of assembly code"），引入 uucp、cron、tar、磁盘配额雏形与 Bourne Shell；伴随 VAX-11/780 移植 32V，标志 UNIX 进入 32 位时代；V7 发行版随附 51 KB 内核镜像（TUHS Seventh Edition 页面）

**史料**：V7 源代码 (TUHS Archive research/Dennis_v7)、UNIX V7 手册 (1979)、32V 源码、Bourne 1978 shell 设计文档、Thompson 1978 BSTJ 论文“UNIX Implementation” ［A］

**史观**：总纲第 25 条——终结与延续：V7 既是 Bell Labs 主导期的终结，又是 BSD、System III/V、Xenix 等分支延续的起点

**辨析**：V7 发布日期经 TUHS、gunkies.org 两项独立来源确认为 1979 年 1 月；Bourne Shell 首次出现于 V7（1979 年 1 月发布）；V7 内核 10,000 行 C + 1,000 行汇编的数字源自 Thompson 1978 论文一手表述，与部分二手文献 18,000 行的差异——后者可能涵盖内核 + 用户空间 + 库 + 命令的合计行数，按 0 信任原则以一手 10,000 为准

**文献**：Thompson K 1978“UNIX Implementation” (Bell System Technical Journal 57.6, 原文"The UNIX kernel consists of about 10,000 lines of C code and about 1,000 lines of assembly code“)；Bourne 1978”The UNIX Shell“ (Bell System Tech. Journal)；Ritchie 1984 BLTJ”The Evolution of the Unix Time-sharing System“；Salus 1994；TUHS”Seventh Edition Unix"页面（确认 January 1979、~51 Kbytes 内核镜像） ［B］

## 8.2.2 Bourne Shell 的引入与成熟

**要点**：Stephen Bourne 1976-1978 年于 Bell Labs 设计 Bourne Shell (sh)，V7 首次正式发布；引入流程控制、变量、命令替换、here document；取代 Thompson Shell 成为默认 shell，影响 POSIX shell 与 bash

**史料**：Bourne 1978 BSTJ 文章“The UNIX Shell”、V7 /bin/sh 源代码、Bourne 个人回忆邮件 (TUHS) ［A］

**史观**：总纲第 17 条——软件工程：Bourne Shell 把非交互脚本提升为一等公民，标志 shell 从命令解释器向编程语言演化

**辨析**：Bourne Shell 的 ALGOL 68 风格语法（if/fi、case/esac、while/do/done 等倒序关键字）在 V7 早期是否被 1127 室内部批评存在回忆差异，三方当事人陈述对照如下：其一，Bourne 本人在 1978 年 BSTJ 论文 “The UNIX Shell” 中系统阐述 shell 的结构化设计，采用 ALGOL 68 风格的控制结构（if-then-elif-else-fi、case-in-esac、while-do-done、until-do-done）系受其 ALGOL 68 研究经历影响，Bourne 将此视为 shell 从命令解释器向编程语言演化的必要设计，此为当事人自述立场；其二，Kernighan 在 2019 年回忆录《UNIX: A History and a Memoir》第 9 章中记述了 Bourne Shell 的设计背景与 1127 室内部反响，对 ALGOL 68 式倒序关键字语法的评价需对照原著核实—— Kernighan 一贯的工程审美偏好“小工具 + 文本流”组合，对 Bourne Shell 引入结构化编程语法既认可其提升脚本可读性的一面，亦可能视其 ALGOL 68 风格为与 C 语言为主的 UNIX 工具生态不协调的个人风格标志；其三，McIlroy 在 1978 年 BSTJ 57.6 前言 “Style” 小节中倡导“让每个程序做好一件事”的组件化哲学，对 shell 作为工具组合节点的定位有间接论述，但对 Bourne Shell 具体语法的评价需查 TUHS 邮件列表与后期口述史。[存疑脚注：Bourne、Kernighan、McIlroy 三人对 ALGOL 68 风格语法的具体评价措辞与出处页码待 Kernighan 2019 回忆录英文版原件与 McIlroy 后期 TUHS 邮件列表回忆进一步核实，此处据项目内既有文献引用与计算科学史公认事实整理，按 0 信任原则标注此档案缺口。] 与 csh (Joy 1978) 的关系是并行还是竞争需辨析——Bourne Shell 与 csh 于 1978 年同期出现，前者面向系统脚本编程（结构化、可移植），后者面向交互式使用（C 语法风格、作业控制、历史替换），两者定位互补而非直接竞争

**文献**：Bourne 1978 BSTJ；Joy 1978“An Introduction to the C Shell”；Kernighan 2019 第 9 章 [考据脚注：Bourne shell 1978 年首次发表于 BSTJ、csh 1978 年由 Joy 发布等核心事实经 Bourne 1978 BSTJ 原文与 Kernighan 2019 交叉验证确证。]

## 8.2.3 V7 与 32V 的 VAX 移植

**要点**：V7 伴随 VAX-11/780 移植 32V，标志 UNIX 进入 32 位时代；32V 为后续 3BSD 与 4BSD 在 VAX 上的发展奠定基础；VAX 移植推动 UNIX 从 PDP-11 向更广泛硬件平台扩散

**史料**：32V 源码、VAX-11/780 硬件文档、Ritchie 1984 BLTJ 对 VAX 移植的回顾 ［A］

**史观**：总纲第 19 条——信息技术：V7 与 32V 的 VAX 移植印证了操作系统随硬件演进而迁移的原则

**辨析**：32V 与 V7 的关系是并行还是派生存在叙事分歧；VAX 移植的技术难点需考据

**文献**：Ritchie 1984 BLTJ BLTJ；Salus 1994；32V 源代码 (TUHS) ［A］
