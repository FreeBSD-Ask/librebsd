# 8.3 V6 与 V7 内核结构的演进

## 7.3.1 V6 至 V7 内核规模的膨胀

**要点**：V6 至 V7 内核从约 9,000 行 C 代码 + 2,000 行汇编（V6 发行版规模，TUHS Dennis_v6 镜像一手资料）膨胀至约 10,000 行 C 代码 + 1,000 行汇编（V7 发行版规模，Thompson 1978 BSTJ 论文一手数据），引入可装载子系统雏形、缓冲缓存重构、文件系统 inode 改进、信号机制完善；内核结构仍为宏内核但模块边界清晰化；V7 内核镜像大小约 51 Kbytes（TUHS Seventh Edition 页面），比 V6 显著增加。V6 与 V7 内核规模对比：

| 版本 | C 代码行数 | 汇编行数 | 内核合计 | 内核镜像大小 | 数据来源 |
| -- | -------- | ------ | ------ | ---------- | ------ |
| V6（1975 年 5 月） | 约 9,000 行 | 约 2,000 行 | 约 11,000 行 | — | TUHS Dennis_v6 镜像 | | |
| V7（1979 年 1 月） | 约 10,000 行 | 约 1,000 行 | 约 11,000 行 | 约 51 Kbytes | Thompson 1978 BSTJ 论文 | | |

**史料**：V6/V7 源代码 diff、Lions 注释本、McKusick et al. "The Design and Implementation of the 4.4BSD Operating System" (1996) 对早期内核的回顾、Thompson 1978 BSTJ 论文 ［A］

**史观**：总纲第 3 条——形式主义膨胀：内核规模翻倍本身即形式积累，但通过模块化推迟了失控

**辨析**：V7 内核 10,000 行 C + 1,000 行汇编数字源自 Thompson 1978 论文一手表述；与部分二手文献 18,000 行差异——后者可能涵盖更广范围（内核 + 用户空间 + 库 + 命令合计）。V7 内核的“模块化”程度是否被高估存在争议，两方论据对照如下：其一，“模块化程度被高估”方论据——（1）V7 内核仍为宏内核结构，子系统间无硬件级内存保护，文件系统、进程管理、内存管理、设备驱动等模块共享同一地址空间与全局数据结构，任一模块的 bug 可导致整个内核崩溃；（2）所谓“模块边界”仅为源代码组织约定，非由硬件或语言机制强制执行，C 语言缺乏模块化语言级支持（无 namespace、无 access control），模块间依赖通过全局变量（如 `u` 结构、`proc` 数组）隐式传递；（3）Lions 1977 注释本对 V6 内核的逐行分析显示，内核各子系统间存在密集的交叉调用与共享状态，耦合度高于“模块化”一词所暗示的程度；（4）V7 的“可装载子系统雏形”仅为概念雏形，非现代意义上的动态加载模块（如 Linux 的 LKM 或 FreeBSD 的 kernel module），设备驱动仍静态链接于内核。其二，“模块化程度符合实际”方论据——（1）V7 内核按功能划分为清晰的源代码目录与文件组织（sys、ken、dmr 等目录），开发者可按子系统定位代码，此组织程度优于同期多数操作系统；（2）Lions 1977 注释本得以按章节系统讲解 V6 内核结构，证明内核的模块边界足以支撑教学与分析，此为模块化程度的实证；（3）V7 内核的模块边界虽无语言级强制，但通过编程约定（如头文件接口声明、函数命名约定）在 1127 室团队内部形成事实标准，对约 10,000 行规模的内核而言此约定已足够；（4）V6/V7 的模块边界为 Berkeley BSD 改造提供了接口基础——BSD 1.0 (1977) 得以在 V6 之上添加 vi、ex、Pascal 编译器等组件，证明内核结构具备可扩展性；（5）按 1970 年代技术条件衡量，V7 的模块化程度须与同期操作系统（如 VMS、Multics）比较而非以现代标准衡量，在 PDP-11 资源约束下宏内核是合理选择。其三，按 0 信任原则，两方论据均须与 V7 源代码（TUHS Archive）与 Lions 1977 注释本交叉验证，避免以现代模块化概念套用历史代码。

**文献**：Thompson 1978"UNIX Implementation" (Bell System Tech. Journal 57.6)；Lions 1977；McKusick et al. 1996 第 1 章；V7 源代码 (TUHS) ［A］

## 7.3.2 V6/V7 模块化与 BSD 改造接口的延续

**要点**：V6/V7 内核模块边界的清晰化为 Berkeley 改造提供接口基础；setuid/setgid、文件锁、信号机制等 V6/V7 特性被 BSD 1.0 (1977) 与后续 BSD 版本继承与发展；V6/V7 至 BSD 的延续性是 UNIX 谱系的关键节点

**史料**：V6/V7 源代码、BSD 1.0 源码、McKusick et al. 1996 ［A］

**史观**：总纲第 25 条——终结与延续：V6/V7 至 BSD 的延续性印证了 Bell Labs 主导期终结后 BSD 分支的延续

**辨析**：V6/V7 至 BSD 的具体改造接口需逐项考据；Berkeley 改造的工程边界需明确

**文献**：McKusick et al. 1996 第 1 章；Lions 1977；BSD 1.0 源码 ［A］
