# 8.10 与同时期操作系统的比较：1975-1978 年同期 IBM VM/370（1972，CP-67 演化，虚拟机监控器架构，每个用户拥有虚拟机，内存管理采用段页式）、TENEX（1969，BBN 开发，分时系统，基于 BBN Pager 硬件实现请求调页）、DEC TOPS-10（1972，PDP-10 分时系统，内存交换而非虚拟内存）、Multics（1969，GE-645，段式虚拟内存，环形保护，层级文件系统）——UNIX V6/V7 的技术路线分化：① 内核架构——UNIX 宏内核简洁性 vs VM/370 虚拟机监控器层次化 vs Multics 环形保护复杂化

## 8.10.1 IBM VM/370 虚拟机路径

**要点**：IBM 1972 年发布 VM/370，源自 CP-67 (1967)；架构为虚拟机监控器 (VMM) + 会话监控系统 (CMS)，每个用户拥有完整虚拟机；与 UNIX 宏内核路线形成对照

**史料**：IBM VM/370 系统手册、CP-67 设计文档、Varian 1974“Virtual Memory, Virtual Machines”论文 ［A］

**史观**：技术路线分化：VM/370 选择虚拟机抽象，UNIX 选择系统调用抽象，两者均为 1960 年代思想的工程分化

**辨析**：VM/370 与 UNIX 在企业市场的竞争关系需考据；VM/370 的虚拟机抽象是否为 MULTICS 的“另一回答”存在学术争议

**文献**：Varian 1974“Virtual Memory, Virtual Machines” (Scientific American)；IBM Systems Journal 1981 VM/370 专题；Ceruzzi 2003“A History of Modern Computing” ［B］

## 8.10.2 TENEX 请求调页路径

**要点**：TENEX 1969 年由 BBN 开发，基于 BBN Pager 硬件实现请求调页；1970 年代在 PDP-10 上广泛使用，影响后续 DEC TOPS-20；为分时系统虚拟内存成熟路线

**史料**：BBN 1972 TENEX 报告、PDP-10 TENEX 手册、Bobrow 1972“TENEX”论文 ［A］

**史观**：技术路线分化：TENEX 把虚拟内存作为核心特性，V6/V7 长期无虚拟内存

**辨析**：TENEX 对 VMS 的间接影响需考据；BBN Pager 硬件的具体设计需查 BBN 原始报告

**文献**：Bobrow et al. 1972“TENEX: A Paged Time Sharing System for the PDP-10” (CACM)；BBN Report 1971；Ceruzzi 2003 ［B］

## 8.10.3 DEC TOPS-10 内存交换路径

**要点**：DEC TOPS-10 名称于 1970 年首次启用（release 5.01），源自 1964 年 PDP-6 Monitor 软件，1967 年 release 2.18 加入 PDP-10 KA10 处理器支持 [考据脚注]；为 PDP-10 分时系统，采用内存交换 (swapping) 而非虚拟内存（虚拟内存直至 release 6.01 才引入）；与 TENEX 形成技术对照；在大学与研究机构广泛使用，1970 年代为 UNIX 主要竞争者

**史料**：DEC TOPS-10 System Reference Manual、DECUS Proceedings 1964-1978、archive.computerhistory.org DEC 时间线 [考据脚注：DEC TOPS-10 为 PDP-10 操作系统、DECUS 1964-1978 用户组文档等核心事实经 Computer History Museum DEC 档案交叉验证确证。] 〔L3 官方文档 + L4 事后叙述〕

**史观**：技术路线分化：TOPS-10 坚持交换路线，UNIX V6/V7 亦如此，但 DEC 在 TOPS-20 转向虚拟内存

**辨析**：[考据脚注] TOPS-10 名称启用时间经 DEC 数字技术手册历史记载（“The TOPS-10 name was first used in 1970 for release 5.01”）与二手百科类来源“Timeline of operating systems”（"1964 - TOPS-10 (DEC, the name TOPS-10 wasn't adopted until 1970)"）两方独立来源交叉印证——TOPS-10 名称于 1970 年首次启用，源自 1964 年 PDP-6 Monitor；早期表述“DEC TOPS-10 (1972)”日期错误，1972 年实为 release 5.03 的发布时间（约 1972 年），而非 TOPS-10 名称首次启用时间；虚拟内存直至 release 6.01（约 1977 年）才引入；TOPS-10 与 UNIX 在学术市场的竞争需考据 DECUS 与 USENIX 早期交叉

**文献**：DEC TOPS-10 Manual (1970 起)；DECUS Proceedings 1964-1978；Ceruzzi 2003 [考据脚注：DEC TOPS-10 经 Ceruzzi 2003 与 Computer History Museum DEC 档案交叉验证确证。]

## 8.10.4 Multics 环形保护路径

**要点**：Multics 采用环形保护 (ring protection) 机制，将特权级别分为 8 环；与 UNIX 用户/内核双态形成对照；环形保护影响后续 Intel x86 保护模式设计 [考据脚注]；GE-645 不支持硬件环，Multics 通过软件 trap 实现环过渡；其后继机型 Honeywell 6180 首次以硬件实现 8 环保护

**史料**：Multics System Programmers' Manual (MSPM) 环形保护章节、Schroeder 1972“Cooperation of Mutually Suspicious Subsystems”论文、Schroeder 1972 MIT MAC TR-88 环形保护章节 ［B］

**史观**：形式主义膨胀：Multics 环形保护为完备但复杂的安全模型，UNIX 的双态为简化但实用的妥协

**辨析**：[考据脚注] Multics 8 环保护的实现方式经 Schroeder 1972 MIT MAC TR-88 与 Organick 1972“The Multics System”确认——GE-645 不支持硬件环，Multics 通过软件 trap 实现环过渡；其后继机型 Honeywell 6180 首次以硬件实现 8 环保护；早期表述仅写“8 环”未区分 GE-645（软件 trap 实现）与 Honeywell 6180（硬件实现）两种实现方式，已补充；x86 ring 0/3 是否直接源自 Multics 存在学术争议；Multics 环形保护的实战效果需考据 Multics.org 安全记录

**文献**：Organick 1972“The Multics System”；Schroeder 1972 MIT MAC TR-88；Multics.org 环形保护页面 [考据脚注：Multics 环形保护机制经 Organick 1972 与 Schroeder 1972 交叉验证确证。]

## 8.10.5 UNIX V6/V7 虚拟内存的落后

**要点**：V6/V7 PDP-11 版本采用 swapping 而非 demand paging；32V (1978) 移植至 VAX-11/780 后仍未利用 VAX 虚拟内存硬件；3BSD (1979 年底) 才首次实现 demand paging，落后 TENEX 约 10 年 [考据脚注]

**史料**：V6/V7 内核源代码 swapping 实现、3BSD 虚拟内存文档、Kashtan 1980“UNIX and VMS”对比报告、McKusick“A Berkeley Odyssey” (Unix Review 1985-01)；资料数据库.duckdb 文献计量学统计（C-41、C-42）——references 表总数 16,867 条，年份提取率 44.42%（7,493/16,867，正则 `\b(1[89]\d{2}|20[0-2]\d)\b` 提取自 `gbt7714` 字段），1978 年参考文献 118 条、1979 年参考文献 58 条，合计 176 条，为本时期 Bell Labs 黄金时代末期（V7 发布与 32V/3BSD 起步）的文献积累量化画像；1978 年文献量达 1969-1979 年 decade 峰值（与 1988 年 107 条、1994 年 268 条等后续高峰对应 CSRG 时期），反映 UNIX V7 发布与学术传播的明显加速；bsd_commits.db 数据库交叉印证——BSD commits 数据库 1993 年起，1978-1979 年本时期无 commit 数据，统计结论以 references 表文献计量学分析为主；Python 脚本 `script/phase6_bibliometrics.py` Task 22，查询日期 2026-07-27 ［A］

**史家判断**（证据等级：L2，来源：`cross_indexes.duckdb.concept_history.4`）

chroot与jail：chroot/jail 容器化概念的演化: 1979 年前后（一说 2BSD 时期）引入 chroot(2)，本为构建与测试设计而非安全机制，因可再次 chroot 逃逸而存在已知缺陷。1990 年代末，FreeBSD 开发者 Poul-Henning Kamp 应托管商 Derrick T. Woolworth 付费需求，开发出比 chroot 更强的内核级进程隔离：使每个 jail 拥有独立根文件系统、网络地址与进程空间。jail 随 FreeBSD 4.0（2000-03-14）正式发布，jail(2)/jail(8) API 沿用至今；同月于 SANE 2000 会议发表论文《Jails: Confining the omnipotent root》（Kamp 与 Robert Watson）。后续演进包括 VNET 虚拟网络栈、分层 jail、RCTL 资源限制、ZFS 深度集成，以及 ezjail/iocage/cbsd/Bastille 等管理工具。2013 年 Docker 容器热潮被视为 jail 早已具备的理念。
