# 22.5 UNIX 与 C 的共生演化——系统语言与操作系统

## 要点

UNIX 与 C 语言的共生关系是计算机史上的独特现象——UNIX 是首个用高级语言（C）重写的操作系统内核（1973），C 语言是首个专为操作系统开发设计的高级语言；二者共生演化的核心机制：UNIX 内核、用户态工具、系统库均用 C 编写，使 C 语言随 UNIX 传播至全球大学与企业；C 语言的指针、结构体、位运算等特性直接服务于 UNIX 的文件系统、进程管理、设备驱动等系统编程需求。
1973-1978 年：C 语言随 UNIX V4-V7 传播至伯克利（CSRG）、CMU、MIT 等学术机构，CSRG 在 4.1BSD（1981）与 4.2BSD（1983）中加入大量 C 代码（如 BSD socket API、虚拟内存子系统），4.4BSD-Lite（1994）成为 FreeBSD、NetBSD、OpenBSD 的共同祖先。
1978-1989 年：K&R C（《The C Programming Language》1st ed., 1978）成为 C 语言事实标准，但 AT&T UNIX 源码许可费高昂（约 20,000-40,000 美元/机构），限制 C 语言在商业领域的扩散；GNU 项目（Richard Stallman, 1983 起）用 C 语言重写 UNIX 工具（GCC 1.0 于 1987 年发布），使 C 语言在无 UNIX 许可的情况下扩散。
1989-1994 年：ANSI C（C89）标准化后，C 语言脱离 UNIX 成为独立语言标准；同时 386BSD（1992）、FreeBSD 1.0（1993）、NetBSD 0.8（1993）、Linux 1.0（1994）等开源 UNIX-like 操作系统大量涌现，C 语言成为这些系统的实现语言。
1994-2026 年：FreeBSD、NetBSD、OpenBSD、DragonFly BSD 与 Linux 等开源 UNIX-like 操作系统持续以 C 语言为主要实现语言；FreeBSD 15.x 内核兼容 C23，OpenBSD 7.6 内核使用 C99/C11 子集，Linux 6.x 内核使用 C11（2022 年 Linux 5.18 起从 GNU C89/gnu89 迁移至 gnu11）；同时，操作系统开发引入部分 C++（如 Windows NT 内核部分模块用 C++）、Rust（Linux 6.1 起支持 Rust 内核模块，2022）、Go（部分用户态工具）等语言，但 C 语言仍是系统编程的主导语言。
共生演化的辩证关系：C 语言的类型系统、指针语义、内存模型直接服务于 UNIX 的系统编程需求；UNIX 的文件抽象（一切皆文件）、进程模型（fork/exec）、I/O 模型（read/write）直接塑造了 C 语言的标准库（<stdio.h>、<unistd.h>、<sys/types.h> 等）；BSD socket API（4.2BSD, 1983）成为 C 语言网络编程的标准（后被 POSIX 标准化）；C 语言的标准化（C89）使 UNIX 工具可跨平台移植，但同时使 UNIX 与 C 的绑定关系逐渐松动（C 语言可用于非 UNIX 系统，UNIX 可用非 C 语言实现）。

## 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 4（分离聚合是永恒规律）**——见 据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

UNIX 与 C 语言的共生关系呈现分离聚合——1973-1978 年聚合（C 仅随 UNIX 传播），1978-1989 年部分分离（GNU 项目使 C 脱离 UNIX 扩散），1989-1994 年再聚合（C89 标准化与开源 UNIX-like 系统共同扩散），1994-2026 年再分离（C 用于非 UNIX 系统，UNIX 用非 C 语言实现部分模块）——这一系列分离聚合并非线性进步，而是不同形式主义的循环呈现。

**总纲 1（形式主义是世界的真实存在）**——见 据原文第 1 章 1.1-1.2 节：

> “形式主义是世界的真实存在，其余一切存在皆不真实。”

所谓 “UNIX-C 共生关系” 作为一种形式主义化的建构——UNIX 的文件抽象、进程模型与 C 语言的指针、结构体并非 “客观最优” 的发现，而是 Ritchie 与 Thompson 对系统编程的主体性选择；其他系统语言（如 PL/I 用于 Multics、Pascal 用于 Lisa/Macintosh 早期）与其他操作系统（如 Windows NT 用 C 与 C++、Plan 9 用 C 与 Alef）亦可形成不同的共生关系。

**总纲 3（不存在进步，只有权力再分配）**——见 据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

AT&T UNIX 源码许可费高昂（1978-1989 年约 20,000-40,000 美元/机构），并非 “UNIX 商业化” 的进步，而是商业资本的权力再分配——AT&T 通过源码许可将 UNIX 商业利益集中于自身；GNU 项目（1983 起）用 C 语言重写 UNIX 工具，是将 UNIX 工具的商业利益从 AT&T 重新分配至开源社区；FreeBSD/Linux 等开源 UNIX-like 系统（1990 年代起）进一步将操作系统实现从商业厂商重新分配至开源社区。

**总纲 5（没有必然性，只有偶然性）**——见 据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义。”

若 Dennis Ritchie 未在 1973 年决定用 C 重写 UNIX 内核，若 Richard Stallman 未在 1983 年发起 GNU 项目，若 Linus Torvalds 未在 1991 年发布 Linux，UNIX 与 C 的共生演化会完全不同。所谓 “UNIX-C 共生必然持续至今” 的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——见 据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

Ritchie 与 Thompson 亲自用 C 重写 UNIX 内核，CSRG 团队（McKusick、Karels、Bostic 等）亲自用 C 实现 4.2BSD/4.4BSD，Richard Stallman 亲自实现 GCC，Linus Torvalds 亲自实现 Linux 内核——这些是动手者的实践，而非 “AT&T 决定” 或 “FSF 决定” 等组织决策的产物。

**自反性声明**：本子节选取 “UNIX-C 共生演化” 为主线，但这一选取本身即形式主义化的非存在。若以 Multics-PL/I 共生为主线，若以 Windows NT-C/C++ 共生为主线，若以 Plan 9-C/Alef 共生为主线，“操作系统-语言共生史” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

## 辨析

**1973 年 C 重写的彻底性辨析**：见 22.1 辨析字段（旧记 161.1），部分性能关键路径仍保留汇编。

**AT&T UNIX 源码许可费辨析**：部分二手资料称 “AT&T UNIX 源码许可费约 20,000-40,000 美元/机构”，部分称 “100,000 美元” 或 “5,000 美元”；考据结论：1970 年代末至 1980 年代初，学术机构约 5,000-20,000 美元，商业机构约 40,000-100,000 美元，差异源于机构类型与许可证条款。本子节采用 “约 20,000-40,000 美元/机构（学术机构较低，商业机构较高）” 的限定性表述。

**Linux 内核 Rust 模块辨析**：Linux 6.1（2022）起支持 Rust 内核模块，但截至 2026 年 7 月，Rust 模块仍为可选特性，主要用于驱动程序；Linux 内核核心仍以 C 为主。本子节采用 “Linux 6.1 起支持 Rust 内核模块（可选，主要用于驱动程序），核心仍以 C 为主” 的限定性表述。

**BSD socket API 标准化辨析**：BSD socket API（4.2BSD, 1983）后被 POSIX 标准化（POSIX.1-1988 的 <sys/socket.h>），但 BSD socket API 与 POSIX socket API 有细微差异（如 BSD 的 `struct sockaddr` vs POSIX 的 `struct sockaddr_storage`）。本子节采用 “BSD socket API 后被 POSIX 标准化，二者有细微差异” 的限定性表述。
