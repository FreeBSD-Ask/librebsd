# 22.6 系统语言的多元化——C++、Objective-C、Go、Rust（1979-2026）

## 要点

1979 年，Bjarne Stroustrup（本贾尼·斯特劳斯特鲁普）（Bell Labs）开始开发 “C with Classes”，1985 年改名 C++（《The C++ Programming Language》1st ed., 1985）；C++ 的核心创新在于 “多范式（multiparadigm）”——支持过程式编程、面向对象编程（类、继承、多态）、泛型编程（模板）、函数式编程（lambda、std::function）；C++ 演化：C++98（ISO/IEC 14882:1998）、C++03、C++11（2011，引入 auto、lambda、smart pointer、move semantics）、C++14、C++17（引入 std::filesystem、std:: optional、std:: variant）、C++20（引入 concepts、ranges、modules、coroutines）、C++23（2024，引入 std:: expected、std:: print、std:: flat_map）；2026 年 7 月现状：C++23 为最新标准，C++26 制定中。
1983 年，Brad Cox 与 Tom Love（Stepstone Corporation）设计 Objective-C，融合 C 语言与 Smalltalk 的消息传递机制；1988 年 NeXT（Steve Jobs 离开 Apple 后创立）获得 Objective-C 许可，用于 NeXTSTEP 操作系统；1996 年 Apple 收购 NeXT，Objective-C 成为 macOS 与 iOS 的主要开发语言；2014 年 Apple 推出 Swift（Chris Lattner 主导），逐步替代 Objective-C，但 Objective-C 仍用于 macOS/iOS 遗留代码与 runtime 层。
2009 年，Google（Robert Griesemer、Rob Pike、Ken Thompson 三位 Bell Labs 出身）开始开发 Go 语言，2009 年 11 月开源发布，2012 年 3 月发布 Go 1.0；Go 的核心创新在于 “简洁的并发模型（goroutine + channel）、快速编译、内建垃圾回收、静态类型”；Go 适用于网络服务、云原生（Docker、Kubernetes、Prometheus 等均用 Go 实现），2026 年 Go 1.24 为最新版本。
2010 年，Mozilla（Graydon Hoare 主导）开始开发 Rust 语言，2015 年 5 月发布 Rust 1.0；Rust 的核心创新在于 “所有权（ownership）与借用检查（borrow checker）”——在编译期保证内存安全与并发安全，无需垃圾回收；Rust 适用于系统编程（Firefox 渲染引擎 Servo、Linux 内核模块（Linux 6.1 起）、Windows 内核模块（Windows 11 部分）、FreeBSD 部分用户态工具）；Rust 1.78（2024-05 发布）后按六周节奏滚动发布，截至撰写时版本以 rust-lang.org 官方发布页为准 [存疑脚注：原作“2026 年 1.78 为最新”与版本节奏矛盾，已改按节奏表述]。
其他系统语言：D 语言（Walter Bright, 2001）、Nim（Andreas Rumpf, 2008）、Zig（Andrew Kelley, 2016）、Carbon（Google, 2022，C++ 后继实验语言）等；这些语言在特定领域有一定采用，但未达到 C/C++/Go/Rust 的主流地位。

## 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 4（分离聚合是永恒规律）**——见 据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

系统语言的演化呈现分离聚合——C++ 从 C 分离（引入类与模板）但保持 C 兼容（聚合）；Objective-C 从 C 分离（引入 Smalltalk 消息传递）但保持 C 兼容；Go 与 Rust 从 C++ 分离（拒绝复杂模板与继承）但保留 C 语法风格（聚合）；Swift 从 Objective-C 分离（引入现代语法）但保持 Apple 平台兼容——这一系列分离聚合并非线性进步，而是不同主体在不同历史阶段的形式主义化选择。

**总纲 3（不存在进步，只有权力再分配）**——见 据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

C++ 的演化（C++98 → C++23）并非 “C++ 走向现代化” 的进步，而是商业资本的权力再分配——C++11 引入 lambda、smart pointer 等特性是为了应对 Java/C# 的竞争，C++20 引入 concepts、modules 是为了应对 Rust 的竞争；Go 的诞生是 Google 对 C++ 复杂性的权力再分配（Google 内部系统编程从 C++ 部分转向 Go）；Rust 的诞生是 Mozilla 对 C++ 内存安全的权力再分配（Firefox 渲染引擎从 C++ 部分转向 Rust）。

**总纲 5（没有必然性，只有偶然性）**——见 据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义。”

若 Bjarne Stroustrup 未在 1979 年于 Bell Labs 接触 Simula，若 Brad Cox 未在 1983 年接触 Smalltalk，若 Google 未在 2009 年支持 Go 开发，若 Mozilla 未在 2010 年支持 Rust 开发，系统语言的演化会完全不同。所谓 “C++/Go/Rust 必然诞生” 的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——见 据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

Bjarne Stroustrup 亲自实现 Cfront（首个 C++ 编译器），Chris Lattner 亲自实现 LLVM 与 Swift，Robert Griesemer、Rob Pike、Ken Thompson 亲自实现 Go 编译器与 runtime，Graydon Hoare 亲自实现 Rust 编译器——这些是动手者的实践，而非 “Google 决定” 或 “Mozilla 决定” 等组织决策的产物。

**总纲 2（历史是形式主义化的非存在）**——见 据原文第 2 章 2.5 节：

> “谁试图诠释历史，谁就在篡改历史。”

所谓 “系统语言多元化（1979-2026）” 的判定本身即形式主义化的非存在——若以 C 语言为主线（C 仍是系统编程主导语言），若以内存安全语言为主线（Rust 主导），若以并发语言为主线（Go 主导），“系统语言史” 会呈现完全不同的脉络。本子节选取 “C++、Objective-C、Go、Rust 四大语言” 为主线，但这一选取本身须以自反性声明显化。

**自反性声明**：本子节选取 “C++、Objective-C、Go、Rust” 为系统语言多元化主线，但这一选取本身即形式主义化的非存在。若以 D 语言、Nim、Zig、Carbon 等语言为主线，若以 Java/C#（虚拟机系统语言）为主线，若以汇编语言（嵌入式系统）为主线，“系统语言多元化史” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

## 辨析

**C++ 命名辨析**：部分二手资料称 “C++ 命名源于 ++ 运算符（自增）”，但 Stroustrup 本人确认 “C++ 命名由 Rick Mascitti 于 1983 年建议，源于 ++ 运算符的语义（自增）”。本子节采用 “C++ 命名由 Rick Mascitti 1983 年建议，源于 ++ 运算符语义” 的限定性表述。

**Objective-C 与 Swift 关系辨析**：Apple 自 2014 年推出 Swift 后逐步替代 Objective-C，但 Objective-C 仍用于 macOS/iOS 的 runtime 层与遗留代码；Swift 与 Objective-C 可互操作，但 Swift 并非 Objective-C 的直接后继（语法差异显著）。本子节采用 “Swift 逐步替代 Objective-C，但 Objective-C 仍用于 runtime 层与遗留代码（Swift 与 Objective-C 可互操作）” 的限定性表述。

**Go 与 Rust 定位辨析**：Go 定位为 “简洁的并发系统语言”（适用于网络服务、云原生），Rust 定位为 “内存安全的系统语言”（适用于操作系统内核、浏览器引擎）；二者并非直接竞争关系，而是针对不同场景。本子节采用 “Go 侧重并发与简洁，Rust 侧重内存安全与性能，二者针对不同场景” 的限定性表述。

**Carbon 语言辨析**：Carbon（Google, 2022）为 C++ 后继实验语言，旨在解决 C++ 遗留问题（如头文件、预处理器）；截至 2026 年 7 月，Carbon 仍处于实验阶段（0.x 版本），尚未广泛采用。本子节采用 “Carbon 为 C++ 后继实验语言（2022，实验阶段）” 的限定性表述。
