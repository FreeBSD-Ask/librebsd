# 22.4 C 语言的诞生与演化——K&R C 到 C23（1972-2026）

## 要点

1972 年，Dennis Ritchie 在 PDP-11 上实现首个 C 语言编译器，C 语言正式诞生；C 语言的核心创新在于 “中级语言（middle-level language）” 定位——既具备高级语言的类型系统、结构体、控制结构，又保留低级语言的指针、位运算、内存管理能力；C 语言的类型系统（char、int、float、double、pointer、struct、array、function）使程序员可精确控制内存布局，同时编译器可生成高效机器码。
1973 年，UNIX 内核用 C 语言重写（Ritchie 1973 年 10 月 ACM SOSP 论文 “The UNIX Time-Sharing System”），标志 C 语言作为系统语言的成熟；1973-1978 年，C 语言随 UNIX 传播至大学（伯克利、CMU、MIT 等），C 语言编译器随 UNIX 源码（含 AT&T 许可证）扩散至学术机构。
1978 年，Brian Kernighan 与 Dennis Ritchie 出版《The C Programming Language》（1st ed.，K&R C），K&R C 成为 C 语言的事实标准（直至 1989 年 ANSI C 标准化）；K&R C 的核心特性：无函数原型（function prototype）、隐式 int 返回值、宽松的类型检查、`=` 与 `==` 警告缺失等。
1983 年，ANSI 成立 X3J11 委员会（James Brodie 主持）制定 C 语言标准；1989 年 ANSI X3.159-1989（C89，ANSI C）发布，引入函数原型、`void` 类型、`const` 与 `volatile` 限定符、标准库（<stdio.h>、<stdlib.h>、<string.h> 等）；1990 年 ISO 采纳 C89 为 ISO/IEC 9899:1990（C90，与 C89 仅排版差异）。
C99（ISO/IEC 9899:1999）引入 `long long` 类型、变长数组（VLA）、`_Bool` 类型（C99 关键字，C++ 的 `bool` 已先于 C99 存在）、`<stdint.h>` 定宽整数、`<complex.h>` 复数、`//` 行注释、`__func__` 标识符等。
C11（ISO/IEC 9899:2011）引入 `_Generic` 泛型选择、`_Static_assert` 静态断言、`<stdatomic.h>` 原子操作、`<threads.h>` 线程、匿名结构体/联合、`_Alignas`/`_Alignof` 对齐控制等。
C17（ISO/IEC 9899:2018）为 C11 的修订版（无新特性，仅修复缺陷与澄清歧义）。
C23（ISO/IEC 9899:2024，2023 年草案，2024 年正式发布）引入 `constexpr`、`typeof`、`_BitInt(N)` 任意宽度整数、`#embed` 二进制嵌入、`nullptr`、`bool`/`true`/`false` 关键字（取代 `_Bool`/`true`/`false` 宏）、属性语法 `[[attribute]]` 等。
2026 年 7 月 27 日现状：C23 为最新正式标准，GCC 14、Clang 18、MSVC 19.40 等主流编译器已支持 C23 大部分特性；FreeBSD、NetBSD、OpenBSD 内核与用户态均以 C 语言为主要实现语言（FreeBSD 15.x 内核兼容 C23，OpenBSD 7.6 内核使用 C99/C11 子集）；Linux 内核（6.x）使用 C11（2018 年起从 GNU C89 迁移至 C11）。

## 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 1（形式主义是世界的真实存在）**——见 据原文第 1 章 1.1-1.2 节：

> “形式主义是世界的真实存在，其余一切存在皆不真实。”

C 语言的标准演化（K&R C → C89 → C99 → C11 → C17 → C23）作为一种形式主义化的建构——每个版本的特性选择（如 C99 的 VLA、C11 的 `_Generic`、C23 的 `constexpr`）并非 “客观最优” 的发现，而是 WG14 委员会对不同需求（性能、安全、可移植性、现代化）的主体性权衡。

**总纲 4（分离聚合是永恒规律）**——见 据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

C 语言与 C++ 从分离（C++ 1985 年由 Bjarne Stroustrup（本贾尼·斯特劳斯特鲁普） 在 Bell Labs 设计，基于 C 但引入类、模板等特性）到部分聚合（C99 引入 `//` 行注释、`inline` 关键字等 C++ 特性），再到再分离（C++ 持续演化至 C++23，C 语言保持简洁）——这一系列分离聚合并非线性进步，而是不同主体在不同历史阶段的形式主义化选择。

**总纲 3（不存在进步，只有权力再分配）**——见 据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

C89 标准化并非 “C 语言走向标准化” 的进步，而是商业资本的权力再分配——AT&T、IBM、Microsoft、Borland 等厂商通过 ANSI X3J11 委员会重新分配 C 语言实现的市场份额，使 K&R C 的 “AT&T 主导” 转为 C89 的 “多方厂商主导”。所谓 “C89 标准化是技术进步” 的叙事，掩盖了厂商之间的权力再分配。

**总纲 5（没有必然性，只有偶然性）**——见 据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义。”

若 Dennis Ritchie 未在 1972 年完成 C 编译器，若 Brian Kernighan 未在 1978 年与 Ritchie 合著《The C Programming Language》，若 ANSI 未在 1983 年成立 X3J11 委员会，C 语言的演化会完全不同。所谓 “C 语言必然成为系统语言主流” 的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——见 据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

Dennis Ritchie 亲自实现 C 编译器，Brian Kernighan 亲自撰写《The C Programming Language》，WG14 委员会成员（David Keaton、Tom Plum、Clark Nelson 等）亲自起草与修订 C 标准，GCC/Clang/MSVC 工程师亲自实现 C 编译器——这些是动手者的实践，而非 “ANSI 决定” 或 “ISO 决定” 等组织决策的产物。

**自反性声明**：本子节选取 “K&R C → C89 → C99 → C11 → C17 → C23” 为 C 语言演化主线，但这一选取本身即形式主义化的非存在。若以 GCC 扩展（GNU C）为主线，若以嵌入式 C（C90 子集 + 扩展）为主线，若以 MISRA C（安全关键 C 子集）为主线，“C 语言演化史” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

## 辨析

**K&R C 与 ANSI C 差异辨析**：部分二手资料称 “K&R C 与 ANSI C 仅差函数原型”，但二者差异还包括 `void` 类型、`const`/`volatile` 限定符、标准库扩展、字符串字面量是否可修改（K&R C 可修改，C89 后未定义行为）等。本子节采用 “K&R C 与 ANSI C 差异包括函数原型、void 类型、const/volatile、标准库等” 的限定性表述。

**C99 VLA 弃用辨析**：C99 引入变长数组（VLA），但 C11 将 VLA 改为可选特性（实现可不支持），GCC 仍支持 VLA，MSVC 从未支持 VLA；FreeBSD/Linux 内核不使用 VLA。本子节采用 “C99 引入 VLA，C11 改为可选，GCC 支持 MSVC 不支持” 的限定性表述。

**C23 发布日期辨析**：部分二手资料称 “C23 于 2023 年发布”，部分称 “2024 年”；考据结论：C23 草案（N3220）于 2023 年 2 月完成，ISO/IEC 9899:2024 于 2024 年正式发布（2023 年草案，2024 年正式标准）。本子节采用 “C23 草案 2023 年，ISO/IEC 9899:2024 正式发布” 的限定性表述。

**Linux 内核 C 标准辨析**：Linux 内核在 2018 年前使用 GNU C89 扩展，2022 年（Linux 5.18 起）迁移至 C11；但 Linux 内核使用 C11 子集+GNU 扩展，并非严格 C11。本子节采用 “Linux 内核使用 C11（2018 年起，GNU 扩展）” 的限定性表述。
