## 15.4.1 Ritchie 与 C 语言在 Bell Labs 的诞生

**要点**：Dennis M. Ritchie 于 1972-1973 年间在 Bell Labs 在 B 语言（Ken Thompson 1970）基础上发明 C 语言，用于重写 UNIX 内核；1973 年《Fourth Edition UNIX Programmer's Manual》首次记载 C 语言；1978 年 Kernighan 与 Ritchie 出版《The C Programming Language》（K&R C）；C 语言成为 UNIX 与 BSD 的系统编程语言，贯穿 BSD 全部历史

**史观**：总纲第 2 条与第 20 条——实践先于理论与基础科学：C 从 UNIX 内核重写的工程需求中诞生

## 15.4.3 GCC 进入 FreeBSD：GNU 工具链的接管

**要点**：Richard Stallman 于 1987 年 3 月 22 日发布 GCC 0.9（第一个 beta 版本），随后于 1987 年 5 月 23 日正式发布 GCC 1.0（GNU C Compiler）；386BSD（1992）与早期 FreeBSD（1.0/2.0，1993-1994）已采用 GCC 作为系统编译器，PCC 逐步退役；FreeBSD 基础系统长期使用 GCC 2.7.2.3 → GCC 2.95 → GCC 3.x → GCC 4.2.1 的演进路径；FreeBSD 9.0（2012 年 1 月）仍以 GCC 4.2.1 为默认编译器，同时默认安装 Clang 3.0 作为可选；GCC 采用 GPLv2+ 许可证，为后续许可证争议埋下伏笔。**FreeBSD 基础系统 C 编译器演进**：

## 15.4.4 Clang/LLVM 的崛起与 FreeBSD 编译器切换

**要点**：LLVM 项目由 Chris Lattner 于 2000 年在伊利诺伊大学发起，Clang C/C++/Objective-C 编译器前端于 2007 年首次开源；FreeBSD 社区自 2009 年起推进 Clang 适配，Brooks Davis、David Chisnall（戴维·奇斯纳尔）、Dimitry Andric、Ed Schouten、Roman Divacky 等为核心贡献者；FreeBSD 9.0（2012 年 1 月）默认安装 Clang 3.0 但默认编译器仍为 GCC 4.2.1，WITH_CLANG_IS_CC 选项可切换；FreeBSD 10.0（2014 年 1 月）i386/amd64/arm 等平台正式以 Clang/LLVM 3.3 为默认系统编译器，GCC 4.2.1 不再默认构建（仅 pc98 等少数平台保留）；切换动机包括 BSD 许可证友好（BSD vs GPL）、编译速度更快、错误诊断更友好、模块化架构适合 IDE 集成；GCC 4.2.1 最终从 FreeBSD 基础系统完全移除为 FreeBSD 12/13 时期

## 15.4.5 Fortran 编译器在 BSD 中的演进：f77→f2c→g77→gfortran

**要点**：早期 BSD（1BSD-4.3BSD）包含 Bell Labs 的 f77 Fortran 编译器（与 PCC 配套），为科学计算用户提供 Fortran 77 支持；f2c（Fortran to C 转换器）由 Bell Labs、AT&T 与民间开发者于 1990 年代初开发，可将 Fortran 77 源码转换为 C 代码后用 GCC 编译；GCC 的 g77（GNU Fortran 77）前端自 1990 年代中期进入 FreeBSD Ports 与基础系统，FreeBSD 9.0 基础系统 GCC 4.2.1 仍包含 f77/（即 g77）目录；gfortran 作为 GCC 4.0（2005）引入的新 Fortran 95/2003/2008 前端取代 g77，但未进入 FreeBSD 基础系统（用户需通过 Ports 安装 lang/gcc）；Clang/LLVM 目前无原生 Fortran 前端，Flang（基于 LLVM 的 Fortran 编译器）正在开发中

**史料**：FreeBSD SVN base/release/9.0.0/gnu/usr.bin/cc/f77/ 目录、f2c 官方文档、GCC g77/gfortran Release Notes、FreeBSD Porter's Handbook、freebsd.duckdb 数据库交叉验证——`SELECT DISTINCT cf.file_path, c.author_date, c.message_subject FROM commits c JOIN commit_files cf ON c.commit_hash=cf.commit_hash AND c.repo_name=cf.repo_name WHERE c.repo_name='freebsd-src' AND c.author_date BETWEEN '1993-01-01' AND '1995-12-31' AND (cf.file_path LIKE '%fortran%' OR cf.file_path LIKE '%f77%' OR cf.file_path LIKE '%f2c%') ORDER BY cf.file_path LIMIT 30` 返回 30+ 条 1994-1995 年记录：(1) 1994-01-12 commit aaed6788e756 L Jonas Olsson "Added -o option to rename C output file. This only works when Fortran input is from a file, not stdin."；(2) 1994-05-01 FreeBSD 1.1 RELEASE commit a16f65c7d117 含 `gnu/usr.bin/cc/cc/f77.script`、`include/f2c.h`、`lib/libF77/Makefile`、`lib/libF77/README`、`lib/libF77/Version.c`、`lib/libF77/abort_.c`、`lib/libF77/c_abs.c`、`lib/libF77/c_cos.c`、`lib/libF77/c_div.c`、`lib/libF77/c_exp.c` 等——证实 FreeBSD 1.1 起基础系统已含完整 f77/f2c/libF77 工具链；(3) 1994-07-01 FreeBSD 1.1.5.1 commit 5e0e9b99dc3f 含 `gnu/usr.bin/cc25/usr.bin.f77/Makefile`、`gnu/usr.bin/cc25/usr.bin.f77/f77.script`；(4) 1994-10-25 commit 1f967df0a48e L Jonas Olsson "Added FORTRAN rule"；(5) 1994-10-26 commit a5a29f816ec1 L Jonas Olsson "Install f2c.h for FORTRAN support. Obtained from: netlib.att.com"；(6) 1997-09-15 commit f37c3d0edb12 Jordan K. Hubbard（乔丹·哈伯德） "MFC: a number of trivial cosmetic updates and a fairly large update of f2c"；(7) 1997-09-15 commit 5a5c688432b1 Jordan K. **史观**：总纲第 2 条与第 22 条——实践先于理论与开源运动：Fortran 支持从 Bell Labs 原生工具到 GNU 工具链再到 LLVM 生态的演进

**辨析**：FreeBSD 基础系统中 Fortran 支持的终止时间——FreeBSD 10.0 移除 GCC 后基础系统不再包含 Fortran 编译器，用户需通过 Ports 安装 lang/gcc（含 gfortran）；f2c 曾长期在 Ports 中提供（lang/f2c）；[考据脚注] FreeBSD 1.1（1994-05-01）起基础系统已含 f77/f2c/libF77 完整工具链一事经 freebsd.duckdb 交叉印证——commit a16f65c7d117（"Release FreeBSD 1.1"，1994-05-01）含 `gnu/usr.bin/cc/cc/f77.script`、`include/f2c.h`、`lib/libF77/` 系列文件

**要点**：

- PCC 几乎就是原初的 UNIX C 编译器，主要由 Stephen Johnson 写作，是 1970 年代中后期首个真正可重定目标的编译器；其可移植性设计是当年 UNIX 取得巨大成功的原因之一。该编译器原为 AT&T 授权，直到 2001-2002 年 Caldera 以 BSD 许可证发布后才为公众可得。（BSDTalk EP131，[50.43-92.48]，L1）
- Ragge 复兴 PCC 的偶然路径：他出于对奇异计算机架构的兴趣写过 NetBSD 的 VAX 移植，后受托把 GCC 移植到 PDP-10，却发现 GCC 充满 bug、难以驾驭且远不能为该架构生成合理代码；适逢 Caldera 开放旧 PCC，他判断 1970 年代为奇异架构所写的编译器更易移植，遂将 PCC 移植到 PDP-10 并用它编译 NetBSD 的 PDP-10 版，自 2002 年起作为业余项目持续约五年。（BSDTalk EP131，[102.23-172.27]，L1）
- 工程目标是将这个三十年老编译器改造成小型、可理解、C99 兼容的编译器；已重写寄存器分配器（他自评属当今最佳实现之列），编译器可自举，但开发期间用 GCC 编译 PCC 以免落入自己造成的 bug；当前版本内置大量内部一致性检查以验证生成代码的正确性。（BSDTalk EP131，[174.79-333.31]，L1）
- 性能画像：编译速度约为 GCC 的 10 至 15 倍（同一台机器编译 NetBSD 全源码 GCC 约十小时而 PCC 略超两小时）；生成代码执行速度目前比 GCC 慢 10-20%，但在长整型需双寄存器的 Intel 场景其寄存器分配优于 GCC 3。（BSDTalk EP131，[247.43-362.83]，L1）
- 架构与语言扩展：已有 i386、MIPS、PDP-10 支持（i386 移植仅两天，两小时打出 hello world），PDP-11 与 VAX 旧移植约一天可复活，HPPA 进行中、ARM32 有人启动；PCC 天生前后端分离——语言相关前端经良定义中间格式对接目标相关后端，从旧 BSD 源码复原的 Fortran 77 前端已可直接复用其后端与优化，C++ 前端因日常工作无暇，RISC 所需的延迟加载类交错指令处理尚待补齐。（BSDTalk EP131，[264.59-414.28]，L1）
- 采纳过程：一封宣告邮件引发远超预期的兴趣，OpenBSD 人在数小时内决定将其引入基础系统，NetBSD 导入主源码树，DragonFly BSD 与 MirOS BSD 有人跟进移植；Red Hat 为 Fedora 制作软件包但因许可证条款不能进入主分发版；项目基础设施（网页、wiki、源码树、邮件列表）依托吕勒奥理工大学机房一台旧机器搭建。（BSDTalk EP131，[410.59-631.76]，L1）
- 许可证细节：Caldera 以四条款 BSD 许可证（含广告条款）发布 PCC——随其他产品分发该编译器须在全部广告材料中标注 Caldera 版权；广告条款在 1980 年代即构成使用旧 BSD 代码的实际障碍，现代 BSD 已改用三条款或更少；Red Hat 因无法在主分发版履行广告义务而将 PCC 挪入收录此类许可证软件的独立源码仓库。（BSDTalk EP131，[481.72-550.73]，L1）
- 动机演变与版本策略：Ragge 自承最初并不特别在意许可证（本人即 BSD 用户），只是想让真正的 BSD C 编译器复活；但随着 GPLv3 即将问世且许多人对之不满，BSD 许可证对大量潜在使用者变得极重要；其发布策略为先冻结新开发、打磨 1.0 稳定基线供人编译真实软件，之后再加优化与清理。（BSDTalk EP131，[631.76-767.15]，L1）

**史料**：

- Caldera 于 2001-2002 年以 BSD 许可证开放 PCC 源码（此前为 AT&T 授权私有）；PCC 原作者 Stephen Johnson；项目服务器 pcct.ludde.ltu.se（吕勒奥理工大学）；OpenBSD 与 NetBSD 源码树的导入记录；Red Hat Fedora 打包。（BSDTalk EP131，[80.39-631.76]，L1）
- Ragge 本人的移植工作物：NetBSD VAX port、PDP-10 上以 PCC 编译 NetBSD 的移植实践，为其叙述的直接一手凭据。（BSDTalk EP131，[105.95-167.59]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：PCC 的复兴系一连串偶然的叠加：个人对奇异架构的兴趣、GCC 移植到 PDP-10 的受挫、Caldera 开放源码的时点恰好赶在一封邮件引发的社区热情之前——旧编译器重回三大 BSD 基础系统并非技术演进的必然，而是具体事件与条件的偶然汇合。（BSDTalk EP131，[102.23-447.11]，L1）
- 总纲13 法律与道德是利益分配：许可证条款直接决定代码的流通路径：广告条款使 Red Hat 只能将 PCC 放入独立仓库而无法进入主分发版，现代 BSD 删去广告条款后三条款成为流通标准——许可证的文本差异即利益分配机制的差异，其后果由分发者与使用者的实际选择显现。（BSDTalk EP131，[510.47-550.73]，L1）
- 总纲21 革命与改革是历史方法论的分歧：GPLv3 的出台促使 BSD 阵营以引入自主许可的编译器作为路线回应：copyleft 强制路线与 BSD 自愿路线在工具链层面的分歧，经由 OpenBSD 对 PCC 的数小时导入行动具体化。（BSDTalk EP131，[756.64-767.15]，L1）
