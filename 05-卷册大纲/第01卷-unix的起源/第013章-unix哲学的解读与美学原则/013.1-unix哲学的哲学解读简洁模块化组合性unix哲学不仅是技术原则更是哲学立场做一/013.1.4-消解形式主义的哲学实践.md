# 013.1.4 消解形式主义的哲学实践

**要点**：UNIX 哲学作为 “消解形式主义” 的哲学实践——通过小工具组合消解大全系统的形式主义；此实践与道家 “大音希声”、禅宗 “不立文字” 形成跨文化共鸣

**史料**：Pike 1983、McIlroy 1986 AT&T Tech. Journal、跨文化哲学文献 ［B］

**史观**：总纲第 3 条与第 14 条——哲学思潮：UNIX 哲学与东方哲学的跨文化共鸣

**辨析**：UNIX 与道家/禅宗的关联为事后建构——Thompson、Ritchie、Pike、McIlroy 在公开文献与访谈中均未表达过道家或禅宗立场，关联由 Raymond 2003 "The Art of Unix Programming" 第 1 章首次系统化建立，本书沿用此建构性解读但须明确其为史观投射而非 UNIX 设计者的文化自觉

**文献**：Pike 1983；老子《道德经》；铃木大拙《禅学入门》 [考据脚注：经 Pike 1983 USENIX 论文原文与《道德经》《禅学入门》通行版本交叉验证。]

**要点**：

- Frederic Cambus 记述 OpenBSD 的 airport(7) 文件与相关习俗：2016 年他向 tech 邮件列表提交波兰机场代码补丁，Theo de Raadt 私下指出存在一条开发者圈内已知但从未成文的规则，即新机场代码只能由亲自到访并验证其存在的 OpenBSD 开发者添加。（BSD Now EP460，[1132.86-1244.26]，L2）
- 该规则于 OpenBSD 某次 hackathon 被写入新引入的 airport(7) 手册页，且不要求实际乘机，只需到访即可，Cambus 遂以一日游方式到访卢布林机场并提交 LUZ 代码。（BSD Now EP460，[1173.42-1246.9]，L2）
- 一篇关于极简窗口管理器的文章认为，真正符合 Unix 哲学的极简窗口管理器尚不存在，dwm 因内置状态栏与按键映射违反模块性与组合原则，bspwm 虽更模块化但仍过于特定，作者由此着手自写窗口管理器。（BSD Now EP460，[890.6-1132.86]，L2）
- containerD 获得在 FreeBSD 上启动 Linux 容器的支持，其机制类似 jail 与 chroot 的路径前缀查找，使 Alpine 或 Ubuntu 等发行版可借 FreeBSD 的 Linux 兼容层运行。（BSD Now EP460，[76.0-160.8]，L2）
- Norling 的 BSD 入门由家庭器物与文献启蒙双重促成：丈夫是 DEC 计算机收藏者，修复完毕便失去兴趣，她遂坐拥满车库 PDP-11 与 VAX 可玩；因厌恶 VMS 命令行的括号语法而决意在 VAX 上装 NetBSD——时值 OpenBSD 尚无 VAX 移植（后来补上），NetBSD 的可移植性正合其手头硬件；读惯 GNU 风格的 man 与 info 页曾令她自疑不适应 UNIX，直到偶然读到 OpenBSD 的 find 手册，其清晰精确令她醒悟问题在文档而非自己，由此转向 BSD 并盛赞其手册与系统整洁度；FreeBSD 则始终未正经安装。（BSDTalk EP143，[314.44-418.04]，L1）
- 以当事人身份梳理辅助技术器物史：所谓盲文终端今实为盲文显示器——串口、蓝牙或 USB 的显示外设，昔日确有真终端形态的盲文 VT100（盛行于德国），名词却如 Kleenex 般固化；欧美制度差异决定普及率——欧洲有政府资金购置设备且学校强制低视力者学盲文，美国设备昂贵（一万美元级），主流转向语音合成与屏幕放大；她曾任盲文显示硬件厂商技术支持，得以在 eBay 以 65 美元捡得价值一万美元的显示器。语音合成方面，1980 年代为带并口/串口与语音芯片的硬件盒（Echo PC、Votrax Personal Speech System），1990 年代中 CPU 够快后软件合成渐成主流，分拼接与共振峰两路，开源代表为 C++ 所写的小足迹共振峰合成器 eSpeak 与 CMU 系的 Festival；合成器之上还须有屏幕访问程序智能转译屏幕内容，而以数字键盘操控的传统令笔记本用户无从施展。 [存疑脚注] 转写中的软件/硬件合成器名 WIDMode 无法辨识，具体型号待核（BSDTalk EP143，[434.32-702.42]，L1）
- BSD 可访问性的实况：因 BSD 无本地屏幕阅读器，她以 Windows 机器作终端、运行屏幕阅读程序连入 BSD，语音与盲文并用——语音为主因其快，盲文则如打印稿用于写码回看；纯文本应用尚可，curses 界面的高亮、反显与光标分离须靠智能推断焦点，links 之类浏览器须专门选项标示当前链接，操作繁琐；而她认定最需改进的竟是文档——headless 安装文档默认读者是装过无数遍的服务器老手，盲人却常做 headless 安装且可能是首次接触该系统，不知须等多久方能敲入切换串口的命令（OpenBSD 用 `set tty com0`，NetBSD 用 `com0`，FreeBSD 的 `boot -h` 她从未成功）；并指出每个全盲者背后约有十个低视力者，受众绝非小众。（BSDTalk EP143，[704.92-896.30]，L1）
- 入门路径与方法论：其一，借用 SDF 的免费 shell 账号（freeshell.org，社区内已有盲人与视障者群体），免于硬件折腾；其二，SimH——纯控制台应用、对屏幕阅读器完全可及的旧机模拟器（PDP-11、VAX 3900、VAX 780 等，可运行于三大 BSD、Linux 与 Windows），可随时保存状态，恰是 VMware 等不可及方案之外的活路；其三，在带串口或可靠 USB 串口的机器上 headless 安装 BSD（OpenBSD 最易装而后续加装软件最难，NetBSD 提供带串口 boot block 的软盘）；架构层面 i386 的 BIOS 多不可经串口访问，Compaq ProLiant 系列却是例外而许多盲人不知；方法论上强调最小化同时学习的对象，邮件列表上盲学生常因贪多而被压垮。（BSDTalk EP143，[1144.80-1261.44]，L1）

**史料**：

- Frederic Cambus 的博客与 OpenBSD airport(7) 手册页共同构成 airport 文件习俗的一手记载，其补丁与 Theo de Raadt 的私下回复均可溯源。（BSD Now EP460，[1136.02-1184.7]，L2）
- HardenedBSD 2022 年 5 月状态报告与 DragonFly BSD 6.2.2 变更日志，记录 chroot 限制、无调试内核更新、HAMMER2 修复等版本级工程事实。（BSD Now EP460，[1444.3-1739.18]，L2）
- 口述可考的一手器物与实践：家中 PDP-11 多型（11/53 正试验不同 MSCP 控制器与硬盘，另有 11/04、其自有的 11/83，因体积弃 11/780）；BRLTTY（转写误作 Bell TTY）在 VAX 上的移植编译尝试（PC 上于 NetBSD 与 OpenBSD 均编译无误）及其经 pkgsrc 的构建；SimH 项目站点 simh.trailing-edge.com；SDF 公共 UNIX 系统与其视障社群；Linux 侧的 SpeakUp 内核补丁、其邮件列表与 LDP 文档——她由 Linux 可及性入道三年后再转 BSD。 [存疑脚注] BRLTTY 系据上下文（盲文驱动、pkgsrc 编译）对转写 Bell TTY 的辨识；SDF 会员等级转写含混（BSDTalk EP143，[113.32-194.40]，L1）

**史观**：

- 总纲15 文化即形式主义：airport(7) 规则本为开发者圈内默契，经一次补丁触发才被成文固化，显示社区文化以非正式实践维系并最终形式化，属文化即形式主义的例证。（BSD Now EP460，[1143.58-1184.7]，L2）
- 总纲20 历史地理塑造思想土壤：airport 文件要求开发者亲访机场验证存在，把地理经验与代码贡献绑定，体现历史地理与社区实践的相互塑造。（BSD Now EP460，[1184.7-1244.26]，L2）
- 总纲9 经验优先：她的 UNIX 观完全长自使用经验：DOS 下筛选目录须听合成器念完冗长输出，而一条 grep、cut 加参数的管道只让她听子目录名，awk 令小改动唾手可得——对盲人而言，过滤与组合不只是工程风格，而是把阅读负担一并滤掉的效率机制；专业上她靠 Windows 技术支持谋生，个人时间却只属于命令行。（BSDTalk EP143，[972.18-1011.76]，L1）
- 总纲8 本体论上各方平等：她点破系统文档里潜藏的单一用户形象：headless 安装被默认为“拥有众多服务器、装过百万遍系统的大叔”之事，而视障者恰恰是 headless 安装的常态用户；要求以初学者与视障者视角重写文档，等于主张视障用户在本体上与其他用户平等，其需求不是边缘特例而是系统书写应予正视的常项。（BSDTalk EP143，[822.26-896.30]，L1）

**辨析**：

- airport(7) 规则在转写中被归于 OpenBSD hackathon 写入，但具体是哪一次 hackathon 及成文时间需查手册页修订记录与邮件列表。 [考据脚注] airport(7) 手册页引入的具体时间与 hackathon 场次需查 OpenBSD CVS 与 Undeadly 记录。（BSD Now EP460，[1173.42-1184.7]，L4）
- 若干个体经验不可外推为系统事实：FreeBSD 的 `boot -h` 在她处从未成功仅是单人经历，不能据此断定 FreeBSD 串口引导存在缺陷，须以引导机制文档与 headless 安装指南复核；转写层面，BRLTTY 被记作 Bell TTY、Compaq ProLiant 被记作 compact ProLiance、语音合成器型号 WIDMode 不可辨识，引用相关名物时均须据原始史料校正。 [存疑脚注] FreeBSD boot -h 失败为单一来源个体经验；转写名物辨识均待核（BSDTalk EP143，[856.42-877.38]，L4）
