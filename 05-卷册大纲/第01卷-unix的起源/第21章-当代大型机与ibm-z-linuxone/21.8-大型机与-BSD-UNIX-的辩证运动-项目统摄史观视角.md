# 21.8 大型机与 BSD/UNIX 的辩证运动——项目统摄史观视角

## 要点

大型机与 BSD/UNIX 谱系的关系典型呈现项目统摄史观的辩证运动——大型机与 UNIX 并非 “大型机决定 UNIX” 或 “UNIX 决定大型机” 的单向因果，而是互为形式主义化的辩证共构：Multics 作为 GE-645 大型机上的分时操作系统（1964-1969）直接启发了 UNIX 在 PDP-7 小型机上的极简重构（1969），而 UNIX 通过 C 语言重写（1973）获得源代码可移植性后，反向影响大型机的 UNIX 化（IBM IX/370 1985、AIX 1986、z/OS UNIX System Services 2001）；同时，BSD 4.1a/4.1c/4.2 在 VAX-11/780 小型机上的虚拟内存重构（1980-1983）反向影响了 IBM MVS/XA 的 31 位地址空间设计（1981），IBM VM/370 的虚拟机技术（1972）反向影响了 BSD jail（1999，Kirk McKusick 与 Poul-Henning Kamp）与 Linux Containers（2008，LXC）的虚拟化路径；至 2026 年 7 月 27 日，Linux on Z 作为 “UNIX 化的大型机” 与 FreeBSD/OpenBSD/NetBSD 作为 “小型机化的 UNIX” 在云原生时代重新交汇——Linux on Z 通过 OpenShift 4.x 容器化与 BSD 通过 containerd/Podman 容器化共享同一容器运行时接口（OCI 规范）。
大型机作为 UNIX 的 “他者” 在三个维度呈现辩证张力：(1) **分时 vs 批处理**——UNIX 源自 Multics 分时理想主义，大型机源自 S/360 批处理商业实用主义，但二者在演化中相互吸收——MVS/TSO 吸收分时能力，BSD 的 at/atrun/batch 批处理设施（与 cron 并列的定时/批处理命令族）；(2) **开源 vs 专有**——BSD 谱系以 BSD 许可证开源，大型机以 IBM 专有许可证封闭，但 IBM 在 2000 年后通过 Linux on Z、EPL 协议贡献 Eclipse、CPL 协议贡献 Linux 内核代码部分 “开放化”，而 BSD 社区对 “专有 BSD”（如 macOS、Junos、NetApp ONTAP）的接纳体现 “开源 vs 专有” 的辩证张力；(3) **商品形式主义化的不同呈现**——大型机以 “生态锁定” 为形式主义化（五十年二进制兼容、专有硬件、专有操作系统），BSD 以 “开放生态” 为形式主义化（POSIX 兼容、源代码可移植、多硬件平台），但二者皆受 “商品召唤” 机制驱动，皆非 “客观技术必然”。
项目统摄史观视角下，所谓 “大型机被 UNIX 替代” 或 “UNIX 被大型机吸收” 的目的论叙事皆需被超越——大型机至 2026 年仍在银行核心、航空订票、政府数据中心延续，UNIX/BSD 至 2026 年仍以 macOS、iOS、Junos、PS4/5 操作系统、PlayStation 系统软件等形式延续，二者并非 “一方取代另一方”，而是 “分离聚合的辩证共构”——大型机与 UNIX/BSD 在不同应用场景中持续重构各自的物质基础与形式主义化路径，这正是总纲 4 “分离聚合是永恒规律” 的呈现。

#### 史观

本子节史观映射覆盖以下 7 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 4（分离聚合是永恒规律）**——见 据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。UNIX 分裂出各种 BSD，BSD 又分裂出 FreeBSD、NetBSD、OpenBSD、DragonFly BSD，此乃分离；而各分支间的代码共享、ports 互通、社区人员的流动，此乃聚合。”

大型机与 BSD/UNIX 谱系的关系是分离聚合的典型——Multics 从大型机谱系中分离，聚合为 UNIX 在小型机上的极简重构；UNIX 从小型机谱系中分离，聚合为 BSD 在工作站与 x86 上的多平台扩散；BSD 从 UNIX 谱系中分离，聚合为 FreeBSD、NetBSD、OpenBSD、DragonFly BSD；大型机通过 Linux on Z 重新聚合 UNIX 谱系（Linux 是 UNIX 化的操作系统）。这种分离聚合并非 “进步”，而是不同硬件、不同应用场景、不同社区驱动的主体的辩证运动。

**总纲 2（历史是形式主义化的非存在）**——见 据原文第 2 章 2.2 节：

> “历史从来都没有存在过，或者说，存在过，但是只有一种古代史。认为时间是线性的并无依据。谁试图诠释历史，谁就在篡改历史。”

所谓 “大型机决定 UNIX” 或 “UNIX 决定大型机” 的因果叙事，是史家的事后重构——Multics 启发 UNIX 的过程涉及 GE-645 撤离、Thompson 在 PDP-7 上的 “Space Travel” 游戏、Ritchie 在 B 语言上的 C 演化、Kernighan 的命名等多重偶然；UNIX 反向影响大型机的路径涉及 IBM 内部多次评估、AIX 项目立项、Linux on Z 商业决策等多重偶然。本子节拒绝 “硬件决定软件” 或 “软件决定硬件” 的技术决定论叙事，承认因果叙事本身即形式主义化的非存在。

**总纲 3（不存在进步，只有权力再分配）**——见 据原文第 3 章 3.2 节：

> “任何宣称时代的变革、现代化的不同、大变局，本质上都是为了达成自己的目的。所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

所谓 “UNIX 替代大型机” 或 “大型机被 Linux 吸收” 的叙事，并非 “技术进步导致大型机退场”，而是市场份额与话语权的权力再分配——UNIX/BSD 在工程与学术市场夺取了大型机的部分话语权，Linux 在企业市场夺取了大型机的部分话语权，但大型机在银行核心、航空订票、政府数据中心仍保有不可替代的话语权。所谓 “大型机终结” 是形式主义化的判定，掩盖了大型机在特定场景的延续性。

**总纲 5（没有必然性，只有偶然性）**——见 据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义。那种认为‘张三不上李四也会上’的观点，无视了世界上没有必然性只有偶然性这一事实。”

Multics 退场与 UNIX 诞生、IBM 1985 年推出 IX/370、IBM 2000 年推出 Linux on Z、IBM 2018 年收购 Red Hat——这些节点皆不可替代的偶然。若 Thompson 当年未在 PDP-7 上写 “Space Travel”，若 IBM 当年未与 Interactive Systems Corporation 签订 IX/370 合同，若 Linus Torvalds 当年未在 1999-2000 年合并 S/390 patch，若 IBM 当年未收购 Red Hat，大型机与 BSD/UNIX 的辩证运动会呈现完全不同的路径。所谓 “UNIX 必然影响大型机” 或 “Linux 必然登上大型机” 的目的论叙事是史家的事后重构。

**总纲 11（商品是形式主义）**——见 据原文第 8 章 8.1 节：

> “商品本身是一种形式主义。不是人们在追求商品，而是商品在召唤人们。”

大型机与 BSD/UNIX 谱系作为商品形式主义化的不同呈现——大型机以 “五十年二进制兼容” 召唤银行与政府客户群，BSD 以 “POSIX 兼容与源代码可移植” 召唤学术与开源客户群，Linux on Z 作为 “UNIX 化的大型机” 召唤 “既需大型机可靠性又需开源生态” 的客户群。所谓 “开源 vs 专有” 的二元对立是形式主义化的判定，掩盖了商品形式主义化的多元路径。

**总纲 10（动手者创造历史）**——见 据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者。”

Thompson 亲自在 PDP-7 上写 UNIX 雏形的文件系统，Ritchie 亲自在 PDP-11 上调试 C 编译器，McKusick 亲自在 VAX-11/780 上调试 4.2BSD 的虚拟内存，Creasy 亲自在 Cambridge Scientific Center 调试 CP/CMS 的虚拟机调度，Linus Torvalds 亲自合并 S/390 patch 进入 Linux 主线，Red Hat 工程师亲自在 z/VM 上验证 RHEL 8.1——这些是动手者的实践，而非 “大型机战略” 或 “UNIX 战略” 的产物。须注意：项目统摄史观的 “动手者” 指 “没有多余形式主义的老实人”，与厂商、阶级、经济无直接等同关系。把 Thompson 等同于 “小型机英雄” 或把 Creasy 等同于 “大型机精英” 皆落入项目统摄史观批评的形式唯物主义对象。

**总纲 27（自反性是项目统摄史观的内在要求）**——见 据原文第 27 章：

> “项目统摄史观的自我批评是项目统摄史观的内在要求，不是外在的补充。任何对项目统摄史观的释读都须包含自反性声明，承认自身释读的局限性。”

本子节作为项目统摄史观释读的载体，须含自反性声明：本章选取 “大型机与 BSD/UNIX 的辩证运动” 为主轴叙述，但这一选取本身即形式主义化的非存在——若以 “虚拟化史” 为主线（CP/CMS → VM/370 → z/VM → VMware → Xen → KVM → Docker → Kubernetes），若以 “分时系统史” 为主线（CTSS → Multics → UNIX → TOPS-10 → VMS → Windows NT → Linux），若以 “数据库史” 为主线（IMS → System R → DB2 → Oracle → PostgreSQL），大型机与 BSD/UNIX 的关系会呈现完全不同的脉络。本子节承认 “辩证运动” 叙事是史家的形式主义化决策，欢迎被更自反的释读所超越。

#### 辨析

**Multics 与 UNIX 的 “母-子” 谱系辨析**：部分二手资料将 Multics 与 UNIX 的关系简化为 “Multics 是 UNIX 的前身”，但 Ritchie 1984 年论文明确指出 UNIX 的诞生涉及多重因素（Multics 退场、GE-645 撤离、Thompson 的 “Space Travel” 游戏、GECOS 性能不佳、PDP-7 可用性等），Multics 是灵感来源之一但非唯一来源。本子节采用 “Multics 启发 UNIX 的辩证关系” 的精确表述，避免 “Multics 是 UNIX 的前身” 的简化叙事。

**BSD 虚拟内存与 VAX MMU 共构辨析**：部分二手资料称 “BSD 4.2 的虚拟内存设计由 VAX MMU 决定”，但 McKusick 与 Karels 在 CSRG 技术报告中明确指出，BSD 4.2 的虚拟内存设计是 “VAX MMU 启发下的主体性选择”——4.2BSD 的页面颜色（page coloring）、vfork、mmap 等机制是 BSD 团队的创造性设计，VAX MMU 提供了物质基础但未 “决定” BSD 的设计。本子节采用 “VAX MMU 启发下的主体性选择” 的辩证表述。

**VM/370 与 BSD jail 的反向影响辨析**：部分学术研究将 BSD jail（1999）视为 VM/370 虚拟机技术的 “延续”，但 Poul-Henning Kamp 与 Robert Watson 在 SANE 2000 论文中明确指出，BSD jail 的设计是 “UNIX chroot 的强化版”，与 VM/370 的 “全系统虚拟化” 路线不同——jail 是 “进程级隔离”，VM 是 “机器级隔离”。本子节采用 “反向影响” 而非 “延续” 的精确表述。

**Linux on Z 与 BSD 的容器化辨析**：至 2026 年 7 月 27 日，Linux on Z 通过 OpenShift 4.x 支持 OCI 容器规范，BSD 通过 containerd/Podman/jails 支持容器化但并非 OCI 标准实现。本子节采用 “共享同一容器运行时接口（OCI 规范）” 的限定性表述，承认 Linux on Z 与 BSD 在容器化上的 “共享” 是有限的。

**“UNIX 化的大型机” 表述辨析**：本子节采用 “Linux on Z 作为 UNIX 化的大型机” 的表述，但 Linux 严格意义上不是 UNIX（Linux 不含 System V 代码，未通过 Single UNIX Specification 认证），更准确的表述是 “类 UNIX 化的大型机” 或 “UNIX 风格化的大型机”。本子节采用 “UNIX 化” 的常用表述，并标注此处的 “UNIX 化” 指 “提供 POSIX 兼容接口”，而非 “通过 Single UNIX Specification 认证”。

### 关键术语

- **大型机（Mainframe）**：以 IBM S/360 谱系为代表的高性能、高可靠性、高 I/O 吞吐量通用计算机，主要服务于银行核心、航空订票、政府数据中心等 “关键业务” 场景。
- **BUNCH**：1970 年代对 IBM 之外五大大型机厂商的合称——Burroughs、UNIVAC（Sperry）、NCR、Control Data（CDC）、Honeywell，后加 RCA 与 National Advanced Systems 形成 “BUNCH-7”。
- **MVS（Multiple Virtual Storage）**：IBM 大型机 “主力” 操作系统谱系，演化至 z/OS。
- **VM（Virtual Machine）**：IBM 大型机虚拟机操作系统谱系，演化至 z/VM，是后续 VMware、Xen、KVM 等虚拟化技术的奠基者。
- **TPF（Transaction Processing Facility）**：IBM 大型机为极端高吞吐量交易场景设计的操作系统，至今仍由航空订票、信用卡支付、股票交易等核心系统使用。
- **AS/400**：IBM 中型商业系统谱系，演化至 IBM i，特色为集成 DB2 数据库与单级存储（single-level store）。
- **z/Architecture（z/Arch）**：IBM 2000 年发布的 64 位大型机架构，延续 S/370 与 ESA/390 的二进制兼容性。
- **LinuxONE**：IBM 2015 年推出的仅运行 Linux 工作负载的大型机产品线，与 IBM Z 共享硬件平台但仅支持 RHEL、SUSE、Ubuntu。
- **Telum**：IBM z16 集成的处理器，7 纳米工艺，8 核 4.0 GHz，集成 AI 推理加速器。
- **DASD（Direct Access Storage Device）**：IBM 大型机直接存取存储设备，从 RAMAC 305（1956，5 MB）演化至 DS8950（2024，单框架 4.8 PB）。
- **IX/370**：IBM 1985 年发布的 S/370 上独立 UNIX 实现。
- **AIX（Advanced Interactive eXecutive）**：IBM 的 UNIX 谱系操作系统，1986 年首发于 PS/2，1990 年在 RS/6000 上以 AIX 3.1 主力化。
- **UNIX System Services（USS）**：z/OS 内置的 POSIX 兼容子系统，源自 OpenEdition MVS。

### 观点增补

- 现代 Linux 仍沿用 Unix 的特权模型（特权/能力），但“转写以丢弃特权”并不自动提升安全，需配合重构方能收敛攻击面。（Criswell et al., 2019）
- ZFS on Linux 的写入路径缺陷（未对齐 I/O 触发 read-modify-write）表明文件系统移植需关注底层 I/O 对齐，否则吞吐骤降。（Shen & Luo, 2014）

### 说明增补

- 在 Ceph/RBD 分布式块存储栈上对比 Ext4/XFS/BtrFS/ZFS，填补了“文件系统运行于 RBD”的性能评估空白。（Ab Karim et al., 2016）
- GFS 作为 64 位共享磁盘文件系统，允许多台 Linux 经 Fibre Channel 共享磁盘，是集群文件系统早期代表。（Preslan et al., 2004）
- Pentium 上用户态缺乏受限硬件 I/O 访问途径，提出了在 Linux/FreeBSD 下可控访问硬件端口的方法。（Radcliffe, 2008）

### 批评

- 既有文件系统性能评估多孤立于底层存储栈，未覆盖 RBD 场景；PrivAnalyzer 揭示 capability 使用有效性长期缺乏量化方法。（Ab Karim et al., 2016; Criswell et al., 2019）

### 褒奖

- PrivAnalyzer 首次可量化 Linux 特权使用有效性，对容器（Docker）与最小特权实践有直接启示。（Criswell et al., 2019）

### 不同观点

- 共享磁盘（GFS）与共享存储（ZFS/RBD）代表了集群存储的两条路线，前者重并发共享、后者重数据完整与快照，取舍随负载而异。（Preslan et al., 2004; Ab Karim et al., 2016）
