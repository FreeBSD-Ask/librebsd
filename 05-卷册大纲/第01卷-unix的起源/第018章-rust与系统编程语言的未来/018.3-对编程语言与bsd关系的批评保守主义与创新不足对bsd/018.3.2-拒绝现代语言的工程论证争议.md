# 018.3.2 拒绝现代语言的工程论证争议

**要点**：支持者论证 FreeBSD 基本系统坚持 C 的工程理由：构建依赖最小化、引导编译便利、可移植性、与历史代码兼容；反对者认为这些理由在现代工具链下已可解决

**史料**：freebsd-arch 邮件列表工程讨论、McKusick 著作 ［A］

**史观**：总纲第 17 条与第 23 条——软件工程与社区治理：工程权衡与社区决策的张力

**辨析**：工程论证是否为 “事后合理化”——以 freebsd-arch 邮件列表时序还原决策语境：1990 年代初的 C++ 抵制讨论以 ABI 不稳定为主要理由（GCC 2.7 至 3.x 间 ABI 多次变更），2000 年代的讨论以构建依赖为主要理由，2020 年代的 Rust 讨论以构建时间为主要理由，理由随时代变化但 “保守” 立场一致，说明工程论证与社区保守文化共生而非单方面合理化

**文献**：freebsd-arch 邮件存档；McKusick《Design of 4.4BSD》 (1996)；FreeBSD Source Tree 注释 ［A］
