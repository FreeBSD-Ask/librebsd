# 018.3.4 批评的形式主义分析

**要点**：从总纲第 3 条形式主义膨胀角度分析，批评本身亦可能陷入 “现代语言必然优于 C” 的形式主义；BSD 的保守或为对另一形式主义的抵抗

**史料**：哲学文献、社区辩论文本 ［B］

**史观**：形式主义膨胀：批评与被批评者皆需警惕形式主义

**辨析**：形式主义分析不消解具体工程争议——哲学层面的 “形式主义膨胀” 批评与工程层面的 “ABI 稳定性” “构建时间” 争议分属不同范畴，前者评估语言选择的哲学立场，后者评估具体技术约束，二者可并行不悖；将形式主义分析误用为工程决策的替代会消解工程争议的具体性，但形式主义分析本身作为哲学审视仍有价值

**文献**：1.md 项目统摄史观；社区辩论存档；McKusick 著作 ［A］

**邮件来源**：T.J. Teixeira（tjt at kobold.UUCP），comp.unix.wizards，1983年10月，Message-ID: `187@kobold.UUCP`
**史学意义**：呈现 DEC 传统中 BLISS 对 C 的系统编程地位挑战，说明 C 在 BSD 的统治并非唯一选项。
