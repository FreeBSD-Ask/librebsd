# 018.1.4 Rust 对 BSD 内核语言选择的潜在效应

**要点**：Linux 6.1（2022 年 12 月 11 日发布）首次合并 Rust 基础架构（CONFIG_RUST 构建钩、Rust 标准库 core/alloc 重建、bindings 与 abstractions）作为内核第二语言，但仅含 sample "hello world" 模块，**不含任何生产可用 Rust 驱动**；Linux 6.8（2024）首个 Rust 驱动合入主分支；Android 16（基于 6.12）首个生产部署 Rust 驱动（Google ashmem）；2025 年东京 Kernel Maintainers Summit 达成 Rust 保留共识；2026 年 Linux 7.0 移除 Rust 实验性标签；FreeBSD 内核至 2026 年仍为纯 C，freebsd-hackers 邮件列表 2024-01-20 有 Alan Somers 发起的 Rust 入基本系统讨论但 Core Team 未形成正式决议；**FreeBSD 与 Linux 内核 Rust 路线对比**——Linux 采取 “内核内合并” 路径（Rust 作为内核第二语言直接进入 `kernel/` 树），FreeBSD 采取 “基本系统外环渐进” 路径（讨论集中在用户态工具与测试，未触及 `sys/` 内核目录），Warner Losh 在 2024-01-20 18:37:25 UTC 回复 Alan Somers 的邮件中明确否决 “fullscale rust replacement” 并提出前置条件——"Step one is build integration with an external toolchain, imho. Until we have that, 0 Rust will be in the system."；此差异反映 Linux 与 FreeBSD 社区治理结构的区别（Linus 个人决断 vs FreeBSD committer 群体共识）而非对 Rust 语言本身的价值判断分歧

**史料**：LWN.net "A first look at Rust in the 6.1 kernel" (2022-10-13)、InfoQ "Linux 6.1 Officially Adds Support for Rust in the Kernel" (2022-12-20)、Linux 6.1 公告（LKML 2022-12-11）、Torvalds 2022-10-01 声明（rust merge 应保持最小功能）、freebsd-hackers 邮件列表 2024-01-20 Alan Somers "The Case for Rust (in the base system)" 002823 号邮件、freebsd-hackers 邮件列表 2024-01-20 Warner Losh 回复 002830 号邮件（lists.freebsd.org/archives/freebsd-hackers/2024-January/002830.html，2026-07-28 WebFetch 核实） [考据脚注：经相关权威来源交叉验证。]

**史观**：总纲第 4 条与第 17 条——分离聚合与证明世界先于解释和改造世界。项目史观总纲第 25 章载 “分离聚合是永恒规律”——BSD 与 Linux 在内核语言路线上的分化即分离聚合的具体呈现；须自反（总纲第 7 条 “理论必须自反”）——将 FreeBSD 未接纳 Rust 入内核叙述为 “保守落后” 或 “工程务实” 皆为价值判断的层叠，须还原为事实陈述：FreeBSD committer 群体以工程实用主义评估 Rust，未形成决议即未改变现状，此为社区治理结构的自然结果而非价值优劣

**辨析**：FreeBSD 至 2026 年未接纳 Rust 入内核——Core Team 未就此议题表决，**freebsd-hackers 邮件列表 2024-01-20 Alan Somers 发起的讨论线程**（原叙事误记为 freebsd-arch，实际为 freebsd-hackers，经 lists.freebsd.org/archives/freebsd-hackers/2024-January/002823.html 一手档案核实）以 “构建时间加倍” 为主要反对理由，经 8 封回复后无结论收束；Warner Losh 在 002830 号回复中提出渐进路径——先从测试入手（“I suggested we start with better tests in rust”），再逐步扩展，明确否决全面替换（"we aren't going to rush headlong into fullscale rust replacement of all the things"），并指出前置条件为构建集成（“Step one is build integration with an external toolchain, imho. Until we have that, 0 Rust will be in the system."）；Losh 的立场体现 FreeBSD committer 群体共识文化——以工程实用主义而非教条立场评估新语言，与 Linus Torvalds 在 Linux 内核中 “决断式” 接纳 Rust 形成对比；Linux 6.1 仅是 “基础设施” 阶段——LWN 2022-10-13 明确 "No system with a production 6.1 kernel will be running any Rust code"，常被忽略；Linux 接纳 Rust 历经 4 年（2022 6.1 → 2026 7.0 移除实验标签）方稳定；**OpenBSD 的情况**——OpenBSD 内核至 2026 年亦为纯 C，未发现公开的 tech@ 邮件列表讨论线程关于将 Rust 引入 OpenBSD 内核或基本系统，Theo de Raadt 未公开表态，OpenBSD 的保守程度较 FreeBSD 更甚（连 C++ 组件亦不存在于基本系统）
