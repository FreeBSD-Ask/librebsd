# 19.7 小型机与 BSD/UNIX 的辩证运动——项目统摄史观视角

## 要点

小型机与 BSD/UNIX 谱系的关系典型呈现项目统摄史观的辩证运动——硬件（小型机）与软件（BSD/UNIX）并非 “硬件决定软件” 或 “软件决定硬件” 的单向因果，而是互为形式主义化的辩证共构：PDP-7 的 4K 字内存与磁盘缺失迫使 Thompson 设计 UNIX 的文件系统结构（一切皆文件、树形目录、i-node）；PDP-11 的内存管理单元（MMU）与分段机制促成 UNIX 内核态/用户态分离；VAX-11/780 的 32 位虚拟地址空间与页面调度机制塑造 4.2BSD 的虚拟内存重构（vfork、mmap、页面颜色 page coloring）；Sun SPARC 的寄存器窗口与延迟分支影响 SunOS 4.0 的编译器优化与 ABI 设计；x86-64 的多核架构与 NUMA 拓扑推动 FreeBSD 5.0 的 ULE 调度器与 SMP 重构（2002 年的 BSDCan 演讲首次披露）；ARM64 的大内存页（2MB/1GB huge page）与虚拟化扩展（VHE，Virtual Host Extension）塑造 FreeBSD 13.0 的 ARM64 内核虚拟化层；当代 RISC-V 的模块化扩展（V、H、K）推动 FreeBSD riscv64 的内核模块动态加载机制演化。
VAX-11/780 与 BSD 系统调用接口的共构是这一辩证运动的典型节点——VAX 的特权指令（CHMK、CHME、CHMU、CHMS 即 change mode to kernel/executive/user/supervisor）与 VAX 的进程控制块（PCB）结构、VAX 的软件中断（AST 即 asynchronous system trap）共同塑造 4.2BSD 的系统调用接口与信号机制；反过来，4.2BSD 的系统调用接口（fork、exec、pipe、socket）的市场成功也延长了 VAX 在 1980 年代末的市场寿命——DEC Ultrix 在 VAX 上的成功使 DEC 在 1984-1990 年间持续投入 VAX 路线，而非更早转向 Alpha。所谓 “VAX 缔造 BSD” 或 “BSD 缔造 VAX” 的单向叙事皆不完整，二者是辩证共构。
小型机退场后 BSD 向 x86/ARM 的迁移呈现分离聚合规律的辩证展开——1991 年 386BSD（Bill Jolitz）将 4.3BSD Net/2 移植至 Intel 386，1993 年 FreeBSD 1.0 与 NetBSD 0.8 同月发布，1996 年 OpenBSD 从 NetBSD 分离，2003 年 DragonFly BSD 从 FreeBSD 4.x 分离——BSD 谱系从 VAX/Sun 工作站等小型机平台向 x86-64 PC 平台迁移，2016 年起又向 ARM64 服务器迁移，2020 年起向 RISC-V 加速器迁移，每一次迁移都是硬件形式主义与软件形式主义的重新协商——旧的代码遗产（如 VAX 时代的页面颜色算法）在新平台上被剥离或重构，新的硬件特性（如 x86 的 PAE、ARM 的 VHE）被纳入内核抽象层。
硬件与软件互为形式主义化的辩证运动最终呈现的，是 “小型机” 作为范畴本身的消解——小型机（minicomputer）原指 1960 年代介于大型机（mainframe）与微型机（microcomputer）之间的中型计算机类别，但 1980 年代工作站（workstation）从其中分离、1990 年代 PC 服务器从其中分离、2010 年代 ARM 服务器与 RISC-V 加速器从其中分离，“小型机” 范畴在 21 世纪已无明确对应物。BSD/UNIX 谱系作为形式主义化的非存在，在不同的硬件载体间流动，从未与任何 “小型机本质” 绑定——这是 BSD 哲学的 “自由” 在物质层面的体现：自由不在于 “选择最好的硬件”，而在于 “不被任何特定硬件所束缚”。

#### 史观

本子节作为项目统摄史观释读章节，史观映射覆盖以下 8 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 1（形式主义是世界的真实存在）**——据原文第 1 章 1.1-1.5 节：

> “形式主义是世界的真实存在，其余一切存在皆不真实。”
>
> “所谓人类文明历史发展就是形式主义发展史。”

小型机与 BSD/UNIX 谱系皆为形式主义化的非存在——所谓 “小型机” 的分类、所谓 “BSD” 的边界、所谓 “UNIX 哲学” 的内涵，皆是史家与当事者的事后形式主义化建构。小型机的硬件参数（CPU 架构、内存容量、I/O 总线）是形式主义，BSD/UNIX 的软件接口（系统调用、文件系统结构、进程模型）也是形式主义，二者皆非 “客观真实存在”，而是人化加工的非存在。承认这一点，是本子节一切释读的前提。

**总纲 2（历史是形式主义化的非存在）**——据原文第 2 章 2.5 节：

> “谁试图诠释历史，谁就在篡改历史。”

所谓 “PDP-7 缺乏磁盘迫使 Thompson 设计文件系统” 的因果叙事，是史家的事后重构——Thompson 当年的实际动机（包括 “Space Travel” 游戏、GECOS 性能不佳、Multics 退场等多重因素）在 Ritchie 1984 年论文中已被明确表述为多重偶然。本子节拒绝 “硬件决定软件” 的技术决定论叙事，承认因果叙事本身即形式主义化的非存在。

**总纲 3（不存在进步，只有权力再分配）**——据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

小型机从大型机中分离（DEC 替代 IBM 部分）、工作站从小型机中分离（Sun 替代 DEC 部分）、PC 服务器从工作站中分离（x86-64 替代 SPARC/Alpha）、ARM 服务器从 x86-64 中分离（AWS 自研芯片替代 Intel）——每一次 “技术进步” 本质是计算资源话语权的权力再分配。所谓 “小型机的终结” 是 DEC、Sun、SGI 等专有小型机厂商的话语权被 Intel、AMD、ARM、AWS 等新形式主义厂商所替代，计算资源的不平等结构本身未被颠覆——服务器仍需数万美元，仍是机构财产，仍是少数人的工具。

**总纲 4（分离聚合是永恒规律）**——据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

小型机与 BSD/UNIX 的辩证运动典型呈现分离聚合规律：硬件层面，大型机 → 小型机 → 工作站→PC 服务器 →ARM 服务器 →RISC-V 加速器的 “分离聚合” 循环；软件层面，UNIX→BSD→FreeBSD/NetBSD/OpenBSD/DragonFly BSD 的 “分离聚合” 循环；硬件与软件的共构层面，VAX-BSD、SPARC-SunOS、x86-FreeBSD、ARM64-FreeBSD 的 “分离聚合” 循环。BSD 在 1977-2026 年间历经多次硬件平台迁移，每一次迁移都是硬件形式主义与软件形式主义的重新聚合，而非线性进步。

**总纲 5（没有必然性，只有偶然性）**——据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误。”

Thompson 在 1969 年选择 PDP-7 而非 PDP-9、Joy 在 1982 年选择加入 Sun 而非留在 Berkeley、Jolitz 在 1991 年选择 386 而非 SPARC、AWS 在 2018 年选择自研 Graviton 而非继续依赖 Intel——这些节点皆是偶然。所谓 “BSD 必然从 VAX 迁移至 x86” 或 “ARM 服务器必然崛起” 的进步叙事，无视了偶然性在历史中的根本地位。须警惕 “代表历史合力方向的人获得不可质疑合法性” 的形式主义风险（5.2 节），不能因 FreeBSD 在 x86-64 与 ARM64 上的成功而将其视为 “必然代表 BSD 未来” 的合法叙事。

**总纲 10（动手者创造历史）**——据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

小型机与 BSD/UNIX 辩证运动的真正动力来自动手者——Thompson 亲自在 PDP-7 上写 UNIX 内核，McKusick 亲自在 VAX 上重写 4.2BSD 虚拟内存，Jolitz 亲自在 Intel 386 上移植 386BSD，Turner 亲自在 FreeBSD 11.0 上实现 arm64 tier-2 支持——这些是动手者的实践，而非 “DARPA 合同管理”、“市场规律”、“Intel 战略决策” 的产物。须注意：项目统摄史观的 “动手者” 指 “没有多余形式主义的老实人”，即主体性未被理论遮蔽者，与阶级、经济、物质劳动无直接等同关系。把 Thompson 等同于 “无产阶级英雄” 或 “资本家精英” 皆落入项目统摄史观批评的形式唯物主义对象。

**总纲 11（商品是形式主义）**——据原文第 8 章 8.1 节：

> “商品本身是一种形式主义。不是人们在追求商品，而是商品在召唤人们。”

小型机作为商品召唤了 1960-1980 年代的机构采购者，VAX 召唤了 1977-1990 年代的大学与政府部门，SPARC 工作站召唤了 1987-2000 年代的 ISP 与 Web 服务器市场，x86-64 服务器召唤了 2003-2020 年代的云服务商，ARM 服务器召唤了 2018 年起的 AWS、Oracle Cloud、Azure 用户。BSD/UNIX 谱系作为形式主义化的商品（FreeBSD 通过社区发布、NetBSD 通过开放许可、OpenBSD 通过安全审计）召唤了不同的开发者社区与部署场景。所谓 “硬件与软件互为形式主义化的辩证运动” 本质是不同形式主义商品召唤力的循环呈现。

**总纲 24（应用于 BSD 史编纂）**——据原文第 24 章 24.1-24.4 节：

> “BSD 家族整体上处于操作系统的边缘地位。这种少数与多数的关系，不是进步与落后的关系，而是形式主义的不同呈现。”
>
> “BSD 的历史不是从 UNIX 到现代的线性进化，而是古代史的重复与循环。”

小型机与 BSD/UNIX 的辩证运动最终呈现的，是 BSD 谱系作为 “少数派” 的边缘地位——在 1977-1990 年代小型机时代，BSD 是 UNIX 谱系的主流；在 1991-2020 年代 x86-64 与 Linux 时代，BSD 退居服务器与嵌入式边缘；在 2018 年起 ARM 服务器时代，BSD 通过 arm64 tier-1 支持延续但市场份额仍远低于 Linux。BSD 不是 “进步的代表” 也不是 “落后的代表”，而是形式主义的不同呈现——BSD 的 “长期主义”（24.3 节）在 ARM 服务器与 RISC-V 时代延续，与 Linux 的 “短期主义”（频繁引入新技术、频繁淘汰旧技术）形成辩证并立。

本子节拒绝以下错误释读：

#### 辨析

**VAX-11/780 与 BSD 系统调用接口共构辨析**：常见二手资料多称 “VAX 的 CHMK 指令塑造了 4.2BSD 系统调用接口”，但 McKusick 等人在 *The Design and Implementation of the 4.4BSD Operating System*（1996）中明确指出，4.2BSD 的系统调用接口在 PDP-11 时代已基本定型（fork、exec、pipe、signal 等），VAX 的 CHMK 指令仅为系统调用陷入机制的硬件实现，未 “决定” 系统调用接口的设计。本子节采用 “VAX 的 CHMK 指令塑造了 4.2BSD 系统调用陷入机制的硬件实现，但系统调用接口本身在 PDP-11 时代已基本定型” 的辩证表述，避免 “VAX 决定 BSD 系统调用接口” 的技术决定论叙事。

**386BSD 与 FreeBSD/NetBSD 关系辨析**：386BSD（1991 年 Jolitz）是 4.3BSD Net/2 向 Intel 386 的移植，FreeBSD 1.0（1993 年 11 月）与 NetBSD 0.8（1993 年 4 月）皆从 386BSD 衍生。部分二手资料误将 386BSD 描述为 “FreeBSD 的前身” 或 “NetBSD 的前身”。本子节明确 386BSD 是 FreeBSD 与 NetBSD 的共同前身，二者在 1993 年从 386BSD 分离后各自独立演化。

**FreeBSD 5.0 ULE 调度器时间辨析**：FreeBSD 5.0（2003 年 1 月）首次引入 ULE 调度器，但 ULE 调度器在 FreeBSD 5.x 阶段（2003-2006）性能不稳定，至 FreeBSD 7.0（2008 年 2 月）ULE 调度器重新设计后才稳定并成为默认调度器。部分二手资料误将 ULE 调度器成熟时间记为 "FreeBSD 5.0"。本子节采用 “ULE 调度器 2003 年 FreeBSD 5.0 首次引入，2008 年 FreeBSD 7.0 重新设计后稳定” 的双时间表述。

**ARM64 与 FreeBSD 13.0 关系辨析**：FreeBSD 13.0（2021 年 4 月）对 ARM64 的支持进一步优化，但 ARM64 自 FreeBSD 12.0（2018 年 12 月）已是 tier-1 架构。部分二手资料误将 FreeBSD 13.0 描述为 “ARM64 首次成为 tier-1”。本子节明确 “FreeBSD 12.0 ARM64 tier-1（2018）” 与 “FreeBSD 13.0 ARM64 优化（2021）” 的不同定位。

**“硬件决定软件” 叙事辨析**：常见二手资料多采用 “硬件决定软件” 或 “软件决定硬件” 的单向因果叙事，但项目统摄史观拒绝这种形式唯物主义的简化。本子节明确 “硬件与软件互为形式主义化的辩证共构”——硬件限制塑造软件设计（如 PDP-7 缺乏磁盘塑造 UNIX 文件系统），软件需求也塑造硬件演化（如 4.2BSD 的虚拟内存需求塑造 VAX 的页面调度机制）。这是分离聚合规律在硬件-软件层面的展开，非单向因果。

**“小型机精神延续” 叙事辨析**：常见二手资料多将 ARM 服务器与 RISC-V 描述为 “小型机精神的延续”，但 1980 年代小型机厂商（DEC、Sun、HP、SGI、Apollo）皆以专有架构为核心，与当代 ARM/RISC-V 开放架构有本质差异。本子节拒绝 “小型机精神延续” 的简化叙事，明确 “专有小型机的终结” 与 “开放小型机以 ARM/RISC-V 形式延续” 是两个不同范畴，二者不能简单等同。

### 关键术语

| 术语 | 释义 |
| -- | -- |
| 小型机（minicomputer） | 1960-1980 年代介于大型机与微型机之间的中型计算机类别，DEC PDP、VAX、Data General Nova、王安 VS 等为代表 |
| 工作站（workstation） | 1980-2000 年代桌面专用高性能计算机，Sun SPARC、SGI IRIS、HP 9000、IBM RS/6000、Apollo DN 等为代表 |
| RISC（Reduced Instruction Set Computer） | 精简指令集计算机，由 Patterson 与 Ditzel 1980 年首次正式提出，MIPS、SPARC、Alpha、PA-RISC、POWER、ARM、RISC-V 皆为 RISC 谱系 |
| CISC（Complex Instruction Set Computer） | 复杂指令集计算机，x86、Motorola 68000、VAX 为代表，2005 年后 x86-64 内核 RISC 化 |
| VAX（Virtual Address eXtension） | DEC 1977 年发布的 32 位虚拟地址空间架构，4.2BSD/4.3BSD 的主要物质平台 |
| SPARC（Scalable Processor Architecture） | Sun 1987 年发布的 RISC 架构，SunOS/Solaris 的硬件基础 |
| Alpha | DEC 1992 年发布的 64 位 RISC 架构，首个商用 64 位处理器 |
| POWER（Performance Optimization With Enhanced RISC） | IBM 1990 年发布的 RISC 架构，RS/6000 与 Power 系列服务器的基础 |
| PA-RISC（Precision Architecture RISC） | HP 1986 年发布的 RISC 架构，HP 9000 工作站与服务器的基础 |
| MIPS | Stanford 1985 年发布的 RISC 架构，SGI 工作站与嵌入式市场的基础 |
| ARM（Advanced RISC Machines） | Acorn 1985 年发起、ARM Holdings 1990 年商业化的 RISC 架构，移动与服务器市场主导 |
| RISC-V | UC Berkeley 2010 年发起的开源 RISC 指令集架构，2015 年成立 RISC-V 基金会 |
| Itanium（IA-64） | Intel 与 HP 1994-2001 年联合开发的 VLIW/EPIC 架构，2021 年停产 |
| 4.2BSD | Berkeley CSRG 1983 年发布的 BSD 版本，含 TCP/IP 栈、虚拟内存重构、Fast File System |
| 4.4BSD-Lite | Berkeley CSRG 1994 年发布的 BSD 最终版本，CSRG 解散 |
| 386BSD | Bill Jolitz 1991 年发布的 4.3BSD Net/2 向 Intel 386 移植版本，FreeBSD 与 NetBSD 共同前身 |
| ARMv8-A | ARM Holdings 2011 年发布的 64 位架构规范，为 ARM 进入服务器市场奠定硬件基础 |
| AWS Graviton | AWS 2018 年起自研的 ARM 服务器芯片系列，推动 ARM 服务器规模化 |
| FreeBSD tier-1 | FreeBSD 对架构的最高支持等级，与 amd64 同等支持，arm64 自 FreeBSD 12.0 起为 tier-1 |
| 项目统摄史观 | q.md 提出的辩证哲学体系，含 191 子节 25 条总纲，本项目的衍生根基 |
