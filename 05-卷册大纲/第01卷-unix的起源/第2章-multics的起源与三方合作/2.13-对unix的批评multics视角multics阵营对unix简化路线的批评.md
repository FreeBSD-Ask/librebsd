# 2.13 对 Unix 的批评：Multics 视角——Multics 阵营对 Unix 简化路线的批评

## 2.13.1 Multics 阵营对 Unix 简化路线的批评

**要点**：Multics 工程师认为 UNIX 丢弃了环形保护、动态链接、统一数据库等核心创新，退化为“玩具系统”；Corbató 在 1970 年代访谈中称 UNIX“退回到 1962 年的水平”

**史料**：Corbató 1970 年代访谈、Multics 社区内部讨论存档 ［A］

**史观**：总纲第 3 条——形式主义对简洁的偏见，复杂系统的设计者难以理解简洁的价值

**辨析**：Corbató 的批评是否被准确转述——需查原始访谈记录；Multics 阵营内部对 UNIX 的态度并非铁板一块

**文献**：Corbató 访谈（Annals of the History of Computing 1980 年代）；Multics 讨论存档（Multics.org） ［A］

## 2.13.2 复杂性与简洁性的哲学分歧

**要点**：Multics 代表“系统正确性优先”路径——所有功能完备后再发布；UNIX 代表“可用优先”路径——先发布最小可用版本再迭代；两种哲学的张力贯穿操作系统史

**史料**：Ritchie 1984 BLTJ 63 No. 6 Part 2:1577-1593, DOI 10.1002/j.1538-7305.1984.tb00054.x 文章、Multics 设计文档 [考据脚注：Multics 与 UNIX 两种设计哲学对比经 Ritchie 1984 BLTJ 与 Organick 1972 交叉验证确证。] 〔L3 官方文档 + L5 学术论文〕

**史观**：总纲第 3 条与第 4 条的张力——形式主义追求完备，但完备往往导致无法交付；分离后的简洁反而获得生命力

**辨析**：两种哲学并非绝对对立——Multics 的设计理念在后续系统（如 Java、Windows NT）中以变形延续

**文献**：Ritchie 1984 BLTJ 63 No. 6 Part 2:1577-1593, DOI 10.1002/j.1538-7305.1984.tb00054.x；Organick 1972；Pike & Thompson“Program Design in the UNIX Environment” (1984) [考据脚注：两种设计哲学对比经 Ritchie 1984 BLTJ 与 Organick 1972 交叉验证确证。]

## 2.13.3 Multics 工程师对 Unix 后续演进的评价

**要点**：部分 Multics 工程师后来承认 UNIX 的简洁具有实用价值，但批评其安全模型粗糙、文件系统原始；Peter Neumann 持续批评 UNIX 安全缺陷至 21 世纪

**史料**：Neumann RISKS Forum 记录、Multics 社区后续评论 [考据脚注：Neumann 长期主持 RISKS Forum 并批评 UNIX 安全缺陷、部分 Multics 工程师后来承认 UNIX 简洁的实用价值等核心事实经 ACM RISKS Forum 存档与 multicians.org 社区评论交叉验证确证。] 〔L2 邮件列表〕

**史观**：总纲第 25 条——终结中的延续，Multics 的批评本身成为 UNIX 改进的动力

**辨析**：Neumann 的批评是否公平——需对比 Multics 与 UNIX 的实际安全记录；批评中是否夹杂项目失败的情绪

**文献**：Peter Neumann RISKS Forum (ACM)；Multics.org 社区评论；Neumann“Computer Security in Open Systems” (1995) ［B］

分时思想出现于 1950 年代末：1959 年 Strachey 与 McCarthy 各自提出 time-sharing。1961 年 11 月，Fernando Corbató 与 Robert Daley 等在 MIT 建成并演示 Compatible Time-Sharing System（CTSS），成为首个可运行的分时系统，1963 年发展为稳定大规模系统；其后 CTSS 在 ARPA 支持下演进为 Project MAC（1963 年上线）。1965 年 CMOS 分时设计更上层楼，MIT Project MAC、贝尔电话实验室与通用电气联合启动 Multics（由 Corbató 领导），引入分页、分段存储与树状文件系统；贝尔实验室 1969 年退出，1970 年 GE 计算机业务转售 Honeywell 将其商业化，1985 年被取消。1990 年 Corbató 因在 CTSS 与 Multics 上的开创性工作获 ACM 图灵奖。

文件系统概念演化大体历经：①顺序/平坦期（1950–1960s）：磁带顺序访问与早期磁盘平面目录；②层次化突破（1960s–1970s）：Multics（始于 1965）首创树状文件目录与路径名，Unix（1970s）以 inode 架构、挂载点、“一切皆文件”简明化并推广层次文件系统；③性能重构期（1980s）：Marshall Kirk McKusick 等为 4.2BSD 设计 Fast File System（FFS/现称 UFS1，1982 年写出、随 4.2BSD 发行），引入柱面组、碎片、软更新，UFS2（2002–2003）改用 64 位块指针扩展至多 TB；④网络化期：Sun Microsystems 1984 年推出网络文件系统 NFS，确立 VFS/vnode 接口；⑤存储与纠错集成期：如 ZFS（2001–2006）将文件系统与卷管理、写时拷贝、校验和集成。

Capsicum 源自剑桥大学计算机实验室 Robert N.M. 1979 年前后（一说 2BSD 时期）引入 chroot(2)，本为构建与测试设计而非安全机制，因可再次 chroot 逃逸而存在已知缺陷。1990 年代末，FreeBSD 开发者 Poul-Henning Kamp 应托管商 Derrick T. Woolworth 付费需求，开发出比 chroot 更强的内核级进程隔离：使每个 jail 拥有独立根文件系统、网络地址与进程空间。jail 随 FreeBSD 4.0（2000-03-14）正式发布，jail(2)/jail(8) API 沿用至今；同月于 SANE 2000 会议发表论文《Jails: Confining the omnipotent root》（Kamp 与 Robert Watson）。后续演进包括 VNET 虚拟网络栈、分层 jail、RCTL 资源限制、ZFS 深度集成，以及 ezjail/iocage/cbsd/Bastille 等管理工具。2013 年 Docker 容器热潮被视为 jail 早已具备的理念。
