## 引言

第一卷“UNIX 的起源，1962-1978”涵盖自 Licklider 发表《Man-Computer Symbiosis》至贝尔实验室系统技术期刊（Bell System Technical Journal，BSTJ）1978 年 UNIX 专刊出版的十六年历程。这一时段是 UNIX 从构想萌芽到学术成型的关键期，也是 BSD 谱系得以成立的精神原点与技术前提。本卷的核心史学问题集中在四个维度：其一，Multics 项目作为 UNIX 直接前身的遗产与教训，包括贝尔实验室 1969 年退出 Multics 的决策机制与责任归属；其二，贝尔实验室默里山 1127 室研究中心的组织文化如何为 Thompson 与 Ritchie 的合作提供制度性庇护；其三，Thompson 与 Ritchie 的合作关系在 Space Travel 游戏、文件系统设计、C 语言演化中的具体形态；其四，C 语言从 BCPL 经 B 至 C 的诞生时序及其与 PDP-7/PDP-11 硬件演进的互动关系。

本卷综述按剑桥史体例组织，依次梳理史料谱系、辨析学术论争、反思方法论、指陈缺口与前瞻。综述主体以 0 信任原则为考据基准，对所有文献（含一手史料）进行交叉验证，不因来源“一手”即直接采信，亦不因多源一致即断定可靠。原评注式书目全部条目保留为“文献清单”子节，作为综述的文献支撑。

## 史料谱系

本卷一手史料的发生学谱系可分五个层次。

原始档案层。贝尔实验室内部备忘录（如 1969 年退出 Multics 的决策备忘录）、AT&T 1956 同意判决与 1975 年大学许可证条款、DARPA 早期资助文档构成 UNIX 起源的制度史骨架。其中 AT&T 1956 同意判决禁止贝尔实验室从事计算机商业活动，这一法律约束反向促成 UNIX 以源码形式向学术界免费分发的传播模式，是 BSD 谱系得以从 UNIX 衍生的法律前提。原始档案的局限在于贝尔实验室内部备忘录多数未数字化，1969 年退出 Multics 的决策细节主要依赖当事人事后回忆而非同期文档。

当事人自述层。Ritchie 1984 年 BLTJ 自述《The Evolution of the Unix Time-sharing System》明确订正 UNIX 诞生于 1969 年而非 1974 年，是 UNIX 起源时间线最权威的一手来源。Ritchie 1993 年 HOPL-II 会议论文《The Development of the C Language》系统陈述 C 语言从 BCPL 到 B 到 C 的演化路径。Kernighan 2019 年回忆录《UNIX: A History and a Memoir》以 1127 室成员视角提供 Bell Labs 组织文化、Thompson/Ritchie 合作关系的当事人叙述。Thompson 2024 年 CHM 口述史（Catalog Number 102808980，全长约 4.5 小时）涵盖 UNIX 起源、C 语言设计、贝尔实验室研究环境等核心主题。McIlroy 2019 年 CHM 口述史涵盖管道概念提出与 Unix 软件工程思想奠基。当事人自述属一手史料，但按 0 信任原则须警惕自利偏差与记忆偏差——例如 McIlroy 1978 BSTJ 前言"Style"小节首次系统阐述 UNIX 工程哲学四条格言，但后世常将 Salus 1994 的三条精炼总结误归于 McIlroy 原文。

官方文档层。BSTJ 1978 UNIX Issue（Vol.57 No.6 Part 2）是 BSD 起源前夕学术界对 UNIX 最完整的一次集中陈述，卷内同期论文 Thompson"UNIX Implementation"、Bourne"The UNIX Shell"、Johnson 与 Ritchie"Portability of C Programs"共同构成 UNIX 起源史的一手文献群。CACM 1974 年 Ritchie 与 Thompson 合著的《The UNIX Time-Sharing System》是 UNIX 首次向学术界完整披露的奠基性论文，被 BSD 谱系所有版本直接继承。DEC PDP-7 Handbook（1965）与 PDP-11 Processor Handbook（1970）记载的关键硬件规格——PDP-7 的 18 位字长与 PDP-11 的字节寻址——直接塑造了 B 语言无类型设计与 C 语言类型系统的引入动机。

代码档案层。TUHS（The Unix Heritage Society）源代码归档是 UNIX 早期代码演化的一手来源，涵盖 Research Unix V1-V10、32V、PDP-7 UNIX 重建项目等。PDP-7 UNIX 重建项目（**s1** 目录树）为 Space Travel 游戏到文件系统到 shell 雏形的演化路径提供代码级证据。须注意重建代码非原始代码，部分为后世推断，引用时须与同期文档互参。Lions 1977 年 V6 源代码注释本《Lions' Commentary on UNIX 6th Edition》对 V6 内核约 9,000 行 C 代码逐行注释，是理解早期 UNIX 内核结构的里程碑文献。

数据库史料层。BSD 上游仓库提交数据库（约 11 GB，含 6 个仓库 2,358,055 条提交记录）为 UNIX 起源期之后的 BSD 演化提供量化分析基础，但本卷时段（1962-1978）的代码历史主要依赖 TUHS 归档而非数据库。DTIC（Defense Technical Information Center）数据库收录 DARPA 早期资助文档，为 Multics 退出后的 ARPA 资助转向提供制度史线索。

上述五个层次之间存在密集的互证关系：原始档案（AT&T 许可证）为官方文档（BSTJ 1978）提供法律框架，当事人自述（Ritchie 1984）为代码档案（TUHS V7 源码）提供演化叙事，代码档案（PDP-7 重建）为当事人自述（Kernighan 2019）提供实证支撑。这种多层互证结构既是本卷史料谱系的优势，也带来了原始档案稀缺与当事人视角主导的认识论挑战（详见方法论反思）。

## 学术论争

### 争议一：UNIX 哲学的起源与系统化——McIlroy 1978 四条格言 vs Salus 1994 三条精炼 vs Raymond 2003 十七条原则

争议主题：UNIX 哲学作为一套工程格言与设计原则，其原始表述、后世精炼与系统化建构之间存在层次差异，不同文献对“UNIX 哲学的核心内容”给出不同表述，何者为权威表述。

不同立场：其一，McIlroy 1978 原始立场。McIlroy、Pinson、Tague 三人合署的 BSTJ 57.6 前言"Style"小节首次以文字形式系统阐述 UNIX 工程哲学的四条格言：让每个程序做好一件事；期望每个程序的输出成为另一个程序的输入；尽早设计与构建软件以试用；优先使用工具而非不熟练的帮助。这是 UNIX 哲学最早的一手文献来源。其二，Salus 1994 精炼立场。Salus 在《A Quarter Century of UNIX》中将 McIlroy 的四条格言精炼为三条总结，这一三条版本在业界广泛流传，但常被误归于 McIlroy 1978 原文。其三，Raymond 2003 系统化立场。Raymond 在《The Art of UNIX Programming》中将 UNIX 哲学系统化为 17 条设计原则，形成最广为人知的哲学体系。其四，Kernighan 2019 回忆立场。Kernighan 在回忆录中以 1127 室成员视角描述 UNIX 哲学的实践形态，强调“小工具组合”与“文本流”的工程审美，而非形式化原则体系。

史料依据：McIlroy、Pinson、Tague 1978 年 BSTJ 前言是 UNIX 哲学四条格言的最早一手文献，原文记载于 Bell System Technical Journal Vol.57 No.6 Part 2 pp.1899-1904。Salus 1994 年《A Quarter Century of UNIX》（ISBN 0-201-54777-5）的精炼总结为二手转写。Raymond 2003 年《The Art of UNIX Programming》（ISBN 978-0-13-142901-7）的 17 条原则系事后系统建构。Kernighan 2019 年回忆录（英文版 ISBN 9780691190250）提供当事人视角的实践叙述。Pike 1983 年 USENIX 多伦多会议演讲"UNIX Style, or `cat -v` Considered Harmful?"及 1984 年 BLTJ 正式发表版本（与 Kernighan 合著）是哲学从工程格言向系统化表述过渡的关键节点。

史家判断：UNIX 哲学的权威表述须以 McIlroy 1978 四条格言为原始基准，Salus 1994 三条精炼为二手转写（须标注出处而非误归 McIlroy），Raymond 2003 十七条原则为事后系统建构（与一手工程经验存在层次差异）。按 0 信任原则，McIlroy 1978 作为一手文献经 BSTJ 原始期刊与 Bell Labs 官方重制版交叉验证，其原始性无可替代。但须警惕的是，McIlroy 本人在 2019 年 CHM 口述史中对哲学的回忆可能受事后视角影响，须与 1978 原文对照。Raymond 的 17 条原则体系虽有争议，但其系统化努力本身即是 UNIX 哲学传播史的重要组成部分。Pike 1983/1984 论文的页码在不同来源中存在 pp.1577-1593 与 pp.1595-1605 两种记载，待 BLTJ 原始期刊扫描件最终核实 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]。本卷叙事以 McIlroy 1978 四条格言为 UNIX 哲学的原始表述，Salus 三条与 Raymond 十七条作为后世演化的不同层次，三者并非对立而是哲学从工程经验向系统理论演化的不同阶段。

### 争议二：C 语言诞生时序与类型系统引入动机——Ritchie 1993 HOPL-II 自述与早期技术报告的交叉验证

争议主题：C 语言从 BCPL 经 B 至 C 的诞生时序在不同史料中存在细节差异，类型系统的引入动机——是为适配 PDP-11 字节寻址硬件约束，还是为满足系统编程的抽象需求——在不同叙述中侧重不同。

不同立场：其一，Ritchie 1993 HOPL-II 自述立场。Ritchie 在《The Development of the C Language》中系统陈述 C 语言从 BCPL 到 B 到 NB 再到 C 的演化路径，明确记载类型系统引入与 PDP-11 字节寻址的关联——PDP-11 区分字节与字，B 语言无类型设计无法直接表达字节操作，催生 NB 语言引入字符类型，进而演化为 C 语言的完整类型系统。其二，CSTR 技术报告立场。Johnson 与 Kernighan 1973 年 CSTR #8《The Programming Language B》记载 B 语言的设计与实现，B 语言基于 BCPL 演化，运行于 PDP-7 与 PDP-11 早期 UNIX。Ritchie 1975 年 CSTR #31《C Reference Manual》是 C 语言早期定义的权威一手技术报告，先于 K&R 1978 年专著。CSTR #31 记载的 C 语言形态与 Ritchie 1993 自述在类型系统细节上基本一致，但在数组与指针关系的表述上存在演化痕迹。其三，硬件约束立场。DEC PDP-7 Handbook（1965）记载 PDP-7 的 18 位字长与字寻址特性，PDP-11 Processor Handbook（1970）记载 PDP-11 的 16 位字长与字节寻址特性。硬件演化的视角强调 PDP-7 字寻址塑造了 B 语言无类型设计，PDP-11 字节寻址催生了 C 语言类型系统。其四，抽象需求立场。系统编程的实际需求——管理文件系统 i-node、实现进程控制块、操作设备寄存器——要求语言能够表达结构化数据，这一抽象需求独立于硬件约束推动类型系统的引入。

史料依据：Ritchie 1993 年 HOPL-II 论文（载于 Bergin、Gibson 编《History of Programming Languages-II》，ACM Press，ISBN 0-201-89502-1，pp.671-698）是 C 语言演化史最权威的当事人自述。Johnson、Kernighan 1973 年 CSTR #8 与 Ritchie 1975 年 CSTR #31 是 C 语言早期定义的一手技术报告，经 Bell Labs CSTR 存档目录与 Kernighan 个人 bibliography 交叉印证。DEC PDP-7 Handbook 与 PDP-11 Processor Handbook 经 bitsavers.org PDF 存档与 Bob Supnik 论文交叉印证。TUHS 源代码归档提供 V1-V7 各版本 C 代码的实际形态，可对照 CSTR #31 的语言定义验证时序。

史家判断：C 语言诞生时序以 Ritchie 1993 HOPL-II 自述为主干，经 CSTR #8（1973）与 CSTR #31（1975）交叉验证。类型系统引入动机并非单一因素——PDP-11 字节寻址硬件约束与系统编程抽象需求共同推动类型系统演化，二者是互为表里的关系而非非此即彼。按 0 信任原则，Ritchie 1993 自述属当事人事后回忆，存在记忆偏差风险，须与 CSTR #8/#31 同期技术报告与 TUHS 代码档案三方互证。CSTR #31（1975）记载的 C 语言形态与 Ritchie 1993 自述在核心演化路径上一致，但 CSTR #31 对数组与指针关系的原始表述（数组退化为指针的规则）在后续 K&R 1978 专著与 ANSI C 标准中有所修订，这种细节演化本身即是 C 语言从早期形态向标准化演化的证据。须警惕的是，Ritchie 1993 自述的硬件决定论叙事（PDP-11 催生类型系统）可能简化了实际演化过程的多元动因，系统编程抽象需求的独立推动作用在 Ritchie 叙事中着墨较少，须从 CSTR 技术报告与代码档案中补充这一视角 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]。

### 争议三：Multics 退出的责任归属——贝尔实验室管理层 vs MIT vs GE 的多方叙事

争议主题：贝尔实验室 1969 年退出 Multics 项目的决策，在不同当事方的叙述中责任归属不一，这一退出决策直接催生 Thompson 在 PDP-7 上的独立 UNIX 开发，是 UNIX 起源史的关键转折点。

不同立场：其一，贝尔实验室管理层立场。贝尔实验室官方叙事将退出归因于 Multics 项目复杂性超预期、进度滞后、成本超支，Multics 的雄心目标（通用计算分时系统）与贝尔实验室的研究定位不匹配。Vyssotsky 作为贝尔实验室 Multics 项目负责人，其立场反映管理层对项目风险的评估。其二，MIT 立场。Corbató 作为 Multics 首席架构师在 2006 年 CHM 口述史中提供 MIT 视角，强调 Multics 的技术成就与设计前瞻性，将贝尔实验室退出归因于管理层缺乏长期承诺与组织优先级调整。Fano 1966 年 MAC 项目报告反映 MIT 对 Multics 早期进展的乐观评估。其三，Multics 团队立场。Van Vleck 作为 Multics 核心开发者在 multicians.org 回忆录中维护 Multics 项目从 1964 年到 2000 年关机的全过程叙事，强调 Multics 最终在 Honeywell 商业化运行至 2000 年的事实，间接反驳“Multics 失败”的简化叙事。其四，GE 立场。GE 作为 Multics 硬件合作方与后续商业化方，其视角在现有史料中最为稀缺，主要通过 Gertner 2012 年《The Idea Factory》的二手叙述间接呈现。

史料依据：Corbató 与 Vyssotsky 1965 年 AFIPS 论文《Introduction and Overview of the Multics System》是 Multics 系统首篇公开学术论文，代表 MIT、贝尔实验室与 GE 三方合作的官方立场。Fano 1966 年 IEEE 论文《The MAC Project: A Progress Report》是 MIT MAC 项目官方进展报告。Corbató 2006 年 CHM 口述史（Catalog Number 102656855）提供 MIT 视角的退出叙事。Van Vleck multicians.org 回忆录提供 Multics 团队视角。Gertner 2012 年《The Idea Factory》（ISBN 9781594203282）提供贝尔实验室管理层视角的二手叙述。Salus 1994 年《A Quarter Century of UNIX》综合多方叙事但侧重贝尔实验室视角。

史家判断：Multics 退出责任归属无法简单归因于单方。贝尔实验室管理层的风险评估（复杂性、成本、进度）是退出的直接原因，但 MIT 的技术乐观主义与 GE 的硬件商业化利益之间存在三方张力，贝尔实验室的退出是这一张力失衡的结果而非单方过错。按 0 信任原则，Corbató 2006 口述史作为 MIT 当事人叙述存在立场倾向（强调 Multics 技术价值、淡化 MIT 在协作中的责任），须与 Van Vleck multicians.org 叙事与 Gertner 2012 贝尔实验室视角叙述三方互证。须警惕的是，Multics 退出后 Honeywell 商业化运行至 2000 年的事实表明 Multics 并非“失败”项目，贝尔实验室退出更多是组织战略调整而非技术判断。GE 视角的一手叙述稀缺是本争议的史料缺口，Gertner 2012 对 GE 着墨较少，GE 内部档案尚未进入公开档案机构 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]。Multics 退出的史学意义在于：它直接释放 Thompson 与 Ritchie 的创造力，使 1127 室在失去 Multics 项目后转向 PDP-7 上的独立探索，这一组织意外恰是 UNIX 诞生的制度性前提。

## 方法论反思

本卷史料考据的方法论反思须从 0 信任原则的适用性谈起。0 信任原则要求对所有资料（含一手资料）进行考据验证，不得因来源“一手”即直接采信。这一原则在本卷面临独特挑战：UNIX 起源的核心当事人（Thompson、Ritchie、Kernighan、McIlroy）既是历史事件的参与者，又是后世叙事的主要书写者，其当事人叙述同时承担一手史料与二手研究的双重身份。Ritchie 1984 年 BLTJ 自述作为 UNIX 起源时间线最权威的一手来源，其作为当事人一方叙述可能存在立场倾向（强调个人贡献、淡化协作复杂性）与记忆偏差（时间、人物、细节记错）。按 0 信任原则，须与 TUHS 一手代码归档、Bell Labs CSTR 技术报告交叉验证后方可采信。

多源交叉验证不可靠性规则在本卷亦有典型体现。UNIX 哲学的“三条精炼总结”在业界广泛流传，多源一致引用，但其源头可追溯至 Salus 1994 的二手转写而非 McIlroy 1978 原文。这一案例表明，多源一致的二手转述仍可能是大众误解——三条版本虽经多源转引，但其源头是对 McIlroy 1978 四条格言的二手精炼而非原始表述。按多源交叉验证不可靠性规则，考据中须考察这些来源是否相互独立、是否引用自同一一手来源、是否存在信息茧房效应。本卷综述在 UNIX 哲学表述上以 McIlroy 1978 BSTJ 原文为权威基准，Salus 三条与 Raymond 十七条作为后世演化的不同层次标注出处，避免误归。

本卷史料谱系的另一方法论特征是档案不对称。TUHS 归档是核心一手数字证据来源，但 TUHS 主要收录发布版本源码磁带，贝尔实验室 1127 室内部备忘录、邮件存档、决策文档尚未公开数字化，这使 UNIX 起源的内部决策过程（如 Multics 退出决策的具体沟通、C 语言类型系统引入的内部讨论、Thompson-Ritchie 合作的分工细节）难以从内部视角重构。这种档案不对称使本卷叙事不可避免地偏向公开归档（TUHS、BSTJ）所反映的视角，而内部决策过程的重建依赖口述史推断，存在推断偏差风险。

自反性反思：本综述作为 BSD 历史叙事的组成部分，本身存在立场倾向。本卷以“UNIX 的起源”为标题，以 Thompson-Ritchie 合作为叙事主体，这一叙事框架天然地以贝尔实验室 1127 室为中心，可能遮蔽 MIT Multics 团队、GE 硬件团队、BBN ARPANET 团队在同期历史中的角色。Multics 退出责任的叙事以贝尔实验室管理层视角为主导，MIT 与 GE 视角的一手叙述相对稀缺。史家须在叙事中显化这种不对称，通过标注 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证] 与呈现不同立场，使读者能够识别叙事的立场边界。本综述的立场声明：在承认 Thompson 与 Ritchie 对现代计算的基础性贡献的同时，警惕英雄叙事对协作网络与边缘贡献者的遮蔽，力求在档案证据与当事人叙述之间建立批判性距离。

## 缺口与前瞻

本卷史料存在三类缺口，需在未来研究中补全。

档案缺口：其一，贝尔实验室 1127 室内部备忘录与邮件存档未数字化。Multics 退出决策的具体沟通、C 语言类型系统引入的内部讨论、Thompson-Ritchie 合作的分工细节等关键史实，目前主要依赖当事人事后回忆，缺乏同期文档的直接证据。其二，AT&T 1956 同意判决与 1975 年大学许可证的完整法律文本虽可获取，但许可证执行的实务记录（哪些大学索取了源码、分发时间、分发范围）尚未系统整理。其三，GE 作为 Multics 硬件合作方的内部档案未进入公开档案机构，GE 视角的 Multics 叙事几乎空白。未来方向为贝尔实验室档案发掘（如 AT&T 档案馆、Alcatel-Lucent 历史档案）、GE 档案发掘、许可证分发记录的系统整理。

方法论缺口：其一，缺乏 PDP-7 UNIX 重建代码与原始代码的系统比对。TUHS PDP-7 UNIX 重建项目（**s1** 目录树）为推断代码，部分为后世重构，其与 1969-1971 年实际代码的差异尚未有系统量化分析。未来可借助代码考古学方法，对照 PDP-7 硬件手册与 Thompson 1984 自述，评估重建代码的推断可靠性。其二，缺乏 CSTR #8（B 语言）与 CSTR #31（C 语言）的代码层面演化分析。B 到 C 的类型系统引入在技术报告与 Ritchie 1993 自述中有定性叙述，但缺乏基于 V1-V7 源码 diff 的代码层面量化比较。其三，口述史的系统性整理不足。Thompson、Ritchie、Kernighan、McIlroy 的口述史散见于 CHM、CoRecursive 播客等不同来源，缺乏系统性的口述史整理与交叉索引。

史学缺口：其一，Multics 退出责任归属的 GE 视角缺失。GE 作为 Multics 硬件合作方与后续商业化方，其视角在现有叙事中主要通过 Gertner 2012 间接呈现，缺乏 GE 内部档案或 GE 核心成员的系统性口述史。其二，1127 室组织文化的社会学分析不足。Kernighan 2019 提供了 1127 室文化的当事人叙述，但缺乏组织社会学视角的系统分析——1127 室的管理自主权、研究自由度、资源分配机制如何为 UNIX 诞生提供制度性庇护，这一制度分析需借助贝尔实验室组织手册与 AT&T 管理档案。其三，UNIX 早期传播网络的量化分析不足。1975-1978 年 UNIX 源码向大学分发的具体路径、接收机构、衍生版本，目前主要依赖 Salus 1994 的定性叙述，缺乏基于许可证分发记录的社会网络分析。其四，女性与边缘参与者角色的挖掘不足。UNIX 起源叙事以 Thompson、Ritchie、Kernighan、McIlroy 等男性核心成员为主，女性参与者（如贝尔实验室 1127 室的女性程序员与助手）与边缘贡献者的角色在现有史料中几乎缺席 [考据完成：2026-07-28 该处存疑标注属史料缺口，须待原始档案公开后方可补充确证]。

未来研究方向：贝尔实验室档案发掘与 1127 室内部文档数字化，GE 档案发掘与 Multics 商业化史补全，PDP-7 UNIX 重建代码的考古学验证，CSTR 系列技术报告的代码层面演化分析，UNIX 早期传播网络的社会网络分析，1127 室组织文化的制度史研究。这些方向将有助于补全本卷史料的档案缺口、方法论缺口与史学缺口，使第一卷的叙事从当事人叙述主导转向档案证据与当事人叙述的批判性互证。

### 一手史料

- **Ritchie D M, Thompson K. The UNIX Time-Sharing System [J]. Communications of the ACM, 1974, 17(7): 365-375. DOI: 10.1145/361011.361061.**
UNIX 首次向学术界完整披露的奠基性论文，由作者亲笔撰写。论文系统陈述文件系统 i-node 抽象、管道、shell、fork/exec 进程模型，被 BSD 谱系所有版本直接继承，是 FreeBSD 当代内核的设计原点。其原始性无可替代，但 1974 版对 PDP-11/70 与 Interdata 移植尚未涉及，须与 1978 BSTJ 扩展版互参。
- **Ritchie D M, Thompson K. The UNIX Time-Sharing System [J]. Bell System Technical Journal, 1978, 57(6, Part 2): 1905-1929.**
1974 CACM 论文的更新扩展版，新增 PDP-11/70 与 Interdata 8/32 机型描述，对 BSD 直接继承的 UNIX 设计作了 4 年实践后的反思与修订。BSTJ 1978 UNIX Issue 是 BSD 起源前夕学术界对 UNIX 最完整的一次集中陈述，卷内同期论文 Thompson"UNIX Implementation"、Bourne"The UNIX Shell"、Johnson 与 Ritchie"Portability of C Programs"共同构成 UNIX 起源史的一手文献群。
- **McIlroy M D, Pinson E N, Tague B A. UNIX Time-Sharing System: Foreword [J]. Bell System Technical Journal, 1978, 57(6, Part 2): 1899-1904.**
三人合署的 BSTJ 57.6 前言，其中"Style"小节首次以文字形式系统阐述 UNIX 工程哲学的四条格言：让每个程序做好一件事；期望每个程序的输出成为另一个程序的输入；尽早设计与构建软件以试用；优先使用工具而非不熟练的帮助。该文是"Do one thing well"原则的最早一手文献来源，须与 Raymond 2003 著作交叉验证，注意业内常将三条精炼总结误归于 McIlroy 1978 原文，实则三条版本出自 Salus 1994 的二手转写。
- **Corbató F J, Vyssotsky V A. Introduction and Overview of the Multics System [C]//Proceedings of the 1965 Fall Joint Computer Conference. Las Vegas: AFIPS, 1965: 185-196.**
Multics 系统的首篇公开学术论文，由 Corbató 与 Vyssotsky 联合发表，代表 MIT、贝尔实验室与 GE 三方合作的官方立场。论文首次向学术界完整介绍 Multics 的整体架构、分层安全模型、动态链接、单级存储等创新设计，是理解 UNIX 诞生前 Multics 遗产的核心一手文献。Corbató 作为 Multics 首席架构师，Vyssotsky 作为贝尔实验室 Multics 项目负责人，二人合著具有不可替代的原始性。
- **Fano R M. The MAC Project: A Progress Report [J]. IEEE Transactions on Human Factors in Electronics, 1966, 7(1): 2-12.**
MIT MAC 项目首任主任 Fano 撰写的官方进展报告，系统总结 1963-1965 年研究进展，包括 Multics 设计目标、早期架构与 CTSS 向 Multics 的过渡计划。该文是 Multics 早期发展史的核心一手文献，对理解 Multics 设计哲学与工程背景具关键价值。其局限在于为官方报告，对项目内部争议与成本超支问题未有陈述，须与 Bell Labs 1969 年退出决策备忘录互参。
- **Thompson K. UNIX Implementation [J]. Bell System Technical Journal, 1978, 57(6): 1931-1946.**
Thompson 亲笔撰写的 UNIX 内核实现技术论文，明确记载 V7 内核“约 10,000 行 C 代码与约 1,000 行汇编代码”。该文是 UNIX 内核规模、结构、实现细节最权威的一手来源，纠正了后世对早期 UNIX 代码量的多种不准确估计。论文对中断处理、进程调度、文件系统缓冲区管理等机制作了工程级陈述，是研究 V7 内核演化的必读一手文献。
- **Licklider J C R. Man-Computer Symbiosis [J]. IRE Transactions on Human Factors in Electronics, 1960, 1(1): 4-11.**
人机交互与分时系统概念的奠基性论文，首次系统阐述“人机共生”理念，直接影响 ARPA IPTO 研究方向，为 Multics、CTSS 等分时系统提供思想源头。Licklider 时任 ARPA IPTO 主任，其资助的研究项目直接孕育了 Multics 与 ARPANET。该文属 UNIX 起源史的思想源头文献，局限在于为概念性论述，缺乏工程实现细节。

### 二手研究

- **Salus P H. A Quarter Century of UNIX [M]. Reading: Addison-Wesley, 1994. ISBN: 0-201-54777-5.**
Salus 的 UNIX 通史是 UNIX 史书写的奠基性二手著作，覆盖 1969-1994 年二十五年间 UNIX 的诞生、传播、商业化与 BSD 分化。该书是众多 UNIX 史实（如 Bell Labs 1969 年退出 Multics、AT&T 1975 年大学许可证仅收 150 美元工本费、UNICS 命名由来等）的主要二手转写来源。其局限在于叙事线性化、对争议点（如 BBN 与 Berkeley TCP/IP 争议）未充分呈现多方视角，且部分时间线经后世考据需修订。
- **Kernighan B W. UNIX 传奇：历史与回忆 [M]. 韩磊，译。北京：人民邮电出版社，2021. ISBN: 978-7-115-55717-9.**
Kernighan 作为贝尔实验室 UNIX 团队核心成员的亲笔回忆录，原书英文版 *UNIX: A History and a Memoir* 于 2019 年由 Princeton University Press 出版。该书兼具一手史料（作者亲历）与二手研究（事后回忆）的双重性质，对 Bell Labs 1127 室文化、Thompson/Ritchie 合作关系、UNIX 命名轶事等提供了当事人视角。其局限在于回忆录性质，对部分时序细节需与 Ritchie 1984 BLTJ 文章交叉印证。
- **Gertner J. The Idea Factory: Bell Labs and the Great Age of American Innovation [M]. New York: Penguin Press, 2012. ISBN: 9781594203282.**
Gertner 对贝尔实验室创新文化的通俗史著，覆盖晶体管、信息论、UNIX、光纤通信等重大创新。该书对 Bell Labs 1969 年组织结构、物理研究部与计算研究部的关系、管理层对 Multics 退出的决策机制提供了可读性强的二手叙述。其局限在于为面向大众的非学术著作，对 UNIX 技术细节着墨较少，1127 室精确层级描述与 Bell Labs 1969 年原始组织手册存在出入。
- **Raymond E S. The Art of UNIX Programming [M]. Boston: Addison-Wesley Professional, 2003. ISBN: 978-0-13-142901-7.**
Raymond 将 UNIX 哲学系统化为 17 条设计原则的著作，附录 B 提供详细参考文献。该书是 UNIX 哲学最广为人知的二手总结，但 Raymond 的 17 条原则体系系事后系统建构，与 McIlroy 1978 原始四条工程格言存在层次差异。引用时须明确区分一手工程经验与二手哲学体系，该书对哲学的概括虽有争议但核心事实经 Kernighan 2019 交叉验证。
- **Pike R, Kernighan B W. Program Design in the UNIX Environment [J]. AT&T Bell Laboratories Technical Journal, 1984, 63(8): 1595-1605.**
Pike 1983 年夏季 USENIX 多伦多会议演讲"UNIX Style, or `cat -v` Considered Harmful?"的正式期刊发表版本，以 `cat -v` 争议为核心案例系统阐述 UNIX 程序设计风格与哲学原则。该文是 UNIX 哲学从工程格言向系统化表述过渡的关键节点，兼具一手（作者为 Bell Labs 成员）与二手（事后总结）性质。按 Wiley 期刊元数据（onlinelibrary.wiley.com/toc/15387305b/1984/63/8），本期（Vol. 63, Issue 8, Part 2, October 1984）中 Ritchie"Evolution of the Unix Time-sharing System"居前（pp.1577-1593），Pike & Kernighan 本文居后（pp.1595-1605），两者页码不可混淆。
- **McKusick M K, Bostic K, Karels M J, Quarterman J S. The Design and Implementation of the 4.4BSD Operating System [M]. Reading: Addison-Wesley, 1996. ISBN: 0-201-54979-4.**
CSRG 核心成员合著的 4.4BSD 设计实现专著，是 BSD 谱系技术史最权威的二手著作。该书对 BSD 从 1BSD（1978）到 4.4BSD-Lite（1994）的演化路径、内核架构、文件系统、网络栈等提供了当事人视角的系统陈述。其局限在于聚焦 4.4BSD 技术实现，对 UNIX 起源阶段（1969-1978）仅作背景性回顾，须与 Salus 1994、Kernighan 2019 互参。
- **Lions J. Lions' Commentary on UNIX 6th Edition [M]. Raleigh: Peer-to-Peer Communications, 1996 复刻版。原版 1977.**
John Lions 1977 年为新南威尔士大学课程编写的 V6 UNIX 源代码注释本，长期因 AT&T 许可证限制地下流通，1996 年才正式公开出版。该注释本是 UNIX 教学的奠基性文献，对 V6 内核约 9,000 行 C 代码逐行注释，是理解早期 UNIX 内核结构的最重要二手文献。其局限在于聚焦 V6（1975），对 V7（1979）及后续 BSD 演化未涉及。

### 工具书与参考

- **Kernighan B W, Ritchie D M. The C Programming Language [M]. Englewood Cliffs: Prentice-Hall, 1978. ISBN: 0-13-110163-3.**
通称 K&R 第一版，C 语言创始人合著的 C 语言权威参考书。该书既是 C 语言的定义性文献（1978 年 ANSI C 标准化前的事实标准），又是 UNIX 工具哲学的示范文本——全书以小工具组合演示 UNIX 编程风格。K&R 第一版记载的 C 语言形态是 1973 年 UNIX 用 C 重写时的语言版本，对理解 V6/V7 内核源代码具直接参考价值。须与 1988 年第二版（ANSI C）区分。
- **Kernighan B W, Ritchie D M. C 程序设计语言 [M]. 徐宝文，李志，译。第 2 版。北京：机械工业出版社，2019. ISBN: 978-7-111-61794-5.**
K&R 第二版的中文译本，基于 ANSI C 标准。该书是中文读者学习 C 语言与 UNIX 编程哲学的权威工具书，对 BSD 谱系中文社区的技术传承具重要意义。译本须与英文原版互参，注意中文译本对部分术语的翻译选择。
- **Kernighan B W, Pike R. The UNIX Programming Environment [M]. Englewood Cliffs: Prentice-Hall, 1984. ISBN: 0-13-937681-X.**
Kernighan 与 Pike 合著的 UNIX 编程环境经典系统著作，对 UNIX 工具使用、shell 编程、程序设计哲学有深远影响。该书与 McIlroy 1978 四条格言、Pike 1983/1984 论文共同构成 UNIX 哲学的核心一手文献群，是理解 UNIX 时期编程审美与实践的必读工具书。
- **DEC PDP-7 Handbook [M]. Maynard: Digital Equipment Corporation, 1965.**
DEC 官方 PDP-7 硬件手册，记载 PDP-7 的 18 位字长、4K 字标准内存、1.75 微秒内存周期等关键规格。该手册是考据 UNIX 诞生硬件约束的核心工具书，PDP-7 的字寻址特性直接塑造了 B 语言无类型设计。手册版权页标注 © 1964，经 Bob Supnik 论文与 DEC 官方时间线交叉印证 1964 年 12 月首次出货为准确日期，bitsavers.org 提供 PDF 存档。
- **DEC PDP-11 Processor Handbook [M]. Maynard: Digital Equipment Corporation, 1970.**
DEC 官方 PDP-11 处理器手册，记载 PDP-11 的 16 位字长、字节寻址、内存管理等关键特性。该手册是理解 C 语言类型系统引入动机的核心工具书——PDP-11 字节寻址需要区分字节与字，直接催生 Ritchie 1971 年 NB 语言的字符类型与 1972-1973 年 C 语言的类型系统演化。
- **TUHS. The Unix Heritage Society 源代码归档 [EB/OL]. (1971)[2026-07-18]. <https://www.tuhs.org/>.**
