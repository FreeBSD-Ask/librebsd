**要点**：

- Jun Ebihara（转写讹作 Jun Ibehara）自述其 BSD 缘起与社区参与：1987 年二十岁时在大学以 Sony News 工作站上的 4.2BSD 入门，并用 YACC 编写 BASIC 解释器；1993 年脱离富士通集团创办 SOM 公司后，应友人建议创建日本 NetBSD 邮件列表，二十年累计约 872 名订阅者与上万封邮件；其友人、NetBSD 核心成员萩野纯一郎（itojun）构成其进入开发者社群的直接纽带。这一自述为日本 BSD 社区起源提供了少见的当事人证词。 [存疑脚注] 转写将姓名讹作 Jun Ibehara、Hagi no Junichiro，正文依语音与语境分别推断为 Jun Ebihara 与 itojun（萩野纯一郎），引用前宜核对原始音轨。（BSD Now EP96，[1353.92-1484.82]，L1）
- 访谈核心展示环节：Ebihara 逐一演示运行 NetBSD 的边缘设备——夏普智能手机（W-ZERO3 系）、夏普 Zaurus PDA（StrongARM 处理器）、NetWalker 掌上终端与 Raspberry Pi 2，并提及运行 NetBSD 的 SH4 处理器迷你机器人；他强调同一份 ARM 二进制可跨设备运行，同一操作系统覆盖从掌机到工作站的全部形态因子，其公司主业即将 NetBSD 移植到电视、路由器、打印机与网络相机等嵌入式产品。 [存疑脚注] 设备专名在转写中失真（讹作 003、Xaos、Species 等），W-ZERO3、Zaurus、SH4 机器人等均依语音与语境推断，引用前宜核对原始音轨。（BSD Now EP96，[1493.82-1730.24]，L1）
- Ebihara 以英国 Goodwood 老车赛车节修复法拉利、莲花等经典赛车的文化类比计算机收藏圈：爱好者挖掘旧机器、更换电容与电源单元，让欧姆龙 Luna 等老工作站运行 NetBSD 7 等当前系统并运转良好；在他口中这既是乐趣也是手艺，把“过时”硬件重新纳入可用的技术世界而非博物馆式封存，这一表述正呼应本期以冷门技术为主题的编辑取向。 [存疑脚注] “Omron”“Luna”依转写语音推断为欧姆龙 Luna 工作站，引用前宜核对原始音轨。（BSD Now EP96，[1747.14-1836.94]，L1）

**史料**：

- 本期提及的一手史料密度较高：BSDCan 2015 演讲视频（Ryan Stone 论 PCI SR-IOV、George Neville-Neil 的 Measure Twice Code Once、Kirk McKusick 的 ZFS 实现导论、Matt Ahrens 论 OpenZFS 远程复制、Warner Losh 论 IO 调度与 CAM、mandoc 主题演讲的备用录音与幻灯片）；FreeBSD 基金会资助者的两篇 BSDCan 行程报告（Stephen Douglas、Ahmed Kamal）；Oracle 提交给 OpenBSD 的 PF SMP 补丁邮件（附 AMD64 panic 截图，自称可百分之百复现）；OpenSSH 6.9、DragonFly BSD 4.2.0（含 Matt Dillon 的 HAMMER2 状态更新）、OpenSMTPD 5.7.1 发布公告；以及 FreeBSD 8 sendmail 弱 DH 参数勘误公告。 [存疑脚注] 演讲者姓名多处转写失真（讹作 Werner Losh、Ed Shouten、Ingo Suarez、Valesovod Stokhov 等），分别依语境推断为 Warner Losh、Ed Schouten、Ingo Schwarze、Vsevolod Stakhov，引用前宜核对原始音轨。（BSD Now EP96，[531.56-595.76]，L2）

**史观**：

- 总纲10 动手者创造历史：Ebihara 的叙事结构本身即是一份史学立场声明：历史由当事人经验构成——二十年邮件列表的 872 人、1999 年以来约 50 名用户组成员维护日本 FTP 镜像与网页、在千余人规模的开源会议上演示 2GB Raspberry Pi 镜像并借 pkgsrc 推广打包生态——这些默默做事的移植工程师、打包者与镜像维护者而非明星黑客构成叙事主体；同时 Zaurus、NetWalker 与工作站被本体论上平等对待，不存在“先进平台淘汰落后平台”的进步等级，只有同一系统在不同机器上的流转。（BSD Now EP96，[1925.08-2142.70]，L1）[订正：原 [1925.08-2108.62]，2026-09-30 SenseAudio 重转核对]
- 总纲4 分离聚合是永恒规律：Oracle 为下一代 Solaris 采用 OpenBSD 的 PF 并将 SMP 补丁以概念验证形式交回上游，主持人顺势设想 FreeBSD 与 OpenBSD 两条 PF 路线未来或可重新统一；PF 自 2001 年诞生后经历 OpenBSD 与 FreeBSD 的分离、多年独立演进、再向商业系统流转，其代码在各方之间不断分离与聚合，权力与实现随之再分配——这呈现的不是防火墙技术的单向进步，而是同一形式在多个阵营间的循环流动。（BSD Now EP96，[604.76-713.94]，L2）

**辨析**：

- 由 Ted Unangst 关于 OpenBSD 工具重写与精简的文章引出的“软件最佳使用期限”之辨：bzip2 上一次发布还是 2006 年针对一个 CVE 的修复，主持人追问“没有已知 bug 不等于没有未知 bug”，并引文章观点——重写的目标不是修复“当前有 bug 的代码状态”，而是针对“预期未来的有 bug 状态”，即修复未知错误（约 101-112 秒处）；可辨析处在于：维护停滞的依赖库风险如何评估、重写是否必然优于继续维护，以及“过期”隐喻对软件生命周期的解释力与局限。 [存疑脚注] 文章作者转写讹作 Ted Ewing，依语境推断为 Ted Unangst，引用前宜核对原始音轨。（BSD Now EP96，[384.00-426.68]，L2）
