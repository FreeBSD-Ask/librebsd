# 1.4.1 套接字接口在两侧的实现差异

<!-- ROW_MINE: lkml.messages.5641755 -->`
- 【Linux社区】2001-02-05 Dan Kegel（dank@alumni.caltech.edu）就 Tony Finch 向 FreeBSD 提交并合入 -CURRENT 的 TCP_NOPUSH 正确 uncorking 补丁，提出标准化建议：对比两个 OS 的 setsockopt 定义，“FreeBSD: netinet/tcp.h”中 TCP_NOPUSH=0x04，“Linux: netinet/tcp.h”中 TCP_CORK=0x03——同一语义但数值不同。Kegel 主张“If it does behave identically, it might be time to standardize the symbolic name for this option, to make apps more portable between the two OS's. (It'd be nice to also standardize the numeric value, in the interest of making the ABI's more compatible, too.)”，是 BSD↔Linux TCP 套接字选项语义标准化的一手证据。 

<!-- ROW_MINE: lkml.messages.1865213 -->`
- 【Linux社区】2000-12-07 Veritas 工程师 Tigran Aivazian（tigran@veritas.com）在 truncate(2) 权限补丁串中直接引 FreeBSD 作语义实证：他说明为何仍对 append-only 文件返回 EPERM——“Facts verified under FreeBSD 4.2”，并明确设计权衡：“The rationale for being compatible with 4.4BSD on append-only but not on immutable is -- for immutable we can do the test by means of permission() fast but for append-only we would need an extra if() above permission so let's just be BSD-compatible”，补丁注释留“EPERM for 4.4BSD compat. EACCES would make more sense”。Linux truncate(2) 以 4.4BSD 语义为基准作选择性兼容的一手证据。 

<!-- ROW_MINE: lkml.messages.2067746 -->`
- 【Linux社区】2003 年 7 月 Daniel Cavanagh 在 LKML 提交 linux kernel problem (disklabel and swap) 报告，指出 OpenBSD 经 disklabel 告知外界某分区/切片为 swap 而非在 swap 切片起点，linux kernel 对此不知情而要求 SWAPSPACE2 位于分区/切片起点，并实测 OpenBSD 强制换页后覆写了切片起点的 SWAPSPACE2 签名。BSD disklabel 与 Linux swapon 语义冲突的第一手报告。 

<!-- ROW_MINE: lkml.messages.5183453 -->`
- 【Linux社区】2013年4月 Adrian Chadd(adrian@freebsd.org) 在“Re: Version number policy!”串中 以其身为 FreeBSD 用户、熟知 Linux 之外另有未全支持特性的 ext2/3 实现的经历“I'm a FreeBSD user. I know what it's like to have an alternate, out of linux implementation of ext2/3 that doesn't implement all of the features”，论证实现差异会使新版本文件系统挂上旧内核未必善终，是 BSD 文件系统经验反哺 Linux 固件版本治理讨论的实例

- 【Linux社区】2017年6月 Al Viro(viro@zeniv.linux.org.uk) 在“Re: UFS s_maxbytes bogosity”中 给出按 BSD 树深度计算 s_maxbytes 的实现，“for UFS2 the function I'd posted would do the right thing”是 Linux 对 FreeBSD/44BSD 位宽的定向兼容。 `
