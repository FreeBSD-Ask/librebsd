# 1.4.4 文件系统布局的相似性辨析

<!-- ROW_MINE: lkml.messages.1782605 -->`
- 【Linux社区】2006 年 1 月 Suleiman Souhlal（FreeBSD 组织）在 LKML“soft update vs journaling?”线程中反驳 Diego Calleja 断言 FreeBSD“getting rid of softupdates”的说法，公开回应“You read the message wrong: We're not getting rid of softupdates”，为 BSD softupdate 策略在 Linux 社区留下明确立场——FreeBSD 在 UFS 上引入 journaling 的同时仍保留 softupdate 机制，展示 BSD 文件系统策略演进的公开锚点 `

<!-- ROW_MINE: lkml.messages.6522826 -->`
- 【Linux社区】2006年John Richard Moser在softupdates vs journaling串中转述Diego Calleja立场 FreeBSD is implementing journaling for UFS and getting rid of softupdates，附引freebsd-hackers 2004年12月邮件原文：softupdates still requires a fsck run on recovery, and the multi-terabyte filesystems that are possible these days make fsck a very long and unpleasant experience, even with bg-fsck；是FreeBSD UFS从softupdates转向journaling的路线讨论经Linux侧转发的一手证据。 

<!-- ROW_MINE: lkml.messages.7084295 -->`
- 【Linux社区】2001年9月FreeBSD核心团队成员Warner Losh（imp@harmony.village.org）就Slashdot“BSD-Linux FlameWar over SoftRAID”报道公开发言，以1992年ObjectBuilder for Linux老资历背书，直面Soren Schmidt SoftRAID代码被Linux直接拷贝：“The fact of the matter is that the code was copied from FreeBSD verbatim, or with minor alterations. That's not a problem at all, since our license allows for that. The problem came in that Soren's name was removed from the headers”，区分attribution与license问题，声明“FreeBSD's core team has never issued any statements on this issue”，主张“Healthy code and concept sharing between Linux and FreeBSD... is in everyone's best interest”；BSD核心团队对Linux采用BSD代码的治理立场声明，与2007 ath5k/GPL-BSD冲突（205.x）形成前后里程碑。 `

<!-- ROW_MINE: freebsd-hackers.messages.2515805 -->`
- 【Linux社区】1998年2月 Sean Eric Fagan(sef@kithrup.com) 在“Re: kirk's soft-update integration..”串中 类比 Kirk soft-update 许可证与 GPL 第四条款的相似性，“If you read the fourth clause, it requires, like the GPL, that the entire program's source be included”，是 BSD 维护者对 BSD 许可证与 GPL 义务等同性的早期法律论证 `
