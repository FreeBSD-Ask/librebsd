# 1.4.6 共同技术传统与代码借用的分野

<!-- ROW_MINE: lkml.messages.5479906 -->`
- 【Linux社区】2012 年 3 月 Adrian Chadd 回应 Joe Perches 关于 ath5k printk 宏的疑问时明确指出：“The FreeBSD HAL used to be like this. I changed it so it didn't evaluate the arguments before it figured out whether or not to do the (k)printf()”，公开说明 ath5k 的调试宏源自 FreeBSD HAL 的实践并被改良后移植到 Linux ath5k 驱动，是 BSD 无线硬件抽象层代码实践进入 Linux 内核无线栈的直接证据 `

<!-- ROW_MINE: lkml.messages.5822881 -->`
- 【Linux社区】2004年Bill Huey（hui，bhuey@lnxw.com）在Linux BKL撤除串中论及FreeBSD-current自适应锁（adaptive mutex）与Solaris MUTEX设计，评价“the FreeBSD community has ignored a lot of the really hard work of pushing down locks in favor of 'getting fancier locks', which only abuses thread priorities and the scheduler”，并援引Bill Irwin闲谈提供的数据，将Linux手雕per-CPU感知的SMP路线与FreeBSD/Solaris复杂SMP基础架构作对照，认为Linux路线当下明显更正确，是SMP锁策略跨内核比较的一手存档。 

<!-- ROW_MINE: lkml.messages.1988789 -->`
- 【Linux社区】2003年6月Adaptec aic79xx/aic7xxx SCSI 驱动维护者Justin T. Gibbs 在 aic79xx 问题串中，为跑 Red Hat 8.0 的用户指出 the stock driver in 8.0 可能已落后近一年，并把 Linux 版本驱动的 RPM、DUD 软盘与源码下载指针明确挂在 FreeBSD 个人站点：http://people.FreeBSD.org/~gibbs/linux/RPM/aic79xx/、/DUD/aic79xx/、/SRC/。FreeBSD 维护者的个人主页成为 Linux 内核 aic79xx SCSI 驱动的用户分发通道，是 FreeBSD 内核工程与 Linux 内核 SCSI 子系统之间长期代码流动的直接物证，也说明 FreeBSD 侧维护的驱动代码反过来被 Linux 社区作为上游来源使用。 

<!-- ROW_MINE: lkml.messages.1625369 -->`
- 【Linux社区】2003年12月 Matthew Wilcox(willy@debian.org) 在“Re: partially encrypted filesystem”串中 复述 Acorn RISCiX 压缩页技术，指出其为“4.3BSD based”并以之论证 Linux page cache 需支持更大 chunk，是 BSD 血统技术经验被 Linux 内核作者直接借用的例证 `

<!-- ROW_MINE: lkml.messages.1724762 -->`
- 【Linux社区】2004年9月 Jan Blunck(j.blunck@tu-harburg.de) 在“Re: [PATCH 1/3] copyfile: generic_sendpage”串中 说明自己的 union-mount 内核实现以 McKusick 论文为设计蓝本，“The focus is on the basic functionality explained by McKusick”，是 BSD 血统文件系统技术被 Linux VFS 层直接借用的例证 `
