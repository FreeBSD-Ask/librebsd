# 1.2.3 独立实现中的接口复刻路径

<!-- ROW_MINE: lkml.messages.1693799 -->`
- 【Linux社区】2005 年 1 月 Dmitry Torokhov 向 Andries Brouwer 提交 i8042 访问时序补丁时明确写道“I peeked into FreeBSD code and they use delays to access both registers and I wonder if that's the piece that makes i8042 mysteriously fail on some boards”，把 FreeBSD i8042 驱动实现作为 Linux 2.6 输入子系统故障定位的对照基准，是 BSD 驱动代码进入 Linux 内核开发对话的直接证据 `

<!-- ROW_MINE: lkml.messages.3766149 -->`
- 【Linux社区】2006年9月Joerg Roedel就EtherIP tunnel driver补丁RESUBMIT回复jamal“You just need to use GRE tunnel”与“the only other OS that implemented this got it wrong”两项质疑：明确“at least OpenBSD, NetBSD and FreeBSD support the EtherIP protocol. The first of them was OpenBSD”，指出RFC 2397未定义16位以太网头内MUST=0011的字节序与位序，为保OpenBSD互操作性照OpenBSD实现且不校验入站EtherIP头；援引Google检索到的BSD forums相关讨论与一位希望其NetBSD实现与Linux互通的用户作为驱动初衷，回应“I am not a friend of censorship...users should have the freedom to decide”；Linux内核协议栈以OpenBSD为互操作基准落地EtherIP的一手证据。 `

<!-- ROW_MINE: lkml.messages.3827779 -->`
- 【Linux社区】2023 年 10 月 OpenBSD 创始人 Theo de Raadt 在 mseal() RFC PATCH v1 讨论中直接介入：“mseal() is a clone of mimmutable(2), but with an extremely over-complicated API based upon dubious arguments. I designed mimmutable(2) [1] in OpenBSD, it took about a year to get all the components working correctly. There were many intermediate API during development, but in the end the API is simply: int mimmutable(void *addr, size_t len)”“Very simple semantics. The only case where the immutable marker is ignored is during address space teardown as a result of process termination”，Jeff Xu 随即就 mimmutable 是否覆盖 mlock/madvice 场景发问，是 OpenBSD 作者以 API 设计权威身份反向审视 Linux mseal 语义的一手证据 `
