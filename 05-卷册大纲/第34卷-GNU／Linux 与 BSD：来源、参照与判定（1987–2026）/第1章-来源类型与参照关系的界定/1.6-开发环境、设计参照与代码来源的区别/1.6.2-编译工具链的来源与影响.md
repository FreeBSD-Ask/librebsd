# 1.6.2 编译工具链的来源与影响

<!-- ROW_MINE: lkml.messages.4164828 -->`
- 【Linux社区】2007年9月2日OpenBSD pkgtools维护者Marc Espie在lkml发表“GPL weasels and the atheros stink”，为Reyk Floeter与Theo de Raadt辩护并直指法律与伦理双重问题：Reyk将代码以ISC/GPL双许可发布后外出度假，Jiri Slaby等人在他不在时将文件改为仅GPL，Espie指出“The ISC licence is perfectly compatible with the GPL (note to GPL trolls: this new licence does not have any advertizing clause, which was the ONLY issue with the old licence)”，故移除无必要；他将其诊断为主线“pride”与“GPL fan-boys”的独占行为，最后警告GPL阵营若继续“absorbing and relicensing and evolving code”则他未来对gcc、binutils、kde的贡献将改为保留ISC补丁形式。 `

<!-- ROW_MINE: lkml.messages.1794682 -->`
- 【Linux社区】2007-09-02 Jonathan A. George（jageorge@austin.rr.com）在“GPL weasels and the atheros stink”串中回击对 Marc B. Cox 邮件的防御性反驳：他设问“Question #1: Is it _ethical_ to take someone else's actively maintained work (for example an OpenBSD driver) and make changes which can not be shared/used by the original developer/maintainer?”自答“No it is not ethical”；再问“Question #2: Is it _technically beneficial_ to branch an OSS work in such a way as to diminish the ability to share contributions between projects?”并要求“don't let the rude language distract from doing the right thing”。P.S. 追加法律问题：“it could be legally dubious to relicense an existing file from the OpenBSD license”。atheros 驱动 OpenBSD→GPL 重许可争议中 BSD 阵营最直接的伦理+法律双轨反驳。 `

<!-- ROW_MINE: fb-5392 -->`
- 【Linux社区】2010年11月 Daniel Nebdal 在“[head tinderbox] failure on powerpc64/powerpc”串中 将选择 BSD 许可编译器描述为优于 GPL 版本，是 BSD 阵营对 GPL 工具链的持续态度样本 ``The main thing is that it's BSD-licensed instead of GPL` `

<!-- ROW_MINE: freebsd-hackers.messages.1315779 -->`
- 【Linux社区】2015年 Chris H (bsd-lists at bsdforge.com) 在“GSoC 2015 Task: Unifying ping and ping6”串中透露 liboping 作者愿意从“LGPL/GPLv2 licensed”重释为“BSD/MIT”，是 BSD 社区借 GSoC 机制尝试驯化 GPL 生态工具进入基线的边缘案例 `

<!-- ROW_MINE: linux-fsdevel.messages.419383 -->`
- 【Linux社区】2020年7月 Mickaël Salaün(mic@digikod.net) 在“[PATCH v15 00/10] Landlock LSM”中 简化对象/规则/规则集管理（SLOC 1542→1273、Jann Horn 贡献更保守的内存释放）、引入规则层级防止嵌套沙箱越权，并公开列出 dentry 路径遍历与 UnionFS 两项限制，“FreeBSD Capsicum or OpenBSD Pledge/Unveil”在此首次进入内核提交流成为 BSD 沙箱设计来源的正式声明。 `

<!-- ROW_MINE: linux-fsdevel.messages.277074 -->`
- 【Linux社区】2006年5月 Evgeniy Dushistov(dushistov@mail.ru) 在“Re: [PATCH 2/2] ufs: directory and page cache: from blocks to pages”中 回应 Andrew Morton 关于 Linux 上如何创建 UFS 的疑问，“had a go at porting BSD ufsutils ... and nearly died”是 BSD 工具链进入 Linux 生态阻力的一处实证。 `

<!-- ROW_MINE: linux-fsdevel.messages.556563 -->`
- 【Linux社区】2018年 Boaz Harrosh(boazh@netapp.com) 在“ZUF文件系统构建与许可”中 为NetApp的ZUF零拷贝用户态供给文件系统采用GPL-2.0或BSD-3-Clause双许可，“GPL-2.0 OR BSD-3-Clause”是 BSD许可证进入Linux新文件系统提交的标准范式 `

<!-- ROW_MINE: linux-fsdevel.messages.603727 -->`
- 【Linux社区】2025年 Aditya Garg(gargaditya08@live.com) 在“Re: [RFC] apfs: thoughts on upstreaming an out-of-tree module”中 质疑 BSD3 许可的 LZFSE/LZVN 能否进内核，“GPL-compatible, but what is the kernel's policy on external algorithms being included”是 BSD 许可进入 Linux 内核的治理争议 `

<!-- ROW_MINE: netdev.messages.8649013 -->`
- 【Linux社区】2018年 Jakub Kicinski 在“[PATCH bpf-next 3/3] tools: bpftool: dual license all files”中 将 bpftool 全部文件统一为 GPL-2.0-only 或 BSD-2-Clause 双授权，“dual licensed under GPLv2 and BSD-2-Clause”是 BSD 许可证在 Linux 网络工具链的规模化落地 `

<!-- ROW_MINE: netdev.messages.8952279 -->`
- 【Linux社区】2023年3月 作者 Jakub Kicinski 在“[PATCH net 3/3] ynl: make the tooling check the license”中 让 YNL 生成器读取并校验 spec 的 SPDX 标签，“GPL-2.0 WITH Linux-syscall-note OR BSD-3-Clause”是 BSD 双重许可在 net-next 工具链中被机器强制执行的形态 `
