# 277.1.5 缺口与前瞻

本卷史料的缺口集中于四处，未来研究方向亦由此展开。
其一，Stanford M1412 档案的数字化与系统利用。M1412 档案保留了 NeXT 时期低公开度工程师的贡献记录，是纠正“Apple 品牌中心叙事”的关键边缘者史料，但目前需现场查阅，数字化程度有限。未来方向为推动 M1412 档案的数字化（至少为工程文档与邮件列表存档建立索引），使 Mike Parkhill、Doug McCallum、Peter Lipson 等工程师的贡献可被远程考据。
其二，XNU 快照发布机制对个人贡献者的遮蔽。Apple 以 release tag 形式发布 XNU 快照而非逐 commit 镜像内部 Git 历史，使 first_commit 集中于 2003-08-08，个人贡献者被“文件级聚合”遮蔽。**darwin.duckdb** 查询 L7.5.1 显示 XNU bsd/ 目录 BSD 子系统文件（如 bsd/vfs/vfs_syscalls.c 88 commits、bsd/vfs/vfs_subr.c 85 commits、bsd/kern/kern_exec.c 83 commits）在 XNU 公开源码快照中持续维护，但维护者身份与 NeXT 时期的对应无法从 commit 历史直接追溯。未来方向为结合 CREDITS 文件、Darwin 邮件列表存档（darwinos-users、darwinos-developers、darwinos-cvs）与 Apple 内部工程文档披露（如有）重建个人贡献者谱系。
其三，Apple Silicon 期 XNU ARM64 内部文档未公开。Apple 自 2020 年 Mac Transition to Apple Silicon 后未公开 XNU ARM64 内部文档，使 BSD 层在 ARM64 架构上的适配细节（**osfmk/arm64/**、**bsd/arm64/**）无法从官方文档验证。Asahi Linux 项目的逆向工程是当前唯一外部参照，但其覆盖范围限于 Linux 移植所需，非 XNU 全貌。未来方向为推动 Apple 公开更多 XNU ARM64 工程文档，或以逆向工程社区协作系统化记录 ARM64 适配细节。
其四，Darwin 与 FreeBSD 代码 diff 的量化分析。**freebsd.duckdb** 已提供 freebsd-src 仓库的 commit 元数据，但 Darwin 源码不在数据库中，使双向流动的量化分析受限。Robert Watson 2001-08-29 与 2008-07-31 的 commit、David Chisnall 2011-11-20 的 xlocale 移植 commit 是代码级证据，但整体双向流动的规模、方向与时间分布尚需系统量化。未来方向为建立 Darwin 源码快照与 FreeBSD 版本的逐文件 diff 数据库，量化双向流动的 commit 级证据。
此外，方法论层面的前瞻是：本卷叙事须在“Apple 品牌中心叙事”与“BSD 谱系延续”之间维持平衡，既不否认 Apple 对 BSD 层的工程投入与商业化成功，亦不将 BSD 代码在 macOS 中的延续简化为“Apple 独立维护”。此平衡是“隐形 BSD 基石”史观的核心——BSD 代码在 macOS 中既是“隐形的”（被品牌叙事遮蔽），又是“基石的”（构成 Darwin/XNU 的工程根基），二者不可偏废。
