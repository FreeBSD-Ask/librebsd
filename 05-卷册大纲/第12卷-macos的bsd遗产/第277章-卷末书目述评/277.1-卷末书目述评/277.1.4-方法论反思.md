# 277.1.4 方法论反思

本卷方法论反思须直面三重张力，并对史家自身叙事立场进行自反性检视。
第一重张力是“Apple 品牌中心叙事”与“边缘者贡献”之间的失衡。Apple 官方档案（Press Release、WWDC、SEC 10-K）天然以 Apple 为叙事主体，使 Avie Tevanian、Steve Jobs、Jordan Hubbard 等高公开度人物占据中心，而 Mike Parkhill（BSD VFS 层移植）、Doug McCallum（BSD 网络栈适配）、Peter Lipson（Mach/BSD 桥接层）等 NeXT 时期低公开度工程师的贡献被遮蔽。**darwin.duckdb** 查询显示 XNU 仓库仅 155 条 commit，first_commit 集中于 2003-08-08，此发布机制使个人贡献者被“文件级聚合”遮蔽，无法从 commit 历史直接追溯。史家在此须主动引入 Stanford M1412 档案与 NeXT Developer Documentation，以“边缘者史料”校正“品牌中心叙事”，但须承认 M1412 档案需现场查阅的局限，并在叙事中明确标注哪些贡献者记录来自档案、哪些来自二手转述。自反性检视：本综述作者亦受 Apple 品牌叙事的潜移默化，须警惕将“Apple 决策”等同于“BSD 层演进”的归因偏差——例如 Darwin 开源既是 Apple 的商业决策，亦是 BSD 代码在商业语境中的延续，二者不可混为一谈。
第二重张力是“形式认证”与“实质开放”之间的辨析。APSL 2.0 经 OSI 认证与 FSF 认可，构成“形式”的开放，但其“非真正 copyleft”与“与 GPL 不兼容”两项实践问题使 Darwin 仍可被闭源商品化，构成“实质”的不彻底。类似地，macOS 自 Leopard（10.5，2007-10-26）起获 UNIX 03 认证，构成“形式”的 UNIX 身份，但 FreeBSD 虽实质遵守 POSIX（自 5.0 起持续通过 POSIX 合规测试）却从未申请 UNIX 03 认证，二者形成“持证 vs 实质遵守”的对照。史家在此须严格遵循主题规则——macOS 持有 UNIX 03 证书，而 FreeBSD 不持有，须明确区分二者，不得将 macOS 的 UNIX 03 认证误用于论证 FreeBSD 也“是 UNIX 认证系统”。此辨析不仅是法律事实的厘清，更是史观立场的显现：形式主义化的合规契约获得了真实的法律效力，但实质合规与形式认证不可混为一谈。自反性检视：本综述作者须警惕“认证即正统”的隐性偏见——FreeBSD 不持证不意味着其 POSIX 合规性低于 macOS，二者法律状态不同但实质合规相近。
第三重张力是“代码级证据”与“叙事级证据”之间的层级。**darwin.duckdb** 提供的 commit hash、author_date、message_subject 是代码级证据，但其覆盖范围有限（XNU 仅 155 条 commit，iOS 等嵌入式 Darwin 源码不在数据库中），且 first_commit 集中于 2003-08-08 使 NeXT 时期（1985-1996）的 BSD 选型与早期移植无法直接印证。Apple 官方 Release Notes 与 WWDC 档案是叙事级证据，覆盖范围广但存在“品牌中心叙事”倾向。Singh《Mac OS X Internals》是代码级与叙事级的混合，但其出版于 2006 年，无法覆盖 Apple Silicon 期（2020 年后）的演进。史家在此须按 0 信任原则对各类证据进行分层验证——代码级证据优先但须标注覆盖局限，叙事级证据须与代码级证据交叉验证，缺失期（如 NeXT 时期、Apple Silicon 期）须以 Stanford M1412 档案与 Asahi Linux 逆向工程补充。自反性检视：本综述作者须承认，对 NeXT 时期 BSD 选型的判断主要依赖 Singh 专著与 CSRG Release Notes 的二手推断，而非 NeXTSTEP 源码考古的一手验证，此局限须在叙事中明确标注。
