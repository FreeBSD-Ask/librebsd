# 245.2 Snow Leopard 的 BSD 性能工程（2009）

## 245.2.16 4 位全面化与 BSD 用户空间优化

**要点**：Snow Leopard 将默认用户空间改为 **64 位**（在 64 位 Mac 上，`bash`、`zsh`、`tcsh`、`vi`、`grep`、`awk`、`sed` 等 BSD 用户空间工具默认以 64 位二进制运行），但内核仍保持 32 位（64 位内核支持至 **10.6 Snow Leopard Server** 才启用，桌面版至 **10.7 Lion** 才默认 64 位内核）。Snow Leopard 引入 **Grand Central Dispatch（GCD）**、**OpenCL**（GPU 通用计算框架）、**QuickTime X**（基于 AVFoundation 重写）等性能导向功能。BSD 子系统整体性能提升——`malloc`、`mmap`、`fork`、`exec` 等系统调用的性能优化。Snow Leopard 移除 **PowerPC** 支持（仅在 Intel x86_64 与 i386 上运行），此移除是 Darwin 从多架构向 Intel 单一架构收敛的关键一步。

  | Snow Leopard BSD 层特性 | 内容 | 后续状态 |
  | --- | --- | --- |
  | **64 位用户空间默认** | `bash`/`zsh`/`tcsh`/`vi`/`grep` 等默认 64 位 | 至 2024 年仍在 macOS |
  | **64 位内核（Server）** | 仅 Snow Leopard Server 启用 | 桌面至 10.7 Lion 才默认 |
  | **GCD** | 任务队列并发抽象 | 至 2024 年仍在 macOS |
  | **OpenCL** | GPU 通用计算 | 至 2024 年仍在 macOS |
  | **QuickTime X** | 基于 AVFoundation 重写 | 至 2024 年仍在 macOS |
  | **PowerPC 移除** | 仅 Intel x86_64/i386 | 多架构向 Intel 收敛 |

  ~~Snow Leopard 因 “无新功能” 定位而 BSD 层无变化~~，事实上 BSD 层有显著变化：64 位用户空间默认化、GCD 引入、PowerPC 移除、性能优化——此变化在用户可见层面较少但在 BSD 子系统层面变化显著。
**史料**：Apple Inc. Mac OS X 10.6 Snow Leopard Release Notes [EB/OL]. (2009-08-28). Apple Developer（64 位用户空间与 PowerPC 移除）；Apple Inc. WWDC 2009 Session: Snow Leopard Performance [EB/OL]. (2009-06-08). Apple Developer；Darwin 源码仓库 opensource.apple.com（xnu-1504 系列对应 10.6 Snow Leopard）。〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 19 条——科学技术历史哲学。Snow Leopard 的 “无新功能” 定位使其 BSD 改进以内核/库层为主——此即项目史观总纲第九章的具体呈现：BSD 子系统的性能优化是 “形式主义化的通信规则” 的优化，不改变用户可见功能但提升底层效率。q.md “快乐的辩护” 在此显现：Apple 投入工程资源优化 BSD 子系统性能，此优化不直接带来新功能但提升整体体验——此即 “快乐的辩护” 中 “不为辩护而辩护，而是因内在价值而延续” 的显现。

**辨析**：Snow Leopard 的 “无新功能” 定位是否意味着 BSD 层无变化——BSD 层在 Snow Leopard 中有显著变化：64 位用户空间默认化、GCD 引入、PowerPC 移除、性能优化。此变化在用户可见层面较少（“无新功能” 指用户可见功能），但在 BSD 子系统层面变化显著。采信 “Snow Leopard 用户可见功能少但 BSD 子系统变化显著” 的判断。

**文献**：Apple Inc. Mac OS X 10.6 Snow Leopard Release Notes [EB/OL]. (2009-08-28). Apple Developer; Apple Inc. WWDC 2009 Session: Snow Leopard Performance [EB/OL]. (2009-06-08). Apple Developer.

## 245.2.2 外部贡献者与 libdispatch 开源社区

**要点**：libdispatch 开源后形成独立社区，贡献者包括 Apple 工程师（如 **Doug Davidson**、**Dave Zmikly**，libdispatch 的核心开发者）与外部贡献者。FreeBSD 社区开发者 **Stanislav Sedov**（<stas@FreeBSD.org>）于 **2009-09-23T15:02:29Z** 在 freebsd-ports 仓库提交首条 libdispatch 移植 commit（commit_hash `fdd841f9197f1910059414771324205d30d93a2a`，commit message"- Add port for libdispatch, the userland implementation of Grand Central Dispatch technology."），与 Snow Leopard 发布（2009-08-28）和 libdispatch 开源（2009-09-10）仅相隔 13 天，构成 Apple→BSD 的代码回馈案例。freebsd.duckdb 一手数据核验推翻了前述“Marcus von Appen 在 2010-2013 年间完成移植”的二手叙事——von Appen 在 freebsd-ports 仓库虽有 972 commits（2009-02-19 ~ 2016-12-23），但其 commit 中无任何 libdispatch/dispatch/GCD 相关。libdispatch 后续随 **Swift** 开源（**2015 年 12 月 3 日** Swift 开源时，libdispatch 作为 **swift-corelibs-libdispatch** 仓库一同开源），成为 Swift 标准库的基础组件。
