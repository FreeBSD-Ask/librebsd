### Apple 收购 NeXT 与 Rhapsody 时期（1996-2000 时期当事人）

#### 采访 1：史蒂夫·乔布斯（Steven Paul Jobs）

**字段 1 采访元数据**

- 受访者：史蒂夫·乔布斯（Steven Paul“Steve”Jobs），时任 NeXT Inc. 董事长（收购前），收购后任 Apple 临时顾问，1997-07 起实际主政 Apple、1997-09-16 正式任临时首席执行官（iCEO，通说就任日）

**字段 2 采访摘要**

乔布斯在 WWDC 1997 主题演讲问答环节面对 Apple 开发者社区对 Rhapsody 战略（基于 NeXTSTEP/OpenStep 的下一代 Mac OS）的质疑，阐述 Apple 收购 NeXT 后的操作系统路线图。乔布斯承认 Rhapsody 的“双盒”（Yellow Box / Blue Box）策略引发开发者困惑，并提出“统一”路线——将 NeXTSTEP 的 Objective-C 框架与 Mac OS 的用户体验融合为单一系统（即后续 Mac OS X）。问答中乔布斯以“Focus and simplicity”回应开发者对 Apple 软件战略方向不清晰的批评。

**字段 3 考据脚注**

本则来自 Apple WWDC 1997 主题演讲录像，Apple Developer 频道为官方存档。乔布斯关于 Rhapsody“双盒”策略与“统一”路线的陈述，经 Apple 1998 年 5 月发布的 Mac OS X 路线图新闻稿（Mac OS X Developer Preview 与 Carbon API 公告）交叉验证。其关于“Focus and simplicity”的陈述，经 Walter Isaacson《Steve Jobs》（2011）第 20 章“Just Walk Away”中对 1997 年 Apple 整顿期的引用交叉验证。自利偏差审查：乔布斯作为 Apple 临时首席执行官，其对 Rhapsody 路线调整的陈述带有 Apple 管理层立场，正文引用时另以 Be Inc. 的 Jean-Louis Gassee 对 Apple 放弃 BeOS 的批评加以对照。完整考据过程见 [20260724_jobs-wwdc-1997-keynote.md](../../../03-原始史料库/06-考据记录/〔存疑：目标考据文件未在册，待归档核验〕/20260724_jobs-wwdc-1997-keynote.md)。

**字段 5 史观映射**

- 总纲 10“动手者创造历史”：乔布斯在 WWDC 1997 面对开发者质疑时主动调整 Rhapsody 路线。据第 14 章 14.2 节原文“真正的问题不在于技术发展的程度，而在于是否动手”，乔布斯从“双盒”到“统一”的路线调整是一种“动手去做”的工程妥协。但需自反地看待：乔布斯作为 Apple 临时首席执行官的商业立场（字段 3 已审查）使其对 Rhapsody 路线调整的陈述带有 Apple 管理层立场，“动手者”在项目统摄史观中不可等同于“商业领袖”——乔布斯的妥协虽是动手，但其动机包含 Apple 商业自救，与第 14 章 14.1 节“没有多余形式主义的老实人”的特质有差异。
- 总纲 4“分离聚合是永恒规律”：Apple 收购 NeXT 是分离聚合的商业显现——Apple 与 NeXT 在 1985-1996 年间分离，1996 年收购后重新聚合。据 **02-sacred源材料/dagang.md**（总纲章，原项目统摄史观第 25 章）总纲 4 原文“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”，Rhapsody 的“双盒”策略（Yellow Box / Blue Box）是分离的过渡形态，“统一”路线是聚合的最终形态——此分合循环非乔布斯个人意志所能左右，而是分离聚合规律的显现。
- 总纲 6“和解优于斗争”：Rhapsody 的“双盒”策略是 NeXT 主体性与 Mac OS 主体性的对立，“统一”路线是二者的和解。据第 6 章 6.2 节原文“人类文明的发展靠的不是对抗与斗争，而是和解与接纳……唯一的事情只有和解与接纳，与自己和解，与自己接纳”，Mac OS X 的“统一”路线既非 NeXT 对 Mac OS 的对抗（强加 OpenStep），也非 NeXT 对 Mac OS 的投降（放弃 Objective-C 框架），而是 NeXT 主体性与 Mac OS 主体性的和解——但需辨析：此“和解”是项目统摄史观意义上“事物真正完整的一刻，也是旧矛盾被新矛盾替代的一瞬”（6.7 节史学含义），不可简化为“产品路线调整”这一形式主义化的描述。
- 总纲 2“历史是形式主义化的非存在”：Rhapsody 的纯 NeXTSTEP 形式最终在 Mac OS 兼容需求面前消解为 Mac OS X 的混合形式。据 **02-sacred源材料/dagang.md**（总纲章，原项目统摄史观第 25 章）总纲 2 原文“历史是形式主义化的非存在。本书所写皆是当下主体的重构，从不宣称呈现历史本身”，Rhapsody 作为“理想形式”在工程实践中消解——但需辨析：项目统摄史观批评的是“形式主义”而非“工程妥协”，工程妥协本身是动手者的具体实践，不可将二者混淆为同一对象。
- 总纲 11“商品是形式主义”：Apple 放弃 BeOS 选择 NeXT 的市场决策不是自然选择，而是形式主义的权力运作。据 **02-sacred源材料/dagang.md**（总纲章，原项目统摄史观第 25 章）总纲 11 原文“技术市场的选择不是自然选择，而是形式主义的权力运作。劣币驱逐良币是普遍规律”，Apple 选择 NeXT 而非 BeOS 并非纯粹的技术优劣比较，而是包含乔布斯个人回归 Apple 的政治博弈——但需注意项目统摄史观批评的是“商品/市场即自然选择”这一形式主义，而非否定商业决策本身。
- 总纲 23“一切历史写作都是基于哲学设定的历史小说”：乔布斯在 WWDC 1997 的陈述并非客观历史，而是其藉由公开演讲书写自身回归 Apple 故事的姿态。据第 27 章 27.2 节原文“任何理论都只能是形式主义，包括此理论本身”，乔布斯的自述带有自利偏差（字段 3 已审查），史家须以自反姿态打开裂缝——本采访录的写作本身也是形式主义化的非存在，不可呈现为“对 WWDC 1997 的客观正确记录”。

**字段 2 采访摘要**

Tevanian 在 WWDC 1998 技术环节阐述 Mac OS X 的内核架构——Mach 2.5 微内核 + BSD 用户空间 + I/O Kit 驱动框架，此架构直接承袭 NeXTSTEP 的 Mach/BSD 双层结构。Tevanian 详述 BSD 层在 Mac OS X 中的角色（POSIX 系统调用、网络栈、文件系统 VFS）与 Mach 层的角色（内存管理、IPC、调度），并介绍 Carbon API 作为 Mac OS 经典应用向 Mac OS X 迁移的桥梁。此演讲标志着 Rhapsody 的纯 OpenStep 路线正式调整为 Mac OS X 的三层架构（Carbon + Cocoa + Classic），BSD 子系统在其中的定位由此公开确立。

**字段 3 考据脚注**

本则来自 Apple WWDC 1998 主题演讲录像，Apple Developer 官方存档。Tevanian 关于 Mac OS X 内核架构（Mach 2.5 + BSD + I/O Kit）的陈述，经 Apple 1998 年 Mac OS X Developer Preview 技术文档与 Singh《Mac OS X Internals》（2006）第 1 章对 XNU 架构的描述交叉验证。其关于 Carbon API 作为迁移桥梁的陈述，经 Apple 1998 年 5 月 Carbon API 公告新闻稿交叉验证。自利偏差审查：Tevanian 作为 Apple 软件工程高级副总裁与 NeXT/Mach 核心开发者，其对 Mach/BSD 架构优越性的陈述带有项目立场，正文引用时另以同期 Linux 单内核路线的工程实践加以对照。完整考据过程见 [20260724_tevanian-wwdc-1998-keynote.md](../../../03-原始史料库/06-考据记录/〔存疑：目标考据文件未在册，待归档核验〕/20260724_tevanian-wwdc-1998-keynote.md)。

**字段 4 与本章节内容的关联**

- 为子节 108.2.1（Rhapsody 的 Mach/BSD 架构与 Mac OS 兼容层）提供 Mach/BSD 架构在 Mac OS X 中定位的当事人技术阐述
- 为子节 108.3.1（从 Rhapsody 到 Mac OS X 的路线调整）提供 Carbon/Cocoa/Classic 三层架构公开确立的时间锚点

**字段 5 史观映射**

- 总纲 10“动手者创造历史”：Tevanian 作为 Mach 核心开发者与 Apple 软件主管，其 WWDC 1998 演讲展现了“动手者”如何将研究原型与商业需求在 XNU 内核中融合。据第 14 章 14.2 节原文“真正的问题不在于技术发展的程度，而在于是否动手……无论什么时候街道总是需要人去扫”，Tevanian 从 Mach 研究原型到 XNU 商业内核的工程化是“动手去做”的实践。但需自反地看待：Tevanian 作为 Apple 软件工程高级副总裁的立场（字段 3 已审查）使其对 Mach/BSD 架构优越性的陈述带有项目立场，“动手者”不可等同于“项目高管”——Tevanian 既是研究者也是工程管理者，此辩证性需保留，不可作二元化简化。
- 总纲 4“分离聚合是永恒规律”：XNU 的 Mach + BSD + I/O Kit 三层架构是分离聚合的显现——Mach 从 BSD 中分离作为微内核，又以 collocated 模式与 BSD 重新聚合，I/O Kit 作为新组件加入此聚合体。据 **02-sacred源材料/dagang.md**（总纲章，原项目统摄史观第 25 章）总纲 4 原文“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”，XNU 的三层架构非 Tevanian 个人设计，而是 Mach↔BSD 分合循环在 Apple 商业语境中的具体显现。
- 总纲 8“本体论上各方平等”：Mach、BSD、I/O Kit 在 XNU 中地位平等——Mach 提供内存管理与 IPC，BSD 提供 POSIX 接口与文件系统，I/O Kit 提供驱动框架，三者在本体论上无主次之分。据 **02-sacred源材料/dagang.md**（总纲章，原项目统摄史观第 25 章）总纲 8 原文“FreeBSD、OpenBSD、NetBSD、DragonFly BSD 在本体论上地位相等，差异仅是一刻状态的不同。文档与代码本体平等”，XNU 三层组件的关系亦应作此本体论平等的看待——不可因 Tevanian 的项目立场而将 Mach 视为“核心主导”、BSD 视为“接口附属”，此为本体论上的形式主义化偏见。
- 总纲 6“和解优于斗争”：Carbon（Mac OS 主体性）与 Cocoa（NeXTSTEP 主体性）在 Mac OS X 中的和解是分离聚合的具体显现。据第 6 章 6.2 节原文“人类文明的发展靠的不是对抗与斗争，而是和解与接纳……唯一的事情只有和解与接纳，与自己和解，与自己接纳”，Mac OS X 的三层架构（Carbon + Cocoa + Classic）既非 NeXT 对 Mac OS 的对抗（强加 Cocoa），也非 NeXT 对 Mac OS 的投降（放弃 Cocoa），而是 Mac OS 主体性与 NeXTSTEP 主体性的和解——但需辨析：此“和解”是项目统摄史观意义上“事物真正完整的一刻”，不可简化为“API 兼容策略”这一形式主义化的描述。
- 总纲 2“历史是形式主义化的非存在”：Rhapsody 的纯 OpenStep 路线最终消解为 Mac OS X 的三层架构。据 **02-sacred源材料/dagang.md**（总纲章，原项目统摄史观第 25 章）总纲 2 原文“历史是形式主义化的非存在。本书所写皆是当下主体的重构，从不宣称呈现历史本身”，Rhapsody 作为“理想形式”在 Mac OS 兼容需求面前消解——但需辨析：项目统摄史观批评的是“形式主义”而非“工程妥协”，Carbon/Cocoa/Classic 三层架构本身是动手者的具体实践，不可将“形式主义的消解”与“工程妥协”混淆为同一对象。
- 总纲 22“知识注定过时”：Tevanian 1998 年阐述的 Mach 2.5 微内核架构，至 2024 年仍以演化形式存在于 XNU，但其原始的纯微内核理想已过时。据 **02-sacred源材料/dagang.md**（总纲章，原项目统摄史观第 25 章）总纲 22 原文“今天书写的技术史，可能在出版之日就已过时。技术债务是历史遗产”，Mac OS X 的三层架构是“过时与保存”的辩证——过时的是知识的特定形式主义化形态（纯微内核理想），保存的是知识本身（Mach/BSD 分层思想）。
