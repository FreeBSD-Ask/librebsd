# 239.2 Rhapsody 与 XNU 内核的成形（1997-1998）

## 239.2.1 XNU：Mach 3.0 + BSD 层 + IOKit 的混合内核架构

**要点**：Rhapsody 采用 **XNU 内核**——XNU 是 NeXT 时期已形成的 Mach/BSD 混合内核的延续，非 Apple 收购后新设计。XNU 由三部分组成：其一，**Mach 3.0 微内核**（原 NeXT 修改的 Mach 2.5 演进至 Mach 3.0，提供任务/线程/IPC 抽象，位于内核最底层）；其二，**BSD 层**（4.3BSD 派生，提供进程、虚拟内存、文件系统与网络栈，作为 Mach 之上的服务集合而非独立内核）；其三，**IOKit**（Apple 的设备驱动框架，基于 Embedded C++，提供设备驱动的面向对象抽象）。NeXTSTEP 本身是 Mach 与 BSD 的混合体，时间早于 FreeBSD——Apple 的 XNU 内核并非直接源自 FreeBSD，而是 NeXT 时期 Mach/BSD 混合的延续。XNU 中 “BSD 层” 是 Mach 之上的服务集合而非独立内核，与纯 BSD 单内核（如 FreeBSD）架构不同，须厘清 “混合内核” 概念——Mach 与 BSD 共享同一内核地址空间，而非微内核 + 用户空间服务的纯微内核架构。

  | XNU 组件 | 源头 | 职责 | 在内核中的位置 |
  | --- | --- | --- | --- |
  | **Mach 3.0** | CMU → NeXT（Mach 2.5 演进） | 任务/线程/IPC 抽象 | 内核最底层 |
  | **BSD 层** | 4.3BSD 派生（NeXT 时期） | 进程/虚拟内存/文件系统/网络栈 | Mach 之上的服务集合 |
  | **IOKit** | Apple 自研（Embedded C++） | 设备驱动面向对象框架 | 内核扩展层 |

  ~~XNU 内核直接源自 FreeBSD~~，事实上 XNU 是 NeXT 时期 Mach/BSD 混合的延续，FreeBSD 用户空间元素在后续 Darwin 版本（2001 年后）中才被纳入。

Mac OS X Internals: A Systems Approach [M]. Boston: Addison-Wesley, 2006. **史观**：总纲第 2 条——实践先于理论。XNU 直接组合已验证组件（Mach 3.0 + BSD + IOKit）而非新设计——此即项目史观总纲第二章 “历史认识论” 的具体显现：XNU 的架构不是理论驱动的全新设计，而是 NeXT 时期工程实践的延续。q.md “道与术的辩证” 在此显现：XNU 的 “混合内核” 是 “术”（工程实现），Mach/BSD/IOKit 三层分工是 “道”（架构设计哲学），二者并行但分属不同层面。q.md “记忆的不可重渡” 在此显现：XNU 延续 NeXTSTEP 的 Mach/BSD 混合，但 Apple 对其的再诠释（如将 BSD 层重新组织为 Darwin 的核心）改变了其原始 NeXT 形态。

**辨析**：XNU 是否 “源自 FreeBSD”——以 Singh《Mac OS X Internals》与 Darwin 源码仓库为准，XNU 的 BSD 层源自 4.3BSD 派生代码（NeXT 时期），非 FreeBSD。FreeBSD 用户空间的某些元素在 later Darwin 版本中被纳入，但 XNU 内核本身是 NeXT 时期 Mach/BSD 混合的延续。采信 “XNU 是 NeXT 时期 Mach/BSD 混合的延续，非直接源自 FreeBSD，FreeBSD 用户空间元素在 later Darwin 版本中才被纳入” 的判断。“混合内核” 概念——XNU 中 Mach 与 BSD 共享同一内核地址空间，而非纯微内核 + 用户空间服务的架构，须区分 “混合内核”（XNU）与 “微内核”（如 L4、QNX）。【0 信任原则·XNU 快照发布局限】darwin.duckdb 查询 L7.5.1 数据基于 XNU 仓库仅 155 条 commit（Apple 以 tag 方式发布快照），无法反映 XNU 三层架构在 1997-1998 年 Rhapsody 时期的成形过程；XNU 早期架构须以 WWDC 1997/1998 技术文档与 Singh《Mac OS X Internals》为准。

## 239.2.2 Rhapsody 的 Yellow Box 与 Blue Box 双层架构

**要点**：Rhapsody 采用 **Yellow Box** 与 **Blue Box** 双层架构——**Yellow Box** 是 Rhapsody 的面向对象应用框架（基于 NeXTSTEP 的 Foundation/AppKit，跨平台可移植至 Windows NT），提供 OpenStep API 兼容；**Blue Box** 是 Mac OS 经典应用兼容环境（Classic Mac OS 的虚拟化运行环境，允许旧 Mac 应用在 Rhapsody 内运行）。Yellow Box 体现 NeXT 工程遗产的延续（OpenStep API），Blue Box 体现 Apple 对旧 Mac 用户的过渡承诺。此双层架构在后续 Mac OS X（**2001 年 3 月 24 日** 发布）中演变为 **Carbon**（经典 Mac API 的子集，原 Blue Box 概念的演进）与 **Cocoa**（Yellow Box 的延续，OpenStep API 的 Apple 实现）。

  | Rhapsody 组件 | 后续 Mac OS X 演进 | 来源 |
  | --- | --- | --- |
  | **Yellow Box** | → Cocoa（2000 年 Mac OS X DP4 改名） | NeXTSTEP Foundation/AppKit（OpenStep API） |
  | **Blue Box** | → Classic（2001-2007）→ Carbon | 经典 Mac OS 虚拟化环境 |
  | **Carbon**（1998 WWDC 引入） | Mac OS X 原生 API 子集 | 经典 Mac API 现代化子集 |
  | **Cocoa** | 至 2024 年仍在 macOS 中 | OpenStep API 的 Apple 实现 |
**史料**：Apple Inc. WWDC 1997 Technical Sessions: Rhapsody Yellow Box and Blue Box [EB/OL]. (1997-05). Apple Developer；Apple Inc. WWDC 1998 Technical Sessions: Carbon and Cocoa Roadmap [EB/OL]. (1998-05). Apple Developer（Yellow Box→Cocoa、Blue Box→Classic/Carbon 的演进路线图）；Singh A. Mac OS X Internals: A Systems Approach [M]. Boston: Addison-Wesley, 2006. ISBN 0-321-36645-0（Yellow Box/Blue Box 架构剖析）。darwin.duckdb 查询 L7.5.1 显示：XNU bsd/kern/kern_exec.c（83 commits，2003-08-08 至 2026-06-17）等 exec 子系统文件在 XNU 快照中持续维护，Yellow Box/Blue Box 双层架构依赖的 BSD exec 接口至 2026 年仍是 macOS 进程管理核心。〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 25 条——终结中的延续。Yellow Box 延续 NeXTSTEP 的 OpenStep API，Blue Box 延续经典 Mac OS 应用——此即项目史观总纲第二十五章的具体显现：NeXT 与 Apple 的工程遗产在 Rhapsody 的双层架构中并存。q.md “记忆的不可重渡” 在此显现：Yellow Box 虽延续 OpenStep API，但 Apple 将其重新命名为 Cocoa（2000 年），改变了其原始 NeXT 命名形态。Blue Box 的经典 Mac OS 兼容是 Apple 对旧用户的过渡承诺，此承诺在 Mac OS X 10.5 Leopard（2007 年）移除 Classic 环境后终结。

**辨析**：Yellow Box 与 Cocoa 的关系——Yellow Box 是 Rhapsody 期的命名，Cocoa 是 Mac OS X 期（2000 年后）的命名，二者为同一 OpenStep API 实现的不同命名阶段。Blue Box 与 Classic/Carbon 的关系——Blue Box 是 Rhapsody 期的命名，Classic 是 Mac OS X 期的运行环境命名，Carbon 是 Classic Mac API 的子集（允许旧 Mac 应用在 Mac OS X 原生运行，无需 Classic 虚拟化）。采信 “Yellow Box→Cocoa、Blue Box→Classic/Carbon 是 Rhapsody 架构在 Mac OS X 期的演进” 的判断。【0 信任原则·XNU 快照发布局限】darwin.duckdb 查询 L7.5.1 数据无法反映 Yellow Box/Blue Box 双层架构的具体实现，XNU 快照仅含 BSD 层代码，应用框架层（Yellow Box/Blue Box）须以 WWDC 技术文档与 Singh《Mac OS X Internals》为准。
