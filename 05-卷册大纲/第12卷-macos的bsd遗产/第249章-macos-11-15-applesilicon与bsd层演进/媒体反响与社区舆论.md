## 冲突类

### 新闻条目 1

- **新闻标题（中英）**：Bonjour (Rendezvous) introduced in Mac OS X 10.2 / Bonjour（原名 Rendezvous）引入 Mac OS X 10.2
- **新闻来源**：Apple Mac OS X 10.2 发布说明 + 2002-08-24 + <https://support.apple.com/en-us/HT2207> + 存档：<https://web.archive.org/web/2002/https://support.apple.com/en-us/HT2207>
- **新闻摘要**：Apple 于 2002-08-24 发布 Mac OS X 10.2 Jaguar，引入 Rendezvous 零配置网络协议（后于 2005 年因商标争议更名为 Bonjour）。Rendezvous 是 Apple 对 IETF Zeroconf（Zero Configuration Networking）开放协议的实现，基于多播 DNS（mDNS）与 DNS 服务发现（DNS-SD）。Rendezvous 允许局域网设备无需配置即可发现彼此服务，如打印机、文件共享、iTunes 音乐共享。Bonjour 协议源自 Apple 工程师 Stuart Cheshire（Zeroconf 工作组主席）的研究工作，Cheshire 同时是 IETF RFC 3927（IPv4 Link-Local Addressing）与 RFC 6762（Multicast DNS）的作者。Bonjour 后续扩展至 iOS、tvOS、watchOS，并开源至 Linux/Windows 平台，成为 Apple 跨平台网络发现标准。
- **与本章主题的关联说明**：本条时点（2002-08-24，Mac OS X 10.2 Jaguar）早于本章覆盖期（macOS 11-15/Apple Silicon，2020-2026），列此作为 macOS 网络栈 BSD 层演进脉络的起点背景参照——Bonjour/Rendezvous 所依托的 mDNS/DNS-SD 即运行于 BSD socket 层，与本章 Apple Silicon 时期网络栈延续与收紧主题构成前后对照，非同期史料，读者注意时点差。
- **与官方史料的交叉验证结论**：经查 Bonjour（原名 Rendezvous）随 Mac OS X 10.2 Jaguar（2002-08-24）引入、2005 年因商标争议更名，属公开史料，与 Apple 官方支持文档（本条来源链接）及 IETF RFC 6762（Multicast DNS）、RFC 6763（DNS-SD）记载互证；Stuart Cheshire 为 Zeroconf 工作组主席及两 RFC 作者亦与 IETF 记载一致。条目摘要与官方史料相符，可采信。

## 里程碑事件类

### 新闻条目 1

- **新闻标题（中英）**：Network Extension framework introduced / Network Extension 框架引入
- **新闻来源**：Apple WWDC 2015 + 2015-06-08 + <https://developer.apple.com/documentation/networkextension> + 存档：<https://web.archive.org/web/2015/https://developer.apple.com/documentation/networkextension>
- **新闻摘要**：Apple 于 WWDC 2015 发布 Network Extension 框架，统一 iOS 与 macOS 的网络扩展开发接口。Network Extension 取代早期 iOS 的 VPN 插件接口与 macOS 的 Network Kernel Extensions（KEXT）网络接口。框架支持四种扩展类型：Packet Tunnel Provider（自定义 VPN 隧道）、App Proxy Provider（应用代理）、Filter Provider（流量过滤）、Content Filter Provider（内容过滤）。Network Extension 限制扩展运行在用户态而非内核态，提升系统稳定性与安全性。macOS 10.15 Catalina（2019-10）后，Apple 强制网络扩展迁移至 Network Extension 框架，弃用网络 KEXT。Apple Silicon Mac（2020 后）进一步限制 KEXT，使 Network Extension 成为唯一网络扩展接口。
- **与本章主题的关联说明**：本条时点（2015-06-08 WWDC）早于本章覆盖期（macOS 11-15，2020 起），列此系 Apple Silicon 时期 KEXT 收紧（网络驱动强制迁向 DriverKit/Network Extension 用户态框架）的制度前史背景参照——本章主题中的 KEXT 限制即以此为源头，非同期史料，读者注意时点差。
- **与官方史料的交叉验证结论**：经查 Network Extension 框架于 WWDC 2015（2015-06-08）发布，支持 Packet Tunnel Provider、App Proxy Provider、Filter Provider、Content Filter Provider 四类扩展且运行于用户态，与 Apple 官方开发者文档（本条来源链接）一致；macOS 10.15 Catalina（2019-10）后弃用网络 KEXT、Apple Silicon 时期进一步以 DriverKit/Network Extension 为唯一网络扩展接口属公开史料，与本条摘要相符，可采信。

### 新闻条目 2

- **新闻标题（中英）**：macOS network stack based on BSD / macOS 网络栈基于 BSD
- **新闻来源**：Apple 开发者文档 + 持续 + <https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/KernelProgramming/Networking.html> + 存档：<https://web.archive.org/web/2020/https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/KernelProgramming/Networking.html>
- **新闻摘要**：macOS 网络栈基于 FreeBSD 网络代码，是 Darwin 操作系统的核心组件。macOS 网络栈包含 BSD socket API、TCP/IP 协议栈（IPv4/IPv6）、网络接口层（如以太网、Wi-Fi、蜂窝）、防火墙（IPFW 与 PF）。PF（Packet Filter）防火墙源自 OpenBSD，于 Mac OS X 10.7 Lion（2011-07）引入，同版 IPFW 被标记弃用，至 OS X 10.10 Yosemite（2014-10）IPFW 被完全移除，PF 自此成为 macOS 默认包过滤防火墙 [考据完成：2026-09-12 联网复核——manjusri.ucsc.edu《PF on Mac OS X》（10.7 起 macOS 含 PF 与应用防火墙两类，ipfw 于 10.7 弃用、10.10 移除）、HPC.mil IPv6 Knowledge Base（pf introduced in OS X 10.7 Lion，ipfw removed in OS X 10.10 Yosemite）；核查报告所拟 “PF 自 10.4 Tiger（2005）即默认” 经查不成立，10.5 Leopard（2007）新增的是应用层防火墙，不采信]。macOS 的网络内核扩展（Network KEXT）机制允许第三方驱动网络硬件，但 Catalina 后逐步弃用。Apple Silicon Mac（M1 及后续）进一步收紧 KEXT 机制，强制网络驱动通过 DriverKit 用户态框架实现。macOS 网络栈持续从 FreeBSD 与 OpenBSD 同步上游改进，但 Apple 保留私有扩展（如 AWDL 无线直连、MultiPath TCP）。
- **与本章主题的关联说明**：本条为持续性官方文档（非单一时点新闻），直接对应本章主题——macOS 11-15/Apple Silicon 时期 BSD 网络栈的延续（FreeBSD 上游同步）与收紧（KEXT 弃用、DriverKit 强制），为本章网络栈演进叙述的官方锚点，无时点差问题。
- **与官方史料的交叉验证结论**：经查 Apple 官方内核编程文档（Kernel Programming Guide → Networking，本条来源链接）载明 macOS 网络栈基于 FreeBSD 网络代码，属官方一手表述；条目中 PF 引入与取代 IPFW 的时点表述经 2026-09-12 联网复核修正为 “10.7 Lion 引入 PF、10.7 弃用 ipfw、10.10 Yosemite 移除后 PF 成为默认包过滤防火墙”（详见摘要内考据注），其余内容与官方史料相符，可采信。
