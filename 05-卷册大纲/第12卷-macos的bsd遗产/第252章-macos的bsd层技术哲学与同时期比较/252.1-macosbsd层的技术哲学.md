# 252.1 macOS BSD 层的技术哲学

## 252.1.1 实用主义与混合许可的延续

**要点**：Apple 于 **1999 年 3 月 16 日** 在 Mac OS X Server 1.0 发布同期公开 Darwin 源码，采用 **APSL 1.0 许可证**；**2003 年 8 月 6 日** 发布 **APSL 2.0** 并获 OSI 批准、FSF 认定为自由软件许可证。Darwin 内核大量代码派生自 FreeBSD 4.4-Lite 与后续 FreeBSD 版本（如网络栈、用户态工具），但 Apple 在 XNU 内核中混入 **Mach 3.0 微内核** 与自研 I/O Kit，形成“BSD 宏内核 + Mach 微内核 + Apple 专有组件”的混合架构——此即“开放核心 + 品牌控制”策略的工程基础。APSL 2.0 第 2 条要求修改后的代码须向 Apple 通报并标注变更说明，第 9.2 条赋予 Apple 终止违规者许可证的权利，这两条款使 APSL 的“宽松度”低于纯 BSD 许可——BSD 许可不要求通报修改、不保留终止权。

  | Darwin 开源节点 | 日期 | 许可证 | 状态 |
  | --- | --- | --- | --- |
  | Darwin 源码首次公开 | 1999-03-16 | APSL 1.0 | 随 Mac OS X Server 1.0 |
  | APSL 2.0 发布 | 2003-08-06 | APSL 2.0 | OSI 批准 + FSF 认定 |

  | 许可证对比 | 通报义务 | 终止权 | 派生限制 | 宽松度 |
  | --- | --- | --- | --- | --- |
  | **BSD 许可证** | 无 | 无 | 无 | 最高（完全消极自由） |
  | **APSL 2.0** | 有（第 2 条） | 有（第 9.2 条） | 须标注变更说明 | 有限消极自由 |
  | **GPL v2/v3** | 有（copyleft） | 有 | 派生须同许可 | 积极自由（强制回馈） |

  > BSD 许可证的“消极自由”（不强制回馈、不强制开源）被 APSL 转化为“有限消极自由”（允许派生但须通报）——Apple 以“开放核心”定义了 Darwin 的“自由”边界。
**史料**：APSL 2.0 全文（<https://opensource.apple.com/apsl/>，2003-08-06 提交 OSI，提交人 Ernest Prabhakar）；OSI 批准记录（<https://opensource.org/license/apsl>）；Darwin 源码仓库 opensource.apple.com；FreeBSD 许可证文本（<https://www.freebsd.org/copyright/freebsd-license/>）；GPL v2/v3 文本（<https://www.gnu.org/licenses/>）。〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 24 条——许可证哲学直接塑造社区形态。macOS 的 BSD 层在工程层面继承 FreeBSD 的代码，但在许可证层面以 APSL 的“通报义务”与“终止权”附加了 Apple 的品牌控制——此即项目史观总纲第七章“文化历史哲学”的具体显现：BSD 许可证的“消极自由”（不强制回馈、不强制开源）被 APSL 转化为“有限消极自由”（允许派生但须通报），对应 q.md“自由的张力”中“谁给你定义自由，谁就是想限制你的自由”——Apple 以“开放核心”定义了 Darwin 的“自由”边界，此边界即形式主义化的非存在。

**辨析**：[2026-08-15 双库核查] APSL 2.0 第 2 条（修改通报义务）经参考文献库 entry08182 apsl 全文印证；Darwin 用户态大量源自 FreeBSD 经参考文献库 “Mac OS X Internals”（Amit Singh, 2006）与邮件列表库 2003-07-18 Darwin→FreeBSD 代码导入邮件印证。原辨析：APSL 与 BSD 许可的“宽松度”比较存在两种说法——FSF 在 2003 年 8 月 APSL 2.0 发布后认定其为自由软件许可证（<https://www.gnu.org/licenses/license-list.html#APSL2>），但指出 APSL 2.0 仍存三项缺陷：终止条款的模糊性、专利条款的不对等性、对“外部部署”的定义过宽。采信 FSF 的技术性分析而非大众印象中的“APSL 等于 BSD”的简化判断。BSD 许可不要求修改通报、不保留终止权，APSL 2.0 两者皆有，故二者非等价的“宽松许可”。【统计结论 C-28 整合】统计结论 [C-28] vol-9 存疑率 0.00%（推断性统计 Task 11 卡方检验 χ² = 229.62 Cramer's V = 0.127）——vol-9 存疑率为 12 卷中最低（与 vol-10 21.33% 最高形成鲜明对照），此结果具有反直觉性：macOS BSD 遗产涉及 Apple 闭源代码与商业秘密，理论上存疑率应较高，但实际存疑率为 0.00%。0 信任原则提示：存疑率 0.00% 不等于“无存疑”，可能是资料数据库.duckdb 录入时未对 vol-9 史料进行存疑标注（数据缺口），亦可能是 vol-9 史料来源相对集中（Apple 官方公告与 Darwin 源码仓库为主源）使存疑判定易于达成；卡方检验 Cramer's V = 0.127 为小效应量，存疑率跨卷差异虽统计显著但实际差异幅度有限；vol-9 存疑率 0.00% 的解读须以资料数据库.duckdb trust_basis 字段覆盖率 0.00%（数据缺口）叠加考量，不得据此推断 vol-9 史料已全部经三次复查。
