# 250.2 iPadOS/watchOS/tvOS/visionOS 的 Darwin 延续（2010-2024）

## 250.2.1 iPadOS 的分支与 Darwin 内核的设备特化（2019）

**要点**：Apple 于 **2019 年 6 月 3 日** 在 WWDC 2019 公布 iPadOS，同年 9 月随 iOS 13 正式发布（iPadOS 13.1 首版，**2019 年 9 月 24 日**）。iPadOS 从 iOS 分支但共享 XNU 内核——二者的 Mach/BSD 核心相同，差异在外层框架（iPadOS 增强多任务、Apple Pencil 支持、Sidecar 等桌面外接功能）。iPadOS 是 Darwin 谱系中首个从同一内核分支出的设备特化版本，标志着 Apple 不再以 “一套 iOS 适配所有设备” 的策略运行。BSD 层的设备特化通过 **I/O Kit 驱动框架** 实现——iPadOS 的 I/O Kit 配置与 iOS 不同（支持更多外设、触控板、键盘快捷键），但 BSD 子系统本身几乎无修改。

  | iPadOS 分支要素 | 内容 |
  | --- | --- |
  | 公布日期 | 2019-06-03（WWDC 2019） |
  | 首版发布 | 2019-09-24（iPadOS 13.1） |
  | 内核共享 | 与 iOS 共享 XNU（Mach/BSD 核心相同） |
  | 差异层 | 外层框架（多任务、Apple Pencil、Sidecar） |
  | BSD 层变更 | 通过 I/O Kit 实现，BSD 子系统几乎无修改 |

  > iPadOS 的 “分支” 是产品策略层面的分支，非内核源码的根本分叉——二者的 Mach/BSD 核心代码相同，差异在设备驱动配置与外层框架。

**史观**：总纲第 6 条——和解优于斗争。iPadOS 从 iOS 分支是 “分离聚合” 的显现——此即项目史观源材料第六章 “主体性与和解”（源文本章序，非总纲条号）的具体呈现：iPadOS 与 iOS 共享 Darwin 核心但发展出不同的主体性（iPad 侧重桌面化、iPhone 侧重移动化），二者既不对立也不可和解，而是在同一内核基础上各自演化。q.md “好望角与塔式起重机”（q.md 系项目哲学源材料内部文件名，书内不可解析，下同）在此显现：iPadOS 的分支是 “塔式起重机” 式的渐进扩张（在 iOS 基础上增加桌面能力），而非 “好望角” 式的根本转向。

## 250.2.2 watchOS 与 tvOS 的 Darwin 裁剪（2015）

**要点**：Apple Watch 于 **2015 年 4 月 24 日** 上市，预装 watchOS 1.0（基于 iOS 8.2 裁剪），其 XNU 内核在 Apple Watch 初代（Series 0）至 Series 3 上运行 32 位 ARMv7 版本，Apple Watch Series 4 起升级至 64 位 ARMv8。watchOS 的 BSD 层极端裁剪——移除文件系统服务（Apple Watch 使用只读系统分区加用户数据分区）、移除多用户登录、强化电量管理（BSD 层的 `sched_*` 系统调用被约束以配合省电策略）。Apple TV 第 4 代于 **2015 年 10 月** 上市，预装 tvOS（基于 iOS 9 裁剪），引入 App Store 与第三方应用——tvOS 的 BSD 层裁剪少于 watchOS（Apple TV 接电源、资源较丰富），但移除多用户与桌面服务。watchOS 与 tvOS 的 BSD 用户空间工具默认不向用户暴露，须通过 Apple Configurator 或开发者模式方可访问。

  | 嵌入式 Darwin 平台 | 上市日期 | 基础 iOS 版本 | BSD 层裁剪程度 |
  | --- | --- | --- | --- |
  | **watchOS** | 2015-04-24 | iOS 8.2 | 极端裁剪（仅保留进程调度、内存管理、基本 I/O） |
  | **tvOS** | 2015-10 | iOS 9 | 中度裁剪（移除多用户与桌面服务） |

  | watchOS BSD 层裁剪 | 裁剪前（iOS） | 裁剪后（watchOS） |
  | --- | --- | --- |
  | 文件系统服务 | 完整 BSD VFS | 只读系统分区 + 用户数据分区 |
  | 多用户登录 | `init`、`getty` | 移除 |
  | `sched_*` 系统调用 | 完整调度 | 约束以配合省电策略 |
  | BSD 用户空间工具 | `bash`、`vi` 等 | 存在但默认不暴露 |

  ~~watchOS 的 BSD 层已不存在~~，事实上 watchOS 仍保留 BSD 的 `fork`、`exec`、`mmap`、`socket` 等核心系统调用——BSD 层虽裁剪至极致但未消失。

Apple Press Release；Apple Inc. watchOS Developer Documentation [Z]. Apple Developer, 2015-2024；Darwin 源码仓库 opensource.apple.com（含 watchOS 与 tvOS 对应的 XNU 源码版本）。〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律。BSD 核心在穿戴与机顶盒设备上延续——分离与聚合的永恒规律在此显现：BSD 代码在穿戴设备上被裁剪至极致（分离），但 Mach/BSD 核心仍在运行（聚合的延续）。q.md “存在即破烂” 在此显现：watchOS 的 BSD 层被裁剪至最小，仅保留进程调度、内存管理、基本 I/O 三项核心功能，其余 BSD 工具均被移除——此即 “存在即破烂” 的具体显现：存在的不是完整的 BSD，而是被裁剪至仅维持系统运转的 “破烂” BSD。

**辨析**：watchOS 的 BSD 层裁剪程度是否达到 “BSD 已不存在” 的边界——经 Darwin 源码仓库比对，watchOS 仍保留 BSD 的 `fork`、`exec`、`mmap`、`socket` 等核心系统调用，故 BSD 层虽裁剪但未消失。Apple Watch Series 0（第一代）的 8GB 存储空间中，系统分区仅约 2GB，BSD 用户空间工具（如 `bash`、`vi`）虽存在但默认不暴露。采信 “watchOS 是 BSD 裁剪至极致但仍保留核心” 的判断，而非 “watchOS 与 BSD 无关” 的简化判断。

## 250.2.3 visionOS 与空间计算时代的 Darwin（2024）

**要点**：Apple Vision Pro 于 **2024 年 2 月 2 日** 在美国首发（起售价 3,499 美元），预装 visionOS 1.0。visionOS 基于 XNU 内核，但为空间计算设备定制了实时性增强——Mach 调度器针对低延迟头部追踪（须低于 **12 毫秒** 延迟以避免眩晕）做了优化，BSD 层的 I/O Kit 新增 **R1 芯片**（Vision Pro 专用传感器芯片）的驱动支持。visionOS 是 Darwin 谱系中首个面向空间计算的版本，其 BSD 层在保持核心系统的同时，新增空间渲染与眼动追踪的系统调用接口。visionOS 的 BSD 用户空间工具可通过 Apple Developer Mode 访问，但默认不向普通用户暴露——此模式延续 iOS/watchOS 的 “BSD 层隐藏” 策略。

  | visionOS 要素 | 内容 |
  | --- | --- |
  | 首发日期 | 2024-02-02（美国） |
  | 起售价 | 3,499 美元 |
  | 内核 | XNU（Mach + BSD + I/O Kit） |
  | 实时性需求 | 头部追踪延迟 < 12 毫秒 |
  | 专用芯片 | **R1**（传感器）+ **M2**（应用） |
  | Mach 调度器优化 | 实时优先级与中断处理（未改变消息传递架构） |

  > visionOS 的实时性需求 “难”（12 毫秒延迟的工程挑战），但 BSD 层的 Mach 调度器 “行”（已有 30 年的成熟实现）使其可行——“难” 在空间渲染的新需求，“易” 在 BSD 层的基础架构已就绪。
**史料**：Apple Inc. Apple Vision Pro Available in the U.S. on February 2 [EB/OL]. (2024-01-08). Apple Press Release（<https://www.apple.com/newsroom/2024/01/08/Apple-Vision-Pro-available-in-the-US-on-February-2/>）；Apple Inc. visionOS Developer Documentation [Z]. Apple Developer, 2024；Apple Inc. Apple Vision Pro Technical Specifications [EB/OL]. (2024-01-19). Apple Press Release（R1 芯片与传感器规格）。〔L3 官方文档与公告〕

**史观**：总纲第 18 条——时间是一种形式主义。visionOS 是 BSD 谱系进入空间计算时代的首个版本——调度器与发布节奏的形式主义化演进正是其显现：BSD 的 Mach 调度器从桌面（NeXTSTEP）、移动（iPhone）、穿戴（Apple Watch）扩展至空间计算（Vision Pro），其 “形式主义化的通信规则”（系统调用接口）在不同设备形态上保持稳定。q.md “知难行易” 在此显现：visionOS 的实时性需求（12 毫秒延迟）“难”（工程挑战），但 BSD 层的 Mach 调度器 “行”（已有 30 年的成熟实现）使其可行——“难” 在空间渲染的新需求，“易” 在 BSD 层的基础架构已就绪。

## 250.2.4 外部贡献者与开源边界

**要点**：嵌入式 Darwin 的开源部分仍经 **APSL 2.0** 接受外部贡献，但 iOS、iPadOS、watchOS、tvOS、visionOS 的完整内核源码不公开——Apple 仅公开 macOS 端的 Darwin 源码（通过 opensource.apple.com），嵌入式端的 XNU 源码以 macOS 版本为基础间接公开。Apple 于 **2020 年** 推出 Apple Security Research Device Program（安全研究设备计划），向经审核的安全研究者提供特殊 iPhone（具备 shell 访问权限与调试接口），此为 iOS 内核源码未完全开源背景下的研究路径。Darwin 开源社区（如 GitHub 上的 darwin-on-xnu 项目、Chitkara University 的 Darwin 研究组）对嵌入式 Darwin 的贡献集中于工具链与文档，内核核心代码的修改仍由 Apple 内部完成。

  | 嵌入式 Darwin 开源边界 | 内容 |
  | --- | --- |
  | macOS Darwin 源码 | 开源（APSL 2.0，opensource.apple.com） |
  | iOS/iPadOS/watchOS/tvOS/visionOS 完整内核 | 不公开 |
  | 嵌入式端 XNU 源码间接公开方式 | 以 macOS 版本为基础 |
  | Apple Security Research Device Program | 2020 年推出，提供 shell 访问权限 |
  | 外部贡献范围 | 工具链与文档，非内核核心代码 |

  > iOS 内核运行时可访问（通过 Security Research Device Program）但源码未完全开源——此即 “运行时可访问” 与 “源码可审查” 的区别。
**史料**：Apple Inc. Apple Security Research Device Program [EB/OL]. (2020-07-15). Apple Security Blog（<https://security.apple.com/blog/security-research-device-program/>）；Apple Open Source. Darwin Source Releases [EB/OL]. <https://opensource.apple.com/releases/>；GitHub. apple-oss-distributions/xnu [EB/OL]. <https://github.com/apple-oss-distributions/xnu>（Apple 官方 GitHub 镜像）。〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 10 条——动手者创造历史。嵌入式 Darwin 的外部贡献者（如逆向工程师、安全研究者、越狱社区开发者）在 BSD 谱系中属 “边缘者”——他们的贡献不进入 Apple 的 “主线叙事”，但通过越狱工具（如 Pangu、unc0ver）与安全研究披露漏洞间接影响 iOS 的 BSD 层演进。此即 q.md “局外人姿态” 的具体显现：越狱社区开发者（如 Jay Freeman “saurik”、Comex 等）是 Darwin 谱系的 “局外人”，其 Cydia 越狱商店与 Substrate 框架实质上构建了一个 “民间 Darwin 生态”，但此生态被 Apple 的中心叙事遮蔽。

**辨析**：iOS 内核 “开源” 与 “闭源” 的边界须明确——Darwin 的 macOS 版本开源（APSL 2.0），iOS 版本基于 macOS Darwin 但附加闭源的移动框架（UIKit 移动版、SpringBoard 等）。Apple Security Research Device Program 提供的设备可访问 shell，但内核源码本身未公开——此即 “运行时可访问” 与 “源码可审查” 的区别。采信 “iOS 内核运行时部分可访问、源码未完全开源” 的判断，而非 “iOS 内核完全闭源” 或 “iOS 内核完全开源” 的简化判断。

**文献**：Apple Inc. Apple Security Research Device Program [EB/OL]. (2020-07-15). Apple Security Blog; Apple Open Source. Darwin Source Releases [EB/OL]. <https://opensource.apple.com/releases/>; GitHub. apple-oss-distributions/xnu [EB/OL]. <https://github.com/apple-oss-distributions/xnu>.
