# 244.3 Leopard 的 BSD 技术其他进展（2007）

## 244.3.1 64 位内核过渡与 DTrace 引入

**要点**：**Mac OS X 10.5 Leopard** 引入 **64 位内核** 支持（部分——仅在 Xserve 与部分 Mac Pro 上默认启用 64 位内核，桌面版至 **10.7 Lion** 才默认 64 位内核）。Leopard 引入 **DTrace**（源自 **Sun Microsystems** 的 **OpenSolaris**，Dynamic Tracing 工具，经 Apple 工程师移植至 Darwin），允许开发者动态追踪系统调用、进程、内核行为——DTrace 的引入使 macOS 的 BSD 层获得了 Solaris 级别的可观测性工具。Leopard 还引入 **ZFS 只读** 支持预览（可读取 ZFS 池但不可创建或管理），但完整 ZFS 支持未进入 shipping macOS（至 **10.11 El Capitan** 后 ZFS 支持被完全移除）。其他新功能包括 **Time Machine**（基于 BSD 层的硬链接与 `fs_snapshot` 机制）、**Boot Camp**（双系统启动）、**Spaces**（虚拟桌面）。

  | Leopard BSD 层特性 | 引入内容 | 上游来源 | 后续状态 |
  | --- | --- | --- | --- |
  | **64 位内核（部分）** | Xserve/Mac Pro 默认启用 | Apple 自研 | 10.7 Lion 桌面默认 64 位 |
  | **DTrace** | 动态追踪工具 | Sun Microsystems OpenSolaris（CDDL） | 至 2024 年仍在 macOS |
  | **ZFS 只读预览** | 可读取 ZFS 池 | OpenSolaris ZFS（CDDL） | 10.11 后完全移除 |
  | **Time Machine** | 基于硬链接 + `fs_snapshot` | BSD 层机制 | 至 2024 年仍在 macOS |
  | **Boot Camp** | 双系统启动 | BSD 层启动支持 | 至 2024 年仍在 macOS |
  | **Spaces** | 虚拟桌面 | Apple 自研 | 至 2024 年仍在 macOS |

  ~~Leopard 的 ZFS 完整支持已进入 shipping macOS~~，事实上 Leopard 仅为 ZFS 只读预览，完整 ZFS 因 CDDL 与 Apple 商业策略冲突未进入 shipping macOS，至 10.11 El Capitan 后完全移除。
**史料**：Apple Inc. Mac OS X 10.5 Leopard Release Notes [EB/OL]. (2007-10-26). Apple Developer（64 位内核、DTrace、ZFS 只读）；Sun Microsystems. DTrace Documentation [EB/OL]. <https://dtrace.org/>（DTrace 原始文档）；OpenSolaris. ZFS Source Code [EB/OL]. <https://github.com/openzfs/zfs>（ZFS 原始源码）；Darwin 源码仓库 opensource.apple.com（`bsd/dev/dtrace/` 目录含 DTrace 移植代码）。

**史观**：总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕。DTrace 的引入是 “形式主义化的可观测规则” 的显现——DTrace 作为 Solaris 的可观测工具，被 Apple 移植至 Darwin 的 BSD 层，使 macOS 获得了 Solaris 级别的系统追踪能力。q.md “快乐的辩护” 在此显现：Apple 投入工程资源移植 DTrace，此移植不直接带来用户可见功能但提升开发者体验——此即 “快乐的辩护” 中 “不为辩护而辩护，而是因内在价值而延续” 的显现。

**辨析**：Leopard 的 ZFS 仅为只读预览，完整 ZFS 未进入 shipping macOS——Apple 在 Leopard 期曾计划将 ZFS 作为默认文件系统（2007 年 WWDC 上 Steve Jobs 提及），但因 CDDL 与 Apple 商业策略的冲突（CDDL 要求源码开源，Apple 倾向于自研 APFS）至 10.11 El Capitan 后完全移除 ZFS 支持。采信 “Leopard ZFS 为只读预览，完整 ZFS 因 CDDL 与 Apple 策略冲突未进入 shipping macOS” 的判断。

**文献**：Apple Inc. Mac OS X 10.5 Leopard Release Notes [EB/OL]. (2007-10-26). Apple Developer; Sun Microsystems. DTrace Documentation [EB/OL]. <https://dtrace.org/>; OpenSolaris. ZFS Source Code [EB/OL]. <https://github.com/openzfs/zfs>.

## 244.3.2 外部贡献者与 DTrace CDDL 许可证兼容性

**要点**：Leopard 的 DTrace 移植依赖 Sun Microsystems 开源的 **OpenSolaris** 代码（**CDDL 许可证**）。DTrace 的 CDDL 许可证与 Apple 的 APSL/BSD 混合许可证的兼容性须厘清——CDDL 与 APSL 2.0 在 2007 年经 FSF 与 OSI 分别确认为自由软件许可证与开源许可证，二者在源码混合时的兼容性由 Apple 法务部门审核。DTrace 的 FreeBSD 移植同期进行——**FreeBSD 7.0**（**2008 年 2 月 27 日** 发布）引入 DTrace 作为可选模块（通过 `options DTRACE` 编译选项启用），FreeBSD 的 DTrace 移植同样基于 OpenSolaris 的 CDDL 代码。

  | 系统 | DTrace 引入版本 | 发布日期 | 启用方式 | 上游来源 |
  | --- | --- | --- | --- | --- |
  | **macOS Leopard** | 10.5 | 2007-10-26 | 默认集成 | OpenSolaris CDDL |
  | **FreeBSD 7.0** | 7.0 | 2008-02-27 | `options DTRACE` 编译选项 | OpenSolaris CDDL |

  | DTrace 原作者 | 所属机构 | 开发时间 | 在 BSD 谱系中的角色 |
  | --- | --- | --- | --- |
  | **Bryan Cantrill（布莱恩·坎特里尔）** | Sun Microsystems | 2003-2005 | DTrace 主设计师 |
  | **Mike Shapiro** | Sun Microsystems | 2003-2005 | DTrace 共同开发者 |
  | **Adam Leventhal** | Sun Microsystems | 2003-2005 | DTrace 共同开发者 |

  > DTrace 的 CDDL 许可与 Apple APSL/BSD 的兼容性通过模块分离实现——Apple 在 Darwin 中将 DTrace 代码作为独立 CDDL 模块与其他 APSL/BSD 许可代码分离，避免许可证混合。
**史料**：Apple Inc. WWDC 2007 Session: DTrace on Mac OS X [EB/OL]. (2007-06-11). Apple Developer；Sun Microsystems. OpenSolaris DTrace Source Code [EB/OL]. (2005-01-25). 〔DTrace 源码见 OpenSolaris 源树及其镜像，openzfs/zfs 仓库不含 DTrace〕；FreeBSD Project. FreeBSD 7.0 Release Notes [EB/OL]. (2008-02-27). <https://www.freebsd.org/releases/>（DTrace 引入）；openzfs.duckdb 查询结果（FreeBSD DTrace 相关 commit，可查）。〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 10 条——动手者创造历史被中心叙事遮蔽。DTrace 的开发者 Bryan Cantrill、Mike Shapiro、Adam Leventhal（Sun Microsystems 三位工程师，2003-2005 年开发 DTrace）在 BSD 谱系中属 “边缘者”——他们的贡献通过 OpenSolaris 进入 macOS 与 FreeBSD，但其姓名在 Apple 的 “主线叙事” 中被遮蔽。此即 q.md “局外人姿态” 的具体显现。

**辨析**：DTrace 的 CDDL 许可与 Apple APSL/BSD 的兼容性——CDDL 与 APSL 2.0 均为 OSI 批准的开源许可证，但 CDDL 的 “文件级 copyleft”（修改的 CDDL 文件须继续开源）与 APSL 的 “通报义务” 存在差异。Apple 在 Darwin 中将 DTrace 代码作为独立模块（CDDL 许可）与其他代码（APSL/BSD 许可）分离，避免许可证混合。采信 “Apple 通过模块分离避免 CDDL 与 APSL 许可证混合” 的判断。

**文献**：Apple Inc. WWDC 2007 Session: DTrace on Mac OS X [EB/OL]. (2007-06-11). Apple Developer; Sun Microsystems. OpenSolaris DTrace Source Code [EB/OL]. (2005-01-25). <https://github.com/openzfs/zfs>; FreeBSD Project. FreeBSD 7.0 Release Notes [EB/OL]. (2008-02-27). <https://www.freebsd.org/releases/>.

## 244.3.3 Objective-C 2.0 与垃圾回收的引入

**要点**：Leopard 引入 **Objective-C 2.0**——Apple 对 Objective-C 语言的重大更新，由 **Chris Lattner** 主导（其同时领导 LLVM 项目），核心新增特性包括：**垃圾回收（Garbage Collection，GC）**——基于代际分代收集的自动内存管理，替代手动 `retain`/`release` 引用计数（RC），GC 在 Leopard 期为按应用选配启用〔原稿“默认启用”存疑待复核〕但在后续版本（10.8 Mountain Lion）被废弃，最终由 **ARC（Automatic Reference Counting，2011 年 10.7 Lion 引入）** 取代；**属性（@property）**——声明式的实例变量访问器生成，简化 `getter`/`setter` 样板代码；**Fast Enumeration**——`for...in` 语法遍历集合，性能优于传统 `NSEnumerator`。Objective-C 2.0 与 BSD 层的关联体现于：GC 运行时依赖 BSD 层的 `mmap`/`mprotect` 系统调用实现写屏障（write barrier）——GC 通过 `mprotect` 将堆内存标记为只读以检测写操作，触发 `SIGSEGV` 信号后由 GC 处理器更新写屏障，这一机制依赖 BSD 层的内存保护原语。

  | Objective-C 2.0 特性 | 引入版本 | 后续状态 | BSD 层依赖 |
  | --- | --- | --- | --- |
  | 垃圾回收（GC） | 10.5 Leopard | 10.8 废弃，由 ARC 取代 | `mmap`/`mprotect` 写屏障 |
  | `@property` 属性 | 10.5 Leopard | 至 2024 年仍在 | 无直接依赖 |
  | Fast Enumeration | 10.5 Leopard | 至 2024 年仍在 | 无直接依赖 |
  | ARC（后续） | 10.7 Lion | 至 2024 年仍在 | 无直接依赖 |

  > Objective-C 2.0 的 GC 与 ARC 是两种不同的自动内存管理路径——GC 采用运行时分代收集，ARC 采用编译期引用计数插入，二者技术路线不同，ARC 最终胜出。
**史料**：Apple Inc. Mac OS X 10.5 Leopard Release Notes [EB/OL]. (2007-10-26). Apple Developer（Objective-C 2.0 章节）；Apple Inc. WWDC 2007 Session: The Objective-C 2.0 Runtime [EB/OL]. (2007-06-11). Apple Developer；Lattner, C. (2008). *LLVM: A Compilation Framework for Lifelong Program Analysis & Optimization*[Z]. LLVM Project；Darwin 源码仓库 opensource.apple.com（`objc4/` 目录含 Objective-C 运行时源码，对应 Leopard 期版本）。〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕。Objective-C 2.0 的 GC 是 “形式主义化的内存管理规则” 的显现——手动 `retain`/`release` 的分散内存管理被 GC 统一为运行时自动收集，内存管理规则从 “分散形式” 转化为 “统一形式”。q.md “道与术的辩证” 在此显现：GC 是 “术”（运行时机制），自动内存管理的 “道”（设计哲学），二者在 Leopard 期合一，但 GC 的 “术” 在 10.8 被废弃、由 ARC 的 “术” 取代，反映 “道” 的延续与 “术” 的迭代。

**辨析**：Objective-C 2.0 的 GC 与 ARC 的关系——GC 是运行时分代收集（Stop-the-world 间歇暂停），ARC 是编译期引用计数插入（无运行时暂停），二者技术路线不同。GC 在 Leopard 引入后因性能开销与确定性不足被废弃，ARC 在 10.7 Lion 引入后成为 Objective-C 内存管理的主导方案。采信 “GC 与 ARC 是两种不同的自动内存管理路径，ARC 最终胜出” 的判断。GC 的 `mmap`/`mprotect` 写屏障机制与 BSD 层的关系须以 Darwin 源码 `objc4/` 仓库为准，不得仅凭一般认知推断。

**文献**：Apple Inc. Mac OS X 10.5 Leopard Release Notes [EB/OL]. (2007-10-26). Apple Developer; Apple Inc. WWDC 2007 Session: The Objective-C 2.0 Runtime [EB/OL]. (2007-06-11). Apple Developer; Lattner, C. (2008). *LLVM: A Compilation Framework for Lifelong Program Analysis & Optimization*[Z]. LLVM Project.

## 244.3.4 CoreAnimation 与 Quartz Core 的 BSD 层依赖

**要点**：Leopard 引入 **CoreAnimation** 框架——基于 **Quartz Core**（macOS 的 2D 图形合成引擎，源自 NeXTSTEP 的 Display PostScript 与 Mac OS X 的 Quartz 演进）的动画框架，将图层（layer）合成、动画时间曲线、隐式动画抽象为声明式 API。CoreAnimation 与 BSD 层的关联体现于：动画渲染通过 BSD 层的 `mmap` 映射 GPU 显存、通过 `mach_msg`（Mach 消息传递）与窗口服务器（WindowServer，基于 BSD 层的 `bootstrap_server` 注册）通信、通过 `IOSurface`（后引入的共享内存框架，Leopard 期已有雏形）在进程间共享图像缓冲。CoreAnimation 的引入为后续 iOS 的 UIKit 动画体系奠定基础——iPhone OS（UIKit 自 2007 年 iPhone OS 1.0 已存在〔原稿系于 2.0 存疑〕，2008 年 2.0 经 SDK 面向第三方） 动画 API 直接复用 CoreAnimation 的图层合成机制，此为 Darwin 谱系中桌面与移动共享图形栈的关键节点。

  | CoreAnimation 技术要素 | 上游来源 | BSD 层依赖 |
  | --- | --- | --- |
  | Quartz Core 图层合成 | NeXTSTEP Display PostScript → Quartz | `mmap` GPU 显存 |
  | WindowServer 通信 | Mac OS X 窗口服务器 | `mach_msg` + `bootstrap_server` |
  | IOSurface 共享内存 | Leopard 期雏形 | BSD 层 `mmap` 共享内存 |
  | UIKit 动画复用 | CoreAnimation（Leopard） | iPhone OS 2.0（2008）继承 |

  > CoreAnimation 是 Leopard 期 Darwin 图形栈的关键演进——其图层合成机制在桌面与移动间共享，是 Apple “一次设计多端复用” 工程哲学的显现。
**史料**：Apple Inc. Mac OS X 10.5 Leopard Release Notes [EB/OL]. (2007-10-26). Apple Developer（CoreAnimation 章节）；Apple Inc. WWDC 2007 Session: Introduction to CoreAnimation [EB/OL]. (2007-06-11). Apple Developer；Darwin 源码仓库 opensource.apple.com（`QuartzCore/` 目录含 CoreAnimation 源码，对应 Leopard 期版本）。〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕。CoreAnimation 是 Quartz 图形栈的延续而非断裂——此即项目史观总纲第二十五章的显现：从 NeXTSTEP 的 Display PostScript 到 Mac OS X 的 Quartz 再到 Leopard 的 CoreAnimation，图形栈的形式（图层合成）在演化中延续，但具体实现（PostScript → PDF → CoreImage → CoreAnimation）不断迭代。q.md “数字墓地” 在此显现：Display PostScript 作为 “数字墓地” 被 Quartz 取代，但 Quartz 的图层合成思想在 CoreAnimation 中延续。

**辨析**：CoreAnimation 与 Quartz 的关系——CoreAnimation 是基于 Quartz Core 的上层框架，二者非替代关系而是分层关系。Quartz Core 提供底层图层合成，CoreAnimation 提供声明式动画 API。CoreAnimation 在 Leopard 引入后成为 macOS 与 iOS 共享的图形栈基础，但其具体在 iPhone OS 2.0 中的复用细节须以 Apple Developer 文档为准，不得仅凭一般认知推断。采信 “CoreAnimation 是 Leopard 期引入的图形栈关键演进，桌面与移动共享” 的判断。

**文献**：Apple Inc. Mac OS X 10.5 Leopard Release Notes [EB/OL]. (2007-10-26). Apple Developer; Apple Inc. WWDC 2007 Session: Introduction to CoreAnimation [EB/OL]. (2007-06-11). Apple Developer.

## 244.3.5 BSM 审计框架的引入（OpenBSM 移植，跨 BSD/UNIX/macOS 扩展）

**要点**：**Mac OS X 10.5 Leopard**（**2007 年 10 月 26 日**发布）引入 **BSM（Basic Security Module）审计框架**，源自 **TrustedBSD 项目**的 **OpenBSM** 子项目——OpenBSM 由 **Robert N. M. Watson（罗伯特·N·M·沃森）** 主导开发，TrustedBSD 官方主页 **trustedbsd.net** 明确列 **Apple Computer, Inc.** 为赞助商之一。macOS BSM 审计与 FreeBSD OpenBSM 共享上游源码，使用 **audit(8)** 与 **praudit(1)** 工具，审计日志路径为 **/var/audit/**。此移植是 TrustedBSD 项目成果向 macOS 的反向流动（FreeBSD → macOS），与 Linux Audit 完全独立演化。

  | BSM 审计要素 | 内容 |
  | --- | --- |
  | 引入版本 | Mac OS X 10.5 Leopard |
  | 发布日期 | 2007-10-26 |
  | 上游来源 | TrustedBSD OpenBSM 子项目 |
  | 主导开发者 | Robert N. M. Watson |
  | 赞助商 | Apple Computer, Inc.（列于 trustedbsd.net） |
  | 工具 | audit(8)、praudit(1) |
  | 日志路径 | /var/audit/ |
**史料**：TrustedBSD Project. *TrustedBSD Home Page*[EB/OL]. <http://www.trustedbsd.net/（明确列> Apple Computer, Inc. 为赞助商）；Apple Inc. *Mac OS X 10.5 Leopard Release Notes*[EB/OL]. (2007-10-26). Apple Developer；**audit(8)** 与 **praudit(1)** man page（developer.apple.com）。〔L3 官方文档与公告〕

**史观**：总纲第 10 条——动手者创造历史〔原挂第 1 条伪标签，按语义重审挂 10〕：BSM 审计框架是 Watson 面对 FreeBSD/macOS 安全审计需求的工程洞察；总纲第 2 条——分离与聚合：OpenBSM 在 TrustedBSD 中开发，聚合入 FreeBSD 与 macOS，是跨 BSD 谱系的聚合时刻；总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：macOS 选择移植 OpenBSM 而非独立实现，付出与 Apple 私有安全机制集成的代价，但获得与 FreeBSD 审计工具的兼容性；总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：macOS 选择 OpenBSM 反映其“BSD 谱系协同”的技术政治选择，与 Linux 的“独立 Audit”形成对照；总纲第 10 条——动手者创造历史：Watson 作为 OpenBSM 主导开发者，其姓名在 Apple 主线叙事中常被遮蔽，仅保留“TrustedBSD Project”集体署名；总纲第 15 条——文化即形式主义：BSM 作为“形式”（审计记录格式）统一了 FreeBSD 与 macOS 的“内容”（安全事件）；总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：OpenBSM 从 FreeBSD 反向移植至 macOS，是 BSD 谱系内部“延续”的显现，与 Linux Audit 的“分离”形成对照；自反性声明：本释读不预设“macOS 中心论”——BSM 是 TrustedBSD 项目的成果，FreeBSD 是原始开发方，macOS 是移植接收方。

**辨析**：macOS BSM 审计与 FreeBSD OpenBSM 共享上游源码但实现细节有差异——macOS BSM 与 Apple 私有安全机制（如 sandbox_init）协同，FreeBSD OpenBSM 与 Capsicum 协同；macOS BSM 审计日志路径为 **/var/audit/**，FreeBSD OpenBSM 审计日志路径亦为 **/var/audit/**，二者格式兼容；与 Linux Audit 完全独立演化，无源码关系。

**文献**：TrustedBSD Project. *TrustedBSD Home Page*[EB/OL]. <http://www.trustedbsd.net/>; Apple Inc. *Mac OS X 10.5 Leopard Release Notes*[EB/OL]. (2007-10-26). Apple Developer; Watson, R. N. M. (2003). *TrustedBSD: Adding Trusted Operating System Features to FreeBSD*. USENIX Annual Technical Conference 2003（该文实为 2001 年 ATC FREENIX Track〔年份按报告订正待复核〕）, FREENIX Track.
