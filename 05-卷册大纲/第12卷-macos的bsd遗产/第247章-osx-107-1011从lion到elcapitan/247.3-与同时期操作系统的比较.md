# 247.3 与同时期操作系统的比较

## 247.3.1 OS X 10.7-10.11 对比 FreeBSD 9/10、Linux 3.x、Windows 8/10

**要点**：**2011-2015 年** OS X 10.7-10.11 对比 **FreeBSD 9.x**（**2012 年 1 月 12 日** 发布）/**10.x**（**2014 年 1 月 14 日** 发布）、**Linux 3.x**（2011-2015 年）、**Windows 8**（**2012 年 10 月 26 日** 发布）/**8.1**（**2013 年 10 月 17 日** 发布）/**10**（**2015 年 7 月 29 日** 发布），其沙盒（Gatekeeper）与 SIP 在桌面安全模型上领先。FreeBSD 9.x/10.x 的安全模型以 **jail(8)** 与 TrustedBSD MAC 为基础，未引入类似 SIP 的系统级权限限制。Linux 3.x 的安全模型以 **SELinux**（NSA 主导，2003 年合入 Linux 2.6）与 **AppArmor** 为基础，与 OS X 的 SIP 实现路径不同（SELinux 基于 LSM 钩子，SIP 基于 TrustedBSD MAC）。Windows 8/10 的安全模型以 **UAC**（User Account Control，2007 年 Windows Vista 引入）与 Windows Defender 为基础，与 OS X 的 Gatekeeper/SIP 组合差异显著。

  | 操作系统 | 发布时间 | 安全模型 | 实现机制 | 与 OS X 差异 |
  | --- | --- | --- | --- | --- |
  | **OS X 10.7-10.11** | 2011-2015 | Gatekeeper + SIP | TrustedBSD MAC 框架 | 自身 |
  | **FreeBSD 9.x/10.x** | 2012-2014 | **jail(8)** + TrustedBSD MAC | 进程级容器 + MAC | 无系统级 SIP |
  | **Linux 3.x** | 2011-2015 | SELinux + AppArmor | LSM 钩子 | 实现路径不同 |
  | **Windows 8/8.1/10** | 2012-2015 | UAC + Windows Defender | NT 内核机制 | 不属 Unix 谱系 |

  > SIP 与 Linux 的只读根（immutable root）设计理念相似但实现路径不同——Linux 的只读根（如 Fedora Silverblue 的 `/usr` 只读）在文件系统层实现，SIP 在内核的 MAC 框架层实现。

**史观**：总纲第 6 条——主体性与和解。OS X、FreeBSD、Linux、Windows 在安全模型选择上是“主体性”的显现——此即项目史观总纲第六章的具体呈现：OS X 选择 Gatekeeper+SIP（基于 TrustedBSD MAC），FreeBSD 选择 **jail(8)**+MAC，Linux 选择 SELinux/AppArmor，Windows 选择 UAC+Defender——四者共享 Unix/POSIX 哲学的根基但发展出不同的安全模型主体性。

**辨析**：SIP 与 Linux 的只读根（immutable root）设计理念相似但实现路径不同——Linux 的只读根（如 Fedora Silverblue 的 `/usr` 只读）在文件系统层实现，SIP 在内核的 MAC 框架层实现。采信“SIP 与 Linux 只读根理念相似但实现路径不同”的判断。
