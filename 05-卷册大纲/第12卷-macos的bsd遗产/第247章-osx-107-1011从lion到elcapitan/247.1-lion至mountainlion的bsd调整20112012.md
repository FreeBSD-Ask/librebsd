# 247.1 Lion 至 Mountain Lion 的 BSD 调整（2011-2012）

## 247.1.1 名称简化与 Darwin 同步 FreeBSD 8.x

**要点**：**Mac OS X 10.7 Lion** 于 **2011 年 7 月 20 日** 发布（首次通过 Mac App Store 分发，不再提供光盘），引入 **Mac App Store**、**Launchpad**、**Mission Control**、全屏 API 等 iOS 风格功能。**Darwin 11.x**（对应 10.7 Lion）的 BSD 用户空间同步 **FreeBSD 8.x** 级别——FreeBSD 8.0 于 **2009 年 11 月 25 日** 发布，8.2 于 **2011 年 1 月** 发布，Darwin 11.x 的用户空间工具版本与此对应。**OS X 10.8 Mountain Lion** 于 **2012 年 7 月 25 日** 发布，操作系统名称从“Mac OS X”简化为“OS X”（去“Mac”前缀，与 iOS 命名风格统一）。此改名公告于 **2012 年 2 月 16 日** 随 OS X 10.8 Mountain Lion 预告同步发布［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］——业界记录显示 Apple 在 Mountain Lion 预告日同步公布“Mac OS X”→“OS X”的命名简化，但本次考据未取得 Apple Newsroom 一手公告页面，待后续查询互联网档案馆补全。Mountain Lion 引入 iCloud 集成、Notification Center、Messages（替代 iChat）、**Gatekeeper**（代码签名机制，限制未签名应用运行）。**Darwin 12.x** 同步 FreeBSD 8.x/9.x 级别用户空间——FreeBSD 9.0 于 **2012 年 1 月 12 日** 发布，Darwin 12.x 部分吸收 9.x 用户空间工具。

  | OS X 版本 | 发布日期 | Darwin 版本 | BSD 用户空间来源 | 主要功能引入 |
  | --- | --- | --- | --- | --- |
  | **10.7 Lion** | 2011-07-20 | Darwin 11.x | FreeBSD 8.x | Mac App Store、Launchpad、Mission Control |
  | **10.8 Mountain Lion** | 2012-07-25 | Darwin 12.x | FreeBSD 8.x/9.x | Gatekeeper、Notification Center、Messages |

**史观**：总纲第 2 条——实践先于理论。Darwin 用户空间的增量同步而非重写，此即项目史观总纲第二章“历史认识论”中“经验优先”的显现——Apple 未为每个 OS X 版本重新实现 BSD 用户空间工具，而是持续同步 FreeBSD 已验证的工具版本。q.md“道与术的辩证”在此显现：Lion 的 iOS 风格功能（Launchpad、Mission Control）是“道”（品牌战略），BSD 层同步是“术”（工程实现），二者并行但分属不同层面。

**辨析**：Lion 期的 Darwin 与 FreeBSD 8.x 同步程度须以源码 tag 比对确认——Darwin 源码仓库中可见对 FreeBSD 8.x 用户空间工具的直接引用（如 `usr.bin/tcpdump`、`usr.sbin/config`），但内核代码（XNU）与 FreeBSD 内核无直接派生关系。采信“Apple 同步 FreeBSD 用户空间工具版本，内核独立实现”的判断。【统计结论 C-49 整合】统计结论 [C-49] cross_references 表 0 行（数据缺口，schema 就绪）；xnu 仓库 29 个非零月 155 commits 2.4 年活动窗口——darwin.duckdb 中 xnu 仓库仅 155 条 commit，反映 Apple 以 tag 方式发布 XNU 源码快照而非逐 commit 镜像内部 Git 历史，此数据局限性使 Lion 至 El Capitan 时期（2011-2015）的 XNU 内核具体演化无法从 commit 历史直接追溯。0 信任原则提示：xnu 仓库 155 条 commit 的“低 commit 数”是发布机制的结果而非项目活跃度低的证据，不得据此推断 Apple 内部整合工作量；Darwin 源码仓库 opensource.apple.com 的 release tag 列表才是 XNU 版本演进的可靠参照。

## 247.1.2 Gatekeeper 与代码签名机制

**要点**：**OS X 10.8 Mountain Lion**（**2012 年 7 月 25 日** 发布）引入 **Gatekeeper**——代码签名机制，限制未签名应用运行。Gatekeeper 提供“**Mac App Store**”、“**Identified Developers**”、“**Anywhere**”三档安全级别（默认为“Identified Developers”，仅允许签名应用运行）。此机制在 BSD 层的实现依赖代码签名验证（`amfid` 守护进程，验证应用签名）与 BSD 的 `execve` 系统调用——`execve` 在启动应用前检查签名，未签名应用的执行被拒绝。Gatekeeper 是 Darwin BSD 层权限模型收紧的第一步，为后续 **SIP**（**10.11 El Capitan**）奠定基础。

  | Gatekeeper 安全级别 | 允许运行的应用 | 默认设置 |
  | --- | --- | --- |
  | **Mac App Store** | 仅 Mac App Store 应用 | 否 |
  | **Identified Developers** | 签名应用（含 App Store 与认证开发者） | 是（默认） |
  | **Anywhere** | 任何应用（含未签名） | 否 |

  > Gatekeeper 在用户态守护进程 `amfid` 中实现签名验证，但通过 BSD 层的 `execve` 钩子触发——BSD 内核的 `execve` 接口本身未修改，但增加了签名验证的调用路径。
**史料**：Apple Inc. OS X 10.8 Mountain Lion Security Overview [Z]. Apple Developer Documentation, 2012（Gatekeeper 章节）；Apple Inc. WWDC 2012 Session: Gatekeeper [EB/OL]. (2012-06-11). Apple Developer；Darwin 源码仓库 opensource.apple.com（`bsd/kern/kern_exec.c` 含签名验证代码）。

**史观**：总纲第 24 条——许可证哲学。Gatekeeper 是 Apple 对 BSD 层“开放执行”传统的改造——此即 q.md“自由的张力”的具体显现：BSD 层的 `execve` 系统调用原本允许执行任何可执行文件（Unix 传统“开放执行”），Gatekeeper 通过签名验证将“开放执行”转为“受控执行”，此即“消极自由”向“受控自由”的转变。

**辨析**：Gatekeeper 是否修改了 BSD 内核——经 Darwin 源码仓库比对，Gatekeeper 的签名验证在用户态守护进程 `amfid` 中实现，但通过 BSD 层的 `execve` 钩子触发。BSD 内核的 `execve` 接口本身未修改，但增加了签名验证的调用路径。采信“Gatekeeper 在用户态实现签名验证，但通过 BSD 层的 `execve` 钩子触发”的判断。

**文献**：Apple Inc. OS X 10.8 Mountain Lion Security Overview [Z]. Apple Developer Documentation, 2012; Apple Inc. WWDC 2012 Session: Gatekeeper [EB/OL]. (2012-06-11). Apple Developer.
