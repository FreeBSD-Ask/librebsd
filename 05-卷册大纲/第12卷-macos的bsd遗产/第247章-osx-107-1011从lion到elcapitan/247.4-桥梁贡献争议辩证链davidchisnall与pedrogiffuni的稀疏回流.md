# 247.4 桥梁贡献争议辩证链：David Chisnall（戴维·奇斯纳尔） 与 Pedro Giffuni 的稀疏回流

## 247.4.1 批评层：BSD 阵营对“桥梁贡献稀疏”的指控

**要点**：BSD 社区针对 2011-2015 年（OS X 10.7 Lion 至 10.11 El Capitan）Apple 与 FreeBSD 之间桥梁贡献的批评可归纳为三点。其一，**桥梁贡献者数量稀疏**——freebsd.duckdb 查询显示，此期横跨 FreeBSD 与 Apple 两个社区的桥梁贡献者仅 **David Chisnall** 与 **Pedro F. Giffuni** 两位，前者在 freebsd-src 仓库 2011-2015 年间共有 149 条 commit，其中与 Apple/Darwin 相关的 commit 37 条（以 xlocale API 移植、libc++ 导入与清理为主，关键 commit 为 **2011 年 11 月 20 日** “Implement xlocale APIs from Darwin, mainly for use by libc++”、**2014 年 4 月 2 日** “Add support for some block functions that come from OS X”），后者在 2011-2015 年间共有 932 条 commit，其中与 Apple/Darwin 相关的 commit 21 条（以 Apple 开发者工具补丁、GCC 与 Apple GCC 差异缩减为主，关键 commit 为 **2012 年 6 月 10 日** "Bring a couple of libstdc++ patches from Apple's llvm-gcc project“、**2014 年 1 月 5 日** ”gcc: Add support for Apple's Block extension"），合计 58 条 Apple 相关 commit，相对于 FreeBSD 同期数万条 commit 总量与 Apple 自 XNU 至用户空间的庞大体量，桥梁贡献在量上呈“稀疏”状态。其二，**桥梁贡献的子系统错位**——Chisnall 的 xlocale 移植是 Darwin→FreeBSD 方向（将 Darwin 的扩展 locale API 反向移植至 FreeBSD），Giffuni 的补丁集中在 Apple llvm-gcc 与开发者工具向 FreeBSD GCC 的移植，二者均非 FreeBSD→Darwin 方向的核心子系统回馈；与此对照，Apple 从 FreeBSD 吸收的代码涉及 libc、TCP/IP 网络栈、VFS 等核心子系统，桥梁贡献的“方向”与“子系统”均与吸收不对称。其三，**桥梁贡献的时间窗口短促**——Chisnall 的 Apple 相关 commit 跨度约 3 年 5 个月（2011-11 至 2015-04），Giffuni 的 Apple 相关 commit 至 2014 年 8 月结束，此后桥梁贡献几乎中断，而 apple.com 邮箱的 commit 在 freebsd-src 中直至 **2021 年 7 月 20 日** 才再次出现（且为 Cosimo Cecchi 与 Yann Kerherve 两位非桥梁型贡献者，6 条 commit 集中在 2021-2024 年，与本期的 2011-2015 年窗口不重叠）。

## 247.4.2 反批评层：Apple 阵营对“桥梁稀疏”指控的回应

**要点**：Apple 阵营对“桥梁贡献稀疏”批评的回应可归纳为三条路径。其一，**BSDL 设计意图即允许稀疏**——BSD 许可证明文允许“with or without modification”的商业使用与闭源发行，“允许不回馈”是 BSDL 的哲学选择而非 Apple 的剥削，桥梁贡献的稀疏恰是 BSDL 创始者有意授予的自由在 2011-2015 年间的自然显现；要求 Apple 在 BSDL 契约之外“主动”提供桥梁贡献，是将法律契约与伦理期待混淆。其二，**Apple 的开源贡献以其他形式存在**——Apple 经 apple-oss-distributions 组织在 GitHub 发布 **509 个开源仓库**（含 XNU 内核、WebKit、Security 子系统、libdispatch 等），此期 Apple 对 **LLVM/Clang** 项目的持续投入使 FreeBSD 10.0（**2014 年 1 月 14 日** 发布）起得以摆脱 GCC GPLv3 约束，**libdispatch** 以 Apache 2.0 许可证开源使 FreeBSD 可无障碍移植并发编程库——此等贡献虽不以 freebsd-src 仓库 commit 形式显现，但构成 Apple 对开源生态的实质回馈。其三，**人才回流即隐性桥梁**——**Jordan Hubbard**（FreeBSD 联合创始人，freebsd.duckdb 查询 5 显示其在 freebsd-src 仓库有 7,101 条 commit，时间跨度 **1993 年 6 月 18 日** 至 **2004 年 11 月 14 日**）于 **2001 年 7 月** 加入 Apple，其 FreeBSD 经验影响了 Darwin 的工程实践，此为“人才回流”虽非“代码回流”但同样构成桥梁——Jordan Hubbard 在 Apple 任职期间仍持续向 FreeBSD 提交 commit（至 2004 年 11 月），其个人即是一座“人形桥梁”。

## 247.4.3 再批评层：BSD 阵营对 Apple 回应的再反驳

**要点**：BSD 阵营对 Apple 回应的再反驳聚焦三点。其一，**“合法”不等于“合宜”**——BSDL 允许桥梁稀疏是法律事实，但批评者追问的是“许可证允许的行为是否符合 FreeBSD 社区长期利益”，此为伦理与利益问题而非法律问题；桥梁贡献者仅 2 人（Chisnall 与 Giffuni），且二者的贡献均非 Apple 雇员行为（Chisnall 为 FreeBSD committer 兼 Cambridge 大学研究者，Giffuni 为 FreeBSD committer），Apple 作为商业实体未直接派遣员工以 apple.com 邮箱向 freebsd-src 提交，此事实强化了“合法但不合宜”的判断。其二，**桥梁贡献的子系统错位无法以其他形式补偿**——Apple 的 LLVM/Clang 投入惠及 FreeBSD 编译器栈，libdispatch 开源惠及 FreeBSD 并发库，但此二者均与 Apple 从 FreeBSD 吸收的 libc、TCP/IP 网络栈、VFS 不在同一子系统；FreeBSD 无法以 libdispatch 弥补 libc 的流失，二者不可互换，故“平行回馈”非“对等回馈”，桥梁贡献的子系统错位无法以其他形式的开源贡献补偿。其三，**Jordan Hubbard 的“人形桥梁”论点须量化验证**——freebsd.duckdb 查询 5 显示 Jordan Hubbard 的 commit 跨度为 1993-06-18 至 2004-11-14，其 2001 年 7 月加入 Apple 后的 commit 频率变化须以时间分布查询验证；若其加入 Apple 后 commit 频率显著下降，则“人形桥梁”论点须打折——Jordan Hubbard 在 Apple 的工作重心转向 Darwin/macOS，其对 FreeBSD 的贡献可能逐渐从“主动 commit”转为“间接影响”。

**辨析**：再批评层须避免将“合法但不合宜”简单化为对 Apple 的道德指责——BSDL 的宽容是 FreeBSD 自愿授予，Apple 在契约内行事无可指责，但社区利益的长期维护须依赖社区自身的制度安排而非商业公司的善意。子系统错位的判断须谨慎——xlocale/libc++ 移植虽不能弥补 libc/网络栈/VFS 的流失，但 xlocale 与 libc++ 本身对 FreeBSD 的现代化（尤其是 C++ 标准库支持）有实质贡献，不应被完全否定。Jordan Hubbard 的“人形桥梁”论点须量化验证——其 2001 年加入 Apple 后的 commit 频率变化是可量化检验的命题。采信“再批评层在伦理层面成立，但须区分法律、伦理、利益三个层面，不得将三者混淆”的判断。

## 247.4.4 合图层：商品形式主义下的桥梁稀疏

**要点**：**合图层：商品形式主义下的桥梁稀疏**。将批评层、反批评层、再批评层合图，可见“桥梁贡献稀疏”争议的本质不是桥梁数量的多寡，而是商品形式主义下的权力结构。Apple 以 BSD 代码为底层组件构建 macOS 商业生态（商品化），FreeBSD 以非营利模式维护代码源头（非商品化）——同一代码在两端的“商品化程度”不同，决定了桥梁贡献的不对称。项目史观总纲第 11 条“商品是形式主义”在此显现：技术市场的选择不是自然选择，Apple 的商业成功与 FreeBSD 的边缘化不是技术优劣而是形式主义的权力运作。BSD 许可证“允许不回馈”的设计，在商品形式主义下演化为“劣币驱逐良币”的机制——商业封装的 macOS 获得市场主导权，非营利的 FreeBSD 在服务器市场被 Linux（GPL 强制回馈的生态）挤压。David Chisnall 与 Pedro F. Giffuni 作为桥梁贡献者，其稀疏性既是 BSDL 哲学的必然代价，亦是商品形式主义下权力结构的显现——Apple 无动力派遣员工以 apple.com 邮箱向 FreeBSD 回馈，因其商业利益与 FreeBSD 的非营利地位在形式主义层面已分叉。合图层的判断是：桥梁贡献稀疏是 BSDL 哲学的必然代价，此代价由 FreeBSD 社区自觉承担，但不应被伪装为“无代价”或“双向对等”。
