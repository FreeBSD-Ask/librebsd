# 237.3 Objective-C、AppKit 与 BSD 的共生（1989-1996）

## 237.3.1 上层框架对 BSD 接口的封装

**要点**：NeXT 的 **Objective-C** 运行时与 **AppKit** 框架建立在 BSD/POSIX 系统调用接口之上——**Objective-C** 的 `NSObject` 基类的内存管理（`alloc`/`dealloc`）底层调用 BSD 的 `mmap`/`munmap`，AppKit 的 `NSThread` 底层调用 BSD 的 `pthread` 接口。**NeXTSTEP 1.0**（1989 年）即提供 “双轨” 开发模式：开发者既可调用 Objective-C 框架（**AppKit**、**Foundation Kit**），也可直接调用 BSD 系统调用（`open`、`read`、`write`、`socket`）。此 “双轨” 模式被后续 macOS 继承——至 2024 年 macOS 仍同时支持 Objective-C/Swift 框架层与直接 BSD/POSIX 系统调用。

  | 层次 | 组件 | 底层 BSD 接口 |
  | --- | --- | --- |
  | 应用层 | Objective-C 框架（AppKit/Foundation） | 无直接调用，经运行时桥接 |
  | 运行时层 | NSObject 内存管理 | `mmap`/`munmap` |
  | 运行时层 | NSThread | `pthread` 系列 |
  | 系统调用层 | BSD/POSIX | `open`/`read`/`write`/`socket` |
  | 内核层 | Mach 微内核 | 消息传递 IPC |

**史观**：总纲第 19 条——科学技术历史哲学。Objective-C 与 BSD libc 的共生预示了 Darwin 的双层结构——此即项目史观总纲第九章 “科学技术历史哲学” 的显现：Objective-C 作为 “形式主义化的编程范式” 建立在 BSD 系统调用这一 “形式主义化的通信规则” 之上，二者非派生关系而是共生关系。q.md “道与术的辩证” 在此显现：Objective-C 框架是 “道”（上层抽象），BSD 系统调用是 “术”（底层实现），但 “道” 并不否定 “术”——二者在同一系统中各自显现。

**辨析**：Objective-C 是否 “基于” BSD 须澄清——Objective-C 是编程语言与运行时（Brad Cox 1983 年设计），BSD 是操作系统接口，二者是共生而非派生关系。Objective-C 可在任何提供 C 编译器的操作系统上运行（如 GNUstep 在 Linux 上实现），但 NeXTSTEP/macOS 的 Objective-C 运行时与 BSD 系统调用深度集成，此集成是 NeXT 工程选择而非 Objective-C 语言本身的限制。Brad Cox 的原始 Objective-C 实现（1983 年）先于 NeXTSTEP（1988 年），此时间顺序支持 “共生而非派生” 的判断。【0 信任原则·XNU 快照发布局限】darwin.duckdb 查询 L7.5.1 数据无法直接反映 NeXTSTEP 1989-1996 年间 Objective-C 运行时与 BSD 系统调用的集成细节，XNU 快照仅覆盖 2003 年后的实现状态；Objective-C 运行时与 BSD 接口的早期集成须以 NeXTSTEP 源码考古与 Cox 原始文献为准。
