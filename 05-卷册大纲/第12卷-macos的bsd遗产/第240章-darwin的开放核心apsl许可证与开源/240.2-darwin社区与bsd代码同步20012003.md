# 240.2 Darwin 社区与 BSD 代码同步（2001-2003）

## 240.2.1 Darwin 与 FreeBSD 的代码互鉴

**要点**：**2001-2003 年** 间 Darwin 的 BSD 层（`libc`、网络栈、部分驱动）与 **FreeBSD 4.x/5.x** 保持代码同步。freebsd.duckdb 查询显示，**Robert Watson** 于 **2001 年 8 月 29 日** 在 freebsd-src 仓库提交 “Reduce gratuitous whitespace difference from Darwin”——此 commit 证明 FreeBSD 与 Darwin 的代码同步是双向的，Watson 作为 FreeBSD 核心开发者与 Apple 顾问，在 **2001-2008 年** 间提交多条与 Darwin 同步相关的 commit。**Jordan Hubbard**（FreeBSD 联合创始人）于 **2001 年 7 月** 加入 Apple 任 Darwin 技术负责人，freebsd.duckdb 显示其在 freebsd-src 仓库的 commit 记录为 **7,101 条**（1993-06-18 至 2004-11-14），2001 年 7 月加入 Apple 后仍有少量 FreeBSD 提交至 2004 年 11 月。Apple 工程师向 FreeBSD 回馈补丁，FreeBSD 的部分修复也并入 Darwin，形成双向流动。

  | 关键 commit | 提交者 | 日期 | 方向 | 说明 |
  | --- | --- | --- | --- | --- |
  | “Reduce gratuitous whitespace difference from Darwin” | Robert Watson | 2001-08-29 | Darwin→FreeBSD | 证明双向同步 |
  | "Further synchronization of copyrights, licenses, white space, etc from Apple" | Robert Watson | 2008-07-31 | Darwin→FreeBSD | 持续 7 年同步 |
  | “Implement xlocale APIs from Darwin, mainly for use by libc++” | David Chisnall（戴维·奇斯纳尔） | 2011-11-20 | Darwin→FreeBSD | xlocale API 反向移植 |

  > Jordan Hubbard 加入 Apple（2001-07）后，其在 FreeBSD 的 commit 频率从年均数百条降至 2004 年 11 月的基本停止，此为 FreeBSD→Apple 人才流动的量化证据。

**史观**：总纲第 4 条——分离聚合是永恒规律。BSD 代码在 Apple 与 FreeBSD 间双向延续——此即分离与聚合永恒规律的显现：Darwin 与 FreeBSD 共享 4.4BSD-Lite 上游，但在 2001-2003 年间发展为两个独立但相互贡献的主体。q.md “道与术的辩证” 在此显现：Darwin 的 BSD 层是 “术”（工程实现），其与 FreeBSD 的代码同步是 “道”（开源社区的协作哲学），二者并行但分属不同层面。

**辨析**：Darwin 与 FreeBSD 的 “代码同步” 程度和方向——darwin.duckdb 显示 2001-2003 年间同步以 FreeBSD→Darwin 为主（Apple 从 FreeBSD 吸收用户空间工具版本），反向（Darwin→FreeBSD）以 Robert Watson 的 whitespace 同步 commit 为代表但数量有限。Jordan Hubbard 加入 Apple 后的 FreeBSD commit 频率下降（2004 年 11 月后逐渐减少），采信 “Jordan Hubbard 2001 年 7 月加入 Apple 任 Darwin 技术负责人，2004 年后逐渐减少 FreeBSD 直接贡献” 的判断。【0 信任原则·XNU 快照发布局限】darwin.duckdb 查询 L7.5.1 数据无法直接反映 Darwin 1.x/7.x 时期与 FreeBSD 4.x/5.x 的代码同步路径，XNU 快照仅含 later Apple 时期的 BSD 层代码；代码同步路径须以 Robert Watson/Jordan Hubbard commit 记录与 Darwin 源码仓库 release notes 为准。

## 240.2.2 XNU 源码快照发布规律与 Apple 开源仓库迁移

**要点**：Apple 以 tag 方式发布 XNU 源码快照，**darwin.duckdb** 中 xnu 仓库共 **155 个 release tag**，与 Mac OS X 10.0（**2001-03-24**）至 macOS 26 Tahoe（**2025-09-15**）全部 macOS 主版本对应。tag 命名规则为 `xnu-XXXX.Y.Z`（如 `xnu-123.5` 对应 Mac OS X 10.0 Cheetah、`xnu-12377.1.9` 对应 macOS 26 Tahoe），`tagger_name` 全部为 `Apple OSS Distributions`。**2021-10-06** Apple 将历史 XNU 源码快照从 **opensource.apple.com** 批量迁移至 **GitHub apple-oss-distributions** 仓库——darwin.duckdb 显示此日 `target_commit_date` 集中于 `2021-10-06T05:41:03Z` 至 `2021-10-06T05:41:20Z`（约 17 分钟内），2022 年之前的所有 xnu tag 均按原始公告日期回填 `tagger_date`。XNU tag 与 macOS 公告日期的偏差规律呈三阶段演化：阶段一（2003-2009，Mac OS X 10.3 Panther 至 10.6 Snow Leopard）偏差 1-14 天；阶段二（2011-2019，10.7 Lion 至 10.15 Catalina）偏差 -7 至 121 天，存在 tag 早于公告的负偏差与异常长偏差（Catalina 偏差 121 天为历史最大值）；阶段三（2022-2026，macOS 13 Ventura 起）偏差收敛至 -6 至 19 天。**macOS 14 Sonoma**（**2023-09-26**）是 Apple 公开发布与 XNU tag 同日的首个版本（`xnu-10002.1.13`，`tagger_date` `2023-09-26T19:38:39Z`），此后 macOS Tahoe 26.x 系列（2025-2026）稳定为“公告后约两周开源”的 13-22 天节奏。

  | 阶段 | 时间范围 | XNU tag 与公告偏差 | 典型版本 |
  | --- | --- | --- | --- |
  | 阶段一 | 2003-2009 | 1-14 天 | Panther 至 Snow Leopard |
  | 阶段二 | 2011-2019 | -7 至 121 天 | Lion 至 Catalina（Catalina 偏差 121 天为历史最大值） |

**史观**：总纲第 18 条——时间是一种形式主义。XNU 源码快照的发布节奏从“公告后数月”演化为“公告后两周”再至 macOS 14 Sonoma 的“同日发布”，是 Apple 开源工程流程形式主义化的显现——发布节奏的形式主义化正是时间作为形式主义的呈现：Apple 通过工程流程改进逐步缩短公告与开源发布的时间差，此缩短本身即“形式主义化的合规规则”的扩展。q.md“道与术的辩证”在此显现：XNU tag 的命名规则（`xnu-XXXX.Y.Z`）是“道”（命名规范），tag 对应 macOS 版本的快照内容是“术”（工程实现），二者并行但分属不同层面。总纲第 4 条——分离聚合是永恒规律：Apple 从 opensource.apple.com 的 tarball 发布迁移至 GitHub apple-oss-distributions 的 git tag 发布，组织载体的分离与聚合重塑了开源协作的可能性边界。

**辨析**：XNU tag 偏差规律的阶段划分——darwin.duckdb 显示阶段二的异常长偏差（如 macOS 10.15 Catalina 偏差 121 天）可能反映 Apple 在 2018-2019 年推迟开源发布周期，亦可能反映 darwin.duckdb 中该时期 tag 是后来回填的。macOS 12 Monterey 偏差 102 天为阶段三的异常值，可能因 macOS 12 周期内 Apple 调整开源发布流程。采信“Apple 在 2021 年开源仓库迁移后逐步收紧 XNU tag 发布节奏，macOS 14 Sonoma 首次实现同日发布”的判断。【0 信任原则·XNU 快照发布局限】darwin.duckdb 中 2022 年之前所有 xnu tag 的 `target_commit_date` 集中于 2021-10-06，反映的是 Apple 仓库迁移而非实际开源发布时间；`tagger_date` 系 Apple 按原始公告日期回填，可能存在误差，须以 opensource.apple.com 历史记录与 GitHub apple-oss-distributions 仓库 release 列表交叉确证。macOS Tahoe 26.x 系列小版本（26.0.1、26.3.1、26.3.2、26.4.1、26.5.1）是否对应独立 XNU tag 标注 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］——darwin.duckdb 显示部分小版本共用同一 tag（如 26.3.1 与 26.3.2 共用 `xnu-12377.81.4`），可能 Apple 将多个小版本的 XNU 源码合并到同一快照，亦可能部分小版本未发布 XNU tag。

**BSD 组件在 XNU 中的代码级证据**：Apple 官方 XNU 仓库（github.com/apple-oss-distributions/xnu）README 明示 XNU 内核为 Mach 与 BSD 组件（含 FreeBSD 组件）的结合；更直接的代码级证据是，Apple 官方发布的 `touch.c`、`ls.c`、`top.c` 等用户态源码文件中保留有 FreeBSD 版权头与 `__FBSDID` 宏标记——`__FBSDID` 是 FreeBSD 源码专有的 RCS ID 声明宏，其存在于 Apple 发布的源码中，构成 BSD 代码进入 Darwin 的不可篡改的版权头链证据。本条为 240.2 节 BSD 代码同步叙事与 247.x 节“稀疏回流”争议提供 L5 级锚点：回流密度的争议不影响“回流存在”的代码级事实。
