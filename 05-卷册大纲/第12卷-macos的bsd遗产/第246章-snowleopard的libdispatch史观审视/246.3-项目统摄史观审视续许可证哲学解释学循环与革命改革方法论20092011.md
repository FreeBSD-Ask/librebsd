## 246.3.1 总纲第 13 条映射——许可证哲学作为法律与道德的利益分配

**要点**：项目史观总纲第 13 条“法律与道德是利益分配。任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”为审视 Apple 使用 FreeBSD 代码但不回馈争议提供了根本框架。Snow Leopard 时代（2009-2011）的争议在三个层面显现总纲第 13 条的张力。其一，法律层面——BSD 许可证条款明确允许 Apple 使用 FreeBSD 代码而无强制回馈义务，Apple 的行为在法律层面完全合法。**Marshall Kirk McKusick（马歇尔·柯克·麦库西克）** 的“BSD 许可证就是一个复制中心，可以为所欲为，但我们不在乎”表述将此合法性具象化——BSD 许可证的法律设计即是允许“为所欲为”的使用模式，此合法性由 FreeBSD 社区主动选择，不可事后否认。其二，道德层面——批判方以“FreeBSD 贡献者常常被调侃为 Apple 公司的无薪员工”叙事质疑 Apple 的道德立场，但总纲第 13 条指出“任何道德问题本质上是利益问题”——“无薪员工”叙事的实质不是 Apple 道德缺陷，而是 BSD 许可证契约下利益分配的结构性失衡。**John Baldwin（约翰·鲍德温）** 的“我不会因此而责怪他们。FreeBSD 是一个 BSD 许可的项目，而不是 GPL”表述将此利益分配的辨析推回法律层面——Baldwin 拒绝将利益分配失衡道德化，而将其归因于许可证契约的选择。其三，社区治理层面——FreeBSD 社区选择 BSD 许可证即选择此利益分配模式，社区治理本身是“形式主义的政治产物”（总纲第 13 条原文），社区成员的“看得开”态度（McKusick、Baldwin）是此形式主义政治的稳定机制。freebsd.duckdb 一手数据印证此利益分配的客观结构：freebsd-src 仓库 2009-2011 年间 `@apple.com` 域名 commit 数量稀少［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 反映 Apple 工程师未直接向 FreeBSD 主线提交代码，freebsd-ports 仓库 2009-09-23 Sedov 移植 libdispatch 反映 FreeBSD 社区自主吸收 Apple 的开源回馈——此即 BSD 许可证契约下“Apple 选择性开源 →FreeBSD 自主移植”的利益分配格局。

## 246.3.2 总纲第 19 条映射——解释学循环与权力知识共谋在 Apple-FreeBSD 争议中的显现

**要点**：项目史观总纲第 19 条“解释学循环是历史认识的根本条件。前理解的差异使分歧不可避免。权力与知识在历史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使”为审视 Apple 使用 FreeBSD 代码但不回馈争议提供了认识论框架。Snow Leopard 时代（2009-2011）的争议在解释学循环中显现为四方视角的非收敛对话。其一，**Apple 视角**——Apple 通过 opensource.apple.com 持续发布 Darwin 源代码、以 Apache 2.0 开源 libdispatch、聘用 FreeBSD 创始人 Jordan Hubbard，将自身叙述为“BSD 社区的实质性回馈者”，此叙述在前理解上预设“源代码公开即回馈”。其二，**FreeBSD 核心开发者视角**——McKusick 与 Baldwin 的“看得开”态度将争议叙述为“BSD 许可证契约的合法行使”，此叙述在前理解上预设“BSD 许可证选择即接受其后果”。其三，**自由软件阵营视角**——FSF 在 APSL 2.0 评估中明言"only part of Mac OS X is being released under the APSL... that does no good for the other parts of Mac OS X whose source code is not being released at all"，将争议叙述为“Apple 商业模式整体封闭性的局部显现”，此叙述在前理解上预设“软件自由是不可分割的整体”。其四，**第三方观察者视角**——开源中国《FreeBSD 大败局》将争议叙述为“FreeBSD 贡献者作为 Apple 无薪员工”的结构性失衡，此叙述在前理解上预设“利益分配应与贡献规模对称”。四方视角的前理解差异使分歧不可避免（总纲第 19 条原文），任何一方试图绝对化为“客观真相”即陷入解释学循环的权力知识共谋——什么被记录（如 libdispatch Apache 2.0 开源的诚意）、什么被遗忘（如 Snow Leopard 时代 Apple 工程师未直接向 freebsd-src 主线提交代码的事实［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］），本身就是权力行使。freebsd.duckdb 一手数据在此解释学循环中扮演“去权力化”的角色——`@apple.com` 域名 commit 数量稀少与 Sedov 2009-09-23 移植 libdispatch 的事实不依赖任何一方视角的叙述，而是代码级证据，史家须以此还原被遮蔽的事实。

## 246.3.3 总纲第 21 条映射——革命与改革方法论在 BSD-GPL 许可证分歧中的显现

**要点**：项目史观总纲第 21 条“革命与改革是历史方法论的分歧。Linux 靠革命，BSD 靠改革。改革的困难远高于革命。破山中贼易，破心中贼难”为审视 Apple 使用 FreeBSD 代码但不回馈争议提供了方法论框架。Snow Leopard 时代（2009-2011）的争议在革命与改革方法论上显现为 GPL 与 BSD 许可证的方法论分歧。**Linux 靠革命**——GPL 的“传染性”与“强制回馈”是革命式方法论的许可证体现，GPL 通过法律强制力彻底推翻“专有软件可以自由使用开源代码”的旧秩序，建立“使用 GPL 代码即须开源衍生作品”的新秩序，Linux 借此聚拢生态并避免“被利用但不被回馈”的困境。**BSD 靠改革**——BSD 许可证的“完全消极自由”与“无强制回馈”是改革式方法论的许可证体现，BSD 通过渐进式调适在保留“商业公司可以使用 BSD 代码”传统的基础上推动开源协作，FreeBSD 借此维持与 Apple 等商业公司的协作但承受“被利用但不被回馈”的结构性代价。**改革的困难远高于革命**——总纲第 21 条原文的此判断在 Apple 案例中具体显现：BSD 改革式方法论要求 FreeBSD 社区承受结构性不对称的代价（Apple 使用 FreeBSD 代码但不回馈），同时通过社区共识（McKusick 与 Baldwin 的“看得开”态度）与阶段性妥协（libdispatch Apache 2.0 开源、Darwin 源码公开）维持协作；GPL 革命式方法论通过法律强制力避免此代价，但亦失去与 Apple 等商业公司的协作可能性（Apple 不可能以 GPL 释放 Mac OS X 任何部分）。**破山中贼易，破心中贼难**——总纲第 21 条原文的此判断在 Apple 案例中显现为：批判方试图通过道德批评“破”Apple 的“不回馈”行为（破山中贼）相对容易，但试图改变 BSD 许可证契约的结构性不对称（破心中贼）则极其困难——BSD 许可证契约是 FreeBSD 社区的形式主义政治产物（总纲第 13 条），改变此契约即改变 FreeBSD 社区的本体论基础。freebsd.duckdb 一手数据印证此方法论分歧的客观后果：freebsd-src 仓库 2009-2011 年间 `@apple.com` 域名 commit 数量稀少［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 反映 BSD 改革式方法论下 Apple 的“不回馈”是结构性产物，Linux kernel 仓库同期 `@apple.com` 域名 commit 数量亦稀少但 Linux 不依赖 Apple 回馈（因 GPL 强制回馈其他商业公司如 IBM、Red Hat 的贡献），二者形成方法论对比。
