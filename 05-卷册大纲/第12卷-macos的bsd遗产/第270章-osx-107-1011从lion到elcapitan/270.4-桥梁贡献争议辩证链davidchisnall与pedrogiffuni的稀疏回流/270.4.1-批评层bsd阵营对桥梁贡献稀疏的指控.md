# 270.4.1 批评层：BSD 阵营对“桥梁贡献稀疏”的指控

**要点**：BSD 社区针对 2011-2015 年（OS X 10.7 Lion 至 10.11 El Capitan）Apple 与 FreeBSD 之间桥梁贡献的批评可归纳为三点。其一，**桥梁贡献者数量稀疏**——freebsd.duckdb 查询显示，此期横跨 FreeBSD 与 Apple 两个社区的桥梁贡献者仅 **David Chisnall** 与 **Pedro F. Giffuni** 两位，前者在 freebsd-src 仓库 2011-2015 年间共有 149 条 commit，其中与 Apple/Darwin 相关的 commit 37 条（以 xlocale API 移植、libc++ 导入与清理为主，关键 commit 为 **2011 年 11 月 20 日** “Implement xlocale APIs from Darwin, mainly for use by libc++”、**2014 年 4 月 2 日** “Add support for some block functions that come from OS X”），后者在 2011-2015 年间共有 932 条 commit，其中与 Apple/Darwin 相关的 commit 21 条（以 Apple 开发者工具补丁、GCC 与 Apple GCC 差异缩减为主，关键 commit 为 **2012 年 6 月 10 日** "Bring a couple of libstdc++ patches from Apple's llvm-gcc project“、**2014 年 1 月 5 日** ”gcc: Add support for Apple's Block extension"），合计 58 条 Apple 相关 commit，相对于 FreeBSD 同期数万条 commit 总量与 Apple 自 XNU 至用户空间的庞大体量，桥梁贡献在量上呈“稀疏”状态。其二，**桥梁贡献的子系统错位**——Chisnall 的 xlocale 移植是 Darwin→FreeBSD 方向（将 Darwin 的扩展 locale API 反向移植至 FreeBSD），Giffuni 的补丁集中在 Apple llvm-gcc 与开发者工具向 FreeBSD GCC 的移植，二者均非 FreeBSD→Darwin 方向的核心子系统回馈；与此对照，Apple 从 FreeBSD 吸收的代码涉及 libc、TCP/IP 网络栈、VFS 等核心子系统，桥梁贡献的“方向”与“子系统”均与吸收不对称。其三，**桥梁贡献的时间窗口短促**——Chisnall 的 Apple 相关 commit 跨度约 3 年 5 个月（2011-11 至 2015-04），Giffuni 的 Apple 相关 commit 至 2014 年 8 月结束，此后桥梁贡献几乎中断，而 apple.com 邮箱的 commit 在 freebsd-src 中直至 **2021 年 7 月 20 日** 才再次出现（且为 Cosimo Cecchi 与 Yann Kerherve 两位非桥梁型贡献者，6 条 commit 集中在 2021-2024 年，与本期的 2011-2015 年窗口不重叠）。

- 查证来源：freebsd.duckdb 数据库（**c:\Users\ykla\Documents\LibreBSD\原材料\研究\bsd 仓库分析\freebsd.duckdb**）查询 1 结果——freebsd-src 仓库中 2011-2015 年间 committer_email 或 author_email 含 theraven@ 的 commit 共 149 条（其中 message_subject 含 Apple/Darwin/xlocale/libc++/llvm-gcc 等关键词的 commit 37 条），含 pfg@ 的 commit 共 932 条（其中 Apple 相关 21 条），合计 58 条 Apple 相关 commit；查询 2-3 结果——author_email 含 apple.com 的 commit 仅 6 条，时间为 2021-07-20 至 2024-06-06，不在 2011-2015 年窗口内。
- 交叉验证方法：以 darwin.duckdb 的 commit 元数据（author、author_email、author_date、message_subject、repo_name）为量化依据，与 Apple OSS Distributions（**<https://github.com/apple-oss-distributions>**）公开仓库列表、Darwin 源码仓库（** <https://opensource.apple.com/releases/**>）的 CREDITS 文件交叉比对，确认桥梁贡献者数量与子系统分布。
- 存疑判定依据：darwin.duckdb 不含 Darwin 仓库，Apple 实际从 FreeBSD 吸收的代码量无法从数据库直接统计；“子系统错位”判断基于 Darwin 源码的 CREDITS 文件与 commit 主题文本，未逐行比对代码，故“错位”判断是“可观察层面的错位”而非“精确总量层面的错位” ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。
**史观**：总纲第 10 条——动手者创造历史。David Chisnall 与 Pedro F. Giffuni 是 2011-2015 年间 FreeBSD 与 Apple 之间真正的“动手者”——他们的 commit 是可验证的代码事实，而非旁观评论。此即项目史观总纲第十章“动手者创造历史”的具体显现：桥梁贡献的稀疏不否定其作为“动手者”的地位，反而凸显在 Apple 商业体量与 FreeBSD 社区体量之间，真正动手跨越两端的人寥若晨星。

**辨析**：批评层的量化依据须明确数据库覆盖盲区——freebsd.duckdb 仅含 freebsd-src 等仓库的 commit，不含 Darwin/XNU 仓库的 commit，故“桥梁贡献稀疏”是“FreeBSD 端可观察的稀疏”，非“Apple 端实际回馈的稀疏”。Apple 可能在 Darwin 仓库中接受了 FreeBSD 提交者的 pull request，但此部分不在 freebsd.duckdb 覆盖范围内。采信“2011-2015 年间 FreeBSD 端可观察的桥梁贡献稀疏，Apple 端的实际回馈量须另行考据”的判断。
