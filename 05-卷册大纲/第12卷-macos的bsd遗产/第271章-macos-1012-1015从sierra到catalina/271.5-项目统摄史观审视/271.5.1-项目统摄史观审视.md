# 271.5.1 项目统摄史观审视

本节从项目史观总纲第 5、8、11、19 条切入（依 spec 要求从总纲第 5、8、11、13、19、21 条中选 4 条），审视 2016-2019 年间 Apple 与 FreeBSD 代码交流的哲学意涵。

**总纲第 5 条——没有必然性，只有偶然性**。2016-2019 年间 Apple 与 FreeBSD 代码交流的“零回馈”状态，是偶然的而非必然的。darwin.duckdb 显示，apple.com 邮箱的 commit 在 2016-2019 年间为零，而 2021-2024 年间出现了 6 条（由 Cosimo Cecchi 与 Yann Kerherve 两位非桥梁型贡献者提交）——此时间分布表明，“零回馈”并非 Apple 的固有政策，而是 2016-2019 年间 Apple 工程资源分配（APFS 自研、64 位纯净化、Catalina shell 切换）与 FreeBSD 社区需求之间的偶然错位。项目史观总纲第五章“没有必然性，只有偶然性”在此显现：若 Apple 在 2016-2019 年间有员工（如 Jordan Hubbard 早期在 Apple 的角色）以个人时间向 FreeBSD 提交，“零回馈”状态可能被打破；反之，若 2021-2024 年间的 6 条 commit 未发生，“零回馈”状态可能延续至今。桥梁贡献者的出现与消失皆不可被预测，亦不可被制度化为“Apple-FreeBSD 回馈计划”。替代品的无限性不能否定事物的独特价值——2016-2019 年间的“零回馈”是偶然性在代码交流中的具体显现；任何要求“制度化回馈”的呼吁，皆忽视了偶然性是历史根本动力这一哲学事实。史家须承认：“零回馈”不是制度失败，而是偶然性在 2016-2019 年间的具体显现。

**总纲第 8 条——本体论上各方平等**。Apple 作为商业实体与 FreeBSD 作为非营利社区，在本体论上地位相等——差异仅是一刻状态的不同。2016-2019 年间的“零回馈”状态，揭示了本体论平等在代码交流中的具体显现：Apple 选择自研闭源 APFS（商品化路径），FreeBSD 选择开源 ZFS（非商品化路径），二者皆是“文件系统”作为本体的不同形态，不因 Apple 的商业属性或 FreeBSD 的非营利属性而有本体论上的高下。项目史观总纲第八章“本体论上各方平等”在此显现：macOS 与 FreeBSD 在本体论上地位相等，差异仅是商品化程度的不同——macOS 是 BSD 代码的商品化形态，FreeBSD 是 BSD 代码的非商品化形态，二者同源于 BSD 代码本体。史家不应将 Apple 描绘为“剥削者”或 FreeBSD 描绘为“受害者”——此等叙事预设了本体论上的不平等，违反第 8 条。“零回馈”的事实须被承认，但其哲学意涵是“本体论平等下的形式主义分叉”，而非“本体论不平等下的剥削关系”。APFS 与 ZFS 的分叉是本体论平等的具体显现——二者皆是文件系统的不同形态，差异仅是商品化程度与设计目标的不同。

**总纲第 11 条——商品是形式主义**。2016-2019 年间的“零回馈”状态，本质是同一 BSD 代码在“商品化”与“非商品化”两端的分流。Apple 将 BSD 代码吸收进 Darwin，再以 macOS 商业发行的形式商品化——此即项目史观总纲第八章所述“商品本身是一种形式主义，不是人们在追求商品，而是商品在召唤人们”。macOS 作为商品获得了市场主导权，FreeBSD 作为非商品在桌面市场被边缘化，此非技术优劣的反映而是“劣币驱逐良币”的显现——“占据主流的未必是设计最优的，而往往是营销最成功的、时机最恰当的”。BSD 许可证“允许不回馈”的设计，在商品形式主义下演化为商业公司可汲取非营利社区代码而无需对等回馈的结构性通道——2016-2019 年间的“零回馈”正是此结构性通道的具体显现。APFS 自研是商品形式主义在文件系统层面的极端显现——Apple 不采用开源 ZFS 而选择自研闭源 APFS，因商品化 macOS 须将文件系统作为核心组件控制，此控制逻辑与开源共享逻辑在形式主义层面已分叉。然而，项目统摄史观不预设此“零回馈”为恶——BSDL 的选择承认人类的有限性，“允许不回馈”是消极自由的底线，其代价是“零回馈”。史家的职责不是裁决 Apple 是否“应该”回馈 FreeBSD，而是揭示商品形式主义下权力运作的真实结构——“零回馈”是此结构的必然结果，而非偶然失误。

**总纲第 19 条——解释学循环是历史认识的根本条件**。2016-2019 年间 Apple 与 FreeBSD 代码交流的叙事本身陷入解释学循环——Apple 阵营与 BSD 阵营对“同一组事实”的前理解截然不同。Apple 阵营的前理解是“许可证即契约，零回馈是契约的极端但合法的结果”，BSD 阵营的前理解是“许可证允许不等于社区利益所宜，零回馈是利益分配失衡”。此即项目史观总纲第十九章所述“我们往往预设了读者与作者享有相同的前理解与前意识，因此随着讨论深入，分歧只会越来越多”。更深层的是权力与知识的共谋——“什么是重要的历史事件，什么被记录，什么被遗忘，什么被视为错误，什么被视为进步，这些判断背后都有权力的运作”。freebsd.duckdb 记录了 freebsd-src 中 2016-2019 年间的“零 apple.com 邮箱 commit”，但未记录 Apple 在 Darwin 仓库中的内部开发——什么被记录、什么不被记录，本身即权力行使。APFS 自研的高可见度（因 Apple Developer Documentation 公开）与 Apple 从 FreeBSD 吸收代码的低可见度（因 Darwin 仓库不在 freebsd.duckdb 中）形成对比——此即“权力与知识在历史书写中共谋”在代码交流叙事中的显现。史家须自反地承认：本节对“零回馈”的书写本身亦是形式主义化的非存在，前理解的差异使分歧不可避免，唯有坦承此局限方能打开裂缝。
