# 250.2 Apple 向 FreeBSD 回馈的代码（2000-2026）

## 250.2.1 libdispatch 与工具回馈
  - 要点：Apple 以 **Apache 2.0 许可证** 开源 libdispatch（Grand Central Dispatch 核心），FreeBSD 将其移植至用户态线程池库。freebsd.db 查询 freebsd-src 仓库中 message_subject 含 “libdispatch” 的 commit 未返回直接结果（查询 4 返回的 20 条 commit 多为 `.gcda` 文件依赖关系，非 Grand Central Dispatch），说明 libdispatch 的移植可能记录在 freebsd-ports 仓库或以其他关键词提交——此即 “数据库无对应记录时须叠加联网核查” 的实例【2026-07-30 联网核查：穷尽检索 GitHub `github.com/freebsd/freebsd-ports` commits 搜索（需登录）与 FreshPorts `freshports.org/devel/libdispatch` 维护者记录，Marcus von Appen 在 freebsd-ports 仓库移植 libdispatch 的具体 commit hash 与日期无法从公开 GitHub 搜索直接获取；freebsd-ports 仓库历史经 git 迁移后部分早期 commit 元数据缺失，FreshPorts 维护者记录未公开历史 commit hash。依据 0 信任原则 + 严禁臆造约束，本子节不予著录 Marcus von Appen 的具体 commit hash 与 freebsd-ports libdispatch port 维护者记录 URL，待后续以 freebsd-ports 仓库 git log 命令行或 FreshPorts 历史记录核验后补全——详 `03-原始史料库/06-考据记录/20260730_jianyi缺口补全考据.md` §9y】。**Pedro F.   > Apple 选择以 Apache 2.0（而非 APSL）开源 libdispatch，使 FreeBSD 可无障碍移植——同一 Apple 的代码，APSL 许可的部分难以回馈 FreeBSD，Apache 2.0 许可的部分可无障碍移植。
  - 史料：darwin.db 查询 1 结果（Pedro F. Giffuni 的 6 条 Apple 来源 commit，2012-2014 年）；darwin.db 查询 4 结果（libdispatch/GCD 关键词查询，20 条 commit 均非 Grand Central Dispatch 而是 .gcda 文件）；Apple libdispatch 开源仓库（<https://github.com/apple/swift-corelibs-libdispatch>，Apache 2.0 许可证）；LLVM 项目文档（<https://llvm.org/>）。
  - 史观：总纲第 24 条——许可证哲学。Apple 选择以 Apache 2.0（而非 APSL）开源 libdispatch，使 FreeBSD 可无障碍移植——此即 q.md “自由的张力” 的具体显现：APSL 的 “有限消极自由” 使 Darwin 代码难以被 FreeBSD 直接回馈，而 Apache 2.0 的 “完全消极自由” 使 libdispatch 的双向流动成为可能。许可证选择直接决定代码能否双向流动。
  - 辨析：Clang/LLVM 的归因存在混淆——Clang/LLVM 是 LLVM 项目（UIUC 许可证，后改为 Apache 2.0 with LLVM exceptions）的成果，Apple 是主要赞助者而非唯一作者。FreeBSD 10.0（2014 年 1 月 20 日发布）起默认使用 Clang 替代 GCC，此决策的背景是 GCC GPLv3 与 FreeBSD 的 BSDL 不兼容——Apple 对 Clang/LLVM 的大规模投入间接惠及 FreeBSD，但 FreeBSD 受益属 “许可证兼容” 的间接路径而非 “Apple 直接回馈”。
