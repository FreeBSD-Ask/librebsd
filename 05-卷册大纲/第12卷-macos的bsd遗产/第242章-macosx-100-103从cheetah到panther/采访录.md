### Mac OS X 早期发布时期（2001-2003 时期当事人）

#### 采访 1：史蒂夫·乔布斯（Steven Paul Jobs）

- 采访者：Apple 开发者关系团队（Apple WWDC 2001 主题演讲）
- 采访时间：2001-05-21（WWDC 2001 召开时间）
- 采访形式：会议主题演讲（WWDC 2001 录像）
- 原始来源：Apple WWDC 2001 Keynote, Steve Jobs。Apple 官方录像存档 **<https://developer.apple.com/videos/wwdc2001/>** （Apple Developer 官方存档，访问日期 2026-07-24）

**字段 2 采访摘要**

乔布斯在 WWDC 2001 主题演讲中正式发布 Mac OS X 10.0 Cheetah（2001-03-24 零售发布后的首次 WWDC），阐述 Mac OS X 的 BSD 子系统如何为 Mac 平台带来 Unix 级别的稳定性与开发者熟悉度。乔布斯演示 Mac OS X 的 Terminal 应用与 BSD 命令行，强调开发者可直接使用 BSD 工具链在 Mac 上工作。此演讲标志着 Mac OS X 的 BSD 遗产从工程内部走向公开开发者社区。

**字段 3 考据脚注**

本则来自 Apple WWDC 2001 主题演讲录像，Apple Developer 官方存档。乔布斯关于 Mac OS X 10.0 BSD 子系统的陈述，经 Apple 2001-03-24 Mac OS X 10.0 新闻稿与 Singh《Mac OS X Internals》（2006）第 1 章对 XNU BSD 层的描述交叉验证。自利偏差审查：乔布斯作为 Apple 首席执行官，其对 Mac OS X 稳定性的陈述带有 Apple 官方立场，正文引用时另以 10.0 发布初期性能问题的用户反馈加以对照。完整考据过程另见考据记录文件 20260724_jobs-wwdc-2001-keynote.md（2026-09-12 整改：原“原材料/”路径不存在，文件经全库检索未落盘，断链移除改述留痕）。

- 为子节 110.3.1（旧节号，映射现 242.3.x，10.2 Jaguar 的 BSD 层更新与 FreeBSD 4.x 同步）提供 BSD 工具链在 Mac 平台公开化的口述溯源

**字段 5 史观映射**

- 总纲 10“动手者创造历史”：乔布斯在 WWDC 2001 公开演示 BSD 命令行，展现了“动手者”如何将 Unix 遗产从工程内部推向公开市场。据第 14 章 14.2 节原文“真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者”，乔布斯亲自演示 Terminal 应用与 BSD 工具链是“动手去做”的实践。但需自反地看待：乔布斯作为 Apple 首席执行官的商业立场（字段 3 已审查）使其对 Mac OS X 稳定性的陈述带有 Apple 官方立场，“动手者”不可等同于“商业领袖”——10.0 发布初期性能问题的用户反馈（字段 3 已审查）正是对此陈述的自反性校正。
- 总纲 4“分离聚合是永恒规律”：Mac OS X 的 BSD 子系统是 UNIX/BSD 分合循环的显现——BSD 从伯克利分离，经 NeXTSTEP 聚合入 Apple，再于 Mac OS X 中重新呈现为桌面 Unix。据第 25 章总纲 4 原文“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”，Mac OS X 10.0 的 BSD 子系统非乔布斯个人创造，而是 BSD 分合循环在 Apple 商业语境中的具体显现。
- 总纲 9“经验优先”：乔布斯公开演示 BSD 命令行而非套用复杂框架，体现了“经验优先”的认识论模式。据第 25 章总纲 9 原文“优先呈现质朴的事实与当事人的直接经验，而非套用复杂框架”，WWDC 2001 演讲中的 Terminal 演示优先于抽象的稳定性指标陈述——但乔布斯作为 Apple 首席执行官的立场使其演示带有营销姿态，并非纯粹的“质朴事实”。
- 总纲 3“不存在进步，只有权力再分配”：BSD 从服务器走向桌面不是“进步”，而是权力再分配。据第 25 章总纲 3 原文“技术演进不是从低级到高级的进步，而是形式主义的诡异曲线。思想亦不随技术进步”，Mac OS X 将 BSD 带入桌面市场并非“BSD 的胜利”，而是 Unix 桌面化的形式主义化呈现——但需注意项目统摄史观批评的是“进步史观”这一形式主义，而非否定 Mac OS X 的工程成就本身。
- 总纲 22“知识注定过时”：Mac OS X 10.0 的 BSD 子系统至 2024 年已大幅演化。据第 25 章总纲 22 原文“今天书写的技术史，可能在出版之日就已过时。技术债务是历史遗产”，2001 年的 BSD 子系统状态至 2024 年已过时，但其分层思想以演化形式保存于现代 macOS——过时的是知识的特定形式主义化形态，而非 BSD 子系统本身。

**字段 5 史观映射**

- 总纲 10“动手者创造历史”：Hubbard 亲自协调 Apple 工程师与 FreeBSD 项目的代码双向流动是“动手去做”的实践（2026-09-12 整改：原条引文残片“Hubbard 作为 FreeBSD 相关记录（详情见存疑库）无论什么时候街道总是需要人去扫””系粘贴损坏、出处不明，删除留痕——批次 C225 问题 2/6）。但需自反地看待：Hubbard 作为 Apple BSD 团队负责人的立场（字段 3 已审查）使其对 Apple-FreeBSD 代码流动的陈述带有 Apple 雇员立场，“动手者”不可等同于“商业公司桥梁”——Hubbard 既是 FreeBSD 创始人也是 Apple 雇员，此辩证性需保留，不可作二元化简化。

- 总纲 4“分离聚合是永恒规律”：Apple 与 FreeBSD 的代码同步是分离聚合的显现——FreeBSD 5.x 的 VFS 改进与网络栈更新分离至 Darwin，Darwin 的改进又回流至 FreeBSD 上游。据第 25 章总纲 4 原文“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”，Apple-FreeBSD 的代码分合循环是 BSD 史根本结构在商业公司层面的具体显现——此分合非 Hubbard 个人意志所能左右，而是分离聚合规律的显现。
- 总纲 8“本体论上各方平等”：Apple 工程师与 FreeBSD committer 在代码贡献上本体平等——Apple 工程师通过 FreeBSD committer 身份直接提交补丁，二者在本体论上无主次之分。据第 25 章总纲 8 原文“FreeBSD、OpenBSD、NetBSD、DragonFly BSD 在本体论上地位相等，差异仅是一刻状态的不同。文档与代码本体平等”（原文如此：“一刻”系总纲原文用语——2026-09-12 整改注），Apple 工程师与 FreeBSD committer 的关系亦应作此本体论平等的看待——Apple 工程师以 committer 身份直接提交补丁，恰是这一本体论平等的工程化显现。
- 总纲 6“和解优于斗争”：Apple-FreeBSD 代码同步既非（2026-09-12 整改：原条引文残片“相关记录（详情见存疑库）唯一的事情只有和解与接纳，与自己和解，与自己接纳””系粘贴损坏、出处不明，删除留痕——批次 C225 问题 2） Apple 对 FreeBSD 的对抗（封闭代码），也非 Apple 对 FreeBSD 的投降（放弃商业控制），而是 Apple 商业主体性与 FreeBSD 开源主体性的和解——但需辨析：此“和解”是项目统摄史观意义上事物完整呈现的具体时点状态（2026-09-12 整改：原“事物真正完整的一刻”按禁用名称纪律中性化——批次 C225 问题 1），不可简化为“代码同步策略”这一形式主义化的描述。

- 总纲 2“历史是形式主义化的非存在”：代码同步的“理想形式”在工程实践中部分消解。据第 25 章总纲 2 原文“历史是形式主义化的非存在。本书所写皆是当下主体的重构，从不宣称呈现历史本身”，Apple-FreeBSD 代码同步的“理想形式”（完整双向流动）在工程实践中受制于资源、优先级、许可证等具体因素而部分消解——但需辨析：项目统摄史观批评的是“形式主义”而非“工程妥协”，工程妥协本身是动手者的具体实践。
- 总纲 9“经验优先”：Apple 工程师通过 FreeBSD committer 身份直接提交补丁的工程经验，优先于抽象的“开源协作框架”。据第 25 章总纲 9 原文“优先呈现质朴的事实与当事人的直接经验，而非套用复杂框架”，Hubbard 采访中详述的“committer 身份直接提交补丁”机制是当事人直接工程经验的一手陈述，优先于后世综述的二次重构——但 Hubbard 作为 Apple 雇员的立场使其陈述带有项目自利倾向，并非纯粹的“质朴事实”。
