# 242.6 macOS lsof 作为 fstat 的标准替代（跨 BSD/UNIX/macOS 扩展）

## 242.6.1 lsof 移植与 BSD fstat 的缺席

**要点**：macOS 自 Mac OS X 10.0（**2001-03-24**）起移植 lsof 作为 **fstat(1)** 的标准替代——macOS 无 BSD 谱系的 fstat(1) 命令，Apple 选择移植 Vic Abell 的 lsof 以提供打开文件列表功能。lsof 在 macOS 中保留至今，man page 见 developer.apple.com。此选择反映 macOS 的 BSD 层与 BSD 谱系的细微分叉——macOS 保留了大量 BSD 工具但放弃了 fstat(1)。

**史料**：Apple Developer. *Mac OS X 10.0 Release Notes*；**lsof(8)** man page（developer.apple.com）；Darwin 源码仓库 opensource.apple.com；Singh, A. (2006). *Mac OS X Internals: A Systems Approach*. Addison-Wesley.〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：源头时刻：macOS 选择 lsof 而非移植 BSD fstat 是 Apple 工程师的工程判断；总纲第 4 条——分离聚合是永恒规律：lsof 在 Darwin 中聚合为标准工具，是 BSD 与 Linux 工具链的聚合时刻；技术选择的代价：macOS 选择 lsof 付出与 BSD 谱系工具链分叉的代价，但获得跨平台兼容性；总纲第 7 条——技术选择即政治选择：macOS 选择 lsof 反映其“实用优先”的技术政治选择，与 BSD 谱系的“传统保留”形成对照；总纲第 10 条——边缘者贡献：Abell 的 lsof 工作在 macOS 中延续，但其在 Apple 主线叙事中被遮蔽；自反性声明：本释读不预设“macOS 中心论”——lsof 在 Linux 与 macOS 均有移植，BSD 谱系保留 fstat，本节仅释读 macOS 一支。

**辨析**：macOS lsof 与 BSD fstat 的关键差异——前者基于遍历内核数据结构，后者基于 kvm(3)；macOS 选择 lsof 而非 fstat 的原因可能是 lsof 已成熟且跨平台，移植成本低。

**文献**：Apple Inc. *Mac OS X 10.0 Release Notes*[EB/OL]. (2001-03-24). Apple Developer; Apple Inc. *lsof(8) Manual Page*[EB/OL]. <https://developer.apple.com/>; Singh, A. (2006). *Mac OS X Internals: A Systems Approach*. Addison-Wesley.
