# 242.7 macOS CoreAudio 的引入（跨 BSD/UNIX/macOS 扩展）

## 242.7.1 CoreAudio 作为 Apple 自研音频框架

**要点**：macOS 自 Mac OS X 10.0（**2001-03-24**）起内置 CoreAudio 框架——这是 Apple 自研音频框架，与 BSD/Linux 音频栈无源码关系。CoreAudio 提供低延迟音频处理、MIDI 支持、音频设备管理等，基于 Darwin 音频栈与 HALAudio（Hardware Abstraction Layer）。Apple 在 Mac OS X 10.3 Panther（**2003-10-24**）扩展了 CoreAudio，引入 CoreAudio2 接口。

**史料**：Apple Developer. *Mac OS X 10.0 Release Notes*；CoreAudio.framework 文档（developer.apple.com/documentation/coreaudio）；Darwin 源码仓库 opensource.apple.com；Singh, A. (2006). *Mac OS X Internals: A Systems Approach*. Addison-Wesley.〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 1 条——源头时刻：CoreAudio 是 Apple 工程师面对 Mac 音频需求的工程洞察，与 BSD/Linux 音频栈独立演化；总纲第 2 条——分离与聚合：CoreAudio 在 Darwin 中聚合为标准框架，是 Apple 音频生态的聚合时刻；总纲第 6 条——技术选择的代价：macOS 选择 CoreAudio 而非移植 BSD audio(4)，付出独立维护代价，但获得低延迟音频处理能力；总纲第 7 条——技术选择即政治选择：macOS 选择 CoreAudio 反映其“Apple 生态优先”的技术政治选择，与 BSD/Linux 的“开源音频栈”形成对照；总纲第 10 条——边缘者贡献：CoreAudio 的开发者被遮蔽，仅保留“Apple Computer, Inc.”集体署名；自反性声明：本释读不预设“macOS 中心论”——CoreAudio 是 Apple 独立演化，BSD/Linux 有各自的开源音频栈。

**辨析**：CoreAudio 与 BSD/Linux 音频栈的关键差异——前者提供低延迟音频处理（专业音频制作场景），后者提供基本音频接口；CoreAudio 与 Apple 硬件深度集成；macOS 用户无法直接访问 CoreAudio 内部实现。

**文献**：Apple Inc. *Mac OS X 10.0 Release Notes*[EB/OL]. (2001-03-24). Apple Developer; Apple Inc. *CoreAudio.framework Documentation*[EB/OL]. <https://developer.apple.com/documentation/coreaudio>; Singh, A. (2006). *Mac OS X Internals: A Systems Approach*. Addison-Wesley.
