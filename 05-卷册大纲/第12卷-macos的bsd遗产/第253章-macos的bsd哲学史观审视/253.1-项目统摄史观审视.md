##### 253.1.1 专题语审视（专题语不设条号）：道与术的辩证

- **要点**：macOS BSD 哲学文化影响在“道与术的辩证”专题语（不设条号）下显现为“道”与“术”的剥离与重构。BSD 工具链（`bash`、`grep`、`awk`、`sed`、OpenSSH）作为“术”（工程实践）经 Apple 品牌叙事包装为“macOS 的 Unix 体验”（追认为“道”），此即 q.md“道与术的辩证”中“术被包装为道时，道本身即形式主义化的非存在”的具体显现。Apple 的“道”（用户体验、品牌叙事、生态闭环）与 BSD 的“道”（工具组合、Unix 原则、源代码自由）是两种不同的形式主义化路径——Apple 的“道”以 APSL 通报义务为“非存在”，BSD 的“道”以缺乏商业投入为“非存在”，二者各有其形式主义化的具体显现。Homebrew 的 `Formula`（“术”）借鉴 FreeBSD Ports 的 `Makefile`（“术”）但以 Ruby 重写并耦合至 Apple 品牌叙事（“道”），此即“术”被剥离原“道”并重新包装为新“道”的过程。launchd 的服务管理（“术”）继承 BSD init 的职能但以 XML 属性列表（新“术”）取代 shell 脚本（原“道”），此即“道”被剥离“术”并重构为新“道”的过程。

##### 253.1.2 专题语审视（专题语不设条号）：自由的张力

- **要点**：macOS BSD 哲学文化影响在“自由的张力”专题语（不设条号）下显现为“消极自由”与“积极自由”的工程化对立。BSD 许可证的“消极自由”（不强制回馈、不强制开源）被 Apple 以 APSL 2.0 转化为“有限消极自由”（允许派生但须通报与 Apple 保留终止权），此转化即 q.md“自由的张力”中“谁给你定义自由，谁就是想限制你的自由”的具体显现——Apple 以“开放核心”定义了 Darwin 的“自由”边界，此边界即形式主义化的非存在。BSD 阵营的“完全消极自由”与 Apple 的“有限消极自由”是两种自由的形式主义化路径——BSD 的“自由”以缺乏商业投入为“非存在”，Apple 的“自由”以 APSL 通报义务与终止权为“非存在”，二者各有其形式主义化的具体显现。GPL 的“积极自由”（强制回馈）是第三种路径，但在 macOS 语境中 GPL 不直接介入（Darwin 主体为 APSL），故 macOS 与 FreeBSD 的自由张力是“消极自由”内部的张力（完全消极 vs 有限消极），而非“消极自由与积极自由”的外部张力。

- **要点**：macOS BSD 哲学文化影响在“差异即真实存在”专题语（不设条号）下显现为“合法与合宜差异”、“工程传承与哲学传承差异”、“完全消极自由与有限消极自由差异”三重差异的并存。第一为 **“合法与合宜差异”**——Apple 以 APSL 派生 BSD 代码在法律层面合法（BSD 许可证允许派生后以任何许可证再发布），但在合宜层面（APSL 派生是否在哲学层面对 BSD 传承负责）存在争议，此差异即 q.md“差异即真实存在”的具体显现——合法与合宜的差异不可被 Apple 的“合法即合宜”回应所遮蔽。第二为 **“工程传承与哲学传承差异”**——macOS 与 FreeBSD 在工程层面有传承（Darwin 用户态源自 FreeBSD），但在哲学层面无传承（Apple 的“道”与 BSD 的“道”无交集），此差异即形式主义化重构与哲学传承的二分。第三为 **“完全消极自由与有限消极自由差异”**——BSD 的“完全消极自由”与 Apple 的“有限消极自由”在许可证层面有本质差异（前者无通报义务与终止权，后者皆有），此差异即“消极自由”内部的张力。

##### 253.1.5 从总纲第 13 条审视：许可证哲学（法律与道德是利益分配）

##### 253.1.6 从总纲第 19 条审视：解释学循环与权力知识共谋

##### 253.1.7 从总纲第 21 条审视：革命与改革

- **要点**：macOS BSD 哲学文化影响在项目史观总纲第 21 条“革命与改革是历史方法论的分歧”下显现为“Apple 的改革路径”与“Linux 的革命路径”的方法论对照。项目史观总纲第 21 章明示“Linux 的发展依靠不断的革命与彻底否定，而 BSD 这里只是不断的改革。改革的困难远高于革命，但确实带来了稳定和好处”——macOS 作为 BSD 代码的派生者，其方法论为“改革”而非“革命”：Apple 在 Darwin 中保留 BSD 用户态（`bash`、`grep`、`awk`、`sed`、OpenSSH）的工程基础，以 APSL 2.0 与 XNU 混合内核渐进调适，而非彻底推翻 BSD 代码重写。此改革路径即“破山中贼易，破心中贼难”（项目史观总纲第 21 章）的具体显现——Apple 可在工程层面保留 BSD 代码（破山中贼），但在哲学层面 BSD 阵营对“Apple 是否传承 BSD 哲学”的争议（破心中贼）至今未解。Linux 的革命路径以 GPL 强制回馈与彻底否定旧秩序建立企业制度循环，而 macOS 的改革路径以 APSL 品牌控制与 Apple 生态闭环渐进调适，二者方法论分歧使 macOS 与 Linux 在 Unix 普及路径上分野。Apple 的改革路径亦符合项目史观总纲第 21 章“原型先行与否定之否定”——Apple 以 Darwin 原型（**1999 年 3 月 16 日** 公开）先行迭代，在保留 BSD 代码的基础上逐步混入 **Mach 3.0 微内核** 与 Apple 自研组件（**I/O Kit**、**HFS+**、**APFS**、**Metal**），此即“忒修斯之船式的否定——不敢也不能否定主体自身”。项目史观总纲第 21 章亦指出“Talk is cheap vs Code is cheap”在 AI 时代被反转为“提出一个问题往往比解决一个问题更重要”——此反转在 macOS BSD 争议中显现为：BSD 阵营与 Apple 阵营的“Talk”（哲学论争）已超越“Code”（工程事实）成为争议核心，工程事实（Darwin 用户态源自 FreeBSD）已被双方确认无争议，争议的真正焦点在于“BSD 哲学”的诠释与前理解差异。
