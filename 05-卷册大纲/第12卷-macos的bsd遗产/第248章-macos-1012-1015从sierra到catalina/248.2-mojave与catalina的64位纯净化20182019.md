# 248.2 Mojave 与 Catalina 的 64 位纯净化（2018-2019）

## 248.2.1 Catalina 移除 32 位支持与 BSD 用户空间效应

**要点**：**macOS 10.14 Mojave** 于 **2018 年 9 月 24 日** 发布，首次对 32 位应用发出废弃警告（运行 32 位应用时弹出“该应用需要更新”提示）。**macOS 10.15 Catalina** 于 **2019 年 10 月 7 日** 发布，彻底移除 32 位应用支持——所有应用须为 64 位方可运行。BSD 用户空间全面 64 位化：**Darwin 19.x**（对应 macOS 10.15）的 BSD 用户空间工具（`bash`、`zsh`、`tcsh`、`vi`、`grep`、`awk`、`sed`）均为 64 位二进制。Catalina 还将默认 shell 从 `bash` 改为 **`zsh`**（因 `bash` 4.0+ 采用 **GPLv3**，Apple 不愿采纳 GPLv3，故保留 `bash` 3.2.57 为最后版本并改用 `zsh`）。Catalina 引入 **Sidecar**（iPad 作为 Mac 第二屏幕）、**Voice Control** 等功能，但此等功能在应用层运行，与 BSD 内核关系间接。

  | macOS 版本 | 发布日期 | 32 位支持状态 | 默认 shell | Darwin 版本 |
  | --- | --- | --- | --- | --- |
  | **10.14 Mojave** | 2018-09-24 | 仍支持（首次警告） | `bash` 3.2.57 | Darwin 18.x |
  | **10.15 Catalina** | 2019-10-07 | **彻底移除** | `zsh` | Darwin 19.x |

  | shell 切换要素 | 内容 | 原因 |
  | --- | --- | --- |
  | 旧默认 shell | `bash` 3.2.57 | 最后版本（GPLv2） |
  | 新默认 shell | `zsh` | MIT-like 许可证 |
  | 切换原因 | `bash` 4.0+ 采用 GPLv3 | Apple 不愿采纳 GPLv3 |

  > macOS 10.15 Catalina 于 2019 年 10 月移除 32 位，FreeBSD 15.0（预计 2025 年发布）计划移除 i386 支持——Apple 比 FreeBSD 早约 6 年完成 64 位纯净化，源于 Apple 对硬件的完全控制。
**史料**：Apple Inc. macOS 10.14 Mojave Release Notes [EB/OL]. (2018-09-24). Apple Developer（32 位废弃警告）；Apple Inc. macOS 10.15 Catalina Release Notes [EB/OL]. (2019-10-07). Apple Developer（32 位移除与 `zsh` 默认）；Apple Inc. Apple Developer Documentation: 64-Bit Support [EB/OL]. (2019). Apple Developer（64 位迁移指南）；GNU Project. Bash License Change [EB/OL]. <https://www.gnu.org/software/bash/>（`bash` 4.0 起 GPLv3）。〔L3 官方文档与公告〕

**史观**：总纲第 25 条——终结中的延续。32 位支持的终结是 BSD 层“形式主义化的纯净化”的显现——此即项目史观总纲第二十五章的具体呈现：32 位代码在 macOS 中的终结（Catalina 移除 32 位）未导致 BSD 层的终结，反而使 BSD 用户空间全面 64 位化。q.md“证明世界先于改造世界”在此显现：Apple 改造 macOS（移除 32 位）的前提是“世界”（应用生态）已先于“改造”完成 64 位迁移——若在 2010 年移除 32 位将导致生态崩溃，2019 年移除则因应用生态已基本 64 位化而可行。

**辨析**：macOS 移除 32 位与 FreeBSD 放弃 32 位（i386）的时间线对比——macOS 10.15 Catalina 于 2019 年 10 月移除 32 位，FreeBSD 15.0（预计 2025 年发布）计划移除 i386 支持（2023 年 9 月 FreeBSD 项目公告）。二者均朝 64 位纯净化演进，但 macOS 比 FreeBSD 早约 6 年。此时间差异源于 Apple 对硬件的完全控制（可强制 64 位）与 FreeBSD 对多架构的开放支持（须兼顾嵌入式 32 位设备）。

**文献**：Apple Inc. macOS 10.14 Mojave Release Notes [EB/OL]. (2018-09-24). Apple Developer; Apple Inc. macOS 10.15 Catalina Release Notes [EB/OL]. (2019-10-07). Apple Developer; FreeBSD Project. FreeBSD 15.0 i386 Deprecation Notice [EB/OL]. (2023-09). <https://www.freebsd.org/news/>.

## 248.2.2 外部贡献者与 APSL 2.0 流程

**要点**：此期 Darwin 开源仍经 **APSL 2.0 许可证**（**2003 年 8 月 6 日** 起），独立开发者贡献网络与安全补丁。freebsd.duckdb 查询显示 **2016-2019 年** 间 freebsd-src 仓库中 message_subject 含“From Apple”/“From Darwin”的 commit 数量较低（延续 2010 年后的“低密度回馈”特征），主要涉及 Apple HFS 分区、Apple Mac codec ID 与少量 Apple 开发者工具补丁（**Pedro F. Giffuni** 的 6 条 commit 至 **2014 年** 结束）。此期 FreeBSD 端的 Apple 相关 commit 以硬件支持为主，而非用户空间代码回馈。

  | APSL 2.0 流程要素 | 内容 |
  | --- | --- |
  | 许可证生效日 | 2003-08-06 |
  | 独立开发者贡献类型 | 网络补丁、安全补丁 |
  | Apple 相关 commit 主题 | “From Apple”/“From Darwin” |
  | 主要内容 | Apple HFS 分区、Apple Mac codec ID |
  | Pedro F. Giffuni 贡献 | 6 条 commit（至 2014 年结束） |

  > 2016-2019 年间 FreeBSD 端的 Apple 相关 commit 以硬件支持为主，Apple 向 FreeBSD 回馈用户空间代码为辅——此即“低密度回馈”特征在 Sierra-Catalina 期的延续。
**史料**：freebsd.duckdb 查询结果（freebsd-src 仓库 message_subject 含“From Apple”/“From Darwin”的 commit，2016-2019 年）；Apple Open Source. Darwin Source Releases [EB/OL]. <https://opensource.apple.com/releases/>（xnu-4903 系列对应 macOS 10.15 Catalina）。〔L1 代码/构建产物〕

**史观**：总纲第 10 条——边缘者贡献被中心叙事遮蔽。此期 Apple 对 FreeBSD 的直接代码回馈仍然有限，FreeBSD 端的 Apple 相关 commit 以硬件支持为主——此即 q.md“局外人姿态”的具体显现：FreeBSD 社区为 Apple 硬件提供支持，但此支持不进入 Apple 的“主线叙事”。

**辨析**：2016-2019 年间 Apple 与 FreeBSD 的代码交流是否“双向”——darwin.duckdb 显示 FreeBSD 端的 Apple 相关 commit 以硬件支持为主（FreeBSD→Apple 硬件适配），而 Apple→FreeBSD 的用户空间代码回馈较少。采信“此期代码交流以 FreeBSD 适配 Apple 硬件为主，Apple 向 FreeBSD 回馈用户空间代码为辅”的判断。
