# 268.2.2 4 位全面化与 BSD 用户空间优化

**要点**：Snow Leopard 将默认用户空间改为 **64 位**（在 64 位 Mac 上，`bash`、`zsh`、`tcsh`、`vi`、`grep`、`awk`、`sed` 等 BSD 用户空间工具默认以 64 位二进制运行），但内核仍保持 32 位（64 位内核支持至 **10.6 Snow Leopard Server** 才启用，桌面版至 **10.7 Lion** 才默认 64 位内核）。Snow Leopard 引入 **Grand Central Dispatch（GCD）**、**OpenCL**（GPU 通用计算框架）、**QuickTime X**（基于 AVFoundation 重写）等性能导向功能。BSD 子系统整体性能提升——`malloc`、`mmap`、`fork`、`exec` 等系统调用的性能优化。Snow Leopard 移除 **PowerPC** 支持（仅在 Intel x86_64 与 i386 上运行），此移除是 Darwin 从多架构向 Intel 单一架构收敛的关键一步。

  | Snow Leopard BSD 层特性 | 内容 | 后续状态 |
  | --- | --- | --- |
  | **64 位用户空间默认** | `bash`/`zsh`/`tcsh`/`vi`/`grep` 等默认 64 位 | 至 2024 年仍在 macOS |
  | **64 位内核（Server）** | 仅 Snow Leopard Server 启用 | 桌面至 10.7 Lion 才默认 |
  | **GCD** | 任务队列并发抽象 | 至 2024 年仍在 macOS |
  | **OpenCL** | GPU 通用计算 | 至 2024 年仍在 macOS |
  | **QuickTime X** | 基于 AVFoundation 重写 | 至 2024 年仍在 macOS |
  | **PowerPC 移除** | 仅 Intel x86_64/i386 | 多架构向 Intel 收敛 |

  ~~Snow Leopard 因 “无新功能” 定位而 BSD 层无变化~~，事实上 BSD 层有显著变化：64 位用户空间默认化、GCD 引入、PowerPC 移除、性能优化——此变化在用户可见层面较少但在 BSD 子系统层面变化显著。

**史观**：总纲第 19 条——科学技术历史哲学。Snow Leopard 的 “无新功能” 定位使其 BSD 改进以内核/库层为主——此即项目史观总纲第九章的具体呈现：BSD 子系统的性能优化是 “形式主义化的通信规则” 的优化，不改变用户可见功能但提升底层效率。q.md “快乐的辩护” 在此显现：Apple 投入工程资源优化 BSD 子系统性能，此优化不直接带来新功能但提升整体体验——此即 “快乐的辩护” 中 “不为辩护而辩护，而是因内在价值而延续” 的显现。

**辨析**：Snow Leopard 的 “无新功能” 定位是否意味着 BSD 层无变化——BSD 层在 Snow Leopard 中有显著变化：64 位用户空间默认化、GCD 引入、PowerPC 移除、性能优化。此变化在用户可见层面较少（“无新功能” 指用户可见功能），但在 BSD 子系统层面变化显著。采信 “Snow Leopard 用户可见功能少但 BSD 子系统变化显著” 的判断。
