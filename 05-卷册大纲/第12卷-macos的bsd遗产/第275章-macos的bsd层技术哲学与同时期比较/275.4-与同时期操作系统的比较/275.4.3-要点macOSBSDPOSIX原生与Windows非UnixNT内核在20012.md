# 275.4.3 要点macOSBSDPOSIX原生与Windows非UnixNT内核在20012

**要点**：macOS（BSD/POSIX 原生）与 Windows（非 Unix，NT 内核）在 **2001-2024 年** 间的文化对照呈现“原生 Unix”与“非 Unix 加 Unix 兼容层”两条路径。Windows 在 **2016 年 3 月** 发布 **WSL**（**Windows Subsystem for Linux**），使 **Windows 10** 能运行 Linux 用户态环境——此即 Windows 对“Unix 即默认”趋势的回应。但 macOS 的 BSD 层是内核原生集成，WSL 是用户态兼容层，二者在架构上有本质差异：macOS 的 `bash`、`grep`、`awk` 等工具直接调用 Darwin 内核系统调用，WSL 的相同工具通过 pico 进程桥接至 NT 内核。

  | macOS BSD 层与 Windows WSL 架构对照 | macOS | Windows |
  | --- | --- | --- |
  | 文化路径 | “原生 Unix” | “非 Unix 加 Unix 兼容层” |
  | 内核类型 | Darwin（BSD/POSIX 原生） | NT 内核（非 Unix） |
  | Unix 兼容机制 | BSD 层内核原生集成 | **WSL**（**2016 年 3 月** 发布） |
  | 工具调用方式 | `bash`、`grep`、`awk` 直接调用 Darwin 系统调用 | 通过 pico 进程桥接至 NT 内核 |
  | WSL2 演进（**2023 年**） | — | 已采用完整 Linux 内核（基于 **5.15 版本**） |
  | 月活跃用户（**2023 年**） | — | WSL 超过 **400 万** |

  > WSL 的“Unix 体验”作为形式主义化的非存在获得了真实的使用价值（2023 年 Microsoft 披露 WSL 月活跃用户超过 400 万），但其“非存在”（非原生 Unix）是架构事实——WSL 缩小了 Windows 与 macOS 在 Unix 体验上的差距但未消除架构差异。
**史料**：Microsoft WSL 发布公告（<https://blogs.microsoft.com/blog/2016/03/30/announcing-windows-subsystem-for-linux/>，2016 年 3 月 30 日）；Apple Mac OS X 10.0 发布信息（2001 年 3 月 24 日，Apple 新闻稿存档）；WSL 架构文档（Microsoft Developer Network，<https://learn.microsoft.com/en-us/windows/wsl/>）。〔L3 官方文档与公告〕

**史观**：总纲第 1 条——形式主义即真实存在。Windows 通过 WSL 引入 Unix 兼容层是“形式主义化的误置”的另一形态——WSL 使 Windows 用户获得“类 Unix 体验”但非真正的 Unix 内核，此即项目史观总纲第一章“形式主义即非存在”在操作系统文化中的显现：WSL 的“Unix 体验”作为形式主义化的非存在获得了真实的使用价值（2023 年 Microsoft 披露 WSL 月活跃用户超过 400 万），但其“非存在”（非原生 Unix）是架构事实。

**辨析**：WSL 是否构成对 macOS BSD 层的“替代”——存在两种判断。第一种认为 WSL 使 Windows 用户获得 Unix 环境，削弱了 macOS 的“原生 Unix”竞争优势；第二种认为 WSL 的兼容层架构与 macOS 的原生内核集成在性能与一致性上有本质差异，不构成直接替代。经查证，Microsoft 2023 年 Build 大会披露 WSL2 已采用完整 Linux 内核（基于 5.15 版本），在架构上已从“兼容层”演进为“轻量虚拟机”，但此虚拟机仍非 NT 内核原生——采信“WSL 缩小了 Windows 与 macOS 在 Unix 体验上的差距但未消除架构差异”的判断。

**文献**：Microsoft. Announcing Windows Subsystem for Linux [EB/OL]. (2016-03-30). <https://blogs.microsoft.com/blog/2016/03/30/announcing-windows-subsystem-for-linux/>; Microsoft. WSL Documentation [EB/OL]. <https://learn.microsoft.com/en-us/windows/wsl/>.

**要点**：

- Raymond 的许可证实用主义：他从不是传染性许可的拥趸，使用 GPL 只是随大流，且仅用于几乎无人会重用为库的独立项目；可链接库一律采用 BSD 许可，使开源与闭源、商业与非商业软件皆可使用，不愿以此限制用途；其思想近年演化到认为 GPL 如今可能弊大于利（十年十五年前未必如此）；Linux 及 GPL 软件的商业成功主要来自分布式同行评审效应的力量、与许可证大致正交；公司选择开源许可取决于商业目标——为颠覆市场而追求最大使用量时常选 BSD，为颠覆特定竞争对手则 GPL 可能是更好选择。（BSDTalk EP38，[399.04-498.8]，L1）
- 对商业盟友与受众的判断：IBM、Red Hat、Novell 等大公司是巨大资产——改变世界的基本规则之一是必须拉拢能签大额支票的人，拥有富有盟友的权力与杠杆是好事，因为开发者不能靠电子邮件过活；至于普通计算人群是否理解开源讯息，他承认不知答案：开源知识主要存在于勤于思考的人群中，多数普通用户只是邮件与浏览器使用者、主要对更低价格作出反应，务实的计算观可能继续占上风。（BSDTalk EP38，[682.28-755.46]，L1）
- 语言生态观察：Raymond 现在最偏爱 Python，自认有大量 C 经验但新项目严格回避 C——机器已足够强大，可以把周期挥霍在自动内存管理上，再以 C 的抽象层级写程序已无意义；五年间 Python 大幅扩张、出人意料地把 TCL 逼至灭绝，社区规模与库多样性已可与主流比肩；同时 Ruby 正以当年 Python 式的热情逼近，Python 社区已在回头张望，且 Ruby 的热情同时来自 Web（Rails）与通用语言两个群体。（BSDTalk EP38，[865.42-960.46]，L1）

**史料**：

- 当事人身份与开源运动状态判断：Eric Raymond 以《The Cathedral and the Bazaar》为今所谓开源开发奠定了基本理论与大量宣传，其本人参与开源文化远早于该运动拥有名字与自觉（可上溯至 70 年代末）；他认为 2003 年前后跨越了真正的临界点——分布式同行评审产生更好软件的命题已被广泛接受、反对该模型者转入守势，风险资本家也已习惯资助使用开源的公司、商业上不再怪异；他仍预测市场将走向 95% 开源的均衡，闭源仍有经济生态位但将成为例外而非通例。（BSDTalk EP38，[89.72-196.16]，L1）
- GPSD 项目的许可转向与技术贡献：GPSD 为监视 GPS 设备的服务守护进程，原以 GPL 发布，在开发供客户程序链接的客户端库时由 Raymond 决定移至 BSD 许可——不愿接受 GPL 的传染属性、担心吓退潜在使用者，开发者一致同意；其最重要贡献是 GPS 类型自动识别：热插拔脚本唤醒守护进程、经识别状态机判定所连接设备而免去任何配置，从而掩盖 NMEA 0183 与各厂商怪异二进制协议的差异；项目已用于船导航与高精度农学并移植到 BSD；厂商协议并未标准化甚至倒退（Garmin 宣称将停止支持 NMEA），但识别机制已足以隐藏细节。另其 docwifter 项目将 troff（ms、man 等）旧 UNIX 格式转换为 DocBook XML。（BSDTalk EP38，[203.28-377.84]，L1）

**史观**：

- 总纲4 分离聚合是永恒规律：BSD 与 Linux 社会结构的当事人诊断：Raymond 披露其大部分 UNIX 经验其实来自 BSD（早在 BSD 4.1 时代），自称源自 BSD 地界；转向 Linux 桌面是因为判断 Linux 的“社会机器”拥有巨大优势——Linux 社区的肥沃混沌将不可避免地超越 BSD 地界更受控的开发风格；BSD 社区倾向碎裂而 Linux 社区不然，原因恰是 BSD 引以为傲的单一构建树：不同意发行版政策选择者几乎只能另起炉灶自建发行版，而 Linux 地界耦合松散、用户可在 userland 自由取舍、无须绑定特定发行版工具集；给 BSD 的处方是松开耦合、效仿 Linux 的做法——看上去乱，但运转更好。（BSDTalk EP38，[560.44-682.28]，L1）

**辨析**：

- 可用性失败的历史包袱与新的竞争威胁：开源社区对可用性“做得很糟”，根源是工程传统承自 UNIX 社区，而 UNIX 社区的特征是除用户界面外一切都对；BSD 与 Linux 在复刻原初命令行 UNIX 的目标上其实早已完成，那曾是衡量自身的模型，一旦进入没有现成范本的新领域便出现混乱的界面局面；他因此提出“忘掉 Windows”——纯开源操作系统当下真正的威胁竞争是 Mac OS X：它收编了 UNIX 技术优势与半开源路线的优势，又有漂亮 GUI，开源阵营必须学得更好，否则终将被其夺走午餐；相比之下 OpenSolaris 给他的印象是亦步亦趋，Sun 内部方向反复摇摆，他称等到 Sun 开源 Java 才会有兴趣。（BSDTalk EP38，[755.46-865.42]，L1）
