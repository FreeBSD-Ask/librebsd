# 298.2 GNU 工具链的构建——Emacs、GCC、glibc、bash、coreutils（1985-1991）

#### 要点

1985 年，GNU Emacs 作为 GNU 项目首个生产级软件发布。Emacs 起源于 Stallman 在 MIT AI Lab 维护的 ITS Emacs（1970 年代中期）与后来的 EINE（Emacs ITS Never Expires）、ZWEI（Zwei Was Eine Initially）等 Lisp 机器编辑器；GNU Emacs 用 C 语言实现核心编辑器，用 Emacs Lisp 实现扩展层，这一架构延续至今。GNU Emacs 最初的发布方式是磁带寄送（FSF 向付费订户寄送源代码磁带），用户须自行编译；这一“自由软件但收费分发”的商业模式是 FSF 早期的主要收入来源，与 BSD 的“源代码随许可证分发”模式根本不同。
1987 年，GCC（GNU Compiler Collection）1.0 发布。GCC 起源于 Stallman 自 1985 年开始的 C 编译器项目，旨在替代 AT&T Unix 附带的 cc 编译器与 Berkeley 的 pcc（Portable C Compiler）；GCC 1.0 支持 C 语言，后续版本扩展至 C++（1990 年 g++ 分支）、Objective-C（1992 年）、Fortran（1995 年 g77）、Java（1996 年 gcj）、Ada（2001 年 GNAT）、Go（2015 年 gccgo）等语言。GCC 的 RMS 原始架构在 1990 年代后期由 EGCS（Experimental/Enhanced GNU Compiler System）分支挑战，1999 年 EGCS 合并回 GCC 主线并取代 RMS 原始架构，标志 GCC 治理结构从“Stallman 个人权威”向“贡献者共识”转型。
1988 年，glibc（GNU C Library）启动，由 Roland McGrath 主导；glibc 旨在替代 Linux 早期使用的 Linux libc（基于 BSD libc 演化），1997 年 glibc 2.0 发布后成为 Linux 发行版的主流 libc，但 FreeBSD、OpenBSD、NetBSD 各自维护 BSD libc，不使用 glibc——这是 GNU 与 BSD 在 C 库选择上的根本分歧，亦是“BSD 化”进程的重要议题。
1989 年，Brian Fox 为 FSF 编写 GNU bash（Bourne-Again Shell）1.0 alpha 版本，作为 POSIX shell 标准的实现，替代 AT&T Unix 的 Bourne shell（sh）；bash 1.0 正式版于 1990 年发布，Brian Fox 离开 FSF 后由 Chet Ramey 接手维护至今（2026 年）。bash 与 BSD 的 csh、tcsh、zsh（zsh 不属 GNU 项目）形成 shell 谱系竞争，但 bash 因 Linux 发行版默认 shell 的地位成为最广泛使用的 Unix shell。
1990 年代初，GNU coreutils（当时尚未合并为 coreutils，分别称为 fileutils、sh-utils、textutils）由多个 GNU 开发者贡献，实现 ls、cp、mv、rm、cat、sort、uniq、wc 等 Unix 标准命令的 GNU 版本；2003 年 fileutils、sh-utils、textutils 合并为 coreutils。GNU coreutils 与 BSD coreutils（FreeBSD、OpenBSD、NetBSD 各自维护）在命令选项、行为细节上存在差异（如 ls 的 -f 选项、cp 的 -p 选项），这一差异在跨平台脚本移植中常导致问题，亦是“BSD 化”进程的议题之一。

#### 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 1（形式主义是世界的真实存在）**——据原文第 1 章 1.1-1.2 节：GNU 工具链作为一种形式主义化的建构——Emacs 的“可扩展编辑器”范式、GCC 的“多语言编译器”架构、glibc 的“POSIX C 库”实现、bash 的“Bourne shell 兼容”设计——皆是 GNU 开发者对 Unix 工具的主体性重写，无“客观最优”的“Unix 工具本质”。

**总纲 4（分离聚合是永恒规律）**——据原文第 4 章 4.1 节：GNU 工具链从 Unix 工具的分离（重写而非继承）到与 Linux 内核的聚合形成 GNU/Linux，再到 BSD 化进程中的工具链分离（Clang 替代 GCC、libedit 替代 readline、mandoc 替代 groff）——这一系列分离聚合并非线性进步，而是不同形式主义的循环呈现。

**总纲 5（没有必然性，只有偶然性）**——据原文第 5 章 5.2 节：若 Stallman 未在 1985 年选择 Emacs 作为 GNU 首个产品，若 GCC 未在 1987 年及时发布（Linux 1991 年发布时依赖 GCC 编译），若 EGCS 分支未在 1999 年合并回主线，GNU 工具链史会呈现完全不同的脉络。所谓“GCC 必然主导开源编译器”的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——据原文第 14 章 14.1-14.2 节：Stallman 亲自编写 GNU Emacs 与 GCC 早期版本，Brian Fox 亲自编写 bash，Roland McGrath 亲自编写 glibc，Chet Ramey 亲自维护 bash 三十余年——这些是动手者的实践，而非“FSF 决定”或“开源运动决定”等组织决策的产物。

**总纲 2（历史是形式主义化的非存在）**——据原文第 2 章 2.5 节：所谓“GNU 工具链（1985-1991）”的判定本身即形式主义化的非存在——若以 EGCS 1999 年合并为“GCC 治理现代化”的起点，若以 LLVM 2003 年启动为“编译器谱系分化”的起点，“GNU 工具链史”会呈现完全不同的脉络。本子节选取“1985-1991 年 GNU 工具链构建”为主线，但这一选取本身须以自反性声明显化。

**自反性声明**：本子节选取“Emacs → GCC → glibc → bash → coreutils”为 GNU 工具链主线，但这一选取本身即形式主义化的非存在。若以 GNU binutils（ld、as、ar）为主线，若以 GNU make 为主线，若以 GNU gdb 为主线，“GNU 工具链史”会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

#### 辨析

**GCC 1.0 发布日期辨析**：部分二手资料称“1987 年 GCC 1.0 发布”，但 *gcc.gnu.org* 官方档案明确为 1987 年 3 月 22 日 GCC 1.0 发布；部分资料称“1985 年 GCC 启动”，混淆了 Stallman 1985 年开始 C 编译器项目与 1987 年 GCC 1.0 发布的时间。本子节采用“1985 年启动，1987 年 3 月 22 日 GCC 1.0 发布”的区分性表述。

**EGCS 与 GCC 关系辨析**：部分二手资料称“1999 年 EGCS 取代 GCC”，但准确表述是 1999 年 EGCS 合并回 GCC 主线并取代 RMS 原始架构，GCC 项目名称保留，但治理结构与代码基础来自 EGCS。本子节采用“1999 年 EGCS 合并回 GCC，取代 RMS 原始架构，GCC 项目名称保留”的限定性表述。

**glibc 与 Linux libc 关系辨析**：部分二手资料称“Linux 早期使用 glibc”，但 Linux 早期使用的是 Linux libc（基于 BSD libc 演化），1997 年 glibc 2.0 发布后才逐渐成为 Linux 发行版主流 libc；FreeBSD、OpenBSD、NetBSD 各自维护 BSD libc，从不使用 glibc。本子节采用“Linux 早期使用 Linux libc，1997 年 glibc 2.0 后成为 Linux 主流 libc，BSD 各自维护 BSD libc”的区分性表述。

**bash 与 Bourne shell 关系辨析**：部分二手资料称“bash 是 Bourne shell 的克隆”，但 bash 实际上兼容 Bourne shell 语法并吸收 csh、tcsh、ksh 部分特性（如命令行编辑、历史、别名、作业控制），并非简单克隆。本子节采用“bash 兼容 Bourne shell 并吸收 csh、ksh 特性”的限定性表述。
