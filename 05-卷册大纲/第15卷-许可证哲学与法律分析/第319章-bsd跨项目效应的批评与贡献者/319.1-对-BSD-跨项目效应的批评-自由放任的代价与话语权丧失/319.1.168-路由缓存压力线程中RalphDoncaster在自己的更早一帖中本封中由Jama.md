# 319.1.168 路由缓存压力线程中RalphDoncaster在自己的更早一帖中本封中由Jama

2003-06-10 路由缓存压力线程中，Ralph Doncaster 在自己的更早一帖中（本封中由 Jamal Hadi 转贴）指出 Linux 缺少类似 BSD 的参数来控制用户态与内核态 CPU 份额，并述其 CPU 负载达 70–80% 时宁可丢包也不愿让 BGP 会话中断。本封作者 Ralph Doncaster 的实际内容是：确认环境仍为 Duron 750（Asus/Via 芯片组）、Zebra 0.93b，最近两周两次丢失 BGP 会话；他说明当时 3com 网卡虽被普遍认为选型不佳但已部署，现改购 tg3 与 e1000；其技术同事在 1GHz Celeron + 2 张 e1000 上以 freeBSD/polling 加完整路由表测试，可抗 50kpps synflood，他希望 Linux 也能达到；因此他计划以 1 台 Linux 路由加 1 台 BSD 路由各跑 zebra、经 ibgp 互通并各自向 OSPF 宣告默认路由，即受 DDoS 击倒 Linux 时 BSD 一侧更可能保持在线，若 BSD 性能确实约为 Linux 两倍则宁可整体改用 BSD 路由。
