在 audit 子系统的 contid/capcontid 补丁讨论中，Richard Guy Briggs 提出折中方案："How about making loginuid/contid/capcontid writable only via netlink but still provide the /proc interface for reading? Deprecation of proc can be left as a decision for later."，理由是 sshd/crond/getty 因此不再需要 /proc，而仍需读取该信息的工具仍可读到（系 Briggs 提议在本封中的被引内容）。此前主张直接改用系统调用的是 Steve Grubb，他指出 Eric 的要旨是 /proc 是诸多棘手问题的交汇点，依赖它就无法简化 API 以降低复杂度，且多数程序本就不需要访问 /proc——chroot 囚室通常只需加 /dev/random 或 /dev/null 而几乎从不加 /proc，真正逼你加 /proc 的是 sshd 之类入口守护进程（它需要设置 loginuid），因此迁离 /proc 能简化系统设计（系 Grubb 论述在本封中的更深层被引内容）。Paul Moore 本封对这两条均持反对意见：认为在下一个补丁集中加入任何 loginuid 变更都是错误（即使只是挂在末尾的 RFC），且除 Eric 对容器内 /proc 即将消亡另有惊人表态外，加入 netlink API 同样是错误，主张"保持小而聚焦"。
