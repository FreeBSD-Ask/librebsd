# 293.7 美国加密出口管制对 BSD 代码分发的影响

## 293.7.1 ITAR/EAR 对 FreeBSD crypto 的历史限制

**要点**：1990 年代强加密软件被归类为军火——FreeBSD DES/kerberos 无法含在官方 FTP 镜像中。2000 年 1 月克林顿放宽后解除。

**史料**：FreeBSD crypto 分发历史（1994-2000）; Bernstein v. US 判决 ［A］

**史观**：总纲第 12 条——法律限制对技术分发的塑造。

**辨析**：

**辨析**：加密出口管制对 BSD 代码分发的影响程度在不同来源中存在争议——部分开发者认为管制是 BSD 安全特性滞后的主要原因，但也有观点认为 BSD 社区自身的安全审计文化不足才是更根本的因素。出口管制的法律文本与执行实践之间存在差距，实际影响需结合具体时间段和代码模块分析。
**文献**：FreeBSD crypto 历史； Bernstein 判决 ［A］

**要点**：

- Brent Cook 一手自述其入社路径：1998 年前后在得克萨斯大学以 FreeBSD 1/2 运行 web 服务器约三四年，其后在嵌入式公司用 FreeBSD 制作专用防火墙 appliance；在 Boundary 公司的跨平台 agent 中嵌入 OpenSSL 长期受构建缓慢与 API 混乱之苦，Heartbleed 事件后转向替代方案。他以业余时间搭建自动构建环境测试 LibreSSL portable 版约两个月，期间 Theo de Raadt 主动邮件联系他讨论 PRNG 改动，并邀其赴斯洛文尼亚参加 hackathon，最终成为正式 OpenBSD developer。（BSD Now EP48，[1166.52-1321.73]，L1）
- portable 化工程路径：Cook 模仿 BSD makefiles 建立构建框架，选 autoconf/automake 以覆盖 HP-UX 等长尾平台；最大难点在 PRNG——libBSD 的 arc4random 实现不达 OpenBSD 安全标准，libottery 方案亦被 Theo 否定；最终推动 getentropy(2) 新系统调用进入多个平台，使其他操作系统无需模拟 OpenBSD 的 sysctl 接口，内存分配保护等亦重构为可移植层。初版全用 C 而非汇编，其基准测试显示在 Ubuntu 上 LibreSSL 的 C 版块密码反而比 OpenSSL 快近两倍，引入汇编时将按现代编译器能力批判性评估，不再为旧编译器绕弯。（BSD Now EP48，[1404.57-1675.71]，L1）
- Bob Beck 致节目邮件指出：FreeBSD 内置 arc4random 为陈旧实现（仅依赖 RC4 流程、随机性强度不足），OpenBSD 版本在其移植后已重写且行为不同，故 FreeBSD 目前并非受支持的 LibreSSL 运行平台；Ted Unangst 已提交更新 FreeBSD arc4random 的补丁，当时正由 FreeBSD 安全团队评审，通过后方能正式支持 LibreSSL。　[存疑脚注] 转写存在语音识别误差（如 R4Random、Ted Unanks 等），函数与人名细节以邮件原文为准。（BSD Now EP48，[3346.28-3436.28]，L2）
- pkg 1.3.0 发布：历时九个月、新增约 6.7 万行代码、29 位贡献者；引入真正的 SAT 求解器自动处理 Perl、PHP 等多版本升级冲突，不再需要手工 pkg set -o；引入 Capsicum 沙箱代码使多数操作在受控环境执行；重写安装流程以正确处理 SCHG 系统不可变标志；更细粒度的锁提升并行度；扩大 libUCL 使用并简化 API。7 月 23 日发布 1.3.0 后连发 1.3.1、1.3.2、1.3.3 修复，poudriere 仓库构建亦多核化。（BSD Now EP48，[710.35-834.96]，L2）
- 主持人的 UNIX 起点约在 1996 年：先在 DOS 分区上运行 Minix（记忆最深的是随附的 Asteroids 游戏），继而被赠予 O'Reilly《Running Linux》随书 CD-ROM——内含 Red Hat Linux 2.1 的源码与安装文档，安装过程费力，最终跑起 X 图形环境时令他极为兴奋；更早在大学时代（1980 年代末至 1990 年代初）所用系统已记忆模糊，只记得用 finger 查看其他大学的朋友是否在线、以基础 talk 工具交谈。（BSDTalk EP60，[75.2-156.0]，L1）
- 其可查的最早 BSD 兴趣记录是 1999 年 11 月 3 日发往 FAQ@openbsd.org 的提问邮件，获 OpenBSD 开发者 Eric Jackson（monkey.org）清晰友好的回复，这份回复被他视为鼓励自己继续钻研 BSD 的关键；最早的 OpenBSD 实物为 1999 年 12 月 1 日发布的 2.6 CD 组与原装贴纸；同期他也研究过 FreeBSD（留有 2000 年 2 月的 4.0-RC2 CD），却不记得为何未续用，OpenBSD 反而留存下来。（BSDTalk EP60，[156.0-334.48]，L1）
- OpenBSD 2.6 CD 是一段加密法制史的物证：该版为首个随版附带 OpenSSH 的发行版本；CD 插页仍印有“因专利或其他限制，SSH 与 PGP 等包不能置于 CD-ROM”的旧表述（主持人推测为转用 OpenSSH 后的残留语言），而基于 OpenSSL 的 libssl 与 libcrypto（供 SSH、HTTPD、ISAKMPD 使用）确因专利授权限制不在 CD 上、须另行下载；与 2006 年的美国环境对照，加密管制的松紧变化一目了然。（BSDTalk EP60，[227.28-293.36]，L1）
- 当下的 OpenBSD 使用：公司 Web 服务器运行 OpenBSD，用于托管带内容管理系统的基本站点且要求相当安全；他看中 OpenBSD 的 chroot 特性——Apache 默认已置于 chroot 监牢，几乎无需额外工作即可运行；chroot 对不愿被改造的不兼容应用确会带来额外问题，但整体运行良好。（BSDTalk EP60，[356.66-401.94]，L1）
- spamd 灰名单实战：近期在 OpenBSD 4 上以网桥方式部署 spamd 灰名单（无须改动既有配置），置于公司 Exchange Server 2003 之前——原先内置过滤加 Outlook 的组合占用大量带宽与算力而效果平平；灰名单一周内效果显著，且未遇到邮件列表或外发服务器池从不同 IP 重新入队等常见顾虑；他预告将邀请 spamd 相关开发者上节目。（BSDTalk EP60，[401.94-467.3]，L1）
- 无障碍议题呼吁：主持人公开征集有视觉或其他障碍的 BSD 用户，指出屏幕阅读器、外接盲文终端等无障碍特性在 BSD 生态中少受讨论；他提及 YASR（yet another screen reader）曾可在 FreeBSD 上编译，联系项目后获复“应能编译但未做过测试”；其关切理由包括同事正在使用屏幕阅读器、任何人都可能因事故临时需要无障碍能力、政府合同常对此有硬性要求，以及语音输入输出对未来车载计算等场景的价值。（BSDTalk EP60，[471.0-597.76]，L1）

**史料**：

- 对 OpenSSL 代码库的一手观察：Cook 称其中大量不安全且无人维护的代码，密码学部分呈数学家与博士生风格（A、B、C、D、E、F 式变量命名），静态分析发现大量“遗传性旧代码”——不执行任何功能亦无害。他自述作为美国公民刻意不修改加密算法本体，以免触碰出口管制敏感区，这构成出口管制持续约束开源加密开发行为的一手证词。（BSD Now EP48，[2292.04-2361.23]，L1）
- 该期提供了多件私人收藏的实物史料：1999 年 11 月 3 日 FAQ@openbsd.org 提问邮件及 Eric Jackson 的回复、OpenBSD 2.6 CD 组及其加密限制插页原文、FreeBSD 4.0-RC2 CD（2000 年 2 月）、以及在 SPARCstation IPC 上安装 OpenBSD 的亲历描述（他盛赞该机拆解后的工程紧凑性）。（BSDTalk EP60，[156.0-356.66]，L1）

**史观**：

- 总纲10 动手者创造历史：portable LibreSSL 的发布、测试与集成实际由 Cook（每周约 10 小时的业余投入）与 Bob Beck 两人支撑，改进建议来自 GitHub 议题与各类论坛的散点反馈，Windows 支持长期悬置等待认领者；安全关键基础设施的日常运转依赖少数默默投入的个体，而非有组织的团队。（BSD Now EP48，[1756.61-1830.54]，L1）
- 总纲9 经验优先：可移植性策略的反转：面对 musl libc 提议用条件编译绕过 glibc 保护代码，Cook 拒绝基于运行时检测的变通——不存在安全可靠的方式检测特权环境（进程可能运行在错误内核上）——转而与 musl 开发者合作在上游实现 issetugid 系统调用，结果比任何变通更安全。portable 版不再堆叠兼容层，而是把正确修复推进操作系统与 libc 本体，与 OpenSSL“忍受操作系统所给的一切”的哲学形成对照；其论证是开源项目有能力让正确修复进入上游。（BSD Now EP48，[1892.33-1975.85]，L1）
- 总纲5 没有必然性，只有偶然性：其 BSD 忠诚并非理性比较的产物：手中留有 FreeBSD 4.0 CD 却未续用，OpenBSD 仅因一封开发者友好回复的邮件而“留了下来”——个人技术路径常被微小的偶然事件锁定，而非由功能优劣的决定性比较选定。（BSDTalk EP60，[302.44-334.48]，L1）

**辨析**：

- Linux PRNG 争议事件：ARS Technica 报道 LibreSSL 未检测 PRNG PID 回绕；Cook 证实团队在文章发表前几天已内部讨论该角落案例，文章发表当日清晨补丁即由 Bob Beck 推送。他拒绝阅读网络评论，与 PaX 团队交换加固思路，并指出权衡困境——将 PRNG 页面标记为不可被子进程继承会使直接调用 fork/clone 的进程崩溃，彻底方案可能需要内核协助；在“更安全”与“不破坏既有软件”之间只有细线。这一表述与其安全观互为表里：今天的偏执角落案例就是明天的大规模漏洞。（BSD Now EP48，[2031.90-2160.53]，L1）
