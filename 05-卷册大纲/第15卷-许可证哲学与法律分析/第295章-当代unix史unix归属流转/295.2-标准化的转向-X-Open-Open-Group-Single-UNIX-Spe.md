# 295.2 标准化的转向——X/Open、Open Group、Single UNIX Specification

## 要点

X/Open 公司 1984 年由欧洲主要计算机厂商（Bull、ICL、Siemens、Olivetti、Nixdorf，合称 BISON）发起成立，旨在创建统一 UNIX 标准以打破厂商锁定；1985 年 Philips 与 Ericsson 加入后正式采用 “X/Open” 名称，1987 年注册为 X/Open Company, Ltd.（总部设于英国雷丁 Reading, Berkshire）；1989 年发布 XPG3（X/Open Portability Guide Issue 3，Volume 1-3 于 1989 年由 Prentice Hall 出版，Volume 4-7 于 1988 年出版；分卷出版顺序如此：第四至七卷 1988 年先出，第一至三卷 1989 年后出，非笔误，经 Open Group 源书书目与出版记录复核），1992 年发布 XPG4（以 CAE Specification 形式发布，含 System Interfaces and Headers XSH C202、Commands and Utilities XCU C203、System Interface Definitions XBD C204 三卷），1993 年与 Open Software Foundation（OSF）合并谈判启动，1996 年正式合并为 The Open Group，总部设于英国雷丁（Reading, Berkshire），沿用 X/Open 原址　[存疑脚注] “美国加州雷丁”之说查无出处，已删（美国无“加州雷丁”地名，疑为机器翻译或来源混淆）；The Open Group 合并初期美国办事处所在（波士顿/旧金山等）依二手资料各异，沿革以官方档案为准。
Single UNIX Specification（SUS）演化谱系：SUSv1（UNIX 95，X/Open CAE Specification C706，1995 年发布）、SUSv2（UNIX 98，1997 年发布，新增 Y2K 与 64 位处理）、SUSv3（UNIX 03，2002 年 1 月发布，与 IEEE Std 1003.1-2001 即 POSIX.1-2001 合并，含 4 卷：Base Definitions、System Interfaces、Shell & Utilities、Rationale）、SUSv4（UNIX V7，2008 年发布，与 IEEE Std 1003.1-2008 合并，新增 readdir_r 废弃、strerror_r 修订、Thread-Safe API 调整等）、Open Group UNIX V8（2016 年发布，与 IEEE Std 1003.1-2008 修订版对齐，新增 C11 原子操作、TLS 线程局部存储等）。
2026 年 7 月现状：Open Group UNIX V8 仍为最新正式标准，UNIX V9 制定工作因厂商投入下降与 Linux 主导格局而搁置；通过 UNIX V8 认证的操作系统包括 AIX 7.3、HP-UX 11i v3、Solaris 11.4、z/OS 3.1、macOS（Apple 自 macOS 10.5 Leopard 起持续认证）、华为 EulerOS、Inspur K-UX（中国国产 UNIX 认证代表）。
POSIX 标准与 SUS 关系：POSIX.1-2001 起 POSIX 标准与 Single UNIX Specification 合并为同一文档（IEEE Std 1003.1），由 Austin Common Standards Revision Group（CSRG，与伯克利 CSRG 同名但不同实体）维护；FreeBSD、NetBSD、OpenBSD、Linux（glibc）虽未正式申请 UNIX 商标认证（认证费用高昂），但实质上高度兼容 POSIX.1-2008。

## 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 2（历史是形式主义化的非存在）**——据原文第 1 章 1.1-1.2 节：

> “形式主义是世界的真实存在，其余一切存在皆不真实。”

Single UNIX Specification 作为一种形式主义化的建构——所谓 “UNIX 兼容” 是一组 API、Shell 工具、文件层次、字符编码等标准的集合——并非 “客观 UNIX 本质” 的发现，而是 Austin Group 工程师团队对 UNIX 兼容性的主体性选择。SUSv1 至 UNIX V8 的演化（删除 readdir_r、修订 strerror_r、新增 C11 原子操作等）皆是形式主义化的非存在，每一次修订都是对 “何为 UNIX” 这一问题的重新定义。

**总纲 4（分离聚合是永恒规律）**——据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

X/Open 与 OSF（Open Software Foundation）从分离（1988 年 OSF 由 DEC、IBM、HP 等对抗 AT&T/Sun 的 Open Software Foundation 成立）到聚合（1996 年合并为 Open Group），POSIX 标准与 SUS 从分离（POSIX 由 IEEE 维护、SUS 由 X/Open 维护）到聚合（2001 年 POSIX.1-2001 与 SUSv3 合并为同一文档）——这一系列分离聚合并非线性进步，而是标准化组织在不同历史阶段的主体性选择。

**总纲 3（不存在进步，只有权力再分配）**——据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

UNIX 标准化从厂商俱乐部（X/Open 由欧洲厂商发起、OSF 由美国厂商发起）转向开放标准（Austin Group 由 IEEE、Open Group、ISO/IEC 联合维护），并非 “标准化民主化” 的进步，而是权力再分配——厂商俱乐部模式下 AT&T、IBM、HP、Sun 等大厂主导标准制定，开放标准模式下这些大厂仍通过工程师投入与认证费用主导标准走向，所谓 “开放” 只是形式主义化的转换。

**总纲 5（没有必然性，只有偶然性）**——据 shigang 第八节总纲原文：

> “没有必然性，只有偶然性。”（总纲第 5 条，shigang.md 第八节；第 5 章原文细节引文俟回源补正）

X/Open 1984 年由欧洲厂商发起、OSF 1988 年由美国厂商发起、1996 年两者合并为 Open Group——这些节点皆不可替代的偶然。若 1988 年 OSF 未因对抗 AT&T/Sun 的 Open Look vs Motif 之争而成立，若 1996 年 X/Open 与 OSF 合并谈判失败，当代 UNIX 标准化生态会呈现完全不同的格局。所谓 “UNIX 标准化必然走向开放统一” 的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——据原文第 14 章 14.2 节：

> “真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者。”

Austin Group 工程师（Andrew Josey、Don Cragun、Nick Stoughton 等）亲自起草与修订 SUS 标准文本，glibc、FreeBSD libc、NetBSD libc、musl libc 工程师亲自实现 POSIX API——这些是动手者的实践，而非 “Open Group 决定” 或 “IEEE 决定” 等组织决策的产物。须注意：Open Group 的组织架构是外部条件，但 SUS 标准的具体条款与 API 细节是 Austin Group 工程师的主体性选择。

**自反性声明**：本子节选取 “X/Open → Open Group → Single UNIX Specification 演化” 为 UNIX 标准化主线，但这一选取本身即形式主义化的非存在。若以 Linux 标准基础（LSB，Linux Standard Base）为主线，若以 ISO/IEC 9945（POSIX 国际标准）为主线，若以 GNU C Library（glibc）的实际 API 实现为主线，“UNIX 标准化史” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

## 辨析

**X/Open 与 OSF 合并时间辨析**：部分二手资料称 “X/Open 与 OSF 于 1996 年合并”，但合并实际于 1996 年 2 月宣布，正式法律合并于 1996 年 3 月完成。本子节采用 “1996 年正式合并为 The Open Group” 的月份表述，避免给出未经合并协议核验的精确日。

**SUSv3 与 POSIX.1-2001 关系辨析**：部分二手资料称 “SUSv3 包含 POSIX.1-2001”，部分称 “POSIX.1-2001 等同于 SUSv3”。考据结论：POSIX.1-2001 与 SUSv3 是同一文档（IEEE Std 1003.1-2001）的两个名称，由 Austin Group 联合维护，SUSv3 在 POSIX.1-2001 基础上增加了 XSI（X/Open System Interfaces）扩展选项。本子节采用 “POSIX.1-2001 与 SUSv3 合并为同一文档，SUSv3 含 XSI 扩展” 的限定性表述。

**UNIX V8 与 POSIX.1-2008 关系辨析**：UNIX V8（2016）与 IEEE Std 1003.1-2008（POSIX.1-2008）的关系类似于 SUSv3 与 POSIX.1-2001——同一文档的两个名称，但 UNIX V8 增加了 C11 原子操作、TLS 等扩展。本子节采用此表述。

**macOS UNIX 认证辨析**：Apple 自 macOS 10.5 Leopard（2007 年）起持续通过 UNIX 03（SUSv3）认证，至 macOS 14 Sonoma（2023 年）仍保持认证状态；但 macOS 内核（XNU）混合 Mach 微内核与 BSD 子系统，与 SVR4 内核结构差异显著，认证是基于 API 兼容性而非内核结构。本子节采用 “macOS 通过 UNIX 03 认证（基于 API 兼容性）” 的限定性表述。

**K-UX 与 EulerOS 认证辨析**：Inspur K-UX 3.0 于 2013 年通过 UNIX 03 认证（全球第五款通过 UNIX 03 认证的操作系统，首个中国国产 UNIX 认证），华为 EulerOS 2.0 于 2016 年通过 UNIX 03 认证；二者皆基于 Linux 内核，但通过实现 SUSv3 兼容 API 通过认证。K-UX 3.0 的 Open Group 具体认证编号（brand 编号）与精确认证日期经三次联网核查未获（Open Group 官方注册列表 `https://www.opengroup.org/openbrand/register/xy.htm` 当前已无 K-UX 条目，疑认证已过期或撤销；互联网档案馆存档超时无法访问）。　[存疑脚注] K-UX 3.0 的 Open Group 认证编号（brand 编号）与精确认证日期经多次联网核查未获，官方注册列表已无 K-UX 条目，认证是否过期或撤销待核；互联网档案馆存档超时无法访问，“据一手文献印证消解”原表述与“未获”结论矛盾，现统一为存疑口径，最终结论以官方注册列表恢复可访问后的核验为准。本子节采用 “K-UX 与 EulerOS 基于 Linux 内核通过 UNIX 03 认证” 的限定性表述。
