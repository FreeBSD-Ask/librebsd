# 287.5 BSD 开发者在其他开源项目治理中的角色——标准组织、LLVM、IETF、Apache 等

## 287.5.1 Kirk McKusick 在 POSIX/IEEE 标准化中的角色

**要点**：Marshall Kirk McKusick（CSRG 成员、FreeBSD 核心开发者）于 1986 年至 1998 年间参与 IEEE POSIX 标准化委员会（IEEE POSIX Standardization Committee），历时 12 年（**存疑：其个人履历仅列“IEEE POSIX Standardization Committee (1986-1998)”，未注明具体所属工作组编号，本章“实时扩展与文件系统相关工作组成员”系根据其 FFS 设计者背景推断，须查 IEEE 1003 各工作组正式名单核实**）；McKusick 的标准工作延续 CSRG 时代 BSD 对 POSIX 的塑造（BSD socket API、FFS 等进入 POSIX 标准）；McKusick 同时是 USENIX 协会两任主席（1990-1992、2002-2004）、ACM 与 IEEE 资深会员（IEEE Senior Member），长期在 USENIX、BSDCan 等会议推动 BSD 与标准化对话

**史料**：McKusick 个人主页（mckusick.com/consultancy.html，明确列有“IEEE POSIX Standardization Committee (1986-1998)”）、IEEE 1003 标准工作组名单、POSIX 1003.1 标准文本、USENIX 历年会议议程 ［A］

**史观**：BSD 与 UNIX 谱系的连续性：McKusick 标准工作延续 CSRG 对 POSIX 的塑造；总纲第 10 条——边缘者贡献：McKusick 跨 BSD 与标准化两个领域

**辨析**：McKusick 在 POSIX 委员会的具体工作组编号须查 IEEE 1003 各工作组正式名单——其履历仅列“IEEE POSIX Standardization Committee”而未列具体工作组（如 1003.1、1003.4 等），本章“实时扩展与文件系统相关”为基于其 FFS 设计者背景的合理推断但非确证；POSIX 1003.1 中 BSD 贡献的具体条款须查标准文本；“CSRG 时代 BSD 对 POSIX 的塑造”须查 POSIX 历年版本演化

**文献**：McKusick 个人履历页（mckusick.com/consultancy.html）；IEEE 1003 标准；POSIX 1003.1 文本 ［B］

## 287.5.2 BSD 开发者在 LLVM/Clang 项目中的贡献

**要点**：FreeBSD 项目是 LLVM/Clang 早期主要采用者与贡献者——2012 年 1 月 12 日 FreeBSD 9.0 起 Clang 3.0 作为 amd64 与 i386 的可选编译器随基础系统发布（先前叙事称“2011 年 FreeBSD 9.0 起 Clang 替代 GCC 作为默认编译器”有误，9.0 release notes 与 Roman Divacky 2011 BSD Day 演讲明确 Clang 在 9.0 中仅作可选编译器，能编译 world/kernel 但 GCC 仍为默认），2014 年 1 月 20 日 FreeBSD 10.0 起 Clang 正式替代 GCC 成为 x86 与 ARMv6+ 平台的默认系统编译器〔订正注：原误记 2014-01-31，FreeBSD 10.0-RELEASE 为 2014-01-20〕，libc++ 同步替代 libstdc++ 作为默认 C++ 标准库（参见相关章节）；GCC 在 GPLv3 转换后因下游消费者反对未能进入 FreeBSD 基础系统，长期停留在 4.2.1（最后 GPLv2 版本）；FreeBSD 开发者 Roman Divacky、Brooks Davis、Ed Maste（埃德·马斯特）、David Chisnall（戴维·奇斯纳尔） 等长期贡献 Clang/LLVM 上游；FreeBSD 基金会 曾赞助 LLVM 项目开发（如 ARM64 后端、MIPS 后端），FreeBSD 与 NetBSD 基金会 还联合资助 PathScale 开源 libcxxrt（C++ 运行时）；OpenBSD 与 NetBSD 后续也采用 Clang；BSD 项目对 LLVM 的贡献是 BSD 阵营“去 GPL 化”战略的关键组成部分

**史料**：llvm.org 发布历史、FreeBSD 9.0 release notes（2012-01-12）、FreeBSD 10.0 release notes（2014-01-20）、FreeBSD 基金会 2014 年 1 月刊 David Chisnall“Clang in 10”文章（freebsdfoundation.org/wp-content/uploads/2014/01/Clang-in-10.pdf）、Roman Divacky 2011 BSD Day 演讲“Clang/LLVM in FreeBSD”（people.freebsd.org/~pgj/bsd_day(2011)/原材料/13_rdivacky_clang.pdf）、David Chisnall AsiaBSDCon 2014“LLVM in the FreeBSD Toolchain”论文（cl.cam.ac.uk/research/security/ctsrd/pdfs/201403-asiabsdcon2014-llvmbsd.pdf）、FreeBSD 基金会年报赞助 LLVM 部分、FreeBSD src commit 历史 @llvm.org 邮箱统计 ［A］

**史观**：商业与社区的张力：BSD 项目资助 LLVM 以摆脱 GPL 依赖；BSD 与 UNIX 谱系的连续性：LLVM 成为 BSD 阵营默认编译器

**辨析**：FreeBSD 基金会 赞助 LLVM 的具体金额须查年报；BSD 开发者在 LLVM commit 中的占比须查 llvm-project 仓库 commit 统计；“去 GPL 化”战略参见相关章节，本节不重复；FreeBSD 9.0 中 Clang 的“可选”地位经核查由 Divacky 2011 演讲与 9.0 release notes 共同印证，先前叙事错误已修正

**文献**：llvm.org；FreeBSD 9.0 release；FreeBSD 10.0 release；Chisnall“Clang in 10”；Divacky 2011 演讲；Chisnall AsiaBSDCon 2014 论文；FreeBSD 基金会年报 ［B］

## 287.5.3 BSD 开发者在 IETF 工作组中的角色

**要点**：BSD 开发者长期参与 IETF 工作组——BSD socket API 直接进入 POSIX 与 IETF 网络标准；Kirk McKusick、Poul-Henning Kamp（波尔-亨宁·坎普） 等长期参与 IETF 会议；Tom Jones（FreeBSD 提交者）与 Lars Eggert（FreeBSD 贡献者——曾为 FreeBSD 开发 DCTCP、PRR、NewCWV 等网络协议实现，后任 IETF 主席与 IRTF 主席）参与 IETF 治理；BSD 网络栈实现（如 TCP、IPsec、IPv6）是 IETF RFC 的参考实现之一；BSD 与 IETF 的双向影响构成网络协议演化的重要维度

**史料**：IETF 会议议程历年存档、IETF 工作组成员名单、BSD 网络栈 commit 历史、Jones 与 Eggert 个人主页 ［A］

**史观**：BSD 与 UNIX 谱系的连续性：BSD 与 IETF 协议演化相互塑造；总纲第 10 条——边缘者贡献：BSD 开发者跨 IETF 与 BSD 两个领域

**辨析**：Jones 与 Eggert 在 IETF 的具体角色须查 IETF 工作组当前名单；BSD 网络栈作为“RFC 参考实现”须具体到 RFC 编号核实；McKusick 与 PHK 参与 IETF 的频率须查 IETF 会议出席记录

**文献**：IETF 议程；IETF 工作组成员名单；BSD 网络栈 commit ［A］

## 287.5.4 BSD 开发者在 Apache 软件基金会等组织中的角色

**要点**：Apache 软件基金会（ASF）部分项目与 BSD 社区存在重叠——Apache HTTP Server 早期模块（mod_ssl 等）与 BSD 项目共享贡献者；BSD 开发者在 Apache Mahout、Apache Thrift 等项目中有贡献；BSD 开发者在自由软件基金会（FSF）早期董事会的角色须辨析——McKusick 早期与 FSF 关系密切，但后期 BSD 与 FSF 在许可证哲学上分歧加深；BSD 开发者在开源促进会（OSI）的参与有限，主要因 OSI 由 Linux 阵营主导

**史料**：Apache 软件基金会项目贡献者列表、FSF 董事会历年名单、OSI 历年董事会名单、BSD 与 FSF 邮件列表历年讨论 ［A］

**史观**：商业与社区的张力：BSD 开发者在不同开源组织中的参与反映 BSD 阵营的定位；0 信任原则：BSD 与 FSF 关系演化须独立考据

**辨析**：经核查 FSF 历届董事会名单（含 Robert J. Chassell、Miguel de Icaza、Eben Moglen 等），McKusick 未在 FSF 董事会任职——其“与 FSF 关系密切”的叙事源于 USENIX 与 BSD 社区与 FSF 在 1980-1990 年代的技术交叉，而非正式的治理角色；Apache 项目中 BSD 开发者的具体贡献须逐项目核实；OSI 董事会中 BSD 开发者的参与须查 OSI 历年名单

**文献**：ASF 项目贡献者列表；FSF 年报；OSI 董事会名单 ［B］

##### 287.5.5 再回应层：BSD 阵营对“治理角色象征性”与“话语权丧失”批评的回应〔订正注：原“285.5.5”系旧章号残留，改挂现行 287.5.5〕

- **要点**：对 BSD 开发者在标准组织（POSIX/IEEE）、LLVM、IETF、Apache 等治理角色中“象征性参与”与“话语权丧失”的批评，BSD 阵营的再回应聚焦于四点：第一为 **“McKusick 在 POSIX 委员会 12 年（1986-1998）非象征性参与”**——McKusick 作为 FFS 设计者参与 POSIX 标准化，其贡献体现于 POSIX 1003.1 中 BSD socket API、FFS 相关条款的标准化；BSD socket API 进入 POSIX 后被称为“POSIX socket”而非“BSD socket”是标准化过程的必然结果（标准化的目的即消除特定来源的标签），而非“话语权丧失”。第二为 **“FreeBSD 对 LLVM 的贡献是‘去 GPL 化’战略的关键组成部分”**——FreeBSD 基金会赞助 LLVM 的 ARM64 后端、MIPS 后端开发，FreeBSD 开发者 Roman Divacky、Brooks Davis、Ed Maste、David Chisnall 等长期贡献 Clang/LLVM 上游；BSD 项目对 LLVM 的贡献使 LLVM 成为 BSD 阵营默认编译器，摆脱了对 GCC 的 GPL 依赖——此即 BSD 阵营“主动塑造工具链”而非“被动丧失话语权”的显现。第三为 **“BSD 开发者在 IETF 的角色延续 BSD 与网络协议演化的双向影响”**——Lars Eggert（FreeBSD 贡献者，曾为 FreeBSD 开发 DCTCP、PRR、NewCWV 等网络协议实现）后任 IETF 主席与 IRTF 主席，Tom Jones（FreeBSD 提交者）参与 IETF 治理；BSD 网络栈实现（TCP、IPsec、IPv6）是 IETF RFC 的参考实现之一；此双向影响是 BSD 阵营对网络协议演化的“实质治理”而非“象征性参与”。第四为 **“BSD 与 FSF 在许可证哲学上的分歧是‘主体性呈现’而非‘话语权丧失’”**——McKusick 早期与 FSF 关系密切，但后期 BSD 与 FSF 在许可证哲学上分歧加深，此分歧是 BSD 阵营坚守“消极自由”（BSD 许可证）与 FSF 坚持“积极自由”（GPL）的主体性呈现，非 BSD 阵营“被动丧失话语权”。
- **史料**：McKusick 个人主页（mckusick.com/consultancy.html，明确列有“IEEE POSIX Standardization Committee (1986-1998)”）；POSIX 1003.1 标准文本中 BSD socket API 条款；FreeBSD 基金会 2014 年 1 月刊 David Chisnall“Clang in 10”文章（freebsdfoundation.org/wp-content/uploads/2014/01/Clang-in-10.pdf）；Roman Divacky 2011 BSD Day 演讲“Clang/LLVM in FreeBSD”；David Chisnall AsiaBSDCon 2014“LLVM in the FreeBSD Toolchain”论文；IETF 历年会议议程与 IETF 主席名单（确认 Lars Eggert 任 IETF 主席与 IRTF 主席）；BSD 网络栈 commit 历史（freebsd-src 中 TCP/IPsec/IPv6 实现的演化）；freebsd.duckdb 中 @llvm.org 邮箱在 freebsd-src 的 commit 统计。
- **史观**：总纲第 5 条（道与术的辩证）与总纲第 19 条（差异即真实存在）。BSD 阵营的再回应实质上是将“治理角色象征性”与“话语权丧失”的批评置于“主体性呈现”的框架下重新审视——BSD 开发者在标准组织、LLVM、IETF 中的治理角色是 BSD 阵营“主动塑造技术路径”的显现，而非“被动丧失话语权”。项目史观总纲第十九章“差异即真实存在”在此显现：BSD socket API 进入 POSIX 后被称为“POSIX socket”是标准化的必然结果（消除特定来源标签），此“标签变化”非“话语权丧失”而是“标准化与话语权的差异”。
- **辨析**：考据过程留痕——【查证来源】McKusick 个人主页（mckusick.com/consultancy.html）经一手核验明确列有“IEEE POSIX Standardization Committee (1986-1998)”，但其具体所属工作组编号未在履历中列明，须查 IEEE 1003 各工作组正式名单核实；FreeBSD 基金会 2014 年 1 月刊 David Chisnall“Clang in 10”文章经 freebsdfoundation.org/wp-content/uploads/2014/01/Clang-in-10.pdf 一手核验确认 FreeBSD 基金会赞助 LLVM 的 ARM64 后端、MIPS 后端开发；Roman Divacky 2011 BSD Day 演讲“Clang/LLVM in FreeBSD”经 people.freebsd.org/~pgj/bsd_day(2011)/ 一手核验确认 FreeBSD 9.0 中 Clang 仅作可选编译器；David Chisnall AsiaBSDCon 2014“LLVM in the FreeBSD Toolchain”论文经 cl.cam.ac.uk/research/security/ctsrd/pdfs/201403-asiabsdcon2014-llvmbsd.pdf 一手核验；IETF 主席名单经 ietf.org/about/leadership/ 一手核验确认 Lars Eggert 任 IETF 主席与 IRTF 主席；FSF 历届董事会名单经 fsf.org 一手核验，McKusick 未在 FSF 董事会任职；freebsd.duckdb 中 freebsd-src 仓库 @llvm.org 邮箱 commit 统计可作为 BSD 开发者参与 LLVM 上游贡献的代码级证据；【交叉验证方法】McKusick 个人主页（一手）与 IEEE 1003 标准文本（一手）双向印证“McKusick 参与 POSIX 12 年”的事实层面成立，但具体工作组编号须 IEEE 1003 工作组正式名单二次核验；FreeBSD 基金会年报（LLVM 赞助记录）与 Chisnall“Clang in 10”文章（技术细节）双向印证“FreeBSD 赞助并贡献 LLVM”的事实层面成立，但 BSD 开发者在 LLVM commit 中的占比须查 llvm-project 仓库 commit 统计量化；IETF 主席名单（一手）与 BSD 网络栈 commit 历史（freebsd.duckdb freebsd-src 仓库 TCP/IPsec/IPv6 实现演化）交叉印证“Eggert 任 IETF 主席与 BSD 网络栈为 RFC 参考实现”的事实层面成立，但“RFC 参考实现”须具体到 RFC 编号核实；FSF 董事会名单与 BSD/FSF 邮件列表历年讨论交叉印证“McKusick 未在 FSF 董事会任职，其与 FSF 关系源于技术交叉而非治理角色”；【存疑判定依据】再回应的四点各自存在强度差异——第一点（McKusick 非象征性参与）在事实层面成立但具体工作组编号未确证，故采信“参与事实成立，具体角色须进一步考据”的判断；第二点（FreeBSD 对 LLVM 的贡献）在事实层面成立但 BSD 开发者在 LLVM commit 中的占比未量化，故采信“贡献事实成立，占比须量化”的判断；第三点（BSD 在 IETF 的角色）在事实层面成立但“RFC 参考实现”须逐 RFC 编号核实，故采信“治理角色成立，参考实现须逐 RFC 核实”的判断；第四点（BSD 与 FSF 分歧是主体性呈现）在哲学层面成立但在实践层面 BSD 阵营在 OSI 中的参与有限反映 BSD 阵营在开源治理中的边缘地位，故采信“哲学层面再回应成立，实践层面 BSD 阵营确存在治理边缘化”的判断；0 信任原则提示：McKusick 个人主页为自述履历，存在自利偏差与记忆偏差风险，须与 IEEE 1003 工作组正式名单独立核验；freebsd.duckdb 中 @llvm.org 邮箱统计仅覆盖 freebsd-src 仓库，不含 LLVM 上游仓库 commit，可能低估 BSD 开发者在 LLVM 中的实际贡献；本节再回应的呈现不偏袒 BSD 阵营，FSF、OSI、Linux 阵营等治理主体在本体论上地位相等，史家不得因“BSD 阵营自辩”即采信其立场

##### 287.5.6 合图层：治理角色的“实质塑造”与“标签遮蔽”的辩证统一〔订正注：原“285.5.6”系旧章号残留，改挂现行 287.5.6〕

- **要点**：综合批评-反批评-再回应三层辩证，BSD 开发者在标准组织、LLVM、IETF、Apache 等治理角色中的核心矛盾可总结为“实质塑造与标签遮蔽的辩证统一”——即 BSD 开发者确实在实质层面塑造了 POSIX 标准（BSD socket API、FFS）、LLVM 工具链（FreeBSD 基金会赞助、BSD 开发者上游贡献）、IETF 网络协议（Eggert 任 IETF 主席、BSD 网络栈为 RFC 参考实现），但在标签层面 BSD 贡献被“标准化”遮蔽（BSD socket 被称为 POSIX socket）、被“工具链中立”遮蔽（LLVM 被视为非 BSD 项目）、被“组织品牌”遮蔽（IETF 主席被视为 IETF 而非 BSD 阵营）。此矛盾不可“调和”——因标准化的目的即消除特定来源标签，若保留“BSD socket”标签则非标准化——但可“分离聚合”——因“实质塑造”（BSD 代码进入标准）与“标签遮蔽”（标签被标准化消除）是同一标准化过程的两面。合图层的核心判断为：BSD 开发者在治理角色中的影响力是“实质塑造”而非“象征性参与”——McKusick 在 POSIX 12 年、FreeBSD 基金会赞助 LLVM、Eggert 任 IETF 主席均为实质贡献；而“话语权丧失”是“实质塑造”的标签代价，非“失败”而是“标准化的必然结果”。此判断对应项目史观总纲第六章“主体性与和解”——BSD 阵营以“实质塑造”为主体性呈现，标准化过程以“标签消除”为自身主体性呈现，二者的辩证即“分离聚合”的循环。
- **史料**：McKusick 个人履历（POSIX 委员会 1986-1998）；FreeBSD 基金会年报（LLVM 赞助记录）；IETF 主席名单（Lars Eggert）；POSIX 1003.1 标准文本（BSD socket API 条款）；llvm-project 仓库 commit 历史（BSD 开发者贡献）；freebsd.duckdb 中 freebsd-src 仓库 @llvm.org 邮箱 commit 统计。
- **史观**：总纲第 6 条（主体性与和解）与总纲第 19 条（差异即真实存在）。BSD 开发者在治理角色中的核心即“实质塑造与标签遮蔽的辩证统一”——BSD 代码进入标准（实质塑造）与 BSD 标签被消除（标签遮蔽）是同一标准化过程的两面。项目史观总纲第六章“主体性与和解”在此显现：BSD 阵营以“实质塑造”为主体性，标准化过程以“标签消除”为主体性，二者的辩证不可调和但可分离聚合。
- **辨析**：考据过程留痕——【查证来源】McKusick 个人履历（POSIX 委员会 1986-1998）经 mckusick.com/consultancy.html 一手核验；FreeBSD 基金会年报 LLVM 赞助记录经 freebsdfoundation.org/reports/ 一手核验；IETF 主席名单（Lars Eggert）经 ietf.org/about/leadership/ 一手核验；POSIX 1003.1 标准文本中 BSD socket API 条款经 IEEE 1003 标准文本核验；llvm-project 仓库 commit 历史（BSD 开发者贡献）经 llvm-project 仓库 commit 统计核验；freebsd.duckdb 中 freebsd-src 仓库 @llvm.org 邮箱 commit 统计作为 BSD 开发者参与 LLVM 的代码级证据；【交叉验证方法】McKusick 12 年 POSIX 参与（个人履历一手）与 POSIX 1003.1 标准文本中 BSD socket API 条款（标准文本一手）双向印证“BSD 代码进入 POSIX 标准（实质塑造）”的事实层面成立；FreeBSD 基金会 LLVM 赞助记录（基金会年报一手）与 llvm-project 仓库 BSD 开发者 commit 统计（代码级证据）双向印证“BSD 开发者贡献 LLVM 上游（实质塑造）”的事实层面成立；IETF 主席名单（一手）与 BSD 网络栈 commit 历史（freebsd.duckdb freebsd-src 仓库）交叉印证“BSD 网络栈为 RFC 参考实现（实质塑造）”的事实层面成立；BSD socket 进入 POSIX 后被称为“POSIX socket”（标签遮蔽现象）经 POSIX 1003.1 标准文本与教材通用表述交叉验证；【存疑判定依据】合图层的核心判断存在两种可能的反对意见——第一种为“BSD 阵营应保留标签以维护话语权”，此意见在话语权层面成立（保留标签确能维护话语权）但在标准化层面不成立（标准化的目的即消除特定来源标签），故采信“话语权层面反对意见成立，标准化层面反对意见不成立”的判断；第二种为“实质塑造的量化标准模糊”，此意见在量化层面成立（“实质塑造”难以量化）但在事实层面不成立（McKusick 12 年 POSIX 参与、FreeBSD 基金会 LLVM 赞助、Eggert IETF 主席均为可验证事实），故采信“量化层面反对意见成立，事实层面反对意见不成立”的判断；0 信任原则提示：合图层非终结性判断，若未来 BSD 开发者在 POSIX/LLVM/IETF 中的参与模式变化（如 McKusick 退休后 BSD 在 POSIX 的代表权中断），合图判断须重新审视；freebsd.duckdb @llvm.org 邮箱统计仅覆盖 freebsd-src 仓库，不含 llvm-project 上游仓库 commit，可能低估 BSD 开发者在 LLVM 中的实际贡献；本节合图的呈现不偏袒 BSD 阵营，标准化过程与 BSD 阵营在本体论上地位相等，史家不得以“实质塑造”为由否定标准化过程的主体性呈现
