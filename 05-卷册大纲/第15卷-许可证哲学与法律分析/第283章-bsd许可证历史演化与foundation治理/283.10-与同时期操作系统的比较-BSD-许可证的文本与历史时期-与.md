# 283.10 **与同时期操作系统的比较**：**BSD** 许可证的文本与历史时期——与 **Linux**/**GPL**、**Apache**/**MIT**、**Windows** 闭源许可、其他 **BSD** 变体（**NetBSD**/**OpenBSD**/**FreeBSD** 许可演进）的对照

## 282.10.1 Linux / GPL（copyleft 对照）

**要点**：**GPL**（**GNU** 通用公共许可）以 **copyleft**（传染性）要求派生作品同许可开源，与 **BSD** 许可的 “最小限制” 形成根本对照；**Linux** 内核采用 **GPLv2**，使整个内核生态受 **copyleft** 约束，与 **BSD** 家族的 permissive 许可在 “自由定义” 上分野。

**史料**：**GPLv2** 文本；**Stallman**. Free Software Definition ［B］

**史观**：总纲第 6 条——技术路线分化：**GPL** **copyleft** vs **BSD** permissive 是许可哲学的核心分歧，塑造生态差异。

**辨析**：**GPL** 的 “病毒式” 聚合与 **BSD** 的 “信任用户” 是两种自由观，非优劣。

**文献**：**Free Software Foundation**. **GPLv2** [Z]；**Stallman R**. Free Software Definition [EB/OL]. ［B］

## 282.10.2 Apache / MIT（其他宽松许可）

**要点**：**Apache 2.0** 与 **MIT** 同属宽松许可，与 **BSD** 许可家族相近但各有细节（**Apache** 含专利授权条款、**MIT** 极简）；二者与 **BSD** 共同构成 “permissive 阵营”，与 **GPL** 的 **copyleft** 对立，体现开源许可光谱。

  | 许可证 | 关键特征 | 与 **BSD** 关系 |
  |---|---|---|
  | **BSD 2-Clause** | 极简 | 基准 |
  | **MIT** | 极简 | 实质等价 |
  | **Apache 2.0** | 含专利授权 | 复杂度更高 |
  | **GPLv2** | **copyleft** | 对立 |
**史料**：**Apache 2.0** / **MIT** 文本 ［B］

**史观**：总纲第 6 条——技术路线分化：宽松许可（**BSD**/**Apache**/**MIT**）vs **copyleft**（**GPL**）构成许可光谱两端。

**辨析**：**BSD** 与 **MIT** 几乎等价，**Apache 2.0** 增加专利保护，三者均属 permissive。

**文献**：**Apache Software Foundation**. **Apache 2.0 License** [Z]；**MIT License** [Z]. ［B］

## 282.10.3 Windows / 闭源商业许可

**要点**：**Microsoft Windows** 采用闭源商业最终用户许可（**EULA**），禁止源码查看与修改，与 **BSD** 许可的 “源码自由 + 最小限制” 根本对立；闭源使代码不可审计，与 **BSD** 的开源可验证存在差异。

**史料**：**Microsoft** `EULA` 模式文档 ［B］

**史观**：总纲第 6 条——技术路线分化：闭源商业许可 vs **BSD** 开源许可是软件分发范式的根本对立。

**辨析**：闭源许可保护商业利益但牺牲可审计性，**BSD** 许可反之。

**文献**：**Microsoft**. `EULA` Overview [EB/OL].[考据完成：2026-07-28 经穷尽联网考据，上述文献清单为已知公开来源汇总，部分原始档案未公开数字化或须付费访问，属史料缺口，须待原始档案公开后方可补充确证]

## 282.10.4 其他 BSD 变体（NetBSD/OpenBSD/FreeBSD 许可演进）

**要点**：三大 **BSD** 的许可同源 **4.4BSD-Lite** 的 **BSD** 许可，后各自微调（如去 **UC Regents** 署名、调整广告条款）；**FreeBSD**/**NetBSD**/**OpenBSD** 的许可文本趋同于 “简化 **BSD**/2-clause”，体现 **BSD** 家族在许可上的共识与流动。

**史料**：各 **BSD** 许可文本（2-clause/3-clause）［A］

**史观**：总纲第 7 条——**BSD** 谱系：三大 **BSD** 的许可同源演进，体现 family 在许可上的共识。

**辨析**：**BSD** 许可的微调（去广告条款）是文本澄清，非哲学改变。

**文献**：**FreeBSD**/**NetBSD**/**OpenBSD**. License Texts [Z]. ［A］

## 282.10.5 同期许可格局总览

**要点**：软件许可呈 “**copyleft**（**GPL**）vs permissive（**BSD**/**Apache**/**MIT**）vs 闭源（**Windows EULA**）” 三极格局；**BSD** 许可以 “最小限制 + 可审计” 在开源生态中独特定位，既区别于 **GPL** 的约束，也区别于闭源的不透明。

**史料**：各许可文本与采用统计 ［B］

**史观**：总纲第 6 条——技术路线分化：三极许可格局是技术哲学差异的外显。

**辨析**：许可选择影响生态聚合方式，**BSD** 许可促进代码在闭源/开源间自由流动。

**文献**：**McKusick M K**, **Neville-Neil G**. The Design and Implementation of the FreeBSD Operating System [M]. 2nd ed. Addison-Wesley, 2015. ［B］

史学含义：BSD 社区的治理结构——Core Team、committer 权限、Ports 维护者制度——皆是形式主义的政治产物。Core Team 的权威不来自技术优越，而来自形式主义的权力分配。社区中的边缘化现象、贡献者的话语权不均，皆是利益分配问题的体现。BSD 许可证选择承认人类的有限性，而非以强制形式限制自由。史家应揭示社区治理结构背后的权力逻辑，而非将其伪装为纯技术决策。
