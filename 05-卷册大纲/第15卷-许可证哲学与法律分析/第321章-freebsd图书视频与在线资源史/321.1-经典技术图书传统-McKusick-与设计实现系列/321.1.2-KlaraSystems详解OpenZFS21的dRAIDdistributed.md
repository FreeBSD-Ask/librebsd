# 321.1.2 KlaraSystems详解OpenZFS21的dRAIDdistributed

- Klara Systems 详解 OpenZFS 2.1 的 dRAID（distributed RAID）：在 RAID-Z 语义上重排数据块使访问均匀铺满全部盘，配合预分配的分布式热备实现快速换盘；其顺序 resilver 仅沿 parity 布局重建目标盘，随后自动触发 healing resilver 补全校验，把传统 scrub 式全池校验拆分为两阶段以适应大容量盘时代；OpenZFS wiki 的 90 盘 16TB 组测试显示换盘时间由约 29 小时缩短至 15 小时余，且单/双/三奇偶校验皆不放大耗时。（BSD Now EP393，[463.28-869.34]，L2）
- 主持人重读 27 年前 Adrian Cockcroft 的 Sun Performance and Tuning：SunOS 4 目录名查找缓存（DNLC）只缓存 14 字符以内文件名、le0 网卡与 SCSI 接口共享 DMA 导致重负载网络拖慢磁盘吞吐等细节，折射 90 年代系统调优的现实约束；书中 VM stat/SAR 的多因素组合测量（六因素四水平即 4096 组合）提醒读者性能实验的组合爆炸与读数陷阱。（BSD Now EP393，[89.12-426.96]，L2）
- Signal 在伊朗遭封锁后给出代理方案，其官方 Docker 镜像内里只是 nginx 配置；社区据此给出 FreeBSD + nginx + acme.sh（Let's Encrypt/ZeroSSL）的等价部署教程，并默认关闭访问日志以避免记录经代理的通信内容。（BSD Now EP393，[1065.54-1311.46]，L2）
- 从 macOS 迁移者的 PDF 需求牵引出 OpenBSD ports 中的 Xournal/Xournalpp（触笔与手指标注、签名、导出只读 PDF）与 OCRmyPDF（对扫描件识别后生成可复制文本），讨论指出这类工具并非 OpenBSD 独有，映射桌面 Unix 在文档工作流上的补课过程。（BSD Now EP393，[1311.46-1662.86]，L2）
- Fabricator 平台的“现在就该做”清单以 Facebook 教训立论：ID 从 2 的 33 次方起跳以杜绝标识符与业务数值混淆（PHP array_slice 重排索引导致渲染错人的案例）、只存有效 UTF-8 以避免文件名跨系统漂移（Bacula 备份还原场景反例）、勿以黑名单构建安全系统（Facebook 的 CSS 黑名单制造了无尽的安全漏洞）、生产环境 SQL 语法错误应当高声报警以充当 SQL 注入的高信号探测器。（BSD Now EP393，[1672.1-1939.58]，L2）
- 反馈环节：Dan Langille 当场实测证明 ZFS 快照彼此独立、可任意删除旧快照而不影响新快照（快照是文件系统时点照片而非增量差分，仅回滚受限于更新快照）；另有听众询问 bhyve 中直通设备与物理盘并存的失败案例，以及多操作系统共享同一 ZFS 池引导的可行性，主持人以 bootfs 参数唯一性与加载器对加密池（GELI）的支持边界作答。（BSD Now EP393，[2438.92-2922.44]，L1）
- Joseph Kong 自述为多伦多大学工业工程毕业生，无计算机科学专业背景、完全自学；兴趣路径从低层系统编程出发，经安全、漏洞利用开发与逆向工程自然延伸至 rootkit。其书稿源于约四十页个人笔记——为免遗忘而整理，且因网上资料过时、残缺而决定成书；出版提案首发 No Starch Press 即获创始人 Bill Pollock 次日回应，随后的技术审校由 FreeBSD 核心开发者 John Baldwin 担任，其指出代码缺陷与未处理的边界情况，迫使 Kong 重写大量代码乃至已完成的章节。写作原计划六个月，实际耗时一年，出版团队共五人参与审阅。 [存疑脚注] 出版人姓名转写作“Bill Paulak”，按 No Starch Press 史应为 Bill Pollock；其余编辑人名拼写均以转写存疑（BSDTalk EP113，[103.62-202.14, 257.06-319.58]，L1）
- 关于书籍定位，Kong 说明其目标读者是对低层系统编程与 FreeBSD 感兴趣者，意图展示“引擎盖之下的 FreeBSD”；与 McKusick 及 Neville-Neil 的《The Design and Implementation of the FreeBSD Operating System》相比，后者是高层概览而本书偏低层实用；他自述偏好 Stevens 式以大量实际示例教学的写作传统。对于伦理质疑，其界定很明确：加载 rootkit 的前提是已取得 root 权限，故全书不含漏洞利用内容，只讨论内核的修改与扩展——“rootkit 就是系统程序”，用途取决于使用者，并承认系统管理员亦会用 rootkit 隐蔽其监视行为。 [存疑脚注] 转写作“Kurt McCusick”，按史实应为 Marshall Kirk McKusick（BSDTalk EP113，[321.62-351.94, 351.94-434.82, 772.04-786.04]，L1）
- 《The Design and Implementation of the FreeBSD Operating System》第二版于 2014 年春完稿、同年秋由 Pearson 出版，作者为 Marshall Kirk McKusick、George Neville-Neil 与新加入的 Robert Watson（剑桥大学），三人协作数年；出版须对齐大学秋季学期，纸质书的截止日期远比软件来得硬；新版覆盖 FreeBSD 10 并少量触及 11，而上一版覆盖 5.2；自完稿到面市约六个月内系统本身仍在演变，作者的目标是让书在约十年内保持相关——此系列约十年一版。写作期间 Kirk 明令禁止中途修改代码以迁就书稿，否则书永远写不完。（BSDTalk EP253，[79.96-330.30]，L1）
- 新版的关键主题之一是 FreeBSD 的锁架构与各子系统加锁时的交互，因为锁机制是程序员与系统打交道的最大难点，锁不正确便出严重问题；上一版选 5.2 正为覆盖 SMP 与锁等长期保持相关的主题，事实证明其贯穿了上一版的整个生命周期；从 5 到 10 之间系统已有多队列网络接口与远比 5 时代细粒度的锁；单核时代趋于终结——ARM32 某些板卡（如初代 Raspberry Pi）仍是单核，但最便宜的设备也已是两核四核，仍执着于单处理器的人并不运行 FreeBSD。（BSDTalk EP253，[331.44-445.22]，L1）
- 新版内容版图：Robert Watson 撰写全新的安全章节，Kirk McKusick 撰写全新的 ZFS 章节，George Neville-Neil 大幅增写网络栈（SCTP——非新协议但在特定环境重要且在 FreeBSD 中已重度使用——与模块化拥塞控制）并新增整节 DTrace；他提出著名的论断：DTrace 本质上是操作系统的 rootkit——它在运行中动态替换指令、启用即以 root 权限运行，对常做安全工作的人而言极其有用却也相当可怕；DTrace 内部此前从未有书籍记载，仅见 Sun 开发者写在源码头文件中的注释，Brendan Gregg 的著作只讲使用，故本书是唯一系统记载 DTrace 内部机制的出版物。（BSDTalk EP253，[568.02-727.28]，L1）
- 写作经历带来对 DTrace 的认识论顿悟：他为理解 NFSv4 而以 DTrace 观察其运行，发现这是理解大型运行系统前所未有的工具——传统的 print 调试缓慢、易错且无法随意开关，而 DTrace 进入 Sun 与 FreeBSD 的每个出货内核，现场排障与课堂演示（如 TCP 状态机的建立、运行与关闭，取代 Stevens 之书或 RFC 中的 ASCII 图）皆可实时呈现；由此他与 Robert Watson 开发面向大学生与从业者的 DTrace 课程，George 在 2015 年 3 月的 Asia BSDCon 讲授，Robert 在剑桥讲授硕士版并在 BeagleBone Black 的 ARM 环境教学；Sun 原班设计者是真正聪明、经验丰富的内核工程师并长期打磨此一问题，将其导入 FreeBSD 的 John Birrell 亦须深谙其理；其他操作系统的重新实现属“重写三次才会对”的路径且远不及 FreeBSD 版详尽，而 DTrace 之于整个操作系统的渗透性远超 SCTP、拥塞控制等其他新特性。 [存疑脚注] 转写作 John Burrell，音近；按 FreeBSD DTrace 移植史应作 John Birrell，仍待文字史料核验（BSDTalk EP253，[1088.58-1296.14]，L1）
- 本书读者定位：面向以 C 编程者、系统程序员与以 FreeBSD 构建产品的厂商——Juniper、Isilon、NetApp 之外还有 WhatsApp 等会议常客，产品团队中总需要有人理解系统内部以诊断问题、优化性能；同时面向能编程的系统管理员——当事人感慨系统管理员一词已经退化，如今多数从业者不会编程，而旧模式下能读代码的管理员才是本书读者；操作系统的设计刻意在引擎盖下遮蔽复杂性、呈现简化的世界图景，NFSv4 协议为维持简单的 open、close、read、write 接口而在内部机巧重重即为例证，一旦系统出问题或被推向极限，深层理解便不可或缺；只想架设 ZFS 阵列的读者则应读 FreeBSD Journal 上 Alan Jude 的文章而非本书。（BSDTalk EP253，[758.60-1015.42]，L1）
- 写作工艺延续传统：全书以 troff 排版、以 CVS 做版本控制——正是 4.3BSD 之书由 Kirk 与 Sam Leffler、Mike Karels、John Quarterman 等人开创的旧例；本版图表混用 XFig 与 Mac 上的 OmniGraffle，George 与 Robert 发现所见即所得画图更高效，但二进制图形文件难以 diff，而文本加 CVS 可以审阅彼此改动——三位作者互相修改对方章节，谁在何时改了什么必须可追溯，这一可 diff 性至关重要；troff 体系极简、宏标签寥寥（以索引为主），半天即可上手，但过度标注会让页面如鸟粪斑驳；校样以 troff 生成 PostScript 再经 ps2pdf 转换提交出版社，Word 一类工具则无法处理复杂图表与代码样例。（BSDTalk EP253，[1410.06-1758.50]，L1）
- McKusick 强调 BSD 图像人物系 daemon 而非 demon：后者指邪恶精灵，前者承希腊词义的半人半神之中介性存在，故有“做软件至少需要半个神站在你这边”的自况；daemon 从未被项目正式命名，社区不断起名，有人提议 Chuck，但因 Chuck 系演讲人高中时令其头疼之人而被否决（一件 Chuck the Demon 衬衫设计被否决，演讲人自述持有唯一一件），最终定名 Beastie，起名者经翻检笔记与邮件未能查明；NetBSD 与 OpenBSD 早期沿用该形象，FreeBSD Foundation 曾推出西装版本，其后各项目与基金会均因 daemon 在部分文化语境中被视为邪恶精灵、公关不佳而弃用，改换独立标志。[订正：原“某衬衫上出现的 Chuck 之名只是设计被否决的玩笑，起名者已不可考”→新转写证实 Chuck 提议因演讲人高中阴影被否决，起名者不可考系指 Beastie 之定名者]（YouTube EPF9mtbe9vw90，[47.52-112.64]，L1）
