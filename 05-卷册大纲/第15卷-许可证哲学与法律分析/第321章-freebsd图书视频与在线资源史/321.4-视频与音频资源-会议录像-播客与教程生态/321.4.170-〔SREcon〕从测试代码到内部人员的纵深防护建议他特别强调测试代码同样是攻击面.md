# 321.4.170 〔SREcon〕从测试代码到内部人员的纵深防护建议他特别强调测试代码同样是攻击面

- 〔SREcon〕从测试代码到内部人员的纵深防护建议。他特别强调测试代码同样是攻击面：xz-utils 就是通过测试代码给 SSH 埋后门，部署时测试代码行为略有不同从而把后门注入软件，该 APT 团队两年间几近成功，最终只因一名关注 MySQL 查询时序的“可观测性极客”偶然发现。生产系统应定期做漏洞扫描与修补（他建议在 SREcon 的语境下多靠重新部署现成 Linux 版本）、文件完整性监控、可观测性与端点检测，并转向不可变 Linux 甚至不可变 Windows 实例。CI/CD 部分以 Cloudflare 事件为例说明攻击者取得小立足点后沿流水线横向移动，主张每个系统都有第二套架构即构建与部署架构、应与应用架构同等用心，并类比福特 F-150 车厂无法直接改产泰勒斯；.gitlab 与 .github/workflows 是隐藏在仓库里最关键的配置，而 Jenkinsfile 至少是可见文件。代码仓库与工具托管建议交给把这件事当本职工作的厂商（Amazon、Netflix 有专门的 team），自建有工具自身 RCE 与 SQL 注入等风险且通常只排在第二、第三优先级。开发与管理笔记本靠 MFA、端点防护与 DLP 防御钓鱼（CircleCI 是经典案例），他认为 10% 到 12% 的安全预算并不离谱；供应商侧要对包括微软在内的厂商做安全评估问卷并落到书面，Slack、Okta、微软邮箱均出过事，Russian SVR（普京时期 KGB 的延续）背景的 Cozy Bear 主要攻击微软安全团队，SolarWinds 则波及全部客户；浏览器生态上要求保持更新、限制插件（他自己除公司强制的身份插件外不装）、避免浏览器单一化（约 90% 基于 Chromium、约 85% 跑 Chrome，他自己用 Firefox）。最后以 Knowbe4 事件收尾：朝鲜黑客要把工作伪装成来自美国，需在美国某住宅部署几百台笔记本的“农场”，那百台机器背后是遍布美国的企业 IT 承包商，银行、电信、高科技与制造公司全部中招却只有 Knowbe4 公开披露，因此建议盯紧供应商的反常表现（反复的“猫病了”、无法开摄像头的借口、被 PS 的工卡照片）、注意内部人员与离职员工，并警惕 Evasive Panda 这类窃取云登录 cookie 并完整盘点云账号的工具包。（YouTube EPSBGVEc3LrLU，[1255-2440]，L1）
- 〔会议不详（推测 系统会议）〕Banana Double Split 驱动模型：把 Xen 拆分驱动再拆一次。主讲人说明本工作与 IBM 的 Hani Jamjoom（其主管）及 Cornell 的导师 Hakim Weatherspoon 合作。他先用 Xen 拆分驱动模型说明现状：guest 的前驱驱动不掌握硬件细节，与控制域 domain 0 中的后驱驱动交互，后者再对接硬件驱动，前端看似与硬件解耦但依赖并未消除——迁到新机器可能没有原先的 GPU 或 FPGA，网络配置（如特定端口的 VLAN tag）也依赖具体耦合，且后驱与硬件驱动是临时拼凑的组合、没有可插拔的接入点。提案是把系统侧再拆一刀：包裹硬件驱动的部分称为 corm（取自香蕉的地下根茎），充当后驱的部分称为 spike（取自香蕉的花穗），两者经定义良好的标准接口由 wire 连接，可按软件定义的方式重连、重配；迁移时 spike 随 guest 一起搬走、wire 被拉长跨越多台物理机。架构上还含位于每个 hypervisor 的 endpoint controller，负责决定各端点连到哪并选择 wire 类型（本地桥、VXLAN 封装隧道或 OpenVPN 隧道），端点管理与虚拟迁移机制集成、端点形态类似虚拟网卡，迁移完成后更新端点即实现 wire 拉伸。实现首先聚焦 Xen 网络：端点在 Linux 中以 netdev 形式暴露，经自研 endpoint bridge 嫁接到后驱与物理出口，wire 有桥接、由内核模块实现并给报文加 VXLAN 头的封装 wire、以及 OpenVPN 隧道三种。（YouTube EPSI-iNGr61XY，[10-698]，L1）
- 〔会议不详（推测 系统会议）〕跨云热迁移实验、corm switching 与问答。为做跨云热迁移需更苛刻的测试环境：一端的虚拟机跑在 Amazon EC2 上、用先前自研的嵌套虚拟化方案 Xen-blanket 在其上再跑一层 Xen，另一端在本地，磁盘走本地 NFS，用 netperf 度量吞吐与延迟。两台虚拟机全程互打 netperf，先迁一台、停顿、再迁另一台，迁移期间性能大幅下降是预期结果，因为 spike 把 wire 拉长使流量全部隧道回本地；迁移两端都用完后他把两端 corm 切到本地 corm（corm switching），性能随即恢复，据此主张该机制可在位置依赖消失后作为一种优化。他补充实验环境本身带来很大开销：嵌套虚拟化已使停机时间增加 43%，Banana 端点迁移再增加约 30%，跨云热迁移总停机为 2.8 秒。wire 性能评估显示自研内核模块封装相对其他隧道机制有性能提升，且嵌套环境下内核模块尤其重要，因为上下文切换代价被放大。相关工作中他对比了 Xen blkback、net channel、绕过操作系统的 Nomad、USB 相关以及 VxLAN 等虚拟网络方案。问答中波士顿大学的 Jonathan 对比 Plan Nine 式挂载、ATA over Ethernet 与 iSCSI，并追问 SR-IOV 等硬件虚拟化支持是否会削弱这种灵活性；IBM Research 的 Qinghao 追问对 GPU、存储类驱动与容器式虚拟化的可扩展性，讲者坦承除网络设备外尚未做具体工作、也还没有完整的设备分类法。（YouTube EPSI-iNGr61XY，[698-1638]，L1）
- 〔会议不详（推测 系统与信任会议）〕把 TLS 与远程认证结合以访问可信执行环境。讲者设定场景为数据中心中的机密计算服务，客户端需先经远程认证确认对端软件状态；TEE 是许多处理器的硬件扩展（如 Intel TDX、AMD SEV），通过内存加密与隔离保护执行，但只有客户端能校验这些保护才真正生效，认证报告包含 nonce、软件状态哈希与元数据并由位于数据中心的硬件根信任签名。设计目标是最少改动 TLS 线路格式、握手不增加往返以保持低延迟、信道建立后不引入额外加密、不绑定单一根信任技术、抵抗中继攻击并具备加性安全（认证的有效性不依赖 TLS 私钥的安全性）、且不改动 CA 与认证基础设施。做法是利用 TLS 1.3 对消息扩展的密码学安全追加能力：在 client hello 上携带 attestation request、在 certificate 消息上携带 attestation report，这两项扩展都已在 IETF 标准化进程中进行且与本论文作者重叠，扩展内容本质是二进制 blob，因此可承载任意认证报告，只让消息变大、不加往返也不加加密。他也点出本工作与相关工作的分界在于中继攻击：设想中间有一台持有 TLS 私钥并运行恶意软件的机器、后面才是真正运行正确软件的 TEE，服务方有意把客户端引向那个恶意版本。（YouTube EPSIDEgm2KACQ，[10-464]，L1）
- 〔会议不详（推测 系统与信任会议）〕中继攻击的机制、短期会话密钥锚定与加性安全。攻击的具体步骤是：客户端发起普通 TLS 连接并在 client hello 中带上 attestation nonce，恶意软件随即转身向良性版本发起一次新的、密码学上独立但复用同一 nonce 的 TLS 连接，取得合法的认证报告后原样转发给客户端；于是客户端信以为真，而校验的实际是另一台机器的软件状态，认证形同虚设。结论是必须把认证与 TLS 信道密码学绑定，但相关工作多把绑定建立在长期 TLS 密钥之上，一旦该私钥在别处被克隆又可重演同样的转发技巧；而且客户端为此必须校验软件无侧信道漏洞（如 Heartbleed 类）以及数据中心的硬件安全模块安全保管密钥，这与“不再信任运营商”的初衷冲突，等于依赖私钥的整个来源历史。该工作的解法是改锚短期 TLS 会话密钥：TLS 1.3 强制临时 Diffie-Hellman 交换，双方各自维护消息日志并哈希出一个与常规 transcript hash 不同的 linking hash（因 TLS 库内部实现原因无法直接复用 transcript hash），分别交给 TLS 私钥签名与认证根信任签名；两个签名彼此独立、都锚定当前会话密钥，客户端可分别校验“该机器持有私钥”与“该机器软件状态合法”。由此得到独立部署与独立失效两个性质：认证不依赖 TLS 私钥、TLS 也不依赖认证，任一方被攻破仍能保住另一方的性质，即 TLS+RA 叠加两种协议的保证；吞吐与常规 TLS 完全一致，延迟增加仅源于消息变大而非额外往返。（YouTube EPSIDEgm2KACQ，[465-952]，L1）
- 〔会议不详（推测 安全类会议）〕用形式化方法消除可利用漏洞：为何现在是好时机与 HACMS 成果。讲者曾在 DARPA 任职，报告 DARPA HACMS 项目（转写音写为 Hackers、HackMD）三年间、尤其是前十八个月与阶段二的结果，平台为 ArduCopter 与 Boeing 的无人直升机 Little Bird，威胁模型是无物理接触、无线攻击、可看到全部源码并旁听开发者会议且假定硬件正确。他先论证时机：摩尔定律与丹纳德缩放在丹纳德失效前的积累，SAT 竞赛从 2002 到 2010 在同一台机器上求解 80 题的时间从 1000 秒降到 40 秒、即两个数量级且叠加于硬件进步之上，加上近十到十五年工具生态爆发使人不必再自研工具，并引用 seL4 负责人 Gerwin Klein 的观点。HACMS 阶段一无防护的商用 ArduCopter 被位于纽约 Rome 的 AIS 红队完全接管，改造后在 FreeRTOS 之上加硬件抽象层、改用 NICTA 正在被验证的实时操作系统 eChronos，航控代码用 Haskell 内嵌的领域专用语言写成、生成内存安全的 C 并附带可被其他形式化工具消解的整数溢出断言，Rockwell Collins 提供描述软硬件架构的架构描述语言；阶段一末 80% 软件由高保证工具写出，红队拿到全部源码六周后未找到安全缺陷，DARPA 同行的评估是这台四轴飞行器大概是地球上最安全的无人机。阶段二把它拆成双处理器（飞控跑 eChronos、任务控制跑 SEL4、CAN 总线互联）并把代码移植到 Little Bird，Boeing 载人并配安全飞手的试飞未察觉飞行差异；四轴飞行器航控代码 100% 高保证，红队拿到 SEL4 隔离内核某一分区内的 root 权限后既无法逃逸沙箱也无法干扰飞行。他还给出形式化方法光谱：类型系统最省力但保证最弱，符号执行如 Klee 可扩展但性质偏弱，模型检查经微软驱动程序强制通过以大幅减少蓝屏，有保证的静态分析如 Astrée、Frama-C、Infer 分别用于空客、PolarSSL 与 Facebook 全站，验证过的运行时监视如 Chrome 的 NaCl（转写 Roxal），自动定理证明如中国某团队验证的车载实时操作系统 OrientOS（约 140 万辆车在用）与微软的垃圾回收器，以及交互式证明助手如 seL4、CompCert、UCSD 用 Coq 验证的浏览器与 MIT 即将在 SOSP 报告的已验证文件系统；另引用 2009 年 ACM Computing Surveys 的问卷，62 个小组中 35% 认为形式化方法使项目更快、53% 认为无影响、12% 认为更慢，而代码质量普遍改善。（YouTube EPSITk8Y-WiVM，[10-2188]，L1）
- 〔会议不详（推测 安全类会议）〕两个标杆项目、采用障碍、经验教训与遗留难题。讲者详述 seL4 微内核：以 Isabelle/HOL 实现并证明正确，实现一万行代码、证明四十八万行，用时十三人年（若重做估计八年，因有五年花在可复用的基础设施工具上），进程间通信从最先进实现的 206 周期到它的 227 周期，并证明访问控制、不同进程不互相干扰、无时序侧信道泄漏，且验证了 C 到汇编的翻译与 IPC 快速路径；以及 CompCert 被验证的 C 编译器，Xavier Leroy 2006 年公布（2004 年时人们还认为不可能），覆盖航空工业所用不含并发的 C 子集，用 Coq 编写并从中抽取可执行代码、三 Xavier 人年完成，性能比未优化的 GCC 快两倍、比 -O1 慢 7%、比 -O2 慢 12%，正在认证以便编译空客软件。他列出障碍：专家稀缺（估计不足 6000 人，但可教，他提到与 Andrew Appel 谈到其普林斯顿课程每年五六十人）；工作量差异极大（seL4 因规格与性质极深而证明庞大，CompCert 编译器约一万行、证明约三万二千行，因为“生成代码正确实现源语义”比规范一个操作系统容易得多）；出资方与承担后果者往往不是同一人；性能上被验证代码并不天然更慢，但把更快的代码验证完更耗时，Chrome 的验证沙箱每秒处理一百万条指令反而快于原有检查器，因为可证明不变量从而删掉冗余检查；延迟与特性完整度不足，Facebook 用 Infer 一夜四小时扫完全站并把反馈纳入提交流程、单开发者平均十分钟内得到结果，但只覆盖空指针与资源泄漏。他强调小字重要：Utah 的 John Regehr 用 Csmith 做编译器模糊测试，在 PLDI 2011 报告发现 325 个 C 编译器漏洞，CompCert 的漏洞位于未验证的前端解析器与底层硬件模型中、事后已修复并验证，但 Csmith 在 CompCert 中段编译器找不到任何错误代码，为此投入了六 CPU 年。经验教训包括不要验证既有代码、先用静态分析除掉明显漏洞、不要验证全部代码而要留出被验证的小内核（如 quadcopter 上红队分区的相机代码可以任意行为）、善用领域专用语言提高抽象层级、自动化与 Coq 战术库至关重要（Adam Chlipala 的战术库使文件系统验证在五年人年内完成）；遗留难题是需要可被社区共同认可的 Linux、x86、POSIX 与浏览器 API 模型（剑桥的 Peter Sewell 在做）、大规模证明工程管理、让人接受推广（Amazon 团队改称“可穷尽测试的伪代码”后立刻有十几个团队跟进），以及房间里的大象并发——加一把锁可能使证明义务翻倍，NICTA 的 Gernot 提出了有意思的想法。问答中他谈到 seL4 已跑在 Qualcomm 手机上与 Boeing 试飞的直升机上、原论文发表于 2009 年 SOSP，北美用 Coq 生态更顺（Adam Chlipala、Benjamin Pierce、Stephanie Weirich、Steve Zdancewic、Greg Morrisett）而 seL4 用 Isabelle，物理辐射侧信道不在其模型内因而无法被证明，验证与验证之外的有效性问题同样重要。（YouTube EPSITk8Y-WiVM，[2188-4366]，L1）
