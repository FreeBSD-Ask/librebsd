# 321.4.53 〔FAST推测〕后半场讲解SpanFS的设计与评测SpanFS用多个互不重叠的微

- 〔FAST（推测）〕后半场讲解 SpanFS 的设计与评测。SpanFS 用多个互不重叠的微文件系统服务（domain）替换集中式文件系统服务，每个 domain 拥有独立磁盘结构与日志实例、可独立执行日志/提交/checkpoint，并通过块组重分配（block group reallocation）平衡存储空间；借 Linux 块设备架构为每个 domain 提供专属 buffer cache address space 避免底层锁竞争；命名空间经分布式对象（dentry 存父目录所在域、inode 存远端域）切分，崩溃不一致（stale dentry、不可回收的孤儿 inode）通过双向 remote entry 索引、在线完整性校验删除与后台 GC 解决；fsync 经由 JBD2 客户端-服务器架构向路径跨越的各 domain 并行提交事务，rename 原子性由有序事务提交保证。基于 Linux 3.18.0 的 XFS 实现、32 核 Intel 机器 + Fusion SSD 评测：append/delete 等元数据负载单核略慢于 XFS 但 32 核分别领先约 1.1 倍与 4 倍，chunked 负载约 7 倍；Filebench file server 与 dbench 在 32 核分别提升 73% 与 61%；300 万文件下后台 GC 扫描仅约 20 秒、前台吞吐仅降 12%（且仅在崩溃后运行）。问答说明 domain 数可少于核数（4/16 域即可显著获益），动态域数调整留作未来工作。（YouTube EP7yDk2uEO_g8，[408.1-1286.2]，L1）
- 〔会议不详〕共同一作 Jiyoung Kim 介绍 Dogi——面向日志结构系统（log-structured systems）最小化写放大（write amplification）。日志结构系统把小随机写转为顺序追加写获得高吞吐，但更新旧数据会产生无效块，须由垃圾回收（GC）先拷贝有效块再批量擦除，写放大因子（WAF）度量这一开销；数据放置（data placement）技术通过预测每块失效时间并按相近时间分组避免 GC 拷贝。作者以近最优基线 DoDa（精确知晓失效时间、离线最优分组配置）为参照，剖析 Midas、Sepbit、PHFTL、MLDT 四种 SOTA 技术的三步工作流（预测失效时间、按固定组数分组、按年龄迁移 GC 残留块），发现三处缺陷：启发式与机器学习预测精度均远低于 DoDa、WAF 高出约 2.5 倍，而 ML 预测延迟高出约 6.5 倍；组数选择不当（MLDT 在 3 组最优、组数再增预测更难导致错配）；按年龄单向迁冷使 WAF 比按剩余失效时间迁移高出 19%，整体至少比 DoDa 高 2.5 倍 WAF。（YouTube EP81UYq6ZDCCY，[18.2-498.0]，L1）
- 〔会议不详〕后半场给出 Dogi 的三项设计与 ZNS SSD 上的评测。针对“最热与最冷块两类预测方法精度相近、温块上 ML 更准”的实验发现，Dogi 用 hot filter（启发式、低延迟）滤出最热块，其余交给轻量多层感知机（6 输入特征、10 输出类别）；以 ML 预测日志中各组占比与训练期实测失效率计算误预测率，输入马尔可夫链模型预测各候选分组配置的 WAF 并择优在线应用；GC 残留块先用 frozen filter（启发式）筛出极冷块，其余按预测日志计算剩余失效时间并赋予 GC 类别、可迁往任意组。原型实现于 ZNS SSD、六种负载对比四种 SOTA：平均 WAF 较最佳基线降低 15%，在 FarMail、Alibaba、Exchange 等动态 I/O 模式负载上优势更大；组件消融显示分组与 GC 迁移分别降低 WAF 15% 与 22%、用户块分离单独使用反而增加 1%；吞吐高于各 SOTA，预测延迟远低于 ML 型 PHFTL、与启发式 Sepbit 相当。（YouTube EP81UYq6ZDCCY，[493.1-933.4]，L1）
- 〔USENIX Security（推测）〕讲者（与 Bar-Ilan University 的 Benny Pinkas 教授合作）介绍《From IP ID to Device ID and KASLR bypass》——用 16 位 IP 头分片字段 IP ID 做设备追踪。跨站追踪/实时定向营销虽遭人恨，但也有欺诈检测等正面用途；IP ID 本应为分片服务、在同源-目的对上不应短间隔重复且不可预测，Windows 与 Linux/Android 的现代实现都用“数千计数器数组 + 以源/目的 IP 与密钥的哈希索引 + 递增（Linux 另加基于时间的随机量，Windows 另加第二个哈希）”的结构。攻击通过嵌入任意网站的 JavaScript 跟踪片段强迫浏览器连接多个攻击者控制的 IP 并收集 IP ID，利用计数器哈希碰撞（不同 IP 在不同时刻由同一计数器生成 IP ID）以 GF(2) 上的 15 位方程组求解密钥（Windows 因 Toeplitz 双线性哈希极弱，分两阶段恢复 41-45 位）；该密钥仅在启动/重启时重新生成，跨浏览器、隐私模式、VPN 与网络切换不变，因此充当稳定的设备 ID，且每个站点可用不同目的 IP 集规避检测。（YouTube EP83Upk_WR2JY，[10.3-557.4]，L1）
- 〔USENIX Security（推测）〕后半场延伸到 Linux/Android 与 KASLR 绕过。KASLR 随机化内核镜像加载地址以防 ROP/JOP 攻击，枚举随机偏移因每次猜错导致系统崩溃/冻结而不可行；而 Linux/Android 对无状态协议（UDP、ICMP）的 IP ID 算法把内核静态变量 net 的地址（含 KASLR 偏移位）与 GFS 时钟计时参与密钥，密钥空间仅 32 位。攻击令浏览器发送约 400 个 UDP 包的突发（可经 WebRTC 的 STUN 包实现），以 IP ID 差小于 180（对比随机对的均值约 3.2 万）筛出桶碰撞候选对，再枚举 32 位密钥与 KASLR 偏移（新内核 9 位、Android 16 位），碰撞真值数超过阈值 11 即命中——同时得到密钥与 KASLR 偏移，即实现 KASLR bypass。Microsoft 于 2019 年 4 月修复并发布 CVE，Linux 亦发布两个 CVE 且作者参与向 3.x 旧分支贡献修复；结论是即便生成看似非安全的 IP 头这类数据也要用工业强度加密与足够大的密钥，且切勿把内核地址等敏感数据纳入密钥。问答说明 WebRTC/STUN 获取 UDP 途径，及 Windows 亚秒级、Linux 32 位秒级而 41 位约 12 小时（普通机器）的破解耗时。（YouTube EP83Upk_WR2JY，[567.4-1161.8]，L1）
- 〔会议不详〕来自 Johns Hopkins University、Hewlett Packard Labs 与 UC Riverside 的合作团队提出互联网公平包调度的新方法 SCRR。理想调度器应为延迟关键应用（如 Zoom）提供低延迟、为大流提供高吞吐、无需配置即可公平分配带宽；调度无处不在——主机 QDisc 层、网卡多队列、交换机路由器乃至 I/O 与进程调度器。经典方案中自时钟公平队列（SCFQ）排序开销大而不可实现，1996 年的 deficit round robin（DRR）快速可扩展却依赖两个假设：所有流持续积压、包长分布不偏斜（quantum 须不小于最大包）；用 ISP 骨干、园区、数据中心公开 trace 计算突发长度分布显示不到 1% 的突发超过 10 包、包长从 60 字节到 jumbo 悬殊，假设已不再成立。在 8 条单包请求-响应流与 72 条 TCP Cubic 背景流共享 DRR 瓶颈的实验中，大 quantum 使短包高延迟、小 quantum 使 CPU 因频繁轮转与缓存压力升高，即使启用 sparse flow 等优化也存在无正确答案的配置两难。（YouTube EP85fAV2OZduc，[16.2-387.8]，L1）
- 〔会议不详〕后半场给出 SCRR（self-clocked round robin）设计与评测：用自时钟语义取代刚性 quantum——由进展最多的流定义全局时钟，按包的虚拟开始时间（队尾包虚拟时间加包长；非活跃流取全局时钟）在轮询中发送直到队首包虚拟时间超过时钟，每轮每队列保证至少发一个包以防饥饿且不影响公平界；传输粒度随网络中最大包长动态自适应。针对短、突发、延迟敏感流的三项增强：initial advance（新活跃突发流可立即发送多个包而不违反调度界）、sparse flow 与 no-empty 优化（两条链表分离新流与积压流、无需每包元数据），使请求-响应负载短突发流延迟改善 45%、流式负载改善 15%。评测：SCRR 延迟较 DRR 最优配置低 4 倍（最差配置低 8 倍），CPU 利用率较 DRR 最差情况低 2.6 倍；与各范式对比中，较 DropTail 低 15 倍、较默认 Linux I/O 调度器低 50%、较 SCFQ 低 20% 延迟且兼得低资源占用；理论证明其公平份额与 DRR 相同、每轮各流距全局时钟不超过一个包、每轮每流突发不超过 2 个 MTU，是 DRR 的即插即用、无参数替换。（YouTube EP85fAV2OZduc，[424.5-941.2]，L1）

- 〔会议不详〕事务内存与弱内存模型的结合。主讲人（与 Nathan Chong、Tyler Sorensen 合作的学者）讲解弱内存：并发程序在顺序一致性（SC）下只有三种交错结果，但在 x86 上运行约十万次可能出现 SC 无法解释的第四种 0-0 结果，即弱行为；IBM Power、ARM、Nvidia/AMD GPU 以及 C++、OpenCL、Java 都存在弱内存。团队把已有弱内存模型扩展出事务语义，覆盖 x86、Power、ARM 与 C++，并验证了加事务不会让禁止行为变为允许的数学性质。（YouTube EP0MBUhonK2NY，[64.0-467.4]，L1）
- 〔会议不详〕模型验证与 ARM lock elision 反例。五项验证包括查手册、咨询各公司工程师、检查数学性质与编译器映射，最关键的是把模型放入约束求解器生成恰在允许/禁止边界的测试并在真实 x86 与 Power 硬件上大量运行。随后展示 ARM 上弱内存、事务与 lock elision 的组合是有毒的：两个临界区并发下 x 可能得到错误结果 2，该反例可由约束求解器自动生成，ARM 团队已修复。（YouTube EP0MBUhonK2NY，[476.5-848.2]，L1）
- 〔ASPLOS（推测）〕Finding Nemo：灵巧而富有表达力的内存可观测性。演讲者 Matthew 与 Vic（合作论文）指出数据中心多层内存（NUMA、CXL）与翻译开销使操作系统亟需内存遥测，但现有方案（soft page fault、page table 扫描、Intel PEBS 采样）都在保真度与开销间取舍，如 MemTIS 采样 LLC miss 会扭曲 huge page 偏斜度分布。Nemo 在内存控制器这一能观测每次 LLC miss 的位置做遥测，请求复制后离数据处理，用 match/update/notify 三段流水线加两级翻译实现任意 2 的幂粒度的可编程匹配。（YouTube EP0XP66s10UD4，[19.4-509.9]，L1）

- 〔OSDI〕数据感知集群调度中选择的力量。主讲人 Shivaram（合作者 Arunesh Panda、Ganesh Ananthanarayanan 及导师 Mike Franklin、Ion Stoica）指出大数据与低延迟两大趋势相互矛盾，而 BlinkDB、Facebook 的 Presto、SGD 类机器学习等应用本身只处理数据子集。核心洞察是采样意味着大量输入选择自由（n 选 k），现有调度器未能利用这一点；为利用该特性，KMN 调度器让任务物化为 DAG，在前一阶段多发少量额外任务即可换来数据局部性与更少跨机架传输。（YouTube EP0e8UdWzD_5k，[21.6-740.6]，L1）
- 〔OSDI〕局部性分析与跨机架偏斜治理。内存带宽比 10 Gbps 网络高约 50 倍，解析模型显示 10% 采样率下即使 90% 集群利用率也能保持高局部性概率；many-to-one 阶段中 Facebook Hadoop trace 显示大于 50 任务的中大型作业中位跨机架偏斜不低于 4，多发额外任务可把偏斜从 3 降到 2（一般形式映射为 NP-hard 的设施选址问题）。系统基于 Apache Spark 实现仅需一行改动，回放 Facebook 作业获得 60-90% 改进，10% 额外任务即可获得大部分收益，相关工作包括 Sparrow（SOSP 2013）、Quincy、Dolly。（YouTube EP0e8UdWzD_5k，[581.6-1480.3]，L1）
- 〔FAST（推测）〕MoST：用跨层镜像实现分层存储负载均衡。主讲人 Kai Wei（与 Google 合作，转录中称 Udacity 应为 UW）指出低延迟 SSD 使存储层级变扁平，传统把热数据放性能层的方法在负载密集时性能层饱和、容量层闲置；迁移类系统有三大缺点：后台流量与应用争带宽、难适应突发负载、额外写入损耗设备寿命。MoST 只镜像少量最热数据，通过 load switch 按卸载比例路由读流量，配合基于延迟的反馈式 optimizer 动态调参，无需迁移即可负载均衡，评估最高取得 2.3 倍吞吐并减少 84% 设备写入。（YouTube EP0rYxUJjxrW4，[18.2-500.8]，L1）
- 〔FAST（推测）〕写负载处理与实现评测。写只发往一份副本会使另一份失效、长期削弱读均衡，MoST 对读多写少的数据后台重镜像、对写密集数据让写本身充当均衡器；为避免 2 MB 元数据块上的部分写（partial write），把元数据切成 4 KB 子页独立写，使 2 TB 层级的元数据从 13 GB 降到 140 MB。实现基于 Meta 开源 FlashCache（CacheLab），在 Intel Optane SSD 加 Samsung flash SSD 上对比 striping 与迁移类分层系统：动态突发负载下迁移类系统（如迁移 400 GB 的 Cloyd）反而比不均衡基线低 26%，MoST 达到 1.5 倍基线吞吐、比迁移方案高 45%，写密集场景也比 Cloyd 高 27%。（YouTube EP0rYxUJjxrW4，[385.7-946.5]，L1）
