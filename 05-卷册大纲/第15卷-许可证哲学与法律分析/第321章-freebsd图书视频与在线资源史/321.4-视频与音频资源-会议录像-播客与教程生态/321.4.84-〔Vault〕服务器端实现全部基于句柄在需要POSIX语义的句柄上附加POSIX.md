- 〔NSDI〕Canvas：面向多应用远程内存交换的隔离与自适应系统。主讲人 Yifan Qiao（UCLA 四年级博士生），与 UCLA、UCSD、清华大学及 Princeton 合作；摩尔定律放缓带来内存容量墙而数据中心内存又常闲置，远程内存（经 RDMA 或 CXL 连接内存池，应用借内核 page fault 与 swap 透明访问）是解决方向，但现有工作多只优化单应用。动机实验显示 4 个真实云应用在最新远程内存交换系统上共跑时，即便用 Linux cgroup 隔离 CPU 与本地内存仍出现不可预测降速，根源是共享内核远程内存数据路径的三类干扰：共享 swap cache 锁与 swap 分区分配/释放的锁竞争使整体交换吞吐下降 56%，共享预取器因共跑应用访问轨迹混合而失效，内核不控制交换的网络带宽使 99 分位网络时延增加 2.1 倍。（YouTube EPE_W5gupUeB0，[13.9-402.5]，L1）
- 〔NSDI〕Canvas 为每个应用构建完全隔离的交换数据路径（专属预取器、swap cache、swap 分区与 RDMA 带宽），并据此做自适应优化：对 Spark 以每线程模式跟踪器只为有顺序访问模式的 mutator 线程预取、用二维 RDMA 调度器协调应用线程与预取器带宽、用自适应分配器降低远程内存分配率以减轻锁竞争；核心的自适应条目分配器在页上记录首次分配的 swap entry ID 形成一对一保留映射，使后续换出无锁直写，内存吃紧时再按内核 LRU 列表回收条目以时间换空间。在 Linux 5.5 上评测：不同本地内存配比下较 FastSwap 整体提升 3.5 倍与 1.9 倍，Snappy、Memcached、XGBoost 共跑性能波动平均降低 7.4 倍（一个数量级）；结论是云多租户性质决定远程内存需要性能隔离、Canvas 是首个提升多应用远程内存性能与 QoS 的系统，且隔离解锁了自适应优化，代码已开源。（YouTube EPE_W5gupUeB0，[437.7-855.4]，L1）

- 〔USENIX Security〕去污安全收益的量化：phpMyAdmin 映射到源码的 20 个 CVE 中文件级可移除 20%、函数级 60%（WordPress 仅 0% 与 10%）；加密与 cookie 类漏洞遍布全库难以移除，CSRF 仅在底层特性被移除时消除，而代码执行类漏洞常经 PHP 对象注入（攻击者控制进入不安全反序列化的字符串，复用应用内对象并依赖自动执行的魔法函数组成 gadget 链）利用——基于 PHPGGC 已知 gadget 链测试，文件级可移除 6 条中的 4 条，函数级可破坏全部已知 gadget 链。外部包是膨胀主因：phpMyAdmin 外部包代码量约为主程序两倍、45 个包中 38 个从未被执行，函数级去污可移除 80% 以上的外部包代码行。结论：Web 去污最多可减少 71% 逻辑代码行、60% 的 CVE 与 100% 的对象注入 gadget，但 Web 去污不同于二进制去污、不能只删死代码，还需提升可用性与性能才能低开销上线；流水线、去污后应用与 CVE 映射发布于 debloating.com。（YouTube EPEbKpD0bj89A，[568.0-899.3]，L1）

- 〔会议不详〕网络研究者报告 Velo：首个在链路故障与路由变化下求最坏链路负载的系统。作者以 ISP 网络运营商排查拥塞为动机，指出此前工作（如 QARC）只考虑链路故障而忽略按 BGP 路由转发的现实，实验显示仅计至多两重链路故障时每条链路中位数约低估 20% 额外负载，而再计入至多 10 个目的地路由任意变化后中位数达 60%–70%、最高约 130%。挑战在于搜索空间巨大（仅 30 个 BGP 邻居即约十亿种路由输入）、故障在不同目的地与路由输入间引入依赖、以及 BGP 超百万目的地带来的超大输入空间；Velo 的第一项技术是按故障逐一分解、在单个故障内独立求各目的地最坏情况再合并，并基于热土豆路由最优子路径性质证明移除非当前选中的 egress 不会降低链路负载、最坏情况只出现在单一 egress，该结论对沿最优路径路由的协议与 ECMP 负载均衡均成立。（YouTube EPEgBhDMMPrDc，[16.4-519.5]，L1）
