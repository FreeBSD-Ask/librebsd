# 321.4.63 〔USENIXSecurity推测〕ComRace检测COM对象中的数据竞争漏洞

- 〔USENIX Security（推测）〕ComRace：检测 COM 对象中的数据竞争漏洞。主讲人 Fangming Gu（中科院信息工程研究所）介绍：COM 是微软 1993 年推出的二进制接口标准，广泛部署于 Windows 用户态（Office、浏览器 ActiveX、DirectX、UMDF 驱动等）并以 apartment（STA/MTA/NTA）线程模型封装线程共享规则，MTA 与 NTA 对象若不保证线程安全便易遭数据竞争攻击。以系统服务进程中的 GeoLocation 对象为实例，并发调用两个接口方法会因读写同一共享变量且一处 free 而触发 use-after-free 或 double free，多数情形可导致提权；由此提出静态分析工具 ComRace，分四步：提取 COM 对象（读注册表 HKCR\CLSID 下的 CLSID、线程模型、服务权限等）、还原接口实现（借 .NET 反编译与基于对 Windows 二进制三条关键观察的 vtable 重构启发式）、识别不安全方法（追踪 this 指针访问未加同步的成员域）、合成 PoC exploit。（YouTube EP9bBh2YEqVMA，[7.9-354.4]，L1）
- 〔USENIX Security（推测）〕ComRace 评测：26 个已确认提权漏洞。不安全方法与未加保护字段访问按 read-read、read-write、write-read、write-write、write-free、free-free 六类竞态上报，PoC 合成基于预定义骨架程序，用接口依赖图生成获取接口类型参数的调用序列，编译后并发运行并收集运行时信息。在 Windows 10 上 ComRace 成功分析 92.1% 的 COM 对象，8 万余个支持 MTA/NTA 线程模型、463 个跨进程 COM 对象易受攻击；62% 的已验证 PoC 可触发内存破坏，26 个已确认漏洞全部可提权、23 个可逃逸 Windows 应用容器沙箱、20 个可提权至 NT AUTHORITY\SYSTEM。在开源 ReactOS 上的精度评估：成功提取 147 个 MTA 对象、恢复 152/172 个接口，假阳性率 31.4%；工具共合成 234 个 PoC，暴露 26 个 CVE。（YouTube EP9bBh2YEqVMA，[354.6-716.9]，L1）

- 〔SREcon（推测）〕域名与 DNS 安全最佳实践及工具演示。注册商保护：client 转移/更新/删除锁需授权码，server 锁更安全但每年每域名 500-2000 美元且仅少数注册商支持（如 MarkMonitor、Cloudflare），普通用户可用 2FA、IP 白名单与 Okta SSO 加固注册商门户；建议部署 DNSSEC 防中间人改写、在多个 AS 与多 DNS 提供商间分散名字服务器以保证可用性（参照 Dyn 大规模故障教训），加长 TTL 并非好办法。邮件 DNS 记录（SPF/DMARC/DKIM、TLSA 证书公钥哈希校验、MTA-STS 强制认证加密、SMTP TLS 报告、BIMI/VMC 验证徽标）连同不发邮件域名也应配置否定性记录；另建议实现 security.txt 与 CAA。作者受 SSL Labs 与 securityheaders.com 启发开发 domainlabs 工具现场演示：Top 千域名中 Yahoo 得分最佳（客户端与服务端锁全开但无 DNSSEC、无 BIMI/TLSA），YouTube 反而偏低，并展示即将过期域名（pendo.io、googleanalytics.com）监控。（YouTube EP9bhyyC9tFMs，[567-1125.2]，L1）

- 〔ACSAC〕（推测）波鸿鲁尔大学博士生 Emre Gülal 报告如何把模糊测试原理应用于 Web 应用以发现 SQL 注入、PHP 命令注入等服务端漏洞，团队据此构建模糊测试器 Atropos，方法不限于 PHP。他指出静态分析工具误报多且缺少可直接执行的测试用例，而 Web 应用的输入空间以键-值对为主且字符串密集：必须同时命中正确的键全串、正确的值全串及两者关联，简单的位翻转无法探索行为空间，因此仅靠代码覆盖反馈不足以覆盖全部行为空间。（YouTube EP9j_snus1mPo，[8-390]，L1）

- 〔FAST〕（推测）石溪大学 Pradeep Shetty 报告用 VT-Tree 构建工作负载无关的存储（与 Ravi Kannan 等同事及导师 Erez Zadok 教授合作）。ext4 等原地 B+ 树随机写伴随写放大，LFS 解决随机写却使顺序读退化为随机读，LSM 树随机写与顺序读良好但顺序写因 minor compaction 产生 log n 轮冗余拷贝。VT-Tree 对 LSM 的扩展是拼接（stitching）：minor compaction 时与其他参与表不重叠的 SSTable 块只拷贝二级索引项而不搬数据，示例中块写从 6 次降为 2 次；由此引入的内部碎片用 stitching threshold 与按连续跨度评分的 zone 级碎片整理（权重只保留顺序性）缓解。（YouTube EP9nMwkeyEC8M，[10-710]，L1）
