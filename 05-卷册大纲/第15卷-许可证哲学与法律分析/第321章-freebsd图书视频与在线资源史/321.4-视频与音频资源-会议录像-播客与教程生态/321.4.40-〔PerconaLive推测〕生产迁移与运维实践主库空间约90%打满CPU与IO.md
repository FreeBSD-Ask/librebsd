# 321.4.40 〔PerconaLive推测〕生产迁移与运维实践主库空间约90%打满CPU与IO

- 〔Percona Live（推测）〕生产迁移与运维实践：主库空间约 90% 打满、CPU 与 I/O 空闲，目标是空间减半并同机合并两个实例（曾评估 TokuDB 但 CPU 太高而放弃）。迁移流程包括停一台从库做逻辑导出、以主键序直写最底层 SST 文件（写放大为 1）的快速加载、InnoDB 与 MyRocks 间的四类数据校验（索引行数、统计信息、同 GTID 快照下 SELECT 比对、审计插件影子查询），再用开源的 MyRocks Hot Backup 二进制备份快速生成第二副本，经影子流量验证后提升 MyRocks 为主库、保留 InnoDB 以便回切；崩溃安全上补齐 binlog 与 RocksDB WAL 的两阶段提交，并治理 LSM 写停顿（write stalls：软停顿限速 16MB/s、硬停顿阻塞写入，默认 64GB pending compaction 限制、L0 十个文件阈值），用 LZ4/Zstandard 分层压缩、增加 compaction 线程、放缓 SSD 文件删除规避 trim stall，最终以空间减半与数据正确性检查支撑生产部署。（YouTube EP5X2bSHPWUqg，[1485.2-2979.3]，L1）
- 〔会议不详〕密歇根大学 Hassan（导师 Moinuddin Qureshi）介绍面向远程内存的轻量高效数据通路 Leap。内存密集型应用内存不足时性能断崖式下跌——VoltDB 被拿走 25% 内存即换页到磁盘、损失约 80% 性能，PowerGraph 拿走一半内存损失约 75%，性能损失与内存损失严重不成比例（38 倍与 4 倍）；云端用户只能过量分配内存，导致 Google、Facebook、Alibaba 等大集群约 30-40% 的内存长期闲置且分布不均。内存解聚合（memory disaggregation）借助 RDMA 用集群全局内存池缓解，但 4KB 页经 RDMA 访问约 4 微秒、有背景负载时达数十微秒，远超 3 微秒的不可感知上限；分析 Linux 内核缺页路径发现传统块层的请求队列合并等屏障操作对远程存储毫无价值，故设计软件在线预取器 Leap：削减慢路径块层操作、用固定大小环形缓冲记录各进程页访问历史、以多数投票法检测模式并配合急切缓存淘汰（eager cache eviction）提升缓存命中。（YouTube EP5Xs8y0cwOSA，[7.8-656.9]，L1）
- 〔会议不详〕Leap 预取器细节与评估：与只看最近两次访问、遇不规则即关闭预取的 Linux readahead 不同，Leap 以线性时间、常数空间的 Boyer-Moore 多数投票算法在小窗口内找多数趋势，窗口逐级放大到上限，可容忍短期不规则访问，并按缓存命中情况渐进调节预取窗口尺寸（无命中时减速但不骤停）。实现在 Linux 4.4 内核并部署于 RDMA 集群、集成进 Infiniswap 与 Remote Regions 两个解聚合框架：顺序模式下 Infiniswap 远程 4KB 页访问中位延迟改善 4 倍，PowerGraph 上多识别 30% 顺序访问与约 14% 的不规则模式，VoltDB 仅剩 25% 内存时性能损失仅 2.4%（接近本地内存）；瘦数据通路本身带来最高 95 分位约 1 微秒延迟收益，预取器再添亚微秒收益、尾部延迟再降 12%，急切淘汰策略又降 22%。未来方向包括线程级预取与页跟踪、优化 I/O 接口等。（YouTube EP5Xs8y0cwOSA，[657.1-1306.6]，L1）
- 〔会议不详〕与 Maverick Wu、Brian Parno 合作的报告，主题是减少逆向工程的繁琐：遗留软件源码常不可得，反编译器虽历经数十年研究仍输出欠佳——NSA 的 Ghidra 对单链表把 node 指针变成 undefined4*，Hex-Rays/IDA Pro 甚至把 4 字节 int 变成 int64。以往学术工作分推导式“类型恢复（type recovery）”与机器学习式“类型预测（type prediction）”两路，都试图恢复源代码类型，但其隐含假设“完美恢复工具能还原源码类型（仅差重命名）”被证明根本不可行——不存在唯一的真值（ground truth）；因此应转向“类型重建（type reconstruction）”，以逆向工程师真正想理解程序行为为目标、用类型捕获可观测行为，并据此提出新的约束式推导工具 T-Rex，支持输出全部 C 标量类型、指针、结构体、联合、数组及链表等递归类型。（YouTube EP5cOyIJt2cAw，[10.2-288.7]，L1）
- 〔会议不详〕T-Rex 的方法与评估：尽量推迟到分析后期才使用类型，采用能精确刻画行为（即使不可用 C 表达）的结构类型（structural types），再经“type rounding”（证明为 NP 难）扩展出符合惯例的 C 型输出（如支持加减除的类型顺带支持乘法，对应 int32_t）。单链表示例上 T-Rex 完全正确，而 Ghidra、Hex-Rays/IDA Pro、Binary Ninja 均错误；机器学习方法 RE-Sim（上年杰出论文奖）仅 2% 正确且结果不确定，T-Rex 完全确定。在既有恢复指标上优于 Kitra 与 REM，而在面向逆向工程的新评分指标下 T-Rex 优于 Kedra 与 RE-Sim，Gator 与 REM 排名互换；结论是即便在 ML 时代，推导式技术在正确性攸关场景仍有很高价值，制品已开源、可复现。（YouTube EP5cOyIJt2cAw，[289.7-583.7]，L1）
- 〔会议不详〕中国科学技术大学的 Qin Yang Zhang 报告混合存储设备上排序型 KV 存储资源依赖缓解的工作（论文题：Mitigating Resource Usage Dependency in Sorting-based KV Stores on Hybrid Storage Devices via Operation Decoupling）。LSM-tree 型 KV 存储（LevelDB、RocksDB、Cassandra、TiKV）依赖后台 flush/compaction 等数据整理操作，在由 NVMe SSD、CXL SSD、持久内存等快设备与 HDD/SSD 慢设备组成的混合存储上，热数据（memtable、低层）放快设备、冷数据（高层）放慢设备是常见做法，但排序操作存在三重耦合：固定阈值被动触发造成的相邻层操作依赖、写重负载下多层级同时整理的资源竞争、以及单操作内 CPU 与 I/O 消耗交织（compaction 的归并排序偏 CPU、读写偏 I/O）；实测快设备（PMEM、NVMe）上 CPU 时间占 compaction 60% 以上成为瓶颈，慢设备上 I/O 带宽为瓶颈，瓶颈随设备交替导致利用率波动大、资源碎片严重。（YouTube EP5cshtHqVtfo，[18.1-444.3]，L1）
- 〔会议不详〕方案与结果：其系统将数据整理操作解耦为资源独立的单一资源任务——把 SST 解耦为索引与数据两部分，用 DRAM 中的索引表与可归并跳表结构承载 CPU 密集的索引归并任务，用快设备上的未排序追加写（AOF）文件承载 I/O 密集的数据追加与刷新任务，并以索引归并队列（IMQ）与数据 flush 队列（DFQ）的长度感知 CPU/I/O 资源状态进行自调度（CPU 紧张时少触发索引归并、多调度 I/O 任务）；高层因内存限制与慢设备随机读差仍用 leveled compaction，但放宽容量阈值以缓解操作间依赖。在 Optane、NVMe（快）与 SATA SSD（慢）上对比 RocksDB 及 MatrixKV、ADOC 两类代表工作：平均 CPU 利用率提升 25-32% 且波动区间收窄，插入/更新 P90 尾延迟降低 71-83%、P99 降低 74-91%，吞吐提升 1.6-4.3 倍、平均延迟降 38-77%，YCSB 写重负载（A、F）提升 1.4-4.9 倍，内存开销与同类工作相当。（YouTube EP5cshtHqVtfo，[444.5-891.5]，L1）
- 〔会议不详〕Amelia（合作者含 Pedro Malagón、José Moya、Tomás Eisenbarth）报告利用缓存替换策略实施隐蔽缓存攻击的新方法。缓存攻击催生了对抗性防御，检测式防御用性能计数器（如 cache miss 数）为受保护进程建立行为模型，引出核心问题：攻击者能否不引发缓存缺失而从缓存获取信息？由于数据驱逐取决于其使用情况，团队聚焦决定逐出对象的替换策略与末级缓存（LLC），通过在软件中模仿硬件行为——已知内存块在缓存中的位置、可强制访问顺序并测量命中/缺失时间——逆向工程替换策略，在多代 Intel 处理器上得出观察：数据线性插入缓存组、仅 LLC 访问更新块年龄，四五代与六七八代实现看似自适应与固定两种，实则同为“驱逐年龄等于 3 的块”，仅插入年龄不同。（YouTube EP5etfntWcvik，[8.0-296.2]，L1）
- 〔会议不详〕据此提出 Reload&Refresh 攻击：利用替换策略知识把数据放入期望位置并操纵其状态，仅凭驱逐候选的变化即可区分受害者是否访问，全程几乎不引发受害者缓存缺失；攻击分准备缓存、等待受害者访问、强制缺失取信息、恢复缓存状态等阶段，并假设共享内存与可构造 eviction set。评估显示其准确率与 Flush+Reload、Prime+Probe 相当但分辨率更低（隐蔽性的代价），仍可用于密码分析——以相近性能恢复 RSA 私钥并提取 RSA 解密中乘法运算的执行序列，缓存缺失数可忽略；对性能计数器的分析表明仅 L2 指令缺失计数器能在所有场景（AES、RSA）区分攻击与正常状态，说明攻击者只要充分了解微架构即可针对检测算法可用的有限计数器集合隐藏攻击效果、绕过检测式防御，攻击概念验证已在 GitHub 开源。（YouTube EP5etfntWcvik，[317.2-593.8]，L1）
- 〔会议不详〕SBA Research 的 Dominic Schreiber（同事 Dimitris Simos、Manuel Leitner、Johann Cejvanovic，致力于数学基础与软件测试的桥梁）介绍用组合方法测试蓝牙低功耗（BLE）。组合测试（CT）基于 NIST 的经验观察——多数软件错误由少量（多为 1-2 个）参数交互触发；组合安全测试（CST）则专门构造长字符串等恶意输入以触发漏洞与未指定行为，此前已用于 SQL 注入、XSS 与 TLS 实现测试。其方法基于曾在同会议发表的 Greyhound 模糊测试器（最初面向 Wi-Fi，后扩展支持蓝牙经典与 BLE），借助 Scapy 扩展定义了 BLE 各协议层（含难以测试的链路层），为 nRF52840 dongle 开发可发送任意 BLE 包的自定义固件（USB 串口控制）与 BLE 状态机，以概率引导遍历状态机并操纵包字段值，启发式优化算法调参以最大化触发未定义行为。（YouTube EP5iotkYbcKcA，[18.7-478.3]，L1）
- 〔会议不详〕建模与实验结果：将 BLE 包视为由各层组成的复合系统，每层建一个强度 2 的覆盖数组（CA），再组合成强度 2 的元 CA（meta CA）以覆盖层间交互，用波浪号标记无效值并限制每条测试至多一个无效值以免过早被目标拒绝；值集来自蓝牙规范与 Scapy 定义分析，并加 unchanged/larger/smaller 关键字。测试搭建两块 nRF52840 dongle（收发与可用性 oracle）、MongoDB 记录，四套并行共测 10 家厂商的 10 款微控制器；问题多出现在协商连接参数的 initiating 状态，且全部问题仅由单个参数触发，按超时（TO）、手动复位可修复（URWF）、需手动复位（URN）与 core dump（疑内存损坏）四类归档。与原版 Greyhound 对比，CST 发现的漏洞更多、执行的测试更少而耗时相同；向厂商披露后 Espressif 确认并修复、支付漏洞赏金，Realtek 索要细节后不再回应，其余厂商无回应。（YouTube EP5iotkYbcKcA，[480.4-975.3]，L1）
- 〔OSCON（推测）〕Rob Pike 的主题演讲开篇谈 Go 语言“为什么值得做”。他引用 Dick Gabriel 对早期编程语言“轻触与静谧”的赞美——老程序读来像健谈的研究者与博学的机械同事间的安静对话，而非与编译器的辩论——并批评当下软件世界的过度精巧：C++0x 草案标准中描述函数名解析规则的一段话已超出其承受力，标准语言不带垃圾回收逼着人们在七个 Boost 模板指针类型中选一个管内存，网络上随处可见令朋友惊呼“上帝，让它停下来”的声明。他回溯个人版历史：C 与 Unix 先在研究界与学界称霸，Bjarne Stroustrup 把 Simula 的想法嫁接到 C 上造出 C++，随后作为简化版 C++ 的 Java 又成为教育界标准语言，应届生把这类语言的思维方式当作软件的正解——他明确反对，并借 Peter Norvig 的观点指出设计模式（patterns）不过是记法失败的证据，就像四十年前的子程序调用若在今天也会被叫做模式。（YouTube EP5kj5ApnhPAE，[3.4-371.8]，L1）
- 〔OSCON（推测）〕演讲后半给出语言设计诊方：Python、Ruby、JavaScript 等动态解释语言与 Haskell、Scala 等是对 C++/Java 官僚化编程的反动，但“动态好、静态编译坏”是伪二分——动态语言慢、类型不安全（错误推迟到运行时）、难扩展；静态编译语言在专家手里很强但难用、编译慢、二进制庞大、陈旧且对多核不友好。因此存在一个打破伪二分的新兴语言生态位：易理解、静态类型、页面美观、有趣好写、扩展性好、不依赖 IDE 工具、面向现代硬件与网络。Go 正是对这一生态位的尝试——结合静态编译语言的安全与性能和动态语言的灵活与乐趣，语法简洁、类型系统有趣而富表达力、以不同于 Java/C++ 的方式面向对象、并发支持强、垃圾回收、编译极快、运行速度快且完全开源实现，Python 用户称其用起来像 Python 而运行快得多；稍后楼下还有一场关于 Go 的演讲，更多信息见 golang.org。（YouTube EP5kj5ApnhPAE，[371.8-744.8]，L1）
- 〔SREcon（推测）〕Meta 高级生产工程师 Kyle 分享其职业生涯最难忘的一次事故，先科普亚稳态失效（metastable failure）：该术语 2021 年在 HotOS 的论文《Metastable Failures in Distributed Systems》中普及，三要素为触发器使系统进入坏态且移除触发后仍停留、坏态下系统近乎不可用、以及阻止自恢复的维持效应（sustaining effect）；它与级联失效（cascading failure）重叠但互相独立、并非子集关系。事故起因是欧盟团队在流量高峰时段做 DRP 负载演练（模拟最大区域宕机），随后一组机器地理相关性集体失联，按 runbook 断电重启后机器恢复又再次宕机，当时在东海岸赶飞机的主讲人一度怀疑是数据中心电力事故；主讲人随后讲解 Meta CDN 架构——照片/视频跨区双副本容灾、以区域权重（region weights）构成路由环（routing ring）、各 PoP 本地健康检查剔除故障区域、PoP-区域负载均衡-Web 服务器-转码器的请求流——并观察到请求在区域对之间因独立故障切换而来回“泼溅”，确认这是同时满足三要素的亚稳态失效：DR 演练已回滚（触发移除）、系统不可用、各区域恢复时遭雷群效应（thundering herd）。（YouTube EP5ksTcC3uSUE，[7.7-749.6]，L1）
