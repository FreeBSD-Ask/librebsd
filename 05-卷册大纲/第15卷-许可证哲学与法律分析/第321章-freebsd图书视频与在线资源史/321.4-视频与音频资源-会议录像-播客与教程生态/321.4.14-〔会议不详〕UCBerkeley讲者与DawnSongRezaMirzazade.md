# 321.4.14 〔会议不详〕UCBerkeley讲者与DawnSongRezaMirzazade

- 〔会议不详〕 UC Berkeley 讲者（与 Dawn Song、Reza Mirzazade 合作）介绍"用神经网络识别二进制中的函数"：剥离符号表的二进制需恢复函数起止以支撑控制流完整性等后续分析；演示 push rbp 等朴素模式在开优化编译后失效，综述 ByteWeight（USENIX 去年）等基于记忆函数起始指令序列的方法需反汇编规整化与昂贵静态分析，并系统讲解 embedding、循环神经网络如何处理变长字节序列、单向 RNN 只受历史影响的问题及双向 RNN（前向与反向隐层并行）的解决原理与梯度训练过程。（YouTube EP1_CqTuEj5gE，[10.4-837.2]，L1）
- 〔会议不详〕 报告实验：使用 ByteWeight 收集的约 2200 个二进制（Linux GCC/ICC 与 Windows MSVC、x86/x86-64、四种优化级别），训练 8 个双向 RNN（字节直接输入、单隐层 16 维、每网络训练 2 小时，按 start/end、OS、架构分别建模），十折交叉验证下函数起始识别错误率较 ByteWeight 降低 2.4 倍（仅一个 OS/架构分片略差），函数边界降低 1.6 倍，训练总时长 80 小时（去交叉验证约 8 小时，ByteWeight 报 587 小时），全量分析耗时从约 2 万分钟（约 14 天）降至 43 分钟（不足 1 小时）；并回应混淆二进制适用性、网络学到的模式（函数间 nop 填充误判）与 x86 非对齐常量对抗等提问。（YouTube EP1_CqTuEj5gE，[837.2-1572.2]，L1）
- 〔会议不详〕 讲者 Peter 介绍 Data Parallel Actors（DPA）——面向可扩展查询服务系统的编程模型：Druid、ClickHouse、Pinot、Timescale/Influx、文本与向量检索等系统都具有数据并行查询、低延迟专用数据表示与可批量化更新三大共性，但每套系统都自建复杂分发层（容错、复制、一致性），既阻碍新系统构建又缺负载均衡、弹性等用户所需特性；DPA 以封装不透明数据分区的有状态 actor 加集合操作统一分发层，可将单节点 Lucene、MonetDB 分布式化、以通用运行时替换 Druid 原生分发层，每系统定制代码不足千行。（YouTube EP1_OA63YZtNg，[15.6-467.5]，L1）
- 〔会议不详〕 介绍查询接口与评估：retrieve/combine 两算子即可分布式 Lucene 检索，scatter/gather 可组合 shuffle join、reduce by key 等复杂集合操作，开发者只需提供 actor 实现与查询规划器，通用运行时 Uniserve 负责容错/复制/一致性/负载均衡；适用边界为数据并行查询、低延迟专用系统与低写并发（不面向 Memcached 式点查与 OLTP）；评估显示 DPA 分布式 Lucene 对 Solr、DPA Druid 对原 Druid 的吞吐/延迟曲线基本重合，高度偏斜负载下因新增负载均衡反而显著更优，基于 MinIO 构建的简化数仓性能与 Redshift 相当。（YouTube EP1_OA63YZtNg，[467.5-853.7]，L1）
- 〔FAST〕 会议上由合作者代讲（西部数据 Damien Le Moal 团队，与 Karlsruhe 的 Johannes Thumshirn 合作、Ting Yao 因旅行限制缺席）介绍 zonefs：针对 SMR 硬盘与 ZNS 等分区块设备，将每个 zone 暴露为常规文件（分 conventional zones 与 sequential write required/preferred 两类目录，文件大小即写指针，挂载时向驱动查询），支持 conventional zones 聚合为单文件、默认属主/权限等挂载选项与 remount read-only、zone offline 等操作，把以往必须用 ioctl 精心对齐直写的访问简化为 POSIX 文件接口，zone reset/finish 映射为 truncate，可防止误写他区。（YouTube EP1c-vh7s7c2c，[5.4-607.0]，L1）
- 〔FAST〕 现场演示 15 TB SMR 盘（524 个 conventional zones、55000 个 sequential zones）上 zonefs 的目录结构与聚合模式，对比 ioctl（report zones/zone data 结构）与 zonefs 的 zone 报告、写入与管理差异；介绍 Ting Yao 修改 LevelDB 支持 zonefs 的数据论文（FAST）与 db_bench 结果（fill random+read sequential 下写性能远高于 ext4，但源于直写需打折扣、直接 I/O 不经页缓存使二读更快），并谈及 zonefs 已在 5.6-rc1 发布前一刻被 Linus 合入主线、配有独立测试套件，未来工作包括异步 I/O、zone 显式 open/close、NVMe zone append 与 SATA/libata 支持等。（YouTube EP1c-vh7s7c2c，[439.1-877.1]，L1）
- 〔USENIX Security〕 Sebastian Österlund 介绍 Parmesan——sanitizer 引导的灰盒模糊测试：指出覆盖导向"更多覆盖即更多 bug"的假设已难发现新崩溃，而现代编译器自带的 sanitizer 运行时检查（越界、整型溢出等）是天然定向目标，且部分 sanitizer 本身高靶向（只插桩高概率出 bug 的代码路径）；Parmesan 分离线/在线两阶段，离线用 LLVM diff 对比原程序与加 sanitizer 编译的 IR 提取插桩分支作为目标（对任意 sanitizer 通用），在线以模糊器协同动态控制流图定向引导。（YouTube EP1jnkOTNnQ_A，[8.3-280.8]，L1）
- 〔会议不详〕 介绍基于 Angora 覆盖导向灰盒模糊器的实现：队列按运行次数与到目标距离双键排序，用动态数据流分析确定决定分支与间接调用目标的输入字节（相比 AFLGo 的静态插桩距离，动态 CFG 可增量更新并解析间接调用），配以基于剖析（保留冷代码目标）与复杂度（插桩越多越可疑）两种启发式将数千目标剪枝至数百；评估较 AFLGo 到达目标最多快 290%，较覆盖导向模糊器触发 bug 快约 40%，且按所选 sanitizer 可定向特定类型 bug，代码已开源。（YouTube EP1jnkOTNnQ_A，[280.8-714.7]，L1）
- 〔USENIX Security〕 讲者 Kevin（Google 与柏林洪堡大学合作）介绍私有信息检索（PIR）中的通信—计算权衡：PIR 允许用户检索第 i 条数据而服务器不知所查索引，通信、服务器计算与客户端计算三者需按场景权衡（如移动端查云存储应压客户端计算），可用云服务通信/计算定价估算货币成本；回顾同态加密 PIR（选择向量与数据库点积）与将数据库摆成方阵的递归方案（上传两组平方根数量密文），并概述三项贡献：MulPIR 通信优化、可调通信—计算权衡的新版 GenTree-Ramzan、稀疏 PIR 到稠密 PIR 的通用转换。（YouTube EP1sbIHz7gHQ8，[7.9-755.6]，L1）
- 〔USENIX Security〕 讲解在 SealPIR（2018）之上的五项优化：客户端改用私钥加密并以短 PRG 种子替代长随机量使上传减半；服务器用模数切换压缩下载密文；改进的无知扩展（oblivious expansion）算法取消压缩比特向量 Hamming 重量至多为 1 的限制，使递归场景拼接后的行/列选择向量可一次压缩、消除最坏情形一半以上的密文空置；MulPIR 上传最多降 75%、下载最多降 80% 且货币成本在三个数据库中两个更低，可调版 GenTree-Ramzan 服务器计算最多降 85%，稀疏 PIR 经布谷鸟哈希拆两张表、两次稠密 PIR 查询即得。（YouTube EP1sbIHz7gHQ8，[402.7-781.9]，L1）
- 〔会议不详〕 Simon Fraser University 的 Kabil Bora 介绍 LUMOS——依赖驱动的盘外图处理：BSP 迭代图算法（PageRank、社区检测、推荐）在内存受限时依赖磁盘分区流式处理，实测状态最先进的 GridGraph 有 69–90% 线程时间耗于装载分区；LUMOS 通过乱序处理计算"未来值"并以依赖驱动的跨迭代值传播摊销 I/O，但直接未来值实测在十亿级图（UK web、Friendster、Twitter）上仅覆盖 30–45% 顶点、不足 4% 边——高入度顶点的依赖难以提前满足。（YouTube EP1tuAl7l-FBM，[10.2-413.1]，L1）
- 〔会议不详〕 突破该障碍：利用 sum 等可交换可结合聚合的增量可算性，改为维护"未来部分聚合"并随依赖到达增量合并，使可跳过装载的边比例升至 45% 以上，配合 HOF/HIL/HRF 三种度感知网格划分启发式（最大化网格上三角边）将跨迭代传播提升至 72–93%；在 GridGraph 之上实现，六种图算法上比 GridGraph 快 1.6–1.7 倍（加权/无权图一致），RAID 实验显示 HDD 可随并行 I/O 扩展而 SSD 收益有限；对异步算法（如 SSSP 的单调 min 聚合）可安全前向传播部分结果，并回应仅对比 GridGraph 的原因、与 Graphene/dynamic shards（ATC '16）选择性 I/O 的兼容及低直径图适用性等提问。（YouTube EP1tuAl7l-FBM，[413.1-1302.8]，L1）
- 〔会议不详〕 讲者（与亚利桑那大学 Saadur Rahman 及 CISPA 的 Agnes Kiss、Michael Backes 合作）介绍脚本语言原生扩展（native extension）的安全问题：Python/Ruby/Node.js 生态依赖中大量 C/C++ 代码经专用绑定在同一进程内运行（性能、硬件能力或 SQLite/OpenSSL 等成熟代码），C/C++ 内存管理缺陷会直接泄露进脚本层；通过实证比较三种语言原生扩展 API 对异常、参数校验、返回值与跨语言指针/同步调用的处理，指出 Node.js 最宽松（无效参数可继续执行导致未初始化字节泄露、复杂对象致进程崩溃），易造成开发者认知混乱并引入漏洞。（YouTube EP1vLBGOQUShQ，[8.5-429.7]，L1）
- 〔会议不详〕 提出两阶段方法论验证这些细微缺陷能否端到端影响 Web 应用：包分析构建统一 JS 与 C/C++ 节点的跨语言数据流图（sink 多在 C 侧、搜索两侧 sanitizer）检测类型校验缺失，应用分析做过程间静态分析定位可远程触达问题包的 Web 应用；对 7600 个 npm 包分析并人工复核（区分 JS 侧有类型检查的包以避免误报），发现可利用漏洞并上报维护者、获 CVE（如 sqlite3 包遇带特定 toString 属性的对象即崩溃 Node.js 进程，可被重复 POST 请求打瘫 Web 应用）。（YouTube EP1vLBGOQUShQ，[429.7-710.0]，L1）

- 〔USENIX Security〕 分析运营者、用途与教训：从 333 个独立 C2 基础设施簇与 48 个密码字典演化树推断存在多个独立运营者（簇 1 为攻击 Krebs 的原始 botnet、簇 2 最复杂并演化出加壳/DGA 与 CWMP 扫描、簇 6 为攻击 Dyn 的最大簇）；Mirai 对 Krebs 的攻击达 623 Gbps（当时公开记录最大 DDoS），Dyn 攻击中被同时攻击的 6 个 IP 反向解析出 4 个属 PlayStation 名称服务器、且与 Xbox 等游戏基础设施攻击交织，提示游戏动机；Mirai 偏好 TCP 状态耗尽与应用层攻击、仅 3% 为反射放大，结论为约 25 万 bot 即可发动史上最大公开 DDoS，并讨论 IoT 安全加固（非默认密码、关闭端口、自动更新）、设备归因（5500 万扫描 IP 中仅约三分之一 banner 可标注）与设备生命周期教训及问答。（YouTube EP1pywzRTJDaY，[609.4-1732.9]，L1）
- 〔会议不详〕 北京大学讲者（腾讯实习期间与腾讯合作）介绍 Blade——面向下一代实时通信（NGRTC，如 30 Mbps 以上、20 ms 内延迟的云游戏与 XR）的自适应 Wi-Fi 竞争控制：边缘服务器经 Pico 广域拥塞控制后，Wi-Fi 末跳仍高卡顿率源于神秘的 RTT 膨胀；基于 200 名志愿者家庭路由器驱动级埋点、跨一年的全国测量（含全栈逐帧延迟分解）定位根因——Wi-Fi 末跳传输本身无长尾但 AP 出现毫秒级"包递送旱灾"，与信道利用率完全相关，指向 IEEE 802.11 CSMA/CA 竞争机制；二进制指数退避在失败后翻倍 CW 导致更易被注入流量阻塞、重传等待更长的恶性循环，秒级看似公平、毫秒尺度公平性尽失。（YouTube EP-lM1SF7mbrM，[18.3-606.6]，L1）
- 〔会议不详〕 提出以全信道共识信号——微观接入率 MAR（可用传输时隙中被尝试的比例，所有共享信道设备均可本地嗅探计算）为核心的新竞争控制：MAR 对应瓶颈链路利用率、CW 对应拥塞窗口，将经典拥塞控制原则搬到 MAC 层，用 AI/MD 两阶段算法（激进项加速收敛、保守项保公平、对数乘性下降）使各发送端快速收敛至最优 CW；4 个 AP 同信道实验中云游戏流尾延迟减半、服务端视频卡顿率降 90% 以上，4 个超流饱和场景 MAC 中位包递送延迟降 3 倍（即中位吞吐 3 倍）且无饥饿，文件下载、网页浏览与传统手游同样获益，并总结"公平不是效率的代价——更公平的系统同时改善下界与平均性能"。（YouTube EP-lM1SF7mbrM，[606.6-1010.7]，L1）
