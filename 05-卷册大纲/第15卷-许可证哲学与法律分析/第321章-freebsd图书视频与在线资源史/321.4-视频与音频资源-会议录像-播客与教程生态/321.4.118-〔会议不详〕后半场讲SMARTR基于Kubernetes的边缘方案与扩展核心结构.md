- 〔NSDI〕ACC 的设计、实现与评估。研究表明足够长时间地停止拥塞流是端到端消除队头阻塞最快的手段，而受害流是否限速取决于拥塞扩散程度；据此 ACC 利用 TCD 遥测信号，为拥塞流引入 source hunt 状态、先精确等待过量包排空再将速率匹配到管道容量，受害流按连续 UE 跳数指标自适应降速，未确定流则渐进增速。ACC 在 SoftRocket 上实现（收发端仅新增约 200 行代码），在 5 台主机 10Gbps 测试床与 ns-3 胖树大规模仿真中评估：收敛较 DCC+QCN 快约 2.5 倍，排空缓冲比 HPCC 快 1.75 倍且 50 次 web search 随机流量仿真均无死锁，80% 网络负载下平均 FCT 较 HPCC 降低 29%、尾 FCT 降低 40%。（YouTube EPIa-iYFPeWio，[541.5-1094.9]，L1）
- 〔会议不详〕PeRF：支持抢占的 RDMA 框架。论文二作 Mingjie Choi 介绍，RDMA 的内核旁路使其绕开操作系统控制，带来安全、可扩展与性能隔离难题；在 ConnectX-6 100Gbps RoCE 网卡上的微基准测试发现 RNIC 会均匀处理各队列对的 MTU 分段包，并在多 QP 间采用轮询调度，导致多 QP 应用独占 RNIC 资源——B/M/D 应用共存时 M 应用吞吐下降 3.8 倍、D 应用平均延迟增加 6.1 倍。直接改硬件的方案隔离严格但难适应动态需求，用户态软件方案依赖预留式资源分配导致性能退化，PeRF 据此利用受管 QP 与 enable/wait 等特殊 work request 在网卡内实现消息级与 QP 级抢占。（YouTube EPIbLrGpe39mQ，[16.5-592.8]，L1）
- 〔会议不详〕PeRF 的抢占实现、架构与评估。消息级抢占将带宽密集应用的大消息拆为等长子 work request 并与立即完成的 zero-weight work request 交错，临时暂停其 QP 让小消息应用获得传输机会；QP 级抢占通过抢占控制 QP/CQ 上的 pause/resume 操作限制活跃 QP 数量。PeRF 划分 onloading 与 offloading 进程以最小化数据面开销，offloading 进程仅用一个专用 CPU 核即可同时管理上千应用。评估显示 PeRF 在 B-D、B-M 共存场景达到与硬件方案 SP/ETS 相当的吞吐与延迟，工作守恒式抢占使吞吐与消息速率全面优于基于令牌的 Justitia 及其宽松版 Justitia-R，并在 Apache Flink、Herd、rPing 三个真实应用共享 RNIC 时整体表现最佳。（YouTube EPIbLrGpe39mQ，[599.4-1198.3]，L1）
- 〔USENIX ATC〕RepairBoost：加速纠删码存储的全节点修复。来自厦门大学的报告人（与香港中文大学、清华大学合作）介绍，纠删码将文件分为 k 个数据块并编码出 m 个校验块分布到 k+m 个节点，但修复单个失效块需读回 k 个块、修复流量巨大；LRC 用本地校验块把读回量降为 k/L 但增加存储开销，PPR 将修复分解为多阶段并行执行却引入传输依赖。直接用于全节点修复时存在两类局限：未充分利用全双工传输而无法均衡上/下载修复流量，以及未充分利用各时隙带宽而再度拥塞链路。RepairBoost 框架由此提出修复抽象、修复流量均衡与传输调度三项技术，C++ 原型已集成进 HDFS 并在 Amazon EC2 上评估。（YouTube EPIbUnGxv8SkY，[9.2-437.6]，L1）
- 〔USENIX ATC〕修复 DAG 抽象、最大流调度与原型评估。RepairBoost 用修复有向无环图（rDAG）形式化单块修复的网络数据路由与块间依赖，将顶点分为中间、根、叶子三类并按携带上下载吞吐的元组映射到存储节点，以保持容错度并均衡双向修复流量；再将各时隙的传输调度形式化为最大流问题，迭代求出该时隙可同时传输的最大块数直至修复完成。原型以协调器加多代理的中间件形式运行在现有存储系统之上，在 17 台 EC2 虚拟机、RS(6,3) 编码配置下对不同纠删码与修复算法的平均修复吞吐提升 60.4%，分解分析显示其较流量均衡与传输调度单独作用分别高 45.7% 与 19.8%，且失效节点从 1 个增到 3 个时吞吐仅轻微下降，原型已公开供验证。（YouTube EPIbUnGxv8SkY，[441.4-919.8]，L1）
