- 〔USENIX Security '21（推测）〕方案是把符号验证引入飞地程序："we propose to use symbolic verification to"〔06:04〕（正解 Tamarin Prover）——"Damen tour starts with the design logic of a protocol in the form of multi-set rewriting rules and the security property in the form of first-order logic"〔06:12〕，输出该性质是否对模型全部执行成立。〔06:30〕关键观察是"the cryptographic protocol share common features with sjx environment"："The agents in the protocol can be considered as equals in the Sj side"〔06:37〕（正解 equals 即 enclaves），"And adversary on public channel can be considered as adversary in the privilege code"〔06:42〕；且"the Tamron input language is dynamic enough to customize the Ajax environment"〔06:48〕。〔06:55〕流程是从 SGX 应用的飞地执行逻辑与 SGX 线程逻辑出发，"we systematically transform it into Tamarin input language"再对全部执行验证状态连续性；贡献含一批 SGX 原语建模与"model templates for three open source Sjx applications"〔07:15〕；其中飞地原语涵盖飞地威胁模型、SGX 实体的关联网络、单调计数器等〔07:30〕，编程原语涵盖日志、循环与分支等〔07:36〕，并且逐一仔细建模了 SGX 威胁模型下的每项敌手能力。〔08:20〕以 Sort-Order 建模为例，网络中"each node executes in three steps, and a user acts at each node"，节点经区块链接口交互，可视为某个 ISV 部署的一条网络，其上可有多个进程。〔08:55〕层级靠"fresh facts, which can produce unique variables"构造——含 fresh fact 的定理规则可被无界实例化，逐层传递 ISV、用户、节点实体变量，"we create a three level hierarchy of ISVs, user nodes and processes"〔09:35〕。〔09:48〕线程靠两种事实区分："Linear facts can be consumed only once. So we use it to bind different rules of one enclave thread unit"，而"a persistent fact which can be consumed unbounded number of time"〔10:00〕用于配置多线程。〔10:29〕性质表述为"each node must not generate two certificate with same monotonic counter reference value"，借时间戳编码成一阶逻辑。〔10:56〕喂给证明器后"in its raw form we derive an attack"，"Tamarin Prover shows a detailed trace of the sorted workflow to show the root cause of the attack"；"we apply a patch in the form of slide chain in the logic"〔11:12〕（正解 state chain）后重跑得"a model where the state controllability property holds"（正解 state continuity）。〔11:23〕整体方法应用于"three open source SFX applications"（正解 SGX），"we build safe and vulnerable model for each three cases"〔11:33〕，即每个案例各造一份安全模型与一份脆弱模型；"our work is first attempt towards symbolic verification tool to verify state continuity property for SJX and play program"，并据此说明 Tamarin 能够有效建模 SGX 特有语义与状态连续性性质，Tamarin 代码已在 GitHub 公开。（YouTube EPYG-KrGRqNwA，[364-725]，L1）
- 〔USENIX Security '17（推测）〕代讲人 Caroline Whitnell 开场点明这是与 David McCan、Elizabeth Oswald 在布里斯托尔大学合作的项目，"it's one of those special papers that was actually accepted in spite of having the word practical in the title"〔00:10〕，论文主题是"simulating instruction level power consumption in order to detect side channel leakage during software development"〔00:46〕。〔01:27〕目标是"equipping software designers to detect side-channel vulnerabilities in the development stage"，尤其惠及"the growing Internet of Things sector"〔01:44〕：芯片厂商"are typically large and well established"〔02:01〕，养得起评估实验室或自建专家；"By contrast, small IoT companies are operating in a climate where security considerations are still playing catch-up with rapid innovation"〔02:41〕。〔02:47〕方法论坐标是"a spectrum between what we call white box and what we call black box modeling"：白箱"relies on the type of detailed circuit level knowledge that can be found in transistor or cell level netlists"〔03:00〕，用"transition counts"〔03:14〕给功耗近似，但"phenomena such as crosstalk"〔03:29〕仍在网表范围之外；黑箱只假设了解算法，"collect lots of traces relating to each of the possible values of the target intermediate"〔04:02〕再用拟合分布作模板。〔04:29〕本工作取中间态："Gray box leakage characterizations do not require detailed circuit level information, but they do assume that something more is known about the implementation than just the underlying algorithm"，例如拿到汇编即可做指令级建模；既有工作多依赖"the popular Hamming weight and distance models"〔04:46〕这类简化假设，而"research into power costs, including that done by Tiwari and colleagues, has revealed that the true form"〔04:59〕要复杂得多——"The power consumed by a given instruction varies, for example, depending on the instructions around it"〔05:15〕。〔05:41〕于是"Our contribution is a methodology for building appropriately complex models for instruction level leakage"，工具名为"ELMo"〔05:55〕。〔06:07〕建模主干是"linear regression provides a natural tool for finding expressions for one variable as a function of a number of others"，系数"estimated by minimizing the sum of squares of the residuals"〔06:53〕，有效性依赖噪声独立同分布且解释变量间不存在多重共线性；解释变量取自被处理数据与运行中的汇编序列。〔08:01〕模型质量的度量是"the coefficient of determination or the R squared"，但"It always increases when you add a new explanatory variable, regardless of whether or not the contribution of that variable is truly meaningful"〔08:32〕，故比较不同规模模型"it is generally recommended to use the F-test"〔08:45〕；若 R 方偏低但整体显著，仍可解释与数据相关的那部分，若整体不显著"it may mean that the traces do not leak information about the processed data"〔09:31〕——但这不等于设备不泄漏，也许该回去改进测量装置。〔10:26〕实验对象是"members of the Arm Cortex M processor family"（2004 年推出、六个变体，本文聚焦低成本低功耗的 M0），核内含"an arithmetic logic unit, a hardware multiplier and a barrel shifter"〔10:49〕；Thumb 是指令集子集，每条十六位对应一条等价的三十二位 ARM 指令，"we identify twenty one of these instructions as being particularly important to typical implementations of symmetric cryptography"〔11:28〕，并按 ALU、桶形移位器、load/store、乘法分组。〔12:17〕"The open source C program Thumbulator emulates the data flow of arbitrary Thumb instruction sequences"将被复用；〔13:14〕实测在 STMicroelectronics 的 STM Discovery 板上进行，"We empirically chose a sampling rate of five hundred mega samples per second"〔13:39〕并对每条指令收集"five thousand traces for each instruction for varying operands"〔14:12〕，"we sandwiched the instruction in each case between two move instructions"〔14:18〕以抑制代码序列效应。（YouTube EPYL6WSOa8XYI，[10-880]，L1）
- 〔USENIX Security '17（推测）〕逐条指令的独立建模结论是"all of the models that we tested in this way were overall significance"〔14:44〕（正解 significant），且"there were discernible differences in the form of the leakage between the different instructions"〔14:50〕——"load instructions depend only on the bits of the operand and not on the bit flips"〔14:54〕，而"store instructions depend only on the bits and bit transitions of the second operand"〔15:00〕，乘法不依赖第二操作数的位跳变。〔15:23〕为容纳更复杂的模型，先"remove as much redundancy as possible"："we represented each instruction by its data dependent coefficients and performed a hierarchical cluster analysis on them"〔15:42〕，按轮廓指数最优的划分"ALU stores, loads, shifts and multiplications separated out into five distinct groups"〔15:59〕，于是"we can uh confidently reduce our list of instructions to just these five representatives"〔17:01〕，把三指令序列的组合数从 21 的三次方（逾九千）压到 125。〔17:22〕每个组合采集"one thousand traces for each combination with random data inputs"并交错取样、中心化去漂移，模型同前但"with the addition of dummy variables indicating the previous and subsequent instructions"〔17:43〕，再"fitting four sets of interaction terms"〔17:58〕以容纳差分数据依赖——即指令哑变量与操作数汉明权重、汉明距离的乘积项；"The differential data effects are found to be jointly significant in almost all cases"〔18:18〕。〔18:32〕局限在于"it restricts the relationship between the leakage and the data bits to be linear"，故补测相邻与非相邻位交互，结果"we did find significant effects precisely and only where we might expect to"〔18:51〕，即仅出现在显式联合操作位域的移位与乘法上；最终模型"include sequence dependence data interactions in all cases and input bit interactions in the case of shifts and multiplications only"〔19:12〕。〔19:40〕整合环节是让开源的 Thumbulator 解码并顺序执行 Thumb 汇编，把"the values of the operands in a linked list data structure"〔20:16〕喂给模型方程，输出对应代码段的预测功耗轨迹。〔20:47〕首验是模型与实测的相关性：以 AES 第一轮输出的汉明权重作基线对比后，"we can easily see that the Elmo model captures leakage information beyond that characterized by the Hamming weights"。〔21:11〕最具价值的应用是自动泄漏检测，方法取自 Goodwill 等的经典假设检验：固定对随机测试下"A Welch's two-sample t-test is used to decide whether at each point in the trace the two groups have significantly different mean power consumption"〔21:37〕。〔22:13〕案例是一段号称受掩码保护的 AES shiftRows 实现：掩码本意是"divide all sensitive intermediates into statistically independent shares which only reveal the original uh variable when recombined"，但"the rotate right operation leaks a function of the bit flips from the previous data operands, there could be a problem if the prior instruction is protected by the same mask"〔22:29〕；用 Goodwill 等建议的 4.5 阈值判峰，"leakage is detected in the Elmo traces for the expected instructions"〔23:02〕，与真实轨迹的结论吻合，唯一差异是最后一条 load 之后仍有残余泄漏——"our models are constructed at instruction level rather than clock cycle level"〔23:24〕，代价是视觉相似度略降，好处是"we can easily track back to the offending instruction"〔23:43〕。〔23:56〕总结论："our tool is able to capture vulnerabilities in arbitrary code sequences"，流程"appropriate for use with different devices and channels"〔24:10〕，工具将开源到 GitHub。问答中被追问普适性，答"you kind of need to build the models separately for each device that you want to simulate for"〔25:09〕。（YouTube EPYL6WSOa8XYI，[880-1750]，L1）
- 〔FAST '24（推测）〕讲者代为呈现 Xingjian 因故缺席的工作，主题"combining buffered I O and direct I O in distributed file system"〔00:16〕。背景是 Linux 默认走 buffered I/O、"utilizing of course the Linux page cache"〔00:37〕，而"for over twenty years now we have also an alternative I O mode which is called direct I O and it bypasses the Linux page cache"〔00:50〕；本地 LFS 实测显示"for direct I O we start slower but then at around one megabyte we're already significantly faster than buffered I O"〔01:13〕。〔01:44〕既然更快为何仍少用？"there are very very various challenges that hinder the wide adoption"：用户熟悉缓冲式；"there are some alignment constraints that can be difficult to accommodate right so your the offset size and memory buffer address must be aligned"〔02:02〕，通常需对齐到扇区大小，现有 statx 系统调用可取该信息，但既有应用很难重写整个 I/O 层。〔02:40〕于是"We propose here that we can combine the benefits of both"并在文件系统内透明决策、由文件系统而非用户拍板；"The decision is not only based in our work on the I O size, but we also take additional variables into account like the lock contention"〔03:09〕，实现落在"the Lustre parallel file system"。〔03:37〕先用 perf 解剖十六 MB I/O 的时间去向："only about twenty percent of the time is really going to copying the data from user space to to the page cache. More than forty percent is page cache management"，后者含页分配、页缓存内加锁、LRU 老化与回收；ext4 上差距比网络文件系统更明显，后者还叠加了网络通信成本。〔04:28〕Lustre 架构三件套：客户端经挂载点与文件系统交互、MDT（元数据目标）处理元数据、OST（对象存储目标）存放数据及部分元数据。〔05:02〕一致性与锁：Lustre 保持强一致语义，"it uses a distributed lock manager that especially used for file synchronization, metadata access"，且 OST、MDT 各有独立的分布式锁命名空间，客户端在本地影子命名空间持有副本；若第二节点要在冲突偏移处写入，锁须被撤销，反复如此即"lock ping pong or what we call it lock thrashing and this then degrades performance"〔05:28〕。〔06:07〕两侧各有主场：buffered 在"small io sizes"、掩盖高延迟存储（如机械盘）、以及"unaligned I/O"〔06:20〕时占优；direct 则在"large sequential I O"〔06:48〕、进程与节点数多（缓冲式不具扩展性）、页缓存内存吃紧时占优。〔07:47〕特性分两层，先做"unaligned direct I O support"——"the Lustre client is doing that alignment for you"，未完全对齐时向存储服务器多取数据后本地对齐写入，虽有额外开销但大 I/O 下仍优于缓冲式；再做"client-side I/O mode decision, which we call Aura I O"〔08:04〕（正解 Auto I/O）。〔08:09〕核心判据仍是"revolving about the I O size and this is because it's the most important and the largest contributor to performance"，但有"two"〔08:37〕阈值：一侧是缓冲式恒优区、一侧是 direct 恒优区，中间留一段"decision window"；初设该窗口为"from thirty two kilobytes to two megabyte"〔09:25〕，窗口内再看锁竞争与页缓存过量使用。〔09:58〕为证伪该假设专门构造（未收入论文、仅本场展示）的锁竞争负载显示："Now under lock contention, direct I O becomes more beneficial the smaller the exercises become, and even for two hundred fifty six K it's kind of close"——原本两 MB 处打平，锁竞争下提前；而"whether you will reuse things that you actually put in the page cache"〔10:34〕不成立（页被快速逐出）时，两 MB 以下同样可提前切 direct。（YouTube EPYPpTPQURy-U，[16-660]，L1）
