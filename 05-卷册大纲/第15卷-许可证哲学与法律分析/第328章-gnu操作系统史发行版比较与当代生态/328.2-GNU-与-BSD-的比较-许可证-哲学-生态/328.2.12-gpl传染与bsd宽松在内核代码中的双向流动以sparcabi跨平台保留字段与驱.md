# 328.2.12 GPL 传染与 BSD 宽松在内核代码中的双向流动：以 sparc ABI、跨平台保留字段与驱动许可字段为三条通道（1997–2026）

GPL 传染与 BSD 宽松的内核双向流动不止发生在网络与 InfiniBand 驱动里，它同时发生在 sparc ABI 的返回约定、跨平台保留字段的占用博弈与 SCSI 驱动的许可字段中：1997 年 Linux 0.12 起以 GPL-2.0 发布却允许用户态以任意许可链接，2004 年 Alexey Nezhdanov 在 Sun Blade 2000 上经一周尝试仍无法启动 GNU 系统，留下一句 "Most probably that I will try my luck again several times with different FreeBSD approaches and most probably end up with Solaris system"，把 BSD 与商业 Sun 系统并列为 sparc 用户面对 Linux 启动失败时的现实退路，同一时期 David Miller 解释 sparc clone 在子进程返回父进程 pid 的原因时直接写出 "The system call convention follows that of SunOS on which the syscall handling was based. Return '1' in the %o1 register in the child and '0' in the parent"，BSD 血统以寄存器级 ABI 的形式固化进内核 sparc 分支，Blue Swirl 同期报告已能在 OpenBSD/Sparc64 上运行 sparc32 模拟器、在 Linux/Sparc64 上配合较新 glibc 也有部分成功，把 BSD 系统当作跨内核验证 Linux 移植的实验室

跨平台保留字段的占用博弈把 BSD 与 Hurd 一并推入 Linux 开发者的视线：2025 年 Theodore Ts'o 在 ext4 32 位保留 uid 补丁讨论中警告 "GNU Hurd or BSD had hijacked some reserved field"，担心跨平台兼容性风险；2015 年 Ts'o 在移除 ext3 驱动时列出独立实现清单，包括 Hurd's ext2、星号 BSD 的 ext2 以及 Grub 的 ext2/3/4，把 BSD 与 Hurd 一并算作 Linux 之外的 ext 家族实现；2014 年 Jeff Layton 在 glibc 文件私有锁讨论中转述 "on BSD, flock() and fcntl() based locks do conflict"，把 BSD 锁语义作为 Linux 私有锁设计的对照坐标，Neil Brown 代笔 flock(2) 手册页 NOTES 段落时进一步说明自内核 2.0 起 flock 独立成系统调用"这带来经典 BSD 语义，即两种锁类型之间互不交互"，BSD 文件锁语义在 Linux 中不是移植而是作为文档先例被引用

BSD 与 Hurd 也作为负面先例反向约束 Linux 开发：2015 年 Josh Triplett 在 CLONE_FD 补丁讨论中援引 FreeBSD 的 pdfork 实现，指出 "FreeBSD never implemented pdwait4"，故 glibc 不应先行实现以免与 FreeBSD 内核最终语义不一致，BSD 生态的空白反而成为 glibc 的边界；2026 年 David Laight 在 ELF $ORIGIN 支持讨论中回应 Brauner 对 glibc 实现的 "very hackish and full of edge cases" 担忧，断言 "NetBSD refused to implement $ORIGIN because it was full of loopholes"，并建议内核持有目录 inode 引用并给 openat 加相对该目录的参数，把 NetBSD 拒绝的路径作为 Linux 拒绝的判据；2008 年 Gerd Hoffmann 在 preadv 与 pwritev 补丁讨论中转引 Michael Kerrisk 的立场，明确写出 glibc 用户态接口应 "compatible to the existing implementations in the *BSD family"，BSD 家族在此被直接点名作为 Linux 系统调用的兼容基准

GPL 与 BSD 双授权字段在 SCSI 驱动层以文件头形式制度化：Adaptec ADP94xx SAS HBA 驱动公告附带完整许可证头，"Redistribution and use in source and binary forms, with or without modification" 与 "may be distributed under the terms of the GNU General Public License" 并列，Copyright (c) 2004 Adaptec Inc. 保留所有权利；FlashPoint 驱动的注释清理补丁删除了重复的许可证声明，被删文本显示该文件 "available under both the GNU General Public License and a BSD-style copyright" 并引用 LICENSE.FlashPoint 细则；2014 年 Sam Ravnborg 转引 H. Peter Anvin 关于 glibc endian.h 字节交换函数的说法 "taken from FreeBSD I believe"，把 BSD 代码谱系作为 glibc 端序转换能力的来源，BSD 宽松条款以驱动许可字段与 libc 代码谱系的双重方式进入 Linux 内核树

从 1997 年 Linux 0.12 起 GPL 传染与 BSD 宽松在内核代码中的双向流动不止于网络与 InfiniBand：sparc ABI 的 %o1 返回约定、跨平台保留字段的占用博弈、BSD 与 Hurd 作为负面对照与兼容基准、SCSI 驱动的 BSD+GPL 双授权字段与 glibc endian.h 的 FreeBSD 谱系，共同构成 GPL 传染边界与 BSD 宽松条款在 Linux 内核中另一种日常对话形式，BSD 家族与 Hurd 因此既是 Linux 用户态接口的来源、也是其拒绝路径的判据

以上叙述基于 dslinux_claims.duckdb 与本节 ROW_MINE 锚指向的邮件列表条目，1997 年内核起始节点与 2025–2026 年 ext4、$ORIGIN 讨论属过程性证据，具体技术结论仍须以源码与提交记录复核
