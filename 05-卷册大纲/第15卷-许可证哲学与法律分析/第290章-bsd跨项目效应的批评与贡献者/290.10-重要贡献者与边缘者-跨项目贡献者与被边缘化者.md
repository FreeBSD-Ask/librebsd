**史观**：总纲第 10 条——边缘者贡献：跨项目贡献者是 BSD 阵营跨项目影响的关键贡献者；总纲第 25 条——0 信任原则：贡献者名单需通过考据程序验证；统计结论印证：C-24/C-25/C-26/C-27 揭示 BSD 4 项目贡献者分布的高度集中——Gini 系数 0.82-0.92 意味着贡献极度不均，top 10% 贡献者承担约 90% commit 量，此量化结论为 “明星效应” 提供数据基础；E-09 的 Contributor Absence Factor 1-5 进一步揭示 BSD 项目对少数核心贡献者的高度依赖，高 Gini + 低 CAF 共同构成 BSD 跨项目贡献者结构的 “少数明星 + 多数边缘者” 特征，与 136.10.2/136.10.3 节的 “明星效应” 叙事相互印证

**辨析**：每位贡献者的具体跨项目角色须逐个核实——如 Watson 在 CHERI 中的角色 vs FreeBSD 中的角色须区分；Damien Miller 在 OpenSSH portable 中的角色须查 openssh.com 治理文档；0 信任原则局限标注：L7.2.1 查询基于 author_email 字段统计，但 author 字段可由提交者任意填写，同一人使用不同邮箱（如工作邮箱与个人邮箱）会导致统计分散，<behindendorf1@llnl.gov> 的 2,603 次回馈可能未涵盖其在其他邮箱下的贡献；查询仅统计衍生项目贡献者（trueos-src/ghostbsd-src/hardenedbsd-src/midnightbsd-src/truenas-middleware/opnsense-core/pfsense-src 七个仓库），不含 OpenZFS/OpenSSH/LibreSSL 等独立项目的贡献者，因此 OpenZFS 的 <behlendorf1@llnl.gov> 被纳入仅因其同时是 trueos-src 等仓库贡献者；≥5 次的阈值排除了大量低频回馈者，可能低估社区长尾贡献；<ryan@iXsystems.com> 邮箱识别可较确定归属 iXsystems 公司，但 @gmail.com/@alumni.stonybrook.edu 等个人/教育邮箱无法直接识别所属机构；统计周期截至 2026-06-22（数据库快照时点），此后新增回馈未纳入；C-24/C-25/C-26/C-27 方法学局限：Gini 系数基于 author_email 去重统计 contributors，同一人多邮箱会导致 contributors 高估从而使 Gini 系数偏低（实际集中度可能更高）；Gini 系数仅度量 commit 量分布，不反映贡献质量分布（如核心贡献者的架构决策、代码审查贡献无法量化）；Bootstrap 95% CI 虽提供置信区间但 B = 2000 次重抽样仍受样本量限制，freebsd-src contributors 数量大故 CI 较窄，dragonfly-src contributors 数量少故 CI 较宽 [0.8517, 0.9187]；4 项目 Gini 系数差异（freebsd-src 0.9188 > dragonfly-src 0.8972 > openbsd-src 0.8244 > netbsd-src 0.8158）反映项目规模与贡献者集中度的关系，但差异较小且 CI 重叠，不可过度解读为项目间治理模式差异；E-09 方法学局限：Contributor Absence Factor 估算值 1-5 为定性推断而非精确计算，精确计算须按 CHAOSS 公式重算（需获取 BSD 4 项目 90 天活跃窗口内的 contributor 与 commit 数据），当前估算仅作量级参照；CHAOSS 指标定义基于通用开源社区，BSD 项目的核心开发者群体特征（资深系统程序员、长期贡献）与 CHAOSS 模型假设的 “轮换式贡献者” 可能不匹配，估算值可能高估或低估实际依赖度；统计显著 ≠ 实际显著，Gini 系数高不等于社区不健康，BSD 项目 30 余年持续发展证明高 Gini 模式在 BSD 语境下具可持续性

**文献**：各项目 commit 历史；BSDCan 议程 ［A］；bsd_commits.duckdb L7.2.1 查询报告（衍生项目与跨项目对比分析.md §L7.2.1）；bsd_commits.duckdb C-24/C-25/C-26/C-27 查询报告（推断性统计.md Task 10 + 描述性统计.md SubTask 2.3）；外部基准 E-09 查询报告（外部基准-GitHub-CHAOSS.md 第 3 节）

## 290.10.2 被忽视的跨项目贡献

**要点**：BSD 跨项目贡献中存在大量被忽视的贡献——jemalloc 曾被 Rust 作为默认分配器（后随 RFC 1974 全局分配器机制在 Rust 1.28 中稳定化，默认分配器已切换为系统分配器，但 jemalloc 仍通过 tikv-jemallocator crate 被大量 Rust 项目采用）；socket API 进入 POSIX 后 BSD 贡献被“标准化”掩盖；FFS 对 ext2 的设计影响常被忽视；libarchive 被 macOS（bsdtar）、Debian/Ubuntu（bsdtar 包）、Homebrew 等广泛采用，但作为“看不见的基础设施”默默支撑全球归档工具，鲜少被归功于 FreeBSD；这些被忽视的贡献反映 BSD 跨项目影响的“基础设施性”特征——影响越基础越容易被忽视

**史料**：Rust RFC 1183/1974 全局分配器文档、crates.io tikv-jemallocator 统计、POSIX 标准演化、Rémy Card 等 ext2 设计论文、libarchive 官网采用列表 ［A］

**史观**：总纲第 10 条——边缘者贡献：被忽视的跨项目贡献反映 BSD 影响的基础设施性；总纲第 25 条——0 信任原则：被忽视的贡献需通过考据程序验证

**辨析**：每项被忽视的贡献须具体核实——jemalloc 在 Rust 中的默认分配器地位已于 Rust 1.28（2018 年 8 月）随全局分配器机制稳定化而改变，此后默认使用系统分配器，但 jemalloc 仍通过 tikv-jemallocator crate 被大量 Rust 项目主动选用；libarchive 在 macOS/Debian/Homebrew 中的具体版本须查各平台文档；socket API 被“标准化”掩盖的实质须查 POSIX 1003.1g 历年文本中 BSD 贡献的表述变化

**文献**：Rust RFC 1183/1974；crates.io jemalloc 关键词；POSIX 1003.1 标准；Rémy Card 等 ext2 论文；libarchive 官网 ［B］

## 290.10.3 被遗忘的贡献者辨析

**要点**：BSD 跨项目贡献中存在被遗忘的贡献者——Björn Grönvall（OSSH 创建者，OpenSSH fork 的源头，1999 年初重新发现 Tatu Ylönen 的 SSH 1.2.12 最后自由版本并修复漏洞，但 OpenBSD 项目成员在 OpenBSD 2.6 发布前不到两个月才发现其工作，随即 fork 为 OpenSSH，Grönvall 此后逐渐淡出，其 OSSH 仅支持 SSH 1.3 协议且“可能在 OpenSSH 成熟后停止了开发”）在 OpenSSH 历史中长期被边缘化；Anders Berg（Varnish 项目发起者，VG 系统管理员，2005 年撰写项目规格书，自述“我是一个思考者而非执行者——我想出了 Varnish Cache 的想法，但执行者是其他人”）在 Varnish 历史中被 PHK 名声掩盖；Anders Nordby（Aftenposten 系统管理员，Varnish 项目的关键连接者——Berg 通过 Nordby 认识 PHK，Nordby 建议“找一个内核开发者”并推荐了 PHK，Varnish Software 官方历史明确记载 Nordby 参与项目启动）在 Varnish 叙事中几乎完全被遗忘；Dag-Erling Smørgrav（FreeBSD 提交者与安全官，2005 年底在巴塞尔 EuroBSD 会议上将 PHK 拉到一旁提出了 Varnish 项目构想，当时任 Linpro 顾问，后担任 FreeBSD Varnish port 维护者）在 Varnish 历史中更多被视为“连接者”而非“开发者”；Luke Mewburn（NetBSD rc.d 设计者，Wasabi Systems 工程师，USENIX ATC 2001 FREENIX Track 论文作者）在 rc.d 跨项目扩散中较少被归功；这些被遗忘的贡献者反映 BSD 跨项目叙事中的“明星效应”——项目创始人被铭记，协助者、连接者与早期推动者被遗忘

**史料**：OpenSSH 官方历史（openssh.org/history.html，明确记载“OpenBSD 项目成员在 OpenBSD 2.6 发布前不到两个月才得知 Björn 的工作”与“Björn 可能在 OpenSSH 成熟后停止了开发”）、Varnish Software 官方历史（varnish-software.com/varnish-history/，明确记载 Anders Nordby 参与项目启动）、Anders Berg 2016 年 Q&A（varnish-software.com/blog，自述“thinker, not a doer”与 Nordby 推荐 PHK 的细节）、PHK 2016 年 Q&A（varnish-software.com/blog，自述“DES 在 EuroBSD 会议上把我拉到一旁”）、Mewburn USENIX 2001 论文“The Design and Implementation of the NetBSD rc.d System”（署名机构 Wasabi Systems, Inc.）、NetBSD rc.d(8) 手册页（"The /etc/rc.d support was implemented in NetBSD 1.5 by Luke Mewburn"）、FreeBSD 提交者指南中 DES 条目（曾任 FreeBSD 安全官）、FreeBSD Bugzilla Varnish port 维护记录（des@ 为维护者） ［A］

**史观**：总纲第 10 条——边缘者贡献：被遗忘的贡献者反映 BSD 跨项目叙事的明星效应；总纲第 25 条——0 信任原则：被遗忘的贡献者辨析需通过考据程序验证

**辨析**：每位被遗忘贡献者的具体贡献须逐个核实——Grönvall 的 OSSH 与 OpenSSH 的关系经 openssh.org 官方历史核实（“fork from the OSSH release”）；Berg 的“发起者”角色经 Varnish Software 官方历史与自述 Q&A 双重印证；Nordby 的关键连接者角色经 Berg 自述与 Varnish Software 官方历史双重印证；DES 的“连接者”角色经 PHK 自述核实（"Dag-Erling Smørgrav pulled me aside at a EuroBSD conference in Basel and suggested it"）；Mewburn 的 rc.d 设计者角色经 NetBSD **rc.d(8)** 手册页与 USENIX 论文双重印证；“明星效应”的判断须避免过度解读——部分被遗忘源于贡献可见度差异而非纯粹叙事偏差

## 290.10.4 边缘贡献者的史料辨析

**要点**：BSD 跨项目贡献中边缘贡献者的史料辨析需关注——贡献记录的完整性（部分贡献未留下 commit 记录）、来源的多样性（需通过 commit、邮件列表、会议记录、个人自述等多源交叉核查）、叙事的偏差（明星效应导致协助者被遗忘）；辨析需通过多源史料重建，避免单一来源（如官方历史）的偏差；需注意 0 信任原则——即使贡献者自述也需独立验证

**史料**：BSD 项目 CVS/SVN/Git 历史全量、邮件列表历年存档、BSDCan/EuroBSDCon/AsiaBSDCon 历年演讲、贡献者个人主页与博客 ［A］

**史观**：总纲第 25 条——0 信任原则：边缘贡献者史料辨析需通过考据程序验证；总纲第 10 条——边缘者贡献：辨析本身是对边缘者的重新归位

**辨析**：贡献记录的完整性与代表性是核心辨析点——部分贡献可能未留下记录，需通过多源交叉核查；“明星效应”的判断需避免过度解读——明星效应部分源于贡献可见度而非纯粹叙事偏差

**文献**：BSD 项目版本控制历史；邮件列表存档；会议演讲记录 ［A］

##### 288.10.5 再回应层：BSD 阵营对“明星效应”与“边缘者被遗忘”的回应

- **要点**：对 BSD 跨项目叙事中“明星效应”（项目创始人被铭记，协助者、连接者与早期推动者被遗忘）的批评，BSD 阵营的再回应聚焦于四点：第一为 **“明星效应部分源于贡献可见度差异而非纯粹叙事偏差”**——PHK 作为 Varnish 首席架构师的设计笔记（varnish-cache.org/docs/trunk/phk/firstdesign.html）是公开可查的技术贡献，而 Anders Berg 的“发起者”角色（自述“thinker, not a doer”）与 Anders Nordby 的“连接者”角色（建议“找一个内核开发者”并推荐 PHK）虽经 Varnish Software 官方历史记载，但其贡献可见度低于 PHK 的技术产出——此“可见度差异”部分源于贡献性质（技术产出 vs 协调角色）而非纯粹叙事偏差。第二为 **“被遗忘的贡献者经考据可重新归位”**——Björn Grönvall（OSSH 创建者）经 OpenSSH 官方历史核实为 OpenSSH fork 的源头（“fork from the OSSH release”）；Anders Berg 与 Anders Nordby 经 Varnish Software 官方历史与 Berg 自述 Q&A 双重印证；Dag-Erling Smørgrav（DES）经 PHK 自述核实为 Varnish 项目构想者（“DES 在 EuroBSD 会议上把我拉到一旁”）；Luke Mewburn 经 NetBSD **rc.d(8)** 手册页与 USENIX 2001 论文双重印证为 rc.d 设计者——考据程序本身是对边缘者的重新归位，而非“永久遗忘”。第三为 **“freebsd.duckdb 的量化分析可部分修复边缘者被遗忘”**——freebsd.duckdb 查询 L7.2.1 显示衍生项目贡献者在 freebsd-src 的回馈前 10 位，其中 <behlendorf1@llnl.gov>（LLNL，OpenZFS 核心开发者）2,603 次、<ryan@iXsystems.com>（iXsystems）329 次、<mahrens@delphix.com>（Delphix）229 次等——这些量化数据使部分“看不见的贡献者”可见，修复了纯粹叙事中的边缘者遗忘。第四为 **“边缘者被遗忘是‘基础设施性’的代价而非道德失败”**——BSD 跨项目影响的“基础设施性”特征使贡献越基础越容易被忽视——libarchive 作为“看不见的基础设施”默默支撑 macOS/Debian/Homebrew，其贡献者 Tim Kientzle 与 Martin Matuska 的知名度低于 Varnish 的 PHK，此“知名度差异”是“基础设施性”的代价（影响越基础越容易被忽视）而非道德失败。
- **史料**：Varnish Software 官方历史（varnish-software.com/varnish-history/，明确记载 Anders Nordby 参与项目启动）；Anders Berg 2016 年 Q&A（varnish-software.com/blog，自述“thinker, not a doer”与 Nordby 推荐 PHK 的细节）；PHK 2016 年 Q&A（varnish-software.com/blog，自述“DES 在 EuroBSD 会议上把我拉到一旁”）；OpenSSH 官方历史（openssh.org/history.html，明确记载“fork from the OSSH release”与“Björn 可能在 OpenSSH 成熟后停止了开发”）；NetBSD **rc.d(8)** 手册页（"The /etc/rc.d support was implemented in NetBSD 1.5 by Luke Mewburn“）；Mewburn USENIX 2001 论文”The Design and Implementation of the NetBSD rc.d System"；bsd_commits.duckdb 查询 L7.2.1（衍生项目贡献者回馈 commit 前 10 位）；libarchive 官网采用列表（libarchive.github.io）。
- **史观**：总纲第 10 条（边缘者贡献）与总纲第 25 条（0 信任原则）。BSD 阵营的再回应实质上是将“明星效应”与“边缘者被遗忘”的批评置于“贡献可见度差异”与“考据程序修复”的框架下重新审视——明星效应部分源于贡献性质差异而非纯粹叙事偏差，且考据程序本身是对边缘者的重新归位。项目史观总纲第十章“边缘者贡献”在此显现：边缘者非“被动的受害者”而是“主动的贡献者”，考据程序使其贡献被重新发现。

##### 288.10.6 合图层：跨项目贡献者的“明星可见”与“边缘者被遗忘”的辩证统一

- **要点**：综合批评-反批评-再回应三层辩证，BSD 跨项目贡献者的核心矛盾可总结为“明星可见与边缘者被遗忘的辩证统一”——即 BSD 跨项目叙事中项目创始人（PHK、McKusick、Watson、Hubbard 等）因技术产出可见度高而被铭记，协助者（Berg、Nordby、DES）、连接者（Grönvall、Mewburn）、早期推动者因协调角色可见度低而被遗忘，此“明星效应”部分源于贡献性质差异（技术产出 vs 协调角色），部分源于叙事偏差。此矛盾不可“调和”——因技术产出的可见度天然高于协调角色，若要求同等可见度则忽视贡献性质差异——但可“分离聚合”——因考据程序（如 bsd_commits.duckdb 量化分析、官方历史交叉验证、邮件列表存档）可使部分被遗忘的贡献者重新归位，此“重新归位”是“明星可见”与“边缘者被遗忘”的聚合点。合图层的核心判断为：BSD 跨项目贡献者是“明星与边缘者的集合”而非“仅明星的贡献”——PHK 主持 Varnish 但 Berg 发起、Nordby 连接、DES 提出构想；Watson 主持 Capsicum 但 Moore、Sewell、Davis 等共同参与；McKusick 参与 POSIX 但 CSRG 时代的 BSD 团队共同塑造——明星与边缘者的贡献是同一项目的两面，二者各有其形式主义化的具体显现。此判断对应项目史观总纲第十章“边缘者贡献”——边缘者非“被动的受害者”而是“主动的贡献者”，考据程序使其贡献被重新发现，此“重新发现”即“边缘者归位”的具体显现。
- **史料**：Varnish Software 官方历史（Berg 发起、Nordby 连接、DES 构想、PHK 执行）；OpenSSH 官方历史（Grönvall 的 OSSH 为 fork 源头）；openbsd.duckdb 查询 L7.2.1（衍生项目贡献者回馈前 10 位，使部分“看不见的贡献者”可见）；NetBSD rc.d(8) 手册页与 Mewburn USENIX 2001 论文（Mewburn 为 rc.d 设计者）；libarchive 官网（Kientzle 创建、Matuska 接手维护）；FreeBSD Darwin CREDITS 文件（2003-2020 年间超过 200 名外部贡献者）。
- **史观**：总纲第 10 条（边缘者贡献）与总纲第 6 条（主体性与和解）。BSD 跨项目贡献者的核心即“明星可见与边缘者被遗忘的辩证统一”——明星因技术产出可见度高而被铭记，边缘者因协调角色可见度低而被遗忘，二者是同一项目的两面。项目史观总纲第十章“边缘者贡献”在此显现：边缘者非“被动的受害者”而是“主动的贡献者”，考据程序使其贡献被重新发现。

**要点**：

- 移植工程缘起：Christoph Egger 经一家以 OpenBSD 为基础出售安全产品的慕尼黑公司 Gainware 接触 OpenBSD，寻找学位论文题目时由公司选定“把 OpenBSD 移植到 Xen”；其于 2005 年 12 月从 Xen 2 起步，2006 年 XenSource 经由 Google Summer of Code 把“OpenBSD 移植到 Xen3”立项，因其已有 OpenBSD 跑在 Xen 2 上的基础而顺势承接，至受访时已在 Xen 3 上完整可用——身份是 Xen 客户机（Xen guest）而非宿主。（BSDTalk EP69，[83.32-248.96]，L1）
- Xen 技术原理：Xen 是 XenSource 开发的 hypervisor，把大型机虚拟化技术带到 PC，使多个操作系统同时高速并行；所有系统都运行在 Xen 之上，Xen 掌管硬件与 CPU，其中特权最高的 domain zero（xenhost）负责管理其余客户机。Xen 不模拟整机（那是 VMware 的全虚拟化，客户机看到的是伪造的通用硬件），而采用半虚拟化——客户机操作系统自知运行于虚拟环境并直视真实硬件，开销约 2%-3%；借助 AMD Pacifica 与 Intel VT 硬件虚拟化还可运行未经修改的客户机。版本演进上，Xen 2 仅支持 i386 且要求 i686 级 CPU，Xen 3 已扩展至 IA64、Itanium、AMD64 并在开发 PowerPC 支持，加入 ACPI 电源管理与客户机 SMP；迁移分停机迁移与动态迁移（后者 TCP 网络连接不中断），并支持运行时增删 CPU 与增减内存——前提是客户机操作系统支持相应热插拔，否则结果未定义。（BSDTalk EP69，[159.36-505.38]，L1）
- OpenBSD 客户机功能与回馈主线：其移植提供网络、块设备 I/O（磁盘与 CD-ROM）、时钟、FPU、控制台五类基础驱动，使其普通可用；自加的特别功能是网络与块设备在运行时动态挂载与卸载。工作自 OpenBSD current（彼时即 4.0）起步并持续跟进 current；移植过程暴露的缺陷已修复并被接受——其一在 TCP 栈、其一在 UVM 内存管理，均已进入 OpenBSD 3.9，后续补丁将进入 current；此举也被视为 OpenBSD 社区借 Xen 移植清理内核缺陷的集体努力，目标是进入 OpenBSD current 并希望 4.1 收录 OpenBSD/Xen；现时代码经其 GSoC 导师与其他 OpenBSD 开发者试用，进展在专门邮件列表上讨论；使用状态为家中自用与部分开发者测试，尚无生产环境用户。（BSDTalk EP69，[505.38-897.16]，L1）
- 跨项目关系与许可证立场：受访者先找 NetBSD 后经公司转入 OpenBSD，评价两者代码干净、文档优良、运行稳定且极为相似——既已互移植彼此的缺陷修复，本可更紧密合作；许可证方面，其认为 BSD 许可证不强制公司开源，是优点还是缺点取决于立场，个人对 GPL 与 BSD 均接受、认为差别不大，只有在公司语境讨论是否开放源码时才真正相关；其时已供职 AMD，公司重心在市占更大的 Linux，但研究部门仍用 BSD 以求更宽的观察面，且多位同事使用并定期阅读 BSD 动态；桌面并跑 OpenBSD、NetBSD（SPARC 与 i386）与 Solaris、Mac OS X，除 Mac 外几乎全命令行，编辑器用 VI。（BSDTalk EP69，[624.8-815.22]，L1）

**史观**：

- 总纲8 本体论上各方平等：受访者把 NetBSD 与 OpenBSD 并置为同等洁净、同源相似的两个系统，合作不足被表述为待兑现的潜力而非优劣取舍；对 GPL 与 BSD 两种许可证亦持中立接受的态度，认为差别只在商业语境中方才显现——这种对 BSD 各分支与各许可传统一视同仁的姿态，是各分支本体论平等的具体发声。（BSDTalk EP69，[645.1-706.18]，L1）
