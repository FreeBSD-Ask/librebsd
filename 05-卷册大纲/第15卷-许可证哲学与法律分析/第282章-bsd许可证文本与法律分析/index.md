# 第282章 bsd许可证文本与法律分析

## 要点

- **BSD 4-Clause** 原始版含广告条款，1999 年 7 月 22 日 **William Hoskins** 在 **Berkeley** 官方公告中宣布弃用广告条款，演进为 **3-Clause “New BSD”**，2006 年进一步简化为 **2-Clause “Simplified BSD”**。
- **BSD** 许可证核心条款包括版权声明保留、二进制分发文档声明保留、免责声明，**3-Clause** 增加背书禁止条款，**2-Clause** 移除背书条款。
- **MIT** 许可证仅保留版权声明与免责声明，**BSD 2-Clause** 与 **MIT** 实质等价；**Apache 2.0** 增加专利授权与商标条款，复杂度高于 **BSD**。
- **BSD** 许可证原始文本的最早版本需追溯至 1980 年代 **BSD 4.3 Tahoe** 分发，1990 年代通过 **CSRG** 文件标准化为 **4-Clause** 形式。
- **Creative Commons（CC）**六种组合协议＝四要素排列——**BY**（署名）/ **SA**（相同方式共享）/ **NC**（非商业）/ **ND**（禁止演绎），另有 **CC0**（公共领域奉献）；版本沿革：CC 1.0（2002-12-16 发布）为美国法移植版，2.0–3.0 为多司法辖区移植（porting）版，**4.0（2013-11-25）不再以司法辖区移植，改为国际版**。

## 史观

- 总纲第 13 条——法律与道德是利益分配：CC 以“some rights reserved”（部分权利保留）反对版权绝对主义，是“作者自决”原则的文化作品实现。
- 辨析：CC 1.0 精确发布日（2002-12-16）须 creativecommons.org 存档进一步确证（存疑项）；CC 4.0 国际版与 3.0 移植版的差异（4.0 引入全球适用条款、明确数据库权利处理）须逐版对照。
- 文献：Creative Commons. License Versions [EB/OL]. <https://creativecommons.org/share-your-work/licensing-types-examples/>.
- 总纲第 13 条——法律与道德是利益分配：标准冲突是“自由”定义之争的文本化——OSD/FSD 以“可修改、可再分发、可商用”为内核，NC/ND 与之根本冲突。
- 辨析：**编号防错**——FSD 四自由官方编号为 0–3，NC 违反自由0（不是“第1条”），ND 违反自由1+自由3（不是“第3条”）；OSD 引用须用 §1/§3/§6 条款号，不得混用。
- 文献：OSI. The Open Source Definition [EB/OL]. <https://opensource.org/osd>.
- 总纲第 13 条——法律与道德是利益分配：CC 家族中恰好落入开源/自由标准的三者，分别对应公共领域、permissive、copyleft 三种制度原型。
- 辨析：CC-BY-SA 与 GPL 同为 share-alike 家族，但适用对象（文化作品 vs 软件）与传染边界不同，不得将二者混同；CC0 与 Unlicense 的公共领域奉献机制差异（CC0 含“不得反悔”条款）须辨析。
- 文献：Creative Commons. CC0 1.0 Universal [Z/OL]. <https://creativecommons.org/publicdomain/zero/1.0/>.

- 该期辨析 ZFS 与 OpenZFS 术语：ZFS 为技术总称，OpenZFS 为 2010 年后由 illumos 延续的开源项目，Oracle ZFS 为其专有分支，二者应分别称呼。（BSD Now EP232，[3306.54-3592.66]，L2）
- FreeBSD 基金会 2018 年 1 月更新称 Kostik 负责 x86 内核的 PTI 缓解，retpoline 与 Clang 工具链缓解正在推进，并强调基金会使专职开发者能放下原计划集中应对漏洞。（BSD Now EP232，[2468.14-2777.78]，L2）
- 维护者 Kjell Wooding 阐明 mg 的定位：这是一个极小的 Emacs 风格编辑器，与 Emacs 本质不同——后者是恰好附带编辑器的 Lisp 解释器，而 mg 首先是编辑文件的工具，不内嵌编程语言、不提供游戏或浏览器式扩展，只为满足 Emacs 用户的键位肌肉记忆；他并非原作者，而是在维护过程中偶然接手，mg 于 2000 年进入 OpenBSD 基本系统。（BSDTalk EP200，[60.04-157.16]，L1）
- mg 的历史与可移植性：Wooding 回忆该编辑器 1986 年即已问世、早于 OpenBSD 存在；多年来被社区自发移植至 Debian、Mac OS X 等环境，维护者至今仍收到 Debian 用户的 bug 报告；项目并无独立便携版仓库，获取最新源码的正规途径始终是 OpenBSD 源树。（BSDTalk EP200，[359.88-401.88]，L1）
- 许可证工程：mg 初入项目时约九成代码即属 public domain，团队随后逐个联系在树作者，将全部补丁释放进 public domain，如今仅 theo mode 一个文件仍持 BSD 许可——该模式仿照 Emacs 中 ELIZA 式对话实验，输出 Theo de Raadt 多年来的言论语录，属社区自嘲文化产物；Wooding 同时指出 public domain 在瑞典等法域仍有法律适用问题。（BSDTalk EP200，[691.08-751.56]，L1）
- Wooding 的参与路径与角色变迁：他曾经营安全公司 Code Talker Communications，与一巷之隔的 Secure Networks 公司一次喝啤酒闲谈中得知 OpenBSD 开发者住在自己的家乡 Calgary，遂联系并加入项目；最初职责是维护旧 IPF 防火墙代码并整合 Darren Reed 的改动，亲历该代码被整体移出源树、代之以 PF 的大分裂；此后其贡献呈游牧状，在 hackathon 间隙深入源码各处修 bug，如 pfsync 与冗余代码问题。（BSDTalk EP200，[412.48-526.32]，L1）
- 维护哲学与状态：Wooding 的长期目标是让代码行数越来越少，通过迭代清理与简化逼近；mg 仍存在积年未修的设计缺陷，修复通常依赖某份 bug 报告将维护者唤醒；他曾在 hackathon 中专门重写文档，如今手册页可能比源码本身更长，呼应 OpenBSD 对完整 man page 的自豪传统；另曾于愚人节发布可用的 vi 模式补丁。（BSDTalk EP200，[654.32-801.48]，L1）
