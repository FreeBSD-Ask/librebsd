# 282.10 CC 协议定性考据——为何大部分 CC 协议不是开源许可证却符合 FSF 理念与开源理念

> 本子节为 2026-08-04 许可证系统性考据工程新增。必须论证“大部分 CC 协议（含 NC/ND 要素者）**不是**开源许可证，但**符合** FSF 理念与开源理念”这一双重命题，并严格区分“理念符合”与“标准符合”。FSD 四自由官方编号为 0–3（自由0 运行、自由1 研究修改、自由2 再分发、自由3 发布改进版），不得使用“第1条/第3条”错误编号。

## 282.10.1 CC 协议四要素结构与版本沿革

**要点**：**Creative Commons（CC）**六种组合协议＝四要素排列——**BY**（署名）/ **SA**（相同方式共享）/ **NC**（非商业）/ **ND**（禁止演绎），另有 **CC0**（公共领域奉献）；版本沿革：CC 1.0（2002-12-16 发布）为美国法移植版，2.0–3.0 为多司法辖区移植（porting）版，**4.0（2013-11-25）不再以司法辖区移植，改为国际版**。

**史料**：Creative Commons 官方版本说明（creativecommons.org）；SPDX License List `CC0-1.0`/`CC-BY-4.0`/`CC-BY-SA-4.0` 等条目 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：CC 以“some rights reserved”（部分权利保留）反对版权绝对主义，是“作者自决”原则的文化作品实现。

**辨析**：CC 1.0 精确发布日（2002-12-16）须 creativecommons.org 存档进一步确证（存疑项）；CC 4.0 国际版与 3.0 移植版的差异（4.0 引入全球适用条款、明确数据库权利处理）须逐版对照。

**文献**：Creative Commons. License Versions [EB/OL]. <https://creativecommons.org/share-your-work/licensing-types-examples/>；SPDX. SPDX License List [EB/OL]. <https://spdx.org/licenses/> ［A］

## 282.10.2 NC/ND 与 OSD/FSD 条款逐条对照

**要点**：含 NC 或 ND 的四种组合（BY-NC、BY-ND、BY-NC-SA、BY-NC-ND）**均非开源许可证、均非自由许可证**，因违反 OSI 开源定义（OSD）与 FSF 自由软件定义（FSD）的特定条款：

- **NC（非商业）**违反 OSD §1（自由再分发——不得限制出售/赠送、不得要求版税）与 §6（不歧视应用领域——不得禁止商业使用）；违反 FSD **自由0（运行自由）**——gnu.org 明示“自由软件必须可以商用”；亦排除 FSD 自由2（再分发——可收费分发）。
- **ND（禁止演绎）**违反 OSD §3（衍生作品——必须允许修改与衍生并以相同条款分发）；违反 FSD **自由1（研究并修改）与自由3（发布改进版）**。
**史料**：OSI Open Source Definition 官方条款（opensource.org/osd）；FSF Free Software Definition 官方文本（gnu.org/philosophy/free-sw.html）；Creative Commons 官方条款 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：标准冲突是“自由”定义之争的文本化——OSD/FSD 以“可修改、可再分发、可商用”为内核，NC/ND 与之根本冲突。

**辨析**：**编号防错**——FSD 四自由官方编号为 0–3，NC 违反自由0（不是“第1条”），ND 违反自由1+自由3（不是“第3条”）；OSD 引用须用 §1/§3/§6 条款号，不得混用。

**文献**：OSI. The Open Source Definition [EB/OL]. <https://opensource.org/osd>；FSF. What is Free Software? [EB/OL]. <https://www.gnu.org/philosophy/free-sw.html> ［A］

## 282.10.3 符合开源标准的例外：CC0、CC-BY、CC-BY-SA

**要点**：仅 **CC0-1.0**（公共领域奉献，类 Unlicense）、**CC-BY**（署名，类 permissive）、**CC-BY-SA**（署名-相同方式共享，类 copyleft）符合开源/自由标准；CC-BY-SA 的“相同方式共享”＝GPL 继承条款，是 copyleft 从软件向文化/科学/教育领域的制度迁移。

**史料**：CC0-1.0 官方文本（creativecommons.org/publicdomain/zero/1.0/）；FSF 对 CC 许可证的官方态度清单（gnu.org/licenses/license-list.html） ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：CC 家族中恰好落入开源/自由标准的三者，分别对应公共领域、permissive、copyleft 三种制度原型。

**辨析**：CC-BY-SA 与 GPL 同为 share-alike 家族，但适用对象（文化作品 vs 软件）与传染边界不同，不得将二者混同；CC0 与 Unlicense 的公共领域奉献机制差异（CC0 含“不得反悔”条款）须辨析。

**文献**：Creative Commons. CC0 1.0 Universal [Z/OL]. <https://creativecommons.org/publicdomain/zero/1.0/>；FSF. Various Licenses and Comments about Them [EB/OL]. <https://www.gnu.org/licenses/license-list.html> ［A］

## 282.10.4 理念符合 ≠ 标准符合：五维度论证

**要点**：CC 家族作为整体“符合 FSF 理念与开源理念”，**不等于**通过了 OSD/FSD 标准测试。五个维度：

  1. **共享文化伦理同构**——CC“some rights reserved”与开源“free sharing”共享信息自由伦理根基，都反对版权绝对主义；
  2. **创作者控制权**——CC 与 FSF 都主张创作者对作品使用的保留性控制（区别于公共领域的无保留放弃）；
  3. **Copyleft 精神延伸**——CC-BY-SA 的 share-alike 是 copyleft 从软件向文化领域的制度迁移；
  4. **反商业侵占同构**——NC 的伦理动机（防止文化作品被商业无偿掠夺而不回馈）与 FSF 对专有软件“无偿取用、闭源回报”的批判**结构同构**——注意是动机同构、非条款同构（FSF 仍反对 NC 限制本身）；
  5. **自由观多元性与同源性**——CC 侧重文化自由、FSF 侧重软件自由，同根于启蒙自由传统；Lessig（CC 创始人）明确 CC 受自由软件运动启发。
**史料**：Lessig 关于 CC 与自由软件运动关系的公开论述；FSF 对 CC 的官方分层态度（BY/BY-SA 自由、NC/ND 非自由、CC0 自由） ［A］

**史观**：总纲第 25 条——逻辑是形式主义：理念符合与标准符合的区分，是“自由”概念的多元理解与制度标准的严格性之间的张力。

**辨析**：**关键辨析**——“CC 符合开源理念”不得被误读为“CC 是开源许可证”；书中表述建议：“CC 协议家族的设计目标不是生产‘开源软件许可证’，而是为文化作品提供作者自决的弹性光谱；其中 BY/BY-SA/CC0 恰好落入开源/自由标准，含 NC/ND 的组合则因违反 OSD/FSD 特定条款而停留在‘理念同道、标准不合’的位置。”（此为 281.10 题眼）

**文献**：LESSIG L. Free Culture [M]. New York: Penguin Press, 2004；FSF. Various Licenses and Comments about Them [EB/OL]. <https://www.gnu.org/licenses/license-list.html> ［A］

**要点**：

- TiddlyWiki 的独特设计：传统 wiki 是架设于 web 服务器的网站、内容分页、点链接跳转新页；TiddlyWiki 则把信息块（作者自嘲起名不当的 tiddlers）呈现在单个页面内、随阅读动态开合，相当于微型 wiki。其整体存在于单个 HTML 文件之中，可如 Word 文档般拷入 U 盘、邮件传送、双击即在浏览器中打开并就地编辑、保存后写回磁盘；发布只需把文件拷上任意 web 服务器（如 Google Pages 账号即可），无需 PHP 或 Perl 扩展、也无需数据库后端。（BSDTalk EP24，[328.50-455.74]，L1）
- 游击 wiki 场景：基础设施需求薄如纸，使其可部署于无法架设真正 wiki 的场合——压制性政权之下，或大型跨国公司之内（IT 部门忙于安装本周的安全补丁，无暇为你建站）；任何人下载即可在本机运行，并在工作小组内分享，全程无需 IT 部门参与。（BSDTalk EP24，[459.54-512.06]，L1）
- 实现与规模：其行为层为 JavaScript——在浏览器中查看源码，开头三四千行 JavaScript 看上去与常规 C 代码相仿，内容打包于文件末尾的一小块 HTML；跨浏览器兼容是作者的祸根，浏览器间差异细小而难查，Internet Explorer 与其他所有浏览器做法不同，Firefox 与 Safari 则可互通。可扩展性出人意料：许多用户的单文件已达 1.5 MB 左右（约 200 KB 为 JavaScript 代码、其余 1.2 MB 为用户内容，相当于几本书），而性能上限来自浏览器——浏览器 JavaScript 原为图片翻转之类小把戏而设计，此项目是在掰弯浏览器。（BSDTalk EP24，[512.06-657.50]，L1）
- 许可证演变：初版仅作实验发布、未细想许可证，恰逢 Creative Commons 刚上线且当时受关注的作品多用 CC，遂采用允许共享但为自己保留商业权利的 CC 版本（心底想着或许能商业开发）；收到的普遍反馈是 CC 是内容许可证而非代码许可证（当事人不认为必然如此，但反馈之多促使复核）；两三封论证有力的来信指出非商业条款的麻烦——排除商业使用几乎等于排除一切有意思的再利用。作者的目标是让人尽可能多地使用、谈论与思考它，不愿设任何门槛；粗查发现 BSD 许可证短到能读懂、足够开放；且 TiddlyWiki 是开源更是暴露源——查看源码即见全部、不过一个文本文件、无从保护，索性把限制化为优点，选一个能找到的最友好开放的许可证。（BSDTalk EP24，[662.22-815.66]，L1）
- Wiki 词源与理念背景（当事人转述）：WikiWiki 为夏威夷语之快，夏威夷公交车上即写有 wiki wiki；Ward Cunningham 发明 wiki-wiki web 时寻找形容其编辑之快的词，其核心洞见是协作场景中最难的是促使人贡献，故把编辑门槛降到最低——任何人可编辑任何页并保存；直觉上似在纵容破坏，但在重要的社区场景中社区能自我调节保持内容切题有用，Wikipedia 为经典例；wiki 使链接如标点般轻易，camel case 规则令大写开头的复合词自动成为链接。（BSDTalk EP24，[155.00-323.74]，L2）
