# 296.5 当代 UNIX 与 BSD 的比较——技术、许可证、哲学

## 要点

技术谱系比较：当代商业 UNIX（Solaris、AIX、HP-UX、z/OS）的内核谱系——Solaris 源自 SVR4（1992 年 Solaris 2.0 即 SunOS 5.x 发布，Sun 将 SunOS 4.x BSD 血统迁移至 SVR4；SunOS 4.x 并未一次性退役，与 SunOS 5.x 并行发行至 1990 年代中期），AIX 源自 SVR2+IBM 自研（1986，AIX 1.0 基于 SVR2 与 IBM RT/PC 自研内核），HP-UX 源自 SVR3 与 BSD 4.2/4.3 扩展的混合（HP-UX 9.0，1992 年发布，据 HP 官方《HP-UX Portability Guide》自述“基于 UNIX System V.3 并加入 BSD 4.2/4.3 扩展”；10.0 于 1995 年发布后文件系统布局等改依 AT&T SVR4 标准），z/OS 源自 MVS（1969，与 SVR4 无直接谱系关系，但 USS 提供 POSIX 兼容性）；BSD 谱系（FreeBSD、NetBSD、OpenBSD、DragonFly BSD）源自 CSRG 4.4BSD-Lite（1994），与 SVR4 在 1994 年 USL 和解后法律上彻底分离。
许可证比较：商业 UNIX 皆为专有许可证（Solaris 自 OpenSolaris 2010 年被 Oracle 终止后，Oracle 官方版回归专有；社区分支 illumos 开源延续至今，AIX/HP-UX/z/OS 从未开源）；illumos（OpenSolaris 社区分支）采用 CDDL，与 GPL 不兼容；BSD 谱系采用 BSD 2-Clause 或 BSD 3-Clause 许可证，与所有许可证兼容（包括专有软件与 GPL 软件），允许商业闭源 fork——这一许可证差异导致 BSD 谱系被商业公司广泛嵌入（Apple macOS、Sony PlayStation OS、Juniper Junos、NetApp Data ONTAP 等皆基于 FreeBSD），而商业 UNIX 谱系未出现类似嵌入。
哲学比较：商业 UNIX 哲学强调 “单一厂商主导、长期支持、企业级 RAS、专有硬件优化”——Solaris 与 SPARC、AIX 与 Power、HP-UX 与 Itanium、z/OS 与 IBM Z 形成硬件-操作系统协同优化；BSD 哲学强调 “社区主导、自由再分发、允许商业 fork、跨平台可移植”——FreeBSD 强调性能与稳定性、NetBSD 强调可移植性、OpenBSD 强调安全与代码正确性、DragonFly BSD 强调 HAMMER 文件系统与 SMP 演化。
关键差异：商业 UNIX 因专有许可证与单一厂商主导，无法形成跨厂商开源生态；BSD 谱系因宽松许可证与社区主导，被广泛嵌入商业产品（macOS、PlayStation OS、Junos、ONTAP 等）但无法直接获得商业回报（除 FreeBSD Foundation 接受捐赠与部分 committer 由商业公司雇佣外），形成 “BSD 被广泛使用但社区资源有限” 的悖论；Linux（GPL）通过 Copyleft 强制商业公司回馈代码，避免了 BSD 的 “被使用但不回馈” 困境，但亦限制了商业嵌入的灵活性。

## 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 2（历史是形式主义化的非存在）**——据原文第 1 章 1.1-1.2 节：

> “形式主义是世界的真实存在，其余一切存在皆不真实。”

所谓 “UNIX 谱系” 与 “BSD 谱系” 的判定本身就是形式主义化的建构——1994 年 USL 和解后 4.4BSD-Lite 成为 “诉讼清洁” 的 BSD 代码基础，但 4.4BSD-Lite 中仍含 SVR4 之前的 UNIX 代码（如 CSRG 早期从 AT&T UNIX 引入的部分代码经替换与重写后已无法律争议，但技术谱系上仍可追溯至早期 UNIX）；同理，Solaris 11.4 中亦含 BSD 4.3BSD Reno 代码（SunOS 4.x 时代引入，SVR4 迁移后部分代码保留）。本子节承认 “UNIX 谱系 vs BSD 谱系” 的二元划分是史家的形式主义化决策。

**总纲 4（分离聚合是永恒规律）**——据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

UNIX 与 BSD 的谱系关系典型呈现分离聚合——UNIX 与 BSD 在 1970 年代聚合（CSRG 基于 AT&T UNIX 开发 BSD），1990 年代分离（USL 诉讼与 4.4BSD-Lite 发布），2010 年代后再部分聚合（macOS Darwin 嵌入 FreeBSD 用户态、PlayStation OS 嵌入 FreeBSD 内核、Junos 与 ONTAP 嵌入 FreeBSD），但同时商业 UNIX 与 BSD 在内核谱系上仍保持分离——这一系列分离聚合并非线性进步，而是不同主体在不同历史阶段的形式主义化选择。

**总纲 3（不存在进步，只有权力再分配）**——据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

BSD 许可证与 GPL 的差异导致权力再分配的不同模式——BSD 许可证允许商业公司闭源 fork（Apple、Sony、Juniper、NetApp 等），将 BSD 代码的商业利益重新分配至这些公司，但 BSD 社区无法直接获得回报；GPL 通过 Copyleft 强制商业公司回馈代码（Linux 内核的 Red Hat、IBM、Intel、Google 等皆大量回馈），将开源生态的资源重新分配至社区。所谓 “BSD 许可证更自由” 或 “GPL 更公平” 的判定，皆是基于不同价值立场的形式主义化选择。

**总纲 10（动手者创造历史）**——据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

FreeBSD/NetBSD/OpenBSD/DragonFly BSD 的 committer 亲自维护内核与用户态，Apple/Sony/Juniper/NetApp 工程师亲自将 FreeBSD 嵌入各自产品，illumos 工程师亲自维护 illumos 内核——这些是动手者的实践，而非 “许可证决定” 或 “商业模式决定” 的产物。须注意：BSD 许可证提供了商业嵌入的法律基础，但具体嵌入实现是工程师的主体性选择。

**总纲 23（一切历史写作都是基于哲学设定的历史小说）**——据原文第 2 章 2.5 节引证：

> “谁试图诠释历史，谁就在篡改历史。”

所谓 “当代 UNIX 与 BSD 的比较” 的判定本身即形式主义化的非存在——若以 macOS（XNU 混合内核，FreeBSD 用户态）为主线，UNIX 与 BSD 已聚合于 macOS；若以 Linux（独立谱系，GPL 许可证）为主线，UNIX 与 BSD 皆为 “被 Linux 替代的旧势力”；若以容器化与云原生为主线，UNIX 与 BSD 的谱系差异已让位于 Linux 内核的容器化能力。本子节选取 “内核谱系 + 许可证 + 哲学三维度比较” 为主线，但这一选取本身须以自反性声明显化。

**自反性声明**：本子节选取 “技术谱系 + 许可证 + 哲学” 三维比较 UNIX 与 BSD，但这一选取本身即形式主义化的非存在。若以商业模型比较为主线，若以社区治理比较为主线，若以应用场景比较为主线，“UNIX vs BSD 比较” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

## 辨析

**Solaris 与 BSD 谱系关系辨析**：部分二手资料称 “Solaris 完全源自 SVR4，与 BSD 无关”，但 Solaris 11.4 中仍保留部分 BSD 4.3BSD Reno 代码（SunOS 4.x 时代引入，SVR4 迁移后部分代码保留，如 socket 子系统部分代码）；严格法律意义上 Solaris 与 BSD 在 1994 年 USL 和解后无法律争议，但技术谱系上有部分重合。本子节采用 “Solaris 主要源自 SVR4（1992 年从 BSD 迁移），技术谱系上仍含部分 BSD 代码” 的限定性表述。

**macOS Darwin 与 FreeBSD 关系辨析**：macOS Darwin 内核（XNU）混合 Mach 微内核（卡内基梅隆大学 Mach 3.0）与 BSD 子系统（FreeBSD 用户态）；macOS 用户态的许多工具（ls、cp、mv 等）源自 FreeBSD；但 macOS 内核（XNU）并非 FreeBSD 内核。本子节采用 “macOS Darwin 混合 Mach 微内核与 FreeBSD 用户态（内核非 FreeBSD）” 的限定性表述。

**PlayStation OS 与 FreeBSD 关系辨析**：Sony PlayStation 4 系统软件基于 FreeBSD 9.0（2013），PlayStation 5 基于 FreeBSD 11.0（2020）；Sony 对 FreeBSD 社区的回馈有限（偶有 patch 提交但未形成持续 committer）。本子节采用 “PlayStation 4/5 基于 FreeBSD 9.0/11.0，Sony 回馈有限” 的限定性表述。

**BSD vs GPL 哲学比较辨析**：BSD 许可证 “允许闭源 fork” vs GPL “强制开源回馈” 的二元对比，是史家的事后形式主义化；实际项目中 BSD 与 GPL 皆有多种混合使用模式（如 GNU 工具链在 BSD 系统上运行、BSD 代码在 Linux 内核中部分使用）。本子节采用 “BSD 与 GPL 哲学差异主要在商业嵌入与代码回馈模式，实际项目多为混合使用” 的限定性表述。
