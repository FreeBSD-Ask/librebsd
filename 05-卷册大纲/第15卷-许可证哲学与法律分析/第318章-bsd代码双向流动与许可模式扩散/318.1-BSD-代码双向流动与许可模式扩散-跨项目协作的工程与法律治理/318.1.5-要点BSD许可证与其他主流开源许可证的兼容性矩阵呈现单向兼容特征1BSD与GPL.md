# 318.1.5 要点BSD许可证与其他主流开源许可证的兼容性矩阵呈现单向兼容特征1BSD与GPL

**要点**：BSD 许可证与其他主流开源许可证的兼容性矩阵呈现 “单向兼容” 特征——（1）**BSD 与 GPL 的兼容性**：BSD-2-Clause 与 BSD-3-Clause 均与 GPLv2、GPLv3 兼容，BSD 代码可进入 GPL 项目（如 Linux 内核中保留的部分 BSD 代码），但 GPL 代码不可进入 BSD 项目（因 GPL 的 copyleft 条款要求衍生作品亦采用 GPL）；Linux 内核源代码中可 grep 到 “Regents of the University of California” 版权声明，证明 BSD 代码进入 Linux 内核；BSD 与 GPL 的单向兼容性是 BSD 阵营 “去 GPL 化” 战略的动因——FreeBSD 10.0 起 Clang 替代 GCC 成为默认编译器，部分原因是 GCC 在 GPLv3 转换后因下游消费者反对未能进入 FreeBSD 基本系统；（2）**BSD 与 Apache 2.0 的兼容性**：BSD-2-Clause 与 Apache 2.0 兼容，Apache 2.0 代码可进入 BSD 项目（如部分 Apache 软件基金会库被 FreeBSD 采用），BSD 代码亦可进入 Apache 项目；BSD 与 Apache 2.0 的双向兼容性源于二者均为宽松许可证且 Apache 2.0 的专利反制条款不与 BSD 冲突；（3）**BSD 与 MIT 的兼容性**：BSD 与 MIT 高度兼容，二者均为宽松许可证，可双向流通；MIT 许可证在 X Window System、JavaScript 生态中的扩散与 BSD 许可证在 UNIX 生态中的扩散形成互补；（4）**BSD 与 MPL 2.0 的兼容性**：BSD 与 MPL 2.0（Mozilla Public License 2.0）兼容，MPL 2.0 的弱 copyleft 条款（文件级 copyleft）不与 BSD 冲突，二者可双向流通；MPL 2.0 在 Mozilla Firefox、Redis（2024 年改为 RSALv2/SSPLv1 前曾考虑 MPL 2.0）等项目中应用；（5）**BSD 与 CDDL 的兼容性**：BSD 与 CDDL（Common Development and Distribution License，Sun Microsystems 基于 MPL 1.0 修改）兼容，CDDL 代码可进入 BSD 项目（如 OpenZFS 的 CDDL 代码进入 FreeBSD 基本系统），但 CDDL 与 GPL 不兼容（此为 Sun 选择 CDDL 而非 GPL 发布 OpenSolaris 的原因之一）；OpenZFS 在 FreeBSD 中以 CDDL 许可证保留，与 FreeBSD 基本系统的 BSD 许可证并存。BSD 许可证与其他许可证的兼容性矩阵体现 BSD 许可证的 “基础设施性”——BSD 代码可进入几乎所有其他许可证体系（GPL、Apache、MIT、MPL、CDDL），但其他许可证代码进入 BSD 受 copyleft 条款限制——此 “单向兼容” 是 BSD 阵营 “去 GPL 化” 战略的许可证层面动因

**史料**：FSF 许可证兼容性矩阵（gnu.org/licenses/license-list.html）；OSI 许可证兼容性说明（opensource.org/licenses）；GPLv2 第 6 条与 GPLv3 第 5 条关于 “附加许可” 的条款；Apache 2.0 第 4 条关于 “重新分发” 的条款；MPL 2.0 第 3.3 条关于 “可 Secondary License” 的条款；CDDL 第 3.4 条关于 “文件级 copyleft” 的条款；Linux 内核源代码 grep “Regents” 结果（git.kernel.org）；FreeBSD src/contrib/openzfs 中的 CDDL 许可证声明（freebsd.org/copyright/freebsd-license/ 与 CDDL 文本对比）；OpenZFS 许可证说明（openzfs.org/wiki/FAQ） ［A］

**史观**：总纲第 13 条——法律与道德是利益分配（见 据原文第 11 章 11.1 节）：“任何法律问题都是政治问题，任何政治问题都是利益分配问题”——BSD 与 GPL/Apache/MIT/MPL/CDDL 的兼容性矩阵是法律层面的利益分配规则——BSD 的 “单向兼容”（BSD 代码可进入 GPL 但 GPL 代码不可进入 BSD）是 copyleft 与非 copyleft 之间的利益分配规则，决定了 BSD 阵营与 GPL 阵营之间的代码流向；总纲第 13 条——法律与道德是利益分配（见 据原文第 11 章 11.1 节）：“任何法律问题都是政治问题，任何政治问题都是利益分配问题”——BSD 的 “单向兼容” 是 BSD 阵营 “被利用却不被回馈” 的许可证层面动因，而 GPL 的 copyleft 通过强制回馈 “聚拢了生态”〔订正注：原挂“总纲第 24 条——应用于 BSD 史编纂”系伪标签，权威第 24 条为“美是消解性的体验”；“被利用却不被回馈”的利益结构依权威表改挂第 13 条〕；总纲第 7 条——理论必须自反（见 据原文第 6 章 6.3 节）：“任何理论本身的发展最后都会变成八股文，变成最反动的，因为他没有勇气否定自己”——BSD 阵营 “去 GPL 化” 战略（如 FreeBSD 10.0 起 Clang 替代 GCC）是 BSD 许可证哲学的自反性显现——BSD 阵营承认 copyleft 的回馈机制对生态的聚拢作用，但选择坚守 BSD 许可证的 “消极自由” 而非采用 copyleft

**辨析**：考据过程留痕——【查证来源】FSF 许可证兼容性矩阵（gnu.org/licenses/license-list.html）经一手核验，BSD-2-Clause 与 BSD-3-Clause 均与 GPLv2、GPLv3 兼容；GPLv2 第 6 条与 GPLv3 第 5 条关于 “附加许可” 的条款经 GPL 原文核验；Apache 2.0 第 4 条关于 “重新分发” 的条款经 Apache 2.0 原文核验；MPL 2.0 第 3.3 条关于 “可 Secondary License” 的条款经 MPL 2.0 原文核验；CDDL 第 3.4 条关于 “文件级 copyleft” 的条款经 CDDL 原文核验；Linux 内核源代码 grep “Regents” 结果经 git.kernel.org 核验；FreeBSD src/contrib/openzfs 中的 CDDL 许可证声明经 FreeBSD 源代码核验；OpenZFS 许可证说明经 openzfs.org/wiki/FAQ 一手核验；【交叉验证方法】FSF 许可证兼容性矩阵（FSF 官方）与 OSI 许可证兼容性说明（OSI 官方）双向印证 “BSD 与 GPL/Apache/MIT/MPL/CDDL 的兼容性” 的判断；Linux 内核源代码中 “Regents of the University of California” 版权声明（代码级证据）与 FSF 兼容性矩阵（法律层面判断）交叉印证 “BSD 代码进入 Linux 内核” 的事实层面成立；FreeBSD src/contrib/openzfs 中的 CDDL 许可证声明（代码级证据）与 OpenZFS 许可证说明（项目官方）双向印证 “OpenZFS 在 FreeBSD 中以 CDDL 许可证保留” 的事实层面成立；【存疑判定依据】“BSD 代码进入 Linux 内核的具体比例” 须 grep 统计核实（**存疑：Linux 内核源代码中 BSD 代码的具体比例须独立 grep 统计，本节仅引用 grep “Regents” 结果作为存在性证据**）；“GCC 在 GPLv3 转换后因下游消费者反对未能进入 FreeBSD 基本系统” 的判断须查 FreeBSD 邮件列表讨论（**存疑：GCC 在 FreeBSD 中的演化须查 FreeBSD commit 历史与邮件列表讨论，本节判断基于 FreeBSD 9.0 release notes 与 Divacky 2011 演讲**）；“CDDL 与 GPL 不兼容” 的判断在法律层面成立（FSF 与 Sun 均承认）但 “Sun 选择 CDDL 而非 GPL 发布 OpenSolaris 的原因” 须查 Sun 内部决策文档（**存疑：Sun 选择 CDDL 的具体动机须查 Sun 内部文档或工程师访谈**）；0 信任原则提示：FSF 作为 copyleft 推动者其许可证兼容性矩阵存在立场偏差风险（倾向强调 copyleft 优势），须与 OSI 与法律学术文献独立核验；OSI 作为开源推动者其许可证兼容性说明存在立场偏差风险（倾向强调宽松许可证优势），须与 FSF 与法律学术文献独立核验；OpenZFS 许可证说明作为项目自身文档存在自利偏差风险（倾向淡化 CDDL/GPL 不兼容问题），须与 FSF 与 Sun 独立声明交叉验证
