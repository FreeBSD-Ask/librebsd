# 299.2 GNU 与 BSD 的比较——许可证、哲学、生态

#### 要点

GNU 与 BSD 在自由软件谱系中呈现不可通约性——本子节从许可证、哲学、生态、开发模式、商业化五个维度系统比较，呈现多方主体性辩证张力，禁止“优劣”二元判断。
许可证维度——GPL 传染性 vs BSD 宽松：GPL（GPLv1/v2/v3）要求衍生作品必须以 GPL 发布（copyleft 传染）；BSD（2-Clause、3-Clause）允许 BSD 代码被闭源再分发（仅要求保留版权声明）；二者法律机制根本不同——GPL 是“传染”（copyleft），BSD 是“宽松”（permissive）；二者哲学根本不同——GPL 要求“使用者必须保持开源”，BSD 承认“使用者有闭源自由”。
哲学维度——自由即权利（Stallman）vs 自由即责任（BSD 传统）：Stallman 与 FSF 的自由软件哲学强调“自由即权利”——使用、研究、修改、再分发是用户的权利，应通过 copyleft 强制保障；BSD 传统哲学强调“自由即责任”——用户有自由使用 BSD 代码，但有责任承担使用后果（BSD 许可证明确免责），不强制保持开源；本子节呈现不可通约性，禁止“优劣”二元判断。
生态维度——GNU/Linux 主流 vs FreeBSD/OpenBSD/NetBSD 边缘：2026 年 GNU/Linux 服务器市场占有率约 70%（含云计算），桌面市场占有率约 4%（含 ChromeOS），嵌入式与移动领域通过 Android（基于 Linux 内核）占据主导；FreeBSD 在 Netflix、Juniper、Sony PlayStation 等特定领域有重要部署，但整体市场占有率远低于 Linux；OpenBSD 在安全研究、密码学（OpenSSH）、防火墙（**pf(4)**）等领域有重要影响，但用户数极少；NetBSD 在跨平台移植领域有传统优势，但市场占有率极低；本子节禁止“GPL 必胜”目的论，呈现多方主体性辩证张力。
开发模式维度——GNU 邮件列表驱动 vs BSD Core Team 精英制：GNU 项目长期采用邮件列表驱动（gnu.org 邮件列表、Savannah 平台、2020s 后部分迁移至 GitLab），决策基于共识与维护者权威；BSD 项目（FreeBSD、OpenBSD、NetBSD）采用 Core Team 精英制，Core Team 由 committer 选举产生，对项目方向有最终决策权；二者皆是形式主义化的社区治理结构，皆非“客观最优”。
商业化维度——GPL 商业模式双授权服务 vs BSD 商业模式嵌入式设备固件：GPL 商业模式主要为双授权（开源版 GPL + 商业版专有许可，如 MySQL、Qt）与服务（订阅支持、咨询、培训，如 Red Hat Enterprise Linux）；BSD 商业模式主要为嵌入式设备固件（路由器、防火墙、存储设备，基于 FreeBSD 的 Juniper Junos、Sony PlayStation OS、Netflix CDN）与闭源衍生（macOS 基于 Darwin 与 FreeBSD 用户态）；本子节呈现二者商业模式的多方主体性，禁止“优劣”二元判断。
GNU 与 BSD 在自由软件谱系中的不可通约性——禁止“优劣”二元判断：GPL 与 BSD 在许可证哲学、社区治理、商业模式上根本不同，二者皆有其合理性，皆有其代价——BSD 的代价是可能被闭源挪用（如 macOS 闭源 BSD 代码、Sony PlayStation 闭源 FreeBSD），GPL 的代价是商业兼容性受限（如 GPLv3 反 Tivoization 限制嵌入式厂商、GPL 传染限制与专有软件组合）；本子节明确禁止“优劣”二元判断。

#### 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 1（形式主义是世界的真实存在）**——见 据原文第 1 章 1.1-1.2 节：GPL 与 BSD 作为两种形式主义化的建构——GPL 的“copyleft 传染”法律机制、BSD 的“宽松许可”法律机制——皆是设计师对“自由软件应当如何保障”的主体性选择，无“客观最优”的“自由软件许可证本质”。二者不可通约，禁止“优劣”二元判断。

**总纲 4（分离聚合是永恒规律）**——见 据原文第 4 章 4.1 节：GNU 与 BSD 从 Unix 谱系的分离（1983-1989），到 GNU/Linux 与 BSD 在服务器市场的聚合（1990s-2000s），到 BSD 化进程的再分离（Clang 替代 GCC、libedit 替代 readline等）——这一系列分离聚合并非线性进步，而是不同形式主义的循环呈现。

**总纲 5（没有必然性，只有偶然性）**——见 据原文第 5 章 5.2 节：若 Stallman 未在 1989 年起草 GPL，若 BSD 未在 1989 年从 AT&T 代码中清理（Net/2），若 USL v. BSDi 诉讼未在 1992-1994 年限制 BSD 分发，GNU 与 BSD 的相对地位会呈现完全不同的脉络。所谓“GPL 必胜”或“BSD 必衰”的叙事是史家的事后重构，本子节明确禁止目的论。

**总纲 10（动手者创造历史）**——见 据原文第 14 章 14.1-14.2 节：Stallman 亲自起草 GPL，BSD 开发者（Marshall Kirk McKusick（马歇尔·柯克·麦库西克）、Mike Karels 等）亲自维护 BSD 许可证文本，Theo de Raadt 亲自在 openbsd-misc 邮件列表阐述 OpenBSD 对 GPL 的立场——这些是动手者的实践，而非“FSF 决定”或“BSD 阵营决定”等组织决策的产物。

**总纲 2（历史是形式主义化的非存在）**——见 据原文第 2 章 2.5 节：所谓“GNU 与 BSD 比较（2026）”的判定本身即形式主义化的非存在——若以 macOS 闭源 BSD 代码为主线（BSD 闭源挪用史），若以 Android 闭源 Linux 内核为主线（GPL 闭源挪用史），若以 BSD 化进程为主线（GPL 向 BSD 替代史），“GNU 与 BSD 比较史”会呈现完全不同的脉络。本子节选取“五维度比较”为主线，但这一选取本身须以自反性声明显化。

**自反性声明**：本子节选取“许可证 + 哲学 + 生态 + 开发模式 + 商业化”五维度为 GNU 与 BSD 比较主线，但这一选取本身即形式主义化的非存在。若以技术架构（宏内核 vs 宏内核）为主线，若以社区治理（Core Team vs 维护者权威）为主线，若以法律诉讼（USL v. BSDi vs SCO v. IBM）为主线，“GNU 与 BSD 比较史”会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

#### 辨析

**GPL “传染”表述辨析**：部分二手资料称“GPL 是病毒”，但“病毒”表述被 FSF 与部分法律学者认为带有贬义，本子节采用“copyleft 传染”的中性表述；“传染”指 GPL 要求衍生作品以 GPL 发布的法律机制，非贬义。

**BSD “宽松”表述辨析**：部分二手资料称“BSD 是公共领域许可证”，但 BSD 许可证非公共领域——BSD 代码仍受版权保护，仅要求保留版权声明与免责声明；公共领域（public domain）意味着放弃所有版权，BSD 许可证保留版权但授予广泛使用权。本子节采用“BSD 宽松许可，非公共领域”的限定性表述。

**macOS 与 FreeBSD 关系辨析**：部分二手资料称“macOS 基于 FreeBSD”，但准确表述是 macOS（Darwin）用户态部分（如一些命令行工具）来源于 FreeBSD，但 macOS 内核（XNU）是 Mach + BSD 混合内核，非 FreeBSD 内核；macOS 闭源其 BSD 衍生代码，是 BSD 闭源挪用的典型案例。本子节采用“macOS 部分用户态来源于 FreeBSD，非 macOS 基于 FreeBSD 内核”的区分性表述。

**GPLv3 反 Tivoization 对 BSD 影响辨析**：部分二手资料称“GPLv3 推动 BSD 化”，但准确表述是 GPLv3 反 Tivoization 条款（§6）是 BSD 化进程的外部推动力之一——嵌入式厂商为避免 GPLv3 反 Tivoization 限制，倾向选择 BSD 代码替代 GPL 代码（如 Clang 替代 GCC、libedit 替代 readline）；BSD 化是多因素叠加，GPLv3 是重要因素但非唯一。本子节采用“GPLv3 是 BSD 化的外部推动力之一，非唯一”的限定性表述。
