# 317.1.8 2026年6月至7月间FreeBSD项目通过freebsdannounce邮件列

- **要点**：2026 年 6 月至 7 月间，FreeBSD 项目通过 freebsd-announce 邮件列表连续发布三项关键治理公告，标志着项目治理结构的代际更替与维护周期的常态化推进。第一为 **2026 年核心团队选举结果公告**——2026-06-24（UTC），Kyle Evans 以个人名义发信“New FreeBSD Core Team Elected”，宣告新一届核心团队经社区选举产生，邮件存档位于 **<https://lists.freebsd.org/archives/freebsd-announce/2026-June/000278.html>**；此为 FreeBSD 治理结构的常规代际更替，核心团队作为项目的最终决策机构每两年选举一次。第二为** FreeBSD 14.3 end-of-life 公告 **——2026-06-20（UTC），FreeBSD Security Officer 以官方账号发信“FreeBSD 14.3 end-of-life”，宣告 FreeBSD 14.3-RELEASE 自该日起不再接收安全补丁与 Errata 修复，邮件存档位于 **<https://lists.freebsd.org/archives/freebsd-announce/2026-June/000277.html>**；14.3 的 EOL 意味着 14.x 系列的维护负担收缩至 14.4-RELEASE（2026-03-10 发布）单一分支，用户须迁移至 14.4 或 15.x 系列。第三为 **Ports Repository Freeze 公告**——2026-07-22（UTC），Kyle Evans 再次发信“Ports Repository Freeze”，宣告 Ports 仓库进入冻结期，邮件存档位于 **<https://lists.freebsd.org/archives/freebsd-announce/2026-July/000294.html>**；Ports Freeze 是 FreeBSD 季度发布流程的常态化环节，冻结期间 ports 树不接受非关键性更新，以保证镜像同步与发布质量。三项公告在时间上紧凑相连（2026-06-20 至 2026-07-22，跨度 32 天），反映 FreeBSD 项目治理的“选举—维护—发布”三重节奏：选举更替决策层、EOL 收缩维护层、Freeze 规范发布层。
- **史料**：freebsd-announce 邮件列表存档（lists.freebsd.org/archives/freebsd-announce/，2026-June 与 2026-July 存档）；FreeBSD Security Advisories 页（<https://www.freebsd.org/security/advisories/>，2026-07-23 访问，印证 14.3 EOL 后 SA 公告不再覆盖 14.3 分支）；FreeBSD Release Information 页（<https://www.freebsd.org/releases/>，2026-07-23 访问，Legacy Releases 列出 14.3 但不再列为 Production Release）；freebsd.duckdb 中 freebsd-src 仓库 `tags` 表（2026-06-12 `release/15.1.0` tag 与 2026-06-16 公告的 4 天偏差印证 Colin Percival Release Engineer Lead 任内的标准流程）；原材料/研究/考据记录/20260723_announcements-freebsd.md（考据过程留痕） ［A］
- **史观**：总纲第 5 条——组织结构塑造技术路径：核心团队选举体现 FreeBSD“精英民主”治理结构——由活跃提交者选举产生核心团队，核心团队决策项目方向，与 Linux 内核的“独裁者 + 副独裁者”模式形成对比；技术选择的代价：14.3 EOL 是维护周期收缩的必然代价——FreeBSD 资源有限，无法无限期维护所有历史分支，EOL 是将有限资源集中于当前分支的理性选择，但对仍在使用 14.3 的用户构成迁移负担；0 信任原则：三项公告虽均通过 freebsd-announce 邮件列表一手来源确认，但公告的具体内容（如新 Core Team 成员名单）因邮件正文未在本次抓取中保留而标注 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
