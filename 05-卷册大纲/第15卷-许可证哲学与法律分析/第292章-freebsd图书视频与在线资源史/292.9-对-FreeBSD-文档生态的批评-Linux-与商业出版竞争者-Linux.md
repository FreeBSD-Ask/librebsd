# 292.9 对 FreeBSD 文档生态的批评：Linux 与商业出版竞争者——Linux 文档项目（LDP）与 Arch Wiki 对 FreeBSD Handbook 的对比批评、商业出版商（O'Reilly、Apress）放弃 BSD 图书市场的市场反馈、Linux 培训生态对 BSD 教育资源的挤压

## 292.9.1 Linux 文档优势的具体方面

**要点**：Linux 文档项目（LDP）1992 年起建立（经 tldp.org/history.html 一手核验，原文 “It started in 1992, before the World Wide Web existed”），文档仓库托管于 GitHub `github.com/tLDP/LDP`（经 tldp.org 首页 “GIT repository” 链接一手核验），文档分为 HOWTOs（经 tldp.org/HOWTO/HOWTO-INDEX/howtos.html 核验，完整列表超 350 篇，从 3-Button-Mouse 至 Danish-HOWTO 等按字母排序）、Guides（较长深度文档）、FAQs、man pages 四类；Arch Wiki 2005 年 7 月 8 日起在 MediaWiki 上建立活跃社区（经 wiki.archlinux.org/title/ArchWiki:About “Early history” 一手核验，原文 “2005-07-08: The ArchWiki was set up on MediaWiki”，先前叙事称 “2008 年起” 有误，应为 2005 年），Arch Wiki 文档内容以 MediaWiki 协作模式维护（非 Git 仓库），MediaWiki 源代码镜像于 `gitlab.archlinux.org/archlinux/archwiki`（GitHub 只读镜像 `github.com/archlinux/archwiki`），ArchWiki:About 页面表述 “thousands of articles”（精确文章数须通过 Special:Statistics 查询，**据一手文献印证消解^doubt-resolved-1439：精确文章数待补入**）；二者覆盖范围与更新频率优于 FreeBSD Handbook；商业培训生态（Linux Foundation Training `training.linuxfoundation.org`、Red Hat Academy）进一步拉大文档资源差距，Linux Foundation Training 提供 LFCS（Linux Foundation Certified SysAdmin）、LFCE（Linux Foundation Certified Engineer）、CKA（Certified Kubernetes Administrator）等认证课程（经 training.linuxfoundation.org 一手核验），BSD 培训生态无对应商业认证体系。[考据完成：2026-07-30 经 tldp.org、wiki.archlinux.org/title/ArchWiki:About、training.linuxfoundation.org 一手核验；Arch Wiki 启动时间修正为 2005-07-08，先前叙事 “2008 年起” 有误]

**史料**：Linux Documentation Project 历史、Arch Wiki About 页、Linux Foundation Training 目录 ［B］；freebsd.duckdb 查询 L5.1.1 显示：freebsd-doc 仓库 commit 量从 2004 年 4,000 commit（峰值）持续下降至 2024 年 854 commit，反映 FreeBSD 官方文档维护活跃度长期下滑；freebsd.duckdb 查询 L5.2.1.freebsd-doc_vs_freebsd-src 显示：freebsd-doc/freebsd-src commit 比例从 2004 年 25.70%（峰值）下降至 2024 年 5.87%（低谷），20 年间文档相对于代码的投入比例下降约 4 倍，与 Linux 文档生态（LDP/Arch Wiki 等）的扩张形成对照；外部基准 E-10 显示：**Stack Overflow** Developer Survey 中 BSD 类操作系统使用率 2019 年为 **0.1%**（近 90,000 名受访者中约 90 名使用 BSD/Unix，来源：Wayback Machine 2019 年历史快照 Python 提取，外部基准-StackOverflow-PackageEcosystem.md 第 1.2 节），2021 年为 **0.18%**（来源：Wayback Machine 2021 年历史快照 Python 提取，外部基准-StackOverflow-PackageEcosystem.md 第 1.2 节），其余年份（2016-2018、2020、2022-2023）BSD 选项存在但具体百分比未在 Wayback Machine 存档 HTML 中保留；BSD 使用率长期维持末位，与 Linux-based 选项的持续高位形成对照，反映 BSD 在全球开发者社区中的认知度与采用率远低于 Linux，间接印证 FreeBSD 文档生态对开发者吸引力不足——文档投入下滑（L5.2.1 比例从 25.70% 降至 5.87%）与开发者采用率低位（E-10 BSD 0.1%-0.18%）形成相互强化的负反馈循环

**史观**：总纲第 11 条——商品是形式主义（原“商业形态分化”挂第 7 条系伪名目，按商品论旨改挂）：Linux 与 BSD 文档生态差距；统计结论印证：E-10 揭示 BSD 在全球开发者调查中的使用率长期处于 0.1%-0.18% 末位，与 L5.1.1/L5.2.1 显示的 freebsd-doc commit 量下滑（2004 年 4,000 commit → 2024 年 854 commit）与 doc/src 比例下降（25.70% → 5.87%）相互印证——文档投入相对减少与开发者采用率低位构成负反馈循环，BSD 文档生态的萎缩与 BSD 在开发者社区中的边缘地位相互强化；Stack Overflow Survey 作为全球开发者社区的代表性调查，其 BSD 0.1%-0.18% 的占比为 “Linux 文档优势” 命题提供了量化基础，Linux 文档生态（LDP/Arch Wiki）的扩张与 Linux-based 选项在开发者调查中的高位形成正反馈循环

freebsd-doc 的对比须结合独立来源的 Linux 文档统计；考据过程留痕——【查证来源】**LDP（Linux Documentation Project）** 经 tldp.org 一手核验，其文档仓库托管于 GitHub `github.com/tLDP/LDP`（经 tldp.org 首页 “GIT repository” 链接一手核验），LDP 始于 1992 年（经 “Early history” 双向印证；【存疑判定依据】LDP 精确 commit 量与 Arch Wiki 精确文章数须独立查询后补入，当前仅标注仓库地址与启动时间；commit 量下降不必然等于文档质量下降——2004 年后 Handbook 内容趋于稳定，小修复 commit 占比上升是正常维护模式；2024 年 5.87% 的低比例须结合 freebsd-src 仓库 commit 量是否同时增长综合判断（如 freebsd-src 2024 年 commit 量较 2004 年大幅增长，则比例下降未必反映文档投入绝对减少）；dragonfly-docs 自 2023-01 后无更新，netbsd-htdocs 跳过（CVS 主仓），3 仓库对比的实际有效性有限；E-10 方法学局限：Stack Overflow Developer Survey 存在自选择偏差（受访者倾向活跃的 Stack Overflow 用户，对 BSD 资深系统管理员、BSD 邮件列表长期参与者、IRC/Matrix 社区成员等非 Stack Overflow 重度用户群体代表性不足，导致 BSD 实际使用率被低估）；样本规模不均（2016-2023 年调查规模在 56,000 至 100,000+ 之间波动，BSD 类操作系统受访者绝对数极少，2019 年约 90 名、2021 年约 144 名，统计方差大，单年百分比波动不具统计显著性）；Wayback Machine 存档不完整（2016-2018、2020、2022-2023 年的存档 HTML 未保留 BSD 具体百分比数值，仅 2019 与 2021 两年可精确提取）；macOS 单独统计（macOS 在所有调查年份中均单独统计，与 BSD 类操作系统分开，故 BSD 占比不包含 macOS——macOS 的 Darwin 内核虽源自 FreeBSD 但 Apple 不将其归入 BSD，这导致 BSD 在调查中的占比被低估，若将 macOS 计入 BSD 衍生系统，BSD 系占比将显著上升至 20%-30% 量级）；WSL 影响（2021 年起新增 WSL 作为独立选项，部分原 Linux/BSD 用户可能迁移至 WSL 选项）；Linux 合并选项（调查将所有 Linux 发行版合并为 “Linux-based” 单一选项，但 BSD 各发行版未合并，BSD 占比为合并后 BSD 类总占比——合并方式与 Linux 一致，故合并方式不影响 BSD 整体占比）；Stack Overflow Developer Survey 虽为开发者社区一手调查数据，但 BSD 占比 0.1%-0.18% 的具体数值仅反映 Stack Overflow 受访者中的相对位置，不等于全球开发者群体的 BSD 实际使用率，须与其他外部基准（GitHub Octoverse、PyPI/npm/crates.io 包生态、CVE 数据库）交叉验证；统计显著 ≠ 实际显著，BSD 使用率低不等于 BSD 技术价值低

## 292.9.2 商业出版商放弃 BSD 市场

**要点**：O'Reilly、Apress、Sybex 等商业出版商在 2000 年代后期逐步放弃 BSD 图书市场，转向 Linux 与开源通用题材，BSD 新书数量从 2000 年高峰下滑至 2010 年代每年不足 5 本。

**要点**：

- 新著 The Best of FreeBSD Basics（Reed Media 出版）汇编其自 2000 年起为 O'Reilly 撰写的 FreeBSD Basics 专栏：约 700 页原始内容逐篇在 FreeBSD 6.2 上重测、修正时过境迁之处与笔误后成书约 600 页；生产流程本身即为 BSD 工作流样本——Jeremy Reed 以脚本将全部 HTML 转换为 LaTeX，作者以 vi 编辑，并与 BSD Hacks 一样用 Subversion 维系作者与编辑的版本协同。（BSDTalk EP139，[53.68-151.61]，L1）
- 全书按主题分类重排：熟悉 FreeBSD、通用 UNIX 技巧、ports 与 packages 及 PBI 专章（因 PC-BSD 基于 FreeBSD、许多新手由 PC-BSD 入门）、文件系统、备份与 RAID、网络、服务配置、安全、防火墙与 VPN；内容在 6.2 上测试、估计约 98% 适用于 FreeBSD 7；4 至 6 的变迁之外大部分通用，且大量属基础 UNIX 知识，Linux 与 Mac OS X 用户稍作调整即可受益，原理不变。（BSDTalk EP139，[151.61-248.97]，L1）
- 销售渠道与上架困境：经出版商网站与 Amazon、Barnes & Noble 发售，但 BSD 书籍在实体书店长期稀缺；轶事为证——某次 BSD 大会期间 Dru 与 Greg Lehey（The Complete FreeBSD 作者）、Michael Lucas（Absolute BSD 作者）午餐后同赴加拿大 Chapters 书店比赛谁先找到彼此的书，结果三人的书均不在计算机区，仅 Lucas 的 Cisco Routers for the Desperate 被错放在与计算机无关的区域。（BSDTalk EP139，[248.97-351.17]，L1）
- 2008 年出版展望：风气开始转变——Michael Lucas 又有 BSD 新书面世，No Starch Press 年内将出 FreeBSD 服务器搭建书籍；希望有人为 BSD 认证编写兼顾原理与实验的课件，而 Dru 自身因担任考试科目专家回避写应试书籍以免利益冲突；另有一家欧洲期刊公司（旗下以 Hakin9 知名）将于 4 月出版完全 devoted to BSD 的专刊，首期作者已定，选题由 FreeBSD 扩展到全部 BSD 并期待桌面 BSD 素材，投稿可经 Dru 牵线。（BSDTalk EP139，[351.17-474.30]，L1）
- OSBR 进展：Dru 的正职为该刊编辑；定位非技术 how-to，而是可呈交经理或客户的开源议题材料；自 2007 年 7 月创办已出数期、正编 2 月刊；全刊在 FreeBSD 系统上以全开源工具制作、排版用 Scribus，她将于下周洛杉矶 SCALE 演讲该排版工具；圣诞假期已将站点迁移至不列颠哥伦比亚大学的开源项目 Open Journal Systems，获得作者评论、文章推荐与统计等工具；长期征集面向管理者与非技术受众的开源研究文章。（BSDTalk EP139，[479.73-628.17]，L1）
- 认证考试上线：BSD 认证考试正式 live，于周日在 BSD 认证邮件列表宣布；今年以会议现场纸笔形式提供（电子投递系统仍在开发）；已排定考场包括 SCALE（2 月 9 日两场）、布鲁塞尔 FOSDEM（2 月 23-24 日五场）、德国开姆尼茨 Linux-Tage（3 月 2 日）、芝加哥 Flourish、波兰克拉科夫 Confidence 安全会议与渥太华 BSDCan（5 月）、纽约 NYCBSDCon（10 月）与波兰 MeetBSD（预计华沙）；欢迎建议更多会场，将接洽组织方；Dru 负责北美考场，欧洲考场由多位身在欧洲的认证委员负责，南美会议季较晚、年内有望在巴西开考。（BSDTalk EP139，[634.05-783.64]，L1）
- Lucas 的最新著作 Absolute FreeBSD 是其处女作 Absolute BSD 的重写；书名与成书方式的分化源于 BSD 家族的趋异：2000 至 2001 年写 Absolute BSD 时各 BSD 相同点多于差异，熟悉其一即可操作其余，而此后各分支走出独特方向——NetBSD 直指可移植性并为嵌入式开发者提供便利，另一分支（转写作 3BSD，疑为 FreeBSD）深耕 SMP、内核锁与高性能——以致每个分支都值得单独成书，他希望最终为各 BSD 各著一本。（BSDTalk EP153，[114.84-214.22]，L1）
- 其写作理念是在纯信息（如源代码打印稿）与纯装饰之间取细线平衡：技术正确且有用之外还须可读；不只讲 how 更讲 why——为什么网络配置必须正确、为什么文件系统分区布局重要；他以 Red Hat 默认单一分区覆盖全盘为例，指出这种默认灵活但带风险，使用者应当理解风险所在。（BSDTalk EP153，[443.88-513.48]，L1）
- 出版生态的竞争压力：Absolute BSD 热卖后，其他出版社紧盯其出版商并抢先推出同题材书籍，Absolute OpenBSD 亦遭此遇；他批评赶工出版的书是废纸，坚持一年一书的节奏，且并非全职作者，搬家等变故即打乱写作日程。（BSDTalk EP153，[335.66-369.12]，L1）
- 应对时效与协作方法：Absolute OpenBSD 交稿数小时后 PF 宣布大批新特性，他恳求出版商宽限两三周补写章节；写作前先读邮件列表存档与 man 帕吉做足功课，开发者乐于受访，会直言某节应暂缓撰写并纠正错误；他举例就 Absolute FreeBSD 中 freebsd-update 一节向作者 Colin Percival 求证其在邮件列表中自贬早期源码为羞于示人之作的说法，获复已重写。（BSDTalk EP153，[529.68-703.54]，L1）

**史观**：

- 总纲10 动手者创造历史：文档作者以工程师方式写作：版本控制、脚本化格式转换、逐条在真实系统上重测——书籍生产本身是动手实践，创作者以工程流程对抗文字与系统状态的双重漂移。（BSDTalk EP139，[79.31-151.61]，L1）
- 总纲22 知识注定过时：技术写作的知识注定过时：700 页专栏须逐篇在 FreeBSD 6.2 重测并修正，98% 适用率之说是对过时速率的经验估计——技术书籍的存续依赖对旧知的持续修缮而非一劳永逸的权威文本。　[存疑脚注] 98% 适用率为当事人个人估计，无逐条验证清单佐证（BSDTalk EP139，[123.72-248.97]，L4）
- 总纲3 不存在进步，只有权力再分配：书店货架按主题分配注意力与销量，BSD 书籍的缺席与 Linux 的庞大货架构成可见性权力的不对称——三人寻书不遇的轶事表明，技术共同体的边缘处境部分由出版流通环节的分配机制制造。（BSDTalk EP139，[264.10-351.17]，L1）
- 总纲22 知识注定过时：Lucas 的叙述承认技术写作处于快速流变的特性环境中：交稿即出新特性，成书注定落后于代码；他的应对是与开发者对话预判演化方向、延后易朽章节、并把重心放在不易过时的 why 上——写作是对流变的把握而非对知识的冻结。（BSDTalk EP153，[529.68-582.66]，L1）
