**要点**：

- NCC 团队（Jesse Hertz 与 Tim Newson，自称 Project Triforce）对 OpenBSD 内核开展模糊测试，发现 mmap、kexec、线程 sleep、线程 signal divert、UFS getdents、mount 等多条可致内核崩溃的调用路径。　[订正：原 kevent，2026-09-30 SenseAudio 重转核对]（BSD Now EP151，[120.00-250.00]，L2）
- OpenBSD 决定废弃并在 6.0 后删除 `kern.user_mount`（FreeBSD 对应 `vfs.usermount`）sysctl，理由是 mount 系统调用把过多代码暴露给用户态，无法证明已修尽全部缺陷，宁可整体收缩攻击面。（BSD Now EP151，[510.00-720.00]，L2）
- Kristaps Dzonsons 发布以 C 语言实现的 Let's Encrypt 客户端 acme-client，把流程拆为六个隔离步骤，采用 privilege separation，仅依赖 LibreSSL，以此回应既有 Python、Bash 客户端的复杂性。（BSD Now EP151，[896.00-1180.00]，L2）
- Dru Lavigne 接受 BSD Magazine 采访，自述 20 世纪 90 年代中期通过搜索免费 UNIX 找到 freebsd.org，打印手册章节强迫自己在 FreeBSD 上完成全部工作，并认为 BSD 文化适合愿意深究系统运作的人。（BSD Now EP151，[2118.00-2278.00]，L1）
- Joseph Kong 自述为多伦多大学工业工程毕业生，无计算机科学专业背景、完全自学；兴趣路径从低层系统编程出发，经安全、漏洞利用开发与逆向工程自然延伸至 rootkit。其书稿源于约四十页个人笔记——为免遗忘而整理，且因网上资料过时、残缺而决定成书；出版提案首发 No Starch Press 即获创始人 Bill Pollock 次日回应，随后的技术审校由 FreeBSD 核心开发者 John Baldwin 担任，其指出代码缺陷与未处理的边界情况，迫使 Kong 重写大量代码乃至已完成的章节。写作原计划六个月，实际耗时一年，出版团队共五人参与审阅。　[存疑脚注] 出版人姓名转写作“Bill Paulak”，按 No Starch Press 史应为 Bill Pollock；其余编辑人名拼写均以转写存疑（BSDTalk EP113，[103.62-202.14, 257.06-319.58]，L1）
- 关于书籍定位，Kong 说明其目标读者是对低层系统编程与 FreeBSD 感兴趣者，意图展示“引擎盖之下的 FreeBSD”；与 McKusick 及 Neville-Neil 的《The Design and Implementation of the FreeBSD Operating System》相比，后者是高层概览而本书偏低层实用；他自述偏好 Stevens 式以大量实际示例教学的写作传统。对于伦理质疑，其界定很明确：加载 rootkit 的前提是已取得 root 权限，故全书不含漏洞利用内容，只讨论内核的修改与扩展——“rootkit 就是系统程序”，用途取决于使用者，并承认系统管理员亦会用 rootkit 隐蔽其监视行为。　[存疑脚注] 转写作“Kurt McCusick”，按史实应为 Marshall Kirk McKusick（BSDTalk EP113，[321.62-351.94, 351.94-434.82, 772.04-786.04]，L1）

- 文档定位哲学：文档应是程序的一部分而非事后补记——程序再好，用户不会用即等于不存在；FAQ 的功能是被反复指向的答案库；而重大特性常在发布最后关头才补入手册，bsdinstall 之于 FreeBSD 9.0、pkg-ng 文档之于其成为 FreeBSD 10 默认均为显例。（BSDTalk EP231，[541.32-557.61]，L1）
- Vinum 起源于真实故障而非规划：Lehey 在中国为 Tandem 讲学时接触 Veritas 卷管理器颇为赞赏；其后加州的 Nicole Harrington 因公司磁盘崩溃无法恢复而求助，其系统运行 FreeBSD 的 CCD 串联磁盘驱动，而 CCD 当时本就不善处理磁盘失败；Lehey 判断 FreeBSD 需要类似 Veritas 的卷管理器，以拉丁语双关命名为 vinum（意为酒）；恰逢 CyberNet 公司寻求 RAID5 实现并支付费用，成果于 1998 年底进入 FreeBSD 源码树。（BSDTalk EP55，[397.8-462.52]，L1）
- 至 2006 年访谈时，Vinum 已被多个 GEOM 类取代，但 Lehey 认为部分 GEOM 类仍未具备 Vinum 五年前已有的特性，希望社区将其吸收进传统 GEOM 类，显示替代并非完整的功能接续。（BSDTalk EP55，[462.52-483.24]，L1）
- SMPNG 的直接诱因是 1999 年 Mindcraft 基准：微软展示 Windows 在部分网络场景胜过 Linux，BSD 方面自知成绩亦不会好看而选择沉默；约一年后社区聚议，认定真正问题在于 Linux 与 BSD 处理多处理器的方式，遂于 2000 年 6 月在 Yahoo 园区开会确立 SMPNG（新一代 SMP 支持）；Lehey 从头参与并先做了约六个月中断处理程序，其后主要由 John Baldwin 接手；项目启动时预计约两年，最终五年后才正式宣告结束。　[考据脚注] 转写将 Mindcraft 误作 Minecraft、将 SMPNG 会址写作 Yahoo complex，本条按通行名称重写，细节以当期录音与 SMPNG 设计文档复核为准。（BSDTalk EP55，[558.88-625.44]，L1）
- Lehey 的职业生涯呈连续跨界：1982 年起在 Tandem 十年，从专有操作系统转到 UNIX；1992 年认定大公司不知去向而转做顾问，由此获得写书时间；1999 年底经 Dan Shearer 召集加入 LinuxCare 澳洲分部任“BSD 专员”，但公司不知如何使用 BSD，他自述大半年未做实际工作；.com 泡沫破灭后澳洲分部关闭，多数同事转往 IBM 从事 Linux，他因居家办公方式不合 IBM 文化而离开，此后在阿德莱德一家存储系统公司任职（因保密协议不能详述），约 2005 年转投 MySQL。（BSDTalk EP55，[78.96-660.16]，L1）
- 在 MySQL 任在线备份方向高级软件工程师，重点工作之一是确保 MySQL 在 FreeBSD 上良好运行，同时也是 NetBSD 开发者；其自述旨趣是防止 BSD 碎片化、推广所有 BSD 项目，认为 2006 年碎片化正在改善——跨项目沟通增多、个人恩怨减少；其经手的大型 FreeBSD 安装上存在仅在线上复现的竞态类崩溃（MySQL bug 12187，追踪逾半年、无法在测试环境重现），公开向听众征集相似案例。（BSDTalk EP55，[683.4-876.16]，L1）
- 著述经历：O‘Reilly 的 Porting UNIX Software 于 1995 年底出版（Tim O’Reilly 曾断言此类书只有两年好卖）；The Complete FreeBSD 起于与 Jack Velte 等 FreeBSD 人士在德国书展的会面，原约化为 50 页安装手册、成书 200 页，历经五版并相当成功；因无暇更新，他选择将全书放入公有领域而非任其消亡，并希望组建团队维护。（BSDTalk EP55，[222.32-331.0]，L1）

**辨析**：

- 删除 user_mount 与 ZFS 权限委托（zfs allow）的既有用法存在冲突：主持人指出自己在 FreeBSD 上依赖该机制实现非 root 的复制与挂载，删除后改用 sudo 或 doas 并未完全消除攻击面，只是把风险转移到受控的命令执行。（BSD Now EP151，[629.00-861.00]，L2）
- Kong 对 rootkit 检测给出结构性悲观判断：书末虽对自己提出的每种隐藏算法附两种检测算法，但这些检测本质上是签名式与被动的，如同杀毒软件——攻击手法公开后才有人写出对应检测；要真正可靠地检测 rootkit 需要百分之百可验证的操作系统，而现行操作系统的设计方式不具备此性质；使用自研钩子与补丁的 rootkit 无法被检测，可检测的只有公开流通的已知 rootkit。他并观察到 Unix 侧 rootkit 检测工具远落后于 Windows，归因于 Windows 用户基数大、研究者多；FreeBSD 方向的相关研究关注度尤其低，社区存在“ FreeBSD 天然安全”的错觉。此为其个人专业判断，其中工具落后论属行业观察而非系统测量结论。　[存疑脚注] “Unix rootkit 检测工具落后于 Windows”为当事人经验性判断，未提供系统比较依据（BSDTalk EP113，[543.58-629.54, 629.54-721.08]，L1）
