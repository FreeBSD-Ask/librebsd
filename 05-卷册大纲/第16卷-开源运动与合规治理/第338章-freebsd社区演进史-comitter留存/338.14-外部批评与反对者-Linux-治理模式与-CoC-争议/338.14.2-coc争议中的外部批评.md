# 338.14.2 CoC 争议中的外部批评

  **要点**：2018 年 Linux 采纳 CoC 后，部分 Linux 社区成员批评 FreeBSD CoC 执行不力或过度
  **史料**：CoC 争议记录、freebsd-hackers 讨论、外部评论 ［A］
  **史观**：总纲第 22 条——CoC 争议中的社区立场
  **辨析**：考据过程留痕——【查证来源】FreeBSD CoC 官方页面经 <https://www.freebsd.org/internal/code-of-conduct/> 一手核验，发布日期 2020-06-09，最后修改 2023-06-22 由 Sergio Carlavilla Delgado 提交（cgit.freebsd.org/doc/commit/?id = 9e3690e5b6）；CoC 文本明确说明"based on the LLVM Project's draft CoC, which in turn is based on the Django Project Code of Conduct, which is in turn based on wording from the Speak Up! project"；外部批评散见于 freebsd-hackers 邮件列表 2020 年 CoC 争论串、Reddit r/freebsd 讨论等；【交叉验证方法】以 CoC 官方文本与 freebsd-hackers 2020 年 CoC 争论串交叉验证“执行不力”与“过度执行”两端批评的具体所指——“执行不力”批评指向 Code of Conduct Committee 处理记录的公开程度有限，“过度执行”批评指向 CoC 对社区言论自由氛围的限制；两端批评的具体案例须以 Core Team 公告与 commit log 交叉验证；【存疑判定依据】Code of Conduct Committee 的系统性公开报告在本次考据中未直接找到，CoC 的实际执行效果须以委员会公开报告为准核验，不得仅凭文本借鉴判定 CoC 的合理性；“CoC 引发派系分化”论证须对照 CoC 引入前后的社区活跃度数据，若社区活跃度未显著下降则“派系分化”可能是少数老派开发者的不满而非社区整体现象
  **文献**：CoC 争议 Archive；freebsd-hackers CoC threads ［A］
