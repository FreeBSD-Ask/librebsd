## 311.14.2 法律框架演变对 BSD 科学部署的效应

  **要点**：BSD 科学部署的法律约束经历了从早期以许可证合同与行业自律为主，到欧盟 1995 年《数据保护指令》（95/46/EC）确立数据保护立法框架，再到 2016/679 GDPR（2018 年 5 月 25 日起适用）、CLOUD Act（2018-03-23）与中国《个人信息保护法》（2021-11-01 施行）相继生效后进入强监管时期的演变；法律框架的每次收紧都使 BSD 的“许可证自由”与“数据监管义务”的双层结构更加显著
  **史料**：Directive 95/46/EC（EUR-Lex 31995L0046，已由 2016/679 废止取代）；Regulation (EU) 2016/679（EUR-Lex 32016R0679）；CLOUD Act（Pub. L. 115-141, Division V）［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕
  **史观**：总纲第 13 条——法律与道德是利益分配：法律框架的演变反映 BSD 科学部署所处法律环境中的利益再分配——数据主体权利、国家安全诉求与数据流动自由之间的再平衡

## 311.14.3 BSD 与 Linux 科学合规比较

  **要点**：BSD 与 Linux 科学合规的差异：BSD 许可证（BSD-2/3-Clause）仅要求保留版权与免责声明，合规重心在归属声明保留与免责条款传递；Linux 内核 GPLv2 要求衍生作品按 GPLv2 分发，合规重心还包括 copyleft 义务履行与源码提供。企业支持模式上，Linux 生态以厂商认证与合规服务体系为主，BSD 生态以基金会、社区文档与邮件列表协作为主
  **史料**：BSD-2-Clause 与 BSD-3-Clause 文本（Open Source Initiative <https://opensource.org/licenses/BSD-2-Clause>、<https://opensource.org/licenses/BSD-3-Clause>）；GNU GPLv2 文本（<https://www.gnu.org/licenses/old-licenses/gpl-2.0.html>）；Regulation (EU) 2016/679（EUR-Lex 32016R0679）［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕
  **史观**：总纲第 4 条——分离聚合是永恒规律：BSD 与 Linux 合规机制的分化与并行，是分离聚合规律在治理层面的体现
  **辨析**：“BSD 合规更侧重许可证合规”须通过具体案例验证；“Linux 合规更侧重企业合规支持”须通过厂商支持档案核查
  **文献**：BSD-2-Clause/BSD-3-Clause 文本（OSI）；GNU GPLv2 文本（gnu.org）；Regulation (EU) 2016/679（EUR-Lex 32016R0679）［考据注：2026-07-28 联网考据留痕，模板句式已按 0 信任原则精简（WO-004）；语义以正文与所引来源为准］
