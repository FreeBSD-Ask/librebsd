#### 300.4《大教堂与集市》——Raymond 1997 年的核心论点

- 300.4.1 Raymond 1997 年《大教堂与集市》的核心论点
  - 要点：Eric S. Raymond 于 1997 年 5 月在 Linux Kongress 发表《大教堂与集市》（CatB），1999 年扩展为书籍；核心论点：(1) 大教堂模式（封闭开发，发布周期长，如 GNU Emacs、BSD）；(2) 集市模式（开放开发，频繁发布，如 Linux）；(3) “Linus 定律”——足够多的眼球让所有 bug 无所遁形；(4) 集市模式优于大教堂模式

- 300.4.2 Raymond 对 BSD 开发模式的分析
  - 要点：Raymond 在 CatB 中将 BSD 描述为 “大教堂模式”——核心团队封闭开发，发布周期长（CSRG 时代 2-3 年）；Raymond 认为 BSD 模式在互联网时代落后于 Linux 集市模式；BSD 社区反驳认为 BSD 是 “精英评审” 模式而非 “大教堂”
  - 史料：CatB 文本、BSD 邮件反驳［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

- 300.4.3 Linus 定律与 BSD 精英评审模式的对比
  - 要点：Linus 定律（“足够多的眼球让所有 bug 无所遁形”）强调参与者数量；BSD 精英评审模式（committer 审核机制）强调参与者质量；Linux 模式快速但代码质量参差，BSD 模式稳健但贡献门槛高；两种模式各有优劣，BSD 社区认为精英评审更适合生产级系统
  - 史料：CatB、BSD committer 文档、邮件 [A]；freebsd.duckdb 查询 L7.3.1 显示：BSD 四大 src 仓库（freebsd-src/openbsd-src/netbsd-src/dragonfly-src）与 linux-kernel 仓库 commit 量与贡献者对比——1996 年 BSD = 29,245 commit/177 贡献者（Linux = 1，Linux 当时刚起步）；2000 年 BSD = 76,507/533（Linux commit 量缺失或极低）；2005 年 BSD = 60,533/658，Linux = 16,697/1,464，linux_to_bsd_ratio = 0.28（Linux commit 量首次达到 BSD 的 28%）；2008 年 BSD = 48,242/690，Linux = 48,825/2,746，ratio = 1.01（Linux commit 量首次追平 BSD）；2010 年 BSD = 45,586/643，Linux = 49,814/3,115，ratio = 1.09（Linux commit 量超越 BSD）；数据反映 2005-2010 年间 Linux commit 量从 BSD 的 28% 增长至 109%，但 BSD 贡献者人数（643-690）远低于 Linux（2,746-3,115），印证 “BSD 精英评审模式贡献者少但参与门槛高、Linux 集市模式贡献者多但参与门槛低” 的叙事；freebsd.duckdb 查询 L3.1.1.GPL 存疑标注：深层信息挖掘报告中 L3.1.1 系列查询仅覆盖 MFC/Fix/Add/Refactor/Document/Linux/Import/Update 八个关键词，无 GPL 专项关键词查询，GPL 关键词 commit 演化数据须直接查询 freebsd.duckdb 获取（建议查询条件：`message_subject LIKE '%GPL%' OR message_body LIKE '%GPL%'`，repos = ['freebsd-src']，年份 1996-2010）[A]
