# 307.16 非 committer 贡献者挫折

104.16 **非 committer 贡献者挫折**———FreeBSD 使用 Bugzilla PR 系统接收外部补丁，非 committer 需通过 PR 提交补丁由 committer 审查后提交，但 FreeBSD 没有类似 LKML 那样的公开高流量补丁讨论论坛，内部讨论在需要 committer 权限的邮件列表上进行

## 307.16.1 非 committer 补丁提交流程

  **要点**：非 committer 通过 Bugzilla PR 提交补丁，由 committer 审查后合并，无类似 LKML 的高流量公开补丁讨论论坛，内部讨论在需要 committer 权限的邮件列表上进行
  **史料**：FreeBSD Bugzilla PR 系统存档、freebsd-hackers 邮件列表存档 ［A］
  **史观**：总纲第 10 条——边缘者（非 committer）贡献路径塑造项目
  **辨析**：Bugzilla PR 是否能完整反映外部贡献需评估；与 LKML 模式的可对比性需考据
  **文献**：FreeBSD Bugzilla PR Archive；freebsd-hackers 邮件列表 ［A］

## 307.16.2 补丁审查迟缓与贡献者流失

  **要点**：补丁审查迟缓导致贡献者流失，部分 PR 数月甚至数年无人响应，影响社区活力
  **史料**：Bugzilla PR 历史数据、贡献者流失案例、freebsd-hackers 关于审查迟缓的讨论 ［A］

## 307.16.3 FreeBSD 与 Linux 补丁流程辨析

  **要点**：FreeBSD 走 Bugzilla PR 路径，Linux 走 LKML 公开讨论路径，两种模式各有利弊，FreeBSD 内部讨论在需 committer 权限的邮件列表上进行

**要点**：

- Mitchell Horne 的实习总结描述新手常见误区：误以为 FreeBSD 由少数 rockstar committer 包办一切，实则数百名低频贡献者提交的错误报告、补丁与反馈同样重要；他反思自己不应与资深 committer 对比而贬低自身工作，强调从小处着手并在学习新事物的过程中获得满足。（BSD Now EP247，[53.00-765.02]，L1）
- Mitchell 指出 FreeBSD 的审查与推进机制对新人存在门槛：提交的工作须经至少两人审查，但要找到人查看自己的补丁需要自我倡导与主动催促，文档与手册页对新手价值巨大。（BSD Now EP247，[372.36-532.24]，L1）
- FreeBSD 在 AMD64、ARM64、i386、PowerPC、SPARC64 上默认启用内核崩溃转储的加密、压缩与网络转储支持，网络转储代码起源久远；节目同时报道 Intel 微码拆分工具与 Speculative Store Bypass 的 hw.spec_store_bypass_disable 控制。（BSD Now EP247，[770.36-1151.44]，L1）
- 节目解释 FreeBSD 治理为选举制：每两年由过去一年内提交过代码的 committer 从候选人中选出 9 人 Core 团队，形成共识式民主而非仁慈独裁；2018 年选举有 16 名候选人，投票于 6 月 20 日截止。（BSD Now EP247，[1283.72-1474.54]，L1）

- 一手史料：Mitchell Horne 在 FreeBSD 基金会博客的实习总结；FreeBSD 崩溃转储与 SSB 缓解相关提交；FreeBSD Core 团队选举公告与候选人名单。（BSD Now EP247，[53.00-1474.54]，L2）
