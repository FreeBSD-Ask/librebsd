# 306.11 Core Team 决策低效

104.11 **Core Team 决策低效**———Benno Rice（本诺·赖斯） 承认“FreeBSD 直到 2008 年还在使用 CVS。为什么呢？因为大家对于应该用什么来代替它没有达成共识。考虑过 BitKeeper、Git 和 Mercurial，最后都无疾而终了”

  **要点**：FreeBSD Core Team 共识模式导致多个决策迟缓，典型案例是 2008 年前 CVS 迁移讨论多年无果，最终选择 SVN

## 305.11.2 CVS 到 SVN 到 Git 迁移迟缓

  **要点**：FreeBSD 1993-2008 年使用 CVS，2008-2020 年使用 SVN，2020 年迁移至 Git，相比 Linux（2002 即采用 BitKeeper 后转 Git）迟缓约 8-15 年
  **史料**：FreeBSD 2008 SVN 迁移公告、2020 Git 迁移 freebsd-hackers 讨论、Linux BitKeeper 2002-2005 历史 ［A］
  **史观**：总纲第 19 条——信息技术工具采用速度受治理模式影响
  **辨析**：FreeBSD 2008 年为何选 SVN 而非 Git 需查讨论；2020 年迁移是否因外部压力（如 GitHub 流行）需考据
  **文献**：FreeBSD SVN Migration Announcement 2008；FreeBSD Git Migration 2020 Documentation ［A］

## 305.11.3 共识模式与独裁模式效率辨析

  **要点**：Linux 独裁模式下 Linus 可直接决定采用 Git（2005），FreeBSD 共识模式需多年讨论才迁移至 SVN（2008）与 Git（2020），效率差距明显
  **史料**：Torvalds 2005 Git 引入声明、Benno Rice 2018 演讲 ［A］
  **史观**：总纲第 23 条——社区治理效率比较
  **辨析**：Linux 独裁的“效率优势”是否伴随“风险”（如 Linus 休假时决策停滞）需分析；FreeBSD 共识的“稳健性”是否实质优于独裁需考据
  **文献**：Torvalds 2005 Git announcement；Rice 2018 AsiaBSDCon talk ［A］
