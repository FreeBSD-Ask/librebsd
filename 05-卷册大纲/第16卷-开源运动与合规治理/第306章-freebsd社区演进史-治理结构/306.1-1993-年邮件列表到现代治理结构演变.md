## 306.1.2 治理结构演变历程

  **要点**：FreeBSD 治理结构从 1993 年创始人小组到 2000 年首次 Core Team 直选，再到 2000 年 Foundation 成立形成“Core Team 共识 + Foundation 商业托管”双轨治理

| 时间 | 治理事件 | 关键节点 |
| -- | ------ | ------ |
| 1993 | FreeBSD 项目创始人小组成立 | 早期 Core Team 自选/共识推举 |
| 2000 | 首次 Core Team 直选 | 所有 active committer 投票选出 9 人 Core Team |
| 2000-03-19 | FreeBSD Foundation 成立 | “Core Team 共识 + Foundation 商业托管”双轨治理成型 |

| 年份 | 23 仓库合计新增贡献者数（汇总口径注见下） | 活跃贡献者数（≥10 commit/年） |
| -- | --------------------- | --------------------------- |
| 1993 | 72 | 57 |
| 2000 | 181 | 552 |
| 2005 | 1,563（首次破千） | 1,011（首次破千） |
| 2014 | 2,130（首次破 2 千） | - |
| 2015 | - | 1,927 |
| 2017 | 2,215 | - |
| 2021 | - | 2,094 |

**史料**：FreeBSD Core Team 2000 年选举公告、FreeBSD Foundation Articles of Incorporation 2000-03-19、freebsd-hackers 邮件列表 1993-2000 年治理讨论 ［A］；跨项目 23 仓库汇总统计（原记 freebsd.duckdb 查询 L1.2.1〔存疑：该库 commits 表实测仅 freebsd-src/freebsd-ports/freebsd-doc 3 个 repo_name，23 仓库口径与汇总来源待核〕）显示：FreeBSD 23 仓库合计每年新增贡献者数从 1993 年 72 人增至 2000 年 181 人，2005 年首次突破千人（1,563 人），2014 年突破 2 千人（2,130 人），2017 年达 2,215 人；freebsd.duckdb 查询 L1.2.2 显示：每年活跃贡献者数（≥10 commit/年）从 1993 年 57 人增至 2000 年 552 人，2005 年突破千人（1,011 人），2015 年达 1,927 人，2021 年达 2,094 人，反映社区核心团队规模持续扩张
**史观**：总纲第 15 条——文化即形式主义：治理形式主义化的渐进过程；统计结论印证：统计结论 [C-24] FreeBSD freebsd-src 仓库贡献者 Gini 系数 0.9188（Bootstrap 95% CI [0.9093, 0.9270]）、统计结论 [C-25] DragonFly BSD dragonfly-src Gini 0.8972（[0.8517, 0.9187]）、统计结论 [C-26] OpenBSD openbsd-src Gini 0.8244（[0.7857, 0.8538]）、统计结论 [C-27] NetBSD netbsd-src Gini 0.8158（[0.7922, 0.8365]）共同反映 BSD 4 项目贡献集中度均处于高度不均区间（Gini > 0.8），FreeBSD 作为 4 项目中 Gini 最高者印证其社区贡献集中于少数核心开发者，与 140.1.2 节所述 “Core Team + committer” 双轨治理形式主义化进程在数据层面互证——社区规模扩张（L1.2.1/L1.2.2 新增与活跃贡献者数持续增长）但贡献集中度未明显下降，反映治理形式主义化与贡献集中度脱钩的张力；netbsd.duckdb 实测仅含 netbsd-src/netbsd-pkgsrc，四项目对比须由各库分别查询后汇总；freebsd/netbsd/openbsd/dragonfly 四库 L3.4.1.top10 查询合并显示 4 大 BSD src 仓库前 10 贡献者占总 commit 比例演化（1993-2026）作为旁证

- Intel FPU 推测执行漏洞被确认：OpenBSD 的 Philip Guenther 于 7 月 5 日提交从惰性切换到主动切换的变更，Colin Percival 根据 Theo de Raadt 演讲披露的信息约五小时写出概念验证并通知 Intel，促使 Intel 提前公布；FreeBSD 2015 年 3 月的邮件列表曾有人建议为性能做同样变更。（BSD Now EP251，[3176.16-3380.00]，L1）

- TrueOS 宣布把重点转向核心操作系统，Project Trident 接管图形化 FreeBSD 桌面开发；Ken Moore（Lumina 开发者）、JT 等桌面团队成员转入 Trident，TrueOS 核心由 iXsystems 付费开发者继续维护，并以 JSON 清单系统方便他人基于 TrueOS 构建发行版。（BSD Now EP250，[88.90-271.86]，L1）

**史观**：

- 总纲5 没有必然性，只有偶然性：FreeBSD 早在 2015 年就有改为主动 FPU 切换的建议，因担心引入难以诊断的缺陷而未实施，最终由漏洞披露这一外部偶然事件促成变更。（BSD Now EP251，[3287.60-3368.70]，L1）
- 总纲15 文化即形式主义：awk、grep、rc、GECOS 等命令名是历史语境在工具命名上的沉积，命名本身成为 Unix 文化的形式化载体。（BSD Now EP251，[3944.18-4195.44]，L2）
- 总纲4 分离聚合是永恒规律：TrueOS 与 Project Trident 的拆分把商业核心与社区桌面分离为两个实体，呈现组织随功能需要而分离聚合的规律。（BSD Now EP250，[193.26-271.86]，L1）
- 总纲13 法律与道德是利益分配：LLD 替代 GNU ld 成为默认链接器，其驱动力之一是许可证纯洁化与工具链自主，体现法律许可作为利益分配机制对工程选型的塑造。（BSD Now EP250，[4653.80-4658.16]，L1）
- 总纲6 和解优于斗争：Hubbard 提出社区管理至少与技术管理同等重要、有时更为优先的论断——“社区管理这一环更重要，否则项目没有未来；代码是不会有的，剩下的只是弃置软件”（6902.92-6948.02）；他以乐队因无法就艺术方向达成一致而解散作比，指出开源项目同样会在人际失谐中分裂或停滞（6964.42-7010.14）。这一判断把项目存续的因果链从代码生产逆转到共同体的维系，与其强调友善招募、团队对话优先于路线争吵的立场一以贯之。（BSD Now EP113，[6902.92-6948.02]，L1）
