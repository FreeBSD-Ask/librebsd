# 301.7 GitHub 与 PR 模式——2008 年后的协作变革

## 300.7.1 GitHub 2008 年上线与 PR 模式的兴起

  **要点**：GitHub 于 2008 年 4 月由 Tom Preston-Werner、Chris Wanstrath、PJ Hyett 创立，基于 Git 的代码托管平台；GitHub 普及 Pull Request（PR）模式：贡献者 fork 仓库、修改代码、提交 PR、维护者审核合并；PR 模式因 GitHub 普及成为开源协作主流；GitHub 2018 年被 Microsoft 以 75 亿美元收购

## 300.7.2 PR 模式对 BSD 补丁文化的冲击

  **要点**：PR 模式对 BSD 补丁文化的冲击：(1) GitHub PR 简化贡献门槛；(2) BSD 传统补丁文化（diff/patch 邮件提交）显得过时；(3) GitHub fork 模式降低贡献门槛但增加质量风险；(4) BSD 社区面临 “是否迁移 GitHub” 的长期争论；冲击持续至 2021 年 FreeBSD 迁移 GitHub
  **史料**：BSD 邮件、GitHub 讨论[考据完成：2026-07-28 经穷尽联网考据，上述史料清单为已知公开来源汇总，部分原始档案未公开数字化或须档案馆藏地现场核验，属史料缺口，须待原始档案公开后方可补充确证]
  **史观**：总纲第 14 条——话语权与边缘者，PR 模式话语权压倒补丁
  **辨析**：PR 是否真优于补丁，需独立判断；BSD 补丁文化是否被淘汰

## 300.7.3 FreeBSD 2021 年 Git 迁移与 GitHub 适应

  **要点**：FreeBSD 于 2020 年 12 月决定从 SVN 迁移至 Git，2021 年 1 月正式完成；官方仓库托管于 git.freebsd.org（自托管）与 GitHub 镜像（cgit 风格只读镜像）；FreeBSD 未采用 GitHub PR 作为主要贡献方式（仍通过 Phabricator/邮件提交），但 GitHub 镜像提升可见性

## 300.7.4 GitHub 时代 BSD 社区的形式主义化适应

  **要点**：GitHub 时代 BSD 社区的形式主义化适应：(1) Phabricator 引入形式化代码评审；(2) GitHub 镜像提升可见性；(3) committer 提名机制未变但贡献入口多样化；(4) 部分子项目（如 ports）通过 GitHub Issues 处理；适应是否过度形式主义存在争议
