# 301.7 GitHub 与 PR 模式——2008 年后的协作变革

## 301.7.1 GitHub 2008 年上线与 PR 模式的兴起

  **要点**：GitHub 于 2008 年 4 月由 Tom Preston-Werner、Chris Wanstrath、PJ Hyett 创立，基于 Git 的代码托管平台；GitHub 普及 Pull Request（PR）模式：贡献者 fork 仓库、修改代码、提交 PR、维护者审核合并；PR 模式因 GitHub 普及成为开源协作主流；GitHub 2018 年被 Microsoft 以 75 亿美元收购
  **史料**：GitHub 2008 上线公告、Microsoft 2018 收购公告［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕
  **史观**：总纲第 1 条——偶然性改写历史，GitHub 普及改变开源协作
  **辨析**：PR 模式是否真优于补丁，需独立判断；Microsoft 收购是否影响开源
  **文献**：GitHub 官方历史［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 301.7.2 PR 模式对 BSD 补丁文化的冲击

  **要点**：PR 模式对 BSD 补丁文化的冲击：(1) GitHub PR 简化贡献门槛；(2) BSD 传统补丁文化（diff/patch 邮件提交）显得过时；(3) GitHub fork 模式降低贡献门槛但增加质量风险；(4) BSD 社区面临 “是否迁移 GitHub” 的长期争论；冲击持续至 2021 年 FreeBSD 迁移 GitHub
  **史料**：BSD 邮件、GitHub 讨论［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
  **史观**：总纲第 14 条——话语权与边缘者，PR 模式话语权压倒补丁
  **辨析**：PR 是否真优于补丁，需独立判断；BSD 补丁文化是否被淘汰
  **文献**：freebsd-hackers mailing list archives；FreeBSD Quarterly Status Reports；The FreeBSD Foundation Annual Reports ［A］

## 301.7.3 FreeBSD 2021 年 Git 迁移与 GitHub 适应

  **要点**：FreeBSD 于 2020 年 12 月决定从 SVN 迁移至 Git，2021 年 1 月正式完成；官方仓库托管于 git.freebsd.org（自托管）与 GitHub 镜像（cgit 风格只读镜像）；FreeBSD 未采用 GitHub PR 作为主要贡献方式（仍通过 Phabricator/邮件提交），但 GitHub 镜像提升可见性
  **史料**：FreeBSD 2020.12 Git 迁移公告、GitHub 镜像说明；freebsd.duckdb freebsd-doc 仓库 2021-03 至 2021-06 间 GitHub 主题 commit 共 10 余条，反映 doc 仓库的 Git 迁移文档更新集中在 2021 年 3 月至 6 月：

## 301.7.4 GitHub 时代 BSD 社区的形式主义化适应

  **要点**：GitHub 时代 BSD 社区的形式主义化适应：(1) Phabricator 引入形式化代码评审；(2) GitHub 镜像提升可见性；(3) committer 提名机制未变但贡献入口多样化；(4) 部分子项目（如 ports）通过 GitHub Issues 处理；适应是否过度形式主义存在争议
  **史料**：Phabricator 文档、邮件［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
  **史观**：总纲第 6 条——形式主义膨胀与抽象克制
  **辨析**：适应是否合理，需独立判断
  **文献**：freebsd-hackers mailing list archives；FreeBSD Quarterly Status Reports；The FreeBSD Foundation Annual Reports ［A］
