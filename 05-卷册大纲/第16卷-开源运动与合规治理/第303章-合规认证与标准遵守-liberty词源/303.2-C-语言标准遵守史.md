# 303.2 C 语言标准遵守史

303.2 **C 语言标准遵守史**——ANSI C 于 1989 年由 ANSI X3J11 委员会完成（ANSI X3.159-1989，简称 C89），1990 年 ISO 采纳为国际标准 ISO/IEC 9899:1990（C90），1999 年 ISO/IEC 9899:1999（C99）发布新增 `//` 行注释、`long long`、变长数组、`stdbool.h`、`stdint.h`、复数类型、指定初始化器、复合字面量、`__func__` 预定义标识符等特性，2011 年 ISO/IEC 9899:2011（C11）发布新增 `_Static_assert`、`_Generic`、`_Alignas`/`_Alignof`、原子操作 `<stdatomic.h>`、线程支持 `<threads.h>`、`char16_t`/`char32_t` 等，2018 年 ISO/IEC 9899:2018（C17，亦称 C18）发布作为 C11 的技术勘误版无新增语言特性，2024 年 ISO/IEC 9899:2024（C23）发布新增 `#embed` 指令、`typeof` 关键字、`constexpr`、`bool`/`true`/`false` 关键字化、二进制字面量 `0b`、`nullptr`、属性 `[[...]]` 系统化等

## 303.2.1 ISO C 标准演进与编译器跟踪

**要点**：C 标准从 C89/C90 演进至 C23，FreeBSD 内核与基本系统跟踪 ISO C 标准更新，2014 年起 FreeBSD 10.0 默认以 C99 编译，2024 年 FreeBSD 15.0 起以 C23 为目标

| C 标准版本 | ISO 编号 | 发布时间 | 状态 | 关键特性 |
| -------- | ------ | ------ | -- | ------ |
| C89/C90 | ANSI X3.159-1989 / ISO/IEC 9899:1990 | 1989/1990 | - | ANSI C 首版 |
| C99 | ISO/IEC 9899:1999 | 1999 | Withdrawn | `//` 行注释、`long long`、变长数组、`stdbool.h`、`stdint.h`、复数类型、指定初始化器、复合字面量、`__func__` 预定义标识符 |
| C11 | ISO/IEC 9899:2011 | 2011-12 | Withdrawn 2018-07-05 | `_Static_assert`、`_Generic`、`_Alignas`/`_Alignof`、原子操作 `<stdatomic.h>`、线程支持 `<threads.h>`、`char16_t`/`char32_t` |
| C17/C18 | ISO/IEC 9899:2018 | 2018-06 | Withdrawn 2024-10-31 | C11 的技术勘误版，无新增语言特性 |
| C23 | ISO/IEC 9899:2024 | 2024-10 | Published | `#embed` 指令、`typeof` 关键字、`constexpr`、`bool`/`true`/`false` 关键字化、二进制字面量 `0b`、`nullptr`、属性 `[[...]]` 系统化 |

| FreeBSD 版本 | 默认 C 标准 | 切换时间 |
| ---------- | --------- | ------ |
| 10.0 | C99 | 2014 年起 |
| 15.0 | C23（目标） | 2024 年起 |

## 303.2.2 内核 KNF 风格与 C 标准张力

**要点**：FreeBSD 内核沿用 CSRG/4.4BSD 的 KNF（Kernel Normal Form）风格，对 C 标准新特性（如 C99 变长数组、C11 _Generic）的采纳保守，常滞后于用户空间
**史料**：FreeBSD src/share/misc/style 文件、freebsd-hackers 邮件列表关于 KNF 与 C 标准的讨论、style(9) 手册页 ［A］
**史观**：总纲第 25 条——延续与终结，KNF 风格是 BSD 传统的延续，对 C 新特性的保守是形式上的克制
**辨析**：内核中是否完全禁用变长数组存在争议，2017 年后部分驱动引入 VLA 但 2020 年又移除；**style(9)** 的具体条款版本演变需追溯

## 303.2.3 BSD libc 与 glibc 接口比较

**要点**：FreeBSD libc 与 GNU glibc 在接口集、国际化、DNS 解析实现（resolv vs glibc resolver）等方面存在差异，跨平台移植需注意 strlcpy/strlcat 等 BSD 原生函数在 glibc 中曾长期缺位

| 维度 | FreeBSD libc | GNU glibc |
| -- | ---------- | ------- |
| 接口集 | BSD 原生函数（strlcpy/strlcat 等） | 长期缺位 strlcpy/strlcat，2012-2018 年长期争论，最终 2023 年 glibc 2.38 加入 strlcpy（glibc 2.38 于 2023-07-31 发布）[存疑脚注] |
| 国际化 | 自有实现 | GNU gettext 体系 |
| DNS 解析实现 | resolv | glibc resolver |
| 跨平台移植 | 需注意 BSD 原生函数移植 | 需注意 glibc 特有扩展 |

**史料**：FreeBSD libc 源码、glibc 源码、Todd C. Miller（托德·C·米勒）与 Theo de Raadt 的 strlcpy/strlcat 论文（USENIX 1999 FREENIX；原记“1996 年论文”系年份误记，2026-09-12 校正）、glibc 2.38 加入 strlcpy 公告 ［A］
