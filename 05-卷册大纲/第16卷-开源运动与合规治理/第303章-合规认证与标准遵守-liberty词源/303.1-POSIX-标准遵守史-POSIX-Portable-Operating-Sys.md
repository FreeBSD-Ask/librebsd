# 303.1 POSIX 标准遵守史——POSIX（Portable Operating System Interface，可移植操作系统接口）由 IEEE 与 The Open Group 联合制定，1988 年 IEEE 批准首个核心标准 IEEE Std 1003.1-1988，1990 年该版本被采纳为国际标准 ISO/IEC 9945-1:1990，POSIX 名称由 Richard Stallman 建议取"Portable Operating System Interface"之首字母缩写并加"X"以类 Unix 风格收尾；1993 年 POSIX.1b 实时扩展（IEEE 1003.1b，进程调度、内存锁、实时信号、信号量、共享内存、消息队列、时钟与定时器、异步 I/O）批准，1995 年 POSIX.1c 线程扩展（IEEE 1003.1c，即 pthreads）批准，1999 年 POSIX.1d 批准，2000 年 POSIX.1j 高级实时扩展发布；2001 年 IEEE 1003.1-2001 发布（即 Single UNIX Specification v3 的核心），整合 1996 版与 Open Group Base Specifications Issue 6；2008 年 IEEE 1003.1-2008 发布，2013 年与 2016 年两次技术勘误，2017 年 IEEE 1003.1-2017（POSIX.1-2017）发布，2024 年 6 月 IEEE 1003.1-2024（POSIX.1-2024，Base Specifications Issue 8）发布并与 C17 标准对齐；FreeBSD 2.0（1995 年）即引入仿照 HP-UX 的 **rtprio(1)** 实时调度用户命令（作者 Henrik Vestergaard Draboel），对应系统调用为 **rtprio(2)**；POSIX.1b 标准的实时调度接口（**sched_setscheduler(2)** 等）则在 FreeBSD 5.0-RELEASE（2003 年 1 月）首次内置，POSIX.1b 进程相关扩展于 1998 年合入，线程支持于 1999 年加入，FreeBSD 5.0（2003 年 1 月）正式合并 TrustedBSD 子项目并对 POSIX.1e ACL 与 POSIX.1c（pthreads 线程）扩展 等做完整支持；2004 年 6 月 IEEE 与 The Open Group 正式授权 FreeBSD 项目使用 POSIX 标准 1400 余个接口的文档材料（headers、system interfaces、utilities）以供手册页与文档引用，此举使 FreeBSD 开发者可合法从 POSIX 标准文本直接复制材料至手册页，避免以往必须自行重述的负担；FreeBSD 长期设有"C99 and POSIX Conformance Project"项目旨在合规于 Single UNIX Specification 的子集并记录差异点，但 FreeBSD 从未正式申请 POSIX™ Certified 认证（需向 The Open Group 缴纳费用并通过 VSX4/VSX5/VSTH/VSU5/VSRT 等测试套件），其合规性以“实际遵守但未缴费认证”的形式实现；FreeBSD 与 LSB（Linux Standard Base）的关系长期紧张——LSB 由 Linux Foundation 主导覆盖 POSIX 80% 内容但与 POSIX 存在差异，POSIX 阵营曾主张合并 LSB 而 LSB 阵营拒绝，FreeBSD 因不参与 LSB 而在跨平台脚本兼容性上需依赖 Ports Collection 的 Linuxulator（即 **linux(4)** 描述的 Linux ABI 兼容层，无 **linuxulator(4)** man 页，"Linuxulator"为社区俗称）兼容层运行 Linux 二进制；按 0 信任原则考据：2004 年 IEEE 与 Open Group 授权 FreeBSD 使用 POSIX 文档材料一事经 OSNews 2004 年 6 月 2 日首报与 IEEE 官方公告交叉验证，但"C99 and POSIX Conformance Project"的具体起止时间与产出文档在 FreeBSD 邮件列表存档中只有零散提及，该项目是否最终完成存疑，本节叙事仅依据已核实材料；

## 303.1.3 POSIX 与 LSB 标准冲突辨析

  **要点**：LSB 由 Linux Foundation 主导覆盖 POSIX 80% 内容但与 POSIX 存在差异，POSIX 阵营曾主张合并 LSB 而 LSB 阵营拒绝，FreeBSD 因不参与 LSB 而在跨平台脚本兼容性上依赖 Ports Collection 的 Linuxulator（**linux(4)**）兼容层

| 维度 | POSIX | LSB |
| -- | --- | - |
| 主导机构 | IEEE 与 The Open Group | Linux Foundation |
| 首版发布 | 1988（IEEE Std 1003.1-1988） | 1999（LSB 1.0） |
| 覆盖范围 | 操作系统接口标准 | 覆盖 POSIX 80% 内容但与 POSIX 存在差异 |
| FreeBSD 立场 | 实际遵守但未缴费认证 | 不参与 LSB |
| 跨平台脚本兼容性 | 直接支持 | 依赖 Ports Collection 的 Linuxulator（**linux(4)**）兼容层 |
| 合并讨论结果 | POSIX 阵营主张合并 | LSB 阵营拒绝 |

**史料**：Linux Foundation LSB 规范文档、POSIX/LSB 合并讨论 freebsd-standards 邮件列表、Linux Standard Base 1.0 1999 年发布说明 ［A］
**史观**：总纲第 6 条——技术路线分化导致 POSIX 与 LSB 两套标准并存
**辨析**：“覆盖 80%”的比例来源需追溯 LSB 4.0 与 POSIX.1-2008 的接口对照表；合并讨论的具体邮件线索需在 freebsd-standards 与 lsb-discuss 两列表交叉检索

**辨析**：

- 题眼冷知识考据 POSIX 路径解析中的双斜杠：除以两个连续斜杠开头的情形外，路径中的多余斜杠均可折叠为单斜杠，而“//”开头的路径被允许按实现定义方式解释——规格的 rationale 小节对此并未给出解释；主持人循 Stack Overflow 旧帖盘点各实现：Cygwin 以之承载 Windows UNC 网络路径，IBM z/OS 用以访问 MVS 数据集，Apollo Domain OS 与 AT&T System V Release 3 的 RFS 远程文件共享以“//主机/路径”指向他机文件，Perforce 的 //depot 指向版本库内文件，Blender 甚至以双斜杠表示相对路径——多源并置足证该空隙是各实现历史分岔在标准文本中的沉淀，而非规范自身的逻辑要求。（BSD Now EP183，[536.94-661.60]，L3）
