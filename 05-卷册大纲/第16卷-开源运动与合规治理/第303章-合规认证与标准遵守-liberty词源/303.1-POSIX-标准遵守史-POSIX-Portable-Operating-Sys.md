## 303.1.1 POSIX 标准接口与 FreeBSD 实现

  **要点**：FreeBSD 2.0（1995 年）即引入仿照 HP-UX 的 **rtprio(1)** 实时调度用户命令（作者 Henrik Vestergaard Draboel），对应系统调用为 **rtprio(2)**；POSIX.1b 标准的实时调度接口（**sched_setscheduler(2)** 等）则在 FreeBSD 5.0-RELEASE（2003 年 1 月）首次内置，1998 年合入 POSIX.1b 进程相关扩展，1999 年加入 pthreads 线程支持，5.0（2003 年 1 月）合并 TrustedBSD 后完整支持 POSIX.1e ACL 与 POSIX.1c（pthreads 线程）扩展

| POSIX 版本 | 发布年份 | 标准编号 | 关键内容 |

| POSIX.1 | 1988 | IEEE Std 1003.1-1988 | 第一版 POSIX.1 标准，POSIX 名称由 Richard Stallman 建议取“Portable Operating System Interface”之首字母缩写并加“X”以类 Unix 风格收尾；1990 年该版本被采纳为国际标准 ISO/IEC 9945-1:1990 |
| POSIX.1b | 1993 | IEEE Std 1003.1b-1993 | 实时扩展：进程调度、内存锁、实时信号、信号量、共享内存、消息队列、时钟与定时器、异步 I/O |

## 303.1.3 POSIX 与 LSB 标准冲突辨析

  **要点**：LSB 由 Linux Foundation 主导覆盖 POSIX 80% 内容但与 POSIX 存在差异，POSIX 阵营曾主张合并 LSB 而 LSB 阵营拒绝，FreeBSD 因不参与 LSB 而在跨平台脚本兼容性上依赖 Ports Collection 的 Linuxulator（**linux(4)**）兼容层

| 维度 | POSIX | LSB |
| -- | --- | - |
| 主导机构 | IEEE 与 The Open Group | Linux Foundation |
| 首版发布 | 1988（IEEE Std 1003.1-1988） | 1999（LSB 1.0） |
| 覆盖范围 | 操作系统接口标准 | 覆盖 POSIX 80% 内容但与 POSIX 存在差异 |
| FreeBSD 立场 | 实际遵守但未缴费认证 | 不参与 LSB |
| 跨平台脚本兼容性 | 直接支持 | 依赖 Ports Collection 的 Linuxulator（**linux(4)**）兼容层 |
| 合并讨论结果 | POSIX 阵营主张合并 | LSB 阵营拒绝 |

**史料**：Linux Foundation LSB 规范文档、POSIX/LSB 合并讨论 freebsd-standards 邮件列表、Linux Standard Base 1.0 1999 年发布说明 ［A］
  **史观**：总纲第 4 条——分离聚合是永恒规律：POSIX 与 LSB 两套标准在分离与并存中演化
**辨析**：“覆盖 80%”的比例来源需追溯 LSB 4.0 与 POSIX.1-2008 的接口对照表；合并讨论的具体邮件线索需在 freebsd-standards 与 lsb-discuss 两列表交叉检索
**文献**：Linux Standard Base 4.0 Specification；IEEE Std 1003.1-2008；M. Tim Jones“Cross-Platform Development with LSB”［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**辨析**：

- 题眼冷知识考据 POSIX 路径解析中的双斜杠：除以两个连续斜杠开头的情形外，路径中的多余斜杠均可折叠为单斜杠，而“//”开头的路径被允许按实现定义方式解释——规格的 rationale 小节对此并未给出解释；主持人循 Stack Overflow 旧帖盘点各实现：Cygwin 以之承载 Windows UNC 网络路径，IBM z/OS 用以访问 MVS 数据集，Apollo Domain OS 与 AT&T System V Release 3 的 RFS 远程文件共享以“//主机/路径”指向他机文件，Perforce 的 //depot 指向版本库内文件，Blender 甚至以双斜杠表示相对路径——多源并置足证该空隙是各实现历史分岔在标准文本中的沉淀，而非规范自身的逻辑要求。（BSD Now EP183，[536.94-661.60]，L3）
- 随着苹果宣布 APFS 将随 iOS 10.3 出货，Adam Leventhal 延续其对 APFS 的 DTrace 考古：以约十九行 C 程序调用 fs_snapshot 系统调用遭权限拒绝，借 DTrace 十三万七千个插桩点定位到凭证检查函数，对照 xnu 源码加 sudo 后创建成功，继而以暴力枚举重建了 WWDC 演示中未曾发放的快照工具，随后却在 Sierra 系统目录里发现官方 apfs_snapshot 与疑似支持就地转换的 hfs_convert；更具考据价值的是回滚语义——revert 调用返回成功却不即时生效，须卸载重挂方见回退，且静默删除其后全部快照，而 ZFS 面对同样操作会显式警告将销毁快照；同一概念在两个谱系中的约定程度落差，叠加快照致磁盘工具失序乃至仅重启可解的挂载死锁，显示该文件系统尚在成形途中。　[存疑脚注] 转写开头将受访者误作“Evan Leventhal”，后文“adam being adam”可证为 Adam Leventhal，引用时以 dtrace.org 原文为准。（BSD Now EP183，[710.08-1139.12]，L2）
