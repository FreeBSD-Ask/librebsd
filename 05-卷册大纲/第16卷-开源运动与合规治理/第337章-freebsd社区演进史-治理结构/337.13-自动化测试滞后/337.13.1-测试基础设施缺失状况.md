# 337.13.1 测试基础设施缺失状况


306.13 **自动化测试滞后**——FreeBSD 自动化测试基础设施的引入时间线与测试债务对开发者体验的影响。注意：ATF 自动化测试框架 2012 年即自 NetBSD 引入 FreeBSD（FreeBSD Journal 2019 年 3-4 月刊，Kristof Provost《The Automated Testing Framework》），“直到 2017 年才发现自动化测试的概念”的旧论断与史实不符，2017 年前后应限于 Jenkins CI 部署等节点且时间线待考

  **要点**：FreeBSD 直到 2017 年才引入 CI/CD（Jenkins）系统，先前主要依赖手动测试与 release engineering 团队的安装测试

| 时间 | 测试基础设施状态 | 关键节点 |
| -- | -------------- | ------ |
| 2017 前 | 主要依赖手动测试与 release engineering 脚本 | 无 CI/CD 系统 |
| 2017 后 | 引入 Jenkins CI | CI/CD 系统建立 |
| 后续 | 引入 kyua 测试框架、GitHub Actions | 测试基础设施逐步完善 |

> FreeBSD 直到 2017 年才发现自动化测试的概念，技术债务拖累开发者体验。（存疑：FreeBSD 早在 2012 年即自 NetBSD 引入 ATF 自动化测试框架，此句论断与该史实相悖，且所署 BSDCan 2017 演讲出处待考）
>
> ——BSDCan 2017 演讲
