# 2.2.3 审议强度随改动规模而定

<!-- DOC_MINE: ref10507#url -->
**官方文档**（证据等级：L3，来源：`historical_claims.duckdb.claim.CL-RM-497661`；2026-11-21 V50 补证批 b012）

committer(7) “DISCUSSING COMMITTABLE WORK BEFOREHEAD” 节明言文档类简单改动不需预告（“Simple and obvious work such as documentation edits or additions doesn't really need a heads up.”），而复杂议题通常先经列表讨论（“More complex issues are usually discussed on the lists first.”）——审议强度随改动规模而定。引文出处：DragonFly BSD Project. committer(7) — DragonFly 提交者指南[EB/OL]. https://gitweb.dragonflybsd.org/dragonfly.git/blob_plain/HEAD:/share/man/man7/committer.7 [2026-11-21].；引文按 L3 纪律：以上为公开文献记载（官方文档或同时代报道），非当事人直接证词，具体结论仍须回核原文与同期一手材料，不得单独引为定论。
