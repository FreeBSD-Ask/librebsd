# 299.4.3 再批评层：回馈的结构性不对称

**要点**：BSD 阵营的再批评是——商业采用者的回馈在结构上仍不对称：(1) 回馈集中于商业采用者自身依赖的子系统（如 Netflix 回馈网络栈、NetApp 回馈文件系统），是“自利性回馈”而非“对等回馈”；(2) 核心商业逻辑（Netflix 推荐算法、Sony DRM、Apple iOS 用户空间、Juniper 转发平面、NetApp WAFL）未开源；(3) 雇佣 committer 使商业采用者获得 committer 全职产出，社区仅获得其业余时间的非商业贡献；(4) 商业采用者通过 BSDL 获得了“免费 R&D”，但 FreeBSD 社区未获得对等商业回报；不对称在许可证框架内合法但在道德层面存疑

**史料**：Netflix Tech Blog（核心商业逻辑未开源）、Apple Darwin Source（仅部分 BSD 衍生代码开源）、Juniper Junos 文档（转发平面为 Juniper 自研）、NetApp ONTAP 文档（WAFL 为 NetApp 专有）；freebsd.duckdb〔原标注 openbsd.duckdb 系挂库讹误，数据本体为 freebsd-src 口径〕 查询 L3.2.1 与 L7.2.1 显示商业实体 commit 占比与衍生项目回馈 commit 排名均偏低，但该统计基于邮箱域名识别，可能遗漏使用 @freebsd.org 或个人邮箱的企业开发者［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**史观**：总纲第 19 条——解释学循环是历史认识的根本条件，“回馈”与“散逸”的命名本身是权力行使

**辨析**：考据过程留痕——【查证来源】FreeBSD Handbook 官方“Who’s Using FreeBSD”页面（**<https://www.freebsd.org.cn（中文镜像站，非官方主站 freebsd.org）/freebsdhandbook/nutshell.html>**，访问日期 2026-07-23）一手核验 Apple/Juniper/NetApp/Netflix/Sony 各企业采用 FreeBSD 但核心商业逻辑未开源的事实——Apple iOS 用户空间、Sony PS DRM 与专有驱动、Netflix 推荐算法与内容分发调度、Juniper 转发平面（Juniper 自研）、NetApp WAFL（NetApp 专有）各企业文档均确认未开源；freebsd.duckdb contributors 表查询一手核验确认 @netflix.com/@juniper.net/@netapp.com/@apple.com 四域邮箱在 freebsd-src 仓库合计仅 110 条 commit（64+29+11+6），占 freebsd-src 总 444067 commits 的 0.0248%；【交叉验证方法】FreeBSD Handbook 官方文档（一手）与 freebsd.duckdb contributors 表（一手）互证，确认“核心商业逻辑未开源”与“商业实体直接 commit 占比极低”两个事实；但“对等回馈”的标准是价值判断而非事实判断——BSDL 不要求对等回馈，“对等”是 GPL 框架的标准而非 BSD 框架的标准，以 GPL 标准衡量 BSD 实践是范畴混淆；【存疑判定依据】freebsd.duckdb 邮箱域名识别存在局限——Netflix 工程师 Jonathan T. Looney（`jtl@FreeBSD.org`，205 commits）与 Andrew Gallatin（`gallatin@FreeBSD.org`，759 commits）使用项目官方邮箱提交，二者合计 964 条 commit 占 @netflix.com 直接 commit（64 条）的 15 倍，证实“邮箱域名 commit 占比偏低”不能直接等同于“回馈稀薄”，须与 Foundation 年度报告、企业工程档案、BSDCan 演讲名单多源交叉验证；回馈集中于商业采用者自身依赖的子系统（Netflix 网络栈、NetApp 文件系统）是“自利性回馈”而非“对等回馈”的事实成立，但“自利性回馈”在 BSDL 框架内仍属回馈，BSDL 不区分“自利”与“利他”回馈；0 信任原则提示：本节辩证链的事实基础（核心商业逻辑未开源、回馈子系统集中）以各企业官方文档与 freebsd.duckdb 查询结果交叉验证，但“不对称在道德层面存疑”是史家判断而非企业自述
