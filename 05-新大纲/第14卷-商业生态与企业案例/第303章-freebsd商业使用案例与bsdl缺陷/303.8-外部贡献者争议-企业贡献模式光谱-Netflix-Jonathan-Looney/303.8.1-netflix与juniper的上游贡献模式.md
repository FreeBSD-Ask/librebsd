# 303.8.1 Netflix 与 Juniper 的上游贡献模式

**要点**：**Netflix** 与 **Juniper** 是 **FreeBSD** 上游贡献最活跃的企业，两者均有 committer 直接推送代码。**Netflix** 贡献 **kernel TLS offload**，**Juniper** 贡献 **ARM64** 支持。

  | 企业 | 贡献类型 | 贡献者 | 核心技术 |
  |---|---|---|---|
  | **Netflix** | 上游 committer | **Jonathan Looney**、**Drew Gallatin** | **kernel TLS offload** |
  | **Juniper** | 上游 committer + 资金 | — | **Broadcom** **ARM64** SoC |

  > 有很多来自像 Netflix 这样的公司，内部会有 FreeBSD 专家团队开发功能，这些工作直接进入上游 FreeBSD。
  > ——John Baldwin
**史料**：**FreeBSD** commit 记录、**Baldwin** 公开评论、**Foundation** 年报 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：企业贡献的双重动机

**辨析**：贡献动机的 “利他 vs 利己” 辨析需避免道德判断；四公司贡献模式对照——**Netflix**（committer 约 2-3 人，commit 数千级，资金赞助，代码回馈方向：kernel TLS offload 等直接推入上游）、**Juniper**（committer 数人，commit 数百级，资金赞助占 **Foundation** 年度预算半数以上，代码回馈方向：**ARM64** SoC 支持推入上游）、**Sony**（committer 0 人，commit 0，无资金赞助，代码回馈方向：完全封闭 fork 无上游回馈）、**Apple**（committer 极少，commit 不足十来个，无资金赞助，代码回馈方向：**Darwin** fork 后与 **FreeBSD** 主线分化）；四公司贡献模式的差异反映的不仅是企业意愿差异，更是企业商业模式与 **BSD** 许可证互动的结构性差异——**Netflix**/**Juniper** 的商业模式需要上游内核持续维护（**CDN** 与路由器依赖 **FreeBSD** 内核稳定性），而 **Sony**/**Apple** 的商业模式将 **FreeBSD** 嵌入消费电子产品后法务部门严格限制外部代码交流，商业模式决定回馈意愿而非许可证本身[考据完成：2026-07-30 四公司 committer 数与 commit 数为基于 darwin.duckdb L3.2.1/L3.2.2 查询的估算，精确统计须以 git 仓库实时检索为准]
