# 298.1.9 BSDCan2006复盘第三届新场地第二年组织较前两年从容组织者本人甚至能一天听

- BSDCan 2006 复盘：第三届、新场地第二年，组织较前两年从容，组织者本人甚至能一天听四场报告；与会者逾 210 人（高于预期的 180 至 190，日注册数待核）；来源分布为加拿大约 140 人、美国 73 人、日本 6 人、欧洲十余至二十人，合计 14 个国家与 18 个美国州；讲者质量与会者反馈俱佳，会前数周已启动 2007 年筹备。（BSDTalk EP47，[151.24-207.08]，L1）
- 论文征集的结构性困难：程序委员会由各主要项目成员构成，职能是主动征稿与催稿、力求各项目论文均衡；NetBSD 与 OpenBSD 的投稿历来来者皆收却仍不足额——症结在于社区成员不主动投稿；2007 年拟增设 userland 演讲轨道，将讲者扩展至 BSD 开发者与用户之外。（BSDTalk EP47，[238.88-278.72]，L1）
- 演讲者经济模式：讲者或自费、或由雇主承担（雇主随后以赞助者身份获致谢）；组织方尽量补贴住宿与差旅，FreeBSD Foundation 及其他团体时有相助；但坚持不向讲者付酬——付酬将构成在加拿大境内工作，触发移民法障碍，这一约束在跨国学术会议组织中具有决定性。（BSDTalk EP47，[278.72-325.92]，L1）
- 社交即会议本体：2007 年拟为周五与周六午餐寻得赞助，使与会者留在场馆内用餐交谈；BSDCan 的社交面向来广为人知，与久闻其名而初次见面的讲者建立工作关系的能力不可低估，被视为一切开源项目的基石之一。（BSDTalk EP47，[329.24-371.44]，L1）
- 会议哲学的自我声明：不打算把 BSDCan 办成金钱炫目的大型展会；IBM、AMD、Apple、Intel 级别的主动参与固然欢迎，但目标始终是维持小型友好的社交型会议，让人们聚在一起讨论各自的工作；组织工作在会前数月与会后数周近乎全职，大额赞助可维系组织者生计，却不是目标本身。（BSDTalk EP47，[428.68-482.84]，L1）
- 公司谱系与存续：iXsystems 自视为 BSDI 的最后遗存——在同一办公地点近十年，先后经历 BSDi、九十年代初的硬件供应商 Telenet（其业务被 BSDi 收购）、BSDi 软件售予 Wind River 后硬件业务的延续；在多轮裁员困境中由 Matt Olander 向董事会提出员工买断并获接受；公司至今在五千平方英尺厂房里折弯金属、手工制造服务器，业务依然健康。（BSDTalk EP77，[62.32-132.46]，L1）
- 制造与测试体系：多数出货系统预装操作系统，偏好 FreeBSD，市场要 Linux 则装各发行版；产线工人最偏爱 FreeBSD，因为 Linux 变体过多且彼此差异足以打乱装配流程；由 Doug White 承建的自动测试系统引导安装 FreeBSD 后连续测试 48 小时，日志汇入主服务器并按 MAC 地址归档，机器半年后返修时可回查趋势、定位特定芯片组的性能问题；所有部署与定制配置均先经 FreeBSD 预测试。（BSDTalk EP77，[168.42-264.56]，L1）
- 反直觉的硬件支持观察：同时装配 FreeBSD 与各种 Linux 使该公司看到外人看不到的一面——服务器级硬件上 FreeBSD 的支持常优于多数 Linux，某 RAID 卡 FreeBSD 支持而 Red Hat 不支持、某网卡芯片组 FreeBSD 支持而 Debian 不支持；其归因是 Red Hat 专注软件、硬件测试规模远不及像他们这样亲手装配测试硬件的厂商；多数人被 Linux 的商业支持声势误导而意识不到这一点，FreeBSD 在多方面实际胜出。（BSDTalk EP77，[920.36-983.08]，L1）
- 对 FreeBSD 项目的回馈方式：唯一持续财务支持的项目是 FreeBSD，形式包括专供项目使用的专用 T1 线路与一整架设备；与 Intel 合作开发 Woodcrest 系统早于多数厂商甚至 Dell；为 Doug White 的嵌入式 FreeBSD 工作购置开发板；赞助 FreeBSD 在 Intel 与 IBM 刀片上的集成使其无缝运行，已售出多台，客户包括旧金山大学医疗部门的全校 FreeBSD 部署。（BSDTalk EP77，[289.28-346.64]，L1）
- 收购 PC-BSD 的动机与承诺：贸易展上派发 FreeBSD CD 却总被索要 PC-BSD CD，促其反思 FreeBSD 项目多年忽视桌面与笔记本、抱着够聪明就自己搞定的态度；家庭 web 服务器体验决定职场推荐的传播链使桌面成为生态入口；Kris Moore 的目标是让自己母亲能用（其母即首批测试者）；针对社区对闭源化的担忧，他以 BSDi 亲历者身份承诺——在开源环境中把开源代码闭源会遭严厉看待，更多眼球审视代码只有好处，商业世界终将放弃源码紧控、转向以法律自保加增值服务支撑公司，公司无意闭源且恰恰相反。（BSDTalk EP77，[442.28-593.78]，L1）
- 服务器图形界面需求的兴起与桌面路线：收购前 Kris Moore 已启动 PC-BSD 服务器版，规划服务器专用、笔记本专用与桌面专用的 PBI 功能；从服务器厂商视角看，带 X 的 FreeBSD 服务器需求真实增长——某大型 web hosting 客户的资深管理员明确欢迎图形界面，以便初级员工承担简单任务；系统爱好者容易忘记运维热情并非人人都有；iXsystems 自己将借 Win4BSD 的 PBI 覆盖 Office 与仅支持 IE 的老旧门户，准备全员转向纯 BSD 桌面。（BSDTalk EP77，[615.18-782.48]，L1）
- 个人结缘与工程文化判断：1994、1995 年间做销售自动化顾问时，在客户处撞见 x86 兼容机而非 Sun 或 IBM 工作站承载 X 与 TWM，随后又在另一客户处遇到 BSD/OS；先做 Red Hat 管理员、第一天就造出 RPM 依赖噩梦，深入 FreeBSD 后如换跑车——再无依赖地狱、ports 源码管理体系一见倾心； FreeBSD 社区不急于把最激进代码塞进内核、谨慎评估变更影响、以用户为念，而企业要的是持续运行而非最前沿，这种专业化的处事方式让他留守十余年。（BSDTalk EP77，[788.48-920.36]，L1）
- GPL 违规驱动的采用信号：常跑展会的直接观察是越来越多副总裁与高管层级人物主动到 BSD 展台谈论 GPL 与 BSD 许可证、谈论 GPL 违反问题；随着成功的 GPL 违规案例与企业担忧同步增多，寻找替代方案的人将持续增加，而发现 BSD 是可行替代者往往选择采用。（BSDTalk EP77，[1058.38-1102.98]，L1）
- 与 iXsystems 合并的结构与意图：合并想法约一年前提出，Kris Moore 原以百分之百持有 PC-BSD 软件公司（该公司为保护名称与商标而设），合并后保留部分所有权；iXsystems 在 FreeBSD 社区声誉良好、此前已提供服务器硬件与专业资源；合并带来的是商业社区最欠缺的东西——一家出问题时可以致电或邮件的公司与专业开发背书；11 月 1 日起 Kris 转为全职，从业余挤时间变为每天八小时以上，未来凭付费电话与邮件支持的收入的资本扩雇技术支持、网页设计、C++ 开发与 shell 脚本人手；人仍居华盛顿州温哥华近郊远程办公，品牌不变，iXsystems 只是其背后的公司。（BSDTalk EP78，[91.32-142.32]，L1）
- 开源与免费承诺：明确否认闭源或转收费产品的计划，保持同样的开源许可与免费下载；与 Mac OS X 每半年 129 美元的升级收费形成刻意对照；商业模式建立在企业电话与邮件支持之上——企业需要知道有专业公司在背后持续开发、需要时找得到人，这正是此前阻碍商业采用的一环。（BSDTalk EP78，[1110.04-1142.64]，L1）
- PC-BSD 1.3 beta 的技术内容：因专注促成交易而延迟约一个月，安装器为全新从零重写——防火墙设置、分区、用户创建与服务器安装选项，观感更专业；服务器安装装载与桌面相同的包，但默认引导进 Fluxbox 加 iDesk 的轻量环境，避免 KDE 常驻服务器耗用资源，同时保留临时登入 KDE 的能力；新增镜像盘安装——指定主盘与镜像盘、安装前即预填充、首次开机即处于镜像状态；基座跟随 FreeBSD 6.1，新 release 出来一两个月内评估发布更新；PAMP PBI 数次点击即部署 Apache、MySQL、PHP 全栈。（BSDTalk EP78，[327.78-512.04]，L1）
- PBI 生态与专利合规困境：多媒体与浏览器尽量打成 PBI（Linux Flash 兼容层、Opera 等），尚无 BSD 原生 Flash，期望借 iXsystems 的媒体曝光与 BSDStats 数据说服 Adobe 发布原生版本；美国软件专利环境下公司不能背书 MP3 编解码与 DVD 播放、不能建议用户下载，只能任由法律许可地区的第三方托管含编解码的 PBI；Real 曾为 Linux 版 RealPlayer 授权 MP3 编解码，是否延伸到 BSD 尚待查证——如法律变化则愿意内置。（BSDTalk EP78，[626.44-728.48]，L1）
- BSDStats 市场情报机制：匿名统计提交服务已在 ports 集合存在一段时间，PC-BSD 集成以了解用户国别与硬件分布，用于定向营销与针对性特性规划，并与媒体曝光配合增强对 Adobe 等专有厂商的谈判筹码。（BSDTalk EP78，[555.96-581.36]，L1）
- 单一桌面策略与防碎片承诺：拒绝在桌面端提供多桌面选择——多桌面令家庭用户困惑、库与桌面链接位置分裂、PBI 开发者被迫适配各窗口管理器；服务器端附 Fluxbox 面向会自行定制的专业用户则无碍；明确承诺与 FreeBSD 保持百分之百兼容——不分叉、不改内核、不做不兼容改动，PBI 属 PC-BSD 侧工具不能原生装于 FreeBSD；期望 PC-BSD 作为 FreeBSD 的补充，用户熟习后向下挖掘原生 FreeBSD，两项目互相推广。（BSDTalk EP78，[939.20-998.32]，L1）
- 架构与兼容性规划：i386 优先，AMD64 原生版为下一步目标，PowerPC 有用户请求待评估；64 位版的推进门槛是保证其可运行 32 位 PBI，使仅有 32 位构建的 Firefox 或 Opera 之类应用不构成使用限制。（BSDTalk EP78，[998.32-1043.52]，L1）
- 定位话术：向潜在用户的推介逻辑是 BSD 在基础操作系统层比 Linux 少碎片化、核心更坚实（自认属个人观点）、PBI 免除 Windows 用户解析依赖之苦、系统免于病毒且底层为高效稳定的服务器级基座；产品被定位为 Mac OS X 同类的竞争者，社区中已有将其称为做得对的 Mac OS X 的说法；项目当时仅约两年历史，始于一个想法放上网络、社区贡献随即涌入，创始人自视为补足 FreeBSD 社区久缺之物。（BSDTalk EP78，[1049.52-1102.56]，L1）
