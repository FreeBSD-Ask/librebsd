# 155.3.6 其他 BSD 网络栈（NetBSD / OpenBSD / DragonFly）

**要点**：NetBSD 网络栈强调可移植与 NP 简化；OpenBSD 以 pf 防火墙著称并主导 pf 的演进；DragonFly 自 2009 年起将网络栈 MPSAFE 化，到 2014 年实现主要协议完全并发；三者与 FreeBSD 网络栈同源 4.4BSD，在防火墙（pf 共享）、虚拟化（VNET 思路）、并发化上并行演进、代码互鉴。FreeBSD 网络栈与同时期主流操作系统网络栈关键维度对比汇总见下表。

| 操作系统 | 网络栈起源 | 防火墙框架 | 高性能数据面 | 网络虚拟化 | 可编程数据面 |
| --- | --- | --- | --- | --- | --- |
| FreeBSD | 4.2BSD TCP/IP 直系继承（1983） | **ipfw(8)**/**ipfilter(5)**/**pf(4)** 三框架并存 | **netmap(4)**、KTLS、**iflib(4)** | VNET（2009 实验性，2016 生产就绪） | netmap 用户态 + 内核态 API |
| Linux | Ross Biro 等 1992-1993 从头实现（借鉴 BSD socket API） | netfilter（iptables/nftables） | DPDK（用户态）、KTLS、eBPF/XDP | network namespaces（2008，Linux 2.6.24） | eBPF/XDP 通用内核虚拟机（生态领先） |
| DPDK（用户态框架） | Intel 2010 发布 | 不适用（绕过内核） | 完全用户态轮询；线速转发 | 不适用 | 用户态 PMD 驱动生态 |
| illumos/Solaris | UNIX SVR4 血脉 | ipfilter（ipf） | Crossbow 网络虚拟化与带宽管理 | Crossbow | DTrace 观测框架（FreeBSD 亦移植） |
| Windows | Winsock API（基于 BSD socket 借鉴）；NT 3.1 由 Spider Systems 基于 BSD 代码移植，Windows 2000 起完全重写 | Windows Filtering Platform（WFP） | NDIS、RSS、VMQ、SR-IOV | Hyper-V 虚拟交换机 | WFP 可编程过滤 |
| NetBSD | 4.4BSD-Lite 同源 | npf（现代）、ipf、pf 移植 | 较弱（强调可移植性） | 不强调 | —— |
| OpenBSD | 4.4BSD-Lite 同源 | **pf(4)**（上游主导，OpenBSD 3.0/2001.12 首发） | 较弱（强调安全与代码防御） | rdomain（路由域） | —— |
| DragonFly | 2003 年从 FreeBSD 4.x 分叉 | **ipfw(8)**/**pf(4)**（2014 完成 MPSAFE） | per-CPU 线程+IPI 消息传递无锁并发 | if_bridge、VNET 思路 | —— |

**史观**：总纲第 7 条——BSD 谱系：三大 BSD 网络栈同源 4.4BSD-Lite，pf 的共享、VNET 思路的互鉴体现 BSD 家族“代码自由流动”的特征。

**辨析**：OpenBSD 主导 pf 开发，FreeBSD/NetBSD 移植并各自扩展，这一“上游在 OpenBSD、下游多 BSD 复用”的模式是 BSD 协作的典型样本。
