# 155.1.4 要点netmapiflibSCTPKAMEIPv6这几个子系统有一个共同点它们都

**要点**：netmap、iflib、SCTP、KAME IPv6 这几个子系统有一个共同点：它们都是由特定领域专家长期维护的 “专业级” 代码——Rizzo 的 netmap/dummynet、Stewart/Tuexen 的 SCTP、Baldwin/Macy 的 iflib、KAME 团队的 IPv6、Leffler 的无线子系统；FreeBSD 网络栈不是由某个统一团队 “设计” 的，而是在 30 年间由不同领域的专家持续贡献和维护形成的有机整体；netmap 的一个常被忽视的特点：它的 API 设计同时支持内核模块和用户态程序，内核模块可以直接使用 netmap API 实现高速包处理（如软件交换机、防火墙）。FreeBSD 网络子系统关键技术演进汇总见下表。

| 技术 | 首次引入 FreeBSD 版本 | 主要贡献者 | 关键功能 |

| KAME IPv6 | FreeBSD 4.0（2000.03） | KAME 项目（NEC、Toshiba、Hitachi、IIJ、Keio University、WIDE 项目） | BSD IPv6/IPsec 参考实现，1998-2006 项目周期 |
| **dummynet(4)** | FreeBSD 2.x（1998） | Luigi Rizzo（比萨大学） | 带宽限制、延迟模拟、丢包模拟、队列管理；学术研究标准工具 |

**史观**：总纲第 10 条——动手者创造历史（存疑）〔订正注：原挂“总纲第 10 条——边缘者贡献”系自创名目，权威第 10 条为“动手者创造历史”；按权威表正名改挂〕：网络子系统的许多关键技术来自学术界（Rizzo 在比萨大学、KAME 在日本大学和研究机构）和专业领域公司（Netflix 做 CDN 优化），不是来自 “核心团队” 的规划；这体现了开源的力量——最好的代码可能来自意想不到的地方

**辨析**：netmap 是否被 FreeBSD 弃用——没有，netmap 仍在活跃维护，是 FreeBSD 高速包处理的主要方案；DPDK 在 FreeBSD 上的支持——DPDK 有 FreeBSD 移植但不在基本系统中，需要从 ports 安装；KAME 项目的 IPv6 代码是否还存在于现代 FreeBSD 中——KAME 代码经过 20 年演进和重写，现代 FreeBSD IPv6 栈已不是原始 KAME 代码，但 KAME 的遗产保留在设计和代码注释中；SCTP 是否 “失败了”——SCTP 在电信 SS7 over IP 领域有广泛使用，在通用互联网上因中间件（NAT/防火墙）支持问题未普及，但作为协议设计和 FreeBSD 实现质量很高
