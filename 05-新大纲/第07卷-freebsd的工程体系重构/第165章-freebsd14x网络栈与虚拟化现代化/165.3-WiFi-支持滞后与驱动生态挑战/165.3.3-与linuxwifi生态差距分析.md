# 165.3.3 与 Linux WiFi 生态差距分析

**要点**：Linux WiFi 生态的规模优势体现在三个方面：① 厂商直接支持——Intel、Qualcomm、Broadcom 等向 Linux 内核贡献驱动代码（部分为开源驱动 + 闭源固件）；② 专职开发者团队——Google、Intel、Red Hat、Canonical 等公司有全职工程师维护 WiFi 驱动栈；③ mac80211/cfg80211 框架成熟——Linux 无线子系统（mac80211）是经过 20 年演进的成熟框架，驱动作者只需实现芯片特定部分；FreeBSD 无线子系统 net80211（最初由 Atheros 资助开发）虽然稳定但功能与 Linux mac80211 有差距；OpenBSD 的 WiFi 支持同样依赖从 Linux 移植驱动（通过类似的兼容层）但 OpenBSD 对固件许可更严格（拒绝可再分发但不允许修改的固件），硬件支持范围更窄

**史料**：Linux mac80211 文档（wireless.wiki.kernel.org）；Atheros 资助 FreeBSD WiFi 历史（Sam Leffler 等工作）；OpenBSD 无线驱动移植策略说明 ［B］

**史观**：总纲第 4 条——分离聚合是永恒规律：操作系统在硬件支持上存在 “赢家通吃” 效应——芯片厂商优先为市场份额最大的 OS（Windows 用于桌面、Linux 用于服务器/移动/嵌入式）开发驱动，小市场 OS 只能通过兼容层移植驱动；这不是 FreeBSD 工程能力的问题，而是市场结构决定的生态位限制——FreeBSD 必须接受 “部分硬件支持永远滞后于 Linux” 的现实，同时通过 LinuxKPI 等策略尽量缩小差距

**辨析**：Broadcom WiFi 芯片（广泛用于 Raspberry Pi、Broadcom 自家芯片、Apple 设备）在 FreeBSD 上支持最差——Broadcom 以对开源支持差著称，其 brcmfmac 驱动在 Linux 上也需要闭源固件；Raspberry Pi 3B/4/5 的板载 WiFi 支持在 FreeBSD 上可用但稳定性不如 Linux
