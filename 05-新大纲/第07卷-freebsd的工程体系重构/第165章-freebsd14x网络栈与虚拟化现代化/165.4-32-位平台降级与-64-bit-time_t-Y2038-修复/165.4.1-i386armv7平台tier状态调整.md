# 165.4.1 i386/armv7 平台 Tier 状态调整

**要点**：FreeBSD 14.x 明确为最后一个包含 32 位平台 RELEASE 镜像的大版本系列——**15.0 将不再发布 i386 安装镜像**（原计划 14.0 即为最后 32 位 RELEASE，后调整为 14.x 周期内仍提供 i386 RELEASE 支持但 15.0 起停止）；i386 在 14.x 中仍为 Tier 2 架构（有 RELEASE 镜像和安全更新）；armv6 在 14.0 前已降级为 Tier 3（无 RELEASE，仅源码级支持），armv7 在 14.x 中保持 Tier 2；powerpc（32 位）、powerpcspe 等老旧架构也逐步降级；riscv64 在 14.0 中为 Tier 2（有 RELEASE 镜像但未获 Tier 1 完整支持）；aarch64（arm64）自 FreeBSD 13.x 已为 Tier 1，14.0 中继续完善——支持 Raspberry Pi 4/5、AWS Graviton（1/2/3/4）、Ampere Altra/Altra Max、AmpereOne、Apple Silicon（通过 Asahi Linux 移植经验与 FreeBSD 自身 Apple Silicon 移植工作）等平台

**史料**：FreeBSD 14.0 Release Notes Supported Architectures；FreeBSD 官方支持平台列表（freebsd.org/platforms/）；各架构 Tier 定义（Tier 1: RELEASE+ 安全更新 + 完整包构建，Tier 2: RELEASE+ 安全更新 + 部分包，Tier 3: 仅源码） ［A］

**史观**：总纲第 25 条——终结与延续：32 位平台的 “终结” 不是突然死亡，而是渐进降级——从 Tier 1 到 Tier 2 再到 Tier 3 最终从源码树移除，每个阶段都给用户迁移时间；FreeBSD 对老旧架构的支持时间长于大多数 Linux 发行版（Ubuntu 16.04 后停止 32 位桌面、RHEL 9 无 32 位），但也无法对抗半导体行业整体转向 64 位的大趋势

**辨析**：需区分 “架构降级” 与 “应用兼容性”——即使 15.0 不再发布 i386 RELEASE 镜像，amd64 版本的 FreeBSD 仍支持运行 32 位 i386 二进制（通过兼容层，类似 Linux multilib）；这意味着为 FreeBSD i386 编译的 32 位程序仍可在 amd64 FreeBSD 上运行，但无法在纯 i386 内核上启动新系统——这是 “内核纯 64 位化” 而非 “抛弃所有 32 位代码”
