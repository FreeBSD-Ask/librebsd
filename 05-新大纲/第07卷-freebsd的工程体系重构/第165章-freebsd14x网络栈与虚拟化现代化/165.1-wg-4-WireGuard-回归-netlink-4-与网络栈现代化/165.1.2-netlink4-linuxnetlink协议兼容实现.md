# 165.1.2 **netlink(4)**——Linux Netlink 协议兼容实现

**要点**：14.0 新增 **netlink(4)** 协议族实现，由 Alexander V. Chernikov（melifaro@）开发与提交；Netlink 是 Linux 内核与用户态网络管理工具之间通信的主要接口协议（Linux 原生接口，iproute2 工具集如 ip 命令使用 Netlink 与内核通信）；FreeBSD **netlink(4)** 实现了 Netlink 协议的核心子集（路由、接口配置、地址管理、neighbor 表等），使 Linux 网络管理工具（包括部分 iproute2 组件、网络配置守护进程）可以更方便地移植到 FreeBSD，也为未来统一网络配置接口（替代分散的 ifconfig/route/arp 等工具）提供了协议基础；**netlink(4)** 的实现严格遵循 Linux Netlink 语义但使用 FreeBSD 原生内核数据结构与路由栈，不是简单模拟层

**史料**：netlink(4) 系列 commit（cgit.freebsd.org/src/，Alexander V. Chernikov 提交）；netlink(4) 手册页；Chernikov EuroBSDCon 2023 netlink 演讲；freebsd-net@ 邮件列表 netlink 设计讨论 ［A］

**史观**：技术路线分化：**netlink(4)** 的引入代表 FreeBSD 网络栈现代化的一个重要方向选择——在保留 BSD socket API 与传统网络工具（ifconfig、route、arp 等）的同时，提供 Netlink 兼容接口以吸引熟悉 Linux 网络管理的用户与工具；这不是“放弃 BSD 网络传统”，而是承认 Netlink 作为网络配置接口的生态事实标准地位

**辨析**：**netlink(4)** 在 14.0 中的支持范围需精确说明——实现了 NETLINK_ROUTE 协议族的主要功能（路由、接口、地址、邻居、规则、路由表），但 NETLINK_GENERIC、NETLINK_NETFILTER 等其他 Netlink 协议族在 14.0 中尚未完整实现（部分在 14.x 后期与 15.0 中持续完善）；**netlink(4)** 不影响传统 ioctl/SIOCSIFxxx 接口——ifconfig、route 等传统工具继续工作且仍是官方推荐管理工具
