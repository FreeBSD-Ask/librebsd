# 165.1.1 **wg(4)** WireGuard 重新集成与代码争议解决

**要点**：FreeBSD 14.0 重新集成了 **wg(4)** WireGuard VPN 驱动（commit 744bfb213144，由 Netgate/Rubicon Communications 与 FreeBSD Foundation 赞助）；这是 2021 年 WireGuard 争议事件的收尾——FreeBSD 13.0 开发周期中，WireGuard 驱动被仓促合入后因代码质量、安全漏洞与审查流程问题在 RC 阶段被临时移除，引发社区激烈争议；14.0 中的 **wg(4)** 完全由 John Baldwin（约翰·鲍德温）（jhb@）团队独立重新实现，而非基于当时争议的代码，经过多轮独立安全审计、Peer Review 与广泛测试后才合入；**wg(4)** 在 GENERIC 内核中默认编译为模块（if_wg.ko），但 **不自动加载**，需用户通过 `if_wg_load="YES"` rc.conf 设置或手动 kldload 加载；14.0 发布时 WireGuard 协议已成为现代 VPN 事实标准（Linux 5.6 2020 年内核集成、OpenBSD 6.8 2020.10 集成）

**史料**：FreeBSD 14.0 Release Notes wg(4) 条目；wg(4) 重集成 commit 744bfb213144；John Baldwin wg(4) 重写状态报告（freebsd-net@ 邮件列表）；2021 年 WireGuard 争议邮件列表存档（freebsd-current@ 2021.3）；WireGuard 官方网站 wireguard.com ［A］

**史观**：社区治理：WireGuard 争议是 FreeBSD 社区治理史上的标志性事件——它暴露了 FreeBSD 在大功能合入流程中的审查不足问题，也推动了代码评审流程的改进；争议过后 Core Team 发布了更严格的新驱动合入准则，Foundation 赞助 John Baldwin 全职进行 **wg(4)** 重写，最终结果是更安全的实现与更严格的代码审查文化——这是危机推动制度改进的经典案例

**辨析**：2021 年争议中的原始 WireGuard 代码（由 Netgate 员工编写）与 14.0 中的 **wg(4)** 是完全独立的实现——14.0 中没有一行来自争议代码；WireGuard 创始人 Jason Donenfeld 对 FreeBSD **wg(4)** 重写持肯定态度，曾在邮件列表中提供技术建议；**wg(4)** 与 WireGuard-Go（用户态实现，ports 中的 wireguard-go）的区别：内核实现性能远高于用户态，但需要稳定的内核驱动支持
