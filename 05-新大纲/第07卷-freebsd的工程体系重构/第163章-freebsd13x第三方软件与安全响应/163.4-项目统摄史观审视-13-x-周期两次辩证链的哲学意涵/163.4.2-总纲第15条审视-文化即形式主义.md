# 163.4.2 总纲第 15 条审视——文化即形式主义

**要点**：bsdgrep 默认化与 WireGuard 重写都印证“传统在形式主义化过程中被遮蔽与重构”。bsdgrep 作为“BSD 自己的 grep”是一种文化形式主义——它将“BSD 自给自足”的传统通过 **grep(1)** 手册页的默认化形式主义化为可见的工程身份标识；但 BSD 的 grep 实现历史上从未真正“自给自足”——FreeBSD 的 grep 长期是 GNU grep 的薄包装，bsdgrep 本身也借鉴了 OpenBSD 的实现路径，“BSD 自己的 grep”这一文化叙事是形式主义化后的重构。WireGuard 重写同样如此——Donenfeld 将重写后的 if_wg 描述为“接近 OpenBSD 的实现”，这一表述将“OpenBSD 实现作为正统”的形式主义化过程呈现得淋漓尽致；原本 Macy 的实现是基于 Linux 内核 compat module 的 40,000 行代码，重写后变为 1,800 行的 **crypto.c** 加上从 OpenBSD 逐字复制的 **wg_noise.c** 与 **wg_cookie.c**——“正统”的形式主义化通过代码来源的合法性重构完成。知音难觅同样适用——Macy 在公开邮件列表的“沉默式回应”使得技术对话只在一方（Donenfeld、Kyle Evans、Matt Dunwoodie 三方）展开，形式主义化的“对话”实际是单向的。

**史料**：项目史观总纲第 15 条原文；Donenfeld 邮件中关于“copied verbatim from OpenBSD”的表述；FreeBSD 13.0 Release Notes bsdgrep 默认化条目；OpenBSD 5.0 Release Notes（bsdgrep 引入）

**史观**：总纲第 15 条——文化即形式主义：两件事均体现“传统在形式主义化过程中被遮蔽与重构”——bsdgrep 的“BSD 身份”与 WireGuard 重写后的“OpenBSD 正统”都是形式主义化的文化叙事，史家须识别叙事背后的实际代码来源与历史连续性，不被形式主义化的“身份”遮蔽

**辨析**：本审视不否定 bsdgrep 或重写后 if_wg 的技术价值，而是揭示“BSD 自己的实现”这一文化叙事的形式主义性质；形式主义不等于虚假，但形式主义化的叙事会遮蔽实际的代码谱系——bsdgrep 的实际谱系包含 GNU grep 与 OpenBSD grep 的双重影响，重写后的 if_wg 实际谱系是 OpenBSD、WireGuard 项目、FreeBSD 社区的三方协作
