# 161.3.3 与其他 OS 版本控制策略比较

**要点**：同期其他操作系统的版本控制迁移情况：(1) Linux 内核从 2005 年起使用 Git（林纳斯·托瓦兹（Linus Torvalds）为管理 Linux 内核开发亲自创建 Git），从未使用 svn；(2) OpenBSD 长期使用 CVS，直到 2024 年仍在使用 CVS（OpenBSD 开发者认为 CVS 足够简单可靠）；(3) NetBSD 于 2015 年从 CVS 迁移到 Git；(4) DragonFly BSD 较早使用 Git；(5) illumos 从 Mercurial 迁移到 Git；FreeBSD 是主要 BSD 系统中较晚迁移到 Git 的，这与其代码库规模大、保守的工程文化有关

**史料**：OpenBSD CVS 使用说明（openbsd.org/cvs.html）；NetBSD Git 迁移公告（2015）；Linux 内核 Git 历史；各 BSD 项目官网仓库信息 ［A］

**史观**：总纲第 6 条——技术路线分化：版本控制系统选择体现了各项目的工程哲学：OpenBSD 坚持 CVS 体现了“够用就好、不盲目追新”的保守哲学；FreeBSD 经过多年评估和测试才迁移，体现了“不破坏开发者体验”的工程原则；Linux 最早迁移并创建 Git 本身，体现了“自主研发工具”的黑客精神

**辨析**：“OpenBSD 不迁移 Git 是因为技术落后”是一种误解——OpenBSD 开发者多次公开表示 CVS 满足其需求，Git 的复杂性对 OpenBSD 项目规模而言不必要；工具选择应服务于项目需求，而非反过来
