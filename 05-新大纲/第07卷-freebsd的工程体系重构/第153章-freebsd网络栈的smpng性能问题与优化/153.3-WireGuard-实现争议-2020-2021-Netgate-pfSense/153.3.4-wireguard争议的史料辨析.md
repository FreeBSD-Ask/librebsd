# 153.3.4 WireGuard 争议的史料辨析

**要点**：WireGuard 事件的一手史料完整且公开：freebsd-net 邮件列表上有完整的讨论线程（2020 年 11 月 -2021 年），代码提交和审查记录可在 cgit.freebsd.org 查阅，Core Team 有公开声明，Donenfeld 的原始批评邮件全文可查；需要澄清几个常见误解：① “WireGuard 从 FreeBSD 中移除了”——不准确——有问题的初始 **if_wg(4)** 被移除了，被从头重写的高质量 **wg(4)** 替代，WireGuard 在 FreeBSD 13.1+ 和 14+ 中都存在且支持良好；② “FreeBSD 拒绝了 WireGuard”——相反，FreeBSD 现在拥有高质量的 WireGuard 实现；③ “Donenfeld 起诉/禁止 FreeBSD 使用 WireGuard”——没有法律行动，只是技术批评，后续 Donenfeld 协助了新实现的审查。WireGuard 争议关键时间线汇总见下表。

| 时间 | 事件 | 关键参与方 |
| --- | --- | --- |
| 2020 年 | Netgate 赞助 Matt Macy 开发 FreeBSD 内核 WireGuard 实现 **if_wg(4)** | Netgate、Matt Macy |
| 2020.11 | **if_wg(4)** 初始代码合并入 FreeBSD 13.0-CURRENT 开发分支 | FreeBSD committer、Matt Macy |
| 2020.12 上旬 | Jason Donenfeld 在 freebsd-net 邮件列表发表详细代码审查，列出密码学 nonce 处理、重放窗口、密钥管理、协议状态机、内存泄漏等多个严重问题 | Jason Donenfeld（WireGuard 作者） |
| 2020.12 至 2021.01 | 社区讨论；FreeBSD Core Team 介入并发布声明 | FreeBSD Core Team、社区开发者 |
| 2021 年中 | John Baldwin 等人启动基于 WireGuard 官方标准的重新实现 **wg(4)**，邀请 Donenfeld 参与审查 | John Baldwin、Jason Donenfeld |
| FreeBSD 13.0-RELEASE | 初始 **if_wg(4)** 标记为实验性/废弃 | FreeBSD Release Engineering |
| FreeBSD 13.1+/14+ | 初始 **if_wg(4)** 移除，被从头重写的 **wg(4)** 替代；Donenfeld 认可新实现 | FreeBSD Project、Jason Donenfeld |

**史料**：freebsd-net 邮件列表完整存档（2020-11 至 2021）；cgit.freebsd.org if_wg(4) 移除和 wg(4) 添加的 commit 记录；Core Team 公开声明；WireGuard 官网关于 FreeBSD 支持的页面 ［A］

**史观**：形式主义膨胀：WireGuard 事件的一手史料全部公开可查，这是开源治理透明度的体现——闭源软件的类似问题可能永远不会被公开；但历史书写也需要注意不要过度简化事件为 “Netgate 做错了”，应该理解当时的时间压力（FreeBSD 13.0 版本冻结临近）和多方因素

**辨析**：事件时间线：①2020-11：**if_wg(4)** 初始代码合并；②2020-12-10 左右：Donenfeld 发表详细批评；③2020-12 至 2021-01：社区讨论，Core Team 介入；④2021 年中：新实现开始开发；⑤FreeBSD 13.0 发布时初始 if_wg 标记为实验性，最终在后续版本替换为新 wg；初始代码作者 Matt Macy 的角色——Macy 是经验丰富的 FreeBSD 开发者（贡献过 iflib 等多个子系统），这不是 “新手写烂代码”，而是安全协议实现需要专业领域知识
