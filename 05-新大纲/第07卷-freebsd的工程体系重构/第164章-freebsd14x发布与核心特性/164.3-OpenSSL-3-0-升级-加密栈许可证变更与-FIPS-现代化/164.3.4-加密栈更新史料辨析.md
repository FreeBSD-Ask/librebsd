# 164.3.4 加密栈更新史料辨析

**要点**：OpenSSL 3.0 升级工作由 Ed Maste（埃德·马斯特）、Bryan Drewery（布莱恩·德鲁里）、Bernard Spil 等多位开发者协作完成，涉及 base 系统中所有链接 libcrypto 的库与工具的重新编译与测试；由于 OpenSSL 3.0 的 API 相对于 1.1 有若干废弃函数与变更，Ports 中大量软件需要补丁才能与 OpenSSL 3.0 兼容——这是 14.0 发布前 ports 冻结期较长的原因之一；OpenSSL 1.1.1 作为 FreeBSD 12.x/13.x 的默认版本，在 13.x 周期内通过 backport 安全补丁持续维护至 13.x EOL；OpenSSL 3.0 的长期支持（LTS）版本，官方支持至 2026 年 9 月（但会扩展，类似 1.1.1 延长支持）

**史料**：FreeBSD base OpenSSL 3.0 迁移 commit 系列；Ports Collection OpenSSL 3.0 跟踪 PR；OpenSSL Release Schedule（openssl.org/policies/releasestrat.html） ［A］

**史观**：软件工程：OpenSSL 大版本升级是 base system 维护中风险最高的变更之一——libcrypto 被几乎所有涉及网络的基础程序链接（ssh、telnet、fetch、pkg、证书工具、KTLS 等），任何 API 不兼容都可能导致系统级故障；FreeBSD 采用 “大版本边界升级” 策略（14.0 升级 3.0，13.x 保持 1.1.1）而非 “滚动升级”，是为了避免在 STABLE 分支中引入此类高风险变更

**辨析**：vendor import OpenSSL 到 FreeBSD base 的过程采用了与 OpenZFS 类似的 vendor branch 策略（在 crypto/openssl 目录下维护与上游对齐的代码，本地修改通过 svn2git/vendor 分支管理）；OpenSSL 3.0 在 FreeBSD 14.0 发布时的精确版本为 3.0.12，14.1 跟进至 3.0.x 更新版本（随 14.1 OpenSSH 9.7p1 同步）
