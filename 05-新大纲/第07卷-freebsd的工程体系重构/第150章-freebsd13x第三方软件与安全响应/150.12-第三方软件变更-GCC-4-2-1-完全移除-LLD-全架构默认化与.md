# 150.12 第三方软件变更——GCC 4.2.1 完全移除、LLD 全架构默认化与 OpenSSL 版本

## 150.12.1 GCC 4.2.1 从所有架构完全移除

**要点**：FreeBSD 13.0-RELEASE（2021 年 4 月 13 日）将 GCC 4.2.1 从 base system 源码树中完全移除，结束 GCC 在 FreeBSD base 中长达 27 年的历史（自 FreeBSD 2.0 起）。GCC 移除由 Warner Losh（沃纳·洛什）（imp@）主导，是 FreeBSD 许可证纯洁化工程的最终里程碑。移除时间线：10.0（2014 年 1 月）Clang 成为 x86/arm 默认编译器，GCC 保留用于非 x86；12.0（2018 年 12 月）x86 不再默认安装 GCC 4.2.1 二进制；13.0（2021 年 4 月）完全移除 GCC 4.2.1 源码及相关的 libstdc++、libgomp、libssp 等库。所有架构（包括 powerpc、powerpc64、mips、riscv 等先前依赖 GCC 的架构）均完成 Clang 迁移，GCC 不再存在于 base 中。需使用 GCC 的用户可通过 ports 安装现代 GCC 版本（lang/gcc10-gcc13 等）。

**史料**：FreeBSD 13.0-RELEASE Release Notes（GCC 完全移除）、Warner Losh 2020-2021 年 freebsd-arch 邮件列表 GCC 退休公告与 commit 系列 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：GCC 4.2.1 完全移除标志着 FreeBSD 许可证纯洁化工程在编译器层面的最终完成——自 2007 年 GPLv3 发布以来，FreeBSD 项目用 14 年时间完成了从 GPL 编译器到 BSD 许可编译器的全面迁移，这是操作系统史上规模最大的编译器迁移之一；总纲第 22 条——知识注定过时：GCC 4.2.1（2007 年 5 月 13 日发布，GCC 4.2.1 于 2007 年 7 月 18 日发布）在 FreeBSD base 中存活 14 年，它的终结不是“编译器消亡”，而是“编译器自由”的实现——FreeBSD 不再受制于 GPLv3 不兼容

**辨析**：GCC 4.2.1 的移除不等同于“GCC 在 FreeBSD 上不可用”——ports 中的 lang/gcc 系列持续提供现代 GCC 版本（GCC 10/11/12/13 等），用户可自由安装；构建 ports 中的某些软件（如需要 OpenMP 的 C++ 程序、使用 GCC 特定扩展的 Fortran 程序）仍需要 ports GCC；GCC 移除仅影响 base system，不影响 ports 生态

**文献**：FreeBSD 13.0-RELEASE Release Notes [Z]. 2021-04-13；FreeBSD 10.0/12.0 Release Notes [Z]. 2014/2018；Warner Losh GCC retirement announcement [EB/OL]. freebsd-arch mailing list, 2020-2021 ［A］

## 150.12.2 LLD 成为所有架构的默认链接器

**要点**：FreeBSD 13.0-RELEASE 将 LLD（LLVM Linker）设为所有架构的默认系统链接器，完成 LLD 从“部分架构默认”到“全架构默认”的迁移。12.0（2018）中 LLD 仅为 amd64/arm64 默认，13.0 扩展到 i386、armv7、powerpc、powerpc64、riscv64 等所有支持架构。GNU ld 和 GNU binutils 从 base 中移除（与 GCC 4.2.1 一同移除），LLD 成为 base 中唯一的链接器。LLD 的链接速度优势（大型 C++ 项目快 2-5 倍）、LTO 原生支持、Apache 2.0 许可证是其成为全架构默认的关键因素。

**史料**：FreeBSD 13.0-RELEASE Release Notes（LLD 章节）、FreeBSD 12.0 Release Notes（LLD 部分默认） 〔L3 官方文档〕

**史观**：总纲第 13 条——法律与道德是利益分配：LLD 全架构默认化与 GNU binutils 移除是许可证纯洁化工程在链接器层面的最终完成，FreeBSD base 彻底摆脱 GNU binutils（GPLv3）的依赖；总纲第 9 条——经验优先：LLD 从“部分默认”到“全架构默认”的渐进迁移（12.0→13.0，历时 3 年）体现了 FreeBSD 对待底层工具链变更的谨慎态度

**辨析**：关于“GNU binutils 移除”——13.0 移除的是 base 中的 GNU binutils（GNU ld、GNU as、GNU objdump、GNU readelf 等），但用户仍可通过 ports 安装 GNU binutils（devel/binutils）用于特定需求；ELF Tool Chain 项目（FreeBSD 赞助的 BSD 许可 binutils 替代品）在 13.0 中已成熟，提供 objcopy、objdump、readelf、size、strings 等工具的 BSD 许可实现

**文献**：FreeBSD 13.0-RELEASE Release Notes [Z]. 2021；ELF Tool Chain Project [EB/OL]. sourceforge.net/projects/elftoolchain［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 150.12.3 OpenSSL 与 OpenSSH 版本

**要点**：FreeBSD 13.0-RELEASE 搭载 OpenSSL 1.1.1l（13.0）→ 1.1.1q（13.1）→ 1.1.1t（13.2）→ 1.1.1w（13.3），13.4 搭载 OpenSSL 3.0.16+。OpenSSL 1.1.1 支持 TLS 1.3，13.x 全程保持 1.1.1 系列的安全更新直到 13.3，13.4 升级至 OpenSSL 3.0 系列。OpenSSH 版本从 7.9p1（13.0）升级至 9.6p1（13.4），支持 sntrup761x25519 混合后量子密钥交换。sendmail 在 13.x 全系列中仍为默认 MTA（版本 8.16.1），DMA 不在 base 中——sendmail 的默认地位延续至 14.0 才被 DMA 替代。

**史料**：FreeBSD 13.0-13.4 Release Notes（OpenSSL/OpenSSH/sendmail 版本号） 〔L3 官方文档〕

**史观**：总纲第 22 条——知识注定过时：sendmail 在 13.x 中仍为默认 MTA，延续了自 4.1cBSD（1982）以来 40 年的传统，其替换发生在 14.0（2023 年），从讨论到实施历时近十年

**辨析**：OpenSSL 3.0 系列引入了新的 FIPS 140-3 模块和 Provider 架构，但 API 与 1.1.1 不完全兼容，因此 13.x 在前三个版本中保持 1.1.1 系列，仅在末期 13.4 升级至 3.0；OpenSSL 3.0 的许可证从 OpenSSL License 改为 Apache 2.0，这一许可证变更消除了 20 年的许可证兼容性问题（OpenSSL License 与 GPL 兼容性存在争议）

**文献**：FreeBSD 13.x Release Notes [Z]. 2021-2025；OpenSSL Project. OpenSSL 3.0 Release Notes [EB/OL]. openssl.org［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 150.12.4 第三方软件变更的史料辨析

**要点**：13.0 是 FreeBSD 许可证纯洁化工程的“竣工”版本——GCC 4.2.1 完全移除、LLD 全架构默认、GNU binutils 移除，三项变更共同标志着 FreeBSD base 彻底摆脱了对 GPL（v2/v3）许可组件的依赖。这一工程自 2007 年 GPLv3 发布启动，历时 14 年，涉及编译器、链接器、汇编器、调试器、文本工具、构建系统、DNS 解析器、软件包管理器等数十个组件的替换。13.0 的第三方软件变更体现了“终结”多于“开始”——旧工具链的移除多于新工具链的引入，这是 12.0/13.0 作为“移除期”的特征。

**史料**：FreeBSD 10.x/11.x/12.x/13.x Release Notes 对比 〔L3 官方文档〕

**史观**：总纲第 4 条——分离聚合是永恒规律：13.0 的 GCC/ld/binutils 移除是“终结”，但 LLVM 工具链（Clang/LLD/LLDB/libc++/libc++abi/compiler-rt）的全面接管是“延续”——FreeBSD 从一个“依赖 GPL 工具链的项目”转变为一个“拥有完整 BSD 许可工具链的项目”，这是 CSRG 解散后 FreeBSD 社区在工具链自主性上取得的最大成就

**辨析**：许可证纯洁化的“成功”不等于“所有 GPL 软件都从 FreeBSD 生态消失”——ports 中仍有大量 GPL 许可的软件（如 GCC、GIMP、GNU Emacs 等），但 base system 作为操作系统的核心，完全由 BSD 许可/兼容许可的代码组成，这确保了 FreeBSD 核心的许可证自由性

**文献**：FreeBSD 13.0-RELEASE Release Notes [Z]. 2021；FreeBSD 10.0/12.0 Release Notes [Z]. 2014/2018［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
