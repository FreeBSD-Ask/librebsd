# 154.1.1 TCP SACK 漏洞技术细节与效应范围

**要点**：TCP SACK（Selective Acknowledgment，选择确认）是 RFC 2018 定义的 TCP 扩展，允许接收方告知发送方哪些段已成功接收，在丢包场景下提升重传效率；2019 年 6 月，Netflix 信息安全团队（Jonathan Looney）发现了 Linux 和 FreeBSD TCP SACK 实现中的多个严重漏洞，统称为 “SACK Panic” 系列漏洞：①CVE-2019-5599——FreeBSD 特定漏洞，SACK 处理中整数溢出导致远程内核 panic（拒绝服务）；②CVE-2019-11477——Linux 特定漏洞，TCP_SKB_FRAG 数组溢出导致远程内核 panic；③CVE-2019-11478——Linux/FreeBSD 都受影响，SACK 分片重组导致高 CPU 占用（DoS）；④CVE-2019-11479——TCP MSS 与 SACK 组合导致资源耗尽；这些漏洞都是远程可触发的——攻击者只需向目标发送特制的 SACK 包序列即可导致内核 panic 或极端 CPU 占用，无需认证

**史观**：信息技术（不设总纲条号）：SACK Panic 漏洞揭示了一个深刻的信息技术悖论——TCP/IP 协议在 1981 年（RFC 793）设计时几乎不考虑安全问题，SACK 作为 1996 年的扩展（RFC 2018）也主要关注性能，40 年后这些核心协议实现中的安全漏洞可以让整个互联网基础设施面临风险；这说明 “性能优化” 与 “安全保证” 之间存在永恒张力

**辨析**：漏洞影响的 FreeBSD 版本——SA-19:08 显示受影响版本为 FreeBSD 11.2、11.3、12.0、12.1〔存疑：受影响版本列表未经 SA-19:08 原文逐项复核，11.3/12.1 在公告时点（2019-06-17）是否已发布待核〕，使用 RACK TCP 栈的 FreeBSD 13-CURRENT 不受 CVE-2019-5599 影响；SACK Panic 不是 OpenBSD 2026 年发现的——SACK Panic 是 2019 年的漏洞，章节标题提到的 “OpenBSD TCP SACK 27 年漏洞” 可能指其他漏洞，需要核实 据 fosdem (2019) 一手文献印证消解［^doubt-resolved-497：此处事实待多源交叉验证］；这些漏洞不是 “后门”，都是 1990 年代末 -2000 年代初代码中的整数溢出和逻辑错误
