# 152.2.3 与 Linux eBPF/XDP 可编程数据面的比较

**要点**：netgraph 与 Linux eBPF/XDP 在“可编程内核网络”目标上相似，但架构设计存在根本差异：① 执行模型——netgraph 节点是内核 C 代码模块，编译时静态确定类型；eBPF 是字节码虚拟机，程序可在运行时动态加载且经过内核 verifier 安全检查；② 组合模型——netgraph 使用显式图拓扑（节点 + 钩子）；eBPF 使用 maps 和 helper functions 组合，程序附加到钩子点（hook points）；③ 用户交互——netgraph 通过 **ng_socket(4)** 和 ioctl 控制；eBPF 通过 bpf() 系统调用和 pinned maps；④ 生态规模——eBPF 拥有庞大的工具生态（Cilium、bpftrace、BCC 等），netgraph 生态小但稳定；⑤ 历史时机——netgraph 1999 年即已存在，但因缺乏通用可编程能力和宣传推广，未获得 eBPF 那样的行业影响力；eBPF/XDP 诞生于 2014-2016 年（Alexei Starovoitov 和 Daniel Borkmann 重写），赶上了云原生和 SDN 浪潮

**史料**：Gregg, B. 2019《BPF Performance Tools》eBPF 历史章节；Starovoitov, A. eBPF 内核补丁系列（2014-2015）；Rizzo, L. netgraph vs netmap vs XDP 比较演讲；FreeBSD 项目关于是否移植 eBPF 的邮件列表讨论（2016-2024） ［A］

**史观**：总纲第 6 条——技术路线分化：netgraph 与 eBPF 的分化是“通用图抽象”与“安全字节码虚拟机”两条技术路线的竞争；netgraph 在 1999 年选择了“内核模块 + 图拓扑”路线，eBPF 在 2014 年选择了“字节码验证 + 动态附加”路线——后者凭借云原生生态胜出，但不代表前者在技术上更差

**辨析**：“netgraph 已经过时”是不准确的——截至 FreeBSD 15，netgraph 仍在活跃维护，被 pfSense/OPNsense 等防火墙发行版广泛使用；FreeBSD 项目有过移植 eBPF 的讨论但未付诸实施，核心维护者更倾向于在现有框架上演进而非引入一整套新子系统；XDP（eXpress Data Path）的“在网卡驱动层运行程序”思想与 netmap 更接近，与 netgraph 不在同一层次——XDP 是驱动层钩子，netgraph 是协议层中间件
