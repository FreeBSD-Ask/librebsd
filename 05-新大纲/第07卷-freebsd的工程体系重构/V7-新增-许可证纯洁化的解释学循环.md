# 许可证纯洁化——“什么是纯粹 BSD” 的解释学循环

#### 要点

FreeBSD 在 2011-2017 年间推动了一场“许可证纯洁化”运动，核心目标是移除系统中所有 GPL 许可的代码，用 BSD 许可的替代品替换。最显著的事件是：2011 年 GCC 发布 GPLv3 版本后 FreeBSD 决定将 Clang/LLVM（BSD 许可证）作为默认编译器纳入 base system（2012 年 FreeBSD 9.1 引入，2017 年 FreeBSD 10.0 完成默认切换）。与此同时，GDB 被 LLDB 替换，Binutils 被 ELF Tool Chain 替换。这场运动的底层问题——“什么是纯粹 BSD？”——是一个典型的解释学循环（§25）：必须预设“纯粹 BSD”的标准才能开始纯洁化，但纯洁化过程本身不断修正这一标准，使得起点与终点构成不可打破的循环。

解释学循环在许可证纯洁化中表现为三重嵌套。第一重：源代码层面——判断一段代码是否“属于 BSD”必须追溯到其上游，但上游溯源必然经过 BSD 与其他系统的交叉混血（如 FreeBSD NAS 使用 Samba 的部分数据结构）。第二重：许可证层面——BSD 二条款许可证允许商业闭源使用，若闭源派生品被“纯洁化”排除不算 BSD，则不闭源的闭源派生许可算不算？第三重：社群层面——“我们的 BSD”的社群想象与“他们的 GPL”的对立建构本身就是对历史的理解循环。1994 年 NetBSD 创始人 Chris Demetriou 在 core@ 邮件列表中与 Jordan Hubbard 的争论已经触及此问题（“我们写的是不属于任何阵营的代码，还是属于 BSD 阵营的代码？”），这意味着纯洁化运动并非 2011 年的创新，而是 BSD 社群存在伊始就内置的张力。

#### 史观

**总纲 25（解释学循环是历史认识的根本条件）**——§19 解释学 19.4 节直接追问：“当我们书写 ‘BSD’ 时，FreeBSD 5.0 是 BSD 吗？14.0 呢？历史参考的同一性本身就是形式主义的建构。” 许可证纯洁化运动将这一问题从史学层面推到工程层面：在源代码中，“BSD” 不是给定的实体而是解释的产物——一段含有 GPL 头文件 include 的 C 程序是否是纯粹的 BSD 程序？

**总纲 22（知识注定过时）**——GCC → Clang 的替换被叙述为“进步”，但 GCC 当年替代 AT&T 的 cc（C 编译器）时同样被叙述为“自由战胜专有”。2011 年 GCC 是“专制”（GPLv3 束缚），1991 年 GCC 是“解放”（GPL 对抗 AT&T 垄断）。GCC 从解放者变为压迫者是许可证纯洁化解释学循环中的关键反转。

**自反性声明**：本子节将“许可证纯洁化”建构为解释学循环案例，但本子节的解读本身也在解释学循环内——“纯洁”一词的选取本身带有对许可证立场的价值预设。本子节承认自身也是形式主义，欢迎被更自反的分析超越（27.2）。

#### 辨析

**GPLv3 vs GPLv2 的实际影响辨析**：GCC 从 GPLv2 升级至 GPLv3 引发了 FreeBSD 社群的排斥，部分二手源将之简化为“GPLv3 不让闭源闭源”—实际上 FreeBSD base system 自身的许可证允许多种使用，排除 GCC 的根本原因在于 GPLv3 的专利条款与 TiVo-化条款与 FreeBSD 社群的“非限制”立场不可调和——不是 “GPLv3 阻止闭源”而是 “GPLv3 引入的限制违背了 BSD 许可证的根本立场”。

**Clang 本身的“纯 BSD”辨析**：Clang/LLVM 项目由 Apple 主导且使用 BSD 许可证——但 Apple 是 mac OS Darwin 的闭源主要承载者。“用 Apple 的 BSD 工具替代 GNU 的 GPL 工具”——纯洁化的讽刺意味在于，纯洁化的动力来自商业利益（Apple 的投资动机之一是减少 GPL 工具的使用），BSD 社群的纯洁追求恰好配合了商业资本的利益。
