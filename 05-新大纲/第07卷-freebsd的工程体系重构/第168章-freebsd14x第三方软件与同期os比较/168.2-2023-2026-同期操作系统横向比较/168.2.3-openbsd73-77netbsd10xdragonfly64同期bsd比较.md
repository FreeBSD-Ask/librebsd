# 168.2.3 OpenBSD 7.3-7.7、NetBSD 10.x、DragonFly 6.4 同期 BSD 比较

**要点**：14.x 同期三大 BSD 都有重要进展：① **OpenBSD**：7.3（2023.4）、7.4（2023.10）、7.5（2024.4）、7.6（2024.10）、7.7（2025.4）持续半年一发的稳定节奏，重点改进安全（进一步 pledge/unveil 收紧、内核随机化）、硬件支持、WiFi 6 驱动（从 Linux 移植）、自己编写的 smtpd/httpd/bgpd/rpki-client 等基础组件持续完善；② **NetBSD 10.0**（2024.3.28）是 NetBSD 历史上重要版本，引入 ARM64 服务器支持、RISC-V 改进、内核加密框架优化、Lua 内核脚本、新的音频子系统；NetBSD 10.x 系列持续发布维护版本；③ **DragonFly BSD**：6.4（2022.12）、持续 HAMMER2 文件系统改进、SMP 性能优化、**dma(8)** 作为默认 MTA（FreeBSD 14.0 借鉴了 DragonFly 的 dma）；三大 BSD 与 FreeBSD 保持代码交流——驱动、工具、安全修复在 BSD 生态内流动，每个 BSD 都有自己的哲学侧重：OpenBSD 安全第一、NetBSD 可移植性优先、DragonFly 集群与 SMP 性能、FreeBSD 工程化与通用性

**史观**：总纲第 10 条——动手者创造历史：BSD 家族的 “多分支并行演化” 模式是开源生态中独特的存在——三个主要 BSD（加上 FreeBSD 共四个）虽然用户基数远小于 Linux，但每个分支都产生了被整个生态采纳的创新：pf 来自 OpenBSD、HAMMER/HAMMER2 来自 DragonFly、dma 来自 DragonFly 并被 FreeBSD 采用、NetBSD 的 makefs 与 rumpkernel 被 FreeBSD 借鉴；这种 “小团队探索、大生态共享” 的模式是 BSD 许可与 BSD 文化的产物

**辨析**：OpenBSD 的 WiFi 支持策略与 FreeBSD 不同——OpenBSD 也从 Linux 移植 WiFi 驱动，但对固件许可证更严格（只允许可自由再分发的固件，不允许仅允许二进制分发的限制性固件），因此支持的 WiFi 硬件范围比 FreeBSD 更窄；NetBSD 10.0 是其多年开发的重要里程碑，支持的硬件架构数量仍是所有 OS 中最多的（约 50+ 种架构），但主流服务器/桌面架构支持深度不如 FreeBSD；DragonFly BSD 是四个 BSD 中开发者最少的（通常个位数核心开发者），但在文件系统与 SMP 领域持续创新
