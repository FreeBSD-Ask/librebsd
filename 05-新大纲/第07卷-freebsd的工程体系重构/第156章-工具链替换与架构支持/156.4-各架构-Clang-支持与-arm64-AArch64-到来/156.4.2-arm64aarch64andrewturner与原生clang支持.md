# 156.4.2 arm64/AArch64：Andrew Turner 与原生 Clang 支持

**要点**：arm64（AArch64）架构在 FreeBSD 中的支持是 Clang/LLVM 迁移的重要副产品——GCC 4.2.1 完全不支持 AArch64（ARM 64 位架构在 2011 年才发布，远晚于 GCC 4.2.1 的 2007 年），因此没有 Clang 就不可能有 FreeBSD/arm64。Andrew Turner（andrew@）是 FreeBSD/arm64 移植的主要开发者，在 FreeBSD Foundation 和商业赞助商支持下完成了 arm64 支持。FreeBSD 11.0（2016.10.10）首次将 arm64 作为支持架构发布（但非 Tier 1）；FreeBSD 13.0（2021.4.13）正式将 arm64/AArch64 提升为 Tier 1 架构，与 amd64 并列获得发布镜像、二进制包、安全更新的全面支持。Clang/LLVM 对 AArch64 的原生支持（AArch64 后端由 ARM 公司和 Apple 工程师联合开发，质量极高）使 FreeBSD/arm64 从一开始就有高质量编译器支持——这与 mips/powerpc/sparc64 等旧架构在 Clang 迁移中挣扎形成鲜明对比。arm64 升为 Tier 1 标志着 FreeBSD 正式进入 64 位 ARM 服务器、云原生和嵌入式市场。

**史料**：FreeBSD 11.0/13.0 Release Notes 和 Announcement、Andrew Turner arm64 移植邮件列表公告和提交记录、FreeBSD Quarterly Status Reports arm64 章节、FreeBSD 架构支持级别页面。 ［A］

**史观**：总纲第 5 条——没有必然性，只有偶然性：Clang 原生支持 AArch64 的事实使 FreeBSD 在 ARM64 时代获得了相对于旧 GCC 生态的架构优势——新架构不必等待旧编译器（GCC 4.2.1）的移植，因为 Clang/LLVM 本身就原生支持 AArch64。这是许可证纯洁化工程的意外正面红利：摆脱了古老 GCC 的束缚后，FreeBSD 得以更快拥抱新硬件架构。

**辨析**：FreeBSD/arm（32 位 ARMv6/v7）的 Clang 支持早于 arm64，但 32 位 ARM 生态碎片化（大量不同 SoC）使其从未升为 Tier 1；arm64 因 ARM 服务器标准化（SBSA/SBBR 规范）和 Apple Silicon Mac 的推动而快速成熟。FreeBSD 13 arm64 Tier 1 后，Amazon EC2 Graviton、Ampere Altra 等 ARM 云实例正式支持 FreeBSD。
