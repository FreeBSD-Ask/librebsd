# 162.7.1 MIPS 架构降级与退役路径

**要点**：FreeBSD 13.0-RELEASE 将 MIPS 架构（包括 mips、mipsel、mips64、mips64el、mipsn32、mipselhf、mipshf、mips64elhf、mips64hf 等多种变种）从 Tier-2 降级，标志着 FreeBSD 对 MIPS 架构支持的终结过程开始；MIPS 自 FreeBSD 8.0（2009-11）起由 Oleksandr Tymoshenko、Jung-uk Kim 等开发者移植，主要用于嵌入式路由器（Atheros/Qualcomm Wi-Fi 路由器、Lantiq DSL 调制解调器）、SGI 工作站、龙芯（Loongson）处理器；MIPS 退役原因：(1) 市场份额被 ARM 大幅取代——路由器厂商逐步转向 ARM 架构；(2) 龙芯自 2020 年代起转向自主指令集 LoongArch，不再使用 MIPS；(3) Clang/LLVM 对 MIPS 后端支持长期滞后于 GCC；(4) 活跃维护者持续减少；(5) MIPS 存在多种 ABI（o32/n32/n64）和字节序变种，维护复杂度极高；FreeBSD 13.x 期间 MIPS 支持持续降级，13.4 是最后一个包含 MIPS 支持的稳定分支之一

**史料**：FreeBSD 13.0 Release Notes“Architectures”章节；freebsd-mips@ 邮件列表 Oleksandr Tymoshenko 等关于 MIPS 退役的帖子；Oleksandr Tymoshenko、Jung-uk Kim 的 MIPS 相关 commit 历史 ［A］

**史观**：BSD 与 UNIX 谱系的连续性：MIPS 是 RISC 处理器的先驱，SGI IRIX 是重要的商业 UNIX 平台；FreeBSD 对 MIPS 的支持延续了 BSD 在非 x86 架构上的传统，但市场和技术的变化使其退役成为必然

**辨析**：13.0 是 MIPS 降级而非完全移除——MIPS 代码在 13.x 源码树中仍存在但不再作为正式支持架构；MIPS 完全移除发生在 FreeBSD 14.0；与 sparc64、PC98、armv6 等退役架构类似，MIPS 退役是架构生态演化的自然结果

**文献**：FreeBSD Project. (2021). *13.0 Release Notes* (Architectures section); Tymoshenko, O. (2020-2021). freebsd-mips mailing list posts on MIPS support status. ［A］
