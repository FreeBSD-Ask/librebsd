# 150.1.5 FreeBSD2020年第四季度状态报告覆盖基金会资助的多个方向OpenZFSL

- FreeBSD 2020 年第四季度状态报告覆盖基金会资助的多个方向：OpenZFS、Linuxulator 应用兼容、LLDB 调试器、测试实验室基础设施、Wi-Fi、代码覆盖率、包工具、对用户态工具的 Capsicum 加固，以及面向 base 的宽松许可证 Git 客户端 Game of Trees；NetApp 正把其内部补丁上游化以缩小与上游的 diff，Rick Macklem 推进 NFS over TLS（内核 TLS 默认开启，预期 13.1 具备加密 NFS）。（BSD Now EP388，[76.0-143.0]，L2）
- 去 GPL 化工程在 2020 年末推进到收尾阶段：GDB 已完全移除、由 LLDB 取代，GNU grep 替换为 bsdgrep，libgnuregex 删除；尚未替代的只有 GPL 的 Dialog（无良好替代）、可选的 GCOV 内核代码覆盖率，以及由 Baptiste Daroussin 收尾的部分完成 diff3。（BSD Now EP388，[384.26-430.42]，L2）
- 随机数生成器更新：FreeBSD 11 起默认采用 Ferguson 与 Schneier 设计的 Fortuna（熵积累进多池并据此重播种）；2019 年 Ferguson 发表 Windows 10 随机数生成器设计白皮书，社区据此实现 FenestrasX——每 CPU 一个生成器构成树、消除多核读锁竞争，小请求从缓冲服务并在用后安全擦除，集成进 arc4random，已在 -current 但默认关闭，需自定义内核 RANDOM_FENESTRASX 并重建。（BSD Now EP388，[593.74-739.5]，L2）
- PF 与路由查找的性能优化：Christoph 用 HWPMC 工具定位到 PF 对每包、每字节做 64 位计数导致多核 cache 抖动，将计数器替换为内核 counter 框架，并把 PF 规则的用户态配置结构与内核评估结构解耦；Alexander（melifaro）引入 FIB lookup 框架，可按路由数量在 Bsearch4、Radix4 lockless 与 DPDK 的 LPM4 之间动态选择，8 条路由时 Bsearch 达约 6900 万 pps，70 万条全量路由时 LPM 达约 4600 万 pps。（BSD Now EP388，[745.82-955.22]，L2）
- PFBadHost 是 Undeadly 介绍的安全脚本：定期从 Spamhaus、FireHOL、Emerging Threats、Binary Defense 等源拉取恶意 IP 列表，写入 PF 表并以规则拦截进出流量；部署时创建无登录 shell、空口令的专用用户，仅授 doas 执行最小命令集，cron 定时刷新并可邮件报告拦截数量（示例中一度拦截 6.2 亿地址），支持按 AS 号、国家、Tor 节点与出口节点分别处理。（BSD Now EP388，[1432.88-1753.88]，L2）
- Bastille 的端口重定向以 pf.conf 的 rdr 锚点、外部接口与 bastille0 环回接口三要素实现：`bastille rdr` 子命令把宿主机端口转发到 jail 的 TCP/UDP 端口，规则写入 rdr.conf 并随 jail 重载与重启持久化，也可在模板中自动化定义，从而把防火墙配置复杂度收敛进单一工具。（BSD Now EP388，[1755.02-1934.8]，L2）
- 词源考据梳理 Unix 工具命名：awk 取自 Alfred Aho、Peter Weinberger、Brian Kernighan 姓氏首字母；grep 源自 ed 的 g/re/p 命令；ping 由 Mike Muuss 取声呐回响之义（他厌恶 Packet Internet Groper 之类的反推词源）；sudo 是 superuser do 的拼接；vi 是 Bill Joy 1976 年为 ex 编写的 visual interface，而 ex 又是 ed 的扩展；tar 即 tape archiver；finger 得名于用手指扫过登录名单；fortune 首现于第 7 版 Unix、仿照中餐馆签语饼。（BSD Now EP388，[2282.24-2624.62]，L2）
- GhostBSD 21.01.15 发布说明：清理默认包（移除 LibreOffice 与 Telegram）以使 ZFS 只读 live 文件系统可在 4GB 内存机器运行，移除安装器的 UFS full disk 选项（仍可自定义分区），修复自定义分区 next 按钮限制与默认 locale，加入 Linux Steam 默认配置并升级 refined EFI 引导管理器以改善 UEFI 双启动。（BSD Now EP388，[2624.62-2748.94]，L2）
- 节目介绍 Brian Kernighan 关于 Unix 诞生的 45 分钟以上 CMU 访谈（附全文转写与视频）：访谈回溯 60 年代末至 70 年代初贝尔实验室构建 Unix 的语境，被主持人定位为面向史学读者的优质一手来源。（BSD Now EP388，[2749.7-2796.58]，L2）
- 本期核心访谈由 FreeBSD 开发者 Conrad 讲解加密内核崩溃转储：威胁模型覆盖两类对象——可能物理接触转储设备的攻击者，以及企业内不应接触转储的运维人员；实现上由 dumpOn 在用户态生成一次性 AES 密钥并以 RSA 公钥加密后送入内核，内核生成初始化向量并构建密钥调度以 CBC 模式加密转储，多次转储之间以 SHA-256 哈希链替换 IV 防止重用，savecore 检测转储头中的密钥标记后另存密钥文件，decryptcore 再以 RSA 私钥还原会话密钥解出内存映像，且 dumpOn 与 decryptcore 均运行于 Capsicum capability mode；全量转储与各架构小型转储已支持，文本转储因 CBC 模式下头部尺寸须回写而暂缓，下一步拟在 ARM64、MIPS、SPARC 等实机上征集测试。（BSD Now EP184，[2731.60-3365.90]，L1）[订正：原 savecore 沙箱化、原 [2731.60-2993.58]，2026-09-30 SenseAudio 重转核对]
- Christos Zoulas 在 NetBSD 基金会博客宣布 amd64 与 sparc64 已可完全可复现构建：同一源码树能产出逐位相同的 CD 镜像；实现依赖 build.sh 便携式交叉构建系统自带全套工具链，从源头规避宿主工具版本差异，并须逐一驯服时间戳、时区与区域设置、并行构建导致的文件顺序、GPT 分区全局唯一标识符、地址空间随机化与嵌入二进制的构建路径等非确定性来源；作者明言借鉴 Debian 社区的可复现构建测试平台与 diffoscope 二进制差分工具，并致谢 build.sh 的历届维护者，后续目标覆盖全部平台与无特权构建。 [存疑脚注] 博主姓名转写为“Christos Zolas”，致谢名单中的“Jörg Sonnenberg”“Thomas Clausen”“Todd Verling”“Luke Muburn”均为失真转写，引用前须以 NetBSD 基金会博客原文核对。（BSD Now EP184，[702.04-1410.10]，L2）[订正：原 [702.04-1318.92]，2026-09-30 SenseAudio 重转核对]
- OpenBSD 开发者 Bob Beck 报告 LibreSSL 进展：大数库中的常量时间函数被统一改为始终使用安全的常量时间模式以缓解时序侧信道；随后对 SSL/TLS 结构体实施大规模私有化、收缩公开 API 并改用访问器，与 OpenSSL 下一版本的结构封装方向殊途同归，短期内造成 ports 回归并回退了部分过于激进的条目；同期还有 ftp 客户端与镜像选择 CGI 的修复、安装器 TLS 支持以及新增的 OCSP 装订命令行工具。 [存疑脚注] “jsing”“rpe”为开发者句柄且转写杂糅，OCSP 工具的作者归属在转写中前后混叠，引用前须以 LibreSSL 提交记录核证。（BSD Now EP184，[560.44-684.88]，L2）
- 2015 年 5 月末，FreeBSD 的 Linux 兼容层（Linuxulator）64 位支持由开发者长期维护的用户分支以约 200 个提交合并进 head，64 位 Linux base ports 的提交预期赶在 BSDCan 2015 完成，64 位兼容端口不能与 32 位并存但自带 32 位兼容层；社区同时讨论 pkg 未来直接对接 yum 仓库以摆脱逐 RPM 手工解包的现状，而 Steam 在 FreeBSD 上仍因缺失 futex 相关系统调用无法运行，移植以增量补齐系统调用的方式推进。（BSD Now EP91，[344.84-569.38]，L2）
- PC-BSD 10.1.2 发布热修复版，修正 RAIDZ 安装中 cache 与 log 设备名解析及 TrueOS 文本安装器在 UEFI 模式下的分区问题；同期 Lumina 桌面 0.8.4 随该版本发布，以 Qt5 从零编写、不依赖 DBus、PolicyKit、ConsoleKit、SystemD、HAL 等桌面框架，文件管理器内建 ZFS 快照与目录回滚概念，项目计划以自研窗口管理器替代 Fluxbox，动机包括 4K 显示器下的界面与字体缩放及全局键盘快捷键统一，且已可移植至多种 Linux 发行版等非 FreeBSD 平台。（BSD Now EP91，[2702.44-2925.40]，L2）
- DragonFly BSD 在 fstab 中引入 crypt 挂载选项，以一次性随机密钥自动加密交换分区，master 分支已默认启用但因低内存与高换页场景未测而仍标实验性；主持人对照指出 FreeBSD 在设备名后加 .eli 后缀即可实现类似的单次 geli 密钥交换加密，OpenBSD 则早已默认加密交换分区——内存换页中可能残留口令与密钥的敏感性问题构成各系统共同动机。（BSD Now EP90，[533.34-724.08]，L2）
- Delphix 将可恢复复制与 VDEV 移除两项特性开源，计划数周内进入 illumos 并经 OpenZFS 汇流，Linux 侧跟进节奏取决于上游治理；Allan Jude 以跨互联网复制数百吉字节的 PC-BSD 包数据集为例说明中断续传的实际价值——2015 年 ZFS 生态呈现 Delphix 研发、illumos/OpenZFS 汇聚、各平台再分发的分层结构。 [存疑脚注] 转写将 illumos 失真为 Lumos 等专名，系依 OpenZFS 治理语境恢复，平台流向表述以语义推断为准（BSD Now EP90，[1822.10-1946.12]，L2）[订正：原 失真清单为 Lumos、3DSD，2026-09-30 SenseAudio 重转核对]
- Michael W. Lucas 自述 FreeBSD Mastery: Storage Essentials 的成书动机：自 Absolute FreeBSD 之后，FreeBSD 存储栈经历了 CAM 层接管设备命名、默认分区方案转向 GPT 等重大变化，需要一次自底向上的连贯文档更新；该书从 CAM 与 GEOM 的 provider/consumer 堆叠讲起，对 UFS/FFS 做深度剖析，并论证 UFS 在许多场景仍是恰当工具，而体量庞大的 ZFS 留待单独成书。（BSD Now EP68，[1803.65-1936.66]，L1）
- 本期新闻聚合呈现 2014 年末 BSD 生态的多线动态：OpenSMTPD 自 OpenBSD 5.6 起成为默认邮件传输代理，sendmail 将于 5.7 完全移除，并发布邮件过滤 API 草案；OpenBSD 自研 httpd 于 5.6 首秀，以特权分离、默认 chroot 与近乎自然语言的配置语法获得早期用户好评；FreeBSD 的 opencrypto 框架在 FreeBSD Foundation 与 Netgate 赞助下加入 AES-ICM/GCM 模式与 AES-NI 支持，修复了一处可伪造消息的时序信息泄露，部分代码借自 OpenBSD 与 NetBSD。（BSD Now EP68，[3695.95-4047.35]，L2）
- Justin Cormack 阐明 rump kernel 之构造：自 NetBSD 内核剥离广义驱动（自文件系统驱动至网络栈），覆以最小虚拟化层，进程与内存管理等困难部分转借宿主环境，叠加 libc 后即得近乎完整之 POSIX 用户态，成为可运行真实应用的轻量用户态虚拟机，令 NetBSD 代码几乎可运行于任何环境；其核心用例为驱动开发与测试——用户态 IPv6 协议栈可原样移植供缺乏协议栈之系统直接复用，用户态 PCI 层使网卡驱动可在用户态编写、崩溃后重置设备即可续跑，持续集成测试每小时于多平台运行，Minix 社区亦有意借用 NetBSD 驱动以充实其微内核框架。（BSD Now EP64，[2724.34-2984.22]，L1）
- Cormack 自述个人路径：早年在 MIT 初遇 UNIX 与 X 窗口终端，此后任系统管理员涉猎 Solaris 与 Linux，因 FOSDEM 年会接触 NetBSD 并对其测试文化产生兴趣；适逢语言可直接运行于 hypervisor 之设想（Erlang on Zen、Mirage 等先例），遂以 rump kernel 对接 Xen hypercall 驱动自带之迷你操作系统环境，交叉编译 NetBSD libc 并将系统调用陷阱替换为 rump kernel 调用，使 Lua 得以直接运行于 Xen 且通过 NetBSD 测试套件；此工作促成其于 2014 年初成为 NetBSD 开发者。（BSD Now EP64，[2518.82-2626.96]，L1）
- FreeBSD 10.1 于 2014 年 11 月 14 日发布，距 10.0 约十一个月，升级路径刻意保持平滑；主要特性包括新 VT 控制台（支持 Intel 与 AMD 显卡加速显示）、amd64 平台 UEFI 引导（暂仅限 UFS）、GELI 口令缓存使多盘加密 ZFS 阵列仅需输入一次口令、ARMv6 SMP 支持、bhyve 大量更新（含根 ZFS 引导与 32 位 FreeBSD 客户机）、Geom 层直接 IO 分发与 zvol 新增 volmode 属性等，属 10.x 稳定分支首个点版本。（BSD Now EP64，[740.02-960.88]，L2）
- FreeBSD Foundation 获其史上最大单笔捐款——WhatsApp 首席执行官捐赠一百万美元；其社交平台自述称少年时为贫困移民学生，课余自学 FreeBSD，由此进入 Yahoo 专职 FreeBSD 工作，后创立 WhatsApp 仍持续使用 FreeBSD，故以捐款回馈；主持人进而说明基金会之 501(c)(3) 地位受 IRS 公众支持测试约束，若资金过度集中于少数企业将沦为行业团体而丧失慈善资格，故基金会更看重经常性小额捐赠以保证预算可预期。（BSD Now EP64，[3342.66-3509.48]，L2）
- 访谈给出 Capsicum 沙盒化的应用谱系：Robert Watson 在披露 SysTrace 漏洞后设计能力框架，FreeBSD 最早落地案例之一是 gzip——man 页常由 root 查看且需解压不可信输入；此后 tcpdump、dhclient、fetch 等相继沙盒化，受访者称社区自 1975 年起反复尝试促使开发者正确处理不可信输入，并打算为其承袭 OpenSSH 代码的 CGI 库补齐 Capsicum 支持（BSD Now EP63，[2231.95-2325.62]，L2）
- FreeBSD 随机数设备经历大重构：沿用多年的 Yarrow（Bruce Schneier 参与设计）基本止步，由 Mark Murray 等依 Ferguson、Schneider、Kohno 的《Cryptography Engineering》实现 Fortuna 替代，做成可加载模块并预留可插拔熵源接口，熵采集新增 UMA 内存分配器来源（默认关闭），经安全官与 Warner Losh、Robert Watson、Edward Napierala 等评审后提交，计划在 11-CURRENT 转为默认（BSD Now EP63，[672.12-855.64]，L2）
- 嘉宾（结合 ZFS 移植、GELI、casper、auditdistd 等工作可辨认为 FreeBSD 提交者 Pawel Jakub Dawidek，转写讹作 Dodek）自述移植缘起：少年时自 Amiga 直接转用 FreeBSD，后经在波兰电信业任职的朋友偶然谈及 Sun 正在开发、具备多数据集、端到端校验、压缩与集成卷管理的新文件系统，遂起意亲手移植；彼时 FreeBSD 除 UFS 外，HFS、ReiserFS、XFS 等移植皆未竟或只读，UFS2 仅属有限改良。他自述“十天十夜几乎不停编码”即得可读写原型（587.77-595.77），其后又历时数月方达可提交状态。（BSD Now EP62，[483.69-624.77]，L1）
- 技术路径上，受访者归纳移植可行的三重条件：ZFS 代码整洁且多数可在用户态编译，Sun 侧为可移植性投入充分；FreeBSD 与 Solaris 内核 API 相近程度远超 FreeBSD 与 Linux；他自建的 Solaris 兼容层虽自嘲“不甚体面”（692.05-701.13），却将本方改动与上游差异压至最小，得以跟上 Sun 时期 ZFS 的高速迭代。最大障碍在 VFS 层集成——他称其为内核中最复杂、充满“隐秘知识”的部分（744.45-747.29），并以亲身体验解释此前多次文件系统移植失败之因；FreeBSD VFS 代劳缓冲等事务的设计，对 ZFS 这类自带缓冲策略与文件区间锁的复杂文件系统反而构成掣肘。（BSD Now EP62，[650.77-853.73]，L1）
- GELI 一节系其一手叙述：因早期 ZFS 加密不合需求，他另写位于文件系统之下的磁盘加密 GEOM 类，特色包括软件内数据认证（以存储空间为代价校验数据完整性）、自始集成 OpenCrypto 框架以利用硬件加速与 AES-NI，以及多密钥解锁——口令、U 盘密钥文件等可并用；他举例企业场景中安全官另持主密钥，雇员遗失密钥亦不致数据不可恢复。同类方案他点名 TrueCrypt 与 Linux 自有实现。 [存疑脚注] 受访者提及 macOS 已出现同类块级加密方案处转写残损（Mac OS 10 502），具体所指待核。（BSD Now EP62，[1015.53-1152.29]，L1）
