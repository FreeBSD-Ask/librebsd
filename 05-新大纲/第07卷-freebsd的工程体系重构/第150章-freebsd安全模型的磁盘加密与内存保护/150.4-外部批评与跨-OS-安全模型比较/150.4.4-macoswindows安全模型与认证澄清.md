# 150.4.4 macOS/Windows 安全模型与认证澄清

**要点**：FreeBSD 与 macOS/Windows 安全模型对比及关键认证澄清：(1) macOS——Apple macOS 基于 Darwin（FreeBSD + Mach 混合内核），XNU 内核中的 MAC 框架源自 FreeBSD TrustedBSD，衍生为 Seatbelt（App Sandbox）；System Integrity Protection（SIP/rootless，OS X El Capitan 10.11，2015）限制 root 用户修改系统文件和内核扩展，类似 FreeBSD securelevel 但更细粒度；macOS 持有 Common Criteria 认证，但这是 macOS 产品认证，与 FreeBSD 上游无关；(2) Windows——Windows 安全模型以 NT ACL、Mandatory Integrity Control（MIC）、Windows Defender、UAC、Patch Tuesday、AppContainer 沙箱等为核心，与 FreeBSD 架构差异极大；(3) 重要澄清——FreeBSD 项目本身从未持有 FIPS 140、Common Criteria、UNIX 03、FedRAMP 等形式认证；Apple macOS、TrueNAS、NetApp ONTAP、Juniper Junos、Sony PlayStation OS 等产品基于或衍生自 FreeBSD，但这些产品的安全认证是产品级认证，不是 FreeBSD 操作系统本身持有认证

**史料**：Apple Platform Security 指南（support.apple.com/guide/security/）；XNU 源码中 MAC/Seatbelt 实现（Apple Open Source 仓库）；Microsoft Windows 安全文档；Common Criteria 认证产品查询页面；The Open Group UNIX 认证目录 ［A］

**史观**：专题语（不设总纲条号）——企业研究双重性：FreeBSD 作为 BSD 许可的通用操作系统，被多家商业公司作为产品基础，但这些公司的安全认证和加固通常不回馈到 FreeBSD 上游——Apple 将 MAC 框架衍生为 Seatbelt 但大量改动为私有；Juniper、NetApp 使用 FreeBSD 作为网络/存储设备基础但内核改动多为私有；这是宽松许可证的 “代价”——公司可以自由使用和修改，但无义务回馈

**辨析**：“macOS 是 FreeBSD 所以 macOS 的安全就是 FreeBSD 的安全”——这是极其常见的误解；macOS/Darwin 仅在用户层和部分 API 层面源自 FreeBSD，XNU 内核是 Mach + FreeBSD 紧密混合，安全机制（SIP、Seatbelt、Code Signing、Notarization、Secure Enclave）均为 Apple 私有技术；“FreeBSD 没有 Common Criteria 认证所以不安全”——CC 认证是过程/文档认证，不是安全性的直接度量；OpenBSD 也没有 CC 认证，但被普遍认为是最安全的通用 OS 之一

**文献**：Apple Inc. Apple Platform Security. support.apple.com/guide/security/; Apple Inc. XNU Source Code (opensource.apple.com); The Open Group. Common Criteria Portal. commoncriteriaportal.org; The Open Group. UNIX Certification Directory. opengroup.org. ［A］
