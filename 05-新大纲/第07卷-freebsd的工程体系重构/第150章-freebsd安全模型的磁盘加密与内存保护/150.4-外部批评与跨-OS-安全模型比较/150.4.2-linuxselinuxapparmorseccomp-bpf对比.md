# 150.4.2 Linux SELinux/AppArmor/seccomp-bpf 对比

**要点**：FreeBSD 与 Linux 安全机制对比：(1) MAC 框架——FreeBSD TrustedBSD MAC（2003，多模块并行，默认不启用）vs Linux LSM（2003，最初单模块，后支持堆叠；SELinux 默认于 RHEL/Fedora，AppArmor 默认于 Ubuntu/SUSE）；(2) 沙箱/能力——FreeBSD Capsicum（2012，对象能力模型，cap_enter+ 能力 fd）vs Linux seccomp-bpf（2012，系统调用过滤，BPF 程序白名单）；(3) 进程隔离——FreeBSD **jail(8)**+VNET（2000/2008）vs Linux namespaces+cgroups（2008+，LXC/Docker 基础）；(4) 内存保护——OpenBSD W^X（2003）最早，FreeBSD/Linux 后续跟进；(5) 默认安全——OpenBSD 最激进（大量安全加固默认启用），FreeBSD 中间（提供机制但默认保守），Linux 因发行版差异大（RHEL 默认 SELinux，Ubuntu 默认 AppArmor，部分发行版默认禁用 MAC）；Apple macOS 的 Seatbelt（App Sandbox）和 XNU 内核的 MAC 框架源自 FreeBSD TrustedBSD——罗伯特·N. M. 沃森（Robert Watson）本人参与了 Apple 的 MAC 框架移植工作

**史料**：**mac(4)** vs **security_modules(7)** 手册页；**capsicum(4)** vs **seccomp(2)** 手册页；**jail(8)** vs **namespaces(7)** 手册页；Cowan C et al. Linux Security Modules (USENIX Security 2002); Watson et al. Capsicum (USENIX Security 2010) ［A］

**史观**：总纲第 8 条——本体论上各方平等：Linux 和 FreeBSD 安全模型的分化是两个社区文化差异的系统体现——Linux 安全机制更多由安全公司和发行版厂商驱动（NSA 贡献 SELinux、Novell/SUSE 贡献 AppArmor、Chrome 团队推动 seccomp-bpf），FreeBSD 安全机制更多由学术研究和个人开发者驱动（TrustedBSD/DARPA/剑桥/Capsicum）；Linux 路径获得了更大的工业部署（Android、RHEL、云原生生态），FreeBSD 路径在安全研究界有更大影响力（Capsicum 影响 WASI、CHERI 影响硬件安全）——两条路线各有其存在场域，无高下之分

**辨析**：“Linux 比 FreeBSD 安全” 或反之——简单比较没有意义，取决于具体版本、配置、使用场景；“SELinux 是 MAC 框架”——SELinux 是 LSM 的一个安全策略模块（实现 FLASK/TE 模型），非框架本身，类似 FreeBSD 的 mac_mls+mac_biba 等模块而非 **mac(4)** 框架本身；seccomp-bpf 与 Capsicum 技术路线完全不同——前者是系统调用号白名单/过滤器，后者是对象能力系统

**文献**：Cowan C et al. Linux Security Modules (USENIX Security 2002); Watson et al. Capsicum (USENIX Security 2010); FreeBSD/Linux manual pages. ［B］
