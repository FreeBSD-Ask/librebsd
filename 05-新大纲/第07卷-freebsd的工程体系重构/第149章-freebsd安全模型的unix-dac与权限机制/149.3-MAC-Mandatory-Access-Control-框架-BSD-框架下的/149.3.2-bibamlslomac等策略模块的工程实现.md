# 149.3.2 Biba/MLS/LOMAC 等策略模块的工程实现

**要点**：FreeBSD 5.0 及后续版本包含多个 MAC 策略模块，各模块用途与引入时间如下：**mac_biba(4)** 实现 Biba 完整性模型（低水标完整性策略，防止低完整性数据污染高完整性对象），随 MAC 框架在 FreeBSD 5.0 引入；**mac_mls(4)** 实现多级安全（Multi-Level Security，MLS）保密性模型（Bell-LaPadula 模型，基于敏感度标签控制信息流），FreeBSD 5.0 引入；**mac_lomac(4)** 实现 Low-Watermark 完整性策略（LOMAC，与 Biba 类似的浮动标签模型），FreeBSD 5.x 引入；**mac_bsdextended(4)**（即 ugidfw）实现基于文件系统 UID/GID 的扩展 ACL 规则，通过 **ugidfw(8)** 工具管理，FreeBSD 5.x 引入；**mac_ifoff(4)** 提供接口防火墙功能（可动态禁用网络接口）；**mac_partition(4)** 将进程分区到独立的 process view（进程只能看到同分区其他进程）；**mac_portacl(4)** 实现端口 ACL（控制哪些用户/组可绑定到特定端口号）；**mac_seeotheruids(4)** 隐藏其他 UID 的进程（类似 Linux hidepid 选项）；**mac_none(4)**/**mac_stub(4)**/**mac_test(4)** 为测试/占位模块

**史料**：各 MAC 策略模块手册页（**mac_biba(4)**、**mac_mls(4)**、**mac_lomac(4)**、**mac_bsdextended(4)**、**mac_portacl(4)**、**mac_seeotheruids(4)**、**mac_partition(4)** 等）；FreeBSD src/sys/security/ 目录各模块源码（mac_biba.c、mac_mls.c、mac_lomac.c、mac_bsdextended.c 等）；FreeBSD 5.x-7.x Release Notes 关于 MAC 模块的记录；**ugidfw(8)** 手册页 ［A］

**史观**：总纲第 23 条——社区治理：MAC 策略模块的多样化反映了 FreeBSD 安全社区对 “安全无万能方案” 的共识——不同场景需要不同安全模型：军事/政府场景需要 MLS（保密性），完整性保护场景需要 Biba/LOMAC，简单服务器加固场景需要 mac_seeotheruids/mac_portacl 等轻量级模块；但这也导致 MAC 框架在通用服务器场景中配置复杂度高、默认不启用，与 OpenBSD pledge/unveil 的 “默认安全” 哲学形成对比

**辨析**：mac_bsdextended（ugidfw）常被误认为是 ACL 实现，但它是 MAC 策略模块而非文件系统 ACL——FreeBSD 的 POSIX.1e ACL 支持通过 UFS/ext2fs/ZFS 等文件系统的扩展属性实现（**getfacl(1)**/**setfacl(1)**），ugidfw 是基于 MAC 框架的补充性规则引擎；“MLS 模块可直接用于军用分级环境” 说法不准确——mac_mls 提供 MLS 机制，但完整的高保证认证需要形式化验证、审计文档、Covert Channel 分析等大量配套工作，FreeBSD 本身未经过 Common Criteria EAL4+ 或更高等级认证
