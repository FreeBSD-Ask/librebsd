# 149.3.1 MAC 框架的核心数据结构与策略接口

**要点**：TrustedBSD MAC（Mandatory Access Control）框架由 罗伯特·N. M. 沃森（Robert Watson）发起，项目始于 2000 年，作为 DARPA CHATS（Composable High Assurance Trusted Systems）研究项目的一部分，首次在 FreeBSD 5.0-RELEASE（2003 年 1 月）中正式发布；MAC 框架是内核模块化安全策略框架，允许加载多个安全策略模块并通过策略组合（composition）实现复杂安全目标；核心数据结构包括 **mac(4)** 框架定义的 `mac_t` 标签结构（挂接到 inode、proc、socket、mbuf、ipq 等内核对象上）、策略模块的入口点向量（entry points，覆盖系统调用路径上的权限检查点）、标签管理 API（**mac_get(3)**/**mac_set(3)** 等用户态接口）；框架设计允许策略模块以可加载内核模块（KLD）形式动态加载/卸载，无需重新编译内核

**史观**：密码学：MAC 框架是 FreeBSD 对 TCSEC（Orange Book，橘皮书）B 级安全要求的回应——橘皮书 B1 级要求强制访问控制（MAC）支持，MAC 框架的设计直接参考了 TCSEC B1/B2 级和 Common Criteria 的要求；但 FreeBSD 从未以获得 TCSEC/CC 认证为目标——框架提供机制（mechanism）而非策略（policy），具体安全策略由可加载模块实现，这与 NSA 主导的 SELinux 将策略与框架深度绑定的设计形成对比

**辨析**：“TrustedBSD MAC 框架是 FreeBSD 版的 SELinux” 说法过于简化——SELinux 最初是 NSA 为 Linux 设计的 FLASK/TE 安全架构，移植到 FreeBSD 时作为 MAC 框架的一个策略模块（mac_flask），而非 MAC 框架本身；MAC 框架比 LSM（Linux Security Modules）更早起步（2000 年 vs LSM 2001-2003 年合入 Linux 2.6），但 Linux LSM 因 SELinux 的广泛采用而更受关注；MAC 框架默认不启用任何策略模块，这与许多 Linux 发行版默认启用 SELinux/AppArmor 的做法不同；[双库核查：2026-08-14] 本节要点“MAC 框架由 Robert Watson 发起、首次在 FreeBSD 5.0-RELEASE（2003 年 1 月）正式发布”经参考文献库验证通过（检索词“TrustedBSD”命中 reference_id=521《The TrustedBSD MAC Framework: Extensible Kernel Access Control for FreeBSD 5.0》，2003，作者 Robert Watson，与要点一致）；邮件列表库检索“MAC framework”未命中 2000-2003 年设计讨论（命中多为 2020s 季度状态报告），该时期设计讨论细节两库无法验证，保留
