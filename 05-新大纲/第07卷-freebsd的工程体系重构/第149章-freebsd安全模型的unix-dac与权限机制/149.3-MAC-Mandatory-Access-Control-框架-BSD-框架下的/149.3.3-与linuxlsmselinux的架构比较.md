# 149.3.3 与 Linux LSM/SELinux 的架构比较

**要点**：FreeBSD TrustedBSD MAC 框架与 Linux LSM（Linux Security Modules）在架构上有相似之处——两者均为内核安全钩子框架，允许加载不同安全策略模块；关键差异包括：(1) 设计起点——MAC 框架由 Watson 为 FreeBSD 从头设计（2000 年启动），LSM 由 Crispin Cowan 等人设计以将 SELinux 接入 Linux 主线（2001 年 LSM 补丁，Linux 2.6 正式合入）；(2) 策略组合——MAC 框架原生支持多策略模块并行加载与组合（MAC Policy Composition），LSM 在早期版本要求排他性加载单模块，直到 Linux 5.x 后才通过 stacking 改进；(3) 默认策略——FreeBSD GENERIC 内核包含 MAC 框架但默认不加载任何策略模块，主流 Linux 发行版（RHEL/CentOS/Fedora、Ubuntu 等）默认启用 SELinux 或 AppArmor；(4) 标签存储——MAC 框架标签可存储在文件系统扩展属性或内存中，SELinux 依赖 xattr 存储安全上下文；Apple macOS 的 Seatbelt（App Sandbox）和 XNU 内核的 MAC 框架源自 FreeBSD TrustedBSD——罗伯特·N. M. 沃森 本人参与了 Apple 的 MAC 框架移植工作

The TrustedBSD MAC Framework (BSDCan 2004 演讲)；Apple XNU 源码中 MAC 框架痕迹（XNU 是 Darwin/macOS 内核，基于 FreeBSD 和 Mach）；Wright C et al. Linux Security Module Framework [C]. USENIX Security 2002

**史观**：总纲第 6 条——技术路线分化：MAC 框架与 LSM 的分化是 FreeBSD 与 Linux 安全哲学差异的缩影——FreeBSD 倾向于 “提供机制而非策略”（mechanism, not policy），让用户/管理员选择是否启用安全模块；Linux 则倾向于 “默认启用合理安全配置”，以 SELinux/AppArmor 作为默认安全层；这一分化可追溯至两个社区的文化差异：BSD 强调用户选择权与系统最小化，Linux 强调开箱即用与安全加固默认值

**辨析**：“Apple macOS 基于 FreeBSD 所以持有 FreeBSD 的安全认证” 说法是常见误解——macOS/Darwin 确实使用了 FreeBSD 的用户层组件和 TrustedBSD MAC 框架（衍生为 Seatbelt sandbox），但 macOS 作为独立操作系统单独持有 Common Criteria 认证（如 macOS 12 Monterey CC 认证），这些认证与 FreeBSD 本身无关；FreeBSD 项目本身从未持有 FIPS 140、Common Criteria、UNIX 03、FedRAMP 等形式认证，基于 FreeBSD 的产品（如 Apple macOS、TrueNAS、NetApp ONTAP、Juniper Junos、Sony PlayStation OS）的认证是产品级认证而非 OS 上游认证
