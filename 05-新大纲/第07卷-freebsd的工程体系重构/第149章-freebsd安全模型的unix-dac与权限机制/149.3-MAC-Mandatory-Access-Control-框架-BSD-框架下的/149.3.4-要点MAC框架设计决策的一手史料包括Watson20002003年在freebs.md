# 149.3.4 要点MAC框架设计决策的一手史料包括Watson20002003年在freebs

**要点**：MAC 框架设计决策的一手史料包括：Watson 2000-2003 年在 freebsd-arch@ 和 trustedbsd-discuss@ 邮件列表的设计讨论；FreeBSD 5.0 Early Adopter's Guide 中 MAC 章节；Watson 2003 年 USENIX ; login: 文章 “TrustedBSD MAC Framework”；Watson 2012 年剑桥博士论文详细记录框架演进过程；MAC 框架源码中各模块的初始 commit 记录；可信来源包括 TrustedBSD 项目官方文档、Watson 作为作者和维护者的论文/演讲、FreeBSD 官方手册与 Release Notes

**史料**：FreeBSD 邮件列表存档 lists.freebsd.org/archives/freebsd-arch/（2000-2003 年 MAC 框架设计讨论）；TrustedBSD 项目文档 trustedbsd.org/mac/；Watson 2003 ; login: 文章；Watson 2012 博士论文第 5 章；FreeBSD SVN commit 历史（src/sys/security/mac/ 目录） ［A］

**史观**：总纲第 3 条——形式主义膨胀：MAC 框架在 FreeBSD 5.0 中标记为 experimental（实验性），FreeBSD 5.x 系列是 “New Technology” 预览系列（5.0-5.5），生产环境用户普遍停留在 FreeBSD 4.x stable 分支直到 FreeBSD 6.0（2005 年 11 月）发布；MAC 框架在 FreeBSD 6.x/7.x 中逐步成熟，但始终未成为默认启用的安全层——这与 MAC 框架本身的设计哲学一致：为高安全需求场景提供工具，而非强制所有用户承担配置复杂度

**辨析**：原大纲本节列入 “CVE-2002-0639” 和 “CVE-2024-6387” 等 OpenSSH 漏洞作为 MAC 框架史料系模板错误，这些漏洞与 MAC 框架无直接关联，已删除；原文献列表中 “Qualys 2024 regreSSHion”、“Lucas 2018 FreeBSD Mastery: Storage Essentials” 等与 MAC 框架无关文献已删除，替换为 MAC 框架专属一手文献；“TrustedBSD 是 NSA 项目” 说法不准确——NSA 是 TrustedBSD 项目资助方之一（通过 DARPA/SPARTA 等渠道），同时也资助了 SELinux，但 TrustedBSD 由 Watson 在社区主导开发

**文献**：Watson R N M. The TrustedBSD MAC Framework: Extensible Kernel Access Control for FreeBSD 5.0 [J]. ; login:, 2003, 28(4); FreeBSD Project.
