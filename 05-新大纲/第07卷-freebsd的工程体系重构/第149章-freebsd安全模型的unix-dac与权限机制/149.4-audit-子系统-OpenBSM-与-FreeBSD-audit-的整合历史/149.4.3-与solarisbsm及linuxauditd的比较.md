# 149.4.3 与 Solaris BSM 及 Linux auditd 的比较

**要点**：三种审计系统的架构比较如下：(1) FreeBSD/OpenBSM vs Solaris BSM——OpenBSM 在 API 和日志格式层面兼容 Solaris BSM，支持大部分 BSM 事件类和令牌类型，但实现完全独立（BSD 许可 vs Solaris 原 CDDL 许可）；Solaris 作为 BSM 的发源地，在 Oracle Solaris 11 中持续扩展审计功能，包括 ZFS 审计标签、Solaris Zones 审计等高级特性；(2) FreeBSD OpenBSM vs Linux auditd——Linux auditd 由 Steve Grubb 等人开发（2005 年前后进入 Linux 主线），使用自定义的 audit 日志格式而非 BSM 格式，通过 **auditctl(8)** 配置规则，框架分为内核 audit 子系统、auditd 守护进程、audispd 插件分发层；FreeBSD OpenBSM 采用标准 BSM 格式，配置通过 **audit_control(5)** 文件而非运行时规则引擎；(3) 共同目标——三者均旨在满足 TCSEC/Common Criteria 审计要求，记录安全相关事件供事后分析，但 Linux auditd 在现代发行版中更常默认启用，FreeBSD auditd 默认关闭

**史料**：FreeBSD **audit(4)**/**auditd(8)** 手册页；Solaris **audit(1M)**/**auditd(1M)** 手册页；Linux **auditd(8)**/**auditctl(8)** 手册页；OpenBSM 文档关于 Solaris 兼容性说明；Linux Audit Project 官方页面 people.redhat.com/sgrubb/audit/ ［A］

**史观**：总纲第 6 条——技术路线分化：审计系统的分化体现了 UNIX 世界“标准化 vs 创新”的张力——BSM 审计格式作为 1990 年代的标准，被 FreeBSD/macOS 采用以保持互操作性；Linux 选择重新设计 audit 框架以更好地与 Linux 内核特性（LSM、cgroups、namespaces）集成；FreeBSD 选择 BSM 也与其与 Sun 的历史渊源有关——Sun 是 BSD 4.x 的早期商业采用者，FreeBSD 从 KAME 项目获得 IPv6/IPsec、从 OpenBSD 获得 OpenSSH/PF，从 Sun 获得 BSM 审计思想，体现了 BSD 家族内部以及与 System V 世界的技术交流

**辨析**：“BSM 审计比 Linux audit 更安全”或反之的说法缺乏依据——审计系统的安全性取决于实现质量、配置正确性和日志保护机制，而非格式选择；三者均存在过审计绕过或日志注入漏洞；“macOS 审计与 FreeBSD 审计完全相同”说法不准确——Apple 虽然基于 OpenBSM，但已添加大量 macOS 特有事件类和私有扩展；【man 交叉复核·OpenBSM 审计命令 man 页稀疏检出缺口】**auditd(8)**、**auditreduce(1)**、**praudit(1)** 等命令 man 页未在本地稀疏检出范围内（contrib/openbsm/man/ 已就位，audit(4) 与 audit.2 HISTORY 段确认 OpenBSM 由 McAfee Research 受 Apple 委托于 2004 年创建，但 auditd.8/auditreduce.1/praudit.1 等命令 man 页本地不可读），本节 auditd(8)/auditreduce(1)/praudit(1) 的功能描述方向正确但无法从 man 源直接验证 AUTHORS/HISTORY 段，详见考据记录 20260723_man-cross-verification-round1.md 条目 14
