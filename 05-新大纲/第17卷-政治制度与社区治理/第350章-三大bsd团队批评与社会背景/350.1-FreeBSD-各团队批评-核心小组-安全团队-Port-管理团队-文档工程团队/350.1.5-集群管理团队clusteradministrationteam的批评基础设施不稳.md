# 350.1.5 集群管理团队（Cluster Administration Team）的批评：基础设施不稳定、服务中断频发与透明度不足

  **要点**：FreeBSD 集群管理团队（Cluster Administration Team，简称 clusteradm）负责运维 FreeBSD 项目的基础设施（包括 git 仓库、邮件列表、Bugzilla、CI 系统、镜像站、www 站点等），长期面临以下批评——基础设施不稳定，邮件列表、Bugzilla、CI 系统等服务中断频发，影响开发效率；服务中断后的通报不及时、不透明，用户往往通过社交媒体才得知服务故障，官方公告滞后数小时甚至数天；基础设施升级计划缺乏公开讨论，部分升级（如 SVN 转 Git、Bugzilla 迁移）过程中出现意外宕机；镜像站管理不善，部分镜像同步延迟高、部分地区镜像覆盖不足；集群管理团队成员数量少，长期由少数志愿者承担运维工作，响应能力受限
  **史料**：FreeBSD 基础设施服务中断记录（邮件列表 downtime 通知、状态页面历史）；clusteradm 邮件列表存档（公开部分）；SVN 转 Git 期间的服务中断记录；镜像站同步状态监控数据；用户对基础设施的投诉与反馈 ［A］
  **史观**：总纲第 13 条——法律与道德是利益分配（原“经济历史哲学”系伪名目，存疑），基础设施运维资源不足是社区经济基础薄弱的反映；总纲第 19 条——解释学循环是历史认识的根本条件（原“历史解释学与权力”系自撰名目，正名），服务中断通报不透明是权力运作的微观呈现
  **辨析**：“服务中断频发”须与其他开源项目（如 Linux、Apache、Mozilla）的基础设施可用性横向比较；集群管理团队人手不足是事实还是借口须基于运维工作量统计；镜像站问题的责任——clusteradm vs 各镜像站管理员须区分
  **文献**：FreeBSD 状态页面历史；clusteradm 邮件列表存档；基础设施服务中断公告；镜像站监控数据 ［A］
