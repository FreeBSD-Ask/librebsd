# 355.4.2 2016年3月packagingbase正式发出测试召集用户检出SVN的rele

- 2016 年 3 月 packaging base 正式发出测试召集：用户检出 SVN 的 release-package 分支（Git 镜像同步），以 build world、build kernel 加 make packages 三步在 obj 目录生成 pkg 仓库，再以 pkg install -g freebsd-* 注册覆盖既有系统；访谈中 Brad Davis 描述其愿景“打个包升级，十分钟后回来就完事了”（2305.76-2314.88），并确认目标是在 11.0 使其成为默认形态（3263.98-3267.98）。（BSD Now EP133，[3010.9-3086.1]，L2）[订正：原 [3022.10-3071.42]，2026-09-30 SenseAudio 重转核对]
- 11.0 前夜多线并进：Haswell 图形支持随 DRM 与 i915 驱动更新至 Linux 3.8.13 后落地 -current，开发者铺设 shim 以便直接跟进上游并已着手 3.9（898.18-941.06）；Konstantin Belousov 发布首个基础 ASLR 补丁，按 ABI 启用、限原生 i386 与 AMD64，并致谢 HardenedBSD 的 Oliver Pinter 与 Sean Webb（3779.36-3855.00）；FreeBSD 10.3-RC2 回退了引发 ZFS 挂起的 VFS 改进与 fast forwarding 代码，OpenSSH CVE-2016-3115 修复仍在等待；pfSense 发布含 iCAP 代理与 IPv6 透明代理等更新的点版本。 [存疑脚注] 转写将 pfSense 失真为 open senses、Konstantin Belousov 失真为 Konstantin Blausov、-current 失真为 previous D，专名已按上下文校正。（BSD Now EP133，[898.18-931.06]，L2）
- OpenBSD VMM/VMD：BeehiveCon 已从 bhyve 专题扩展为覆盖全 BSD 虚拟化的会议；VMM 缘起 2015 年布里斯班 hackathon，经 OpenBSD Foundation 资助后夏秋持续推进（1128.18-1143.54）；设计取舍上不移植 bhyve——两者工作量相当，而 OpenBSD 想要的恰是 bhyve 明确放弃的旧硬件与 i386 支持、嵌套虚拟化（1150.62-1195.82）；路线图含 nested VMX、AMD SVM、文件系统透传、仿 ZFS 语法的 vmctl send/receive 在线迁移、QEMU 加速与 KVM 兼容接口使 OpenStack 类工具免改造可用（1287.26-1334.34）；Reyk Floeter 重写 VMD 与 vmctl 以贴合 OpenBSD 工具风格（1249.21-1262.34）。 [存疑脚注] 转写将 bhyve 失真为 Beehive、Reyk Floeter 失真为 Reich Floiter，已按上下文校正。（BSD Now EP133，[1128.18-1143.54]，L2）
- Brad Davis 的贡献路径：2003 年经友人引荐，三个月内把家中 12 台机器从 Linux 全面换为 4.x 时代的 FreeBSD；在卫星流媒体公司值夜班期间创办基于 FreeBSD 的虚拟主机公司，为回馈项目自修 ports 补丁起步，因 ports 过于活跃“轮不到被注意”转投文档；首次申请 docs commit bit 被 doceng 以“我没有足够的新增内容”（1657.36-1661.84）否决——二三十个 PR 全是修复，后经 BSDCan 与 doceng 成员线下结识而获准；此后持 ports bit，进入集群管理与 postmaster 团队再退任，转向 pkg 打包与 RaspBSD。（BSD Now EP133，[1494.0-1689.7]，L1）[订正：原 [1494.24-1681.84]，2026-09-30 SenseAudio 重转核对]

**史观**：

- 总纲4 分离聚合是永恒规律：base 系统的打包化呈现为一次分离聚合的循环：统一的 base 分发被分离为 700 余个细粒度包（debug、lib32、profiling 与逐个共享库各自成包以便最小化依赖），又经计划的 meta 包 FreeBSD-base 重新聚合以降低安装负担；安全更新周转由自建 freebsd-update 服务器的数天缩至 Jenkins 上一小时级（2772.36-2777.06）——形态在不同聚合度之间流转，工程上“分离以便取舍、聚合以便安装”的权衡反复出现，而非能力意义上的线性进步。 [存疑脚注] 史观映射为编者对当期访谈素材的方法论提炼，非当事人陈述。（BSD Now EP133，[3143.6-3188.9]，L4）[订正：原 [3161.82-3186.26]，2026-09-30 SenseAudio 重转核对]
- 总纲10 动手者创造历史：本期人物史由动手者构成：Brad Davis 从夜班操作员、文档修复者到 packaging base 主力；Glen Barber 以发布工程师身份承担仓库签名；Brian Drewry 在 head 清理构建系统，使错误在 build world 阶段即被投诉而不必等 pkg 反馈；Kirk 等人处理 ZFS 挂起回退（3589.19-3602.28）；而决定 commit bit 命运的关键竟是一次线下会议的当面接触——机制在此承认了动手者的在场价值，面向听众的公开招募“Docs needs help”（1609.07-1610.40）亦提示贡献入口的开放。 [存疑脚注] 史观映射为编者对当期访谈素材的方法论提炼，非当事人陈述；转写仅作 Kirk 的当事人按语境指 Kirk McKusick。（BSD Now EP133，[1525.3-1619.8]，L4）[订正：原 [1546.52-1619.00]，2026-09-30 SenseAudio 重转核对]
