# 354.2.6 chflags 与 flags 传统：BSD 文件标志扩展与 even root cannot modify 保证

  **要点**：chflags(1) 与文件标志（file flags）自 4.4BSD（1994 年）引入；BSD 文件标志扩展传统 Unix 权限模型，包含 uchg（user immutable，用户不可变标志）、schg（system immutable，系统不可变标志）、uappnd（user append-only）、sappnd（system append-only）、uunlnk/sunlnk（不可删除/重命名）、nodump（dump 命令跳过）等；chflags(1) 命令用于设置/清除标志；FreeBSD、NetBSD、OpenBSD、DragonFly BSD 均支持 chflags；chflags 是 BSD 对 Unix 文件权限的关键扩展，与 securelevel 配合实现 “even root cannot modify” 的安全保证
  **史料**：FreeBSD chflags(1) man page（<https://man.freebsd.org/cgi/man.cgi?query=chflags&sektion=1&format=html>，访问 2026-07-27）；NetBSD chflags(1) man page（<https://man.netbsd.org/chflags.1>，访问 2026-07-27）；OpenBSD chflags(1) man page（<https://man.openbsd.org/chflags.1>，访问 2026-07-27） ［A］
  **史观**：总纲第 9 条——经验优先，chflags 是工程实践的具体沉淀，每个标志（uchg、schg、uappnd、sappnd 等）皆源于实际安全需求；总纲第 4 条——分离聚合是永恒规律，chflags 从 4.4BSD 聚合至四大 BSD 分支，是分离聚合律的具体显现；总纲第 7 条——理论必须自反，本子节作为 chflags 传统的考据叙事，自身亦嵌入 “even root cannot modify 即安全善” 的前理解，须自觉呈现这一前理解；总纲第 8 条——本体论上各方平等，BSD chflags 与 Linux chattr 在本体论上地位相等，差异仅是一刻状态的不同；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，“chflags 与 securelevel 配合实现 even root cannot modify 的安全保证” 等文化意义叙事是史家基于当下史料的形式主义建构
  **辨析**：考据过程留痕——【查证来源】FreeBSD chflags(1) man page 经 man.freebsd.org 一手核验；NetBSD chflags(1) man page 经 man.netbsd.org/chflags.1 一手核验；OpenBSD chflags(1) man page 经 man.openbsd.org/chflags.1 一手核验；【交叉验证方法】chflags 标志清单（uchg、schg、uappnd、sappnd、uunlnk、sunlnk、nodump）须以四大 BSD man page 互证；chflags 与 securelevel 的配合关系须以 chflags(1) man page 与 init(8) man page 互证；【0 信任原则·“4.4BSD 1994 年引入”】“chflags(1) 与文件标志（file flags）自 4.4BSD（1994 年）引入” 的考据须以 4.4BSD 源码或 man page 核验，本考据以既有学术文献为间接依据；【0 信任原则·标志清单完整性】“uchg、schg、uappnd、sappnd、uunlnk/sunlnk、nodump” 的标志清单完整性须以四大 BSD chflags(1) man page 实际样本核验，本考据以既有 man page 为依据；【与同类 UNIX/BSD 习俗对比】Linux 有 chattr + lsattr（ext2/ext3/ext4 文件系统属性），概念相似但实现独立；BSD chflags 跨文件系统统一（UFS、FFS、ZFS 等均支持）；illumos 与 Solaris 无类似文件标志机制；【自反性声明】本子节作为 chflags 传统的考据叙事，自身嵌入 “even root cannot modify 即安全善” 的前理解，实际 chflags 的工程价值（如与文件系统兼容性、与容器化的冲突）须以多源交叉验证逼近史实
