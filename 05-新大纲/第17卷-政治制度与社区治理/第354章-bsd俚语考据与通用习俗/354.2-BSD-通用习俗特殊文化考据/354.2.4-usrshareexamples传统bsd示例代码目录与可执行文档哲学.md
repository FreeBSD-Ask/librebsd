# 354.2.4 /usr/share/examples/ 传统：BSD 示例代码目录与可执行文档哲学

  **要点**：/usr/share/examples/ 目录自 4.4BSD（1994 年）起成为标准；FreeBSD、NetBSD、OpenBSD、DragonFly BSD 均继承此传统；BSD 系统在 /usr/share/examples/ 下提供大量配置与代码示例，含 /etc 配置示例（如 pf.conf 示例）、csh/sh 脚本示例、make 示例、kernel 配置示例等；此传统延续 Unix “示例即文档” 哲学；所有 BSD 系统仍维护 /usr/share/examples/ 目录；示例目录是 BSD 文档体系的重要补充，与 man page 共同构成 “可执行文档”
  **史料**：FreeBSD hier(7) man page（<https://man.freebsd.org/cgi/man.cgi?query=hier&sektion=7>，访问 2026-07-27）；NetBSD hier(7) man page（<https://man.netbsd.org/hier.7>，访问 2026-07-27）；OpenBSD hier(7) man page（<https://man.openbsd.org/hier.7>，访问 2026-07-27） ［A］
  **史观**：总纲第 9 条——经验优先，/usr/share/examples/ 目录的内容是工程实践的具体沉淀，每个示例（pf.conf 示例、kernel 配置示例等）皆源于实际工程需求；总纲第 4 条——分离聚合是永恒规律，/usr/share/examples/ 从 4.4BSD 聚合至四大 BSD 分支，是分离聚合律的具体显现；总纲第 7 条——理论必须自反，本子节作为 /usr/share/examples/ 传统的考据叙事，自身亦嵌入 “示例即文档善” 的前理解，须自觉呈现这一前理解；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，“示例目录与 man page 共同构成可执行文档” 等文化意义叙事是史家基于当下史料的形式主义建构
  **辨析**：考据过程留痕——【查证来源】FreeBSD hier(7) man page 经 man.freebsd.org 一手核验；NetBSD hier(7) man page 经 man.netbsd.org/hier.7 一手核验；OpenBSD hier(7) man page 经 man.openbsd.org/hier.7 一手核验；【交叉验证方法】/usr/share/examples/ 目录的内容清单须以四大 BSD 实际系统目录与 hier(7) man page 互证；示例的演化（4.4BSD 1994 至今）须以各 BSD 版本 release notes 互证；【0 信任原则·“4.4BSD 1994 年起成为标准”】“/usr/share/examples/ 目录自 4.4BSD（1994 年）起成为标准” 的考据须以 4.4BSD 源码或 hier(7) man page 核验，本考据以既有学术文献为间接依据；【0 信任原则·示例内容覆盖度】“含 /etc 配置示例、csh/sh 脚本示例、make 示例、kernel 配置示例等” 的内容覆盖度须以四大 BSD 实际系统 /usr/share/examples/ 目录样本核验，本考据以定性观察为依据；【与同类 UNIX/BSD 习俗对比】Linux 发行版有 /usr/share/doc/ 但 /usr/share/examples/ 不如 BSD 标准化；illumos 与 Solaris 有类似但不完全相同的示例目录传统；【自反性声明】本子节作为 /usr/share/examples/ 传统的考据叙事，自身嵌入 “示例即文档善” 的前理解，实际 /usr/share/examples/ 的工程价值（如示例的时效性、与 man page 的重复度）须以多源交叉验证逼近史实
