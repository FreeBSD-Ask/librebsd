# 354.2.3 BSD make 与 GNU make 区别传统：bsd.*.mk 宏文件与 /usr/share/mk/ 共享工程

  **要点**：BSD make 宏文件传统自 4.4BSD（1994 年）确立，包括 bsd.prog.mk（程序构建）、bsd.lib.mk（库构建）、bsd.man.mk（man page 安装）、bsd.dep.mk（依赖关系）、bsd.subdir.mk（子目录递归）等；BSD make（pmake）与 GNU make（gmake）语法差异显著——BSD make 使用 ${VAR} 与 .include 指令，GNU make 使用 $(VAR) 与 include 指令；BSD make 依赖系统定义的宏文件（位于 /usr/share/mk/）简化 Makefile 编写；FreeBSD ports 框架基于 bsd.port.mk，是 BSD make 工程应用的巅峰；FreeBSD、NetBSD、OpenBSD、DragonFly BSD 均保留 /usr/share/mk/ 宏文件传统；pkgsrc 在非 NetBSD 平台使用 bmake 替代 make，NetBSD 官方文档明确 "use the bmake command instead of ‘make’ to run NetBSD make, which is required for correct pkgsrc operation"
  **史料**：NetBSD pkgsrc 文档（<https://www.netbsd.org/docs/software/packages.html>，访问 2026-07-27，原文 "Note that when using pkgsrc on a non-NetBSD system, use the bmake command instead of ‘make’ to run NetBSD make, which is required for correct pkgsrc operation"）；FreeBSD Porter's Handbook（<https://docs.freebsd.org/en/books/porters-handbook/>，访问 2026-07-27） ［A］
  **史观**：总纲第 9 条——经验优先，bsd.*.mk 宏文件是工程实践的具体沉淀，每个宏文件（bsd.prog.mk、bsd.lib.mk 等）皆源于实际构建需求而非预先设计的理论框架；总纲第 4 条——分离聚合是永恒规律，BSD make 从 GNU make 分离，形成 BSD 独有的宏文件聚合，是分离聚合律的具体显现；总纲第 7 条——理论必须自反，本子节作为 BSD make 与 GNU make 区别传统的考据叙事，自身亦嵌入 “简洁即工程善” 的前理解，须自觉呈现这一前理解；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，“bsd.*.mk 宏文件是 BSD 工程简洁性的体现” 等文化意义叙事是史家基于当下史料的形式主义建构
  **辨析**：考据过程留痕——【查证来源】NetBSD pkgsrc 文档经 netbsd.org/docs/software/packages.html 一手核验，确认 “use the bmake command instead of ‘make’ to run NetBSD make” 表述；FreeBSD Porter's Handbook 经 docs.freebsd.org/en/books/porters-handbook/ 一手核验；【交叉验证方法】bsd.*.mk 宏文件清单与演化须以 4.4BSD 源码、各 BSD 项目 /usr/share/mk/ 目录、FreeBSD Porter's Handbook 三源互证；BSD make 与 GNU make 语法差异须以同 Makefile 在 pmake 与 gmake 下的执行差异互证；【0 信任原则·“4.4BSD 1994 年确立宏文件传统”】“BSD make 宏文件传统自 4.4BSD（1994 年）确立” 的考据须以 4.4BSD 源码 /usr/share/mk/ 目录核验，本考据以既有学术文献为间接依据；【0 信任原则·宏文件清单完整性】“bsd.prog.mk、bsd.lib.mk、bsd.man.mk、bsd.dep.mk、bsd.subdir.mk” 的清单完整性须以各 BSD 项目 /usr/share/mk/ 目录实际样本核验，本考据以既有学术文献为依据；【与同类 UNIX/BSD 习俗对比】Linux 发行版主要使用 GNU make 与 autotools；BSD make 因简洁性被部分跨平台项目（如 pkgsrc）选用；illumos 与 Solaris 使用 Sun make，与 BSD make 与 GNU make 形成三方对照；【自反性声明】本子节作为 BSD make 与 GNU make 区别传统的考据叙事，自身嵌入 “简洁即工程善” 的前理解，实际 BSD make 宏文件的工程代价（如跨平台移植性、与现代构建系统如 CMake、Meson 的兼容性）须以多源交叉验证逼近史实
