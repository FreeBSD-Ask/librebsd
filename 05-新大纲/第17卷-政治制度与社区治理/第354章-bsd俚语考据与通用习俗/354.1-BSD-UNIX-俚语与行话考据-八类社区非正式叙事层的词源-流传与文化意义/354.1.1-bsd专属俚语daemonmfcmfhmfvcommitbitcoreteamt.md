# 354.1.1 BSD 专属俚语：daemon、MFC/MFH/MFV、commit bit、core team、tainted code 与 BSD is dying 梗

  **要点**：BSD 专属俚语承载 BSD 项目长期形成的工程传统与社区身份认同，核心词条覆盖守护进程术语、分支合并约定、提交权限角色、子树治理结构与 recurring 梗五类。daemon 一词据 Jargon File 4.4.7 版本（ESR 维护，`catb.org/jargon/html/D/daemon.html`）原文确证源自物理学家 James Clerk Maxwell 1867 年思想实验中的“麦克斯韦妖”（Maxwell's Demon），后由 MIT CTSS（Compatible Time-Sharing System）团队引入计算领域，原型为名为 DAEMON 的自动磁带备份程序，发音为 /dee'mon/；BSD Daemon 吉祥物形象由 John Lasseter（后任 Pixar 首席创意官）为 4.3BSD-Tahoe 发行绘制，版权由 Marshall Kirk McKusick（马歇尔·柯克·麦库西克） 持有，名为“beastie”而非“Chuck”（Walnut Creek CDROM 公司某位广告人员编造的传言经 McKusick 个人站点 `mckusick.com/beastie/` 澄清）。MFC（Merge From Current）、MFH（Merge From Head）、MFV（Merge From Vendor）缩写源于 1990 年代中后期的分支管理实践（freebsd.duckdb 实测含 MFC 的 commit 最早为 1996-11-12，2000 年前已 5,200 条；“MFC after”字段则 2001-05-08 方首现）〔原“4.x 时代起源”断言已按库内证据分层订正〕，从 -CURRENT 合并至 -STABLE 的操作须在 commit message 中标注 MFC，FreeBSD Committer's Guide（`docs.freebsd.org/en/articles/committers-guide/`）记载分支约定"Noteworthy src/ Git Branches: stable/n (n-STABLE), main (-CURRENT)"，MFC after 字段在 2026 年 7 月仍为 FreeBSD src 仓库活跃使用的 commit message 标准字段（经 `cgit.freebsd.org/src/log/?qt=grep&q=MFC+after` 一手核验）。commit bit 一词源于 BSD 项目早期使用 CVS（Concurrent Versions System）时通过服务器端配置文件中的“commit bit”（一位二进制标志位）启用提交权限，FreeBSD Committer's Guide 第 4 章“Commit Bit Types”原文记载 FreeBSD 将 commit bit 分为 src（srcmgr@）、doc（doceng@）、ports（portmgr@）三类。NetBSD 自 2024 年 5 月修订 Commit Guidelines 起明确将 LLM 生成代码视为 tainted code（被污染的代码），未经 core 书面批准不得提交，原文经互联网档案馆存档版本核验"Code generated by a large language model or similar technology, such as GitHub/Microsoft‘s Copilot, OpenAI’s ChatGPT, or Facebook/Meta's Code Llama, is presumed to be tainted code“。”BSD is dying"是 BSD 社区内外反复出现的 recurring 梗，无单一源头，每隔数年在 BSD 重大事件时重新出现，BSD 社区对此梗的态度从早期的严肃反驳逐渐演变为自嘲与解构
  **史料**：Jargon File 4.4.7 版本 daemon 词条全文（`catb.org/jargon/html/D/daemon.html`，原文"[from Maxwell's Demon, later incorrectly retronymed as ‘Disk And Execution MONitor’] A program that is not invoked explicitly, but lies dormant waiting for some condition(s) to occur. ... The term daemon was introduced to computing by CTSS people (who pronounced it /dee'mon/) and used it to refer to what ITS called a dragon; the prototype was a program called DAEMON that automatically made tape backups of the file system."，经一手核验）；Marshall Kirk McKusick 个人站点 beastie 页（`mckusick.com/beastie/`，原文"All drawings and images in this set of web-pages are Copyright by Marshall Kirk McKusick“与”Contrary to a myth first started by some advertising droid at Walnut Creek, the daemon's name is NOT Chuck ... If you insist on a name, call him beastie."，经一手核验）；FreeBSD Committer's Guide 第 4 章 Commit Bit Types（`docs.freebsd.org/en/articles/committers-guide/#committer.types`，原文"When FreeBSD commit bits are allocated, the areas of the tree where the bit may be used are specified."，经一手核验）；FreeBSD 项目管理页面（`freebsd.org/administration/`，Core Team、Documentation Engineering Team、Ports Management Team、Source Management Team、Release Engineering Team 角色定义，经一手核验）；NetBSD Commit Guidelines（互联网档案馆 2024 年存档版本，原文"Do not commit tainted code to the repository. ... Salus（彼得·H·萨卢斯）《The Daemon, the Gnu and the Penguin》（2007，开放出版，BSD daemon 起源与 BSD 文化史背景参照）［A］
  **史观**：专题语（不设总纲条号）——文化历史哲学（原挂总纲第 7 条系自创名目，删条号），词源考的真正意义不在还原“原义”而在揭示“语义层积”的过程，daemon 从 Maxwell's Demon（1867 物理思想实验）→ CTSS DAEMON 程序（1960s MIT 计算领域引入）→ BSD Daemon 吉祥物（1988 Lasseter 绘制）的跨域迁移是语义层积的典型呈现；总纲第 13 条——法律与道德是利益分配，BSD Daemon 版权由 McKusick 个人持有是文化符号私有化的利益分配，commit bit 三类分权（src/doc/ports）是子树治理权限的利益分配，NetBSD tainted code 政策是代码来源可追溯性的利益分配；总纲第 19 条——解释学循环是历史认识的根本条件（原“解释学循环与权力知识共谋”系增衍名目，正名），“BSD is dying”梗的传播渠道非对称性（Linux 阵营多渠道 vs BSD 阵营 `freebsd-advocacy` 邮件列表 2022-2024 年共 7 条消息，经 `lists.freebsd.org/archives/freebsd-advocacy/` 一手核验）是权力知识共谋的具体显现；总纲第 21 条——革命与改革，MFC 约定是 BSD“改革性”分支管理传统的延续，与 Linux“革命性”重构形成对照；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，本节作为 BSD 专属俚语考据的审视本身是历史小说，史家须自觉呈现自身的哲学设定
