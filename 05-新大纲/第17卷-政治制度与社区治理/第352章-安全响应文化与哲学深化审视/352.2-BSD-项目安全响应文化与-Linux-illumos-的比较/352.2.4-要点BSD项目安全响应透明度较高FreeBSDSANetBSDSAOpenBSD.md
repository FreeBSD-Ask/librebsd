# 352.2.4 要点BSD项目安全响应透明度较高FreeBSDSANetBSDSAOpenBSD

  **要点**：BSD 项目安全响应透明度较高——FreeBSD-SA、NetBSD-SA、OpenBSD errata 均为公开档案，漏洞披露后修复 commit 直接进入公开仓库；Linux kernel security team 采用半透明机制——敏感漏洞在修复前通过私密邮件列表协调，修复后公开发布 CVE 与补丁；illumos 透明度最低——无统一 SA 公告体系，各发行版自行披露；freebsd.duckdb 查询显示 freebsd-src CVE commit 1791 条、netbsd-src 1301 条、openbsd-src 165 条、dragonfly-src 122 条、illumos-gate 无 CVE commit（22 条 ZFS 路径 commit 中无 CVE 编号引用），反映 illumos 社区对 CVE 编号引用习惯的缺失
  **史料**：四大 BSD 官方 SA 公告存档、Linux kernel security team 工作流程文档、illumos 各发行版安全公告页面、freebsd.duckdb CVE commit 查询结果（freebsd-src 1791 条、netbsd-src 1301 条、openbsd-src 165 条、dragonfly-src 122 条、illumos-gate 0 条 CVE commit）、互联网档案馆 illumos 历史存档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L1 代码/构建产物〕
  **史观**：边缘者贡献，BSD 公开 SA 档案体现社区参与透明度；社区与文明历史哲学，安全响应透明度是社区文明的反映
  **辨析**：illumos-gate 0 条 CVE commit 是否反映其漏洞稀少或 CVE 引用习惯缺失需查 illumos 邮件列表存档（本研究未发现 illumos 统一 CVE 引用规范）；Linux kernel security team 半透明机制是否延缓了漏洞披露需查历史案例（如 2014 年 Heartbleed 协调过程）；BSD 公开 SA 档案的完整性需逐条核对（DragonFly VSA 官方页面 404，须以邮件列表存档与数据库提取构建索引）；详见考据记录 20260722_bsd-cve-vulnerability-fact-check-第十二卷.md
