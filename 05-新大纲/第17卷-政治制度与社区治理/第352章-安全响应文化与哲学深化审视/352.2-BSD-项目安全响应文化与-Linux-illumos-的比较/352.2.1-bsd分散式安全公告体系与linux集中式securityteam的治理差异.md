# 352.2.1 BSD 分散式安全公告体系与 Linux 集中式 security team 的治理差异

  **要点**：四大 BSD 各自维护独立的 Security Advisory 公告体系——FreeBSD-SA（713 条，1996-2026）[2026-08-15 双库核查：资料数据库.duckdb freebsd_sa 表 COUNT=713，最早 1996-04-20，最晚 2026-06-30]、NetBSD-SA（289 条，1998-2026）、OpenBSD errata（563 条，1996-2026）、DragonFly VSA（166 条 CVE，2003-2024，官方页面 404 须以邮件列表存档补全）；Linux kernel 由 Linux kernel security team（私密邮件列表 <security@kernel.org>）集中协调，2024 年 1 月 Linux kernel 正式成为 CNA（CVE Numbering Authority）可自主分配 CVE 编号；freebsd.duckdb L7.3.1 查询显示 2020 年 Linux kernel 90,911 commits、4,864 contributors，BSD 四大 src 合计 36,392 commits、574 contributors，Linux 贡献者量级为 BSD 的 8.5 倍，但 BSD 项目以更小的人力规模维持独立的 SA 公告体系，反映其“小而精”的安全响应文化
  **史料**：MITRE CNA 列表（cve.mitre.org 2026-07-22 直接访问确认 Linux kernel 自 2024-01 起 as CNA，CNA ID MITRE-CNA-LFN，scope Linux kernel source code；FreeBSD、OpenBSD、NetBSD、DragonFly 均不在 CNA 列表）、FreeBSD Security Advisories 官方存档、NetBSD Security Advisories 官方存档、OpenBSD errata 官方页面、Linux kernel security team 官方页面（kernel.org 2026-07-22 直接访问确认 <security@kernel.org> 为私密邮件列表，含 CVE 编号申请流程文档）、freebsd.duckdb L7.3.1（BSD 4 大 src 与 Linux kernel commit 量与贡献者对比，36 行结果）［A］
  **史观**：经济历史哲学，BSD 分散式 SA 体系是社区自治传统的产物，Linux 集中式 security team 是企业赞助规模化的产物；总纲第 4 条——分离与聚合，BSD 4 项目虽同源 CSRG 但 commit 量分布已统计显著分化；社区与文明历史哲学，安全响应文化的差异是社区组织形态的反映；延续与终结，freebsd-src 与 netbsd-src 在 commit 量分布上无统计显著差异印证二者延续 CSRG 工程节奏的相近性，openbsd-src 与 dragonfly-src 则在 commit 量分布上与他者显著分化；统计结论印证：统计结论 [E-21] NVD FreeBSD 相关 CVE 421 个（1999-2026）、统计结论 [E-22] NVD OpenBSD 相关 CVE 143 个[2026-08-15 双库核查：资料数据库.duckdb nvd_cve_metadata 表 bsd_projects=openbsd COUNT=143]、统计结论 [E-23] NVD NetBSD 相关 CVE 82 个[2026-08-15 双库核查：资料数据库.duckdb nvd_cve_metadata 表 bsd_projects=netbsd COUNT=82，原文 136 不准确，存疑确认]、统计结论 [E-24] NVD DragonFly BSD 相关 CVE 1 个、统计结论 [E-25] FreeBSD 官方安全公告 FreeBSD-SA 382 条（2008-04 至 2026-06-30）、统计结论 [E-26] FreeBSD 平均 CVSS 6.24、统计结论 [E-27] OpenBSD 平均 CVSS 6.17、统计结论 [E-28] NetBSD 平均 CVSS 5.50 共同构成 BSD 4 项目 CVE 与 CVSS 全量基准——BSD 4 项目 NVD CVE 合计 678 个（421+143+82+1[2026-08-15 双库核查重算]，去重前）反映 BSD 分散式 SA 体系的量化基础，FreeBSD 以 421 个 CVE 与 382 条 SA 居 BSD 4 项目之首印证其 “实际遵守但未缴费认证” 的合规路径，OpenBSD 以 143 个 CVE（NVD 2026-08-15 核查）与 563 条 errata 印证其主动代码审计文化（errata 数量超过 CVE 数量反映审计发现 vs 外部披露的差异），DragonFly BSD 仅 1 个 CVE 反映 NVD CPE 命名不完整而非实际漏洞稀少；CVSS 跨项目对照（FreeBSD 6.24 > OpenBSD 6.17 > NetBSD 5.50）不直接等同于安全响应质量差异，须结合各项目 SA 发布周期与回溯补丁覆盖率综合判断；freebsd.duckdb L7.3.1 查询显示 2020 年 Linux kernel 90,911 commits、4,864 contributors，BSD 四大 src 合计 36,392 commits、574 contributors 作为旁证；统计结论 [C-16] 4 个 BSD 项目 src 仓库月度 commit 量分布的 Kruskal-Wallis H 检验（共同时间窗口 2003-06 至 2026-07，总样本量 n = 1112 月即 4 仓库 × 278 月，组数 k = 4）显示 H = 763.399, df = 3, p <0.001（3.75 × 10⁻¹⁶⁵），效应量 η²=0.6863 属大效应（η² > 0.14 为大效应），拒绝 H₀ 即 4 仓库月度 commit 量分布存在统计显著差异，组间差异解释约 68.63% 的总方差，与 L7.3.1 所示 BSD 4 项目 commit 量级分化相互印证；统计结论 [C-17] Dunn‘s 事后比较（Bonferroni 校正，α’= 0.05/6 = 0.0083）进一步显示 6 组两两比较中 5 组统计显著（p < 0.0083），唯独 freebsd-src ↔ netbsd-src 不显著（p = 1.000），二者在 2003-2026 共同窗口内 commit 量分布相近（均值 1183 vs 1566，中位数 1156 vs 1450），而 freebsd-src ↔ openbsd-src（p = 2.75 × 10⁻²⁵）、freebsd-src ↔ dragonfly-src（p = 5.70 × 10⁻¹²⁰）、netbsd-src ↔ openbsd-src（p = 1.48 × 10⁻²⁸）、netbsd-src ↔ dragonfly-src（p = 4.95 × 10⁻¹²⁷）、openbsd-src ↔ dragonfly-src（p = 9.09 × 10⁻³⁷）均统计显著——此为 BSD 4 项目 “同源多速” 分化格局的统计证据，freebsd-src 与 netbsd-src 因延续 CSRG 早期工程节奏（commit 粒度、release 周期）而分布相近，openbsd-src 因 1996 年 fork 后强调主动审计与小颗粒 commit 而 commit 量显著低于前二者，dragonfly-src 因 2003 年 fork 后社区规模萎缩而 commit 量进一步显著低于前三者
  **辨析**：[2026-08-15 双库核查] FreeBSD-SA 713 条（1996-2026）经资料数据库.duckdb freebsd_sa 表直接 COUNT 验证；NVD CVE 各项目数量经 nvd_cve_metadata 表 bsd_projects 字段 GROUP BY 验证：FreeBSD 421、OpenBSD 143、NetBSD 82、DragonFly 32；原大纲 FreeBSD-SA 705/OpenBSD 168/NetBSD 136 已修正。Linux kernel 成为 CNA 后其 CVE 编号分配速度是否优于 BSD 须以 2024 年后数据对比；BSD 项目是否曾集体申请成为 CNA 需查 MITRE 历史申请档案；Linux kernel security team 的私密邮件列表机制是否削弱了漏洞响应透明度存在社区争议；【0 信任原则·commit 量不等于安全响应深度】L7.3.1 commit 量与贡献者数量对比反映开发规模差异，不直接等同于安全响应质量，须结合 SA 公告发布周期、CVE 修复滞后时间、回溯补丁覆盖率等指标综合判断；【0 信任原则·CVE 数量不等于漏洞数量】统计结论 [E-21]/[E-22]/[E-23]/[E-24] NVD CVE 数量受 NVD CPE 命名完整性影响（DragonFly BSD 仅 1 个 CVE 为 CPE 命名缺失而非实际漏洞稀少），且 CVE 披露存在滞后与选择偏差，726 个 CVE 仅为 NVD 收录部分，不等于 BSD 4 项目实际漏洞总量；【0 信任原则·SA 公告统计口径】统计结论 [E-25] 382 条 FreeBSD-SA 为官方存档计数（2008-04 至 2026-06-30），部分早期 SA 可能已归档或合并，数据须与 freebsd-security 邮件列表存档交叉验证；【0 信任原则·CVSS 跨版本不可直接比较】统计结论 [E-26]/[E-27]/[E-28] 平均 CVSS 含 CVSS v2 与 v3 混合评分，跨版本评分不可直接算术平均，该均值为近似指标，且跨项目 CVSS 均值差不直接等同于安全响应质量差异；【0 信任原则·共同时间窗口限制】统计结论 [C-16]/[C-17] Kruskal-Wallis H 检验与 Dunn's 事后比较仅采用 2003-06 至 2026-07 共同窗口（278 月）以对齐 4 仓库，丢弃了 freebsd-src/netbsd-src 的 1993-2003 早期数据与 openbsd-src 的 1995-2003 早期数据，早期数据可能反映 BSD 项目初创期的差异；【0 信任原则·分布形状假设】Kruskal-Wallis 检验假设各组分布形状相似，实际 4 仓库的标准差差异极大（netbsd-src σ = 973 vs dragonfly-src σ = 112），可能违反假设，须结合描述性统计的正态性检验结果复核；【0 信任原则·commit 粒度变化】CSRG 时代倾向大颗粒 commit、现代 BSD 强调原子化小 commit，commit 计数的时间序列在 1990s 与 2020s 之间不可直接比较，C-16/C-17 的统计显著差异可能部分源于 commit 粒度变化而非纯粹的工程节奏分化；【0 信任原则·SVN-to-Git 迁移失真】FreeBSD 仓库 2008 年 CVS→SVN、2020 年 1 月 SVN→Git 迁移可能压缩历史 commit、重写作者字段或丢失原始时间戳，导致 commit 量分布失真，C-16/C-17 结论须结合 Task 6 变点检测（freebsd-src 变点 1999-08 非 2020-01 SVN-to-Git 迁移期）交叉验证；【统计显著 ≠ 实际显著】726 个 CVE 与 382 条 SA 的数量对比不直接等同于安全响应质量，须结合修复滞后时间、回溯补丁覆盖率等指标综合判断；C-16/C-17 的 η² = 0.6863 虽属大效应但仅反映组间差异的解释方差比例，不反映趋势方向，结合 Task 5 趋势检验 4 仓库的 commit 量趋势方向不同（freebsd-src 上升，其余下降），分布差异可能源于趋势分化；详见外部基准-Academic-CVE.md 第 2 节、推断性统计.md Task 7 与考据记录 20260727_第十二卷-统计学整合.md
