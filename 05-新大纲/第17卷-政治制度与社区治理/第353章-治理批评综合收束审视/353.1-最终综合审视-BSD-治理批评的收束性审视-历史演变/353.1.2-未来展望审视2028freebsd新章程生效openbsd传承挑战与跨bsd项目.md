# 353.1.2 未来展望审视：2028 FreeBSD 新章程生效、OpenBSD 传承挑战与跨 BSD 项目协作的可能性

  **要点**：从项目史观总纲第 19 条“前理解的差异使分歧不可避免，权力与知识在历史书写中共谋”审视，BSD 治理模式的未来展望呈现三类议题——其一，2028 FreeBSD 新章程生效的预期效应：2026.5.27 新章程引入任期限制（"an Incumbent Core Team Member currently in their third or fourth consecutive year may not run for reelection"，经 <https://www.freebsd.org/internal/bylaws/> 一手核验），拟 2028 年生效，预期效应有三——效应一是 Core Team 成员的强制轮换，Core.10 回顾显示 Hiroki Sato（佐藤広生） 已任 7 届、John Baldwin（约翰·鲍德温） 6 届、Warner Losh（沃纳·洛什） 6 届（FreeBSD Core Team Activity Reports，2020-07-27），任期限制可能打破“小圈子循环”现象；效应二是选举周期的固定化，新章程引入年度选举机制，可能提升 Core Team 决策的社区可见度；效应三是过渡期的适应成本，2026 至 2028 年的 2 年过渡期可能产生“旧章程惯性”与“新章程预演”的双轨期，须考据观察；其二，OpenBSD de Raadt 个人主导模式的传承挑战：OpenBSD 自 1995 年至今 31 年由 Theo de Raadt 个人主导（经 <https://www.openbsd.org/goals.html> 一手核验，"Be as politics-free as possible; solutions should be decided on the basis of technical merit"），但 de Raadt 本人对传承规划未公开表态，OpenSSH、LibreSSL、OpenSMTPD 等子项目的维护者群体已形成隐性传承结构（如 OpenSSH 维护者 Damien Miller），隐性传承结构是否能在 de Raadt 退出后维持 OpenBSD 项目目标，是未来展望的核心不确定项；其三，跨 BSD 项目协作的可能性：FreeBSD、NetBSD、OpenBSD、DragonFly BSD 四大 BSD 项目在 pkgsrc（NetBSD 主导，跨 BSD 共享软件包管理系统）、mfsBSD（FreeBSD 衍生，用于系统安装与恢复）、OpenSSH（OpenBSD 主导，跨 BSD 共享 SSH 实现）等组件上已有协作实践，但四大项目的治理结构差异（FreeBSD Core Team 选举制、NetBSD Foundation 执行委员会制、OpenBSD BDFL 制、DragonFly BSD 个人主导制）使跨项目协作呈现“组件级协作、治理级独立”的格局，未来展望的核心议题是“组件级协作”是否可能扩展至“治理级协作”（如跨 BSD 项目的安全响应协调、跨 BSD 项目的版权与许可证协议）；其四，BSD 与 Linux 治理模式未来展望的对照：BSD 治理模式的未来展望是“改革性”的——FreeBSD 2026 新章程的任期限制、OpenBSD 隐性传承结构的逐渐显化、跨 BSD 项目组件级协作的扩展皆是渐进调整；Linux 治理模式的未来展望是“革命性”的——Linux Foundation 自 2014 年后持续扩展多项目托管（CNCF、Kubernetes、Hyperledger 等），未来可能进一步整合开源生态治理；BSD 的“改革性”未来展望与 Linux 的“革命性”未来展望在本体论上地位相等（总纲第 8 条），皆是开源生态的一刻状态；其五，本审视作为历史小说的自觉（总纲第 23 条）：本节作为 BSD 治理模式未来展望的审视，本身是基于项目统摄史观设定的历史小说——“未来展望”是史家基于当下史料的推断而非已实现的事实，史家须自觉呈现这一推断的限度而非伪装预言者
  **史料**：项目史观总纲第 19、8、23 条原文（据原文第 25 章，第 19 条“前理解的差异使分歧不可避免，权力与知识在历史书写中共谋”，第 8 条“本体论上各方平等”，第 23 条“一切历史写作都是基于哲学设定的历史小说”）；FreeBSD Core Bylaws 2026.5.27 新版（<https://www.freebsd.org/internal/bylaws/>，任期限制条款原文"an Incumbent Core Team Member currently in their third or fourth consecutive year may not run for reelection"，由 Dag-Erling Smørgrav 于 2026-05-28 提交，cgit.freebsd.org/doc/commit/?id=，经一手核验）；FreeBSD Core Team Activity Reports（Core.10 回顾 2020-07-27，Hiroki Sato 7 届、John Baldwin 6 届、Warner Losh 6 届，作为“小圈子循环”现象的证据）；OpenBSD Project Goals（<https://www.openbsd.org/goals.html>，OpenBSD 自 1995 年至今 31 年由 de Raadt 个人主导，经一手核验）；OpenSSH 维护者档案（Damien Miller 等，作为 OpenSSH 隐性传承结构的证据）；pkgsrc 项目档案（NetBSD 主导，作为跨 BSD 共享软件包管理系统的证据）；mfsBSD 项目档案（FreeBSD 衍生，作为跨 BSD 系统安装与恢复协作的证据）；Linux Foundation 多项目托管档案（CNCF、Kubernetes、Hyperledger 等，作为 Linux 治理革命性重构的证据）；参见相关章节 BSD 治理改革与 Linux 治理重构部分史料 ［A］
  **史观**：总纲第 19 条——解释学循环是历史认识的根本条件（原“解释学循环与权力知识共谋”系名目变体，正名），BSD 治理模式未来展望的审视受前理解差异制约（BSD 阵营以“工程传统”为前理解，Linux 阵营以“治理现代化”为前理解，外部观察者以“民主化”为前理解），未来展望的叙事建构本身是权力知识共谋的具体显现；总纲第 8 条——本体论上各方平等，BSD 改革性未来展望与 Linux 革命性未来展望在本体论上地位相等；总纲第 23 条——一切历史写作都是基于哲学设定的历史小说，本节作为 BSD 治理模式未来展望的审视本身是历史小说，史家须自觉呈现自身的哲学设定
  **辨析**：考据过程留痕——【查证来源】FreeBSD Core Bylaws 2026.5.27 新版经 <https://www.freebsd.org/internal/bylaws/> 一手核验，确认任期限制条款原文"an Incumbent Core Team Member currently in their third or fourth consecutive year may not run for reelection"经核验准确，2026 新章程由 Dag-Erling Smørgrav 于 2026-05-28 提交（cgit.freebsd.org/doc/commit/?id=）；FreeBSD Core Team Activity Reports 经 FreeBSD 官方公开档案核验（Core.10 回顾 2020-07-27）；OpenBSD Project Goals 经 <https://www.openbsd.org/goals.html> 一手核验；OpenSSH 维护者档案经 OpenSSH 官方公开档案核验（Damien Miller 等）；pkgsrc 项目档案经 pkgsrc.org 官方公开档案核验；Linux Foundation 多项目托管档案经 Linux Foundation 官方公开档案核验；【交叉验证方法】“2028 FreeBSD 新章程生效预期效应”论证须以新章程文本（任期限制条款）、Core.10 回顾（“小圈子循环”现象）、过渡期安排（2026-2028 年 2 年）三源互证；“OpenBSD 传承挑战”论证须以 de Raadt 个人主导模式（1995 至今 31 年）、OpenSSH 隐性传承结构（Damien Miller 等）、de Raadt 未公开表态三源互证；“跨 BSD 项目协作”论证须以 pkgsrc（NetBSD 主导）、mfsBSD（FreeBSD 衍生）、OpenSSH（OpenBSD 主导）三个案例互证，确认“组件级协作、治理级独立”是各案例的共同结构；【0 信任原则·2028 新章程生效的预期效应】2028 FreeBSD 新章程生效的预期效应（强制轮换、选举周期固定化、过渡期适应成本）是史家基于 2026 新章程文本的推断而非已实现的事实，须区分“已实现项”（2026 新章程通过）与“预期项”（2028 新章程生效、任期限制实际运作）；【0 信任原则·OpenBSD 传承规划的考据空白】OpenBSD de Raadt 个人主导模式的传承挑战目前缺乏一手史料（de Raadt 本人未公开传承规划），史家须承认这一考据空白而非臆造传承方案；【0 信任原则·跨 BSD 项目协作的限度】“跨 BSD 项目协作”的论证须区分“已实现项”（pkgsrc、mfsBSD、OpenSSH 等组件级协作）、“提议项”（跨 BSD 项目的安全响应协调）、“未讨论项”（跨 BSD 项目的治理级协作），不得以“协作”一词模糊具体进展；【0 信任原则·未来展望的非预言性】本节作为未来展望的审视不是预言而是基于当下史料的推断，史家须自觉呈现推断的限度——2028 新章程生效的实际效应可能偏离预期，OpenBSD 传承方案可能在 de Raadt 退出后才显现，跨 BSD 项目协作的扩展可能因治理结构差异而受阻；【0 信任原则·“改革性”与“革命性”标签的限度】“BSD 改革性未来展望 vs Linux 革命性未来展望”是史家的形式主义建构——BSD 亦有革命性未来展望（如跨 BSD 项目治理级协作的提议），Linux 亦有改革性未来展望（如 Linux Foundation 内部治理结构的渐进调整），不得以“改革性”与“革命性”标签简化未来展望的复杂性；【0 信任原则·合图的非终结性】本审视作为最终综合审视不是史家认识的终结而是阶段性综合，随 BSD 与 Linux 治理演进（如 2028 年 FreeBSD 新章程生效、OpenBSD 传承规划公开、跨 BSD 项目协作扩展、Linux Foundation 治理调整）须重新展开
