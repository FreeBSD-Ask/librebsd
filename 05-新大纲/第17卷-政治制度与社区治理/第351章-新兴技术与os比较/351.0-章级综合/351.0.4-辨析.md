# 351.0.4 辨析

- NetBSD Core Team 的“封闭”是治理模式选择还是人员老化须区分；pkgsrc 管理的“僵化”是质量保证还是官僚主义须辩证看待；安全响应迟缓与项目规模的关系——人手少导致响应慢是客观限制还是管理问题须厘清
  - 文献：NetBSD Core Team 页面；pkgsrc 统计数据；NetBSD Security Advisories Archive；NetBSD Guide 历史版本
- Theo 的“个人主导”是事实还是夸张——有多少决策实际由 Theo 个人决定须考据；“有毒”社区的判断须基于具体案例统计，避免以偏概全；安全与功能的平衡是价值判断，不同用户有不同偏好，不宜简单否定 OpenBSD 的选择
  - 文献：OpenBSD 邮件列表存档；Theo 公开声明；补丁统计；外部评论文章 ［A］
- “规模过小”是 DragonFly BSD 的选择（坚持技术方向而非追求规模）还是无奈结果须区分；核心团队单一与 Matt Dillon 个人能力的关系——Dillon 作为主要设计者与实现者，其高度参与是项目优势还是风险须辩证看待；社区互动不足与用户基数小互为因果，不宜简单归因于团队态度
  - 文献：DragonFly BSD 开发者页面；邮件列表存档；dports 统计；Wiki 与手册；用户反馈
- 三大 BSD 团队批评的交叉比较与一手来源
  - 要点：三大 BSD 各团队批评的史料辨析须基于——各项目官方邮件列表存档（一手）；各项目官方团队页面与公开报告（一手）；外部开发者与研究者的评论与论文（二手）；跨项目比较研究（二手，但有助于把握全局）；用户文章关于三大 BSD 团队批评的论述须按 0 信任原则考据；须警惕“以偏概全”——个别案例不能代表整个团队，个别团队的问题不能代表整个项目；须注意比较的公平性——项目规模不同，团队面临的资源约束不同，不宜用同一标准衡量（据本章要点同款条目完整版回源补全）
- BSD 项目与美国两党政治的关系是“环境性嵌入”而非“实质性参与”，须避免将 BSD 项目政治化；联邦资助在两党共识期的持续性须考据具体预算数字，避免笼统判断；冷战结束对 BSD 项目的影响须量化考据——DARPA 对 CSRG 的资助在 1990 年代是否实质性减少须查 DARPA 历年合同档案；“两党极化加剧”的判断须以 Pew Research 等权威机构数据为依据，避免主观判断；本目（对应 351.2 节美国宏观社会语境素材）不评价
