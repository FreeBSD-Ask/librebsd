# 381.5.1 技术路线之争-Capsicum-vs-pledge-unveil-Clang-L

- **要点**：FreeBSD Capsicum（2012 年随 FreeBSD 9.0 引入，由 Cambridge 大学 Robert Watson 领导）与 OpenBSD `pledge`/`unveil`（`pledge` 于 OpenBSD 5.9 引入，`unveil` 于后续版本引入）构成 BSD 两大安全模型之争——前者采用 capability 模型，后者采用 promise/visibility 模型，两者技术哲学不同但目标相近。FreeBSD 2012 年前后决策以 Clang/LLVM 替换 GCC，许可证纯洁化是核心动机——GCC 在 GPLv3（2007 年）后 BSD 社区对许可证扩散的担忧加剧，Clang/LLVM 的 BSD 许可证符合 FreeBSD 治理偏好。GPLv3 争议在 BSD 社区引发广泛讨论，部分 `committer` 主张全面驱逐 GPL 代码，部分主张实用主义保留。`systemd` 争议外溢至 BSD 社区——`systemd` 作为 Linux 初始化系统替代 `sysvinit` 后，其“大而全”的架构哲学与 BSD 的“小而精”传统形成张力，BSD 各分支明确拒绝 `systemd` 但争议反映了 Unix 哲学的内部分歧。Wayland vs X11 在 BSD 社区的讨论延续这一哲学分歧。关键人物包括 Robert Watson、Jonathan Anderson、Poul-Henning Kamp（波尔-亨宁·坎普）。

- **史料**：一手史料包括 `freebsd-hackers`、`freebsd-arch` 邮件列表关于 Capsicum 的讨论存档，`misc@openbsd.org` 关于 `pledge`/`unveil` 的讨论存档，FreeBSD 9.0 release notes（Capsicum 引入），OpenBSD 5.9 release notes（`pledge` 引入），GCC→Clang 迁移公告与 freebsd-toolchain 邮件列表存档，`systemd` 相关 LKML 与 distrowatch 报道；二手史料包括 Anderson 等人关于 Capsicum 的学术论文（USENIX Security）、de Raadt 在 `misc@` 关于 `pledge` 设计的阐述；互联网档案馆存档的 `phoronix.com`、`lwn.net` 相关报道 ［A］。

- **史观**：总纲第 4 条（**分离聚合是永恒规律**，见 sacred 源材料第 4 章）——Capsicum 与 `pledge`/`unveil` 是 BSD 安全模型分离聚合的体现，两者目标相近但路径分化；总纲第 8 条（**本体论上各方平等**，见 sacred 源材料第 25 章）——Capsicum 与 `pledge` 在本体论上地位相等，禁止“技术先进 vs 落后”二元判断；总纲第 12 条（**科学是形式主义**，见 sacred 源材料第 25 章及第 9 章）——安全模型的设计选择不是科学真理的发现，而是形式主义化的工程偏好；总纲第 15 条（**文化即形式主义**，见 sacred 源材料第 25 章及第 7 章）——GPLv3 争议与 `systemd` 拒绝是 BSD 社区文化形式主义化的显化；总纲第 21 条（**革命与改革是历史方法论的分歧**，见 sacred 源材料第 21 章）——`systemd` 的革命式重构与 BSD 的改革式延续是方法论分歧，非“进步 vs 保守”。

- **辨析**：Capsicum 与 `pledge`/`unveil` 的技术对比须以学术论文与 release notes 为准，禁止以社区印象替代技术分析；【0 信任原则·技术路线之争的当事人立场】Robert Watson 与 de Raadt 对各自安全模型的阐述均有立场预设，须与第三方独立安全研究者的审计交叉验证；FreeBSD 引入 Clang/LLVM 的具体时间节点需考据——决策时间与实际默认编译器切换时间存在差异，以 release notes 为准核验；GPLv3 争议中“全面驱逐 GPL 代码”的主张是否曾实际进入 FreeBSD 官方议程需核验，部分叙述可能夸大；`systemd` 争议外溢至 BSD 的具体表现须以邮件列表讨论为据，BSD 各分支明确拒绝 `systemd` 是事实但其哲学争议的强度需量化；Wayland vs X11 在 BSD 社区的讨论截至 2026-07-27 仍在进行，结论保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。
