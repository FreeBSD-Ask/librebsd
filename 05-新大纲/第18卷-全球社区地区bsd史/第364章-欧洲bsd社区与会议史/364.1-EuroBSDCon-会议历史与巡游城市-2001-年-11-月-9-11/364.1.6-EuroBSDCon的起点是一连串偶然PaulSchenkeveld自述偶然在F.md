# 364.1.6 EuroBSDCon的起点是一连串偶然PaulSchenkeveld自述偶然在F

- EuroBSDCon 的起点是一连串偶然：Paul Schenkeveld 自述偶然在 FreeBSD 邮件列表读到两名英国人拟于 2001 年把 BSD 会议带到欧洲，因确认 Greg Lehey 将开设内核调试教程而下定决心参加，首届于 2001 年 11 月在英国 Brighton 举行，此后他一届未缺——会议史由具体教程与具体人物牵引，而非任何自上而下的规划。（BSD Now EP66，[1043.46-1086.07]，L1）
- 基金会制度化的动因是终结年度重复劳动：前八届 EuroBSDCon 由不同欧洲国家的团队逐年承办，每年从零搭网站、组程序委员会、开银行账户并另建注册支付系统，全是完事即散的一次性工程；2011 年荷兰第十届承办团队决议成立 EuroBSDCon Foundation 以承接知识、经验与资源，此后财务、常设网站与注册系统由基金会统一负责，本地组织得以专注于场地、演讲者住宿、餐饮与社交活动等本地事务。（BSD Now EP66，[1092.47-1223.47]，L1）
- 治理结构内嵌项目平等原则：基金会规则写明每个主要 BSD 项目至少设一名董事会代表，时任 FreeBSD、OpenBSD、NetBSD 各占一席，用以回应历史上个别项目对会议曝光不均的抱怨；Paul 同时观察到 NetBSD 与 OpenBSD 参会人数近年回升、本届出现 DragonFly BSD 报告，多项目并存的会议生态被视为常态。（BSD Now EP66，[1586.16-1644.96]，L1）
- EuroBSDCon 的创会缘起系欧洲社区对美洲会议格局的一次组织回应。受访者转述，2001 年英国同人因感到 BSD 社区仅在美国保有 BSDCon、欧洲开发者缺乏年度见面场合而创办该会议，此后延续为常设年会；2007 届选址哥本哈根，举办地惯例于上届会议最后一日表决产生。（BSDTalk EP118，[86.52-131.88]，L2）
- 2007 届会议的筹备细节呈现一次成熟的社区会议运作样本：9 月 12 至 15 日会期由两日五门教程与两日正式会议构成，注册费约 2000 丹麦克朗且仅覆盖会议本身；组织方弃酒店而选用青年旅舍，理由是与会者本就惯于席间的走廊交谈文化，多人间住宿更利于聚拢交流并节省开支；程序委员会收到约 48 篇投稿而仅有约 20 个演讲席位，讲者名单于 4 月敲定；FreeBSD 开发者峰会与周五社交活动照例并行，会后另设乐高乐园家庭日。（BSDTalk EP118，[133.84-309.4]，L1）
- 受访者的组织者背景与个人技术路径构成欧洲 BSD 社区人才生态的微观样本：她曾任职丹麦 BSD 用户组（BSD-DK）董事会约五年，以多年操办约 2500 人规模的丹麦 Linux Forum 会议的经验受 BSD-DK 前主席之邀加入 EuroBSDCon 2007 组织团队；本职为哥本哈根大学计算机科学系 Unix 系统管理员，2000 年起在任，自 NT 系统管理转向 Unix 后本欲安装 Linux，遭同人拦阻并获赠 FreeBSD 安装光盘而改换门庭，此后以 Apache、DNS 与 BIND、邮件等系统管理用途为主，从未试用 OpenBSD 或 NetBSD，亦自称非开发者。（BSDTalk EP118，[317.1-443.68]，L1）
- 该访谈为 Solaris ZFS 移植 FreeBSD 的关键前夜留下了用户侧期待记录：受访者最期待 EuroBSDCon 2007 的相关演讲，欲了解移植的具体过程及其将为 FreeBSD 带来之物，并指出 FreeBSD 已长期依赖 UFS 即快速文件系统，ZFS 能否注入新意是其关切所在。（BSDTalk EP118，[447.32-483.32]，L1）
- Giorgos Keramidas 的贡献路径始于 1996 至 1997 年间将 Linux 文档译为希腊语并协助他人安装使用，约三年后转向 FreeBSD，此后长期投身文档、用户支持与缺陷解决，自定位为 FreeBSD 的倡导者而非核心代码开发者。（BSDTalk EP177，[97.1-151.8]，L1）
- 他归因于 FreeBSD 的吸引力在于系统级一致性：多数操作系统需从不同来源拼凑软件包、由用户自行充当集成者，而 FreeBSD 以组织一致的方式让终端用户快速获得可用系统，安装体验也更简单。（BSDTalk EP177，[157.7-218.1]，L1）
- 其博客借马戏团大象因幼年被拴而不敢逃脱的寓言，描述新贡献者的不合理恐惧：担心开发者精英主义、轻视新人并拒纳其幼稚贡献；他强调 FreeBSD 团队实际运作相反——不仅接受新用户而且依赖他们，期待新人测试、评论与提出改进，新视角被视作项目的更新源泉。（BSDTalk EP177，[338.4-476.8]，L1）
- 他以亲历的 mailwrapper 事件说明社区文化：未读全文档即提交缺陷报告，资深开发者友善回应指出这是配置问题而非缺陷；他将这类内容上否定、精神上肯定的回复视为 FreeBSD 社区不会打击新人积极性的例证。 [存疑脚注] 受访者回忆的资深开发者姓名转写作 Seldon Shearn，通行拼写疑为 Sheldon Hearn，未经原始音频与邮件存档核对。（BSDTalk EP177，[543.6-654.6]，L1）
- mentorship 机制被系统阐述：每位准 FreeBSD 开发者均指派一位资深成员为导师，负责工具入门、提交前政策与代码审查；导师的肩后监督兼具规则传导与心理支持双重功能，化解新人弄坏源码树、不懂提交命令与分支操作的恐惧。（BSDTalk EP177，[746.8-873.6]，L1）
- 希腊社区十年变迁：约十年前他仅认识五至十位希腊 FreeBSD 用户，且 FreeBSD 不设中央使用登记故实际规模不可知；至 2009 年各地社区渐次成形，另一位希腊贡献者积极组织用户、翻译团队扩员，并通过在其他会议宣讲为希腊用户倡导 FreeBSD。（BSDTalk EP177，[960.7-1058.9]，L1）
- EuroBSDCon 2010剑桥站的缘起系当事人在曼彻斯特一次活动中与Robert Watson、Poul-Henning Kamp共进晚餐时提出，后者表示愿出讲者但须有人承担组织；从决定到实际举办历时约两年，于前一年的会上宣布；组织团队不大但分工明确，Watson承担最多（联络讲者并主办配套dev summit）；会议开始后可能灾难性出错的事项极少且难补救，主办方仅能保持体面；主会议轨完成录音以便会后回听。（BSDTalk EP187，[58.26-252.36]，L1）
- EuroBSDCon逐年换地使组织团队如接力赛般传递：坏处是一致性缺失，好处是每年犯下不同的新错误而吸取新教训；活动风格随组织者而变（剑桥站呈UKUUG风格、哥本哈根站气质迥异），当事人视之为既是优点也是缺点的双刃特征；下届定于2010年10月8日至10日德国卡尔斯鲁厄。（BSDTalk EP187，[255.76-379.72]，L1）
- 志愿BSD会议的运营经济学：论文投稿是根本性贡献（无论文则会议无从成立）；赞助用于讲者机票、场地、住宿与餐饮，直接降低与会成本并提供低价学生名额；英国自持货币带来汇率管理问题（美国赞助者要求以美元计），赞助到账通常先于支出故可作有依据的预估；BSD的志愿文化中主动帮忙者往往“被奖以更多工作”，组织者永远稀缺。（BSDTalk EP187，[374.52-565.52]，L1）
- UKUUG成立于1976年、至访谈时已三十四年，由会员出资、完全独立于软硬件厂商、以自身盈余自我维持；90年代中期其Linux特别兴趣小组因Linux不再是特殊兴趣而解散，Linux夏季会议后并入常规活动；会员调查显示Solaris与商业UNIX仍在大量使用（渐少但在用），而Linux是个体兴趣的最大项；当事人看重跨系统用户组形式，乐于比较各UNIX处理同类问题的管理界面与强弱项。（BSDTalk EP187，[592.32-824.84]，L1）
- 当事人的BSD入门史三段：本科时因Linux服务器问题决意迁往FreeBSD 3.0，迁移六小时后发现新版不再支持其SCSI卡（基础设施变更后驱动未跟上），凌晨两点文件系统已重格式化，改试具实验性ext2支持的NetBSD得以启动但夜间暴露稳定性问题，数月后暂回Linux；其后在笔记本装OpenBSD，恰逢施工挖断大楼主电源致全楼断电三秒，装机三小时的笔记本撑起整个下午且所需软件两小时内自ports补齐；自此以OpenBSD为主力（桌面与服务器），另置一台FreeBSD jail机。（BSDTalk EP187，[827.84-1063.20]，L1）
- 其大学研究组技术团队仅一人而高校不干预研究员的平台选择；工作以Perl为主（平台无关）并依赖ports安装软件；一年三四次更新OpenBSD snapshot（先置放24小时观察再上主工作站），一条命令即可升级全部ports与packages而系统不坏，当事人以此展示对系统的深度信任；OpenBSD将Perl置于base、base与packages同步升级保持整体一致，避免旧版本依赖断裂，契合其半生产staging用途。（BSDTalk EP187，[1068.64-1215.20]，L1）
- Paul Schenkeveld 于 1978 年进入 IT 行业，1983 年接触 UNIX 并决意以之为终身事业；九十年代初受托接管欧洲一份 BSD 的 FTP 镜像维护，此后工作重心转向 FreeBSD；他因 EuroBSDCon 社区的技术口碑于两年前首次参加 BSDCan，去年因 EuroBSDCon 组织事务缺席，本届 BSDCan 重返。（BSDTalk EP213，[75.88-137.20]，L1）
- EuroBSDCon 起源于 2001 年英格兰几位人士的实验性会议，次年有人效仿续办，至今已举办十届、巡游不同国家、由不同团队组织且成功程度不一，每年都要重新发明轮子；2011 年第十届时组织者决定成立 EuroBSDCon Foundation，以在年度之间传递知识与资源；受访者正是通过基金会参与协助波兰团队筹办 2012 年会议。（BSDTalk EP213，[156.52-206.40]，L1）
- EuroBSDCon 2012 定于 10 月 18 日至 21 日在华沙理工大学举行，本地组织由 FreeBSD GEOM 层与 ZFS 移植的作者 Paweł Dawidek 领导；波兰此前已办过三届 MeetBSD，其组织者已加入基金会团队；基金会承担会议的财务责任并运营注册与支付系统——一国基金会在另一国办会须应对欧洲各国税制与规则的差异，集中建设注册支付系统正是为了终结每年重造轮子的时间浪费。（BSDTalk EP213，[206.40-336.48]，L1）
- 会议采用四天格式：两天 tutorial 期间同期举办 FreeBSD 与 NetBSD 开发者峰会，另两天为 talk（周四五安排 tutorial 与峰会、周六日安排 talk），与 BSDCan 的格式相近；会议自创办起以英语为百分之百的工作语言，track 之外允许使用母语；本届 CFP 于 5 月 20 日截止，约三四周内确定讲者名单，注册预计 6 月中旬开放。（BSDTalk EP213，[729.98-771.72]，L1）
- 基金会治理与人力需求：董事会现仅三人、皆出自去年组织团队，计划扩充——至少各一名 OpenBSD、NetBSD、FreeBSD 项目代表，并吸纳去年、今年与明年组织团队的人，通过定期电话会议保证知识与经验传递顺畅；基金会网站需要程序员、设计师、美工志愿者并考虑更换永久 logo；会议志愿者应先联系波兰本地团队，社区联络可径致 Paweł Dawidek（PJD@freebsd.org）。（BSDTalk EP213，[388.68-557.36]，L1）
- 会议生态观察：BSD 活动逐年增多导致排期愈发困难，十月还需避开纽约的既有传统会议；受访者两个月内参加了五个 BSD 会议，另有 SCALE 等设 FreeBSD 展位的泛开源会议；连续参加两三届后即可认出熟面孔，会议对他已如家庭聚会；场地方面华沙理工大学带宽与建筑俱佳，波兰的酒店与餐饮成本远低于荷兰与英国。（BSDTalk EP213，[557.36-684.04]，L1）
- Xenocara 的起源：因 X 窗口系统上游实现项目变更许可证条款、且旧名称已成商标，OpenBSD 一度考虑自行 fork 并另起新名；开发者 Matthieu Herrb 借清洁鱼缸玻璃的小鱼学名造出 Xenocara 一词（以 X 开头，呼应 OpenBSD 以鱼类命名的传统）。最终项目决定不 fork 而跟随 X.org，Xenocara 遂成为既有做法的正式名称——为把 X 作为 OpenBSD base 系统的一部分而设的构建系统（X 不经 ports 与包系统分发）。 [存疑脚注] 转写将许可证变更写作 X386 许可证与 David Davis，通行记载为 XFree86 许可证争议，人名与项目名待核。（BSDTalk EP221，[80.04-161.60]，L1）
- Xenocara 的实质是构建封装而非分叉：它按依赖顺序对超过 250 个 X.org 模块调用 configure、make、make install；因 X 属于 base 系统，构建不得依赖外部工具——Mesa 构建系统过深依赖 GNU make 与 Python，OpenBSD 遂将预生成文件作为源文件提交进 CVS 树，免除全体开发者构建时的 Python 与 GNU make 依赖；另有支持 Vax、Sparc 等旧平台的本地改动未上游化。（BSDTalk EP221，[161.60-213.88]，L1）
- X server 特权分离代码由 Herrb 于约十年前（2002-2003）实现，至今仍在 OpenBSD 正常工作，但因在 Linux、Solaris 等 X.org 支持平台上移植该代码缺乏足够兴趣——他本人无意独力承担，其他项目亦无人接手——始终以一组 diffs 形式存于 Xenocara 树内，未提交上游。（BSDTalk EP221，[214.12-251.72]，L1）
- KMS（内核模式设置）困境是当时 OpenBSD 图形栈的核心问题：X.org 驱动整体转向 KMS，而 OpenBSD 内核尚无 KMS 支持，使项目要么困于旧版驱动，要么另辟蹊径——开发者将源自 Linux KMS 驱动的模式设置代码回植用户态，为 Sandy Bridge 与 Ivy Bridge 芯片组维护自定义 Intel 驱动，以传统用户态 X 驱动方式运行，保住 3D 加速与 X 视频加速能力；受访者视向内核移植 KMS 为 X 的未来，也是去除 X 服务器额外特权（系统主要安全隐患之一）的前提。 [存疑脚注] 转写将两位开发者名记作 Owen Haysworth 与 Jonathan Gray，人名拼写待与源码提交记录核对。（BSDTalk EP221，[262.44-372.14]，L1）
- 对 Wayland 的评估：该项目由 Kristian Høgsberg 等人自零开始、面向 Linux 设计，深度依赖 Linux 特有内核接口（输入子系统尤甚）；模式设置部分因 BSD 拟采用类似 KMS 的内核接口而在理论上可移植，但 Wayland 开发者明确不愿构建操作系统无关抽象层，故移植到 BSD 近乎按其合成 API 思想重写，工作量巨大且尚无人启动；其理念（削减 X 开销、提升本地图形性能、经合成管理器以另一方式实现远程显示）是否根本正确、能否满足真实应用需求，受访者直言尚无把握，而 X 目前工作良好、使用无处不在。 [存疑脚注] Wayland 发起人名依转写为 Christian Huxberg，通行记载为 Kristian Høgsberg，待核。（BSDTalk EP221，[456.46-572.66]，L1）
- 构建系统的可移植性与线程议题：Xenocara 构建系统因刻意保持简单（仅是 autotools 流程的封装）而具备合理可移植性，已被 DPB（OpenBSD 分布式包构建器）用于在 ports 集群上并行构建 Xenocara 且无需改动其本身；X 内部多线程场景不多，但新版 Mesa 的 LLVMpipe 软件渲染驱动使用线程，rthreads 真线程将使其受益，前提是解决 LLVMpipe 对 LLVM 与 Clang 的依赖——像 FreeBSD 那样以 LLVM/Clang 构建 base 并非易事，因 LLVM 构建系统存在大量 base 系统所无的外部依赖。 [存疑脚注] 转写记作 Mark SP 的演讲者疑为 DPB 作者 Marc Espié，待核。（BSDTalk EP221，[374.68-448.84]，L1）
