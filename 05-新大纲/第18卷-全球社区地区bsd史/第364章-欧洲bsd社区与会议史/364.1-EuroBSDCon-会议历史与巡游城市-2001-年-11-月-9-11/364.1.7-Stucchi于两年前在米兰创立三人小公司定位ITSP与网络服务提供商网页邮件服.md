# 364.1.7 Stucchi于两年前在米兰创立三人小公司定位ITSP与网络服务提供商网页邮件服

- Stucchi 于两年前在米兰创立三人小公司，定位 ITSP 与网络服务提供商（网页、邮件服务及经合作企业的连接），非完全 ISP；公司全程大量使用 FreeBSD 托管服务，并以之为电话服务的首选交付平台；理由是平台坚如磐石、开发者优秀、遇障可获得良好支持，且既有基础设施已在 FreeBSD 上，转投 Linux 反而是错误选择；ports 系统对软件版本的管理完全可靠，而电话服务部署要求超过百分之百的可靠性，ports 正是达成此目标的手段。（BSDTalk EP57，[81.88-188.72]，L1）
- FreeBSD 开发者 Luigi Rizzo 于访谈前约五六个月加入 Asterisk 项目，对主流应用做了大量修改使其可运行于 FreeBSD；此前 Asterisk 无法在 FreeBSD 上开箱编译，此后不仅可以，且代码路径与 ports 同步，make 文件中更因他而设 FreeBSD 专用选项。（BSDTalk EP57，[190.26-229.58]，L1）
- VoIP 硬件支持主要来自 asterisk-BSD 邮件列表；因 VoIP 演进过快，ports 中的 Asterisk 版本滞后于上游，其惯例是经 ports 安装 Asterisk、再从上游 subversion 仓库安装硬件驱动；约九个月前升级最新 Zaptel 驱动后机器每小时重启，求助消息发出数小时后（凌晨一时）即获回补丁；只要选用 Digium 与 Sangoma 卡即有良好支持，Sangoma 卡有厂商直接支持。（BSDTalk EP57，[234.7-342.82]，L1）
- 商业定位上转向以企业客户为主：VoIP 的价值已不在通话费用（免费市话服务随处可得），而在附加服务——会议、按用户分发的企业语音信箱、IVR 交互式语音应答、与企业管理系统集成，用 Asterisk 加几行 PHP 或 Python 即可任意定制；可靠性方面，传统电话世界的 SS7 协议族（他喻为电话界的 BGP）包含逐线复制的协议，电话业处理冗余已四五十年，而 Asterisk 存在结构性限制——话机注册绑定单机、宕机后注册信息无法与其他机器共享，难以做到完全冗余，用户“拿起听筒必然可用”的习惯预期叠加断线、路由器宕机等变量，构成他所称的 21 世纪挑战。（BSDTalk EP57，[342.82-523.96]，L1）
- 内部系统上，除一台因意大利复杂税制而保留的 Windows 会计机（运行合作者开发的账簿软件）外，从桌面到服务器全部运行 FreeBSD；BSD 平台的 SIP 软电话仍然匮乏：Ekiga（GNOME Meeting 新版，已含 SIP 支持）系朋友测试、其本人未亲验，X-Lite 堪称最佳但仅运行于 Windows。（BSDTalk EP57，[523.96-600.04]，L1）
