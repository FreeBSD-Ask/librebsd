# 069.1.3 移植完成的时间线

  **要点**：1989 年 Jolitz 开始 386 移植实验；**1992-03-12** 发布 **386BSD 0.0**（首个公开版本，由 Dr. Dobb's Journal 配套发行；1992-03-12 系 Usenet 公告日，386BSD 0.0 Release Notes 落款期为 1992 年 3 月 1-7 日，二者分别为公告日与文档编写期）；**1992-07-14**（Bastille Day/法国国庆日）发布 **386BSD 0.1**，因 AT&T 诉讼于 **1992 年 8 月** 暂停公开更新；**1994 年末（late 1994）** 发布 **386BSD 1.0** 时已远落后于 FreeBSD/NetBSD；**不存在 386BSD 0.2 公开版本**——社区补丁包积累期间无 Jolitz 官方版本发布。386BSD 版本发布时间线如下：

| 版本 | 发布日期 | 备注 |
| -- | ------ | -- |
| 386BSD 0.0 | 1992-03-12 | 首个公开版本，DDJ 配套发行 |
| 386BSD 0.1 | 1992-07-14 | Bastille Day，因 USL 诉讼后暂停公开更新 |
| 386BSD 1.0 | 1994 年末 | 远落后于 FreeBSD/NetBSD |

**史料**：386BSD 0.0 Release Notes (1-7 March 1992)、386BSD 0.1 Release Notes (14 July 1992)、comp.unix.bsd Usenet 原始公告（386BSD 0.0 发布于 12 March 1992）、NetBSD Project 官方历史时间线、FreeBSD Handbook “A Brief History of FreeBSD”；freebsd.duckdb 间接证据——netbsd-src 中 cgd 1993-03-21T09:45:37Z 提交 “initial import of 386bsd-0.1 sources”（commit_hash `0d110d127c41d7aeb2b1bfdc71964c5a496eabf9`），证明 386BSD 0.1 至迟在 1993-03-21 已被 NetBSD 项目作为基线 import，与 1992-07-14 Release Notes 日期一致；freebsd-src 中 Rodney W. Grimes（罗德尼·W·格赖姆斯） 1993-06-20T13:41:45Z 提交 “Initial import of 386BSD 0.1 othersrc/etc”（commit_hash `1bf9d5d9518e789360439c1db3d568b113caf60d`），印证 FreeBSD 项目亦以 386BSD 0.1 为 fork 基线 ［A］

**史观**：总纲第 5 条——没有必然性，只有偶然性：Jolitz 在 1992 年中后期的停滞是一个具体的人的具体决定，但这一停滞直接催生了 FreeBSD 与 NetBSD 的 fork；不存在的 0.2 版本成为社区补丁包与 fork 叙事的误解来源

**辨析**：**386BSD 0.0 发布日期经一手 Usenet 公告确认为 1992 年 3 月 12 日**，而非先前误传的 1991 年 7 月或 1992 年 2 月；**经 NetBSD 官方时间线、FreeBSD 官方历史、386BSD 0.0/0.1 Release Notes 三方交叉验证，确认不存在 386BSD 0.2 公开版本**——“0.2” 可能是对社区 patchkit 累积版本的误称，或源于非正式的内部测试版本；386BSD 1.0 发布于 1994 年末（late 1994），晚于 NetBSD 0.8（1993 年 4 月）与 FreeBSD 1.0（1993 年 11 月公告/12 月 CD-ROM）；freebsd.duckdb 验证结论——386BSD 0.1 作为 FreeBSD 与 NetBSD 共同基线，在 netbsd-src 与 freebsd-src 早期 commit 中均有显式 import 记录，commit message 中明确提及 “386bsd-0.1 sources” 与 “Initial import of 386BSD 0.1 othersrc/etc”，与 Release Notes 日期相互印证；0 信任原则提示：386BSD 0.0/0.1 本身无独立 git 仓库（Bill Jolitz 1990 年代早期使用单一 tarball 分发），数据库中的 import commit 是下游项目对 386BSD 源码的二次 import，时间晚于原始发布日期约 9-12 个月，须与一手 Release Notes 与 Usenet 公告交叉验证
