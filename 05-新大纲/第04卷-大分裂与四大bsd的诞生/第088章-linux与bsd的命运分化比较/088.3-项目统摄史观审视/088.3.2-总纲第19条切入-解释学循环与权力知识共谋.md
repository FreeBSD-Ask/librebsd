# 088.3.2 总纲第 19 条切入——解释学循环与权力知识共谋

  **要点**：从总纲第 19 条（解释学循环是历史认识的根本条件）切入，Linux vs BSD 争议中 “什么被记录、什么被遗忘” 本身就是权力行使——Linux 端主流叙事通过 man page、官方文档、培训教材、社区话语等渠道，将 BSD 端的一手作者、起源日期、概念先验地位系统性隐去，使读者形成 “该工具或概念起源于 Linux 端” 的误判；BSD 端的 “先验存在” 在 Linux 端主流叙事中被 “遗忘”，这一 “遗忘” 不是 “自然遗忘” 而是 “权力与知识共谋” 的产物；批评方与反批评方的前理解差异使分歧不可避免，合图非 “消除分歧” 而是 “在分歧中呈现各主体性”；“什么被记录、什么被遗忘” 的三类典型表现如下：

| 案例 | BSD 端一手作者 | Linux 端主流叙事的 “遗忘” |
| -- | ------------ | ----------------------- |
| sudo | Coggeshall 与 Spencer **1980 年**（编写；1985-12 经 net.sources 公开） | LPI 认证以 “Todd C. Miller（托德·C·米勒） 1994” 为起点 |
| BIND | Terry 等 4 人 **1984 年** | BIND 9 官方文档不点明 4 人姓名 |
| Capsicum | Watson 与 Laurie 等 **2010 年**（论文；2012 年随 FreeBSD 9.0 集成） | Linux man **landlock(7)** 不点明作者姓名〔订正注：原记“Watson 与 Anderson 2012 年”，归属与年份双错置，经行 109 自引论文订正〕 |

**史料**：〔存疑：原引 原材料/研究/linux 文化挪用/ 下 79 项案例文件与模式总结.md，该目录经查全项目不存在，出处无从对证〕；Coggeshall 与 Spencer **1985-12** net.sources sudo 公告、4.2BSD **1983-08** Release Notes、UCB/CSD-84-182 BIND 论文、4.4BSD-Lite **1994-06** Release Notes、FreeBSD 9.0-RELEASE **2012-01-12** Capsicum 公告；Linux man page 与培训教材档案 ［A］

**史观**：总纲第 19 条——解释学循环是历史认识的根本条件：Linux vs BSD 争议中 “什么被记录、什么被遗忘” 本身就是权力行使，Linux 端主流叙事的 “内部一致性” 是权力与知识共谋的产物；前理解的差异使 BSD 与 Linux 两端的分歧不可避免，合图非 “消除分歧” 而是 “在分歧中呈现各主体性”

**辨析**：总纲第 19 条的切入须经具体案例的 “什么被记录、什么被遗忘” 考据——Coggeshall 与 Spencer **1980 年** sudo 起源被 “遗忘”（Linux man **sudo(8)** 不回溯 4.1BSD 起源）、Terry 等 4 人 **1984 年** BIND 起源被 “遗忘”（BIND 9 官方文档不点明 4 人姓名）、Watson 与 Laurie 等 **2010 年**（USENIX Security 论文；2012 年随 FreeBSD 9.0 集成）Capsicum 起源被 “遗忘”（Linux man **landlock(7)** 不点明作者姓名〔订正注：原记“Watson 与 Anderson 2012 年”系归属与年份双错置——Capsicum 论文（本文件行 109 自引）作者为 Robert Watson 与 Ben Laurie 等，2012 年系 FreeBSD 9.0 集成之年而非论文年〕），这一 “遗忘” 须经一手档案与主流叙事的比对交叉验证；【0 信任原则·共谋须经考据】“权力与知识共谋” 须经 Linux 端主流叙事的 “内部一致性”（man page 与培训教材的一致性）与 BSD 端一手档案的 “被遮蔽” 比对交叉验证，不得仅凭推测即断定 “共谋”；【0 信任原则·前理解差异非对立】批评方与反批评方的前理解差异使分歧不可避免，但前理解差异非 “对立” 而是 “不同视角”，合图须在分歧中呈现各主体性而非消除分歧
