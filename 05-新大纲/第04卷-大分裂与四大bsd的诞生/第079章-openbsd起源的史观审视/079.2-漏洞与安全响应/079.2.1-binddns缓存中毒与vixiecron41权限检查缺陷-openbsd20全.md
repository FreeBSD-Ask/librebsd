# 079.2.1 BIND DNS 缓存中毒与 Vixie cron 4.1 权限检查缺陷——OpenBSD 2.0 全代码审计的首批网络服务漏洞成果

  **要点**：OpenBSD 2.0（1996 年 10 月发布）继承自 NetBSD 1.0 的 BIND 4.9.x 系列 DNS 服务器存在缓存中毒（cache poisoning）与 NXT 记录处理缺陷，远程攻击者可借由伪造 DNS 响应污染解析器缓存，进而劫持域名解析流量；同期 Vixie cron 4.1 的 **cron(8)** 守护进程存在权限检查缺陷，本地用户可借由 **crontab(1)** 提交特制 crontab 文件触发权限提升；上述漏洞属于 OpenBSD 1.2 发布后全代码审计（1996 年夏天起，OpenBSD security.html 明确记载 “We have been auditing since the summer of 1996”）在 2.0 release 前后识别的首批网络服务与本地权限类缺陷，errata 以补丁形式发布，未引用 CVE 编号（1996-1997 年 CVE 体系尚未被 OpenBSD errata 系统性引用）；修复策略为源码补丁配合 errata 公告，未采用独立 Security Advisory 编号——OpenBSD 2.0 时期 errata 机制尚处于雏形阶段，与后世 OpenBSD 3.x 起成熟的 errata+ 补丁分离发布模型不同
  
**史料**：OpenBSD 2.0 errata 页面（openbsd.org/errata20.html）、BIND 4.9.x 安全公告存档、Vixie cron 4.1 发布说明与安全修复记录；openbsd.duckdb 数据库证据——openbsd-src 仓库 1996 年 commit 量为 5,240 commits，其中 deraadt 个人贡献占主导，与全代码审计期开发活跃度吻合 ［A］
  
**史观**：BIND 缓存中毒与 cron 权限提升是 OpenBSD 全代码审计方法论的首批工程成果，标志 OpenBSD 从被动响应转向主动审计；de Raadt 个人主导的全代码审计决定 OpenBSD 2.0 的安全基线
  
**辨析**：BIND 4.9.x 缓存中毒与 cron 4.1 权限提升的精确发现者与披露时点在 errata 原文中未注明，须对照 BIND 安全公告与 Vixie cron 发布说明交叉验证；【0 信任原则·errata 无 CVE 引用】OpenBSD 2.0 errata 未引用 CVE 编号，不等于漏洞不存在 CVE——1996-1997 年 CVE 体系（MITRE CVE 于 1999 年 1 月正式发布）尚未建立，errata 以技术机制描述而非 CVE 编号索引漏洞，史家不得以 “无 CVE” 推论 “漏洞不重要”；【0 信任原则·commit 量不等于审计质量】1996 年 openbsd-src 5,240 commits 反映开发活跃度但不等于审计覆盖度，BIND/cron 漏洞的审计质量须结合 errata 补丁内容与 commit message 主题词综合判断
