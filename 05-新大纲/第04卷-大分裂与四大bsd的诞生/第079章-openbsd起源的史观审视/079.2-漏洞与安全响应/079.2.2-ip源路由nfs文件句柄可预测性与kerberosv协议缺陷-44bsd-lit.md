# 079.2.2 IP 源路由、NFS 文件句柄可预测性与 Kerberos V 协议缺陷——4.4BSD-Lite 遗留网络栈漏洞的系统性识别

  **要点**：OpenBSD 2.0 内核默认接受带源路由选项的 IP 数据包，攻击者可构造源路由数据包绕过地址验证实现 TCP 连接劫持；4.4BSD NFS 实现的文件句柄（file handle）生成缺乏足够随机性，攻击者可猜测或推算文件句柄绕过 NFS 导出限制；MIT Kerberos V5 实现存在可被伪造的票据授予票据（TGT）与密钥分发中心（KDC）缺陷；上述三类漏洞均继承自 4.4BSD-Lite 网络栈与 Kerberos 实现，属于 OpenBSD fork 时即 inherited 的遗留漏洞面，全代码审计在 2.0 release 前后系统性识别并修复；IP 源路由修复策略为内核默认禁用源路由接受（sysctl 可调），NFS 文件句柄修复策略为引入更强随机性生成算法，Kerberos V 修复策略为同步 MIT 上游安全补丁
  
**史料**：OpenBSD 2.0 errata 页面、4.4BSD-Lite 网络栈源码（IP 源路由处理路径）、MIT Kerberos V5 安全公告存档、OpenBSD CVS 历史早期网络栈 commit 序列 ［A］
  
**史观**：IP 源路由、NFS 文件句柄与 Kerberos V 三类漏洞的系统性识别体现全代码审计对 4.4BSD-Lite 遗留漏洞面的覆盖深度；总纲第 4 条——分离聚合是永恒规律：OpenBSD 从 4.4BSD-Lite 基线分离后主动加固，是 BSD 安全文化从继承到重构的转折
  
**辨析**：IP 源路由默认禁用的精确 commit 与 sysctl 可调参数名称须对照 OpenBSD 2.0 源码与 **ip(4)** 手册页核实；NFS 文件句柄随机性增强的算法细节须对照 OpenBSD CVS 历史 NFS 子系统 commit 核实；Kerberos V 修复是否同步 MIT 上游全部安全补丁须对照 MIT Kerberos 公告与 OpenBSD errata 交叉验证；【0 信任原则·errata 无 CVE 引用】上述三类漏洞在 OpenBSD 2.0 errata 中均未引用 CVE 编号，CVE 体系 1999 年方建立，史家不得以现代 CVE 索引标准回溯评判 1996-1997 年 errata 的规范性
