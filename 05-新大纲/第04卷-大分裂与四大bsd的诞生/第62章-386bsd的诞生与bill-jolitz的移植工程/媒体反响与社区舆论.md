# 第 62 章 媒体反响与社区舆论

> 本子节汇总与本章主题相关的新闻报道与社区舆论，按“批评类 / 故障类 / 冲突类 / 里程碑事件类 / 外部冲击类 / 校园社会文化新闻类 / 商业产业新闻类”七类组织。所有新闻条目遵循 0 信任原则，须与官方史料交叉验证后方可采信。

## 批评类

### 新闻条目 1

- **新闻标题（中英）**：A Brief History of Hackerdom（黑客道简史）
- **新闻来源**：O'Reilly Openbook（开源文集《Open Sources: Voices from the Open Source Revolution》）+ Eric S. Raymond + 1999-01（第一版） + **<http://www.oreilly.com/openbook/opensources/book/raymond.html>** + 访问日期 2026-07-27
- **新闻摘要**：Eric S. Raymond 在 O'Reilly 出版的开源文集章节中明确写道：“1991 年，与 Linus Torvalds 早期实验同时，William 与 Lynne Jolitz 正在实验性地将 BSD Unix 源码移植到 386。多数观察者比较 BSD 技术与 Linus 粗糙的早期成果后，预期 BSD 移植将成为 PC 上最重要的自由 Unix。”Raymond 进一步指出：“Linux 以完全不同的方式演化……质量并非通过严格标准或独裁维护，而是通过每周发布、数日内获得数百用户反馈的简单策略。”该文为 Salon 2000 年专访引用的关键来源。
- **与本章主题的关联说明**：本章叙事需呈现 386BSD 停滞的社会性而非技术性原因，Raymond 这篇 1999 年文章是“Jolitz 夫妇开发风格过于独裁”观点的最早系统化论述，先于 Salon 2000 年专访，是本章“批评报道”的核心文献之一。
- **与官方史料的交叉验证结论**：Raymond 文章关于“BSD 技术优于 Linux 早期版本”的判断与 Torvalds 在 Meta 访谈中“386BSD 是好的 BSD 移植”的判断一致；关于“Jolitz 开发风格过于独裁”的判断与 FreeBSD Handbook 1.3.1 节 fork 起因叙事方向一致。Raymond 作为 OSI 创始人，其立场须标注“开源运动倡导者视角”。

## 冲突类

### 新闻条目 1

- **新闻标题（中英）**：The unknown hackers（鲜为人知的黑客）
- **新闻来源**：Salon + Rachel Chalmers + 2000-05-17 + **<https://www.salon.com/2000/05/17/386bsd/>** + 互联网档案馆待补
- **新闻摘要**：Rachel Chalmers 在 Salon 发表长篇专访，回顾 Bill 与 Lynne Jolitz 夫妇于 1992 年 3 月（Release Notes 1992-03-01/07）发布 386BSD 0.0、1992-07-14（巴士底日）发布 386BSD 0.1 的历程。文章援引 Linus Torvalds 在 1993 年 Meta 杂志访谈中的原话"If 386BSD had been available when I started on Linux, Linux would probably never have happened"，并引述 Eric Raymond 对 Jolitz 夫妇“试图以二人之力控制质量”的批评性评论。文章明确指出 386BSD 0.1 被下载约 250000 次，但在 1993-12 发布 1.0 后失去动力，社区分裂为 FreeBSD、NetBSD 阵营。
- **与本章主题的关联说明**：本章核心叙事是 386BSD 的停滞与 Bill Jolitz 受到批评的报道，Salon 这篇 2000 年的回溯性专访是 386BSD 阵营唯一主流媒体长篇采访，集中呈现 Jolitz 夫妇对“386BSD 停滞”叙事的反控与对 FreeBSD 起源叙事的“完全虚构”指控，是本章不可绕开的新闻视角史料。
- **与官方史料的交叉验证结论**：与 FreeBSD Handbook 1.3.1 节及 FreeBSD 1.0 RELEASE Announcement（1993-11-01）的官方叙事存在冲突——FreeBSD 官方叙事称 patchkit 协调员因 Jolitz 撤回授权而 fork，Jolitz 夫妇则称“用户群窃取”。冲突时以邮件列表原始帖与 386BSD 0.1 源码树等一手史料为最终依据，Salon 专访标注为“386BSD 阵营视角”。

### 新闻条目 2

- **新闻标题（中英）**：The Choice of a GNU Generation: An Interview With Linus Torvalds（GNU 一代的选择：Linus Torvalds 访谈）
- **新闻来源**：Meta Magazine + Mike Linksvayer + 1993 年末 + **<http://gondwanaland.com/meta/history/interview.html>** + 访问日期 2026-07-27
- **新闻摘要**：Mike Linksvayer 在 Meta Magazine 通过电子邮件访谈 Linus Torvalds，被问及“对 386BSD 的看法”时，Torvalds 明确表示“从未实际试用 386BSD”，但承认"If 386BSD had been available when I started on Linux, Linux would probably never had happened"。Torvalds 进一步批评 386BSD“缺乏协调”，指出存在三个互不兼容的键盘/控制台驱动程序，并认为“长期发布周期伤害了自由软件开发”，称 NetBSD 项目“可能是朝正确方向迈出的一步”。
- **与本章主题的关联说明**：本章重点之一是 Bill Jolitz 受到的批评报道，Torvalds 作为 Linux 创始人在 1993 年（386BSD 1.0 发布同年）公开评论 386BSD“缺乏协调”“发布周期过长”，是对 Jolitz 开发模式的早期权威性批评，先于 Salon 2000 年回溯性报道，构成本章“批评报道”时间线的起点。
- **与官方史料的交叉验证结论**：Torvalds 的批评与 FreeBSD Handbook 1.3.1 节关于“patchkit 协调员因 Jolitz 撤回授权而 fork”的官方叙事方向一致，但措辞较温和。Meta 访谈原文置于公共领域（public domain），无版权争议。访谈中关于“三个互不兼容的键盘/控制台驱动程序”的具体说法未经源码树逐字核实，标注为“媒体转述”。

## 里程碑事件类

### 新闻条目 1

- **新闻标题（中英）**：FreeBSD 1.0 RELEASE now available（FreeBSD 1.0 正式版现已发布）
- **新闻来源**：comp.os.386bsd.announce Usenet newsgroup + Jordan K. Hubbard（乔丹·哈伯德） + 1993-11-01 + **<https://www.freebsd.org/releases/1.0/announce/>** + FreeBSD 官方归档
- **新闻摘要**：Jordan K. Hubbard 在 Usenet 新闻组 comp.os.386bsd.announce 发布 FreeBSD 1.0 RELEASE 公告，明确标注“the first ‘official’ release of FreeBSD 1.0”，列出动态缓冲区缓存机制、Linux 声卡驱动、Mitsumi CDROM 接口、XFree86 2.0 syscons 支持等新增功能。公告明确致谢 Walnut Creek CDROM“持续的（迄今仍无利可图的）支持使这一切成为可能”。
- **与本章主题的关联说明**：本章核心时间节点是 1993 年 FreeBSD 1.0 的诞生，该 Usenet 公告是 FreeBSD 1.0 发布的唯一一手官方公告，构成本章时间线的锚点。同时公告中致谢 Walnut Creek CDROM 的内容，与第 26 章 FreeBSD 商业支持叙事相衔接，为 386BSD 阵营“用户群窃取”反控提供了官方对照。
- **与官方史料的交叉验证结论**：该公告本身即为 FreeBSD 项目官方史料，与 FreeBSD Handbook 1.3.1 节“1993 年 11 月 FreeBSD 1.0 发布”的叙事一致。公告中“no more greek letters”的表述印证了 FreeBSD 1.0 发布前存在 ALPHA、BETA、EPSILON 等希腊字母预发布版本的事实。

### 新闻条目 2

- **新闻标题（中英）**：Porting BSD to the 386（将 BSD 移植到 386）系列文章
- **新闻来源**：Dr. Dobb's Journal + William Jolitz 与 Lynne Jolitz + 1991 年 1 月起连载 + 期刊原始存档待补；EBSCO/MIT 图书馆有索引
- **新闻摘要**：Bill 与 Lynne Jolitz 在 Dr. Dobb's Journal 1991 年全年以每月一篇连载形式，系统记录将 BSD Net/2 移植到 Intel 80386 的工作。该系列文章被 Linus Torvalds 在 1993 年 Meta 访谈中明确承认为“有趣的”参考资料，被 Eric Raymond 在《黑客道简史》中称为“影响了整整一代操作系统开发者”的里程碑式工作。Salon 2000 年专访指出该系列文章“可能比代码本身更具影响力”。
- **与本章主题的关联说明**：本章时间起点为 1992-1993 年，但 386BSD 的思想源头可追溯至 1991 年 Dr. Dobb's Journal 连载。该系列文章构成本章“386BSD 先驱”叙事中“先驱”一词的文献依据，亦是后续 Jolitz 夫妇被视为“开源先驱”的原始证据。
- **与官方史料的交叉验证结论**：该系列文章为 Jolitz 夫妇本人署名作品，属当事人一手史料。其影响力判断（“影响了 Torvalds”）经 Torvalds 本人 1993 年 Meta 访谈确认。具体连载期数与原始 PDF 待通过 Dr. Dobb's Journal 期刊数据库补全，标注为待补充。

**要点**：

- FlightAware 于 2006 年的架构为全 AMD64 FreeBSD 6：两台 PostgreSQL 数据库服务器各配 16 块 300GB 磁盘构成 RAID 1 对（约 5TB 旋转容量、存储约 1TB 数据），以 Slony-I 复制容灾；地图服务器为双 AMD64 双核 1U 机型，单图生成约 160 毫秒 CPU 时间，配合自研负载均衡表实现日生成数百万张地图，足以承接 CNN 与 Fox News 报道空难事件时的流量尖峰。（BSDTalk EP42，[203.16-308.68]，L1）
- 每日约 4000 万条飞机位置更新令 PostgreSQL 即便批量插入也不堪负荷，团队遂为航班轨迹数据定制内存驻留数据库（约占 1GB RAM），内建经纬度框、速度阈值与部分尾号或航司前缀（如 COA 对应 Continental Airlines）查询，并在全部地图服务器间复制；新机启动时从既有服务器对拷数据库约一分钟即上线。（BSDTalk EP42，[656.02-727.52]，L1）
- Lehenbauer 的 BSD 渊源始于 1991 年：以无浮点协处理器的 386/16 经 9600 波特 SLIP 链路历时约 24 小时下载 Bill 与 Lynne Jolitz 的 386BSD；早期系统仅稳定数分钟，随补丁发布逐步延长至 20 分钟、1 小时，但基于 4.4BSD 代码的文件系统自始稳定、从未丢文件——他将这份可靠性视为自己不曾失去信心的关键。（BSDTalk EP42，[410.38-465.50]，L1）
- 九十年代其团队以 BSD 建立并运营整家 ISP，1999 年以令人满意的价格售出；FlightAware 创业时天使资金极少，Oracle 与 Microsoft SQL 的许可费足以压垮预算，加上对 BSD 性能、稳固与自身既有经验的信任，选型几乎不言自明；扩展哲学是拒绝大型专有多处理器系统、以廉价 PC 服务器横向堆叠。（BSDTalk EP42，[390.86-510.58]，L1）
- 桌面端迁移路径：多年维持 Windows 与 BSD 双分区双启动，为 Excel 与 Photoshop 重启进 Windows、其余时间活在 BSD 的终端与 SSH 中；2002 年 11 月购入 Titanium PowerBook 并装载 Mac OS X 10.1 后完成切换，理由是终端加 SSH 照常远程工作、Tcl 随系统附带、Darwin Ports 可编译与 FreeBSD ports 相同的软件，乃至 FlightAware 产品可在离线笔记本上运行——Mac OS X 因此成为其 BSD 桌面经验的自然延伸。（BSDTalk EP42，[817.14-939.40]，L1）

**史料**：

- 该期留存的一手史料线索：Slony-I 复制服务器（见 postgresql.org 文档）；3-Ware 硬件 RAID 的选型测试记录——标准为双盘系统拔出任一盘保持运行且重启后可从任一盘引导，而三年前主板板载 RAID 无一能可靠从第二盘引导；FAA 数据馈送延迟五分钟加处理约一分钟的时延结构；其个人机器上保留着 Microport Unix、Bell Technologies、SCO 时代直至 BSD 的连续文件时间戳，最早可追溯至 1980 年代末。（BSDTalk EP42，[316.28-375.46]，L1）

**史观**：

- 总纲17 证明世界先于解释和改造世界：Lehenbauer 的可靠性主张全部建立在自设测试之上：RAID 1 使磁盘可靠性较无冗余提升千倍、ECC 内存较非 ECC 提升百万倍的判断，均以其亲手拔盘、重启、引导验证为准，而非厂商参数；这种以可重复实测证明替代宣传解释的工程取向，正是其选型纪律的核心。（BSDTalk EP42，[743.12-807.10]，L1）

**辨析**：

- 对 BSD 的批评与敬意并存：Lehenbauer 抱怨会撞上奇怪内核限制（共享内存相关转换表的尺寸难觅文档），须翻检一年前的邮件列表自行揣测；承认其他发行版的安装流程更精致；但赞其发布工程从未放行早期 Linux 曾出现的卸载即毁文件系统一类的缺陷，并在 Linux 占尽 mind share 与公司投入的 2006 年，仍称许 Berkeley 阵营的强健，特别致敬 Theo de Raadt 与 NetBSD、OpenBSD 的工作。[考据脚注] 其所称早期 Linux umount 缺陷细节未经核实，系当事人回忆。 [考据脚注] 早期 Linux umount 缺陷的具体所指未核实，仅作当事人 2006 年回忆记录。（BSDTalk EP42，[943.92-1068.48]，L1）
