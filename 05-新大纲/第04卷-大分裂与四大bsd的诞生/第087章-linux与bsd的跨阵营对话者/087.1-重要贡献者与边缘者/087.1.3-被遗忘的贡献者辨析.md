# 087.1.3 被遗忘的贡献者辨析

  **要点**：被遗忘的贡献者辨析须识别两类——“技术贡献被低估”（如补丁作者、文档作者，其工作可经 bsd_commits.duckdb commit 数与邮件列表补丁提交记录量化）与“非技术贡献被忽视”（如组织者、翻译者、调解者，其工作须从 BSD 大会组织档案与非英语 BSD 社区档案挖掘）；两类贡献者的史料都须从原始档案主动挖掘，不得仅依赖主流叙事
  
**史料**：BSD 邮件列表贡献记录；BSD 大会组织档案；非英语 BSD 社区档案 ［A］
  
**史观**：总纲第 10 条——动手者创造历史：被遗忘的贡献者作为边缘者，其贡献须从 bsd_commits.db（技术贡献量化）与 BSD 邮件列表贡献记录、BSD 大会组织档案、非英语 BSD 社区档案（非技术贡献挖掘）主动识别——主流叙事仅记录 Core Team 核心成员，边缘者贡献须依赖原始数字档案与机构档案〔订正注：原误用“边缘者贡献”非权威名目，改权威名目〕
  
**辨析**：被遗忘的标准经 bsd_commits.duckdb contributors 表与 BSD 邮件列表贡献记录交叉验证——“被主流叙事忽视”（如补丁作者、文档作者、组织者、翻译者未在 Core Team 名单或 BSDCon 演讲名单中出现）不等同于“贡献低”（bsd_commits.duckdb 中部分非 Core Team 的贡献者 commit 数超过 Core Team 成员，BSD 大会组织者与翻译者的工作经 BSD 大会组织档案与非英语 BSD 社区档案可量化）；贡献规模（commit 数、补丁数、文档数、组织活动数）与叙事曝光度（Core Team 名单、BSDCon 演讲、媒体报道）非同一维度，主流叙事的曝光度偏差不反映贡献规模差异
