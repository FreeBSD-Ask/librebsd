# 087.1.4 边缘贡献者的史料辨析

  **要点**：边缘贡献者的史料辨析须经三类史料交叉验证——技术贡献（bsd_commits.duckdb 代码提交、BSD 邮件列表补丁提交记录）、文化贡献（BSD 教程存档如 Dru Lavigne FreeBSD 新闻网教程、BSD 文档如 Handbook 与 FAQ、BSDCon 演讲存档）、组织贡献（BSD 大会组织记录、非英语 BSD 文档翻译项目、社区调解邮件存档）；三类史料须交叉验证，不得仅依赖代码提交记录评估贡献
  
**史料**：BSD 邮件列表贡献记录；BSD 文档与教程存档；BSD 大会与社区组织档案 ［A］
  
**史观**：0 信任原则〔订正注：原误挂“总纲第 25 条”，0 信任原则系本项目考据方法论而非总纲条目，去号处理〕：边缘贡献者史料须经 bsd_commits.db（技术贡献量化）、BSD 教程与文档存档（文化贡献考据）、BSD 大会与社区组织档案（组织贡献考据）三类来源交叉验证，不得仅依赖单一来源（如仅依赖 bsd_commits.duckdb 评估贡献会忽视文化贡献与组织贡献）
  
**辨析**：边缘贡献者的史料价值在不同维度表现不同——技术贡献经 bsd_commits.duckdb contributors 表与 commit_files 表可精确量化（commit 数、改动行数、影响文件数），文化贡献经 BSD 教程与文档存档可部分量化（文章数、教程数、翻译字数）但难以评估影响力，组织贡献经 BSD 大会组织档案可部分量化（大会数、参与人数）但难以评估长期影响；三类贡献须结合各自可量化的指标与定性评估综合考据，不得仅以技术贡献的 commit 数为唯一标准

**观点**：1992 年 12 月 2 日，时任 Lotus Development Ireland 雇员的 Jordan Hubbard 在 Usenet 公告与 Hypermedia Concepts 公司合作制作一张同时收录 386BSD 0.1 加 patchkit、Linux 0.95、X11R5 与 GNU 源码的 CD-ROM，称“任何能让 386BSD 与 Linux 更易获取的事都是好事”，并声明本人不从中获利、定价以学生等穷困群体可承受为限。
**邮件来源**：Jordan K. Hubbard，comp.unix.bsd，1992-12-02，Message-ID: `JKH.92Dec2030349@whisker.lotus.ie`
**史学意义**：该公告是 386BSD 与 Linux 尚未分立时期跨阵营分发实践的一手证据，显示 FreeBSD 后来的核心组织者曾以中立分发者姿态同时服务两大自由 UNIX 阵营，“跨阵营对话者”身份有其具体商业与社会语境。

**观点**：1993 年 9 月 26 日 Jordan Hubbard 在答复 FreeBSD 安装问题时自述其硬盘上 DOS、Linux 与 FreeBSD 三个系统共存且运行良好，并以“并非所有 BSD 用户都是 Linux 偏执者”自嘲回应社区戏谑。
**邮件来源**：Jordan K. Hubbard，comp.os.386bsd.bugs，1993-09-26，Message-ID: `JKH.93Sep26045608@whisker.lotus.ie`
**史学意义**：当事人自述证明跨系统并存是 1993 年 BSD 核心开发者的日常实践，阵营对立在后世的强化叙事与此一手记录之间存在明显落差。

**观点**：1992 年 8 月 1 日 Linus Torvalds 在 USL 起诉 BSDI 的讨论中承认 Linux 的概念取自 USL 与 BSD 已有特性，但强调 Linux 不含任何 AT&T 代码，并明确把 Linux 作为“无 AT&T 源码亦可在一年内写出可用系统”的论据反驳 USL 关于 BSDI 开发离不开 AT&T 源码的主张。
**邮件来源**：Linus Torvalds，comp.unix.bsd，1992-08-01，Message-ID: `1992Aug1.114436.8733@klaava.Helsinki.FI`
**史学意义**：该邮件将 Linux 置入 USL 诉讼的公共论辩场域，是 386BSD 时代 Linux 与 BSD 直接对话的一手记录，也表明 Linux 作者本人清醒承认对 UNIX 既有概念体系的承袭。
