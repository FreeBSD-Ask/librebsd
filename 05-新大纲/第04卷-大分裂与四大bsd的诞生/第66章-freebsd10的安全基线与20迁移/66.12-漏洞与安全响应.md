## 66.12.2 FreeBSD-SA-96:20 栈缓冲区溢出——回溯影响 FreeBSD 1.0 的本地提权漏洞

  **要点**：FreeBSD-SA-96:20.stack-overflow 公告（1996-12-16 发布）披露 **cron(8)**、**crontab(1)**、**ppp(8)** 三个用户空间工具存在栈缓冲区溢出（buffer overrun），本地用户可构造超长输入触发溢出获取 root 权限；受影响版本范围为 FreeBSD 1.0 至 FreeBSD 2.1.6.1，表明漏洞自 FreeBSD 1.0（1993-11-01）起即存在但直至 1996-12-16 才被公开修复——漏洞潜伏期约 3 年；公告原文未引用 CVE 编号（1996 年 CVE 体系尚未建立），CVSS 评分与 CWE 分类无法事后精确赋值，但从栈缓冲区溢出机制推断属于 CWE-121 Stack-based Buffer Overflow 范畴，本地提权至 root 的危害等级评估为 High（约 7.2-7.8）；发现者与披露过程未在公告中署名；修复版本为 FreeBSD 2.1.7 与 FreeBSD 2.2-RELEASE，回溯策略为针对 2.1.x 系列发布补丁（2.1.6.1 之前版本须手动应用补丁），FreeBSD 1.x 系列因已停止维护而无官方补丁回溯；官方 SA 编号为 FreeBSD-SA-96:20.stack-overflow；历史影响评估——该漏洞是 FreeBSD 1.x 时期继承自 4.3BSD/386BSD 用户空间工具栈溢出缺陷的集中爆发，暴露 FreeBSD 1.x 无栈保护机制（stack canary、ASLR、W^X 均未引入）的架构性缺陷
  
**史料**：FreeBSD-SA-96:20.stack-overflow 公告原文（`<https://www.freebsd.org/security/advisories/FreeBSD-SA-96:20.stack-overflow.asc`，PG>P 签名发布）；freebsd-security-notifications 邮件列表 1996-12 存档；bsd_commits.duckdb 早期漏洞补遗条目 ［A］
  
**史观**：技术选择的代价：FreeBSD 1.x 继承 4.3BSD 用户空间工具意味着继承其全部栈溢出缺陷，无栈保护机制的基线选择使这些缺陷在 1993-1996 年间持续可利用；形式与内容：FreeBSD 1.x 无栈保护是内容层面的安全缺陷，但形式层面（Net/2 基线选择）决定了这一缺陷的不可避免性
  
**辨析**：FreeBSD-SA-96:20 的受影响版本下限为 FreeBSD 1.0，但公告发布于 1996-12-16（FreeBSD 2.1.x 时期），须区分“漏洞引入时间”（1993-11-01 FreeBSD 1.0 发布时即继承）与“漏洞公开修复时间”（1996-12-16）——3 年潜伏期内漏洞是否被实际利用无公开记录 据一手文献印证消解^doubt-resolved-286：漏洞在 1993-1996 年间是否被实际利用须对照 freebsd-security 邮件列表与 Bugtraq 存档核实 ］；FreeBSD 1.x 系列无官方补丁回溯，1.x 用户须升级至 2.1.7 或 2.2-RELEASE 方能修复，这一回溯策略差异反映 FreeBSD 1.x 已进入生命周期终点；公告原文"Several buffer overruns exist in the cron, crontab and ppp utilities"明确为多个溢出点（Several），非单一漏洞，三个工具的溢出机制可能独立存在；【0 信任原则·PGP 签名公告仍须交叉验证】FreeBSD 官方公告虽为 PGP 签名发布的一手史料，但修复 commit 的实际完整性须对照 freebsd-src 仓库 diff 核验

## 66.12.3 FreeBSD 1.x 安全基线的架构性缺陷与版本周期关联

  **要点**：FreeBSD 1.x 版本周期内仅有的安全响应（2 条 isprint() 修复 commit）与回溯影响的栈溢出漏洞（FreeBSD-SA-96:20）共同反映 FreeBSD 1.x 安全基线的架构性缺陷——FreeBSD 1.0 基于 Net/2（4.3BSD 网络栈），未引入 securelevel 内核安全等级机制（securelevel 于 4.4BSD-Lite 引入，FreeBSD 2.0 rebase 后方进入 FreeBSD），无栈保护机制（stack canary 在 GCC 3.x 后才系统化引入，ASLR 与 W^X 在 FreeBSD 5.x-7.x 后才逐步引入），单文件 **/etc/passwd** 将密码散列存于公开可读文件（shadow password 分离机制直至 FreeBSD 4.x 才弥合），基于 DES 的 **crypt(3)** 密码散列在 1993 年已显陈旧；这些架构性缺陷使 FreeBSD 1.x 时期的安全响应只能以“逐工具补丁”方式被动进行，无法通过内核层面机制（如 securelevel 限制 root 能力、栈保护阻止溢出利用）系统性缓解；FreeBSD 2.0 rebase 至 4.4BSD-Lite 后引入 securelevel 是 FreeBSD 安全基线的首次架构性升级，但栈保护等深度防御机制须等待 FreeBSD 5.x-7.x 时代的 GCC 栈保护、ProPolice、ASLR 等技术引入方能实现
  
**史料**：freebsd.duckdb `commits` 表（freebsd-src, 1993-11-01 至 1995-01-01, security fix commit 仅 2 条）；FreeBSD-SA-96:20.stack-overflow 公告；4.4BSD SMM: 16《On the Security of UNIX》；FreeBSD 1.0 源代码（无 securelevel 相关代码）；FreeBSD 2.0 源代码（引入 securelevel） ［A］
  
**史观**：形式与内容：FreeBSD 1.x 的安全基线是“形式（Net/2 基线选择）决定内容（安全缺陷范围）”的典型呈现，基线选择一旦确定，安全响应能力即被基线约束；技术选择的代价：继承 Net/2 基线的代价是继承 4.3BSD 全部安全缺陷，这一代价在 FreeBSD 1.x 时期以 isprint() 补丁与栈溢出遗留的形式显现
  
**辨析**：FreeBSD 1.x 安全基线的架构性缺陷须区分“基线继承缺陷”（来自 Net/2 与 386BSD 0.1）与“FreeBSD 自身引入缺陷”（fork 后新代码中的缺陷）——26.12.1 的 isprint() 修复与 26.12.2 的栈溢出遗留均属基线继承缺陷，FreeBSD 自身引入缺陷在 1.x 时期因 commit 量有限（1993-11-01 至 1995-01-01 freebsd-src commit 量较少）而相对较少；securelevel 缺失的影响须精确界定——securelevel 限制 root 能力但无法阻止本地用户利用用户空间工具栈溢出提权，故 securelevel 引入（FreeBSD 2.0）并不能直接解决 FreeBSD-SA-96:20 类型的栈溢出漏洞，栈溢出的根本性缓解须依赖栈保护机制；【0 信任原则·基线缺陷量化】FreeBSD 1.x 安全基线缺陷的量化评估须基于源代码审计而非 commit 量推断，本次考据基于已有研究底稿的结论，完整源代码审计超出本子节范围
