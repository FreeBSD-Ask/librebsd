# 073.1.3 FreeBSD 2.0 rebase 至 4.4BSD-Lite 后的安全基线迁移

  **要点**：FreeBSD 2.0（1994-11-22 网络公告，12 月 CD-ROM 分发）是首个完全基于 4.4BSD-Lite 的版本，消除 Net/2 争议代码的法律风险，同时引入 4.4BSD-Lite 的新安全机制——securelevel 内核安全等级机制（level 0 不安全模式、level 1 安全模式禁止 `/dev/mem` 访问与原始磁盘写入并强制 **chflags(2)** 不可变标志、level 2 高安全模式进一步限制系统时间修改），securelevel 一旦提升至非零级即不可降级，须重启方能恢复至 level 0；FreeBSD 1.1.5.1（1994-07-01）作为 1.x 系列最后版本（过渡版），仍基于 Net/2 代码，未继承 securelevel；FreeBSD 1.x 与 4.4BSD-Lite 的基线差异导致安全补丁须在 2.0 rebase 时重新合并，Rodney W. Grimes（罗德尼·W·格赖姆斯） 于 1994-05-24/25 提交的 4.4BSD-Lite 源码导入 commit（`59deaec541ae8baaa58daf6c5a2196ea7de180c3`、`df8bae1de4b67ccf57f4afebd4e2bf258c38910d`、`26f9a76710a312a951848542b9ca1f44100450e2`）标志 FreeBSD 2.0 安全基线迁移的开始
  
**史料**：FreeBSD 2.0 Release Announcement (22 Nov 1994)（Jordan Hubbard 原始公告）；FreeBSD 1.1.5.1 RELEASE Announcement (5 Jul 1994)；4.4BSD-Lite Release Notes (1994.6)；4.4BSD SMM: 16《On the Security of UNIX》；4.4BSD PSD: 5《Berkeley Software Architecture Manual (4.4 Edition)》；bsd_commits.duckdb `tags` 表（release/2.0_cvs tagger_date 1994-11-22T10:58:58Z, Jordan K. Hubbard）与 `commits` 表（4.4BSD-Lite 导入 commit） ［A］
  
**史观**：总纲第 2 条——历史是形式主义化的非存在：FreeBSD 2.0 rebase 是 “形式（法律洁净的 4.4BSD-Lite）压倒内容（386BSD 安全基线的延续）” 的转折，securelevel 等 4.4BSD-Lite 新机制通过 rebase 进入 FreeBSD；总纲第 13 条——法律与道德是利益分配：USL v. BSDi 1994.1 和解协议（法律结构）直接决定 FreeBSD 2.0 的安全基线迁移（技术路径）
  
**辨析**：FreeBSD 2.0 rebase 至 4.4BSD-Lite 的安全基线迁移须区分 “法律洁净” 与 “安全机制升级”——前者是 rebase 的直接动机（USL 诉讼和解要求），后者是 rebase 的附带收益（securelevel 等 4.4BSD-Lite 新机制进入 FreeBSD）；securelevel 的具体级别与约束须对照 4.4BSD SMM: 16 与 PSD: 5 核实，本节叙述基于研究底稿的考据结论；FreeBSD 1.1.5.1（1994-07-01）与 FreeBSD 2.0（1994-11-22）间隔约 4 个月 22 天，须区分 “1.x 系列最后版本” 与 “2.0 系列首个版本” 的安全基线差异；【0 信任原则·commit 量不等于质量】bsd_commits.duckdb 中 4.4BSD-Lite 导入 commit 反映 rebase 工程规模但不等于安全机制迁移质量，securelevel 的实际集成状态须对照 FreeBSD 2.0 源代码核验
  
**文献**：FreeBSD 2.0 Release Announcement (22 Nov 1994)；FreeBSD 1.1.5.1 RELEASE Announcement (5 Jul 1994)；4.4BSD-Lite Release Notes (1994.6)；4.4BSD SMM: 16《On the Security of UNIX》；4.4BSD PSD: 5《Berkeley Software Architecture Manual (4.4 Edition)》；bsd_commits.duckdb `tags` 表与 `commits` 表 ［A］
