# 073.1.2 FreeBSD 1.0 安全基线的具体内容与 4.3BSD 网络栈远程漏洞面

  **要点**：FreeBSD 1.0 继承的 386BSD 安全基线中，4.3BSD 网络栈远程漏洞面是 FreeBSD 1.0 时期最活跃的安全风险面——sendmail DEBUG 命令允许远程执行任意命令（Morris 蠕虫 1988 年利用的漏洞之一，在 4.3BSD 网络栈中持续存在）、fingerd 缓冲区溢出（Morris 蠕虫另一利用路径）、`~/.rhosts` 信任链允许无密码远程登录；FreeBSD 1.0 继承 Net/2 的密码文件布局——公开可读的 `/etc/passwd` 与仅 root 可读的 `/etc/master.passwd` 并存，pwd_mkdb(8) 生成的 `/etc/spwd.db`（含加密口令）与 `/etc/pwd.db`（口令字段以 `*` 占位）构成 shadow 机制，非 root 进程经 getpwnam(3)/getpwuid(3) 取得的口令字段为 `*`（pwd_mkdb(8) 手册页 HISTORY：首现于 4.3BSD Net/2；System V 的对应机制是 `/etc/shadow`）；基于 DES 的 **crypt(3)** 密码散列（继承自 UNIX v7）在 1993 年已显陈旧，DES 56 位密钥长度易受暴力破解，但 FreeBSD 1.0 未引入更强的密码散列算法
  
**史料**：FreeBSD 1.0 源代码中 sendmail 配置与 fingerd 实现；Morris 蠕虫技术分析（Spafford 1989 年三部分析论文）；4.3BSD 网络栈安全相关邮件列表存档；FreeBSD 1.0 `/etc/passwd` 格式文档 ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律（技术选择的代价）：FreeBSD 1.0 继承 386BSD 安全基线的代价是继承 4.3BSD 网络栈的全部远程漏洞面，这一代价在 FreeBSD 1.0 时期（1993-1994）通过社区补丁逐步缓解，但根本性解决须等待 FreeBSD 2.0 rebase 至 4.4BSD-Lite 后的 securelevel 机制与后续安全加固；0 信任原则：4.3BSD 网络栈远程漏洞面的考据须对照 FreeBSD 1.0 源代码与 Morris 蠕虫技术分析交叉验证
  
**辨析**：sendmail DEBUG 命令在 FreeBSD 1.0 中的具体状态须对照源代码核验——Morris 蠕虫 1988 年利用的 sendmail DEBUG 漏洞在 4.3BSD 后续版本中可能已修复，但 sendmail 本身作为网络服务持续暴露远程攻击面；fingerd 缓冲区溢出在 FreeBSD 1.0 中的具体状态须对照源代码核验；`~/.rhosts` 信任链是 4.3BSD 网络栈的设计特性而非漏洞，但在互联网化场景中成为安全风险；FreeBSD 1.0 时期 DES **crypt(3)** 的暴力破解风险在 1993 年已受关注但未立即引发算法替换——据 FreeBSD 4.0-RELEASE Handbook（Chapter 8.1 “DES, MD5, and Crypt”）与 FreeBSD 3.0-RELEASE FAQ（§2.22）印证：FreeBSD 1.x 及部分 2.0 前的快照使用 Nate Williams 编写的非管制散列函数，FreeBSD 2.0 起默认口令散列改为 RSA Data Security MD5 单向散列（`$1$` 前缀，Mark Murray 开发的 md5crypt）；具体散列实现仍须对照 FreeBSD 1.x 与 2.0 源代码及 release notes 核实
