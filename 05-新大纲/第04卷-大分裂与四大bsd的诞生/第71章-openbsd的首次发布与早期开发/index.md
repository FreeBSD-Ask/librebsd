# 第 71 章 openbsd的首次发布与早期开发

## 要点

- IPFilter 许可证争议引发 OpenBSD 对全部依赖组件的许可证审计——审计结果导致多个组件被移除或重写；连锁反应强化 OpenBSD 对自由软件准则的严格执行
- OpenBSD 早期（1996-2003）技术淘汰具有“安全驱动而非商业驱动”的鲜明特征——淘汰决策主要基于安全论证而非市场份额或商业压力；这一特征使 OpenBSD 在 BSD 阵营中独树一帜，与 FreeBSD 的“兼容优先”形成对照；但需警惕将 OpenBSD 叙事为“安全原教旨主义”的回溯性建构——彼时 OpenBSD 的移除决策多基于具体工程权衡（如 telnetd 移除后 ssh 已成熟可用），而非抽象安全原则
- Sun Solaris 2.5（1995）是基于 SVR4 的 UNIX，运行于 SPARC 与 x86，面向企业服务器与工作站台；作为商业 UNIX，Solaris 拥有成熟的企业安全特性但无 OpenBSD 式的公开代码审计文化。OpenBSD 在 1995-1996 以 “开源 + 主动安全” 开辟了一个商业 UNIX 与 Linux 都未占据的细分市场。
- **辨析**：4.4BSD-Lite 替代 386BSD 作为 OpenBSD 直接基线的时间点须严格区分——NetBSD 1.0 rebase 至 4.4BSD-Lite 于 1994 年 10 月 26 日完成，早于 OpenBSD 1.0 fork（1995 年 10 月 18 日）约一年，故 OpenBSD 1.0 fork 时即直接基于 4.4BSD-Lite 而非 386BSD；securelevel 在 4.4BSD-Lite 中为概念雏形，OpenBSD 后续主动加固并演化为 **securelevel(7)** 手册页，与 FreeBSD 的 `kern.securelevel` sysctl 形成路径分化；OpenBSD 1.0/1.2 时期 securelevel 的实际启用状态需对照源码与 release notes 核实，概念雏形与默认启用为不同维度
  
- OpenBSD 1.2 在 BSD 社区引发关注——部分成员认可安全审计路径，部分成员质疑分叉的必要性；反响在 BSD 与 Linux 邮件列表持续讨论

## 史观

- 总纲第 10 条——动手者创造历史：基于 NetBSD 分叉的开发路径与 de Raadt 个人主导的全代码审计方法论决定 OpenBSD 的工程方向（据 71.7、71.13）。
- 总纲第 4 条——分离聚合是永恒规律：OpenBSD 1.2 的发布标志 BSD 阵营的新聚合；NIS 退役后其功能由 LDAP 与 Kerberos 等分散聚合（据 71.7、71.11）。
- 总纲第 4 条——分离聚合是永恒规律：4.4BSD-Lite 替代 386BSD 成为 OpenBSD 直接基线，安全基线经 NetBSD 1.0 间接继承 386BSD 遗留基因并直接继承 4.4BSD-Lite 新机制（据 71.13）。
- 总纲第 4 条——分离聚合是永恒规律：安全至上的工程选择带来性能与功能广度的牺牲；FreeBSD 与 OpenBSD 形成“性能/生态 vs 安全/审计”路线分叉（据 71.7、71.12）。
- 总纲第 21 条——革命与改革是历史方法论的分歧：全代码审计是从被动安全响应转向主动安全审计的改革式关键工程实践；安全驱动淘汰是 OpenBSD 工程文化的核心特征（据 71.11、71.13）。
- 总纲第 13 条——法律与道德是利益分配：许可证解释的差异与许可证审计是 BSD 项目法律利益结构的关键节点与实践（据 71.10）。
- 总纲第 15 条——文化即形式主义：OpenBSD 1.2 的反响反映开源社区对安全审计路径的关注（据 71.7）。
- 总纲第 23 条——一切历史写作都是基于哲学设定的历史小说：避免将工程权衡回溯性叙事为抽象原则（据 71.11）。
- 总纲第 22 条——知识注定过时：r-commands 在 1996-2021 年共 25 年的渐进退役周期中保留兼容形式直至完全移除；386BSD 的安全基因经中转在 OpenBSD 主线延续（据 71.11、71.13）。
- 总纲第 4 条——分离聚合是永恒规律：OpenBSD 是 NetBSD 的直接派生，证明 BSD 许可证允许自由分叉以追求不同工程优先级（据 71.12）。

## 辨析

- OpenBSD 移除决策是否完全基于安全需考据——sendmail 退役亦涉及配置复杂度与维护成本；r-commands 退役虽然安全论证为主，但 SSH 已成熟亦是工程前提
- Solaris 与 OpenBSD 目标用户重叠有限（企业 vs 高安全/研究）；OpenBSD 的价值不在企业特性丰富度，而在可验证的安全流程。
- OpenBSD 全代码审计的起始时间需考据——审计可能在 fork 后立即开始（1995 年 10 月起），亦可能在 OpenBSD 1.2 发布前集中进行（1996 年上半年），需对照 CVS 历史核实；【0 信任原则·commit 量不等于质量】L1.1.1 的 1995-1996 openbsd-src commit 量（770→5,240）反映开发活跃度但不等于代码质量，OpenBSD 1.2 的“全代码审计”质量须结合 commit message 主题词与安全公告记录综合判断。 [存疑脚注] 全代码审计的起始时间待考，须对照 openbsd.duckdb CVS 历史核实

## 史观映射

> 本章体现项目统摄史观中“没有必然性，只有偶然性”与“分离聚合是永恒规律”的双重运作——de Raadt 被 NetBSD Core Team 逐出是具体的个人决定，但直接催生 OpenBSD 这一 BSD 家族的安全堡垒；fork 是“分离”的极端形式，但分离后的“聚合”（加密代码集成、代码审计文化建立）才是 OpenBSD 真正的创造性贡献；“安全至上”作为差异化定位是“技术选择即政治选择”的典型——de Raadt 选择安全而非可移植性或性能，这一选择反映了 OpenBSD 对 BSD 哲学的不同理解；Core Team 的驱逐决议则体现了“组织结构塑造技术路径”——NetBSD 的精英决策结构直接改变了 BSD 家族的格局
