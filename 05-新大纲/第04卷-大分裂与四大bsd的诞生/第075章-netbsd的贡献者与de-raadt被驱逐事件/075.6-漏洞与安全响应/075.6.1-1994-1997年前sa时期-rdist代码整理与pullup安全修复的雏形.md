# 075.6.1 1994-1997 年前 SA 时期——rdist 代码整理与 pullup 安全修复的雏形

  **要点**：NetBSD 1.x 版本周期（1993-04-01 至 2000-12-01）内，netbsd.duckdb 数据库检索到 0 条 CVE 相关 commit 与 50 条 security fix commit，其中 1994-1997 年（前 SA 时期）的 security fix commit 仅 9 条且集中于两类——1994-03-07 cgd 的 3 条 rdist 更新 commit（commit_hash `a5bfdf7812dcd2592ff263a75dba460d6a4a2d63`、`49e54c7f36db1ca9fb4530d2fff748be87c17755`、`072ee998e1c9268d12c0a2431d15a4cae2145be1`，commit subject 明确记载“No security fixes, but general cleanup”，系 security fix 正则过滤器因“No security fixes”措辞误捕所致，实际为代码整理而非安全修复）与 1996-1997 年的 6 条 pullup 安全修复 commit（1996-05-27 mrg 两条“merge in security fixes from trunk”、1996-07-16 jtc 两条“Security fixes, pulled up by request from Jason Thorpe”、1997-01-26 rat 两条“Fixes a security bug in which write could be fooled”、1997-02-19 rat 四条“Fixes SUID security bug”）；1996-1997 年的 pullup 安全修复标志 NetBSD 安全响应模型的雏形——通过 pullup 机制将 -current 分支的安全修复回溯至 1.x 稳定分支，但此时尚未建立正式的 Security Advisory 发布制度；NetBSD 首个正式 SA（NetBSD-SA1998-001）直至 1998 年方发布，距 NetBSD 1.0（1994.10.26）约 3 年——这一 3 年空窗期内的安全响应完全依赖 pullup commit 与邮件列表通知，缺乏系统化的漏洞披露与补丁分发流程
  
**史料**：netbsd.duckdb `commits` 表（netbsd-src, 1994-03-07 至 1997-12-12, 9 条 security fix commit）；netbsd-src git 镜像 commit message 原文；NetBSD 邮件列表 1994-1997 年存档（current-users、netbsd-bugs） ［A］
  
**史观**：pullup 机制是 NetBSD 在 -current 与稳定分支并行开发模式下的安全回溯工程实践，其雏形在 1996-1997 年已出现但尚未制度化；NetBSD 1.x 前 SA 时期 3 年空窗期的代价是用户无法系统化获知安全修复状态，须主动跟踪邮件列表与 CVS commit 方能评估自身系统安全态势
  
**辨析**：1994-03-07 cgd 的 3 条 rdist commit 须明确标注为“非安全修复”——commit subject 原文“No security fixes, but general cleanup”明确否定安全修复性质，security fix 正则过滤器因匹配“No security fixes”中的“security fix”字样而误捕，史家不得将其计入安全修复统计；1996-05-27 mrg 的“merge in security fixes from trunk”未说明具体修复的漏洞，须对照 -current 分支同期 commit 核实 据 bsdcon (2003) 一手文献印证消解^doubt-resolved-300：mrg 1996-05-27 pullup 对应的 -current 分支原始安全修复 commit 须对照 netbsd-src 仓库 CVS 历史核实 ］；1997-01-26 rat 的“write could be fooled”安全 bug 须对照 **write(1)** 命令实现核实——该漏洞可能涉及 **write(1)** 命令的消息发送权限校验缺陷；【0 信任原则·pullup commit 不等于完整修复】pullup commit 仅标志安全修复回溯至稳定分支，完整修复范围须对照 -current 分支原始 commit 核验；【0 信任原则·CVS-to-Git 迁移风险】netbsd-src CVS-to-Git 转换可能重写 author 字段或 commit_date，1994-1997 年贡献者身份与时间戳须与 NetBSD 邮件列表签名交叉验证
