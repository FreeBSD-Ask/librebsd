# 082.3.5 security fix commit 模型与跨项目安全修复流动——deraadt/itojun/fgsch 的安全响应实践（1998-2001）

  **要点**：OpenBSD 2.x 版本周期（**1996-10-01** 至 **2001-06-01**）的 openbsd.duckdb 数据库记录 5 条 security fix commit（无 CVE 编号）。5 条 commit 对照如下：

| 日期 | 提交者 | commit_hash | message_subject | 跨项目流动 |
| -- | ---- | --------- | ------------- | -------- |
| **1998-08-31** | deraadt | `e9c24f64af83b204d7a1ae324638873d6e4d6a03` | put back a security fix downsj removed ages ago | 恢复 downsj 移除的修复 |
| **2000-05-06** | itojun | `b1847376027c1fcbf7570b990861ab21508d188c` | avoid underflow on unsigned value arithmetic (when optlen < 4). 2nd half of NetBSD Security Advisory | 引用 NetBSD SA |
| **2001-03-31** | fgsch | `2a6be46ef2855608aed33bee9976d282e2b4c62c` | Security fixes: check for short packets and bad types; from FreeBSD. millert@ ok. | 引用 FreeBSD 修复 |
| **2001-04-02** | fgsch | `db6846956ee03c261001da9491a0f4b981fbf02f` | Security fix; discard short packets. | — |
| **2001-04-02** | fgsch | `28c97ceb003a0200c7b12d005359e580282886e2` | More security fixes; check type before using it as tsptype index. | 针对 **talkd(8)** 类协议 |

5 条 commit 反映 OpenBSD 2.x 时期安全响应的三个特征——其一为安全修复在 commit 历史中可能被意外移除后恢复（deraadt 1998 commit），其二为 OpenBSD 与 NetBSD/FreeBSD 间存在双向安全修复流动（itojun 2000 commit 引用 NetBSD SA，fgsch 2001 commit 引用 FreeBSD 修复），其三为 fgsch 作为新晋开发者在 2001 年连续提交安全修复，体现 OpenBSD 安全响应贡献者圈层的扩展

**史料**：openbsd.duckdb 数据库 openbsd-src 仓库 5 条 security fix commit 完整记录（commit_hash、author_date、author_name、message_subject）、OpenBSD CVS 历史对应 commit 序列、NetBSD Security Advisory 存档（itojun commit 引用）、FreeBSD 安全修复记录（fgsch commit 引用） ［A］

**史观**：总纲第 13 条法律与道德是利益分配——密码学与信息安全：security fix commit 模型反映 OpenBSD 2.x 时期安全响应从 errata 补丁向源码树内 commit 演化的工程路径；总纲第 4 条分离聚合是永恒规律——分离与聚合：OpenBSD 与 NetBSD/FreeBSD 间的双向安全修复流动证明 BSD 阵营分离后仍存在工程层面的聚合

**辨析**：deraadt 1998-08-31 commit（“put back a security fix downsj removed ages ago”）的具体被移除安全修复内容须对照 commit diff 核实——commit subject 仅说明 “恢复”，未说明被恢复的安全修复具体机制，史家不得臆造修复内容；itojun 2000-05-06 commit 引用的 “NetBSD Security Advisory” 具体编号须对照 NetBSD SA 存档核实——commit subject 仅称 “2nd half of NetBSD Security Advisory”，未注明 SA 编号；fgsch 2001-03-31 commit 引用的 FreeBSD 修复具体 commit 须对照 FreeBSD CVS 历史核实——commit subject 仅称 “from FreeBSD”，未注明 FreeBSD commit hash；【0 信任原则·security fix 正则过滤器误捕风险】openbsd.duckdb 的 security fix commit 通过正则匹配 commit subject 中 “security fix” 字样识别，deraadt 1998 commit 的 “put back a security fix” 措辞被正则匹配但实际为恢复操作而非新修复，史家须区分 “新安全修复” 与 “恢复被移除的安全修复” 两类 commit；【0 信任原则·CVS-to-Git 迁移风险】openbsd-src 主仓为 CVS（anoncvs.openbsd.org），GitHub 为只读 git 镜像，CVS-to-Git 转换可能重写 commit hash，5 条 commit 的 40 字符 hash 须与 OpenBSD CVS 主仓交叉验证
