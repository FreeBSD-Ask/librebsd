# 070.5.1 386BSD 安全基线的具体内容——4.3BSD-Reno 安全机制在 80386 平台的完整移植


> 分工注释：本节与 **05-卷册大纲\第04卷-大分裂与四大bsd的诞生\第075章-netbsd的贡献者与de-raadt被驱逐事件\68.14-netbsd0809对386bsd安全基线的直接继承与netbsd10.md** 互为分工——本节侧重 386BSD 安全基线本身的形成（机制构成与“未引入”考据），68.14 侧重 NetBSD 0.8/0.9 与 1.0 对该基线的继承与 rebase 迁移路径；两章机制对照表与“未引入 securelevel/chroot/shadow password”枚举系同一考据的两侧引用，读者对照阅读时应以各自叙事主线为准，不视为内容重复。对侧 68.14 的同款分工注释待该文件所属核查报告的整改流程补设（超出本文件权限，登记 DEFERRED）。

  **要点**：**386BSD 0.0**（**1992-03-12**）与 **0.1**（**1992-07-14**）由 Bill Jolitz 与 Lynne Jolitz 夫妇完成，基于 4.3BSD-Reno 与 Networking Release 2（Net-2，1991），是 BSD UNIX 在 Intel 80386 个人计算机平台上的首次完整移植；386BSD 的安全基线本质上是 4.3BSD-Reno 安全机制在 80386 平台的移植，未引入新的安全机制——root/超级用户二元特权模型（继承自 Research UNIX v4）、文件权限 rwx 三段式结构（继承自 UNIX v4/v6）、setuid/setgid 机制（继承自 UNIX v6）、基于 DES 的 **crypt(3)** 密码散列（继承自 UNIX v7）、单文件 **`/etc/passwd`**（未引入 shadow password）、4.3BSD 网络栈远程漏洞面（sendmail DEBUG、fingerd 缓冲区溢出、**`~/.rhosts`** 信任链）；386BSD 未引入 securelevel（4.4BSD-Lite 才引入）、未引入 chroot 安全沙箱用途（chroot 在 4.4BSD-Lite 时期仍为构建隔离用途）、未引入 shadow password（System V 才有 **`/etc/shadow`**，BSD 延续单 **`/etc/passwd`** 直至 FreeBSD 4.x 才弥合）。386BSD 安全基线机制对照如下：

| 安全机制 | 来源 | 386BSD 引入 |
| ------ | -- | --------- |
| root/超级用户二元特权模型 | Research UNIX v4 | 继承 |
| 文件权限 rwx 三段式结构 | UNIX v4/v6 | 继承 |
| setuid/setgid 机制 | UNIX v6 | 继承 |
| **crypt(3)** DES 密码散列 | UNIX v7 | 继承 |
| 单 **`/etc/passwd`** | 4.3BSD-Reno | 继承 |
| 4.3BSD 网络栈远程漏洞面 | 4.3BSD-Reno | 继承 |
| securelevel | 4.4BSD-Lite | 未引入 |
| chroot 安全沙箱用途 | 4.4BSD-Lite | 未引入 |
| shadow password | System V | 未引入 |

**史料**：386BSD 0.0 与 0.1 源代码与 release notes（1992）；Bill Jolitz 与 Lynne Jolitz 在 Dr. Dobb's Journal 的 386BSD 移植系列文章（1991 年起）；CSRG 邮件列表存档（1991-1994）；Networking Release 2（Net-2）发布说明（1991） ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：386BSD 安全基线是 BSD 前安全史（1969-1992）与 BSD 后安全史（1992 年后四大 BSD CVE 漏洞史）之间的关键过渡，386BSD 将 BSD UNIX 安全基因从 VAX 与 Sun 工作站的学术场景带入个人计算机平台；硬件与软件辩证：Intel 80386 的 32 位地址空间与硬件 MMU 是 BSD PC 化的硬件前提，386BSD 安全机制在 80386 平台的移植是硬件发展推动软件演化的具体呈现（“硬件与软件辩证” 为本章专题语，未对应总纲 25 条单一条目，故不设条号）

**辨析**：386BSD 安全基线的具体内容须区分 “继承自 4.3BSD-Reno” 与 “386BSD 新引入”——386BSD 未引入任何新的安全机制，所有安全机制均继承自 4.3BSD-Reno；386BSD 未引入 securelevel 的考据基于 4.4BSD SMM: 16《On the Security of UNIX》中关于 securelevel 的描述（4.4BSD 引入）与 386BSD 0.0/0.1 源代码的对照，386BSD 源代码中未发现 securelevel 相关代码；386BSD 未引入 shadow password 的考据基于 386BSD 0.0/0.1 源代码中 `/etc/passwd` 格式与 System V `/etc/shadow` 的对照；【0 信任原则·当事人自述需交叉验证】Bill Jolitz 与 Lynne Jolitz 在 Dr. Dobb's Journal 的连载文章须与 386BSD 0.0/0.1 源代码、CSRG 邮件列表存档交叉验证
