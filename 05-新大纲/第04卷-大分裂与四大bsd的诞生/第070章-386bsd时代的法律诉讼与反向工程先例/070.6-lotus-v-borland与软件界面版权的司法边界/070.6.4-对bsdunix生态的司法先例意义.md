# 070.6.4 对 BSD/UNIX 生态的司法先例意义

**要点**：Lotus v. Borland 对 BSD/UNIX 生态的司法先例意义有三：(1) 确立“用户操作界面（菜单、命令层级）属操作方法、不可版权”的裁判路径，为后续独立实现兼容界面的软件（含 BSD 衍生系统）提供界面自由的法律背书；(2) 与 Sega v. Accolade 的反向工程合理使用先例互补——前者管“界面本身不可版权”、后者管“为兼容而复制界面可免责”，共同构成 1990 年代软件互操作性的司法双支柱；(3) 案件争议的实质——界面是“表达”还是“功能”——与 BSD 社区在 Net/2 重写运动中“重写 AT&T 代码但保留接口”的工程实践高度同构，接口与实现之分在此获得法律语言表达；该案与 USL v. BSDi（本卷 40-42 章）同期（1990-1994），共同反映 1990 年代初软件版权诉讼激增的法律环境

**史料**：Lotus v. Borland 一、二审及最高法院判决书（1993/1995/1996）；Sega v. Accolade 判决书（977 F.2d 1510）；CSRG Net/2 重写工程记录（第041章 38.1-38.6）；USL v. BSDi 案卷（本卷 40-42 章） ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：“操作方法不可版权”是 BSD 式“接口兼容、实现独立”工程哲学的法律镜像：BSD 项目以重写实现换取接口兼容，Lotus 案以排除界面版权保障兼容自由，法律结构与技术实践在此同构互证

**辨析**：须避免过度引申——Lotus 案仅涉及菜单命令层级（用户界面），未直接解决 API 声明代码（declaring code）的版权问题；2014 年联邦巡回法院在 Oracle v. Google 中明确区分二者，认定 Java API 声明代码可版权（750 F.3d 1339, Fed. Cir. 2014），2021 年最高法院虽维持 Google 胜诉但基于合理使用而非“API 不可版权”（593 U.S. 1, 2021，见第161章 148.10）——因此“Lotus 案确立界面一律不可版权”属过度概括，准确表述应为“菜单命令层级作为操作方法不可版权，且此结论因平票无全国先例效力” ［A］

**文献**：Lotus Dev. Corp. v. Borland Int'l, Inc., 49 F.3d 807 (1st Cir. 1995) & 516 U.S. 233 (1996)；Oracle Am., Inc. v. Google Inc., 750 F.3d 1339 (Fed. Cir. 2014)；Google LLC v. Oracle America, Inc., 593 U.S. 1 (2021)；Sega Enterprises, Ltd. v. Accolade, Inc., 977 F.2d 1510 (9th Cir. 1992)；CSRG Net/2 重写工程记录 ［A］
