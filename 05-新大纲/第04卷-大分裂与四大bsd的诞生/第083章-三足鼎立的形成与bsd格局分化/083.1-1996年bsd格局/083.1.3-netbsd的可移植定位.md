# 083.1.3 NetBSD 的可移植定位

  **要点**：NetBSD 选择可移植定位——聚焦多平台移植，扩展至 50+ 平台（日后累计）；定位选择决定 NetBSD 后续工程方向；netbsd.duckdb 统计结论 C-04 显示：netbsd-src 总 commit 数 774,061（SQL 查询 `SELECT COUNT(*) FROM commits WHERE repo_name='netbsd-src'`），为四 BSD 项目 src 仓库中累计 commit 量最高者——与 C-03 freebsd-src 总 commit 数 445,203（freebsd.duckdb）、C-05 openbsd-src 总 commit 数 246,535（openbsd.duckdb）对照，NetBSD 累计 commit 量约为 FreeBSD 的 1.74 倍、OpenBSD 的 3.15 倍，反映 NetBSD 在更多平台移植目标（50+ 平台）下的累计工程产出规模最大，可移植定位的工程代价体现为单平台深度优化 commit 的分散
  
**史料**：NetBSD 1.0-1.2 发布声明、NetBSD 平台支持列表、Hannum 关于可移植的公开声明［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；netbsd.duckdb 数据库证据——netbsd-src 总 commit 774,061（netbsd.duckdb）、freebsd-src 总 commit 445,203（freebsd.duckdb）、openbsd-src 总 commit 246,535（openbsd.duckdb） ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔存疑：挂条待主理人审定〕：可移植定位带来主流平台深度的牺牲；统计结论印证总纲第 15 条——文化即形式主义——C-04 netbsd-src 774,061 与 C-03 freebsd-src 445,203 的量级差异反映两项目工程组织模式的分化（NetBSD 多平台移植累计 commit 更多，FreeBSD 聚焦 x86/64 性能优化 commit 粒度可能更大），第 25 章分离聚合是永恒规律在 commit 量层面得到量化印证
  
**辨析**：定位选择的具体诱因在不同叙事中略有差异——需对照 NetBSD 早期邮件列表核实；【0 信任原则·commit 量不等于质量】C-04 netbsd-src 774,061 与 C-03 freebsd-src 445,203 的量级差异不等于两项目代码质量或工程效率的差异——commit 粒度（单次 commit 的 additions/deletions 规模）、提交习惯（小步提交 vs 大步提交）、迁移历史（CVS-to-Git 转换可能拆分或合并原 CVS commit）均影响 commit 总数，NetBSD 的多平台移植工作天然产生更多小粒度 commit（每个平台的 MI/MD 适配各为独立 commit），须结合 commit_files 表与 commit 规模综合判断；【0 信任原则·CVS-to-Git 迁移风险】netbsd-src 为 CVS 主仓的 GitHub 镜像，CVS-to-Git 转换可能重写 commit_date 字段或拆分原 CVS commit，C-04 累计 commit 总量须与 NetBSD 官方档案交叉验证；【0 信任原则·多重比较风险】C-03、C-04、C-05 跨章引用（第 26、27、28、29、30 章均引用）时存在多重比较风险，须按 Bonferroni 或 Benjamini-Hochberg 校正后解读
