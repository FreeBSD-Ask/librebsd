# 084.1.1 FreeBSD 的路线图缺失与 2021 年转折


三项目在项目战略规划上的长期缺失：FreeBSD 近 30 年无正式路线图（首份 Technology Roadmap 迟至 2021 年 9 月由 FreeBSD Foundation 发布——freebsdfoundation.org/blog/technology-roadmap，涵盖终端用户、商用服务器、工具应用、虚拟化容器四个方向，先前 FreeBSD 无任何形式化的演进规划或优先级文档）、Jordan Hubbard 2001 年辞职信揭示的“反应迟钝”即缺乏方向治理的表征、NetBSD“无截止日期”发布模式（Pronchery 2014 论文“Carve your NetBSD”："there is usually no particular deadline set with regard to when a new version should be released: it is done when considered ready"）、NetBSD 无公开的功能路线图或战略文档、OpenBSD 唯一可预测结构为六个月发布周期但无公开功能规划、对比 Linux 内核开发模式（两周合并窗口、-rc 候选发布周期、documented roadmap）、对比 Red Hat/Canonical/SUSE 商业路线图、LWN 评价“FreeBSD 很大，它很旧，而且它行动迟缓”

  **要点**：FreeBSD 近 **30 年** 无正式路线图——首份 Technology Roadmap 迟至 **2021 年 9 月** 由 FreeBSD Foundation 发布，涵盖终端用户、商用服务器、工具应用、虚拟化容器四个方向；先前 FreeBSD 无任何形式化的发展规划或优先级文档。BSD vs Linux 路线图对比对照如下：

| 项目 | 路线图状态 | 发布模式 | 可预测性 |
| -- | -------- | ------ | ------ |
| FreeBSD | **2021 年 9 月** 首份 Technology Roadmap | — | 近 30 年无规划 |
| NetBSD | 无公开功能路线图 | “无截止日期”发布模式（“it is done when considered ready”） | 低 |
| OpenBSD | 无公开功能规划 | 六个月发布周期 | 发布周期可预测，功能不可预测 |
| Linux 内核 | documented roadmap | 两周合并窗口、-rc 候选发布周期 | 高 |
| Red Hat/Canonical/SUSE | 完整商业路线图 | 商业发布周期 | 高 |
