# 381.5 386BSD 的技术目标与历史意义

## 381.5.1 设计目标与四项技术革新

  **要点**：386BSD 的设计目标是在 commodity 386 硬件上提供完整、自由、可自举的 BSD 系统；其公认的技术革新包括四项——role-based security（角色安全）、ring buffers（环形缓冲）、self-ordered configuration（自序配置）与 modular kernel design（模块化内核设计）；386BSD 1.0（1994）则宣称“全新的内核设计与实现”，并开始纳入早期伯克利设计者提出但 BSD 从未实践过的建议；其历史意义在于：一者证明 BSD 内核可在廉价 x86 上稳定运行，二者为 USL 诉讼后 BSD 的重建提供不经诉讼限制的自由代码线，三者直接成为 FreeBSD 与 NetBSD 的共同基线——所有现代 BSD 均可溯源至 386BSD
  
**史料**：386BSD 0.1 源码树（TUHS／freebsd.org 历史归档）；386BSD 条目（四项革新表述）<https://en.chped.com/wiki/386BSD>［2026-10-03 访问］；386BSD 官方站 <https://www.386bsd.org/about>；historical_claims.duckdb CL-4-002（386BSD 规格将 386 内存管理列为独立主题章节）；Jolitz 夫妇《Operating System Source Code Secrets》两卷（1996／2000）［A］
  
**史观**：
- 总纲第 10 条——动手者创造历史：四项革新皆以代码形态存世，其“革新”地位由下游项目的继承（而非宣言）确证
- 总纲第 12 条——形式主义的嵌套：role-based security 的形式后来嵌套于 TrustedBSD 等能力模型谱系，革新是形式体系的再组合
- 总纲第 17 条——证明世界先于解释和改造世界：386BSD 先“做成”，后“被解释”为分水岭——分水岭地位是史学后设判断，非 1992 年当事人的自我宣称
- 总纲第 4 条——分离聚合是永恒规律：386BSD 的技术遗产在 FreeBSD／NetBSD 的分叉中分离，又在共同用户空间传统中聚合
- 总纲第 25 条——终结中的延续：386BSD 项目 1997 年后停止公开发行，但其形式遗产延续于全部现代 BSD
  
**辨析**：四项革新的名目取自外部条目化表述（wiki 系），Jolitz 原始文献中的对应设计（如自序配置见其 DDJ 连载 Device Autoconfiguration 一篇）须逐项回溯原文核对，勿以条目名目替代原始设计名；1.0“全新内核设计”系 386BSD 官方站口径，与 0.x 的 Net/2 继承关系并陈——1.0 与 0.1 之间设计断裂程度无第三方源码 diff 研究支撑；“所有现代 BSD 溯源 386BSD”须限定为谱系意义（FreeBSD／NetBSD 以 0.1 为 import 基线），OpenBSD 溯源 NetBSD、DragonFly 溯源 FreeBSD，为间接继承链
