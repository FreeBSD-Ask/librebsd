# 018.5.1 Linus Torvalds 对 C++ 的公开发难：1992 年尝试、2004 年 LKML 邮件与 2007 年 Git 选择 C 的理由

**要点**：Linus Torvalds 对 C++ 的批评贯穿 Linux 内核项目三十余年，形成三条主线：(1) 1992 年 Linux 内核早期曾尝试使用 C++ 编写内核代码，Torvalds 在 2004 年 LKML 邮件中回溯此次经验为"It sucks. Trust me - writing kernel code in C++ is a BLOODY STUPID IDEA."，称 1992 年的尝试为其 C++ 立场的直接经验来源；(2) 2004 年 1 月 19 日（PST），Torvalds 在 LKML 回复 Robin Rosenberg 关于 C++ 内核模块编译的讨论时（邮件主题"Re: Compiling C++ kernel module + Makefile"，由 Click Modular Router 自 2.4 至 2.6 内核移植问题引发），系统阐述了反对 C++ 的三大理由：异常处理机制在内核中"fundamentally broken"、编译器在背后隐藏内存分配不可接受、C 语言本身足以写出面向对象代码（如文件系统 VFS 层）；(3) 2007 年 9 月 6 日（BST，对应 UTC 9 月 6 日 17:50），Torvalds 在 Git 邮件列表（gmane.comp.version-control.git）与 Microsoft 工程师 Dmitry Kakurin 争论 Git 为何用 C 而非 C++ 时，发表了最为激烈也最为著名的批评："C++ is a horrible language... even if the choice of C were to do *nothing* but keep the C++ programmers out, that in itself would be a huge reason to use C."，并进一步批评 STL 和 Boost 导致"infinite amounts of pain"和"inefficient abstracted programming models"；这三条主线共同构成 Torvalds 从 C++ 支持者（大学时期使用 C++）到 C++ 反对者的完整转变叙事，其立场在 2022 年 Linux 6.1 接纳 Rust 为内核第二语言时被反复引用作为对比参照

**史料**：Torvalds 2004-01-19 LKML 邮件（Date: Mon, 19 Jan 2004 22:46:23 -0800 (PST)，回复 Robin Rosenberg，主题"Re: Compiling C++ kernel module + Makefile"，KernelTrap node/2067 存档）、Torvalds 2007-09-06 Git 邮件列表（gmane.comp.version-control.git，Date: Thu, 6 Sep 2007 18:50:28 +0100 (BST)，Message-ID: <alpine.LFD.0.999.0709061839510.5626@evo.linux-foundation.org>，LWN.net Article 249460 一手存档）、Torvalds 1992 C++ 尝试的二次引述（2004 邮件中提及）、Torvalds 1991 comp.os.minix 首次 Linux 公告 ［A］

**史观**：总纲第 4 条与第 17 条——分离聚合与证明世界先于解释和改造世界。项目史观总纲第 25 章载 “分离聚合是永恒规律”——内核语言选择是工程权衡与个人经验共同作用的结果，C 与 C++ 的路线分化即分离聚合的具体呈现

**辨析**：Torvalds 的 C++ 批评是否应被理解为技术真理还是个人偏好——需区分技术论证（异常处理、内存管理、ABI 稳定性）与修辞策略（"horrible language""BLOODY STUPID IDEA"）；Torvalds 2004 年邮件中"we did try C++ once already, back in 1992"的具体细节缺乏一手文档（1992 年 Linux 内核尚在 0.1x 版本，邮件列表存档不完整），仅能从 Torvalds 后续回忆中推断；2007 年 Git 邮件中 Torvalds 以 Monotone（C++ 编写的 VCS）为例说明 C++ 项目"horrible and unmaintainable"，但此批评的适用性因 Monotone 与 Git 的设计目标差异而存疑；Torvalds 本人 2022 年接纳 Rust 入内核时态度缓和，称“Rust 不是 C++”，暗示其反对的是 C++ 而非“非 C 语言”本身；[考据脚注] 2007 Git 邮件时区经 LWN.net Article 249460 一手档案邮件 Date 头 "Thu, 6 Sep 2007 18:50:28 +0100 (BST)" 复核——BST 为英国夏令时（UTC+1），对应 UTC 9 月 6 日 17:50:28，早期修正稿曾误标为 “9 月 5 日（PST）/ 9 月 6 日（UTC）”，实际即便换算为 PST（UTC-8）亦为 9 月 6 日 09:50:28，“9 月 5 日（PST）” 表述错误，已修正
