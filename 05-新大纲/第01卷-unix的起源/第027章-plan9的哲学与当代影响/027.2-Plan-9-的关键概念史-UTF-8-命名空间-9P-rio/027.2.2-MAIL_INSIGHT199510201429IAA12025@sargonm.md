**观点**：1995 年 10 月，Alan F Lundin 在 freebsd-hackers 引用 Ron G. Minnich 的话，称其约一年前实现了简化版 Plan 9 rfork()，可共享数据空间与文件表，并配以简单锁原语，认为这几乎与内核线程一样好。
**邮件来源**：Alan F Lundin（引 Ron G. Minnich），freebsd-hackers，1995-10-20，Message-ID: `199510201429.IAA12025@sargon.mdl.sandia.gov`
**史学意义**：记录 Plan 9 的 rfork 进程模型在 1995 年被 BSD 开发者实际实现，是 Plan 9 关键概念向 UNIX/BSD 迁移的实例。

**要点**：

- 独立开发者以“告别 GPL”为题撰文，论证 copyleft 在云软件（SaaS）时代已失去实际效用：其仅存的用武之地是 MongoDB、Elastic 等商业厂商对抗云巨头的业务动机，而 FSF 在 Stallman 复职风波后既无应对云软件威胁的方案，也持续重复数十年前的论调，作者因此主张改用 MIT、BSD、Apache 2.0 等宽松许可证，并把精力转向反垄断、可持续商业模式与用户利益优先的监管。（BSD Now EP402，[282.18-516.52]，L2）
- AWS 工程师 Samuel Karp 开源 RunJ，一个面向 FreeBSD Jails 的实验性 OCI 兼容容器运行时；因 runc 与 containerd 现有 shim 深度假设 Linux 内核接口（cgroups、namespaces），作者选择从零实现而非移植，并附带自写 containerd shim，为 OCI 镜像生态进入 FreeBSD 打开通道，随后即有社区志愿者将其导入 ports。（BSD Now EP402，[716.66-918.42]，L2）
- 前微软 Xenix 团队成员回顾 1980-1989 年 Xenix 史：Xenix 为 AT&T Unix 的移植打包版本，1980 年 8 月 25 日经《Computerworld》公告上市、单套定价 2000 至 9000 美元；微软持有商标与 Unix 母许可证并向各 OEM 再授权，1983 年为 IBM PC AT（代号 Salmon）完成移植，后因放弃零售市场而与 Santa Cruz Operation（SCO）达成打包、销售与支持协议，1989 年团队解散。（BSD Now EP402，[919.42-1253.24]，L2）
- FreeBSD 开发者 Warner Losh 更新 QEMU bsd-user 用户态模拟分支：为摆脱数千补丁 rebase 的僵局，他将基于 3.1 的 bsd-user 目录直接并入 QEMU 6.0 并设 Blitz（快速可用）与 Kaizen（持续缩减 diff、先保 x86）双分支，与上游达成原则上每月合并的协议，目标是恢复以用户态模拟加速 FreeBSD 跨架构包构建的能力。（BSD Now EP402，[1254.24-1524.86]，L1）
- 2009 年 HP 老笔记本安装 FreeBSD 13.0 的实践记录：作者借 OpenZFS 2.0 原生数据集加密之机重装并加密 ZFS 池，经 i915 KMS 声卡 hint、微码加载、电源管理与 RAM disk home 等配置后成为轻量工作站，作者以 vi/Emacs、Firefox、LibreOffice 与 SSH 工作流证明旧硬件上的 FreeBSD 桌面仍然可用，同时折射出 base 系统对老硬件支持持续收窄的边界。（BSD Now EP402，[1604.78-1976.64]，L2）
- 新闻汇编：FreeBSD 开发者峰会（2021 年 6 月 9-11 日）开放注册并以直播与跨时区分场扩大参与；DragonFly BSD 6.0 RC1 镜像发布；Rob Pike 论文重提 Plan 9 词法文件名与符号链接破坏 Unix 层级路径语义的问题；OpenBSD 由 Dale Rahn 提交 64 位 RISC-V 架构初始支持，技术基础为 Brian Bamsch 等人的移植论文。（BSD Now EP402，[1976.64-2331.46]，L2）
- 个人史与结缘路径：二十四岁的德国人，六岁起接触电脑，经 MS-DOS、汇编、Pascal 学至 C、make 与 shell；1997 至 1998 年间转向 Linux，先在无互联网条件下以软盘从学校运回软件包、自建追求小体积的 libc5 系统，并用这套自制系统完成首次拨号上网；随后经书籍认识 FreeBSD、NetBSD 与 OpenBSD，OpenBSD 2.4 初试、2.9 发布前购入即喜欢上，从此弃用 Linux，仅保留 MS-DOS 作直接硬件访问与引导器实验之用。（BSDTalk EP81，[111.76-239.56]，L1）
- MirOS 分叉起源：以 32.6k 调制解调器拉取源码并跟踪 OpenBSD CVS 仓库，较早掌握 CVS；改进尝试以邮件提交后遭遇 flame 与无视——后来得知其他外部投稿者遭遇相同；遂将自建的 OpenBSD patchkit 公开，主页提供 diff 集、生成脚本与二进制；与上游决裂后自建 CVS 仓库、导入 OpenBSD 源码打上补丁继续开发——其时他从未成为 OpenBSD 开发者。（BSDTalk EP81，[255.32-354.02]，L1）
- 项目命名与多内核雄心：项目名从 OpenBSD Current Mirabila、BSD Mirabila 缩为 MirBSD——Mirabilis 拉丁语义兼奇妙与怪异（时人对其昵称），Mir 又取俄语和平与世界之义，自称奇妙而和平世界的操作系统；起初只是其个人源码与 ports 树的昵称，其他开发者加入后（一人至今活跃）因计划向用户提供多内核选择——BSD 内核或带专有驱动的 Linux 内核（其本人从未使用）——改称 MirOS 项目，定位为同一 BSD 观感的基础操作系统。（BSDTalk EP81，[356.26-426.12]，L1）
- 与 OpenBSD 的差异自述：自视为更好的 OpenBSD、时而偏向 NetBSD 方向；精简取向——移除受众用不到的 Kerberos、全量按体积优化编译使启动软盘容纳更多内容；外部工具更新更勤（新工具链、文本浏览器、ncurses 自 5.2 升 5.5 并加 Unicode）；移植框架独立演进——起于 OpenBSD ports，在 Marc Espie 转用 Perl 重写时不跟进，自行按可移植性方向改进，框架亦可运行于其他操作系统；更早转向 ELF；base 系统弃 groff 改用 4.4BSD alpha 的 AT&T nroff，且不残留任何 C++ 代码。（BSDTalk EP81，[444.12-553.80]，L1）
- 平台版图与 SMP 拒绝：现支持 i386，两版前因友人捐赠的机器支持过 SPARC，复活计划因 i386 负担搁置；AMD64 因听闻 NetBSD 与 OpenBSD 实现欠稳而宁守两个稳定平台；对 SMP 明确说不——合并 OpenBSD 4.0 增强时代码会包含但禁用，理由是其实现方式不对、BSD 内核结构不适宜多处理、单处理器内核有时反而更快；项目没有内核程序员，未来数年不拟支持 SMP，优先工作是把 wscons 控制台代码转为 Unicode。（BSDTalk EP81，[553.80-663.48]，L1）
- 发布与兼容策略：稳定版 MirOS 9 以十进制编号；开发快照经 BitTorrent 分发、上传前必经测试保证可引导可安装，CVS head 则不保证可构建——提交有时仅为异地备份；安装器继承自 OpenBSD；以库版本号递升保障旧程序——系统上可同时共存三四个大版本 C 库，数月前编译的 MPlayer 依然可运行；提供 OpenBSD 二进制兼容层，几乎可运行任何 OpenBSD 3.8 程序，因内核偏离远小于系统其余部分而实现容易。（BSDTalk EP81，[663.48-771.28]，L1）
- Unicode 的 Plan 9 路线：明确不走完整国际化路线并直陈不相信它，而取 Plan 9 式终局——最终只保留 UTF-8 与标准要求的七位 C locale；已实现 libc 宽字符所需部分、升级 ncurses 使既有应用可显示宽字符（中文昵称的 MSN 联系人可正常显示）、shell 将 UTF-8 字符按单字符处理。（BSDTalk EP81，[1010.16-1066.12]，L1）
- FreeWRT 协作与跨平台构建：协助友人 Waldemar Brodkopf 自 OpenWRT 分叉的 FreeWRT——面向 Netgear 等无线路由器的嵌入式 GNU/Linux——承担交叉编译、工具链、构建系统与 diff 审读；OpenWRT 原本只能在 Linux 上自行编译，经其工作可在 BSD 上构建，并计划扩展 Cygwin 与 Mac OS X 可编译性。（BSDTalk EP81，[826.60-891.20]，L1）
- 团队结构与欧洲展会网络：Benny Siegert——萨尔州化学专业学生、非 IT 背景——承担 ports 基础设施，所继承自 OpenBSD、NetBSD 再上溯 FreeBSD 的老程序（一个 C 文件内并存三种缩进风格）被持续改进，另负责全部 GNOME 及因商标原因重命名的当前 Firefox 移植；两人把 FOSDEM、FrOSCon、Chaos Communication Congress、LinuxTag 当作迷你 hackathon；首届 FrOSCon 上曾携咖啡机为 BSD 摊位提供免费咖啡；近期移植支持网络对战的 Frozen Bubble 2，其框架同时可运行于 Mac OS X 与 OpenBSD。（BSDTalk EP81，[895.20-992.52]，L1）

**史观**：

- 总纲13 法律与道德是利益分配：“告别 GPL”论断的核心是把许可证还原为利益分配装置：copyleft 的道德叙事在 MongoDB、Elastic 等厂商手中显形为阻止云厂商搭便车的商业工具，许可证之争的本质由此成为软件利益结构的再分配之争。（BSD Now EP402，[403.02-432.58]，L2）
- 总纲3 不存在进步，只有权力再分配：主持人以“不可能拿到一个不含 BSD 代码的专有 SDK”反驳 GPL 阵营的道德话语，指出宽松分发实际改变了软件权力的分布；两种许可证路线的消长并非技术进步，而是分发权力结构的再平衡。（BSD Now EP402，[623.42-669.34]，L2）
- 总纲5 没有必然性，只有偶然性：UTF-8 的诞生史是偶然性改写标准的典型案例：编码方案在餐馆餐垫上于一夜成形，一周内完成全系统实现，这一无预谋的偶然设计此后支撑起整个互联网的文本层。（BSD Now EP402，[2236.8-2268.02]，L1）
- 总纲10 动手者创造历史：Warner Losh 数年维护 bsd-user、自嘲“最后的孤注一掷”式目录拷贝并以 Blitz/Kaizen 分支推进上游化，展示了动手者叙事：决定 FreeBSD 交叉构建生态存续的不是路线图，而是个别工程师对数千补丁的持续清理。（BSD Now EP402，[1254.24-1335.08]，L1）
- 总纲1 一切真历史都是古代史：Xenix 回忆与散伙饭上的时间线考据表明，微软 Unix 史的书写必须回到“古代”档案与当事人记忆中重构；当下对 Xenix 的普遍误解正源于这段历史长期无人书写。（BSD Now EP402，[919.42-1232.8]，L2）
- 总纲5 没有必然性，只有偶然性：MirOS 的存在本身是偶然链的产物：一台 32.6k 调制解调器拉回的源码、一封引来 flame 的邮件、一连串被无视的投稿——分叉并非路线图的必然，而是社区互动中偶然条件的累积；当事人自己把项目命名解释为兼具奇妙与怪异，无意间为这条偶然路径作了注脚。（BSDTalk EP81，[274.96-354.02]，L1）
- 总纲15 文化即形式主义：完整国际化是一套多元 locale 的形式体系，MirOS 选择了以单一 UTF-8 编码将其消解的 Plan 9 路线——只留 UTF-8 与标准强制的七位 C locale；当事人直陈不相信完整国际化，把字符处理还原为编码本身而非层层 locale 形式。（BSDTalk EP81，[1052.36-1066.12]，L1）

**辨析**：

- “告别 GPL”文章的作者归属在转写中存在噪声：主持人将文章与 local-first software 论文作者（Kleppmann 等）并置转述，作者身份与论文关系须以原文署名核实。[存疑脚注] 转写将 Martin Kleppmann 读作文章作者，须核对原文署名 [存疑脚注] 文章作者身份与 local-first 论文作者关系系主持人转述，转写噪声明显，须以原文署名核实（BSD Now EP402，[322.02-349.9]，L4）
- Xenix 时间线作者自称 1986 年入职时为团队最资浅者，1986 年前的 OEM 关系其本人无亲历知识，时间线系资深同事协作成果；转写未署名，人物归属待考。[考据脚注] 时间线作者姓名在转写中缺失，须回溯原文核对 [存疑脚注] Xenix 时间线作者身份未署名，1986 年前内容系二手追述（BSD Now EP402，[949.5-962.14]，L4）
- 主持人“广告条款几乎已从所有软件中消失”的说法系概括性陈述：4-Clause BSD 广告条款于 1999 年由 UC Berkeley 正式废除，但“remnants 存在与否”无法在对话中核验。（BSD Now EP402，[585.46-592.34]，L2）
- OpenBSD RISC-V 初始支持的功劳归属存在两层：commit 落于 Dale Rahn，技术基础是 Bamsch 等人的移植论文；主持人的致谢转述对两代贡献的边界较模糊，引用时宜并置。（BSD Now EP402，[2284.52-2314.22]，L2）
- 转写术语失真严重：MirOS、ncurses、nroff、groff、FOSDEM、FrOSCon、Chaos Communication Congress、OpenWRT、Waldemar Brodkopf 等均按通行拼写校正；更好的 OpenBSD 为主观自我定位；对 AMD64 稳定性的负面评论系道听途说，当事人自承仅凭所闻。[存疑脚注] AMD64 稳定性评价与 OpenBSD SMP 决策背景均为单方转述。 [存疑脚注] AMD64 稳定性评价为传闻转述，SMP 决策原因未与 OpenBSD 方核对（BSDTalk EP81，[591.72-635.64]，L4）
