# 016.2.4 Lisp 在 FreeBSD Ports 中的生态

**要点**：FreeBSD Ports 提供多种 Lisp 实现——SBCL、CLISP、ECL、Clozure CL；Lisp 生态在 FreeBSD 中虽非主流但稳定延续

**史料**：FreeBSD Ports Lisp 类目、SBCL FreeBSD 移植文档 [考据脚注·Lisp 在 FreeBSD Ports 生态的考据过程] 经三轮 WebSearch 与 WebFetch 核实：其一，FreeBSD Ports 官方 cgit 仓库（cgit.freebsd.org/ports/plain/lang/sbcl/Makefile，2026-07-28 WebFetch 核实）显示 lang/sbcl 端口当前版本为 2.6.6（DISTVERSION = 2.6.6，DISTVERSIONSUFFIX =-source，PORTEPOCH = 1），维护者字段为 `MAINTAINER=krion@FreeBSD.org`（Kirill Ponomarev，FreeBSD 提交者），支持架构为 amd64/i386/powerpc64/powerpc64le，许可证为 BSD2CLAUSE 与 PD 双重许可，注释明确 "Common Lisp development system derived from the CMU CL system"；其二，FreeBSD Ports 官方 cgit 仓库（cgit.freebsd.org/ports/plain/lang/clisp/Makefile，2026-07-28 WebFetch 核实）显示 lang/clisp 端口当前版本为 2.49.95+20241228（PORTVERSION = 2.49.95+20241228，PORTREVISION = 3），维护者字段为 `MAINTAINER=kiri@TrueFC.org`（Sam Steingold，CLISP 核心维护者之一），源代码来自 GNU GitLab（GL_ACCOUNT = gnu-clisp，GL_TAGNAME = c3ec11bab87cfdbeba01523ed88ac2a16b22304d），许可证为 GPLv2；其三，SBCL 官方平台表（sbcl.org/platform-table.html，2026-07-28 WebFetch 核实）显示 FreeBSD 平台的官方预编译二进制支持滞后——x86-64 与 x86 停留于 1.2.7 版本（2014 年发布），ARM64 停留于 2.2.0 版本（2022 年发布），而最新源代码版本为 2.6.6（2026-06-28 发布），表明 FreeBSD 平台的官方二进制支持非最优先（Linux 与 Windows 为最优先平台），但通过 Ports 系统从源代码构建可获取最新版本；其四，原辨析字段中 “SBCL FreeBSD 移植维护者多年为 Bruno Haible 与 Christophe Rhodes 轮值” 的说法存在事实错误——Bruno Haible（CLISP 原作者）与 Christophe Rhodes（SBCL 核心开发者之一）均为上游项目维护者而非 FreeBSD Ports 维护者，FreeBSD Ports 的实际维护者为 <krion@FreeBSD.org>（SBCL）与 <kiri@TrueFC.org>（CLISP），已据此纠正。综上，FreeBSD Lisp 生态稳定延续但非主流，维护者上游与下游分离——上游项目（SBCL/CLISP）的核心开发者不直接承担 FreeBSD Ports 维护，Ports 维护由 FreeBSD 提交者承担。

**史观**：终结与延续：Lisp 在 FreeBSD 中的延续

**辨析**：FreeBSD Lisp 生态的实际使用规模无精确统计——Ports 下载量数据由 FreeBSD Foundation 内部持有未公开发布，邮件列表 freebsd-lisp 与 freebsd-common-lisp 讨论频率长期低位稳定，未形成规模性用户群；维护者结构方面，FreeBSD Ports 的 SBCL 维护者为 <krion@FreeBSD.org>（Kirill Ponomarev），CLISP 维护者为 <kiri@TrueFC.org>（Sam Steingold，CLISP 上游核心维护者之一），二者均为 FreeBSD Ports 层面的维护者而非 SBCL/CLISP 上游项目的核心开发者（SBCL 上游核心开发者包括 Christophe Rhodes、Juho Snellman 等，CLISP 上游核心开发者包括 Bruno Haible、Sam Steingold 等）；SBCL 官方对 FreeBSD 平台的二进制支持滞后于 Linux/Windows，但源代码构建路径长期可用
