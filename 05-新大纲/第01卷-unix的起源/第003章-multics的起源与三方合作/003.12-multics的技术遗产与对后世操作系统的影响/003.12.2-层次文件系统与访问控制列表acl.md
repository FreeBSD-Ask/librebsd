# 003.12.2 层次文件系统与访问控制列表（ACL）

**要点**：Multics 首次实现了层次文件系统——目录树结构——以及基于访问控制列表（ACL）的细粒度权限管理。这一设计直接为 Unix 的目录结构与文件权限模型提供了参照（尽管 Unix 简化为 owner/group/other 三级模型），也为 Windows NTFS 的 ACL 体系提供了先例。Multics 还支持文件的长名称、多名称链接、符号链接与存储配额——这些特性在后续系统中逐项被重新发明。

**史料**：R. C. Daley 与 P. G. Neumann, “A General-Purpose File System For Secondary Storage,” FJCC 1965（Multics 文件系统原始设计论文）；multicians.org/features.html 对文件系统特性的枚举 ［A］；本地档案：MSPM 文件系统章节（`03-原始史料库/12-multics史料/02-mit-saltzer/MSPM/` 与 `01-multicians-org/mspm/`）

**史观**：法律结构对技术创新的制约与解放：Multics 文件系统的复杂性在 Unix 中被刻意简化，这种简化既是工程选择的产物，也是 AT&T 1956 年同意令下的资源约束结果——Bell Labs 退出了 Multics 的高成本路线，转而追求可快速实现的“够用”方案。

**辨析**：Unix 三级权限模型（owner/group/other）虽比 Multics ACL 简单，但具有“足够好”的工程特性——这也是 Unix 传播成功的关键。然而，当前云计算多租户场景中 ACL 的回归（如 AWS IAM、Kubernetes RBAC）说明 Multics 的 ACL 理念从未真正过时。

**文献**：R. C. Daley & P. G. Neumann, “A General-Purpose File System For Secondary Storage,” Proceedings of the FJCC, 1965; multicians.org/features.html; Marshall Kirk McKusick（马歇尔·柯克·麦库西克） et al., "The Design and Implementation of the FreeBSD Operating System," 2nd ed., 2014（文件系统权限演化章节） ［A］
