# 023.8.1 年JohnMcCarthy约翰麦卡锡MIT设计LISP详见222222早期高级语

## 要点

1958-1960 年，John McCarthy（约翰·麦卡锡）（MIT）设计 LISP（详见 [22.2](../023.2-早期高级语言-Fortran-LISP-ALGOL-COBOL/)），首个函数式编程语言；LISP 的演化谱系：LISP 1.5（1960）→ MacLISP（1966，MIT）→ InterLISP（1967，BBN）→ Franz LISP（1978，伯克利）→ Common Lisp（1984，ANSI CL 标准化）→ Scheme（1975，MIT，最小化方言）→ Clojure（2007，Rich Hickey，运行于 JVM）→ Racket（1994，PLT）。
1973 年，Robin Milner（爱丁堡大学）设计 ML（Meta Language），最初为 LCF 定理证明器的元语言；ML 的核心创新在于 “静态类型推断（Hindley-Milner 类型系统）、代数数据类型（algebraic data type）、模式匹配（pattern matching）、多态类型”；ML 的演化谱系：Standard ML（SML, 1990）→ Caml（1987，INRIA）→ OCaml（1996，INRIA，引入对象与模块）→ F#（2005，Microsoft，运行于 .NET）。
1990 年，Haskell 1.0 由 Haskell 委员会（Philip Wadler、Simon Peyton Jones 等）发布，命名取自 Haskell Curry（数理逻辑学家）；Haskell 的核心创新在于 “纯函数式（purely functional）、惰性求值（lazy evaluation）、单子（monad）处理副作用”；Haskell 演化至 Haskell 2010（最新标准）；Haskell 在学术界影响深远，但在工业界采用有限（Facebook Sigma、Cardano 区块链等项目使用）。
1986 年，Joe Armstrong（Ericsson）设计 Erlang，专为电信交换机高并发容错系统设计；Erlang 的核心创新在于 “actor 模型（轻量级进程）、消息传递（无共享内存）、热代码替换（hot code swap）、‘let it crash’ 容错哲学”；Erlang 在电信（Ericsson AXD301 交换机）、即时通讯（WhatsApp 后端）、数据库（CouchDB）等领域应用；Elixir（2012，José Valim）运行于 Erlang VM（BEAM），融合 Ruby 语法与 Erlang 并发模型。
2014 年，Apple 推出 Swift（Chris Lattner 主导），融合多范式（面向对象、函数式、协议导向）；Swift 的核心创新在于 “类型安全（type safety）、可选类型（optional）、协议扩展（protocol extension）、值语义（value semantics）”；Swift 为 Apple 平台（macOS、iOS、watchOS、tvOS）的主要开发语言，2026 年 Swift 5.10 为最新版本，Swift 6.0（2024）引入严格并发检查。
其他函数式与多范式语言：Scala（2004，Martin Odersky，融合面向对象与函数式，运行于 JVM）、Kotlin（2011，JetBrains，Android 官方语言之一）、Clojure（2007，Rich Hickey，LISP 方言，运行于 JVM）、F#（2005，Microsoft，ML 方言，运行于 .NET）等。

## 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 4（分离聚合是永恒规律）**——见 据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

函数式语言的演化呈现分离聚合——LISP 谱系（LISP 1.5 → Common Lisp → Scheme → Clojure）从分离（不同方言）到部分聚合（Common Lisp 标准化），ML 谱系（ML → SML → OCaml → F#）从分离（不同实现）到部分聚合（Hindley-Milner 类型系统共享），函数式与面向对象从分离（LISP/ML vs Smalltalk/C++）到聚合（Scala、Swift、Python 多范式）——这一系列分离聚合并非线性进步，而是不同形式主义的循环呈现。

**总纲 1（形式主义是世界的真实存在）**——见 据原文第 1 章 1.1-1.2 节：

> “形式主义是世界的真实存在，其余一切存在皆不真实。”

所谓 “函数式编程” 作为一种形式主义化的建构——纯函数、不可变性、高阶函数、惰性求值等特性并非 “客观最优” 的发现，而是 McCarthy、Milner、Wadler 等设计师对 “何为编程” 这一问题的主体性选择；面向对象、过程式、逻辑式等编程范式亦是形式主义化的不同呈现。

**总纲 3（不存在进步，只有权力再分配）**——见 据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

函数式语言在工业界的采用（Scala at Twitter/LinkedIn、Erlang at WhatsApp、Clojure at Walmart）并非 “函数式优于面向对象” 的进步，而是商业资本的权力再分配——Twitter/LinkedIn 采用 Scala 是为了应对 Java 在并发与函数式编程上的局限，WhatsApp 采用 Erlang 是为了应对高并发即时通讯的需求，Walmart 采用 Clojure 是为了应对 Java 遗留系统的现代化需求。

**总纲 5（没有必然性，只有偶然性）**——见 据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义。”

若 John McCarthy 未在 1958 年设计 LISP，若 Robin Milner 未在 1973 年设计 ML，若 Haskell 委员会未在 1990 年达成妥协，若 Joe Armstrong 未在 1986 年于 Ericsson 设计 Erlang，函数式语言史会完全不同。所谓 “函数式语言必然复兴” 的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——见 据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

John McCarthy 亲自实现 LISP 1.5 解释器，Robin Milner 亲自实现 ML 编译器，Simon Peyton Jones 亲自实现 GHC（Glasgow Haskell Compiler），Joe Armstrong 亲自实现 Erlang VM（BEAM），Chris Lattner 亲自实现 Swift 编译器——这些是动手者的实践，而非 “MIT 决定” 或 “Ericsson 决定” 等组织决策的产物。

**自反性声明**：本子节选取 “LISP、ML、Haskell、Erlang、Swift 五大语言” 为函数式与多范式语言主线，但这一选取本身即形式主义化的非存在。若以 Scheme、Clojure 等 LISP 方言为主线，若以 OCaml、F# 等 ML 方言为主线，若以 Scala、Kotlin 等多范式语言为主线，“函数式与多范式语言史” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

## 辨析

**LISP 与 Scheme 关系辨析**：LISP 1.5（1960）为 LISP 原始版本，Scheme（1975，Gerald Sussman 与 Guy Steele）为 LISP 的最小化方言（引入词法作用域与一等公民 continuation），Common Lisp（1984）为 LISP 的标准化方言（融合 MacLISP、InterLISP 等特性）；三者皆为 LISP 家族但语法与语义有差异。本子节采用 “LISP 1.5 为原始版本，Scheme 为最小化方言，Common Lisp 为标准化方言” 的区分性表述。

**ML 与 Standard ML 关系辨析**：ML（1973）为 Robin Milner 最初设计的语言，Standard ML（SML, 1990）为 ML 的标准化版本；OCaml（1996）为 INRIA 对 ML 的扩展（引入对象与模块），与 SML 并行演化但语法有差异。本子节采用 “ML（1973）为最初设计，SML（1990）为标准化，OCaml（1996）为扩展方言” 的区分性表述。

**Haskell 惰性求值辨析**：Haskell 默认惰性求值（lazy evaluation），但惰性求值可能导致空间泄漏与性能问题；部分 Haskell 程序员使用严格求值（strict evaluation）优化性能。本子节采用 “Haskell 默认惰性求值，但可使用严格求值优化” 的限定性表述。

**Erlang 与 Elixir 关系辨析**：Elixir（2012，José Valim）运行于 Erlang VM（BEAM），语法融合 Ruby，但与 Erlang 共享并发模型与容错哲学；Elixir 不是 Erlang 的后继，而是 Erlang 生态的补充。本子节采用 “Elixir 运行于 Erlang VM（BEAM），与 Erlang 共享并发模型但语法不同” 的限定性表述。
