# 395.14.4 207.2 【Linux社区】BSD 人物在 LKML 的出场（续）

- 【Linux社区】2024 年 1 月 Jeff Xu（Chromium）在 mseal() PATCH v7 串中回应 Theo de Raadt 关于 PROT_SEAL 的 OpenBSD 立场，自陈“I'm sorry, I have never looked at one line of openBSD code, prototype or not, nor did I install openBSD before”，并解释“For PROT_SEAL in mmap(), I see it as a good and reasonable suggestion raised during the RFC process, and incorporate it into the patch set”，是 OpenBSD 创始人 Theo 在 lkml 内核设计讨论中直接发声、Linux 开发者据其意见修订补丁的一手证据 `<!-- ROW_MINE: lkml.messages.3827779 -->`
- 【Linux社区】2023 年 10 月 OpenBSD 创始人 Theo de Raadt 在 mseal() RFC PATCH v1 讨论中直接介入：“mseal() is a clone of mimmutable(2), but with an extremely over-complicated API based upon dubious arguments. I designed mimmutable(2) [1] in OpenBSD, it took about a year to get all the components working correctly. There were many intermediate API during development, but in the end the API is simply: int mimmutable(void *addr, size_t len)”“Very simple semantics. The only case where the immutable marker is ignored is during address space teardown as a result of process termination”，Jeff Xu 随即就 mimmutable 是否覆盖 mlock/madvice 场景发问，是 OpenBSD 作者以 API 设计权威身份反向审视 Linux mseal 语义的一手证据 `<!-- ROW_MINE: lkml.messages.3584118 -->`
- 【Linux社区】2003 年 1 月 NetBSD 核心开发者 Bill Studenmund（wrstuden@netbsd.org）在 lkml 就“Technical Differences of *BSD and Linux”新手提问做系统性回应，以 BSD 家族资深视角直陈历史与格局：“*BSD kernels were derived from 4.4-Lite, and Linux was derived, I believe, from Minix”，并给出三族分工口诀——“FreeBSD wants to make kick-ass servers, NetBSD wants to support lots and lots of hardware, and OpenBSD is concerned all about security”，进一步说明“There is a lot of polination between BSDs”与“der Mouse pointed out the GPL issue, which is one where I think the BSD and Linux folks will just agree to disagree”，是 BSD 家族工程师对 BSD/Linux 谱系分裂的第一方陈述。 `<!-- ROW_MINE: lkml.messages.2016458 -->`
