- 【Linux社区】James Bottomley：对类型系统开题的系统性质疑——1) gcc plugin 每次构建检查与 **“effectively making make C=1 the default”（有 sparse 时默认运行）有何区别**；2) 确认 separation logic 所有权类型系统是否“Sort of like a self garbage collecting reference”；3) 核心反对：**“rewriting in some as yet undefined language simply to get better typing and conversions looks very daunting”、追问为何 sparse 扩展（补注解+更新 sparse）不能同样奏效、且免去内核构建对新语言实现的依赖**——“修 C 还是换语言”确立为该议题核心分野 `<!-- ROW_MINE: ksummit-discuss.messages.346198 -->`

- 【Linux社区】Eric Biederman：阐明类型系统终局愿景——gcc plugin 与默认跑 sparse 无实质差别、只是想让它总是运行；澄清 separation logic 方案非 self-GC、而是**“complete alias analysis at type checking time”——类型系统知晓程序员所知的全部别名与对象生命周期、未传递或未释放即报错**；坦承已在自造新语言中实现该检查、retrofit 到 C 尚未验证；卡点预计是 C 所无的 **discriminated unions（如确保先调 IS_ERR(ptr) 再把指针当指针用）**；终局目标：**“a type system that doesn't permit memory errors, reference counting errors, locking errors, or deadlocks”**、且兼容现有内核代码结构 `<!-- ROW_MINE: ksummit-discuss.messages.346200 -->`
