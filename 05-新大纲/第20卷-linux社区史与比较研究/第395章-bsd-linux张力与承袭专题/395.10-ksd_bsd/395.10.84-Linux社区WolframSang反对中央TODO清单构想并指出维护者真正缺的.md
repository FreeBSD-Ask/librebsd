# 395.10.84 Linux社区WolframSang反对中央TODO清单构想并指出维护者真正缺的

- 【Linux社区】Wolfram Sang：反对“中央 TODO 清单”构想并指出维护者真正缺的是审阅者——**“老实说，我认为那是件大事。维护一个含各子系统详细信息的文件、并保持更新，是相当繁重的任务。更细分的子系统 TODO 文件可能有帮助——前提是维护者能保持它更新。对一个新手，我期望他能自己弄清如何找出内核树里所有的 TODO 文件 ;)”**；**“如果你在某子系统的邮件列表里潜水（或读 gmane 存档），你会容易地发现它的问题与短板”**；其关键反转是 **“对我来说，我不是那么缺补丁，我缺的是审阅者。而那需要新人的一些时间和善意才能进入：读旧审阅记录、把玩子系统（‘为什么这样做？’）、翻 git 历史去理解那种有机生长……”**；对“从硬件入手”则 **“同意。这就是为什么我把人们引向 OpenWRT，它有大量未进主线的硬件支持，而旧路由器很容易搞到。然而，人必须有足够的意愿去把一件大多已过时的硬件的支持弄进内核，纯粹为了好玩”**（KS2014 档案） `<!-- ROW_MINE: ksummit-discuss.messages.347301 -->`
- 【Linux社区】Bradley M. Kuhn：以长篇回应拒绝被“copyleft 极大主义者”标签定义，并以 Perl 版权谈判史作反证——开场声明 **“［我知道我说过不会再就这个子话题回复，而 Karen 已在别处发帖说 Conservancy 不会在这个线程上投入更多官方回复时间，所以这个回复是我用自己的时间（从自己的邮箱）写的。当 Linus 在一封邮件里七次提到我的名字时，我实在很难不表现得像 Kibo 一样。:)］”**；其方法质疑是 **“把我的论证过度简化成一个金句、然后攻击那个金句，肯定会成为《开源每日秀》的好素材……但 Ted 提到的整套‘每日秀’方法之所以作为喜剧有效、作为深层政策分析无效，原因在于许多政策问题很复杂，而经常谈论复杂政策话题的人会产生一串金句，你可以用不代表其实际立场的方式把它们拼在一起”**；其核心立场是 **“行动才重要。我向谁负责才重要……当我在 Conservancy 的日常工作里做 Linux 开发者 GPL 合规项目时，我帮助执行 GPL，但 Karen 和我都说过，我们向一群在你的内核里写了代码的人负责”**；对“你觉得自己是 copyleft 极大主义者吗”的回应是 **“我没有回答，不是因为我‘援引第五修正案’，而是因为我不理解那个说法”**；其专业自述是 **“在过去 25 年你写 Linux 代码的时间里，我没有（虽然有些日子我希望自己曾尝试把 1993 年为大学写并部署的那个小补丁集上游化）。相反，我把那段时间（本可以用来折腾 Linux 的时间）花在学习和试图理解 copyleft 作为一种工具与策略上：它如何运作、是否有效、以及它如何能运作得更好”**；其苏格拉底式立场是 **“人们喜欢在会后社交场合向我抛出关于 GPL 的假设情景。我的简短回应是问他们：‘纯假设而言？’当他们说‘是’，我就说：‘我从没学过说假设语。’这是个玩笑，但我是认真的：我不声称知道法院会对问题说什么……除非有一个真实世界的情形摆在我面前、我能分析那起具体 GPL 违规的所有细微之处”**；其公开立场是 **“就我自己而言，我说：我站在 Christoph Hellwig 一边。我相信 VMware 把他的代码（以及其他 Linux 开发者的代码）盗用进一个更大的作品，并以违反 GPLv2§2(b)（主要是）以及其他若干条款（其次是）的方式分发其结果”**；其对 Linus 的回应是 **“我将要求你遵守你多次说过的话（此处转述）：‘所有 Linux 贡献者保留自己的版权，每个人自己做与版权相关的决定’。你作为 Linux 领袖的意见对我重要，但正因为它对我重要，我才会要求你遵守你先前关于‘无版权转让’的声明，直到你改变那个政策并从每一位贡献者那里收集版权转让”**；并以 Perl 版权之争作反证 **“我在简历上的主要自由软件项目是 Perl。我参与了 Perl4 与 Perl5 早期到中期阶段。我在许多 Perl 模块与 perl5 本身里用非 copyleft 许可证写过代码。我甚至对抗过我的大学——他们本已同意把我的工作（以他们的版权）GPL 化。我专门雇了一位律师，就为了保留我自己的版权、以非 copyleft 许可证（GPLv2-or-later|Artistic）发布，以便与 perl 的许可证兼容。想想看：Bradley M. Kuhn，‘Copyleft 先生™’，付钱请律师与他的大学打了一场法律仗（但不是诉讼），因为他希望自己写的东西不被 copyleft 化，因为 Perl 社区不想要它在 copyleft 下，尽管他的大学想那样。那很能说明我的性格与观点”**；对 Larry Wall 的补充是 **“我曾是提名 Larry Wall 获得 FSF 1998 年奖项的人之一。Larry Wall 曾在我的论文委员会里。同时，我与 FSF 最早做的志愿活动之一，就是鼓励人们把 Perl 模块的许可规范化为非 copyleft（GPLv2-or-later|Artistic）。我还写了 Clarified Artistic License……所以，虽然我不知道你说的 Larry 被妖魔化是指什么，但没有人能可信地说，当时既是 FSF 志愿者又参与 Perl 的我，曾经妖魔化过 Larry”** `<!-- ROW_MINE: ksummit-discuss.messages.347302 -->`
