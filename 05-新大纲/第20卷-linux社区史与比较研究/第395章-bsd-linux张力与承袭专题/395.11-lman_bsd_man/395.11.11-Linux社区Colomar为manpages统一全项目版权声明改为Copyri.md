# 395.11.11 Linux社区Colomar为manpages统一全项目版权声明改为Copyri

- 【Linux社区】Colomar 为 man-pages 统一全项目版权声明（改为“Copyright, the authors of the Linux man-pages project”并配顶层 AUTHORS 文件），起因是旧的逐文件声明格式不一、文件搬移时未随迁、他自己等也漏加声明；他已向每位声明被改动者邮件征询，约三分之一明确同意、其余沉默、无人反对；他说明在 SPDX 化期间已获全部版权持有人同意改许可证，当时有发行版投诉部分现有许可证被视为非自由软件。 <!-- ROW_MINE: linux-man.messages.725721 -->`
- 【Linux社区】Colomar 主张 Linux man-pages 已成 C 的 de-facto 标准，虽非 Unix 标准的正统继承者；他指出 POSIX 与 C89 在结构与格式上皆源于 Unix 与 System V 手册页，而 Unix/System V 是当时最大的系统，GNU+Linux 现处同等位置；对 Branden 提到的 Ritchie C Reference Manual 因 Prentice-Hall 不愿放行而不见于 Unix 机器一事，他询问 TUHS 存档是否有副本，并称手册页的教育职能是该项目的终极职责——正如车辆手册必须说明高速升空与侧撞气囊失效等限制。 <!-- ROW_MINE: linux-man.messages.725920 -->`
- 【Linux社区】针对 Joey Schulze（dir_colors 作者）表示愿意将 dir_colors(5) 重新许可为 GPLv2+、“以保住 man page 的自由状态并在 Fedora 里保留一份”，Colomar 表示欢迎，但按项目现行做法改写为 SPDX 形式：保留“Copyright (c) 2001 Martin Schulze <joey@infodrom.org>”一行，其后改为 SPDX-License-Identifier: GPL-2.0-or-later，并反问对方是否接受。 <!-- ROW_MINE: linux-man.messages.728004 -->`
- 【Linux社区】harms 提交 bswap_16/32/64 的新 man page，页头署“Copyright 2012 walter harms”、许可写作“Distributed under GPL”，.TH 行则标为“GNU”“Linux Programmer's Manual”，而内容描述的 bswap 宏实为 glibc 的 <byteswap.h> 接口。 <!-- ROW_MINE: linux-man.messages.728857 -->`
- 【Linux社区】Colomar 向 SPDX 社群求助合法性问题：他决定统一整个项目的版权署名为“Copyright, the authors of the Linux man-pages project”，再由顶层 AUTHORS 文件列出全部作者，认为这比此前混乱的逐文件署名“更准确”。此前的问题是版权声明常随代码搬移而丢失，也有作者（包括他自己）大幅改写文件却忘记补署自己。他已通知所有被改署名的当事人，约三分之一给出明确同意、其余沉默且无人反对，仍征询法律意见。Vincent Lefevre 补充指出更关键的问题是各 man page 许可并不统一，且 GPL 要求版权声明必须出现在文件本身。 <!-- ROW_MINE: linux-man.messages.729914 -->`
- 【Linux社区】Colomar 提交 RFC v3 补丁集“Use SPDX markings”：将版权标记简化为 SPDX 与 REUSE 约定——文件内只留几行，完整许可文本统一放入 LICENSES/ 目录以避免重复。他特别请求审查人“特别留意”其中一类页面：那里的版权文本与历史版本标记并未清楚区分，“我可能搞错了”。他说明尚在补 Verbatim-man-pages 许可文本（SPDX 即将发布该标识），并提供对应 git 标签 spdx-v3-20210905 供整体核对。 <!-- ROW_MINE: linux-man.messages.730085 -->`
- 【Linux社区】Brouwer 就 man-pages-6.14 将源码内贡献记录移入 CREDITS 文件并统一版权头提出法律性质疑：以 man2/unlink.2 为例，原有逐人版权记录（1992 Drew Eckhardt、1993 Ian Jackson、2006 与 2014 Michael Kerrisk）配以“允许逐字复制分发，前提是版权与许可声明在所有副本上保留”的声明；改为“Copyright, The contributors to the Linux man-pages project”加 SPDX-License-Identifier: Linux-man-pages-copyleft 后，再也无法找到该页的所有权信息，而旧许可声明似不允许在不保留该信息的前提下分发。 <!-- ROW_MINE: linux-man.messages.731462 -->`
- 【Linux社区】Kerrisk 为新手册页 scandirat(3) 征询许可证意见，倾向采用 VERBATIM 许可或 GPLv2 而非 GPLv3，理由之一是“GPL 主要是为代码设计的许可证”，并明确表示希望避免 man-pages 中的许可证蔓延（licensing proliferation）；项目许可证页 man-pages/licenses.html#gpl 虽同时提及 v3 与 v2，但当时尚无任何已有页面使用 v3。 <!-- ROW_MINE: linux-man.messages.731510 -->`
- 【Linux社区】Colomar 公布并执行 AI 政策：明确禁止贡献任何由 AI 工具创建或参与的内容，涵盖用于推导贡献的 AI linter、静态分析器与摘要工具；仅屏幕阅读、语音转写等不影响贡献内容的辅助工具例外，且无需披露。理由含版权关切——各地关于生成内容的版权规则尚未成型，既可能构成侵权，也可能削弱版权主张并使 copyleft 许可的保障落空——以及质量与伦理关切。政策文本取自（但不同于）Gentoo 项目的 AI 政策，标注 SPDX-License-Identifier: CC-BY-SA-4.0。 `<!-- ROW_MINE: linux-man.messages.732229 -->`
- 【Linux社区】O'Donell 解释 glibc 无法把源码文档并入手册，原因是 GFDL 与 LGPLv2 之间存在许可壁垒；而因 gcc 在 C++ 上有同样问题，FSF 已有一个可复用的既定流程——由 FSF 维护者获得重新许可所生成文档并将其检入的权利。他还质疑部分信息的可版权性：线程安全标注是函数本身的属性、不受版权保护，但解释为何不遵循标准的描述性文字则可以受版权保护。 `<!-- ROW_MINE: linux-man.messages.732285 -->`

- 【Linux社区】就手册页页脚与版权呈现达成协议：Ingo Schwarze 认为手册页不应包含任何样板文字，处处重复的文字只是干扰与屏幕空间的浪费；手册页正文也不应出现 COPYRIGHT，但每个文件都应在顶部以注释携带版权与许可证头——手册页文件用 troff 注释、程序源文件用 /* */ 注释——因为使用者只要是在使用程序或函数、且它大致属于自由软件，就无须考虑任何版权或许可。Colomar 称自己本犹豫删除 Kerrisk 早年加入的样板，因其主张那能提升项目的可被知晓度。 <!-- ROW_MINE: linux-man.messages.734006 -->`
