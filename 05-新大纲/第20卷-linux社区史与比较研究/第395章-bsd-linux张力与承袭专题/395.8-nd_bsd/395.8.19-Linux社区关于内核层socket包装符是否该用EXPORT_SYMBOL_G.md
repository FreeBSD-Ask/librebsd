# 395.8.19 Linux社区关于内核层socket包装符是否该用EXPORT_SYMBOL_G

- 【Linux社区】关于内核层 socket 包装符是否该用 EXPORT_SYMBOL_GPL 的争论，Brian Bidulock 论称这些接口是 “direct derivatives of the BSD/POSIX system call interface”，故协议函数指针本身并非 GPL 专属。BSD/POSIX 血统被用来豁免 GPL 限制。`<!-- ROW_MINE: netdev.messages.8271814 -->`
- 【Linux社区】PMTU 边界处理回退争议中 David Miller 复述旧逻辑的第一条即 “check for a BSD 4.2 anomaly and subtract old_mtu by the IP header length”。Linux 内核在 ICMP 差错报文解析上长期为 BSD 4.2 的错误实现保留特判。`<!-- ROW_MINE: netdev.messages.8271955 -->`
- 【Linux社区】Landlock LSM 设计说明把定位写为 “comparable to the Seatbelt/XNU Sandbox or the OpenBSD Pledge”，即与 Apple 的 Seatbelt 沙箱和 OpenBSD Pledge 同类。BSD 谱系沙箱机制是 Linux 安全模块设计时的直接对标对象。`<!-- ROW_MINE: netdev.messages.8272305 -->`
- 【Linux社区】Inter Process Networking 提案文档在论证动机时点明 “The Berkeley socket Application Programming Interface” 系为客户端服务器模型设计，缺少广播域支持。Berkeley sockets 的设计边界被引为在内核新增协议族的正当性依据。`<!-- ROW_MINE: netdev.messages.8272396 -->`
- 【Linux社区】ip_rt_frag_needed 函数被移除前，其注释说明 “BSD 4.2 derived systems incorrectly adjust tot_len by the IP header length”，使 Linux 需容忍 ICMP 报文中的零 MTU 并做猜测。删除该兼容代码后被观察到 PMTU 缓存失效。`<!-- ROW_MINE: netdev.messages.8272496 -->`
- 【Linux社区】1Mpps 转发性能讨论中 jamal 记载 “Our friends in FreeBSD claim they can do 1Mpps” 转发吞吐，并指出 “the BSD folks batch their transmits. They have a very dumb egress with no QoS”。BSD 批量发送路径被视为 Linux 需复现的关键实现细节。`<!-- ROW_MINE: netdev.messages.8272575 -->`
- 【Linux社区】IPv6 地址哈希重构补丁在动机中列出三点，其中之一是改用 jhash2 取代被作者称为 “some old BSD algorithm” 的旧哈希函数。被替换的旧实现注释自 net_alias.c，此处以“旧 BSD 算法”为名被正式换下。 `<!-- ROW_MINE: netdev.messages.8272766 -->`
- 【Linux社区】过滤规则默认放行行为的考古中 Alexey Kuznetsov 反问 “current behaviour matches another implementations (BSD whatever), is it true?”，显示 BSD 同类实现长期作为判断 Linux 行为是否合理的外部参照。`<!-- ROW_MINE: netdev.messages.8273410 -->`
- 【Linux社区】针对路径 MTU 修复提交迟缓的回应，Edward Allcutt 反讽 “if OpenBSD can wait more than 2 decades to implement proper path mtu handling”，并坚持 OpenBSD 该缺陷不可能出于设计意图而应被调查。BSD 分支长期未修的 MTU 缺陷被引为论据。 `<!-- ROW_MINE: netdev.messages.8273417 -->`
- 【Linux社区】IPv6 地址选择与路由同步讨论里 Pekka Savola 陈述 “At least BSD and I think Linux create ad-hoc, cloned routes” 以在 Path MTU 发现时保存不同取值。BSD 与 Linux 在此处被描述为共享同一实现传统的两个分支。`<!-- ROW_MINE: netdev.messages.8273506 -->`
- 【Linux社区】DCCP 序列号比较宏讨论中，Gerrit Renker 转述 David Miller 所指 “Even BSD suffers of this issue, since the beginning”，并举 SEQ_LT 与 “TSTMP_LT() macro in OpenBSD's tcp_input.c” 为例；Renker 回应称自己不知 OpenBSD 用法，但 Stevens 卷 2 早已按此方式定义。BSD 缺陷被引为接受修改的理由。 `<!-- ROW_MINE: netdev.messages.8273543 -->`
- 【Linux社区】SCTP 数据块合并讨论中 Michael Tuexen 交代两个实现的分歧：“In FreeBSD we do support SCTP_EOR, but not MSG_MORE, which seems to be Linux specific.” FreeBSD 支持的显式结束符语义未进入 Linux，MSG_MORE 则反向成为 Linux 特有。`<!-- ROW_MINE: netdev.messages.8273787 -->`
- 【Linux社区】套接字自旋轮询方案讨论中 Stephen Hemminger 建议改用 FreeBSD 谱系项目 netmap，称 “Have you looked at netmap? Seems like a cleaner user API for this.” Eliezer Tamir 顺势提出把虚拟功能映射进用户态作为 netmap 的替代思路。`<!-- ROW_MINE: netdev.messages.8275197 -->`
- 【Linux社区】套接字协处理器虚拟设备提案自称 “The Berkeley sockets coprocessor is a virtual PCI device”，可让未修改的应用在 BSD sockets 接口上完成卸载。Alan Cox 随即质疑 Unix 一贯主张的套接字接口通用性传统是否应被打破。`<!-- ROW_MINE: netdev.messages.8275646 -->`
- 【Linux社区】madwifi 停止维护后 Nick Kossifidis 招募 ar5k 协助者并说明动机：修复 “making ar5k work with newer madwifi versions” 的工作 “that 'll also help bsd ppl”。作者未交代 ar5k 原始出处，仅称已把 ar5k 移植到 Linux，修复亦惠及 BSD 用户。 `<!-- ROW_MINE: netdev.messages.8276131 -->`
- 【Linux社区】HFSC 服务曲线研究长文中作者写道 “The Linux and BSD implementation of HFSC go beyond the original specification”，两者都允许把 ls 曲线与 rt 曲线分离指定。Linux 与 BSD 在 HTB 与 HFSC 上被归为同一批偏离原始规范的实现。`<!-- ROW_MINE: netdev.messages.8276188 -->`
- 【Linux社区】adjtimex 位定义之争中 John Stultz 系统对比两套约定，列举 “differences compared with BSD’s timex mode definitions”，指出 Linux 的 ADJ_TICK 等于 FreeBSD 的 MOD_CLKB，并警告 0x40 在 BSD 中已占用为 MOD_PPSMAX。BSD timex 语义直接约束 Linux 位号分配。`<!-- ROW_MINE: netdev.messages.8276355 -->`
- 【Linux社区】XDP 程序是否应绑定单个 RX 队列的架构争论中，Brouer 引 netmap 作先例：“Recently netmap added support for running on a single specific queue”，并称这是客户拒绝 DPDK 的首要原因。Herbert 以 netmap 与 dpdk 的设计动因回应。 `<!-- ROW_MINE: netdev.messages.8276563 -->`
- 【Linux社区】TCP ISN 随机化补丁评审中有人质疑 “I'm not sure how the OpenBSD code is better in any way”，指出它使用与 Linux 相同的 half_md4_transform；答复者则提醒 “OpenBSD added SMP support in June 2004”，建议参照当时 OpenBSD 的现状判断安全性。 `<!-- ROW_MINE: netdev.messages.8276630 -->`
