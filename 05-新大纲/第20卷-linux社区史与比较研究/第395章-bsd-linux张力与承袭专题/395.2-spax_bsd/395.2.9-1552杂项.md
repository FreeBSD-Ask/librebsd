# 395.2.9 155.2 杂项

- 【Linux社区】Glaubitz 与 Linus Walleij 讨论旧架构平台的存废标准。Glaubitz 认为按 git 活跃度判断一个移植是否已死是糟糕指标，商业利益正在挤压爱好者用途，二者需要健康平衡，并指出 m68k 等冷门架构仍有 SECCOMP 等功能缺口可供教学性开发。Walleij 回应称自己在 ARM 树中删改子架构时从不删除愿意维护的项目，公司实体偏向删除主义，而社区总有强烈的包容立场与之对抗，并援引 Torvalds 自传 Just for fun 中的动机说明作为保护这一特质的依据。他要求保留宠儿架构者做三件事：测试确认他人补丁、迁移驱动到通用子系统、改用设备树或 ACPI 描述硬件。 `<!-- ROW_MINE: sparclinux.messages.9327885 -->`
- 【Linux社区】Keith Wesolowski 宣布因利益冲突不再维护 sparc32 内核树，希望很快公布新任维护者，在此之前请把所有补丁与缺陷报告直接提交到邮件列表。他为有兴趣参与 sparc32 的人交出最新待办清单，该清单最初由 Pete 编写，Pete 的注释以双井号开头、他本人的以双星号开头，他认为工作正常的条目列在底部。清单涵盖取消内存别名的统一、移除 fork_kpsr 与 fork_kwim、抢占式调度下的 rtrap、重写 ioport.c 建立本地资源索引、JavaStation 用户态、移除 __irq_itoa、JSFLASH 老化需迁移到 MTD、以及把 current 迁回 g6 并改进 thread_info 等多组工作。 `<!-- ROW_MINE: sparclinux.messages.9331622 -->`
