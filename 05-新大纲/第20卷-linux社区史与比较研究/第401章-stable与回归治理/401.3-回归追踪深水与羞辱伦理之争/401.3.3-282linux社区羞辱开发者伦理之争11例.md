# 401.3.3 28.2 【Linux社区】“羞辱开发者”伦理之争（11 例）

**要点（判定表逐字）**：Guenter Roeck 以自身 usb 修复为例，称若干复现需数小时乃至数日压力测试且高度依赖硬件，竞态多无法证明已修只证其仍在，若因缺单测而羞辱开发者只会使其停止修 bug；Rostedt 澄清所谓羞辱仅针对已有可百发百中复现用例却未入 selftests 者，并断言多数靠检视或难复现的 bug 本非回归而是既存特性，反问我们究竟在追踪回归还是普通 bug；Greg KH 力挺 Guenter——羞辱思路是症结；举 xfstests 与 i915 测试为可行之例，指 kselftests 刚获统一输出格式，其余基础设施需求未明；Bottomley 谓大量设备驱动回归本是既存 bug、待他事触发方显，竞态由常胜转常败即用户眼中之回归，故投票站在用户一边判其为回归而非特性；Rostedt 指众人纠缠羞辱一词、忽视其主旨——changelog 与邮件中大量复现器未入 selftests，主张可触发 bug 者必入，并扩 selftests 含 config 清单，自陈 ftrace 早已用之；Rostedt 退一步问究竟要解何题——难复现者焉知为回归或巧合，并笑称 kselftests 中竟无 SCSI 测试；Guenter Roeck 谓公开羞辱内核开发者不比羞辱孩童更有效，宜以友好方式建议提交测试、表扬 kselftest 贡献，并忧羞辱一旦起便难止；Dan Williams 称曾写针对 xhci TRB 边界条件的测试基础设施，证部分修复可单测，但非全部；Dan Williams 认同 Guenter——此不应成维护者新负担，而应作新开发者贡献路径，于修 bug 之外再建议以单测兜底回归；Rostedt 自嘲为友好羞辱者，并以假想邮件示其所谓羞辱不过提醒开发者为何修复 bug 后未将复现器入 selftests；Rostedt 认本子线程已偏题，并同意难修之回归恰是无模型可建者，亦认同 Bottomley 之回归定义
