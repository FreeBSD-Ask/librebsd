# 131.5.1 bhyve 维护者的 committer 状态

**要点**：bhyve 项目的核心维护者 committer 状态：Neel Natu（尼尔·纳图）（nneul@）是 bhyve 初始代码作者，NetApp 员工，其 FreeBSD src committer 权限持续活跃至 2010 年代中后期，后逐渐减少活动；Peter Grehan（彼得·格雷汉）（grehan@）是 bhyve 长期主要维护者，FreeBSD Foundation 董事，持续活跃至 2020 年代，负责 bhyve 功能开发、bug 修复、与其他子系统集成；其他重要贡献者包括：John Baldwin（jhb@，负责 SVM/AMD 支持、PCI 直通等）、Konstantin Belousov（kib@，内核基础设施支持）、Mihai Carabaș（arm64 移植）等；bhyve 代码审查主要在 freebsd-virtualization 邮件列表与 Phabricator 进行；无 bhyve 核心维护者被撤销 committer 权限的公开记录

**史料**：FreeBSD src 仓库 commit log（cgit.freebsd.org）；FreeBSD Core Team 公告；freebsd-virtualization 邮件列表存档；FreeBSD Committer 指南 ［A］

**史观**：终结与延续：committer 身份的持续性是开源项目延续性的重要指标，但 committer 权限存在不等于项目活跃度高——Neel Natu 在将 bhyve 导入 FreeBSD 后逐渐减少直接贡献，由 Peter Grehan 接过维护职责，这种 “作者启动、维护者延续” 的模式在开源项目中非常常见；核心维护者的精力投入直接决定了项目的演进速度

**辨析**：原文中提到的 “Qing Huang” 作为主要维护者需要核实——该名字未在 bhyve 主要 commit 历史与演讲作者中显著出现 ［ 存疑脚注：此处事实待多源交叉验证 ］，bhyve 核心维护者应为 Neel Natu、Peter Grehan、John Baldwin 等人；bhyve 维护团队规模较小是事实，这直接导致了功能开发速度慢于 KVM，但也意味着代码审查严格、架构一致性保持较好；FreeBSD 项目未设立专门的 “bhyve 核心团队” 或 “bhyve 维护者” 正式职位，维护职责通过实际贡献自然形成
