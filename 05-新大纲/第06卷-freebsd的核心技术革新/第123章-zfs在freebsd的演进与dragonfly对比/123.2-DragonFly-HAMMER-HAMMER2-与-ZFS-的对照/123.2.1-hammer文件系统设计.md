# 123.2.1 HAMMER 文件系统设计

**要点**：HAMMER 文件系统由 Matthew Dillon（DragonFly BSD 创始人，曾是 FreeBSD 核心开发者、Amiga 著名开发者）设计，DragonFly BSD 2.0（2008 年发布）首次引入 HAMMER；HAMMER 是写时复制（CoW）文件系统，支持无限历史快照、崩溃一致性、增量镜像、数据校验（CRC32）；HAMMER 的设计哲学与 ZFS 不同——HAMMER 选择在 VFS 层之下实现，使用 B+ 树结构而非 ZFS 的 Merkle 树 + 块指针模型，面向单一大存储池设计但未采用 ZFS 的存储池（zpools）模型；HAMMER 不提供 RAID 功能（RAID 由 DragonFly 的磁盘管理子系统处理），不提供端到端校验的多层哈希树，设计更为轻量

**史料**：Matthew Dillon HAMMER 设计文档（2007-2008 年，dragonflybsd.org）；DragonFly BSD 2.0 Release Notes（2008）；Dillon 在 NYCBSDCon 2008 的 HAMMER 演讲［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档；L4 事后叙述〕

**史观**：总纲第 8 条——本体论上各方平等：HAMMER 是 Matthew Dillon 在 DragonFly BSD 项目中独立发展的 CoW 文件系统，代表了 BSD 世界中 “不依赖 Sun 技术” 的另一条路径；Dillon 选择自研 HAMMER 而非移植 ZFS，既有工程判断（DragonFly BSD 的 VFS 架构与 ZFS 的 Solaris 依赖不兼容），也有技术路线独立的考量

**辨析**：HAMMER 首次发布日期：DragonFly BSD 2.0 发布日期存疑〔存疑：正文原记 2008 年 10 月，同文件 PODCAST 块两处记 2008 年 7 月且与 EP154 录制时点（2008-07-08）自洽，精确发布日待以 DragonFly 官方 Release Notes 核实〕，HAMMER 在该版本中标记为 experimental；HAMMER2 与 HAMMER 是完全不同的文件系统，不是简单升级；Dillon 选择不移植 ZFS 的原因并非许可证（DragonFly 同样是 BSD 许可，可以集成 CDDL 代码），而是工程和架构选择；HAMMER 2008-2009 年间活跃迭代经邮件列表库验证通过（dragonfly kernel 列表，Matthew Dillon 2008-12-17/2009-06-22 讨论 HAMMER 扩展与特性，Message-ID: <200812171723.mBHHNr5Z092485@apollo.backplane.com>）；DragonFly 2.0 精确发布日（2008-10）两库无法验证
