# 123.1.5 辨析FreeBSDZFS的版本命名容易混淆早期FreeBSD使用SolarisZ

**辨析**：FreeBSD ZFS 的版本命名容易混淆：早期 FreeBSD 使用 Solaris ZFS pool version 号（1-28），feature flags 机制引入后不再使用全局 pool version，改为每个功能独立 flag；OpenZFS 2.0 是统一版本号，取代了之前 ZoL（0.6、0.7、0.8）和 FreeBSD 独立版本的命名；**数据库验证结论**：8 个 FreeBSD 大版本（7.0/8.0/9.0/10.0/11.0/12.0/13.0/14.0）的 ZFS 演进时间线声明与 `openzfs.duckdb` `tags` 表与 `commit_files` 表交叉验证通过——7.0/8.0 的 tagger_date 与公开声明日期完全一致；9.0-14.0 的 tagger_date 均早于公开声明日期 3-17 日，符合 “tag 创建后等待公开公告” 的 FreeBSD 发布流程；FreeBSD 11.0 的 17 日偏差最大，与 FreeBSD 11.0 发布前发现 last-minute 问题推迟公告的历史一致；0 信任原则提示：9.0-12.x 系列在 SVN 时代发布，commit hash 经 2020 年 SVN-to-Git 迁移重算，tagger_date 由迁移脚本回填，须与 FreeBSD 官方发布公告交叉验证；13.0+ 系列在 Git 时代发布，hash 与 tagger_date 可信度更高［考据注：2026-09-13 复核：release/8.0.0 tagger_date 实测为 2009-11-21T06:13:29Z，“完全一致”之说系官方公告日期口径；各名义 tag 著录为 2026-07 查询快照，须以 FreeBSD 官方发布公告为权威］
