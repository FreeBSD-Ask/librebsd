# 119.3 2014 年 1 月 FreeBSD 10.0-RELEASE 正式包含 bhyve

## 119.3.1 bhyve 集成至 FreeBSD 基本系统

**要点**：bhyve 随 FreeBSD 10.0-RELEASE 于 2014 年 1 月 20 日正式发布，首次成为 FreeBSD 基本系统的一部分（SVN revision r245652 标记为初始导入）；FreeBSD 10.0 中的 bhyve 初始版本仅支持 Intel VT-x（VMX）配合 Extended Page Tables（EPT）的硬件虚拟化扩展，要求 CPU 为 Intel Nehalem 及更新架构（不支持低端 Atom CPU），不支持 AMD SVM（AMD-V）；初始版本客户机操作系统支持有限，仅可运行 64 位 FreeBSD 与 Linux 客户机，不支持 Windows、OpenBSD/NetBSD 等其他客户机；bhyve 在 FreeBSD 10.0 中作为技术预览（technology preview）发布，标记为实验性功能

**史料**：FreeBSD 10.0-RELEASE Release Notes “Virtualization support” 章节；**freebsd.duckdb** `tags` 表 `freebsd-src` 仓库 release tag 数据库验证——`release/10.0.0` tagger_date = 2014-01-16T18:43:50Z，tagger_name = Glen Barber（格伦·巴伯）（FreeBSD 10.0 release engineer），target_commit_hash = `e3ff8788aa4381f45f5c39efd99c9cbf1b174b5a`，target_commit_date = 2014-01-16T18:33:10Z，与公开声明发布日期 2014-01-20 相差 4 日（在 FreeBSD 公告流程正常偏差范围内，tagger_date 为 tag 创建日期，公开发布日期需等待镜像同步与官方公告）；bhyve 用户态工具首次合入 freebsd-src 仓库的 commit 经 `commit_files` 表查询为 `366f60834ff8ef709f132fe8976c96a5e2caace9` "Import of bhyve hypervisor and utilities, part 1. vmm.ko - kernel module for VT-x, VT-d and hyperv"，author = Peter Grehan（彼得·格雷汉），author_date = 2011-05-13T04:54:01Z，committer_date = 2011-05-13T04:54:01Z，远早于 FreeBSD 10.0 发布（2014-01-16）约 2 年 8 个月，反映 bhyve 在导入 FreeBSD-CURRENT 后经历了较长的成熟过程才作为正式特性随 FreeBSD 10.0 发布；该 commit 同时引入 `usr.sbin/bhyve/Makefile`、`usr.sbin/bhyve/atpic.c`、`usr.sbin/bhyve/consport.c` 等用户态文件；bhyve(4) 手册页首次引入 commit 为 `a06c84f84a732b4967c5b5617bd5f8a4f71e32f0`（Neel Natu（尼尔·纳图），2013-01-07T06:37:22Z，subject = "Add man page for bhyve(4). The project as well as the man page is a work-in-progress."），bhyve(8) 手册页首次引入 commit 为 `b13e60da569243e8c7a37edbe7600798e9a1f701`（Peter Grehan，2013-12-13T08:31:13Z，subject = “bhyve(8) man page.”）；`历史代码复核/freebsd-目录结构验证.md` 验证显示 `usr.sbin/bhyve/` 目录在 release/9.0 与 release/9.3 tag 中均不存在，在 release/10.0 起开始存在并持续至今，与 “bhyve 随 FreeBSD 10.0 首次正式包含” 的时间线一致；值得注意的是 `sys/dev/bhyve/` 目录在所有 release tag 中均未检测到存在，反映 bhyve 内核侧实现长期位于 `sys/amd64/vmm/` 而非 `sys/dev/bhyve/`；**freebsd.duckdb** L2.3.1.bhyve 查询（bhyve 特性引入周期，从首条 commit 至稳定周期）——查询结果摘要：共返回 20 条 commit，时间序列首条为 `366f60834ff8ef709f132fe8976c96a5e2caace9`（2011-05-13T04:54:01Z，Peter Grehan，"Import of bhyve hypervisor and utilities, part 1. vmm.ko - kernel module for VT-x, VT-d and hyperv"），第二条为 `6c4c7d0f96c632ef104b202a633a06db33f74d6b`（2011-05-14，Peter Grehan），第三条为 `34a6b2d6274e0adeae33754556652f985a07e96f`（2011-05-14，John Baldwin），后续 commit 涉及 Neel Natu、Doug Rabson（道格·拉布森）、Sean Bruno 等贡献者，反映 bhyve 导入 freebsd-src 后立即获得多位 FreeBSD committer 的协作开发；该 20 条 commit 的时间跨度从 2011-05-13 起延续至 2011-2012 年间，对应 bhyve 从初始导入到 FreeBSD 10.0-RELEASE（2014-01-16）前的成熟期；0 信任原则局限提示：(1) bhyve 代码最初在 FreeBSD Perforce 仓库 `//depot/projects/bhyve/` 分支开发，后通过 SVN 导入 FreeBSD-CURRENT，freebsd.duckdb 中的 freebsd-src 仓库数据经 2020 年 SVN-to-Git 迁移重算，2011-2013 年间的 commit hash 与 author_date 可能由迁移脚本根据原始 SVN/Perforce 元数据回填，需与 Perforce 时代原始记录交叉验证；(2) L2.3.1.bhyve 查询仅返回 20 条 commit，可能为 LIMIT 限制而非完整 commit 历史，完整的 bhyve 特性引入周期分析须结合 `sys/amd64/vmm/` 与 `usr.sbin/bhyve/` 路径的完整 commit 查询；(3) commit author 归属在 SVN-to-Git 迁移过程中可能存在偏差，特别是 Neel Natu 的 commit 是否全部正确归属需与 Perforce 时代原始记录核对；**freebsd.duckdb** L2.2.1.sys_amd64_vmm 查询（sys/amd64/vmm 子系统 commit 演化）——该查询在 `中观模式挖掘.md` §L2.2 报告段落中计划但未单独执行，freebsd.duckdb 的 L2.2.1 系列查询目前仅覆盖 sys/kern、sys/net、sys/geom、sys/cam、sys/dev、sys/vm、sys/fs、sys/contrib 八个子系统，尚未包含 sys/amd64/vmm 子系统；bhyve 内核侧代码主要位于 `sys/amd64/vmm/` 目录下（包括 vmm.ko 内核模块、vmx(4)、svm(4) 后端驱动等），sys_amd64_vmm 查询数据缺失意味着无法通过 commit 量统计直接量化 bhyve 内核侧代码的年度演化趋势；替代数据来源：可通过 freebsd-src 仓库的 `sys/amd64/vmm/` 路径直接查询 commit 历史获取 bhyve 内核侧代码演化数据，亦可结合 `usr.sbin/bhyve/` 路径查询用户态代码演化；0 信任原则局限提示：sys/amd64/vmm 子系统不仅包含 bhyve 代码，还可能包含其他虚拟化相关组件，commit 量统计须结合 commit message 关键词过滤才能区分 bhyve 与其他虚拟化特性 ［A］

**史观**：总纲第 19 条——信息技术标准演进与硬件进步同步：bhyve 的发布时机与 Intel VT-x/EPT 在服务器 CPU 中的普及高度同步——Nehalem 架构于 2008 年发布，到 2014 年 EPT 已成为服务器 CPU 标配；FreeBSD 选择在硬件虚拟化成熟后而非提前发布 hypervisor，体现了 BSD 工程文化中 “不抢跑、等硬件就绪” 的务实传统

**辨析**：原文标题 “2014.1 FreeBSD 11.0 正式发布 bhyve” 存在严重事实错误——bhyve 首次随 FreeBSD 10.0-RELEASE（非 11.0）发布，FreeBSD 11.0 直到 2016 年 10 月才发布；FreeBSD 10.0-RELEASE 的 `release/10.0.0` tag 经 `freebsd.duckdb` `tags` 表验证 tagger_date = 2014-01-16T18:43:50Z（tagger = Glen Barber），此为 tag 创建日期；FreeBSD 官方公开声明发布日期为 2014 年 1 月 20 日，二者相差 4 日属于 FreeBSD 公告流程正常偏差（tag 创建后需等待镜像同步与官方公告）——原 [存疑——精确日期需 FreeBSD 10.0 正式发布公告最终核实] 已解决，tagger_date 与公开公告日期相互印证；初始版本不支持 AMD SVM 是重要的早期限制——AMD SVM 支持在后续 FreeBSD 版本中逐步添加，具体添加版本与 SVN revision 标注为 ［ 存疑脚注：此处事实待多源交叉验证 ］；FreeBSD 10.0 中 **virtio(4)** 驱动已独立于 bhyve 存在（revision r227652 添加），支持 **virtio_blk(4)**、**virtio_scsi(4)**、**vtnet(4)**（即 virtio_net）、**virtio_balloon(4)** 等半虚拟化设备；**数据库验证结论**：bhyve 引入 freebsd-src 的 commit `366f60834ff8...` author_date = 2011-05-13 远早于 FreeBSD 10.0-RELEASE 的 tagger_date = 2014-01-16，表明 bhyve 在 freebsd-src 仓库中存在近 3 年才作为正式特性随 FreeBSD 10.0 发布；`release/10.0.0` tagger_name = Glen Barber 与 FreeBSD 10.0 release engineer 公开身份一致；0 信任原则提示：FreeBSD 10.0 系列在 SVN 时代发布，commit hash 经 2020 年 SVN-to-Git 迁移重算，author_date = 2011-05-13 可能由迁移脚本根据原始 SVN commit 元数据回填，可信度较高但非原始 Git 时代记录
