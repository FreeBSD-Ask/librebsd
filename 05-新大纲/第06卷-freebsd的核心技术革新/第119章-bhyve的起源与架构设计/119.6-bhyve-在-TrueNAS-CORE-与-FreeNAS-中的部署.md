# 119.6 bhyve 在 TrueNAS CORE 与 FreeNAS 中的部署

## 119.6.1 bhyve 的主要商业用户场景

**要点**：FreeNAS（后更名为 TrueNAS CORE）是 bhyve 最知名的商业部署场景，由 iXsystems 开发与维护；FreeNAS 是基于 FreeBSD 的开源网络附加存储（NAS）操作系统，从 FreeNAS 9.x 版本开始集成 bhyve 虚拟化功能，允许用户在存储设备上同时运行虚拟机；TrueNAS CORE（FreeNAS 的继承者）继续基于 FreeBSD 与 bhyve 提供 VM 功能；bhyve 在 TrueNAS/FreeNAS 中与 ZFS 深度集成，支持 ZFS 卷作为 VM 磁盘、ZFS 快照作为 VM 检查点、ZFS send/recv 用于 VM 迁移；iXsystems 工程团队对 bhyve 做出了大量功能贡献与 bug 修复，回馈上游 FreeBSD；iXsystems 于 2017 年 2 月在 FreeNAS 中正式引入 VM 功能，bhyve 随 FreeNAS 11.0 官方可用，至 2018 年 3 月已累计报告 244 个 bhyve 相关 bug（其中 VNC 相关 21 个），FreeNAS 累计下载超 1000 万次、活跃用户超 20 万（Araujo, 2018）

**史料**：TrueNAS CORE 文档 “Virtual Machines” 一章；iXsystems FreeNAS/TrueNAS 发布公告；FreeNAS 9.x/11.x Release Notes［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；Araujo M. FreeNAS and bhyve: Where the shark bites the hive [C]//bhyvecon Tokyo 2018. Tokyo, 2018（作者为 iXsystems 工程师 <araujo@FreeBSD.org>，2018-03-09，提供 FreeNAS 引入 bhyve 的一手时间线与部署数字）

**史观**：商业形态分化：bhyve 的商业采用高度集中于存储设备厂商（NetApp 内部使用、iXsystems TrueNAS/FreeNAS），这与 bhyve 起源于 NetApp 的背景直接相关；存储厂商选择 bhyve 而非 KVM 的原因包括：FreeBSD ZFS 集成成熟度、BSD 许可证允许专有产品集成、bhyve 代码简洁易于定制

**辨析**：需纠正原文中关于 TrueNAS 转向 Linux 的叙述——TrueNAS 存在两个并行版本：TrueNAS CORE（基于 FreeBSD + bhyve）与 TrueNAS SCALE（基于 Debian Linux + KVM/QEMU），两个版本并行开发维护，CORE 并未被放弃或 “转向 Linux”；TrueNAS SCALE 从 2020 年开始开发，作为面向超融合基础设施（HCI）的独立版本，并非 CORE 的替代品；iXsystems 对 FreeBSD 与 bhyve 的工程投入确实因 SCALE 开发资源分流而受到影响，但声称 “TrueNAS 放弃 FreeBSD” 是不准确的，需要区分两个版本线；bhyve 并非 TrueNAS/FreeNAS 的唯一虚拟化选项，早期 FreeNAS 也支持通过 Jail 进行 OS-level 虚拟化，bhyve 提供的是 full machine 虚拟化

## 119.6.2 bhyve 在 illumos 与其他 BSD 衍生系统中的移植

**要点**：bhyve 的 BSD 许可证使其可被移植到其他 BSD 或 CDDL 许可的操作系统中，最重要的移植是 Joyent 的 illumos/SmartOS bhyve 移植——Joyent 在 2015 年开始将 bhyve 移植到 illumos 内核，利用 bhyve 替代此前 SmartOS 依赖的 KVM 移植（illumos KVM 移植维护成本高且功能受限）；Joyent 的 bhyve 移植保留了 bhyve 的用户态设备模型，重写了内核态 vmm 模块以适配 illumos 内核 API；Pluribus Networks 也在其基于 illumos 的网络操作系统 Pluribus Netvisor 中集成了 bhyve；NetApp 作为 bhyve 的初始开发方，在内部存储产品中使用 bhyve 作为虚拟化层，但具体产品型号与部署规模未公开披露；这些移植案例验证了 bhyve BSD 许可证选择的商业价值——GPL 许可的 KVM 无法被移植到 CDDL 许可的 illumos 而不引发许可证冲突

**史料**：Joyent 公司博客 bhyve 移植公告；Joyent GitHub 仓库 illumos-kvm 与 bhyve 移植分支；Pluribus Networks 技术文档；Grehan 在 AsiaBSDCon 2014 的 “bhyve - Past, Present, and Future” 演讲中提及 illumos 移植 ［A］

**史观**：总纲第 24 条——许可证选择直接决定商业采用模式与生态走向：bhyve 的 BSD 许可证不仅服务于 FreeBSD 自身的商业生态（TrueNAS/FreeNAS），还通过 illumos 移植扩展到 CDDL 许可的生态，形成了 “BSD 许可证 → 跨内核移植 → 多生态商业采用” 的正向循环；这是 BSD 许可证在虚拟化领域相对于 GPL 许可证的核心结构性优势

**辨析**：Joyent bhyve 移植的当前状态需要标注——Joyent 在 2019 年被 Maezzem（后更名为 MMC）收购后，SmartOS 与 bhyve 移植的维护节奏放缓，部分开发者离职后以社区方式继续维护；Joyent 的 bhyve 移植并非简单代码搬运，illumos 内核的内存管理、中断子系统、CPU 调度器与 FreeBSD 差异显著，移植工作涉及大量适配代码；Pluribus Networks 的 bhyve 集成主要用于网络功能虚拟化（NFV）场景，将虚拟网络功能（VNF）运行在 bhyve 虚拟机中，与 Pluribus 的 SDN 控制平面集成
