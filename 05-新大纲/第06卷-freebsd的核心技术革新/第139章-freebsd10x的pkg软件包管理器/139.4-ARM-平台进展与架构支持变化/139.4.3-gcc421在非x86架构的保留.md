# 139.4.3 GCC 4.2.1 在非 x86 架构的保留

**要点**：FreeBSD 10.x 全系列中 GCC 4.2.1 仍保留在 base 系统源码树中，用于构建 sparc64、powerpc、powerpc64、mips 等尚未完成 Clang 迁移的架构。Clang/LLVM 在 10.x 时期对这些架构的支持尚不完善：sparc64 Clang 支持存在代码生成 bug 且缺乏持续维护；powerpc/powerpc64 Clang 支持在 10.x 仍为实验性；mips Clang 支持更不成熟。x86（i386/amd64）与 armv6 在 10.0 已默认使用 Clang 构建且不默认安装 GCC，但用户仍可通过 WITHOUT_CLANG_WITH_GCC src.conf 选项启用 GCC 构建（用于 ports 中需要 GCC 的软件也可通过 ports/devel/gcc 安装现代 GCC 版本）。GCC 4.2.1 在 base 中继续存在约 6 年（2014-2020），最终在 FreeBSD 13.0 前后被 Warner Losh（沃纳·洛什）（imp@）等人逐步移除。

**史料**：FreeBSD 10.0 Release Notes Userland Changes（"GCC 4.2.1 and libstdc++ are still built and used by default on... all other platforms where clang is not the default"）、src.conf(5) WITH_GCC/WITHOUT_CLANG 选项文档、Warner Losh freebsd-arch 邮件列表 GCC 退休公告。 ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界：编译器迁移不能 “一刀切”——非 x86 架构的 Clang 支持成熟度不足时继续保留 GCC 是务实工程决策，这也是为什么 GCC 4.2.1 从 “默认” 到 “可选” 到 “完全移除” 历时约 6 年（2014-2020，以 10.0 将 GCC 在 x86 上转为非默认起算）。sparc64 等架构最终因硬件市场萎缩（Oracle 停止 SPARC 服务器开发）与 Clang 支持不足而降级为 Tier 3 或淘汰，GCC 移除加速了这一过程但非唯一原因。

**辨析**：此处再次强调：“10.0 完全移除 GCC” 是常见错误——GCC 4.2.1 在 10.x 全系列 base 中存在并用于非 x86 架构，仅在 x86/arm 默认不安装；sparc64 在 10.x 仍为 Tier 2 架构发布镜像但实际使用人数极少，至 FreeBSD 13 降级为 Tier 3。
