# 139.1.6 基座维护策略揭示了分叉项目的上游同步难题OPNsense151基于FreeBSD

- 基座维护策略揭示了分叉项目的上游同步难题：OPNsense 15.1 基于 FreeBSD 10.0，而后者 2015 年 2 月即终止支持，下一代 15.7 却要等到 7 月，期间依靠安全补丁回移维持；系统内建升级走 FreeBSD pkg 包系统，计划结合 pkg audit 实现安全更新的定向强制升级，且明确将快速发布周期置于长期支持方案之前。（BSD Now EP72，[1523.22-1679.90]，L1）
- 本期新闻记录了 OpenBSD 安全机制的演进节点：将 W^X（同一内存页不可同时可写与可执行）从用户态扩展至内核，使注入代码无法执行而只能触发崩溃，既阻断利用又暴露异常；内核态实现容错空间远小于用户态、调试更难，AMD64 与 SPARC64 因 MMU 硬件支持获得额外优势，技术细节见 CVS 提交。（BSD Now EP72，[515.52-616.44]，L2）
- 听众问及经多国运输的商业 CD 套装是否可能被情报机构截获篡改，节目转引 OpenBSD 邮件列表回复：常规做法并不拦截替换 CD，且可用 signify 工具校验镜像完整性；Theo de Raadt 戏称 CD 标签以“放射性颜料”印刷、在全球邮政系统中更易寻获（4675.76-4683.92），以反讽回应阴谋式担忧。 [存疑脚注] 转写将校验工具记作 Sinify，当为 signify（OpenBSD 5.5 起引入的签名校验工具），系上下文推断（BSD Now EP72，[4592.50-4692.86]，L2）
- Ian Sutton 在 GSoC 期间为 OpenBSD 编写 systemd 四个非 init 组件的兼容包装器：GNOME 3 对 hostnamed、localed、timedated、logind 存在硬依赖，包装器经由 D-Bus 提供与 systemd 相同的接口使其透明可用；项目按操作系统无关设计，FreeBSD 提交者 Baptiste Daroussin 已着手移植，logind 因涉及 PAM 与 3D 加速设备权限传递而最为复杂，其余三个组件已基本成形。（BSD Now EP71，[879.16-934.98]，L1）
- 在 ISC NTPD 连串安全补丁与 NTP 反射攻击的背景下，长期无人维护的 portable OpenNTPD 由曾参与 LibreSSL 相关工作的 Brent Cook 等志愿者接手复活，产出 16 个补丁并重新发布至 GitHub 与 FreeBSD 包仓库，修复过程中还反哺了 OpenBSD 原生版代码。（BSD Now EP71，[602.16-686.20]，L2）
- pkg（pkgng）新增对 OS X 的支持并连发新版本，MacPorts 因 FreeBSD ports 树日益依赖 pkg 而考虑移植其完整功能，未来或为 Mac 引入二进制包；pkg 由此从 BSD 生态扩展为跨平台包管理方案，同期亦出现 Linux 移植迹象。（BSD Now EP71，[1842.70-1950.34]，L2）
- Bryan Drewery（转写误作 Brian Drury）自述入圈路径：2003 年前后经 IRC 结识经营 shell 服务的 FreeBSD 4.11 用户而入坑，2012 年因不满包安装状态找到 pkgng 项目并协同 Baptiste Daroussin，从提交补丁到获 ports 提交权，再到以包框架贡献者身份进入 Port Manager 团队并新获 source 提交权——包体系维护者由工具建设者自然生长而成。（BSD Now EP46，[1963.44-2018.28]，L1）
- FreeBSD 官方包构建集群的一手运维细节：四台号称 beefy 的机器各配 32 核与 96—100GB 内存，每周二 UTC 凌晨一点对 ports 树拍快照并按各发布版与 head 构建 x86 包集，全量需三至五天；另有八套每日测试系统覆盖非 root 构建、打包测试与 QA，quarterly 季度分支自 head 切出并回灌安全修复，属仍在试验中的稳定化机制。（BSD Now EP46，[2439.92-2628.96]，L1）
- iodine DNS 隧道演示的实操要点构成其技术史价值：服务端以特权分离用户与 chroot 运行但密码将以明文见于进程列表，且 iodined 须独占一个 IP 承担 DNS 应答而无法与既有域名服务共存；客户端探测可用查询类型并按 DNS 包尺寸协商 MTU，建隧道后经压缩 SSH 登录验证，并可与 stunnel、SSH 链式跳板教程组合成受限网络下的成套突围方案。（BSD Now EP46，[5978.10-6327.42]，L1）
- Dev Summit 回顾：由 John Baldwin 主持的 FreeBSD 11 目标清单会议逐项认领——新测试框架、MIPS 与 64 位 ARM 扩展、LLDB 调试器、UEFI 引导、以包系统管理基本系统（须解决 chflags 与删除 libc 后无法安装新版本的升级难题）、ASLR、AES-GCM IPsec、Xen Dom0、64 位 kqueue、加密内核转储、可复现构建等，并决定终止仅余两名用户的 Itanium 支持；同场提出的支持模型改革主张按分支计时——分支创建起支持五年、每两年半开新分支、新点发布三个月后弃用旧分支，以矫正 9.1 因扩展支持反而比 9.2 存续更久的倒挂并为厂商提供可预测周期 [存疑脚注] 与会者人名转写多处失真（如 Julio Marino 应为 Julio Merino、David Chisnull 应为 David Chisnall、Beehive 应为 bhyve），具体认领清单应以 Michael Lucas 博客纪要等一手记录复核（BSD Now EP38，[604.04-1361.54]，L2）
- pkgsrc 源流与教程：叙述者称 1997 年 NetBSD 自 FreeBSD ports 体系分叉出自有包系统（初拟名 PackageSRC 或 PackageSource 一类），以可移植性为第一目标——bootstrap 脚本不假设宿主系统提供任何工具，自带编译器与打包工具链，支持非特权安装至用户家目录，可运行于 NetBSD/FreeBSD/OpenBSD/Linux/Solaris/SmartOS/macOS 乃至 Cygwin，并内置基于 VUXML 的漏洞审计框架与选项机制 [存疑脚注] 新转写将 pkgsrc 记作 package src / package source，1997 年分叉动机与初名叙述系主持人口述史，须以 pkgsrc 官方指南与 NetBSD 邮件列表复核（BSD Now EP38，[3293.9-3671.5]，L2）[订正：原 转写将 pkgsrc 多次失真记作 Package Shores、[3294.70-3490.82]，2026-09-30 SenseAudio 重转核对]
- PC-BSD 10.0.2 的包管理重构自述：项目负责人称已将 PBI 体系拆改重建为 pkgng 之上的人性化前端，用户首次升级时自动把既有 PBI 转换为标准包格式，重设计的 AppCafe 成为覆盖约两万余个 ports 应用的统一图形化包管理器，实现全系统单一包管理入口，并探索借助 GRUB 内建模块实现无未加密引导分区的 ZFS 全盘加密方案 [存疑脚注] 转写将 ZFS 失真记作 jelly、TrueOS 失真记作 TruOS/ChurOS，说话人姓名未在本段出现，以 PC-BSD 官方博客与 Kris Moore 发言记录复核为宜（BSD Now EP38，[4212.58-4354.6]，L1）[订正：原 [4212.58-4341.44]，2026-09-30 SenseAudio 重转核对]
- OpenSMTPD 的起点是 OpenBSD 基本系统中缺乏 BSD 许可的 SMTP 服务器；Gilles Chehade 因 sendmail 过于复杂、无法修补而自行编写简单 SMTP 服务器。（BSD Now EP3，[653.72-703.80]，L1）
- OpenSMTPD 的配置语法受 PF 规则语言启发，以逐行规则、首次匹配求值的方式描述邮件路由，追求简洁可读与安全默认值。（BSD Now EP3，[1231.08-1383.62]，L1）
- PackageNG 由 Baptiste Daroussin 开发，在旧 pkg_* 工具之上提供升级、仓库签名与 SQLite 包数据库，并以 pkg install、pkg upgrade 等命令替代旧式安装流程。（BSD Now EP3，[1820.78-1889.22]，L1）
- OpenZFS 在 LinuxCon 上宣布成立，FreeBSD、ZFS on Linux、illumos 等各方协作维护开源 ZFS，并以特性标志与版本统一降低各实现差异。（BSD Now EP3，[2935.46-3032.28]，L2）
- Moore 口述 PC-BSD 发布模式在 2013 年分裂为双轨：延续传统的 9.1、9.2 稳定版，间隔约 12 至 13 个月，适合安装后不再折腾的用户；另增设基于 9-stable 的滚动发布，提供每周更新的 pkgng 仓库并每月推送 world 与 kernel，待 10-stable 成熟后再整体迁移，以弥合 FreeBSD 长发布周期造成的空窗。（BSDTalk EP225，[126.46-185.88]，L1）
- 滚动发布的底层设施是借用与自建的混合：PC-BSD 采用 Colin Percival 的 freebsd-update 工具自建更新服务器，自行决定纳入哪些补丁与哪个 stable 分支；iXsystems 提供硬件，运行 Poudriere 构建自有 pkgng 仓库。Moore 明言此举是与 FreeBSD 项目略微分离，以自主控制推送频率。 [存疑脚注] 转写将 freebsd-update 的作者记作 Collins、构建工具记作 Podrie，按语境应为 Colin Percival 与 Poudriere，须以原始音频复核。（BSDTalk EP225，[192.78-224.86]，L1）
- PC-BSD 桌面无关化后的分发架构是 pkgng 与 PBI 双体系并行：不再构建多套桌面镜像，而是单一镜像加按桌面环境划分的 pkgng 包集，用户可在线调整；PBI 体系即 AppCafe，定位如应用商店，应用自带全部依赖，仅在 9.0 上构建即因 ABI 兼容覆盖整个 9 系列，完全不受滚动发布影响，其内容本质是 FreeBSD ports 的 PBI 重打包。（BSDTalk EP225，[258.02-376.52]，L1）
- 安装器正在把用户推向 ZFS：Moore 希望彻底将 UFS 移出安装器，除老式 32 位且内存不足 1GB 的机器外皆引导使用 ZFS，其理由是 boot environments——更新前快照、失败即回滚——是滚动发布的安全网；他自述 8 系列 ZFS 内存表现粗糙，9 系列在 1GB 内存的 Intel Atom 上桌面使用已无碍。配套地，PC-BSD 重写了网络管理器与挂载工具并逐步摆脱 HAL，因为桌面文件管理器多为 Linux 开发、并不利用 ZFS 快照；Warden 借 ZFS 实现秒级 jail 克隆与快照，Life Preserver 备份工具计划将快照复制到 FreeNAS 或 TrueOS 实现异地保全。（BSDTalk EP225，[429.62-593.14]，L1）
- Daroussin 自述重写动机：学生时代在笔记本上编译 ports 尚可当作乐趣，成为真正使用者后只求装上即用、升级不必等待两天；而在旧体系下想安装特定版本的 Apache，须先上网站查有无对应二进制包，再赌其构建正确、未过时且无安全漏洞。（BSDTalk EP239，[133.06-195.90]，L1）
- 为何不修 pkg_install：许多人尝试过，但该工具并非为如此长的服役期设计，代码注释即可证明其年代已逾二十年；OpenBSD 早年即认清其缺陷并整体重写——当时 ports 树规模尚小、重写代价低，NetBSD 仍在旧代码上不断增补却无法根治，FreeBSD 则选择不作为，以补丁和 ports 树中的大量变通手法迁就，最终得到一个用 C 写成却近乎 shellcode、处处错误执行、内存泄漏、随时可能损坏且完全不可维护的工具。（BSDTalk EP239，[195.90-291.66]，L1）
- 旧工作流的实际体验：pkg_add -r 装包之后只能祈祷依赖齐全、系统不被毁掉一半；两周后想升级 Apache 时，唯一安全的二进制升级路径是全部删除、清理 /usr/local 中残留的大量遗留、再全部重装；Portmaster 与 Portupgrade 虽提供二进制途径，但其底层依赖 pkg_install，因此注定同样做不好。（BSDTalk EP239，[296.46-359.52]，L1）
- pkg 的新范式：安装最新 Firefox 只需一条命令，包引擎自动计算全部依赖、确认可得性并按正确顺序预演安装，用户确认后才抓取、校验一致性与隐藏冲突，若有问题则什么都不会被安装；pkg upgrade 依据本地数据库与远程仓库推断升级顺序与冲突处理，把系统升至最新；此后用户即可卸载 Portmaster 与 Portupgrade，纯二进制用户甚至不再需要 ports 树、不必在主机上编译。（BSDTalk EP239，[362.86-442.16]，L1）
- pkgng 的架构定位：它不是又一个前端而是新的二进制包管理系统，覆盖安装、删除与信息查询——包使用的许可证、构建时选项、文件与包的双向归属查询皆可完成；同时它是一个高层 C 库，命令行的 pkg 只是作者写出的一个前端，刻意让他人可基于该库为 GNOME、KDE 或 PackageKit 等编写图形前端；演进计划上下一版本预计次月底发布，并教授用户编写插件以自行扩展。（BSDTalk EP239，[446.06-499.36]，L1）
