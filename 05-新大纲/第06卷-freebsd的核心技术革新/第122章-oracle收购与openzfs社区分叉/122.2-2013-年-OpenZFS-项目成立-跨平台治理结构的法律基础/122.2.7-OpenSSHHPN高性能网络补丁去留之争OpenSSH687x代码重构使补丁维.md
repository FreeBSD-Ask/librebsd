# 122.2.7 OpenSSHHPN高性能网络补丁去留之争OpenSSH687x代码重构使补丁维

- OpenSSH HPN（高性能网络）补丁去留之争：OpenSSH 6.8/7.x 代码重构使补丁维护困难，FreeBSD 邮件列表就弃用与否展开讨论，有参与者称 HPN 反而劣化性能；Alan Jude 以背靠背 10GbE 实测回应——基础 OpenSSH 达 5-6 Gbps，AES-CTR/GCM 足以喂饱链路、瓶颈在 MAC 与 CPU 而非加密本身，且 HPN 动态窗口行为异常；又借 dummy net 模拟 50/100 毫秒往返时延，按带宽时延积推导出 62.5/128 MB 套接字缓冲需求。辨析点在于：邮件列表的直觉争论最终须让位于可复现的基准测试，同时基准设计本身（背靠背、回环、时延模拟）决定了结论的适用边界。[存疑脚注] 转写人名失真：“deg erling smart grave”疑为 Dag-Erling Smørgrav，“john margurney”与“brian drury”均无法凭本转写确证。 [存疑脚注] HPN 之争涉及的多方邮件列表参与者人名在转写中失真，仅能部分推断，引用前须回查原始邮件列表。（BSD Now EP116，[1257.30-1498.32]，L1）
- 围绕 FreeBSD 是否存在“客户”的分歧构成该期最尖锐的治理辨析：Hubbard 转述 Samba 团队列出的 FreeBSD 架构缺陷清单及其与基金会的沟通，主张项目应以战略协作回应 NFS、CIFS、对象存储等真实部署需求，并直斥“开源项目没有客户”之说为非（4778.99-4893.58）；他同时自陈在项目无共识时推动议程如同推石上山，缺乏回流机制的贡献者极易选择私下分叉。争论背后是志愿者自治传统与商业化现实之间的张力，是理解 2015 年前后 FreeBSD 治理走向的关键切口。（BSD Now EP113，[4778.99-4893.58]，L1）
- Hubbard 以 X Consortium 源码树拆分为先例论证 FreeBSD 基本系统打包化的必要性：他承认自己当年斥 X.org 组件化为异端，如今承认“X.org 的拆分者事后被证明完全正确”（5946.28-5949.92），并断言“FreeBSD 面前也有类似的演化在等着”（5977.42-5984.02）；其设想是以 JSON 之类可读格式定义 base 内容、按角色生成发行镜像，把 sendmail、Perl 等历史包袱移出 base。此论把“base 的定义”与“如何为特定用途构建”分离，直指单体源码树与现代化打包体制之间的结构性矛盾。（BSD Now EP113，[5946.28-5988.30]，L1）
- 新闻聚合部分须逐项复核后方可用于考据：mandoc 模糊测试文章作者名转写失真，应为 Ingo Schwarze；OpenZFS 大会主讲人转写亦失真，应为 Matt Ahrens；Facebook 白皮书的具体错误率数字经双音轨转写疑有失真；NetBSD 7.0 RC1 新特性清单（KMS/DRM、ARM SMP、安装器 GPT、Lua 内核脚本、NPF、Clang 3.6.1）以及 OpenSMTPD 5.7.1 RC1、OctoPackage（自 Arch Linux 的 Octopi 移植至 FreeBSD package-ng）均为主持人二手转述，须以对应发布公告与原始文章核对。 [存疑脚注] 转写专名系统性失真：FreeBSD 多次转作 FreemiusD、VSD、previous D 等，人名 Ingo Schwarze、Matt Ahrens 及白皮书数字均须对照节目 show notes 与原始公告复核（BSD Now EP95，[3685.17-3763.53]，L2）
- 是否 Linux 化的分歧被摆上台面：听众来信以 base 与附加软件的清晰区隔正是 FreeBSD 区别于任意包集合式 Linux 发行版之处为由质疑打包化方向；主持人与访谈者反复申明 base 与第三方以 usr/local 为界的结构不变、world 与 kernel 仍一体化开发，pkg 只是升级与分发载体。争议实际落在工具链变更与本体论边界的混淆上。（BSD Now EP84，[3885.96-3985.84]，L2）
- 企业存在与治理文化的双重辨析：主持人断言 Juniper 设备几乎皆基于 FreeBSD、多数 Cisco 防火墙亦然，PF 已内置于 OS X 与 iOS，以此论证 BSD 技能的职场价值；另以 OpenBSD 提交日志末尾的 OK 署名对照 FreeBSD 的 Reviewed by 与 Approved by 机制，展示两项目代码评审治理的同构与差异。 [存疑脚注] 多数 Cisco 防火墙基于 FreeBSD 的说法为主持人单方断言，本期未给出处，未经交叉验证；Juniper 基于 FreeBSD 属可查事实但同样未当期举证。（BSD Now EP84，[4197.66-4389.78]，L2）
