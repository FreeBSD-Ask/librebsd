# 122.3.1 要点ZFSOnLinuxZoL最初由LawrenceLivermoreNatio

**要点**：ZFS On Linux（ZoL）最初由 Lawrence Livermore National Laboratory（LLNL）的 Brian Behlendorf 于 2008 年发起，作为 HPC（高性能计算）场景下 ZFS 的 Linux 移植；ZoL 将 ZFS 实现为可加载内核模块（LKM），通过 SPL（Solaris Porting Layer，solaris.ko 和 spl.ko 模块）提供 Solaris 内核 API 兼容层；ZoL 代码完全以 CDDL 许可发布，不包含任何 GPL 代码，因此主张 ZFS 模块是独立作品而非 Linux 内核的衍生作品；Linux 内核的 MODULE_LICENSE(“CDDL”) 宏标记 ZFS 为非 GPL 模块，这意味着 ZFS 无法使用 Linux 内核中仅导出给 GPL 模块的符号（GPL-only symbols），但可使用所有 EXPORT_SYMBOL() 导出的通用符号

**史料**：Behlendorf 2008 年 ZoL 项目公告（zfsonlinux.org）；SPL（Solaris Porting Layer）GitHub 仓库（github.com/openzfs/spl）；ZoL 代码库 MODULE_LICENSE 声明；Linux 内核 COPYING 文件关于模块的例外条款说明；netbsd.duckdb 查询 L6.4.1.Linux 显示：openzfs/zfs 仓库 commit message 含 “Linux” 关键词的年度统计——2008 年 6249/8883（70.4%）、2009 年 8927/10914（81.8%）、2010 年 3989/5656（70.5%），2011 年骤降至 140/459（30.5%）反映 ZoL 代码库从 LLNL 内部仓库迁移至 GitHub 后 commit 量大幅下降；2019 年 146/1090（13.4%）至 2025 年 266/1552（17.1%），Linux 关键词占比稳定在 13%-25%，反映 OpenZFS 2.0 统一代码库后 Linux 不再是唯一主导平台；netbsd.duckdb 查询 L6.4.1.FreeBSD 显示：FreeBSD 关键词 commit 从 2011 年 2/459（0.4%）上升至 2024 年 621/1352（45.9%）、2025 年 640/1552（41.2%），与 OpenZFS 2.0 后 FreeBSD 集成深度提升一致 ［A］

**史观**：专题语（不设总纲条号）——技术路线分化（原挂总纲第 6 条系伪名目）：ZoL 的模块加载策略是法律约束下的工程妥协——ZFS 无法进入主线内核，因此通过 DKMS/LKM 方式在主线外分发；这种 “核外生存” 模式虽然有性能和维护成本，但在法律灰区中开辟了一条可行路径

**辨析**：需澄清：Linux 内核的 GPL 许可范围问题——Linux 内核 COPYING 文件明确指出 “kernel modules are considered derivative works”，但内核社区实际上长期容忍非 GPL 模块（NVIDIA、VMware 等闭源驱动，以及 OpenAFS 等 CDDL 模块），这形成了事实上的 “模块例外” 实践；ZoL 的法律地位在理论上有争议，但在实践中已被大多数 Linux 发行版（Ubuntu、Debian、Fedora、SUSE 等）通过各种方式接受；netbsd.duckdb L6.4.1 数据提示：2008-2010 年 Linux 关键词占比高达 70%-82%，因 ZoL 早期 commit message 普遍含 “Linux” 适配说明；2011 年后占比下降并非 Linux 适配工作减少，而是 OpenZFS 代码库统一后 commit message 不再强调平台特定性；0 信任原则提示：关键词匹配大小写不敏感（LIKE 默认），“Linux” 可能匹配非平台语境（如人名、路径名），须结合 commit message 全文交叉验证
