# 122.3.4 FreeBSD 与 Linux ZFS 法律地位比较

**要点**：FreeBSD 与 Linux 在 ZFS 法律地位上的根本差异：FreeBSD 内核采用 BSD-2-Clause 许可证（permissive），CDDL 文件可以直接放入内核源码树分发，不存在 copyleft 冲突；Linux 内核采用 GPLv2（strong copyleft），CDDL 文件无法合入主线，只能通过 DKMS/LKM 方式单独分发；这一差异导致的实际后果：FreeBSD 从 7.0（2008 年）起即在内核中包含 ZFS，FreeBSD 13.0（2021 年 4 月）将 OpenZFS 2.0 作为默认文件系统；Linux 上 ZFS 始终是外核模块，发行版支持情况不一（Ubuntu 20.04+ 可选安装、Debian contrib 源、Fedora 不官方支持、NixOS 原生支持）；FreeBSD 可以通过 pkg 升级 ZFS 版本，也可在启动时选择不同 ZFS 版本；Linux ZFS 升级通常需要重新编译内核模块（DKMS 自动处理）

**史料**：FreeBSD 13.0 Release Notes（2021-04-13，OpenZFS 默认）；各 Linux 发行版 ZFS 支持文档；GPLv2 §2(b) 与 CDDL §3.2 对比；FreeBSD Core Team ZFS 许可声明 ［A］

**史观**：专题语（不设总纲条号）——技术路线分化（原挂总纲第 6 条系伪名目）：许可证兼容性差异是 FreeBSD 和 Linux 在 ZFS 部署路径上分化的根本原因，这一分化不仅影响技术架构（内核内 vs 内核模块），也深刻影响了 ZFS 的社区分布和开发重心——OpenZFS 2.0 选择以 ZoL 代码为基础统一跨平台开发，某种程度上反映了 Linux 用户群体规模优势最终压过了 FreeBSD 的先发优势

**辨析**：需注意 FreeBSD 并非唯一能原生集成 ZFS 的 BSD 系统：TrueOS（基于 FreeBSD）、DragonFly BSD（采用 HAMMER 而非 ZFS）、NetBSD 通过 zfs 模块支持 ZFS、OpenBSD 因许可证和安全考虑拒绝 ZFS（OpenBSD 开发者认为 CDDL 与 BSD 许可证存在潜在冲突，且 ZFS 代码过于复杂）
