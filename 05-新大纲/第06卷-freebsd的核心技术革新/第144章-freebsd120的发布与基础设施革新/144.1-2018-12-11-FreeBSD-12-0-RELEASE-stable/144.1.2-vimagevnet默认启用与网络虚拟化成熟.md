# 144.1.2 VIMAGE/VNET 默认启用与网络虚拟化成熟

**要点**：VIMAGE（VNET 虚拟网络栈）在 FreeBSD 12.0 GENERIC 内核中正式默认启用，结束了自 FreeBSD 8.0（2009）引入以来长达近十年的实验性状态。VIMAGE 允许每个 **jail(8)** 拥有独立的网络栈实例——包括独立的路由表、接口集合、防火墙规则、套接字缓冲区等网络状态，是云环境与容器化部署的关键基础设施。VIMAGE/VNET 的主要开发者包括 Bjoern Zeeb（bz@）、Marko Zec 等人，FreeBSD Foundation 赞助了部分稳定性工作。VNET 默认启用后，与 **pf(4)** 可在 **jail(8)** 中使用（12.0 另一个新特性）配合，使每个 jail 可拥有独立的 pf 防火墙规则集。同期 NUMA（Non-Uniform Memory Access）支持也在 amd64 GENERIC 与 MINIMAL 内核配置中默认启用，优化多路 CPU 系统的内存访问性能。

**史料**：FreeBSD 12.0-RELEASE Announcement（“The VIMAGE kernel configuration option has been enabled by default”、“The NUMA option has been enabled by default in the amd64 GENERIC and MINIMAL kernel configurations”）、**VNET(9)** 手册页、Bjoern Zeeb 关于 VNET 的技术演讲与邮件列表提交、FreeBSD Quarterly Status Reports 网络章节、GENERIC 内核配置文件中 `options VIMAGE` 的默认启用提交。 ［A］

**史观**：总纲第 9 条——经验优先：VIMAGE/VNET 是一个典型的“复杂内核功能经过长期实践检验最终进入默认配置”案例。网络虚拟化本质上是给内核网络子系统引入了一整套“实例化”机制——每个网络状态都需要从全局变量变为 per-instance 变量，这涉及数千行代码的重构。VIMAGE 从实验性选项到默认启用耗时近十年，体现了 FreeBSD 以运行经验与稳定性验证为准绳、“不到成熟不默认”的工程哲学。

**辨析**：部分资料称“VNET 在 11.x 已稳定可用”——11.x 时期 VIMAGE 确实可通过自定义内核启用，但 GENERIC 内核默认不带 `options VIMAGE`，用户需重编译内核；12.0 是 GENERIC 首次默认包含此选项。VNET 默认启用不等于网络栈完全虚拟化无缺陷——12.x 与 13.x 时期仍有 VNET 相关的稳定性修复，特别是模块加载/卸载时的资源泄漏问题。**pf(4)** 在 jail 中的支持在 12.0 为初始状态，部分高级功能（如 ALTQ 队列规则）在 jail 环境中仍有限制。
