# 144.3.1 **bhyve(8)** 虚拟化增强

**要点**：FreeBSD 12.0 中 **bhyve(8)** Type-2 hypervisor 获得多项重要改进：①NVMe 设备仿真——bhyve 可向客户机导出 NVMe 命名空间，模拟 NVMe SSD 设备，对测试 NVMe 驱动与存储堆栈有重要价值（r338210 含部分赞助标记）；②bhyve 可在 **jail(8)** 中运行——配合 VNET，可在 jail 内运行 bhyve 虚拟机，实现容器与虚拟化的双层隔离；③UEFI GOP（Graphics Output Protocol）帧缓冲改进——bhyve 图形支持持续完善；④bhyve 命令行增加 `help` 子命令列出支持的 LPC/PCI 设备；⑤checkpoint/suspend/resume 功能稳定性改进；⑥PCI 直通（passthrough）改进。bhyve 主要由 Peter Grehan（彼得·格雷汉）（grehan@）和 Neel Natu（尼尔·纳图）（neel@）维护，NetApp 与 iXsystems 赞助了部分开发工作。12.x 时期 bhyve 已支持 FreeBSD、Linux、OpenBSD、NetBSD、Windows（需 UEFI+VirtIO）等客户机操作系统。

**史料**：FreeBSD 12.0-RELEASE Announcement（"The **bhyve(8)** utility has been updated to add NVMe device emulation“、”The **bhyve(8)** utility is now able to be run within a **jail(8)**"）、**bhyve(8)** 手册页、12.0 Release Notes Virtualization 章节、Peter Grehan BSDCan/EuroBSDCon 演讲、FreeBSD Quarterly Status Reports Virtualization 章节。 ［A］

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧〔映射存疑，待主理人审定〕：bhyve 代表 FreeBSD 在虚拟化领域“自研 BSD 许可 hypervisor”的路线，与 Linux 的 KVM（GPL）、Xen（混合许可）形成差异化。bhyve 在 jail 中运行的能力是 KVM 所不具备的（KVM 需要 /dev/kvm 访问权限，通常在宿主机全局命名空间运行），这体现了 FreeBSD 将 jail 作为核心隔离机制的设计哲学——所有服务包括虚拟化本身都可被 jail 约束。

**辨析**：bhyve 在 12.0 仍不支持实时迁移（live migration）——此功能在 FreeBSD 13.x 才引入；bhyve 管理仍以命令行为主，图形化/API 化管理工具（如 vm-bhyve、CBSD、bhyvectl）通过 ports 提供；bhyve 的 NVMe 仿真为软件仿真而非 VFIO 直通 NVMe 设备——真实 NVMe 设备直通需通过 PCI passthrough 实现。NVIDIA vGPU 等高级 GPU 虚拟化不在 12.x bhyve 支持范围内。
