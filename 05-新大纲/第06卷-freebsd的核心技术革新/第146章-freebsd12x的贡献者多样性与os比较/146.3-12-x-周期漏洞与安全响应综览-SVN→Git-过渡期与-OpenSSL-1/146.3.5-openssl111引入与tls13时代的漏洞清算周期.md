# 146.3.5 OpenSSL 1.1.1 引入与 TLS 1.3 时代的漏洞清算周期

**要点**：12.x 周期是 FreeBSD 历史上 OpenSSL 第三次代际迁移（1.0.2→1.1.1）的执行期——12.0-RELEASE（2018.12.11）首次将 OpenSSL 升级至 1.1.1a，引入 TLS 1.3（RFC 8446）支持，是 11.x 全系列停留于 OpenSSL 1.0.2 长达 5 年后的代际跨越；12.x commit 周期内 OpenSSL 相关 CVE commit 共 **约 8 条**，涉及 CVE-2020-1967（OpenSSL 远程 DoS，**SA-20:11.openssl**，commit `c79d631acdb9`，2020-04-21，Gordon Tetlow 修复）、CVE-2020-1968（Raccoon attack，TLS 1.2 及以下 DH 弱点，commit `922c452bd871`，2021-02-18，Jung-uk Kim 修复）、CVE-2020-1971（ASN.1 NULL 指针解引用，**SA-20:33.openssl**，commit `2120d07af09c`，2020-12-08，Gordon Tetlow 修复）、CVE-2021-23840（EVP_CipherUpdate 输出长度溢出，commit `9e94eac9765f`，2021-02-18，Jung-uk Kim 修复）、CVE-2021-23841（X509_issuer_and_serial_hash NULL 解引用，commit `2dcaecea30c0`，2021-02-18，Jung-uk Kim 修复）、CVE-2021-3449（TLS 重协商 ClientHello NULL 解引用，commit `af61348d61f5`，2021-03-25，Gordon Tetlow 修复）、CVE-2021-3450（X509_V_FLAG_X509_STRICT 证书链检查缺陷，同 commit）；**关键辨析**：12.x 周期 OpenSSL 1.1.1 系列的 CVE 数量（约 8 个）显著少于 14.x 周期 OpenSSL 3.0 系列（约 20 个），反映 OpenSSL 1.1.1 作为 LTS 版本在 2018-2023 年间已充分成熟，而 3.0 系列在 2021-2024 年仍处于“代际迁移带来的 CVE 清算”阶段

**史料**：**freebsd.duckdb** `commits` 表 `freebsd-src` 仓库 OpenSSL CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2018-12-01' AND author_date<'2021-04-01' AND message_subject LIKE '%OpenSSL%' AND (message_body LIKE '%CVE-%' OR message_subject LIKE '%CVE-%') ORDER BY author_date ASC`；FreeBSD-SA-20:11.openssl（2020-04-21）、SA-20:33.openssl（2020-12-08）、SA-21:07.openssl（2021-03-25）PGP 签名公告；Gordon Tetlow 与 Jung-uk Kim 的 OpenSSL CVE 修复 commit 序列；OpenSSL 1.1.1 Release Notes（openssl.org）；RFC 8446 TLS 1.3 规范 ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界：12.x 周期 OpenSSL 1.0.2→1.1.1 迁移与 14.x 周期 1.1.1→3.0 迁移的对比揭示“代际迁移代价”的规律——每次 OpenSSL 主版本切换都会带来 3-5 年的 CVE 清算周期，1.1.1 迁移带来约 8 个 CVE（12.x-13.x 周期），3.0 迁移带来约 20 个 CVE（14.x 周期）；这一规律反映 OpenSSL 重构规模与 CVE 数量正相关——1.1.1 相对 1.0.2 的重构主要在 API 层（数据结构变不透明），3.0 相对 1.1.1 的重构涉及 Provider 架构、随机数生成器重写等更深层次；**TLS 1.3 引入的工程意义**：12.0 引入 TLS 1.3 是 FreeBSD 加密栈进入“现代密码学”时代的标志——TLS 1.3 强制前向保密、移除 RSA 密钥交换与 SHA-1/MD5 等不安全算法，使 FreeBSD 服务器（Netflix CDN、Yahoo! 等）的 TLS 性能与安全性同步提升；**与 Linux 对比**：Debian 10（2019.7）使用 OpenSSL 1.1.1，Ubuntu 18.04 LTS 使用 1.1.0，FreeBSD 12.0 早于 Debian 10 半年完成迁移，反映 FreeBSD 在加密栈升级上的相对及时

**辨析**：**需严格区分 OpenSSL 上游 CVE 与 FreeBSD 特有 CVE**：12.x 周期 OpenSSL CVE 全部来自 OpenSSL 上游（OpenSSL 项目发布的 CVE），FreeBSD 通过 vendor import 同步修复，无 FreeBSD 特有的 OpenSSL 漏洞——这与 14.x 周期 CVE-2024-5535（OpenSSL 3.0 重构 API 引入）不同；**CVE-2020-1968 Raccoon attack 的特殊性**：Raccoon 是 TLS 1.2 及以下版本的 DH 共享密钥弱点，与 TLS 1.3 无关——TLS 1.3 强制使用 ephemeral DH 且移除静态 DH，故 TLS 1.3 不受 Raccoon 影响；这反而印证 TLS 1.3 的设计安全性；**OpenSSL 1.1.1a 中的“a”后缀辨析**：12.0 携带 1.1.1a（不是 1.1.1 初始版本），“a”是 1.1.1 发布后的首个补丁版本，修复了 1.1.1 初始发布后的问题；**12.1/12.2 OpenSSL 升级链**：12.1（2019.11）升级至 1.1.1d，12.2（2020.10）升级至 1.1.1h，12.3（2021.12）升级至 1.1.1q，12.4（2022.12）升级至 1.1.1q（与 12.3 同版本但累积安全补丁）；**与 14.x 周期 OpenSSL 3.0 迁移对比**：14.x 周期 OpenSSL 3.0 在 14.0（2023.11）替换 1.1.1，恰在 1.1.1 EOL（2023-09-11）后两个月，时机选择与 12.0 在 1.1.1 发布后三个月引入形成对照——前者是被 EOL 倒逼的迁移，后者是主动跟进上游
