# 146.3.7 12.x 安全响应文化评估——Security Officer Gordon Tetlow 任期全程与 SVN→Git 迁移的连续性

**要点**：12.x 周期是 FreeBSD Security Officer Gordon Tetlow（gordon@）任期的核心阶段——Gordon Tetlow 自 11.2-RELEASE（2018.6）接任 Security Officer，至 14.x 周期仍持续任职，12.x 周期（2018-2022）是其任期稳定期；Deputy 为 Ed Maste（埃德·马斯特）（emaste@）、Remko Lodder（remko@，至 12.1 后淡出）、Xin Li（delphij@，12.2 起任 Security Team Liaison）；**Gordon Tetlow 在 12.x 周期主导的修复 commit 数量**：根据 freebsd-12.x.md CVE commit 清单统计，Gordon Tetlow 名下修复 commit 约 148 条（freebsd.duckdb 同口径 SQL 实测，2026-09-13 复核；占 12.x 周期 CVE commit 总数 309 条的约 48%），是 12.x 周期 CVE 修复的核心执行者；**SVN→Git 迁移的连续性**：12.x 周期跨越 2020 年 12 月 SVN-to-Git 迁移，12.0-12.2 为 SVN 时代发布，12.3-12.4 为 Git 时代发布；这一迁移对 Security Team 工作的影响是 commit hash 从 svn revision（r341484）变为 git hash（`4ba619efbdd2`），但 MFC（Merge From Current）工作流保持不变——stable/12 分支在迁移前后均可通过 cherry-pick 或 svn merge 方式回溯 -CURRENT 修复

**史料**：**freebsd.duckdb** `commits` 表 `freebsd-src` 仓库 Gordon Tetlow CVE commit 查询：`SELECT count(*), min(author_date), max(author_date) FROM commits WHERE repo_name='freebsd-src' AND author_date>='2018-12-01' AND author_date<'2021-04-01' AND author_name LIKE '%Gordon Tetlow%' AND (message_subject LIKE '%CVE-%' OR message_body LIKE '%CVE-%')`；FreeBSD Core Team 选举公告（freebsd-announce，2018/2020 届）；FreeBSD Security Team 历史成员名单；freebsd-12.x.md CVE commit 清单作者分布统计；SVN-to-Git 迁移记录（详见相关章节） ［A］

**史观**：总纲第 23 条——一切历史写作都是基于哲学设定的历史小说：12.x 周期 FreeBSD Security Team 的工程伦理呈现三个特征：① **“单一 Security Officer 长期稳定”模式**——Gordon Tetlow 任期跨越 11.2 至 14.x，长达 6 年以上，为 FreeBSD 安全响应提供连续性；这一模式与 OpenBSD 的“团队式 security”（Theo de Raadt（西奥·德·若特） 主导但多人参与 errata 决策）形成对比，FreeBSD 更依赖单一 Security Officer 的判断与执行；② **“SVN→Git 迁移不影响安全工作流”**——12.x 周期跨越版本控制系统的根本性迁移，但 Security Team 的 SA 发布节奏（2019 年 26 个、2020 年 33 个）在迁移前后保持稳定，反映 Security Team 工作流对版本控制系统的解耦——SA 发布依赖 -CURRENT 与 -STABLE 分支的代码同步机制，与具体版本控制系统无关；③ **“贡献组件维护者作为 Security Team 延伸”模式**——Cy Schubert（wpa_supplicant/SQLite/Unbound/Heimdal）、Martin Matuska（libarchive）、Kristof Provost（pf）等维护者在 12.x 周期承担了大量贡献组件 CVE 修复工作，是 Security Team 在子系统层面的延伸；这种“Security Officer + 子系统维护者”的协作模式是 FreeBSD 安全响应的组织基础

**辨析**：**需精确说明 Gordon Tetlow 的修复 commit 数量**：根据 freebsd-12.x.md CVE commit 清单，Gordon Tetlow 名下 commit 涵盖 bhyve（SA-18:14、SA-19:16）、pf（SA-19:06）、ipfw（SA-20:10）、SCTP（SA-20:14）、IPv6（SA-20:20）、ICMPv6（SA-19:19、SA-20:31）、cryptodev（SA-20:15/16）、USB（SA-20:17）、posix_spawnp（SA-20:18）、libfetch（SA-20:01）、ipsec（SA-20:02）、UFS（SA-19:10）、cd(4)（SA-19:11）、pts（SA-19:13）、mqueuefs（SA-19:15/24）、fd（SA-19:02/17）、telnet（SA-19:12）、bhyve_vmcs/bhyve_svm（SA-20:28/29）、unbound（SA-20:19）、sqlite（SA-20:22）、sendmsg（SA-20:23）、rtsold（SA-20:32）、bzip2（SA-19:18）、ntpd（SA-19:04）、OpenSSL（SA-20:11、SA-20:33、SA-21:07）等几乎所有子系统——Gordon Tetlow 不是特定子系统的维护者，而是 Security Officer 的“全栈修复者”角色，这是 FreeBSD Security Team 与 Linux 各子系统独立维护者模式的显著差异；**SVN→Git 迁移对 SA 发布的影响辨析**：12.0-12.2 时期 SA 引用的修复 commit 是 svn revision（如 r341484），12.3-12.4 时期是 git hash（如 `4ba619efbdd2`）——这一变化对管理员使用 SA 的方式产生影响，**freebsd-update(8)** 二进制补丁机制在迁移前后均正常工作，但源码构建用户需要适应新的版本控制命令；**与 14.x 周期对比**：14.x 周期 Security Officer 由 Mark Johnston 接任，Deputy 为 Philip Paeps（菲利普·佩普斯），Security Team 进入“主动审计—批量披露”模式；12.x 周期 Security Team 仍以“被动响应外界报告 + 贡献组件 CVE 同步”为主，主动审计尚未成为主要工作模式——这是 12.x 与 14.x 周期安全响应文化的根本差异；**12.x 周期 SA 数量稳定性的辨析**：2019 年 26 个 SA、2020 年 33 个 SA、2021 年 1-3 月 7 个 SA，月均约 2.4 个，未出现 14.x 周期 2026 年上半年 49 个 SA 的爆发式增长——这反映 12.x 周期 Security Team 的工作节奏以“持续稳定响应”为主，而非“集中审计批量披露”
