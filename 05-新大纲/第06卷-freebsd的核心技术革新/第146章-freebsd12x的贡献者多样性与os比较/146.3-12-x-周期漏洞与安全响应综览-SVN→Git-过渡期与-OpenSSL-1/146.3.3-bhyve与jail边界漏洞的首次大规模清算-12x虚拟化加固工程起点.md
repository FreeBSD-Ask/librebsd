# 146.3.3 bhyve 与 jail 边界漏洞的首次大规模清算——12.x 虚拟化加固工程起点

**要点**：12.x 周期内 FreeBSD 虚拟化与隔离子系统共发布 **12 个 SA**——bhyve 5 个（**SA-18:14.bhyve**、**SA-19:16.bhyve**、**SA-19:21.bhyve**、**SA-20:28.bhyve_vmcs**、**SA-20:29.bhyve_svm**，其中 SA-20:28/29 为同日成对发布的 SVM/VMCS 双补丁）、jail 3 个（**SA-20:08.jail**、**SA-21:04.jail_remove**、**SA-21:05.jail_chdir**），其余 4 个涉及 epair（SA-20:07.epair）、freebsd32（SA-19:14.freebsd32）、sendmsg（SA-20:23.sendmsg）、posix_spawnp（SA-20:18.posix_spawnp）；SA-21:08.vm 系 13.0 周期开端，不计入本周期 12 个；**bhyve 漏洞群的技术演进**：SA-18:14.bhyve（CVE-2018-17160，2018-12-04）是 bhyve 设备模型边界检查不足，是 12.x 周期首个 SA，恰好早于 12.0-RELEASE 一周；SA-19:16.bhyve（CVE-2019-5604）是 XHCI 设备越界读，由 Gordon Tetlow 修复（commit `5b7c0b55b21e`）；SA-19:21.bhyve 涉及 e1000 与 TSO 验证（CVE-2019-5609，commit `ed9ffd2f09f7`，John Baldwin（约翰·鲍德温） 修复）；SA-20:28.bhyve_vmcs（CVE-2020-24718）与 SA-20:29.bhyve_svm（CVE-2020-7467）是 12.x 周期最严重的 bhyve 漏洞——VMCS（Intel）与 SVM（AMD）虚拟机控制结构写入允许导致 guest 逃逸至 host 内核，由 Konstantin Belousov 在 commit `101d5b527a52`、`3294cd04c6a4` 等修复

**史料**：**freebsd.duckdb** `commits` 表 `freebsd-src` 仓库 bhyve CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2018-12-01' AND author_date<'2021-04-01' AND message_subject LIKE '%bhyve%' AND message_body LIKE '%CVE-%' ORDER BY author_date ASC`；FreeBSD-SA-18:14.bhyve、SA-19:16.bhyve、SA-19:21.bhyve、SA-20:28.bhyve_vmcs、SA-20:29.bhyve_svm PGP 签名公告；Gordon Tetlow、John Baldwin、Konstantin Belousov 的 bhyve CVE 修复 commit 序列；**jail** SA-20:08.jail（CVE-2020-7453，nested jails 内核内存泄露）、SA-21:04.jail_remove（CVE-2020-25581，**jail_remove(2)** 与 **fork(2)** 竞争，commit `b306be13a9c7`，Jamie Gritton 修复）、SA-21:05.jail_chdir（CVE-2020-25582，**jail_attach(2)** 同时切换 root 与 cwd，commit `4dd124c3171d`，Jamie Gritton 修复）PGP 签名公告 ［A］

**史观**：总纲第 6 条——和解优于斗争：12.x 周期是 bhyve 作为 FreeBSD 自研 BSD 许可 hypervisor 的“第一次大规模漏洞清算期”——先前 10.x-11.x 周期 bhyve 漏洞 SA 极少（仅零星一两个），12.x 周期 5 个 bhyve SA 集中爆发，反映 bhyve 在 12.0 引入 NVMe 仿真、jail 内运行、PCI 直通改进后攻击面扩大；**与 14.x 周期对比**：14.x 周期 bhyve SA 共 5 个（SA-24:01.bhyveload、SA-24:10/12/15/17.bhyve）但集中于 6 周内爆发（2024 年 9-10 月），是 Security Team 主动审计结果；12.x 周期 bhyve SA 时间跨度近 2 年（2018.12-2020.09），是被动响应外界报告与开发过程发现；这一差异印证 FreeBSD bhyve 安全治理从“被动响应”到“主动审计”的演进；**jail 漏洞群的特殊性**：12.x 周期 jail 漏洞 SA 由 Jamie Gritton（jail 维护者）主导修复，反映 jail 在 12.x 时期功能扩展（VNET+pf 集成、Linuxulator in jail）带来的新攻击面

**辨析**：**需严格区分**：① SA-20:28.bhyve_vmcs（CVE-2020-24718，Intel VMCS 写入）与 SA-20:29.bhyve_svm（CVE-2020-7467，AMD SVM 写入）是两个独立 SA 但同日（2020-09-15）发布——这是 FreeBSD Security Team 处理“同源漏洞跨架构”的典型模式，Intel 与 AMD 虚拟化指令集独立但漏洞原理同构；**bhyve 漏洞影响范围辨析**：12.x 时期 bhyve 默认配置不开启 SVM/VMCS 写入许可——CVE-2020-24718/7467 仅在 bhyve 配置允许 guest 写入 VMCB/VMCS 时触发，默认配置不受影响，但企业部署中为性能常启用此选项；**jail_remove 竞争条件辨析**：CVE-2020-25581 是 **jail_remove(2)** 与 **fork(2)** 之间的 TOCTOU（time-of-check-to-time-of-use）漏洞——jail_remove 检查进程列表时 fork 已发起但尚未完成，导致 jail 被销毁后仍有进程引用其资源；**与 13.x/14.x jail 漏洞对比**：12.x 周期 jail SA 共 3 个，14.x 周期 jail SA 共 3 个（SA-26:02/04/38.jail），但 14.x 周期 jail SA 集中于 2026 年上半年，反映 jail 安全审计在 14.x 周期被重新激活
