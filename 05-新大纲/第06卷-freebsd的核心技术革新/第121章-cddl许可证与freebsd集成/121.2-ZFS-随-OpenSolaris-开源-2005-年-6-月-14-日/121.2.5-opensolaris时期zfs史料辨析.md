# 121.2.5 OpenSolaris 时期 ZFS 史料辨析

**要点**：OpenSolaris 时期（2005-2010 年）的 ZFS 一手史料面临严重的访问性问题：OpenSolaris 源码仓库（hg.opensolaris.org）于 2010 年 Oracle 收购后逐渐下线；Sun 官方文档站点（docs.sun.com）在 Oracle 收购后多次迁移，大量 ZFS 文档链接失效；OpenSolaris 邮件列表（opensolaris.org/os/community/zfs/）已无法访问，存档分散在 mail-archive.com、Nabble 等第三方存档站点；Bonwick 博客从 blogs.sun.com 迁移到 blogs.oracle.com 后，Oracle 于 2010 年代后期关停了 Oracle Blogs 平台上的旧个人博客，2005-2010 年的博客文章仅能通过互联网档案馆访问；可访问的可靠一手史料包括：illumos-gate GitHub 仓库（github.com/illumos/illumos-gate，包含从 OpenSolaris 分叉后的完整历史）、互联网档案馆存档的 Sun 文档和博客、FreeBSD 源码仓库中 src/sys/cddl/contrib/opensolaris/目录的 vendor import 记录

**史料**：互联网档案馆存档的 opensolaris.org（2005-2010 年各快照）；illumos-gate GitHub 仓库（github.com/illumos/illumos-gate，含 ON consolidation 历史）；FreeBSD src 仓库的 cddl 目录 vendor import 历史（svn.freebsd.org/base/vendor/opensolaris/）；LWN.net 和 Slashdot 的 OpenSolaris/ZFS 报道存档；genunix.org OpenSolaris 社区存档 ［A］

**史观**：形式主义膨胀：OpenSolaris 史料的系统性丢失是技术历史书写的警示——当一个开源项目由单一商业实体控制基础设施（代码仓库、邮件列表、文档站点、博客平台），该商业实体的战略转变（如 Oracle 收购 Sun 后转向封闭）可导致整个项目的历史记录在数年内几乎完全消失；ZFS 的历史能被重建，全靠社区分叉（illumos）、第三方存档（互联网档案馆）和 BSD 世界的独立导入

**辨析**：原文 50.5 节标题写 “2007 年 ZFS 开源至 OpenSolaris” 有事实错误——ZFS 于 2005 年 11 月开源，OpenSolaris 本身于 2005 年 6 月发布，2007 年并非 ZFS 开源年份；Pawel Dawidek 的 FreeBSD ZFS 移植 commit hash 经 freebsd.duckdb `commits` 表查询验证——FreeBSD src 仓库中 ZFS 主干导入 commit 为 `f0a75d274af375d15b97b830966b99a02b7db911`，作者 Pawel Jakub Dawidek（<pjd@FreeBSD.org>），author_date = committer_date = 2007-04-06T01:09:06Z，message_subject 为 “Please welcome ZFS - The last word in file systems.”；该 commit 同时是 `sys/cddl/contrib/opensolaris/` 目录下大量 ZFS 源文件（acl_common.c、acl_common.h 等）的首次引入 commit（commit_files 表 status =‘A’）；原 SVN 时代 r 编号在 2020 年 FreeBSD SVN-to-Git 迁移后已不再作为主引用，Git commit hash 为当前权威追溯依据；Dawidek 的移植工作最初在 FreeBSD Perforce 仓库的 //depot/projects/zfs/ 分支进行，2007-04-06 合入 FreeBSD-CURRENT 主干；0 信任原则提示：该 commit 经 2020 年 SVN-to-Git 迁移，hash 已重算，但 author 字段与 committer 字段一致（<pjd@FreeBSD.org>），且 commit_date 与 Dawidek BSDCan 2007 演讲时间吻合，可信度高

**要点**：

- 当事人 Adam Leventhal 自述其 UNIX 入门与职业轨迹：高中在 NeXT 机器上初识 UNIX，回家在旧 PowerPC 上装 NetBSD 却连 `ls` 都不会、误敲 `dir` 半小时；大学依赖 Solaris 2.6 至 8；2000 年实习于 Solaris 内核团队、2001 年全职，先做 MDB 与 ptools 等诊断工具，随后转入 DTrace；2006-2010 年与 Bryan Cantrill、Mike Shapiro 等在 Sun 内部创业式小组 Fishworks 研发存储设备（即后来的 Oracle ZFS Storage Appliance），恰逢闪存价格骤降与 iPhone 问世，做出 L2ARC 与 SLOG 的混合存储池；Oracle 收购 Sun 后转投 Delphix 历任工程师、经理至 CTO，专注 ZFS 性能。（BSD Now EP112，[744.32-996.62]，L1）
- ZFS 工程贡献的当事人复盘：第一项贡献是把 zlib 移植入内核实现 GZIP 压缩的周末黑客，代码沿用至今基本未改；继而在存储设备项目中把单校验 RAID 扩为双校验并再造三校验（RAID-Z2/Z3），自陈课堂抽象代数难以直接转化为可用的 RAID 数学；与 ZFS 创始工程师之一 Matt Ahrens 合作重写写节流与 I/O 调度器，称其“当然，那很显然——但只有在抛弃了其他更显而易见的答案之后，它才显得显然”（1124.00-1133.34）；send/receive 则源于 Ahrens 滞留中国、不满 rsync 的切肤之痛，Leventhal 明言欣赏这种由急迫痛点催生的创造叙事。（BSD Now EP112，[1013.62-1177.18]，L1）
- 可入册的 Apple 侧一手佐证：Leventhal 回忆 Apple 曾尝试将 ZFS 移植到 Mac OS X 并在某届 WWDC 现场发放演示 DVD，同一届 WWDC 发布了 Time Capsule 与 Time Machine；Sun 一方人员上前询问才发现 Time Machine 与 ZFS 无关，其实现被他称为“以最难看的方式对目录做硬链接”（1276.54-1280.76），而 zfs send/receive 本可优雅完成同样功能；主持人 Kris Moore 随即以 PC-BSD 的 Life Preserver（异地复制加本地快照滑块）作对照。此段为 Apple ZFS 移植夭折史的当事人旁证。（BSD Now EP112，[1242.18-1288.44]，L1）
- George Wilson 自述在 Sun 时期于 ZFS 早期 alpha 阶段即开始使用，2005 年开源后担任 ZFS 集成进 Solaris 10 的技术负责人，随后全职加入 ZFS 开发团队。（BSD Now EP14，[609.0-692.3]，L1）[订正：原 [611.1-677.1]，2026-09-30 SenseAudio 重转核对]
- 他长期以个人兴趣从事存储池恢复，累计完成百余次 pool recovery，以验证 ZFS 不会向社区引入异常。（BSD Now EP14，[684.2-707.1]，L1）
- 他参与的功能包括设备重分配、LUN 自动扩容、设备移除框架、与 Jeff Bonwick 合作的 dedup、ZFS 引导，以及 Delphix 时期的单副本 ARC 与 NoWrite。（BSD Now EP14，[720.4-895.0]，L1）
- Oracle 闭源 ZFS 后，他与 Matt Ahrens 在 Delphix 推动 OpenZFS，2013 年正式宣布，旨在让 FreeBSD、Linux、Illumos、macOS 等平台共享代码、避免重复劳动并统一命令行与管理模型。（BSD Now EP14，[1083.0-1290.6]，L1）[订正：原 [1078.7-1308.8]，2026-09-30 SenseAudio 重转核对]
- 问答部分解释 ZFS 的 vdev 组织与 RAID-Z 性能权衡，说明多个小 vdev 或镜像组通常快于单一大 vdev，但会付出更多冗余成本。（BSD Now EP14，[5225.1-5305.2]，L2）

**史料**：

- 该期提示的一手与近一手材料：Leventhal 本人口述（Sun 内部 DTrace 立项、Fishworks、Delphix）；QNX 官方第三方版权声明 PDF（数百页，丰田 Highlander 车机即 QNX，其中含 OpenCrypto xforms.c 许可文本、NetBSD Foundation 与 NASA Ames 的版权转让、TrustedBSD、OpenSSH、tcpdump 许可等条目）；Chad Dougherty 发往 openbsd-misc 的车机软件信息屏帖；Theo de Raadt 的 pledge(2) 说明文章及全树铺开、征集快照 dmesg 反馈的社区动员；波兰站 Leonardo Taccari 的 NetBSD 7.0 访谈（附英译）；Brian Kernighan 谈 C 语言演化的访谈视频；OpenZFS 开发者峰会议程（Jeff Bonwick 讲 ZFS 诞生史、George Wilson 讲压缩 ARC、Nexenta 讲持久 L2ARC、OVH 讲基于 ZFS 的在线迁移等）；听众整理的 EuroBSDCon 2015 视频时间戳索引。 [存疑脚注] 以上条目名与人名经 ASR 失真（如 Theo Duratt、Christos Zalos），引用前须回查 QNX 版权 PDF、openbsd-misc 原帖与峰会日程原件（BSD Now EP112，[350.78-549.92]，L2）

**史观**：

- 总纲5 没有必然性，只有偶然性：DTrace 的诞生在当事人复盘中处处是偶然而非必然：Cantrill 向论文导师提出改写内核文本作追踪的设想，得到的回答是“我相信如果这可行，早就有人做过了”（1575.18-1580.06）；多年间“DTrace 将解决一切问题、DTrace 知晓一切探针”只是内核组内部“传奇蒸汽件”（1634.54-1649.40）；而 Leventhal 的加入仅因路过办公室时凭 SPARC 架构的一个怪癖想到用户态追踪方案，换来一句“去做吧”。技术史由具体的人在偶然机缘下的日常劳动推进，先于任何总体规划。（BSD Now EP112，[1538.56-1691.96]，L1）
- 总纲13 法律与道德是利益分配：Leventhal 对开源的论证本质是利益结构分析而非道德宣示：开源的价值在于软件不归属某一家公司，公司消失或“变坏”时用户仍有退路；他引 Stephen O'Grady《The Software Paradox》说明软件总利润上升而单一专有软件价值下降，并将开源概括为社区参与、招聘与入市路径；其闭源反事实尤为锋利——“如果 ZFS 或 DTrace 是闭源专有的，它们只会存在于某个垂死的、越来越少人关心的操作系统里”（2272.68-2287.40），即便免费发放二进制也只会加速社区重写兼容实现。许可证与社区规则在此显现为利益分配机制。（BSD Now EP112，[2149.92-2327.12]，L1）
- 总纲4 分离聚合是永恒规律：OpenZFS 的成立以跨平台合作为目标，体现 ZFS 在封闭之后于多平台社区间重新聚合。（BSD Now EP14，[1078.7-1191.8]，L1）
- 总纲10 动手者创造历史：George Wilson 以恢复他人存储池为业余实践，将工程验证落实于具体动手。（BSD Now EP14，[684.2-707.1]，L1）
