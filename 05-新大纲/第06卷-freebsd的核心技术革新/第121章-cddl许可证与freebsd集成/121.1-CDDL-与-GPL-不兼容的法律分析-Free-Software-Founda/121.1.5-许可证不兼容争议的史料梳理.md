# 121.1.5 许可证不兼容争议的史料梳理

**要点**：CDDL 与 GPL 不兼容争议从 2005 年 CDDL 发布持续至今（2025 年），核心事件时间线为：2004 年 12 月 CDDL 提交 OSI；2005 年 1 月 OSI 批准 CDDL；2005 年 6 月 OpenSolaris 发布；2005 年 11 月 ZFS 源码发布；2006 年 FSF 在许可证列表中标注 CDDL 为 GPL 不兼容；2007-2008 年 Pawel Dawidek 将 ZFS 移植到 FreeBSD 并随 FreeBSD 7.0 发布（2008 年 2 月）；2008 年 Brian Behlendorf 在 LLNL 启动 ZFS On Linux 项目；2010 年 Oracle 收购 Sun；2013 年 OpenZFS 项目成立；2016 年 2 月 Ubuntu 16.04 决定默认包含 ZFS 引发大规模法律争议；2020 年 1 月林纳斯·托瓦兹在 RealWorldTech 论坛评论 ZFS；2020 年 11 月 OpenZFS 2.0 发布，统一 ZoL 与 FreeBSD ZFS 代码库；截至 2025 年，CDDL-GPL 兼容性仍无法院判决，Linux 主线内核仍未包含 ZFS

**史料**：OSI 许可证审批档案（2004-2005）；FSF 许可证列表存档（web.archive.org 2006-2025）；FreeBSD 7.0 Release Notes（2008-02-27）；LWN.net ZFS 相关报道时间线（lwn.net/search?query=ZFS）；Ubuntu Technical Board 2016 年会议记录；OpenZFS 2.0 Release Notes（2020-11-30） ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：长达 20 年的 CDDL-GPL 争议没有产生任何法院判例，这本身就是开源许可证执行的一个重要特征——社区通过技术架构（DKMS、独立代码库、分离分发）而非法律诉讼来解决许可证冲突，这种 “实践规避” 模式是开源生态特有的法律执行方式

**辨析**：需纠正一个常见误解：FreeBSD 之所以能集成 ZFS，并非因为 BSD 许可证 “比 GPL 更自由”，而是因为 BSD 许可证是 permissive（宽松许可）——它不对与之聚合分发的代码施加许可要求；GPL 是 copyleft 许可，要求衍生作品整体以 GPL 发布，因此与 CDDL 的文件级 copyleft 冲突；这不是 “自由程度” 的差异，而是 copyleft 边界设计的差异；林纳斯·托瓦兹 2020 年 1 月 6 日帖子的精确 URL 经搜索确认为 realworldtech.com/forum 的一个帖子评论，但该论坛 URL 结构动态变化，原始链接需通过 web.archive.org 查找 ［ 存疑脚注：此处事实待多源交叉验证 ］

**要点**：

- 学区技术主管 Jamie McParland 的自述完整呈现了一条自下而上的 BSD 生产化路径：接管时 IP 地址记录在法律便签上、无防火墙无 DHCP，以捐赠硬件架设 OpenBSD 防火墙起步；因 rsync 全树遍历令备份耗时二十四小时而转向块级复制，先试用 Nexenta 但 K-12 学区无力承担其授权费，对比原生 FreeBSD 与 NetBSD 后落地 FreeNAS；最终形成七台 FreeNAS 服务器、逾 150 块硬盘、每 15 分钟快照复制加异地第三副本的体系，并以“如果只有一份备份，就等于没有备份”（3802.92-3812.72）作为运维信条（BSD Now EP131，[2757.82-2832.20]，L1）
- 将 1989/1990 年的模糊测试研究与 2016 年的讨论并置可见一条方法论延续线：当年以随机字符流击溃约四分之一实用工具、甚至在 Sequent 上令 refer 拖垮整个操作系统的发现，至 2016 年仍由 afl 这类以源码覆盖率引导输入生成的模糊器持续产出修复，主持人并追问其中多少缺陷历经二十余年未愈——可靠性工程并未随系统演化线性改善，而是同一测试哲学在不同工具形态中的循环再现（BSD Now EP131，[4690.52-4740.40]，L2）
- 受访者系统口述了 BSD 起源的制度条件：1956 年反垄断同意令禁止 AT&T 经营计算机软件业，Unix 因此以近乎无偿方式连同源码授权给各大学用于教学研究，伯克利在此基础上持续增补形成 BSD；其后 BSDi 以 1-800-ITS-UNIX 电话号码销售 BSD 触怒持有 Unix 商标的 AT&T，USL 诉讼将 BSD 代码拖入数年法律泥潭，受访者并转引 Linus 的说法称若非 BSD 陷于诉讼，他大概不会另起 Linux。 [考据脚注] 受访者转引 Linus 语录未给出处，须回查原始访谈文本方可征引。（The Changelog EP574，[2411.00-2647.20]，L2）
- 关于诉讼结局与许可证分野，受访者称争议最终仅以约四个文件的重写了结、并无实质侵权成立，但诉讼已足以吓退用户并拖延 BSD 进程；他并回顾 BSD 许可证从含广告条款的多条款版演化为两句条款版——只须保留版权声明、不得冒称己作——并将其概括为 copyfree 与 GPL 的 copyleft 之别：后者要求修改回馈与随附源码，给嵌入式厂商带来持续合规负担，前者只须在手册附一页版权致谢，这正是大量 appliance 厂商选择 BSD 的制度原因。 [考据脚注] “仅四个文件被重写”与广告条款删除过程均系受访者单方陈述，应对照和解协议文本与 4.4BSD-Lite 发布记录核验。（The Changelog EP574，[480.00-795.15]，L2）
- 受访者解释 CDDL 与 GPL 的不兼容机理：CDDL 改编自 Mozilla 公共许可证，允许 CDDL 代码编入以任意许可发布的产品，但 GPL 要求并入代码同样以 GPL 授权且不可改许，形成单向不通；FreeBSD 借两句式许可证将 OpenZFS 全量源码置于 base 系统，由此获得引导器直读 ZFS 池、boot environment 快照回滚、top 直接呈现 ARC 用量等深度集成，并追述其前身为双分区镜像互备的 NanoBSD。 [考据脚注] 受访者自陈非法律人士，许可证解读应与 FSF 正式分析互证。（The Changelog EP574，[1690.00-1982.19]，L2）
- 关于 jails 的谱系，受访者称其概念源于 1999 年一家希望同时托管 PHP 3 与 PHP 4 的网站托管商出资定制、并约定项目完成后一年开源；FreeBSD 由此在 2000 年率先实现操作系统级容器，远早于 Linux 的 namespaces 方案，Sun 亦据此外推 Solaris Zones，而 Solaris 的借鉴反过来使 ZFS 具备向容器委托数据集的能力，形成跨系统循环。 [考据脚注] 委托方与开发者身份系受访者转述，应与 PHK 的原始叙述及 jails 提交记录互证。（The Changelog EP574，[2841.21-3015.00]，L2）

**史观**：

- 总纲9 经验优先：本期最具史学价值的内容并非任何宏大成就叙事，而是一线动手者的故障经验簿：暖故障切换哲学源于对自动故障转移反而制造事故的体认，数据丢失叙事不谈天灾而谈空调误关、承包商拉闸与误将设备加入存储池的自身失误，恢复策略则由恢复耗时实测倒逼出驾车异地取回 JBOD 直插导入的原始搬运方案——运维知识的每一层都内生于具体偶然事件的应对，动手者正是在处置这些不可预演的琐碎中创造了 BSD 的生产史（BSD Now EP131，[2946.08-3091.68]，L1）
- 总纲13 法律与道德是利益分配：围绕 Ubuntu ZFS 的三方法律话语呈现许可证作为利益分配机制的完整剖面：软件自由保护协会代表内核版权持有人主张合规控制权，软件自由法律中心服务于面临许可风险的使用者，Oracle 坐拥 ZFS 版权待价而沽乃至传出拒绝重授权报价，FreeBSD Foundation 则以自身两条款许可的互操作性置身事外并戏言律师是唯一赢家——各方修辞皆高举社区规范，实质关切却是同一份代码之上不同主体间的产权与话语权分配（BSD Now EP131，[1826.3-2132.9]，L2）[订正：原 [1831.74-2106.50]，2026-09-30 SenseAudio 重转核对]
- 总纲3 不存在进步，只有权力再分配：受访者以亲历者身份描述 FreeBSD 治理：每两年由拥有仓库写权限的提交者选举九人组成 core team，其职能是协调方向、仲裁争论与授予写权限，而非自上而下规定路线，他本人曾任两届；以定期改选的委员会替代单一个人权威，使项目权力以制度化节奏反复再分配，并降低对单个个体倦怠或离场的依赖。（The Changelog EP574，[3971.06-4040.29]，L1）
- 总纲5 没有必然性，只有偶然性：受访者提醒，世纪初 BSD 系统管理员的“硬核”光环与 Linux 的“玩具”标签是可反转的历史建构：当年 BSD 文档反而更完善、托管业务首选 BSD，其后 Linux 经 IBM 数十亿美元投入与对 Red Hat 的收购而成熟，两阵营声望结构在二十年间整体倒置；这一位序变动由诉讼、资本与生态事件等偶然条件叠加而成，并非技术优劣的必然。他另以“Unix 不阻止你做蠢事，因为那也会阻止你做聪明事”概括无护栏设计的代价。（The Changelog EP574，[4680.24]，L2）

**辨析**：

- 负载均值语义分歧的考据存在明确证据边界：FreeBSD 仅计可运行进程、NetBSD 计入全部短于一秒的睡眠进程、OpenBSD 似仅计高优先级 IO 等待的结论均出自 Siebenmann 单篇文章及其源码阅读，作者自承未遍历 OpenBSD CVS 日志、illumos 实现因过于复杂未予解析、macOS 完全未考察，且其结论与 2009 年知情的 OpenBSD 开发者说法相抵——在对照各内核现行源码复核之前，该分歧图谱只能视为单一来源的合理推断 [存疑脚注] 各系统实现口径仅见 Siebenmann 一文，FreeBSD 2.0 尚计 IO 等待、此后分叉时点不明，DragonFly 行为完全未考，须逐内核复核源码方可引为定论（BSD Now EP131，[1484.3-1606.0]，L4）[订正：原 [1508.08-1602.34]，2026-09-30 SenseAudio 重转核对]
- 主持人转述曾有人向 Oracle 出价至少一亿美元请求将 ZFS 以 GPLv2 兼容许可重授权而遭拒，并据此推断重授权概率趋近于零——此说被明确标注为非官方听闻，无任何公开文本可稽，既无法证实出价方与金额，也无法证实 Oracle 的回应，仅可作为背景传闻存档，不得进入正式叙事的证据链 [存疑脚注] 纯属主持人转述的匿名传闻，自称非官方听闻，无公开来源可验证（BSD Now EP131，[1800.0-1826.1]，L5）[订正：原 [1808.60-1825.88]，2026-09-30 SenseAudio 重转核对]
- 受访者给出的最有分量的自我批评是把 FreeBSD 比作乐高积木：构件齐备但缺最后 10% 的成品化——jails 自 2000 年即存在，却始终没有 Docker 式拉取即用的镜像仓库；他辨析其中兼有安全考量（永不更新的镜像存在风险）与许可优势（appliance 厂商借此规避 GPL 合规），这也解释了 BSD 生态以 appliance 形态繁荣的格局，但对该批评是否随容器生态演进而失效未作判断。（The Changelog EP574，[4197.15-4448.05]，L2）
