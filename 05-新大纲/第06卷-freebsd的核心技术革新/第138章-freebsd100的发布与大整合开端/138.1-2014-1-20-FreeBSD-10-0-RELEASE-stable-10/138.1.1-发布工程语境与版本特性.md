# 138.1.1 发布工程语境与版本特性

**要点**：FreeBSD 10.0-RELEASE 于 2014 年 1 月 20 日由 Release Engineering Team 正式发布（release/10.0.0 tagger_date = 2014-01-16T18:43:50Z，tagger = Glen Barber（格伦·巴伯），公告晚于 tag 4 天），是 stable/10 分支的首个版本，Release Engineer 为 Glen Barber（gjb@），Release Engineering Lead 为 Ken Smith（kensmith@）。10.0 支持 amd64、i386、ia64、powerpc、powerpc64、sparc64 六种架构。这是 FreeBSD 历史上基本系统变动最大的版本之一：Clang 成为 i386/amd64/arm 默认编译器（参见相关章节），**bhyve(8)** 虚拟机监控器正式纳入 base（首入过程参见相关章节），**pkg(8)** 成为默认软件包管理工具（base 内置 **pkg(7)** 引导工具负责首装），sysinstall 被 bsdinstall 完全替换，BIND 从 base 移除，GCC 不再默认安装于 Clang 默认架构，**make(1)** 替换为来自 NetBSD 的 **bmake(1)**，Unbound 作为本地缓存 DNS 解析器导入。支持生命周期原定于 2015 年 1 月 31 日结束。主要赞助企业包括 The FreeBSD Foundation、Yahoo!、NetApp、Internet Systems Consortium、iXsystems、Juniper Networks、NLNet 等。

**史观**：总纲第 17 条——证明世界先于解释和改造世界：10.0 是 FreeBSD 工程史上 “基础设施集中换代” 的典型版本，编译器、软件包管理器、安装器、DNS、构建工具五大基础组件同时更替，这种 “大爆炸” 式升级在 BSD 历史上较为罕见，通常 FreeBSD 采取渐进式替换策略。集中换代的代价是升级风险显著上升，收益是一次性扫清多年积累的技术债务。

**辨析**：原文件与部分中文资料误称 10.0 默认 MTA 为 dma（DragonFly Mail Agent）——经 10.0 Announcement、10.0 Release Notes 与 10.1 Announcement（明确记录 “Sendmail has been updated to 8.14.9”）交叉验证，10.0 与 10.1 中 **sendmail(8)** 仍存在于 base 且为默认 MTA；**dma(8)** 作为 DragonFly BSD 项目开发的轻量级 MTA，在 FreeBSD 10.x 全系列中既不在 base 中也非默认配置，其成为 FreeBSD 默认 MTA 发生在 FreeBSD 14.0（2023 年 11 月）；原文件称 “USB4BSD 完成”——USB stack 重写（USB4BSD 项目，由 Hans Petter Selasky 主导）实际在 FreeBSD 8/9 时期已基本完成，10.0 是进一步完善而非首次完成；原文件称 “10.0 根目录可 ZFS（ZFS boot 在 9.0 已支持但 10.0 完善）”——9.0 确实已支持 ZFS 引导，但 **bsdinstall(8)** 中的 Root-on-ZFS 自动安装菜单在 10.0 才首次加入（r256361），这是关键区别。Clang 版本经 Release Notes（r251662）核实为 3.3，而非部分资料所称 3.4；经 freebsd.duckdb tags 表验证，release/10.0.0 tag 的 tagger_date 为 2014-01-16T18:43:50Z（tagger: Glen Barber），公告日期 2014-01-20 晚于 tagger_date 4 天，属 FreeBSD 发布工程正常流程（tag 创建后等待镜像同步与公告准备）；[考据完成：2026-08-15 复核查] 邮件列表库验证通过：freebsd-announce 公告“FreeBSD 10.0-RELEASE Now Available”（Glen Barber，2014-01-20，Message-ID: <20140120162953.GA7750@glenbarber.us>），公告要点含“GCC is no longer installed by default”，与 10.0 发布日及 GCC 不再默认安装一致
