# 138.2.4 bhyve、ARM 与网络改进

**要点**：10.1 中 **bhyve(4)** 改进包括：i386 客户机支持（r267399，10.0 仅支持 amd64 客户机）；ZFS 文件系统引导支持（r268932）；XSAVE 虚拟化支持允许客户机使用 AVX 等扩展指令集（r267427）；ACPI S5 软关机支持（r261090）；virtio 随机数驱动 **virtio_random(4)** 加入（r268933）；virtio API 从 32 位扩展到 64 位；post-mortem 调试支持。ARM 架构在 10.1 中大幅改进：armv6 成为正式支持架构（加入发布镜像）；SMP 默认启用在多核 ARM 平台；硬件浮点支持默认启用；C++ 异常处理与 GCC 配合修复；新增对 Raspberry Pi、BeagleBone、PandaBoard、Wandboard、Chromebook（Exynos 5250）、Radxa 等平台的支持；Raspberry Pi I2C 驱动加入。网络方面：UDP-Lite（RFC 3828）支持加入；iSCSI initiator 支持重定向处理与性能优化（FreeBSD Foundation 赞助）；新增 Atheros 11n 无线驱动改进；**cxgbe(4)** Chelsio T5 40G 网卡 netmap 支持；Intel XL710 网卡 **ixl(4)** 驱动导入。

**史料**：FreeBSD 10.1-RELEASE Release Notes（Virtualization support、ARM support、Network Interface Support、Network Protocols 各章节）、svn commit r267399（bhyve i386 guest）、r268932（bhyve ZFS boot）、r267427（XSAVE virtualization）。 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：bhyve 在 10.x 时期的快速演进（单 vCPU→SMP、无 UEFI→UEFI、仅 amd64 客户机 →i386/Windows 客户机）体现了 FreeBSD 在虚拟化领域的独立技术路线——不依赖 KVM/Xen 而是自主开发 Type-2 hypervisor，这与 Linux 生态形成鲜明对比。ARM 支持的进展则是 FreeBSD 应对 ARM 服务器与嵌入式市场崛起的战略布局。

**辨析**：bhyve 在 10.1 仍不支持 SMP 客户机（多 vCPU）——SMP 客户机支持在 10.3 才加入（10.1 中 bhyve 客户机仅限单 vCPU）；bhyve 在 10.1 仍无 UEFI 固件支持——uefi-edk2-bhyve 端口在 10.x 后期才成熟。

**要点**：

- Justin Cormack 阐明 rump kernel 之构造：自 NetBSD 内核剥离广义驱动（自文件系统驱动至网络栈），覆以最小虚拟化层，进程与内存管理等困难部分转借宿主环境，叠加 libc 后即得近乎完整之 POSIX 用户态，成为可运行真实应用的轻量用户态虚拟机，令 NetBSD 代码几乎可运行于任何环境；其核心用例为驱动开发与测试——用户态 IPv6 协议栈可原样移植供缺乏协议栈之系统直接复用，用户态 PCI 层使网卡驱动可在用户态编写、崩溃后重置设备即可续跑，持续集成测试每小时于多平台运行，Minix 社区亦有意借用 NetBSD 驱动以充实其微内核框架。（BSD Now EP64，[2724.34-2984.22]，L1）
- Cormack 自述个人路径：早年在 MIT 初遇 UNIX 与 X 窗口终端，此后任系统管理员涉猎 Solaris 与 Linux，因 FOSDEM 年会接触 NetBSD 并对其测试文化产生兴趣；适逢语言可直接运行于 hypervisor 之设想（Erlang on Zen、Mirage 等先例），遂以 rump kernel 对接 Xen hypercall 驱动自带之迷你操作系统环境，交叉编译 NetBSD libc 并将系统调用陷阱替换为 rump kernel 调用，使 Lua 得以直接运行于 Xen 且通过 NetBSD 测试套件；此工作促成其于 2014 年初成为 NetBSD 开发者。（BSD Now EP64，[2518.82-2626.96]，L1）
- FreeBSD 10.1 于 2014 年 11 月 14 日发布，距 10.0 约十个月，升级路径刻意保持平滑；主要特性包括新 VT 控制台（支持 Intel 与 AMD 显卡加速显示）、amd64 平台 UEFI 引导（暂仅限 UFS）、GELI 口令缓存使多盘加密 ZFS 阵列仅需输入一次口令、ARMv6 SMP 支持、bhyve 大量更新（含根 ZFS 引导与 32 位 FreeBSD 客户机）、Geom 层直接 IO 分发与 zvol 新增 volmode 属性等，属 10.x 稳定分支首个点版本。（BSD Now EP64，[740.02-960.88]，L2）
- FreeBSD Foundation 获其史上最大单笔捐款——WhatsApp 首席执行官捐赠一百万美元；其社交平台自述称少年时为贫困移民学生，课余自学 FreeBSD，由此进入 Yahoo 专职 FreeBSD 工作，后创立 WhatsApp 仍持续使用 FreeBSD，故以捐款回馈；主持人进而说明基金会之 501(c)(3) 地位受 IRS 公众支持测试约束，若资金过度集中于少数企业将沦为行业团体而丧失慈善资格，故基金会更看重经常性小额捐赠以保证预算可预期。（BSD Now EP64，[3342.66-3509.48]，L2）

**史观**：

- 总纲21 革命与改革是历史方法论的分歧：Theo de Raadt 于 arc4random 演讲中宣称：“我们大概是一群相当古怪的人，专为了把软件做得更好而工作……我们的一大力量来自能够把向后兼容整个抛出窗外”（2198.44-2233.16），即一旦认定某物不对便设计替代并推入下一阶段，纵使破坏他人既有环境亦在所不惜；与之对照，同期 FreeBSD 10.1 之升级路径刻意平滑，两种发行版分别体现革命式重设计与改革式渐进之方法论分歧。（BSD Now EP64，[2198.44-2233.16]，L2）
- 总纲15 文化即形式主义：arc4random 之名实分离为考察技术文化之约定性提供标本：其实现早已由 RC4 更替为更强算法，然函数名仍沿用旧称，盖因更名无实益而所有既有程序不待修改即自动获得新算法；命名作为历史约定脱离所指而继续维系兼容，恰说明技术系统中的名称是层累的约定而非当下现实之描述。（BSD Now EP64，[2117.52-2168.52]，L2）

**辨析**：

- 关于 FreeBSD 中 root 默认 shell 为 csh 而普通用户默认为 sh 之惯例，主持人自认无从确证，只能求诸当年在场者；其推测解释为 Bill Joy 于 1970 年代编写 csh 且自用之，BSD 创始遂沿用而无人愿改，变更将引发重大 bike-shed 争议；此例显示技术惯例之延续未必出于技术论证，而系创始人偏好与变更成本之合力。 [存疑脚注] root 默认 shell 源于 Bill Joy 偏好一说系主持人推测而非当事人一手证据，本条仅作线索性存疑记录。（BSD Now EP64，[5897.30-5948.88]，L4）
