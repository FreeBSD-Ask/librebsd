# 127.1.2 Watson 团队的设计过程

**要点**：Capsicum 设计始于 2008 年前后，Watson 在 FreeBSD TrustedBSD MAC 框架的多年工作经验使他认识到：基于强制访问控制（MAC）标签的安全模型配置复杂、容易出错，且与 POSIX API 的全局命名空间访问模式存在根本冲突；设计团队（剑桥的 Watson、Anderson 与 Google 的 Laurie、Kennaway）确定了“混合能力模型（hybrid capability system）”路线——不推翻传统 UNIX 权限模型，而是允许进程在需要时自愿进入能力模式（capability mode），在该模式下丧失所有 ambient authority（环境权限），仅能通过已持有的能力文件描述符访问资源；Pawel Jakub Dawidek 在 FreeBSD 基金会与 Google 开源计划办公室联合资助下承担了 Capsicum 从研究原型到产品级代码的后续工程化工作

**史观**：终结与延续〔订正注：原“总纲第 25 条”伪标签去条号，权威总纲 25 为“逻辑是形式主义”〕：Capsicum 的设计过程体现了安全研究从“外围加固”到“内核重构”的转向——MAC 框架（TrustedBSD/SELinux）是在 UNIX 权限模型之外附加安全策略层，而 Capsicum 选择在进程自愿前提下替换权限模型核心；这一设计决策既是 TrustedBSD 项目经验的延续（Watson 是 TrustedBSD MAC 框架的作者），也是对该框架局限性的反思

**辨析**：Capsicum 与 Google 的合作关系需精确描述——Google 是 Capsicum 研究的资助方（Ben Laurie 为 Google 员工，参与设计），Chromium 浏览器是 Capsicum 最早的目标应用之一；但 Google 从未将 Capsicum 作为 Chrome 沙箱的主方案——Chrome 在 Linux 上最终选择 seccomp-bpf（参见 081.4 节），在 FreeBSD 上的 Chromium Capsicum 沙箱长期维护状态不稳定；“剑桥大学独立设计”的说法也不准确——Capsicum 从一开始就是学术界（Cambridge）与工业界（Google）的合作产物
