# 130.5.1 引导链整合的工程挑战

**要点**：bhyve 初始版本仅支持 **bhyveload(8)** 引导 FreeBSD 客户机，通过直接加载 FreeBSD 内核到客户机内存来启动；对于 Linux 等其他客户机操作系统，需要专门的引导加载程序——grub2-bhyve 是 Peter Grehan（彼得·格雷汉） 维护的 GRUB 2 移植版本，专门用于在 bhyve 中引导 Linux、OpenBSD、NetBSD 等非 FreeBSD 客户机；UEFI 支持通过 uefi-edk2-bhyve 包（ports 中为 `sysutils/uefi-edk2-bhyve`）提供，该包提供基于 TianoCore EDK II 的 UEFI 固件镜像（BHYVE_CODE.fd/BHYVE_VARS.fd）；UEFI 支持是运行 Windows 客户机的必要条件，同时也支持 UEFI-only 的 Linux 发行版与其他操作系统

**史料**：**bhyveload(8)** 手册页；ports/sysutils/grub2-bhyve/ 与 ports/sysutils/uefi-edk2-bhyve/ 目录；FreeBSD Wiki bhyve/Windows 页面；Petersson L. Porting UEFI to bhyve [C]//BSDCan 2015. 2015

**史观**：总纲第 2 条——实践先于理论：引导链整合并非预先规划的架构组件，而是源于 “运行非 FreeBSD 客户机” 这一实际部署需求——bhyveload 解决 FreeBSD 引导、grub2-bhyve 解决多系统引导、UEFI 固件解决 Windows 引导，三者都是按需添加、逐步演进的，而非一开始就设计了统一的引导框架

**辨析**：bhyve UEFI 固件与 Clover/OpenCore 的关系需要澄清——uefi-edk2-bhyve 是标准的 TianoCore EDK II 固件移植，用于运行标准 UEFI 操作系统（如 Windows、Linux）；Clover 与 OpenCore 是 Hackintosh 社区的引导器，用于在非 Apple 硬件上启动 macOS，并非 bhyve 官方 UEFI 固件的组成部分；bhyve 运行 macOS 客户机的支持是社区非官方项目 ［ 存疑脚注：此处事实待多源交叉验证 ］；grub2-bhyve 并非完整的 GRUB 2 移植，而是经过修改以适配 bhyve 虚拟硬件环境的专用引导器
