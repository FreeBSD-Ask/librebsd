# 145.6.4 第三方软件变更的史料辨析

**要点**：12.0 是 FreeBSD 历史上“许可证纯洁化”进入收官阶段的标志性版本——GCC 4.2.1 从 x86 默认移除（13.0 完全移除）、LLD 成为 amd64 默认链接器（13.0 所有架构）、GDB 从 base 移除、OpenSSL 升级至 1.1.1。这些变更的共同主题是“用 BSD 许可/兼容许可的现代实现替换 GPL 许可的旧实现”。12.0 的第三方软件变更体现了“引入-稳定-移除”三阶段模式的第三阶段：10.0 引入 Clang/LLD/LLDB/Unbound，11.x 稳定使用，12.0 开始移除旧的 GPL 组件（GCC/GNU ld/GDB）。

**史料**：FreeBSD 10.x/11.x/12.x Release Notes 对比［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 〔L3 官方文档〕

**史观**：总纲第 24 条——许可证：12.0 的 GCC/ld/GDB 移除是 FreeBSD 对 GPL 许可证的“最终清算”——自 2007 年 GPLv3 发布以来，FreeBSD 项目持续十余年将 base 中的 GPL 组件逐一替换为 BSD 许可/兼容许可的替代品，12.0 是这一工程的收官阶段；终结与延续：GCC 4.2.1（2007 年发布）在 FreeBSD base 中存活了 14 年，它的移除既是 GPLv2 时代在 FreeBSD 中的终结，也是 LLVM 工具链时代的延续

**辨析**：12.0 的 GCC 移除是“部分移除”（仅 x86 默认不安装），13.0 才是“完全移除”（所有架构）；12.0 的 LLD 默认化是“部分默认化”（仅 amd64/arm64），13.0 才是“完全默认化”（所有架构）；这些“部分 → 完全”的渐进模式是 FreeBSD 工程管理的安全策略——避免在单一版本中做出不可逆的变更
