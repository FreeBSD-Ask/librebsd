# 125.4.4 Mac OS X 集成事件史料考证

**要点**：macOS DTrace 集成事件的一手史料包括：Apple 开源代码 opensource.apple.com/source/dtrace/（存档于互联网档案馆）；Leventhal 在 dtrace.org/blogs/ahl/ 的两篇博客（2008-01-18、2008-06-07）；Mac OS X 10.5 Leopard 发布新闻稿和技术文档；MacTech 2007 年 11 月《Exploring Leopard with DTrace》；后续 macOS 版本 DTrace 变更记录（10.5.3 修复、10.11 SIP 限制）；Apple Instruments 应用的版本历史（Instruments 后来扩展为 Xcode 的核心性能分析工具，功能远超 DTrace 封装）

**史料**：互联网档案馆存档的 opensource.apple.com/source/dtrace/（存档日期 2022-06-05）；dtrace.org/blogs/ahl/ Leventhal 博客完整存档；Apple Developer Documentation（Instruments User Guide）；MacTech 杂志 2007 年 11 月刊 ［A］

**史观**：形式主义膨胀：macOS DTrace 事件的史料保存相对完整，得益于 Leventhal 在 dtrace.org 的独立博客记录和 Apple 开源代码仓库；但 Apple 官方从未就 P_LNOATTACH 设计决策发表详细技术说明，这种“只修复 bug 不解释设计”的做法在商业公司中常见，给技术史研究留下了盲点

**辨析**：原文标题称“2008 年 Mac OS X 集成 DTrace”系日期错误——Mac OS X 10.5 Leopard 于 2007 年 10 月 26 日发布，DTrace 争议始于 2008 年 1 月（Leventhal 博客发表），修复于 2008 年 6 月（10.5.3），应修正为“2007 年 Mac OS X 集成 DTrace”；原文称“Apple 修改了部分探针以隐藏 iTunes 进程信息”部分准确但不完整——问题核心是 P_LNOATTACH 机制及其 bug（无关探针失败），而非仅针对 iTunes 的特定修改

**文献**：Apple Inc. opensource.apple.com/source/dtrace/ (archived); Leventhal, A. H. dtrace.org/blogs/ahl/ (2008 posts); Apple Inc. Mac OS X 10.5 Technical Specifications (2007-10-26) ［C］
