# 125.3.2 与 ZFS 共享 CDDL 的法律后果

**要点**：DTrace 与 ZFS 共享 CDDL 许可证的直接后果是二者在 FreeBSD 中采用完全相同的导入模式：src/sys/cddl/contrib/opensolaris/ 存放未修改的 OpenSolaris 源码（vendor branch），src/sys/cddl/compat/opensolaris/ 提供 Solaris 内核 API 兼容层（solaris.ko 模块）；这种分离设计允许 FreeBSD 以最小的本地改动同步上游 DTrace/ZFS 更新，同时保持许可证边界清晰——contrib 下为 CDDL，compat 和 src 其他部分为 BSD；DTrace 在 FreeBSD 中的法律地位与 ZFS 相同：作为独立内核模块加载，不构成 BSD 内核的衍生作品（因 CDDL §3.5 允许聚合分发）

**史料**：FreeBSD src/sys/cddl/contrib/opensolaris/uts/common/dtrace/ 目录（DTrace 核心源码）；FreeBSD src/sys/cddl/compat/opensolaris/ 目录（Solaris API 兼容层）；FreeBSD 基金会关于 CDDL 代码兼容性的声明（与 ZFS 声明一致）；FreeBSD src/COPYRIGHT 文件中关于 cddl/ 目录的许可证说明；**freebsd.duckdb** `commits` 表代码级证据——commit `d5768a7a5b2a48b4092dacd73cfbdbd396a9f81e`（2006-11-21，author = John Birrell）的 commit message 原文记录了 CDDL 约束对 FreeBSD DTrace 集成路径的直接工程影响："Remove the KDTRACE option because I can't implement it the way I intended due to licensing restrictions. I had intended that it would be defaulted on, with opt-out possible for companies that don't accept the CDDL. The FreeBSD GENERIC kernel has to be entirely BSD licensed, so the only alternative would have been to make KDTRACE an opt-in option. That isn't a design I favour."；该 commit 证明 CDDL 文件级 copyleft 与 FreeBSD“GENERIC 内核仅含 BSD 许可代码”政策的直接冲突，使 DTrace 无法像 BSD 原生代码那样默认编译进 GENERIC 内核，只能以可加载内核模块形式分发 ［A］

**史观**：终结与延续：DTrace 与 ZFS 共享 CDDL 许可证这一事实，使 FreeBSD 在 2007-2009 年间同时获得了企业级文件系统和企业级动态追踪两大关键技术，这两大技术的引入是 FreeBSD 7.x/8.x 时代“企业级成熟”的重要标志

**辨析**：DTrace 在 FreeBSD 中的 compat 层比 ZFS 的 compat 层薄——DTrace 对 Solaris 特有 API 的依赖相对较少（主要依赖 cyclic、kmem、taskq 等基础内核原语），因此 FreeBSD DTrace 的兼容性较好，provider 支持较完整；但 pid provider（用户态任意函数追踪）的支持曾长期落后于 Solaris，这与 FreeBSD 链接器和运行时链接编辑器的差异有关；**CDDL 约束的代码级验证**——commit `d5768a7a5b2a48b4092dacd73cfbdbd396a9f81e`（2006-11-21）是 CDDL 法律约束直接影响 FreeBSD DTrace 工程路径的一手证据，Birrell 在 commit message 中明确陈述了三点：(1) 他原本计划将 KDTRACE 选项默认启用（opt-out 模式），但因 CDDL 约束无法实现；(2) FreeBSD GENERIC 内核必须全部为 BSD 许可代码，CDDL 代码不能进入 GENERIC；(3) 最终只能选择 opt-in 模式，但这不符合他的设计偏好；这一工程决策的代码留痕与 FreeBSD Foundation 公开声明的 CDDL-BSD 兼容性立场、CDDL §3.5 聚合分发条款三方交叉验证一致；0 信任原则提示：commit subject 是 Birrell 自述，但与 FreeBSD 项目长期维持的 GENERIC BSD-only 政策一致，采信度高
