# 125.3.3 CDDL 与 GPL 不兼容的效应辨析

**要点**：CDDL 与 GPLv2 不兼容的核心冲突与 ZFS 同源：CDDL §3.2 要求 CDDL 文件保持 CDDL 许可，GPLv2 §2(b) 要求衍生作品整体以 GPL 发布，二者互斥；这一不兼容性对 DTrace 的影响：Linux 主线内核无法直接包含 DTrace 代码；Oracle 于 2011 年 10 月宣布将 DTrace 移植到 Oracle Linux（作为独立内核模块分发，UEK R2 中技术预览），2012 年 12 月 12 日正式 GA（General Availability），采用 GPLv2 许可的模块封装层；dtrace4linux 项目（Paul Fox 等人维护，2008 年起）以独立内核模块方式提供 DTrace，标注内核为“tainted”；Linux 社区长期无法获得原生 DTrace 支持，这为 eBPF 的诞生和发展提供了生态空间

**史料**：CDDL §3.2 原文；GPLv2 §2(b) 原文；Oracle Linux Blog 2012-12-12《Announcement: DTrace for Oracle Linux General Availability》（Zeynep Koch）；Wim Coekaerts 2011-10-09《Trying out dtrace》Oracle 博客；dtrace4linux 项目主页（github.com/dtrace4linux/linux）；LWN.net 2007-08-07《On DTrace envy》 ［C］

**史观**：许可证：CDDL-GPL 不兼容性对 Linux 追踪生态的影响深远——无法直接使用 DTrace 迫使 Linux 社区发展出独立的追踪技术路线：从早期的 SystemTap（Red Hat 主导，2005 年起）到最终的 eBPF（Alexei Starovoitov 2014 年并入内核）；许可证壁垒在阻碍代码流动的同时，也催生了技术创新——eBPF 最终发展为比 DTrace 更通用的内核可编程平台

**辨析**：Oracle 2017 年 8 月以 GPLv2+ 许可发布 DTrace Linux 内核代码的事件，并未改变 FreeBSD/macOS DTrace 的许可状态——FreeBSD 使用的是 illumos/OpenSolaris 分支的 CDDL 代码，非 Oracle 的 GPL 分支；“CDDL 与 GPL 不兼容导致 Linux 没有 DTrace 所以才有了 eBPF”这一叙事有一定道理但过于简化——eBPF 的前身 classic BPF（cBPF）自 1997 年起就在 Linux 中用于包过滤，Alexei Starovoitov 的扩展（eBPF）始于 2011-2013 年，最初用于网络过滤优化，后扩展为通用虚拟机，追踪只是其应用场景之一
