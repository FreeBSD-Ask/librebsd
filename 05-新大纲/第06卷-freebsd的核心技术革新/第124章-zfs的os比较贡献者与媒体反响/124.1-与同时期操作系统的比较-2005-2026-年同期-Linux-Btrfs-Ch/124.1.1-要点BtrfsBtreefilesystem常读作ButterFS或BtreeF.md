# 124.1.1 要点BtrfsBtreefilesystem常读作ButterFS或BtreeF

**要点**：Btrfs（B-tree file system，常读作“Butter FS”或“B-tree FS”）由 Chris Mason 于 2007 年在 Oracle 工作期间启动开发，设计目标是打造 Linux 原生的下一代 CoW 文件系统，提供与 ZFS 类似的功能（快照、校验、池化、RAID）；Btrfs 于 Linux 2.6.29（2009 年）合入主线内核，标记为 experimental；Btrfs 与 ZFS 的核心技术差异：（1）许可：Btrfs 采用 GPLv2（与 Linux 内核一致），可以直接进入 upstream；（2）设计：Btrfs 基于 B-tree 结构，ZFS 基于 Merkle 树 + 块指针；（3）成熟度：Btrfs 的 RAID 5/6 实现长期被标记为不稳定（存在 write hole 问题），直到 2020 年代仍有许多生产环境警告；（4）功能覆盖：Btrfs 缺少 ZFS 的一些企业级功能（如 send/recv 增量流虽然支持但不完整、无 ZIL/SLOG 分离等）；Red Hat 在 RHEL 中从 RHEL 6/7 开始将 Btrfs 列为 technology preview，但在 RHEL 8（2019 年）中移除了 Btrfs 支持，转而支持 Stratis（基于 XFS+LVM）

**史观**：总纲第 24 条——许可证：Btrfs 的诞生很大程度上是为了在 Linux 内核中“绕过”ZFS 的 CDDL 许可问题——Oracle 作为 ZFS 版权持有者，选择重新开发一个 GPL 许可的 CoW 文件系统，这本身就是 CDDL-GPL 不兼容如何塑造技术生态的最好例证

**辨析**：Btrfs 稳定性的争议：Btrfs 在单盘场景下已经相当稳定（被 openSUSE/SUSE 作为默认文件系统多年），但其多盘 RAID 功能的稳定性长期被质疑；这与 ZFS 在所有模式下（包括 RAID-Z）都以生产稳定著称形成对比；Btrfs 的 write hole 问题（RAID 5/6 模式下的原子性问题）直到 2023 年前后才通过新的日志机制部分解决
