# 135.9.1 DragonFly BSD 3.x 与 HAMMER 稳定化

**要点**：FreeBSD 9.x 同期（2012-2014）DragonFly BSD 发布 3.0-3.8 系列版本，Matthew Dillon（马修·狄龙） 持续推进 HAMMER 文件系统稳定化（HAMMER1 在 3.x 时期成为生产就绪，HAMMER2 开始设计）、per-CPU 数据结构优化、vkernel 改进；DragonFly 3.0 于 2012 年 3 月发布，与 FreeBSD 9.0 形成有趣对照——两者共享 UFS/FFS 遗产但在文件系统、SMP 架构上选择了截然不同的路径（DragonFly 坚持 HAMMER，FreeBSD 以 ZFS 为主）

**史料**：DragonFly BSD 3.0-3.8 Release Notes、Matthew Dillon kernel 提交日志、DragonFly BSD 邮件列表 ［A］

**史观**：技术路线分化：DragonFly 与 FreeBSD 的分叉（2003 年）在 9.x 时期已显现出截然不同的技术个性——DragonFly 走轻量、原创（HAMMER）、集群化路线，FreeBSD 走成熟、ZFS/企业级、通用服务器路线；这种分化证明了 fork 在开源生态中的创造性价值——不同技术愿景在独立分支中充分探索

**辨析**：DragonFly 与 FreeBSD 仍保持着代码互移植关系——9.x 时期的 BSD patch 即是从 DragonFly 反向移植到 FreeBSD（详见 79.15）；这种 “分叉不分手” 的模式是 BSD 生态的特色
