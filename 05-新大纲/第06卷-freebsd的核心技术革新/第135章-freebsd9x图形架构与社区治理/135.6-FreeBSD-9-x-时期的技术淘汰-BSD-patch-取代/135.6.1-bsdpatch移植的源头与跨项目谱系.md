# 135.6.1 BSD patch 移植的源头与跨项目谱系

**要点**：**patch(1)** 工具由 Larry Wall 开发原始实现，FSF 在此基础上增强为 GNU patch；FreeBSD 长期使用 GNU patch 2.1 早期版本（其中两个文件受 GPL 约束）；OpenBSD 从 patch 2.0 早期版本分叉并以 PD 或无限制许可证替换 GPL 文件，DragonFly BSD 在 OpenBSD 版本基础上进一步增强，NetBSD 采纳 DragonFly 版本；FreeBSD 由 Pedro F. Giffuni（pfg@）从 DragonFly 反向移植并回填 FreeBSD 原有增强；原始 **patch(1)** 由 Larry Wall 开发，FSF 在其基础上增强为 GNU patch，这是 BSD patch 跨项目谱系的完整脉络

**史料**：Pedro Giffuni 2013.1.29 18:42 freebsd-current 邮件列表 [CFT] WITH_BSD_PATCH 原文（含完整谱系叙述）、Andreas Kohn 2006.6.19 PR 99173 原始 bug 报告、pfg 2014.9.19 PR 99173 关闭评论 ［A］

**史观**：总纲第 22 条——开源运动：BSD patch 的跨项目谱系是 BSD 阵营内部 “代码共享-反向移植” 协作模式的典型样本——OpenBSD 起源 →DragonFly 增强 →NetBSD 采纳 →FreeBSD 反向移植，形成四项目循环的代码流，与 GPL 阵营 “中央仓库-下游分发” 模式形成对照

**辨析**：谱系叙述中须区分两个层次——技术源头是 Larry Wall 原始 **patch(1)**，许可证源头是 OpenBSD 替换 GPL 文件为 PD/无限制版本；DragonFly 的 “进一步增强” 具体内容须对照 DragonFly commit log 核实；pfg “反向移植 FreeBSD 原有增强” 表明 FreeBSD 版本与 DragonFly 版本并非简单复制关系，而是双向融合；Andreas Kohn 2006.6.19 提交的原始 PR 在 7 年后才由 pfg 完成，体现 BSD 工程的长期积累特性
