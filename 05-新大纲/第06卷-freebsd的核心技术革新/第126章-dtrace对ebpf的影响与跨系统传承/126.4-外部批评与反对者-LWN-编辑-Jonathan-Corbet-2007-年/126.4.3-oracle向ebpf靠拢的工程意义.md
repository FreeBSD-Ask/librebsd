# 126.4.3 Oracle 向 eBPF 靠拢的工程意义

**要点**：Oracle 在 2017-2019 年间的两个重要决策标志着 DTrace 技术路线的相对退潮：(1) 2017 年 8 月 Oracle 将 DTrace Linux 内核代码以 GPLv2+ 许可发布——这实质上是承认了 CDDL 路线在 Linux 上的失败，通过重新许可能够让 DTrace 代码更自由地进入 Linux 生态；(2) Oracle Linux 同时支持 DTrace 和 eBPF——Oracle UEK 内核持续集成 eBPF 功能；Cantrill 于 2010 年离开 Oracle，他是 DTrace 在 Sun 内部最强有力的支持者；Oracle 收购 Sun 后战略重心转向数据库、云服务和 Linux，Solaris 和 DTrace 不再是核心战略

**史料**：Mark J. Wielaard 2018-02-14 博客关于 Oracle GPL 许可 DTrace 的报道；Oracle Linux 博客 DTrace 和 eBPF 相关公告；Cantrill 2010-07-25《Good-bye, Sun》博客；Oracle UEK 内核发布说明 ［C］

**史观**：总纲第 25 条——终结与延续：Oracle 作为 DTrace 的“母公司”向 eBPF 靠拢，在工程话语权上标志着 DTrace 不再是可观测性领域的唯一或主导路线；但 DTrace 的技术遗产通过 eBPF 得到了延续——eBPF 验证器、探针模型、聚合思想都有 DTrace 的影子

**辨析**：Oracle 将 DTrace 代码以 GPLv2+ 发布并未使 DTrace 大规模进入 Linux 主线——因为此时 eBPF 已经成熟（2017-2018 年 eBPF 已广泛用于生产环境），DTrace Linux 移植的窗口期已过；这一时间点很重要——Oracle 可以更早（2010-2014 年间）选择 GPL 许可，但 Oracle 在 Sun 收购后忙于整合，战略方向摇摆，错过了可能改变 Linux 追踪生态的时间窗口
