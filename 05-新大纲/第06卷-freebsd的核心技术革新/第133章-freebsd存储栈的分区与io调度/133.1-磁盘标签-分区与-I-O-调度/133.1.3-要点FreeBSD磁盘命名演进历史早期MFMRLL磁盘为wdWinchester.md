# 133.1.3 要点FreeBSD磁盘命名演进历史早期MFMRLL磁盘为wdWinchester

**要点**：FreeBSD 磁盘命名演进历史：早期 MFM/RLL 磁盘为 wd?（Winchester Disk），SCSI 磁盘为 sd?；FreeBSD 3.x CAM 引入后 SCSI 磁盘改为 da?（Direct Access）；FreeBSD 5.x 时期 ATA 磁盘为 ad?（ATA Direct Access）；FreeBSD 9.0 ATA 接入 CAM 后改为 ada?（ATA Direct Access in CAM）；NVMe 为 nvd? 或 nda?；各种虚拟设备包括 md?（内存盘）、mirror/?（gmirror）、eli/?（geli）、label/?（glabel）、gpt/?（GPT 分区标签）等；设备命名稳定问题：传统设备名（ada0, da0 等）由磁盘探测顺序决定，插拔磁盘可能导致设备名变化，这是引入 glabel、GPT 标签的根本原因——通过标签或文件系统 UUID 引用设备可避免引导失败

**史料**：**ada(4)**, **da(4)**, **nda(4)** 手册页；FreeBSD 各版本 Release Notes 设备命名变化记录；Lucas 2018 书磁盘命名章节 ［A］；Tuffli C. Frankenstein’s Disk Drive [C]//BSDCan 2019. Ottawa, 2019（作者为 FreeBSD NVMe 驱动开发者，提出以 bhyve 模拟的虚拟 NVMe 设备 pci_nvme.c 加定制固件替代“错误模式注入”与 mock，测试 NVMe 驱动错误处理）

**史观**：总纲第 15 条——文化即形式主义：从 wd→sd→ad→da→ada→nvd/nda 的设备名变化，反映了存储技术演进和架构统一的过程，但这种名称变化给用户带来了迁移成本，也使得早期文档和教程过时；gpart + glabel 通过标签抽象解决了这个问题，这是形式化抽象在工程实践中降低历史耦合的案例

**辨析**：“FreeBSD 设备名混乱” 是一个常见批评——与 Linux sda/sdb 看似稳定的命名对比，FreeBSD 设备名确实随着架构整合变化过多次；但 Linux 从 hd?（IDE）到 sd?（libata 统一）也经历过类似变化，而且 Linux 的 sd? 命名同样依赖探测顺序，实际生产中也使用 UUID/LVM 标签引用设备而非 sd? 名称；两者只是走了不同的演进路径，最终都收敛到 “通过标签而非物理位置/顺序引用设备”
