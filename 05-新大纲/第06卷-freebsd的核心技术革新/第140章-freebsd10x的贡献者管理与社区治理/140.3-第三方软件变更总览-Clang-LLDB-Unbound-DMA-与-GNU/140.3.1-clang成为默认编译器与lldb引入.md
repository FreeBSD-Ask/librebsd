# 140.3.1 Clang 成为默认编译器与 LLDB 引入

**要点**：FreeBSD 10.0-RELEASE（2014 年 1 月 20 日）将 Clang/LLVM 3.3 设为 i386、amd64、arm 架构的默认系统编译器（GCC 仅保留给非 x86 架构），这是 FreeBSD 历史上最重要的编译器迁移。Clang 迁移的完整历史、许可证背景与工程考量参见相关章节；LLDB（LLVM Debugger）随 10.0 同时引入 base system，作为 GDB 的 BSD 许可替代品——GDB 因 GPL 许可证问题长期是 FreeBSD 许可证纯洁化工程的障碍，LLDB 提供了 BSD 许可的现代调试器，支持 amd64/i386 架构，10.0 中 LLDB 为初始版本，功能完整度不如 GDB 但满足基本调试需求。此后 LLDB 在 11.x/12.x/13.x 持续改进，FreeBSD 12.0 将 GDB 从 base 移除（开发者在 12.0 Release Notes 中确认），LLDB 成为 base 中唯一调试器。

**史观**：许可证：Clang/LLDB 替换 GCC/GDB 的核心动力是 GPLv3 许可证担忧——GCC 4.2.1 是最后一个 GPLv2 版本，GCC 4.3+ 转为 GPLv3，FreeBSD 项目拒绝引入 GPLv3 代码到 base；Clang 使用 BSD 风格许可证（LLVM 使用 Apache 2.0 with LLVM Exceptions），LLDB 同理，消除了许可证风险

**辨析**：关于 “10.0 完全移除 GCC”——经 10.0 Release Notes 核实，此说不准确：GCC 4.2.1 仍存在于 base 源码树中用于 sparc64、powerpc、powerpc64、ia64 等非 x86 架构的构建，x86 上默认不安装 GCC 但可通过 WITH_GCC 选项启用；GCC 4.2.1 完全从 base 移除发生在 FreeBSD 13.0（2021 年 4 月 13 日）；关于 LLDB 的成熟度——10.0 中 LLDB 功能有限，GDB 仍保留在 base 中供需要完整调试功能的用户使用，GDB 的移除发生在 12.0（2018 年 12 月 11 日）而非 10.0
