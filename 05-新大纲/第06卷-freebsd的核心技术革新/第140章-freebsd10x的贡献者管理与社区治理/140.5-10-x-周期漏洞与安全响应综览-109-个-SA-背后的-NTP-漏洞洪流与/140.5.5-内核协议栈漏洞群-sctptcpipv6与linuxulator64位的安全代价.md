# 140.5.5 内核协议栈漏洞群——SCTP、TCP、IPv6 与 Linuxulator 64 位的安全代价

**要点**：10.x 周期 FreeBSD 内核协议栈与系统调用层共发布 **多个 SA**——SCTP 2 个（SA-15:03.sctp、SA-16:01.sctp）、TCP 3 个（SA-14:08.tcp、SA-15:13.tcp、SA-15:15.tcp、SA-16:05.tcp）、IPv6 1 个（SA-15:09.ipv6）、Linuxulator 4 个（SA-16:03.linux、SA-16:04.linux、SA-16:10.linux、SA-16:20.linux）、内核参数验证 3 个（SA-16:15.sysarch、SA-16:18.atkbd、SA-16:19.sendmsg）；**关键节点**：① **SA-14:08.tcp**（**2014 年 4 月 30 日**）修复 CVE-2014-3000 TCP 重组漏洞，commit `c6f70658c313`（Xin LI）——10.0-RELEASE 发布 3 个月后即出现 TCP 协议栈 SA，反映 10.0 网络栈在大规模重构后的稳定性阵痛；② **SA-15:03.sctp**（**2015 年 1 月 27 日**）一次性修复 CVE-2014-8612（SCTP_SS_VALUE 内核内存破坏）与 CVE-2014-8613（SCTP 流重置），commit `52ca05ee1823`（Xin LI）——SCTP 作为 10.x 周期最频繁出问题的内核协议，其复杂性（流重置、SS_VALUE、ICMPv6 错误处理）使代码审计难度远超 TCP/UDP；③ **SA-16:01.sctp**（**2016 年 1 月 14 日**）修复 CVE-2016-1879（SCTP ICMPv6 错误消息漏洞）；④ **SA-16:03.linux** 与 **SA-16:04.linux**（**2016 年 1 月 14 日**）同日发布，修复 CVE-2016-1880（Linuxulator 64 位拒绝服务）与 CVE-2016-1883（Linuxulator **issetugid(2)** 系统调用）——10.3-RELEASE 刚引入 64 位 Linuxulator 支持（详见本章前文 64 位 Linux 兼容层一节），3 个月后即出现安全 SA，反映“新功能引入新攻击面”的工程规律；⑤ **SA-16:15.sysarch**（**2016 年 3 月 16 日**）修复 CVE-2016-1885（**amd64_set_ldt(2)** 整数符号错误）；**freebsd.duckdb** 显示内核协议栈 CVE 修复 commit 主要由 Xin LI、Gleb Smirnoff、Konstantin Belousov（康斯坦丁·别洛乌索夫） 协作完成

**史料**：**freebsd.duckdb** `commits` 表 freebsd-src 仓库内核协议栈 CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2014-01-01' AND author_date<'2016-10-01' AND (message_subject LIKE '%SCTP%' OR message_subject LIKE '%TCP%' OR message_subject LIKE '%Linux%' OR message_subject LIKE '%kernel%') AND (message_body LIKE '%CVE-%' OR message_subject LIKE '%CVE-%') ORDER BY author_date ASC`；FreeBSD-SA-14:08.tcp（2014-04-30）——CVE-2014-3000；FreeBSD-SA-15:03.sctp（2015-01-27）——CVE-2014-8612/8613；FreeBSD-SA-16:01.sctp（2016-01-14）——CVE-2016-1879；FreeBSD-SA-16:03.linux 与 SA-16:04.linux（2016-01-14）——Linuxulator 64 位首批 SA；FreeBSD-SA-16:15.sysarch（2016-03-16）——CVE-2016-1885；Xin LI SCTP 修复 commit `52ca05ee1823`；Konstantin Belousov **ptrace(2)** 修复 commit `fd815c0b8dad`（CVE-2014-4699）；Gleb Smirnoff Linuxulator 修复 commit `57ebe89ac127〔实测 subject 为 Fix SCTP ICMPv6 error message vulnerability（SA-16:01.sctp/CVE-2016-1879，Gleb Smirnoff 2016-01-14），原标 Linuxulator 修复系归属错挂〕）；10.3-RELEASE Release Notes 关于 64 位 Linuxulator 引入的说明 ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界（原“软件工程”系伪名目，正名）：10.x 周期内核协议栈漏洞群反映了 FreeBSD 内核代码的“复杂性—攻击面”权衡——SCTP 协议本身复杂（4 次握手、流多路复用、部分可靠性），**sctp(4)** 模块代码量大，漏洞密度高于 TCP/UDP；Linuxulator 作为“兼容层”必须复制 Linux 系统调用语义，任何 Linux 内核漏洞都可能在 Linuxulator 中重现，且 Linuxulator 维护者长期人手不足（主要是 Dmitry Chagin、Konstantin Belousov），代码审计覆盖面有限；10.3 引入 64 位 Linuxulator 是 10.x 周期最显著的内核功能扩展，但新代码立即带来 4 个 SA——这一模式在 9.x（64 位 Linuxulator 早期工作）与 11.x（Linuxulator 持续修复）中重复出现；**与 14.x 周期 bhyve 漏洞群对比**：14.x 周期 bhyve 5 个 SA 是虚拟化边界审计的产物，10.x 周期 Linuxulator 4 个 SA 是兼容层扩展的产物，两者都反映“新功能—新攻击面”的工程规律，但 bhyve 是新建代码（攻击面较窄），Linuxulator 是复制代码（攻击面与 Linux 内核同步）

**辨析**：**SCTP 漏洞的特殊性**：SCTP 在 FreeBSD 中默认加载（作为 **sctp(4)** 模块），但实际使用率低（绝大多数部署不使用 SCTP 协议）——SCTP 漏洞的影响范围与协议使用率不成比例，是“低使用率—高攻击面”的典型样本；FreeBSD 12.0（2018.12）将 SCTP 从默认内核配置中移除，部分原因即是 10.x 周期 SCTP 漏洞频繁；**Linuxulator 64 位的辨析**：10.3 引入 64 位 Linuxulator 是为运行 Linux 64 位二进制（如 CentOS 7 x86_64 容器），但 64 位 Linuxulator 的系统调用接口比 32 位更复杂（涉及 **setregs(2)**、**set_ldt(2)** 等架构相关调用），10.3 发布 3 个月后即出现 SA-16:03.linux 与 SA-16:04.linux，验证了“架构扩展引入新攻击面”的规律；**CVE-2014-4699 的归属辨析**：CVE-2014-4699 是 Linux 内核 **ptrace(2)** 漏洞（Intel 处理器上 **set_regs()** 与 **ptrace_set_pc()** 不正确使用），FreeBSD 通过 commit `fd815c0b8dad`（Konstantin Belousov，2014-07-09）修复——这是 FreeBSD 主动跟随 Linux 内核漏洞修复的案例，但该 CVE 在版本周期文件中被归入 10.x 周期 commit 清单，实际影响所有支持 **ptrace(2)** 的 FreeBSD 版本
