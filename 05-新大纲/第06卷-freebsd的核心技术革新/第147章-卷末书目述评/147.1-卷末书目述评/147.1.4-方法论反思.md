# 147.1.4 方法论反思

本卷史家在使用上述史料时遵循三条方法论原则，但亦须反思其局限与盲区。
第一，0 信任原则的叠加适用。本卷对所有史料——包括 FreeBSD 官方公告、当事人技术论文、**freebsd.duckdb** 代码档案、剑桥大学学术论文——均施加 0 信任检视，不因“一手”身份而免检。这一原则的实践路径是“三角验证”：每个关键事实须有至少三类独立来源相互印证。然而 0 信任原则亦有局限：当多个来源均源于同一研究团队（如 Watson 团队的 Capsicum 论文与 CheriBSD 实现）时，“三角”退化为“两角”，验证效力下降。本卷对 Capsicum/CHERI 谱系的叙述因此保持克制，避免在证据薄弱处强作结论。
第二，非正式出版物的考据边界。BSD 会议论文集（BSDCan、EuroBSDCon、AsiaBSDCon）多属非正式出版物，无 ISBN 或正式出版编号，多数演讲仅以幻灯片 PDF 形式发布，部分幻灯片链接随时间失效。按 0 信任原则，非正式出版物的史料价值须低于同行评议学术论文与官方一手档案，其内容须以同行评议学术论文与官方一手档案交叉验证后方可采信为史实。对于穷尽考据仍无法交叉验证的非正式出版物内容，允许保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 而非强行采信或臆断排除。
第三，当事人叙述与档案证据的认识论距离。本卷时间范围内多数关键决策的当事人（Watson、Dawidek、Grehan、Davis 等）仍活跃于 FreeBSD 社区，其个人博客、邮件列表回忆、会议演讲构成当事人叙述的密集来源。当事人叙述兼具一手陈述与自利偏差双重性质——作为参与者，其陈述是事件最直接记录；作为当事人，其可能美化个人立场、转嫁责任、重构决策动机。处理方法：其一，当事人叙述须与 commit 历史、Release Notes 等档案证据核对一致；其二，当事人之间的相互印证可降低单一当事人偏差风险；其三，当事人叙述与其他独立来源的交叉验证方可采信为史实。
本卷方法论的主要盲区有三：其一，Sun/Oracle 内部档案的缺位——ZFS 与 DTrace 的原始设计决策记录在 Sun/Oracle 内部，本卷对“Sun 工程师如何设计 ZFS/DTrace”的叙述依赖公开论文与文档，缺乏内部视角；其二，商业用户的沉默——Netflix、iXsystems 等商业用户的内部工程决策档案未公开，本卷对“生产用户反馈如何塑造 FreeBSD 工程”的叙述偏重社区一侧；其三，跨系统比较的深度不足——本卷对 DTrace 与 eBPF、bhyve 与 KVM 的比较偏重技术层面，对商业生态与社区治理维度的比较有待深化。
