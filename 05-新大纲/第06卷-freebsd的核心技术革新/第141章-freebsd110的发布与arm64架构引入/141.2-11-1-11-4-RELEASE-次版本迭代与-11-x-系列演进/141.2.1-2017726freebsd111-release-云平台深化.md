# 141.2.1 2017.7.26 FreeBSD 11.1-RELEASE——云平台深化

**要点**：FreeBSD 11.1-RELEASE 于 2017 年 7 月 26 日发布，是 stable/11 第二个版本，Release Engineering Lead 仍为 Glen Barber（格伦·巴伯）。核心更新：Clang/LLVM/LLD/LLDB/libc++ 全套升级至 4.0.0；**blacklistd(8)** 正式集成到 OpenSSH；新增 **zfsbootcfg(8)** 工具（提供 ZFS 引导一次性 boot.config 风格选项）与 **efivar(8)** 工具（UEFI 变量管理接口）；支持 Microsoft Hyper-V Generation 2 虚拟机（UEFI 引导、安全启动等第二代特性）；新增 **ena(4)** 驱动支持 Amazon EC2“下一代增强网络”（Elastic Network Adapter，100Gbps 级网络）；NFS 客户端支持 Amazon Elastic File System（EFS）；EFI 引导加载器新增 TFTP 远程文件访问（除 NFS 外）；ZFS 改进压缩数据缓存以提高缓存命中率与性能；多项构建可重现性（reproducible builds）改进。11.1 是首个正式登陆 Microsoft Azure Marketplace 的 FreeBSD 版本（10.x 时期仅在 VMDepot），Google Compute Engine、Amazon EC2、Vagrant 镜像继续提供。

**史料**：FreeBSD 11.1-RELEASE Announcement（2017-07-26，明确所有特性列表、Azure Marketplace 上线说明）、FreeBSD 11.1-RELEASE Release Notes（Clang 4.0.0 升级 r308114、Hyper-V Gen2、ena(4) 驱动、ZFS 缓存改进等）、Amazon EC2 ENA 驱动文档；**freebsd.duckdb** `tags` 表 `freebsd-src` 仓库 release tag 数据库验证——`release/11.1.0` tagger_date = 2017-07-21T20:55:38Z，tagger_name = Glen Barber，target_commit_hash = `e1b2281799bf1cab48b112204fef079e6835cde5`，target_commit_date = 2017-07-20T23:39:50Z，tag_type = annotated，tag_message =“Tag releng/11.1@r321309 as 11.1-RELEASE.”，与公开声明日期 2017-07-26 相差 5 日（即 tag 创建后约 5 日才正式发布，符合 FreeBSD 发布工程“tag 先行、公告随后”的标准节奏）；**freebsd.duckdb** `commits` 表 `freebsd-src` 仓库查询 r308114 关键字得到两条 MFC commits——commit `796b1ed89fa59053da5e52d4319f5ba144a18d49`（Konstantin Belousov（康斯坦丁·别洛乌索夫），2016-11-06T12:56:07Z，message_subject ="MFC r308114: Change remained internal uses of boolean_t to bool in vm/vm_fault.c."）与 commit `2507b8a588fd3b38594dbd09a87b9918e99ac09e`（Konstantin Belousov，2016-11-06T13:40:03Z，同 subject），此两条 commits 引用的 r308114 是 boolean_t→bool 改造的 SVN revision 而非 Clang 4.0.0 升级 commit 本身，Clang 4.0.0 实际导入 commit 在 SVN-to-Git 迁移时丢失了 r308114 编号关联 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律（原“开源运动”挂第 22 条系伪名目，按云厂商与 FreeBSD 双向代码流动论旨改挂）：11.1 对 Hyper-V Gen2 与 AWS ENA 的支持标志着 FreeBSD 在公有云平台的地位从“可用”升级为“一等公民”。Microsoft 与 Amazon 都直接向 FreeBSD 贡献了驱动代码（Hyper-V 驱动由 Microsoft Open Source Technology Center 持续贡献，ENA 驱动由 Amazon 工程师提交），这种公有云厂商主动支持 FreeBSD 的现象在 10.x 之前较为罕见。

**辨析**：11.1 Release Notes 提到“build reproducibility”改进但这并非表示 FreeBSD 已实现完全可重现构建——可重现构建是一个持续多年的项目，11.1 为部分组件实现了确定性输出，完全可重现构建在后续版本才逐步完善。**数据库验证结论**：`release/11.1.0` tagger_date = 2017-07-21T20:55:38Z 早于公开声明日期 2017-07-26 共 5 日，与 11.0 的 17 日偏差、11.2 的 6 日偏差、11.3 的 1 日偏差、11.4 的 7 日偏差对比，11.1 的 5 日偏差属于正常范围（反映 tag 创建到正式公告间的镜像构建与发布准备时间）；r308114 在 commits 表中查询到的两条 MFC commits 引用的是 boolean_t→bool 改造而非 Clang 4.0.0 升级，提示原大纲中“Clang 4.0.0 升级 r308114”的 SVN revision 编号可能存在标注偏差或 r308114 是另一条 Clang 升级相关 commit 但在迁移时未保留编号关联；0 信任原则提示：11.1 在 SVN 时代发布，tagger_date 由 2020 年 SVN-to-Git 迁移脚本根据原始 SVN 元数据回填，可信度较高；r308114 编号关联问题需进一步通过 release notes 中其他 Clang 升级相关 commits 交叉验证
