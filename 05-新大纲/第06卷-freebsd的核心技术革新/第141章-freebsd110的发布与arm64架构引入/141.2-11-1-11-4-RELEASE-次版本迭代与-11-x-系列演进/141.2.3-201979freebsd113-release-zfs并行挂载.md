# 141.2.3 2019.7.9 FreeBSD 11.3-RELEASE——ZFS 并行挂载

**要点**：FreeBSD 11.3-RELEASE 于 2019 年 7 月 9 日发布，stable/11 第四个版本。核心更新：Clang/LLVM/LLD/LLDB/compiler-rt/libc++ 升级至 8.0.0；ZFS 文件系统实现并行挂载（parallel mounting），大量 ZFS 文件系统或快照的系统启动速度显著提升；**geli(8)** 加密支持扩展到所有架构（先前部分架构引导时 GELI 支持有限）；**loader(8)** 引导加载器改进；**pkg(8)** 更新至 1.10.5；新增多项安全弃用警告：IPsec 算法弃用警告（遵循 RFC 8221）、**geli(8)** 创建 provider 时对弱加密算法的弃用警告；内核在进程退出时记录 **jail(8)** ID 便于审计；ELF Tool Chain 更新至 r3614；OpenSSL 1.0.2s。赞助企业名单中新增 Netgate（Rubicon Communications，pfSense 母公司）、CyberOne Data、NetActuate、National Chiao Tung University 等。Antoine Brodin（antoine@）加入 Release Team 负责 Package Building。

**史料**：FreeBSD 11.3-RELEASE Announcement（2019-07-09，明确 ZFS 并行挂载、geli 全架构支持、弃用警告、Release Team 新增 Antoine Brodin）、FreeBSD 11.3-RELEASE Release Notes（Clang 8.0.0 r348241、ZFS parallel mount、RFC 8221 警告）；**freebsd.duckdb** `tags` 表 `freebsd-src` 仓库 release tag 数据库验证——`release/11.3.0` tagger_date = 2019-07-08T14:04:44Z，tagger_name = Glen Barber，target_commit_hash = `bf0104cf3db74756d08cba044e7f40a1d6da644a`，target_commit_date = 2019-07-04T23:58:11Z，tag_type = annotated，tag_message =“Tag releng/11.3@r349754 as release/11.3.0 (11.3-RELEASE).”，与公开声明日期 2019-07-09 相差 1 日（即 tag 创建后约 1 日即正式发布，是 11.x 系列中 tag 与公告日期最接近的版本，反映 11.3 发布过程未发生镜像重建等问题）；**freebsd.duckdb** `commits` 表 `freebsd-src` 仓库查询 r348241 关键字找到一条 MFC commit——commit `2cb4785ad01cb322158840a3f937bebcb37f0ff5`（Mark Johnston（马克·约翰斯顿），2019-05-31T15:05:54Z，message_subject ="MFC r348241: Modernize the MAKE_JUST_KERNELS hint in the top-level makefile."），此 commit 引用的 r348241 是 MAKE_JUST_KERNELS 提示现代化的 SVN revision 而非 Clang 8.0.0 升级 commit 本身，Clang 8.0.0 实际导入 commit 在 SVN-to-Git 迁移时丢失了 r348241 编号关联 ［A］

**史观**：总纲第 17 条——证明世界先于解释和改造世界（原“软件工程”系伪名目，按工程实践成效论旨正名）：ZFS 并行挂载是典型的“可感知性能改进”——在拥有数百甚至数千个 ZFS 数据集的系统（如存储服务器、jail 宿主机）上，串行挂载曾是启动瓶颈，并行化后启动时间可缩短数倍。这类改进虽不引入新功能但直接改善了大规模部署场景下的用户体验，是 FreeBSD 工程成熟度的体现。密码学弃用警告则体现了安全团队主动推进加密算法现代化的策略——在彻底移除弱算法前提前警告用户，给予迁移缓冲期。

**辨析**：11.3 中 Clang 版本升级至 8.0.0 而非部分资料所称 7.x——经 Announcement 与 Release Notes 核实确为 8.0.0；这一升级跨度较大（从 11.2 的 6.0.0 直接跳到 8.0.0），因为 stable/11 分支采用 MFC（Merge From Current）策略选择性合并 -CURRENT 中的重要更新而非每次点版本都升级编译器。**数据库验证结论**：`release/11.3.0` tagger_date = 2019-07-08T14:04:44Z 早于公开声明日期 2019-07-09 仅 1 日，是 11.x 系列中偏差最小的版本（对比 11.0 偏差 17 日、11.1 偏差 5 日、11.2 偏差 6 日、11.4 偏差 7 日），反映 11.3 发布过程相对顺利未发生重大问题；r348241 在 commits 表中查询到的 MFC commit 引用的是 MAKE_JUST_KERNELS 改造而非 Clang 8.0.0 升级，提示原大纲中“Clang 8.0.0 r348241”的 SVN revision 标注可能存在编号偏差或 r348241 是另一条 Clang 升级相关 commit 但在迁移时未保留编号关联；0 信任原则提示：tagger_date 由迁移脚本根据原始 SVN 元数据回填，可信度较高；target_commit_date = 2019-07-04T23:58:11Z 早于 tagger_date 约 3 日，反映 tag 指向的 commit 与 tag 创建之间存在 SVN 操作延迟
