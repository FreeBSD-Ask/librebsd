# 141.3.1 bhyve(8) 虚拟化成熟

**要点**：**bhyve(8)** 在 FreeBSD 11.x 时期从“可用的 Type-2 hypervisor”走向成熟。11.0 中 bhyve 获得原生图形支持（native graphics support），允许客户机通过 UEFI GOP 与 framebuffer 输出图形界面，不再局限于串行控制台；UEFI 固件支持持续改进——10.x 时期需通过 ports 安装 uefi-edk2-bhyve，11.x 时期 UEFI 支持更加稳定；客户机操作系统支持扩展——除 FreeBSD/Linux/OpenBSD/NetBSD 外，Windows 客户机支持在 11.x 时期显著改进（需配合 UEFI 固件与 VirtIO 驱动）；SMP 多 vCPU 支持在 10.3 加入后 11.x 持续优化稳定性；PCI 直通（passthrough）功能改进；virtio 设备支持完善（块设备、网络、随机数、ballooning）；checkpoint/suspend/resume 功能在 11.x 引入。bhyve 由 NetApp 赞助的 Peter Grehan（彼得·格雷汉）（grehan@）和 Neel Natu（尼尔·纳图）（neel@）等开发者主导开发，FreeBSD Foundation 也赞助了部分 bhyve 改进。

**史料**：FreeBSD 11.0-RELEASE Announcement（"Native graphics support has been added to the bhyve(8) hypervisor"）、11.x 各版本 Release Notes Virtualization 章节、bhyve(8) 手册页、Peter Grehan 关于 bhyve 的会议演讲、FreeBSD Quarterly Status Reports 虚拟化章节。 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：bhyve 代表了 FreeBSD 在虚拟化领域的独立路线——不采用 KVM（Linux 内核虚拟机，GPL 许可证），也不依赖 Xen（虽有 Dom0/DomU 支持但非 FreeBSD 原创），而是开发完全 BSD 许可的原生 Type-2 hypervisor。这一路线使 FreeBSD 在虚拟化领域保持了操作系统内核的完整性与许可证纯洁性，但也意味着 bhyve 在功能丰富度与生态规模上（如客户机 OS 兼容性、管理工具栈）与 KVM 存在差距。

**辨析**：bhyve 在 11.x 仍不支持 live migration（实时迁移）——此功能在 FreeBSD 13.x 才引入；NVIDIA vGPU 等高级 GPU 虚拟化功能不在 11.x bhyve 支持范围内；bhyve 管理主要依赖命令行（**bhyve(8)**/**bhyvectl(8)**/**bhyveload(8)**），虚拟机管理器（如 vm-bhyve、CBSD）通过 ports 提供而非 base 组件。
