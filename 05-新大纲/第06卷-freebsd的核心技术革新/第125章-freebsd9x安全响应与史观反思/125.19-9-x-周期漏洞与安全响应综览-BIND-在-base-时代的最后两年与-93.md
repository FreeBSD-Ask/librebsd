# 125.19 9.x 周期漏洞与安全响应综览——BIND 在 base 时代的最后两年与 93 个 CVE commit 的考据切片

## 125.19.1 9.x 周期安全态势总览——BIND 在 base 时代的最后两年

**要点**：9.x 版本周期文件覆盖窗口（**2012-01-01** 至 **2014-01-01**，对应 9.0-9.2-RELEASE 开发与维护期）freebsd-src 仓库共 **93 条 CVE 相关 commit**、去重后 **28 个 CVE**，另有 **33 条无 CVE 编号的 security fix commit**；将窗口扩展至 9.x 全支持周期（2012.1 至 2017.1，9.3-RELEASE 支持至 2017.1.1）则 CVE commit 增至 **312 条**；28 个 CVE 全部 “无 CVSS v3 评分”——这一元数据缺失反映 NVD 对 2012-2014 年 FreeBSD CVE 的覆盖长期滞后于 Linux 主流发行版；9.x 周期 BIND/**named(8)** 与 OpenSSL 是两个主要 CVE 来源，**sendmail(8)**、**sshd(8)**、Linuxulator 等子系统次之；9.x 时期 base 系统仍包含 BIND（10.0 才移除）与 sendmail（10.0 才换为 **dma(8)**），是 9.x 周期安全债务的两大结构性来源。9.x 周期关键安全事件时间线汇总见下表。

**辨析**：**数据窗口辨析**：版本周期文件覆盖 2012.1-2014.1（开发与 9.0-9.2-RELEASE 维护期），但 9.3-RELEASE 支持至 2017.1.1——故 “9.x 周期” 在安全响应语境下有两个不同时间窗口：① 版本周期文件窗口（2012.1-2014.1，93 条 CVE commit）；② 全支持周期窗口（2012.1-2017.1，312 条 CVE commit）；本节采用版本周期文件窗口为主、全周期窗口为辅；**与 14.x 周期对比的辨析**：14.x 周期 648 条 CVE commit、189 个去重 CVE，9.x 周期 93 条、28 个，绝对数量差异约 7 倍——但这不直接反映代码质量差异，主要受三因素影响：其一，9.x 时期 NVD 元数据覆盖薄弱（28 个全部无 CVSS v3）；其二，9.x 时期 freebsd-src commit 元数据中 CVE 标注不如 14.x 时期规范；其三，9.x 时期 base 系统包含的第三方组件数量少于 14.x（如 9.x 不含 libarchive、xz 等）；**SA 节奏对比**：9.x 全周期约 130 个 SA，14.x 周期（不足 3 年）80 个 SA——9.x 周期年均约 26 个，14.x 周期年均约 27 个，二者节奏接近

## 125.19.2 OpenSSL 多漏洞批量修复——2012 年 5 月 3 日的 9 个同日 commit 与 Lucky 13 前夜

**要点**：**2012 年 5 月 3 日** Bjoern A. Zeeb（bz@）在 freebsd-src 仓库单日提交 **9 个 OpenSSL 修复 commit**（hash `63a04068615b`、`8b21581b6026`、`09a865e4fb3a`、`34e8deeed81e`、`51b069ec20bf`、`2ba20502898f`、`b5b482d053f2`、`a8ec49085f69`、`a95abaf17347`），一次性处理 **5 个 CVE**：CVE-2011-4109（OpenSSL 0.9.8s 之前版本 double free）、CVE-2011-4576（SSL 3.0 实现缺陷）、CVE-2011-4619（Server Gated Cryptography 实现）、CVE-2012-0884（CMS/PKCS #7 实现问题）、CVE-2012-2110（`asn1_d2i_read_bio` 函数堆缓冲区溢出）；**2013 年 4 月 2 日** Xin LI（delphij@）修复 CVE-2013-0166（OpenSSL CBC Lucky 13）与 CVE-2013-0169（TLS/DTLS 时序攻击），后者即业界著名的 “Lucky 13” 时序攻击；**SA-13:03.openssl**（2013-04-02 发布）是这两组 CVE 的官方公告——但 SA-13:03 发布时间晚于 2012-05-03 修复 commit 近一年，反映 9.x 时期 SA 流程中 commit 与 SA 发布的时间差通常较大

**史料**：**freebsd.duckdb** `commits` 表 freebsd-src 仓库 OpenSSL CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2012-05-03' AND author_date<'2012-05-04' AND message_subject LIKE '%OpenSSL%' ORDER BY author_date ASC`；commit `63a04068615b` 等九个 commit hash；FreeBSD-SA-13:03.openssl（2013-04-02）PGP 签名公告；AlFardan 等关于 Lucky 13 时序攻击的 USENIX Security 2013 论文 ［A］

**史观**：许可证：OpenSSL 是 9.x 时期 base 系统最重要的加密栈组件，其 EOL 与升级周期直接驱动 FreeBSD 安全响应节奏；9.x 时期 OpenSSL 仍在 0.9.8/1.0.0 系列过渡阶段，CVE 密集出现——这一模式在后续周期反复出现（11.x 的 1.0.1→1.0.2、13.x 的 1.0.2→1.1.1、14.x 的 1.1.1→3.0），即 “OpenSSL 代际迁移必然伴随 CVE 集中清算”

**辨析**：**9 个同日 commit 的工程辨析**：Bjoern Zeeb 单日提交 9 个 commit 而非 1 个聚合 commit——这是 9.x 时期 SVN 工作流的典型特征，每个 CVE 修复对应独立的 SVN revision（即后续 MFC 的独立单元）；与 14.x 时期 OpenSSL vendor import 一次性聚合多 CVE 的 commit 模式（如 `9dd13e84fa8e` 一次修复 4 个 CVE）形成对比，反映 SVN 时代与 Git 时代 commit 颗粒度的不同；**SA-13:03 发布时间辨析**：SA-13:03.openssl 在 2013-04-02 发布，但对应 commit 早在 2012-05-03 已落地——近一年的 commit-to-SA 时间差是 9.x 时期安全响应流程的典型滞后，反映 Security Officer 交接期（Colin Percival → Simon Nielsen）的发布节奏；**Lucky 13 的命名辨析**：CVE-2013-0166 在中文安全媒体中常被简化为 “OpenSSL CBC 漏洞”，但其技术本质是 TLS CBC 模式时序攻击——由 AlFardan、Paterson 等学者在 2013 年 USENIX Security 发表，攻击原理基于 CBC 填充预言攻击的时序信号放大

## 125.19.3 BIND/named 漏洞群——9.x 周期 BIND 在 base 的最后两年与 6 个 bind SA

**要点**：9.x 周期 BIND/**named(8)** 相关 SA 共 **6 个**——SA-12:03.bind、SA-12:05.bind、SA-12:06.bind、SA-13:01.bind、SA-13:04.bind、SA-13:07.bind，是 9.x 周期最密集的单一组件 CVE 来源；2012-06-12 Bjoern Zeeb 单日 **9 个 commit** 修复 CVE-2012-0217、CVE-2012-1667（**named(8)** 零长度 RDATA 字段崩溃）；2012-11-22 Simon L. B. Nielsen 单日 **7 个 commit** 修复 CVE-2012-4244、CVE-2012-4445、CVE-2012-4576、CVE-2012-5166（**named(8)** 多重 DoS）；2013-07-26 Xin LI 修复 CVE-2013-4851、CVE-2013-4854（**named(8)** RFC 5011 与 DNSSEC DoS）；9.x 是 BIND 在 base 的最后岁月——**10.0-RELEASE（2014-01-20）才将 BIND 从 base 移除**，转由 ports/dns/bind9 维护；9.x 时期 BIND 在 base 的存在使 **named(8)** CVE 必须通过 SA 流程修复，工作量巨大

**史料**：**freebsd.duckdb** `commits` 表 freebsd-src 仓库 named CVE commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2012-01-01' AND author_date<'2014-01-01' AND message_subject LIKE '%named%' AND (message_subject LIKE '%CVE-%' OR message_body LIKE '%CVE-%') ORDER BY author_date ASC`；FreeBSD-SA-12:03/05/06.bind 与 SA-13:01/04/07.bind PGP 签名公告；ISC BIND 9.x CVE 历史 ［A］

**史观**：软件工程：BIND 在 base 是 9.x 周期安全债务的结构性来源——BIND 作为 ISC 维护的上游项目，其 CVE 修复需要 FreeBSD Security Team 同步 vendor import、回溯至 stable/9 与 releng/9.x 多个分支、编写 SA 公告，工作流冗长；10.0 将 BIND 移出 base 是 FreeBSD “基本系统最小化” 工程哲学的延续——与 sendmail→ **dma(8)**、GCC→Clang、GNU patch→BSD patch 同源，皆为降低 base 中第三方组件的维护负担

**辨析**：**SA-13:01.bind 与 SA-13:07.bind 辨析**：两个 SA 均修复 **named(8)** DoS 漏洞但 CVE 不同——SA-13:01 修复 CVE-2012-5688（DNS64 启用时的 DoS），SA-13:07 修复 CVE-2013-4851（NFS 服务器访问检查）与 CVE-2013-4854（RFC 5011 实现 DoS）；**数据库 commit 与 SA 对应关系**：2013-07-26 Xin LI 6 个 commit（`53ab617e6de7`、`4202b2ded466`、`092516cf2637`、`9657f3ce711e`、`2f44111a34ae`、`cee6f3d0d836`）对应 SA-13:07.bind，部分 commit 在 commit_subject 中明确标注 `[13:07]`——这是 9.x 时期 SVN commit 与 SA 编号直接关联的典型样本；**BIND 移除时间线辨析**：BIND 在 10.0-RELEASE 从 base 移除是 FreeBSD 官方明确声明的工程决策，但有部分中文资料误称 “9.x 已移除 BIND”——9.x 全系列 BIND 仍在 base 中 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 125.19.4 CVE-2012-4576——FreeBSD base 系统的罕见权限提升 CVE 与 MFS 工作流

**要点**：CVE-2012-4576 是 9.x 周期罕见的 FreeBSD base 系统特有 CVE——"Input Validation Flaw allows local users to gain elevated privileges"（输入验证缺陷允许本地用户获取提升权限）；**2012-11-23** Colin Percival 通过 MFS（Merge From Stable）补丁将该修复回溯至 HEAD（commit `43f13bea3529`），commit_subject 明确 "MFS security patches which seem to have accidentally not reached HEAD"——反映 9.x 时期安全补丁的双向回溯工作流（stable→HEAD 与 HEAD→stable 并存）；与同期 OpenSSL/BIND 第三方 CVE 不同，这是 FreeBSD base 自身代码的输入验证缺陷——本地用户可通过特定输入触发权限提升

**史料**：**freebsd.duckdb** `commits` 表 freebsd-src 仓库 CVE-2012-4576 修复 commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND (message_body LIKE '%CVE-2012-4576%' OR message_subject LIKE '%CVE-2012-4576%')`；commit `43f13bea3529`（Colin Percival, 2012-11-23）；NVD CVE-2012-4576 原始记录 [考据完成：2026-08-17 CVE-2012-4576 对应 FreeBSD-SA-12:08.linux（Linux 兼容层输入验证错误，经 cgit.freebsd.org commit 9ea3d854 一手确认，非 SA-12:06.bind）] ［A］

**史观**：社区治理：CVE-2012-4576 反映 9.x 时期 FreeBSD 安全响应流程的成熟——base 系统本地提权漏洞由内部 Security Team 发现并通过 SA 流程修复，而非外部研究者披露；Colin Percival 作为 Security Officer Emeritus 在 commit 第二日即回溯至 HEAD，体现其建立的安全响应速度标准；这一 CVE 也是 9.x 周期少数 base 系统特有 CVE 之一（多数 9.x CVE 来自第三方组件）

## 125.19.5 SA-12:04.sysret——Xen 兼容层漏洞与 9.0 时代的 guest 视角虚拟化安全

**要点**：**SA-12:04.sysret**（**2012 年 6 月 12 日** 发布）修复 CVE-2012-0217——Xen 4.1.2 及更早版本 x86-64 内核系统调用功能中的权限提升漏洞；该漏洞允许 64 位 PV guest 用户模式在异常情况下获得内核权限，影响所有运行 Xen hypervisor 的系统；**2012-06-12** Bjoern Zeeb 单日提交多个 commit 修复 sysret 漏洞，与同日 SA-12:03.bind 修复同步发布——这是 9.0-RELEASE 发布后第一个月内的密集安全响应；这一 SA 反映 9.x 时期虚拟化安全的早期认知——bhyve 尚未发布（10.0 才正式），FreeBSD 主要作为 Xen guest 受影响，而非 hypervisor

**史料**：FreeBSD-SA-12:04.sysret（2012-06-12）PGP 签名公告；**freebsd.duckdb** `commits` 表 freebsd-src 仓库 SA-12:04 修复 commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2012-06-12' AND author_date<'2012-06-13' ORDER BY author_date ASC`；Xen Security Advisory CVE-2012-0217；commit `91843b976ed9`、`7de97b74b6c4`、`03bfa4c289a8`、`5c96f75b591d`、`58aded078e89`、`d7f9effb72bc`、`305ed185837c`、`b0a576ce8eea`（Bjoern Zeeb） ［A］

**史观**：硬件与软件辩证：SA-12:04.sysret 是 9.x 时期 FreeBSD 作为 guest 操作系统受 hypervisor 漏洞影响的典型样本——9.x 时期 FreeBSD 在虚拟化生态中主要扮演 guest 角色（Xen PV guest、KVM guest、VMware guest），10.0 引入 bhyve 后才具备原生 hypervisor 能力；sysret 漏洞的修复反映 FreeBSD 安全团队对 Xen 兼容代码的持续维护负担——这一负担在 9.x 时期尤为突出，因 Xen PV guest 是当时云环境（如 AWS 早期、Rackspace）的主要虚拟化模式

**辨析**：**9 个 commit 与 2 个 SA 的关系辨析**：2012-06-12 单日多个 commit 修复 CVE-2012-0217 与 CVE-2012-1667 两个 CVE，对应 SA-12:03.bind（named RDATA）与 SA-12:04.sysret（Xen sysret）两个 SA——这是 9.x 时期 SVN 工作流中 “多 commit、多 SA、同日发布” 的典型节奏，反映 Security Officer Colin Percival 在 9.0 发布后第一个月内的密集安全响应；**commit `d961d92acefa` 的考据纠正**：该 commit（Bjoern A. Zeeb, 2012-06-12）在数据库中实际 subject 为 "Fix a problem where zero-length RDATA fields can cause named(8) to crash. [12:03]"，subject 中 `[12:03]` 标签明确标记其归属 SA-12:03.bind，**并非** SA-12:04.sysret 修复 commit——先前版本的史料字段将其误列入 SA-12:04.sysret 的 commit 清单，经数据库 0 信任原则审校后纠正并从该清单移除；**Xen 与 bhyve 的对比**：9.x 时期 Xen PV guest 是 FreeBSD 虚拟化的主要场景，10.0 引入 bhyve 后 FreeBSD 才具备原生 Type-2 hypervisor 能力——sysret 漏洞修复是这一过渡期前最后的 “guest 视角” 虚拟化安全事件；**与 14.x 周期 bhyve 漏洞群对比**：14.x 周期 5 个 bhyve SA（SA-24:01/10/12/15/17.bhyve）反映 hypervisor 视角的虚拟化安全，9.x 周期 sysret 漏洞反映 guest 视角的虚拟化安全——两种视角的对比揭示 FreeBSD 在虚拟化生态中角色转变带来的安全响应范式转移

## 125.19.6 内核子系统漏洞群——NFS、SCTP、IPv6 ioctl、nullfs 与 2013-09-10 单日 6 SA

**要点**：9.x 周期内核子系统 CVE 集中于：其一，NFS——CVE-2013-3266（`nfsrvd_readdir` 函数允许 NFS 客户端对文件发起 READDIR）、CVE-2013-4851（`vfs_hang_addrlist` 函数远程客户端访问检查绕过），均由 Dag-Erling Smørgrav 修复；其二，SCTP——CVE-2013-5209（`sctp_send_initiate_ack` 函数）；其三，IPv6/ATM ioctl——CVE-2013-5691（SIOCSIFADDR/SIOCSIFBRDADDR 等 ioctl 处理器权限验证缺失）；其四，nullfs——CVE-2013-5710（`null_vnops.c` 中的访问控制问题）；其五，**sendfile(2)**——CVE-2013-5666（`uipc_syscalls.c` 中 sendfile 长度计算缺陷）；其六，IP_MSFILTER——CVE-2013-3077（IP_MSFILTER/IPV6_MSFILTER 整数溢出）；**2013-09-10** Dag-Erling Smørgrav 单日修复 CVE-2013-5666、CVE-2013-5691、CVE-2013-5710 三个内核漏洞，同日发布 SA-13:08.nfsserver、SA-13:09.ip_multicast、SA-13:10.sctp、SA-13:11.sendfile、SA-13:12.ifioctl、SA-13:13.nullfs 共 **6 个 SA**——这是 9.x 周期单日 SA 发布峰值，反映 9.2-RELEASE 发布（2013-09-30）前的安全收尾工作

**史料**：**freebsd.duckdb** `commits` 表 freebsd-src 仓库 2013-09-10 内核漏洞修复 commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='freebsd-src' AND author_date>='2013-09-10' AND author_date<'2013-09-11' AND message_subject LIKE '%Fix%' ORDER BY author_date ASC`；FreeBSD-SA-13:08.nfsserver、SA-13:09.ip_multicast、SA-13:10.sctp、SA-13:11.sendfile、SA-13:12.ifioctl、SA-13:13.nullfs PGP 签名公告（全部发布于 2013-09-10）；commit `1a05c762b9c2`、`2c3606f5f6d3`、`e2630701b434`、`9720beddca63`、`7a0109492bec`、`448c80b97009`、`772e608bdc47`（Dag-Erling Smørgrav） ［A］

**史观**：硬件与软件辩证：9.x 周期内核子系统漏洞群反映 FreeBSD 内核攻击面的广度——NFS、SCTP、IPv6、nullfs、**sendfile(2)**、IP_MSFILTER 跨越网络栈、文件系统、系统调用等多个子系统；2013-09-10 单日 6 个 SA 反映 Security Officer Dag-Erling Smørgrav 上任后的首次批量披露，与 14.x 周期 2026 年 SA-26 系列的 “audit” 主题工作模式形成历史呼应——两位 Security Officer 在不同时期均采用 “集中审计—批量披露” 模式

**辨析**：**2013-09-10 单日 6 SA 的辨析**：6 个 SA 集中于 2013-09-10 发布，对应 commit 亦在 2013-09-10 当日提交——commit 与 SA 同步发布，与同期 OpenSSL commit 与 SA 长达近一年的滞后（2012-05-03 commit 至 2013-04-02 SA-13:03）形成对比；这一节奏差异反映 Security Officer 交接后（Simon Nielsen → Dag-Erling Smørgrav）流程改进，commit-to-SA 时差大幅缩短；**CVE-2013-5691 IPv6/ATM ioctl 的辨析**：commit_subject 中 "In IPv6 and NetATM, stop SIOCSIFADDR, SIOCSIFBRDADDR, SIOCSIFDSTADDR and SIOCSIFNETMASK at the socket layer rather than pass them on to the link layer without validation or credential checks"——这是 9.x 时期 IPv6 与 ATM 共享 ioctl 路径的遗留问题，ATM 支持在后续版本被移除，但 IPv6 ioctl 路径保留并持续维护；**nullfs CVE-2013-5710 的辨析**：nullfs 是 FreeBSD 特有的 stackable 文件系统，其访问控制漏洞仅影响 FreeBSD——与 CVE-2012-4576 类似，是 base 系统特有 CVE，但严重程度与影响范围远小于 OpenSSL/BIND 第三方漏洞；**与 14.x 周期虚拟化边界漏洞群对比的辨析**：14.x 周期 10 个虚拟化与隔离子系统 SA（bhyve 5 个、Jail 3 个、**ctl(4)** 2 个）反映 “虚拟化边界即安全边界” 的工程原理，9.x 周期内核子系统漏洞群则反映 “传统内核攻击面” 的工程原理——二者揭示了 FreeBSD 从 “传统单体内核” 向 “虚拟化 + 隔离” 演进过程中攻击面的迁移

## 125.19.7 9.x 周期安全响应文化评估——Security Officer 交接与 MFC 工作流的 SVN 时代尾声

**要点**：9.x 周期 Security Officer 经历三次交接：9.0-RELEASE 时期为 Colin Percival（cperciva@，2005 年起任职），9.1 时期为 Simon Nielsen（simon@），9.2 时期为 Dag-Erling Smørgrav（des@），9.3 时期 Xin LI（delphij@）加入 Security Team；这一密集交接与 2012 年入侵事件后的安全团队扩充直接相关；9.x 全周期（2012.1-2017.1）共发布约 **130 个 SA**（SA-12 至 SA-17 早期），年均约 26 个——与 14.x 周期年均约 27 个节奏接近；**MFC 工作流在 9.x 时期是主要 commit 模式**——freebsd-src 仓库 2012-2014 年 MFC commit 总数达 **7933 个**，反映 SVN 时代 “主分支开发、stable 分支回溯” 的工程范式；2012 年入侵事件后 cvsup 弃用、portsnap/freebsd-update 全面采用，安全响应基础设施加速现代化

**史料**：各版本 Release Announcement Acknowledgments 章节（明确列出 Security Officer 名单）；**freebsd.duckdb** `commits` 表 freebsd-src 仓库 MFC commit 查询：`SELECT count(*) FROM commits WHERE repo_name='freebsd-src' AND author_date>='2012-01-01' AND author_date<'2014-01-01' AND message_subject LIKE 'MFC%'` 结果 7933 条；FreeBSD-SA-12 至 SA-17 早期 SA 总数统计（基于本地 **原材料/研究/bsd漏洞史/官方公告/freebsd-sa.md** Grep `FreeBSD-SA-(12|13|14|15|16|17):` 结果）；FreeBSD Security Officer 历史页面［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

**史观**：社区治理：9.x 周期是 FreeBSD Security Officer 制度成熟的关键时期——Colin Percival 长达 7 年的任期塑造了 FreeBSD 安全响应文化（严格、保守、透明），其继任者 Simon Nielsen、Dag-Erling Smørgrav 延续并扩展了这一传统；Security Officer Team 在 9.x 后期采用 “Officer + Emeritus” 双轨制（前任转为荣誉安全官），保留经验传承；这一治理模式延续至 14.x 周期（Mark Johnston（马克·约翰斯顿）、Philip Paeps（菲利普·佩普斯） 时期）；**MFC 工作流的 SVN 时代尾声**：9.x 是 FreeBSD SVN 时代的最后稳定分支（10.0 发布后逐步向 Git 迁移，2020 年完成 SVN-to-Git 迁移），MFC commit 模式在 9.x 时期达到工程成熟度顶峰

**辨析**：**Security Officer 交接的辨析**：9.x 周期三次 Security Officer 交接（cperciva→simon→des→delphij 加入）部分源于 Colin Percival 在 Tarsnap 等商业项目上的精力分配——这一交接动因需在叙事中明示，避免 “项目内部矛盾” 的误读；**130 个 SA 的辨析**：9.x 全周期约 130 个 SA 与 14.x 周期 80 个 SA 的数量对比需考虑：其一，9.x 周期 5 年，14.x 周期不足 3 年——年均节奏接近；其二，9.x 周期 base 系统包含 BIND、sendmail 等大量第三方组件（10.0 后逐步移除），SA 来源更广；其三，14.x 周期 Security Team 投入更多资源进行主动审计（“audit” 主题），SA 来源更倾向内部审计；**MFC 7933 commit 的辨析**：MFC commit 数量庞大反映 9.x 时期 SVN 工作流的工程负担——每个安全修复需在 HEAD 修复后手动 MFC 至 stable/9，再分别 MFC 至 releng/9.0、releng/9.1 等分支；这一工作流在 Git 时代通过 cherry-pick 与分支合并简化，是 9.x 时期工程范式的特征；**与 14.x 周期对比的辨析**：14.x 周期 Security Officer Mark Johnston 与 Deputy Philip Paeps 的 “主动审计—批量披露” 模式在 9.x 周期已具雏形（2013-09-10 单日 6 SA），但 9.x 周期尚未形成制度化审计流程——这是 Security Officer 制度从 “被动响应” 到 “主动审计” 的演进
