# 134.10.1 RACCT/RCTL 资源审计与限制

**要点**：9.0-RELEASE 新增 RACCT（资源审计）和 RCTL（资源限制）框架，提供比传统 **login.conf(5)** 更细粒度的资源限制能力；RACCT 可按进程、jail、login class 跟踪资源使用，RCTL 允许配置规则在资源使用超过阈值时采取动作（如 SIGXRES 信号发送或进程终止）；**rctl(8)** 是用户态管理工具；RACCT/RCTL 在 9.0 中未默认编译入 GENERIC，需添加内核选项 RACCT/RCTL 并重建世界；核心 commit 为 r220137（RACCT）、r220163（RCTL）

**史料**：svn r220137、r220163 commit、FreeBSD 9.0 Release Notes、**rctl(8)** man page、Edward Napierała（trasz@，主要实现者）邮件列表设计讨论 ［A］

**史观**：软件工程：RACCT/RCTL 填补了 FreeBSD 资源管理的空白——FreeBSD 先前仅有 login.conf 的粗粒度 limits，缺乏 Solaris zones/resource controls 式的细粒度限制；这一框架为 jail 虚拟化（资源隔离）和多用户系统公平性提供了基础设施

**辨析**：RACCT/RCTL 默认不编译的设计反映了 FreeBSD “默认内核最小化” 原则——所有非必需功能都以选项形式提供，由管理员按需定制；到 10.x 时期 RCTL 逐步进入 GENERIC 默认配置

**文献**：FreeBSD 9.0-RELEASE Release Notes（Kernel 章节）；**rctl(8)** man page；Edward Napierała 在 EuroBSDCon 2011 关于 RCTL 的演讲 ［B］
