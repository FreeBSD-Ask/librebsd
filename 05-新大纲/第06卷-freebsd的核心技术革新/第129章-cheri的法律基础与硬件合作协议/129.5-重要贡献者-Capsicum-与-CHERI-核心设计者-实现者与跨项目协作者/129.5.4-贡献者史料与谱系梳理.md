# 129.5.4 贡献者史料与谱系梳理

**要点**：Capsicum/CHERI 贡献者谱系的一手史料包括：各篇顶级会议论文的作者列表（USENIX Security 2010、ISCA 2014、IEEE S&P 2015、ASPLOS 2019 等核心论文）；FreeBSD/CheriBSD 源码仓库的 commit log 作者信息；剑桥大学 CHERI/Capsicum 项目页面的 people 目录；CHERI Alliance 成员公司和机构列表；DARPA/UKRI 资助项目公开信息；FreeBSD 基金会年度报告中的资助记录；二手资料包括：会议演讲中的致谢部分、BSDCan/EuroBSDCon CHERI/Capsicum 演讲的 Q&A、LWN.net 和其他科技媒体的采访报道；Peter G. Neumann 作为 “活档案” 的特殊地位——其在 ACM RISKS Forum 近 40 年的主持工作为计算机安全史提供了宝贵的一手记录

**史料**：核心学术论文作者列表；FreeBSD/CheriBSD Git 提交历史；Cambridge Capsicum/CHERI people 页面；FreeBSD Foundation 年度报告（2012-2025）；DARPA/UKRI 项目公开名单 ［A］

**史观**：总纲第 2 条——历史是形式主义化的非存在〔存疑：原挂“第 3 条——形式主义膨胀”系伪标签，权威表第 3 条为“不存在进步，只有权力再分配”，待主理人审定〕：开源项目贡献者谱系的历史记录依赖版本控制系统和论文作者列表，这两种来源都有局限性：commit log 记录代码提交者但不记录设计讨论者、测试者、bug 报告者；论文作者列表按学术贡献排序但不一定反映工程实现工作量；对历史贡献的完整梳理需要结合邮件列表、会议记录、访谈等多种来源；CHERI 项目有意识地维护技术报告系列和作者信息，其贡献者谱系相比许多其他开源项目更完整

**辨析**：Capsicum/CHERI 发展中 “看不见的贡献者”——代码审查者、测试人员、文档写作者、邮件列表讨论者的贡献很少被正式记录，但对项目成功同样重要；FreeBSD 基金会在 Capsicum 工程化中的资助和项目管理角色常被低估，基金会不仅提供资金，还协调开发进度和代码审查；原模板文献列表中大量无关文献已删除并替换为贡献者相关的权威来源

**文献**：CHERI/Capsicum Core Conference Papers (2010-2025); FreeBSD/CheriBSD Git Commit History. github.com/freebsd/freebsd-src, github.com/CTSRD-CHERI/cheribsd; University of Cambridge. Capsicum/CHERI People Pages. cl.cam.ac.uk; FreeBSD Foundation. Annual Reports (2012-2025). freebsdfoundation.org; Neumann, P. G. (1985-2025). ACM RISKS Forum Archive. catless.ncl.ac.uk/Risks/. ［A］
