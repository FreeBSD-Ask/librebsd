# 343.13.13 收束叙述章——从许可证对立到治理实体的制度化承认（2001–2026）

2001 年 2 月，Matt Dillon 在 linux-mm 逐行讲解 FreeBSD `vm_pageout.c` 的扫描节流与进程换出触发，并坦承 FreeBSD-4.2 期间的 pageout scan laundering 算法把重载性能倒退了一个月——“I fubar'd heavy load performance for a month in FreeBSD-4.2”，这一自陈的失败经验同时构成 Linux 侧 memcg 记账争论的背景素材。同期 Christoph Hellwig 驳回了 Moshe Barr 关于 FreeBSD 与 Linux 2.4 相差 30% 的基准说法，落款极短：“As he has not even documented all the parameters: Ignore him.”——BSD 与 Linux 的分野此时已写在措辞本身

2004 至 2005 年，通用 802.11 栈的双许可提案把 BSD 治理哲学与 Linux 回馈精神推上正面冲突。Jeff Garzik 反驳 Luis R. Rodriguez 兼容 BSD 阵营的说明，理由是“the BSD license goes against the stated spirit of Linux -- contribute back”。Grant Grundler 次年以同类论证反为双许可辩护：“If BSD can thrive with it's license, I don't see why it's a problem for linux”。aic7xxx 驱动的维护权交接成为另一处张力点，署名从 Justin T. Gibbs 迁至 Adaptec 的 Luben Tuikov，补丁上下文仍挂“Dual BSD/GPL”，Christoph Hellwig 立刻追问：“Does Luben plan to actually maintain the driver we have now?”——BSD 血统驱动进入内核树，代价是维护权交接的信任真空

2006 年，Kirill Korotaev 把开销最小的网络隔离方案描述为“The trivial bsdjail style as implemented by Serge”，但 Herbert Poetzl 在同年记录当年的结局是“tried to push a 'jail' implementation into mainline”而被否，Jacques Gelinas 主导的 security contexts 由此止步于主线之外。同年 Alan Cox 在 sys_indirect 接口讨论中把问题定性为跨 Unix 家族标准化：“its a BSD problem, an AIX problem, a Solaris problem and an HPUX problem”，要求方案跨发行版统一——BSD 与 Solaris、HPUX 并列进入 API 治理对话，但治理能力本身仍被拒绝

2012 至 2013 年，BSD 阵营开发者以身份方式进入 Linux 内核链路。Suleiman Souhlal 以 FreeBSD committer 邮箱“Suleiman Souhlal<ssouhlal@FreeBSD.org>”提交 memcg 补丁，KAMEZAWA Hiroyuki 当场以“Please do small start”反对扩大记账范围——理由是内核页多不可回收，系统一旦触及内存限额将陷入不稳定。BSD 身份与 Linux 内核设计的接触点由此成型，但仍停留在补丁署名层面

2018 年 10 月，CoC 补丁是否已生效的争论把 BDFL 效力推到前台。Tony Luck 以反问钉住：“What's magic about the release of 4.19?”“Our benevolent dictator committed that patch. Didn't it take effect as soon as he ran "git push" to make it visible to the world?”被提醒“people usually have to agree”后他补上“Perhaps you should review the meaning of the word "dictator". :-)”。NeilBrown 从权力结构切入，判定现行文档“The current document is upside down”，其意义本应在“curtail, bypass, or redirect the power of the powerful”，而现实是“Linus has all the power. Patches are the currency of the realm”，他认为伤害不在虐待本身而在无力感：“It isn't the abuse so much as the powerlessness associated with it”，并借 petition to caesar 的比喻要求替代补丁通道

2019 年 9 月，TAB 选举改用 Condorcet 电子投票，原制度设计者 Matthew Wilcox 表态：“Condorcet is a superior system and allowing people who can't make it to the conference to vote is beneficial for the legitimacy of the TAB”。选举制度改革从峰会现场投票转向电子计票，是 BDFL 顶端之外的第三层治理装置成形时刻

2023 至 2024 年，OpenBSD 维护者 Theo de Raadt 以 `deraad@openbsd.org` 直接参与 Linux 内核 mseal 系统调用 RFC 讨论，并坚持“Unix system calls must be atomic.”Linus 反驳该论断并不绝对，并举 mlock 等反例；他最终采纳 de Raadt 的命名建议“I do like us starting with just mimmutable(), since it already exists”，该 syscall 最终以 mseal 合入，而 mimmutable 谱系直接来自 OpenBSD——BSD 语义原则在此首次进入 Linux 内核设计顶层讨论

2025 年 2 月，Jakub Kicinski 提交系列补丁“MAINTAINERS: add a general entry for BSD sockets”，Patchwork bot 确认补丁落入 netdev/net.git 主分支——BSD sockets 接口在 MAINTAINERS 中获得独立条目，与 UNIX sockets 和 TCP 并列。2026 年 1 月，Dan Williams 提交的项目连续性文档自注“a follow-up from Maintainer Summit”，内容是“a plan for a plan for navigating events that affect the forward progress of the canonical Linux repository, torvalds/linux.git”——BDFL 继承问题由此从个人层升维至 Linux Foundation 层面

从 2001 年 benchmark 之争、2004 年 802.11 双许可对立、2006 年 jail 被拒，到 2012 年 memcg 邮箱署名、2018 年 CoC 与 dictator 反问、2023 年 mseal 语义对话、2025 年 MAINTAINERS 独立条目、2026 年项目连续性文档，Linux 与 BSD 的关系经历了从许可证对立到治理能力移植受挫、再到设计借鉴与维护者身份渗透、直至治理实体承认的渐进演进；这一演进是渐进式渗透而非一蹴而就的治理改革——直到 2025 年 MAINTAINERS 中 BSD sockets 获得独立条目之前，这一跨治理文化的渗透始终停留在具体场景而非制度层面
