# 334.4.1 FreeBSD 网络栈与 RFC 实现


303.3 **RFC 系列标准遵守史**——IETF RFC（Request for Comments）系列规范是互联网核心协议的权威标准，FreeBSD 网络栈自 4.2BSD（1983 年）继承而来长期作为互联网协议参考实现

  **要点**：FreeBSD 网络栈源自 4.2BSD，长期作为 TCP/IP 协议族参考实现，对 RFC 793（TCP）、RFC 768（UDP）、RFC 791（IP）、RFC 2460（IPv6）等核心 RFC 实现稳健

**史料**：4.2BSD 网络代码、FreeBSD **src/sys/netinet** 与 **src/sys/netinet6** 源码、IETF RFC 历史档案（RFC Editor 官网 rfc-editor.org 2026-07-22 直接访问确认：RFC 1 1969-04-07 Steve Crocker UCLA“Host Software”；RFC 791 1981-09“Internet Protocol”；RFC 793 1981-09“Transmission Control Protocol”；RFC 2460 1998-12 S. Deering Cisco R. Hinden Nokia“Internet Protocol, Version 6 (IPv6) Specification”obsoletes 1883；RFC 8200 2017-07 S. Deering Retired R. Hinden Check Point Software obsoletes 2460 STD 86；RFC 5321 2008-10 J. Klensin“Simple Mail Transfer Protocol”obsoletes 2821 updates 1123）［A］
**史观**：总纲第 25 条——延续与继承，FreeBSD 网络栈是 4.2BSD 实现的直接延续
**辨析**：FreeBSD 是否“完全”实现某个 RFC 需查 rfcindex.xml 与 **src/sys/netinet** 中的注释对照；某些 RFC 在 FreeBSD 中的实现存在已知偏差（如 TCP MD5 signatures）；联网核查结论：大纲引用的 RFC 793/768/791/2460 均经 RFC Editor 原文确认日期与作者；RFC 2460 与 RFC 8200 的替代关系（8200 obsoletes 2460）在两份文档首部互相确认；重要更正：任务描述中将 RFC 7541 标注为“HTTP/2 Push”有误——RFC 7541 实为“HPACK: Header Compression for HTTP/2”，HTTP/2 Server Push 是 RFC 7540（HTTP/2 规范）的特性，已由 RFC 9113（2022-06）替代；任务描述中将 RFC 9000 标注为“HTTP/3”有误——RFC 9000 实为“QUIC: A UDP-Based Multiplexed and Secure Transport”（2021-05, J. Iyengar Fastly, M. Thomson Mozilla），HTTP/3 对应 RFC 9114，详见考据记录 20260722_compliance-standards-fact-check.md
