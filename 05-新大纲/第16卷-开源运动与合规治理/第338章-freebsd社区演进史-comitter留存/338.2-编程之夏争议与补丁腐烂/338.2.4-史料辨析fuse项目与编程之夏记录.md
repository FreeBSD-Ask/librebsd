**要点**：

- Mateusz Piotrowski 在朋友参加招聘会结识 FreeBSD committer 后，以零 BSD 经验经 Google Summer of Code 进入项目，其课题是开发用户态工具将 Linux 审计轨迹转换为 FreeBSD 审计格式。（BSD Now EP470，[165.64-289.86]，L1）
- Piotrowski 在 GSoC 结束后继续留在 FreeBSD，投入文档领域，参与 Wiki 清理与迁移讨论，贡献大量手册页，并曾担任首任 doceng 秘书，负责答复邮件与处理 committer 投票程序。（BSD Now EP470，[671.56-731.52]，L1）
- Piotrowski 以 core team 成员身份说明，core 不应替项目决定具体工程方向，其价值在于协调跨团队事务，如为次要版本构建内核模块的包分支，并在技术问题上信任相应领域的专家。（BSD Now EP470，[1044.58-1400.8]，L1）
- Piotrowski 的硕士研究测量 FreeBSD DTrace 与 Linux eBPF 的跟踪开销，起因是业界普遍宣称跟踪工具零开销，但缺乏系统文献，故以科学方法量化比较两类系统的跟踪成本。（BSD Now EP470，[2091.7-2446.22]，L1）

**史料**：

- Piotrowski 关于 GSoC 期间与 Robert Watson 交换邮件、以及最初经 IRC 联系 Adrian 讨论无线工作的叙述，属当事人一手口述史料。（BSD Now EP470，[379.52-499.0]，L1）
- Piotrowski 自述维护约 150 余个 ports，包括 Ansible、dwm、Folding@home、Nix 包管理器与 Terraform，并说明其先入 ports 再提交的移植路径。（BSD Now EP470，[1682.86-2082.42]，L1）

**史观**：

- 总纲8 本体论上各方平等：Piotrowski 强调文档、ports 与秘书工作同样是开源贡献，不擅编程者也可通过修错字、维护手册页成为有效成员，体现本体论上各方平等的贡献观。（BSD Now EP470，[1660.62-1671.22]，L1）
- 总纲17 证明世界先于解释和改造世界：Piotrowski 以测量先行回应 DTrace 与 eBPF 零开销的业界宣称，未测先论并不成立，呼应证明世界先于解释与改造世界的取向。（BSD Now EP470，[2140.94-2222.9]，L1）

**辨析**：

- 转写称 GSoC 课题是转换 Linux 审计轨迹为 FreeBSD 审计格式，但该项目是否最终并入 FreeBSD 主线尚需核对源码与提交记录。 [考据脚注] 该 GSoC 项目成果是否合入主线需查 FreeBSD 审计子系统提交与 GSoC 归档。（BSD Now EP470，[247.16-312.18]，L4）
- Piotrowski 对 DTrace 与 eBPF 开销比较的方法论细节在访谈中仅部分展开，测量设置与噪声控制的具体方案需以其论文与 EuroBSDCon 演讲为准。 [存疑脚注] 访谈仅述研究意图，量化方法与结论需以正式论文为准。（BSD Now EP470，[2246.5-2393.74]，L4）
