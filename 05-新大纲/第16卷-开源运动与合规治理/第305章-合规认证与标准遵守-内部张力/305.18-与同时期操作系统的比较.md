# 305.18 与同时期操作系统的比较

与同期其他操作系统的合规、认证与标准遵守情况对比——Linux（少数发行版如 Inspur K-UX 通过 UNIX 03 认证、SuSE Linux Enterprise Server 9 通过 CC EAL 4+ 认证、Red Hat Enterprise Linux 通过 FIPS 140-2/140-3 认证（FIPS 140-2 已于 2021 年被 FIPS 140-3 替代）、Linux Foundation 主导 SSDF 自证、各发行版自行申请 FedRAMP ATO）、macOS（通过 UNIX 03 认证自 Mac OS X 11.5 Leopard 起、Apple 持有 FIPS 140-2/140-3 证书、Apple 平台自行满足 HIPAA/SOX/GDPR 合规）、Windows（Windows Server 2003/XP 通过 CC EAL 4+、Windows Server 通过 FIPS 140-2/140-3、Microsoft Azure 通过 FedRAMP High、Microsoft 自行满足 SOX/HIPAA/GDPR）、Solaris（通过 CC EAL 4+、UNIX 03 认证）、AIX（通过 CC EAL 4+、UNIX 03 认证）、HP-UX（通过 CC EAL 4+、UNIX 03 认证）、z/OS（通过 CC EAL 5、UNIX 03 认证）——FreeBSD 在“实际合规但未形式认证”的定位上介于 Linux（部分发行版认证、多数不认证）与 macOS（全面认证）之间，其“实际合规但未形式认证”策略是 FreeBSD Foundation 预算约束与社区“实质重于形式”传统的共同产物

## 305.18.1 Linux/macOS/Windows 认证格局

  **要点**：Linux Inspur K-UX 通过 UNIX 03、SUSE SLES 9 通过 CC EAL 4+、RHEL 通过 FIPS 140-2/140-3；macOS 自 10.5 Leopard 起通过 UNIX 03、Apple 持有 FIPS 140-2/140-3 证书；Windows Server 2003/XP 通过 CC EAL 4+、Azure 通过 FedRAMP High

| ------ | ---------- | --------- | ----------- | --------- |

| Linux（SUSE SLES 9） | - | CC EAL 4+ | - | - |
| Linux（RHEL） | - | - | FIPS 140-2/140-3 | - |

| Windows Server 2003/XP | - | CC EAL 4+ | - | - |
| Microsoft Azure | - | - | - | FedRAMP High |
| FreeBSD | **从未通过** | **从未通过** | **从未持有**（仅作为运行环境被列入） | **不持有**（仅可作为 CSP 底层基础设施） |
| Solaris | 通过 | CC EAL 4+ | - | - |
| AIX | 通过 | CC EAL 4+ | - | - |
| HP-UX | 通过 | CC EAL 4+ | - | - |

**史观**：总纲第 6 条——技术路线分化导致各 OS 认证策略差异
**辨析**：Inspur K-UX 是否仍维持 UNIX 03 认证需查最新 Open Group 数据库（2014 年后疑似失效）；SUSE SLES 9 CC EAL 4+ 认证的具体 EAL 等级与证书号需核实；macOS UNIX 03 认证从哪个版本起需逐一查证；联网核查结论：本节涉及的官方权威数据库（The Open Group UNIX 03 Register、NIST CMVP、Common Criteria Portal、FedRAMP Marketplace）均经 2026-07-22 直接访问确认运作中，但各 OS 具体认证条目需逐一检索数据库进一步核实，详见考据记录 20260722_compliance-standards-fact-check.md
**文献**：The Open Group UNIX 03 Register [EB/OL]. <https://www.opengroup.org/certifications/unix> (2026-07-22 访问)；NIST CMVP Active Modules [EB/OL]. <https://csrc.nist.gov/projects/cryptographic-module-validation-program> (2026-07-22 访问)；Common Criteria Portal Certified Products [EB/OL]. <https://www.commoncriteriaportal.org/> (2026-07-22 访问)；FedRAMP Marketplace [EB/OL]. <https://www.fedramp.gov/> (2026-07-22 访问) ［B］

## 305.18.2 商业 Unix 认证与 FreeBSD 定位演变

  **要点**：Solaris、AIX、HP-UX、z/OS 等商业 Unix 普遍通过 CC EAL 4+/5 与 UNIX 03 认证，FreeBSD 在“实际合规但未形式认证”的定位上介于 Linux 与 macOS 之间
  **史料**：Oracle Solaris 11 CC EAL 4+ 证书、IBM AIX 7 VIOS CC 证书、HP-UX 11i CC 证书、IBM z/OS CC EAL 5 证书［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕
  **史观**：总纲第 16 条——经济周期使商业 Unix 投入认证而 FreeBSD 不投入
  **辨析**：各商业 Unix 的 CC 认证是否仍维持需查 NIAP 与 Common Criteria Portal；z/OS CC EAL 5 是少数 EAL 5+ 评级，证书号需核实
  **文献**：Common Criteria Portal 认证列表；Oracle/IBM/HP 安全认证文档［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］

## 305.18.3 实际合规未形式认证策略辨析

  **要点**：FreeBSD 的“实际合规但未形式认证”策略是 Foundation 预算约束与社区“实质重于形式”传统的共同产物，优势是低成本劣势是企业采用受限
  **史料**：FreeBSD Foundation 年度预算报告、社区邮件列表讨论 ［A］
  **史观**：总纲第 23 条——社区治理与经济约束共同决定合规策略
  **辨析**：策略的实际效果（如是否真的限制企业采用）需查企业采用案例；“实质重于形式”传统的源头需追溯至 CSRG 时代
  **文献**：FreeBSD Foundation Annual Reports；McKusick CSRG 回忆录 ［B］

## 305.18.4 史料辨析：各 OS 认证时间线验证

  **要点**：各 OS 认证时间线需通过 Open Group、NIST CMVP、Common Criteria Portal、FedRAMP Marketplace 等权威数据库逐一验证
  **史料**：Open Group Registries、NIST CMVP Active Modules、Common Criteria Portal Certified Products［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕
  **史观**：总纲第 21 条——密码学与安全认证档案的权威性
  **辨析**：不同数据库的更新频率与覆盖范围差异需明确；认证过期与续期的时间窗口需查证
  **文献**：Open Group Registries；Common Criteria Portal［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
