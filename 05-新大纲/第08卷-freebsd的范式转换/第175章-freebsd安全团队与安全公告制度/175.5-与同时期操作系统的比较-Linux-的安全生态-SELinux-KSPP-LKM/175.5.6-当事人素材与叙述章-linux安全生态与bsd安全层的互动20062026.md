# 175.5.6 当事人素材与叙述章——Linux 安全生态与 BSD 安全层的互动（2006–2026）

2006 年 8 月 Alexey Dobriyan 提交一个 inode 瘦身补丁，首行是一句极简谱系陈述："[BSD security levels are deleted in -mm, assuming this below]"，正文补充 "The only user of i_security, f_security, s_security fields is SELinux, so ifdef them with CONFIG_SECURITY_SELINUX"；BSD 安全等级是 FreeBSD 与 NetBSD 的强制访问控制设施，与 SELinux 同源异路，此句把二者并置于同一删除语境，BSD 侧删掉通用安全层，Linux 侧由 SELinux 独占其结构字段；同期 Crispin Cowan 在 AppArmor FAQ 争论中把 BSD Jail 列为非标签式约束方案，"Many systems besides AppArmor have used non-label schemes for effective confinement: TRON, Janus, LIDS, Systrace, BSD Jail, EROS, PSOS, KeyOS, AS400, to name just a few"，Stephen Smalley 反驳传统意义的 confinement 指信息流控制、AppArmor 并不提供；2010 年 7 月 David P. Quigley 在 NFSD MAC Labeling 补丁中要求两套标签互通，"if we have an SELinux box with an MLS policy and a FreeBSD box with their MLS MAC module"，BSD 的 MAC 框架在 Linux 世界既是竞争对象也是互操作标准；2010 年 10 月 26 日 James Morris 在 IMA 补丁争论中以 BSD secure levels 已被移除为例反驳 Al Viro 对 security/ 子树的贬斥，说明 BSD 谱系代码的删减本身成了 Linux 上游取舍论证的正面证据

2017 年 1 月 20 日 Kees Cook 在 ksummit-discuss 发帖 "security-related TODO items?"，自述 "I've already got various Kernel Self-Protection Project TODO items collected"，并称 "Google's Patch Reward Program is trying to expand by helping create a bounty program for security-related TODOs"，向各维护者征集 security wish-lists，安全从此有了可编号、可悬赏的工作项，Linus 式的一票否决之外多了 Google 式的外部激励；同串中 Andy Lutomirski 提出最激进的自保护形态 "how about rewriting execve() so that the actual binary format parsers run in user mode?"，David Howells 列出 pre-loader 内建映射、ASLR、无栈启动、NOMMU 双模 binfmt、脚本循环安全重算等七点难点，Matthew Wilcox 设想内核地址空间的用户模式执行，Alexey Dobriyan 补上 modules_disabled=1 后 unmap 模块加载器这一具体项

2018 年 9 月 5 日 David Howells 提议将 secure boot 与 kernel lockdown 立为 TECH TOPIC，Jiri Kosina 承认 SUSE 是少数自带非上游 lockdown 补丁集的发行版并自承已忘究竟阻塞何在，Justin Forbes 要求 CONFIG_LOCK_DOWN_IN_EFI_SECURE_BOOT 而非一刀切禁用 BPF，Lutomirski 提出 LOCKDOWN_PROTECT_INTEGRITY 与 LOCKDOWN_PROTECT_SECRECY 分级并主张拆小补丁集先并基础框架；10 月 1 日 debugfs 迁往 sysfs 的讨论中 Greg KH 自陈 "Until about 8 months or so ago, maybe a year, debugfs was totally insecure and it was very trivial to use to crash the kernel"，Shuah 实查发现发行版仍启用 BLK_DEBUG_FS 与 KVM_DEBUG_FS，Jan Kara 要求为现场排障保留 tracepoint，这条争论浓缩两种哲学：Linux 保留危险接口再做安全，BSD 直接不提供

2016 年 8 月 Mickaël Salaün 发布 Landlock LSM RFC v2，目标是 "to allow any process, including unprivileged ones, to create powerful security sandboxes comparable to the Seatbelt/XNU Sandbox or the OpenBSD Pledge"；此后 v14 至 v33 的补丁系列反复写明 "Landlock also takes inspiration from other OS sandbox mechanisms: XNU Sandbox, FreeBSD Capsicum or OpenBSD Pledge/Unveil"；SELinux 需受信用户加载策略且配置复杂，Landlock 则把 seccomp-bpf 补成可表达动态策略的沙箱，其坐标系从 NSA 的 Flask 转向 OpenBSD 的 pledge(2)，做减法的系统成为做加法的内核的设计基准

2014 年 6 月 David Drysdale 的 O_BENEATH 与 execveat 系列交代出身，"Capsicum is a security framework that has been present in FreeBSD since version 9.0 (Jan 2012)"，而该功能 "was originally implemented as part of the internals of the Capsicum security framework, which is available in FreeBSD 10.x"；2019 年 10 月 Aleksa Sarai 的 openat2 复活 Al Viro 的 AT_NO_JUMPS，其语义又源自 O_BENEATH；Ameer Hamza 的 O_EMPTY_PATH 自陈 "it is very similar to the FreeBSD O_EMPTY_PATH flag"，动机是避免为 samba 容器授予 /proc 访问，能力安全这条线自剑桥大学经 FreeBSD 9.0 流入 Linux VFS

2019 年 11 月 Jann Horn 在 clone3 文档评审中转述 "on OpenBSD, they do use MAP_STACK now AFAIK" 与 "they periodically check whether the userspace stack pointer points into a MAP_STACK region, and if not, they kill the process"，Kees Cook 认为仅系统调用入口检查不足以防御 ROP；2023 年 4 月 Andrew Morton 引 mmap(2) 手册承认 "MAP_STACK exists (and has an effect) on some other systems (e.g., some of the BSDs)"，2024 年 5 月 14 日 Linus Torvalds 在同串重复此语；2024 年 2 月 Theo de Raadt 在 mseal 线程点明机制差异 "In OpenBSD, sigaltstack() forces MAP_STACK onto the specified (pre-allocated) region, because on kernel-entry we require the sp register to point to a MAP_STACK region"，随即补一句 "Linux does not have MAP_STACK enforcement (yet)"；同年 10 月 Pedro Falcato 称 "I think this version of mseal() is OpenBSD's mimmutable()"，2026 年 6 月 Li Chen 在进程孵化模板 RFC 中横向调研三家并记 "FreeBSD has P_INEXEC, OpenBSD has PS_INEXEC"，而 Linux 至今无等价标志

GTSM 补丁中 Stephen Hemminger 说明 "This is already implemented the same way in BSD kernels"；David S. Miller 讨论随机临时端口时称 "randomized ephemeral port selection, which OpenBSD implements and we could easily implement as well"；Yoshifuji 论证 IPv6 扩展头默认禁止时称 "FreeBSD does this in the same way"；Hallyn 在网络命名空间争论中反问 "we can all use the network part of the bsdjail lsm"；David Miller 以 "The existing LSM hooks do not break BSD socket behavior" 守护 BSD 套接字兼容性契约；反向判例同样存在，2022 年 7 月 Linus Torvalds 批评 "the traditionally horribly broken BSD model of do SCSI ioctl's using read/write calls was a complete disaster"，Hemminger 评 XDP 示例中成串的 bzero 则笑称 "It looks like you write OpenBSD security code"，并指出只有 BSD 派系用 bzero

三条主线合观：Linux 以 SELinux 为骨架、KSPP 清单与 Google 悬赏为血液、Landlock 为轻量新向，治理方式是保留接口再做安全；BSD 路线是删除不需要的东西、在系统调用入口强制语义、让机制不可绕过；但 Linux 的接口语义大量取自 BSD，Capsicum、O_BENEATH、O_EMPTY_PATH、MAP_STACK、GTSM 与 BSD Jail 皆是；BSD 的遗留也在内核中留痕数十年，Jeff Layton 在 NFSv4 讨论中指出 "the only user of fs_pin is the BSD process accounting subsystem"，acct.c 的清理仍在操作 struct bsd_acct，unix.7 手册把 CVE-1999-1402 记为 Solaris 2.x、SunOS 4.x 与 4.4 之前 BSD-based 系统忽略 socket 权限的历史缺陷；BSD 安全哲学因此在 Linux 中同时充当设计基准与反面教材、兼容性契约与待删遗留
