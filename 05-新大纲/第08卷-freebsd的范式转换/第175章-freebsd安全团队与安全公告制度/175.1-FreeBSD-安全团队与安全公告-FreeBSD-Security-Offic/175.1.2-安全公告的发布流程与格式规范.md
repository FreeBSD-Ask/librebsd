# 175.1.2 安全公告的发布流程与格式规范

**要点**：考察 FreeBSD 安全公告的工程化流程——漏洞报告接收（邮件列表、安全团队专用邮箱）、验证与分析（本地复现、影响范围评估）、补丁开发与测试、协调披露（与上游、其他 BSD、CERT/CC 协调）、公告发布（freebsd-security-announce 邮件列表、官方网站同步更新）；公告采用统一格式（FreeBSD-SA-XX: YY 编号体系），包含问题描述、影响范围、解决方案、workaround、补丁链接等结构化字段

**史料**：FreeBSD Security Advisory 模板、freebsd-security-announce 邮件列表存档、安全公告归档页面、FreeBSD 安全团队工作流程文档、CERT/CC 与 FreeBSD 的协调记录 ［A］

**史观**：专题语（不设总纲条号）——形式与内容的张力（原挂总纲第 3 条系伪名目）：安全公告格式的标准化和流程的制度化是形式主义在安全工程中的体现——每一个字段、每一道流程都是对安全响应过程的形式化规范，确保信息传递的准确性和可追溯性

**辨析**：FreeBSD 安全公告分为 经邮件列表库验证通过——FreeBSD 安全公告制度在 freebsd-announce 列表中确认存在（2025-11-26 FreeBSD-SA-25:10.unbound，Message-ID <20251126200921.CA70018D90@freefall.freebsd.org>）。Security Advisory（安全公告，严重漏洞）和 Errata Notice（勘误通知，非安全相关的重要修复）两类，二者的边界有时存在模糊性——某些漏洞的严重程度评估可能因视角不同而有差异；公告的发布时间点选择也涉及安全伦理考量（立即发布 vs 给用户预留补丁时间）
