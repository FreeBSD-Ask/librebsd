#### 史料

《The Biggest Myths》博客一手来源：`https://0pointer.de/blog/projects/the-biggest-myths.html`（2026-07-22 WebFetch 实测可达）。博客原文关键摘录：

> "Since we first proposed systemd for inclusion in the distributions it has been frequently discussed in many forums, mailing lists and conferences. In these discussions one can often hear certain myths about systemd, that are repeated over and over again, but certainly don‘t gain any truth by constant repetition. Let’s take the time to debunk a few of them:"

反驳“systemd is monolithic”论原文：

> "Myth: systemd is monolithic. If you build systemd with all configuration options enabled you will build 69 individual binaries. These binaries all serve different tasks, and are neatly separated for a number of reasons. ... A package involving 69 individual binaries can hardly be called monolithic. What is different from prior solutions however, is that we ship more components in a single tarball, and maintain them upstream in a single repository with a unified release cycle."

反驳“systemd is about speed”论原文：

> "Myth: systemd is about speed. Yes, systemd is fast (A pretty complete userspace boot-up in ~900ms, anyone?), but that's primarily just a side-effect of doing things right. In fact, we never really sat down and optimized the last tiny bit of performance out of systemd."

反驳“个人主导”论的源码证据：systemd 仓库 contributors 表显示实际有 60,192 位 contributors（`bsd_commits.duckdb` 中 systemd 仓库 contributors 表数据，须注意此数据按 `(author_name, author_email)` 二元组去重）。但 `git shortlog -sn` 默认按 `author_name` 去重，Top 20 中 Poettering 26600 commits 仍占全仓库 90,782 commits 的 29.3%——贡献者数量多与 Poettering 个人贡献占比高二者不矛盾。

CVE 修复 commit 追溯证据：systemd 仓库 `git log --grep="CVE-"` 实测找到 23 个不同 CVE 的修复 commit，前 10 个包括 CVE-2025-45582（`4487153116d2`，2026-04-20）、CVE-2024-3094（`34f29079fdba`，2026-04-02）、CVE-2021-42299（`dbbd87834096`，2024-03-26）、CVE-2024-21626（`a13fb98ba76c`，2024-02-05）、CVE-2023-31438（`e375bc5fcc08`，2023-08-18）、CVE-2023-31439（`3846d3aa292a`，2023-10-06）、CVE-2022-4415（`b76414256592`，2022-12-20）、CVE-2021-4034（`356b1ee1febe`，2022-02-01）、CVE-2021-3997（`921810ea2335`，2021-11-30）、CVE-2021-33910（`884d84cbde1f`，2021-06-23）。23 个 CVE 修复 commit 的存在证明修复响应及时。

FOSDEM 2017 主日程页面 `archive.fosdem.org/2017/schedule/` WebFetch 验证存在，确认 FOSDEM 2017 于 2017-02-04 至 2017-02-05 在布鲁塞尔 ULB Solbosch 校区举办，共 610 位演讲者、669 场活动、55 个 track。但 Poettering 具体演讲页面未定位——FOSDEM 2017 schedule 搜索接口未提供关键词检索，须手动浏览。

#### 史观

项目史观总纲第 7 条“理论必须自反”在本节叙事中具体体现为：Poettering 自身论述亦是形式主义化重构——"A package involving 69 individual binaries can hardly be called monolithic"这一反驳本身是 Poettering 对“模块化”定义的形式主义化重构（将“模块化”等同于“二进制数量多”），但源码分析显示 6 个 `shared_library()` 中 `shared` 库被所有可执行文件链接的事实使 Poettering 的反驳在工程实质层面不成立——Poettering 自身亦在用形式主义标签（“69 个二进制”）对抗形式主义标签（“monolithic”），这是形式主义内部的话语博弈。项目史观总纲第 19 条“解释学循环是根本条件”在此体现为：Poettering 的反驳、批评方的再反驳、源码分析的事实三方构成解释学循环——前理解差异使分歧不可避免，源码物理存在并不自我宣称为“单体”或“模块化”，标签是各主体赋予的。

Poettering 反驳“systemd is about speed”论的原文（"Yes, systemd is fast ... but that's primarily just a side-effect of doing things right."）须谨慎解读——Poettering 在此将“快”重新定义为“做对了的副产品”，这是话语层面的修辞转移，将工程目标从“启动速度”转向“正确性”，但“正确性”本身是不可证伪的修辞，构成项目史观总纲第 11 条“商品是形式主义”的例证。
