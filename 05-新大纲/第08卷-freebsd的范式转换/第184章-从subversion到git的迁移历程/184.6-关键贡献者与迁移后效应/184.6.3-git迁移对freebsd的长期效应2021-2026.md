# 184.6.3 Git 迁移对 FreeBSD 的长期效应（2021-2026）

**要点**：Git 迁移完成五年后（2021-2026），其长期影响已清晰显现：(1) **13.x 系列在 Git 下成熟**——13.0 是部分在 SVN 部分在 Git 下开发的版本，13.1 是首个完全在 Git 工作流下发布的版本，13.x/14.x/15.x 系列均在 Git 下完成开发；(2) **CI/CD 体系完善**——基于 GitLab CI 和 Cirrus CI 的自动化构建测试成为开发流程标配，大幅提升了代码质量和发布效率；(3) **外部贡献增加**——GitHub 镜像的存在降低了新贡献者门槛，通过补丁/PR 参与的外部开发者数量显著增加；(4) **GitLab 代码审查迁移（2023）**——从 Phabricator 迁移到 GitLab 进一步深化了 Git 工作流集成；(5) **与现代开源生态接轨**——年轻开发者无需学习 SVN 即可参与，FreeBSD 在 GitHub 上的曝光度提升；(6) **submodule 用于第三方代码**——LLVM、OpenZFS 等大型第三方代码通过 Git submodule 管理，比 SVN vendor 分支更便捷；SVN 只读镜像至今（2026 年）仍保留供历史查询，但不再用于新开发

  **Git 迁移对 FreeBSD 的长期效应（2021-2026）**：

  | 效应维度 | 具体表现 |
  |---|---|
  | 版本发布 | 13.1 是首个完全在 Git 工作流下发布的版本，13.x/14.x/15.x 系列均在 Git 下完成开发 |
  | CI/CD 体系 | 基于 GitLab CI 和 Cirrus CI 的自动化构建测试成为开发流程标配 |
  | 外部贡献 | GitHub 镜像降低新贡献者门槛，通过补丁/PR 参与的外部开发者数量显著增加 |
  | 代码审查 | 2023 年从 Phabricator 迁移到 GitLab，深化 Git 工作流集成 |
  | 生态接轨 | 年轻开发者无需学习 SVN 即可参与，GitHub 曝光度提升 |
  | 第三方代码管理 | LLVM、OpenZFS 等通过 Git submodule 管理，比 SVN vendor 分支更便捷 |

**史观**：总纲第 4 条——分离聚合是永恒规律〔订正：原挂“总纲第 25 条——终结与延续”系伪标签，权威第 25 条为“逻辑是形式主义而非世界本身的结构”，依核查报告按延续论旨改挂第 4 条〕：Git 迁移不是革命而是延续——FreeBSD 的核心开发文化、committer 制度、发布工程流程、技术自主性原则在 Git 时代全部延续；变化的是工具，不变的是工程哲学

**辨析**：“Git 迁移彻底改变了 FreeBSD 开发模式”是夸大——核心工作流和治理结构保持高度连续；但“Git 迁移只是换了个工具”也低估了其影响——CI/CD 和外部贡献生态的变化是真实而深远的；准确的评价是：Git 迁移是 FreeBSD 现代化转型的关键基础设施升级，为 2020 年代的发展奠定了基础
