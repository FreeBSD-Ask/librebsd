**史料**：FreeBSD Wiki GitTransition Src Schedule；freebsd-current 邮件列表 src 迁移公告；SVN r368820 提交记录；src 仓库“Welcome to Git”首个 Git commit；**freebsd.duckdb** L2.1.FreeBSD_SVN_to_Git_migration 查询（SVN→Git 迁移事件 2020-01-01 前后 12/12 个月 commit 量对比）——查询结果摘要：该查询覆盖 freebsd-src 仓库，以 2020-01-01 为事件分界点，对比迁移前 12 个月（2019-01-01 至 2019-12-31）与迁移后 12 个月（2020-01-01 至 2020-12-31）的 commit 量；查询结果仅返回 1 行——`freebsd-src` 仓库 `after` 期间（2020 年）total_commits = 14,203，month_count = 12，avg_monthly_commits = 1,183.6；`before` 期间（2019 年）数据未在结果中返回（可能因查询参数边界条件或 `datetime()` 函数时区处理导致 before 期间 commit 未被纳入统计）；**L2.1 与 L1.1.1 数据交叉验证异常**：L2.1 查询返回的 2020 年 commit 量 14,203 与 L1.1.1 查询返回的 2020 年总 commit 量 111,482 存在巨大差异（后者为前者的 7.85 倍），此差异远超合理的统计口径差异范围，须警惕以下可能性：(1) L2.1 查询的 `datetime()` 边界条件可能因 SQLite 时区处理或参数传递问题导致大量 commit 被排除；(2) L2.1 查询可能仅统计了部分 commit（如仅 author commits 而非全部 commits），但 14,203 亦远低于 L1.1.1 的 author commits 37,604；(3) L2.1 查询结果可能存在执行时数据不完整或查询逻辑缺陷；0 信任原则局限提示：(1) **L2.1 查询结果可信度存疑**——因 before 期间数据缺失且 after 期间数据与 L1.1.1 严重不符，该查询结果不宜作为 SVN→Git 迁移影响分析的主要依据；(2) 建议以 L1.1.1 查询结果（2019 年总 commit 101,699、2020 年总 commit 111,482）为迁移影响分析的主要数据来源；(3) L2.1 查询的 `datetime(?, 'start of month', ? || ' months')` 函数在 SQLite 中的行为须结合具体参数值验证，可能存在边界条件处理差异；**freebsd.duckdb** L1.1.1 查询（freebsd-src 仓库年度 commit 量时间序列）——查询结果摘要：ch66 关注的 SVN→Git 迁移期（2019-2021）freebsd-src 仓库年度 commit 量数据如下：2019 年 27,943 author commits/77,167 committer commits/101,699 总计、2020 年 37,604 author commits/31,858 committer commits/111,482 总计、2021 年 17,116 author commits/13,768 committer commits/110,661 总计；**迁移前后 commit 量变化分析**：2020 年总 commit 量 111,482 较 2019 年的 101,699 增长 9.6%，与 SVN→Git 迁移后 commit 元数据回填效应一致（迁移脚本将 SVN revision 转换为 Git commit 时可能生成额外 commit 记录）；2021 年总 commit 量 110,661 与 2020 年基本持平，反映 Git 迁移完成后开发活跃度趋于稳定；**committer commit 量异常辨析**：2019 年 committer commit 量 77,167 异常偏高（较 2018 年的 8,904 增长 766%），而 2020 年 committer commit 量 31,858 较 2019 年下降 58.7%——此异常波动须警惕 SVN-to-Git 迁移脚本对 committer 字段的统一替换可能引入的归属偏差，2019 年的 77,167 可能部分源于迁移脚本将多个 SVN revision 的 committer 统一映射为单一 Git committer；0 信任原则局限提示：(1) 2010-2020 年间 commit hash 经 2020 年 SVN-to-Git 迁移重算，author_date 由迁移脚本根据原始 SVN commit 元数据回填，存在日期偏差风险；(2) SVN revision 编号在迁移时部分丢失，r368820 等 SVN revision 编号仅在 commit message 中保留（如“r368820”字样），无法通过 Git hash 直接反查；(3) 迁移脚本对 authors.txt 的映射可能存在遗漏或错误，部分历史 committer 的归属可能不准确；(4) **SVN-to-Git 迁移的特殊风险**：迁移过程中 commit 的 author_date 与 committer_date 均由脚本根据 SVN 元数据生成，与原生 Git commit 的元数据生成机制不同，须警惕迁移生成的 commit 在时间序列分析中的系统性偏差 ［A］
