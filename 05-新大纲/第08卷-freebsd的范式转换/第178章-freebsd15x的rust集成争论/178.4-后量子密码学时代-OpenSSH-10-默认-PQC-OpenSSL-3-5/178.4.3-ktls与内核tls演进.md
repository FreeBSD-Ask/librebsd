# 178.4.3 KTLS 与内核 TLS 演进

**要点**：15.0 中 KTLS（Kernel TLS）持续完善，包括 TLS 1.3 发送/接收双向卸载支持的成熟化；KTLS 允许 TLS 记录层对称加密在内核中完成（通过直接在 socket 层处理），避免用户态-内核态数据拷贝，显著提升高带宽 TLS 连接吞吐量——Netflix 是 KTLS 的主要赞助者与使用者，其 CDN 服务器利用 KTLS 支撑每秒数 TB 级别的视频流量加密；15.0 中 KTLS 与 OpenSSL 3.5 PQC 算法的协作、与 **sendfile(2)** 零拷贝的集成持续优化

**史料**：Netflix KTLS 技术博客；FreeBSD 15.0 Release Notes Kernel Networking 部分；ktls(4) 手册页；John Baldwin（约翰·鲍德温） KTLS 演讲（BSDCan 2023-2025） ［A］

**史观**：边缘者贡献：KTLS 的故事再次证明企业大规模用户反哺开源的模式——Netflix 没有为自己的 CDN 维护一个 FreeBSD 私有分支，而是持续将所有 KTLS 改进贡献回主线；这种 “自用即贡献” 模式使 FreeBSD 在高带宽 TLS 性能上保持领先地位

**辨析**：KTLS 不加密所有连接——应用程序需要显式通过 setsockopt 启用 KTLS（TLS_TX/TLS_RX 选项），OpenSSH、curl、nginx 等用户态程序默认使用用户态 TLS 栈（OpenSSL），除非专门配置使用 KTLS；Netflix 的 CDN 使用自定义 TLS 栈与 KTLS 深度集成

**文献**：FreeBSD Project. ktls(4) Manual Page [EB/OL]. [2026-07-19]. <https://man.freebsd.org/ktls/4>; Baldwin J. Kernel TLS Improvements [C]. BSDCan 2025.
