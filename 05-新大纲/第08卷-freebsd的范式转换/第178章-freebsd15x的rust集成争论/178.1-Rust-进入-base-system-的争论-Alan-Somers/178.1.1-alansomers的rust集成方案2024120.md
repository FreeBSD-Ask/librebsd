# 178.1.1 Alan Somers 的 Rust 集成方案（2024.1.20）

**要点**：2024 年 1 月 20 日，开发者 Alan Somers（asomers@，Google 工程师、FreeBSD 文件系统与存储子系统长期贡献者）在 freebsd-hackers@ 邮件列表发布 “The Case for Rust (in the base system)” 一文，正式提出将 Rust 编程语言引入 FreeBSD 基本系统的方案；Somers 指出：Rust 的内存安全特性可以消除 C/C++ 代码中大量的内存安全漏洞（据 Google/MSRC 统计约 70% 的安全漏洞源于内存安全问题）；FreeBSD 已在 Ports 中支持 Rust，但 base system 中引入 Rust 工具链允许用 Rust 重写/新写安全关键组件（如用户态工具、新驱动、文件系统工具等）；Somers 承认主要缺点是构建时间将加倍（Rust 编译器编译较慢），但认为安全收益超过成本

  **Somers Rust 集成方案优缺点对照**：

  | 维度 | 优势 | 劣势 |
  |---|---|---|
  | 内存安全 | 消除 C/C++ 约 70% 安全漏洞（Google/MSRC 统计） | - |
  | 构建时间 | - | Rust 编译器编译较慢，构建时间将加倍 |
  | 工具链 | - | Rust 工具链体积庞大（数百 MB） |
  | 渐进范围 | 先引入工具链，再允许 Rust 编写新用户态工具 | 内核 Rust 支持是远期可能性 |

**史料**：Alan Somers 2024.1.20 邮件原文 “The Case for Rust (in the base system)”（<https://lists.freebsd.org/archives/freebsd-hackers/2024-January/002823.html>）；LWN 2024.8.19 报道 “FreeBSD considers Rust in the base system”（<https://lwn.net/Articles/985210/>）；Rust 编程语言官方文档；Google/MSRC 内存安全漏洞统计报告 ［A］

**史观**：专题语（不设条号）——软件工程：Rust 进入 base 的争论本质上是 “工程安全性” 与 “工程简洁性” 的权衡——C 语言是 FreeBSD 30 多年来的基石，C 编译器与工具链相对简单、构建快速、跨平台支持好；Rust 带来内存安全但增加工具链复杂度与构建时间；Linux 内核自 6.1（2022.12）开始接受 Rust 代码但标记为实验性，为 BSD 社区提供了参考案例（原“总纲第 17 条”标号与基线第 17 条“证明世界先于解释和改造世界”不符，按 R2140 先例改不设条号专题语——批次 C275 问题 1）

**辨析**：Somers 提案并非要求 “用 Rust 重写整个 FreeBSD” 或 “内核立即接受 Rust 代码”——提案范围非常渐进：首先引入 Rust 工具链到 base（作为 ports 之外的基本系统组件），然后允许用 Rust 编写新的用户态工具（如 nfsd、bhyve userspace 组件等），内核 Rust 支持是更遥远的可能性；截至 2026.7，**Rust 尚未进入 FreeBSD base system**——提案仍处于讨论阶段，未形成 Core Team 决议。经邮件列表库验证通过（来源：freebsd-hackers 列表，Message-ID <CAOtMX2hAUiWdGPtpaCJLPZB+j2yzNw5DSjUmkwTi++myemehCA@mail.gmail.com>，2024-01-20，发件人 Alan Somers <asomers@freebsd.org>，主题“The Case for Rust (in the base system)”，同线程含 Gleb Popov、Dimitry Andric、Antranig Vartanian、George Mitchell 等多方回复）
