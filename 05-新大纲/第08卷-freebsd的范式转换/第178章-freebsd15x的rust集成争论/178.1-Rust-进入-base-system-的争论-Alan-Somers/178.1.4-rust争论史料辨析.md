**史观**：专题语（不设条号）——社区治理：Rust 争论的 “漫长但有序” 本身就是 FreeBSD 社区治理成熟的标志——没有 Core Team 强行推进或禁止，而是通过公开邮件列表讨论、会议 BOF、代码实验（如果有人做原型）形成共识；这与 1990-2000 年代 GCC vs EGCS、sendmail vs postfix、SysV init vs rc.d 等历史争论的处理方式一致（原“总纲第 23 条”标号与基线第 23 条“一切历史写作都是基于哲学设定的历史小说”不符，按 R2140 先例改不设条号专题语——批次 C275 问题 1）

**辨析**：需要区分 “邮件列表讨论热度” 与 “实际工程进展”——Rust 争论在邮件列表中持续了两年多，但这期间没有任何 Rust 代码被提交到 base，也没有 Core Team 决议要求或禁止 Rust；这种 “多讨论、少行动” 的模式在 FreeBSD 历史上并不罕见（如 ZFS 从讨论到正式进入 base 也经历了多年）
