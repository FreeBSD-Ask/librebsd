# 180.2.6 实验性 CHERI、WireGuard 回归与 Wayland 引入的安全债务——新代码与新攻击面

**要点**：15.x 周期的三个实验性或新引入子系统带来新的安全债务——① **实验性 CHERI 支持**：CHERI（Capability Hardware Enhanced RISC Instructions）是剑桥大学与 SRI International 的硬件 capability 模型，15.x 在 arm64 上提供实验性 CHERI 支持（Morello 架构）；CHERI 的硬件 capability 在概念上与 Capsicum 软件 capability 互补，但实验性状态意味着代码成熟度低于生产子系统；② **WireGuard 真正回归**：WireGuard 在 14.x 周期因内核 API 变更被移除，15.x 周期重新引入——新引入的 **if_wg(4)** 代码需重新审计；③ **Wayland 实验性支持**：15.x 引入 Wayland 实验性支持，新增 wayland-protocols、wlroots 相关代码——图形栈新代码带来新攻击面；这三个子系统的共同特征是 “实验性”——尚未被 Security Team 全面审计，可能在后续周期暴露漏洞；同期 iconv 漏洞集中修复（CVE-2026-58081/58082，Taylor R Campbell 与 Mark Johnston，**2026 年 6 月 22 日至 23 日**，共约 21 个 commit）反映 base 系统中 “被忽视的老代码” 也是安全债务来源——iconv 自 5.x 引入，多字节编码转换逻辑长期未审计

  **15.x 周期实验性/新引入子系统安全债务**：

  | 子系统 | 状态 | 安全审计状态 | 攻击面 |
  |---|---|---|---|
  | CHERI（arm64/Morello） | 实验性 | 未全面审计 | 仅限 Morello 硬件，普通用户不受影响 |
  | WireGuard（**if_wg(4)**） | 回归引入 | 需重新审计 | 网络栈（新实现） |
  | Wayland | 实验性 | 未全面审计 | 图形栈（仅开发库，无合成器） |
  | iconv | 遗留代码 | 集中修复（CVE-2026-58081/58082） | 多字节编码转换缓冲区溢出 |

**史观**：总纲第 7 条——硬件与软件辩证：CHERI 是 “硬件辅助 capability” 路线，Capsicum 是 “软件 capability” 路线——15.x 同时探索两条路线，是 FreeBSD 在内存安全领域的双重押注；CHERI 的硬件 capability 可在编译期与运行时捕获内存错误，理论上可消除 C 语言的大部分内存安全 bug，但要求重新编译所有用户态代码（CHERI ABI 与传统 ABI 不兼容）；WireGuard 回归与 Wayland 引入反映 15.x 在网络栈与图形栈的现代化——但新代码的安全成熟度需要时间验证；iconv 漏洞集中修复反映 “base 系统中的遗留代码” 也是安全债务——编码转换逻辑长期未审计

**辨析**：**需严格区分实验性子系统的安全状态**：① CHERI 支持在 15.x 中是实验性（experimental），不默认启用，仅限 Morello 硬件——CHERI 相关漏洞不会影响普通 amd64/arm64 用户；② WireGuard 回归后的代码是全新实现（非 13.x 时代的 **if_wg(4)**），需独立审计——15.x 周期 freebsd-src 仓库中未见 WireGuard 相关 CVE commit，但这可能因审计尚未开始而非代码安全；③ Wayland 支持在 15.x 中是实验性，base 系统不包含 Wayland 合成器，仅提供开发库——攻击面有限；**iconv 漏洞的性质**：CVE-2026-58081（HZ 编码缓冲区溢出）与 CVE-2026-58082（ISO-2022 栈缓冲区溢出）是多字节编码转换的典型 bug——**iconv(3)** 处理变长编码时易出现缓冲区溢出，与 64-bit time_t 过渡无直接关系
