**史观**：总纲第 23 条——社区治理：15.x 周期加密栈 CVE 处理延续 14.x 周期的 “贡献组件治理制度化” 模式——OpenSSL vendor import 节奏化（3.5.5 → 3.0.20 → 后续版本）、expat 多版本跟进、krb5/ldns/unbound/xz 同步修复；Gordon Tetlow 作为 Security Officer 主导 OpenSSL 批量修复，体现 Security Team 的 “集中清算” 工作模式；与 14.x 周期不同的是，15.x 周期 OpenSSL 已进入 3.5 时代（PQC 原生支持），加密栈 CVE 处理从 “代际迁移带来的新 CVE 清算” 转向 “成熟版本的持续维护”

**辨析**：**需区分 OpenSSL 3.5 与 3.0 的关系**：OpenSSL 3.5 是 3.0 的后续 LTS 版本，15.0 搭载 3.5.4/3.5.5，但 14.x 仍使用 3.0.x——两个版本系列的 CVE 有重叠但不完全相同；版本周期文件中同时出现 OpenSSL 3.5.5 与 3.0.20 的 vendor import，反映 main 分支与 stable/14 的 OpenSSL 版本不同步；**krb5 NegoEx 漏洞的辨析**：CVE-2026-40355/40356 是 MIT Kerberos 上游漏洞（NegoEx 协议解析），FreeBSD 通过 Heimdal 的 krb5 兼容层受影响，Cy Schubert 的修复同步自上游 MIT Kerberos 补丁——这反映 Heimdal 与 MIT Kerberos 在 CVE 修复上的同步关系；**xz 5.8.3 的背景**：15.x 周期的 xz 升级至 5.8.3 是 14.x 周期 xz 后门事件（CVE-2024-3094）后的版本跟进，CVE-2026-34743 是普通软件漏洞而非供应链攻击
