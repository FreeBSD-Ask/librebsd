# 182.1.2 Rust 进 base 系统讨论进展

**要点**：FreeBSD 社区自 2024 年初开始讨论 Rust 编程语言进入 base system 的可能性，Alan Somers 等开发者发起相关讨论；截至 2026 年 7 月，Rust 主要通过 ports 提供（ports/lang/rust，2026Q1 版本为 1.94.0），是否以及何时进入 base system 仍在社区讨论和评估中，尚未有正式的合入时间表；讨论中的主要顾虑包括：构建时间显著增加（需编译 rustc 及相关组件）、Rust 快速发布周期与 FreeBSD base 系统稳定性要求的协调、Rust 对 LLVM 的依赖与现有 LLVM 工具链的集成等；Linux 内核已开始接受 Rust 编写的内核模块，这一趋势也影响着 FreeBSD 社区的讨论

**史料**：freebsd-hackers 邮件列表 2024 年 1 月 Rust in base 讨论线程（lists.freebsd.org/archives/freebsd-hackers/2024-January/002823.html）、Ports Collection 2026Q1 状态报告（Rust 1.94.0）、Alan Somers 等开发者的相关提案和讨论、Linux Kernel Rust 支持进展（作为外部参照） ［A］

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧〔存疑：原挂总纲第 6 条系伪标签，依核查报告改挂第 21 条，语境适配未经总纲原文逐字复核〕：Rust 是否进入 base 系统的讨论反映了 FreeBSD 工程哲学中“稳定保守”与“拥抱新技术”之间的张力；Linux 选择相对激进地引入 Rust，FreeBSD 则采取更为谨慎的评估路径，这一分歧与两个项目的治理模式和用户基础差异相关

**辨析**：截至 2026 年 7 月，Rust 尚未进入 base system，所有相关讨论均为社区讨论性质，不应表述为“FreeBSD 16 将包含 Rust”；Rust for kernel modules 的进展（如果有）同样属于实验或讨论阶段；将 Rust 纳入 base 会显著增加构建时间和系统复杂性，这一决策需要核心团队达成共识，短期内（16.0 周期）可能性较低
