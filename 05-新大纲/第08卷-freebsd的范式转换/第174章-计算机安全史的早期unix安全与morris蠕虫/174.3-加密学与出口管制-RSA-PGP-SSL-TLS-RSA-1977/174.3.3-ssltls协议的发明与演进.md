# 174.3.3 SSL/TLS 协议的发明与演进

**要点**：梳理 SSL/TLS 协议的发展脉络——Netscape 1994 年开发 SSL 1.0（内部版）和 SSL 2.0（首个公开发布版），1996 年 SSL 3.0；1999 年 IETF 标准化为 TLS 1.0（RFC 2246）；此后历经 TLS 1.1（2006）、TLS 1.2（2008）、TLS 1.3（2018，RFC 8446）；FreeBSD 基本系统通过 OpenSSL 提供 TLS 支持，2014 年后出现 LibreSSL fork（OpenBSD 主导）

  **SSL/TLS 协议演进时间线（1994-2018）**：

  | 协议版本 | 年份 | 标准化机构 | 关键 RFC | 特点与历史地位 |
  |---|---|---|---|---|
  | SSL 1.0（内部版） | 1994 | Netscape | — | 从未公开发布 |
  | SSL 2.0 | 1994 | Netscape | — | 首个公开发布版，存在严重安全缺陷 |
  | SSL 3.0 | 1996 | Netscape | — | 重新设计，奠定 TLS 基础 |
  | TLS 1.0 | 1999 | IETF | RFC 2246 | 标准化起点，SSL → TLS 转名 |
  | TLS 1.1 | 2006 | IETF | RFC 4346 | 修复 CBC 攻击弱点 |
  | TLS 1.2 | 2008 | IETF | RFC 5246 | 引入 AEAD 加密模式 |
  | TLS 1.3 | 2018 | IETF | RFC 8446 | 大幅简化握手、移除弱算法 |

**史料**：RFC 2246 / RFC 5246 / RFC 8446、Netscape Communications 历史文档、OpenBSD LibreSSL 发布公告（2014 年 4 月，OpenBSD 5.6 起替换 OpenSSL）、FreeBSD 基本系统中 OpenSSL 更新历史、Heartbleed（CVE-2014-0160）事件记录〔L3 官方文档与公告〕

**史观**：终结与延续：SSL/TLS 从 Netscape 的商业产品演变为 IETF 开放标准，从早期脆弱的 SSL 2.0 发展到高度优化的 TLS 1.3，既是加密技术的延续，也是安全工程实践不断进化的结果

**辨析**：LibreSSL fork 事件（2014 年 Heartbleed 后）是安全工程路线分歧的典型案例——OpenBSD 团队认为 OpenSSL 代码质量差、过度工程化，选择 fork 并大规模清理；FreeBSD 选择继续使用 OpenSSL 但加强本地安全加固；不同选择反映了不同项目的风险偏好和工程哲学

**文献**：IETF. (2018). *RFC 8446 - The Transport Layer Security (TLS) Protocol Version 1.3*; OpenBSD Project. (2014). *LibreSSL - Release of OpenBSD's fork of OpenSSL*. openbsd.org/56.html; Durumeric, Z. et al. (2014). *The Matter of Heartbleed*. IMC '14
