# 264.3.3 总纲10动手者创造历史Sanchez作为Darwin开源初期的核心工程师其博客记

- 总纲 10“动手者创造历史”：Sanchez 作为 Darwin 开源初期的核心工程师，其博客记录了“动手者”如何在 NeXTSTEP 遗产与开源社区之间搭建工程桥梁。据第 14 章 14.2 节原文“真正的问题不在于技术发展的程度，而在于是否动手……无论什么时候街道总是需要人去扫”，Sanchez 详述 Darwin 的 build 系统与源码发布流程的具体工程工作，是“动手去做”的实践。但需自反地看待：Sanchez 作为 Apple Darwin 团队工程师的立场（字段 3 已审查）使其对 APSL 许可证的描述带有 Apple 雇员立场，“动手者”不可等同于“商业公司工程师”——Sanchez 既是工程师也是 Apple 利益相关者，此辩证性需保留。
- 总纲 8“本体论上各方平等”：Apple 内部团队与外部贡献者在 Darwin 开源协作中本体平等——Apple 内部团队维护 build 系统与源码发布，外部贡献者通过 darwinos mailing list 参与协作，二者在本体论上无主次之分。据第 25 章总纲 8 原文“FreeBSD、OpenBSD、NetBSD、DragonFly BSD 在本体论上地位相等，差异仅是一刻状态的不同。文档与代码本体平等”，Apple 内部团队与外部贡献者的关系亦应作此本体论平等的看待——不可因 Apple 雇佣关系而将内部团队视为“主导”、外部贡献者视为“附属”，此为本体论上的形式主义化偏见。
- 总纲 2“历史是形式主义化的非存在”：APSL 1.0 作为“理想形式”在社区争议中部分消解。据第 25 章总纲 2 原文“历史是形式主义化的非存在。本书所写皆是当下主体的重构，从不宣称呈现历史本身”，APSL 1.0 的“通知变更”条款在 BSD 社区争议中部分消解（FSF 批评、后续修订为 APSL 2.0）——但需辨析：项目统摄史观批评的是“形式主义”而非“许可证条款”，许可证条款本身是动手者的具体实践，不可将二者混淆为同一对象。
- 总纲 13“法律与道德是利益分配”：APSL 许可证争议本质上是利益分配问题，而非纯粹的道德问题。据第 25 章总纲 13 原文“任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”，BSD 社区对 APSL 1.0 的批评（“通知变更”条款不够自由）本质上是 Apple 商业利益与 BSD 社区自由软件利益之间的分配争议——但需注意项目统摄史观批评的是“道德即利益分配”这一形式主义，而非否定许可证争议本身的意义。
- 总纲 22“知识注定过时”：Darwin 的 pbxbuild 工具链与 APSL 1.0 许可证在后续 macOS 演进中逐渐被 xcodebuild 与 APSL 2.0 取代。据第 25 章总纲 22 原文“今天书写的技术史，可能在出版之日就已过时。技术债务是历史遗产”，2001 年的 pbxbuild 与 APSL 1.0 至 2024 年已过时，但其工程思想以演化形式保存于 xcodebuild 与 APSL 2.0——过时的是知识的特定形式主义化形态，而非 build 系统或许可证本身。
- 总纲 14“苦难不值得被提倡”：Sanchez 博客中描述的 Apple 内部团队适应公开协作的“艰难”不应被提倡为苦难哲学。据第 25 章总纲 14 原文“苦难哲学是既得利益者对权力再分配的拒绝。BSD 的长期主义不是苦难哲学，而是对人类有限性的诚实承认”，Apple 内部团队适应公开邮件列表的工程调整是动手者的具体实践，不应被浪漫化为“开源协作的苦难”——项目统摄史观批评的是“苦难哲学”这一形式主义，而非否定工程调整本身。
