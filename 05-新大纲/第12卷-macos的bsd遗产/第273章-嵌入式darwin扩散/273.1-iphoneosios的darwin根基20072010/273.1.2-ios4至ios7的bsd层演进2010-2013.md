# 273.1.2 iOS 4 至 iOS 7 的 BSD 层演进（2010-2013）

**要点**：iPhone OS 于 **2010 年 6 月 21 日** 随 iOS 4.0（iPhone OS 4）更名，iOS 之名正式启用。**iOS 4** 引入多任务（伪多任务，限定 API 后台执行）、FaceTime（基于 SIP 协议，底层 BSD socket）；**iOS 5**（**2011 年 10 月 12 日** 发布）引入 iCloud 与通知中心，底层 BSD socket 与推送通知服务集成；**iOS 6**（**2012 年 9 月 19 日** 发布）移除 Google Maps 改用 Apple Maps，BSD 层的网络栈承担新的地图数据加载；**iOS 7**（**2013 年 9 月 18 日** 发布）全面重设计用户界面，底层 XNU 升级至支持 64 位 ARMv8（随 iPhone 5s A7 芯片首发），此为 Darwin 在移动端的首次 64 位迁移。BSD 层的 `mmap`、`mprotect` 等系统调用为 64 位地址空间管理提供支持。

  | iOS 版本 | 发布日期 | 主要功能 | BSD 层关联 |
  | --- | --- | --- | --- |
  | **iOS 4** | 2010-06-21 | 多任务（伪）、FaceTime | BSD socket（SIP 协议） |
  | **iOS 5** | 2011-10-12 | iCloud、通知中心 | BSD socket + 推送通知 |
  | **iOS 6** | 2012-09-19 | Apple Maps | BSD 网络栈（地图数据加载） |
  | **iOS 7** | 2013-09-18 | 64 位 ARMv8 支持（iPhone 5s A7） | `mmap`/`mprotect` 64 位地址空间 |

  > iOS 4 的 “多任务” 是 API 限制的伪多任务（仅音频、VoIP、定位等特定 API 可后台执行），非 BSD 进程调度的完整多任务——BSD 层的 `fork`、`exec`、`sched_*` 系统调用本身支持完整多任务，iOS 在其上施加了策略限制。

**史观**：终结中的延续。BSD 核心在移动端延续——iPhone OS 至 iOS 7 的 6 年间，BSD 层未因移动设备资源受限而消失，反而随 64 位迁移扩展其能力。此即项目史观总纲第二十五章的显现：BSD 代码的 “终结”（被 Apple 品牌化）反而成为其在移动端的 “延续” 起点。q.md “数字墓地” 在此显现：iOS 的 BSD 层对普通用户完全不可见，但通过越狱或开发者工具可访问——BSD 层成为 “沉默的数字墓地”，存在但不被言说。

**辨析**：iOS 的多任务实现与桌面 BSD 的多任务实现存在根本差异——iOS 4 的 “多任务” 是 API 限制的伪多任务（仅音频、VoIP、定位等特定 API 可后台执行），非 BSD 进程调度的完整多任务。此差异是 Apple 的工程选择（省电与安全），非 BSD 层的技术限制——BSD 层的 `fork`、`exec`、`sched_*` 系统调用本身支持完整多任务，iOS 在其上施加了策略限制。此判断基于 iOS 4 SDK 文档对后台执行 API 的明确限制描述。

**文献**：Apple Inc. iOS 4 Software Update [EB/OL]. (2010-06-21). Apple Press Release; Apple Inc. iOS Application Programming Guide [Z]. Apple Developer Documentation, 2010-2013; Apple Inc. iPhone 5s Technical Specifications [EB/OL]. (2013-09-10). Apple Press Release.
