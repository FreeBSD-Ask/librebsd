# 269.2.2 反批评层——BSD 许可证允许此模式与 Apple 的实质性回馈

**要点**：BSD 阵营与 Apple 工程师对“无薪员工”批判提出反驳，论证分三支。其一，许可证契约层面——BSD 许可证条款明确允许商业使用、修改、再发布而无强制回馈义务，FreeBSD 社区选择 BSD 许可证即是选择此契约模式，批判 Apple 不回馈等同于否认 BSD 许可证契约本身。**Marshall Kirk McKusick** 的公开表述“BSD 许可证就是一个复制中心，可以为所欲为，但我们不在乎”即此反驳的典型——McKusick 作为 4.3BSD/4.4BSD 与 FreeBSD 的深度参与者，其表态反映 BSD 核心开发者对“被利用但不被回馈”现象的契约主义立场。**John Baldwin** 亦明言“我不会因此而责怪他们。FreeBSD 是一个 BSD 许可的项目，而不是 GPL”——此表态将批判的合法性从道德层面收回法律层面。其二，Apple 的实质性回馈——Apple 于 **2000 年 4 月 5 日** 发布 Darwin 1.0 开源版本（APSL 1.0，2003 年 APSL 2.0 修订），通过 **opensource.apple.com** 持续发布 Darwin 源代码，包括 xnu 内核（Snow Leopard 时代为 xnu-1504 系列）、libsyscall、Libc、Libinfo、networkextensions 等 FreeBSD 用户空间代码的 fork 与演化版本——此即 Apple 对 BSD 社区的“源代码公开”回馈，虽以 APSL 2.0 而非 BSD 许可证发布，但满足自由软件标准。**Free Software Foundation** 在 APSL 2.0 评估中明言"APSL 2.0 qualifies as a free software license. Apple's lawyers worked with the FSF to produce a license that would qualify"——此即 FSF 对 APSL 2.0 自由软件资格的官方背书。其三，Apple 聘用 FreeBSD 创始人 **Jordan Hubbard**（2001 年加入 Apple 任 Darwin 项目负责人）本身即构成 BSD 与 Apple 的人才流动——Hubbard 在 Apple 推动 Darwin 与 FreeBSD 的代码同步工作，使 FreeBSD 部分改进通过 Hubbard 的中介回流至 FreeBSD 社区。Snow Leopard 时代 Apple 以 Apache 2.0 开源 libdispatch（详见 113.1.1）是此回馈模式的延续——Apache 2.0 与 BSD 兼容使 FreeBSD 可无障碍移植。
