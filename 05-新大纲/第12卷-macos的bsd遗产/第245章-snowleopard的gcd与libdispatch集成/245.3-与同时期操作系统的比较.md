# 245.3 与同时期操作系统的比较

## 245.3.1 Snow Leopard 对比 FreeBSD 8.0、Linux 2.6.30、Windows 7

**要点**：**2009 年** Snow Leopard 对比 **FreeBSD 8.0**（**2009 年 11 月 25 日** 发布）、**Linux 2.6.30**（**2009 年 6 月 9 日** 发布）、**Windows 7**（**2009 年 10 月 22 日** 发布），其 GCD 并发模型领先同期桌面 OS。FreeBSD 8.0 的并发模型以 `pthread` 与 `kqueue`/`kevent` 为基础，未引入类似 GCD 的任务队列抽象。Linux 2.6.30 的并发模型以 NPTL（Native POSIX Thread Library）与 `epoll` 为基础，亦未引入任务队列抽象——Linux 在 2010 年后才通过 `libgomp`（OpenMP）与 `TBB`（Threading Building Blocks）提供类似抽象。Windows 7 的并发模型以 Win32 线程池与 .NET TPL（Task Parallel Library，2010 年 .NET 4.0 引入）为基础，与 OS X 的 GCD 对比鲜明。

  | 操作系统 | 发布时间 | 并发模型 | 任务队列抽象 | 后续演进 |
  | --- | --- | --- | --- | --- |
  | **Mac OS X 10.6 Snow Leopard** | 2009-08-28 | GCD + libdispatch | 有 | 至 2024 年仍在 macOS |
  | **FreeBSD 8.0** | 2009-11-25 | `pthread` + `kqueue`/`kevent` | 无（libdispatch 后移植） | libdispatch 后通过 ports 移植 |
  | **Linux 2.6.30** | 2009-06-09 | NPTL + `epoll` | 无 | 2010 年后 `libgomp`/`TBB` |
  | **Windows 7** | 2009-10-22 | Win32 线程池 | 无 | .NET 4.0 TPL（2010） |

  > GCD 通过 libdispatch 移植间接影响 FreeBSD 用户空间并发工具，但未改变 FreeBSD 内核并发模型——FreeBSD 内核的并发模型仍以 `pthread` 与 `kqueue`/`kevent` 为基础。

(2009-06-09). <https://www.kernel.org/>；Microsoft. Windows 7 Launch [EB/OL]. (2009-10-22). Microsoft Press Release；Microsoft. .NET 4.0 TPL Documentation [EB/OL]. (2010). Microsoft Developer Network。〔L3 官方文档与公告〕

**史观**：总纲第 6 条——主体性与和解。OS X、FreeBSD、Linux、Windows 在并发模型选择上是 “主体性” 的显现——此即项目史观总纲第六章的具体呈现：OS X 选择 GCD（任务队列抽象），FreeBSD/Linux 选择 `pthread`+`kqueue`/`epoll`（事件驱动），Windows 选择线程池+TPL——四者共享 POSIX/Unix 哲学的根基但发展出不同的并发模型主体性。

**辨析**：GCD 与 FreeBSD 的并发演进存在间接影响——libdispatch 开源后 FreeBSD 移植使 FreeBSD 用户得以使用 GCD 的任务队列抽象，但 FreeBSD 内核的并发模型未因此改变（仍以 `pthread` 与 `kqueue`/`kevent` 为基础）。采信 “GCD 通过 libdispatch 移植间接影响 FreeBSD 用户空间并发工具，但未改变 FreeBSD 内核并发模型” 的判断。
