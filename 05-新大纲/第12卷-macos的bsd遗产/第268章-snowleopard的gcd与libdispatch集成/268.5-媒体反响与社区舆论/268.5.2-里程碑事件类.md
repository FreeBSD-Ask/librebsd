# 268.5.2 里程碑事件类

### 新闻条目 1

- **新闻标题（中英）**：Gatekeeper introduced in OS X Mountain Lion / Gatekeeper 引入 OS X Mountain Lion
- **新闻来源**：Apple 开发者文档 + 2012-02-16（Mountain Lion 预览发布）+ <https://developer.apple.com/documentation/security/notarizing_macos_software_before_distributing_it> + 存档：<https://web.archive.org/web/2012/https://developer.apple.com/library/mac/technotes/tn2206/>
- **新闻摘要**：Apple 于 2012 年 2 月发布 OS X Mountain Lion 预览版时引入 Gatekeeper 安全机制。Gatekeeper 强制对从互联网下载的应用程序进行代码签名验证，根据开发者签名状态决定是否允许运行。Gatekeeper 提供三档安全级别：Mac App Store 仅允许 App Store 应用、Mac App Store and Identified Developers 允许 App Store 与签名开发者应用、Anywhere 允许任意来源应用。Gatekeeper 通过 quarantine 扩展属性标记下载文件，首次运行时触发验证。Gatekeeper 是 Apple 应对 macOS 恶意软件增长的关键举措，但保留用户降级至 Anywhere 的灵活性。

### 新闻条目 2

- **新闻标题（中英）**：System Integrity Protection introduced in OS X El Capitan / 系统完整性保护引入 OS X El Capitan
- **新闻来源**：Apple 开发者文档 + 2015-06-08（WWDC 2015）+ <https://developer.apple.com/documentation/security/disabling_and_enabling_system_integrity_protection> + 存档：<https://web.archive.org/web/2015/https://developer.apple.com/library/prerelease/mac/security/Introduction_to_Security/>
- **新闻摘要**：Apple 于 WWDC 2015 发布 OS X El Capitan 时引入 System Integrity Protection（SIP，又称 Rootless）。SIP 通过内核级强制保护系统目录（/System、/usr、/bin、/sbin）与系统进程，即使 root 用户也无法修改受保护路径。SIP 限制：root 用户无法修改受保护系统目录、无法加载未签名内核扩展（kext）、无法调试系统进程、无法直接访问其他系统进程内存。SIP 可通过恢复模式关闭，但 Apple 强烈不建议。SIP 引入后，传统需修改系统文件的工具（如 Homebrew 的部分操作、Clover 黑苹果引导）需调整工作方式。SIP 是 Apple 应对 root 级恶意软件的关键举措，标志着 macOS 安全模型从基于用户信任转向基于系统强制。
