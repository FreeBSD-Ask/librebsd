# 267.3.1 64 位内核过渡与 DTrace 引入

**要点**：**Mac OS X 10.5 Leopard** 引入 **64 位内核** 支持（部分——仅在 Xserve 与部分 Mac Pro 上默认启用 64 位内核，桌面版至 **10.7 Lion** 才默认 64 位内核）。Leopard 引入 **DTrace**（源自 **Sun Microsystems** 的 **OpenSolaris**，Dynamic Tracing 工具，经 Apple 工程师移植至 Darwin），允许开发者动态追踪系统调用、进程、内核行为——DTrace 的引入使 macOS 的 BSD 层获得了 Solaris 级别的可观测性工具。Leopard 还引入 **ZFS 只读** 支持预览（可读取 ZFS 池但不可创建或管理），但完整 ZFS 支持未进入 shipping macOS（至 **10.11 El Capitan** 后 ZFS 支持被完全移除）。其他新功能包括 **Time Machine**（基于 BSD 层的硬链接与 `fs_snapshot` 机制）、**Boot Camp**（双系统启动）、**Spaces**（虚拟桌面）。

  | Leopard BSD 层特性 | 引入内容 | 上游来源 | 后续状态 |
  | --- | --- | --- | --- |
  | **64 位内核（部分）** | Xserve/Mac Pro 默认启用 | Apple 自研 | 10.7 Lion 桌面默认 64 位 |
  | **DTrace** | 动态追踪工具 | Sun Microsystems OpenSolaris（CDDL） | 至 2024 年仍在 macOS |
  | **ZFS 只读预览** | 可读取 ZFS 池 | OpenSolaris ZFS（CDDL） | 10.11 后完全移除 |
  | **Time Machine** | 基于硬链接 + `fs_snapshot` | BSD 层机制 | 至 2024 年仍在 macOS |
  | **Boot Camp** | 双系统启动 | BSD 层启动支持 | 至 2024 年仍在 macOS |
  | **Spaces** | 虚拟桌面 | Apple 自研 | 至 2024 年仍在 macOS |

  ~~Leopard 的 ZFS 完整支持已进入 shipping macOS~~，事实上 Leopard 仅为 ZFS 只读预览，完整 ZFS 因 CDDL 与 Apple 商业策略冲突未进入 shipping macOS，至 10.11 El Capitan 后完全移除。

**史观**：总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕。DTrace 的引入是 “形式主义化的可观测规则” 的显现——DTrace 作为 Solaris 的可观测工具，被 Apple 移植至 Darwin 的 BSD 层，使 macOS 获得了 Solaris 级别的系统追踪能力。q.md “快乐的辩护” 在此显现：Apple 投入工程资源移植 DTrace，此移植不直接带来用户可见功能但提升开发者体验——此即 “快乐的辩护” 中 “不为辩护而辩护，而是因内在价值而延续” 的显现。

**辨析**：Leopard 的 ZFS 仅为只读预览，完整 ZFS 未进入 shipping macOS——Apple 在 Leopard 期曾计划将 ZFS 作为默认文件系统（2007 年 WWDC 上 Steve Jobs 提及），但因 CDDL 与 Apple 商业策略的冲突（CDDL 要求源码开源，Apple 倾向于自研 APFS）至 10.11 El Capitan 后完全移除 ZFS 支持。采信 “Leopard ZFS 为只读预览，完整 ZFS 因 CDDL 与 Apple 策略冲突未进入 shipping macOS” 的判断。
