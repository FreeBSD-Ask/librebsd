# 267.3.3 Objective-C 2.0 与垃圾回收的引入

**要点**：Leopard 引入 **Objective-C 2.0**——Apple 对 Objective-C 语言的重大更新，由 **Chris Lattner** 主导（其同时领导 LLVM 项目），核心新增特性包括：**垃圾回收（Garbage Collection，GC）**——基于代际分代收集的自动内存管理，替代手动 `retain`/`release` 引用计数（RC），GC 在 Leopard 期为按应用选配启用〔原稿“默认启用”存疑待复核〕但在后续版本（10.8 Mountain Lion）被废弃，最终由 **ARC（Automatic Reference Counting，2011 年 10.7 Lion 引入）** 取代；**属性（@property）**——声明式的实例变量访问器生成，简化 `getter`/`setter` 样板代码；**Fast Enumeration**——`for...in` 语法遍历集合，性能优于传统 `NSEnumerator`。Objective-C 2.0 与 BSD 层的关联体现于：GC 运行时依赖 BSD 层的 `mmap`/`mprotect` 系统调用实现写屏障（write barrier）——GC 通过 `mprotect` 将堆内存标记为只读以检测写操作，触发 `SIGSEGV` 信号后由 GC 处理器更新写屏障，这一机制依赖 BSD 层的内存保护原语。

  | Objective-C 2.0 特性 | 引入版本 | 后续状态 | BSD 层依赖 |
  | --- | --- | --- | --- |
  | 垃圾回收（GC） | 10.5 Leopard | 10.8 废弃，由 ARC 取代 | `mmap`/`mprotect` 写屏障 |
  | `@property` 属性 | 10.5 Leopard | 至 2024 年仍在 | 无直接依赖 |
  | Fast Enumeration | 10.5 Leopard | 至 2024 年仍在 | 无直接依赖 |
  | ARC（后续） | 10.7 Lion | 至 2024 年仍在 | 无直接依赖 |

  > Objective-C 2.0 的 GC 与 ARC 是两种不同的自动内存管理路径——GC 采用运行时分代收集，ARC 采用编译期引用计数插入，二者技术路线不同，ARC 最终胜出。

**史观**：总纲第 15 条——文化即形式主义〔映射存疑，待主理人审定〕。Objective-C 2.0 的 GC 是 “形式主义化的内存管理规则” 的显现——手动 `retain`/`release` 的分散内存管理被 GC 统一为运行时自动收集，内存管理规则从 “分散形式” 转化为 “统一形式”。q.md “道与术的辩证” 在此显现：GC 是 “术”（运行时机制），自动内存管理的 “道”（设计哲学），二者在 Leopard 期合一，但 GC 的 “术” 在 10.8 被废弃、由 ARC 的 “术” 取代，反映 “道” 的延续与 “术” 的迭代。

**辨析**：Objective-C 2.0 的 GC 与 ARC 的关系——GC 是运行时分代收集（Stop-the-world 间歇暂停），ARC 是编译期引用计数插入（无运行时暂停），二者技术路线不同。GC 在 Leopard 引入后因性能开销与确定性不足被废弃，ARC 在 10.7 Lion 引入后成为 Objective-C 内存管理的主导方案。采信 “GC 与 ARC 是两种不同的自动内存管理路径，ARC 最终胜出” 的判断。GC 的 `mmap`/`mprotect` 写屏障机制与 BSD 层的关系须以 Darwin 源码 `objc4/` 仓库为准，不得仅凭一般认知推断。
