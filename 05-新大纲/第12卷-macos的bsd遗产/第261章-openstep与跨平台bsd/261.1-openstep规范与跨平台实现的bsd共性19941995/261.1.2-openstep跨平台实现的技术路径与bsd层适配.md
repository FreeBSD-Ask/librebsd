# 261.1.2 OpenStep 跨平台实现的技术路径与 BSD 层适配

**要点**：OpenStep 跨平台实现的技术路径因平台而异。**OpenStep/Mach**（NeXT 自有平台）直接基于 NeXTSTEP 的 **Mach 3.0** + **4.3BSD 派生内核**，BSD 层无需桥接——此为 NeXT 工程遗产的最直接延续。**OpenStep Enterprise**（Windows NT 版，**1996 年** 发布）通过桥接层调用 Win32 的 POSIX 子系统——Windows NT 内置 POSIX 子系统（基于 SVR4），但功能有限，NeXT 需扩展 BSD socket 与文件系统语义以兼容 OpenStep API。**Sun 的 Solaris OpenStep** 通过 Solaris 的 SVR4/BSD 兼容层（Solaris 提供 BSD 源码兼容包）实现——Solaris 自 SVR4 起即含 BSD 兼容层，此兼容层为 OpenStep 的 BSD 服务调用提供基础。三平台的 BSD 层实现路径不同，但 OpenStep API 对上层应用保持统一。

  | 平台 | BSD 层适配方式 | 桥接层需求 | 兼容度 |
  | --- | --- | --- | --- |
  | **OpenStep/Mach**（NeXT） | 直接调用 4.3BSD 派生代码 | 无需桥接 | 完全兼容 |
  | **OpenStep Enterprise**（Windows NT） | Win32 POSIX 子系统 + 扩展 | 需扩展 BSD socket/文件系统语义 | 部分兼容（需扩展） |
  | **Solaris OpenStep**（Sun） | SVR4/BSD 兼容层 | 利用 Solaris 既有 BSD 兼容包 | 兼容（基于既有 BSD 包） |

  ~~OpenStep 的 BSD 层在所有平台上代码完全同源~~，事实上只有 NeXT 版直接调用 4.3BSD 派生代码，Sun 与 Windows NT 版均为独立桥接实现，API 兼容不等于代码同源。
