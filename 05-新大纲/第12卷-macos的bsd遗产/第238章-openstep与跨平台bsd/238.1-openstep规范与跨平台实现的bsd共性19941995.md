# 238.1 OpenStep 规范与跨平台实现的 BSD 共性（1994-1995）

## 238.1.1 OpenStep 规范的底层 BSD 抽象

**要点**：**OpenStep 规范** 由 **NeXT** 与 **Sun Microsystems** 于 **1994 年** 联合发布，是一组面向对象的 API 规范（**Foundation** + **App Kit** + **Display PostScript** + **Distributed Objects**），与具体实现解耦。OpenStep 规范的核心设计是将应用框架（Foundation/AppKit）与底层操作系统解耦——在 NeXT、Sun Solaris、Windows NT 上的实现共享同一套上层 API，但底层的 BSD 服务（POSIX、BSD socket）由各平台桥接层提供。**NeXT 版**（OpenStep/Mach）仍直接调用 **4.3BSD 派生代码**（NeXTSTEP 时期的 BSD 层），**Sun 版**（Solaris OpenStep）调用 Solaris 的 SVR4/BSD 兼容层，**Windows NT 版**（OpenStep Enterprise）调用 Win32 的 POSIX 子系统。OpenStep 规范的 “BSD 共性” 仅限于 API 层面——底层在不同平台由不同机制实现，须避免将 “API 兼容” 误读为 “代码同源”。

  | 实现版本 | 上层 API | 底层 BSD 服务提供者 | 代码同源性 |
  | --- | --- | --- | --- |
  | OpenStep/Mach（NeXT） | Foundation/AppKit | 4.3BSD 派生（NeXTSTEP BSD 层） | 同源 |
  | Solaris OpenStep | Foundation/AppKit | SVR4/BSD 兼容层 | 独立实现 |
  | OpenStep Enterprise | Foundation/AppKit | Win32 POSIX 子系统 | 独立实现 |

  > OpenStep 规范明确将应用框架与底层操作系统解耦，此即 NeXT/Sun 所称 “独立于操作系统的面向对象应用框架”——API 是统一的，实现是分化的。

## 238.1.2 OpenStep 跨平台实现的技术路径与 BSD 层适配

**要点**：OpenStep 跨平台实现的技术路径因平台而异。**OpenStep/Mach**（NeXT 自有平台）直接基于 NeXTSTEP 的 **Mach 3.0** + **4.3BSD 派生内核**，BSD 层无需桥接——此为 NeXT 工程遗产的最直接延续。**OpenStep Enterprise**（Windows NT 版，**1996 年** 发布）通过桥接层调用 Win32 的 POSIX 子系统——Windows NT 内置 POSIX 子系统（基于 SVR4），但功能有限，NeXT 需扩展 BSD socket 与文件系统语义以兼容 OpenStep API。**Sun 的 Solaris OpenStep** 通过 Solaris 的 SVR4/BSD 兼容层（Solaris 提供 BSD 源码兼容包）实现——Solaris 自 SVR4 起即含 BSD 兼容层，此兼容层为 OpenStep 的 BSD 服务调用提供基础。三平台的 BSD 层实现路径不同，但 OpenStep API 对上层应用保持统一。

  | 平台 | BSD 层适配方式 | 桥接层需求 | 兼容度 |
  | --- | --- | --- | --- |
  | **OpenStep/Mach**（NeXT） | 直接调用 4.3BSD 派生代码 | 无需桥接 | 完全兼容 |
  | **OpenStep Enterprise**（Windows NT） | Win32 POSIX 子系统 + 扩展 | 需扩展 BSD socket/文件系统语义 | 部分兼容（需扩展） |
  | **Solaris OpenStep**（Sun） | SVR4/BSD 兼容层 | 利用 Solaris 既有 BSD 兼容包 | 兼容（基于既有 BSD 包） |

  ~~OpenStep 的 BSD 层在所有平台上代码完全同源~~，事实上只有 NeXT 版直接调用 4.3BSD 派生代码，Sun 与 Windows NT 版均为独立桥接实现，API 兼容不等于代码同源。
