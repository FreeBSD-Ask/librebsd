## 第 34 章 CSRG 时期核心成员的采访录

### CSRG 时期核心成员的采访（1978-1992 时期当事人）

#### 采访 1：麦库西克（Marshall Kirk McKusick）

**字段 1 采访元数据**

- 受访者：麦库西克（Kirk McKusick），时任加州大学伯克利分校 CSRG 核心成员，FFS（Fast File System）设计者
- 采访者：BSD Now 节目主持人 Allan Jude（艾伦·裘德），于 BSDCan 2018 现场录制
- 采访时间：2018-12-27（发布）
- 采访形式：会议演讲问答与播客访谈
- 原始来源：BSD Now Episode 278“The Real McCoy”，**<https://www.bsdnow.tv/278>**
- 存档信息：BSD Now 278 节目页经联网抓取可访问（访问日期 2026-07-24），未失效

**字段 2 采访摘要**

麦库西克在 BSDCan 2018 现场访谈中详述了 4.2BSD（1983 年发布）作为 CSRG 里程碑版本的意义，重点回顾了自己设计 FFS（Fast File System）的经过，包括对原 UNIX 文件系统性能瓶颈的分析、柱面组（cylinder group）与块簇（block clustering）的设计思路。访谈还涉及 4.2BSD 网络栈（TCP/IP）的集成、Sam Leffler 在网络代码中的工作，以及 4.2BSD 发布后对 Internet 协议族演进的推动作用。他提到 2018 年仍能读取 1982 年写入的 FFS 磁盘。

**字段 3 考据脚注**

本则采访的 BSD Now 278 节目页经联网抓取核实。麦库西克关于 FFS 设计的陈述，经他本人 1984 年发表的 TOCS 论文“A Fast File System for UNIX”（与 Bill Joy、Sam Leffler、Bob Fabry 合著）交叉验证，技术细节一致。自利偏差审查：麦库西克作为 FFS 设计者，对自身工作的叙述可能存在自我美化，正文引用时须对照原始论文与同侪回忆。完整考据过程见 [20260724_kirk-mckusick-bsdnow-278-4.2bsd.md](../../../原材料/研究/考据记录/20260724_kirk-mckusick-bsdnow-278-4.2bsd.md)〔存疑：所引考据记录文件全库暂缺（“原材料”顶层目录亦不存在），待补录；本节交叉验证结论以 BSD Now 278 节目页与 McKusick 1984 年 TOCS 论文为准〕。

**字段 4 与本章节内容的关联**

- 为子节 33.1（1981-1983 年 4.2BSD 革命——TCP/IP、FFS、socket 三件套）提供 CSRG 核心成员对开发背景的当事人回忆
- 为子节 33.1（FFS 三件套之一）提供 FFS 设计者的一手记述
- 为子节 33.6（重要贡献者与边缘者——Leffler 与被遗忘的 CSRG 成员）提供对 Sam Leffler 工作的同侪视角

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——据原文第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手。技术的发展使曾经需要数年完成的工作如今数日可成，但问题始终在于是否有人去做”，麦库西克设计 FFS 是从对原 UNIX 文件系统性能瓶颈的分析中动手长出来的，柱面组与块簇不是规划出来的蓝图，而是“动手去做”地针对磁盘硬件物理特性作出的工程回应。但据 14.1 节“决定世界的并非某个阶级，也不是什么经济”，此处“动手者”不可窄化为“文件系统设计者”的固定身份——麦库西克作为 CSRG 核心成员设计 FFS，是主体性未被理论遮蔽的状态。
- 总纲 22“知识注定过时”——据原文第 22 章 22.1 节“今天书写的技术史，可能在出版之日就已过时。但这不意味着史学写作无意义，而是要求史家有此自觉”，FFS 从 1982 年到 2018 年的持续演化，印证知识的过时与保存之辩证。22.2 节“技术债务是历史设计的代价”提示：FFS 数十年延续既是设计哲学的胜利，也是历史包袱的延续。
- 总纲 3“不存在进步，只有权力再分配”——据原文第 25 章 总纲 3“技术演进不是从低级到高级的进步，而是形式主义的诡异曲线”，FFS 的柱面组设计直接回应了当时磁盘硬件的物理特性——但这并非“技术进步”，而是第 9 章 9.3 节“不存在绝对的发展。修仙小说设定古法强于今法存在逻辑悖论，但反过来说今法绝对强于古法同样存在问题”所述的形式主义演化：FFS 针对 1980 年代磁盘的设计权衡，在现代 SSD 时代已成为技术债务。
- 总纲 18“时间是一种形式主义”——据原文第 25 章 总纲 18“等待、记忆、历史的欣赏都具有时间性。沥青滴落般的时间尺度要求史家具备宏观的时间自觉”，麦库西克 2018 年仍能读取 1982 年写入的 FFS 磁盘，是沥青滴落式的时间尺度——第 27 章 27.4 节“和解往往取决于等待，或者说，取决于时间。这世间种种的等待，就好像沥青在滴落”提示：FFS 数十年的延续是 BSD 长期主义的体现，但此长期主义非苦难哲学（见总纲 14）。
- 总纲 9“经验优先”——据原文第 25 章 总纲 9“优先呈现质朴的事实与当事人的直接经验，而非套用复杂框架”，麦库西克作为 FFS 设计者的当事人直接经验，优先于任何事后理论框架。但据第 2 章 2.3 节“记忆的东西从来都是不存在的——那天的偶然性都被转为了必然性，都是不存在的”，其 2018 年的回忆仍是一种形式主义化的重构。

**自反性声明**：本释读本身也是一种形式主义化的重构，不声称是对项目统摄史观的客观正确解读。释读中“麦库西克设计 FFS 是从性能瓶颈分析中动手长出来而非规划蓝图”的判断本身也是一种形式主义化的动手/规划二元对立运作，可能遮蔽 FFS 柱面组设计中对 IBM VSAM 与 Multics 文件系统等既有范式的理论预设；释读中“FFS 数十年延续既是设计哲学胜利也是历史包袱”的判断本身也参与胜利/包袱二元对立的形式主义运作，可能遮蔽 FFS 在 ZFS、APFS 等后继文件系统中通过概念继承而获得的非包袱性延续；释读中“FFS 针对 1980 年代磁盘的设计权衡在现代 SSD 时代已成为技术债务”的判断本身也是一种形式主义化的时代归因，可能遮蔽 FFS 柱面组思想在 SSD 时代通过 write amplification 控制而获得的重新诠释；释读中“麦库西克 2018 年仍能读取 1982 年 FFS 磁盘是沥青滴落式的时间尺度”的判断本身也是一种形式主义化的时间浪漫化，可能遮蔽此事实更源于 FFS 元数据格式的工程稳定性而非时间本身的恩赐；释读中“麦库西克 2018 年回忆仍是形式主义化的重构”的判断本身也是一种形式主义化的时间归因，可能遮蔽麦库西克作为 FFS 设计者对设计细节的原始记忆，欢迎被更自反的释读所超越（见 据原文第 27 章 27.2 节）。

#### 采访 2：Sam Leffler

**字段 1 采访元数据**

- 受访者：Sam Leffler，时任加州大学伯克利分校 CSRG 核心成员，4.2BSD 网络栈主要开发者
- 采访者：ACM Queue 编辑 Gary Powers
- 采访时间：2004-10（ACM Queue 第 2 卷第 8 期发布）
- 采访形式：期刊访谈
- 原始来源：Powers, Gary, “A Conversation with Sam Leffler”, ACM Queue, Vol. 2, No. 8, November 2004。**<https://queue.acm.org/detail.cfm?id=1039535>**
- 存档信息：ACM Queue 文章页经联网检索确认真实存在（访问日期 2026-07-24），未失效

**字段 2 采访摘要**

Leffler 在 ACM Queue 访谈中回顾了 4.2BSD 网络栈（含 TCP/IP 实现）的设计目标与实现过程，详述了 DARPA 对 BSD 作为 Internet 协议试验床的战略考量。他谈到 4.2BSD 网络代码如何从 DARPA 合同需求出发，集成了 TCP、UDP、IP、ICMP 等核心协议，并影响了后续 socket API 的标准化。访谈涉及与 BBN（Bolt Beranek Newman）在 TCP 实现上的协作与分歧。

**字段 3 考据脚注**

本则采访的 ACM Queue 文章页经联网检索核实。Leffler 关于 4.2BSD 网络栈设计的陈述，经 Kirk McKusick BSD Now 278 采访（本章采访 1）与 4.2BSD 手册页中的网络部分交叉验证。自利偏差审查：Leffler 作为网络栈主要开发者，对自身角色的叙述可能存在自我美化，正文引用时须对照 BBN 的 TCP 实现档案。完整考据过程见 [20260724_sam-leffler-acm-queue-2004-4.2bsd.md](../../../原材料/研究/考据记录/20260724_sam-leffler-acm-queue-2004-4.2bsd.md)〔存疑：所引考据记录文件全库暂缺（“原材料”顶层目录亦不存在），待补录；本节交叉验证结论以 ACM Queue 文章页与 BSD Now 278 节目页为准〕。

**字段 4 与本章节内容的关联**

- 为子节 33.1（1981-1983 年 4.2BSD 革命——TCP/IP、FFS、socket 三件套）提供网络栈开发者的当事人一手记述
- 为子节 33.1（socket 三件套）提供 socket API 设计过程的当事人视角
- 为子节 33.1（TCP/IP 与 Internet 协议试验床）提供 BSD 作为 Internet 试验床的当事人证言

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——据原文第 14 章 14.2 节“真正的问题不在于技术发展的程度，而在于是否动手。技术的发展使曾经需要数年完成的工作如今数日可成，但问题始终在于是否有人去做”，Leffler 实现 4.2BSD 网络栈不是“在合同约束下保持技术判断自主性”的二元图景，而是从 DARPA 合同需求出发“动手去做”地集成 TCP、UDP、IP、ICMP 等核心协议。但据 14.1 节“决定世界的并非某个阶级，也不是什么经济”，此处“动手者”不可窄化为“网络栈开发者”的固定身份——Leffler 作为 CSRG 核心成员实现网络栈，是主体性未被理论遮蔽的状态。
- 总纲 13“法律与道德是利益分配”——据原文第 25 章 总纲 13“任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”，DARPA 合同的法律结构直接塑造了 4.2BSD 网络栈的交付范围。但据第 29 章 29.5 节“政治经济理论本身是政治经济斗争的产物。理论不是对现实的客观描述，而是权力斗争的工具”，合同条款不是中立的法律框架，而是 DARPA IPTO 与 CSRG、BBN 等多方主体利益分配的产物——BBN 作为 TCP 实现的另一方，与 CSRG 在协作与分歧中共同塑造了 4.2BSD 网络栈的形态。
- 总纲 4“分离聚合是永恒规律”——据原文第 4 章 4.1 节“分离聚合是世界发展的规律。分久必合，合久必分，具有必然性”，BBN 与 CSRG 在 TCP 实现上的协作与分歧，印证分离与聚合的循环——协作是聚合，分歧是分离，二者在 4.2BSD 网络栈的形成中循环呈现。
- 总纲 19“解释学循环是历史认识的根本条件”——据原文第 25 章 总纲 19“前理解的差异使分歧不可避免。权力与知识在历史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使”，BBN 与 CSRG 在 TCP 实现上的分歧，源于前理解的差异——BBN 作为 ARPANET 的设计者与 CSRG 作为 UNIX 研究者，对 TCP 实现的前理解截然不同，分歧不可避免。第 19 章 19.3 节“权力与知识的共谋”提示：什么被记录为“4.2BSD 网络栈”，什么被遗忘为“BBN 的贡献”，本身就是权力行使。
- 总纲 9“经验优先”——据原文第 25 章 总纲 9“优先呈现质朴的事实与当事人的直接经验，而非套用复杂框架”，Leffler 作为 4.2BSD 网络栈主要开发者的当事人直接经验，优先于任何事后理论框架。但据第 23 章 23.2 节“史家以为自己在书写历史，但历史人物可能正在藉着史家书写他们自己的故事”，Leffler 2004 年的回忆可能存在“作者与人物权力倒转”的性质。

**自反性声明**：本释读本身也是一种形式主义化的重构，不声称是对项目统摄史观的客观正确解读。释读中“Leffler 实现 4.2BSD 网络栈是从合同需求出发动手集成核心协议”的判断本身也是一种形式主义化的工具理性归类，把 Leffler 主体性简化为“需求—动手—集成”闭环，可能遮蔽其在 socket API 抽象层设计中对 UNIX 文件描述符范式的创造性延伸；释读中“DARPA 合同直接塑造 4.2BSD 网络栈交付范围”的判断本身也是一种形式主义化的法律决定论，可能遮蔽 CSRG 在合同范围协商中对 TCP/IP 实现方向的策略性引导；释读中“合同条款是多方利益分配产物而非中立法律框架”的判断本身也参与中立/利益二元对立的形式主义运作，可能遮蔽 DARPA IPTO 对 Internet 协议公共性的真实坚持无法被还原为利益分配；释读中“BBN 与 CSRG 协作与分歧印证分离聚合循环”的判断本身也是一种形式主义化的循环论归因，可能遮蔽 BBN-CSRG 分歧中具体的技术路线选择而非抽象的“分离—聚合”摆动；释读中“什么被记录为 4.2BSD 网络栈什么被遗忘为 BBN 贡献本身是权力行使”的判断本身也是一种形式主义化的权力还原论，可能遮蔽 Leffler 在 2004 年 ACM Queue 访谈中对 BBN 工作的实际承认；释读中“Leffler 2004 年回忆存在作者与人物权力倒转”的判断本身也是一种形式主义化的叙事归因，可能遮蔽 Leffler 作为长期网络栈维护者对协议集成细节的累积性记忆，欢迎被更自反的释读所超越（见 据原文第 27 章 27.2 节）。
