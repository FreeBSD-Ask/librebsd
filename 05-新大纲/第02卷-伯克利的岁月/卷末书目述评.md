## 引言

第二卷所涉时段（1978-1992）是伯克利计算机系统研究小组（CSRG）从草创到全盛、从单一学术项目到国家级基础设施的关键十五年。这一时期以 1978 年 3 月 9 日 1BSD 发布为起点，以 1992 年 USL 诉讼前夕 Net/2 发布为终点，中间贯穿 DARPA 合同（1980 年 4 月启动）、4.2BSD 革命（1983 年 8 月）、Bill Joy 离开伯克利创办 Sun（1982 年）、4.3BSD 系列演化（1986-1990 年）、Morris 蠕虫（1988 年 11 月）等塑造现代计算格局的事件。CSRG 在这十五年间将 UNIX 从贝尔实验室的研究原型改造为支撑互联网、工作站产业与学术计算的基础设施，其技术遗产（socket API、FFS 文件系统、TCP/IP 协议栈、**sendmail(8)**、vi/ex 编辑器）至今仍是现代操作系统的底座。

本综述的史学定位在于：第二卷所涉时段的文献谱系具有鲜明的“当事人叙述主导”特征。CSRG 核心成员 Marshall Kirk McKusick（马歇尔·柯克·麦库西克）、Sam Leffler、Mike Karels、Keith Bostic（基思·博斯蒂克） 等人既是历史事件的参与者，也是后世叙事的主要书写者。McKusick 1999 年《Twenty Years of Berkeley Unix》作为本卷主干二手来源，既是当事人一手回忆，又是二手研究，这种身份叠合使本卷史料考据面临独特的认识论挑战——如何在当事人视角与档案证据之间建立批判性距离。本综述试图在保留评注式书目完整性的同时，引入学术综述的问题意识，围绕 CSRG 全盛期的核心史学问题展开史料辨析与学术论争梳理。

本综述的核心史学问题包括：其一，DARPA 资助如何塑造 BSD 的技术路线与组织形态；其二，4BSD/4.2BSD/4.3BSD 版本演化的内在逻辑与外部驱动；其三，Bill Joy 在 CSRG 时期的角色定位及其离开对 BSD 后续发展的影响；其四，TCP/IP 实现的归属之争及其对互联网基础设施的塑造；其五，Sun Microsystems 创立所代表的学术研究向企业产品转化。围绕这些问题，本综述辨析三个学术争议：BBN 与 Berkeley 的 TCP/IP 实现之争、vi 编辑器的谱系归属、DARPA 合同对 BSD 方向的塑造。每个争议均含争议主题、不同立场、史料依据与史家判断四要素。

## 史料谱系

第二卷史料谱系可按一手史料、二手研究、口述史与工具书四个层次加以梳理，各层之间存在密集的交叉引用与互证关系。

一手史料层以 The Unix Heritage Society（TUHS）归档为轴心。TUHS 由 Warren Toomey 维护，涵盖 1BSD 至 4.4BSD-Lite2 的全部 CSRG 发布版本的源码磁带与发布说明。其中 1BSD READ_ME（1977 年 11 月 23 日）由 Bill Joy 亲笔签注，逐项列明 Pascal 编译系统、ex 1.1 编辑器、改进的 shell 等组件，是 1BSD 内容组成的最权威一手证据，纠正了后世将 csh 与 vi 误归入 1BSD 的常见说法。2BSD Release Notes 首次以 vi 名称对外发布可视编辑器，并引入 csh、termcap、curses 等组件。此外，Fabry 1980 年 3 月 14 日提交给 DARPA 的合同提案（Defense Technical Information Center 即 DTIC 收录编号 ADA094691）是 DARPA 资助 CSRG 的官方一手记录，记载了 1980 年前后 DARPA 对 BSD 的需求方向。Leffler、Joy、Fabry 合著的 4.2BSD Networking Implementation Notes（1983 年）详述 socket 层、TCP/IP 协议栈设计，其第 6.1 节是 BSD socket API 设计的直接来源。McKusick、Joy、Leffler、Fabry 四人合著的 FFS 论文（1984 年发表于 ACM Transactions on Computer Systems）是 Berkeley Fast File System 的奠基性文献。Coulouris 亲笔撰写的 em 编辑器起源自述（1998 年初版，2012 年更新）记载 em 于 1975 年秋在伦敦大学玛丽女王学院开发、1976 年夏访问伯克利时带给 Joy，是 vi 谱系源头的关键一手证据。

二手研究层以 McKusick 1999 年《Twenty Years of Berkeley Unix》为骨干。该文收录于 DiBona 等人编辑的《Open Sources: Voices from the Open Source Revolution》，是 CSRG 核心成员撰写的当事人回忆，详述 DARPA 合同背景、Joy 主导的 1BSD/2BSD 时期、4.2BSD 网络实现、Joy 1982 年离开加入 Sun 等关键史实。4.3BSD 设计专著（Leffler 等，1989 年）与 4.4BSD 设计专著（McKusick 等，1996 年）构成 BSD 技术架构的当事人系统陈述，二者形成时间序列对照。Salus 1994 年《A Quarter Century of UNIX》是 UNIX 二十五年通史，覆盖 1969-1994 年，是众多 BSD 史实的主要二手转写来源。Southwick 1999 年《High Noon》与 Hall、Barry 1990 年《Sunburst》是 Sun Microsystems 早期企业史的双柱，相互印证 Sun 于 1982 年 2 月 24 日成立。National Research Council 1999 年报告《Funding a Revolution》将 BSD 项目置于联邦政府计算机科学资助史的制度框架。Hafner、Lyon 1996 年《Where Wizards Stay Up Late》与 Waldrop 2001 年《The Dream Machine》则提供 ARPANET 起源与 ARPA IPTO 资助理念的网络史背景。Christiansen 1996 年《Csh Programming Considered Harmful》为 csh 评价提供关键批评视角。

口述史层涵盖 Computer History Museum（CHM）口述史、BSD Now 播客、bsdtalk 播客、ACM Queue 期刊访谈、USENIX ; login: 期刊采访等公开来源。Joy 2011 年 CHM 口述史回顾了从密歇根到伯克利的求学经历与 1BSD/2BSD 开发过程。McKusick 在 BSD Now 第 278 期（2018 年）与 bsdtalk 第 018 期（2006 年）中分别回顾了 CSRG 全盛时期与 4.1BSD 至 4.3BSD 系列开发。Leffler 2004 年 ACM Queue 访谈详述 4.2BSD 网络栈设计与 BBN 协作分歧。Allman 2017 年 USENIX ; login: 采访回顾 **sendmail(8)** 开发历程。Bostic 在 BSD Now 访谈中详述 Net/2 代码清理与 USL 诉讼期间动态。Stonebraker 2015 年 CHM 口述史回顾 Ingres 与 Postgres 数据库开发。

工具书层包括 DEC PDP-11 Processor Handbook（1976 年）、Feldman make 技术报告（1977 年）、Wirth Pascal-S 设计文档（1975 年）、TUHS 源码归档、DTIC 在线数据库、IEEE Xplore 数字图书馆等。这些工具书为版本考据、硬件约束分析、文献检索提供基础设施支撑。

上述四个层次之间存在密集的互证关系：一手史料（TUHS 归档、Fabry 提案）为二手研究（McKusick 1999）提供证据基础，口述史（Leffler ACM Queue）补充一手技术文档（4.2BSD Networking Notes）未充分反映的争议细节，工具书（DTIC）为一手合同档案提供检索路径。这种多层互证结构既是本卷史料谱系的优势，也带来了当事人视角主导的认识论挑战（详见方法论反思）。

## 学术论争

### 争议一：BBN 与 Berkeley 的 TCP/IP 实现之争

争议主题：DARPA 合同下 TCP/IP 实现的归属与路径分野——BBN 作为 ARPANET 承建方开发的原始实现与 Berkeley 重写优化后的实现，二者孰为互联网协议的事实参考实现，DARPA 如何裁定。

不同立场：其一，BBN 立场。BBN（Bolt Beranek and Newman）公司作为 ARPANET 的承建方，由 Rob Gurwitz 于 1981-1982 年开发原始 TCP/IP 实现，集成入 4.1a/4.1cBSD 测试版本。BBN 认为其作为 ARPANET 原始承包商，对 TCP/IP 实现享有优先地位。其二，Berkeley 立场。Bill Joy 与 Sam Leffler 重写优化 TCP/IP 实现，引入 socket API 作为网络通信统一抽象。Berkeley 实现在性能与代码简洁性上优于 BBN 原始版本。其三，DARPA 裁定立场。DARPA 委托 Mike Muuss（Michael John Muuss，美国陆军弹道研究实验室 BRL，**ping(8)** 与 **ttcp(1)** 作者）作为独立第三方评估，经一个月测试后认定 Berkeley 代码效率更高且通过所有测试，BBN 代码拥塞处理更优但在压力测试条件下会 panic。DARPA 最终决定 4.3BSD 使用 Berkeley 代码库。

史料依据：Leffler、Joy、Fabry 合著的 4.2BSD Networking Implementation Notes（1983 年）是 4.2BSD 网络实现的最权威一手技术文档，但其局限在于未充分反映 BBN 与 Berkeley 的争议。Jim Dempsey 2017 年在 Internet History 邮件列表的回忆补充了争议细节，原文记载"BBN promptly revised its TCP implementation to use the socket interface, and for about a year there was a battle to determine whose networking code would take precedence...the Berkeley code won the battle"。McKusick 1999 年《Twenty Years of Berkeley Unix》作为当事人叙述记载 Mike Muuss 评估过程与 DARPA 最终裁定。4.3BSD Release Notes（1986 年 6 月）反映 4.3BSD 因 BBN 争议推迟一年发布的事实。

史家判断：Berkeley 实现在性能测试上胜出，成为互联网协议的事实参考实现，这是 DARPA 独立评估后的工程结论。但 BBN 作为 ARPANET 承建方在 TCP/IP 协议设计层面的贡献不可抹杀——Cerf 与 Kahn 1974 年的 TCP 概念论文与 BBN 的 IMP 开发是 BSD socket API 得以成立的协议前提。争议的深层意义在于：socket API 作为 Berkeley 创新，将网络端点抽象为文件描述符，遵循 UNIX 一切皆文件哲学，这一抽象的胜利不仅是技术性能的胜利，更是 UNIX 哲学对网络通信范式的塑造。须警惕的是，本卷叙事以 Berkeley 视角为主导，BBN 视角的一手叙述稀缺（仅 Jim Dempsey 2017 年邮件列表回忆），这种史料不对称可能使争议呈现偏向 Berkeley 的叙事倾斜。socket API 设计是否受 Xerox NS 协议影响亦存争议，BSD socket 设计文献未明确引用 Xerox NS 的 endpoint 概念，但二者在协议族抽象上的结构相似性值得关注 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。

### 争议二：vi 编辑器的谱系——Coulouris em 至 Joy ex/vi 的源流

争议主题：vi 编辑器的发明归属——vi 是 Bill Joy 的独立发明，还是 George Coulouris em 编辑器谱系的延伸，ed→em→ex→vi 的源流如何界定。

不同立场：其一，传统英雄叙事。流行叙事将 vi 视为 Joy 的独立发明，强调 Joy 在 300 波特调制解调器约束下的设计天才。其二，Coulouris 自述立场。George Coulouris 亲笔记载 em 编辑器于 1975 年秋在伦敦大学玛丽女王学院开发，1976 年夏访问伯克利时将 em 源码带给 Joy，Joy 以此为起点先开发 ex 行编辑器再扩展出 vi 可视模式。其三，McKusick 叙述立场。McKusick 1999 年记载 Joy 与 Chuck Haley（查克·黑利） 共同改进 Thompson 的 Pascal 并实现 ex 编辑器，确认 Haley 在 ex 演化为 vi 之前已介入，但未充分强调 Coulouris em 的源头地位。

史料依据：Coulouris 自述（coulouris.net/cs_history/em_story，1998 年初版，2012 年更新）是 vi 谱系源头的最关键一手证据，原文记载“I developed em at QMC in the autumn of 1975”与"I spent the summer of 1976 as a visitor to the CS Dept. at Berkeley"。Joy 1978 年撰写的 vi 入门手册《An Introduction to Display Editing with vi》系统阐述 vi 的模态设计与命令体系，但其局限在于未明确记录 vi 与 em 的谱系关系。1BSD READ_ME（1977 年 11 月 23 日）证实 1BSD 仅有 ex 1.1 编辑器，vi 不在 1BSD 中，首次以 vi 名称发布是在 2BSD。McKusick 1999 年《Twenty Years of Berkeley Unix》记载 Joy 与 Haley 共同开发 ex 的过程。

史家判断：vi 非 Joy 独立发明，而是 ed→em→ex→vi 谱系的延伸，这一判断以 Coulouris 自述为核心依据，经 McKusick 1999 年叙述与 1BSD 磁带清单交叉验证。Coulouris 的贡献长期被 Joy 的光环遮蔽，这是英雄叙事对边缘贡献者的典型遮蔽——em 编辑器作为 vi 的直接技术源头，在多数 vi 叙事中缺席或仅作脚注。按 0 信任原则，Coulouris 自述属当事人回忆，存在记忆偏差风险，但其记载的 em 开发时间（1975 年秋）与访问伯克利时间（1976 年夏）与 McKusick 1999 年关于 ex 开发时间的叙述在时序上吻合，形成交叉验证。Chuck Haley 作为 ex 共同开发者的角色亦须确认——McKusick 1999 年明确记载 Haley 与 Joy 共同改进 Pascal 并实现 ex，但 Haley 本人的自述或访谈至今未进入公开档案 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。vi 谱系争议的史学意义在于：它揭示了 UNIX 早期工具演化的协作本质——编辑器的谱系是跨大西洋的学术网络（QMC→ 伯克利）而非单一英雄的孤立创造。

### 争议三：DARPA 合同对 BSD 方向的塑造

争议主题：DARPA 资助如何塑造 BSD 的技术路线与组织形态——DARPA 合同是 BSD 从学术工具转向国家级基础设施的关键转折，但合同的具体需求方向与塑造程度在不同史料中呈现不一。

不同立场：其一，Fabry 提案立场。Bob Fabry 1980 年 3 月 14 日提交给 DARPA 的合同提案建议设立配置控制机制以维护 ARPA 标准 UNIX 版本，强调配置控制与标准化。Fabry 提案反映 1980 年前后 DARPA 对 BSD 的需求方向以标准化与可维护性为核心。其二，McKusick 1999 年回顾立场。McKusick 作为 CSRG 核心成员，在 1999 年回顾中强调 DARPA 资助使 BSD 从研究原型转向生产系统，记载第二份合同资金规模约为初始合同的五倍，其中一半经费用于 UNIX 项目。McKusick 的叙述侧重 DARPA 资助对 BSD 工程化的推动。其三，NRC 1999 年报告立场。National Research Council 1999 年报告《Funding a Revolution》将 BSD 项目置于联邦政府计算机科学资助史的制度框架，评估 DARPA、NSF、ONR 等机构自 1950 年代至 1990 年代的资助，涵盖 VLSI 计划、BSD 项目、TCP/IP 开发、Mach 项目等。NRC 报告提供制度史视角，将 DARPA 合同视为冷战时期联邦科研资助体系的组成部分。

史料依据：Fabry 1980 年提案（DTIC 收录编号 ADA094691）是 DARPA 资助 CSRG 的官方一手记录，可经 DTIC 数据库溯源。McKusick 1999 年《Twenty Years of Berkeley Unix》记载合同时间节点（1980 年 4 月开始，18 个月期限）、第二份合同五倍资金规模、Joy 主导 4.1BSD 开发等史实。NRC 1999 年报告《Funding a Revolution》（ISBN 0-309-06278-0）提供联邦资助史的制度框架。合同具体金额在 McKusick 1999 年、Salus 1994 年等权威史料中均未记载，网络流传的具体金额说法无一手来源支持 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。初始合同号 F19628-80-C-0002 与后续合同 N00039-82-C-0235 在 McKusick 1999 年中未提及 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。

史家判断：DARPA 合同是 BSD 从学术工具转向基础设施的关键转折，这一判断以 Fabry 提案、McKusick 1999 年叙述、NRC 1999 年报告三方交叉验证为基础。Fabry 提案反映 DARPA 的需求方向（标准化、配置控制），McKusick 叙述反映合同执行结果（4.1BSD/4.2BSD 工程化），NRC 报告提供制度史框架（联邦资助体系）。三方在“DARPA 合同塑造 BSD 方向”这一核心判断上一致，但在塑造程度与具体需求内容上存在差异：Fabry 强调标准化，McKusick 强调工程化，NRC 强调制度性。须警惕的是，McKusick 作为合同受益方与当事人，其叙述可能存在夸大 DARPA 资助作用的立场倾向。合同具体金额与条款仍是史料缺口，需通过 DTIC FOIA 申请与 Bancroft 档案查阅补全。DARPA 合同条款中的版权归属条款为 BSD 后续开源分发奠定法律基础，这一版权条款的深远影响在本卷已初步显现，其完整展开则延续至后续卷册所涉 USL 诉讼与开源运动时期。

## 方法论反思

本卷史料考据的方法论反思须从 0 信任原则的适用性谈起。0 信任原则要求对所有资料（含一手资料）进行考据验证，不得因来源“一手”即直接采信。这一原则在本卷面临独特挑战：CSRG 核心成员（McKusick、Joy、Leffler、Karels、Bostic）既是历史事件的参与者，又是后世叙事的主要书写者，其当事人叙述同时承担一手史料与二手研究的双重身份。McKusick 1999 年《Twenty Years of Berkeley Unix》作为本卷主干二手来源，其作为当事人一方叙述可能存在立场倾向（强调 CSRG 贡献、淡化内部争议）与记忆偏差（时间、人物、细节记错）。按 0 信任原则，须与 TUHS 一手归档、CSRG 技术报告交叉验证后方可采信。例如，McKusick 1999 年记载 SOSP 1973 会议在 Purdue University 举办，但 SOSP 1973 官方记录显示会议在 IBM Yorktown Heights 举办，此差异按 0 信任原则以官方记录为准保留 Yorktown Heights 表述 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。

多源交叉验证不可靠性规则在本卷亦有典型体现。2BSD 发布日期在中文二手来源中长期记为“1979 年 5 月”，但 TUHS RELEASE_DATES 一手归档记为“2 BSD mid 1978”，McKusick 1999 年一手原文记载“By mid-1978”，两项独立权威来源交叉确认 2BSD 发布于 1978 年中而非 1979 年 5 月。这一案例表明，多源一致的二手转述仍可能是大众误解——“1979 年 5 月”的说法虽经多源转引，但其源头可追溯至对 2BSD Release Notes 日期戳的误读，而非 CSRG 原始分发记录。按多源交叉验证不可靠性规则，考据中须考察这些来源是否相互独立、是否引用自同一一手来源、是否存在信息茧房效应。值得注意的是，本卷文献清单中 2BSD Release Notes 条目仍保留“1979 年 5 月”的传统说法，这一保留旨在呈现评注式书目的原始面貌，而综述主体则以最新考据结论为准，二者之间的差异本身即是考据过程的留痕。

本卷史料谱系的另一方法论特征是档案依赖。TUHS 归档是核心一手数字证据来源，但 TUHS 主要收录发布版本源码磁带，CSRG 内部邮件存档（伯克利 Bancroft 图书馆 CU-551 全宗）尚未公开数字化，这使 CSRG 内部决策过程（如 BBN 争议期间的具体沟通、Joy 离开时的交接细节）难以从内部视角重构。DARPA 合同档案依赖 DTIC 数据库，但部分报告未完整公开，需通过 FOIA 申请获取。这种档案不对称使本卷叙事不可避免地偏向公开归档（TUHS、DTIC）所反映的视角，而内部决策过程的重建依赖口述史推断，存在推断偏差风险。

自反性反思：本综述作为 BSD 历史叙事的组成部分，本身存在立场倾向。本卷以“伯克利的岁月”为标题，以 CSRG 为叙事主体，这一叙事框架天然地以伯克利为中心，可能遮蔽 BBN、Bell Labs、其他 UNIX 厂商在同期历史中的角色。BBN 视角的一手叙述稀缺（仅 Jim Dempsey 2017 年邮件列表回忆），Coulouris 之外的 em 用户视角缺失，这种史料不对称使争议呈现偏向 Berkeley 的叙事倾斜。史家须在叙事中显化这种不对称，通过标注 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 与呈现不同立场，使读者能够识别叙事的立场边界。本综述的立场声明：在承认 Berkeley CSRG 对现代计算的基础性贡献的同时，警惕 BSD 中心主义叙事对其他行动者贡献的遮蔽，力求在档案证据与当事人叙述之间建立批判性距离。

## 缺口与前瞻

本卷史料存在三类缺口，需在未来研究中补全。

档案缺口：其一，CSRG 邮件存档（伯克利 Bancroft 图书馆 CU-551 全宗）未公开数字化，这使 CSRG 内部决策过程难以从内部视角重构。BBN 与 Berkeley TCP/IP 争议期间的具体沟通、Joy 离开时的交接细节、DARPA 合同执行的内部讨论等关键史实，目前主要依赖口述史推断，缺乏邮件档案的直接证据。其二，Fabry 档案未数字化。Bob Fabry 作为伯克利引入 UNIX 的关键学术推动者与 DARPA 合同提案撰写者，其个人档案（含与 DARPA、Bell Labs、CSRG 成员的通信）尚未进入公开档案机构。其三，DARPA IPTO 年度报告部分未解密。合同具体金额、评标记录、候选系统比较等史实，需通过 DTIC FOIA 申请获取。未来方向为 Bancroft 实地查阅 CU-551 全宗、DTIC FOIA 申请、Fabry 档案发掘。

方法论缺口：其一，缺乏 4.2BSD 与 4.3BSD 源码 diff 量化分析。BBN 与 Berkeley TCP/IP 实现的性能比较目前依赖 Mike Muuss 1985 年评估与 McKusick 1999 年叙述，缺乏基于源码 diff 的代码层面量化比较。未来可借助 BSD 上游仓库提交数据库进行源码 diff 量化分析，重构 TCP/IP 实现的代码演化路径。其二，缺乏 BBN Coyote 实现的代码层面比较。BBN 端 TCP/IP 实现（Rob Gurwitz 开发）的源码是否存档、是否可获取，直接制约争议的代码层面辨析深度。其三，口述史的系统性整理不足。CSRG 核心成员的口述史散见于 CHM、BSD Now、bsdtalk、ACM Queue、USENIX ; login: 等不同来源，缺乏系统性的口述史整理与交叉索引。

史学缺口：其一，BBN 视角的一手叙述稀缺。BBN 作为 ARPANET 承建方与 TCP/IP 原始实现者，其视角在现有叙事中主要通过 Jim Dempsey 2017 年邮件列表回忆呈现，缺乏 BBN 内部档案或 BBN 核心成员（Rob Gurwitz 等）的系统性口述史。其二，Coulouris 之外的 em 用户视角缺失。em 编辑器作为 vi 的直接技术源头，其在伦敦大学玛丽女王学院的使用情况、传播路径等，目前仅有 Coulouris 本人自述，缺乏其他 em 用户的佐证。其三，Chuck Haley 的角色未充分挖掘。Haley 作为 ex 编辑器的共同开发者与 Pascal 编译器改进者，在 McKusick 1999 年叙述中被提及，但其个人访谈或自述至今未进入公开档案 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。其四，DARPA 合同对 BSD 技术路线的塑造程度缺乏量化评估。合同要求（支持 VLSI 设计、向 DARPA 资助机构分发源代码、提交技术报告）与 BSD 实际技术演化（4.1BSD 至 4.3BSD）之间的因果关系，目前主要依赖定性叙述，缺乏基于合同条款与版本 Release Notes 的系统对照。

未来研究方向：Bancroft 实地查阅 CU-551 CSRG 邮件存档，DTIC FOIA 申请获取 DARPA 合同档案，Fabry 档案发掘，4.2BSD/4.3BSD 源码 diff 量化分析，BBN 档案发掘与 Rob Gurwitz 口述史采集，CSRG 口述史系统性整理与交叉索引。这些方向将有助于补全本卷史料的档案缺口、方法论缺口与史学缺口，使第二卷的叙事从当事人叙述主导转向档案证据与当事人叙述的批判性互证。
