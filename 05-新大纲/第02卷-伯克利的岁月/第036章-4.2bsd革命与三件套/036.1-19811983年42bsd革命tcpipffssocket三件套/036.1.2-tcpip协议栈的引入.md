# 036.1.2 TCP/IP 协议栈的引入

**要点**：4.2BSD 集成的 TCP/IP 协议栈由 Bill Joy 与 Sam Leffler 在伯克利编写（rejecting BBN 原版后），引入 socket API 作为 IPC 与网络通信的统一抽象（Jim Dempsey 2017 互联网历史邮件列表原文"by Bill Joy and Sam Leffler of Berkeley along with Gurwitz. BBN promptly revised its TCP implementation to use the socket interface, and for about a year there was a battle to determine whose networking code would take precedence. Although the BBN code won some adherents, and was licensed to several computer vendors, the Berkeley code won the battle"），使 BSD TCP/IP 成为互联网协议的事实参考实现（DARPA 后续测试认为 4.2BSD 版本性能优于 BBN 官方实现，4.3BSD 保留 BSD 版本）

**史料**：4.2BSD 网络源代码、Joy/Leffler 的 TCP/IP 实现文档（“4.2BSD Networking Implementation Notes”6.1 节“Socket layer”）、DARPA 测试报告、Jim Dempsey 2017“Re: BBN C-series computers”邮件列表一手回顾 ［A］

**史观**：第 9 条经验优先——Joy/Leffler 的 TCP/IP 实现基于实践需求而非协议理论，实践驱动标准化

**辨析**：4.2BSD TCP/IP 的作者归属需严格考证——网络层代码与 socket API 均为 Bill Joy 与 Sam Leffler 共同设计（BBN 的 Rob Gurwitz 是 BBN 端 TCP/IP 实现者，BSD 端是 Joy 与 Leffler）；“Joy 自行编写”的不准确表述应改为“Joy 与 Leffler 共同编写”；BBN 后续曾重写其实现以采用 socket 接口，但 BSD 版本最终胜出成为互联网参考实现；BBN Gurwitz 原型与 CSRG Joy/Leffler 重写版本的具体性能差异（McKusick 1999《Twenty Years of Berkeley Unix》当事人一手记载 BBN 与 Berkeley TCP/IP 评估全过程，互联网档案馆存档 URL: <https://web.archive.org/web/2023/https://www.oreilly.com/openbook/opensources/book/kirkmck.html）：（1）BBN> Gurwitz 原型代码状态——Berkeley 在 4.2BSD 中实际集成的并非 BBN 最终版本，而是 BBN 早年交给 Joy 的“much-hacked initial prototype”原型代码（McKusick 1999 原文"we were still using the much-hacked initial prototype that they had given us many years earlier“），Joy 集成时对其进行了性能调优（McKusick 1999 原文”Joy integrated it into the system and tuned its performance"）；（2）CSRG Joy/Leffler 重写版本状态——Joy 与 Leffler 在 BBN 原型基础上重写了内部结构以支持多协议并行（McKusick 1999 原文"redesigned the internal structuring of the software, refining the interfaces so that multiple network protocols could be used simultaneously"），即从 BBN 单一 TCP/IP 协议实现扩展为支持多协议族（AF_INET、AF_UNIX 等）的通用网络子系统；（3）评估时点与背景——1985 年 6 月 USENIX 会议 CSRG 宣布 4.3BSD 将于夏季发布时，BBN 向 DARPA 投诉称合同分工为“Berkeley 实现接口、BBN 实现协议”（McKusick 1999 原文"Berkeley was to implement the interface while BBN was supposed to implement the protocol"），要求伯克利在 4.3BSD 中以 BBN 实现替换现有 TCP/IP 代码；（4）Karels 初步评估——Mike Karels 获取 BBN 更新代码后评估，决定将 BBN 代码中的优秀思想合并入伯克利代码库而非整体替换，理由是伯克利代码已经过 4.2BSD 大规模分发获得充分测试与改进（McKusick 1999 原文"it had gotten considerable testing and improvements from the widespread distribution in 4.2BSD"），作为妥协，Karels 提议 4.3BSD 发行同时包含两套实现让用户自选；（5）DARPA 决策——DARPA 认为发行两套代码库会导致互操作性问题（McKusick 1999 原文"releasing two code bases would lead to unnecessary interoperability problems"），决定只发布一套实现，将两套代码交予 BRL（Ballistics Research Laboratory，美国陆军弹道研究实验室）的 Mike Muuss 作为伯克利与 BBN 双方均认可的独立第三方评估（McKusick 1999 原文“an independent third party”，注：McKusick 1999 原文拼写为“Mike Muuse”单 s，按 0 信任原则以 Muuss 本人 ARL 主页署名“Mike Muuss”双 s 为准，McKusick 1999 的“Mike Muuse”系拼写错误）；（6）Muuss 评估结论——Muuss 经过约一个月评估后提交报告（McKusick 1999 原文“After a month of evaluation, the report came back”）：伯克利代码效率更高（throughput 更优，McKusick 1999 原文“the Berkeley code was more efficient”）、BBN 代码拥塞控制更好（congestion control 更优，McKusick 1999 原文“the BBN code handled congestion better”），最终决定性因素（tie breaker）：伯克利代码在所有测试中无错运行，BBN 代码在部分压力测试下 panic（McKusick 1999 原文"the Berkeley code flawlessly ran all the tests while the BBN code panicked under some stress conditions"）；（7）DARPA 最终决策——4.3BSD 保留伯克利代码库，Karels 整合 BBN 代码中的优秀思想（包括更好的拥塞控制算法），4.3BSD 因此延期至 1986 年 6 月发布；BBN Gurwitz 原型与 CSRG Joy/Leffler 重写版本的核心性能差异可概括为：Berkeley 版本在吞吐量（throughput）与稳定性（stability under stress）上占优，BBN 版本在拥塞控制（congestion control）上占优，最终稳定性成为决定性因素——这一评估方法论体现了 DARPA“凭实力竞争”的工程优先原则；［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
