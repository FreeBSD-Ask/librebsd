# 037.1.2 csh 与 shell 生态演进

**要点**：C shell（csh）由 Bill Joy 在 2BSD（1978 年中，mid-1978）中引入，提供 C 风格语法、历史记录（!!）、作业控制（Job Control 源自 IIASA Jim Kulp 的工作，由 Joy 集成入内核与 csh）；4.2BSD（1983 年 8 月）将 csh 作为默认交互 shell（interactive shell），但系统脚本仍使用 Bourne shell（/bin/sh）；csh 在 BSD 阵营长期保持默认交互 shell 地位，4.4BSD-Lite（1994 年）仍以 csh 为默认；1990 年代起 tcsh（Ken Greer 1981 年 CMU 原型，1983 年 10 月公开发布）逐步取代 csh 成为 BSD 用户的事实选择，FreeBSD 5.0（2003 年 1 月）将 root 默认 shell 从 csh 改为 tcsh；csh/tcsh 在 BSD base system 中延续至今，但用户默认 shell 市场份额被 bash（1989 年 GNU）与 zsh（1990 年 Paul Falstad）持续侵蚀；CSRG 选择 csh 作为默认交互 shell 而非 Bourne shell 反映 BSD 阵营对 C 语言语法亲和性的偏好

(1978) “An Introduction to the C Shell”（2BSD 文档）；McKusick 1999（记载 Jim Kulp job control 由 Joy 集成入 4BSD，1980.10）；4.2BSD Release Notes (1983.8)；4.4BSD-Lite Release Notes (1994.6)；FreeBSD 5.0 Release Notes (2003.1) 默认 shell 变更条目；Anderson, G. & Anderson, P. (1986) “The UNIX C Shell Field Guide” ［B］

**史观**：技术路线分化：BSD（csh/tcsh 谱系）与 System V（Bourne shell/Korn shell 谱系）形成 UNIX shell 的两大分支，分化延续至今；哲学思潮：csh 的“接近 C 语法”反映 1970 年代 C 语言作为高级语言正典化的影响

**辨析**：Job Control 非 Joy 原创，而是源自 IIASA（奥地利）Jim Kulp 的工作，由 Joy 集成入 4BSD（1980.10）内核与 csh（McKusick 1999 原文“Joy incorporated Jim Kulp's job control”）；4.2BSD 将 csh 设为“默认交互 shell”但系统脚本仍使用 /bin/sh，“默认 shell”表述需精确区分交互与脚本场景；FreeBSD 在 5.0 之前 root 默认 shell 为 csh 而非 bash
