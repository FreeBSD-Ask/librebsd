# 043.6.2 要点shadowpassword密码散列分离存储在BSD与SystemV的分野源

**要点**：shadow password（密码散列分离存储）在 BSD 与 System V 的分野源于 **1980 年代** 两者的安全哲学差异——System V **R3.2**（**1987 年**）引入 `/etc/shadow` 文件将密码散列从 `/etc/passwd` 移至仅 root 可读的 `/etc/shadow`，降低字典攻击风险，反映 System V 优先考虑商用客户的密码安全；BSD 则直至 **4.4BSD-Lite**（**1994.6**）仍坚持 `/etc/passwd` 单文件格式（密码散列留在所有用户可读的 `/etc/passwd` 中，虽经 **crypt(3)** DES 25 轮迭代散列但仍可被字典攻击破解），反映 BSD 优先考虑兼容性与简洁性；**Net/2**（**1991.6**）作为 BSD 完全自由完整代码发布继承此分野——Net/2 仍使用 `/etc/passwd` 单文件格式，未引入 shadow password，与同期 System V R3.2/R4 的 `/etc/shadow` 形成对照；此分野延续至 **FreeBSD 1.0-3.x**（**1993-2000**）与 NetBSD 早期版本均继承 BSD 单文件格式，直至 **FreeBSD 4.x**（**2000 年** 起）才引入 **master.passwd** 与 **spwd.db** 实现密码散列分离，弥合与 System V 的 shadow password 分野；BSD 选择单文件格式的工程原因是 NIS（Network Information Service，原黄页 Yellow Pages，因英国电信商标争议改名）分布式账户管理依赖 `/etc/passwd` 的可读性——NIS 客户端需读取 `/etc/passwd` 构造用户映射表，shadow password 会破坏 NIS 兼容性，此约束在 **1980-1990 年代** BSD 站点广泛部署 NIS 的语境下使 shadow password 不具备工程可行性

| 维度 | BSD（4.2BSD-4.4BSD-Lite） | System V（R3.2/R4） |
| -- | ----------------------- | ----------------- |
| 文件格式 | `/etc/passwd` 单文件 | `/etc/passwd` + `/etc/shadow` 双文件 |
| 密码散列位置 | `/etc/passwd`（所有用户可读） | `/etc/shadow`（仅 root 可读） |
| 安全模型 | **crypt(3)** DES 25 轮迭代散列 | shadow 密码分离，降低字典攻击风险 |
| 引入时间 | 4.2BSD 起至 **4.4BSD-Lite**（**1994.6**） | **R3.2**（**1987 年**）引入，**R4**（**1988 年**）标准化 |
| 兼容性考虑 | NIS 分布式账户管理依赖 `/etc/passwd` 可读性 | 不依赖 NIS，shadow 不影响 NIS |
| 弥合时间 | **FreeBSD 4.0**（**2000.3**）引入 **master.passwd** + **spwd.db** | — |

**史料**：**4.2BSD** `/etc/passwd` 文件格式规范（七字段，**crypt(3)** DES 25 轮迭代）；System V **R3.2** `/etc/shadow` 文件规范（**1987 年**）；**4.4BSD-Lite** Release Notes (**1994.6**) 确认仍使用 `/etc/passwd` 单文件格式；**FreeBSD 4.0** Release Notes (**2000.3**) 确认引入 **master.passwd** 与 **spwd.db**；NIS/Yellow Pages 设计文档；《4xbsd-security-1980-1991》内部史料（史实三）〔存疑：所引材料在本库无对应路径，原位待考〕 ［A］

**史观**：第 2 条历史是形式主义化的非存在——System V 的 shadow password 是“密码安全”形式逻辑的扩张（密码散列须分离存储），BSD 的单文件格式是“兼容性与简洁性”形式逻辑的坚守，两种形式主义对立驱动 shadow password 分野；第 9 条经验优先——BSD 选择单文件格式基于 NIS 分布式账户管理的工程实践需求，而非安全理论先行，工程实践约束决定了安全机制选择

**辨析**：shadow password 分野的“安全哲学差异”叙述需避免简化为“BSD 不重视安全”——BSD 选择单文件格式是基于 NIS 工程约束的实践判断，而非忽视密码安全，须区分“安全哲学差异”与“安全意识差异”；BSD 直至 **4.4BSD-Lite** 仍坚持 `/etc/passwd` 单文件格式的判断需核对——4.4BSD-Lite Release Notes 与 4.4BSD 系统管理员手册确认仍使用单文件格式，但 CSRG 内部可能讨论过 shadow password 引入，须区分“发布版本格式”与“内部讨论”；**FreeBSD 4.x** 引入 **master.passwd** 与 **spwd.db** 弥合 shadow password 分野的精确版本需核对——**FreeBSD 4.0**（**2000.3**）已引入 **master.passwd** 机制，须区分“FreeBSD 4.0 引入”与“FreeBSD 4.x 逐步完善”；System V **R3.2** 引入 `/etc/shadow` 的精确年份存在 **1987 年**（R3.2 引入）与 **1988 年**（R4 标准化）两种记载，须区分“R3.2 引入”与“R4 标准化”。〔存疑：System V R3.2 引入 /etc/shadow 的精确年份待多源交叉验证〕
