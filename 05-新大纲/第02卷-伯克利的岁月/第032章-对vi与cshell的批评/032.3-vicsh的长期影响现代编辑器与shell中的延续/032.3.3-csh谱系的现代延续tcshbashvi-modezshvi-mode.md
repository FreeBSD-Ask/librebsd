# 032.3.3 csh 谱系的现代延续：tcsh、bash vi-mode、zsh vi-mode

**要点**：csh 的交互式创新（历史替换、作业控制、别名、文件名补全）被后续 shell 广泛吸收——**tcsh**（Ken Greer **1981 年 12 月** 在 HP Labs 将 TENEX 风格文件名补全合并入 csh，形成 csh 谱系的直接延续，Arch Linux man **tcsh(1)** 原文 “Ken Greer, HP Labs, 1981. File name completion.”）；**bash**（Brian Fox **1989 年** GNU 项目，吸收 csh 交互功能但以 Bourne shell 语法为基础，通过 readline 库提供 **vi-mode**——用户执行 `set -o vi` 启用 vi 风格命令行编辑，readline 库默认为 emacs-mode，vi-mode 提供命令模式与插入模式切换，支持 h/j/k/l 移动、dd 删除行、cc 修改行、w/b 词移动等 vi 命令）；**zsh**（Paul Falstad **1990 年** 在普林斯顿大学发布于 comp.sources.misc 新闻组，通过 `bindkey -v` 启用 vi-mode，支持 vi 风格命令行编辑，zsh 的 vi-mode 较 bash 更完整，支持 vi-style 文件名补全与命令历史导航）；tcsh 在 csh 基础上增加 TENEX 补全与命令行编辑，成为 BSD 系统（FreeBSD、NetBSD、OpenBSD）的默认 root shell 选项之一；bash 与 zsh 虽非 csh 直接后裔，但 csh 开创的交互式功能（历史替换、别名、作业控制、文件名补全）被二者以不同语法形式吸收，体现 “功能延续、语法分化” 的演化特征

(1989) “Bash Reference Manual”；Falstad, P. (1990) zsh 0.1 发布公告（comp.sources.misc 新闻组，zsh.sourceforge.io 项目历史存档）；zsh Manual（vi-mode 章节，`bindkey -v`） ［A］

**史观**：第 4 条分离与聚合——csh 的交互功能被后续 shell 分别吸收与聚合，tcsh 直接延续 csh 谱系，bash 与 zsh 以不同语法形式聚合 csh 功能；第 6 条技术路线分化——交互式 shell（csh/tcsh）与脚本式 shell（sh/bash）的技术路线分化持续至今，bash 通过兼容 Bourne shell 语法统一了脚本与交互，但 vi-mode 作为交互功能仍独立于脚本语法；第 24 条许可证——csh 作为 BSD 创新未进入 AT&T 默认发行版，但其交互功能通过 bash（GNU）与 zsh（开源）在自由软件生态中得到延续

**辨析**：bash vi-mode 与 zsh vi-mode 的 “兼容性范围” 需区分两个层面——(1) 命令行编辑层面的 vi 模态（bash 与 zsh 均支持，通过 readline 与 zle 实现），(2) 脚本语法层面的 vi 兼容（不存在，bash 与 zsh 均为 Bourne shell 谱系而非 csh 谱系）；bash 的 vi-mode 通过 readline 库实现，readline 的 `editing-mode` 配置项可设为 `vi` 或 `emacs`（默认），`set -o vi` 为临时启用，`~/.inputrc` 中 `set editing-mode vi` 为永久配置；zsh 的 vi-mode 通过 Zsh Line Editor（zle）实现，`bindkey -v` 为启用命令，zsh 的 vi-mode 较 bash 更完整，支持 `vicmd`（命令模式）与 `viins`（插入模式）两套键绑定；tcsh 在 FreeBSD、NetBSD、OpenBSD 中作为可选 shell 提供，但非默认交互 shell（FreeBSD 14 默认为 sh，OpenBSD 默认为 ksh，NetBSD 默认为 sh）；［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ bash、zsh、tcsh 的 “用户规模” 与 “市场份额” 难以获得可靠的一手统计数据——不同发行版的默认 shell 配置不同，且用户可自行更改，按 0 信任原则不引用具体百分比数字；Ken Greer 1981 年合并 tcsh 工作的所属机构在不同来源中存在分歧（Arch Linux man tcsh 标注 HP Labs，部分来源标注 CMU），按 0 信任原则以一手 man tcsh 为准；[2026-08-14 两库核查：tcsh（Ken Greer 1981）、bash（Brian Fox 1989）、zsh（Paul Falstad 1990）的具体发布时间在参考文献库（tech “tcsh” 0 命中）与邮件库 usenet 中均无直接条目，两库无法验证]
