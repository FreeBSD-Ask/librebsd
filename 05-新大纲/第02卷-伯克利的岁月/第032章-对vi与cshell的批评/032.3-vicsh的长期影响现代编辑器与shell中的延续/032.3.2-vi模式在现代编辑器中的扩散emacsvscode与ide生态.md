# 032.3.2 vi 模式在现代编辑器中的扩散：emacs、VS Code 与 IDE 生态

**要点**：vi 的模态设计不仅延续于 vi 谱系编辑器，更扩散至其他编辑器家族——**GNU Emacs** 内置 **viper-mode**（VI PERilous，为 GNU Emacs 默认附带的 vi 仿真次模式，支持 vi 的命令模式、插入模式与可视模式，由 Michael Kifer 开发，随 GNU Emacs 发行版发布，GNU Emacs 手册专设 “Viper” 一章），emacs 社区另发展出 **evil-mode**（Extensible vi Layer for Emacs，由 Frank Fischer **2011 年 11 月** 在 GitHub 发起开发，仓库 <https://github.com/emacs-evil/evil>，最早 commits 可追溯至 2011 年 11 月 10 日，现为 emacs 社区最流行的 vi 仿真层，当前维护者 Tom Dalziel），evil-mode 采用状态机模型实现 vi 模态，被 Spacemacs、Doom Emacs 等流行 emacs 发行版默认集成；**Visual Studio Code** 通过扩展市场提供 Vim 扩展（vscodevim.vim，由 GitHub 用户 vscodevim 团队维护），在 IDE 环境中复现 vi 模态编辑；JetBrains 系列 IDE（IntelliJ IDEA、PyCharm、CLion 等）内置 IdeaVim 插件提供 vi 模态仿真；vi 模态的跨编辑器家族扩散证明 vi 设计的持久生命力，从 1978 年 2BSD 的 300 波特调制解调器约束演化为 2020 年代 IDE 生态的标配功能

**史料**：GNU Emacs 手册 “Viper” 章节（<https://www.gnu.org/software/emacs/manual/html_node/viper/>，访问日期 2026-07-28，访问时超时未获取完整内容，依据 GNU Emacs 官方文档目录确认 Viper 章节存在）；evil-mode GitHub 仓库（<https://github.com/emacs-evil/evil>，访问日期 2026-07-28，最早 commits 可追溯至 2011 年 11 月 10 日，作者 Frank Fischer，当前维护者 Tom Dalziel，仓库 Keywords: [emulation] [vim]）；VS Code Vim 扩展（vscodevim.vim，VS Code Marketplace）；JetBrains IdeaVim 插件（JetBrains Marketplace） ［A］

**史观**：第 4 条分离与聚合——vi 模态设计从 vi 谱系分离出去，被 emacs、VS Code、JetBrains 等不同家族的编辑器聚合吸收；第 6 条技术路线分化——vi 模态与 emacs 无模态的技术路线分化并未消除，而是通过 vi 仿真层在 emacs 内部并存，形成 “模态 vs 无模态” 的持续张力；第015章边缘者——viper-mode 作者 Michael Kifer 与 evil-mode 作者 Frank Fischer 在 vi 叙事中常被忽略，但其工作使 vi 模态得以跨编辑器家族传播，是 vi 影响力的关键放大者
