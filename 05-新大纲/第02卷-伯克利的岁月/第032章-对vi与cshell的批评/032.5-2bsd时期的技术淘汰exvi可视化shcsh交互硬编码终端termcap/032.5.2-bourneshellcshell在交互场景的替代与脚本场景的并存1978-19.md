# 032.5.2 Bourne Shell → C Shell 在交互场景的替代与脚本场景的并存（1978-1979）

**要点**：UNIX V6/V7 早期默认 shell 为 Thompson shell（sh V1，Ken Thompson 1969-1971）与 Bourne shell（sh V7，Stephen Bourne 1975 年末开发、1979 年随 V7 UNIX 发布）；Joy 1978 年在伯克利开发 C Shell（csh），随 2BSD 1978 年中发布，引入类 C 语法、历史替换（`!`）、作业控制（`jobs`/`bg`/`fg`）、别名机制（`alias`）、波浪号（`~`）主目录表示法，在伯克利用户群体中迅速替代 Bourne shell 成为默认交互 shell；但 csh 因脚本语法缺陷（变量作用域混乱、错误处理不足、可移植性差）未取代 Bourne shell 在脚本场景的主导地位，形成 “交互用 csh、脚本用 sh” 的双轨格局；BSD 后续版本（4.1BSD、4.2BSD、4.3BSD）默认交互 shell 为 csh，脚本默认仍为 sh；csh 的交互地位后被 tcsh（Ken Greer 1981 年 12 月 HP Labs，将 TENEX 风格文件名补全合并入 csh）继承，再被 bash（Brian Fox 1989 年 GNU）、zsh（Paul Falstad 1990 年 11 月普林斯顿大学）继承

**史料**：2BSD 发布说明（csh 1.0 随 2BSD 1978 年中发布）；Joy, W. (1978) “An Introduction to the C Shell”；Bourne, S. (1978) “The UNIX Shell”；V7 UNIX 发布记录（1979）；Christiansen, T. (1996) “Csh Programming Considered Harmful”；Arch Linux man tcsh(1) “AUTHORS” 节（HP Labs 1981 标注）；Falstad, P. (1990) zsh 0.1 发布公告，comp.sources.misc 新闻组 ［C］

**史观**：第 6 条技术路线分化——csh 与 sh 的分化代表交互式与脚本式两条技术路线的分野，csh 在交互场景 “淘汰” sh 但未在脚本场景取代；第 24 条许可证——csh 作为 BSD 创新未进入 AT&T 默认发行版（V7 默认仍为 Bourne shell），反映 BSD 与 AT&T 在默认配置上的分化

**辨析**：csh 并未 “取代” sh 而是 “分担” sh 的交互功能，须严格区分交互场景（csh 主导）与脚本场景（sh 主导）；Bourne shell 开发始于 1975 年末/1976 年初、1979 年随 V7 发布，csh 开发于 1978 年、随 2BSD 1978 年中发布，二者开发同期但独立，不存在一方直接影响另一方的证据；Christiansen 1996 年 “Csh Programming Considered Harmful” 对 csh 脚本缺陷的批评需结合其脚本场景而非交互场景理解；Ken Greer 1981 年合并 tcsh 工作的所属机构在不同来源中存在分歧（Arch Linux man tcsh 标注 HP Labs，部分来源标注 CMU），按 0 信任原则以一手 man tcsh 为准
