# 066.2.1 要点PostgreSQL起源于UCBerkeleyPOSTGRES项目Stone

**要点**：PostgreSQL 起源于 UC Berkeley POSTGRES 项目（Stonebraker, 1986），运行于 4.3BSD。MySQL 虽源自 Linux 但始终维护 BSD 完整支持，FreeBSD ports 中的 MySQL 端口是数据库-OS 协作的典型案例。

**史料**：Stonebraker & Rowe SIGMOD 1986; MySQL FreeBSD 安装指南 ［A/B］

**史观**：总纲第 1 条——技术谱系的路径依赖。

**文献**：Stonebraker 1986; MySQL 文档 ［A/B］

**观点**：1995 年 7 月，Vivek Khera 答复 BSDI 用户求荐轻量数据库时推荐 mSQL：教育与非营利用途免费、商用约 225 澳元，不支持每表多键，但提供 C、Perl、Tcl、Python 等语言 API 且“简单快速”。
**邮件来源**：Vivek Khera，comp.unix.bsd.bsdi.misc，1995 年 7 月，Message-ID: `KHERA.95Jul18170600@kci.kciLink.com>#1/1`
**史学意义**：mSQL 在 1995 年的 BSD 社区充当“ndbm 之上的 SQL 过渡品”，其多键缺失等局限恰是次年 MySQL 以更完整实现取而代之的技术缺口。

**观点**：1997 年，PostgreSQL 核心开发者 Bruce Momjian 在 BSDI 组回答二进制包求源时声明：源码在 ftp.postgresql.org，支持 BSD/OS 2.0、2.1 与 3.0——“我清楚，因为我是开发者之一”，6.1.1 起用 configure 编译无忧。
**邮件来源**：Bruce Momjian，comp.unix.bsd.bsdi.misc，1997 年，Message-ID: `5vc9fu$2k4$1@picasso.op.net>#1/1`
**史学意义**：开发者以第一人称向 BSD 用户背书兼容性，显示 PostgreSQL 团队自 1997 年起把 BSD/OS 列为一等目标平台，是 Ingres、POSTGRES 到 PostgreSQL 谱系在 BSD 世界续命的关键一环。
<!-- /MAIL_INSIGHT -->

<!-- MAIL_INSIGHT: zxmsd01.711063005@mailserv -->
**观点**：1992 年 7 月，图宾根大学的 Gunther Schadow 汇报他在 386BSD 上的数据库选型尝试：Ingres 8.5 编译可过但“太古老”令他放弃，转向 3.1 版 Postgres——体量约为 Ingres 四倍，在小系统上是 size 限制因素，且须逐一清理 ftime、ecvt、gtty 等过时函数调用。
**邮件来源**：Gunther Schadow，comp.unix.bsd，1992 年 7 月，Message-ID: `zxmsd01.711063005@mailserv`
**史学意义**：这封用户笔记同时记录了 Ingres 与 Postgres 两代伯克利数据库在自由 BSD 上的第一手移植体感与代际差异，是 386BSD 时代数据库谱系交替的基层观察。
<!-- /MAIL_INSIGHT -->

<!-- MAIL_INSIGHT: 221g7n$sr@pdq.coe.montana.edu>#1/1 -->
**观点**：1993 年 7 月，386BSD 社区核心成员 Nate Williams 回应 sendmail 8.1C 与 db 库冲突：出路要么升级到 NetBSD，要么等 386BSD 过渡版——“它已集成了新的 sendmail 与新的 DB 代码”。
**邮件来源**：Nate Williams，os.386bsd.bugs，1993 年 7 月，Message-ID: `221g7n$sr@pdq.coe.montana.edu>#1/1`
**史学意义**：这句话点明 1993 年新版 Berkeley DB 与 sendmail 8 是作为一对基础设施被自由 BSD 整体接入的，数据库库件的换代与邮件栈换代在社区路线图中互为绑定。
