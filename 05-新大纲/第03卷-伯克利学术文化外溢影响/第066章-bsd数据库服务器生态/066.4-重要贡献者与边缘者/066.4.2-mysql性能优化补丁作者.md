# 066.4.2 MySQL 性能优化补丁作者

  **要点**：MySQL 性能优化补丁作者群体包括：（1）FreeBSD MySQL Port 维护者——经 freebsd.duckdb 查询 MySQL 首次引入 freebsd-ports 为 1997-06-18T19:35:30Z by James FitzGibbon（commit“Import of MySQL, a mutlithreaded SQL database server”，包含 mysql322-client/server 与 mysql323-client/server 系列）；（2）Yahoo! 等公司内部 MySQL on FreeBSD 性能优化团队（Yahoo! 1990 年代后期在 FreeBSD 4.x 上大规模部署 MySQL，但内部性能补丁多为私有未公开）；（3）MySQL AB/Sun/Oracle 的 FreeBSD 平台测试工程师——MySQL AB 早期对 FreeBSD 平台友好，但 Sun/Oracle 时期 FreeBSD 平台优先级下降；（4）LinuxThreads 兼容层优化——FreeBSD 5.x 之前默认线程实现 libc_r 与 LinuxThreads 不兼容，需通过 `-DUSE_LINUX_THREADS` 编译选项启用，FreeBSD 7.x 引入 1:1 线程（libthr）后方原生兼容，此过渡期间的兼容性补丁作者多隐藏在 freebsd-ports/databases/mysql*/Makefile 提交记录中

**史观**：第 10 条动手者创造历史——MySQL 性能优化补丁作者是数据库生态的边缘者，其贡献须基于实践（补丁记录）而非叙事
  
**辨析**：MySQL 首次引入 freebsd-ports 时间经 freebsd.duckdb 确认为 1997-06-18T19:35:30Z by James FitzGibbon（与 Postgres95 同期为 1996-09-23 引入，仅晚 9 个月）；Yahoo! 内部 MySQL 性能优化团队的具体成员与补丁未公开，仅能在 Yahoo! 工程师博客中找到零散提及；LinuxThreads/libthr 过渡经多源一致确认——FreeBSD 5.x 之前默认线程为 libc_r（M: N 模型），与 MySQL 期望的 LinuxThreads（1:1 模型）不兼容，FreeBSD 7.x 引入 libthr（1:1 模型）后原生兼容；MySQL AB 在 2008 年被 Sun 收购后 FreeBSD 平台优先级下降，2010 年 Oracle 收购 Sun 后进一步下降
