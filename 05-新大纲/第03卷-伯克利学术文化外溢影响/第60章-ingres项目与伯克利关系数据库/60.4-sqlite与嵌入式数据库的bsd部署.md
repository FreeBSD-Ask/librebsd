## 60.4.1 SQLite 2000 年开发与嵌入式数据库设计

  **要点**：SQLite 1.0 于 2000 年 8 月 17 日由 D. Richard Hipp 正式发布，背景包括：（1）Hipp 为美国海军合同开发嵌入式数据库（无管理员、无服务器架构）；（2）SQLite 设计为单文件嵌入式数据库（无独立服务器进程，整个数据库存储于一个跨平台磁盘文件）；（3）SQLite 使用 SQL 查询但避免客户端-服务器架构，实现零配置运行；（4）SQLite 采用公有领域（Public Domain）许可证（后改为 Blessing 许可）使其可被任意使用；SQLite 的设计反映“做一件事并做好”的 UNIX 哲学

## 60.4.3 SQLite 与 BSD 哲学的共鸣

  **要点**：SQLite 与 BSD 哲学的共鸣：（1）SQLite 官方文档（sqlite.org/different.html）以“Zero-Configuration”“Serverless”“Public domain”等概念自我定位，与 UNIX“做一件事并做好”传统形成文本层面的呼应；（2）“做一件事并做好”（do one thing and do it well）最早由 Doug McIlroy 1978 年总结 UNIX 管道哲学时提出，后被 Raymond 在《The Art of UNIX Programming》（2003）第 1 章列为 UNIX 哲学基础原则之一；（3）SQLite 的公有领域许可证与 BSD 的宽松许可证在哲学上共鸣——二者均允许任意使用与闭源衍生，但法律实现路径不同（公有领域放弃版权 vs BSD 保留版权声明）；（4）SQLite 的单文件磁盘存储设计与 BSD 的简洁传统在工程美学上共鸣，但 SQLite 仅为数据库引擎而非完整系统，二者在规模上不可直接类比

  | UNIX“做一件事并做好”哲学溯源 | 时间 | 出处 |
| -------------------------- | -- | -- |
| 首次系统表述 | **1978 年** | Doug McIlroy《The UNIX Timesharing System》一文系统表述管道时包含“write programs that do one thing and do it well”思想 |
| 形式化总结 | **2003 年** | Raymond《The Art of UNIX Programming》第 1 章“Rule of Modularity”列为 17 条 UNIX 哲学之首 |

  | SQLite 官方设计特征 | 内容 | sqlite.org/different.html |
| ----------------- | -- | ----------------------- |

| Public domain | 公有领域 | ✓ |
| 单文件磁盘存储 | 整个数据库存储于一个文件 | ✓ |
| 注 | SQLite 官方文档未直接引用 McIlroy 或 Raymond 的表述，“哲学共鸣”是历史叙事者的解释性框架 | |

  | SQLite 与 BSD 许可证法律实现差异 | SQLite | BSD |
| ------------------------------ | ---- |---|
| 路径 | 公有领域完全放弃版权 | BSD 保留版权声明与免责条款 |
| 闭源衍生 | 允许 | 允许 |

**史观**：第 9 条经验优先与第 4 条分离与聚合——SQLite 与 BSD 在设计倾向上聚合（虽在许可证法律形式上分离），实践先于 Raymond 2003 年形式化总结的 UNIX 哲学
  
**辨析**：“做一件事并做好”的溯源——Doug McIlroy 1978 年在《The UNIX Timesharing System》一文中首次系统表述管道时即包含“write programs that do one thing and do it well”思想，Raymond 2003 年《The Art of UNIX Programming》第 1 章“Rule of Modularity”将其列为 17 条 UNIX 哲学之首；SQLite 官方文档（sqlite.org/different.html，2026 年 7 月 22 日访问）确实以“Zero-Configuration”“Serverless”“Public domain”作为设计核心特征，但官方文档未直接引用 McIlroy 或 Raymond 的表述——“哲学共鸣”是历史叙事者的解释性框架而非 SQLite 官方陈述，须在叙事中明确区分“SQLite 官方设计特征”与“后人对其与 UNIX 哲学共鸣的解读”；BSD 与 SQLite 的许可证法律实现差异——BSD 保留版权声明与免责条款（如 BSD 2-Clause），SQLite 公有领域则完全放弃版权（sqlite.org/different.html 明确"No claim of copyright is made on any part of the core source code"），二者在哲学倾向上共鸣但法律路径不同，不应混淆

## 60.4.4 SQLite 在 BSD 嵌入式场景中的部署

  **要点**：SQLite 在 BSD 嵌入式场景中的部署：（1）FreeBSD 软件包元数据自 pkgng 起以 SQLite 为后端（FreeBSD 10.0 起 pkgng 默认），pfSense、OPNsense 等 FreeBSD 衍生防火墙在配置存储中使用 SQLite；（2）OpenBSD **spamd(8)** 不使用 SQLite——其数据库位于 **/var/db/spamd**，使用 OpenBSD 的 **db(3)** hash 接口（Berkeley DB 风格）而非 SQLite（man.openbsd.org/spamd 与 man.openbsd.org/spamdb 确认）；（3）NetBSD 的 pkgsrc 不使用 SQLite 作为包数据库后端——pkgsrc 使用 PLIST 文件与 metadata 目录树管理软件包信息，与 FreeBSD pkgng 的 SQLite 后端形成对比；（4）DragonFly BSD 的 HAMMER 文件系统从未考虑使用 SQLite——HAMMER 是 Matthew Dillon（马修·狄龙） 自研的 B-Tree 日志结构文件系统，与 SQLite 无工程关联，原大纲此陈述为无依据臆测，应删除

  | 四 BSD 嵌入式数据库选择对比 | 项目 | 选择 | 证据 |
| ------------------------- | -- | -- | -- |
| FreeBSD | pkgng | SQLite 后端 | FreeBSD 10.0 Release Notes、freebsd.duckdb（2011-10-05 by Stanislav Sedov） |
| OpenBSD | **spamd(8)** | **db(3)** hash 接口（Berkeley DB 风格），数据库位于 **/var/db/spamd** | man.openbsd.org/spamd 与 man.openbsd.org/spamdb 确认 |
| NetBSD | pkgsrc | PLIST 文件与 metadata 目录树 | pkgsrc.org 官方文档 |
| DragonFly BSD | HAMMER 文件系统 | 自研 B-Tree 日志结构文件系统 | Matthew Dillon 自研，与 SQLite 无工程关联 |

  | 原大纲修正 | 原表述 | 修正 |

| NetBSD pkgsrc | ~~使用 SQLite 作为后端~~ | 基于 PLIST 与 metadata 目录的包管理框架 |

**史观**：第 9 条经验优先与第 10 条动手者创造历史——SQLite 在 BSD 嵌入式场景的实际部署须基于代码级证据而非想当然的“哲学共鸣”，BSD 各项目对嵌入式数据库的选择反映各自的实用主义路径（FreeBSD 选 SQLite、OpenBSD 选 db(3)、NetBSD 选 PLIST 文件、DragonFly BSD 自研 B-Tree）
  
**辨析**：原大纲四项陈述中三项需修正——OpenBSD **spamd(8)** 数据库经 man.openbsd.org/spamd 与 man.openbsd.org/spamdb 确认为 **/var/db/spamd** 文件，使用 OpenBSD **db(3)** 接口（Berkeley DB 风格 hash 数据库），不使用 SQLite；NetBSD pkgsrc 经 pkgsrc.org 官方文档确认为基于 PLIST 与 metadata 目录的包管理框架，不使用 SQLite 作为后端；DragonFly BSD HAMMER 文件系统是 Matthew Dillon 自研的 B-Tree 日志结构文件系统，与 SQLite 无工程关联，原大纲“曾考虑使用 SQLite”为无依据臆测，应删除；FreeBSD pkgng 使用 SQLite 经 FreeBSD 10.0 Release Notes 与 freebsd.duckdb 查询确认（freebsd-src 首次引入 SQLite 为 2011-10-05 by Stanislav Sedov 作为 Heimdal 1.5 依赖），pfSense/OPNsense 等 FreeBSD 衍生防火墙在配置存储中使用 SQLite 为多源一致事实；此修正体现 0 信任原则——原大纲将 SQLite“嵌入式”特征推广至所有 BSD 子项目，但实际各项目根据自身需求选择不同技术路径
