# 049.2.5 总纲5没有必然性只有偶然性BSD课程与研究的存续并不系于技术优劣而系于具体的人与

- 总纲5 没有必然性，只有偶然性：BSD 课程与研究的存续并不系于技术优劣，而系于具体的人与偶然条件：访谈双方都亲历 BSD 课程因授课教师离任而整体回退为 Red Hat 教材的案例；RPI 在 1990 年代曾浸染浓厚的 BSD 传统，随着那批懂行者相继离开，继任者失去专门知识便默认转向 Linux——教学内容随个人际遇与经费流向漂移，教育史上只有具体事件与偶然条件，无所谓进步的必然规律。（BSD Now EP114，[1549.20-1602.78]，L1）
- 总纲13 法律与道德是利益分配：许可证选择在争论中显形为利益分配而非纯粹法理：Fink 承认 HP 为让合作伙伴的法律部门签核项目而被迫采用 Apache 2.0，主持人的回应是宽松许可的全部意义正在于替企业规避法律风险，并举 Intel 将网卡与显卡驱动以 GPL/BSD 双许可发布、使 BSD 项目得以持续使用其代码的实例——法律文本的每一次取舍都在为某一方再分配代码使用权与商业化自由，各方以生态利益为真实筹码展开博弈。（BSD Now EP114，[843.28-915.66]，L2）
- 总纲22 知识注定过时：同一时期内两类知识呈现截然不同的时间尺度：Linux 的 init 与包管理体系数年之内历经更替而使教学内容迅速过时，而 UNIX 基础原理三十年保持稳定，说明系统的形式外壳与底层惯例的寿命并不相同。（BSDTalk EP208，[284.58-872.82]，L1）
- 总纲9 经验优先：课程设计的每个决定都来自课堂操作中的实际摩擦——镜像漂移、网卡命名混乱、下载拥堵——而非平台优劣的理论比较，体现以教学现场经验校准技术选择的取向。（BSDTalk EP208，[402.62-663.68]，L1）
- 总纲17 证明世界先于解释和改造世界：课程把会查文档、在陌生系统上完成实际任务视为能力成立的证明，而非预先讲授完备理论，教学评价以可操作的验证为归宿。（BSDTalk EP208，[811.06-846.18]，L1）
- 总纲3 不存在进步，只有权力再分配：文档格式语言的历史并非线性进步史：五十年来许多人试图发明优于 mdoc 的语言而大多失败，重型替代方案屡屡被证明难以为继，最终承担手册格式化的反倒是尊重既有语义传统的轻量实现；groff 到 mandoc 的更替是格式化实现权与维护权的转移，而非语言本身的淘汰更迭。（BSDTalk EP243，[468.58-524.04]，L1）
- 总纲9 经验优先：mandoc 的功能取舍由真实手册语料驱动而非语言理论：只要现实中的手册用了某个 groff 特性，格式化器就必须处理它，哪怕该特性与手册无关；这种以既有文本经验为准绳、而非按理想模型裁剪输入的工程立场，是 BSD 文档工具数十年延续的底层方法。（BSDTalk EP243，[617.94-684.34]，L1）

**辨析**：

- 主持人对 Fink 论证的反驳值得辨析：其一，Fink 以 Apache 许可证项目普遍设有技术委员会、工作组与董事会而 copyleft 项目无需此类结构为由贬低宽松许可，主持人指出这混淆了项目规模与许可证类型——大型项目无论何种许可证都需要治理，小型宽松许可项目亦大量存在；其二，主持人以从未有人因 BSD 许可证被诉、而 GPL 合规之难长存 tendrils 作对比论证，并援引 Kirk McKusick 衡量开源项目强度应视其能经受多少次领导层更迭的说法（771.56-779.28），把许可证之争进一步还原为治理与利益之争——但前一断言本身未经量化，须存疑处理。 [存疑脚注] “从未有人因 BSD 许可证被诉”为主持人单一来源修辞性断言，未见统计支撑；Fink 观点仅经 LWN 转述，未回核原文，证据强度不足。（BSD Now EP114，[722.72-904.04]，L4）
- UNIX 基础三十年未变为修辞性概括，工具选项与手册细节仍在演变；Teaching UNIX with BSD 出书计划为口头意向，有无成书须另行核实；转写讹误：set 应为 sed、gooey 应为 GUI、pop and yum 疑为 Red Hat 包管理工具链之误记，引用前须校正。 [存疑脚注] 三十年未变与老书目录适用的说法系当事人印象式表述，未经逐项核对；本期为主持人独白，无对话者交叉质证。（BSDTalk EP208，[829.94-894.58]，L4）
- Schwarze 转述其与 Eric Raymond 交谈、Raymond 又与 Richard Stallman 交谈的结果，称两人同意弃用 GNU info 并以其他方案替代，而 Stallman 与 Raymond 属意的 AsciiDoc/DocBook 路线被 Schwarze 评为工具链沉重、未必更易用；此说经过两级转述，RMS 的真实立场须以 FSF 原始文献核证，且许多替代尝试皆已失败的判断亦属其个人评断。 [存疑脚注] GNU info 弃用共识系经 Raymond 转述的二手信息，未经 Stallman 本人文本证实（BSDTalk EP243，[447.54-518.64]，L2）
