## 61.9.1 Linux 的数据库生态主导地位

  **要点**：Linux 的数据库生态主导地位：（1）Linux 运行所有主流数据库服务器——Oracle Database（1998 年首次支持 Linux，Oracle 8 for Linux）、IBM DB2（1999 年支持 Linux）、Microsoft SQL Server（2017 年发布 SQL Server for Linux）、SAP HANA（自 2010 年代起仅支持 SUSE 与 RHEL）、MySQL、PostgreSQL、SQLite；（2）Linux 的 GPL 许可证与商业数据库的兼容性——GPL 与商业数据库服务器的客户端库许可证无冲突，使厂商优先支持 Linux；（3）Linux 容器生态主导数据库部署——Docker（2013-03 由 dotCloud 创始人 Solomon Hykes 在 PyCon 公开演示后开源）与 Kubernetes（2014-06 Google 发布 v0.1，2015-07 1.0 发布，CNCF 成立）推动云原生数据库部署；（4）Linux 在企业数据库市场份额自 2010 年代后期超过 Windows 与 Unix 之和 〔存疑：具体市场份额数据需多源交叉验证，不同来源统计口径差异较大，暂保留存疑〕；Linux 的主导地位反映商业支持与容器生态的综合优势

## 61.9.3 Solaris 的 Oracle 优化路径

  **要点**：Solaris 的 Oracle 优化路径：（1）Oracle Database 在 Solaris 上深度优化——Solaris 与 Oracle Database 的集成可追溯至 Solaris 2.x 时代（1990 年代），Oracle 收购 Sun（2010-01 完成收购）后强化 Solaris 优化；（2）Solaris 的 ZFS 文件系统（2005-01 随 Solaris 10 正式发布）与 Oracle Database 深度集成，提供快照、复制、校验和等数据完整性保障；（3）Solaris 的 DTrace 由 Bryan Cantrill（布莱恩·坎特里尔）、Michael Shapiro、Adam Leventhal 设计，2004 年 USENIX ATC 发表论文“Dynamic Instrumentation of Production Systems”（获最佳论文奖），2005-01 随 Solaris 10 正式发布，提供数据库性能分析；（4）2010-01 Oracle 收购 Sun 后，Solaris 的 Oracle 优化路径延续但市场逐步萎缩，Oracle Database 12c 后 Solaris 优先级下降；Solaris 的路径反映垂直整合哲学

  | Solaris Oracle 优化时间线 | 时间 | 事件 |
| ----------------------- | -- | -- |
| Solaris 2.x 集成 | 1990 年代 | Solaris 与 Oracle Database 的集成可追溯至此 |
| DTrace 论文发表 | **2004 年** | Cantrill、Shapiro、Leventhal 于 USENIX ATC（获最佳论文奖） |
| Solaris 10 正式发布 | **2005 年 1 月 31 日** | ZFS 与 DTrace 随 Solaris 10 正式发布 |
| Oracle 收购 Sun 完成 | **2010 年 1 月 27 日** | Oracle 强化 Solaris 优化 |
| Solaris 11.4 | **2018 年 8 月** | 最后一个主要版本 |
| Oracle Database 12c 后 | **2013 年** | Solaris 优先级下降 |

  | Solaris 关键技术 | 引入时间 | 与数据库的关系 |

## 61.9.4 BSD 数据库生态的实用主义边界

  **要点**：BSD 数据库生态的实用主义边界：（1）BSD 数据库生态以开源（PostgreSQL、MySQL、SQLite）为主，缺乏商业数据库服务器（Oracle Database、IBM DB2、Microsoft SQL Server、SAP HANA）原生支持；（2）BSD 的实用主义哲学——采用最佳工具而非宗教式坚持自研，体现于 FreeBSD 引入 ZFS（2007-04-06 by Pawel Jakub Dawidek，源自 Sun Solaris/CDDL）、导入 Heimdal 1.5（2011-10-05 by Stanislav Sedov），其依赖促成 base 引入 SQLite（2013-06-18 by Peter Wemm）等决策；（3）BSD 的实用主义边界反映其市场份额与商业支持的局限——商业数据库厂商基于市场份额决策不支持 FreeBSD，使 BSD 数据库生态以开源为主既是哲学选择也是市场约束的产物；（4）BSD 数据库生态的实用主义边界须与 Linux 的商业主导（Oracle/IBM/Microsoft/SAP 全面支持 + Docker/Kubernetes 容器生态）、Windows 的全栈（SQL Server + .NET）、Solaris 的垂直整合（Oracle + ZFS + DTrace）对比理解

  | BSD 实用主义决策表 | 时间 | 决策 | commit/版本 |
| ---------------- | -- | -- | --------- |
| 引入 ZFS | **2007 年 4 月 6 日** | 引入 Sun Solaris/CDDL 的 ZFS 而非自研文件系统 | `f0a75d27` by Pawel Jakub Dawidek |
| 导入 Heimdal 1.5 | **2011 年 10 月 5 日** | 由 Stanislav Sedov 导入 Heimdal 1.5，其依赖促成 base 于 2013-06-18 引入 SQLite（by Peter Wemm），而非自研嵌入式数据库 | by Stanislav Sedov |
| 引入 pkgng | **2014 年 1 月** | FreeBSD 10.0 默认使用 pkgng（SQLite 后端）而非坚持旧版 pkg_install | FreeBSD 10.0 Release |

  | 四象限对比：操作系统数据库生态 | 操作系统 | 路径 | 特征 |
| ---------------------------- | ------ | -- | -- |
| Linux | 商业主导 | Oracle/IBM/Microsoft/SAP 全面支持 + Docker/Kubernetes 容器生态 | |
| Windows | 商业全栈 | SQL Server + .NET | |
| Solaris | 垂直整合 | Oracle + ZFS + DTrace | |
| BSD | 开源主导 + 实用主义采用 | PostgreSQL/MySQL/SQLite + 采用最佳工具 | |

  | BSD 数据库生态的双重性质 | 维度 | 内容 |
| ---------------------- | -- | -- |
| 哲学选择 | 实用主义 | 采用最佳工具而非宗教式坚持自研 |
| 市场约束 | 商业数据库厂商基于市场份额决策 | 不支持 FreeBSD |
| 结果 | 开源为主 | PostgreSQL/MySQL/SQLite |
| 缺失 | 商业数据库服务器原生支持 | Oracle Database/IBM DB2/Microsoft SQL Server/SAP HANA |

**史观**：总纲第 10 条——动手者创造历史；总纲第 9 条——经验优先——BSD 数据库生态作为市场份额的边缘者（份额小但质量高），实用主义边界反映其基于实践（采用最佳工具）而非理论（市场份额或宗教式坚持自研）的哲学
