# 065.4.4 SQLite 在 BSD 嵌入式场景中的部署

  **要点**：SQLite 在 BSD 嵌入式场景中的部署：（1）FreeBSD 软件包元数据自 pkgng 起以 SQLite 为后端（FreeBSD 10.0 起 pkgng 默认），pfSense、OPNsense 等 FreeBSD 衍生防火墙在配置存储中使用 SQLite；（2）OpenBSD **spamd(8)** 不使用 SQLite——其数据库位于 **/var/db/spamd**，使用 OpenBSD 的 **db(3)** hash 接口（Berkeley DB 风格）而非 SQLite（man.openbsd.org/spamd 与 man.openbsd.org/spamdb 确认）；（3）NetBSD 的 pkgsrc 不使用 SQLite 作为包数据库后端——pkgsrc 使用 PLIST 文件与 metadata 目录树管理软件包信息，与 FreeBSD pkgng 的 SQLite 后端形成对比；（4）DragonFly BSD 的 HAMMER 文件系统从未考虑使用 SQLite——HAMMER 是 Matthew Dillon（马修·狄龙） 自研的 B-Tree 日志结构文件系统，与 SQLite 无工程关联，原大纲此陈述为无依据臆测，应删除

  | 四 BSD 嵌入式数据库选择对比 | 项目 | 选择 | 证据 |
| ------------------------- | -- | -- | -- |
| FreeBSD | pkgng | SQLite 后端 | FreeBSD 10.0 Release Notes、freebsd.duckdb（2011-10-05 by Stanislav Sedov） |
| OpenBSD | **spamd(8)** | **db(3)** hash 接口（Berkeley DB 风格），数据库位于 **/var/db/spamd** | man.openbsd.org/spamd 与 man.openbsd.org/spamdb 确认 |
| NetBSD | pkgsrc | PLIST 文件与 metadata 目录树 | pkgsrc.org 官方文档 |
| DragonFly BSD | HAMMER 文件系统 | 自研 B-Tree 日志结构文件系统 | Matthew Dillon 自研，与 SQLite 无工程关联 |

  | 原大纲修正 | 原表述 | 修正 |
| -------- | ---- | -- |
| OpenBSD **spamd(8)** | ~~使用 SQLite~~ | 使用 OpenBSD **db(3)** 接口，数据库位于 **/var/db/spamd** |
| NetBSD pkgsrc | ~~使用 SQLite 作为后端~~ | 基于 PLIST 与 metadata 目录的包管理框架 |
| DragonFly BSD HAMMER | ~~曾考虑使用 SQLite~~ | 无依据臆测，应删除；HAMMER 为自研 B-Tree 日志结构文件系统 |

  | FreeBSD 衍生防火墙 SQLite 部署 | 项目 | 用途 |
| ---------------------------- | -- | -- |
| pfSense | 配置存储 | 使用 SQLite |
| OPNsense | 配置存储 | 使用 SQLite |

**史料**：FreeBSD 10.0 Release Notes（pkgng 默认）、OpenBSD **spamd(8)** 与 **spamdb(8)** man 页（man.openbsd.org）、NetBSD pkgsrc 文档（pkgsrc.org）、DragonFly BSD HAMMER 文档 ［B］
  
**史观**：第 9 条经验优先与第 10 条动手者创造历史——SQLite 在 BSD 嵌入式场景的实际部署须基于代码级证据而非想当然的“哲学共鸣”，BSD 各项目对嵌入式数据库的选择反映各自的实用主义路径（FreeBSD 选 SQLite、OpenBSD 选 db(3)、NetBSD 选 PLIST 文件、DragonFly BSD 自研 B-Tree）
  
**辨析**：原大纲四项陈述中三项需修正——OpenBSD **spamd(8)** 数据库经 man.openbsd.org/spamd 与 man.openbsd.org/spamdb 确认为 **/var/db/spamd** 文件，使用 OpenBSD **db(3)** 接口（Berkeley DB 风格 hash 数据库），不使用 SQLite；NetBSD pkgsrc 经 pkgsrc.org 官方文档确认为基于 PLIST 与 metadata 目录的包管理框架，不使用 SQLite 作为后端；DragonFly BSD HAMMER 文件系统是 Matthew Dillon 自研的 B-Tree 日志结构文件系统，与 SQLite 无工程关联，原大纲“曾考虑使用 SQLite”为无依据臆测，应删除；FreeBSD pkgng 使用 SQLite 经 FreeBSD 10.0 Release Notes 与 freebsd.duckdb 查询确认（freebsd-src 首次引入 SQLite 为 2011-10-05 by Stanislav Sedov 作为 Heimdal 1.5 依赖），pfSense/OPNsense 等 FreeBSD 衍生防火墙在配置存储中使用 SQLite 为多源一致事实；此修正体现 0 信任原则——原大纲将 SQLite“嵌入式”特征推广至所有 BSD 子项目，但实际各项目根据自身需求选择不同技术路径
