# 062.2.3 rough consensus 哲学与 BSD 传统的共鸣

  **要点**：IETF 的 “rough consensus and running code” 哲学（由 Dave Clark 1992 年 IETF 会议名言概括）强调：（1）rough consensus（粗略共识）而非全体一致，避免少数阻挠；（2）running code（可运行代码）而非纯理论，强调实践验证；此哲学与 BSD 工程传统（CSRG 的 “先跑起来再谈标准”）深度共鸣，BSD 的 TCP/IP 实现成为 IETF 标准的参考实现，IETF 多个协议（如 SMTP、FTP、Telnet）以 BSD 实现为基础

  | IETF 哲学要素 | 含义 | 与 BSD 传统的共鸣 |
| ----------- | -- | --------------- |
| rough consensus（粗略共识） | 不要求全体一致，由工作组主席判断是否达成大致共识，避免少数阻挠 | 与 BSD 工程传统的 “先跑起来再谈标准” 共鸣 |
| running code（可运行代码） | 强调实践验证而非纯理论 | 与 CSRG 的 “实践先于理论” 深度共鸣 |
| 名言出处 | Dave Clark **1992 年** IETF 会议 | Clark 系 IAB 成员、首任主席（1981-1989 在任） |

  | BSD 实现作为 RFC 标准参考的案例 | RFC | 内容 |
| ----------------------------- |---| -- |
| 4.2BSD TCP/IP 实现 | RFC 1122 | “Requirements for Internet Hosts”（**1989**） |
| BSD 套接字 API | POSIX IEEE Std 1003.1g | 标准化（详见 23.5.4） |
| BIND（DNS） | 对应 RFC | 事实参考 |
| Sendmail（SMTP） | 对应 RFC | 事实参考 |

**史观**：总纲第 9 条——经验优先——IETF 的 “running code” 哲学与 BSD 的 “实践先于理论” 史观共鸣，二者共同反对形式主义
  
**辨析**：Dave Clark“rough consensus and running code”名言的具体出处——多源指向 1992 年 IETF 会议，Clark 系 IAB 成员、首任主席（1981-1989 在任），此名言概括 IETF 标准制定的实践哲学；“rough consensus”（粗略共识）的含义为“不要求全体一致，由工作组主席判断是否达成大致共识，避免少数阻挠”，与正式投票制形成对比；BSD 实现作为 RFC 标准参考的具体案例——4.2BSD TCP/IP 实现（1983.8）被后续 RFC（如 RFC 1122 Host Requirements）引用为参考实现，BSD 套接字 API 被 POSIX IEEE Std 1003.1g 标准化（详见 23.5.4），BIND（DNS）、Sendmail（SMTP）的 BSD 实现成为对应 RFC 的事实参考
