# 064.2.4 要点BINDBerkeleyInternetNameDomain伯克利CSRG四

  **要点**：BIND（Berkeley Internet Name Domain，伯克利 CSRG 四名研究生 Terry/Painter/Riggle/Zhou 1984 年开发，DNS 协议 RFC 882/883 1983 年 11 月标准化）与 Sendmail（1983 年随 4.2BSD 正式发布）长期主导互联网 DNS 与邮件传输市场，但 1990 年代后期两者均面临严重安全挑战——BIND 4.9.x 1990 年代后期多个远程漏洞；BIND 8.2.x 1999 年发现 NXT/SIG/SO_LINGER 等多个漏洞（CERT Advisory CA-1999-14）；Dan Kaminsky 2008 年披露的 DNS 缓存投毒漏洞系 DNS 协议设计层缺陷（事务 ID 与源端口可预测性），影响多数 DNS 实现而非仅限于 BIND；BIND 9（2000 年发布，ISC 维护）虽完全重写但仍持续面临安全挑战；Sendmail 1988 年 Morris 蠕虫利用 DEBUG 后门，1990 年代至 2003 年持续发现远程溢出漏洞；BIND/Sendmail 安全事件后替代方案兴起——PowerDNS（1999 年 Bert Hubert 发布，GPL）、Unbound（2007 年 NLnet Labs 发布，BSD 许可证，DNSSEC 验证解析器）、NSD（2003 年 NLnet Labs 发布，BSD 许可证，权威域名服务器）、Postfix（1998 年 Wietse Venema 发布，IBM Public License，原名 VMailer）、qmail（1995 年 Daniel J. Bernstein 发布，自定义免费许可）等；BIND/Sendmail 在 1990 年代后期的 “主导地位” 被 “淘汰” 为多元并存格局，但 BIND 9 与 Sendmail 在 BSD 与 Linux DNS/邮件服务器市场仍保留一定份额；这一多元替代格局后被 Linux 2000 年代后 systemd-resolved（2014 年起，DNS 解析器整合）等部分继承但本质已分化

**史观**：第 2 条形式主义——BIND/Sendmail 的 “主导地位” 形式逻辑吞并了安全实质，形式便利膨胀为安全风险，安全事件后多元替代方案兴起；第 5 条偶然性——BIND/Sendmail 安全事件的具体时间点是偶然的，但此偶然叠加互联网规模扩大，使安全风险被显性化
  
**辨析**：BIND/Sendmail 被 “淘汰” 指主导地位被多元替代方案挑战，而非完全弃用——BIND 9 与 Sendmail 在 BSD 与 Linux 中仍保留一定份额，须区分 “主导地位退场” 与 “完全弃用”；Dan Kaminsky 2008 年漏洞（CERT VU#800113）是 DNS 协议设计层缺陷（事务 ID 仅 16 位 + 源端口固定），影响所有未实现源端口随机化的 DNS 实现，并非早期 BIND 8.2 漏洞的延续，二者性质不同；Postfix/qmail/Exim 替代 Sendmail 的具体份额在不同年份与不同地区差异显著，须以统计资料为准
