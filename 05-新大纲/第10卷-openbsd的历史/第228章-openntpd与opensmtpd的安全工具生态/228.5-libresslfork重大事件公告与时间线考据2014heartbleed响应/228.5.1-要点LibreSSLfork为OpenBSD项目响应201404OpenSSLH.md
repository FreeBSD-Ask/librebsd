# 228.5.1 要点LibreSSLfork为OpenBSD项目响应201404OpenSSLH

**要点**：LibreSSL fork 为 OpenBSD 项目响应 2014-04 OpenSSL Heartbleed 漏洞（CVE-2014-0160）的重大事件公告，须严格区分三阶段时间线——（1）Heartbleed 漏洞爆发：2014-04-07 OpenSSL 官方发布安全公告 CVE-2014-0160，披露 Heartbleed 漏洞允许远程读取服务器内存；（2）OpenBSD fork 决议：2014-04 OpenSSL Heartbleed 事件后，OpenBSD 开发者（Bob Beck 等）随即启动 LibreSSL fork 项目，fork 决议确为 2014-04，但此时仅为项目启动而非发布；（3）LibreSSL 首次 portable 发布：2014-07-11 LibreSSL portable 首个版本发布，提供 OpenBSD 之外的 portable 版本；LibreSSL 首页（<https://www.libressl.org/>）作为公告 URL；LibreSSL 在 OpenBSD 5.6（2014-11-01）成为 OpenBSD 默认 TLS 库，取代 OpenSSL；LibreSSL fork 体现 OpenBSD“主动审计 + 重写而非补丁”的工程哲学——OpenBSD 阵营认为 OpenSSL 代码质量低劣至无法修补，须 fork 后重写而非补丁修复，这一立场区别于 OpenSSL 阵营的“补丁修复 + 资金注入”改革路线；统计结论印证——openbsd.duckdb openbsd-src 仓库总 commit 数 245,904（统计结论 C-05，2026-07-27 报告口径截点；2026-09-12 核查实测现行库为 246,535，差 631 系后续增量），Heartbleed 披露（2014-04-07）后的安全审计 commit 构成其中一部分，LibreSSL 相关 commit 则始于 2014-04-22 fork 宣议之后；NVD OpenBSD 相关 CVE 共 168 个（外部基准 E-22），OpenBSD 平均 CVSS 评分 6.17（外部基准 E-27），Heartbleed（CVE-2014-0160 CVSS 7.5）作为触发 LibreSSL fork 的关键事件，其 CVSS 评分高于 OpenBSD 平均 CVSS，反映 Heartbleed 在 OpenBSD 安全史中的相对严重性

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧：LibreSSL fork 是革命路线的标志性事件——OpenBSD 阵营以 fork 重写而非补丁修复的方式回应 Heartbleed，区别于 Linux Foundation Core Infrastructure Initiative（CII）资助 OpenSSL 补丁修复的改革路线；总纲第 15 条——文化即形式主义：“LibreSSL 是 OpenBSD 对 Heartbleed 的英勇响应”叙事在 OpenBSD 社区被形式主义化为革命路线的合法性证明，但这一形式主义化使 LibreSSL 在 portable 采用率上的市场失败被遮蔽——LibreSSL 在 OpenBSD 之外的市场采用率长期低于 OpenSSL，证明 fork 路线在工程哲学上具有合理性但在市场生态上面临挑战；总纲第 13 条——法律与道德是利益分配：LibreSSL fork 与 CII 资金流向 OpenSSL 而非 LibreSSL 的对比，反映“革命路线 + 社区维护”与“改革路线 + 基金会资助”两种利益分配模式的竞争——OpenSSL 阵营通过 CII 资金注入维持改革路线的市场主导，LibreSSL 阵营通过 OpenBSD Foundation 维持革命路线的工程独立，二者在 2014-2026 年间各自呈现而非一方胜利；总纲第 19 条——解释学循环是历史认识的根本条件：LibreSSL fork 的历史认识受前理解差异制约——OpenBSD 阵营以“代码质量至上”为前理解（fork 决议即为先前理解的显现），OpenSSL 阵营以“生态兼容性至上”为前理解（CII 资金注入即为先前理解的显现），二者难以通约；统计结论印证——C-05 openbsd-src 总 commit 数 245,904 与 E-22 OpenBSD CVE 168 个的对照反映“分离聚合是永恒规律”（总纲第 4 条）的安全显现——commit 量反映工程节奏，CVE 数量反映外部安全压力，二者共同构成 OpenBSD 安全审计文化的双重证据；E-27 平均 CVSS 6.17 反映“经验优先”（总纲第 9 条）的统计显现——CVSS 评分是事后评估，反映 OpenBSD 在实际安全事件中的相对严重性分布

OpenSSL 官网存档核验；（3）OpenBSD 5.6 release 页面 <https://www.openbsd.org/56.html> 经 OpenBSD 官网核验载明 LibreSSL 为默认 TLS 库；（4）<announce@openbsd.org> 邮件列表存档（marc.info）可交叉验证 LibreSSL 相关公告的发布时间；（5）openbsd.duckdb openbsd-src 仓库 commits 表可交叉验证 LibreSSL 代码提交的时间序列，但 tags 表无 openbsd 仓库的 release tag；【交叉验证方法】Heartbleed 漏洞爆发日期以 OpenSSL 官方安全公告为准；LibreSSL fork 决议日期以 OpenBSD 邮件列表讨论时间为准（2014-04 内，精确到日存疑）；LibreSSL 首次 portable 发布日期以 libressl.org 官网与 OpenBSD 邮件列表交叉验证（2014-07-11）；LibreSSL 成为 OpenBSD 默认 TLS 库以 OpenBSD 5.6 release 页面为准（2014-11-01）；【任务描述日期修正】任务描述曾作“OpenSSL fork 为 LibreSSL（2014-04）”，其中 2014-04 为 Heartbleed 漏洞爆发月份，非 LibreSSL 首次发布月份。LibreSSL 首次 portable 发布为 2014-07-11。fork 决议确为 2014-04，但首次发布为 2014-07，须区分“决议 fork”与“首次发布”两个时间点；【0 信任原则·fork 决议日期的存疑】LibreSSL fork 决议的精确日期在 OpenBSD 官方文档中未明确标注，2014-04 内置版本的开发节奏不同——portable 版本发布晚于 OpenBSD 内置版本，2014-07-11 为 portable 首次发布，OpenBSD 内置 LibreSSL 在 5.6（2014-11-01）正式成为默认，二者不可混淆；【反模糊原则】LibreSSL fork 的历史意义不应被简化为“OpenBSD 救了 OpenSSL”或“LibreSSL 失败了”的二元叙事——LibreSSL 在 OpenBSD 内成功取代 OpenSSL 为默认 TLS 库，在 portable 市场采用率低于 OpenSSL，二者是同一 fork 事件的不同侧面；**统计局限性标注**——E-22 NVD OpenBSD CVE 数量 168 个基于 NVD CPE 命名匹配，受 NVD CPE 命名不完整局限影响（部分 OpenBSD 漏洞可能未在 NVD
