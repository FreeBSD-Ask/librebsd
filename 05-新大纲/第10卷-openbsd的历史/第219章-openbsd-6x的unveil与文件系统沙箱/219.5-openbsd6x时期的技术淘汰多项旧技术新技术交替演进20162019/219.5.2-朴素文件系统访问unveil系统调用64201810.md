# 219.5.2 朴素文件系统访问 → unveil 系统调用（6.4，2018.10）

**要点**：OpenBSD 6.4（2018-10-25 发布）引入 **unveil(2)** 系统调用，由 Bob Beck 设计实现（openbsd.duckdb 显示 2018-07-13 beck commit 8b23add8c74b 首次引入，初始禁用，6.4 release 前启用）；unveil 与 pledge 配合形成双重沙箱——pledge 限制系统调用类别，unveil 限制文件系统访问路径；OpenBSD 自带工具（如 **tcpdump(1)**、**nc(1)**、**ftp(1)**）普遍使用 pledge+unveil；可视为“无文件系统访问限制 → 路径级访问限制”的替代

**史料**：openbsd.duckdb openbsd-src 仓库 commit 8b23add8c74b（2018-07-13 beck“Unveiling unveil(2)”）；OpenBSD 6.4 Release Notes unveil 部分（<https://www.openbsd.org/64.html>）；**unveil(2)** 手册页（<https://man.openbsd.org/unveil.2>）；tech@ 邮件列表 unveil 讨论（<https://marc.info/?laccopenbsd-tech>）

**史观**：专题语（不设总纲条号）——unveil 是“最小权限”原则在文件系统访问中的实现——将文件系统安全约束从全局权限转移至程序自身声明，与 pledge 的系统调用约束形成正交组合

**辨析**：unveil 的引入版本以 openbsd.duckdb commit 8b23add8c74b（2018-07-13 beck）与 OpenBSD 6.4 Release Notes 为准——首次 commit 为 2018-07-13，随 6.4（2018-10-25）正式发布；unveil 与 pledge 的协作机制以 **pledge(2)** 与 **unveil(2)** 手册页为准——pledge 限制系统调用类别，unveil 限制文件路径，二者正交组合；pledge+unveil 的实际防护效果以 OpenBSD Security Advisories 中记录的漏洞影响范围为准
