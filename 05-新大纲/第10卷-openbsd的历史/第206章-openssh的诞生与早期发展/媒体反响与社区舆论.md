### 新闻条目 3

- **新闻标题（中英）**：OpenSSH 9.8 修复 CVE-2024-6387（regreSSHion）——OpenBSD 不受影响（OpenSSH 9.8 fixes CVE-2024-6387 “regreSSHion”——OpenBSD is not vulnerable）
- **新闻来源**：OpenSSH 官方发布说明 + 2024-07-01 + URL: <https://www.openssh.com/txt/release-9.8>
- **新闻摘要**：OpenSSH 9.8 于 2024-07-01 发布，修复两个安全问题。其中 CVE-2024-6387（被 Qualys 命名为 “regreSSHion”）是 sshd(8) 中的关键竞争条件漏洞，影响 Portable OpenSSH 8.5p1 至 9.7p1（含），可能允许任意代码执行并获得 root 权限。Qualys 在 32 位 Linux/glibc 系统上实验室条件下演示成功利用，平均需要 6-8 小时持续连接。64 位系统利用被认为可能但未演示。OpenSSH 9.8 release notes 明确指出 “OpenBSD is not vulnerable”——这是由于 OpenBSD 的信号处理实现与可执行地址空间布局（W^X、地址空间随机化等）阻断了利用路径。Qualys 安全公告团队发现并报告该漏洞，提供详细利用演示与额外缓解措施反馈。第二个较轻漏洞是 ssh(1) ObscureKeystrokeTiming 逻辑错误（影响 9.5-9.7），由 Philippos Giavridis 与剑桥大学计算机实验室 Jacky Wei En Kung 等独立发现。release notes 还预告 2025 年初将完全移除 DSA 签名算法支持。CVE-2024-6387 在中国媒体（头条、掘金、长亭百川云等）大量报道，但多聚焦 Linux 利用，对 “OpenBSD 不受影响” 这一关键事实常被淡化。
- **与本章主题的关联说明**：本章叙述 OpenSSH（1999-2026），2024-07-01 CVE-2024-6387 与 OpenSSH 9.8 是本章 “OpenSSH 安全演进” 叙事的最新节点，体现 OpenBSD base 中 OpenSSH 的安全优势（不受影响）与 portable 版本的差异化风险。
- **与官方史料的交叉验证结论**：OpenSSH 9.8 release notes（openssh.com/txt/release-9.8）与 NVD CVE-2024-6387 条目一致；与 Qualys 安全公告原文（blog.qualys.com）互证；与 OpenBSD errata 同期条目互证——OpenBSD base 中 OpenSSH 无需 syspatch（因不受影响），portable 版本需升级至 9.8p1。一致采纳。

- **新闻摘要**：OpenSSH 项目历史官方叙述：1999 年 OpenBSD 开发者发现 Björn Grönvall 的 OSSH（基于 Tatu Ylönen 的 ssh 1.2.12 最后自由版本）后，决定在 OpenBSD 2.6 发布前两个月内 fork OSSH 并进行快速安全审计。初始 import 于 1999-09-26 完成，发布时部分源文件 RCS 修订号已达 1.34 至 1.66。团队分工：Theo de Raadt（移除非可移植代码以简化源码）、Niels Provos（前往加拿大移除加密与 GPL 组件以实现完全自由可重用）、Markus Friedl（替换 SSH 1.3 协议为 SSH 1.5、后添加 SSH 2 与 SFTP）、Bob Beck（处理 Makefile 与 OpenSSL 无 RSA 专利算法编译）、Aaron Campbell（改进文档）、Dug Song（Kerberos IV 认证）。OpenSSH 1.2.2 于 1999-12-01 随 OpenBSD 2.6 发布，移除所有专利组件，支持 skey 一次性口令认证。OpenBSD 2.6 因 RSA 专利未到期，CD 中 libssl/libcrypto 共享库缺失 RSA，安装时用户可通过 FTP/HTTP 替换。

- **与本章主题的关联说明**：本章叙述 OpenSSH（1999-2026），2014-04-29 OpenSSH 编译可选 OpenSSL 是本章 “OpenSSH 工程独立性” 叙事的核心节点，体现 OpenSSH 在 Heartbleed 后对加密库依赖的解耦。
