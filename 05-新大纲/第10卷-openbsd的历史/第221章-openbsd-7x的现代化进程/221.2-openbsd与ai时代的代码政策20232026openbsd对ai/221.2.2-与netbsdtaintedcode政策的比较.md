# 221.2.2 与 NetBSD tainted code 政策的比较

**要点**：NetBSD Foundation 于 2024-05-17 在 NetBSD Commit Guidelines 第 2 条正式加入 “tainted code” 条款——“由大语言模型或类似技术（如 GitHub/Microsoft Copilot、OpenAI ChatGPT、Facebook/Meta Code Llama）生成的代码被视为受污染代码（tainted code），未经 Core Team 事先书面批准不得提交”；NetBSD 政策比 OpenBSD 更正式化——以书面条款写入 Commit Guidelines；OpenBSD 通过 committer 政策与 de Raadt 的 misc@ 发言间接限制 AI 代码，未形成正式书面条款

  **三大 BSD AI 代码政策对比**：

  | 项目 | 政策形式 | 治理机制 | 严格程度 | 可考据性 |
  | --- | --- | --- | --- | --- |
  | OpenBSD | 非正式（BDFL 发言） | BDFL 制（de Raadt） | 间接限制（commit 须注明可考据作者） | 弱（须检索邮件列表存档） |
  | NetBSD | 正式书面条款（Commit Guidelines 第 2 条） | Core Team 委员会制 | 正式禁止（未经书面批准不得提交） | 强（可查阅文档） |
  | FreeBSD | 无明确条款 | Core Team 选举制 | 允许自行判断（committer 负责） | 无（无政策文本） |

**史料**：NetBSD Commit Guidelines 第 2 条（<https://www.netbsd.org/developers/commit-guidelines.html>，"Code generated by a large language model or similar technology, such as GitHub/Microsoft‘s Copilot, OpenAI’s ChatGPT, or Facebook/Meta's Code Llama, is presumed to be tainted code, and must not be committed without prior written approval by core "）；IT 之家 2024-05-17 报道（<https://cloud.tencent.com.cn/developer/news/1400568>）；OpenBSD committer 政策文档〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 3 条——不存在进步，只有权力再分配：NetBSD 通过 Core Team 委员会决策将 AI 代码禁令正式写入 Commit Guidelines，OpenBSD 通过 de Raadt 个人发言间接限制——两种治理机制（委员会制 vs BDFL 制）对同一问题（AI 代码）的不同回应，实质是政策制定权在委员会集体与个人权威之间的权力再分配差异的显现
