# 221.3.3 与 FreeBSD/NetBSD 权限模型的比较

**要点**：FreeBSD 通过 Core Team 选举与 commit bits 分级管理权限，NetBSD 通过 Core Team 与 pkgsrc 等子项目分离权限；OpenBSD 由 de Raadt 个人主导，无 Core Team 选举；三种权限模型反映项目治理文化差异

  **三大 BSD 权限模型对比**：

  | 项目 | 权限模型 | 准入机制 | 撤销机制 | 治理文化 |
  | --- | --- | --- | --- | --- |
  | OpenBSD | BDFL 制（de Raadt 主导） | 现有 committer 推荐 + de Raadt 批准 | de Raadt 个人决定 | 个人权威优先 |
  | FreeBSD | Core Team 选举制 | Core Team 集体审议 | Core Team 投票 | 集体审议优先 |
  | NetBSD | Core Team + 子项目分离制 | 子项目负责人推荐 + Core Team 批准 | Core Team 决议 | 领域自治优先 |

**史料**：FreeBSD Core Team 选举记录（<https://www.freebsd.org/internal/core-team/>）；NetBSD Core Team 选举记录（<https://www.netbsd.org/foundation/>）；OpenBSD committer 权限记录 ［A］

**史观**：组织结构塑造技术路径：三大 BSD 项目权限模型差异是各自组织结构的显现——FreeBSD 的 Core Team 选举制使 committer 准入经委员会审议，NetBSD 的 Core Team + 子项目分离制使不同子项目有不同准入标准，OpenBSD 的 BDFL 制使准入集中于单一领导者

**辨析**：FreeBSD Core Team 选举的实际影响力以 FreeBSD Core Team bylaws 与历史决策记录为准——Core Team 负责技术争议裁决与 committer 权限管理，实权较大；三种模型的优劣以各自项目的历史事件（如冲突解决、权限撤销）为评价依据，无绝对优劣
