# 225.11.1 故障类


> 本子节汇总与本章主题相关的新闻报道与社区舆论，按“故障类 / 冲突类 / 里程碑事件类”三类组织。所有新闻条目遵循 0 信任原则，须与官方史料交叉验证后方可采信。

### 新闻条目 1

- **新闻标题（中英）**：SSH Protocol 1 Now Disabled at Compile Time（SSH 协议 1 现在编译期默认禁用）
- **新闻来源**：undeadly.org + pitrh（Peter Hessler）署名 + 2015-03-24 + URL: <https://undeadly.org/cgi?action=article;sid=20150324200217>
- **新闻摘要**：undeadly.org 2015-03-24 报道 Damien Miller（达米安·米勒）（djm@）在 tech@ 邮件列表（<https://marc.info/?l=openbsd-tech&m=142716088814469>）宣布提交 commit 在 src/usr.bin/ssh/Makefile.inc 中编译期禁用 SSH 协议 1。Damien Miller 说明：协议 1 陈旧不安全，不应再使用；如确有需要可通过 Makefile.inc 中的开关重新启用；变更在发布周期早期进行以便发现 bug 与残留使用。undeadly.org 评论中 Renaud Allard 表示 “还在用 ssh1 的人不如直接用 telnet”。这一变更是 OpenSSH 全面弃用 SSH 协议 1 的关键步骤，为 OpenSSH 后续版本移除 DSA 与协议 1 铺垫（OpenSSH 9.8（2024-07-01）发布时仅默认编译期禁用 DSA 并预告 2025 年初完全移除，正式移除见后续版本）。
- **与本章主题的关联说明**：本章叙述 OpenSSH（1999-2026），2015-03-24 SSH 协议 1 编译期默认禁用是本章 “OpenSSH 安全演进” 叙事的核心节点，体现 OpenSSH 对陈旧协议的渐进式弃用策略。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 Damien Miller 的 tech@ 邮件列表原文（<https://marc.info/?l=openbsd-tech&m=142716088814469>）完全一致；与 OpenBSD 5.7（2015-05-01）changelog 中 SSH 协议 1 禁用条目互证；与 OpenSSH 6.8 release notes 中 “Support --without-ssh1 option at configure time” 互证。一致采纳。

### 新闻条目 2

- **新闻标题（中英）**：OpenSSH to Replace SunSSH（OpenSSH 将替换 SunSSH）
- **新闻来源**：undeadly.org + tbert 署名 + 2015-07-08 + URL: <https://undeadly.org/cgi?action=article;sid=20150708070412>
- **新闻摘要**：undeadly.org 2015-07-08 报道 Solaris 原 SSH 实现负责人 Darren Moffat 在 Oracle 博客（blogs.oracle.com/darren/entry/openssh_in_solaris_11_3）宣布 SunSSH fork 将逐步淘汰，Solaris 11.3 起除 SunSSH 外同时提供 OpenSSH，未来版本将完全移除 SunSSH 仅保留 OpenSSH。Moffat 承认 “虽然我们定期与 OpenSSH 同步特性与 bug 修复，但 SunSSH 始终是一个 fork”。同期 Solaris 还将 PF 防火墙作为 IPF 的替代引入（undeadly.org 2015-04-15 报道）。这一事件体现专有厂商对 OpenBSD 衍生技术的双重采纳（SSH 与 PF），印证 OpenBSD “通过最小化实现与严格审计创造可被广泛复用的基础组件” 的项目定位。
- **与本章主题的关联说明**：本章叙述 OpenSSH（1999-2026），2015-07-08 Solaris 11.3 改用 OpenSSH 是本章 “OpenSSH 行业标准化” 叙事的核心节点，标志 OpenSSH 成为 UNIX 生态事实标准。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 Darren Moffat 的 Oracle 博客原文（blogs.oracle.com/darren/entry/openssh_in_solaris_11_3）完全一致；与 Solaris 11.3 发行说明互证；与同期 Solaris 引入 PF（undeadly.org 2015-04-15）形成 OpenBSD 技术采纳链。一致采纳。

### 新闻条目 3

- **新闻标题（中英）**：OpenSSH 9.8 修复 CVE-2024-6387（regreSSHion）——OpenBSD 不受影响（OpenSSH 9.8 fixes CVE-2024-6387 “regreSSHion”——OpenBSD is not vulnerable）
- **新闻来源**：OpenSSH 官方发布说明 + 2024-07-01 + URL: <https://www.openssh.com/txt/release-9.8>
- **新闻摘要**：OpenSSH 9.8 于 2024-07-01 发布，修复两个安全问题。其中 CVE-2024-6387（被 Qualys 命名为 “regreSSHion”）是 sshd(8) 中的关键竞争条件漏洞，影响 Portable OpenSSH 8.5p1 至 9.7p1（含），可能允许任意代码执行并获得 root 权限。Qualys 在 32 位 Linux/glibc 系统上实验室条件下演示成功利用，平均需要 6-8 小时持续连接。64 位系统利用被认为可能但未演示。OpenSSH 9.8 release notes 明确指出 “OpenBSD is not vulnerable”——这是由于 OpenBSD 的信号处理实现与可执行地址空间布局（W^X、地址空间随机化等）阻断了利用路径。Qualys 安全公告团队发现并报告该漏洞，提供详细利用演示与额外缓解措施反馈。第二个较轻漏洞是 ssh(1) ObscureKeystrokeTiming 逻辑错误（影响 9.5-9.7），由 Philippos Giavridis 与剑桥大学计算机实验室 Jacky Wei En Kung 等独立发现。release notes 还预告 2025 年初将完全移除 DSA 签名算法支持。CVE-2024-6387 在中国媒体（头条、掘金、长亭百川云等）大量报道，但多聚焦 Linux 利用，对 “OpenBSD 不受影响” 这一关键事实常被淡化。
- **与本章主题的关联说明**：本章叙述 OpenSSH（1999-2026），2024-07-01 CVE-2024-6387 与 OpenSSH 9.8 是本章 “OpenSSH 安全演进” 叙事的最新节点，体现 OpenBSD base 中 OpenSSH 的安全优势（不受影响）与 portable 版本的差异化风险。
- **与官方史料的交叉验证结论**：OpenSSH 9.8 release notes（openssh.com/txt/release-9.8）与 NVD CVE-2024-6387 条目一致；与 Qualys 安全公告原文（blog.qualys.com）互证；与 OpenBSD errata 同期条目互证——OpenBSD base 中 OpenSSH 无需 syspatch（因不受影响），portable 版本需升级至 9.8p1。一致采纳。
