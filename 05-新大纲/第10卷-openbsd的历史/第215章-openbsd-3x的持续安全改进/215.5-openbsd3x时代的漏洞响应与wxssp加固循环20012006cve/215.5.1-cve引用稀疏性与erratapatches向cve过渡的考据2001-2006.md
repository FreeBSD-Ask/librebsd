# 215.5.1 CVE 引用稀疏性与 errata patches 向 CVE 过渡的考据（2001-2006）

**要点**：openbsd.duckdb openbsd-src 仓库在 2001-06-01 至 2006-11-01 期间有 CVE 相关 commit 5 条，去重 CVE 4 条（全部无 CVSS v3 评分），Security fix commit（无 CVE）14 条，早期漏洞补遗 6 条；4 条 CVE 为 CVE-2005-3352（Apache mod_imap 跨站脚本，robert 修复）、CVE-2006-0225（OpenSSH 本地任意命令执行，djm 修复）、CVE-2006-3918（Apache 不支持 Expect 头的错误响应转义缺陷，djm 修复）、CVE-2006-4339（OpenSSL libcrypto RSA 签名填充缺陷，djm 修复）；14 条 Security fix commit 涵盖 OpenSSL 0.9.7a 安全公告（markus commit）、Apache CAN-2002-0840 跨站脚本（henning commit）、zlib CAN-2004-0797（djm commit）等；CVE 引用稀疏反映 OpenBSD commit message 习惯不以 CVE 编号为主轴，仍以 errata patches 存档为漏洞公告主渠道。

**史观**：总纲第 12 条——科学是形式主义（原“形式主义化”系自撰泛称，按机制级防御论旨改挂，存疑）：W^X（3.1）与 SSP（3.3）的引入标志着 OpenBSD 从“逐漏洞修补”向“机制级主动防御”的形式主义化跃迁——漏洞修复不再是终点，而是触发加固重构的起点；总纲第 10 条——动手者创造历史（原“边缘者贡献”系伪名目，正名）：djm 一人修复了 4 条 CVE 中的 3 条，体现 OpenBSD 安全响应高度依赖核心开发者

**辨析**：4 条 CVE 全部无 CVSS v3 评分——NVD 未为其提取 v3 评分，不可臆造评分；CVE-2006-0225 的“本地任意命令执行”具体利用路径（`local/local` 与 `remote/remote` 的区别）须对照 djm commit message 核验；CVE-2006-4339 的 RSA 签名填充缺陷涉及 OpenSSL 上游还是 OpenBSD 本地实现须区分
