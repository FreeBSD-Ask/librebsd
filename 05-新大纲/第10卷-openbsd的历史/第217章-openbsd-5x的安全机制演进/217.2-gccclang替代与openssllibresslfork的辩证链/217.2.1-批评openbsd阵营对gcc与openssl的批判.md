# 217.2.1 批评：OpenBSD 阵营对 gcc 与 OpenSSL 的批判

**要点**：OpenBSD 阵营对 gcc 与 OpenSSL 的批判集中在两个层面。第一层面是 gcc 批判——延续 86.12 的论述，OpenBSD 在 5.6-5.7 周期（2014-2015）于 ports 层推进 gcc→clang/LLVM 切换（base 层默认化经 openbsd.duckdb 实查集中于 2016-09 至 2017 年 commits，6.0-6.1 周期完成，6.1（2017-04）将 Clang 引入为基础编译器），批判动因包括 GPLv3 与 ISC 许可证哲学冲突（许可证因素）与 gcc 4.x 代码质量、诊断信息劣于 clang（技术因素）；openbsd.duckdb 显示 2014-10-23 brad commit 6ad07a3f66f922604b423b6f0c03f220ffafd886 提及“Now that gcc2 is gone”，2015-01-04 daniel commit 84938a7b9c572efc85c2b06e24f6122d8cc98702“remove code for ancient gcc”，2015-02-15 miod commit 1c93e2863e3b9f1c0c7e436e2db3db4debd0d628“Remove ancient gcc workaround on mips”持续清理 gcc 残留；第二层面是 OpenSSL 批判——2014 年 4 月 Heartbleed 漏洞（CVE-2014-0160）暴露 OpenSSL TLS heartbeat 扩展的缓冲区越界读取缺陷，OpenBSD 团队 Beck、jsing、miod、djm、reyk 等当即响应（2014-04-07 djm commit af0b15b8442f cherry-pick Heartbleed fix，2014-04-13 miod commit 9eac5592c816 导入 OpenSSL 1.0.1g，2014-04-13 reyk 移除 OpenSSL Atalla/AEP 引擎，2014-04-14 beck 移除 OPENSSL_SYS_XXX 残留）；Beck 与 jsing 主张 OpenSSL 工程质量存在结构性问题（dead code 跨版本积累、维护流程不透明、API 复杂度过高），应通过 fork 重新设计；de Raadt 在 misc@ 邮件列表主张 fork 是必要的“重新设计”而非修补；LibreSSL 作为独立库于 2014-07-12 jsing commit b6553af36068 首次提交，随 OpenBSD 5.6（2014.11）作为默认 TLS 库发布

**史观**：总纲第 13 条——法律与道德是利益分配（原“法律结构”系自创名目，按报告处方重挂）：LibreSSL fork 是 OpenBSD 对 OpenSSL 工程失败的回应，选择 fork 而非合作是 OpenBSD 许可证纯洁性哲学（ISC 偏好）的实践；专题语（不设总纲条号）——密码学库的工程质量批判：Heartbleed 暴露密码学库的工程质量问题，OpenSSL 作为全球 HTTPS 基础设施的核心组件，其代码质量与安全关键性不匹配，这一矛盾催生 LibreSSL fork

**辨析**：考据过程留痕——【查证来源】Heartbleed 漏洞的技术细节经 heartbleed.com 官网一手核验（CVE-2014-0160 确认为官方编号，TLS heartbeat 扩展 RFC 6520 的 payload length 字段未校验导致缓冲区越界读取，攻击者可读取服务器进程内存最多 64KB 数据）；LibreSSL 官网（<https://www.libressl.org/>）确认“LibreSSL is a version of the TLS/crypto stack forked from OpenSSL in 2014”；OpenBSD 5.6 Release Notes（<https://www.openbsd.org/56.html>）确认 5.6（2014.11.1 发布）引入 LibreSSL 作为默认 TLS 库，移除 Atalla/AEP 等引擎；openbsd.duckdb openbsd-src 仓库验证 6 个关键 commit hash 全部真实存在——af0b15b8442fc07b247a220f2f1870ce2652ec68（2014-04-07T23:57:27Z djm“cherrypick fix for CVE-2014-0160‘heartbleed’vulnerability from OpenSSL git; ok sthen@”）、9eac5592c81620ead272fa71be9a79e0e24176fe（2014-04-13T15:16:32Z miod“Import OpenSSL 1.0.1g”）、b6553af360687681cf2edd0462090e9c76c35110（2014-07-12T01:20:24Z jsing“Initial version of libressl - a library that provides a clean, simple, consistent and secure-by-default API for SSL clients (and soon servers)”）、6ad07a3f66f922604b423b6f0c03f220ffafd886（2014-10-23T07:34:48Z brad“Now that gcc2 is gone revert the removal of anonymous unions”）、84938a7b9c572efc85c2b06e24f6122d8cc98702（2015-01-04T16:12:42Z daniel“remove code for ancient gcc.”）、1c93e2863e3b9f1c0c7e436e2db3db4debd0d628（2015-02-15T09:23:23Z miod“Remove ancient gcc workaround on mips.”）；【交叉验证方法】openbsd.duckdb commit log 与 heartbleed.com 官网、LibreSSL 官网、OpenBSD 5.6 Release Notes 三方交叉验证 Heartbleed 响应时间线——2014-04-07 djm cherry-pick fix，2014-04-13 miod 导入 1.0.1g，2014-04-13 reyk 移除 Atalla/AEP 引擎（openbsd.duckdb 显示 commit 时间 18:50:36 与 19:04:55，commit message 分别为“Remove the Atalla engine”与“Remove the AEP engine”），2014-04-14 beck 移除 OPENSSL_SYS_XXX 残留（commit 00:00:55“remove last vestiges of OPENSSL_SYS_XXX from src/ssl ok deraadt@”），2014-04-14 jsing 大量应用 KNF 格式化（多条 commit），2014-04-14 tedu“make OPENSSL_NO_HEARTBLEED the default and only option”，2014-07-12 jsing 提交 libressl 库初始版本，2014-11 随 5.6 release 默认启用；【存疑判定依据】原大纲称“2014-04-14 beck 开始移除 OpenSSL Atalla/AEP 引擎”——经 openbsd.duckdb 核查，Atalla/AEP 引擎实为 reyk 于 2014-04-13 移除（非 beck 于 2014-04-14 移除），beck 于 2014-04-14 移除的是 OPENSSL_SYS_XXX 残留，此 attribution 差异已修正；Beck 与 jsing 在 LibreSSL fork 中的角色分工以 commit log 为准——Beck 负责对外沟通与 dead code 清理（移除 OPENSSL_SYS_XXX、OPENSSL_DIR_XXX），jsing 负责库架构设计与初始实现（KNF 格式化与 libressl 库初始 commit），reyk 负责移除 Atalla/AEP/GMP 等遗留引擎，三者角色不同但均为 fork 核心成员；OpenSSL Security Advisory 2014-04-07（<https://www.openssl.org/news/secadv_20140407.txt>）经 WebFetch 尝试核验但因 deadline 超时未取得原文，须后续补验或查询互联网档案馆存档版本
