# 222.2.4 LibreSSL 加密栈独立维护——从 OpenSSL fork 后的安全自主路径

**要点**：7.x 周期 LibreSSL 相关 CVE commit 至少 8 条，由 tb 主导修复，涵盖 PKCS7/CMS/X.509/SSL 等多个加密子系统——CVE-2023-0401（PKCS7 NULL deref，**2023 年 3 月 9 日**）、CVE-2024-5535（SSL_select_next_proto 空指针，**2024 年 6 月 28 日**）、CVE-2025-9230（CMS kek_unwrap_key 长度检查，**2025 年 9 月 30 日**）、CVE-2025-69421（PKCS12 NULL check，**2026 年 1 月 27 日**）、CVE-2026-28388（Delta CRL 处理，**2026 年 4 月 7 日**）、CVE-2026-28390（OAEP 参数 NULL deref，**2026 年 4 月 7 日**）、CVE-2014-8275（X509_CRL_verify 缺失检查，**2025 年 7 月 10 日** 修复，历史漏洞晚修复）；此外 **2026 年 4 月 3 日** jsing 提交 `760e21a76780` “Remove workaround for SSL 3.0/TLS 1.0 CBC vulnerability”——移除了针对 SSL 3.0/TLS 1.0 CBC 攻击的历史 workaround，标志着 LibreSSL 终于清理了 OpenSSL 时代遗留的兼容性代码；LibreSSL 路径与 FreeBSD 14.x 周期跟随 OpenSSL 3.0 的路径根本不同——OpenBSD 在 2014 年 Heartbleed 后 fork OpenSSL 为 LibreSSL，此后独立维护，不承受 OpenSSL 3.0 代际迁移带来的 CVE 清算代价

  ```sql
  -- 查询 LibreSSL 相关 CVE commit
  SELECT commit_hash, author_date, author_name, message_subject 
  FROM commits 
  WHERE repo_name=‘openbsd-src’ 
    AND author_date>=‘2021-10-14’ 
    AND author_date<‘2026-07-22’ 
    AND (message_subject LIKE ‘%SSL%’ OR message_subject LIKE ‘%PKCS%’ OR message_subject LIKE ‘%CMS%’ OR message_subject LIKE ‘%X509%’) 
    AND (message_body LIKE ‘%CVE-%’ OR message_subject LIKE ‘%CVE-%’) 
  ORDER BY author_date ASC;
  ```

**史料**：**openbsd.duckdb** `commits` 表 openbsd-src 仓库 LibreSSL 相关 commit 查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='openbsd-src' AND author_date>='2021-10-14' AND author_date<'2026-07-22' AND (message_subject LIKE '%SSL%' OR message_subject LIKE '%PKCS%' OR message_subject LIKE '%CMS%' OR message_subject LIKE '%X509%') AND (message_body LIKE '%CVE-%' OR message_subject LIKE '%CVE-%') ORDER BY author_date ASC`；tb 的 LibreSSL CVE 修复 commit 序列（`aa5715c96c45`、`0a52d54c17a9`——此为 OpenSSL 同源修复、`5daacac8dff8`、`7a3d6f69f0a9`、`842a6bbe1493`、`2fc71f321f1a`）；jsing 的 SSL 3.0/TLS 1.0 CBC workaround 移除 commit `760e21a76780`；LibreSSL 项目文档 ［A］

**史观**：总纲第 23 条——社区治理：7.x 周期 LibreSSL 进入 “独立维护路径的成熟期”——与 6.x 周期 “路线分离后的巩固” 不同，7.x 周期 LibreSSL 已形成稳定的维护团队（tb 主导）与稳定的 CVE 修复节奏（每年 2-3 个）；jsing 在 **2026 年 4 月 3 日** 提交 `760e21a76780` 移除 SSL 3.0/TLS 1.0 CBC 历史 workaround 是 7.x 周期 LibreSSL “成熟期债务清理” 的标志——这一 workaround 可追溯至 OpenSSL 时代，LibreSSL fork 后保留 12 年才最终移除，反映 “独立 fork 后的兼容性债务清理” 是长达十余年的渐进工程；7.x 周期 LibreSSL CVE 修复节奏远低于 OpenSSL 3.0 在 FreeBSD 14.x 周期带来的 CVE 数量（约 16 个），这一差距的成因须区分两个维度：其一，LibreSSL 删除了 OpenSSL 中大量 dead code 与旧 API，攻击面天然较小；其二，LibreSSL 不引入 OpenSSL 3.0 的 provider 架构等新特性，避免了 “新架构引入新 CVE” 的代际迁移代价——前者是代码精简的安全红利，后者是 “安全自主” 与 “功能跟随” 权衡的代价

**辨析**：**须精确说明 LibreSSL 与 OpenSSL 的 CVE 共享与分歧**：部分 CVE 同时影响 OpenSSL 与 LibreSSL（如 CVE-2024-5535 SSL_select_next_proto，OpenSSL 3.0 引入的漏洞但 LibreSSL 同样受影响，因 LibreSSL 保留了相关 API）；部分 CVE 仅影响 OpenSSL（如 OpenSSL 3.0 provider 架构相关漏洞 LibreSSL 不受影响）；部分 CVE 是 LibreSSL 独立发现（如 CVE-2026-28390 OAEP 参数 NULL deref，可能是 LibreSSL 代码路径特有）；**CVE-2014-8275 的修复时序**：此 CVE 编号为 2014 年，但 OpenBSD 于 **2025 年 7 月 10 日** 才修复（commit `aafaeed74858`，tb 提交 “Add missing check to X509_CRL_verify()”），时隔 11 年——这是 “历史漏洞晚修复” 的典型样本，反映 OpenBSD 审计覆盖的渐进性而非全面性 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；**与 FreeBSD OpenSSL 3.0 迁移对比**：FreeBSD 14.x 周期承受 OpenSSL 1.1.1→3.0 代际迁移的 CVE 清算代价（约 16 个 CVE），OpenBSD 7.x 周期因 LibreSSL 独立路径避免了此代价，但承担了独立维护的人力成本
