# 210.1.3 与 FreeBSD malloc/Linux SLAB 的比较

**要点**：FreeBSD 使用 phk malloc（Poul-Henning Kamp 1995 年设计），Linux 使用 SLAB/SLUB 分配器；OpenBSD malloc 强调安全（guard page、随机化、free 后填充），FreeBSD phk malloc 强调性能与 per-CPU 缓存，Linux SLAB/SLUB 强调多核扩展性与内存回收效率；三者设计哲学反映各自社区优先级——OpenBSD 安全优先、FreeBSD 性能优先、Linux 扩展性优先

  **三大 malloc 实现对比**：

  | 项目 | 设计者 | 设计优先级 | 关键特性 | 性能开销 |
  | --- | --- | --- | --- | --- |
  | OpenBSD malloc | tedu@（2006 替代） | 安全优先 | guard page、随机化、free 后填充 | 约 5-10% |
  | FreeBSD phk malloc | Poul-Henning Kamp（1995） | 性能优先 | per-CPU 缓存 | 接近原生 |
  | Linux SLAB/SLUB | Jeff Bonwick（杰夫·邦威克） 等 | 扩展性优先 | 多核扩展、内存回收 | 接近原生 |

**史料**：phk malloc 论文（Poul-Henning Kamp, “You're Doing It Wrong”, 2010, ACM Queue）；Linux SLAB/SLUB 文档（<https://www.kernel.org/doc/html/latest/mm/slab.html>）；OpenBSD malloc 文档（<https://man.openbsd.org/malloc.3>）；openbsd.duckdb openbsd-src 仓库 tedu@ malloc 相关 commit ［A］

**史观**：总纲第 7 条——技术选择即政治选择：三个项目 malloc 设计反映各自政治选择——OpenBSD 以 “安全为不可妥协之预设” 选择 guard page 与随机化（性能开销为代价），FreeBSD 以 “性能为部署之基” 选择 per-CPU 缓存（安全特性为可选），Linux 以 “扩展性为规模化之钥” 选择 SLAB/SLUB（安全特性由 SELinux 等外部机制承担）

**辨析**：三者性能对比以同硬件同负载的 SPECint 等基准测试为准——OpenBSD malloc 的 guard page 与随机化带来约 5-10% 性能开销（OpenBSD 邮件列表讨论估算，无同行评审基准），FreeBSD phk malloc 与 Linux SLUB 性能接近；安全特性的防御效果以 CVE 历史与漏洞利用研究为准——OpenBSD malloc 的 guard page 可检测部分堆溢出，但对堆内 off-by-one 溢出无防御效果

**文献**：Poul-Henning Kamp. You're Doing It Wrong [J]. ACM Queue, 2010；Linux SLAB/SLUB 文档 [EB/OL]. <https://www.kernel.org/doc/html/latest/mm/slab.html>；OpenBSD **malloc(3)** 手册页 [EB/OL]. <https://man.openbsd.org/malloc.3> ［A］
