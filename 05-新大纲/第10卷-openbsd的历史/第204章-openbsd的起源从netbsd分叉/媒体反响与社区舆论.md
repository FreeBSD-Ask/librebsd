## 冲突类

### 新闻条目 1

- **新闻标题（中英）**：OpenBSD pledge(2) 与 unveil(2) 官方手册页
- **新闻来源**：OpenBSD 官方 + 项目持续维护 + URL: <https://man.openbsd.org/pledge.2> + <https://man.openbsd.org/unveil.2> + 存档 URL: 待补
- **新闻摘要**：OpenBSD 官方手册页 pledge(2) 描述："The pledge() system call separates the POSIX feature set into a group of approximately 3 dozen subsystems. By calling pledge() the program can declare which subsystems it will need in the future in a space-separated string called promises. Subsystems not listed become unavailable, and most attempts to use operations in that subsystem result in the process being killed with an uncatchable SIGABRT.“。unveil(2) 描述：”The first call to unveil() that specifies a path removes visibility of the entire filesystem from all other filesystem-related system calls (such as open(2), chmod(2) and rename(2)), except for the specified path and permissions.“。pledge(2) HISTORY 段注明 ”first appeared in OpenBSD 5.8“，unveil(2) HISTORY 段注明 ”first appeared in OpenBSD 6.4"。手册页还列出 pledge 的约 36 个 promise 类别（rpath、wpath、cpath、exec、unveil、inet、unix、dns、getpw、sendfd、recvfd、tty、proto_route、route、id、pf、chown、settime、ps、proc_info、proc_exec、proc_setid、prot_session、proc_fork、proc_signal、prot_wait、vminfo、tty、tor_arp、dns_arp、route_arp 等）。
- **与本章主题的关联说明**：本章叙述 OpenBSD pledge/unveil（2015-2026），官方手册页是本章 “pledge/unveil 接口语义” 叙事的权威史料，是新闻所述的技术细节交叉验证基准。
- **与官方史料的交叉验证结论**：OpenBSD 官方手册页为 pledge(2)/unveil(2) 的权威一手史料，与 OpenBSD 5.8/6.4 changelog 中 pledge/unveil 条目互证；与 undeadly.org 2015-10-13 与 2018-07-27 报道形成时序链。一致采纳。

### 新闻条目 3

- **新闻标题（中英）**：tame(2) is now pledge(2)（tame(2) 现改名 pledge(2)）
- **新闻来源**：undeadly.org + pitrh 署名 + 2015-10-13 + URL: <https://undeadly.org/cgi?action=article;sid=20151013162018> + 存档 URL: 待补
- **新闻摘要**：undeadly.org 报道 Theo de Raadt 于 2015-10-08（CVS 提交时间）将 tame(2) 改名为 pledge(2)。commit log 说明："Rename tame() to pledge(). This fairly interface has evolved to be more strict than anticipated. It allows a programmer to pledge/promise/covenant that their program will operate within an easily defined subset of the Unix environment, or it pays the price."。改名涉及 kern_tame.c → kern_pledge.c、tame.2 → pledge.2、libc/sys/tame.c → pledge.c，以及 100+ base 系统程序的 tame 调用点全部改为 pledge 调用。同期 OpenSSH 的 sandbox-tame.c 改为 sandbox-pledge.c。改名理由是 “pledge” 更准确传达 “程序向操作系统承诺行为” 的语义。
- **与本章主题的关联说明**：本章叙述 OpenBSD pledge/unveil（2015-2026），tame→pledge 改名是本章 “pledge 命名定型” 叙事的核心节点，2015-10-08 是 pledge(2) 正式诞生的精确时间锚点。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD CVS commit（<http://marc.info/?laccopenbsd-cvs&m=144435306927994>）完全一致；与 OpenBSD 5.8（2015-10-18）changelog 中 pledge(2) 条目互证；与 OpenBSD pledge(2) 手册页（<https://man.openbsd.org/pledge.2>）HISTORY 段一致。一致采纳。

- **与本章主题的关联说明**：本章叙述 OpenBSD pledge/unveil（2015-2026），OpenBSD 6.4 是 unveil(2) 首次随版本发布的关键里程碑，本章 “unveil 首次发布” 叙事的核心节点，标志 pledge+unveil 双重沙箱体系正式定型。
