## 201.4.2 unveil(2) 引入与 pledge(2)/unveil(2) 双重声明式安全机制的完成

**要点**：OpenBSD 6.2（2017-10-09）引入 **unveil(2)** 系统调用用于文件系统路径访问限制——unveil(2) 允许进程在启动时声明所需访问的文件系统路径（如 `unveil("/var/www", "r")`），内核据此限制进程的文件系统访问范围，未声明的路径对进程不可见；unveil(2) 与 5.9 引入的 **pledge(2)** 共同构成“进程权限 + 文件路径”的双重声明式安全机制——pledge(2) 限制系统调用类别（如网络、进程控制），unveil(2) 限制文件系统访问范围，两者协同形成 OpenBSD 独有的声明式沙箱模型；unveil(2) 的引入是 OpenBSD 安全哲学从“代码审计 + 加固机制”向“权限声明 + 强制约束”演化的完成阶段，为 7.x 时期 pledge(2)/unveil(2) 在基本系统工具的广泛部署奠定基础

**史料**：OpenBSD 6.2 release 页面（<https://www.openbsd.org/62.html>，记载 unveil(2) 引入）；**unveil(2)** 手册页；OpenBSD 邮件列表关于 unveil(2) 设计的讨论存档；undeadly.org 关于 6.2 发布与 unveil(2) 的报道；原材料/研究/考据记录/20260723_announcements-openbsd.md § 二.4.3 unveil(2) 引入考据 ［A］

**史观**：总纲第 17 条——形式主义化：unveil(2) 将文件系统访问从“事后审计 + 反应式修复”形式主义化为“事前声明 + 强制约束”，与 pledge(2) 共同构成声明式安全机制的形式主义化完成；总纲第 21 条——革命与改革：unveil(2) 是“改革”而非“革命”——在现有 UNIX 文件权限模型基础上渐进引入声明式路径约束，而非从零重写文件系统权限模型——“改革的困难远高于革命”；边缘者贡献：pledge(2)/unveil(2) 作为 OpenBSD 独有的声明式沙箱模型，被其他 BSD/Linux 项目参考但未直接移植，体现 OpenBSD 作为“边缘项目”的安全工程创新

**辨析**：unveil(2) 引入的考据须遵循 0 信任原则——【查证来源】（1）OpenBSD 6.2 release 页面（<https://www.openbsd.org/62.html>）经 2026-07-23 检索，记载发布日期 2017-10-09 与 unveil(2) 引入；（2）**unveil(2)** 手册页记载 unveil(2) 系统调用的设计与约束机制；（3）openbsd.duckdb openbsd-src 仓库 commits 表可查询 unveil 相关 commit 时间线；【交叉验证方法】unveil(2) 引入版本与日期经 OpenBSD 官网 release 页面、unveil(2) 手册页、openbsd.duckdb commit 时间线三方交叉验证；【pledge(2)/unveil(2) 协同机制辨析】pledge(2) 限制系统调用类别（如 `pledge("rpath wpath inet")`），unveil(2) 限制文件系统路径（如 `unveil("/var/www", "r")`），两者协同形成“系统调用 + 文件路径”双重声明式沙箱——pledge(2) 可在未声明 `rpath`/`wpath` 时直接阻断文件系统访问，unveil(2) 在已声明 `rpath`/`wpath` 时进一步限制可访问路径范围，两者的协同关系须以 pledge(2)/unveil(2) 手册页与 OpenBSD 邮件列表设计讨论交叉验证；【存疑判定依据】unveil(2) 在基本系统工具的部署进度存疑：6.2 引入 unveil(2) 后，基本系统工具（如 httpd、relayd、smtpd）逐步部署 unveil(2)，具体部署进度与版本须经各工具的 commit 历史与 release notes 交叉验证，保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
