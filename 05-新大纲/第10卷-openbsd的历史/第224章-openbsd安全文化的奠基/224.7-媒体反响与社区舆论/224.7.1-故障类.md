### 新闻条目 1

- **新闻标题（中英）**：Heartbleed OpenSSL 漏洞（CVE-2014-0160）——LibreSSL fork 的直接导火索
- **新闻来源**：OpenSSL 官方公告 + 多家媒体 + 2014-04-07 + URL: <https://www.openssl.org/news/secadv/20140407.txt> + 存档 URL: 待补
- **新闻摘要**：2014-04-07 OpenSSL 官方发布安全公告 CVE-2014-0160，即 “Heartbleed”（心脏出血）漏洞。该漏洞位于 TLS Heartbeat Extension 实现中，由于 dtls1_process_heartbeat() 函数未正确验证长度字段，允许攻击者读取服务器进程内存最多 64KB 数据，可能泄露私钥、会话凭证、用户密码等敏感信息。Heartbleed 影响 OpenSSL 1.0.1 至 1.0.1f 版本，估计影响当时互联网 17% 的 HTTPS 服务器。OpenSSL 同日发布 1.0.1g 修复。Heartbleed 是 OpenSSL 历史上最严重漏洞之一，直接动摇了业界对 OpenSSL 代码质量的信心，触发 OpenBSD 启动 OpenSSL 代码大扫除，最终于 2014-04-23 fork 为 LibreSSL。
- **与本章主题的关联说明**：本章叙述 LibreSSL（2014），Heartbleed 是 LibreSSL fork 的直接导火索，本章 “LibreSSL 诞生背景” 叙事的核心节点。
- **与官方史料的交叉验证结论**：OpenSSL 官方公告与 CVE-2014-0160 数据库条目一致；与 undeadly.org 2014-04-23 报道（LibreSSL fork 正式定名）形成因果关系；与 OpenBSD 5.6（2014-11-01）changelog 中 LibreSSL 替换 OpenSSL 条目互证。一致采纳。

### 新闻条目 2

- **新闻标题（中英）**：OpenSSL Releases Bugfixes, Advance Notice To Some Vendors But Not OpenBSD（OpenSSL 发布 bug 修复，提前通知部分厂商但未通知 OpenBSD）
- **新闻来源**：undeadly.org + 编辑署名 + 2014-06-05 + URL: <https://undeadly.org/cgi?action=article;sid=20140605202211> + 存档 URL: 待补
- **新闻摘要**：undeadly.org 2014-06-05 报道 OpenSSL 发布 bug 修复，但提前通知了部分厂商却未通知 OpenBSD。这一事件加剧了 OpenBSD 团队对 OpenSSL 治理模式的不满——OpenSSL 的 “提前披露”（advance notice）政策将 OpenBSD 排除在外，尽管 OpenBSD 是 OpenSSL 的重要用户与贡献者。Bob Beck 在 BSDCan 2014 状态报告中已提及此问题。这一事件是 LibreSSL fork 的治理动因之一，体现 OpenBSD 对 “开放披露”（full disclosure）原则的坚持。
- **与本章主题的关联说明**：本章叙述 LibreSSL（2014），OpenSSL 提前通知排他事件是本章 “LibreSSL 治理动因” 叙事的典型节点，揭示 fork 不仅是技术问题，更是治理问题。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 Bob Beck BSDCan 2014 报告中相关表述一致；与 OpenBSD misc@/tech@ 邮件列表 2014-06 讨论 互证。一致采纳。
