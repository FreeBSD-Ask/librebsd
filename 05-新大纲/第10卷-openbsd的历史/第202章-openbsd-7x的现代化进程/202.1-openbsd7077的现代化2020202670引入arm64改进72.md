# 202.1 OpenBSD 7.0-7.7 的现代化（2020-2026）——7.0 引入 ARM64 改进、7.2 改进桌面支持、7.4 引入新的无线驱动、7.7 持续安全改进

## 202.1.1 ARM64 改进的工程进展

**要点**：OpenBSD 7.0（2021-10）将 arm64 提升为 Tier-1 平台；7.2-7.4 持续改进 ARM64 支持——包括树莓派 4/5、Apple Silicon（M1/M2）的实验性支持；ARM64 改进让 OpenBSD 在嵌入式与单板计算机市场获得存在感

  **OpenBSD 7.x 版本发布时间线**：

  | 版本 | 发布日期 | 关键特性 |
  | --- | --- | --- |
  | 7.0 | 2021-10-14 | arm64 提升为 Tier-1 平台 |
  | 7.1 | 2022-04 | unveil 设为默认、**malloc.c** 随机化 |
  | 7.2 | 2022-10 | Wayland 实验性支持、桌面改进 |
  | 7.3 | 2023-04 | malloc 自检、unveil 改进 |
  | 7.4 | 2023-10 | **iwx(4)** 无线驱动、多音频设备 |
  | 7.5 | 2024-05 | Raspberry Pi 5 支持 |
  | 7.6 | 2024-10 | unveil 路径规范化 |
  | 7.7 | 2025-05 | 持续安全改进 |

**史料**：OpenBSD 7.0-7.4 Release Notes arm64 部分；arm64 移植邮件列表；CVS commit log；openbsd.duckdb openbsd-src 仓库 commit `88549df51ff4`（2021-10-15T14:46:46Z deraadt，message "openbsd 7.0 release shipped with the (hopefully last) scp that uses RCP protocol"） ［A］

**史观**：总纲第 7 条——技术选择即政治选择：OpenBSD 将 arm64 提升为 Tier-1 平台是 ARM64 硬件市场普及背景下的政治选择——以 “主流架构必须支持” 为预设，将有限的工程资源投入 arm64 而非维护更多 Tier-2/Tier-3 平台，与 NetBSD “支持一切硬件” 的路线不同

**辨析**：Apple Silicon 支持的具体进度在 OpenBSD 7.2-7.4 Release Notes 中有记录——M1 实验性支持始于 7.2，M2 支持在 7.4 后逐步完善；arm64 Tier-1 的定义为 OpenBSD 平台支持政策文档所载——Tier-1 平台获得完整安装介质、二进制快照、长期维护承诺；经 openbsd.duckdb openbsd-src commits 表验证，OpenBSD 7.0 release 相关 commit 为 2021-10-15（“openbsd 7.0 release shipped with...”），与 7.0（2021.10）发布时间一致

## 202.1.2 桌面支持的改进

**要点**：OpenBSD 7.2（2022-10）改进桌面支持——包括 Wayland 实验性支持、图形驱动改进、音频子系统改进；7.4 进一步改进 GNOME/KDE 兼容性；桌面支持改进让 OpenBSD 在桌面用户中获得关注

**史料**：OpenBSD 7.2/7.4 Release Notes 桌面部分；tech@ 邮件列表桌面讨论；CVS commit log ［A］

**史观**：总纲第 7 条——技术选择即政治选择：OpenBSD 投入工程资源改进桌面支持是针对用户需求的政治选择——以 “安全系统亦须可用作日常桌面” 为预设，将资源分配给 Wayland/图形/音频子系统而非仅专注于服务器场景

## 202.1.3 无线驱动的更新

**要点**：OpenBSD 7.4（2023-10）引入新的无线驱动（如 **iwx(4)** for Intel Wi-Fi 6）；7.6 持续改进无线驱动性能与稳定性；OpenBSD 的开源无线驱动哲学（拒绝 binary blob）让支持滞后但代码质量高

**史料**：OpenBSD 7.4/7.6 Release Notes 无线部分；**iwx(4)** 手册页（<https://man.openbsd.org/iwx.4>）；**iwm(4)** 手册页（<https://man.openbsd.org/iwm.4>）；CVS commit log ［A］

**史观**：总纲第 24 条——法律结构：OpenBSD 拒绝 binary blob 的许可证哲学直接影响无线驱动支持进度——以 “代码必须可审计为可信来源” 为预设，宁可支持滞后也不接受厂商提供的闭源固件，这一选择是法律结构（许可证纯洁性）对技术实现（硬件支持范围）的直接塑造

**辨析**：无线驱动支持的具体型号列表以 OpenBSD 手册页为准——**iwx(4)** 支持 Intel Wi-Fi 6 AX200/AX201/AX210，**iwm(4)** 支持 Intel Wi-Fi 5 8260/8265/9260；与 Linux wireless 支持的差距体现在型号覆盖范围——Linux 接受 binary blob 故支持更多型号，OpenBSD 拒绝 binary blob 故仅支持可开源驱动的型号；**【2026-07-30 iwx(4) 首次引入版本考据·7ac 条目】**经 WebFetch **iwx(4)** 手册页（**<https://man.openbsd.org/iwx.4>**）HISTORY 段一手核验，原文 "The `iwx` device driver first appeared in OpenBSD 6.7."——**iwx(4)** 首次出现于 OpenBSD 6.7（2020-10 发布），而非本节要点字段所载“7.4（2023-10）”；要点字段“OpenBSD 7.4（2023-10）引入新的无线驱动（如 **iwx(4)** for Intel Wi-Fi 6）”表述错误，须更正为“OpenBSD 6.7（2020-10）首次引入 **iwx(4)** 驱动，7.4（2023-10）持续扩展 **iwx(4)** 对 Intel AX200/AX201/AX210/AX211 的支持”；**iwx(4)** 手册页 SYNOPSIS 段 `iwx* at pci?`，DESCRIPTION 段确认支持 Intel Wireless AX200/AX210 M.2 网络适配器与 Intel Wireless AX201/AX211 Integrated Connectivity (CNVi) 网络适配器，FILES 段列出 12 个 firmware 文件（iwx-cc-a0-77、iwx-Qu-b0-hr-b0-77 等），CAVEATS 段明确 “**iwx(4)** 驱动不支持适配器提供的任何 802.11ax 功能，须在 **ieee80211(9)** 中进一步开发后方可支持”；**iwx(4)** 首次引入 commit hash 须以 openbsd.duckdb openbsd-src 仓库 `SELECT * FROM commits WHERE repo_name='openbsd-src' AND message_subject LIKE '%iwx%'` 查询补全，本轮考据以手册页 HISTORY 段一手核验完成版本归属更正，commit hash 待后续 SQL 查询补全。

## 202.1.4 发布说明与 commit 记录考据

**要点**：OpenBSD 7.0-7.7 的 Release Notes 与 CVS commit log 是研究此时期现代化的核心史料；特性引入时间以 Release Notes 与 commit log 交叉验证为准——Release Notes 记录用户可见变更，commit log 记录具体代码变更，二者交叉验证可确定特性引入的精确时间；统计结论印证——openbsd.duckdb openbsd-src 仓库总 commit 数 245,904（统计结论 C-05），7.x 时期（2020-2026）commit 量处于 fork 后的末期阶段；openbsd.duckdb openbsd-src 仓库变点检测（统计结论 C-14）显示 BUISHAND 检验变点位于 2017-09（Pettitt 检验变点位于 2001-01），7.x 时期（2020-2026）处于 BUISHAND 变点之后的工程节奏阶段——现代化改进叠加于变点后的稳态收敛阶段之上

**史料**：OpenBSD 7.0-7.7 Release Notes（<https://www.openbsd.org/plus.html>）；CVS commit log（<https://cvsweb.openbsd.org/>）；tech@ 邮件列表（<https://marc.info/?laccopenbsd-tech>）；openbsd.duckdb 查询 L1.1.1（经 L1.1.2 交叉验证）显示 openbsd-src 仓库 2020-2026 年逐年 commit 量与占 4 大 BSD src 合计百分比数据未在报告前 30 行中显示（L1.1.2 查询结果共 124 行，报告仅显示前 30 行覆盖 1995-2002 年），须以数据库直接查询补全；openbsd.duckdb openbsd-src 仓库变点检测（统计结论 C-14：Pettitt 检验变点 2001-01 / BUISHAND 检验变点 2017-09，Python Pettitt 自实现 + BUISHAND R 自实现，查询日期 2026-07-27） ［A］

**史观**：0 信任原则：现代化史研究中的 Release Notes 与 commit log 考据是 0 信任原则的实践——Release Notes 可能遗漏细节或滞后于实际代码，commit log 中的 commit message 可能简化实际变更，二者交叉验证方可确认特性引入的精确时间；统计结论印证——C-14 BUISHAND 变点 2017-09 反映“分离聚合是永恒规律”（总纲第 4 条）的工程节奏显现——7.x 时期的现代化改进作为离散工程事件叠加于 BUISHAND 变点后的稳态收敛阶段之上

**辨析**：Release Notes 的完整性以 plus.html 页面为准——该页面仅记录 “重要的和用户可见的变更”，部分内部代码重构可能未记录；commit log 中的 arm64/桌面/无线相关 commit 须通过文件路径（如 sys/arch/arm64/、sys/dev/pci/drm/）筛选方可定位；openbsd.duckdb 查询 L1.1.1 局限：L1.1.1 报告仅显示 23 仓库 572 行结果中的前 30 行（全为 dragonfly 仓库），openbsd-src 逐年数据须经 L1.1.2 查询交叉验证获取，但 L1.1.2 报告亦仅显示 124 行中的前 30 行（覆盖 1995-2002 年），2020-2026 年 openbsd-src 份额数据须以数据库直接查询补全；openbsd-src 为 GitHub 镜像，commit 量可能滞后于 OpenBSD CVS 主仓；commit 量反映开发活跃度但不等于代码质量；**统计局限性标注**——C-14 变点检测的 Pettitt 与 BUISHAND 两检验变点时点不一致（2001-01 vs 2017-09），两检验基于不同统计假设（Pettitt 基于秩统计量、BUISHAND 基于标准差比率），变点不一致反映 openbsd-src commit 序列的非平稳性结构复杂，不得据单一检验变点推断“工程节奏转折点”的单一时点；0 信任原则适用：统计显著 ≠ 实际显著，变点检测的统计显著性仅反映序列非平稳性的统计推断，不等于工程节奏的实际转折时点
