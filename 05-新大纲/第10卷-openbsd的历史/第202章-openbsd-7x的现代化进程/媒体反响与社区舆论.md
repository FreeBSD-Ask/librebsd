### 新闻条目 2

- **新闻来源**：undeadly.org + 编辑署名 + 2003-01-31 / 2003-01-26 + URL: <https://undeadly.org/cgi?action=article;sid=20030131031200> + <https://undeadly.org/cgi?action=article;sid=20030126143902> + 存档 URL: <https://web.archive.org/web/20260512161125/https://undeadly.org/cgi?action=article;sid=20030131031200> + <https://web.archive.org/web/20260512155038/https://undeadly.org/cgi?action=article;sid=20030126143902>
- **新闻摘要**：undeadly.org 2003-01 报道 Theo de Raadt（西奥·德·若特） 谈 OpenBSD 安全改进，同期报道 W^X（Write XOR Execute）内存保护机制。W^X 是 OpenBSD 3.3（2003-05）引入的关键安全特性，通过在硬件层面标记内存页为可写或可执行（二者不可兼得），阻断代码注入攻击。W^X 是 OpenBSD 安全文化从 “审计找 bug” 向 “缓解技术阻断漏洞利用” 转型的里程碑，后续的 KARL、RETGUARD、mimmutable 均延续此路线。
- **与本章主题的关联说明**：本章叙述 OpenBSD 安全文化（1996-2026），W^X 2003 引入是本章 “OpenBSD 缓解技术体系奠基” 叙事的核心节点，标志 OpenBSD 从纯审计转向审计 + 缓解双轨制。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD 3.3 changelog（plus33.html）中 W^X 条目一致；与 OpenBSD security.html 中 W^X 列表条目互证；与 Theo de Raadt 2003 年邮件列表说明一致。一致采纳。

### 新闻条目 3

- **新闻标题（中英）**：On the Insecurity of TIOCSTI（论 TIOCSTI 的不安全性）

- **新闻摘要**：undeadly.org 报道 OpenBSD 对 TIOCSTI ioctl 不安全性的分析与处理。TIOCSTI 允许向终端输入队列注入字符，可被用于绕过特权分离与 pledge(2) 沙箱。OpenBSD 选择禁用 TIOCSTI 而非保留它，体现其 “宁可破坏向后兼容也要消除安全隐患” 的安全文化。这是 OpenBSD 安全审计持续 20 余年仍能发现新问题类的例证。
- **与本章主题的关联说明**：本章叙述 OpenBSD 安全文化（1996-2026），TIOCSTI 禁用是本章 “OpenBSD 安全审计持续发现新问题类” 叙事的典型节点，体现安全文化不被向后兼容绑架。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD source-changes@ 邮件列表 2017-07 TIOCSTI 相关 commit 一致；与 OpenBSD 6.2 changelog（plus62.html）中 TIOCSTI 条目互证。一致采纳。

### 新闻条目 1

- **新闻标题（中英）**：On the OpenBSD Mantra of Code Freedom（论 OpenBSD 代码自由信条）+ Redundant code = security errors?（冗余代码等于安全错误？）
- **新闻来源**：undeadly.org + 编辑署名 + 2003-01-23 / 2003-01-24 + URL: <https://undeadly.org/cgi?action=article;sid=20030123025109> + <https://undeadly.org/cgi?action=article;sid=20030124143801> + 存档 URL: <https://web.archive.org/web/20260521074044/https://undeadly.org/cgi?action=article;sid=20030123025109> + <https://web.archive.org/web/20260521080302/https://undeadly.org/cgi?action=article;sid=20030124143801>
- **新闻摘要**：undeadly.org 2003-01 报道 OpenBSD “代码自由” 信条与 “冗余代码即安全错误” 理念。OpenBSD 安全文化的核心哲学是：代码越简洁越安全，冗余代码增加攻击面；代码自由（BSD 许可证）允许任何人审计与改进，安全来自透明而非保密。这一理念与 “security through obscurity”（通过隐蔽实现安全）形成对立，是 OpenBSD 选择完全披露政策的哲学根基。
- **与本章主题的关联说明**：本章叙述 OpenBSD 安全文化（1996-2026），“代码自由” 与 “冗余代码即安全错误” 是本章 “OpenBSD 安全哲学根基” 叙事的核心，与项目统摄史观中 “动手者创造历史” 形成史观对照。
- **与官方史料的交叉验证结论**：undeadly.org 报道与 OpenBSD security.html 中审计流程描述一致；与 OpenBSD 3.3 时期 sendmail/Apache 持续精简工作互证；与 OpenBSD 5.5（2014）base 系统精简（移除 Apache/sendmail/BIND/nginx）形成历史时序链。一致采纳。
