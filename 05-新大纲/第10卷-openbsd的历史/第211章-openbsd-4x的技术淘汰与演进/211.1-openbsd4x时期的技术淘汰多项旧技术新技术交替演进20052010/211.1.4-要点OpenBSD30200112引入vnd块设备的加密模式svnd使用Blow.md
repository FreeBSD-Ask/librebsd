# 211.1.4 要点OpenBSD30200112引入vnd块设备的加密模式svnd使用Blow

**要点**：OpenBSD 3.0（2001.12）引入 vnd 块设备的加密模式 svnd，使用 Blowfish 算法；OpenBSD 4.x 时期持续改进加密栈——softraid 加密于 2007-11-27 tedu commit f18dcc9c26b1 首次引入（4.2 周期），2008-06-14 hshoexer commit 79cdc9424edb 完整启用（4.4 周期），支持 AES-XTS，取代 svnd 成为推荐的磁盘加密方案；4.x 时期的 OpenSSL 集成为后续 LibreSSL fork（2014 年 4 月 Heartbleed 后）积累了 OpenSSL 工程实践——但 LibreSSL fork 发生在 5.6 周期（2014.11），与 4.x 时期（2005-2010）相隔约 4 年，二者不构成直接的 “前期演进” 关系

**史料**：openbsd.duckdb openbsd-src 仓库 commit f18dcc9c26b1（2007-11-27 tedu “split crypto functions”）、commit 79cdc9424edb（2008-06-14 hshoexer “enable softraid crypto”）；OpenBSD 3.0 Release Notes vnd 部分；OpenBSD 4.2/4.4 Release Notes softraid 部分；OpenBSD **softraid(4)**、**bioctl(8)** 手册页 ［A］

**史观**：专题——密码学标准演进与实现（不设总纲条号）：加密栈从 svnd（Blowfish）到 softraid（AES-XTS）的演进是 OpenBSD 对密码学最佳实践变化的响应——AES-XTS 作为 NIST SP 800-38E 推荐的磁盘加密模式取代 Blowfish，这一路径是密码学标准演进对操作系统实现的具体塑造

**辨析**：svnd 与 softraid 的关系以 openbsd.duckdb commit log 为准——softraid 首次 commit 为 2007-03-19 dlg commit 98855ba5cdbc “attach softraid to the root of the device tree”，是新的 RAID 框架，加密是其子功能；AES-XTS 支持的具体引入版本以 **softraid(4)** 手册页与 commit log 为准——softraid 加密自 2008 年启用即支持 AES-XTS；4.x 时期 OpenSSL 集成的具体版本以 OpenBSD Release Notes 为准

**文献**：openbsd.duckdb openbsd-src 仓库 commit 98855ba5cdbc、f18dcc9c26b1、79cdc9424edb；OpenBSD Release Notes [EB/OL]. <https://www.openbsd.org/plus.html>；OpenBSD **softraid(4)** 手册页 [EB/OL]. <https://man.openbsd.org/softraid.4> ［A］

### 史观映射

OpenBSD 4.x 时期是项目统摄史观中 “形式主义化” 与 “修道度人” 在网络安全领域的双重实践。6 个月发布周期作为形式主义化结构（专题——发布周期的形式主义化，不设总纲条号），将时间固化为不可动摇的规则——krw@ 与 espie@ 的 release engineering 工作严格遵循 5 月与 11 月的节奏，这一形式化结构带来稳定性与可预测性，但也限制了单周期内的重大架构重构。pf 的持续演进是 “修道度人” 的工程实践（专题——pf 的持续工程实践，不设总纲条号）——claudio@ 与 henning@ 在 2005-2010 年间持续改进 pf，让 pf 守护着无数网络的边界，但 pf 的作者们很少在公众视野中出现。CARP 冗余协议的开发是对法律结构障碍的重新设计（总纲第 13 条——法律与道德是利益分配）——当 VRRP 协议的 Cisco 专利 US 5,473,599 成为障碍时，OpenBSD 选择重新设计协议（CARP）而非寻求专利授权，这一选择是法律结构对技术实现的直接塑造。malloc 替代（tedu@ 2006-10-24 commit 66e23c51）是 “边缘者承担安全关键基础设施” 的具体显现（总纲第 10 条——动手者创造历史）——OpenBSD 的 malloc 安全替代由单一开发者响应安全研究社区的漏洞披露而实现，非由大厂商团队推动。softraid 加密的引入（tedu@ 2007-11-27 commit f18dcc9c26b1 至 hshoexer@ 2008-06-14 commit 79cdc9424edb）是密码学标准演进对操作系统实现的具体塑造（专题——密码学标准演进与实现，不设总纲条号）——AES-XTS 作为 NIST SP 800-38E 推荐模式取代 Blowfish。de Raadt 的个人主导模式是 “动手者” 存在主义的体现——一个人在不被理解中坚持自己的工程哲学，BDFL 治理（专题——BDFL 治理模式，不设总纲条号）使 OpenBSD 在 4.x 时期保持技术方向一致性。
