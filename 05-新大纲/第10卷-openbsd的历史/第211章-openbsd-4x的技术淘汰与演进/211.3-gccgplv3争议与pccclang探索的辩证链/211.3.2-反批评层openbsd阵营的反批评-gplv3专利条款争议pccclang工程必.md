# 211.3.2 反批评层：OpenBSD 阵营的反批评——GPLv3 专利条款争议、pcc/clang 工程必要性

**要点**：OpenBSD 阵营对 FSF/GPL 批评的反批评集中在四个层面。第一层面是反驳 “GPLv3 专利防御” 论据——de Raadt 在 misc@ 邮件列表主张 GPLv3 将专利问题转化为许可证问题，扩大了 copyleft 范围至专利领域，超越了 “防御 Microsoft-Novell” 的必要范围，使所有 GPLv3 软件承担专利合规负担；第二层面是反驳 “ISC 过于宽松” 批评——OpenBSD 主张 ISC 许可证的 “宽松” 是 BSD 社区的故意选择，认为强制回馈违背 “自由” 的本义（OpenBSD 的 “自由” 包含采纳者自由使用代码的自由，而非仅用户自由），所谓 “商业公司免费研发” 批评忽视 BSD 成果反向流入产业（如 OpenSSH 被 Cisco、Juniper 等广泛采用）的事实；第三层面是 pcc/clang 工程必要性——OpenBSD 主张 pcc 与 clang/LLVM 探索是工程驱动的替代路径而非意识形态选择，openbsd.duckdb openbsd-src 仓库显示 otto@ 于 2007-09-15 commit `60b4da4bc6418e6654a995e733a66436798b5bc0` 实际导入 pcc（"Import ragge's version of PCC into our tree, so we can hack on it more easy. ok deraadt@ miod@"），pcc 探索并非仅在邮件列表讨论，而是已进入 OpenBSD 主干，后因 pcc 不支持 C99 完整特性、缺乏现代优化器而放弃，转而探索 clang/LLVM（2008-11-10 cnst commit 首次使用 clang 静态分析器）；第四层面是 gcc 代码质量与工程治理批评——de Raadt 与 espie@ 在 tech@ 邮件列表指出 gcc 4.x 代码膨胀、维护僵化、编译速度慢、诊断信息劣于 clang，gcc 由 FSF 控制开发流程对 BSD 项目不友好，无法纳入 OpenBSD 的 6 个月 release 节奏

**史料**：de Raadt 关于 gcc GPLv3 的邮件列表发言（<https://marc.info/?laccopenbsd-tech>、<https://marc.info/?laccopenbsd-misc）；espie@> 关于 gcc 代码质量的邮件列表发言；OpenBSD 项目目标官方页面（<https://www.openbsd.org/goals.html>，原文明确 ISC or Berkeley style licences are preferred, the GPL is not acceptable when adding new code，并主张 We want to make available source code that anyone can use for ANY PURPOSE, with no restrictions，4.x 时期页面内容经互联网档案馆 2007-2008 年存档版本交叉核验）；OpenBSD 版权政策官方页面（<https://www.openbsd.org/policy.html>，原文明确 the GNU Public License... usually ends up hindering free sharing and reuse of code and ideas rather than encouraging it，As a consequence, no additional software bound by the GPL terms will be considered for inclusion into the OpenBSD base system，并承认 For historical reasons, the OpenBSD base system still includes the following GPL-licensed components: the GNU compiler collection (GCC) with supporting binutils and libraries, GNU CVS, GNU texinfo, the mkhybrid file system creation tool, and the readline library. Replacement by equivalent, more freely licensed tools is a long-term desideratum，证明 OpenBSD 4.x 时期官方已明确将 GCC 列为待替代的 GPL 历史包袱）；GPLv3 最终文本第 10.4 节与第 11 节（<https://www.gnu.org/licenses/gpl-3.0.txt>）；openbsd.duckdb openbsd-src 仓库 commit 60b4da4bc6418e6654a995e733a66436798b5bc0（2007-09-15 otto "Import ragge's version of PCC into our tree, so we can hack on it more easy. ok deraadt@ miod@"）；openbsd.duckdb openbsd-src 仓库 pcc 相关 commit 共 49 条（1998-2015，含 pccard 等无关项，实际 pcc 编译器相关 commit 约 20 条）；openbsd.duckdb openbsd-src 仓库 clang/LLVM 相关 commit 首条 2008-11-10 cnst；OpenSSH 部署统计；clang/LLVM 项目文档（<https://clang.llvm.org/>） ［A］

**史观**：总纲第 15 条——文化即形式主义：gcc 作为 GNU 文化的核心符号被 FSF 视为自由软件运动的旗帜，OpenBSD 将其视为 “受污染的工具”——同一编译器在不同文化语境中被赋予截然不同的形式主义意义，gcc 的技术价值与许可证符号价值难以分离；总纲第 5 条——没有必然性，只有偶然性：pcc 导入（2007-09-15 otto commit）是偶然的工程尝试，pcc 失败与 clang/LLVM 成功亦是偶然的技术演进结果，不得以 “必然替代” 的目的论叙事遮蔽

**辨析**：考据过程留痕——【查证来源】de Raadt 对 gcc GPLv3 的具体批评内容以 marc.info 存档原始帖子为准——OSNews、Slashdot 等技术媒体常简化语境；GPLv3 专利条款的具体范围以 GPLv3 文本第 10.4 节与第 11 节为准，OpenBSD 的批评主要针对 “专利反制条款扩大 copyleft 范围” 而非专利条款本身；【交叉验证方法】pcc 导入史实经 openbsd.duckdb openbsd-src 仓库直接查询验证：commit `60b4da4bc6418e6654a995e733a66436798b5bc0`（2007-09-15T18:12:23Z otto "Import ragge's version of PCC into our tree, so we can hack on it more easy. ok deraadt@ miod@"）确证 pcc 已进入 OpenBSD 主干，非仅邮件列表讨论；此 commit 经 deraadt@ 与 miod@ 批准（ok deraadt@ miod@），反映 OpenBSD Core Team 对 pcc 探索的正式认可；openbsd.duckdb 显示 2007-2008 年间约 20 条 pcc 编译器相关 commit（过滤 pccard/pccom/pcctwo 等无关项后），证明 pcc 探索是持续的工程实践而非一次性实验；clang/LLVM 首条 commit 2008-11-10 cnst（“remove some dead code and fix a comment; llvm/clang; ok jsg”）确证 clang 静态分析器在 2008 年 11 月已进入 OpenBSD 工程实践；OpenBSD 对 “BSD 反向流入产业” 的论据以 OpenSSH 部署数据为准——OpenSSH 被 Cisco、Juniper 等网络设备厂商广泛采用是 BSD 许可证 “允许 fork 不强制回馈” 特性的具体显现；【存疑判定依据】pcc 在 OpenBSD tech@ 邮件列表的具体讨论时间范围以 marc.info 存档逐帖核查为准，openbsd.duckdb 仅提供 commit 级证据，邮件列表讨论的细节须进一步核验；clang/LLVM 作为 gcc 替代的成熟时间以 clang 项目 Release Notes 为准——clang 2.6（2009）首发，至 clang 3.0（2011）已具备替代 gcc 4.x 的能力；0 信任原则提示：de Raadt 作为 OpenBSD 创始人对 gcc GPLv3 的批评存在自利偏差——de Raadt 有动机将许可证冲突叙述为 “工程必要性” 以正当化 pcc/clang 替代路径；但 openbsd.duckdb 提供的 pcc 导入 commit 是代码级客观证据，不受当事人自述偏差影响
