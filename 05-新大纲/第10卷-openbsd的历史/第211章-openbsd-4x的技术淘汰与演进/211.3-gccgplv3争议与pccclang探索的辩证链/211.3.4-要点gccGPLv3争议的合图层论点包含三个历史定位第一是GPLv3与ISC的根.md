# 211.3.4 要点gccGPLv3争议的合图层论点包含三个历史定位第一是GPLv3与ISC的根

**要点**：gcc GPLv3 争议的合图层论点包含三个历史定位。第一是 GPLv3 与 ISC 的根本分歧是许可证哲学而非技术问题——FSF 的 copyleft 与 OpenBSD 的 ISC 是两种自由观的对立（FSF “用户自由” vs OpenBSD “采纳者自由”），二者各有适配而非优劣之分，对应总纲第 13 条 “法律与道德是利益分配”——FSF 的 “保护用户自由” 与 OpenBSD 的 “尊重采纳者自由” 均是各社区利益的形式主义化政治产物，二者在利益分配的根本层面不存在 “对错”，仅有 “适配”；第二是 OpenBSD 的 gcc→clang/LLVM 切换既因 GPLv3 也因技术优势——de Raadt 与 espie@ 在 tech@ 邮件列表的发言显示许可证因素（GPLv3 与 ISC 不兼容）与技术因素（clang 的更好诊断信息、模块化设计）均为动机，前者在 de Raadt 的发言中权重更高，后者在 espie@ 的发言中权重更高，pcc 导入（2007-09-15 otto commit `60b4da4bc6418e6654a995e733a66436798b5bc0`）与放弃、clang/LLVM 探索（2008-11 cnst 首条 commit）与最终采纳（OpenBSD 5.7 2015.5 默认 clang）构成完整的改革路径；第三是历史结果是 clang/LLVM 在多个 BSD 项目（FreeBSD 10.0 于 2014.1、NetBSD、OpenBSD 5.7 于 2015.5、DragonFly BSD）取代 gcc 作为默认编译器，证明 OpenBSD 路线的可行性，但 Linux 仍坚持 gcc 作为默认编译器（部分发行版提供 clang 选项），证明二者各有适配——这一历史结果是总纲第 4 条 “分离聚合是永恒规律” 的具体显现，gcc 与 clang/LLVM 在 Linux 与 BSD 间分化，二者并存而非一方完全替代

**史料**：de Raadt、espie@ 邮件列表发言（<https://marc.info/?laccopenbsd-tech>）；openbsd.duckdb openbsd-src 仓库 commit `60b4da4bc6418e6654a995e733a66436798b5bc0`（2007-09-15 otto pcc 导入）；openbsd.duckdb openbsd-src 仓库 clang/LLVM 相关 commit（首条 2008-11-10 cnst）；FreeBSD 10.0 Release Notes（<https://www.freebsd.org/releases/10.0R/relnotes/>）；OpenBSD 5.7 Release Notes（<https://www.openbsd.org/57.html>）；Linux 各发行版默认编译器记录 ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：gcc GPLv3 争议的合图层本质是利益分配的承认——FSF 的 copyleft 与 OpenBSD 的 ISC 各自服务于其生态的利益分配，所谓 “道德” 立场是各社区利益的形式主义化政治产物，合图层不裁定 “对错”，仅承认 “适配” 的差异；总纲第 21 条——革命与改革是历史方法论的分歧：FSF 选择革命（通过 GPLv3 改变许可证游戏规则），OpenBSD 选择改革（fork 后逐步探索替代，pcc 导入后因功能不足放弃，转而探索 clang/LLVM）——改革的困难高于革命（pcc 探索失败是改革路径的代价），但 clang/LLVM 的最终成功证明改革路径的可行性，对应总纲第 21 条 “破山中贼易，破心中贼难”——破除 gcc 的 “心中贼”（许可证依赖）比破除 pcc 的 “山中贼”（功能不足）更难

**辨析**：考据过程留痕——【查证来源】FreeBSD、NetBSD、OpenBSD、DragonFly BSD 切换至 clang/LLVM 的具体时间以各自 Release Notes 为准——FreeBSD 10.0（2014.1）将 clang 作为默认编译器，OpenBSD 5.7（2015.5）完成切换，二者间隔约 17 个月；【交叉验证方法】OpenBSD pcc 导入与 clang/LLVM 探索的时间线以 openbsd.duckdb openbsd-src 仓库 commit 记录为代码级证据——pcc 导入 2007-09-15（otto commit `60b4da4bc6418e6654a995e733a66436798b5bc0`），clang/LLVM 首条 commit 2008-11-10（cnst），OpenBSD 5.7 发布 2015-05-01（clang 默认），三者构成 2007-2015 约 8 年的改革路径；Linux 仍坚持 gcc 的原因以 Linux 各发行版文档为准——Debian、Fedora、Ubuntu 等主流发行版默认 gcc，部分发行版（如 Alpine）默认 clang；【存疑判定依据】GPLv3 与 ISC 的 “自由观对立” 的具体表现以 FSF 与 OpenBSD 各自的官方文档为准——FSF “用户自由” 主张用户运行、研究、修改、分发软件的自由，OpenBSD “采纳者自由” 主张采纳者自由使用代码而不强制回馈的自由，二者在前理解层面不可通约；合图层承认争议的部分不可调和性——FSF 的 copyleft 与 OpenBSD 的 ISC 在许可证哲学层面不可调和，但 clang/LLVM 作为 BSD 许可证编译器的出现提供了技术层面的和解路径，使 OpenBSD 可在保留编译器技术能力的同时去除 GPLv3 约束；0 信任原则提示：合图层的撰写须警惕两种叙事陷阱——其一为 “FSF 正当、OpenBSD 逃避自由” 的 FSF 中心叙事，其二为 “OpenBSD 正当、FSF 强制回馈” 的 BSD 中心叙事，两种叙事均以道德判断取代史观审视，违反 “不偏袒叙事姿态”
