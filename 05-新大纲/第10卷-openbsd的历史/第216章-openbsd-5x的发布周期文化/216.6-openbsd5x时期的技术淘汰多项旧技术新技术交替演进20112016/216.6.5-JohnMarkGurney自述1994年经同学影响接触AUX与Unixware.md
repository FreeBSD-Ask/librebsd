# 216.6.5 JohnMarkGurney自述1994年经同学影响接触AUX与Unixware

- John-Mark Gurney 自述 1994 年经同学影响接触 A/UX 与 Unixware 后，在 Slackware（目录硬性布局）、NetBSD（当年安装文档难懂）与 FreeBSD 之间选择后者，以 230KB 引导块完成 1.1.5.1 安装；高中时期提交 fsck 指定文件系统参数的约五六十行补丁并持续撰写工具与 SCSI man page，1997 年初获 commit bit。 [存疑脚注] 转写记为 AUX、fisk、MS-TOS，分别应为 A/UX、fsck 及待核的 DOS 变体；引其入 commit bit 的 George 具体所指待核。（BSD Now EP61，[900.66-1115.64]，L1）
- IPsec 现代化项目由 Netgate（pfSense 开发商）的 Jim Thompson 发起、经 FreeBSD Foundation 资助 Gurney 执行：FreeBSD opencrypto 框架长期缺失 AES-CTR 与 AES-GCM 模式，未利用 AES-NI 与 PCLMULQDQ 指令，项目目标是在廉价商用硬件上经 pfSense 实现约 10Gb/s 加密转发，而彼时软件加密仅数百 MB/s。（BSD Now EP61，[1117.88-1264.12]，L1）
- 当事人给出密码学工程论证：CBC 加密因块间数据依赖无法流水线化（解密方向可反向并行），CTR 以加密计数器异或明文消除依赖；GCM 作为 AEAD 将加密与认证合一提升吞吐；ChaCha20-Poly1305 尚处草案但其软件性能适合无 AES 指令的设备；Gurney 自写的新 GCM 软件实现性能优于 OpenBSD 版并计划反馈；他主张密码学实现应从五个收敛为两三个以便修错与复核，并指出 OpenBSD 版本缺少 FreeBSD 的 SMP 锁但差异仅数行。（BSD Now EP61，[1355.10-1662.62]，L1）
- 主持人转述 OpenBSD 5.6（2014 年 11 月 1 日发布）要点：作为六个学期准时发布周期的延续，5.6 是首个正式搭载 LibreSSL 的版本，新增休眠至全加密文件系统的能力；移除 AltQ 插件式流量整形框架（研究使命完成，HFSC 直用并简化配置），并处于服务栈过渡期——Apache 已由 Nginx 替代、下版再由 httpd 接替，Sendmail、BIND 分别让位 OpenSMTPD 与 Unbound，Kerberos、Bluetooth、TCP wrappers 同时移除；发行歌与 CD 套装销售为 OpenBSD Foundation 主要收入。 [存疑脚注] 转写将 httpd 记为 HDBD、OpenSMTPD 记为 open SMTBD，须以 5.6 官方 changelog 复核。（BSD Now EP61，[479.30-754.10]，L2）
- Theo de Raadt 亲述 OpenBSD 起源：386BSD 停滞、NetBSD 成立后他作为首批四人之一加入；随后因与 NetBSD 的冲突失去仓库访问权，最终另立仓库，OpenBSD 由此诞生。（BSD Now EP6，[508.09-609.45]，L1）
- CSRG 遭入侵事件使其重新转向安全，此后 OpenBSD 建立全代码审计传统；审计后又认识到审计还不够，继而引入 ProPolice 等防护机制。（BSD Now EP6，[594.81-721.24]，L1）
- OpenBSD 几乎不设正式政策，开发者各自在领域内推进，de Raadt 自称最后的协调者；项目不维护分支，开发者与用户同处一条前进的代码路径，并鼓励用户运行快照。（BSD Now EP6，[845.54-908.82]，L1）
- de Raadt 主题演讲论述 64 位 time_t 的必要性：32 位与 16 位嵌入式系统仍将长期存在，SCADA 等关键基础设施升级周期缓慢，须尽早跨越 Y2038 时间曲线。（BSD Now EP6，[1131.78-1233.30]，L1）
- FreeBSD 发行工程团队在代码冻结后审批所有针对该分支的变更，目标是在已知良好状态上修复既有问题而非引入新特性，以降低升级回归风险。（BSD Now EP2，[2347.62-2437.94]，L1）
- Glen Barber 加入 FreeBSD 基金会后获得专职时间协调发布流程，并兼管集群管理团队与项目资源维护，使发布节奏不再完全依赖志愿者的时间。（BSD Now EP2，[4398.47-4558.76]，L1）
- FreeBSD 10-CURRENT 自 2013 年 9 月起不再默认构建 GCC，基本系统改以 Clang 为默认编译器；需要 GCC 的场景改由 ports 提供现代版本。（BSD Now EP2，[543.86-622.62]，L2）
- LDNS 与 Unbound 正被移植入 FreeBSD 基本系统，计划在 10.0 前移除 BIND；主持人预期此举可减少约三分之一的安全公告负担。（BSD Now EP2，[4075.30-4225.94]，L1）
- Poudriere 以 jail 隔离并发构建二进制包，可在一台机器上按 FreeBSD 版本与架构分 jail 编译，并以增量重建与摘要签名支撑自有 pkg 仓库分发。（BSD Now EP2，[865.40-904.68]，L2）
- 该期头条报道 OpenBSD 已实现 64 位 time_t，以避免 2038 年 32 位时间戳溢出；该改动使 32 位平台也能跨越 Y2038 时间曲线。（BSD Now EP2，[71.70-150.60]，L2）
- Henning Brauer 自述正在重写 PF 的队列子系统以取代旧 ALTQ：旧实现约九千行代码、带有 32 位上限且使用方式过于困难，新实现按 PF 原生方式重建队列功能；计划保留旧 ALTQ 一至两个发布周期供用户过渡，届时重命名若干冲突关键词，迁移成本基本只是一次配置调整。（BSDTalk EP214，[90.0-179.32]，L1）
- rthreads 是 OpenBSD 5.1 发布后 current 中最重大的变化：一对一的线程实现使用户态每个线程对应一个内核线程，取代此前内核只见单一进程的用户态模拟线程；旧实现要求全部文件描述符置为非阻塞并手工模拟阻塞语义，既无法利用多核又不可能百分之百正确。作者据当事人口述约在 2004 或 2006 年提交首批代码，启用后经过一个完整六个月开发周期除错，主要遗留问题是 CPU 时间统计与文件描述符表锁定。 [存疑脚注] 受访者本人对 rthreads 首批提交年份不确定（2004 或 2006），转写将提交者名转写为 TATU，通常应指 tedu（Ted Unangst），须以仓库提交记录核证（BSDTalk EP214，[2214.26-2427.73]，L1）
- BGPD 是第一个采用 PF 风格配置语言与内部消息传递框架的守护进程，其后 OpenNTPD、OpenSMTPD 等新写守护进程均沿用该框架，重复代码后来收拢为库；设计目标是使仅懂英语者读配置文件即可了解守护进程行为，与 sendmail 需要八百页专著的复杂性形成对照。OpenSMTPD 沿用 OpenBSD 特权分离模型，受访者判断 BSD 许可的邮件服务器在此之前长期缺位。（BSDTalk EP214，[2769.76-2909.16]，L1）
- OpenBSD 存储栈早期即决定不在硬件 RAID 控制器之上另建逻辑盘接口，而是在控制器之上加 SCSI 模拟层；此后业界反向跟进，硬件 RAID 控制器如今直接在逻辑盘上呈现 SCSI 接口，SCSI 由一种存储接口演化为通用协议。SATA 设备经 SAS ATA 翻译层归入同一路径，与 Linux 与 Solaris 的做法一致，仅旧式 PCI IDE 设备尚未迁移；项目目标是使一切硬件存储最终呈现为 SCSI 盘，SD 卡与 U 盘均已达成，遗留的只有老式并行 ATA 与个别旧架构直连盘驱动。（BSDTalk EP219，[423.04-551.28]，L1）
- SCSI 协议的长寿源于其结构简单与后向兼容：协议本质是命令帧加可选数据载荷，每版协议虽为新读写命令各立条目，但新版本包含对旧版的兼容支持，需要新特性时只是增设新消息。闪存以薄置备 SCSI 盘形式通告逻辑块与物理块无关，配合四千字节物理块对五百一十二字节逻辑块的通告，协议已足以支撑上层软件对存储特性的利用，其灵活性正是普遍性的原因。（BSDTalk EP219，[570.16-700.64]，L1）
- 存储性能的瓶颈已从设备数转向命令槽资源调度：二十年前的 SCSI 总线挂七台设备、每台一至两个命令槽，如今 SAS 与 RAID 控制器可管理一二八至五一二台设备、每台可有上千命令槽，而适配器自身槽位有限，如何调度这些槽位成为核心问题。受访者刻意淡化大内核锁问题的优先级，理由是处理器增速远超磁盘与适配器，宁可在锁上自旋也不可浪费命令槽；SCSI 中层细粒度锁虽已预先布置，其正确性须待整个内核脱离大锁才能验证。（BSDTalk EP219，[727.06-846.5]，L1）
- MCLGETI 的设计动因是巨型帧描述符环的内存压力：九千字节帧乘以五百一十二项描述符环会侵占内核本已有限的内存，在部分架构上内核仅能使用主机内存中的六七十兆；该机制默认仅为环填入两个槽位，按每个中断的实际用量渐进扩大分配，其后 Theo de Raadt 将其推广为背压机制，在系统耗尽处理器时间时限制递交给网卡的包量以归还算力。受访者自述其生产系统已放大其他拥塞限制，仅依赖 MCLGETI 承担过载保护。（BSDTalk EP219，[1002.74-1234.8]，L1）
- Brauer 自述其在柏林 hackathon 收尾的校验和处理重写：新模型假定每条输出路径都具备校验和硬件卸载能力，栈上层不再预计算与就地修补校验和，仅需在数据包上置标记声明需要何种协议校验和，全部计算集中到输出路径末端的单一位置，仅在确知该路径无卸载能力时才回退软件实现。（BSDTalk EP234，[305.23-320.29]，L1）
- 旧实现的缺陷根源在于部分网卡（以 Intel 与 Broadcom 千兆芯片为代表，约占服务器市场九成）要求保留伪头校验和，而另一些网卡做全量卸载，PF 无法判别数据包携带的是部分校验和还是完整校验和，就地更新便可能出错；重写后栈上层彻底不管校验和，桥接路径也被修正；ICMP 错误报文中被引用原始包的校验和因多数被截断而无法验证，选择忽略，并以手工构造异常报文的专用工具对 PF 行为做验证。（BSDTalk EP234，[822.90-1029.94]，L1）
- 新排队子系统分两层：优先级排队极为简单，把 ifnet 结构的单一输出队列头改为八个队列的数组并按序处理，默认优先 CARP 公告与生成树报文以防主备双主故障，且常开不可关闭；带宽整形部分则取代约一万二千行的 AltQ——后者原是 Kenjiro Cho 十余年前的论文研究项目，2003 年 Cho 与 Brauer 将其并入 PF 使 PF 充当分类器，次年加入的 HFSC 因语法难懂而少有人用，用户多用较简单的 CBQ——新版保留可完全表达 CBQ 的 HFSC、重写胶水层并删除可插拔调度器框架，全系统缩至约三千五百行，随 OpenBSD 5.5 提交。（BSDTalk EP234，[374.70-624.38]，L1）
- 关于 PF 的可移植性，Brauer 区分了两类情形：OpenSSH 是用户态、大体以 POSIX 为边界的守护进程集合，故能维持 portable 版本；PF 是内核的内嵌成分，依赖各操作系统的内存管理，可移植难度更高，但 Apple 与 QNX 均已集成 PF，FreeBSD 的移植虽面对不同的内存管理也无需重写一半，各系统挂接网络栈的方式差异有限。（BSDTalk EP234，[1449.18-1525.40]，L1）

**史观**：
