# 216.6.3 gcc → clang/LLVM 替代（5.6-5.7，2014-2015）

**要点**：OpenBSD 的 gcc→clang/LLVM 切换是渐进过程——openbsd.duckdb 显示 2014-10-23 brad commit 6ad07a3f66f922604b423b6f0c03f220ffafd886 提及“Now that gcc2 is gone”，表明 gcc2 在 5.6 开发周期（2014 年下半年）已移除；2015-01-04 daniel commit 84938a7b9c572efc85c2b06e24f6122d8cc98702“remove code for ancient gcc”，2015-02-15 miod commit 1c93e2863e3b9f1c0c7e436e2db3db4debd0d628“Remove ancient gcc workaround on mips”，表明 5.7 开发周期（2015 年上半年）继续清理 gcc 残留代码；切换动机包括 gcc GPLv3 许可证与 OpenBSD ISC 许可证传统的冲突、clang/LLVM 的模块化设计与更好诊断信息

**史料**：openbsd.duckdb openbsd-src 仓库 commit 6ad07a3f66f922604b423b6f0c03f220ffafd886（2014-10-23 brad“Now that gcc2 is gone”）、commit 84938a7b9c572efc85c2b06e24f6122d8cc98702（2015-01-04 daniel“remove code for ancient gcc”）、commit 1c93e2863e3b9f1c0c7e436e2db3db4debd0d628（2015-02-15 miod“Remove ancient gcc workaround on mips”）；OpenBSD 5.7 Release Notes（<https://www.openbsd.org/57.html>）；Marc Espie 在 tech@ 关于 clang 切换的讨论（<https://marc.info/?laccopenbsd-tech>）［A］

**史观**：总纲第 24 条——法律结构：gcc GPLv3 与 OpenBSD ISC 许可证哲学的张力催生 clang/LLVM 替代——OpenBSD 以“许可证纯洁性优先”为预设，宁可承受编译器切换的工程代价也不接受 GPLv3 对基本系统的“污染”；技术选择的代价：切换的代价是部分架构的编译器稳定性需重新验证

**辨析**：gcc 到 clang/LLVM 的切换是渐进过程而非单一版本切换——gcc2 在 5.6 开发周期（2014 年下半年）已移除（brad 2014-10-23 commit 明确记载“Now that gcc2 is gone”），5.7 开发周期（2015 年上半年）继续清理 gcc 残留代码（daniel 2015-01-04、miod 2015-02-15）；切换动机以 de Raadt 与 Espie 在 tech@ 邮件列表的发言为准——许可证因素（GPLv3 与 ISC 不兼容）与技术因素（clang 的更好诊断信息）均为动机，前者在 de Raadt 的发言中权重更高；clang/LLVM 在不同架构上的成熟时间以 Release Notes 为准——amd64、i386 先行，arm64、sparc64 后续跟进
