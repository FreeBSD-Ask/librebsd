# 216.6.2 OpenSSL → LibreSSL fork（5.6，2014）

**要点**：2014 年 4 月 Heartbleed 漏洞（CVE-2014-0160）暴露 OpenSSL TLS heartbeat 扩展的缓冲区越界读取缺陷；OpenBSD 团队当即响应——2014-04-07 djm commit af0b15b8442f"cherrypick fix for CVE-2014-0160‘heartbleed’vulnerability from OpenSSL git"，2014-04-13 miod commit 9eac5592c816 导入 OpenSSL 1.0.1g，2014-04-14 beck 开始移除 OpenSSL 中的 Atalla/AEP 引擎，jsing 开始对 OpenSSL 代码应用 KNF 格式化；LibreSSL 作为独立库的首次 commit 为 2014-07-12 jsing commit b6553af36068"Initial version of libressl - a library that provides a clean, simple, consistent and secure-by-default API"；LibreSSL 作为 OpenBSD 5.6（2014.11）默认 TLS 库发布

**史料**：openbsd.duckdb openbsd-src 仓库 commit af0b15b8442f（2014-04-07 djm Heartbleed fix）、commit 9eac5592c816（2014-04-13 miod 导入 OpenSSL 1.0.1g）、commit b6553af36068（2014-07-12 jsing“Initial version of libressl”）；CVE-2014-0160 详情（<https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2014-0160>）；Heartbleed 官网（<http://heartbleed.com/>）；LibreSSL 官方公告（<https://www.libressl.org/>）；OpenBSD 5.6 Release Notes（<https://www.openbsd.org/56.html>）［A］

**史观**：密码学：Heartbleed 暴露密码学库的工程质量问题——OpenSSL 作为全球 HTTPS 基础设施的核心组件，其代码质量（dead code、维护混乱）与安全关键性不匹配，这一矛盾催生 LibreSSL fork；法律结构：LibreSSL fork 是 OpenBSD 对 OpenSSL 工程失败的回应，选择 fork 而非合作是 OpenBSD 许可证纯洁性哲学的实践

**辨析**：LibreSSL fork 的具体时间线——Heartbleed 于 2014-04-07 披露，OpenBSD 当即开始 OpenSSL 代码清理（2014-04-13 导入 1.0.1g，2014-04-14 beck 移除引擎、jsing 应用 KNF），LibreSSL 作为独立库的首次 commit 为 2014-07-12（jsing），LibreSSL 随 OpenBSD 5.6（2014-11）作为默认 TLS 库发布；Beck 是 fork 的主要协调者，jsing 是 libressl 库初始代码的提交者，二者角色不同——Beck 负责对外沟通与 dead code 清理，jsing 负责库架构设计与初始实现；Heartbleed 的责任归属——部分归咎 OpenSSL 项目（代码质量差、维护流程不透明），部分归咎使用方未及时更新；漏洞的实际影响范围无权威统计 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
