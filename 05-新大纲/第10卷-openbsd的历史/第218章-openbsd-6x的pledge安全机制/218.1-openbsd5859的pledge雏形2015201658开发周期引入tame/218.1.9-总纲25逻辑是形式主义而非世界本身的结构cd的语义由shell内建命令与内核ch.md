- 总纲25 逻辑是形式主义而非世界本身的结构：cd 的语义由 shell 内建命令与内核 chdir 系统调用共同完成，目录权限由内核强制而非信任用户程序，说明命令语义是经系统调用形式化的产物。（BSD Now EP236，[3777.2-3821.5]，L2）

- 总纲10 动手者创造历史：Cantrill 叙述其通过删除代码完成的罕见系统改进：SmartOS 低内存时的 kmem 迁移逻辑会在持有锁的状态下“狩猎”magazine 层数以百万计的缓冲区，使系统陷入无法观测的停顿，统计工具本身亦被锁死；他判定该逻辑与低内存场景自相矛盾而整体删除，diff 全为减号、未新增一条指令，并主张内核函数名中永远不应出现 hunt 之类动词，还要为此补写注释说明为何不再如此。系统史由动手者以手术刀式的删除书写，而非仅由宏大的架构图书写。（BSD Now EP117，[1823.68-1876.66]，L1）
- 总纲21 革命与改革是历史方法论的分歧：Cantrill 断言“Linux 不是被设计的，它是演化的”，任何形似整体设计之物都会激起社区的免疫反应，而 ZFS、DTrace、容器与安全这类复杂构造无法靠演化抵达，必须有人重新思考整体并获准整合大型成果；FreeBSD 与 illumos 的价值恰在于允许这种整体性设计着陆，优秀想法还能在共享价值观的系统间交叉授粉。他将自由软件内部的路线之争表述为革命性整体设计与渐进演化两种历史方法论的分歧，并归因于 Linux 缺乏承担架构方向的责任结构、无人为设定架构方向负责。（BSD Now EP117，[4133.02-4236.92]，L1）
- 总纲15 文化即形式主义：Cantrill 力陈命名即软件的基石而非琐碎细节：名字将被未来世代用于理解、扩展既有设计并判断其做法是否恰当，命名失当如同基石被掀翻在街心，是系统沦为贫民窟、无法起造摩天楼的根源。他举 DNF 包管理器连作者本人都拒答缩写含义、systemd 与 libsystemd 以库之名封装守护进程且边界无限扩张、KVM 之名与机房键盘视频鼠标切换器相冲撞为例，指出命名混乱会迫使真正理解系统的善意聪明人自我怀疑；命名之争的僵局往往暗示存在尚未被想到的第三方案。（BSD Now EP117，[2781.72-2809.82]，L1）
- 总纲9 经验优先：allocation throttle 反转了跨设备均分分配的理论预设，以客户环境与内部系统的实际观测为准：池碎片化后各设备分配速度分化，索性“why not give more work to devices that are actually responding faster”（2193.18-2199.20），按响应能力倾斜工作负载使快设备保持满载。这一设计出自运维经验而非抽象公平原则，印证经验观测优先于理论均分的工程认识论。（BSD Now EP116，[2145.16-2202.86]，L1）
- 总纲4 分离聚合是永恒规律：Compressed ARC 衍生出 compressed send/receive 复制（由其同事 Dan Kimmel 完成接收端关键工作），后续 ABD 内存表示（以散布-聚集页表取代 KMEM 缓存）源于 Linux 侧设计并回流惠及全部平台，L2ARC 元数据精简则复用块指针校验和以获得 SHA-256/512 级校验。代码在 Illumos/Delphix、Linux、FreeBSD 等平台间分离又聚合，恰是 OpenZFS 时代跨平台分叉之后走向再聚合的活体样本。（BSD Now EP116，[2949.82-3055.54]，L1）
- 总纲10 动手者创造历史：Theo de Raadt 的 pledge 状态更新显示 600 个基本系统 ELF 二进制中 368 个已完成改造，并区分不值得列出的平凡工具与 reboot、mount、perl 等无法 pledge 的顽固组件，主张“low hanging fruit first”（715.35-717.25）。pledge 的历史不是安全理论史，而是无数默默改造工具的手工劳动史——默默做事的转换工作而非台前宣言构成 OpenBSD 安全路线的实体。（BSD Now EP116，[539.38-590.78]，L2）

- 总纲6 和解优于斗争：Hubbard 提出社区管理至少与技术管理同等重要、有时更为优先的论断——“社区管理这一环更重要，否则项目没有未来；代码是不会有的，剩下的只是弃置软件”（6902.92-6948.02）；他以乐队因无法就艺术方向达成一致而解散作比，指出开源项目同样会在人际失谐中分裂或停滞（6964.42-7010.14）。这一判断把项目存续的因果链从代码生产逆转到共同体的维系，与其强调友善招募、团队对话优先于路线争吵的立场一以贯之。（BSD Now EP113，[6902.92-6948.02]，L1）
- 总纲5 没有必然性，只有偶然性：DTrace 的诞生在当事人复盘中处处是偶然而非必然：Cantrill 向论文导师提出改写内核文本作追踪的设想，得到的回答是“我相信如果这可行，早就有人做过了”（1575.18-1580.06）；多年间“DTrace 将解决一切问题、DTrace 知晓一切探针”只是内核组内部“传奇蒸汽件”（1634.54-1649.40）；而 Leventhal 的加入仅因路过办公室时凭 SPARC 架构的一个怪癖想到用户态追踪方案，换来一句“去做吧”。技术史由具体的人在偶然机缘下的日常劳动推进，先于任何总体规划。（BSD Now EP112，[1538.56-1691.96]，L1）
- 总纲13 法律与道德是利益分配：Leventhal 对开源的论证本质是利益结构分析而非道德宣示：开源的价值在于软件不归属某一家公司，公司消失或“变坏”时用户仍有退路；他引 Stephen O'Grady《The Software Paradox》说明软件总利润上升而单一专有软件价值下降，并将开源概括为社区参与、招聘与入市路径；其闭源反事实尤为锋利——“如果 ZFS 或 DTrace 是闭源专有的，它们只会存在于某个垂死的、越来越少人关心的操作系统里”（2272.68-2287.40），即便免费发放二进制也只会加速社区重写兼容实现。许可证与社区规则在此显现为利益分配机制。（BSD Now EP112，[2149.92-2327.12]，L1）
- 总纲4 分离聚合是永恒规律：GNOME 与 FreeBSD 的协作史在本期呈现分离聚合的完整弧线：上游发布、下游追补十个 bug、六个月后重演的分离循环，被 jhbuild 每日构建打破——破坏发生一两天内即可定位到具体提交并联系到记忆尚新的作者；Baptiste 主动驻留 #freebsd-gnome 频道充当跨社区界面，并明言让上游了解 BSD 的能力与短板是“对双方都赢”（1972.90-1975.60）。两个原本各自演化的社区由偶发的个人接触走向制度化聚合，正是分离聚合规律的当代表现。（BSD Now EP99，[1938.52-1998.42]，L1）
- 总纲22 知识注定过时：OpenBSD 以约 350 行的 doas 取代基本系统中滞留多年的 sudo（旧版约一万行），把 LDAP 等扩展特性连同 sudo 一并降级至 ports；主持人指出基本系统中冻结的软件版本注定落后于上游演进，与其反复审计膨胀的新代码不如重写最小必需实现，man 手册仅一页半与三个命令行旗标即构成“足够好”的边界。承认 base 内知识必然过时、把演化自由让渡给包管理体系，是“知识注定过时”命题的一次工程化演练。（BSD Now EP99，[610.64-681.16]，L2）
- 总纲10 动手者创造历史：Zoulas 自述其 NetBSD 安全官身份并非任命所得，“人人都去做他们认为能帮上忙的事”（1438.96-1447.12）；blacklistd 亦非立项规划的产物，而是他面对自身服务器日志膨胀时的动手自救。项目角色与工具产出均生长于具体动手者在偶然遭遇中的自发行动，这一时期的 BSD 史应当由这些动手者的实践而非职位与蓝图来解释。（BSD Now EP87，[1438.96-1447.12]，L1）
