# 218.1.4 要点pledge的CVScommitlog与pledge2手册页历次版本是研究p

**要点**：pledge 的 CVS commit log 与 **pledge(2)** 手册页历次版本是研究 pledge 演进的核心史料；openbsd.duckdb openbsd-src 仓库中 pledge 相关 commit 自 2015-10-09 起（deraadt“Rename tame() to pledge()”），后续 semarie、benno、millert 等 committer 持续扩展 pledge 覆盖范围；pledge 的功能扩展过程以 commit log 中 message_subject 含“pledge”关键字的 commit 为索引；统计结论印证——openbsd.duckdb openbsd-src 仓库总 commit 数 245,904（统计结论 C-05），6.x 时期（2015-2020）commit 量处于 fork 后的中后期阶段；openbsd.duckdb openbsd-src 仓库 Mann-Kendall 趋势检验（统计结论 C-10）显示 1993-2026 年月度 commit 量呈下降趋势 slope = −0.24/月 p = 0.0358 95% CI [−0.46, −0.016]，反映 OpenBSD 在 6.x 时期从 fork 后的工程节奏继续向稳态收敛——pledge/unveil 等安全机制的引入作为离散工程事件叠加于下降趋势之上

**史料**：openbsd.duckdb openbsd-src 仓库 pledge 相关 commit（2015-10-09 起 deraadt、semarie、benno、millert 等）；**pledge(2)** 手册页历次版本（<https://man.openbsd.org/pledge.2>）；tech@ 邮件列表 pledge 讨论（<https://marc.info/?laccopenbsd-tech>）；openbsd.duckdb 查询 L1.1.1（经 L1.1.2 交叉验证）显示 openbsd-src 仓库 2015-2019 年逐年 commit 量与占 4 大 BSD src 合计百分比数据未在报告前 30 行中显示（L1.1.2 查询结果共 124 行，报告仅显示前 30 行覆盖 1995-2002 年），须以数据库直接查询补全；openbsd.duckdb openbsd-src 仓库 ARIMA 模型（统计结论 C-31：ARIMA(5,0,5) AIC = 176.47，Python statsmodels.tsa.arima.model.ARIMA 实现，查询日期 2026-07-27）；openbsd.duckdb openbsd-src 仓库预测精度指标（统计结论 C-35：MAPE = 45.21% RMSE = 187.96 coverage = 84.21%，Python 自实现 MAPE/RMSE 计算，查询日期 2026-07-27） ［A］

**史观**：0 信任原则：pledge 考据是 0 信任原则在安全机制史研究中的实践——commit log 中的 pledge 相关 commit 须以 message_subject 与 file_path（lib/libc/sys/pledge.2、regress/sys/kern/pledge/）交叉筛选方可定位，仅凭 message_subject 关键字可能遗漏未标注“pledge”但实际扩展 pledge 覆盖的 commit；统计结论印证——C-31 ARIMA(5,0,5) 模型以工程节奏的统计刻画印证“分离聚合是永恒规律”（总纲第 4 条），6.x 时期 pledge/unveil 的离散工程事件叠加于 ARIMA 刻画的趋势分量之上；C-35 MAPE = 45.21% 反映“实践先于理论”（）的统计显现——ARIMA 模型对 OpenBSD commit 量的预测能力有限，说明 pledge/unveil 等离散事件对开发节奏的扰动难以被线性模型完全捕捉

**辨析**：pledge 演进的具体里程碑以 Release Notes 与 commit log 交叉验证为准——Release Notes 记录用户可见的 pledge 覆盖扩展，commit log 记录具体代码变更；commit log 中的 pledge 相关 commit 以 file_path 含“pledge”或 message_subject 含“pledge”为筛选条件，openbsd.duckdb commit_files 表中 lib/libc/sys/pledge.2 与 regress/sys/kern/pledge/ 路径下的 commit 为权威索引；openbsd.duckdb 查询 L1.1.1 局限：L1.1.1 报告仅显示 23 仓库 572 行结果中的前 30 行（全为 dragonfly 仓库），openbsd-src 逐年数据须经 L1.1.2 查询交叉验证获取，但 L1.1.2 报告亦仅显示 124 行中的前 30 行（覆盖 1995-2002 年），2015-2019 年 openbsd-src 份额数据须以数据库直接查询补全；openbsd-src 为 GitHub 镜像，commit 量可能滞后于 OpenBSD CVS 主仓；commit 量反映开发活跃度但不等于代码质量；openbsd.duckdb 查询 L2.3.1.pledge 与 L2.3.1.unveil 在中观模式挖掘报告中均不存在（报告仅含 L2.3.1.ZFS、L2.3.1.Capsicum、L2.3.1.bhyve、L2.3.1.Clang、L2.3.1.ARM64、L2.3.1.RISC-V 等 FreeBSD 特性查询，未覆盖 OpenBSD pledge/unveil 子系统），pledge/unveil 相关子系统级 commit 数据须以 freebsd.duckdb 直接查询 file_path 维度（如 lib/libc/sys/pledge.2、lib/libc/sys/unveil.2、regress/sys/kern/pledge/、regress/sys/kern/unveil/）补全；**统计局限性标注**——C-35 MAPE = 45.21% 高于行业基准（通常 < 30%），coverage = 84.21% 低于其余 3 BSD src 仓库（freebsd-src 94.74%、netbsd-src 94.74%、dragonfly-src 89.47%），反映 openbsd-src 月度 commit 量波动较大，ARIMA 模型预测能力有限，6.x 时期 pledge/unveil 等离散工程事件作为结构性冲击构成 ARIMA 模型未捕捉的异方差性来源；C-31 ARIMA(5,0,5) 的 AIC = 176.47 在 4 BSD src 仓库中居中（freebsd-src 107.39、netbsd-src −79.34、dragonfly-src 233.80），AIC 仅用于同序列内模型比较，不得跨仓库直接比较模型优劣；0 信任原则适用：统计显著 ≠ 实际显著，Mann-Kendall 趋势（C-10）与 ARIMA 模型（C-31）均刻画 openbsd-src 下降趋势，但二者基于不同统计假设，趋势方向一致性不构成模型验证，仅反映数据生成过程的稳健性
