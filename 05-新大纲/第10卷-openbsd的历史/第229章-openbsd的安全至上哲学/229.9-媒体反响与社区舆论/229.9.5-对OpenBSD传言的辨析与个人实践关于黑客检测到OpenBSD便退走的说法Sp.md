# 229.9.5 对OpenBSD传言的辨析与个人实践关于黑客检测到OpenBSD便退走的说法Sp

- 对 OpenBSD 传言的辨析与个人实践：关于黑客检测到 OpenBSD 便退走的说法，Spitzner 的观测结论是并非因其强而退，而是因其非所期——坏人只携带已知平台（Linux、Windows）的 exploit 与恶意软件，遇到预期之外的系统便径直跳过，近乎借助隐蔽求安全；其个人规则为凡联互联网的机器必用 OpenBSD，理由是其安全与他对 de Raadt 安全狂热的个人信任，私人桌面则选 Mac OS 纯为易用；另据 NetCraft 观察该组织网站多年托管于 OpenBSD 或 NetBSD、近期转 Linux，他解释纯因 HoneyWall CD-ROM 基于 RPM、网站需承担自建 RPM 的构建与分发，就 web 平台而言仍偏好 OpenBSD。（BSDTalk EP49，[1282.50-1519.84]，L1）
- 主持人观察到开发者与终端用户在媒体可见性上的结构性不对称：开发者的联系方式遍布项目页面、易于追踪，而“在不寻常场所使用 BSD 的终端用户”不为世界所知，口述资源因此天然偏向开发者叙事。节目遂公开征集终端用户故事。这一自白为口述史料在人群结构上的偏倚提供了一个当事人级别的机制说明，提示史料收集需为此偏倚留出修正空间。（BSDTalk EP88，[328.32-379.4]，L1）
- 开源推广的层间落差：管理层自上而下拥抱在合理处节省成本的开源（初创公司 40 人规模易说服，硬件靠复用退役机器、从未为 IT 服务购置新服务器）；开发者使用并参与开源；但桌面端推广屡屡受挫——用户要么受既有习惯限制、要么只信任 Microsoft 与 Adobe 的品牌符号，即便开源软件可完成同样工作。他还观察到从业者心态分野：有人愿意学习，有人宁可“出问题时把责任推给大公司”，也不愿查代码或向社区求解。（BSDTalk EP90，[356.32-457.62]，L1）
