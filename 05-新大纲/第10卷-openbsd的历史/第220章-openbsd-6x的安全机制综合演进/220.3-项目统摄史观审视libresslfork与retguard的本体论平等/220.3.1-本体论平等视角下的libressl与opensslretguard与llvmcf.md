# 220.3.1 本体论平等视角下的 LibreSSL 与 OpenSSL、RETGUARD 与 LLVM CFI

**要点**：从项目史观总纲第 8 条“本体论上各方平等”审视，LibreSSL 与 OpenSSL 在本体论上地位相等，二者皆是 TLS 实现的特定阶段状态，差异仅是工程哲学的不同而非本体等级的高下——LibreSSL 的“极简安全”（删除 dead code、简化 API、ISC 许可证）与 OpenSSL 的“功能全面”（保留向后兼容、持续新增功能、Apache 许可证）各自在其生态内具有合理性；RETGUARD 与 LLVM CFI、Microsoft CFG 在本体论上地位相等，三者皆是控制流防护机制的特定阶段状态——RETGUARD 以 per-function 随机 canary 防护返回地址，LLVM CFI 以控制流完整性图防护间接调用，Microsoft CFG 以目标地址验证防护间接调用，三者差异是工程哲学的不同而非本体等级的高下；文档与代码本体平等——LibreSSL fork 公告文本与 openbsd.duckdb commit log 在本体论上地位相等，前者塑造 fork 的叙事认知，后者记录 fork 的实际代码变更，二者共同构成 LibreSSL fork 的完整本体；RETGUARD 的设计文档与编译器实现代码在本体论上地位相等，前者塑造 RETGUARD 的设计哲学叙事，后者记录 RETGUARD 的工程实现，二者共同构成 RETGUARD 的完整本体；OpenBSD 阵营（Beck、de Raadt、Mortimer 等）与 OpenSSL 阵营（OpenSSL 维护者、下游应用维护者）在本体论上地位相等，二者的叙事须对称呈现

**史料**：项目史观总纲第 8 条原文（据原文第 25 章）、LibreSSL 与 OpenSSL 综合对比研究、RETGUARD 与 LLVM CFI/Microsoft CFG 综合对比研究、openbsd.duckdb openbsd-src 仓库 LibreSSL/RETGUARD 相关 commit、LibreSSL fork 公告与 RETGUARD 设计文档〔L1 代码/构建产物/L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 8 条——本体论上各方平等：LibreSSL 与 OpenSSL、RETGUARD 与 LLVM CFI/Microsoft CFG、OpenBSD 阵营与 OpenSSL 阵营在本体论上地位相等

**辨析**：本体论平等不等于价值中立——史家仍须呈现 LibreSSL fork 与 RETGUARD 的具体效应（工程自主与生态碎片化、安全加固与性能开销），但不得以“极简优于全面”或“全面优于极简”的前理解预先判定；【0 信任原则·本体论平等的非相对主义】本体论平等不意味着所有机制无差别，而是意味着差异是特定阶段状态的不同而非本体等级的高下；【0 信任原则·本体论平等与考据验证的区分】本体论平等是史观预设而非考据结论——史家仍须以多源交叉验证逼近史实，本体论平等不豁免考据义务

**文献**：项目史观总纲第 8 条；LibreSSL 与 OpenSSL 综合对比研究；RETGUARD 与 LLVM CFI/Microsoft CFG 综合对比研究；openbsd.duckdb openbsd-src 仓库 LibreSSL/RETGUARD 相关 commit ［A］
