# 220.3.3 解释学循环视角下的 LibreSSL fork 与 RETGUARD 评估

**要点**：从项目史观总纲第 19 条“解释学循环是历史认识的根本条件”审视，LibreSSL fork 与 RETGUARD 的评估受前理解差异制约——OpenBSD 阵营以“工程自主”与“安全优先”为前理解，OpenSSL 阵营以“生态完整”与“功能全面”为前理解，下游应用维护者以“适配成本”为前理解，外部观察者以“治理多样性”为前理解，四者难以通约；解释学循环意味着 LibreSSL fork 与 RETGUARD 的历史认识不存在中立旁观者——任何叙事都嵌入特定前理解，史家的任务不是消除前理解而是自觉呈现前理解；权力与知识在 LibreSSL fork 与 RETGUARD 的历史书写中共谋——OpenBSD 官方叙事（如 Beck 的 fork 声明、Mortimer 的 RETGUARD 设计文档、de Raadt 的 tech@ 发言）与 OpenSSL 阵营叙事（如 OpenSSL 维护者声明、下游应用维护者批评）在“什么被记录、什么被遗忘”上本身就是权力行使，本节的辩证链补足即是试图打破单一叙事的权力垄断，使 OpenBSD 阵营与 OpenSSL 阵营/批评者阵营的运点对称呈现〔订正：原括注"（88.2.5-88.2.8、88.5.5-88.5.8）"及下文"合图（88.2.8、097.5.8）"系第097章旧章号残留，本章 201.3 无对应辩证链小节号，2026-09-14 依核查报告删去括注〕；解释学循环亦适用于本审视自身——项目统摄史观审视嵌入项目统摄史观的前理解，须自觉呈现这一前理解而非伪装中立，合图不是辩证链的终结而是阶段性综合，随 LibreSSL 与 OpenSSL 演进（如 OpenSSL 3.0 与 LibreSSL 的进一步分化）与 RETGUARD 演进（如新架构扩展）须重新展开

**史料**：项目史观总纲第 19 条原文、OpenBSD 官方叙事文档（Beck fork 声明、Mortimer RETGUARD 设计文档、de Raadt tech@ 发言）、OpenSSL 阵营叙事文档（OpenSSL 维护者声明、下游应用维护者批评）、外部观察者叙事文档（TLS 库生态演进史、编译时安全机制演进史）〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 19 条——解释学循环：LibreSSL fork 与 RETGUARD 的历史认识受前理解差异制约，无中立旁观者

**辨析**：解释学循环不意味着相对主义——史家仍须以多源交叉验证逼近史实，但须自觉呈现前理解；【0 信任原则·叙事权力的自觉】本节作为项目统摄史观审视，自身亦嵌入项目统摄史观的前理解，须自觉呈现这一前理解而非伪装中立；【0 信任原则·辩证链的非终结性】辩证链四层（批评-反批评-再批评-合图）不是史家认识的终结而是阶段性综合——合图本身嵌入特定前理解，随 LibreSSL/OpenSSL 演进与 RETGUARD/LLVM CFI 演进须重新展开；【0 信任原则·对称呈现的限度】本节试图使 OpenBSD 阵营与 OpenSSL 阵营/批评者阵营运点对称呈现，但“对称”本身是史家的形式主义建构——史料的不对称性（OpenBSD 官方叙事丰富、OpenSSL 阵营批评叙事相对稀缺）使绝对对称不可能，史家须自觉呈现这一限度
