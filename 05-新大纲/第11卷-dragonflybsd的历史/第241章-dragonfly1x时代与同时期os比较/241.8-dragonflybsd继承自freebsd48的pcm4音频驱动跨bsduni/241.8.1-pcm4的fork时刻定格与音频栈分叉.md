# 241.8.1 pcm(4) 的 fork 时刻定格与音频栈分叉

**要点**：DragonFly BSD 自 fork 自 FreeBSD 4.8（**2003-06-20**）起继承 **pcm(4)** 音频驱动框架（FreeBSD 称为 pcm(4)，NetBSD/OpenBSD 称为 audio(4)），源码位于 **sys/dev/sound/pcm/** 目录——此实现未跟随 FreeBSD 5.0 后的音频栈重构，保留了 4.x 时代的实现路径。**pcm(4)** 在 DragonFly BSD 中保留至今。

**史料**：DragonFly BSD src 仓库 **sys/dev/sound/pcm/**；**pcm(4)** man page（man.dragonflybsd.org）；DragonFly BSD 1.0 Release Notes；Dillon, M. (2003). *DragonFly BSD Design Goals*.〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 1 条——源头时刻：DragonFly BSD fork 时“冻结”了 pcm(4) 的 4.x 实现；总纲第 4 条——分离聚合是永恒规律：DragonFly BSD 从 FreeBSD 分离时聚合了 pcm(4) 框架；技术选择的代价：DragonFly BSD 选择保留 4.x pcm(4) 而非跟随 FreeBSD 5.0 音频栈重构，付出代码路径分叉代价，但获得实现稳定性；边缘者贡献：pcm(4) 的最初设计者被遮蔽，Dillon 的 fork 决策是边缘者贡献的显现；总纲第 17 条——形式与内容：pcm(4) 作为“形式”（音频设备接口）保留了 4.4BSD-Lite2 的“内容”；自反性声明：本释读不预设“DragonFly BSD 中心论”——pcm(4) 在 FreeBSD、NetBSD（audio(4)）、OpenBSD（audio(4)）均有保留或演化。

**辨析**：DragonFly BSD pcm(4) 与 FreeBSD 5.0+ pcm(4) 在 fork 时刻同源，分叉发生在 FreeBSD 5.0 音频栈重构后；与 Linux ALSA 无代码共享；macOS CoreAudio 是 Apple 自研。

**文献**：DragonFly BSD Project. *DragonFly BSD 1.0 Release Notes*[EB/OL]. (2005-07-24). <https://www.dragonflybsd.org/>; DragonFly BSD Project. *pcm(4) Manual Page*[EB/OL]. <https://man.dragonflybsd.org/>.
