# 241.4.1 项目统摄史观审视

220.3 节已从总纲第 5、6、8 条切入审视 DragonFly fork 争议的偶然性、和解可能与本体论平等。本节从总纲第 13、19、21 条切入，补足对 fork 争议的利益分配本质、史料权力共谋与革命改革方法论分歧的审视，与 241.3 节形成互补而非重复。

**总纲第 13 条——法律与道德是利益分配**。任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物。DragonFly fork 争议中的批评语言常以道德化表述出现——“分叉加剧 BSD 社区分裂”“Dillon 的个人主义开发风格”“与 FreeBSD 5.x SMPng 路线的竞争浪费资源”——但第 13 条要求史家穿透道德语言的利益本质。其一，“社区分裂”批评的利益本质是 FreeBSD 社区有限的 committer 群体被分散——dragonfly.duckdb 显示 fork 后 DragonFly 2003 年仅 10 位贡献者、2005 年峰值 22 位，相对 FreeBSD 数百 committer 群体属少数派，但 Dillon 与 Jeffrey Hsu（fork 公告后 8 天即首 commit `2003-07-24T05:21:48Z`）等核心开发者从 FreeBSD 流向 DragonFly 是开发者资源的重新分配。其二，“个人主义开发风格”批评的利益本质是 DragonFly 的 bus factor 极低（2003 年 top10 占 100.00%、2008 年 top10 占 91.56%，Dillon 个人占比从 53.13% 降至 21.84% 仍居主导）让 FreeBSD 社区无法通过常规治理路径影响 DragonFly 技术决策——治理结构的不可影响性被表述为道德缺陷。其三，“竞争浪费资源”批评的利益本质是两个项目同时维护 SMP 路径的重复投入——但第 13 条指出社区治理是形式主义的政治产物，FreeBSD Core Team 选择 SMPng 路线与 Dillon 选择 LWKT 路线各自是治理结构的政治产物，“浪费”的判定以“单一最优路径”为前提，但第 8 条已指出 SMPng 与 LWKT 在本体论上地位相等，“单一最优路径”前提本身不成立。fork 争议的真正问题不是“道德”而是“利益分配”——有限的开发者注意力、有限的 commit 权限、有限的项目治理席位如何在 BSD 阵营内分配，这才是 fork 争议的实质。

**许可证角度的补足**。FreeBSD 与 DragonFly 均使用 BSD 许可证，BSD 许可证允许 fork 是 fork 的法律前提但非道德判定标准。BSD 许可证的“允许 fork”是中性的法律框架——它既允许 Dillon fork 出 DragonFly，也允许任何其他开发者 fork 出新项目；它既不“鼓励”fork 也不“禁止”fork，只是让 fork 成为法律上可能的选择。第 13 条指出法律是利益分配的形式主义产物——BSD 许可证允许 fork 的法律设计本身反映 BSD 阵营对“代码自由”高于“项目统一”的价值排序，这一价值排序是历史形成的利益分配共识。批评方以“分裂”道德语言批评 fork 时，实际上是在质疑 BSD 许可证允许 fork 的价值排序——但这一价值排序是 BSD 阵营的根本共识，质疑它等于质疑 BSD 许可证哲学本身。DragonFly fork 后仍使用 BSD 许可证、2003-2007 年间仍从 FreeBSD 回移代码、仍与 FreeBSD 共享部分用户态工具，证明 fork 在许可证层面是“自由行使”而非“许可证冲突”——这与 GPL 阵营的 fork 争议（如 Linux 发行版分裂）有本质不同。

**总纲第 19 条——解释学循环是历史认识的根本条件**。前理解的差异使分歧不可避免。权力与知识在历史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使。DragonFly fork 争议的史料层呈现三重解释学循环与权力共谋。其一，前理解的差异——Dillon 的 Amiga 操作系统背景（OSNews 2003.7.17 报道下评论 32 转引 Slashdot 评论"Matt Dillon's early background as an Amiga programmer is really showing through here. He's basically proposing doing a piecewise conversion of BSD to an Amiga-style message-passing operating system"）让 Dillon 倾向消息传递架构，Core Team 的传统 UNIX 与学术背景让 SMPng 细粒度锁路径自然成立。前理解差异使 SMP 设计分歧不可避免——Dillon 与 Core Team 在 fork 前的争议不是“谁对谁错”的判定问题，而是“从不同前理解出发得出不同结论”的解释学循环问题。其二，权力与知识共谋——DragonFly 官方 history 页面（**dragonflybsd.org/history/**）将“the logical continuation of the FreeBSD 4.x series”表述归入 fork 公告原文（“as quoted in the announcement”），但经公告原文逐句核验（**lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html**），公告中并无此句，公告原文表述是“take over development of the 4.x tree”。“logical continuation”表述实际源自 OSNews 2003.7.17 报道开篇（"DragonFly is an operating system and environment designed to be the logical continuation of the FreeBSD-4.x OS series"）或 DragonFly 网站早期 Goals 页面，后被官方 history 页面误记为出自公告——这是“什么被记录”的权力行使，官方历史页面通过错误引用建构了 fork 的“合法性叙事”。其三，“什么被遗忘”的权力行使——Core Team 选择“沉默处理”而非公开辩论（freebsd-current 2003-July 存档 thread 视图核验，thread 中仅 committer 群体跟帖，无 Core Team 成员发言），Dillon commit bit 撤销的具体过程 FreeBSD 官方从未公开说明（freebsd.duckdb 显示 Dillon 在 freebsd-src 末次 commit `2003-01-28T18:44:40Z`，此后 5.5 个月无贡献），Core Team 内部决议记录（若存在）未公开。“沉默”与“未公开”是“什么被遗忘”的权力行使——史家面对的 fork 史料是不对称的，Dillon 一方的公告、邮件、commit log 较完整，Core Team 一方的内部决议记录缺失，这一不对称本身就是权力行使的结果。史家书写 fork 史时须自反地承认这一史料不对称，不得以 Dillon 一方叙事为“客观真相”，亦不得以 Core Team 的“沉默”为“默认同意 fork”。

**总纲第 21 条——革命与改革是历史方法论的分歧**。Linux 靠革命，BSD 靠改革。改革的困难远高于革命。破山中贼易，破心中贼难。DragonFly fork 争议在第 21 条审视下呈现革命与改革方法论的张力。其一，fork 作为革命选择——Dillon 选择 fork 而非在 FreeBSD 内部推进 LWKT，本质上是选择“革命”而非“改革”。fork 是从 FreeBSD 4.x 分裂出去另起炉灶，而非在 FreeBSD 5.x 框架内渐进改造。Dillon 在 fork 公告中表述"I considered starting with a 5.x base but it is simply too heavily mutexed, it was actually faster to start with 4.x and move forward rather then to start with 5.x and move backwards"——这一表述证明 Dillon 评估了“在 5.x 框架内改革”的路径并否定了它，选择“从 4.x 重新革命”的路径。其二，改革的困难远高于革命——Dillon 在 FreeBSD 内部推进消息传递架构的尝试（freebsd.duckdb 显示 Dillon 在 freebsd-src 末次 commit `2003-01-28T18:44:40Z` 后的 5.5 个月无贡献）因 Core Team 的 SMPng 路线已定而无法成功，这正是“改革的困难”。fork 成为唯一出路，是因为在既有项目内部推进根本性架构变革（从锁路径转向消息传递路径）的成本高于另起炉灶——这一判断在 Dillon 的工程评估中成立，但 Core Team 可能持有不同判断（SMPng 路线已投入大量工程资源，转向 LWKT 等于放弃既有投入），双方判断的差异正是第 19 条前理解差异的体现。其三，BSD 靠改革的悖论——BSD 历史上的 fork（386BSD→FreeBSD/NetBSD、NetBSD→OpenBSD、FreeBSD→DragonFly）表面上看是“革命”，但每次 fork 后都迅速进入“改革”模式。DragonFly fork 后仍从 FreeBSD 4.x 继承大量代码（freebsd.duckdb 显示 fork 时 `984263bcb83a` commit message“Initial import from FreeBSD RELENG_4”），2003-2007 年间仍回移 FreeBSD 改动，至 2007 年 HAMMER 首引（commit `8750964d1997`）后回移停止——证明 fork 不是纯粹的革命而是“革命 + 改革”的复合。其四，破山中贼易，破心中贼难——Dillon 在 fork 公告中表述的“too heavily mutexed”工程判断是“山中贼”（具体的技术路线分歧），fork 解决了“山中贼”（SMPng vs LWKT 的技术分歧通过分离各自实现）。但 fork 后的真正困难是“心中贼”——DragonFly 社区需在 Dillon 个人主导下建立独立技术身份（Dillon 后期放弃“logical continuation of the FreeBSD 4.x series”定位，DragonFly 官方 history 页面标注“this description has long since become obsolete”，反映“心中贼”的逐步破除），FreeBSD 社区需面对 fork 后的“分裂”叙事（Core Team 的“沉默”是“心中贼”的呈现——不公开回应让“分裂”叙事由 committer 群体与技术媒体建构），BSD 阵营需在多元路径中维持整体认同（这一认同从未真正建立，BSD 阵营始终是“分离聚合律”下的多元主体并存而非统一阵营）。fork 解决了“山中贼”但“心中贼”始终未被解决——这是第 21 条对 fork 争议最深刻的审视。

**合图之下**。第 13、19、21 条的审视与 241.3 节第 5、6、8 条的审视形成互补而非重复。第 5 条指出 fork 的偶然性，第 13 条补足 fork 批评的利益分配本质；第 6 条指出 fork 是和解的失败，第 19 条补足 fork 史料的权力共谋；第 8 条指出 SMPng 与 LWKT 在本体论上平等，第 21 条补足 fork 作为革命选择的方法论意义。三条总纲交汇之处，DragonFly fork 争议呈现为：一起以道德语言呈现但本质是利益分配的社区治理事件（第 13 条），其史料记录与遗忘本身是权力行使（第 19 条），其发生是革命方法论选择但 fork 后仍需面对改革的困难（第 21 条）。这一审视不否定 241.3 节的合图——争议的不可调和性仍被承认——但补足了不可调和性的深层结构：利益分配的不对称（有限的开发者资源在 BSD 阵营内的分配争议）、史料权力的不对称（Dillon 一方叙事较完整而 Core Team 一方内部记录缺失）、革命与改革的不对称（fork 解决了技术分歧但未解决社区认同）。史家呈现这一深层结构，即是对 DragonFly fork 史作为“各方主体性的呈现与和解之书”的诚实书写。
