## 229.2.2 总纲第 8 条映射——DRM 切换中的本体论平等审视

**要点**：项目史观总纲第 8 条“本体论上各方平等”为审视 DragonFly DRM 切换提供了去中心化视角。dragonfly.duckdb 显示 2014-2017 年间 DragonFly、FreeBSD、Linux 三方在 DRM 子系统上的关系不是“先进-落后”的等级关系，而是各自独立演化的本体论平等主体：DragonFly 的 DRM 移植（Tigeot 1346 条 commit）是 DragonFly 主体性的显现，FreeBSD 维持自有 DRM 栈（sys/dev/drm2/ 目录）是其主体性的显现，Linux 上游 DRM 演化是 Linux 主体性的显现。DRM 切换不是 DragonFly 向 Linux“臣服”，而是 DragonFly 在自身约束下选择与 Linux DRM 主体性进行代码层面的协作。本体论平等审视避免将 DRM 切换叙述为“Linux 同化 DragonFly”的等级叙事，还原为三方主体性在代码层面的对等交往。

## 229.2.3 总纲第 11 条与第 19 条映射——DRM 作为商品形式主义与解释学循环

**要点**：项目史观总纲第 11 条“商品是形式主义”与第 19 条“解释学循环是历史认识的根本条件”为审视 DragonFly DRM 切换提供了双重透镜。形式主义层面：DRM 作为 GPU 驱动抽象层，其代码在 DragonFly、FreeBSD、Linux 三方间流动时被“形式主义化”——同一份 Linux DRM 代码在 DragonFly 中被重组为 DragonFly 内核子系统的一部分，其“商品形式”（可移植的 GPU 驱动代码）被剥离原有 Linux 内核语境而保留其功能形式。dragonfly.duckdb 显示 Tigeot 的 1346 条 DRM 移植 commit 多为“形式适配”——将 Linux DRM 代码的 API 调用、数据结构、锁机制改造为 DragonFly 内核的对应形式，此即“商品形式主义”在代码层面的显现。解释学循环层面：DRM 切换的历史认识须置于“DragonFly 视角—Linux 视角—FreeBSD 视角—第三方观察者视角”的解释学循环中——dragonfly.duckdb 数据是 DragonFly 视角的客观记录，Linux git log 是 Linux 视角的客观记录，FreeBSD 邮件列表是 FreeBSD 视角的客观记录，三方视角的循环对话构成 DRM 切换史的完整认识。解释学循环审视避免将任何单一视角（如 DragonFly 自述“工程必然”或 Linux 中心叙事“Linux 主导”）绝对化为“客观真相”。
