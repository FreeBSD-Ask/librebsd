# 247.1.5 要点BSD阵营sendmail策略分化为四条路径NetBSD早期152000引入

**要点**：BSD 阵营 sendmail 策略分化为四条路径——NetBSD 早期（1.5/2000）引入 Postfix 并行，2.0（2004）设为默认，4.0（2007）完全移除 sendmail，是 “先并行后移除” 的渐进路径；OpenBSD 2014 下半年直接移除 sendmail（5.7/2015.5 发行说明确认），是 “激进移除” 路径；DragonFly 2015.3 自研 DMA 替代，是 “自研替代” 路径；FreeBSD 至 2022 年仍保留 sendmail 为默认 MTA，但 2014 年起在 base 中保留 DMA 副本（通过 `WITH_DMAGENT` src.conf 选项启用）作为可选组件，2022.1.27 Ed Maste 在 freebsd-hackers 征求 DMA 作为最小 base MTA 的反馈，是 “保守观察” 路径；四条路径反映了各项目对 “base 应包含什么” 的不同回答。四 BSD sendmail 策略对照如下：

    | 项目 | 策略类型 | 关键节点 | 治理模式 |
    |---|---|---|---|
    | NetBSD | 先并行后移除 | 1.5（2000.12）→ 2.0（2004.12）→ 4.0（2007.12） | Foundation 治理 |
    | OpenBSD | 激进移除 | 5.7（2015.5）发行说明确认 | de Raadt 主导 |
    | DragonFly | 自研替代 | DMA（2015.3）替换 sendmail | Dillon 个人主导 |
    | FreeBSD | 保守观察 | 2014 起 base 含 DMA 副本，2022 仍保留 sendmail 默认 | Core Team + Foundation |
**史料**：NetBSD 1.5/2.0/4.0 release notes；OpenBSD 5.6/5.7 release notes；DragonFly BSD Digest 2015.3.9 评论；FreeBSD src.conf `WITH_DMAGENT` 选项文档；Ed Maste 2022.1.27 freebsd-hackers 邮件；John Baldwin（约翰·鲍德温） 2022.1.27 回复邮件（确认 DMA 在 cron/periodic 邮件场景可用） ［A］

**史观**：技术路线分化：BSD 四个项目在 sendmail 上的四种策略是技术路线分化的极致体现，每种策略都有其合理性；社区治理：策略差异背后的治理差异——DragonFly 个人主导可快速决策自研、NetBSD Foundation 治理可渐进替换、OpenBSD de Raadt 主导可激进移除、FreeBSD Core Team + Foundation 治理倾向于保守保留以兼容既有部署

**辨析**：FreeBSD 2014 起 base 中含 DMA 副本但未默认启用，需明确区分 “在 base 中可用” 与 “默认 MTA” 两个状态；OpenBSD 移除 sendmail 的精确版本（5.6 vs 5.7）需进一步考据 release notes 原文；NetBSD 在 2000-2007 年间同时维护两套 MTA 的资源成本需量化考据
