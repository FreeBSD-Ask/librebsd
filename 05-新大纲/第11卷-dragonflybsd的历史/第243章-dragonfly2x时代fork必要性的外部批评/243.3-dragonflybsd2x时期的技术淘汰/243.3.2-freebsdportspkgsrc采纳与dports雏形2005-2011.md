# 243.3.2 FreeBSD Ports → pkgsrc 采纳与 DPorts 雏形（2005-2011）

**要点**：DragonFly fork 自 FreeBSD 4.x 初期仍共享 FreeBSD Ports tree，但随代码差异扩大，ports tree 同步成本上升；2005 年 DragonFly 决定采纳 NetBSD 的 pkgsrc 作为补充软件包管理路径，与 FreeBSD ports 并行存在；pkgsrc 提供跨 BSD 通用软件包管理，但与 FreeBSD ports 不完全兼容，导致 DragonFly 用户面临双软件包管理系统的复杂性；2.10（2011）引入 DPorts 雏形——基于 pkgsrc 与 FreeBSD ports 的混合方案，为后续 DPorts 完整化奠定基础；这一时期的软件包管理演化“淘汰”了 DragonFly 对 FreeBSD ports 直接同步的依赖

**史料**：DragonFly 2005 年 pkgsrc 采纳公告；DragonFly 2.10 release notes DPorts 部分；DragonFly 邮件列表 pkgsrc/DPorts 讨论 ［A］

**史观**：总纲第 4 条——分离与聚合：DragonFly 软件包管理从 FreeBSD ports 转向 pkgsrc/DPorts 是分离聚合律的体现——技术分离推动软件包管理系统独立；总纲第 17 条——软件工程：软件包管理演化反映“先共享 → 后独立”的工程路径

**辨析**：pkgsrc 采纳的精确日期需考据——2005 年是 DragonFly 官方文档记载，但实际 commit 可能更早；DPorts 雏形与正式版的边界需考据——2.10 仅是雏形，正式 DPorts 在后续版本完善；pkgsrc 与 FreeBSD ports 在 DragonFly 中的并行持续时间需结合 commit log 核验
