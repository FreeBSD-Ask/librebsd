# 243.1.1 Linux 社区的质疑

**要点**：Linux 内核社区对 DragonFly fork 的必要性提出质疑，认为 FreeBSD 4.x 与 5.x 的差异不足以支持 fork，Dillon 的离开是“个人野心”而非技术必要

**史料**：LKML（Linux Kernel Mailing List）中关于 DragonFly fork 的讨论（**<https://lkml.org/**，2003-07> 至 2004-12 年间 DragonFly 相关 thread）；Linux 内核开发者个人博客/评论；OSNews 等技术媒体的报道（OSNews 2003 年 DragonFly fork 报道，含评论 21 “自我中心”、评论 24 “fork 带来正向回报”）；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `d:\librebsd\03-原始史料库\01-代码仓库史料\01-数据库本体\`，含 fork 首 commit `984263bcb83a` 2003-06-17、LWKT 首引 commit `8ad65e080342` 2003-06-20）；DragonFly BSD 邮件列表存档（**<https://www.dragonflybsd.org/mailinglists/**，kernel@/users@> 2003-2004 年间 Linux 社区质疑的回应讨论）；DragonFly BSD Release Notes（**<https://www.dragonflybsd.org/releases/**）；Dillon> fork 公告（**<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html**，“too> heavily mutexed” 表述）；HAMMER 设计 PDF（**<https://www.dragonflybsd.org/hammer/hammer.pdf**，Dillon> 2008 完整设计文档）[三角验证：dragonfly.duckdb 代码层 + 邮件列表言论层 + Release Notes 官方层 + LKML/OSNews 第三方观察层四类来源互参] ［C］

**史观**：总纲第 10 条——边缘者贡献：Dillon 在 Linux 社区眼中是“边缘者”，但其 fork 决策本身是 BSD 哲学的一次独立实践

**辨析**：Linux 社区的质疑需考据背景——Linux 与 BSD 哲学不同，Linux 社区对 fork 的容忍度本就较低，批评可能带有阵营偏见；具体争议点：1) OSNews 2003 年评论 21 “自我中心”、评论 24 “fork 带来正向回报” 属第三方观察者言论，须以 LKML 与 dragonfly.duckdb 核验其事实基础——dragonfly.duckdb 显示 LWKT 首引 commit 距 fork 首 commit 仅 2 天 19 小时 36 分钟，反映 Dillon 在 fork 前已完成 LWKT 设计，“个人野心” 判定须警惕目的论叙事；2) Linux 社区 “fork 容忍度低” 的判断本身属群体特征概括，须以 LKML 中具体 thread 的逐条核验为据，避免群体刻板印象 [存疑脚注：LKML 中关于 DragonFly fork 的具体 thread URL 须以 lkml.org 站内检索核验，部分早期 LKML 存档可能元数据丢失]。0 信任原则应用维度：author 字段可伪造（dragonfly.duckdb author_email 须与 committer 字段交叉验证）、OSNews 评论匿名可伪造（须与 LKML 实名讨论交叉印证）、关键词匹配局限（“DragonFly” 关键词可能匹配 Linux DRM 驱动 DragonFly 相关 commit 而非 BSD 项目）。考据留痕至 `d:\librebsd\03-原始史料库\06-考据记录\20260730_jianyi缺口补全考据.md` 8x 节
