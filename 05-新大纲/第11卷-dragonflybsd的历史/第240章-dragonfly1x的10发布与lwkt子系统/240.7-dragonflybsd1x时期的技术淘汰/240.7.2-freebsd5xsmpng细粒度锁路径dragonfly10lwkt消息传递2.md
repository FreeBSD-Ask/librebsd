# 240.7.2 FreeBSD 5.x SMPng 细粒度锁路径 → DragonFly 1.0 LWKT 消息传递（2003-2004）

**要点**：FreeBSD 5.x（5.0 于 2003.1 发布）选择 SMPng（SMP Next Generation）细粒度锁路径改造内核，让多核并行进入内核；Dillon 认为 SMPng 的锁路径 “过于复杂、脆弱、维护困难”，主张以消息传递与轻量级内核线程替代；**DragonFly 1.0**（**2004.7.12** 发布）即包含 LWKT（Light Weight Kernel Threading）子系统、IPI（Inter-Processor Interrupt）消息传递机制、每 CPU 独立线程队列；1.0 发布公告明确称：
    > replaced nearly all of the core threading, process, interrupt, and network infrastructure
    并将 “开始移除 BGL（Big Giant Lock）” 列为下一阶段目标；同期 FreeBSD 5.x 继续推进 SMPng 路径，二者在 SMP 设计上根本分化。DragonFly 1.x 版本发布时间线如下：
    | 版本 | 发布日期 | 关键特性 |
    |---|---|---|
    | 1.0 | **2004.7.12** | LWKT、token 雏形、FreeBSD 4.x 兼容性 |
    | 1.0A | **2004.7.14** | 快速修正版 |
    | 1.2 | 2005-04-08 | 基础发布（HAMMER 雏形实为 1.12/2008-02-26 实验性引入） |
    | 1.4 | 2006.8 | SMP 性能改进、LWKT 调度器优化 |
    | 1.6 | 2007.2 | 基于 LWKT 的每 CPU 网络栈线程 |
    | 1.8 | 2007.11 | 基于 LWKT 的 VFS 操作消息传递 |
    | 1.10 | **2007.8.6** | token 机制替代 mutex |
    | 1.12 | 2008.4 | token 优化、多核性能改进 |
**史料**：DragonFly 1.0 RELEASED 公告（**lists.dragonflybsd.org/pipermail/kernel/2004-July/212809.html**，Dillon 2004.7.12）；DragonFly 1.0A 公告（**lists.dragonflybsd.org/pipermail/kernel/2004-July/212852.html**，2004.7.14，快速修正版）；DragonFly 1.0 release notes；SMPng 设计文档；LWKT 设计文档（dragonflybsd.org/goals/threads.cgi）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］〔L3 官方文档与公告〕

**史观**：技术路线分化：SMPng 与 LWKT 的根本分歧反映 FreeBSD 与 DragonFly 的技术路线分化，是 BSD 阵营技术路线分化的典型；总纲第 17 条——软件工程：LWKT 是软件工程中 “消息传递 vs 锁” 哲学分歧的具体实现

**辨析**：DragonFly 1.0 的精确发布日期在不同来源中存在差异——本卷 50.1.2 节原稿沿用 ~~2005.3~~ 说法，经 WebFetch `https://www.dragonflybsd.org/releases/` 一手核证与 Dillon 2004.7.12 kernel@ 邮件公告交叉验证，已修正为 **2004.7.12**（1.0A 为 **2004.7.14**）；~~2005.3~~ 系部分二手来源的误传；1.0 公告中 “replaced nearly all” 的表述为 Dillon 自我陈述，需对照 commit log 核验实际替换范围；1.0 仍依赖 FreeBSD ports tree 与 4.x pthreads 模型，并非完全替换
