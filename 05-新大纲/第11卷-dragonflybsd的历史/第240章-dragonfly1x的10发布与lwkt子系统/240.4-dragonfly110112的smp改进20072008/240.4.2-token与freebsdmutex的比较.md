# 240.4.2 token 与 FreeBSD mutex 的比较

**要点**：FreeBSD mutex 是传统自旋锁/睡眠锁，持有时不可抢占；DragonFly token 是 LWKT 框架下的轻量级同步原语，持有时可被抢占；token 让 DragonFly 在多核扩展性上优于 mutex，但学习曲线较陡

**史料**：FreeBSD mutex 设计文档（FreeBSD kernel mutex(9) 手册页、Baldwin SMPng 实现文档）；DragonFly token 设计文档（Dillon token 设计文档、DragonFly 源码 `sys/sys/lwkt_token.h`）；FreeBSD 与 DragonFly 同步机制对比；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `d:\librebsd\03-原始史料库\01-代码仓库史料\01-数据库本体\`，含 token 机制 1.10 引入 2007.8.6、sys/sys/lwkt_token.h 路径 commit 演化）；DragonFly BSD 邮件列表存档（**<https://www.dragonflybsd.org/mailinglists/**，kernel@> 关于 token vs mutex 的讨论）；DragonFly BSD Release Notes（**<https://www.dragonflybsd.org/releases/**，1.10> Release Notes token 部分）；Dillon fork 公告（**<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html**）；HAMMER> 设计 PDF（**<https://www.dragonflybsd.org/hammer/hammer.pdf**）[三角验证：dragonfly.duckdb> + 邮件列表 + Release Notes] ［A］

**史观**：技术路线分化：mutex 与 token 的根本分歧反映 FreeBSD 与 DragonFly 的技术路线分化

**辨析**：mutex 与 token 的性能对比在不同基准测试中差异较大——需对照同硬件同负载核验；token 的实际采用难度需考据
