# 240.2.2 LWKT 与 FreeBSD 5.x SMPng 的比较

**要点**：SMPng（FreeBSD 5.x）采用细粒度锁改造内核，让多核并行进入内核；LWKT（DragonFly）采用消息传递与每 CPU 独立调度，避免锁竞争；两种路径在 SMP 性能上各有优势——SMPng 适配现有代码，LWKT 适配重新设计

**史料**：SMPng 设计文档（Baldwin 2002 FreeBSD SMPng 实现文档）；LWKT 设计文档（dragonflybsd.org/goals/threads.cgi）；FreeBSD 与 DragonFly SMP 性能对比基准测试；dragonfly.duckdb dragonfly-src 仓库 commits 表与 commit_files 表（路径 `d:\librebsd\03-原始史料库\01-代码仓库史料\01-数据库本体\`，含 LWKT 首引 commit `8ad65e080342` 2003-06-20、sys/kern/lwkt_thread.c 与 sys/sys/lwkt_token.h 路径 commit 演化）；DragonFly BSD 邮件列表存档（**<https://www.dragonflybsd.org/mailinglists/>**，kernel@ 关于 LWKT vs SMPng 的讨论）；DragonFly BSD Release Notes（**<https://www.dragonflybsd.org/releases/>**）；Dillon fork 公告（**<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>**，“too heavily mutexed” 表述）；HAMMER 设计 PDF（**<https://www.dragonflybsd.org/hammer/hammer.pdf>**）[三角验证：dragonfly.duckdb 代码层 + 邮件列表言论层 + Release Notes 官方层] ［A］

**史观**：总纲第 21 条——革命与改革是历史方法论的分歧：SMPng 对既有内核的保守锁改造与 LWKT 的重新设计，反映 FreeBSD 与 DragonFly 在多核演进方法论上“改良与革命”的路线分歧

**辨析**：两种路径的性能对比缺乏权威基准——需对照同硬件同负载核验；SMPng 的实际复杂度需考据
