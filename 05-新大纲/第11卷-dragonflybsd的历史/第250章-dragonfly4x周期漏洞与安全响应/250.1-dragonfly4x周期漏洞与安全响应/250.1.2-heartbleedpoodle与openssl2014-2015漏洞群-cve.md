# 250.1.2 Heartbleed、POODLE 与 OpenSSL 2014-2015 漏洞群——CVE-2014-0160/CVE-2014-3566/CVE-2015-0204/0209/1788（2014-2016）

**要点**：DragonFly 4.x 周期最重大的两起漏洞为 Heartbleed 与 POODLE——**CVE-2014-0160** Heartbleed（OpenSSL TLS heartbeat 远程内存泄露，2014-04-07 commit `8b433ce356b93ab0860f82b85543ae8895f55cab` 修复，攻击者可远程读取服务器进程内存最多 64KB/次，影响所有使用 OpenSSL 1.0.1-1.0.1f 的系统）、**CVE-2014-3566** POODLE（SSL 3.0 协议降级攻击，2014-10-22 commit `1dbe5f1bdb7c65581b1d147ea402abf784851d18` 修复，与 CVE-2014-3513/3567/3568 同一 commit，攻击者可借降级至 SSL 3.0 解密 TLS 会话）。OpenSSL 漏洞群按修复 commit 聚合如下：

**史料**：**dragonfly.duckdb** dragonfly-src 仓库 commit `8b433ce356b93ab0860f82b85543ae8895f55cab`（2014-04-07 CVE-2014-0160 Heartbleed）、commit `1dbe5f1bdb7c65581b1d147ea402abf784851d18`（2014-10-22 CVE-2014-3566 POODLE）、commit `4bb195ec3a948415fae3237631f3bbc3d17cd2c9`（2014-06-06 CVE-2014-0195/0221/0224/3470）、commit `4b6818e855c236add2f0d7f640cba95af9f302e8`（2015-01-15 CVE-2014-3569/3570/3571/3572/8275、CVE-2015-0204/0205/0206）、commit `9eaaad393e25112c87cecd9ae1ad7faf1adb5480`（2015-03-19 CVE-2015-0209/0286/0287/0288/0289/0293）、commit `25952ef9630b0828388a6b4180dc54899e136622`（2015-06-11 CVE-2015-1788/1789/1790/1791/1792）；NVD CVE-2014-0160、CVE-2014-3566 条目 ［A］

**史观**：专题语（不设条号）：DragonFly 4.x 周期对 Heartbleed 与 POODLE 的响应延续了“跟进上游 OpenSSL”策略——与 OpenBSD 5.6 周期 Heartbleed 后 fork LibreSSL 的“自维护”策略形成路线对照；DragonFly 选择继续依赖 OpenSSL 上游版本升级（而非 fork），这一选择的政治含义是“信任上游社区审计能力”优于“自建独立维护能力”，但对 small-team 项目而言这一选择的代价是持续的安全响应压力（原挂“总纲第 7 条——技术选择即政治选择”，基线第 7 条为“理论必须自反”，主题对不上基线，按 R2140 先例改不设条号专题语——2026-09-12 整改）

**辨析**：Heartbleed（CVE-2014-0160）是 OpenSSL 历史上最严重的漏洞之一——TLS heartbeat 扩展实现缺陷让攻击者可远程读取服务器进程内存（含私钥、会话令牌等敏感数据），影响全球约 17% 的 HTTPS 服务器；DragonFly 在披露同日（2014-04-07）即由 commit `8b433ce356b93ab0860f82b85543ae8895f55cab` 修复，响应速度与 FreeBSD、OpenBSD 同步；POODLE（CVE-2014-3566）不是 OpenSSL 实现缺陷而是 SSL 3.0 协议设计缺陷——修复方式为禁用 SSL 3.0 或禁用 CBC 模式套件，影响所有支持 SSL 3.0 的系统 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
