# 235.3.6 Dillon 对 Core Team 回应的再回应层

**要点**：Dillon 对 Core Team 的“沉默”与 committer 群体的质疑作出多层次的再回应。在 fork 之前，Dillon 已在 freebsd-arch 邮件列表就 SMPng 细粒度锁路线与 FreeBSD 架构社区展开技术论证（2002 至 2003 年初），这一“预先回应”层是后续 fork 公告中“it is simply too heavily mutexed”工程判断的公开论证基础。fork 之后，再回应分四个层次展开：第一层是 fork 公告本身——Dillon 在公告中预先回应了“5.x 路线”的技术批评，明确表述“it is simply too heavily mutexed”，将 fork 定位为技术路线分歧而非个人恩怨；第二层是 ONLamp 2004 采访——Dillon 进一步阐述 LWKT 消息传递架构优于 SMPng 细粒度锁的设计理念，以技术论证回应 committer 群体对 fork 必要性的质疑；第三层是 dragonfly.kernel 邮件列表 2003 至 2006 年间的持续发言——Dillon 多次提及撤权程序不透明，对 Core Team 的“沉默处理”表达长期不满；第四层是持续技术输出——dragonfly.duckdb 显示 Dillon 在 dragonfly-src 仓库 2003 至 2008 年间 4222 条 commit（LWKT、HAMMER、vkernel 等核心子系统由 Dillon 一人首引），以代码成果证明 fork 路线的可行性，这是对 Core Team“沉默”最实质的再回应
