- 总纲 10“动手者创造历史”——项目史观总纲第 14 章 14.2 节原文“真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者”。Sherrill 以 release engineer 的工程实践将 Dillon 的 HAMMER2 工程产出形式化为可发布的 release tag，dragonfly.duckdb tags 表显示 v5.0.0 至 v6.0.0 系列 tag 均由 Sherrill 创建（tagger=Justin C. Sherrill（tags 表无 tagger_email 列，原邮箱引注删除）），是其持续动手实践的量化证据。须区分项目统摄史观主张与项目统摄史观批评的对象：项目统摄史观批评的是“旁观评论者”以理论框架替代动手实践，而主张历史由动手做事的老实人创造——release engineering 作为经验性实践，与代码贡献在本体论上地位相等。
- 总纲 5“没有必然性，只有偶然性”——项目史观总纲第 25 章原文“每一个关键人物、每一次 fork、每一个技术决定，都是不可替代的偶然”。5.x 时期 5-15 个月的开发周期反映 DragonFly 的工程节奏，v5.8.0 至 v6.0.0 的 15 个月周期可能与 2020-2021 年 COVID-19 疫情对开发节奏的影响有关——疫情作为偶然事件，塑造了 release 节奏。须区分项目统摄史观主张与项目统摄史观批评的对象：项目统摄史观批评的是“将 release 节奏归结为必然规律”的目的论叙事，而主张偶然性是历史的根本结构——15 个月周期并非工程失败，而是偶然性在工程实践中的呈现。
- 总纲 20“历史地理塑造思想土壤”——项目史观总纲第 25 章原文“土地与自由的养分、农耕文明与工商业文明、中心与边缘，皆是形式主义的空间呈现”。DragonFly BSD Digest 作为社区博客，构成了 DragonFly BSD 项目的“思想土壤”：博客持续记录社区动态，塑造了项目的文化地理。须注意项目统摄史观批评的对象是“将地理视为决定性因素”的地理决定论，而主张地理是形式主义的空间呈现之一——COVID-19 疫情作为全球性事件，重塑了开发者协作的“历史地理”，远程协作的“边缘”与官方组织的“中心”在本体论上地位相等，共同构成 DragonFly 5.x 时期的思想土壤。

加缪认为生活越没有意义越值得过。那么生活有没有意义？这一存在主义命题在历史哲学中意味着：历史本身没有意义，但正因为没有意义，历史才值得被书写。意义不是预设的，而是在无意义的荒谬中被主体创造的。BSD 的历史没有宏大的意义——它不会改变世界，不会推翻 Linux，不会拯救人类。但正因为如此，它才值得被忠实地记录。

**要点**：

- pfSense 的定位与起源：全功能防火墙发行版，面向中大型企业，具备 m0n0wall 所缺的负载均衡、监控等功能——功能缺口正是当初 fork m0n0wall 代码的初始动因；据当事人所知是继 m0n0wall 之后第二个以 PHP 实现的 FreeBSD 系完整防火墙发行版；当事人认为足以替代多数市售商业防火墙，大量 ISP 在用，其本人已部署约 25 处，并有巴西一家医院在 155Mb 管道上跑到约七至七成五利用率、正准备以 CARP 增设负载均衡的实例。（BSDTalk EP39，[88.12-247.36]，L1）
- 名称渊源与技术取舍：pfSense 得名于所用的 OpenBSD 包过滤器 PF，同时采用 OpenBSD 的 CARP 与 pfsync，并计划很快集成 OpenBGPD 与 OpenOSPFD；但基底仍是 FreeBSD——当事人十年深度使用 FreeBSD 形成的熟练度是主要因素，技术上并非不能移植到 OpenBSD，只是部分组件依赖 FreeBSD 专属守护进程、移植工作量可观；团队正在等待 FreeBSD 6.1：多数所需特性 6.0 已备，唯无线支持欠佳，无线开发者 Sam 的系列提交令 6.1 的无线明显改善。（BSDTalk EP39，[125.12-202.68]，L1）
- 两种安装模式与 BSD installer 的设计哲学：完整安装走 BSD installer，嵌入式版面向 CompactFlash——用 DD 或 Windows 的 physdiskwrite 把镜像写入介质、重启即得完整 pfSense，嵌入式安装方式承自 m0n0wall；BSD installer 虽同用 curses 文本框架，却摒弃传统 FreeBSD 安装器令人晕头转向的无限循环菜单，改为顺序步骤、失败即回退上一步，九成情况下全选默认即可安装重启后直接可用。（BSDTalk EP39，[253.36-378.04]，L1）
- BSD installer 的通用化：它完全可用于一般 BSD 发行版，已有多人投入移植——当事人早期做过向 FreeBSD 的首次移植，近期又把 Lua 版 BSD installer 移植到 FreeBSD，并曾列为 Summer of Code 项目；团队拟在 BSDCan 的开发者峰会上推动 FreeBSD 更广泛地采用 BSD installer。（BSDTalk EP39，[347.32-378.04]，L1）
- VPN 互操作与包安装机制：据用户反馈 pfSense 的 IPsec 部分与 Cisco、Nortel 设备互操作良好，与 m0n0wall 天然互通（同用 racoon），OpenBSD 一侧的用户经 isakmpd 亦报告良好，OpenVPN 作为上升期的 SSL VPN 方案同样内置，而旧式 PPTP 虽被当事人视为希望消失的遗留协议、却因用户反对而保留；包安装器则叠在 FreeBSD packages 之上、以若干 XML 文件包装，可将 XML 在运行中动态变换为 PHP GUI，GUI 呈现乃至包数据保存全部自动完成，包作者几乎无须编写 PHP，只须挂接钩子、从配置文件取数据并生成配置文件，用户全程无须接触命令行。（BSDTalk EP39，[378.04-486.32]，L1）

**史料**：

- 当事人入坑与两个项目的交汇：约十年前其工作地点需要防火墙，当时 Checkpoint 报价约两万美元而作罢；大学时代偏用 Linux 的他架起 Linux 防火墙却频繁内核恐慌，经友人劝说转入 FreeBSD 并从此顺遂；Matthew Dillon fork FreeBSD 时他自然好奇该方向能走多远而加入 DragonFly；恰逢 DragonFly 抛弃自带安装器需要新装器、而 pfSense 也需要一个顺手的安装器，他与 Chris Presley 及几位 DragonFly 开发者便着手编写 BSD installer，pfSense 随之诞生——两个阵营由此交汇。（BSDTalk EP39，[490.8-588.0]，L1）

**辨析**：

- 安装器生态的分岔与惋惜：当事人与 PC-BSD 开发者邮件交流并赞赏其成果——外观精致、发行版优秀，也认同简易安装是引导用户接触操作系统的好方式；但惋惜 PC-BSD 的图形安装未与 BSD installer 结合：BSD installer 的前端系统 DFUI 独立于用户输入、可动态生成表单，同一后端既可驱动 DragonFly BSD 或 pfSense 的网页安装，也可输出 CGI 或 curses 前端，另有尚待打磨的 Qt 前端；两个项目本可共用一个安装器、只需重写 Qt 前端。（BSDTalk EP39，[588.0-676.64]，L1）
- 桌面使用的坦白与 X 的短板：当事人自认会因此挨批——桌面用 Microsoft 产品与 OS X，虽尝试过 Linux 与 FreeBSD 上的 GNOME、KDE、XFCE 且评价不恶，但因职业须支持 Apple 与 Microsoft 产品，桌面停留在 XP 与 OS X 更省事；服务器、防火墙与路由器则全部用 FreeBSD；BSD 桌面的具体短板：三显示器在 X 下难以各按理想原生分辨率配置，为此耗费的时间不如写代码，而 X 剪贴板行为不合标准——关闭应用即丢失剪贴板数据，与 Windows、OS X 乃至 OS 9 的惯例相悖。（BSDTalk EP39，[678.44-772.88]，L1）
