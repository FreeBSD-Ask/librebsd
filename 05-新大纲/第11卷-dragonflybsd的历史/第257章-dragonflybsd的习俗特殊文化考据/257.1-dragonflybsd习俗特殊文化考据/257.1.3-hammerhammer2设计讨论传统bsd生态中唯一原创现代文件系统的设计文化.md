# 257.1.3 HAMMER/HAMMER2 设计讨论传统：BSD 生态中唯一原创现代文件系统的设计文化

**要点**：HAMMER 文件系统 2007-2008 年开发，2008 年 7 月随 DragonFly 2.0 首次发布；HAMMER2 自 2012 年起开发，现为 DragonFly 官方默认文件系统；HAMMER2 特性包括 block copy-on-write、即时恢复、即时快照、可写快照挂载、自动压缩、自动去重、动态基数树、64-bit hardlink 计数器、2^63 逻辑文件大小限制、递归校验码、任意数量伪文件系统卷等；2024 年 DragonFly 6.4 系列引入 HAMMER2 远程挂载实验性支持；HAMMER/HAMMER2 设计讨论长期在 DragonFly BSD 邮件列表进行，Dillon 个人主导设计延续 BSD 单一架构师传统；HAMMER/HAMMER2 是 DragonFly BSD 技术独特性的核心，与 FreeBSD ZFS、OpenBSD FFS2 形成 BSD 文件系统三足鼎立

**史料**：DragonFly BSD HAMMER 页面（<https://www.dragonflybsd.org/hammer/>，访问 2026-07-27，原文"HAMMER2, the successor of HAMMER, is under active development since 2012 and now the official default filesystem for DragonFly"）；DragonFly BSD History 页面（<https://www.dragonflybsd.org/history/>）：HAMMER 2008 年 7 月随 DragonFly 2.0 首次发布；DragonFly BSD 6.4 Release（<https://www.dragonflybsd.org/release64>，访问 2026-07-27）：HAMMER2 远程挂载实验性支持；DragonFly BSD 邮件列表（<https://lists.dragonflybsd.org/>） ［A］

**史观**：总纲第 9 条——经验优先，HAMMER/HAMMER2 设计是 Dillon 工程实践的具体沉淀，每项特性皆源于实际工程需求而非预先设计的理论框架；总纲第 4 条——分离聚合是永恒规律，HAMMER/HAMMER2 从 DragonFly BSD 既有文件系统（UFS）分离，形成 DragonFly BSD 独有的文件系统聚合；总纲第 7 条——理论必须自反，本子节作为 HAMMER/HAMMER2 设计讨论传统的考据叙事，自身亦嵌入“原创即工程善”的前理解，须自觉呈现这一前理解；总纲第 8 条——本体论上各方平等，HAMMER/HAMMER2、FreeBSD ZFS、OpenBSD FFS2 在本体论上地位相等，差异仅是一刻状态的不同；总纲第 22 条——知识注定过时，HAMMER2 自 2012 年开发至今的特性集随技术演进而须重新展开，如 HAMMER2 远程挂载在 2024 年仍为实验性支持

**辨析**：考据过程留痕——【查证来源】DragonFly BSD HAMMER 页面经 dragonflybsd.org/hammer/ 一手核验，确认"HAMMER2, the successor of HAMMER, is under active development since 2012 and now the official default filesystem for DragonFly"表述；DragonFly BSD History 页面经 dragonflybsd.org/history/ 一手核验，HAMMER 2008 年 7 月随 DragonFly 2.0 首次发布；DragonFly BSD 6.4 Release 经 dragonflybsd.org/release64 一手核验；【交叉验证方法】HAMMER/HAMMER2 特性清单须以 dragonflybsd.org/hammer/ 主页面与 DragonFly 邮件列表讨论互证；HAMMER2 远程挂载实验性支持须以 6.4 Release Notes 与邮件列表讨论互证；【0 信任原则·“HAMMER 2007-2008 年开发”】“HAMMER 文件系统 2007-2008 年开发”的具体开发起止时点须以 DragonFly BSD 早期 commit log 核验，本考据以官方 history 页面为间接依据；【0 信任原则·“BSD 生态中唯一原创现代文件系统”】“HAMMER2 是 BSD 生态中唯一原创的现代文件系统”的考据须以 FreeBSD ZFS（移植自 OpenZFS）、OpenBSD FFS2（传统 FFS 扩展）的来源对比核验，本考据以三文件系统的公开文档为依据；【0 信任原则·“BSD 文件系统三足鼎立”】“HAMMER/HAMMER2、FreeBSD ZFS、OpenBSD FFS2 形成 BSD 文件系统三足鼎立”的归纳基于定性判断，实际 BSD 文件系统生态（含 NetBSD FFS、LFS 等）更复杂，本考据以三大 BSD 主线默认文件系统为依据；【与同类 UNIX/BSD 习俗对比】FreeBSD ZFS 移植自 OpenZFS（2010 年代起默认推荐）；OpenBSD FFS2 为传统 FFS 扩展；NetBSD FFS 与 LFS；HAMMER2 是 BSD 生态中唯一原创的现代文件系统；【自反性声明】本子节作为 HAMMER/HAMMER2 设计讨论传统的考据叙事，自身嵌入“原创即工程善”的前理解，实际 HAMMER2 的工程成熟度与生产采用情况（如 DragonFly 6.4 系列之前的稳定性问题）须以多源交叉验证逼近史实
