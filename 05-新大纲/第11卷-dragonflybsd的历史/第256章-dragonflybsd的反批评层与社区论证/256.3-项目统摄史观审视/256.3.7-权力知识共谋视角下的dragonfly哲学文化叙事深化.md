# 256.3.7 权力知识共谋视角下的 DragonFly 哲学文化叙事深化

**要点**：从项目史观总纲第 19 条“解释学循环是历史认识的根本条件”与“权力与知识在历史书写中共谋”审视，DragonFly 哲学文化叙事的权力知识共谋体现在三个层次——其一，命名权的权力行使：Dillon 在 2003 年 fork 时选择“DragonFly BSD”作为项目名称（fork 公告原标题“Annoucning DragonFly BSD!”，原拼写错误保留），这一命名本身是权力行使——以蜻蜓（DragonFly）象征轻盈、敏捷、转向灵活，与 FreeBSD 的“自由”（Free）、NetBSD 的“网络”（Net）、OpenBSD 的“开放”（Open）形成命名哲学的对照；Dillon 通过命名确立了 DragonFly 项目的独立身份，但这一命名权的行使本身是利益分配——Dillon 作为 founder 拥有命名权，其他贡献者（Wildner、Aaron LI、Kusumi 等）虽贡献代码但未参与命名决策；其二，叙事权的权力行使：DragonFly 官方 history 页面（dragonflybsd.org/history/，last edited Thu Jan 17 13:32:06 2019）由 Dillon 主导撰写，其表述"From a performance perspective DragonFly's only real competitor these days is Linux"将 DragonFly 定位为 Linux 的竞争者而非 FreeBSD 的分支——这一表述本身是叙事权力的行使，将 DragonFly 从 BSD 阵营的边缘项目重构为与 Linux 同级的竞争者；DragonFlyBSD Digest 博客（dragonflydigest.com，Justin C. Sherrill（贾斯廷·C·谢里尔） 运营）作为非官方叙事渠道补充了 Dillon 主导的官方叙事，但 Sherrill 作为 Dillon 任命的 release engineer 其叙事亦受 Dillon 影响；其三，遗忘机制的权力行使：DragonFly 哲学文化叙事中被遗忘的部分包括——Dillon 2003 年被 FreeBSD Core Team 撤销 commit 权限的具体经过（dragonflybsd.org 官方 history 仅称“forked from FreeBSD 4.8 in June of 2003 by Matthew Dillon（马修·狄龙）”而未提及权限撤销）、被疏远贡献者（Hsu、Sonnenberger、Pandya、Sepherosa Ziehau、Tigeot）的淡出原因（无公开声明）、DragonFlyBSD Foundation 的注册年份与章程文本（dragonflybsd.org/foundation/ 页面 404）——这些被遗忘的部分本身就是权力行使，Dillon 作为叙事主导者选择性地记录与遗忘；权力知识共谋在 DragonFly 哲学文化叙事中的具体显现是——Dillon 个人主导模式既是治理结构也是叙事结构，治理权力与叙事权力在同一人手中集中，使 DragonFly 哲学文化叙事缺乏多元声音的制衡；本审视自身亦嵌入项目统摄史观的前理解——总纲第 19 条“前理解的差异使分歧不可避免”意味着本审视并非中立旁观，史家的任务是自觉呈现前理解而非消除前理解

**史料**：项目史观总纲第 19 条原文（据原文第 25 章）；Dillon 2003-07-16 fork 公告（lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html，原标题“Annoucning DragonFly BSD!”，原拼写错误保留）；DragonFly BSD 官方 history 页面（dragonflybsd.org/history/，last edited Thu Jan 17 13:32:06 2019，含"From a performance perspective DragonFly's only real competitor these days is Linux"表述）；DragonFly BSD Digest 博客（dragonflydigest.com，Justin C. Sherrill 运营）；dragonflybsd.org/foundation/ 页面 404（截至 2026-07-22）；dragonfly.duckdb dragonfly-src 仓库 contributors 表（被疏远贡献者淡出时点）；FreeBSD Core Team bylaws（freebsd.org/internal/core-team/）［ 查证来源：Dillon fork 公告经 lists.freebsd.org 邮件列表存档核验原标题拼写“Annoucning”为原文；DragonFly 官方 history 页面经 WebFetch 核验含“only real competitor these days is Linux”表述；交叉验证方法：对照 DragonFly 官方 history 页面与 Dillon 邮件列表发言、DragonFlyBSD Digest 博客的非官方叙事、被疏远贡献者的公开回应（如有）；存疑判定依据：被疏远贡献者的淡出原因无公开声明，须以邮件列表存档与个人公开声明交叉验证后方可采信；Dillon 2003 年被 FreeBSD Core Team 撤销 commit 权限的具体经过在 DragonFly 官方 history 中未记载，须以 FreeBSD 邮件列表存档核验 ］

**史观**：总纲第 19 条——解释学循环是历史认识的根本条件：DragonFly 哲学文化叙事的评估受前理解差异制约，Dillon 主导的官方叙事与被疏远贡献者叙事、外部观察者叙事在前理解上难以通约；权力与知识在历史书写中共谋：Dillon 个人主导模式既是治理结构也是叙事结构，治理权力与叙事权力在同一人手中集中，使 DragonFly 哲学文化叙事的“什么被记录、什么被遗忘”本身是权力行使

**辨析**：权力知识共谋审视不意味着否定 DragonFly 官方叙事的真实性——Dillon 主导的官方叙事在工程事实层面（LWKT、HAMMER、HAMMER2、vkernel commit 时间序列、release 节奏、贡献者统计）经 dragonfly.duckdb 核验为真，但叙事的真实性不否定其作为权力行使的性质；【0 信任原则·叙事权力的对称呈现】本节试图呈现 DragonFly 阵营与批评者阵营的叙事对称性，但史料的不对称性（DragonFly 官方叙事相对稀缺、被疏远贡献者叙事更为稀缺）使绝对对称不可能，史家须自觉呈现这一限度；【0 信任原则·“DragonFly 与 Linux 同级竞争者”表述的核验】DragonFly 官方 history 页面“the only real competitor these days is Linux”表述经 WebFetch 核验存在，但这一表述可能反映 DragonFly 对自身定位的自我认知，亦可能是营销性表述，须以 Dillon 邮件列表发言交叉核验其语境与意图；【0 信任原则·命名权作为权力行使的辨析】“Dillon 通过命名确立 DragonFly 项目身份”是事实陈述，但命名权的行使本身不构成道德缺陷——所有 BSD 项目的 founder 都拥有命名权（Torvalds 命名 Linux、de Raadt 命名 OpenBSD），这一权力行使是项目治理的常态而非例外；【0 信任原则·本审视的自反性】本审视自身亦嵌入项目统摄史观的前理解，须自觉呈现这一前理解而非伪装中立——项目统摄史观审视 DragonFly 哲学文化叙事时以“权力知识共谋”为前理解，这一前理解本身可能遮蔽 DragonFly 工程事实的真实性
