# 249.2.1 NetBSD 可移植性的对照

**要点**：netbsd.duckdb 显示 2011-2018 年间 netbsd-src 与 dragonfly-src 仓库 commit 量对照如下：

    | 年份 | netbsd-src | dragonfly-src | netbsd/dragonfly 比例 |
    |---|---|---|---|
    | 2011 | 25959 | 2511 | 10.3 倍 |
    | 2012 | 19358 | 3161 | 6.1 倍 |
    | 2013 | 19460 | 2429 | 8.0 倍 |
    | 2014 | 20949 | 2205 | 9.5 倍 |
    | 2015 | 17365 | 3112 | 5.6 倍 |
    | 2016 | 16600 | 2340 | 7.1 倍 |
    | 2017 | 13101 | 1888 | 6.9 倍 |
    | 2018 | 10959 | 1706 | 6.4 倍 |
    netbsd-src 年均约 17969 条（2026-09-12 整改：原 16669 与表内 8 年逐值合计 143751/8≈17969 不符，按表值重算统一，库侧逐年值复核列 DEFERRED），dragonfly-src 年均约 2419 条——NetBSD 年均 commit 量是 DragonFly 的约 7.4 倍（原 6.9 倍随分母订正）。NetBSD 5.x-7.x 时期（2011-2018）持续推进可移植性，支持数十种硬件架构（arm、mips、powerpc、sparc、vax 等）；DragonFly 则在 2015 年移除 i386 后专注 x86-64 平台的轻量级内核优化，与 NetBSD 的多平台策略形成对照
**史料**：netbsd.duckdb commits 表（netbsd-src 与 dragonfly-src 仓库 2011-2018 年对照）；NetBSD 5.x/6.x/7.x release notes；NetBSD 支持架构列表（**netbsd.org/ports/**）；DragonFly 平台支持说明（**dragonflybsd.org/docs/hardware/**）〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 6 条——技术路线分化：dragonfly.duckdb 数据显示 NetBSD 选择“广度”路线（多架构支持），DragonFly 选择“深度”路线（轻量级内核优化），二者都是 BSD 哲学的不同展开；总纲第 3 条——不存在进步，只有权力再分配：dragonfly.duckdb 数据显示 NetBSD 与 DragonFly 的 commit 量差距（7.4 倍）反映开源项目在资源动员能力上的分化——多架构策略吸引厂商贡献与轻量级策略吸引较少贡献者，是贡献资源流向的再分配而非“先进/落后”（原挂“总纲第 22 条——开源运动”，基线第 22 条为“知识注定过时”，按权威表改挂——2026-09-12 整改）——NetBSD 的多架构策略吸引更多硬件厂商贡献，DragonFly 的轻量级内核策略吸引较少贡献者

**辨析**：dragonfly.duckdb 显示 DragonFly 在 2015 年移除 i386 后专注 x86-64，与 NetBSD 的多架构策略分化加剧——但 DragonFly 仍保留 vkernel 虚拟化支持作为“软件多样性”；NetBSD 支持架构数量须以 netbsd.org/ports/ 核验 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；可移植性与轻量级内核并非完全对立——但 DragonFly 4.x 时期未表现出对多架构的兴趣
