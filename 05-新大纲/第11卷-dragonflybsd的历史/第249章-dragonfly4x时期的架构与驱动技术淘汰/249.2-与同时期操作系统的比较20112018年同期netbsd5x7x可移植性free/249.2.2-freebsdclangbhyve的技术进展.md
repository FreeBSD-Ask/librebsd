# 249.2.2 FreeBSD Clang/bhyve 的技术进展

**要点**：freebsd.duckdb 显示 2011-2018 年间 freebsd-src 与 dragonfly-src 仓库 commit 量对照如下：

    | 年份 | freebsd-src | dragonfly-src | freebsd/dragonfly 比例 |
    |---|---|---|---|
    | 2011 | 10657 | 2511 | 4.2 倍 |
    | 2012 | 14081 | 3161 | 4.5 倍 |
    | 2013 | 12928 | 2429 | 5.3 倍 |
    | 2014 | 15435 | 2205 | 7.0 倍 |
    | 2015 | 15622 | 3112 | 5.0 倍 |
    | 2016 | 17362 | 2340 | 7.4 倍 |
    | 2017 | 16157 | 1888 | 8.6 倍 |
    | 2018 | 14957 | 1706 | 8.8 倍 |
    freebsd-src 年均约 14650 条，dragonfly-src 年均约 2419 条——FreeBSD 年均 commit 量是 DragonFly 的约 6.1 倍。dragonfly.duckdb 显示 FreeBSD 10.0 tagger_date = **2014-01-16**（release/10.0.0 tag，tagger = Glen Barber），10.0 引入 Clang/LLVM 替代 GCC 作为默认编译器；FreeBSD 11.0 tagger_date = **2016-09-23**（release/11.0.0 tag），11.0 引入 arm64 Tier-2 支持、改进 bhyve 虚拟化、改进无线网络栈。DragonFly 同期主要推进 HAMMER 2 与 LWKT，技术广度不及 FreeBSD——dragonfly.duckdb 显示 DragonFly 在 **v4.0.0**（**2014-11-23**）完成 Linux DRM 切换与 i386 移除（**2015-06-20** 起），但未引入类似 Clang/bhyve/arm64 的重大新特性
**史料**：freebsd.duckdb commits 表（freebsd-src 与 dragonfly-src 仓库 2011-2018 年对照）；freebsd.duckdb freebsd-src 仓库 tags 表 release/10.0.0 = 2014-01-16、release/11.0.0 = 2016-09-23；FreeBSD 9.x/10.x/11.x release notes；DragonFly 4.x release notes〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 6 条——技术路线分化：dragonfly.duckdb 数据显示 FreeBSD 与 DragonFly 在技术广度上的分化进一步加深——FreeBSD 9.x-11.x 引入 Clang/LLVM、bhyve、arm64、UEFI 等多个重大新特性，DragonFly 4.x 专注 HAMMER 2 与 LWKT 深化既有路径；总纲第 8 条——本体论上各方平等：dragonfly.duckdb 数据显示 FreeBSD 年均 commit 量是 DragonFly 的 6.1 倍，反映 FreeBSD 的工程动员能力远超 DragonFly——但 DragonFly 在 LWKT/HAMMER 等子系统上的“轻量级内核哲学”投入是 FreeBSD 未涉足的领域，两种工程形态在本体论上地位相等（原挂“总纲第 17 条——软件工程”，基线第 17 条为“证明世界先于解释和改造世界”，按权威表改挂——2026-09-12 整改）

**辨析**：dragonfly.duckdb 显示 FreeBSD 10.0 引入 Clang/LLVM 替代 GCC，DragonFly 同期仍使用 GCC——DragonFly 在 5.x 时期才转向 Clang/LLVM ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］，须以 DragonFly 5.x release notes 核验；FreeBSD 11.0 的 arm64 Tier-2 支持在 13.0 才升至 Tier-1；技术比较需结合项目目标——FreeBSD 追求主流服务器市场，DragonFly 追求轻量级内核哲学，二者目标不同
