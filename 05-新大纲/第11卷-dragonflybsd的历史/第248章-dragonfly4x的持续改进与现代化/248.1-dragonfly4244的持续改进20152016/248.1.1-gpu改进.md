**史观**：dragonfly.duckdb 数据显示 DragonFly 在 4.x 时期的 GPU 改进是从 FreeBSD DRM 转向 Linux DRM 的工程实践——332 条 DRM 相关 commit 反映持续投入，Tigeot 作为 DRM 移植主要贡献者是个人主导项目中 “边缘者支柱” 的典型；总纲第 4 条——分离聚合是永恒规律：DRM 转向让 DragonFly 与 FreeBSD 代码共享进一步减少，与 Linux 内核代码同步增加；统计结论 C-11 印证——dragonfly-src 月度 commit 量统计显著下降（Sen's slope =-0.907/月，p < 0.001），4.x 时代正处此下降趋势的中段，反映 DragonFly 工程动员能力持续衰减与社区规模萎缩

**辨析**：v4.2.0 发布日期以 dragonfly.duckdb tags 表 tagger_date 为准——2015-06-28 而非 2016 年，原大纲 “4.2（2016 年发布）” 错误已修正；dragonfly.duckdb 关键词搜索可能低估 DRM 改进的实际 commit 量——部分 DRM commit 可能以 ‘i915’/‘radeon’ 等具体驱动名为关键词而未提及 ‘DRM’，须以 commit_files 表核验；Tigeot 的 DRM 移植工作具体 commit 须以 commit_files 表 sys/dev/drm/ 目录核验；【统计显著 ≠ 实际显著·C-11 局限】Mann-Kendall 趋势检验仅表明 commit 量存在统计显著的单调下降趋势，不证明下降原因——4.x 时代 commit 量下降可能源于社区规模萎缩、Dillon 个人精力分配变化、LWKT/HAMMER 路径未获主流采纳等多种因素，须结合邮件列表与开发者访谈交叉验证；【序列独立性假设】Mann-Kendall 检验假设观测值独立，若存在显著自相关须预白化，dragonfly-src ACF 缓慢衰减（lag = 36 仍 0.3003）表明序列存在自相关，C-11 结论须谨慎解读；【多重比较风险】C-11 与 Task 6 变点检验（C-15）、Task 9 编程之夏 季节性（C-23）同源 dragonfly-src 仓库，跨 Task 多重比较未做 family-wise error rate 校正
