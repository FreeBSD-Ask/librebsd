# 252.5.6 MP-safe 子系统与安全演化——MPSAFE-TTY 时代的并发安全

**要点**：DragonFly 6.0（**2021 年 5 月 7 日** 发布）引入 MPSAFE-TTY，是 6.x 周期 MP-safe 子系统演化的关键节点——dragonfly.duckdb 显示 6.0 系列期间 message_subject 含“MPSAFE”的 commit 集中于 TTY 子系统的锁细化，反映 TTY 是 DragonFly 最后完成 MP-safe 化的子系统之一；6.0 之后 MPSAFE 关键词 commit 量显著减少，反映 LWKT 路线在 6.x 周期已进入“维持阶段”而非“扩展阶段”；6.x 周期数据库中无 MP-safe 相关 CVE commit，反映 MP-safe 重构在 6.x 之前已基本完成（5.x 时期是 MP-safe 重构高峰）；但 MP-safe 子系统的复杂性可能引入新的并发 bug 类——这类 bug（如 race condition、deadlock）难以通过 CVE 系统捕获，多通过普通 bug 报告处理

**史料**：**dragonfly.duckdb** `commits` 表 dragonfly-src 仓库 MPSAFE 关键词查询：`SELECT commit_hash, author_date, author_name, message_subject FROM commits WHERE repo_name='dragonfly-src' AND author_date>='2021-01-01' AND author_date<'2022-06-01' AND message_subject LIKE '%MPSAFE%'` 结果含 6.0 系列 MPSAFE-TTY commit；DragonFly 6.0 release notes MPSAFE-TTY 说明；DragonFly LWKT 设计文档 ［A］

**史观**：总纲第 7 条——硬件与软件辩证：6.x 周期 MPSAFE-TTY 的引入标志着 DragonFly MP-safe 路线进入“收尾阶段”——与 5.x 周期“持续演化的关键阶段”不同，6.x 周期 TTY 子系统作为最后持有 Giant Lock 的子系统之一完成 MP-safe 化，反映 DragonFly LWKT 路线在 6.x 时期已基本覆盖全部主要内核子系统；6.x 周期 LWKT 路线的工程问题从“扩展 MP-safe 覆盖”转为“维持 MP-safe 稳定性”——dragonfly.duckdb 显示 6.x 周期 MPSAFE 关键词 commit 量较 5.x 时期减少（主要集中于 6.0 系列的 TTY 锁细化），反映 MP-safe 重构已完成主要工作量；但 MP-safe 子系统的复杂性带来的并发 bug 隐患在 6.x 周期持续存在，这类 bug 通常不申请 CVE 编号——这与 FreeBSD 14.x 周期 ZFS 协调锁漏洞偶发 CVE 形成对照

**辨析**：**MP-safe 完成 vs CVE 关系的辨析**：6.x 周期 MPSAFE-TTY 完成后 DragonFly 主要内核子系统均已 MP-safe 化，但 MP-safe 完成不等于并发安全无虞——MP-safe 重构引入的 bug（如 race condition、deadlock、use-after-free）在 6.x 周期仍以普通 bug fix commit 处理，不申请 CVE 编号；与 5.x 周期“扩展 MP-safe 覆盖”阶段不同，6.x 周期进入“维持 MP-safe 稳定性”阶段后，并发 bug 的出现频率应较 5.x 周期降低（但 dragonfly.duckdb 中无统计佐证）［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；**MPSAFE-TTY 的安全意义**：MPSAFE-TTY 使 TTY 子系统在多核环境下无需 Giant Lock，提升了多核场景下的 TTY 操作并发性，但其安全影响是间接的——主要体现为性能提升而非安全加固；与 FreeBSD 14.x 周期 TTY 子系统早已 MP-safe 化的对照，DragonFly 6.0 才完成 TTY MP-safe 化反映 DragonFly MP-safe 路线的完成时间晚于 FreeBSD 约 15 年（FreeBSD Giant Lock 退役始于 5.x 时期约 2006 年）
