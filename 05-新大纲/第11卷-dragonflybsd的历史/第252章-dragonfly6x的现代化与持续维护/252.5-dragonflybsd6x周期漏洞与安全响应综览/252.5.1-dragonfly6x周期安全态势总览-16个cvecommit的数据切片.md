# 252.5.1 DragonFly 6.x 周期安全态势总览——16 个 CVE commit 的数据切片

**要点**：DragonFly BSD 6.x 周期（**2020 年 6 月 1 日** 至 **2026 年 7 月 22 日**，覆盖 v6.0.0 于 **2021 年 5 月 7 日** 发布至 v6.4.2 于 **2025 年 5 月 9 日** 发布）数据库共记录 **16 条 CVE 相关 commit**，对应 **32 个去重 CVE**；NVD 元数据中仅 1 个 CVE 有 CVSS v3.x 评分——CVE-2024-6387（regreSSHion，CVSS 8.1 High），其余 31 个 CVE 在本地 cvelistV5 镜像中无 CVSS v3 评分；这一数据分布与 FreeBSD 14.x 周期（648 条 CVE commit、189 个去重 CVE、80 个 FreeBSD-SA）形成鲜明对比——DragonFly 6.x 周期 CVE commit 量仅为 FreeBSD 14.x 同期的 2.47%，且无任何正式 Security Advisory。6.x 周期漏洞来源分布如下：

    | 来源类别 | commit 数 | 占比 | 具体组件/CVE |
    |---|---|---|---|
    | 贡献组件 vendor import | 12 条 | 75% | expat/libarchive/libressl/zlib/libpcap/less/openssh |
    | FreeBSD 安全补丁 MFC 回溯 | 2 条 | 12.5% | CVE-2023-3107、CVE-2008-2476 |
    | DragonFly base 本地修复 | 2 条 | 12.5% | **ftpd(8)** CVE-2020-7468（两条 commit 对应同一 CVE 的不同分支回溯） |
    base 系统原创漏洞极少，与 DragonFly base 代码量小、社区审计投入低的客观条件吻合
**史料**：**dragonfly.duckdb** `commits` 表 dragonfly-src 仓库 CVE commit 查询：`SELECT count(*) FROM commits WHERE repo_name='dragonfly-src' AND author_date>='2020-06-01' AND author_date<'2026-07-22' AND (message_subject LIKE '%CVE-%' OR message_body LIKE '%CVE-%')` 结果 16 条；**原材料/研究/bsd 漏洞史/版本周期/dragonfly-6.x.md** 版本周期归档（2026-07-22 整理）；dragonfly.duckdb dragonfly-src 仓库 tags 表 v6.0.0 = 2021-05-07、v6.4.2 = 2025-05-09 ［A］

**史观**：软件工程：16 条 CVE commit 的稀疏分布反映 DragonFly 6.x 周期安全态势的两个特征——其一，base 系统代码量小且架构稳定（LWKT/HAMMER2 等核心子系统已过初始 CVE 高发期）；其二，社区规模有限导致主动安全审计投入不足（2024 年 commit 谷值 277 条仅为 FreeBSD 同期 1.9%）；这与 FreeBSD 14.x 周期“主动审计—批量披露”模式形成对照——DragonFly 的安全响应是被动的、依赖上游 CVE 披露后跟进，而非主动审计发现漏洞

**辨析**：16 条 commit 数量少不等于安全态势好——可能反映 DragonFly base 系统未进入第三方安全研究者的审计视野，HAMMER2 等独有子系统不在通用 CVE 扫描工具覆盖范围；与 OpenBSD errata 同期约数百条对比，DragonFly 的 CVE commit 稀疏更可能是“审计盲区”而非“代码质量优”；cvelistV5 中 31 个 CVE 无 CVSS v3 评分反映这些 CVE 多为老旧 CVE（CVE-2008-2476、CVE-2012-0876 等），NVD 未重新评估其严重性，而非 DragonFly 特有现象
