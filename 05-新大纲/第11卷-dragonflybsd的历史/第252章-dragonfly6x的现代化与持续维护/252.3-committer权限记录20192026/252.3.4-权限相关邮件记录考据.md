# 252.3.4 权限相关邮件记录考据

**要点**：dragonfly.duckdb 不直接记录 commit 权限变动，权限授予与撤销须以 DragonFly 邮件列表（lists.dragonflybsd.org）中 Dillon 或 kernel@ 的公告为准。lists.dragonflybsd.org 完整归档 2003-2026 年间 kernel@、commits@、users@、bugs@ 等邮件列表，未发生类似 FreeBSD 2012 年 mailman 迁移丢失事件。权限相关邮件记录的考据须交叉对照 commit log 中新 author_email 首次出现时间与邮件列表公告时间

**史料**：lists.dragonflybsd.org 邮件列表完整归档（2003-2026，含 kernel@/commits@/users@/bugs@）；dragonfly.duckdb dragonfly-src 仓库 contributors 表（新 author_email 首次 commit 时间作为权限授予的间接证据）；marc.info 第三方备份

**史观**：总纲第 9 条——经验优先：commit log 与邮件列表公告的当事人记录互证优先于任何单一来源推断——bsd_commits.duckdb contributors 表中 first_commit_date 字段是权限授予时间的间接证据，须与邮件列表公告交叉验证——0 信任原则下，commit log 与邮件列表任一来源均不可单独采信

**辨析**：邮件记录可能不完整——部分权限决策可能在私下邮件或 IRC 中进行；dragonfly.duckdb 显示 Aaron LI 首 commit = 2017-09-27，但其在 kernel@ 邮件列表的首次发言 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］ 须单独核验；权限撤销记录在 DragonFly 中罕见——dragonfly.duckdb contributors 表显示贡献者停止贡献是自然淡出而非被撤销权限，与 FreeBSD Core Team 2003 年撤销 Dillon 权限的主动撤销模式不同

**文献**：lists.dragonflybsd.org 邮件列表归档；dragonfly.duckdb dragonfly-src 仓库 contributors 表（first_commit_date 序列）；marc.info DragonFly 备份 ［A］
