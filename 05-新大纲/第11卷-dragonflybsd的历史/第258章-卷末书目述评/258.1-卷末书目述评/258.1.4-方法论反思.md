# 258.1.4 方法论反思

本卷叙事的方法论反思集中于三处：0 信任原则在 DragonFly BSD 史研究中的应用、数字史料的局限、史家立场的自反性反思。

0 信任原则在 DragonFly BSD 史研究中的应用体现于对一手资料的逐项考据。Dillon 的分叉公告是当事人单方面声明，可能存在自我美化、责任转嫁、记忆偏差——Dillon 可能在自述中将治理冲突包装为技术路线分歧，亦可能夸大 SMPng 路线的问题以合理化分叉决定。DragonFly BSD 官方历史页面是官方自述，对社区内部争议与可持续性危机着墨甚少——官方历史倾向于呈现项目成功的一面，对 bus factor 极低（**dragonfly.duckdb** 显示 2008 年 top10 占 91.56%、2009 年 top10 占 86.93%）、社区规模萎缩等可持续性问题避而不谈。**dragonfly.duckdb** 中的 commit 记录虽为数字史料，亦有局限——dragonfly-src 仓库为 GitHub 镜像，CVS 时期的早期 commit 可能存在元数据丢失；commit message 中的自述（如 Dillon 在 commit message 中引用 FreeBSD SA 编号）须经原始公告交叉印证。考据过程须留痕——本述评在每个关键史料后注明其考据维度与交叉验证路径，存疑之处明确标注 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。

数字史料的局限体现于 **dragonfly.duckdb** 的覆盖边界。**dragonfly.duckdb** 收录的是 commit 元数据，而非代码内容——对于 HAMMER 与 ZFS 的源码级比较，**dragonfly.duckdb** 仅能提供 commit 时间序列与文件路径，无法替代源码级分析。**dragonfly.duckdb** 的 tagger_date 与实际发布日期可能存在数日偏差，须与官方 Release Notes 互参。**dragonfly.duckdb** 中 DragonFly fork 后与 FreeBSD 主线的 merge commit 比例及上游同步频率的查询在卷章数据映射中已登记，但实际数据报告中未见对应查询结果——L7.1.1 系列仅执行 ghostbsd-src、hardenedbsd-src、trueos-src、pfsense-src 四项 merge commit 比例查询，未覆盖 dragonfly-src 仓库，故 DragonFly fork 后与 FreeBSD 主线的代码流动须以 commits 表 parent_hashes 字段单独查询核验 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。

史家立场的自反性反思体现于对项目统摄史观的警觉。本述评受项目统摄史观影响，承认本体论上各方平等，不判定 Dillon 与 Core Team 谁对谁错。但这一立场本身须被反思——史家可能因项目统摄史观的影响而过度淡化技术路线的工程差异，将 SMPng 与 LWKT 的实质差异简化为“特定历史情境下的状态差异”。史家亦可能因 0 信任原则的过度适用而陷入怀疑主义——对一手资料的逐项考据若走极端，可能导致对一切史料的怀疑，反而无法构建叙事。本述评的自反性立场是：0 信任原则是考据的方法，不是考据的结论——考据后仍可采信，但须注明采信依据与存疑之处；本体论平等是史观的立场，不是事实的判断——SMPng 与 LWKT 在本体论上平等，但二者在工程实践中的采纳规模与社区影响是经验事实，须如实呈现。史家须在 0 信任原则与叙事构建之间保持张力，在项目统摄史观与经验事实之间保持张力，不得以方法论原则取代史实呈现。
