# 258.1.6 以下保留原评注式书目的全部条目按一手史料二手研究工具书与参考三类组织作为本述评的

> 以下保留原评注式书目的全部条目，按一手史料、二手研究、工具书与参考三类组织，作为本述评的史料基础。

### 一手史料

- **Dillon M. Annoucning DragonFly BSD! [EB/OL]. (2003-07-16)[2026-07-23]. <https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>.**

> Matthew Dillon 2003 年 7 月 16 日发布于 freebsd-current 邮件列表的分叉公告，是 DragonFly BSD 诞生的最权威一手文件。公告陈述分叉动机为与 FreeBSD 核心团队在 SMP 扩展路径上的根本分歧，Dillon 主张以消息传递与轻量级线程替代传统锁机制。按 0 信任原则，此为当事人单方面声明，须经 FreeBSD Core Team 同期决议与 **freebsd.duckdb** 中 Dillon 在 freebsd-src 末次 commit（2003-01-28）和 dragonfly-src 首 commit（2003-06-17）交叉验证。标题中“Annoucning”为原始拼写，保留不改。

- **DragonFly BSD Project. DragonFly BSD History [EB/OL]. (2003-2026)[2026-07-23]. <https://www.dragonflybsd.org/history/>.**

> DragonFly BSD 官方历史页面，确认项目分叉日期为 2003 年 7 月 16 日，并概述各阶段技术演进。该页面是本卷分叉时间线与版本节奏的官方基准来源，须与各版本 Release Notes、**dragonfly.duckdb** tags 表的 tagger_date 字段交叉印证。其局限在于为官方自述，对社区内部争议与可持续性危机着墨甚少。

- **DragonFly BSD Project. DragonFly BSD commits mailing list archive (2003-10)[EB/OL]. (2003-10)[2026-07-23]. <https://www.dragonflybsd.org/mailarchive/commits/2003-10/index.html>.**

> DragonFly BSD 项目 2003 年 10 月的提交邮件列表存档，记录 Dillon 对 `src/sys/kern/lwkt_thread.c` 等文件的早期提交，是 LWKT 子系统代码最早可追溯的一手实证。该存档对研究分叉后最初几个月的代码演化具不可替代的史料价值，须与 GitWeb 仓库 commit 历史及 **dragonfly.duckdb** 中 commit 984263bcb83a（2003-06-17 首次导入）交叉印证。

- **BSD 仓库分析数据库（bsd_commits.db）. 23 个 BSD 与跨项目仓库结构化 commit 元数据 SQLite 数据库（v3 扩展版）[DB/OL]. (2026-07-22)[2026-07-22]. 原材料/研究/bsd 仓库分析/bsd_commits.db.**

> 本项目自建的 BSD 仓库 commit 元数据库（原 bsd_commits.db 已拆分升格，现对应 **dragonfly.duckdb** 等项目库），dragonfly-src 仓库含 202 位贡献者与完整 tag 序列（131 条 tag；统计基准 2026-08-18 增量更新），是本卷量化考据的核心数字史料。Dillon 按年 commit 统计、HAMMER/HAMMER2 首引 commit、v6.4.2 末 tag（2025-05-09）等关键事件均经数据库直接验证。须注意 dragonfly-src 仓库的 tagger_date 与实际发布日期可能存在数日偏差，须与官方 Release Notes 互参。

- **DragonFly BSD Project. DragonFly BSD 2.0 Release Announcement [EB/OL]. (2008-07-20)[2026-07-23]. <https://www.dragonflybsd.org/release20/>.**

> DragonFly BSD 2.0 于 2008 年 7 月 20 日发布，HAMMER 文件系统由 Dillon 设计首次正式引入，支持即时快照、历史版本、多卷镜像、CRC 校验等特性。该公告是 HAMMER 引入版本与精确日期的核心一手来源，须与 HAMMER 设计文档、**dragonfly.duckdb** 中 `sys/vfs/hammer/` 目录首引 commit（8750964d1997, 2007-10-10）交叉印证。

- **DragonFly BSD Project. DragonFly BSD 5.6 Release Announcement [EB/OL]. (2019-06-17)[2026-07-23]. <https://www.dragonflybsd.org/release56/>.**

> DragonFly BSD 5.6 于 2019 年 6 月 17 日发布，HAMMER2 在发布前最后一刻切换为默认文件系统，标志 HAMMER2 生产就绪。该公告是 HAMMER2 默认切换版本的最权威一手来源，须与 commit 718989（安装器默认文件系统切换）、DragonFly BSD Digest 2019.7.30 报道交叉印证。部分二手百科来源误载“5.2.0 成为默认”，按 0 信任原则不采信。

- **DragonFly BSD Project. DragonFly BSD 6.0 Release Notes [EB/OL]. (2021-05-10)[2026-07-23]. <https://www.dragonflybsd.org/release60/>.**

> DragonFly BSD 6.0 于 2021 年 5 月 10 日发布，发行说明明确记载因 VM 系统重大改造须移除 MAP_VPAGETABLE mmap() 特性，vkernel 在此版本不再支持。该文档是 vkernel 移除事件的最权威一手来源，并为后续复活工程留下“Support may be re-added at a later time via HVM”的伏笔，须与 commit 770134、DragonFly BSD Digest 2021.1.8 报道交叉印证。

- **Dillon M. DragonFly Mail Agent 首次发布邮件 [EB/OL]. (2007-03)[2026-07-22]. <http://leaf.dragonflybsd.org/mailarchive/kernel/2007-03/msg00060.html>.**

> Dillon（邮件列表 ID corecode）于 2007 年 3 月在 kernel@ 邮件列表发布的 DMA 首发公告，定位为“小型、简洁、干净”的 base 内 mailer。该邮件是 DMA 项目起源的最权威一手来源，须与 Schmidt 2008.2.1“round two”邮件、DragonFly BSD Digest 2015.3.9 报道、FreshPorts mail/dma 元数据交叉印证。DMA 后被 FreeBSD 采纳并于 FreeBSD 14.0（2023）成为默认 MTA，是 DragonFly 技术反哺 FreeBSD 的典型案例。

- **DragonFly BSD Project. commit 718989: 将安装器默认文件系统从 HAMMER1 切换为 HAMMER2 [EB/OL]. (2019-06)[2026-07-22]. <http://lists.dragonflybsd.org/pipermail/commits/2019-June/718989.html>.**

> DragonFly commit 链 718989，发生于 5.6.0（2019.6.17）发布前最后一刻，将安装器默认文件系统从 HAMMER1 切换为 HAMMER2。该 commit 是 HAMMER2 默认切换事件的最权威一手 commit 记录，须与 DragonFly 5.6 Release Notes、DragonFly BSD Digest 2019.7.30 报道交叉印证。

- **Huete Jimenez A. DragonFly Submit #3389: vkernel HVM 复活工程 [EB/OL]. (2025-12-18)[2026-07-22]. <https://bugs.dragonflybsd.org/>.**

> tuxillo（Antonio Huete Jimenez）于 2025 年 12 月 18 日创建的代码审查票号，目标版本 6.6，试图基于 HVM 路径复活 vkernel64。该工程方向与 6.0 Release Notes 中“Support may be re-added at a later time via HVM”承诺一致。须注意 Submit #3389 当前状态为 Feedback，意味着代码审查中尚未合并入主线，“复活工程进行中”与“vkernel 已复活”两个状态须明确区分。

- **Dillon M. DragonFly BSD Presentation [C]//AsiaBSDCon 2004. 东京：AsiaBSDCon, 2004 [2026-07-23]. <https://www.dragonflybsd.org/presentations/dragonflybsd.asiabsdcon04.pdf>.**

> DragonFly BSD 分叉后首次公开技术演讲，由项目创始人 Dillon 主讲，2004 年发表于第一届 AsiaBSDCon（东京理科大学）。演讲涵盖分叉缘起、LWKT 子系统设计与项目远景，PDF 托管于项目官方网站。属一手会议演讲，须与 DragonFly BSD History 页面、分叉公告邮件交叉印证。

- **Dillon M. DragonFlyBSD BSD Track Slides [C]//USENIX 2005 Annual Technical Conference, BSD Track. Anaheim, CA: USENIX Association, 2005 [2026-07-23]. <https://www.dragonflybsd.org/presentations/USENIX2005_BSD/dfly_usenix2005_bsd.pdf>.**

> DragonFly BSD 项目在 USENIX 2005 年度技术大会（CCF A 类会议）BSD 专场的演讲，由 Dillon 主讲，深入阐述 LWKT 子系统、token 同步原语与 vkernel 设计。该演讲是 DragonFly 核心架构设计理念最系统的公开陈述之一，须与 USENIX 2005 官方议程、DragonFly BSD History 页面交叉印证。

### 二手研究

- **ONLamp. DragonFly BSD: A Fork in the FreeBSD Road [EB/OL]. (2004)[2026-07-23]. 原始链接已失效，经互联网档案馆（web.archive.org）2004 年代 ONLamp 域名存档快照获取（存疑：具体存档快照 URL 未能确证，待考）。**

> 2004 年 ONLamp 对 DragonFly BSD 分叉事件的报道，是分叉后最早的主流技术媒体报道之一，提供了 FreeBSD 社区对外部观察者视角的记录。该报道原始链接已失效，须经互联网档案馆获取存档版本。按 0 信任原则，媒体报道对技术细节的叙述可能存在简化与偏差，须与 Dillon 分叉公告、**dragonfly.duckdb** 中 LWKT 首引 commit 序列交叉印证。

- **Luciani R. Threading in DragonFly BSD [C]//DCBSDCon 2009. 华盛顿特区：DCBSDCon, 2009 [2026-07-23]. <http://www.dcbsdcon.org/speakers/slides/luciani_dcbsdcon2009.pdf>.**

> DragonFly BSD 线程模型的第三方技术分析演讲，由 Luciani 主讲，2009 年发表于 DCBSDCon 2009。该演讲深入剖析 LWKT 子系统、token 同步原语与用户态线程实现，是少数由非项目创始人主讲的 DragonFly BSD 学术性演讲。演讲 PDF 托管于 `dcbsdcon.org` 域名，该域名已不再活跃，后续引用须通过互联网档案馆查询存档版本。须与 Dillon AsiaBSDCon 2004 演讲、USENIX 2005 BSD Track 演讲交叉印证。

- **DragonFly BSD Digest. HAMMER2 now default [EB/OL]. (2019-07-30)[2026-07-22]. <https://www.dragonflydigest.com/2019/07/30/hammer2-now-default/>.**

> DragonFly BSD Digest 2019 年 7 月 30 日报道，确认 HAMMER2 在 5.6 发布前切换为默认文件系统，是 HAMMER2 默认切换事件最权威的一手报道。该博客由 Justin Sherrill 维护，长期跟踪 DragonFly BSD 动态，是本项目叙事的重要二手来源。须与 commit 链 718989、DragonFly 官方 hammer 文档交叉印证。

- **DragonFly BSD Digest. vkernels broken for now [EB/OL]. (2021-01-08)[2026-07-22]. <https://www.dragonflydigest.com/2021/01/08/vkernels-broken-for-now/>.**

> DragonFly BSD Digest 2021 年 1 月 8 日报道，记录 commit 移除 MAP_VPAGETABLE 后 **vkernel(7)** 随之不可用。该报道是 vkernel 因 VM 系统重大改造与 MAP_VPAGETABLE 特性冲突而被迫移除的关键一手记录，须与 commit 770134、DragonFly 6.0 Release Notes 交叉印证。

- **Phoronix. DragonFly BSD HAMMER Performance Benchmarks [EB/OL]. (2008-2015)[2026-07-23]. <https://www.phoronix.com/>.**

> Phoronix 在 2008 至 2015 年间对 DragonFly BSD HAMMER 文件系统的性能基准测试系列报道，提供了 HAMMER 与 UFS、ZFS 等文件系统的横向性能比较数据。该系列是少数对 DragonFly BSD 文件系统进行量化性能分析的第三方来源。其局限在于测试环境与基准版本随时间变化较大，引用时须注明具体测试日期与 DragonFly 版本号，且 Phoronix 测试方法论的可重复性须经独立验证。

- **Baldwin J M. FreeBSD SMPng Implementation [EB/OL]. (2002)[2026-07-23]. <https://www.freebsd.org/platforms/smp.html>.**

> FreeBSD SMPng（SMP Next Generation）实现文档，由 FreeBSD 核心开发者 John Baldwin（约翰·鲍德温） 撰写，详述 FreeBSD 5.x 起以细粒度锁替代 Giant 锁的 SMP 扩展路径。该文档是理解 DragonFly 分叉技术背景的核心二手来源——Dillon 正是因不认同 SMPng 的锁路径而主张以消息传递替代，须与 Dillon 分叉公告、LWKT 设计文档对照理解两条技术路线的根本分歧。

- **Bonwick J. ZFS: The Last Word in File Systems [C]//Proceedings of the 4th USENIX Conference on File and Storage Technologies (FAST ’05). San Francisco: USENIX Association, 2005.**

> Bonwick 在 USENIX FAST 2005 发表的 ZFS 设计论文，是理解同期文件系统技术格局的关键参照。在本卷叙事中，HAMMER（2008）与 HAMMER2（2017）的设计选择须与 ZFS 的写时复制、端到端校验、池化存储等理念对照理解。Dillon 明确选择了与 OpenZFS 不同的技术路线——HAMMER 基于 B-Tree 索引与历史保留，HAMMER2 引入动态基数树与去重，二者设计哲学的差异须经源码级比较方能充分呈现。

- **Schimmel B. Unix Systems for Modern Architectures: Symmetric Multiprocessing and Caching for Kernel Programmers [M]. Reading: Addison-Wesley, 1994. ISBN: 0-201-63338-8.**

> Schimmel 关于 UNIX SMP 与缓存一致性的经典著作，是理解 1990 年代 BSD 内核 SMP 扩展技术背景的基础文献。该书系统阐述多处理器环境下内核同步、缓存一致性、锁粒度等核心问题，为理解 FreeBSD SMPng 与 DragonFly LWKT 两条路径的技术分歧提供了理论框架。其局限在于出版于 1994 年，未涵盖 2000 年后多核架构与 NUMA 的演进。

- **Moody G. Rebel Code: Linux and the Open Source Revolution [M]. Cambridge: Perseus Publishing, 2001. ISBN: 0-7382-0670-9.**

> Moody 关于 Linux 与开源运动的通史，为本卷 BSD 分叉事件提供同期开源生态背景。在本卷叙事中，DragonFly BSD 的分叉发生于开源运动商业化高潮期（2003 年），Linux 内核 2.6（2003.12）的 SMP 改进与 FreeBSD 5.x 的 SMPng 形成竞争态势，须将 DragonFly 的技术选择置于这一更广阔的开源竞争格局中理解。

### 工具书与参考

- **Dillon M. THE HAMMER FILESYSTEM [R/OL]. (2008-06-21)[2026-07-23]. <https://www.dragonflybsd.org/hammer/hammer.pdf>.**

> HAMMER 文件系统的完整设计文档 PDF，由文件系统作者 Dillon 撰写，2008 年 6 月 21 日发布，详述 B+Tree 索引、UNDO/REDO、历史保留、快照、镜像、低级存储层、内核 API 等设计决策。该文档是 HAMMER 文件系统最权威的一手技术文献，与 HAMMER File System Design 项目页面互为补充——项目页面是入口索引，本 PDF 是完整设计文档。须与 DragonFly 2.0 Release Announcement、`sys/vfs/hammer/` 源码目录交叉印证。

- **Dillon M. HAMMER2 Design documents v1-v6 [R/OL]. (2012-2018)[2026-07-23]. <https://gitweb.dragonflybsd.org/dragonfly.git/blob/05af5bd1aeaf8bf30d36fc65103097415b943700:/sys/vfs/hammer2/DESIGN>.**

> HAMMER2 文件系统六份版本演进设计文档，由 Dillon 撰写，记录 HAMMER2 自 2012 年启动设计至 2018 年的演进过程，涵盖动态基数树、64 位硬链接计数器、递归校验码、块写时复制、自动去重等设计决策。六份版本时间戳从 v1（2012-02-08）至 v6（2018-12-08），版本演进链完整可追溯设计决策随时间的变化。须与 DragonFly 4.6/5.0/5.6 Release Notes、`sys/vfs/hammer2/` 源码目录交叉印证。

- **DragonFly BSD Project. vkernel(7) 手册页 [EB/OL]. [2026-07-22]. <https://man.dragonflybsd.org/?command=vkernel&section=7>.**

> DragonFly BSD **vkernel(7)** 手册页，记载 vkernel 由 Dillon 开发，由 host kernel 通过 `vmspace_create()` 等系统调用与 `mmap` 的 `madvise`/`mcontrol` 扩展支持，在 DragonFly 中被视为与 i386/amd64 同等的一等公民架构。该手册页是 vkernel 技术实现与系统调用支持的最权威一手来源，须与 DragonFly 1.8 Release Notes（2007.1.30 vkernel 首次稳定发布）、DragonFly 6.0 Release Notes（2021.5.10 vkernel 移除）交叉印证。

- **DragonFly BSD Project. DragonFly BSD Handbook: MTA [EB/OL]. [2026-07-22]. <https://www.dragonflybsd.org/handbook/mta/>.**

> DragonFly BSD 官方 Handbook 的 MTA 章节，记载“On 15 March 2015, the default MTA has been switched to DMA, in preparation for removing sendmail 8.14.5 from the base system”，是 DMA 默认 MTA 切换日期的最权威一手来源。须与 DragonFly BSD Digest 2015.3.9 报道、John Marino 2015.3 users@ 邮件公告、DragonFly 4.2.0（2015.6.29）发行说明交叉印证，区分 2014.11.25 DragonFly 4.0 发布时仍使用 sendmail 与 2015.3.15 DMA 默认切换两个时间点。

- **DragonFly BSD Project. DragonFly BSD Official Releases Page [EB/OL]. (2004-2026)[2026-07-23]. <https://www.dragonflybsd.org/releases/>.**

> DragonFly BSD 官方发布汇总页面，列出所有正式版本及其发布日期。截至 2025 年 5 月，最新正式版本为 6.4.2（6.4.x 系列维护更新），不存在 6.6、6.8 版本。该页面是本卷版本时间线的官方基准来源，纠正了若干二手来源对版本号的误载，须与 **dragonfly.duckdb** dragonfly-src 仓库 tags 表的 tagger_date 字段交叉印证。

- **DragonFly BSD Project. HAMMER File System Design [EB/OL]. (2007-2008)[2026-07-23]. <https://www.dragonflybsd.org/hammer/>.**
