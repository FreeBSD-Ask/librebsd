# 258.1.5 缺口与前瞻

DragonFly BSD 史研究的史料缺口集中于五处，亦对应五个未来研究方向。

缺口一：DragonFly BSD 在主流同行评审学术数据库的覆盖稀薄。DBLP、ACM DL、IEEE Xplore 等数据库对 DragonFly BSD 的同行评审论文覆盖极为有限，可著录文献集中于 BSD 主题专业会议演讲（AsiaBSDCon、DCBSDCon、USENIX BSD Track）与项目官方一手技术文献。这一缺口使 DragonFly BSD 史研究难以参照同行评审的二手学术研究，须更多依赖一手资料与第三方媒体报道。未来方向：鼓励学术界对 DragonFly BSD 的 LWKT 子系统、HAMMER/HAMMER2 文件系统、vkernel 等核心技术进行同行评审研究，弥补二手学术研究的稀薄性。

缺口二：项目治理结构的一手文档严重缺失。DragonFly Foundation 页面（dragonflybsd.org/foundation/）返回 404，项目治理结构的一手文档严重缺失。Dillon 个人网站（apollo.backplane.com）部分内容失效，Dillon 个人对项目决策的陈述散见于邮件列表与演讲，缺乏系统性的治理文档。这一缺口使 DragonFly BSD 史研究难以参照正式的治理结构文档，须从邮件列表、commit message、演讲问答等零散资料中重建治理图景。未来方向：通过互联网档案馆查询 DragonFly Foundation 页面的历史存档版本，重建项目治理结构的演变；通过深度访谈 Dillon、Justin Sherrill、Simon Schubert、Peter Avalos、Sepherosa Ziehau、Hasso Tepper、Antonio Huete Jimenez（安东尼奥·韦特·希门尼斯）（tuxillo）等核心开发者，补充一手口述史料。**2026-07-30 考据补充**：经 WebFetch 直接核验，**<https://www.dragonflybsd.org/foundation/>** 返回 “The requested URL was not found on this server.”（HTTP 404），确认 Foundation 页面截至 2026-07-30 仍处于失效状态；互联网档案馆 Wayback Machine 查询（**<https://web.archive.org/web/2024/https://www.dragonflybsd.org/foundation/>**）未返回可用的 Foundation 页面历史快照内容（仅返回 Wayback Machine 通用页面），DNS 历史记录查询（**<https://dnshistory.org/>**）未在本次考据中完成，Foundation 页面失效的具体时间点仍未确证 [存疑脚注：互联网档案馆存档未返回可用历史快照，Foundation 页面失效时间点待后续考据核验]。

缺口三：vkernel HVM 复活工程的后续跟踪。tuxillo（Antonio Huete Jimenez）于 2025 年 12 月 18 日创建 Submit #3389，试图基于 HVM 路径复活 vkernel64，目标版本 6.6。该工程方向与 6.0 Release Notes 中“Support may be re-added at a later time via HVM”承诺一致。但 Submit #3389 当前状态为 Feedback，意味着代码审查中尚未合并入主线——“复活工程进行中”与“vkernel 已复活”两个状态须明确区分。未来方向：跟踪 Submit #3389 的代码审查进展，记录 vkernel HVM 复活工程的成功或失败；若复活成功，分析 HVM 路径与原 MAP_VPAGETABLE 路径的技术差异；若复活失败，分析失败原因与 vkernel 在 DragonFly BSD 中的最终定位。**2026-07-30 考据补充**：经 WebFetch 核验，**<https://www.dragonflybsd.org/releases/>** 显示 6.6 系列 release tag 不存在，最新正式版本仍为 6.4.2（2025-05-09），确认 vkernel HVM 截至本考据日期尚未实际合入主线；**<https://bugs.dragonflybsd.org/issues/3389>** 因启用 Anubis 反爬虫保护，WebFetch 无法获取 Submit #3389 当前状态（Feedback / Resolved / Closed），原始记载“状态为 Feedback”无法更新 [存疑脚注：Submit #3389 当前状态待后续以非 WebFetch 方式核验，考据留痕见考据记录 **20260730_jianyi缺口补全考据** 8d 节（原文件未见于现行磁盘布局，待考）]。

缺口四：DragonFly 与 FreeBSD 4.x 源码 diff 量化分析。**dragonfly.duckdb** 显示 DragonFly fork 首 commit（2003-06-17）标题“Initial import from FreeBSD RELENG_4”明确基线选择，但 fork 后 DragonFly 与 FreeBSD 4.x 的源码 diff 演化缺乏量化分析——LWKT、HAMMER、vkernel 等核心创新在源码层面对 FreeBSD 4.x 基线的偏离程度未经量化。未来方向：以 **dragonfly.duckdb** 中 dragonfly-src 仓库的 commits 表 parent_hashes 字段与 **freebsd.duckdb** 中 freebsd-src 仓库进行源码 diff 量化分析，记录 DragonFly 对 FreeBSD 4.x 基线的偏离演化。

缺口五：项目可持续性危机的深度访谈考据。**netbsd.duckdb** 显示 DragonFly 2024 年 commit 量仅 277 条，远低于 FreeBSD 主线；2008 年 top10 占 91.56%、2009 年 top10 占 86.93%，bus factor 极低。这些数字事实指向项目可持续性危机，但可持续性危机的成因（细分市场未建立、LWKT 未获主流采纳、Dillon 个人精力分配等）须经深度访谈考据方能充分呈现。未来方向：对 Dillon 等核心开发者进行深度访谈，考据可持续性危机的成因与项目内部认知；对 DragonFly BSD 用户社区进行调查，考据项目在 BSD 生态中的实际定位。**2026-07-30 考据补充**：经 WebFetch 核验，**<https://www.dragonflydigest.com/>** 显示 Justin Sherrill 仍持续维护 DragonFly BSD Digest 博客，最新博文日期为 2026-07-05（“Lazy Reading for 2026/07/05”），反映项目仍有社区观察者跟踪；邮件列表存档位置经 **<https://www.dragonflybsd.org/mailinglists/>** 确认为 lists.dragonflybsd.org（官方全组存档）、leaf.dragonflybsd.org/mailarchive/（旧官方存档）、marc.info（BSD 区）、Gmane.org（gmane.os.dragonfly-bsd）四处；Dillon 2020-2026 年间关于项目可持续性的具体发言未在本次 WebFetch 中检索到，netbsd.duckdb netbsd-src/openbsd-src 仓库 commits 表 GROUP BY year 横向参照查询未执行 [存疑脚注：Dillon 关于项目可持续性的具体发言待后续检索邮件列表存档核验，openbsd.duckdb 横向参照查询待补充，考据留痕见考据记录 **20260730_jianyi缺口补全考据** 8e 节（原文件未见于现行磁盘布局，待考）]。
