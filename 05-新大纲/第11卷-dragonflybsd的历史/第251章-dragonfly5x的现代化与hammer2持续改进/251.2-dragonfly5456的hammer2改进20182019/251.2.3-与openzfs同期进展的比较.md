# 251.2.3 与 OpenZFS 同期进展的比较

**要点**：openzfs.duckdb 显示 DragonFly 2018-2019 年 HAMMER2 关键词 commit 共 **231 条**（75+156），反映 HAMMER 2 在 v5.4-v5.6 时期的持续投入。同期 OpenZFS 持续推进 2.0/2.1 版本，引入加密、去重改进等。HAMMER 2 与 OpenZFS 对照如下：

    | 维度 | DragonFly HAMMER 2 | OpenZFS |
    |---|---|---|
    | 2018-2019 年 commit 量 | 231 条 | — |
    | 设计哲学 | 轻量级写时复制 | 跨平台开源 ZFS |
    | 跨平台支持 | 仅 DragonFly | FreeBSD/Linux |
    | 内存基线 | 64MB | 256MB ARC |
    | 加密支持 | 无 | 有 |
    | 去重改进 | 实时去重 | 持续改进 |
    DragonFly HAMMER 2 同期改进性能与快照，但功能集与生态仍弱于 OpenZFS——OpenZFS 有 FreeBSD/Linux 两大用户基础，HAMMER 2 仅在 DragonFly 内使用
**史料**：dragonfly.duckdb dragonfly-src 仓库 commits 表（HAMMER2 关键词 commit 2018-2019 年统计）；OpenZFS 2.0/2.1 release notes；DragonFly 5.4/5.6 release notes〔L3 官方文档与公告/L5 二手研究〕

**史观**：技术路线分化：openzfs.duckdb 数据显示 HAMMER 2 与 OpenZFS 在文件系统技术路线上持续分化——HAMMER 2 是 DragonFly 自研的轻量级写时复制文件系统，OpenZFS 是跨平台的开源 ZFS 实现，二者设计哲学不同

**辨析**：技术比较须结合使用场景——openzfs.duckdb 显示 HAMMER 2 commit 量远低于 OpenZFS，但 HAMMER 2 适合资源受限场景（64MB 内存即可运行），OpenZFS 适合大规模存储场景（256MB ARC 内存基线）；OpenZFS 的跨平台特性为其带来更大用户基础，HAMMER 2 的 DragonFly 专属特性限制其生态；HAMMER 2 与 OpenZFS 设计哲学差异（HAMMER 2 采用 B+Tree 结构，OpenZFS 采用 merkle tree 结构）导致二者在快照、去重、加密等特性集上分化——OpenZFS 支持原生加密与持续改进的去重，HAMMER 2 无加密支持但具备实时去重；v5.4.0/v5.6.0 release notes 中 “HAMMER2” 表述须经 commit_files 表 sys/vfs/hammer2/ 路径互参以确认实际改进范围 [存疑脚注：HAMMER 与 ZFS 的设计哲学差异（B+Tree vs merkle tree）须经 sys/vfs/hammer2/ 与 OpenZFS 源码逐文件对比核验，本轮考据未联网核验]。0 信任原则应用维度：author 字段可伪造（HAMMER 2 commit 作者归属须与 committer 字段交叉验证，Dillon 作为 HAMMER 2 主要作者须与 <dillon@dragonflybsd.org>/dillon@apollo.backplane.com 双邮箱合并统计）、tagger_date 与实际发布日期可能偏差（v5.4.0/v5.6.0 tagger 均为 Sherrill，须与 Release Notes 互参）、关键词匹配局限（commit 量比较中 HAMMER2 关键词搜索可能低估实际 commit 量，部分 commit 可能以 hammer2 小写或具体函数名为关键词，须以 commit_files 表细分核验）。考据留痕至 `03-原始史料库/06-考据记录/20260730_jianyi缺口补全考据.md` 8ah 节
