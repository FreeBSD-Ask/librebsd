# 251.7.3 OpenBSD 6.x（2018-2020）

**要点**：openbsd.duckdb 显示 2018-2020 年间 openbsd-src 仓库年均 commit 量约 6687 条（2018 = 7205、2019 = 6247、2020 = 6608）。OpenBSD 6.4-6.8（2018-2020）以安全机制（pledge/unveil）与 FFS/softraid 简洁著称，未用 HAMMER2/ZFS；与 DragonFly 5.x 的 HAMMER2 对照——OpenBSD 6.x 坚持简单可信 FFS，DragonFly 5.x 打磨复杂 CoW HAMMER2，两者目标分化。openbsd.duckdb 显示 OpenBSD 2018-2020 年 commit 量约为 DragonFly 同期 3.8 倍，但 OpenBSD 未在文件系统创新上投入

**史料**：openbsd.duckdb commits 表（openbsd-src 2018-2020 年统计）；dragonfly.duckdb dragonfly-src 仓库 commits 表（2018-2020 年对照）；OpenBSD 6.4-6.8 release notes；DragonFly 5.x release notes〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律：OpenBSD 与 DragonFly 同期演进但目标分化——OpenBSD 安全简洁（FFS/softraid）vs DragonFly 自研 CoW（HAMMER2），两者投入方向不同；总纲第 8 条——本体论上各方平等：OpenBSD 在文件系统上“保守不创新”与 DragonFly“持续自研”是两种工程哲学的平等对照

**辨析**：OpenBSD 的 FS 选择基于安全审计与代码可读性考量，DragonFly 5.x 的 HAMMER2 基于“轻量级写时复制”哲学创新；openbsd.duckdb openbsd-src 仓库 2018-2020 年 commit 量须单独核验；OpenBSD 在 pledge/unveil 上的投入须单独统计
