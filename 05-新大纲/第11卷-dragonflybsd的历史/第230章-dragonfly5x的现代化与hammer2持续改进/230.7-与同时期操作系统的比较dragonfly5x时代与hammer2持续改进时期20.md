# 230.7 与同时期操作系统的比较：DragonFly 5.x 时代与 HAMMER-2 持续改进时期（2017-2021）——与 FreeBSD 12/13（ZFS）、NetBSD 9、OpenBSD 6.x、Linux 5.x（btrfs/ZFS）的对照

## 230.7.1 FreeBSD 12/13（ZFS，2018-2020）

**要点**：freebsd.duckdb 显示 2018-2020 年间 freebsd-src 仓库年均 commit 量约 14487 条（2018 = 14985、2019 = 14273、2020 = 14203），dragonfly-src 仓库年均约 1752 条（2018 = 1709、2019 = 1962、2020 = 1585），FreeBSD 是 DragonFly 的 8.3 倍。FreeBSD 12.0（2018-12-11 发布）引入 OpenZFS 整合与 ZFS 引导改进，13.0（2021-04-13 发布）改进 ZFS 加密；DragonFly 5.x 同期打磨自研 HAMMER2（dragonfly.duckdb 显示 2018-2019 年 HAMMER2 关键词 commit 共 231 条），两者存储哲学持续分化——FreeBSD 上游 ZFS，DragonFly 自研 HAMMER2。FreeBSD 12/13 与 DragonFly 5.x 存储路线对照如下：

| 维度 | FreeBSD 12/13 | DragonFly 5.x |
|---|---|---|
| 文件系统 | OpenZFS（上游整合） | HAMMER2（自研） |
| 12.0/13.0 发布日 | 2018-12-11 / 2021-04-13 | — |
| 2018-2020 年均 commit | 14487 条 | 1752 条 |
| HAMMER2/ZFS commit | — | 231 条（2018-2019） |
| 路线 | 上游成熟方案 | 自研轻量级方案 |

**史料**：freebsd.duckdb commits 表（freebsd-src 2018-2020 年统计）；dragonfly.duckdb dragonfly-src 仓库 commits 表（dragonfly-src 2018-2020 年对照、HAMMER2 关键词 2018-2019 年统计）；FreeBSD 12.0/13.0 release notes；DragonFly 5.x HAMMER2 文档〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律：FreeBSD 与 DragonFly 在存储路线上持续分化——FreeBSD 12.x/13.x 时期 OpenZFS 整合属“采用上游成熟方案”，DragonFly 5.x 时期 HAMMER2 打磨属“自研轻量级方案”，两者投入方向不同；dragonfly.duckdb 显示 HAMMER2 关键词 commit 2018-2019 年共 231 条，反映 DragonFly 在自研路径上的持续投入

**辨析**：HAMMER2 的集群复制是 ZFS 之外特性，DragonFly 5.x 持续投入；dragonfly.duckdb 关键词搜索可能低估 HAMMER2 改进的实际 commit 量，须以 commit_files 表核验；FreeBSD 12.0/13.0 的 ZFS 改进 commit 量须单独统计

**文献**：freebsd.duckdb commits 表（freebsd-src 2018-2020 年统计）；dragonfly.duckdb dragonfly-src 仓库 commits 表（含 HAMMER2 关键词统计）；FreeBSD. 12/13 Release Notes [EB/OL]. freebsd.org/releases/；DragonFly. 5.x HAMMER2 Docs [EB/OL]. dragonflybsd.org/docs/ ［A］

## 230.7.2 NetBSD 9（2020）

**要点**：netbsd.duckdb 显示 2018-2020 年间 netbsd-src 仓库年均 commit 量约 3715 条（2018 = 4356、2019 = 3316、2020 = 3473）。NetBSD 9.0（2020-05-31 发布）引入 OpenZFS 集成与 SMP 改进，与 FreeBSD 同用 OpenZFS 上游；DragonFly 5.x 同期守自研 HAMMER2——dragonfly.duckdb 显示 2018-2019 年 HAMMER2 关键词 commit 231 条 vs NetBSD 同期 ZFS 相关 commit 量。BSD 家族存储路线呈“两派”格局：FreeBSD/NetBSD 选 OpenZFS，DragonFly 守 HAMMER2，OpenBSD 守 FFS

**史料**：netbsd.duckdb commits 表（netbsd-src 2018-2020 年统计）；dragonfly.duckdb dragonfly-src 仓库 commits 表（HAMMER2 关键词 2018-2019 年统计）；NetBSD 9.0 release notes；DragonFly 5.x release notes〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律：NetBSD 9 与 FreeBSD 同用 OpenZFS，DragonFly 5.x 独立 HAMMER2，BSD 家族存储路线呈“两派”格局——OpenZFS 阵营（FreeBSD/NetBSD）vs 自研阵营（DragonFly HAMMER2）vs 简洁阵营（OpenBSD FFS）；总纲第 8 条——本体论上各方平等：NetBSD 9 选 OpenZFS 反映其 Core Team 集体审议后的整合策略，DragonFly HAMMER2 反映 Dillon 个人主导的自研策略

**辨析**：NetBSD 9 的 ZFS 与 DragonFly HAMMER2 路线不同，反映 fork 后整合策略差异；netbsd.duckdb netbsd-src 仓库 2020 年 commit 量须单独核验；HAMMER2 vs OpenZFS 在不同负载下的性能对比须结合具体 benchmark

**文献**：netbsd.duckdb commits 表（netbsd-src 2018-2020 年统计）；dragonfly.duckdb dragonfly-src 仓库 commits 表（HAMMER2 关键词统计）；NetBSD. 9.0 Release Notes [EB/OL]. netbsd.org/releases/；DragonFly. 5.x Docs [EB/OL]. dragonflybsd.org/docs/ ［A］

## 230.7.3 OpenBSD 6.x（2018-2020）

**要点**：openbsd.duckdb 显示 2018-2020 年间 openbsd-src 仓库年均 commit 量约 6687 条（2018 = 7205、2019 = 6247、2020 = 6608）。OpenBSD 6.4-6.8（2018-2020）以安全机制（pledge/unveil）与 FFS/softraid 简洁著称，未用 HAMMER2/ZFS；与 DragonFly 5.x 的 HAMMER2 对照——OpenBSD 6.x 坚持简单可信 FFS，DragonFly 5.x 打磨复杂 CoW HAMMER2，两者目标分化。openbsd.duckdb 显示 OpenBSD 2018-2020 年 commit 量约为 DragonFly 同期 3.8 倍，但 OpenBSD 未在文件系统创新上投入

**史料**：openbsd.duckdb commits 表（openbsd-src 2018-2020 年统计）；dragonfly.duckdb dragonfly-src 仓库 commits 表（2018-2020 年对照）；OpenBSD 6.4-6.8 release notes；DragonFly 5.x release notes〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律：OpenBSD 与 DragonFly 同期演进但目标分化——OpenBSD 安全简洁（FFS/softraid）vs DragonFly 自研 CoW（HAMMER2），两者投入方向不同；总纲第 8 条——本体论上各方平等：OpenBSD 在文件系统上“保守不创新”与 DragonFly“持续自研”是两种工程哲学的平等对照

**辨析**：OpenBSD 的 FS 选择基于安全审计与代码可读性考量，DragonFly 5.x 的 HAMMER2 基于“轻量级写时复制”哲学创新；openbsd.duckdb openbsd-src 仓库 2018-2020 年 commit 量须单独核验；OpenBSD 在 pledge/unveil 上的投入须单独统计

**文献**：openbsd.duckdb commits 表（openbsd-src 2018-2020 年统计）；OpenBSD. 6.4-6.8 Release Notes [EB/OL]. openbsd.org/；DragonFly. 5.x Docs [EB/OL]. dragonflybsd.org/docs/ ［A］

## 230.7.4 Linux 5.x（btrfs/ZFS，2018-2020）

**要点**：Linux 5.x（2018-2020）在 DragonFly 5.x 同期以 ext4/btrfs 为主流文件系统，ZFS 经 OpenZFS-on-Linux 树外提供（因 CDDL 许可证冲突无法合入主线）。Linux 内核主线同期 commit 规模远超 BSD 各项目〔存疑：linux-stable 仅含 stable 分支，主线量化口径未复核〕。与 DragonFly 5.x 的 HAMMER2 对照——btrfs 与 HAMMER2 同为 CoW 实验且均曾有稳定性争议，Linux 5.x 的 ZFS 树外与 BSD 基树整合对照

**史料**：Linux 5.x 文件系统文档（kernel.org/doc/html/latest/filesystems/）；OpenZFS-on-Linux 项目（github.com/openzfs/zfs）；DragonFly 5.x HAMMER2 文档〔L3 官方文档与公告/L5 二手研究〕

**史观**：总纲第 4 条——分离聚合是永恒规律：Linux 5.x 的 ZFS 树外提供（因 CDDL 许可证冲突）与 BSD 基树整合形成对照——FreeBSD/NetBSD 直接整合 OpenZFS 至基树，Linux 因许可证冲突无法整合；总纲第 13 条——法律与道德是利益分配：CDDL vs GPL 许可证冲突是 Linux ZFS 树外提供的法律根源，反映许可证利益分配对技术整合的约束

**辨析**：CoW FS 的稳定性是共性工程难题，HAMMER2 与 btrfs 各有取舍；Linux 5.x 的 ZFS 树外提供使 ZFS 在 Linux 上无法随内核启动，须额外配置 initramfs；linux-stable 仓库仅含 stable 分支，主线 commit 量须以 git.kernel.org 核验

**文献**：Linux. 5.x Filesystem Docs [EB/OL]. kernel.org/doc/html/latest/filesystems/；OpenZFS-on-Linux [EB/OL]. github.com/openzfs/zfs；DragonFly. HAMMER2 Docs [EB/OL]. dragonflybsd.org/docs/ ［A］

## 230.7.5 同期文件系统创新总览（2018-2020）

**要点**：dragonfly.duckdb 数据显示 2018-2020 年 BSD 四仓库文件系统相关 commit 量对照——dragonfly-src HAMMER2 关键词 commit 共 400 条（2018 = 75、2019 = 156、2020 = 169），freebsd-src/openbsd-src/netbsd-src 的 ZFS/FFS 相关 commit 量须单独统计。2018-2020 年同期文件系统创新格局对照如下：

| 项目 | 文件系统 | 路线 | 2018-2020 commit | 特色 |
|---|---|---|---|---|
| FreeBSD 12/13 | OpenZFS | 上游整合 | — | 加密、引导 |
| NetBSD 9 | OpenZFS | 上游整合 | — | SMP 改进 |
| DragonFly 5.x | HAMMER2 | 自研 CoW | 400 条 | 集群复制 |
| OpenBSD 6.x | FFS/softraid | 简洁保守 | — | 安全优先 |
| Linux 5.x | btrfs/ext4+树外 ZFS | 主流 + 树外 | — | CDDL 冲突 |

DragonFly 5.x 的 HAMMER2 是 BSD 家族内仅有的独立 CoW FS 持续演进

**史料**：dragonfly.duckdb dragonfly-src 仓库 commits 表（HAMMER2 关键词 2018-2020 年统计）；各系统 2018-2020 文件系统史料；FreeBSD 12/13、NetBSD 9、OpenBSD 6.x、Linux 5.x release notes〔L1 代码/构建产物/L3 官方文档与公告〕

**史观**：总纲第 4 条——分离聚合是永恒规律：DragonFly 的 HAMMER2 与 FreeBSD/NetBSD 的 OpenZFS 同源分叉——HAMMER2 是 BSD 家族内仅有的独立 CoW FS，与 OpenZFS 的“上游整合”路径形成对照；dragonfly.duckdb 显示 HAMMER2 关键词 commit 2018-2020 年共 400 条，反映 DragonFly 在自研路径上的持续投入

**辨析**：FS 创新路线由项目目标决定——HAMMER2 的集群特性为其独特定位，OpenZFS 的跨平台特性为其生态优势；openzfs.duckdb 关键词搜索可能低估各项目文件系统改进的实际 commit 量，须以 commit_files 表核验；跨项目 FS commit 量比较须结合项目规模与开发者基数

**文献**：dragonfly.duckdb dragonfly-src 仓库 commits 表（HAMMER2 关键词统计）；McKusick M K, Neville-Neil G. The Design and Implementation of the FreeBSD Operating System [M]. 2nd ed. Addison-Wesley, 2015；各系统 release notes ［A］
