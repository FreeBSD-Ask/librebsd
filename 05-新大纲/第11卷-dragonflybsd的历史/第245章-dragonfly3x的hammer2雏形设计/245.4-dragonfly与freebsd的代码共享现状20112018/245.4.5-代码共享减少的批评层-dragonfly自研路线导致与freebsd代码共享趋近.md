# 245.4.5 代码共享减少的批评层——DragonFly 自研路线导致与 FreeBSD 代码共享趋近于零的批评

**要点**：bsd_commits.duckdb dragonfly-src 仓库 commits 表显示 2011-2015 年间 MFC/From FreeBSD 关键词 commit 按年序列为 6/34/37/34/18，2011 年仅 6 条反映 v3.x 系列初期 DragonFly 与 FreeBSD 代码共享已接近“几乎独立”状态，2015 年 18 条占总 commit 量 3112 条的 0.58% 量化反映代码共享已趋近于零。批评方论点集中于三个层面——其一，技术路线分化的代价：DragonFly 自研 LWKT/HAMMER/HAMMER2/vkernel 等核心子系统使其与 FreeBSD 在内核架构上的共享基础逐步削弱，2011 年 6 条 MFC commit 反映 DragonFly 在 v3.x 系列初期已无法有效回移 FreeBSD 的 SMP 持续改进（如 FreeBSD 9.x 的细粒度锁与 NUMA 支持），2015 年 18 条 MFC commit 反映 DragonFly 在 v4.x 系列时期与 FreeBSD 10.x/11.x 的代码共享已限于驱动程序与工具链的小幅移植，核心子系统（HAMMER2、LWKT、vkernel）完全独立维护；其二，社区规模的代价：bsd_commits.duckdb 显示 dragonfly-src 仓库 2015 年活跃 committer 数降至 28 人（较 2012 年 35 人减少 20%），同期 freebsd-src 仓库活跃 committer 数以百计，代码共享减少使 DragonFly 无法有效利用 FreeBSD 社区的维护力量——FreeBSD 对驱动程序、工具链、第三方软件的持续改进难以通过 MFC 移植至 DragonFly，DragonFly 须独立维护全部子系统，社区规模的有限性与独立维护的全面性之间的张力使 DragonFly 的维护负担持续加重；其三，生态孤立的代价：代码共享减少使 DragonFly 与 FreeBSD 的生态距离持续扩大——DragonFly 的 Ports/DragonFly dports 团队须独立维护 dports 与 FreeBSD Ports 的同步，bsd_commits.duckdb 显示 dports 仓库更新滞后于 FreeBSD Ports，软件包数量与更新及时性均不及 FreeBSD，生态孤立使 DragonFly 对新用户的吸引力下降，bsd_commits.duckdb 显示 dragonfly-src 仓库 2011-2015 年间活跃 committer 数从 33 人降至 28 人反映社区规模在 v3.x-v4.0 时期持续萎缩

**史料**：bsd_commits.duckdb dragonfly-src 仓库 commits 表 MFC/From FreeBSD 关键词按年（2011 = 6、2012 = 34、2013 = 37、2014 = 34、2015 = 18）与 2015 年总 commit 量 3112 条；bsd_commits.duckdb dragonfly-src 仓库 commits 表活跃 committer 数按年（2011 = 33、2012 = 35、2013 = 33、2014 = 33、2015 = 28）；bsd_commits.duckdb freebsd-src 仓库 tags 表（FreeBSD 9.x/10.x/11.x release 序列）；DragonFly BSD 官方 release 页面（v3.0.0 = 2012-01-22、v3.2.0 = 2012-08-20、v3.4.0 = 2013-04-29、v3.6.0 = 2013-11-25、v4.0.0 = 2014-11-23、v4.2.0 = 2015-06-29）；DragonFly dports 仓库提交记录与 FreeBSD Ports 仓库对比；DragonFly kernel@ 邮件列表 2011-2015 年间关于代码共享的讨论

**史观**：总纲第 4 条——分离与聚合：dragonfly.duckdb MFC commit 量从 2011 年 6 条到 2015 年 18 条反映分离聚合律的非线性演化——2013 年峰值 37 条反映 v3.4-v3.6 时期 DragonFly 与 FreeBSD 的短暂聚合（可能是驱动程序移植高峰），但整体趋势是分离加剧；总纲第 25 条——终结与延续：代码共享减少是“终结”的具体显现——DragonFly 与 FreeBSD 的代码共享关系在 v3.x-v4.x 时期逐步走向终结，但 DragonFly 的独立延续（持续维护与 HAMMER2 生产可用）亦是“延续”的具体显现
