# 239.2.1 fork 后 userland 的初始共享状态

**要点**：dragonfly.duckdb dragonfly-src 仓库首 commit `984263bcb83a`（2003-06-17T02:57:24Z）标题“Initial import from FreeBSD RELENG_4”——DragonFly 1.0 fork 自 FreeBSD 4.8（2003-04-03 release），userland 几乎完全相同。fork 后 1 小时 33 分钟 commit `1de703daf673`（2003-06-17T04:30:05Z）即开始 `Add the DragonFly cvs id and perform general cleanups on cvs/rcs/sccs ids`，2 小时 18 分钟后 commit `bec037ae07f0`（2003-06-17T05:15:13Z）“Remove UUCP support”——差异化操作在 fork 当日即启动。fork 当日 commit 序列与差异化操作对照如下：

**史观**：总纲第 4 条——分离聚合是永恒规律：fork 初期的共享状态——DragonFly 1.0 与 FreeBSD 4.8 userland 共享源于 fork 首 commit“Initial import from FreeBSD RELENG_4”，该共享状态经 fork 当日即启动的差异化操作（添加 DragonFly cvs id、移除 UUCP）逐步终结；分离过程从 fork 首小时即开始，符合“分离非瞬时事件而是长期演化”的史观
