**字段 2 采访摘要**

Dillon 在 23 年间（2003-2026）以“设计 + 实现 + 提交”三步一体方式推进 DragonFly 所有重大架构决策，dragonfly.duckdb 显示核心子系统首引 commit 均由其一人提交：LWKT（`8ad65e080342`，2003-06-20T02:09:59Z）、HAMMER（`8750964d1997`，2007-10-10T19:37:25Z）、HAMMER2（`703720e4d599`，2012-02-26）、vkernel（`39619464950a`，2006-10-22）。DragonFly 无 Core Team 选举机制、无 Foundation 法律实体（dragonflybsd.org/foundation/ 页面 404）、无公开 bylaws，Dillon 作为创始人对技术路线拥有最终裁定权。dragonfly.duckdb contributors 表显示 Dillon 合并 10666 条 commit，与第二名 Wildner（10846 条）体量相当，但在核心子系统设计决策上唯一独立。23 年间 DragonFly 无公开重大技术路线分歧事件（对比 FreeBSD 5.x SMPng 争议、NetBSD 2007 Core Team 解散事件）。

本则 Dillon 治理模式的证据来自 dragonfly.duckdb dragonfly-src 仓库 contributors 表与 commit_files 表的交叉验证：（1）contributors 表显示 Dillon 合并 10666 条 commit（<dillon@dragonflybsd.org>/dillon@apollo.backplane.com/dillon@backplane.com 等邮箱合并），与 Wildner 合并 10846 条体量相当；（2）commit_files 表显示 sys/kern/lwkt_thread.c、sys/vfs/hammer/、sys/vfs/hammer2/、sys/platform/vkernel/ 等核心子系统目录的首次引入 commit 均由 Dillon 提交（commit_hash 序列 8ad65e080342/8750964d1997/703720e4d599/39619464950a）；（3）dragonflybsd.org/foundation/ 页面 HTTP 404 经 WebFetch 抓取核实（访问日期 2026-07-24），证实 DragonFly 无 Foundation 法律实体。自利偏差审查：Dillon 作为单一决策核心对 DragonFly 治理模式的自述带有为自身决策方式辩护的自利倾向，正文引用时须对照 Wildner 等其他长期贡献者的陈述与第三方社区评论；“23 年间无公开重大技术路线分歧事件”的陈述须谨慎解读——可能反映决策效率高，亦可能反映异议者无公开表达渠道（如 Hsu 2007 年停止贡献的具体原因 dragonfly.duckdb 不记录）。完整考据过程见 20260723_announcements-dragonfly.md 第 2.4 节“Dillon 主导模式”与 20260724_dillon-governance-model.md。

**字段 5 史观映射**

- 总纲 10“动手者创造历史”——项目史观总纲第 14 章 14.2 节原文“真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者”“真正的问题不在于技术发展的程度，而在于是否动手”。Dillon 单一决策模式直接塑造 DragonFly 技术路径——LWKT 的消息传递架构、HAMMER 的写时复制设计、vkernel 的用户态虚拟化均出自 Dillon 个人设计，与 FreeBSD Core Team 集体审议后推进 GEOM/ZFS/bhyve 的路径截然不同。须区分项目统摄史观主张与项目统摄史观批评的对象：项目统摄史观批评的是“旁观评论者”以理论框架替代动手实践，而主张历史由动手做事的老实人创造——Dillon“设计 + 实现 + 提交”三步一体的工程实践，是对“动手者”定位的工程化呈现。
- 总纲 17“证明世界先于解释和改造世界”——项目史观总纲第 25 章原文“问题不在于解释世界和改造世界，而在于证明世界”。Dillon“设计 + 实现 + 提交”三步一体的工程实践反映“证明世界”的工程认识论——核心子系统设计文档散见 commit message 与邮件列表发言，无系统性 RFC/PEP 公开审议流程，是以可运行代码“证明世界”，而非以理论先行解释。须注意项目统摄史观批评的对象是“解释与改造的二分”这一形式主义框架本身，而非简单的“实践先于理论”。
- 总纲 5“没有必然性，只有偶然性”——项目史观总纲第 25 章原文“每一个关键人物、每一次 fork、每一个技术决定，都是不可替代的偶然”。Dillon 个人精力与健康状况直接影响项目存续——dragonfly.duckdb 显示 2018-2020 年间 Dillon commit 频率显著下降，同期项目整体 commit 量同步下降，反映 Dillon 个人节奏与项目节奏的高度耦合。须区分项目统摄史观主张与项目统摄史观批评的对象：项目统摄史观批评的是“将项目存续归结为必然规律”的目的论叙事，而主张偶然性是历史的根本结构——Dillon 个人状况作为偶然因素，塑造 DragonFly 项目的存续节奏。
