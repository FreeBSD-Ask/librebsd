**字段 5 史观映射**

- 总纲 8“本体论上各方平等”——项目史观总纲第 25 章原文“FreeBSD、OpenBSD、NetBSD、DragonFly BSD 在本体论上地位相等，差异仅是一刻状态的不同。文档与代码本体平等”。dragonfly.duckdb 量化数据对照（2024 年 DragonFly 277 条 vs OpenBSD 5097 条 vs NetBSD 4290 条）反映各 BSD 分支社区规模差异，但本体论上地位相等——commit 量差异仅是一刻状态的不同，不构成项目价值高下的判定依据。须区分项目统摄史观主张与项目统摄史观批评的对象：项目统摄史观批评的是“以社区规模或市场占有率判定项目价值”的形式主义评判，而主张各 BSD 分支在本体论上地位相等——DragonFly 即使在 commit 量与社区规模上远逊于 OpenBSD/NetBSD，其工程路线的本体论地位并不因此降低；外部批评以“整体影响力下降”为目的论叙事，遮蔽了本体论平等的辩证结构。
- 总纲 4“分离聚合是永恒规律”——项目史观总纲第 25 章原文“UNIX 与 BSD、BSD 各分支之间的分合循环，是历史的根本结构”。BSD 家族反复分裂（NetBSD 1993、OpenBSD 1995、DragonFly 2003）是分离聚合律的历史呈现——“10 个 BSD 开发者”讽刺以夸张形式反映了 BSD 社区对分离代价的反思。须区分项目统摄史观主张与项目统摄史观批评的对象：项目统摄史观批评的是“将分离视为纯粹断裂”的形而上学理解，而主张分离本身蕴含聚合的可能——BSD 各分支虽反复分裂，但共享 UNIX 哲学传统、共同维护 pkgsrc 等跨项目基础设施，分离中聚合张力始终存在；外部批评以“整体影响力下降”为目的论叙事，遮蔽了分离聚合律的辩证结构。
- 总纲 19“解释学循环是历史认识的根本条件”——项目史观总纲第 25 章原文“前理解的差异使分歧不可避免。权力与知识在历史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使”。Linux 内核社区、FreeBSD Core Team、NetBSD/OpenBSD 社区、DragonFly 阵营对 fork 必要性与可持续性的不同评价，源于各自前理解的差异——Linux 内核选择细粒度锁 + RCU 路线的前理解使其对 LWKT 消息传递路线持观望态度；FreeBSD Core Team 采取“沉默处理”策略反映其前理解中对 fork 事件的权力敏感。须区分项目统摄史观主张与项目统摄史观批评的对象：项目统摄史观批评的是“以前理解判定对错”的形式主义评判，而主张解释学循环是历史认识的根本条件——外部批评并非客观真理，而是各自前理解的呈现，正文引用时须对照 DragonFly 阵营的反驳加以辨析。

**要点**：

- Dillon 阐明 DragonFly 1.8 最具分量的特性是 vkernel：以普通进程形态运行于真实 DragonFly 内核之上的完整 DragonFly 内核，思路近似 User Mode Linux，但与 Xen 支持多客户系统不同，它只支持 DragonFly 自身的嵌套运行。（BSDTalk EP98，[51.8-65.72]，L1）
- vkernel 的实现仅依赖三项新增的通用机制——信号邮箱（signal mailboxes）、可经 mmap 映射的虚拟页表、以及受用户完全控制的 VM 空间管理；Dillon 明确建议其他 BSD 项目审视并采纳这些机制，而非完全依赖 QEMU/VMware 做内核虚拟化。（BSDTalk EP98，[1202.34-1302.26]，L1）
- 1.8 版本以底层工程为主：缓存一致性管理部分并入内核、命名空间拓扑重构并重写 nullFS 以支持 jail/chroot 场景下的只读挂载、文件系统 API 为 SysLink 协议预作清理、并引入 GCC 4.1 形成以环境变量切换多编译器的体系（基础编译器仍为 3.4），为项目第二阶段的集群目标铺垫。（BSDTalk EP98，[469.1-583.34]，L1）
- Dillon 宣告项目进入下半场：SMP 基础设施基本就绪，第二阶段主线是集群、SysLink 链路协议与新文件系统；他预计 2.0 不会在生产环境携带新特性，2.1 才是真正落地新文件系统的版本，并直言不愿使用 1.10 这类字符串排序混乱的版本号。（BSDTalk EP98，[706.12-743.92]，L1）
- 关于自 FreeBSD 分化后的代码互通，Dillon 给出分层评估：应用层走 pkgsrc 相当省力，缺陷修复在两树之间双向取用几乎无痛，但整块驱动替换（如移植 FreeBSD 新 ATA 驱动）因 DragonFly 驱动基础设施已显著分叉而代价高昂。（BSDTalk EP98，[605.18-674.7]，L1）

**史料**：

- 本期可核验的一手材料包括：DragonFly 1.8 中为 vkernel 新增的系统调用与代码实现（信号邮箱、虚拟页表 mmap、VM 空间管理三要素）、Dillon 在项目网站发布的开发日志与博客中关于文件系统选型的讨论，以及 release 与 head 分支的维护实践。（BSDTalk EP98，[452.74-1259.5]，L1）

**史观**：

- 总纲10 动手者创造历史：Dillon 自述其工作风格是不深读研究论文，而是提取各家文件系统的可取思想后从头自行实现；这种以动手者个体工程创造替代文献路径的姿态，正是动手者创造历史的一手例证。（BSDTalk EP98，[927.96-944.12]，L1）
- 总纲9 经验优先：vkernel 的立项动机出自直接的工程经验：内核开发中“测试—修改—再测试”的循环在 QEMU/VMware 上过慢，vkernel 将启动压缩到五秒左右并支持在真实内核上以 GDB 实时调试，说明这一技术决策由开发体验而非理论论证驱动。（BSDTalk EP98，[79.0-104.28]，L1）

**辨析**：

- Dillon 估计移植 ZFS 的耗时与按同类原则自建新文件系统相当，并断言 ZFS 本质是海量存储而非集群文件系统；此判断出自其个人经验而非公开测算，且他自认不深读研究文献，采用时应存疑待验。 [存疑脚注] ZFS 移植成本与自建相当的估计系 Dillon 个人经验判断，未见公开量化依据；转写存在乱序与重复标记，时间戳经重排后理解（BSDTalk EP98，[756.0-777.98]，L4）
