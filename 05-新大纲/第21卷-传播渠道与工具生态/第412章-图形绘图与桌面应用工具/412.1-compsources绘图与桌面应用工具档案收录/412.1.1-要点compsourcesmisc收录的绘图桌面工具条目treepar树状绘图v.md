**要点**：

- Wayland 首次进入 FreeBSD ports 树：该 port 由 Koop Mast（kwm）创建、Johannes Lundberg 更新改进，经 Baptiste 合入；主持人称其“意在成为比 X 更简单的替代、更易开发与维护”（125.22-130.78），GNOME 与 KDE 预期最终迁移，Qt 工具链已先行移植，为 KDE 5 与 Lumina 打通路径；Wayland 本体是合成器与客户端之间的协议及实现该协议的 C 库，可运行于内核模式设置驱动之上，也可作为 X 应用或 Wayland 客户端存在。（BSD Now EP179，[98.64-130.78]，L2）
- Baptiste 与原 X11 团队为 Xorg 1.18.4 升级及配套新 Intel/ATI DDX 驱动发起测试征集，以匹配内核侧新 DRM 驱动；录制时点在 FreeBSD 11 上装此补丁暂不能期待新增 GPU 支持，因为其依赖尚未合入的内核部件，需配合 DRM Next 分支与更新的 ports 分支使用。（BSD Now EP179，[289.34-351.2]，L2）
- 一位主持人（TrueOS 开发者）以维护者身份自述：TrueOS 已拉入上述 Wayland 与 Xorg 相关更新并正在构建新包集，数日内推出供测试；又以一手使用经验佐证 TrueOS 同样改用 Xorg 之上的 modesetting 驱动，实践中其可靠性优于 Intel 驱动，与 Fedora、Debian 的官方建议一致。（BSD Now EP179，[415.6-446.92]，L1）
- OpenBSD ARM64 port 初期以 Pine64 与 Raspberry Pi 3 为首批目标；因 ARM SoC 异构，无法如 AMD64 那样统一声明支持，而须按板卡分级列出驱动覆盖（SMSC LAN95XX 网卡、板载 USB hub）；两板均无带电池备份的实时时钟，启动时须以 date -s 容忍大幅偏差校时；录制时快照下载链接尚为 404，预期发布后将涌现以 Raspberry Pi 3 作 PF 路由的实践文章。（BSD Now EP179，[1727.0-1831.56]，L2）
- ChaCha20 讲解：以 ARX 结构的哈希函数在计数器模式下充当流密码，密文即明文与伪随机流的异或；只要同一 key 与 nonce 不复用即可视作一次一密，因而无需填充、加解密同构；512 比特状态按四个 32 位字分组做 quarter round 并行混淆，块内看似多余的 32 位常量实为安全关键；文章出自 Loup Vaillant，主持人坦言超出自身专长但推荐密码学爱好者通读。（BSD Now EP179，[1874.72-2058.52]，L2）
- Netflix 用 FreeBSD 分发视频，早期以 nginx 与 sendfile 半同步方式运行，后改造为全异步以支撑数万长连接并逐步填满 30Gbps。（BSD Now EP167，[294.02-359.9]，L1）
- 在单路 Intel E5-2697 v4 与 Mellanox 100G 网卡上，FreeBSD 可达 100Gbps 网络吞吐且 CPU 仍有约 45% 空闲，而四五年前尚无法填满 10G 端口。（BSD Now EP167，[384.3-423.3]，L1）
- Netflix 与 Intel 合作以手写汇编的 ISA-L 库替代 OpenSSL 批量加密，在 FreeBSD 上实现约 83Gbps 的加密速率，瓶颈转为内存带宽而非 CPU。（BSD Now EP167，[424.46-527.04]，L1）
- iflib 是 Netflix 资助的、位于 ifnet 之上的网络驱动编写库，抽象 ioctl 与多队列处理，旨在降低厂商编写高性能驱动的成本并提升驱动质量。（BSD Now EP167，[567.18-692.66]，L1）
- Netflix 认为厂商常以 FreeBSD 市场小而拒绝投入，iflib 让现有工程师即可编写高质量驱动，Intel 与 Qualcomm 驱动已有变体，Chelsio 与 Mellanox 亦在讨论之列。（BSD Now EP167，[692.66-728.02]，L1）[订正：原 Intel 与 Procom 驱动已有变体，2026-09-30 SenseAudio 重转核对]
- Netflix 资助 FreeBSD 图形栈，以 shim 层把 Linux DRM 代码重编译进 FreeBSD 内核，从陈旧的 DRM 3.x 直接跳到 4.6 与 4.7，从而支持 Skylake 及尚未发布的 Kaby Lake。（BSD Now EP167，[775.92-1133.94]，L1）
- Scott Long 将图形驱动投资称为“moonshot”，Netflix 的 OCA 服务器并不跑 GUI，此举意在让社区健康并扩大开发者基盘，长期回馈 Netflix 自身。（BSD Now EP167，[781.44-859.18]，L1）
- Netflix 正开发 TCP RACK 重新实现拥塞控制与重传，并以包节流缓解视频分块突发导致的尾部丢包；软件 pacing 与 TSO 存在冲突，正与 Mellanox、Chelsio 合作推进硬件 pacing。（BSD Now EP167，[1273.84-1539.26]，L1）
- Netflix 放弃长期停留的 stable-10，直接跳至 12-current 并计划年底前全网络运行，以便开发成果更快回馈 FreeBSD 上游。（BSD Now EP167，[1544.92-1608.76]，L1）
- Netflix 从硬盘平台转向 NVMe 闪存，预测数年后不再为平台采购机械硬盘；Warner Losh 在 CAM 中实现了可优先读写且不过度惩罚任一方的 IO 调度器。（BSD Now EP167，[1681.12-2044.06]，L1）
- Adrian Chadd 自述在 Reddit 发起征集帖是一种采样方法论的自觉：开发者峰会与邮件列表构成内向反馈圈层，而家用、FreeNAS 与桌面场景的用户几乎不进入这些渠道，他有意越出开发者社群补齐用户画像；回收的反馈集中指向无线驱动、笔记本体验等桌面痛点，使其意识到 BSD 社区对自身用户构成的认知存在结构性盲区，且这一人群与会议出席者几乎不重叠。（BSD Now EP101，[1189.14-1303.46]，L1）
- Adrian Chadd 提出 BSD 推广的核心命题：营销只能以言行一致为前提，宣称开箱即用就必须让安装器、无线与默认包集真做到开箱即用；Canonical 与 Ubuntu 的可及性建设被引为参照，用户自发口碑被认定远胜任何公关投入，并回溯九十年代 Linux 社区少数热心者持续布道与导师制的动员效应，认为 FreeBSD 开发者恰恰羞于讲述自己的工作。另附其对各 BSD 的直接劝告：尽快远离 CVS 迁向 Git，越拖社区开发者越老化。（BSD Now EP101，[3321.52-3439.64]，L1）
- 该期头条报道 FreeBSD 10-CURRENT 合入 Radeon KMS 内核图形驱动，标志 FreeBSD 桌面图形栈由传统驱动模式向内核模式设置过渡，并为 10.0 发布前的驱动测试提供基础。（BSD Now EP1，[70.30-125.02]，L2）
- VeriSign 公开拥抱 FreeBSD，以之支撑 .com、.net 等顶级域名的 DNS 根服务器；主持人归纳其选择理由为平台稳定、高并发查询处理能力与社区可回馈性。（BSD Now EP1，[281.60-311.04]，L2）
- Peter Hessler 的 BGP SpamD 以 BGP 协议实时分发垃圾邮件黑名单与白名单：黑名单社区属性为 666、白名单为 42，运营于私有自治系统 AS65066，并以 OpenBGPD 为基础。（BSD Now EP1，[4554.19-4919.96]，L1）
- FreeBSD 基金会 2013 年春季筹款募集 219806 美元，来自 12 家企业与 365 名个人捐赠者；为维持 501(c)(3) 免税地位，个体小额捐赠被视为关键支撑。（BSD Now EP1，[1879.13-1939.54]，L2）
