# 282.1.3 BSD 社区对 Linux 阵营的反向批评

- 要点：BSD 社区对 Linux 阵营也有反向批评——其一，Linux 内核由 Linus Torvalds 个人独裁，决策风险集中于个人；其二，Linux 生态被 Red Hat/IBM 控制垄断，开源独立性受质疑；其三，Linux 内核代码风格不一致，不同子系统差异大；其四，Linux 社区 LKML 毒性行为严重，对新人不友好。这些反向批评在 FreeBSD 邮件列表、OpenBSD 邮件列表、Theo de Raadt（西奥·德·若特） 公开发言中反复出现，构成 BSD 阵营对 Linux 的反向话语压力。
- **BSD 社区对 Linux 阵营反向批评汇总表**：

| 序号 | 反向批评内容 | 关键例证 |
| --- | --- | --- |
| 1 | Linux 内核由 Linus Torvalds 个人独裁 | 决策风险集中于个人 |
| 2 | Linux 生态被 Red Hat/IBM 控制垄断 | 开源独立性受质疑 |
| 3 | Linux 内核代码风格不一致 | 不同子系统差异大 |
| 4 | Linux 社区 LKML 毒性行为严重 | 对新人不友好 |

**史料**：〔考据任务〕FreeBSD/OpenBSD 邮件列表中关于 Linux 的具体发言线程与 Theo de Raadt 关于 Linux 的公开发言原文（标题、日期、链接）待补入后方可著录；泛指表述不作为史料著录

**史观**：总纲第 8 条——本体论上各方平等，BSD 社区对 Linux 的反向批评是社区话语权运作的具体呈现；总纲第 3 条——不存在进步，只有权力再分配，反向批评是 BSD 阵营对 Linux 阵营的话语权争夺

**辨析**：反向批评与 Linux 阵营的批评呈镜像结构——双方都倾向于把对方的治理特征概括为缺陷；辨析时须对称适用同一证据标准，不能因立场同情而放宽对反向批评的核验要求；Theo de Raadt 发言须以原文为准，转述不作为证据
