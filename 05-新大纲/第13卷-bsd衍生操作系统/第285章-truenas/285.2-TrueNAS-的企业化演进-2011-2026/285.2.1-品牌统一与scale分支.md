# 285.2.1 品牌统一与 SCALE 分支

  - 要点：2010 年代 FreeNAS 品牌统一为 TrueNAS；later 推出 TrueNAS SCALE（基于 Linux 的 Debian 分支）与 TrueNAS CORE（基于 FreeBSD）并存，标志 BSD 衍生在企业存储中的分化；具体年份须以 iXsystems 公告核实。
  - **truenas-middleware 仓库 TrueNAS 时代 commit 量演变表（L7.6.1）**：

| 年份 | commit_count | contributor_count | ixsystems_contributors | 工程事件 |
| --- | --- | --- | --- | --- |
| 2017 | 5,370（峰值） | 61 | 10 | commit 量达峰 |
| 2020 | 5,292 | 38 | 5 | TrueNAS SCALE（Linux 分支）推出，社区精力分散 |
| 2026 | 1,610 | 21 | 10 | 震荡下降 |

- 史观：终结中的延续，FreeBSD 分支与 Linux 分支并存；统计结论印证：C-54（truenas-middleware 仓库 commit 量趋势 L7.6.1）显示 2017 年 commit_count = 5,370（峰值）→ 2020 年 5,292 → 2026 年 1,610，commit 量在 2017 年达峰后震荡下降，与 TrueNAS SCALE（Linux 分支）2020 年前后推出后社区精力分散的时间点吻合，0 信任原则适用：commit 量下降不等于项目衰退，TrueNAS SCALE 推出后 middleware 仓库可能拆分为 CORE 与 SCALE 双线维护
- 辨析：SCALE 转向 Linux 反映存储软件栈（容器/K8s）的生态压力，须客观论述［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；freebsd.duckdb 查询 L7.6.1 的 commit 量下降须警惕 commit 量不等于质量的局限——TrueNAS SCALE 推出后 middleware 仓库可能拆分为 CORE 与 SCALE 双线维护，单仓库 commit 量下降未必反映项目衰退，须与 iXsystems 商业战略说明、TrueNAS CORE/SCALE 发布记录交叉验证；freebsd.duckdb 查询 L3.2.1 与 L3.2.2 的 iXsystems commit 占比须警惕邮箱域名识别不精确——员工可能用个人邮箱提交，公司被收购后邮箱域名变更，且占比为全 23 仓库合计，须按单仓库细分（如 truenas-middleware 仓库 iXsystems 占比远高于 freebsd-src）
