# 280.2.2 红帽（Red Hat）控制下的 Linux：从社区项目到企业主导

  - 要点：Red Hat 对 Linux 的控制呈现逐步深化的过程——1990 年代 Red Hat Linux 是社区发行版之一，2000 年代 Red Hat 拆分为 Fedora（社区）与 RHEL（企业），2010 年代 Red Hat 成为 Linux 内核最大企业贡献者，2019 年 IBM 收购 Red Hat 后 Red Hat 对 Linux 的控制进一步巩固。Red Hat 控制下的 Linux 在工程效率上有积极面（系统性投入内核开发、企业级支持），但在社区独立性上有负面效应（Linux 内核方向越来越多由 Red Hat 商业利益塑造，如 systemd、cgroups、eBPF 等关键基础设施由 Red Hat 员工主导）。BSD 内核无单一企业主导，故 BSD 内核方向更多由核心开发者个人兴趣与基金会赞助方共同塑造，独立性更高但商业推动力更弱。

- 史观：总纲第 13 条——法律与道德是利益分配（存疑），Red Hat 控制下的 Linux 是商业资本塑造开源项目的典型；总纲第 15 条——文化即形式主义，Linux 社区从社区项目向企业主导的转变是社区演化的呈现
- 辨析：Red Hat 员工在内核 MAINTAINERS 中的比例须以 MAINTAINERS 文件统计为准；systemd 由 Lennart Poettering 主导的事实须考据；“Linux 内核方向由 Red Hat 商业利益塑造”的判断须有具体案例支持；systemd 的工程架构与 BSD init 的哲学分野详见第186章 systemd 与 BSD init 的哲学合图层。**双方分歧点**：Linux 阵营陈述——Greg Kroah-Hartman 作为 Linux stable 内核维护者长期受 SUSE 雇佣，其在内核 summit 与 LKML 中的自述体现企业雇佣维护者在内核子系统维护者中的结构性占比，Linux 阵营据此论证 Red Hat 主导是“企业级投入保障内核持续演进”的正当结果；BSD 阵营陈述——BSD Now 播客（**bsdnow.org**）多次在节目中对 Red Hat 控制 Linux 内核方向提出批评，核心论点为 Red Hat 通过雇佣 maintainer 实质主导子系统决策，使 Linux 内核演进偏向 Red Hat 商业利益（如 systemd、cgroups v2 等），与 BSD 内核无单一企业主导的分散模式形成对照。两方分歧的实质在于“企业主导”作为开源治理模式的双重性——Linux 阵营视其为工程效率保障，BSD 阵营视其为社区独立性侵蚀。[存疑脚注：MAINTAINERS 文件中 Red Hat 员工比例统计存在口径差异——以雇佣关系统计（含 Red Hat 直接雇佣与前员工）与以 @redhat.com/@gmail.com 邮箱域名统计所得比例不同，Greg Kroah-Hartman 等维护者使用个人邮箱（@linuxfoundation.org）提交但受 SUSE 雇佣，按邮箱域名统计会低估其雇主企业实际占比，按雇佣关系统计须以 Red Hat 官方或 Linux Foundation 年报披露为准，具体比例须待原始档案公开后方可补充确证]
