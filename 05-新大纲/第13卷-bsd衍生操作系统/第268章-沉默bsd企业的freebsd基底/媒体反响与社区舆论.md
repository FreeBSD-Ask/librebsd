**要点**：

- PC-BSD 发布 1.0 的第二候选版：本质是将 FreeBSD 6.0 打包为单 CD 的桌面导向系统，预装 KDE 3.5，全程图形化安装并默认创建普通用户与自动登录，明确面向家用场景。其区别于普通 FreeBSD 加 KDE 之处在于自研包管理器：以单个文件夹容纳应用的程序、库与配置，以双击式安装器交付并请求 root 密码安装，库彼此隔离以避免依赖冲突；当事人梳理此应用包理念的前史为 Acorn 的 RISC OS 与 NeXT，经 Apple 的 Darwin 推广。批评者指其制造冗余膨胀，当事人认为在单用户桌面系统上代价可接受；系统另提供在线更新，免除传统 make world 升级流程；因 1.0 正式版未至，当事人认为此时难作定评。（BSDTalk EP8，[55.22-316.42]，L1）
- 当事人盘点五项免费 BSD shell 账户服务：GNUK（转写亦作 gnooc）与 metawire.org 基于 OpenBSD，arbornet.org 基于 FreeBSD，freeshell.org 基于 NetBSD，此类社区服务多在低配硬件上勉强维持；另有惠普的 HP Test Drive 提供 FreeBSD、NetBSD、Tru64 UNIX、OpenVMS 与 Linux 的 shell，硬件规模远超社区服务（含 16 CPU 系统、GB 级内存），其 NetBSD 已是 3.0 版。当事人注册 GNUK.org 实测获当天技术支持响应，账户按使用年限与捐赠硬件分级、可申请提升配额；并警告挂 IRC 机器人、拒绝服务攻击、骚扰等滥用会毁掉此类免费服务。（BSDTalk EP8，[389.20-605.24]，L1）
- 对 HP Test Drive 以 Telnet 接入一事，当事人批评 OpenSSH 作为 BSD 许可的安全 Telnet 替代品早已人人可用，Telnet 继续被使用不可原谅；并推测 HP 或有意以不安全协议劝阻用户将测试机当重要系统使用。（BSDTalk EP8，[559.26-605.24]，L1）
- OpenBSD 发行传统：自 3.0 版起每版附带一首发布歌曲，当事人以其中一首作为本期节目开场音乐。（BSDTalk EP8，[42.72-51.34]，L1）
- 受访者（EMC 中端 NAS 产品实验室管理员，设施前身 Data General）回溯测试基础设施的演化：最初以 Linux 装六张网卡、用 IP masquerading 支持每组五个网段的测试隔离（第六口接公共生产网）；组间偶需互通时只能跨楼层临时拉线，既难看又有安全隐患；Linux 的 masquerading 存在私有侧路由不干净、擅自挪动端口等问题，网卡驱动质量更是糟糕。他逐步以 FreeBSD 接管这些 Linux 盒的角色：五个私有网段间获得干净路由，并以 NATD 提供对公共网的 NAT，性能更好、更易管理。（BSDTalk EP93，[254.86-433.52]，L1）
- 为替代临时拉线，受访者设计出私有骨干网架构：原 FreeBSD 路由/NAT 盒禁用 NAT、改为骨干网与所辖五个客户网段之间的路由，另置一台双网卡 FreeBSD 盒在骨干网与公共世界之间提供 NAT；由此各组测试流量日常隔离、组间按需自由路由，性能强劲。随着千兆以太网普及与产品需支持 NAS，FreeBSD 盒升级为支持 64 位 PCI 与千兆的机器，作为廉价路由器其性能与扩展性持续保持良好。（BSDTalk EP93，[433.52-577.32]，L1）
- 受访者讲述静态路由的教训与路由协议引入：骨干网上网关众多，每新增一组网络就得更新骨干网上所有机器（FreeBSD 路由器、DNS 服务器等）的静态路由，成为“网络世界为何发展出路由协议”的切身体会；在开发者推动下他改用 RIP2，采用当时 ports 树中的 gated port（该工具的许可证其后发生变化），路由在各 FreeBSD 路由器与骨干网基础设施机器之间自动分发。其后交换机从 3Com 逐步升级到不支持三层功能的 Cisco Catalyst 4000（此间仍靠 FreeBSD 盒在 VLAN 间路由），再到支持硬件三层路由的 Catalyst 6500，FreeBSD 路由基础设施随之逐渐退出。极端案例是一座数千节点的新实验室因三层 supervisor 板卡延迟到位、上线后约三周无硬件路由可用，他以一台 Pentium 3 500 的 Dell 台式机加板载网卡与三张四口网卡共 13 个以太口、每口连接不同 VLAN，由单台 FreeBSD 路由全部流量三周，表现良好。（BSDTalk EP93，[617.32-885.48]，L1）
- 关于负载规模的一手观测：一台双千兆网卡的 FreeBSD NAT 盒承载着 CIFS 与 NFS 文件流量（软件镜像分发、crash dump 传输、测试 harness）、约 200 个 shell 会话以及经 NATD 端口映射的数百个 VNC 或远程桌面 TCP 连接；观测时 NATD 守护进程仅占用约 30% CPU 而两块网卡完全饱和。受访者以此认为该软件极为健壮，FreeBSD 服务其组织非常好。（BSDTalk EP93，[989.16-1123.56]，L1）
- FreeBSD 在该设施内的扩散与企业文化：除测试基础设施外，FreeBSD 被用作 NAS 产品的测试对照操作系统，并广泛用于内部 Web 服务器、DNS、DHCP、MySQL 后端与受访者本人的工作站。该设施曾承担 Data General 的 DG/UX Unix 产品的相当部分开发，聚集大量资深 Unix 开发者——他们能看出 Linux 的缺陷，因代码成熟度而更尊重 BSD 系平台；受访者并断言商业世界出于 GPL 的源码公开连带要求，天然更易接受 BSD 许可平台。（BSDTalk EP93，[1138.02-1231.78]，L1）

**史料**：

- PC-BSD 1.0 RC2 的一手试用记录（安装流程、KDE 3.5 环境、bundle 式包管理器、卸载系统与在线更新），为桌面 BSD 早期形态的直接证词；另含 2006 年 1 月免费 BSD shell 账户服务名录及其底层系统、硬件规模与滥用生态的口述记录，以及 OpenBSD 发行歌传统（自 3.0 起）的口述。（BSDTalk EP8，[42.72-479.56]，L1）
- 本期为 EMC 实验室管理员 Glen R. J. Neff 的口述访谈（bsdtalk093，2007-01-15），其中对 FreeBSD Foundation 职能的陈述尤为详尽：基金会以捐款与 Sun 达成许可协议，得以分发稳定的 Diablo Java VM 二进制，终结 FreeBSD 上须经 Linux 模拟 bootstrap、过程痛苦且产物不稳定的 JDK 构建史；基金会正筹资与 Adobe 合作提供 FreeBSD 原生 Shockwave Flash 插件（既有 Linux 包装器不稳定、常致浏览器崩溃）；基金会资助 BSD 会议并为散居各地开发者提供差旅补助以促成两三天的面对面磋商；其资助的 NetPerf Cluster（位于加拿大）为高端硬件环境，FreeBSD 6.x 网络栈的大量改进、jemalloc 的测试与大量 ZFS 开发均在此完成；基金会并赞助虚拟网络栈的开发。 [存疑脚注] 转写将 NetPerf Cluster 的托管方记作 Cintex，疑为 Sentex 之失真；gated port 的细节亦受转写噪声影响，待核。（BSDTalk EP93，[1495.9-1810.48]，L1）

**史观**：

- 总纲15 文化即形式主义：OpenBSD 每版附发行歌的做法，把版本发布这一纯技术事件转化为可感知的文化仪式：例行发布程序被赋予音乐形式而成为社区文化产品，显示技术社群如何以仪式性形式维系自我认同与传播节奏。（BSDTalk EP8，[42.72-51.34]，L1）
- 总纲3 不存在进步，只有权力再分配：FreeBSD 路由基础设施的命运曲线揭示技术角色的流转机制：其表现越好、越有效地服务测试与开发，项目获得资金越多；资金增长带来 Cisco Catalyst 4000 乃至 6500 的部署，硬件三层路由最终取代了自己扶持起来的 FreeBSD 路由层。技术角色的更替并非单纯的技术优劣裁决，而是随组织预算结构与权力层级的再分配而流转。（BSDTalk EP93，[734.88-805.4]，L1）

**辨析**：

- 免费 shell 服务的 OpenBSD 系站点域名在转写中出现 gnooc.org 与 GNUK.org 两种拼写，实名待考；引用该服务名录前须核对域名实名。当事人对 HP 采用 Telnet 的动机解释（有意以不安全协议劝阻重度使用）是其自承的猜测，无 HP 方面证据支撑，Telnet 接入的事实本身可信，但动机解释仅可作推测对待。[存疑脚注] 域名拼写不一致且企业动机无一手佐证。 [存疑脚注] gnooc.org 与 GNUK.org 拼写不一致，需与 2006 年免费 shell 服务名录核对；HP 采用 Telnet 的动机为当事人推测。（BSDTalk EP8，[389.20-605.24]，L4）
- 受访者对 Linux 与 BSD 的比较观：BSD 项目是完整操作系统，而 Linux 只是内核——用户态工具与配置方式随发行版而异、内核日益去中心化、发行版彼此竞争，他视 Linux 为碎片化的努力；虽自称“工具至上者”，仍偏爱 FreeBSD，理由是可阅读源码、文档为各操作系统之最佳、支持网络发达（IRC、新闻组、邮件列表，且能直接联系驱动开发者协作修 bug）。其入坑契机是拨号时代以三美元购得的 FreeBSD 3.0 光盘，亲身体验印证了朋友所言 BSD 驱动质量优于 Linux 的判断。（BSDTalk EP93，[1345.66-1492.3]，L1）
