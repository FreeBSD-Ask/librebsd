# 279.4.1 小团体化作为开源治理的普遍现象

  - 要点：小团体化（oligarchic tendency）是开源治理的普遍现象，BSD 与 Linux 各项目均不例外——无论是采用共识选举制的 BSD 项目、采用个人主导制的 OpenBSD/DragonFly BSD，还是采用层级 maintainer 体系的 Linux 内核，均在形式治理结构之下存在一个由少数核心开发者构成的实际决策圈层。小团体化在工程效率上有合理性（决策快速、责任明确、内圈成员熟悉代码库），但在社区民主上有负面效应（普通开发者无实质参与权、外部贡献者难获认可）。各 BSD 项目与 Linux 内核的具体团队批评（含反批评与再批评的三层辩证）归入文化治理批评章，此处不展开具体项目的内圈构成细节。

  - 史观：总纲第 3 条——不存在进步，只有权力再分配：小团体化是社区权力集中的呈现，“民主选举”作为形式主义操作常掩盖实质的小团体决策
  - 辨析：小团体化的判断须有具体案例支持，避免泛泛而谈；“普遍现象”的判断须基于跨项目比较研究，避免以单一项目推断全行业；各项目小团体化的具体表现与反批评归入文化治理批评章，本节仅做抽象辨析
