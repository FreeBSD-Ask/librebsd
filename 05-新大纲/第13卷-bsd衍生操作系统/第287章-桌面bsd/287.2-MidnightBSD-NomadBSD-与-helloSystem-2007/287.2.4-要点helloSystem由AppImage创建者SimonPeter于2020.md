# 287.2.4 要点helloSystem由AppImage创建者SimonPeter于2020

  - 要点：helloSystem 由 AppImage 创建者 Simon Peter 于 2020 年初启动，以 FreeBSD 为基底（早期基于 FreeBSD 12.2，0.8 版本基于 FreeBSD 13.1，后续有基于 FreeBSD 14.0 的实验版本），目标是打造 “简洁、优雅和实用” 的桌面操作系统；其设计哲学受 20 世纪 80、90 年代早期 MacOS（如 System 1）启发，桌面布局采用顶部全局菜单 + 底部 Dock 的 macOS 风格，文件管理器命名为 Filer 并兼负窗口管理职责；helloSystem 在技术选型上采用明确的 “欢迎与不欢迎技术” 列表——欢迎 Qt、mDNSResponder、Python、Go，拒绝 GTK、Gnome、Wayland、D-Bus、Polkit、XDG 桌面规范、客户端窗口装饰、Pipewire 等，反映 Simon Peter 对 “简化系统层次” 的工程偏好；应用程序安装采用 AppImage 机制，用户点击未安装应用时系统自动下载对应 AppImage 运行，避免传统包管理器的依赖复杂度；窗口管理器从早期的 Openbox 切换至 KWin，以支持窗口拖拽边缘缩放（类似 Aero Snap）、窗口标题居中、最小化动画等现代桌面体验；系统默认启用 ZFS，且不设密码或用户账户系统，其官方文档明确声明此举并非无视安全，而是主张 “设备合法所有者应真正拥有该设备” 的所有权哲学
  - 史料：helloSystem GitHub 仓库（github.com/helloSystem/helloSystem）；Linux 中国 2021-10-24 报道《helloSystem：一款类似 Mac 的 FreeBSD 系统》（译者 Xingyu.Wang，原文作者 John Paul Wohlscheid，原文链接 news.itsfoss.com/hellosystem-towards-first-release/）；网易新闻 2022 年 helloSystem 0.8 发布报道（基于 FreeBSD 13.1）；网易新闻 helloSystem 基于 FreeBSD 14.0 实验版本报道；Simon Peter 作为 AppImage 创建者的公开身份资料 ［A］
  - 史观：总纲第 2 条——实践先于理论：helloSystem 的 “欢迎与不欢迎技术” 列表是 BSD 工程文化中 “明确技术选型立场” 的极端化体现，与 FreeBSD 内核 “包含一切” 的传统路线形成对照；总纲第 6 条——并行演化：helloSystem 选择 Qt 而非 GTK、选择 AppImage 而非 pkg/Ports，体现了桌面 BSD 在工具链层面的多元探索路径
  - 辨析：须纠正原文中 “helloSystem 由 GhostBSD 衍生思想启发” 的表述——经联网考据，helloSystem 由 Simon Peter 独立发起，其设计灵感明确来源于早期 MacOS（System 1），与 GhostBSD 无直接衍生关系，二者仅同属 “FreeBSD 桌面化” 大类；helloSystem “无密码/无用户账户” 的设计在多用户场景与远程管理中存在结构性局限，须以项目官方文档为准，不得仅凭此推断其 “无视安全”；helloSystem 版本与 FreeBSD 基底的对应关系须以项目 Release Notes 核实，0.8 基于 FreeBSD 13.1、后续实验版本基于 FreeBSD 14.0 的时间线须持续跟踪；helloSystem 拒绝 Wayland、D-Bus、Polkit 的技术立场使其与现代 Linux 桌面生态（尤其是 Flatpak/Portal 体系）兼容性受限，这是其 “简化优先” 哲学的代价

- MidnightBSD 起于 Holt 2004 年的构想，定位桌面 BSD 系统，以易用与安全为核心诉求；他判定其他 BSD 项目对普通用户不够友好。桌面环境选择 GNUstep 而非 KDE 或 GNOME：PC-BSD 与 DesktopBSD 已占据 KDE 路线，GNOME 被众多 Linux 发行版采用而不合其差异化意图，且 Mac 社区存在 Objective-C 动量可资借助；其论证援引 NeXTSTEP 与 Mac OS X 的 BSD 痕迹与共享代码——Cocoa 即 NeXTSTEP、OpenStep 原始库的增强版本，GNUstep 则在库层面克隆 OpenStep，故 GNUstep 配 BSD 是历史的自然搭配。（BSDTalk EP126，[55.96-190.24]，L1）
- mports 是项目差异化重点：Holt 批评 FreeBSD ports 中相当一部分无法正确构建可复用的包，项目首要目标是让所有 port 都能打包，以 pkg_add、pkg_delete 式工具像 Linux 发行版那样消费二进制包，并完全重写包工具、提供命令行与图形两种界面、进而兼作系统更新之用。开发者 Chris Reinhardt 已完成初始脚本与 makefile 改动，正开发 ports 构建集群测试工具，包工具库与命令行界面随后，图形界面与系统偏好工具由 Holt 之妻以 GNUstep 编写。（BSDTalk EP126，[197.80-310.78]，L1）
- 基线与发布策略：当时仅发 i386，AMD64 随下一版本，Sparc64 仅为开发兴趣、PowerPC 无近期计划；项目继续基于 FreeBSD 6 系列，仅个别特性自 7 回移，Holt 强调“我们不是发行版，而是从 FreeBSD 项目分出的分支”；安装仍用 FreeBSD 的 sysinstall，基于 GNUstep 的 live CD 图形安装器（后端库加可选命令行界面）在开发中；镜像站点包括项目自有 FTP、ISD、东密歇根大学与 allbsd.org。1.0 设有自我约束门槛：普通用户放入光盘即得完整桌面环境并能图形化管理系统的程度未达，即不发布 1.0，以 Ubuntu 的开箱即用为参照；1.0 前至少五个发布，0.2 前完成包工具与新安装器，0.3 增加偏好工具，其余视社区反馈自适应。（BSDTalk EP126，[313.06-601.54]，L1）
- Holt 自陈开发以来最大障碍是获得社区接受：项目必须使用大量 GPL 许可的工具；操作系统偏好根深蒂固，Linux 仍然流行，许多开发者不愿看到又一个 BSD 出现；向上游提交补丁的成败因项目而异，Perl 项目是第一个接受其上游补丁的项目。安全方面，项目计划提供按服务开关、易于配置的防火墙面板（以 Mac OS X 防火墙控制面板为参照），并做用户态与内核的透明安全增强，针对 X11 的历史安全问题；明确不走 OpenBSD 那种妨碍用户的极端路线；ProPolice 曾进入代码树但因线程库问题撤出，未来可能恢复或转向 GCC 4.2；项目设安全官员专责研究。（BSDTalk EP126，[749.70-869.04]，L1）

- 受访者自 2005 年 1 月起学习 C 语言，以真实目标驱动学习：WPOP3D 为其自设的 POP3 daemon 目标，兼学邮件机制、C 语言与 UNIX 的结合；WMPDF 源于工作中处理 PDF 的需求而写成简单 C PDF 库，借机理解 C 库的存储、调用与链接；Ratsina 是 Squid 的重定向器，自其重度使用的 SquidGuard 分出——差异在于以后端数据库（MySQL 或 PostgreSQL）承载规则，并支持约束继承：工作时间槽内可嵌套午休子槽、自动继承并允许覆写访问约束，该设计想法来自友人 Max Law。Ratsina 即将发布 1.0，其公司亦愿意采用。（BSDTalk EP91，[253.32-444.86]，L1）
- 受访者介绍 MidnightBSD：一个由 Lucas Holt 主导的 FreeBSD 衍生操作系统，目标是易用的桌面环境并维持图形化的 ports 管理系统（M port，自 FreeBSD ports 起步）；刻意做成完整 fork 而非 live CD 或并行版本，以获得向桌面用户优化的完全自由；不采用 KDE 或 GNOME，而将开发专属的窗口管理器与登录管理器；曾考虑改用 pkgsrc 或 OpenBSD ports，最终决定以自己的基本系统自定方向，以免日后受制于他方演进；并计划引入 OpenBSD 有而 FreeBSD 无的应用。受访者本人主要参与 ports 集合的开发。（BSDTalk EP91，[510.0-675.62]，L1）

**史料**：
