# 284.2.3 Olivier自述其BSD之路始于2005年为家用NAS寻找方案Linux嵌入式

- Olivier 自述其 BSD 之路始于 2005 年为家用 NAS 寻找方案：Linux 嵌入式工具链与 BusyBox 编译过于繁难，他参照 m0n0wall 官方开发者指南，以纯 PHP 重写脚本，在与 FreeBSD 底座的接触中造出 Freedance，即后来的 FreeNAS 前身；后因自认缺乏存储领域的视野，甚至从 FreeNAS 功能请求列表中才初识“快照”概念，遂将项目移交他人，回到网络本业另创 BSD Router Project。（BSD Now EP60，[982.74-1217.36]，L1）
- BSDRP 被作者界定为面向电信运营商与 ISP 的路由发行版而非家用防火墙：不含 web 界面，仅以 SSH 命令行管理，以 nanoBSD 定制镜像集成 Bird、Quagga、OpenVPN、StrongSwan 等路由与安全组件；其判断前提是 x86 商品服务器的转发瓶颈纯在软件侧（netmap、DPDK 一类路径），云时代一周部署上百台路由器的批量运维将淘汰逐台人工配置，软件路由因此将持续扩张。（BSD Now EP60，[1220.80-1347.96]，L1）
- 对 OpenBSD 作为路由底座的评估呈两面：ospfd、bgpd 等守护进程配置语法的同质性极利于管理工具开发；但以其在 OpenBSD 5.x 时期的基准测试，OpenBSD 缺乏多队列网卡驱动与多线程网络栈，转发性能不及 FreeBSD，作为参照，禁用 FreeBSD 的多处理器特性后两者路径趋同。（BSD Now EP60，[1611.26-1680.98]，L1）
- Alan Jude 以当事人身份复盘 Lenovo BIOS 的 GPT 引导缺陷：固件仅检查 protective MBR 中是否置有活动分区标志，未置位即拒绝引导而不查看真正的 GPT；其补丁以 gpart set -a active 对整盘置位解决，并已合入安装器的 ZFS 自动模式，同期亦有 ThinkPad T420 经 UEFI 安装 FreeBSD 11 快照的完整流程记录。（BSD Now EP60，[1953.12-2071.68]，L1）
- OpenBSD tech 邮件列表披露 col(1) 工具 -f 选项的缺陷自 1990 年 5 月 22 日引入，波及 4.3BSD Reno 以降的 4.4BSD、4.4BSD-Lite、386BSD 及 NetBSD、FreeBSD、OpenBSD、DragonFly 全系，乃至 Debian 等部分 Linux，潜伏 24 年后经 hexdump 对比验证修复，构成一个横贯 BSD 谱系代码传承的考古样本。（BSD Now EP60，[3715.96-3795.84]，L2）
- Theo 为 LibreSSL 重新设置 warrant canary：以项目网站字体是否维持 Comic Sans 作为收到国家安全信函而被禁言的暗示信号，以近乎戏谑的方式延续“未受传票”的公开声明机制；该机制的效力依赖公众对信号缺席的持续关注。（BSD Now EP60，[3801.04-3867.56]，L2）
- DragonFly BSD 1.4 于 2006 年 1 月 7 日发布；主持人补记此前遗漏，并说明该项目由一群围绕 FreeBSD 5 系内核希望作出重大改动的人分叉而来，旨在验证其在多处理性能上的理论，若理论成立则成果可惠及全部 BSD。（BSDTalk EP7，[20.38-79.16]，L2）
- GPL 正酝酿第三版：Richard Stallman 主导的修订拟纳入争议性反 DRM 条款，即 GPLv3 软件不得被改造用于对不自愿用户强制数字版权管理（如 TiVo 式设备限制用户复制与媒介转移的合理使用）。因 BSD 生态大量依赖 GNU 工具、尤其 GCC 编译器（Apple 亦曾长期为 PowerPC 改进 GCC），主持人推演其后果：并非所有软件都会升级到 v3，若 GCC 随 v3 发布可能出现以 v2 末版为基的分叉编译器，商业公司转向 Intel 平台后也可能改用 Intel 编译器；而 BSD 许可证仅有数行、几乎无限制（只要求署名与免于诉讼），GPLv3 的争议或促使商业公司重新审视 BSD 许可证与 BSD 系统，成为 BSD 的转折点。（BSDTalk EP7，[84.90-361.82]，L2）
- 主持人选取五款 BSD live CD 实测：FreeSBIE（FreeBSD 基）、Anonymous（OpenBSD 基）、DragonFly 安装盘（自述兼作 live CD 但极简）、NetBSD 官方 live CD（定位救援盘兼 KDE 桌面）、Newbee（NetBSD 基，主打全功能图形桌面）；测试硬件为 233 MHz/128 MB 旧笔记本、自制 AMD 2600 台式机、仅 USB 外设的 Dell GX280 与新款 Centrino 笔记本 Dell Latitude D610。（BSDTalk EP7，[376.02-517.04]，L1）
- 实测结果：除 Dell GX280 上 NetBSD live CD 不识别 USB 键盘致无法继续外，其余组合均可启动联网；DragonFly 盘仅文本模式、实用价值低但足以验证硬件支持；NetBSD 盘因缺 libqt 而无法启动 KDE，但 X 与轻量窗口管理器可用；Newbee 启动 Fluxbox 或 Blackbox 并预装浏览器邮件聊天工具；FreeSBIE 允许启动时选择轻量或重量级图形界面，基于 FreeBSD 5.3（2004 年 12 月发布），虽技术偏旧仍被主持人评为最佳 BSD live CD 桌面。横向对照：BSD live CD 资源占用普遍不高，但与 Linux 系 live CD 参照物（转写作 Canopix）相比浏览器启动明显偏慢，当事人将差距归因于后者更成熟、优化投入更多。（BSDTalk EP7，[549.84-843.56]，L1）
- 在 i386 架构的三大 BSD 上挂载 USB 闪存盘的一手实测：FreeBSD 6.0 经 UMass 驱动走 SCSI 子系统，将 SanDisk Cruzer Mini 识别为 da0，用 ls /dev/da 加通配符定位后以 mount_msdosfs 挂载其预格式化的 MS-DOS 分区；NetBSD 3.0 识别为 sd0，MS-DOS 分区本例位于 sd0e，挂载命令为 mount_msdos；OpenBSD 3.8 分区位于 sd0i，且 disklabel 须指定整盘 sd0c。不想逐个试错可用 disklabel 查看分区表；NetBSD 与 OpenBSD 因共同祖先更近而彼此更相似。（BSDTalk EP11，[93.00-454.46]，L1）
- FreeNAS（Free Network Attached Storage）定位为轻量定制 FreeBSD 发行版：刻录 CD 引导后快速安装裸 FreeBSD 6.0，并以源自 m0n0wall 项目的 Web 界面管理磁盘挂载、软 RAID、格式化与 Samba、NFS、FTP 共享，亦支持 USB 引导。作者动机是市面上没有免费的 NAS 服务器；其原为 m0n0wall 长期用户且不懂 FreeBSD，因 m0n0wall 开发者指南易读易懂而决定照此做一个存储版。对 BSD 许可证可能被他人拿走而不回馈的顾虑，作者表示毫不在意：项目起初只为自用，用户可任意处置，这样做反而更好。（BSDTalk EP11，[461.60-667.44]，L1）
- 作者选择 FreeBSD 作为 NAS 基座的理由：稳定性高、系统足迹小、安全问题极少，且市面已有大量基于 FreeBSD 的设备，顺势而为。作者的个人环境：主力开发与编译工作站为 FreeBSD，另有一台 Windows 机与一台改造为媒体播放机的 Xbox；FreeNAS 是其编程起点，边做边学 PHP 并借项目认识 FreeBSD。（BSDTalk EP11，[675.50-762.58]，L1）
- 局限与生态观察：FreeBSD 对 NTFS 的支持很差（可读 Linux ext2 但 NTFS 弱）；FreeNAS 当时尚无用户认证，文件对任何能访问者开放，只应部署于可信网络，认证功能在开发中。作者尝试把 FreeBSD 装上日常工作笔记本时认为安装器不够易用——小项目与服务器场景尚可，桌面扩展不行；主持人因此推荐桌面导向、安装器易用的 PC-BSD。节目收尾主持人提醒：当前版本不宜直接暴露于互联网。（BSDTalk EP11，[567.92-948.42]，L1）
- 系统管理员 NJ Thomas 的参会自述最具代表性：作为以 Linux 维生、在个人服务器上使用 BSD 的用户，他几乎每届 NYCBSDCon 必到（仅首届因婚礼缺席），认为这种日场会的收获远超票价——发布最佳实践、新技术，以及 session 之间的“走廊轨道”交流；他今年带来日职的存储工程师现场试用 ZFS on BSD、带来乐于接触新技术的应用开发者，会间大家讨论数据库选型与策略，并向新人推荐 NYCBUG 例会。（BSDTalk EP238，[85.00-161.90]，L1）
- 与会者中可见内容与代码的生产者：DragonFly BSD Digest 的维护者 Justin Sherrill 来会是为了寻找源源不断的可发布素材；天文学家出身的软件开发者 John Vranaleo 自 Linux 背景转入，正在参与并贡献较新的 BSD 衍生项目 BitRig，作为纽约本地人来此与区域内的 BSD 同好相聚。（BSDTalk EP238，[163.32-197.58]，L1）
- 会上自述的商业采用案例：Calyptic Security 的 CEO Ben Yarbrough 称公司以 BSD（主要是 OpenBSD）为核心为小企业提供简化的网络安全产品，来会寻求成长资源；OneCloud Labs 的 Nate Van Voorst 介绍其从 VMware 数据中心向 Amazon 云做灾备的创业项目、客户端以 FreeBSD 为基底，并借会招募新英格兰地区的工程师；软件咨询公司 BitBase 用 BSD 支撑移动应用后端，深耕 ZFS 与 PostgreSQL 以求系统更优。（BSDTalk EP238，[196.42-330.08]，L1）
- 口述样本亦覆盖了光谱的另一端：OpenBSD Project 的 Mike Erdly 专程到会支持美国东海岸的会议；Amplify Education 的系统管理员自称 1998 年起的 FreeBSD 老用户、来此社交；初到纽约、任职 Warby Parker 自动化部门的 David Neudorfer 终生使用 Mac、深谙终端却几乎无 BSD 服务器经验，为 ZFS 与 BSD 网络设备而来；另有康涅狄格的技术顾问首次参加 BSD 活动、九十年代从 Sun 起步的老兵四年来首次回归，以及一位机械工程训练出身、六年前借 FreeBSD 学 Unix 管理的爱好者。（BSDTalk EP238，[365.42-419.44]，L1）
- 一位 Debian 老用户的参会动机集中显示 2014 年初 BSD 对 Linux 用户的吸引点：两场 ZFS 演讲是其最大亮点，Netflix“三分之一互联网流量”的演讲标题对他冲击极大，而关于集成 BSD 设备的演讲让他第一次意识到 Juniper 等大型公司基于 BSD；他此前仅在 OpenIndiana 上为跑通 ZFS 数据共享而短暂使用，损坏过数次数据仍相当满意，并因想要最新版 ZFS 而 Linux 发行版不能原生附带、当时几乎没有别的途径。（BSDTalk EP238，[419.44-500.74]，L1）
- 个人史与结缘路径：二十四岁的德国人，六岁起接触电脑，经 MS-DOS、汇编、Pascal 学至 C、make 与 shell；1997 至 1998 年间转向 Linux，先在无互联网条件下以软盘从学校运回软件包、自建追求小体积的 libc5 系统，并用这套自制系统完成首次拨号上网；随后经书籍认识 FreeBSD、NetBSD 与 OpenBSD，OpenBSD 2.4 初试、2.9 发布前购入即喜欢上，从此弃用 Linux，仅保留 MS-DOS 作直接硬件访问与引导器实验之用。（BSDTalk EP81，[111.76-239.56]，L1）
- MirOS 分叉起源：以 32.6k 调制解调器拉取源码并跟踪 OpenBSD CVS 仓库，较早掌握 CVS；改进尝试以邮件提交后遭遇 flame 与无视——后来得知其他外部投稿者遭遇相同；遂将自建的 OpenBSD patchkit 公开，主页提供 diff 集、生成脚本与二进制；与上游决裂后自建 CVS 仓库、导入 OpenBSD 源码打上补丁继续开发——其时他从未成为 OpenBSD 开发者。（BSDTalk EP81，[255.32-354.02]，L1）
- 项目命名与多内核雄心：项目名从 OpenBSD Current Mirabila、BSD Mirabila 缩为 MirBSD——Mirabilis 拉丁语义兼奇妙与怪异（时人对其昵称），Mir 又取俄语和平与世界之义，自称奇妙而和平世界的操作系统；起初只是其个人源码与 ports 树的昵称，其他开发者加入后（一人至今活跃）因计划向用户提供多内核选择——BSD 内核或带专有驱动的 Linux 内核（其本人从未使用）——改称 MirOS 项目，定位为同一 BSD 观感的基础操作系统。（BSDTalk EP81，[356.26-426.12]，L1）
- 与 OpenBSD 的差异自述：自视为更好的 OpenBSD、时而偏向 NetBSD 方向；精简取向——移除受众用不到的 Kerberos、全量按体积优化编译使启动软盘容纳更多内容；外部工具更新更勤（新工具链、文本浏览器、ncurses 自 5.2 升 5.5 并加 Unicode）；移植框架独立演进——起于 OpenBSD ports，在 Marc Espie 转用 Perl 重写时不跟进，自行按可移植性方向改进，框架亦可运行于其他操作系统；更早转向 ELF；base 系统弃 groff 改用 4.4BSD alpha 的 AT&T nroff，且不残留任何 C++ 代码。（BSDTalk EP81，[444.12-553.80]，L1）
- 平台版图与 SMP 拒绝：现支持 i386，两版前因友人捐赠的机器支持过 SPARC，复活计划因 i386 负担搁置；AMD64 因听闻 NetBSD 与 OpenBSD 实现欠稳而宁守两个稳定平台；对 SMP 明确说不——合并 OpenBSD 4.0 增强时代码会包含但禁用，理由是其实现方式不对、BSD 内核结构不适宜多处理、单处理器内核有时反而更快；项目没有内核程序员，未来数年不拟支持 SMP，优先工作是把 wscons 控制台代码转为 Unicode。（BSDTalk EP81，[553.80-663.48]，L1）
- 发布与兼容策略：稳定版 MirOS 9 以十进制编号；开发快照经 BitTorrent 分发、上传前必经测试保证可引导可安装，CVS head 则不保证可构建——提交有时仅为异地备份；安装器继承自 OpenBSD；以库版本号递升保障旧程序——系统上可同时共存三四个大版本 C 库，数月前编译的 MPlayer 依然可运行；提供 OpenBSD 二进制兼容层，几乎可运行任何 OpenBSD 3.8 程序，因内核偏离远小于系统其余部分而实现容易。（BSDTalk EP81，[663.48-771.28]，L1）
- Unicode 的 Plan 9 路线：明确不走完整国际化路线并直陈不相信它，而取 Plan 9 式终局——最终只保留 UTF-8 与标准要求的七位 C locale；已实现 libc 宽字符所需部分、升级 ncurses 使既有应用可显示宽字符（中文昵称的 MSN 联系人可正常显示）、shell 将 UTF-8 字符按单字符处理。（BSDTalk EP81，[1010.16-1066.12]，L1）
- FreeWRT 协作与跨平台构建：协助友人 Waldemar Brodkopf 自 OpenWRT 分叉的 FreeWRT——面向 Netgear 等无线路由器的嵌入式 GNU/Linux——承担交叉编译、工具链、构建系统与 diff 审读；OpenWRT 原本只能在 Linux 上自行编译，经其工作可在 BSD 上构建，并计划扩展 Cygwin 与 Mac OS X 可编译性。（BSDTalk EP81，[826.60-891.20]，L1）
- 团队结构与欧洲展会网络：Benny Siegert——萨尔州化学专业学生、非 IT 背景——承担 ports 基础设施，所继承自 OpenBSD、NetBSD 再上溯 FreeBSD 的老程序（一个 C 文件内并存三种缩进风格）被持续改进，另负责全部 GNOME 及因商标原因重命名的当前 Firefox 移植；两人把 FOSDEM、FrOSCon、Chaos Communication Congress、LinuxTag 当作迷你 hackathon；首届 FrOSCon 上曾携咖啡机为 BSD 摊位提供免费咖啡；近期移植支持网络对战的 Frozen Bubble 2，其框架同时可运行于 Mac OS X 与 OpenBSD。（BSDTalk EP81，[895.20-992.52]，L1）
- 受访者讲述 BSD Nexus 的社区媒体演化：网站最初为其学习网络与建站的玩票之所，以壁纸起家——经原作者 Andre 同意转载其 OpenBSD 壁纸后逐步累积至近百张，链接先后出现在 OpenBSD 邮件列表与 NetBSD 网站上。论坛由友人托管，缘起是一批 BSD forums 的重度用户对原论坛政策变更的不满（并非否定其聚拢社区的功劳），遂经在线商议另立无广告、不限制 BSD 语境下观点表达的 forums.bsdnexus；how-to 与问答的持续积累使其成长为来源远超预期的社区。（BSDTalk EP91，[105.08-253.32]，L1）
- 受访者自 2005 年 1 月起学习 C 语言，以真实目标驱动学习：WPOP3D 为其自设的 POP3 daemon 目标，兼学邮件机制、C 语言与 UNIX 的结合；WMPDF 源于工作中处理 PDF 的需求而写成简单 C PDF 库，借机理解 C 库的存储、调用与链接；Ratsina 是 Squid 的重定向器，自其重度使用的 SquidGuard 分出——差异在于以后端数据库（MySQL 或 PostgreSQL）承载规则，并支持约束继承：工作时间槽内可嵌套午休子槽、自动继承并允许覆写访问约束，该设计想法来自友人 Max Law。Ratsina 即将发布 1.0，其公司亦愿意采用。（BSDTalk EP91，[253.32-444.86]，L1）
