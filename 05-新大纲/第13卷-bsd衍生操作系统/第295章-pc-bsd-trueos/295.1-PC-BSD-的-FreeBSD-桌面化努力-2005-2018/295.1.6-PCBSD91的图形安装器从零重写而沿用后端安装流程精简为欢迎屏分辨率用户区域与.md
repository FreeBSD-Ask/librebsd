# 295.1.6 PCBSD91的图形安装器从零重写而沿用后端安装流程精简为欢迎屏分辨率用户区域与

- PC-BSD 9.1 的图形安装器从零重写而沿用后端：安装流程精简为欢迎屏、分辨率、用户、区域与无线网络设置，不再询问根口令等旧式步骤；每次安装自动保存配置文件，使同一配置可反复批量部署系统。文本模式安装仍保留，且瘦客户端脚本可将装好的桌面系统变为 PXE 启动主服务器，计划加入 PXE 网络安装钩子。（BSDTalk EP216，[117.86-252.16]，L1）
- Warden 监狱管理工具原为可单独安装的 PBI 产品，9.1 起整合为默认预装的系统组件，桌面端提供图形界面、服务器端仅命令行；新增向监狱内安装软件包的能力并预置 Apache、MySQL、ownCloud、WordPress 等元包集合，系统管理器与用户管理器改造为监狱感知。配合 ZFS 时每个监狱自动获得专属 zvol，可对监狱做快照与回滚。（BSDTalk EP216，[584.46-689.1]，L1）
- PBI 软件包格式在 PC-BSD 之外获得采纳：pfSense 将其并入产品，FreeNAS 以之为插件架构基础，受访者持续收到外部改进补丁并乐于接受；AppCafe 从网页转为市场式本地应用，另有开发者编写 EasyPBI 图形前端从既有 port 一键生成 PBI。格式本身可移植，受访者预期其可能出现在其他 BSD 上。（BSDTalk EP216，[496.94-569.78]，L1）
- 桌面体验受制于图形驱动：约两万行的 Intel KMS 与 GEM 支持补丁当时等待进入 FreeBSD head 后 MFC 至 9.1，届时 Sandy Bridge 等新硬件的 3D 加速方能恢复，对低端笔记本尤为关键。系统硬件要求反而随时间下降，256MB 内存配 LXDE 即可得可用桌面；受访者希望尽快退役 32 位支持以全面推广 ZFS 的 64 位特性，但短期内仍须维持 i386。（BSDTalk EP216，[358.34-495.94]，L1）
- Moore 口述 PC-BSD 发布模式在 2013 年分裂为双轨：延续传统的 9.1、9.2 稳定版，间隔约 12 至 13 个月，适合安装后不再折腾的用户；另增设基于 9-stable 的滚动发布，提供每周更新的 pkgng 仓库并每月推送 world 与 kernel，待 10-stable 成熟后再整体迁移，以弥合 FreeBSD 长发布周期造成的空窗。（BSDTalk EP225，[126.46-185.88]，L1）
- 滚动发布的底层设施是借用与自建的混合：PC-BSD 采用 Colin Percival 的 freebsd-update 工具自建更新服务器，自行决定纳入哪些补丁与哪个 stable 分支；iXsystems 提供硬件，运行 Poudriere 构建自有 pkgng 仓库。Moore 明言此举是与 FreeBSD 项目略微分离，以自主控制推送频率。 [存疑脚注] 转写将 freebsd-update 的作者记作 Collins、构建工具记作 Podrie，按语境应为 Colin Percival 与 Poudriere，须以原始音频复核。（BSDTalk EP225，[192.78-224.86]，L1）
- PC-BSD 桌面无关化后的分发架构是 pkgng 与 PBI 双体系并行：不再构建多套桌面镜像，而是单一镜像加按桌面环境划分的 pkgng 包集，用户可在线调整；PBI 体系即 AppCafe，定位如应用商店，应用自带全部依赖，仅在 9.0 上构建即因 ABI 兼容覆盖整个 9 系列，完全不受滚动发布影响，其内容本质是 FreeBSD ports 的 PBI 重打包。（BSDTalk EP225，[258.02-376.52]，L1）
- 安装器正在把用户推向 ZFS：Moore 希望彻底将 UFS 移出安装器，除老式 32 位且内存不足 1GB 的机器外皆引导使用 ZFS，其理由是 boot environments——更新前快照、失败即回滚——是滚动发布的安全网；他自述 8 系列 ZFS 内存表现粗糙，9 系列在 1GB 内存的 Intel Atom 上桌面使用已无碍。配套地，PC-BSD 重写了网络管理器与挂载工具并逐步摆脱 HAL，因为桌面文件管理器多为 Linux 开发、并不利用 ZFS 快照；Warden 借 ZFS 实现秒级 jail 克隆与快照，Life Preserver 备份工具计划将快照复制到 FreeNAS 或 TrueOS 实现异地保全。（BSDTalk EP225，[429.62-593.14]，L1）
- Brian Tiemann 的写作路径带有强烈的偶然性：《FreeBSD Unleashed》2001 年出第一版，前两版与 Michael Urban 合著——Urban 本已签约写书，发现工作量超出单人极限，恰好是 Tiemann 所运营 FreeBSD 系统的用户，便直接邀请管理员合写；此版为独著的第三版，目标覆盖 FreeBSD 6.0，预计三月完成作者审阅、五月上架，将是市场最早覆盖 6.0 的书之一；其出版线为 SAMS 的 Unleashed 系列，作者另参与 In a Snap 与 How to Do Everything With 两个系列。（BSDTalk EP19，[42.84-75.27]，L1）
- 他与 FreeBSD 的结缘始于 1994 年进入加州理工学院：校园学生网清一色 Unix 且以 Sun 机器为主，此前只有早期 Windows 与 DOS 经验的朋友把他引向命令行、Pine 邮件与新闻组；当时 FreeBSD 2.2.1 为最新版，因常被称道为高性能 web 服务器平台而入眼——Apache 项目以 FreeBSD 为中心、性能模块参数主要按 FreeBSD 列写，Yahoo 与 Walnut Creek CDROM 在单一 web 服务器时代都以 FreeBSD 商店自豪；他为自己的迪士尼《狮子王》粉丝站 lionking.org 选服务器时，Linux 尚未满 1.0，FreeBSD 好玩的软盘安装流程让他一试成主顾，该站此后十年兼营用户站点、邮件与 PHP 托管；学生集群的集中磁盘与终端接入体验甚至一度让他怀疑单机桌面 PC 的存在意义，工作数年后才理解计算用途因人而异。（BSDTalk EP19，[252.33-554.47]，L1）
- 十年服务器运维见证了安装范式的两次变化：早期安装 FreeBSD 须通过可视化硬件配置器逐项指定 ISA 设备的中断与内存地址，PCI 普及后该流程几乎消失，安装工作量缩减至从前的四分之一并成为单一流程；其托管商现已把 FreeBSD 与三个 Linux 及若干 Windows 并列为磁盘镜像默认安装选项但不含支持；升级方法论上，他只信任 5.4 到 6.0 的二进制升级脚本，认为 4 到 5 的跨越远超脚本可覆盖的配置组织方式，而 5.0 引入的 etc rc.d 目录以标准化脚本统一服务的启停重启；他把最佳升级法总结为备份数据后全量重装，理由是 FreeBSD 把本地软件与配置集中 compartmental 化，使迁移可以绕过配置合并，而车库家用服务器因可承受风险，走同步源码加 make world 的路线。（BSDTalk EP19，[575.31-871.97]，L1）
- 桌面选择上他白日使用 Mac 已约六年：享受 Mac OS X 自发布以来的演进体验，部分原因是其 FreeBSD 基座保留了熟悉的工具、本质是壳下的 Unix；他提及 Eric Levenez 的横向 Unix 历史谱系图（可打印约十六页拼接为墙幅、数月一更）并称 FreeBSD 与 Mac OS X 多年互相滋养是迷人课题，但他用 Mac 的根本理由是用户体验——Apple 是唯一把大量专门努力投入用户界面目标的公司，老手习以为常的邮件与网页小习惯对普通用户是折磨，整个计算业的用户体验远未达到汽车业的成熟度。（BSDTalk EP19，[877.00-1099.57]，L1）
- 为写书重返 BSD 桌面令他惊喜：KDE 进步显著并已有关键链管理器这类他依赖的功能；写作过程中发现刚从 FreeBSD 分出的 PC-BSD——以 KDE 为基座、追求与任何桌面系统同级的透明安装与易用、配备图形化包管理；对照九十年代中期他在慢机器上追捧 Enlightenment 伪透明效果的经历，如今 KDE、窗口管理器与 X11 内置合成功能令他鼓舞——合成不是为好看的怪癖而是真正的功能，Mac 的窗口缩小动效之所以能指示窗口去向，正依赖 Quartz 合成层，同类技术进入 X11 与 GNOME、KDE 各自的界面准则，意味着 Unix 端真正的用户应用有了可期的未来；他也确认 FreeBSD 团队的服务器专注无人否认，图形界面责任多在核心系统之外。（BSDTalk EP19，[1110.35-1351.87]，L1）
- 其日职所在公司制造带宽管理设备，实验室须在各种拓扑间做高强度流量互抛测试，结论是 FreeBSD 在灵活与稳定之间给出最佳平衡：对内核做正确调校后，其 TCP/IP 栈所能压榨出的高端速度超过同级的 Linux 与其他 Unix 机器。（BSDTalk EP19，[366.35-403.41]，L1）
- Lumina 的创建动机是多年桌面使用挫折的积累：主流桌面环境几乎全部在 Linux 上为 Linux 而写，移植到 BSD 后以莫名方式损坏，Moore 追踪后几乎总将故障归结为渗入移植流程的 Linux-ism；加之 KDE、GNOME 等上游随时可能深度依赖 systemd 等 BSD 缺失的组件，他决意从零编写一个专为 BSD 家族、BSD 许可、稳定可靠的桌面环境，免除对 Linux 系统机制的依赖。（BSDTalk EP244，[379.14-464.76]，L1）
- Lumina 的组件结构自下而上分为三层：Qt4 图形工具链提供跨平台一致的绘制能力；后端窗口管理器选用 Fluxbox，理由是其 MIT 许可证与 BSD 授权家族相近，保持同类后端；桌面环境本身则是窗口管理器之上的统筹层，负责任务栏、遵循 freedesktop.org 标准的应用注册与文件关联、以及统一主题外观，将各离散部件粘合为一致的用户体验。（BSDTalk EP244，[126.46-325.50]，L1）
- Lumina 贯彻只做统筹不造应用的极简哲学：本体仅含启动二进制、文件启动器、文件管理器与 lumina-config 四件，拒绝为覆盖全部用途编写二流工具，宁可让用户自行安装第三方软件也不附赠劣质应用；文件管理器核心只依赖 Qt 与 phonon，Samba 网络浏览与 ZFS 快照恢复皆为运行时可选探测——后者源于 PC-BSD 的实际需求，且因主流文件管理器皆为 Linux 而写、彼时 Linux 缺乏良好 ZFS 支持而无先例；整套环境不使用 HAL 与 systemd，实机内存占用约一百至一百五十兆字节。（BSDTalk EP244，[553.56-886.24]，L1）
- Moore 的个人路径始于被迫而非志向：大学必修编程课引发兴趣，本科与研究生之间在空军理工学院实习继续编程，研究生阶段又因导师项目分工而承担全部编码；读研期间其兄 Kris Moore（PC-BSD 创始人）邀其兼职维护 PBI 文件与测试应用，毕业后 iXsystems 全职雇用并迁居田纳西，Lumina 则是其数年间失眠夜晚的业余项目（部分源文件版权标记为 2012），成熟至可用状态后并入 PC-BSD 仓库并纳入其日常工作。 [存疑脚注] PC-BSD 创始人姓名转写音为 Chris Moore，据通行记载应为 Kris Moore（BSDTalk EP244，[1197.04-1335.76]，L1）
- 该期以喜剧框架汇总 2017 年 2 月 BSD 生态动态：NetBSD 7.1 首个候选版本于 1 月发布、自 7.0 以来变更众多（完整变更清单见官网）；OpenBSD 布里斯班 hackathon 收官，各开发者报告集中发布于 Undeadly.org，活动由 OpenBSD Foundation 资助并获 David Gwynne 支持；DragonFly 安装器新增尚属基础的 UEFI 支持（仅限全盘、不支持 secure boot），vkernel 虚拟内核架构持续改动。（BSDTalk EP266，[63.46-143.54]，L2）
- FreeBSD Foundation 发布 2017 年首份项目进展更新，项目开发总监 Ed Maste 概述基金会识别、评审并遴选项目的机制，项目由受薪开发人员与资助接受者共同承担——为基金会从志愿者模式转向职业化资助运作提供时点佐证。（BSDTalk EP266，[80.16-108.46]，L2）
- Lumina 桌面环境 1.2 发布：BSD 许可的轻量级桌面环境，明确不使用 consolekit、policykit、dbus、systemd 等 Linux 系桌面框架；其为 FreeBSD 系 TrueOS 而开发，同时打包给多种 BSD 乃至 Linux，体现 BSD 桌面对 Linux 用户态栈的刻意疏离。（BSDTalk EP266，[143.54-173.96]，L2）
- 虚构框架本身构成 BSDTalk 的停播史料：上期节目后中断逾六个月，社区与播客客户端传言主持人“内核恐慌”或“转投 systemd”；主持人 Will Backman 在“节点”电话采访中承认节目半途搁置、约访难以安排，承诺当年参加 BSDCan 补充访谈素材，并点名 BSD Now 等其他 BSD 播客在持续填补内容空缺。（BSDTalk EP266，[203.96-360.96]，L1）
- PC-BSD 于 2006 年 5 月发布 1.0，项目启动逾一年；Moore 将其定义性特征归纳为图形安装器、KDE 3.5.2 桌面环境与 PBI 软件包体系三者，并明确定位为基于 FreeBSD 的桌面操作系统而非分叉——不改 FreeBSD 默认系统，系统管理员与高级用户可无损使用 ports 与 packages，PBI 与之完全并行。（BSDTalk EP40，[403.02-446.20]，L1）
- PBI 以 QT 编写，模仿 Windows 下 InstallShield 式自解压自安装体验：每个包自带全部运行库、装入独立目录，从而消除不同库依赖软件互装互卸时的冲突；其代价是包体积因重复捆绑库而增大，Moore 判断对最终用户而言可用性优先于若干兆字节的磁盘开销。（BSDTalk EP40，[188.50-241.02]，L1）
- Moore 自述十六岁（约十年前）进入 ISP 行业，FreeBSD 承载互联网托管是其最初接触；此后工作辗转 Linux 却始终回归 FreeBSD，理由是 ports 与系统整体布局更连贯、各部件咬合更好，而其体感是 Linux 生态中大量工具与工具之间并非为彼此协作而设计，呈碎片化状态。（BSDTalk EP40，[893.10-931.50]，L1）
- PBI 立项动因出自 Moore 对普通用户的观察：初学者在 Linux 与 Unix 桌面上无法自行安装软件，即便借助易用的图形包管理器，卸载或变更软件时也会触发库依赖问题乃至破坏系统；故选择 95% 用户熟悉的自解压自安装文件作为突破口。（BSDTalk EP40，[931.50-967.10]，L1）
- 商业模式上 Moore 参照 Red Hat 与 SUSE 以企业服务求生的路径，拟通过在线商店与付费电话、邮件支持使 PC-BSD 自给自足，进而雇佣全职开发者、投入营销与 Apple 及 Microsoft 竞争；同时明确承诺不闭源、不对下载收费。（BSDTalk EP40，[565.36-617.12]，L1）
- 产品定位与公司策略：Virtual Bridges 长期为 Unix 与 Linux 平台提供平台迁移与共存能力，观察到 BSD 虽市场体量小但网站活跃度与社区热情极高、且有一批以 BSD 为服务器农场与基础设施的企业用户，遂将既有 Win4Lin 技术引入这一自认未被充分服务的市场；Win4BSD 与 Win4Lin 同代码库、功能对等，实为下一代 Win4Lin，且因架构可移植而比 Linux 版本更早落地。（BSDTalk EP75，[271.24-307.96]，L1）
- 技术架构与混合源策略：产品集成 QEMU 与 KQEMU 开源组件及自有增值层，对用户呈现为单一无缝套件；安装不修改内核——使用运行时加载驱动动态载入，无需重启；产品整体闭源，但与 QEMU 直接相关的部分以开源补丁形式回馈社区、部分已合入主线，且随产品包一并发售，用户无需另行索取。（BSDTalk EP75，[446.94-526.24]，L1）
- 与传统虚拟化软件的差异化在于卖集成而非卖虚拟机：产品不面向需要并发多系统的技术专业者，而面向想留在偏好环境中无缝使用 Windows 应用的一般用户——Windows 被做成 BSD 环境中的无缝访客；默认安装模式下 My Documents 等文档目录直接存放在 BSD 文件系统的家目录中，Windows 系统镜像受宿主的原生权限与安全机制控制。（BSDTalk EP75，[713.02-806.00]，L1）
- 兼容性边界：支持 Windows 2000（SP3 因在原生硬件上亦有故障而除外）与 XP Home、Pro 至 SP2；不含 Windows 许可证，卖点是运行用户已有 Windows 授权的能力；除重度 3D 第一人称游戏外，个人生产力、商业、财会乃至流媒体多媒体应用均可运行；依据 Win4Win 的数据支持几乎各语言版本的 Windows 与约 24 种键盘布局，覆盖欧洲、亚洲与拉丁美洲。（BSDTalk EP75，[526.24-635.42]，L1）
