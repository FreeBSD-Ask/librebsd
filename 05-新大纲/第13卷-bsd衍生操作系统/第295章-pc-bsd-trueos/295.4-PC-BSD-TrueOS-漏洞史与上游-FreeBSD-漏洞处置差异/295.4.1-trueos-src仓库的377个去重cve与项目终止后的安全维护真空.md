# 295.4.1 trueos-src 仓库的 377 个去重 CVE 与项目终止后的安全维护真空

  - 要点：bsd_commits.duckdb 查询显示 trueos-src 仓库共 273 条 CVE 相关 commit、377 个去重 CVE，commit 数（273）低于去重 CVE 数（377），表明 TrueOS 存在单次 commit 合并多个 CVE 修复的批量化安全维护模式；trueos-src 的 CVE commit 跨越 2005 至 2020 年，2020 年后无新增 CVE commit，与 Project Trident 2020 年转向 Void Linux、TrueOS 项目终止的时间点吻合；merge commit 比例从 2006 年 0.8%（87/11,119）上升至 2020 年 5.2%（8/154），2020 年 commit 量骤降至 154 且 merge 比例升至 5.2%——本地 commit 量下降但上游同步 commit 占比相对上升，反映项目终止前夕仅维持最低限度的上游安全同步
  - **trueos-src 仓库 CVE 与 merge 比例演变表**：

| 年份 | total_commits | merge_commits | merge 比例 | 阶段 |

- 史观：终结中的延续，TrueOS 项目的终止不仅标志桌面 BSD 实验的落幕，也意味着 377 个已跟踪 CVE 的安全维护责任转移至上游 FreeBSD 与用户自身，fork 项目终止后的安全维护真空是 BSD 衍生生态的结构性风险
- 辨析：trueos-src 的 273 条 CVE commit 与 377 个去重 CVE 的数量差异（commit 数 < CVE 数）表明部分 commit 引用多个 CVE 编号，此批量化模式须以具体 commit message 核实，不得仅凭数量差异推断安全维护质量；2020 年后无新增 CVE commit 可能有多种原因——项目终止、仓库归档、镜像同步停止——须与 Project Trident 公告、iXsystems 商业战略说明交叉验证；TrueOS 终止后其用户基础是否迁移至 GhostBSD 或其他 BSD 桌面须以社区调查为准
