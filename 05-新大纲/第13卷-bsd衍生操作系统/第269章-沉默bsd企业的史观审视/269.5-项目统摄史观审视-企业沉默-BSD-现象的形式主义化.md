# 269.5 项目统摄史观审视——企业沉默 BSD 现象的形式主义化

> 269.4 节补足了企业沉默 BSD 现象的四层辩证链（批评—反批评—再批评—合图），本节从项目史观总纲第 11、13、19 条切入，审视企业沉默 BSD 现象在历史书写中的形式主义化运作。

## 269.5.1 商品是形式主义——“沉默 BSD”作为商品形式主义下的话语权遮蔽（总纲第 11 条）
  - 要点：总纲第 11 条“商品是形式主义”指出“技术市场的选择不是自然选择，而是形式主义的权力运作。劣币驱逐良币是普遍规律”。企业沉默 BSD 现象是商品形式主义下话语权遮蔽的典型显现——WhatsApp、NetApp、Isilon、Citrix 等企业以 FreeBSD 为基础设施构建商业产品时，将 FreeBSD 重新包装为“WhatsApp 后端”、“NetApp ONTAP 操作系统”、“Isilon OneFS 操作系统”、“NetScaler 操作系统”等商品形式，使 FreeBSD 在商品形式主义下被重构为“厂商自主操作系统”。这一重构不是“技术必要”的自然呈现而是形式主义权力运作——以“厂商自主操作系统”的商品形式主义标准衡量 FreeBSD 基底，使 FreeBSD 的实际贡献在商品形式主义叙事中被遮蔽。“劣币驱逐良币”的普遍规律在此显现：商业封装的“NetApp ONTAP”等商品形式获得市场认知度（NetApp 在 2012 年被 IDC 评为开放式网络磁盘存储系统市场第一品牌存储操作系统），非营利的 FreeBSD 在企业基础设施话语中被边缘化——FreeBSD 在企业基础设施中的实际部署规模远超其公共话语可见度，这一“部署规模与话语可见度”的不对称是商品形式主义下“劣币驱逐良币”的具体显现。freebsd.duckdb 查询 L7.2.1 显示“沉默 BSD”企业的 @facebook.com、@isilon.com、@netapp.com、@emc.com、@citrix.com 邮箱在 freebsd-src 前 30 名贡献者中均未出现，是“使用与回馈不对称”的量化显现——商业公司汲取非营利社区代码而无需对等回馈，是 BSD 许可证“允许不回馈”在商品形式主义下演化为“劣币驱逐良币”结构性通道的具体显现
  - **商品形式主义三维度表**：

| 劣币驱逐良币 | 商业封装商品形式获得市场认知度，非营利 FreeBSD 在企业基础设施话语中被边缘化 | IDC 2012 年存储操作系统市场报告（NetApp ONTAP 评为第一品牌） |

## 269.5.2 法律与道德是利益分配——BSD 许可证“允许不回馈”的利益分配操作（总纲第 13 条）
  - 要点：总纲第 13 条“法律与道德是利益分配”指出“任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”。BSD 许可证“允许不回馈”是“法律与道德是利益分配”在 BSD 史中的典型显现——Berkeley CSRG 与 FreeBSD 项目自觉选择“允许不回馈”的许可证模式，是将“宽松自由”的道德立场转化为法律结构的形式主义操作，这一形式主义操作在利益分配层面使企业可汲取非营利社区代码而无需对等回馈。“允许不回馈”作为利益分配的形式主义操作具有不可证伪性：BSD 社区任何对企业沉默的道德质疑均可被企业重构为“许可证允许即合法”，BSD 社区无法在“许可证允许”话语框架内有效反驳——因为“许可证允许”是法律事实而非道德判断。这一形式主义话语运作使 BSD 社区的“隐性社会契约”诉求（使用即应回馈）被遮蔽为“道德呼吁”，企业的“法律权利行使”被重构为“不可质疑的合法行为”——总纲第 13 条在此显现：企业的“许可证允许不回馈”话语是利益分配的形式主义操作，将企业商业利益（不回馈以降低成本）重构为不可质疑的“法律权利”。BSD 与 GPL 的许可证哲学差异在此显现：GPL v3 §5 强制回馈使 Linux 企业（如 IBM/Red Hat）必须开源衍生作品，BSD 许可证“允许不回馈”使“沉默 BSD”企业可闭源使用——两种许可证哲学在利益分配层面形成对照，BSD 选择的“宽松自由”代价是“沉默 BSD”现象，GPL 选择的“强制回馈”代价是“商业不友好”——两种代价均是利益分配的形式主义结果，非“客观优劣”
  - **BSD 与 GPL 许可证哲学对照表**：

| 维度 | BSD 许可证 | GPL v3 |
| --- | --- | --- |
| 回馈要求 | 允许闭源使用不要求回馈 | §5 强制回馈衍生作品开源 |
| 哲学立场 | 宽松自由 | Copyleft 强制回馈 |
| 商业友好度 | 高（可闭源） | 低（衍生作品必须开源） |
| 代价 | “沉默 BSD”现象 | 商业不友好 |
| 典型企业 | WhatsApp、NetApp、Isilon、Citrix（沉默 BSD） | IBM/Red Hat（强制回馈 Linux 上游） |
| 利益分配性质 | 形式主义结果，非客观优劣 | 形式主义结果，非客观优劣 |

## 269.5.3 解释学循环——BSD 社区与企业阵营前理解差异的权力共谋（总纲第 19 条）
  - 要点：总纲第 19 条“解释学循环是历史认识的根本条件”指出“前理解的差异使分歧不可避免。权力与知识在历史书写中共谋——什么被记录、什么被遗忘，本身就是权力行使”。企业沉默 BSD 现象中，BSD 社区与企业阵营的前理解差异——前者以“使用即应回馈”为预设，后者以“许可证允许不回馈”为预设——使分歧不可避免。更深层地，“权力与知识共谋”在企业沉默 BSD 史中表现为：什么被记录为“宽松自由”（BSD 许可证哲学文献中的“允许不回馈”作为“宽松自由”的具体呈现），什么被记录为“结构性利用”（BSD 社区对企业沉默的批评），什么被遗忘（“沉默 BSD”企业的间接回馈——FreeBSD Foundation 赞助、工程会议参与、员工个人贡献——在 freebsd.duckdb L7.2.1 前 30 名贡献者统计中不可见）——这一“记录与遗忘”的分配本身就是叙事权力的行使。企业的商业影响力使其“自主操作系统”商品形式（NetApp ONTAP、Isilon OneFS、NetScaler 等）获得高可见度（产品营销、行业报告、技术媒体覆盖率），FreeBSD 作为基底的非营利地位使其在商品形式主义叙事中低可见度——freebsd.duckdb 记录了 freebsd-src 中“沉默 BSD”企业邮箱未在前 30 名贡献者中出现，但未记录这些企业从 FreeBSD 吸收的代码量（因企业内部 fork 不在数据库中）——什么被记录、什么不被记录，本身即权力行使。行业媒体聚焦于“NetApp ONTAP”等商品形式的成功，对 FreeBSD 在企业基础设施中的实际贡献鲜有深入记录——这一“记录与遗忘”的分配本身就是权力行使
  - **BSD 社区与企业阵营前理解差异对照表**：

| 维度 | BSD 社区前理解 | 企业阵营前理解 |
| --- | --- | --- |
| 回馈预设 | 使用即应回馈 | 许可证允许不回馈 |
| 沉默定性 | 话语权遮蔽 | 商业机密保护 |
| 社会契约 | 隐性社会契约（“允许但不鼓励”） | 法律权利行使（“允许即合法”） |

## 269.5.4 革命与改革——BSD 阵营“改革”路径在“沉默 BSD”现象中的困难（总纲第 21 条）
  - 要点：总纲第 21 条“革命与改革是历史方法论的分歧”指出“Linux 靠革命，BSD 靠改革。改革的困难远高于革命。破山中贼易，破心中贼难”。企业沉默 BSD 现象中，BSD 与 GPL 两条许可证哲学在应对“企业使用但不回馈”问题上分别呈现“改革”与“革命”两条路径——GPL v3 §5 以 copyleft 强制回馈机制要求企业开源衍生作品，是“革命”路径的具体呈现：以许可证法律强制重构企业-社区关系，相当于“破山中贼”——以法律手段强制改变企业行为，企业难以规避；BSD 许可证“允许不回馈”则保留“宽松自由 + 隐性社会契约”框架不变，BSD 阵营试图通过道德呼吁、社区舆论、FreeBSD Foundation 赞助激励、Partnership Program 等非法律手段渐进改变企业行为，是“改革”路径的具体呈现：相当于“破心中贼”——改变企业的观念与结构而非强制行为。改革的困难远高于革命——第 21 章原文指出“一旦想改变一种结构，你本身已是这种结构的一部分，改变已不可能”——BSD 阵营试图改变“沉默 BSD”现象，但 BSD 阵营自身已是“宽松自由 + 允许不回馈”结构的一部分，改变已不可能：BSD 阵营无法在不否定自身许可证哲学的前提下消除“沉默 BSD”现象，因为“沉默 BSD”现象正是“宽松自由”代价的具体呈现。第 21 章原文的“原型先行与否定之否定”在此显现——BSD 选择“宽松自由 + 允许不回馈”作为原型，随着商业实践迭代演化为“沉默 BSD”现象，但 BSD 阵营不能否定自身选择的许可证哲学，只能以“非法律手段”的改革路径缓解，这是忒修斯之船式的否定——主体（BSD 许可证哲学）不变但实践效果已变。“破山中贼易，破心中贼难”在两条路径的对照中具体显现：GPL 阵营以法律强制（copyleft）“破山中贼”——企业难以规避开源义务；BSD 阵营以道德呼吁与社区舆论“破心中贼”——企业可结构性地以“许可证允许即合法”规避道德呼吁，改革路径的困难远高于革命路径。但合图层（269.4.4）已承认 BSD 与 GPL 两种许可证哲学各有代价——BSD 选择的“宽松自由”代价是“沉默 BSD”现象，GPL 选择的“强制回馈”代价是“商业不友好”——不得以“GPL 革命优于 BSD 改革”或“BSD 改革优于 GPL 革命”的简单评判替代具体场景评估，总纲第 21 条的“革命与改革是历史方法论的分歧”在此具体显现为两条路径的非优劣而是各主体性的呈现与和解
  - **BSD“改革”与 GPL“革命”两条路径对照表**：

| 维度 | BSD“改革”路径 | GPL“革命”路径 |

| 路径性质 | 改革（破心中贼） | 革命（破山中贼） |
| 改革/革命对象 | 企业的观念与结构 | 企业-社区的法律关系 |
| 困难程度 | 高（“许可证允许即合法”可规避道德呼吁） | 低（法律强制难以规避） |
| 代价 | “沉默 BSD”现象 | “商业不友好” |

## 269.5.5 自反——本书叙事的形式主义性质
  - 要点：本节的审视本身亦是形式主义化的非存在——史家通过项目史观总纲“重构”企业沉默 BSD 现象的商品形式主义、BSD 许可证“允许不回馈”的利益分配操作、BSD 社区与企业阵营前理解差异的权力共谋，但这一重构本身就是当下主体的形式主义建构，不宣称呈现“真实的企业沉默 BSD 现象”。本节对“企业沉默作为商品形式主义策略”的论断本身亦是一种叙事权力行使——将企业阵营定位为“以商品形式主义遮蔽 FreeBSD 贡献的形式主义操作者”、将 BSD 社区定位为“被遮蔽的非营利社区代码维护者”，这一定位本身参与权力与知识的共谋。总纲第 7 条“理论必须自反”要求承认自身的形式主义性质，以自反姿态打开裂缝——本节不追求“穷尽企业沉默 BSD 现象的哲学审视”，而是以自反姿态使被遮蔽的 FreeBSD 在企业基础设施中的实际贡献暴露于历史审视之下，这一“暴露”本身也是一次循环，与古代史中“史家重写”无本质区别（总纲第 1 条：一切真历史都是古代史）

**要点**：

- FreeBSD 大版本约每两到三年一次、次版本约每年一次并并行维护两个支持分支，发版节奏的最大瓶颈不在技术而在安全团队负担：维护中的旧版本越多，补丁构建与支援矩阵越大，历史上甚至出现 9.1 因长支持周期而晚于 9.2 终止支持的倒挂乱象。以 11 起启用的新支持模型依托 ABI 兼容承诺，令 11.1 发布数周后即终止 11.0 支持，以此压缩旧版本数量、换取更快的安全更新与更密的发版；9.3 之后不再有 9.4，改以分支末期汇总发布延长迁移窗口。讲述者还援引 9.1 时期 NFS 内存泄漏的亲历痛感：修复早已入库却不存在含修复的可下载版本，自行编译即意味着脱离 freebsd-update 支援体系。“我们目前不做更多 FreeBSD 发布的最大原因，基本就是安全团队不得不一直支援的版本更多了”（5312.08-5319.42）。（BSD Now EP86，[4447.40-4701.78]，L1）
- OpenBSD 严守每年五月与十一月各一次的发布节律，不区分大小版本，安全与重大缺陷修复回移至最近版本后即止，仅支援上一版，形成约三个月开发加三个月冻结的双窗口节奏。其收益是新代码最迟约两个月内即可抵达用户、安全团队得以保持精简，代价是对需要长期支持的企业不友好，且冻结期对 SMP 等大型改造构成节律性拖累；评论者认为 CVS 缺乏开发者侧分支的合并能力放大了这一结构性紧张，开发者遂以补丁集流转工作，形成与其余分支不同的协作形态。（BSD Now EP86，[4736.32-4886.76]，L2）
- M:Tier 的核心业务是为一家业务遍及一百五十余国、IT 部门规模超越其所在国任何本土集成商的蓝筹客户，在从边缘防火墙与路由器、FTP、Kerberos、LDAP、DNS、NTP、VPN 等服务到普通员工工作站的全栈上部署自管理 OpenBSD，公司内部约九成系统为 OpenBSD；选型动机受保密协议所限只能概括为法律与安全两条。为应对当地普遍缺乏 Unix 与 BSD 经验、多来自 Windows 背景的用户，方案以 PXE 安装服务器加一键引导实现全基础设施的自动分区、装包与配置，并围绕 GNOME 桌面补齐 Windows 用户预期（U 盘自动挂载、无线漫游图形工具），GNOME 3 所需 KMS 支持由公司出资赞助。 [存疑脚注] 嘉宾姓名转写作 Anton Jakuto（通行拼法为 Antoine Jacoutot），公司名转写存在 m-tier、m-chair、mtr 等变体，均按上下文校准为 M:Tier。（BSD Now EP86，[1200.02-1495.06]，L1）
- 针对 OpenBSD stable 分支不提供二进制安全更新、需自行重制版本或手工打补丁的现状，BinPatchNG 以一组 makefile 将 base 系统安全修复构建为可用包管理器安装的补丁包并支持回滚，OpenUp 则负责扫描仓库、自动安装缺失补丁并更新全部软件包；该工具链由 Gerardo Santana 首创，后经前 OpenBSD 开发者接手更名并搁置，M:Tier 维护至今。其外围效应是社区对 stable 的关注度上升，开发者开始更多向 stable 回移包级修复——“如今我们可以看到大量提交进入 stable，这在以前是不存在的”（2231.90-2236.62）。 [存疑脚注] BinPatchNG 的接手者姓名转写作 Felix Rolager，拼写待核。（BSD Now EP86，[1953.22-2244.60]，L1）

**史观**：

- 总纲3 不存在进步，只有权力再分配：嘉宾口述的最佳保密秘密现象揭示了 BSD 企业采用史的深层结构：大量公司以 FreeBSD 做 ZFS 存储、以 OpenBSD 做防火墙与路由却从不宣传，如同不宣传所用 Brocade 交换机一般；其决定机制并非技术优劣，而是责任规避的劳动政治——出问题的若是人人皆用的主流方案则无人担责，引入非主流系统者则独揽故障罪名，故 BSD 进入企业依赖懂行者的个人决断，与十年前 Linux 的处境同构。技术采纳史因此不能写成进步叙事，而是支持生态与责任分配的权力再分配史。“倘若你带来一台 OpenBSD 机器，随后整个防火墙基础设施因故崩溃，那就要算在你头上”（1926.14-1942.32）。（BSD Now EP86，[1899.18-1952.26]，L2）
- 总纲8 本体论上各方平等：四大分支并存的发布工程学——FreeBSD 的版本矩阵与 ABI 冻结、OpenBSD 的节律与冻结、NetBSD 的大版本、小版本与安全版本三类划分及新装机可直接安装已打补丁镜像、DragonFly 依赖开发者私有 Git 侧分支使发版不扰动主线——没有一种可被追认为主流进化方向，各自是不同社区规模、版本控制工具与用户结构下偶然成形又自我强化的形式安排；讲述者明言所有方案各有优劣、其偏好 OpenBSD 模式属个人趣味而非历史必然。“所有这些方案都有优点和缺点”（5084.72-5088.06）。历史书写应在本体论层面平等对待各分支的工程文化，而非以某一家为进步标尺。（BSD Now EP86，[4886.76-5182.96]，L2）

**辨析**：

- 听众质疑 pkg-ng 以二进制包取代源码编译是否为针对 Unix 传统的一次 systemd 式反叛，主持人澄清 ports 树相对于 Linux 的历史价值在于提供可定制编译的框架而非拒绝二进制（如自打补丁限定运行时长的 rsync），pkg-ng 的每周构建化解了旧时代 ports 与冻结二进制包不可混用的痛点，同规模部署的安装时间从约四十五分钟的编译压缩至三分钟装包；进一步的可复现构建愿景是自编译结果与官方包逐位一致以供安全验证。嘉宾以 OpenBSD 的 Flavor 变体包机制（如带 LDAP 支持的 Dovecot 独立包名）反衬 FreeBSD options 变更导致的重编译痛点（Bacula 默认绑定 PostgreSQL 而其自用 MySQL，每次升级被要求重装），并期待 ports 树本身可作为包安装、与官方包的构建基线保持同步。 [存疑脚注] 转写将 Dovecot 记作 Bacode，Bacula 数据库选项对话以听写近似呈现，专名以通行拼写为准。（BSD Now EP86，[4173.42-4411.42]，L2）
