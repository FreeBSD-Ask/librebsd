# 195.7.4 tcpdump/file(1) 等基本系统工具漏洞（2007-2008）

**要点**：NetBSD 3.x 周期基本系统工具漏洞以 tcpdump 与 **file(1)** 为代表——CVE-2007-1218（tcpdump 缓冲区溢出，5424bb8f4d77d5b6bf8f3a5c5127c283277512e0，2008-04-14）、CVE-2007-1536（**file(1)** 堆溢出，1eb1fa2462408e11d5a21b2406f2a92a416448e3，2007-06-24，commit 正文为 “Update file(1) to version 4.21, including security fixes (CVE-2007-1536 and CVE-2007-2799).” 的 netbsd-4 pullup）、CVE-2007-3798（tcpdump 整数溢出，5424bb8f4d77d5b6bf8f3a5c5127c283277512e0，2008-04-14）；这些漏洞虽影响范围有限（需攻击者构造恶意抓包数据或恶意文件），但反映 NetBSD 3.x 时期对基本系统工具的持续安全审计；**file(1)** 漏洞的特殊性在于其被广泛用于邮件过滤器、Web 上传检测等场景，恶意文件可触发 **file(1)** 堆溢出获取运行 **file(1)** 的进程权限

**史料**：netbsd.duckdb netbsd-src 仓库 commit `5424bb8f4d77d5b6bf8f3a5c5127c283277512e0`（2008-04-14，CVE-2007-1218/3798 tcpdump）；commit `1eb1fa2462408e11d5a21b2406f2a92a416448e3`（2007-06-24，CVE-2007-1536 file(1) 堆溢出） ［A］

**史观**：总纲第 15 条——文化即形式主义：**file(1)** 漏洞揭示 “文件类型识别” 作为攻击面的工程风险——**file(1)** 解析未知文件格式时须处理不可信数据，任何格式解析缺陷均可被恶意文件利用；总纲第 9 条——经验优先：**file(1)** 被广泛用于安全检测（如邮件附件类型判断），其自身漏洞可导致 “安全检测工具成为攻击入口” 的悖论

**辨析**：CVE-2007-1536 的 commit 正文 “Update file(1) to version 4.21, including security fixes (CVE-2007-1536 and CVE-2007-2799).” 表明修复由 Christos Zoulas（NetBSD 核心贡献者，**file(1)** 长期维护者）提供，但 Christos 是否为 **file(1)** 上游维护者须考据——Christos 确为 **file(1)** 上游维护者，此修复可能同步至上游；tcpdump 漏洞的攻击场景须考据——tcpdump 通常以 root 权限运行，其缓冲区溢出可导致 root 权限获取；【0 信任原则·CVSS 评分缺失】全部 CVE 均无 CVSS v3 评分

**文献**：netbsd.duckdb netbsd-src 仓库 tcpdump、file(1) 相关 commit 记录；CVE-2007-1218、CVE-2007-1536、CVE-2007-3798 NVD 条目 ［A］
