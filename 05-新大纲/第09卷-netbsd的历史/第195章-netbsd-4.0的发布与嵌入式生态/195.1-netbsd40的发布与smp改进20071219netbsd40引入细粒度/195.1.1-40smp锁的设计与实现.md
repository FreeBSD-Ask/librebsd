**要点**：NetBSD 4.0（**2007.12.19**）的 SMP 锁设计与实现——引入细粒度锁替换大内核锁，改进多核性能；SMP 锁设计反映 NetBSD 在多核时代的适应

**史料**：NetBSD 4.0 Release Notes；SMP 锁 commit 日志；SMP 架构文档；netbsd.duckdb netbsd-src 仓库 branches 表验证（netbsd-src 无 release tag，branches 表 commit_date 为分支最后更新时间非发布时间）：origin/netbsd-4-0 branch commit_date = 2012-11-14T20:26:54Z（commit e8a6796c553c，远晚于 NetBSD 官方公告 4.0 发布日期 2007.12.19 约 4 年 11 个月，属分支持续维护末次更新时间，非发布时间）；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2005 年 commit_count = 30,344，2006 年 = 30,561，2007 年（4.0 发布年）= 28,670，2008 年 = 26,543，2009 年 = 26,690，2005-2009 年间 commit 量呈逐年下降趋势（从 30,344 降至 26,690，降幅约 12%），反映 4.0 发布周期内开发活跃度逐步收敛；netbsd.duckdb 查询 L2.3.1.smp 显示：netbsd-src 2007 年 SMP 相关 commit = 38（4.0 发布年峰值），2008 年 = 24，2009 年 = 24，印证 4.0 细粒度 SMP 锁改造集中在 2007 年；统计结论 [C-04]: netbsd-src 仓库总 commit 数 773,683（截至 2026-07-27 查询），为 4 大 BSD src 仓库中 commit 累计最高者，本章时期（2005-2009）的 commit 活动构成此总量的中段；统计结论 [C-09]: netbsd-src 月度 commit 量 Mann-Kendall 趋势检验呈显著下降趋势（Sen's slope=−7.27/月，p<0.001，95% CI [−8.15, −6.42]），本章时期（2005-2009）处于该长期下降趋势的中段，2005 年 30,344→2009 年 26,690 的年度降幅与全期下降趋势吻合；统计结论 [C-25]: netbsd-src 贡献者 Gini 系数 0.8158（Bootstrap 95% CI [0.7922, 0.8365]，B=2000），反映 NetBSD 贡献者集中度低于 freebsd-src（0.9188）但接近 openbsd-src（0.8244），本章时期 SMP 开发（ad/Doran 等）在此集中度背景下进行 ［A］

**史观**：技术选择的代价：细粒度锁付出复杂度代价，但获得多核性能

**辨析**：SMP 锁设计的具体实现需考据——细粒度锁的具体范围需对照源码 diff 核实。经 netbsd.duckdb netbsd-src 仓库 branches 表验证：origin/netbsd-4-0 branch commit_date = 2012-11-14T20:26:54Z，远晚于 NetBSD 官方公告 4.0 发布日期 2007.12.19（约 4 年 11 个月），印证 branches 表 commit_date 是分支最后更新时间而非版本发布时间，须与 NetBSD 官方公告（netbsd.org/releases/formal.html）交叉验证；4.0 发布日期 2007.12.19 仍须以官方公告为准。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），commit 量可能不完整或滞后于主仓；L2.3.1.smp 查询基于 message_subject LIKE '%SMP%’ 匹配，可能遗漏未在 subject 中含 “SMP” 关键词但实际涉及 SMP 锁改造的 commit，38 这个数字是下限而非上限。统计结论 [C-09] 局限性继承：Mann-Kendall 趋势检验 p < 0.001 显著仅反映 netbsd-src 月度 commit 量存在统计学显著的下降趋势，不等于该下降趋势在 2005-2009 年本章时期内单调递减——Sen's slope = −7.27/月是全期（1993-2026）平均斜率，本章时期内年度 commit 量可能存在波动（如 2007 年 SMP commit 峰值 38），须结合 L1.1.1 年度 commit 量数据交叉验证；趋势检验不区分 “开发衰退” 与 “开发模式转型”，下降原因须结合 commit message 主题词与文件路径分析。统计结论 [C-25] 局限性继承：Gini 系数 0.8158 的 Bootstrap 95% CI [0.7922, 0.8365] 反映贡献者集中度的不确定性，但 Gini 系数不区分 “核心贡献者” 与 “长期维护者” 的职能差异，且 Bootstrap 重抽样基于 commit author 字段，存在 author 字段可伪造风险，分析贡献者归属时须与 committer 字段交叉验证
