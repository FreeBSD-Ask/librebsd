# 195.5.1 粗粒度 SMP 锁 → 细粒度 SMP 锁（2007.12.19）

**要点**：NetBSD 3.x 及之前采用大内核锁（Big Kernel Lock, BKL）的粗粒度 SMP 实现，多核扩展性受限；NetBSD 4.0（2007.12.19）引入细粒度锁替换大内核锁，将全局锁拆分为子系统级锁与对象级锁；细粒度锁改造由 Andrew Doran（安德鲁·多兰） 等开发者推进，工程量巨大是 4.0 发布周期约 2 年（自 3.0 于 2005.12.23 发布起算）的重要原因；细粒度锁使 NetBSD 在 4 核至 16 核机器上获得显著性能提升

**史料**：NetBSD 4.0 Release Notes；Andrew Doran 在 tech-kern 邮件列表的 SMP 锁设计帖；CVS commit log 中 SMP 锁相关 commit；netbsd.duckdb netbsd-src 仓库 branches 表验证：origin/netbsd-4-0 branch commit_date = 2012-11-14T20:26:54Z（commit e8a6796c553c，远晚于 4.0 发布 2007.12.19 约 4 年 11 个月，属分支末次维护更新时间，非发布时间），origin/netbsd-3-0 branch commit_date = 2009-04-30T20:36:52Z（commit 99f7cbea021b，晚于 3.0 发布 2005.12.23 约 3 年 4 个月）；两 branch commit_date 印证 3.x 与 4.x 分支均持续维护至 2009/2012 年，4.x 分支维护期更长（约 5 年），与 “4.0 细粒度锁改造工程量大、维护周期长” 叙事间接吻合；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2007 年 commit_count = 28,670（4.0 发布年），2008 年 = 26,543，2009 年 = 26,690，2007-2009 年间 commit 量稳定在 26,000-29,000 区间，反映 4.0 发布后进入稳定维护期；netbsd.duckdb 查询 L2.3.1.smp 显示：netbsd-src 2005 年 SMP 相关 commit = 15，2006 年 = 8，2007 年 = 38（4.0 发布年，显著峰值），2008 年 = 24，2009 年 = 24，2007 年 SMP commit 量为 2005-2009 年间最高，印证细粒度 SMP 锁改造集中在 4.0 发布年 ［A］

**史观**：技术选择的代价：细粒度锁付出复杂度与发布周期代价，但获得多核性能；总纲第 17 条——形式与内容：从大内核锁到细粒度锁是锁机制 “形式” 的演进

**辨析**：4.0 细粒度锁的具体实现范围需考据——并非所有子系统完成细粒度化，部分仍保留粗粒度锁，需对照源码 diff 核验；4.0 与 5.0 在 SMP 锁改造上的分工需考据。经 netbsd.duckdb netbsd-src 仓库 branches 表验证：origin/netbsd-4-0 与 origin/netbsd-3-0 的 commit_date 时序与版本演进顺序一致，但 commit_date 非发布时间，4.0 发布日期 2007.12.19 与 3.0 发布日期 2005.12.23 仍须以 NetBSD 官方公告为准。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2007-2009 年 commit 量可能不完整；L2.3.1.smp 查询基于 message_subject LIKE '%SMP%’ 匹配，38 这个数字是 SMP 相关 commit 的下限，实际涉及细粒度锁改造的 commit 可能更多（如 subject 中含 “lock” “mutex” “scheduler” 但未含 “SMP” 的 commit 未被统计）
