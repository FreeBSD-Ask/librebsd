# 202.5.3 Tainted Code 政策传统：AI 时代代码伦理的早期制度化回应（考据冲突存疑）

**要点**：考据记录 20260727_customs-bsd.md § 二、2.4 记载：2024 年 5 月 NetBSD 修改开发者守则引入“tainted code”（被污染的代码）概念，规定未经 core 书面批准不得提交 AI 生成的代码，由 NetBSD Core Group 监督执行；“tainted”（被污染）一词借鉴 Linux 内核“tainted kernel”概念（加载非 GPL 或非签名模块后内核自标记为 tainted），延伸至代码来源合规性；同期 Gentoo 理事会 2024-04-14 投票禁止 AI 生成代码，QEMU 自 2023 年 11 月起限制；**但本章既有考据（基于考据记录 20260723_announcements-netbsd.md）显示**：NetBSD Foundation Policies 目录（**<https://www.netbsd.org/foundation/policies/>**）仅有 4 件政策文件（Donation Policy 2003-07-15、Reimbursement Policy 2018-05-02、application-procedure、membership-app），无任何名为“Tainted Code”的政策；WebSearch 检索“NetBSD Foundation ‘tainted’ code policy GPL license 2024”与“NetBSD Foundation Tainted Code policy 2024 announcement”均未返回 NetBSD 官方相关结果；** 两份考据记录存在直接冲突**——2026-07-23 考据未找到政策文件，2026-07-27 考据声称政策存在，本子节保留存疑状态［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；按 0 信任原则，穷尽考据后仍无法确证的，不得强行采信或证伪
