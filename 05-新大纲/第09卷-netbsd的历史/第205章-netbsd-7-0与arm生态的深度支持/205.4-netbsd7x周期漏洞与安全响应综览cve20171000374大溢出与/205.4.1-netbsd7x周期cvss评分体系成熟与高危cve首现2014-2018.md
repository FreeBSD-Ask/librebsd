**要点**：NetBSD 7.x 版本周期（2014-07-01 至 2018-05-01）是 NetBSD 历史上首次出现 Critical 与 High 级别 CVE 的版本周期——netbsd.duckdb netbsd-src 仓库查询显示此周期内 365 条 CVE commit、55 条 Security fix commit、217 条去重 CVE，其中 1 条 Critical（CVE-2017-1000374，CVSS v3 9.8）、7 条 High（CVE-2017-12836、CVE-2017-3135/3137/3143/3145/3141、CVE-2018-5732）、7 条 Medium、1 条 Low、201 条无评分；CVE commit 量较 6.x 周期（113 条）增长 223%，反映 NetBSD 7.x 周期（约 4 年）较长且 CVE 编号引用习惯进一步固化；NetBSD 7.0（2015.9）改进 ARM 多核支持、引入 RPI2 树莓派支持〔存疑：RPI3 支持进入 7.0 系初版公告抑或 7.1 补充，待核〕、64-bit 时间戳迁移，架构变化使 ARM 平台攻击面扩大——ARM 架构的缓存一致性、内存管理单元（MMU）差异可能引入新的内核漏洞

**史料**：netbsd.duckdb netbsd-src 仓库 commits 表（7.x 周期 365 条 CVE commit、55 条 Security fix commit、217 条去重 CVE，CVSS 分布 Critical 1/High 7/Medium 7/Low 1/无评分 201）；NetBSD 7.0 Release Notes（2015.9）；早期漏洞补遗归档（原材料/研究/bsd 漏洞史/版本周期/netbsd-7.x.md） ［A］

**史观**：总纲第 3 条（不存在进步，只有权力再分配）：CVSS v3 评分体系的成熟使 NetBSD 7.x 周期首次能够量化漏洞严重程度——Critical（9.8）与 High（7.0-7.5）级别的出现不等于 NetBSD 7.x 周期漏洞 “更严重”，而是 NVD 对 2014 年后 CVE 的 CVSS v3 评分回填覆盖率提升所致；专题语（不设总纲条号）：CVE commit 量增长 223% 反映 NetBSD 7.x 周期安全响应的 “统计显性化”——commit message 普遍引用 CVE 编号使安全响应可量化追踪

**辨析**：“首次出现 Critical 与 High CVE” 的论断须限定为 “首次在 netbsd.duckdb 查询结果中出现 CVSS v3 评分的 Critical/High CVE”——早期版本周期（1.x-6.x）的 CVE 全部无 CVSS v3 评分，不代表这些周期无 Critical/High 级别漏洞，仅代表 NVD 未回填评分；217 条去重 CVE 中 201 条无评分（92.6%）反映 NVD 对 2014-2018 年 CVE 的 CVSS v3 回填仍不完整；【0 信任原则·CVSS 评分来源】CVSS v3 评分来自 NVD，须对照 NVD 条目逐一核验，不得依赖 netbsd.duckdb 单一来源
