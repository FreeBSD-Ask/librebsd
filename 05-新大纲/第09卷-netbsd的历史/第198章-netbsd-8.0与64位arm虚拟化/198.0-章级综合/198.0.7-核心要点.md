# 198.0.7 核心要点

**要点**：NetBSD 8.0（2018-07-17）时期是 evbarm 生态的承前启后期——ARM 多核与 SMP 支持改进、旧 ARM ABI 向 aarch64 过渡的技术淘汰推进（181.2）；**但 AArch64（64 位 ARM）正式支持与 NVMM 虚拟化框架实际首次出现于 NetBSD 9.0（2020-02-14），8.0 官方发布页未列二者**（章定位勘误 doubt 1895，见上方编排说明）；同期 kernel ASLR 实验性引入与 retguard（2016-2018）构成本周期的安全演进线（181.4）；本时期的同期坐标为 FreeBSD 11.x/12、OpenBSD 6.3、Linux 4.1x 与 Windows 10/Server 2016（181.3）。

**史料**：The NetBSD Project. NetBSD 8.0 Released（2018-07-17 官方发布页）；NetBSD 9.0 Released（2020-02-14 官方发布页）；AsiaBSDCon 2020《Engineering NetBSD 9.0》（三者共同构成 AArch64/NVMM 断代核验源，见编排说明）；NetBSD 8.0 Release Notes（ARM 多核/SMP 与 KASLR 官方记载）；[DB:code_repos:netbsd.duckdb] netbsd-src 仓库 commits 表（KASLR/retguard、ARM 多核切片，2016-2018）

**史观**：总纲第 4 条——分离聚合是永恒规律：8.0 时期的 ARM 生态演进是旧 ABI/旧 SMP 与新路径（aarch64）的分离—聚合循环；总纲第 5 条——没有必然性，只有偶然性：AArch64 与 NVMM 未在 8.0 落地而在 9.0 落地，系工程人力与上游 LLVM 基础等偶然条件的产物，不存在“64 位化必然在 8.0 到来”的进步叙事；总纲第 22 条——知识注定过时：本卷目录名“8.0 与 64 位 ARM 虚拟化”的知识口径已被 9.0 断代事实过时——勘误 doubt 1895 本身即该条纲领的例证

**辨析**：章名“8.0 与 64 位 ARM 虚拟化”与史实的偏差是本节首要辨析对象（断代以官方发布页为准，勘误留痕）；数据库统计受 CVS/SVN-to-Git 迁移与镜像滞后影响存在系统性偏差；KASLR 在 8.0 系实验性引入的完备程度须以 sysctl 与源码树核验，不得径称“8.0 已具备 KASLR”。自反性声明：本节五字段系 2026-09-12 章级核查整改补写，提炼自 181.1-181.4 各节、勘误 doubt 1895 与库内断代核验，属形式主义化重构，欢迎被更诚实的叙事所超越（总纲第 23 条）
