# 198.2.2 旧 SMP 实现 → 改进 SMP 支持（2018）

**要点**：NetBSD 8.0（2018.7）改进 SMP 实现，引入对多核扩展性与性能的优化；旧 SMP 实现存在锁竞争与缓存一致性问题，8.0 引入新的同步原语与调度优化；改进让 NetBSD 在 16 核以上机器上获得更好性能；旧 SMP 路径作为分离分支保留，体现“终结中的延续”（总纲第 4 条分离聚合的延续面）

**史料**：NetBSD 8.0 Release Notes SMP 部分；tech-kern 邮件列表讨论；CVS commit log 中 SMP 相关 commit；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2016 年 commit_count = 16,600，2017 年 = 13,101（较 2016 年下降 21.1%），2018 年 = 10,983（8.0 发布年，较 2017 年下降 16.2%），2016-2018 年间 commit 量持续下降反映 8.0 开发周期内社区规模收缩或开发模式转型；netbsd.duckdb 查询 L2.3.1.smp 显示：netbsd-src 2016 年 SMP 相关 commit = 10，2017 年 = 5（开发低谷），2018 年 = 21（8.0 发布年峰值，较 2017 年增长 320%），2018 年 SMP commit 峰值反映 8.0 发布年 SMP 改进的集中投入，2017 年的低谷可能反映 SMP 开发在 8.0 开发周期中段进入平台期 ［A］

**史观**：专题语（不设总纲条号）：旧 SMP 实现的形式主义膨胀（锁粒度过粗）促使重构；SMP 作为信息技术的基础组件，其演进体现总纲第 4 条（分离聚合是永恒规律）的分合循环

**辨析**：8.0 SMP 改进的具体性能提升缺乏权威基准——需对照同硬件测试核验；与 FreeBSD SMP 的对比需考据；新同步原语的具体名称与设计需对照源码核验。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2016-2018 年 commit 量可能不完整，2016-2018 年持续下降趋势的归因需复核——NetBSD 主仓由 CVS 迁移至 Mercurial（**hg.NetBSD.org**）于 2020 年完成，晚于该时段，不能以迁移解释该下降，镜像滞后与匹配口径仍为主要局限；L2.3.1.smp 查询基于 message_subject LIKE‘%SMP%”匹配，10/5/21 这组数字是 SMP 相关 commit 的下限，实际涉及 SMP 改进的 commit 可能更多（如 subject 中含“scheduler”“lock”“mutex”“runqueue”“preemption”“work stealing”但未含“SMP”的 commit 未被统计）；2018 年 SMP commit 峰值（21）与 8.0 发布年时序吻合，但 commit 量峰值不等于技术成熟度峰值

**文献**：NetBSD 8.0 Release Notes；tech-kern 邮件列表；SMP 设计文档；netbsd.duckdb 数据分析·宏观趋势统计.md §L1.1.1（netbsd-src 2016-2018 年度 commit 量）、§L2.3.1.smp（netbsd-src SMP 相关 commit 2016-2018） ［A］
