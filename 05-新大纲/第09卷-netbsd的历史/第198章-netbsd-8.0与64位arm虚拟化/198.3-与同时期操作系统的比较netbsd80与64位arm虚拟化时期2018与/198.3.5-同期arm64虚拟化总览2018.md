2019 年 9 月 28 日，Kamil Rytarowski 在回应中说明，使用 musl 可为与主机相同的 CPU 配置取得交叉工具链，而无需构建定制的 gcc 或 clang；其主要动机是为 compat_linux 运行 LTP 内核回归测试并纳入 ATF 即 src/tests；他明确该阶段并不需要 Linux compat，该需求仅出现在测试 hello-world 示例时；纯 musl-gcc 方式构建非平凡应用多半会失败，因为系统仍会被识别为 NetBSD 从而影响结果，构建带依赖的应用至少在 chroot 中进行；他认为把 MUSL 集成进 src/ 的用例值得考虑，而 musl-gcc 属 musl 仓库的一部分，需自行执行 gmake 构建 musl-gcc 与 specs 并装入 /usr/local；NetBSD 与 Linux 的 ELF 大体相似，少数差异由 musl-gcc 的 GCC 脚本处理；用 musl-gcc 构建 Linux 内核会更棘手，因为有若干假定 uname 为 Linux 的 hack，但应可做到。引用时按 L3 纪律：以上为邮件列表当事人陈述，属过程性证据，具体事实与量化结论仍须交叉复核，不得单独引为定论。
