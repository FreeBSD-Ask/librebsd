**要点**：NetBSD 10.0（**2024.3.31**）引入对 Apple Silicon M1/M2 的实验性支持，由 Jared McNeill（jmcneill）、Nick Hudson（skrll）、Ryo Shimizu（ryo）等共同推动；移植工作最早可追溯至 2021-08-30（jmcneill“Identify Apple M1 ‘Icestorm’ and ‘Firestorm’ CPU types.”与“Add initial support for Apple M1.”），早于 10.0 发布约 2 年 7 个月；支持包括 aarch64 内核启动、PCIe、NVMe、I2C、GPIO、SMC 等设备驱动；M1/M2 移植让 NetBSD 在 Apple 硬件上获得实验性可用性

**史观**：总纲第 10 条——动手者创造历史：McNeill、Hudson、Shimizu 作为动手者贡献，让 NetBSD 在 Apple 硬件上获得存在感；总纲第 4 条——分离聚合是永恒规律〔存疑：重挂待复核〕：多个 commit 显式标注“From OpenBSD”或“Ported from OpenBSD”（NVMe、I2C、RTKit SMC），反映 NetBSD Apple Silicon 移植大量借鉴 OpenBSD 代码，体现 BSD 项目间的代码协同；统计结论印证：C-04（netbsd-src 总 commit 数 773,683 为 4 BSD src 仓库最高）与 C-09（Mann-Kendall 趋势下降 slope = −7.27/月 p < 0.001）共同反映 NetBSD 在 10.0 时期面临 “高累计 commit 量” 与 “持续下降趋势” 的张力——高累计量反映历史工程投入沉淀，但下降趋势反映 10.0 时期开发活跃度的结构性收敛，0 信任原则适用：统计显著不等于实际显著，下降趋势不区分 “开发衰退” 与 “开发模式转型”

**辨析**：经 netbsd.duckdb netbsd-src 仓库 commits 表验证：Apple Silicon M1 移植最早可追溯至 2021-08-30（jmcneill），早于 10.0 发布 2024.3.31 约 2 年 7 个月；移植由 jmcneill（2021-2022）、skrll（2022）、ryo（2022）三位开发者共同推动，原叙事中“由 Jared McNeill 等推动”中的“等”应明确包含 skrll 与 ryo；重要修正：原叙事称“移植基于 Asahi Linux 逆向工程成果”声明未得到代码级确认——netbsd.duckdb netbsd-src 仓库 commits 表中多个 Apple Silicon commit 显式标注“From OpenBSD”或“Ported from OpenBSD”（NVMe、I2C、RTKit SMC），反映 NetBSD Apple Silicon 移植主要借鉴 OpenBSD 代码而非 Asahi Linux 逆向工程成果，存疑已部分解决（代码来源得到代码级确认，但底层逆向工程可能仍源于 Asahi Linux，须对照 OpenBSD Apple Silicon 移植文档核验）；M1/M2 的具体支持功能（如 GPU、神经网络引擎）在 10.0 中几乎不可用，需考据；10.0 发布日期 2024.3.31 仍须以 NetBSD 官方公告为准。L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2020-2024 年 commit 量可能不完整，2022 年的断崖式下降（41.8%）可能部分源于 Mercurial 主仓与 GitHub 镜像同步机制的调整或主仓迁移影响，须与 NetBSD 官方 commit 统计交叉验证；2020-2024 年 commit 量累计降幅 53.5% 反映社区规模萎缩趋势，但 commit 量下降不等于技术产出下降——部分 commit 可能更集中、更大规模（如 Apple Silicon 移植的单次 commit 涉及多文件）。统计结论 [C-09] 局限性继承：Mann-Kendall 趋势检验 p < 0.001 显著仅反映 netbsd-src 月度 commit 量存在统计学显著的下降趋势，不等于该下降趋势在 2020-2026 年本章时期内单调递减——Sen's slope = −7.27/月是全期（1993-2026）平均斜率，本章时期内 Apple Silicon 子领域 commit 反呈局部峰值（如 2022 年 skrll 多次提交 NVMe/I2C/RTKit SMC 驱动），须结合 L1.1.1 年度 commit 量数据交叉验证；趋势检验不区分 “开发衰退” 与 “开发模式转型”（如向 Mercurial 迁移的过渡期影响），下降原因须结合 commit message 主题词与文件路径分析
