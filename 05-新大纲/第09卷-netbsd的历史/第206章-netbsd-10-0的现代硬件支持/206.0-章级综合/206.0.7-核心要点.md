# 206.0.7 核心要点

**要点**：NetBSD 10.0 时期（2024 年发布〔日期两说待核，见索引注〕）是 NetBSD 现代硬件支持的跃升期——引入对 Apple Silicon（M1/M2）的实验性支持、改进 NVMe 与 USB4 支持、新音频子系统（189.1）；pkgsrc 持续演进并引入 Pkgin 二进制前端、与 Docker/容器生态集成（189.2，注意“pkgsrc 3.0-4.0”系节命名遗留非版本号——勘误已核）；2023 年起 NetBSD 将 AI 生成代码定性为“被污染的代码”（tainted code）禁止直接合入主线（189.3，“率先”表述待核）；同期 Foundation 治理成熟（资金结构、Core Team 选举、与 FreeBSD Foundation 合作，189.4）、committer 权限执行 18 个月不活跃自动退休（189.5）；KVA 保护等内核安全特性引入（189.8）。

**史料**：The NetBSD Project. NetBSD 10.0 Release Notes 与官方发布页；The NetBSD Foundation. Commit Guidelines（LLM 生成代码标注条款）；pkgsrc 官方文档与 Pkgin 设计文档；[DB:code_repos:netbsd.duckdb] tech_features 表 ARM 特性标记 7,351 次（1996-2026，见 GITREPO_FINE_BLOCK）

**史观**：总纲第 5 条——没有必然性，只有偶然性：Apple Silicon 移植的时机与完成度系上游 ARM64 基础与人力分布的偶然产物，非“现代硬件支持必然到位”的进步叙事；总纲第 4 条——分离聚合是永恒规律：pkgsrc 季度分支体系是代码与发行物分离—聚合的制度化形态，Docker/容器集成是新一轮聚合面；总纲第 22 条——知识注定过时：“率先明确 tainted code”的表述随各项目 AI 政策演化须持续重估；总纲第 3 条——不存在进步，只有权力再分配：Foundation 治理成熟与 Core Team 选举是治理权力的制度化再分配

**辨析**：“NetBSD 10.0 发布日期”两说（2024-03-06 vs 索引串 2024.3.28）须以官方发布页核定；“pkgsrc 3.0-4.0”系节命名遗留不可作版本号引用（勘误已核）；“率先明确 tainted code”的“率先”缺对照系（其他 BSD 项目政策时点）须补对照考据；数据库统计受迁移与镜像滞后影响存在系统性偏差。自反性声明：本节五字段系 2026-09-12 章级核查整改补写，提炼自 189.1-189.8 各节与勘误登记，属形式主义化重构，欢迎被更诚实的叙事所超越（总纲第 23 条）
