# 184.2 NetBSD 2.x/3.x 时期的社区与发布工程

**要点**：NetBSD 2.x/3.x 时期发布工程由 Jeff Rizzo、Soren Jacobsen 等推动；社区在 tech-kern、tech-userlevel 等邮件列表持续讨论架构方向；Foundation 在此时期逐步建立捐赠与企业合作机制

**史料**：NetBSD Foundation 2003-2007 年度报告；release-engineering 邮件列表；NetBSD commit log 中 releng 相关分支；netbsd.duckdb 查询 L1.4.1 显示：netbsd-src 仓库 tags 表为空（0 个 tag），与 freebsd-src 仓库 tags 表含 release/12.0.0 等标准 release tag 不同；netbsd-src 仓库 branches 表使用 netbsd-4-0、netbsd-10 等命名约定（非 release/X.Y.Z 格式），反映 NetBSD 与 FreeBSD 在发布分支命名约定上的差异；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 2003 年 commit_count = 50,546，2004 年 = 37,918，2005 年 = 30,344，2006 年 = 30,561，2007 年 = 28,670，2.x-3.x 时期 commit 量逐年下降反映发布工程团队在社区投入收缩背景下维持稳定发布节奏的压力 ［A］

**史观**：第 14 章边缘者贡献，发布工程团队的志愿者劳动是项目稳定运行的基础

**辨析**：发布工程的具体贡献者名单需对照 commit log 核验，部分叙事仅突出 Core Team 而忽略 release engineering 团队。L1.4.1 查询对 netbsd-src 不适用——netbsd-src 仓库 tags 表为空，无法通过 tag 提取发布版本信息，须依赖 branches 表的 netbsd-X-Y 命名约定识别发布分支；netbsd-src 分支命名约定（netbsd-4-0 等）与 FreeBSD（release/12.0.0）不同，导致 L1.4.1 查询在 NetBSD 上不适用，相关发布日期考据须依赖 commit message 中的 “Welcome to NetBSD X.0 release.” 等字符串匹配（已在 81.1、81.2 中验证）；L1.1.1 查询的 commit 量数据存在 GitHub 镜像滞后风险——netbsd-src 为 GitHub 镜像（主仓为 Mercurial **hg.NetBSD.org**），2003-2007 年 commit 量可能不完整

**文献**：NetBSD Foundation 2003-2007 Annual Reports [EB/OL]. <https://www.NetBSD.org/foundation/reports/>；release-engineering 邮件列表 [EB/OL]. <https://mail-index.netbsd.org/release-engineering/>；Jeff Rizzo、Soren Jacobsen releng commit 记录 [DB/OL]. netbsd.duckdb netbsd-src 仓库；netbsd.duckdb 数据分析·宏观趋势统计.md §L1.1.1（netbsd-src 2003-2007 年度 commit 量）、§L1.4.1（netbsd-src tags 表为空，分支命名约定差异） ［A］
