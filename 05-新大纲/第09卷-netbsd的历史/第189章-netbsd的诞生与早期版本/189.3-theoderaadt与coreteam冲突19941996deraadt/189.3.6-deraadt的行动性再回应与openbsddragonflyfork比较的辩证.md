# 189.3.6 de Raadt 的行动性再回应与 OpenBSD/DragonFly fork 比较的辩证层（再批评层）

  **OpenBSD fork 与 DragonFly fork 对照表**：

  | 维度 | OpenBSD fork（de Raadt） | DragonFly fork（Dillon） |
  | --- | --- | --- |
  | 源项目 | NetBSD | FreeBSD |
  | 撤权决议日期 | 1994-12-20 | 2003-01-28（末次 commit） |
  | 源项目末次 commit | `699d2a37b0e3`（1994-12-17T23:12:41Z） | —（2003-01-28T18:44:40Z） |
  | fork 首条 commit | `df930be708d5`（1995-10-18T08:37:01Z） | `984263bcb83a`（2003-06-17T02:57:24Z） |
  | 筹备期 | 约 10 个月（304 天） | 约 5 个月（140 天） |
  | fork 动机 | 人际冲突与治理分歧 | 技术路线分歧（SMPng vs LWKT） |
  | 撤权前贡献状态 | 仍活跃贡献（被外部终止） | 已实质性停止贡献（内部退出） |
  | 细分市场 | 安全细分市场（pledge/unveil/LibreSSL） | 未建立明确细分市场 |
  | 2024 年 commit 量 | 持续活跃 | 277 条（可持续性挑战） |
  | 不可调和性来源 | 前理解差异（不可通约） | 工程判断分歧（可通约但未妥协） |

**要点**：de Raadt 对 Core Team 撤权决议的再回应以“行动性再回应”而非“公开声明性再回应”呈现——1995 年 10 月 18 日 OpenBSD CVS 仓库初始导入（commit `df930be708d50e9715f173caa26ffe1b7599b157`，commit message“initial import of NetBSD tree”），以独立项目的创建回应 Core Team 的“不适合继续担任官方代表”判定；OpenBSD 官方 goals.html 将项目定位为“best development platform”“robust and secure”“#1 most secure operating system”“Make a release approximately every six months”，未提及与 NetBSD 的争议——这一沉默本身是史观素材，OpenBSD 选择以工程定位而非历史争议定义自身。与 DragonFly fork 的比较深化辩证：OpenBSD fork（1995.10.18）距撤权决议（1994.12.20）约 10 个月，DragonFly fork（2003.06.17 首 commit `984263bcb83a`）距 Dillon 在 freebsd-src 末次 commit（2003.01.28）约 4.5 个月；freebsd.duckdb 显示 de Raadt fork 后 10 个月方首 commit（筹备期较长），Dillon fork 后 5 个月即首 commit（筹备期较短），反映两人技术准备状态与项目酝酿程度的不同。两次 fork 的动机差异构成辩证核心：de Raadt fork 源于人际冲突与治理分歧（Core Team 单方面撤权），Dillon fork 源于技术路线分歧（SMPng 细粒度锁 vs LWKT 消息传递）；netbsd.duckdb 显示 de Raadt 在 netbsd-src 末次 commit 1994-12-17 早于 12 月 20 日决议 3 天，Dillon 在 freebsd-src 末次 commit 2003-01-28 后 4.5 个月无贡献，反映 de Raadt 撤权前仍在活跃贡献（被外部终止），Dillon 撤权前已实质性停止贡献（内部退出）。两次 fork 的可持续性差异亦构成辩证：OpenBSD 在 1995-2026 年间建立安全细分市场（pledge/unveil/LibreSSL 等），openbsd.duckdb 显示 openbsd-src 仓库持续活跃；DragonFly 在 2003-2026 年间未建立明确细分市场，dragonfly.duckdb 显示 dragonfly-src 仓库 2024 年 commit 量仅 277 条，反映 fork 动机与细分市场建立的关联

**史料**：OpenBSD CVS 历史早期记录（1995-10-18T08:37:01Z 初始导入，commit_hash `df930be708d50e9715f173caa26ffe1b7599b157`，commit message“initial import of NetBSD tree”）；OpenBSD 官方 goals.html（<https://www.openbsd.org/goals.html>，项目定位为“best development platform”“robust and secure”“#1 most secure operating system”“Make a release approximately every six months”，未提及与 NetBSD 的争议）；netbsd.duckdb commits 表 deraadt netbsd-src 末次 commit = 1994-12-17T23:12:41Z（commit_hash `699d2a37b0e3c0c6ff29ea0d407c3feeba5642b4`）；openbsd.duckdb commits 表 deraadt openbsd-src 首 commit = 1995-10-18T08:37:01Z；freebsd.duckdb commits 表 Dillon freebsd-src 末次 commit = 2003-01-28T18:44:40Z；dragonfly.duckdb commits 表 Dillon dragonfly-src 首 commit = 2003-06-17T02:57:24Z（commit_hash `984263bcb83a`，message_subject“Initial import from FreeBSD RELENG_4”）；dragonfly.duckdb dragonfly-src 仓库 2024 年 commit 量 = 277（反映 DragonFly 可持续性挑战）［A］

**史观**：总纲第 10 条——动手者创造历史：项目史观总纲第 14.2 节指出“真正推动 BSD 的是‘Get your hands dirty’（动手去做）的人，而非旁观者”，de Raadt 以 1995-10-18 OpenBSD CVS 仓库初始导入（commit `df930be708d50e9715f173caa26ffe1b7599b157`）作为对 Core Team 决议的“行动性再回应”，以独立项目创建而非公开声明的方式呈现主体性；但第 14.1 节“没有多余形式主义的人就是老实人”亦提示：fork 这一行为本身并非天然等同于“动手者”姿态，须审视其后是否持续以工程实践而非组织化论战定义自身——openbsd.duckdb 显示 openbsd-src 仓库 1995-2026 年持续活跃并建立安全细分市场（pledge/unveil/LibreSSL），是其作为“动手者”的物质印证；总纲第 6 条——和解优于斗争：de Raadt 未选择公开论战，而是以独立项目创建呈现自身主体性，这一选择在形式上接近“和解”——不否定 Core Team 的决议权，但以行动开辟新主体性空间；总纲第 5 条——没有必然性，只有偶然性：OpenBSD 与 DragonFly 两次 fork 的筹备期差异（10 个月 vs 5 个月）、动机差异（人际冲突 vs 技术分歧）、可持续性差异（建立细分市场 vs 未建立）皆是不可替代的偶然，不得以“fork 必然成功”或“fork 必然失败”的目的论叙事遮蔽

**辨析**：考据过程留痕——【查证来源】OpenBSD goals.html 经 <https://www.openbsd.org/goals.html> 一手核验，页面内容确为“best development platform”“robust and secure”“#1 most secure operating system”等定位描述，未提及与 NetBSD 的争议；但 0 信任原则提示：goals.html 页面内容是动态的，可能存在事后修订，1995-1996 年原始页面内容须以互联网档案馆存档交叉验证；【交叉验证方法】netbsd.duckdb commits 表提供 de Raadt 与 Dillon 两人 fork 前后 commit 时间线的代码级证据——deraadt netbsd-src 末次 commit 1994-12-17 → openbsd-src 首 commit 1995-10-18（间隔 304 天），Dillon freebsd-src 末次 commit 2003-01-28 → dragonfly-src 首 commit 2003-06-17（间隔 140 天），两人筹备期差异 164 天，反映 de Raadt 筹备期较长（可能涉及团队组建与代码整理），Dillon 筹备期较短（技术路线已明确）；【存疑判定依据】de Raadt 是否在 OpenBSD misc 邮件列表（1995 年后建立）或其他渠道发表过针对 Core Team 决议的公开回应，需对照 OpenBSD 邮件列表早期存档核实，本次考据未取得原文，无法确证；de Raadt 个人主页自述中对驱逐事件的记述需按 0 信任原则考据——当事人自述存在自利偏差与记忆偏差风险；【两次 fork 可比性的界限】OpenBSD 与 DragonFly 的可比性限于“个人主导型开发者与集体治理结构冲突”框架——de Raadt 1994 年撤权涉及 NetBSD Core Team 多名成员公开站队（Adam Glass、Charles Hannum 等），Dillon 2003 年撤权未见 FreeBSD Core Team 成员公开表态，反映 NetBSD Core Team 1994 年决议机制较 FreeBSD Core Team 2003 年决议机制更为公开化；fork 后 30 年的可持续性差异主要源于细分市场而非 fork 本身——OpenBSD 填补了安全细分市场，DragonFly 的 LWKT/HAMMER/vkernel 创新未获业界主流采纳，缺乏细分市场支撑；0 信任原则提示：de Raadt 的“沉默论战”不等于“接受决议”——行动性回应可能掩盖对决议程序的异议，史家不得因“未公开论战”即推论“接受判定”
