# 189.1.2 0.8 至 1.0 的开发历程

**要点**：NetBSD 0.8（1993.4.20）至 1.0（1994.10.26）的开发历程——约 18 个月内完成从 fork 到正式发布，团队整合 4.4BSD-Lite 预览代码、移植多平台（hp300、i386、sparc）、建立 pkgsrc 雏形；发布周期较长源于 1994 年 USL 诉讼和解促使的 4.4BSD-Lite 基础迁移工程；1.0 的发布奠定 NetBSD“可移植性至上”的定位

**史料**：NetBSD 0.8 与 1.0 Release Notes（netbsd.org/releases/formal-1.0.html）；早期 CVS 提交日志；NetBSD 核心团队开发记录；netbsd.duckdb netbsd-src 仓库 branches 表验证（netbsd-src 无 release tag，branches 表 commit_date 为分支最后更新时间非发布时间）：origin/netbsd-0-9 branch commit_date = 1993-08-25T23:58:11Z（commit 4051c5751e24，与 NetBSD 0.9 发布时间 1993.8 时序一致）；origin/netbsd-1-0 branch commit_date = 1994-11-29T04:19:15Z（commit 94ac458bb17d，与 NetBSD 1.0 发布日期 1994.10.26 时序一致，branch 最后更新时间晚于发布约 1 个月，可能含发布后小修补）；netbsd.duckdb 查询 L1.1.1 显示：netbsd-src 1994 年 commit_count = 17,726（占 4 大 BSD src 总量 80.78%），1995 年 commit_count = 12,163（占 58.88%，openbsd-src 同期 fork 后首次出现 commit 770 条，占 3.73%）；netbsd.duckdb 查询 L1.4.1 显示：netbsd-src 仓库在标准 release tag 过滤条件（tag_name LIKE ‘release/%’ OR ’%-RELEASE’ OR 'OPENBSD_%’）下无匹配 tag，与 ch70 已用 branches 表代替 tags 表验证 release 节点的处理一致，反映 netbsd-src GitHub 镜像 tag 命名约定不同于 freebsd-src/release/ 前缀格式 ［A］

**史观**：技术选择的代价：NetBSD 选择多平台战略付出复杂度代价，但获得可移植性声誉；法律结构：USL 诉讼和解推动的 4.4BSD-Lite 迁移作为法律结构事件重塑 NetBSD 1.0 代码基础

**辨析**：1.0 发布日期在不同叙事中存在差异——部分早期资料误作 1993.10.4，但 NetBSD 官方发布页面（netbsd.org/releases/formal.html）明确为 1994.10.26；0.8 至 1.0 历时约 18 个月而非 6 个月，多平台移植的具体顺序需对照 CVS 日志核实。经 netbsd.duckdb branches 表验证，origin/netbsd-1-0 branch 最后更新时间 1994-11-29 与 NetBSD 官方公告 1.0 发布日期 1994.10.26 时序一致（branch 最后更新可能含发布后小修补），1993.10.4 说法不正确，存疑已解决；L1.1.1 显示 netbsd-src 1994 年 commit_count = 17,726 较 1993 年 14,507 上升 22.2%，与 1.0 发布前开发强度增加的叙事吻合，但 L1.1.1 commit 量受 GitHub 镜像同步策略影响，须与 hg.NetBSD.org 主仓数据交叉验证；L1.4.1 标准过滤条件未匹配到 netbsd-src release tag，反映 netbsd-src tag 命名约定与 freebsd-src/release/ 前缀不同，须改用 branches 表交叉验证 release 节点
