# 193.4.4 内核权限提升与 OpenSSL/OpenSSH 漏洞群（2002-2006）

**要点**：NetBSD 2.x 时期内核权限提升与用户态守护进程漏洞并行——CVE-2002-0429（**PSL_NT** 标志位清理缺陷，yamt 2004-03-11 commit `aad9f63765c96a39eb18f32b8427fb5f1e697078`，commit subject "before resuming from failure during return to user mode, clear PSL_NT. it can"，本地用户可利用系统调用失败恢复路径中的标志位残留获取内核权限，反映 NetBSD 2.x 对 i386 架构返回用户态路径的深度审计）；一批 OpenSSL 漏洞（CVE-2006-2937、CVE-2006-2940、CVE-2006-3738、CVE-2006-4343，均由 christos 2006-09-29 commit `897b34d36dc3e0cbe4b31f2d4a1a8d00b2fab107` 统一修复，OpenSSL 0.9.7l/0.9.8d 升级，反映 “同组件多漏洞合并修复” 实践）；CVE-2006-5794（OpenSSH **sshd(8)** 权限分离缺陷，commit `1be366570b9fd1861a64526dc60281a17d031b94`，2006-11-14，随 OpenSSH release-4.5 引入）；这些漏洞反映 NetBSD 2.x 时期对内核返回用户态路径与基本系统捆绑的 OpenSSL/OpenSSH 安全组件的系统性安全审计

**史料**：netbsd.duckdb netbsd-src 仓库 yamt commit `aad9f63765c96a39eb18f32b8427fb5f1e697078`（2004-03-11，CVE-2002-0429 PSL_NT）；christos commit `897b34d36dc3e0cbe4b31f2d4a1a8d00b2fab107`（2006-09-29，CVE-2006-2937/2940/3738/4343 OpenSSL 0.9.7l/0.9.8d 升级）；commit `1be366570b9fd1861a64526dc60281a17d031b94`（2006-11-14，CVE-2006-5794 OpenSSH **sshd(8)** 权限分离） ［A］

**史观**：总纲第 15 条（文化即形式主义）：CVE-2002-0429 的 PSL_NT 标志位缺陷揭示 “系统调用失败恢复路径” 作为安全审计盲区——失败路径中的状态清理不完整可被利用获取权限，此为 “错误处理代码本身包含错误” 的典型范式；专题语（不设总纲条号）：OpenSSH/OpenSSL 漏洞群反映 “基本系统安全组件” 作为攻击面的持续存在——NetBSD 基本系统捆绑的 OpenSSL 与 OpenSSH 虽属成熟第三方组件，仍须及时跟进上游安全版本

**辨析**：CVE-2002-0429 的 CVE 编号年份（2002）与修复 commit 日期（2004-03-11）相差近 2 年，反映该漏洞可能在 2002 年即被披露但修复延迟至 2004 年，或 CVE 编号系事后回溯分配——具体时序须对照 NetBSD-SA 公告与 NVD 条目核验；OpenSSL 漏洞群（CVE-2006-2937/2940/3738/4343）由同一 commit `897b34d36dc3e0cbe4b31f2d4a1a8d00b2fab107` 修复，反映 “同组件多漏洞合并修复” 的工程效率，但该 commit 是否完全修复所有子漏洞须对照 NVD 条目逐一核验；【0 信任原则·CVSS 评分缺失】全部 CVE 均无 CVSS v3 评分，但 “内核权限提升”（CVE-2002-0429）与 “OpenSSH 权限分离”（CVE-2006-5794）的机制类型本身暗示较高风险
