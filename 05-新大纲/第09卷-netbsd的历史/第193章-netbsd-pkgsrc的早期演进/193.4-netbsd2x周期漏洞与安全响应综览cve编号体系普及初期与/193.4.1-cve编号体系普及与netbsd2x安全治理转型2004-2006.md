**要点**：NetBSD 2.x 版本周期（2004-12 至 2006-12）恰逢 CVE 编号体系在 BSD 项目中系统化普及——netbsd.duckdb netbsd-src 仓库查询显示此周期内 89 条 CVE commit 与 161 条 Security fix commit，去重 CVE 16 条（全部无 CVSS v3 评分，反映 NVD 对 2006 年前 CVE 的评分回填滞后），3 条早期漏洞补遗覆盖 2004-2006 年；与 1.x 时期 “SA 驱动” 模式不同，2.x 时期 commit message 开始显式引用 CVE 编号（如 yamt 2004-03-11 commit `aad9f63765c96a39eb18f32b8427fb5f1e697078` 直接标注 “CVE-2002-0429”），反映 NetBSD 安全治理从 “SA 公告驱动” 向 “CVE 编号驱动” 的渐进转型；此时期 pkgsrc 早期发展（1997-2004）与 NetBSD 2.x 版本周期重叠，pkgsrc 跨平台软件包分发使漏洞修复须在 NetBSD 主仓与 pkgsrc 软件包树两处同步推进

**史观**：总纲第 15 条（文化即形式主义）：CVE 编号体系在 NetBSD 2.x 时期的普及是安全治理形式主义化的关键一步——将 “漏洞标识” 从项目内部 SA 编号统一为跨项目通用编号，使漏洞修复的可追溯性从 NetBSD 社区内部扩展至整个安全生态；总纲第 15 条（文化即形式主义）：commit message 显式引用 CVE 编号的习惯养成是 NetBSD 安全文化从 “自洽” 走向 “开放协作” 的标志

**辨析**：89 条 CVE commit 与 16 条去重 CVE 的差距反映 “同一 CVE 多分支 pullup” 的工程实践——NetBSD 维护 netbsd-2-0、netbsd-2-1、netbsd-3 等多个稳定分支，同一漏洞修复须在多分支重复提交；16 条去重 CVE 全部无 CVSS v3 评分系 NVD 对 2006 年前 CVE 的评分回填滞后所致，本节不臆造评分；【0 信任原则·CVSS 评分缺失】无评分不等于低风险——CVE-2002-0429（权限提升）与 CVE-2006-5794（权限提升）的 “权限提升” 机制类型本身暗示较高风险，但具体评分须待 NVD 回填或对照 CVSS v2 评估
