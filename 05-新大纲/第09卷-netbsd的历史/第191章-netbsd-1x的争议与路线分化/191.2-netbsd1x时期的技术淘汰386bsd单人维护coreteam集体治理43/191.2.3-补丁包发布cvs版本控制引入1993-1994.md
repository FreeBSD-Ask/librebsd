# 191.2.3 补丁包发布 → CVS 版本控制引入（1993-1994）

**要点**：386BSD 采用补丁包（patchkit）发布模式，补丁由 Jolitz 个人整合，难以追溯版本历史；NetBSD 1993 年创建后即引入 CVS 作为版本控制系统，建立 commit log、分支、标签机制；CVS 引入使 NetBSD 开发过程可追溯、可回溯、可协作，告别补丁包时代；CVS 仓库托管于 anoncvs.netbsd.org，通过 anoncvs 协议公开访问；NetBSD 是早期采用 CVS 的开源项目之一，与 FreeBSD 共同推动 CVS 在 BSD 生态的普及

**史料**：NetBSD CVS 仓库早期 commit log；anoncvs.netbsd.org 早期访问记录；386BSD 补丁包发布档案；NetBSD 1993-1994 邮件列表 CVS 讨论帖 ［A］

**史观**：总纲第 17 条——形式与内容：CVS 作为“形式”（版本控制框架）改变了开发“内容”（代码协作方式）；社区文化即技术资产：CVS 公开访问机制作为社区文化资产降低了贡献门槛

**辨析**：NetBSD 引入 CVS 的具体时间存在叙事分歧——部分资料称 1993.4 项目创建即引入，部分称 1993 年中期引入，需对照最早 commit log 核验；CVS 与同期 RCS、SCCS 的选择动机需考据
