**要点**：

- 入行经过：大学时新笔记本需要可用的无线局域网，FreeBSD 5 当时未就绪、NetBSD 与 OpenBSD 在该机器上亦不理想，恰逢 Matt Dillon 宣布 DragonFly 项目且缺少 CardBus（32 位 PCMCIA 扩展）支持，其首个贡献即把 FreeBSD 5 的 CardBus 支持回移到 DragonFly。（BSDTalk EP135，[101.77-137.10]，L1）
- pkgsrc 引入 DragonFly 的经过：先前以本地 override 方式修补 FreeBSD ports（复制到本地仓库改写、以 hack 绕过系统头文件与符号链接差异），随 DragonFly 与 FreeBSD 分歧扩大而难以为继；2005 年另一开发者完成 pkgsrc bootstrap 与关键组件，其尝试后将 DragonFly 本地改动并入 pkgsrc；Thomas Klausner 等因补件 flood 而授予其直接提交权；此后第三方应用适配多在 pkgsrc 完成，用户在 FreeBSD ports 与 pkgsrc 之间的取舍变得容易。（BSDTalk EP135，[142.22-247.27]，L1）
- NetBSD 电源管理工作：Jared McNeill 早先着手改进 ACPI 挂起/恢复（部分机器可用、许多笔记本失效、AMD64 完全不可用）；另一方向是让未使用设备自动断电（未启用的网络接口、声卡等）；NetBSD 设有专门分支（转写作 jmcnally-pm）以把电源管理支持推进更多驱动；其本人因笔记本需要而投入，并视电源管理为当前比 jail 更紧迫的工作。（BSDTalk EP135，[253.27-312.47]，L1） [订正：原“有专门邮件列表推动电源管理进入更多驱动”，2026-09-29 SenseAudio 重转核对]
- Google Summer of Code 的 pkgsrc 项目分两部分：一是重做批量构建框架——旧系统无法处理多 chroot 或分布式构建集群，新系统以轻松利用多机、动态加入与退出为设计目标；二是 pkgsrc 交叉编译，重点是 modular Xorg（沿 XFree86 老路则工作量巨大且与 DragonFly 需求重复维护），核心是让 pkgsrc 复用 NetBSD 基本系统的交叉编译工具链，使 Amiga、VAX 等慢架构免于本地构建大包；适用前提为单平台且目标基础设施相似（ELF），跨操作系统交叉编译仅为未测试设想。（BSDTalk EP135，[365.44-505.83]，L1）
- GPLv3 的两大问题（EuroBSDCon 2007 项目状态讨论议题）：基本系统层面，需定期更新的 GPL 组件是 groff 与 GCC，要害不在 GCC 本身而在 libgcc 与 libstdc++——二者长期带有允许链接的例外条款，GPLv3 未将例外延及反 tivoization 条款，使高度定制且不允许篡改的系统能否用 GCC 构建成疑；对策包括 OpenBSD 导入 PCC、为 groff（BSD 源码树中唯一主要 C++ 组件）寻求替代。包管理层面，pkgsrc 已有非开源许可标签框架（mk.conf 的 acceptable_licenses 变量控制构建），计划扩展至全部许可类别尤其是 GPLv3，令用户知情并自决；批量构建基础设施问题待解决，目前仅对升级到 GPLv3 的包加注释。（BSDTalk EP135，[509.55-721.07]，L1）
- DragonFly jail 与 FreeBSD jail 的分化：DragonFly 源自 FreeBSD 4 的 jail 代码，FreeBSD 5/6 期间核心未大改（主要是适配 Robert Watson 的新凭证框架）；DragonFly 近期提交关键补丁，支持每 jail 多 IP 地址乃至 jail 内 IPv6，jail 的一大主要问题基本消除；FreeBSD 尚缺此能力，其替代路径是重量级虚拟化而非修补 jail 代码。（BSDTalk EP135，[734.95-791.94]，L1）
- NetBSD 的 kauth 式 jail 设想：kauth 已把大部分安全决策抽象到单一位置、便于修改；在 NetBSD 实现 jail 需给进程结构与凭证增加字段，使 root 权限决策可依是否处于 jail 而调整；剩余难题是 localhost 地址翻译的复杂代码；虚拟化路径的优点是避免在 jail 代码中特判。应用兼容性问题：Samba 因 localhost 特殊处理需要本地补丁，syslog 等守护进程绑定全部地址的对外行为需如 FreeBSD 团队那样专门修改。（BSDTalk EP135，[797.41-886.94]，L1）
- 开发者自我定位与环境：自称对所工作的 BSD 大体持不可知态度，现用 NetBSD 只因在其笔记本上优于 DragonFly，欣赏 DragonFly 的许多想法，不排斥 OpenBSD 且可能提交补丁；开发环境以控制台与多个 xterm 为主，使用 ion 平铺窗口管理器、midnight commander 与 vi。（BSDTalk EP135，[320.47-353.67]，L1）

**史料**：

- 当事人工作物：DragonFly CardBus 回移补丁；pkgsrc bootstrap（2005 年由另一开发者完成）与其本人获 pkgsrc 提交权；GSoC pkgsrc 批量构建与交叉编译项目；DragonFly 多 IP 与 IPv6 jail 关键补丁；OpenBSD 导入 PCC。（BSDTalk EP135，[119.09-770.67]，L1）
- EuroBSDCon 2007 的项目状态开放讨论（GPLv3 为关键议题）；SourceForge 上归档 FSF 作品最后 GPLv2 版本的项目（发起人转写作 Todd Veal，拼写存疑须核证）。（BSDTalk EP135，[509.55-721.07]，L2） [订正：原“发起人姓名转写不可辨”，2026-09-29 SenseAudio 重转核对]

**史观**：

- 总纲8 本体论上各方平等：跨项目开发者以可用性与问题驱动选择工作对象而非效忠单一分支：从 DragonFly 回移、到 pkgsrc 提交、再到 NetBSD 电源管理与可能的 OpenBSD 补丁，四大 BSD 在其实践中是可互换的工程场域。（BSDTalk EP135，[320.47-353.67]，L1）
- 总纲4 分离聚合是永恒规律：jail 代码从 FreeBSD 4 分离至 DragonFly 后独立演化出多 IP 与 IPv6 支持，而包管理层反向聚合于跨项目的 pkgsrc 平台——分离与聚合在代码谱系的不同层面同时进行，构成循环而非单向演进。（BSDTalk EP135，[142.22-791.94]，L1）
- 总纲13 法律与道德是利益分配：pkgsrc 的许可标签框架把许可证选择转译为用户可见的构建配置（acceptable_licenses），GPLv3 包的处置方案是让用户在知情前提下自决——许可证的利益分配通过包管理基础设施落到用户决定。（BSDTalk EP135，[649.76-705.47]，L1）
