# 194.5.1 嵌入式部署场景下的攻击面收缩与 NetBSD SA 公告体系的嵌入式适用性（1998-2006）

**要点**：NetBSD 1.x-2.x 时期是 NetBSD 嵌入式市场定位的确立期——Dreamcast、Sharp Zaurus、Cobalt Qube 等嵌入式设备部署 NetBSD，这些设备通常资源受限、远程管理、长期运行不重启，对安全响应提出特殊要求；netbsd.duckdb netbsd-src 仓库查询显示 1.x 时期 50 条 Security fix commit 与 2.x 时期 89 条 CVE commit 覆盖的漏洞中（检索口径注：commits 表按 message 关键词 “Security fix” / “CVE” 分期扫描，时间窗 1.x=1993-2002-10、2.x=2002-10-2006；系注入层预聚合值，精确检索式未随注入留痕，复核须重查），远程守护进程（ftpd、telnetd、sendmail、OpenSSH、httpd）类漏洞占主导——NetBSD-SA2001-005（**ftpd(8)** 远程溢出）、NetBSD-SA2001-012（**telnetd(8)** 选项协商溢出）、NetBSD-SA2003-009（**sendmail(8)** prescan 溢出）、NetBSD-SA2002-005（OpenSSH challenge-response 绕过）等公告对嵌入式设备厂商的紧迫性高于桌面/服务器场景，因嵌入式设备往往无法及时升级固件；此时期 NetBSD 尚无 VERIEXEC、pkg_signatures 等后续安全机制，嵌入式设备的安全防线依赖传统权限模型与 SA 公告响应

**史料**：NetBSD-SA2001-005 公告（CVE-2001-0240〔CVE 编号待核：未见官方索引所列，须对照 SA 公告原文 CVE 字段〕，ftpd 远程溢出）；NetBSD-SA2001-012 公告（telnetd 选项协商溢出）；NetBSD-SA2003-009 公告（CVE-2003-0161，sendmail prescan 溢出）；NetBSD-SA2002-005 公告（CVE-2001-1483〔CVE 编号待核：未见官方索引所列，须对照 SA 公告原文 CVE 字段〕，OpenSSH challenge-response）；netbsd.duckdb netbsd-src 仓库 1.x-2.x 时期 Security fix commit 与 CVE commit 统计 ［A］

**史观**：总纲第 17 条——软件工程：嵌入式场景下的安全响应困境是 “形式主义化” 未能完全覆盖的领域——SA 公告体系虽建立了 “发现漏洞—发布公告—提供补丁” 的标准流程，但嵌入式设备的固件更新滞后使补丁无法及时到达终端设备，揭示 “安全响应流程” 与 “设备实际更新能力” 之间的鸿沟；技术选择的代价：NetBSD 选择嵌入式市场获得部署广度，但付出安全维护成本——嵌入式设备的长期运行特性使漏洞暴露窗口期远长于桌面/服务器

**辨析**：嵌入式设备厂商对 NetBSD SA 公告的实际响应速度须考据——Dreamcast、Zaurus 等设备的固件更新历史须对照厂商公告核验，不得假设厂商及时跟进 NetBSD SA；“嵌入式设备无法及时升级固件” 的论断须区分消费级设备（Dreamcast 无固件更新机制）与企业级设备（Cobalt Qube 有厂商支持通道）；【0 信任原则·SA 公告与嵌入式厂商关系】NetBSD SA 公告的发布不等于嵌入式设备已修复——二者之间存在 “NetBSD 发布 SA → 厂商评估影响 → 厂商发布固件更新 → 用户安装更新” 的多级延迟链
