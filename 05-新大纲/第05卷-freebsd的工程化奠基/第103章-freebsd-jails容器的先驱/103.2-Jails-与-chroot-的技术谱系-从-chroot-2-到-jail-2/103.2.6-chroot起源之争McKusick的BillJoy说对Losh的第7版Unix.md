# 103.2.6 chroot起源之争McKusick的BillJoy说对Losh的第7版Unix

- chroot 起源之争（McKusick 的 Bill Joy 说对 Losh 的第 7 版 Unix 说）尚未完全闭合：两种说法都指向 1979 年前后，但发明动机叙事不同，4.2BSD SCCS 日志解读与 V7 源码证据须并置裁决。（BSD Now EP392，[752.12-806.12]，L1）
- FreeBSD 13 beta 基准的公平性存疑：beta 快照可能含调试符号，主持人的怀疑未获证实，数据宜作趋势参考而非定论。（BSD Now EP392，[461.56-493.08]，L2）
- helloSystem 的“macOS 启发”定位与 PyQt5 技术选型系主持人转述，项目自述与许可细节待核。[存疑脚注] helloSystem 项目细节以 GitHub 官方说明为准 [存疑脚注] helloSystem 项目细节系转述，须以项目仓库自述核对（BSD Now EP392，[1394.66-1406.5]，L4）
- DragonFly 5.8 的新包集在讨论中被误认为新版本发布，后澄清为季度二进制包集：版本发布与包集发布的语义边界需在引用时保持区分。（BSD Now EP392，[2259.02-2289.32]，L2）
- [存疑脚注] F-stack 宣称的千万并发与五百万请求每秒等性能数字系项目自报，须以独立基准测试核验。 [存疑脚注] F-stack 性能数字系项目自报。（BSD Now EP242，[573.34-599.48]，L4）
- [考据脚注] jails 随 FreeBSD 4.0 于 2000 年 3 月出现及作者信息须以 FreeBSD 手册与发布说明核验。 [考据脚注] jails 起源时间须以官方文档核验。（BSD Now EP242，[1644.92-1655.28]，L4）
- Arch Linux 论坛案例：/sys 下以文件形式暴露的 EFI 变量默认可写，`rm -rf /` 将其一并删除后，部分主板固件因变量缺失而彻底无法开机。主持人的辨析是：根因在固件缺陷而非内核暴露接口，Linux 侧“别那么做”的回应回避了伪文件系统可写性的设计问题；并引对 Brian Cantrill 访谈的回忆称 `rm -rf /` 本应失败——POSIX 不允许删除进程当前所在目录而进程总在某个目录之中，FreeBSD 的 rm 自约 2009 年起即据此拒绝该操作。 [存疑脚注] “POSIX 禁止删除当前目录”与“FreeBSD rm 自 2009 年起防护”均系节目口头转述与对旧访谈的记忆引用，未核对规范原文与源码历史，引用前须单独考据（BSD Now EP127，[7320.8-7463.5]，L4）[订正：原 [7338.74-7463.50]，2026-09-30 SenseAudio 重转核对]
- 主持人口称 chroot 自 1970 年代末即已存在、最初为发行版构建流程而写，又称 jail 可自 FreeBSD 6 或 7 起嵌套、VIMAGE 提供独立网络栈，均属无出处的口头概括；且本转写为双音轨交错，受访者与多位演讲者姓名被打碎，凡涉年代、版本号与人名者，引用前须以手册页、提交记录与会议日程核验。 [存疑脚注] 上述 chroot 年代与 jail 嵌套版本表述为单一来源口头推断，且转写专名失真（Sefi、Matthew Dylan、rake floydr 等）须逐条核对。（BSD Now EP93，[2571.60-2602.40]，L4）
- 主持人转述 Tor 中继平台分布统计（Linux 近 6000、Windows 约 1600、FreeBSD 173、OpenBSD 44、NetBSD 7、DragonFly BSD 仅 1），并以 Verisign 按 Linux、FreeBSD、Solaris 三分部署、OpenSSL 单点缺陷波及全网、Linux 伪随机数缺陷致 Tor 部分节点失效为例，主张平台多元是对冲系统性风险的工程策略；该论证与本期 LibreSSL 背景互为呼应 [存疑脚注] 节点统计数字仅经主持人转述且未附原始出处，属单一来源线索，待 tor-relays 邮件列表原始数据核验（BSD Now EP63，[928.52-1024.56]，L4）
- jails 与 Docker 的比较是本讲最显著的争议点：Lucas 认为两者是相似思路的不同边缘，并以其检查时点判断 jails 的轻量虚拟化当时更为完整；他批评 Docker 镜像如 Linux 包般散落随机站点、缺乏集中审计，与官方 iocage 插件的集中分发形成对照；该判断个人立场鲜明且时效敏感，Lucas 自己也承认三个月内情况可能已经改变。 [存疑脚注] jails 比 Docker 完整为讲者在 2020 年前后的个人判断，引用前须与 Docker 及容器运行时的后续版本演进交叉核验。（YouTube EPhQmOc0egcl4，[2782.8-2880.0]，L4）
