# 94.11 项目统摄史观审视——商品形式主义、文化形式主义与革命—改革方法论

## 94.11.1 总纲第 11 条审视：商品是形式主义

  **要点**：从项目史观总纲第 11 条“商品是形式主义。技术市场的选择不是自然选择，而是形式主义的权力运作。劣币驱逐良币是普遍规律”审视 jails 与 Docker 的市场命运。Docker 在 2013 年之后的产业胜利并非因其隔离机制优于 **jail(2)**——Docker 依赖的 Linux namespace 与 cgroup 在隔离粒度上未必超过 Jails 后期的 **jail_set(2)** 与 VNET 组合。Docker 的胜利是资本叙事、Docker Hub 分发生态与 Kubernetes 编排标准三者叠加的形式主义结果。“劣币驱逐良币”在此具象化：工程上更早（1999 年）、设计上更稳健（phk 直接针对“全能 root”问题）的 Jails，被工程上更晚、隔离层更薄但生态更激进的 Docker 驱逐出主流叙事。VMware 博客称 Jails 存在“severe restrictions”、Rutgers 课程笔记称其“lacked fine-grained resource management”，这些批评的传播力不来自批评本身的准确性，而来自 Docker 生态的形式主义霸权——批评被反复引用不是因为真实，而是因为有用。但第 11 条的审视也须承认：phk 本人在 jails saga 中将 jails 自评为“shitty Virtualization”，即作者侧对“虚拟化能力不足”亦有自我承认，“劣币”的判定因此呈现复杂面貌——被驱逐者并非纯粹“良币”，驱逐者亦非纯粹“劣币”，形式主义的“劣币驱逐良币”在此不是简单的善恶对立，而是两种不完美方案在形式主义市场中的不对称博弈

## 94.11.2 总纲第 15 条审视：文化即形式主义

  **要点**：从项目史观总纲第 15 条“文化即形式主义。传统在形式主义化过程中被遮蔽与重构。知音难觅同样适用于技术社区”审视 jails 作为容器先驱叙事的文化命运。容器技术的“传统”在形式主义化过程中被遮蔽与重构——今日开发者谈及“容器”，默认指向 Docker 镜像与 Kubernetes Pod，chroot→ **jail(2)** →Solaris Zones→LXC→Docker 的真实谱系被压缩为“Docker 革命”的单一叙事。Jails 在这一重构中被遮蔽：它不是被技术淘汰，而是被叙事遗忘。Docker 官方文档的“The underlying technology”小节提及 Linux namespace 与 Linux 内核特性，却不提及 Jails——这不是有意隐瞒，而是形式主义文化运作的无意识效果，其机制是“仅叙述 Linux 内核起源”的叙事框架将 BSD 谱系排除在容器正史之外。传统在形式主义化中被重构：Jails 从“容器技术的先驱”被重构为“Docker 前史中的脚注”，甚至完全消失。“知音难觅同样适用于技术社区”在此具象化——phk 的 **jail(2)** 在 Docker 时代已无“知音”，但 phk 本人在 jails saga 中以“shitty Virtualization”自嘲与“imperfect virtualization can and often is preferable”的哲学陈述，构成了作者侧的自我知音——当外部叙事遗忘时，作者通过自我书写保存了 jails 的历史一刻

## 94.11.3 总纲第 21 条审视：革命与改革是历史方法论的分歧

  **要点**：从项目史观总纲第 21 条“革命与改革是历史方法论的分歧。Linux 靠革命，BSD 靠改革。改革的困难远高于革命。破山中贼易，破心中贼难”审视 jails 与 Docker 的方法论分野。Linux 选择革命：Docker 彻底重建容器栈，引入镜像分层、`Dockerfile` 声明式接口、编排层等全新抽象，以断裂式否定推翻旧秩序。BSD 选择改革：Jails 从 **chroot(2)** 增量演进而来，**jail_set(2)** 扩展 API、VNET 引入完全网络栈虚拟化、**mac_jail(4)** 细化特权，每一步都是在保留传统基础上的调适。“改革的困难远高于革命”在此具象化——Docker 在 2013 至 2015 年间以革命性速度重建了整个容器生态，而 Jails 的改革历经 2000 至 2010 年仍在逐步完善网络栈虚拟化。“破山中贼易，破心中贼难”：Jails 的改革困难不在于技术论证（phk 的设计在 1999 年即已成立），而在于观念与结构——一旦 chroot→jail 的渐进路径确立，引入镜像与编排等全新抽象即与改革方法论冲突，Docker 的革命没有这一包袱。但第 21 条的审视也须承认：phk 本人在 jails saga 中将 jails 的核心发现定位为“accidentally discovered”即“偶然发现”，这表明 BSD 的“改革”方法论并非完全自觉的战略选择，而是路径依赖的渐进演化——改革者未必意识到自己在“改革”，这使得“改革的困难”不仅是结构性约束，也包含方法论上的无意识成分
  
**史料**：项目史观总纲第 21 条（“革命与改革是历史方法论的分歧。Linux 靠革命，BSD 靠改革。改革的困难远高于革命。破山中贼易，破心中贼难”，见 **据原文第 25 章.md**）、Docker 官方文档关于镜像分层与 `Dockerfile` 的记述、FreeBSD **jail_set(2)** 手册页、FreeBSD VNET 设计文档、**mac_jail(4)** 手册页、phk 个人网站 jails saga“accidentally discovered”陈述（**phk.freebsd.dk/sagas/jails/**）［A］
  
**史观**：总纲第 21 条——革命与改革是历史方法论的分歧，Linux 容器革命与 BSD jails 改革是该总纲最清晰的具象化

### 史观映射

> phk 不是在构思容器化战略时发明了 Jails——他只是在给一家托管客户做隔离，发现 chroot 不够用，就在那天下午写了 **jail(2)**。这便是技术史上偶然性的残酷：Jails 比所有后来的容器都早，但“先驱”这个称号并没有让它在 Docker 的叙事中获得任何位置——VMware 说它“severe restrictions”，Rutgers 的课程笔记说它“lacked fine-grained resource management”，Sun 以它为反面论证 Zones 的必要性，而 Docker 生态干脆假装它不存在。先驱不被记住，不是因为来太早，是因为后来的叙事不需要它

### 项目统摄史观审视

从总纲第 11 条、第 15 条、第 21 条切入，FreeBSD Jails 的历史命运可作如下审视。

**第 11 条“商品是形式主义”**。容器技术市场的选择不是自然选择，而是形式主义的权力运作。Docker 在 2013 年之后的产业胜利，并非因为其隔离机制优于 **jail(2)**——Docker 依赖的 Linux namespace 与 cgroup 在隔离粒度上未必超过 Jails 后期的 **jail_set(2)** 与 VNET 组合。Docker 的胜利是资本叙事、Docker Hub 分发生态与 Kubernetes 编排标准三者叠加的形式主义结果。“劣币驱逐良币”在此表现为普遍规律：工程上更早（1999 年）、设计上更稳健（phk 直接针对“全能 root”问题）的 Jails，被工程上更晚、隔离层更薄但生态更激进的 Docker 驱逐出主流叙事。VMware 博客称 Jails 存在“severe restrictions”、Rutgers 课程笔记称其“lacked fine-grained resource management”，这些批评的传播力不来自批评本身的准确性，而来自 Docker 生态的形式主义霸权——批评被反复引用不是因为真实，而是因为有用。

**第 15 条“文化即形式主义”**。容器技术的“传统”在形式主义化过程中被遮蔽与重构。今日开发者谈及“容器”，默认指向 Docker 镜像与 Kubernetes Pod，chroot→ **jail(2)** →Solaris Zones→LXC→Docker 的真实谱系被压缩为“Docker 革命”的单一叙事。Jails 在这一重构中被遮蔽：它不是被技术淘汰，而是被叙事遗忘。Docker 官方文档的“Underlying Technology”部分提及 Linux namespace 与 cgroup，却不提及 Jails——这不是有意隐瞒，而是形式主义文化运作的无意识效果。传统在形式主义化中被重构：Jails 从“容器技术的先驱”被重构为“Docker 前史中的脚注”，甚至完全消失。知音难觅同样适用于技术社区——phk 的 **jail(2)** 在 Docker 时代已无“知音”。

**第 21 条“革命与改革是历史方法论的分歧”**。Linux 与 BSD 在容器技术上的分野，是这一总纲最清晰的具象化。Linux 选择革命：Docker 彻底重建容器栈，引入镜像分层、`Dockerfile` 声明式接口、编排层等全新抽象，以断裂式否定推翻旧秩序。BSD 选择改革：Jails 从 **chroot(2)** 增量演进而来，**jail_set(2)** 扩展 API、VNET 引入完全网络栈虚拟化、**mac_jail(4)** 细化特权，每一步都是在保留传统基础上的调适。“改革的困难远高于革命”在此具象化——Docker 在 2013 至 2015 年间以革命性速度重建了整个容器生态，而 Jails 的改革历经 2000 至 2010 年仍在逐步完善网络栈虚拟化。“破山中贼易，破心中贼难”：Jails 的改革困难不在于技术论证（phk 的设计在 1999 年即已成立），而在于观念与结构——一旦 chroot→jail 的渐进路径确立，引入镜像与编排等全新抽象即与改革方法论冲突。Docker 的革命没有这一包袱。

这三种审视指向同一结论：Jails 的历史命运不是技术失败的案例，而是形式主义运作的标本。“先驱”称号本身也是形式主义——以时间先后评判技术价值，与以市场份额评判技术价值，是同一种形式主义的两种表现。真正的审视应超越“先驱是否被记住”的叙事，回到项目统摄史观的根本姿态：历史是形式主义化的非存在，Jails 作为历史一刻已经完成，其价值不依赖于 Docker 叙事的承认。
