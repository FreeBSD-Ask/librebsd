# 111.1.1 Evans 的开发动机

  **要点**：Jason Evans 自 2005 年起为 FreeBSD 开发 jemalloc（其 BSDCan 2006 论文即以 FreeBSD 为题），其后 jemalloc 被 Mozilla 采纳并适配进 Firefox 3，用于缓解 Firefox 在 Linux/Solaris/Windows 上的内存碎片与性能下降问题。 [存疑脚注] 原稿“Evans 时为 Mozilla 短期合同开发者”与“2005 年为 Firefox 3 开发”两说所据为 Mozilla Bugzilla 与 Evans 个人博客范围，本库无法直接验证，合同关系待回源。
  
**史料**：Evans 个人博客 “jemalloc”、Mozilla Bugzilla 2005 讨论、Firefox 3 开发档案 ［C］；bsd_commits.duckdb 查询 L2.3.1.jemalloc 显示：中观模式挖掘报告中 L2.3.1 特性查询仅覆盖 ZFS/Capsicum/bhyve/Clang/ARM64/RISC-V 六项，无 jemalloc 专项查询，jemalloc 引入到稳定周期的 commit 时间序列须直接查询 bsd_commits.duckdb 获取；bsd_commits.duckdb 查询 L2.2.1.lib_libc 显示：中观模式挖掘报告中 L2.2.1 子系统查询仅覆盖 sys/kern/sys/net/sys/geom/sys/cam/sys/dev/sys/vm/sys/fs/sys/contrib 八项，无 lib/libc 子系统查询，libc（含 malloc 实现）的 commit 量变化须直接查询 bsd_commits.duckdb 获取（原稿所附建议查询条件等操作说明已移考据记录，此处从略）
  
**史观**：总纲第 9 条——经验优先：内存碎片问题 FreeBSD 工程实践中的实际经验驱动 jemalloc 设计
  
**辨析**：经参考文献库验证通过（fact-check 2026-08-14），reference_id=533（bsdcan. evans-jemalloc-paper, 2006）《A Scalable Concurrent malloc(3) Implementation for FreeBSD》署名 Jason Evans <jasone@FreeBSD.org>、2006-04-16，reference_id=534 为同题幻灯片，印证 jemalloc 论文于 2006 年 BSDCan 发表；“2005 年为 Firefox 3 开发”的开发起点两库无法直接验证（属 Mozilla Bugzilla 与 Evans 个人博客范围，超出两库覆盖）；Evans 是否独立开发，需查 Mozilla 合同；0 信任原则适用说明：L2.3.1.jemalloc 与 L2.2.1.lib_libc 查询数据在中观模式挖掘报告中缺失，反映数据库分析覆盖范围有限——jemalloc 作为用户态内存分配器，其 commit 可能分布在 freebsd-src 仓库 lib/libc/ 目录下，但 L2.2.1 子系统查询未覆盖 lib/ 目录；须直接查询 freebsd.duckdb 验证 jemalloc 引入时间与 libc 子系统 commit 量变化；关键词匹配（“jemalloc”）可能漏命中（commit message 可能使用 “malloc” 或 “allocator” 等表述）
