# 118.1.5 缺口与前瞻

本卷史料缺口可按成因分为四类，各类缺口的成因分析与未来研究方向如下。

第一类：邮件列表存档的不完整。freebsd-smp、freebsd-fs、freebsd-core 等关键邮件列表存档未完整索引，2000 至 2005 年部分存档存在时间断层，freebsd-core 邮件列表作为 Core Team 决策记录长期保持私密。成因分析：邮件列表归档在 1990 年代末尚未制度化，部分列表依赖个人志愿者维护，志愿者离任后存档中断；Core Team 私密性是刻意设计，旨在保护内部讨论的坦诚性，但代价是历史可追溯性的丧失。未来方向：推动 FreeBSD Project 与互联网档案馆合作，对现有邮件列表存档进行完整镜像；Core Team 决策记录的脱敏归档（去除个人评价，保留技术决策）可作为长期目标。

第二类：BSDCon 会议论文集的散佚。BSDCon 1999 至 2006 部分演讲录音与论文散佚，USENIX 官方存档仅覆盖部分年份，Kamp BSDCon 2000 Jails 演讲、BSDCon 2002 GEOM 演讲等关键事件的一手记录不完整。成因分析：BSDCon 2006 年停办后，会议档案移交混乱，部分演讲未提交正式论文，仅存幻灯片或参会者笔记；USENIX 的数字化优先级长期偏向其他会议。未来方向：通过 BSDCan、EuroBSDCon 等后续会议的参会者网络征集私人存档；与 USENIX 协商 BSDCon 档案的完整数字化与开放获取。

第三类：4.x 至 5.x 转型期决策记录的缺失。SMPng、KSE、ULE、GEOM 等架构改造的决策过程（为何选择某一路径而非另一路径）缺乏系统性记录，仅有散见于邮件列表与 commit message 的片段。成因分析：FreeBSD Project 在 1999 至 2003 年间缺乏正式的“设计文档”制度，架构决策主要在邮件列表讨论中形成，无统一的 RFC 或设计提案归档机制（对比 Python PEP、Rust RFC 等后续制度）。未来方向：对仍在世的核心开发者（如 McKusick、Kamp、Watson、Roberson 等）开展系统性口述史访谈，重点补足 4.x 至 5.x 转型期的决策过程记录。

第四类：量化数据的不足。本卷虽以 **freebsd.duckdb** 为量化考据基础，但性能基准数据（SMPng vs 4BSD 调度器在不同负载下的性能对比、ULE 在 7.0 与 7.1 的性能改进量化）、部署规模数据（1996 至 2010 年间 FreeBSD 在不同场景的部署量估算）仍不足。成因分析：性能基准数据散落于各 BSDCon 与 AsiaBSDCon 论文，缺乏统一数据库；部署规模数据因商业用户非义务披露而长期缺乏。未来方向：建立 BSD 性能基准历史数据库，系统爬取 BSDCon、AsiaBSDCon、BSDCan、EuroBSDCon 1999 至 2010 论文中的性能数据；通过 FreeBSD Foundation 年度报告与商业用户公开案例（如 Netflix、Yahoo!）部分补足部署规模数据。

前瞻：本卷史料的未来拓展方向有三：其一，口述史的系统化——对 1996 至 2010 年间的核心开发者（McKusick、Kamp、Watson、Roberson、Dillon、Hubbard 等）开展结构化口述史访谈，重点补足决策过程与个人视角；其二，跨项目比较史——将 FreeBSD 1996 至 2010 工程化进程与同期 Linux（2.4 至 2.6 大内核锁演进）、NetBSD（1.x 至 5.x 可移植性路径）、OpenBSD（2.x 至 4.x 安全审计文化）进行系统比较，凸显各项目的工程哲学分化；其三，STS 视角的引入——借鉴科学技术学的“技术塑造社会、社会塑造技术”框架，分析 FreeBSD 工程化进程与同期互联网商业化、开源运动机构化、知识产权法律变迁的共构关系。这三方向均超出本卷单卷篇幅所能承载，留待全书综合卷与后续研究补足。
