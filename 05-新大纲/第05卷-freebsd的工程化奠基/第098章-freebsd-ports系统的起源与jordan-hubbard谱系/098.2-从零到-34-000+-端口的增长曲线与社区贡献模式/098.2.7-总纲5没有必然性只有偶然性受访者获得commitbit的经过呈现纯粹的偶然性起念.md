# 098.2.7 总纲5没有必然性只有偶然性受访者获得commitbit的经过呈现纯粹的偶然性起念

- 总纲5 没有必然性，只有偶然性：受访者获得 commit bit 的经过呈现纯粹的偶然性：起念也许该争取提交权限约一周后，他在一个 FreeBSD 相关 IRC 频道被两名俄罗斯 committer 认出并当场授予提交权限，自述“真的、真的完全没有预料到”（907.08-909.68）；社区权威的授予并非履历阶梯的必然产物，而系具体人物在具体场合的即兴行动，书写 committer 群体时应保留此类非制度化的偶然入口。（BSD Now EP108，[872.3-930.0]，L1）[订正：原 [879.78-913.84]，2026-09-30 SenseAudio 重转核对]

**辨析**：

- 受访者转述油气行业用户“跑 Linux 时约百节点每周一故障，换 FreeBSD 后一年无故障”（1606.5-1626.8），并断言多数 Linux 发行版的质量平衡“过于靠近够用”（4068.02-4085.42）；两条比较均出自单一场合口述、无仓库数据或公告可独立复核，且受访者立场明显亲 FreeBSD，书稿引用时须与 Netflix 等大规模 Linux 生产环境案例相互制衡，避免以一己对比修辞直接立论。 [存疑脚注] 故障率对比系受访者转述的第三方经验，无法独立验证；对 Linux 发行版质量的评价属当事人立场性论断。（BSD Now EP108，[1594.3-1631.6]，L4）[订正：原 [1606.5-1626.8]，2026-09-30 SenseAudio 重转核对]

- 当事人指认 GNOME 上游的 Linux 中心化：他初入上游时被告知“我们不以 Linux 为中心”，早期模块讨论尚可发声，但如今邮件列表尽是发行版话题，HAL、NetworkManager、GNOME Power Manager 等候选模块在当下一律 Linux 特定；Sun 的 Solaris 贡献者主要承担文档，NetBSD 社区提交过优秀补丁，GNOME 对非 Linux 补丁总体接纳；相比之下 KDE 开发者（尤其 FreeBSD KDE 团队）明显更在乎跨平台与 FreeBSD 硬件支持走向。 [存疑脚注] 当事人自承“多数 GNOME 核心开发者只以 Linux 为开发平台”系无证据的个人推断，仅据邮件列表观感（BSDTalk EP32，[347.14-445.46]，L1）
