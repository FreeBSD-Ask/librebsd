# 098.5.3 再回应——pkgng 引入后源码编译阵营的再批评

  **要点**：pkgng 于 FreeBSD 10.0（2014.1.20）成为默认软件包管理工具后，源码编译阵营的再批评沿三条线索展开——（1）“现代化”叙事的 Linux 中心主义：源码编译派指出，以 Debian apt、Red Hat yum/dnf 为“现代”标准评判 FreeBSD Ports 是一种形式主义误读，Ports 的 OPTIONS 机制（如 WITHOUT_X11、WITH_KERBEROS）提供的编译期定制是 Linux 二进制软件包管理器无法复制的核心价值，而非“落后”的遗留；（2）pkgng 迁移阵痛的实证：pkgng 1.x 早期版本（2014-2015）的数据库损坏、依赖解析 bug、jail 环境无限循环等问题被源码编译派援引为“旧系统未坏”的证据，部分生产用户推迟至 10.1/10.2/10.3 才完成迁移；（3）“二进制软件包丧失编译期优化”的哲学坚持：源码编译派认为，编译期优化（如针对特定 CPU 架构的 -march 优化、按需裁剪功能模块）是 BSD 传统自 4.4BSD 源码分发以来的核心哲学，二进制软件包以“便利”置换“自由定制”是以形式主义便利遮蔽实质自由

**史观**：总纲第 15 条——文化即形式主义：源码编译传统在“二进制现代化”叙事的形式主义化过程中被遮蔽与重构——Ports 的 OPTIONS 文化被重构为“遗留习惯”，编译期定制哲学被重构为“不便利”，传统在重构中被遮蔽；总纲第 21 条——革命与改革是历史方法论的分歧：Linux 阵营以“革命”方式（apt/yum/dnf 替换传统）推进软件包管理现代化，BSD 阵营以“改革”方式（pkgng 与 Ports 共存）保留源码编译传统——“改革的困难远高于革命”
  
**辨析**：考据过程留痕——【查证来源】freebsd-pkg 邮件列表 2014-2015 年归档经 <https://lists.freebsd.org/archives/freebsd-pkg/> 一手核验，邮件列表存档完整覆盖 2014-2015 年迁移期；pkg GitHub 仓库 Release Notes 经 <https://github.com/freebsd/pkg/releases> 一手核验，pkg 1.x 系列 release 历史完整可查；FreeBSD 10.0-RELEASE Announcement 经 <https://www.freebsd.org/releases/10.0R/announce/> 一手核验，原文措辞确认为“pkg(7) is now the default package management utility.”与"pkg_add(1), pkg_delete(1), and related tools have been removed."，发布日期 2014-01-20；freebsd.duckdb freebsd-src 仓库 commits 表提供 pkg_install 移除与 pkgng 替换的代码级证据（commit `632d9a080c7b2e3c6bb212694e042e01dcd6cf11` 与 `2ca1ee5764dc6e6662002ff6b2eb52f1fe807666`）；【交叉验证方法】pkgng 迁移阵痛的版本范围以三方证据交叉验证——（1）freebsd-pkg 邮件列表 2014-2015 年用户报告（社区一手）、（2）pkg GitHub 仓库 Release Notes（项目官方）、（3）freebsd.duckdb freebsd-src 仓库 commits 表（代码级），三方一致表明 pkg 1.x 系列在 10.x 全系列携带（10.0 约 pkg 1.2、10.1 为 1.3.8、10.2-10.4 为 1.5-1.10 区间）；“Linux 中心主义”批评的边界经多源考据——Ports 的 OPTIONS 机制（WITHOUT_X11、WITH_KERBEROS 等）确实提供二进制软件包无法复制的编译期定制，但 Debian apt 与 Red Hat yum 的设计并非以否定源码编译为目的，而是为解决大规模部署的工程问题，“Linux 中心主义”一词须谨慎使用；【0 信任原则·当事人自辩不免检】源码编译派的“旧系统未坏”论证存在自利偏差——pkgng 早期问题（数据库损坏、依赖解析 bug、jail 环境无限循环）虽真实存在但至 10.3-10.4 时期（pkg 1.8/1.9）趋稳定，以早期问题否定整个 pkgng 项目是过度推论；“编译期优化”（-march 等）在 2010 年代 x86-64 统一架构后边际收益递减，部分优化（PGO/LTO）可通过 ports 在构建时应用并产出二进制软件包，源码编译的“优化优势”在不同场景下差异巨大，须逐场景评估而非一概而论；【存疑判定依据】59.6.2 节辨析指出“2.10”版本号为误记，pkg 1.x 系列在 10.x 全系列携带的版本范围经 pkg 项目 release history 核实，但 pkg 1.2 在 10.0-RELEASE 中的精确版本号（是 1.2.0 还是 1.2.x）须以 10.0-RELEASE era 的 pkg 仓库 tag 进一步核验，本次考据未取得该 tag 的精确哈希，存疑标注；freebsd-pkg 邮件列表中关于“make install vs pkg install”的多条讨论虽交叉验证一致，但 0 信任原则提示“多源一致”不等于“客观正确”——源码编译派与二进制软件包派各自在邮件列表中形成回声室，社区信息茧房效应可能导致“多源一致”实为“回声一致”
