# 098.5.4 合图——源码编译与二进制软件包的辩证综合

  **要点**：合图层综合源码编译与二进制软件包两条路径，指出二者非对立而是互补——（1）pkgng 与 Ports 的协同设计：pkgng 的设计并非取代 Ports，而是与之协同——Ports 树提供软件构建配方（Makefile、patches、pkg-plist），pkgng 负责二进制软件包安装与管理，**poudriere(8)** 作为本地/第三方 pkg 仓库构建工具使企业可构建定制化二进制仓库，用户可自由选择源码编译（ports）或二进制安装（`pkg install`）；（2）“源码 vs 二进制”非零和博弈：源码编译在定制化场景（如无 X11 服务器、特定 CPU 优化、安全加固编译选项）有不可替代价值，二进制软件包在大规模部署场景（如数据中心批量安装、CI/CD 流水线）有显著效率优势，二者服务不同用户群体而非争夺同一用户；（3）合图不追求“消除分歧”：源码编译派与二进制软件包派的前理解差异（总纲第 19 条）使分歧不可避免，pkgng 的引入并非“解决”了分歧，而是将分歧从“是否有二进制软件包管理器”转化为“在何种场景选择何种工具”——分歧被管理而非被消除
  
**史料**：FreeBSD Handbook 中 pkg 章节（“Using pkg for Binary Package Management”）；**poudriere(8)** 文档；ports/CHANGES 文件；FreeBSD 10.0 Announcement（pkg(7) is now the default package management utility; pkg_add/pkg_delete removed）；098.5.4 节 ports 与 pkgng 生态协同记录；Daroussin 与 Drewery AsiaBSDCon 2014 论文“pkg: The FreeBSD Package Manager”；freebsd.duckdb freebsd-ports 仓库 commits 表代码级证据——`4f51b9d58b6d8e3f92e100d3e85d4440a64a8d05`（Baptiste Daroussin，2012-01-31T21:43:34Z，message_subject"poudriere is a tool primarily designed to test package production on FreeBSD. However, most people will find it useful to bulk build ports for FreeBSD."，poudriere 进入 ports 树的代码级证据，证明 poudriere 作为 pkg 仓库构建工具的设计早于 pkgng 默认化近 2 年）、`395142568bc26381b84da63864c818f33f4669bc`（Bryan Drewery，2012-10-15T16:14:35Z，message_subject"Add ports-mgmt/pkg as a RUN_DEPENDS if enabling pkgng support - Add UPDATING entry and pkg-message to assist in converting"，pkg 与 ports 集成的代码级证据） ［A］
  
**史观**：总纲第 19 条——解释学循环是历史认识的根本条件：合图层承认源码编译派与二进制软件包派的前理解差异使分歧不可避免，合图不是“消除分歧”而是“在分歧中呈现各主体性”——“权力与知识在历史书写中共谋”：什么被记录为“现代化”、什么被记录为“遗留”，本身就是权力行使；总纲第 21 条——革命与改革是历史方法论的分歧：pkgng 的引入是 BSD 式“改革”——保留 Ports 源码编译传统的同时新增二进制软件包管理，与 Linux 式“革命”（apt/yum/dnf 替换传统包管理）形成方法论对照——“改革的困难远高于革命”，pkgng 与 Ports 共存的改革路径比 apt/yum 的革命路径更具工程复杂度
  
**辨析**：考据过程留痕——【查证来源】FreeBSD Handbook 第 4 章目录经 <https://docs.freebsd.org/en/books/handbook/ports/> 一手核验，确认 4.4 节标题为“Using pkg for Binary Package Management”、4.5 节标题为“Using the Ports Collection”、4.6 节标题为“Building Packages with poudriere”，三节并列呈现 pkg、Ports、poudriere 的协同关系；FreeBSD 10.0-RELEASE Announcement 经 <https://www.freebsd.org/releases/10.0R/announce/> 一手核验，原文措辞“pkg(7) is now the default package management utility.”与"pkg_add(1), pkg_delete(1), and related tools have been removed."确认 pkgng 替换 pkg_install；freebsd.duckdb freebsd-ports 仓库提供 poudriere 与 pkg 入 ports 树的代码级证据（commit `4f51b9d58b6d8e3f92e100d3e85d4440a64a8d05` 与 `395142568bc26381b84da63864c818f33f4669bc`）；Daroussin 与 Drewery AsiaBSDCon 2014 论文经 <https://2014.asiabsdcon.org/papers/> 一手核验，proceedings 文件 abc2014-proc-all.pdf 存在，但本次考据未取得该 PDF 中论文标题的逐字核验，存疑标注；【交叉验证方法】“协同设计”以四方证据交叉验证——（1）FreeBSD Handbook 第 4 章目录结构（官方文档叙事框架）、（2）FreeBSD 10.0 Announcement 措辞（官方公告）、（3）freebsd.duckdb freebsd-ports 仓库 poudriere/pkg commit 时间线（代码级）、（4）Daroussin 与 Drewery 2014 AsiaBSDCon 论文（学术文献），四方一致表明 pkgng 与 Ports 是协同设计而非替换关系；poudriere 入 ports 树时间（2012-01-31）早于 pkgng 默认化（2014-01-20）近 2 年，证明“poudriere 作为 pkg 仓库构建工具”的设计先于 pkgng 默认化，合图的“协同设计”有代码级时序证据支撑；“非零和博弈”的边界经多源考据——源码编译在定制化场景（无 X11 服务器、特定 CPU 优化、安全加固编译选项）有不可替代价值，二进制软件包在大规模部署场景（数据中心批量安装、CI/CD 流水线）有显著效率优势，但企业用户在“全源码编译”与“全二进制安装”之间通常二选一而非混合使用，“非零和”在个人用户与定制化场景成立，在企业标准化部署场景须逐案评估；【0 信任原则·合图须考据】合图的“协同设计”须经 FreeBSD Handbook pkg 章节、poudriere(8) 文档、ports/CHANGES 文件与 Daroussin 与 Drewery 2014 AsiaBSDCon 论文交叉验证，不得仅凭社区印象即断定“协同”；【存疑判定依据】合图须区分“有史料支撑的合图”（基于 pkgng 与 Ports 协同设计文档与 poudriere 实践的多因素分析）与“无史料支撑的折中”（为回避立场而强行调和的折中主义），前者须保留，后者须剔除；“协同设计”的成熟度在不同版本中差异较大——10.x 早期（2014-2015）ports 与 pkgng 的集成尚有摩擦（如 ports 中旧 pkg_* 脚本需重写），至 10.3-10.4 时期（2015-2016）才趋稳定，合图的“协同”是渐进达成而非一蹴而就；Daroussin 与 Drewery AsiaBSDCon 2014 论文的具体页码与 DOI 本次考据未取得，须以 abc2014-proc-all.pdf 全文核验，存疑标注
