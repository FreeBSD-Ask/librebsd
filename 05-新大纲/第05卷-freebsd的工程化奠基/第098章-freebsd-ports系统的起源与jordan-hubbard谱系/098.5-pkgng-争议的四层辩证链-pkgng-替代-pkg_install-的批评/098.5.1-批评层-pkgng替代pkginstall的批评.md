# 098.5.1 批评层——pkgng 替代 pkg_install 的批评


> 本节完整呈现 pkgng 替代 pkg_install 的四层辩证链——批评层（89.5.1，传统 Ports 用户的适应阵痛、pkgng 早期不稳定性、生态迁移成本）、反批评层（89.5.2，pkg_install 技术债务、pkgng 工程必要性、二进制软件包管理现代化需求）、再回应层（89.5.3，pkgng 默认化后源码编译阵营的再批评）、合图层（89.5.4，源码编译与二进制软件包的辩证综合）。038.4 节梳理了源码编译 vs 二进制软件包的哲学分歧作为批评层的前置语境，038.6 节呈现对 Ports 源码编译哲学的外部批评作为反批评层的外部参照。

  **要点**：pkgng 替代 pkg_install 的批评沿三条线索展开——（1）传统 Ports 用户的适应阵痛：FreeBSD 自 2.2.2-RELEASE（1997）起以 **pkg_add(1)**、**pkg_delete(1)**、**pkg_info(1)**、**pkg_create(1)** 构成的 pkg_install 工具集为二进制软件包管理工具，用户与管理员历经十余年形成的操作习惯、shell 脚本自动化、文档体系在 pkgng 引入后须全面重写，`pkg add`、`pkg remove`、`pkg info` 的子命令语义与 pkg_install 的命令行接口不兼容，迁移成本由用户承担而非项目承担；（2）pkgng 早期的不稳定性：pkgng 以 beta 状态进入 ports 树（commit `df0aa973b92158277cba7de4b3058c07ad970fd3`，Baptiste Daroussin（巴蒂斯特·达鲁桑），2012-01-30，message_subject“Please welcome pkgng beta1.”），beta 版本工具被定为未来默认引发对生产环境稳定性的质疑，pkgng 1.x 系列（2012-2014）的 SQLite 数据库损坏、依赖解析缺陷、`pkg bootstrap` 自举失败等问题在 freebsd-pkg 邮件列表与 pkg GitHub Issues 中有记录；（3）生态迁移成本：第三方软件包仓库镜像须从 tarball 分发迁移至 SQLite 仓库格式，FreeBSD Handbook 须重写 pkg 章节，自动化运维脚本与配置管理工具（Puppet、Chef、Ansible 的 FreeBSD 模块）须适配 pkgng API，迁移的工程成本由整个生态承担
  
**史料**：freebsd-pkg 邮件列表 2012-2014 年归档（pkgng beta 与 1.x 早期问题报告）；pkg GitHub 仓库 Issues（SQLite 数据库损坏、依赖解析缺陷、bootstrap 自举失败等早期 issue）；FreeBSD 10.0-RELEASE Announcement（2014-01-20，pkg(7) is now the default）；freebsd.duckdb freebsd-ports 仓库 commits 表代码级证据——`df0aa973b92158277cba7de4b3058c07ad970fd3`（Baptiste Daroussin，2012-01-30T12:39:14Z，“Please welcome pkgng beta1.”，pkgng 以 beta 状态进入 ports 树的代码级证据）；freebsd.duckdb freebsd-src 仓库 commits 表代码级证据——`9b953f2ce40fb43141ad280a365d4f41ee06b3b1`（Baptiste Daroussin，2013-07-12T23:11:17Z，“Disable building of pkg_install by default”，pkg_install 默认禁用的代码级证据，证实迁移在 pkgng 稳定前即已启动） ［A］
  
**史观**：总纲第 13 条——法律与道德是利益分配：pkgng 替代 pkg_install 的“现代化”叙事以技术进步为名义，但迁移成本由用户与生态承担而非项目承担，本质是利益分配问题——“任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物”；总纲第 15 条——文化即形式主义：pkg_install 工具集十余年形成的操作文化在“现代化”叙事的形式主义化过程中被遮蔽与重构——用户的操作习惯被重构为“遗留习惯”，自动化脚本被重构为“技术债务”
  
**辨析**：考据过程留痕——【查证来源】freebsd-pkg 邮件列表 2012-2014 年归档经 <https://lists.freebsd.org/archives/freebsd-pkg/> 一手核验，覆盖 pkgng 从 beta 进入 ports 树（2012-01-30）到默认化（2014-01-20）的完整周期；pkg GitHub 仓库 Issues 经 <https://github.com/freebsd/pkg/issues> 一手核验，早期 issue（SQLite 数据库损坏、依赖解析缺陷、bootstrap 自举失败）可查；FreeBSD 10.0-RELEASE Announcement 经 <https://www.freebsd.org/releases/10.0R/announce/> 一手核验，原文措辞“pkg(7) is now the default package management utility.”与"pkg_add(1), pkg_delete(1), and related tools have been removed."；freebsd.duckdb freebsd-ports 仓库提供 pkgng beta 入 ports 树的代码级证据（commit `df0aa973b92158277cba7de4b3058c07ad970fd3`），freebsd-src 仓库提供 pkg_install 默认禁用的代码级证据（commit `9b953f2ce40fb43141ad280a365d4f41ee06b3b1`）。【交叉验证方法】“beta 状态进入 ports 树”以三方证据交叉验证——（1）freebsd.duckdb commits 表 commit body“Please welcome pkgng beta1.”（代码级）、（2）freebsd-pkg 邮件列表 2012 年 1 月讨论（社区一手）、（3）pkg GitHub 仓库 Release Notes（项目官方），三方一致表明 pkgng 以 beta 状态进入 ports 树；“迁移成本由用户承担”的论断经 freebsd-pkg 邮件列表中用户报告交叉验证——多个独立用户报告脚本失灵、操作习惯不适配，但“由用户承担而非项目承担”是史家对利益分配的诠释，非当事人直接表述 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］。【0 信任原则·当事人自辩不免检】批评方存在自利倾向——部分批评来自源码编译派对二进制软件包管理一贯的抵制立场，“beta 不稳定”的批评可能放大早期问题而忽视 pkgng 至 1.4/1.5（2014-2015）已趋稳定的事实；但 commit `df0aa973b92158277cba7de4b3058c07ad970fd3` 的 commit body“beta1”与 commit `9b953f2ce40fb43141ad280a365d4f41ee06b3b1` 的“Disable building of pkg_install by default”时间差仅约一年半（2012-01-30 至 2013-07-12），pkg_install 默认禁用时 pkgng 仍处早期，批评方的“过早迁移”担忧有代码级时序证据支撑。【存疑判定依据】“生态迁移成本”的量化须以 FreeBSD Handbook 版本比对、第三方镜像迁移记录、配置管理工具 changelog 进一步交叉验证，本次考据未取得 Handbook 历史版本与镜像迁移记录，存疑标注；0 信任原则提示：多源交叉验证不可靠性规则——freebsd-pkg 邮件列表中多条批评虽交叉验证一致，但社区信息茧房效应可能导致“多源一致”实为“回声一致”
