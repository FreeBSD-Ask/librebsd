**要点**：

- Smith 以首席发布工程师身份描述流程全貌：决定发布后进入代码冻结，阻止开发者添入新功能而专注收尾，随后切出发布分支并做测试构建（自 beta 起），此间一切代码改动须经发布工程团队批准方可提交，由该队裁量何者为必须先行解决的拦路问题、何者留待未来版本；经候选版本测试合格方正式发布，同一团队同时操办 6.3 与 7.0 两个发布；版本号语义上，次版本号系列内竭力维持 ABI 与 API 不变，主版本号变更则一切约束解除，允许要求重编译的剧变与新子系统进场。（BSDTalk EP142，[106.80-241.68]，L1）
- 7.0 并无单一中心目标，主旋律是自 FreeBSD 5 起延续至今的 SMPNG 倡议进入性能阶段：内核已大体具备 SMP 能力，开发者转而剖析锁的落点与次序以求削减瓶颈；Kris Kennaway（转写误作 Chris Kenoway）的基准测试被用作定位与验证工具，部分基准较 Linux 领先约 15%，但 Smith 明确拒绝将其外推为全面优势，并举例基准互动的健康竞争——Kennaway 曾发现 Linux 侧异常行为、经提出后由对方修复。 [存疑脚注] 基准测试者人名系据上下文（基准与瓶颈分析）辨识为 Kris Kennaway，转写原文作 Chris Kenoway，待与其他史料核对（BSDTalk EP142，[414.06-664.64]，L1）
- 7.0 的两项悬置：ULE 调度器仅以毫厘之差未成默认，被喻为“稍晚了些的选择性手术”，7.1 大概率转正；DTrace 则因拟议中思科方面感兴趣的合同工作告吹而搁浅，未能进入 7.0，仍在与有意者接洽。支持矩阵上，ZFS 不向 6 系列回移而性能改进择要回移，开发者重心在 7；5 系列仅余安全团队短暂维护、不再出新版；Linux 兼容层默认仍对 2.4 内核，2.6 支持有进展但尚有缺陷与缺项、未达默认水准；7 的改进大体利于服务器，桌面用户须自行重编译内核换用 ULE 方得其利。（BSDTalk EP142，[467.00-721.20]，L1）
- core 成员给出 FreeBSD 7 的性能叙事：SMP 工作在 5 分支完成、在 6 分支真正可用、到 7 开始快速扩展，系统开箱即能吃满多核；7 是里程碑，在多项关键基准上定期胜过 Linux，不再是追赶姿态；本次项目还学会制作公众关心的基准图表并向企业与开源出版物传播，与以往赢得性能却不宣传形成对照。（BSDTalk EP152，[298.54-343.10]，L1）
- 性能工作的下一步在用户态：在 FOSDEM 上 BSD 与 PostgreSQL 开发者同室共处一日讨论性能议题，PostgreSQL 开发者对其软件在 FreeBSD 上的表现明显优于其他平台感到惊喜，并看到向 FreeBSD 提交内核改进以进一步提速的机会；内核侧已尽力，数据库等用户态组件的争用处理成为下一个协作面。（BSDTalk EP152，[634.20-679.00]，L1）
- 嵌入式格局转型：嵌入式处理器（ARM、PowerPC、MIPS）走向多核，多年高端计算的 SMP 问题随之进入嵌入式领域，FreeBSD 7 已含 PowerPC 与 ARM 支持（MIPS 未及）；公司消费者以行动回馈——Juniper 交出其自持多年的 MIPS port，一家转写作 Timing Solutions 的公司贡献 ARM 支持；BSDL 不强制回馈，但升级到 6/7 的公司发现回馈共同基础设施可换来更低维护成本、他人代为维护与既已修复的 bug，遂保留产品竞争力部分而回馈其余。（BSDTalk EP152，[343.10-571.32]，L1）
- 桌面易用性是项目自认短板：安装器与管理工具长期被资深开发者忽视，因其工作环境多为大规模部署而非装机；对策包括 Ivan Voras 的图形安装器 finstall（Google Summer of Code 赞助，当年约 20 名受资助学生）、PC-BSD 在桌面方向的推进、Java 问题解决后桌面体验改善；PC-BSD 还迫使项目重新审视高级显卡驱动，项目层面正与 NVIDIA 洽谈以跟上其最新硬件。（BSDTalk EP152，[694.48-940.10]，L1）
- FreeBSD 8 前瞻：Marko Zec 的虚拟网络栈（萨格勒布大学研究项目，曾在 USENIX 年会发表，经 FreeBSD Foundation 与另一机构资助两年更新至 7）计划随 8 发布，本质是大幅增强的 jail——每个 jail 可有自己的防火墙与限速、管理粒度更细；配套 Sun ZFS 的可容器化文件系统、Sam Leffler 的虚拟接入点（单一射频承载多 SSID，面向机场等无线服务商场景）、Ed Schouten 分阶段重写 TTY 层，DTrace 已由 John Birrell 提交部分至 head 并可能回合并至 7.1，SMP 与网络栈扩展性改进亦可从 8 分支合并回 7.1，而网络栈虚拟化因不兼容风险过大不回合并。（BSDTalk EP152，[1103.40-1441.58]，L1）

**史料**：

- 一手运维场景自述：布法罗纽约州立大学计算机系以 FreeBSD 兼营生产与教学，有八处理器 64 位系统承担网页、FTP 与视频处理负载，系统管理员即 Smith 本人且执教高级内核课程；其跨大版本升级惯用源码树更新后整体重建安装，第三方软件以 portupgrade 从源码跟进，并期待以 ZFS 改造系内大容量存储服务器。（BSDTalk EP142，[262.20-364.80]，L1）
- 8-CURRENT 期的组织性一手节点：7.0 发布、API 冻结之后，开发者随即开启 FreeBSD 8 的自由议题，其中 jail 基础设施改进讨论已于受访前两周启动，jail 被评“立了大功但已见老”；与 PC-BSD、DesktopBSD 等衍生项目的发布团队则几乎不相往来，Smith 自承沟通是其短板并有意改善。（BSDTalk EP142，[737.68-798.68]，L1）
- 本期为 BSDCan 2008 现场对 FreeBSD core team 部分成员（Brooks Davis、Philip Paeps、Warner Losh、George Neville-Neil、Murray Stokely、Robert Watson）的集体一手口述，涉及开发者峰会与 release engineering 时间表、FOSDEM 的 BSD 与 PostgreSQL 联席会、Marko Zec 的 USENIX 论文、Google Summer of Code 学生数、freebsd-update 用户测试统计等可核查线索，人名与机构多处误转需以音频核对。（BSDTalk EP152，[0.00-66.62]，L1）

**史观**：

- 总纲10 动手者创造历史：发布工程师的自我刻画是协调者与守门人而非明星编码者：发布周期内只亲手修唯他能修的缺陷，其余时间用于审阅他人工作，非发布期方有余裕写码——发布质量被组织为对众人之工的裁断与串接，历史由大量无名提交与其裁决流程共同完成。（BSDTalk EP142，[838.76-858.14]，L1）
- 总纲12 科学是形式主义：Smith 对 15% 领先数字的自我节制——强调基准只是改进工具、拒绝作出“处处优于 Linux”的普遍断言——显示项目内部对形式化度量的效力边界有自觉：数字是组织工程的手段，不是世界结构的陈述。（BSDTalk EP142，[612.12-644.24]，L1）
- 总纲3 不存在进步，只有权力再分配：core 成员自述治理机制：每两年选举新 core team，候选人向社区陈述立场后全员投票，选举因欧洲假期常拖过夏季，至 2008 年已是约第八届选举产生；其自我定位不在于宣称进步，而在于人事权力的周期性再分配——领导来去，实践与社会模型则须保证项目在更迭中自我延续。（BSDTalk EP152，[1441.58-1515.78]，L1）

**辨析**：

- Smith 转述老一辈开发者间流传的“奇数版本魔咒”：FreeBSD 3 与 5 两个主版本皆非项目佳话，故社区期望 7.0 破除趋势。此属把成败经验凝结为魔咒的社区俗信，主版本号本身并不构成失败原因，恰是典型的把偶然处境误作规律的叙事，版本评价须回到各版本具体工程事实。（BSDTalk EP142，[924.82-940.82]，L2）
- 转写人名与机构多处受损（Warner Losh、George Neville-Neil、Marko Zec、John Birrell、Ivan Voras、Sam Leffler、FOSDEM、finstall、ZFS 等），引用须以音频与原始文献核对；击败 Linux 的基准说法为 core 成员自述且未给出具体数据，需对照 2008 年公开基准报告验证；ARM 贡献公司名 Timing Solutions 与 vimage 资助方 LNET 的真实身份待考。 [存疑脚注] 基准优势为当事方自述；Timing Solutions 与 LNET 两个机构名转写不可靠，身份待考。（BSDTalk EP152，[343.10-436.70]，L4）
