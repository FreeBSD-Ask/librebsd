# 100.2.11 JulianElischer一手自述其BSD起点1990年入职TRW在基于VME

- Julian Elischer 一手自述其 BSD 起点：1990 年入职 TRW，在基于 VME 总线 68030 的图像处理服务器群上运行 BSD 4.3；公司为降级到 x86 工作站而采用 Mach 系统——即 CMU 将其微内核研究成果嫁接 BSD 4.3 之上、保留原文件系统与网络栈的产物；x86 与 68030 的大小端差异令他迅速领教网络栈中字节序转换函数存在的理由。因 Mach 无 SCSI 支持，他为 Mach 编写了 SCSI 子系统，随后将其移植入 386BSD，该代码成为 FreeBSD SCSI 子系统的基础，后由 Justin Gibbs 等人重写；他声称其残留文件与署名至今仍存于 FreeBSD、NetBSD 与 OpenBSD 之中。（BSDTalk EP165，[508.86-588.84]，L1）
- 386BSD patchkit 时期的协作形态由当事人还原：Bill Jolitz 与 Lynn Jolitz 因家庭危机淡出后，开发者群体自行维护官方补丁集，无版本控制工具，参与者复制源码树制作 diff 汇入补丁集；Julian 在 TRW 金融系统的外部网络上架设服务器，向所有愿意工作的人开放账号。1993 年他返澳期间 Jordan Hubbard 等人分叉出 FreeBSD，他将其定性为组织性争论而非技术争论；NetBSD 更早分叉、性质偏技术，诉求是获得 CVS 树与更好的支持结构。Jolitz 夫妇最终因家庭变故（他提及 Bill 父亲去世等）彻底退出，FreeBSD 从此自立。（BSDTalk EP165，[359.28-477.40]，L1）
- Whistle Communications（1996 至 1999）是其总结的“以 BSD 解决问题、开发成果回流 FreeBSD”模式的典型：小企业一体机被当事人称为盒装 IT 部门，公司被 IBM 收购后产品线遭整体关停，当事人形容为花费约 1.2 亿美元买下再关掉的怪异决策；该时期回流 FreeBSD 的成果包括以合同委托 McKusick 移植的 soft updates、Divert Sockets、NetGraph 子系统与 AppleTalk 栈。对“BSD 许可证纵容企业只取不予”的担忧，他以跨公司经验给出系统性反驳：回馈即由社区维护、代码保鲜，NetGraph 首次提交仅约 12 个模块、如今 50 至 60 个模块大多出自他人之手，回馈即省钱；竞争对手若已自行实现同类功能，将己方代码回馈入主线会抬高对手门槛，拖延三年则可能错失窗口——对手正解决同一问题，谁先回馈谁的定义成为事实标准，故总有理由尽快回馈。（BSDTalk EP165，[884.96-1081.76]，L1）
- TRW 分部管理层强推 COTS（商用现货）路线的教训由当事人痛陈：以改用 Windows NT 与 Sun 服务器、把工程师从百人裁至五十人为诱饵的论证，被其斥为似是而非——采用 COTS 即接受所有公司共有的 COTS 局限，公司从能做出差异化产品的 vendor 沦为 me-too vendor。此前自研系统曾以 15.5K 巨型帧穿过作局部总线用的以太网、专用驱动将包直接写入内存缓冲馈入磁盘、几乎无 CPU 干预，一台 68030 即可打满六七条以太网；自造成本 1.5 万美元售 7 万美元，而改用 Sun 方案后需三倍硬件，24 万美元的 Sun 设备以 18 万美元亏本竞标。管理层的省钱承诺从未兑现。（BSDTalk EP165，[1223.02-1367.42]，L1）
- IronPort（2005 年加入，后被 Cisco 收购）延续同一人群与同一模式：设备为 Dell 硬件，其 AsyncOS 即标准 FreeBSD 加一层异步事件驱动、协作式线程的 Python 运行时；内部沿用 Whistle 时代的引导块实现双 root 分区、下载写入备用分区失败即回退的升级机制，当事人认为其在该功能上仍优于现行 FreeBSD 引导块。因所有改动回流主线，公司升级路径顺畅：4.8、6.1、6.3、再到等待中的 7.1，自研补丁先入 current 再回稳定分支，抵达新分支时补丁已在其中；反例是 Nokia 因对 FreeBSD 魔改过深而长期困守 2.0，待需 SMP 升级至 6.0 时付出巨大代价。（BSDTalk EP165，[1497.22-1710.10]，L1）
- Cisco 收购后的组织生态由当事人描述：IronPort 并入安全技术业务单元 STBU，原 IronPort 首席执行官接管 STBU，被当事人形容为一场宫廷政变，STBU 现近乎 IronPort 的放大版。收购消息令 Linux 工程师担心被迫转 BSD、BSD 工程师担心被迫转 Linux，管理层回答均为否定；BSD 在 Cisco 内部渐获尊重。当事人还透露 Cisco 内部曾有项目考虑采用 BSD，被 Linux 派以政治手段阻止，理由包括采用 BSD 会“验证 Juniper 选择 BSD 的正确性”；Cisco 设有开源监督流程，要求报告所用开源组件并核验许可证，其对 Cisco 大量采用 Linux 的 GPL 合规持保留态度。（BSDTalk EP165，[1790.74-1888.62]，L1）

**史观**：

- 总纲9 经验优先：当事人反复以工程师经验对抗管理层的抽象成本论证：COTS 转型的纸上省钱方案在他看来完全站不住脚，因为真实性能、可维护性与差异化能力只存在于一线动手者的实践 knowledge 之中；TRW 由领先者沦为跟随者的过程，正是管理层以公式化推理覆盖工程经验的后果。技术决策的正当性来自动手者的经验，而非报表上的论证。（BSDTalk EP165，[1265.06-1292.04]，L1）

**辨析**：

- 转写音译误植须按上下文考订：Mark 应为 Mach（微内核嫁接 BSD 4.3 的 CMU 系统，对应 Mach 2.5 形态）、E-Melon 应为 CMU、Scuzzy system 即 SCSI 子系统的诨名、Jollitz 应为 Jolitz、McCusick 应为 McKusick、Freeride 6BSD 与 previous D 等均应为 FreeBSD、VSD 为 BSD；自称“QWERTY member”不可考，按其自述语境仅为“始终在场的老资格长期开发者”。IBM 收购 Whistle 的 1.2 亿美元金额系当事人单方回忆，Vycor 后续买家转写不清，均待外部文献核验。[存疑脚注] 涉及金额、人名拼写与公司归属的细节仅有一手口述孤证。 [存疑脚注] Mach、CMU 为按上下文考订；1.2 亿美元收购金额与 Vycor 买家名无法自转写内证确证，需以新闻报道与公司档案复核。（BSDTalk EP165，[249.52-277.48]，L4）
