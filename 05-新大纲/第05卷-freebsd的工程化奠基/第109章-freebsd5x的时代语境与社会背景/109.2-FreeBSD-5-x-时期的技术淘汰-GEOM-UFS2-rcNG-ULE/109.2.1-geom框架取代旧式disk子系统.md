# 109.2.1 GEOM 框架取代旧式 disk 子系统

  **要点**：FreeBSD 5.0-RELEASE（2003 年 1 月 16 日，release/5.0.0 tagger_date = 2003-01-16T16:56:23Z）引入 GEOM（Geometric Modular Disk Framework）框架，由 Poul-Henning Kamp（波尔-亨宁·坎普） 设计实现，取代 4.x 时代分散的 disk 子系统（包括旧式 disklabel、slice、BSD disklabel、Vinum）；GEOM 采用模块化 class 与 provider/consumer 模型，把磁盘 I/O 抽象为可堆叠的 transformation 链——如 gmirror（镜像）、gstripe（条带）、gconcat（连接）、geli（加密）、gbde（块加密）、gjournal（日志）、gpart（分区）等 class 各自提供独立功能；GEOM 取代旧式 disk 子系统的原因是 4.x 时代的 disk 子系统过于分散，难以支持现代存储需求（如软 RAID、加密、多路径）；GEOM 至今仍是 FreeBSD 的标准磁盘抽象层，Vinum 于 5.x 开发周期启动向 GEOM 之上的迁移（gvinum），约 6.0 前后落地；gvinum 最终在 FreeBSD 15.0（2025 年 11 月 tag、12 月初发布）完全移除
  
**史料**：FreeBSD 5.0-RELEASE Release Notes (2003.1) GEOM 章节、Kamp BSDCon 2002 “GEOM” 演讲、geom(4) 手册页、FreeBSD Handbook “GEOM” 章节；freebsd.duckdb freebsd-src 仓库 tags 表 release/5.0.0 的 tagger_date = 2003-01-16T16:56:23Z（target_commit_hash = 47227ef0ef663b7abb81ab5a60a450da9a93d24b） ［A］
  
**史观**：总纲第 4 条——分离与聚合：GEOM 通过模块化 class 分离存储功能，通过 provider/consumer 链聚合为完整磁盘 I/O 路径；总纲第 15 条——文化即形式主义：GEOM 的可堆叠设计是软件工程对存储子系统模块化的典型实现
  
**辨析**：经 freebsd.duckdb tags 表验证，5.0-RELEASE 的 tagger_date 为 2003-01-16（非旧叙事 2003.1.19，误差 3 天，可能为公告日期与 tag 日期差异）；GEOM 是否真正 “取代” 旧 disk 子系统需考据——5.0 引入但 4.x 的 disk 子系统仍保留兼容直至 7.x；GEOM 与 Linux device mapper（2002 年随 2.5 内核引入）的设计差异需对照论文核实
