# 109.6.4 网络服务与内核安全修复合并叙述——syncookies 改进、TCP RST 处理、l2tp/ftpd/isc-dhcpd/zlib/mmap/xe(4) 漏洞群

  **要点**：5.x 版本周期内中低风险安全修复涉及网络服务与内核多组件——2003-01-16 David E. O'Brien（戴维·E·奥布赖恩） 提交 isc-dhcpd-3.0.1rc11 导入（commit `5ad7270f30563f9e223343950b9d85f78b3be537`，修复内置解析器库安全漏洞）；2003-02-04 Jacques Vidrine 提交 xe(4) 修复（commit `2c3e98f60f990eacfce207ae99e73ad60afb83f9`，文档说明该修复被意外 slip in）；2003-02-23 Jacques Vidrine 提交 syncookies 安全与性能改进（commit `e93e1ddabbb7febd6001b71685c6f0e1daa4d341`，MFC tcp_syncache.c 1.38，连续 2 条 MFC commit `81dad2e2de852b42d06b6ffdc71a024cad85a7ff`、`deb4c713c6e1fc49bd8cb611d97b170d453fe1ed`）；2004-01-13 Bill Fenner 提交 l2tp 漏洞修复（commit `b97c9af58ad5902b91f3e97c12ac18b76954b8e2`，引用 Przemyslaw Frasunek 在 bugtraq 邮件列表的报告）；2004-01-21 Jacques Vidrine 提交 CVS 安全修复（commit `c8ae5f056296ca06d45a165f9c8588a777b19a89`，从 CVS 1.11.11 NEWS 文件合并，另 commit `462959355ed47d58af97b5797d9f94eb55245e7d` 从 vendor branch 1.1.1.14 合并）；2004-04-25 Ken Smith 提交 mmap(2) 安全修复（commit `fd0b0325304f856319cdaea50b0342092035483c`，引用 Alan Cox 的工作，修复标记为 MAP_NOSYNC 的页面安全问题）；2004-08-18 David E. O'Brien 提交 ftpd 修复（commit `3a802515c66410d4be197709554a1888484563a8`，从 NetBSD CVS 仓库导入 LukeM ftpd，关闭远程可利用漏洞）；2004-08-26 Jacques Vidrine 提交 zlib DoS 修复（commit `521adbdfc74b5f8ee5c81fd5afa1188408cca87a`，2004-09-02 MFC commit `995c28950bf9c942e6b886401f75ca7eaff5dc25`）；2005-01-05 Mike Silbersack 提交 TCP RST 处理改进（commit `01e59d4dee6c039c714785a6949d444127843145`，MFC revs 1.235 与 1.264，改进 RST 处理安全性并添加 sysctl 回退机制，另 commit `4cf393bc356a046dd819fb5b3726360f63927cf5`）；上述修复覆盖 DHCP/网络驱动/SYN flood 防护/VPN/版本控制/内存映射/FTP/压缩库/TCP 协议栈等多个子系统，反映 5.x 转型期新组件引入与既有组件维护并行的安全响应负担

**史观**：总纲第 22 条——知识注定过时：5.x 时期既有组件（telnetd/ftpd/sendmail/CVS）的安全债务与新组件（GEOM/UFS2/MAC）的引入并行，安全响应负担叠加；专题语（不设总纲条号）——软件工程：MFC 多分支回溯模型在 5.x 时期成熟化——单一修复向 RELENG_4_x/RELENG_5_x 多分支回溯成为标准操作
  
**辨析**：上述修复均无 CAN/CVE 编号，但 commit message 明确引用漏洞报告来源（bugtraq 邮件列表、OpenSSL 公告、NetBSD CVS 等），按 0 信任原则交叉验证可采信；【架构关联】syncookies 改进与 TCP RST 处理改进直接关联 5.x 时期 SMPng 引入的网络栈锁改造——SMPng 细粒度锁使 TCP 同步队列（syncache）的并发暴露面扩大，syncookies 与 RST 处理的安全改进是对新攻击面的响应；mmap(2) 安全修复与 5.x 时期虚拟内存子系统改造（41.2 节〔存疑：旧 41 章节号，现行结构无对应节，重挂待考〕所载 SMPng）相关——SMPng 锁改造可能引入新的内存映射竞争窗口；【commit 量比较公平性】80 条 security fix commit 中约 30 条涉及 4.x 分支 MFC 回溯（如 RELENG_4_7/4_8/4_9/4_10/4_11），5.x 本身的新增安全修复约 50 条，月均 2.27 条/月，低于 4.x 的 3.09 条/月——这一下降可能反映 5.x 转型期社区工程资源集中于 SMPng/GEOM/KSE 等架构改造而非安全响应
