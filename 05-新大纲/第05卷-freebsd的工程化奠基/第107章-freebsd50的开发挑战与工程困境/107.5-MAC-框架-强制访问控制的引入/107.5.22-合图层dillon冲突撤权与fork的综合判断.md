# 107.5.22 合图层：Dillon 冲突、撤权与 fork 的综合判断

  **要点**：综合 Dillon 与 Core Team 双方立场，5.x 时期的 Dillon 冲突、撤权与 DragonFly fork 事件并非单纯的 “个人性格冲突” 或 “路线对错”，而是 BSD 谱系在 SMP 现代化转型期 “分离聚合” 规律的必然呈现。Core Team 的 SMPng 细粒度锁路线与 Dillon 的 LWKT 无锁路线代表对多核未来的两种诚实判断——前者选择渐进改造但付出 5.x 早期性能倒退代价，后者选择激进重构但付出集群目标放弃代价；二者在 2003 年的技术语境下均非显然正确。撤权事件本身是组织权力对个人路线的终止，但 BSD 许可证使 fork 成为 “制度化的和解”——Dillon 携 4.x 代码另起 DragonFly，双方在代码层面保持法律上的和平。合图层不判定 “谁对谁错”，而呈现冲突作为 BSD 谱系演化张力的历史事实：FreeBSD 与 DragonFly 在本体论上地位相等，二者的分歧是 BSD 哲学多元探索的体现，而非零和博弈
  
**史料**：上述 41.9.1-41.9.5 节综合史料；Dillon 2003-07-16 DragonFly BSD 公告（freebsd-current 邮件列表，<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>）；DragonFly BSD 官方历史页面（<https://www.dragonflybsd.org/history/>）；FreeBSD 5.x/6.x/7.x Release Notes；freebsd.duckdb freebsd-src 仓库 Dillon commit 时间线（首条 1998-08-26T01:58:39Z、末条 2003-01-28T18:44:40Z，共 1027 条）；dragonfly.duckdb dragonfly-src 仓库首条 commit（2003-06-17T02:57:24Z，commit_hash = 984263bcb83a） ［A］
  
**史观**：总纲第 4 条——分离聚合是永恒规律，DragonFly 从 FreeBSD 分离是 BSD 谱系分合循环的一环；总纲第 8 条——本体论上各方平等，FreeBSD 与 DragonFly 地位相等；终结与延续，fork 终结了 Dillon 在 FreeBSD 的贡献，延续了 BSD 哲学的多元探索
  
**辨析**：考据过程留痕——【查证来源】合图层基于现有公开史料综合判断，所引 Dillon fork 公告经一手核验（见 41.9.5 节辨析【查证来源】，<https://lists.freebsd.org/pipermail/freebsd-current/2003-July/006889.html>）；DragonFly 官方历史页面经一手核验（<https://www.dragonflybsd.org/history/>，含“forked from FreeBSD 4.8 in June of 2003 ”与集群目标放弃表述）；FreeBSD 5.x/6.x/7.x Release Notes 与 freebsd.duckdb tags 表交叉验证一致（release/5.3.0、release/7.1.0 时间戳已核实）；freebsd.duckdb freebsd-src 仓库 Dillon commit 时间线（首条 526f06b278d9252add168aa18b60242c08771165、末条 f959d237889c23cf709e1981c53a2ab62495a81a，共 1027 条）与 dragonfly.duckdb dragonfly-src 仓库首条 commit（984263bcb83a，2003-06-17T02:57:24Z）形成 fork 前后代码级证据链；【交叉验证方法】Dillon fork 公告（一手）、DragonFly 官方历史页面（一手）、freebsd.duckdb commits/tags 表（代码级证据）三方互证，确认 fork 启动时间（2003 年 6 月）、撤权时间（Dillon freebsd-src 末次 commit 2003-01-28）、fork 公告时间（2003-07-16）三者的时序关系；与第077章 70.3.7 节 NetBSD/OpenBSD fork 合图层的辩证结构对照，构成 BSD 谱系内两次主要 fork 事件（1995 OpenBSD fork、2003 DragonFly fork）的史观比较基础——OpenBSD fork 因人际冲突与治理分歧（前理解不可通约），DragonFly fork 因技术路线分歧（可通约但未妥协），二者不可调和性程度不同，史家须如实区分；【存疑判定依据】合图层须严格保持双方对称呈现，不得因 DragonFly 后续规模小于 FreeBSD 即判定其路线“ 失败 ”，亦不得因 FreeBSD SMPng 最终成熟即判定 Core Team“ 正确 ”；“ 制度化的和解 ”表述须以 BSD 许可证的实际法律框架为据，而非浪漫化 fork 事件；fork 的“ 必然性 ”仅指 BSD 谱系的结构性张力，不指 Dillon 个人离开的必然——后者属偶然（总纲第 5 条）；Core Team 撤权决定的内部决策记录未完整公开，合图层以公开史料为准，不对未公开内部决策作臆断，保留 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］；0 信任原则提示：合图层的“ 双方对称 ”是史家的方法论要求，不等于历史事实的对称——史家须诚实呈现史料不对称的事实（Dillon 的 fork 公告完整公开，Core Team 的撤权决议未公开），不得以方法论对称掩盖史料不对称；与第077章 70.3.7 节 NetBSD fork 合图层对照——NetBSD Core Team 通过 Adam Glass 1994-12-23 公开通知撤权（显性权力行使），FreeBSD Core Team 2003 年对 Dillon 的撤权呈现“ 隐性撤权 ” 特征（决议未公开），两种撤权模式在本体论上地位相等，但史料不对称程度不同，史家须如实区分
