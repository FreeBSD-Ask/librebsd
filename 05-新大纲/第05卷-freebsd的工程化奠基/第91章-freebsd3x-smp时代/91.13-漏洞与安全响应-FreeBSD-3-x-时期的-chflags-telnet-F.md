# 91.13 漏洞与安全响应：FreeBSD 3.x 时期的 chflags/telnet/FTP bounce 漏洞群与 SMP 过渡期安全基线（1998-2000）

## 91.13.1 chflags 权限绕过与 OpenSSH agent 转发漏洞——权限层与加密协议层漏洞

  **要点**：FreeBSD-SA-99:01.chflags（1999 年 9 月 4 日）记录 BSD File Flags 权限检查缺陷——**chflags(1)** 的权限检查存在漏洞，本地用户可绕过文件标志保护修改受保护文件，受影响版本为 FreeBSD 3.2 及更早版本，公告原文未引用 CVE 编号；FreeBSD-SA-01:01.openssh（2001 年 1 月 15 日）记录恶意 SSH 服务器可利用 OpenSSH agent 转发与 X11 转发漏洞攻击客户端——导致客户端用户权限被窃取，受影响版本为 FreeBSD 4.2-RELEASE（含 OpenSSH 2.3.0），该漏洞被编号为 CVE-2001-0144；FreeBSD-SA-00:21.ssh（2000 年 6 月 7 日）记录 ports collection 中 ssh 软件包端口 722 配置问题可能导致未授权访问；上述漏洞覆盖权限层（chflags 文件标志绕过）与加密协议层（OpenSSH agent/X11 转发），反映 FreeBSD 3.x 至 4.x 过渡期权限模型与加密服务基线的缺陷——chflags 为 4.4BSD 继承的文件标志机制，OpenSSH 为 3.x 时期新引入的加密服务，二者分别代表继承漏洞面与新引入漏洞面
  
**史料**：FreeBSD-SA-99:01.chflags 公告（freebsd.org/security/advisories/FreeBSD-SA-99:01.chflags.asc）、FreeBSD-SA-01:01.openssh 公告（CVE-2001-0144）、FreeBSD-SA-00:21.ssh 公告、CVE-2001-0144 NVD 条目 ［A］
  
**史观**：密码学与信息安全：chflags 权限绕过为 4.4BSD 继承漏洞面的延续，OpenSSH agent 转发漏洞为新引入组件漏洞面的代表；技术路线分化：FreeBSD 3.x 引入 OpenSSH 作为加密服务，与同期 OpenBSD 2.6（1999 年 12 月首次发布 OpenSSH）形成路径交叉
  
**辨析**：chflags 权限绕过的精确触发路径须对照 FreeBSD-SA-99:01.chflags 公告原文与 **chflags(2)** 手册页核实——公告仅称 “权限检查缺陷”，未详细说明绕过路径；CVE-2001-0144 的 CVSS 评分须对照 NVD 条目核实——版本周期文件未提取 CVSS 评分，史家不得臆造评分值；FreeBSD-SA-01:01.openssh 影响 FreeBSD 4.2-RELEASE，超出 FreeBSD 3.x 版本周期（1998-10 至 2000-03），但 OpenSSH 在 3.x 时期引入故归入本章叙事，史家须在叙事中明确版本归属；【0 信任原则·CVE 编号时序】CVE-2001-0144 编号年份为 2001 年，但 OpenSSH agent 转发漏洞的发现与披露可能早于 2001 年，史家须区分 “CVE 编号年份” 与 “漏洞披露年份”
  
**文献**：FreeBSD-SA-99:01.chflags 公告；FreeBSD-SA-01:01.openssh 公告；FreeBSD-SA-00:21.ssh 公告；CVE-2001-0144 NVD 条目；本项目。原材料/研究/bsd 漏洞史/版本周期/freebsd-3.x.md；本项目。原材料/研究/bsd 漏洞史/早期漏洞补遗/freebsd-早期漏洞.md ［A］

## 91.13.2 telnet -E 安全绕过、FTP bounce 攻击与 lpd/kern_descrip 修复——网络服务与内核描述符安全

  **要点**：1999 年 6 月 14 日 Ruslan Ermilov 连续提交两条 telnet 安全修复 commit（`0c4c7cf0a150e17093908db00b3b7c866ff6b238` 与 `2fa0b6edf0af52ffcd73b3ef633b7799e75f94b4`，commit subject 均为 "MFC: It was possible to circumvent telnet's security -E (no escape at all) option by running it"——telnet 的 `-E` 选项（禁用转义字符）可被绕过，用户可通过特定操作恢复转义字符能力，构成安全绕过）；1999 年 11 月 17 日 John Polstra 提交 commit `6b2bdf2c083d4f69ce5c25fb386e926ace4c6d19`（"Fix a bug in the hack that protects against FTP bounce attacks"——修复 FTP bounce 攻击防护中的缺陷，FTP bounce 攻击为攻击者利用 FTP 服务器 PORT 命令向第三方发起连接的攻击方式）；2000 年 1 月 25 日 Matthew Dillon（马修·狄龙） 连续提交两条 MFC 安全修复 commit（`0cbe72ab43d5b41ffcd67f81052635fa03ba5781` 修复 **lpd(8)** 缓冲区零填充错误、`00a6b0f08dbdd9ac33c84e544d61c952227f5878` 回溯 kern_descrip.c/kern_exec.c/filedesc.h 修复）；2000 年 2 月 24 日 Yoshinobu Inoue 提交 commit `53c9088f688ee6fee2a93029f8eb2612d7afd01c`（"Security fixes. (Just same as sbin/ping and usr.sbin/traceroute) -Open socket() at first and then drop root privilege"——**ping(8)** 与 **traceroute(8)** 的权限降级修复，先打开 socket 再丢弃 root 权限，为最小权限原则的工程实践）；上述漏洞覆盖网络服务绕过（telnet -E）、远程攻击防护（FTP bounce）、打印服务（lpd）、内核描述符（kern_descrip）与网络工具权限降级（ping/traceroute）五类技术机制
  
**史料**：freebsd.duckdb freebsd-src 仓库 12 条 security fix commit 完整记录（Ruslan Ermilov 1999-06-14、John Polstra 1999-11-17、Matthew Dillon 2000-01-25、Yoshinobu Inoue 2000-02-24 等）；FreeBSD 3.x Release Notes 安全章节 ［A］
  
**史观**：密码学与信息安全：telnet/FTP bounce/lpd/kern_descrip/ping 漏洞群覆盖网络服务与内核描述符多层，反映 FreeBSD 3.x 安全基线的多层缺陷；总纲第 10 条——动手者创造历史：Yoshinobu Inoue 的 ping/traceroute 权限降级修复体现最小权限原则的工程实践
  
**辨析**：telnet `-E` 绕过的精确触发路径须对照 Ruslan Ermilov 1999-06-14 commit diff 核实——commit subject 仅称 “可被绕过” 未说明绕过路径；FTP bounce 攻击防护缺陷的具体 bug 须对照 John Polstra 1999-11-17 commit diff 核实——commit subject 称 “Fix a bug in the hack” 表明原有防护存在缺陷；lpd 缓冲区零填充错误的细节须对照 Matthew Dillon 2000-01-25 commit diff 核实——commit subject 称 “The wrong buffer's last element was being zero”，表明零填充操作作用于错误缓冲区；【0 信任原则·MFC 回溯时序】Ruslan Ermilov 1999-06-14 与 1999-06-17 的 telnet 修复 commit 均为 MFC 操作，原始修复须在 -current 分支中查找，史家须区分 “原始修复时间” 与 “MFC 回溯时间”；【0 信任原则·commit subject 信息量限制】部分 commit subject（如 "Security fixes. (Just same as sbin/ping and usr.sbin/traceroute)"）通过类比说明修复内容而非直接描述漏洞机制，史家须对照被类比对象的修复 diff 间接核实

## 91.13.3 FreeBSD 3.x 安全响应的架构关联——SMP 引入、ELF 切换与 soft updates

  **要点**：FreeBSD 3.x 时期（1998-2000）的安全响应模型延续 FreeBSD 2.x 的 “Security Advisory + MFC 回溯” 双层结构，但版本周期内的架构变化为安全响应提供新维度——SMP 支持（3.0-RELEASE 引入初步 SMP，依赖 Giant Lock 粗粒度锁）带来内核并发访问的新漏洞面，kern_descrip.c/kern_exec.c 安全修复（Matthew Dillon 2000-01-25 commit `00a6b0f08dbdd9ac33c84e544d61c952227f5878`）可能涉及 SMP 并发场景下的文件描述符表竞争；ELF 切换（3.0-RELEASE 将 ELF 作为默认二进制格式）改变可执行文件加载路径，可能引入新的内存布局相关漏洞面；soft updates（McKusick 的文件系统元数据一致性保护设计）为文件系统操作提供一致性保证，间接减少文件系统竞争条件类漏洞；CAM SCSI 子系统（3.0-RELEASE 引入）重构存储设备访问路径，其引入可能伴随新的设备权限模型缺陷；FreeBSD 3.x 版本周期内 freebsd.duckdb 记录 12 条 security fix commit（无 CVE 编号），较 FreeBSD 2.x 的 40 条显著减少，反映 3.x 版本周期较短（1998-10 至 2000-03，约 17 个月）且架构重构期安全修复以 MFC 回溯为主
  
**史料**：freebsd.duckdb freebsd-src 仓库 12 条 security fix commit 完整记录、FreeBSD 3.0-RELEASE Release Notes（SMP/ELF/CAM/soft updates 章节）、McKusick soft updates 设计文档 ［A］
  
**史观**：密码学与信息安全：SMP 引入带来内核并发访问新漏洞面，ELF 切换改变可执行文件加载路径，soft updates 提供文件系统一致性保证，三者共同塑造 FreeBSD 3.x 安全基线的新维度；组织结构塑造技术路径：SMP/ELF/CAM/soft updates 的架构重构决定 3.x 时期安全响应的新特征
  
**辨析**：kern_descrip.c 安全修复与 SMP 并发访问的关联须对照 Matthew Dillon 2000-01-25 commit diff 与 FreeBSD 3.x SMP 锁模型核实——commit subject 称 “Backport fix”，未明确说明是否涉及 SMP 并发，史家须以 commit diff 为据而非臆造关联；ELF 切换对安全基线的具体影响须对照 FreeBSD 3.x ELF 加载器源码核实——ELF 切换主要影响二进制格式，对安全基线的影响为间接的（内存布局变化），史家不得以 “ELF 切换” 直接推论 “安全基线变化”；soft updates 对文件系统竞争条件漏洞的减少效果须对照 McKusick 设计文档与 FreeBSD 3.x 文件系统 commit 核实——soft updates 主要保证元数据一致性，对应用层数据竞争无直接影响；【0 信任原则·commit 量比较的公平性】3.x 的 12 条 security fix commit 较 2.x 的 40 条减少，但版本周期长度不同（3.x 约 17 个月 vs 2.x 约 45 个月），月均 commit 量分别为 0.71 条/月与 0.89 条/月，差异不显著，史家不得以绝对数量减少推论 “安全响应质量下降”
