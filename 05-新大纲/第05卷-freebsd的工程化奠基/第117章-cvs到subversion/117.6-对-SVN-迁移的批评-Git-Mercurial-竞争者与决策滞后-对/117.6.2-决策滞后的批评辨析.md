# 117.6.2 决策滞后的批评辨析

  **要点**：决策滞后批评：（1）8 年争论过长反映核心团队决策机制低效；（2）SVN 在 2008 年已显过时（Git 分布式优势明显）；（3）Wemm 强行推进反映共识机制的失败；（4）FreeBSD 后续 2019 年再迁 Git 是否印证 SVN 选择的失误
  
**史料**：邮件、社区讨论、2019 年 GitHub 迁移公告 [考据脚注：FreeBSD Git/GitHub 迁移（2020 年正式执行，2019 年公告启动）经 FreeBSD 官方公告与 freebsd.duckdb 中 SVN-to-Git 迁移痕迹交叉验证确证。]
  
**史观**：专题语（不设条号）：决策机制的形式主义是否阻碍技术演进（原“第 6 条——形式主义膨胀与抽象克制”与基线第 6 条“和解优于斗争”不符，按 R2140 先例——2026-09-12 整改）
  
**辨析**：8 年是否过长须与同期其他项目对比——Linux 内核 2002-2005 年用 BitKeeper，2005 年因许可证争议快速迁 Git（约 2 个月），NetBSD 2008 年探讨 SVN 但迁移动作迟缓；FreeBSD 8 年争论在三大 BSD 中最长，反映共识机制的时间成本；2019 年再迁 Git 不是事后诸葛亮——2008 年 Git 已是候选，2020 年迁 Git 是 Git 成为行业事实标准后的顺势而为，与 2008 年判断不矛盾
