# 115.11.4 DTrace 从用户态移植 → 内核原生支持（7.1 导入 → 8.0 内核支持）

  **要点**：DTrace 是 Sun Microsystems 为 OpenSolaris 开发的动态追踪框架（CDDL 许可证），由 Bryan Cantrill（布莱恩·坎特里尔）、Mike Shapiro、Adam Leventhal 设计；FreeBSD 项目由 John Birrell 主导 vendor import（原大纲称“由 John Baldwin 主导移植”不准确，详见辨析字段），FreeBSD 7.1-RELEASE（release/7.1.0 tagger_date = 2008-12-31T22:57:14Z，官方公告日期 2009.1.4）首次导入 DTrace 用户态工具与基础内核支持，作为实验性功能；John Birrell 于 2008-04-25 当日连续提交 5 条 vendor import commit，分别导入 DTrace app 与 test suite（commit `12456ea875a4e2a468753b9890e6864519aeb931`，2008-04-25T06:56:31Z）、libraries（commit `c53d354ffe3b3f603cf36c67c489eeeb881403b2`，2008-04-25T09:04:09Z）、CTF code（commit `38c68f8a196ef330599c13b5caa9d0bc5c5bff0c`，2008-04-25T09:07:28Z）、support files（commit `2de84d2572206157cf33d1fb75463eeb42ae8e42`，2008-04-25T23:33:18Z）、full userland contrib（commit `275928fc142e604d7d091feb5eff54c72f241964`，2008-04-26T00:54:52Z）；DTrace 文件首次引入 commit `144cd58d16b601d52d00c5a37c8e0226aa1ce55a`（John Birrell，2008-08-27T04:41:15Z，MFC）导入 `sys/cddl/contrib/opensolaris/uts/common/dtrace/dtrace.c`、`fasttrap.c`、`lockstat.c`、`profile.c`、`sdt_subr.c` 等核心文件；John Baldwin 于 2008-08-27T19:24:18Z 提交 commit `290984576da42d7f902c249bdc4842ad36d50c95` “Bump __FreeBSD_version to note DTrace MFC”，标志 DTrace 完成 MFC 整合；2008-08-29T18:54:35Z John Baldwin 提交 commit `2e39a10f0d47984da7ac7fae652f836752732af9` "Disable the KDTRACE options in GENERIC for now. They have not yet been enabled in HEAD, and they really need to be enabled..."，将 DTrace 选项从 GENERIC 内核配置中临时禁用；2008-08-29T20:18:56Z John Baldwin 提交 commit `89caa60525041ed249b823353d150f195ff3814f` "Don't build the dtrace tools during bootstrap tools for now and don’t build the kernel with CTF symbols by default"，禁用 dtrace 工具的 bootstrap 构建与内核 CTF 符号默认生成；移植工作通过 Perforce 仓库 `//depot/projects/dtrace/` 分支进行，John Birrell 维护“DTrace for FreeBSD”页面（people.freebsd.org/~jb/reasons/）记录所有改动；FreeBSD 8.0-RELEASE（2009.11.25）完善 DTrace 内核原生支持，包括 KDTRACE_HOOKS、DDB_CTF、KDTRACE_FRAME（amd64）等内核选项，CTF（Compact C Type Format）数据支持，以及 dtraceall 模块加载；FreeBSD 8.x 时期 DTrace 仍需手动加载内核模块（`kldload dtraceall`）并编译自定义内核（`options KDTRACE_HOOKS` 等）；FreeBSD 9.2 与 10.0-RELEASE（2013-2014）才将 DTrace 内建于 GENERIC 内核，模块在执行 `dtrace` 命令时自动加载；DTrace 与 Solaris 实现存在差异——FreeBSD 以内核模块组实现而非内建，dtmalloc provider 为 FreeBSD 独有（按 malloc 类型追踪），cpc/mib provider 未实现；DTrace 引入使 FreeBSD 获得生产级动态追踪能力，与 Linux SystemTap、ktrace/kdump 形成对照

**史观**：总纲第 24 条——许可证政治：DTrace 采用 CDDL 许可证，与 FreeBSD BSD 许可证存在兼容性限制，但 CDDL 允许 FreeBSD 集成 DTrace 模块（模块以 CDDL 发布，内核仍为 BSD）；BSD 与 UNIX 谱系的连续性：DTrace 移植延续 FreeBSD 吸收 Solaris 优秀技术（ZFS、DTrace）的传统
  
**辨析**：经 freebsd.duckdb commits 表验证，原大纲称“由 John Baldwin 主导移植”不准确——vendor import 由 John Birrell（<jb@FreeBSD.org>）于 2008-04-25 主导完成，当日连续提交 5 条 import commit；John Baldwin（<jhb@FreeBSD.org>）的角色是 MFC 整合与回滚修复：2008-08-27 提交 4 条 commit（包括 MFC version bump 与 3 条 revert 非 DTrace 相关变更的修复），2008-08-29 提交 2 条 commit 禁用 GENERIC 中的 KDTRACE 选项与 dtrace bootstrap 构建；“DTrace for FreeBSD”页面 people.freebsd.org/~jb/reasons/ 中的“jb”对应 John Birrell 而非 John Baldwin（jhb），进一步证明 Birrell 才是主导者；原大纲将“DTrace for FreeBSD”页面归属于 John Baldwin 是误读；John Birrell 在 freebsd-src 仓库的 last_commit_date 为 2008-09-27，与其 DTrace 移植工作完成时间一致，此后未再活跃——可能因 Birrell 转向其他项目或离开 FreeBSD 项目；DTrace 在 7.1 与 8.0 的功能完整度边界之争仍部分存疑——commit `2e39a10f0d47984da7ac7fae652f836752732af9`（2008-08-29）的 message_subject 显示 7.1 时期 KDTRACE 选项“尚未在 HEAD 中启用”，说明 7.1 时期的 DTrace 仍处于早期阶段，8.0 才完善内核模块支持；DTrace 在 FreeBSD 9.2 内建于 GENERIC 的具体版本在不同叙事中存在差异——部分资料称 9.2，部分称 10.0，需对照手册页历史核验；0 信任原则适用说明：所有 vendor import commit 的 author 与 committer 均为 John Birrell（<jb@FreeBSD.org>），交叉验证一致；author_date 与 committer_date 在所有 commit 中相同，无被 `git commit --date` 修改迹象；FreeBSD SVN-to-Git 2020 迁移可能引入 hash 重算，但 commit 的 message_subject 与日期信息应保持一致；contributors 表显示 John Birrell 末年活跃为 2008 年，与其 DTrace 工作完成时间吻合，可作为 Birrell 主导 DTrace 移植的间接佐证
