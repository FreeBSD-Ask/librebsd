# 115.11.2 KSE M: N 线程模型 → libthr 1:1 模式彻底确立（8.0 移除 libkse 选项，2009.4 文档残留清理）

  **要点**：FreeBSD 5.0-RELEASE（2003.1）引入 KSE（Kernel Scheduled Entities）M: N 线程模型，由 Daniel Eischen 等设计；KSE 设计为 M 个用户线程映射到 N 个内核调度实体，理论上可减少内核开销；但 KSE M: N 实现复杂、性能不及预期、调试困难；FreeBSD 7.0-RELEASE（2008.2）将 libthr（1:1 线程库）设为默认线程库，KSE 退居可选；8.x 时期完成 KSE 的彻底淘汰——2008-03-12T09:49:39Z Jeff Roberson 提交 commit（commit_hash = 34147e43085adb95bec20538cfd4291260fa4fa3，message_subject ="Remove libkse and related support code in libpthread from the build. Don't remove the files yet. Kernel support will be removed shortly."）首先将 libkse 从构建中移除但保留源码文件；2008.3.29 Ruslan Ermilov 提交 commit `dbdb679c` "Remove options MK_LIBKSE and DEFAULT_THREAD_LIB now that we no longer"，移除 `MK_LIBKSE` 构建选项与 `DEFAULT_THREAD_LIB` 切换机制，标志 libkse 在构建系统层面被完全移除；2009.3.31 David Xu 提交 commit `35c60825` 为 libthr 启用 `nodelete` 链接器标志，确保 libthr 不能被安全卸载；2009.4.1 Tom Rhodes 提交 commit `190608` 处理 PR 132392，从 **pthread(3)** 手册页移除 libkse 残留引用，仅保留 libthr 作为 POSIX 线程实现；8.0-RELEASE（release/8.0.0 tagger_date = 2009-11-21T06:13:29Z，tagger = Ken Smith，target_commit_hash = 59dd044d1cb744d3dba6b41c41e196b54e8fd9f8；官方公告日期 2009.11.25）发布时 libkse 已完全从默认构建中移除；libthr 1:1 模式彻底确立，与 Linux NPTL、Solaris 10（2005 年放弃 M: N）的 1:1 路线趋同

**史观**：总纲第 6 条——技术选择的代价：KSE M: N 付出工程复杂度代价（M: N 调度器实现困难），最终被 1:1 简单模型取代，反映“简单胜过聪明”的工程哲学；总纲第 7 条——技术选择即政治选择：KSE → libthr 反映“学院派 M: N”vs“工业派 1:1”的技术政治选择，与 Solaris 早期 M: N 后转 1:1 路线一致
