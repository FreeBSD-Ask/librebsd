# 110.12.2 KSE M: N 线程模型 → libthr 1:1 线程模型起步（6.x 时期过渡）

  **要点**：FreeBSD 5.0-RELEASE（2003.1.16，release/5.0.0 tagger_date = 2003-01-16T16:56:23Z）引入 KSE（Kernel Scheduled Entities）M: N 线程模型，由 Daniel Eischen 等设计；KSE 设计为 M 个用户线程映射到 N 个内核调度实体，理论上可减少内核开销；但 KSE M: N 实现复杂、性能不及预期、调试困难；同期 libthr（1:1 线程库）作为替代方案由 David Xu 等开发，每个用户线程对应一个内核线程，实现简单但开销较高；FreeBSD 5.3-RELEASE（2004.11.4，release/5.3.0 tagger_date = 2004-11-04T19:12:42Z）将 KSE 设为默认线程库，libthr 作为可选；6.x 时期社区逐步倾向 libthr——John Baldwin（约翰·鲍德温） 等在 freebsd-arch 邮件列表 2007 年讨论在 7.0 将 libthr 设为默认，8.0 完全移除 KSE 内核支持；libthr 在 7.0-RELEASE（2008.2.24，release/7.0.0 tagger_date = 2008-02-24T05:45:17Z）正式成为默认线程库，KSE 内核数据结构在 8.0-RELEASE（2009.11.21，release/8.0.0 tagger_date = 2009-11-21T06:13:29Z）移除，libkse 用户态库目录在 2014.4 由 Brooks Davis 完全删除
  
**史料**：FreeBSD 5.0/6.0/7.0 Release Notes 线程部分；Daniel Eischen 在 freebsd-arch 邮件列表 2001-2005 年关于 KSE 设计的讨论；John Baldwin 在 freebsd-arch 2007 年关于 libthr 默认化的 RFC；Brooks Davis 2007.11.20 关于 libkse*.a 移除的 patch；CVS commit log 中 libkse 与 libthr 相关 commit；freebsd.duckdb freebsd-src 仓库 tags 表 release/5.0.0 的 tagger_date = 2003-01-16T16:56:23Z、release/5.3.0 的 tagger_date = 2004-11-04T19:12:42Z、release/7.0.0 的 tagger_date = 2008-02-24T05:45:17Z、release/8.0.0 的 tagger_date = 2009-11-21T06:13:29Z ［A］
  
**史观**：总纲第 3 条——不存在进步，只有权力再分配〔映射存疑，待主理人审定〕：KSE M: N 模型付出工程复杂度代价（M: N 调度器实现困难），最终被 1:1 简单模型取代，反映 “简单胜过聪明” 的工程哲学；总纲第 13 条——法律与道德是利益分配〔映射存疑，待主理人审定〕：学院派 M: N 与工业派 1:1 的路线之争：KSE → libthr 反映 “学院派 M: N” vs “工业派 1:1” 的技术政治选择
