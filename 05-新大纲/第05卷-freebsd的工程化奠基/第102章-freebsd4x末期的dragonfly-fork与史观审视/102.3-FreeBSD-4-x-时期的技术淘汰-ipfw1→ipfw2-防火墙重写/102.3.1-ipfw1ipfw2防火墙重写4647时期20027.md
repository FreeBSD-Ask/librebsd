# 102.3.1 ipfw1 → ipfw2 防火墙重写（4.6/4.7 时期，2002.7）

  **要点**：FreeBSD 3.x 时期使用 ipfw1 防火墙（原始 ipfirewall 实现通行说法归于 Daniel Boulet 一路，Rizzo 系 1996 年起 dummynet 引入者与 2002 年 ipfw2 重写主持人〔原归属表述存疑已按通行记载订正〕），规则语法简单但缺少状态检测、dummynet 流量整形与 keep-state 机制的完善支持；ipfw2 防火墙由 Luigi Rizzo 重新设计，首次 commit 于 2002 年 7 月 9 日（4.6-RELEASE 2002.7.3 之后，4.7-RELEASE 2002.10.8 之前），2002 年 7 月 24 日 MFC 至 -stable 分支；ipfw2 引入更灵活的规则语法（基于规则集与动作分类）、内置 dummynet 流量整形、keep-state 状态检测、IP 协议无关规则（IPv4/IPv6 统一）；ipfw2 替代 ipfw1，但 ipfw1 接口在兼容性考虑下保留一段时间；4.x 时期 ipfw2 是默认防火墙，与同期 OpenBSD pf（2001 年 OpenBSD 3.0 引入）形成竞争
  
**史料**：FreeBSD 4.6/4.7-RELEASE Release Notes；Luigi Rizzo 在 freebsd-ipfw 邮件列表 1999-2000 年关于 ipfw2 设计的讨论；man **ipfw(8)** 历次版本；freebsd.duckdb freebsd-src 仓库 commits 表 ipfw2 首次 commit 为 2002-07-09 Luigi Rizzo（commit c7ea6831353b20a8dac2dbcb65f6932a25598158，subject = "Change one variable to make it easier to switch between ipfw and ipfw2"），2002-07-24 MFC 至 -stable（commit 489e451968935d9b0494271a82e41bef54210157，subject = “Bring ipfw2 into the -stable tree”） ［A］
  
**史观**：专题语（不设总纲条号）——技术选择的代价（原挂总纲第 6 条系伪名目，删条号）：ipfw1 → ipfw2 重写付出规则兼容性代价（旧 ipfw1 规则需重写），但获得状态检测与流量整形能力；专题语（不设总纲条号）——形式与内容（原挂总纲第 17 条系自创名目，删条号）：防火墙规则语法作为 “形式” 改变 “内容”（网络管理员可用的策略表达能力）
  
**辨析**：经 **freebsd.duckdb** commits 表验证〔原 bsd_commits.duckdb 系拆分前旧库名〕，ipfw2 首次 commit 为 2002-07-09（4.6-RELEASE 2002.7.3 之后），MFC 至 -stable 为 2002-07-24，故 ipfw2 实际引入版本为 4.6/4.7 时期而非旧叙事所称的 4.0 或 4.1，存疑已解决；ipfw2 与 ipfw1 共存期约 2002.7-2003 年（4.6-4.9 期间），4.10 起基本为默认；ipfw2 与同期 OpenBSD pf（2001）的设计哲学差异需对照源码核验
