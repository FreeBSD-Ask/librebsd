# 102.6.1 批评层：SMP 支持滞后与市场份额下滑的批评

  **要点**：对 FreeBSD 4.x 时代的批评集中于两点——SMP 支持滞后与市场份额下滑。SMP 支持层面，FreeBSD 4.x 全系列沿用 Giant lock（单一内核大锁）模型，任何时刻仅一个 CPU 可在内核态运行，多核扩展性受限；4BSD 调度器为 O(n) 算法，无 CPU 亲和性、无 SMT 支持。同期 Linux 2.4（2001.1）已引入改进的 SMP 支持，Linux 2.6（2003.12）进一步以 O(1) 调度器与细粒度内核抢占大幅提升多核性能。FreeBSD 的 SMPng（SMP Next Generation）项目虽 2001 年启动，但直至 5.0-RELEASE（2003.1.16）才引入初步架构，4.x 全系列未能受益。市场份额层面，Linux 2.4 成熟后蚕食 FreeBSD 在 ISP 与企业市场的份额，Red Hat Enterprise Linux（2003）进一步加速这一趋势；4.x 代码冻结期间部分用户因 5.x 不稳定、4.x 不再更新而转向 Linux。批评者将 4.x 时代定性为 “工程成功但商业失败”——Jails、kqueue 等技术领先未转化为市场优势，归因于 BSD 许可证的宽松、营销不足、Linux 商业生态的资本投入。
  
**史料**：FreeBSD 4.0-RELEASE 公告（2000.3.14，Jordan K. Hubbard（乔丹·哈伯德） 发布，经 WebFetch 一手核验 <https://www.freebsd.org/releases/4.0R/announce/>）；FreeBSD 4.11-RELEASE 公告（2005.1.25，Ken Smith 发布，明确称 "This is expected to be the last release from the RELENG_4 branch"，经 WebFetch 一手核验 <https://www.freebsd.org/releases/4.11R/announce/>）；freebsd.duckdb freebsd-src 仓库 commits 表 ULE 调度器首次 commit 为 2003-01-26 Jeff Roberson（5.0-RELEASE 之后），印证 4.x 全程沿用 4BSD 调度器；Linux 2.4 ChangeLog；Red Hat Enterprise Linux 发布公告（2003）；本章 37.12.5 节 Giant 锁与 4BSD 调度器考据 ［A］
  
**史观**：经济周期，Linux 2.4 成熟期与互联网泡沫后企业成本压力叠加；总纲第 11 条——商品是形式主义，“市场成功” 本身是形式主义的权力运作
  
**辨析**：考据过程留痕——【查证来源】FreeBSD 4.0-RELEASE 公告日期 2000.3.14 与 4.11-RELEASE 公告日期 2005.1.25 均经 WebFetch 一手核验；4.x 全系列沿用 Giant lock 与 4BSD 调度器经 freebsd.duckdb freebsd-src 仓库 commits 表 ULE 首次 commit 时间（2003-01-26，5.0-RELEASE 之后）反证；Linux 2.4 SMP 改进的具体基准测试数据未在批评层史料中直接引用，需对照 Linux 2.4 ChangeLog 与同期基准测试报告核验；【交叉验证方法】FreeBSD 4.0/4.11 公告（一手发布文档）、freebsd.duckdb freebsd-src commits 表（代码级证据）、Linux 2.4 ChangeLog（一手发布文档）三方互证——4.x 版本周期（2000.3 至 2005.1）与 Linux 2.4（2001.1）/2.6（2003.12）发布时序吻合，SMP 支持差距在 2001 至 2003 年窗口确凿存在；【0 信任原则·“市场份额下滑” 的量化困境】批评层所称 “市场份额下滑” 缺乏权威量化数据，Netcraft Web Server Survey 统计的是 Web 服务器软件（Apache/nginx/IIS）而非操作系统，FreeBSD 作为 Apache 后端操作系统的份额需从 Apache 部署统计间接推断，且 BSD 系统广泛部署于路由器、存储设备、嵌入式场景，此类场景不在 Netcraft 统计范围内，故 “市场份额下滑” 的量化判断须以具体市场细分（Web 服务器、ISP、企业桌面、嵌入式）为据，不得笼统断言；【存疑判定依据】“工程成功但商业失败” 的定性本身带有前理解——以 “市场成功” 作为评判标准，这一标准本身是争议焦点，批评层的归因（BSD 许可证、营销不足、Linux 商业生态）均需对照具体企业迁移案例核验
