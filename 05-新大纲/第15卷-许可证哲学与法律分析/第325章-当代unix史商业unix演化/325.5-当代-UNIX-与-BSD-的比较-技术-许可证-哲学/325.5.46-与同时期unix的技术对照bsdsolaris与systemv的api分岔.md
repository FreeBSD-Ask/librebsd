# 325.5.46 与同时期 UNIX 的技术对照：BSD、Solaris 与 System V 的 API 分岔

McKusick 在 Twenty Years of Berkeley Unix 中给出的世系图被 Branden Robinson 修正：Unix 32/V（DEC VAX 移植）才是全部 AT&T 与 BSD Unix 的共同祖先——2BSD 为 PDP-11 专用、保留 PDP-11 内核但持续从 3BSD/4BSD 更新用户态，2.11BSD 至今仍在维护；4.1BSD 本应称 5BSD 却因 AT&T 对数字五提出专有主张而受阻，直到 4.3BSD 因影响过大而部分被并入 SVR4、AT&T 多年威胁起诉 Berkeley 的阴影才逐渐消解；这一修正说明 BSD 与 System V 的分岔并非自 V7 开始，而是自 Unix 32/V 的 VAX 移植分道——3BSD 转 VAX 并支持 demand paging，与 System III/V 共享同一祖先；naab 进一步梳理手册页目录结构史：BSD 谱系一侧架构专属子目录的做法直到 4.4BSD 才出现，其 bsd.man.mk 提供 MANSUBDIR 用于安装到 MANDIR/manN/MANSUBDIR/page.N，在 vax、sparc 等架构上较广泛使用；而 System III 与 SVR1–4 的转储中未见在线手册，推测仅以纸质书分发

1985 年 8 月 Robert Elz 为 BSD 创建 memory.h 文件——"apparently I did create these files for BSD in early Aug 1985 - probably based upon some kind of description of what was in System V"——但 4.4BSD 实际分发的代码"would have been Chris Torek's ANSI C rewrite though, perhaps 4.3 as well"；Paul Eggert 查出 4.3BSD include/memory.h 的版权头为 1985 年加州大学董事会、注明"Definitions of the Sys5 compat memory manipulation routines"，仅声明 memccpy/memchr/memcmp/memcpy/memset 五个函数，他自评该版权头"feels bogus"——按 SCCS 记录最初提交者是 Robert Elz、几乎不可能由 UCB 员工撰写这些原型；SVR4 为向后兼容保留 memory.h 仅含原始 5 个 mem* 声明并重复于 string.h，C89 委员会将 mem* 从 memory.h 移至 string.h 与 str* 合并，Joseph Myers 反驳称"the APIs have been in <memory.h> since 1986 in 4.3BSD, and in System V they go back further to 1983"，认为 C89 此举是"a huge mistake"；Colomar 展示用 dspinellis 的 unix-history-repo 查证 BSD 源码的方法，以 4.3BSD（1986）qsort 实现为例：比较函数写成 K&R 风格 int (*compar)()、无 const 限定语，据此推断原型由 C89 引入但似早于 const 出现在更早草案，因为 POSIX.1-1988 有原型而无 const

realpath 的传播链由 Guy Harris 1992 年 1 月断言确立："realpath() is *not* present in BSD, as of 4.3-reno; I think it first showed up in SunOS 4.0, and was then picked up by other systems, such as System V Release 4"——即 SunOS 4.0 → SVR4 → Solaris 2.0；Andries Brouwer 确认该注记源自"4.4BSD-Lite man page realpath.3 (dated 1994-02-16)"，Solaris 2.0 的 realpath 派生自 SVR4 且恒返回绝对路径、相对路径行为仅见于 SunOS 4.x；同期 der Mouse 指出 lseek(2) 手册"SVr1-3 returns long instead of off_t, BSD returns int"已过时——NetBSD 自 1.5 起就从 lseek(2) 返回 off_t，他以"the days when BSD deserved the B in its name"形容早期 BSD 的历史用法；Hellwig 赞同删除该记载："历史上的 SysV 与 BSD 行为在九十年代初或许有趣，但这些日子已经过去，它属于历史书的内容，而非手册页"；Seth McDonald 按 standards(7) 所载年份排定 BSD/SV/POSIX 出现次序，Colomar 给出合并序列并判断"4.4BSD seems clearly later than POSIX.1-1990"，指出 standards(7) 未收录的 SV 标准应包括 SVID Issue 2（1986）与 SVID Issue 3（1991），怀疑 SVID 最终被 POSIX 吸收——POSIX.1-2001 被称为"Issue 6"且仍引用更早的 issue

手册页章节标题的来源亦暴露谱系差异：Ingo Schwarze 经历史调查发现"CONFORMING TO"在 AT&T UNIX（v6、PWB、v7、32v、v8、v10、System III、SVR1、SVR2）及任何 UCB CSRG BSD 版本中均无实例，而"STANDARDS"自 4.3BSD-Reno（1990 年 6 月）起即已存在；4.3BSD-Reno 比 Linux 内核首版早一年多，故该标题似非 UNIX 传统；Aeleen Frisch 在 Essential System Administration 中称 Linux 受 4.3BSD 影响略多于 System V Release 3；Branden Robinson 主张 .TH 第四参数应标识页面来源版本，称此用法与 AT&T 和 BSD Unix 中该参数的用途"congruent"——彼时为 7th Edition、System III、4.2 Berkeley Distribution 之类；mandoc 约 15 年前立项时的目标次序中速度目标"was secondary to the goals of BSD licensing, ease of use, and security"，Alpine、Void、illumos 及几乎全部 BSD 系统默认使用 mandoc，但它并非 groff 替代物、PDF 输出较弱且只能排版 man 页

API 层面的跨实现比对揭示了 BSD 与商业 UNIX 的并行演化：fsync_range 系统调用中 Nick Piggin 对标 BSD——"should add an fsync_range syscall like AIX and some BSDs have"，但 Hellwig 更正称并不存在 FreeBSD 实现——AIX 复用 O_ 标志、NetBSD 使用独立命名空间；nftw(3) 悬空符号链接的 lstat() 归属上，Kerrisk 称"我看了 Solaris、OpenBSD、FreeBSD 和 musl。这一切强烈表明 glibc 搞错了"；SS_AUTODISARM 写法上 Stas Sergeev 承认："Some implementations (including *all* the ones that I looked at the source code for, that is Illumos, FreeBSD, OpenBSD) explicitly error if ss.ss_flags has bits other than SS_DISABLE set"；setitimer(2)/alarm(2) 的 si_code 对照显示：alarm 与 setitimer 在 Linux 与 NetBSD 均为 SI_TIMER，FreeBSD 与 illumos 皆无，OpenBSD 无 POSIX 定时器故不可比，наб主张"The Linux behaviour matches NetBSD"；mkstemp 的谱系追溯显示该函数首现于 4.3BSD 但无头文件、用户须自行声明，4.4BSD 将其放入 <unistd.h>，POSIX.1-1990 尚无此函数，到 POSIX.1-2001 已出现在 <stdlib.h> 而 POSIX 未说明为何移动；getdtablesize(3) 的 STANDARDS 原文为"SVr4, 4.4BSD (the getdtablesize() function first appeared in 4.2BSD)"，并注明 POSIX.1 未规定、可移植程序应改用 sysconf(_SC_OPEN_MAX)；2.11BSD 的 sysctl.3 页面标注 1993 年却标注为 4.4BSD 的反向移植——Robinson 判定其为 1994 至 1995 年间因 USL v. BSDI 诉讼和解而分出 Lite 与 Encumbered 版本时的产物，SCCS 标记"@(#)sysctl.3 8.1.1 (2.11BSD GTE) 1/13/95"与 1995 年一致，故"带 sysctl 的 2.11BSD 比 4.3BSD 更晚"
