# 325.5.48 2010–2026：Solaris、illumos 与 XNU 作为 BSD 之外的接口锚点

2010 年 coredump 程序头扩展补丁直接对标 Solaris 已实现的机制并援引 Sun 文档——"Solaris has already dealt with this issue, and other OSes have also adopted the same method as in Solaris"——把 Solaris 系作为外部 OS 参照正式纳入 Linux 内核设计论据；同年 9 月 Eric Dumazet 在 connect() 空地址语义争论中对比 FreeBSD 与 Darwin 的 connect(2) 手册页与 Solaris 手册页，指出"Linux 却采用不同解释且十年无人使用"

2014 年 4 月 Hin-Tak Leung 在 hfsplus 讨论中点出 macOS 内核文件系统的 BSD 血统——"The fs code in the OS X kernel is under the xnu component, in the bsd layer"——并把 OS X 代码包进 fuse 框架的设想交给 Vyacheslav Dubeyko 评估，XNU 由此确立为 BSD 谱系在主流商业 OS 中的技术锚点；2014 年 11 月 declance 64 位编译修复讨论以 Darwin 的 CFString 与 Solaris 的 cmn_err 作为内核接受非常规符号的先例——"cmn_err' and `CFString' (for Solaris and Darwin)"；2015 年 4 月 Minchan Kim 针对 MADV_FREE 补丁组体量大而失控的质疑，以 jemalloc 跨平台实现作答——"in MADV_FREE supporting OSes(FreeBSD, Solaris, Darwin, Windows)"——把 BSD 语义当作 Linux 补齐该特性入主线的现实需求；同年 5 月 Tom Herbert 援引 BSD 侧先例为 IPv6 flow label 默认开启辩护——"BSD (MacOS) has already turned on flow labels by default"

2015 至 2018 年间 BSD 与 Apple 的同构机制被集中援引为 Linux 新特性的设计基准。2015 年 12 月 Meelis Roos 讨论 Fujitsu SPARC64 V 与 VI 支持时援引 OpenBSD 团队曾因无效硬件访问导致 XSCF 固件故障的案例，并参考 Solaris 与 illumos 的 pcicmu 桥代码；2016 年 Loganaden Velvindron 与 Mickaël Salaün 相继在 seccomp-object 与 Landlock LSM RFC 中把 Linux 非特权沙箱能力与 BSD 及 Apple 的同构机制并列——"comparable to the Seatbelt/XNU Sandbox or the OpenBSD Pledge"；2017 年 Paul McKenney 在 RCU dynticks 原子位优化讨论中引入 Darwin 内核作为横向参照——"Amusingly, Darwin appears to do something similar without an atomic op"；2017 年 Kerrig 就 SS_AUTODISARM 查阅多个实现，Stas Sergeev 承认"Illumos, FreeBSD, OpenBSD"三个 BSD 相关系统对 ss.ss_flags 非 SS_DISABLE 位均显式报错，把 BSD 家族作为 glibc 实现与 POSIX 文本不一致的证据；2018 年 Jan Kara 与 Amir Goldstein 直接把 macOS 的 FSEvents 作为文件系统变更日志 API 的对标——"Not only Windows but also MacOS which has FSEvents API"

2023 至 2024 年间 Darwin 与 illumos 作为 BSD 谱系代表进入更多 Linux 议题。2023 年 Dave Chinner 在内核文件系统信任与维护议题中说明 hfsplus 虽无人维护仍收修复、因对 macOS 互操作有用——"We used to have one that was ported from the open source Darwin code drops"；同年 Ingo Schwarze 说明 mandoc 立项时速度目标"was secondary to the goals of BSD licensing, ease of use, and security"，其后 Alpine、Void、illumos 及几乎全部 BSD 系统默认使用 mandoc；2024 年 1 月 Jeff Xu 的 mseal() 补丁集把新内存密封系统调用锚定在 BSD 先例上——"A similar feature already exists in the XNU kernel and on OpenBSD with the mimmutable syscall"；同年 5 月 наб 就 setitimer(2)/alarm(2) 的 si_code 给出实现对照表——alarm 与 setitimer 在 Linux 与 NetBSD 均为 SI_TIMER，FreeBSD 与 illumos 皆无，OpenBSD 无 POSIX 定时器故不可比，Linux 行为与 NetBSD 一致，属 BSD 变体内部对同一 POSIX 接口的分化证据

2025 年 illumos 作为 BSD 与 System V 谱系的交叉实现被反复并列。9 月 Rick Macklem 把 FreeBSD 14 及以后的 NFS 服务端与 Solaris、illumos 并列——"the Solaris&&Illumos NFS servers, and maybe the FreeBSD >= 14 NFS server"，Trond Myklebust 自嘲"with me being at outlier, testing the FreeBSD client"；同期 Mateusz Guzik 断言 O_CLOFORM"implemented in all the BSDs (no, really) and illumos, but got NAKed in Linux"；10 月 Sunday Adelodun 提议删除 AF_UNIX 释放函数中关于 Linux 与 BSD 在 ECONNRESET 发送时点上差异的陈旧注释，并在 FreeBSD 14.3-RELEASE 与 macOS 上实测验证；同月 Mottola 在 Debian sparc64 排查中报告"tested OpenBSD and NetBSD, they now work fine"替代早年 Solaris 测试基线；年底 John Ericson 提议为 Linux 引入 connectat 与 bindat，此前两次提案均未获回应——"I am interested in seeing something like the BSD's connectat/bindat in Linux"

2026 年 BSD 与 XNU、illumos 共同作为接口分歧的仲裁清单继续被援引，同时清单内部条目开始模糊。3 月 Dorjoy Chowdhury 的 openat2 OPENAT2_REGULAR 系列反复援引 FreeBSD 与 macOS 既有的 EFTYPE 错误码——"EFTYPE is already used in BSD systems like FreeBSD, macOS"，Andy Lutomirski、Christian Brauner 与 Jeff Layton 在 v3 到 v6 之间反复讨论该标志语义；4 月 Landlock cover letter 明确受限进程"connect to named UNIX sockets through the BSD socket API described in unix(7)"，同一补丁集 6 月抽出的 af_unix 分层解耦函数命名为 unix_lookup_bsd_path，BSD 术语在 Linux 网络代码中成为实现标签；5 月 David Hildenbrand 在软件页表方案讨论中回溯 SunOS 与 UVM 的 amap 中间结构——"SunOS and UVM call it amap"——把 BSD 4.4 VM 谱系作为 Linux 页表格式差异的一手比较；7 月 O_CREAT 与 O_DIRECTORY 组合讨论中作者以 POSIX 未定义为前提列出 FreeBSD 与 NetBSD 各自语义不同、OpenBSD 与 Solaris 及 illumos 情形各异——"cannot rely on _any_ common behavior between platforms"，最后自嘲"it's 2026 lol who cares about BSD"；同月 Ali Ahmet Memis 说明自己从 Linux 挂载 FreeBSD、NetBSD、OpenBSD 与 Solaris 磁盘——"reading FreeBSD, NetBSD, OpenBSD and Solaris disks from Linux"，Jan Kara 担任 UFS 维护者；8 月 Mark Harris 更正 memory.h(3head) 文档——Illumos 在 usr/src/head/memory.h 确实提供该头文件，但仅声明历史上原有的五个 mem* 函数，与 SVR4 及 4.3BSD 1986 年为 System V 兼容引入 memory.h 时的形态一致，把 BSD 与 System V 兼容的接口分岔重新钉在 1985 年 Robert Elz 创建 memory.h 与 4.3BSD 分发的两条时间线上

从 2010 年 coredump PN_XNUM 到 2026 年 memory.h 溯源，Solaris、illumos 与 XNU 已取代 SunOS、HP-UX、AIX 与 Tru64 成为"同时期 UNIX"新的技术联邦成员，与 BSD 变体共同承担接口语义仲裁功能；但 O_CREAT 与 O_DIRECTORY 之争中"who cares about BSD"的自嘲表明，横向清单在工程界的影响力已出现明显的选择性遗忘，BSD 与 illumos、XNU 的锚点作用同时被援引与遗忘所并存
