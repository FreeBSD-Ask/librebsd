# 325.5.2 时间线延伸至20252026年BSD家族与illumos已在POSIX采纳路径上

时间线延伸至 2025-2026 年，BSD 家族与 illumos 已在 POSIX 采纳路径上协同——"all the BSDs (no, really) and illumos"已实现 O_CLOFORM，而 Linux 否决该提案；同期 O_CREAT 与 O_DIRECTORY 组合语义讨论出现"it's 2026 lol who cares about BSD"的自嘲式评述，反映 BSD 作为接口参照系的历史地位与实际工程影响力之间的张力；截至 2026 年 7 月 27 日现状，BSD 谱系（FreeBSD 15.x、NetBSD 10.0、OpenBSD 7.6、DragonFly BSD 6.4）在服务器操作系统市场份额合计不足 3%，却通过商业产品嵌入覆盖了全球数以亿计的计算终端；这一"被广泛使用但不回馈"的悖论，从 GNU 阵营视角看是 GPL Copyleft 的必要补足、从 BSD 阵营视角看则是"代码是商品而非武器"的立场实践——两种许可证哲学最终在商业 UNIX 衰退、Linux 主导、BSD 嵌入的三方格局中完成权力再分配，而非任何形式的"进步"叙事。

BSD 与商业 UNIX 的分野在接口层面同样清晰——Carlos O'Donell 明确指出 flock 接口并非 POSIX 而是源自 4.2BSD、早期由 glibc 用 fcntl 模拟（"flock is not POSIX, it's an interface invented by 4.2BSD"），并因 HPUX 把 EAGAIN 映射为 EWOULDBLOCK 而产生兼容层；Al Viro 在 io_uring getdents64 讨论中回溯目录读取接口的由来，指出"as soon as FFS had introduced support for names longer than 14 characters, the things got more complicated"，FFS 即 4.2BSD 快速文件系统属 BSD 谱系直接塑造 Linux 目录遍历接口；Christoph Hellwig 陈述 BSD 早于 Linux 完成 64-bit off_t 迁移（"4.4BSD and descendants have made the switch to 64-bit off_t in 1994 and haven't supported a non-LFS since"）、Mike Frysinger 以"BSD's can get away with it because their entire modus operandi is that you get no backwards compatibility"直接对比 BSD 与 Linux 的向后兼容政策

时间线延伸至 2000 年代，Linux 内核开发者反复回到 BSD 谱系作为缺失接口的参照——KOSAKI Motohiro 指出"the behavior of linux madvise(MADV_DONTNEED) is similar to Solaris or BSD madvise(MADV_FREE)"、说明 glibc 的 posix_madvise(DONTNEED) 是空操作；Gerd Hoffmann 提交 preadv/pwritev 补丁时声明"BSD has this syscall for quite some time"，以 NetBSD 手册为参照实现，Russell King 与 Arnd Bergmann 引 FreeBSD、OpenBSD 已实现该接口、Solaris 仅有 1994 年 5 月 25 日 feature request 单，属 BSD 阵营对 POSIX I/O API 的先导被用作 Linux 补齐依据；H. Peter Anvin 指出"glibc has a pretty nice set of functions for byte swapping in <endian.h>, taken from FreeBSD I believe"，构成本地用户态工具链的直接移植

2025-2026 年间 Mateusz Guzik 明确指出"The O_CLOFORM idea was accepted into POSIX and recent-ish implemented in all the BSDs (no, really) and illumos, but got NAKed in Linux"，显示 BSD 家族与 illumos 已在 POSIX 采纳路径上协同、而 Linux 内核反向偏离；Ian Lance Taylor 在 O_CLOFORK 提议中援引"Solaris and macOS and OpenBSD have O_CLOFORK already Hopefully it will catch on further"证明该接口并非 Linux 原创而是 BSD 与 Solaris 谱系早已有之，Kyle Evans 提醒 FreeBSD 上 O_CLOFORK 尚不存在属 BSD 内部不同分支在 POSIX 采纳节奏上的真实差异；2023 年 1 月 9 日 Florian Weimer 记录 chrony 若改用 glibc 版 arc4random、放弃其 OpenBSD 兼容版的 userspace buffering 后"NTP packet response rate"下降 25%，说明 OpenBSD 的 arc4random 语义已被 Linux 用户态实际吸收——BSD 谱系在商业嵌入之外于 Linux 内核接口层面持续承担"事实标准锚"角色，与 Solaris 谱系在 illumos 分支后的技术延续形成呼应

Michael Kerrisk 指出 errno 中 ENOTSUP 与 EOPNOTSUPP 并存的根源是 BSD 与其他历史实现的分歧：POSIX.1-2008/SUSv4 的 <errno.h> 对两者都写作“可同值”（"[ENOTSUP] Not supported (may be the same value as [EOPNOTSUPP])."／"EOPNOTSUPP] Operation not supported on socket (may be the same value as [ENOTSUP])."）；BSD 为 sockets API 发明 EOPNOTSUPP，这一点反映在 POSIX.1 中，System V 一系用 ENOTSUP，见于 POSIX.1 的 timer_create() 与 clock_nanosleep()；glibc 在 sysdeps/unix/sysv/linux/bits/errno.h 中以 "#define ENOTSUP EOPNOTSUPP" 把两者并置。他同时更正了同线程中的内核统计口径：内核中 ENOTSUP 出现次数为 0（tools 与 samples 除外），真正出现在内核里的是拼成 ENOTSUPP（两个 P）的常量，定义为 524，位于 include/linux/errno.h。
