GPL 与 BSD 的法律边界在 1997 年的内核头文件里就已开始模糊：Linux 内核自 0.12 起以 GPL-2.0 发布，却允许用户态程序以任意许可链接之，直到 2004 年 Topspin Communications 把 Mellanox mthca 驱动送进主线时，文件头第一次以“You may choose to be licensed under the terms of the GNU General Public License (GPL) Version 2 … or the OpenIB.org BSD license below”这种二选一文本把 BSD 条款制度化送入内核网络子系统，版权声明署 Topspin 2004 保留所有权利，之后 Roland Dreier 的 mthca_cq.c、mthca_av.c、Glenn Grundstrom 的 nes_nic.c、IPoIB 多播分区补丁、Urs Thuermann 与 Oliver Hartkopp 的虚拟 CAN 模块 `MODULE_LICENSE("Dual BSD/GPL")`、Ramkrishna Vepa 的 Neterion 网口驱动、Adaptec ADP94xx SAS 与 FlashPoint 驱动、Tom Hromatka 的 Oracle sparc64 ADI 补丁、直至 2024 年 yunsilicon 以太网驱动，全部沿同一模板递延——BSD 宽松条款不再是被 GPL 边缘化的异端，而是厂商把商业代码送进主线的合规出口；Greg KH 转贴这段文本时未加删改，等于以维护者沉默把双许可写成内核的许可惯例

glibc 成为两派许可证主张的第一处对撞面：2017 年 Michael Kerrisk 与 Rob Landley 围绕 `pid_namespaces(7)` 的 `#define _GNU_SOURCE` 展开论战，Landley 直言“GNU has nothing to do with Linux, and never did”，并转述 Linus Torvalds 早年“printing out a copy of the GNU coding standards, and NOT read it. Burn them”，把 `_GNU_SOURCE` 比作“#define GNU_GNU_GNU_ALL_HAIL_STALLMAN”，Eric W. Biederman 顺势解释 `features.h` 在未定义任何 feature test 宏时会同时打开 `_BSD_SOURCE`、`_SVID_SOURCE`、`_POSIX_SOURCE` 与 `_POSIX_C_SOURCE=200809L`，而 `_GNU_SOURCE` 是“全开”而非精细控制；Landley 另举 2001 年 glibc 维护者所称“hostile takeover of glibc development”为证，并把自己 2001 年赴 MIT 拜访 Stallman 时听到的 BSD 抵御 AT&T 诉讼的自述与实际参与者史料做交叉比对，指出“didn't really make much of a splash”，把 GPL 与 BSD 之争还原为 1980 年代具体人物与具体邮件列表的现场判断

BSD 内核接口以“借语义”的方式反向流入 Linux：2010 年 1 月 KOSAKI Motohiro 在 `MAP_UNLOCKED` 讨论中提出 `ru_maxrss` 的单位应“is set to KBs which is the way it is done in BSD systems”，Hugh Dickins 转引 2.6.32 提交 `1f10206cf8e9` 与 2009 年填表理由“->ru_maxrss value is set to kbs which is the way it is done in bsd systems”，指出 GNU time 把已经按 KB 提供的数值再乘 `ptok()` 导致 MaxRSS 过量报告，把“Linux getrusage 语义向 BSD 对齐”写进进程资源统计接口；Jiri Pirko 与 KOSAKI 的另一版补丁则专门说明 `exec()` 后 `sig->maxrss` 不清除是有意为之，因为“BSD getrusage have exec() inheriting”；2017 年 Rik van Riel 提交 `MADV_WIPEONFORK`，直接援引 OpenBSD `minherit` 系统调用与 `MAP_INHERIT_ZERO`，把 fork 后密钥与 PRNG 状态失效交给内核，补丁正文写“This is similar to the OpenBSD minherit”；Andy Lutomirski 与 Ahmed S. Darwish 记录 glibc 自 2.25 起“implementing a BSD-like getentropy(3) in terms of getrandom”，使得用户态启动路径普遍调用 getrandom，引发嵌入式系统卡启动；Florian Weimer 举证 glibc 的 arc4random 沿用 OpenBSD 兼容实现，chrony 从该兼容实现切到基于 getrandom 的版本后 NTP 响应速率下降，“instead of its OpenBSD compat version, which uses userspace buffering”；Aleksa Sarai 2019 年 11 月提交 `openat2` 系统调用补丁系列第 15 至 16 版，`RESOLVE_BENEATH` 文档明确写“RESOLVE_BENEATH 的语义仿照 FreeBSD 的 O_BENEATH”；James Bottomley 与 Andy Lutomirski 追问为何 BSD 不在 `license_is_gpl_compatible` 列表，Bottomley 指向 GNU 许可证清单 `license-list.en.html#ModifiedBSD`，主张四段式 BSD 属 GPL 兼容；Andy Lutomirski 另提交 alternate CREDs 系统调用，指出“this is done exactly the same on FreeBSD, with same exact glibc intervention”；Jann Horn 在 seccomp 与 glibc 包装函数讨论中把 GNU/Linux 分离开发与 OpenBSD 单一代码树相对照，“seccomp filters are incompatible with the GNU/Linux model, unlike say OpenBSD”；Ted Ts'o 在官方 Linux 系统包装库讨论中称 glibc 接口设计“they are no worse as a source of APIs than all the old BSD / SVID interfaces”
