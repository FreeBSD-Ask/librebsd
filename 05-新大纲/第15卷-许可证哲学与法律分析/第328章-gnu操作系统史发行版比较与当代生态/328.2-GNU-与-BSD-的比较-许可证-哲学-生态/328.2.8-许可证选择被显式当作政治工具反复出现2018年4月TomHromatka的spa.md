# 328.2.8 许可证选择被显式当作政治工具反复出现2018年4月TomHromatka的spa

许可证选择被显式当作政治工具反复出现：2018 年 4 月 Tom Hromatka 的 sparc64 ADI 驱动补丁把 Oracle 版权声明与“双许可”文本并列，内核内或与其他软件包一起分发时适用 GPL-2.0，脱离内核单独分发时改用宽松条款“free to use, copy, modify, merge, publish, distribute, sublicense, and/or sell copies”；2018 年 8 月 James Bottomley 主张新表结构开发走 copyleft-next，已与 GPLv2 兼容，并请了三名律师做合规审查，其中两位在 SUSE；Bob Beck 在 2007 年围绕 r.kernel.org 的争论中借 Jeff Garzik 转述，“What is this? a concerted attack by some organization on the BSD projects?”，点名 FSF 与 freesoftware.org，把许可证政治显形为利益分配；2020 年 5 月 Maciej Żenczykowski 讨论 Android Bionic 与 socklen_t 时引 Wikipedia“Bionic is basically a BSD licensed C library for use with Linux”，并对比“other BSD C libraries which require a BSD kernel”与采用 LGPL 的 glibc，把 BSD 许可在 Linux 用户态 C 库谱系中的位置直接摆上台面；2025 年一位 Rust for Linux 邮件列表新成员提出现有 Rust for Linux 代码统一采用 GPL-2.0 是否只是“沿用默认设置”，援引 Linux DRM 核心与 i915、radeon、amdgpu 驱动采用 GPL 与 MIT 双许可、OpenBSD 可直接使用，希望苹果芯片驱动同样双许可，把 GNU 内核中已有的双许可先例与 BSD 系统跨内核复用需求直接连起来

BSD 兼容别名与命名习惯作为长期技术债留在代码与文档里：2015 年 6 月 Stephen Hemminger 修补 linux/in.h 与 netinet/in.h 定义重叠，让 glibc 保住 BSD netinet 定义；2020 年 5 月 Sergei Trofimovich 指出 glibc 手册把 O_NDELAY 标注为“provided for compatibility with BSD”，但 sparc32 的 O_NDELAY 是 0x0004 与 O_NONBLOCK 的组合、sparc64 却单独定义为 0x0004，glibc 侧不随架构变化导致 sparc32 二进制在 sparc64 内核上运行时两侧理解不一致，Adhemerval Zanella 考古追溯到 linux-2.1.29 的 fcntl.h 与 fs/fcntl.c 中标注“严格 SunOS 仿真”的映射逻辑；2005 年 7 月 Jeremy Huddleston 重排 sparc Kconfig 时连带删去一段“Linux 传统上使用类似 BSD 的主设备 /dev/ptyxx、从设备 /dev/ttyxx”的说明；2018 年 Linus 指出 BSD 惯用单下划线 `_BYTE_ORDER` 而 glibc 用双下划线 `__BYTE_ORDER`，决定让内核改用 CONFIG 宏、仅修 uapi 头部；Ingo Schwarze 批评 FHS“dismissing decade-old *BSD standards like the use of /usr/ for the base system and /usr/local/ for packages as a standard violation”，G. Branden Robinson 援引 Solaris 2.3/2.4 与 Oracle 文档确认 /opt/ 早于 Linux 已存在；2026 年 1 月 Andreas Larsson 提交 sparc clone3 支持补丁时说明 sparc_clone、sparc_vfork、sparc_fork 中“存在一个因 SunOS 返回值约定而设置的工作变通手段，而 clone3 不需要它”，SunOS 派生的 ABI 约束延续到 2020 年代

BSD 工具链与文档传统在内核外围继续被引为先例：H. Peter Anvin 在 initramfs 扩展属性格式讨论中反复强调“the BSD one is better maintained these days”，把 GNU cpio 与 BSD cpio 作为设计坐标；2014 年 util-linux 2.25.2 变更清单记录“remaining kFreeBSD hackery for building”；Neil Brown 代笔 flock(2) 手册页 NOTES 段落时说明自内核 2.0 起 flock 独立成系统调用“这带来经典 BSD 语义，即两种锁类型之间互不交互”；Roland McGrath 2008 年主张暴露 DT_WHT 白名单条目时以“BSD had unions with whiteouts years ago, and their ls et al have options to let you see”论证用户态可见白名单的谱系传统；Dave Chinner 讨论 tmpfs fallocate 中断语义时引用 Adam Borowski“both glibc's and FreeBSD's fallback emulation don't rollback”；Pavel Machek 与 Arseny Maslennikov 为 SIGINFO 争取依据时援引“GNU make on BSD does support SIGINFO (Not a standard tool, but obviously an established one)”；Mateusz Guzik 在 fs/pipe 补丁评审中提出“Both GNU and BSD makes share a token pipe”导致 -j 并发下的 poll 锁排队问题；2010 年 8 月 Changli Gao 转述维护者论断“strlcpy() is a BSD function that never caught on in Linux”，glibc 维护者亦认为其截断行为有误导性；2010 年 1 月 Eric Dumazet 在 GTSM 讨论中指出“This is already implemented the same way in BSD kernels”；2015 年 Justin Gibbs 回复 OLVETTI 7782 适配询问时引用自己在 FreeBSD 个人空间托管的 GNU 补丁包地址；Aaron Traas 在 st(4) 手册 MT_ST_SYSV 语义颠倒的争论中列出“BSD and Solaris man pages on the subject contradict Linux s”；Minchan Kim 提议 MADV_FREE 时指出 jemalloc 与 tcmalloc 已在 FreeBSD 上实现

从 1997 年 Linux 0.12 起 GPL 传染与 BSD 宽松条款就以内核代码里的每一段头文件、每一个 API 语义、每一条许可证字段的方式双向流动：GPL 传染性为回馈设定法律边界，BSD 宽松条款为商业嵌入留下合法出口，glibc 与 libc 生态把二者的边界从许可证文本推入运行时语义，`_GNU_SOURCE`、`_BSD_SOURCE`、`RESOLVE_BENEATH`、`MADV_WIPEONFORK`、`getentropy(3)`、`arc4random`、`ru_maxrss`、`flock`、`DT_WHT`、`openat2`、BSD 双许可模板、copyleft-next、SPDX、ModifiedBSD——这些技术符号成为两种许可证哲学在代码与文档层面的日常对话，而不是判决或和解
