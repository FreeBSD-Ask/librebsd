# 328.2.11 手册页、目录约定与工具行为：许可证文本之外的第三条分界线（2003–2026）

许可证条款与 API 语义之外，GNU 与 BSD 的分界还落在手册格式、目录约定与工具行为这些日常细节里，2003 年 1 月 Justin Gibbs 回复 aic79xx 适配询问时给出的补丁包地址是 people.FreeBSD.org/~gibbs/linux/SRC/aic79xx-linux-2.5.59-20030122-gnupatch.gz，Linux SCSI 驱动的 GNU 补丁托管在 FreeBSD 的个人空间，工具链的归属与项目的归属并不一致；同年 4 月 Aaron Traas 讨论磁带 st(4) 的 MT_ST_SYSV 选项时，其公司专有备份软件在 BSD 系与 SysV 系上行为相反，Linux 手册却把两种语义标反，团队据手册判定 Linux 为非 BSD 风格而触发 fsf 错误，他列出的对照引语是 “BSD and Solaris man pages on the subject contradict Linux s”，手册文档本身成为跨生态误判的现场

手册页与文档格式的分界最早显形于 2008 年 12 月，Kerrisk 与 Rob Landley 争论 man-pages 的受众定位，Landley 称自己为打算支持 Dragonfly BSD 的平台写可移植程序时会告知，并指出 “Posix 可移植” 还涵盖 Windows NT 与奇怪的 IBM 大型机，Kerrisk 回应 man-pages 面向一般读者、其中许多人确实关心可移植性，但强调只要这个一般读者不包括把 Linux 视为自有平台的人即可，Landley 承认自己未翻页就漏读了 notes 段，Kerrisk 顺势讨论如何让读者注意到细则；到 2025 年 9 月，Collin Funk 就 GNU 手册页并入 Linux man-pages 一事问 “mdoc is the format mandoc uses for the different BSD man pages, correct?”，Colomar 答 “Yes, the BSDs use mdoc(7) instead of man(7)”，并补充 Linux 上 nginx 等项目也使用 mdoc，“but they're minoritary”；就 GNU Coding Standards 对 --help 的要求他虽可通过 bug-standards@gnu.org 争取修改，个人却 “don't intend to change that”；G. Branden Robinson 回应 Joseph Myers 关于应从 glibc manual 生成手册页、让文档由正当协商程序维护而非跟随一人意见的提议，推测 Stallman 本就期望此事 “would be soon implemented and accomplished...in 1989. Or earlier”，并称 GNU 官方文档仍主张 (Tex)Info 优先、手册页终将消失，“man pages are destined to wither away, as Engels predicted of the State”，维护 groff 的经验显示约 300 页 Texinfo 手册与约 400 页手册页仅部分重叠，同步全靠手工且不完美

目录约定与命名习惯的分界由 Ingo Schwarze 在 2022 年 7 月集中记录，他批评某草案 “dismissing decade-old *BSD standards like the use of /usr/ for the base system and /usr/local/ for packages as a standard violation”，并称 /opt/ “firmly a Linux-only invention”，G. Branden Robinson 则援引 Solaris 2.3/2.4 与 Oracle 文档确认 /opt 早于 Linux 已存在；Schwarze 回忆曾试图说服 FHS 维护者将数十年 BSD 惯例纳入标准，FHS 社区却 “very firmly entrenched as ‘Linux only’”，拒绝将 /usr/ 用于基本系统、/usr/local/ 用于软件包，转而推广他视为 Linux 专属的 /opt/，他因此退出并称其他 OpenBSD 开发者嘲笑他 “Why do you even care about that Linux-only crap?”，Colomar 致谢并引用 Branden 的考证；命名层面 Linus 在 2013 年 3 月指出 “the standard under BSD seems to be single-underscore ‘_BYTE_ORDER’”，而 glibc 用双下划线 __BYTE_ORDER，决定让内核改用 CONFIG 宏、仅修 uapi 头部以免把这套混乱搬进内核

工具链层面 BSD 血统以维护状况的方式被反复引用，2019 年 5 月 H. Peter Anvin 在 initramfs 扩展属性格式讨论中问 “I wonder how existing GNU or BSD cpio (the BSD one is better maintained these days) would deal with reading such a file”，Rob Landley 转发同一段话并把 BSD 版 cpio 当作编码方案的检验基准，把格式设计与工具链兼容性直接挂钩；2014 年 10 月 util-linux 2.25.2 变更清单仍标注 “remaining kFreeBSD hackery for building”，同时为 BSD 改用 -lutil 链接、修补 ipcrm 在 BSD 上的构建失败、修正 GNU/kFreeBSD 下报告的磁盘容量，用户态工具链长期维护对 FreeBSD 与 kFreeBSD 的兼容；2026 年 5 月 Mateusz Guzik 在 fs/pipe 减少 poll_usage 写次数的评审中提出 “Both GNU and BSD makes share a token pipe”，GNU make 与 BSD make 因共享同一条 token 管道而在 -j 高并发下触发同一类 poll 处理器多核性能问题，Linux 侧因此改 poll_wait 的锁排队；信号语义上 Pavel Machek 与 Arseny Maslennikov 为 SIGINFO 争依据时援引 “GNU make on *BSD does support SIGINFO (Not a standard tool, but obviously an established one)”，另一记录称 strace 开发者希望支持 SIGINFO 用于打印跟踪器状态；文件锁方面 Neil Brown 代笔 flock(2) 手册页 NOTES 段落，说明自内核 2.0 起 flock 独立成系统调用而非在 GNU C 库中经 fcntl 模拟，带来经典 BSD 语义即两种锁类型之间互不交互，Jeff Layton 则补充 “on BSD, flock() and fcntl() based locks do conflict”，据此判断若 BSD 将来实现文件私有锁其冲突面将与 Linux 现状不同

跨平台兼容性是贯穿上述三条线的压力源，2009 年 1 月新增 preadv 与 pwritev 系统调用时提交者明确要求 glibc 用户态接口 “compatible to the existing implementations in the BSD family”，直接把 BSD 家族当作 API 设计基准；2025 年 9 月讨论 ext4 文件系统 32 位保留 uid 时警告 “GNU Hurd or BSD had hijacked some reserved field”，保留字段成为跨实现共享的雷区；2015 年 7 月 Theodore Ts'o 在讨论移除 ext3 时梳理支持略有不同特性集的独立实现清单，列出 Hurd 的 ext2、星号 BSD 的 ext2 以及 Grub 的 ext2/3/4；2019 年 10 月移除 sysctl 系统调用与 uapi/linux/sysctl.h 的 RFC 中，作者统计头文件引用来源，glibc 之外的绝大多数命中是 “almost all of those hits are conditional includes for BSD systems”，Linux 内核头文件被 BSD 系统依赖的事实写在补丁正文里；2006 年 12 月 glibc 构建被内核头变更破坏的讨论中，依赖 BSD 特性的应用 “uses bsd features thus including net/if.h” 与同时引用的 linux/if.h 相撞；2014 年 6 月 Sam Ravnborg 转引 glibc endian.h 字节交换函数 “taken from FreeBSD I believe”，指出老系统缺乏该头文件支持因而需要 Linux 侧自行补齐端序转换能力

到 2026 年 6 月，这条线收束为一次对 BSD 拒绝的引用，David Laight 在 ELF 解释器路径支持 $ORIGIN 串的讨论中回应 Brauner 对 glibc 实现满是不当边角的担忧，确信 “NetBSD refused to implement $ORIGIN because it was full”，full 指的是漏洞，随后建议内核持有目录 inode 引用并给 openat 加相对该目录的参数；从 2003 年 FreeBSD 个人空间托管的 Linux GNU 补丁包，到 2022 年 Schwarze 因 FHS 拒绝 BSD 惯例而退出，再到 2026 年 fs/pipe 里 GNU make 与 BSD make 共享的同一条 token 管道，手册页、目录约定与工具行为这三条不以许可证文本为尺度的分界线，始终与 GPL 传染和 BSD 宽松条款并行累积，它们不以判决或和解收场，而以邮件列表里逐条被引用、逐次被勘误的方式，把两种操作系统传统写进代码、文档与构建脚本
