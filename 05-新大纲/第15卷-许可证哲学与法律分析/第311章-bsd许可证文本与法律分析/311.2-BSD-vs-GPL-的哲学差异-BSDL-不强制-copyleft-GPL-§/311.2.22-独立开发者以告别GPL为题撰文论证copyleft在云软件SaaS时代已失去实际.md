# 311.2.22 独立开发者以告别GPL为题撰文论证copyleft在云软件SaaS时代已失去实际

- 独立开发者以“告别 GPL”为题撰文，论证 copyleft 在云软件（SaaS）时代已失去实际效用：其仅存的用武之地是 MongoDB、Elastic 等商业厂商对抗云巨头的业务动机，而 FSF 在 Stallman 复职风波后既无应对云软件威胁的方案，也持续重复数十年前的论调，作者因此主张改用 MIT、BSD、Apache 2.0 等宽松许可证，并把精力转向反垄断、可持续商业模式与用户利益优先的监管。（BSD Now EP402，[282.18-516.52]，L2）
- AWS 工程师 Samuel Karp 开源 RunJ，一个面向 FreeBSD Jails 的实验性 OCI 兼容容器运行时；因 runc 与 containerd 现有 shim 深度假设 Linux 内核接口（cgroups、namespaces），作者选择从零实现而非移植，并附带自写 containerd shim，为 OCI 镜像生态进入 FreeBSD 打开通道，随后即有社区志愿者将其导入 ports。（BSD Now EP402，[716.66-918.42]，L2）
- 前微软 Xenix 团队成员回顾 1980-1989 年 Xenix 史：Xenix 为 AT&T Unix 的移植打包版本，1980 年 8 月 25 日经《Computerworld》公告上市、单套定价 2000 至 9000 美元；微软持有商标与 Unix 母许可证并向各 OEM 再授权，1983 年为 IBM PC AT（代号 Salmon）完成移植，后因放弃零售市场而与 Santa Cruz Operation（SCO）达成打包、销售与支持协议，1989 年团队解散。（BSD Now EP402，[919.42-1253.24]，L2）
- FreeBSD 开发者 Warner Losh 更新 QEMU bsd-user 用户态模拟分支：为摆脱数千补丁 rebase 的僵局，他将基于 3.1 的 bsd-user 目录直接并入 QEMU 6.0 并设 Blitz（快速可用）与 Kaizen（持续缩减 diff、先保 x86）双分支，与上游达成原则上每月合并的协议，目标是恢复以用户态模拟加速 FreeBSD 跨架构包构建的能力。（BSD Now EP402，[1254.24-1524.86]，L1）
- 2009 年 HP 老笔记本安装 FreeBSD 13.0 的实践记录：作者借 OpenZFS 2.0 原生数据集加密之机重装并加密 ZFS 池，经 i915 KMS 声卡 hint、微码加载、电源管理与 RAM disk home 等配置后成为轻量工作站，作者以 vi/Emacs、Firefox、LibreOffice 与 SSH 工作流证明旧硬件上的 FreeBSD 桌面仍然可用，同时折射出 base 系统对老硬件支持持续收窄的边界。（BSD Now EP402，[1604.78-1976.64]，L2）
- 新闻汇编：FreeBSD 开发者峰会（2021 年 6 月 9-11 日）开放注册并以直播与跨时区分场扩大参与；DragonFly BSD 6.0 RC1 镜像发布；Rob Pike 论文重提 Plan 9 词法文件名与符号链接破坏 Unix 层级路径语义的问题；OpenBSD 由 Dale Rahn 提交 64 位 RISC-V 架构初始支持，技术基础为 Brian Bamsch 等人的移植论文。（BSD Now EP402，[1976.64-2331.46]，L2）
- Adam Dunkels 自述其为瑞典计算机科学研究所（SICS）网络研究员，专攻内存仅数百字节量级的超小型网络化嵌入式设备；其主导的 Contiki 2.0 于 2007 年春发布，三大新特性为 ELF 格式动态加载模块（取代此前的预链接自定义格式，允许同一网络混布多版本内核）、protothreads 轻量线程与 RIME 低功耗协议栈。（BSDTalk EP107，[59.55-90.31, 640.47-791.38]，L1）
- Contiki 的差异化定位在于运行时动态加载与卸载程序：Dunkels 指出通用操作系统自 1960 年代即支持动态装载，但嵌入式领域默认将软件写入 ROM 后不可更改，而远程传感器（如投放入波罗的海后整个冬季不可触及的水质监测节点）必须支持运行中重编程，这一现实需求塑造了整个系统架构。（BSDTalk EP107，[199.19-263.0, 126.23-157.48]，L1）
- protothreads 以每线程仅 2 字节状态存储替代完整线程约 200 字节的栈预分配，在保留类线程线性编程模型的同时消除内存开销；uIP 栈以约 5K 编译代码、200 字节至 2K 可配置 RAM 的足迹实现 2001 年时最小的 RFC 兼容 IP 栈，RIME 则针对无线电收发能耗远高于 CPU 指令执行的现实，以头部压缩与非 TCP 原语（本地广播、网络泛洪、二进制数据分发）适应低功耗射频链路。（BSDTalk EP107，[717.01-768.37, 329.55-349.55, 366.91-459.60]，L1）
- Rick Macklem 完整口述了其 NFS 史前史：1980 年代中期其机构将 VAX 11/780 更换为 MicroVAX 2，因 DEC Ultrix 的许可证诸多限制不切实用，遂采用 BSD 源码（彼时尚属 AT&T 许可证时代、付费但不昂贵且须谨慎不外传）；因 CSRG 尚未向该机型移植，他自行完成 BSD 向 MicroVAX 2 的移植并交予 CSRG；继而因实际需要且恰逢 CSRG 对此感兴趣，他编写了 NFS 实现，该实现随各版发行流传，最终进入不携带 AT&T 代码负担的 4.4BSD-Lite Release 2。（BSDTalk EP116，[499.66-558.22]，L1）
- 截至 2007 年其 NFSv4 工程状态：过去一年专注于移植、可移植性与缺陷修复，代码已接近生产质量并在其环境中实际运行——服务器端跑 FreeBSD，学生实验室二十五台 iMac 以其客户端挂载；BSDCan 现场演示涵盖 Mac OS X（当时仅客户端，服务器端移植未完成）、OpenBSD 4 的客户端与服务器、以及 FreeBSD 服务器，均可互为 NFSv4 对端并同时兼容 V2/V3（共用同一端口、部分协议仍然共通）；全部代码以测试后期状态公开于圭尔夫大学的匿名 FTP 站点。 [存疑脚注] 转写作“ftp.cis.uogelph.ca flashpub flashNFSv4”，按圭尔夫大学域名应为 ftp.cis.uoguelph.ca 之 /pub/NFSv4 类路径（BSDTalk EP116，[64.7-147.48, 82.36-114.2]，L1）
- 对 NFSv4 协议的技术分析：安全上经 RPCSEC_GSS 调用 Kerberos，按挂载选项可对全部 RPC 做加密校验和的完整性检查或全链路加密，信任模型由主机级改为个人用户级（两种取向孰优在他看来始终存有争论）；RFC 要求合规实现支持 Kerberos 但部署上并不强制使用；统一用户命名空间取代了以往统一的 UID/GID 空间；ACL 仅以远程 setfacl/getfacl 的形式透传，协议本身假定服务器本地文件系统负责强制执行；字节范围锁定成为协议的组成部分，NFSv4 转为有状态协议、由服务器跟踪客户端打开文件与锁并内置状态恢复；Delegations 委托机制在客户端正确实现的前提下可带来显著性能提升，但当时各客户端实现尚未到位，故整体性能与 NFSv3 大致持平。（BSDTalk EP116，[151.88-307.8, 423.14-463.86]，L1）
- 对 NFSv4.1 的展望：其名为次要修订实为重大修订，草案已近五百页；两项主要新特性为 sessions（一个包罗全部 RPC 的传输层，同时承担状态处理）与 pNFS（将数据服务器与元数据服务器分离、面向高性能计算集群的并行化版本）——pNFS 的本质是将 Panasas 等厂商以专有技术做过的事情标准化为开放的 IETF 协议。（BSDTalk EP116，[691.06-752.74]，L1）
- Robin Watts 自述 Theora ARM 优化项目缘起于 2009 年作为独立承包商的工作空档期：以 BSD 许可的 Theora 参考实现为起点，经性能剖析定位热点后改写 C 代码并追加 ARM 汇编，最终在 500 MHz 的 BeagleBoard 开发板上实现 PAL DVD 影片的纯软件实时解码，目标是把视频回放带入更早期、性能更弱的手机。（BSDTalk EP189，[538.60-580.56]，L1）
- 当事人阐述的优化方法论为：先用 profiler 找出耗时集中的函数，优先在算法与 C 层面改进；再利用 ARM 寄存器更多、指针算术与移位近零成本等架构特性重排代码，最后才诉诸 ARM 汇编。其代码自 ARM2 起保持兼容，仅对收益显著的代际做专项优化，并指出 ARM 的 Neon SIMD 与 x86 的 SSE 定位相当。（BSDTalk EP189，[237.06-337.26]，L1）
- 许可轨迹为当事人刻意设计：最初以 GPL 发布自己的优化成果，使无法接受 GPL 的设备厂商须上门谈判付费，从而为投入的时间换取回报；Google 主动接洽并买断其开发时间后，整套代码回到 BSD 许可并入 Xiph.Org 上游仓库，Android 等任何项目均可自由使用。（BSDTalk EP189，[651.16-746.62]，L1）
- 当事人评述 HTML5 video 标签的价值：此前网页视频被 Flash、Java、Windows Media 等专有方案分割，任选其一都会排除部分受众；video 标签把解码责任交还各平台，手机可全屏、桌面可内联。但 H.264 因专利费与解码功耗不可能成为普适基线，Mozilla 即明言因专利费拒绝支持 H.264，Theora 因此可以充当处处可用的基线编解码器。（BSDTalk EP189，[1526.38-1667.72]，L1）
- ISC 为美国 501(c)(3) 非营利公益组织，维护 BIND、DHCP 及遗留产品 INN，约 40 名员工且半数远程办公，收入主要来自支持合同；Losher 任高级运维架构师，自嘲职责是“让所有人能在家里工作”。F 根服务器实际运行基本是现货软件：99.9% 情况下跑官方 FTP 站的 stock BIND，系统以 FreeBSD 为主、杂有少量 Linux 与 Windows，防火墙以 dummynet 应对 DDoS。（BSDTalk EP206，[45.36-400.88]，L1）
- 根服务器负载史：早期 F 根托管 com、net、org 及军方 mil 等大型区域，须用 DEC Alpha 5U 大机并装载 8GB 内存才能容纳 zone；Verisign 将 com/net 迁往 gTLD 服务器、arpa 区域外移后，根服务器专注于根区域本身。如今 F 根分布式部署逾 50 个节点、以 1U 商品机 4GB 内存即为过剩（签名后的根 zone 不足 300K），十三家根运营者之间刻意保持操作系统、硬件与名字服务器软件的多样性。（BSDTalk EP206，[527.92-682.16]，L1）
- DNSSEC 与 IPv6：根区域签名于此前一年夏天完成，从根运营者视角切换“无可挑剔”，曾担忧的“响应增大三至四倍、穿透不过防火墙”并未成真；ISC 自有区域已签名五年，com/net/org 与主要 ccTLD 已陆续签名，下一步目标是把 DNSSEC 验证能力推进到基础操作系统层而非仅浏览器。ISC 自 2003 年起内部双栈运行 IPv4/IPv6，参与 World IPv6 Day 并向项目提供 IPv6 隧道。（BSDTalk EP206，[682.16-856.78]，L1）
- 商业化与公益的边界：因根服务基础设施属公益免费资源，ISC 长期拒绝企业“帮忙做 secondary”的请求；此后另建由多家 tier-1 提供商组成的全球网络（ISC 运营设备而非自有网络）推出商业 secondary DNS 服务，把 F 根多年运维经验变现。F 根部署扩展则面向发展中世界（斐济、内罗毕、达卡等），并正将平台缩减得更经济、便于运输。（BSDTalk EP206，[856.78-948.80]，L1）
- McKusick 回忆早期 BSD 谱系：项目最初就是 Bill Joy 的一人工程，发布一些工具程序，首个发行物径称 BSD、后追认 1BSD，历经数个修订仍是工具集而非完整系统；约 1979 年的 3BSD 才是第一个带全部工具的完整系统；1979 年项目声望足以让 Bob Fabry 为系里争取到 DARPA 拨款，DARPA 想要一个所有承包商共用的操作系统基座，Joy 以 Unix 不绑定特定厂商说服对方，主要对手是只运行于 DEC 机器的 VMS——尽管当时 Unix 其实也只在 DEC 设备上运行，这一局面在 80 年代初随包括 Joy 赴创的 Sun 在内的工作站浪潮而迅速改变。（BSDTalk EP18，[77.45-211.79]，L1）
- 关于 TCP/IP 进入 BSD：ARPANET 原用 NCP 协议，仅运行于专用处理器且上限 256 台主机，扩张注定使其失效；伯克利的 DARPA 项目是让新协议 TCP/IP 落地，工作分工为 BBN 编写协议、伯克利定义并构建 API，今天尽人皆知的 socket 接口即伯克利的设计；BBN 交付的代码能打满一台 1 MIPS 处理器的 56 kbps，作为 ARPANET 速度尚称够用，但接上 3 M 以太网仍只有 56 kbps 吞吐，Joy 为使其跑满 3 M 乃至 10 M 以太网做了大量调优，期间与 BBN 产生分歧但最终解决；伯克利版的 API 与 TCP/IP 代码成为至少到 90 年代初几乎所有实现的共同基础。（BSDTalk EP18，[231.97-349.19]，L1）
- BSD 许可证诞生的完整链条：80 年代末以前获取 BSD 发行须先购 AT&T 源码许可证再另付一千美元，AT&T 许可费从两万至五万美元涨到 80 年代中期的二十五万至五十万，小公司无力承担，遂请伯克利单独发放明确属于伯克利的 TCP/IP 代码；伯克利律师想借此收取版税，团队以代码由政府资金开发、伯克利无权收费为由坚持开放；团队也评估过当时刚起步的 GNU 通用公共许可证，因其要求改动及关联代码全部开源——TCP/IP 运行于内核意味着交出整个内核——而否决；既不接受锁死权利的版权模式也不接受要求交出知识产权的 copyleft，他们自称 copy center，随取随拷、不要求回馈但予鼓励，许多厂商最终回赠大量代码，动因不是利他而是不堪每次新版发布后重新合并自有改动的负担；与大学律师反复争论后由律师定稿，即今日的 BSD 许可证，1988 年随 TCP/IP 代码及相关工具一并发布。（BSDTalk EP18，[371.17-547.37]，L1）
- 随后的代码释放与三团体分化：Keith Bostic 决心测试能解放多少代码，除内核外释放了全部有趣部分，CSRG 逐文件甄别内核归属并清除外来部分，尘埃落定时仅余约六个关键内核文件，1989 年发布后不久网络上的黑客便补齐了这六个文件，到 1990 年已出现可独立运行的 BSD；由此分出三支——坚持大学研究风格、保持系统小巧、追求多平台的 NetBSD，全力在 PC 架构上做到用户友好的 FreeBSD，两者目标分化迅速但都保持伯克利式许可证因而代码往来频繁；第三支是走向专有的 Berkeley Software Design Incorporated，整个 90 年代销售该系统，最终被 Wind River Systems 收购并将技术并入其产品。（BSDTalk EP18，[561.23-675.43]，L1）
- McKusick 当下的工作清单：近年持续增强文件系统——soft updates 以类似日志的机制让文件系统既快又稳且可恢复，snapshots 支持活动系统转储与后台文件系统检查；两年前出版 FreeBSD 操作系统设计与实现专著，其后围绕该书开发课件、授课并录像，即将开设一个读约八万行 FreeBSD 内核源码的代码阅读课；未来计划为 FFS 补上日志版本——对部分用户这只是采购清单上的勾选项——并完善 FreeBSD 中已有的 NFSv4 原型；他同时以教授身份厘清概念：UFS 是 Unix 文件系统的统称，FFS 是多数 BSD 系统采用的磁盘布局变体，此外还有日志式与内存式变体用于临时文件系统。（BSDTalk EP18，[683.77-834.79]，L1）
- Raymond 的许可证实用主义：他从不是传染性许可的拥趸，使用 GPL 只是随大流，且仅用于几乎无人会重用为库的独立项目；可链接库一律采用 BSD 许可，使开源与闭源、商业与非商业软件皆可使用，不愿以此限制用途；其思想近年演化到认为 GPL 如今可能弊大于利（十年十五年前未必如此）；Linux 及 GPL 软件的商业成功主要来自分布式同行评审效应的力量、与许可证大致正交；公司选择开源许可取决于商业目标——为颠覆市场而追求最大使用量时常选 BSD，为颠覆特定竞争对手则 GPL 可能是更好选择。（BSDTalk EP38，[399.04-498.8]，L1）
