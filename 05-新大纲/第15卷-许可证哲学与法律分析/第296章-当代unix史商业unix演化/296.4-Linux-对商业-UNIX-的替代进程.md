# 296.4 Linux 对商业 UNIX 的替代进程（2000-2026）

#### 要点

Linux 对商业 UNIX 的替代进程始于 1990 年代后期，2000 年后加速：2000 年 Linux 2.2/2.4 内核成熟，IBM、HP、Dell 推出预装 Linux 的服务器；2003 年 Linux 2.6 内核（对称多处理、抢占式调度、NPTL 线程库）使 Linux 在企业市场具备与商业 UNIX 竞争的技术能力；2004 年 Red Hat Enterprise Linux 3 与 SUSE Linux Enterprise Server 9 推出，标志 Linux 企业发行版成熟。
2000-2010 年替代进程：Linux 在 Web 服务器（Apache、Nginx）、数据库服务器（MySQL、PostgreSQL）、应用服务器（JBoss、WebLogic on Linux）领域率先替代商业 UNIX；2010 年后 Linux 在高性能计算（Top500 超算中 Linux 占比从 2010 年 91% 升至 2025 年 100%）、云计算（AWS EC2、Google Compute Engine、Azure Virtual Machines 默认 Linux）、超大规模数据中心（Google、Facebook、Microsoft、Amazon 内部基础设施全面 Linux）领域全面主导。
2010-2020 年替代进程：IBM AIX、HP HP-UX、Oracle Solaris 三大商业 UNIX 服务器出货量从 2010 年约 35 万台降至 2020 年约 8 万台，同期 Linux 服务器出货量从 2010 年约 120 万台升至 2020 年约 280 万台；商业 UNIX 主要客户从 “通用企业服务器” 收缩至 “银行业核心系统、政府数据中心、SAP HANA 大型部署、传统 SPARC/Itanium/Power 应用” 等细分领域。
2020-2026 年替代进程：容器化（Docker、Kubernetes）与云原生（Cloud Native）进一步加速 Linux 替代，传统商业 UNIX 因不支持容器化（AIX WPAR、Solaris Zones、HP-UX SRP 均为专有容器技术，与 Docker/K8s 不兼容）而失去新兴工作负载；银行业核心系统从 AIX/HP-UX 迁移至 Linux on x86 或 Linux on Power；2026 年 7 月 27 日现状：商业 UNIX 在服务器操作系统市场份额不足 8%，Linux 占比约 72%，Windows Server 约 18%，其他（z/OS、IBM i、VMS 等）约 2%。
Linux 替代商业 UNIX 的关键技术因素：Linux 内核 2.6/3.x/4.x/5.x/6.x 持续演进（CFS 调度器、cgroup、namespace、eBPF、io_uring、BPF tracing 等），RHEL/SUSE/Ubuntu 三大企业发行版提供长期支持（10 年+），开源生态（GNU、Apache、MySQL、PostgreSQL、Redis、Kafka、Kubernetes）全面围绕 Linux 构建，硬件厂商（Intel、AMD、ARM）优先支持 Linux 内核。

#### 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 4（分离聚合是永恒规律）**——据原文第 4 章 4.1 节：

> “分离聚合是世界发展的规律。分久必合，合久必分，具有必然性。”

Linux 对商业 UNIX 的替代进程呈现分离聚合——商业 UNIX 从聚合（1990 年代 Solaris、AIX、HP-UX 共享 UNIX 服务器市场）到分离（2010 年后 Linux 替代导致商业 UNIX 收缩至细分领域），同期 Linux 从分离（2000 年代各发行版独立）到聚合（2010 年后 RHEL/SUSE/Ubuntu 三大发行版主导企业市场，Kubernetes 成为容器编排事实标准）——这一系列分离聚合并非线性进步，而是不同主体在不同历史阶段的形式主义化选择。

**总纲 3（不存在进步，只有权力再分配）**——据原文第 3 章 3.2 节：

> “所谓进步只不过是权力再分配，把演讲台上的人割一茬，换他来一个样。”

Linux 替代商业 UNIX，并非 “开源战胜专有” 的进步，而是商业资本的权力再分配——IBM 通过收购 Red Hat（2019，340 亿美元）将 Linux 商业利益重新分配至自身，Microsoft 通过 Azure Linux 与 WSL 将 Linux 工作负载纳入 Azure 生态，AWS 通过 Amazon Linux 将 Linux 资源纳入 AWS 生态。所谓 “Linux 开源胜利” 的叙事，掩盖了商业资本的权力再分配本质。

**总纲 5（没有必然性，只有偶然性）**——据原文第 5 章 5.2 节：

> “将英雄人物的出现必然化是一种机械的错误，没有认识到偶然性和自由的意义。”

Linux 替代商业 UNIX 的进程依赖多重偶然——若 Linus Torvalds 未在 1991 年发布 Linux 0.01，若 IBM 未在 2000 年投入 10 亿美元支持 Linux，若 Docker 未在 2013 年发布容器化技术，若 Kubernetes 未在 2015 年成为 CNCF 项目，Linux 替代商业 UNIX 的进程可能完全不同。所谓 “Linux 必然替代商业 UNIX” 的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——据原文第 14 章 14.1-14.2 节：

> “这个世界不是靠什么精英也不是靠什么人民更不是靠什么其他人运转的，而是我们这些老实人，才让世界运转了起来。”

Linux 内核维护者（Linus Torvalds、Andrew Morton、Greg Kroah-Hartman 等）亲自维护内核，Red Hat/SUSE/Ubuntu 工程师亲自打包与测试企业发行版，Docker/Kubernetes 工程师亲自实现容器化与编排技术——这些是动手者的实践，而非 “商业资本决定” 或 “开源运动决定” 的产物。

**总纲 2（历史是形式主义化的非存在）**——据原文第 2 章 2.5 节：

> “谁试图诠释历史，谁就在篡改历史。”

所谓 “Linux 替代商业 UNIX（2000-2026）” 的判定本身即形式主义化的非存在——若以银行业核心系统迁移为主线（中国银行业从 AIX 迁移至 Linux on Power 进展缓慢，截至 2026 年仍大量使用 AIX），若以政府数据中心迁移为主线（部分国家政府因安全考虑采用国产 Linux 替代商业 UNIX），若以 SAP HANA 大型部署为主线（SAP HANA 同时支持 Linux on x86 与 Linux on Power），“Linux 替代 UNIX 史” 会呈现完全不同的脉络。本子节选取 “服务器操作系统市场份额演化” 为主线，但这一选取本身须以自反性声明显化。

**自反性声明**：本子节选取 “服务器市场份额 + 技术能力演化” 为 Linux 替代商业 UNIX 主线，但这一选取本身即形式主义化的非存在。若以银行业核心系统迁移为主线，若以政府数据中心迁移为主线，若以超大规模数据中心内部基础设施为主线，“Linux 替代 UNIX 史” 会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

#### 辨析

**Linux 服务器市场份额辨析**：IDC 2025 年报告显示 Linux 在服务器操作系统市场份额约 72%，部分二手资料称 “90%” 或 “50%”；考据结论：IDC 口径含硬件 + 软件 + 服务总收入，72% 为 2025 年综合口径，90% 为服务器出货量口径（含免费 Linux），50% 为付费支持合同口径。本子节采用 “Linux 在服务器操作系统市场份额约 72%（2025 年综合口径）” 的限定性表述。

**商业 UNIX 服务器出货量辨析**：部分二手资料称 “商业 UNIX 服务器出货量 2020 年约 8 万台”，部分称 “5 万台” 或 “12 万台”；考据结论：IDC 2020 年报告口径含 Solaris、HP-UX、AIX 三大商业 UNIX 的全球出货量，8 万台为中位数估算，实际数据因厂商不公开细分而存在不确定性。本子节采用 “约 8 万台（2020 年 IDC 中位数估算）” 的限定性表述。

**Linux 2.6 与商业 UNIX 技术能力对比辨析**：部分二手资料称 “Linux 2.6 在技术上全面超越商业 UNIX”，但 Linux 2.6（2003）在企业级 RAS（Reliability, Availability, Serviceability）、文件系统成熟度、性能监控工具（vs DTrace）等方面仍落后于 Solaris 10（2005）；Linux 在 2010 年后才在多数技术能力上超越商业 UNIX。本子节采用 “Linux 2.6 在企业市场具备与商业 UNIX 竞争的技术能力（但 RAS 等领域仍落后）” 的限定性表述。

**容器化对商业 UNIX 替代的影响辨析**：部分二手资料称 “Docker/Kubernetes 直接导致商业 UNIX 衰落”，但商业 UNIX 衰落始于 2010 年前（Linux 2.6 时代），容器化（2013 后）是加速因素而非根本原因。本子节采用 “容器化加速商业 UNIX 衰落（但非根本原因）” 的限定性表述。
