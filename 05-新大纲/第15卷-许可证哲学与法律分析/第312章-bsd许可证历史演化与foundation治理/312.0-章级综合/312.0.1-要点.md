# 312.0.1 要点

- **GPL**（**GNU** 通用公共许可）以 **copyleft**（传染性）要求派生作品同许可开源，与 **BSD** 许可的 “最小限制” 形成根本对照；**Linux** 内核采用 **GPLv2**，使整个内核生态受 **copyleft** 约束，与 **BSD** 家族的 permissive 许可在 “自由定义” 上分野。
- **Apache 2.0** 与 **MIT** 同属宽松许可，与 **BSD** 许可家族相近但各有细节（**Apache** 含专利授权条款、**MIT** 极简）；二者与 **BSD** 共同构成 “permissive 阵营”，与 **GPL** 的 **copyleft** 对立，体现开源许可光谱。
- **Microsoft Windows** 采用闭源商业最终用户许可（**EULA**），禁止源码查看与修改，与 **BSD** 许可的 “源码自由 + 最小限制” 根本对立；闭源使代码不可审计，与 **BSD** 的开源可验证存在差异。
- 三大 **BSD** 的许可同源 **4.4BSD-Lite** 的 **BSD** 许可，后各自微调（如去 **UC Regents** 署名、调整广告条款）；**FreeBSD**/**NetBSD**/**OpenBSD** 的许可文本趋同于 “简化 **BSD**/2-clause”，体现 **BSD** 家族在许可上的共识与流动。
- 软件许可呈 “**copyleft**（**GPL**）vs permissive（**BSD**/**Apache**/**MIT**）vs 闭源（**Windows EULA**）” 三极格局；**BSD** 许可以 “最小限制 + 可审计” 在开源生态中独特定位，既区别于 **GPL** 的约束，也区别于闭源的不透明。
