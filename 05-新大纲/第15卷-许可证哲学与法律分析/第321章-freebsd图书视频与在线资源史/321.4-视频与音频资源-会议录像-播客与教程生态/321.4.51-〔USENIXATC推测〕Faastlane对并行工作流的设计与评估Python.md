- 〔USENIX ATC（推测）〕Faastlane 对并行工作流的设计与评估。Python、Node.js 等解释型语言受全局解释器锁（GIL）限制无法并行多线程，因此在工作流存在并行阶段（如 FINRA 数百条审计规则可并行）时按进程乃至跨容器启动函数，以牺牲部分交互时延换取硬件并行度。评估在 36 核 Intel Xeon 机器上进行：AWS Step Functions 与 OpenWhisk（Kafka 队列）函数交互时延很高，Sand 次之，Faastlane 最多仅花 1.6% 的执行时间在函数交互上，吞吐较 OpenWhisk 最高提升 16 倍、较最接近的 TensorRT 高 49%，且对开发者完全透明。（YouTube EP5T104i7fYgU，[450-888]，L1）
- 〔USENIX FAST（推测）〕Kosmo：面向可变缓存大小与逐出策略的高效缺失率曲线（MRC）在线建模。主讲人指出 Redis、Memcached 等内存缓存配置过小性能差、过大则浪费昂贵内存，且负载随时间动态变化，需要实时高效建模；MRC 上的悬崖（cliff）与平台（plateau）区间对容量调优很关键，LRU/LFU/FIFO/2Q/S3-FIFO 各有适用场景，并无一劳永逸之选（该负载下约 67GB 以上 S3-FIFO 反被 LRU/LFU 超越）。现有近似 MRC 生成工具中 MiniSim 是唯一支持非 LRU 策略的，但其多模拟缓存不共享内部数据结构，52 条公开轨迹共 1260 亿次访问下单策略单条 MRC 内存可高达 3GB，且须预先指定缓存数量与大小范围。Kosmo 让所有模拟缓存共享一份对象副本，并引入新颖的 eviction map（逐出映射）数据结构按需动态重建任意大小的缓存栈。（YouTube EP67QWxt4QZ38，[16-555]，L1）
- 〔USENIX FAST（推测）〕Kosmo 的重建流程、优化与评估。eviction map 按策略记录对象从哪些缓存大小被逐出（如 LFU 还记录逐出时的频次计数），每次访问时重建对象缺失的缓存栈、插入并更新相关对象的逐出记录。通过逐出记录剪枝（被 size 3 逐出必然曾被更小缓存逐出）平均每对象逐出记录规模缩减约 387 倍；引入粒度参数在重建次数与精度间权衡，每次访问限制 5-10 个模拟缓存时 MRC 平均绝对误差（MAE）低于 2%，仅 1 个模拟缓存时中位 MAE 也在 5% 以内；沿用 shard 采样使存储与计算开销降低超 1000 倍。在相同 52 条轨迹上，Kosmo 内存占用较 MiniSim 平均低 3.6 倍、极端情况低 36 倍，并免去了预先配置参数的要求。（YouTube EP67QWxt4QZ38，[555-1110]，L1）
- 〔USENIX FAST（推测）〕LADS：布局感知的数据传输节点（DTN）调度。Los Alamos 国家实验室的 Yongjae Kim 主讲；DOE 数据中心年产出预计达 EB 级，ESnet 已部署 400GbE，而数据集仍存于较慢的存储系统，DTN 成为快网络与慢存储之间阻抗失配的焦点：Oak Ridge 的 Spider 并行文件系统（Lustre）与 Titan 超算共享，多集群 I/O 争用在网络层、文件服务器、磁盘多层发生。传统基于文件（file-based）的传输忽略底层文件布局，多线程争用同一对象存储目标（OST）或受条带宽度限制，可使线程速度放慢 25% 甚至 50%。LADS 采用对象级（object-based）方法理解文件条带、OST 与存储服务器拓扑，把 I/O 线程调度到不同对象与磁盘以避免争用，设计目标包括最大化 DTN 多核并行、经 CCI（Common Communication Interface）支持现代网络、利用 PFS 并行性以及热点/拥塞规避。（YouTube EP7GKcRNzX-zk，[10-647]，L1）
- 〔USENIX FAST（推测）〕LADS 的实现、算法与评估。基于 CCI 的源/汇架构含主线程、I/O 线程与通信线程，预注册 RMA 缓冲区并以队列驱动读写；实现基于阈值的反应式拥塞规避算法跳过热点 OST，以及 SSD 映射的扩展缓冲避免 RMA 缓冲满载阻塞。测试床（Xeon DTN + Fusion-io SSD，QDR InfiniBand 40Gb，32 盘 Lustre PFS）验证存储带宽约 2.3GB/s 慢于网络 3.2GB/s；评估显示 LADS 在 I/O 线程数上近乎完美线性扩展而 bbcp 提升有限，拥塞场景下优于轮询基线，在 Oak Ridge 两个 Atlas 文件系统间实测数据传输速率比 bbcp 高达 6.8 倍。问答环节讨论了与 Lustre NRS 的关系，并承认本工作未处理磁盘故障与 Lustre 客户端逐出等失效情形。（YouTube EP7GKcRNzX-zk，[647-1564]，L1）
- 〔USENIX ATC（推测）〕FpgaNIC：基于 FPGA、以 GPU 为中心的多功能 100G 智能 NIC。浙江大学的 Zeke Wang 主讲，与 Gustavo Alonso 等合作；动机是 GPU 在 HPC/AI 应用中承载绝大部分网络流量却只是 CPU 的"打工人"，应让 GPU 成为网络数据的"老板"：ARM 智能 NIC 内存带宽仅约 28GB/s 难以消化 100G 数据，ASIC 则需要多年流片周期且成本高昂。FpgaNIC 由三部分组成：GPU 通信栈实现控制面与数据面卸载（FPGA 直接与 GPU 经 PCIe P2P 通信，并首创让 FPGA 使用 GPU 虚拟地址访问 GPU 显存）、硬件网络传输（开源 100G TCP 协议栈，GPU 只处理网络载荷）、片上计算提供灵活的 100G 数据面加速。（YouTube EP7g_VGfhh3dE，[13-585]，L1）
- 〔USENIX ATC（推测）〕FpgaNIC 的三种语义模型与实验评估。direct 模型直接连接 GPU 通信栈与硬件传输（GPU 中心网络，GPU 直接收发 NIC 命令并启动 kernel，NIC 与 GPU 操作易于并行）、off-path 模型让片上计算直接操纵栈与硬件（纯硬件 AllReduce）、on-path 模型让片上计算充当栈与传输间的垫片（边传输边做 HyperLogLog 基数估计）。在 8 台服务器（Xilinx Alveo U280/U50 + Nvidia A100）上验证：GPU-FPGA 时延稳定且远小于 GPU-CPU-FPGA 之和，访问 GPU 与 CPU 显存吞吐相当；控制面卸载在各传输长度下均显著提升吞吐且越小越明显，纯硬件 AllReduce 在数据大于 2MB 时带宽与启用 RDMA/GPUDirect 的 NCCL 相当而不占任何 CPU/GPU 周期与显存，on-path HyperLogLog 不影响可达吞吐。系统已在 GitHub 开源。（YouTube EP7g_VGfhh3dE，[585-1156]，L1）
- 〔SREcon〕Meru：Dropbox 开源的去中心化用户权限管理系统。Dropbox 基础设施安全团队工程师、Meru 维护者 Luke Ferrone 主讲；Meru 是认证与授权服务，为每位员工维护带元数据与组成员关系的档案，开源、去中心化（尽力把安全团队移出关键路径）、可审计，内部原名 grouper 因与 Internet2 的 Grouper 项目撞名而改名。构建动机包括让建组与授权足够简单以抑制越权申请、可扩展、可见性（一站式查看员工权限范围）以及合规（ISO 27001、HIPAA BAA 等审计要求），并回顾了从 Google 表单 + 审批电子表格、到带数据库与"Other 万能自由文本字段"的内部工具的演进；约 2014 年一位休育儿假的 SRE 写出了 Meru 的初始版本，涵盖 user、group、permission、service account 四个核心组件。（YouTube EP7gzYhEch0_I，[6-613]，L1）
- 〔SREcon〕Meru 的模型、民主化审批与分布式审计。现场演示用户加入组、经组获得权限的流程：组可嵌套继承权限（类似 LDAP 但支持多重继承、不强制严格层级），权限形为 permission + 自由参数并针对具体资源。Meru 的核心在民主化：把审批权下放给组主与 permission granter，权限请求可由全局审批者或资源所属组批准，还支持以自定义 Python 插件路由请求（如让机器属主审批其机器的访问）。系统维护全量审计日志并支持分布式审计：权限可标记为 audited，持有该权限的组成为受审组，组主须接受培训并每季度完成访问复核，合规团队另有"天眼"视图。对外提供只读 REST API 与 JSON/自定义格式数据导出（cron 同步），并介绍了与 AWS IAM 的集成。（YouTube EP7gzYhEch0_I，[613-1220]，L1）

- 〔NSDI（推测）〕Sandook：驯服性能变异、释放数据中心 SSD 潜力。主讲人 Gohar 指出 1TB 数据中心级 SSD 价格因 AI 负载需求从约 60 美元涨至近 300 美元，资源弥足珍贵；在其 12 块 SSD 测试床（90% 读负载、尾时延 SLO 小于 1ms）上，厂商标称聚合约 500 万 IOPS 实际只跑出不到一半，性能缩水 50%。性能变异有三大来源：设备异构（不同厂商/型号/固件乃至同型号因磨损不同而异，同 SLO 下从 0.3 到 100 万 IOPS 不等）、读写干扰（90% 读混合 10% 写即令吞吐下降 33%）、以及软件不可控的固件垃圾回收（毫秒级尾时延尖峰）。现有系统负载均衡对所有 SSD 一视同仁、路由僵化，且三类变异出现在相互冲突的时间尺度上。Sandook 借两大设计应对：路由灵活性（写按日志结构追加到任意有效 SSD、读经副本路由）与时间尺度分离（慢路径集中控制器 + 快路径即时响应拥塞信号）。（YouTube EP7mkkDIrrkCo，[18-525]，L1）
- 〔NSDI（推测）〕Sandook 的系统设计、策略与评估。应用经标准 Linux 块设备（/dev/Sandook）或文件系统访问，薄客户端连接存储服务器上的 SSD agent，中央控制器周期性下发调度策略（控制路径），拥塞信号则由 agent 捎带在请求上直达客户端（快速路径）；数据路径上写按最新策略复制到合适的 SSD、按副本读。策略包括以线性程序做基于性能画像的负载引导（黑盘 100 万、灰盘 70 万 IOPS 时按 60/40 分流可同时满足需求与 SLO，而均分会让灰盘过饱和）、以只读/写模式物理分离读写操作（聚合从 120 万提升到 220 万 IOPS）以及借鉴 TCP 的存储拥塞控制。评估中 Sandook 综合各策略解锁理想吞吐的 95%（同等美元成本下吞吐翻倍），较现有系统存储吞吐提升 1.7 倍、应用层吞吐 1.9 倍、时延降低 88%，无需修改应用代码且已开源。（YouTube EP7mkkDIrrkCo，[525-1033]，L1）
- 〔SREcon（推测）〕Unix 架构演化的教训（上）：历史与方法。主讲人（合作者为格罗宁根大学 Paris Avgeriou）以"systemd 做错了什么"为备选标题，回顾 Unix 自 AT&T 贝尔实验室（8 项诺贝尔奖、3 项图灵奖之地）的诞生：Multics 因过于野心勃勃失败后，Ken Thompson、Dennis Ritchie 等在 PDP-7 上开发出内核不足 2600 行汇编的无名系统。研究基于三类史料：GitHub 上的 Unix 历史仓库（早期版本据 Caldera 授权版与志愿者扫描的第一版手册备忘录合成提交时间戳）、以 troff 源排版的手册、以及 500 多个由手册功能提炼的架构设计决策清单。教训包括：写小程序；经分区、组合与分层构建模块化代码（ed 的冒号命令沿用至今）；重视开发者时间胜过机器时间（inode 与 namei、一切皆文件、统一的文件 I/O API）；先原型后打磨（第一研究版的系统调用名称与编号在 FreeBSD 乃至 Linux 中沿用）；每个程序只做一件事（cat 对比 12 个选项的 cut）；避免被俘获的接口（shell 是可替换的普通用户程序催生大量 shell 创新）；写可扩展的程序与协议（/usr 用户贡献工具与 cron 删除无手册文档的做法），并现场演示经动态加载器与 readline 为任意 CLI 注入自然语言 AI 接口（OpenAI API）。（YouTube EP7mwzwgWz2k8，[16-1030]，L1）
- 〔SREcon（推测）〕Unix 架构演化的教训（下）：过滤器、可维护性与机制/策略分离。管道作为文本流过滤器源自 Doug McIlroy 1964 年"像花园水管一样连接程序"的备忘录，1973 年第三研究版实现 pipe 系统调用后贝尔实验室彻夜把数十个程序改造成过滤器；第四研究版以结构化编程（new B 语言 6300 行内核 + 700 行汇编，函数 105 个、全局符号仅 50 个）与共享头文件（145+ 处复用）树立可维护性典范。50 年前的照排机故障（"cannot open file foo bar"）促使标准错误流的发明。选择足够强大的抽象：第六版的可移植 C 库（Lions 注释的源码笔记广为流传）使程序免移植即可跨系统、第七版确立"移植 Unix 比移植复杂应用更容易"；机制与策略分离带来 malloc（26 个程序立即采用）、lint 静态分析、环境变量、目录层级约定与自举（self-hosted）等成功，lex/yacc 生成器与小语言（shell、awk、sed、make）抬高抽象层级。反面教训是架构创新有粘性：正则表达式库客户端增长缓慢、FreeBSD 收编 awk/sed/grep/expr 各自实现颇为痛苦；现代 FreeBSD 数百万行代码仍保留大部分架构形态。最后一课：包管理器孕育生态与社区——386 BSD 补丁包把开源软件变成开源项目，FreeBSD 的包管理器（含依赖处理）带动今天围绕操作系统的繁荣生态。（YouTube EP7mwzwgWz2k8，[1030-2050]，L1）
- 〔HotCloud〕在不可信云上用部分同态加密保密切性地做大数据分析。主讲人 Julian（合作者转写为 John Volk、Silas Russell，导师 Patrick Eugster 教授）在 HotCloud 会议上报告；动机是隐私泄露频发（privacyrights.org 记录的医院患者病历与 P.F. Chang's 信用卡信息泄露），全同态加密（FHE）开销极高且表达力受限（只能手工组合寄存器级加法与乘法），而部分同态方案各有专长：Paillier 支持密文加法、ElGamal/未填充 RSA 支持密文乘法、保序加密（OPE）支持比较。其思路是变换开发者编写的 Pig Latin 脚本使其直接作用于密文：sum 变换为 Paillier 的 ENC_sum（密文相乘后 mod n^2），filter 用 OPE 加密常量后比较——因加密值超出 Java int/long 范围而以十六进制字符串表示并经 GMP 大整数库比较；同一列既用于 sum 又用于 filter 时需以两种加密方案各加载一份，group by 则要求操作数具有确定性。（YouTube EP7p17skkCtnA，[11-662]，L1）
