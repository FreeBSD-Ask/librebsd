# 321.4.4 受访者将播客定位为倡导而非新闻采访风格刻意温和不做对抗性质询希望受访者有愉快经历

- 受访者将播客定位为倡导而非新闻：采访风格刻意温和，不做对抗性质询，希望受访者有愉快经历。BSD 一词在其栏目中取宽泛定义，涵盖一切宽松许可证项目而非仅 BSD 内核体系，BSD、MIT、ISC 许可证被视为同类；栏目目标之一是让开发者对宽松许可证安心，借盈利企业沿用该许可证而不损害商业模式的事例消解白白赠出却无人回馈的顾虑。（BSDTalk EP217，[286.9-348.38]，L1）
- Allan Jude 自述两档节目的生产机制：TechSnap 开播 134 周以来每周四一期从未间断，定位为面向系统管理员的安全新闻拆解加听众问答；BSD Now 则专攻 FreeBSD、NetBSD、OpenBSD，每周三东部时间下午两点直播，由 TJ 撰写几乎全部节目笔记与教程、PC-BSD 的 Kris Moore 主持；他起初认为 BSD 内容不足以支撑每周一档，深入参与会议与文档写作后才改观。（BSDTalk EP235，[272.10-378.10]，L1）
- Scale Engine 的 CDN 分布于 10 国 30 个数据中心（仅荷兰即 4 个），以 GDNSD 做全局服务器负载均衡——该软件原是 Logitech 开发者为地理分布驱动下载而写，用 GeoIP 数据库按解析请求来源改写结果，并辅以外部健康监控插件：经 SNMP 轮询网卡利用率、超过七成即视为不可用而改指次近节点；由于 DNS TTL 加上部分 ISP 无视 TTL 长时间缓存，无法确保新用户立即离开故障节点，故只向每台服务器推送六至七成链路容量——直播流一旦发生争用是全体观看者体验崩坏，而 HTTP 下载争用只是各自变慢。（BSDTalk EP235，[451.72-619.30]，L1）
- 运维与部署体系：全球机房一律租用服务器而非托管，以换取 30 天合约与厂商换件；经 VPN 加 IPMI 带外管理，可在汉密尔顿的桌面上给阿姆斯特丹的服务器挂载 ISO 重装系统；部署链为 FreeBSD 9.2 原版安装、自有 pkg 仓库（以定制编译选项预编译 Nginx 与 Varnish）、bootstrap pkg 后交 Puppet 签名引导，从 Puppet 启动到投产约七八分钟；PC-BSD 的 ISO 与 pkgng 仓库以 ZFS 复制预置到边缘，而 pkgng 仓库要求 repo 清单与密码学签名的 SHA-256 摘要文件同全部包文件保持整体一致、绝不许新旧混合状态，故用 rsync 延迟更新选项先写入临时目录再原子改名就位，每 15 分钟复制一次。（BSDTalk EP235，[691.80-978.18]，L1）
- Puppet 链路的性能改造：视频流所依赖的大型 Java 应用打包成 jail 由 Puppet 分发、EzJail 部署；经 Puppet 的 Ruby 代码直接分发 500MB 文件效率极低，其解法是教会 Nginx 信任 Puppet 的证书颁发机构，仅允许持 Puppet CA 所签客户端证书的已激活节点从安全文件库直接经 Nginx 拉取，安全模型不变而性能大幅提升；这些 Puppet 与 Nginx 优化曾于 2013 年春在 BSDCan 演讲披露。（BSDTalk EP235，[980.90-1046.78]，L1）
- 包管理迁移的量化对比：当年各边缘节点启动时自行从 ports 编译全部所需软件约需 45 分钟，切换 pkgng 后缩短至七分钟且一半耗在 EzJail；Poudriere 取代旧 Tinderbox，实测每 CPU 开一个 jail、单作业串行反而快于跨机并发分派，一台 24 核 96GB 内存的机器在 tmpfs 中编译全量约 24000 个 port（含 24 种语言的 LibreOffice 与四个 Firefox 版本）约 14 小时；他以 Poudriere 生成新包集再以 pkg2ng 转换旧机，通过手工改写包 origin 化解 Perl 5.10 到 5.14 与 PHP 5.3、5.4 并存的依赖冲突，迁移之顺利出乎意料。（BSDTalk EP235，[1069.80-1268.36]，L1）
- 升级 FreeBSD 9.2 的主要动机是 ZFS v5000：LZ4 压缩与存储池接近满载时的性能改进，对存有四组共 50 至 60TB 视频数据的阵列尤为关键；新版命令行全面支持干跑预演——删除快照前可预估将释放的空间，增量 zfs send 前可预估传输量，他据此脚本化出进度条，得以预知一次发送的体量与完成时间。（BSDTalk EP235，[1443.66-1538.90]，L1）
- BSDTalk 的主要文件托管于主持人所属大学的 IT 基础设施已逾十年，近年随大学 IT 整合，服务器从物理机转为虚拟机、再沦为基础设施中只剩 IP 地址的无名存在，最终于 2014 年秋被回收且早于预期，近期备份未能如预期迁出，仅音频文件因早已备份至 archive.org 而幸存。（BSDTalk EP245，[44.20-100.94]，L1）
- 主持人描述了个人服务器文化的情感与功能双重结构：多年不变的 DNS 名与 IP 地址、常年备有的 shell 账户、随需中转连接的跳板、以安全拷贝上传再经标准 HTTP 分发的个人模式，对照彼时新兴的 Google Drive 式云分享；其数字空间的归属感系于一个机构地址，而机构流程的变动即可令其一夜漂泊。（BSDTalk EP245，[100.94-154.62]，L1）
- 该服务器长期运行 Novell SUSE Linux，因为那是大学 IT 支持的体系；主持人自省 BSD 播客却托管于 Linux，但选择入乡随俗、不强求超越机构标准；失去托管后他考虑重建自有服务器，并权衡 VPS 提供商、共置托管、家庭服务器等路径，同时指出暴露于互联网的服务器不可无人值守地放任运行，必须易于维护、更新与安全补丁管理。（BSDTalk EP245，[154.62-330.38]，L1）
- 主持人在权衡备份方案时列举了 BSD 文件系统技术的当代能力：HAMMER 文件系统的主从 PFS 复制与 ZFS send 均可实现近乎实时的异地副本，使备份从偶发行为变为接近连续的镜像；这为个人档案保存提供了区别于传统周期备份的技术路径。（BSDTalk EP245，[262.30-287.54]，L1）
- 主持人为重建播客服务器设定了 SSH 命令行、基本 web 服务、低维护与长期存续四项准则，并据此评估现有条件：家中的 Soekris 单板机（4501 或 5501 型）无活动部件、低功耗，但 ZFS 按通行建议需数 GB 内存、ECC 内存与多块磁盘，HAMMER 虽具吸引力却因 DragonFly 即将放弃 i386 支持而使旧设备没有多年期未来，故结论是需要低功耗的 64 位机器；他同时提醒 UFS 与 FFS 久经考验、在其数据量级下不应被轻易否定。（BSDTalk EP246，[95.24-265.12]，L1）
- 主持人试验了冰岛服务商 PageKite 的隧道方案：一个任何人都能运行的 Python 脚本实现向外隧道，由服务商承接 web 地址与 SSL 终结，支持任意端口转发并采取自定价收费，为家庭宽带上的主机提供了一层对外部世界的抽象与网络可达性。（BSDTalk EP246，[271.70-313.04]，L1）
- 在 OpenBSD 上主持人完成了一项 Tor 强制实验：经 ports 安装的 Tor 以 _tor 用户身份运行，利用 PF 防火墙可按用户匹配规则的特性，先以 block out all 封禁全部出站，再仅放行 _tor 用户产生的 TCP 与 UDP 出站包，使笔记本除 Tor 流量外无任何出站连接；DHCP 因先于 PF 启动而幸存，NTP 等服务被阻断，更新软件包时需临时停用 PF；该强制规则反过来保证了浏览器必须正确配置远程 DNS，否则 Tor 完全无法使用。（BSDTalk EP246，[584.98-702.50]，L1）
- 主持人以亲历视角剖析 Tor 的可见性与泄漏问题：浏览器默认经操作系统解析器发起 DNS 查询而绕过 Tor 网络，造成流量信息泄漏，须按浏览器分别设置远程 DNS；以明信片与信封作喻指出，在多数流量近乎明文的互联网上，Tor 流量被本地 ISP 识别这一事实本身，在某些国家反而可能使用户成为监控关注对象；诸如 CapLoader 之类的流量分类工具据称可凭统计分析而非端口号稳定识别 Tor 流量。（BSDTalk EP246，[483.20-575.40]，L1）
- 主持人复述了 2014 年语境下的 Tor 威胁图景：出口节点对返回数据具有控制力；据其读到的新闻报道对 Edward Snowden 文件的披露，政府机构曾以运行恶意出口节点劫持或注入返回流量（例如篡改 Flash 更新二进制）、以 FoxAcid 攻击 Firefox、利用 Tor 浏览器捆绑包中旧版 Firefox 的漏洞等手段针对 Tor 用户；登录邮箱即暴露身份、cookie 与设备指纹（浏览器与插件版本、补丁级、屏幕分辨率）皆可去匿名化，故运行 Tor 的机器不应兼作日常用途。（BSDTalk EP246，[797.64-1057.68]，L2）
- TeachBSD 的缘起与教学法假设：剑桥大学硕士项目长期缺乏实践性操作系统课程，Robert Watson 与 George Neville-Neil 借此检验两个假设——其一，以真实世界的操作系统取代玩具系统与模拟器来教授 OS 课程；其二，以追踪与性能分析工具为课程核心，把操作系统当作被观察、分析、修改的实物。课程以源自 Solaris 的 DTrace 为基础，通过案例研究让学生可控地接触真实系统复杂性，避免传统内核实验中连续数周崩溃系统的低效模式，并使学生毕业即掌握可迁移的追踪分析技能。（BSDTalk EP260，[179.16-359.52]，L1）
- 双轨课程、教材与平台：学术版为剑桥 8 周硕士课，从业者版可在两日内授完（2015 年 3 月 AsiaBSDCon 试教，业界面向在职者的动手型 OS 培训此前近乎空白，唯一先例是 Kirk McKusick 在 UC Berkeley Extension 的 15 周密集课与公司内 5 天版）；教材由 FreeBSD 设计与实现（McKusick、Neville-Neil、Watson 第二版）、Brendan Gregg 的 DTrace 实践书与 Raj Jain 1991 年性能分析经典组成，静态教材无法覆盖 OS 演进与动态行为，DTrace 恰补足真实负载下的系统行为分析；学术版用 ARMv7 BeagleBone Black 受控平台保证性能测量可复现（含缓存与页表遍历等微架构成本），从业者版用 x86 虚拟机免去硬件采购但性能受宿主影响、多数虚拟化系统不支持性能计数器，可复现性较弱。（BSDTalk EP260，[360.62-1155.22]，L1）
- 课程开发对 FreeBSD 的反哺：学术课尽力追踪 current，因备课过程本身为 FreeBSD 做出大量改进——ARMv7 上 DTrace 的成熟化（项目启动时 DTrace 在 x86 良好而 ARM 不佳）、BeagleBone Black 支持改进，以及开发实验时发现的通用 trace points 进入 current；两年教学间可在基准中直接观察到 ARM SuperPage 支持引入带来的性能变化；近期目标是把课程改动合入 FreeBSD 本体，实现“现货 FreeBSD 加 TeachBSD 包即可运行”。（BSDTalk EP260，[1637.34-1801.86]，L1）
- 推广与社区化路径：teachbsd.org 承载两条材料线——GitHub 上的参考开发主干（发布时已被 fork 12 次，团队主动甄别 fork 者并联络）与剑桥实际授课页面快照；教学指南同时经 Pearson（FreeBSD 设计与实现一书的出版商）渠道推向美国高校；Neville-Neil 携课程经验全球访校，泰国朱拉隆功大学（3.5 万本科生、年招约百名计算机本科生）表现浓厚兴趣，其半退休教授早已在用 DTrace 与 FreeBSD 授课而双方此前互不知晓；口号“偷走这门课”表明开放复制与本地化改造的预期。（BSDTalk EP260，[642.04-879.72]，L1）
- 人才培养论辩：低层系统岗位市场随高层系统扩张而在增长，但大学课程从 C/C++ 转向 Java、Python 等高级语言削弱了学生的低层系统能力；剑桥研究生课程中硬件软件协同设计、编译器与低层 OS 等课程因技术挑战性而广受欢迎，说明需求与兴趣俱在，瓶颈在于教授构建可复现课程的成本——8 周的 L41 课程备课约需 700 至 800 小时，远超常规讲义每小时 8 至 16 小时的投入，在线分发参考材料可分担此成本；Watson 自述从事 FreeBSD 工作十五至二十年仍觉得内核大部不透明、须借 DTrace 理解，学生由此获得对性能与功能分析的直觉式掌握，此类技能同样适用于浏览器、办公套件等大型代码库。（BSDTalk EP260，[1282.34-1450.04]，L1）
- Joshua Stein 自述约 1998 年起使用 OpenBSD，先用其运行 BBS，继而制作 ports 并由其他开发者提交合入；2000 年起运营 RT.fm OpenBSD 镜像并向开发者捐赠硬件；在一家互联网服务商任职期间引入 OpenBSD 替换 Linux 与 OpenVMS 服务器；2001 年获得提交权限，此后以编写驱动等零散工作持续参与。（BSDTalk EP263，[73.12-128.72]，L1）

- 两人均以 OpenBSD 为个人与工作的主力桌面并运营大量服务器；对即将发布的 5.9 的期待包括 EFI 引导支持使其可装上新式仅支持 EFI 的笔记本（Joshua 为自己的新机型编写了 i2c 相关驱动）、网络栈改进与显卡支持；并反驳外界“OpenBSD 硬件支持匮乏”的印象，认为笔记本安装体验已相当顺畅。（BSDTalk EP263，[236.90-378.98]，L1）
- 两人于 2015 年 10 月创办每周五更新的音频播客 Garbage（garbage.fm），定位为坦诚抱怨软件开发现实、呈现企业世界之外的真相，其名言式立场是“技术几乎都是垃圾，而且正在让你的生活更难”；受众为 OpenBSD 开发者、最终用户乃至非 OpenBSD 用户；制作上以 Skype 对录、Audacity 剪辑（因高 DPI 屏幕显示问题在 Mac 上完成），Brandon 把完全在开源 BSD 系统上制作播客列为个人挑战，基于浏览器的录音服务已可在 OpenBSD 的 Firefox 上运行。（BSDTalk EP263，[397.86-737.10]，L1）
