# 321.4.94 〔会议不详〕Peregrine的核心操作模块化系统集群与评估核心支持数据上传分块

- 〔会议不详〕Peregrine 的核心操作、模块化系统、集群与评估。核心支持数据上传（分块、编码、建索引块、按块/段区间合并段文件并更新版本，全部成功才确认上传、保证数据完整性）、仅基于索引执行的搜索（结果最小粒度为块区间，值条件由指标条件经逻辑运算组合而成）与四种抽取（全量、采样、聚合、变换）；模块化系统提供 storage、reader、writer、metrics、transformations 五类编程接口，集群基于 HashiCorp 实现的 Raft 共识算法实现水平扩展与容错。评估显示 Peregrine 读优化编码带来 4 倍压缩；索引全部驻内存使其可在 1.2 秒内执行 1 万个并发搜索请求、远快于 ClickHouse 与 InfluxDB；对 86 亿点的抽取吞吐达 2400 万点/秒，同为三者最佳；AWS EC2 实验表明大抽取请求下 S3 比 EBS 高效至 2 倍（EBS 受 IOPS 与吞吐的合成限制），S3 最坏情形响应慢 7 倍但差值仅约 300 毫秒。（YouTube EP3tXYm7IdYPM，[507-1086]，L1）
- 〔会议不详〕LinkedIn 以自适应服务器选择（adaptive server selection）提升 Apache Pinot 查询处理韧性。LinkedIn 软件工程师 Jiaguo（与 SRE、SDE 团队合作）介绍部署规模：1500+ broker、8000+ server、4500+ 表、超 30 万 QPS；传统 round-robin 路由会把固定比例查询确定性地送往因 GC 停顿、网络或磁盘故障而变慢的服务器。自适应方案在 broker 本地维护 stats collector（记录到各服务器的在途查询数、其加权移动平均及延迟），按“平均延迟 × 估计队列大小的指数幂”计算服务器分数选优（分数越低越好），冷启动阶段回退 round-robin，所有统计采集与分数计算异步进行、不进入查询关键路径。生产效果：平均查询延迟随 QPS 升高改善更显著，慢节点告警大幅减少；对短暂性慢化（如网卡 NIC 抖动）与持续性慢化（如 JVM 堆配置错误）都能及时把 QPS 移走并在恢复后回切，90% 以上的单节点性能劣化场景避免了延迟退化。（YouTube EP3v3VgUS3nJQ，[16-1362]，L1）
- 〔会议不详〕韧性故事的另一半：自动查询击杀（automatic query killing）。混合查询模式下用户偶发的 ad hoc 高成本查询会悄悄拖慢同表低延迟查询，极端时击垮服务器（OOM 后重启约 10 分钟、用户收不到告警并反复压垮副本直至可用性归零），而 Pinot 原无线程池环境下逐查询的内存追踪。方案分两块：query stats collection 用树状 query context（含查询 ID 与任务 ID）标定 runner/worker 线程池中各线程归属，为每线程分配 thread-local volatile 变量，经 ThreadMXBean 的 getThreadAllocatedBytes 等发布内存/CPU 用量；query stats accounting 线程每几毫秒自调度一次，按查询 ID 聚合用量、在 OOM 风险临近时对消耗最大的查询置中断标志（策略可插拔，95-96% 堆占用时可触发 panic 策略击杀全部在途查询），整体可视为采样式方法、置于查询执行路径之外。部署后采样与聚合开销仅 0.3% CPU，捕获 85% 以上的 OOM 崩溃并阻止级联可用性下降；未来工作包括低优先级查询让位的工作负载管理、准入控制与跨服务器击杀决策传播。（YouTube EP3v3VgUS3nJQ，[1364-2357]，L1）
- 〔USENIX LISA〕自治网络与知识表示主题演讲。Motorola 研究员 John Strassner（曾参与 Cisco IOS）指出电信运维/业务支撑系统（OSS/BSS）中各 best-of-breed 应用微观地维护各自数据库与键、数据类型，患上“烟囱综合征”（stovepipe syndrome），导致 DSL 这类简单服务开通迟缓，并引用电信业每小时约 200 万美元的收入损失；自治网络由 IBM 的 Paul Horn 于 2001 年提出并类比生物自主神经系统，让配置、库存等非自主功能自动化，把管理员解放出来做容量管理与网络优化等更难的事。他强调自治系统是“自治理（self-governing）”而非“自管理”系统，需从环境与管理员处学习、以业务规则约束优化；其 FOCAL 架构（Foundation-Observe-Compare-Act-Learn，另以 poetic license 加 Reason）配合模型化翻译层（MBTL）把厂商专有的 SNMP/CLI 管理数据翻译为厂商中立表示，实现系统 Genesis 具备动态联邦知识库、模型变换引擎与自适应控制回路，并以面向方面建模把 self-* 功能作为 aspect 织入遗留代码。（YouTube EP45urWdwTEAk，[23-2585]，L1）
- 〔USENIX LISA〕状态机、策略连续体、机器学习推理与现场问答。Strassner 认为传统 UML 状态机“状态只是信号”、缺乏行为信息，正以经典有限自动机理论重定义 UML 状态机并回馈 OMG，借助上下文感知策略为配置状态图的边赋权、引导设备偏向特定配置命令序列；策略连续体自上而下从无技术细节的业务视图到 CFEngine/CLI/SNMP 实例视图逐级转换（如“John gets gold service”最终翻译为流量整形 CLI 命令）。机器学习不是单一算法：多层感知机（MLP）与 RBF 学习器在全局拟合、离群点与在线实时敏感性上表现完全不同，须依上下文选择；强化学习须离线构建知识库并在人类控制下谨慎启用，机器推理用于形成假设、再驱动系统取证并回填知识库。问答中他补充：MBTL 正在标准化为管理数据的统一表示；为某运营商路由器新板卡上线开发的 configlet 软件把 30-45 天的开通时间缩到约 5 分钟；除连续体各级策略外还需 safety policies 保护人类；策略冲突检测与解决构成独立的策略引擎工作，模型驱动架构在生成代码的同时生成文档。（YouTube EP45urWdwTEAk，[2581-5168]，L1）
- 〔USENIX Security（推测）〕PlatPal：以平台多样性检测恶意文档。主讲人 Meng Xu 指出恶意文档正成为攻击者传播恶意软件的新工具（如 APT28 针对酒店业的攻击），Adobe Reader 2015 年报告逾百个 CVE、次年超 200 个，解析器与 JavaScript 引擎等组件无一幸免；而现有静态/动态检测过度依赖外部 PDF 解析器（存在 parser confusion 攻击）、机器学习模型（可被自动规避）与已知攻击特征，难以应对零日。PlatPal 改用 Adobe 自身解析器与简单启发式：同一 PDF 在 Windows 与 macOS 两台虚拟机中打开，内部 tracer 以 Adobe Reader 插件钩取渲染元素、脚本执行等关键函数，外部 tracer 抓取系统调用并聚合为文件系统操作、网络活动、新程序启动与崩溃/退出四类，再由外部实体比对轨迹判定分歧。对 VirusTotal 320 个恶意样本（限 2013 年后 CVE），65% 观察到内外轨迹分歧、11% 两平台同址崩溃、24% 未见分歧（多因针对旧版本或 VirusTotal 误标）；1000 个良性样本零分歧误报，平均检测约 20 秒、每虚拟机约 2 GB 内存。（YouTube EP4WwhFf41Z5A，[11-805]，L1）
- 〔USENIX Security（推测）〕分歧根因、绕过难度与问答。PlatPal 归纳出九个跨平台实现差异因素：shellcode 创建时的系统调用语义、调用约定与库依赖不同，内存管理差异（Windows segment heap 与 macOS malloc、堆元数据与缓冲区布局不同，使覆盖堆元数据的利用无法跨平台成功），平台特有可执行格式、文件系统语义与配置信息库等；因此攻击要么在漏洞发现/利用阶段失败，要么在执行 shellcode、加载可执行文件、窃取文件等活动阶段被检出，绕过需同时攻破全部平台（heap feng shui、堆喷射与多态 shellcode trampoline 亦难以构造）。局限是无法处理用户交互驱动的攻击、社会工程与非确定性来源（如随机数），更适合云存储服务商周期性扫描或 VirusTotal 等在线恶意软件分析流水线。问答确认：该方案是提高攻击门槛而非根治、与机器学习分类器互补（后者检测快但需训练与动态刷新模型）；因 Linux 端 Adobe Reader 止于 v9 故选 Windows/macOS，CPU 架构（ARM vs Intel）是另一条多样性维度；Office 文档理论上同样适用。（YouTube EP4WwhFf41Z5A，[805-1604]，L1）
- 〔会议不详〕面向硬件的常时间（constant-time）定义。主讲人以 2006 年南 Padre 岛因膨胀性黏土地基而拆毁的豪华塔楼为喻：软件社区已广泛采用常时间编程纪律与经形式化验证的密码库（进入 Firefox、Chrome 并影响 TLS 规范），但这些保证全部建立在底层指令与功能单元本身常时间的假设之上，一旦假设不成立所有证明失效，因此要有可验证的常时间软件保证必须先验证硬件。硬件并行、流水化的执行模型使软件常时间定义（针对直线性顺序代码）无法直接沿用，连“时间”本身都难以界定；为此作者显式追踪输入对寄存器（尤其输出寄存器）的影响，把“影响某寄存器的全部时钟周期集合”定义为影响集（influence set），并要求任意两次执行（无论秘钥取值）所有输出产生相同影响集。以带零快速路径的 FPU 乘法器 Verilog 代码为例，快速路径与慢速路径下输出寄存器的影响集不同，据此可形式化地证明该乘法器非常时间。（YouTube EP4ZjZWGLvi2E，[10-582]，L1）
- 〔会议不详〕活性等价（liveness equivalence）与验证工具 Iodine。为便于验证，作者把影响集等价改写为活性等价：寄存器在周期 t 活性当且仅当 t 属于其影响集，两次执行活性等价当且仅当所有输出对每个 t 的活性位一致；随后为乘法器引入类似 ARM data-independent timing 指令的常时间模式（ct 位置位时强制走慢路径），并在程序中为每个寄存器插装额外活性位、复制两份程序，把“输出活性位一致”化为可用现有快速验证器检查的简单断言。工具 Iodine 接受 Verilog 与一组假设、生成中间语言表示与验证条件，并自动寻找证明、发现违例；评估从 GitHub 与 OpenCores 取来 2 个简单 CPU、2 个 FPU 与 1 个 ALU（其一 FPU 因多种快速路径在结构上不可能常时间，作者强调这是设计取舍而非 bug），另验证了 SHA-256 与 RSA 核（后者因 Montgomery 乘法存在时间侧信道）。证明以“某些输入公开、某些寄存器在上下文切换时刷新”为假设，注释负担较重但已可自动推断，全部检查耗时均在 12 秒以内。（YouTube EP4ZjZWGLvi2E，[582-1153]，L1）
- 〔会议不详〕KEPLER：面向 Linux 内核的单发（single-shot）漏洞利用。中科院信息工程研究所的 Wei Wu 与 Penn State University 合作，指出 C/C++ 编写的内核难免越界访问、UAF、数据竞争等可利用漏洞，而自动化漏洞利用生成在 SMEP/SMAP、physmap 标记不可执行、虚拟化 hypervisor 监测 CR4 清位、usermode helper 二进制白名单等缓解面前处处受阻，且常因内核态栈 pivot gadget 缺失、通用寄存器控制不足（如 copy_from_user 需要三个参数而通常只控一个）以及多次触发漏洞的利用路径陷阱而失败。KEPLER 采用类似用户态“magic gadget”的单发利用：以 copy_from_user 调用点类栈粉碎 gadget 无需精确地址即可把 RDI 指向内核栈帧，用 copy_to_user 类栈泄露 gadget 与伪造栈帧放行 canary 的辅助 gadget 组合泄露栈保护值，借 VMA 对象多重解引用取参的 blooming gadget 提升寄存器控制，再由含两次可控间接调用的 bridging gadget（如页缓存脏标记函数，转写作 rage_cache_mark_dirty）把泄露 canary 与栈溢出组合为一次完成。（YouTube EP4b_GbFs5XZI，[10-855]，L1）
- 〔会议不详〕KEPLER 的实现、评估与问答。实现分两模块：基于 IDA Pro 插件的静态分析收集候选 gadget，把利用链识别建模为候选 gadget 上五步搜索树的树搜索问题（gadget 拼接引擎基于 Angular 实现），多 worker 并发探索、在多个关键位置做约束可满足性检查剪枝，并设每阶段最大步数与进入循环最多次数的阈值抑制状态爆炸。对 16 个 Linux 内核 CVE 与 3 个 CTF 题目（含越界、UAF、double-free、整数溢出、未初始化使用），KEPLER 为 17/19 个漏洞生成利用、优于现有利用生成工具，首个利用链 15 分钟内即可找到、利用链总数达数万条；所用函数 gadget 难以从内核移除，利用链难以防御。问答：KASLR 需配合信息泄露漏洞、细粒度（再）随机化将带来很大挑战；评估内核为 4.15（撰写时最新），并验证 4.20 亦可行；作者承认尚未统计不同漏洞利用链的可复用性。结论呼吁在主流内核版本广泛部署低开销 CFI 方案。（YouTube EP4b_GbFs5XZI，[855-1253]，L1）
- 〔USENIX Security（推测）〕NewHope：后量子密钥交换。来自荷兰 University of Twente 的 Peter Schwabe（与 Ege University 的 Erdem Alkim、CWI 的 Leo Ducas、Infineon 的 Thomas Pöppelmann 合作）引用 IBM 的 Mark Ketchen 关于通用量子计算机“15 年左右可实现”的判断：Shor 算法可在多项式时间内分解整数与计算离散对数，意味着 RSA、ElGamal、DSA、Diffie-Hellman 及全部椭圆曲线变体的终结；“先记录后解密”攻击使完美前向保密（PFS）失效——PFS 只把长期密钥用于认证、以即弃临时密钥加密，挡不住逐个破解已记录流量的密码学攻击。方案基于环上带误差学习（Ring-LWE）：在系数模 q、模 x^n+1 的多项式环中由 (a, as+e) 对恢复秘密 s。相比 BCNS（把 Peikert 2014 方案选参并集成进 OpenSSL，仅宣称前量子 128 位安全），NewHope 把失败概率从 2^-131000 放宽到 2^-60，给出紧致的失败概率分析；保持维度 1024 而把 q 大幅减小（q 越小噪声相对权重越大反而更安全、消息更短且运算更快），并用两个 k 位整数汉明重量相减的中心化二项分布替代难以常时间实现采样的离散高斯噪声。（YouTube EP4rK4X9O8qj0，[10-1186]，L1）
- 〔USENIX Security（推测）〕NewHope 的协议设计、实现、性能与部署。每次协议运行用 SHAKE128（FIPS 202 的可扩展输出函数）从种子展开生成新鲜的随机 a：既避免密码学界就固定公共参数达成一致（nothing-up-my-sleeve 也无法根除后门疑虑）的困难，也把格筛法未来可能的进展转化为攻击者对每次密钥交换都要重复一年量级预计算（类比 Logjam 攻击的防护），服务器可将展开结果缓存约一小时；必须禁止复用密钥与噪声，否则方案立即不安全。多项式以 NTT 域传输省去两次变换，C 参考实现仅用 16/32 位整数、全程无除法与取模（NTT 内用 Montgomery 表示，噪声采样用 ChaCha20），AVX2 版本再提速约 3 倍，密钥生成比 BCNS 快约一个数量级、共享密钥计算快约 5 倍；基于核心-SVP 硬度 2^0.265n 的保守分析给出约 200 位后量子安全性（同一分析下 BCNS 仅 86 位）。2016 年 7 月 Google 宣布在 Chrome Canary 与自家服务间开展两年 CECPQ1 实验，采用 X25519+NewHope 混合密钥交换；问答讨论了带宽（每方向约 2 KB，比 ECC 大约百倍）、方案仅具选择明文安全故不能用于签名与长期密钥/证书，以及 Ring-LWE 是否与一般 LWE 同难的开放问题。（YouTube EP4rK4X9O8qj0，[1186-2363]，L1）
