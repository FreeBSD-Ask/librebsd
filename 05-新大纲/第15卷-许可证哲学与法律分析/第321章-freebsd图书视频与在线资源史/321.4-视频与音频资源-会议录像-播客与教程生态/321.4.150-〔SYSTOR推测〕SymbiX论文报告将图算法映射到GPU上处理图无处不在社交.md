- 〔会议不详〕Leo——GPU 应用的动态自动优化框架：优化 GPU 代码今天很难，因为优化效果与输入强相关、需要大量人工微调与多版本代码；GPU 的两大性能瓶颈是不规则控制流与不规则全局内存访问（warp 内线程访问不连续地址导致合并访存失效）。以 AoS 到 SoA 的数据布局变换为例，行主序下 4 线程访问 4 个成员需 16 次全局内存事务、列主序合并后仅 4 次；但在 SkyServer 等值连接应用上，低选择度输入下该优化有效、高选择度输入下反而劣化——布局变换虽减少了内存事务却破坏了缓存局部性，说明即便是公认优化也不能静态假定有效，必须动态决策。（YouTube EPPh6XNyslKAw，[10-600]，L1）

- 〔会议不详〕后半场介绍 Slowpoke 的模型、实现与评估：不同于 Coz 只看并发执行，Slowpoke 以轻量分布式协调机制减慢所有非目标服务，并用线性规划形式化“瓶颈等价”（减慢执行与优化执行由同一约束/瓶颈服务决定解），从而仅凭减慢执行的吞吐推断优化后吞吐，且可推广到多线程服务、动态调用图等场景。减速经 gossip 式传播按请求数批量触发（避免逐请求暂停的开销与下游空等），数据面在 Kubernetes pod 内为每个服务部署 poker 控制进程，通过对 HTTP/gRPC 通信库的轻量插桩、Unix 管道与专用 TCP 通道协调并暂停服务进程组。评估使用 DeathStarBench 中的四个应用与 Google demo 应用及 108 个合成应用（共 1080 次实验），真实应用预测 RMSE 为 2.1%、合成应用为 1.9%，且在不同拓扑、协议与瓶颈位置下精度稳定；系统已开源。（YouTube EPPjvJbhigf04，[293-798]，L1）

- 〔SOSP（推测）〕上海交通大学 IPADS 博士生 Haoran Ding 报告 Flux——有状态 serverless 应用幂等性的自动验证与保证：serverless 平台以重试实现容错，重试会导致错误结果（如先读价格再扣余额的函数失败重试后二次扣款），平台因此要求开发者编写幂等应用，但判断与修复幂等问题负担沉重。已有工作各有短板：AWS 的幂等工具只覆盖函数抛异常触发的重试、不能处理硬件崩溃或网络问题，FSCQ 等验证框架只能验证顺序函数，Beldi 与 Boki 用日志保证所有数据库操作 exactly-once 但性能代价高。演讲用 write/read 两函数并发的例子说明顺序幂等定义在并发下失效：write 与 read 各自幂等，但并发加重试时客户端观察到值被修改 3 次而非无重试时的 2 次。（YouTube EPPlD_ZtD5owA，[16-360]，L1）
- 〔SOSP（推测）〕后半场介绍 Flux 的三步方案与评估：受可串行化启发提出幂等一致性（idempotence consistency）——带重试的执行可被某次无重试执行前向模拟；用组合证明降低验证复杂度，为函数 F 构造 F*（在每个数据库操作后插入随机失败建模、reset local states 模拟本地数据丢失、go to begin 模拟重试），证明每函数满足 idempotent simulation 则整个函数集满足幂等一致性，并给出 failure reduction 定理：至多一次失败下成立即可推出任意失败下成立。修复端引入 advisor：关键观察是逐操作记录日志并非幂等一致性的必要条件，advisor 找出最小必要日志操作集并复用 Beldi/Boki 的日志机制。评估覆盖来自 AWS Serverless Application Repository 与 GitHub 的 27 个应用、79 个函数，验证器与 advisor 分别在 110 秒与 90 秒内完成，相比 Beldi/Boki 部分应用峰值吞吐提升约 10 倍且延迟更低，表明形式化方法既保正确也能优化性能。（YouTube EPPlD_ZtD5owA，[361-797]，L1）
