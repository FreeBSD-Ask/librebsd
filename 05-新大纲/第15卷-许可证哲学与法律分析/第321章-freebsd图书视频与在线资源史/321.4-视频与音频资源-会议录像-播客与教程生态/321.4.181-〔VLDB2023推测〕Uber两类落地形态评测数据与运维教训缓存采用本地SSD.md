# 321.4.181 〔VLDB2023推测〕Uber两类落地形态评测数据与运维教训缓存采用本地SSD

- 〔VLDB 2023（推测）〕Uber 两类落地形态、评测数据与运维教训。缓存采用本地 SSD 以避免受内存容量限制、以页为单位组织并用哈希索引集合快速定位；以正则或 JSON 格式表达式做缓存准入后，只有不到 10% 的请求需要穿透到外部存储，HDFS 数据节点侧再用历史访问热度做块准入后穿透比例降至约 1%。计算层把本地缓存嵌入 Presto，并用软亲和调度把同一文件的分片分配给同一 worker 以减少频繁的准入与淘汰；Uber 超过 97% 的查询会经过负责数据输入与初步过滤的 scan filter project 算子，启用缓存后读取 Parquet 的墙钟时间最高下降 90%（P90 下降 67%、P50 下降 64%）。存储层每个数据节点有 500 TB 容量但只有几 TB SSD 可用，用限流器按历史访问模式决定是否准入块以避免频繁换页，一小时窗口内本地缓存可服务超过 70% 的请求并显著减少阻塞在 I/O 上的进程，支撑至多 1 EB 数据落在高密度硬盘上并至少节省 50% TCO；经验教训包括缓存序列化元数据可最多降低 40% CPU、1 MB 页大小是读放大与元数据占用的最优折中，以及针对读请求挂起、文件损坏导致查询失败、SSD 提前占满分别采取回退远端存储、主动驱逐与捕获 No space left on device 提前淘汰。（YouTube EPTXMkhyX8V8Q，[554-1160]，L1）

- 〔USENIX Security〕改在空间域拍快照、按内容匹配重建因果。作者指出 IoT hub（如跑在 Raspberry Pi 上的 OpenHAB）频繁 ping 云端、巡检设备，日志被大量高频良性事件淹没，且无法从正常改动中区分未授权的文件改动；由于攻击通常低频，他们改为只在空间维度以很低频率记录文件系统状态的 delta 快照，利用 ZFS 的 copy-on-write 得到改动文件列表，再用面向取证的通用文件模型（含数据源、权限、位置等元数据及脚本内嵌 API）表示，随后以信息检索式的内容匹配跨快照反推因果，生成含数据流、控制流与内容匹配三类边的内容溯源图，并借鉴 PageRank 按文件内容相似度与层级语义耦合为边赋权、自症状文件传播分数筛出高分节点。在 3 款主流手机平台、1 部 Android 手机与 1 台 PC 上复现 16 个攻击（PC 复用 DARPA 透明计算项目的测试脚本），与 CLOnE、Alchemist、eAudit 三个基线对比：PostMark 下平均运行开销仅 3%（eAudit 5%、其余超 14%），一周额外空间约 100MB（其他系统多出 6 到 20 倍），精确率与召回率均最优。（YouTube EPUFwLiw8ChZI，[288-962]，L1）
- 〔WOOT〕安全启动的阿喀琉斯之踵：Xilinx Zynq-7000 上的 RSA 认证绕过。演讲者坦言这是两年前完成、当时懒于成文的工作，研究对象是 AMD（前 Xilinx）Zynq-7000 SoC——单片内含 Arm Cortex-A9 与 FPGA，可引导完整 Linux、写 Verilog 做硬件加速，广泛用于工业自动化、医疗设备、汽车乃至航空航天与国防，因而高度依赖内置安全特性。他介绍其安全特性包括 RSA-2048 安全启动、构成信任根的不可变 boot ROM、比特流加密与认证、可烧写 eFuse 的安全配置、只读回保护乃至熔断检测，随后拆解 boot image 的 BIH、分区头表（PHT）、FSBL、PL（比特流）与 PS 分区，以及各分区可分别 AES 加密、HMAC 认证并选择启用 RSA 的两阶段认证（主密钥已烧入 eFuse，仅存哈希；分区从属密钥由主密钥认证）。威胁模型假设有物理访问、可复制 SD 卡上的 boot image、且 RSA 熔断已启用；关键发现是 FSBL 会两次加载 PHT——它认证的是第二份 PHT，实际引导用的却是未认证的第一份，构成典型 TOCTOU 漏洞，作者据此设计了一块 SD 卡切换器，在 boot 过程中于被篡改卡与正版卡之间切换。（YouTube EPUHe8zrYskgE，[8-653]，L1）
- 〔WOOT〕从 PHT 双重加载到比特流读取的链路攻击。该攻击起初只是近乎漏洞：需要在 FSBL 里加一行初始化第二张 SD 卡的代码，而加密的 FSBL 无法改动；用 FPGA 做无缝 SD 卡切换器的方案又因找不到同时支持主从卡的开源实现而放弃。他们于 2022 年 3 月向厂商报告，数周内获确认并拿到 CVE 与设计咨询通告，追溯 GitHub 历史发现该缺陷自 2013 年起在 FSBL 代码中存在长达九年。作者进一步把它与 USENIX 2020 年针对 Xilinx 7 系列 FPGA 的 StabBleed 攻击结合：先用合法比特流初始化 PL 拉高 DONE 引脚，再发送含单字回读的畸形比特流，让其中一个字经 WBSTAR 寄存器被解密后可读回，代价是每恢复 32 位需完整上电一次、整轮离线攻击要持续数天；演示中展示了被篡改 PHT 与被篡改分区均引导失败、而借助切换器可引导 StabBleed 载荷并回收 32 位明文比特流。结论是该缺陷已被厂商确认并修复，补丁版本与 boot ROM 中均无此双重获取问题。（YouTube EPUHe8zrYskgE，[654-1291]，L1）
- 〔USENIX Security〕Dr. Checker：Linux 内核驱动的 soundy 静态分析。Facebook 团队凭此工作拿下 Internet Defense Awards 亚军；第一作者签证未办妥，由第二作者 Chad Spensky 代讲，并解释了工具名的由来——他最初只想把 driver 缩写成 dr_checker，同事却直接把 Dr. Checker 当成正式标题用到了投稿当天。他说明动机：第三方驱动审计不足，2003 年的研究显示 Windows XP 约 85% 的漏洞来自第三方驱动，其团队统计过去一年 CVE 中约 28% 出自 Linux 内核驱动，而 2016 年 Linux Security Summit 上 Android 安全团队的结论表明移动内核重现了同样的趋势。工具以指向分析与污点分析为唯二核心、在其上叠加多个检测器；为压住状态爆炸，采用 Ben Liblit 提出的 soundiness 策略，主动打破三条假设——非第三方驱动代码视为完美实现、循环只迭代到达达定义不动点或最长 use-def 链、循环内的调用点只遍历一次——同时保证上下文敏感、字段敏感与流敏感，使每条告警都能还原完整污点流。（YouTube EPUHyDMiJEEz8，[10-849]，L1）
- 〔USENIX Security〕310 万行移动驱动跑出 158 个零日漏洞。团队用 diff 与 grep 从厂商分叉内核中剥离第三方驱动，处理 file_operations、attribute、socket 等四类入口并标注污点为直接还是间接，最终在 4 类内核合计 310 万行代码上跑通；与 Flawfinder、RATS、Sparse、cppcheck 等易上手工具对比后，5071 条告警全部人工复核，其中 3973 条为真阳性、精确率 78%，含 158 个此前未披露的零日漏洞（论文另给出 MediaTek 驱动在 sprintf 处的溢出样例），而 Flawfinder 一类工具要人肉翻 44900 条告警。消融实验在随机抽的 100 个入口点上显示：加入循环优化带来约三倍加速，改成严格 sound 分析后 82 个用例根本跑不完；现场问答中，Deborah Shands（NSF）追问移动端驱动为何漏洞更多、Francesco Loddo（Facebook）追问方法对驱动的特殊依赖，主讲人强调该技术不局限于驱动、只分析一次指的是调用点而非函数名。（YouTube EPUHyDMiJEEz8，[849-1857]，L1）
- 〔USENIX Security〕审计框架需要资源隔离：超生产者威胁的系统研究。北京大学的 Peng 报告该工作：审计框架是溯源分析系统的基础组件，负责从 OS 内核收集系统调用等溯源数据，Sysdig、Falco、Linux Audit、CamoFlow 等实现普遍采用同一中心化架构——内核态中各进程事件汇入一个集中日志缓冲，用户态由一个或少数消费者逐个处理。他构造三类进程（普通应用如 nginx、含提权行为的恶意程序、以及由 getuid 等高速系统调用组成的超生产者）说明后果：Sysdig、LTTNG、Linux Audit 等限制采集器配额，处理速度跟不上产生速度，恶意事件因缓冲区满而被丢弃，他们称之为 P-DDoS 攻击；CamoFlow 一类反其道给采集器更多资源，却抢占后端应用资源、拖垮整机性能，由此断定所有现有审计框架都受超生产者威胁，而用 cgroup 之类阈值压制生成速度既不实用（阈值难定、攻击者可用一组超生产者规避）。（YouTube EPUIOTdeF7dKc，[8-320]，L1）
- 〔USENIX Security〕以线程内自消费实现零丢失与性能隔离。团队把根因归结为中心化架构打破了进程间的数据与资源隔离，据此设定三条设计目标（零数据丢失、性能隔离、开销不显著高于 SOTA）与两条隔离策略：自消费执行（每个运行线程自行消化自己产生的溯源数据）与同步日志缓冲（为每个线程分配专用缓冲并在其中同步处理），由此提出基于 threadlet 的 NoDrop——把溯源处理逻辑（consumer）注入当前运行线程的内存，配合地址随机化与 MPK 等内存保护手段阻止攻击者触碰该区域，运行流程分捕获记录、检查缓冲、首次注入、按运行线程配额处理、归还控制权五阶段。五个研究问题的结论是：NoDrop 彻底消除事件丢弃、成功攻击率为零（Sysdig、LTTNG、Linux Audit 丢弃严重），在超生产者负载增大时后端应用性能保持稳定；用基准测试衡量系统开销、以八个真实应用衡量应用开销，测得开销低于 SOTA 的 CamoFlow，因为它省去了进程调度与跨核数据传输；而把 CPR 溯源规约算法内联进内核后每核每秒仅能处理约 2000 事件、远不及超生产者每秒 10 万的产生速率，单纯扩大环形缓冲也解决不了问题。（YouTube EPUIOTdeF7dKc，[320-631]，L1）
- 〔SREcon〕用机器学习自动化系统配置调优。Akamai CTO Stefano Doni 分享 SRE 以机器学习自动化配置调优的做法：他引用 Google 的 SRE 书籍说明 SRE 关注最大变更速率不违反 SLA、需求预测与容量规划、效率与性能，并给出实证——一次 JVM 重配置让应用服务器 CPU 使用率下降 75% 而承载流量不变，另一例最优配置显著提升了服务韧性，而调优不止于 Java，从数据库到 Kubernetes 容器、中间件与应用服务器全栈都适用。他指出调优正变得愈发困难：JVM 已有 800 多个参数、MySQL 超过 500 个、AWS 一年新增 100 多种 EC2 机型；配置效应可能反直觉（给 MongoDB 分配更少内存反而跑得更快）；发布节奏加快又使主要依赖专家的手工调优耗时严重。Akamai 由此提出四点要求——全栈优化、在数十亿量级配置空间中智能探索、支持自定义优化目标（削峰延迟或降本）、全流程自动化以减少 toil，并以飞机设计流程类比：排队网络模型最便宜却难建模垃圾回收等复杂场景、仿真器准确但昂贵且不可移植，故主张在真实系统上做实验并把实验次数压到最少。（YouTube EPUK8awloEZNI，[13-660]，L1）

- 〔NSDI〕让网络数据平面支持原地可编程：从架构到语言。清华大学的 Yunfeng 报告该工作：交换机芯片已从固定功能走向可编程、用户可写自己的报文处理函数，但运行期不中断现网流量地更新功能仍是刚需——网络遥测需在运行时按需部署、网络内计算函数宜热插拔、表项规模要随流量与网络规模伸缩、多租户升级不能相互影响、设备更新不应破坏拥塞控制与缓存这类有状态函数的状态。他指出 PISA 作为主流实现存在四重限制：前端解析器与流水线解耦，新增协议须同时更新二者；协议字段必须在设计期精细编排，无法追加新协议；级数上限固定硬连线，插入新函数要重编所有受影响阶段、删除函数还留下空处理器拖累延迟；处理逻辑迁移意味着表项迁移，大流表还要占用多个处理器，灵活性受限。为此提出 ASPA，四个支柱是分布式按需解析器支持协议更新、基于模板的处理单元支持运行时逻辑定制、虚拟流水线提升原有流水线灵活性、解聚的内存池支持运行时增删与回收流表。（YouTube EPUOGhcXOQnrA，[14-441]，L1）
