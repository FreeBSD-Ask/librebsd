- 〔云计算可信性研究讲座〕演讲者主张云可以变得可信赖，并提出第一条技术原则：引用谚语 "trust but verify"（转写作 "doverier no provirie"）——端到端正确性校验〔07:57〕。它有两种用法：多疑的用户把云当黑盒直接取端到端保证；运维者则在内部用它赶在客户之前发现并修正 bug。第一例 SafeStore：用户数据被切分到多个云、冗余数据放进第三朵云，写入时云签发含数据哈希的证书作为承诺〔10:35〕；用户可周期性发起 "end-to-end proof of storage" 质询并拿回签名证书〔10:57〕。设计的巧思在于让云在利益上愿意诚实：偶尔抽查——约 1% 的概率到冗余云取回数据、重建原文、自己算出随机数应答并与证书对照〔12:27〕；若对不上，即可凭签名证书向任何第三方证明云"承诺存储却撒了谎"，再靠合同罚则使 "the right strategy for them is to never lie when they produce a certificate"〔13:28〕。于是只需偶尔 spot check 以督其诚实。技术上这给出失效检测时间的紧界：视云为理性经济体则界很短，视其为宁可弃货赔款也要赖账的拜占庭节点则稍长〔14:08〕；由此可测得极高的数据耐久性，"my data can be stored over decades and i can get it back"。演讲者的结语颇具画面感："i can sleep well at night knowing that the pictures of my daughter are safe in the cloud"〔14:42〕。（YouTube EPW-ZdMO03EKM，[460-900]，L1）
- 〔云计算可信性研究讲座〕Depot 把这一问题推向极限："what's the absolute minimal trust we can put into a black box storage system"〔15:04〕，答案是 "completely eliminate trust"——对最终一致性、数据新鲜度、依赖保持等正确性性质完全去信任〔16:22〕。每个节点完全自治："if the node i'm using is correct then it doesn't matter if every other node in the system fails"〔16:45〕；每个客户端与服务器都保存其见过的全部更新历史，消息到达只需本地校验两条性质：其一 "no omissions"（历史不能跳向未来），其二更新 "must not modify history"（不能回到过去改写）〔19:32〕。真正的难关是"分叉"：故障节点可能给出红黄两份各自合法的历史，"a single bit flip in your system on a single node can propagate through the system"、把系统割裂成互不接受更新的两半〔21:34〕。Depot 的解法是把错误 "convert it into concurrency"：把故障节点视作两个正确的虚拟节点，将冲突并入因果一致视图，并发更新的调和沿用自 Coda、Bayou 以来的悠久研究传统〔21:55〕〔22:33〕；同时凭两份互相冲突的签名更新即可构造 misbehavior 证明、把坏节点逐出系统〔22:48〕。第二原则是活性与健壮性：SafeStore 用多云冗余，但冗余不能毁掉云计算的经济性。Salus 试图 "square this circle"——造一个 robust、可扩展且廉价的块存储〔24:31〕：保留 HBase/HDFS 乃至 BigTable、Azure Store 这一代集群存储的核心架构〔25:00〕，但把易成单点的 tablet server 一并复制、为其更新附上证书并互相校验〔29:36〕；再让 tablet server 与存储副本同地共置，使压缩与清理变成局部操作〔31:55〕，"in these systems we become network limited"〔35:44〕。结论是：只要设计得当，这类健壮性的代价可以压到相当低。（YouTube EPW-ZdMO03EKM，[900-2145]，L1）

- 〔LISA 2009 大会演讲〕Sun 的 Bryan Cantrill 回溯 DTrace 的诞生动因：1996 年他加入 Jeff Bonwick 领衔的 Solaris 性能团队，困扰很简单——"We didn't know why the system sucked"，且系统时好时坏、问题时隐时现，这种瞬态对排障者残酷至极——基准正常段的吞吐明明够打破世界纪录，间歇卡顿却让成绩不可发表〔03:30〕。1997 年冬他们在俄勒冈调试 E10K 基准：64 处理器、64GB DRAM 的大型机重启一次要 90 分钟〔04:02〕；客户一口气摆了五台——一台跑基准、一台跑 Oracle、三台施压〔05:37〕。当时唯一的工具是 Bonwick 在 Solaris 2.6 上写的 lockstat，"was kind of a shard of light into pitch black"〔06:15〕；为验证假设只能手写内核模块动态替换插桩，一旦出错系统 panic 又得等 90 分钟重启。两周不分昼夜、全球接力调用内核专家之后，最终答案竟是机器被误配为路由器〔08:31〕——/etc/defaultrouter 未设置，实验室别处路由器一崩，"the world's slowest, most expensive router would volunteer to start routing packets"。这次经历让他认定：计数器只能告诉你 sad，回答不了"why I'm sad"〔10:16〕；而源码里"if logging enabled"式的条件探针终将编译成 load-compare-branch，即使不启用也让代码慢得无法发布〔11:04〕，必须另辟蹊径，实现可安全动态插桩、能对系统提出任意问题并收集任意数据的机制〔11:26〕。（YouTube EPxGk5WK1s_CE，[196-712]，L1）
