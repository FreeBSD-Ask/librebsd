# 321.4.95 〔会议不详〕GRASP近似分析中的落后者straggler缓解主讲人与Berke

- 〔会议不详〕GRASP：近似分析中的落后者（straggler）缓解。主讲人（与 Berkeley、USC、Caltech 合作）指出下一代分析强调“及时但不完全准确”的近似结果（如 BlinkDB、Presto 及各大云厂商框架），可在期限（deadline）或误差（error）两轴上探索；作者主张近似分析需要一类新的调度设计决策——最优调度器应像知道任务时长那样知道作业的近似界，在 Facebook 与 Bing 生产负载上可把期限型作业精度提升近 50%、误差型作业提速约 40%。核心挑战是任务优先级：近似作业是多波（multi-wave）任务作业，精度与完成任务数成正比，须在“为落后者调度推测副本”与“调度未排程任务”间动态权衡，因为推测占用额外资源、存在机会成本。作者提出两种基于机会成本的设计：贪心调度 GS（总选最早完成者、不推测）与资源感知调度 RAS（仅当同时省时省资源才推测），二者无一致优劣——期限宽松时 RAS 更好、迫近期限时应更激进；理论模型证明剩余任务多于两个波次时用 RAS、最后两个波次切换到 GS 接近最优（任务时长经验证服从重尾 Pareto 分布）。（YouTube EP4rUJpDaqaIA，[9-700]，L1）
- 〔会议不详〕GRASP 的实现与评估。理论模型假设波边界严格、波宽恒定，实践中作者放宽为“接近期限/误差界时切换”并用历史作业样本学习切换时机，构成探索-利用权衡（epsilon=0.1 的多臂老虎机式采样）；GRASP 实现于 Hadoop 与 Spark 的公平调度器中，任务周期性上报进度、剩余时间按剩余数据量外推、新副本时长从已完成任务采样。评估在 EC2 上 200 节点 2xlarge 集群进行，使用 Facebook 与 Bing 生产负载加注近似需求，基线为现行延迟调度（late binding）：期限型作业平均精度提升 47%（随期限余量在 35%-45%+ 之间变化），每个作业规模分桶上都优于单独的 GS 或 RAS，且性能匹配离线最优；误差型作业提速近 38%，零误差的精确作业也提速超 30%，使 GRASP 成为统一服务精确与近似负载的落后者缓解方案。问答讨论了推测中击杀慢副本的假设、以及任务时长与数据相关可能导致近似结果有偏（当前假设任务同权，留待带外信息处理）。（YouTube EP4rUJpDaqaIA，[700-1362]，L1）
- 〔USENIX Security（推测）〕“聪明人做蠢事”：物理安全中的愚蠢实践主题演讲。Argonne 国家实验室漏洞评估团队（Vulnerability Assessment Team）的 Roger Johnston 基于数百次物理设备、系统与程序的漏洞评估，把安全失效主要归因于“智慧与常识俱在却不用”的“狗鼻涕模型”（其两条荷兰牧羊犬面对 Max 猫宁愿反复冲撞玻璃窗也不走自动门），并借 Bruce Schneier 的 security theater 概念给出约 25 条识别特征——越是重大紧迫的安全应用越容易沦为表演、让人感觉良好即是坏信号。他用大量案例说明“重要事务必然有人想清楚了”是错觉：美国承认在 32 起事件中丢失约 60 枚核弹头（broken arrows），IAEA 呼吁成员国审查核设施员工背景却不对自家检查员做任何背景审查，1945 年苏联赠送的“大印章”木雕实为微波谐振腔窃听器（The Thing）七年后才被发现，电子涂销失败屡禁不绝（CNN 泄露戈尔邮箱、Blagojevich 案泄露与奥巴马的通话记录），Sequoia Advantage AVC 投票机选民端可换线切换候选人并配半英里外射频开关躲避选前选后检测，RFID 与 GPS 属清单技术却被当安全使用（50 美元干扰器与卫星模拟器可远距欺骗，静止接收机被“以 600 英里时速移动”），核材料双人规则的唯一实证研究竟源于冷战民兵井试验；其团队研究的 244 种防拆封条全部可用低技术工具快速破解——半数不到 1 分钟、攻击方法发现中位仅 12 分钟——并提出把“尚未篡改”信息预存于封条、篡改即擦除的反证据（anti-evidence）方法及多种原型（含 Near Miss 货运公司口号封条）。（YouTube EP51MxGK2q7Wo，[4-2450]，L1）
- 〔USENIX Security（推测）〕访问控制、分层安全迷信、漏洞评估误区与问答。Johnston 继续列举：尿液药检套件及运动员/员工/事故后检测的安全协议形同虚设，货运窃贼拧开铆钉转动竖向锁杆即可绕过门把手上的锁与封条，出入口控制与生物识别设备在出厂 15-30 秒接触后即可终身掌控（对比之下，运动传感器底部却舍不得多贴一张 3 美分标签）；分层安全常被当挡箭牌误用——多层坏安全不会神奇相加为好安全、增加复杂度且滋生自满；“工程师思维”视自然为对手、不惯于恶意意图，预留 JTAG、不设微处理器安全位、EEPROM 明文存放口令与生物数据是常见设计蠢行。他强调漏洞很多且永远找不全——发现漏洞是好消息；漏洞评估唯一目的是改进安全而非通过考试，须在开发早期迭代进行，警惕伪严谨与精确谬误；合规不等于安全（约 20% 的官方安全规则反而有害），应善用组织内具“黑客心态”者、像坏人一样思考。问答（Dave Wagner、Peter Neumann、Matt Blaze 等）涉及：热封标签胶 48 小时才固化、真正的攻击发生在无签收的教堂地下室与低标货运公司而非投票现场；重复评估中组织的“coulda-woulda-shoulda”定律（知道有对策便不再担心却不去实施）；安全投入应先找组织内的黑客型人才；物理与网络安全“thugs vs. nerds”的文化融合；以及客户满足于次品、保险公司报销 2% 货物盗窃损失导致好封条没有市场。（YouTube EP51MxGK2q7Wo，[2282-4885]，L1）
- 〔USENIX ATC（推测）〕新加坡国立大学的 Jialin Li 与微软研究院 Dan Ports 等（合作者含 Jacob Nelson、Alice Michael、Xin Jin）介绍 Pegasus，一种用网内一致性目录实现分布式存储负载均衡的机架级系统。真实工作负载高度倾斜且动态变化，缓存层只对读密集负载有效、选择性复制又难以及时追踪副本；Pegasus 由 32 到 128 台存储服务器接到单个可编程 ToR 交换机，把选择性复制与实现在交换机内的网内一致性目录结合，目录处理全部请求、把请求转发到有富余处理能力的服务器并在每次写时重平衡副本集，用轻量级版本号协议（next/completed version）保证线性一致性且不产生额外失效流量。（YouTube EP55Aki75fAr4，[7.9-531.0]，L1）

- 〔NSDI（推测）〕普林斯顿大学的研究者（项目网站 covizor.cs.princeton.edu）提出 CoVisor，一个允许网络管理员在同一网络上组合多个第三方 SDN 控制器的组合式 hypervisor。Frenetic 需要管理员与厂商都采用同一语言与运行时，而 FlowVisor、OpenVirteX 等网络 hypervisor 只支持不相交切片；CoVisor 提供并行、顺序、override 三种组合算子（如监控+路由并行、防火墙先过滤再路由、大象流路由器接管 elephant flow），并用 many-to-one / one-to-many 虚拟拓扑原语和细粒度访问控制（限制可匹配的报文头字段、可执行的动作）约束每个控制器能看什么、能做什么，防止有 bug 或恶意第三方控制器破坏网络。（YouTube EP5umwCWs8Bos，[10.0-591.2]，L1）
- 〔NSDI（推测）〕增量编译与评估。CoVisor 把控制器发来的流规则编译为物理网络流规则，关键发现是规则优先级构成方便的代数：并行组合用加法、顺序组合用拼接（字典序）、override 用优先级空间堆叠，从而增量编译策略与更新交换机，把一条规则插入的重编译开销从朴素自上而下方案的上百至上千毫秒降到几微秒、流表更新从数千条 flow mod 降到只插入新规则；一对多映射的编译通过注入覆盖全流空间的符号包得到符号树再逐分支顺序组合；问答中说明该组合编译比直接运行 Frenetic 开销显著更低，其一对多映射是主动式（proactive）编译而既有虚拟拓扑抽象方案是反应式（reactive）逐包处理。（YouTube EP5umwCWs8Bos，[591.2-1310.8]，L1）
- 〔会议不详〕讲者演示用激光照射状态指示灯 LED 的注入攻击：强光能量会反向流入电子电路，后果从毫无影响到远程代码执行。其中至少有两种物理效应——光电效应（photoelectric，只能把二进制 0 变 1）与光电导效应（photoconductive，只能把 1 变 0），且部分元件只响应其一，这给攻击者设下约束：可把 load 指令改成 branch、add 改成 subtract，构成一种'任意性代码'（arbitrary-ish code）怪机器；攻击者耐心观察总线上的指令流、挑选可改写的 opcode 在高内存中搭出目标程序并先自我修复，演示环节用一台四-bit CPU 工厂自动化控制器模型（累加器 LED 走规扫描模式）展示攻击者先观察获得 CPU 相位锁定、紫外激光发射数秒后机器开始运行完全不同的程序。（YouTube EP6hswHjXfTyk，[7.8-343.8]，L1）

- 〔会议不详〕达特茅斯学院 Trust Lab 的 Rebecca Shapiro（该 Intern 目前在 Qualcomm 实习，致谢中提及）介绍 Clobber——ELF 元数据驱动的图灵完全计算引擎，把 ELF 元数据当指令、运行时加载器当执行这些指令的机器。讲者回顾 SQL 注入、XSS、栈 smashing 等注入式攻击与杀毒软件、DEP、ASLR、代码签名、输入净化等防御后指出：数据同样可以驱动怪机器（ROP 即'自带数据'），而 ELF 元数据定义地址空间布局、比代码更受信任，是代码签名的阿喀琉斯之踵；此前 ELF 中的 DORF 错误处理元数据已被证明可驱动图灵完全计算。工具链用 Python 解析 ELF 并把 brainfuck 源码编译成追加进 ELF 的符号与重定位元数据，由 loader 的 link_map 双向链表逐条执行重定位即执行程序（目标 glibc 2.13、AMD64）。（YouTube EP6xbirzvr-mQ，[9.8-786.2]，L1）
- 〔会议不详〕原语、条件分支与结论。在元数据汇编中符号充当内存映射寄存器、重定位元数据充当字节码，move 与 add 原语不依赖具体 libc 版本；jump-if-not-zero 通过把 link_map 链表环回自身、设置下一重定位入口与计数 n 等四条 move 完成预备，再借 ifunc（间接函数）符号的 shn_index 字段——非零则调用间接函数、为零则直接复制值——配合提前找到的返回 0 的 ROP gadget 实现条件分支；ELF 元数据还能定位栈与全部已映射库、重定向库调用与执行函数调用；结论指出该重定位引擎不在乎 DEP 与 ASLR、loader 隐式信任 ELF，问答与主持总结认为这是把 ROP 从代码复用推广到数据复用的新范式，对入侵检测含义深远。（YouTube EP6xbirzvr-mQ，[786.3-1555.4]，L1）

- 〔USENIX LISA〕Buoyant 现场工程师 Charles 在 USENIX LISA 21 大会上介绍服务网格与 Linkerd（Buoyant 是 Linkerd 开源项目主要赞助方）。服务网格源于 Twitter 2010 年为解决单体应用稳定性问题把系统拆成多个经网络通信的分布式组件后引入的复杂性；服务网格利用网络层对分布式系统进行观察、保护与可靠性加固，主要收益是降低错误的平均检测时间与平均修复时间。Linkerd 由数据平面与控制平面组成：数据平面是自动注入工作负载的 sidecar 代理，接管服务间全部流量（本地回环收发），提供延迟遥测、无需在业务代码中实现的双向 TLS（identity 服务签发证书并互相验证身份）、基于 EWMA（估计加权移动平均）算法的负载均衡与代理侧重试/超时；控制平面是 destination 服务（服务发现）、identity 服务（证书）、proxy injector 与 controller 等有限组件，用于配置新加入数据平面的代理。（YouTube EP7hgFr53HBbA，[7.8-958.5]，L1）
