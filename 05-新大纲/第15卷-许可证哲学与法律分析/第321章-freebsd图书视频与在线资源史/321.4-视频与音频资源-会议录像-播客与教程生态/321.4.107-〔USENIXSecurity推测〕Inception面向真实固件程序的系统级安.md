# 321.4.107 〔USENIXSecurity推测〕Inception面向真实固件程序的系统级安

- 〔USENIX Security（推测）〕Inception：面向真实固件程序的系统级安全测试。Maxim Integrated 芯片公司工程师、博士研究生 Nassim Corteggiani（转写作 Nassim Kortejani，与 Giovanni Camurati、Aurélien Francillon 合作）指出嵌入式系统日益互联且难打补丁——bootloader 常在量产时硬编码进 mask ROM 无法更新，Nintendo Switch 微控制器 USB 栈缓冲区溢出与 iPhone boot ROM 漏洞均属此类，还可能驱动 CNC 等敏感硬件。符号执行是高路径覆盖、能返回可复现测试用例的固件测试手段，且源码级分析优于二进制级：编译丢失类型与尺寸语义（对比 Clang 字节码与 S2E、Angr 提升器的语义），低资源设备上还会产生检测不及时的静默损坏（参见 NDSS 2018 "What You Corrupt Is Not What You Crash"）。Inception 的目标是不改代码测试含 C/C++、汇编与二进制的固件，两大挑战是混合代码支持与未在源码中定义的硬件交互（内存映射外设、中断信号）。（YouTube EPGqCSaWlNGQg，[11-554]，L1）
- 〔USENIX Security（推测）〕Inception 的实现与评测。实现上把含汇编的 C/C++ 函数整体替换为从二进制提升的 LLVM 字节码，中间加 glue 层按 ARM ABI 提升/降低语义层级并按同一位置分配对象以支持间接交互，修改 KLEE（转写作 Qwen）执行混合字节码，支持 Arm Cortex-M（含间接调用提升表、SVC 上下文切换模拟）；内存可配置为 KLEE 本地、重定向真实外设或符号化（对外设返回值过近似，可测攻击者可操控的不可信外设），并基于 JTAG 用现成器件研制受 Avatar 启发、取代已停产 PCIe 调试器 Surrogare 的低成本调试器，向 KLEE 转发中断并同步状态。评测：Inception 与 Surrogare 一样快（读操作因 libusb 用户态驱动每请求触发 DMA 而稍慢，主要瓶颈仍是字节码执行）；expat 注入漏洞基准显示提升函数越多检出率越低，NIST Juliet 测试套件除缓冲整数溢出（旧版 Clang 所致）外全部检出；用 4.3 万条来自 ARM 规范的测试用例比对寄存器与栈验证 lifter 与真实 CPU 行为一致；已测 FreeRTOS、Mbed OS（转写作 MINI-MOS）、mbed TLS 与 STM32/NXP 演示程序，已在 Maxim Integrated 用于测试 ROM 代码并发现多个漏洞，代码在 GitHub 开源。（YouTube EPGqCSaWlNGQg，[556-1423]，L1）
- 〔会议不详〕在极窄 pico 进程环境中运行富桌面应用：POSIX 仿真与 zones。主讲人 John Howell 回顾二十年来以类型安全在客户端隔离不可信代码（Java、Flash、Silverlight 到 JavaScript），但按钮、数学库、XML、PDF 等类库逃逸口不断蚕食隔离——JavaScript 解释器很小，浏览器却是上百 MB 的信任基础；ActiveX 之败在于根本不做隔离，而其 Zax 项目已证明可在容器中隔离原生代码运行 PDF 渲染器、Python 解释器、OpenGL。其团队在 NSDI 发表的 Embecosm 论文论证了"以极小可信运行时替换浏览器复杂性、把复杂性塞进应用交由厂商负责"的前提，本讲聚焦如何把 KDE Marble、Inkscape 这类富应用装进极窄 pico 进程环境：接口仅提供内存分配（不可自选地址）、线程、基于 Linux futex 的同步原语（转写作 zetex）、实时时钟与定时器、以 IP 为唯一 IPC、随机数、以及"给定屏幕矩形、离屏位图自绘后拷贝上屏"，接口规约简单到几周即可写出一个宿主并看清如何做对隔离（现场正以 Inkscape 在该容器中演示本报告）。（YouTube EPGrJ6ikxeLZA，[10-716]，L1）
- 〔会议不详〕POSIX 仿真与 zones 把整个应用装进窄接口。在容器底部实现 POSIX ABI 仿真层：虚拟文件系统（只读内容经自定协议走 IP 取回、读写盘放临时文件）、把单 timer 与 IP 这类窄接口多路复用出 poll/select 与 UDP socket 等丰富语义，并内嵌 Linux 共享库加载器加载 ELF 二进制、静态改写 glibc 使系统调用变成仿真层函数调用。Linux 333 个系统调用中约三分之二从不被桌面应用提及、其余一半可返回 0 或 -1 糊弄过去（应用本就在给操作系统"提建议"），应用二进制仅需位置无关重链接、glibc 改写一次即通吃；zones 技术进一步把整个 X server、窗口管理器、D-Bus 乃至 LWIP TCP 栈以库身份载入同地址空间（各程序内存交错而互不知晓，无需故障隔离），消除部分系统调用后应用反而更快。问答确认仿真开销基本不可察觉、应用启动可压到约 100 毫秒、X server 与同域应用共享信任边界从而化解 Norman Wilson（University of Toronto）的键盘记录疑虑、端侧可信核可小至百 KB 量级；端侧加入 X server 约多花 10MB 内存，未来设想把 GPU 当 CPU 同样下发二进制并隔离。（YouTube EPGrJ6ikxeLZA，[744-2210]，L1）
- 〔会议不详〕Unikernel 会被证明是下一个大事物：传统应用栈的冗余论证。主讲人为某公司云管理部门 CTO，指出今天跑一个简单进程要叠硬件、hypervisor、guest OS、Docker 容器、共享库、语言运行时和应用配置，隔离层层重复；Linux 内核就有 2200 万行代码、Debian 发行版达 4.19 亿行，几乎无法推理，这是社区当年为兼容性牺牲效率的演化结果；unikernel 主张只打包应用真正需要的部分，只支持单进程单用户，从而去掉权限检查、多地址空间和内核环，带来更小体积（约 2000 行 vs 最小 1GB）、更快启动、硬件级隔离与真正的不可变基础设施；随后介绍其团队用 Go 编写并开源半年、GitHub 超千星的平台 Unik，并提到语言特定型（MirageOS/OCaml、IncludeOS/C++）与 POSIX 兼容型（Rump kernel）两类 unikernel 及 OSv 团队转型做 ScyllaDB 快 10 倍的例子。（YouTube EPGuRTsCw1Utw，[9.7-1208.5]，L1）
- 〔会议不详〕Unik 平台架构、生态集成与现场演示。Unik 借鉴 Kubernetes 的接口化设计，把 unikernel 类型（社区可自行添加）、云 provider（OpenStack、VirtualBox、AWS、VMware Photon、QEMU/KVM、Google Cloud 等）和平台（含 ARM 嵌入式设备）三层解耦；它教 Unik 说 Docker API 让脚本无需改动，并集成 Kubernetes、Cloud Foundry，Kubelet 经 KubeVirt 请求 Unik 拉起 unikernel 实例；用例上强调 IoT（树莓派烤面包机演示）、Mirai 式 DDoS 攻击手法对 unikernel 不适用、微软在 NetBSD 上跑 .NET 后可把 .NET 搬进 unikernel、以及 serverless/NFV 等快速启动场景；现场演示在 AWS 上用 56MB 镜像跑 Node.js 网站和 Minecraft 多人游戏（经 9967 端口取日志调试），并强杀 unikernel 实例展示 Kubernetes 自动拉起；Q&A 回应了上手资源、安装只需 git clone 与 make、以及复用 NetBSD/Rump kernel 而非重写网络栈的疑问。（YouTube EPGuRTsCw1Utw，[1208.5-2417]，L1）
- 〔会议不详〕用 DAG 存储 profiler 数据：把足迹降低五个数量级。主讲人 Pat Samaroo 是 Meta 效率与容量工程团队的生产工程师，介绍 perf、libbpf、YourKit 等工具生成的 profiler 数据本质上是系统运行的快照观测数据；性能问题往往不可稳定复现，必须持续采集，而 10 秒 profiling 就能产生 2GB 数据、汇总到每天约三分之一 PB，存储与查询都成问题；Meta 的做法是把调用图存成 DAG（有向无环图），使数据足迹降低约五个数量级（玩具应用降两个数量级），并开源了实现工具 Stow（store things optimize）；第一个原语 Stack Node Data 把符号、文件路径、行号三元组全局唯一化后哈希成 64 位整数替换原字符串，大幅缩小数据并支持跨二进制发现复用代码的回归。（YouTube EPGvVkfS1LuQs，[7.7-373]，L1）

- 〔FAST（推测）〕SHARDS：常数空间构造缺失率曲线（MRC）的动机与基本设计。来自 CloudPhysics 的研究者分享其已上线于虚拟化环境缓存分析服务的成果，MRC 画出缓存大小与缺失率的关系、暴露工作集的各个拐点，是高效分配缓存空间的关键；MRC 构造依赖重用距离直方图，作者回顾了 45 年研究史：Mattson 1970 年单遍算法、基于平衡树的精确离线改进、集合采样与时间簇采样等近似技术、UMON/RapidMRC/ParDA 等在线与并行方案，直到 OSDI '14 的 counter stacks 与 SoCC '14 的工作；SHARDS（Spatially Hashed Approximate Reuse Distance Sampling）用确定性哈希做随机空间采样并保证同一块的所有引用都被采样以捕获重用距离，在现有重用距离算法前放一个阈值采样滤波器、再按采样率放大结果，是首个常数空间的 MRC 算法，但基础版空间无界且采样率难选，催生了固定大小版本。（YouTube EPGx0RBLwkwUc，[9.8-763]，L1）
- 〔FAST（推测）〕固定大小 SHARDS 的评估、与 counter stacks 对比及非 LRU 泛化。固定大小版本指定最大采样数并淘汰哈希值最大的样本、同步下调阈值 T 并重缩放旧样本权重，采样率从 0.1 起自适应下降，运行只需约 1MB 内存、比基线小一万倍以上；在 124 条真实块 I/O trace（106 条来自 VMware 生产环境、虚拟盘 8GB 到 34TB，另含 SNIA/FIU 公开 trace）上，8K 采样时 MAE 中位数仅 0.0027，误差与样本数平方根成反比（回归相关系数 0.98），直觉是多数负载由少量底层统计过程构成；CPU 加速 40 倍到 1000 倍，固定大小版仍达 200 倍；与 counter stacks 同配置对比，SHARDS 内存 2MB 对 80MB、吞吐约 1700 万对 230 万引用每秒，counter stacks 慢约 7 倍、大 40 到 62 倍；还演示了用空间哈希加缩放仿真准确建模 ARC、Clock-Pro 等非 LRU 自适应策略，Q&A 讨论了写策略建模与对抗性 trace 防御（MurmurHash 随机化种子）。（YouTube EPGx0RBLwkwUc，[763-1526.4]，L1）
- 〔会议不详〕Dropbox 的 Naru：安全自动修复的理念与工具化生命周期。主讲人 David Ma 来自 Dropbox 存储团队，因要安全地自动化重格式化硬盘等吓人操作而造出自动修复系统 Naru（日语意为修复），Dropbox 的几十个机器学习团队大都在用它；值班可执行项包括批量重启升级内核、下线替换坏盘、重格式化损坏磁盘但不能碰用户数据最后一份副本，目标是零事故；他给出工具化生命周期模板：手动操作→加告警（自动找活）→加修复脚本→直接上 cron 会跨步太大出事，中间必须插入人工授权阶段，反复追问为什么我不该运行这段自动化（是否有事故进行中、影响面是否离谱、解释是否自洽），再把这些问题逐步写成防护并最终完全自动化。（YouTube EPGxdgXMkYIpE，[5.3-685]，L1）
- 〔会议不详〕Naru 流水线细节与竞态处理。告警进入 diagnose plugins（只运行非危险逻辑，区分症状与根因：如 SSH 告警经带外检查发现机器卡死在 initramfs shell、硬盘彻底损坏，重启无用则改判下线），插件产出 prescription 后需人工授权；随后经过 pre-remediate hooks，Dropbox 杠杆最高的防护是速率限制与可用性检查（另有仅工作时间运行、一次只动一个数据中心等），如 Zookeeper 的 hook 检查 ensemble 成员存活否则推迟，速率限制配合可用性检查可在事故时止损并给人类留出响应时间；remediate plugin 失败会带着尝试计数重新进入整条流水线，二次尝试可从重启改用下线；当操作员完全自信地连按 yes 时按具体 remediation 逐项取消人工授权（重启可免审、重格式化仍保留）；Q&A 讨论了陈旧 remediation 与竞态：diagnose 插件每 5 分钟重跑并重新生成 prescription，处方键变化即重置状态，剩余窗口靠速率限制拉大间隔兜底。（YouTube EPGxdgXMkYIpE，[685-1213.1]，L1）
- 〔会议不详〕GoFetch：Apple M 系列 DMP 使常时间代码不再是常时间。主讲人与 Yingchen Wang、Pradyumna Shome、Christopher Fletcher、David Kohlbrenner、Riccardo Paccagnella、Daniel Genkin 合作；在回顾依赖缓存命中/缺失时序差的经典攻击与常时间编程三原则（密钥不影响控制流、访存模式、指令操作数）后指出：Apple M 系列 CPU 的数据内存依赖预取器（DMP）会把从内存加载的任意数据当作地址去访问，即使程序不含密钥相关访存，DMP 也会解引用密钥值（如指向不同 cache line 的 pointer1/pointer2），在缓存中留下共置攻击者可观测的差异状态；相比首个发现 Apple M1 DMP 但未能演示实际攻击的 Augury，本工作通过全面逆向工程发现触发 DMP 并不需要 Augury 所述的数组指针访存模式，并构造了新的选择输入攻击以突破 DMP 只能泄露指针值的限制，实现了对四个常时间密码学实现（含已部署与提交 NIST 后量子标准化者）的端到端密钥提取。（YouTube EPGxfF6W1tNAI，[8.5-347.8]，L1）
- 〔会议不详〕DMP 逆向、选择输入攻击与现实影响。实验表明单个内存加载即可触发 DMP，DMP 只扫描 L1 cache fill 时的数据、按指针大小对齐块逐块检查、且目标须映射到进程有效内存区域才会成功解引用；由于密码学中间状态通常看似随机，作者构造选择输入攻击（例如用全 1 的 64 位掩码与密钥做 AND，使中间状态为合法指针或全 0 非指针，通过 DMP 是否解引用区分密钥），实现端到端密钥提取 PoC，覆盖 OpenSSL Diffie-Hellman 密钥交换、Go 的 RSA 解密以及模块格数字签名标准与密钥封装机制；现实影响方面，Apple 发布了启用数据独立计时（DIT）位的指引（仅 M3 及更新芯片能禁用 DMP，M1/M2 不行），Go 计划加入可选 DIT 位并在 GopherCon 介绍了该攻击，Asahi Linux 项目负责人 marcan（Hector Martin）找到了仅内核态可设置的 M1/M2 chicken bit 并承诺提交补丁，GoFetch 还获 Pwnie Awards 年度最佳密码学攻击奖。（YouTube EPGxfF6W1tNAI，[347.8-695.5]，L1）
