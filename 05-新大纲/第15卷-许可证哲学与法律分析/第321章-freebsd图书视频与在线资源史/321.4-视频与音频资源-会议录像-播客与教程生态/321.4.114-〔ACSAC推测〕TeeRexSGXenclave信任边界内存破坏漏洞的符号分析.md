# 321.4.114 〔ACSAC推测〕TeeRexSGXenclave信任边界内存破坏漏洞的符号分析

- 〔ACSAC（推测）〕TeeRex：SGX enclave 信任边界内存破坏漏洞的符号分析。杜伊斯堡-埃森大学的 Tobias Cloosters 介绍其 TeeRex 框架：以符号执行（内部基于 Angora）自动分析 enclave 的 ecall，寻找宿主-enclave 信任边界引入的未充分校验不可信输入导致的控制流跳转、越界访问与空指针解引用，生成含利用原语的漏洞报告供分析者构造完整利用；背景在于 SGX 威胁模型下 enclave 内数据校验无法提前完成、且 SGX 中绝大多数内存破坏 bug 都可利用（空指针解引用与读未分配内存不会崩溃、一个字节的地址损坏即足以利用、enclave 私有内存中还存有合法调用传入的攻击者可控数据可造成类型混淆）；团队在多个公开 enclave 中发现漏洞，最重要的是 Synaptics 与 Goodix 指纹驱动 enclave 中的任意代码执行（随 Lenovo、HP、Dell 近年几乎所有笔记本出货），并对 Intel、Baidu 等公开 enclave 代码及多个 TLS 库构造了概念验证利用，已通知所有厂商修复（仅已停维护的 Teaclave 项目除外，指纹 enclave 在六个月负责任披露后更新），未在 Signal 的 enclave 代码中发现漏洞。（YouTube EPHrrPDyHy7v8，[8-315]，L1）
- 〔ACSAC（推测）〕enclave 漏洞代码模式与利用链。讲者以 Rust SGX SDK 的 TLS 连接清理示例展示典型漏洞模式：攻击者把伪造的会话对象跨放在安全内存边界上即可绕过"严格在安全内存之外"的检查，指针仍在攻击者控制下，可用于任意代码执行并窃取密钥；受限原语（攻击者只控地址、值受限或仅单字节写）虽无法直接劫持控制流，但可通过受控值原语改变 enclave 内部状态并链接多个 ecall 组成利用链——第一个 ecall 在安全内存已知位置初始化对象（空检查保证已初始化），第三个与本对象无关的 ecall 以攻击者可控方式向任意地址写常量错误码，借此破坏前一 ecall 所用对象指针、把对象挪出安全内存，最终获得任意代码执行能力；结论是 enclave 边界是高度危险的攻击面而现行开发实践未考虑此类漏洞，需要提升安全意识并使用 TeeRex 这类自动分析工具。（YouTube EPHrrPDyHy7v8，[315-630]，L1）
- 〔SoCC（推测）〕Beaver：面向分布式云服务的首个部分快照协议。讲者指出许多分布式系统问题归结为确定全局状态，快照算法（以写入所有教科书的 Chandy-Lamport 为代表）通过出站发起并以标记消息传播因果关系，保证因果一致性（快照包含某事件的效果就必须包含导致它的事件）；但其基本假设是参与者集合对因果传播封闭、需协调全体节点，而现代云部署中服务依赖图复杂、部分组件属其他团队或托管在不可访问的基础设施、插桩代价高昂，且外部流量（研究表明可占总流量相当份额）还带来隐藏因果关系——即便单个非参与节点也可让经典快照不一致（事件 e2 在快照中而导出其效果的事件未被包含）；Beaver 将节点分为 in-group（关注机器）与 out-group（其余外部机器），在不阻塞（不缓冲或延迟用户包）的前提下提供与经典快照相同的抽象，其核心是带外实例化逻辑网关并标记所有来自 out-group 的入站包以开启新快照，组内节点照常执行传统快照操作，且该"单体网关标记"被形式化证明正确——即使因果链含多个外部跳甚至人为环节也成立，网关只需观察进入 in-group 的包、无需追踪到 out-group 的依赖。（YouTube EPHtGntQ8QJgs，[17-440]，L1）
- 〔SoCC（推测）〕基于 SLB 的网关实例化、乐观网关标记与评估。公有云数据中心本就以四层负载均衡器（软件负载均衡 SLB）按目的 VIP 处理所有入站流量（无论来自互联网还是其他 VIP），Beaver 复用其在近零成本下执行网关标记逻辑（如海狸用就地取材的石块树枝筑坝），且出站流量通常绕过 SLB 也与设计兼容、无需处理出站消息；面对单网关服务器无法承载流量与容错所需的多个网关（SLB 异步导致晚进入快照的网关引发不一致），若强制跨 SLB 共识会阻塞入站消息、增加响应时间与缓冲容量，Beaver 改用乐观网关标记：观察到因果相关消息需经"网关→组内节点→out-group 节点→网关"的消息链形成，当首个与末个 SLB 快照发起的时间差小于形成外部因果链所需时间（至少三次数据中心 fabric 往返加处理开销）时快照自然一致，否则用定理比较左右两侧值检测违规并拒绝（左侧借单一时钟源测上界，可能误拒但可近零成本重试，不影响正确性）；云数据中心测试床原型评估显示典型组内服务规模下保持高快照速率、最坏情形下拒绝不到 5% 快照、对现有流量零影响，并支撑引用计数垃圾回收等用例——serverless 匿名存储服务中经典快照因外部因果不可见可致超 30% 的无效解引用调用并错误回收仍在使用的键，Beaver 保证零无效调用。（YouTube EPHtGntQ8QJgs，[440-903]，L1）
- 〔USENIX Security〕Kage：实时嵌入式系统上的整体控制流防护。罗切斯特大学与 WPI 的团队（合作者包括 Komal Darshi、John Criswell 与 WPI 的 Robert Walls）指出，微控制器广泛用于无人机、家庭 IoT、SSD 控制器与汽车，但无虚拟内存、无 TrustZone、低主频，缺乏抵御代码注入、return-to-libc、ROP/JOP 等控制流劫持攻击的保护——内存安全语言因嵌入式仍普遍用 C/C++ 甚至汇编而不可行、ASLR 因无虚拟内存而失效；shadow stack 与 CFI 检查虽久经桌面验证，但此前嵌入式工作多针对无操作系统的裸机设备，支持实时操作系统的前作 RecFish 只保护上下文切换时的处理器状态、缺少中断入口保护与内核 API 输入校验（攻击者可借损坏参数关闭其他防护），且开销高达 21%（Wozniak 等指出主要源于每次写 shadow stack 存返回地址都需从非特权模式切换到特权模式）；Kage 补齐中断入口的状态保护与全部内核 API 函数运行时检查，基于 FreeRTOS 面向 ARMv7-M（无 TrustZone、使用 MPU 的）设备实现，通过修改编译器把返回地址存入 shadow stack 并对所有函数指针加 CFI 检查，CoreMark 平均开销仅 5.19%（线程增多时因上下文切换更频繁而略升）。（YouTube EPHuKqsKl4KhM，[8-395]，L1）
- 〔USENIX Security〕Kage 的 store hardening 低开销技术与安全评估。低开销的秘诀是源自其前作 Silhouette 的 store hardening：利用 ARMv7 各架构中已有的非特权 store 指令，把应用代码的 store 指令改写后，让应用与内核全部运行在特权模式的同时模拟非特权行为，违规写保护内存即触发故障，从而免去模式切换；防绕过方面，操作系统以隔离内存区域防止应用互写栈与内核内存、缩小 TCB（将大量内核特性移出 TCB 至非特权侧）、对剩余内核函数加运行时检查，并因一切运行于特权模式而增设 sanitizer 检查应用代码是否覆写栈指针或调用无运行时检查的内核函数；在 AWS FreeRTOS 官方认证的 STM32 IoT 节点上以 ROPgadget 评估，无防护时可发现 2000 多个代码复用 gadget 且攻击者可随意跳转，Kage 下仅剩 27 个可达 gadget（减少 98.8%），其中 17 个位于应用函数开头、10 个位于直接调用之后，无法拼接成攻击链、难以发起强力攻击；Kage 已开源。（YouTube EPHuKqsKl4KhM，[395-750]，L1）
- 〔会议不详〕NetRPC：把网络内计算（in-network computation）引入 RPC 编程模型。清华大学博士生 Bo Han Zhao 介绍其动机：可编程交换机上的 NC 能缓解分布式训练参数服务器的 incast 问题、并降低分布式共识的投票延迟，但开发面临三大挑战——把网络细节并入应用导致网络编程繁琐、P4/NPL 等芯片专用语言复杂、交换机表与寄存器需在启动时静态布局。NetRPC 把数据流视为一系列键值对、把交换机内存组织为虚拟 map，识别出五类覆盖现有 NC 应用的原语；用户只需用 Protobuf 定义服务与消息、指定 netfilter 参数，再由 gRPC 编译器自动生成接口，调用远程过程即可获得 NC 收益。（YouTube EPHucaH6jb7zA，[13.7-472.9]，L1）
- 〔会议不详〕NetRPC 的并发、幂等、回退与内存管理设计及实验结果。系统把全部原语部署在 Tofino 交换机的同一条流水线上以支持多应用并发；因 RPC 必须最终成功，用随发送窗口周期翻转的 flip bit 在有限内存下检测重传包、消除重复累加，并在交换机 NC 失败时把数据迁移到服务器由主机端回退完成计算；内存按发送窗口池化复用、键值流按缓存命中处理，并靠控制器两阶段超时（先迁回服务器再清除）平衡利用率与可用性。实验（8 台 GPU 服务器接两台可编程交换机）显示 NetRPC 把 HPC 应用代码量最多减少 97%、性能与基线相当，分布式训练吞吐比 ADP 更好、比 P4 交换机方案高约 12%，多应用并发几乎无损，且在多种丢包率下性能退化最小。（YouTube EPHucaH6jb7zA，[475.1-947.0]，L1）

- 〔GTUG Sydney〕Rob Pike（Google，Go 语言作者之一）在悉尼 GTUG 演讲 Lexical Scanning in Go。他从 Michael Jackson（非歌手）的结构化编程讲起：块与行等两侧数据形态不匹配使控制流难以写对，而协程正是为解决此类问题而发明；以他为 Go 早期库写的模板系统为背景，词法器向 parser 交付由类型与字符串值组成的 item，itemType 借 iota 枚举、经 String 方法美化打印调试。他逐一排除 lex 等工具（错误信息难产、要另学一门语言、生成巨大而慢的状态机）与正则表达式（引擎大而重，静态问题套动态机制属杀鸡用牛刀），提出把状态与动作合并为返回自身类型的 state function（递归类型定义），使词法器主循环折叠为一行 state = state(lexer)；随后以 goroutine 协程与 channel（类比语义更严格的 Unix 管道）把 item 递给 parser，并演示 lexText、lexLeftMeta、lexInsideAction 状态函数与 emit 机制（发送 input 的 start 到 pos 切片）。（YouTube EPHxaD_trXwRE，[31.4-1531.8]，L1）
- 〔GTUG Sydney〕词法器的辅助函数、数字扫描与“去并发化”。借助 next、ignore、backup、peek 与 accept/acceptRun 辅助函数逐 rune（UTF-8 解码字符）推进扫描；lexNumber 采用 maximal munch 思路取“最长可能是数字的串”（十进制/十六进制/浮点/复数虚部）交给 parser 校验，错误经返回 state function 的 errorf 输出格式化错误信息后停机。因 Go 初始化阶段不允许运行 goroutine（否则初始化语义模糊），他把 channel 加缓冲变成环形缓冲、并用带 select 的 nextItem 循环以几行改动移除对外的并发 API，内部仍是同一干净状态机；结论强调并发是设计概念而非并行（并发使能并行但不要求并行），Q&A 中确认词法器对输入字符串零拷贝、可改造为 reader 接口，并谈及与 ragel 生成代码的同构及性能取舍。（YouTube EPHxaD_trXwRE，[1544.9-3077.1]，L1）
