- 〔USENIX Security〕（推测）Arbiter：融合静态与动态分析的二进制漏洞发现。主讲人 Jay Krishna（亚利桑那州立大学，与南加州大学、Cisco 等合作）提出漏洞驱动的分析观：数据流敏感（P1）、源/汇易识别（P2）、别名可由控制流决定（P3）三条性质支撑混合分析——静态分析借可识别 source/sink 高覆盖地筛候选路径，无约束符号执行保高精度并可自适应增强上下文敏感性、在精度与可靠性间可配置权衡；Arbiter 平台接受漏洞描述与目标二进制，选取四类 CWE 评估：CWE-131 缓冲区大小计算错误、CWE-134 外部可控格式串、CWE-252 未检查返回值、CWE-337 伪随机数可预测种子。（YouTube EP4OWjLStPtcc，[8-337]，L1）
- 〔USENIX Security〕（推测）Arbiter 实战评估：发现其他工具找不到的漏洞。对 Ubuntu APT 仓库约 76000 个 x86-64 用户态二进制运行，共产生 1130 条告警，人工判定 661 真/410 假、约六成真阳率；AFL 在 24 小时内仅借手工 harness 找到 25 个 bug 中的 3 个，无 harness 一无所获；核查 CWE-131 报告时还在 25 个包中定位到 OCaml 编译器在 32 位程序中引入的编译期漏洞（源码无 C 代码可比对）；在 Juliet 合成数据集上真阳率与真实评估相当，并发现 190 个清单标注不可触发实为可利用的用例（32 位整数取绝对值回绕导致 malloc 1 字节却复制 2^32 字节的堆溢出），代码已开源于 GitHub 并提供 Docker 镜像。（YouTube EP4OWjLStPtcc，[338-680]，L1）
- 〔会议不详〕Glitch Glue：以硅前布局数据为蓝图的引导式硬件故障注入。主讲人 Charlotte 指出软件级防护（如输入长度校验）在门级不可见，电压毛刺等物理扰动可自底向上传播（寄存器出错位→错误指令→返回地址被改写）；传统黑盒攻击依赖指令跳过等故障模型、需穷举故障参数（数千次试验才得少数有效故障）且基于试错、不可移植，高精度激光/EM 设备也仍环境依赖，对防护设计者而言逐一人工分析形同灾难。Glitch Glue 把处理器硬件状态按字级寄存器切分，在仿真测试台生成记录各寄存器输出值（十六进制）与时钟沿的动态状态转移图（DSTG），无需改动 RTL 或门级网表，并提供时间窗口选择以控制绘制开销。（YouTube EP4XsPCTUwmCI，[10-568]，L1）
- 〔会议不详〕DSTG 引导的三步攻击流程与硅后验证。以 assert 输入校验的缓冲区溢出防护（16 字节缓冲 vs 19 字节串）为例：第一步在 DSTG-PC 上定位漏洞决策状态 VDS（进入死循环防护还是执行 strcpy 的跳转，位于指令 0xF08E）；第二步确定故障注入状态 FI（寄存器 R13 中 0x213→0xF 的转移，使 R13 值大于 R12 而跳过防护）；第三步确定注入时间（时钟周期 923，4 位翻转，逻辑传播时延上限 6 纳秒）；时钟毛刺攻击需宽度落在 4.7–6 纳秒（避开其他关键寄存器稳定窗口），激光注入则按布局感知只翻转半径内特定位并可用 5 纳秒毛刺在仿真中攻破防护；在 TSMC 180nm OpenMSP430 ASIC 上以扫描链做硅后验证，宽度大于 6 纳秒无效、小于 4.7 纳秒误伤其他寄存器，与仿真参数吻合；方法还迁移到 ibex、PicoRV32 等核心，未来计划 IBEX 芯片流片与参数提取自动化。（YouTube EP4XsPCTUwmCI，[498-1229]，L1）
- 〔OSDI〕Koala：补上 Shell 研究缺失的基准套件。主讲人 Evangelos 与 Lucas 以对话式讲解：Shell 是 GitHub 十大编程语言之一、广泛用于生物信息、数据科学管线、CI/CD 与系统管理，但 shell 优化系统长期缺乏公认基准（如某篇 shell 脚本语言优化工作不得不自凑程序评估）；他们展示了研究人员数字化金字塔文（ Pyramid Texts）象形文字时真实使用的 shell 识别管线（分割模型→边界框→分类模型→建库），以及 GNU Parallel、Pash、HS 等可加速该脚本的系统，进而引出 Koala——一套真实 shell 程序配多尺寸真实输入、附自动化可配置基础设施的基准套件，程序来源涵盖互联网、历史脚本、博客与学术工作。（YouTube EP4YsdRy_S1gA，[18-424]，L1）

- 〔SREcon〕（推测）真实世界中的 SLI 与 SLO：系统边界方法。主讲人 Matthew Flammang 与 Alisa Bennett（均来自 New Relic，分别负责站点可靠性团队与可靠性工程/内部监控团队）澄清 SLI/SLO/SLA 概念，提出以系统边界（一个或多个组件向外部客户暴露能力之处，通常与团队边界对齐）组织测量，边界 SLI/SLO 对维护工程师、依赖客户与整个工程组织杠杆最大；基本配方是识别边界与能力、用平实英语定义可用性、定义 SLI 并测基线后再设 SLO 并持续迭代。以简化版 SaaS 监控平台为例，数据接入层拆分为数据摄取（X% 合法载荷返回 2xx，异步端点不关心时延）与数据路由（Y% 消息 Z 秒内可在消息总线上读取）两个能力，并强调 SLO 目标须立足技术现实、作为组织对齐工具且会随负载演化、先测量后设目标。（YouTube EP4cFl-Ge0x4g，[10-600]，L1）
- 〔SREcon〕（推测）从查询层到基础设施层的 SLI/SLO 落地与要点清单。New Relic 自研数据库 NRDB 查询层用响应时间（P95–P99 分位而非均值）与错误率两个 SLI 作数千节点底层行为的宽代理，可设复合 SLO（各 SLI 逻辑与便于客户理解）；硬分片的老旧系统须按每个分片单独测 SLI/SLO，因为丢 1/3 节点时三分之一的客户完全不可用与所有客户都降级有本质区别；网络层关心负载均衡端点可用性与 AZ 内/跨 AZ 路由（经验上每层基础设施要多付半个到一个数量级的可用性，三层九可用性的服务网络层宜从四个九起步），容器调度（Mesos/Marathon）关注链路饱和与集群自身引入的宕机，最后以合成端到端脚本做总可用性 sanity check 并可为核心客户单独设 SLI/SLO；收尾复述重视 SLI 胜于 SLO、先测量再设目标、每个逻辑实例可能需要自己的 SLI/SLO 等十条要点。（YouTube EP4cFl-Ge0x4g，[600-1221]，L1）
- 〔会议不详〕Wave：支持传递委托的去中心化授权。主讲人 Michael（UC Berkeley）以楼宇出租/IoT 场景指出中心化授权服务器（Active Directory/LDAP 类）既是攻击焦点（一台失陷全部租户与设备失陷）又可窥探本应私有的授权关系，且撤销不具传递性（如 Google Docs 撤销初始分享后二级共享仍有效）；Wave 是密码学强制执行的去中心化授权，权限表示为全局授权图：实体（密钥集合，可为人、服务或设备）间的授予是签名证明（attestation），权限证明即从命名空间权威到实体的图上路径，授予各构成证明权限的交集，任何人（含 IoT 设备）都可验证。（YouTube EP4fEH6iQFyk0，[11-430]，L1）
- 〔会议不详〕反向可发现加密与日志派生存储。公开图上的隐私靠 reverse discoverable encryption：签发证明时以通配符身份加密（WIBE，每实体自带 IBE 系统、无私钥生成器）内嵌可解密上游相交权限证明的密钥，HVAC 控制器从自身密钥出发逐级解密授权链，而资源不符或无路径的证明保持不可解密且无需带外通信、与授予先后顺序无关；存储上区块链每秒仅数十笔事务不够用，故设计类似证书透明、支持不存在证明（用于撤销）的 log-derived map：操作日志+稀疏 Merkle 树地图+地图根日志三棵 Merkle 树，审计者重放操作日志构建副本并与客户端低频（日/周）比对根哈希以防服务器给不同客户端不一致视图；系统以 Go 实现（密码部分 C++），三年内在多组织 20 栋楼保护 200+ 设备，授权耗时 45ms、证明构建 <15ms、验证 <8ms；Q&A 涉及用于 DNSSEC 的可能、图含环不影响发现、以及审计者非中心权威（地图只存哈希、审计极轻量，可多人运行）。（YouTube EP4fEH6iQFyk0，[430-1206]，L1）
