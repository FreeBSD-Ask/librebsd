- 〔OSDI〕后半场介绍写入路径与评估。插入/更新先落入叶子级 insert buffer，填满后整块复制到主机，由 patch 线程更新主机内存中的树副本并生成新子树，再由 DPA stitcher 线程经单次原子 connect stitch 挂回 NIC DRAM，配合 epoch 回收保证遍历不被中断；热键值对经放在缓存行剩余空间、常驻 L2 的 bloom filter 直达 cache line 桶哈希表，无需遍历或主机 DMA 即可命中约 50% 请求并提升 get 性能。单卡 BlueField-3 配六个 DPDK 客户端实测 get 峰值 3300 万 ops/s（无热缓存约 2600 万），B-tree 仅在 epsilon 取 16 的数据集上可反超 learned index；原始插入被卡在 170 万 ops/s（疑为 DPA 内存管理限制，试过拉取/推送及 NVIDIA API 均未突破），但混合负载不受影响；与基于 RDMA 的 Rolex 相比，单个 DPA-Store 实例即可与六个完整 x86 节点在同一量级竞争，范围查询全程占优。（YouTube EPD5nHTHdKeoY，[455.4-930.1]，L1）

- 〔USENIX Security（推测）〕后半场给出两个攻击原语与完整攻击链：基于 ocall 机制的 oread 原语仅需控制指令指针与栈即可获得部分上下文控制，基于异常处理的 continue 原语还需控制第一参数寄存器 rdi、但可取得全部 CPU 状态控制权，二者可互相触发构成 oread+continue 循环，从而把整个函数而非小 gadget 链起来，示例中窃取 getkey 返回的加密密钥并用 sendfile 外发。攻击可绕过 SGX-Shield：TRTS 未经随机化，且其返回边 CFI 插桩存在缺陷使 oread 原语仍可行，而 SGX-Shield 其余软件缓解依赖 CFI、CFI 一失效即全部失效；缓解建议包括在 SDK 结构中嵌入或 XOR 混淆秘密（如 GNU libc 的做法）、扩展 SGX-Shield 随机化 SDK 代码以及更细粒度 CFI。问答中 Rochester 的 John Criswell 指出这与 SVA/Virtual Ghost 系列保护保存程序状态的思路相通，主讲人确认软件保存的状态确实未受 SFI 保护。（YouTube EPDFCkemhiayk，[672.5-1374.5]，L1）
