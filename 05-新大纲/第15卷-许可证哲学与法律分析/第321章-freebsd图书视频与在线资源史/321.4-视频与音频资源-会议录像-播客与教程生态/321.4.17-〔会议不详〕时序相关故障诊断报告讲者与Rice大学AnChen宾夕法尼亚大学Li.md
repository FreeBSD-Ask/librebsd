- 〔会议不详〕时序相关故障诊断报告。讲者（与 Rice 大学 An Chen、宾夕法尼亚大学 Ling Fan 合作）指出 Google Cloud 公开事件中时序类故障占三分之一以上；现有 Dapper 跟踪树与溯源（provenance）调试器只能呈现事件何时发生、无法解释某事件为何耗时长，因其不捕捉时间因果（如滥用维护服务的 RPC 挤占存储后端队列、真实根因根本不出现在输出中）。提出将溯源推广为时间溯源（temporal provenance），向溯源图引入 sequencing 边并对子树标注延迟贡献（对应潜在加速空间），实现调试器 Zeno（支持 RapidNet、Zipkin、带 P4 交换机的 MiniNet），在七个复现的 Google Cloud 事件上可捕获仅时间贡献的离路根因，标注与聚合技术使溯源图缩小 89% 以上，查询十秒内完成。（YouTube EP2gnJiBAEQYw，[10.8-1041.7]，L1）

- 〔会议不详〕Blockade 报告。讲者介绍 Blockade 是面向 Web 应用的运行时数据访问策略强制系统：以 SQL 代理拦截应用查询，用数据库视图定义策略，借助 SMT 求解器验证查询不会泄露策略之外的信息（依据 Codd 定理把 SQL 归约为一阶逻辑，配合若干近似），不合规查询被阻止，兼顾与 Django/Rails 等现有框架的兼容性与语义透明（违规时报错而非静默改写结果）；SMT 求解每查询数百毫秒太慢，引出决策缓存设计。（YouTube EP2hrppqw3exE，[12.7-620.7]，L1）
- 〔会议不详〕缓存泛化与评测。决策缓存把已判合规的三元组（请求上下文、查询、查询跟踪）泛化为决策模板以提升命中率，模板由求解器以 unsat core 引导逐轮枚举约束生成；以 JDBC 驱动实现，在 Diaspora、Spree、Autolab 三个应用（每应用约 2200 行代码修改）上评测：合规决策全缓存时开销约 12%，关闭缓存则超过 200 倍，说明智能缓存是低开销关键；系统开源并附 artifact。（YouTube EP2hrppqw3exE，[617.0-950.2]，L1）
- 〔独立讲座〕讲者 Costantinos（与 Ram、Sibar 合作）介绍数据库调优背景：Cassandra 等系统出厂带数百个可调旋钮（knob），自动化调优框架的离线剖析阶段需数小时至数天并主导总调优时间；核心问题是达到好性能究竟需要调多少个旋钮。实验发现 Cassandra 在均衡负载下仅 5/155 个旋钮即可获得接近全调优的性能，且这组旋钮对完全不同的负载同样重要。（YouTube EP2mLaVJT5mTA，[7.8-325.9]，L1）

- 〔USENIX Security〕单服务器 PIR 报告。讲者 Samir（与 David Wu 合作）回顾 SimplePIR（Henzinger 等，上一年 USENIX）及其离线 hint 机制：hint 依赖数据库内容，每次更新客户端都需重下，由此引出研究问题——能否去掉离线阶段、回到无预处理的朴素 PIR 模型。已有 HintlessPIR、Tiptoe（Hensinger 等、Lee 等）用环 LWE 外层同态加密对 hint 内积做双包封（double wrapping）来消除 hint，但外层明文空间须容纳内层密文空间，使响应膨胀约 10 倍。（YouTube EP2olt_mChIgQ，[8.1-382.1]，L1）
- 〔USENIX Security〕本文方案 YPIR 与结果。不再把 LWE 重嵌进环 LWE，而用代数变换直接把一组 LWE 密文转换为环密文（log d 次 key switching），并把大部分 key switching 计算预计算（静默预处理）使在线可行；在 8GB 数据库上小项检索的下载与吞吐与 DoublePIR 相当且零离线成本（查询 1.5MB 对 DoublePIR 1MB），大项检索响应尺寸显著优于 HintlessPIR，并给出证书透明与口令泄露检查应用、跨客户端查询批处理与 SimplePIR hint 加速等附加贡献；结论：现实部署中离线成本很重要，做 bootstrapping 类操作前应先找代数变换；论文与代码通过 artifact 评测并开源。（YouTube EP2olt_mChIgQ，[382.1-653.7]，L1）
