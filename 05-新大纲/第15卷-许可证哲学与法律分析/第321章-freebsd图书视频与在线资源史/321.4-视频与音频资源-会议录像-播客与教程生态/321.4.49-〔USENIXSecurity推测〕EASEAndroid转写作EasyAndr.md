- 〔USENIX Security（推测）〕EASEAndroid（转写作 EasyAndroid）——首个用于 SEAndroid 策略分析与新纲的半监督学习系统。主讲人（与导师及 Samsung Research America 同事合作）介绍自 Android 4.3 移植的 SELinux/SEAndroid 强制访问控制（allow 规则白名单与编译期 neverallow 检查），指出 SEAndroid 策略需完整重设计、需兼具 Android 功能与安全领域知识并随新版本新攻击持续新纲；主流新纲方式是人工分析审计日志中被拒访问事件（论文将其泛化为六元组 access pattern），系统以知识库存已知模式、用三个学习器寻找已知与未知模式间的语义关联：KNN 变体（用满足连接要求的全部邻居而非 top-K 投票）的最近邻分类器、以决策树匹配深度度量新模式与既有规则距离的 pattern-to-rule 度量器，以及基于多步攻击/功能与已知模式共现推断的共现学习器，分类结果经 combiner 合并回知识库迭代学习。（YouTube EP7CZPRpLwr90，[10.4-762.2]，L1）
- 〔USENIX Security（推测）〕EASEAndroid 的评估、策略新纲生成与恶意模式发现。基于 8 节点 Hadoop 集群、130 万条 2014 年真实设备审计日志（去重后 14.5 万访问事件、泛化为 3530 个模式，以 9 个确认 exploit kit 与早期策略起步），六轮迭代最终覆盖约 74% 模式、误报/漏报率约 4%，严格阈值高精确与宽松阈值高覆盖的双模式互补；生成的规则语义与人工规则一致但更细粒度，案例研究为多个系统守护进程访问 timezone 数据文件生成新标签与新 allow 规则；并发现大量 rooting 攻击模式（直写设备节点、改 push 文件属主/setuid、修改系统分区、操纵 cifs/procfs、ptrace 与 kill 特权进程、连 Unix 域套接字攻击守护进程，以及操纵 SELinuxFS 运行时策略状态注入 allow 规则、利用内核漏洞改 cred 换域），表明攻破 SEAndroid 完整性已成为 Android 攻击常见步骤、需同时加固内核；问答涉及 MySQL 到 Hadoop 的工程演进、隐私政策与为何不重造更安全系统的哲学问题。（YouTube EP7CZPRpLwr90，[762.2-1514.0]，L1）
- 〔USENIX Security（推测）〕Windows into the Past——对现代操作系统 Kerberos 实现遗留密码学的端到端攻击。主讲人 Michal Shagam（Tel Aviv University，导师 Eyal Ronen）介绍 Kerberos 被 Linux、Mac 与 Windows 支持并广泛用于大学、医院与政府组织，2006 年起协议扩展支持智能卡双因素认证以摆脱易受字典/钓鱼攻击的密码；但智能卡的 PKINIT 使用易受 Bleichenbacher 攻击（已存在 25 年以上、多次攻破 SSL/TLS）的 RSA 填充方案；在 Kerberos 中寻找预言机困难：无错误报文、连接在 RSA 解密发生前即超时使时间分析失效、解密在智能卡上执行使微架构侧信道难用，于是瞄准 Windows 非常数时间的去填充（unpadding）层用 flush+reload 攻击，虽有反馈但仍嘈杂；实施 Bleichenbacher 百万消息攻击还需可修改密文、海量消息，且攻击只恢复一个 10 小时生命周期的 Kerberos 令牌、必须足够快。（YouTube EP7EKRHgwyXlQ，[8.2-309.5]，L1）
- 〔USENIX Security（推测）〕使 Bleichenbacher 攻击对 Kerberos 实用化的技术路径。引入看似无害的恶意网站在用户一次 PIN 输入后生成所需消息并对 KDC 服务器隐匿；用完美预言机模拟器对 KDC 生成的 4 万条消息测试，相当一部分可在 2 万次查询内解密，只需解密一个令牌即可访问受害者资源；针对非二进制预言机设计定制重复算法降低假阳性，针对快子集（17 次尝试成功 15 次）失败后用第二阶段长连假结果检测假阳性、保存并回溯状态回滚到先前状态，并利用初始搜索与范围约简速度的相关性提前分类快消息、非快消息即中止；三天实验解密 3 条消息，检测与解密均不到 20 小时，最终实现 Windows 端到端冒充攻击——一次 PIN 输入加一个恶意网站，一天内获得完全控制权，代码开源于 Git。（YouTube EP7EKRHgwyXlQ，[309.5-610.7]，L1）
- 〔NSDI〕Slim——用少量操作系统内核支持改进容器覆盖网络。主讲人 Danyang Zhuo（University of Washington 六年级博士生，与 Kaiyuan、Yibo、Hongqiang、Matthew 及导师 Arvind Krishnamurthy 合作）指出容器组网中共享主机 IP、macvlan/SR-IOV 与覆盖网络三种方案各有管理或开销问题，现有方案本质是基于包的网络虚拟化：Open vSwitch 对虚拟网络每个包封装主机头部；微基准显示其吞吐下降、延迟上升，10Gbps TCP 单连接 CPU 利用率提升 93%（经 packet steering 改进后仍约 60%）；根因是每个包都要在容器网络栈、虚拟网卡与 vSwitch 间来回穿过内核长管线，Slim 改用基于连接的虚拟化，由主机上的 Slim router 把虚拟网络连接翻译为主机连接、按连接而非按包支付虚拟化成本。（YouTube EP7FkpQ5QzQEM，[10.9-821.7]，L1）
- 〔NSDI〕Slim 的兼容性设计、真实应用收益与代价。Slim Socket 以动态链接实现 socket 库保持对 POSIX 应用兼容，网络策略因只在建连时见到目的 IP 而移至连接建立时执行 ACL 拒绝，Slim 内核模块跟踪发给容器的文件描述符、对即使绕过动态库直调的 get-own-IP 等不安全系统调用予以拒绝；微基准中 Slim 与直用主机网络吞吐、延迟与 CPU 完全一致（CPU 用量约降 40%），Memcached 相对改进版包级方案吞吐提升 71%、延迟降 42%、综合 CPU 节省约 56%，四类应用（Memcached、Nginx、PostgreSQL、Kafka）介于 10%-56%；代价是连接建立时间延长 106%、包级网络策略支持有限、tcpdump 不可用且不支持数据报套接字；问答涉及与 Istio/代理类工作的关系、每主机 TCP 6.5 万端口上限、与 OVS 的可扩展性对比及容器迁移支持。（YouTube EP7FkpQ5QzQEM，[821.7-1632.5]，L1）
- 〔会议不详〕ZK-SMT——在零知识中证明 SMT 定理的虚拟机。主讲人 Daniel Lueck（与 Yale、Gaia、Boston University、Northwestern 的研究者合作）指出验证工具链（源代码与规范经程序分析工具生成验证条件、SMT 求解器求解出证书、再经 unsat checker 校验）若要向第三方证明专有代码正确性需暴露源代码与证明细节，应用商店验证提交应用安全属性的场景还可能因厂商自研应用引发反垄断担忧；ZK-SMT 使 prover 能向第三方证明公式为假（即无 bug）而不泄露公式与证明细节，支持布尔、未解释函数与线性整数算术理论并可较易扩展新理论；并介绍明文 unsat 证明格式：每步由可从初始公式推导的结论、规则与前提组成，首式为初始假设、末式为 false。（YouTube EP7GnJzGe_LiA，[8.2-334.3]，L1）
- 〔会议不详〕ZK-SMT 的虚拟机设计与评估。难点在于证明步骤中的公式是可任意增长的递归数据类型而零知识无法直接隐藏大小，现成通用 ZK VM（可直接在零知识中执行 LLVM 程序）会错失查找表与针对具体规则的优化；设计把检查证明表类比为程序执行：main checker 充当控制单元逐步加载前提与结论并派发，各规则的子检查器充当 ALU，所有表达式按 AST 节点放入只读内存、以等长指针传递并在需要时解引用从而隐藏大小；基于 EMP-ZK（构建交互式零知识协议的库）实现并在一组 Amazon 机器上评估，通过的最大 SMT-LIB 官方基准证明含 20 万步、约 3 小时（更大出现内存溢出），与通用 ZK VM cheesecloth 相比始终至少快 1000 倍；新增理论只需增加子检查器即可扩展。（YouTube EP7GnJzGe_LiA，[334.3-660.3]，L1）
- 〔USENIX ATC〕智能手机 Android I/O 栈特性分析与 SQLite×ext4 交互剖析。主讲人来自韩国汉阳大学（USENIX ATC 报告，与 Ki Sung、Sung Jin、Sung Bum 及教授合作），指出移动应用性能更多受存储速度而非网络或 CPU 限制；在 Galaxy S3（ICS）上对 Twitter 与 Facebook 的分析显示：SQLite 数据库与 journal 文件占总写请求 90%，元数据与 ext4 journal 块占 40%，同步写占 70%、随机写占 80%、4KB 及以下 I/O 占 64%、eMMC 处理中断占 18%；SQLite 为可靠性每步调用 fsync 而 ext4 也按序日志化，二者叠加导致 journaling of journal——单次 insert 触发两次 fsync、9 次块 I/O，且 ext4 会额外记录 SQLite journal 文件；随后比较四种 SQLite 日志模式（delete/truncate/persist/WAL），WAL 模式（转写作 warm mode）fsync 调用与写操作及总 I/O 量最少、为最佳模式。（YouTube EP7JgQPy4NdiU，[9.8-871.9]，L1）
- 〔USENIX ATC〕五项纯软件优化与端到端评估。针对 write-then-fsync 负载比较文件系统：ext4 journal 开销达 200%、Btrfs 因 COW 与 B+ 树每次写多 5 个 I/O、NILFS2（转写作 NeRFs two）因 128KB 段与频繁 fsync 不适配，XFS 与 F2FS 模式最高效；再辅以 SQLite 用 fdatasync 替代 fsync 减少元数据冲刷、将 journal 存于独立存储的外部日志化以利用 I/O 局部性、修改 mmcqd 驱动以轮询替代中断驱动 I/O 减少上下文切换；Galaxy S3 评估中 WAL 模式在五种文件系统均最佳（ext4 上较 truncate 高 116%、F2FS 较 ext4 基线高 281%），fdatasync 提升 70%、外部日志化提升 20%-39%、轮询在录像场景提升 13%，全部优化叠加在 ext4 上提升 134%、换用 F2FS 达 300%，现场演示默认机 42 TPS 对优化机 174 TPS 的 SQLite insert；问答讨论轮询仅用于写、能耗影响与三星何时移植到生产版本。（YouTube EP7JgQPy4NdiU，[871.9-1734.0]，L1）
- 〔会议不详〕Juntao Ou（University of Wisconsin–Madison）报告分解式存储下与 NVMe 感知 fabric 协同设计的流量控制工作，对存储区域网络的交换式（switched）与无交换（switchless）架构进行对比研究。论文首先给出两大趋势：PCIe 带宽扩展（Dell R7725 已支持 256 条 PCIe Gen5 lane、内部带宽达 1 TB/s）与 EDSFF 紧凑形态（1U 可装 32 块 E1.S 盘，约为 2.5 英寸盘 3 倍密度），使存储节点逐年更快更密。基于对 NVMe over Fabrics 的三项测量观察——网络往返延迟仅占随机读总延迟约 4.8%、顺序写约 12.7%，流量成对且不对称（读命令 64 字节进、数 KB 数据出），SSD 混合读写与碎片化会使队列向后传播填满交换机缓冲（碎片化使带宽降约 26%）——提出 INT 辅助对称路由、预分配响应带宽的 eager 带宽预留与存储驱动的流量调度三条协同设计原则。（YouTube EP7KOhArlWUsQ，[39.6-475.8]，L1）
