- 〔会议不详〕后半场介绍方法与实验结果。核心思想是不仅推理元组还要推理数值，提出统一近似模型（集合近似 + 数值近似）与前向传播分析（set-to-set、set-to-value、value-to-value、value-to-set 四种传播类型），为每个算子赋以语义映射和单调方向符号，沿 AST 从局部变异推导最终结果间的全局变异关系；工作流为生成-变异-验证，含聚合变异器（如 max 换 min）与表达式级数值变异器（如 c1 换 c1±2）。在 SQLite、MariaDB、OceanBase、PolarDB、TiDB 等被广泛测试的 60 个 DBMS 上共发现 67 个唯一逻辑 bug，57 个获开发者确认，含 MySQL 一个严重级别 bug 与 MariaDB 十个 major bug，覆盖子查询、聚合、派生计算、连接、group by/having 等特性；57 个确认 bug 中 48 个在 2020 年前即已存在，最长潜伏 20 年，证明其与现有方法互补。（YouTube EPBBCLtIx59lc，[506.1-1053.9]，L1）
- 〔USENIX Security（推测）〕主讲人 Ben（萨尔大学 CISPA，即信息技术安全、隐私与问责中心博士后）报告 Web 漏洞通知的大规模可行性研究（合作者含 Giancarlo、Christian、Martin、Michael），背景是 Drupal、Joomla 等内容管理系统的严重漏洞曾在数小时内被大规模利用，而社区长于找漏洞、疏于通知受影响方。研究使用两组漏洞：WordPress 中的两个 XSS 与 XML-RPC multicall 缺陷（可单请求暴力破解大量用户名口令组合绕过限速，补丁已存在至少六个月，Alexa Top 百万中约 4.4 万域名受影响），以及作者三年前在 CCS 提出的方法发现的未知客户端/DOM XSS（站点特异、无现成补丁）。通知渠道涵盖直接渠道（联系表单不可扩展，故用 info@/security@/webmaster@/abuse@ 等通用别名与 Whois 注册人/技术联系人）与间接渠道（VRP 不普及，故改用托管商 abuse 联系人及美国 CERT、德国 CERT、FIRST 等可信第三方）；实验把漏洞域名等分为四个通知组与一个控制组，邮件只披露漏洞类型并引导访问详情网站或回信带秘密令牌，对 CERT 发聚合 CSV，分别于 1 月 14 日、28 日与 2 月 11 日发三轮邮件，并以每天一次 PoC（WordPress）、每三小时一次（客户端 XSS）持续监测。（YouTube EPBFI4VsU2YoM，[10.0-560.1]，L1）
- 〔USENIX Security（推测）〕后半场给出效果与关键洞见。WordPress 各组因自然更新控制组也有 22.5% 修复率，通知带来的净修复仅约 280 个域名（Whois 组最佳）；客户端 XSS 控制组仅 2%，可信第三方组最佳（31 个域名，约 17%），结果统计显著但绝对数量很不令人满意。渠道分析显示通用邮箱近 50% 退信、仅 3% 触达，Whois 约 6% 触达且 18% 域名无邮箱；托管商 40% 以上被触达但脆弱域名前五大托管商毫无动作，可信第三方触达率 85%/75% 却很少转发处置；查看报告后有 25-30% 修复率，且提醒邮件显著提升触达。其他洞见包括发件人声誉的作用（约 200 个域名的同批域名经德国 CERT 转达的查看率 60%、直接通知为 0%）与消息形式（WordPress 上含链接邮件反而优于全文披露）。结论称实验结束时约四分之三域名仍存在漏洞，最大瓶颈是触达管理员本身；问答涉及邮件营销式设计、定性访谈与 abuse desk 多渠道误判等。（YouTube EPBFI4VsU2YoM，[566.4-1839.6]，L1）
- 〔FAST（推测）〕存储服务的以缓存为中心的多资源分配（Cache-Centric Multi-resource Allocation for Storage Service）：主讲人 Chen Hao（威斯康星大学麦迪逊分校）提出云存储系统中 Redis 缓存叠加 DynamoDB 等多个计费资源的多租户公平共享问题，均分与 DRF（主导资源公平）都因缓存而失效。核心论断是缓存使吞吐与资源呈非线性关系，且缓存层之下的读/写单元等资源消耗都依赖缓存缺失率，需求向量不再是常量而是被缓存大小参数化，这是全部复杂性的根源。（YouTube EPBGerEz9R02U，[18.2-527.0]，L1）
- 〔FAST（推测）〕Hera 算法与 HyperKB/BanyanFS 两个案例系统：Hera 分为 harvest（在不降低各租户基线吞吐的前提下迭代交换缓存块并把节省的读单元收进池子）与 redistribute（按已有资源占比把池中资源再分配）两阶段，是对 DRF 的完全推广。实现上以 Redis module（DSO 二进制）加 allocator daemon 落地 HyperKB，用 spatially sampled ghost cache 以纳秒级开销估计缺失率曲线，并用 MRC salting 容忍噪声；YCSB 四租户评测显示对基线至少 1.7 倍提升，且可保证任何租户不退化。（YouTube EPBGerEz9R02U，[527.3-1043.4]，L1）
- 〔SREcon（推测）〕Kubernetes 环境下的可靠抓包（一）：平台网络团队的工程师主讲，从“我们觉得可能是网络问题”这一常见场景出发，指出 TCP socket 抽象之下的网络本质是概率性的（无保证延迟、顺序与吞吐），需要包级观测才能定位真因。第一种策略是节点上抓包：先 SSH 到节点，在 eth0 上用 tcpdump（-i、-n、-W 与 BPF host 过滤）排查 CNI/overlay（如 VXLAN）与 Calico/Cilium 网络策略问题；再用 nsenter + crictl 查 PID 进入 Pod 网络命名空间，排查端口占用与 sidecar 明文/加密流量问题，代价是都需要节点 root 权限。（YouTube EPBIPiWnyzi60，[18.2-1013.2]，L1）
- 〔SREcon（推测）〕Kubernetes 环境下的可靠抓包（二）：第二种策略是 ksniff（kubectl 插件，用 kubectl cp 注入静态 tcpdump 二进制并 exec 运行，输出直接管道到本地 Wireshark），虽便捷但官方标注非生产就绪且会改动运行中的容器；第三种也是最推荐的官方方式是 kubectl debug 临时容器，它与应用容器共享网络命名空间但有独立挂载命名空间，配合 netshoot 镜像即可抓包。现场演示排查虚机高延迟：包证据显示 DNS 查询先发往黑洞地址 10.42.42.42、超时 1 秒后才转发到可用服务器，从而把“网络慢”变成可行动的根因；最后展示 eBPF 与 Cilium/Hubble 服务地图可把投机抓包升级为定向抓包。（YouTube EPBIPiWnyzi60，[1015.0-2023.7]，L1）
- 〔NSDI（推测）〕数据中心流量工程中的精度损失问题：主讲人（与 Google、Airbnb 合作者及导师共同完成）介绍 TE 控制环（收集需求、控制器优化、把 TE 解下发到交换机实现，每隔一分钟运行一次），以 Raptor 为例说明 TE 解要求在交换机内存中按端口复制条目来逼近流量分布。核心论断是交换机内存有限导致 group reduction 必须缩小组，从而在 TE 解与 TE 实现之间产生精度损失，并会沿多层级联累积放大；Google 生产网络测量显示链路利用率仅升 10% 尾部流完成时间可上升 40%，实际链路利用率长尾最差可达理想情形的 5 倍。（YouTube EPBKRahdhVL-c，[16.0-501.7]，L1）
- 〔NSDI（推测）〕三种启发式与两个新 group reduction 算法 DMIR/IGR：针对规模、路径多样性、偏斜权重、异构与级联五类根因，提出 group sharing（对归约后相同的组去重复用）、table carving（按流量占比分配空间）与 table pruning（必要时放弃端口保留性质）三种启发式。DMIR 基于混合整数规划、IGR 基于贪心搜索，评测显示两者把最坏情形与理想场景的误差从 table fitting 的 67% 降到 7%，最坏流完成时间从 1.6 倍降到 1.2 倍，总体可降 10 倍精度损失、26% FCT 且快 10 倍；建议追求响应性用 IGR、困难场景用 DMIR。（YouTube EPBKRahdhVL-c，[502.3-1005.3]，L1）
- 〔NSDI〕AdaptSize：主讲人 Daniel（与 CMU 的 Mo、Akamai 的 Ramesh 合作）提出 CDN 服务器热对象缓存（HARC+磁盘）的按大小准入问题：Akamai 服务器对象大小跨约 9 个数量级，固定大小阈值 C 会随早间新闻、晚间视频等流量混合在一天内漂移，概率化准入又引入新的待调参数。核心贡献是 AdaptSize——首个持续自适应准入参数的缓存系统，用马尔可夫链模型直接预测命中率-阈值曲线做全局优化，替代容易陷入局部最优、假设曲线平稳的爬山法，并以线性状态空间近似解决指数爆炸；在 Varnish 中以 doorkeeper 落地，用无锁生产者-消费者模式与并发环形缓冲区收集统计。（YouTube EPBLAaAfluTYM，[10.2-837.4]，L1）
- 〔NSDI〕评测与问答：用 Akamai 生产请求轨迹在数据中心大规模重放，Varnish、Nginx 与 AdaptSize 的对象命中率分别约 30%、40% 与 60%；与 LRU-K、SLRU、2Q、TLFU 等研究系统相比，对次优系统取得 67% 更高命中率。在人为切换流量混合的鲁棒性实验中 AdaptSize 几乎全程贴近离线最优（size-aware opt），而爬山法适应慢且经常卡住。问答中作者补充：命中率提升使磁盘利用率大降、请求延迟整体改善超过 30%（Shanker，AT&T Labs 提问）；驱逐仍用原版 LRU、只考虑准入（NetApp 的 Peter Matsko 提问）；Wikipedia 在约 80GB 缓存上的相对改进与之一致；系统已在 GitHub 开源。（YouTube EPBLAaAfluTYM，[841.7-1685.9]，L1）
- 〔会议不详〕用不精确的流大小信息最小化 FCT：主讲人温心怡（天津大学，与李科奇等天津大学、香港科技大学 Kai Chen、大连理工大学及纽约大学上海分校的合作者共同完成）指出依赖精确流大小（近似 SRPT，如 pFabric）部署困难，而仅凭已发送字节估计的方案又难以从头分离小流。核心论断是随机森林估出的流大小常不精确（三个公开负载中至少 34% 的流与估计值差距超 100KB），但其下界高度可靠：用分位数回归森林构建预测区间后，超过 99.9% 的流可被准确界住，小流实际大小通常贴近下界。（YouTube EPBM2JpR_pJVo，[15.8-498.3]，L1）
- 〔会议不详〕QCram（转写音写）下界调度与交换机外纯主机实现：调度分 Q-climb-up 与 Q-climb-down 两阶段，先按下界映射优先级队列、流未完成则按剩余数据升队、超过下界后按已发送字节逐步降队，从而从传输一开始就优先小流；配合接收端基于优先级的丢失检测与定制 ACK，避免默认 TCP 把乱序当丢包触发重传。原型以 Linux 内核模块实现（交换机只需内置严格优先级队列），8 台服务器经 Barefoot Tofino 交换机 25G 链路测试：对 pFabric 类对端平均/尾部小流 FCT 最多降 88% 与 97%，随机森林推理仅 3 微秒；40G/100G 仿真降 46% 与 62%，对精确信息的 pFabric 平均仅差 5.9% 且丢包少 30%。（YouTube EPBM2JpR_pJVo，[498.6-973.7]，L1）
- 〔NSDI（推测）〕自动推断有状态网络功能模型（一）：以防火墙连接表策略为例，测试与验证工具（VMM、SimNet、Bo 等）都需要有状态 NF 的模型，而手写模型既不准确（模糊测试因手写模型只查 SYN/SYN-ACK、真实防火墙校验三次握手而误报策略违规）又错误地假设各厂商行为同质。主讲人提出给定配置自动推断 NF 的 FSM 行为模型：用组合模型应对多条规则、用抽象掉 IP/端口字段的符号模型应对大取值集合、利用每连接状态相互独立将范围展开为运行时实例化的 FSM 集合（ensemble），并借鉴经典学习理论的 L* 算法做黑盒 FSM 推断，从规则内 IP/端口生成输入字母表、按可达性剪枝并配置超时以分类输出。（YouTube EPBM9YtOWAoEU，[10.6-790.2]，L1）
- 〔NSDI（推测）〕自动推断有状态网络功能模型（二）与评测：先经区分性测试推断状态粒度（跨连接、按源、按目的、按连接等键），再走两阶段工作流——离线每 NF 运行一次生成符号 FSM 与键的数据库，在线按具体配置组合实例化。对 pfSense、某专有防火墙与 untangle 及 HAProxy 等跨 4 厂商评测：iPerf 测试 100% 匹配、随机包测试 99.8%、规则激活测试 95%；发现专有防火墙状态机有 79 个状态（远超手写模型的 2-3 状态）、untangle 默认允许且用 ACK 终止连接、含出窗包的状态机达 200+ 状态、千条规则配置 5 秒内响应。问答中进一步说明以补集式测试方法论验证准确性，并引入配置模式（configuration schema）约束规则类型与字段数据类型。（YouTube EPBM9YtOWAoEU，[791.5-1577.9]，L1）
- 〔会议不详〕密码策略与可用性（一）：LIGO 安全官 Abe 与 LIGO 科学家、计算机安全委员会委员 Warren Anderson 联合主讲。Abe 论证常见密码规则并非标准（最早已知出处是 Windows 2000 默认设置），复杂化、定期修改等要求带来认知负荷与真实经济成本（引用 FAA 可用性研究），反而催生写下来、加尾数递增、共享、保持登录等变通，本质上是让用户做不可能之事；密码老化源于小密钥空间时代，所有 60/90 天期限都是拍脑袋，真正想要的是把破解时间推到超过系统寿命。Warren 则分析 8500 个 MySpace 泄露 8 字符密码：21% 可被 500M 词的 cracklib 字典复现，而基于常见 2-3 字符模式的音位字典（限小写无符号也达 2 万亿组合）覆盖 75%，三阶马尔可夫链构造的 5000 亿字典同样命中 50%——隐藏模式使简单方法就能吃掉额外 30-50%。（YouTube EPBNXOEskChJM，[9.8-1245.1]，L1）
- 〔会议不详〕密码策略与可用性（二）：Warren 用集合论框架总结——攻击者关心的不是规则允许的全空间，而是用户实际选择的密码所聚成的用户字典与攻击字典的交集；人在尝试随机时本质是隐马尔可夫过程，因此密码规则无法强制用户字典高熵，口令短语也因语言习惯（副词跟动词等）不解决问题。政策结论：LIGO 改为系统随机生成、用户从候选中挑选、除非确认泄露否则永不强制更换、允许写在安全处，并配合单点登录；用约 1 万常用英文词组字典按词数与字符数凑熵，各选项等强（xkcd 电池马钉漫画当年抢了他们的先手）。问答中 Dan Klein 质疑马尔可夫链外推，Abe 回应曾用 Google n-gram 构 40 亿词字典做主动密码检查却因可用性灾难而放弃；Chalmers 大学听众佐证用户能快速记住并接受随机密码。（YouTube EPBNXOEskChJM，[1281.6-2627.8]，L1）
