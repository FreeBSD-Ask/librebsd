- 〔SREcon（推测）〕用 eBPF/BCC 监控 JVM：内嵌追踪点、trace 工具与 BPF 原理。主讲人 Sasha 来自以色列培训咨询公司 SELA，先介绍 OpenJDK 内嵌的静态追踪点（用 readelf -n 或 BCC 的 tplist 查看，覆盖 GC、类加载、对象分配、线程启停、锁事件等，Oracle JDK 没有），参数含义需查 JVM 附带的 SystemTap 探针定义文件。随后用 BCC 的 trace 工具演示无侵入排查：过滤 fd=1 追踪 sys_write 到标准输出的内容并打印用户栈，因工具无法解析 Java JIT 符号，需用 perf-map-agent 生成地址到函数名映射文件，之后即可完整解析出产生可疑输出的 Java 应用栈帧；再借 method entry 追踪点（需命令行开关开启）抓到 DataFetcher.fetchData 手动调用 System.gc 的强制 GC 源头。与 perf 相比，BPF 的关键差异是在事件源头（内核）做过滤与聚合：perf 记录每个收包事件产生 19MB/s 的数据、不可持续，而 BPF 用 map 在内核实时聚合并支持有状态程序，只在内核里生成直方图、与用户空间仅共享约百字节结果；代价是 BPF 追踪需要较新内核（追踪点支持 4.7、栈回溯 4.6）。（YouTube EPM54gbffeFhs，[10-1330]，L1）
