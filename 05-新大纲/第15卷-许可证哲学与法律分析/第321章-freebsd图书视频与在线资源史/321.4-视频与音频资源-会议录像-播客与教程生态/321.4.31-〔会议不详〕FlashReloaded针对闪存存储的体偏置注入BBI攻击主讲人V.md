# 321.4.31 〔会议不详〕FlashReloaded针对闪存存储的体偏置注入BBI攻击主讲人V

- 〔会议不详〕Flash Reloaded：针对闪存存储的体偏置注入（BBI）攻击。主讲人 Valentin Huber 介绍其论文。BBI 向芯片衬底注入电压形成局部物理故障路径、扰动局部电源网络，并通过体效应移动特定晶体管的阈值电压；闪存靠浮栅电荷与阈值电压编码数据，擦除/编程需高达 20V 电场，器件内部本就使用 p-well 负偏置（如 -10V）来降低控制栅电压。攻击分两类：针对断电设备的离线方式外部施加偏置模拟闪存操作、造成持久位翻转；针对运行设备的在线方式利用体效应瞬态误读。（YouTube EP0UNB0P8ugT4，[10.6-433.7]，L1）
- 〔会议不详〕离线与在线攻击结果及其利用。自制低成本 BBI 探针可输出最高 320V 双极性脉冲，负脉冲在 STM32 上造成编程式持久位翻转，受影响位与探针 X/Y 坐标相关、损伤限于单个 bank；借此可修改 bank 0 中存储的 readout protection 配置，降级成功率超 80%、最坏平均损伤 27KB。在线方式仅需 DC 电源（两节 9V 电池即可）让整个 bank 读为全 1，启动时读取调试接口配置后移除偏置数据自动恢复，可完全解锁 MSP430 的 JTAG。结论：体偏置注入是嵌入式闪存的现实威胁，安全芯片设计不能假设体电位固定。（YouTube EP0UNB0P8ugT4，[283.6-828.8]，L1）
- 〔FAST（推测）〕SWAN：通过空间分离消除全闪存阵列中的 GC 干扰。主讲人 Qiu Qin 介绍。NVMe SSD 顺序读写达数 GB/s、存储接口带宽增长快于网络，但 SSD 内部垃圾回收仍是性能瓶颈，少数高端 SSD 即可打满节点网络带宽。传统 RAID 的随机写易受 SSD 内部 GC 拖累，log-structured RAID 依赖空闲时间的宿主级 GC，无空闲时吞吐照样波动（8 盘连续两小时随机写下约 1000 秒后 GC 启动、性能起伏）。SWAN 把盘阵在空间上划分为前端（以分段 append-only 顺序写服务用户 I/O）与后端（执行 GC），并维护映射表，实现在宿主的 block 层（plug layer）。（YouTube EP0WJdD8-WbOk，[10.3-517.1]，L1）
- 〔FAST（推测）〕SWAN 评测与 Q&A。对比传统 RAID 与 log-structured RAID：log-structured RAID 在 GC 启动后带宽因用户 I/O 与 GC 干扰下降，SWAN 则在 GC 启动后保持稳定吞吐、达到网络带宽上限；逐盘吞吐显示同一时刻只有一个 backend 参与垃圾回收；YCSB 上读尾延迟同样更平稳。附加收益是可采用小 DRAM、小 overprovision 的低价 SSD 以及块/段级 trim 降本。Q&A 中说明 trim 由宿主下发以触发 SSD 内部 GC，并解释未采用通用 I/O 调度器的原因是需控制所有 SSD、实现过于复杂。（YouTube EP0WJdD8-WbOk，[543.2-1047.2]，L1）
- 〔NSDI（推测）〕FlexTO：面向 CPU 型 SmartNIC 的灵活高性能 TCP 卸载。报告指出即使 TAS、Google Snap 等优化栈，短 RPC 场景下 Memcached 每请求仅 26% CPU 周期用于应用；商用卸载网卡 Chelsio Terminator 面向大流量优化、RPC 场景只留 16% 周期且逻辑硬线化难以适配。FlexTO 消除全部宿主 TCP 栈开销、给应用留出过半 CPU 周期，支持未修改应用的 POSIX socket 兼容，实现 TIMELY 与 DCTCP 数据中心拥塞控制，纯 C 软件实现、升级如重启用户态应用，并支持动态加载 eBPF 扩展（防火墙、VLAN 封装、带过滤的 tcpdump，以及仅 24 行 eBPF 实现的线速 connection splicing）。（YouTube EP0sRLk2zNrdE，[12.7-424.0]，L1）
- 〔NSDI（推测）〕FlexTO 架构、细粒度并行与评测。TCP 处理分为 SmartNIC 数据路径、控制平面与动态链接的 libto 应用库；数据路径分解为细粒度模块的并行流水线，模块可复制、分片甚至并行处理同一连接的段，并以流水线序号缓冲重排乱序传输，负载不缓存在 NIC 内存以支持数千连接。在 Netronome Agilio CX SmartNIC 上原型：Memcached 每请求节省最多 50% CPU 周期、扩展性提升 1.6 倍、延迟分布最窄；细粒度并行设计带来 286 倍吞吐提升与 120 倍尾延迟下降；移植到 Mellanox BlueField 与 x86 后在 RPC 基准上比 TAS 单体方案分别快至多 4 倍与 2.4 倍。代码开源。（YouTube EP0sRLk2zNrdE，[282.6-844.8]，L1）
- 〔会议不详〕Polyscope：从 Android 访问控制策略自动生成攻击操作。主讲人先讲动机：Android 强制 SELinux 后 OEM 因快速跟进 AOSP 变更并大量定制策略而易产生配置错误与漏洞，例如通过符号链接劫持的 link traversal attack。难点在于数据流过多且缺乏区分可信与不可信主体的系统方法；框架先对信息流分诊，以完整性违规（IV，对手可修改潜在受害者将使用的资源）刻画风险流，并提出 per-subject TCB 的最坏/最好情形信任模型——最坏信任必须是最好信任的子集，最好信任基于 Google 的进程特权级别（T5 至 T0）构建，且验证了 Google 与 OEM 策略均符合该假设。（YouTube EP0x5GxGRhDjE，[9.2-363.0]，L1）
- 〔会议不详〕策略弹性、可行性筛选与评测结果。Polyscope 考虑 adversary expansion（对手请求 Bluetooth 等非 signature 权限后获得 net_bt 等 DAC 补充组）与 victim expansion（对手对自己拥有的对象 chmod 向受害者授权），考虑策略弹性后 IV 数量提升 122% 到 1550%；结合部分文件系统不允许符号链接与 FileProvider 等 Java 层防御剔除不可利用的 IV，14%-21% 的 IV 无法落地为任何攻击操作。在多版 Google 与 OEM Android 镜像上应用发现两个漏洞，其中攻击者借 Android 权限获得 DAC 组并以符号链接替换 reset reason.txt 路径，可向加密文件系统写入致设备变砖，已获 CVE 并修复；并行化显著降低分析运行时。（YouTube EP0x5GxGRhDjE，[365.3-723.1]，L1）
- 〔会议不详〕用学习型重排序器（learned ranker）加速规则匹配系统。主讲人来自中国科学技术大学，属其 AI for systems 项目，聚焦 OWASP CRS 与 Snort 入侵检测。规则集以数百条手工规则为主、包含大量昂贵且易引发回溯的正则规则（占 24%-35%，含数千个量词与点号），REDoS 类攻击可把处理延迟从微秒拉到秒级直至超时；现有优化（JIT 编译、filter 预筛、Hyperscan 多模式匹配、FPGA 硬件引擎）只优化单条规则处理。本工作把规则匹配顺序当作可重排问题，在 filter 之后用 ranker 把最可能命中的规则排前实现提前终止且不改变结果；LRU/LFU 启发式在长尾流量可达 90% 以上 top-5 准确率但均匀分布下不足 20%，故 ranker 应提取输入特征而不应假设流量分布。（YouTube EP226ixWBQT7A，[10.3-405.0]，L1）
- 〔会议不详〕模型选择、训练流水线与评测。比较传统机器学习（逻辑回归、SVM 需至少 n-1 个模型、推理开销指数增长）与深度学习（全连接网络与 RNN 均为多分类模型），RNN 准确率最高但推理比全连接慢近 3 倍而 top-5 准确率仅差 2%；训练由生成器（回溯 NFA/DFA 路径构造输入）与变换器（增删替换字符增强覆盖）加训练器构成闭环。评测显示最优全连接模型在 CRS 上需近 400 神经元/层而 Snort 不足 100，logistic regression 因多模型总推理延迟反超神经网络；学习型 ranker 可把需处理的正则规则数减少 90% 以上并显著降低端到端延迟。Q&A 讨论跨规则集训练无法泛化（按分类建模需见过规则）与部署仅需在匹配循环前加两三行代码。（YouTube EP226ixWBQT7A，[405.0-899.9]，L1）
- 〔会议不详〕交易系统可靠性：事故严重度随时间剧变与风险面。主讲人为电子交易（e-trading）行业系统工程师。多数受约束市场只在很窄的时间窗交易，凌晨两点的事故几乎无碍、十二小时后开盘时段则是彻底糟糕的一天；2023 年 12 月 LSEG 磁盘阵列硬件故障虽低于自动切换阈值，仍致市场当日两度停牌并立即见报。交易系统面临财务风险（大额订单价差的小偏差即重创 PnL）、监管风险（全球监管机构迅速审查，可能招致制裁与罚款）与声誉风险；标准韧性手段有多机房、多实例按业务线隔离、双端定期演练与分阶段灰度发布。（YouTube EP2kxrT-dSpk8，[16.1-328.9]，L1）
- 〔会议不详〕潜伏故障形态与架构级缓解。遗留 bug 可能潜伏多年，遇市场数据量激增、异常消息类型或环境变化即触发；Knight Capital 因组件版本互通行为差异，功能开关开启后无控轰炸市场。缓解须落到架构层面：缩小爆炸半径（按用例拆分服务变体而非通用部署同一服务）、核心交易功能与外围模块隔离实现优雅降级、以及用有功能重叠的另一交易系统兜底（须平时持续演练，不能指望临时启用）；金字塔底座的架构修改成本最高、越晚改越难。结论：没有银弹，必须投资架构、设计时预期故障并持续验证。（YouTube EP2kxrT-dSpk8，[202.4-638.6]，L1）
- 〔USENIX Security（推测）〕CacheWarp：基于选择性状态重置的软件故障注入攻击。主讲人为 MPI-SP 博士生 Ray Zhang（转写作 SISPA，存疑） 与 Schutzwerk 安全顾问 Yuheng Lu（与 Lukas、Daniel、Andy、Michael 等联合完成）。CacheWarp 是首个完全突破 AMD SEV-SNP 完整性的攻击，核心是滥用特权指令 INVD（invalidate，刷新缓存但不触发写回）；通过清除 VM 页表 present 位配合 page fault 处理器实现页粒度代码模式识别，用 APIC timer 实现单步执行，并以 WBINVD（写回后失效）保证每次中断前缓存干净、获得可靠单步，再结合选择性 prime+probe 构成精确控制框架。（YouTube EP34qHV9fxO8s，[8.5-444.6]，L1）
- 〔USENIX Security（推测）〕Time Warp：从单指令故障到全链利用。先用 sudo 中初始化为零的特权变量演示最简单的无密码提权，再提出通用原语 Time Warp——在函数写返回地址时执行 INVD，使程序复用过期返回地址实现“时光倒流”，在 SSH 密码登录的哈希比较处等效注入一行代码绕过口令校验。总结称这是首个对 SEV-SNP VM 的全链利用（远程代码执行加权限提升），AMD 已通过固件与微码更新修补，代码开源并附漏洞演示与博客。（YouTube EP34qHV9fxO8s，[444.9-700.8]，L1）
- 〔USENIX Security（推测）〕RIZOM：对 TrustZone 可信 OS 降权的新安全架构。主讲人为葡萄牙米尼奥大学博士生 David（与 Jose Martins 合作，IST 里斯本 Nuno Santos 为共同导师）。回顾 TrustZone 自 2004 年以来的 normal world/secure world 双域架构与 secure monitor 安全上下文切换，指出十余年安全关键漏洞主要源于一个架构缺陷——可信 OS 对全系统拥有不受限的特权，攻击者可从破解 TA 一路攻陷可信 OS、其他 TAs 以至最高特权的 secure monitor；RIZOM 的目标是降权可信 OS，为 normal world 增加保护、让 secure world 承载多个 Trust OS 并保护 secure monitor。（YouTube EP3VPLY7rHfvs，[8.6-362.4]，L1）

- 〔FAST '25（推测）〕VectorCDC：用向量指令加速数据去重中的内容定义分块。主讲人为滑铁卢大学四年级博士生 Sreeharsha Udayashankar（与 Abdelrahman Baba 及导师 Samer Al-Kiswany 合作）。指出 AWS、Google、HP 等云存储依赖去重节省网络与存储成本，而分块计算量大；已有 AVX-512 加速哈希型算法的 SS-CDC 因哈希算法相邻字节依赖、被迫使用昂贵的 scatter/gather 指令，最高仅 1.2-1.8 倍加速；VectorCDC 转而加速无哈希 CDC 家族，吞吐比 SS-CDC 高 21 倍且不损害去重空间节省。（YouTube EP3d2154j7tWk，[16.2-381.1]，L1）
