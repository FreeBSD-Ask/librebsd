# 321.4.9 〔会议不详〕Gevoken由透明资源池GPU资源定制器rendermanager

- 〔会议不详〕Gevoken 由透明资源池、GPU 资源定制器、render manager 与 media engine 四模块组成，无需修改应用或驱动即可让原 Vulkan 光追应用利用云端 GPU/CPU 池。三项关键方法：资源分类的透明转发（将 Vulkan API 分为 context、handle、requirement 三类，前两类可批处理、requirement 型需立即返回以最小化发送耗时）、依赖解耦的并行渲染（跳过云渲染不需要的 present 相关 API，解耦 GPU/CPU 任务使一方恒在工作）、时延决定的自适应负载均衡（按任务量与耗时重算各 GPU 工作量并计入主 GPU 拷贝负载）。评估：较无 API 分类方案 FPS 高 10.3 倍，回传图像 PSNR 高于 30，GPU 间优化效果显著，动态自平衡在算力不均时带来明显提升且稳定单元降低波动；四 GPU 下取得 3.81 倍加速。（YouTube EP-PNOug51HRg，[507.3-1047.6]，L1）

- 〔会议不详〕UMass Lowell 的 Qingjian Ge（与中科院合作者）报告正则表达式拒绝服务（ReDoS）对非回溯（non-backtracking）引擎的攻击：回溯引擎（Python、Perl 等）可回退到先前状态，非回溯引擎基于 DFA/NFA 自动机被认为线性、更安全，且在失败时回退 NFA、再不行回退回溯引擎。讲者证明这些机制皆不安全：DFA 状态复杂度可超线性，回退 NFA 亦不安全；描述性复杂度方面，含计数结构（尤其嵌套计数）的 NFA→DFA 确定化会指数膨胀，而 UTF-8 变长编码（相对 ASCII）会生成更多 DFA 状态。示例输入在 RE2 非回溯引擎上耗时近两秒而 Python 回溯引擎仅 1 毫秒。（YouTube EP-SL7RJAH_CU，[8.1-411.0]，L1）

- 〔会议不详〕讲者报告对 CPU 环形互连（ring interconnect）这一未被利用的微架构侧信道的首次系统研究，分逆向与攻击两部分：以发送/接收双进程（各自钉核并对目标 LLC slice 计时或轰炸）穷举 core/slice 组合实验，归纳出产生争用的条件——流量须同向、路径重叠、位于同一条 lane 且发送方对接收方有优先权。逆向揭示现代 Intel CPU 有四条环（request、data、acknowledge、snoop），LLC 命中仅用其中三条；分布式仲裁可概括为“在环流量恒优先于新流量”（火车车厢比喻：注入须等空车厢）；每环分两条 lane，目的地归属决定走哪条；核与其最近 slice 共享 ring stop，本地流量不越站干扰。（YouTube EP-vDiFeatxdk，[7.8-478.8]，L1）
