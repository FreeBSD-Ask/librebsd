- 〔USENIX ATC（推测）〕整数 GEMM 核与迭代器式内存优化及端到端结果。针对 cuBLAS 等浮点核不支持整数环运算的问题，Piranha 借助 NVIDIA CUTLASS 直接实现 32/64 位整数 GEMM，避免浮点分解方案约 10 倍的乘法开销；面对比较操作等带来的 2-10 倍内存压力，允许协议用迭代器定义对同一数据的就地视图，消除数据搬运与重分配。评测中相对 CPU 上 MP-SPDZ 同一协议实现取得最高 273 倍加速（三方协议、较大维度），VGG 前向内存由约 2.3GB 降至 1.4GB，并以 10 epoch 在 GPU 上用 33 小时完成超过 1 亿参数 VGG 训练（CPU 估需两周），据称是首个在安全计算中端到端训练此类网络的工作。（YouTube EP97DRvViog78，[371.1-711.0]，L1）
- 〔SREcon（推测）〕Amazon DynamoDB 的多租户 NoSQL 架构。DynamoDB 承载 Prime Day 等大规模流量，是全托管、多租户、schema 灵活的键值存储：简单 API（put/get/delete/update/query/scan）带来可预测的个位数毫秒延迟，区域表 SLA 4 个 9、全局表 5 个 9，数据跨 3 个可用区复制。与 Dynamo 的关键区别在于单租户变多租户、偏好一致性、并把路由与存储解耦：put 请求经负载均衡到请求路由器，先经 IAM 认证、查分区元数据并做准入控制，再转发到正确的存储节点，由 leader 用多 Paxos 选举并按 quorum 复制确认写入。（YouTube EP9AkgiEJ_dA4，[13.1-568.5]，L1）
- 〔SREcon（推测）〕DynamoDB 运维三课：准入控制、metastable 故障与 MemDS。早期按读写容量单位（RCU/WCU）均分到各分区并用令牌桶准入，客户为应对尖峰只能过度预配，遂引入最高约 5 分钟配额的突发（rollover）机制，最终把准入控制前移为全局准入控制（GAC），配合精细的分区/副本放置算法让分区可随时突发。2015 年一次大故障源于分区元数据：正常时缓存命中率 99.75%，缓存失效后未命中流量从 0.25% 飙到 100%（400 倍尖峰），形成无法水平扩展自救的 metastable failure；事后自建分布式内存缓存 MemDS，改用 Patricia 树与 Merkle 树混合的 Percol 结构支持 floor/ceiling 查询，并让每个请求即使命中也异步回源以保持恒定负载。结尾补充另外两课：数据持续校验与精心运维工具/纪律（形式化方法、模糊测试、混沌测试等）。（YouTube EP9AkgiEJ_dA4，[596.4-1188.6]，L1）
- 〔FAST（推测）〕Remix：LSM 树上高效范围查询的动机与观察。主讲人 Wen Shaozhong 介绍 LSM 树作为写优化结构的核心地位与两类压缩策略的权衡：tiered 压缩按 run 聚积批量合并、写成本低但 run 多，leveled 压缩每层单 run、读代价低但反复重写。范围查询用最小堆合并迭代器，须对每个 run 二分 seek、每次推进需多次比较，且即便 key 只属一个 run 也必须访问所有重叠 run；两个关键观察是排序视图在 run 不变时保持稳定（却每次查询后即弃）、以及 SSD 使物理排序不再划算、CPU 成为瓶颈。（YouTube EP9F4AzqBp8Ng，[15.8-342.0]，L1）
- 〔FAST（推测）〕Remix 元数据设计与 RemixDB 评测。REmix 用 rank selector 记录排序视图的顺序访问路径，辅以 anchor key 切段和各段 cursor offset，使迭代器初始化只需一次对 anchor key 的二分查找、推进无需任何 key 比较，并能跳过不在访问路径上的 run。在其上构建的单层分区布局、分区内 tiered 压缩的 RemixDB 支持次/主/分裂三类压缩；微基准下 16 个表文件时 seek 最高提速 9.3 倍（扫 50 个 key 约 3 倍），YCSB 评测中加载吞吐比同为 tiered 压缩的 PebblesDB 快约 30%，以范围查询为主的 workload E 相对 leveled 系统最高提速 2 倍。（YouTube EP9F4AzqBp8Ng，[342.4-686.4]，L1）
- 〔会议不详〕O Atomic：文件系统级的失败原子更新接口。主讲人 Ajay（来自印度，代表 HP Labs 与 HP Storage）介绍应用于 HP Advanced File System 的方案，动机是让应用在两个原子同步点之间的任意崩溃后回滚到上一个成功同步点。他逐一评析既有途径：关系数据库与内存结构存在阻抗失配且 OSDI'14 论文显示许多数据库断电后不一致，键值存储缺乏表达力，rename+fsync 写法易埋 bug 且大文件复制慢，Fusion-IO 需专用硬件，Valo/TxF 接口不直观或复杂遇冷，failure-atomic msync 受日志大小限制且只支持 mmap/msync；O Atomic 只需在 open 时传入 atomic 标志，其后所有 sync 系统调用即变原子，并另实现了可对多个文件原子同步的系统调用。（YouTube EP9IFCKKmS7U8，[65.7-425.7]，L1）
- 〔会议不详〕克隆快照实现、崩溃/断电测试与问答。实现上利用可写快照（clone）：以 O Atomic 打开文件时创建克隆，修改走写时复制（原文件指向新块、克隆指向旧块），每次 sync 删除旧克隆并新建，克隆即文件的原子版本，恢复延迟到查找时执行删文件改名克隆，可移植到任何支持可写快照的文件系统。正确性用崩溃点宏测试与外部脚本断电设备验证无损坏，性能与现有键值存储相当，代价是文件系统碎片化（靠在线碎片整理缓解）与多进程更新需应用协调；问答中回答了碎片化评估未做、多进程崩溃检测困难，以及 John Ousterhout（Stanford）问到的 sync 开销与改动数据量而非文件大小相关。（YouTube EP9IFCKKmS7U8，[463.9-896.2]，L1）
- 〔会议不详〕IMIX：硬件强制的进程内内存隔离。TU Darmstadt 与 Intel Research ICS 合作的 IMIX 针对进程内缺乏隔离的问题：攻击者一旦取得读写原语即可破坏代码并攻陷缓解机制的安全区，如 shadow stack 只要一次信息泄露便可改写备份返回地址。作者评述既有原语：内存保护键（MPK）最多 16 个域但每次域切换都要重设权限、不适合高频切换；硬件边界检查（MPX）需大量插桩开销大；随机化存在熵不足问题。IMIX 设计为页粒度、两个隔离域（敏感域与常规域），用特殊 smove 指令编码域权限实现安全访问，无需逐域检查权限，可阻止其他线程和缺指令的遗留库访问敏感数据，并以 shadow stack 为用例展示安全区无法被普通 move 覆写。（YouTube EP9KFId9x3Ybw，[12.6-670.4]，L1）
- 〔会议不详〕实现路径、CPI 用例评测与问答。实现覆盖全流水线：LLVM 中的 smove 加载/存储表示供 pass 与属性使用，页表位标记敏感域并修改 OS 内核支持 mmap/mprotect，在 CPU 核实现 smove 并在 MMU 加入类似 NX 的检查，CPU 部分用 Intel 仿真分析引擎（JIT 仿真器）验证可行性与性能。用例选需高频切换的代码点完整性（CPI）缓解：把原先基于 GS 段寄存器随机化的 safe region 改为 IMIX 隔离并将寄存器偏移改为编译期解析的直接访存，几何平均下与 32 位分段方案几乎持平，优于基于 MemSentry 近似实现的 MPK 及 MPX 方案；问答讨论了依赖 CFI/CPI 防 gadget 滥用 smove、与 HDFI 的硬件量对比，以及 x86 环结构（rings）是否值得纳入评估。（YouTube EP9KFId9x3Ybw，[672.6-1385.3]，L1）
- 〔会议不详〕针对 SQL 结构化加密的泄露滥用攻击框架。主讲人（自述为密码学家）研究端到端加密云托管 SQL 数据库的安全性：客户上传前自行加密，服务端借结构化加密（structured encryption，SSE 的推广）在密文数据结构上处理查询。此类方案的安全性相对泄露档案（leakage profile）证明，但泄露的实际危害长期不明；沿袭十余年的泄露滥用攻击研究，作者在攻击者除泄露外还掌握辅助知识（如往年数据库的分布信息，如医院数据疾病频率）的分布设定下提出 4 种新攻击，其中针对 SQL 选择查询的列相等泄露攻击可推广此前对抗确定性加密的频率分析并直接适用于部分 SSE 方案，另有 3 种针对 SQL 连接查询。（YouTube EP9KwWq_Q9cXg，[11.6-343.7]，L1）
- 〔会议不详〕跨列相等泄露：定义、攻击与实验结果。SQL 等值连接（inner equi-join）中，服务端通过带响应揭示能力的加密 multimap 得到匹配行的指针对，由此泄露跨列相等（cross-column equality）信息——严格强于单独观察两列各自的频率直方图，可表示为对齐直方图。作者给出 3 种用不同算法技术、结合分布信息恢复明文的连接攻击，在芝加哥公开数据（crime、crash、taxi、rideshare 表）上模拟结构化加密 SQL 方案观测连接并统计恢复率：即便在最难的 crime-crash（域很大）场景平均也能恢复超过 15% 的值和行，显著优于仅用单列频率直方图的攻击；论文还给出贝叶斯模型下最优推断的证明、部分最优推断的 NP 难结论及一个集合划分优化算法。（YouTube EP9KwWq_Q9cXg，[362.9-762.3]，L1）
