- 〔OSDI（推测）〕Donghyun Kwon（KAIST，导师 Myoungsoo Jung 领导计算机体系结构与内存系统实验室）介绍 Direct CXL——基于 CXL 直接访问的高性能内存分离。现有内存分离依赖 RDMA，需昂贵的专用 RNIC 与交换机，且微秒级内存访问延迟拖累应用性能；CXL 是基于 PCIe 的开放工业标准缓存一致性互连，按 type 1/2/3 设备分类，团队聚焦 type 3 的 CXL.mem 协议用 load/store 指令直接访问远端内存，实现了 CXL 主机、CXL 内存设备与 CXL 交换机的完整原型，并修改 Linux 内核把 CXL 测试内存暴露给用户态应用，真实硬件原型评估性能较 RDMA 内存分离高约 3 倍。设计上 CPU 发出的 load/store 指令直接转为 CXL flit 包：CXL root port 在缓存缺失时把内存请求转为 flit，设备侧 CXL endpoint 将 flit 还原为内存请求交给内存控制器；单缓存行加载 Direct CXL 比 RDMA 快约 8 倍，且 RDMA 需用户态库额外介入而 CXL 无软件开销，综合性能约 24 倍。（YouTube EPI7wF-TCHGEI，[12.7-363.3]，L1）
- 〔OSDI（推测）〕后半：Direct CXL 交换机、软件栈与演示。可重构交换机基于与 CXL CPU 相同的硬件平台，支持 4 个 CXL 主机与 4 个 CXL 内存设备，crossbar 可经 fabric manager 配置并支持运行时热插拔与热移除；软件运行时分枚举、初始化与使用三阶段——CXL host bridge driver 在 PCI 枚举时发现设备并映射远端内存，CXL memory device driver 加载后暴露字符设备，用户经 ioctl 创建命名空间、mmap 后即可用 load/store 直接访问 CXL 附加内存。演示一使用 Meta DLRM 模型把整个 embedding 表放入远端内存，推理阶段较 RDMA 快 2.8 倍、端到端快 33.3 倍；演示二展示跨主机内存热插拔，将 C、D 主机的 CXL 内存设备分离后附加到主机 A，系统内存从 900MB 升至 49GB。团队总结其为世界首个真实 CXL 2.x 内存分离系统（转写作 CXL version two），软硬件自底向上完整支持并降低直接访问远端内存的成本。（YouTube EPI7wF-TCHGEI，[364.8-729.1]，L1）
- 〔USENIX Security（推测）〕Samsung Knox 研究者（合作者含 Lee Harrison、Michael Grace 及 UC Berkeley 的 Rohan Padhye 与 Kaushik Sinha）介绍通过仿真 TrustZone 支持动态分析的工作（即 PARTEMU）。手机上存在与 Android 并行、负责整机安全的 TrustZone 软件栈：安全世界运行自有 OS 与 TA 应用，仅 TrustZone 可访问硬件密钥且软件需签名才能运行，故无法对 TZ 执行插桩或监控，动态分析严重受限；团队构建可运行 4 个广泛使用的真实 TZOS 的仿真器，经仿真获得完全可控的执行环境。传统把所有固件塞进仿真器的做法不现实（存储控制器等难以仿真），团队改为精选组件子集：将 bootloader 与存储间的紧耦合依赖用执行处理器所期望操作的 stub 仿真掉，从而完全消除对每个存储控制器的仿真需要，并对 TZ OS 依赖的其他组件如法炮制，寻找支持 TZOS 运行的最优组件组合。（YouTube EPI90v8UMhBQs，[8.3-345.6]，L1）
- 〔USENIX Security（推测）〕后半：PARTEMU 实现与大规模 TA 研究。多数仿真工作可用简单模式完成——读返回常量、写返回最后写入值、API 调用返回常量或最后写入值等；硬件仿真实现在 QEMU 内，并基于 PANDA 的模块化框架实现 AFL 模块与 TA 调试模块，真实 TA 与 TZOS 运行于 guest，由小驱动负责读输入、喂给 TA 并检测崩溃。团队从 12 家手机与 IoT 厂商的 16 个固件镜像提取 TA，构建近 200 个唯一 TA 的语料库，用 AFL 经仿真器 fuzzing 崩溃了 48 个 TA；人工分析与逆向归纳出三类崩溃反模式：TA 假设客户端请求序列有序（恶意客户端可发乱序请求导致崩溃甚至可利用）、未校验 normal world 指针（恶意客户端可传共享内存之外任意指针造成完整性与机密性违反）、GlobalPlatform API 参数类型未校验（本应为缓冲区的参数被传值可指向 TA 内存任意位置）。结论：实践上可在仿真器中运行真实 TZOS，且该技术揭示了 TA 开发独有的漏洞模式，需要面向 TA 开发者的专门安全教育。（YouTube EPI90v8UMhBQs，[360.8-664.5]，L1）
- 〔会议不详〕Ding Shan（中关村实验室与清华大学合作工作）介绍面向均衡恢复负载分布的数据放置算法。HDFS、Ceph、GFS 等分布式存储系统把数据切成小块并用副本或纠删码保障可靠性，数据单元到具体存储位置的映射即数据放置（data placement）；节点故障后需在其相关联的全部 placement group 中并行修复，并行可将恢复速度提升至受限于集群带宽而非单节点带宽，但恢复负载在各节点分布不均会造成拥塞并延长恢复时间，也挤占节点带宽影响正常服务。细粒度数据单元加随机化可均衡恢复负载，却大幅提高多故障组合下的数据丢失概率；恢复负载分布高度依赖数据放置，核心问题是如何设计数据放置算法均衡恢复负载。团队以 eij 刻画节点 i 故障时从节点 j 读数据的负载并构建恢复负载图，问题形式化为加入新 placement group 时最小化最大边权，并证明该问题是 NP-hard（最大独立集问题可多项式时间归约）。（YouTube EPI9WrwbNS6pM，[15.8-336.9]，L1）
- 〔会议不详〕后半：贪心数据放置算法、系统扩展与评估。贪心算法先选边权和最小的节点加入当前 placement group，再在数据量不超过最小值一定程度的节点中挑选对当前组其他节点恢复代价和最小者加入，重复直至完成放置；系统扩展时向新节点以受控速度放置数据，随新数据更倾向落在新节点而自然均衡，避免传统复杂迁移破坏正常运行。宏基准实验显示贪心放置给出更均衡的数据与恢复负载分布；扩容测试（存有 500 个 placement group 时加 1 块或同时加 2 块盘）表明扩容初期会出现暂时性恢复负载失衡，同时加多盘更明显且回归更慢，但集成更多放置组后回归正常；该算法显著缩短恢复时间，恢复性能较随机数据分布算法提升 1.7 至 2.4 倍。总结指出最优恢复负载分布问题为 NP-hard，该领域仍可能有更高效算法待发现。（YouTube EPI9WrwbNS6pM，[355.2-618.0]，L1）
- 〔USENIX Security（推测）〕Jiang Ming（得州大学阿灵顿分校，合作者 Dongpeng Xu、Yufei Jiang、Dinghao Wu 来自宾州州立大学）介绍 BinSim——基于系统调用切片段等价检查的树形语义二进制差异分析。二进制分析是安全研究刚需：恶意代码、商用软件与固件常无源码，且计算机执行的是二进制而非源码；二进制 diffing 源于补丁分析，可支撑 1-day 漏洞利用快速生成、软件剽窃检测与恶意软件同源分析（判定同家族、同作者、同漏洞）。最大挑战是普遍的代码混淆（加壳、多态、变形、代码虚拟化）迫使差异分析从语法转向语义层面。现有语义 diffing 分两类：动态类比较运行时行为（系统调用序列、依赖图），可能漏掉条件等价行为（如新版恶意样本仅在触发条件满足时作恶）；语义类基于基本块符号执行建模，因函数边界在混淆下难识别且符号执行开销大而局限于基本块，形成 block-centric 局限——跨基本块边界的相似或差异无法捕捉；循环展开与函数内联、ROP gadget 链、位运算替代实现（如 Hacker's Delight 技巧集）、opaque predicate、控制流平坦化与虚拟化 decode-dispatch 循环都会触发该局限。（YouTube EPIBaqMKuRm74，[11.2-786.3]，L1）
- 〔USENIX Security（推测）〕后半：BinSim 方法、评估与局限。BinSim 混合动态分析与语义建模，核心概念是系统调用切片段（system call slice segment）等价检查：沿控制与数据依赖切出对系统调用参数取值有贡献的指令片段，再以符号执行与约束求解做等价检查，因而既能判定两个匹配的系统调用是否在特定条件下条件等价，又天然绕过基本块边界。流程含五步：动态采集指令轨迹与系统调用序列、系统调用对齐（借鉴生物信息学启发的方法并靠追踪系统调用间控制依赖与参数语义过滤噪声）、动态切片与符号执行、计算到达系统调用参数的最弱前条件；对密码学函数（勒索软件常见）因公式爆炸而终止符号执行、以拼接符号执行加近似匹配处理相似性。评估对比 6 个二进制差异工具（两个工业界、两个 block-centric、两个语义动态方法），BinSim 是唯一能准确区分混淆对与随机对的工具；2017 年 2 月采集的大规模恶意样本分析显示 11% 恶意变体为条件等价（动态方法无法发现），并识别出 CryptoWall 变体在感染机 UI 语言属前苏联国家时终止执行的触发行为。局限是继承动态分析：只能检测执行期间表现出的异同，沙箱敏感恶意软件无法分析。（YouTube EPIBaqMKuRm74，[786.9-1635.0]，L1）
- 〔USENIX Security（推测）〕论文共同作者之一 Mike Enda 介绍如何用 FPGA 位流加密引擎本身攻破 Xilinx 7 系列 FPGA 的位流加密——“Spiderman 打败 Spiderman”。FPGA 经位流（bitstream）编程，位流即 FPGA 固件，经 USB/JTAG 加载或存于外部 flash：攻击者读到位流即可获取全部知识产权与算法，且因 flash 可重写还能植入硬件木马，厂商遂以位流加密应对——AES 解密核置于配置引擎之前实现即时解密，HMAC 保证位流真实性。攻击思路是把从外部 flash 读出的加密位流改写后交回 FPGA 请求解密，把加密引擎当作解密 oracle；配置引擎含约 20 个文档化寄存器，位流以“写寄存器命令加若干数据字”的方式操作，FDRI 命令将 fabric 数据写入 fabric——这正是要窃取的 IP 所在。（YouTube EPIBhOKS9Cdms，[8.3-328.8]，L1）
- 〔USENIX Security（推测）〕后半：两个攻击、根因与对策。机密性攻击利用 CBC 缺陷改写位流，把 FDRI 命令改为写 WBSTAR 寄存器，使解密后的 fabric 数据以明文滞留其中；随后故意让 HMAC 校验失败触发 FPGA 自复位，而文档写明复位脉冲会重置整个配置逻辑、唯独不重置多启动逻辑（含 WBSTAR）——再用读出位流读该寄存器即泄露 32 位明文，重复五步即可逐字泄露整个位流。真实性攻击因 HMAC 密钥存于位流头部的加密部分，用第一个攻击解密后即可伪造有效 HMAC 标签。根因有二：位流命令先解释后验证（use before validation），以及密钥依赖机密性。7 系列芯片内已固化无法打补丁，只有混淆设计或改 PCB 等抬高门槛的对策；新系列采用先验证后使用的全新位流加密引擎。更一般的教训：该漏洞仅靠仔细阅读文档即可发现，应对系统整体做模型检查而非临时安全设计，并依 Kerckhoffs 原则开放社区评审。（YouTube EPIBhOKS9Cdms，[329.4-702.4]，L1）
- 〔HotStorage（推测）〕Umesh Maheshwari（研究大部分完成于 HPE 任职期间）介绍键值设备上小对象的纠删码问题。主机经键值接口以变长对象加应用指定键直接存取 flash 设备，服务器无需大哈希表或 B 树，仅凭 home map（按键范围分区或哈希）定位对象所在设备；目标是为容忍 p 个设备丢失加奇偶校验类纠删码（如 Reed-Solomon，存储放大降为 1+p/d），并能快速恢复损坏对象而不做全盘扫描。大于约 16KB 的对象用简单切分：近等分、算校验、各部分以带序号的后端键存储，沿用原 home map 无需额外映射；小对象若采用 multi-packing（多对象打包成大对象再切分编码）则需服务器内重量级前后端键转换，违背键值设备的初衷。FAST 上提出的 KVMD 采用 unpacking——前端对象原样存入后端，但面临同 stripe 对象大小不一（需缓冲等大对象）与损坏恢复需找到同 stripe 其他键（键空间巨大稀疏，只能存含全部键序列的元数据对象，每个前端键存 siblings、每个 sibling 存 p+1 个 clone）的难题，元数据开销可观：4 数据 2 校验的 stripe 有 12 个元数据对象，对象放大 4.5 倍比副本（3 倍）更差；256 字节对象 16 字节键时字节放大 2.8 倍仅略优于副本。（YouTube EPIDjIaAOHwp8，[8.6-488.3]，L1）
- 〔HotStorage（推测）〕后半：StripeFinder 两项优化与结论。降字节放大：元数据对象无需含全键序列，只需存 stripe 中下一数据对象的键，最小元数据对象称为 finder object，共同构成一个环，给定任意数据键即可找出 stripe 内其他数据键（每个 finder 克隆 p+1 次以抗 p 故障，校验对象键取数据键序列的强哈希而无需显式存储），字节放大从 2.8 降到 1.9；unpacking 相对副本实用的可用性上限从对象/键比 28 降到 8（但 Facebook 研究中该比低于 6，仍不可用）。降对象放大：把若干经随机哈希函数映到同值的 finder 对象合并为一个对象，10 合 1 时对象放大从 4.5 降到 1.8。结论三角：约 16KB 以上对象用切分（高效简单）；小对象 multipacking 需重量级转换不可取；unpacking 元数据开销高，StripeFinder 将其可用范围扩展到 128 字节对象仍有相对副本 25% 的节省，对 Facebook 式极小对象仍只能退回复制；键值设备上小对象的奇偶校验编码是一场 uphill battle，若找不到稳健方案可能削弱键值设备相对 zoned 设备的吸引力。未来方向包括扩展标准化中的键值设备接口以更高效存储 stripe 元数据、设计更优编码、证明元数据量下界，以及质疑前提：若键值分离使小对象数据占比很小，简单性可能比存储效率更重要，副本或已足够。（YouTube EPIDjIaAOHwp8，[499.7-977.9]，L1）
- 〔会议不详〕LinkedIn 工程师介绍用更快的集合覆盖算法加速分布式社交图查询。LinkedIn 的搜索结果、个人主页、How You Are Connected 与公司页面都展示社交距离与共同连接数，三大图 API（getConnections、getSharedConnections、getGraphDistance）中超过 50% 的后端查询是为一组成员 ID 计算图距离。后端为两层系统：graph DB 以邻接表存储 2.25 亿以上成员的连接，按固定分区切分并多副本放置；其前的 network cache service（NCS）用环形哈希存每个成员登录时实时计算的二度连接缓存，把图遍历操作转化为集合交集以降低跨 graph DB 节点延迟；API 层负责路由。扩容时发现扩展性问题：负载均衡使更多 graph DB 节点参与二度查询、各自返回更小的结果集，合并与去重工作从 graph DB 集群转移到 NCS，造成 NCS 性能退化。问题形式化为集合覆盖：给定分区 ID 集合找出能服务该查询的最小 graph DB 节点集——NP 完全问题，标准贪心每轮需与集群中每个节点求交集，机器多时引入固定延迟。（YouTube EPIKJLgSi3nDA，[9.7-733.0]，L1）
