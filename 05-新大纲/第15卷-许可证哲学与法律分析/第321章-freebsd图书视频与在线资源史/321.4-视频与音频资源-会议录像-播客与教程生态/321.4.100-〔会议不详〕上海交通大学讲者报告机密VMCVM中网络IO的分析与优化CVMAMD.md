# 321.4.100 〔会议不详〕上海交通大学讲者报告机密VMCVM中网络IO的分析与优化CVMAMD

- 〔会议不详〕上海交通大学讲者报告机密 VM（CVM）中网络 I/O 的分析与优化。CVM（AMD SEV、模拟 Intel TDX）通过硬件隔离与内存加密保护数据，但在 I/O 密集应用上相比传统 VM 开销可达 30%；作者定义并量化 CVM tax——CPU 花在安全保护与固有网络 I/O 流程上的时间，分为 VM exit tax（由 guest-host 交互频率决定，TDX 类 posted interrupt 可消除）、bounce buffer tax（私有内存需经 bounce buffer 双拷贝，由 I/O 数据大小决定）与 packet processing tax（逐包头解析与封装，由包数决定）三类；以 Memcached 为例 CVM tax 占用超过一半 CPU 时间，其中开销主要来自 VM exit tax 与包处理。（YouTube EPE47Jgd6zXW8，[16.8-563.6]，L1）
- 〔会议不详〕提出以前端 I/O 为主的 Bifrost 设计（取自北欧神话彩虹桥，喻指 CVM 与不可信 hypervisor 间安全快速的 I/O 数据传输），TCB 仅含 CPU 硬件与固件。三项设计：利用"端到端加密或私有内存保护其一即可保数据安全"的观察做 zero-copy encryption/decryption（专用 zc-ed NUMA 节点作共享内存、载荷直接加密到共享内存仅一拷贝），以 one-time patched read（OTTR）只信首次读防御 TOCTOU 攻击，并把重组逻辑从 guest 前端驱动卸载到有冗余 CPU 的后端（pre-receiver packet assembly，PRPR）；原型仅在 guest Linux 加 800 行、后端加 700 行代码，Memcached 等应用基准相比传统 VM 最高提升 21%，应用负载 CPU 占比从 43% 升至 74%，后端 CPU 虽多耗最多 19% 仍未饱和；原型已在 GitHub 开源。（YouTube EPE47Jgd6zXW8，[563.6-1127.2]，L1）
- 〔会议不详〕微软研究院讲者报告 NetKernel——把网络栈从租户 VM 解耦、做成虚拟化基础设施的一部分。现有云双层架构中租户须自行调 TCP 参数（初始拥塞窗口、RTO、延迟 ACK 等）与内核参数、装高级拥塞控制与用户态栈，而拥有专家与资源的运营商对 VM 内网络栈几乎零可见性与控制（难以部署 DCTCP、定义性能 SLA、测量与排障）；NetKernel 将网络栈做成独立模块 NSM，通过 glibc 中新的 socket 类型透明重定向 BSD socket 系统调用（应用零修改），用轻量语义通道 NQE（netkernel queue elements，32 字节）队列传元数据、huge page 传数据，配每核无锁队列与队列引擎（含 VM-NSM 映射连接表以做负载均衡与 SLA）支撑 100 GbE，NSM 以 VM 形态承载、可支持 Linux/Windows/FreeBSD 等不同内核与用户态栈，崩溃重启即可。（YouTube EPE8zGdnnWD1s，[9.0-674.9]，L1）
- 〔会议不详〕在 Linux KVM（双 Xeon、256G 内存、Mellanox 100G 单口 NIC）上的三个用例与评估：多路复用使同一云 trace 只用 9 核（每应用 1 核加 NSM 5 核加队列引擎等）即达原先约 12 核的峰值归一化 RPS；把 mTCP 移植为 NSM 后租户不加修改即可在 Nginx 上使用并在 4 vCPU 场景获约 1.8 倍提升（移植期间还发现了 DPDK Mellanox 驱动的 bug）；VM 间共享内存通信在 8K 消息下性能翻倍以上；宏基准显示吞吐与 RPS 与基线持平（100 Gbps、8 核收 3 核发），RPS 测试中 64 字节请求下 mTCP NSM 在 8 核场景带来近 2 倍提升；讨论指出 netfilter 难以支持、性能排障反而是收益（可用 PingMesh 等由运营商诊断）、攻击面不变，未来方向包括吞吐/RPS 性能隔离、NSM 计费策略与用 FPGA/SoC 实现队列引擎。（YouTube EPE8zGdnnWD1s，[674.9-1205.3]，L1）
