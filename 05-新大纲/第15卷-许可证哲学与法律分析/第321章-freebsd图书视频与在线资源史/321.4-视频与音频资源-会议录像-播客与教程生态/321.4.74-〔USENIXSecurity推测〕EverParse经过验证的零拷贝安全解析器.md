# 321.4.74 〔USENIXSecurity推测〕EverParse经过验证的零拷贝安全解析器

- 〔USENIX Security（推测）〕EverParse：经过验证的零拷贝安全解析器生成。框架以 F* 为验证语言定义经典解析器组合子（monadic bind 构造），每种组合子三层：规格层（做解析安全证明）、函数式实现（证得与规格一致的正确性）与 LowStar 低层实现（额外证明内存安全，可经 KRML 编译器抽取为零拷贝 C 代码）；用户只需在 DSL 中写数据 schema，全自动工具链生成规格与两种实现，规格正确性可靠互操作测试校验——只要在 F* 中验证通过即保证生成的解析器正确、安全。支持整数端序、定长数组、变长列表、struct 与依赖类型的 tag union 等格式，完整写出比特币区块格式并移植全部 TLS 类型到 Project Everest/miTLS：315 个 TLS 数据类型以约 1600 行 DSL 输入生成 7 万行 F*，验证约 45 分钟、抽取约 30 分钟；零拷贝加内联使 Bitcoin Core 解析比其自带反序列化快约 10 倍，该工作还发现 TLS 消息规格（如 heartbeat）中的 bug。结论为首个同时生成零拷贝且安全解析器的工具、自动证明正确性/安全/内存安全、可用于原生应用与标准化（检测格式歧义），全部开源并提供 Docker 镜像；Q&A 确认 2019 年大量高性能零拷贝解析代码未经形式化验证，protobuf/FlatBuffers/CBOR 均不产生安全解析器、不适用于密码学场景。（YouTube EPBuWXR26XhmQ，[608.4-1258.7]，L1）
- 〔EuroSys 2025（推测）〕Wallet：面向机密无服务器计算的 CVM 重构。慕尼黑工业大学系统研究组（TU Munich）提出在不可信云上可信执行 serverless 函数的问题；直接把函数放进机密虚拟机（CVM）并不够——完整 Linux 栈的 TCB 约 500 万行代码、启动约 8 秒、函数合并受硬件加密密钥数量限制、函数间通信因收发两侧 bounce buffer 双拷贝而昂贵。Wallet 借助 CVM 分区（CVM partitioning）与嵌套虚拟化，在最高特权级放最小可信监视器（trusted monitor）、最低特权级放 guest OS，中间是函数运行时与沙箱化函数，实现 4.3 倍 TCB 缩减、78% 内存消耗改善与高达 900 倍的函数合并提升。（YouTube EPBvkTCG025tI，[18-536]，L1）
- 〔EuroSys 2025（推测）〕Wallet 的设计与评估：内部引入两类可信进程——zygote 为含最小 LibOS 与基础运行时的模板镜像，trusslet 为基于 zygote 以写时复制（copy-on-write）fork 出的执行单元；可信监视器独占页表修改权实现隔离，并以共享内存数据对象（发送方只写、接收方只读）实现共置函数间通信。原型扩展 AMD SEV 的 Coconut-SVM 监视器，选用 Gramine 作为最小 LibOS 并捆绑 CPython 运行时；在 1TB 内存的 AMD 机器上对比容器、普通 VM 与 CVM 基线，端到端平均提升 85%–93%，长函数链通信最高提升约 30 倍，且多数页面可在 trusslet 间共享；项目开源。（YouTube EPBvkTCG025tI，[536-1046]，L1）
- 〔会议不详〕OPTI-Fuzz：面向 JavaScript 编译器的保优化模糊测试。主讲人 Jimmy 介绍 JavaScript 引擎中 JIT 编译器实现复杂、含 CSE 与 LICM 等优化，近年漏洞频发且多源于优化被触发时的优化错误；团队分析主流引擎的 JIT 优化提出“优化 pass”（外层循环中通向代码变换点的执行路径）概念，并总结三点观察：进入优化不等于触发优化、触发新优化 pass 的测试用例可能因未覆盖新边而在边覆盖引导模糊测试中丢失、优化路径之间存在测试不均衡。（YouTube EPByp_XmCh_9k，[8-300]，L1）
- 〔会议不详〕OPTI-Fuzz 的方案与评估：为避免优化 pass 中嵌套内循环导致的种子爆炸，提出忽略嵌套内循环的 optimization chunk pass（OPT pass），并配套基于 OPT pass 的种子保存、二级种子队列调度与裁剪策略；模糊测试模块构建于 Fuzzilli 之上。评估选取 4 个 SOTA 方法与 4 个主流 JavaScript 引擎，OPTI-Fuzz 发现 36 个新 bug，其中 26 个经厂商确认并分配 CVE；对比 N2/N4/N8 与 loop pass 等种子策略，OPT pass 策略产生种子最少但发现的 bug 最多。（YouTube EPByp_XmCh_9k，[300-567]，L1）
- 〔USENIX Security 2023（推测）〕Big Mac：面向 Android 固件的安全策略分析框架。Android 攻击面广泛（Stagefright 远程 MMS 漏洞、USB 提权、本地 use-after-free 等），其安全策略由 Linux DAC、Linux capabilities 与 SELinux（SEAndroid）共同构成，散布于文件标签、文件与进程中；Big Mac 直接从固件提取核心文件系统与 DAC/CAP/MAC 标签，结合 SELinux 策略类型图构建主体图、数据流图与进程树，并叠加为完全实例化的攻击图，注入查询引擎生成攻击图以分析进程间提权路径。（YouTube EPC1BgqF1S9nY，[9-350]，L1）
- 〔USENIX Security 2023（推测）〕Big Mac 的评估与案例研究：通过对 Android 启动的部分模拟/仿真（基于 init rc 文件）恢复运行时进程与凭据，仅凭静态固件即恢复超过 98% 的文件、进程恢复准确率超过 75%，可扩展至无法 root 的设备；查询接口以 Prolog 实现，分层路径缩减是关键——在 Samsung S8+（约 130 万节点、200 万边）与 LG G7 镜像上，仅用 MAC 策略时 untrusted app 到 media server 返回超 10.2 万条路径，叠加 DAC 后缩减 20 倍。案例发现 system_server 写强度过高建议像 media server 一样拆分重构，并用 Big Mac 复现 vold 提权（经 zygote 的 ptrace 边），另发现 22 个可达同样提权的起始节点。（YouTube EPC1BgqF1S9nY，[350-685]，L1）
- 〔PoPETs 2023（推测）〕用密码学分析强制解密（compelled decryption）的“既定结论”（foregone conclusion）原则。波士顿大学（Boston University）计算机系五年级博士生 Sarah Scheffler 研究 Court 能否合法强制用户解密自己的设备；背景为 Andrews 诉新泽西州案已申请最高法院复审（被告援引第五修正案拒绝交出密码，否则以藐视法庭论处），下级法院同类判决分歧的核心在于：输入密码这一“作为行为”泄漏的隐含证言是什么。第五修正案的自证其罪特权只覆盖 testimonial 行为，政府可以强制执行隐含证言属于 foregone conclusion（对既有知识增益甚微）的行动。（YouTube EPC3YbCTyt_GY，[9-380]，L1）
- 〔PoPETs 2023（推测）〕foregone conclusion 的密码学仿真定义与 FC resilience。团队把世界拆为“被告心智”与“自然（nature）”：若政府能用除心智内容外的一切构建仿真器，产生与被迫行为计算不可区分的结果，则该行为是 foregone conclusion；在此模型下，密码只在被告心智中时解密通常不可被强制，但在存在辅助信息（他人知道密码或文档内容）时可以被强制。若引入执法特殊访问（law enforcement exceptional access）密钥，此类强制解密将自动成为 foregone conclusion——两个密码战方向叠加对隐私不利。进一步定义协议的 FC resilience（运行协议不新增可被强制的行动），MPC 本身不满足，团队给出基于 garbled circuits 的两方计算构造，对 garbler 仅常数开销。（YouTube EPC3YbCTyt_GY，[380-744]，L1）
- 〔会议不详〕Chisel：广域网上的 5G 光层切片。5G RAN 正从专用硬件转向商用硬件+专有软件的云化架构，但塔到云数据中心之间经过广域网的数据路径缺乏切片保障；在光层（optical layer）做切片相比在分组层做流量工程（traffic engineering）可避免沿途光-电转换与路由器端口占用，实验显示 Chisel 持续消耗少于 3 倍的路由器端口数，且在 Ithaca-Syracuse 之间 24 小时 RTT 实测中光路径不仅更低而且抖动远小于路由路径，端到端性能可预测；论据还包括路由器优先级队列稀缺、排队时延固有等。（YouTube EPC7NVPF5hikY，[16-530]，L1）
- 〔会议不详〕Chisel 的实现：利用 Microsoft 拓扑中约 75% 链路拥有超过 75% 空闲频谱的过 provisioning 余量；每台 5G 设备可产生 10-20 Gbps 负载、数十台设备进出即引发数百 Gbps 需求波动，故需按需快速光切片。将问题形式化为可动态调用的混合整数线性规划（MILP），约束包括只用空闲波长（C 波段约 4800 GHz 分 128 个 37.5 GHz 波长块）、每切片单路径、共享链路用不同波长、跨链路波长一致性；谱位图作为单一变量编码简化了约束。评估显示 150-200 个切片请求可分配超过 90%，Microsoft 网络上约 200 切片 15 秒内收敛（设 5% MIP gap 约 30 秒），目标函数中加入带权重 epsilon 的碎片最小化项可权衡碎片率与分配率；在实验室与纽约州区域 ISP NYSERNet 生产网络上验证，新增/移除波长不影响既有流量的质量因子（Q factor），项目开源。（YouTube EPC7NVPF5hikY，[530-1053]，L1）

- 〔会议不详〕CAVer：针对 C++ bad casting（类型混淆）的运行时检测。主讲人 Pengyong Li 与 Chengyu Song 及两位导师 Taesoo Kim、Wenke Lee 合作，指出经典栈溢出在下降而 use-after-free 持续上升（其前作所治），本工作聚焦新兴攻击向量 bad casting：downcasting 不总是安全，将对象错误下转型在 C++ 标准中属未定义行为并可通过解引用越界成员引发内存破坏、覆盖虚函数表指针劫持控制流；以 Chrome 的 bad casting（用于 2013 年 Pwn2Own）为例，HTMLUnknownElement 仅 96 字节却被下转为 160 字节的 SVGElement，攻击者多出 64 字节越界写能力，且 57 个兄弟类的复杂继承使其极易出错。动态转换（dynamic_cast）在非多态类上会崩溃，因此既有方案（含 UBSan）只能靠黑名单试错排除，难以部署。（YouTube EPC9LOitE97vI，[10-950]，L1）
- 〔会议不详〕CAVer 的设计与评估：编译期生成类型层次表（TH table，类名哈希存储、层次展开避免递归），运行时插桩 trace 函数建立对象到元数据的隐藏内部映射（元数据与对象解耦，多线程用无锁数据结构、堆对象按对齐直接映射、栈与全局对象用 per-thread/per-process 映射），验证时枚举 TH 表检查目标类是否为合法转换目标，并做选择性对象追踪与验证结果缓存优化。基于 LLVM 实现（3000 余行 C++，支持 Linux x86-64，一个编译器开关启用），仅需改动 Chromium 与 Firefox 构建配置 21/10 行即可无黑名单、无运行时崩溃地构建；发现 11 个新漏洞（Firefox 2 例获漏洞赏金、GNU libstdc++ 9 例）全部报告并修复，Chromium 平均开销 7.6%、Firefox 64.6%；作者强调其针对 bad casting 根因、与利用手法无关，可作后端 bug 检测或运行时缓解，并现场用含 CVE-2013 漏洞的 Chromium 演示检测报告。（YouTube EPC9LOitE97vI，[950-1847]，L1）

- 〔SREcon（推测）〕你可能不知道的 NGINX 五件事（下）：nginScript 与 HTTP/2。第五件事是刚发布的 nginScript——NGINX 内运行 JavaScript 的自定义 VM（因 GitHub 上 JavaScript 最流行而选它，且要为服务器环境而非浏览器环境优化），它不是 Lua 的替代品、目前仍是实验性的部分 JS 实现；每个 VM 运行一条注入配置的 snippet 后销毁，阻塞操作时抢占挂起再调度，js_set 设置变量可被其他指令使用、js_run 可执行自定义计算。用例包括故障应急 band-aid（注入 snippet 限制异常请求给修复争取时间）、按 referral 加 cookie 动态限带宽、以及微服务场景将 authentication 等 aspect 从服务提升到服务器层（类 AOP 思路）。HTTP/2 支持已上线（编译时加 --with-http_v2_module，默认未启用、仍处实验阶段，迁移可能影响既有优化模式）；Q&A 中听众提醒对含认证 cookie 的动态内容启用 gzip 存在 BREACH 攻击风险（中间人可从压缩连接恢复 cookie），静态内容无碍。（YouTube EPCALO0Y8kLAE，[900-1668]，L1）
