- 〔NSDI（推测）〕后半：quACK 编码、路径感知拥塞控制与实现。quACK 源于 straggler identification 与 set reconciliation 的代数工作：把缺失报文（在已发集合中而中间盒未收到）表示为幂和多项式方程组，各中间盒维护至多阈值个幂和（阈值为可容忍缺失报文数上界），解码得到 m 个方程 m 个变量精确解出缺失报文，且为累积表示、可抗 quACK 自身丢失。路径感知拥塞控制借鉴 split CUBIC：QUIC 与 TCP 端到端时同用 CUBIC 性能相同，TCP 经 PEP 拆分后有两个拥塞窗口（split CUBIC）故更快；仅用 quACK 重传而照常拥塞响应无收益，忽略丢包则会拥塞崩溃，path-aware CUBIC 在仅一个拥塞窗口下模拟 split TCP 行为，在不超出 TCP 公平性的前提下尽量快。实现全部开源并获社区奖：quACK 库与 sidekick 二进制处理单包约 74 周期、单核 46.4 万包/秒（瓶颈在 NIC 读包），客户端集成含媒体通话与 QUIC/HTTP3（libquic 及 Cloudflare 的 QUIC 实现 quiche），发送端开销约 3%。仿真与真实部署（计算机系楼接入点）均显示抖动缓冲延迟下降、上传吞吐提升且对变化的网络条件更稳健。（YouTube EPIKlsKGbswbA，[477.4-981.1]，L1）
- 〔FAST（推测）〕Anthony Rebello（威斯康星大学麦迪逊分校，合作者 Yuvraj Patel、Ramnatthan Alagappan、Andrea 与 Remzi Arpaci-Dusseau）介绍应用能否从 fsync 失败中恢复的系统研究。写系统调用仅把脏页留在 page cache，fsync 强制脏页落盘并支撑持久性保证（绕过 page cache 用 direct I/O 仍需 fsync 触发设备 flush、也可强制写入顺序），但应用很难用对：某些文件系统创建文件时还须 fsync 目录才能持久化目录项。转引 Fosdem 报告：Postgres 社区发现 Linux 与部分 BSD 的 fsync 可能不按预期工作，多年来对 fsync 失败处理的假设不正确，危及数据持久性与一致性。团队在未改内核下于块层注入故障（自建 device mapper 工具 DM-Loki，可确定性地放行前若干写、失败指定写），针对单块原地更新与多块追加两种负载研究 ext4、XFS 与 Btrfs：三者 fsync 失败后均把脏页标记为干净，重试无效——这正是 Postgres 问题的症结（以为 fsync 成功而截断 WAL）；ext4/XFS 在 RAM 中保留最新内容而 Btrfs 因写时复制回滚旧内容，故失败后不能依赖 page cache 内容；ext4 data 模式错误上报更晚，fsync 先写日志即报成功，日志落块失败仅清空日志并记 syslog，后续 fsync 才能得知、但可能为时已晚（总是补一次第二次 fsync 可更早发现）。（YouTube EPILrZ7TkVP_U，[9.6-590.2]，L1）
- 〔FAST（推测）〕后半：内存态错误、五应用策略与结论。ext4/XFS 失败后不回滚内存元数据：append 场景中偏移到块的链接在卸载或后续写入后会被持久化，产生没有写入内容的 non-overwritten blocks，读取即损坏；Btrfs 整体回滚但继续写入会在更新偏移处留洞，读见零同样损坏。团队进一步研究 5 个广泛使用的应用（3 个嵌入式、2 个服务器，键值存储与关系数据库混合），自建用户态文件系统 CuttleFS 确定性注入 fsync 故障并模拟三种文件系统的失败反应：崩溃重启策略因重启时从 page cache 恢复而产生 false failures（告知用户失败但状态如同成功），重试非幂等操作（如递减）会导致双重执行，主要出现在 ext4 ordered 模式与 XFS 的 WAL 恢复中；ext4 data 模式的假持久感对每个被研究应用都造成数据丢失；Redis 从不检查 fsync 返回码故总是报成功；Btrfs 写时复制对 WAL 恢复友好，但对 SQLite 回滚模式有害——Btrfs 还原回滚日志后 SQLite 以为无可回退而保留新状态（ext4/XFS 下还会从 non-overwritten block 回滚导致损坏）。结论：简单策略皆不奏效、恢复状态勿信 page cache、double fsync 是快速补救；POSIX 对 fsync 失败行为模糊，需标准化文件系统行为（FreeBSD 在 VFS 层重新弄脏页面可借鉴），并应测试文件系统错误处理代码路径。（YouTube EPILrZ7TkVP_U，[592.8-1242.0]，L1）
