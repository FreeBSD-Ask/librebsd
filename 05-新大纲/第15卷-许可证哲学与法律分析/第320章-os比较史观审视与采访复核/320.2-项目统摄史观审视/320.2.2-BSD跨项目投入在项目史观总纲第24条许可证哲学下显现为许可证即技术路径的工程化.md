# 320.2.2 BSD跨项目投入在项目史观总纲第24条许可证哲学下显现为许可证即技术路径的工程化

- **要点**：BSD 跨项目投入在项目史观总纲第 24 条“许可证哲学”下显现为“许可证即技术路径的工程化”。BSD 许可证作为“消极自由”的工程化，使 BSD 代码以“无强制回馈”方式扩散至全球软件基础设施——Varnish 13% 前一万网站采用率、libarchive 进入 macOS/Debian/Homebrew、jemalloc 进入 Meta/Rust、bhyve 进入 illumos、OpenSSH 进入 Linux/Windows/macOS、socket API 进入 POSIX 标准——此“许可证宽松性”是 BSD 跨项目影响的结构性优势。但同一“消极自由”使采用者无强制回馈义务，导致 BSD 阵营的“许可证代价”——OpenBSD 2014 年资金危机、Jails 被 Docker 流行化掩盖、socket API 被称为“POSIX socket”而非“BSD socket”、LibreSSL fork 后未能吸引足够贡献者。GPL 作为“积极自由”的工程化，使 Linux 阵营以强制回馈机制获得生态规模优势，但付出“许可证兼容性代价”——CDDL 与 GPLv2 不兼容阻碍 ZFS/DTrace 进入 Linux 主线。CDDL（Solaris/OpenSolaris）作为第三种许可证，与 BSD 兼容使 ZFS、DTrace 进入 FreeBSD，与 GPLv2 不兼容阻碍其进入 Linux 主线——此“许可证兼容性差异”使 FreeBSD 成为 Solaris 代码的主要开源继承者。商业 Unix 的封闭许可证导致其影响有限，反衬 BSD 许可证在开源生态扩散中的结构性优势。BSD、GPL、CDDL、封闭许可证四种许可证哲学各自塑造了不同的跨项目影响模式，此差异非“优劣之分”而是“主体性呈现差异”。
- **史料**：项目史观总纲第 24 章原文（据原文第 24 章）；BSD 许可证文本（<https://www.freebsd.org/copyright/freebsd-license/>）；GPL v2/v3 文本（<https://www.gnu.org/licenses/>）；CDDL 文本（OpenSolaris，opensolaris.org 已归档）；APSL 2.0 文本（<https://opensource.apple.com/apsl/>）；Torvalds 1998 年 LinuxFocus 访谈（GPL 与 BSD 比较）；ZFS on Linux 的 CDDL-GPL 兼容性争议；FreeBSD 7.0/8.0 release notes（ZFS）；FreeBSD 7.1/9.2/10.0 release notes（DTrace）；bsd_commits.duckdb 查询 L3.2.1（商业实体 commit 统计）；IBM JFS 与 SGI XFS 开源公告（1999 年）。
- **史观**：总纲第 24 条。BSD 跨项目投入的核心即“许可证即技术路径的工程化”——BSD、GPL、CDDL、封闭许可证四种许可证哲学各自塑造了不同的跨项目影响模式。项目史观总纲第 24 章“许可证哲学”在 BSD 跨项目语境中的具体显现即：许可证非“技术中立”而是“技术路径的塑造者”，BSD 的“消极自由”、GPL 的“积极自由”、CDDL 的“兼容性选择性”、封闭许可证的“封闭性”各有其形式主义化的具体显现。
- **辨析**：许可证哲学在 BSD 跨项目投入中是否存在“BSD 许可证优于其他许可证”的层级——此层级判断在 BSD 阵营中隐含存在（BSD 许可证被视为“最自由”），但若“自由”是相对的则不存在“BSD 优于 GPL”的层级，故采信“许可证哲学在 BSD 跨项目投入中不存在层级高低，而存在形式主义化路径差异”的判断。

##### 289.12.6 从总纲第 13 条审视：法律与道德是利益分配

- **要点**：BSD 跨项目投入在项目史观总纲第 13 条“法律与道德是利益分配”下显现为“许可证法律结构即利益分配机制”的工程化。BSD 许可证与 GPL 的法律结构差异本质上是利益分配机制的差异——BSD 许可证的“消极自由”允许采用者无回馈采用（利益流向采用者），GPL 的“积极自由”强制采用者回馈修改（利益回流上游）。BSD 阵营内部亦存在利益分配的不均——bsd_commits.duckdb 查询 L3.2.1 显示商业实体 commit 占比长期低于 1.3% 但绝对值自 2010 年后增长（2015 年 3,391 commits、2020 年 3,820 commits），反映部分商业实体（iXsystems、Delphix、NetApp 等）确有回馈但集中度高，而 Apple、Meta 等大型采用者回馈有限。“回馈不足”的道德批评本质上是利益分配问题——OpenBSD 2014 年资金危机（de Raadt 呼吁支付电费约 2 万加元）是利益分配失衡的极端显现，即 BSD 代码构成全球软件基础设施但 BSD 阵营本身资金匮乏。BSD 社区治理中的“信任即授予”提交者权限模型亦是形式主义的政治产物——核心团队的决议权、portmgr 的 Ports 管理权、基金会的项目优先级决定权，皆是利益分配的制度化呈现。编程之夏的资源分配（Google 资助 vs FreeBSD 基金会执行 vs 导师时间投入）同样是利益分配——Google 获得机构声誉、基金会获得项目产出、导师获得社区地位，而学生的利益获取（津贴、简历增色）与 BSD 阵营的利益获取（长期人才培养）之间存在结构性错位。
- **史料**：项目史观总纲第 25 章总纲第 13 条原文（据原文第 25 章）；BSD 许可证文本（`https://www.freebsd.org/copyright/freebsd-license/`）；GPL v2/v3 文本（`https://www.gnu.org/licenses/`）；openbsd.duckdb 查询 L3.2.1（商业实体 commit 统计）与 L7.2.1（衍生项目贡献者回馈前 10 位）；OpenBSD 基金会 2014 年 1 月资金呼吁（de Raadt 公开呼吁支付电费账单约 2 万加元，后获 Mircea Popescu 约 2 万美元比特币捐赠解困）；trasz@ 2025 年 12 月 30 日退休公开信（freebsd-hackers 邮件列表）；FreeBSD 基金会 Joe Mingrone 2025 编程之夏总结；Torvalds 1998 年 LinuxFocus 访谈（GPL 与 BSD 比较）。
- **史观**：总纲第 13 条。BSD 跨项目投入的核心即“法律与道德是利益分配”——BSD 与 GPL 的许可证差异是利益分配机制的法律形式，“回馈不足”的道德批评本质上是利益分配问题，BSD 社区治理是形式主义的政治产物。项目史观总纲第 13 条在 BSD 跨项目语境中的具体显现即：任何道德问题本质上是利益问题，社区治理亦是形式主义的政治产物，史家须穿透道德叙事揭示背后的利益分配结构。
- **辨析**：考据过程留痕——【查证来源】BSD 许可证文本（freebsd.org/copyright/freebsd-license/）经一手核验“AS IS”条款与“无强制回馈”条款为许可证核心；GPL v2 文本（gnu.org/licenses/old-licenses/gpl-2.0.html）经一手核验第 2 条“分发修改版本须以 GPL 开源”为强制回馈条款；bsd_commits.duckdb 查询 L3.2.1（商业实体 commit 占比长期低于 1.3% 但 2015 年 3,391 commits、2020 年 3,820 commits）经 SQL 查询一手核验；bsd_commits.duckdb 查询 L7.2.1（衍生项目贡献者回馈前 10 位，<behlendorf1@llnl.gov> 2,603 次、iXsystems 329 次、Delphix 229 次）经 SQL 查询一手核验；OpenBSD 基金会 2014 年 1 月资金呼吁经 openbsd-misc 邮件列表存档（marc.info/?l = openbsd-misc&m = 138730448307723）一手核验；Torvalds 1998 年 LinuxFocus 访谈（linuxdoc.org/linuxfocus/English/March1998/article27.html）经一手核验明确表示“GPL 保证回馈”但“GPL 与 BSD 无本质优越性”；【交叉验证方法】BSD 许可证文本（一手法律文本）与 GPL v2 文本（一手法律文本）对照印证“BSD 与 GPL 的法律结构差异本质上是利益分配机制的差异”的判断；bsd_commits.duckdb L3.2.1 量化数据（商业实体 commit 占比低）与 OpenBSD 2014 年资金危机（de Raadt 呼吁电费）双向印证“利益分配失衡的极端显现”的判断；Torvalds 1998 访谈（GPL 创立者陈述）与 BSD 许可证文本（无强制回馈条款）交叉印证“GPL 强制回馈 vs BSD 不强制回馈是利益分配机制差异”的判断；【存疑判定依据】总纲第 13 条的审视存在两种可能的反对意见——第一种为“BSD 阵营的道德呼吁（如 de Raadt 资金呼吁）是超越利益的纯粹道德诉求”，此意见在道德层面成立（de Raadt 的呼吁确有道德维度）但在利益层面不成立（资金呼吁的本质是要求采用者回馈利益），故采信“道德层面反对意见成立，利益层面反对意见不成立”的判断；第二种为“许可证法律结构是技术中立而非利益分配”，此意见在技术层面成立（许可证确是法律工具）但在政治层面不成立（许可证的法律结构直接决定利益流向），故采信“技术层面反对意见成立，政治层面反对意见不成立”的判断；0 信任原则提示：bsd_commits.duckdb L3.2.1 查询基于 12 类商业邮箱域名匹配，企业员工若用个人邮箱提交则不计入，可能低估实际商业贡献；de Raadt 资金呼吁邮件作为当事人陈述存在自利偏差风险（倾向夸大危机严重性），须与 OpenBSD 基金会年报独立核验；本节审视的呈现不偏袒任何一方，BSD 阵营、GPL 阵营、采用者各方在本体论上地位相等，史家不得以“利益分配”为由否定任何一方的主体性呈现。
