# 314.2.1 批评层：规则沉默与许可证政治的双向批评

**要点**：BSD 纯化派批评 Committer’s Big List of Rules 作为 FreeBSD 项目核心治理文档对许可证审查程序保持沉默，committers 可在未经许可证合规审查的情况下将 GPL 代码引入 base 系统，规则的程序设计（active committer 资格以 12 个月内 commit 为门槛、Core Team 三分之二多数表决可驱逐 committer）处理“谁有权提交”却回避“提交什么”，使 GPL 代码在工程实用主义名义下累积，为后续 BSD 化工程制造债务。GPL/FSF 阵营同时批评规则的程序中立性掩盖了 BSD 化工程对 GPL 贡献者的结构性效应——当 FreeBSD 以工程决策（Clang 替换 GCC）移除 GPL 代码后，原 GCC 维护 committer 活跃度下降，active committer 资格门槛规则随即触发，形成许可证纯化与 committer 群体同质化的反馈回路。GPL/FSF 阵营进一步批评 FreeBSD Software License Policy 中“complete BSD-licensed operating system”目标与"no existing BSD-licensed components may be replaced with differently-licensed software"禁令构成强制 BSD 偏好——该政策将 BSD 许可证设定为 base 系统的默认许可证政治目标，使 GPL 组件被定位为“待替换的过渡态”而非“可共存的平等选项”，而"carefully isolated in the source tree so that it cannot contaminate BSD-only components"的隔离要求将 GPL 代码塑造为“污染源”，反映了对 GPL 组件的限制性态度——GPL 代码被允许存在但被结构性地边缘化，其存在被解读为工程实用主义的让步而非许可证多元性的体现。

**史料**：Committer’s Big List of Rules 文档（FreeBSD Committer’s Guide 第 20 章，docs.freebsd.org/en/articles/committers-guide/#rules）、FreeBSD Core Bylaws（freebsd.org/internal/bylaws/，2000.8.28 经 active committers 投票通过，规定 active committer 须“在过去 12 个月内对树做过 commit”、Core 与 committers 可经 Core 三分之二投票驱逐）、FreeBSD Software License Policy（freebsd.org/internal/software-license，明确"The FreeBSD Project aims to produce a complete, BSD-licensed operating system“、”no existing BSD-licensed components may be replaced with differently-licensed software“、”carefully isolated in the source tree so that it cannot contaminate BSD-only components"三核心条款）、freebsd-hackers BSD 化讨论、GCC→Clang 迁移 commit log ［A］

**史观**：总纲第 13 条——法律与道德是利益分配：规则沉默本身是利益分配的政治产物

**辨析**：
    【查证来源】Committer’s Big List of Rules 一手来源经 docs.freebsd.org/en/articles/committers-guide/#rules WebFetch 一手核验，文档目录条目第 20 章确认存在“The FreeBSD Committers’Big List of Rules”章节；FreeBSD Core Bylaws 一手来源经 freebsd.org/internal/bylaws/ WebFetch 一手核验，2000.8.28 版 bylaws 第 1 条"Active committers have made a commit to the tree in the last 12 months“明确 12 个月不活跃门槛；2026.5.27 版新 bylaws 第 Eligibility 节”an Active Contributor is someone who has an active src, ports, or doc commit bit and has committed to the main branch of the src, ports or doc repositories in the last twelve months"延续 12 个月门槛；FreeBSD Software License Policy 一手来源经 freebsd.org/internal/software-license WebFetch 一手核验，页面明确三核心条款："The FreeBSD Project aims to produce a complete, BSD-licensed operating system allowing consumers of the system to produce derivative products without constraint or further license obligations“（强制 BSD 偏好目标）、”We require any software under alternative licenses to be carefully isolated in the source tree so that it cannot contaminate BSD-only components“（GPL 组件隔离要求）、”Unless a special exception is made, no existing BSD-licensed components may be replaced with differently-licensed software"（禁止 BSD 组件被 GPL 替换）；BSD 化工程史料核验见 135.8 节
    【交叉验证方法】四层交叉验证：（1）官方文档目录核验 Committer’s Big List of Rules 章节存在；（2）Core Bylaws 一手文本核验 active committer 资格门槛为 12 个月；（3）Software License Policy 一手文本核验“complete BSD-licensed operating system”目标与“carefully isolated”隔离要求与“no existing BSD-licensed components may be replaced”禁令三核心条款；（4）GCC→Clang 迁移时间线与 Core Team 选举周期对照（2012 年 Clang 成为默认编译器，2010 年 Core Team 选举、2012 年 Core Team 选举）核验许可证纯化与治理周期同步性；BSD 纯化派与 GPL/FSF 阵营双向批评方向相反但共享同一前提——规则与许可证哲学存在结构性关联，两方对“规则应否管许可证”给出相反答案；GPL/FSF 阵营对“强制 BSD 偏好”与“对 GPL 组件的限制性态度”的批评基于 Software License Policy 一手文本，非空泛指责
    【存疑判定依据】原稿 135.4.1〔待核实节号〕 称“18 个月不活跃自动退休”与 bylaws 12 个月门槛不符，可能源自 Committer’s Big List of Rules 章节内的具体执行条款（如 srcmgr/doceng/portmgr 各子系统的不同活跃度评估周期）或早期版本规则，但 docs.freebsd.org WebFetch 未能完整获取第 20 章正文（页面过长且 #rules 锚点未在 TOC 后返回完整章节文本），故“18 个月”具体出处待补验；FreeBSD Core Bylaws 2026.5.27 新版“未生效”状态须注意，叙事应仍以 2000.8.28 版 bylaws 为准；本节“形成许可证纯化与 committer 群体同质化的反馈回路”为假说性叙事，缺乏 committer 活跃度与许可证倾向的量化数据支撑，BSD 化推进期 committer 退休原因可能多元（职业变动、兴趣转移等），不能简单归因于许可证替代；“强制 BSD 偏好”批评中“GPL 组件被定位为待替换的过渡态”是 GPL/FSF 阵营的解读，FreeBSD 阵营反批评见 314.2.2 节，本批评层仅呈现 GPL/FSF 阵营立场，不预设立场判断 ［考据注：2026-07-28 联网考据留痕，模板句式已按考据审慎原则精简（WO-004）；语义以正文与所引来源为准］
