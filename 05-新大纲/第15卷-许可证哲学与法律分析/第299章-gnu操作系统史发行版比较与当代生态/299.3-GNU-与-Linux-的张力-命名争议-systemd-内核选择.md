# 299.3 GNU 与 Linux 的张力——命名争议、systemd、内核选择

#### 要点

GNU/Linux 命名争议是 1990 年代后期至 2026 年自由软件谱系的核心张力之一。Stallman 与 FSF 自 1990 年代后期公开倡导“GNU/Linux”命名，主张“Linux 发行版实质上是 GNU 工具链 + Linux 内核的组合，GNU 贡献应被命名认可”；Stallman 在 *gnu.org/gnu/linux-and-gnu.html* 与 *gnu.org/gnu/gnu-linux-faq.html* 系统阐述 FSF 立场。Linux 阵营（包括 Torvalds、大多数 Linux 发行版、大多数技术媒体）坚持“Linux”命名，主张“Linux 是内核，但‘Linux’在通用语境已指代整个操作系统，命名应遵循通用习惯而非 FSF 主张”。本子节须呈现多方主体性辩证张力——Stallman 立场（GNU 贡献应被认可）、Torvalds/Linux 阵营立场（命名遵循通用习惯）、BSD 阵营立场（“Linux”命名争议是 GNU 内部事务，BSD 不涉及）皆须如实呈现，禁止“Linux 正确”或“GNU/Linux 正确”二元判断。
systemd 争议是 2010-2014 年 GNU/Linux 谱系的核心技术争议。systemd 由 Lennart Poettering（伦纳特·珀特林）（Red Hat）与 Kay Sievers 于 2010 年发起，作为 SysVinit 替代的 init 系统与服务管理器；systemd 2011 年被 Fedora 采用，2014 年被 Debian 采用，2015 年被大多数主流 Linux 发行版采用。systemd 争议的核心是“Unix 哲学”（小工具、文本流、可组合性）vs“现代系统工程”（性能优化、依赖管理、统一 API）——反对者（包括一些 GNU 开发者、BSD 阵营、Unix 传统主义者）认为 systemd 违反 Unix 哲学，支持者认为 systemd 是现代系统必需。2014 年 Debian 技术委员会以 4:4 平票（后主席 Bdale Garbee 投决定票）决定采用 systemd，引发 Debian 社区分裂。
Devuan fork 是 systemd 争议的直接后果。2014 年 Debian 采用 systemd 后，部分 Debian 开发者与用户（以 Jaromil aka Denis Roio 为代表）发起 Devuan GNU+Linux，作为“无 systemd 的 Debian fork”，保留 SysVinit 或提供 OpenRC、runit 等替代。Devuan 2016 年发布 1.0（Jessie），2026 年仍作为小众发行版维护。Devuan 与 Debian 的关系是“fork 但协作”——Devuan 同步 Debian 非 systemd 相关包，仅替换 init 系统与服务管理器。
内核选择争议——GNU 是否应回归 Hurd？部分 GNU 开发者（如 Samuel Thibault）主张继续维护 Hurd 作为 GNU 官方内核，认为“Linux 是 GNU 的偶然内核替代，GNU 应有自主内核”；部分 GNU 开发者与大多数 Linux 阵营主张“Linux 已是 GNU 事实内核，Hurd 无存在必要”；BSD 阵营立场（“GNU 与 BSD 皆应维持自主内核，避免单一内核垄断”）须如实呈现。2026 年 Hurd 仍由少数开发者维护，Debian GNU/Hurd 仍可作为实验性发行版安装，但生产用户数极少。
GNU 与 Linux 张力的多方主体性辩证——Stallman/FSF 立场（GNU 是 Linux 可用性基础，命名与内核选择应认可 GNU）、Torvalds/Linux 阵营立场（Linux 是独立项目，命名遵循通用习惯，内核选择基于实用性）、BSD 阵营立场（GNU/Linux 张力是 GNU 内部事务，BSD 维持自主内核谱系）——皆须如实呈现，禁止“Linux 必胜”或“GNU 必衰”目的论。

#### 史观

本子节史观映射覆盖以下 5 条相关总纲，皆已回溯到 29 章原文核验：

**总纲 1（形式主义是世界的真实存在）**——据原文第 1 章 1.1-1.2 节：GNU/Linux 命名、systemd 架构、内核选择作为三种形式主义化的建构——命名是法律与符号的形式主义、架构是工程的形式主义、内核选择是技术哲学的形式主义——皆是参与者的主体性选择，无“客观最优”的“Linux 发行版本质”。

**总纲 4（分离聚合是永恒规律）**——据原文第 4 章 4.1 节：GNU/Linux 从聚合（1991 Linux 与 GNU 工具链组合）到 systemd 争议的分离（2014 Devuan fork），到内核选择的再分离（Hurd 维护与 Linux 替代）——这一系列分离聚合并非线性进步，而是不同形式主义的循环呈现。

**总纲 5（没有必然性，只有偶然性）**——据原文第 5 章 5.2 节：若 Stallman 未在 1990 年代后期倡导“GNU/Linux”命名，若 Poettering 未在 2010 年发起 systemd，若 Debian 技术委员会 2014 年投票未以主席决定票通过 systemd，GNU 与 Linux 张力史会呈现完全不同的脉络。所谓“systemd 必胜”或“Devuan 必败”的叙事是史家的事后重构。

**总纲 10（动手者创造历史）**——据原文第 14 章 14.1-14.2 节：Stallman 亲自倡导“GNU/Linux”命名，Poettering 亲自开发 systemd，Jaromil 亲自发起 Devuan fork，Thibault 亲自维护 Hurd——这些是动手者的实践，而非“FSF 决定”或“Linux 社区决定”等组织决策的产物。

**总纲 2（历史是形式主义化的非存在）**——据原文第 2 章 2.5 节：所谓“GNU 与 Linux 张力（1990s-2026）”的判定本身即形式主义化的非存在——若以命名争议为主线（1990s-2026），若以 systemd 争议为主线（2010-2014），若以内核选择为主线（1991-2026），“GNU 与 Linux 张力史”会呈现完全不同的脉络。本子节选取“命名 + systemd + 内核”三议题为主线，但这一选取本身须以自反性声明显化。

**自反性声明**：本子节选取“命名争议 + systemd + 内核选择”为 GNU 与 Linux 张力主线，但这一选取本身即形式主义化的非存在。若以 udev 争议为主线，若以 Wayland vs X11 为主线，若以 Glibc vs musl 为主线，“GNU 与 Linux 张力史”会呈现完全不同的脉络。本子节承认主轴选取本身是史家的形式主义化决策，欢迎被更自反的释读所超越。

#### 辨析

**GNU/Linux 命名倡导起始日期辨析**：部分二手资料称“1991 年 Stallman 倡导 GNU/Linux 命名”，但 Stallman 自述在 1990 年代后期才开始公开倡导；1991 年 Linux 发布时 GNU 项目已存在 8 年，但“GNU/Linux”命名倡导是后期建构。本子节采用“1990 年代后期 Stallman 开始公开倡导 GNU/Linux 命名”的限定性表述。

**systemd 与 SysVinit 性能对比辨析**：部分二手资料称“systemd 性能远超 SysVinit”，但准确表述是 systemd 在启动速度与服务依赖管理上优于 SysVinit，但在简单性与可移植性上劣于 SysVinit；systemd 仅适用于 Linux 内核（依赖 cgroups、 namespaces 等 Linux 特有机制），不适用于 BSD 或 Hurd。本子节采用“systemd 在启动速度与依赖管理上优于 SysVinit，在简单性与可移植性上劣于 SysVinit”的区分性表述。

**Devuan 与 Debian 关系辨析**：部分二手资料称“Devuan 是 Debian 的 fork”，但准确表述是 Devuan 是 Debian 的“无 systemd fork”——Devuan 同步 Debian 大部分包，仅替换 init 系统与服务管理器；Devuan 与 Debian 的关系是“fork 但持续同步”，非完全独立。本子节采用“Devuan 是 Debian 的无 systemd fork，持续同步 Debian 非相关包”的限定性表述。

**Hurd 2026 年状态辨析**：部分二手资料称“Hurd 已放弃”，但 Hurd 在 2026 年仍有 Samuel Thibault 等少数开发者维护，Debian GNU/Hurd 仍可作为实验性发行版安装；Hurd 是低活跃度但非完全停止。本子节采用“Hurd 2026 年低活跃度维护，非完全停止”的限定性表述。
