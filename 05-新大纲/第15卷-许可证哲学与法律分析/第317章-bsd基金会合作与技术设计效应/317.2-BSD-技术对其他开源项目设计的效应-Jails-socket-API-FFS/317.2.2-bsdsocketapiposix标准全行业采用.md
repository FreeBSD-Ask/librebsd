# 317.2.2 BSD socket API → POSIX 标准 → 全行业采用

**要点**：BSD socket API 由 CSRG 在 4.2BSD（1983 年 8 月）引入，作为统一网络编程接口，替代早期 UNIX 的多种不兼容网络接口；socket API 设计包括 socket()、bind()、listen()、accept()、connect()、send()、recv() 等系统调用；socket API 后被 POSIX 1003.1g 标准化（1997 年草案，2001 年并入 POSIX 1003.1-2001），成为所有现代操作系统（Linux、Windows Winsock、macOS、Solaris、AIX 等）的标准网络编程接口；BSD socket API 是 BSD 对全行业软件设计影响最深远的技术之一

**史料**：4.2BSD release notes（1983.8）、POSIX 1003.1-2001 标准、Leffler "The Design and Implementation of the 4.3BSD UNIX Operating System"、Windows Winsock 文档、Linux socket(2) 手册页 ［A］

**史观**：总纲第 4 条——分离聚合是永恒规律：socket API 是 BSD 塑造全行业软件设计的典型案例；总纲第 13 条——法律与道德是利益分配：BSD 许可证允许 socket API 进入所有操作系统

**辨析**：本目遵循 0 信任原则，须区分“事实标准”与“正式标准”两个层面——socket API 自 4.2BSD（1983.8）起即成为各 UNIX 实现网络编程的事实接口，而 POSIX 1003.1g 草案（1997）至并入 POSIX 1003.1-2001（2001）的标准化滞后约 14 至 18 年，期间各实现已形成事实标准，故“全行业采用”并非由 POSIX 标准化启动，而是标准化对既有事实的追认；【0 信任原则】“所有现代操作系统采用”的表述须以 Linux socket(2) 手册页、Windows Winsock 文档、macOS/Solaris/AIX 手册页一手核验，不得凭二手转述断言；【存疑判定依据】Windows Winsock 与 BSD socket 的兼容性存在差异（Winsock 非完全 BSD socket 实现），其“采用 socket API”的定性须辨析 API 形状一致性与实现语义差异
