# 318.1.8 Fstack是腾讯基于DPDK的高性能用户态网络框架核心做法是把FreeBSD1

- F-stack 是腾讯基于 DPDK 的高性能用户态网络框架，核心做法是把 FreeBSD 11.1 的 TCP/IP 栈移植到 Linux 用户态；腾讯因权威 DNS 服务器抗 DDoS 需求于 2012 年底改用万兆网卡并引入内核旁路，2013 年发布基于 DPDK 的 DNS 服务器，后为降低自研栈维护成本而选择移植 FreeBSD 网络栈。（BSD Now EP242，[413.70-944.96]，L2）
- iXsystems CEO 在 Forbes 撰文主张开源商业模式的秘密是领导力而非许可证：FreeNAS 与 TrueOS 基于 FreeBSD 并以 BSD 许可证免费分发，用社会契约而非法律契约维系用户，把热情用户变成全球最大的质量保障部门，并强调区分领导力与管理。（BSD Now EP242，[1133.18-1583.44]，L2）
- 节目介绍 FreeBSD Jails：jails 与用户态工具于 2000 年 3 月随 FreeBSD 4.0 出现，与 LXC 类似但作为一等公民集成于基本系统；节目讲解 jail.conf、jexec、jls、thin jails 以及 127.0.0.1 被重写为 jail 首地址所导致的服务暴露陷阱。（BSD Now EP242，[1588.18-2387.32]，L2）
- TrueOS Stable 18.03 发布，采用年.月版本方案，内含针对 Meltdown 的内核页表隔离与针对 Spectre 的缓解，并更新 LibreSSL、Firefox、Chromium 等包。（BSD Now EP242，[58.24-198.04]，L2）
- bsdiff 与 bspatch 是 Colin Percival 2003 年在牛津攻读博士学位期间提出的二进制差分算法，当前实现已演进至 4.3 版。（BSD Now EP171，[1303.36-1644.9]，L2）
- Android 官方开发者博客公布采用 bsdiff 做文件级增量更新，应用更新体积平均缩小 65%、部分缩小超过 90%，每日节省约 6 PB 的应用下载流量。（BSD Now EP171，[1243.48-1529.34]，L2）
- bsdiff 的 BSD 许可代码被 Firefox、Chrome、Chrome OS 与 Android 广泛采用，Colin Percival 观察到如今仅 bsdiff 节省的带宽已相当于他 2003 年写下该算法时的全网流量。（BSD Now EP171，[1556.66-1747.34]，L2）
- 主持人转述 Android 的 libc 部分源自 OpenBSD，并指出 Android 生态使用了相当数量的 BSD 组件。 [存疑脚注] Android Bionic 的 BSD 派生关系须核验一手来源。（BSD Now EP171，[1233.08-1243.48]，L2）
- Ken Thompson 在 1984 年 8 月《Communications of the ACM》第 27 卷第 8 期发表《Reflections on Trusting Trust》，叙述其在 C 编译器中对 login 植入后门，并再植入第二重木马使编译 CC 时自我复制。（BSD Now EP171，[2926.58-3007.3]，L2）
- 该编译器木马使 login 与 CC 的源代码均保持干净，后门仅在二进制层面存在，并随每次自举编译持续传播，源代码审计无法发现。（BSD Now EP171，[3137.62-3360.8]，L2）
- Ken Thompson 表示这类木马的可能性最早见于美国空军对 Multics 早期实现安全性的批评，但他无法找到该具体引用并公开征集线索。 [考据脚注] Thompson 所引 Multics 批评文献待核验。（BSD Now EP171，[3470.46-3493.62]，L2）
- 主持人由编译器信任问题引申出可复现构建的价值：从可信编译器出发重建相同二进制，才能对产物建立有限信任。（BSD Now EP171，[3539.9-3563.62]，L2）
- FreeBSD libc 的 link_ntoa 函数存在约 26 年、可追溯至原始 BSD 的静态缓冲区溢出，特制参数可改写相邻静态缓冲区；HardenedBSD 复核发现补丁对剩余空间的计算方向有误。（BSD Now EP171，[3896.24-3998.72]，L2）
- Ansible playbook 可自动创建 FreeBSD jail 服务器，以 jump jail 作为唯一 SSH 入口，用 iocage 创建各服务 jail，并可在 AWS 或 VirtualBox 上部署，配合 Travis 测试。（BSD Now EP171，[1048.16-1230.52]，L2）
- 在 PC Engines APU2 单板机上运行 OpenBSD 需先以 Tiny Core Linux 刷 BIOS、设串口为 115200 8N1，再以文件系统镜像安装，整套硬件约 200 美元并提供三个网络接口。（BSD Now EP171，[202.0-563.94]，L2）
- core 成员给出 FreeBSD 7 的性能叙事：SMP 工作在 5 分支完成、在 6 分支真正可用、到 7 开始快速扩展，系统开箱即能吃满多核；7 是里程碑，在多项关键基准上定期胜过 Linux，不再是追赶姿态；本次项目还学会制作公众关心的基准图表并向企业与开源出版物传播，与以往赢得性能却不宣传形成对照。（BSDTalk EP152，[298.54-343.10]，L1）
- 性能工作的下一步在用户态：在 FOSDEM 上 BSD 与 PostgreSQL 开发者同室共处一日讨论性能议题，PostgreSQL 开发者对其软件在 FreeBSD 上的表现明显优于其他平台感到惊喜，并看到向 FreeBSD 提交内核改进以进一步提速的机会；内核侧已尽力，数据库等用户态组件的争用处理成为下一个协作面。（BSDTalk EP152，[634.20-679.00]，L1）
- 嵌入式格局转型：嵌入式处理器（ARM、PowerPC、MIPS）走向多核，多年高端计算的 SMP 问题随之进入嵌入式领域，FreeBSD 7 已含 PowerPC 与 ARM 支持（MIPS 未及）；公司消费者以行动回馈——Juniper 交出其自持多年的 MIPS port，一家转写作 Timing Solutions 的公司贡献 ARM 支持；BSDL 不强制回馈，但升级到 6/7 的公司发现回馈共同基础设施可换来更低维护成本、他人代为维护与既已修复的 bug，遂保留产品竞争力部分而回馈其余。（BSDTalk EP152，[343.10-571.32]，L1）
- 桌面易用性是项目自认短板：安装器与管理工具长期被资深开发者忽视，因其工作环境多为大规模部署而非装机；对策包括 Ivan Voras 的图形安装器 finstall（Google Summer of Code 赞助，当年约 20 名受资助学生）、PC-BSD 在桌面方向的推进、Java 问题解决后桌面体验改善；PC-BSD 还迫使项目重新审视高级显卡驱动，项目层面正与 NVIDIA 洽谈以跟上其最新硬件。（BSDTalk EP152，[694.48-940.10]，L1）
- FreeBSD 8 前瞻：Marko Zec 的虚拟网络栈（萨格勒布大学研究项目，曾在 USENIX 年会发表，经 FreeBSD Foundation 与另一机构资助两年更新至 7）计划随 8 发布，本质是大幅增强的 jail——每个 jail 可有自己的防火墙与限速、管理粒度更细；配套 Sun ZFS 的可容器化文件系统、Sam Leffler 的虚拟接入点（单一射频承载多 SSID，面向机场等无线服务商场景）、Ed Schouten 分阶段重写 TTY 层，DTrace 已由 John Birrell 提交部分至 head 并可能回合并至 7.1，SMP 与网络栈扩展性改进亦可从 8 分支合并回 7.1，而网络栈虚拟化因不兼容风险过大不回合并。（BSDTalk EP152，[1103.40-1441.58]，L1）
- Open Connect 设备是装有大容量磁盘的 PC 架构服务器，用于缓存、存储并流式分发影片；Netflix 此前依赖 Level 3 与 Akamai 等第三方内容分发网络，此后将分发全部收回自营，以基于 FreeBSD 9 的 Open Connect 设备实现，受访时该设备已开发近两年并持续扩大部署。（BSDTalk EP226，[160.64-196.22]，L1）
- 选择 FreeBSD 的理由有三：工程师本身的偏好是约两年前启动 Open Connect 设备开发时的关键决策；良好的厂商支持是加分项；对商业友好的 BSD 许可条款更是重大优势。（BSDTalk EP226，[205.36-231.90]，L1）
- 受访时点引用 Sandvine 报告称 Netflix 占北美下行流量约 32-33%（峰值口径），第二名 YouTube 仅为其一半，且受访者称其中大部分流量此刻正由 FreeBSD 承载。 [存疑脚注] 流量份额与 FreeBSD 承载比例为受访者单方陈述，Sandvine 报告本身不含操作系统维度，须以报告原文与 Netflix 官方资料交叉验证。（BSDTalk EP226，[253.36-281.40]，L1）
- 设备具有相当的通用性：服务软件的改动几乎全部回馈社区，用市售 PC 组件即可复现同样性能；仅与云端控制面通信的部分属专有组件，负责影片放置与客户端调度统计。其架构定位是分布式源站而非代理缓存，在填充窗口推入内容、在峰值时段向外服务，操作系统与 web 服务器的性能增强均已交还社区。（BSDTalk EP226，[347.98-396.20]，L1）
- Netflix 期待 FreeBSD 10 的虚拟内存设计改进，使 VM 系统与缓存层更高效，并已着手把其中部分特性回移植到 FreeBSD 9 以提前验证；受访工程师强调公司工程师数量少、无力独自维护整个操作系统，与活跃社区共生是其使用 FreeBSD 的根基，并愿以自身实践为后来企业铺路。（BSDTalk EP226，[405.02-457.14]，L1）
- Netflix 正在把 FreeBSD 推向此前未至的工作区：目标为单机持续 40Gb 流量，且不是仅从内存缓存输出静态内容，而是从磁盘经 CPU 到网络层的全链路持续吞吐，为此对系统各子系统提出全面挑战。（BSDTalk EP226，[471.14-499.66]，L1）

**史观**：

- 总纲15 文化即形式主义：腾讯在 Linux 用户态选择移植 FreeBSD 网络栈而非复用 Linux 网络栈，说明许可证与可维护性等形式化考量塑造了跨系统代码流动的方向。（BSD Now EP242，[829.60-887.44]，L2）
- 总纲11 商品是形式主义：iXsystems 认为软件的价值由领导力与社区关系而非许可证控制决定，商品的价值在此被归结为组织与关系的形式。（BSD Now EP242，[1232.28-1355.92]，L2）
- 总纲4 分离聚合是永恒规律：一小段 BSD 许可代码借由宽松许可证扩散至 Android、Chrome 等生态并产生每日 PB 级影响，代码分离后在全球各系统中重新聚合。（BSD Now EP171，[1556.66-1747.34]，L3）
- 总纲7 理论必须自反：Thompson 的编译器木马揭示信任链无法由代码自身自证，安全体系必须自反地追问“用什么编译器编译编译器”。（BSD Now EP171，[3335.66-3563.62]，L3）
- 总纲10 动手者创造历史：一个 2003 年写下的差分算法由具体动手者提出，并在此后十三年间被全球软件生态复用。（BSD Now EP171，[1303.36-1747.34]，L3）
- 总纲22 知识注定过时：存续 26 年的 libc 缺陷表明既有代码并非永久可靠，历史沉淀的“知识”仍会在后来被发现错误。（BSD Now EP171，[3896.24-3998.72]，L3）
- 总纲15 文化即形式主义：Android 生态大量复用 BSD 代码却少被强调来源，文化传播中借用与命名归属发生偏移。（BSD Now EP171，[1233.08-1747.34]，L3）
- 总纲3 不存在进步，只有权力再分配：core 成员自述治理机制：每两年选举新 core team，候选人向社区陈述立场后全员投票，选举因欧洲假期常拖过夏季，至 2008 年已是约第八届选举产生；其自我定位不在于宣称进步，而在于人事权力的周期性再分配——领导来去，实践与社会模型则须保证项目在更迭中自我延续。（BSDTalk EP152，[1441.58-1515.78]，L1）
- 总纲3 不存在进步，只有权力再分配：Netflix 把分发业务从 Level 3、Akamai 等第三方 CDN 收回自营，并以设备嵌入 ISP 网络的方式直连落地，实质是内容分发基础设施控制权的再分配：权力从专业 CDN 厂商转向内容方与接入网运营商的直接协作。（BSDTalk EP226，[173.28-185.58]，L1）
