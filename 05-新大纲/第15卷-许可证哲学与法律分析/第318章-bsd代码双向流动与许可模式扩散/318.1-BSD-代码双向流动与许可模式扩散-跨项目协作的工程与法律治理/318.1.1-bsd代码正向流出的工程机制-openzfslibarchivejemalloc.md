# 318.1.1 BSD 代码正向流出的工程机制——OpenZFS、libarchive、jemalloc、bhyve 等代码扩散

**要点**：BSD 代码向其他开源项目的正向流出主要通过三种工程机制实现——（1）**基本系统采纳**：libarchive 自 Mac OS X 10.6 Snow Leopard 起作为 bsdtar 的底层库进入 macOS 基本系统，自 Debian/Ubuntu 起作为 bsdtar 软件包进入 Linux 发行版，自 Homebrew 起作为 bottles 打包工具进入 macOS 包管理器；jemalloc 自 2005 年 9 月起作为 FreeBSD libc 默认分配器，后被 Facebook（Meta）、Mozilla Firefox 采用，Rust 早期版本曾以 jemalloc 为默认分配器（后随 Rust 1.28 全局分配器机制稳定化切换为系统分配器，但 jemalloc 仍通过 tikv-jemallocator crate 被大量 Rust 项目主动选用）；（2）**独立项目 fork 与移植**：OpenSSH 由 OpenBSD 项目于 1999 年 9 月从 Björn Grönvall 的 OSSH fork 而来，后以 portable 分支独立维护，进入几乎所有现代操作系统；LibreSSL 由 OpenBSD 项目于 2014 年 4 月 Heartbleed 漏洞后从 OpenSSL fork，后以 portable 版本进入 FreeBSD ports、Gentoo 等；（3）**跨项目代码同步**：OpenZFS 自 2013 年 9 月由 ZFS on Linux 与 illumos ZFS 团队合并成立 “OpenZFS 项目” 后，FreeBSD 的 ZFS 实现与 Linux 的 ZFS on Linux 实现通过共享代码库实现双向同步，FreeBSD ZFS 代码向 Linux 流出，Linux ZFS on Linux 代码向 FreeBSD 回流；bhyve 自 2013 年由 Pluribus Networks 移植到 illumos，2017 年末 Pluribus 将代码贡献给 illumos 社区，2021 年 7 月 Joyent 基于 FreeBSD-11.1 整合至其 illumos 分支并持续改进。BSD 代码正向流出的工程机制体现 BSD 许可证 “允许无回馈采用” 的设计意图——采用者无需贡献代码即可使用，但 BSD 阵营通过基本系统采纳、独立项目 fork、跨项目代码同步三种机制使代码扩散至全球软件基础设施

**史料**：libarchive 官网采用列表（libarchive.github.io，明确列出 macOS、Debian/Ubuntu、Homebrew 等采用方）；jemalloc.net 官网与 Rust RFC 1974 全局分配器机制文档；OpenSSH 官方历史（openssh.org/history.html）；LibreSSL 官网（libressl.org）与 OpenBSD 5.6 release notes（openbsd.org/56.html）；OpenZFS 项目公告（openzfs.org，2013 年 9 月成立）；FreshPorts security/libressl 条目（Port Added: 2014-07-12）；omnios.org/info/bhyve（OmniOS bhyve 历史页）；Joyent Triton “Reintroducing Bhyve”（2021-07-08，joyent.com/blog/reintroducing-bhyve）；FreeBSD src commit 历史 ［A］；openzfs.duckdb 查询 L3.2.1 显示：BSD 全谱系 22 仓库中商业实体（Netflix/Juniper/NetApp/EMC/Google/Apple/Microsoft/Sony/iXsystems 等 12 类邮箱域名）commit 占比随时间变化——2005 年 153 commercial_commits / 267,087 total，2015 年 3,391 / 381,897，2020 年 3,820 / 303,425，反映商业实体 commit 绝对值自 2010 年后增长但占比长期低于 1.3%，与 BSD 许可证 “无强制回馈” 设计意图在数据层面相互印证

**史观**：总纲第 4 条——分离聚合是永恒规律（见 据原文第 4 章 4.1 节）：“UNIX 分裂出各种 BSD，BSD 又分裂出 FreeBSD，这不是技术优劣的较量，而是形式主义的权力运作”——BSD 代码正向流出而回馈有限是 BSD 许可证 “消极自由” 的工程化显现〔订正注：原引文“BSD 又分裂出 FreeBSD 相关记录（详情见存疑库）”系插入污染，按 sacred blocks.4.1 原文删除插入语〕

**辨析**：考据过程留痕——【查证来源】libarchive 官网采用列表（libarchive.github.io）经一手核验明确列出 macOS、Debian/Ubuntu、Homebrew 等采用方；jemalloc 在 Rust 中的默认分配器地位经 Rust RFC 1974 与 Rust 1.28 release notes 核实，2018 年 8 月后默认分配器已切换为系统分配器，但 jemalloc 仍通过 tikv-jemallocator crate 被大量 Rust 项目主动选用；OpenSSH 官方历史经 openssh.org/history.html 一手核验；OpenZFS 项目公告经 openzfs.org 一手核验，2013 年 9 月由 ZFS on Linux 与 illumos ZFS 团队合并成立；bhyve illumos 移植历史经 omnios.org/info/bhyve 与 Joyent Triton “Reintroducing Bhyve”（2021-07-08）一手核验；freebsd.duckdb 查询 L3.2.1 经 SQL 查询一手核验；【交叉验证方法】libarchive 官网采用列表（项目官方记录）与 macOS 10.6 release notes（Apple 官方公告）双向印证 “libarchive 进入 macOS 基本系统” 的事实层面成立；jemalloc.net（项目官方）与 Rust RFC 1974（Rust 官方）双向印证 “jemalloc 在 Rust 中的采用历史” 的事实层面成立；OpenZFS 项目公告（项目官方）与 FreeBSD src commit 历史中 ZFS 代码演化（代码级证据）交叉印证 “OpenZFS 双向同步” 的事实层面成立；【存疑判定依据】BSD 代码正向流出的具体范围与版本对应须逐项目核实——libarchive 在 macOS 中的具体版本与 FreeBSD src/contrib/libarchive 的版本对应须查 Apple 开源 release（**存疑：Apple 开源 release 仅公开部分版本，macOS 内部 libarchive 版本演化无法完整追溯**）；OpenZFS 双向同步的实际代码流量须通过 OpenZFS 仓库 commit 统计量化（**存疑：OpenZFS 仓库 commit 统计须独立查询，本节引用 freebsd.duckdb 仅覆盖 freebsd-src 仓库，不含 openzfs-zfs 仓库**）；0 信任原则提示：freebsd.duckdb L3.2.1 查询基于 12 类商业邮箱域名匹配，企业员工若用个人邮箱（@gmail.com）或 @users.noreply.github.com 提交则不计入 commercial_commits，可能低估实际商业贡献；查询覆盖 22 个仓库包括 BSD 4 大 src 与衍生项目，但 Apple/Sony 等公司在 macOS/PS 内部 fork 中的贡献未公开，无法纳入统计；libarchive 官网采用列表由项目维护，存在自利偏差风险（倾向夸大采用范围），须与 macOS/Debian/Homebrew 各平台独立文档交叉验证
