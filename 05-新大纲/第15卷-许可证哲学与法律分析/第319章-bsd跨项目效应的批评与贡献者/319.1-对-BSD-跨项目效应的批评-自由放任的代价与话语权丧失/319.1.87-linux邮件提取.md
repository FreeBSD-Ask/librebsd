IPv6 自动填充 flow label 补丁讨论中，Tom Herbert 转发并逐点回应 Florent Fourcot 的意见。Florent 认为 flow label manager 早于新 RFC 且对 flow label 实施强策略，因无法知悉使用者及其用法故反对该新行为，禁用 manager 可接受但不应为默认；他另指 auto_flowlabel 命名不佳——若只在隧道上设置 label 则此名不妥，因该名称与 BSD 侧一个 sysctl 完全相同（该 sysctl 为 TCP、UDP 等所有 socket 设置随机 label），而 flow label 世界已够难懂了。Tom Herbert 回应：RFC 定义的是线上协议，不能假设一个站点只用 Linux，"As you pointed out BSD already has this functionality, and we cannot assume any stateful association in received flow labels"，若有人对 flow label 实施强策略（如据此丢弃报文）就会出错；他引 RFC6437 为据，"Any such method MUST NOT disturb nodes taking part in the stateless scenario just described"。他还认为该机制不限于隧道、亦可适用于 transports 并可能免去大量 UDP 封装（如 ESP/UDP），"So it would appear that this is pretty much the same thing as what the BSD implementation does and same sysctl name (a happy coincidence)"，并称"Looks like the default in BSD is on btw"。线程更深层另有一段未标明发言人的原话："By enabling auto_flowlabels, we can have conflict between the flow label manager policy, and a randomly generated label"。
