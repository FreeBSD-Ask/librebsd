Phillip Potter 自述其改写 ufs_set_de_type 的动机源自个人使用经验："I only changed this code in the first place because of the comment in the code - I was looking for things to do basically, and this caught my eye because I play with FreeBSD now and then which of course uses UFS."，即以 FreeBSD 使用 UFS 的实践触发了对 UFS 代码的清理，属 FreeBSD 使用实践驱动 Linux BSD 派生文件系统代码整理。讨论并未转向 Linux 与 FreeBSD 的 ufs 编码差异，而是转向 Linux 内部其他文件系统：Matthew Wilcox 建议至少检查 xfs、ubifs、squashfs、romfs、ocfs2、nilfs2、hfsplus、f2fs、ext4、ext2、exofs、coda、cifs、btrfs；Amir Goldstein 补充自己两年前曾尝试，动机是修 ext2 被复制到其他文件系统中的潜伏 bug，遭 ext4/xfs 维护者反弹（认为 d_type 的 on-disk 取值各文件系统私有），最终合入 xfs 的修法反而是把查表改成 switch。Potter 反问 re-spin 是否仅指修好并保证内核仍可编译。
