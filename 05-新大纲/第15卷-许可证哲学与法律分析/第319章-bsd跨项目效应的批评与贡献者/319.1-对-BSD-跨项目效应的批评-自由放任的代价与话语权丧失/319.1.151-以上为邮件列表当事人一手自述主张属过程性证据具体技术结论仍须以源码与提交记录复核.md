2008年8月 SO_REUSEPORT 是否在内核实现的讨论中，线程里有一方以 BSD 为语义基准给出否定意见：“On Linux, SO_REUSEADDR provide most of what SO_REUSEPORT provides on BSD. In any case, there is absolutely no point in creating multiple TCP listeners. Multiple threads can accept() on the same listener - at the same time.”即主张 Linux 上 SO_REUSEADDR 已提供 BSD SO_REUSEPORT 的大部分能力，多监听端点毫无必要，多个线程可同时并发 accept 同一监听者。Tom Herbert 则反驳这一做法无法解决分布问题：他们已在这样做，但唤醒后仍是听凭调度，最先醒来的线程先处理 accept 队列，偏向于唤醒调用所在的 CPU，因此不能得到跨线程的均匀分布。本封作者 Rick Jones 的回复针对这一反驳：多个 TCP 监听端点并不能改变这个局面——那样反而要听凭内核栈内部的“调度”；若确实要在各线程间均衡，可用一个派发线程（或虚拟派发线程）：每个线程知道自己在服务的连接数，互相通报，若某线程比其它线程多服务 N 个连接，那一次就不进入 accept()，必要时再为“所有其它线程都挂死”这类病态饥饿情形做调整。
