# 319.2.2 被忽视的跨项目贡献

**要点**：BSD 跨项目贡献中存在大量被忽视的贡献——jemalloc 曾被 Rust 作为默认分配器（后随 RFC 1974 全局分配器机制在 Rust 1.28 中稳定化，默认分配器已切换为系统分配器，但 jemalloc 仍通过 tikv-jemallocator crate 被大量 Rust 项目采用）；socket API 进入 POSIX 后 BSD 贡献被“标准化”掩盖；FFS 对 ext2 的设计影响常被忽视；libarchive 被 macOS（bsdtar）、Debian/Ubuntu（bsdtar 包）、Homebrew 等广泛采用，但作为“看不见的基础设施”默默支撑全球归档工具，鲜少被归功于 FreeBSD；这些被忽视的贡献反映 BSD 跨项目影响的“基础设施性”特征——影响越基础越容易被忽视

**史料**：Rust RFC 1183/1974 全局分配器文档、crates.io tikv-jemallocator 统计、POSIX 标准演化、Rémy Card 等 ext2 设计论文、libarchive 官网采用列表 ［A］

**史观**：边缘者贡献：被忽视的跨项目贡献反映 BSD 影响的基础设施性；0 信任原则：被忽视的贡献需通过考据程序验证

**辨析**：每项被忽视的贡献须具体核实——jemalloc 在 Rust 中的默认分配器地位已于 Rust 1.28（2018 年 8 月）随全局分配器机制稳定化而改变，此后默认使用系统分配器，但 jemalloc 仍通过 tikv-jemallocator crate 被大量 Rust 项目主动选用；libarchive 在 macOS/Debian/Homebrew 中的具体版本须查各平台文档；socket API 被“标准化”掩盖的实质须查 POSIX 1003.1g 历年文本中 BSD 贡献的表述变化

**文献**：Rust RFC 1183/1974；crates.io jemalloc 关键词；POSIX 1003.1 标准；Rémy Card 等 ext2 论文；libarchive 官网 ［B］
