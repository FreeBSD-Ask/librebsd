# 319.2.8 当事人补记：从 sys_indirect 线程到 man-pages 版权行的两幕

本节的当事人素材以两封相隔十七年的邮件锚定 BSD 跨项目贡献者边缘化的两条独立但同向的机制——一条走标准议程，一条走文档署名

2008-04-24，Red Hat 的 Ulrich Drepper 在 [PATCH] alternative to sys_indirect, part 1 线程里回应 Alan Cox 关于跨系统统一方案的呼吁——“We shouldn't be seeing this as a Linux problem, its a BSD problem, an AIX problem, a Solaris problem and an HPUX problem and really wants one solution applying across distributions or it will harm everyone in the long term.”——Drepper 给出的答案是“I've proposed them for POSIX and they are going to be in the next revision (O_CLOEXEC, F_DUPFD_CLOEXEC)”，他确信“whatever we'll do will be endorsed this way”，只是因为“It's just too late for the next revision, it'd have to wait a few years until work on the next revision (esp reviews) start. That's too long.”——所以 Linux 先行自定。此邮件的 thread_refs 中同时出现 linux-kernel@vger.kernel.org、netdev@vger.kernel.org、akpm@linux-foundation.org、Linus Torvalds 与 linux-man@vger.kernel.org，收件人是 Alan Cox、抄送 Michael Kerrisk——这是一次 Linux 内核主导者的技术决策场合，BSD 在其中仅以接口名称出现，Drepper 的角色是提出该接口进入 POSIX 的个人提案人，BSD 维护者并未在场发言；这就是第 290.10 节所说的 BSD 贡献者以个人身份进入公共标准议程的场景，跨项目贡献者在其中既非 BSD 官方代表，也非 Linux 上游维护者，而是两者交界处的规范搬运工

十七年后，2025-05-05，Alejandro Colomar 在 man-pages 邮件列表的 "Removing in-source contribution records contributer" 线程中说明“I've moved all contribution credits to a new CREDITS file, and changed all copyright notices to claim Copyright, The contributors to the Linux man-pages project”，并明确“I've kept only a few copyright notices, which are not from contributors of this project, but from projects from which we've imported pages”；他随邮件附上 grep 统计：全库 1359 页统一为“Copyright, The contributors to the Linux man-pages project”，保留下来的外部版权行中 BSD 相关有 1980-1991 共 5 行、1980-1993 共 1 行、1983-1987 共 1 行、1983-1991 共 13 行、1986 共 1 行、1987-1993 共 1 行、1989-1994 共 1 行、1990-1991 共 1 行、1991-1992 共 1 行、1992-1994 共 1 行、1993 共 8 行、1983 共 2 行、1983-1993 共 2 行、1989-1993 共 2 行、1991 共 2 行、1990-1993 共 5 行——BSD Regents 版权行的年份跨度从 1980-1991 一直到 1989-1994，完整覆盖了 CSRG 时代到 4.x BSD 时代的移植页面，合计 81 行

1359 比 81 说明 man-pages 项目绝大多数页面由 Linux 社区自主编写与修改，BSD 来源的移植页面是少数；而 Colomar 移除了个人贡献者署名、却保留了 BSD 版权行，说明 BSD 在此处是以“来源项目”身份保留，而非作为“贡献者”被列名——这与第 319.2.6 节所说的“BSD 在 Linux 语境中的‘来源’身份是可被 grep 到的历史痕迹，而非等价的署名权”构成同向印证，且从数字上给出量级：1359 页项目里 BSD 保留行数在 81 行以内

两处证据合在一起呈现出第 290.10.7 与 319.2.6 节所提炼的悖论的完整证据链——Drepper 以个人身份把 BSD 接口推进 POSIX 议程，署名是 Drepper 而非 FreeBSD；Colomar 保留了 BSD 的版权行，却没有把 BSD 记为 man-pages 贡献者；BSD 的语义被持续吸纳，BSD 的版权被历史性地保留，但 BSD 的贡献者主体在两种证据中都未获得等比例的署名回报。从 2008 年 Drepper 的线程到 2025 年 Colomar 的整理，十七年间 BSD 在 Linux 语境中的位置始终是“来源”而非“主体”，技术吸纳持续，署名回报稀少——正是第 319.2 节所说的 BSD 跨项目贡献者边缘化的历史结构的两处具象锚点
