# 316.1.9 Perlstein对FreeBSD上手体验提出一组可检验的批评pkginstal

- Perlstein 对 FreeBSD 上手体验提出一组可检验的批评：pkg install Django 直接报无包，而真实包名是 py27-django 这类带版本前缀的命名；学会 Subversion 与 Phabricator 的技能难以外溢到 Git/GitHub 主流生态；仓库过大令新手克隆即卡壳。他主张举办“反向安装马拉松”——不给新手帮助，只记录他们在何处卡住——甚至公开抛出为项目改名的争议建议（3051.12-3136.92），理由是连大会讲者与他的母亲都念错 FreeBSD。这些均为当事人单一来源立场，尚待社区实践检验。（BSD Now EP142，[2344.3-3152.0]，L1）[订正：原 [2686.14-2922.74]，2026-09-30 SenseAudio 重转核对]
- NetBSD 引入 NVMe 支持取 OpenBSD 代码而非 FreeBSD 实现，后者系 Intel 直接贡献；主持人归因于 OpenBSD 本为 NetBSD 的 fork、设备模型与内核更接近故移植 diff 更小，并以同一 NVMe 设备在传统盘模拟接口下五六百兆与 NVMe 模式读 3800 兆、写 1700 兆每秒的性能差，及协议允许 64 路并发而其中一路保留给管理用途的队列细节佐证技术跃迁。 [存疑脚注]移植路径归因为主持人单源推断（原话以 I imagine 引导），未见 NetBSD 移植者自述佐证；性能数字为主持人借测试集群设备的一手自述（BSD Now EP141，[3600.8-3640.4]，L4）[订正：原 [3607.47-3631.34] 并 65536/63 并发表述，2026-09-30 SenseAudio 重转核对]
- Tarsnap 1.0.36 修复 libarchive 一字节堆溢出（字符串 null 终止符计数错误）后，Colin Percival 的悬赏对象不是找新漏洞而是利用已知漏洞——2015 年底前第一位可信演示严重利用者获 1000 美元，Starfighter 创始人随即加倍至 2000 美元；这种把 bounty 从发现转向利用路径确认的做法，将“可利用性尚不确证”公开化并以经济激励求解，显示加密备份服务商对数据安全的自我施压式治理，与常规漏洞悬赏形成方法论差异。 [存疑脚注] 转写将 Thomas Ptacek 记为 Thomas Patak，demonology.net 与 Starfighter 拼写语义可辨但待核；悬赏金额与截止年份据主持人转述，未见原文直接核验（BSD Now EP104，[3999.24-4129.92]，L2）
- FreeBSD 10.2 的变更组合指向发行策略转向：新装系统默认采用季度二进制包集，以放弃滚动更新换取主版本稳定与纯安全补丁；Linux 兼容层基座由 Fedora Core 换为 CentOS 6（64 位支持未及赶上）；growfs 随 first boot 脚本默认化，使 SD 卡与虚拟机镜像首启自动扩容。讲解者兼具 PC-BSD 相关项目当事人身份，将其解读为面向 Linux 背景迁移者与服务器用户的可用性经营，而非单纯的技术升级。（BSD Now EP104，[452.92-560.22]，L2）
- iXsystems 数年试水官方 PC-BSD/FreeBSD 笔记本失败的结构性原因由当事人自述：厂商不承诺特定型号的生产一致性，除非万台起订；压货仓储成本高企而笔记本约五个月即过时；零部件随机替换（如 Wi-Fi 芯片）即足以摧毁兼容性认证。实测兼容良好的 Lenovo 老款（X230/T430/T530）只是无承诺的经验值，Broadwell 世代的 X1 Carbon 仍有障碍，尚在众筹的开放硬件笔记本被视作可能的替代路径，“官方笔记本”因此悬置于市场结构之外。（BSD Now EP104，[4550.56-4735.40]，L1）
- LibreSSL 与 OpenSSL 的安全对比数字存在口径风险：Spil 自报其个人汇总的公告计数为 OpenSSL 三十五项对 LibreSSL 十九项（2676.30-2680.38）并已载入 Wikipedia（2654.60-2661.94）；其将 LibreSSL 随机数问题评 medium 遭 Bob Beck 异议，Spil 亦自陈为免显得偏袒 LibreSSL 而将 OpenSSL 同类问题同降为 low（2714.42-2741.42）——评级带有人为对称校准，两组数字只宜作叙事线索而非两库安全性的计量结论。 [存疑脚注] 计数（35/19）与涉事版本号均出自转写且系当事人单方汇总，转写处 210 or 211、212 0 0 等存在明显语音失真，须以官方公告与 bug 追踪原件复核后方可引用（BSD Now EP82，[2676.30-2744.68]，L1）
- Pipecut 与 UNIX 哲学的紧张在演讲现场即被点破：Maxwell 转述 Jordan Hubbard 评议“你在构建一个把 Unix 里所有事都做了的工具”（2024.86-2030.24），并承认若要理解全部命令则项目永无完工之日；其折中是 black box 机制——单引号包裹的命令以 exec 原样执行，工具只对其输出作弱假设。对“每程序只做一件事并做好”的偏离与守成，构成对该哲学一次具体的当代检讨。（BSD Now EP73，[2015.46-2043.30]，L2）
- LibreSSL 替代 FreeBSD base 系统 OpenSSL 在 2015 年初仍是未竟之问：base 更新受制于测试与发布流程而滞后于 ports，committers 已开始记录以 make.conf 变量改用 ports OpenSSL 并试验 LibreSSL portable 的过程，OpenZFS 团队亦透露考虑在 ports 与 base 双线切换；主持人提醒“不愿看到他们在未权衡全部影响前就切换”（1084.02-1088.02），且部分 Python ports 的不兼容标记属陈年遗留而非实际依赖。（BSD Now EP73，[943.92-1090.34]，L2） [订正：原 OPNsense 团队，2026-09-30 SenseAudio 重转核对]
- 主持人转述 Tor 中继平台分布统计（Linux 近 6000、Windows 约 1600、FreeBSD 173、OpenBSD 44、NetBSD 7、DragonFly BSD 仅 1），并以 Verisign 按 Linux、FreeBSD、Solaris 三分部署、OpenSSL 单点缺陷波及全网、Linux 伪随机数缺陷致 Tor 部分节点失效为例，主张平台多元是对冲系统性风险的工程策略；该论证与本期 LibreSSL 背景互为呼应 [存疑脚注] 节点统计数字仅经主持人转述且未附原始出处，属单一来源线索，待 tor-relays 邮件列表原始数据核验（BSD Now EP63，[928.52-1024.56]，L4）
- 三处专名与归属在转写中失真而须核验：其一，Espie 转述原包工具作者自评“周末写成的好用的垃圾”时自称记不清是否为 PHK，作者归属与措辞均待 pkg_install 历史与邮件列表原文印证；其二，构建机所在“Fuse Besmed”疑为人名误听（OpenBSD 包构建长期由 Landry Breuil 维护）；其三，影响 Java 的 PCID（新转写作 PCIDs，Process Context Identifier），具体 errata 编号待查 FreeBSD 公告档。 [存疑脚注] PHK 归属、Fuse Besmed 人名、PCID errata 编号三处均系转写失真或记忆性转述，须以邮件列表原文与 FreeBSD Errata Notices 核验后方可引用（BSD Now EP43，[1955.80-1988.06]，L4）[订正：原 引文“Fios basement”/“PCI DS”，新转写作 Fuse Besmed/PCIDs，2026-09-30 SenseAudio 重转核对]
- LibreSSL 分叉初期的技术辨析：OpenSSL 被评述为兼具最好与最糟的 SSL/TLS 库——加密原语尚可用而外围实现与协议处理腐烂；LibreSSL 以可直接替换 OpenSSL 为目标而被迫继承恶劣 API；向 Linux 与 FreeBSD 的早期移植尝试被指存在把 explicit_bzero 简单别名到常规清零函数、致使密钥清零被编译器优化掉的隐患，移植须区分“能跑起来”与“正确地工作”（4158.20-4162.08），该讨论呼应 Bob Beck 关于 LibreSSL 头三十天的演讲（BSD Now EP38，[4086.40-4199.42]，L2）
- Schwarze 转述其与 Eric Raymond 交谈、Raymond 又与 Richard Stallman 交谈的结果，称两人同意弃用 GNU info 并以其他方案替代，而 Stallman 与 Raymond 属意的 AsciiDoc/DocBook 路线被 Schwarze 评为工具链沉重、未必更易用；此说经过两级转述，RMS 的真实立场须以 FSF 原始文献核证，且许多替代尝试皆已失败的判断亦属其个人评断。 [存疑脚注] GNU info 弃用共识系经 Raymond 转述的二手信息，未经 Stallman 本人文本证实（BSDTalk EP243，[447.54-518.64]，L2）
