# 《给我自由——一部 BSD 的历史》

本仓库是科学技术史体裁学术专著《给我自由——一部 BSD 的历史》的编纂工程仓：以 AI 参与撰写，规划规模约 300–400 万字，工作范围限于大纲、考据、数据库与目录页。按项目红线，**全量证据复核止于阶段稿，未经明示批准不得启动正文编纂**（2026-10-14 裁定）。

本 README 只作入口页与质量设施说明。项目结构职责、每批必跑门禁与绝对红线一律以 [AGENTS.md](AGENTS.md) 为唯一权威；卷／章／节口径的唯一机器可读权威是目录页页首 `doc-metrics`，本文件不复述此类数字。

## 仓库速览

顶层为 11 个编号目录（00–12，编号缺口 06／09）与若干保留目录：

- `00-编纂规则与格式规范/`：规则唯一真相源与操作手册
- `01-项目管理/`：变更记录（changelog.duckdb）、规划归档、工程决策与技术债
- `02-sacred源材料/`：编纂指导思想源材料与 sacred_sources.duckdb
- `03-原始史料库/`：一手史料（代码仓库史料、邮件列表、TUHS Wiki 等）
- `04-现代研究文献/`：研究产出、claim 唯一真值（historical_claims.duckdb）与参考文献全文
- `05-卷册大纲/`：大纲目录页（装配源与产物）、映射台账、卷章节目录树
- `07-事实核查记录/`、`08-核查报告与多轮复核/`：核查原子记录与汇总报告
- `10-交叉索引/`、`11-元数据接口/`：八类索引与元数据接口
- `12-数据库备份/`：备份归档层（删除本目录内容须用户明示）

各目录完整职责与二级结构见 [AGENTS.md](AGENTS.md)“文件结构”；数据库五条通则同样以该文件为准。

## 环境要求

- Python 3.14（本机以 `C:/Python314/python.exe` 调用）；门禁脚本除数据库类外只用标准库。
- DuckDB 运行时锁定 `duckdb==2.0.0`，唯一声明源为 `00-编纂规则与格式规范/01-规则/脚本与命令/duckdb-version-baseline.txt`；数据库工作副本不入库。
- Node ≥ 22（markdownlint-cli2 0.24.0 的引擎下限；CI 侧装 Node 24）：目录页视觉回归三套件与 markdownlint 所需；本地钉定 markdownlint-cli2 0.24.0（markdownlint 0.42.0）。
- 全新克隆只含文本与装配产物：数据库类门禁须在恢复 `12-数据库备份/` 副本的本机环境执行。

## CI（GitHub Actions）

[.github/workflows/ci.yml](.github/workflows/ci.yml) 在 push、pull request 与手动触发时运行，收编范围为**不依赖本地数据库、浏览器与机器固定路径**的门禁，按层分步执行：

- 文本与格式层：文档格式门禁（第十件）、直角引号清零门禁（第二十四件）、Markdown 加粗空格门禁（第二十八件）、AI 不可见字符扫描、行为源块作用域门禁（第二十三件）、大纲树根级派生件入库白名单（第二十五件）、磁盘术语一致性（P2-11）、旁路备份残留扫描（第三十六件）、测试夹具新鲜度（第十三件）、主题词索引（含 C5 单主题占比与 C6 零使用 WARN）。
- 大纲与目录页结构层：目录页结构自检（第七件）、节号章号连续性、DATA 数据完整性、内嵌数据块一致性（`embed.py --check`）、口径同步（`sync_refactor2026_baseline.py --check`）、页面资产层完整性（第九件，须 fontTools＋brotli）、服务器契约（第十一件）、页面版本号递增兜底（第十八件）。
- 守卫、锚与交叉引用层：改号同源守卫（第十七件）、静默丢失守卫（第二十件；T1 为仓内快照 `08-核查报告与多轮复核/重构2026/data/outline-t1-20261011.txt`，不依赖历史对象）、大纲重复锚与重复块（第三十五件）、成对锚配平（第三十三件）、BEGIN/END 章内配对（第三十四件）、目录页交叉引用（第五件）、分工注四判据（第十四件）。
- 落地与治理层：大纲落地一致性（第三十七件；CI 以 `--root 05-卷册大纲` 相对根运行，缘由见工作流内注释）、门禁体系元门禁（第十六件）、工程实践基线（第二十九件）、测试夹具 `outline_selfcheck.py`（第二十一件）与 `tri_structure_negtest.py`（第十二件）。
- CI 专用语法冒烟（非项目门禁）：`compileall`（固定脚本与夹具）与 `node --check`（视觉回归三套件、探针与行为源）。

派生索引同批义务：`05-卷册大纲/` 内题名变动（如 TF 改题批）须同批跑 `build_theme_index.py --write` 重建 `chapter_keywords.json`／`theme_index.json`；漏重建时主题词索引门禁按设计报 B1（哈希不符）——这是真阳性，处置即重建后提交。

工作流引用的三个第三方 action 一律以 **40 位提交 SHA** 钉定、行尾注释记语义版本，不用浮动 tag（tag 可被改指而改变流水线行为）；2026-10-29 联网核对的最新正式版为 `actions/checkout` v7.0.1、`actions/setup-python` v7.1.0、`actions/setup-node` v7.1.0。升级由 [.github/dependabot.yml](.github/dependabot.yml) 的 github-actions 生态提 PR（Dependabot 会连 SHA 与行尾版本注释一并改写）。

未收编门禁及原因：

- 浏览器类：视觉回归三套件与无障碍门禁（第二十二件）的夹具硬编码本机 Playwright／Chromium 路径，限本机 Windows 运行。
- 数据库类：写库门禁、人物库语义完整性（第十五件）、锚解析（第十九件）、批次收口（第三十／三十一件）、长线登记表数值校验等依赖不入库的 DuckDB 工作副本。
- 扫描面不入库：任务生命周期（第三十二件）的扫描面是 `.trae/specs/`（按 2026-10-17 裁决不入库），全新克隆下按设计 `exit 2`（扫描面缺失）——由本机批流程执行；待其扫描面改为仓内台账后再并入 CI。
- 存量缺损未清：成对锚配平（第三十三件）与 BEGIN/END 章内配对（第三十四件）暂不收编。两条缘由：①二者仅在带 `--check` 时 `exit 1`，缺省恒 `exit 0`，原样收编即假绿；②存量 56 件块头／块尾缺失（含正文截断）＋第 71 卷 3.2.1 一处 W172 孤儿 END 未清。逐件清单与处置口径见 [锚配平缺损清单与处置施工单](01-项目管理/02-工程决策与技术债/锚配平缺损清单与处置施工单-20261029.md)；清零后恢复调用并显式带 `--check`。

