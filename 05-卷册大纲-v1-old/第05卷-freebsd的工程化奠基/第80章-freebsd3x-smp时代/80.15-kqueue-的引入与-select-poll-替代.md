# 91.2 kqueue 的引入与 select/poll 替代

## 91.2.1 kqueue 的设计哲学
  - 要点：kqueue 由 Jonathan Lemon 设计，2000 年引入 FreeBSD 4.1，采用统一 filter 接口替代 select/poll 的分散 API，支持文件、套接字、信号、定时器、进程等多种事件源，设计哲学是 “消解复杂性”
  - 史料：kqueue(2) 手册页、Lemon 的 kqueue 论文 (BSDCon 2000)、SVN commit log ［A］
  - 史观：总纲第 2 条——实践先于理论，kqueue 源于 select/poll 性能瓶颈的实践
  - 辨析：kqueue 引入版本存在 4.0 与 4.1 争议，需查 commit log
  - 文献：Lemon “Kqueue: A Generic and Scalable Event Notification Facility”(BSDCon 2000)；kqueue(2) 手册页 ［A］
## 91.2.2 select/poll 的替代逻辑
  - 要点：kqueue 通过 kevent 结构传递事件，避免 select/poll 的 O(n) 全量描述符扫描，实现 O(1) 事件通知；支持 level-triggered 与 edge-triggered 两种模式，比 Linux epoll(2002) 早 2 年

  kqueue 与 epoll 特性对照：

  | 特性 | kqueue | epoll | select/poll |
  | --- | --- | --- | --- |
  | 引入年份 | 2000（FreeBSD 4.1） | 2002（Linux 2.6） | 1983/1997 |
  | 设计者 | Jonathan Lemon | Davide Libenzi | BSD/AT&T |
  | 时间复杂度 | O(1) | O(1) | O(n) |
  | 事件源类型 | 文件、套接字、信号、定时器、进程 | 早期仅文件描述符 | 文件描述符 |
  | 触发模式 | level + edge | level + edge（epoll_ctl） | level only |

  - 史料：kqueue 实现代码 sys/kern/kern_event.c、Lemon 论文、性能基准测试 ［A］
  - 史观：总纲第 19 条——信息技术，kqueue 是高并发服务器需求推动的工程
  - 辨析：kqueue 与 epoll 的性能对比在不同负载下结论不同
  - 文献：Lemon 论文；kqueue(2) 手册页；epoll 文档 ［A］
## 91.2.3 kqueue 对后续的效应
  - 要点：kqueue 影响了 Linux epoll(2002)、macOS kqueue(Apple 直接采纳)、libevent 跨平台库；是 FreeBSD 对操作系统设计的标志性贡献之一
  - 史料：Linux epoll commit log、Apple macOS 文档、libevent 源码 ［A］
  - 史观：总纲第 4 条——分离与聚合，kqueue 设计分离至 Linux/macOS 后各自聚合
  - 辨析：epoll 是否 “借鉴” kqueue 存在争议，Libenzi 称独立设计
  - 文献：epoll 文档；macOS kqueue 文档；libevent 源码 ［A］
## 91.2.4 kqueue 史料辨析
  - 要点：kqueue 史料保存较好，Lemon 的 BSDCon 论文与手册页完整，但设计决策的演化散落在 commit log 中
